# ⚙️ Реалізація N-ферзів та Судоку

Практична реалізація алгоритмів пошуку з поверненням (backtracking) демонструє, як концептуальне дерево станів та предикати відтинання втілюються у робочий та високоефективний код. 

На відміну від теоретичного опису, де поняття «скасування вибору» здається простою декларативною дією відступу назад, у реальному програмуванні ключове значення має обчислювальна складність перевірки предикатів допустимості. Якщо перевірка того, чи є новий крок безпечним, вимагатиме лінійного або квадратичного часу від розміру задачі, загальна швидкодія алгоритму помітно погіршиться. 

У цій практичній вставці ми детально розберемо дві класичні комбінаторні задачі — розв'язання задачі N-ферзів із бітовими оптимізаціями та розв'язувач Судоку 9×9 — двома мовами програмування: C++ (для максимальної швидкодії) та Python (для високої виразності й наочності).

## Задача 1: N-Ферзів із бітовими масками

Класична реалізація перевірки безпечності позиції ферзя за допомогою двовимірного масиву N×N вимагає циклу для перевірки стовпчика, двох діагоналей та рядків. Така перевірка займає **O(N)** операцій на кожен крок рекурсії. При N = 15 чи N = 16 кількість викликів обчислюється мільярдами, і лінійний перевіряльник уповільнює виконання у десятки разів.

Завдяки підходу на основі **бітових масок (Bitmasking)** ми можемо звести перевірку наявності конфліктів до побітових операцій `AND`, `OR` та бітових зсувів, виконуючи її за **O(1)** машинного часу.

### Принцип роботи бітових масок

Для шахівниці розміром N×N стан зайнятості вертикалей та діагоналей зберігається у трьох цілочисельних змінних:

1. `cols` (зайняті стовпчики): якщо i-й біт дорівнює `1`, це означає, що у стовпчику i вже стоїть ферзь.
2. `diag1` (головні діагоналі, що йдуть зліва направо вгору): при переході на наступний рядок усі небезпечні зони зсуваються вліво на один біт (`diag1 << 1`).
3. `diag2` (побічні діагоналі, що йдуть справа наліво вгору): при переході на наступний рядок небезпечні зони зсуваються вправо на один біт (`diag2 >> 1`).

Для поточного рядка маска небезпечних позицій обчислюється як побітове `OR`: `(cols | diag1 | diag2)`. 

Відповідно, вільні безпечні позиції є інверсією цієї маски. Виразом `pos = limit & ~(cols | diag1 | diag2)` ми отримуємо маску, у якій одиничні біти позначають клітинки, куди можна безпечно поставити ферзя в поточному рядку.

Вираз `bit = pos & -pos` використовує властивість доповнювального коду (two's complement) і миттєво виділяє **наймолодший одиничний біт** (найлівішу вільну позицію). На апаратному рівні ця операція компілюється у високошвидкісні процесорні інструкції типу `BSF` (Bit Scan Forward) або `TZCNT` (Count Trailing Zeros), що працюють за один такт центрального процесора.

### Чому бітова версія працює кардинально швидше?

Зверніть увагу на відсутність динамічних масивів для зберігання стану шахівниці. Стан повністю вміщується у трьох 32-бітових реєстрах процесора `cols`, `diag1` та `diag2`. Перевірка конфліктів — це кілька побітових інструкцій ЦПУ без жодного звернення до оперативної пам'яті. 

Крім того, вираз `pos & -pos` у циклі `while` дозволяє алгоритму **взагалі не ітерувати по небезпечних клітинках**. Цикл виконується точно стільки разів, скільки в поточному рядку є дійсних безпечних варіантів. Якщо в рядку немає жодної безпечної клітинки, `pos` дорівнює `0`, і цикл не виконується жодного разу — відбувається миттєвий відкат назад (Backtrack).

## Задача 2: Розв'язувач Судоку (Sudoku Solver 9×9)

У головоломці Судоку потрібно заповнити ігрове поле 9×9 цифрами від 1 до 9. Правила вимагають, щоб у кожному з 9 рядків, кожному з 9 стовпчиків та кожному з 9 локальних блоків 3×3 кожна цифра зустрічалася точно один раз.

### Алгоритмічна стратегія рішення

Пошук із поверненням для Судоку працює за наступними кроками:
1. **Пошук першої порожньої клітинки**: скануємо сітку у пошуку клітинки зі значенням `0`. Якщо порожніх клітинок немає, головоломка розв'язана повністю.
2. **Перебір кандидатів**: випробовуємо послідовно значення від `1` до `9`.
3. **Оцінка допустимості (Предикат)**: перевіряємо, чи немає обраного числа у поточному рядку, у поточному стовпчику та у відповідній підсітці 3×3. Для швидкого знаходження координат лівого верхнього кута блоку 3×3 використовується формула: `startRow = 3 * (row / 3)`, `startCol = 3 * (col / 3)`.
4. **Вибір і рекурсія (Choose & Explore)**: якщо число допустиме, записуємо його у сітку і рекурсивно викликаємо розв'язувач для наступних клітинок.
5. **Скасування вибору (Unchoose / Backtrack)**: якщо рекурсивний виклик повернув `false` (тобто далі виник глухий кут), ми вилучаємо число (стираємо клітинку назад у `0`) і випробовуємо наступне значення від 1 до 9.

## Профіль швидкодії та класична розширеність: Танцюючі посилання (Dancing Links / DLX)

Для звичайних головоломок Судоку чи N-ферзів базового рекурсивного алгоритму цілком достатньо. Проте при підвищенні розмірності або для складніших комбінаторних задач (таких як замощення площини пентаміно чи задача про точне покриття Exact Cover) Дональд Кнут винайшов техніку **Dancing Links (DLX)**.

Алгоритм DLX є оптимізованою варіацією backtracking, де структура даних простору станів подається у вигляді двонаправленого тороїдального зв'язаного списку. При розширенні гілки вузли списку виключаються зі структури шляхом зміни вказівників: `x.left.right = x.right`, `x.right.left = x.left`. Під час відкату назад (Unchoose) вказівники відновлюються у зворотному порядку: `x.left.right = x`, `x.right.left = x`.

Оскільки відтворення вказівників виконується за сталий час O(1) без виділення чи звільнення пам'яті, це робить DLX найшвидшою відомою реалізацією backtracking для задач точного покриття.

### Наочне порівняння реалізацій

При виборі конкретного інструменту реалізації варто враховувати системні обмеження:

- **Бітовий N-Queens (C++)**: ідеальний вибір для максимальної швидкодії, коли розмір шахівниці N ≤ 32 і стани містяться у стандартних цілочисельних реєстрах ЦПУ.
- **Масивне Судоку (Python/C++)**: класична проста реалізація, що чудово підходить для навчання та розуміння шаблону Choose-Explore-Unchoose.
- **Dancing Links DLX**: індустріальний вибір для складної комбінаторики та комбінаторного покриття матриць великої розрядності.

Завдяки стабільним типам даних, оптимізаціям компілятора та прямому використанню регістрів ЦПУ, C++ реалізація задачі N-ферзів працює у 40–80 разів швидше за Python версію при N ≥ 13. Проте інтерпретований Python код є чудовим вибором для швидкого навчального прототипування.
