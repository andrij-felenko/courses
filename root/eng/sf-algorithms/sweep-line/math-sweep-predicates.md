# 🧮 Предикати орієнтації та точна геометрія перетину відрізків

Алгоритм замітальної прямої спирається на дві фундаментальні геометричні операції: визначення того, чи перетинаються два відрізки на площині, та підтримання вертикального порядку невертикальних відрізків на замітальній прямій `x = x_curr`. Якщо реалізувати ці операції через класичні рівняння прямих `y = k·x + b` із діленням чисел із рухомою комою, неминучі похибки округлення стандарту IEEE 754 призведуть до порушення антисиметричності та транзитивності порядку в дереві пошуку: комп'ютер може визначити, що відрізок `A` вище за `B`, `B` вище за `C`, але водночас `C` вище за `A`. Це руйнує дерево пошуку і спричиняє зациклення або аварійне завершення програми.

Надійна реалізація вимагає побудови **точних предикатів орієнтації** на основі знаків визначників та цілочисельної або адаптивної арифметики без втрати точності.

## Афінна орієнтація трійки точок (2D Cross Product)

Нехай задано три точки на площині: `A(x_A, y_A)`, `B(x_B, y_B)` та `C(x_C, y_C)`. Предикат орієнтації `orient(A, B, C)` визначає, з якого боку від спрямованого вектора `AB` лежить точка `C`: ліворуч (поворот проти годинникової стрілки), праворуч (поворот за годинниковою стрілкою) чи на самій прямій (колінеарність).

Геометрично це значення дорівнює подвоєній орієнтованій площі трикутника `ABC`, яка задається визначником однорідної матриці 3×3:

```
orient(A, B, C)
= det | x_A  y_A  1 |      [визначник однорідних координат точок]
      | x_B  y_B  1 |
      | x_C  y_C  1 |
= det | x_B − x_A   y_B − y_A |  [віднімання першого рядка від другого й третього]
      | x_C − x_A   y_C − y_A |
= (x_B − x_A) · (y_C − y_A) − (y_B − y_A) · (x_C − x_A)  [розкриття визначника 2×2]
```

Знак отриманого скалярного виразу задає геометричну орієнтацію:

```
orient(A, B, C) > 0  →  лівий поворот (проти годинникової стрілки, CCW)
orient(A, B, C) < 0  →  правий поворот (за годинниковою стрілкою, CW)
orient(A, B, C) = 0  →  точки A, B, C лежать на одній прямій (колінеарні)
```

Якщо вхідні координати є цілими числами розрядності `B` біт (наприклад, 32-розрядні цілі числа `int32`), різниці координат займають `B + 1` біт, а їхній добуток — `2B + 2` біт. Отже, різниця двох таких добутків потребує `2B + 3` біт. Для 32-розрядних координат (`B = 32`) обчислення орієнтації без переповнення та без похибок гарантується використанням стандартного 64-розрядного цілого типу `int64_t`.

## Умова перетину двох відрізків

Розглянемо два відрізки: `S₁` із кінцями `A, B` та `S₂` із кінцями `C, D`. Два відрізки перетинаються у внутрішній точці (строгий перетин) тоді й лише тоді, коли одночасно виконано дві умови:
1. Кінці `C` і `D` лежать по різні боки від нескінченної прямої, що містить відрізок `AB`.
2. Кінці `A` і `B` лежать по різні боки від нескінченної прямої, що містить відрізок `CD`.

Мовою предикатів орієнтації це записується як протилежність знаків:

```
d₁ = orient(A, B, C)
d₂ = orient(A, B, D)
d₃ = orient(C, D, A)
d₄ = orient(C, D, B)

строгий_перетин = (d₁ · d₂ < 0) ∧ (d₃ · d₄ < 0)
```

Зверніть увагу: добуток `d₁ · d₂ < 0` означає, що один зі знаків додатний, а інший — від'ємний, тобто точки дійсно розділені прямою.

### Колінеарність і перевірка обмежувального прямокутника

Якщо бодай одне з чисел `d₁, d₂, d₃, d₄` дорівнює нулю, точка лежить на прямій, яка містить інший відрізок. Щоб з'ясувати, чи лежить точка `C` безпосередньо на відрізку `AB`, перевіряють умову належності її координат проекціям (обмежувальному прямокутнику, англ. *bounding box*):

```
on_segment(A, B, C) = (orient(A, B, C) = 0)
                      ∧ (min(x_A, x_B) ≤ x_C ≤ max(x_A, x_B))
                      ∧ (min(y_A, y_B) ≤ y_C ≤ max(y_A, y_B))
```

Повна перевірка перетину з урахуванням дотиків та накладання:

```
перетинаються(AB, CD) = ((d₁ · d₂ < 0) ∧ (d₃ · d₄ < 0))
                        ∨ on_segment(A, B, C)
                        ∨ on_segment(A, B, D)
                        ∨ on_segment(C, D, A)
                        ∨ on_segment(C, D, B)
```

Якщо відрізки `AB` та `CD` є колінеарними й перекриваються вздовж спільного відрізка, множина точок перетину визначається перетином їхніх одновимірних проекцій на вісь `X` (а для вертикальних відрізків — на вісь `Y`):

```
x_left = max(min(x_A, x_B), min(x_C, x_D))
x_right = min(max(x_A, x_B), max(x_C, x_D))

відрізок_перекриття = [x_left, x_right],   якщо x_left ≤ x_right
```

## Проективна геометрія: перетин прямих у однорідних координатах

У проективній площині точка `P(x, y)` представляється вектором однорідних координат `p = (x, y, 1)ᵀ`, а пряма, що проходить крізь дві точки `A` та `B`, задається векторним добутком:

```
L = A × B = (y_A − y_B,  x_B − x_A,  x_A·y_B − y_A·x_B)ᵀ
```

Точка перетину `P` двох прямих `L₁ = (a₁, b₁, c₁)ᵀ` та `L₂ = (a₂, b₂, c₂)ᵀ` знаходиться як векторний добуток їхніх векторів прямих:

```
p_cross = L₁ × L₂ = (b₁·c₂ − b₂·c₁,  c₁·a₂ − c₂·a₁,  a₁·b₂ − a₂·b₁)ᵀ
```

Третя координата `w = a₁·b₂ − a₂·b₁` є детермінантом системи лінійних рівнянь. Якщо `w = 0`, прямі паралельні (точка перетину лежить на нескінченно віддаленій прямій). Якщо `w ≠ 0`, перехід до декартових координат здійснюється одноразовим діленням у самому кінці:

```
x_P = (b₁·c₂ − b₂·c₁) / (a₁·b₂ − a₂·b₁)
y_P = (c₁·a₂ − c₂·a₁) / (a₁·b₂ − a₂·b₁)
```

Цей підхід дозволяє виконувати всі проміжні геометричні перетворення виключно в цілих числах, відкладаючи ділення до моменту виводу результату.

## Адаптивні предикати Шевука та числова стійкість

У промислових бібліотеках обчислювальної геометрії (зокрема CGAL, GEOS та Triangle) для чисел із рухомою комою використовують підхід Джонатана Шевука (Jonathan Richard Shewchuk, 1997) — адаптивні предикати точної арифметики.

Шевук запропонував багаторівневу фільтрацію:
1. Спочатку визначник `det = (x_B − x_A) · (y_C − y_A) − (y_B − y_A) · (x_C − x_A)` обчислюється у стандартному типі `double` стандарту IEEE 754.
2. Одночасно оцінюється максимальна можлива абсолютна похибка округлення:
   `ε_max = (3 · 2⁻⁵³ + 16 · 2⁻¹⁰⁶) · (|x_B − x_A| · |y_C − y_A| + |y_B − y_A| · |x_C − x_A|)`.
3. Якщо обчислений визначник перевищує за модулем `ε_max` (`|det| > ε_max`), його знак гарантовано правильний — результат повертається миттєво з апаратною швидкістю процесора.
4. Якщо ж `|det| ≤ ε_max` (точки майже колінеарні або лежать на відстані мікронів), фільтр перемикається на адаптивне розширення масивами `double` без втрати бітів (англ. *floating-point expansions*), де кожне проміжне число зберігається як сума неперекривних значень.

Це дозволяє поєднати пікову швидкість апаратних інструкцій FPU для 99.9% випадків із абсолютною математичною строгістю для вироджених геометричних конфігурацій.

## Компаратор структури статусу: порівняння за Y при поточному X

У структурі статусу замітальної прямої відрізки впорядковуються за їхньою висотою `Y` у поточній позиції прямої `x = x_curr`. 

Для невертикального відрізка `AB` (де `x_A < x_B`) його координата `Y` при поточному `x` виражається лінійною інтерполяцією:

```
y_AB(x) = y_A + (x − x_A) · (y_B − y_A) / (x_B − x_A)
```

Щоб порівняти два відрізки `AB` та `CD` у точці `x = x_curr` без виконання неточного ділення, ми аналізуємо знак різниці:

```
Δy(x)
= y_AB(x) − y_CD(x)
= [y_A + (x − x_A) · (y_B − y_A) / (x_B − x_A)] − [y_C + (x − x_C) · (y_D − y_C) / (x_D − x_C)]   [підстановка формули прямої]
```

Звівши дроби до спільного знаменника, враховуємо, що для коректних невертикальних відрізків `x_B − x_A > 0` та `x_D − x_C > 0`, а отже їхній добуток завжди строго додатний. Тоді знак різниці `Δy(x)` повністю збігається зі знаком чисельника:

```
знак_порівняння = (y_A · (x_B − x_A) + (x − x_A) · (y_B − y_A)) · (x_D − x_C) − (y_C · (x_D − x_C) + (x − x_C) · (y_D − y_C)) · (x_B − x_A)
```

Якщо `знак_порівняння > 0`, то відрізок `AB` лежить вище за `CD` на замітальній прямій `x`. Якщо `знак_порівняння < 0`, то вище лежить `CD`. 

Якщо ж `знак_порівняння = 0`, відрізки перетинаються або збігаються безпосередньо на прямій `x`. Для збереження строгого порядку в дереві пошуку порівнюють кутові коефіцієнти відрізків праворуч від точки `x`:

```
знак_нахилу = (y_B − y_A) · (x_D − x_C) − (y_D − y_C) · (x_B − x_A)
```

Відрізок із більшим нахилом після точки `x` підніметься вище, тому він вважається більшим при сортуванні.

## Покроковий числовий приклад розрахунку

**Перевіримо перетин двох відрізків:**
Нехай задано відрізок `AB` із точками `A(1, 1)`, `B(5, 5)` та відрізок `CD` із точками `C(1, 5)`, `D(5, 1)`.

```
d₁ = orient(A, B, C)
= (5 − 1) · (5 − 1) − (5 − 1) · (1 − 1)   [підстановка координат у визначник]
= 4 · 4 − 4 · 0                          [обчислення різниць]
= 16                                     [знак > 0: точка C ліворуч від AB]

d₂ = orient(A, B, D)
= (5 − 1) · (1 − 1) − (5 − 1) · (5 − 1)   [підстановка координат у визначник]
= 4 · 0 − 4 · 4                          [обчислення різниць]
= −16                                    [знак < 0: точка D праворуч від AB]

d₃ = orient(C, D, A)
= (5 − 1) · (1 − 5) − (1 − 5) · (1 − 1)   [підстановка координат у визначник]
= 4 · (−4) − (−4) · 0                    [обчислення різниць]
= −16                                    [знак < 0: точка A праворуч від CD]

d₄ = orient(C, D, B)
= (5 − 1) · (5 − 5) − (1 − 5) · (5 − 1)   [підстановка координат у визначник]
= 4 · 0 − (−4) · 4                       [обчислення різниць]
= 16                                     [знак > 0: точка B ліворуч від CD]
```

Оскільки `d₁ · d₂ = 16 · (−16) = −256 < 0` та `d₃ · d₄ = (−16) · 16 = −256 < 0`, обидва відрізки строго перетинаються.

Обчислимо координати точки перетину:

```
знаменник = (x_B − x_A) · (y_D − y_C) − (y_B − y_A) · (x_D − x_C)
= 4 · (−4) − 4 · 4                       [підстановка різниць координат]
= −16 − 16                               [множення компонентів]
= −32                                    [результат детермінанта]

чисельник_t = (x_C − x_A) · (y_D − y_C) − (y_C − y_A) · (x_D − x_C)
= (1 − 1) · (−4) − (5 − 1) · 4           [підстановка різниць координат]
= 0 − 16                                 [множення компонентів]
= −16                                    [чисельник параметра t]

t = чисельник_t / знаменник
= −16 / −32                              [ділення чисельника на знаменник]
= 0.5                                    [параметричне положення на AB]

x_P = x_A + t · (x_B − x_A)
= 1 + 0.5 · 4                            [підстановка параметра t в рівняння X]
= 3                                      [координата X точки перетину]

y_P = y_A + t · (y_B − y_A)
= 1 + 0.5 · 4                            [підстановка параметра t в рівняння Y]
= 3                                      [координата Y точки перетину]
```

Отримано точну точку перетину `P(3, 3)`, що повністю узгоджується з геометрією.
