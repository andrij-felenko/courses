# 🧮 Імовірнісний аналіз пропускного списку: математичне очікування та межі концентрації

Пропускний список (англ. *Skip List*) досягає логарифмічної ефективності операцій пошуку, вставки, видалення та діапазонного сканування без використання детерміністичних поворотів піддерев. Його збалансованість є наслідком закону великих чисел і фундаментальних властивостей геометричного розподілу.

Нижче наведено строге математичне виведення просторової складності, висоти структури, математичного очікування й дисперсії довжини шляху пошуку через метод зворотного обходу (англ. *backward search analysis*), аналіз вартості оновлень та діапазонних вибірок, оцінку ймовірностей відхилення за допомогою нерівностей Чернова, математику розширення для пошуку за рангом (англ. *ranked skip list*) та пошуку за вказівником (англ. *finger search*), а також порівняльний аналіз процесорного кешування й вибору констант розгалуження.

## 1. Геометричний розподіл рівнів вузлів

Висота кожного вузла визначається серією незалежних випробувань Бернуллі з імовірністю успіху `p` (де `0 < p < 1`, у практичних реалізаціях зазвичай обирають `p = 1/2` або `p = 1/4`).

Вузол завжди має базовий рівень 1. Вузол отримує рівень 2 з імовірністю `p`, рівень 3 — з імовірністю `p²`, і загалом рівень не менше ніж `k` — з імовірністю `p^(k-1)`. Процес вибору висоти можна уявити як підкидання монети до першої появи «герба» (невдачі): якщо монета випадає «числом» (успіх), рівень вузла інкрементується.

Важливою рисою цього процесу є **відсутність післядії** (англ. *memoryless property*): ймовірність того, що вузол підніметься на рівень `k + 1`, за умови, що він уже досяг рівня `k`, завжди дорівнює точно `p` і не залежить від висоти сусідніх вузлів або значень збережених ключів.

Це створює фундаментальну відмінність між пропускним списком і детерміністичними двійковими деревами пошуку без балансування. У звичайному незбалансованому двійковому дереві відсортований вхідний потік гарантовано перетворює дерево на лінійний список `O(n)`. У пропускному списку порядок додавання ключів не має жодного впливу на форму структури: навіть якщо вхідний масив відсортований, розріджений чи згрупований блоками, випадковість вибору висот кожного вузла гарантує збереження логарифмічної продуктивності.

Ймовірність того, що точна висота вузла `H` дорівнює цілому числу `k ≥ 1`, описується дискретним геометричним розподілом:

```
P(H = k) = p^(k-1) · (1 - p)
```

Ймовірність того, що висота вузла становить щонайменше `k`, обчислюється як сума нескінченної спадної геометричної прогресії:

```
P(H ≥ k) = ∑_{j=k}^{∞} p^(j-1) · (1 - p)
= p^(k-1) · (1 - p) · ∑_{i=0}^{∞} p^i     [заміна індексу підсумовування i = j - k]
= p^(k-1) · (1 - p) · (1 / (1 - p))        [сума спадної геометричної прогресії при p < 1]
= p^(k-1)                                  [скорочення спільного множника (1 - p)]
```

## 2. Просторовий оверхед: середня кількість покажчиків на вузол

Кожен вузол висоти `k` містить масив із рівно `k` покажчиків `forward[0...k-1]`. Знайдемо математичне очікування кількості покажчиків у довільному вузлі `E[H]`.

За означенням математичного очікування дискретної випадкової величини:

```
E[H] = ∑_{k=1}^{∞} k · P(H = k)
= ∑_{k=1}^{∞} k · p^(k-1) · (1 - p)        [підстановка розподілу ймовірностей P(H = k)]
= (1 - p) · ∑_{k=1}^{∞} k · p^(k-1)        [винесення спільного множника (1 - p)]
```

Розглянемо базовий степеневий ряд для суми геометричної прогресії при `|p| < 1`:

```
∑_{k=0}^{∞} p^k = 1 / (1 - p)
```

Візьмемо формальну похідну за змінною `p` від обох частин рівності:

```
d/dp (∑_{k=0}^{∞} p^k) = d/dp (1 / (1 - p))
∑_{k=1}^{∞} k · p^(k-1) = 1 / (1 - p)²     [диференціювання степеневого ряду та дробу]
```

Підставимо отриману суму ряду у вираз для математичного очікування `E[H]`:

```
E[H] = (1 - p) · (1 / (1 - p)²)
= 1 / (1 - p)                              [скорочення лінійного множника (1 - p)]
```

### Дисперсія кількості покажчиків у вузлі

Щоб оцінити коливання розміру вузлів навколо середнього значення, знайдемо другий момент `E[H²]`. Скористаємося другою похідною геометричного ряду:

```
d²/dp² (∑_{k=0}^{∞} p^k) = d²/dp² (1 / (1 - p))
∑_{k=2}^{∞} k · (k - 1) · p^(k-2) = 2 / (1 - p)³ [похідна другого порядку]
```

Помножимо обидві частини на `p`:

```
∑_{k=1}^{∞} k · (k - 1) · p^(k-1) = 2 · p / (1 - p)³
```

Запишемо `k² = k · (k - 1) + k`, звідки:

```
E[H²] = (1 - p) · ∑_{k=1}^{∞} k² · p^(k-1)
= (1 - p) · (∑_{k=1}^{∞} k · (k - 1) · p^(k-1) + ∑_{k=1}^{∞} k · p^(k-1)) [розклад квадрата k]
= (1 - p) · ( (2 · p / (1 - p)³) + (1 / (1 - p)²) )                     [підстановка похідних]
= (2 · p / (1 - p)²) + (1 / (1 - p))                                    [скорочення (1 - p)]
= (1 + p) / (1 - p)²                                                    [зведення до спільного знаменника]
```

Обчислимо дисперсію `Var(H) = E[H²] - (E[H])²`:

```
Var(H) = ((1 + p) / (1 - p)²) - (1 / (1 - p))²
= ((1 + p) - 1) / (1 - p)²                 [зведення під спільний знаменник (1 - p)²]
= p / (1 - p)²                             [арифметичне спрощення в чисельнику]
```

Для стандартних конфігурацій:
- При `p = 1/2`: `Var(H) = 0.5 / (0.5)² = 0.5 / 0.25 = 2.0`, стандартне відхилення `σ = √2 ≈ 1.414`.
- При `p = 1/4`: `Var(H) = 0.25 / (0.75)² = 0.25 / 0.5625 = 4/9 ≈ 0.444`, стандартне відхилення `σ = 2/3 ≈ 0.667`.

Мала дисперсія гарантує, що пам'ять під масиви покажчиків розподіляється передбачувано без ризику неконтрольованого розростання структури. Загальна кількість покажчиків у списку з `n` вузлів є сумою `n` незалежних випадкових величин, тому за центральною граничною теоремою сумарне споживання пам'яті дуже щільно концентрується навколо `n / (1 - p)`.

## 3. Математичне очікування максимальної висоти списку

Нехай список містить `n` вузлів. Позначимо максимальну висоту серед усіх `n` вузлів як `L_max = max(H₁, H₂, ..., Hₙ)`.

Визначимо характерну висоту структури `L(n) = log_{1/p} n`. 

Знайдемо верхню межу ймовірності того, що хоча б один вузол досягне висоти, більшої або рівної `L(n) + c` для деякого цілого зміщення `c > 0`. Застосуємо нерівність Буля (англ. *union bound*) для об'єднання випадкових подій:

```
P(L_max ≥ L(n) + c) = P(⋃_{i=1}^{n} {H_i ≥ L(n) + c})
≤ ∑_{i=1}^{n} P(H_i ≥ L(n) + c)            [за нерівністю Буля для об'єднання подій]
= n · p^(L(n) + c - 1)                     [підстановка точної ймовірності P(H ≥ k)]
= n · p^(log_{1/p} n + c - 1)              [підстановка визначення L(n) = log_{1/p} n]
= n · (p^(log_{1/p} n)) · p^(c - 1)        [розклад показника степеня на добуток]
= n · (1/n) · p^(c - 1)                    [оскільки p^(log_{1/p} n) = (1/p)^(-log_{1/p} n) = 1/n]
= p^(c - 1)                                [скорочення n та 1/n]
```

При виборі `p = 1/2` та константи `c = 4`:

```
P(L_max ≥ log₂ n + 4) ≤ (1/2)³ = 1/8 = 0.125
```

При константі `c = 10`:

```
P(L_max ≥ log₂ n + 10) ≤ (1/2)⁹ = 1/512 ≈ 0.00195
```

Звідси випливає, що математичне очікування максимальної висоти списку обмежене константою відхилення:

```
E[L_max] = log_{1/p} n + O(1)
```

### Вплив обмеження максимального рівня MaxLevel

У практичних бібліотеках висоту списку обмежують апаратною константою `MaxLevel` (наприклад, 32 або 64), щоб уникнути виділення надмірно великих масивів покажчиків у головному вузлі `HEAD`.

Якщо фактична кількість елементів `n` не перевищує `(1/p)^MaxLevel`, обмеження не впливає на структуру. Якщо ж `n` перевищить цю величину, список не ламається і не втрачає коректності: верхній рівень просто перетворюється на звичайний зв'язаний список, а час пошуку плавно деградує як `O(MaxLevel + n · p^MaxLevel)`. Для `MaxLevel = 32` і `p = 1/2` місткість списку без втрати швидкості становить `2³² ≈ 4.29 · 10⁹` елементів.

## 4. Аналіз зворотного шляху пошуку (Backward Search Analysis)

Класичне пряме обчислення довжини шляху пошуку зверху вниз ускладнене взаємною залежністю кроків: вибір напрямку залежить від значень ключів у всіх пройдених вузлах.

Метод Вільяма П'ю аналізує пошук у **зворотному напрямку** (англ. *backward search*): ми починаємо рух від знайденого цільового вузла на нульовому рівні і піднімаємося назад у лівий верхній кут до головного вартового `HEAD`. Оскільки топологія зв'язків є детерміністичною відносно згенерованих висот, зворотний шлях є точною дзеркальною копією прямого спуску.

### Правила зворотного кроку

Нехай зворотний шлях перебуває у вузлі `v` на рівні `k`:
1. Якщо вузол `v` не мав вежі висоти `k+1`, прямий пошук не міг опуститися в нього зверху з вищого рівня. Отже, під час прямого пошуку ми прийшли до вузла `v` зліва на поточному рівні `k`. Це означає, що у зворотному напрямку ми робимо **крок ліворуч** на тому ж рівні `k`.
2. Якщо вузол `v` мав вежу висоти `k+1` або вище, прямий пошук опустився в нього зверху з рівня `k+1`. Отже, у зворотному напрямку ми робимо **крок угору** на рівень `k+1`.

Оскільки висота кожного вузла обиралася абсолютно незалежно від інших вузлів:
- Ймовірність того, що вузол не продовжується на рівень `k+1` (крок ліворуч), становить `1 - p`.
- Ймовірність того, що вузол продовжується на рівень `k+1` (крок угору), становить `p`.

Нехай `C(k)` — математичне очікування кількості кроків зворотного шляху, необхідних для підйому на `k` рівнів угору.

Складемо рекурентне рівняння:

```
C(k) = 1 + (1 - p) · C(k) + p · C(k - 1)
```

Розв'яжемо рекурентне рівняння відносно величини `C(k)`:

```
C(k) - (1 - p) · C(k) = 1 + p · C(k - 1)   [перенесення доданка з C(k) у ліву частину]
p · C(k) = 1 + p · C(k - 1)                [спрощення коефіцієнта: 1 - (1 - p) = p]
C(k) = (1 / p) + C(k - 1)                  [ділення обох частин рівності на p]
```

Базовий випадок для нульового підйому: `C(0) = 0`. Розгорнемо рекурентний ланцюг за індукцією:

```
C(k) = (1 / p) + C(k - 1)
= (1 / p) + (1 / p) + C(k - 2)             [розкриття кроку C(k-1)]
= k · (1 / p)                              [сума k однакових доданків 1/p]
= k / p                                    [зведення у дріб]
```

### Загальна довжина шляху пошуку

Підйом відбувається від рівня 1 до характерного рівня `L(n) = log_{1/p} n`. Досягнувши рівня `L(n)`, зворотний шлях рухається виключно ліворуч до вартового `HEAD`. Кількість елементів списку на рівні `L(n)` має математичне очікування:

```
E[Nodes_at_top] = n · p^(log_{1/p} n)
= n · (1/n)                                [оскільки p^(log_{1/p} n) = 1/n]
= 1                                        [скорочення множників n та 1/n]
```

Очікувана кількість кроків ліворуч на верхньому рівні дорівнює `E[Nodes_at_top] / p = 1 / p`.

Отже, повне математичне очікування кількості переходів покажчиків під час пошуку `E[Cost]` становить:

```
E[Cost] ≤ C(L(n) - 1) + (1 / p)
= ((log_{1/p} n - 1) / p) + (1 / p)        [підстановка формули C(k)]
= (log_{1/p} n) / p                        [спрощення доданків -1/p + 1/p]
```

## 5. Складність операцій вставки, видалення та діапазонного запиту

### Вставка та видалення

Операція вставки складається з двох послідовних фаз:
1. **Пошук позиції попередників:** спуск зверху вниз із заповненням масиву `update[0...MaxLevel-1]`. Ця фаза виконує точно такий самий шлях, як і операція пошуку, тому її очікувана вартість становить `E[Cost_search] ≤ (log_{1/p} n) / p`.
2. **Перечіплювання покажчиків:** новий вузол висоти `k` перечіплює рівно `k` покажчиків `forward`. Оскільки математичне очікування висоти нового вузла дорівнює `E[H] = 1 / (1 - p)`, очікувана кількість модифікацій покажчиків є константою `O(1)`.

Загальне математичне очікування часу вставки:

```
E[Cost_insert] = E[Cost_search] + E[H]
= ((log_{1/p} n) / p) + (1 / (1 - p))      [підстановка очікуваних значень фаз]
= O(log n)                                 [логарифмічна асимптотика]
```

Аналогічно, для видалення вузла оновлюються покажчики попередників із масиву `update[]` лише на тих рівнях, де існував видалений вузол. Очікувана вартість видалення також становить `O(log n)`.

### Діапазонний запит (Range Query)

Запит на вибірку всіх ключів у замкненому інтервалі `[k_start, k_end]` складається з:
1. Пошуку першого вузла `v_start ≥ k_start` за час `O(log n)`.
2. Послідовного лінійного проходу по нульовому рівню `forward[0]` до досягнення вузла `v_end > k_end`.

Якщо діапазон містить `m` елементів, кількість кроків на нульовому рівні становить рівно `m`. Загальна складність операції:

```
T_range(n, m) = O(log n + m)
```

Оскільки елементи нульового рівня формують звичайний відсортований однозв'язаний список, ітерація по діапазону виконується з мінімальними накладними витратами — без потреби в рекурсивному обході піддерев чи підтримці стека батьківських вузлів, як у двійкових деревах.

## 6. Межі концентрації: нерівність Чернова

Кількість кроків ліворуч `W` до моменту здійснення `L_max` підйомів угору підпорядковується від'ємному біноміальному розподілу (кількість невдач до накопичення заданої кількості успіхів у схемі незалежних випробувань Бернуллі).

Для оцінки ймовірності відхилення випадкової величини від її математичного очікування нерівність Маркова дає занадто слабку лінійну границю `P(X ≥ a · E[X]) ≤ 1/a`, а нерівність Чебишова — квадратичну оцінку `P(|X - E[X]| ≥ k · σ) ≤ 1/k²`.

Застосуємо експоненційну нерівність Чернова через твірну функцію моментів, що дає сувору оцінку спадання хвостів розподілу. Для довільного параметра відхилення `δ > 0`:

```
P(Cost > (1 + δ) · E[Cost]) ≤ exp(- (δ² · E[Cost]) / (2 + δ))
```

Позначимо `μ = E[Cost] = 2 · log₂ n`. Розглянемо випадок `δ = 1` (шлях удвічі довший за середнє очікування):

```
P(Cost > 2 · μ) ≤ exp(- (1² · 2 · log₂ n) / 3)
= exp(- (2/3) · (ln n / ln 2))             [перехід до натурального логарифма ln n]
= exp(- 0.9618 · ln n)                     [чисельне обчислення коефіцієнта 2 / (3 · ln 2)]
= n^(-0.9618)                              [перетворення показникової функції e^(-a · ln n)]
```

Розглянемо випадок `δ = 3` (шлях у 4 рази довший за середнє очікування):

```
P(Cost > 4 · μ) ≤ exp(- (3² · 2 · log₂ n) / (2 + 3))
= exp(- (18/5) · (ln n / ln 2))            [підстановка квадратів і доданків]
= exp(- 3.6 · (ln n / 0.69315))            [підстановка значення ln 2]
= exp(- 5.194 · ln n)                      [обчислення добутку 3.6 / 0.69315]
= n^(-5.194)                               [перетворення в степінь n]
```

Для списку з одного мільйона записів (`n = 10⁶`):

```
P(Cost > 4 · μ) ≤ (10⁶)^(-5.194)
= 10^(-31.16)                              [множення показників степенів]
```

Ймовірність критичного відхилення настільки мізерна, що в інженерній практиці Skip List розглядають як структуру з де-факто гарантованою логарифмічною поведінкою.

## 7. Оптимізація параметра розгалуження p

Виразимо середній час пошуку як функцію від параметра `p`:

```
T(p) = (log_{1/p} n) / p
= (ln n / ln(1/p)) / p                     [формула переходу до натуральної основи логарифма]
= ln n / (p · ln(1/p))                     [перенесення множника p у знаменник]
= ln n / (- p · ln p)                      [оскільки ln(1/p) = ln(p^(-1)) = -ln p]
```

Щоб мінімізувати час `T(p)`, максимізуємо функцію `f(p) = - p · ln p` на відкритому інтервалі `(0, 1)`.

Знайдемо першу похідну:

```
f'(p) = d/dp (- p · ln p)
= - (1 · ln p + p · (1/p))                 [диференціювання добутку функцій]
= - ln p - 1                               [спрощення доданка p · (1/p) = 1]
```

Прирівняємо похідну до нуля:

```
- ln p - 1 = 0
ln p = -1                                  [перенесення одиниці у праву частину]
p = e^(-1) = 1/e ≈ 0.36788                 [експоненціювання обох частин]
```

Оскільки друга похідна `f''(p) = -1/p < 0` для всіх `p > 0`, точка `p = 1/e` є глобальним максимумом функції знаменника та точкою глобального мінімуму часу пошуку.

## 8. Пошук за порядковим номером: ранговий пропускний список

Класичний пропускний список можна розширити для підтримки операцій за порядковим номером (англ. *order statistic / rank query*): визначення індексу ключа або пошук `k`-го за величиною елемента за час `O(log n)`.

Для цього кожен покажчик `forward[i]` доповнюється полем `span[i]` (ширина переходу) — кількістю вузлів нульового рівня, яку перестрибує цей покажчик.

### Інваріанти ширини переходу

1. Для нульового рівня: кожен покажчик `forward[0]` з'єднує суміжні вузли, тому `span[0] = 1`.
2. Для рівня `i > 0`: `span[i]` дорівнює сумі значень `span[i - 1]` для всіх проміжних вузлів між поточним і цільовим.
3. Під час пошуку `k`-го елемента: рухаючись праворуч на рівні `i`, ми віднімаємо `span[i]` від шуканого рангу `k`, якщо `span[i] ≤ k`. Якщо `span[i] > k`, ми спускаємося на рівень `i - 1`.

Математичне очікування кількості кроків при пошуку за рангом точно збігається з довжиною звичайного пошуку за ключем і становить `E[Cost] ≤ (log_{1/p} n) / p`.

## 9. Локалізований пошук за вказівником (Finger Search)

У багатьох практичних сценаріях запити на пошук не є рівномірно розподіленими, а мають високу просторову локальність: наступний шуканий ключ розташований поблизу щойно знайденого (наприклад, при злитті двох відсортованих послідовностей або ітеративному обході).

Якщо запам'ятати покажчик на попередньо знайдений вузол (так званий «палець» або вказівник, англ. *finger*), пошук можна починати не з головного вузла `HEAD`, а безпосередньо з цього вказівника, піднімаючись угору до першого рівня, покажчик якого перестрибує шукану позицію, а потім звичайним чином спускаючись униз.

Якщо відстань у кількості елементів між позицією вказівника та новим шуканим ключем дорівнює `d`, математичне очікування кількості переходів складає:

```
E[Cost_finger] = O(log d)
```

Коли `d ≪ n`, пошук за вказівником виконується за малий час `O(1)` або `O(log d)`, що значно швидше за стандартний глобальний пошук `O(log n)`.

## 10. Детерміністичні проти ймовірнісних пропускних списків

У теорії існують спроби детерміністичної побудови пропускних списків (англ. *Deterministic Skip Lists*, розроблені Манро, Пападжіоу та Маннані у 1992 році на основі ієрархій 1-2 або 1-2-3). У такій структурі строго вимагається, щоб між будь-якими двома вузлами рівня `k` розташовувався рівно 1 або 2 вузли рівня `k - 1`.

Детерміністичні списки гарантують логарифмічний час у найгіршому випадку, проте вони повністю втрачають головну практичну перевагу винаходу П'ю: простоту та локальність операцій. Вставка та видалення в детерміністичному списку вимагають каскадного розщеплення та злиття веж (аналогічно 2-3 деревам), що призводить до втрати неблокувальних властивостей у багатопотоковому режимі. Саме ймовірнісна природа робить класичний Skip List неперевершеним для паралельних архітектур.

## 11. Числове порівняння та розрахунок пам'яті для 64-бітних систем

Розглянемо практичний індекс на `n = 10 000 000` (10 млн) записів у 64-бітній системі, де розмір покажчика становить 8 байтів, розмір ключа `uint64_t` — 8 байтів, розмір значення `uint64_t` — 8 байтів.

| Параметр | `p = 1/2` | `p = 1/e ≈ 0.368` | `p = 1/4 = 0.25` |
| :--- | :--- | :--- | :--- |
| **Очікувана висота `log_{1/p} n`** | `23.25` рівнів | `16.12` рівнів | `11.63` рівнів |
| **Середня довжина пошуку `E[Cost]`** | `46.5` кроків | `43.8` кроків | `46.5` кроків |
| **Середня кількість покажчиків на вузол `E[H]`** | `2.000` | `1.582` | `1.333` |
| **Пам'ять на покажчики (10 млн вузлів)** | `160.0 МБ` | `126.6 МБ` | `106.7 МБ` |
| **Загальний розмір структур вузлів** | `320.0 МБ` | `286.6 МБ` | `266.7 МБ` |
| **Генерація рівня через побітові маски** | 1 біт на рівень | вимагає ділення | 2 біти на рівень |

Математичний аналіз показує, що перехід від `p = 1/2` до `p = 1/4` не збільшує кількість кроків пошуку (`2 · log₂ n` в обох випадках), але економить понад 53 МБ оперативної пам'яті на кожні 10 мільйонів записів і дозволяє генерувати рівні за допомогою надзвичайно швидких бітових масок `rand() & 3 == 0`.
