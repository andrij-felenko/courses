# 📋 Довідник інтерфейсу та складності пропускного списку (Skip List API)

У цій довідковій специфікації наведено повний контракт інтерфейсу структури даних пропускного списку (англ. *Skip List*), формати структур пам'яті, сигнатури функцій мовами C та C++, перед- і післяумови операцій, матрицю часової та просторової складності, розширення для рангового та локалізованого пошуку, масового завантаження, серіалізації, а також інженерні рекомендації з налаштування параметрів конфігурації.

## 1. Фундаментальні інваріанти структури даних

Пропускний список підтримує чотири ключові топологічні інваріанти, які гарантують коректність навігації та логарифмічну швидкість:

1. **Інваріант строгого монотонного порядку (I1):** на кожному активному рівні `i ∈ [0, MaxLevel - 1]` послідовність ключів є строго зростаючою. Для будь-якого вузла `x`, якщо `x->forward[i] != NULL`, то `x->key < x->forward[i]->key`.
2. **Інваріант вертикального включення підмножин (I2):** якщо вузол `x` містить покажчик на рівні `k > 0`, він обов'язково присутній на всіх нижчих рівнях `0, 1, ..., k - 1`. Рівень 0 завжди містить повний набір усіх елементів структури.
3. **Інваріант вартового вузла (I3):** вартовий вузол `head` завжди має максимальну висоту `MaxLevel` та ініціалізується фіктивним ключем, який вважається меншим за будь-який можливий ключ користувача.
4. **Інваріант точності лічильника елементів (I4):** кількість фізичних вузлів, досяжних на нульовому рівні від `head->forward[0]` до кінцевого `NULL`, строго дорівнює значенню поля `size`.

## 2. Структури даних та організація пам'яті

### Опис вузла та списку

:::tabs
```c
/* Визначення констант конфігурації */
#define SKIPLIST_MAX_LEVEL 32
#define SKIPLIST_P_FACTOR 4  /* p = 1/4 */

/* Коди помилок операцій */
typedef enum {
    SKIPLIST_OK = 0,
    SKIPLIST_ERR_NOMEM = -1,
    SKIPLIST_ERR_NOTFOUND = -2,
    SKIPLIST_ERR_EXISTS = -3,
    SKIPLIST_ERR_INVALID = -4
} SkipListStatus;

/* Структура діагностичної статистики */
typedef struct SkipListStats {
    size_t total_nodes;          /* Загальна кількість вузлів */
    size_t current_max_level;    /* Поточний найвищий рівень */
    size_t total_memory_bytes;   /* Сумарна зайнята пам'ять у байтах */
    double avg_pointers_per_node;/* Середня кількість покажчиків на вузол */
    size_t level_counts[SKIPLIST_MAX_LEVEL]; /* Розподіл вузлів за рівнями */
} SkipListStats;

/* Структура вузла з гнучким масивом покажчиків */
typedef struct SkipNode {
    int key;                     /* Ключ елемента */
    int value;                   /* Корисне навантаження */
    int level;                   /* Висота вежі покажчиків даного вузла */
    struct SkipNode* forward[];  /* Масив покажчиків forward[0...level-1] */
} SkipNode;

/* Головний дескриптор пропускного списку */
typedef struct SkipList {
    int level;                   /* Поточний найвищий активний рівень */
    size_t size;                 /* Кількість збережених пар ключ-значення */
    SkipNode* head;              /* Вказівник на вартовий вузол */
} SkipList;
```
```cpp
// C++20 узагальнена шаблонна структура
#include <vector>
#include <memory>
#include <optional>
#include <functional>
#include <cstdint>
#include <array>

template <typename Key, typename Value, typename Compare = std::less<Key>>
class SkipList {
public:
    static constexpr size_t kMaxLevel = 32;
    static constexpr double kBranchingProb = 0.25;

    enum class Status {
        kOk = 0,
        kNotFound = -1,
        kAlreadyExists = -2,
        kOutOfMemory = -3,
        kInvalidArgument = -4
    };

    struct Stats {
        size_t total_nodes{0};
        size_t current_max_level{1};
        size_t total_memory_bytes{0};
        double avg_pointers_per_node{0.0};
        std::array<size_t, kMaxLevel> level_counts{};
    };

private:
    struct Node {
        Key key;
        Value value;
        std::vector<Node*> forward;

        Node(const Key& k, const Value& v, size_t level)
            : key(k), value(v), forward(level, nullptr) {}

        explicit Node(size_t level)
            : key{}, value{}, forward(level, nullptr) {}
    };

    size_t current_level_{1};
    size_t element_count_{0};
    std::unique_ptr<Node> head_;
    Compare comp_{};
};
```

### Розміщення в оперативній пам'яті (64-бітна архітектура)

У 64-бітних операційних системах пам'ять під вузол `SkipNode` у мові C формується як єдиний суцільний блок:
- Поле `key`: 4 байти (з вирівнюванням до 8 байтів або в парі з `value`).
- Поле `value`: 4 байти.
- Поле `level`: 4 байти (+ 4 байти вирівнювання для 8-байтного вирівнювання покажчиків).
- Масив `forward[]`: `8 · level` байтів (кожен покажчик займає 8 байтів).

Сумарний розмір пам'яті вузла висоти `k`:

```
Size(Node_k) = 16 + 8 · k байтів
```

Середній розмір одного вузла при `p = 1/4` (де `E[k] = 1.333`):

```
E[Size] = 16 + 8 · (4/3) = 16 + 10.67 ≈ 26.67 байтів
```

Для порівняння, вузол червоно-чорного дерева в 64-бітній системі містить: 3 покажчики (лівий, правий, батьківський = 24 байти), колір вузла (1 байт + 7 байтів вирівнювання = 8 байтів), ключ (4 байти) та значення (4 байти), що становить сумарно 40 байтів на вузол — на 50% більше, ніж у пропускного списку. Навіть із урахуванням накладних витрат пам'яті на заголовки блоків алокатора, пропускний список залишається однією з найбільш пам'ятеефективних впорядкованих динамічних структур даних у сучасному програмуванні.

## 3. Параметри конфігурації та інженерне налаштування

| Параметр | Типове значення | Допустимий діапазон | Опис та інженерний вплив |
| :--- | :--- | :--- | :--- |
| **`MaxLevel`** | `32` | `16...64` | Максимальна висота вежі покажчиків. Обчислюється як `ceil(log_{1/p} N_max)`. При `MaxLevel = 32` і `p = 1/4` список вміщує до `4³² ≈ 1.84 · 10¹⁹` елементів без ризику деградації. |
| **`p` (ймовірність)** | `0.25` (`1/4`) | `0.10...0.50` | Ймовірність підйому вузла на вищий рівень. Значення `1/4` зменшує витрати пам'яті на 33% порівняно з `1/2` при збереженні однакової швидкості пошуку. |

### Формула підбору MaxLevel для заданого N

Для гарантії логарифмічного часу пошуку без деградації максимальний рівень списку підбирають за формулою:

```
MaxLevel = ⌈ log_{1/p} N ⌉
```

Для типових розмірів баз даних:
- Для `N = 10⁶` (1 мільйон елементів): при `p = 0.5` `MaxLevel = 20`; при `p = 0.25` `MaxLevel = 10`.
- Для `N = 10⁹` (1 мільярд елементів): при `p = 0.5` `MaxLevel = 30`; при `p = 0.25` `MaxLevel = 15`.
- Для `N = 10¹²` (1 трильйон елементів): при `p = 0.5` `MaxLevel = 40`; при `p = 0.25` `MaxLevel = 20`.

Значення за замовчуванням `MaxLevel = 32` є універсальним для всіх 64-бітних додатків, покриваючи довільні обсяги пам'яті.

## 4. Специфікація базових функцій та методів

### 1. `skiplist_create` / Конструктор

Ініціалізує порожній пропускний список, створює вартовий вузол `head` із масивом покажчиків висоти `MaxLevel` та встановлює початковий рівень списку рівним 1.

:::tabs
```c
SkipList* skiplist_create(void);
```
```cpp
SkipList::SkipList();
```
:::

- **Параметри:** немає.
- **Повертає:** покажчик на створений список або `NULL` при нестачі пам'яті.
- **Перед-умови:** немає.
- **Після-умови:** `list->size == 0`, `list->level == 1`, усі `head->forward[0...MaxLevel-1] == NULL`.
- **Часова складність:** `O(MaxLevel)` у гіршому випадку (ініціалізація покажчиків вартового вузла).
- **Просторова складність:** `O(MaxLevel)` пам'яті.

---

### 2. `skiplist_search` / `find`

Виконує логарифмічний пошук значення за вказаним ключем.

:::tabs
```c
bool skiplist_search(const SkipList* list, int key, int* out_value);
```
```cpp
std::optional<Value> SkipList::find(const Key& key) const;
```
:::

- **Параметри:**
  - `list` / `this`: покажчик на валідний пропускний список.
  - `key`: шуканий ключ.
  - `out_value` (C): покажчик на змінну для запису знайденого значення (може бути `NULL`).
- **Повертає:**
  - C: `true`, якщо ключ знайдено; `false` — якщо ключ відсутній або `list == NULL`.
  - C++: `std::optional<Value>` зі знайденим значенням або `std::nullopt`.
- **Перед-умови:** `list != NULL`.
- **Після-умови:** стан списку залишається незмінним (константна операція читання).
- **Часова складність:**
  - Очікувана (Average): `O(log n)`.
  - Найгірша (Worst-case): `O(n)` (теоретичний випадок, коли всі вузли отримали рівень 1).

---

### 3. `skiplist_insert` / `insert`

Додає нову пару ключ-значення до списку. Якщо такий ключ уже існує, оновлює його значення на нове.

:::tabs
```c
bool skiplist_insert(SkipList* list, int key, int value);
```
```cpp
bool SkipList::insert(const Key& key, const Value& value);
```
:::

- **Параметри:**
  - `list` / `this`: покажчик на список.
  - `key`: ключ для вставки.
  - `value`: значення, асоційоване з ключем.
- **Повертає:**
  - `true`, якщо успішно вставлено новий вузол.
  - C: `true` (оновлено), `false` (помилка виділення пам'яті).
  - C++: `true` (створено новий елемент), `false` (оновлено наявний).
- **Перед-умови:** `list != NULL`.
- **Після-умови:** `size` збільшується на 1 (якщо ключ новий); елемент доступний для пошуку на всіх рівнях своєї висоти; інваріанти впорядкованості збережено.
- **Часова складність:**
  - Очікувана: `O(log n)`.
  - Найгірша: `O(n)`.
- **Просторова складність:** `O(k)` додаткової пам'яті для нового вузла висоти `k`.

---

### 4. `skiplist_delete` / `erase`

Видаляє елемент із заданим ключем зі списку та звільняє виділену під нього пам'ять.

:::tabs
```c
bool skiplist_delete(SkipList* list, int key);
```
```cpp
bool SkipList::erase(const Key& key);
```
:::

- **Параметри:**
  - `list` / `this`: покажчик на список.
  - `key`: ключ елемента для видалення.
- **Повертає:** `true`, якщо елемент успішно знайдено та видалено; `false`, якщо елемент із таким ключем відсутній.
- **Перед-умови:** `list != NULL`.
- **Після-умови:** `size` зменшується на 1; пам'ять вузла звільнено; якщо видалений вузол був єдиним на найвищому рівні, `level` списку автоматично зменшується.
- **Часова складність:**
  - Очікувана: `O(log n)`.
  - Найгірша: `O(n)`.

---

### 5. `skiplist_range` / `lower_bound` + Ітератори

Виконує послідовне сканування елементів у замкненому діапазоні ключів `[min_key, max_key]`.

:::tabs
```c
void skiplist_range(const SkipList* list, int min_key, int max_key,
                    void (*callback)(int k, int v, void* ctx), void* ctx);
```
```cpp
Iterator SkipList::lower_bound(const Key& key) const;
```
:::

- **Параметри:**
  - `min_key` / `key`: нижня межа діапазону.
  - `max_key`: верхня межа діапазону.
  - `callback`: функція зворотного виклику, що приймає чергову пару ключ-значення та контекст.
  - `ctx`: довільний вказівник користувача, що передається у `callback`.
- **Повертає:**
  - C: `void`.
  - C++: `Iterator`, що вказує на перший елемент із ключем `node->key >= key` (або `end()`, якщо такого немає).
- **Часова складність:** `O(log n + m)`, де `m` — кількість знайдених елементів у діапазоні.

---

### 6. `skiplist_destroy` / `clear` / Деструктор

Повністю видаляє всі вузли списку та звільняє виділену динамічну пам'ять.

:::tabs
```c
void skiplist_destroy(SkipList* list);
```
```cpp
void SkipList::clear() noexcept;
SkipList::~SkipList();
```
:::

- **Параметри:** `list` / `this`.
- **Повертає:** `void`.
- **Після-умови:** уся динамічна пам'ять вузлів повернута системі; покажчик `list` інвалідується (у C) або список переходить у стан `size == 0` (у C++).
- **Часова складність:** `O(n)` (однократний прохід по нульовому рівню).

---

### 7. `skiplist_validate` / `validate`

Діагностичний метод для верифікації цілісності топологічних інваріантів списку під час модульного тестування.

:::tabs
```c
bool skiplist_validate(const SkipList* list);
```
```cpp
bool SkipList::validate() const;
```
:::

- **Повертає:** `true`, якщо список повністю задовольняє всім інваріантам впорядкованості, зв'язності та висоти; `false` при виявленні порушень.
- **Часова складність:** `O(n · MaxLevel)`.

## 5. Специфікація розширених інтерфейсів

### 1. Пошук за порядковим номером (Ранговий Skip List)

Дозволяє знаходити елемент за його 1-індексованим порядковим номером у відсортованому списку або визначати ранг заданого ключа за логарифмічний час `O(log n)`.

:::tabs
```c
/* Отримання ключа за порядковим номером rank (1 <= rank <= size) */
bool skiplist_get_by_rank(const SkipList* list, size_t rank, int* out_key, int* out_value);

/* Отримання рангу ключа (повертає 0, якщо ключ відсутній) */
size_t skiplist_get_rank(const SkipList* list, int key);
```
```cpp
// C++ методи для роботи з рангами
std::optional<std::pair<Key, Value>> get_by_rank(size_t rank) const;
size_t get_rank(const Key& key) const;
```
:::

- **Часова складність:** `O(log n)` очікувана.
- **Просторова складність:** `O(1)` додаткової пам'яті (додатковий масив `span[]` у кожному вузлі).

### 2. Локалізований пошук (Finger Search)

Дозволяє виконувати пошук нового ключа, починаючи від раніше знайденого вузла-вказівника `finger`.

:::tabs
```c
/* Пошук ключа від збереженої позиції finger */
bool skiplist_finger_search(const SkipList* list, const SkipNode* finger,
                            int key, int* out_value);
```
```cpp
// C++ пошук від ітератора-вказівника
Iterator find_from(Iterator finger, const Key& key) const;
```
:::

- **Часова складність:** `O(log d)` очікувана, де `d` — відстань між ключем вказівника та шуканим ключем.

### 3. Масове завантаження та лінійна побудова (Bulk Loading)

Якщо вхідний масив елементів уже відсортовано за зростанням ключів, пропускний список можна сконструювати за детермінований лінійний час `O(n)` без випадкових кидків монети.

:::tabs
```c
/* Побудова списку з відсортованого масиву за O(n) */
SkipList* skiplist_bulk_load(const int* sorted_keys, const int* values, size_t n);
```
```cpp
// Конструктор діапазону для C++
template <typename InputIt>
SkipList(InputIt first, InputIt last);
```
:::

- **Часова складність:** `O(n)` гарантована.
- **Просторова складність:** `O(n)` пам'яті без проміжних перевиділень.

### 4. Серіалізація та відновлення стану

Послідовне збереження стану списку на диск та швидке відновлення без повторних операцій пошуку `O(log n)`.

:::tabs
```c
/* Збереження у бінарний потік */
bool skiplist_serialize(const SkipList* list, FILE* stream);

/* Відновлення зі збереженого потоку */
SkipList* skiplist_deserialize(FILE* stream);
```
```cpp
// C++ методи роботи з потоками
void serialize(std::ostream& os) const;
static SkipList deserialize(std::istream& is);
```
:::

- **Формат збереження:** бінарний заголовок із магічним числом, кількість елементів `size`, після чого послідовний масив пар `[key, value, level]` нульового рівня.
- **Часова складність:** `O(n)` для запису та читання.

### 5. Діагностика та збір метрик структури

Функція збору внутрішніх статистичних метрик дозволяє перевірити відповідність практичного розподілу рівнів теоретичному геометричному розподілу.

:::tabs
```c
/* Отримання повної статистики заповнення списку */
void skiplist_get_stats(const SkipList* list, SkipListStats* out_stats);
```
```cpp
// Метод отримання метрик у C++
Stats get_stats() const;
```
:::

- **Часова складність:** `O(n)` для обчислення точного обсягу зайнятої пам'яті та гістограми висот.

### 6. Префіксний пошук для довільних байтових ключів (Slice Seek)

У сховищах даних (RocksDB/LevelDB) ключі представлені зрізами байтів. Інтерфейс підтримує компаратор змінної довжини:

:::tabs
```c
/* Структура зрізу пам'яті для довільних байтових послідовностей */
typedef struct SkipSlice {
    const char* data;
    size_t size;
} SkipSlice;

/* Сигнатура користувацького компаратора */
typedef int (*SkipSliceComparator)(SkipSlice a, SkipSlice b);

/* Пошук першого ключа з заданим префіксом */
bool skiplist_seek_prefix(const SkipList* list, SkipSlice prefix,
                          SkipSliceComparator cmp, int* out_val);
```
```cpp
// C++ префіксний пошук за допомогою string_view
#include <string_view>

std::optional<Value> seek_prefix(std::string_view prefix) const;
```
:::

- **Часова складність:** `O(log n)` переходів, помножених на довжину спільного префікса при порівнянні.

## 8. Контракти потокобезпечності та винятки

### Гарантії безпеки винятків (C++ Exception Safety)

- **Конструктор:** базовий конструктор `SkipList()` не кидає винятків (`noexcept`), якщо виділення пам'яті під вартовий вузол успішне.
- **Пошук `find()` / `lower_bound()`:** строга гарантія без винятків (`noexcept` для базових типів ключів або з гарантією відсутності змін стану контейнера).
- **Вставка `insert()`:** сильна гарантія винятків (англ. *strong exception safety*). Якщо під час виділення пам'яті під новий вузол кидається `std::bad_alloc`, стан списку залишається повністю ідентичним тому, що був до виклику операції.
- **Видалення `erase()`:** не кидає винятків (`noexcept`), якщо компаратор не кидає винятків.

### Потокобезпечність (Concurrency Model)

1. **Однопотоковий базовий контракт:** базова реалізація не містить внутрішніх м'ютексів. Паралельні читання є цілком безпечними (`const` методи). Одночасне читання та запис або паралельні записи вимагають зовнішньої синхронізації (наприклад, `std::shared_mutex` із розділенням читачів і письменників).
2. **Неблокувальний контракт (Lock-Free Extension):** у промислових багатопотокових реалізаціях (`ConcurrentSkipListMap`) усі покажчики `forward[i]` оголошуються атомарними (`std::atomic<Node*>`). Модифікації здійснюються виключно через інструкції `atomic_compare_exchange_weak`. Читачі ніколи не блокують письменників і не блокуються ними.

### Порядок пам'яті для атомарних операцій (Memory Ordering)

Під час побудови неблокувальних пропускних списків у C/C++ застосовуються такі вимоги до бар'єрів пам'яті (англ. *memory barriers*):
- **Читання покажчиків `forward[i]`:** виконується з семантикою `std::memory_order_acquire` для гарантії того, що поля вузла (ключ і значення) будуть повністю видимі читачеві до моменту зчитування зв'язку.
- **Вставка нового вузла:** запис покажчика `update[i]->forward[i]` виконується з семантикою `std::memory_order_release`.
- **Логічне маркування:** виклик CAS для модифікації молодшого біта вимагає `std::memory_order_acq_rel`.

### Керування ресурсами (Memory Safety)

- **Володіння пам'яттю:** дескриптор `SkipList` одноосібно володіє пам'яттю всіх створених вузлів. Користувач відповідає за життєвий цикл корисного навантаження (якщо значення є зовнішніми вказівниками).
- **Запобігання подвійному звільненню (Double Free):** очищення виконується строго через прохід по покажчиках нульового рівня `forward[0]`. Оскільки кожен вузол обов'язково присутній на нульовому рівні рівно один раз, ризик подвійного виклику `free()` або пропуску вузла математично виключено.

## 9. Інтеграція користувацьких арена-алокаторів

У системах із високим темпом вставок стандартні системні виклики `malloc` призводять до значної фрагментації. Інтерфейс пропускного списку підтримує заміну стандартного алокатора на швидкий користувацький Арена-алокатор (англ. *Arena Allocator*):

:::tabs
```c
/* Контракт функцій виділення арени */
typedef void* (*SkipListAllocFn)(size_t bytes, void* user_data);

/* Створення списку з користувацьким алокатором пам'яті */
SkipList* skiplist_create_custom(SkipListAllocFn alloc_fn, void* user_data);
```
```cpp
// C++ створення пропускного списку з кастомним поліморфним алокатором (PMR)
#include <memory_resource>

template <typename Key, typename Value, typename Compare = std::less<Key>>
using pmr_skiplist = SkipList<Key, Value, Compare>;
// підтримка std::pmr::memory_resource* у конструкторі
```
:::

- **Вимоги до алокатора:** алокатор повинен повертати покажчики, вирівняні щонайменше за 8-байтною межею (на 64-бітних процесорах).
- **Звільнення пам'яті:** якщо алокатор підтримує пакетне скидання (англ. *arena reset/drop*), функція `skiplist_destroy` може бути замінена на моментальне скидання арени за `O(1)`.

## 11. Стан вузлів у неблокувальному життєвому циклі (State Machine)

Для запобігання гонкам даних у багатопотоковому режимі життєвий цикл кожного вузла проходить 4 послідовні фази:

1. **Ініціалізація (Unlinked/Fresh):** вузол виділено в пам'яті, встановлено його ключ, значення та висоту вежі. Вузол поки що невидимий для інших потоків.
2. **Активний стан (Active/Linked):** вузол успішно підключено до нульового та вищих рівнів через атомарний CAS. Доступний для пошуку й діапазонного обходу.
3. **Логічне видалення (Logically Deleted):** потік-видаляч встановив молодший біт покажчиків `forward[i]` в одиницю. Інші потоки, зустрівши такий вузол, ігнорують його значення та допомагають у фізичному видаленні. Нові вставки після цього вузла відхиляються.
4. **Фізичне відключення та утилізація (Unlinked/Retired):** попередник перенаправлений в обхід вузла через CAS. Вузол поміщається в чергу очікування епохального збирача сміття (RCU/Hazard Pointers) і остаточно звільняється після завершення всіх активних читачів.

## 12. Підтримка багатоверсійного паралелізму (MVCC в RocksDB/LevelDB)

У дискових рушіях на базі LSM-дерев пропускний список зберігає композитні внутрішні ключі:

```
InternalKey = UserKey (зростання) + SequenceNumber (спадання) + ValueType (Put/Delete)
```

Завдяки впорядкуванню за номером послідовності `SequenceNumber` у зворотному порядку, новіші версії одного й того самого користувацького ключа `UserKey` завжди розташовуються у пропускному списку лівіше (раніше) за старіші.

Операція читання зі зрізом (англ. *Snapshot Read*) на момент послідовності `S` виконує звичайний пошук `lower_bound(UserKey, S)`. Перший знайдений запис гарантовано є найновішою валідною версією ключа на момент зрізу `S`, що забезпечує підтримку транзакційного читання без блокувань і без створення фізичних копій даних. Такий механізм робить пропускний список незамінним компонентом сучасних високонавантажених СУБД реального часу.
