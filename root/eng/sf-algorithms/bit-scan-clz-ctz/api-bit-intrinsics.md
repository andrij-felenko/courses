# 📋 Довідник бітових інтринсиків та бібліотеки C++20 <bit>

Низькорівневі операції бітового сканування, підрахунку провідних нулів та обчислення ваги Геммінга тривалий час залишалися поза офіційними стандартами мов програмування C та C++. Системні розробники були змушені або використовувати компіляторні інтринсики (вбудовані псевдофункції компілятора), або писати власні вставки мовою асемблера для кожної цільової мікроархітектури.

Із прийняттям стандарту C++20 мова отримала єдиний, безпечний за типами, вільний від прихованої невизначеної поведінки та повністю обчислюваний під час компіляції (`constexpr`) заголовок `<bit>`.

Нижче наведено вичерпний довідник із низькорівневих інтерфейсів бітових маніпуляцій для компіляторів GCC, Clang, MSVC та стандартної бібліотеки C++20.

---

### 1. Компіляторні інтринсики GCC та Clang

Компілятори сімейства GNU Compiler Collection (GCC) та LLVM/Clang надають розширення мови у вигляді вбудованих функцій із системним префіксом `__builtin_`. Вони не є звичайними функціями бібліотеки часу виконання: під час семантичного аналізу та генерації проміжного коду (Intermediate Representation, IR) компілятор замінює їх безпосередньо на відповідні апаратні інструкції цільового процесора (наприклад, `lzcnt`, `tzcnt` чи `popcnt`).

#### Підрахунок провідних нулів (Count Leading Zeros, CLZ)

:::tabs
```c
int __builtin_clz(unsigned int x);
int __builtin_clzl(unsigned long x);
int __builtin_clzll(unsigned long long x);
```
```cpp
template <std::unsigned_integral T>
[[nodiscard]] constexpr int countl_zero(T x) noexcept;
```
:::

- **Призначення:** Повертає кількість послідовних нульових бітів, починаючи від найстаршого значущого розряду (Most Significant Bit, MSB) ліворуч до першої знайденої одиниці.
- **Тип аргументу:** Лише беззнакові цілі типи відповідної розрядності. `unsigned int` має розрядність 32 біти на всіх сучасних платформах, `unsigned long` — 32 або 64 біти залежно від моделі даних операційної системи (32 біти в моделі LLP64 на Windows, 64 біти в моделі LP64 на Linux/macOS), `unsigned long long` — гарантовано 64 біти.
- **Поведінка на нульовому вході (`x = 0`):** **Сувора невизначена поведінка (Undefined Behavior) у C builtins; детерміновано повертає `digits` у C++20.**

#### Підрахунок кінцевих нулів (Count Trailing Zeros, CTZ)

:::tabs
```c
int __builtin_ctz(unsigned int x);
int __builtin_ctzl(unsigned long x);
int __builtin_ctzll(unsigned long long x);
```
```cpp
template <std::unsigned_integral T>
[[nodiscard]] constexpr int countr_zero(T x) noexcept;
```
:::

- **Призначення:** Повертає кількість послідовних нульових бітів, починаючи від наймолодшого розряду (Least Significant Bit, LSB, біт 0) праворуч до першої знайденої одиниці.
- **Тип аргументу:** Беззнакові цілі числа `unsigned int`, `unsigned long`, `unsigned long long`.
- **Поведінка на нульовому вході (`x = 0`):** **Сувора невизначена поведінка (Undefined Behavior) у C builtins; детерміновано повертає `digits` у C++20.**

#### Підрахунок кількості одиниць (Population Count / Hamming Weight)

:::tabs
```c
int __builtin_popcount(unsigned int x);
int __builtin_popcountl(unsigned long x);
int __builtin_popcountll(unsigned long long x);
```
```cpp
template <std::unsigned_integral T>
[[nodiscard]] constexpr int popcount(T x) noexcept;
```
:::

- **Призначення:** Обчислює сумарну кількість одиничних бітів у двійковому представленні числа.
- **Поведінка на нульовому вході (`x = 0`):** Повністю детермінована, повертає `0`.

#### Допоміжні бітові інтринсики

:::tabs
```c
int __builtin_ffs(int x);          /* Find First Set: індекс 1..32 першого встановленого біта (0, якщо x == 0) */
int __builtin_parity(unsigned int x); /* Біт парності: 1, якщо кількість одиниць непарна, інакше 0 */
```
```cpp
// В C++20 еквіваленти виражаються через стандартні шаблони
template <std::unsigned_integral T>
[[nodiscard]] constexpr int find_first_set(T x) noexcept {
    return x == 0 ? 0 : std::countr_zero(x) + 1;
}

template <std::unsigned_integral T>
[[nodiscard]] constexpr bool parity(T x) noexcept {
    return (std::popcount(x) % 2) != 0;
}
```
:::

#### Механізм і пастка оптимізації невизначеної поведінки на нулі

Головна небезпека використання `__builtin_clz` та `__builtin_ctz` у промисловому коді полягає у трактуванні нульового вхідного значення. Причина криється в історичній спадщині мікроархітектури Intel x86. Інструкція `BSF` (Bit Scan Forward), представлена в процесорі 80386, на нульовому вході виставляла прапорець нуля `ZF = 1`, але фізично залишала вміст цільового регістра незмінним або записувала туди проміжний стан зсувача.

Оскільки поведінка регістра була невизначеною на рівні кремнію, розробники компіляторів GCC та Clang зафіксували це як мовну невизначену поведінку (UB).

У внутрішньому представленні компілятора LLVM виклик `__builtin_clz(x)` перетворюється на внутрішній інтринсик:

```llvm
%res = call i32 @llvm.ctlz.i32(i32 %x, i1 true)
```

Другий параметр `i1 true` явно повідомляє оптимізатору LLVM, що значення `%x = 0` є недосяжним за контрактом програми. Це дозволяє модулю оптимізації (*LLVM Instruction Combiner*) приймати агресивні рішення:
1. Якщо компілятор виявляє математичну залежність, яка за певних умов призводить до виклику `__builtin_clz(0)`, він може оголосити весь блок коду недосяжним (*dead code elimination*) і повністю вирізати його з бінарного файлу;
2. Компілятор може викинути наступні перевірки на нуль або спотворити логіку умовних переходів, оскільки згідно зі стандартом програма гарантує ненульовий аргумент.

Щоб уникнути цього дефекту в мові C, розробник зобов'язаний створювати спеціальну захисну обгортку з явною перевіркою на нуль або використовувати інструкції процесора, які мають детерміновану поведінку.

### 2. Інтринсики Microsoft Visual C++ (MSVC)

У середовищі MSVC для платформи Windows доступ до апаратних інструкцій процесора надається через системний заголовок `<intrin.h>`. Філософія API компілятора Microsoft суттєво відрізняється від стилю GCC: замість повернення результату через значення функції базові інтринсики повертають логічний код успіху операції, а числовий індекс знайденого біта записують за переданим вказівником.

#### Специфікація базових інтринсиків сканування

| Інтринсик MSVC | Сигнатура | Опис дії | Результат на `Mask == 0` |
|---|---|---|---|
| `_BitScanForward` | `unsigned char _BitScanForward(unsigned long *Index, unsigned long Mask)` | Пошук індексу молодшого біта (від LSB до MSB) | Повертає `0`, пам'ять за `*Index` не модифікується |
| `_BitScanForward64` | `unsigned char _BitScanForward64(unsigned long *Index, unsigned __int64 Mask)` | 64-бітний пошук індексу молодшого біта | Повертає `0`, пам'ять за `*Index` не модифікується |
| `_BitScanReverse` | `unsigned char _BitScanReverse(unsigned long *Index, unsigned long Mask)` | Пошук індексу старшого біта (від MSB до LSB) | Повертає `0`, пам'ять за `*Index` не модифікується |
| `_BitScanReverse64` | `unsigned char _BitScanReverse64(unsigned long *Index, unsigned __int64 Mask)` | 64-бітний пошук індексу старшого біта | Повертає `0`, пам'ять за `*Index` не модифікується |

#### Прямі апаратні інтринсики сучасних розширень

Для процесорів із підтримкою сучасних розширень набору інструкцій (ABM, BMI1, SSE4.2) MSVC надає окремі функції прямого виклику:

| Інтринсик | Сигнатура | Апаратна команда | Результат на нулі |
|---|---|---|---|
| `__lzcnt` | `unsigned int __lzcnt(unsigned int x)` | `lzcnt` (32 біти) | Повертає `32` |
| `__lzcnt64` | `unsigned __int64 __lzcnt64(unsigned __int64 x)` | `lzcnt` (64 біти) | Повертає `64` |
| `__popcnt` | `unsigned int __popcnt(unsigned int x)` | `popcnt` (32 біти) | Повертає `0` |
| `__popcnt64` | `unsigned __int64 __popcnt64(unsigned __int64 x)` | `popcnt` (64 біти) | Повертає `0` |

Важливо враховувати, що `_BitScanReverse` повертає порядковий номер біта (від 0 до 31 або 63), тоді як `__lzcnt` повертає кількість нульових розрядів перед ним. Для переведення результату `_BitScanReverse` у формат CLZ необхідно виконати віднімання: `(31 - Index)`.

### 3. Стандартний заголовок C++20 `<bit>`

Стандарт C++20 остаточно уніфікував роботу з бітовими примітивами, ввівши бібліотечний заголовок `<bit>`. Він усунув усі недоліки компіляторних розширень, запропонувавши суворий математичний контракт із гарантованою типобезпекою.

#### Ключові інженерні принципи дизайну C++20 `<bit>`

1. **Сувора типізація через концепти:** Усі функції заголовка обмежені концептом `std::unsigned_integral`. Спроба передати знаковий тип (`int`, `int64_t`) або тип із плаваючою комою призводить до помилки компіляції (`static_assert`). Це захищає розробника від неоднозначностей зі знаковим бітом, знакопереносним арифметичним зсувом та доповняльним кодом.
2. **Гарантія обчислюваності під час компіляції (`constexpr`):** Будь-яка функція заголовка `<bit>` може виконуватися на етапі компіляції для обчислення розмірів статичних масивів, параметрів шаблонів або константних структур даних.
3. **Відсутність винятків (`noexcept`):** Жодна функція не генерує виняткових ситуацій.
4. **Повна детермінованість на граничних значеннях:** На нульовому вході поведінка кожної функції чітко визначена математичним стандартом. Невизначена поведінка повністю виключена.

#### Повний перелік функцій заголовка C++20 `<bit>`

| Функція | Математичне визначення | Результат для `x = 0` (ширина типу `W`) |
|---|---|---|
| `std::countl_zero(x)` | Кількість провідних нулів (CLZ, зліва направо від MSB) | `std::numeric_limits<T>::digits` (`W`) |
| `std::countl_one(x)` | Кількість провідних одиниць (зліва направо від MSB) | `0` |
| `std::countr_zero(x)` | Кількість кінцевих нулів (CTZ, справа наліво від LSB) | `std::numeric_limits<T>::digits` (`W`) |
| `std::countr_one(x)` | Кількість кінцевих одиниць (справа наліво від LSB) | `0` |
| `std::popcount(x)` | Кількість встановлених бітів (вага Геммінга) | `0` |
| `std::has_single_bit(x)` | Перевірка, чи є число точним степенем двійки `2ⁿ` | `false` |
| `std::bit_width(x)` | Мінімальна кількість бітів для запису числа `x` | `0` |
| `std::bit_floor(x)` | Найбільший степінь двійки, що не перевищує `x` | `0` |
| `std::bit_ceil(x)` | Найменший степінь двійки, не менший за `x` | `1` (якщо результат вміщується в тип) |
| `std::rotl(x, s)` | Циклічний зсув бітів регістра ліворуч на `s` розрядів | `0` |
| `std::rotr(x, s)` | Циклічний зсув бітів регістра праворуч на `s` розрядів | `0` |

#### Поведінка спеціальних функцій обчислення розрядності

- **`std::bit_width(x)`:** Якщо `x == 0`, функція повертає `0`. Для ненульового значення результат обчислюється як `1 + ⌊log₂(x)⌋`, що еквівалентно виразу `std::numeric_limits<T>::digits - std::countl_zero(x)`. Це дозволяє миттєво визначати необхідну кількість бітів для кодування діапазону значень у протоколах стиснення.
- **`std::bit_floor(x)`:** Повертає значення, де встановлено лише один найстарший біт числа `x`. Якщо `x == 0`, повертає `0`.
- **`std::bit_ceil(x)`:** Округлює число вгору до найближчого степеня двійки. Якщо результат перевищує максимальне значення типу `T`, поведінка функції є невизначеною в сенсі переповнення беззнакового типу (для уникнення цього слід перевіряти вхідне значення).

### 4. Трансляція компілятором у машинний код цільових архітектур

Сучасні компілятори транслюють виклики стандартних функцій C++20 `<bit>` в оптимальні поодинокі інструкції АЛП без створення проміжних викликів або накладних витрат (*Zero-Cost Abstraction*).

#### Асемблерний вихід для x86-64

На архітектурі x86-64 компілятор обирає машинний код залежно від прапорців цільової архітектури:
- За наявності розширень BMI1/ABM (прапорець `-mbmi -mlzcnt` або `-march=haswell` / `-march=x86-64-v3`):
  - `std::countl_zero(x)` транслюється в інструкцію `lzcnt rax, rdi`;
  - `std::countr_zero(x)` транслюється в інструкцію `tzcnt rax, rdi`;
  - `std::popcount(x)` транслюється в інструкцію `popcnt rax, rdi`.
- Для базової архітектури без BMI (старі процесори або дефолтний x86-64 baseline):
  - `std::countl_zero(x)` транслюється в послідовність інструкцій `bsr`, `xor` та умовного пересилання `cmovz` для коректної обробки нуля;
  - `std::popcount(x)` транслюється у виклик бібліотечної функції або табличну комбінацію зсувів.

#### Асемблерний вихід для ARM64 (AArch64)

В архітектурі ARM64 інструкції бітового пошуку є частиною базового набору:
- `std::countl_zero(x)` транслюється в одну команду `clz x0, x0`;
- `std::countr_zero(x)` транслюється у зв'язку з двох однотактових команд: `rbit x0, x0` (розгортання бітів задом наперед) та `clz x0, x0`;
- `std::popcount(x)` для скалярних регістрів транслюється через векторний блок NEON інструкцією `cnt v0.8b, v0.8b` із подальшим горизонтальним підсумовуванням `uaddlv h0, v0.8b`.

#### Асемблерний вихід для RISC-V

На процесорах RISC-V із розширенням Zbb:
- `std::countl_zero(x)` транслюється безпосередньо в команду `clz a0, a0`;
- `std::countr_zero(x)` транслюється в команду `ctz a0, a0`;
- `std::popcount(x)` транслюється в команду `cpop a0, a0`.

### 5. Практичний приклад: Безпечна сумісність у C та сучасний C++20

Нижче наведено практичний приклад реалізації поширених системних операцій (визначення кількості бітів для представлення числа та округлення розміру буфера пам'яті до степеня двійки) з ручною перевіркою граничних умов мовою C та за допомогою стандартного заголовка C++20:

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

/* Безпечне обчислення кількості провідних нулів у C з захистом від UB на нулі */
static inline uint32_t safe_countl_zero64(uint64_t x) {
    if (x == 0) {
        return 64;
    }
    return (uint32_t)__builtin_clzll(x);
}

/* Безпечне обчислення бітової ширини числа в C (аналог bit_width) */
static inline uint32_t safe_bit_width64(uint64_t x) {
    if (x == 0) {
        return 0;
    }
    return 64 - (uint32_t)__builtin_clzll(x);
}

/* Перевірка, чи є число степенем двійки в C (аналог has_single_bit) */
static inline bool safe_has_single_bit64(uint64_t x) {
    return x != 0 && (x & (x - 1)) == 0;
}

/* Округлення розміру буфера пам'яті вгору до найближчого степеня двійки */
static inline uint64_t safe_bit_ceil64(uint64_t x) {
    if (x <= 1) {
        return 1;
    }
    /* Захист від переповнення: якщо старший біт встановлений, округлити неможливо */
    if (x > (1ULL << 63)) {
        return 0;
    }
    int lz = __builtin_clzll(x - 1);
    return 1ULL << (64 - lz);
}
```
```cpp
#include <cstdint>
#include <bit>
#include <concepts>

// В C++20 всі операції доступні з коробки без необхідності ручних перевірок
template <std::unsigned_integral T>
[[nodiscard]] constexpr int get_leading_zeros(T val) noexcept {
    return std::countl_zero(val); // Повністю безпечно для 0: повертає розрядність типу
}

template <std::unsigned_integral T>
[[nodiscard]] constexpr int calculate_bit_width(T val) noexcept {
    return std::bit_width(val); // Повертає 0 для 0, інакше 1 + floor(log2(val))
}

template <std::unsigned_integral T>
[[nodiscard]] constexpr bool is_power_of_two(T val) noexcept {
    return std::has_single_bit(val); // Безпечно для 0: повертає false
}

template <std::unsigned_integral T>
[[nodiscard]] constexpr T round_up_allocation_size(T bytes) noexcept {
    return std::bit_ceil(bytes); // Обчислюється під час компіляції (constexpr)
}
```
:::

Використання заголовка C++20 `<bit>` усуває необхідність створення громіздких платформно-залежних макросів, гарантує повну безпеку від дефектів оптимізації компілятора та забезпечує максимальну апаратну швидкодію на будь-якому цільовому процесорі.
