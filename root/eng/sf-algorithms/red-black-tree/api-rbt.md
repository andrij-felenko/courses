# 📋 Довідник API та специфікація червоно-чорного дерева

Специфікація публічного та внутрішнього інтерфейсу червоно-чорного дерева (Red-Black Tree), детальний аналіз внутрішніх структур даних, алгоритмічної складності, оптимізацій пам'яті та порівняльний аналіз із суміжними збалансованими структурами даних.

## 1. Публічний контракт операцій

Нижче наведено таблицю базових операцій, які надає типовий модуль абстрактного типу даних (ADT) червоно-чорного дерева.

| Назва операції | Сигнатура (C-стиль) | Опис та семантика | Часова складність |
| :--- | :--- | :--- | :--- |
| `rbtree_create` | `RBTree* rbtree_create(int (*cmp)(const void*, const void*))` | Створює й ініціалізує нове порожнє червоно-чорне дерево із вказаною функцією порівняння `cmp`. Створює фіктивний листок `nil`. | `O(1)` |
| `rbtree_destroy` | `void rbtree_destroy(RBTree *tree)` | Рекурсивно вивільняє пам'ять усіх вузлів дерева, включаючи фіктивний вузол `nil` та структуру дерева. | `O(n)` |
| `rbtree_insert` | `RBNode* rbtree_insert(RBTree *tree, void *key, void *value)` | Шукає позицію для нового ключа, створює новий червоний вузол, вставляє його за правилами BST і викликає `rbtree_insert_fixup` для відновлення інваріантів. | `O(log n)` |
| `rbtree_delete` | `void* rbtree_delete(RBTree *tree, const void *key)` | Вилучає вузол із відповідним ключем із дерева, за потреби заміщуючи його наступником, і викликає `rbtree_delete_fixup` при вилученні чорного вузла. Повертає вказівник на збережене значення. | `O(log n)` |
| `rbtree_find` | `RBNode* rbtree_find(const RBTree *tree, const void *key)` | Здійснює класичний бінарний пошук за ключем у дереві. Повертає вказівник на знайдений вузол або `tree->nil`, якщо ключ відсутній. | `O(log n)` |
| `rbtree_min` | `RBNode* rbtree_min(const RBTree *tree, RBNode *x)` | Повертає найлівіший вузол у піддереві з коренем `x`. | `O(log n)` |
| `rbtree_max` | `RBNode* rbtree_max(const RBTree *tree, RBNode *x)` | Повертає найправіший вузол у піддереві з коренем `x`. | `O(log n)` |
| `rbtree_successor`| `RBNode* rbtree_successor(const RBTree *tree, RBNode *x)` | Повертає вузол із найменшим ключем, більшим за `x->key` (наступник в ітераційному порядку). | `O(log n)` |
| `rbtree_predecessor`| `RBNode* rbtree_predecessor(const RBTree *tree, RBNode *x)` | Повертає вузол із найбільшим ключем, меншим за `x->key` (попередник в ітераційному порядку). | `O(log n)` |

## 2. Покроковий опис семантики операцій

### 2.1. `rbtree_create`
- **Прекондиція:** Вказівник на функцію порівняння `cmp` повинен бути коректним або `NULL` (для стандартного порівняння цілих чисел).
- **Посткондиція:** Створюється об'єкт `RBTree`, у якому вказівник `nil` посилається на динамічно виділений чорний вузол, а `root` посилається на `nil`.
- **Помилки:** При невдалому виділенні пам'яті повертається `NULL`.

### 2.2. `rbtree_insert`
- **Прекондиція:** Вказівники `tree` та `key` є коректними й не дорівнюють `NULL`.
- **Алгоритм:** Здійснюється спуск від кореня до листків для знаходження позиції вставки. Створюється новий червоний вузол `z` з посиланнями на `tree->nil`. Вузол зв'язується з батьком `y`. Після цього викликається `rbtree_insert_fixup(tree, z)`.
- **Обробка дублікатів:** При спробі вставити ключ, який вже існує у дереві, семантика контейнерів унікальних ключів (`std::set` / `std::map`) оновлює корисне навантаження `value` без створення нового вузла або повертає помилку `EEXIST`. Контейнери з дублікатами (`std::multimap`) розміщують новий елемент у правому піддереві однакових ключів.
- **Гарантія:** Вставка виконує не більше 2 поворотів і завершується за час `O(log n)`.

### 2.3. `rbtree_delete`
- **Прекондиція:** Дерево існуюче, ключ знайдено серед вузлів.
- **Алгоритм:** Якщо вузол має менше двох дітей, він вилучається безпосередньо. Якщо вузол має двох дітей, шукається його наступник `y` (найменший вузол у правому піддереві). Значення `y` копіюється у вилучений вузол, а сам `y` вилучається. Якщо колір вилученого вузла був чорним, викликається `rbtree_delete_fixup` для ліквідації подвійного чорного вузла.
- **Гарантія:** Вилучення виконує не більше 3 поворотів і завершується за `O(log n)`.

### 2.4. `rbtree_successor` та `rbtree_predecessor`
- **Семантика пошуку наступника:** Якщо праве піддерево вузла `x` не дорівнює `nil`, наступником є найлівіший вузол у правому піддереві (`rbtree_min(x->right)`). Якщо ж праве піддерево порожнє, здійснюється підйом вгору за батьківськими вказівниками доти, доки поточний вузол не виявиться лівою дитиною свого батька. Перший такий батьківський вузол і є наступником.
- **Семантика пошуку попередника:** Дзеркальна логіка. Якщо ліве піддерево не порожнє, повертається найправіший вузол у лівому піддереві (`rbtree_max(x->left)`). Інакше підйом вгору шукає першого батька, для якого поточний вузол є правою дитиною.

## 3. Внутрішні процедури балансування

Операції балансування гарантують збереження 5 інваріантів червоно-чорного дерева без зміни порядкового слідування елементів у бінарному дереві пошуку.

```
                  Left-Rotate(tree, x)
        x                                 y
       / \                              /   \
      α   y        -------------->     x     γ
         / \       <--------------    / \
        β   γ     Right-Rotate(tree, y)  α   β
```

### 3.1. `left_rotate(tree, x)`
- **Вхідні дані:** Дерево `tree`, вузол `x`, де `x->right != tree->nil`.
- **Семантика:** Права дитина `y` стає новим коренем піддерева. Ліве піддерево `β` вузла `y` стає новим правим піддеревом вузла `x`. Батьківські вказівники переставляються відповідно.
- **Складність:** `O(1)` за часом та `O(1)` за пам'яттю (зміна точно 6 вказівників).

### 3.2. `right_rotate(tree, y)`
- **Вхідні дані:** Дерево `tree`, вузол `y`, де `y->left != tree->nil`.
- **Семантика:** Ліва дитина `x` стає новим коренем піддерева. Праве піддерево `β` вузла `x` стає новим лівим піддеревом вузла `y`.
- **Складність:** `O(1)` за часом та `O(1)` за пам'яттю.

### 3.3. `rbtree_insert_fixup(tree, z)`
- **Вхідні дані:** Щойно вставлений червоний вузол `z`.
- **Цикл:** Виконується доки `z->parent` є червоним вузлом.
- **Гарантія:** Виконує не більше 2 поворотів за весь час вставки. Після завершення корінь дерева примусово фарбується у чорний колір.

### 3.4. `rbtree_delete_fixup(tree, x)`
- **Вхідні дані:** Вузол `x`, який отримав додаткову «чорноту» (Double Black) після вилучення чорного вузла.
- **Цикл:** Просуває подвійну чорноту вгору за 4 випадками конфігурацій брата (Sibling).
- **Гарантія:** Виконує не більше 3 поворотів за весь час вилучення.

## 4. Складові пам'яті та оверхед структур даних

Структура кожного вузла червоно-чорного дерева вимагає збереження наступних полів:

1. `key` — ключ пошуку (розмір залежить від типу даних `T`).
2. `value` — корисне навантаження або вказівник на дані.
3. `left` — вказівник на лівого сина (8 байтів на 64-бітній архітектурі).
4. `right` — вказівник на правого сина (8 байтів).
5. `parent` — вказівник на батька (8 байтів).
6. `color` — колір вузла (1 біт).

На 64-бітних системах через вирівнювання типів (alignment) поле `color` розширюється до 1 байта або використовує вирівнювання до 4/8 байтів.

🔧 **Оптимізація пам'яті (Pointer Tagging):**
Оскільки вказівники у 64-бітних системах вирівняні по 8-байтовій межі, нижні 3 біти адреси вказівника завжди дорівнюють `000₂`. Реалізації вищого рівня (зокрема `rbtree` в ядрі Linux) упаковують прапорець кольору безпосередньо у найнижчий біт вказівника на батьківський вузол (`parent_color`). Це дозволяє уникнути витрат додаткової пам'яті на окреме поле кольору.

```
Структура parent_color у Linux Kernel (lib/rbtree.c):
[63                                                    3 | 2 | 1 | 0]
|-------------------- Вказівник на parent ---------------| X | X | C |
                                                                   ^--- Color bit (0 = RED, 1 = BLACK)
```

## 5. Порівняльний аналіз із суміжними збалансованими структурами

У таблиці нижче наведено систематичне порівняння червоно-чорного дерева з іншими збалансованими структурами даних.

| Критерій порівняння | Червоно-чорне дерево (Red-Black) | AVL-дерево (AVL Tree) | B-дерево (B-Tree, t ≥ 2) | Декартове дерево (Treap) |
| :--- | :--- | :--- | :--- | :--- |
| **Максимальна висота `h`** | `2 log₂(n + 1)` | `1.44 log₂ n` | `log_t ((n+1)/2)` | В середньому `2 log₂ n`, розірвана у найгіршому випадкові |
| **Складність пошуку** | `O(log n)` | `O(log n)` (швидше на ~30% через меншу висоту) | `O(log n)` | `O(log n)` в середньому |
| **Повороти при вставці** | Не більше **2** | Не більше **2** | 0 (використовується Split) | В середньому `O(1)`, максимум `O(log n)` |
| **Повороти при вилученні** | Не більше **3** | До `O(log n)` (можливе каскадне балансування) | 0 (використовується Merge/Borrow) | В середньому `O(1)` |
| **Переважна область застосування** | Модулі пам'яті із частими оновленнями (`std::set`, `std::map`, CFS scheduler) | Пошуково-інтенсивні структури (рідкісні оновлення, часті запити) | Дискові накопичувачі, СУБД, файлові системи (Btrfs, NTFS) | Рандомізовані алгоритми, розрізи масивів (Implicit Treap) |

## 6. Гарантії безпеки та випадки виродження

Червоно-чорне дерево забезпечує найвищий рівень надійності серед усіх не-рандомізованих бінарних дерев пошуку. На відміну від звичайного бінарного дерева або декартового дерева (Treap), у якому вибір пріоритетів спирається на генератор випадкових чисел (що залишає теоретичну можливість найгіршого випадку `O(n)` при невдалому розродженні випадкових величин), червоно-чорне дерево виключає можливість виродження за будь-якого вхідного потоку ключів. Незалежно від того, чи надходять дані у строго впорядкованому, зворотному чи випадковому порядку, алгоритми відновлення інваріантів гарантують виконання операцій у межах логарифмічного часу `O(log n)`.

## 7. Потокобезпека та ітерація

У системних середовищах базова структура червоно-чорного дерева не містить внутрішніх засобів синхронізації. Паралельний доступ з кількох потоків вимагає зовнішнього узгодження (наприклад за допомогою rwlock або spinlock). Для неблокуючого ітерування за елементами у порядку зростання ключів використовується послідовний виклик `rbtree_min` з наступними операціями `rbtree_successor`. Кожен крок ітерації займає у середньому амортизований час `O(1)`, що дозволяє здійснювати повний обхід усього дерева з `n` елементів за `O(n)` часу.
