Коли інженер розгортає магістральну оптоволоконну мережу між сотнею промислових центрів або розводить доріжки живлення на багатошаровій друкованій платі з тисячами контактних площадок, перед ним постає фундаментальне топологічне обмеження: усі вузли мають бути гарантовано з'єднані між собою так, щоб інформаційний або електричний сигнал міг безперешкодно пройти від будь-якого джерела до будь-якого приймача, але загальна довжина ліній зв'язку була мінімально можливою. Будь-який зайвий кілометр кабелю або міліметр провідника збільшує фінансову собівартість системи, вносить додатковий опір та паразитну ємність, а виникнення замкнених петель у топології провокує виникнення широкомовних штормів у комутаторах та небезпечних паразитних струмів у контурах заземлення.

У комп'ютерних мережах Ethernet комутатори другого рівня моделі OSI не мають механізму обмеження часу життя пакетів (TTL, як у протоколі IP). Якщо між комутаторами утворюється замкнене кільце, широкомовний кадр (Broadcast Frame, наприклад, ARP-запит) починає нескінченно дублюватися і циркулювати всіма сегментами мережі. За лічені мілісекунди пропускна здатність каналів вичерпується на 100%, процесори комутаторів перевантажуються обробкою мільйонів дублікатів, і мережева інфраструктура повністю припиняє передавати корисний трафік. Тому будь-яка інженерна мережа вимагає строго ациклічної базової топології, яка з'єднує всі вузли, але повністю виключає замкнені контури.

Спроба розв'язати цю оптимізаційну задачу прямим комбінаторним перебором стикається з нездоланним бар'єром. За формулою Келі, кількість можливих кістякових дерев для повного неорієнтованого графа зі `100` вершин дорівнює `100⁹⁸ = 10¹⁹⁶`. Це число перевищує кількість елементарних частинок у всьому спостережуваному Всесвіті, тому повний перебір конфігурацій неможливо виконати на жодному суперкомп'ютері навіть за мільярди років безперервних обчислень. Нам потрібен детермінований алгоритмічний механізм, який знаходить точну мінімальну конфігурацію за мілісекунди без перегляду безглуздих комбінацій.

Таким механізмом є елегантна жадібна стратегія, яку 1956 року запропонував американський математик Джозеф Краскал: якщо на кожному кроці обирати глобально найдешевше доступне з'єднання, яке не замикає вже прокладені лінії у кільце, підсумкова конфігурація гарантовано утворить мінімальне кістякове дерево.

Детальний аналіз історичного контексту появи цієї ідеї, робіт чеських математиків Отакара Борувки та Войтєха Ярніка, а також зв'язку алгоритму із задачею комівояжера наведено у вставці [Історія відкриття алгоритму Краскала та жадібних мінімальних кістяків](root:sf-algorithms/kruskal-algorithm/hist-kruskal-mst.md).

## 1. Механізм жадібного злиття лісу дерев

Уявімо початковий стан мережі: жодної лінії зв'язку ще не змонтовано. Кожен із `V` серверів є повністю ізольованим вузлом. З точки зору теорії графів ми маємо початковий ліс із `V` тривіальних дерев, кожне з яких містить рівно одну вершину і не має ребер.

Вхідними даними для побудови є повний перелік усіх `E` потенційних каналів зв'язку між вузлами з відомою фіксованою вартістю прокладання (вагою ребра). Робота алгоритму розгортається у три чіткі послідовні фази:

1. **Глобальне впорядкування кандидатів:** Усі `E` ребер вхідного графа сортуються за зростанням їхньої ваги. Ми формуємо єдину лінійну чергу зв'язків: від найдешевшого до найдорожчого.
2. **Ітеративний жадібний відбір:** Алгоритм послідовно переглядає відсортований список ребер. Для кожного чергового ребра `(u, v)` перевіряється єдине структурне питання: чи належать вершини `u` та `v` до різних ізольованих компонент зв'язності?
   - Якщо вершини перебувають у **різних деревах**, це ребро є безпечним мостом: воно додається до підсумкового набору кістяка, а два раніше незалежних дерева зливаються в єдину більшу компоненту.
   - Якщо вершини вже перебувають в **одному й тому самому дереві**, між ними вже гарантовано існує альтернативний непрямий маршрут через раніше додані дешевші ребра. Додавання ребра `(u, v)` не додасть нових зв'язків для решти системи, але створить замкнену петлю. Таке ребро безповоротно відкидається.
3. **Раннє завершення (Early Termination):** Будь-яке дерево на `V` вершинах містить рівно `V - 1` ребро. Щойно кількість успішно включених ребер досягає величини `V - 1`, алгоритм миттєво припиняє роботу, ігноруючи решту важких ребер у черзі.

З цього механізму природно випливає термінологічний апарат дисципліни:

Підсумкова структура називається **кістяковим деревом** (від праслов'янського *\*kostь* — каркас, тверда основа, несуча опора; англійською *spanning tree*, від давньоанглійського *spannan* — з'єднувати, охоплювати). Вона повністю покриває (охоплює) всі вершини вихідного графа без надлишкових замкнених контурів.

Сам метод ухвалення рішень зветься **жадібним підходом** (від праслов'янського *\*žędati* — пристрасно прагнути, хапати найближче; англійською *greedy algorithm*), оскільки на кожному кроці алгоритм беззастережно обирає локально найвигідніший варіант, не прораховуючи можливих складних комбінацій на майбутніх кроках.

Заборонений для побудови стан називається **циклом** (від грецького *κύκλος* — коло, оберт, замкнений контур) — шляхом, початкова та кінцева вершини якого збігаються. Структура без таких контурів зветься **ациклічною** (грецький заперечний префікс *ἀ-* + *κύκλος*).

Окремі незв'язані між собою фрагменти графа називаються **компонентами зв'язності** (від латинського *componere* — складати разом, компонувати).

## 2. Покроковий розбір роботи алгоритму на прикладі

Розглянемо детальний числовий приклад для неорієнтованого графа з `V = 6` вершинами `{A, B, C, D, E, F}` та `E = 9` ребрами з різними вагами.

Початковий стан:
- Множина вершин: `{A, B, C, D, E, F}`;
- 6 ізольованих компонент: `{A}, {B}, {C}, {D}, {E}, {F}`;
- Список ребер після сортування за зростанням ваги:
  1. `(A, B)` — вага 1
  2. `(D, E)` — вага 2
  3. `(B, C)` — вага 3
  4. `(A, D)` — вага 4
  5. `(B, E)` — вага 5
  6. `(C, E)` — вага 6
  7. `(C, F)` — вага 7
  8. `(E, F)` — вага 8
  9. `(A, C)` — вага 9

Це демонструє фундаментальну властивість алгоритму Краскала: він нарощує кістяк одночасно з багатьох незалежних центрів (ліс дерев), на відміну від алгоритму Прима, який обов'язково росте суто з одного початкового вузла.
- **На ітерації 5:** Ребро `(B, E)` розглядається, коли між вершинами `B` та `E` вже існує шлях `B - A - D - E`. Додавання ребра створило б контур `B - A - D - E - B` із сумарною вагою `1 + 4 + 2 + 5 = 12`. Оскільки ребро `(B, E)` має найбільшу вагу в цьому контурі (5), воно відхиляється.
- **На ітерації 7:** Останнє необхідне ребро `(C, F)` приєднує вершину `F`, після чого кількість ребер досягає `V - 1 = 5`. Алгоритм негайно завершує виконання.

## 3. Теоретичне підґрунтя: властивості розрізу та циклу

Чому локально жадібний вибір гарантує глобально мінімальну сумарну вагу? У багатьох комбінаторних задачах (наприклад, у задачі про рюкзак або задачі комівояжера) жадібні рішення приводять до субоптимальних результатів. У випадку мінімального кістяка безпомилковість вибору забезпечується двома математичними властивостями: **властивістю розрізу (Cut Property)** та **властивістю циклу (Cycle Property)**.

### Властивість розрізу (безпечні ребра)

**Розрізом графа** (від праслов'янського *\*rězati* — розділяти, розсікати) називається розбиття множини вершин `V` на дві непорожні підмножини, що не перетинаються: `S` та `V \ S`.

Ребра, які одним кінцем належать `S`, а іншим — `V \ S`, утворюють так званий перетин розрізу `δ(S)`. Будь-яке зв'язне дерево зобов'язане містити хоча б одне ребро з перетину розрізу, інакше передача сигналу між `S` та `V \ S` буде фізично неможливою.

**Лема про розріз (Cut Property):** Нехай `(S, V \ S)` — довільний розріз графа `G`. Якщо ребро `e*` має строго мінімальну вагу серед усіх ребер, що перетинають цей розріз:

```
w(e*) < w(e)          [для всіх інших ребер e ∈ δ(S)]
```

тоді ребро `e*` обов'язково належить кожному мінімальному кістяковому дереву графа `G`.

Доведення базується на класичній техніці заміни ребер (Exchange Argument):
Припустимо від супротивного, що існує мінімальне кістякове дерево `T*`, яке не містить ребра `e*`. Оскільки `T*` зв'язує всі вершини, додавання `e*` до `T*` створить замкнений цикл `C`. Цей цикл починається в `S`, переходить у `V \ S` через `e*` і мусить повернутися назад у `S` через деяке інше ребро `e' ∈ δ(S)`.
Якщо ми видалимо ребро `e'` і замінимо його на `e*`, ми отримаємо нове кістякове дерево `T' = (T* \ {e'}) ∪ {e*}`. Обчислимо зміну ваги:

```
w(T') - w(T*)
= w(T* \ {e'} ∪ {e*}) - w(T*)     [за конструкцією нового дерева T']
= w(T*) - w(e') + w(e*) - w(T*)    [адитивність сумарної ваги]
= w(e*) - w(e')                    [скорочення доданків]
< 0                                [оскільки за умовою w(e*) < w(e')]
```

Отримано нерівність `w(T') < w(T*)`, що суперечить припущенню про мінімальність дерева `T*`. Отже, ребро `e*` обов'язково має бути частиною мінімального кістяка.

### Властивість циклу (відхилення надлишкових зв'язків)

Дуальною до властивості розрізу є властивість циклу, яка визначає точний критерій для відкидання ребер:
Якщо в графі існує довільний простий замкнений цикл `C`, то ребро `e_max` із максимальною вагою в цьому циклі не належить жодному мінімальному кістяковому дереву.

Видалення ребра `e_max` із дерева розбиває його на дві компоненти. Проте оскільки решта ребер циклу `C \ {e_max}` утворює альтернативний шлях між тими самими вершинами з меншими вагами, відновлення зв'язку через будь-яке з цих легших ребер дає дерево меншої сумарної ваги.

Алгоритм Краскала гармонійно поєднує обидва правила:
1. Коли він додає найлегше ребро між двома різними компонентами `A` та `B`, це ребро є мінімальним на розрізі `(A, V \ A)` (властивість розрізу).
2. Коли він відкидає ребро між вершинами з однієї компоненти, це ребро є найважчим у циклі, утвореному разом із раніше доданими дешевшими ребрами (властивість циклу).

![Властивості розрізу та циклу](/root/eng/sf-algorithms/kruskal-algorithm/img/cut-and-cycle-rule.svg)
*Два фундаментальні правила: ліворуч — властивість розрізу визначає безпечне ребро e*; праворуч — властивість циклу доводить безпечність відкидання найважчого ребра e_max.*

Строге виведення теореми єдиності мінімального кістяка та зв'язок із теорією графових матроїдів представлено у вставці [Математичне обґрунтування: лема про безпечне ребро та теорія розрізів](root:sf-algorithms/kruskal-algorithm/math-cut-property.md).

## 4. Система неперетинних множин як обчислювальний рушій

Головна інженерна трудність у практичній реалізації алгоритму полягає в перевірці: чи належать два кінці ребра `(u, v)` до однієї компоненти зв'язності?

Якщо виконувати цю перевірку наївно — запускати обхід у глибину (DFS) або в ширину (BFS) від вершини `u` після кожного кроку, — кожен запит вимагатиме `O(V)` операцій. На графі з `E` ребрами сумарний час перевірок складе `O(E · V)`. Для мережі зі `100 000` вершин та `1 000 000` ліній зв'язку це призведе до виконання `10¹¹` операцій, що займе десятки хвилин процесорного часу.

Алгоритм Краскала досягає блискавичної швидкості завдяки використанню спеціалізованої структури даних — **системи неперетинних множин** (Disjoint Set Union, DSU, або Union-Find).

DSU зберігає розбиття вершин на компоненти у вигляді лісу кореневих дерев, де кожен вузол зберігає номер свого батьківського вузла в масиві `parent`. Структура реалізує дві основні операції:
- `find(u)` — піднімається по ланцюжку батьківських вказівників угору до кореня дерева, який слугує канонічним ідентифікатором усієї компоненти;
- `union(u, v)` — об'єднує дві компоненти, роблячи корінь одного дерева дочірнім вузлом іншого.

Дві взаємодоповнюючі оптимізації забезпечують практично миттєве виконання цих операцій:

1. **Об'єднання за рангом (Union by Rank):** Масив `rank` зберігає оцінку висоти піддерева. Під час об'єднання дерево з меншим рангом завжди приєднується під корінь дерева з більшим рангом. Це гарантує, що висота дерева ніколи не перевищить логарифмічну межу `O(log V)`.
2. **Стиснення шляхів (Path Compression):** Під час виконання операції `find(u)` усі вузли, пройдені на шляху до кореня, переприв'язуються напряму до абсолютного кореня дерева. Під час наступного виклику пошук виконується рівно за один крок.

![Еволюція лісу компонент у DSU](/root/eng/sf-algorithms/kruskal-algorithm/img/dsu-forest-growth.svg)
*Еволюція структури DSU: від ізольованих одиничних коренів через об'єднання за рангом до майже плоского дерева глибини 1 завдяки стисненню шляхів.*

Математично доведено, що послідовність із `m` операцій над `n` елементами в DSU з рангами та стисненням шляхів виконується за час `O(m · α(n))`, де `α` — функція, обернена до функції Аккермана.

Функція Аккермана описує граничні швидкості зростання в теорії обчислюваності. Її перші рівні відповідають базовим арифметичним діям: перший рівень — додаванню, другий — множенню, третій — піднесенню до степеня, четвертий — тетрації (вежі степенів). Значення `A(4, 2) = 2⁶⁵⁵³⁶` — це число з приблизно `19 729` десятковими знаками, що незрівнянно перевершує кількість атомів у Всесвіті. Тому для будь-яких фізично можливих наборів даних значення оберненої функції не перевищує 4 (`α(V) ≤ 4`). Таким чином, перевірка циклічності та злиття компонент у алгоритмі Краскала виконуються за фактично константний час `O(1)`.

## 5. Аналіз часової та просторової складності

Розіб'ємо виконання алгоритму Краскала на окремі стадії та оцінимо їхній обчислювальний внесок:

1. **Ініціалізація структур даних:**
   Створення масиву ребер та початкового стану DSU (масиви `parent` та `rank` розміром `V`):

```
T_init = O(V)
```

2. **Сортування ребер:**
   Впорядкування масиву з `E` ребер за допомогою швидкого сортування (Quicksort) або сортування злиттям (Mergesort):

```
T_sort = O(E · log E)
```

Оскільки у простому графі без мультиребер кількість ребер не перевищує `V²`, маємо:

```
log(E) ≤ log(V²) = 2 · log(V) = O(log V)
```

Звідси вартість сортування набуває вигляду:

```
T_sort = O(E · log V)
```

3. **Обробка ребер у DSU:**
   Для кожного з `E` ребер виконується дві операції `find` (разом `2E` викликів), і щонайбільше `V - 1` операцій `union`:

```
T_dsu = O(E · α(V))
```

4. **Загальна часова складність:**
   Підсумовуючи всі складові:

```
T_total
= T_init + T_sort + T_dsu         [сумарний час усіх фаз]
= O(V) + O(E · log V) + O(E · α(V)) [підстановка оцінок]
= O(E · log V)                    [оскільки α(V) << log V]
```

Таким чином, головним обчислювальним вузьким місцем алгоритму Краскала є виключно початкове сортування ребер. Фаза перевірки та злиття компонент через DSU працює практично лінійно.

### Просторова складність

Алгоритм вимагає:
- Збереження списку ребер: `O(E)` пам'яті (у компактній формі масиву 16-байтних структур);
- Масивів `parent` (4 байти) та `rank` (1 байт) у DSU: `O(V)` пам'яті;
- Буфера для збереження відібраних ребер кістяка: `O(V)` пам'яті.

Загальні просторові витрати оцінюються як `O(V + E)`. Важливою перевагою є те, що всі структури даних є плоскими монолітними масивами, які виділяються єдиним блоком без фрагментації динамічної пам'яті.

## 6. Порівняння: Краскал проти Прима та Борувки

Вибір оптимального алгоритму для побудови мінімального кістяка залежить від щільності графа — співвідношення між кількістю ребер `E` та кількістю вершин `V`.

| Характеристика | Алгоритм Краскала | Алгоритм Прима (двійкова купа) | Алгоритм Прима (матриця) | Алгоритм Борувки |
|---|---|---|---|---|
| **Часова складність** | `O(E · log V)` | `O(E · log V)` | `O(V²)` | `O(E · log V)` |
| **Оптимальна щільність** | Розріджені графи (`E ≈ V`) | Розріджені та помірні графи | Надщільні графи (`E ≈ V²`) | Паралельні архітектури (GPU) |
| **Формат вхідних даних** | Плоский масив ребер | Списки суміжності | Матриця суміжності | Списки або масиви ребер |
| **Локальність кешу** | **Ідеальна** (послідовне читання) | Низька (стрибки по покажчиках) | Висока (послідовні рядки) | Середня |
| **Ранній вихід** | Так (на `V - 1` ребрі) | Ні (обхід усіх вершин) | Ні | Так (за `log V` раундів) |

![Порівняння алгоритмів кістякових дерев](/root/eng/sf-algorithms/kruskal-algorithm/img/density-tradeoff.svg)
*Криві продуктивності алгоритмів: алгоритм Краскала випереджає конкурентів на розріджених графах завдяки максимальній кеш-локальності, тоді як алгоритм Прима на матриці домінує на екстремально щільних графах.*

- **На розріджених графах (`E = O(V)`):** Алгоритм Краскала є беззаперечним лідером. Його вхідні дані зберігаються у вигляді суцільного масиву структур, що завантажується в процесорний кеш L1/L2 лінійними блоками. Апаратний блок випереджального читання (Prefetcher) заздалегідь підтягує наступні ребра, усуваючи простої конвеєра.
- **На надщільних графах (`E ≈ V² / 2`):** Сортування `V²` ребер вимагає `O(V² log V)` операцій. Тут алгоритм Прима на матриці суміжності працює за `O(V²)`, взагалі не сортуючи ребра.

## 7. Крайові випадки та архітектурні нюанси

У промисловій розробці граф рідко буває ідеальним. Реалізація алгоритму Краскала вимагає врахування таких тонкощів:

1. **Від'ємні ваги ребер:**
   На відміну від алгоритму Дейкстри для найкоротших шляхів, де від'ємні ваги призводять до нескінченних циклів або хибних результатів, алгоритм Краскала коректно працює з будь-якими від'ємними вагами. Якщо зменшити вагу кожного ребра на константу `C`, вага кожного можливого кістякового дерева зменшиться на фіксовану величину `(V - 1) · C`. Відносний порядок оптимальності конфігурацій залишається незмінним.
2. **Незв'язані графи (Мінімальний кістяковий ліс):**
   Якщо граф складається з `k` ізольованих компонент, зв'язати їх єдиним деревом неможливо. Алгоритм Краскала автоматично знайде мінімальне кістякове дерево для кожної компоненти окремо, сформувавши **мінімальний кістяковий ліс (Minimum Spanning Forest)** із `V - k` ребер. Перевірка `edge_count == V - 1` наприкінці слугує швидким тестом зв'язності графа.
3. **Паралельні ребра (мультиграфи) та петлі:**
   - Петлі виду `(u, u)` автоматично відкидаються, оскільки перевірка `find(u) == find(u)` негайно виявляє цикл.
   - Якщо між парою вершин існує кілька паралельних ліній різної вартості, сортування виставить найдешевшу лінію першою. Вона буде успішно включена в кістяк, а всі дорожчі дублікати відхиляться при наступних перевірках `find(u) == find(v)`.
4. **Цілочисельна оптимізація (Порозрядне сортування):**
   Якщо ваги ребер є невеликими цілими числами (наприклад, затримка зв'язку в діапазоні `0..65535`), замість швидкого сортування можна застосувати 16-бітний порозрядний сортувальник (Radix Sort). Це зменшує час фази сортування з `O(E log V)` до строго лінійного `O(E)`. У цьому разі загальний час алгоритму стає лінійним: `O(E · α(V)) ≈ O(E)`.

> 🔧 **Навіщо це.**
> Алгоритм Краскала лежить в основі багатьох інженерних систем:
> - **Комп'ютерні мережі:** Побудова базової безпетлевої топології у протоколах сімейства STP (Spanning Tree Protocol, IEEE 802.1D / 802.1w) для запобігання нескінченної циркуляції Ethernet-кадрів.
> - **Машинне навчання та аналіз даних:** Ієрархічна кластеризація методом поодинокого зв'язку (Single-Linkage Clustering). Якщо зупинити алгоритм Краскала, коли в лісі залишається рівно `k` дерев, ми отримаємо математично оптимальне розбиття точок на `k` природних кластерів.
> - **Наближені комбінаторні алгоритми:** 1.5-наближений алгоритм Крістофідеса для розв'язання метричної задачі комівояжера починає свою роботу з побудови мінімального кістяка алгоритмом Краскала.
> - **Процедурна генерація в іграх:** Створення лабіринтів (Maze Generation). Грати кімнат зіставляється сітка ребер із випадковими вагами; алгоритм Краскала будує ідеальний лабіринт із єдиним шляхом між будь-якими двома кімнатами без ізольованих глухих зон.
> - **Сегментація зображень:** Алгоритм Фельзеншвальба–Хаттенлохера розглядає пікселі зображення як вершини графа, а відмінності в кольорових градієнтах — як ваги ребер. Побудова кістяка з динамічним порогом об'єднання формує природні контури візуальних об'єктів.

Нижче наведено еталонну інженерну реалізацію алгоритму Краскала мовами C та C++ з використанням лінійного масиву ребер, DSU з рангами та стисненням шляхів, а також підтримкою раннього виходу.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>

// Опис зваженого ребра графа
typedef struct {
    uint32_t u;
    uint32_t v;
    int64_t weight;
} Edge;

// Система неперетинних множин (DSU)
typedef struct {
    uint32_t *parent;
    uint8_t *rank;
    uint32_t count;
} DisjointSet;

static bool dsu_create(DisjointSet *dsu, uint32_t n) {
    dsu->parent = (uint32_t *)malloc(n * sizeof(uint32_t));
    dsu->rank = (uint8_t *)calloc(n, sizeof(uint8_t));
    if (!dsu->parent || !dsu->rank) {
        free(dsu->parent);
        free(dsu->rank);
        return false;
    }
    for (uint32_t i = 0; i < n; ++i) {
        dsu->parent[i] = i;
    }
    dsu->count = n;
    return true;
}

static void dsu_destroy(DisjointSet *dsu) {
    free(dsu->parent);
    free(dsu->rank);
    dsu->parent = NULL;
    dsu->rank = NULL;
}

// Пошук кореневого представника зі стисненням шляху
static uint32_t dsu_find_root(DisjointSet *dsu, uint32_t i) {
    uint32_t root = i;
    while (root != dsu->parent[root]) {
        root = dsu->parent[root];
    }
    // Двопрохідне стиснення шляху: переприв'язка на знайдений корінь
    uint32_t curr = i;
    while (curr != root) {
        uint32_t next = dsu->parent[curr];
        dsu->parent[curr] = root;
        curr = next;
    }
    return root;
}

// Об'єднання двох множин за рангом
static bool dsu_unite(DisjointSet *dsu, uint32_t i, uint32_t j) {
    uint32_t root_i = dsu_find_root(dsu, i);
    uint32_t root_j = dsu_find_root(dsu, j);
    if (root_i == root_j) {
        return false; // Вершини в одній компоненті (утворення циклу)
    }

    if (dsu->rank[root_i] < dsu->rank[root_j]) {
        dsu->parent[root_i] = root_j;
    } else if (dsu->rank[root_i] > dsu->rank[root_j]) {
        dsu->parent[root_j] = root_i;
    } else {
        dsu->parent[root_j] = root_i;
        dsu->rank[root_i]++;
    }
    dsu->count--;
    return true;
}

// Компаратор для сортування масиву ребер
static int compare_edges(const void *a, const void *b) {
    const Edge *ea = (const Edge *)a;
    const Edge *eb = (const Edge *)b;
    if (ea->weight < eb->weight) return -1;
    if (ea->weight > eb->weight) return 1;
    return 0;
}

// Структура результату виконання
typedef struct {
    Edge *tree_edges;
    size_t num_edges;
    int64_t total_weight;
    bool is_connected;
} MstOutput;

MstOutput kruskal_find_mst(uint32_t num_vertices, Edge *edges, size_t num_edges) {
    MstOutput out = { NULL, 0, 0, false };
    if (num_vertices == 0) {
        out.is_connected = true;
        return out;
    }

    out.tree_edges = (Edge *)malloc((num_vertices - 1) * sizeof(Edge));
    if (!out.tree_edges && num_vertices > 1) {
        return out;
    }

    // Фаза 1: Глобальне сортування ребер
    qsort(edges, num_edges, sizeof(Edge), compare_edges);

    // Фаза 2: Ініціалізація DSU
    DisjointSet dsu;
    if (!dsu_create(&dsu, num_vertices)) {
        free(out.tree_edges);
        out.tree_edges = NULL;
        return out;
    }

    // Фаза 3: Жадібний відбір ребер
    for (size_t i = 0; i < num_edges; ++i) {
        if (dsu_unite(&dsu, edges[i].u, edges[i].v)) {
            out.tree_edges[out.num_edges++] = edges[i];
            out.total_weight += edges[i].weight;

            // Ранній вихід: кістяк набрано
            if (out.num_edges == num_vertices - 1) {
                break;
            }
        }
    }

    out.is_connected = (out.num_edges == num_vertices - 1);
    dsu_destroy(&dsu);
    return out;
}
```

```cpp
#include <vector>
#include <span>
#include <algorithm>
#include <cstdint>
#include <numeric>
#include <expected>

struct Edge {
    uint32_t u{0};
    uint32_t v{0};
    int64_t weight{0};

    [[nodiscard]] constexpr bool operator<(const Edge& other) const noexcept {
        return weight < other.weight;
    }
};

class DisjointSet {
public:
    explicit DisjointSet(uint32_t size)
        : parent_(size), rank_(size, 0), components_(size) {
        std::iota(parent_.begin(), parent_.end(), 0);
    }

    [[nodiscard]] uint32_t find(uint32_t node) noexcept {
        uint32_t root = node;
        while (root != parent_[root]) {
            root = parent_[root];
        }
        // Двопрохідне стиснення шляхів без рекурсії
        uint32_t curr = node;
        while (curr != root) {
            uint32_t nxt = parent_[curr];
            parent_[curr] = root;
            curr = nxt;
        }
        return root;
    }

    bool unite(uint32_t u, uint32_t v) noexcept {
        uint32_t root_u = find(u);
        uint32_t root_v = find(v);
        if (root_u == root_v) {
            return false; // Виявлено замкнений цикл
        }

        if (rank_[root_u] < rank_[root_v]) {
            parent_[root_u] = root_v;
        } else if (rank_[root_u] > rank_[root_v]) {
            parent_[root_v] = root_u;
        } else {
            parent_[root_v] = root_u;
            ++rank_[root_u];
        }
        --components_;
        return true;
    }

    [[nodiscard]] uint32_t component_count() const noexcept {
        return components_;
    }

private:
    std::vector<uint32_t> parent_;
    std::vector<uint8_t> rank_;
    uint32_t components_;
};

struct MstResult {
    std::vector<Edge> edges;
    int64_t total_weight{0};
    bool is_connected{false};
};

enum class GraphError {
    InvalidVertexIndex,
    EmptyGraph
};

[[nodiscard]] std::expected<MstResult, GraphError>
build_kruskal_mst(uint32_t num_vertices, std::span<Edge> edges) {
    if (num_vertices == 0) {
        return MstResult{{}, 0, true};
    }

    for (const auto& edge : edges) {
        if (edge.u >= num_vertices || edge.v >= num_vertices) {
            return std::unexpected(GraphError::InvalidVertexIndex);
        }
    }

    // Фаза 1: Сортування масиву ребер за зростанням ваги
    std::ranges::sort(edges);

    // Фаза 2: Ініціалізація DSU
    DisjointSet dsu(num_vertices);

    MstResult result;
    result.edges.reserve(num_vertices - 1);

    // Фаза 3: Жадібне об'єднання з раннім виходом
    for (const auto& edge : edges) {
        if (dsu.unite(edge.u, edge.v)) {
            result.edges.push_back(edge);
            result.total_weight += edge.weight;

            if (result.edges.size() == num_vertices - 1) {
                break;
            }
        }
    }

    result.is_connected = (result.edges.size() == num_vertices - 1);
    return result;
}
```
