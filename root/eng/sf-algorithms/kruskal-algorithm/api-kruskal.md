# 📋 Інтерфейс та контракт модуля побудови мінімального кістяка (Kruskal API)

Модуль `kruskal` надає низькорівневий та високорівневий програмний інтерфейс для знаходження мінімального кістякового дерева (Minimum Spanning Tree, MST) або мінімального кістякового лісу (Minimum Spanning Forest, MSF) на довільних зважених неорієнтованих графах. Архітектура модуля спроєктована з урахуванням сучасних вимог до системного програмування: нульові накладні витрати на абстракцію (Zero-Cost Abstractions), суворе розмежування володіння ресурсами, передбачувана робота з динамічною пам'яттю та повна відсутність прихованих виділень пам'яті на гарячому шляху виконання.

## 1. Архітектурні засади та моделі володіння пам'яттю

Під час проєктування інтерфейсу для алгоритмів на графах розробник стикається з вибором між двома основними моделями передачі даних:
1. **Модель із копіюванням (Copy-based):** Алгоритм самостійно дублює вхідний масив ребер, що забезпечує незмінність даних викликаючого коду, але подвоює пікове споживання оперативної пам'яті.
2. **Модель на місці (In-place):** Алгоритм приймає мутабельний зріз ребер і сортує їх безпосередньо у вихідному буфері.

Модуль `kruskal` реалізує компромісний підхід: інтерфейс C++ приймає мутабельний `std::span<Edge>`, що дозволяє уникнути зайвого дублювання гігабайтних масивів ребер у пам'яті. Якщо клієнтському коду необхідно зберегти вихідний порядок ребер, він створює копію до виклику або передає масив індексів.

У мові C модель виділення ресурсів базується на явному розмежуванні: викликаючий код володіє вхідним масивом `edges`, а функція `kruskal_compute_mst` виділяє рівно один монолітний блок пам'яті для збереження масиву `mst_edges` у структурі результату. Звільнення цього блоку покладається на парну функцію `kruskal_free_result`, що повністю виключає витоки пам'яті при дотриманні контракту.

### Вирівнювання та компонування структур у пам'яті

Для досягнення максимальної пропускної здатності шини пам'яті структура `Edge` скомпонована таким чином, щоб кожен елемент мав розмір рівно 16 байтів без прихованого проміжного заповнення (Padding Bytes):
- Байт 0..3: `uint32_t u` — індекс першої вершини (діапазон `0` до `2³² - 1`);
- Байт 4..7: `uint32_t v` — індекс другої вершини (діапазон `0` до `2³² - 1`);
- Байт 8..15: `int64_t weight` — 64-бітна знакова вага зв'язку.

Завдяки розміру в 16 байтів рівно 4 ребра вміщуються в один 64-байтний кеш-рядок (Cache Line) сучасних мікропроцесорів. Послідовне сканування такого масиву забезпечує максимальну ефективність блоку апаратного попереднього завантаження (Hardware Prefetcher).

## 2. Публічні типи даних та специфікація API

### Коди повернення та обробка помилок

Функції модуля гарантують безпеку від винятків (Strong Exception Safety у C++) або повертають явні коди помилок у стилі POSIX (у C):

| Ідентифікатор C | Значення C++ | Опис семантики |
|---|---|---|
| `KRUSKAL_OK` | `ErrorCode::Success` | Граф повністю зв'язаний; побудовано єдине мінімальне кістякове дерево з `V - 1` ребер. |
| `KRUSKAL_DISCONNECTED_FOREST` | `ErrorCode::DisconnectedForest` | Граф містить більше однієї компоненти; побудовано мінімальний кістяковий ліс із `V - k` ребер. |
| `KRUSKAL_ERR_INVALID_VERTEX` | `ErrorCode::InvalidVertexIndex` | Одне з ребер містить індекс вершини, що перевищує або дорівнює переданому значенню `num_vertices`. |
| `KRUSKAL_ERR_NULL_POINTER` | `ErrorCode::NullPointer` | Передано нульовий покажчик замість обов'язкового масиву ребер або структури графа. |
| `KRUSKAL_ERR_NO_MEMORY` | `ErrorCode::AllocationFailure` | Не вдалося виділити пам'ять під внутрішні масиви `parent` та `rank` системи DSU. |

:::tabs
```c
#ifndef KRUSKAL_API_H
#define KRUSKAL_API_H

#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

// Статуси виконання алгоритму
typedef enum {
    KRUSKAL_OK = 0,
    KRUSKAL_DISCONNECTED_FOREST = 1,
    KRUSKAL_ERR_INVALID_VERTEX = -1,
    KRUSKAL_ERR_NULL_POINTER = -2,
    KRUSKAL_ERR_NO_MEMORY = -3
} KruskalStatus;

// Компактна структура представлення ребра
typedef struct {
    uint32_t u;
    uint32_t v;
    int64_t weight;
} KruskalEdge;

// Опис графа для передачі в модуль
typedef struct {
    uint32_t num_vertices;
    size_t num_edges;
    KruskalEdge *edges;
} KruskalGraph;

// Результат побудови мінімального кістяка
typedef struct {
    KruskalEdge *mst_edges;      // Динамічно виділений масив відібраних ребер
    size_t edge_count;           // Кількість ребер у дереві або лісі
    int64_t total_weight;        // Сумарна вага кістяка
    uint32_t num_components;     // Кількість отриманих компонент зв'язності
} KruskalResult;

/**
 * @brief Обчислює мінімальне кістякове дерево або ліс графа методом Краскала.
 * 
 * @param[in]  graph   Вказівник на ініціалізовану структуру графа. Масив edges буде відсортовано.
 * @param[out] result  Вказівник на структуру, куди записуються результати обчислення.
 * 
 * @return KruskalStatus Код результату операції.
 */
KruskalStatus kruskal_compute_mst(KruskalGraph *graph, KruskalResult *result);

/**
 * @brief Звільняє динамічні ресурси, виділені під час обчислення результату.
 * 
 * @param[in,out] result Вказівник на структуру результату для очищення.
 */
void kruskal_free_result(KruskalResult *result);

#ifdef __cplusplus
}
#endif

#endif // KRUSKAL_API_H
```
```cpp
#ifndef KRUSKAL_API_HPP
#define KRUSKAL_API_HPP

#include <cstdint>
#include <cstddef>
#include <span>
#include <vector>
#include <expected>

namespace algorithms::graphs {

// Компактне представлення ребра з підтримкою операцій порівняння
struct Edge {
    uint32_t u{0};
    uint32_t v{0};
    int64_t weight{0};

    [[nodiscard]] constexpr bool operator==(const Edge&) const noexcept = default;
    [[nodiscard]] constexpr bool operator<(const Edge& other) const noexcept {
        return weight < other.weight;
    }
};

// Типізовані коди помилок
enum class ErrorCode {
    InvalidVertexIndex,
    EmptyGraph,
    AllocationFailure
};

// Результат побудови кістяка з автоматичним керуванням пам'яттю
struct MstResult {
    std::vector<Edge> edges;
    int64_t total_weight{0};
    uint32_t num_components{1};
    bool is_fully_connected{true};
};

/**
 * @brief Знаходить мінімальне кістякове дерево на множині ребер.
 * 
 * @param num_vertices Загальна кількість вершин графа (індекси від 0 до num_vertices - 1).
 * @param edges        Вхідний зріз ребер. Сортується безпосередньо за місцем (in-place).
 * 
 * @return std::expected<MstResult, ErrorCode> Результат або код помилки.
 */
[[nodiscard]] std::expected<MstResult, ErrorCode>
compute_mst(uint32_t num_vertices, std::span<Edge> edges);

} // namespace algorithms::graphs

#endif // KRUSKAL_API_HPP
```

## 3. Детальний контракт поведінки та інваріанти

### Передмови (Preconditions)

1. **Індексація вершин:** Усі ідентифікатори вершин у полях `u` та `v` кожного ребра мають задовольняти нерівність `0 ≤ u, v < num_vertices`. Якщо виявлено ребро з некоректним індексом, функція негайно повертає статус `KRUSKAL_ERR_INVALID_VERTEX` (`ErrorCode::InvalidVertexIndex`) і не змінює стан пам'яті.
2. **Невпорядкованість вхідних даних:** Вхідний масив `edges` може містити ребра у довільному порядку. Він не зобов'язаний бути відсортованим до виклику функції.
3. **Мультиграфи та кратні ребра:** Допускається наявність довільної кількості паралельних ребер між будь-якою парою вершин. Алгоритм гарантує, що до кістяка потрапить найдешевше з них, а всі інші будуть проігноровані без додаткових перевірок з боку користувача.
4. **Петлі (Self-loops):** Допускаються ребра виду `(u, u)`. Вони автоматично відсікаються DSU на першому ж кроці й не впливають на коректність результату.
5. **Знаковість ваг:** Дозволяються будь-які значення ваг: додатні, нульові та строго від'ємні. Алгоритм використовує коректне знакове порівняння `int64_t`.

### Післямови та гарантії результату (Postconditions)

1. **Ациклічність:** Масив відібраних ребер `mst_edges` гарантовано не містить замкнених циклів, тобто формує ациклічний граф (ліс або дерево).
2. **Зв'язність та кількість компонент:**
   - Якщо вхідний граф був зв'язаним, результуючий масив містить рівно `num_vertices - 1` ребер, `num_components == 1`, а статус рівний `KRUSKAL_OK`.
   - Якщо вхідний граф складався з `k > 1` ізольованих компонент зв'язності, результат містить рівно `num_vertices - k` ребер, `num_components == k`, а статус рівний `KRUSKAL_DISCONNECTED_FOREST`.
3. **Мінімальність:** Сума ваг `total_weight` є строго мінімальною серед усіх можливих кістякових лісів графа.
4. **Цілісність даних при помилках:** Якщо функція повертає код помилки (наприклад, через брак пам'яті), усі частково виділені проміжні ресурси автоматично звільняються, виключаючи витоки.

### Багатопоточність та потокова безпека (Thread Safety)

- **Конкурентне читання:** Декілька потоків можуть одночасно викликати функцію над незалежними буферами без будь-якої міжпотокової синхронізації або блокувань (Reentrant / Pure Function).
- **Спільний масив:** Одночасна передача одного й того самого масиву `edges` з різних потоків є небезпечною (Data Race), оскільки функція виконує сортування пам'яті на місці.
- **Відсутність глобального стану:** Модуль не використовує статичних або глобальних змінних, прихованих синглтонів чи нелокальних структур даних.

## 4. Інтеграція з іншими графовими структурами даних

У реальних інженерних застосунках вхідні дані графа можуть надходити у вигляді матриці суміжності або списків суміжних вершин. Для використання API Краскала необхідно попередньо перетворити ці структури на плоский масив ребер:

1. **Із матриці суміжності:** Оскільки граф є неорієнтованим, достатньо виконати ітерацію лише над верхнім трикутником матриці (`i < j`), виключаючи головну діагональ. Це запобігає дублюванню ребер ще на етапі ініціалізації.
2. **Із списків суміжності:** Під час обходу списків додаються лише ті ребра `(u, v)`, для яких виконується умова `u < v`. Це гарантує створення рівно одного ребра на кожну пару зв'язаних вершин.

Приклад виклику в клієнтському коді мовами C та C++:

:::tabs
```c
#include "kruskal_api.h"
#include <stdio.h>

void run_example(void) {
    KruskalEdge edges[] = {
        {0, 1, 10}, {0, 2, 6}, {0, 3, 5},
        {1, 3, 15}, {2, 3, 4}
    };
    KruskalGraph graph = { 4, 5, edges };
    KruskalResult result;

    if (kruskal_compute_mst(&graph, &result) == KRUSKAL_OK) {
        printf("Кістяк знайдено, вага: %lld\n", (long long)result.total_weight);
        kruskal_free_result(&result);
    }
}
```
```cpp
#include "kruskal_api.hpp"
#include <iostream>
#include <vector>

void run_example() {

    };
```
