Бортовий комп'ютер космічного апарата або авіаційної системи керування польотом отримує 50 000 телеметричних показників на секунду від трикратно або п'ятикратно резервованих каналів датчиків кутової швидкості. Кожен окремий канал зазнає впливу космічного випромінювання, температурного дрейфу, електромагнітних завад та шуму квантування. Системі необхідно на кожному такті синхронізації миттєво визначити узгоджене значення польотного параметра, якому довіряє абсолютна більшість справних вузлів (понад 50% усіх голосів), і відкинути хибні сигнали скомпрометованих або пошкоджених модулів.

Аналогічна інженерна потреба виникає у мережевих процесорах магістральних комутаторів на швидкості 100 Гбіт/с, де апаратний модуль eBPF або SmartNIC аналізує потік із 30 мільйонів мережевих пакетів на секунду. Оператору зв'язку необхідно в реальному часі визначити, чи не захопила одна конкретна IP-адреса понад половину всієї смуги пропускання каналу під час масованої DDoS-атаки.

У цих високошвидкісних системах застосування стандартних підходів стикається з трьома нездоланними інженерними обмеженнями:

1. **Обмеження динамічної пам'яті**: Традиційна хеш-таблиця частот вимагає виділення динамічної пам'яті в купі під кожен новий унікальний ключ `O(U)`. Для потоку з мільйонами різних IP-адрес або ідентифікаторів це призводить до вичерпання статичної пам'яті SRAM мережевого чипа, зупинок на збирання сміття та непрогнозованих затримок обробки.
2. **Неможливість повторного читання (Single-pass constraint)**: Мережеві пакети та сигнали авіоніки пролітають через конвеєр один-єдиний раз і безповоротно зникають із буферів. Алгоритми на зразок сортування чи Quickselect вимагають збереження всього масиву в оперативній пам'яті для довільного доступу до елементів, що фізично неможливо при безперервному потоці даних.
3. **Неприпустимість статистичної похибки**: Ймовірнісні методи випадкової вибірки можуть пропустити слабку більшість (наприклад, 51% голосів) через дисперсію вибірки, що неприпустимо у критичних системах авіаційної безпеки або фінансового клірингу.

Потрібна детермінована обчислювальна схема, яка здатна знайти елемент абсолютної більшості у потоці довільної довжини `N` рівно за один послідовний прохід, використовуючи строго фіксовану пам'ять `O(1)` — лише дві скалярні змінні у процесорних регістрах.

## Механізм взаємного парного знищення

Щоб зрозуміти, як знайти лідера без збереження лічильників для всіх учасників, розглянемо фізичну аналогію зали з виборцями.

Нехай у залі зібралося `N` делегатів, кожен із яких підтримує певного кандидата. Якщо серед них є кандидат, який має абсолютну більшість, це означає, що кількість його прихильників строго перевищує половину всієї зали: `m > N / 2`. Усі інші кандидати разом узяті мають менше половини голосів: `N - m < N / 2`.

Введемо просте правило взаємного вибуття: будь-які два делегати, які голосують за *різних* кандидатів, беруться за руки та разом залишають залу. Що відбудеться з підсумковим балансом сил?

* Кожне таке парне вибуття забирає рівно двох делегатів.
* У найгіршому для лідера випадку кожен вибулий опонент забирає із собою одного прихильника більшості.
* Оскільки опонентів усього `N - m`, вони зможуть забрати із собою щонайбільше `N - m` прихильників лідера.
* Кількість прихильників лідера, які обов'язково залишаться в залі після того, як усі опоненти вичерпаються, становить:

```text
m - (N - m)
= 2 · m - N              [розкриття дужок]
> 2 · (N / 2) - N        [оскільки m > N / 2]
= N - N                  [множення 2 · N/2]
= 0                      [результат віднімання]
```

Оскільки залишок строго більший за нуль, делегати меншості закінчаться раніше, ніж прихильники більшості. У залі неминуче залишаться лише прихильники справжнього переможця.

Цей принцип попарної анігіляції нерівних елементів лежить в основі класичного методу, відомого як **алгоритм голосування більшості Бойєра — Мура** (Boyer–Moore majority vote algorithm; від латинського *major* — більший, та англійських прізвищ розробників Robert S. Boyer і J Strother Moore).

![Знищення взаємно відмінних пар у потоці елементів](/root/eng/sf-algorithms/majority-vote-boyer-moore/img/fig-pairing-cancellation.svg)
*Принцип взаємного скорочення: кожне спарювання двох різних елементів зменшує частку меншості швидше, ніж частку абсолютної більшості, залишаючи кандидата-переможця.*

Детальна історія створення алгоритму у контексті верифікації коду для аерокосмічних систем викладена у нарисі: [Історія алгоритму Бойєра — Мура: від автоматичного доведення теорем до потокової аналітики](root:sf-algorithms/majority-vote-boyer-moore/hist-boyer-moore.md).

## Потоковий автомат станів: лічильник переваги

Для реалізації парного знищення на потоці даних не потрібно зберігати пари явно. Достатньо підтримувати лише дві комірки пам'яті:

1. `candidate` — поточний кандидат на роль більшості.
2. `count` — лічильник активної переваги кандидата над спареними опонентами.

Коли надходить новий елемент потоку `x`, алгоритм виконує один із трьох переходів:

1. **Скидання та призначення (`count == 0`)**: Якщо лічильник дорівнює нулю, це означає, що всі попередні елементи успішно взаємно скоротилися на пари. Попередній баланс обнулився. Ми встановлюємо `candidate = x` і задаємо початкову вагу `count = 1`.
2. **Підтвердження (`x == candidate`)**: Якщо новий елемент збігається з поточним кандидатом, його позиція посилюється, і ми збільшуємо лічильник: `count++`.
3. **Взаємне скорочення (`x != candidate`)**: Якщо новий елемент відрізняється від кандидата, ми спарюємо цей новий елемент з одним із накопичених екземплярів кандидата і подумки відкидаємо обидва. Лічильник переваги зменшується: `count--`.

![Схема переходів станів лічильника в алгоритмі Бойєра — Мура](/root/eng/sf-algorithms/majority-vote-boyer-moore/img/fig-state-transitions.svg)
*Автомат станів потокового алгоритму: скидання на нуль, накопичення переваги та взаємне зменшення ваги при зіткненні з відмінним значенням.*

### Покрокове трасування потоку

Простежимо роботу автомата станів для масиву з дев'яти елементів `[A, B, A, C, A, A, D, A, B]`, де `N = 9`. Елемент `A` зустрічається 5 разів, що перевищує поріг більшості `9 / 2 = 4.5`.

```text
Крок │ Елемент x │ Стан до кроку    │ Умова переходу    │ Дія над станом             │ Стан після кроку
─────┼───────────┼──────────────────┼───────────────────┼────────────────────────────┼──────────────────
  1  │     A     │ count = 0        │ count == 0        │ candidate = A, count = 1   │ cand: A, cnt: 1
  2  │     B     │ cand: A, cnt: 1  │ x != cand (B != A)│ count-- (скорочення A і B) │ cand: A, cnt: 0
  3  │     A     │ cand: A, cnt: 0  │ count == 0        │ candidate = A, count = 1   │ cand: A, cnt: 1
  4  │     C     │ cand: A, cnt: 1  │ x != cand (C != A)│ count-- (скорочення A і C) │ cand: A, cnt: 0
  5  │     A     │ cand: A, cnt: 0  │ count == 0        │ candidate = A, count = 1   │ cand: A, cnt: 1
  6  │     A     │ cand: A, cnt: 1  │ x == cand (A == A)│ count++ (накопичення)      │ cand: A, cnt: 2
  7  │     D     │ cand: A, cnt: 2  │ x != cand (D != A)│ count-- (скорочення A і D) │ cand: A, cnt: 1
  8  │     A     │ cand: A, cnt: 1  │ x == cand (A == A)│ count++ (накопичення)      │ cand: A, cnt: 2
  9  │     B     │ cand: A, cnt: 2  │ x != cand (B != A)│ count-- (скорочення A і B) │ cand: A, cnt: 1
```

Після обробки всіх дев'яти значень автомат завершує роботу зі станом `candidate = A` та `count = 1`. Елемент `A` безпомилково ідентифікований як переможець.

Повний математичний доказ інваріанта лічильника та доведення нерівності `count ≥ 2m - N` наведено у додатку: [Математичний апарат алгоритму Бойєра — Мура: інваріанти, потенціали та бар'єри пам'яті](root:sf-algorithms/majority-vote-boyer-moore/math-majority-proof.md).

## Детальний аналіз крайових випадків та патологічних послідовностей

Поведінка лічильника суттєво залежить від порядку прибуття елементів та структури розподілу. Розглянемо ключові крайові випадки:

### 1. Усі елементи однакові (`[A, A, A, A]`)

Коли вхідний потік повністю гомогенний, лічильник збільшується на кожній ітерації без жодного скорочення: `count = N`. Це найкращий випадок для алгоритму, оскільки він демонструє абсолютний запас міцності.

### 2. Чергування лідера з опонентами (`[A, B, A, B, A]`)

У цьому випадку лідер `A` почергово спарюється з опонентом `B`. Лічильник змінюється за схемою: `1 → 0 → 1 → 0 → 1`. Наприкінці потік завершується зі значенням `candidate = A` та `count = 1`. Попри мінімальний запас лічильника, кандидат визначений правильно.

### 3. Лідер з'являється виключно у другій половині потоку (`[B, C, D, E, A, A, A, A, A, A]`)

У першій частині потоку `[B, C, D, E]` лічильник почергово скидається між різними міноритарними значеннями (`B`, `D`), залишаючи `count = 0` після елемента `E`. Коли починається серія значень `A`, алгоритм безперешкодно захоплює слот кандидата і накопичує лічильник до значення 6. Це підтверджує інваріант: історія першої половини потоку, де всі елементи скоротилися, ніяк не заважає лідеру другої половини здобути перемогу.

### 4. Граничний поріг рівно 50% у парному масиві (`[A, A, B, B]`)

У масиві довжиною `N = 4` елемент `A` зустрічається 2 рази, що становить рівно 50% (`2 / 4 = 0.5`). Проте за строгим математичним означенням більшості вимагається `f(M) > N / 2` (тобто щонайменше 3 для `N = 4`). Автомат після обробки повертає `count = 0` або випадкового останнього кандидата `B`, але верифікаційний прохід показує, що частота дорівнює 2, і правильно відкидає результат.

## Пастка однопрохідного висновку та необхідність другого проходу

Критичною особливістю алгоритму Бойєра — Мура, яку часто ігнорують розробники, є різниця між знаходженням *кандидата* та підтвердженням *існування* більшості.

Алгоритм детерміновано повертає певне значення `candidate` для абсолютно будь-якого вхідного потоку, навіть якщо в ньому взагалі немає елемента з частотою `> N / 2`.

Розглянемо контрприклад на потоці з трьох елементів: `[A, B, C]`. У цьому масиві кожен елемент зустрічається рівно один раз (частота `1/3`), отже, абсолютної більшості не існує.

1. Крок 1: надходить `A` → `candidate = A, count = 1`.
2. Крок 2: надходить `B` → `B != A`, лічильник падає: `count = 0`.
3. Крок 3: надходить `C` → оскільки `count == 0`, призначається `candidate = C, count = 1`.

Алгоритм повертає `C`. Проте `C` не є більшістю. Чому це сталося? Тому що взаємне знищення скоротило пари `(A, B)`, обнуливши лічильник, а останній елемент `C` просто зайняв порожній слот.

Звідси випливає фундаментальне розділення контрактів використання алгоритму:

* **Контракт із гарантією (Promised Majority)**: Якщо на рівні протоколу чи фізичної моделі гарантовано, що більшість існує (наприклад, у консенсусі Raft або системі з трьох сенсорів, де щонайменше 2 датчики завжди справні), результат першого проходу є остаточним і безпомилковим. Потрібен рівно один прохід `O(N)` за пам'яті `O(1)`.
* **Контракт без гарантії (Arbitrary Stream)**: Якщо вхідний масив може мати будь-який розподіл, потрібен **другий прохід** по масиву. Під час другого проходу ми підраховуємо точну кількість входжень знайденого `candidate` і перевіряємо умову `actual_count > N / 2`. Якщо умова не виконується, алгоритм повідомляє про відсутність більшості.

Якщо потік є нескінченним або одноразовим (single-pass stream), виконати другий прохід неможливо. Теорема комунікаційної складності доводить, що детермінована перевірка наявності більшості за один прохід без другого читання принципово вимагає пам'яті `Ω(min(N, U))` біт — тобто збереження всіх унікальних елементів.

## Узагальнення Місри — Гріса: важкі елементи з частотою понад N/k

Принцип попарного скорочення елементів допускає узагальнення для пошуку всіх важких елементів (Heavy Hitters), чия частота перевищує довільну частку `1 / k` від загального обсягу потоку `N` (де `k ≥ 2`).

Джаядев Місра та Девід Гріс у 1982 році довели: для пошуку всіх елементів із частотою `> N / k` достатньо підтримувати масив із `k - 1` слотів кандидатів.

* Для класичної більшості `k = 2`: поріг `> N/2`, кількість слотів `2 - 1 = 1` (алгоритм Бойєра — Мура).
* Для порогу понад третину `k = 3`: поріг `> N/3`, кількість слотів `3 - 1 = 2`.
* Для порогу понад чверть `k = 4`: поріг `> N/4`, кількість слотів `4 - 1 = 3`.

Логіка оновлення слотів Місри — Гріса:

1. Якщо новий елемент `x` уже є серед `k - 1` збережених кандидатів, ми збільшуємо його індивідуальний лічильник `count_i++`.
2. Якщо елемента немає серед кандидатів, але є порожній слот (`count_j == 0`), елемент займає цей слот із вагом `count_j = 1`.
3. Якщо елемента немає і всі `k - 1` слотів зайняті, ми здійснюємо **групове скорочення**: зменшуємо лічильники ВСІХ `k - 1` кандидатів на одиницю (`count_i--` для всіх `i`).

![Узагальнення Місри — Гріса: k-1 комірок і групове скорочення](/root/eng/sf-algorithms/majority-vote-boyer-moore/img/fig-misra-gries-generalization.svg)
*Узагальнення для k-1 кандидатів: одночасне зменшення всіх лічильників при надходженні елемента, відмінного від усіх поточних лідерів.*

Кожне групове скорочення знищує групу з `k` попарно різних значень (новий елемент плюс `k - 1` кандидатів). Загальна кількість таких скорочень у потоці довжиною `N` не може перевищити `N / k`. Отже, будь-який елемент, чия справжня частота строго більша за `N / k`, не може бути витіснений до нуля і гарантовано опиниться серед фінальних кандидатів.

## Паралельне злиття станів у розподілених системах

Коли потік даних обробляється паралельно на кількох ядрах або вузлах кластера (наприклад, у MapReduce або Apache Spark), немає потреби централізовано збирати сирі дані на одному сервері.

Кожен воркер `i` незалежно обробляє свою порцію даних довжиною `N_i` і формує локальний результат `(candidate_i, count_i)`.

Для злиття результатів двох потоків `(C_A, c_A)` та `(C_B, c_B)` застосовується асоціативний оператор редукції:

* Якщо кандидати збігаються (`C_A == C_B`), їхні переваги підсумовуються:
  ```text
  (C_A, c_A) ⊕ (C_A, c_B) = (C_A, c_A + c_B)
  ```
* Якщо кандидати відрізняються (`C_A ≠ C_B`), менший лічильник віднімається від більшого (взаємне анулювання накопичених переваг):
  ```text
  (C_A, c_A) ⊕ (C_B, c_B) = (C_A, c_A - c_B),  якщо c_A ≥ c_B
  (C_A, c_A) ⊕ (C_B, c_B) = (C_B, c_B - c_A),  якщо c_B > c_A
  ```

Ця операція є строго комутативною та асоціативною, що дозволяє виконувати паралельну деревоподібну редукцію (Tree-based Reduction) масиву довільного розміру на GPU або кластерах за логарифмічний час `O(log P)`, де `P` — кількість процесорних вузлів.

## Апаратна реалізація в мережевих кристалах та FPGA

В апаратних мережевих конвеєрах (FPGA, ASIC, мова P4 для програмованих комутаторів) алгоритм Бойєра — Мура є одним із небагатьох алгоритмів аналізу потоку, який можна повністю вкласти в один такт конвеєра частоти 1 ГГц без зупинок (pipeline stalls).

Для реалізації в апаратурі створюються два 32-бітних регістри: `reg_candidate` та `reg_count`. На кожному такті синхронізації надходить черговий заголовок пакета `data_in`. Комбінаційна логіка за один такт формує наступні значення:

* Прапор рівності: `is_match = (reg_candidate == data_in)`.
* Прапор нульового залишку: `is_zero = (reg_count == 0)`.
* Нове значення кандидата: `next_candidate = is_zero ? data_in : reg_candidate`.
* Нове значення лічильника: `next_count = is_zero ? 1 : (is_match ? reg_count + 1 : reg_count - 1)`.

Оскільки відсутні будь-які звернення до зовнішньої динамічної пам'яті DRAM чи складних хеш-таблиць, схема споживає мінімальну кількість логічних вентилів (LUTs) і забезпечує лінійну швидкість обробки на фізичному рівні 400 Гбіт/с (400GbE).

## Порівняння зі суміжними потоковими структурами

Щоб чітко бачити межі застосування методу, зіставимо алгоритм Бойєра — Мура з іншими фундаментальними потоковими структурами даних:

| Структура даних | Задача | Пам'ять | Точність | Гарантія |
|---|---|---|---|---|
| **Бойєр — Мур (Majority Vote)** | Пошук елемента з частотою `> 50%` | `O(1)` (1 слот) | Детермінована | 100% точний кандидат за 1 прохід |
| **Місра — Гріс (Frequent Items)** | Пошук елементів із частотою `> N/k` | `O(k)` (`k-1` слотів) | Детермінована | Похибка частоти `≤ N/k` |
| **Count-Min Sketch** | Оцінка частоти довільного запиту | `O((1/ε) · ln(1/δ))` | Ймовірнісна | Адитивна похибка `ε · N` |
| **HyperLogLog** | Підрахунок унікальних елементів | `O(log log U)` | Ймовірнісна | Відносна похибка `1.04 / √m` |
| **Reservoir Sampling** | Рівномірна випадкова вибірка | `O(k)` | Ймовірнісна | Незміщена вибірка `k` елементів |

## Реалізація та системні оптимізації

Нижче наведено базову реалізацію двоетапного алгоритму мовами C та C++. Реалізація C++ використовує безпечну роботу з пам'яттю через `std::span` та повернення результату через `std::optional`.

:::tabs
```c
#include <stdbool.h>
#include <stddef.h>
#include <stdint.h>

/* Пошук елемента більшості у масиві цілих чисел */
bool boyer_moore_majority(const int32_t *data, size_t size, int32_t *out_majority) {
    if (data == NULL || size == 0 || out_majority == NULL) {
        return false;
    }

    int32_t candidate = 0;
    size_t count = 0;

    /* Етап 1: Визначення кандидата */
    for (size_t i = 0; i < size; ++i) {
        if (count == 0) {
            candidate = data[i];
            count = 1;
        } else if (data[i] == candidate) {
            count++;
        } else {
            count--;
        }
    }

    if (count == 0) {
        return false;
    }

    /* Етап 2: Верифікація частоти знайденого кандидата */
    size_t actual_frequency = 0;
    for (size_t i = 0; i < size; ++i) {
        if (data[i] == candidate) {
            actual_frequency++;
        }
    }

    if (actual_frequency > size / 2) {
        *out_majority = candidate;
        return true;
    }

    return false;
}
```
```cpp
#include <concepts>
#include <cstddef>
#include <cstdint>
#include <optional>
#include <span>

template <std::equality_comparable T>
[[nodiscard]] std::optional<T> boyer_moore_majority(std::span<const T> data) noexcept {
    if (data.empty()) {
        return std::nullopt;
    }

    T candidate{};
    std::size_t count = 0;

    // Етап 1: Знаходження кандидата за один прохід
    for (const auto& item : data) {
        if (count == 0) {
            candidate = item;
            count = 1;
        } else if (item == candidate) {
            ++count;
        } else {
            --count;
        }
    }

    if (count == 0) {
        return std::nullopt;
    }

    // Етап 2: Верифікація реальної частоти кандидата
    std::size_t actual_frequency = 0;
    for (const auto& item : data) {
        if (item == candidate) {
            ++actual_frequency;
        }
    }

    if (actual_frequency > data.size() / 2) {
        return candidate;
    }

    return std::nullopt;
}
```

### Безрозгалужена обробка (Branchless Execution)

У високонавантажених циклах перевірка умовних розгалужень `if-else` на кожній ітерації може призводити до частих промахів передбачувача переходів процесора (Branch Predictor). Застосування безрозгалуженого виразу дозволяє компілятору використати інструкцію `cmov` (Conditional Move):

```text
count += (x == candidate) ? 1 : -1
```

Повний вихідний код оптимізованого безрозгалуженого акумулятора, векторних інструкцій SIMD та узагальненого трекера Місри — Гріса наведено в інженерному додатку: [Практична реалізація та SIMD-оптимізації алгоритму Бойєра — Мура](root:sf-algorithms/majority-vote-boyer-moore/proj-boyer-moore.md).

> 🔧 **Навіщо це.** Алгоритм Бойєра — Мура та його узагальнення Місри — Гріса є фундаментальним інструментом у системах, де критична фіксована пам'ять та нульові затримки. Вони використовуються у кворумному голосуванні відмовостійких систем авіоніки (TMR), у ядрах мережевих комутаторів для виявлення перевантажень і блокування аномального трафіку (DDoS Heavy Hitters), у протоколах розподіленого консенсусу (Raft/Paxos) для миттєвої перевірки більшості голосів лідера, а також у потокових базах даних для виконання швидких агрегацій без виділення динамічної пам'яті.
