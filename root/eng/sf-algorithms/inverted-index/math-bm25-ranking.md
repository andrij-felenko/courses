# 🧮 Ймовірнісне ранжування: Математичне виведення моделі Okapi BM25

Модель ранжування Okapi BM25 є вершиною розвитку ймовірнісного підходу до інформаційного пошуку. На відміну від евристичних векторних моделей, де формули зважування підбиралися емпірично, кожен компонент BM25 має суворе математичне обґрунтування, що випливає з теорії ймовірностей, байєсівського оцінювання, таблиць спряженості та 2-пуассонівського розподілу слів у текстах.

---

## 1. Принцип ймовірнісного ранжування (PRP)

Теоретичним фундаментом ймовірнісного пошуку є **Принцип ймовірнісного ранжування** (Probability Ranking Principle, PRP), сформульований Стівеном Робертсоном у 1977 році:

> Якщо інформаційна система впорядковує знайдені документи за спаданням їхньої апостеріорної ймовірності бути релевантними для користувача, то сумарна корисність видачі для користувача буде строго максимальною, а очікувана похибка вибору — мінімальною.

Формалізуємо задачу. Нехай:
* `Q` — пошуковий запит, що складається з набору термів `q₁, q₂, ..., q_m`;
* `D` — документ із колекції;
* `R` — бінарна випадкова величина релевантності: `R = 1` (документ релевантний запиту), `R = 0` (документ нерелевантний).

Згідно з принципом PRP, система повинна ранжувати документи за апостеріорним відношенням шансів (odds of relevance):

```
O(R | D, Q) = P(R = 1 | D, Q) ÷ P(R = 0 | D, Q)
```

Застосуємо теорему Байєса до чисельника та знаменника:

```
P(R = 1 | D, Q) = P(D | R = 1, Q) · P(R = 1 | Q) ÷ P(D | Q)
P(R = 0 | D, Q) = P(D | R = 0, Q) · P(R = 0 | Q) ÷ P(D | Q)
```

Підставивши ці вирази у відношення шансів, отримуємо факторизацію на два співмножники:

```
O(R | D, Q)
= [P(D | R = 1, Q) ÷ P(D | R = 0, Q)] · [P(R = 1 | Q) ÷ P(R = 0 | Q)]
```

Другий множник `P(R = 1 | Q) ÷ P(R = 0 | Q)` є апріорним відношенням релевантних документів до нерелевантних у системі для даного запиту. Оскільки це константа, абсолютно однакова для всіх документів колекції `D`, вона не впливає на монотонний порядок сортування і може бути вилучена.

Для спрощення подальших обчислень перейдемо від добутку ймовірностей до адитивної суми за допомогою взяття натурального логарифма:

```
Score(D, Q) = ln( P(D | R = 1, Q) ÷ P(D | R = 0, Q) )
```

## 2. Гіпотеза незалежності та вага Робертсона — Спарк Джонс (RSJ)

Представимо документ `D` як бінарний вектор індикаторів входження слів `x = (x₁, x₂, ..., x_V)`, де `x_t = 1`, якщо терм `t` зустрічається у документі, і `x_t = 0`, якщо він відсутній. Розмірність `V` дорівнює розміру словника корпусу.

Припустимо, що появи окремих слів у тексті є умовно незалежними подіями за умови фіксованої релевантності (наївне байєсівське припущення):

```
P(D | R = 1, Q) = ∏ [p_t^(x_t) · (1 - p_t)^(1 - x_t)]
P(D | R = 0, Q) = ∏ [u_t^(x_t) · (1 - u_t)^(1 - x_t)]
```

де введено ймовірнісні параметри:
* `p_t = P(x_t = 1 | R = 1, Q)` — ймовірність зустріти терм `t` у довільно вибраному релевантному документі;
* `u_t = P(x_t = 1 | R = 0, Q)` — ймовірність зустріти терм `t` у довільно вибраному нерелевантному документі.

Підставимо ці вирази під логарифм відношення правдоподібності:

```
Score(D, Q)
= ln( ∏ [p_t^(x_t) · (1 - p_t)^(1 - x_t)] ÷ ∏ [u_t^(x_t) · (1 - u_t)^(1 - x_t)] )
= ∑ ln( [p_t^(x_t) · (1 - p_t)^(1 - x_t)] ÷ [u_t^(x_t) · (1 - u_t)^(1 - x_t)] )
= ∑ [ x_t · ln( p_t ÷ u_t ) + (1 - x_t) · ln( (1 - p_t) ÷ (1 - u_t) ) ]
```

Перегрупуємо суму, відокремивши члени, що залежать від наявності слова в документі (`x_t`):

```
Score(D, Q)
= ∑ x_t · [ ln( p_t ÷ u_t ) - ln( (1 - p_t) ÷ (1 - u_t) ) ] + ∑ ln( (1 - p_t) ÷ (1 - u_t) )
= ∑ x_t · ln( [p_t · (1 - u_t)] ÷ [u_t · (1 - p_t)] ) + C
```

Сума `C = ∑ ln( (1 - p_t) ÷ (1 - u_t) )` є константою, що залежить виключно від глобальних параметрів термів запиту, і не змінюється від документа до документа. Отже, відкинувши `C`, отримуємо чисту зважену суму за всіма термами запиту, присутніми в документі (`x_t = 1`):

```
Score(D, Q) = ∑_{t ∈ Q ∩ D} w_t
```

де вага кожного терма визначається формулою:

```
w_t = ln( [p_t · (1 - u_t)] ÷ [u_t · (1 - p_t)] )
```

Ця величина називається **вагою релевантності Робертсона — Спарк Джонс** (Robertson-Spärck Jones weight, RSJ).

## 3. Таблиця спряженості та виведення згладженого IDF

На практиці до початку обробки запиту система не має списку релевантних документів (це власне те, що потрібно знайти). Тому параметри `p_t` та `u_t` необхідно статистично оцінити за колекцією.

Розглянемо таблицю спряженості для корпусу з `N` документів:

```
Таблиця розподілу документів для терма t:
                    Релевантні (R = 1)   Нерелевантні (R = 0)     Всього
Містить терм (x=1)          r_t                  n_t - r_t          n_t
Не містить   (x=0)        R - r_t            N - n_t - R + r_t    N - n_t
Всього                      R                      N - R             N
```

де:
* `N` — загальна кількість документів у корпусі;
* `R` — загальна кількість релевантних документів для запиту `Q`;
* `n_t` — кількість документів колекції, що містять терм `t`;
* `r_t` — кількість релевантних документів, що містять терм `t`.

Прямі оцінки максимальної правдоподібності мають вигляд:

```
p_t = r_t ÷ R
u_t = (n_t - r_t) ÷ (N - R)
```

Підставивши ці оцінки у вагу RSJ, отримуємо:

```
w_t = ln( [ (r_t / R) · (1 - (n_t - r_t)/(N - R)) ] ÷ [ ((n_t - r_t)/(N - R)) · (1 - r_t/R) ] )
    = ln( [ r_t · (N - n_t - R + r_t) ] ÷ [ (n_t - r_t) · (R - r_t) ] )
```

Оскільки за відсутності зворотного зв'язку від користувача `R` та `r_t` невідомі, приймають стандартні апріорні припущення:
1. Загальна кількість релевантних документів дуже мала порівняно з розміром бази: `R << N`, тому `N - R ≈ N`;
2. Ймовірність зустріти терм у релевантному документі фіксується константою: `p_t = 0.5` (або `r_t = 0.5 · R`);
3. Переважна більшість документів є нерелевантними, отже `n_t - r_t ≈ n_t`.

Для усунення ділення на нуль та запобігання невизначеності при нульових лічильниках застосовують байєсівське згладжування за Халдейном (додавання `0.5` до кожного осередку таблиці спряженості):

```
w_t = ln( [ (r_t + 0.5) · (N - n_t - R + r_t + 0.5) ] ÷ [ (n_t - r_t + 0.5) · (R - r_t + 0.5) ] )
```

Підставивши `R = 0` та `r_t = 0` (повна відсутність апріорної інформації про релевантність), отримуємо класичну формулу Робертсона — Спарк Джонс:

```
w_t = ln( (N - n_t + 0.5) ÷ (n_t + 0.5) )
```

У сучасній практиці (зокрема у Lucene та Elasticsearch) до виразу під логарифмом додають одиницю, щоб гарантувати невід'ємність ваги для широко розповсюджених слів:

```
IDF(t) = ln( (N - n_t + 0.5) ÷ (n_t + 0.5) + 1 )
```

## 4. 2-пуассонівська модель та крива насичення частоти (TF Saturation)

Бінарна модель RSJ враховує лише присутність чи відсутність слова (`x_t ∈ {0, 1}`). Вона вважає документ із 1 входженням слова абсолютно еквівалентним документу зі 100 входженнями.

Для врахування реальної частоти слова `f_{t,D}` Робертсон і Спарк Джонс ввели поняття **елітності** (eliteness) — прихованої бінарної змінної `E_t ∈ {0, 1}`:
* `E_t = 1` — документ фундаментально сфокусований на концепції `t` (слово є центральною темою тексту);
* `E_t = 0` — документ не присвячений темі `t`, а слово вжите випадково як побічна згадка.

Розподіл кількості входжень слова `f` у документах моделюється сумішшю двох пуассонівських процесів:
* Для елітних документів: `P(f | E = 1) = (λ^f · e^(-λ)) ÷ f!` із високим математичним сподіванням `λ`;
* Для неелітних документів: `P(f | E = 0) = (μ^f · e^(-μ)) ÷ f!` із низьким математичним сподіванням `μ`.

Апостеріорна ймовірність того, що документ є елітним за умови спостереження частоти `f`, описується сигмоїдальною кривою. Робертсон апроксимував цей зв'язок гіперболічною функцією насичення:

```
S(f) = f ÷ (f + k₁)
```

де `k₁ > 0` — параметр крутизни насичення.

```
Аналіз граничної корисності додаткових входжень (k₁ = 1.2):
f = 0:  S(0) = 0.000
f = 1:  S(1) = 1 ÷ 2.2 = 0.455   [граничний приріст Δ = +0.455]
f = 2:  S(2) = 2 ÷ 3.2 = 0.625   [граничний приріст Δ = +0.170]
f = 3:  S(3) = 3 ÷ 4.2 = 0.714   [граничний приріст Δ = +0.089]
f = 10: S(10) = 10 ÷ 11.2 = 0.893 [граничний приріст Δ = +0.012]
f → ∞:  S(f) → 1.000
```

Ця крива ідеально відображає психологію сприйняття тексту людиною: перша згадка терма дає 45% впевненості у релевантності, друга додає ще 17%, а після 10 згадок подальше повторення практично не збільшує інформативність.

Для калібрування діапазону значень функцію множать на `(k₁ + 1)`, що забезпечує нормування `TF_Score(1) ≈ 1`:

```
TF_Score(f) = [ f · (k₁ + 1) ] ÷ ( f + k₁ )
```

## 5. Нормалізація за довжиною документа та параметр `b`

Довгі тексти природно містять більшу кількість повторень слів з двох різних причин:
1. **Багатослівність** (verbosity) — автор детально розписує ту саму думку, використовуючи більше слів. Реальна інформаційна щільність не зростає, тому висока частота слів є артефактом стилю;
2. **Широта тематики** (scope) — великий документ містить багато окремих розділів і висвітлює широкий спектр питань.

Щоб компенсувати багатослівність, фактичний поріг насичення `k₁` динамічно модифікують залежно від довжини документа:

```
k_eff = k₁ · [ (1 - b) + b · (|D| ÷ L_avg) ]
```

де:
* `|D|` — довжина документа в токенах;
* `L_avg` — середня довжина документа у всій колекції;
* `b ∈ [0, 1]` — коефіцієнт штрафу за довжину.

### Граничний аналіз параметра `b`:
* **`b = 0` (відсутність нормалізації):** довжина документа повністю ігнорується (`k_eff = k₁`). Довгі тексти отримують несправедливу перевагу над короткими;
* **`b = 1` (повна пропорційна нормалізація):** довжина документа вважається чистою багатослівністю. Оцінка частоти ділиться строго пропорційно відношенню `|D| / L_avg`;
* **`b = 0.75` (стандартне значення):** 75% збільшення довжини списується на багатослівність, а 25% — на розширення тематики.

## 6. Врахування частоти термів у запиті (параметр `k₃`)

Якщо пошуковий запит є довгим і користувач повторює певні слова кілька разів (наприклад, `"алгоритм пошуку швидкий алгоритм"`), частоту входження слова в запит `qtf` також необхідно враховувати.

Для запиту застосовується аналогічна функція насичення з параметром `k₃` (зазвичай `k₃ ∈ [1, 2]` або `k₃ = 8` для довгих запитів):

```
QTF_Score(qtf) = [ qtf · (k₃ + 1) ] ÷ ( qtf + k₃ )
```

Для стандартних коротких користувацьких запитів, де всі `qtf = 1`, цей множник спрощується до константи і не впливає на ранжування.

## 7. Модифікації BM25+: Розв'язання проблеми наддовгих документів

У класичній формулі BM25 існує фундаментальна математична аномалія для надзвичайно довгих документів (`|D| >> L_avg`). Якщо документ дуже великий, знаменник `k_eff` зростає до нескінченності, і внесок навіть точного збігу за словом запиту прямує до нуля:

```
lim_{|D| → ∞} TF_BM25(t, D) = 0
```

Це призводить до того, що довгі енциклопедичні статті (наприклад, стаття у Вікіпедії про комп'ютерні науки обсягом 20000 слів) можуть програвати мікроскопічному твіту з 5 слів, навіть якщо в енциклопедії шуканий терм розкритий набагато ґрунтовніше.

Щоб виправити цей недолік, у 2011 році дослідники запропонували модифікацію **BM25+**. До компонента TF додається фіксований нижній поріг корисності `δ > 0` (зазвичай `δ = 1.0`):

```
TF_BM25+(t, D) = [ f_{t,D} · (k₁ + 1) ] ÷ [ f_{t,D} + k₁ · (1 - b + b · (|D| / L_avg)) ] + δ
```

Доданок `δ` гарантує, що сам факт наявності шуканого слова завжди додає мінімум `δ · IDF(t)` до загального скору документа незалежно від того, наскільки великим є текст.

## 8. Зв'язок із мовними моделями та згладжуванням Діріхле

В альтернативній парадигмі інформаційного пошуку — **мовних моделях** (Language Modeling approach, Ponte & Croft, 1998) — релевантність розглядається як ймовірність генерації запиту `Q` статистичною мовною моделлю документа `M_D`:

```
P(Q | M_D) = ∏ P(q_t | M_D)
```

Для запобігання нульовим ймовірностям використовують байєсівське згладжування з апріорним розподілом Діріхле (Dirichlet Prior Smoothing):

```
P(q_t | M_D) = ( f_{t,D} + μ · P(q_t | C) ) ÷ ( |D| + μ )
```

де `P(q_t | C) = c_t / |C|` — ймовірність слова у всій колекції `C`, а `μ` — псевдолічильник слів (зазвичай `μ ≈ 2000`).

Логарифмуючи та перетворюючи відношення ймовірностей мовної моделі до фонової колекції:

```
ln( P(Q | M_D) ÷ P(Q | C) )
= ∑ ln( 1 + f_{t,D} ÷ (μ · P(q_t | C)) ) + |Q| · ln( μ ÷ (|D| + μ) )
```

Звідси видно дивовижну математичну конвергенцію двох незалежних шкіл:
1. Член `ln( 1 + f_{t,D} / (μ · P(q_t | C)) )` є логарифмічним аналогом компонента `TF · IDF` у BM25;
2. Член `|Q| · ln( μ / (|D| + μ) )` накладає штраф за довжину документа `|D|`, повністю еквівалентний нормалізації за параметром `b` у BM25.

## 9. Аналітичні властивості функції BM25 та верхня межа для WAND

Розглянемо аналітичні властивості функції `BM25(D, Q)` як функції двох змінних: частоти `f` та довжини документа `L = |D|`.

### 1. Монотонність за частотою входження:
Перша часткова похідна за `f` завжди строго додатна:

```
∂(TF_BM25) / ∂f = [ (k₁ + 1) · k_eff ] ÷ (f + k_eff)² > 0
```

Це математично гарантує, що при незмінній довжині тексту збільшення кількості входжень ключового слова завжди підвищує ранг документа (відсутність інверсії порядку).

### 2. Опуклість та спадна віддача:
Друга часткова похідна за `f` строго від'ємна:

```
∂²(TF_BM25) / ∂f² = - [ 2 · (k₁ + 1) · k_eff ] ÷ (f + k_eff)³ < 0
```

Це доводить строгу увігнутість (concavity) функції: кожен наступний терм приносить менше корисного сигналу, ніж попередній.

### 3. Абсолютна верхня межа внеску терма (Upper Bound):
При прямуванні частоти `f → ∞` функція `TF_BM25` обмежена зверху константою `k₁ + 1`:

```
max_{D} TF_BM25(t, D) ≤ k₁ + 1
```

Звідси випливає фундаментальна теорема про максимальний внесок терма `t` у будь-який можливий документ корпусу:

```
U_t = IDF(t) · (k₁ + 1)
```

Ця асимптотична оцінка `U_t` є ключем до роботи сучасних алгоритмів динамічного відсікання **WAND** (Weak AND) та **Block-Max WAND**. Оскільки система наперед знає максимальний теоретичний бал `U_t` для кожного слова, вона може миттєво підсумувати `∑ U_t` для підмножини слів запиту і відкинути мільйони документів без читання їхніх постингових записів з диска, якщо сума верхніх меж не здатна перевершити поточний поріг Top-K.

## 10. Емпіричне калібрування гіперпараметрів для різних доменів

Оптимальні значення параметрів `k₁` та `b` залежать від природи текстового корпусу та середньої поведінки користувачів:

```
Рекомендовані діапазони параметрів Okapi BM25:
Домен даних               Параметр k₁   Параметр b    Обґрунтування конфігурації
─────────────────────────────────────────────────────────────────────────────────
Веб-пошук (HTML)           1.2 – 1.5     0.75 – 0.80  Суворий штраф за довгі SEO-сторінки
Наукові статті (PDF)       1.5 – 2.0     0.55 – 0.65  Знижений штраф за великі розділи
Технічна документація      1.2 – 1.6     0.70 – 0.75  Баланс між довідками та мануалами
Пошук у вихідному коді     1.0 – 1.2     0.30 – 0.40  Слабкий штраф (код довгий за природою)
Логи та повідомлення чату  0.8 – 1.0     0.10 – 0.20  Короткі рядки, довжина малоінформативна
```

* **Збільшення `k₁`** робить формулу чутливішою до точної кількості повторень слова (наближає до лінійного TF). Це корисно для наукових оглядів, де ключовий термін вживається десятками разів у ядрі дослідження;
* **Зменшення `b`** захищає довгі аналітичні документи від дискримінації, коли важливо знайти вузькоспеціалізований підрозділ усередині великої монографії.

Калібрування параметрів на практиці здійснюється методом сіткового пошуку (Grid Search) або байєсівської оптимізації на валідаційній вибірці запитів. Якість ранжування вимірюється сукупністю метрик:
* **NDCG@10** (Normalized Discounted Cumulative Gain) — оцінює корисність першої десятки результатів із логарифмічним штрафом за позицію (чим нижче релевантний документ, тим менший внесок);
* **MAP** (Mean Average Precision) — усереднена точність по всьому списку релевантних документів для оцінки повноти видачі;
* **MRR** (Mean Reciprocal Rank) — фокусується на позиції першого правильного результату (критично для запитальних та навігаційних запитів, де користувача цікавить єдина точна відповідь).

## 11. Повна канонічна формула Okapi BM25

Об'єднуючи IDF, насичення частоти з нормалізацією довжини та зважування частоти запиту, отримуємо повне рівняння **Okapi BM25**:

```
BM25(D, Q)
= ∑_{t ∈ Q} IDF(t) · [ f_{t,D} · (k₁ + 1) ] ÷ [ f_{t,D} + k₁ · (1 - b + b · (|D| / L_avg)) ] · [ qtf_t · (k₃ + 1) ] ÷ ( qtf_t + k₃ )
```

де:

```
IDF(t) = ln( (N - n_t + 0.5) ÷ (n_t + 0.5) + 1 )
```

## 12. Покроковий числовий приклад розрахунку

Простежимо роботу алгоритму на конкретних числових даних.

### Вхідні параметри індексу:
* Загальна кількість документів у корпусі: `N = 50000`;
* Середня довжина документа: `L_avg = 250` токенів;
* Параметри моделі: `k₁ = 1.2`, `b = 0.75`, `k₃ = 1.5`.

### Запит користувача `Q`:
`"хешування таблиця"` (`t₁` = "хешування", `t₂` = "таблиця", для обох `qtf = 1`).

Статистика поширеності термів у корпусі:
* Слово `"хешування"` присутнє у `n₁ = 400` документах;
* Слово `"таблиця"` присутнє у `n₂ = 3500` документах.

### Аналізований документ `D`:
* Довжина документа: `|D| = 400` токенів;
* Частоти входження: `f_{t₁,D} = 4`, `f_{t₂,D} = 2`.

---

### Крок 1. Обчислення інверсної частоти документів (IDF)

Для першого терма `"хешування"` (`n₁ = 400`):

```
IDF(t₁)
= ln( (50000 - 400 + 0.5) ÷ (400 + 0.5) + 1 )   [підстановка N = 50000, n₁ = 400]
= ln( 49600.5 ÷ 400.5 + 1 )                     [арифметика чисельника та знаменника]
= ln( 123.846 + 1 )                             [ділення аргументу]
= ln( 124.846 )                                 [додавання одиниці згладжування]
≈ 4.827                                         [значення натурального логарифма]
```

Для другого терма `"таблиця"` (`n₂ = 3500`):

```
IDF(t₂)
= ln( (50000 - 3500 + 0.5) ÷ (3500 + 0.5) + 1 ) [підстановка N = 50000, n₂ = 3500]
= ln( 46500.5 ÷ 3500.5 + 1 )                     [арифметика часток]
= ln( 13.284 + 1 )                              [ділення аргументу]
= ln( 14.284 )                                  [додавання одиниці згладжування]
≈ 2.659                                         [значення натурального логарифма]
```

Рідкісний термін `"хешування"` отримав майже вдвічі вищу вагу (`4.827` проти `2.659`), що відповідає його вищій інформаційній дискримінативності.

---

### Крок 2. Обчислення коефіцієнта довжини документа `B(D)`

```
B(D)
= 1 - b + b · (|D| ÷ L_avg)                     [формула масштабу довжини]
= 1 - 0.75 + 0.75 · (400 ÷ 250)                 [підстановка b = 0.75, |D| = 400, L_avg = 250]
= 0.25 + 0.75 · 1.6                             [обчислення відносної довжини]
= 0.25 + 1.20                                   [множення на ваговий коефіцієнт b]
= 1.45                                          [підсумковий множник масштабу]
```

Ефективний поріг насичення з урахуванням довжини документа:

```
k_eff
= k₁ · B(D)                                     [масштабування порогу насичення]
= 1.2 · 1.45                                    [підстановка k₁ = 1.2, B(D) = 1.45]
= 1.74                                          [ефективний поріг k_eff]
```

---

### Крок 3. Обчислення нормалізованого внеску частот (TF)

Для першого терма `"хешування"` (`f = 4`):

```
TF_Score(t₁)
= [ 4 · (1.2 + 1) ] ÷ ( 4 + 1.74 )              [підстановка f = 4, k₁ = 1.2, k_eff = 1.74]
= [ 4 · 2.2 ] ÷ 5.74                            [спрощення чисельника та знаменника]
= 8.8 ÷ 5.74                                    [ділення величин]
≈ 1.533                                         [нормалізований бал частоти]
```

Для другого терма `"таблиця"` (`f = 2`):

```
TF_Score(t₂)
= [ 2 · (1.2 + 1) ] ÷ ( 2 + 1.74 )              [підстановка f = 2, k₁ = 1.2, k_eff = 1.74]
= [ 2 · 2.2 ] ÷ 3.74                            [спрощення чисельника та знаменника]
= 4.4 ÷ 3.74                                    [ділення величин]
≈ 1.176                                         [нормалізований бал частоти]
```

---

### Крок 4. Розрахунок підсумкового балу релевантності

```
BM25(D, Q)
= IDF(t₁) · TF_Score(t₁) + IDF(t₂) · TF_Score(t₂) [сума зважених частот термів]
= 4.827 · 1.533 + 2.659 · 1.176                   [підстановка обчислених компонентів]
= 7.400 + 3.127                                   [зважування за окремими словами]
= 10.527                                          [фінальний ранг документа]
```

Документ `D` отримав оцінку `10.527`. У процесі виконання запиту WAND-алгоритм порівняє це значення з поточним порогом Top-K для включення документа у фінальний список видачі користувачеві.
