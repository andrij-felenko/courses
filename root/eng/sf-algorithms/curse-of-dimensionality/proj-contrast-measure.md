# ⚙️ Поміряти прокляття на своїх даних: контраст і лічильник вузлів

Перш ніж вибирати структуру пошуку, варто дізнатися, чи є в базі що шукати. Далі — дві робочі програми на C++: перша міряє, наскільки відстані у ваших даних відрізняються одна від одної, друга рахує, скільки роботи насправді робить просторове дерево на одному запиті. Обидві повертають число, а не враження, і однаково працюють на згенерованому кубі й на вивантаженні з вашої бази — треба лише підмінити генератор на читання файлу.

## Три числа, а не одне

**Відносний розкид σ/μ** — стандартне відхилення відстані між двома випадковими точками, поділене на середню відстань. Це питання до **даних**: чи є в цьому просторі різниця між «далеко» й «близько» взагалі.

**Контраст (D_max − D_min) / D_min** — на скільки найдальша точка бази далі за найближчу для конкретного запиту. Це питання до **запиту**: чи виграє переможець у решти помітно, чи випадково.

**Частка відвіданих листків** — скільки дерево обійшло, доводячи, що знайдений сусід справді найближчий. Це питання до **структури**: чи має індекс що відсікати.

Перші два числа міряються без жодного індексу, і саме тому їх міряють першими: якщо розкид уже вузький, вибір індексу нічого не врятує, бо рятувати нема чого.

## Дані, які повторюються

Генератор має бути детермінований. З `std::random_device` або `time(nullptr)` у зерні число стрибає між прогонами, і ви не відрізните, що змінилося — код чи випадковість. Потрібна протилежна властивість: ті самі числа на будь-якому компіляторі й будь-якій машині.

Беремо splitmix64: стан — одне 64-бітове слово, дев'ять операцій на число, жодних масивів і прогрівання. Алгоритм SplitMix описали Ґай Стіл, Даґ Лі та Крістін Флад на OOPSLA 2014 («Fast Splittable Pseudorandom Number Generators»); реалізація на C, яку відтоді переписують усі, — Себастьяно Віньї, 2015 рік, це варіант java-8-івського `SplittableRandom` зі сталим кроком.

```cpp
#include <cstdint>
#include <cstdio>
#include <cmath>
#include <vector>
#include <algorithm>

struct Rng {
    uint64_t s;
    uint64_t next() {
        uint64_t z = (s += 0x9E3779B97F4A7C15ULL);
        z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9ULL;
        z = (z ^ (z >> 27)) * 0x94D049BB133111EBULL;
        return z ^ (z >> 31);
    }
    // 53 старші біти → double у [0,1). Зібрано руками навмисно: стандарт фіксує
    // рушії точно, а розподіли — ні, тож std::uniform_real_distribution дає
    // з того самого зерна різні числа під libstdc++ і під libc++.
    double u01() { return (next() >> 11) * (1.0 / 9007199254740992.0); }   // 2⁵³
};

// n точок по d координат в ОДНОМУ суцільному масиві: точка i — це [i·d, i·d + d)
std::vector<double> gen(int n, int d, uint64_t seed) {
    Rng g{seed};
    std::vector<double> p(static_cast<size_t>(n) * d);
    for (double& v : p) v = g.u01();
    return p;
}

static double dist2(const double* a, const double* b, int d) {
    double s = 0.0;
    for (int i = 0; i < d; ++i) { const double t = a[i] - b[i]; s += t * t; }
    return s;
}
```

Суцільний масив замість `vector<vector<double>>` — не педантизм. За d = 1000 і n = 10⁵ вкладені вектори означають сто тисяч окремих виділень пам'яті, розкиданих купою як прийдеться, і внутрішній цикл, який на кожну точку спершу читає вказівник і чекає на нього. Саме обчислення відстаней — те місце, де це видно найкраще: тут пам'ять або йде суцільним рядком, або не йде.

## Програма перша: контраст

Ідея двоходова. Розкид рахуємо по вибірці пар — тисячі пар вистачає з головою. Контраст рахуємо для кожного запиту окремо й беремо **медіану** по запитах, а не середнє.

```cpp
struct Stat { double spread, contrast, dmin, dmax; };

Stat measure(int n, int d, int queries, uint64_t seed) {
    const std::vector<double> base = gen(n, d, seed);
    const std::vector<double> qs   = gen(queries, d, seed + 0x51ED);
    const double* B = base.data();

    // 1) відносний розкид — по вибірці пар, за Велфордом
    Rng pick{seed + 0x9A17};
    const int m = 4000;
    double mean = 0.0, m2 = 0.0;
    for (int k = 1; k <= m; ++k) {
        const int i = static_cast<int>(pick.next() % static_cast<uint64_t>(n));
        int       j = static_cast<int>(pick.next() % static_cast<uint64_t>(n));
        if (j == i) j = (j + 1) % n;
        const double D = std::sqrt(dist2(B + static_cast<size_t>(i) * d,
                                         B + static_cast<size_t>(j) * d, d));
        const double delta = D - mean;
        mean += delta / k;
        m2   += delta * (D - mean);
    }
    const double spread = std::sqrt(m2 / m) / mean;

    // 2) контраст кожного запиту
    std::vector<double> cs(queries);
    double sdmin = 0.0, sdmax = 0.0;
    for (int q = 0; q < queries; ++q) {
        const double* Q = qs.data() + static_cast<size_t>(q) * d;
        double lo = HUGE_VAL, hi = 0.0;
        for (int i = 0; i < n; ++i) {
            const double D2 = dist2(Q, B + static_cast<size_t>(i) * d, d);
            if (D2 < lo) lo = D2;
            if (D2 > hi) hi = D2;
        }
        lo = std::sqrt(lo);  hi = std::sqrt(hi);   // корінь двічі на запит, а не n разів
        cs[q] = (hi - lo) / lo;
        sdmin += lo;  sdmax += hi;
    }
    std::nth_element(cs.begin(), cs.begin() + queries / 2, cs.end());
    return Stat{spread, cs[queries / 2], sdmin / queries, sdmax / queries};
}

int main() {
    std::printf("   d      s/m   contrast    D_min    D_max   0.59/sqrt(d)\n");
    for (int d : {2, 3, 10, 100, 1000}) {
        const Stat s = measure(1000, d, 101, 20260808ULL + d);
        std::printf("%4d   %6.3f   %8.2f  %7.3f  %7.3f   %8.3f\n",
                    d, s.spread, s.contrast, s.dmin, s.dmax,
                    0.59 / std::sqrt(static_cast<double>(d)));
    }
}
```

Два рішення в цьому коді варті окремого слова.

**Велфорд замість шкільної формули.** Спокуса — накопичити суму й суму квадратів, а дисперсію дістати як σ² = E[D²] − E[D]². За d = 1000 середня відстань близько 12.9, її квадрат — 166.4, а сама дисперсія — 0.06. Тобто ми віднімаємо 166.40 від 166.46 і сподіваємося на результат: три-чотири значущі цифри гинуть на цьому рядку. У `double` запасу ще вистачає, у `float` — уже ні. Велфорд накопичує відхилення від поточного середнього й ніде не віднімає велике від великого.

**Медіана замість середнього.** За d = 2 знаменник D_min іноді виходить крихітним — запит випадково впав майже на точку бази, — і одне таке значення тягне середнє куди завгодно. На п'яти різних зернах середнє по сотні запитів дало 83, 95, 97, 104 і 116 — розкид у півтора раза на тих самих за суттю даних. Медіана на тих самих п'яти прогонах лишилася в межах від 60 до 72.

Від десяти вимірів угору виміряний розкид лягає точно на 0.59/√d. Рівномірний куб — це чистий випадок, у якому кожна координата справді незалежна, тож він і дає найгірше можливе значення для своєї розмірності. Ось звідки береться користь програми на **реальних** даних: різниця між виміряним σ/μ і теоретичним 0.59/√d показує, наскільки ваші координати повторюють одна одну.

> 🔧 **Навіщо це.** Оберніть формулу — і виміряний розкид дасть грубу оцінку того, скільки в даних справді незалежних напрямів: `ефективна розмірність ≈ (0.59 / (σ/μ))²`. Тисяча колонок із σ/μ = 0.17 поводиться як дванадцятивимірна задача, і жоден індекс на ній не задихнеться. Оцінка приблизна — вона припускає однаково розподілені координати, — але відповідає на головне питання дешево й одразу: у вас тисяча вимірів чи дванадцять. Точніші способи міряти [внутрішню розмірність](root:sf-ml/intrinsic-dimension) починають саме з цієї ідеї.

## Програма друга: лічильник замість секундоміра

Секундомір міряє машину: кеш, компілятор, сусідів по процесору. Лічильник відвіданих листків міряє задачу — і не міняється ні від чого, крім даних. Тому спершу лічильник, а секундомір уже потім, коли є що звіряти.

Дерево беремо найпростіше й чесне: розріз по найширшій осі комірки, позиційно по медіані, кошик на 16 точок, точний пошук із відсіканням. Це не швидка реалізація — [повне kd-дерево з розкладкою пам'яті, віконними запитами й k найближчих описане окремо](root:sf-algorithms/kd-tree). Тут потрібне не швидке, а зчисленне: два лічильники в полях і жодного трюку, який зіпсував би вимір.

```cpp
struct KdCounted {
    KdCounted(const double* pts, int n, int d, int leaf)
        : p_(pts), n_(n), d_(d), leaf_(leaf), idx_(n), lo_(d), hi_(d) {
        for (int i = 0; i < n; ++i) idx_[i] = i;
        nodes_.reserve(4 * (n / leaf + 1));
        build(0, n);
    }

    int leaves() const {
        int k = 0;
        for (const Node& nd : nodes_) if (nd.axis < 0) ++k;
        return k;
    }

    int nearest(const double* q) {          // номер найближчої точки
        visitedLeaves = distCalls = 0;
        best_ = -1;  bestD2_ = HUGE_VAL;
        nn(0, q);
        return best_;
    }

    long visitedLeaves = 0, distCalls = 0;  // ← весь вимір живе тут

private:
    struct Node { double split; int axis, right, begin, end; };

    const double* p_;
    int n_, d_, leaf_;
    std::vector<int>    idx_;
    std::vector<double> lo_, hi_;           // буфери меж комірки, по одному на дерево
    std::vector<Node>   nodes_;
    int    best_   = -1;
    double bestD2_ = HUGE_VAL;

    const double* pt(int i) const { return p_ + static_cast<size_t>(i) * d_; }

    int build(int b, int e) {
        const int me = static_cast<int>(nodes_.size());
        nodes_.push_back(Node{0.0, -1, -1, b, e});          // поки що листок
        if (e - b <= leaf_) return me;

        for (int a = 0; a < d_; ++a) { lo_[a] = HUGE_VAL; hi_[a] = -HUGE_VAL; }
        for (int i = b; i < e; ++i) {
            const double* v = pt(idx_[i]);
            for (int a = 0; a < d_; ++a) {
                if (v[a] < lo_[a]) lo_[a] = v[a];
                if (v[a] > hi_[a]) hi_[a] = v[a];
            }
        }
        int axis = 0;
        for (int a = 1; a < d_; ++a)
            if (hi_[a] - lo_[a] > hi_[axis] - lo_[axis]) axis = a;
        if (hi_[axis] <= lo_[axis]) return me;              // ділити нічим

        const int mid = b + (e - b) / 2;
        std::nth_element(idx_.begin() + b, idx_.begin() + mid, idx_.begin() + e,
                         [&](int i, int j) { return pt(i)[axis] < pt(j)[axis]; });
        nodes_[me].axis  = axis;
        nodes_[me].split = pt(idx_[mid])[axis];
        build(b, mid);                                      // лівий нащадок = me + 1
        const int r = build(mid, e);
        nodes_[me].right = r;
        return me;
    }

    void nn(int node, const double* q) {
        const Node nd = nodes_[node];
        if (nd.axis < 0) {
            ++visitedLeaves;
            for (int i = nd.begin; i < nd.end; ++i) {
                ++distCalls;
                const double D2 = dist2(q, pt(idx_[i]), d_);
                if (D2 < bestD2_) { bestD2_ = D2; best_ = idx_[i]; }
            }
            return;
        }
        const double diff = q[nd.axis] - nd.split;
        const int near = (diff < 0.0) ? node + 1 : nd.right;
        const int far  = (diff < 0.0) ? nd.right : node + 1;
        nn(near, q);
        if (diff * diff < bestD2_) nn(far, q);              // єдине правило відсікання
    }
};

int main() {
    const int n = 20000, leaf = 16, queries = 20;
    std::printf("   d   leaves   visited    frac      dists\n");
    for (int d : {2, 3, 5, 8, 10, 12, 15, 20, 100}) {
        const std::vector<double> pts = gen(n, d, 20260808ULL + d);
        const std::vector<double> qs  = gen(queries, d, 20260808ULL + d + 0x51ED);
        KdCounted t(pts.data(), n, d, leaf);

        long vl = 0, dc = 0;
        for (int q = 0; q < queries; ++q) {
            const double* Q = qs.data() + static_cast<size_t>(q) * d;
            const int got = t.nearest(Q);
            vl += t.visitedLeaves;  dc += t.distCalls;

            int ref = 0;                                    // звіряння з перебором
            double bd = HUGE_VAL;
            for (int i = 0; i < n; ++i) {
                const double D2 = dist2(Q, pts.data() + static_cast<size_t>(i) * d, d);
                if (D2 < bd) { bd = D2; ref = i; }
            }
            if (got != ref) std::printf("  !!! d=%d q=%d: дерево збрехало\n", d, q);
        }
        const double avg = static_cast<double>(vl) / queries;
        std::printf("%4d   %6d   %7.1f   %5.1f%%   %8.0f\n",
                    d, t.leaves(), avg, 100.0 * avg / t.leaves(),
                    static_cast<double>(dc) / queries);
    }
}
```

Звіряння з перебором стоїть у циклі не для краси: «мало відвіданих листків» однаково добре пояснюється вдалим відсіканням і зіпсованим правилом відсікання, а розрізняє їх лише відповідь. У прогоні нижче дерево не збрехало жодного разу — 20 запитів із 20 на кожній розмірності.

*Уп'ятеро більше точок дає дереву лише два зайві розрізи: половину листків доводиться обходити на 12.8 виміру замість 11.5. Це весь важіль, який дає збільшення бази.*

За часом перебір виграє задовго до того, як частка дійде до одиниці. Суцільний прохід читає пам'ять поспіль, не має непередбачуваних переходів і векторизується; спуск деревом — це ланцюг залежних читань і перехід, який передбачувач гілок вгадує погано. Константи різняться в кілька разів, тож дерево, яке торкається п'ятої частини бази, уже програє. У цій таблиці такий рівень лежить між вісьмома й десятьма вимірами; де саме на вашій машині — питання до `std::chrono`, бо відповідь залежить від того, чи влазить кошик у кеш.

## Скільки це коштує

```
побудова дерева   O(n·d + n·log n)   розкид по осях на кожному рівні + nth_element
рівнів у дереві   log₂(n / leaf)
запит, мала d     ≈ O(log n) листків × leaf × d
запит, велика d   → O(n·d): частка відвіданих листків прямує до одиниці
контраст          O(queries · n · d)
усі попарні       O(n²·d) часу і O(n²) пам'яті
```

Останній рядок і є найчастішою причиною, чому вимір не доходить до кінця: за n = 50 000 матриця всіх пар — це 1.25 мільярда чисел, тобто 10 ГБ у `double`.

## Пастки

**Матриця всіх пар.** Вона не потрібна. σ/μ — відношення двох середніх, а похибка середнього по вибірці спадає як 1/√m: для m = 4000 це півтора відсотка. Відрізнити 0.06 від 0.19 такої точності досить із запасом, тож програма вище бере чотири тисячі випадкових пар замість n².

**Швидка формула D² = ‖x‖² + ‖y‖² − 2·⟨x, y⟩.** До неї тягнеться рука кожного, бо вона перетворює всі попарні відстані на одне множення матриць. І ламається вона рівно там, де потрібна: у близьких точок D² прямує до нуля, а обидві норми лишаються великими, тож абсолютна похибка порядку ‖x‖², помноженого на машинний крок типу, нікуди не дівається, поки сама відповідь тане. Для одиничних векторів у `float` це 6·10⁻⁸ абсолютної похибки проти D² порядку 10⁻⁵ у майже-дублікатів — тобто піввідсотка похибки там, де зазор між сусідами й сам близько відсотка. Це не теорія: scikit-learn носив цю ваду від повідомлення про неї № 9354 (2017) до версії 0.21 (2019), де її залатали, рахуючи відстані шматками з підвищенням до `double` ([модель похибки операцій із плаваючою комою](root:math-numeric/float-arithmetic-error)).

**Накопичення суми квадратів.** Наївний цикл по d доданках має відносну похибку не гіршу за d·u, де u = 2⁻²⁴ ≈ 6·10⁻⁸ для `float`. Порівнювати її треба не з відстанню, а із зазором, який вона не сміє замазати, — між першим і другим сусідом:

```
n = 1000, медіана зазору (D²₂ − D²₁)/D²₁ проти межі похибки d·u для float

d =  100  →  зазор 3.0·10⁻²   похибка 6.0·10⁻⁶   запас 5000×
d = 1000  →  зазор 7.9·10⁻³   похибка 6.0·10⁻⁵   запас  130×
d = 4000  →  зазор 3.9·10⁻³   похибка 2.4·10⁻⁴   запас   16×
```

Зазор тане приблизно як 1/√d, межа похибки росте як d — отже, запас з'їдається як розмірність у степені півтора й вичерпується десь на двох десятках тисяч вимірів. До того ж це найгірший випадок; типова похибка росте як √d, тож справжня стіна ще далі. Висновок протилежний до звичного страху: чесний цикл у `float` найближчого сусіда не губить на тих розмірностях, які трапляються, — губить його швидка формула через попередній пункт. Хочете гарантії дешево — тримайте дані у `float`, а суму накопичуйте в `double`: вектор стане вдвічі вужчим, зате питання закрите. [Компенсоване підсумовування](root:math-numeric/kahan-summation) тут уже надмір: чотири операції на доданок заради похибки, якої порядок сусідів не помічає.

**Запит, узятий із бази.** Тоді D_min = 0, контраст обертається на нескінченність або на ділення на нуль, а картина виходить гарною й брехливою. Програма вище генерує запити окремим потоком навмисно; на реальних даних відкладіть частину записів під запити або виключайте точку за номером.

**Вимір на вже нормованих даних.** Пасток дві, і вони різні. Нормування довжини до одиниці садить усі точки на сферу, де D² = 2 − 2·cos, — гістограма звужується за побудовою. Само собою це не вада: якщо індекс і справді шукає серед нормованих векторів, то міряти треба нормовані. Вада — міряти одне, а шукати інше. Гірше з покоординатним масштабуванням до [0, 1] або до одиничної дисперсії: воно бере колонки, які майже нічого не несли, і роздуває їх до ваги значущих. Прокляття рахує саме кількість незалежних напрямів — тож така підготовка виготовляє його з нічого. Поміряйте σ/μ до й після: якщо після стандартизації розкид помітно впав, винна стандартизація, а не розмірність.
