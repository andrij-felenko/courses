# 📋 Довідник інтерфейсу Heavy-Light декомпозиції

Цей довідник містить повну технічну специфікацію програмного інтерфейсу (API) модуля Heavy-Light декомпозиції (HLD) для мов програмування C (стандарт C11/POSIX) та C++ (стандарт C++20). Модуль призначений для виконання інтервальних модифікацій та агрегатних запитів на простих шляхах і піддеревах довільних кореневих дерев за гарантований логарифмічний час. Довідник охоплює описи типів даних, сигнатур функцій, контрактів виклику, інваріантів пам'яті, кодів помилок, розширених інженерних патернів, серіалізації та правил інтеграції у системні додатки.

## Загальний огляд архітектури та моделі використання

Архітектура модуля розділена на два рівні абстракції, призначені для різних інженерних середовищ:

1. **Процедурний системний C-інтерфейс (`hld_tree_t`):** орієнтований на вбудовані системи (Embedded), модулі операційних систем, мережеві драйвери та високонавантажені сервери, де динамічне виділення пам'яті (`malloc`/`free`) заборонене або обмежене. Структура працює з монолітними попередньо виділеними плоскими буферами пам'яті, гарантуючи детермінований час ініціалізації та повну відсутність фрагментації кучі.
2. **Шаблонний об'єктно-орієнтований C++ інтерфейс (`HeavyLightDecomposition<T, Op>`):** надає сучасну типізовану обгортку з підтримкою семантики володіння RAII, безпеки винятків (Strong Exception Safety), концептів (Concepts C++20), довільних алгебраїчних моноїдних операторів та перегляду послідовностей через `std::span`.

### Життєвий цикл модуля HLD

Робота з модулем HLD підпорядковується суворій фазовій моделі стану (State Machine):

* **Фаза 1. Конфігурація та ініціалізація:** створення екземпляра структури, завдання розміру `N` та виділення буферів.
* **Фаза 2. Побудова топології:** послідовне додавання рівно `N - 1` ребер між вершинами.
* **Фаза 3. Заморожування та компіляція декомпозиції (`build`):** виконання обходів DFS, лінеаризація масивів, визначення важких ланцюгів та побудова відрізкового дерева.
* **Фаза 4. Експлуатація (Query / Update):** паралельне виконання довільної кількості запитів агрегації та динамічних модифікацій на шляхах і піддеревах.

### Базові структури даних та типи

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

#define HLD_MAX_NODES 200005
#define HLD_SUCCESS    0
#define HLD_ERR_BOUNDS -1
#define HLD_ERR_CYCLE  -2
#define HLD_ERR_DISCON -3

typedef struct {
    int to;
    int next;
} hld_edge_t;

typedef struct {
    int n;                          /* Кількість вершин у дереві (0 .. n-1) */
    int root;                       /* Індекс кореневої вершини */
    int edge_cnt;                   /* Поточна кількість доданих спрямованих ребер */
    int cur_pos;                    /* Лічильник поточної позиції лінеаризації DFS */

    int head_edge[HLD_MAX_NODES];   /* Голова списку суміжності для кожної вершини */
    hld_edge_t edges[HLD_MAX_NODES * 2]; /* Масив спрямованих ребер */

    int parent[HLD_MAX_NODES];      /* Батьківський вузол у кореневому дереві */
    int depth[HLD_MAX_NODES];       /* Глибина вершини від кореня (корінь = 0) */
    int sz[HLD_MAX_NODES];          /* Розмір піддерева вершини */
    int heavy[HLD_MAX_NODES];       /* Індекс важкого сина (-1 якщо лист) */
    int head[HLD_MAX_NODES];        /* Голова важкого ланцюга */
    int pos[HLD_MAX_NODES];         /* Позиція вершини у лінеаризованому масиві */
    int inv_pos[HLD_MAX_NODES];     /* Зворотна таблиця: індекс вершини за позицією */

    int64_t node_val[HLD_MAX_NODES];/* Початкові значення у вершинах */
    int64_t flat_val[HLD_MAX_NODES];/* Значення, впорядковані за DFS-індексами */

    int64_t seg_tree[HLD_MAX_NODES * 4]; /* Значення агрегатів дерева відрізків */
    int64_t seg_lazy[HLD_MAX_NODES * 4]; /* Відкладені операції (Lazy Propagation) */
} hld_tree_t;
```

## Специфікація внутрішніх полів та розкладки пам'яті

Для забезпечення максимальної локальності кеш-пам'яті (L1/L2 Cache Locality) та запобігання хибному розділенню кеш-ліній (False Sharing) у багатопотокових середовищах поля структури розбиті за функціональними зонами:

1. **Зона топології графа:**
   * `head_edge[u]` — містить індекс першого інцидентного ребра для вершини `u` у масиві `edges`. Створює компактний ланцюжок суміжності типу Forward Star. Якщо вершина не має ребер, значення дорівнює `-1`.
   * `edges[e]` — статичний масив розміром `2 · HLD_MAX_NODES`, де кожне неорієнтоване ребро зберігається як пара зустрічно спрямованих ребер `(u → v)` та `(v → u)`. Поле `next` вказує на наступне ребро з тієї самої вихідної вершини.
2. **Зона декомпозиції ланцюгів:**
   * `parent[u]` — номер батьківського вузла вершини `u`. Для кореня дерева `parent[root] = -1`.
   * `depth[u]` — цілочисельна глибина вузла у кореневому дереві. Глибина кореня дорівнює `0`, його дітей — `1` і так далі.
   * `sz[u]` — кількість вершин у піддереві з коренем `u`, включаючи саму вершину `u` (для листків `sz = 1`, для кореня `sz = n`).
   * `heavy[u]` — ідентифікатор безпосередньої дитини з максимальним розміром піддерева. Якщо вершина є листком, поле містить `-1`.
   * `head[u]` — вершина, що є початком важкого ланцюга, якому належить `u`. Для вершини, яка сама є головою нового ланцюга, `head[u] = u`.
3. **Зона просторової лінеаризації:**
   * `pos[u]` — порядковий номер вершини у лінеаризованому масиві, призначений під час другого проходу DFS. Усі вершини одного важкого ланцюга мають строго послідовні значення `pos`.
   * `inv_pos[p]` — масив зворотного відображення, що дозволяє за позицією `p` у дереві відрізків миттєво відновити початковий номер вершини `u`.
4. **Зона інтервальних обчислень:**
   * `seg_tree[4N]` — двійкове дерево відрізків, де корінь займає індекс `0`, а діти вузла `k` розташовані за індексами `2k + 1` та `2k + 2`.
   * `seg_lazy[4N]` — масив накопичених відкладених операцій, які передаються нащадкам під час спуску (Lazy Push Down).

### Ініціалізація та побудова топології графа

#### `hld_init` / Конструктор класу

:::tabs
```c
int hld_init(hld_tree_t *tree, int n, int root);
```
```cpp
explicit HeavyLightDecomposition(int n, int root = 0, CombineOp op = CombineOp{});
```
:::

* **Призначення:** Здійснює початкове скидання стану та ініціалізацію внутрішніх структур даних для дерева з `n` вершин з фіксацією кореневої вершини `root`.
* **Параметри виклику:**
  * `tree` (C): обов'язковий валідний вказівник на структуру `hld_tree_t`. Не повинен бути `NULL`.
  * `n`: загальна кількість вершин у дереві. Допустимий діапазон: `1 ≤ n ≤ HLD_MAX_NODES`.
  * `root`: цілочисельний індекс кореня дерева. Допустимий діапазон: `0 ≤ root < n`.
  * `op` (C++): об'єкт асоціативного бінарного оператора моноїда.
* **Повертане значення (C):**
  * `HLD_SUCCESS` (`0`) — успішна ініціалізація.
  * `HLD_ERR_BOUNDS` (`-1`) — значення `n` або `root` виходить за межі допустимих розмірів.
* **Винятки (C++):** `std::invalid_argument`, якщо `n ≤ 0`, або `std::out_of_range`, якщо `root` виходить за межі `[0, n - 1]`.
* **Часова складність:** `O(N)` для скидання масивів у пам'яті.
* **Просторова складність:** `O(N)` виділеної пам'яті.

#### `hld_add_edge` / `add_edge`

:::tabs
```c
int hld_add_edge(hld_tree_t *tree, int u, int v);
```
```cpp
void add_edge(int u, int v);
```
:::

* **Призначення:** Додає неорієнтоване ребро між парою вершин `u` та `v`.
* **Параметри виклику:**
  * `u`: індекс першої кінцевої вершини (`0 ≤ u < n`).
  * `v`: індекс другої кінцевої вершини (`0 ≤ v < n`, `u ≠ v`).
* **Повертане значення (C):**
  * `HLD_SUCCESS` (`0`) — ребро успішно додано.
  * `HLD_ERR_BOUNDS` (`-1`) — некоректні індекси вершин або переповнення статичного масиву ребер.
* **Винятки (C++):** `std::out_of_range`, якщо індекс будь-якої вершини виходить за межі `[0, n - 1]`.
* **Передумови:** Функція повинна викликатися рівно `n - 1` разів для формування зв'язного дерева до виклику `hld_build()`.
* **Часова складність:** `O(1)` операція вставки у прямий список суміжності.

#### `hld_build` / `build`

:::tabs
```c
int hld_build(hld_tree_t *tree);
```
```cpp
void build(int root = 0);
```
:::

* **Призначення:** Виконує повну компіляцію структури: обчислення розмірів піддерев, визначення важких дітей, формування ланцюгів через DFS-лінеаризацію та ініціалізацію дерева відрізків.
* **Повертане значення (C):**
  * `HLD_SUCCESS` (`0`) — дерево успішно скомпільовано та готове до обробки запитів.
  * `HLD_ERR_DISCON` (`-3`) — виявлено, що граф є незв'язним (кількість відвіданих вершин менша за `n`).
  * `HLD_ERR_CYCLE` (`-2`) — виявлено зворотне ребро або циклічну залежність.
* **Постінваріант:** Після успішного виклику топологія дерева стає незмінною, а масиви `depth`, `parent`, `head`, `pos` набувають статусу read-only.
* **Часова складність:** `O(N)`.

### Запити та модифікації на простих шляхах

#### `hld_query_path` / `query_path`

:::tabs
```c
int64_t hld_query_path(hld_tree_t *tree, int u, int v);
```
```cpp
[[nodiscard]] ValueType query_path(int u, int v);
```
:::

* **Призначення:** Обчислює агреговану функцію (наприклад, суму, мінімум або максимум) уздовж простого шляху між вершинами `u` та `v` включно.
* **Параметри виклику:**
  * `u`: початкова вершина шляху.
  * `v`: кінцева вершина шляху.
* **Повертане значення:** Результат моноїдної агрегації для всіх вершин на шляху.
* **Алгоритмічний контракт:** Алгоритм циклічно піднімає вершину з глибшою головою важкого ланцюга, транслюючи кожен важкий відрізок у виклик `seg_query()`.
* **Часова складність:** `O(log² N)` у найгіршому випадку, `O(log N)` у середньому для випадкових дерев.
* **Потокобезпечність (Thread-Safety):** Повністю безпечно для одночасного паралельного виклику з довільної кількості потоків ОС без синхронізаційних блокувань.

#### `hld_update_path` / `update_path`

:::tabs
```c
int hld_update_path(hld_tree_t *tree, int u, int v, int64_t val);
```
```cpp
void update_path(int u, int v, ValueType val);
```

:::

* **Призначення:** Застосовує операцію групової модифікації (додавання або перезапис значення `val`) до всіх вершин на простому шляху між вузлами `u` та `v`.
* **Параметри виклику:**
  * `u`, `v`: кінцеві точки цільового шляху.
  * `val`: дельта або нове значення модифікації.
* **Алгоритмічний контракт:** Розбиває шлях на логарифмічну кількість інтервалів і застосовує ліниву модифікацію у дереві відрізків (`seg_update`).
* **Часова складність:** `O(log² N)`.

### Запити та модифікації на піддеревах

#### `hld_query_subtree` / `query_subtree`

:::tabs
```c
int64_t hld_query_subtree(hld_tree_t *tree, int v);
```
```cpp
[[nodiscard]] ValueType query_subtree(int v);
```
:::

* **Призначення:** Обчислює агреговане значення для всіх вершин піддерева, коренем якого є вершина `v`.
* **Параметри виклику:**
  * `v`: корінь піддерева (`0 ≤ v < n`).
* **Алгоритмічний контракт:** Завдяки DFS-лінеаризації піддерево займає рівно один неперервний відрізок `[pos[v], pos[v] + sz[v] - 1]`, тому операція виконує рівно одне звернення до дерева відрізків.
* **Часова складність:** `O(log N)`.

### Топологічні та метричні операції

#### `hld_lca` / `find_lca`

:::tabs
```c
int hld_lca(hld_tree_t *tree, int u, int v);
```
```cpp
[[nodiscard]] int find_lca(int u, int v) const noexcept;
```
:::

* **Призначення:** Знаходить ідентифікатор найменшого спільного предка (LCA) для вершин `u` та `v`.
* **Алгоритмічний контракт:** Виконує підйоми за головами важких ланцюгів `u = parent[head[u]]` без звернення до дерева відрізків.
* **Часова складність:** `O(log N)` у найгіршому випадку, `O(1)` якщо вершини лежать на одному важкому ланцюгу.
* **Просторова складність:** `O(1)`.

#### `hld_distance` / `get_distance`

:::tabs
```c
int hld_distance(hld_tree_t *tree, int u, int v);
```
```cpp
[[nodiscard]] int get_distance(int u, int v) const noexcept;
```
:::

* **Призначення:** Обчислює кількість ребер на простому шляху між вершинами `u` та `v`.
* **Математична формула:**
```
dist(u, v) = depth[u] + depth[v] - 2 · depth[lca(u, v)]    [формула метричної відстані на дереві]
```
* **Часова складність:** `O(log N)`.

## Розширені інженерні патерни та правила інтеграції

У практичній розробці розподілених систем, рушіїв баз даних та аналітичних пайплайнів HLD застосовується у поєднанні з різними спеціалізованими шаблонами проектування:

### 1. Пакетне вилучення інтервалів (Batch Segment Extraction)
Для прискорення масових запитів на графічних процесорах (GPGPU) або векторизованих SIMD-блоках корисно розділити логіку обходу дерева та логіку інтервального обчислення. Функція експорту перетворює шлях між вершинами `u` та `v` у компактний плоский список числових пар `[L_i, R_i]`:
* Кількість таких пар гарантовано не перевищує `2 · log₂ N + 1`.
* Отриманий масив відрізків передається у векторизоване ядро обчислення або розподілений кластер пам'яті.

### 2. Застосування неасоціативних або складених моноїдів
Якщо задача вимагає одночасного пошуку мінімального значення та індексу вершини, у якій цей мінімум досягається (ArgMin), тип значення визначається як пара `struct ValueIndexPair { int64_t val; int node_id; }`. Оператор об'єднання порівнює поля `val`, зберігаючи відповідний ідентифікатор вузла. Якщо значення рівні, пріоритет надається вузлу з меншим індексом або меншою глибиною, що зберігає детермінізм обчислень.

### 3. Гарантії бінарної сумісності ABI та вирівнювання
Усі структури C-інтерфейсу мають детерміноване розташування полів без неявних компіляторних проміжків (Padding). Для 64-бітних архітектур x86-64 та AArch64 усі масиви 64-бітних чисел (`node_val`, `flat_val`, `seg_tree`, `seg_lazy`) розташовані з вирівнюванням по 8-байтовій межі, що запобігає штрафам не вирівняного доступу до пам'яті (Unaligned Memory Access) та дозволяє використання інструкцій AVX2 / AVX-512.

### 4. Серіалізація та швидке відновлення стану (Zero-Rebuild Persistence)
У розподілених сервісах обчислення двох проходів DFS на дереві розміром `N = 10⁷` займає сотні мілісекунд. Щоб уникнути повторного аналізу під час перезапуску процесу або передачі графа між серверами, стан HLD зберігається на диск або у спільну пам'ять (Shared Memory / `mmap`):
* Достатньо зберегти масиви фіксованої довжини: `depth`, `parent`, `head`, `pos`, `sz`, `inv_pos` та `flat_val`.
* При завантаженні процес миттєво монтує відображення пам'яті через виклик `mmap(..., MAP_SHARED)` без виконання жодних рекурсивних обходів.

## Поведінка системи на крайових топологіях

Модуль спроектований для стабільної роботи на всіх можливих класах кореневих дерев:

* **Одиночний вузол (`N = 1`):** Ребер немає (`edge_cnt = 0`). Корінь `root = 0` є власним важким ланцюгом довжини 1. Запити `query_path(0, 0)` та `query_subtree(0)` виконують рівно одне звернення до дерева відрізків і повертають значення кореня.
* **Зіркоподібне дерево (Star Tree):** Корінь з'єднаний з `N - 1` листками. Рівно один листок отримує важке ребро, решта утворюють ізольовані ланцюги довжини 1. Глибина дерева не перевищує 1, тому всі операції виконуються за константний час `O(1)`.
* **Вироджений лінійний ланцюг (Bamboo Tree):** Усе дерево стає єдиним важким ланцюгом. Запити шляхів між будь-якими вузлами зводяться до єдиного інтервалу в дереві відрізків за час `O(log N)`.

## Порівняльний аналіз інтерфейсу з альтернативними структурами

При проектуванні системної архітектури важливо чітко розмежовувати сфери застосування різних інтерфейсів для роботи з деревами:

* **HLD проти Link-Cut Trees (LCT):** LCT підтримує динамічні операції `link(u, v)` та `cut(u, v)` (зміна топології графа в реальному часі) за амортизований час `O(log N)`. Проте інтерфейс LCT є значно складнішим у реалізації, вимагає динамічного балансування splay-дерев і має у 5–10 разів більшу константу часу на статичних графах порівняно з HLD.
* **HLD проти Ейлерового обходу (Euler Tour Technique):** Ейлерів обхід зберігає дерево як послідовність входів і виходів `tin[u] / tout[u]`, що дозволяє обробляти запити на піддеревах за `O(log N)`. Проте запити на шляхах через Ейлерів обхід вимагають алгоритму Мо (Mo's algorithm on trees), який є статичним офлайн-методом зі складністю `O(N √Q)`. HLD забезпечує строгий онлайн-режим за `O(log² N)`.

## Каталог інваріантів структури та діагностика відмов

Для забезпечення безвідмовної роботи підсистеми користувацький код зобов'язаний дотримуватися наступних архітектурних інваріантів:

1. **Ациклічність та зв'язність графа (Tree Invariant):**
   * Граф повинен містити рівно `N` вершин та `N - 1` неорієнтованих ребер.
   * Усі вершини повинні бути досяжними з кореня `root`. Якщо під час `hld_build()` функція `dfs1` відвідає менше ніж `N` вершин, повертається код `HLD_ERR_DISCON`.
2. **Незмінність топології після компіляції (Immutability Invariant):**
   * Після виклику `hld_build()` заборонено викликати `hld_add_edge()`. Якщо топологія мережі змінюється, екземпляр структури повинен бути переініціалізований через `hld_init()`.
3. **Межі числових типів (Monoid Overflow Invariant):**
   * При використанні операцій додавання на великих деревах користувач повинен забезпечувати захист від переповнення 64-бітних цілих чисел (`int64_t`).
4. **Консистентність лінивої пропогації (Lazy Invariant):**
   * Будь-який запит у дерево відрізків повинен гарантувати виконання функції `seg_push()` перед зверненням до дочірніх інтервалів.

```c
#include <assert.h>

int main(void) {
    hld_tree_t router_tree;
    int node_count = 6;
    int root_gateway = 0;

    rc = hld_build(&router_tree);

    int64_t subtree_traffic = hld_query_subtree(&router_tree, 1);

    return 0;
}
```
