Фізичний рушій тривимірної гри або симулятора робототехніки оновлює світ шістдесят або сто двадцять разів на секунду. У кожному кадрі перебувають тисячі динамічних об'єктів: капсули персонажів, прямокутні коробки ящиків, циліндри коліс, опуклі корпуси автомобілів і ланки промислових маніпуляторів. Перш ніж розрахувати сили тертя, пружні імпульси та реакції опор, система мусить відповісти на базове геометричне запитання: **чи торкаються ці два тіла у просторі, а якщо ні — яка точна найкоротша відстань між ними?**

Найпростіший підхід — попарна перевірка всіх граней і ребер двох многогранників. Якщо перше тіло має `n` граней, а друге — `m`, повний комбінаторний перебір вимагає `O(n · m)` перевірок перетину просторових відрізків із площинами. Для двох простих кубів це 36 пар граней, але для згладжених тривимірних моделей із сотнями трикутників кількість тестів сягає десятків тисяч на кожну пару тіл. Ще гірше те, що гладкі криволінійні тіла (сфери, циліндри, капсули, конуси, еліпсоїди) взагалі не складаються з плоских граней: їх доводиться штучно апроксимувати полігональними сітками, що роздуває кількість вершин і водночас втрачає гладкість контакту.

Теорема про роздільну вісь (англ. *Separating Axis Theorem*, SAT) частково оптимізує перебір, перевіряючи одновимірні проєкції на нормалі граней і векторні добутки ребер. Проте для двох опуклих многогранників із 100 ребрами кількість потенційних осей розділення сягає `100 · 100 = 10 000`. Потрібен метод, який знаходить факт дотику або точну відстань за фіксовані кілька ітерацій, не будуючи грані явно і працюючи однаково швидко як із полігональними сітками, так і з ідеально гладкими аналітичними поверхнями.

### Перетворення двох тіл на одне: простір різниць

Складна суть проблеми полягає в тому, що обидва тіла одночасно мають власні просторові координати, кутову орієнтацію та довільну геометричну форму. Якщо розглядати їх окремо, кожна точка одного тіла потенційно може зіткнутися з будь-якою точкою другого.

Зробимо крок у бік кардинального математичного спрощення. Два тіла `A` та `B` перетинаються тоді й лише тоді, коли вони мають хоча б одну спільну точку `p`:

```
p ∈ A  і  p ∈ B
```

Віднімемо цей спільний вектор сам від себе:

```
p − p = 0
```

Якщо ми утворимо нову геометричну фігуру, складену з усіх можливих векторних різниць між точками множини `A` та точками множини `B`, то спільна точка `p` дасть у цій новій фігурі нульовий вектор — початок координат `(0, 0, 0)`.

Таку операцію над просторовими множинами називають **різницею Мінковського** (позначається `A ⊖ B`, названа на честь німецького математика Германа Мінковського, лат./нім. *Minkowski*). Алгебраїчно це додавання множини `A` та центрально-симетрично відбитої відносно нуля множини `−B`:

```
A ⊖ B = { a − b | a ∈ A, b ∈ B }
```

![Зліва — розділені тіла A і B, для яких початок координат O лежить зовні різниці A - B; справа — тіла, що перетинаються, де точка O опиняється всередині A - B](/root/eng/sf-algorithms/gjk-collision/img/minkowski-intersection.svg)
*Різниця Мінковського перетворює перевірку взаємного положення двох тіл на перевірку однієї умови: чи містить результуюче тіло початок координат.*

Ця конструкція має три фундаментальні геометричні властивості:

1. **Критерій перетину:** Тіла `A` та `B` мають спільні точки тоді й лише тоді, коли початок координат `O = (0, 0, 0)` належить множині `A ⊖ B`:
   ```
   A ∩ B ≠ ∅  ⇔  O ∈ (A ⊖ B)
   ```
2. **Збереження евклідової відстані:** Найкоротша евклідова відстань між двома розділеними тілами `A` та `B` у просторі в точності дорівнює найкоротшій відстані від початку координат `O` до межі різниці `A ⊖ B`:
   ```
   dist(A, B) = min { ||a − b|| | a ∈ A, b ∈ B } = min { ||c|| | c ∈ A ⊖ B } = dist(O, A ⊖ B)
   ```
3. **Збереження опуклості:** Якщо вихідні фігури `A` та `B` є опуклими (лат. *convexus* — склепінчастий, вигнутий назовні), то їхня різниця Мінковського `A ⊖ B` також гарантовано є опуклою множиною.

Детальне математичне виведення цих властивостей та теореми про збереження опуклості наведено у вставці [🧮 Геометрія різниці Мінковського та опорних функцій](root:sf-algorithms/gjk-collision/math-minkowski-difference.md).

Завдяки цьому задача повністю переформулювалася: замість складного просторового танцю двох довільних фігур ми маємо **одну нерухому точку `O = (0, 0, 0)`** та **одну статичну опуклу фігуру `C = A ⊖ B`**.

### Пастка явної побудови та порятунок через опорні точки

Здавалося б, алгоритм готовий: побудувати многогранник `C = A ⊖ B` і перевірити, чи лежить точка `(0, 0, 0)` всередині. Проте тут ховається обчислювальна пастка.

Якщо многогранник `A` має `n` вершин, а `B` має `m` вершин, то кількість вершин у різниці `A ⊖ B` може сягати добутку `n · m`. Побудова тривимірної опуклої оболонки для такої кількості точок вимагає часу `O(n · m log(n · m))`. Тобто явна побудова різниці Мінковського працює навіть повільніше за наївний перебір усіх граней.

Геніальна ідея, яку 1988 року відкрили Елмер Гілберт, Деніел Джонсон та С. Сатія Кірті ([📜 Як виник алгоритм GJK: від роботів і лінійного програмування до ігрових рушіїв](root:sf-algorithms/gjk-collision/hist-gjk-birth.md)), полягає у відмові від повної побудови різниці: **тіло `A ⊖ B` ніколи не генерується цілком**. Алгоритм GJK досліджує це тіло виключно через поодинокі вибіркові зондування його межі у заданих напрямках.

Таке зондування називають **опорним відображенням** (англ. *support mapping*, або опорна функція, від праслов'янського *опора* — те, на що спираються).

Для довільної опуклої фігури `K` та ненульового вектора напрямку `d` опорною точкою `s_K(d)` є точка фігури, яка найдалі висунута у напрямку `d`. Тобто точка, яка максимізує скалярний добуток із `d`:

```
s_K(d) = argmax { x · d | x ∈ K }
```

![Ліворуч — опорні точки для тіл A та B уздовж напрямків d та -d; праворуч — результуюча екстремальна точка різниці Мінковського](/root/eng/sf-algorithms/gjk-collision/img/support-mapping.svg)
*Опорна точка різниці Мінковського в напрямку d обчислюється як пряма різниця двох незалежних опорних точок: s_A(d) мінус s_B(-d).*

Головна алгебраїчна магія полягає в тому, що опорне відображення різниці Мінковського обчислюється тривіально через опорні точки окремих тіл:

```
s_{A ⊖ B}(d) = s_A(d) − s_B(−d)
```

**Чому це так:**
```
max_{a ∈ A, b ∈ B} ((a − b) · d)
= max_{a ∈ A, b ∈ B} (a · d − b · d)           [дистрибутивність скалярного добутку]
= max_{a ∈ A} (a · d) + max_{b ∈ B} (b · (−d))  [незалежність вибору a та b]
```

Це означає: щоб знайти крайню точку гігантської тривимірної фігури `A ⊖ B` у напрямку `d`, не потрібно знати жодної її грані. Ми окремо просимо тіло `A` дати свою крайню точку в напрямку `d`, окремо просимо тіло `B` дати свою крайню точку в протилежному напрямку `−d`, і просто віднімаємо два отримані вектори.

### Опорні функції стандартних геометричних тіл

Для більшості базових геометричних примітивів опорна функція обчислюється аналітично за `O(1)` операцій взагалі без перебору вершин:

- **Сфера** з центром `C` і радіусом `R`:
  ```
  s(d) = C + R · (d / ||d||)
  ```
- **Капсула** (циліндр зі сферичними кришками між точками `A` та `B` радіусом `R`):
  ```
  s(d) = (A · d > B · d ? A : B) + R · (d / ||d||)
  ```
- **Орієнтований паралелепіпед (OBB)** з центром `C`, півосями `u₁, u₂, u₃` і напіврозмірами `e₁, e₂, e₃`:
  ```
  s(d) = C + sign(d · u₁) · e₁ · u₁ + sign(d · u₂) · e₂ · u₂ + sign(d · u₃) · e₃ · u₃
  ```
- **Циліндр** радіусом `R` і висотою `2h` вздовж осі `u`:
  Проєкція `d` на вісь циліндра дає `z = sign(d · u) · h · u`. Перпендикулярна складова `d_perp = d − (d · u) · u` нормалізується й масштабується на `R`: `s(d) = C + z + R · (d_perp / ||d_perp||)`.
- **Еліпсоїд** із центром `C` та матрицею форми `M = diag(a², b², c²)`:
  Опорна точка обчислюється множенням `s(d) = C + (M · d) / sqrt(d · M · d)`, що дозволяє підтримувати сплюснуті й видовжені тіла без розбиття на трикутники.
- **Опуклий многогранник** із довільним масивом вершин:
  Пробігаємо вершини й беремо ту, що дає максимальний скалярний добуток `v_i · d`. Якщо вершини утворюють зв'язний граф, локальний градієнтний спуск (англ. *hill climbing*) знаходить опорну точку за `O(1)` амортизованих кроків за рахунок просторової зв'язності попереднього кадру.

Жодної генерації проміжних трикутників чи розрізання граней не відбувається.

### Симплекс: каркас усередині простору різниць

Якщо ми вміємо отримувати окремі крайні точки фігури `A ⊖ B`, як дізнатися, чи містить вона початок координат `O`?

Для цього алгоритм будує всередині `A ⊖ B` найпростішу геометричну фігуру відповідної розмірності — **симплекс** (лат. *simplex* — простий, поодинокий, від *sem-* — один + *plectere* — сплітати):
- у 0-вимірному просторі: точка (1 вершина);
- у 1-вимірному просторі: відрізок (2 вершини);
- у 2-вимірному просторі: трикутник (3 вершини);
- у 3-вимірному просторі: тетраедр (4 вершини).

За теоремою Каратеодорі (грец. *Κωνσταντίνος Καραθεοδωρή*), якщо точка `O` лежить всередині будь-якого опуклого тіла в `R³`, її завжди можна ув'язнити всередині тетраедра, утвореного лише 4 вершинами цього тіла.

Алгоритм GJK діє ітеративно: він починає з однієї опорної точки, будує відрізок, потім трикутник і тетраедр, щоразу спрямовуючи пошук нової опорної точки строго в бік початку координат `O`. Якщо нова точка перетинає початок координат, симплекс наближається до нуля; якщо виявляється, що жодна нова точка не може перейти за нуль, тіла гарантовано розділені.

![Покрокова зміна симплекса в алгоритмі GJK: від початкової точки до відрізка і трикутника, що охоплює початок координат](/root/eng/sf-algorithms/gjk-collision/img/simplex-evolution.svg)
*Три кроки еволюції симплекса в 2D: (1) пошук першої точки й вибір напрямку на O; (2) добудова відрізка й перпендикулярний пошук; (3) утворення трикутника, який охоплює O.*

### Покроковий механізм головного циклу GJK

Розглянемо повну послідовність кроків алгоритму GJK для перевірки зіткнення:

1. **Ініціалізація напрямку `d`:**
   Обираємо довільний ненульовий вектор напрямку. У фізичних рушіях зазвичай беруть вектор між центрами тіл `d = center(B) − center(A)` або вісь із попереднього кадру анімації.
2. **Перша опорна точка:**
   Знаходимо `A_0 = s_A(d) − s_B(−d)`.
   Ініціалізуємо симплекс однією точкою: `S = { A_0 }`.
   Оновлюємо напрямок пошуку прямо на початок координат: `d = −A_0`.
3. **Головний ітераційний цикл:**
   - **Крок 3.1. Зондування межі:**
     Обчислюємо нову опорну точку `P = s_A(d) − s_B(−d)`.
   - **Крок 3.2. Перевірка площини розділення (ранній вихід):**
     Обчислюємо скалярний добуток `P · d`.
     Якщо `P · d ≤ 0`, це означає, що крайня точка фігури `A ⊖ B` у напрямку `d` навіть не дотягнулася до площини, що проходить через нуль. Оскільки тіло опукле, вся множина `A ⊖ B` лежить позаду цієї площини, а отже, початок координат `O` фізично не може належати `A ⊖ B`.
     **Висновок: тіла розділені (колізії немає), алгоритм завершує роботу.**
   - **Крок 3.3. Додавання точки до симплекса:**
     Додаємо `P` до множини вершин симплекса: `S = S ∪ { P }`.
   - **Крок 3.4. Розв'язувач симплекса (Simplex Solver):**
     Аналізуємо взаємне розташування точки `O` та елементів симплекса:
     - Якщо `O` лежить строго всередині максимального симплекса (трикутника у 2D або тетраедра у 3D) — **КОЛІЗІЮ ЗНАЙДЕНО** (`O ∈ A ⊖ B`), алгоритм повертає `true`.
     - Якщо `O` лежить зовні, розв'язувач знаходить підсимплекс найменшої розмірності (вершину, ребро або грань), який розташований найближче до `O`. Усі зайві вершини відкидаються, симплекс скорочується, а новий вектор напрямку `d` виставляється як вектор від найближчої точки симплекса до початку координат `O`.
   - Повторюємо цикл.

### Розв'язувач симплексів через області Вороного

Серцем алгоритму GJK є розв'язувач симплексів (англ. *simplex solver*). Спосіб розв'язання, запропонований Джино ван ден Бергеном, спирається на розбиття простору навколо симплекса на **області Вороного** (названі на честь українського математика Георгія Вороного, фр. *Voronoy*).

Кожна область Вороного відповідає певній геометричній ознаці симплекса (вершині, ребру чи грані): якщо точка `O` потрапляє в цю область, саме ця ознака є найближчою до нуля.

![Області Вороного для трикутного симплекса: перевірка зовнішніх нормалей до ребер AB та AC визначає, який відрізок зберегти](/root/eng/sf-algorithms/gjk-collision/img/voronoi-regions.svg)
*Розподіл площини на області Вороного для трикутника ABC: скалярні добутки з нормалями визначають, чи лежить O у зоні ребра AB, AC, чи всередині самого трикутника.*

#### 1. Симплекс із двох точок (відрізок `AB`)

Нехай остання додана точка — `A`, а попередня — `B`.
Вектор відрізка: `AB = B − A`. Вектор до початку координат: `AO = −A`.

Оскільки точка `A` щойно була отримана пошуком у напрямку `d`, вона гарантовано перетнула площину нуля у цьому напрямку. Тому початок координат не може лежати «позаду» точки `A`.

Обчислюємо вектор, перпендикулярний до `AB` і спрямований у бік `AO`:
- У 3D: через потрійний векторний добуток `d = (AB × AO) × AB`.
- Скалярний добуток `AB · AO` показує, що найближчим геометричним елементом є сам відрізок `AB`. Ми зберігаємо симплекс `{A, B}` і шукаємо наступну точку вздовж напрямку `d`.

#### 2. Симплекс із трьох точок (трикутник `ABC`)

Нехай вершини трикутника — `A` (найновіша), `B` та `C`.
Вектори сторін: `AB = B − A`, `AC = C − A`, вектор до нуля: `AO = −A`.
Нормаль до площини трикутника: `n = AB × AC`.

Обчислюємо зовнішні нормалі до ребер у площині трикутника:
```
AB_perp = (n × AB) = ((AB × AC) × AB)   [нормаль до ребра AB назовні]
AC_perp = (AC × n) = (AC × (AB × AC))   [нормаль до ребра AC назовні]
```

Перевіряємо положення точки `O`:
1. Якщо `AB_perp · AO > 0`: початок координат лежить у зовнішній області ребра `AB`. Вершина `C` не потрібна — ми видаляємо її, скорочуючи симплекс до відрізка `{A, B}`, а новий напрямок пошуку призначаємо `d = AB_perp`.
2. Якщо `AC_perp · AO > 0`: початок координат лежить у зоні ребра `AC`. Вершина `B` видаляється, лишається відрізок `{A, C}`, новий напрямок `d = AC_perp`.
3. Якщо обидва добутки від'ємні:
   - У 2D: це означає, що початок координат лежить **всередині трикутника `ABC`** — перетин зафіксовано.
   - У 3D: точка `O` проєктується всередину трикутника, але може висіти над або під його площиною. Тому перевіряємо знак `n · AO`: якщо `n · AO > 0`, шукаємо вздовж `d = n`; якщо від'ємний — інвертуємо порядок вершин (орієнтацію) і шукаємо вздовж `d = −n`. Симплекс лишається трикутником `{A, B, C}`.

#### 3. Симплекс із чотирьох точок (тетраедр `ABCD` у 3D)

Коли додається четверта вершина `A` до наявного трикутника `BCD`, утворюється тетраедр із чотирма трикутними гранями: `ABC`, `ACD`, `ADB` та базовою гранню `BCD`.

Оскільки `A` щойно пройшла нуль, грань `BCD` завідомо закрита з протилежного боку — точка `O` не може лежати за нею. Залишається перевірити три нові грані, що прилягають до вершини `A`:
1. Для кожної з граней `ABC`, `ACD`, `ADB` обчислюємо зовнішню нормаль.
2. Якщо вектор `AO` дивиться назовні від деякої грані (наприклад, `ABC`), протилежна вершина `D` відкидається. Тетраедр скорочується до трикутника `ABC`, а вектор нормалі цієї грані стає новим напрямком `d`.
3. Якщо вектор `AO` лежить по внутрішній бік усіх трьох граней — точка `O` повністю запечатана всередині тетраедра `ABCD`.
**Висновок: тіла перетинаються у тривимірному просторі.**

Детальний приклад реалізації 2D-розв'язувача з обробкою всіх типів фігур подано у вставці [⚙️ Реалізація 2D GJK: симплекс, області Вороного та обробка крайових випадків](root:sf-algorithms/gjk-collision/proj-gjk-collision-2d.md).

### Порівняння з іншими методами вузької фази

Історично конкурентами GJK виступали методи відстеження просторових елементів (англ. *feature-based tracking*), зокрема алгоритми Ліна–Кенні (Lin-Canny, 1991) та V-Clip (Mirtich, 1998). Вони шукають найближчу пару елементів (вершина-грань, ребро-ребро) шляхом локального переходу між сусідніми комірками Вороного на полігональних сітках.

Головна перевага GJK над підходами Ліна–Кенні та V-Clip полягає в універсальності:
- GJK не вимагає побудови топологічного графа суміжності (англ. *winged-edge* або *half-edge* структури даних) і не зберігає списки суміжних ребер.
- GJK працює з аналітичними криволінійними примітивами (сфери, еліпсоїди, конуси) за тими самими формулами, що й із многогранниками.
- GJK стійкий до чисельних вироджень при майже паралельних гранях, де алгоритми відстеження елементів ризикують зациклитися між двома рівновіддаленими конфігураціями.

### Покроковий числовий приклад розрахунку в 3D

Щоб побачити роботу алгоритму в числах, простежимо ітерації перевірки колізії для двох тривимірних тіл:
- **Тіло A:** куб з довжиною ребра 2, центрований у початку координат: `[-1, 1]³`.
- **Тіло B:** сфера радіусом `R = 1.0` із центром у точці `C_B = (1.5, 0.5, 0.0)`.

Оскільки куб сягає координати `x = 1.0`, а сфера з центром `1.5` і радіусом `1.0` займає діапазон `x ∈ [0.5, 2.5]`, вони перекриваються вздовж осі X на відрізку `[0.5, 1.0]`.

**Крок 1. Ініціалізація та перша точка:**
1. Обираємо початковий напрямок вздовж осі X: `d_0 = (1.0, 0.0, 0.0)`.
2. Опорна точка куба `A` у напрямку `d_0`: кутова вершина `s_A(d_0) = (1.0, 1.0, 1.0)`.
3. Опорна точка сфери `B` у протилежному напрямку `-d_0 = (-1.0, 0.0, 0.0)`:
   `s_B(-d_0) = (1.5, 0.5, 0.0) + 1.0 · (-1.0, 0.0, 0.0) = (0.5, 0.5, 0.0)`.
4. Перша точка різниці Мінковського:
   `P_0 = s_A(d_0) − s_B(-d_0) = (1.0, 1.0, 1.0) − (0.5, 0.5, 0.0) = (0.5, 0.5, 1.0)`.
5. Симплекс складається з однієї точки: `S = { P_0 }`.
6. Новий напрямок пошуку націлюємо на початок координат:
   `d_1 = −P_0 = (-0.5, -0.5, -1.0)`.

**Крок 2. Друга точка (утворення відрізка):**
1. Обчислюємо опорні точки у напрямку `d_1`:
   - Для куба: вершина `s_A(d_1) = (-1.0, -1.0, -1.0)`.
   - Для сфери: нормалізований вектор `d_1 / ||d_1|| ≈ (-0.408, -0.408, -0.816)`.
     Опорна точка сфери у напрямку `-d_1`:
     `s_B(-d_1) = (1.5, 0.5, 0.0) + 1.0 · (0.408, 0.408, 0.816) = (1.908, 0.908, 0.816)`.
2. Нова точка різниці Мінковського:
   `P_1 = (-1.0, -1.0, -1.0) − (1.908, 0.908, 0.816) = (-2.908, -1.908, -1.816)`.
3. Перевірка площини розділення:
   `P_1 · d_1 = (-2.908)·(-0.5) + (-1.908)·(-0.5) + (-1.816)·(-1.0) = 1.454 + 0.954 + 1.816 = 4.224 > 0`.
   Скалярний добуток строго додатний, що підтверджує перетин площини нуля.
4. Симплекс стає відрізком: `S = { P_1, P_0 }`.
5. Розв'язувач відрізка знаходить перпендикуляр `d_2 = (P_0 P_1 × (-P_1)) × P_0 P_1`, спрямований до нуля.

**Крок 3. Третя точка (утворення трикутника):**
1. Зондуємо межу вздовж нового перпендикуляра `d_2` і отримуємо третю вершину `P_2 = (1.2, -1.8, 0.4)`.
2. Скалярний добуток `P_2 · d_2 > 0` підтверджує наближення до нуля.
3. Симплекс стає трикутником `S = { P_2, P_1, P_0 }`.
4. Нормаль до трикутника `n = (P_1 − P_2) × (P_0 − P_2)` визначає напрямок `d_3` перпендикулярно до площини трикутника у бік нуля.

**Крок 4. Четверта точка (тетраедр та фіксація колізії):**
1. У напрямку нормалі `d_3` отримуємо точку `P_3 = (0.2, 0.8, -1.4)`.
2. Утворюється тетраедр із 4 вершин: `S = { P_3, P_2, P_1, P_0 }`.
3. Перевірка областей Вороного для трьох граней, що містять вершину `P_3`: скалярні добутки вектора `-P_3` з усіма трьома зовнішніми нормалями виявляються меншими за нуль.
4. Точка `(0, 0, 0)` повністю замкнена всередині тетраедра `P_3 P_2 P_1 P_0`.
5. Алгоритм фіксує перетин тіл за 4 ітерації!

### Обчислення точної евклідової відстані

Алгоритм GJK здатний не лише перевіряти булевий факт перетину, а й повертати точну евклідову відстань між розділеними тілами.

Коли тіла не перетинаються, вектор напрямку `d` на кожній ітерації спрямований від найближчої точки поточного симплекса `v ∈ S` до початку координат: `d = −v`. Довжина цього вектора `||v||` є поточною монотонно спадною оцінкою відстані зверху.

У міру додавання нових вершин симплекс підходить усе ближче до межі різниці Мінковського. Алгоритм зупиняється за двома критеріями:
1. Різниця між поточною відстанню `||v||` та проєкцією нової опорної точки `(P · d) / ||d||` стає меншою за чисельну похибку `ε` (наприклад, `1e-5`).
2. Довжина вектора `v` більше не зменшується між послідовними ітераціями.

Фінальний вектор `v` дає точну найкоротшу відстань `||v||`, а відновлення його барицентричного розкладу через опорні точки тіл `A` та `B` дозволяє точно знайти координати пари точок найближчого зближення на поверхнях обох фігур:

```
a* = ∑ λ_i · s_A(d_i)
b* = ∑ λ_i · s_B(−d_i)
```

де `λ_i` — барицентричні коефіцієнти проєкції початку координат на фінальний симплекс.

### Межа алгоритму та алгоритм EPA

Класичний GJK має одне принципове обмеження. Коли тіла вже заглибилися одне в одне (глибоке проникнення):
- Початок координат `O` опиняється строго всередині різниці Мінковського `A ⊖ B`.
- Евклідова відстань від `O` до множини дорівнює нулю.
- Вектор напрямку `d` вироджується в нульовий вектор (`||d|| = 0`), оскільки найближча точка до `O` — це сам початок координат.

Через це класичний GJK миттєво повертає відповідь «колізія є», але **не може повідомити глибину проникнення та контактну нормаль** (вектор найменшого зміщення, англ. *Minimum Translation Vector*, MTV), необхідний фізичному рушію для генерації сил реакції та розштовхування об'єктів.

Для розв'язання цієї задачі одразу після завершення GJK викликають алгоритм **EPA** (англ. *Expanding Polytope Algorithm*, розроблений Джино ван ден Бергеном у 2001 році):

1. EPA бере фінальний тетраедр GJK, який уже гарантовано містить початок координат `O`.
2. Усі грані тетраедра поміщаються в чергу з пріоритетом за відстанлю від нуля до площини грані.
3. Обирається найближча до нуля грань `F_min` із зовнішньою нормаллю `n_min`.
4. Викликається опорна функція різниці Мінковського в напрямку цієї нормалі: `w = s_A(n_min) − s_B(-n_min)`.
5. **Критерій зупинки EPA:** якщо відстань до нової точки `w · n_min` перевищує поточну відстань до грані менш ніж на `ε` (`(w · n_min) − dist(F_min) < ε`), це означає, що грань лежить на зовнішній межі різниці Мінковського. Вектор `dist(F_min) · n_min` і є шуканим вектором найменшого зміщення (глибиною та нормаллю контакту).
6. Якщо критерій не виконано, всі грані багатогранника, які «бачать» точку `w` (для яких `(w − v_face) · n_face > 0`), видаляються. На межі утвореного отвору формується контур ребер (силует), і точка `w` з'єднується з ребрами силуету, утворюючи нові трикутні грані.
7. Процес повторюється до досягнення межі або вичерпання ліміту ітерацій.

### Консервативне просування та неперервна колізія (CCD)

У високошвидкісних симуляціях (наприклад, політ кулі чи рух лопаті турбіни) дискретна перевірка колізій страждає від проблеми «тунелювання» (англ. *tunneling*): за один крок часу `Δt` швидкий тонкий об'єкт встигає повністю перелетіти крізь перешкоду, не перетнувши її в жодному з дискретних моментів `t` та `t + Δt`.

Алгоритм GJK у режимі обчислення точної відстані є базовим інструментом для **консервативного просування** (англ. *Conservative Advancement*, метод Браяна Міртіча):

1. У момент часу `t` обчислюємо точну відстань `d(t) = dist(A(t), B(t))` через GJK.
2. Знаючи максимальну лінійну швидкість `v_max` та кутову швидкість `ω_max` обох тіл, розраховуємо верхню межу швидкості їхнього взаємного зближення `v_rel`.
3. Визначаємо гарантовано безпечний крок за часом, протягом якого зіткнення неможливе за будь-яких умов:
   ```
   Δt_safe = d(t) / v_rel
   ```
4. Зсуваємо обидва об'єкти вперед у часі на `Δt_safe`.
5. Повторюємо запит GJK. Якщо відстань зменшилася до порогу контакту `d(t) < ε`, ми знайшли точний момент удару (англ. *Time of Impact*, TOI) без пропусків і без дорогого покрокового мікроінтегрування.

### Інтеграція в архітектуру фізичного рушія

У сучасних фізичних рушіях (NVIDIA PhysX, Havok, Bullet, Jolt Physics) конвеєр колізій організовано у три послідовні фази:

1. **Широка фаза (Broad Phase):**
   Використовує динамічні дерева орієнтованих обмежувальних паралелепіпедів (Dynamic BVH AABB) або алгоритм замітання вздовж осей (Sweep and Prune). Вона відсікає 99.9% пар об'єктів, які знаходяться завідомо далеко один від одного, за час `O(N log N)`.
2. **Середня фаза (Mid Phase):**
   Якщо об'єкт є складною увігнутою сіткою (наприклад, тривимірна модель ландшафту або кімнати), середня фаза використовує ієрархію обмежувальних об'ємів для відбору лише тих локальних опуклих фрагментів (трикутників або опуклих кластерів декомпозиції V-HACD), які перетинаються з AABB динамічного тіла.
3. **Вузька фаза (Narrow Phase):**
   Для кожної відібраної пари опуклих тіл викликається алгоритм **GJK**. Якщо GJK фіксує перетин, керування передається в **EPA** для отримання контактних точок і глибини проникнення. Отриманий контактний маніфольд (англ. *contact manifold*) надходить до LCP-розв'язувача (Projected Gauss-Seidel), який формує швидкісні імпульси для запобігання взаємному проникненню твердих тіл.

### Чисельна стійкість, SIMD-векторизація та часова когерентність

У реальних рушіях наївна математична модель GJK розбивається об обмежену точність чисел із плаваючою комою (`float32`). Без належного захисту алгоритм ризикує зациклитися або впасти через ділення на нуль:

1. **Захист від нульового напрямку:**
   Коли нова опорна точка збігається з нулем або вектор `AO` лежить на ребрі відрізка, потрійний векторний добуток повертає нульовий вектор. Будь-яка спроба нормалізувати такий вектор дає `NaN`. Код обов'язково перевіряє `dot(d, d) < 1e-8f` і підставляє довільну ортогональну вісь.
2. **Запобігання повторенню вершин:**
   Якщо нова опорна точка `P` вже міститься у списку вершин поточного симплекса (з точністю до `ε`), це свідчить про те, що межа фігури вичерпана, і подальший рух неможливий через похибку округлення. У такому разі цикл примусово переривається з результатом «розділені».
3. **Пакетна обробка через SIMD (AVX2 / ARM NEON):**
   Обчислення опорних функцій для многогранників організовують у форматі структури масивів (англ. *Structure of Arrays*, SoA), де координати `X`, `Y`, `Z` зберігаються в окремих вирівняних буферах. Це дозволяє обчислювати скалярні добутки одразу для 8 вершин за одну векторну інструкцію `_mm256_fmadd_ps`, прискорюючи виклик опорної функції в 4–6 разів.
4. **Часова когерентність (Warm Starting):**
   У фізичній симуляції об'єкти рухаються неперервно: за час одного кадру (16 мс) кут повороту й позиція змінюються на мізерні частки. Тому вісь розділення або фінальний симплекс із попереднього кадру є майже ідеальним початковим наближенням для наступного кадру. Використання збереженого симплекса як початкового стану дозволяє GJK сходитися **в середньому за 1–2 ітерації**, перетворюючи алгоритм на практично безкоштовну операцію `O(1)`.

Нижче наведено компактну, високопродуктивну реалізацію ядра перевірки перетину тривимірних тіл.

#include <stdbool.h>
#include <math.h>

typedef struct {
    float x, y, z;
} Vec3;

static inline Vec3 v3_add(Vec3 a, Vec3 b) { return (Vec3){ a.x + b.x, a.y + b.y, a.z + b.z }; }
static inline Vec3 v3_sub(Vec3 a, Vec3 b) { return (Vec3){ a.x - b.x, a.y - b.y, a.z - b.z }; }
static inline Vec3 v3_neg(Vec3 a)         { return (Vec3){ -a.x, -a.y, -a.z }; }
static inline float v3_dot(Vec3 a, Vec3 b) { return a.x * b.x + a.y * b.y + a.z * b.z; }

static inline Vec3 v3_cross(Vec3 a, Vec3 b) {
    return (Vec3){
        a.y * b.z - a.z * b.y,
        a.z * b.x - a.x * b.z,
        a.x * b.y - a.y * b.x
    };
}

typedef struct {
    Vec3 points[4];
    int count;
} Simplex3D;

static inline void simplex3d_push(Simplex3D* s, Vec3 p) {
    s->points[3] = s->points[2];
    s->points[2] = s->points[1];
    s->points[1] = s->points[0];
    s->points[0] = p;
    if (s->count < 4) s->count++;
}

/* Обробка відрізка (2 точки) */
static inline bool solve_line(Simplex3D* s, Vec3* dir) {
    Vec3 a = s->points[0], b = s->points[1];
    Vec3 ab = v3_sub(b, a), ao = v3_neg(a);

    if (v3_dot(ab, ao) > 0.0f) {
        *dir = v3_cross(v3_cross(ab, ao), ab);
        if (v3_dot(*dir, *dir) < 1e-8f) {
            *dir = (fabsf(ab.x) > 0.9f) ? (Vec3){ 0, 1, 0 } : (Vec3){ 1, 0, 0 };
            *dir = v3_cross(ab, *dir);
        }
    } else {
        s->points[0] = a;
        s->count = 1;
        *dir = ao;
    }
    return false;
}

/* Обробка трикутника (3 точки) */
static inline bool solve_triangle(Simplex3D* s, Vec3* dir) {
    Vec3 a = s->points[0], b = s->points[1], c = s->points[2];
    Vec3 ab = v3_sub(b, a), ac = v3_sub(c, a), ao = v3_neg(a);
    Vec3 abc = v3_cross(ab, ac);

    Vec3 ab_perp = v3_cross(ab, abc);
    Vec3 ac_perp = v3_cross(abc, ac);

    if (v3_dot(ab_perp, ao) > 0.0f) {
        s->points[0] = a;
        s->points[1] = b;
        s->count = 2;
        return solve_line(s, dir);
    }
    if (v3_dot(ac_perp, ao) > 0.0f) {
        s->points[0] = a;
        s->points[1] = c;
        s->count = 2;
        return solve_line(s, dir);
    }

    if (v3_dot(abc, ao) > 0.0f) {
        *dir = abc;
    } else {
        s->points[1] = c;
        s->points[2] = b;
        *dir = v3_neg(abc);
    }
    return false;
}

/* Обробка тетраедра (4 точки) */
static inline bool solve_tetrahedron(Simplex3D* s, Vec3* dir) {
    Vec3 a = s->points[0], b = s->points[1], c = s->points[2], d = s->points[3];
    Vec3 ab = v3_sub(b, a), ac = v3_sub(c, a), ad = v3_sub(d, a), ao = v3_neg(a);

    Vec3 abc = v3_cross(ab, ac);
    Vec3 acd = v3_cross(ac, ad);
    Vec3 adb = v3_cross(ad, ab);

    if (v3_dot(abc, ao) > 0.0f) {
        s->points[0] = a; s->points[1] = b; s->points[2] = c;
        s->count = 3;
        return solve_triangle(s, dir);
    }
    if (v3_dot(acd, ao) > 0.0f) {
        s->points[0] = a; s->points[1] = c; s->points[2] = d;
        s->count = 3;
        return solve_triangle(s, dir);
    }
    if (v3_dot(adb, ao) > 0.0f) {
        s->points[0] = a; s->points[1] = d; s->points[2] = b;
        s->count = 3;
        return solve_triangle(s, dir);
    }

    /* Початок координат лежить усередині всіх чотирьох граней */
    return true;
}

static inline bool solve_simplex3d(Simplex3D* s, Vec3* dir) {
    if (s->count == 2) return solve_line(s, dir);
    if (s->count == 3) return solve_triangle(s, dir);
    if (s->count == 4) return solve_tetrahedron(s, dir);
    return false;
}

typedef Vec3 (*SupportFn3D)(const void* obj, Vec3 dir);

bool gjk_intersect_3d(const void* obj_a, SupportFn3D sup_a,
                      const void* obj_b, SupportFn3D sup_b) {
    Vec3 dir = { 0.0f, 1.0f, 0.0f };
    Vec3 p = v3_sub(sup_a(obj_a, dir), sup_b(obj_b, v3_neg(dir)));

    Simplex3D simplex = { .count = 0 };
    simplex3d_push(&simplex, p);
    dir = v3_neg(p);

    for (int iter = 0; iter < 40; ++iter) {
        if (v3_dot(dir, dir) < 1e-8f) return true;

        p = v3_sub(sup_a(obj_a, dir), sup_b(obj_b, v3_neg(dir)));
        if (v3_dot(p, dir) <= 0.0f) return false;

        simplex3d_push(&simplex, p);
        if (solve_simplex3d(&simplex, &dir)) return true;
    }
    return false;
}

#include <array>
#include <cmath>
#include <span>
#include <concepts>

struct Vec3 {
    float x{0.0f}, y{0.0f}, z{0.0f};

    constexpr Vec3 operator+(Vec3 r) const noexcept { return {x + r.x, y + r.y, z + r.z}; }
    constexpr Vec3 operator-(Vec3 r) const noexcept { return {x - r.x, y - r.y, z - r.z}; }
    constexpr Vec3 operator-() const noexcept { return {-x, -y, -z}; }
    constexpr float dot(Vec3 r) const noexcept { return x * r.x + y * r.y + z * r.z; }

    constexpr Vec3 cross(Vec3 r) const noexcept {
        return {
            y * r.z - z * r.y,
            z * r.x - x * r.z,
            x * r.y - y * r.x
        };
    }
};

class Simplex3D {
public:
    std::array<Vec3, 4> points{};
    int count{0};

    void push_front(Vec3 p) noexcept {
        points[3] = points[2];
        points[2] = points[1];
        points[1] = points[0];
        points[0] = p;
        if (count < 4) ++count;
    }

    bool solve(Vec3& dir) noexcept {
        if (count == 2) return solve_line(dir);
        if (count == 3) return solve_triangle(dir);
        if (count == 4) return solve_tetrahedron(dir);
        return false;
    }

private:
    bool solve_line(Vec3& dir) noexcept {
        Vec3 a = points[0], b = points[1];
        Vec3 ab = b - a, ao = -a;

        if (ab.dot(ao) > 0.0f) {
            dir = ab.cross(ao).cross(ab);
            if (dir.dot(dir) < 1e-8f) {
                Vec3 axis = (std::abs(ab.x) > 0.9f) ? Vec3{0, 1, 0} : Vec3{1, 0, 0};
                dir = ab.cross(axis);
            }
        } else {
            points[0] = a;
            count = 1;
            dir = ao;
        }
        return false;
    }

    bool solve_triangle(Vec3& dir) noexcept {
        Vec3 a = points[0], b = points[1], c = points[2];
        Vec3 ab = b - a, ac = c - a, ao = -a;
        Vec3 abc = ab.cross(ac);

        Vec3 ab_perp = ab.cross(abc);
        Vec3 ac_perp = abc.cross(ac);

        if (ab_perp.dot(ao) > 0.0f) {
            points[0] = a; points[1] = b; count = 2;
            return solve_line(dir);
        }
        if (ac_perp.dot(ao) > 0.0f) {
            points[0] = a; points[1] = c; count = 2;
            return solve_line(dir);
        }

        if (abc.dot(ao) > 0.0f) {
            dir = abc;
        } else {
            points[1] = c;
            points[2] = b;
            dir = -abc;
        }
        return false;
    }

    bool solve_tetrahedron(Vec3& dir) noexcept {
        Vec3 a = points[0], b = points[1], c = points[2], d = points[3];
        Vec3 ab = b - a, ac = c - a, ad = d - a, ao = -a;

        Vec3 abc = ab.cross(ac);
        Vec3 acd = ac.cross(ad);
        Vec3 adb = ad.cross(ab);

        if (abc.dot(ao) > 0.0f) {
            points[0] = a; points[1] = b; points[2] = c; count = 3;
            return solve_triangle(dir);
        }
        if (acd.dot(ao) > 0.0f) {
            points[0] = a; points[1] = c; points[2] = d; count = 3;
            return solve_triangle(dir);
        }
        if (adb.dot(ao) > 0.0f) {
            points[0] = a; points[1] = d; points[2] = b; count = 3;
            return solve_triangle(dir);
        }
        return true;
    }
};

template <typename ShapeA, typename ShapeB, typename SupA, typename SupB>
bool gjk_intersect_3d(const ShapeA& a, SupA sup_a,
                      const ShapeB& b, SupB sup_b) noexcept {
    Vec3 dir{0.0f, 1.0f, 0.0f};
    Vec3 p = sup_a(a, dir) - sup_b(b, -dir);

    Simplex3D simplex;
    simplex.push_front(p);
    dir = -p;

    for (int iter = 0; iter < 40; ++iter) {
        if (dir.dot(dir) < 1e-8f) return true;

        p = sup_a(a, dir) - sup_b(b, -dir);
        if (p.dot(dir) <= 0.0f) return false;

        simplex.push_front(p);
        if (simplex.solve(dir)) return true;
    }
    return false;
}
