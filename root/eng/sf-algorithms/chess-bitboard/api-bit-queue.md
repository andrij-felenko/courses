# 📋 Специфікація інтерфейсу пріоритетної бітової черги (Bit-Queue API)

Пріоритетна бітова черга (*Bit-Queue*) є низькорівневою структурою даних ядра операційної системи та мережевих підсистем. Її головне призначення — відстеження активних дискретних каналів або рівнів пріоритету та їхня вибірка за сталий час `O(1)` за допомогою апаратного сканування бітів.

На відміну від черг на основі бінарних куп (*binary heaps*, де вилучення елемента вимагає `O(log N)` операцій) чи масивів зв'язних списків (де пошук непорожнього списку вимагає `O(N)` сканування), бітова черга використовує регістрові бітові маски. Процесор маніпулює всіма рівнями пріоритету одночасно за 1 такт АЛП.

Нижче наведено формальну специфікацію системного програмного інтерфейсу (C та C++ API) для однослівної (64 рівні) та двослівної (128 рівнів) реалізацій бітової черги.

---

### Структури даних та представлення в пам'яті

Пріоритетна бітова черга зберігає компактний бітовий масив, де кожен розряд `i` кодує стан готовності відповідного рівня: `1` — рівень містить активні задачі або події, `0` — черга цього рівня порожня.

Для запобігання хибному розділенню кеш-ліній (*false sharing*) у багатоядерних системах структури бітової черги вирівнюються по межі 64 байтів (розмір стандартної кеш-лінії L1D).

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

/* 64-бітна пріоритетна бітова черга */
typedef struct {
    uint64_t mask;           /* Бітова маска активних рівнів (розряди 0..63) */
    size_t   count;          /* Загальна кількість елементів у всіх чергах */
} BitQueue64;

/* 128-бітна розширена пріоритетна бітова черга */
typedef struct {
    uint64_t words[2];       /* words[0] — рівні 0..63, words[1] — рівні 64..127 */
    size_t   count;          /* Сумарна кількість елементів у системі */
} BitQueue128;
```
```cpp
#include <cstdint>
#include <cstddef>
#include <array>
#include <bit>
#include <optional>

struct alignas(64) BitQueue64 {
    uint64_t mask{0};
    size_t   count{0};
};

struct alignas(64) BitQueue128 {
    std::array<uint64_t, 2> words{0, 0};
    size_t                  count{0};
};
```
:::

### Специфікація функцій (Таблиця інтерфейсу)

| Функція / Метод | Складність | Призначення та семантика |
| :--- | :--- | :--- |
| `bitq64_init` | `O(1)` | Ініціалізує чергу у порожній стан (`mask = 0`, `count = 0`). |
| `bitq64_set` | `O(1)` | Встановлює біт рівня `level` у масці (`mask |= (1ULL << level)`). |
| `bitq64_clear` | `O(1)` | Скидає біт рівня `level` у масці (`mask &= ~(1ULL << level)`). |
| `bitq64_test` | `O(1)` | Перевіряє, чи активний рівень `level` (`(mask >> level) & 1`). |
| `bitq64_find_highest` | `O(1)` | Повертає номер наймолодшого встановленого біта (`CTZ`) або `-1`, якщо маска порожня. |
| `bitq64_find_lowest` | `O(1)` | Повертає номер найстаршого встановленого біта (`63 - CLZ`) або `-1`. |
| `bitq64_pop_highest` | `O(1)` | Знаходить найвищий пріоритет та скидає його розряд у масці за 1 виклик. |
| `bitq64_active_levels` | `O(1)` | Повертає кількість активних рівнів пріоритету через `POPCNT`. |

### Детальний опис контрактів функцій

#### 1. Ініціалізація черги (`bitq64_init`)

:::tabs
```c
void bitq64_init(BitQueue64 *q) {
    if (q != NULL) {
        q->mask = 0;
        q->count = 0;
    }
}
```
```cpp
void bitq64_init(BitQueue64& q) noexcept {
    q.mask = 0;
    q.count = 0;
}
```
:::

- **Вхідні вимоги (Preconditions):** Вказівник `q` повинен вказувати на валідну область пам'яті;
- **Гарантії (Postconditions):** Поле `q->mask` дорівнює нулю, `q->count` дорівнює нулю. Усі біти деактивовані;
- **Помилки та винятки:** Функція є абсолютно безпечною і не породжує виняткових ситуацій.

---

#### 2. Активація рівня (`bitq64_set`)

:::tabs
```c
void bitq64_set(BitQueue64 *q, uint8_t level) {
    if (level < 64) {
        q->mask |= (1ULL << level);
    }
}
```
```cpp
void bitq64_set(BitQueue64& q, uint8_t level) noexcept {
    if (level < 64) {
        q.mask |= (1ULL << level);
    }
}
```
:::

- **Семантика:** Встановлює біт на позиції `level`. Якщо рівень уже був активним, стан маски не змінюється (операція ідемпотентна);
- **Крайові випадки:** Якщо `level >= 64`, виклик ігнорується для запобігання невизначеній поведінці при зсуві понад розрядність слова;
- **Апаратна трансляція:** В архітектурі x86-64 транслюється в одну інструкцію `BTS` (*Bit Test and Set*) або послідовність `MOV` + `SHL` + `OR`.

---

#### 3. Деактивація рівня (`bitq64_clear`)

:::tabs
```c
void bitq64_clear(BitQueue64 *q, uint8_t level) {
    if (level < 64) {
        q->mask &= ~(1ULL << level);
    }
}
```
```cpp
void bitq64_clear(BitQueue64& q, uint8_t level) noexcept {
    if (level < 64) {
        q.mask &= ~(1ULL << level);
    }
}
```
:::

- **Семантика:** Скидає розряд `level` у нуль. Викликається диспетчером, коли список задач на цьому рівні стає повністю порожнім;
- **Апаратна трансляція:** В архітектурі x86-64 транслюється в інструкцію `BTR` (*Bit Test and Reset*).

---

#### 4. Пошук найвищого пріоритету (`bitq64_find_highest`)

:::tabs
```c
int bitq64_find_highest(const BitQueue64 *q) {
    if (q->mask == 0) {
        return -1;
    }
    #if defined(_MSC_VER)
    unsigned long idx;
    _BitScanForward64(&idx, q->mask);
    return (int)idx;
    #else
    return __builtin_ctzll(q->mask);
    #endif
}
```
```cpp
[[nodiscard]] std::optional<uint8_t> bitq64_find_highest(const BitQueue64& q) noexcept {
    if (q.mask == 0) {
        return std::nullopt;
    }
    return static_cast<uint8_t>(std::countr_zero(q.mask));
}
```
:::

- **Семантика:** Знаходить порядковий номер молодшого одиничного розряду. В операційних системах менший числовий індекс відповідає критичнішому рівню пріоритету (рівень 0 — задачі жорсткого реального часу);
- **Повертане значення:** Число від `0` до `63` при наявності активних бітів, або `-1` (`std::nullopt`), якщо вся маска порожня (стан відсутності готових задач у системі, перехід у режим сну процесора `HLT` чи `WFI`);
- **Швидкодія:** Виконується рівно за 1 машинний такт завдяки виділеному комбінаційному блоку `TZCNT`/`CTZ` в АЛП.

---

#### 5. Вилучення найвищого пріоритету (`bitq64_pop_highest`)

:::tabs
```c
int bitq64_pop_highest(BitQueue64 *q) {
    if (q->mask == 0) {
        return -1;
    }
    int highest = __builtin_ctzll(q->mask);
    /* Скидання наймолодшого біта через вираз x & (x - 1) */
    q->mask &= (q->mask - 1);
    return highest;
}
```
```cpp
[[nodiscard]] std::optional<uint8_t> bitq64_pop_highest(BitQueue64& q) noexcept {
    if (q.mask == 0) {
        return std::nullopt;
    }
    const uint8_t highest = static_cast<uint8_t>(std::countr_zero(q.mask));
    q.mask &= (q.mask - 1);
    return highest;
}
```
:::

- **Семантика:** Поєднує сканування молодшого розряду та його атомарне витирання з маски;
- **Апаратна оптимізація:** Скидання біта `mask &= mask - 1` транслюється процесором в інструкцію `BLSR` (*Reset Lowest Set Bit*) із набору інструкцій BMI1.

### Робота з розширеною 128-бітною чергою (`BitQueue128`)

Для систем, які потребують понад 64 рівні пріоритетів (наприклад, планувальник Linux зі 140 рівнями), маска розширюється на кілька слів.

:::tabs
```c
int bitq128_find_highest(const BitQueue128 *q) {
    if (q->words[0] != 0) {
        return __builtin_ctzll(q->words[0]);
    }
    if (q->words[1] != 0) {
        return 64 + __builtin_ctzll(q->words[1]);
    }
    return -1;
}
```
```cpp
[[nodiscard]] std::optional<uint8_t> bitq128_find_highest(const BitQueue128& q) noexcept {
    if (q.words[0] != 0) {
        return static_cast<uint8_t>(std::countr_zero(q.words[0]));
    }
    if (q.words[1] != 0) {
        return static_cast<uint8_t>(64 + std::countr_zero(q.words[1]));
    }
    return std::nullopt;
}
```
:::

Вибір найвищого пріоритету спочатку перевіряє молодше 64-бітне слово `words[0]`. Якщо воно ненульове, результат повертається миттєво без звернення до другого слова. Це оптимізує критичний шлях диспетчеризації для високопріоритетних процесів.

### Конкурентний доступ та бар'єри пам'яті

У багатоядерних SMP-системах кілька процесорних ядер можуть одночасно додавати задачі до черг різних пріоритетів. Для усунення гонитви даних (*data race*) встановлення та скидання бітів виконується атомарними інструкціями шини пам'яті з явною семантикою впорядкування пам'яті (*memory ordering semantics*):

:::tabs
```c
#include <stdatomic.h>

void bitq64_atomic_set(_Atomic uint64_t *mask, uint8_t level) {
    atomic_fetch_or_explicit(mask, (1ULL << level), memory_order_release);
}

void bitq64_atomic_clear(_Atomic uint64_t *mask, uint8_t level) {
    atomic_fetch_and_explicit(mask, ~(1ULL << level), memory_order_release);
}
```
```cpp
#include <atomic>

void bitq64_atomic_set(std::atomic<uint64_t>& mask, uint8_t level) noexcept {
    mask.fetch_or(1ULL << level, std::memory_order_release);
}

void bitq64_atomic_clear(std::atomic<uint64_t>& mask, uint8_t level) noexcept {
    mask.fetch_and(~(1ULL << level), std::memory_order_release);
}
```
:::

Використання `memory_order_release` гарантує, що всі зміни в структурі вузла задачі (`task->priority`, `task->state`, `task->next`) стануть повністю видимими іншим процесорним ядрам до того, як біт готовності з'явиться у загальній масці черги. При вибірці задачі диспетчер використовує `memory_order_acquire`, що запобігає спекулятивному читанню даних задачі до перевірки біта готовності.

### Інваріанти стану та діагностика

Для систем підвищеної надійності та авіоніки (де збій планувальника є неприпустимим) контракт бітової черги доповнюється діагностичною функцією валідації інваріантів:

:::tabs
```c
bool bitq64_validate(const BitQueue64 *q, size_t actual_non_empty_queues) {
    if (q == NULL) return false;
    /* Кількість одиничних бітів повинна строго дорівнювати кількості непорожніх списків */
    return (size_t)__builtin_popcountll(q->mask) == actual_non_empty_queues;
}
```
```cpp
[[nodiscard]] bool bitq64_validate(const BitQueue64& q, size_t actual_non_empty_queues) noexcept {
    return static_cast<size_t>(std::popcount(q.mask)) == actual_non_empty_queues;
}
```
:::

### Типові інженерні пастки при роботі з бітовими чергами

1. **Невизначена поведінка при зсувах понад розрядність слова:** У мовах C та C++ зсув `1ULL << 64` є невизначеною поведінкою (*Undefined Behavior*). На процесорах x86 інструкція `SHL` обрізає величину зсуву за маскою `count & 63`, тому вираз `1ULL << 64` перетворюється на `1ULL << 0 = 1`, несанкціоновано вмикаючи нульовий пріоритет. Усі виклики API зобов'язані перевіряти умову `level < 64`;
2. **Передчасне скидання біта в масці:** Якщо в черзі певного пріоритету перебуває кілька задач, після вилучення першої з них скидати біт у масці категорично заборонено. Біт повинен скидатися лише тоді, коли голова списку стає рівною `NULL` (`q->head == NULL`);
3. **Поведінка інструкції `BSF` на нульовому операнді:** Застаріла інструкція x86 `BSF` (*Bit Scan Forward*) при нульовому вхідному операнді залишає вихідний регістр у невизначеному стані й лише встановлює прапорець нуля `ZF = 1`. Новіша інструкція `TZCNT` повертає точне число 64 при вхідному нулі. Програмний інтерфейс захищає від цієї пастки попередньою перевіркою `if (mask == 0)`.

### Апаратне транслювання та машинний код

Нижче наведено порівняння генерації асемблерного коду для ключових операцій пріоритетної черги на провідних процесорних архітектурах:

#### 1. Сканування молодшого біта (`CTZ`)
- **x86-64 (з прапорцем `-mbmi`):** Інструкція `tzcnt rax, rdi` (1 такт затримки, пропускна здатність 1 інструкція за такт);
- **x86-64 (застарілий базовий набір):** Інструкція `bsf rax, rdi` (3 такти затримки);
- **ARM64:** Пара інструкцій `rbit x0, x0` + `clz x0, x0` (по 1 такту кожна, сумарно 2 такти);
- **RISC-V (розширення Zbb):** Інструкція `ctz a0, a0` (1 такт).

#### 2. Скидання молодшого біта (`BLSR`)
- **x86-64 (з прапорцем `-mbmi`):** Інструкція `blsr rax, rdi` (1 такт);
- **x86-64 (без BMI):** `lea rdx, [rdi - 1]` + `and rax, rdx` (2 такти);
- **ARM64:** `sub x1, x0, #1` + `and x0, x0, x1` (2 такти);
- **RISC-V:** `addi a1, a0, -1` + `and a0, a0, a1` (2 такти).

Завдяки цьому апаратному забезпеченню маніпуляції з бітовою чергою виконуються з максимально можливою швидкістю процесора, повністю усуваючи накладні витрати на диспетчеризацію в критичних вузлах операційної системи.
