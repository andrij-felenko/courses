# 🧮 Математичне обґрунтування алгоритму Касаї

Масив найдовших спільних префіксів (Longest Common Prefix, LCP) є необхідним доповненням до суфіксного масиву, оскільки саме він перетворює простий список позицій на повноцінний індекс, здатний знаходити повтори, спільні підрядки та виконувати швидкий двійковий пошук.

Наївне обчислення спільних префіксів для кожної пари сусідніх у суфіксному масиві елементів вимагає посимвольного порівняння рядків. У найгіршому випадку (наприклад, для рядка з однакових символів `aⁿ`) порівняння кожного суфікса довжини `k` із суфіксом довжини `k-1` займає `O(k)` операцій, що дає сумарну квадратичну складність `O(N²)`.

Алгоритм Касаї, Арікави, Арімури, Лі та Парка (2001) обчислює весь масив LCP за строго лінійний час `O(N)`. Нижче наведено математичне доведення інваріантів коректності та амортизованої складності цього алгоритму.

---

## 1. Формальні позначення

Нехай задано текст `T = t[0] t[1] ... t[N-1]` довжини `N` над скінченним алфавітом `Σ`, що завершується унікальним термінальним символом `$`.

1. **Суфікс:** `S[i] = T[i..N-1]` — суфікс рядка `T`, що починається з позиції `i` (`0 ≤ i < N`);
2. **Суфіксний масив `SA`:** перестановка індексів `[0, 1, ..., N-1]` така, що суфікси впорядковані лексикографічно:
```
S[SA[0]] < S[SA[1]] < S[SA[2]] < ... < S[SA[N-1]]
```
3. **Обернений суфіксний масив (масив рангів `Rank`):** масив позицій суфіксів у `SA`:
```
Rank[i] = k   ⇔   SA[k] = i
```
4. **Функція найдовшого спільного префікса `lcp(A, B)`:** довжина найдовшого початкового фрагмента, однакового в рядках `A` та `B`:
```
lcp(A, B) = max { k : A[0..k-1] = B[0..k-1] }
```
5. **Масив `LCP`:** довжина спільного префікса сусідніх суфіксів у лексикографічному порядку:
```
LCP[0] = 0
LCP[k] = lcp( S[SA[k]], S[SA[k-1]] )    для 1 ≤ k < N
```
6. **Величина `h(i)`:** довжина спільного префікса між суфіксом `S[i]` та його безпосереднім лівим сусідом у суфіксному масиві:
```
h(i) = LCP[Rank[i]] = lcp( S[i], S[SA[Rank[i] - 1]] )    при Rank[i] > 0
```

## 2. Головна лема Касаї про нерівність довжин префіксів

Ключова ідея алгоритму полягає в обробці суфіксів не в порядку їхнього розташування в суфіксному масиві `SA` (де суфікси стрибають по всьому тексту), а в **природному порядку тексту**: `S[0], S[1], S[2], ..., S[N-1]`.

> **Лема 1 (Нерівність Касаї).** Для будь-якої позиції `i` (`0 < i < N`), якщо `Rank[i-1] > 0` та `Rank[i] > 0`, виконується нерівність:
> ```
> h(i) ≥ h(i-1) - 1
> ```

### Доведення

Нехай `Rank[i-1] = r`, де `r > 0`. Це означає, що в суфіксному масиві безпосередньо перед суфіксом `S[i-1]` стоїть деякий суфікс `S[j]`, тобто `j = SA[r - 1]`.

За означенням функції `h`:
```
h(i-1) = lcp( S[i-1], S[j] )
```

Розглянемо можливі значення `h(i-1)`:

**Випадок 1:** `h(i-1) ≤ 1`.
Тоді права частина нерівності:
```
h(i-1) - 1 ≤ 0
```
Оскільки довжина спільного префікса будь-яких двох рядків є невід'ємною величиною (`h(i) ≥ 0`), нерівність `h(i) ≥ 0 ≥ h(i-1) - 1` виконується тривіально.

**Випадок 2:** `h(i-1) > 1`.
Нехай `k = h(i-1)`. Оскільки `lcp(S[i-1], S[j]) = k > 1`, перші `k` символів суфіксів `S[i-1]` та `S[j]` повністю збігаються:
```
T[i-1 .. i-1 + k - 1] = T[j .. j + k - 1]
```
Зокрема, їхні перші символи рівні: `T[i-1] = T[j]`.

Оскільки `S[j] < S[i-1]` за лексикографічним порядком у `SA`, і їхні перші символи збігаються, відкидання першого символу зберігає строгий лексикографічний порядок між утвореними залишками:
```
S[j+1] < S[i]
```

При цьому довжина спільного префікса між `S[j+1]` та `S[i]` зменшується рівно на один символ:
```
lcp( S[i], S[j+1] )
= lcp( S[i-1], S[j] ) - 1     [відкинули однаковий перший символ T[i-1] = T[j]]
= h(i-1) - 1                   [за означенням h(i-1) = lcp(S[i-1], S[j])]
```

Оскільки `S[j+1] < S[i]`, у відсортованому масиві `SA` суфікс `S[j+1]` розташований строго лівіше від `S[i]`:
```
Rank[j+1] < Rank[i]
```

Нехай `p = SA[Rank[i] - 1]` — безпосередній попередник суфікса `S[i]` у масиві `SA`. Тоді маємо ланцюжок лексикографічного порядку:
```
S[j+1] ≤ S[p] < S[i]
```

З фундаментальної властивості лексикографічного впорядкування випливає, що спільний префікс між крайніми елементами не перевищує спільного префікса між будь-якими проміжними сусідами:
```
lcp( S[j+1], S[i] ) = min( lcp( S[j+1], S[p] ), lcp( S[p], S[i] ) )
```
Звідси безпосередньо випливає:
```
lcp( S[p], S[i] ) ≥ lcp( S[j+1], S[i] )
```

Оскільки за означенням `h(i) = lcp(S[p], S[i])` та `lcp(S[j+1], S[i]) = h(i-1) - 1`, отримуємо:
```
h(i) ≥ h(i-1) - 1
```
Лему повністю доведено.

## 3. Амортизований аналіз часової складності O(N)

Нерівність `h(i) ≥ h(i-1) - 1` є основою для оптимізації посимвольних порівнянь.

При переході від обчислення LCP для суфікса `S[i-1]` до суфікса `S[i]` алгоритм не починає порівняння символів з нульової позиції. Замість цього поточне значення лічильника `h` зменшується щонайбільше на одиницю:
```
h_start = max( 0, h_prev - 1 )
```
Після цього виконується пряме посимвольне порівняння, починаючи з індексу `h_start`, доки символи збігаються, збільшуючи `h` на кожному успішному кроці.

Порахуємо загальну кількість операцій:
1. **Зовнішній цикл** виконується рівно `N` разів (для кожного індексу `i` від `0` до `N-1`);
2. На кожній ітерації зовнішнього циклу значення `h` може **зменшитися** не більше ніж на `1`. Отже, сумарне зменшення `h` за всі `N` ітерацій не перевищує `N`;
3. Значення `h` ніколи не може бути від'ємним (`h ≥ 0`) і ніколи не може перевищувати довжину тексту `N` (`h ≤ N`);
4. Нехай `Δ⁺` — загальна кількість операцій **інкременту** (`h++`) у внутрішньому циклі `while`.

З балансу змін величини `h`:
```
h_final = h_initial + Δ⁺ - Δ⁻
```
Підставивши граничні значення `h_initial = 0`, `h_final ≤ N` та `Δ⁻ ≤ N`, отримуємо:
```
Δ⁺
= h_final + Δ⁻ - h_initial     [алгебраїчне перенесення доданків]
≤ N + N - 0                   [оскільки h_final ≤ N та Δ⁻ ≤ N]
≤ 2N                          [сума обмежень]
```

Оскільки внутрішній цикл `while` виконує порівняння символів рівно стільки разів, скільки відбувається інкрементів `h++` (плюс одне неуспішне порівняння на кожну ітерацію зовнішнього циклу), сумарна кількість посимвольних порівнянь за весь час роботи алгоритму становить:
```
Порівнянь ≤ 2N + N = 3N
```

Отже, алгоритм Касаї гарантує часову складність `O(N)` у найгіршому випадку.

## 4. Зв'язок LCP із запитами RMQ (Range Minimum Query)

Для довільних двох суфіксів `S[SA[a]]` та `S[SA[b]]` (де `a < b`), які не обов'язково є сусідами в суфіксному масиві, довжина їхнього спільного префікса визначається наступною теоремою:

> **Теорема 2 (LCP через мінімум на відрізку).** Для будь-яких індексів `0 ≤ a < b < N` у суфіксному масиві:
> ```
> lcp( S[SA[a]], S[SA[b]] ) = min_{a < k ≤ b} LCP[k]
> ```

### Доведення

Доведемо теорему за математичною індукцією за величиною інтервалу `d = b - a`.

**База індукції (`d = 1`, тобто `b = a + 1`):**
За означенням масиву `LCP`:
```
lcp( S[SA[a]], S[SA[a+1]] ) = LCP[a+1] = min_{a < k ≤ a+1} LCP[k]
```
Твердження виконується.

**Індукційний перехід:**
Припустимо, що твердження істинне для всіх пар з відстанню `b - a = d - 1`. Розглянемо пару з відстанню `d`: суфікси `S[SA[a]]` та `S[SA[b]]`.

Розглянемо проміжний суфікс `S[SA[b-1]]`. Оскільки `SA` відсортовано лексикографічно:
```
S[SA[a]] ≤ S[SA[b-1]] ≤ S[SA[b]]
```

З властивості лексикографічного порядку спільний префікс між трьома впорядкованими рядками задовольняє рівність:
```
lcp( S[SA[a]], S[SA[b]] ) = min( lcp( S[SA[a]], S[SA[b-1]] ), lcp( S[SA[b-1]], S[SA[b]] ) )
```

За припущенням індукції:
```
lcp( S[SA[a]], S[SA[b-1]] ) = min_{a < k ≤ b-1} LCP[k]
```
А за базою індукції:
```
lcp( S[SA[b-1]], S[SA[b]] ) = LCP[b]
```

Об'єднуючи мінімуми:
```
lcp( S[SA[a]], S[SA[b]] )
= min( min_{a < k ≤ b-1} LCP[k], LCP[b] )   [підстановка за індукційним припущенням]
= min_{a < k ≤ b} LCP[k]                    [об'єднання діапазонів пошуку мінімуму]
```
Індукційний перехід доведено.

Завдяки побудові структури даних [Таблиця заміни (Sparse Table)](root:sf-algorithms/sparse-table) над масивом `LCP` за час `O(N log N)`, запит мінімуму на довільному відрізку `min_{a < k ≤ b} LCP[k]` виконується за `O(1)` час. Це дозволяє обчислювати найдовший спільний префікс будь-якої пари суфіксів за константний час.
