# Суфіксний масив

<preknowlist>
- [Масив](root:sf-algorithms/array) — послідовне розміщення елементів у пам'яті з доступом за O(1).
- [Двійковий пошук](root:sf-algorithms/binary-search) — знаходження меж діапазону у відсортованому масиві за O(log N).
- [Таблиця заміни (Sparse Table)](root:sf-algorithms/sparse-table) — статична структура для запитів мінімуму на відрізку (RMQ) за O(1).
- [Швидке сортування](root:sf-algorithms/quicksort) — алгоритм сортування масиву на основі розділення відносно опорного елемента.
- [Побітові операції](root:sf-algorithms/bitwise-operations) — бітові зсуви та маски для оптимізації структур даних.
</preknowlist>

Коли пошукова система обробляє запити над базою вихідного коду обсягом 50 гігабайтів або біоінформатичний конвеєр шукає мутації серед 3.2 мільярда пар основ геному людини, лінійне сканування тексту алгоритмами типу KMP чи Боєра — Мура вимагає секунди на кожен запит. Якщо система повинна обслуговувати тисячі запитів на секунду з часом відповіді менше однієї мілісекунди, текст необхідно попередньо проіндексувати.

Будь-який шуканий підрядок `P` довжини `M` зустрічається у вихідному тексті `T` довжини `N` тоді й лише тоді, коли `P` є префіксом деякого суфікса тексту `T`. Якщо виписати всі `N` можливих суфіксів тексту `T` і відсортувати їх у лексикографічному порядку, всі суфікси, що починаються зі зразка `P`, опиняться поруч і утворять один неперервний діапазон. Проте пряме збереження всіх суфіксів у пам'яті вимагало б `O(N²)` байтів (для тексту в 3 ГБ це понад 4.5 ексабайта).

Вихід полягає у збереженні лише числових початкових позицій суфіксів у єдиному компактному масиві цілих чисел `SA[0..N-1]`. Така структура даних називається **суфіксним масивом** (англ. *suffix array*, від лат. *suffixus* — прикріплений ззаду, та ст.-фр. *areiier* — приводити в порядок, шикувати).

## 1. Анатомія та представлення в пам'яті

Нехай задано рядок `T` довжини `N`, пронумерований від `0` до `N-1`. **Суфіксом** `S[i]` називається підрядок `T[i..N-1]`, що починається з індексу `i` і триває до самого кінця рядка.

```
Текст: T = "banana$" (довжина N = 7)

Всі суфікси тексту T:
  i = 0:  "banana$"
  i = 1:  "anana$"
  i = 2:  "nana$"
  i = 3:  "ana$"
  i = 4:  "na$"
  i = 5:  "a$"
  i = 6:  "$"
```

**Суфіксний масив** `SA` (Suffix Array) — це перестановка цілих чисел `[0, 1, ..., N-1]`, яка задає початкові позиції суфіксів у порядку їхнього лексикографічного зростання:

```
T[SA[0]..N-1] < T[SA[1]..N-1] < T[SA[2]..N-1] < ... < T[SA[N-1]..N-1]
```

Для рядка `"banana$"` відсортовані суфікси та відповідний масив `SA` мають вигляд:

```
Ранг k | SA[k] | Суфікс T[SA[k]..N-1]
-------+-------+---------------------
   0   |   6   | "$"
   1   |   5   | "a$"
   2   |   3   | "ana$"
   3   |   1   | "anana$"
   4   |   0   | "banana$"
   5   |   4   | "na$"
   6   |   2   | "nana$"
```

Таким чином, суфіксний масив для `"banana$"` являє собою масив із семи цілих чисел: `SA = [6, 5, 3, 1, 0, 4, 2]`.

![Концепція та побудова суфіксного масиву](/root/eng/sf-algorithms/suffix-array/img/suffix-array-concept.svg)
*Формування суфіксного масиву для рядка "banana$": виписування суфіксів, їхнє лексикографічне впорядкування та збереження числових індексів початку.*

### Роль термінального символу-сентинела

Для однозначності лексикографічного сортування в кінець тексту завжди додається спеціальний символ-сентинел `$` (від лат. *sentire* — відчувати, вартувати), якого немає в алфавіті вихідного тексту. 

Сентинел має бути **лексикографічно меншим за будь-який інший символ алфавіту** (`$ < 'a'`, `$ < 'A'`). Це забезпечує дві критичні властивості:
1. **Жоден суфікс не є власним префіксом іншого суфікса.** Якщо два суфікси без сентинела мали вигляд `"ana"` та `"anana"`, то перший був префіксом другого. З сентинелом суфікси `"ana$"` та `"anana$"` мають різний четвертий символ (`'$' < 'n'`), тому `"ana$"` гарантовано і строго менший за `"anana$"`;
2. **Строгий лінійний порядок:** усі `N` суфіксів стають попарно різними, що виключає невизначеність при сортуванні.

### Обернений суфіксний масив (масив рангів)

Поряд із масивом `SA` часто використовується **обернений суфіксний масив** (Inverse Suffix Array, або `Rank`, від лат. *inversus* — перевернутий). Масив `Rank[0..N-1]` зберігає позицію (ранг) кожного суфікса `S[i]` у відсортованому масиві `SA`:

```
Rank[SA[k]] = k    та    SA[Rank[i]] = i
```

Для рядка `"banana$"`:
* Суфікс `S[0] = "banana$"` стоїть на позиції `4` у `SA` → `Rank[0] = 4`;
* Суфікс `S[1] = "anana$"` стоїть на позиції `3` у `SA` → `Rank[1] = 3`;
* Суфікс `S[5] = "a$"` стоїть на позиції `1` у `SA` → `Rank[5] = 1`.

Масив рангів будується за один прохід по `SA` за час `O(N)`:

```
Rank[SA[i]] = i    для всіх i від 0 до N-1
```

### Апаратна перевага: кеш-локальність проти гонитви за покажчиками

Головна причина витіснення суфіксних дерев суфіксними масивами полягає в організації сучасної комп'ютерної пам'яті. 

Суфіксне дерево являє собою розгалужений граф у купі. Кожен вузол містить кілька вказівників на дочірні вершини, батьківський вузол, суфіксні посилання та числові межі підрядків. У 64-бітній архітектурі це вимагає від 36 до 48 байтів пам'яті на один символ тексту. При обході такого дерева процесор змушений постійно переходити за випадковими адресами пам'яті (**Pointer Chasing**). Кожен такий перехід спричиняє промах кешу процесора (Cache Miss) і вимагає звернення до повільної DRAM із затримкою 50–100 наносекунд (200–300 тактів процесора).

Суфіксний масив вимагає лише **4 байти на символ** (при використанні 32-бітного типу `uint32_t` для текстів до 4 ГБ) або 8 байтів для надвеликих текстів. Усі індекси розміщені у пам'яті в єдиному неперервному буфері. Апаратні блоки попередньої вибірки процесора (**Hardware Prefetchers**) автоматично завантажують сусідні 64-байтні кеш-лінії з оперативної пам'яті у надшвидкий кеш першого рівня L1. Завдяки високій просторовій локальності даних сканування та бінарний пошук у суфіксному масиві працюють у 10–30 разів швидше за обхід суфіксного дерева на реальному обладнанні.

> 📜 Про те, як виникли перші суфіксні дерева Вайнера та Укконена, чому вони страждали від надмірного споживання оперативної пам'яті, і як Уді Манбер та Юджин Маєрс винайшли суфіксний масив, читайте у вставці [Історія виникнення суфіксних структур: від дерев Вайнера до лінійних масивів](root:sf-algorithms/suffix-array/hist-suffix-structures.md).

## 2. Пошук підрядків за допомогою двійкового пошуку

Оскільки суфікси в масиві `SA` відсортовані за алфавітом, будь-який шуканий зразок `P` довжини `M` шукається за допомогою [двійкового пошуку](root:sf-algorithms/binary-search).

Всі суфікси, що починаються з підрядка `P`, розташовані в суфіксному масиві строго поспіль і утворюють цілісний діапазон індексів `[L, R]`. Пошук цього діапазону складається з двох кроків:
1. **Пошук нижньої межі `L` (Lower Bound):** перший суфікс у `SA`, який лексикографічно не менший за `P` (`S[SA[k]] >= P`). Якщо префікс цього суфікса не збігається з `P`, то зразка взагалі немає в тексті;
2. **Пошук верхньої межі `R` (Upper Bound):** останній суфікс у `SA`, який починається з `P`.

```
Приклад: пошук зразка P = "an" у тексті "banana$"

Діапазон SA:
  k = 1: SA[1] = 5 ("a$")       -> "a" < "an"  (шукаємо праворуч)
  k = 2: SA[2] = 3 ("ana$")     -> починається з "an"  <- Нижня межа L = 2
  k = 3: SA[3] = 1 ("anana$")   -> починається з "an"  <- Верхня межа R = 3
  k = 4: SA[4] = 0 ("banana$")  -> "banana" > "an"    (поза межами)

Результат: знайдено R - L + 1 = 2 входження у тексті за індексами SA[2]=3 та SA[3]=1.
```

```c
/* Двійковий пошук діапазону входжень зразка P довжини M */
typedef struct {
    int left;
    int right;
    int count;
} SearchRange;

SearchRange suffix_array_search(const char *text, int n, const int *sa, const char *pattern, int m) {
    SearchRange res = {-1, -1, 0};
    if (n <= 0 || m <= 0) return res;

    /* 1. Пошук лівої межі */
    int low = 0, high = n - 1;
    int first = -1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        int cmp = strncmp(text + sa[mid], pattern, (size_t)m);
        if (cmp >= 0) {
            first = mid;
            high = mid - 1;
        } else {
            low = mid + 1;
        }
    }

    if (first == -1 || strncmp(text + sa[first], pattern, (size_t)m) != 0) {
        return res; /* Не знайдено */
    }

    /* 2. Пошук правої межі */
    low = first;
    high = n - 1;
    int last = first;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        int cmp = strncmp(text + sa[mid], pattern, (size_t)m);
        if (cmp == 0) {
            last = mid;
            low = mid + 1;
        } else if (cmp < 0) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }

    res.left = first;
    res.right = last;
    res.count = last - first + 1;
    return res;
}
```
```cpp
#include <string_view>
#include <span>
#include <algorithm>

struct SearchRange {
    int left{-1};
    int right{-1};
    int count{0};

    [[nodiscard]] bool found() const noexcept { return count > 0; }
};

SearchRange search_suffix_array(std::string_view text, 
                                std::span<const int> sa, 
                                std::string_view pattern) noexcept {
    SearchRange res;
    if (text.empty() || pattern.empty() || sa.empty()) return res;

    const int n = static_cast<int>(text.size());
    const int m = static_cast<int>(pattern.size());

    // 1. Пошук лівої межі
    int low = 0, high = n - 1;
    int first = -1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        std::string_view suf(text.data() + sa[mid], std::min(m, n - sa[mid]));
        if (suf >= pattern) {
            first = mid;
            high = mid - 1;
        } else {
            low = mid + 1;
        }
    }

    if (first == -1) return res;

    std::string_view found_suf(text.data() + sa[first], std::min(m, n - sa[first]));
    if (!found_suf.starts_with(pattern)) {
        return res;
    }

    // 2. Пошук правої межі
    low = first;
    high = n - 1;
    int last = first;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        std::string_view suf(text.data() + sa[mid], std::min(m, n - sa[mid]));
        if (suf.starts_with(pattern)) {
            last = mid;
            low = mid + 1;
        } else if (suf < pattern) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }

    res.left = first;
    res.right = last;
    res.count = last - first + 1;
    return res;
}
```

### Складність пошуку
* Кожен крок двійкового пошуку виконує до `M` посимвольних порівнянь;
* Кількість кроків двійкового пошуку дорівнює `O(log N)`;
* Сумарний час знаходження діапазону `[L, R]` становить `O(M · log N)`;
* Час виведення всіх `K` позицій входжень становить `O(K)` після знаходження меж.

### Оптимізація двійкового пошуку через LCP до O(M + log N)
У класичному двійковому пошуку на кожному кроці порівняння зразка `P` із суфіксом `S[SA[mid]]` починається з нульового символу. Якщо зразок довгий (`M = 10 000`), ми виконуємо тисячі однакових повторних порівнянь символів.

Манбер і Маєрс запропонували оптимізацію: якщо заздалегідь відомо, що ліва межа пошуку `L` збігається зі зразком `P` на перших `l` символах (`l = lcp(P, S[SA[L]])`), а права межа `R` — на `r` символах (`r = lcp(P, S[SA[R]])`), то при порівнянні з серединою `mid` ми можемо використати попередньо обчислене значення `lcp(S[SA[L]], S[SA[mid]])`:
1. Якщо `lcp(L, mid) > l`, це означає, що суфікс `mid` збігається з суфіксом `L` на більшій кількості символів, ніж зразок `P`. Отже, порівняння між `P` та `mid` одразу дає той самий результат, що й з `L`, без жодного посимвольного порівняння;
2. Якщо `lcp(L, mid) < l`, то `lcp(P, mid) = lcp(L, mid)`, і результат порівняння визначається без читання тексту;
3. Якщо `lcp(L, mid) == l`, ми починаємо посимвольне порівняння `P` та `mid` не з початку, а починаючи з індексу `l`.

Завдяки цьому кожен символ шаблону `P` порівнюється щонайбільше один раз на успішному кроці, що знижує часову складність двійкового пошуку до строгого `O(M + log N)`.

## 3. Алгоритми побудови суфіксного масиву

### Наївне сортування: O(N² log N)
Найпростіший спосіб побудови полягає у створенні масиву індексів `[0..N-1]` та їхньому сортуванні стандартною функцією `std::sort` або `qsort`, де компаратор порівнює суфікси за допомогою `strcmp`.

Оскільки порівняння двох суфіксів довжини `N` займає до `O(N)` операцій, а сортування `N` елементів вимагає `O(N log N)` порівнянь, загальна часова складність становить `O(N² log N)`. Для тексту довжиною 100 000 символів такий алгоритм виконує мільярди операцій і є непридатним для практики.

### Алгоритм подвоєння префіксів Манбера — Маєрса: O(N log N)
У 1990 році Уді Манбер та Юджин Маєрс запропонували алгоритм, що базується на ідеї Карпа — Міллера — Розенберга (KMR, 1972): **подвоєння довжини порівнюваних префіксів**.

Ідея полягає в ітеративному сортуванні суфіксів не за всією їхньою довжиною одразу, а за префіксами довжини `2ᵏ` (`k = 0, 1, 2, ...`):
1. **Крок 0 (`2⁰ = 1`):** суфікси сортуються за першим символом `T[i]`. Кожному суфіксу присвоюється початковий ранг `Rank[i]`;
2. **Крок k (`2ᵏ`):** припустимо, що всі суфікси вже впорядковані за першими `2ᵏ⁻¹` символами, і ми знаємо їхні ранги. Щоб впорядкувати суфікси за першими `2ᵏ` символами, достатньо порівняти для кожної позиції `i` пару чисел:
```
( Rank[i], Rank[i + 2ᵏ⁻¹] )
```
де перший елемент пари — це ранг першої половини підрядка (довжини `2ᵏ⁻¹`), а другий елемент — ранг другої половини підрядка (зміщеної на `2ᵏ⁻¹` символів управо). Якщо зміщення `i + 2ᵏ⁻¹ >= N`, другий ранг вважається рівним `-1`.

![Алгоритм подвоєння префіксів Манбера — Маєрса](/root/eng/sf-algorithms/suffix-array/img/prefix-doubling-steps.svg)
*Етапи подвоєння префіксів для рядка "banana$": перехід від одиничних символів до підрядків довжини 2 та 4 через комбінацію рангів.*

Оскільки кожна пара складається з двох цілих чисел у діапазоні `[0..N]`, сортування пар на кожному кроці виконується за допомогою двопрохідного порозрядного сортування (Counting Sort) за лінійний час `O(N)`.

Загальна кількість кроків подвоєння становить `⌈log₂ N⌉`. Отже, сумарна складність алгоритму становить:
```
T(N) = O(N) · ⌈log₂ N⌉ = O(N log N)
```

```c
/* Алгоритм побудови SA подвоєнням префіксів за O(N log N) */
void build_suffix_array(const char *text, int n, int *sa, int *rank) {
    int *cnt = (int*)calloc((size_t)(n + 256 + 2), sizeof(int));
    int *temp_sa = (int*)malloc((size_t)n * sizeof(int));
    int *new_rank = (int*)malloc((size_t)n * sizeof(int));

    /* 1. Ініціалізація рангами одиничних символів */
    for (int i = 0; i < n; ++i) {
        sa[i] = i;
        rank[i] = (unsigned char)text[i];
    }

    /* 2. Подвоєння k = 1, 2, 4, 8... */
    for (int k = 1; k < n; k <<= 1) {
        /* Двопрохідний Counting Sort за парою (rank[i], rank[i+k]) */
        for (int step = 1; step >= 0; --step) {
            int offset = (step == 1) ? k : 0;
            int max_val = 0;
            for (int i = 0; i < n; ++i) {
                int val = (i + offset < n) ? rank[i + offset] + 1 : 0;
                if (val > max_val) max_val = val;
            }
            memset(cnt, 0, (size_t)(max_val + 2) * sizeof(int));
            for (int i = 0; i < n; ++i) {
                int val = (i + offset < n) ? rank[i + offset] + 1 : 0;
                cnt[val]++;
            }
            for (int i = 1; i <= max_val + 1; ++i) cnt[i] += cnt[i - 1];
            for (int i = n - 1; i >= 0; --i) {
                int val = (sa[i] + offset < n) ? rank[sa[i] + offset] + 1 : 0;
                temp_sa[--cnt[val]] = sa[i];
            }
            memcpy(sa, temp_sa, (size_t)n * sizeof(int));
        }

        /* Перерахунок нових рангів */
        new_rank[sa[0]] = 0;
        int r = 0;
        for (int i = 1; i < n; ++i) {
            int prev = sa[i - 1];
            int curr = sa[i];
            int prev_r2 = (prev + k < n) ? rank[prev + k] : -1;
            int curr_r2 = (curr + k < n) ? rank[curr + k] : -1;
            if (rank[prev] != rank[curr] || prev_r2 != curr_r2) {
                r++;
            }
            new_rank[curr] = r;
        }
        memcpy(rank, new_rank, (size_t)n * sizeof(int));
        if (r == n - 1) break; /* Усі ранги унікальні — сортування завершено */
    }

    free(cnt);
    free(temp_sa);
    free(new_rank);
}
```
```cpp
#include <vector>
#include <string_view>
#include <numeric>
#include <algorithm>

std::vector<int> build_suffix_array(std::string_view text) {
    const int n = static_cast<int>(text.size());
    if (n == 0) return {};

    std::vector<int> sa(n);
    std::vector<int> rank(n);
    std::vector<int> temp_sa(n);
    std::vector<int> new_rank(n);
    std::vector<int> cnt;

    for (int i = 0; i < n; ++i) {
        sa[i] = i;
        rank[i] = static_cast<unsigned char>(text[i]);
    }

    for (int k = 1; k < n; k <<= 1) {
        auto counting_pass = [&](int offset) {
            int max_val = 0;
            for (int i = 0; i < n; ++i) {
                int val = (i + offset < n) ? rank[i + offset] + 1 : 0;
                if (val > max_val) max_val = val;
            }
            cnt.assign(max_val + 2, 0);

            for (int i = 0; i < n; ++i) {
                int val = (i + offset < n) ? rank[i + offset] + 1 : 0;
                cnt[val]++;
            }
            for (size_t i = 1; i < cnt.size(); ++i) {
                cnt[i] += cnt[i - 1];
            }
            for (int i = n - 1; i >= 0; --i) {
                int val = (sa[i] + offset < n) ? rank[sa[i] + offset] + 1 : 0;
                temp_sa[--cnt[val]] = sa[i];
            }
            sa = temp_sa;
        };

        counting_pass(k);
        counting_pass(0);

        new_rank[sa[0]] = 0;
        int r = 0;
        for (int i = 1; i < n; ++i) {
            int prev = sa[i - 1];
            int curr = sa[i];
            int prev_r2 = (prev + k < n) ? rank[prev + k] : -1;
            int curr_r2 = (curr + k < n) ? rank[curr + k] : -1;
            if (rank[prev] != rank[curr] || prev_r2 != curr_r2) {
                ++r;
            }
            new_rank[curr] = r;
        }
        rank = new_rank;
        if (r == n - 1) break;
    }

    return sa;
}
```

## 4. Лінійні алгоритми прямої побудови O(N)

Хоча алгоритм подвоєння префіксів за `O(N log N)` є простим та надійним, для індексації мільярдних геномних корпусів або терабайтних архівів потрібна строго лінійна швидкість.

### 1. Алгоритм DC3 / Skew (Difference Cover modulo 3)
Розроблений Юхою Кярккяйненом та Петером Сандерсом у 2003 році, алгоритм DC3 ділить усі позиції рядка на три підмножини залежно від залишку індексу від ділення на 3:
* `B₀ = { i : i mod 3 == 0 }`
* `B₁ = { i : i mod 3 == 1 }`
* `B₂ = { i : i mod 3 == 2 }`

Алгоритм виконує чотири кроки:
1. **Редукція вибірки `B₁ ∪ B₂`:** розглядаються суфікси з позицій `i mod 3 != 0` (рівно `2/3 · N` усіх суфіксів). Кожен такий суфікс кодується трійкою символів `(T[i], T[i+1], T[i+2])`. Трійки символів замінюються їхніми лексикографічними рангами, утворюючи новий рядок удвічі меншої довжини над розширеним цілочисловим алфавітом;
2. **Рекурсивний виклик:** рекурсивно будується суфіксний масив для рядка довжини `2/3 · N`. Це дає точний відносний порядок для всіх суфіксів з `B₁ ∪ B₂`;
3. **Лінійне сортування `B₀`:** кожен суфікс `i ∈ B₀` можна записати як перший символ `T[i]`, після якого йде суфікс `i + 1 ∈ B₁`. Оскільки порядок суфіксів з `B₁` вже відомий після кроку 2, множина `B₀` сортується за один прохід `Counting Sort` за парою `(T[i], Rank[i+1])` за лінійний час `O(N)`;
4. **Лінійне злиття (Merge):** впорядкований масив `B₁ ∪ B₂` та впорядкований масив `B₀` зливаються в єдиний масив за один прохід двома покажчиками. Для порівняння суфікса `i ∈ B₀` та `j ∈ B₁` достатньо порівняти пари `(T[i], Rank[i+1])` та `(T[j], Rank[j+1])` (оскільки `i+1 ∈ B₁` та `j+1 ∈ B₂`, їхні ранги вже відомі). Для порівняння `i ∈ B₀` та `j ∈ B₂` порівнюються трійки `(T[i], T[i+1], Rank[i+2])` та `(T[j], T[j+1], Rank[j+2])`.

Рекурентне рівняння часу роботи алгоритму DC3 має вигляд:
```
T(N) = T(2N / 3) + O(N)
```
За основною теоремою про рекурентності (Master Theorem) сума спадної геометричної прогресії дає строгий лінійний час:
```
T(N) = O(N) · (1 + 2/3 + 4/9 + ...) = O(N) · 3 = O(N)
```

### 2. Алгоритм SA-IS (Suffix Array by Induced Sorting)
Опублікований у 2009 році Ґе Нонґом, Сеном Чжаном та Вай Гонґ Чаном, алгоритм SA-IS є найшвидшим та найбільш економним за пам'яттю алгоритмом побудови суфіксного масиву.

Він базується на класифікації суфіксів на два типи:
* **S-тип (Small):** суфікс `S[i]` лексикографічно менший за `S[i+1]`;
* **L-тип (Large):** суфікс `S[i]` лексикографічно більший за `S[i+1]`.

Класифікація виконується за один прохід справа наліво:
* Останній символ `T[N-1] = '$'` завжди має **S-тип**;
* Для кожного `i` від `N-2` до `0`:
  - Якщо `T[i] < T[i+1]`, то `i` має **S-тип**;
  - Якщо `T[i] > T[i+1]`, то `i` має **L-тип**;
  - Якщо `T[i] == T[i+1]`, тип `i` збігається з типом `i+1`.

Позиція `i` називається **LMS-символом** (Leftmost S-type), якщо `i` має S-тип, а її попередник `i-1` має L-тип.

Алгоритм індукованого сортування виконує наступні фази:
1. Виділяє для кожного унікального символу алфавіту свій кошик (Bucket) у масиві `SA`. L-суфікси завжди розміщуються на початку кошика, а S-суфікси — у кінці кошика;
2. Рекурсивно знаходить правильний порядок для компактної множини LMS-суфіксів;
3. **Індукування L-суфіксів (прохід зліва направо):** сканує `SA` з початку до кінця. Якщо суфікс `SA[k] - 1` має L-тип, він автоматично вставляється на перше вільне місце на початку кошика символу `T[SA[k] - 1]`;
4. **Індукування S-суфіксів (прохід справа наліво):** сканує `SA` з кінця до початку. Якщо суфікс `SA[k] - 1` має S-тип, він вставляється на останнє вільне місце в кінці кошика символу `T[SA[k] - 1]`.

Завдяки тому, що кількість LMS-суфіксів не перевищує `N / 2`, рекурсія виконується для задачі розміром максимум `N / 2`, що гарантує час `T(N) = T(N/2) + O(N) = O(N)` та рекордно низькі накладні витрати пам'яті (усього кілька байтів на символ).

Повний вихідний код промислового рушія наведено у вставці [Практична реалізація суфіксного масиву: побудова, LCP та двійковий пошук](root:sf-algorithms/suffix-array/proj-sais-construction.md).

## 5. Масив найдовших спільних префіксів (LCP Array)

Суфіксний масив фіксує лише порядок суфіксів, але нічого не говорить про те, наскільки сильно сусідні суфікси збігаються між собою. Для структурного аналізу тексту разом із `SA` обов'язково будується **масив найдовших спільних префіксів** (Longest Common Prefix, `LCP`).

**Масив `LCP[0..N-1]`** визначається так:
* `LCP[0] = 0` (перед нульовим елементом немає суфікса);
* `LCP[k]` — довжина найдовшого спільного префікса між суфіксами `S[SA[k]]` та `S[SA[k-1]]` для всіх `1 <= k < N`:
```
LCP[k] = lcp( T[SA[k]..N-1], T[SA[k-1]..N-1] )
```

Для рядка `"banana$"`:
```
k | SA[k] | LCP[k] | Відсортований суфікс | Спільний префікс із попереднім
--+-------+--------+---------------------+------------------------------
0 |   6   |   0    | "$"                 | -
1 |   5   |   0    | "a$"                | lcp($, a$) = 0
2 |   3   |   1    | "ana$"              | lcp(a$, ana$) = 1 ("a")
3 |   1   |   3    | "anana$"            | lcp(ana$, anana$) = 3 ("ana")
4 |   0   |   0    | "banana$"           | lcp(anana$, banana$) = 0
5 |   4   |   0    | "na$"               | lcp(banana$, na$) = 0
6 |   2   |   2    | "nana$"             | lcp(na$, nana$) = 2 ("na")
```

![Масив LCP та запити мінімуму на відрізку](/root/eng/sf-algorithms/suffix-array/img/lcp-array-rmq.svg)
*Масив найдовших спільних префіксів (LCP) для "banana$" та знаходження спільного префікса суфіксів "ana$" і "anana$" через мінімум на відрізку.*

### Властивість RMQ (Range Minimum Query) для LCP
Фундаментальна теорема стверджує: найдовший спільний префікс будь-яких двох довільних суфіксів `S[SA[i]]` та `S[SA[j]]` (де `i < j`) дорівнює **мінімальному значенню** в масиві `LCP` на відрізку між ними:

```
lcp( S[SA[i]], S[SA[j]] ) = min( LCP[k] )    для i + 1 <= k <= j
```

Якщо над масивом `LCP` побудувати [Таблицю заміни (Sparse Table)](root:sf-algorithms/sparse-table) за час `O(N log N)`, будь-який запит спільного префікса між двома довільними підрядками тексту виконується за **константний час `O(1)`**.

### Алгоритм Касаї: побудова LCP за O(N)
Наївний розрахунок `LCP` вимагає посимвольного порівняння рядків і може зайняти `O(N²)` часу. Тору Касаї (Toru Kasai, 2001) запропонував лінійний алгоритм, заснований на ключовому інваріанті:

Якщо суфікс `S[i]` має спільний префікс довжини `h` зі своїм лівим сусідом у `SA`, то наступний суфікс `S[i+1]` (отриманий відкиданням першого символу) має спільний префікс довжини **щонайменше `h - 1`** зі своїм лівим сусідом у `SA`:

```
h(i+1) >= h(i) - 1
```

Завдяки цьому алгоритм перебирає суфікси у природному порядку вихідного тексту (`i = 0, 1, ..., N-1`). На кожному кроці лічильник спільних символів `h` зменшується щонайбільше на одиницю, а потім збільшується прямим посимвольним порівнянням:

:::tabs
```c
/* Побудова масиву LCP за алгоритмом Касаї за O(N) */
void build_lcp_kasai(const char *text, int n, const int *sa, const int *rank, int *lcp) {
    int h = 0;
    for (int i = 0; i < n; ++i) {
        if (rank[i] > 0) {
            int j = sa[rank[i] - 1];
            while (i + h < n && j + h < n && text[i + h] == text[j + h]) {
                h++;
            }
            lcp[rank[i]] = h;
            if (h > 0) h--;
        } else {
            lcp[0] = 0;
        }
    }
}
```
```cpp
#include <vector>
#include <string_view>
#include <span>

std::vector<int> build_lcp_kasai(std::string_view text, 
                                 std::span<const int> sa, 
                                 std::span<const int> rank) {
    const int n = static_cast<int>(text.size());
    std::vector<int> lcp(n, 0);

    int h = 0;
    for (int i = 0; i < n; ++i) {
        if (rank[i] > 0) {
            int j = sa[rank[i] - 1];
            while (i + h < n && j + h < n && text[i + h] == text[j + h]) {
                ++h;
            }
            lcp[rank[i]] = h;
            if (h > 0) --h;
        } else {
            lcp[0] = 0;
        }
    }

    return lcp;
}
```

Оскільки `h` зменшується щонайбільше `N` разів на одиницю, воно може збільшитися не більше ніж `2N` разів за весь час роботи. Алгоритм виконує не більше `3N` посимвольних порівнянь і гарантує часову складність `O(N)`.

## 6. Класичні задачі на суфіксному масиві

Суфіксний масив разом із масивом `LCP` дозволяє розв'язувати широкий спектр фундаментальних задач обробки рядків з оптимальною асимптотичною складністю.

### 1. Кількість унікальних підрядків
Текст довжини `N` має загалом `N · (N + 1) / 2` підрядків (включаючи дублікати). Суфікс `S[SA[i]]` має довжину `N - SA[i]`, отже він містить `N - SA[i]` різних префіксів.

Оскільки впорядковані суфікси порівнюються з попередніми, перші `LCP[i]` префіксів суфікса `S[SA[i]]` вже були враховані у попередніх суфіксах. Кількість **нових унікальних підрядків**, які вносить суфікс `S[SA[i]]`, дорівнює:
```
Unique(i) = (N - SA[i]) - LCP[i]
```

Загальна кількість унікальних підрядків обчислюється сумуванням за один прохід за `O(N)`:
```
Total_Distinct
= ∑ [ (N - SA[i]) - LCP[i] ]    [для всіх i від 0 до N-1]
= N·(N + 1)/2 - ∑ LCP[i]        [розкриття суми довжин суфіксів]
```

Для рядка `"banana$"` (`N = 7`):
* Всього підрядків: `7 · 8 / 2 = 28`;
* Сума LCP: `0 + 0 + 1 + 3 + 0 + 0 + 2 = 6`;
* Унікальних підрядків: `28 - 6 = 22`.

### 2. Найдовший повторюваний підрядок (Longest Repeated Substring)
Підрядок зустрічається в тексті щонайменше двічі тоді й лише тоді, коли він є спільним префіксом принаймні двох різних суфіксів. Оскільки суфікси відсортовані, максимальна довжина спільного префікса обов'язково досягається на деякій сусідній парі в масиві `SA`.

Задача зводиться до пошуку максимального елемента в масиві `LCP`:
```
Max_Len = max( LCP[i] )    для 1 <= i < N
```
Якщо максимальне значення досягається при індексі `k`, то шуканий підрядок — це префікс довжини `LCP[k]` суфікса `S[SA[k]]`. Час пошуку становить строго `O(N)`.

Для рядка `"banana$"`: `max(LCP) = 3` при `k = 3` (`SA[3] = 1`). Найдовший повторюваний підрядок — `"ana"`.

### 3. Найдовший спільний підрядок кількох текстів (LCS / Generalized Suffix Array)
Для знаходження найдовшого спільного підрядка двох або більше текстів `T₁`, `T₂`, ..., `T_K`:
1. Усі тексти об'єднуються в один суцільний рядок через унікальні термінальні роздільники: `T = T₁ + "$₁" + T₂ + "$₂" + ... + T_K + "$_K"`;
2. Будуються масиви `SA` та `LCP` для об'єднаного рядка `T` за час `O(|T|)`;
3. Задача зводиться до методу **ковзного вікна з двома покажчиками** (Sliding Window): ми шукаємо найвужче вікно `[L, R]` у суфіксному масиві, яке містить суфікси від усіх `K` вихідних документів. Довжина спільного підрядка для вікна `[L, R]` обчислюється через мінімум на відрізку `min(LCP[L+1..R])`.

Часова складність алгоритму становить `O(∑ |T_i|)` — лінійний час від сумарного розміру всіх вхідних документів.

### 4. Пошук тандемних повторів
Тандемним повтором (квадратом) називається підрядок вигляду `W = U U`, де фрагмент `U` довжини `L` повторюється двічі поспіль. Використовуючи суфіксний масив та швидкі запити LCP через Sparse Table, усі тандемні повтори у тексті довжини `N` знаходяться алгоритмом Мейнса — Лоренца за час `O(N log N)`.

### 5. Узагальнений суфіксний масив для повнотекстових баз даних (GSA)
У реальних інформаційно-пошукових системах (наприклад, утилітах пошуку по коду `Zoekt` або індексаторах поштових архівів) потрібно шукати входження не в одному гігантському файлі, а серед сотень тисяч окремих файлів.

Узагальнений суфіксний масив (**Generalized Suffix Array**, GSA) об'єднує всі документи колекції в єдиний конкатенований буфер. Поряд із масивом `SA` будується паралельний масив ідентифікаторів документів `DocID[k]`, який для кожного суфікса `SA[k]` вказує номер вихідного документа.

Коли користувач виконує двійковий пошук за зразком `P`, алгоритм знаходить діапазон `[L, R]` у `SA`. Потім за один прохід по підмасиву `DocID[L..R]` система вибирає список унікальних ідентифікаторів документів, де зустрічається шуканий підрядок, без необхідності сканувати окремо кожен файл.

## 7. Зв'язок із BWT, FM-індексом та стисненими структурами

Суфіксний масив є ключовим будівельним блоком для **перетворення Барроуза — Вілера** (Burrows-Wheeler Transform, BWT).

Якщо взяти всі `N` циклічних зсувів рядка `T`, відсортувати їх лексикографічно в концептуальній матриці та виписати останній стовпець цієї матриці, ми отримаємо рядок `BWT(T)`. Оскільки кожен рядок матриці починається з суфікса `SA[i]`, символ в останньому стовпці — це символ, що безпосередньо передує суфіксу `SA[i]` у вихідному тексті:

```
BWT[i] = T[ (SA[i] - 1 + N) mod N ]    для всіх i від 0 до N-1
```

```
Текст T = "banana$"

k | SA[k] | Суфікс     | Попередній символ T[SA[k]-1] (BWT)
--+-------+------------+-----------------------------------
0 |   6   | "$"        | T[5] = 'a'
1 |   5   | "a$"       | T[4] = 'n'
2 |   3   | "ana$"     | T[2] = 'n'
3 |   1   | "anana$"   | T[0] = 'b'
4 |   0   | "banana$"  | T[6] = '$'
5 |   4   | "na$"      | T[3] = 'a'
6 |   2   | "nana$"    | T[1] = 'a'

Результат: BWT("banana$") = "annb$aa"
```

Перетворення BWT групує однакові символи поруч, що забезпечує високий коефіцієнт стиснення архіваторами (наприклад, `bzip2`). 

У 2000 році Паоло Феррагіна та Джованні Манзіні створили **FM-індекс**, який поєднує BWT із таблицею рангів символів (`Rank / Checkpoint Arrays`). FM-індекс дозволяє виконувати пошук підрядків за час `O(M)` безпосередньо у стисненому тексті за допомогою механізму зворотного пошуку (**Backward Search**), займаючи менше 1 байта на символ вихідного тексту.

### Зріджений суфіксний масив (Sampled Suffix Array)
У біоінформатиці зберігання навіть 4 байтів на символ для геному розміром 3.2 ГБ вимагає 12.8 ГБ RAM. Для стиснення індексу застосовують **зріджений суфіксний масив** (Sampled SA):
* Зберігаються лише ті значення `SA[k]`, які кратні деякому кроку вибірки `K` (наприклад, `K = 8` або `K = 16`);
* Решта позицій відновлюється за `O(K)` кроків переходу за таблицею LF-mapping у BWT.

Це скорочує обсяг пам'яті до 0.5–1.5 байта на символ, дозволяючи завантажувати повний індекс геному людини у звичайну оперативну пам'ять ноутбука або сервера (менше 4 ГБ).

## 8. Архітектурні компроміси та порівняння рішень

![Порівняння суфіксного дерева та суфіксного масиву](/root/eng/sf-algorithms/suffix-array/img/suffix-tree-vs-array.svg)
*Структурне зіставлення суфіксного дерева з розгалуженими покажчиками та компактного суфіксного масиву з неперервною адресацією в пам'яті.*

| Характеристика | Суфіксне дерево (Suffix Tree) | Суфіксний масив (Suffix Array + LCP) | FM-індекс (BWT Index) | Інвертований індекс (Inverted Index) |
|---|---|---|---|---|
| **Пам'ять на символ** | 20–45 байтів | 4–8 байтів | 0.5–1.5 байта | 1–3 байти (лише слова) |
| **Час побудови** | `O(N)` (Укконен) | `O(N)` (SA-IS) або `O(N log N)` | `O(N)` | `O(N)` |
| **Час пошуку зразка M**| `O(M)` | `O(M · log N)` або `O(M + log N)` | `O(M)` | `O(1)` або `O(log \|V\|)` |
| **Кеш-локальність** | Вкрай низька (промахи кешу) | Ідеальна (неперервний масив) | Середня (розріджені бітмапи) | Висока (постингові масиви) |
| **Пошук довільного зрізу**| Повний довільний підрядок | Повний довільний підрядок | Повний довільний підрядок | Лише цілі слова / леми |
| **Складність реалізації** | Вкрай висока | Низька / Середня | Висока | Середня |

> 🔧 **Навіщо це.**
> 1. **Біоінформатика та генетика (Next-Gen Sequencing):** карти зчитування мільйонів коротких фрагментів ДНК (Reads) довжиною 100–300 пар основ зіставляються з еталонним геномом людини у програмах Bowtie2, BWA-MEM та Minimap2 за допомогою суфіксних масивів та FM-індексів;
> 2. **Швидкий пошук у вихідному коді (Code Search Engines):** сервіси Google Zoekt, Sourcegraph та Livegrep використовують суфіксні масиви для пошуку точних регулярних виразів і фрагментів коду за мілісекунди без розбивки на слова природної мови;
> 3. **Стиснення даних та дедуплікація:** утиліти пошуку спільних блоків даних (Rsync, Zstandard, архіватори BWT) знаходять довгі повторювані послідовності за лінійний час за допомогою масивів LCP.
