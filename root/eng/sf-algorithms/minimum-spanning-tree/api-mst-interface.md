# 📋 Програмний інтерфейс розрахунку мінімального кістякового дерева

Програмний інтерфейс (Application Programming Interface, API) системної бібліотеки розрахунку мінімальних кістякових дерев визначає контракт обчислення оптимальної зв'язності для високонавантажених модулів, геоінформаційних систем (GIS), САПР проектування топологій інтегральних мікросхем (VLSI) та мережевих планувальників. Архітектура бібліотеки надає прямий доступ до алгоритмів Прима–Ярніка та Борувки, гарантує суворий контроль виділення пам'яті, детерміновану обробку кодів помилок без аварійних завершень та повну ізоляцію стану обчислень від середовища виконання.

---

### 1. Архітектурні принципи та життєвий цикл об'єктів

Програмний інтерфейс організовано навколо концепції неперервного життєвого циклу графових даних. Граф створюється з фіксованою або динамічно зростаючою кількістю вершин, наповнюється зваженими ребрами через послідовні або пакетні виклики, після чого передається обчислювальному рушію.

Життєвий цикл розрахунку МКД складається з чотирьох строго визначених фаз:
1. **Ініціалізація структури графа:** виділення пам'яті під дескриптор, попередній розрахунок ємності списків суміжності або буфера ребер залежно від обраного формату представлення.
2. **Формування топології:** додавання неорієнтованих зважених ребер. Бібліотека підтримує ваги довільного знаку (додатні, нульові та від'ємні), автоматично фільтрує паралельні ребра (зберігаючи ребро з мінімальною вагою) та відкидає петлі `(u, u)`.
3. **Обчислення кістяка:** виклик функції `mst_solve()` з вибором алгоритмічної стратегії або режимом автоконфігурації (`MST_ALGO_AUTO`). Автоконфігуратор оцінює щільність графа `m / n`: для щільних графів (`m > n · log n`) обирається алгоритм Прима на матриці або купі, а для розріджених — паралельний алгоритм Борувки або Краскала.
4. **Утилізація ресурсів:** структури розв'язку та самого графа мають чітко розмежовану власність над пам'яттю. Звільнення графа не інвалідує вже обчислений об'єкт `MstSolution`, оскільки ребра кістяка копіюються в незалежний суцільний буфер.

### 2. Типи даних та коди станів

Усі типи визначено з явною розрядністю (`int32_t`, `int64_t`), що гарантує двійкову сумісність між різними платформами та архітектурами.

:::tabs
```c
#ifndef MST_TYPES_H
#define MST_TYPES_H

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

#ifdef __cplusplus
extern "C" {
#endif

/* Коди помилок та статусів виконання операцій */
typedef enum {
    MST_STATUS_SUCCESS            = 0,  /* Успішний розрахунок повного кістякового дерева */
    MST_STATUS_DISCONNECTED_GRAPH = 1,  /* Граф незв'язний: побудовано мінімальний кістяковий ліс */
    MST_STATUS_INVALID_ARGUMENT   = 2,  /* Передано нульовий покажчик або некоректні розміри */
    MST_STATUS_VERTEX_OUT_OF_BOUNDS = 3,/* Індекс вершини виходить за межі діапазону [0, V-1] */
    MST_STATUS_OUT_OF_MEMORY      = 4   /* Помилка виділення динамічної пам'яті */
} MstStatusCode;

/* Алгоритмічний бекенд для виконання розрахунку */
typedef enum {
    MST_ALGO_AUTO    = 0, /* Автоматичний вибір стратегії за щільністю графа */
    MST_ALGO_PRIM    = 1, /* Алгоритм Прима–Ярніка на базі індексованої двійкової купи */
    MST_ALGO_BORUVKA = 2  /* Алгоритм Борувки на базі лісу неперетинних множин */
} MstAlgorithmType;

/* Дескриптор зваженого ребра */
typedef struct {
    int32_t u;        /* Перша вершина ребра */
    int32_t v;        /* Друга вершина ребра */
    int64_t weight;   /* Вага ребра (допустимі будь-які дійсні цілі значення) */
} MstEdgeDesc;

/* Структура збереження результатів розрахунку */
typedef struct {
    MstEdgeDesc *edges;       /* Суцільний масив ребер, що увійшли до кістяка */
    size_t edge_count;        /* Загальна кількість ребер у знайденому розв'язку */
    int64_t total_weight;     /* Точна сумарна вага кістякового дерева або лісу */
    size_t num_components;    /* Кількість компонент зв'язності (1 для дерева, >1 для лісу) */
    MstStatusCode status;     /* Фінальний статус виконання розрахунку */
} MstSolution;

#ifdef __cplusplus
}
#endif

#endif /* MST_TYPES_H */
```
```cpp
#pragma once

#include <cstdint>
#include <cstddef>
#include <vector>
#include <span>
#include <expected>

namespace mst {

enum class StatusCode : int32_t {
    Success = 0,
    DisconnectedGraph = 1,
    InvalidArgument = 2,
    VertexOutOfBounds = 3,
    OutOfMemory = 4
};

enum class AlgorithmType : int32_t {
    Auto = 0,
    Prim = 1,
    Boruvka = 2
};

struct EdgeDesc {
    int32_t u{0};
    int32_t v{0};
    int64_t weight{0};
};

struct Solution {
    std::vector<EdgeDesc> edges;
    int64_t total_weight{0};
    size_t num_components{0};
    StatusCode status{StatusCode::Success};

    [[nodiscard]] bool is_connected_tree() const noexcept {
        return num_components <= 1 && status == StatusCode::Success;
    }
};

} // namespace mst
```

### 3. Функції побудови графа та додавання ребер

Бібліотека надає процедури для поступового формування топології. Індексація вершин завжди є нуль-орієнтованою: для графа з `N` вузлами допустимими індексами є `0, 1, ..., N - 1`.

При виклику `mst_graph_add_edge()` бібліотека автоматично перевіряє межі переданих індексів `u` та `v`. Якщо будь-який із них є від'ємним або перевищує `num_vertices - 1`, операція негайно припиняється без пошкодження внутрішніх структур графа і повертає код помилки `MST_STATUS_VERTEX_OUT_OF_BOUNDS`. Для оптимізації масового наповнення графа надається функція `mst_graph_add_edges_batch()`, яка виділяє пам'ять єдиним блоком, мінімізуючи фрагментацію купи та скорочуючи час ініціалізації на великих наборах даних.

:::tabs
```c
/* Непрозорий дескриптор графа */
typedef struct MstGraph MstGraph;

/* Створення графа з фіксованою кількістю вершин */
MstGraph* mst_graph_create(size_t num_vertices);

/* Додавання неорієнтованого ребра до графа */
MstStatusCode mst_graph_add_edge(MstGraph *graph, int32_t u, int32_t v, int64_t weight);

/* Пакетне додавання масиву ребер */
MstStatusCode mst_graph_add_edges_batch(MstGraph *graph, const MstEdgeDesc *edges, size_t count);

/* Отримання кількості вершин */
size_t mst_graph_get_vertex_count(const MstGraph *graph);

/* Звільнення всієї виділеної пам'яті графа */
void mst_graph_destroy(MstGraph *graph);
```

### 4. Функції розрахунку та верифікації

Функція `mst_solve()` приймає граф та алгоритмічний прапорець, повертаючи результат у попередньо виділену або автоматично керовану структуру `MstSolution`. 

Внутрішня логіка функції `mst_solve()` гарантує детерміновану поведінку:
- Якщо граф містить рівно одну компоненту зв'язності, поле `edge_count` вихідної структури буде строго дорівнювати `num_vertices - 1`, а статус виконання буде встановлено в `MST_STATUS_SUCCESS`.
- Якщо граф є розірваним (складається з двох або більше ізольованих підграфів), функція формує мінімальний кістяковий ліс (MSF) із загальною кількістю ребер `num_vertices - num_components` і встановлює статус `MST_STATUS_DISCONNECTED_GRAPH`.
- Поле `total_weight` містить точну суму ваг усіх обраних ребер. У разі наявності від'ємних ваг переповнення виключається завдяки використанню 64-бітного знакового типу `int64_t`.

Для верифікації правильності розрахунку надається функція `mst_verify_solution()`, яка незалежно перевіряє ациклічність, зв'язність та відповідність кількості ребер за допомогою алгоритму пошуку в глибину (DFS).

:::tabs
```c
/* Головна функція розрахунку МКД */
MstStatusCode mst_solve(
    const MstGraph *graph,
    MstAlgorithmType algo,
    MstSolution *out_solution
);

/* Звільнення динамічного буфера ребер у структурі розв'язку */
void mst_solution_free(MstSolution *solution);

/* Незалежна верифікація ациклічності та зв'язності результату */
bool mst_verify_solution(size_t num_vertices, const MstSolution *solution);
```

### 5. Організація пам'яті та кеш-локальність (CSR проти списків суміжності)

Продуктивність обчислення МКД критично залежить від того, як саме ребра розташовані в оперативній пам'яті:

1. **Формат Compressed Sparse Row (CSR):**
   Усі ребра графа зберігаються у двох неперервних масивах: масиві зміщень `row_ptr[V + 1]` та масиві цільових вершин і ваг `col_idx[2E]`. Таке розміщення виключає фрагментацію пам'яті та забезпечує максимальну пропускну здатність шини пам'яті (Memory Bandwidth) при паралельному скануванні в алгоритмі Борувки.
2. **Зв'язні списки суміжності (Adjacency Lists):**
   Кожна вершина зберігає покажчик на зв'язний список сусідніх ребер `EdgeNode`. Це полегшує динамічне додавання нових зв'язків за `O(1)`, проте спричиняє промахи повз кеш процесора (Cache Misses) через випадкове розкидання вузлів списку по адресній купі під час ітерацій алгоритму Прима.
3. **Масив ребер (Edge Array / Coordinate Format):**
   Суцільний одновимірний масив структур `MstEdgeDesc`. Є найбільш компактним поданням (`16` байтів на ребро), ідеально підходить для алгоритму Краскала та багатофрагментного фільтрування Борувки.

Формула розрахунку пам'яті для графа на `V` вершин та `E` ребер:

```text
Пам'ять (CSR) = V · 4 байти + 2E · (4 + 8) байтів = 4V + 24E байтів
Пам'ять (Списки) = V · 8 байтів + 2E · (4 + 8 + 8) байтів = 8V + 40E байтів
Пам'ять (Масив ребер) = E · 16 байтів
```

### 6. Поведінка у граничних умовах та гарантії потокобезпечності

1. **Багатопоточність (Thread Safety):** Дескриптор `MstGraph` є незмінним (immutable) після завершення додавання ребер. Функція `mst_solve()` є реентрабельною і може одночасно виконуватися в десятках паралельних потоків над одним і тим самим графом без встановлення блокувань чи використання м'ютексів. Модифікація топології під час активного розрахунку заборонена і вимагає зовнішньої синхронізації.
2. **Вироджені графи:**
   - Порожній граф (`num_vertices = 0`): повертає `MST_STATUS_SUCCESS`, встановлюючи `edge_count = 0`, `total_weight = 0`, `num_components = 0`.
   - Граф з однієї ізольованої вершини (`num_vertices = 1`): повертає `edge_count = 0`, `total_weight = 0`, `num_components = 1`.
   - Граф без ребер (`num_vertices = N`, `E = 0`): повертає `MST_STATUS_DISCONNECTED_GRAPH`, формуючи `N` тривіальних компонент без жодного ребра.
3. **Контроль виділення ресурсів:** Бібліотека ніколи не виконує неконтрольованих виділень пам'яті всередині циклів обчислення. Усі допоміжні робочі буфери (двійкова купа, масиви DSU, таблиці мінімальних ребер) алокуються єдиним блоком на початку виконання `mst_solve()` і гарантовано звільняються перед поверненням керування, виключаючи будь-які витоки пам'яті (Memory Leaks).
