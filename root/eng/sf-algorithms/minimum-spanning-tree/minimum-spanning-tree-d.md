Коли регіональна енергетична компанія проєктує високовольтну мережу між десятьма розподільними підстанціями, де вартість прокладання кабелю між кожною парою пунктів варіюється від 12 000 доларів за кілометр на рівнині до 45 000 доларів у заболоченій місцевості, інженери стикаються з вибором конфігурації трас. З'єднання кожної підстанції з усіма іншими вимагає `V · (V - 1) / 2 = 45` кабельних ліній, що призводить до мільйонних перевитрат і створює численні замкнені контури, які ускладнюють узгодження автоматичних реле захисту. Натомість, щоб забезпечити подачу електроенергії на кожну станцію від генератора, достатньо прокласти такий мінімальний набір ліній, який зв'язує всі вузли в єдину мережу без жодного замкненого кільця. Оскільки будь-який зв'язний підграф без циклів є деревом, задача зводиться до знаходження дерева, що охоплює всі вершини й має найменшу можливу суму ваг ребер.

Такий підграф називають **мінімальним кістяковим деревом** (англ. *Minimum Spanning Tree*, MST; від латинського *minimus* — найменший, праслов'янського *kostь* — каркас, основа, та грецького *δένδρον* — дерево). На відміну від дерев найкоротших шляхів, які мінімізують відстань від одного фіксованого джерела до кожної окремої вершини, мінімальне кістякове дерево розв'язує глобальну оптимізаційну задачу: воно мінімізує сумарну вартість усієї зв'язної інфраструктури воєдино.

Детальний історичний контекст виникнення цієї задачі під час масштабної електрифікації Моравії у дослідженнях Отакара Борувки та її подальші незалежні перевідкриття розкрито у статті [Історія виникнення концепції мінімального кістякового дерева](root:sf-algorithms/minimum-spanning-tree/hist-mst-origins.md).

### Анатомія кістяка: чим кістякове дерево відрізняється від дерева найкоротших шляхів

Нехай задано зв'язний неорієнтований зважений граф `G = (V, E, w)`, де:
- `V` — скінченна множина вершин (вузлів), `|V| = n`;
- `E` — множина неорієнтованих зв'язків (ребер), `|E| = m`;
- `w: E → ℝ` — вагова функція, що приписує кожному ребру `e = (u, v)` числову вартість `w(e)`.

Підграф `T = (V, E_T)` називається **кістяковим деревом** (або кістяком) графа `G`, якщо він задовольняє три фундаментальні топологічні властивості:
1. **Повне покриття вершин:** множина вершин підграфа `T` точно збігається з множиною вершин вихідного графа `V`. Жодна вершина не може бути виключена чи залишена ізольованою.
2. **Глобальна зв'язність:** між будь-якою парою вершин у `T` існує принаймні один шлях.
3. **Ациклічність:** у підграфі `T` немає жодного замкненого контуру.

З базової теореми Келі про дерева випливає фундаментальний структурний інваріант: будь-яке дерево на `V` вершинах містить **рівно `V - 1` ребер**. Якщо видалити хоча б одне ребро з кістяка, граф втрачає зв'язність і розпадається на дві ізольовані компоненти; якщо ж додати до нього будь-яке стороннє ребро з `E \ E_T`, утворюється рівно один замкнений цикл.

**Вагою кістякового дерева** `w(T)` називають суму ваг усіх `V - 1` ребер, що увійшли до його складу:

```text
w(T) = ∑_{e ∈ E_T} w(e)
```

Поширеною помилкою є ототожнення мінімального кістякового дерева (МКД) із деревом найкоротших шляхів (англ. *Shortest-Path Tree*, SPT), яке будує [алгоритм Дейкстри](root:sf-algorithms/dijkstra). Хоча обидві структури охоплюють усі вершини графа без циклів, вони мінімізують принципово різні критерії:

| Параметр порівняння | Мінімальне кістякове дерево (МКД / MST) | Дерево найкоротших шляхів (ДНШ / SPT) |
|---|---|---|
| **Цільова функція** | Мінімізація сумарної ваги всіх ребер: `min ∑ w(e)` | Мінімізація відстаней від кореня: `min dist(s, v)` для кожного `v` |
| **Залежність від кореня** | Не має виділеного кореня (глобальна властивість графа) | Строго прив'язане до обраної кореневої вершини `s` |
| **Кількість ребер** | Завжди рівно `V - 1` | Завжди рівно `V - 1` |
| **Приклади застосування** | Прокладання магістральних мереж, кабелів, газопроводів | Маршрутизація пакетів в IP-мережах (OSPF), автомобільна навігація |

Розглянемо наочний приклад: трикутна мережа з вершинами `A, B, C` та вагами ребер `w(A, B) = 3`, `w(B, C) = 3`, `w(A, C) = 4`.
- **Мінімальне кістякове дерево** обирає два найдешевші ребра: `(A, B)` та `(B, C)`. Його сумарна вага становить `3 + 3 = 6`. Проте шлях між `A` та `C` по дереву проходить через `B` і має довжину `3 + 3 = 6`.
- **Дерево найкоротших шляхів із коренем у точці `A`** оптимізує шлях до кожного вузла. До вершини `B` воно веде напряму через `(A, B)` довжиною 3, а до вершини `C` — напряму через `(A, C)` довжиною 4. Відстань `dist(A, C) = 4` є меншою, ніж у МКД, але сумарна вартість усього дерева зростає до `3 + 4 = 7`.

### Фундаментальні закони: властивість розрізу та властивість циклу

Усі алгоритми пошуку МКД спираються на два дуальні математичні інваріанти: **властивість розрізу** (Cut Property, що визначає безпечні ребра для додавання) та **властивість циклу** (Cycle Property, що визначає надлишкові ребра для вилучення).

#### 1. Властивість розрізу (Cut Property)

**Означення розрізу:** **Розрізом** `(S, V \ S)` називається довільний поділ множини вершин `V` на дві непорожні підмножини `S` та `V \ S`. Ребро `e = (u, v)` **перетинає розріз**, якщо один його кінець лежить у `S`, а інший — у `V \ S`.

![Властивість розрізу (Cut Property) у зваженому графі](/root/eng/sf-algorithms/minimum-spanning-tree/img/mst-definition-cut.svg)
*Розріз графа ділить вершини на дві підмножини S та V \ S. Найлегше ребро (позначене червоним кольором, w = 3) серед усіх ребер, що перетинають границю розрізу, обов'язково належить мінімальному кістяковому дереву.*

**Формулювання властивості розрізу:** якщо серед усіх ребер, які перетинають довільний фіксований розріз `(S, V \ S)`, ребро `e` має строго найменшу вагу, то це ребро **гарантовано належить кожному мінімальному кістяковому дереву** графа.

Доведення цього твердження здійснюється технікою заміни ребер (Exchange Argument):
1. Припустимо, що деяке МКД `T` не містить цього найлегшого ребра `e = (u, v)`.
2. Оскільки `T` є зв'язним деревом, у ньому існує єдиний простий шлях між `u` та `v`. Оскільки `u ∈ S`, а `v ∈ V \ S`, цей шлях зобов'язаний щонайменше один раз перетнути границю розрізу по деякому іншому ребру `e'`.
3. Замінимо ребро `e'` на `e`, утворивши новий підграф `T' = T ∪ {e} \ {e'}`.
4. Оскільки `e'` видалено, а `e` додано, граф `T'` залишається зв'язним і має рівно `V - 1` ребер, отже, є валідним кістяковим деревом.
5. Порівняємо сумарні ваги:

```text
w(T')
= w(T) - w(e') + w(e)          [заміна ребра e' на ребро e]
≤ w(T) - w(e') + w(e')          [оскільки w(e) ≤ w(e') за вибором мінімального ребра розрізу]
= w(T)                          [алгебраїчне спрощення]
```

Оскільки `T` було мінімальним, нерівність `w(T') ≤ w(T)` означає, що `w(T') = w(T)`. Отже, `T'` також є мінімальним кістяковим деревом, яке вже містить ребро `e`.

#### 2. Властивість циклу (Cycle Property)

**Формулювання властивості циклу:** якщо в довільному простому замкненому циклі `C` графа деяке ребро `e_max` має строго більшу вагу, ніж будь-яке інше ребро цього циклу, то це ребро **не може належати жодному мінімальному кістяковому дереву**.

![Властивість циклу (Cycle Property) та техніка заміни ребер](/root/eng/sf-algorithms/minimum-spanning-tree/img/cycle-property-exchange.svg)
*Додавання до кістяка T стороннього ребра e_new замикає цикл C. Вилучення найважчого ребра цього циклу e_max відновлює дерево та зменшує його загальну вагу.*

Механізм доведення: якщо припустити, що деяке МКД `T` містить `e_max`, то видалення `e_max` розбиває `T` на дві компоненти зв'язності (індукуючи розріз). Проте решта циклу `C \ {e_max}` забезпечує альтернативний шлях між розірваними компонентами через деяке дешевше ребро `e'`. Заміна `e_max` на `e'` утворює кістяк `T' = T \ {e_max} ∪ {e'}` із вагою `w(T') < w(T)`, що прямо суперечить мінімальності `T`.

Повні алгебраїчні формулювання та матроїдне обґрунтування жадібного оптимуму (теорема Радо–Едмондса) наведено у статті [Математичні властивості розрізів, циклів та матроїдної структури МКД](root:sf-algorithms/minimum-spanning-tree/math-cut-cycle-properties.md).

> 🔧 **Навіщо це.** Якщо всі ваги ребер у графі є попарно різними, граф має **рівно одне унікальне мінімальне кістякове дерево**. Якщо деякі ребра мають однакову вагу, можуть існувати кілька різних рівноважних кістяків, проте їхня загальна вага завжди однакова, а будь-який коректний алгоритм гарантовано знайде один із глобальних оптимумів.

### Класичні алгоритмічні стратегії: Прим, Борувка та Краскал

Властивість розрізу стверджує, що додавання найдешевшого ребра розрізу є безпечним. Різні алгоритми відрізняються тим, які саме розрізи вони формують і в якому порядку їх розширюють.

![Еволюція побудови МКД: Алгоритм Прима проти Алгоритму Борувки](/root/eng/sf-algorithms/minimum-spanning-tree/img/prim-vs-boruvka-evolution.svg)
*Порівняння стратегій росту: алгоритм Прима розширює одне дерево послідовним приєднанням найближчих вершин, тоді як алгоритм Борувки паралельно об'єднує ізольовані фрагменти лісу.*

#### 1. Алгоритм Прима–Ярніка (Prim–Jarník Algorithm)

Алгоритм Прима реалізує **стратегію росту одного дерева**:
1. Початково обирається довільна стартова вершина `s`, яка утворює тривіальне дерево `T = ({s}, ∅)`.
2. На кожному кроці розрізом виступає пара `(V(T), V \ V(T))` — вершини, які вже увійшли до дерева, проти решти графа.
3. Алгоритм знаходить найдешевше ребро `(u, v)`, де `u ∈ V(T)`, а `v ∉ V(T)`, і додає його разом із вершиною `v` до дерева `T`.
4. Цей крок повторюється рівно `V - 1` разів.

Для ефективного пошуку найдешевшого вихідного ребра алгоритм використовує [двійкову купу](root:sf-algorithms/binary-heap-implementation). Кожна невідвідана вершина `v` зберігає оцінку `key[v] = min_{(u, v) : u ∈ T} w(u, v)` — вагу найдешевшого ребра, що зв'язує її з поточним деревом.

Покроковий псевдокод алгоритму Прима:

```text
Крок 1 (Ініціалізація):
  Для всіх v ∈ V встановити key[v] = ∞, parent[v] = null.
  Обрати довільний старт s ∈ V, встановити key[s] = 0.
  Створити пріоритетну Min-купу Q і додати туди всі вершини з ключами key[v].

Крок 2 (Основний цикл):
  Поки купа Q не порожня:
    u = Q.extract_min()
    Позначити вершину u як включену до дерева T.
    Для кожного сусіда v вершини u у списку суміжності adj[u]:
      Якщо v ∉ T та w(u, v) < key[v]:
        key[v] = w(u, v)
        parent[v] = u
        Q.decrease_key(v, key[v])
```

Часова складність алгоритму Прима залежить від структури черги:
- `O(V²)` при використанні простого масиву (оптимально для дуже щільних графів, де `E ≈ V²`);
- `O(E log V)` при використанні двійкової купи та списків суміжності;
- `O(E + V log V)` при використанні фібоначчієвої купи (теоретично найкраща межа).

#### 2. Алгоритм Борувки (Borůvka Algorithm)

Алгоритм Борувки реалізує **паралельну багатофрагментну стратегію**:
1. Початково кожна вершина графа утворює власну ізольовану компоненту зв'язності (ліс із `V` дерев).
2. На кожній фазі **кожна компонента паралельно** знаходить своє індивідуальне найдешевше ребро, яке веде назовні (до будь-якої іншої компоненти).
3. Усі знайдені мінімальні ребра одночасно додаються до лісу, після чого сполучені компоненти зливаються воєдино за допомогою структури [системи неперетинних множин](root:sf-algorithms/union-find).
4. Оскільки на кожному етапі кожна компонента зливається принаймні з однією сусідньою, кількість компонент зменшується щонайменше вдвічі: `C_{k+1} ≤ C_k / 2`.
5. Алгоритм гарантовано зупиняється не більше ніж за `⌈log₂ V⌉` фаз.

Складність алгоритму Борувки становить `O(E log V)`. Оскільки на кожній фазі обробка компонент не залежить одна від одної, цей алгоритм ідеально масштабується на багатоядерних процесорах, кластерах та графічних прискорювачах (GPU).

#### 3. Алгоритм Краскала (Kruskal Algorithm)

Алгоритм Краскала використовує **глобальну жадібну сортувальну стратегію**:
1. Усі `E` ребер вихідного графа сортуються за зростанням ваги.
2. Алгоритм послідовно сканує відсортовані ребра: якщо поточне ребро з'єднує вершини з двох різних компонент (перевіряється через `DSU.find()`), воно додається до розв'язку, а множини об'єднуються (`DSU.union()`). Якщо обидва кінці ребра вже належать одній компоненті, ребро відкидається, оскільки воно створило б надлишковий цикл.

Складність становить `O(E log E) = O(E log V)` через сортування ребер. Повний аналіз алгоритму Краскала винесено у присвячену тему [Алгоритм Краскала](root:sf-algorithms/kruskal-algorithm).

| **Оптимальна область** | Розріджені графи (`E ≪ V²`) | Повні/щільні графи (`E ≈ V²`) | Паралельні/розподілені системи | Дуже розріджені графи |
| **Базова структура даних**| Min-Heap (двійкова купа) | Простий одновимірний масив | Disjoint-Set Union (DSU) | Disjoint-Set Union (DSU) |
| **Локальність пам'яті (L1/L2)**| Середня (стрибки по купі) | Висока (послідовний прохід) | Висока (лінійне сканування) | Максимальна (сортований масив)|
| **Паралелізація** | Погана (строго послідовний)| Погана | **Ідеальна (масивний SIMD/GPU)**| Середня (лише сортування) |

### Покрокове трасування побудови МКД на контрольному прикладі

Простежимо виконання алгоритму Прима на прикладі неорієнтованого графа з 6 вершинами (`A, B, C, D, E, F`) та 9 ребрами:
- `(A, B): 4`, `(A, C): 2`
- `(B, C): 1`, `(B, D): 5`
- `(C, D): 8`, `(C, E): 10`
- `(D, E): 2`, `(D, F): 6`
- `(E, F): 3`

#### Покроковий протокол роботи алгоритму Прима (Старт із `A`)

Початковий стан: `key[A] = 0`, для решти вершин `key = ∞`.

```text
Крок 1:
  Вилучаємо з купи вершину A (key = 0). Включаємо A до дерева: T = {A}.
  Перевіряємо суміжних сусідів вершини A:
    - Ребро (A, B) з вагою 4: оскільки 4 < key[B] (∞), встановлюємо key[B] = 4, parent[B] = A.
    - Ребро (A, C) з вагою 2: оскільки 2 < key[C] (∞), встановлюємо key[C] = 2, parent[C] = A.
  Поточний стан черги: {C: 2, B: 4, D: ∞, E: ∞, F: ∞}

Крок 2:
  Вилучаємо вершину з мінімальним ключем: C (key = 2).
  Додаємо ребро (A, C) вагою 2. Склад дерева: T = {A, C}.
  Оновлюємо оцінки невідвіданих сусідів вершини C (B, D, E):
    - Ребро (C, B) з вагою 1: оскільки 1 < key[B] (4), покращуємо key[B] = 1, parent[B] = C.
    - Ребро (C, D) з вагою 8: оскільки 8 < key[D] (∞), встановлюємо key[D] = 8, parent[D] = C.
    - Ребро (C, E) з вагою 10: оскільки 10 < key[E] (∞), встановлюємо key[E] = 10, parent[E] = C.
  Поточний стан черги: {B: 1, D: 8, E: 10, F: ∞}

Крок 3:
  Вилучаємо вершину з мінімальним ключем: B (key = 1).
  Додаємо ребро (C, B) вагою 1. Склад дерева: T = {A, C, B}.
  Оновлюємо сусідів вершини B (D):
    - Ребро (B, D) з вагою 5: оскільки 5 < key[D] (8), покращуємо key[D] = 5, parent[D] = B.
  Поточний стан черги: {D: 5, E: 10, F: ∞}

Крок 4:
  Вилучаємо вершину з мінімальним ключем: D (key = 5).
  Додаємо ребро (B, D) вагою 5. Склад дерева: T = {A, C, B, D}.
  Оновлюємо сусідів вершини D (E, F):
    - Ребро (D, E) з вагою 2: оскільки 2 < key[E] (10), покращуємо key[E] = 2, parent[E] = D.
    - Ребро (D, F) з вагою 6: оскільки 6 < key[F] (∞), встановлюємо key[F] = 6, parent[F] = D.
  Поточний стан черги: {E: 2, F: 6}

Крок 5:
  Вилучаємо вершину з мінімальним ключем: E (key = 2).
  Додаємо ребро (D, E) вагою 2. Склад дерева: T = {A, C, B, D, E}.
  Оновлюємо сусідів вершини E (F):
    - Ребро (E, F) з вагою 3: оскільки 3 < key[F] (6), покращуємо key[F] = 3, parent[F] = E.
  Поточний стан черги: {F: 3}

Крок 6:
  Вилучаємо останню вершину: F (key = 3).
  Додаємо ребро (E, F) вагою 3. Склад дерева: T = {A, C, B, D, E, F}.

Черга порожня — виконання завершено.
Фінальний список ребер мінімального кістякового дерева:
  1. (A, C) — вага 2
  2. (C, B) — вага 1
  3. (B, D) — вага 5
  4. (D, E) — вага 2
  5. (E, F) — вага 3

Сумарна вага знайденого мінімального кістякового дерева: 2 + 1 + 5 + 2 + 3 = 13.
Загальна кількість ребер: 5 (що точно дорівнює V - 1 = 6 - 1).
```

### Прикладні застосування та алгоритмічні редукції

Мінімальне кістякове дерево є фундаментальною опорою для багатьох суміжних прикладних дисциплін:

#### 1. Кластеризація методом максимального розділення (Single-Linkage Hierarchical Clustering)

В аналізі багатовимірних даних часто необхідно згрупувати `N` спостережень у `k` природних кластерів так, щоб мінімальна відстань між точками з різних кластерів була максимально можливою (англ. *Max-Spacing k-Clustering*).

![Застосування МКД: Кластеризація (k-Clustering) та Вузькі місця](/root/eng/sf-algorithms/minimum-spanning-tree/img/clustering-and-bottleneck.svg)
*Видалення k - 1 найважчих ребер із попередньо побудованого МКД розбиває граф на k кластерів із гарантовано максимальним міжкиликовим розділенням.*

Процедура кластеризації:
1. Будуємо повне МКД над усіма точками, де вага ребра — це евклідова або косинусна відстань між ними.
2. Знаходимо `k - 1` найважчих ребер у побудованому дереві та видаляємо їх.
3. Граф розпадається рівно на `k` зв'язних компонент, які утворюють шукані кластери. Відстань розділення між кластерами точно дорівнює вазі найменшого з вилучених `k - 1` ребер.

#### 2. Апроксимація метричної задачі комівояжера (Metric TSP 2-Approximation)

У метричних графах (де діє нерівність трикутника `w(u, v) ≤ w(u, w) + w(w, v)`) мінімальне кістякове дерево дає швидку 2-апроксимацію для NP-важкої задачі комівояжера:
1. Знаходимо МКД `T` за час `O(E log V)`. Вага оптимального маршруту комівояжера `w(TSP*)` строго перевищує `w(T)`, оскільки видалення будь-якого ребра з циклу TSP дає кістякове дерево.
2. Виконуємо обхід дерева в глибину (DFS), дублюючи кожне ребро. Довжина обходу дорівнює `2 · w(T)`.
3. Формуємо фінальний цикл, пропускаючи вже відвідані вершини (shortcutting). Завдяки нерівності трикутника прямий перехід ніколи не збільшує довжину:

```text
w(Маршрут) ≤ 2 · w(T) < 2 · w(TSP*)
```

Отриманий поліноміальний розв'язок гарантовано відхиляється від недосяжного оптимуму не більше ніж удвічі.

#### 3. Мережеві протоколи запобігання петлям (IEEE 802.1D STP / MSTP)

У комутованих комп'ютерних мережах Ethernet наявність фізичних резервних ліній між комутаторами може призводити до нескінченних широкомовних штормів (Broadcast Storms). Протокол **Spanning Tree Protocol (STP)** динамічно обчислює кістякове дерево над фізичною топологією мережі та блокує надлишкові порти комутаторів. Якщо активний канал виходить із ладу, протокол перераховує кістяк і автоматично розблоковує резервний лінк.

### Граничні умови та системні пастки

При розробці системних модулів необхідно враховувати специфічні крайові стани:

1. **Незв'язний граф:** якщо граф розпадається на `C > 1` ізольованих компонент, побудувати єдине кістякове дерево неможливо. Алгоритми коректно повертають **мінімальний кістяковий ліс** (Minimum Spanning Forest, MSF), який містить `V - C` ребер.
2. **Від'ємні ваги ребер:** алгоритми МКД (Прим, Краскал, Борувка) **працюють з від'ємними вагами абсолютно коректно**. Додавання константи `C` до всіх ребер лише зсуває сумарну вагу на `(V - 1) · C`, не змінюючи оптимальну структуру кістяка.
3. **Паралельні ребра та петлі:** петлі `(u, u)` ніколи не входять до МКД. Серед кількох паралельних ребер між `u` та `v` до розрахунку береться лише ребро з мінімальною вагою.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <stdint.h>

#define INF_WEIGHT INT64_MAX

typedef struct EdgeNode {
    int to;
    int64_t weight;
    struct EdgeNode *next;
} EdgeNode;

typedef struct {
    int num_vertices;
    EdgeNode **adj;
} Graph;

typedef struct {
    int u;
    int v;
    int64_t weight;
} MstEdge;

typedef struct {
    MstEdge *edges;
    int edge_count;
    int64_t total_weight;
    bool is_connected;
} MstResult;

typedef struct {
    int vertex;
    int64_t key;
} HeapNode;

typedef struct {
    HeapNode *data;
    int *pos;
    int size;
    int capacity;
} MinHeap;

static void heap_swap(MinHeap *h, int i, int j) {
    HeapNode tmp = h->data[i];
    h->data[i] = h->data[j];
    h->data[j] = tmp;
    h->pos[h->data[i].vertex] = i;
    h->pos[h->data[j].vertex] = j;
}

static void sift_up(MinHeap *h, int idx) {
    while (idx > 0) {
        int parent = (idx - 1) / 2;
        if (h->data[idx].key < h->data[parent].key) {
            heap_swap(h, idx, parent);
            idx = parent;
        } else break;
    }
}

static void sift_down(MinHeap *h, int idx) {
    while (true) {
        int left = 2 * idx + 1, right = 2 * idx + 2, smallest = idx;
        if (left < h->size && h->data[left].key < h->data[smallest].key) smallest = left;
        if (right < h->size && h->data[right].key < h->data[smallest].key) smallest = right;
        if (smallest != idx) {
            heap_swap(h, idx, smallest);
            idx = smallest;
        } else break;
    }
}

MinHeap* min_heap_create(int capacity) {
    MinHeap *h = (MinHeap*)malloc(sizeof(MinHeap));
    h->data = (HeapNode*)malloc(sizeof(HeapNode) * capacity);
    h->pos = (int*)malloc(sizeof(int) * capacity);
    h->size = 0;
    h->capacity = capacity;
    for (int i = 0; i < capacity; ++i) h->pos[i] = -1;
    return h;
}

void min_heap_free(MinHeap *h) {
    if (!h) return;
    free(h->data);
    free(h->pos);
    free(h);
}

void min_heap_insert_or_decrease(MinHeap *h, int v, int64_t key) {
    if (h->pos[v] == -1) {
        int idx = h->size++;
        h->data[idx].vertex = v;
        h->data[idx].key = key;
        h->pos[v] = idx;
        sift_up(h, idx);
    } else {
        int idx = h->pos[v];
        if (key < h->data[idx].key) {
            h->data[idx].key = key;
            sift_up(h, idx);
        }
    }
}

bool min_heap_extract_min(MinHeap *h, HeapNode *out) {
    if (h->size == 0) return false;
    *out = h->data[0];
    h->pos[out->vertex] = -1;
    h->size--;
    if (h->size > 0) {
        h->data[0] = h->data[h->size];
        h->pos[h->data[0].vertex] = 0;
        sift_down(h, 0);
    }
    return true;
}

MstResult prim_mst(const Graph *g) {
    int n = g->num_vertices;
    MstResult res = {0};
    if (n <= 0) return res;

    res.edges = (MstEdge*)malloc(sizeof(MstEdge) * (n > 1 ? n - 1 : 1));
    int64_t *key = (int64_t*)malloc(sizeof(int64_t) * n);
    int *parent = (int*)malloc(sizeof(int) * n);
    bool *in_mst = (bool*)calloc(n, sizeof(bool));
    MinHeap *heap = min_heap_create(n);

    for (int i = 0; i < n; ++i) {
        key[i] = INF_WEIGHT;
        parent[i] = -1;
    }

    key[0] = 0;
    min_heap_insert_or_decrease(heap, 0, 0);
    int visited = 0;

    while (heap->size > 0) {
        HeapNode node;
        min_heap_extract_min(heap, &node);
        int u = node.vertex;
        in_mst[u] = true;
        visited++;

        if (parent[u] != -1) {
            res.edges[res.edge_count].u = parent[u];
            res.edges[res.edge_count].v = u;
            res.edges[res.edge_count].weight = node.key;
            res.total_weight += node.key;
            res.edge_count++;
        }

        for (EdgeNode *e = g->adj[u]; e != NULL; e = e->next) {
            int v = e->to;
            int64_t w = e->weight;
            if (!in_mst[v] && w < key[v]) {
                key[v] = w;
                parent[v] = u;
                min_heap_insert_or_decrease(heap, v, w);
            }
        }
    }

    res.is_connected = (visited == n);

    min_heap_free(heap);
    free(key);
    free(parent);
    free(in_mst);
    return res;
}
```

```cpp
#include <vector>
#include <queue>
#include <span>
#include <cstdint>
#include <limits>

struct Edge {
    int to;
    int64_t weight;
};

struct MstEdge {
    int u;
    int v;
    int64_t weight;
};

struct MstResult {
    std::vector<MstEdge> edges;
    int64_t total_weight{0};
    bool is_connected{false};
};

class Graph {
public:
    explicit Graph(int num_vertices) : adj_(num_vertices) {}

    void add_edge(int u, int v, int64_t weight) {
        adj_[u].push_back(Edge{v, weight});
        adj_[v].push_back(Edge{u, weight});
    }

    [[nodiscard]] int num_vertices() const noexcept {
        return static_cast<int>(adj_.size());
    }

    [[nodiscard]] std::span<const Edge> neighbors(int u) const noexcept {
        return adj_[u];
    }

private:
    std::vector<std::vector<Edge>> adj_;
};

[[nodiscard]] MstResult prim_mst(const Graph& graph) {
    const int n = graph.num_vertices();
    if (n == 0) return {};

    MstResult result;
    result.edges.reserve(n > 1 ? n - 1 : 0);

    std::vector<int64_t> min_key(n, std::numeric_limits<int64_t>::max());
    std::vector<int> parent(n, -1);
    std::vector<bool> in_mst(n, false);

    // Min-Priority Queue зберігає пари (вага, вершина)
    using QueueNode = std::pair<int64_t, int>;
    std::priority_queue<QueueNode, std::vector<QueueNode>, std::greater<>> pq;

    min_key[0] = 0;
    pq.emplace(0, 0);
    int visited_count = 0;

    while (!pq.empty()) {
        const auto [weight, u] = pq.top();
        pq.pop();

        if (in_mst[u]) continue;

        in_mst[u] = true;
        visited_count++;

        if (parent[u] != -1) {
            result.edges.push_back(MstEdge{parent[u], u, weight});
            result.total_weight += weight;
        }

        for (const auto& [v, w] : graph.neighbors(u)) {
            if (!in_mst[v] && w < min_key[v]) {
                min_key[v] = w;
                parent[v] = u;
                pq.emplace(w, v);
            }
        }
    }

    result.is_connected = (visited_count == n);
    return result;
}
```
