# 🧮 Математичний аналіз сортування злиттям: рекурентність, точні межі та інверсії

Сортування злиттям (Merge Sort) є еталонним алгоритмом парадигми «розділяй і володарюй» у теоретичній інформатиці. На відміну від швидкого сортування (Quicksort), чия швидкодія коливається від `O(n log n)` до квадратичної деградації `O(n²)` залежно від невдалого вибору опорного елемента, та сортування купою (Heapsort) зі складною динамікою кеш-промахів, Merge Sort володіє суворо детермінованою структурою обчислень.

У цьому математичному аналізі наведено строге виведення часової складності через апарат рекурентних рівнянь, обчислено точну кількість операцій порівняння ключів для найкращого, найгіршого та середнього випадків, доведено інформаційно-теоретичну оптимальність алгоритму та розібрано задачу підрахунку інверсій у масиві.

## 1. Рекурентне рівняння та фаза злиття

Нехай `T(n)` позначає кількість елементарних операцій (або кількість порівнянь ключів), необхідних для сортування масиву розміром `n`.

Алгоритм виконує три послідовні фази:
1. **Розбиття (Divide):** обчислення індексу середини `mid = lo + (hi - lo) / 2` та поділ задачі на дві підзадачі розміром `⌈n / 2⌉` та `⌊n / 2⌋`. Цей крок виконується за сталий час `O(1)`.
2. **Рекурсивний спуск (Conquer):** два незалежних виклики сортування для кожної половини масиву, що вимагає `T(⌈n / 2⌉) + T(⌊n / 2⌋)` часу.
3. **Об'єднання (Combine / Merge):** злиття двох впорядкованих підмасивів у єдиний буфер.

Розглянемо кількість порівнянь ключів під час злиття двох підмасивів розміром `n₁` та `n₂`, де `n₁ + n₂ = n`. 

На кожному кроці процедури злиття порівнюються два поточні елементи підмасивів, і менший із них записується у вихідний масив. Після кожного порівняння один елемент гарантовано займає своє підсумкове місце. Коли один із підмасивів вичерпується повністю, решта елементів другого підмасиву просто копіюється без жодного додаткового порівняння.

Звідси випливають точні межі кількості порівнянь `C(n₁, n₂)` на фазі злиття:
- **Найгірший випадок (Worst Case):** елементи обох підмасивів чергуються за значенням аж до останнього кроку (наприклад, `[1, 3, 5]` та `[2, 4, 6]`). Злиття зупиняється, коли у грі залишається рівно 1 елемент. Кількість порівнянь становить:
```
C_worst(n₁, n₂) = n₁ + n₂ − 1 = n − 1
```
- **Найкращий випадок (Best Case):** усі елементи одного підмасиву строго менші за найменший елемент другого підмасиву (наприклад, `[1, 2, 3]` та `[4, 5, 6]`). Перший підмасив вичерпується рівно за `min(n₁, n₂)` кроків, після чого решта `max(n₁, n₂)` елементів копіюється без порівнянь:
```
C_best(n₁, n₂) = min(n₁, n₂) = ⌊n / 2⌋
```

Отже, загальне рекурентне рівняння для найгіршого випадку кількості порівнянь `W(n)` при степенях двійки `n = 2ᵏ` має вигляд:
```
W(n) = 2 · W(n / 2) + n − 1    [для n ≥ 2]
W(1) = 0                       [базовий випадок для одного елемента]
```

## 2. Розв'язок рекурентності методом дерева рекурсії

Щоб знайти точний замкнений вираз для `W(n)`, побудуємо дерево рекурсивних викликів.

Нехай `n = 2ᵏ`, тобто висота дерева рекурсії становить `k = log₂ n` рівнів (індексуємо рівні від `j = 0` до `k`):
- На рівні `j = 0` (корінь) маємо `2⁰ = 1` задачу розміром `n`. Вартість злиття: `n − 1`.
- На рівні `j = 1` маємо `2¹ = 2` задачі розміром `n / 2`. Вартість злиття на кожній: `n / 2 − 1`. Сумарна вартість рівня: `2 · (n / 2 − 1) = n − 2`.
- На рівні `j = 2` маємо `2² = 4` задачі розміром `n / 4`. Сумарна вартість рівня: `4 · (n / 4 − 1) = n − 4 = n − 2²`.
- На довільному рівні `j` (де `0 ≤ j ≤ k − 1`) маємо `2ʲ` підзадач розміром `n / 2ʲ`. Сумарна кількість порівнянь на рівні `j` становить:
```
Cost(j) = 2ʲ · ((n / 2ʲ) − 1) = n − 2ʲ
```
- На рівні листя `j = k` розмір підзадач дорівнює `1`, і порівняння не виконуються (`Cost(k) = 0`).

Просумуємо вартість усіх рівнів від `j = 0` до `k − 1`:

```
W(n)
= ∑ [n − 2ʲ]                        [сума по j від 0 до k - 1]
= ∑ n − ∑ 2ʲ                        [розбиття на дві незалежні суми]
= n · k − (2⁰ + 2¹ + ... + 2ᵏ⁻¹)    [обчислення першої суми: k доданків по n]
= n · k − (2ᵏ − 1)                  [формула суми геометричної прогресії]
= n · log₂ n − n + 1                [підстановка k = log₂ n та 2ᵏ = n]
```

Таким чином, для будь-якого масиву розміром `n = 2ᵏ` найгірша кількість порівнянь ключів у сортуванні злиттям строго дорівнює:
```
W(n) = n · log₂ n − n + 1
```

Для довільного натурального `n`, що не є точним степенем двійки, застосовується формула з округленням:
```
W(n) = n · ⌈log₂ n⌉ − 2^⌈log₂ n⌉ + 1
```

## 3. Аналіз найкращого та середнього випадків

Розглянемо найкращий випадок, коли на кожному кроці злиття один із підмасивів одразу вичерпується:

```
B(n) = 2 · B(n / 2) + n / 2         [рекурентність найкращого випадку для n = 2ᵏ]
B(1) = 0
```

Обчислимо вартість на рівні `j`: маємо `2ʲ` підзадач, кожна з яких робить `(n / 2ʲ) / 2 = n / 2ʲ⁺¹` порівнянь:

```
B(n)
= ∑ [2ʲ · (n / 2ʲ⁺¹)]               [сума по j від 0 до k - 1]
= ∑ [n / 2]                         [скорочення 2ʲ у кожному доданку]
= (n / 2) · k                       [сума k однакових доданків]
= (n / 2) · log₂ n                  [підстановка k = log₂ n]
```

У найкращому випадку алгоритм виконує рівно вдвічі менше порівнянь, ніж у найгіршому: приблизно `0.5 · n log₂ n`.

Для визначення середньої кількості порівнянь `A(n)` припустимо, що всі `n!` перестановок вхідних даних рівноймовірні. Точний ймовірнісний аналіз злиття двох випадкових впорядкованих списків розміром `m = n / 2` показує, що сподівана кількість порівнянь на один елемент становить:
```
E[C(m, m)] = 2m − (2m / (m + 1)) = n − (2n / (n + 2)) ≈ n − 2
```

Підсумовуючи за всіма рівнями дерева рекурсії, отримуємо середню кількість порівнянь:
```
A(n) = n · log₂ n − γ · n + O(log₂ n)
```
де константа `γ = 1 + ∑ (1 / (2ʲ + 1)) ≈ 1.2644997...`.

Середня кількість порівнянь Merge Sort відрізняється від найгіршої лише на невеликий лінійний коефіцієнт:
```
A(n) ≈ n · log₂ n − 1.264 · n
```

## 4. Інформаційно-теоретична нижня межа та оптимальність

Постає фундаментальне теоретичне питання: чи можливо створити детермінований алгоритм сортування порівняннями, який робить асимптотично менше операцій, ніж `n log₂ n`?

Будь-який алгоритм сортування, що спирається на попарні порівняння елементів (`A[i] < A[j]`), можна представити як бінарне **дерево рішень** (decision tree):
- Кожен внутрішній вузол дерева відповідає одному порівнянню двох елементів.
- Дві гілки, що виходять із вузла, відповідають наслідкам `ТАК` (`≤`) або `НІ` (`>`).
- Кожен листок дерева відповідає одній унікальній перестановці вхідних елементів, яка є остаточним впорядкованим результатом.

Оскільки для масиву з `n` різних елементів існує рівно `n!` (n-факторіал) можливих перестановок, бінарне дерево рішень зобов'язане мати щонайменше `L = n!` листків, щоб розрізнити всі можливі вхідні порядки.

Висота бінарного дерева `h` із `L` листками обмежена знизу співвідношенням:
```
2ʰ ≥ L = n!
h ≥ ⌈log₂ (n!)⌉
```

Застосуємо формулу Стірлінга для апроксимації факторіала великих чисел:
```
n! ≈ √(2πn) · (n / e)ⁿ
```

Візьмемо двійковий логарифм від обох частин:

```
log₂ (n!)
= log₂ (√(2πn) · (n / e)ⁿ)                        [логарифмування формули Стірлінга]
= n · log₂ (n / e) + 0.5 · log₂ (2πn)             [властивості логарифма добутку]
= n · log₂ n − n · log₂ e + 0.5 · log₂ n + O(1)   [розкриття log₂(n/e) = log₂ n - log₂ e]
= n · log₂ n − 1.442695 · n + 0.5 · log₂ n + O(1) [підстановка log₂ e ≈ 1.442695]
```

Порівняємо теоретичну абсолютну нижню межу будь-якого сортування порівняннями із найгіршим випадком Merge Sort:
```
Теоретичний мінімум: h_min ≥ n · log₂ n − 1.4427 · n
Найгірший Merge Sort: W(n)  = n · log₂ n − 1.0000 · n + 1
```

Різниця між абсолютною межею природи та результатом сортування злиттям становить менше ніж `0.443 · n` порівнянь. Це доводить, що **Merge Sort є асимптотично та практично оптимальним за кількістю порівнянь алгоритмом сортування**.

## 5. Задача підрахунку інверсій за O(n log n)

Класичним застосуванням механіки Merge Sort є задача підрахунку інверсій у масиві (Counting Inversions), яка виникає у вимірюванні подібності уподобань користувачів (колаборативна фільтрація), аналізі рангових кореляцій Кендалла (Kendall tau distance) та біоінформатиці.

**Інверсією** у масиві `A[0..n-1]` називається будь-яка пара індексів `(i, j)`, для яких виконується умова:
```
i < j   та   A[i] > A[j]
```

Наївний перебір усіх можливих пар `(i, j)` вимагає перевірки `n(n - 1) / 2` комбінацій, тобто працює за квадратичний час `O(n²)`.

Сортування злиттям дозволяє обчислити точну кількість інверсій за час `O(n log n)`.

Розглянемо розбиття масиву на дві половини: ліву `A[lo..mid]` та праву `A[mid+1..hi]`. Усі інверсії в масиві діляться на три типи:
1. **Ліві інверсії:** обидва індекси `i, j` лежать у лівій половині (`lo ≤ i < j ≤ mid`). Обчислюються рекурсивно викликом на лівій частині.
2. **Праві інверсії:** обидва індекси `i, j` лежать у правій половині (`mid+1 ≤ i < j ≤ hi`). Обчислюються рекурсивно викликом на правій частині.
3. **Перехресні інверсії (Split Inversions):** лівий індекс лежить у лівій половині (`lo ≤ i ≤ mid`), а правий — у правій (`mid+1 ≤ j ≤ hi`), причому `A[i] > A[j]`.

Ключовий математичний інваріант полягає в тому, що коли обидві половини вже впорядковані за зростанням, перехресні інверсії підраховуються безпосередньо під час двовказівникового злиття.

Нехай вказівник `i` сканує лівий підмасив, а вказівник `j` — правий. Якщо на певному кроці виявляється, що:
```
A[i] > A[j]
```
то оскільки лівий підмасив відсортований, елемент `A[j]` є строго меншим не лише за `A[i]`, а й за **усі наступні елементи лівого підмасиву** від позиції `i` до позиції `mid`.

Кількість таких елементів становить рівно:
```
Count_inv = mid − i + 1
```

Додаючи `mid − i + 1` до загального лічильника щоразу, коли черговий елемент обирається з правого підмасиву, алгоритм підраховує всі перехресні інверсії за лінійний час `O(n)` паралельно зі злиттям.

Загальна рекурентність підрахунку інверсій тотожна рекурентності Merge Sort:
```
Inv(n) = 2 · Inv(n / 2) + O(n) = O(n log n)
```

Це демонструє, як комбінаторна структура сортування злиттям перетворює складну задачу аналізу перестановок на лінійно декомпонований процес.
