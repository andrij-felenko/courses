# 📋 Довідник інтерфейсів та інваріантів сортування вибором

Сортування вибором (Selection Sort) надає строгий і передбачуваний контракт виконання. Цей довідник містить повну специфікацію функціональних інтерфейсів для мов C та C++, підсумкову таблицю часової та просторової складності, контрактні інваріанти пре- та пост-умов, характеристики потокобезпеки, а також практичні рекомендації щодо системних обмежень у вбудованих платформах (Embedded Systems) та ОС реального часу (RTOS).

## 1. Сигнатури функцій та специфікація API

Нижче подано декларації системних функцій та шаблонів для програмної інтеграції сортування вибором у C та C++ проєкти.

:::tabs
```c
#include <stddef.h>

/*
 * Сортування масиву цілих чисел типу int.
 *
 * @param arr Покажчик на перший елемент масиву. Повинен бути не-NULL.
 * @param n   Кількість елементів у масиві.
 */
void selection_sort_int(int *arr, size_t n);

/*
 * Універсальне сортування буфера довільного типу за аналогією з qsort().
 *
 * @param base Покажчик на початок буфера пам'яті.
 * @param num  Кількість елементів у буфері.
 * @param size Розмір одного елемента в байтах (sizeof(T)).
 * @param cmp  Функція-компаратор: повертає <0 якщо (a < b), 0 якщо (a == b), >0 якщо (a > b).
 */
void selection_sort_generic(void *base, size_t num, size_t size,
                            int (*cmp)(const void *a, const void *b));

/*
 * Двостороннє сортування вибором (Min-Max Selection Sort).
 * Зменшує кількість ітерацій зовнішнього циклу у 2 рази.
 */
void double_selection_sort(int *arr, size_t n);

/*
 * Стійке сортування вибором (Stable Selection Sort).
 * Застосовує зсув елементів замість прямого swap, зберігаючи відносний порядок.
 */
void stable_selection_sort(int *arr, size_t n);
```
```cpp
#include <span>
#include <functional>
#include <concepts>
#include <iterator>

namespace algo {

/*
 * Основний шаблон сортування вибором для безперервного послідовного контейнера (std::span).
 *
 * @tparam T      Тип елементів. Мусить підтримувати переміщення або копіювання.
 * @tparam Compare Тип предикату порівняння. За замовчуванням std::less<T>.
 *
 * @param data    Перегляд масиву через std::span<T>.
 * @param comp    Об'єкт порівняння.
 */
template <typename T, typename Compare = std::less<T>>
void selection_sort(std::span<T> data, Compare comp = Compare{}) noexcept(
    noexcept(comp(data[0], data[0])) && std::is_nothrow_move_assignable_v<T>);

/*
 * Перевантаження для довільних ітераторів прямого доступу.
 *
 * @tparam RandomIt Тип ітератора (вимагає RandomAccessIterator).
 * @tparam Compare  Тип предикату порівняння.
 */
template <typename RandomIt, typename Compare = std::less<>>
void selection_sort(RandomIt first, RandomIt last, Compare comp = Compare{});

/*
 * Двостороннє сортування вибором (Min-Max Selection Sort).
 */
template <typename T, typename Compare = std::less<T>>
void double_selection_sort(std::span<T> data, Compare comp = Compare{});

/*
 * Стійке сортування вибором (Stable Selection Sort).
 */
template <typename T, typename Compare = std::less<T>>
void stable_selection_sort(std::span<T> data, Compare comp = Compare{});

} // namespace algo
```

Детальний текстовий розбір контрактів C API:
1. **Специфікація `selection_sort_int`:**
   - **Призначення:** Оптимізована реалізація для масивів значущих цілих чисел `int`.
   - **Параметри:** `arr` — покажчик на неперервний блок пам'яті у виділеному сегменті. Якщо `arr == NULL` або кількість елементів `n < 2`, функція миттєво повертає керування, не здійснюючи жодних операцій у пам'яті.
   - **Повертане значення:** `void`. Зміни здійснюються безпосередньо у переданому масиві (in-place modification).
   - **Побічні ефекти:** Мутує вміст буфера `arr`. Не викликає процедур динамічного виділення пам'яті (`malloc`/`calloc`).
   - **Потокобезпека (Thread-Safety):** Потокобезпечна для неперетинних масивів. Якщо кілька потоків звертаються до одного масиву без зовнішньої синхронізації (mutex/spinlock), виникає стан гонитви (Data Race).

2. **Специфікація `selection_sort_generic`:**
   - **Призначення:** Універсальний інтерфейс для сортування масивів довільних структур даних, що аналогічний стандартній функції POSIX `qsort()`.
   - **Параметри:** `base` — неоформлений покажчик на початок буфера даних; `num` — кількість елементів у буфері; `size` — точний розмір одного елемента у байтах (обчислюється через оператор `sizeof`); `cmp` — покажчик на користувацьку функцію порівняння.
   - **Функція-компаратор `cmp`:** Приймає два покажчики `const void *a` та `const void *b`. Повинна повертати від'ємне число, якщо елемент `a` строго менший за `b`, нуль якщо значення рівні, та додатне число якщо `a` більше за `b`.
   - **Вимоги до пам'яті:** Побайтовий обмін вмісту двох елементів здійснюється через локальний буфер фіксованого розміру на стеку або побайтову ітерацію.

3. **Специфікація `double_selection_sort`:**
   - **Призначення:** Оптимізований двосторонній варіант (Min-Max Selection Sort), який знаходить найменший і найбільший елементи за один прохід.
   - **Особливості:** Зменшує кількість ітерацій зовнішнього циклу з `N - 1` до `N / 2`. Не рекомендується для масивів з елементами, чий розмір перебільшує розмір кеш-лінії процесора, якщо операція порівняння є дуже дорогою.

4. **Специфікація `stable_selection_sort`:**
   - **Призначення:** Модифікація сортування вибором з гарантією збереження відносного порядку однаковими елементами.
   - **Ціна стійкості:** Замість прямого обміну `swap` (який робить не більше `N - 1` записів) виконує зсув усіх елементів підмасиву, що збільшує кількість фізичних операцій перезапису пам'яті до квадратичного рівня `O(N²)`.

Детальний текстовий розбір контрактів C++ API:
1. **Шаблон `selection_sort(std::span<T>, Compare)`:**
   - **Концептуальні обмеження:** Тип `T` мусить задовільняти вимоги `std::movable` чи `std::copyable`. Предикат `Compare` мусить бути бінарним оператором, який реалізує строгий слабкий порядок (Strict Weak Ordering).
   - **Специфікація винятків (Exception Safety):** Забезпечує базову або сильну гарантію безпеки винятків (Strong Exception Guarantee). Якщо компаратор або операції присвоєння типу `T` не генерують винятків (`noexcept`), сам шаблон декларується як `noexcept`.
   - **Управління ресурсами (RAII):** Обмін елементів виконується через `std::swap` з підтримкою ADL (Argument-Dependent Lookup), що гарантує виклики специфікованих користувацьких функцій обміну для складних об'єктів.

2. **Шаблон `selection_sort(RandomIt, RandomIt, Compare)`:**
   - **Вимоги до категорій ітераторів:** Вимагає від ітератора підтримки категорії `std::random_access_iterator_tag`. Працює з `std::vector`, `std::array`, `std::deque` та звичайними сирими вказівниками.
   - **Передавання за посиланням:** Компаратор передається за значенням або за константним посиланням, що дозволяє використовувати як лямбда-вирази, так і функтори `std::less<>` чи `std::greater<>`.

## 2. Специфікація обчислювальної складності та ресурсних обмежень

Таблиця нижче підсумовує гарантії складності сортування вибором за часом, додатковою пам'яттю, кількістю порівнянь та фізичних перезаписів у пам'ять.

| Параметр / Характеристика | Пряме сортування вибором (Standard) | Двостороннє вибором (Min-Max) | Стійке сортування вибором (Stable) |
| :--- | :--- | :--- | :--- |
| **Часова складність (Найкращий)** | `Θ(N²)` | `Θ(N²)` | `Θ(N²)` |
| **Часова складність (Середній)** | `Θ(N²)` | `Θ(N²)` | `Θ(N²)` |
| **Часова складність (Найгірший)** | `Θ(N²)` | `Θ(N²)` | `Θ(N²)` |
| **Додаткова пам'ять (Space)** | `O(1)` (in-place) | `O(1)` (in-place) | `O(1)` (in-place) |
| **Кількість порівнянь (Exact)** | `(N² - N) / 2` | `≈ 0.375 · N²` | `(N² - N) / 2` |
| **Кількість обмінів / Записів** | `≤ N - 1` (Max `O(N)`) | `≤ N` (Max `O(N)`) | `O(N²)` (через зсуви) |
| **Стійкість (Stability)** | **Ні** (Unstable) | **Ні** (Unstable) | **Так** (Stable) |
| **Адаптивність (Adaptivity)** | Ні (фіксовані кроки) | Ні | Ні |

Текстовий аналіз параметрів складності:
- **Часова складність `Θ(N²)` у всіх випадках:** На відміну від Insertion Sort чи Bubble Sort, де найкращий випадок для відсортованого масиву становить `O(N)`, сортування вибором виконує фіксовану кількість порівнянь незалежно від стану вхідних даних.
- **Просторова складність `O(1)`:** Алгоритм не потребує виділення динамічної пам'яті у купі (`heap`). Увесь необхідний стан зберігається у двох локальних реєстрах процесора (`i` та `min_idx`), що робить алгоритм повністю безпечним для систем із суворим обмеженням обсягу стек-пам'яті (Stack Space < 256 байтів).
- **Кількість операцій перезапису в пам'ять `O(N)`:** Це основний інженерний показник для систем із пам'яттю типу Flash або EEPROM. Кількість перестановок елементів не перевищує `N - 1`.

## 3. Таблиця контрактів та формальних інваріантів

Формальний контракт сортування вибором визначає пре-умови, інваріанти виконання та пост-умови:

```
[Пре-умова (Precondition)]
- Масив A не є NULL (для C) або надано чинний span/діапазон ітераторів [first, last).
- Розмір масиву N >= 0.
- Елементи масиву порівнювані між собою через наданий компаратор (строгий частковий порядок).

[Інваріант циклу (Loop Invariant)]
- Перед кожною ітерацією i (0 <= i < N):
  1. A[0...i-1] містить i найменших елементів вхідного масиву.
  2. A[0...i-1] є відсортованим за незменшенням.
  3. Для всіх k in [0, i-1] та m in [i, N-1]: A[k] <= A[m].

[Пост-умова (Postcondition)]
- Для всіх i в діапазоні [0, N-2]: A[i] <= A[i+1].
- Масив A є перестановкою початкового масиву (збереження множини елементів).
- Загальна кількість фізичних записів у пам'ять <= N - 1 (для прямої версії).
```

Детальний текстовий розбір контрактних зобов'язань:
1. **Пре-умови:** Розробник зобов'язаний забезпечити чинність покажчиків пам'яті. Переданий компаратор повинен реалізовувати математичне відношення строгого слабкого порядку (Strict Weak Ordering): `cmp(a, a) == false`, якщо `cmp(a, b)` істинне, то `cmp(b, a)` хибне, а також транзитивність відношень.
2. **Інваріанти:** Гарантують, що на кожному кроці виконання префікс `A[0...i-1]` залишається строго найменшим і впорядкованим.
3. **Пост-умови:** Гарантують, що підсумковий масив впорядковано і що жодний елемент не був втрачений чи спотворений у процесі обмінів.

## 4. Інженерне керівництво для розробників вбудованих систем (Embedded Architect Guidelines)

### Коли слід застосовувати Selection Sort:
1. **Обмеження ресурсу перезапису флеш-пам'яті (Flash Memory Endurance):**
   У мікроконтролерах (AVR, STM32, ESP32), де таблиці конфігурацій чи калібрувальні коефіцієнти зберігаються безпосередньо у внутрішній EEPROM або NOR Flash пам'яті з обмеженим ресурсом у `10 000` — `100 000` циклів запису. Сортування вибором мінімізує кількість змін комірок до `N - 1`, продовжуючи термін служби пристрою на роки.
2. **Строгий детермінізм часу виконання (Hard Real-Time Systems):**
   У робототехніці, авіонійці та системному управління, де час виконання циклу сортування повинен бути строго передбачуваним. Алгоритм позбавлений "найгірших випадків" (Worst Case Penalty), характерних для QuickSort, де невдалий вибір опорного елемента вибухає до `O(N²)`.
3. **Захист від атак за сторонніми каналами (Side-Channel Security):**
   У криптографічних модулях, де вимірювання часу виконання сортування масиву не повинно розкривати інформацію про значення елементів чи секретні ключі (Execution Timing Side-Channel Analysis).
4. **Суворе обмеження обсягу стеку (Strict Stack Bound):**
   У мікроконтролерах з розміром оперативної пам'яті в кілька сотень байтів, де рекурсивні виклики QuickSort або виділення додаткового буфера Merge Sort призведуть до переповнення стеку (Stack Overflow) та фатального збою системи.

### Коли НЕ слід застосовувати Selection Sort:
1. **Великі масиви даних (`N > 100`):** Квадратична складність `O(N²)` робить алгоритм занадто повільним порівняно з логарифмічними алгоритмами (`O(N log N)`).
2. **Масиви з високим ступенем початкової впорядкованості:** Якщо дані часто приходять майже відсортованими, краще застосувати Insertion Sort, який відпрацює за лінійний час `O(N)`.
3. **Вимога стійкості без погіршення записів:** Якщо необхідно зберегти відносний порядок однакових елементів без збільшення операцій запису в пам'ять до `O(N²)`.
