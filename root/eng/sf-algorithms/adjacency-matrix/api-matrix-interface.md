# 📋 Інтерфейс та memory-layout матриці суміжності

Ця довідкова вставка містить повнофункціональну специфікацію програмного інтерфейсу (API), фізичні варіанти бітового та векторного розташування у пам'яті (Memory Layout), порівняльну таблицю складності операцій та аналіз специфічних значень-сентинелів матриці суміжності.

Матриця суміжності представляє граф `G = (V, E)` як двовимірну таблицю фіксованого розміру `N × N` (де `N = |V|`). Залежно від вимог до пам'яті, типів ребер та апаратних обмежень використовують кілька стандартних топологій розташування даних у пам'яті.

## 1. Варіанти розташування у пам'яті (Memory Layout Topologies)

У системному програмуванні спосіб розміщення елементів двовимірної матриці в одновимірному адресному просторі оперативної пам'яті розпинається між продуктивністю обходу, використанням кеш-ліній процесора та розміром споживаної пам'яті.

### 1.1. Неперервний плоский масив (Flat Row-Major 1D Array)

Основна топологія для високопродуктивних обчислень у мовах C та C++. Усі `N × N` елементів розміщуються в єдиній неперервній ділянці оперативної пам'яті.

* **Формула індексації**: `index(i, j) = i * N + j`
* **Обсяг пам'яті**: `N² × sizeof(T)` байтів (наприклад, для `double` при `N = 10 000` це 800 МБ).
* **Виділення пам'яті**: 1 системний виклик `malloc` або створення одного контейнера `std::vector<T>(N * N)`.
* **Апаратна перевага**: Відсутність фрагментації пам'яті. Послідовний доступ до рядка `i` гарантує 100% завантаження в L1/L2 кеш процесора завдяки системному апаратному префечеру (Hardware Prefetcher).

### 1.2. Упакована бітова матриця (Bit-Packed Matrix)

Для незважених (бінарних) графів кожне ребро позначається 1 бітом (`1` — ребро існує, `0` — відсутнє). 64 елементи рядка упаковуються в одне 64-бітне машинне слово (`uint64_t`).

* **Формула індексації**: 
  * Індекс 64-бітного слова у масиві: `word_index = (i * N + j) / 64`
  * Бітовий зсув усередині слова: `bit_offset = (i * N + j) % 64`
  * Маска перевірки: `bool exists = (data[word_index] & (1ULL << bit_offset)) != 0`
* **Обсяг пам'яті**: `⌈N² / 8⌉` байтів (у 8 разів менше за `uint8_t` і в 64 рази менше за `double`).
* **Апаратна перевага**: Можливість виконання бітових операцій `AND`, `OR`, `XOR` над 64 вершинами за 1 такт процесора; ідеально для SIMD-інструкцій (AVX2 / AVX-512).

### 1.3. Стиснута трикутна матриця (Packed Triangular Matrix)

Використовується для неорієнтованих графів без петель. Оскільки матриця суміжності неорієнтованого графа симетрична (`A[i][j] = A[j][i]`), а на діагоналі завжди нулі (`A[i][i] = 0`), достатньо зберігати лише нижній трикутник під головною діагоналлю.

* **Кількість елементів**: `N · (N - 1) / 2`
* **Формула індексації** (для `i > j`): `index(i, j) = i · (i - 1) / 2 + j`
* **Обсяг пам'яті**: Скорочується удвічі порівняно з повною матрицею: `(N² - N) / 2 × sizeof(T)`.
* **Мінуси**: Трохи складніша індексація з гілкуванням: якщо `i == j`, повертаємо `0`; якщо `i < j`, міняємо індекси місцями `swap(i, j)`.

### 1.4. Формат стиснутого рядка (CSR — Compressed Sparse Row)

Використовується як проміжний формат для розріджених графів великої розмірності (`N > 100 000`), коли повна матриця `N²` не вміщується у пам'ять, але потрібна висока швидкість матрично-векторного множення на графічних прискорювачах (GPU).

Формат CSR складається з трьох неперервних масивів:
1. `values[]`: Масив значень вагових коефіцієнтів усіх існуючих `M` ребер.
2. `col_indices[]`: Масив індексів стовпчиків відповідних ребер (розмір `M`).
3. `row_offsets[]`: Масив зміщень початків рядків у масиві `values` (розмір `N + 1`).

## 2. Специфікація публічного інтерфейсу (API Contract)

Нижче зведено стандартний контракт функцій та методів для роботи з матрицею суміжності у C та C++.

```c
/* Конструктор та деструктор графа */
AdjMatrix* adj_matrix_create(size_t vertices);

/* Аналітичні та алгоритмічні операції */
size_t adj_matrix_out_degree(const AdjMatrix* g, size_t u);
```

```cpp
template <typename T = double>
requires std::is_arithmetic_v<T>
class AdjacencyMatrix {
public:
    // Конструктор ініціалізації розміру графа
    explicit AdjacencyMatrix(std::size_t vertices);

    // Модифікатори графа
    void add_edge(std::size_t u, std::size_t v, T weight = T{1});
    void add_undirected_edge(std::size_t u, std::size_t v, T weight = T{1});
    void remove_edge(std::size_t u, std::size_t v);

    // Селектори та перевірки стану
    [[nodiscard]] bool has_edge(std::size_t u, std::size_t v) const;
    [[nodiscard]] std::optional<T> get_weight(std::size_t u, std::size_t v) const;
    [[nodiscard]] std::span<const T> get_row(std::size_t u) const;

    // Метрики вершин
    [[nodiscard]] std::size_t num_vertices() const noexcept;
    [[nodiscard]] std::size_t out_degree(std::size_t u) const;
    [[nodiscard]] std::size_t in_degree(std::size_t v) const;

    // Алгоритми аналізу
    [[nodiscard]] std::vector<T> compute_all_pairs_shortest_paths() const;
};
```

#### Опис методів класу C++:
* `get_row(u)`: Повертає безнаслідний перегляд `std::span<const T>` на неперервний рядок `u`. Дозволяє ітеруватися по всіх сусідках вершини без копіювання масиву.
* `get_weight(u, v)`: Повертає `std::optional<T>`, який містить вагу ребра при його наявності або `std::nullopt`, якщо ребра немає. Це позбавляє від використання небезпечних значень-сентинелів.

## 3. Таблиця порівняльної складності структур даних графів

У цій таблиці наведено асимптотичну складність за часом і пам'яттю для Матриці суміжності, Списку суміжності (Adjacency List), Матриці інцидентності та Списку ребер (Edge List). Позначення: `N = |V|` (вершини), `M = |E|` (ребра), `deg(v)` — степінь вершини `v`.

| Операція / Структура | Матриця суміжності (Flat bool) | Матриця (Packed Bitset) | Список суміжності (`std::vector`) | Список ребер (Edge List) |
| :--- | :--- | :--- | :--- | :--- |
| **Обсяг пам'яті (Space)** | `O(N²)` (байтів) | `O(N² / 8)` (байтів) | `O(N + M)` | `O(M)` |
| **Перевірка ребра (u, v)** | `O(1)` | `O(1)` | `O(deg(u))` або `O(log deg(u))` | `O(M)` |
| **Додавання ребра (u, v)** | `O(1)` | `O(1)` | `O(1)` | `O(1)` |
| **Видалення ребра (u, v)** | `O(1)` | `O(1)` | `O(deg(u))` | `O(M)` |
| **Перераховування всіх сусідів u** | `O(N)` | `O(N / 64)` | `O(deg(u))` | `O(M)` |
| **Додавання нової вершини** | `O(N²)` (перевиділення) | `O(N²)` | `O(1)` | `O(1)` |
| **Видалення вершини** | `O(N²)` (зсув елементів) | `O(N²)` | `O(N + M)` | `O(M)` |
| **Придатність до SIMD / GPU** | Відмінна | Екстремальна | Погана | Середня |

## 4. Вибір значень-сентинелів (Sentinel Values) для відсутніх ребер

Матриця суміжності вимагає заповнення всіх `N × N` комірок. Залежно від домену застосування обирають відповідні значення для позначення відсутності ребра:

1. **Незважені графи (Бінарні)**:
   * Наявність ребра: `1` або `true`
   * Відсутність ребра: `0` або `false`
   * Діагональ `A[i][i]`: `0` (якщо немає самопетлі)

2. **Зважені графи для алгоритмів найкоротших шляхів (Floyd-Warshall / Dijkstra)**:
   * Наявність ребра: `weight` (числове значення)
   * Відсутність ребра: `+∞` (`INFINITY` у C або `std::numeric_limits<T>::infinity()`)
   * Діагональ `A[i][i]`: `0.0` (найкоротший шлях з вершини в саму себе дорівнює 0)

3. **Графи максимального потоку (Max-Flow / Capacity Networks)**:
   * Наявність ребра: пропускна здатність `C[i][j] > 0`
   * Відсутність ребра: `0` (нульова пропускна здатність)

4. **Кореляційні та ймовірнісні графи**:
   * Наявність ребра: коефіцієнт від `-1.0` до `+1.0` або ймовірність від `0.0` до `1.0`.
   * Відсутність ребра: значення `NaN` (Not a Number) або маркери поза робочим діапазоном.

## 5. Граничні випадки та пастки реалізації

При розробці продуктового коду з використанням матриці суміжності слід враховувати такі крайові випадки:

* **Порожній граф (`N = 0`)**: Конструктор повинен коректно обробляти `N = 0`, виділяючи порожній масив або викидаючи виняток `std::invalid_argument`.
* **Самопетлі (Self-loops)**: Ребро `(i, i)` зберігається на головній діагоналі `A[i][i]`. Для алгоритмів кратних шляхів значення на діагоналі ініціалізують нулем `0`, а не нескінченністю, щоб запобігти хибним найкоротшим шляхам.
* **Мультиграфи (Multigraphs)**: Стандартна матриця суміжності не може зберігати кілька паралельних ребер між тими самими вершинами `i` та `j`. Для мультиграфів у комірці `A[i][j]` зберігають ціле число (лічильник ребер) замість прапорця.
* **Переповнення при від'ємних вагах**: У разі використання `+∞` у вигляді `INT_MAX`, додавання двох таких значень `INT_MAX + INT_MAX` у циклі Флойда — Уоршелла призведе до цілочисельного переповнення (*Integer Overflow*) та хибних від'ємних значень. Необхідно обов'язково перевіряти `if (ik != INF && kj != INF)` перед додаванням.
* **Перевиділення при розширенні (Dynamic Resizing Penalty)**: Додавання однієї вершини до матриці розміром `N × N` вимагає виділення нового блоку `(N+1)²` та копіювання `N²` елементів. Якщо граф активно змінює розмір під час виконання, використання матриці суміжності недоцільне.
