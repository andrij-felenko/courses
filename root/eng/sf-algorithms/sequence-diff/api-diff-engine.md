# 📋 Інтерфейс бібліотеки порівняння послідовностей

Бібліотека порівняння послідовностей надає модульний, високопродуктивний інтерфейс для зіставлення текстових файлів, масивів токенів та довільних структур даних у пам'яті. Інтерфейс дозволяє обирати алгоритм пошуку розбіжностей (Myers, Patience, Heckel, Histogram), налаштовувати фільтрацію пробільних символів, обмежувати максимальну глибину пошуку та генерувати структуровані фрагменти різниць (Hunks) в уніфікованому форматі.

## Архітектурні принципи та дизайн API

Публічний інтерфейс бібліотеки спроєктовано з дотриманням таких вимог:
1. **Відсутність зайвого копіювання пам'яті (Zero-Copy):** Усі структури результатів посилаються на оригінальні буфери вхідних даних через вказівники та довжини в C або `std::string_view` у C++. Рядки тексту не дублюються в динамічній пам'яті під час генерації проміжних структур.
2. **Повна потокобезпечність (Reentrancy):** Усі функції є чистими або приймають стан виключно через явно передані параметри. Бібліотека не містить глобальних змінних чи прихованого стану, що дозволяє виконувати паралельні порівняння сотень файлів у пулі потоків без блокувань (mutex).
3. **Передбачуваність споживання ресурсів:** Прапорець `max_edit_distance` у конфігурації дозволяє встановити жорстку межу кількості допустимих відмінностей. Якщо файли виявляються повністю незбіжними (наприклад, випадково порівнюються два велетенські бінарні файли), алгоритм гарантовано перериває роботу, запобігаючи вичерпанню оперативної пам'яті та зависанню процесора.

## Вибір алгоритмічної стратегії

Бібліотека надає чотири взаємодоповнюючі алгоритми порівняння, кожен з яких оптимізований під конкретний клас задач:

- **Myers (`DIFF_ALGO_MYERS`):** Стандартний алгоритм пошуку найкоротшого сценарію редагування за час `O((N + M) · D)`. Рекомендований як універсальний вибір для генерації компактних патчів, де критичним є мінімальний сумарний обсяг вставок і видалень.
- **Patience (`DIFF_ALGO_PATIENCE`):** Алгоритм на основі найдовшої зростаючої підпослідовності унікальних рядків. Рекомендований для систем перегляду коду (Code Review) та інструментів злиття (3-way merge), оскільки він фіксує синтаксичні каркаси (сигнатури функцій, оголошення типів) і не плутає однакові закривальні дужки чи порожні рядки.
- **Histogram (`DIFF_ALGO_HISTOGRAM`):** Оптимізована модифікація Patience diff, що використовує локальні гістограми частот і обирає як опорні точки рядки з найменшою частотою появи. Працює швидше за класичний Patience на великих файлах із повторюваними сигнатурами.
- **Heckel (`DIFF_ALGO_HECKEL`):** Лінійний алгоритм ізоляції унікальних блоків за час `O(N + M)`. Рекомендований для задач виявлення масштабного рефакторингу (перенесення цілих функцій чи файлових блоків) та графічних підсистем оновлення термінальних вікон (`ncurses`).

## Публічні типи та структури даних

### Переліки алгоритмів та операцій

:::tabs
```c
/* Доступні алгоритми порівняння */
typedef enum {
    DIFF_ALGO_MYERS     = 0, /* Класичний O(ND) алгоритм Маєрса (мінімальний розмір diff) */
    DIFF_ALGO_PATIENCE  = 1, /* Patience diff (семантично чисті межі функцій та блоків) */
    DIFF_ALGO_HISTOGRAM = 2, /* Histogram diff (швидка оптимізована версія Patience) */
    DIFF_ALGO_HECKEL    = 3  /* Лінійний алгоритм Гекеля з виявленням переміщень блоків */
} diff_algo_t;

/* Тип операції над елементом послідовності */
typedef enum {
    DIFF_OP_KEEP   = 0, /* Рядок збережено без змін (контекстний рядок) */
    DIFF_OP_INSERT = 1, /* Новий рядок додано до ревізії B */
    DIFF_OP_DELETE = 2  /* Старий рядок вилучено з ревізії A */
} diff_op_t;

/* Коди помилок бібліотеки */
typedef enum {
    DIFF_OK               =  0, /* Успішне виконання */
    DIFF_ERR_INVALID_ARG  = -1, /* Некоректні вхідні аргументи (NULL вказівник або некоректні прапорці) */
    DIFF_ERR_NO_MEMORY    = -2, /* Помилка виділення динамічної пам'яті */
    DIFF_ERR_LIMIT_EXCEED = -3  /* Перевищено ліміт правок D_max або розмір послідовності */
} diff_error_t;
```
```cpp
namespace diff {

enum class Algorithm : uint8_t {
    Myers,      // Класичний O(ND) алгоритм Маєрса
    Patience,   // Patience diff (LIS унікальних рядків)
    Histogram,  // Histogram diff (низькочастотні опорні точки)
    Heckel      // Алгоритм Гекеля з підтримкою переміщень блоків
};

enum class Operation : uint8_t {
    Keep,   // Рядок без змін
    Insert, // Додавання
    Delete  // Видалення
};

enum class ErrorCode : int32_t {
    Ok = 0,
    InvalidArgument = -1,
    OutOfMemory = -2,
    LimitExceeded = -3
};

} // namespace diff
```

### Структури конфігурації та дескриптори фрагментів

Конфігурація задає правила нормалізації тексту, кількість рядків контексту довкола змін та обмеження ресурсомісткості. Фрагмент (`diff_hunk_t` / `diff::Hunk`) описує неперервну групу змінених рядків, обрамлену рядками контексту.

:::tabs
```c
/* Налаштування процесу порівняння */
typedef struct {
    diff_algo_t algorithm;      /* Обраний алгоритм порівняння */
    size_t context_lines;       /* Кількість рядків контексту довкола змін (типово 3) */
    bool ignore_whitespace_eol; /* Ігнорувати пробільні символи в кінці рядка */
    bool ignore_all_whitespace; /* Ігнорувати всі пробільні символи */
    size_t max_edit_distance;   /* Граничне значення D (0 — без обмежень) */
} diff_config_t;

/* Окремий рядок у структурованому фрагменті diff */
typedef struct {
    diff_op_t op;
    size_t old_line_num; /* 1-індексований номер рядка у файлі A (0 для вставки) */
    size_t new_line_num; /* 1-індексований номер рядка у файлі B (0 для видалення) */
    const char* text;    /* Вказівник на початок тексту рядка */
    size_t length;       /* Довжина рядка в байтах */
} diff_line_entry_t;

/* Структурований фрагмент різниць (Hunk) */
typedef struct {
    size_t old_start;           /* Початковий рядок у файлі A */
    size_t old_count;           /* Кількість рядків з файлу A у фрагменті */
    size_t new_start;           /* Початковий рядок у файлі B */
    size_t new_count;           /* Кількість рядків з файлу B у фрагменті */
    diff_line_entry_t* entries; /* Масив рядків фрагмента */
    size_t entry_count;         /* Кількість елементів у масиві entries */
} diff_hunk_t;

/* Повний результат порівняння */
typedef struct {
    diff_hunk_t* hunks;         /* Масив фрагментів */
    size_t hunk_count;          /* Кількість фрагментів */
    size_t total_deletions;     /* Загальна кількість видалених рядків */
    size_t total_insertions;    /* Загальна кількість доданих рядків */
    size_t edit_distance;       /* Обчислена редакторська відстань D */
} diff_result_t;
```
```cpp
namespace diff {

struct Config {
    Algorithm algorithm{Algorithm::Myers};
    size_t context_lines{3};
    bool ignore_whitespace_eol{false};
    bool ignore_all_whitespace{false};
    size_t max_edit_distance{0}; // 0 = без обмежень
};

struct LineEntry {
    Operation op{Operation::Keep};
    size_t old_line_num{0};
    size_t new_line_num{0};
    std::string_view text;
};

struct Hunk {
    size_t old_start{0};
    size_t old_count{0};
    size_t new_start{0};
    size_t new_count{0};
    std::vector<LineEntry> entries;
};

struct Result {
    std::vector<Hunk> hunks;
    size_t total_deletions{0};
    size_t total_insertions{0};
    size_t edit_distance{0};
};

} // namespace diff
```

## Опис функцій публічного інтерфейсу

### 1. Ініціалізація конфігурації
- `void diff_config_init_default(diff_config_t* config)`: Заповнює структуру `config` безпечними типовими значеннями: алгоритм Маєрса (`DIFF_ALGO_MYERS`), 3 рядки контексту довкола змін, збереження пробілів без модифікацій, відсутність обмежень на `max_edit_distance`.
- У C++ конструктор за замовчуванням `diff::Config{}` виконує еквівалентну ініціалізацію всіх полів структури.

### 2. Порівняння текстових буферів
- `diff_error_t diff_compare_buffers(...)`: Приймає вказівники на два текстові буфери, їхні довжини в байтах та конфігурацію. Функція розбиває текст на рядки, обчислює розбіжності згідно з обраним алгоритмом, групує зміни у фрагменти `hunks` з урахуванням рядків контексту та повертає заповнену структуру `diff_result_t` через вихідний параметр `out_result`.
- `std::expected<Result, ErrorCode> diff::Engine::compare(...)`: Сучасний ідіоматичний C++20 метод, який повертає об'єкт `Result` або типізований код помилки без генерації винятків.

### 3. Форматування та експорт
- `diff_error_t diff_format_unified(...)`: Генерує текстовий потік у стандартному форматі Unified Diff (з заголовками `--- a/...`, `+++ b/...` та мітками фрагментів `@@ -l,s +l,s @@`). Виділяє новий динамічний буфер `out_string`, який клієнт повинен звільнити викликом `diff_free_string`.
- `std::string diff::Engine::format_unified(...)`: Статичний метод, що повертає готовий об'єкт `std::string`.

### 4. Керування пам'яттю
- `void diff_free_result(diff_result_t* result)`: Рекурсивно звільняє всі внутрішні масиви фрагментів `hunks`, записи рядків `entries` та саму кореневу структуру результату.
- `void diff_free_string(char* str)`: Звільняє буфер, виділений функцією форматування.

## Обробка пробільних символів та бінарних даних

Бібліотека містить вбудовані фільтри нормалізації перед обчисленням хешів рядків:
- **`ignore_whitespace_eol = true`:** Відсікає кінцеві пробіли та символи табуляції перед кінцем рядка. Це запобігає появі зайвих фрагментів у diff через випадкове автоформатування редакторами коду.
- **`ignore_all_whitespace = true`:** Ігнорує будь-яку зміну пробільних символів всередині рядка (включаючи заміну пробілів на табуляцію або зміну відступів indentation).
- **Виявлення бінарних даних:** Якщо у перших 8192 байтах вхідного буфера виявлено нульовий байт (`\0`), бібліотека ідентифікує файл як бінарний і перериває посимвольне порівняння, повертаючи спеціальну мітку `Binary files differ` замість створення велетенського текстового diff.

## Повний приклад інтеграції бібліотеки

Нижче наведено робочий приклад виклику бібліотечного API для порівняння двох рядків та обробки результатів.

:::tabs
```c
#include <stdio.h>
#include <string.h>

void run_diff_example(void) {
    const char* text_old = "int main() {\n    printf(\"Hello\\n\");\n    return 0;\n}\n";
    const char* text_new = "int main() {\n    puts(\"Hello, World!\");\n    return 0;\n}\n";

    diff_config_t cfg;
    diff_config_init_default(&cfg);
    cfg.algorithm = DIFF_ALGO_MYERS;
    cfg.context_lines = 2;

    diff_result_t* res = NULL;
    diff_error_t err = diff_compare_buffers(
        text_old, strlen(text_old),
        text_new, strlen(text_new),
        &cfg, &res
    );

    if (err != DIFF_OK) {
        fprintf(stderr, "Помилка порівняння: код %d\n", err);
        return;
    }

    char* formatted = NULL;
    size_t fmt_len = 0;
    if (diff_format_unified(res, "a/main.c", "b/main.c", &formatted, &fmt_len) == DIFF_OK) {
        printf("%s\n", formatted);
        diff_free_string(formatted);
    }

    diff_free_result(res);
}
```
```cpp
#include <iostream>

void run_diff_example_cpp() {
    constexpr std::string_view text_old = "int main() {\n    printf(\"Hello\\n\");\n    return 0;\n}\n";
    constexpr std::string_view text_new = "int main() {\n    puts(\"Hello, World!\");\n    return 0;\n}\n";

    diff::Config cfg{
        .algorithm = diff::Algorithm::Myers,
        .context_lines = 2
    };

    diff::Engine engine(cfg);
    auto res = engine.compare(text_old, text_new);

    if (!res) {
        std::cerr << "Помилка порівняння: код " << static_cast<int>(res.error()) << '\n';
        return;
    }

    std::string patch = diff::Engine::format_unified(*res, "a/main.c", "b/main.c");
    std::cout << patch << '\n';
}
```

## Інваріанти та гарантії викликів

1. **Життєвий цикл пам'яті:** Текстові вказівники `text` у структурах `diff_line_entry_t` та `std::string_view` посилаються безпосередньо на вхідні буфери `text_a` та `text_b`. Вхідні буфери повинні залишатися незмінними та доступними протягом усього життєвого циклу структури `diff_result_t` / `diff::Result`. Звільнення або мутація вхідних буферів до виклику `diff_free_result` призводить до невизначеної поведінки (Use-After-Free).
2. **Гарантія граничного часу та захист від атак (ReDoS/Algorithmic Complexity):** Якщо задано `config.max_edit_distance > 0`, алгоритм гарантовано перериває пошук і повертає `DIFF_ERR_LIMIT_EXCEED`, якщо кількість правок перевищує вказаний поріг. Це унеможливлює зависання сервера або сервісу контролю версій при спробі обробити штучно сконструйовані файли з максимальним рівнем розбіжностей.
3. **Гарантія нульового динамічного виділення на гарячому шляху:** Під час токенізації та хешування рядків усі проміжні обчислення виконуються в єдиному попередньо виділеному векторному буфері. Хеш-таблиця інтернування рядків не створює окремих дрібних вузлів у динамічній пам'яті, що мінімізує накладні витрати системного алокатора `malloc`.

## Конвеєр обробки даних (Data Processing Pipeline)

Внутрішня архітектура функції `diff_compare_buffers` організована у вигляді послідовного п'ятистадійного конвеєра:

1. **Стадія 1 (Сканування та валідація):** Перевірка вхідних вказівників на `NULL`, валідація розмірів буферів та швидка перевірка на наявність нульових байтів (виявлення двійкових файлів).
2. **Стадія 2 (Швидке відсікання збігів):** Побайтове сканування спільного префікса та суфікса від країв файлів за час `O(min(N, M))`. Якщо файли мають ідентичні шапки або підвали (наприклад, незмінені ліцензійні коментарі чи стандартні завершення), вони виключаються з подальшого графа пошуку.
3. **Стадія 3 (Хешування залишку):** Обчислення 64-бітних FNV-1a хешів для рядків середньої частини файлів, що залишилися після відсікання.
4. **Стадія 4 (Виконання обраного алгоритму):** Запуск алгоритму Маєрса, Patience, Histogram або Гекеля над числовими масивами хешів.
5. **Стадія 5 (Агрегація фрагментів Hunk):** Об'єднання елементарних операцій редагування у змістові фрагменти з додаванням `context_lines` незмінених рядків, злиття сусідніх фрагментів, що перекриваються за контекстом, та формування підсумкової структури `diff_result_t`.

## Стратегія відновлення при помилках

При отриманні помилки `DIFF_ERR_LIMIT_EXCEED` клієнтський додаток може застосувати каскадний фолбек (Fallback Strategy):
- Переключити алгоритм з Myers на лінійний `DIFF_ALGO_HECKEL` або `DIFF_ALGO_HISTOGRAM`, які гарантують лінійний час виконання навіть на повністю незбіжних даних.
- Збільшити гранулярність порівняння: замість посимвольного або порядкового аналізу розбити файл на більші блоки (наприклад, функції або абзаци).
- Повідомити користувача про надмірний обсяг змін та запропонувати бінарне або повносторінкове оновлення файлу.
