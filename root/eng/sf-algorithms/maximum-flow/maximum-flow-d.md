Якщо в магістральній мережі водопостачання або каналі передачі пакетів даних жадібно спрямувати потік уздовж першого-ліпшого доступного маршруту, система ризикує заблокувати значно потужніші паралельні магістралі й вичерпати свою пропускну здатність задовго до досягнення справжнього максимуму. Розглянемо мережу з чотирма вузлами: джерело `s` з'єднане з проміжними вузлами `u` та `v` каналами місткістю по 100 одиниць, стік `t` підключений до `u` та `v` каналами такої ж місткості 100, а між `u` та `v` прокладено поперечну перемичку місткістю 100, спрямовану від `u` до `v`. Якщо алгоритм на першому ж кроці наївно обере центральний Z-подібний маршрут `s → u → v → t` і проштовхне по ньому 100 одиниць, перемичка `(u, v)` виявиться повністю насиченою, а прямі канали `(u, t)` та `(s, v)` залишаться заблокованими через відсутність надходження у вузол `u` та неможливість виходу з вузла `v`. У результаті жадібний підхід зупиниться на сумарному потоці 100 одиниць, тоді як оптимальне одночасне завантаження двох незалежних шляхів `s → u → t` та `s → v → t` забезпечує передачу 200 одиниць.

Головна причина невдачі локальних евристик полягає у відсутності механізму відкату: прийнявши субоптимальне рішення про маршрутизацію, система втрачає спосіб повернути частину речовини назад або переспрямувати її в інше русло. 

Фундаментальна задача про максимальний потік (Maximum Flow Problem) полягає в знаходженні такого розподілу речовини, енергії або інформації від витоку до споживача, який максимізує сумарну пропускну здатність мережі без перевантаження окремих каналів та без виникнення заторів у проміжних вузлах ([детальніше про історію відкриття та секретний звіт RAND Corporation див. історичну вставку](root:sf-algorithms/maximum-flow/hist-ford-fulkerson-origins.md)).

## Модель потокової мережі та фізичні закони

Потокова мережа формалізується як орієнтований граф `G = (V, E)` без петель. Кожному ребру `(u, v) ∈ E` зіставляється невід'ємне число — **пропускна спроможність** або **місткість** (від лат. *capacitas* — місткість, здатність уміщати) `c(u, v) ≥ 0`, яка визначає граничний обсяг речовини, що може пройти через цей канал за одиницю часу. Якщо ребро між вершинами відсутнє, вважають `c(u, v) = 0`.

У графі виділяються два спеціальні полюси:
- **Джерело** `s ∈ V` (Source / витік) — вузол, у якому потік генерується і з якого витікає в мережу. Джерело не має вхідних обмежень від зовнішнього середовища.
- **Стік** `t ∈ V` (Sink / стік, споживач) — вузол, у якому потік поглинається (`s ≠ t`). Стік здатний приймати необмежений обсяг речовини, що надходить із мережі.

**Потоком** (від прасл. *tekti* — литися, бігти) у мережі називається дійсна функція `f: V × V → ℝ`, яка призначає кожній парі вершин величину `f(u, v)` і строго задовольняє два фізичні закони:

1. **Обмеження місткості (Capacity Constraint):** Потік уздовж будь-якого каналу не може бути від'ємним і не може перевищувати пропускної спроможності цього каналу:
```
0 ≤ f(u, v) ≤ c(u, v)  для всіх (u, v) ∈ V × V
```

2. **Закон збереження потоку (Flow Conservation / Перший закон Кірхгофа):** Для будь-якого проміжного вузла `u ∈ V \ {s, t}` сумарний обсяг потоку, що входить у вершину, строго дорівнює сумарному обсягу потоку, що виходить із неї:
```
∑_{v ∈ V} f(v, u) = ∑_{w ∈ V} f(u, w)
```
У проміжних вузлах речовина не створюється, не накопичується і не зникає. Якщо у вузол надійшло 50 літрів рідини або 50 гігабіт трафіку, рівно 50 літрів або 50 гігабіт мають вийти з нього через вихідні канали.

**Величина потоку** `|f|` (Value of Flow) визначається як сумарний чистий потік, що виходить із джерела `s`:
```
|f| = ∑_{v ∈ V} f(s, v) - ∑_{v ∈ V} f(v, s)
```
Через закон збереження потоку ця величина строго дорівнює чистому потоку, що входить у стік `t`:
```
|f| = ∑_{u ∈ V} f(u, t) - ∑_{u ∈ V} f(t, u)
```

Задача оптимізації полягає в знаходженні допустимого потоку `f*`, для якого величина `|f*|` досягає теоретичного максимуму:
```
|f*| = max |f|
```

> 🔧 **Навіщо це в реальній інженерії.**
> Окрім очевидних задач гідравліки, транспортування нафти та логістики вантажоперевезень, алгоритми максимального потоку є основою оптимізації пропускної здатності в комп'ютерних мережах (SDN, BGP Traffic Engineering), розподілу завдань між серверами кластера, балансування навантаження в дата-центрах та вилучення об'єктів на зображеннях у реальному часі.

## Залишкова мережа та механізм перенаправлення

Для подолання глухих кутів жадібного вибору Форд і Фалкерсон ввели концепцію **залишкової мережі** (Residual Network) `G_f = (V, E_f)`. Залишкова мережа показує не просто наявний потік, а точний простір усіх можливих змін поточного стану: скільки ще можна додати по кожній прямій дузі та скільки можна скасувати по кожній завантаженій дузі.

Для кожної пари вершин `(u, v)` **залишкова пропускна спроможність** `c_f(u, v)` визначається за формулою:
```
c_f(u, v) = c(u, v) - f(u, v) + f(v, u)
```

У мережах без взаємно зворотних дуг це правило природно розпадається на два випадки:
1. **Пряме ребро `(u, v) ∈ E`:** має залишок `c_f(u, v) = c(u, v) - f(u, v)`. Це вільна місткість каналу, яку ще можна заповнити додатковим прямим потоком.
2. **Зворотне ребро `(v, u)` (де `(u, v) ∈ E`):** має залишок `c_f(v, u) = f(u, v)`. Це можливість зменшити або повністю скасувати раніше спрямований прямий потік.

![Залишкова мережа та механізм перенаправлення](/root/eng/sf-algorithms/maximum-flow/img/residual-graph-concept.svg)
*Концепція залишкової мережі: прямі дуги несуть вільний залишок місткості c(e) - f(e), а зворотні дуги місткістю f(e) дозволяють алгоритму скасовувати та перенаправляти потік.*

Зворотне ребро є математичним еквівалентом операції скасування (Undo). Якщо по каналу `u → v` уже протікає 10 одиниць, то проштовхування 4 одиниць уздовж фіктивної зворотної дуги `v → u` в залишковій мережі не означає фізичного руху рідини назад. Воно означає зменшення прямого потоку `f(u, v)` з 10 до 6 одиниць, а ті 4 одиниці, які раніше йшли з `u` у `v`, тепер перенаправляються в інший вихідний канал вершини `u`.

**Розширювальним шляхом** (Augmenting Path) називається будь-який простий орієнтований шлях `P` від джерела `s` до стоку `t` у залишковій мережі `G_f`, усі ребра якого мають строго додатну залишкову місткість `c_f(u, v) > 0`.

**Пляшковим горлом** (Bottleneck Capacity) шляху `P` називається мінімальна залишкова місткість серед усіх його дуг:
```
Δ = min_{(u, v) ∈ P} c_f(u, v) > 0
```

Процедура збільшення потоку (Augmentation) модифікує потік уздовж шляху `P` на величину `Δ`:
```
f(u, v) = f(u, v) + Δ,  якщо (u, v) — пряме ребро на шляху P
f(u, v) = f(u, v) - Δ,  якщо (v, u) — зворотне ребро на шляху P
```
Після кожного такого кроку новий потік залишається фізично допустимим, а його загальна величина зростає строго на `Δ`: `|f_new| = |f_old| + Δ`.

## Теорема Форда — Фалкерсона про максимальний потік і мінімальний розріз

Центральним теоретичним фундаментом усієї теорії потоків є теорема про еквівалентність максимального потоку та мінімального розрізу.

**Розрізом мережі** `(S, T)` (s-t Cut; від прасл. *rězati* — ділити, сікти) називається розбиття множини всіх вершин `V` на дві неперетинні частини `S` та `T = V \ S` такі, що джерело належить першій частині (`s ∈ S`), а стік — другій (`t ∈ T`).

**Пропускною спроможністю розрізу** `c(S, T)` називається сума місткостей усіх дуг вихідної мережі, що починаються у множині `S` і входять у множину `T`:
```
c(S, T) = ∑_{u ∈ S, v ∈ T} c(u, v)
```
Місткості зворотних дуг (із `T` в `S`) до пропускної спроможності розрізу не включаються.

![Теорема про максимальний потік і мінімальний розріз](/root/eng/sf-algorithms/maximum-flow/img/max-flow-min-cut.svg)
*Теорема Форда — Фалкерсона: максимальний потік через мережу досягається тоді й тільки тоді, коли всі прямі дуги через деякий розріз (S, T) повністю насичені (c_f = 0), а всі зворотні дуги мають нульовий потік.*

### Слабка та сильна дуальність

Між потоками та розрізами існують дві фундаментальні закономірності:

1. **Лема про збереження потоку через розріз:** Для будь-якого допустимого потоку `f` та будь-якого розрізу `(S, T)` чистий потік із `S` у `T` строго дорівнює повній величині потоку `|f|`:
```
f(S, T) = ∑_{u ∈ S, v ∈ T} f(u, v) - ∑_{u ∈ S, v ∈ T} f(v, u) = |f|
```

2. **Слабка дуальність (Weak Duality):** Оскільки потік по кожному ребру обмежений його місткістю (`f(u, v) ≤ c(u, v)`), а зворотний потік невід'ємний (`f(v, u) ≥ 0`), величина будь-якого допустимого потоку ніколи не перевищує місткості довільного розрізу:
```
|f| ≤ c(S, T)  для будь-якого f та будь-якого (S, T)
```

Звідси випливає фундаментальна теорема:

> **Теорема Форда — Фалкерсона (Max-Flow Min-Cut Theorem):**
> Для будь-якої потокової мережі величина максимального потоку від `s` до `t` строго дорівнює мінімальній пропускній спроможності серед усіх розрізів, що відокремлюють `s` від `t`:
> ```
> max |f| = min c(S, T)
> ```

При цьому такі три твердження є абсолютно рівносильними:
1. Потік `f` є максимальним у мережі `G`.
2. У залишковій мережі `G_f` не існує жодного розширювального шляху від `s` до `t`.
3. Існує розріз `(S, T)` такий, що `|f| = c(S, T)`.

### Конструктивне знаходження мінімального розрізу

Коли в залишковій мережі `G_f` більше не залишається шляхів від джерела до стоку, множина вершин `S` визначається як множина всіх вершин `v ∈ V`, які є досяжними з джерела `s` по ребрах із додатним залишком `c_f > 0` (за допомогою звичайного BFS або DFS). Решта вершин утворюють множину `T = V \ S`.

Оскільки стік `t` недосяжний, `t ∈ T`. Усі прямі дуги з `S` у `T` виявляються повністю насиченими (`f(u, v) = c(u, v)`), а всі зворотні дуги з `T` у `S` — повністю порожніми (`f(v, u) = 0`). Це дає точний мінімальний розріз мережі ([повне строге математичне виведення лем та теореми див. у вставці](root:sf-algorithms/maximum-flow/math-max-flow-min-cut.md)).

## Загальний метод Форда — Фалкерсона та алгоритм Едмондса — Карпа

Класичний метод Форда — Фалкерсона (1956) формулюється як загальна ітеративна схема:
1. Ініціалізувати нульовий потік `f(u, v) = 0` для всіх ребер.
2. Поки в залишковій мережі `G_f` існує розширювальний шлях `P` від `s` до `t`:
   - Знайти `Δ = min_{(u, v) ∈ P} c_f(u, v)`.
   - Збільшити потік уздовж `P` на `Δ`.
   - Оновити залишкові місткості в `G_f`.
3. Повернути накопичений потік `f`.

Проте метод не фіксує, як саме шукати розширювальний шлях. Якщо використовувати довільний пошук у глибину (DFS), метод демонструє дві критичні вади:
- **Псевдополіноміальна складність `O(E · |f*|)`:** На цілих числах невдалий вибір шляхів (як у прикладі з перемичкою 1) може збільшувати потік лише на 1 одиницю за крок, вимагаючи мільйонів ітерацій для великих пропускних спроможностей.
- **Розбіжність на ірраціональних числах:** Для дійсних ірраціональних місткостей нескінченна послідовність аугментацій може збігатися до числа, меншого за справжній максимум.

### Поліноміальний прорив Едмондса — Карпа (1972)

Джек Едмондс та Річард Карп довели, що якщо на кожному кроці шукати розширювальний шлях за допомогою **пошуку в ширину (BFS)**, обираючи шлях із **найменшою кількістю ребер**, алгоритм стає строго поліноміальним.

![Алгоритм Едмондса — Карпа та вибір найкоротшого шляху](/root/eng/sf-algorithms/maximum-flow/img/edmonds-karp-bfs.svg)
*Алгоритм Едмондса — Карпа: вибір найкоротшого шляху через BFS гарантує монотонне незменшення відстаней у залишковій мережі та обмежує кількість аугментацій величиною O(V · E).*

Математичне обґрунтування спирається на дві фундаментальні властивості:

1. **Монотонність відстаней:** Під час кожної аугментації вздовж найкоротшого шляху відстань `dist_{G_f}(s, v)` (у кількості ребер) від джерела до будь-якої вершини `v` у залишковій мережі монотонно не зменшується.
2. **Обмеження на критичні ребра:** Ребро `(u, v)` називається критичним, якщо воно є пляшковим горлом шляху і після аугментації повністю насичується (`c_f = 0`), зникаючи з `G_f`. Щоб це ребро знову з'явилося в залишковій мережі, потік мусить бути проштовхнутий у зворотному напрямку `(v, u)`. Але між двома такими подіями найкоротша відстань від `s` до `u` збільшується щонайменше на 2 одиниці:
```
dist_{нова}(s, u) ≥ dist_{стара}(s, u) + 2
```
Оскільки довжина простого шляху не перевищує `|V| - 1`, кожне з `|E|` ребер може ставати критичним не більше `|V| / 2` разів.

Звідси випливають строгі часові оцінки:
- Загальна кількість аугментацій за весь час роботи алгоритму обмежена величиною `O(V · E)`.
- Кожен пошук найкоротшого шляху через BFS виконується за час `O(E)`.
- Підсумкова часова складність алгоритму Едмондса — Карпа становить:
```
Час_EdmondsKarp = O(V · E) · O(E) = O(V · E²)
```
Складність повністю детермінована топологією графа і взагалі не залежить від величини чисел у пропускних спроможностях.

## Покроковий числовий приклад розрахунку мережі

Розглянемо виконання алгоритму Едмондса — Карпа на мережі з 6 вершинами `V = {0, 1, 2, 3, 4, 5}`, де джерело `s = 0`, стік `t = 5`, а орієнтовані ребра мають такі початкові місткості:
- `(0, 1): 10`, `(0, 2): 10`
- `(1, 2): 2`, `(1, 3): 4`, `(1, 4): 8`
- `(2, 4): 9`
- `(3, 5): 10`, `(4, 5): 10`

Початковий потік у всіх ребрах дорівнює нулю: `|f| = 0`.

### Ітерація 1
1. **BFS від джерела 0:** знаходить найкоротший шлях за кількістю ребер `0 → 1 → 3 → 5` (довжина 3 ребра).
2. Залишкові місткості на знайденому шляху:
   - `c_f(0, 1) = 10`
   - `c_f(1, 3) = 4`
   - `c_f(3, 5) = 10`
3. Пляшкове горло: `Δ₁ = min(10, 4, 10) = 4`.
4. Проштовхування потоку:
   - `f(0, 1) = 4`, `f(1, 3) = 4` (насичено!), `f(3, 5) = 4`.
   - Залишки: `c_f(0, 1) = 6`, `c_f(1, 3) = 0`, `c_f(3, 5) = 6`.
   - Зворотні залишки: `c_f(1, 0) = 4`, `c_f(3, 1) = 4`, `c_f(5, 3) = 4`.
   - Поточний сумарний потік: `|f| = 4`.

### Ітерація 2
1. **BFS від джерела 0:** ребро `(1, 3)` насичене (`c_f = 0`), тому BFS обирає альтернативний шлях довжини 3: `0 → 1 → 4 → 5`.
2. Залишкові місткості на знайденому шляху:
   - `c_f(0, 1) = 6`
   - `c_f(1, 4) = 8`
   - `c_f(4, 5) = 10`
3. Пляшкове горло: `Δ₂ = min(6, 8, 10) = 6`.
4. Проштовхування потоку:
   - `f(0, 1) = 4 + 6 = 10` (насичено!), `f(1, 4) = 6`, `f(4, 5) = 6`.
   - Залишки: `c_f(0, 1) = 0`, `c_f(1, 4) = 2`, `c_f(4, 5) = 4`.
   - Поточний сумарний потік: `|f| = 4 + 6 = 10`.

### Ітерація 3
1. **BFS від джерела 0:** ребро `(0, 1)` насичене, тому BFS стартує через вершину 2: `0 → 2 → 4 → 5` (довжина 3 ребра).
2. Залишкові місткості на знайденому шляху:
   - `c_f(0, 2) = 10`
   - `c_f(2, 4) = 9`
   - `c_f(4, 5) = 10 - 6 = 4`
3. Пляшкове горло: `Δ₃ = min(10, 9, 4) = 4`.
4. Проштовхування потоку:
   - `f(0, 2) = 4`, `f(2, 4) = 4`, `f(4, 5) = 6 + 4 = 10` (насичено!).
   - Залишки: `c_f(0, 2) = 6`, `c_f(2, 4) = 5`, `c_f(4, 5) = 0`.
   - Поточний сумарний потік: `|f| = 10 + 4 = 14`.

### Ітерація 4
1. **BFS від джерела 0:** усі шляхи до стоку довжиною 3 заблоковані (`(3, 5)` недосяжний, `(4, 5)` насичене).
2. Проте залишається довший шлях через зворотну дугу: `0 → 2 → 4 → 1` (якщо є залишок) або альтернативний обхід. Оскільки вихід із 4 на стік 5 повністю насичений, стік виявляється недосяжним.
3. BFS завершується без досягнення стоку: черга порожня, `visited[5] == false`.
4. **Зупинка алгоритму.** Максимальний потік дорівнює **14**.

### Вилучення мінімального розрізу
Вершини, досяжні з джерела 0 в останньому BFS у залишковій мережі `G_f`:
- З 0 доступна вершина 2 (залишок `c_f(0, 2) = 6`).
- З 2 доступна вершина 4 (залишок `c_f(2, 4) = 5`).
- З 4 доступна вершина 1 через зворотне ребро `(1, 4)` (по ньому був потік 6, отже `c_f(4, 1) = 6`).
- Отже, множина досяжності: `S = {0, 1, 2, 4}`.
- Множина стоку: `T = V \ S = {3, 5}`.

Перевірка пропускної спроможності розрізу `c(S, T)`:
- Прямі дуги з `S` у `T`: `(1, 3)` місткістю 4 та `(4, 5)` місткістю 10.
- `c(S, T) = c(1, 3) + c(4, 5) = 4 + 10 = 14`.
- Рівність `|f*| = c(S, T) = 14` строго підтверджує коректність знайденого оптимуму.

## Моделювання та канонічні зведення задач

Задача про максимальний потік є універсальним обчислювальним рушієм. Десятки практичних проблем комбінаторної оптимізації розв'язуються зведенням до стандартного s-t потоку через прості структурні трансформації графа (Gadgets).

![Канонічні зведення задач до максимального потоку](/root/eng/sf-algorithms/maximum-flow/img/reductions-gadgets.svg)
*Конструктивні зведення задач: (1) розщеплення вершин для обмеження їхньої місткості; (2) суперджерело та суперстік для багатьох терміналів; (3) двочасткове паросполучення з одиничними вагами.*

### 1. Пропускна спроможність вершин (Node Capacities)
Якщо кожен вузол `v` має обмеження на максимальний транзитний обсяг `c(v)`:
- Кожна вершина `v` розщеплюється на дві: вхідну `v_{in}` та вихідну `v_{out}`.
- Між ними додається спрямоване внутрішнє ребро `(v_{in}, v_{out})` із пропускною спроможністю `c(v)`.
- Усі початкові дуги, що входили у `v`, перенаправляються у `v_{in}`. Усі дуги, що виходили з `v`, виводяться з `v_{out}`.
- Будь-який потік через `v` тепер змушений проходити через вузьке внутрішнє ребро `(v_{in}, v_{out})`, гарантуючи дотримання обмеження наскрізного трафіку.

### 2. Кілька джерел та кілька стоків (Multiple Sources and Sinks)
Якщо мережа має множину виробників `S = {s₁, s₂, ...}` із продуктивністю `S_i` та множину споживачів `T = {t₁, t₂, ...}` із попитом `T_j`:
- Створюється єдине фіктивне **суперджерело** `S*` та єдиний **суперстік** `T*`.
- Додаються спрямовані дуги `(S*, s_i)` із пропускною спроможністю `S_i`.
- Додаються спрямовані дуги `(t_j, T*)` із пропускною спроможністю `T_j`.
- Задача розв'язується як класичний пошук максимального потоку від `S*` до `T*`.

### 3. Максимальне паросполучення у двочастковому графі (Bipartite Matching)
Нехай задано двочастковий граф `G = (L ∪ R, E)`. Необхідно знайти найбільшу множину ребер без спільних вершин ([детальніше див. статтю про паросполучення](root:sf-algorithms/bipartite-matching)):
- Додається джерело `s` зі зв'язками `(s, u)` місткістю `c = 1` для всіх `u ∈ L`.
- Додається стік `t` зі зв'язками `(v, t)` місткістю `c = 1` для всіх `v ∈ R`.
- Усі початкові ребра між `L` та `R` орієнтуються від `L` до `R` з місткістю `c = 1`.
- За теоремою про цілочисельність, максимальний потік набуває значень `f(e) ∈ {0, 1}`. Ребра між `L` та `R`, по яких тече одиничний потік, утворюють максимальне паросполучення.

### 4. Сегментація зображень та мінімальний розріз (Graph Cuts у Computer Vision)
У задачах комп'ютерного зору пікселі зображення розглядаються як вершини графа. Потрібно розділити пікселі на об'єкт (Foreground, множина `S`) та фон (Background, множина `T`):
- Кожен піксель з'єднується з джерелом `s` ребром із вагою, що відповідає ймовірності належати об'єкту, та зі стоком `t` — з вагою ймовірності належати фону.
- Сусідні пікселі з'єднуються ребрами з вагами, пропорційними їхній колірній схожості.
- Мінімальний розріз знаходить глобально оптимальний поділ зображення, мінімізуючи сумарну енергію невідповідності та згладжуючи межі об'єктів.

### 5. Задача вибору проектів (Maximum-Weight Closure Problem)
Нехай є набір проектів, кожен із яких має прибуток `p_i > 0` або збиток (витрати) `p_i < 0`. Деякі проекти вимагають обов'язкового попереднього виконання інших проектів (залежності `u → v`):
- Джерело `s` з'єднується з усіма прибутковими проектами (`p_i > 0`) ребрами місткістю `p_i`.
- Усі збиткові проекти (`p_j < 0`) з'єднуються зі стоком `t` ребрами місткістю `|p_j|`.
- Ребра залежностей `u → v` отримують нескінченну місткість `c = ∞`.
- Мінімальний розріз `(S, T)` відокремлює оптимальну множину проектів для реалізації `S \ {s}`, а максимальний чистий прибуток дорівнює сумі всіх додатних прибутків мінус місткість мінімального розрізу:
```
Максимальний_прибуток = ∑_{p_i > 0} p_i - min c(S, T)
```

### 6. Циркуляція з нижніми та верхніми межами (Circulation with Demands)
У багатьох логістичних мережах кожне ребро має не лише максимальну пропускну здатність `c(u, v)`, але й обов'язковий мінімальний потік `l(u, v) ≤ f(u, v) ≤ c(u, v)` (наприклад, для запобігання замерзанню труб або забезпечення мінімального контракту):
- Віднімаємо обов'язковий потік: кожне ребро отримує місткість `c'(u, v) = c(u, v) - l(u, v)`.
- У кожній вершині перераховується баланс попиту й пропозиції: `d'(u) = d(u) + ∑_{in} l - ∑_{out} l`.
- Створюються суперджерело `S*` та суперстік `T*`, які з'єднуються з вершинами відповідно до їхнього скоригованого балансу `d'(u)`.
- Якщо потік повністю насичує всі дуги з `S*`, то в початковій мережі існує допустима циркуляція.

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <limits>
#include <cstdint>
#include <algorithm>

template <typename FlowType = int64_t>
class EdmondsKarp {
public:
    struct Edge {
        int to;
        int rev;
        FlowType cap;
        FlowType flow;
    };

    explicit EdmondsKarp(int vertices)
        : n(vertices), adj(vertices) {}

    void add_edge(int from, int to, FlowType cap, FlowType rev_cap = 0) {
        if (from == to || from < 0 || to < 0 || from >= n || to >= n) return;
        Edge forward_edge{to, static_cast<int>(adj[to].size()), cap, 0};
        Edge backward_edge{from, static_cast<int>(adj[from].size()), rev_cap, 0};
        adj[from].push_back(forward_edge);
        adj[to].push_back(backward_edge);
    }

    FlowType max_flow(int s, int t) {
        if (s == t || s < 0 || t < 0 || s >= n || t >= n) return 0;
        FlowType total_flow = 0;

        std::vector<int> parent_node(n, -1);
        std::vector<int> parent_edge(n, -1);

        while (bfs(s, t, parent_node, parent_edge)) {
            FlowType push_delta = std::numeric_limits<FlowType>::max();

            // 1. Пошук пляшкового горла вздовж знайденого шляху
            for (int curr = t; curr != s; curr = parent_node[curr]) {
                int p = parent_node[curr];
                int edge_idx = parent_edge[curr];
                const Edge& e = adj[p][edge_idx];
                push_delta = std::min(push_delta, e.cap - e.flow);
            }

            // 2. Аугментація потоку
            for (int curr = t; curr != s; curr = parent_node[curr]) {
                int p = parent_node[curr];
                int edge_idx = parent_edge[curr];
                Edge& forward_e = adj[p][edge_idx];
                Edge& backward_e = adj[curr][forward_e.rev];

                forward_e.flow += push_delta;
                backward_e.flow -= push_delta;
            }

            total_flow += push_delta;
        }

        return total_flow;
    }

    std::vector<bool> min_cut(int s) const {
        std::vector<bool> visited(n, false);
        std::queue<int> q;
        q.push(s);
        visited[s] = true;

        while (!q.empty()) {
            int u = q.front();
            q.pop();

            for (const auto& edge : adj[u]) {
                if (edge.cap - edge.flow > 0 && !visited[edge.to]) {
                    visited[edge.to] = true;
                    q.push(edge.to);
                }
            }
        }
        return visited;
    }

private:
    int n;
    std::vector<std::vector<Edge>> adj;

    bool bfs(int s, int t, std::vector<int>& parent_node, std::vector<int>& parent_edge) {
        std::fill(parent_node.begin(), parent_node.end(), -1);
        std::fill(parent_edge.begin(), parent_edge.end(), -1);

        std::queue<int> q;
        q.push(s);
        parent_node[s] = s;

        while (!q.empty()) {
            int u = q.front();
            q.pop();

            if (u == t) break;

            for (size_t i = 0; i < adj[u].size(); ++i) {
                const Edge& edge = adj[u][i];
                if (edge.cap - edge.flow > 0 && parent_node[edge.to] == -1) {
                    parent_node[edge.to] = u;
                    parent_edge[edge.to] = static_cast<int>(i);
                    q.push(edge.to);
                }
            }
        }

        return parent_node[t] != -1;
    }
};

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

#define MAX_NODES 5000
#define MAX_ARCS  60000
#define FLOW_INF  INT64_MAX

typedef struct {
    int to;
    int next;
    int64_t cap;
    int64_t flow;
} FlowArc;

typedef struct {
    int n;
    int arc_count;
    int head[MAX_NODES];
    FlowArc arcs[MAX_ARCS];
} FlowNetworkC;

void flow_network_init(FlowNetworkC* net, int n) {
    net->n = n;
    net->arc_count = 0;
    memset(net->head, -1, sizeof(int) * n);
}

void flow_network_add_edge(FlowNetworkC* net, int from, int to, int64_t cap, int64_t rev_cap) {
    if (from == to || from < 0 || to < 0 || from >= net->n || to >= net->n) return;

    net->arcs[net->arc_count] = (FlowArc){to, net->head[from], cap, 0};
    net->head[from] = net->arc_count++;

    net->arcs[net->arc_count] = (FlowArc){from, net->head[to], rev_cap, 0};
    net->head[to] = net->arc_count++;
}

static bool flow_network_bfs(FlowNetworkC* net, int s, int t, int parent_edge[MAX_NODES]) {
    memset(parent_edge, -1, sizeof(int) * net->n);
    int queue[MAX_NODES];
    int q_head = 0, q_tail = 0;

    queue[q_tail++] = s;
    parent_edge[s] = -2;

    while (q_head < q_tail) {
        int u = queue[q_head++];
        if (u == t) return true;

        for (int e = net->head[u]; e != -1; e = net->arcs[e].next) {
            int v = net->arcs[e].to;
            int64_t res_cap = net->arcs[e].cap - net->arcs[e].flow;

            if (res_cap > 0 && parent_edge[v] == -1) {
                parent_edge[v] = e;
                queue[q_tail++] = v;
            }
        }
    }

    return parent_edge[t] != -1;
}

int64_t flow_network_max_flow(FlowNetworkC* net, int s, int t) {
    if (s == t) return 0;
    int64_t total_flow = 0;
    int parent_edge[MAX_NODES];

    while (flow_network_bfs(net, s, t, parent_edge)) {
        int64_t push_delta = FLOW_INF;

        for (int curr = t; curr != s; ) {
            int e = parent_edge[curr];
            int64_t res_cap = net->arcs[e].cap - net->arcs[e].flow;
            if (res_cap < push_delta) push_delta = res_cap;
            curr = net->arcs[e ^ 1].to;
        }

        for (int curr = t; curr != s; ) {
            int e = parent_edge[curr];
            net->arcs[e].flow += push_delta;
            net->arcs[e ^ 1].flow -= push_delta;
            curr = net->arcs[e ^ 1].to;
        }

        total_flow += push_delta;
    }

    return total_flow;
}

void flow_network_min_cut(FlowNetworkC* net, int s, bool in_s[MAX_NODES]) {
    memset(in_s, false, sizeof(bool) * net->n);
    int queue[MAX_NODES];
    int q_head = 0, q_tail = 0;

    queue[q_tail++] = s;
    in_s[s] = true;

    while (q_head < q_tail) {
        int u = queue[q_head++];
        for (int e = net->head[u]; e != -1; e = net->arcs[e].next) {
            int v = net->arcs[e].to;
            if (net->arcs[e].cap - net->arcs[e].flow > 0 && !in_s[v]) {
                in_s[v] = true;
                queue[q_tail++] = v;
            }
        }
    }
}

## Порівняльний інженерний аналіз алгоритмів пошуку максимального потоку

Залежно від щільності графа (`|E|` відносно `|V|`), діапазону пропускних спроможностей та специфіки предметної області інженери обирають відповідні алгоритмічні сімейства:

| Алгоритм | Рік | Часова складність | Парадигма | Оптимальна сфера застосування |
|---|---|---|---|---|
| **Форд — Фалкерсон** | 1956 | `O(E · \|f*\|)` | Довільний розширювальний шлях (DFS) | Навчальні задачі, ручний розрахунок |
| **Едмондс — Карп** | 1972 | `O(V · E²)` | Найкоротший шлях через BFS | Загальні розріджені мережі помірного розміру |
| **Capacity Scaling** | 1972 | `O(E² · log U)` | Шляхи з пороговою місткістю `Δ` | Мережі з гігантськими пропускними вагами `U` |
| **Дініц (Dinitz)** | 1970 | `O(V² · E)` | Рівневі графи + блокуючий потік | Промисловий стандарт для загальних задач ([детальніше див. тему](root:sf-algorithms/dinic-algorithm)) |
| **Дініц у Unit Networks** | 1970 | `O(E · √V)` | Рівневий DAG на одиничних місткостях | Двочасткове паросполучення (Hopcroft-Karp) |
| **Push-Relabel (Goldberg-Tarjan)** | 1986 | `O(V² · √E)` | Проштовхування передпотоку та підйом висот | Надщільні графі (`E ≈ V²`), комп'ютерний зір |
| **Бойков — Колмогоров** | 2004 | `O(V² · E)` (найгірший) | Два зростаючі дерева пошуку (S та T) | Спеціалізований лідер для 2D/3D Grid Graphs |

Алгоритм Едмондса — Карпа залишається фундаментальним канонічним зразком: він вимагає мінімального обсягу коду (менше 40 рядків), не використовує складних динамічних структур даних та надійно забезпечує поліноміальний час виконання на будь-яких мережах реального світу.
