# 📋 Специфікація інтерфейсу: структура даних та методи розв'язувача максимального потоку

Програмний контракт модуля розв'язання потокових мереж надає структури даних залишкового графа, обчислення максимального потоку за алгоритмом Едмондса — Карпа та вилучення мінімального s-t розрізу. Інтерфейс оптимізовано для високої обчислювальної продуктивності та безпеки типів: він поєднує ідіоматичний об'єктно-орієнтований стиль у C++ із низькорівневим процедурним керуванням пам'яттю у C.

## Огляд архітектури та представлення типів

Модуль надає два взаємодоповнюючі інтерфейси:
1. **Шаблонний клас C++ `EdmondsKarp<FlowType>`:** інкапсулює динамічні списки суміжності на основі `std::vector`, підтримує довільні числові типи для пропускних спроможностей (`int32_t`, `int64_t`, `double`) та надає строгі гарантії безпеки винятків (Strong Exception Safety).
2. **Структура C `FlowNetworkC`:** реалізує компактне представлення графа у форматі Forward Star зі статичним виділенням пам'яті та бітовою адресацією зворотних ребер `e ^ 1`, що забезпечує нульовий оверхед динамічної алокації та максимальну локальність даних у процесорному кеші.

:::tabs
```cpp
#include <vector>
#include <cstdint>

template <typename FlowType = int64_t>
class EdmondsKarp {
public:
    struct Edge {
        int to;         // Індекс цільової вершини дуги (0 <= to < n)
        int rev;        // Позиція парного ребра у списку adj[to]
        FlowType cap;   // Початкова пропускна спроможність (cap >= 0)
        FlowType flow;  // Поточний потік через ребро (0 <= flow <= cap)
    };

    explicit EdmondsKarp(int vertices);
    // ... методи інтерфейсу
};
```
```c
#include <stdint.h>
#include <stdbool.h>

#define MAX_NODES 5000
#define MAX_ARCS  60000

typedef struct {
    int to;         // Цільова вершина дуги
    int next;       // Індекс наступного ребра у списку суміжності (-1 = кінець)
    int64_t cap;    // Пропускна спроможність
    int64_t flow;   // Поточний потік через ребро
} FlowArcC;

typedef struct {
    int n;                      // Кількість вершин у мережі
    int arc_count;              // Загальна кількість дуг у масиві
    int head[MAX_NODES];        // Голова списку суміжності для кожної вершини
    FlowArcC arcs[MAX_ARCS];    // Статичний масив усіх спрямованих дуг
} FlowNetworkC;
```
:::

## Специфікація методів та функцій API

### 1. Ініціалізація мережі

:::tabs
```cpp
explicit EdmondsKarp(int vertices);
```
```c
void flow_network_init(FlowNetworkC* net, int n);
```
:::

- **Призначення:** Створює порожню потокову мережу з фіксованою кількістю вершин `n`.
- **Параметри:**
  - `vertices` / `n` — кількість вершин у графі (`n ≥ 1`, для C-версії `n ≤ MAX_NODES`).
- **Передумови (Preconditions):**
  - Кількість вершин повинна бути строго додатною. Для C-структури вказівник `net` не повинен бути `NULL`.
- **Постумови (Postconditions):**
  - Усі списки суміжності ініціалізуються порожніми. Вершини отримують індекси від `0` до `n - 1`.
- **Складність:**
  - Час: `O(V)`.
  - Пам'ять: `O(V)` для векторів списків суміжності в C++ або обнулення масиву голів у C.

### 2. Додавання спрямованої дуги

:::tabs
```cpp
void add_edge(int from, int to, FlowType cap, FlowType rev_cap = 0);
```
```c
void flow_network_add_edge(FlowNetworkC* net, int from, int to, int64_t cap, int64_t rev_cap);
```
:::

- **Призначення:** Додає орієнтовану дугу від вершини `from` до вершини `to` з прямою місткістю `cap` та відповідну їй зворотну дугу від `to` до `from` з місткістю `rev_cap`.
- **Параметри:**
  - `from` — індекс вихідної вершини (`0 ≤ from < n`).
  - `to` — індекс цільової вершини (`0 ≤ to < n`).
  - `cap` — пряма пропускна спроможність (`cap ≥ 0`).
  - `rev_cap` — зворотна пропускна спроможність (`rev_cap ≥ 0`). За замовчуванням `0` (для звичайних орієнтованих дуг). Якщо мережа неорієнтована, встановлюється рівним `cap`.
- **Поведінка та крайові випадки:**
  - Якщо `from == to` (петля) або індекси вершин виходять за межі діапазону `[0, n - 1]`, виклик безпечно ігнорується.
  - Дозволяється багаторазове додавання дуг між однією і тією ж парою вершин (паралельні ребра). Кожна пара дуг отримує власні незалежні комірки в залишковій мережі.
- **Складність:**
  - Час: `O(1)` амортизований.

### 3. Обчислення максимального потоку

:::tabs
```cpp
FlowType max_flow(int s, int t);
```
```c
int64_t flow_network_max_flow(FlowNetworkC* net, int s, int t);
```
:::

- **Призначення:** Знаходить максимальний потік від джерела `s` до стоку `t` за алгоритмом Едмондса — Карпа.
- **Параметри:**
  - `s` — індекс джерела (витоку), `0 ≤ s < n`.
  - `t` — індекс стоку (кінцевого споживача), `0 ≤ t < n`.
- **Повертане значення:**
  - Величина максимального потоку `|f*|`. Якщо `s == t`, якщо параметри некоректні, або якщо стік недосяжний з джерела у початковій мережі, повертає `0`.
- **Побічні ефекти:**
  - Модифікує поля `flow` усіх дуг мережі так, що фінальний стан задовольняє закон збереження потоку та обмеження місткостей.
- **Складність:**
  - Часова складність: `O(V · E²)` у найгіршому випадку.
  - Просторова складність: `O(V)` додаткової пам'яті для черги обходу BFS та масиву батьківських посилань.

### 4. Вилучення мінімального розрізу

:::tabs
```cpp
std::vector<bool> min_cut(int s) const;
```
```c
void flow_network_min_cut(FlowNetworkC* net, int s, bool in_s[MAX_NODES]);
```
:::

- **Призначення:** Знаходить мінімальний s-t розріз `(S, T)` після обчислення максимального потоку.
- **Параметри:**
  - `s` — індекс джерела.
  - `in_s` (у C) — вихідний булевий масив розміру `MAX_NODES`.
- **Повертане значення:**
  - У C++: вектор `std::vector<bool>` розміру `n`, де елемент `[u] == true`, якщо вершина `u` належить множині `S` (досяжна з `s` у залишковій мережі `G_f`), та `false`, якщо належить множині `T = V \ S`.
  - У C: заповнює масив `in_s` відповідними булевими значеннями.
- **Теоретична властивість:**
  - Сумарна пропускна спроможність прямих ребер вихідної мережі, що починаються у вершинах `S` і закінчуються у вершинах `T`, строго дорівнює величині максимального потоку: `c(S, T) = |f*|`.
- **Складність:**
  - Час: `O(V + E)` (одноразовий пошук у ширину в `G_f`).
  - Пам'ять: `O(V)`.

### 5. Інспекція суміжних дуг та діагностика інваріантів

:::tabs
```cpp
const std::vector<Edge>& get_edges(int u) const;
int vertex_count() const;
bool verify_invariants(int s, int t) const;
```
```c
// Ітерація по дугах вершини u в C:
// for (int e = net->head[u]; e != -1; e = net->arcs[e].next) { ... }
int flow_network_vertex_count(const FlowNetworkC* net);
bool flow_network_verify_invariants(const FlowNetworkC* net, int s, int t);
```
:::

- **Призначення:** Надає доступ для читання до списку інцидентних дуг вершини `u` для верифікації розподілу потоків та вилучення списку критичних каналів мінімального розрізу.
- **Метод верифікації `verify_invariants`:** виконує повну перевірку виконання закону Кірхгофа для всіх внутрішніх вершин `u ∉ {s, t}` та дотримання обмежень пропускної спроможності `0 ≤ flow ≤ cap` для всіх ребер. Повертає `true`, якщо всі інваріанти збережено без порушень.

## Системні інваріанти, правила сумісності та обробка помилок

1. **Інваріант місткості (Capacity Invariant):** Для будь-якої прямої дуги виконується нерівність `0 ≤ edge.flow ≤ edge.cap`. У разі використання дійсних чисел із рухомою комою (`double`, `float`) порівняння здійснюється з урахуванням машинного епсилон `ε = 1e-9` для запобігання накопиченню похибок округлення під час послідовних аугментацій.
2. **Інваріант кососиметричності (Skew Symmetry):** Для будь-якої пари ребер `(e, rev_e)` завжди виконується тотожність `flow[rev_e] == -flow[e]`. Це гарантує математичну еквівалентність скасування та зворотного проштовхування в залишковому графі.
3. **Інваріант збереження потоку (Flow Conservation):** Для кожної внутрішньої вершини `u ∉ {s, t}` чистий баланс потоку строго дорівнює нулю:
```
∑_{e ∈ Out(u)} flow[e] - ∑_{e ∈ In(u)} flow[e] = 0
```
4. **Гарантії винятків у C++ (Exception Safety):** Конструктор та метод `add_edge` забезпечують сильну гарантію винятків (Strong Exception Safety). Якщо під час алокації пам'яті вектора виникає `std::bad_alloc`, стан об'єкта залишається незмінним. Метод `max_flow` є безетапним і не виділяє динамічної пам'яті поза межами локальних векторів черги.
5. **Потокобезпечність (Thread Safety):** Одночасні виклики константних методів (`min_cut`, `get_edges`, `verify_invariants`, `to_dot`) на одному екземплярі з різних потоків є цілком безпечними. Виклики методів-мутаторів (`add_edge`, `max_flow`) вимагають зовнішньої синхронізації через м'ютекси або блокування на рівні програми.
6. **Робота з великими статичними графами в C:** Якщо кількість вершин або дуг перевищує константи `MAX_NODES` або `MAX_ARCS`, функція `flow_network_add_edge` безпечно ігнорує додавання нових дуг. Для промислових вбудованих систем рекомендується підбирати значення констант під час компіляції за допомогою препроцесорних директив `-DMAX_NODES=...` та `-DMAX_ARCS=...`.
