# 📋 Інтерфейс та контракт LSH-бібліотеки

Ця вставка містить повну специфікацію публічного інтерфейсу (API), структур даних, конфігураційних параметрів та гарантій безпеки для системної бібліотеки хешування з урахуванням локальності (Locality-Sensitive Hashing). Вона описує низькорівневий C-ABI та ідіоматичний C++20 контракт, призначений для інтеграції у високонавантажені сервери векторного пошуку, бази даних та аналітичні сервіси.

## 1. Архітектурні принципи та призначення API

Головне призначення даного публічного контракту полягає в ізоляції прикладної логіки додатку від складних рандомізованих математичних обчислень LSH. Бібліотека надає уніфіковані структури даних для ініціалізації індексу, вставки векторних об'єктів та проведення швидкого ймовірнісного пошуку за критерієм найближчих сусідів (Approximate Nearest Neighbors, ANN).

Внутрішньо бібліотека абстрагує різновиди хеш-функцій для трьох основних геометричних метрик. При створенні індексу розробник фіксує обрану метрику схожості, вимірність векторів та параметри підсилення (кількість смуг `L` та кількість рядочків у смузі `k`). Далі система автономно керує генерацією випадкових гіперплощин чи проекційних ліній, розподілом пам'яті під хеш-таблиці бакетів та оптимізацією вибірки кандидатів.

Всі виклики API розроблені з урахуванням суворих вимог до системного програмування: відсутність невизначеної поведінки, явний контроль алокацій пам'яті, сумісність із C-ABI для зв'язування з іншими мовами (Go, Rust, Python, Java) та забезпечення безблокувального паралельного читання з багаторазових робочих потоків.

Система спроектована за принципом мінімального накладного обсягу пам'яті на один вектор. Кожен доданий вектор зберігається в єдиному екземплярі у щільному лінійному буфері, тоді як хеш-таблиці бакетів оперують лише компактними 64-бітними ідентифікаторами та вказівниками на внутрішні індекси. Це виключає дублювання важких масивів чисел типу float між різними смугами індексу.

## 2. Перелік метрик схожості та їхніх характеристик

Бібліотека підтримує три ключові типи метрик схожості, для кожного з яких використовується відповідний клас LSH-функцій:

| Метрика | Вхідний тип даних | Алгоритм LSH | Діапазон значень | Функція колізії |
| :--- | :--- | :--- | :--- | :--- |
| **`LSH_METRIC_JACCARD`** | Набір `k`-грам / ідентифікаторів | **MinHash** | `[0.0, 1.0]` | `P(h(A) = h(B)) = J(A, B)` |
| **`LSH_METRIC_COSINE`** | Щільний вектор `float32` | **SimHash (Hyperplanes)** | `[0.0, 2.0]` | `P(h(u) = h(v)) = 1 - θ/π` |
| **`LSH_METRIC_EUCLIDEAN`** | Щільний вектор `float32` | **`p`-Stable (Gaussian)** | `[0.0, ∞)` | `h(x) = floor((a·x + b)/w)` |

Кожен екземпляр індексу зв'язується з однією конкретною метрикою під час створення. Спроба додати вектор некоректної вимірності або передати некоректну метрику завершується поверненням відповідного коду помилки без порушення цілісності внутрішнього стану індексу.

Вибір метрики визначає спосіб інтерпретації вхідного буфера даних:
* Для `LSH_METRIC_JACCARD` масив інтерпретується як впорядкований список унікальних 32-бітних або 64-бітних ідентифікаторів дискретних елементів.
* Для `LSH_METRIC_COSINE` масив інтерпретується як щільний вектор чисел з плаваючою комою одинарної точності. Модуль вектора автоматично враховується при обчисленні кута.
* Для `LSH_METRIC_EUCLIDEAN` масив інтерпретується як точка в евклідовому просторі, де значення мають важливе значення разом із нормою вектора.

## 4. Детальний опис життєвого циклу та керування ресурсами

Життєвий цикл будь-якого екземпляра LSH-індексу підпорядкований суворій послідовності викликів, яка гарантує відсутність витоків оперативної пам'яті (Memory Leaks) та руйнування покажчиків (Dangling Pointers).

### Створення та ініціалізація індексу
При виклику функції `lsh_index_create` або статичного методу `Index::create` відбувається перевірка коректності вхідних параметрів. Вимірність `dim` повинна бути більшою за нуль, кількість смуг `num_bands` та кількість рядочків `rows_per_band` повинні становити щонайменше 1.

Внутрішній алокатор виділяє єдиний суцільний блок пам'яті під матрицю випадкових гіперплощин розміром `(num_bands * rows_per_band * dim) * sizeof(float)`. Для генерування чисел використовується вибіркова ініціалізація від генератора Mersenne Twister (std::mt19937) із вказаним зерном `seed`. Фіксоване зерно забезпечує повну відтворюваність результатів між повторними запусками додатка.

Далі створюється масив із `L` хеш-таблиць. Кожна хеш-таблиця ініціалізується початковою кількістю бакетів `initial_capacity`. Якщо параметри некоректні або системна пам'ять вичерпана, функція повертає від'ємний код помилки, залишаючи результуючий вказівник у стані NULL.

### Вставка векторних даних
Вставка векторів виконується викликом `lsh_index_insert`. Переданий масив чисел перевіряється на відповідність конфігураційній вимірності. 

Внутрішньо алгоритм обчислює `L` смугових хешів. Для кожної смуги обчислюється `k` скалярних добутків або MinHash-значень, які упаковуються у 64-бітне число. Отримане число визначає номер бакета в відповідній хеш-таблиці. Ідентифікатор вектора додається на початок однозв'язного списку елементів даного бакета.

Векторні дані зберігаються у внутрішньому динамічному масиві. Якщо виникає потреба розширення масиву, застосовується стратегія подвоєння місткості (Amortized O(1) Reallocation).

### Пошук найближчих сусідів
Пошукова операція `lsh_index_query_knn` виконується у декілька проходів. Спочатку обчислюються бакетові хеші для вектора запиту. Далі система послідовно проходить по відповідних бакетах усіх `L` хеш-таблиць та збирає унікальні ідентифікатори кандидатів.

Для відсікання дублікатів кандидатів використовується бітовий прапорець або відвідуваний масив розміром `N` елементів. Якщо кількість зібраних кандидатів перевищує параметр `max_candidates`, збір припиняється, що захищає систему від сплесків затримок при наявності аномально великих бакетів.

Після завершення збору кандидатів система обчислює точну відстань між вектором запиту та кожним відібраним кандидатом. Отриманий список сортується за допомогою швидкого сортування `qsort` чи `std::sort`, і `top_k` найближчих елементів копіюються у вихідний буфер результатів.

### Знищення індексу
При виклику `lsh_index_destroy` або виході C++ об'єкта `unique_ptr` із області видимості виконується послідовне вивільнення всіх однозв'язних списків бакетів у кожній із `L` хеш-таблиць, знищення матриці гіперплощин та звільнення буфера векторних даних. Після завершення виклику пам'ять повністю повертається операційній системі.

## 5. Специфікація параметрів та рекомендації з налаштування

Для досягнення заданої порогової схожості `s₀` та рівня точності відклику (Recall) налаштування параметрів `k` (рядків у смузі) та `L` (кількості смуг) підпорядковується наступним практичним орієнтирам:

| Цілева схожість `s₀` | Рекомендовані `k` | Рекомендовані `L` | Обчислювальна складність на запит | Обсяг пам'яті на вектор |
| :--- | :--- | :--- | :--- | :--- |
| **High Precision (`s₀ ≥ 0.85`)** | `k = 8...10` | `L = 50...100` | Дуже мала (короткі кандидати) | Висока (`100` вказівників в індексі) |
| **Balanced (`s₀ ≈ 0.50`)** | `k = 4...5` | `L = 15...20` | Оптимальна | Середня (`20` вказівників у бакетах) |
| **High Recall (`s₀ ≤ 0.30`)** | `k = 2...3` | `L = 5...10` | Висока (широкі списки кандидатів) | Низька (`10` вказівників у бакетах) |

При збільшенні `k` зростає вибірковість кожної смуги: ймовірність випадкової колізії двох недотичних векторів зменшується експоненціально `p^k`. Однак це вимагає компенсації шляхом збільшення кількості смуг `L`, щоб не втратити релевантні вектори.

## 6. Формула оцінки витрат оперативної пам'яті

Загальний обсяг оперативної пам'яті `RAM` для збереження `N` векторів вимірності `D` при `L` смугах обчислюється за формулою:

```
RAM_total = RAM_vectors + RAM_index

RAM_vectors = N · (D · sizeof(float) + sizeof(uint64_t))
RAM_index   = L · (N · sizeof(bucket_node_t) + Capacity_buckets · sizeof(pointer))
```

Для `N = 1 000 000` векторів вимірності `D = 128` при `L = 20` смугах:
* Пам'ять векторів: `10⁶ · (128 · 4 + 8) B ≈ 520 МБ`.
* Пам'ять LSH-індексу: `20 · 10⁶ · 16 B ≈ 320 МБ`.
* **Загальний обсяг**: `~840 МБ`, що у десятки разів менше за щільний графічний індекс HNSW.

## 7. Вимоги до вирівнювання пам'яті та SIMD-оптимізацій

Для забезпечення максимальної продуктивності обчислення скалярних добутків у гарячих циклах LSH рекомендується дотримуватися таких системних правил:

1. **Вирівнювання пам'яті**: Всі буфери векторних даних `float` повинні виділятися з вирівнюванням на межу 32 байти (для процесорів з підтримкою AVX2) або 64 байти (для AVX-512). Це виключає накладні витрати на невирівняне зчитування з кешу CPU.
2. **Апаратна підтримка POPCNT**: Для алгоритмів SimHash обчислення відстані Хеммінга між бітовими кодами повинно виконуватися за допомогою вбудованої процесорної інструкції `__builtin_popcountll` чи `_mm_popcnt_u64`.
3. **Гарантії потокобезпечності (Thread Safety)**: Операція пошуку `lsh_index_query_knn` є повністю констатною, не змінює внутрішній стан індексу і може безпечно виконуватися паралельно з довільної кількості потоків без залучення м'ютексів. Операція вставки `lsh_index_insert` змінює внутрішні списки бакетів і вимагає зовнішнього блокування (наприклад, через `std::shared_mutex`).
