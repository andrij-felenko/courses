## Базові типи даних та коди повернення

typedef enum {
    XOR_OK = 0,

## Побудова фільтра (Construction API)

:::tabs
```c
/* Конструювання 8-бітного Xor-фільтра з масиву унікальних ключів */
xor_error_t xor_filter_8_build(xor_filter_8_t *filter, const uint64_t *keys, size_t count);
```
```cpp
namespace algorithms {

template <typename FingerprintType>
class XorFilter {
public:
    /* Фабричний метод побудови з неперервного діапазону ключів */
    [[nodiscard]] static std::expected<XorFilter, FilterError>
    build(std::span<const uint64_t> keys);
};

} // namespace algorithms
```
:::

* **Призначення**: Виділяє пам'ять та конструює Xor-фільтр із переданого масиву унікальних ключів за середній час `O(N)`.
* **Параметри**:
  * `filter` / повертаний об'єкт: екземпляр структури `xor_filter_8_t` або типізований об'єкт `XorFilter`.
  * `keys`: неперервний буфер 64-бітних ключів.
  * `count`: кількість ключів (мусить бути `> 0`).
* **Передумови та валідація**:
  * Вхідні вказівники не повинні дорівнювати `NULL` (`XOR_ERR_NULL_POINTER` / `FilterError::NullPointer`).
  * Кількість ключів не повинна дорівнювати 0 (`XOR_ERR_EMPTY_INPUT` / `FilterError::EmptyInput`).
  * Ключі у масиві обов'язково мають бути дедупліковані (наявність дублікатів спричиняє самоскасування в акумуляторі степенів та повернення помилки вичерпання спроб `XOR_ERR_MAX_ATTEMPTS_EXCEEDED` / `FilterError::PeelingFailedExceededAttempts`).
* **Повертане значення**:
  * `XOR_OK` або валідний `std::expected` з готовим фільтром.
  * Помилка алокації `XOR_ERR_ALLOCATION_FAILED` / `FilterError::AllocationFailure`, якщо вичерпано пам'ять.

## Перевірка належності (Lookup API)

:::tabs
```c
/* Константна перевірка наявності ключа O(1) */
bool xor_filter_8_contains(const xor_filter_8_t *filter, uint64_t key);
```
```cpp
namespace algorithms {

template <typename FingerprintType>
class XorFilter {
public:
    /* Швидка перевірка належності ключа O(1) */
    [[nodiscard]] bool contains(uint64_t key) const noexcept;
};

} // namespace algorithms
```
:::

* **Призначення**: Виконує константну перевірку ймовірної належності ключа множині.
* **Гарантії повернення**:
  * `true` — ключ імовірно належить множині (якщо ключ був у множині під час побудови — гарантовано `true`; якщо не був — помилка з імовірністю `ε ≈ 0.39%` для 8 бітів).
  * `false` — ключ **гарантовано відсутній** у множині (нульова ймовірність хибнонегативних відповідей).
* **Складність**: строго `O(1)` (3 читання слотів з пам'яті, 2 операції `XOR`, без циклів та розгалужень). Метод у C++ є `const noexcept` та повністю потокобезпечним (Lock-Free) для необмеженої кількості одночасних читачів.

## Бінарний формат серіалізації (On-Disk / Wire Layout)

Для збереження Xor-фільтра у файлах незмінних таблиць (SSTable), кешах дисків або передачі через мережевий сокет визначено фіксований бінарний заголовок із порядком байтів Little-Endian:

```
+-----------------------------------------------------------------------+
| Зсув (байти) | Поле             | Тип      | Опис                     |
+-----------------------------------------------------------------------+
| 0x00 .. 0x03 | Magic Header     | char[4]  | Символи 'X', 'O', 'R', 'F'|
| 0x04         | Version          | uint8_t  | Версія формату (0x01)    |
| 0x05         | Fingerprint Bits | uint8_t  | Розмірність (8 або 16)   |
| 0x06 .. 0x07 | Reserved         | uint16_t | Вирівнювання (0x0000)    |
| 0x08 .. 0x0F | Seed             | uint64_t | Псевдовипадковий засів   |
| 0x10 .. 0x13 | Block Length (L) | uint32_t | Розмір одного блоку      |
| 0x14 .. 0x17 | Reserved2        | uint32_t | Зарезервовано під прапорці|
| 0x18 .. Кінець| Payload         | raw byte | 3 * L відбитків          |
+-----------------------------------------------------------------------+
```

### Переваги бінарного формату

1. **Швидке відображення в пам'ять (Zero-Copy mmap)**:
   Завдяки вирівнюванню заголовка за 8-байтовою межею та розміщенню відбитків у прямому лінійному масиві, файл фільтра можна підключати через системний виклик `mmap()`. Операція перевірки `contains` виконує пряме читання сторінок оперативної пам'яті без потреби копіювання чи додаткового парсингу.
2. **Перевірка цілісності та версіонування**:
   Сигнатура `0x46524F58` ('XORF') та поле розмірності відбитків дозволяють миттєво відхилити пошкоджені або несумісні байти до початку виконання запитів.

## Гарантії потокобезпеки (Concurrency Guarantees)

| Операція | Однопотоковий режим | Багатопотоковий доступ (Concurrent Reads) | Одночасні читання та запис |
|---|---|---|---|
| `build` / побудова | Так | Не підтримується (потрібен зовнішній `std::mutex`) | Небезпечно (UB) |
| `contains` / запит | Так | **Повністю потокобезпечно (Lock-Free)** | Небезпечно (UB) |
| `destroy` / деструктор | Так | Потребує ексклюзивного доступу | Небезпечно (UB) |

Після завершення побудови екземпляр Xor-фільтра є **повністю незмінним (immutable)**. Спільне використання одного об'єкта сотнями робочих потоків у пулі задач (Worker Pool) не вимагає жодних блокувань, атомарних інструкцій чи бар'єрів пам'яті, забезпечуючи лінійне масштабування продуктивності за кількістю процесорних ядер.

## Метрики продуктивності та телеметрія

Для діагностики ефективності Xor-фільтра у виробничому середовищі рекомендується відстежувати такі ключові метрики:

1. **Фактична частка хибних спрацьовувань (Empirical False Positive Rate)**:
   * Розраховується як відношення кількості запитів до відсутніх ключів, на які фільтр повернув `true`, до загальної кількості перевірок відсутніх ключів.
   * Для 8-бітного фільтра теоретичний поріг становить `0.3906%` (`1/256`). Відхилення спостережуваної частки понад `0.45%` свідчить про наявність аномалій або зміщень у розподілі вхідних хеш-функцій.
2. **Кількість спроб побудови (Build Attempt Counter)**:
   * Фіксує кількість ітерацій зміни псевдовипадкового засіву `seed` до знаходження ациклічного 3-гіперграфа.
   * У нормі понад 80% фільтрів будуються за 1 спробу, а середня кількість спроб становить `1.22`. Якщо показник систематично перевищує 2.5, необхідно перевірити вхідні дані на наявність недедуплікованих ключів або змінити якість функції хешування.
3. **Ефективність кешу процесора (Cache Line Utilization)**:
   * Завдяки фіксованим 3 зверненням до пам'яті фільтр демонструє стабільний час відповіді. При розміщенні слотів у суміжних ділянках пам'яті завантаження ліній кешу L1/L2 досягає максимальної ефективності без виникнення паразитних черг очікування на шині пам'яті.

## Вимоги до вирівнювання пам'яті (Memory Alignment)

Для досягнення максимальної пропускної здатності на сучасних архітектурах x86-64 та AArch64 накладаються такі інженерні вимоги:

1. **Вирівнювання масиву відбитків**:
   * Масив `fingerprints` виділяється з вирівнюванням щонайменше за 64-байтовою межею (`alignas(64)` або `posix_memalign`).
   * Це запобігає перетину ліній кешу L1 (Cache Line Splits) під час паралельного читання слотів `B₀`, `B₁` та `B₂` кількома конвеєрними портами завантаження.
2. **Векторизація пакетних запитів**:
   * Для векторних інструкцій AVX2 (`_mm256_i32gather_epi32`) та AVX-512 розмір виділеного буфера повинен бути кратним 64 байтам. Якщо фактична кількість слотів `3 · L` не кратна 64, виділяється додатковий паддінг (Padding), заповнений нулями, який не бере участі в логіці фільтра, але гарантує безпечне векторне зчитування без виходу за межі пам'яті (Buffer Over-read).

## Рекомендації щодо міграції з фільтра Блума

При переведенні існуючого сховища з фільтра Блума на Xor-фільтр слід враховувати такі кроки:
1. **Зміна моделі запису**: Фільтр Блума дозволяє дописувати біти в режимі реального часу під час надходження нових ключів. Xor-фільтр вимагає, щоб повний набір ключів був відомий до початку побудови. Тому генерація фільтра переноситься на етап фіналізації сегмента (flush/compaction).
2. **Очищення від дублікатів**: Вхідний масив ключів перед викликом `build` обов'язково сортується або дедуплікується.
3. **Зменшення виділеної пам'яті**: Для того самого рівня хибних спрацьовувань розмір виділених буферів зменшується на 15–20%, вивільняючи додатковий простір під сторінковий кеш бази даних.
4. **Конфігурація розмірності відбитка**: Якщо в системі раніше використовувався фільтр Блума з `FPR = 1%`, рекомендується перехід на 8-бітний Xor-фільтр (`FPR = 0.39%`), який дає у 2.5 раза менше помилок при майже однаковому споживанні пам'яті (9.84 біти на ключ проти 9.6–10 бітів у фільтра Блума).
