# 📜 Історія виникнення масивів та апаратної адресації пам'яті

Еволюція масиву пролягає від фундаментальних ідей архітектури фон Неймана та мови Fortran 1950-х років до виникнення покажчикової арифметики в мові C та сучасних апаратних інструкцій індексації в процесорах x86 та ARM. Осмислення цієї еволюції розкриває, чому сучасні мови програмування досі несуть у собі компроміси між безпосередньою швидкістю адресації та безпекою роботи з пам'яттю.

## Фізична пам'ять фон Неймана та поява індексних регістрів

До виникнення архітектури зі збережуваною в пам'яті програмою (модель фон Неймана, 1945 рік) перші електронно-обчислювальні машини, такі як ENIAC (1946), зберігали дані в окремих електронних регістрах на базі вакуумних ламп чи тригерів. Обробка послідовностей чисел вимагала фізичного перемикання комутаційних кабелів або послідовного читання з перфокарт. Не існувало поняття «адреси пам'яті» як числового значення, над яким можна виконувати арифметичні операції.

З появою концепції лінійного адресованого оперативного запам'ятовуючого пристрою (ОЗП) на феритових осердях виникла потреба звертатися до послідовних комірок пам'яті в циклі. У перших ЕОМ для вибірки елемента з пам'яті програмістам доводилося модифікувати самий код інструкції — самомодифікований код (self-modifying code) перезаписував поле адреси в команді вибірки перед кожною ітерацією циклу.

У 1949 році Том Кілберн та Фредерік Вільямс у Манчестерському університеті на машині Manchester Mark 1 створили перший в історії **індексний регістр** (початково названий *B-line*). Це був апаратний регістр, вміст якого процесор автоматично додавав до адреси, вказаної в інструкції. З цього моменту обчислення адреси елемента `BaseAddress + Offset` стало апаратною операцією, а не результатом перезапису коду в RAM.

## Fortran (1957) та математичне обґрунтування структури

Коли Джон Бекус очолив розробку мови Fortran у компанії IBM у 1954–1957 роках, головним завданням було перекласти математичні формули та операції над матрицями у швидкісний машиний код для IBM 704. Матриці були природною формою вираження систем лінійних рівнянь у фізиці й інженерії.

Fortran створив концепцію статичного багатовимірного масиву на рівні мови високого рівня. Оскільки пам'ять IBM 704 була одновимірним масивом слів, компілятор Fortran мав автоматично трансформувати індекси матриці `A(I, J)` у плаский зсув пам'яті. Розробники Fortran обрали **Column-Major Order** (порядок за стовпчиками): у пам'яті спочатку розміщувалися всі елементи першого стовпчика, потім другого і так далі. Це рішення було зумовлене специфікою інструкцій індексації IBM 704 та зручністю реалізації алгоритмів матричного множення для тогочасних магнітних барабанів.

Оскільки Fortran розроблявся для наукових обчислень, розмірність масивів мала бути відома під час компіляції. Компілятор виділяв фіксований неперервний блок слів у сегменті даних і розраховував адреси за допомогою лінійної арифметики.

## Algol 60 та дескриптори динамічних масивів

У мові ALGOL 60 (1960) міжнародний комітет науковців під керівництвом Пітера Наура та Джона Бекуса зробив наступний крок: масиви отримали можливість оголошуватися з межами, які обчислювалися під час виконання програми (dynamic arrays on stack).

Щоб реалізувати динамічні масиви на стеку, було створено концепцію **доп-вектора** (dope vector) або дескриптора масиву. Доп-вектор являв собою службову структуру даних, яку компілятор клав у стек при вході в блок. Вона містила:
1. Вказівник на початок області елементів.
2. Кількість вимірів (dimensions).
3. Нижні та верхні межі для кожного виміру (`lower_bound`, `upper_bound`).
4. Кроки (strides) для множення індексів.

ALGOL 60 дозволяв індексацію з довільного цілого числа (наприклад, `array A[-10:10]`). Адресна формула враховувала зсув нижньої межі. Завдяки доп-векторам виконання програми могло здійснювати автоматичну перевірку виходу за межі масиву (bounds checking).

## Burroughs B5000 (1961): апаратний захист меж

Архітектура комп'ютера Burroughs B5000, розроблена Робертом Бартоном у 1961 році, була створена спеціально під мову ALGOL. B5000 не мала класичних регістрів загального призначення, а працювала як стек-машина із безпосередньою підтримкою дескрипторів на рівні процесорного заліза.

У B5000 будь-яке звернення до масиву здійснювалося через **дескриптор масиву** (Array Descriptor), який містив базову адресу, довжину блоку та прапорці доступу. При виконанні інструкції індексації мікрокод процесора апаратно порівнював переданий індекс із довжиною масиву у дескрипторі. Якщо індекс виходив за межі, процесор миттєво ґенерував переривання (hardware trap / boundary fault).

Це забезпечувало повну просторову безпеку пам'яті на апаратному рівні. Жоден збійний код не міг прочитати або перезаписати комірку за межами виділеного масиву. Однак така перевірка вимагала додаткових тактів процесора та ускладнювала логіку виконання інструкцій.

## Мова C (1972): тотожність масивів і покажчиків

При розробці операційної системи UNIX та мови C Денніс Рітчі та Кен Томпсон обрали кардинально інший шлях. Вони орієнтувалися на мінімалістичні процесори, такі як PDP-11, де кожен такт і кожен байт пам'яті були на вагу золота.

У мові C масив перестали розглядати як складну об'єктну структуру з дескриптором. Масив у C — це просто неперервний блок байтів у пам'яті, а його ім'я у більшості контекстів автоматично «розпадається» (array decay) у звичайний вказівник на перший елемент (`&A[0]`).

Рітчі запровадив тотожність покажчикової арифметики та індексації:

:::tabs
```c
A[i] == *(A + i)
```
```cpp
// У C++ тотожність покажчикової арифметики збережена для сумісності з C:
A[i] == *(A + i)
```
:::

Завдяки цьому вирази `A[i]` та `i[A]` у C є абсолютними синонімами, адже додавання покажчика та цілого числа є комутативним: `*(A + i) == *(i + A)`.

Свідома відмова від зберігання розміру масиву та відмова від перевірки меж дозволили мові C досягти максимальної продуктивності, яка дорівнювала швидкості чистого асемблера. Однак це рішення відкрило двері для найнебезпечнішої вразливості в історії програмного забезпечення — **переповнення буфера** (buffer overflow).

## Архітектури x86 SIB та сучасний апаратний стан

У 1985 році з виходом 32-бітного процесора Intel 80386 апаратна індексація масивів набула сучасної класичної форми через формат адресації **SIB** (Scale-Index-Base). Інструкція x86 дозволяє в рамках одного процесорного такту обчислити адресу вигляду:

```assembly
MOV EAX, [EBX + ESI*4 + 0x10]
```

Тут `EBX` є базовою адресою (Base), `ESI` — індексом (Index), `4` — масштабуючим множником (Scale, що відповідає розміру елемента 1, 2, 4 або 8 байтів), а `0x10` — постійним зсувом (Displacement).

У XXI столітті, зі зростанням швидкостей процесорів порівняно з оперативною пам'яттю, масиви стали головним інструментом забезпечення кеш-ефективності (cache friendliness). Процесори отримали апаратні блоки попередньої вибірки (Hardware Prefetchers), які аналізують лінійний доступ до елементів масиву та заздалегідь підвантажують наступні кеш-лінії з RAM у кеш L1/L2.

Сучасна інженерія повернулася до ідеї апаратного захисту меж. Проєкти, такі як **CHERI** (Capability Hardware Enhanced RISC Instructions) та інструкції ARM Memory Tagging Extension (MTE), знову додають до вказівників на рівні заліза апаратні межі та теги безпеки, поєднуючи швидкість індексації C із захистом рівня Burroughs B5000.
