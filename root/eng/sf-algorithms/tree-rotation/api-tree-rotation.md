# 📋 Інтерфейс та контракти операцій повороту

В даному розділі наведено специфікацію програмного інтерфейсу (API) операцій повертання двійкових дерев пошуку, контракти методів, таблиці прекондицій та посткондицій, а також чекліст перевірки інваріантів пам'яті та системи управління пам'яттю.

## 1. Архітектурні принципи та дизайн інтерфейсу

Операції повороту є внутрішніми примітивами структури даних. На відміну від високорівневих методів користувача на кшталт `insert()`, `find()` або `erase()`, повороти працюють безпосередньо з топологією зв'язаного графа вузлів. Тому дизайн API повороту мусить вирішувати три системні задачі:

1. **Гарантія сталості часу `O(1)`:** Функції не повинні містити циклів, обходів чи глибоких копіювань. Обробка зводиться до перепідключення фіксованої кількості вказівників у системній пам'яті.
2. **Прозоре оновлення кореня:** Якщо вузол, навколо якого виконується поворот, був коренем всієї структури (`root`), вказівник кореня у дескрипторі дерева повинен автоматично модифікуватися. У мові C це досягається передачею подвійного вказівника `Node** root`, а в мові C++ — передачею посилання на вказівник `Node*& root`.
3. **Збереження цілісності двоспрямованих зв'язків:** Вузли містять не лише вказівники на дітей (`left`, `right`), а й вказівник на батька (`parent`). Будь-який поворот зобов'язаний симетрично оновлювати зв'язки в обох напрямках.

```c
#ifndef TREE_ROTATION_H
#define TREE_ROTATION_H

#include <stddef.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

/**
 * @brief Структура вузла двійкового дерева з розширеними метаданими.
 */
typedef struct Node {
    int key;                /**< Ключ вузла для порівняння */
    int height;             /**< Висота піддерева з коренем у даному вузлі */
    size_t size;            /**< Кількість вузлів у піддереві (для порядкових статистик) */
    struct Node *left;      /**< Вказівник на лівого сина */
    struct Node *right;     /**< Вказівник на правого сина */
    struct Node *parent;    /**< Вказівник на батьківський вузол */
} Node;

Node* rotate_right(Node* x, Node** root);
Node* rotate_left(Node* x, Node** root);

#ifdef __cplusplus
}

#endif /* TREE_ROTATION_H */
```

## 2. Повний контракт операцій: Прекондиції, Посткондиції та Інваріанти

Формальний контракт описує вимоги до стану системи перед викликом функції (прекондиції) та гарантії стану після її завершення (посткондиції).

### Таблиця контракту для `rotate_right(x, root)`

```
Параметр / Елемент | Прекондиція (Стан ДО повороту)     | Посткондиція (Стан ПІСЛЯ повороту)
-------------------|------------------------------------|------------------------------------
x                  | Вказівник != NULL                  | Опускається на щабель нижче, стає правим сином y
x->left (y)        | Вказівник != NULL (піддерево є)    | Піднімається нагору, стає новим коренем фрагмента
y->right (B)       | Вказівник на піддерево або NULL   | Стає лівим сином x (x->left = B)
B->parent          | Якщо B != NULL, вказує на y        | Якщо B != NULL, вказує на x (B->parent = x)
x->parent (P)      | Батьківський вузол P або NULL      | y->parent = P, x->parent = y
P->left / P->right | Вказував на x (якщо P != NULL)     | Вказує на y (P->left = y або P->right = y)
root               | Вказівник на корінь всього дерева  | Якщо x_old був коренем, root оновлюється на y
Центровий порядок  | A < X < B < Y < C                  | A < X < B < Y < C (Строго незмінний)
Висота h(x), h(y)  | h(x) = max(h_A, h_BC) + 1          | h(x) = max(h_B, h_C)+1; h(y) = max(h_A, h_x)+1
Розмір s(x), s(y)  | s(x) = 1 + s_A + s_B + s_C         | s(x) = 1 + s_B + s_C; s(y) = 1 + s_A + s_x
```

### Таблиця контракту для `rotate_left(x, root)`

```
Параметр / Елемент | Прекондиція (Стан ДО повороту)     | Посткондиція (Стан ПІСЛЯ повороту)
-------------------|------------------------------------|------------------------------------
x                  | Вказівник != NULL                  | Опускається на щабель нижче, стає лівим сином y
x->right (y)       | Вказівник != NULL (піддерево є)    | Піднімається нагору, стає новим коренем фрагмента
y->left (B)        | Вказівник на піддерево або NULL   | Стає правим сином x (x->right = B)
B->parent          | Якщо B != NULL, вказує на y        | Якщо B != NULL, вказує на x (B->parent = x)
x->parent (P)      | Батьківський вузол P або NULL      | y->parent = P, x->parent = y
P->left / P->right | Вказував на x (якщо P != NULL)     | Вказує на y (P->left = y або P->right = y)
root               | Вказівник на корінь всього дерева  | Якщо x_old був коренем, root оновлюється на y
Центровий порядок  | A < X < B < Y < C                  | A < X < B < Y < C (Строго незмінний)
Висота h(x), h(y)  | h(x) = max(h_AB, h_C) + 1          | h(x) = max(h_A, h_B)+1; h(y) = max(h_x, h_C)+1
Розмір s(x), s(y)  | s(x) = 1 + s_A + s_B + s_C         | s(x) = 1 + s_A + s_B; s(y) = 1 + s_x + s_C
```

## 3. Чекліст аудіту та валідації безпеки вказівників

При розробці систем з високими вимогами до надійності (наприклад, реалізації драйверів пристроїв, СУБД або ядерних модулів) код повороту дерева піддається автоматизованій валідації за п'ятьма інваріантами пам'яті.

### 1. Перевірка Null-Safety (Захист від розіменування нульового вказівника)
Функція повороту зобов'язана виконувати вхідну валідацію або містити статики `assert`:
- Якщо `x == NULL`, поворот неможливий (повертається `NULL`).
- Для `rotate_right(x)` обов'язкова перевірка `x->left != NULL`. Спроба виконати правий поворот навколо вузла, який не має лівого сина, призводить до спроби читання за адресою `NULL` та аварійного завершення процесу (`segmentation fault`).

### 2. Перевірка Двоспрямованої Симетрії (Parent-Child Symmetry)
Для будь-якої пари зв'язаних вузлів `U` та `V` в системі повинен виконуватися інваріант двоспрямованості. Якщо батьківський вузол вказує на дитину, дитина зобов'язана посилатися на того самого батька. Зламаний зв'язок у будь-якому з двох напрямків означає фатальну помилку топології графа:
- Якщо `U->left == V`, то `V->parent` зобов'язаний дорівнювати `U`.
- Якщо `U->right == V`, то `V->parent` зобов'язаний дорівнювати `U`.

Під час повороту піддерево `B` змінює свого батька з `Y` на `X`. Якщо знехтувати оновленням `B->parent = X`, інваріант порушується: зворотний прохід від листків до кореня піде хибним шляхом, викликавши невизначену поведінку (`undefined behavior`).

### 3. Перевірка Оновлення Кореневого Вказівника (Root Propagation)
Якщо вузол `X`, що повертається, мав `X->parent == NULL`, це означає, що він був коренем усього дерева. Після повороту новим коренем всієї структури стає `Y`.
- Інтерфейс зобов'язаний записати новий корінь у переданий вказівник: `*root = Y` (у мові C) або `root = Y` (у мові C++).
- Якщо цього не зробити, зовнішній дескриптор дерева збереже посилання на `X`, який тепер опинився на другому рівні. Це призводить до випадання вузла `Y` та всього його другого піддерева з зони досяжності.

### 4. Перевірка Порядку Оновлення Агрегованих Метрик
Вузли дерева часто містять розраховані метрики (висоту `height`, розмір піддерева `size`, суму ключів `sum`).
- При правому повороті вузол `X` стає дитиною вузла `Y`.
- Отже, піддерево з коренем `X` є складовою частиною піддерева `Y`.
- Оновлення метрик **мусить** виконуватися строго у послідовності:
  1. `update_metrics(X);` — спочатку обчислюються нові значення для опущеного вузла.
  2. `update_metrics(Y);` — потім обчислюються значення для нового кореня на основі актуальних даних `X`.
Порушення цього порядку призводить до того, що `Y` порахує свої значення за застарілими метриками `X`, що спотворить балансові фактори вищих рівнів.

### 5. Відсутність Витоків Пам'яті та Циклічних Посилань
Поворот дерева є чисто топологічною операцією перегрупування зв'язків. Він:
- **Не виділяє** нову пам'ять через `malloc`/`new`.
- **Не звільняє** наявну пам'ять через `free`/`delete`.
- **Не змінює** загальну кількість вузлів у дереві.
Якщо інструмент аналізу пам'яті (наприклад, Valgrind або AddressSanitizer) фіксує витік пам'яті під час повороту, це свідчить про некоректний перезапис вказівника, який залишив один з вузлів без єдиного зовнішнього посилання.

## 4. Специфікація крайових випадків (Edge Cases)

При тестуванні модулів повороту дерев обов'язково перевіряються 4 граничні конфігурації:

1. **Поворот кореня всього дерева:** `X->parent == NULL`. Перевіряється коректне оновлення глобального вказівника `root`.
2. **Поворот вузла з порожнім середнім піддеревом:** `B == NULL` (наприклад, у `rotate_right(x)` вузол `Y = x->left` не має правого сина). Перевіряється, що код не намагається виконувати `B->parent = x`.
3. **Поворот у 2-вузловому дереві:** Дерево складається лише з кореня `X` та його сина `Y`. Перевіряється, що опусканий вузол `X` коректно отримує `left = NULL` та `right = NULL`.
4. **Поворот найглибшого листка:** Використовується при тестуванні splay-дерев, коли поворот виконується на найнижчому рівні високої гілки. Перевіряється коректність зв'язку з вищим батьківським вузлом `P`.

## 5. Захисне програмування та автоматизований інваріантний супровід

Для забезпечення абсолютної гарантії надійності у продакшн-коді систем керування бази даних або оперативних операційних систем застосовується захисне програмування. Перед поверненням з функції повороту викликається спеціальна валідаційна процедура `validate_tree_invariants()`. Вона рекурсивно перевіряє, що центровий обхід піддерева строго монотонно зростає, висоти кожного вузла точно дорівнюють `max(left->height, right->height) + 1`, а батьківські зв'язки є симетричними. Завдяки цьому будь-яке викривлення топології ловиться негайно в точці виникнення, запобігаючи неявній псуті даних (silent data corruption) на пізніших етапах роботи алгоритму.
