# 📋 Програмний інтерфейс розв'язувача задачі про призначення

Довідник інтерфейсу програмування описує структури даних, сигнатури функцій, константи помилок та контракт володіння пам'яттю бібліотечного модуля розв'язання задачі про оптимальне призначення.

---

### Огляд архітектури та цільове призначення інтерфейсу

Бібліотечний розв'язувач спроєктовано для забезпечення максимальної продуктивності та надійності в системному й прикладному програмуванні. Модуль надає два взаємодоповнюючі рівні програмного доступу:
1. **Низькорівневий ABI-стабільний інтерфейс мови C** (`hungarian_c_api`):
   Призначений для вбудованих систем, модулів ядра, низькорівневих системних сервісів, а також для безшовної інтеграції в інші мови програмування через механізми Foreign Function Interface (FFI). Зокрема, цей інтерфейс дозволяє викликати оптимізований машинний код із середовищ Python (через `ctypes` або `cffi`), Rust (через `extern "C"`), Go (через `cgo`), C#/.NET (через `DllImport` / `P/Invoke`) та Java (через JNI / Foreign Function & Memory API).
2. **Високорівневий безпечний шаблонний інтерфейс C++20** (`HungarianSolver<T>`):
   Орієнтований на сучасні високонавантажені C++ застосунки. Він побудований на парадигмі нульових накладних витрат (zero-overhead abstractions), використовує концепцію автоматичного управління ресурсами RAII, безпечні неволодіючих зрізи пам'яті `std::span` та надає строгі гарантії безпеки винятків (strong exception safety).

### Контракт параметрів та опис поведінки

#### Параметри функцій
- `matrix` / `flat_matrix`: Вказівник або неволодіючий зріз `std::span` на суцільний одновимірний масив розміром `rows * cols` у пам'яті. Вхідні дані є строго незмінними (кваліфікатор `const`), функція гарантує відсутність будь-якої модифікації буфера користувача.
- `rows`: Кількість виконавців (рядків матриці). Повинно задовольняти строгу умову `rows > 0`.
- `cols`: Кількість завдань (стовпців матриці). Повинно задовольняти строгу умову `cols ≥ rows`.
- `mode` / `target`: Режим розрахунку (`MINIMIZE` для пошуку мінімальних сумарних витрат, `MAXIMIZE` для пошуку максимального сумарного виграшу).
- `out_result`: Вказівник на структуру `HungarianResultC`, куди записуються результати обчислення (тільки для C-інтерфейсу).

#### Поведінка при помилках та коди завершення
1. **У мові C**:
   - Якщо вказівник `matrix` або `out_result` дорівнює `NULL`, функція негайно припиняє виконання та повертає код помилки `HUNGARIAN_ERR_NULL_PTR`.
   - Якщо передано некоректні розмірності матриці (`rows <= 0`, `cols <= 0` або `rows > cols`), повертається код `HUNGARIAN_ERR_INVALID_DIM`.
   - Якщо системний виклик `malloc` не зміг виділити необхідний обсяг оперативної пам'яті під робочі буфери, функція повертає `HUNGARIAN_ERR_NO_MEMORY`, а результуюче поле `out_result->assignment` встановлюється в `NULL`.
   - При успішному розв'язанні повертається `HUNGARIAN_OK` (`0`).
2. **У мові C++**:
   - При виявленні некоректних розмірів матриці (`rows <= 0`, `cols < rows` або `flat_matrix.size() != rows * cols`) метод `HungarianSolver::compute` генерує виняток `std::invalid_argument` з детальним текстовим описом причини.
   - У разі вичерпання доступної системної пам'яті стандартні контейнери генерують виняток `std::bad_alloc`.

### Контракт володіння пам'яттю та життєвий цикл ресурсів

1. **Для мови C**:
   - Пам'ять під масив призначень `out_result->assignment` виділяється всередині функції `hungarian_solve_c` за допомогою системного алокатора `malloc`.
   - Відповідальність за своєчасне звільнення цього масиву повністю покладається на сторону, що викликає функцію. Після завершення використання результату користувач зобов'язаний передати структуру у функцію `hungarian_result_free`.
   - Повторний виклик `hungarian_result_free` на вже очищеній структурі є повністю безпечним (ідемпотентним), оскільки функція перевіряє вказівник на `NULL` і скидає його після звільнення.
2. **Для мови C++**:
   - Усі динамічні ресурси інкапсульовані всередині стандартного контейнера `std::vector<int32_t>`.
   - Життєвий цикл пам'яті повністю керується автоматично за ідіомою RAII (Resource Acquisition Is Initialization). Пам'ять звільняється автоматично при виході об'єкта `AssignmentSolution` з області видимості, що повністю унеможливлює витоки пам'яті навіть при виникненні винятків у користувацькому коді.

### Вирівнювання пам'яті та оптимізація кешу

Для досягнення пікової продуктивності на сучасних процесорах x86-64 та ARM64 рекомендується забезпечувати вирівнювання вхідного буфера матриці на межу кеш-лінії (64 байти). Це запобігає розщепленню кеш-ліній (cache line splitting) під час векторного завантаження інструкціями SIMD (AVX2 / AVX-512):
- У мові C для виділення вирівняної пам'яті слід використовувати функцію `posix_memalign` (POSIX) або `_aligned_malloc` (Windows):
  `void* ptr = NULL; posix_memalign(&ptr, 64, rows * cols * sizeof(int64_t));`
- У мові C++ вирівнювання досягається через `std::aligned_alloc` або спеціалізовані алокатори типу `boost::alignment::aligned_allocator`.

### Інтеграція через Foreign Function Interface (FFI)

Завдяки суворій відповідності стандарту C ABI, функція `hungarian_solve_c` може бути скомпільована у спільну динамічну бібліотеку (`.so` / `.dll` / `.dylib`) і викликатися без проміжного коду з мов високого рівня:

1. **Python (через ctypes)**:
   Вхідна матриця передається як одновимірний масив `ctypes.c_int64`, створений з плоского масиву NumPy: `matrix.ctypes.data_as(ctypes.POINTER(ctypes.c_int64))`. Отриманий масив `assignment` обертається у NumPy-вектор без додаткового копіювання пам'яті.
2. **Rust (через FFI binding)**:
   Оголошується `extern "C"` блок із сигнатурою `hungarian_solve_c`. Безпечна Rust-обгортка перевіряє розміри зрізів `&[i64]` та автоматично викликає `hungarian_result_free` всередині реалізації трейту `Drop`.

### Гарантії безпеки, багатопотоковість та числова стійкість

1. **Потокобезпечність (Thread-Safety)**:
   Обидва інтерфейси не використовують жодних глобальних, статичних чи потоко-локальних змінних стану. Усі робочі буфери виділяються виключно в межах локального контексту конкретного виклику. Інтерфейси є строго реентрабельними та потокобезпечними: довільна кількість паралельних потоків може одночасно виконувати розв'язання різних задач без використання блокувань, м'ютексів чи критичних секцій.
2. **Числова стійкість та захист від переповнення**:
   Усі проміжні розрахунки потенціалів та залишків використовують 64-бітні знакові цілі числа `int64_t` або тип `CostType`. Значення константи нескінченності обмежене величиною `INT64_MAX / 4`, що гарантує відсутність арифметичного переповнення при додаванні локальних дельт `u[i] + Δ` навіть для матриць великої розмірності (`N > 10000`).
