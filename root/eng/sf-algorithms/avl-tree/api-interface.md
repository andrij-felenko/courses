# 📋 Довідник інтерфейсу та складності операцій AVL-дерева

Цей довідник містить формальну специфікацію інтерфейсу, детальний аналіз структури вузла та її розміщення в пам'яті, порівняльну характеристику часової та просторової складності, а також контрактні інваріанти операцій для **AVL-дерева** (англ. *AVL tree*).

## 1. Специфікація асимптотичної складності операцій

AVL-дерево забезпечує суворі логарифмічні гарантії часу виконання завдяки дотримання інваріанта обмеження висоти `h < 1.4404 · log₂ (n + 2)`.

| Операція | Середній випадок | Найгірший випадок | Допоміжна пам'ять | Кількість обертань |
| :--- | :--- | :--- | :--- | :--- |
| **Пошук за ключем (`contains / find`)** | `O(log n)` | `O(log n)` | `O(1)` (ітеративно) | 0 |
| **Пошук найменшого/найбільшого (`min / max`)** | `O(log n)` | `O(log n)` | `O(1)` | 0 |
| **Знаходження межі (`lower_bound / upper_bound`)**| `O(log n)` | `O(log n)` | `O(1)` | 0 |
| **Знаходження наступника/попередника** | `O(log n)` | `O(log n)` | `O(1)` | 0 |
| **Діапазонна вибірка (`range_query`)** | `O(log n + k)` | `O(log n + k)` | `O(log n + k)` | 0 |
| **Вставка елемента (`insert`)** | `O(log n)` | `O(log n)` | `O(log n)` (стек викликів) | ≤ 1 (мале або велике) |
| **Видалення елемента (`remove / delete`)** | `O(log n)` | `O(log n)` | `O(log n)` (стек викликів) | від 0 до `O(log n)` |
| **Симетричний обхід (`in_order_traversal`)** | `O(n)` | `O(n)` | `O(log n)` (стек викликів) | 0 |
| **Очищення всього дерева (`clear`)** | `O(n)` | `O(n)` | `O(log n)` | 0 |
| **Загальне споживання пам'яті** | `O(n)` | `O(n)` | `O(n)` на `n` вузлів | — |

### Докладний порівняльний аналіз із альтернативними структури даних

Для правильного інженерного вибору структури даних важливо порівнювати AVL-дерево з іншими впорядкованими та невпорядкованими контейнерами:

1. **Порівняння з незбалансованим двійковим деревом пошуку:**
   - Незбалансоване двійкове дерево пошуку має простішу реалізацію та не витрачає пам'яті на зберігання висот. Проте на відсортованих вхідних даних воно вироджується у список, де складність пошуку, вставки та видалення стає `O(n)`. AVL-дерево усуває цей ризик і гарантує `O(log n)` завжди.

2. **Порівняння з червоно-чорним деревом:**
   - Червоно-чорне дерево має послаблений інваріант висоти (`h ≤ 2 log₂ n`). Завдяки цьому вставка та видалення викликають менше обертань, що робить його привабливим для модифікованих контейнерів широкого призначення. Проте AVL-дерево має меншу середню та максимальну висоту, що забезпечує на 15–20% швидший пошук на статичних та напівстатичних наборах даних.

3. **Порівняння з B-деревом:**
   - B-дерево орієнтоване на зовнішню пам'ять (твердотільні накопичувачі SSD та жорсткі диски HDD) і групує елементи у великі вузли-сторінки розміром 4 КБ або 16 КБ, мінімізуючи операції читання з диска. AVL-дерево призначене для оперативної пам'яті (RAM), де покажчикова адресація виконується за наносекунди.

4. **Порівняння з хеш-таблицею:**
   - Хеш-таблиці пропонують середню складність `O(1)` для точкового пошуку, але не підтримують порядок. У хеш-таблиці неможливо ефективно знайти мінімум, максимум або виконати діапазонну вибірку (англ. *range query*). AVL-дерево тримає ключі впорядкованими і підтримує операції `lower_bound` та `upper_bound` за `O(log n)`.

## 2. Формат вузла та вирівнювання у пам'яті

На 64-бітній архітектурі (x86_64, ARM64) фізичне розміщення полів структури `Node` має такий вигляд:

:::tabs
```c
typedef struct Node {
    KeyType key;         // 8 байт (для int64_t або покажчика)
    int height;          // 4 байти (висота піддерева)
    // 4 байти неявного вирівнювання (padding) для 8-байтового межі
    struct Node *left;   // 8 байт (покажчик на лівого сина)
    struct Node *right;  // 8 байт (покажчик на правого сина)
} Node;
```
```cpp
template <typename T>
struct Node {
    T key;                                 // Значення ключа
    int height{1};                         // Висота піддерева
    std::unique_ptr<Node> left{nullptr};   // Автоматичне володіння лівим сином
    std::unique_ptr<Node> right{nullptr};  // Автоматичне володіння правим сином

    explicit Node(T val) : key(std::move(val)) {}
};
```
:::

### Аналіз розміру та оптимізаційні підходи

- **Стандартний розмір вузла:** 32 байти на 64-бітних системах (з урахуванням 4 байтів компіляторного вирівнювання).
- **Оптимізація фактора балансу:** Оскільки фактор балансу набуває лише трьох значень `{-1, 0, +1}`, його можна зберігати у двобітовому полі (`int8_t balance`). Також можливе упаковка прапорців балансу у молодші невикористовувані біти покажчиків `left` чи `right` (техніка *tagged pointers*), що дозволяє зменшити розмір вузла до 24 байтів.

## 3. Формальні контракти та інваріанти інтерфейсу

### 3.1. Функція обчислення висоти та балансу

:::tabs
```c
int get_height(const Node *node);
int get_balance(const Node *node);
```
```cpp
static int getHeight(const std::unique_ptr<Node>& node) noexcept;
static int getBalance(const std::unique_ptr<Node>& node) noexcept;
```
:::

- **Предумова:** Об'єкт `node` є дійсним покажчиком або `NULL` (`nullptr`).
- **Постумова:** Повертає 0, якщо `node == NULL`, або значення `node->height > 0`, якщо вузол існує. `get_balance` повертає різницю `h(Right) - h(Left)`.
- **Винятки / Помилки:** Ніколи не генерує винятків (`noexcept`).
- **Інваріант збалансованості:** Після завершення будь-якої публічної операції вставки або видалення для кожного вузла виконується умова `get_balance(node) ∈ {-1, 0, +1}`.

### 3.2. Операції обертання піддерев

:::tabs
```c
Node* rotate_right(Node *y);
Node* rotate_left(Node *x);
```
```cpp
static std::unique_ptr<Node> rotateRight(std::unique_ptr<Node> y);
static std::unique_ptr<Node> rotateLeft(std::unique_ptr<Node> x);
```
:::

- **Призначення:** Ліквідують перекоси LL та RR за час `O(1)`.
- **Постумова:** Повертають новий корінь піддерева з оновленими висотами.

### 3.3. Операції вставки та видалення

:::tabs
```c
Node* insert(Node *root, KeyType key);
Node* delete_node(Node *root, KeyType key);
```
```cpp
void insert(T key);
void remove(const T& key);
```
:::

- **Предумова:** `root` є коренем коректного AVL-дерева (або `NULL`).
- **Постумова:** Модифікують дерево із збереженням інваріанта BST та AVL-балансу за час `O(log n)`.
- **Гарантія балансування:** Вставка виконує не більше ніж 1 обертання; видалення виконує від 0 до `O(log n)` каскадних обертань.

## 4. Обробка крайових випадків та помилок

Під час практичного використання AVL-дерева можуть виникати такі нестандартні та крайові ситуації:

1. **Спроба видалення відсутнього ключа:**
   - Алгоритм виконує звичайний логарифмічний спуск до порожнього покажчика `NULL`, після чого повертає початкове дерево без внесення змін і без виконання обертань.

2. **Спроба вставки вже наявного ключа:**
   - За стандартного контракту унікальності тотожні ключі ігноруються. Якщо необхідна підтримка однакових ключів, структура вузла доповнюється полем лічильника частоти `size_t count`, або нові елементи розміщуються у правому піддереві з відповідною адаптацією умов порівняння `<=`.

3. **Вичерпання пам'яті під час вставки:**
   - У мові C функція `malloc` повертає `NULL`. Обробник повинен перевіряти результат і залишати дерево у вихідному коректному стані без витоків пам'яті. У C++ функція `std::make_unique` ґенерує виняток `std::bad_alloc`, при цьому стек рекурсії безпечно згортається (гарантія строкрової безпеки щодо винятків).

## 5. Апаратні аспекти та кешова локальність (CPU Cache Dynamics)

На сучасних процесорах швидкість обробки структур даних суттєво залежить від ефективності використання кеш-пам'яті L1/L2/L3:

- **Недолік покажчикових дерев:** Кожен вузол AVL-дерева виділяється окремо в динамічній пам'яті (купі). Вузли розташовуються за довільними адресами, тому перехід за покажчиками `node->left` та `node->right` призводить до частого виникнення промахів кешу (англ. *cache misses*).
- **Вплив висоти на кеш:** Завдяки тому, що AVL-дерево має меншу висоту (`1.44 log₂ n`), воно виконує менше переходів за покажчиками, ніж червоно-чорне дерево (`2.00 log₂ n`). Це дає перевагу у швидкості виконання на процесорах із глибокими конвеєрами та повільним доступом до RAM.
- **Оптимізація пулами пам'яті:** Для покращення кешевої локальності вузли AVL-дерева рекомендується виділяти суцільними блоками за допомогою арена-алокаторів (англ. *arena allocators*) або пулів об'єктів (англ. *memory pools*).

## 6. Багатопотокова безпека та потокозахищеність

- **Паралельне читання:** Оскільки операція пошуку (`search / contains`) не змінює структуру дерева і не модифікує покажчики, довільна кількість потоків може одночасно читати AVL-дерево без блокувань (англ. *lock-free read*).
- **Модифікація в кількох потоках:** Вставка та видалення змінюють висоти і виконують обертання покажчиків, тому одночасне внесення змін вимагає зовнішньої синхронізації (наприклад, за допомогою м'ютекса `std::shared_mutex` у режимі ексклюзивного блокування для запису).
- **Персистентні версії:** Для неблокуючого паралельного доступу AVL-дерево може бути реалізоване з використанням механізму [Copy-on-Write](topic:sf-algorithms/copy-on-write-structures) (шляхового копіювання), що створює нові версії вузлів уздовж шляху модифікації без зміни існуючих.
