# 📋 Довідник синтаксису, обмежень та модифікаторів Extended Asm

Цей довідник містить повну специфікацію контракту розширеного вбудованого асемблера (Extended Assembly) компіляторів GCC та Clang, включаючи формальну граматику, модифікатори операндів, архітектурні обмеження (constraints), список зіпсованих ресурсів (clobbers) та мітки переходів `asm goto`.

У традиційній мовній моделі C/C++ компілятор самостійно транслює абстрактні операції у послідовність машинних команд. Проте під час використання розширеного асемблера програміст укладає з розподілювачем регістрів та планувальником інструкцій строгий контракт. Цей довідник систематизує всі елементи такого контракту, описуючи правила, за якими компілятор зв'язує змінні високого рівня з фізичними регістрами процесора та керує побічними ефектами.

## Граматика виклику Extended Asm

Формальний синтаксис виразу розширеного вбудованого асемблера складається з текстового шаблону інструкцій та чотирьох опціональних секцій, розділених символом двокрапки:

```text
asm [volatile] [inline] [goto] (
    "AssemblerTemplate"
    : OutputOperands    /* Секція вихідних операндів */
    : InputOperands     /* Секція вхідних операндів */
    : Clobbers          /* Секція зіпсованих ресурсів */
    : GotoLabels        /* Секція міток переходу (тільки для форми asm goto) */
);
```

Кожне ключове слово та атрибут визначає поведінку оптимізаційного конвеєра:

- `asm` або `__asm__`: головний оператор вставки. Варіант з подвійними підкресленнями використовується в суворому режимі сумісності зі стандартами ANSI C та ISO C++, коли ключове слово `asm` може конфліктувати зі сторонніми ідентифікаторами.
- `volatile` або `__volatile__`: забороняє оптимізатору видаляти асемблерну вставку як мертвий код (навіть якщо жоден з її вихідних операндів не використовується далі) та блокує винесення блоку за межі циклів у ході оптимізації LICM (Loop-Invariant Code Motion).
- `inline`: спеціальна підказка для евристики розгортання функцій. Повідомляє компілятору, що асемблерний блок займає мінімальну кількість байтів у пам'яті програм, що заохочує інлайнінг функції в місці виклику.
- `goto`: активує розширення, яке дозволяє асемблерним інструкціям здійснювати прямі переходи на мітки мови C/C++.

## Секції операндів та позиційна адресація

Операнди у вихідній та вхідній секціях задаються списками, розділеними комами. Кожен елемент описується кортежем: `[символьне_ім'я] "рядок_обмеження" (вираз_мови_C)`.

Компілятор нумерує всі операнди послідовно, починаючи від `%0` для першого вихідного операнда і продовжуючи нумерацію через усю секцію входів:

:::tabs
```c
/* Позиційна адресація: %0 — dst (вихід), %1 — src (вхід) */
void copy_value_positional(int src, int *dst) {
    __asm__ ("movl %1, %0" : "=r" (*dst) : "r" (src));
}

/* Іменована адресація: %[out] та %[in] усувають плутанину з номерами */
void copy_value_named(int src, int *dst) {
    __asm__ ("movl %[in], %[out]" : [out] "=r" (*dst) : [in] "r" (src));
}
```
```cpp
/* Ідіоматичний еквівалент на C++ */
void copy_value_positional(int src, int &dst) noexcept {
    asm ("movl %1, %0" : "=r" (dst) : "r" (src));
}

void copy_value_named(int src, int &dst) noexcept {
    asm ("movl %[in], %[out]" : [out] "=r" (dst) : [in] "r" (src));
}
```
:::

Якщо в тексті асемблерного шаблону необхідно використати буквальний символ відсотка (наприклад, для позначення імені регістра `%eax` у діалекті AT&T), його слід подвоїти: `%%eax`. Це запобігає спробі компілятора інтерпретувати назву регістра як номер операнда.

### Модифікатори обмежень (Constraint Modifiers)

Модифікатор записується на початку рядка обмеження і визначає правила взаємодії генератора коду з розподілювачем регістрів:

| Модифікатор | Назва | Механізм і призначення |
| :---: | :--- | :--- |
| `=` | Write-Only | Операнд є виключно вихідним. Компілятор вважає попереднє значення змінної знищеним і перезаписує його результатом виконання інструкції. |
| `+` | Read-Write | Операнд є одночасно і входом, і виходом (Read-Modify-Write). Компілятор завантажує початкове значення змінної в регістр перед початком вставки і зберігає оновлений результат після неї. |
| `&` | Earlyclobber | Операнд модифікується ДО того, як процесор завершить зчитування всіх вхідних операндів. Забороняє розподілювачу регістрів призначати цьому виходу той самий фізичний регістр, що й будь-якому входу. |
| `%` | Commutative | Оголошує операцію комутативною з наступним за порядком операндом. Надає оптимізатору право міняти місцями регістри операндів задля зменшення кількості інструкцій пересилання `mov`. |

## Базові загальні обмеження (Generic Constraints)

Загальні обмеження є платформонезалежними та підтримуються бекендами всіх цільових архітектур GCC та LLVM/Clang:

| Символ | Тип ресурсу | Опис та поведінка розподілювача |
| :---: | :--- | :--- |
| `r` | Регістр | Довільний регістр загального призначення (General Purpose Register). Алокатор обирає найменш завантажений регістр. |
| `m` | Пам'ять | Пряма адресація оперативної пам'яті (`[base + index*scale + disp]`). Не витрачає жодного апаратного регістра. |
| `i` | Константа | Ціле числове значення або константний вираз, відомий на етапі компіляції (Immediate). Кодується прямо в тіло інструкції. |
| `n` | Числова константа | Ціла константа з відомим числовим значенням (на відміну від `i`, виключає символьні адреси лінкування). |
| `g` | Універсальне | Будь-який доступний варіант (`r`, `m` або `i`). Надає компілятору повну свободу вибору найдешевшого варіанта адресації. |
| `0` .. `9` | Збіг номерів | Вимагає, щоб вхідний операнд був розміщений у точно тому самому фізичному регістрі, що й відповідний вихідний операнд із зазначеним номером. |
| `X` | Довільний | Дозволяє передати абсолютно будь-який операнд, коректний для цільового асемблера (включаючи нетипізовані мітки). |

### Багатоваріантні обмеження (Multiple Alternative Constraints)

Компілятори підтримують визначення кількох альтернативних наборів обмежень через кому (наприклад, `"r,m"` або `"r,i"`). Це дозволяє розподілювачу регістрів обрати оптимальний шлях генерації коду: якщо змінна вже знаходиться в пам'яті або в регістрі, компілятор обирає відповідну гілку без генерації зайвих команд завантаження.

## Специфічні архітектурні обмеження

Кожна процесорна мікроархітектура має унікальні апаратні регістри зі спеціалізованим призначенням (наприклад, множення, ділення, зсуви або векторна обробка). Для прямого доступу до них використовуються специфічні літерні обмеження.

### Архітектура x86 / x86-64

| Обмеження | Призначений регістр / Ресурс |
| :---: | :--- |
| `a` | Регістр акумулятора: `RAX`, `EAX`, `AX`, `AL` (множення, ділення, рядкові інструкції, системні виклики) |
| `b` | Базовий регістр: `RBX`, `EBX`, `BX`, `BL` |
| `c` | Регістр лічильника: `RCX`, `ECX`, `CX`, `CL` (апаратні зсуви `shl`/`shr`, лічильники циклів `rep`) |
| `d` | Регістр даних: `RDX`, `EDX`, `DX`, `DL` (старша частина добутку при множенні, залишок при діленні) |
| `S` | Індекс джерела: `RSI`, `ESI`, `SI` (рядкові операції `movsb`, `lodsb`) |
| `D` | Індекс приймача: `RDI`, `EDI`, `DI` (рядкові операції `stosb`, перший аргумент System V ABI) |
| `q` | Будь-який байт-адресовний регістр: `a`, `b`, `c`, `d` у 32-розрядному режимі; усі регістри GP у 64-розрядному |
| `x` | Векторний регістр SSE / AVX: `XMM0`–`XMM15` |
| `v` | Розширений векторний регістр AVX-512: `XMM`, `YMM`, `ZMM` |

### Суфікси модифікації розміру операнда в x86

Якщо операнд зв'язано з 64-розрядним регістром (наприклад, `rax`), але конкретна машинна інструкція вимагає його молодшої 32-бітної або 8-бітної частини, у шаблоні вказуються додаткові символи модифікації:

- `%k0` — форсує 32-розрядний регістр (наприклад, `eax` замість `rax`);
- `%w0` — форсує 16-розрядний регістр (наприклад, `ax`);
- `%b0` — форсує молодший 8-розрядний байт (`al`, `bl`, `cl`, `dl`);
- `%h0` — форсує старший 8-розрядний байт (`ah`, `bh`, `ch`, `dh`).

### Архітектура ARM / AArch64

| Обмеження | Призначений регістр / Ресурс |
| :---: | :--- |
| `r` | Регістри загального призначення: `X0`–`X30` / `W0`–`W30` (AArch64) або `R0`–`R14` (ARM32) |
| `w` | Векторний / FPU регістр: `V0`–`V31` (AArch64) або `S0`–`S31` / `D0`–`D31` (ARM32) |
| `I` | Константа для безпосереднього додавання або віднімання (12-бітний діапазон з опціональним зсувом) |
| `J` | 16-бітна константа для інструкцій переміщення з обнуленням чи інверсією `movz`/`movn` |
| `K` | 32-бітна константа, що представляє бітову маску для логічних інструкцій `and`/`orr` |

### Архітектура RISC-V

| Обмеження | Призначений регістр / Ресурс |
| :---: | :--- |
| `r` | Цілочисельні регістри загального призначення `x0`–`x31` (включаючи `a0`–`a7`, `t0`–`t6`, `s0`–`s11`) |
| `f` | Регістри чисел з рухомою комою стандартних розширень F/D/Q: `f0`–`f31` |
| `I` | Знакова 12-бітна безпосередня константа (Immediate для інструкцій `addi`, `lw`, `jalr`) |
| `K` | 5-бітне безпосереднє число для операцій побітового зсуву (`slli`, `srli`, `srai`) |

## Секція зіпсованих ресурсів (Clobbers)

Секція Clobbers є критичним механізмом безпеки, через який програміст інформує компілятор про неявні побічні ефекти асемблерного блоку:

```text
asm volatile ("..." : /* виходи */ : /* входи */ : "rax", "rcx", "memory", "cc");
```

### Семантика ключових clobber-елементів

1. `"memory"` (**Програмний бар'єр компілятора / Compiler Memory Barrier**):
   Повідомляє оптимізатору, що асемблерна вставка виконує довільне читання або запис в оперативну пам'ять за невідомими адресами. Компілятор зобов'язаний зберегти всі модифіковані змінні, які наразі утримуються в регістрах процесора, назад у пам'ять перед виконанням цієї вставки. Після завершення блоку всі попередньо кешовані в регістрах значення вважаються недійсними (stale) і за потреби зчитуються з фізичної пам'яті заново.
2. `"cc"` (**Арифметичні прапорці стану**):
   Інформує компілятор про те, що інструкції змінюють прапорці процесора (Zero Flag, Carry Flag, Overflow Flag тощо). Якщо після асемблерного блоку в коді на C/C++ слідує умовний вираз, компілятор знає, що стан прапорців не зберігся, і згенерує нову інструкцію порівняння `cmp` або `test`.
3. Фізичні назви регістрів (`"rax"`, `"xmm0"`, `"r11"`):
   Попереджає генератор коду, що вказані регістри будуть безповоротно змінені в процесі роботи вставки. Розподілювач регістрів гарантує, що жодна важлива змінна програми не буде розташована в цих регістрах під час виконання вставки.

## Взаємодія зі стеком, Red Zone та збереженими регістрами

При роботі з вбудованим асемблером існують критичні обмеження щодо маніпуляцій з апаратним стеком:

- **Червона зона (Red Zone) у System V AMD64 ABI:** стандарт дозволяє компілятору зберігати тимчасові локальні змінні у 128-байтовій зоні нижче поточного покажчика стека `%rsp` без його явної зміни. Якщо всередині асемблерної вставки викликати інструкцію `push` або вручну змінити `%rsp`, вміст цієї червоної зони буде миттєво знищено, що призведе до катастрофічного краху програми. Для безпечного використання `push` у коді ядра або системних драйверах збірка повинна здійснюватися з прапорцем `-mno-red-zone`.
- **Заборона модифікації покажчика кадру (`%rbp` / `%ebp`):** якщо ввімкнено створення кадрів стека (без `-fomit-frame-pointer`), спроба вказати `%rbp` у списку clobbers або модифікувати його призведе до помилки компілятора, оскільки цей регістр є критично необхідним для розгортання стека (Stack Unwinding) та обробки винятків.

## Мітки переходу (asm goto)

Синтаксична форма `asm goto` дозволяє передавати керування безпосередньо на мітки мови C/C++, уникаючи проміжних прапорців та зайвих умовних переходів у коді високого рівня:

:::tabs
```c
#include <stdbool.h>

/* Прямий стрибок на мітку error_handler у разі виникнення переносу */
bool check_add_overflow(unsigned long a, unsigned long b, unsigned long *res) {
    __asm__ __volatile__ goto (
        "addq %[val], %[dest]\n\t"
        "jc %l[overflow_label]"
        : [dest] "+r" (a)
        : [val] "r" (b)
        : "cc"
        : overflow_label
    );
    
    *res = a;
    return false;

overflow_label:
    return true;
}
```
```cpp
#include <utility>

/* C++ варіант з поверненням прапорця успіху */
bool check_add_overflow(unsigned long a, unsigned long b, unsigned long &res) noexcept {
    asm volatile goto (
        "addq %[val], %[dest]\n\t"
        "jc %l[overflow_label]"
        : [dest] "+r" (a)
        : [val] "r" (b)
        : "cc"
        : overflow_label
    );
    
    res = a;
    return false;

overflow_label:
    return true;
}
```
:::

Починаючи з GCC 9 та Clang 9, конструкція `asm goto` підтримує не лише вхідні, але й вихідні операнди (форма `asm goto with outputs`), що дозволяє одночасно повертати обчислені значення по звичайному шляху виконання та передавати керування на мітки виняткових ситуацій з мінімальними накладними витратами.
