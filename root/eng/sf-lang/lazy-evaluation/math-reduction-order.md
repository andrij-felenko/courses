# 🧮 Стратегії редукції лямбда-числення та теореми стандартизації

Теоретичним фундаментом усіх мов програмування з лінивим та строгим обчисленням є безтипове лямбда-числення Алонзо Черча. Питання про те, коли вираз слід обчислювати і чи завершиться програма результатом, формалізується як вибір **стратегії редукції** (англ. *reduction strategy*) термів.

### Синтаксис, редекси та β-редукція

У чистому лямбда-численні будь-який вираз (терм) будується за трьома правилами:

```
t ::= x          [змінна]
    | λx. t      [абстракція / анонімна функція]
    | t₁ t₂      [застосування / аплікація]
```

Основним правилом обчислення є **β-редукція** (англ. *beta-reduction*): застосування функції до аргументу шляхом заміни формального параметра на тіло аргументу:

```
(λx. e₁) e₂  →β  e₁[x ↦ e₂]
```

Тут `e₁[x ↦ e₂]` позначає коректну підстановку виразу `e₂` замість усіх вільних входжень змінної `x` у виразі `e₁` (з перейменуванням зв'язаних змінних за потреби для уникнення захоплення імен, тобто α-конверсією).

Підвираз вигляду `(λx. e₁) e₂` називають **редексом** (англ. *redex*, від *reducible expression*). Якщо терм не містить жодного редексу, він перебуває у **нормальній формі** (англ. *normal form*). Нормальна форма відповідає остаточному значенню результату програми, яке вже не можна спростити.

### Конфлюентність: теорема Черча — Россера

Якщо вираз містить кілька різних редексів у різних піддеревах, порядок їх вибору може різнитися. Чи залежить кінцевий результат від того, в якому порядку ми спрощуємо вираз?

Відповідь дає фундаментальна **перша теорема Черча — Россера** (1936), відома також як властивість **конфлюентності** (англ. *confluence* або *diamond property*):

```
         a
       ↙   ↘
     b       c
      *↘   ↙*
         d
```

> **Теорема 1 (Черч — Россер).** Якщо терм `a` редукується за скінченну кількість кроків до термів `b` та `c` (`a →* b` і `a →* c`), то існує такий терм `d`, до якого можна зредукувати як `b`, так і `c` (`b →* d` і `c →* d`).

**Прямий наслідок:** якщо терм має нормальну форму, то ця **нормальна форма єдина** (з точністю до α-еквівалентності). Байдуже, якою дорогою редукцій ви підете — ви не можете отримати дві різні правильні відповіді.

Проте теорема Черча — Россера гарантує лише єдиність результату, якщо ми до нього дійшли. Вона **не гарантує**, що довільна обрана дорога взагалі завершиться.

### Нетермінація та елемент ⊥ (Bottom)

Не кожен терм можна звести до нормальної форми. Класичним прикладом вічного циклу є комбінатор `Ω`:

```
ω ≡ λx. x x
Ω ≡ ω ω = (λx. x x) (λx. x x)
```

Застосуємо β-редукцію до `Ω`:
```
(λx. x x) (λx. x x)  →β  (x x)[x ↦ (λx. x x)]  =  (λx. x x) (λx. x x)  =  Ω
```

Терм `Ω` за один крок редукції переходить сам у себе. Його редукція триває нескінченно. У денотаційній семантиці такі нетермінуючі обчислення (а також обчислення, що завершуються фатальною помилкою) позначають символом `⊥` (англ. *bottom*).

Тепер розглянемо поведінку виразу, де один аргумент є корисним, а інший — нескінченним циклом. Нехай функція `K` відкидає свій другий аргумент:

```
K ≡ λx. λy. x
Const₄₂ ≡ K 42 = (λx. λy. x) 42  →β  λy. 42
```

Розглянемо редукцію виразу `Const₄₂ Ω`:

```
E ≡ (λy. 42) Ω
```

Тут є два конкуруючих редекси:
1. Зовнішній редекс: застосування `(λy. 42)` до `Ω`.
2. Внутрішній редекс: сам терм `Ω = (λx. x x) (λx. x x)`.

### Аплікативний порядок проти нормального порядку

Вибір порядку розкриття цих редексів породжує дві протилежні стратегії:

1. **Аплікативний порядок (Applicative Order / Call-by-Value):** завжди спершу редукувати найглибший (внутрішній) редекс, тобто обчислювати аргументи до їх підстановки у функцію.
   Спробуємо обчислити `(λy. 42) Ω`:
   ```
   (λy. 42) Ω  →  (λy. 42) Ω  →  (λy. 42) Ω  →  ... [нескінченний цикл, ⊥]
   ```
   Програма зависає, намагаючись обчислити невикористаний аргумент.

2. **Нормальний порядок (Normal Order / Call-by-Name):** завжди спершу редукувати **найлівіший-зовнішній** (англ. *leftmost-outermost*) редекс.
   Спробуємо обчислити той самий вираз:
   ```
   (λy. 42) Ω  →β  42   [успішне завершення за 1 крок!]
   ```
   Зовнішній редекс розкривається, аргумент `Ω` підставляється замість `y`, але оскільки `y` не зустрічається в тілі, `Ω` просто зникає з виразу.

Чому нормальний порядок є математично вищим за будь-який інший? Відповідь дає фундаментальна теорема стандартизації.

### Теорема стандартизації Каррі — Фейса

> **Теорема 2 (Стандартизація / Повнота нормального порядку).** Якщо терм `t` взагалі має нормальну форму, то редукція в нормальному порядку (leftmost-outermost) **гарантовано завершиться і знайде цю нормальну форму**.

Жодна інша детермінована стратегія обчислень не має більшої області збіжності, ніж нормальний порядок. Якщо програма завершується хоча б за якоїсь послідовності кроків — нормальний порядок знайде цей результат. Якщо нормальний порядок зациклюється — вираз не має нормальної форми в принципі.

### Проблема ефективності: дублювання редексів

Чому ж усі компілятори не використовують чистий нормальний порядок?

Через проблему дублювання роботи. Розглянемо функцію подвоєння аргументу:

```
Double ≡ λx. x + x
```

Нехай аргументом є довге обчислення `E` (наприклад, `2 + 3`). При нормальному порядку:

```
Double E
= (λx. x + x) (2 + 3)
→β (2 + 3) + (2 + 3)        [аргумент продубльовано!]
→  5 + (2 + 3)              [перше додавання]
→  5 + 5                    [друге додавання — повторна робота!]
→  10
```

Якщо функція застосовує аргумент `k` разів, а всередині нього є інші вкладені виклики, кількість редукцій зростає **експоненційно** від глибини викликів: `O(kⁿ)`.

### Графова редукція та Call-by-Need

Розв'язанням цієї дилеми став перехід від синтаксичних дерев до **напрямлених ациклічних графів (DAG)**, запропонований Крістофером Водсвортом (1971) і формалізований Жан-Жаком Леві (Jean-Jacques Lévy) у теорії оптимальних редукцій.

У графовому лямбда-численні вираз `(λx. x + x) (2 + 3)` представляється вузлом аплікації, де зв'язана змінна `x` представлена двома ребрами, що вказують на **один спільний вузол** `(2 + 3)`:

```
    [ + ]
   ↙     ↘
 [ 2 + 3 ] ── (єдиний спільний вузол у пам'яті)
```

Правило редукції **Call-by-Need** формулюється так:
1. Застосовуємо редукцію за правилом нормального порядку (найлівіший-зовнішній редекс).
2. Якщо редукується спільний підвираз, ми не копіюємо його вміст, а **мутуємо вузол графа на місці**, підставляючи результат редукції.

Покрокове обчислення на графі:
```
Крок 1:  [ + ] з двома вказівниками на вузол N
Крок 2:  Операція + вимагає значень своїх операндів. Вузол N (2 + 3) редукується до 5.
Крок 3:  Вузол N перезаписується значенням 5.
Крок 4:  Обидва операнди операції + тепер автоматично вказують на вже готове число 5.
Крок 5:  5 + 5 → 10.
```

**Головний результат теорії:** редукція графів за схемою Call-by-Need володіє властивістю **повноти нормального порядку** (обчислює результат завжди, коли нормальна форма існує), але **гарантує, що кожен спільний редекс редукується щонайбільше один раз**.
