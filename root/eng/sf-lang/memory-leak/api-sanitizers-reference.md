# 📋 Довідник інструментів діагностики витоків: LSan, Valgrind та eBPF

Виявлення, локалізація та усунення витоків динамічної пам'яті вимагають спеціалізованого інструментарію, який діє на різних рівнях виконання програмного коду: від компіляторної інструментації та бінарної емуляції до низькорівневого трасування ядра операційної системи. Нижче наведено детальний довідник інтерфейсів, командних прапорів, змінних оточення та програмних API для трьох провідних діагностичних технологій: LeakSanitizer, Valgrind Memcheck та eBPF memleak.

### 1. LeakSanitizer (LSan / Clang & GCC)

LeakSanitizer (LSan) інтегровано безпосередньо в генератор коду компіляторів LLVM/Clang та GNU GCC. На відміну від важких емуляторів, LSan вбудовує перехоплювачі системних функцій виділення та звільнення пам'яті (`malloc`, `free`, `realloc`, `calloc`, `new`, `delete`) безпосередньо у виконуваний бінарний файл.

Під час завершення процесу або за явним викликом API бібліотека LSan тимчасово призупиняє виконання всіх користувацьких потоків через механізм міжпроцесних сигналів, після чого запускає алгоритм Mark-and-Sweep. Сканування починається з так званих «кореневих областей пам'яті» (Root Regions):
- Регістри процесора кожного активного потоку виконання;
- Стекові кадри всіх потоків від поточної вершини стека до базової адреси кадру;
- Глобальні змінні та статичні буфери в сегментах двійкового образу `.data` та `.bss`;
- Області локальної пам'яті потоків (Thread-Local Storage, TLS).

Будь-який блок динамічної пам'яті на купі, адреса якого не зустрічається серед значень кореневих регіонів і на який не вказують інші живі блоки, класифікується як витік.

| Прапор компіляції | Опис та поведінка |
|---|---|
| `-fsanitize=leak` | Вмикає виключно механізм пошуку витоків (мінімальні накладні витрати CPU та пам'яті). |
| `-fsanitize=address` | Вмикає повний AddressSanitizer (на платформі x86_64 LSan активується автоматично). |
| `-g` або `-g3` | Генерує налагоджувальну таблицю символів формату DWARF для зіставлення адрес із номерами рядків коду. |
| `-fno-omit-frame-pointer` | Забороняє компілятору оптимізувати регістр `rbp`, що гарантує точне та швидке розгортання стека викликів. |

#### Керування через змінну середовища `LSAN_OPTIONS`

Усі параметри роботи LeakSanitizer задаються перед запуском бінарного файлу через змінну середовища `LSAN_OPTIONS` у вигляді списку параметрів, розділених двокрапкою:

```bash
export LSAN_OPTIONS="detect_leaks=1:report_objects=1:suppressions=leaks.supp:exitcode=23"
```

Кожен параметр змінює поведінку підсистеми аудиту:
- `detect_leaks=1` — активує сканування пам'яті під час виходу з програми через `exit()` або повернення з `main()`. Встановлення значення `0` вимикає перевірку (корисно, якщо санітайзер увімкнено для пошуку помилок роботи з пам'яттю, але витоки перевіряються окремим кроком).
- `report_objects=1` — вмикає детальний звіт про типи знайдених об'єктів та їхні внутрішні зміщення.
- `suppressions="path/to/file.supp"` — вказує шлях до текстового файлу з регулярними виразами або назвами функцій, витоки в яких слід ігнорувати.
- `exitcode=23` — код повернення, який процес передає операційній системі у разі виявлення хоча б одного витоку. Це дозволяє автоматичним конвеєрам збірки CI/CD зупиняти інтеграційні тести при виявленні регресій пам'яті.
- `max_leaks=10` — обмежує максимальну кількість звітів про витоки, запобігаючи переповненню логів при масових помилках.

#### Програмний інтерфейс C/C++ (`sanitizer/lsan_interface.h`)

Для довгоживучих серверних застосунків, які не завершуються під час тестування, LSan надає програмний API, що дозволяє виконувати діагностику пам'яті в довільні моменти часу:

```cpp
#include <sanitizer/lsan_interface.h>

// Примусовий запуск перевірки витоків. У разі виявлення втрачених блоків
// друкує звіт і негайно перериває процес з аварійним кодом exitcode.
void __lsan_do_leak_check(void);

// Примусова перевірка без аварійної зупинки: повертає 1, якщо знайдено витік,
// або 0, якщо вся виділена пам'ять коректно звільнена.
int __lsan_do_recoverable_leak_check(void);

// Позначає конкретну адресу пам'яті p як прихований корінь: LSan вважатиме цей блок
// і всі досяжні з нього об'єкти живими, навіть якщо на нього немає явних вказівників.
void __lsan_ignore_object(const void *p);

// Реєструє довільний користувацький регіон пам'яті (наприклад, власний стек корутин)
// як додатковий кореневий простір для пошуку вказівників.
void __lsan_register_root_region(const void *p, size_t size);
void __lsan_unregister_root_region(const void *p, size_t size);
```

#### Синтаксис файлу придушення (`suppressions`)

Файл придушення дозволяє ізолювати відомі витоки у сторонніх закритих бібліотеках, системних викликах або глобальних структурах ініціалізації:

```text
# Ігнорувати витоки за назвою символу функції виділення
leak:third_party_legacy_allocator

# Ігнорувати витоки за назвою динамічної бібліотеки
leak:libcrypto.so.3

# Ігнорувати витоки за шаблоном шляху до файлу сирцевого коду
leak:src/legacy/parser.c
```

### 2. Valgrind Memcheck

Valgrind виконує бінарний код у віртуальному середовищі з JIT-трансляцією у проміжне представлення VEX. Це дозволяє аналізувати сторонні виконувані файли без необхідності їхньої перекомпіляції, але спричиняє сповільнення швидкодії у 10–30 разів.

#### Параметри командного рядка

```bash
valgrind --tool=memcheck \
         --leak-check=full \
         --show-leak-kinds=all \
         --track-origins=yes \
         --leak-resolution=high \
         --log-file=valgrind_report.log \
         ./target_executable
```

Ключові прапори Memcheck:
- `--leak-check=full` — розгортає повні стеки викликів для кожної виявленої точки виділення незвільненого блоку пам'яті (значення `summary` виводить лише загальну кількість байтів).
- `--show-leak-kinds=all` — відображає всі чотири внутрішні категорії стану пам'яті (Definite, Indirect, Possible, Reachable).
- `--track-origins=yes` — відстежує історію створення неініціалізованих значень пам'яті, спрощуючи пошук використання висячих покажчиків.
- `--leak-resolution=high` — визначає чутливість групування однакових витоків за глибиною збігу адрес у стеку викликів (доступні рівні `low`, `med`, `high`).
- `--gen-suppressions=all` — автоматично формує готові блоки коду придушення для кожного знайденого дефекту, які можна скопіювати у файл конфігурації.

#### Класифікація витоків у звітах Valgrind

1. **`definitely lost` (Безумовно втрачено)**: на блок пам'яті не вказує жоден покажчик. Пам'ять втрачено безповоротно, це класичний дефект коду.
2. **`indirectly lost` (Опосередковано втрачено)**: на блок вказує покажчик із іншого блоку, який сам є безумовно втраченим. Типовий приклад — вузли бінарного дерева або елементи зв'язаного списку після втрати покажчика на корінь.
3. **`possibly lost` (Ймовірно втрачено)**: покажчик існує, але він вказує не на початок блоку, а всередину його тіла зі зміщенням. Це може бути як наслідком внутрішньої адресної арифметики, так і дефектом пошкодження покажчика.
4. **`still reachable` (Все ще досяжно)**: на момент виклику `exit()` на блок існує прямий вказівник із глобальних або стекових змінних. Зазвичай це статичні структури даних або буфери, які програма вирішила не звільняти перед завершенням процесу, покладаючись на операційну систему.

### 3. eBPF `memleak` (BCC / bpftrace)

Інструмент `memleak` базується на технології розширеного фільтра пакетів ядра Linux (eBPF). Він динамічно перехоплює точки входу та виходу функцій `malloc` та `free` у бібліотеці `libc.so` за допомогою зондів користувацького простору (`uprobes`) без зупинки процесу та без значних накладних витрат.

#### Синтаксис запуску та параметри фільтрації

```bash
# Відстежувати витоки у процесі PID 4812, показуючи блоки, що живуть понад 30 секунд
sudo memleak -p 4812 -a --age 30000 --combined-only --top 10 5
```

Параметри команди:
- `-p PID` — фільтрує події виділення та звільнення пам'яті виключно для вказаного ідентифікатора процесу.
- `-a` — виводить детальну інформацію про кожну окрему адресу пам'яті на додаток до агрегованих стеків викликів.
- `--age MS` — встановлює мінімальний поріг тривалості життя блоку в мілісекундах. Це дозволяє відсіяти нормальний потік короткоживучих виділень і зосередитися на пам'яті, що монотонно накопичується.
- `--combined-only` — групує виділення з ідентичними стеками викликів, відображаючи сумарний розмір пам'яті та кількість активних алокацій.
- `--top N` — обмежує вивід `N` найбільшими джерелами незвільненої пам'яті.
- `-s SAMPLE_RATE` — проріджує вибірку (наприклад, перехоплює 1 з кожних 10 викликів), що дозволяє проводити моніторинг надзвичайно навантажених високонавантажених серверів без помітного впливу на їхню пропускну здатність.
