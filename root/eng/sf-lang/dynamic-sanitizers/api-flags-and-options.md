# 📋 Прапори компіляції, змінні середовища та анотації санітайзерів

Санітайзери Clang та GCC керуються на трьох взаємопов'язаних рівнях: прапорами компілятора та компонувальника під час збірки бінарних файлів, змінними середовища під час виконання скомпільованої програми, а також вбудованими атрибутами, макросами та файлами придушення (suppressions) безпосередньо у вихідному коді.

## 1. Прапори компіляції та компонування

Санітайзери вимагають передачі відповідних прапорів як на етапі компіляції кожного вихідного файлу (`-c`), так і на етапі фінального компонування бінарника. Це зумовлено тим, що компілятор вставляє інструкції перевірки в проміжне представлення коду, а компонувальник зобов'язаний підключити статичну або динамічну бібліотеку рантайму санітайзера (`libclang_rt.asan`, `libclang_rt.tsan` тощо), яка містить реалізацію тіньової пам'яті, кастомні розподілювачі пам'яті та обробники помилок.

| Прапор компілятора | Призначення | Сумісність |
| :--- | :--- | :--- |
| `-fsanitize=address` | Вмикає AddressSanitizer (ASan) для виявлення просторових і часових помилок пам'яті (OOB, UAF, UAR). | Сумісний з UBSan; несумісний із TSan, MSan. |
| `-fsanitize=thread` | Вмикає ThreadSanitizer (TSan) для виявлення гонок даних (data races) та взаємних блокувань. | Несумісний з ASan, MSan. |
| `-fsanitize=memory` | Вмикає MemorySanitizer (MSan) для контролю неініціалізованих читань пам'яті. | Потребує Clang і повної перекомпіляції всіх бібліотек. |
| `-fsanitize=leak` | Вмикає автономний LeakSanitizer (LSan) без повної тіньової пам'яті ASan. | Сумісний з UBSan; вбудований в ASan за замовчуванням. |
| `-fsanitize-memory-track-origins=2` | Додає до звітів MSan точний стек створення неініціалізованої змінної (Origin Tracking). | Вимагає попереднього ввімкнення `-fsanitize=memory`. |
| `-fsanitize=undefined` | Вмикає UndefinedBehaviorSanitizer (UBSan) для контролю невизначеної поведінки C/C++. | Сумісний з ASan, MSan; не створює тіньової пам'яті. |
| `-fno-omit-frame-pointer` | Зберігає покажчик кадру (`RBP`/`EBP`) у кожному виклику для швидкого побудови стек-трейсу. | Критично рекомендовано для всіх санітайзерів. |
| `-g` або `-gline-tables-only` | Генерує налагоджувальну інформацію DWARF для відображення імен файлів і номерів рядків. | Обов'язково для інформативних звітів про збої. |
| `-fsanitize-recover=undefined` | Дозволяє продовжити виконання програми після виявлення порушення (non-fatal mode). | За замовчуванням увімкнено для UBSan. |
| `-fsanitize-trap=undefined` | Генерує апаратну інструкцію переривання (`UD2`/`BRK`) замість виклику рантайм-обробника. | Ідеально для мікроконтролерів і систем без libc. |

### Особливості вибору прапорів відновлення та пасток

Прапор `-fsanitize-recover` визначає, чи буде програма негайно зупинятися при знаходженні першого порушення, чи продовжить роботу, записуючи всі знайдені випадки в журнал. Для ASan за замовчуванням будь-яка помилка пам'яті вважається фатальною (`-fno-sanitize-recover=address`), оскільки виконання коду після пошкодження пам'яті загрожує неконтрольованими каскадними збоями.

На противагу цьому, UBSan дозволяє накопичувати попередження: прапор `-fsanitize-recover=undefined` дозволяє пройти повний набір модульних тестів і отримати звіт про всі знайдені знакові переповнення чи некоректні зсуви за один запуск.

Прапор `-fsanitize-trap=undefined` повністю виключає залежність бінарного файлу від рантайм-бібліотеки UBSan. Замість вставки викликів діагностичних функцій компілятор генерує інструкцію аварійного завершення (наприклад, `ud2` на `x86_64` або `trap` на `ARM`). Це критично для вбудованих прошивок мікроконтролерів (bare-metal, RTOS), де обсяг флеш-пам'яті обмежений, а стандартна бібліотека вводу-виводу відсутня.

При складанні проектів під GCC слід звертати увагу на прапор безпеки `-D_FORTIFY_SOURCE=2`: під час роботи з ASan його рекомендовано вимикати або замінювати на `-D_FORTIFY_SOURCE=0`, оскільки макроси перевірки меж стандартної бібліотеки glibc можуть конфліктувати з перехоплювачами алокацій санітайзера.

## 2. Змінні середовища рантайму

Поведінка рантайму санітайзерів налаштовується без перекомпіляції програми через змінні оточення. Параметри передаються у вигляді списку пар `ключ=значення`, розділених двокрапкою: `OPTION1=val1:OPTION2=val2`.

### Налаштування ASAN_OPTIONS та LSAN_OPTIONS

Змінна `ASAN_OPTIONS` керує обсягом карантинної черги, глибиною перевірки стеків та поведінкою розподілювача пам'яті.

```bash
export ASAN_OPTIONS="quarantine_size_mb=64:detect_stack_use_after_return=1:halt_on_error=1:log_path=asan.log"
export LSAN_OPTIONS="report_objects=1:max_leaks=50"
```

| Параметр | Значення за замовчуванням | Опис дії та вплив на систему |
| :--- | :--- | :--- |
| `quarantine_size_mb` | `256` (64-біт) / `32` (32-біт) | Розмір кільцевого FIFO-буфера звільненої пам'яті (у МБ) перед її повторним виділенням. Збільшення розміру покращує виявлення use-after-free, але підвищує споживання RAM. |
| `detect_stack_use_after_return` | `0` (вимкнено) | Виділяє стекові кадри функцій із пулу динамічної пам'яті (Fake Stack), дозволяючи ловити повернення покажчиків на локальні змінні. Додає 1.5x–2x до сповільнення викликів функцій. |
| `check_initialization_order` | `0` (вимкнено) | Перевіряє порядок динамічної ініціалізації глобальних змінних між різними одиницями трансляції, ловлячи доступ до ще не сконструйованих об'єктів. |
| `detect_leaks` | `1` (Linux) / `0` (macOS) | Автоматично вмикає LeakSanitizer (LSan) під час завершення програми для виявлення незвільнених блоків пам'яті. |
| `halt_on_error` | `1` | Зупиняє виконання процесу (`exit(1)`) після виявлення першої ж помилки доступу до пам'яті. |
| `max_redzone` | `2048` | Максимальний розмір червоної зони в байтах навколо великих алокацій у купі. |
| `malloc_context_size` | `30` | Кількість кадрів стек-трейсу, що зберігаються для кожного виклику `malloc` і `free`. Зменшення до 10 прискорює алокації. |
| `log_path` | `stderr` | Префікс шляху до файлу для збереження діагностичних звітів замість стандартного потоку помилок. До назви автоматично додається PID процесу. |

Під час запуску ASan автоматично перехоплює сигнали операційної системи (`SIGSEGV`, `SIGBUS`, `SIGFPE`, `SIGILL`) і реєструє альтернативний стековий простір (`sigaltstack`). Це гарантує, що навіть у випадку повного вичерпання основного стека програми обробник сигналу матиме достатньо пам'яті для генерації детального діагностичного звіту.

Модуль LeakSanitizer (LSan) під час завершення програми виконує зупинку всіх потоків процесу (stop-the-world) та сканує глобальні змінні, стек і регістри на наявність адрес активних блоків купи. Блоки, на які немає жодних покажчиків, класифікуються як витоки (Direct Leaks), а блоки, досяжні лише через загублені об'єкти — як непрямі витоки (Indirect Leaks).

### Налаштування TSAN_OPTIONS

Змінна `TSAN_OPTIONS` керує глибиною історії подій багатопотоковості та алгоритмами детекції блокувань.

```bash
export TSAN_OPTIONS="history_size=7:report_bugs=1:second_deadlock_stack=1:suppressions=tsan.supp"
```

| Параметр | Значення за замовчуванням | Опис дії та вплив на систему |
| :--- | :--- | :--- |
| `history_size` | `2` (діапазон 0..7) | Розмір кільцевого буфера історії звернень на кожен потік (`2^size × 64` тис. записів). Значення `7` максимізує шанс отримання повного стек-трейсу старого звернення ціною збільшення споживання пам'яті. |
| `second_deadlock_stack` | `0` (вимкнено) | Зберігає та виводить повний стек-трейс першого захоплення м'ютекса при виявленні циклічного взаємного блокування (Deadlock). |
| `report_bugs` | `1` | Дозволяє або вимикає друк звітів про знайдені гонки даних під час виконання. |
| `suppressions` | порожньо | Шлях до текстового файлу правил ігнорування відомих або сторонніх гонок даних. |

При інтенсивній роботі багатьох короткоживучих потоків TSan може вичерпати внутрішню таблицю дескрипторів потоків. Опція `flush_memory_ms=2000` задає періодичність скидання застарілої тіньової пам'яті неактивних потоків, що запобігає неконтрольованому зростанню споживання оперативної пам'яті у тривалих стрес-тестах.

### Налаштування MSAN_OPTIONS

Змінна `MSAN_OPTIONS` дозволяє тонко регулювати поведінку MemorySanitizer при роботі зі звільненою пам'яттю та системними викликами.

```bash
export MSAN_OPTIONS="poison_in_free=1:track_origins=2:abort_on_error=1"
```

| Параметр | Значення за замовчуванням | Опис дії та вплив на систему |
| :--- | :--- | :--- |
| `poison_in_free` | `1` | Отруює пам'ять у викликах `free()` та `delete` міткою «неініціалізовано», запобігаючи несанкціонованому використанню залишкових даних. |
| `track_origins` | `0` | Глибина відстеження джерела: `1` — зберігає точку виділення пам'яті, `2` — відстежує повний ланцюг проміжних копіювань і обчислень значення. |
| `abort_on_error` | `0` | Завершує процес викликом `abort()` (із формуванням core dump) замість штатного `exit()`. |

Параметр `track_origins=2` створює суттєве додаткове навантаження на підсистему пам'яті (до 3x–4x загального обсягу RAM), проте є незамінним для локалізації багів, коли неініціалізоване значення було передане крізь кільцевий буфер, чергу повідомлень або упаковано в складну ієрархію структур перед тим, як потрапити в умову розгалуження.

### Налаштування UBSAN_OPTIONS

```bash
export UBSAN_OPTIONS="print_stacktrace=1:halt_on_error=1:suppressions=ubsan.supp"
```

| Параметр | Значення за замовчуванням | Опис дії |
| :--- | :--- | :--- |
| `print_stacktrace` | `0` | Друкує стек викликів функцій у момент реєстрації невизначеної поведінки. Вимагає збірки з прапором `-g`. |
| `halt_on_error` | `0` | Перериває виконання програми при знаходженні першого UB (якщо програма скомпільована з підтримкою recover). |
| `suppressions` | порожньо | Шлях до файлу правил придушення окремих підтипів невизначеної поведінки. |

## 3. Анотації у вихідному коді та ручне отруєння пам'яті

Для низькорівневих системних компонентів (власні алокатори пам'яті, контекстне перемикання стеків для корутин, оптимізовані SIMD-підпрограми або звернення до апаратних регістрів) компіляторні перевірки санітайзерів можуть давати хибні спрацьовування. Для таких випадків передбачено спеціальні атрибути компілятора та явний C/C++ API для маніпуляцій із тіньовою пам'яттю.

### Атрибути вимкнення інструментації

Компілятори підтримують атрибути `no_sanitize`, що забороняють вставку перевірок у тіло конкретної функції:

:::tabs
```c
#include <stddef.h>

// Вимкнення перевірок AddressSanitizer для оптимізованої функції копіювання
__attribute__((no_sanitize("address")))
void fast_unaligned_block_copy(void *dest, const void *src, size_t n) {
    char *d = (char *)dest;
    const char *s = (const char *)src;
    while (n--) {
        *d++ = *s++;
    }
}

// Вимкнення TSan для прямого опитування апаратного регістра без м'ютекса
__attribute__((no_sanitize("thread")))
unsigned int poll_hardware_status_register(volatile const unsigned int *reg_addr) {
    return *reg_addr;
}
```
```cpp
#include <cstddef>

// Вимкнення перевірок ASan у C++ за допомогою стандартного синтаксису атрибутів
[[gnu::no_sanitize("address")]]
void fast_memory_clear(std::byte* dest, std::size_t size) noexcept {
    for (std::size_t i = 0; i < size; ++i) {
        dest[i] = std::byte{0};
    }
}

// Вимкнення TSan для специфічного lock-free алгоритму
[[gnu::no_sanitize("thread")]]
auto read_relaxed_counter(const volatile unsigned int* counter) noexcept -> unsigned int {
    return *counter;
}
```
:::

У сучасних версіях Clang (починаючи з версії 14) доступний більш радикальний атрибут `__attribute__((disable_sanitizer_instrumentation))`. На відміну від `no_sanitize`, він вимикає абсолютно всі санітайзери (включно з прологами перевірки стеків, перевіркою вирівнювання та покриттям коду), що критично важливо для функцій перемикання контексту процесора, обробників апаратних переривань та низькорівневих точок входу в ядро ОС.

### Інтерфейс ручного керування тіньовою пам'яттю (Manual Poisoning API)

При написанні власних пулів пам'яті (наприклад, арени або блокового алокатора) стандартний ASan не знає, які ділянки виділеного монолітного буфера зараз зайняті об'єктами, а які є вільними. За допомогою заголовка `<sanitizer/asan_interface.h>` розробник може вручну позначати байти як отруєні або валідні:

:::tabs
```c
#include <sanitizer/asan_interface.h>
#include <stdlib.h>
#include <stddef.h>

typedef struct {
    char buffer[1024];
    size_t allocated;
} SimpleArena;

void arena_init(SimpleArena *arena) {
    arena->allocated = 0;
    // Початково отруюємо весь буфер арени
    ASAN_POISON_MEMORY_REGION(arena->buffer, sizeof(arena->buffer));
}

void *arena_alloc(SimpleArena *arena, size_t size) {
    if (arena->allocated + size > sizeof(arena->buffer)) {
        return NULL;
    }
    void *ptr = &arena->buffer[arena->allocated];
    arena->allocated += size;
    // Знімаємо отруєння лише з тих байтів, які віддаються клієнту
    ASAN_UNPOISON_MEMORY_REGION(ptr, size);
    return ptr;
}
```
```cpp
#include <sanitizer/asan_interface.h>
#include <array>
#include <cstddef>
#include <span>
#include <stdexcept>

class CustomStackArena {
public:
    static constexpr std::size_t Capacity = 2048;

    CustomStackArena() noexcept {
        // Отруюємо всю область пам'яті арени при створенні
        ASAN_POISON_MEMORY_REGION(m_storage.data(), m_storage.size());
    }

    ~CustomStackArena() noexcept {
        // Знімаємо отруєння перед знищенням об'єкта
        ASAN_UNPOISON_MEMORY_REGION(m_storage.data(), m_storage.size());
    }

    [[nodiscard]] auto allocate(std::size_t size) -> std::span<std::byte> {
        if (m_offset + size > Capacity) {
            throw std::bad_alloc();
        }
        auto* ptr = &m_storage[m_offset];
        m_offset += size;
        // Дозволяємо доступ лише до виділеного діапазону
        ASAN_UNPOISON_MEMORY_REGION(ptr, size);
        return {reinterpret_cast<std::byte*>(ptr), size};
    }

private:
    alignas(16) std::array<uint8_t, Capacity> m_storage{};
    std::size_t m_offset{0};
};
```
:::

## 4. Файли придушення (Suppression Files)

Коли помилка виникає у сторонній скомпільованій системній бібліотеці (наприклад, драйвері графічного прискорювача чи закритій криптографічній бібліотеці), яку неможливо перекомпілювати або швидко виправити, застосовують механізм файлів придушення.

Файл придушень вказується у відповідній змінній середовища (`TSAN_OPTIONS="suppressions=tsan.supp"`).

### Структура файлу придушень TSan (`tsan.supp`)

Правила будуються за шаблоном `тип_помилки:шаблон_символу_або_файлу`:

```text
# Придушення гонок даних у сторонніх динамічних бібліотеках
race:libcrypto.so
race:libvulkan.so

# Придушення за назвою класу чи функції (підтримуються маски зі зірочкою)
race:LegacyThirdPartyEngine::*
race:pthread_create

# Придушення гонок даних у конкретному файлі вихідного коду
race:src/legacy/old_network_driver.c

# Придушення взаємних блокувань (Deadlock)
deadlock:QMutex::lock
deadlock:std::unique_lock<std::mutex>::lock
```

### Структура файлу ігнорування компілятора (`ignorelist.txt`)

На відміну від рантайм-придушень, прапор Clang `-fsanitize-ignorelist=ignorelist.txt` повністю вимикає генерацію інструментуючих інструкцій для відповідних файлів і функцій на етапі трансляції коду, що дозволяє зменшити розмір бінарника та усунути накладні витрати у вибраних модулях:

```text
# Ігнорувати всі файли у сторонній підпапці
src:*/third_party/zlib/*
src:*/vendor/protobuf/*

# Ігнорувати конкретну функцію за її мангльованим або C-іменем
fun:crc32_fast_avx2
fun:_ZN12CryptoEngine11HashPayloadEPKhm

# Ігнорувати конкретний тип санітайзера для вказаного вихідного файлу
[address]
src:src/allocator/custom_mempool.c

[thread]
src:src/concurrency/lockfree_queue.cpp
```
