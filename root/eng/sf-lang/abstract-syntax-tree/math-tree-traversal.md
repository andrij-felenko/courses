# 🧮 Формальні граматики, обхід дерев та паттерн Visitor

Синтаксичний аналіз та побудова синтаксичних дерев спираються на строгий математичний апарат формальних граматик і теорії графів. Розуміння цієї математичної основи дозволяє не лише конструювати парсери без помилок, а й формально доводити їхню коректність, доцільність та обчислювальну складність.

## 1. Формальне визначення Контекстно-Вільних Граматик (CFG)

Мови програмування описуються **контекстно-вільними граматиками** (англ. *Context-Free Grammars*, CFG), які займають 2-й рівень в ієрархії Хомського.

Математично контекстно-вільна граматика — це четвірка впорядкованих об'єктів:

```
G = (V, Σ, R, S)
```

Де:
- **V** — скінченна множина **нетермінальних символів** (змінних граматики, наприклад `Expr`, `Term`, `Statement`), які позначають синтаксичні категорії.
- **Σ** — скінченна множина **термінальних символів** (алфавіт токенів мови, наприклад `+`, `-`, `if`, `42`, `x`), причому нетермінали й термінали не перетинаються: `V ∩ Σ = ∅`.
- **R** — скінченна множина **правил виведення** (продукцій) вигляду:
  
  `A → α,  де A ∈ V,  α ∈ (V ∪ Σ)*`
  
  Це означає, що ліва частина правила містить **один нетермінал** `A`, а права частина `α` є довільним рядком (можливо порожнім), складеним з нетерміналів і терміналів.
- **S ∈ V** — виділений **початковий нетермінал** (аксіома граматики), з якого починається виведення будь-якої коректної програми.

### Форма Блакуса — Наура (BNF) та EBNF

На практиці правила `R` записують у нотації Блакуса — Наура (BNF). Наприклад, граматика арифметичних виразів над числами виглядає так:

```
Expr   ::= Expr '+' Term  |  Expr '-' Term  |  Term
Term   ::= Term '*' Factor |  Term '/' Factor |  Factor
Factor ::= NUMBER  |  '(' Expr ')'
```

Тут `Expr`, `Term`, `Factor` належать `V`, а `+`, `-`, `*`, `/`, `(`, `)`, `NUMBER` належать `Σ`.

Дерево розбору (CST) для конкретного рядка `w ∈ Σ*` є граф-деревом, де корінь позначено аксіомою `S`, внутрішні вузли позначаються нетерміналами з `V`, а листки — терміналами з `Σ`.

## 2. Математика обходу дерев та ізоморфізм виразів

Абстрактне синтаксичне дерево є орієнтованим ациклічним графом вигляду `T = (N, E)`, де `N` — множина вузлів, `E` — дуги від батьківських вузлів до їхніх дітей.

Нехай `n ∈ N` — вузол з операцією `op(n)` та списком дітей `children(n) = [c₁, c₂, ..., cₖ]`.

Існує три класичні порядок обходу дерев, кожен із яких встановлює биєктивний зв'язок (ізоморфізм) між структурою дерева й відповідною нотацією виразу:

```
       +
      / \
     *   3
    / \
   2   4
```

### 1. Прямий обхід (Pre-order Traversal: N → L → R)

Спочатку відвідується самий вузол `n`, після чого рекурсивно відвідуються всі його дітей від `c₁` до `cₖ`:

```
preorder(n) = op(n) ∘ preorder(c₁) ∘ preorder(c₂) ∘ ... ∘ preorder(cₖ)
```

Для виразового дерева вище префіксний обхід генерує **польську нотацію** (Prefix Notation):
`+ * 2 4 3`

Перевага префіксної нотації полягає в тому, що її можна обчислювати справа наліво за допомогою простого стека без урахування дужок.

### 2. Центрований обхід (In-order Traversal: L → N → R)

Спочатку відвідується ліва дитина `c₁`, потім сам вузол `n`, потім рекурсивно решта дітей:

```
inorder(n) = inorder(c₁) ∘ op(n) ∘ inorder(c₂)
```

Для виразового дерева центрований обхід генерує звичну людям **інфіксну нотацію** (Infix Notation) з дужками:
`((2 * 4) + 3)`

### 3. Зворотний обхід (Post-order Traversal: L → R → N)

Спочатку рекурсивно відвідуються всі дітей від `c₁` до `cₖ`, а сам вузол `n` обробляється в останню чергу:

```
postorder(n) = postorder(c₁) ∘ postorder(c₂) ∘ ... ∘ postorder(cₖ) ∘ op(n)
```

Для виразового дерева зворотний обхід генерує **зворотну польську нотацію** (Reverse Polish Notation, RPN):
`2 4 * 3 +`

**Математична теорема**: Постфіксний обхід AST є математично еквівалентним послідовності інструкцій для стек-машини (абстрактного автомата з пам'яттю у вигляді стека). Кожен листок `NUMBER(v)` генерує команду `PUSH v`, а кожен внутрішній вузол `op` генерує команду `EXEC op`.

## 3. Формалізація шаблону Visitor та Дворазова Диспетчеризація

З точки зору функціонального аналізу, обчислення або трансляція AST — це застосування катаморфізму (узагальненого відображення) `f` з простору дерев `T` у простір результатів `R`:

```
f : T → R
```

У об'єктно-орієнтованому програмуванні для реалізації таких відображень без порушення принципу відкритості/закритости (Open/Closed Principle) застосовують шаблон **Visitor**.

Математична суть Visitor спирається на механізм **дворазової диспетчеризації** (Double Dispatch). Нехай `N` — множина типів вузлів AST, `V` — множина класів-відвідувачів. Ми будуємо функцію відображення:

```
D : N × V → R
```

Замість того, щоб шукати відповідну дію через громіздку таблицю умов `if-else` складності `O(|N|)`, метод `accept` реалізує подвійний перехід за вказівником за час `O(1)`:

```
1. node.accept(v)       ──► виклик з віртуальної таблиці N  (перша диспетчеризація)
2. v.visit_BinaryOp(this) ──► виклик з віртуальної таблиці V  (друга диспетчеризація)
```

### Алгебраїчні типи даних і зіставлення зі зразком

У сучасних функціональних мовах (Rust, Haskell, Swift, OCaml) шаблон Visitor замінюється алгебраїчними типами даних (Sum Types) та механізмом зіставлення зі зразком (Pattern Matching).

Нехай `AST` визначається як алгебраїчний тип:

```
AST = Literal(ℝ) ∪ BinaryOp(Op × AST × AST)
```

Обчислення рекурсивно визначається через систему математичних рівнянь:

```
eval(Literal(v))            = v
eval(BinaryOp('+', l, r))   = eval(l) + eval(r)
eval(BinaryOp('-', l, r))   = eval(l) - eval(r)
eval(BinaryOp('*', l, r))   = eval(l) × eval(r)
eval(BinaryOp('/', l, r))   = eval(l) / eval(r)
```

Цей математичний запис є не просто елегантним, а й дозволяє компілятору доводити вичерпність (exhaustiveness) перевірки всіх можливих форм дерева на етапі компіляції.

## 4. Переписання термів (Term Rewriting System) та Оптимізація

Оптимізація AST (наприклад, згортання констант чи спрощення виразів) математично описується як **система переписання термів** (англ. *Term Rewriting System*, TRS).

Система переписання визначається як множина орієнтованих правил `R_rewrite`:

```
lᵢ → rᵢ,   де lᵢ, rᵢ ∈ T
```

Приклади алгебраїчних правил спрощення AST:

1. **Тотожність додавання**: `BinaryOp('+', x, Literal(0)) → x`
2. **Тотожність множення**: `BinaryOp('*', x, Literal(1)) → x`
3. **Множення на нуль**: `BinaryOp('*', x, Literal(0)) → Literal(0)`
4. **Згортання констант**: `BinaryOp(op, Literal(a), Literal(b)) → Literal(eval(op, a, b))`

Властивість **конфлюентності** (Confluence / властивість Чорча — Россера) гарантує, що незалежно від порядку застосування правил переписання до піддерев AST, підсумкове спрощене дерево завжди завітає до єдиної, найкоротшої **нормальної форми**.
