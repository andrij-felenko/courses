# 📋 Довідник команд, функцій та синтаксису GNU LD

Скрипти компонувальника GNU LD керують процесом перетворення набору незалежних об'єктних файлів у єдиний монолітний образ прошивки, визначаючи точні фізичні адреси розташування кожної інструкції, константи та змінної. Цей довідник містить повну специфікацію синтаксису, команд керування пам'яттю, вбудованих функцій обчислення адрес та операторів вирівнювання, без яких неможливо спроєктувати надійну карту пам'яті для вбудованої системи.

---

## 1. Загальна структура та директиви верхнього рівня

Скрипт компонувальника є текстовим файлом (зазвичай з розширенням `.ld`), що інтерпретується рушієм компонування GNU LD під час фінальної фази збірки. Текст скрипта складається з команд конфігурації середовища, декларацій фізичних регіонів пам'яті та блоку розподілу секцій.

| Директива | Призначення | Приклад ужитку |
|---|---|---|
| `ENTRY(symbol)` | Встановлює початкову точку входу в програму (записується в заголовок ELF). Використовується налагоджувачами (GDB, OpenOCD) для визначення стартової інструкції. | `ENTRY(Reset_Handler)` |
| `MEMORY { ... }` | Оголошує фізичні банки та блоки пам'яті цільового мікроконтролера з їхніми початковими адресами, довжинами та атрибутами доступу. | `MEMORY { FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 512K }` |
| `SECTIONS { ... }` | Описує правила відображення вхідних секцій з об'єктних файлів (`*.o`, `*.a`) у вихідні секції кінцевого ELF-файлу. | `SECTIONS { .text : { *(.text*) } >FLASH }` |
| `REGION_ALIAS(alias, region)` | Створює псевдонім для фізичного регіону пам'яті. Дозволяє створювати універсальні скрипти для лінійок чипів із різними назвами банків пам'яті. | `REGION_ALIAS("RAM_EXEC", RAM_D1);` |
| `INCLUDE filename` | Включає вміст іншого файлу лінкер-скрипта у поточну позицію (наприклад, конфігурацію певної моделі пам'яті). | `INCLUDE memory_map.ld` |
| `SEARCH_DIR(path)` | Додає шлях до списку каталогів, у яких LD шукає бібліотеки та скрипти. | `SEARCH_DIR(/opt/arm-toolchain/lib)` |
| `OUTPUT_FORMAT(bfdname)` | Задає двійковий формат вихідного файлу BFD (Binary File Descriptor). Для ARM зазвичай `elf32-littlearm`. | `OUTPUT_FORMAT("elf32-littlearm")` |
| `OUTPUT_ARCH(bfdarch)` | Вказує архітектуру цільового процесора. | `OUTPUT_ARCH(arm)` |

## 2. Декларація пам'яті: директива MEMORY

Директива `MEMORY` визначає фізичну топологію пам'яті цільового чипа. Якщо сумарний розмір секцій, призначених регіону, перевищує значення `LENGTH`, компонувальник генерує помилку `region '...' overflowed` і зупиняє збірку.

```ld
MEMORY
{
  NAME [(ATTR)] : ORIGIN = origin_address, LENGTH = length_value
}
```

### Атрибути прав доступу (ATTR)

Атрибути записуються в круглих дужках після імені регіону і слугують фільтром для автоматичного розподілу секцій, якщо секція явно не прив'язана до вихідного блоку:

* `r` — Read-only sections (секції лише для читання, наприклад `.rodata`);
* `w` — Read/write sections (секції читання та запису, наприклад `.data`, `.bss`);
* `x` — Executable sections (секції виконуваного машинного коду, наприклад `.text`);
* `a` — Allocatable sections (секції, під які виділяється пам'ять під час завантаження);
* `i` — Initialized sections (секції, що містять початкові дані);
* `!` — Інвертує логіку перевірки наступних атрибутів.

### Специфікація одиниць вимірювання розміру

* `K` або `k` — Кілобайти (множник 1024, `128K` = 131072 байти);
* `M` або `m` — Мегабайти (множник 1024 × 1024, `1M` = 1048576 байтів);
* Числа без суфікса інтерпретуються як байти або шістнадцяткові адреси (з префіксом `0x`).

## 3. Синтаксис опису секцій: директива SECTIONS

Блок `SECTIONS` задає внутрішній устрій прошивки. Кожен запис описує одну вихідну секцію (Output Section):

```ld
SECTIONS
{
  secname start_addr BLOCK(align) (NOLOAD) : AT(lma_addr)
  {
    symbol_before = .;
    KEEP(*(pattern_section*))
    *(EXCLUDE_FILE(*test*.o) .text .text.*)
    . = ALIGN(4);
    symbol_after = .;
  } >REGION_VMA AT>REGION_LMA [ =fill_expression ]
}
```

### Модифікатори та кваліфікатори вихідних секцій

* `>REGION_VMA` — Призначає секції регіон пам'яті для Virtual Memory Address (VMA — адреса часу виконання);
* `AT>REGION_LMA` — Призначає секції регіон пам'яті для Load Memory Address (LMA — адреса зберігання образу у Flash);
* `AT(lma_expr)` — Явно задає фізичну адресу завантаження LMA як результат обчислення виразу;
* `(NOLOAD)` — Вказує компонувальнику, що секція не повинна записуватися в двійковий образ прошивки (Flash). Пам'ять резервується лише в адресному просторі VMA (використовується для буферів DMA, стеків, незанулюваної пам'яті no-init);
* `KEEP(*(.section_name))` — Забороняє оптимізатору лінкера (`--gc-sections`) видаляти зазначену вхідну секцію, навіть якщо на неї немає прямих посилань у таблиці символів інших об'єктних файлів (критично для таблиці векторів переривань `.isr_vector`);
* `EXCLUDE_FILE(file_patterns)` — Виключає об'єктні файли з шаблону захоплення, дозволяючи перенаправити їхні секції в інші області пам'яті;
* `=fill_expression` — Заповнює проміжки між секціями або невикористані байти вказаним патерном (наприклад, `=0xFF` для чистого стану Flash або `=0x00`);
* `/DISCARD/` — Спеціальна вихідна секція для повного видалення непотрібних метаданих компілятора (коментарі, нотатки, непотрібні налагоджувальні секції):
  ```ld
  /DISCARD/ :
  {
    *(.comment)
    *(.note*)
    *(.ARM.attributes)
  }
  ```

## 4. Вбудовані функції обчислення адрес та розмірів

GNU LD має набір вбудованих функцій, які обчислюються під час фінального проходу розміщення секцій:

```ld
/* Приклади обчислення адрес та інваріантів у .ld */
_sidata = LOADADDR(.data);
_data_size = SIZEOF(.data);
_flash_start = ORIGIN(FLASH);
_flash_len = LENGTH(FLASH);
```

| Функція | Повертане значення | Типове застосування |
|---|---|---|
| `LOADADDR(section)` | Повертає абсолютну адресу завантаження LMA вказаної секції. | Отримання адреси джерела даних `.data` у Flash для стартового копіювання (`_sidata = LOADADDR(.data);`). |
| `ADDR(section)` | Повертає абсолютну адресу виконання VMA вказаної секції. | Отримання початкової адреси секції в RAM. |
| `SIZEOF(section)` | Повертає точний розмір скомпільованої секції в байтах. | Перевірка лімітів пам'яті, розрахунок контрольних сум. |
| `ORIGIN(region)` | Повертає початкову адресу регіону, оголошеного в блоці `MEMORY`. | Розрахунок початкових маркерів банків RAM / Flash. |
| `LENGTH(region)` | Повертає довжину в байтах регіону, оголошеного в блоці `MEMORY`. | Розрахунок вершини стека: `_estack = ORIGIN(RAM) + LENGTH(RAM);`. |
| `ALIGN(expr)` | Повертає значення лічильника адрес `.`, округлене вгору до найближчої межі, кратної `expr`. | Вирівнювання полів даних та інструкцій: `. = ALIGN(4);`. |
| `ALIGN(align_expr, expr)` | Повертає значення виразу `expr`, вирівняне до межі `align_expr`. | Обчислення адрес вирівняних буферів без зсуву `.`. |
| `MAX(exp1, exp2)` / `MIN(exp1, exp2)` | Повертає максимальне або мінімальне значення з двох виразів. | Динамічний вибір безпечного розміру стека або буфера. |
| `DEFINED(symbol)` | Повертає `1`, якщо символ оголошено у коді або скрипті, і `0` в іншому випадку. | Умовне створення символів або секцій. |
| `BLOCK(align)` | Еквівалент `ALIGN(align)` всередині заголовка секції. | Вирівнювання початкової адреси вихідної секції. |
| `NEXT(exp)` | Повертає наступну невикористану адресу, кратну `exp`. | Розподіл пам'яті без явного перерахунку зміщень. |
| `LOG2CEIL(exp)` | Обчислює округлений вгору двійковий логарифм виразу. | Розрахунок масок регістрів захисту пам'яті MPU. |

## 5. Символи, лічильник адреси та оператори присвоєння

Лічильник адреси (Location Counter) позначається крапкою `.` і зберігає поточну адресу зміщення всередині поточної секції або адресного простору.

### Правила роботи з лічильником адреси `.`

1. Зчитування `.` повертає поточну абсолютну адресу VMA.
2. Присвоєння `.` призводить до переміщення покажчика генерації адреси вперед (створюючи проміжок / padding):
   ```ld
   . = . + 0x1000; /* Резервує 4 КБ неініціалізованого простору */
   . = ALIGN(8);   /* Зсуває адресу до межі, кратної 8 байтам */
   ```
3. Зменшення лічильника назад (`. = . - 4;`) заборонене і призводить до фатальної помилки компонування.

### Оператори визначення символів

```ld
/* Пряме безумовне створення символу */
_sdata = .;

/* Умовне створення символу: лише якщо він не оголошений в об'єктних файлах */
PROVIDE(_system_stack_size = 0x800);

/* Умовне створення прихованого символу (не потрапляє у dynamic symbol table) */
PROVIDE_HIDDEN(__init_array_start = .);
```

* `PROVIDE(symbol = expr)` — оголошує символ за умови, що жоден з об'єктних файлів програми не містить власного визначення цього символу. Якщо програма на C/C++ містить глобальну змінну з таким самим ім'ям, лінкер без попереджень використає визначення з C, проігнорувавши значення зі скрипта;
* `PROVIDE_HIDDEN(symbol = expr)` — аналогічно до `PROVIDE`, але обмежує видимість символу виключно внутрішнім процесом компонування, запобігаючи експорту в динамічні таблиці.

## 6. Вирази та типи символів: абсолютні проти відносних

Усі математичні вирази в GNU LD обчислюються з використанням цілочисельної арифметики розрядності цільового процесора (32 біти або 64 біти). Синтаксис підтримує стандартні оператори мови C:

* Арифметичні: `+`, `-`, `*`, `/`, `%`;
* Побітові: `&`, `|`, `^`, `~`, `<<`, `>>`;
* Логічні та порівняння: `&&`, `||`, `==`, `!=`, `<`, `>`, `<=`, `>=`;
* Тернарний умовний оператор: `condition ? expr_true : expr_false`.

### Відносні та абсолютні символи

Коли символ створюється **всередині** вихідної секції, компонувальник призначає йому тип **відносного символу** (Section-Relative Symbol). Його значення зберігається як зміщення від початку секції. Якщо секція зсувається, символ автоматично змінює своє значення.

Коли символ створюється **поза** блоками секцій (у глобальній області скрипта), компонувальник створює **абсолютний символ** (Absolute Symbol). Його адреса фіксована і не залежить від зміщень сусідніх структур даних.

```ld
SECTIONS
{
  .text : {
    _relative_start = .; /* Відносний символ, прив'язаний до .text */
    *(.text*)
  } >FLASH

  _absolute_marker = ABSOLUTE(.); /* Явне перетворення на абсолютну константу */
}
```

## 7. Контроль цілісності та діагностика: ASSERT

Команда `ASSERT` забезпечує статичну верифікацію карти пам'яті під час компонування. Якщо умова виявляється хибною, процес збірки аварійно завершується з виведенням вказаного повідомлення:

```ld
ASSERT(condition, "Error message")
```

### Практичні сценарії використання ASSERT

```ld
/* 1. Перевірка, чи не зіткнулися стек і купа в оперативній пам'яті */
_min_stack_size = 0x800; /* 2 KB мінімального стека */
_min_heap_size  = 0x400; /* 1 KB мінімальної купи */

ASSERT(_ebss + _min_stack_size + _min_heap_size <= ORIGIN(RAM) + LENGTH(RAM),
       "Помилка: Недостатньо оперативної пам'яті для гарантованого розміщення стека й купи!")

/* 2. Перевірка вирівнювання таблиці векторів переривань (ARM вимагає 128 або 512 байтів) */
ASSERT((_isr_vector_start & 0x7F) == 0,
       "Помилка: Таблиця векторів .isr_vector не вирівняна за межею 128 байтів!")
```

## 8. Прапори сортування вхідних секцій

Під час компонування декількох об'єктних файлів часто виникає потреба впорядкувати вхідні секції у визначеному порядку (наприклад, конструктори C++ у `.init_array` або секції ініціалізації драйверів).

* `SORT_BY_NAME(pattern)` — сортує вхідні секції за алфавітним порядком їхніх імен (наприклад, `.init_array.00010` перед `.init_array.00020`);
* `SORT_BY_ALIGNMENT(pattern)` — сортує секції за спаданням вимог до вирівнювання (спочатку секції з вирівнюванням 8 байтів, потім 4, 2, 1), що мінімізує втрати пам'яті на проміжні байти заповнення (padding);
* `SORT_BY_INIT_PRIORITY(pattern)` — впорядковує за числовим пріоритетом ініціалізаторів C++ (`__attribute__((init_priority(n)))`);
* `SORT(pattern)` — еквівалент `SORT_BY_NAME`.

```ld
.init_array :
{
  . = ALIGN(4);
  PROVIDE_HIDDEN (__init_array_start = .);
  KEEP (*(SORT_BY_INIT_PRIORITY(.init_array.*) SORT_BY_INIT_PRIORITY(.ctors.*)))
  KEEP (*(SORT_BY_NAME(.init_array.*) SORT_BY_NAME(.ctors.*)))
  KEEP (*(.init_array* .ctors*))
  PROVIDE_HIDDEN (__init_array_end = .);
  . = ALIGN(4);
} >FLASH
```
