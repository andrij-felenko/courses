# 🧮 Монотонні напівґратки та збіжність нерухомої точки

Аналіз потоків даних моделює виконання програми не шляхом покрокової симуляції конкретних чисел у пам'яті, а через алгебраїчне просування абстрактних фактів вздовж графа потоку керування. Щоб компілятор міг гарантувати точність оптимізацій і завершення ітеративного процесу за скінченний час, простір знань програми формалізують як алгебраїчну структуру — **монотонну напівґратку станів** (англ. *monotone dataflow framework*).

Цей формалізм визначає, як упорядковані знання компілятора про програму, як вони комбінуються в точках злиття шляхів, і чому ітеративний алгоритм обов'язково досягає стабільної відповіді — так званої **фіксованої (нерухомої) точки**.

## 1. Алгебраїчна напівґратка станів

Напівґраткою злиття (англ. *meet-semilattice*) називають пару `(L, ⊓)`, де `L` — множина станів (фактів), а `⊓` — бінарна операція злиття (Meet), що задовольняє три аксіоми для довільних елементів `x, y, z ∈ L`:

1. **Ідемпотентність:** `x ⊓ x = x` (повторне отримання того самого факту не змінює знання).
2. **Комутативність:** `x ⊓ y = y ⊓ x` (порядок аналізу попередників у точці злиття не має значення).
3. **Асоціативність:** `(x ⊓ y) ⊓ z = x ⊓ (y ⊓ z)` (групування шляхів не впливає на підсумковий результат).

Будь-яка напівґратка індукує відношення **часткового порядку** `⊑` на множині `L`:

```
x ⊑ y  ⇔  x ⊓ y = x
```

Інтуїція часткового порядку `x ⊑ y`: стан `x` несе *менше знань* (або є більш консервативним / песимістичним), ніж стан `y`.

Напівґратка називається обмеженою, якщо в ній існують два граничні елементи:
- **Найвищий елемент `⊤` (Top):** стан максимальної оптимістичності (ще нічого не обчислювали або припускаємо найкращий випадок). Для будь-якого `x ∈ L` виконується `x ⊓ ⊤ = x`, тобто `x ⊑ ⊤`.
- **Найнижчий елемент `⊥` (Bottom):** стан повної невизначеності або безпечного песимізму (знання відсутні або суперечливі). Для будь-якого `x ∈ L` виконується `x ⊓ ⊥ = ⊥`, тобто `⊥ ⊑ x`.

```
        ⊤ (Top)          ← Максимум знань / Оптимістичний старт
       / \
      x   y              ← Проміжні абстрактні стани (x ⊓ y = ⊥)
       \ /
        ⊥ (Bottom)       ← Мінімум знань / Консервативна невизначеність
```

## 2. Умова обриву ланцюгів та висота ґратки

Ланцюгом у частково впорядкованій множині називають повністю впорядковану послідовність елементів:

```
x₀ ⊑ x₁ ⊑ x₂ ⊑ ... ⊑ xₖ
```

**Висотою ґратки** `Height(L)` називають довжину найдовшого строгого ланцюга від `⊥` до `⊤` (кількість переходів `xᵢ ⊏ xᵢ₊₁`).

У класичних задачах над бітовими векторами розмірності `V` (де `V` — кількість змінних або виразів у функції):
- Множина `L = 𝒫(U)` є булеаном універсуму з `|U| = V`.
- Частковий порядок — це включення підмножин `⊆` (або `⊇`).
- Висота ґратки є строго скінченною: `Height(L) = V`.

Скінченність висоти ґратки є фундаментальною: вона гарантує умову обриву спадних або зростаючих ланцюгів (Descending / Ascending Chain Condition), тобто неможливість нескінченного спуску під час уточнення фактів.

## 3. Монотонні функції передачі

Кожному базовому блоку або інструкції `B` зіставляється функція передачі стану `f_B: L → L`.

Функція `f_B` називається **монотонною**, якщо вона зберігає частковий порядок:

```
∀ x, y ∈ L :   x ⊑ y  ⇒  f_B(x) ⊑ f_B(y)
```

Еквівалентне алгебраїчне формулювання монотонності через оператор злиття:

```
∀ x, y ∈ L :   f_B(x ⊓ y) ⊑ f_B(x) ⊓ f_B(y)
```

**Доведення еквівалентності:**
Якщо `f_B` монотонна, то з очевидних нерівностей `x ⊓ y ⊑ x` та `x ⊓ y ⊑ y` випливає:

```
f_B(x ⊓ y) ⊑ f_B(x)
f_B(x ⊓ y) ⊑ f_B(y)
```

За визначенням операції `⊓` як точної нижньої межі (infimum), якщо елемент `A` менший або рівний за обидва елементи `B` та `C`, то `A ⊑ B ⊓ C`. Підставляючи `A = f_B(x ⊓ y)`, одержуємо:

```
f_B(x ⊓ y) ⊑ f_B(x) ⊓ f_B(y)
```

Монотонність гарантує, що коли знання на вході стають менш точними (зсуваються в бік `⊥`), знання на виході також можуть лише погіршуватися або залишатися незмінними, але ніколи не можуть хаотично коливатися вгору й вниз.

## 4. Теорема Тарського-Кнастера та збіжність алгоритму Кілдалла

Нехай `N` — кількість базових блоків у графі `CFG`. Глобальний стан аналізу представляється вектором `X = (X₁, X₂, ..., X_N) ∈ L^N`.

Глобальна функція передачі `F: L^N → L^N` обчислює новий вектор значень для всіх блоків одночасно:

```
F(X)[B] = f_B( ⊓_{P ∈ Pred(B)} X[P] )
```

Оскільки оператор `⊓` та локальні функції `f_B` є монотонними, функція `F` також є монотонним відображенням простору `L^N` у себе.

За **теоремою Кнастера — Тарського**, будь-яке монотонне відображення на повній ґратці має повну ґратку нерухомих точок, зокрема має єдину **найбільшу фіксовану точку** (англ. *Maximum Fixed Point*, MFP).

Алгоритм Кілдалла стартує з оптимістичного вектора `X⁽⁰⁾ = (⊤, ⊤, ..., ⊤)` (за винятком початкового вхідного блоку `Entry`, який ініціалізується граничним значенням задачі) і послідовно застосовує відображення `F`:

```
X⁽¹⁾ = F(X⁽⁰⁾)
X⁽²⁾ = F(X⁽¹⁾)
...
X⁽ᵏ⁺¹⁾ = F(X⁽ᵏ⁾)
```

Оскільки `X⁽¹⁾ ⊑ X⁽⁰⁾` (елемент `⊤` є найвищим), через монотонність `F` утворюється спадний ланцюг:

```
⊤ = X⁽⁰⁾ ⊒ X⁽¹⁾ ⊒ X⁽²⁾ ⊒ ... ⊒ X⁽ᵏ⁾ ⊒ X⁽ᵏ⁺¹⁾ ...
```

Оскільки висота простору `L^N` обмежена числом `N · Height(L)`, цей ланцюг не може містити більше ніж `N · Height(L) + 1` строго різних елементів. Отже, існує скінченний крок `m ≤ N · Height(L)`, на якому:

```
X⁽ᵐ⁺¹⁾ = X⁽ᵐ⁾
```

Вектор `X⁽ᵐ⁾` є точним розв'язком системи — найбільшою нерухомою точкою (MFP).

## 5. MOP проти MFP: Дистрибутивність та втрата точності

Ідеальним результатом статичного аналізу є розв'язок **Meet-Over-all-Paths (MOP)** — точне злиття результатів уздовж усіх можливих шляхів виконання програми від старту до блоку `B`:

```
MOP[B] = ⊓_{p ∈ Paths(Entry, B)} f_p(InitialState)
```

де `Paths(Entry, B)` — множина всіх шляхів у CFG від входу до блоку `B`, а `f_p` — композиція передавальних функцій блоків уздовж шляху `p = (B₁, B₂, ..., B_k)`:

```
f_p = f_{B_k} ∘ f_{B_{k-1}} ∘ ... ∘ f_{B₁}
```

Обчислити `MOP` безпосередньо неможливо в загальному випадку, оскільки кількість шляхів у графі з циклами є нескінченною. Алгоритм Кілдалла обчислює `MFP`, виконуючи операцію злиття `⊓` на кожному кроці розгалуження в графі, а не на кінцях усіх нескінченних шляхів.

Як співвідносяться `MFP` та `MOP`?

Функція передачі `f` називається **дистрибутивною**, якщо:

```
∀ x, y ∈ L :   f(x ⊓ y) = f(x) ⊓ f(y)
```

**Теорема Кілдалла — Кама — Ульмана (1977):**
1. Для будь-якого монотонного фреймворку розв'язок `MFP` є безпечним нижнім наближенням до `MOP`:
   ```
   MFP ⊑ MOP
   ```
2. Якщо всі передавальні функції фреймворку є **дистрибутивними**, то розв'язок алгоритму Кілдалла збігається з ідеальним розв'язком:
   ```
   MFP = MOP
   ```

### Чому для недистрибутивних задач виникає різниця `MFP ⊏ MOP`?

Усі класичні задачі над бітовими векторами (Reaching Definitions, Live Variables, Available Expressions) мають передавальні функції вигляду `f(x) = GEN ∪ (x \ KILL)`. Ці функції є строго дистрибутивними відносно об'єднання та перетину множин, тому для них `MFP = MOP`.

Однак складніші аналізи, такі як **поширення констант** (Constant Propagation) з обчисленням виразів або аналіз покажчиків, не є дистрибутивними.

**Контрприклад:**
Нехай блок `B₁` встановлює `(x = 2, y = 3)`, а блок `B₂` встановлює `(x = 3, y = 2)`. Обидва блоки переходять у блок `B₃`, що обчислює `z = x + y`.

1. **Ідеальний шлях MOP:**
   - На шляху через `B₁`: `z = 2 + 3 = 5`.
   - На шляху через `B₂`: `z = 3 + 2 = 5`.
   - Злиття в кінці: `5 ⊓ 5 = 5`. Розв'язок MOP знає, що `z = 5`.
2. **Ітеративний аналіз MFP:**
   - Злиття на вході в `B₃`: `(x=2 ⊓ x=3) = ⊥`, `(y=3 ⊓ y=2) = ⊥`.
   - Обчислення передавальної функції `B₃`: `z = ⊥ + ⊥ = ⊥`.
   - Розв'язок MFP стверджує, що `z` не є константою (`⊥`).

Розв'язок MFP виявився консервативнішим за MOP (`⊥ ⊑ 5`), оскільки передавальна функція додавання не розкривається дистрибутивно над парою незалежних змінних. Проте він залишається повністю **безпечним**: компілятор не виконає хибної оптимізації, а лише пропустить потенційне спрощення.

## 6. Оцінка обчислювальної складності

При використанні алгоритму робочого списку (Worklist Algorithm) кожен блок `B` додається до черги на перерахунок лише тоді, коли змінився стан хоча б одного з його попередників.

Оскільки стан кожного блоку може змінюватися в бік погіршення не більше ніж `Height(L)` разів, максимальна кількість викликів передавальних функцій та операторів злиття обмежена величиною:

```
Час виконання = O( Height(L) · |E| )
```

де `|E|` — кількість ребер у графі CFG. Для бітвекторних задач над функцією з `N` блоками та `V` змінними за умов розрідженого графа (`|E| = O(N)`), загальна складність становить `O(V · N)`, що забезпечує швидку роботу навіть на великих кодових базах.
