# 📋 Довідник синтаксису та API регулярних виразів: BRE, ERE та PCRE

Цей довідник містить формальну специфікацію синтаксичних правил, спеціальних послідовностей та системних інтерфейсів для трьох ключових стандартів регулярних виразів: базових POSIX (BRE), розширених POSIX (ERE) та Perl-сумісних регулярних виразів (PCRE). Довідник визначає семантику метасимволів, правила екранування, поведінку символьних класів із урахуванням локалей, а також контракт викликів системного інтерфейсу POSIX C API `<regex.h>` та його ідіоматичного аналога в C++.

## Семантика метасимволів та правила екранування

Головна відмінність між діалектами полягає в інтерпретації спеціальних символів за замовчуванням. У стандарті BRE більшість керівних символів за замовчуванням сприймаються як звичайні текстові літерали, тому для активації їхньої синтаксичної ролі потрібен зворотний слеш. У стандартах ERE та PCRE керівні символи діють як оператори за замовчуванням, а зворотний слеш використовується для їхнього знешкодження (перетворення на буквальний текст).

У наведеній нижче таблиці зіставлено синтаксичні конструкції для кожного з трьох стандартів:

| Можливість / Конструкція | BRE (POSIX Basic) | ERE (POSIX Extended) | PCRE (Perl Compatible) |
|---|---|---|---|
| Довільний символ крім `\n` | `.` | `.` | `.` (або всі символи з прапорцем `s`) |
| Початок рядка | `^` | `^` | `^` (або початок тексту з `\A`) |
| Кінець рядка | `$` | `$` | `$` (або кінець тексту з `\z`, `\Z`) |
| Символьний клас | `[abc]`, `[^abc]` | `[abc]`, `[^abc]` | `[abc]`, `[^abc]` |
| Замикання (0 або більше) | `*` | `*` | `*` (жадібне), `*?` (ліниве), `*+` (посесивне) |
| 1 або більше разів | `\+` (GNU) / немає | `+` | `+` (жадібне), `+?` (ліниве), `++` (посесивне) |
| 0 або 1 раз (опційно) | `\?` (GNU) / немає | `?` | `?` (жадібне), `??` (ліниве), `?+` (посесивне) |
| Діапазон повторень | `\{m,n\}` | `{m,n}` | `{m,n}` (жадібне), `{m,n}?` (ліниве), `{m,n}+` |
| Фіксуюча група | `\(` ... `\)` | `(` ... `)` | `(` ... `)` |
| Нефіксуюча група | Не підтримується | Не підтримується | `(?:` ... `)` |
| Чергування (або) | `\|` (GNU) / немає | `\|` | `\|` |
| Зворотні посилання | `\1` .. `\9` | Не стандартизовано | `\1` .. `\99`, `\g{1}`, `\k<name>` |
| Іменовані групи | Не підтримується | Не підтримується | `(?<name>...)` або `(?'name'...)` |
| Позитивна перевірка вперед (*Lookahead*) | Не підтримується | Не підтримується | `(?=...)` |
| Негативна перевірка вперед (*Neg Lookahead*) | Не підтримується | Не підтримується | `(?!...)` |
| Позитивна перевірка назад (*Lookbehind*) | Не підтримується | Не підтримується | `(?<=...)` (фіксована довжина) |
| Негативна перевірка назад (*Neg Lookbehind*) | Не підтримується | Не підтримується | `(?<!...)` (фіксована довжина) |
| Атомарне групування | Не підтримується | Не підтримується | `(?>...)` |

Слід звернути особливу увагу на такі крайові випадки синтаксису:
- **Позиція символу дефіса ` - ` у символьних класах:** якщо дефіс стоїть першим або останнім символом у квадратних дужках (наприклад, `[-abc]` або `[abc-]`), він трактується як звичайний літерал, а не як оператор діапазону.
- **Закриваюча квадратна дужка ` ] ` у класах:** якщо дужка `]` стоїть першим символом після відкриваючої дужки (або після знака заперечення: `[]abc]` або `[^]abc]`), вона сприймається як звичайний символ множини, а не як закриття класу.
- **Спеціальні позиції `^` та `$ `:** у стандарті BRE символи `^` та `$` мають значення прив'язки до початку та кінця рядка лише тоді, коли вони стоять відповідно на першій та останній позиції підвиразу. Всередині виразу в BRE вони вважаються звичайними літералами. У стандартах ERE та PCRE вони є метасимволами на будь-якій позиції.

## Стандартизовані символьні класи POSIX

Традиційні діапазони символів на кшталт `[a-z]` або `[A-Z]` спираються на числові коди таблиці ASCII. У багатомовних середовищах із локалями UTF-8 або сортуванням за національними алфавітами порядок символів може призводити до неочікуваного зіставлення (наприклад, включення великих літер у діапазон малих в деяких європейських локалях).

Для забезпечення переносності та коректної роботи зі стандартами локалізації POSIX увів стандартизовані символьні класи. Класи POSIX записуються виключно всередині квадратних дужок символьного класу: `[[:class:]]`.

| POSIX-клас | ASCII-еквівалент | Опис множини символів |
|---|---|---|
| `[:alnum:]` | `[a-zA-Z0-9]` | Буквено-цифрові символи |
| `[:alpha:]` | `[a-zA-Z]` | Літери (з урахуванням поточної локалі) |
| `[:blank:]` | `[ \t]` | Горизонтальні пробіли (пробіл і табуляція) |
| `[:cntrl:]` | `[\x00-\x1F\x7F]` | Керуючі символи |
| `[:digit:]` | `[0-9]` | Десяткові цифри |
| `[:graph:]` | `[\x21-\x7E]` | Друковані видимі символи (без пробілу) |
| `[:lower:]` | `[a-z]` | Малі літери |
| `[:print:]` | `[\x20-\x7E]` | Друковані символи (включаючи пробіл) |
| `[:punct:]` | `[!\"#$%&'()*+,-./:;<=>?@[\]^_`{|}~]` | Символи пунктуації |
| `[:space:]` | `[ \t\r\n\v\f]` | Будь-які пробільні символи |
| `[:upper:]` | `[A-Z]` | Великі літери |
| `[:xdigit:]` | `[0-9a-fA-F]` | Шістнадцяткові цифри |

Крім стандартних класів, POSIX визначає дві розширені конструкції для роботи з національними алфавітами:
- **Елементи сортування (*Collation Elements*), `[[.ch.]]`:** дозволяють зіставляти багатосимвольні послідовності, які в певній мові вважаються єдиною літерою (наприклад, диграфи `ch` в іспанській або `ll` у валлійській мові).
- **Класи еквівалентності (*Equivalence Classes*), `[[=e=]]`:** зіставляються з базовим символом та всіма його діакритичними еквівалентами в поточній локалі (наприклад, `e`, `é`, `è`, `ê`, `ë`).

## Спеціальні скорочені класи та керуючі послідовності PCRE

Бібліотека PCRE та похідні від неї рушії надають компактні скорочення через зворотний слеш для найчастіших класів символів, а також спеціальні символи межі:

| Скорочення | Опис | Еквівалентний набір |
|---|---|---|
| `\d` / `\D` | Цифра / Не цифра | `[0-9]` / `[^0-9]` |
| `\w` / `\W` | Символ слова / Не символ слова | `[a-zA-Z0-9_]` / `[^a-zA-Z0-9_]` |
| `\s` / `\S` | Пробільний / Не пробільний | `[ \t\r\n\f\v]` / `[^ \t\r\n\f\v]` |
| `\b` / `\B` | Межа слова / Не межа слова | Позиція між `\w` та `\W` (нульова ширина) |
| `\h` / `\H` | Горизонтальний пробіл / Ні | `[ \t\xA0...]` |
| `\v` / `\V` | Вертикальний перехід рядка / Ні | `[\n\r\x0B\x0C\x85...]` |
| `\A` / `\z` | Абсолютний початок / кінець тексту | Не залежить від прапорця багаторядковості |
| `\p{L}` | Будь-яка літера Unicode | Загальна категорія Unicode *Letter* |
| `\p{N}` | Будь-яке числове значення Unicode | Загальна категорія Unicode *Number* |
| `\p{P}` | Пунктуація Unicode | Загальна категорія Unicode *Punctuation* |

## Системний інтерфейс POSIX C API (`<regex.h>`) та C++

Системний стандарт POSIX визначає чотири функції для повного життєвого циклу компіляції та виконання регулярних виразів. Усі структури даних та оголошення функцій містяться в системному заголовку `<regex.h>`.

:::tabs
```c
/* Оголошення функцій POSIX C API (<regex.h>) */
int regcomp(regex_t *preg, const char *regex, int cflags);
int regexec(const regex_t *preg, const char *string, size_t nmatch, regmatch_t pmatch[], int eflags);
size_t regerror(int errcode, const regex_t *preg, char *errbuf, size_t errbuf_size);
void regfree(regex_t *preg);
```
```cpp
// Стандартні еквіваленти C++ (<regex> та POSIX RAII)
#include <regex>
#include <string_view>

// C++ стандартний інтерфейс std::regex
bool match_cpp(std::string_view text, const std::regex& re) {
    return std::regex_search(text.begin(), text.end(), re);
}
```
:::

### Прапорці компіляції (`cflags` для функції `regcomp`)

Прапорці компіляції передаються у функцію `regcomp` як бітова маска (побітове «АБО» `|`):

- **`REG_EXTENDED`:** активує синтаксис розширених регулярних виразів (ERE). Якщо цей прапорець не вказано, вираз компілюється за правилами базових виразів (BRE).
- **`REG_ICASE`:** вмикає зіставлення без урахування регістру літер (*case-insensitive matching*). При перевірці символів використовується системна таблиця перетворення регістру поточної локалі `LC_CTYPE`.
- **`REG_NOSUB`:** оптимізує виконання, повідомляючи рушію, що позиції окремих захоплених підгруп не потрібні. Якщо встановлено цей прапорець, функція `regexec` ігнорує параметри `nmatch` та `pmatch`, повертаючи лише загальний статус успіху (`0`) або невдачі (`REG_NOMATCH`), що істотно скорочує накладні витрати на виділення пам'яті.
- **`REG_NEWLINE`:** активує спеціальну семантику для символів переходу на новий рядок `\n`:
  1. Метасимвол початку рядка `^` зіставляється з початком всього тексту, а також із позицією безпосередньо після кожного символу `\n`.
  2. Метасимвол кінця рядка `$` зіставляється з кінцем всього тексту, а також із позицією безпосередньо перед кожним символом `\n`.
  3. Метасимвол крапки `.` перестає зіставлятися із символом `\n`.
  4. Заперечні символьні класи на кшталт `[^abc]` перестають зіставлятися із `\n`.

### Прапорці виконання (`eflags` для функції `regexec`)

Прапорці виконання передаються у функцію `regexec` і керують обробкою меж при потоковому розборі фрагментів тексту:

- **`REG_NOTBOL` (*Not Beginning of Line*):** перший байт переданого рядка не вважається початком рядка. Метасимвол `^` не зіставлятиметься з нульовою позицією рядка (хоча продовжить зіставлятися після символів `\n`, якщо ввімкнено `REG_NEWLINE`). Цей прапорець обов'язковий при пошуку шаблонів у тексті, розбитому на послідовні буфери.
- **`REG_NOTEOL` (*Not End of Line*):** кінцевий байт переданого рядка не вважається кінцем рядка. Метасимвол `$` не зіставлятиметься з кінцем поточного буфера.

### Коди помилок POSIX та їхнє діагностичне значення

Якщо функція `regcomp` або `regexec` повертає ненульове значення, воно відповідає одному зі стандартизованих кодів помилок. Текстовий опис помилки формується викликом функції `regerror`:

| Константа коду помилки | Числове значення / Опис |
|---|---|
| `REG_NOMATCH` | Збігу не знайдено (є штатним результатом для `regexec`) |
| `REG_BADPAT` | Неприпустимий або синтаксично некоректний регулярний вираз |
| `REG_ECOLLATE` | Неприпустиме ім'я елемента зіставлення `[.name.]` |
| `REG_ECTYPE` | Неприпустиме ім'я типу символьного класу `[:class:]` |
| `REG_EESCAPE` | Завершальний символ `\` без наступного екранованого символу |
| `REG_ESUBREG` | Неприпустимий номер зворотного посилання `\1`..`\9` |
| `REG_EBRACK` | Незбалансовані квадратні дужки `[` або `]` |
| `REG_EPAREN` | Незбалансовані круглі дужки `(` або `)` |
| `REG_EBRACE` | Незбалансовані фігурні дужки `{` або `}` |
| `REG_BADBR` | Неприпустимий вміст усередині діапазону `{m,n}` (наприклад, `m > n`) |
| `REG_ERANGE` | Неприпустимий діапазон символів (наприклад, `[z-a]`) |
| `REG_ESPACE` | Вичерпано доступну оперативну пам'ять під час компіляції автомата |
| `REG_BADRPT` | Неприпустиме використання квантифікатора (наприклад, `*` на початку виразу) |

Правильна обробка помилок вимагає передачі буфера достатнього розміру у `regerror`. Якщо розмір наданого буфера `errbuf_size` менший за довжину діагностичного повідомлення, функція `regerror` записує обрізане повідомлення з нуль-термінатором і повертає повну кількість байтів, необхідну для повного запису тексту помилки.
