# 🧮 Математична модель збіжності живої міграції

Процес живої міграції віртуальної машини методом ітеративного попереднього копіювання (Pre-Copy) є динамічною системою, де мережевий канал намагається вичерпати обсяг модифікованої пам'яті швидше, ніж гостьові процесори встигають його генерувати.

Якщо швидкість запису гостя перевищує пропускну здатність мережі або наближається до неї, міграція перетворюється на нескінченний процес або спричиняє неприпустимо довгий час простою (downtime). Нижче наведено строго формалізовану математичну модель, яка описує умови збіжності, розподіл інтенсивності оновлення сторінок, компресію різниць, кількість ітерацій, сумарний обсяг переданого трафіку, тривалість зупинки сервісу та параметри необхідного процесорного тротлінгу.

## Базові змінні та формалізація параметрів

Визначимо ключові величини системи:

- `V₀` — повний обсяг фізичної оперативної пам'яті віртуальної машини (МБ або ГБ);
- `B` — ефективна пропускна здатність мережевого каналу, виділена під потік міграції (МБ/с);
- `D(t)` — миттєва швидкість модифікації пам'яті гостьовою операційною системою (англ. *dirty rate*, МБ/с). У базовій лінійній моделі приймемо середнє стаціонарне значення `D`;
- `S_dev` — розмір бінарного стану віртуальних пристроїв, регістрів vCPU, структур vAPIC, дескрипторів virtio та системних таймерів (МБ);
- `T_down_max` — гранично допустимий час зупинки віртуальної машини (секунди), визначений угодою про рівень обслуговування (SLA);
- `V_th` — пороговий обсяг залишкової брудної пам'яті для безпечного переходу до фінальної фази повної зупинки (Stop-and-Copy):

```
V_th = B · T_down_max - S_dev
```

Якщо залишкова брудна пам'ять задовольняє нерівність `V_n ≤ V_th`, гіпервізор гарантовано вкладеться у встановлений дедлайн `T_down_max` під час передачі фінального блоку даних.

## Рекурентна модель лінійного попереднього копіювання

Процес попереднього копіювання складається з послідовності раундів `n = 0, 1, 2, ...`:

### Раунд 0 (Повний початковий дамп пам'яті)
У початковому раунді `n = 0` передається весь масив виділеної оперативної пам'яті `V₀`.
Тривалість нульового раунду визначається виключно швидкістю мережі:
```
T₀ = V₀ / B
```
За час `T₀` гостьова операційна система продовжує виконувати інструкції та модифікує новий обсяг пам'яті `V₁`:
```
V₁ = D · T₀          [генерація брудної пам'яті за час T₀]
   = D · (V₀ / B)    [підстановка T₀ = V₀ / B]
   = V₀ · (D / B)    [перегрупування множників]
```

### Раунд 1
У першому раунді передається накопичений обсяг брудної пам'яті `V₁`.
Тривалість першого раунду:
```
T₁ = V₁ / B = (V₀ · D) / B²
```
Обсяг пам'яті, модифікований під час раунду 1:
```
V₂ = D · T₁ = V₀ · (D / B)²
```

### Раунд n (Загальний вигляд)
Узагальнюючи залежність для довільного раунду `n`:
Тривалість раунду `n`:
```
T_n = V_n / B
```
Обсяг пам'яті, що підлягає передачі на наступній ітерації `n + 1`:
```
V_(n+1) = D · T_n              [брудні дані за час раунду T_n]
        = V_n · (D / B)        [підстановка T_n = V_n / B]
        = V₀ · (D / B)^(n+1)   [індукція за раундами 0..n]
```

Введемо коефіцієнт збіжності міграції `ρ` (безрозмірна величина, що характеризує баланс між генерацією змін та пропускною здатністю каналу):
```
ρ = D / B
```

Тоді обсяг брудної пам'яті на кроці `n` та тривалість відповідного раунду описуються членами геометричної прогресії:
```
V_n = V₀ · ρⁿ
T_n = (V₀ / B) · ρⁿ
```

## Неоднорідність пам'яті та степеневий розподіл Парето–Ціпфа

У реальних гостьових системах лінійна залежність `V_(n+1) = D · T_n` є спрощенням, оскільки пам'ять модифікується вкрай неоднорідно. Програми не розкидають записи рівномірно по всьому адресному простору: переважна більшість операцій запису багаторазово переписує один і той самий **гарячий робочий набір (англ. *Working Set*, W)**.

Якщо сторінка розміром 4 КБ була модифікована 10 000 разів протягом одного раунду тривалістю `T_n`, гіпервізор відправляє її по мережі **лише один раз**, оскільки в бітовій масці брудних сторінок встановлюється рівно один біт.

Розподіл частоти звернень до сторінок пам'яті в базах даних, веб-серверах та компіляторах підпорядковується емпіричному **закону Парето–Ціпфа (степеневий закон локальності)**. Якщо впорядкувати всі `M = V₀ / 4КБ` сторінок за спаданням частоти запису, ймовірність модифікації сторінки з рангом `r` (`r = 1, 2, ..., M`) описується формулою:

```
P(r) = C / r^γ
```
де `γ ≈ 0.7 .. 1.2` — показник ступеня концентрації доступу, а `C = 1 / ∑_{i=1}^{M} i^(-γ)` — нормувальна константа.

При `γ = 1.0` (чистий закон Ціпфа) 80% усіх операцій запису припадає на верхні 20% адресного простору пам'яті. Це означає, що при сумарному потоці запису `D` (МБ/с) швидкість розширення множини унікальних брудних сторінок швидко сповільнюється з часом.

Нехай `W_hot` — обсяг гарячого робочого набору (МБ), а `W_cold` — обсяг холодної пам'яті, де `V₀ = W_hot + W_cold`.
Ймовірність того, що конкретна сторінка з гарячого набору буде модифікована бодай один раз за час раунду `T_n`, описується експоненційним законом Пуассона для унікальних подій:

```
V_effective(T_n) = W_hot · [ 1 - e^(-(D · T_n) / W_hot) ] + D_cold · T_n
```

де `D_cold` — фонова швидкість модифікації рідко використовуваної пам'яті.

При великій тривалості перших раундів (`T_n >> W_hot / D`) обсяг модифікованої пам'яті асимптотично насичується на рівні `W_hot`:
```
lim_{T_n → ∞} V_effective(T_n) = W_hot
```
Це означає, що обсяг брудної пам'яті на перших ітераціях ніколи не перевищує розміру активного робочого набору програми, навіть якщо гостьовий процесор записує гігабайти даних за секунду. Проте на фінальних коротких ітераціях експонента наближається до лінійної моделі Тейлора: `1 - e^(-x) ≈ x`, і збіжність знову підпорядковується коефіцієнту `ρ = D / B`.

## Оптимальний момент гібридного перемикання (Pre-Copy ➔ Post-Copy)

Сучасні оркестратори використовують комбіновану стратегію: міграція починається в режимі Pre-Copy (щоб передати більшу частину пам'яті без будь-якого впливу на продуктивність гостя), а коли швидкість збіжності сповільнюється, система динамічно перемикається в режим Post-Copy.

Сформулюємо задачу знаходження оптимального раунду перемикання `k_opt`. Введемо цільову функцію сукупних витрат системи `J(k)`:

```
J(k) = w₁ · T_total(k) + w₂ · T_down(k) + w₃ · Penalty_post(k)
```

де:
- `w₁, w₂, w₃` — вагові коефіцієнти важливості тривалості міграції, простою та деградації продуктивності;
- `T_total(k)` — сумарний час міграції при перемиканні на кроці `k`;
- `T_down(k)` — тривалість зупинки гостя;
- `Penalty_post(k) = N_remaining_faults(k) · RTT_net` — штраф за затримку сторінкових збоїв.

Оскільки в режимі Pre-Copy кожен раунд `i < k` зменшує обсяг залишкової холодної пам'яті, кількість сторінок, які спричинять промахи в режимі Post-Copy, монотонно спадає з кожною ітерацією:
```
N_remaining_faults(k) ≈ (V_k / Page_Size) · (1 - Hit_ratio_local)
```

Оптимальний момент перемикання `k_opt` настає тоді, коли маржинальне зменшення штрафу від сторінкових збоїв зрівнюється з ціною додаткового раунду попереднього копіювання:
```
d/dk [ J(k) ] = 0
w₁ · T_k = w₃ · [ N_faults(k) - N_faults(k+1) ] · RTT_net
```
Якщо черговий раунд Pre-Copy скорочує обсяг брудної пам'яті менш ніж на 15–20% від попереднього (`V_(n+1) / V_n > 0.80`), подальше виконання Pre-Copy стає енергетично та мережево невигідним: оркестратор негайно ініціює команду `migrate-start-postcopy`.

## Аналіз умов збіжності лінійної та нелінійної моделей

Поведінка системи повністю визначається значенням коефіцієнта збіжності `ρ`:

### 1. Випадок збіжності: ρ < 1 (Швидкість запису менша за мережевий канал)

Оскільки `ρ < 1`, послідовність `V_n = V₀ · ρⁿ` строго монотонно прямує до нуля при `n → ∞`.
Міграція завершується на кроці `N`, коли обсяг залишкової пам'яті стає меншим або рівним порогу `V_th`:

```
V_N ≤ V_th
V₀ · ρ^N ≤ V_th
ρ^N ≤ V_th / V₀
```

Логарифмуючи обидві частини нерівності (враховуючи, що `ln(ρ) < 0`, знак нерівності змінюється на протилежний):
```
N · ln(ρ) ≤ ln(V_th / V₀)
N ≥ ln(V_th / V₀) / ln(ρ)
```

Кількість необхідних ітерацій попереднього копіювання до переходу у Stop-and-Copy:
```
N = ⌈ ln(V_th / V₀) / ln(D / B) ⌉
```

### Сумарний час попереднього копіювання (T_pre)
Загальний час виконання всіх `N` раундів попереднього копіювання є сумою членів геометричної прогресії:

```
T_pre = ∑_{k=0}^{N-1} T_k                      [сума тривалостей N раундів]
      = (V₀ / B) · ∑_{k=0}^{N-1} ρ^k           [винесення спільного множника T₀ = V₀ / B]
      = (V₀ / B) · [ (1 - ρ^N) / (1 - ρ) ]     [формула суми скінченної геометричної прогресії]
```

### Фінальний час простою (T_downtime)
Після `N` раундів віртуальна машина призупиняється. У фазі Stop-and-Copy передається залишок `V_N` та стан пристроїв `S_dev`:

```
T_down = (V_N + S_dev) / B
       = (V₀ · ρ^N + S_dev) / B
```

Повний час від старту міграції до відновлення роботи гостя на цільовому вузлі:
```
T_total = T_pre + T_down                                              [сума фаз Pre-Copy та Stop-and-Copy]
        = (V₀ / B) · [ (1 - ρ^N) / (1 - ρ) ] + (V₀ · ρ^N + S_dev) / B  [підстановка формул T_pre та T_down]
```

### Сумарний обсяг переданих даних (V_total)
Загальна кількість байтів, переданих через мережу:
```
V_total = B · T_total                                         [обсяг даних за формулою V = B · T]
        = V₀ · [ (1 - ρ^N) / (1 - ρ) ] + V₀ · ρ^N + S_dev     [розкриття добутку B · T_total]
        = V₀ · [ (1 - ρ^(N+1)) / (1 - ρ) ] + S_dev            [зведення дробів до спільного знаменника]
```

При нескінченній кількості раундів (`N → ∞`) теоретичний граничний обсяг переданого трафіку становить:
```
lim_{N→∞} V_total = V₀ / (1 - ρ) + S_dev
```

Коефіцієнт надлишковості передачі трафіку (англ. *network overhead factor*):
```
η = V_total / V₀ ≈ 1 / (1 - ρ)
```

```

┌────────┬────────────────┬──────────────────────┬───────────────────────────┐
```

### 2. Випадок розбіжності: ρ ≥ 1 (Швидкість запису перевищує мережу)

Якщо `D ≥ B`, послідовність `V_n = V₀ · ρⁿ` не спадає:
```
V_(n+1) ≥ V_n
```
Обсяг брудної пам'яті на кожному кроці збільшується або залишається незмінним. Міграція ніколи не досягне порогу `V_th`, а процес передачі перетворюється на нескінченну утилізацію мережевого каналу.

## Математика диференційної компресії (XBZRLE)

Для зниження обсягу переданих даних при повторних відправках тієї самої сторінки застосовують алгоритм **XBZRLE (XOR-Based Zero Run-Length Encoding)**.

Нехай сторінка пам'яті `P_old` була відправлена на ітерації `n - 1`. На ітерації `n` гість змінив кілька байтів, утворивши `P_new`. Замість передачі повних 4096 байтів обчислюється порозрядна різниця:
```
Δ = P_new ⊕ P_old
```
Оскільки більшість структур даних змінюють лише окремі лічильники або вказівники, масив `Δ` складається переважно з довгих послідовностей нульових байтів (`0x00`), які стискаються алгоритмом RLE (Run-Length Encoding).

Нехай `C_ratio ≥ 1.0` — коефіцієнт компресії різниць:
```
C_ratio = Size(P_new) / Size(Compressed(Δ))
```

Тоді ефективний обсяг брудної пам'яті, що підлягає передачі по мережі, зменшується:
```
V'_n = V_n / C_ratio
```

Ефективна швидкість передачі зі сторони гостьової пам'яті еквівалентна зростанню пропускної здатності каналу:
```
B_eff = B · C_ratio
ρ_eff = D / B_eff = D / (B · C_ratio) = ρ / C_ratio
```

Якщо базовий коефіцієнт становив `ρ = 1.2` (розбіжність), але алгоритм XBZRLE забезпечує коефіцієнт стиснення `C_ratio = 2.5` для оновлень структур СУБД, новий ефективний коефіцієнт стає:
```
ρ_eff = 1.2 / 2.5 = 0.48 < 1
```
Система переходить зі стану нескінченного циклу в режим стійкої збіжності без будь-якого уповільнення роботи гостя.

## Багатопотокова передача (Multifd) та пропускна здатність TCP

Окремий потік TCP часто не здатний утилізувати 100-гігабітний мережевий адаптер через обмеження вікна перевантаження (TCP Congestion Window) та затримки обробки одним ядром CPU.

За формулою Матіса (Mathis Formula), максимальна швидкість одного TCP-з'єднання при втратах пакетів з ймовірністю `p` та часі кругового обігу `RTT` обмежена зверху:
```
Throughput_TCP ≤ (MSS · C) / (RTT · √p)
```
де `MSS` — максимальний розмір сегмента (зазвичай 1460 байтів для стандартного MTU 1500 або 8960 байтів для Jumbo Frames), а `C ≈ 1.22`.

При `RTT = 0.5 мс` та незначній втраті пакетів `p = 0.0001` один потік TCP здатний передати:
```
Throughput_single ≤ (8960 · 8 · 1.22) / (0.0005 · 0.01) = 87459 / 0.000005 ≈ 17.5 Гбіт/с ≈ 2.18 ГБ/с
```
Це не дозволяє наситити лінк 100 GbE (~11.5 ГБ/с).

Використання `M` паралельних потоків міграції (архітектура **Multifd**) агрегує пропускну здатність:
```
B_multifd(M) = min( ∑_{i=1}^{M} Throughput_single_i,  B_nic_limit,  B_cpu_crypto )
```
При `M = 8` потоках сумарна смуга досягає лінійної швидкості інтерфейсу `B ≈ 11.5 ГБ/с`, що пропорційно зменшує коефіцієнт `ρ = D / B` у 4–8 разів.

## Математика процесорного тротлінгу (Auto-Converge)

Якщо резерви мережі вичерпані, а `ρ ≥ 1`, гіпервізор застосовує механізм Auto-Converge, штучно пригнічуючи процесорні цикли vCPU гостя.

Нехай `α ∈ [0, 0.99]` — коефіцієнт процесорного тротлінгу (частка примусового простою vCPU). Оскільки швидкість модифікації пам'яті прямо пропорційна кількості виконаних процесорних інструкцій запису:
```
D' = D · (1 - α)
```

Новий ефективний коефіцієнт збіжності:
```
ρ' = D' / B = [ D · (1 - α) ] / B = ρ · (1 - α)
```

Щоб гарантувати збіжність (`ρ' < 1`), коефіцієнт тротлінгу `α` повинен задовольняти строгу нерівність:
```
ρ · (1 - α) < 1
1 - α < 1 / ρ
α > 1 - (1 / ρ)
α > 1 - (B / D)
```

У виробничих гіпервізорах (QEMU / KVM) коефіцієнт `α` збільшується ступінчасто після кожного невдалого раунду:
```
α_(k+1) = min( α_k + Δα, α_max )
```
де початковий крок `α₀ = 0.20` (20%), приріст `Δα = 0.10` (10%), а максимальна межа `α_max = 0.95` (95%).

## Модель парадигми Post-Copy

У парадигмі Post-Copy віртуальна машина зупиняється на вихідному вузлі негайно на початку процесу.

### Час простою Post-Copy (T_down_post)
У фазі початкової паузи передається лише стан пристроїв `S_dev` та мінімальна кількість базових сторінок ядра `V_min` (зазвичай кілька мегабайтів):

```
T_down_post = (S_dev + V_min) / B
```
Ця величина є константою і не залежить від загального обсягу оперативної пам'яті `V₀` чи швидкості запису `D`.

### Повний час Post-Copy (T_total_post)
Після відновлення vCPU на цільовому хості вся пам'ять передається рівно один раз (`V₀`). Загальний час складається з фонової передачі та сумарної затримки обслуговування сторінкових збоїв:

```
T_total_post = T_down_post + (V₀ / B) + N_faults · RTT_net
```
де:
- `N_faults` — кількість сторінок, звернення до яких викликало мережевий Page Fault через `userfaultfd`;
- `RTT_net` — затримка мережевого запиту сторінки між хостами (Round-Trip Time, типово 0.05–0.2 мс).

Оскільки кожна сторінка пам'яті передається через мережу **рівно один раз**, обсяг трафіку в Post-Copy строго обмежений:
```
V_total_post = V₀ + S_dev
```
Коефіцієнт надлишковості трафіку в Post-Copy завжди тотожно дорівнює одиниці: `η_post = 1.0`.

### Дилатація часу виконання гостя під час Post-Copy
Кожен промах повз локальну пам'ять призупиняє відповідний потік vCPU на час `RTT_net`. Якщо гостьовий потік робить `f` звернень до відсутніх сторінок на секунду, його швидкість виконання сповільнюється у коефіцієнт разів:

```
Dilation_factor = 1 / ( 1 - f · RTT_net )
```
При `f = 2000 faults/s` та `RTT_net = 0.0001 с` (100 мкс) дилатація становить:
```
Dilation_factor = 1 / ( 1 - 2000 · 0.0001 ) = 1 / 0.80 = 1.25 ×  (сповільнення на 25%)
```

## Практичний розрахунок реального інженерного сценарію

Розглянемо практичний приклад розрахунку міграції сервера високонавантаженої СУБД:

**Вихідні дані інфраструктури:**
- Обсяг пам'яті ВМ: `V₀ = 128 ГБ = 131072 МБ`
- Мережевий канал (10 GbE з урахуванням оверхеду TCP/IP): `B = 1100 МБ/с`
- Стан пристроїв: `S_dev = 32 МБ`
- Цільовий час простою (SLA): `T_down_max = 0.050 с` (50 мілісекунд)

Розрахуємо пороговий обсяг Stop-and-Copy:
```
V_th = B · T_down_max - S_dev    [баланс залишкової пам'яті та дедлайну простою]
     = 1100 · 0.050 - 32         [підстановка B=1100 МБ/с, T=0.050 с, S_dev=32 МБ]
     = 55 - 32                   [обчислення добутку 1100 · 0.050 = 55]
     = 23 МБ                     [пороговий залишок пам'яті]
```

---

### Сценарій 1: Помірне навантаження запису (D = 350 МБ/с)

1. **Коефіцієнт збіжності:**
```
ρ = D / B = 350 / 1100 ≈ 0.3182 < 1  (система строго збіжна)
```

2. **Кількість ітерацій до досягнення порогу V_th = 23 МБ:**
```
N = ⌈ ln(V_th / V₀) / ln(ρ) ⌉              [формула кількості ітерацій]
  = ⌈ ln(23 / 131072) / ln(0.3182) ⌉        [підстановка значень V_th, V₀ та ρ]
  = ⌈ ln(0.00017547) / (-1.1451) ⌉          [обчислення дробу 23/131072 та ln(0.3182)]
  = ⌈ -8.6481 / (-1.1451) ⌉                 [обчислення натурального логарифма ln(0.00017547)]
  = ⌈ 7.55 ⌉                                [ділення логарифмів]
  = 8 ітерацій                              [округлення до більшого цілого ⌈7.55⌉]
```

3. **Покрокова таблиця збіжності:**
```
┌──────────┬──────────────┬──────────────┬──────────────────┐
│ Ітерація │ Обсяг RAM    │ Час раунду   │ Брудна пам'ять   │
│   (n)    │   V_n (МБ)   │   T_n (с)    │  V_(n+1) (МБ)    │
├──────────┼──────────────┼──────────────┼──────────────────┤
│    0     │  131072.0    │   119.16 с   │     41704.7      │
│    1     │   41704.7    │    37.91 с   │     13270.3      │
│    2     │   13270.3    │    12.06 с   │      4222.6      │
│    3     │    4222.6    │     3.84 с   │      1343.6      │
│    4     │    1343.6    │     1.22 с   │       427.5      │
│    5     │     427.5    │     0.39 с   │       136.0      │
│    6     │     136.0    │     0.12 с   │        43.3      │
│    7     │      43.3    │     0.04 с   │        13.8      │
│ Stop&Copy│      13.8    │     0.042 с  │ (пауза гостя)    │
└──────────┴──────────────┴──────────────┴──────────────────┘
```

4. **Підсумкові метрики сценарію 1:**
- Залишок пам'яті на 7-й ітерації: `13.8 МБ ≤ 23 МБ` (умова виконана).
- Реальний час простою у Stop-and-Copy:
```
T_down = (13.8 + 32.0) / 1100 = 45.8 / 1100 = 0.0416 с = 41.6 мс  (< 50 мс SLA)
```
- Сумарний час міграції:
```
T_total = 119.16 + 37.91 + 12.06 + 3.84 + 1.22 + 0.39 + 0.12 + 0.04 + 0.042 ≈ 174.78 секунд (~2.9 хв)
```
- Сумарний обсяг переданих даних:
```
V_total = 131072 + 41705 + 13270 + 4223 + 1344 + 428 + 136 + 43 + 14 + 32 = 192267 МБ ≈ 187.76 ГБ
Надлишковість: η = 187.76 / 128 = 1.47 ×
```

---

### Сценарій 2: Важке навантаження запису (D = 1400 МБ/с)

1. **Коефіцієнт збіжності:**
```
ρ = D / B = 1400 / 1100 ≈ 1.2727 > 1  (система РОЗБІЖНА)
```
Швидкість генерації брудних сторінок випереджає пропускну здатність 10-гігабітної мережі. Без регулювання міграція зависає в нескінченному циклі.

2. **Застосування Auto-Converge тротлінгу:**
Встановлюємо ступінь тротлінгу `α = 0.65` (примусове пригнічення 65% процесорного часу гостя):
```
D' = 1400 · (1 - 0.65) = 490 МБ/с
ρ' = 490 / 1100 ≈ 0.4455 < 1  (збіжність успішно відновлено)
```

Кількість необхідних ітерацій:
```
N = ⌈ ln(23 / 131072) / ln(0.4455) ⌉   [формула кількості ітерацій для ρ'=0.4455]
  = ⌈ -8.6481 / (-0.8086) ⌉            [обчислення логарифма ln(0.4455) = -0.8086]
  = ⌈ 10.69 ⌉                          [ділення -8.6481 / -0.8086]
  = 11 ітерацій                        [округлення до більшого цілого ⌈10.69⌉]
```
Міграція завершується за ~215 секунд, проте протягом цього часу гостьовий сервіс функціонує з продуктивністю 35% від номінальної.

---

### Сценарій 3: Застосування Post-Copy для важкого навантаження

При використанні Post-Copy на тому самому навантаженні `D = 1400 МБ/с`:
1. **Час простою:**
```
T_down_post = (S_dev + V_min) / B = (32 + 4) / 1100 = 0.0327 с = 32.7 мілісекунд
```
2. **Повний час передачі:**
```
T_total_post ≈ (131072 / 1100) + 0.033 + (N_faults · RTT) ≈ 119.16 с + 3.2 с ≈ 122.4 секунди
```
3. **Обсяг переданого трафіку:**
```
V_total_post = 131072 + 32 = 131104 МБ = 128.03 ГБ  (η = 1.00 ×)
```

Математичний аналіз доводить: для спокійних робочих навантажень (`ρ < 0.5`) ітеративне Pre-Copy є абсолютно безпечним та ефективним. Проте для інтенсивних операцій запису (`ρ ≥ 0.8`) безальтернативно вигіднішим стає перехід до Post-Copy або використання паралельних потоків Multifd, які усувають надлишковий трафік та гарантують детермінований час простою незалежно від поведінки гостьової програми.
