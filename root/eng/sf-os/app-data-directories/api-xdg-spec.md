# 📋 Специфікація змінних оточення XDG Base Directory: правила обчислення, права та дефолти

Цей нормативний довідник містить повний контракт специфікації XDG Base Directory Specification (редакція 0.8 від організації Freedesktop.org), алгоритми каскадної резолюції шляхів, вимоги до прав доступу VFS, правила ізоляції рантайму, специфікацію суміжних стандартів (XDG User Dirs, Desktop Entries, Mime Apps) та стандарт маркування каталогів кешу `CACHEDIR.TAG`. Довідник призначений для розробників системного та прикладного програмного забезпечення на платформах Linux, FreeBSD, OpenBSD та інших Unix-подібних операційних системах.

## Призначення та базові принципи специфікації

Специфікація стандартизує розміщення файлів, які створюються або читаються користувацькими програмами. Мета стандарту полягає у звільненні домашнього каталогу користувача `$HOME` від хаотичного накопичення прихованих dot-файлів та наданні операційній системі можливості автоматизовано керувати резервним копіюванням, очищенням дискового простору та перенесенням конфігурацій між комп'ютерами.

Усі шляхи, визначені специфікацією, поділяються на дві групи:
1. **Каталоги рівня користувача (User-Level Directories)** — визначають єдине базове місце для запису та читання приватних файлів поточного користувача.
2. **Системні каскади пошуку (System Search Directories)** — визначають упорядковані списки каталогів для пошуку файлів за замовчуванням, встановлених адміністратором системи або пакунковим менеджером дистрибутива.

## Змінні користувацького рівня (User Base Directories)

Кожна змінна цієї групи вказує на кореневий каталог певної семантичної категорії. Застосунок не повинен зберігати власні файли безпосередньо в корені цього каталогу — замість цього програма створює в ньому власний підкаталог, ім'я якого відповідає назві застосунку (наприклад, `$XDG_CONFIG_HOME/myapp/`).

| Змінна оточення | Значення за замовчуванням | Режим доступу (mode) | Тип носія | Семантичне призначення |
|---|---|---|---|---|
| `$XDG_CONFIG_HOME` | `$HOME/.config` | `0700` або `0755` | Енергонезалежний диск | Конфігураційні файли користувача (JSON, TOML, YAML, INI). Малий розмір, підлягає зберіганню в git (dotfiles) та пріоритетному резервному копіюванню. |
| `$XDG_DATA_HOME` | `$HOME/.local/share` | `0700` або `0755` | Енергонезалежний диск | Довготривалі робочі дані програми (локальні бази даних SQLite, збереження ігор, завантажені шрифти, словники, файли `.desktop`). |
| `$XDG_STATE_HOME` | `$HOME/.local/state` | `0700` | Енергонезалежний диск | Стан попередніх сеансів: історія командного рядка (history), логи, збережені розміри й координати вікон, відкриті вкладки. Не додається в git. |
| `$XDG_CACHE_HOME` | `$HOME/.cache` | `0700` або `0755` | Енергонезалежний диск | Тимчасовий кеш (скомпільовані шейдери, мініатюри зображень, збережені HTTP-відповіді). Може бути видалений системою в будь-який момент. |
| `$XDG_RUNTIME_DIR` | Визначається системою (типово `/run/user/$UID`) | **Строго 0700** | ОЗП (`tmpfs`) | Короткоживучі об'єкти міжпроцесної взаємодії (UNIX-сокети, FIFO, файли блокувань PID). Знищується при виході користувача. |

### Правила обчислення шляхів (Resolution Rules)

Програма повинна обчислювати фактичний шлях до каталогу категорії за таким строгим алгоритмом:

1. **Опитування оточення:** Здійснюється запит системної функції `getenv("XDG_<CAT>_HOME")`.
2. **Перевірка абсолютності шляху:**
   * Якщо змінна встановлена і її перший символ дорівнює `/` (абсолютний шлях), застосунок використовує це значення без змін.
   * Якщо змінна не встановлена, містить порожній рядок або містить **відносний шлях** (наприклад, `relative/path`), специфікація вимагає повністю проігнорувати це значення і застосувати стандартний резервний шлях від `$HOME`.
3. **Отримання домашнього каталогу користувача:**
   * Здійснюється запит `getenv("HOME")`.
   * Якщо змінна `$HOME` відсутня або порожня, застосунок зобов'язаний звернутися до системної бази користувачів через виклик `getpwuid(getuid())` та отримати поле `pw_dir`. Якщо і цей виклик повертає помилку, робота з файловою системою переривається з кодом `ENOENT`.
4. **Конкатенація шляху:** До отриманого кореня додається відповідний системний суфікс (`.config`, `.local/share`, `.local/state`, `.cache`) та ім'я підкаталогу програми.

## Системні каскади пошуку (System Search Cascades)

Системні змінні містять переліки каталогів, розділені символом двокрапки `:`, призначені для пошуку статичних шаблонів налаштувань та загальнодоступних ресурсів.

| Змінна оточення | Значення за замовчуванням | Призначення |
|---|---|---|
| `$XDG_CONFIG_DIRS` | `/etc/xdg` | Список системних каталогів із глобальними налаштуваннями за замовчуванням, які адміністратор встановлює для всієї машини. |
| `$XDG_DATA_DIRS` | `/usr/local/share/:/usr/share/` | Список системних каталогів із загальносистемними статичними даними (шрифти, іконки, теми, локалізації, схеми XML). |

### Алгоритм каскадного опитування файлів

Коли програма завантажує ресурс (наприклад, конфігураційний файл `settings.json`), вона виконує послідовний обхід у такому порядку:

```
1. Локальний каталог користувача:
   $XDG_CONFIG_HOME/myapp/settings.json (або $HOME/.config/myapp/settings.json)
2. Системні каталоги зі списку $XDG_CONFIG_DIRS (або /etc/xdg):
   /etc/xdg/myapp/settings.json
```

Залежно від архітектури застосунку застосовується одна з двох стратегій:
* **Стратегія першого знайденого (First-match wins):** Застосунок відкриває перший файл, який вдалося успішно знайти на диску.
* **Стратегія каскадного злиття (Hierarchical merge):** Застосунок спочатку завантажує базовий системний файл із `/etc/xdg/myapp/settings.json`, а потім накладає поверх нього персональні зміни з `$HOME/.config/myapp/settings.json`.

## Нормативні вимоги до каталогу `$XDG_RUNTIME_DIR`

Оскільки каталог часу виконання призначений для сокетів та комунікаційних каналів, до нього висуваються найжорсткіші критерії безпеки:

1. **Власність процесу:** Каталог **зобов'язаний** належати користувачеві, чий процес виконує операції запису (`stat.st_uid == getuid()`).
2. **Ізоляція прав доступу:** Каталог **повинен мати режим доступу строго 0700** (`S_IRWXU`). Наявність будь-яких бітів доступу для групи (`group`) або сторонніх користувачів (`others`) є грубим порушенням безпеки. Якщо застосунок виявляє некоректні права, він повинен відмовитися від створення сокетів у цьому місці.
3. **Ефемерність носія:** Каталог має бути розміщений на файловій системі в оперативній пам'яті (`tmpfs`). Запис тимчасових сокетів на фізичний SSD чи HDD заборонений для запобігання деградації флеш-пам'яті та витоку ключів після вимкнення живлення.
4. **Обробка відсутності змінної:** Якщо змінна `$XDG_RUNTIME_DIR` не встановлена системою (наприклад, при вході через нестандартний cron або SSH без PAM-модуля `pam_systemd`), програма **не має права** самовільно створювати сокети в загальному каталозі `/tmp`. Програма зобов'язана повідомити користувача про відсутність належного середовища або створити захищений підкаталог із правами `0700` у межах `$XDG_DATA_HOME`.

## Специфікація маркування каталогів кешу (`CACHEDIR.TAG`)

Для запобігання марнотратному копіюванню тимчасових файлів інструментами резервного копіювання (Borg, Restic, Tar, Duplicity) використовується стандарт `CACHEDIR.TAG`.

### Формат файлу маркування

У корені будь-якого підкаталогу кешу (наприклад, `$XDG_CACHE_HOME/myapp/`) створюється файл із точним ім'ям `CACHEDIR.TAG`. Перші 43 байти файлу повинні містити незмінний фіксований заголовок:

```
Signature: 8a477f597d28d172789f06886806bc55
```

Повний рекомендований вміст файлу має такий вигляд:

```
Signature: 8a477f597d28d172789f06886806bc55
# This file is a cache directory tag created by MyApp.
# For information about cache directory tags, see:
# https://bford.info/cachedir/
```

### Поведінка утиліт резервного копіювання

Коли утиліта архівації обходить файлову систему і зустрічає каталог, що містить файл `CACHEDIR.TAG` із валідною сигнатурою:
* Утиліта автоматично виключає весь вміст цього каталогу зі створюваного архіву.
* Сам каталог і файл `CACHEDIR.TAG` можуть бути збережені у знімку як порожня структура, щоб після відновлення застосунок міг відтворити каталог кешу.

## Зв'язок із розширеннями: XDG User Dirs та системні ресурси

Окрім базової специфікації розміщення службових файлів застосунків, екосистема Freedesktop.org визначає правила розміщення користувацьких документів та інтеграційних ресурсів графічного середовища:

### 1. Каталоги користувацьких документів (XDG User Directories)

На відміну від `$XDG_DATA_HOME` (де зберігаються технічні файли програми, не призначені для прямого перегляду користувачем у файловому менеджері), документи користувача організовуються за специфікацією `xdg-user-dirs`. Налаштування зчитуються з файлу `$XDG_CONFIG_HOME/user-dirs.dirs`:

* `XDG_DESKTOP_DIR` — `$HOME/Desktop` (Стільниця)
* `XDG_DOCUMENTS_DIR` — `$HOME/Documents` (Документи)
* `XDG_DOWNLOAD_DIR` — `$HOME/Downloads` (Завантаження)
* `XDG_MUSIC_DIR` — `$HOME/Music` (Музика)
* `XDG_PICTURES_DIR` — `$HOME/Pictures` (Зображення)
* `XDG_VIDEOS_DIR` — `$HOME/Videos` (Відео)
* `XDG_TEMPLATES_DIR` — `$HOME/Templates` (Шаблони)
* `XDG_PUBLICSHARE_DIR` — `$HOME/Public` (Спільні файли)

Застосунок ніколи не повинен створювати приховані технічні бази чи кеші всередині `XDG_DOCUMENTS_DIR` — цей каталог призначений виключно для файлів, які користувач явно створив та зберігає вручну.

### 2. Інтеграція з графічним середовищем (Desktop & Mime)

* **Файли запуску (`.desktop`):** користувацькі ярлики зберігаються у `$XDG_DATA_HOME/applications/`, а системні — у `$XDG_DATA_DIRS/applications/` (типово `/usr/share/applications/`).
* **Асоціації типів файлів (`mimeapps.list`):** користувацькі прив'язки програм до MIME-типів зберігаються у `$XDG_CONFIG_HOME/mimeapps.list`.
* **Піктограми та теми оформлення:** користувацькі теми встановлюються у `$XDG_DATA_HOME/icons/`, системні — у `$XDG_DATA_DIRS/icons/`.

## Матриця помилок VFS при роботі з каталогами XDG

| Системний виклик | Код помилки | Причина у контексті XDG | Спосіб обробки в застосунку |
|---|---|---|---|
| `mkdir()` | `EEXIST` | Каталог або файл із таким ім'ям уже існує. | Перевірити через `stat()`, чи є існуючий об'єкт каталогом. Якщо це каталог — продовжити роботу; якщо файл — повернути помилку конфігурації. |
| `mkdir()` | `ENOENT` | Проміжний батьківський каталог у дереві шляху не існує. | Виконати рекурсивне створення всіх батьківських каталогів (аналог `mkdir -p`). |
| `open()` / `mkdir()` | `EACCES` | Відсутні права на запис (`+w`) або пошук (`+x`) у батьківському каталозі. | Повідомити користувача про неможливість доступу до каталогу та вказати проблемний шлях. |
| `mkstemp()` | `EROFS` | Файлова система змонтована в режимі лише для читання (Read-Only). | Перевести програму в режим читання без спроб збереження локальних налаштувань. |
| `rename()` | `EXDEV` | Спроба перейменувати файл між різними точками монтування. | Виникає, якщо тимчасовий файл створено в `/tmp`, а кінцевий — у `$XDG_CONFIG_HOME`. Виправлення: створювати тимчасовий файл у тому самому каталозі призначення. |
| `rename()` | `EBUSY` | Цільовий файл або каталог заблокований іншим процесом ядра (наприклад, є точкою монтування). | Повторити спробу із затримкою або повернути статус тимчасової недоступності. |
| `open(O_DIRECTORY)` | `ENOTDIR` | Компонент шляху існує, але є звичайним файлом, а не каталогом. | Повідомити про пошкодження структури каталогів застосунку. |
