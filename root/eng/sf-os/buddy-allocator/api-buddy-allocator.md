# 📋 Специфікація програмного інтерфейсу Buddy Allocator API

Цей документ визначає повну специфікацію, формальний контракт, структури даних, константи конфігурації, перед- та післяумови, інваріанти, правила потокобезпечності та обробки помилок для бібліотеки алокатора двійкових близнюків (`buddy_allocator`). Довідник призначений для розробників системного програмного забезпечення, драйверів пристроїв, операційних систем реального часу (RTOS) та високонавантажених рушіїв баз даних.

## 1. Архітектурні засади та модель пам'яті

Алокатор двійкових близнюків керує неперервним діапазоном пам'яті, базовий розмір якого строго дорівнює степеню двійки `2ᴹ` байтів. Уся керована область розглядається як єдиний пул, розбитий на кванти фіксованого мінімального розміру `2ᵏᵐⁱⁿ`.

Бібліотека забезпечує детерміноване виділення та звільнення пам'яті з гарантованою верхньою межею часової складності `O(log N)` у найгіршому випадку та `O(1)` у стаціонарному режимі. Усі повернені адреси задовольняють вимогу природного вирівнювання: адреса блоку порядку `k` завжди кратна `2ᵏ`.

### Життєвий цикл алокатора (State Machine)

Контекст алокатора проходить через чітко визначені стани:
1. **`UNINITIALIZED` (Неініціалізований):** Структура `buddy_allocator_t` містить нульові або довільні значення. Виклик будь-яких функцій, крім `buddy_init`, заборонений і повертає помилку `BUDDY_ERR_INVALID_PARAM`.
2. **`READY` (Готовий до роботи):** Буфер пам'яті зв'язано з контекстом, створено початковий вільний блок максимального порядку, масив дескрипторів очищено. Алокатор готовий приймати запити на виділення.
3. **`ACTIVE` (Експлуатація):** Алокатор обслуговує запити `buddy_alloc` та `buddy_free`. Частина простору виділена користувачам, частина перебуває у списках вільних блоків відповідних порядків.
4. **`DESTROYED` (Знищений):** Усі структури скинуто в початковий стан, зв'язок із сирим буфером розірвано.

## 2. Константи конфігурації та типи даних

### Системні константи

| Константа | Тип | Типове значення | Призначення та обмеження |
| :--- | :--- | :--- | :--- |
| `BUDDY_MIN_ORDER` | `uint8_t` | `4` (16 байтів) | Мінімальний порядок блоку. Не може бути меншим за `sizeof(list_node_t)` (два покажчики 64-бітної архітектури). |
| `BUDDY_MAX_ORDER` | `uint8_t` | `20` (1 МБ) або `16` (64 КБ) | Максимальний порядок блоку, що визначає граничну місткість пулу. Обмежений розрядністю адресного простору (`≤ 63`). |
| `BUDDY_NUM_ORDERS` | `size_t` | `BUDDY_MAX_ORDER - BUDDY_MIN_ORDER + 1` | Кількість окремих рівнів двозв'язних списків у масиві `free_lists`. |
| `BUDDY_ALIGNMENT_DEFAULT` | `size_t` | `16` байтів | Базове вирівнювання для мінімального виділення. |

### Коди повернення та помилок (`buddy_status_t`)

Кожна операція бібліотеки, що модифікує стан пулу або перевіряє коректність покажчиків, повертає статус із фіксованого набору переліку `buddy_status_t`.

| Статус | Числове значення | Семантичний опис та умови виникнення |
| :--- | :--- | :--- |
| `BUDDY_OK` | `0` | Операцію виконано успішно. Усі інваріанти збережено. |
| `BUDDY_ERR_INVALID_PARAM` | `-1` | Передано нульовий покажчик контексту (`NULL`), некоректний порядок або нульовий розмір пулу. |
| `BUDDY_ERR_OUT_OF_MEMORY` | `-2` | У пулі відсутній неперервний блок потрібного порядку. Пам'ять вичерпана або надмірно фрагментована. |
| `BUDDY_ERR_OUT_OF_BOUNDS` | `-3` | Передана адреса лежить за межами керованого діапазону `[pool_base, pool_base + pool_size)`. |
| `BUDDY_ERR_NOT_ALIGNED` | `-4` | Базова адреса наданого буфера або запитаний блок не вирівняні на обов'язковий ступінь двійки. |
| `BUDDY_ERR_DOUBLE_FREE` | `-5` | Спроба звільнити блок, дескриптор якого вже позначений як вільний (захист від пошкодження пам'яті). |
| `BUDDY_ERR_CORRUPTED_METADATA`| `-6` | Виявлено порушення цілісності списку вільних блоків або суперечливі порядки близнюків. |

## 3. Структури стану

### Вузол списку вільних блоків (`list_node_t`)

Розміщується безпосередньо всередині пам'яті вільного блоку (інтрузивна навігація). Не займає додаткового місця у виділеному стані.

```c
typedef struct list_node {
    struct list_node *prev;  /* Покажчик на попередній вільний блок того самого порядку */
    struct list_node *next;  /* Покажчик на наступний вільний блок того самого порядку */
} list_node_t;
```

### Дескриптор кванта пам'яті (`block_tag_t`)

Зберігається у зовнішньому масиві метаданих. Кожен елемент описує стан одного неподільного кванта розміром `2ᵏᵐⁱⁿ`.

```c
typedef struct {
    uint8_t order;    /* Поточний логарифмічний порядок блоку, якому належить квант */
    uint8_t is_free;  /* Прапорець стану: 1 = у вільному списку, 0 = виділено користувачеві */
} block_tag_t;
```

### Головний контекст алокатора (`buddy_allocator_t`)

## 4. Детальна специфікація функцій C API

### `buddy_init` — Ініціалізація екземпляра алокатора

Зв'язує структуру керування з фізичним буфером пам'яті та масивом дескрипторів.

```c
buddy_status_t buddy_init(
    buddy_allocator_t *alloc,
    void              *raw_pool,
    size_t             pool_size,
    block_tag_t       *tag_buffer,
    size_t             tag_buffer_size,
    uint8_t            min_order,
    uint8_t            max_order
);
```

#### Параметри:
- `alloc`: Покажчик на екземпляр `buddy_allocator_t`. Не може бути `NULL`.
- `raw_pool`: Покажчик на неперервний буфер сирої пам'яті. Адреса зобов'язана бути кратною `1 << min_order`.
- `pool_size`: Фактичний розмір буфера в байтах. Повинен строго дорівнювати `1 << max_order`.
- `tag_buffer`: Покажчик на масив дескрипторів `block_tag_t`.
- `tag_buffer_size`: Кількість елементів у масиві дескрипторів. Повинна бути `≥ pool_size >> min_order`.
- `min_order`: Логарифмічний порядок найменшого кванта (типово 4 або 12).
- `max_order`: Логарифмічний порядок найбільшого блоку (типово 16 або 30).

#### Передмови (Preconditions):
- Усі покажчики `alloc`, `raw_pool`, `tag_buffer` є дійсними та ненульовими.
- `min_order < max_order` та `min_order ≥ 4`.
- `raw_pool` вказує на виділену пам'ять розміром щонайменше `1 << max_order` байтів.

#### Післяумови (Postconditions):
- Усі списки `free_lists` ініціалізовані як порожні циклічні списки зі сторожем.
- Список максимального порядку `free_lists[max_order - min_order]` містить рівно один блок, що охоплює весь пул.
- Перший елемент масиву `tag_buffer[0]` має `order = max_order` та `is_free = 1`.
- Лічильники `allocated_bytes` та `allocation_count` скинуті в нуль.

### `buddy_alloc` — Виділення неперервного блоку пам'яті

Знаходить або формує шляхом розщеплення блок мінімального степеня двійки, достатнього для розміщення запитаної кількості байтів.

```c
void *buddy_alloc(
    buddy_allocator_t *alloc,
    size_t             bytes
);
```

#### Параметри:
- `alloc`: Чинний, раніше успішно ініціалізований контекст алокатора.
- `bytes`: Необхідна кількість байтів (корисне навантаження).

#### Повернене значення:
- **Успіх:** Дійсний ненульовий покажчик на початок виділеного блоку. Повернена адреса гарантовано вирівняна на `2^target_order`.
- **Помилка:** `NULL`, якщо:
  - `alloc == NULL` або `bytes == 0`;
  - `bytes > (1 << alloc->max_order)`;
  - У пулі немає вільних блоків достатнього розміру, і розщеплення старших блоків неможливе.

#### Алгоритмічні гарантії:
- Часова складність: `O(max_order - min_order)` у найгіршому випадку (коли відбувається розщеплення від максимального порядку); `O(1)` у разі наявності готового вільного блоку в списку відповідного порядку.
- Жодних блокувань у базовому варіанті. Пам'ять усередині виділеного блоку не очищується (містить залишковий вміст).

---

### `buddy_free` — Звільнення блоку та каскадне злиття

Повертає виділений блок у пул, визначає адресу симетричного близнюка через операцію XOR і рекурсивно об'єднує вільні напарники у блоки вищих порядків.

```c
buddy_status_t buddy_free(
    buddy_allocator_t *alloc,
    void              *ptr
);
```

#### Параметри:
- `alloc`: Чинний контекст алокатора.
- `ptr`: Покажчик на початок блоку, раніше повернений функцією `buddy_alloc`.

#### Повернені статуси:
- `BUDDY_OK`: Блок успішно повернуто та об'єднано з доступними близнюками.
- `BUDDY_ERR_INVALID_PARAM`: Передано `alloc == NULL` або `ptr == NULL`.
- `BUDDY_ERR_OUT_OF_BOUNDS`: Покажчик `ptr` лежить поза діапазоном керованого пулу.
- `BUDDY_ERR_NOT_ALIGNED`: Зміщення `ptr` відносно початку пулу не кратне `1 << min_order`.
- `BUDDY_ERR_DOUBLE_FREE`: Дескриптор блоку вже має прапорець `is_free == 1`.

#### Правило злиття:
Злиття з напарником `buddy_offset = block_offset ^ (1 << order)` відбувається виключно тоді, коли дескриптор близнюка задовольняє дві умови одночасно:
1. `tags[buddy_tag_idx].is_free == 1`;
2. `tags[buddy_tag_idx].order == order`.

## 6. Багатопотоковість та синхронізація

Базова реалізація C API є **потоково-небезпечною** (Non-thread-safe) заради досягнення максимальної швидкодії у вбудованих системах та середовищах із монопольним володінням ядром.

### Рекомендовані стратегії синхронізації:
1. **Глобальний спінлок (Spinlock / Mutex):** Контекст `buddy_allocator_t` захищається одним м'ютексом на рівні зони пам'яті. Оскільки час виконання викликів обмежений логарифмом (`< 20` тактів процесора на перемикання бітів), час утримання блокування мінімальний.
2. **Локальні пули процесорів (Per-CPU Caches):** Кожне процесорне ядро утримує власний невеликий локальний кеш сторінок (як у підсистемі PCP ядра Linux). До глобального алокатора звертаються лише під час вичерпання або переповнення локального списку.
