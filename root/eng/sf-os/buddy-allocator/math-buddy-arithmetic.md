# 🧮 Математичний апарат двійкових близнюків та аналіз фрагментації

Алокатор двійкових близнюків базується на властивостях алгебри логіки над векторними просторами `GF(2)ⁿ`, геометрії повних двійкових дерев та ймовірнісних моделях внутрішньої і зовнішньої фрагментації пам'яті. У цьому розділі наведено строгі математичні доведення адресної інволюції через оператор XOR, виведення очікуваних втрат простору при різних розподілах запитів та аналіз часової складності операцій розщеплення і злиття.

## 1. Алгебраїчні властивості адресації близнюків

Розглянемо адресний простір загального розміру `M = 2ᴺ` байтів (або базових сторінок). Кожна адреса `A` представляється у вигляді `N`-бітного двійкового вектора `A ∈ {0, 1}ᴺ`:

```
A = ∑_{i=0}^{N-1} aᵢ · 2ⁱ,   де aᵢ ∈ {0, 1}
```

Нехай порядок блоку дорівнює `k`, де `0 ≤ k ≤ N`. За означенням двійкової системи близнюків, блок порядку `k` має розмір `Sₖ = 2ᵏ` і задовольняє **інваріант природного вирівнювання**: початкова адреса блоку кратна його розміру.

```
A mod 2ᵏ = 0  ⇔  a₀ = a₁ = ... = a_{k-1} = 0
```

### Доведення теореми про взаємну адресу близнюка

**Теорема 1 (про адресу близнюка).** Для довільного вирівняного блоку порядку `k` з базовою адресою `A`, адреса його парного близнюка `B` визначається побітовою операцією виключного АБО (`XOR`, позначається `⊕`):

```
B = A ⊕ 2ᵏ
```

*Доведення.*
Блок порядку `k` виникає внаслідок розщеплення спільного батьківського блоку порядку `k + 1`. Нехай батьківський блок має початкову адресу `P`. За інваріантом вирівнювання для порядку `k + 1`, молодші `k + 1` бітів адреси `P` дорівнюють нулю:

```
P mod 2^{k+1} = 0  ⇔  p₀ = p₁ = ... = p_{k-1} = pₖ = 0
```

Розщеплення блоку `P` на дві рівні половини розміром `2ᵏ` утворює рівно два дочірні блоки:
1. **Лівий близнюк (`Left`):** займає діапазон адрес `[P, P + 2ᵏ − 1]`. Його початкова адреса `A_L = P`. У двійковому записі `k`-й біт адреси `A_L` дорівнює 0 (`a_L,ₖ = 0`).
2. **Правий близнюк (`Right`):** займає діапазон адрес `[P + 2ᵏ, P + 2^{k+1} − 1]`. Його початкова адреса `A_R = P + 2ᵏ`. У двійковому записі `k`-й біт адреси `A_R` дорівнює 1 (`a_R,ₖ = 1`).

Усі старші біти `i > k` та всі молодші біти `i < k` в адресах `A_L` та `A_R` повністю збігаються. Єдина різниця між ними полягає у значенні `k`-го біта.

Розглянемо дію оператора `⊕ 2ᵏ`:
Число `2ᵏ` має одиницю лише в `k`-й позиції (`1 ≪ k`), а всі інші його розряди дорівнюють 0.

Для лівого близнюка `A_L`:
```
A_L ⊕ 2ᵏ
= (P) ⊕ 2ᵏ                 [оскільки a_L,ₖ = 0]
= P + 2ᵏ                   [додавання без переносу в k-му біті]
= A_R                      [отримали адресу правого близнюка]
```

Для правого близнюка `A_R`:
```
A_R ⊕ 2ᵏ
= (P + 2ᵏ) ⊕ 2ᵏ            [оскільки a_R,ₖ = 1]
= P + (2ᵏ ⊕ 2ᵏ)            [асоціативність та побітова незалежність]
= P + 0                    [властивість x ⊕ x = 0]
= P = A_L                  [отримали адресу лівого близнюка]
```

Таким чином, формула `B = A ⊕ 2ᵏ` є універсальною для обох близнюків: для лівого вона повертає правого, а для правого — лівого. Твердження доведено. ∎

### Доведення властивості інволюції

Операція пошуку близнюка є математичною **інволюцією** (самооберненим відображенням `f(f(x)) = x`).

```
f(f(A))
= (A ⊕ 2ᵏ) ⊕ 2ᵏ            [підстановка означення функції]
= A ⊕ (2ᵏ ⊕ 2ᵏ)            [асоціативність операції XOR]
= A ⊕ 0                    [нейтральний елемент відносно XOR]
= A                        [тотожне відображення]
```

Це гарантує відсутність циклів і однозначну оборотність розбиття на кожному рівні ієрархії.

### Обчислення адреси спільного батька при злитті

Коли обидва близнюки порядку `k` вільні, вони об'єднуються у блок порядку `k + 1`. Базова адреса об'єднаного блоку `P` мусить дорівнювати початку лівого близнюка.

**Теорема 2.** Для довільного блоку з адресою `A` порядку `k` адреса його батьківського блоку порядку `k + 1` обчислюється як:

```
P = A & ~(2ᵏ) = min(A, A ⊕ 2ᵏ)
```

*Доведення.*
Оператор `~(2ᵏ)` формує бітову маску, у якій усі розряди дорівнюють 1, крім `k`-го біта, що дорівнює 0.
Побітове множення `A & ~(2ᵏ)` скидає (обнуляє) `k`-й біт адреси `A`, залишаючи всі інші біти незмінними.
- Якщо `A` — лівий близнюк (`aₖ = 0`), то `aₖ & 0 = 0`, і `P = A`.
- Якщо `A` — правий близнюк (`aₖ = 1`), то `aₖ & 0 = 0`, і `P = A − 2ᵏ = A_L`.

В обох випадках `P` отримує значення `A_L`, яке задовольняє умову вирівнювання `P mod 2^{k+1} = 0`. ∎

## 2. Аналіз внутрішньої фрагментації (Internal Fragmentation)

Внутрішня фрагментація виникає внаслідок того, що алокатор виділяє блок розміру `2ᵏ`, де `k = ⌈log₂ s⌉`, для запиту користувача розміром `s` байтів. Невикористаний надлишок простору дорівнює:

```
W(s) = 2^{⌈log₂ s⌉} − s
```

Відносна внутрішня втрата пам'яті для запиту `s` визначається як:

```
L(s) = W(s) / 2^{⌈log₂ s⌉} = 1 − s / 2^{⌈log₂ s⌉}
```

### Найгірший випадок (Worst-case Bound)

Нехай запит на виділення пам'яті має розмір `s = 2ᵏ + 1` байт (на 1 байт більше степеня двійки). Алокатор змушений виділити блок наступного порядку `k + 1` розміром `2^{k+1}`.

Втрачена пам'ять:
```
W_max
= 2^{k+1} − (2ᵏ + 1)       [підстановка розміру блоку та запиту]
= 2 · 2ᵏ − 2ᵏ − 1          [розкриття множника 2^{k+1}]
= 2ᵏ − 1                   [спрощення різниці]
```

Відносна втрата пам'яті при зростанні `k`:
```
lim_{k → ∞} (2ᵏ − 1) / 2^{k+1}
= lim_{k → ∞} (1/2 − 1/2^{k+1})  [почленний поділ]
= 1/2 = 50%                      [граничне значення]
```

Отже, максимальна теоретична внутрішня фрагментація двійкового алокатора прямує до 50%.

### Математичне сподівання при рівномірному розподілі запитів

Припустимо, що розміри запитів `s` розподілені неперервно та рівномірно на інтервалі `[2ᵏ, 2^{k+1}]` зі щільністю ймовірності `p(s) = 1 / 2ᵏ`.

Обчислимо математичне сподівання виділеної пам'яті `E[S]` та корисного розміру запиту `E[s]`:
Для всіх запитів на цьому інтервалі виділяється блок фіксованого розміру `2^{k+1}`.

Середній розмір запиту:
```
E[s]
= ∫_{2ᵏ}^{2^{k+1}} s · p(s) ds
= (1 / 2ᵏ) · [s² / 2]_{2ᵏ}^{2^{k+1}}
= (1 / 2^{k+1}) · ((2^{k+1})² − (2ᵏ)²)
= (1 / 2^{k+1}) · (4 · 2^{2k} − 2^{2k})
= (1 / 2^{k+1}) · (3 · 2^{2k})
= 3/4 · 2^{k+1}
```

Середня абсолютна внутрішня втрата пам'яті:
```
E[W]
= 2^{k+1} − E[s]           [різниця виділеного і середнього запиту]
= 2^{k+1} − 3/4 · 2^{k+1}  [підстановка E[s]]
= 1/4 · 2^{k+1}            [результат інтегрування]
```

Середня відносна внутрішня фрагментація при рівномірному розподілі:
```
E[L_uniform] = E[W] / 2^{k+1} = (1/4 · 2^{k+1}) / 2^{k+1} = 1/4 = 25%
```

### Математичне сподівання при логарифмічно-рівномірному розподілі

У реальних програмних системах (зокрема операційних системах та вебсерверах) розподіл розмірів виділень підпорядковується логарифмічно-рівномірному закону (розподіл Бенфорда / Зіпфа): малі об'єкти запитуються експоненційно частіше за великі, тобто щільність ймовірності обернено пропорційна розміру: `p(s) = c / s`.

Нормувальна константа `c` на інтервалі `[2ᵏ, 2^{k+1}]`:
```
∫_{2ᵏ}^{2^{k+1}} (c / s) ds = c · [ln s]_{2ᵏ}^{2^{k+1}} = c · ln(2^{k+1} / 2ᵏ) = c · ln 2 = 1
⇒ c = 1 / ln 2
```

Обчислимо середній розмір запиту:
```
E[s]
= ∫_{2ᵏ}^{2^{k+1}} s · (1 / (s · ln 2)) ds
= (1 / ln 2) · ∫_{2ᵏ}^{2^{k+1}} 1 ds
= (1 / ln 2) · (2^{k+1} − 2ᵏ)
= (2ᵏ) / ln 2
= 2^{k+1} / (2 · ln 2)
```

Середня відносна ефективність використання простору:
```
η = E[s] / 2^{k+1} = 1 / (2 · ln 2) ≈ 1 / (2 · 0.69315) ≈ 1 / 1.38629 ≈ 0.7213 (72.13%)
```

Середня внутрішня фрагментація при лог-рівномірному розподілі:
```
E[L_log] = 1 − η = 1 − 1 / (2 · ln 2) ≈ 1 − 0.7213 = 27.87%
```

Таким чином, для реалістичного логарифмічного профілю навантаження середня внутрішня фрагментація становить близько **28%**.

## 3. Комбінаторні межі та теорема про дерево близнюків

Структура розбиття простору розміром `2ᴺ` однозначно моделюється повним двійковим деревом висоти `N`.

**Властивість 1 (про кількість вузлів).**
- Кількість потенційних блоків порядку `k` у пулі розміру `2ᴺ` дорівнює `2^{N-k}`.
- Загальна кількість усіх можливих вузлів у дереві розбиття:
  `∑_{k=0}^{N} 2^{N-k} = 2^{N+1} − 1 = 2M − 1`.

**Властивість 2 (про інваріант покриття простору).**
У будь-який момент часу множина всіх виділених блоків `{Aᵢ}` та вільних блоків у списках `{Fⱼ}` утворює повний диз'юнктний поділ адресного простору `[0, 2ᴺ − 1]`:

```
∑_{i} 2^{k(Aᵢ)} + ∑_{j} 2^{k(Fⱼ)} = 2ᴺ
```

При цьому жодні два блоки в системі не перетинаються за адресами:
`∀ X, Y ∈ {Aᵢ} ∪ {Fⱼ}, X ≠ Y ⇒ [addr(X), addr(X) + 2^{k(X)} − 1] ∩ [addr(Y), addr(Y) + 2^{k(Y)} − 1] = ∅`.

## 4. Аналіз часової складності розщеплення та злиття

Позначимо мінімальний порядок блоку як `k_min`, максимальний — як `k_max = N`. Кількість рівнів у масиві `free_list` дорівнює `K = k_max − k_min + 1 = O(log(M / S_min))`.

### Теорема про складність виділення (Allocation Complexity)

**Теорема 3.** Операція `allocate(s)` виконується за час `O(K) = O(log M)` у найгіршому випадку і за `O(1)` у середньому випадку.

*Доведення.*
1. Обчислення цільового порядку: `k = max(k_min, ⌈log₂ s⌉)` — виконується за `O(1)` за допомогою апаратної інструкції пошуку старшого біта (`CLZ` / `BSR`).
2. Перевірка списку `free_list[k]`:
   - Якщо список непорожній, вилучення першого елемента двозв'язного списку коштує `O(1)`.
3. Якщо список порожній, виконується лінійний пошук першого непорожнього списку `free_list[j]` для `j > k`. Кількість перевірок не перевищує `K − 1`.
4. Знайдений блок порядку `j` розщеплюється `j − k` разів. На кожному кроці розщеплення правий близнюк додається в голову відповідного списку за `O(1)`.
5. Максимальна кількість розщеплень: `j − k ≤ k_max − k_min = K − 1`.

Загальна кількість кроків:
```
T_alloc ≤ 1 + K + (K − 1) = O(K) = O(log(M / S_min))
```

У стаціонарному режимі з високою ймовірністю список `free_list[k]` містить вільні блоки відповідного розміру після попередніх звільнень, що дає `O(1)` для переважної більшості запитів. ∎

### Теорема про складність звільнення (Free/Coalescing Complexity)

**Теорема 4.** Операція `free(ptr)` виконується щонайбільше за `O(K) = O(log M)` кроків.

*Доведення.*
1. Для вихідного блоку порядку `k` адреса близнюка `B = addr ⊕ 2ᵏ` обчислюється за `O(1)`.
2. Перевірка статусу близнюка (чи є він вільним і чи має порядок `k`) через дескриптор або бітову карту займає `O(1)`.
3. Якщо близнюк вільний, його вилучення зі списку `free_list[k]` за збереженими покажчиками `prev/next` займає `O(1)`.
4. Обчислюється адреса батьківського блоку `P = addr & ~(2ᵏ)` за `O(1)`, порядок збільшується `k ← k + 1`, і процедура повторюється.
5. Каскад злиття може піднятися від поточного порядку `k` щонайбільше до `k_max`.

Максимальна кількість ітерацій злиття:
```
N_merge = k_max − k ≤ K − 1
```

Оскільки на кожній ітерації виконується фіксована кількість бітових операцій та маніпуляцій з покажчиками (`O(1)`), загальний час злиття обмежений:

```
T_free ≤ c · (k_max − k) ≤ O(K) = O(log(M / S_min))
```

Жодна операція виділення чи звільнення не залежить від загальної кількості виділених у системі блоків `n`, а залежить виключно від логарифма фізичного розміру пам'яті `log M`. Це гарантує детермінований час виконання, критично необхідний для операційних систем реального часу (RTOS) та системних ядер. ∎
