# 📋 Системні виклики та структури керування правами пам'яті

Цей довідник містить вичерпну специфікацію системних викликів операційних систем POSIX/Linux та Windows NT, апаратних розширень процесора x86-64 та бінарних структур формату ELF, що забезпечують керування атрибутами доступу, захист сторінок від несанкціонованого виконання та реалізацію правила W^X.

---

## 1. Системний виклик mprotect() у Linux/POSIX

Системний виклик `mprotect()` є основним інтерфейсом ядра для динамічної зміни прав доступу до виділених сторінок віртуальної пам'яті процесу.

### Сигнатура функції

```c
#include <sys/mman.h>

int mprotect(void *addr, size_t len, int prot);
```

### Параметри та вимоги вирівнювання

- `addr`: Початкова віртуальна адреса діапазону пам'яті. Адреса **обов'язково** повинна бути вирівняна за межею апаратної сторінки архітектури (`addr % sysconf(_SC_PAGESIZE) == 0`). Передача невирівняної адреси призводить до миттєвого відхилення виклику ядром із кодом помилки `EINVAL`.
- `len`: Розмір діапазону в байтах. Якщо значення `len` не є кратним розміру сторінки, ядро автоматично округлює його вгору до кінця останньої зачепленої сторінки.
- `prot`: Бітова маска прав доступу, сформована через побітове «АБО» (`|`).

### Константи прапорців захисту (Protection Flags)

| Константа | Значення | Семантика в MMU та таблицях сторінок (PTE) |
|---|---|---|
| `PROT_NONE` | `0x0` | Доступ повністю заборонено. Сторінка позначається як недійсна або скидається біт присутності (`Present = 0`). Будь-яке звернення викликає виняток `#PF`. |
| `PROT_READ` | `0x1` | Дозволено читання. Встановлює біт `Present = 1`, біт `R/W = 0` (тільки читання), біт `NX = 1` (без виконання). |
| `PROT_WRITE` | `0x2` | Дозволено запис. Встановлює біт `R/W = 1` та біт `NX = 1`. |
| `PROT_EXEC` | `0x4` | Дозволено виконання інструкцій. Скидає біт заборони виконання (`NX = 0`) у відповідному записі PTE. |
| `PROT_GROWSDOWN` | `0x01000000` | Специфічний прапорець Linux: розширює зміну захисту вниз до початку суміжного сегмента стека. |
| `PROT_GROWSUP` | `0x02000000` | Специфічний прапорець Linux: застосовується для архітектур зі стеком, що зростає вгору. |

### Внутрішня механіка ядра Linux (mm/mprotect.c)

Під час виконання `mprotect()` ядро Linux здійснює послідовність низькорівневих операцій:
1. **Захоплення блокування:** Процес захоплює блокування `mmap_lock` структури пам'яті `mm_struct` у режимі запису.
2. **Розбиття областей VMA:** Якщо діапазон `[addr, addr + len)` покриває лише частину існуючої структури `vm_area_struct`, ядро розщеплює її на дві або три окремі структури за допомогою функції `vma_split()`.
3. **Модифікація таблиць сторінок:** Функція `change_protection()` виконує обхід 4-рівневого дерева сторінок (PGD -> P4D -> PUD -> PMD -> PTE) і оновлює біти доступу кожного запису через виклик `pte_modify()`.
4. **Скидання TLB:** Ядро викликає `flush_tlb_range()`, розсилаючи міжпроцесорні переривання (IPI) на всі активні процесорні ядра, щоб видалити застарілі трансляції з буферів асоціативної трансляції.

### Помилки та діагностика (errno)

- `EINVAL`: Невирівняна адреса `addr`, некоректна комбінація прапорців у `prot`, або `len == 0`.
- `ENOMEM`: Діапазон містить невідображені сторінки, або операція розщеплення VMA призводить до перевищення системного ліміту `vm.max_map_count`.
- `EACCES`: Спроба встановити `PROT_WRITE` для відображення файлу, відкритого виключно в режимі `O_RDONLY`.

## 2. Системний виклик mmap() для створення відображень

Системний виклик `mmap()` виділяє нові області пам'яті в адресному просторі процесу та задає їхні початкові атрибути безпеки.

```c
#include <sys/mman.h>

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
```

### Ключові прапорці створення відображень

- `MAP_ANONYMOUS` (або `MAP_ANON`): Створює анонімне відображення, не пов'язане з жодним файлом на диску. Пам'ять занулюється ядром. Використовується системними алокаторами (`malloc`, jemalloc) для виділення великих блоків купи.
- `MAP_PRIVATE`: Зміни в пам'яті є локальними для процесу (Copy-on-Write).
- `MAP_SHARED`: Зміни в пам'яті записуються в базовий об'єкт або файл і синхронізуються між різними процесами чи відображеннями (основа техніки Dual Mapping).

## 3. Аналоги у Windows API (VirtualAlloc / VirtualProtect)

В операційній системі Windows NT керування правами пам'яті здійснюється через спеціалізовані функції підсистеми Win32.

### Специфікація функцій

```c
#include <windows.h>

LPVOID VirtualAlloc(LPVOID lpAddress, SIZE_T dwSize, DWORD flAllocationType, DWORD flProtect);
BOOL VirtualProtect(LPVOID lpAddress, SIZE_T dwSize, DWORD flNewProtect, PDWORD lpflOldProtect);
```

### Константи захисту пам'яті Windows NT

- `PAGE_NOACCESS` (`0x01`): Повний аналог `PROT_NONE`. Будь-який доступ викликає апаратний виняток `EXCEPTION_ACCESS_VIOLATION` (`0xC0000005`).
- `PAGE_READONLY` (`0x02`): Доступ лише для читання (`PROT_READ`).
- `PAGE_READWRITE` (`0x04`): Доступ для читання та запису (`PROT_READ | PROT_WRITE`). Стандартний режим для стека та купи з увімкненим DEP.
- `PAGE_EXECUTE` (`0x10`): Тільки виконання без права читання/запису.
- `PAGE_EXECUTE_READ` (`0x20`): Тільки виконання та читання (`PROT_READ | PROT_EXEC`). Стандартний режим для секції `.text` бінарних файлів PE.
- `PAGE_EXECUTE_READWRITE` (`0x40`): Небезпечний режим `RWX`. Пряме порушення політики W^X. Сучасні політики безпеки Windows (Arbitrary Code Guard / ACG) блокують спроби встановлення цього прапорця.

## 4. Апаратні ключі захисту Intel MPK (Memory Protection Keys)

Технологія **Intel MPK** (Memory Protection Keys / PKEYs) надає механізм миттєвого перемикання прав пам'яті безпосередньо в просторі користувача без виконання системного виклику та без скидання TLB.

### Сигнатури системних викликів Linux

```c
#define _GNU_SOURCE
#include <sys/mman.h>

/* Виділення апаратного ключа захисту (повертає числовий індекс 1..15) */
int pkey_alloc(unsigned int flags, unsigned int access_rights);

/* Звільнення раніше виділеного ключа */
int pkey_free(int pkey);

/* Прив'язка діапазону сторінок до ключа pkey */
int pkey_mprotect(void *addr, size_t len, int prot, int pkey);
```

### Семантика регістру PKRU

Процесор містить спеціальний 32-розрядний регістр `PKRU` (Protection Key Rights for User pages). Для кожного з 16 можливих ключів виділено по 2 біти:
- Біт `2 * k`: **AD** (*Access Disable*) — забороняє читання та запис сторінок із ключем `k`.
- Біт `2 * k + 1`: **WD** (*Write Disable*) — забороняє будь-яку модифікацію сторінок із ключем `k`.

Зміна значень регістру виконується непривілейованою машинною інструкцією `WRPKRU`, яка виконується всього за 10–20 процесорних тактів (проти 2000–5000 тактів на виклик `mprotect()`).

## 5. Структури формату ELF та прапорці безпеки

Завантажувач ядра Linux (`fs/binfmt_elf.c`) визначає параметри захисту сегментів процесу під час парсингу таблиці заголовків програми (`Program Header Table`).

### Структура заголовка сегмента (Elf64_Phdr)

```c
#include <elf.h>

typedef struct {
    uint32_t   p_type;   /* Тип сегмента */
    uint32_t   p_flags;  /* Прапорці прав доступу (PF_R, PF_W, PF_X) */
    Elf64_Off  p_offset; /* Зміщення у файлі */
    Elf64_Addr p_vaddr;  /* Віртуальна адреса завантаження */
    Elf64_Addr p_paddr;  /* Фізична адреса */
    uint64_t   p_filesz; /* Розмір даних у файлі */
    uint64_t   p_memsz;  /* Розмір сегмента в RAM */
    uint64_t   p_align;  /* Вирівнювання (4096 байтів) */
} Elf64_Phdr;
```

### Типи сегментів безпеки (p_type)

- `PT_LOAD` (`0x1`): Сегмент завантажується в пам'ять із правами, заданими в полі `p_flags`.
- `PT_GNU_STACK` (`0x6474e551`): Спеціальний заголовок GNU, що інструктує ядро щодо режиму роботи стека процесу:
  - `p_flags == PF_R | PF_W` (`0x6`): Стек створюється з правами `PROT_READ | PROT_WRITE` (біт NX активний).
  - `p_flags == PF_R | PF_W | PF_X` (`0x7`): Стек створюється з правами `PROT_READ | PROT_WRITE | PROT_EXEC` (небезпечний режим сумісності).
- `PT_GNU_RELRO` (`0x6474e552`): Позначає сегменти бінарника (зокрема таблицю глобальних зміщень `.got`), які після ініціалізації динамічним лінкером перемикаються в режим `PROT_READ`.

## 6. Простеження прав пам'яті через інтерфейс /proc/[pid]/maps

Підсистема procfs ядра Linux надає повну карту пам'яті активного процесу через віртуальний файл `/proc/[pid]/maps`.

### Формат рядка карти пам'яті

```
address           perms offset  dev   inode       pathname
00400000-00401000 r-xp  000000  fd:01 123456      /usr/bin/app
00600000-00601000 r--p  000000  fd:01 123456      /usr/bin/app
00601000-00602000 rw-p  001000  fd:01 123456      /usr/bin/app
7ffdb8000-7ffdd9000 rw-p 000000 00:00 0           [stack]
7ffff7dd5000-7ffff7df7000 r--p 000000 fd:01 654321 /lib/x86_64-linux-gnu/libc.so.6
```

### Розшифровка поля прав доступу (perms)

Поле складається з 4 символів:
1. `r` або `-`: Дозвіл на читання (`PROT_READ`).
2. `w` або `-`: Дозвіл на запис (`PROT_WRITE`).
3. `x` або `-`: Дозвіл на виконання інструкцій (`PROT_EXEC` / біт NX = 0).
4. `p` або `s`: Тип відображення — приватне (`MAP_PRIVATE`, copy-on-write) або спільне (`MAP_SHARED`).

Утиліти безпекового аудиту (`checksec`, `scanelf`) сканують `/proc/[pid]/maps` і сигналізують про критичну загрозу безпеці у випадку виявлення рядків з комбінацією `rwxp` або `rwxs`.
