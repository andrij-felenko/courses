# 🧮 Математичні засади односторонніх функцій із секретом

В основі асиметричної криптографії лежить математична концепція односторонньої функції з секретом (англ. *trapdoor one-way function*). Це відображення `f : X → Y`, яке задовольняє три суворі умови обчислювальної складності:

1. **Пряме обчислення є легким:** для будь-якого елемента `x ∈ X` значення `y = f(x)` обчислюється за детермінований поліноміальний час `O(n^k)`, де `n` — бітова довжина входу.
2. **Обернення без секрету є складним:** маючи лише `y` та відкритий опис функції `f`, обчислення будь-якого прообразу `x'` такого, що `f(x') = y`, вимагає суперполіноміальних зусиль (усі відомі класичні алгоритми потребують суб-експоненційного або експоненційного часу).
3. **Обернення з секретом є легким:** існує додаткова інформація `k` (секрет або «капкан»), знаючи яку, прообраз `x = f_inv(y, k)` обчислюється за детермінований поліноміальний час.

Усі практичні системи криптографії з відкритим ключем спираються на один із трьох алгебраїчних класів важковирішуваних задач: факторизацію великих складених чисел, дискретне логарифмування у скінченних полях та дискретне логарифмування в групах точок еліптичних кривих. Нижче наведено їхнє строге математичне виведення, числові розрахунки та аналіз стійкості.

---

### 1. Факторизація цілих чисел і криптосистема RSA

Стійкість алгоритму RSA спирається на асиметрію між простотою множення двох простих чисел і складністю розкладання їхнього добутку на множники.

#### Математичний апарат: теорема Ейлера та функція Кармайкла

Нехай `p` і `q` — два незалежні великі непарні прості числа однакової бітової довжини. Модуль криптосистеми визначається як:

```
N = p · q
```

Мультиплікативна група кільця лишків за модулем `N` позначається як `(Z / N·Z)*` або `Z_N*`. Вона містить усі числа від `1` до `N - 1`, які є взаємно простими з `N`. Кількість елементів у цій групі визначається функцією Ейлера `φ(N)`:

```
φ(N) = φ(p · q)
= φ(p) · φ(q)                    [мультиплікативність для взаємно простих p, q]
= (p - 1) · (q - 1)              [для простих чисел φ(p) = p - 1]
```

Для оптимізації розміру секретної експоненти часто використовують функцію Кармайкла `λ(N)`, яка визначає найменше спільне кратне порядків підгруп:

```
λ(N) = lcm(p - 1, q - 1)
= ((p - 1) · (q - 1)) / gcd(p - 1, q - 1)
```

За теоремою Ейлера, для будь-якого цілого `M`, взаємно простого з `N` (`gcd(M, N) = 1`):

```
M^φ(N) ≡ 1 (mod N)
```

І відповідно за теоремою Кармайкла:

```
M^λ(N) ≡ 1 (mod N)
```

#### Побудова ключів і доведення коректності RSA

1. **Відкрита експонента `e`:** обирається непарне число таке, що `1 < e < λ(N)` та `gcd(e, λ(N)) = 1`. Зазвичай обирають число Ферма `e = 65537` (`2¹⁶ + 1`), оскільки воно містить лише дві одиниці в двійковому записі, що максимізує швидкість піднесення до степеня.
2. **Секретна експонента `d`:** обчислюється як мультиплікативно обернений елемент до `e` за модулем `λ(N)` за допомогою розширеного алгоритму Евкліда:

```
e · d ≡ 1 (mod λ(N))
```

Це означає існування такого цілого числа `k`, що:

```
e · d = 1 + k · λ(N)
```

**Доведення коректності операції розшифрування:**
Операція шифрування повідомлення `M` (`0 ≤ M < N`):

```
C = M^e mod N
```

Операція дешифрування шифротексту `C` за допомогою закритого ключа `d`:

```
C^d mod N
= (M^e)^d mod N                  [підстановка визначення C]
= M^(e · d) mod N                [властивість степенів]
= M^(1 + k · λ(N)) mod N         [підстановка e · d = 1 + k · λ(N)]
= M · (M^λ(N))^k mod N           [розбиття степеня на добуток]
= M · (1)^k mod N                [застосування теореми Кармайкла M^λ(N) ≡ 1 mod N]
= M mod N                        [тотожність]
```

Якщо `gcd(M, N) > 1` (повідомлення ділиться на `p` або `q`), рівність все одно зберігається за китайською теоремою про залишки (CRT), оскільки `e · d ≡ 1 (mod p - 1)` і `e · d ≡ 1 (mod q - 1)`.

#### Прискорення RSA через китайську теорему про залишки (CRT)

На практиці операція піднесення до степеня за модулем `N` (довжиною, наприклад, 2048 бітів) обчислювально дорога: складність множення чисел довжини `B` бітів становить `O(B²)`. 

Застосування китайської теореми про залишки (англ. *Chinese Remainder Theorem, CRT*) дозволяє розбити обчислення `M = C^d mod N` на два незалежні обчислення за модулями простих множників `p` та `q` (кожен розміром `B / 2` бітів):

1. Попередньо розраховуються параметри закритого ключа CRT:
```
d_p = d mod (p - 1)
d_q = d mod (q - 1)
q_inv = q⁻¹ mod p
```

2. Дешифрування виконується за модулями `p` і `q`:
```
m_1 = C^d_p mod p
m_2 = C^d_q mod q
```

3. Остаточний результат відновлюється за формулою Гарнера:
```
h = (q_inv · (m_1 - m_2)) mod p
M = m_2 + h · q
```

Оскільки числа `p` і `q` удвічі коротші за `N`, кожне модульне множення виконується в 4 рази швидше, а степінь удвічі менший. З урахуванням двох обчислень сумарне прискорення становить приблизно `4×` порівняно з прямим обчисленням `C^d mod N`.

#### Числовий приклад розрахунку ключів RSA

Оберемо прості числа `p = 61` та `q = 53`.

1. Обчислюємо модуль:
```
N = 61 · 53 = 3233
```

2. Обчислюємо значення функцій Ейлера та Кармайкла:
```
φ(N) = (61 - 1) · (53 - 1) = 60 · 52 = 3120
λ(N) = lcm(60, 52) = (60 · 52) / gcd(60, 52) = 3120 / 4 = 780
```

3. Обираємо відкриту експоненту `e = 17` (перевірка: `gcd(17, 780) = 1`).

4. Знаходимо `d = 17⁻¹ mod 780` за розширеним алгоритмом Евкліда (співвідношення Безу `17·d + 780·y = 1`):
```
780 = 45 · 17 + 15
17 = 1 · 15 + 2
15 = 7 · 2 + 1
```

Виражаємо остачу `1` у зворотному напрямку:
```
1 = 15 - 7 · 2                    [з рівняння 15 = 7·2 + 1]
= 15 - 7 · (17 - 1 · 15)          [підстановка 2 = 17 - 1·15]
= 8 · 15 - 7 · 17                 [групування доданків при 15 та 17]
= 8 · (780 - 45 · 17) - 7 · 17    [підстановка 15 = 780 - 45·17]
= 8 · 780 - 367 · 17              [групування доданків при 780 та 17]
```

Звідси:
```
-367 · 17 ≡ 1 (mod 780)
d = -367 mod 780 = 780 - 367 = 413
```

Перевірка: `(17 · 413) mod 780 = 7021 mod 780 = 1`.

5. Зашифруємо повідомлення `M = 65`:
```
C = 65¹⁷ mod 3233 = 2790
```

6. Розшифруємо `C = 2790`:
```
M = 2790⁴¹³ mod 3233 = 65
```

#### Математична небезпека «сирого» RSA та схема RSA-PSS

Застосування операції `S = M^d mod N` безпосередньо до повідомлення (так званий «сирий» або підручниковий RSA, англ. *textbook RSA*) є фатально небезпечним через мультиплікативну гомоморфність схеми.

Якщо зловмисник перехопить дійсні підписи `S_1 = M_1^d mod N` та `S_2 = M_2^d mod N` над двома різними повідомленнями, він може без знання закритого ключа згенерувати дійсний підпис під третім повідомленням `M_3 = (M_1 · M_2) mod N`:

```
S_3 = (S_1 · S_2) mod N
= (M_1^d · M_2^d) mod N          [підстановка визначень S_1, S_2]
= (M_1 · M_2)^d mod N            [властивість степенів у кільці лишків]
= M_3^d mod N                    [підстановка визначення M_3]
```

Окрім цього, якщо саме повідомлення `M` є малим числом (`M³ < N`), обчислення шифротексту з відкритою експонентою `e = 3` дає `C = M³` у множині дійсних цілих чисел без переповнення модуля, звідки повідомлення видобувається тривіальним обчисленням кубічного кореня `M = ∛C` над звичайними числами.

Для усунення цих алгебраїчних слабкостей стандарт RFC 8017 запроваджує схему підпису **RSA-PSS** (англ. *Probabilistic Signature Scheme*). Математична конструкція PSS формує блок для підпису через функцію генерації маски `MGF1` на основі криптографічного геша:

1. Генерується випадковий рядок солі `salt` фіксованої довжини (наприклад, 32 байти).
2. Обчислюється дайджест: `H = Hash(Padding1 || Hash(M) || salt)`.
3. Формується маскований блок даних: `DB = Padding2 || salt`.
4. Обчислюється маска: `dbMask = MGF1(H, len(DB))`.
5. Маскування виконується через побітове додавання: `maskedDB = DB ⊕ dbMask`.
6. Підсумковий блок: `EM = maskedDB || H || 0xbc`.

Отримане значення `EM` підноситься до секретного степеня `S = EM^d mod N`. Завдяки випадковій солі та рандомізованій масці кожне підписання того самого повідомлення породжує абсолютно інший підпис `S`, що усуває гомоморфні атаки та надає доведену стійкість у моделі випадкового оракула (Random Oracle Model).

### 2. Дискретне логарифмування у скінченних полях (Diffie-Hellman)

Нехай `p` — велике просте число, а `F_p = Z / p·Z` — скінченне поле Галуа. Мультиплікативна група `F_p* = {1, 2, ..., p - 1}` є циклічною групою порядку `p - 1`. Елемент `g ∈ F_p*` називається первісним коренем (генератором групи), якщо його послідовні степені породжують усі елементи групи:

```
{g¹, g², g³, ..., g^(p-1) mod p} = F_p*
```

#### Складність прямої та оберненої задач

- **Пряма дія (модульне піднесення до степеня):** маючи основу `g`, показник `x` і модуль `p`, обчислення `y = g^x mod p` виконується методом швидкого піднесення до степеня (квадрування та множення) за час `O(log x · log² p)` — це бінарний логарифмічний час від величини степеня.
- **Обернена дія (дискретний логарифм, DLP):** маючи лише `y`, `g` та `p`, знаходження такого цілого `x`, що `g^x ≡ y (mod p)` (позначається `x = log_g(y)`), є важкою задачею. Найшвидший відомий загальний класичний алгоритм — метод загального решета числового поля (GNFS) — має субекспоненційну складність:

```
L_p[1/3, c] = exp((c + o(1)) · (ln p)^(1/3) · (ln ln p)^(2/3))
```

#### Математичне виведення протоколу Діффі-Геллмана

1. Сторони відкрито обирають параметри домену: велике просте число `p` та генератор `g`.
2. Аліса генерує таємне випадкове число `a ∈ [2, p - 2]` і обчислює відкритий ключ:
```
A = g^a mod p
```
3. Боб генерує таємне випадкове число `b ∈ [2, p - 2]` і обчислює відкритий ключ:
```
B = g^b mod p
```
4. Сторони відкрито обмінюються значеннями `A` та `B`.
5. Обчислення спільного секрету `K`:
   - Аліса обчислює: `K_A = B^a mod p = (g^b)^a mod p = g^(a · b) mod p`
   - Боб обчислює: `K_B = A^b mod p = (g^a)^b mod p = g^(a · b) mod p`

Оскільки множення в кільці показників степеня комутативне (`a · b = b · a`), отримані результати ідентичні:

```
K = g^(a · b) mod p
```

Перехоплювач, який спостерігає `p`, `g`, `A = g^a` та `B = g^b`, стоїть перед обчислювальною проблемою Діффі-Геллмана (CDH): знайти `g^(a · b)` без знання `a` чи `b`.

### 3. Криптографія на еліптичних кривих (ECC) та ECDSA

Головний недолік RSA та класичного Діффі-Геллмана у полях `F_p` — суб-експоненційна складність їхнього зламу методом GNFS. Це вимагає постійного нарощування довжини ключів: для забезпечення 128 бітів симетричної стійкості розмір модуля `N` у RSA має становити щонайменше 3072 біти.

На еліптичних кривих не працює метод решета числового поля, і найкращі відомі алгоритми дискретного логарифмування (метод ро-Поларда, Pollard rho) мають повну експоненційну складність `O(√n)`, де `n` — порядок групи точок. Завдяки цьому ключ еліптичної кривої довжиною 256 бітів надає такий самий рівень безпеки, як 3072-бітний ключ RSA.

#### Форма Вейєрштрасса над простим полем `F_p`

Нехай `p > 3` — просте число. Несингулярна еліптична крива `E` в короткій формі Вейєрштрасса задається рівнянням:

```
y² ≡ x³ + a · x + b (mod p)
```

де `a, b ∈ F_p`, причому дискримінант кривої є ненульовим:

```
Δ = -16 · (4 · a³ + 27 · b²) ≠ 0 (mod p)
```

Множина точок кривої `E(F_p)` складається з усіх пар координат `(x, y) ∈ F_p × F_p`, які задовольняють рівняння, разом із формальною нескінченно віддаленою точкою `O` (нейтральний елемент групи).

#### Геометричний і алгебраїчний груповий закон додавання точок

Нехай задано дві точки `P = (x_1, y_1)` та `Q = (x_2, y_2)`. Результат їхнього додавання `R = P + Q = (x_3, y_3)` визначається за правилами:

1. **Якщо `P = O`, то `P + Q = Q`. Якщо `Q = O`, то `P + Q = P`.**
2. **Якщо `x_1 = x_2` та `y_1 = -y_2 (mod p)`, то `P + Q = O` (точки є взаємно протилежними).**
3. **У загальному випадку нахил січної або дотичної прямої `s` обчислюється як:**

```
Якщо P ≠ Q (додавання різних точок):
s = (y_2 - y_1) / (x_2 - x_1) mod p
= (y_2 - y_1) · (x_2 - x_1)⁻¹ mod p

Якщо P = Q та y_1 ≠ 0 (подвоєння точки P + P = 2P):
s = (3 · x_1² + a) / (2 · y_1) mod p
= (3 · x_1² + a) · (2 · y_1)⁻¹ mod p
```

4. **Координати результуючої точки `(x_3, y_3)`:**

```
x_3 = s² - x_1 - x_2 mod p
y_3 = s · (x_1 - x_3) - y_1 mod p
```

#### Математичне виведення алгоритму підпису ECDSA

Алгоритм цифрового підпису на еліптичних кривих (ECDSA) спирається на базову точку `G` порядку `n` (`[n]G = O`):

1. **Генерація пари ключів:**
   - Таємний ключ: випадкове число `d ∈ [1, n - 1]`.
   - Відкритий ключ: точка `Q = [d]G`.

2. **Створення підпису над повідомленням `M`:**
   - Обчислюється геш `z = Hash(M)` (беруться ліві `n` бітів геша).
   - Генерується криптографічно стійке випадкове одноразове число `k ∈ [1, n - 1]` (ефемерний ключ, nonce).
   - Обчислюється точка `(x_1, y_1) = [k]G`.
   - Перша компонента підпису: `r = x_1 mod n` (якщо `r = 0`, обирається новий `k`).
   - Друга компонента підпису:
```
s = k⁻¹ · (z + r · d) mod n
```
   Якщо `s = 0`, обирається інший `k`. Підпис складається з пари `(r, s)`.

3. **Перевірка підпису `(r, s)`:**
   - Перевіряється, що `r, s ∈ [1, n - 1]`.
   - Обчислюється геш `z = Hash(M)`.
   - Обчислюється значення `w = s⁻¹ mod n`.
   - Обчислюються допоміжні коефіцієнти: `u_1 = z · w mod n` та `u_2 = r · w mod n`.
   - Обчислюється точка на кривій `(x_1', y_1') = [u_1]G + [u_2]Q`.
   - Підпис є дійсним тоді й лише тоді, коли `r ≡ x_1' (mod n)`.

**Доведення коректності верифікації ECDSA:**
```
[u_1]G + [u_2]Q
= [z · w]G + [r · w]Q            [підстановка визначень u_1, u_2]
= [z · s⁻¹]G + [r · s⁻¹]([d]G)   [підстановка w = s⁻¹, Q = [d]G]
= [(z + r · d) · s⁻¹]G           [факторизація скалярів над G]
= [(z + r · d) · (k⁻¹ · (z + r · d))⁻¹]G  [підстановка формули s]
= [(z + r · d) · (z + r · d)⁻¹ · k]G      [властивість оберненого добутку]
= [k]G                           [скорочення (z + r · d) з його оберненим]
= (x_1, y_1)                     [за визначенням r = x_1 mod n]
```

#### Фатальна вразливість повторного використання nonce `k`

Якщо один і той самий nonce `k` використовується для підпису двох різних повідомлень з гешами `z_1` та `z_2`, таємний ключ `d` розраховується миттєво звичайною арифметикою.

Нехай підписи мають вигляд `(r, s_1)` та `(r, s_2)` (значення `r` однакове, оскільки `[k]G` одне й те саме):
```
s_1 = k⁻¹ · (z_1 + r · d) mod n
s_2 = k⁻¹ · (z_2 + r · d) mod n
```

Віднімаємо друге рівняння від першого:
```
s_1 - s_2 ≡ k⁻¹ · (z_1 - z_2) (mod n)
```

Звідси секретний nonce `k` відновлюється безпосередньо:
```
k = (z_1 - z_2) · (s_1 - s_2)⁻¹ mod n
```

Маючи відновлений `k`, таємний ключ власника `d` обчислюється з першого рівняння за один крок:
```
d = (s_1 · k - z_1) · r⁻¹ mod n
```

Саме ця математична помилка генератора випадкових чисел призвела у 2010 році до повної компрометації головного закритого ключа консолі Sony PlayStation 3 (де `k` було зашите як фіксована константа). Для запобігання цій катастрофі стандарт RFC 6979 визначає детерміновану генерацію `k = HMAC(d || z)`.

### 4. Скручені криві Едвардса: Ed25519

Класична форма Вейєрштрасса має серйозний практичний недолік: формула додавання містить розгалуження (окремі випадки для `P ≠ Q`, `P = Q`, `P = -Q` та додавання нейтрального елемента `O`). Якщо реалізація перевіряє ці умови через умовні переходи `if/else`, час виконання залежить від бітів секретного ключа `k`, що відкриває вразливість до атак за сторонніми каналами (атаки за часом, таймінг-атаки).

Даніель Бернштейн (Daniel J. Bernstein) зі співавторами запропонував використовувати скручені криві Едвардса (англ. *Twisted Edwards Curves*). Крива **Curve25519** для підписів **Ed25519** задається рівнянням над полем `F_p` з простим числом `p = 2²⁵⁵ - 19`:

```
-x² + y² = 1 + d · x² · y²
```

де параметр `d`:

```
d = -121665 / 121666 mod (2²⁵⁵ - 19)
```

#### Повні формули додавання (Complete Addition Law)

Для кривої Ed25519 формула додавання двох точок `(x_1, y_1)` та `(x_2, y_2)` є абсолютно повною (англ. *complete*):

```
x_3 = (x_1 · y_2 + y_1 · x_2) / (1 + d · x_1 · x_2 · y_1 · y_2) mod p

y_3 = (y_1 · y_2 + x_1 · x_2) / (1 - d · x_1 · x_2 · y_1 · y_2) mod p
```

Знаменники цих дробів ніколи не перетворюються на нуль для жодної пари точок на кривій. Завдяки цьому:
- Формула однаково коректно працює для додавання різних точок, для подвоєння точки (`P = Q`), для нейтрального елемента `(0, 1)` та для протилежних точок.
- Алгоритм виконується за строго фіксовану кількість тактів процесора незалежно від значень координат і бітів ключа, що гарантує математичний імунітет до атак через вимірювання часу виконання.

#### Алгоритм цифрового підпису Ed25519 (EdDSA)

Схема підпису EdDSA над кривою Ed25519 використовує криптографічну геш-функцію SHA-512:

1. **Генерація пари ключів:**
   - Закритий ключ: 32 байти випадкового насіння `k`.
   - Обчислюється розширений геш `H(k) = (h_0, h_1, ..., h_63) = (a, prefix)`.
   - Скаляр `a` приводиться до спеціального діапазону (очищення бітів: найменші 3 біти обнуляються для уникнення підгрупових атак, біт 254 встановлюється, біт 255 скидається).
   - Відкритий ключ: точка `A = [a]B`, стиснута у 32 байти (де `B` — фіксована базова точка кривої).

2. **Формування підпису над повідомленням `M`:**
   - Детермінований псевдовипадковий скаляр `r = SHA-512(prefix || M) mod L` (де `L` — порядок підгрупи `2²⁵² + 27742317777372353535851937790883648493`).
   - Точка зобов'язання: `R = [r]B`.
   - Спільний виклик: `e = SHA-512(R || A || M) mod L`.
   - Скалярна відповідь: `S = (r + e · a) mod L`.
   - Підпис — це 64-байтовий масив `(R, S)`.

3. **Перевірка підпису `(R, S)`:**
   - Обчислюється той самий виклик `e = SHA-512(R || A || M) mod L`.
   - Перевіряється групова рівність:

```
[S]B = R + [e]A
```

Доведення рівності:
```
[S]B
= [(r + e · a) mod L]B           [підстановка формули S]
= [r]B + [e · a]B                [дистрибутивність скалярного множення]
= R + [e]([a]B)                  [асоціативність: R = [r]B, [e·a]B = [e][a]B]
= R + [e]A                       [підстановка A = [a]B]
```

#### Сходи Монтгомері (Montgomery Ladder)

Для обчислення скалярного добутку `[k]P` у криптосистемах з постійним часом виконання (Constant-Time) використовується алгоритм сходів Монтгомері. Звичайний метод подвоєння та додавання (double-and-add) виконує операцію додавання лише тоді, коли поточний біт скаляра `k_i` дорівнює `1`. Це створює змінний енергетичний профіль та різний час виконання, що дозволяє відновити секретний ключ за допомогою простого аналізу потужності (SPA).

Сходи Монтгомері на кожному кроці циклу для кожного біта скаляра виконують строго одну операцію додавання та одну операцію подвоєння:

```
Вхід: точка P, скаляр k = (k_{m-1} ... k_1 k_0)_2
Ініціалізація:
R_0 = O (нейтральний елемент)
R_1 = P

Для i від m-1 до 0:
    Якщо k_i == 0:
        R_1 = R_0 + R_1          [додавання точок]
        R_0 = 2 · R_0            [подвоєння точки]
    Інакше (k_i == 1):
        R_0 = R_0 + R_1          [додавання точок]
        R_1 = 2 · R_1            [подвоєння точки]

Вихід: R_0 = [k]P
```

Інваріант алгоритму: на кожній ітерації зберігається різниця `R_1 - R_0 = P`. Завдяки цьому на кривих Монтгомері (таких як X25519) координата `y` взагалі не бере участі в обчисленнях: вся арифметика ведеться виключно над проективною `X/Z` координатою, що додатково прискорює скалярне множення та усуває будь-які витоки інформації через побічні канали.
