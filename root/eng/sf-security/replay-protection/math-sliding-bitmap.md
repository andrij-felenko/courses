# 🧮 Алгебра станів ковзної бітової маски та ймовірність колізій фільтра Блума

Захист від перегравання в асинхронних ненадійних мережах вимагає точного математичного балансу між обчислювальною складністю перевірки, обсягом оперативної пам'яті та стійкістю до мережевого перевпорядкування пакетів. У цьому розділі наведено строгий алгебраїчний апарат ковзної бітової маски (RFC 6479) та ймовірнісну модель фільтра Блума для дедуплікації одноразових чисел.

### 1. Алгебра станів та формальний автомат ковзного бітового вікна

Нехай мережевий протокол передає послідовність пакетів, пронумерованих строго монотонною послідовністю натуральних чисел `S ∈ {1, 2, 3, ...}`. У безпровідних або маршрутизованих мережах дейтаграми можуть прибувати з порушенням первинного порядку через наявність альтернативних шляхів (ECMP / Multi-Path Routing) або через роботу черг із пріоритезацією трафіку (Quality of Service).

Стан фільтра проти перегравання на боці отримувача в будь-який момент часу задається кортежем із трьох компонентів:

```
State = (M, B, W)
де:
  M ∈ ℕ             [найбільший порядковий номер, успішно верифікований до цього часу]
  W ∈ {64, 128, …}  [ширина вікна спостереження у бітах]
  B ∈ {0, 1}^W      [бітовий вектор довжиною W, де біт b[i] = 1 означає,
                     що пакет із номером (M - i) уже отримано та верифіковано]
```

Простір усіх можливих номерів вхідного пакета `S` однозначно розбивається на три неперетинні підмножини відносно поточного максимуму `M` та ширини вікна `W`:

```
Підмножина 1 (Випередження максимуму): Ω_ahead = {S ∈ ℕ | S > M}
Підмножина 2 (Діапазон вікна):        Ω_win   = {S ∈ ℕ | M - W < S ≤ M}
Підмножина 3 (Застарілі пакети):       Ω_stale = {S ∈ ℕ | S ≤ M - W}
```

Об'єднання цих трьох підмножин строго покриває весь простір натуральних чисел `ℕ`:

```
Ω_ahead ∪ Ω_win ∪ Ω_stale = ℕ
Ω_ahead ∩ Ω_win = ∅
Ω_win ∩ Ω_stale = ∅
Ω_ahead ∩ Ω_stale = ∅
```

#### Функція переходу стану автомата

Функція верифікації та переходу стану `F : State × ℕ → {ACCEPT, REJECT} × State` визначається кусочно за трьома детермінованими правилами:

```
Випадок 1: S ∈ Ω_ahead (Пакет новий, попереду відомого максимуму)
  k = S - M                          [величина зсуву вікна вперед]
  Якщо k ≥ W:
    B' = 1                           [усі старі пакети випали з вікна, ставимо лише нульовий біт]
  Інакше:
    B' = (B << k) | 1                [порозрядний зсув маски вліво на k позицій і встановлення біта 0]
  M' = S                             [новий максимум послідовності]
  Результат: (ACCEPT, (M', B', W))

Випадок 2: S ∈ Ω_win (Пакет потрапляє в діапазон поточного вікна)
  offset = M - S                     [зміщення відносно правого краю, 0 ≤ offset < W]
  mask_bit = (B >> offset) & 1       [значення біта за зміщенням]
  Якщо mask_bit == 1:
    Результат: (REJECT_DUPLICATE, (M, B, W))   [пакет уже оброблено — Replay Attack!]
  Інакше:
    B' = B | (1 << offset)           [позначаємо отримання раніше пропущеного пакета]
    Результат: (ACCEPT, (M, B', W))

Випадок 3: S ∈ Ω_stale (Пакет відстає від максимуму більше ніж на W)
  Результат: (REJECT_OLD, (M, B, W)) [пакет занадто старий, неможливо довести свіжість]
```

#### Теорема про коректність фільтрації

Коректність алгоритму спирається на суворе математичне доведення двох взаємодоповнюючих властивостей безпеки та доступності.

**Властивість 1 (Стійкість до повторів у вікні):** Жоден пакет із номером `S`, який уже був успішно верифікований у межах вікна `[M - W + 1, M]`, не може бути прийнятий вдруге.

*Доведення:*
- При отриманні нового пакета `S_1 > M` нульовий біт маски встановлюється в `1` за формулою `B' = (B << k) | 1`.
- Якщо згодом надходить повторний пакет `S_2 = S_1`, його зміщення відносно актуального максимуму `M_current ≥ S_1` дорівнює `offset = M_current - S_1`.
- Оскільки при кожному подальшому зсуві максимуму на `Δ` бітова маска зсувається вліво на `Δ` розрядів, біт, встановлений для `S_1`, переміщується точно на позицію `offset`.
- Отже, вираз `(B >> offset) & 1` гарантовано поверне `1`, і пакет буде відхилено з вердиктом `REJECT_DUPLICATE`.

**Властивість 2 (Толерантність до перевпорядкування):** Будь-який легітимний пакет із номером `S`, що надійшов із запізненням через мережевий джитер, але потрапив у діапазон `M - W < S ≤ M`, буде успішно прийнятий за умови, що він надходить уперше.

*Доведення:*
- Якщо пакет із номером `S` ще не надходив, відповідний біт на позиції `offset = M - S` дорівнює `0`, оскільки початкова ініціалізація або операція зсуву `(B << k)` заповнює нові розряди нулями.
- Вираз `(B >> offset) & 1` повертає `0`, функція перевірки переходить у гілку `ACCEPT`, а стан маски атомарно оновлюється через порозрядне «АБО»: `B' = B | (1 << offset)`.

### 2. Модель мережевого джитеру та ймовірність хибного відкидання

У розподілених мережах із комутацією пакетів затримка доставки є випадковою величиною, зумовленою коливаннями довжини черг на маршрутизаторах. Нехай `X` — випадкова величина запізнення пакета, виражена в кількості пакетів, які встигли обігнати даний пакет на транзитних вузлах зв'язку.

Легітимний пакет буде помилково відкинутий як застарілий (`REJECT_OLD`), якщо величина його відставання `X` перевищить ширину вікна `W`:

```
P_drop(W) = P(X ≥ W) = 1 - F_X(W - 1)
```

#### Модель експоненційного перевпорядкування черги

Якщо ймовірність затримки пакета підпорядковується показниковому розподілу з параметром інтенсивності `λ` (середнє запізнення `E[X] = μ = 1/λ` пакетів):

```
F_X(x) = 1 - e^(-λ · x)            [функція розподілу ймовірностей]
P_drop(W) = 1 - (1 - e^(-λ · W))   [підстановка у формулу перевищення порогу]
= e^(-λ · W)                       [скорочення одиниць]
= e^(-W / μ)                       [заміна параметра λ на 1/μ]
```

Звідси отримуємо аналітичну формулу розрахунку мінімальної ширини вікна `W` для досягнення цільової надійності доставки із допустимим рівнем втрат `ε`:

```
e^(-W / μ) ≤ ε                     [вихідна нерівність надійності]
-W / μ ≤ ln(ε)                     [логарифмування обох частин]
W / μ ≥ -ln(ε)                     [множення на -1 зі зміною знаку нерівності]
W ≥ μ · ln(1 / ε)                  [властивість -ln(ε) = ln(1/ε)]

Розрахунковий приклад:
  Нехай середнє перевпорядкування в черзі маршрутизатора становить μ = 16 пакетів.
  Необхідний рівень втрат легітимного трафіку ε = 10⁻⁶ (один пакет на мільйон).
  W ≥ 16 · ln(10⁶) = 16 · 13.8155 = 221.05 бітів.
  Висновок: вікна W = 256 бітів (4 машинних слова uint64_t) гарантовано достатньо.
```

Цей розрахунок демонструє, чому стандарти IPsec (RFC 4303) та DTLS 1.3 рекомендують мінімальну ширину вікна `W = 64` для звичайних каналів і `W = 128` або `W = 256` для магістральних каналів із високим ступенем паралелізму.

### 3. Ймовірнісна дедуплікація Nonce через фільтр Блума

У прикладних високонавантажених REST і Webhook API з інтенсивністю `R` запитів за секунду та вікном толерантності часу `Δt` секунд, загальна кількість одноразових чисел `n`, що одночасно перебувають під наглядом, становить:

```
n = R · (2 · Δt)
```

Збереження такої кількості ідентифікаторів у точній геш-таблиці вимагає значного обсягу динамічної пам'яті. Фільтр Блума дозволяє стиснути стан у фіксований бітовий масив розміром `m` бітів за допомогою `k` незалежних геш-функцій.

#### Покрокове виведення ймовірності хибного спрацьовування (False Positive)

Нехай у фільтр розміром `m` бітів послідовно вставлено `n` ключів за допомогою `k` хеш-функцій.

1. Ймовірність того, що конкретний біт не був встановлений певною геш-функцією при одному зверненні:
```
p_not_set = 1 - 1/m                [вибір будь-якого з (m - 1) інших бітів]
```

2. Ймовірність того, що біт залишився рівним `0` після вставки всіх `k · n` гешів:
```
p_zero = (1 - 1/m)^(k·n)           [незалежність вибору бітів геш-функціями]
```

Використовуючи фундаментальну границю `lim_{m→∞} (1 - 1/m)^m = e⁻¹`:
```
p_zero = ((1 - 1/m)^m)^((k·n)/m)   [перетворення показника степеня]
≈ e^(-k·n / m)                     [наближення експонентою при великих m]
```

3. Ймовірність того, що конкретний біт встановлений у `1`:
```
p_one = 1 - p_zero                 [доповняльна ймовірність протилежної події]
≈ 1 - e^(-k·n / m)                 [підстановка наближення p_zero]
```

4. Ймовірність того, що новий легітимний Nonce випадково дасть одиниці в усіх `k` позиціях (хибне спрацьовування та помилкове відхилення запиту як replay):
```
p_fp = (p_one)^k                   [сумісна поява одиниць у k незалежних бітах]
≈ (1 - e^(-k·n / m))^k             [підстановка виразу для p_one]
```

#### Мінімізація ймовірності помилки та оптимальне число геш-функцій

Для фіксованих параметрів розміру пам'яті `m` і кількості елементів `n` знайдемо мінімум функції `p_fp(k)` через взяття похідної від натурального логарифма:

```
ln(p_fp) = k · ln(1 - e^(-k·n / m))
```

Диференціюючи вираз по змінній `k` та прирівнюючи похідну до нуля, отримуємо оптимальну кількість геш-функцій `k_opt`:

```
k_opt = (m / n) · ln 2 ≈ 0.69315 · (m / n)
```

Покрокове обчислення мінімальної ймовірності помилки при оптимальному значенні `k_opt`:

```
p_fp = (1 - e^(-( (m/n)·ln 2 · n / m )))^( (m/n)·ln 2 )   [підстановка k_opt у вихідну формулу]
     = (1 - e^(-ln 2))^( (m/n)·ln 2 )                      [скорочення n/m та m/n у показнику]
     = (1 - 1/2)^( (m/n)·ln 2 )                            [властивість e^(-ln 2) = 1/2]
     = (1/2)^( (m/n)·ln 2 )                                [арифметика: 1 - 1/2 = 1/2]
     = 2^(-(m/n) · ln 2)                                   [властивість (1/2)^x = 2^(-x)]
     = (e^(ln 2))^(-(m/n) · ln 2)                          [подання 2 як e^(ln 2)]
     = e^(-(m/n) · (ln 2)²)                                [перемноження показників степеня]
     ≈ e^(-0.48045 · (m/n))                                [обчислення константи (ln 2)² ≈ 0.48045]
```

Звідси отримуємо інженерну формулу розрахунку необхідної кількості бітів пам'яті на один елемент `(m/n)` для забезпечення заданого рівня надійності:

```
ln(p_fp) = -(m/n) · (ln 2)²        [логарифмування мінімального p_fp]
m/n = -ln(p_fp) / (ln 2)²          [вираження відношення m/n]
≈ -2.08136 · ln(p_fp)              [обчислення 1 / (ln 2)² ≈ 2.08136]
≈ 4.79 · log₂(1 / p_fp)            [перехід до двійкового логарифма]
```

### 4. Подвійний буфер поколінь (Generation Slicing)

Щоб запобігти нескінченному насиченню фільтра Блума одиницями (що призвело б до заповнення всіх бітів і деградації `p_fp → 1`), у довготривалих серверах застосовують циклічну ротацію двох поколінь: `B_current` та `B_previous`.

```
Циклічний процес ротації кожні Δt секунд:
  1. Звільнити пам'ять фільтра B_previous
  2. B_previous = B_current
  3. B_current = Створити_Новий_Фільтр_Блума(m, k)

Алгоритм верифікації запиту (Timestamp, Nonce):
  1. delta = |Timestamp - T_server|
  2. Якщо delta > Δt:
       Повернути REJECT_CLOCK_SKEW
  3. Якщо B_current.перевірити(Nonce) == ТАК або B_previous.перевірити(Nonce) == ТАК:
       Повернути REJECT_REPLAY_ATTACK
  4. B_current.додати(Nonce)
  5. Повернути ACCEPT_OK
```

Ця архітектура гарантує, що кількість активних елементів у кожному фільтрі ніколи не перевищує розрахункове значення `n = R · Δt`, забезпечуючи суворе дотримання теоретичної межі ймовірності помилки `p_fp` протягом усього життєвого циклу сервера без витоків пам'яті.
