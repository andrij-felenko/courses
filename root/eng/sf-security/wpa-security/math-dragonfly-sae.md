# 🧮 Математика протоколу Dragonfly: криптографічне виведення SAE у WPA3

Протокол одночасної автентифікації рівноправних вузлів (Simultaneous Authentication of Equals, SAE), стандартизований у специфікації WPA3 та документі RFC 7664, належить до класу криптографічних протоколів PAKE (Password-Authenticated Key Exchange, у перекладі з англійської — «обмін ключами, автентифікований паролем»). Його фундаментальна математична мета — дозволити двом сторонам (клієнту та точці доступу), які володіють спільним слабким секретом низької ентропії (коротким текстовим паролем), узгодити спільний криптографічно стійкий сеансовий ключ високої ентропії через повністю відкритий і ворожий радіоканал, унеможливлюючи для пасивного або активного перехоплювача будь-яку форму офлайн-перебору словника.

Нижче наведено повний алгебраїчний апарат протоколу Dragonfly над еліптичними кривими: перетворення пароля на точку кривої (PWE), симетричний обмін у фазах Commit і Confirm, покроковий числовий приклад групової взаємодії, захист від атак вичерпання ресурсів та математичне доведення стійкості до атак за відкритим текстом.

---

### 1. Криптографічний простір та параметри еліптичної кривої

Протокол SAE оперує в групі точок еліптичної кривої `E(F_p)`, визначеної рівнянням у короткій формі Вейєрштрасса над скінченним простим полем `F_p`:
```
y² ≡ x³ + a·x + b (mod p)
```
де `p` — простий модуль поля (для стандартної кривої NIST P-256 / secp256r1 `p = 2²⁵⁶ - 2²²⁴ + 2¹⁹² + 2⁹⁶ - 1`), а коефіцієнти кривої задовольняють умову ненульового дискримінанта: `4a³ + 27b² ≢ 0 (mod p)`.

Базовими криптографічними параметрами схеми є:
- `p` — простий порядок поля `F_p`.
- `a, b ∈ F_p` — коефіцієнти рівняння кривої (для NIST P-256 `a = -3`).
- `G = (G_x, G_y)` — стандартна базова генераторна точка кривої.
- `q` — великий простий порядок циклічної підгрупи точок, породженої генератором `G` (де `q · G = O`, `O` — точка на нескінченності).
- `pwd` — рядок спільного пароля мережі (ASCII / UTF-8).
- `MAC_A, MAC_B` — 6-байтні фізичні адреси сторін зв'язку (STA та AP).

Для усунення неоднозначності адреси сторін завжди канонічно впорядковуються за числовим значенням:
```
min_max_mac = min(MAC_A, MAC_B) || max(MAC_A, MAC_B)
```

Внутрішні обчислення точок кривої виконуються не в афінних координатах `(x, y)`, де кожна операція додавання вимагає дорогого знаходження оберненого елемента в полі `F_p` (ділення за модулем через розширений алгоритм Евкліда або малу теорему Ферма `a⁻¹ ≡ a^(p-2) mod p`), а в проєктивних координатах Якобі `(X : Y : Z)`, де зв'язок задається формулами `x = X / Z²` та `y = Y / Z³`. Множення точки на скаляр реалізується алгоритмом драбини Монтгомері (Montgomery Ladder) із константним часом виконання: на кожному бітовому кроці виконується рівно одне подвоєння точки та одне додавання незалежно від того, чи дорівнює поточний біт скаляра 0 або 1. Це усуває будь-яку залежність часу обчислення від значень бітів секретного скаляра.

### 2. Фаза 0: Відображення пароля на криву (виведення точки PWE)

Головний математичний бар'єр протоколу PAKE полягає в перетворенні нерівномірного текстового пароля на випадкову валідну точку еліптичної кривої — **`PWE`** (Password Element, елемент пароля), координати якої `(x_pwe, y_pwe)` не розкривають структури вихідного слова.

#### Метод Hunting-and-Pecking (пошук методом проб)
В оригінальній специфікації RFC 7664 формування точки `PWE` здійснювалося ітеративним алгоритмом перевірки квадратичного лишку:

1. **Формування псевдовипадкового насіння (seed):**
   Для цілочисельного лічильника ітерацій `c = 1, 2, 3, ...` обчислюється криптографічний хеш:
   ```
   val = HMAC-SHA256(pwd, min_max_mac || c)
   ```
2. **Кандидат на абсцису точки:**
   Отримане значення `val` розглядається як координата `x`:
   ```
   x_c = val mod p
   ```
3. **Обчислення значення полінома кривої:**
   ```
   w = (x_c³ + a·x_c + b) mod p
   ```
4. **Перевірка критерію Ейлера (символ Лежандра):**
   Значення `w` є квадратичним лишком у полі `F_p` (тобто існує таке `y`, що `y² ≡ w mod p`) тоді і лише тоді, коли:
   ```
   w^((p - 1) / 2) ≡ +1 (mod p)
   ```
   - Якщо `w^((p - 1) / 2) ≡ -1 (mod p)`: число `w` є квадратичним нелишком, точка з абсцисою `x_c` на кривій не існує. Лічильник інкрементується `c = c + 1`, і алгоритм повторює спробу.
   - Якщо `w^((p - 1) / 2) ≡ +1 (mod p)`: координата `x = x_c` знайдена.
5. **Вилучення квадратного кореня (алгоритм Тонеллі — Шенкса):**
   Оскільки для кривої P-256 простий модуль задовольняє умову `p ≡ 3 (mod 4)`, точний корінь обчислюється безпосередньо за формулою Лагранжа:
   ```
   y_candidate = w^((p + 1) / 4) mod p
   ```
6. **Вибір знака ординати за бітом парності:**
   Щоб однозначно зафіксувати одну з двох симетричних точок `(x, y)` та `(x, p - y)`, аналізується молодший значущий біт (LSB) вихідного хешу `val`:
   ```
   якщо (y_candidate mod 2) == (val mod 2):
       y_pwe = y_candidate
   інакше:
       y_pwe = (p - y_candidate) mod p
   ```
   Результуюча точка `PWE = (x_pwe, y_pwe) ∈ E(F_p)` стає персональним базовим генератором для поточної пари пристроїв.

#### Вразливість Dragonblood та детермінований метод Hash-to-Curve
У 2019 році криптографи Маті Ванхоф (Mathy Vanhoef) та Еяль Ронен (Eyal Ronen) виявили вразливість **Dragonblood**. Кількість ітерацій лічильника `c` до знаходження першого квадратичного лишку розподілена геометрично з параметром успіху `p_suc ≈ 0.5`. У середньому потрібно 2 ітерації, однак для деяких паролів пошук вимагає 5 або більше спроб. Ця різниця в часі виконання та специфічний шаблон звернень до кеш-пам'яті процесора створювали побічний канал (Side-Channel Attack), що дозволяло пасивному спостерігачу відновлювати біти пароля.

Для повної ліквідації часових витоків стандарт WPA3 було оновлено (специфікація RFC 9380) з переходом на детерміноване відображення **Hash-to-Curve (H2C)** за спрощеним алгоритмом Шалюе — ван де Вустійна — Уласа (SSWU — Straightforward Simplified Shallue-van de Woestijne-Ulas).

Алгоритм SSWU відображає довільний елемент поля `u ∈ F_p` (отриманий прямим гешуванням пароля) у точку еліптичної кривої за сталий час без циклів пошуку:
1. Задається фіксований неквадратний параметр кривої `Z ∈ F_p` (для NIST P-256 `Z = -10`).
2. Обчислюються раціональні функції від `u`:
   ```
   tv1 = (Z² · u⁴ + Z · u²) mod p
   tv2 = 1 / (tv1 + 1) mod p
   x₁ = (-b / a) · (1 + tv2) mod p
   x₂ = -Z · u² · x₁ mod p
   ```
3. Значення `g(x) = x³ + a·x + b` обчислюється для кандидатів `x₁` та `x₂`. Властивість алгебраїчної конструкції гарантує, що рівно одне зі значень `g(x₁)` або `g(x₂)` завжди є квадратичним лишком у `F_p`.
4. Вибір валідної координати та обчислення `y = √(g(x))` виконуються виключно за допомогою бітових масок константного часу, унеможливлюючи витік інформації через процесорні таймінги чи кеш-лінії.

### 3. Фаза 1: Алгебра обміну Commit

Обидві сторони (клієнт `A` та точка доступу `B`) паралельно та незалежно виконують генерацію ефемерних скалярів і маскувальних елементів.

#### Дії клієнта A:
1. Генерує два криптографічно стійких псевдовипадкових скаляри в діапазоні порядку групи:
   ```
   r_A ∈_R [1, q - 1]     (приватний випадковий скаляр)
   m_A ∈_R [1, q - 1]     (приватний маскувальний скаляр)
   ```
2. Обчислює публічний адитивний скаляр:
   ```
   scalar_A = (r_A + m_A) mod q
   ```
3. Обчислює публічний геометричний елемент, замаскований точкою `PWE`:
   ```
   Element_A = -(m_A · PWE) = (q - m_A) · PWE
   ```
4. Перевіряє коректність сформованих значень: `scalar_A > 1`, `scalar_A < q`, а точка `Element_A` належить кривій і не є точкою на нескінченності `O`.
5. **Валідація підгрупи (Subgroup Confinement Check):**
   Оскільки стандартна крива NIST P-256 має кофактор `h = #E(F_p) / q = 1`, група точок є простою і не містить нетривіальних малих підгруп. Якщо протокол реалізується над довільною кривою з кофактором `h > 1` (наприклад, Curve25519, де `h = 8`), станція зобов'язана помножити отриманий елемент на кофактор `h · Element_B ≠ O`, що унеможливлює атаки вкладення в малі підгрупи (Small Subgroup Attacks), за яких зловмисник міг би відновити значення `r_A mod h`.
6. Відправляє у відкритий ефір кадр **`SAE Commit (scalar_A, Element_A)`**.

#### Дії точки доступу B:
1. Генерує власні випадкові скаляри:
   ```
   r_B ∈_R [1, q - 1],   m_B ∈_R [1, q - 1]
   ```
2. Обчислює публічний скаляр та замаскований елемент:
   ```
   scalar_B = (r_B + m_B) mod q
   Element_B = -(m_B · PWE) = (q - m_B) · PWE
   ```
3. Перевіряє діапазон скаляра та геометричну валідність точки `Element_B`.
4. Відправляє у відкритий ефір кадр **`SAE Commit (scalar_B, Element_B)`**.

### 4. Доведення узгодження спільного секрету K

Отримавши публічні повідомлення партнера, обидві сторони розраховують спільну точку на еліптичній кривій — **`K = (K_x, K_y)`**.

#### Розрахунок на боці клієнта A:
Клієнт `A` множить публічний скаляр `scalar_B` на точку `PWE`, додає отриману точку `Element_B` і множить результат на свій приватний скаляр `r_A`:

```
K_A = r_A · (scalar_B · PWE + Element_B)
```

Розкриємо внутрішній вираз за правилами дистрибутивності скалярного множення точок еліптичної кривої:

```
scalar_B · PWE + Element_B
= ((r_B + m_B) mod q) · PWE + (-(m_B · PWE))     [підстановка значень scalar_B та Element_B]
= (r_B · PWE + m_B · PWE) - m_B · PWE            [дистрибутивність множення скаляра на точку]
= r_B · PWE + (m_B · PWE - m_B · PWE)            [асоціативність додавання точок у групі E(F_p)]
= r_B · PWE + O                                  [де O — нейтральний нульовий елемент групи]
= r_B · PWE
```

Підставимо отриманий проміжний вектор у фінальну формулу для `K_A`:
```
K_A = r_A · (r_B · PWE) = (r_A · r_B) · PWE
```

#### Розрахунок на боці точки доступу B:
Точка доступу `B` дзеркально виконує обчислення з використанням свого приватного скаляра `r_B` та отриманих від `A` параметрів:

```
K_B = r_B · (scalar_A · PWE + Element_A)
= r_B · (((r_A + m_A) mod q) · PWE - m_A · PWE)  [підстановка scalar_A та Element_A]
= r_B · (r_A · PWE + m_A · PWE - m_A · PWE)      [дистрибутивність множення скаляра на точку]
= r_B · (r_A · PWE + O)                          [скорочення m_A · PWE - m_A · PWE = O]
= r_B · (r_A · PWE)                              [нейтральний нульовий елемент O]
= (r_B · r_A) · PWE                              [асоціативність множення скалярів]
= (r_A · r_B) · PWE                              [комутативність множення в полі F_q]
```

**Фундаментальний висновок:**
```
K_A = K_B = K = (r_A · r_B) · PWE
```
Обидва пристрої отримали абсолютно ідентичну точку `K` на еліптичній кривій, не передавши через радіоефір жодного відкритого скаляра, пов'язаного з паролем.

32-байтова абсциса `K_x` точки `K = (K_x, K_y)` стає вихідним матеріалом високої ентропії для функції розгортання ключів на базі HKDF (HMAC-based Extract-and-Expand Key Derivation Function, RFC 5869):
```
PRK = HKDF-Extract(Salt = 0²⁵⁶, IKM = K_x)
k = HKDF-Expand(PRK, "SAE Key", 256)
PMK = HKDF-Expand(PRK, "SAE PMK" || min_max_mac, 256)
```

### 5. Покроковий числовий приклад алгебри Dragonfly

Щоб зробити геометричну взаємодію наочною, розглянемо модельну еліптичну криву над малим простим полем `F_23`:
```
y² ≡ x³ + x + 1 (mod 23)
```
Нехай порядок базової підгрупи дорівнює `q = 28`, а пароль після відображення дав точку `PWE = (1, 7)`. Перевіримо належність точки кривій:
```
7² = 49 ≡ 3 (mod 23)
1³ + 1 + 1 = 3 ≡ 3 (mod 23)   [рівність виконується]
```

**Крок 1. Генерація скалярів:**
- Сторона A обирає: приватний `r_A = 5`, маскувальний `m_A = 9`.
- Сторона B обирає: приватний `r_B = 4`, маскувальний `m_B = 11`.

**Крок 2. Обчислення публічних повідомлень Commit:**
- Сторона A:
  ```
  scalar_A = (5 + 9) mod 28 = 14
  Element_A = -(9 · PWE) = (28 - 9) · PWE = 19 · (1, 7)
  ```
- Сторона B:
  ```
  scalar_B = (4 + 11) mod 28 = 15
  Element_B = -(11 · PWE) = (28 - 11) · PWE = 17 · (1, 7)
  ```

**Крок 3. Взаємний обмін та розрахунок спільної точки K:**
- Сторона A обчислює:
  ```
  K_A = 5 · (15 · PWE + 17 · PWE)                [підстановка отриманих scalar_B та Element_B]
      = 5 · ((15 + 17) mod 28 · PWE)             [дистрибутивність групового додавання]
      = 5 · (32 mod 28 · PWE)                    [редукція за модулем порядку групи q = 28]
      = 5 · (4 · PWE)                            [32 mod 28 = 4]
      = 20 · PWE                                 [скалярний добуток: 5 · 4 mod 28 = 20]
  ```
- Сторона B обчислює:
  ```
  K_B = 4 · (14 · PWE + 19 · PWE)                [підстановка отриманих scalar_A та Element_A]
      = 4 · ((14 + 19) mod 28 · PWE)             [дистрибутивність групового додавання]
      = 4 · (33 mod 28 · PWE)                    [редукція за модулем порядку групи q = 28]
      = 4 · (5 · PWE)                            [33 mod 28 = 5]
      = 20 · PWE                                 [скалярний добуток: 4 · 5 mod 28 = 20]
  ```

Обидві сторони отримали спільну кратну точку `K = 20 · PWE`. Перехоплювач бачить в ефірі лише числа `scalar_A = 14`, `scalar_B = 15` та координати точок `19 · PWE` і `17 · PWE`. Без знання приватних скалярів `5` або `4` відновити множник `20` неможливо через складність задачі дискретного логарифма.

### 6. Фаза 2: Взаємна перевірка знання секрету (Confirm)

Щоб переконатися, що протилежна сторона володіє ідентичним паролем і успішно сформувала точку `K`, сторони обмінюються підтверджувальними токенами **`Confirm`**:

```
Confirm_A = HMAC-SHA256(k, send_confirm_A || scalar_A || Element_A || scalar_B || Element_B)
Confirm_B = HMAC-SHA256(k, send_confirm_B || scalar_B || Element_B || scalar_A || Element_A)
```
де `send_confirm` — 16-бітний порядковий лічильник повідомлень підтвердження (запобігає зацикленню повідомлень під час повторної передачі).

Якщо значення `Confirm`, отримане від партнера, збігається з локально розрахованим хешем, вузол фіксує успішну взаємну автентифікацію і переходить до 4-Way Handshake на базі щойно сформованого `PMK`.

### 7. Захист від атак вичерпання ресурсів (Anti-Clogging Token)

Оскільки операція скалярного множення точки на еліптичній кривій вимагає значних обчислювальних витрат процесора (близько 0.5–2 мс на ядро), зловмисник міг би влаштувати атаку на відмову в обслуговуванні (DoS / Clogging Attack), бомбардуючи точку доступу фальшивими кадрами `SAE Commit` із випадковими MAC-адресами.

Для нейтралізації цієї загрози протокол SAE містить вбудований механізм **Anti-Clogging Token (Cookie)**. Коли кількість одночасних відкритих сесій автентифікації на точці доступу перевищує встановлений поріг (зазвичай понад 5–10 напіввідкритих сесій), AP припиняє виконання операцій на кривій і відповідає клієнту спеціальним кадром:
```
Статус: STATUS_ANTI_CLOGGING_TOKEN_REQUIRED
Вміст: Token = HMAC-SHA256(Secret_AP_Key, Client_MAC || Timestamp)
```
Точка доступу не зберігає стан цієї сесії в пам'яті. Клієнт зобов'язаний повторити свій кадр `SAE Commit`, включивши отриманий `Token`. Точка доступу перевіряє валідність HMAC-підпису токена за лічені мікросекунди без використання важкої асиметричної математики і лише після підтвердження реальності клієнтської IP/MAC-адреси виділяє ресурси на розрахунок точки `K`.

### 8. Математичне доведення неможливості офлайн-атаки

Припустимо, що пасивний радіошпигун перехопив у відкритому ефірі всі кадри обміну:
```
Перехоплено: scalar_A, Element_A, scalar_B, Element_B, Confirm_A, Confirm_B
```

Зловмисник формує гіпотезу про пароль: `pwd'`.
1. Атакуючий обчислює кандидатську точку: `PWE' = HashToCurve(pwd')`.
2. Щоб перевірити гіпотезу `pwd'`, нападник намагається використати публічні рівняння зв'язку:
   ```
   Element_A = -(m_A · PWE)
   scalar_A = r_A + m_A
   ```
3. Якщо нападник додасть до перехопленого елемента `Element_A` точку `scalar_A · PWE'`, він отримає:
   ```
   Element_A + scalar_A · PWE' = -(m_A · PWE) + (r_A + m_A) · PWE'
   ```
   - Якщо здогадка правильна (`PWE' = PWE`), результуючий вираз дорівнює:
     ```
     -(m_A · PWE) + r_A · PWE + m_A · PWE = r_A · PWE
     ```
   - Якщо здогадка неправильна (`PWE' ≠ PWE`), вираз є псевдовипадковою комбінацією точок:
     ```
     r_A · PWE' + m_A · (PWE' - PWE)
     ```

4. **Критична проблема атакуючого:**
   Значення `r_A · PWE` є випадковою точкою еліптичної кривої, оскільки скаляр `r_A` був обраний клієнтом випадково та незалежно для цього конкретного сеансу.
   Аналогічно для точки доступу атакуючий може обчислити лише значення `r_B · PWE`.

5. Щоб перевірити збіг кандидатського токена `Confirm_A`, атакуючий зобов'язаний розрахувати спільний секрет:
   ```
   K = r_A · r_B · PWE
   ```
   Маючи лише значення `(r_A · PWE)` та `(r_B · PWE)`, розрахунок точки `(r_A · r_B · PWE)` еквівалентний розв'язанню **обчислювальної задачі Діффі — Геллмана (Computational Diffie-Hellman, CDH)** на еліптичній кривій над базою `PWE`.

Для кривої NIST P-256 задача CDH є обчислювально нерозв'язною за сучасного стану криптоаналізу (її стійкість становить `2¹²⁸` операцій). Отже, перехоплені в ефірі величини не містять жодної математичної надлишковості або алгебраїчного інваріанта, який можна верифікувати локально без розв'язання задачі CDH. Єдиним способом перевірити гіпотезу `pwd'` залишається створення підробленого кадру `SAE Confirm` і надсилання його до точки доступу, що перетворює атаку на повільну онлайн-спробу з жорстким обмеженням частоти запитів.

### 9. Досконала пряма секретність (Perfect Forward Secrecy, PFS)

Властивість досконалої прямої секретності гарантує: навіть якщо довгостроковий спільний пароль `pwd` буде скомпрометовано в майбутньому (наприклад, через витік бази даних чи фізичне вилучення точки доступу), весь раніше записаний та збережений зашифрований радіотрафік залишиться абсолютно недоступним для розшифрування.

Нехай зловмисник у момент часу `t₁` записав повний дамп трафіку сесії, а в момент `t₂ > t₁` дізнався пароль `pwd`.
1. Знаючи `pwd`, атакуючий розраховує точну точку `PWE = HashToCurve(pwd)`.
2. З перехоплених у момент `t₁` кадрів зловмисник обчислює точки `r_A · PWE` та `r_B · PWE`.
3. Однак ефемерні випадкові скаляри `r_A` та `r_B` генерувалися в оперативній пам'яті вузлів на час сесії і були безповоротно знищені одразу після розрахунку сеансового `PMK`.
4. Для відновлення сеансового ключа `K = (r_A · r_B) · PWE` атакуючий знову опиняється перед необхідністю розв'язати задачу CDH для випадкових точок, записаних у минулому.

Знання пароля не допомагає зняти скалярну маску `r_A · r_B`. Цим WPA3 кардинально відрізняється від WPA2-PSK, де знання пароля дозволяло миттєво обчислити статичний `PMK = PBKDF2(pwd, SSID)` і заднім числом розшифрувати терабайти архівів усього бездротового трафіку, коли-небудь зафіксованого перехоплювачем.
