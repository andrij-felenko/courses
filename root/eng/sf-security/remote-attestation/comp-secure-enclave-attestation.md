# 🔌 Порівняння апаратних коренів довіри для віддаленої атестації

Віддалена атестація принципово вимагає наявності апаратного кореня довіри (Root of Trust, RoT) — кремнієвого компонента, чий приватний ключ захищений фізичними бар'єрами, а стан не може бути скомпрометований навіть за умови повного контролю зловмисника над операційною системою хоста. Проте різні класи обчислювальних систем — від серверів датацентрів та мобільних телефонів до вбудованих контролерів і хмарних віртуальних машин — реалізують цей корінь на базі кардинально відмінних архітектурних концепцій.

Вибір апаратної реалізації безпосередньо визначає межі безпеки, стійкість до фізичного доступу, продуктивність криптографічних операцій, вразливість інтерфейсних шин та складність перевірки атестаційного ланцюга віддаленим сервером.

## 1. Дискретний модуль TPM 2.0 (dTPM)

Дискретний TPM являє собою повністю автономну мікросхему на материнській платі, що містить власне процесорне ядро (зазвичай 16- або 32-бітний мікроконтролер із гарвардською архітектурою), апаратні криптографічні прискорювачі, захищену незалежну пам'ять NVRAM та апаратний генератор справжніх випадкових чисел (TRNG).

```
+-------------------------------------------------------------------+
| Головна материнська плата                                          |
|                                                                   |
|  +-------------------------+            +----------------------+  |
|  | Головний процесор (CPU) |            | Дискретний чип dTPM  |  |
|  | x86_64 / ARM64          |            | (Infineon, Nuvoton)  |  |
|  |                         |  Шина SPI  |                      |  |
|  | Драйвер tpm_tis_spi     |<=========>| Регістри PCR (0-23)  |  |
|  +-------------------------+ (Вразлива  | Приватний EK / AK    |  |
|                               до зонду) +----------------------+  |
+-------------------------------------------------------------------+
```

- **Інтерфейс підключення:** Фізична шина SPI (Serial Peripheral Interface), I2C або застаріла шина LPC. Взаємодія з ядром операційної системи здійснюється через стандартні транзакційні регістри FIFO або інтерфейс TIS (TPM Interface Specification).
- **Рівень захисту:** Максимальна фізична ізоляція від основного процесора. Чип виготовляється за стандартами захисту смарт-карт (Common Criteria EAL4+ або EAL5+), оснащується металевими захисними екранами над кристалом (active shield mesh), детекторами зміни напруги живлення, частоти тактування, лазерного опромінення та датчиками температури для запобігання фізичній декапсуляції й мікрозондуванню.
- **Архітектурна вразливість:** Відкрита фізична шина обміну даними. Оскільки доріжки шини SPI проходять по поверхні текстоліту материнської плати, зловмисник із фізичним доступом може встановити апаратний інтерпозер або пружні голчасті зонди. Якщо операційна система надсилає команди розширення регістра PCR або вичитує дані без автентифікації сесії, зловмисник може перехопити транзакції або інжектувати фальшиві байти. Для нейтралізації цієї загрози сучасні стеки TSS2 використовують сесії авторизованого обміну (`TPM2_StartAuthSession` з параметрами HMAC або AES-CFB шифрування каналу зв'язку).
- **Сфера застосування:** Корпоративні сервери, робочі станції, промислові контролери критичної інфраструктури.

## 2. Мікропрограмний TPM (fTPM / Intel PTT / AMD fTPM)

Мікропрограмний TPM не потребує встановлення окремої мікросхеми. Усі функції та структури даних TPM 2.0 реалізовані у формі захищеного програмного модуля, який виконується в ізольованому мікропрограмному середовищі головного процесора платформи — Intel Management Engine (CSME/PTT) або AMD Platform Security Processor (PSP) на базі виділених ядер ARM Cortex-A чи 32-бітних мікроконтролерів.

```
+-------------------------------------------------------------------+
| Процесорний кристал (SoC)                                         |
|                                                                   |
|  +-----------------------------+  +----------------------------+  |
|  | Звичайний світ (Rich OS)    |  | Захищений світ (TEE / PSP) |  |
|  | Linux Kernel, /dev/tpmrm0   |  | fTPM Firmware Applet       |  |
|  |                             |  | Регістри PCR               |  |
|  | Буфер пам'яті CRB           |<| Внутрішні ключі EK / AK    |  |
|  +-----------------------------+  +----------------------------+  |
|  (Взаємодія через спільну пам'ять без зовнішньої фізичної шини)    |
+-------------------------------------------------------------------+
```

- **Інтерфейс підключення:** Command Response Buffer (CRB) — структура керування у системній оперативній пам'яті з підтримкою MMIO-регістрів, що обслуговується драйвером ядра `tpm_crb`.
- **Рівень захисту:** Відсутність зовнішніх фізичних доріжок на материнській платі унеможливлює апаратне перехоплення команд через зондування шини. Довготривалий стан NVRAM та ключі безпеки шифруються апаратним майстер-ключем, зашитим у перемички кристала процесора (Fused Silicon Root Key), і зберігаються в загальній мікросхемі SPI Flash разом із BIOS/UEFI.
- **Архітектурна вразливість:** Оскільки fTPM виконується на процесорному кремнії та ділить пам'ять і кеші з іншими компонентами платформи, він потенційно піддається атакам через вразливості в складному коді прошивки Management Engine, атакам по побічних каналах кешу (Microarchitectural Data Sampling, Spectre) або збоям при оновленні мікрокоду.
- **Сфера застосування:** Масові споживчі ноутбуки, материнські плати для настільних ПК, недорогі офісні станції.

## 3. Спеціалізовані безпекові співпроцесори (Apple SEP, Google Titan, Samsung Knox)

Мобільні екосистеми та глобальні хмарні провайдери створили власні пропрієтарні криптографічні чипи, тісно інтегровані з операційною системою пристрою.

```
+--------------------------------------------------------------------+
| Спеціалізований співпроцесор (наприклад, Apple Secure Enclave)     |
|                                                                    |
|  +--------------------+  +------------------+  +----------------+  |
|  | Безпечне ядро ARM  |  | Апаратний AES-   |  | Апаратний TRNG |  |
|  | Власна L4 мікро-ОС |  | акселератор      |  | Генератор      |  |
|  +--------------------+  +------------------+  +----------------+  |
|  +--------------------------------------------------------------+  |
|  | Захищена пам'ять SRAM з апаратним шифруванням на льоту       |  |
|  +--------------------------------------------------------------+  |
|  (Сертифікація через закритий фабричний ланцюг Apple CA / Google)  |
+--------------------------------------------------------------------+
```

- **Apple Secure Enclave Processor (SEP):** Фізично виділений модуль у кремнії чипів Apple серій A- та M-. Має власне ядро з мікроядерною операційною системою sepos, апаратний блок шифрування пам'яті AES Engine (з унікальним для кожного циклу живлення ключем) та модуль захисту від перебору паролів (Secure Storage Component). Віддалена атестація здійснюється через фреймворк Apple App Attest: SEP генерує асиметричну пару ключів, а хмарні сервери Apple засвідчують твердження про автентичність пристрою за допомогою службових сертифікатів.
- **Google Titan M2 / Titan Silicon:** Власний дискретний чип компанії Google на відкритій архітектурі RISC-V, встановлений у смартфонах Pixel та на серверах інфраструктури Google Cloud. Реалізує апаратний захист від фізичних атак зі збоями тактування (glitching) та забезпечує атестацію через Android KeyStore Key Attestation, видаючи X.509-сертифікат з інкапсульованими даними про стан завантажувача (Locked/Unlocked) та верифіковану версію збірки Android.
- **Samsung Knox Vault:** Відокремлена підсистема з власним процесором, шифрованою пам'яттю та захистом від електромагнітних витоків, що ізолює корені довіри від основного процесора Exynos або Snapdragon.

## 4. Процесорні TEE для конфіденційних обчислень (AMD SEV-SNP, Intel TDX, ARM CCA)

У хмарних середовищах віддалена атестація перемістилася безпосередньо в обчислювальні конвеєри серверних процесорів, де довіра будується не до фізичної машини, а до ізольованого гостьового анклаву чи захищеної віртуальної машини (Confidential VM).

- **AMD SEV-SNP (Secure Encrypted Virtualization-Secure Nested Paging):** Процесор безпеки AMD-SP підписує криптографічний звіт `ATTESTATION_REPORT` за допомогою ключа VCEK (Versioned Chip Endorsement Key), що видається серверами ключів AMD KDS на основі унікального ідентифікатора кристала та поточної версії прошивки (TCB). Звіт фіксує хеш пам'яті віртуальної машини при старті (Measurement Launch Digest) та налаштування політики ізоляції таблиць сторінок.
- **Intel TDX (Trust Domain Extensions):** Спеціальний апаратно-підтримуваний мікрокод процесора (TDX Module) керує створенням доменів довіри. Атестаційний процесорний звіт `TDREPORT` перетворюється спеціальним архітектурним анклавом Quoting Enclave на підписану за допомогою алгоритму ECDSA цитату `TD-Quote`, що перевіряється через сертифікаційні служби Intel PCS.

## Зведена порівняльна матриця характеристик

| Характеристика | Дискретний TPM 2.0 | Мікропрограмний fTPM | Apple SEP / Google Titan | Хмарні TEE (SEV-SNP / TDX) |
| :--- | :--- | :--- | :--- | :--- |
| **Фізичне розташування** | Окремий чип на платі | Всередині CPU TEE / SoC | Окремий блок у SoC / чип | Логіка CPU + криптомодуль |
| **Шина взаємодії** | SPI / I2C (вразлива до перехоплення) | Внутрішня шина пам'яті (CRB) | Захищена внутрішня поштова скринька | Апаратні інструкції CPU |
| **Фізична стійкість** | Дуже висока (Active Shields) | Середня (залежить від SoC) | Висока (Dedicated Silicon) | Середня/Висока (залежить від CPU) |
| **Швидкість криптографії** | Низька (10–50 підписів/сек) | Середня (100–300 підписів/сек) | Висока (апаратні прискорювачі) | Максимальна (нативна швидкість CPU) |
| **Формат звіту** | `TPM2_Quote` (TPMS_ATTEST) | `TPM2_Quote` (TPMS_ATTEST) | CBOR Attestation / X.509 ASN.1 | `ATTESTATION_REPORT` / TD-Quote |
| **Ланцюг довіри** | Сертифікат виробника (EK-Cert) | Сертифікат вендора CPU | Сертифікат Apple / Google Root | Сертифікат AMD / Intel KDS |
| **Відкликання (Revocation)** | Оновлення прошивки TPM через vendor | Оновлення BIOS / AGESA / CSME | Оновлення ОС / OTA прошивки | Оновлення TCB Recovery / Microcode |

Вибір конкретного кремнієвого кореня довіри залежить від моделі загроз: дискретний TPM незамінний там, де необхідний захист від фізичного втручання в пристрій, тоді як процесорні TEE та виділені співпроцесори забезпечують максимальну швидкість та масштабованість для хмарних сервісів і мобільних платформ.
