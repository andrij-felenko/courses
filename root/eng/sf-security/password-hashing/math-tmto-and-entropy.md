# 🧮 Математика захисту паролів: ентропія, часово-просторовий компроміс та модель пам'ятевитратності

Стійкість системи автентифікації на основі паролів описується трьома взаємопов'язаними математичними моделями: ентропією простору секретів, теорією часово-просторових компромісів (TMTO) для попередньо обчислених словників та апаратною оцінкою складності пам'ятевитратних функцій (Area-Time Complexity).

## 1. Ентропія та обсяг простору пошуку паролів

Інформаційна ентропія за Шеноном (від грец. *ἐν* — в і *τροπή* — перетворення) визначає міру невизначеності дискретної випадкової величини `X` з множиною можливих значень `{x₁, x₂, ..., xₙ}` та відповідними ймовірностями `P(xᵢ)`:

```
H(X) = - ∑ P(xᵢ) · log₂(P(xᵢ))      [означення ентропії Шенона в бітах]
```

Якщо пароль довжиною `L` символів вибирається з алфавіту потужністю `K` строго рівномірно (тобто `P(xᵢ) = 1 / Kᴸ` для всіх варіантів), ентропія досягає свого теоретичного максимуму:

```
H_max
= - ∑ (1 / Kᴸ) · log₂(1 / Kᴸ)       [підстановка рівномірного розподілу]
= - Kᴸ · (1 / Kᴸ) · (-log₂(Kᴸ))     [розкриття суми Kᴸ однакових доданків]
= log₂(Kᴸ)                          [скорочення мінусів та коефіцієнтів]
= L · log₂(K)                       [властивість логарифма степеня]
```

Для типових наборів символів потужність алфавіту `K` становить:
* Лише десяткові цифри `[0-9]`: `K = 10`, `log₂(10) ≈ 3.32` біта на символ.
* Латинські літери одного регістру `[a-z]`: `K = 26`, `log₂(26) ≈ 4.70` біта на символ.
* Змішаний регістр `[a-zA-Z]`: `K = 52`, `log₂(52) ≈ 5.70` біта на символ.
* Повний друкований ASCII (літери, цифри, спецсимволи): `K = 95`, `log₂(95) ≈ 6.57` біта на символ.

**Різниця між теоретичним простором і людською поведінкою.**
Повний розмір простору пошуку `|S| = Kᴸ`. Для 8-значного пароля з повного ASCII `|S| = 95⁸ ≈ 6.63 · 10¹⁵` комбінацій (еквівалентно `52.5` біта ентропії).

Однак через передбачуваність людського вибору (словникові слова, заміна літер на схожі цифри `P@ssw0rd`, фіксовані суфікси `123!`) реальна ентропія користувацьких паролів суттєво нижча. Емпірична ентропія типового 8-10 значного людського пароля зазвичай становить усього `18 - 30` бітів (`2¹⁸ ≈ 262 144` до `2³⁰ ≈ 1.07 · 10⁹` реальних спроб).

## 2. Часова складність атаки повного перебору

При відомому геші цільового користувача математичне сподівання кількості спроб для знаходження пароля у просторі `S` при послідовному випадковому переборі становить:

```
E[N_спроб] = |S| / 2                [середня кількість кроків до успіху]
```

Час злому `T_crack` при сумарній швидкості обчислення гешів `R` (гешів за секунду на апаратному кластері зловмисника):

```
T_crack
= E[N_спроб] / R                    [базове відношення обсягу до швидкості]
= |S| / (2 · R)                     [підстановка математичного сподівання]
```

Якщо використовується швидка гешфункція без пам'яті (наприклад, SHA-256), сучасна ферма з 8 відеокарт RTX 4090 генерує `R ≈ 80 · 10⁹` (80 GH/s). Тоді час повного перебору простору `|S| = 2³⁰`:

```
T_crack
= 2³⁰ / (2 · 80 · 10⁹)              [підстановка параметрів]
= 1 073 741 824 / (160 · 10⁹)       [обчислення степеня двійки]
≈ 0.0067 с                          [менше 7 мілісекунд]
```

Для пам'ятевитратної функції Argon2id з конфігурацією 64 МБ пам'яті швидкість однієї відеокарти падає до `R ≈ 30` гешів/с (обмежується пропускною здатністю шини VRAM). Для 8 відеокарт `R_total ≈ 240` гешів/с:

```
T_crack
= 2³⁰ / (2 · 240)                   [підстановка повільного гешування]
= 1 073 741 824 / 480               [ділення на швидкість кластера]
≈ 2 236 962 с                       [переведення в секунди]
≈ 25.88 доби                        [зростання стійкості у 330 мільйонів разів]
```

## 3. Математична модель часово-просторового компромісу (TMTO)

Атака за допомогою веселкових таблиць (Rainbow Tables), узагальнена Мартіном Геллманом (Martin Hellman) та Філіпом Оксліном (Philippe Oechslin), використовує попередньо обчислені ланцюжки редукцій:

```
Password_0  →  [ Hash ]  →  H_0  →  [ Reduce_1 ]  →  Password_1  →  [ Hash ]  →  ...  →  H_k  →  [ Reduce_k ]  →  Password_k
```

Функція редукції `Reduce_i: Hash → S` проєктує довільний геш назад у допустимий простір паролів `S`. У таблиці зберігаються лише початковий елемент `Password_0` та кінцевий `Password_k`.

Для простору розміром `N = |S|` з довжиною ланцюжка `k` та кількістю збережених пар `M` класичне співвідношення Геллмана пов'язує час пошуку `T` та обсяг таблиці `M`:

```
T · M² = O(N²)                      [рівняння кривої компромісу Геллмана]
```

**Руйнування моделі за допомогою криптографічної солі.**
Якщо кожен пароль гешується з унікальною випадковою сіллю `Salt` розрядністю `b` бітів, простір станів розширюється від `N` до `N · 2ᵇ`.

Щоб застосувати попередньо обчислену таблицю до бази з `U` користувачів:
* Без солі: одна таблиця розміром `M` дозволяє миттєво атакувати всі `U` записів за сумарний час `O(U · T)`.
* З унікальною сіллю: кожна сіль створює абсолютно незалежний простір редукцій. Зловмисник змушений будувати окрему веселкову таблицю для кожної унікальної солі. Сумарні витрати пам'яті й часу множаться на кількість користувачів:

```
Cost_total = ∑ Cost(Saltᵢ) = U · O(N)   [сіль перетворює групову атаку на U окремих]
```

При використанні 128-бітної солі (`2¹²⁸ ≈ 3.4 · 10³⁸`) попереднє обчислення стає неможливим фізично: обсяг даних перевищує кількість атомів у спостережуваному Всесвіті.

## 4. Апаратно-економічна модель пам'ятевитратності: площа та час (AT-Complexity)

Колін Персіваль формалізував стійкість криптографічних функцій до спеціалізованих апаратних атак (FPGA/ASIC) через концепцію складності за площею кристала та часом обчислення (Area-Time complexity).

Вартість створення спеціалізованого кремнієвого чипа визначається двома фізичними факторами:
1. `A` (*Silicon Area*) — фізична площа напівпровідникового кристала, необхідна для розміщення обчислювальних ядер і внутрішньої пам'яті (SRAM/DRAM).
2. `T` (*Execution Time*) — час, необхідний для обчислення одного гешу.

Для традиційних ітеративних алгоритмів (наприклад, PBKDF2 з 100 000 ітерацій SHA-256):
* Стан алгоритму займає `A_core ≈ 0.05 мм²` кремнію (регістри та логіка SHA-256).
* На одному кремнієвому кристалі площею `200 мм²` розробник ASIC розміщує до `4000` паралельних обчислювальних ядер.
* Сумарна вартість обчислення одного гешу: `Cost_ASIC ∝ A · T`. Оскільки `A` мінімальне, вартість перебору для зловмисника мізерна.

Для пам'ятевитратних функцій (Argon2id, scrypt):
* Алгоритм вимагає виділення масиву пам'яті розміром `M` (наприклад, 64 МБ).
* 1 МБ вбудованої пам'яті SRAM на сучасному техпроцесі займає близько `0.5 мм²` площі кристала.
* Відповідно, одне обчислювальне ядро Argon2id з 64 МБ внутрішньої пам'яті вимагає:

```
A_core
= A_logic + M · A_SRAM              [сума площі логіки та площі пам'яті]
= 0.05 мм² + 64 · 0.5 мм²           [підстановка параметрів пам'яті]
= 0.05 мм² + 32.0 мм²               [обчислення добутку]
= 32.05 мм²                         [зростання площі ядра в 640 разів]
```

На тому самому кристалі площею `200 мм²` замість 4000 ядер тепер поміщається лише `200 / 32.05 ≈ 6` паралельних ядер.

Якщо зловмисник намагається зменшити площу кристала `A` у `k` разів, відмовившись від зберігання частини проміжних блоків, йому доводиться повторно обчислювати відсутні блоки щоразу, коли алгоритм випадково звертається до них. Для послідовно-пам'ятевитратних графів це збільшує час обчислення `T` пропорційно `k²`.

Метрика стійкості до апаратних атак виражається через квадратичну складність `AT²`:

```
Metric = A · T²                     [криптографічна метрика незмінності витрат]
```

Оскільки `A_new = A / k`, а `T_new = T · k²`:

```
Metric_new
= (A / k) · (T · k²)²               [підстановка стиснутої пам'яті]
= (A / k) · (T² · k⁴)               [піднесення до квадрата]
= A · T² · k³                       [скорочення k]
= Metric_orig · k³                  [кубічне зростання сумарних енергетичних витрат]
```

## 5. Дискретна модель адресації та індексації блоків в Argon2

Масив пам'яті в алгоритмі Argon2 (RFC 9106) розбивається на `p` смуг (*lanes*), кожна з яких містить `q = m' / p` блоків розміром по 1024 байти (де `m'` — скоригований розмір пам'яті, округлений до кратного `4p` значення).

Весь процес обчислення ділиться на `t` часових ітерацій (проходів), а кожна ітерація розбивається на 4 синхронізаційні скибки (*slices*), `S ∈ {0, 1, 2, 3}`. Кожен сегмент смуги всередині скибки має довжину:

```
L_segment = q / 4                   [довжина сегмента в блоках пам'яті]
```

Для обчислення блоку `B[i][j]` (де `i` — індекс смуги, `j` — індекс блоку всередині смуги) алгоритм вибирає референтний блок `B[l][z]`. 

У режимі **Argon2d** індекс референтного блоку обчислюється напряму з молодших 64 бітів попереднього блоку `B[i][j-1]`:

```
J₁ = B[i][j-1][0] mod 2³²           [перші 32 біти для вибору смуги]
J₂ = B[i][j-1][1] mod 2³²           [наступні 32 біти для вибору блоку]
```

Індекс цільової смуги `l`:

```
l = J₁ mod p                        [якщо перша скибка першого проходу, l = i]
```

Індекс блоку `z` вибирається всередині множини доступних блоків `R` розміром `|R|`. Відображення псевдовипадкового 32-бітного числа `J₂` на інтервал `[0, |R|)` виконується за схемою нелінійного масштабування:

```
x = (J₂)² / 2³²                     [нелінійне піднесення до квадрата]
y = (|R| · x) / 2³²                 [масштабування на розмір множини доступних блоків]
z = |R| - 1 - y                     [зміщення від найсвіжіших блоків]
```

Нелінійне перетворення `(J₂)²` надає статистичну перевагу нещодавно записаним блокам. Це максимізує ймовірність того, що референтний блок уже витіснено з кешу L1/L2 до повільнішої основної оперативної пам'яті (DRAM), що змушує апаратний прискорювач постійно очікувати відповіді від шини пам'яті та унеможливлює приховування затримок читання через конвеєризацію.
