# 📋 Довідник інтерфейсів та форматів: PHC, Argon2 (RFC 9106) та bcrypt

Цей довідник містить технічну специфікацію стандартного рядкового формату PHC (Password Hashing Competition), повний перелік параметрів та кодів помилок алгоритму Argon2 згідно з RFC 9106, структуру модульного формату bcrypt, а також матрицю рекомендованих параметрів для різних апаратних середовищ.

## 1. Специфікація рядкового формату PHC (PHC String Format)

Формат PHC є загальноприйнятим відкритим стандартом для серіалізації гешів паролів у текстовому вигляді. Він дозволяє зберігати назву алгоритму, версію, конфігураційні параметри, сіль та підсумковий геш в одному самодостатньому рядку. Це усуває потребу зберігати параметри гешування (кількість ітерацій, обсяг пам'яті, сіль) в окремих стовпцях реляційної бази даних.

### Загальна граматика та правила синтаксичного аналізу

Рядок формату PHC будується за наступною формальною структурою:

```
$<id>[$v=<version>][$<param>=<val>(,<param>=<val>)*][$<salt>[$<hash>]]
```

Парсер рядка PHC обробляє компоненти як послідовність полів, розділених символом долара `$`. Кожне поле має суворі семантичні обмеження:

1. **Ідентифікатор алгоритму (`<id>`):** Перше поле після початкового символу `$`. Містить назву алгоритму виключно малими латинськими літерами, цифрами та дефісом `[a-z0-9-]`. Будь-які пробіли чи інші символи вважаються синтаксичною помилкою. Приклади валідних ідентифікаторів: `argon2id`, `argon2d`, `argon2i`, `scrypt`, `pbkdf2-sha256`.
2. **Версія алгоритму (`$v=<version>`):** Опціональне, але настійно рекомендоване поле. Вказує версію внутрішньої специфікації. Для актуального стандарту Argon2 v1.3 версія записується як `v=19` (десятковий еквівалент шістнадцяткового `0x13`). Якщо поле відсутнє, реалізація за замовчуванням застосовує найстарішу базову версію стандарту.
3. **Параметри вартості (`$<param>=<val>,...`):** Список пар «ключ=значення», розділених комами. Імена параметрів складаються з малих літер `[a-z]`, а значення — виключно з десяткових цілих чисел без знака. Для Argon2 обов'язковими є три параметри: `m` (пам'ять у КіБ), `t` (кількість ітерацій) та `p` (ступінь паралелізму).
4. **Криптографічна сіль (`$<salt>`):** Випадковий вектор байтів, закодований у форматі B64-RAW (стандартний Base64 за RFC 4648, з якого видалено завершальні символи вирівнювання `=`). Довжина солі повинна становити щонайменше 16 байтів (22 символи в кодуванні Base64).
5. **Фінальний геш (`$<hash>`):** Результуючий криптографічний тег, також закодований у B64-RAW.

### Приклад валідного рядка Argon2id

```
$argon2id$v=19$m=65536,t=3,p=4$c29tZXNhbHQxMjM0NTY3OA$9sNk8bZ3y9Y9HqQ6h4xL3K5rJ8vW2mN1bV7cX0zP4lE
```

| Компонент | Значення | Опис |
| :--- | :--- | :--- |
| `id` | `argon2id` | Гібридний режим алгоритму Argon2 |
| `v` | `19` | Версія специфікації v1.3 (0x13) |
| `m` | `65536` | Виділення оперативної пам'яті: 65536 КіБ (64 МіБ) |
| `t` | `3` | Кількість ітерацій (проходів по пам'яті): 3 |
| `p` | `4` | Ступінь паралелізму: 4 незалежні смуги / потоки |
| `salt` | `c29tZXNhbHQx...` | 16 байтів солі в кодуванні B64-RAW |
| `hash` | `9sNk8bZ3y9Y9...` | 32 байти фінального гешу в B64-RAW |

## 2. Параметри та коди повернення Argon2 (RFC 9106)

Алгоритм Argon2 приймає набір конфігураційних параметрів, які точно задають часові, просторові та апаратні обмеження обчислення.

### Конфігураційні параметри

* **Пам'ять (`m` — Memory Cost):** Задає розмір оперативної пам'яті в кілобайтах (1 КіБ = 1024 байти), яка виділяється під внутрішню матрицю блоків. Пам'ять розбивається на `p` смуг, кожна з яких містить `m / p` блоків по 1024 байти. Значення повинно бути не меншим за `8 · p` КіБ. Рекомендований стандарт для сучасних серверів — від `65536` (64 МіБ) до `131072` (128 МіБ).
* **Час (`t` — Time Cost):** Кількість повних проходів по збудованій матриці пам'яті. Перший прохід ініціалізує та заповнює блоки, наступні `t - 1` проходів перезаписують блоки псевдовипадковими комбінаціями попередніх значень. Збільшення `t` лінійно збільшує час виконання, не змінюючи вимог до RAM. Для режиму `argon2id` безпечним мінімумом вважається `t = 3` (або `t = 1` при виділенні понад 2 ГБ оперативної пам'яті).
* **Паралелізм (`p` — Parallelism):** Кількість незалежних обчислювальних смуг (*lanes*). Під час кожного проходу алгоритм може обчислювати `p` смуг паралельно в окремих системних потоках виконання (POSIX threads). Зазвичай встановлюється рівним кількості доступних апаратних ядер процесора (наприклад, 2, 4 або 8).
* **Довжина тегу (`T` — Tag Length):** Розмір результуючого бінарного гешу в байтах. Стандартний розмір становить 32 байти (256 бітів), що повністю виключає будь-яку ймовірність випадкових колізій.
* **Сіль (`S` — Salt):** Псевдовипадковий бінарний вектор довжиною щонайменше 16 байтів (128 бітів), згенерований криптографічно стійким генератором (CSPRNG, `/dev/urandom` або `getrandom()`).
* **Секретний ключ (`K` — Secret / Pepper):** Опціональний серверний таємний ключ довжиною до 32 байтів. Додається на етапі початкового гешування блоків H0 і забезпечує захист бази даних у разі витоку дампу без доступу до ключів конфігурації.
* **Асоційовані дані (`X` — Associated Data):** Опціональні відкриті контекстні метадані (наприклад, ідентифікатор домену чи версія схеми автентифікації), які жорстко прив'язують геш до конкретного контексту застосування.

| Параметр | Позначення у PHC | Одиниця | Допустимий діапазон | Рекомендований мінімум |
| :--- | :--- | :--- | :--- | :--- |
| **Memory Cost** | `m` | КіБ | `8 · p` ... `2³² - 1` | `65536` (64 МіБ) |
| **Time Cost** | `t` | Ітерації | `1` ... `2³² - 1` | `3` |
| **Parallelism** | `p` | Потоки | `1` ... `2²⁴ - 1` | `4` (або `N_cores`) |
| **Tag Length** | `T` | Байти | `4` ... `2³² - 1` | `32` байти |
| **Salt Length** | `S` | Байти | `8` ... `2³² - 1` | `16` байтів |
| **Secret (Key)** | `K` | Байти | `0` ... `2³² - 1` | `32` байти (опціонально) |
| **Associated Data** | `X` | Байти | `0` ... `2³² - 1` | Довільно (опціонально) |

### Коди помилок еталонної бібліотеки libargon2

Під час виклику функцій `argon2_hash` або `argon2_verify` бібліотека повертає числові статус-коди. Додаток зобов'язаний аналізувати їх для запобігання прихованим відмовам захисту:

| Код константи | Число | Причина виникнення та інженерна дія |
| :--- | :--- | :--- |
| `ARGON2_OK` | `0` | Успішне виконання операції. |
| `ARGON2_OUTPUT_PTR_NULL` | `-1` | Покажчик на вихідний буфер не ініціалізовано. Помилка виділення пам'яті в додатку. |
| `ARGON2_OUTPUT_TOO_SHORT` | `-2` | Запитана довжина гешу `T < 4`. Неприпустимо малий розмір тегу. |
| `ARGON2_OUTPUT_TOO_LONG` | `-3` | Запитана довжина гешу `T > 2³² - 1`. Переповнення розміру буфера. |
| `ARGON2_PWD_TOO_SHORT` | `-4` | Покажчик на пароль є `NULL`. Некоректний виклик API. |
| `ARGON2_PWD_TOO_LONG` | `-5` | Довжина пароля перевищує максимально допустиму межу. |
| `ARGON2_SALT_TOO_SHORT` | `-6` | Довжина солі менша за 8 байтів. Сіль занадто коротка для захисту від колізій. |
| `ARGON2_SALT_TOO_LONG` | `-7` | Довжина солі перевищує допустиму межу. |
| `ARGON2_TIME_TOO_SMALL` | `-12` | Кількість ітерацій `t < 1`. Потрібно щонайменше один прохід. |
| `ARGON2_MEMORY_TOO_LITTLE` | `-14` | Пам'ять `m < 8 · p`. Недостатньо пам'яті для створення мінімальної матриці смуг. |
| `ARGON2_LANES_TOO_FEW` | `-16` | Ступінь паралелізму `p < 1`. Необхідно мати хоча б одну смугу. |
| `ARGON2_MEMORY_ALLOCATION_ERROR` | `-21` | Операційна система відхилила запит `malloc` (ENOMEM). Необхідно знизити ліміт пам'яті або додати swap. |
| `ARGON2_DECODING_FAIL` | `-31` | Вхідний рядок PHC пошкоджено або він містить некоректні символи Base64. |
| `ARGON2_VERIFY_MISMATCH` | `-32` | Пароль не відповідає збереженому гешу (помилка автентифікації). |

## 3. Специфікація модульного формату bcrypt

Алгоритм `bcrypt` використовує історичний модульний формат (Modular Crypt Format, MCF), що складається з фіксованих секцій, розділених символом долара `$`.

### Структура рядка bcrypt

```
$<prefix>$<cost>$<salt_and_hash_radix64>
```

```
$2b$12$R9h/cIPz0gi.URNNX3kh2OPST9/PgBkqquzi.Ss7KIUgO2t0jWMUW
```

### Розбір префіксів та версій bcrypt

* `$2$` — оригінальна версія bcrypt з OpenBSD (1999). Містила баг у реалізації обробки завершального нуля рядка.
* `$2a$` — виправлена версія, що набула масового поширення. Проте деякі бібліотеки (зокрема на базі crypt_blowfish) некоректно обробляли довгі паролі, що призводило до багів із переповненням буфера.
* `$2y$` — специфічний префікс бібліотеки crypt_blowfish у PHP для позначення виправлення бага коректної обробки 8-бітних символів.
* `$2b$` — сучасний канонічний стандарт версії bcrypt (з 2014 року в OpenBSD), який усунув усі попередні розбіжності між реалізаціями та є обов'язковим для нових систем.

### Особливості кодування Radix-64

На відміну від стандартного RFC 4648 Base64, алгоритм bcrypt використовує власну нетипову таблицю кодування Radix-64:
* Порядок символів: `./ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789`.
* Перші 22 символи рядка кодують 128 бітів солі (16 байтів).
* Наступні 31 символ кодують 184 біти внутрішнього шифротексту Blowfish, отриманого в результаті 64-кратного шифрування константного рядка `"OrpheanBeholderScryDoubt"`.

## 4. Матриця калібрування параметрів та методика вимірювання

Вибір параметрів гешування — це пошук балансу між максимальною стійкістю до атак зловмисника та допустимим навантаженням на сервери автентифікації. Загальне правило криптографічної інженерії: **час перевірки одного пароля на цільовому сервері повинен становити від 50 до 250 мілісекунд**.

### Методика калібрування на цільовому обладнанні

1. На цільовому сервері запускається мікробенчмарк із фіксованим виділенням пам'яті (наприклад, `m = 65536` КіБ) та ступенем паралелізму `p = N_cores`.
2. Вимірюється середній час виконання при різних значеннях ітерацій `t ∈ {1, 2, 3, 4, 5}` під реалістичним фоновим навантаженням CPU.
3. Якщо час менший за 50 мс — спочатку подвоюють виділення пам'яті `m` (наприклад, до 131072 КіБ), доки дозволяє бюджет RAM.
4. Якщо бюджет пам'яті вичерпано, збільшують кількість ітерацій `t`.

| Профіль розгортання | Алгоритм | Пам'ять (`m`) | Ітерації (`t`) | Потоки (`p`) | Очікуваний час | Цільове призначення |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Dedicated Auth Server** (Висока безпека) | Argon2id | 65536 КіБ (64 МіБ) | 3 | 4 | ~120 мс | Окремий сервіс авторизації (IdP, Keycloak, OAuth backend). |
| **Interactive Web API** (Стандартний VM) | Argon2id | 32768 КіБ (32 МіБ) | 2 | 2 | ~60 мс | Монолітні або мікросервісні веб-додатки (Node.js, Go, Python). |
| **Serverless / Lambda** (Обмежена RAM) | Argon2id | 16384 КіБ (16 МіБ) | 4 | 1 | ~75 мс | AWS Lambda, Cloudflare Workers, контейнери з лімітом RAM ≤ 128 МБ. |
| **Legacy Compatibility** (Тільки CPU) | bcrypt | 4 КіБ (внутрішня) | cost = 12 (`2¹² = 4096`) | 1 | ~100 мс | Системи без підтримки Argon2 (старі версії Django, Spring Security). |
| **Embedded / IoT Node** (MCU / мікроконтролери) | PBKDF2-HMAC-SHA256 | ~1 КіБ | 100 000 | 1 | ~150 мс | Обладнання з пам'яттю RAM < 16 МіБ, де виділення масивів Argon2 неможливе. |
