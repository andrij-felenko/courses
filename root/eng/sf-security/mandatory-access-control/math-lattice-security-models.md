# 🧮 Алгебраїчна модель ґратки та інформаційних потоків Деннінг у моделях Bell-LaPadula і Biba

Формальне доведення безпеки обов'язкового контролю доступу опирається на алгебраїчну теорію ґраток (англ. *lattice theory*), запропоновану американською дослідницею Дороті Деннінг у 1976 році. Ця математична структура дозволяє формалізувати поняття інформаційного потоку між різними рівнями таємності й довіри, а також суворо довести неможливість несанкціонованого витоку або спотворення даних.

Нижче наведено формальну алгебраїчну побудову міток безпеки, операцій над ними та математичні доведення безпеки моделей Белла — ЛаПадули і Біби.

---

### 1. Аксіоматика системи захищених інформаційних потоків

За моделлю Деннінг, система інформаційних потоків визначається кортежем:

```
FlowSystem = (SC, ->, ⊕, C_low)
```

де:
1. `SC` — скінченна множина класів (міток) безпеки;
2. `->` — бінарне відношення дозволеного потоку інформації на `SC` (`A -> B` означає, що інформація з класу `A` може законно перетікати в клас `B`);
3. `⊕` — комутативна та асоціативна бінарна операція об'єднання класів (join), що визначає клас безпеки результату комбінування інформації з двох різних джерел;
4. `C_low` — найнижчий клас безпеки в системі (відповідає загальнодоступній інформації).

Щоб система інформаційних потоків була безпечною та несуперечливою, відношення `->` повинно бути частковим порядком (reflexive, antisymmetric, transitive). Разом з операцією `⊕` це перетворює множину `SC` на напівґратку або повну ґратку.

---

### 2. Алгебраїчна структура міток багаторівневого захисту (MLS)

У практичних системах обов'язкового доступу кожен клас безпеки є комбінацією двох незалежних просторів:

```
Label = (H, C)
```

де:
- `H` — лінійно впорядкована множина рівнів чутливості (наприклад, `H = {L0, L1, ..., Ln-1}`, де `L0 = Unclassified < L1 = Confidential < L2 = Secret < L3 = Top Secret`);
- `C ⊆ K` — підмножина категорій із загальної множини тематичних напрямків `K = {k1, k2, ..., km}` (наприклад, `K = {Crypto, Nuclear, NATO}`).

Множина всіх можливих категоріальних наборів є булеаном `P(K)` потужністю `2^|K|`. Відповідно, повний простір міток безпеки є прямим декартовим добутком:

```
SC = H × P(K)
```

### 3. Відношення домінування як частковий порядок

На множині `SC` задається бінарне відношення **домінування** (позначається як `dom` або `>=`):

```
(H1, C1) dom (H2, C2) <=> (H1 >= H2) ∧ (C1 ⊇ C2)
```

Інтуїтивний зміст: клас `(H1, C1)` домінує над `(H2, C2)`, якщо його рівень чутливості не нижчий, а набір категорій містить усі категорії другого класу (тобто суб'єкт володіє достатнім грифом і всіма необхідними категоріальними допусками).

Перевіримо виконання трьох аксіом часткового порядку для відношення `dom`:

```
1. Рефлексивність:
   (H, C) dom (H, C)                                          [бо H >= H у лінійному порядку та C ⊇ C у теорії множин]

2. Антисиметричність:
   [(H1, C1) dom (H2, C2)] ∧ [(H2, C2) dom (H1, C1)]
   => (H1 >= H2 ∧ H2 >= H1) ∧ (C1 ⊇ C2 ∧ C2 ⊇ C1)            [за означенням домінування]
   => (H1 = H2) ∧ (C1 = C2)                                   [за властивостями числових нерівностей та рівності множин]
   => (H1, C1) = (H2, C2)

3. Транзитивність:
   [(H1, C1) dom (H2, C2)] ∧ [(H2, C2) dom (H3, C3)]
   => (H1 >= H2 >= H3) ∧ (C1 ⊇ C2 ⊇ C3)                       [за означенням домінування]
   => (H1 >= H3) ∧ (C1 ⊇ C3)                                  [за транзитивністю нерівностей та включення множин]
   => (H1, C1) dom (H3, C3)
```

Отже, пара `(SC, dom)` є частково впорядкованою множиною (poset).

### 4. Точні межі: операції Join (∨) та Meet (∧)

Для довільної пари класів `A = (Ha, Ca)` та `B = (Hb, Cb)` визначено точні межі:

1. **Найменша верхня межа (Least Upper Bound / Join, ∨):** мінімальний безпековий рівень, необхідний для роботи з об'єднаними даними з обох джерел:
```
A ∨ B = (max(Ha, Hb), Ca ∪ Cb)
```

2. **Найбільша нижня межа (Greatest Lower Bound / Meet, ∧):** максимальний безпековий рівень, спільний для обох класів:
```
A ∧ B = (min(Ha, Hb), Ca ∩ Cb)
```

У системі існують унікальні граничні елементи:
- **Глобальний мінімум (Bottom, ⊥):** `bot = (L0, ∅)` — відкрита інформація без обмежень;
- **Глобальний максимум (Top, ⊤):** `top = (Ln-1, K)` — найвища таємність з усіма категоріями.

Оскільки кожна підмножина елементів `SC` має точні верхню та нижню межі, алгебраїчна система `(SC, dom, ∨, ∧, bot, top)` утворює **повну обмежену ґратку** (англ. *complete bounded lattice*).

### 5. Формалізація моделі Bell-LaPadula (Конфіденційність)

Модель Белла — ЛаПадули моделює захищену обчислювальну систему як скінченний автомат переходів станів.

Стан системи визначається кортежем:
```
v = (b, M, f)
```
де:
- `b ⊆ S × O × {read, write, append, execute}` — множина активних доступів між суб'єктами `S` та об'єктами `O`;
- `M: S × O -> P({read, write, append, execute})` — матриця дискреційного доступу;
- `f = (fs, fo, fc)` — функції призначення міток безпеки:
  - `fs: S -> SC` — максимальний рівень допуску суб'єкта;
  - `fo: O -> SC` — фіксований рівень таємності об'єкта;
  - `fc: S -> SC` — поточний активний рівень суб'єкта (`fs(s) dom fc(s)`).

#### Аксіоми безпечного стану Bell-LaPadula

1. **Властивість простої безпеки (Simple Security Property / «No Read Up»):**
   Суб'єкт `s` може читати об'єкт `o` тільки тоді, коли його максимальний допуск домінує над рівнем об'єкта:
```
∀ (s, o, access) ∈ b, access ∈ {read, execute} => fs(s) dom fo(o)
```

2. **Властивість зірочки (*-Property / «No Write Down»):**
   Суб'єкт `s`, який має активний доступ до читання або запису, може записувати інформацію в об'єкт `o` тільки тоді, коли рівень таємності об'єкта домінує над поточним рівнем суб'єкта:
```
∀ (s, o, write) ∈ b => fo(o) dom fc(s)
∀ (s, o, append) ∈ b => fo(o) dom fc(s)
```
   Якщо суб'єкт одночасно читає об'єкт `o1` та пише в об'єкт `o2`, то `fo(o2) dom fo(o1)`.

### 6. Доведення базової теореми безпеки (Basic Security Theorem)

Базова теорема безпеки (BST) стверджує: якщо початковий стан системи є безпечним, а кожне правило переходу стану зберігає властивості Simple Security та *-Property, то будь-який досяжний стан системи є абсолютно безпечним.

```
Доведення методом математичної індукції:

База індукції:
  Початковий стан v0 при ініціалізації системи має b0 = ∅ (немає активних сесій).
  Оскільки b0 порожня, квантори загальності ∀ виконуються тривіально.
  Стан v0 є безпечним за означенням.

Індукційне припущення:
  Нехай стан vk після k переходів є безпечним.

Індукційний перехід:
  Розглянемо дію оператора переходу T: vk -> vk+1 під впливом запиту req від суб'єкта s на об'єкт o:

  Випадок 1: req = get_read(s, o)
    Монітор звернень перевіряє умову: fs(s) dom fo(o).
    Якщо умова виконується:
      bk+1 = bk ∪ {(s, o, read)}.
      Новий елемент задовольняє умову Simple Security.
      Усі попередні елементи з bk безпечні за індукційним припущенням.
      Стан vk+1 є безпечним.
    Якщо умова не виконується:
      bk+1 = bk (запит відхилено). Стан не змінюється, vk+1 є безпечним.

  Випадок 2: req = get_write(s, o)
    Монітор звернень перевіряє умову: fo(o) dom fc(s).
    Якщо умова виконується:
      bk+1 = bk ∪ {(s, o, write)}.
      Новий елемент задовольняє умову *-Property.
      Стан vk+1 є безпечним.
    Якщо умова не виконується:
      bk+1 = bk. Стан vk+1 є безпечним.

  Випадок 3: req = release(s, o)
    bk+1 = bk \ {(s, o, access)}.
    Видалення кортежу не може порушити жодної з аксіом безпеки.
    Стан vk+1 є безпечним.

Висновок:
  Будь-який стан vn, досяжний за n кроків, є безпечним. Інформаційний витік неможливий.
```

### 7. Дуальність моделі Biba та конфлікт вимог

Модель цілісності Біби (1977) використовує аналогічну ґраткову структуру `(I, <=)`, де `I` — множина рівнів цілісності (довіри).

Правила Біби є точним дзеркальним відображенням правил Белла — ЛаПадули:

1. **Властивість простої цілісності (Simple Integrity Property / «No Read Down»):**
```
∀ (s, o, read) ∈ b => I(s) <= I(o)
```
Суб'єкт може читати лише об'єкти з рівнем цілісності не нижчим за власний, щоб не спотворити свій внутрішній стан неперевіреними даними.

2. **Властивість *-цілісності (*-Integrity Property / «No Write Up»):**
```
∀ (s, o, write) ∈ b => I(s) >= I(o)
```
Суб'єкт може записувати інформацію лише в об'єкти з рівнем цілісності не вищим за власний, щоб ненадійний процес не міг пошкодити критичні системні структури.

#### Теорема про звуження потоків при одночасному застосуванні

Якщо спробувати одночасно реалізувати вимоги Bell-LaPadula (для захисту таємниці) та Biba (для захисту цілісності) в межах однієї шкали міток безпеки, де `L(x) = I(x)`, ми отримуємо систему нерівностей:

Для читання:
```
[BLP: L(s) >= L(o)]  ∧  [Biba: L(s) <= L(o)]  =>  L(s) = L(o)
```

Для запису:
```
[BLP: L(s) <= L(o)]  ∧  [Biba: L(s) >= L(o)]  =>  L(s) = L(o)
```

Це доводить фундаментальний висновок комп'ютерної безпеки: **одночасна вимога абсолютної конфіденційності та абсолютної цілісності в єдиній ієрархії рівнів повністю блокує міжрівневий обмін інформацією**, дозволяючи взаємодію виключно між суб'єктами та об'єктами з абсолютно ідентичними мітками безпеки. 

Саме тому сучасні системи (зокрема SELinux) розділяють ці задачі: для конфіденційності використовується багаторівневий MLS, а для контролю цілісності та ізоляції процесів — ортогональна модель примусового застосування типів (Type Enforcement).
