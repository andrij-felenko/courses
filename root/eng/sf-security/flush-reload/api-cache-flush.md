# 📋 Специфікація апаратних інструкцій керування кешем та таймерами

Точне вимірювання затримок пам'яті та керування станом ліній кешу вимагає безпосередньої взаємодії з апаратурою на рівні системи команд (ISA). Нижче наведено детальний опис інструкцій витіснення кешу, бар'єрів серіалізації конвеєра та лічильників тактів для мікропроцесорних архітектур x86-64, ARMv8-A (AArch64) та RISC-V.

### Архітектура x86-64: інструкції кешу та вимірювання часу

Архітектура x86-64 надає повний набір непривілейованих інструкцій для прямого скидання ліній кешу, запису брудних даних та зчитування високоточних позначок часу з апаратного лічильника процесора.

| Інструкція | Опкод | Рівень привілеїв | Дія над кеш-лінією | Вплив на конвеєр та пам'ять |
| :--- | :--- | :--- | :--- | :--- |
| `CLFLUSH` | `0F AE /7` | Ring 3 (користувач) | Витісняє з L1, L2, L3; скидає брудні дані в RAM | Строго серіалізована відносно інших звернень до пам'яті |
| `CLFLUSHOPT` | `66 0F AE /7` | Ring 3 (користувач) | Витісняє з L1, L2, L3; скидає брудні дані в RAM | Слабковпорядкована (дозволяє паралельні скидання різних ліній) |
| `CLWB` | `66 0F AE /6` | Ring 3 (користувач) | Записує брудні дані в RAM без обов'язкового витіснення | Слабковпорядкована; зберігає лінію в кеші |
| `CLDEMOTE` | `0F 1C /0` | Ring 3 (користувач) | Знижує пріоритет лінії: переміщує з L1/L2 у кеш L3 | Підказка апаратурі; не блокує конвеєр |
| `RDTSC` | `0F 31` | Ring 3 (за `CR4.TSD=0`) | Не чіпає кеш; читає 64-бітний TSC у `EDX:EAX` | **Несеріалізована** (може виконуватися позачергово!) |
| `RDTSCP` | `0F 01 F9` | Ring 3 (за `CR4.TSD=0`) | Читає TSC у `EDX:EAX` та ідентифікатор ядра в `ECX` | Чекає завершення всіх попередніх команд (але не наступних) |
| `LFENCE` | `0F AE E8` | Ring 3 (користувач) | Не чіпає кеш | Бар'єр завантаження: чекає завершення читання перед стартом наступних дій |
| `MFENCE` | `0F AE F0` | Ring 3 (користувач) | Не чіпає кеш | Повний бар'єр пам'яті: серіалізує всі операції Load і Store |
| `SFENCE` | `0F AE F8` | Ring 3 (користувач) | Не чіпає кеш | Бар'єр збереження: серіалізує всі операції Store та `CLFLUSHOPT` |
| `CPUID` | `0F A2` | Ring 3 (користувач) | Не чіпає кеш | Повна апаратна серіалізація конвеєра (скидає спекуляцію) |

#### Мікроархітектурна поведінка `CLFLUSH` та `CLFLUSHOPT`

Інструкція `CLFLUSH` приймає ефективну віртуальну адресу пам'яті, обчислює відповідну 64-байтну лінію кешу та ініціює широкомовне повідомлення на внутрішній шині когерентності (протокол MESI/MOESI). Якщо лінія містить незбережені модифіковані дані (стан Modified), контролер кешу виконує зворотний запис у пам'ять (Write-Back) перед інвалідацією. Оскільки `CLFLUSH` серіалізується відносно всіх попередніх і наступних звернень до пам'яті в межах одного ядра, її пропускна здатність обмежена: процесор чекає підтвердження від шини когерентності перед виконанням наступних звернень.

Інструкція `CLFLUSHOPT` (Optimized Cache Line Flush) була введена в мікроархітектурі Intel Skylake для високопродуктивного очищення великих масивів. На відміну від базової `CLFLUSH`, вона є слабковпорядкованою (Weakly Ordered). Це означає, що кілька послідовних інструкцій `CLFLUSHOPT`, які звертаються до різних кеш-ліній, можуть виконуватися контролером пам'яті паралельно. Для гарантування порядку між скиданнями ліній та звичайними записами обов'язково застосовують бар'єр `SFENCE` або `MFENCE`.

```
Скидання масиву за допомогою CLFLUSHOPT:
for (size_t i = 0; i < N; i += 64) {
    _mm_clflushopt(&array[i]); // виконуються паралельно
}
_mm_sfence(); // очікування завершення всіх скидань
```

#### Інструкції витіснення нового покоління: `CLWB` та `CLDEMOTE`

* **`CLWB` (Cache Line Write Back):** призначена для систем із постійною енергонезалежною пам'яттю (NVDIMM/PMEM). Інструкція примусово записує брудну лінію з кешу в енергонезалежний контролер пам'яті, проте **залишає лінію валідною в кеші L1/L2/L3**. Це запобігає затримкам наступного читання, які виникають при повному витісненні через `CLFLUSH`.
* **`CLDEMOTE` (Cache Line Demote):** підказка апаратному контролеру кешу перемістити лінію з найшвидших приватних кешів ядра (L1/L2) у спільний кеш останнього рівня (L3/LLC) без витіснення в оперативну пам'ять DRAM. Це знижує конкуренцію за ресурси L1/L2 між сусідніми потоками.

#### Регістри конфігурації, прапорці захисту та віртуалізація

* **`CR4.TSD` (Time Stamp Disable, біт 2):** прапорець регістру керування `CR4`. Якщо встановлено в `1`, виконання інструкцій `RDTSC` та `RDTSCP` у просторі користувача (Ring 3) генерує виключення загального захисту `#GP(0)`. Операційні системи загального призначення за замовчуванням тримають цей біт рівним `0`, дозволяючи непривілейованим програмам читати лічильник.
* **`MSR_IA32_TSC_AUX` (адреса `0xC0000103`):** 64-бітний модельний регістр (MSR), молодші 32 біти якого зберігають числовий ідентифікатор логічного ядра. Інструкція `RDTSCP` атомарно копіює вміст `IA32_TSC_AUX` у регістр `ECX`, дозволяючи коду перевірити, чи не відбулося перемикання задачі на інше ядро під час вимірювального вікна.
* **Перехоплення гіпервізором (VM-Exit):** у віртуалізованих середовищах (KVM, VMware, Hyper-V) гіпервізор може налаштувати біт перехоплення `RDTSC Exiting` у структурі VMCS/VMCB. У такому разі кожен виклик `RDTSC` віртуальною машиною викликає переривання VM-Exit і передачу керування хосту. Це призводить до колосального зростання виміряного часу (від 1000 до 3000 тактів на кожен замір), що руйнує точність сайд-канал атак.

### Архітектура ARMv8-A (AArch64): операції `DC` та системні лічильники

В архітектурі ARM операції керування кешем даних виконуються через сімейство команд `DC` (Data Cache Maintenance), що приймають віртуальну адресу як операнд у 64-бітному регістрі загального призначення `Xt`.

| Інструкція | Рівень виклику | Точка когерентності (Scope) | Поведінка над лінією пам'яті |
| :--- | :--- | :--- | :--- |
| `DC CIVAC, Xt` | EL0 (користувач) / EL1 | PoC (Point of Coherency) | Очищення (Clean) та повна інвалідація (Invalidate) лінії за адресою `Xt` |
| `DC CVAC, Xt` | EL0 (користувач) / EL1 | PoC (Point of Coherency) | Очищення (запис брудних даних у RAM) без інвалідації лінії в кеші |
| `DC CVAU, Xt` | EL0 (користувач) / EL1 | PoU (Point of Unification) | Очищення кешу даних до точки уніфікації з кешем інструкцій ядра |
| `DC CVAP, Xt` | EL0 (користувач) / EL1 | PoP (Point of Persistence) | Очищення кешу даних до контролера енергонезалежної пам'яті |
| `DC IVAC, Xt` | **EL1 (ядро ОС)** | PoC (Point of Coherency) | Інвалідація лінії без скидання брудних даних (привілейована дія) |
| `DC ZVA, Xt` | EL0 (якщо дозволено) | Блок кешу | Обнулення цілого кеш-блоку в L1D без звернення до оперативної пам'яті |

#### Рівні уніфікації та когерентності в ARM

ARM формально визначає кілька точок видимості пам'яті в системі:
1. **Point of Coherency (PoC):** точка, в якій усі спостерігачі системи (усі ядра CPU, графічний прискорювач GPU та контролери прямого доступу до пам'яті DMA) бачать абсолютно однаковий стан пам'яті (зазвичай це інтерфейс системної шини перед контролером DRAM).
2. **Point of Unification (PoU):** точка, в якій кеш інструкцій, кеш даних та блок трансляції сторінок (MMU Page Table Walker) конкретного ядра бачать узгоджену копію пам'яті.
3. **Point of Persistence (PoP):** точка в системі пам'яті, після досягнення якої дані гарантовано збережуться навіть у разі раптового зникнення живлення.

Інструкція `DC CIVAC` (Clean and Invalidate by Virtual Address to Point of Coherency) є повним функціональним еквівалентом команди `CLFLUSH` у x86: вона очищає та витісняє лінію з усіх приватних і спільних кешів до точки PoC.

#### Таймери та бар'єри синхронізації ARMv8

1. **Читання віртуального лічильника часу:**
   ```
   mrs %0, CNTVCT_EL0
   ```
   Доступність цього лічильника з простору користувача (EL0) контролюється бітом `CNTKCTL_EL1.EL0VCTEN`. Якщо ядро операційної системи Linux увімкнуло цей біт, інструкція повертає 64-бітне монотонне значення часу, що генерується системним таймером Generic Timer (частота зазвичай фіксована в діапазоні від 10 до 50 МГц).

2. **Бар'єри серіалізації конвеєра:**
   * **`ISB` (Instruction Synchronization Barrier):** скидає конвеєр вибірки команд процесора, змушуючи ядро перечитати наступні команди після завершення всіх попередніх системних операцій.
   * **`DSB SY` (Data Synchronization Barrier, Full System):** блокує виконання наступних команд конвеєра доти, доки всі попередні операції читання та запису даних не завершаться в усій системі.
   * **`DMB SY` (Data Memory Barrier):** гарантує строгий порядок звернень до пам'яті для зовнішніх контролерів без призупинення виконання арифметичних мікрооперацій ядра.

### Архітектура RISC-V: розширення Zicbom та лічильники `rdcycle`

Базова специфікація архітектури RISC-V орієнтована на простоту ядра і спочатку не передбачала інструкцій витіснення кешу з простору користувача. Для стандартизації взаємодії з кешами було прийнято розширення **Zicbom** (Cache-Block Management Operations).

| Інструкція | Операнд | Дія над блоком кешу | Примітка |
| :--- | :--- | :--- | :--- |
| `CBO.FLUSH` | `(rs1)` | Запис брудних даних у пам'ять та повна інвалідація блоку | Аналог `CLFLUSH` у x86 та `DC CIVAC` в ARM |
| `CBO.CLEAN` | `(rs1)` | Запис брудних даних у пам'ять без інвалідації | Аналог `CLWB` у x86 та `DC CVAC` в ARM |
| `CBO.INVAL` | `(rs1)` | Негайне видалення блоку з кешу (без скидання) | Може вимагати привілеїв залежно від біта `menvcfg.CBIE` |
| `CBO.ZERO` | `(rs1)` | Заповнення кеш-блоку нулями (із розширення Zicboz) | Апаратне пришвидшення ініціалізації масивів |

#### Зчитування лічильників та бар'єри в RISC-V

* **`rdcycle rd` / `csrr rd, cycle`:** зчитує 64-бітний лічильник виконаних тактів ядра CPU. Доступність інструкції для непривілейованого коду (User Mode) регулюється бітом `CY` у системному регістрі `mcounteren` (Machine Counter-Enable).
* **`rdtime rd` / `csrr rd, time`:** зчитує лічильник стабільного часу реального часу (Wall Clock), підключений до генератора опорної частоти платформи.
* **`FENCE` (Memory Fence):** приймає бітові маски попередніх (`PI, PO, PR, PW`) та наступних (`SI, SO, SR, SW`) операцій, встановлюючи бар'єр між операціями введення-виведення, читання та запису даних.
* **`FENCE.I` (Instruction-Fetch Fence):** синхронізує кеш інструкцій із кешем даних, змушуючи конвеєр інструкцій врахувати зміни, внесені в пам'ять коду або таблиці функцій.
