Коли два мережеві вузли встановлюють захищене з'єднання через відкриті транзитні маршрутизатори, симетричне шифрування потрапляє в замкнене коло: для обміну даними потрібен спільний секретний ключ, проте передати цей ключ відкритим каналом без попереднього шифрування неможливо. Якщо в мережі взаємодіють `M` абонентів, кожній парі потрібен окремий ключ, що вимагає попереднього безпечного розподілу `M · (M - 1) / 2` ключів. У глобальному інтернеті з мільйонами серверів і клієнтів фізична доставка ключів кур'єрами нездійсненна, а компрометація одного секрету відкриває зловмиснику повний доступ до всього архіву перехопленого трафіку.

Розв'язання цієї проблеми полягає в асиметричній криптографії (грец. *asymmetria* — нерівність частин), де операції зашифрування та розшифрування розділені між парою математично пов'язаних ключів. Відкритий ключ публікується у відкритому доступі й дозволяє будь-якому відправнику зашифрувати повідомлення або перевірити підпис. Приватний ключ зберігається виключно у власника і є єдиним інструментом для відновлення відкритого тексту чи генерації цифрового підпису.

Першою практичною реалізацією цієї концепції стала криптосистема RSA, розроблена в 1977 році Рональдом Рівестом, Аді Шаміром та Леонардом Адлеманом у Массачусетському технологічному інституті (MIT). Вона спирається на обчислювальну асиметрію модульної арифметики: перемножити два великих простих числа можна за частки мілісекунди, тоді як зворотна задача факторизації їхнього добутку за відсутності спеціальних апаратних ресурсів потребує мільйонів років обчислень.

## Одностороння перестановка з таємним входом

В основі RSA лежить математична конструкція, відома як **одностороння перестановка з таємним входом** (англ. *Trapdoor One-Way Permutation*). Це бієктивне відображення множини на саму себе, яке задовольняє три умови:

1. **Пряме обчислення:** Для будь-якого вхідного блоку `m` значення `c = f(m)` обчислюється за поліноміальний час `O(log e · log² N)` за допомогою публічних параметрів `(e, N)`.
2. **Нездійсненність обернення без таємниці:** Маючи лише `c` та відкриті параметри `(e, N)`, обчислення прообразу `m = f⁻¹(c)` вимагає розв'язання задачі кореня `e`-го степеня за складеним модулем `N`, що за складністю еквівалентно факторизації `N`.
3. **Легкість обернення з таємницею:** Володіння секретним параметром `d` (таємним входом, англ. *trapdoor*), обчисленим через розклад `N = p · q`, перетворює операцію інвертування `m = c^d mod N` на швидке поліноміальне піднесення до степеня.

### Алгебраїчна структура кільця залишків та порядок групи

Розглянемо комутативне кільце залишків `ℤ_N = {0, 1, 2, ..., N - 1}`, де модуль `N = p · q` є добутком двох великих непарних простих чисел `p` та `q` (`p ≠ q`).

Елементи кільця `ℤ_N`, взаємно прості з модулем `N`, утворюють мультиплікативну групу залишків `ℤ_N*`:

```
ℤ_N* = { a ∈ ℤ_N | НСД(a, N) = 1 }
```

Кількість елементів у цій групі визначається функцією Ейлера `ϕ(N)`:

```
ϕ(N)
= (p - 1) · (q - 1)      [оскільки N = p·q, а p і q — прості числа]
= N - p - q + 1          [розкриття дужок для кількості чисел, взаємно простих із p та q]
```

Мінімальним універсальним показником, який переводить кожен елемент групи `ℤ_N*` в одиницю, є функція Кармайкла `λ(N)`:

```
λ(N) = НСК(p - 1, q - 1) = ((p - 1) · (q - 1)) / НСД(p - 1, q - 1)
```

За теоремою Ейлера для будь-якого елемента `a ∈ ℤ_N*` виконується тотожність:

```
a^ϕ(N) ≡ 1 (mod N)
a^λ(N) ≡ 1 (mod N)
```

### Математичний механізм шифрування та розшифрування

Для побудови криптосистеми обираються відкритий показник `e` та секретний показник `d`, які є мультиплікативно оберненими за модулем `λ(N)`:

```
e · d ≡ 1 (mod λ(N))
```

Шифрування відкритого повідомлення `m ∈ ℤ_N` та розшифрування шифротексту `c ∈ ℤ_N` виконуються операціями:

```
c ≡ m^e (mod N)          [зашифрування відкритим ключем (e, N)]
m ≡ c^d (mod N)          [розшифрування приватним ключем (d, N)]
```

### Доведення коректності розшифрування

Розглянемо перетворення шифротексту приватним ключем:

```
c^d mod N
= (m^e)^d mod N        [підстановка визначення c ≡ m^e mod N]
= m^(e·d) mod N        [властивість степеня: (a^b)^c = a^(b·c)]
= m^(1 + k·λ(N)) mod N [визначення d: e·d = 1 + k·λ(N) для цілого k ≥ 1]
= m · (m^λ(N))^k mod N [розкладання показника степеня на суму]
```

Якщо `НСД(m, N) = 1`, елемент `m` належить групі `ℤ_N*`. За теоремою Кармайкла `m^λ(N) ≡ 1 (mod N)`:

```
m · (m^λ(N))^k mod N
= m · (1)^k mod N      [застосування тотожності Кармайкла m^λ(N) ≡ 1 mod N]
= m mod N              [множення на одиницю]
```

Якщо `НСД(m, N) > 1`, повідомлення `m` ділиться на один із простих множників (наприклад, `p | m` і `q ∤ m`). Доведемо рівність окремо за модулями `p` та `q` за допомогою Малої теореми Ферма:

1. За модулем `p`: оскільки `p | m`, маємо `m ≡ 0 (mod p)`, а отже `m^(e·d) ≡ 0 ≡ m (mod p)`.
2. За модулем `q`: оскільки `q ∤ m`, за Малою теоремою Ферма `m^(q - 1) ≡ 1 (mod q)`. Оскільки `(q - 1) | λ(N)`, то `e·d = 1 + k·λ(N) = 1 + j·(q - 1)`. Звідси:

```
m^(e·d) mod q
= m^(1 + j·(q - 1)) mod q
= m · (m^(q - 1))^j mod q
= m · (1)^j mod q      [за Малою теоремою Ферма m^(q-1) ≡ 1 mod q]
= m mod q
```

Оскільки `m^(e·d) ≡ m (mod p)` та `m^(e·d) ≡ m (mod q)`, а числа `p` та `q` взаємно прості, за Китайською теоремою про лишки:

```
m^(e·d) ≡ m (mod p · q)
m^(e·d) ≡ m (mod N)
```

Отже, розшифрування завжди повертає початкове повідомлення `m` для будь-якого `m ∈ ℤ_N`.

## Практична генерація ключів та оптимізація обчислень

Надійність RSA базується на тому, що факторизація `N` є обчислювально нездійсненною, тоді як генерація ключів і виконання операцій повинні займати мінімальний час процесора.

![Конвеєр генерації ключів RSA та прискорення CRT](/root/eng/sf-security/rsa/img/rsa-key-generation-and-crt.svg)
*Конвеєр генерації ключів RSA: від криптографічного джерела випадковості та тесту Міллера — Рабіна до побудови параметрів CRT, що прискорюють розшифрування у ~4 рази.*

### Алгоритм генерації простих чисел

Генерація пари простих чисел `p` і `q` довжиною по 1024 біти (для створення 2048-бітного модуля `N`) складається з чотирьох етапів:

1. **Криптографічна випадковість:** Генератор випадкових чисел CSPRNG (наприклад, системний виклик `getrandom` у Linux) генерує 1024-бітний масив байтів. Старший біт виставляється в `1` (щоб гарантувати точну розрядність добутку `N`), а молодший біт — в `1` (число має бути непарним).
2. **Швидкий відсів малих дільників:** Кандидат перевіряється діленням на перші 1000 простих чисел (від 3 до 7919). Якщо `кандидат mod prime_i == 0`, число відкидається без запуску важких модульних операцій. Це відсіює понад 85% складених кандидатів за мікросекунди.
3. **Ймовірнісний тест Міллера — Рабіна:** Для кандидата виконується 40 незалежних раундів тесту Міллера — Рабіна з випадковими основами `a`. Кожен пройдений раунд знижує ймовірність помилки (прийняття складеного числа за просте) щонайменше у 4 рази. Після 40 раундів імовірність хибного результату становить `P < 4⁻⁴⁰ = 2⁻⁸⁰ < 10⁻²⁴`, що перевищує надійність апаратних компонентів процесора.
4. **Контроль різниці множників:** Перевіряється умова `|p - q| > 2^(k/2 - 100)`. Якщо `p` і `q` розташовані надто близько, модуль `N` розкладається алгоритмом Ферма через обчислення `⌈√N⌉`.

### Вибір відкритої експоненти e = 65537

Історично для прискорення зашифрування використовували малі значення експоненти, зокрема `e = 3`. Проте малі значення створюють критичні вразливості у разі помилок реалізації доповнення.

Стандартом промислової криптографії є четверте просте число Ферма:

```
e = F₄ = 2¹⁶ + 1 = 65537
```

У двійковому представленні число 65537 має вигляд `10000000000000001₂`. Його вага Геммінга (кількість одиничних бітів) дорівнює 2. При піднесенні повідомлення до степеня методом квадратів і множень (англ. *Square-and-Multiply*) обчислення `m⁶⁵⁵³⁷ mod N` вимагає рівно 16 операцій піднесення до квадрата та лише 1 операцію множення:

```
m² ↦ m⁴ ↦ m⁸ ↦ ... ↦ m⁶⁵⁵³⁶ ↦ m⁶⁵⁵³⁷ = (m⁶⁵⁵³⁶ · m) mod N
```

Це забезпечує максимальну швидкість операцій зашифрування та перевірки підпису, повністю виключаючи вразливості, притаманні експоненті `e = 3`.

### Оптимізація приватних операцій через Китайську теорему про лишки (CRT)

Піднесення 2048-бітного шифротексту до 2048-бітного приватного степеня `d` за 2048-бітним модулем `N` вимагає близько 3072 модульних множень над 2048-бітними числами. Складність класичного множення зростає пропорційно кубу розрядності `O(k³)`.

Китайська теорема про лишки (CRT, англ. *Chinese Remainder Theorem*) дозволяє замінити одну операцію над 2048-бітними числами двома паралельними операціями над 1024-бітними числами за модулями `p` та `q`.

Структура RSA-CRT закріплена стандартом PKCS#1 і містить попередньо обчислені параметри:

```
d_p = d mod (p - 1)
d_q = d mod (q - 1)
q_inv = q⁻¹ mod p
```

Процес розшифрування виконується у три кроки:

1. **Зведення шифротексту та піднесення до степеня в напівмодулях:**
```
m_p = (c mod p)^d_p mod p    [обчислення за 1024-бітним модулем p]
m_q = (c mod q)^d_q mod q    [обчислення за 1024-бітним модулем q]
```
2. **Реконструкція Гарнера (Garner's formula):**
```
h = (q_inv · (m_p - m_q)) mod p
```
Якщо проміжна різниця `m_p - m_q < 0`, до неї додається модуль `p`.
3. **Фінальне збирання результату:**
```
m = m_q + h · q
```

### Математичний виграш у швидкості

Оцінимо обчислювальну складність:
- Піднесення до степеня за модулем розмірності `k` бітів потребує `O(k³)` операцій.
- Обчислення `m_p` потребує `(k/2)³ = k³ / 8` операцій.
- Обчислення `m_q` також потребує `(k/2)³ = k³ / 8` операцій.
- Сумарна складність двох CRT-гілок:

```
Складність_CRT = k³/8 + k³/8 = k³/4 = 0.25 · Складність_Пряма
```

Використання CRT прискорює операції приватного ключа (розшифрування та підпис) рівно у 4 рази.

```c
#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

/* Структура попередньо обчислених параметрів RSA-CRT для фіксованої розрядності */
typedef struct {
    const uint64_t *p;       /* Простий дільник p (1024 біти / 16 слів по 64 біти) */
    const uint64_t *q;       /* Простий дільник q (1024 біти) */
    const uint64_t *dp;      /* d_p = d mod (p - 1) */
    const uint64_t *dq;      /* d_q = d mod (q - 1) */
    const uint64_t *qinv;    /* q_inv = q^(-1) mod p */
    size_t limbs_half;       /* Кількість 64-бітних слів у p та q (наприклад, 16) */
} rsa_crt_key_t;

/* Прототипи модульної арифметики великих чисел (BigInt) */
void bigint_mod_exp(uint64_t *res, const uint64_t *base, const uint64_t *exp,
                    const uint64_t *mod, size_t len);
void bigint_sub_mod(uint64_t *res, const uint64_t *a, const uint64_t *b,
                    const uint64_t *mod, size_t len);
void bigint_mul_mod(uint64_t *res, const uint64_t *a, const uint64_t *b,
                    const uint64_t *mod, size_t len);
void bigint_mul_add(uint64_t *res, const uint64_t *m_q, const uint64_t *h,
                    const uint64_t *q, size_t len_half);

/* Виконання розшифрування за схемою RSA-CRT за алгоритмом Гарнера */
bool rsa_crt_decrypt(uint64_t *out_m, const uint64_t *in_c, const rsa_crt_key_t *key) {
    size_t n = key->limbs_half;
    uint64_t mp[32]; /* Буфер для 1024-бітного проміжного результату */
    uint64_t mq[32];
    uint64_t h[32];
    uint64_t diff[32];

    if (n > 32) return false;

    /* 1. Паралельне обчислення частин повідомлення у факторах p та q */
    bigint_mod_exp(mp, in_c, key->dp, key->p, n);
    bigint_mod_exp(mq, in_c, key->dq, key->q, n);

    /* 2. Обчислення h = (q_inv * (m_p - m_q)) mod p */
    bigint_sub_mod(diff, mp, mq, key->p, n);
    bigint_mul_mod(h, diff, key->qinv, key->p, n);

    /* 3. Фінальна реконструкція Garner: m = m_q + h * q (результат 2048 бітів) */
    bigint_mul_add(out_m, mq, h, key->q, n);

    return true;
}

void bigint_mul_add(std::span<uint64_t> res, std::span<const uint64_t> mq,
                    std::span<const uint64_t> h, std::span<const uint64_t> q);

// Ідіоматична функція розшифрування RSA-CRT
std::expected<std::vector<uint64_t>, RsaError>
rsa_crt_decrypt(std::span<const uint64_t> ciphertext, const RsaCrtKey& key) {
    const size_t n = key.limbs_half;
    if (key.p.size() != n || key.q.size() != n || key.dp.size() != n ||
        key.dq.size() != n || key.qinv.size() != n) {
        return std::unexpected(RsaError::InvalidKeyLength);
    }

    std::vector<uint64_t> mp(n);
    std::vector<uint64_t> mq(n);
    std::vector<uint64_t> diff(n);
    std::vector<uint64_t> h(n);
    std::vector<uint64_t> plaintext(2 * n, 0);

    // 1. Обчислення залишків mp = c^dp mod p та mq = c^dq mod q
    bigint_mod_exp(mp, ciphertext, key.dp, key.p);
    bigint_mod_exp(mq, ciphertext, key.dq, key.q);

    // 2. Реконструкція Garner: h = (qinv * (mp - mq)) mod p
    bigint_sub_mod(diff, mp, mq, key.p);
    bigint_mul_mod(h, diff, key.qinv, key.p);

    // 3. Збирання повного 2048-бітного відкритого тексту m = mq + h * q
    bigint_mul_add(plaintext, mq, h, key.q);

    return plaintext;
}
```

## Вразливості сирого (Textbook) RSA

Застосування математичної формули `c = m^e mod N` напряму без додаткової випадкової обробки в інженерній практиці називається **підручниковим RSA** (англ. *Textbook RSA*). Сирий RSA є критично небезпечним і повністю непридатним для використання в реальних системах через фундаментальні вразливості.

### Детермінізм та словникові атаки

Сире зашифрування є строго детермінованим: одне й те саме відкрите повідомлення `m` завжди дає однаковий шифротекст `c`.

Якщо зловмисник знає, що повідомлення належить невеликому простору можливих значень (наприклад, фінансове рішення «ТАК» або «НІ», значення PIN-коду чи сума транзакції до 10 000 гривень), він застосовує відкритий ключ `(e, N)` для попереднього зашифрування всіх можливих варіантів:

```
c_тестове = m_варіант^e mod N
```

Зіставивши перехоплений шифротекст `c` із згенерованою таблицею, зловмисник миттєво розкриває передані дані без знання приватного ключа. Сирий RSA не забезпечує базової семантичної стійкості IND-CPA (англ. *Indistinguishability under Chosen-Plaintext Attack*).

### Мультиплікативна гомоморфність та маніпуляція шифротекстами

Алгебраїчна структура перестановки RSA зберігає операцію множення:

```
c₁ · c₂ mod N
= (m₁^e mod N) · (m₂^e mod N) mod N
= (m₁ · m₂)^e mod N    [властивість степеня в кільці залишків]
```

Це дозволяє зловмиснику маніпулювати змістом зашифрованого повідомлення без його розшифрування (властивість пластичності, англ. *malleability*):

1. Перехопивши шифротекст банківської транзакції `c = m^e mod N`, атакуючий генерує множник `k = 2`.
2. Обчислює модифікований шифротекст `c' = (c · 2^e) mod N`.
3. Сервер банку розшифровує `c'` за допомогою приватного ключа `d`:

```
(c')^d mod N
= (c · 2^e)^d mod N
= (m^e · 2^e)^d mod N
= ((2 · m)^e)^d mod N
= 2 · m mod N          [сума транзакції подвоїлася]
```

### Атака на малі повідомлення без модуля

Якщо відкрите повідомлення `m` коротке (наприклад, 128-бітний симетричний ключ AES), а відкрита експонента дорівнює `e = 3`, числове значення `m³` може виявитися меншим за 2048-бітний модуль `N`:

```
m < 2¹²⁸ ⟹ m³ < 2³⁸⁴ ≪ N ≈ 2²⁰⁴⁸
```

У цьому випадку операція `m³ mod N` ніколи не досягає межі модуля і не виконує операцію ділення з остачею. Шифротекст дорівнює звичайному кубу числа над полем дійсних чисел `c = m³`. Для його розшифрування зловмиснику не потрібен розклад модуля чи секретний ключ — достатньо добути точний арифметичний кубічний корінь `m = ∛c` стандартними чисельними методами за частки мікросекунди.

### Широкомовна атака Хастада (Håstad Broadcast Attack)

Якщо відправник транслює однакове повідомлення `m` трьом різним одержувачам, які використовують відкриту експоненту `e = 3` та взаємно прості модулі `N₁, N₂, N₃`, зловмисник перехоплює три шифротексти:

```
c₁ ≡ m³ (mod N₁)
c₂ ≡ m³ (mod N₂)
c₃ ≡ m³ (mod N₃)
```

Застосовуючи Китайську теорему про лишки до системи порівнянь, атакуючий знаходить значення `C ∈ ℤ_(N₁·N₂·N₃)`:

```
C ≡ m³ (mod N₁ · N₂ · N₃)
```

Оскільки `m < N₁`, `m < N₂` та `m < N₃`, добуток `m³` строго менший за добуток модулів: `m³ < N₁ · N₂ · N₃`. Це означає, що `C = m³` над кільцем цілих чисел, і вихідне повідомлення відновлюється взяттям кубічного кореня `m = ∛C`.

## Стандарти безпечного доповнення: RSA-OAEP та RSA-PSS

Для перетворення детермінованої односторонньої функції на криптографічно стійку ймовірнісну схему шифрування та підпису відкритий текст перед піднесенням до степеня піддається спеціальному криптографічному доповненню (англ. *padding*).

![Схема безпечного доповнення шифрування RSA-OAEP](/root/eng/sf-security/rsa/img/rsa-oaep-padding-pipeline.svg)
*Схема доповнення RSA-OAEP (RFC 8017): двораундова мережа Фейстеля з випадковим зерном seed та генератором маски MGF1 повністю знищує гомоморфну структуру відкритого тексту.*

### Схема шифрування RSA-OAEP (Optimal Asymmetric Encryption Padding)

Стандарт PKCS#1 v2.2 (RFC 8017) визначає схему RSA-OAEP, яка забезпечує стійкість до адаптивних атак на основі підібраного шифротексту IND-CCA2 (англ. *Indistinguishability under Chosen-Ciphertext Attack*).

OAEP перетворює повідомлення `M` за допомогою двораундової асиметричної мережі Фейстеля з використанням геш-функцій:

1. **Формування блоку даних DB (Data Block):**
```
DB = Hash(L) || PS || 0x01 || M
```
де `Hash(L)` — геш опціональної мітки протоколу `L` (фіксована довжина `hLen`, за замовчуванням порожній рядок), `PS` — рядок нульових байтів для заповнення до потрібної довжини, `0x01` — байт-розділювач, `M` — вихідне відкрите повідомлення.
2. **Генерація випадкового зерна:** З CSPRNG вибирається випадковий рядок `seed` довжиною `hLen` байтів (наприклад, 32 байти для SHA-256).
3. **Перший раунд Фейстеля:** Генератор маски `MGF1` обчислює маску для блоку даних, яка накладається операцією XOR:
```
dbMask = MGF1(seed, k - hLen - 1)
maskedDB = DB ⊕ dbMask
```
4. **Другий раунд Фейстеля:** Маскований блок `maskedDB` використовується для маскування зерна:
```
seedMask = MGF1(maskedDB, hLen)
maskedSeed = seed ⊕ seedMask
```
5. **Формування закодованого повідомлення EM:**
```
EM = 0x00 || maskedSeed || maskedDB
```
Отримане число `EM` інтерпретується як велике ціле число та підноситься до відкритого степеня: `c = EM^e mod N`.

Будь-яка зміна хоча б одного біта в шифротексті `c` внаслідок лавинного ефекту геш-функції повністю руйнує як `seed`, так і `DB` при розкодуванні. Сервер виявляє порушення структури (відсутність байта `0x01` або невідповідність `Hash(L)`) і відхиляє запит без розкриття інформації.

#include <stddef.h>
#include <string.h>

/* Прототип криптографічної геш-функції SHA-256 */
void sha256(const uint8_t *data, size_t len, uint8_t out[32]);

/* Генератор маски MGF1 на базі SHA-256 (RFC 8017 PKCS#1 v2.2) */
void mgf1_sha256(const uint8_t *seed, size_t seed_len, uint8_t *mask, size_t mask_len) {
    uint32_t counter = 0;
    uint8_t counter_bytes[4];
    uint8_t hash_buf[32 + 4];
    uint8_t digest[32];
    size_t generated = 0;

    memcpy(hash_buf, seed, seed_len);

    while (generated < mask_len) {
        /* Запис лічильника у форматі Big-Endian */
        counter_bytes[0] = (uint8_t)(counter >> 24);
        counter_bytes[1] = (uint8_t)(counter >> 16);
        counter_bytes[2] = (uint8_t)(counter >> 8);
        counter_bytes[3] = (uint8_t)(counter);

        memcpy(hash_buf + seed_len, counter_bytes, 4);
        sha256(hash_buf, seed_len + 4, digest);

        size_t to_copy = mask_len - generated;
        if (to_copy > 32) to_copy = 32;

        memcpy(mask + generated, digest, to_copy);
        generated += to_copy;
        counter++;
    }
}

### Ймовірнісна схема підпису RSA-PSS (Probabilistic Signature Scheme)

У разі сирого цифрового підпису `s = H(m)^d mod N` мультиплікативна гомоморфність дозволяє сфальсифікувати підпис під новим документом: якщо зловмисник має підписи `s₁ = H(m₁)^d` та `s₂ = H(m₂)^d`, добуток `s₁ · s₂ mod N` є валідним підписом для повідомлення, геш якого дорівнює `H(m₁) · H(m₂) mod N`.

Схема RSA-PSS усуває цю вразливість додаванням випадкової солі `salt` перед гешуванням:

```
M' = 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 || mHash || salt
H = Hash(M')
DB = PS || 0x01 || salt
maskedDB = DB ⊕ MGF1(H, emLen - hLen - 1)
EM = maskedDB || H || 0xBC
```

Підпис обчислюється як `s = EM^d mod N`. Завдяки випадковій солі підпис того самого документа щоразу має інший вигляд, що забезпечує доказову стійкість у моделі випадкового оракула (англ. *Random Oracle Model*).

## Атаки на реалізації, сторонні канали та методи захисту

Навіть якщо математична модель алгоритму бездоганна, фізична реалізація на конкретному обладнанні може стати джерелом витоку секретних ключів.

### Атака оракула заповнення Блейхенбахера (PKCS#1 v1.5)

У застарілому стандарті PKCS#1 v1.5 блок перед зашифруванням мав фіксовану структуру:

```
EM = 0x00 || 0x02 || PS (не менше 8 ненульових випадкових байтів) || 0x00 || M
```

У 1998 році швейцарський криптограф Даніель Блейхенбахер виявив, що якщо сервер під час розшифрування повертає клієнту помилку «невірне доповнення» або демонструє різницю в часі обробки, він перетворюється на **оракул відповідності PKCS#1**.

![Атака оракула заповнення Блейхенбахера](/root/eng/sf-security/rsa/img/rsa-bleichenbacher-oracle-attack.svg)
*Атака мільйона повідомлень Блейхенбахера на PKCS#1 v1.5: надсилаючи спеціально модифіковані шифротексти c' = c · s^e mod N, атакуючий за 10⁶ запитів розкриває ключ TLS-сесії.*

Механізм атаки Блейхенбахера (відомої як *Million Message Attack* або сучасніша вразливість *ROBOT attack* у 2017 році):

1. Сервер приймає шифротекст `c` і розшифровує його: `m = c^d mod N`.
2. Оракул повертає `1` (істина), якщо розшифроване число `m` починається з байтів `0x00 0x02`, що відповідає діапазону:

```
2 · B ≤ m < 3 · B,    де B = 2^(8 · (k - 2))
```

3. Атакуючий вибирає множник `s` і надсилає на сервер модифікований шифротекст `c' = (c · s^e) mod N`. Сервер розшифровує його як `m' = (m · s) mod N`.
4. Якщо оракул відповідає «успіх», атакуючий знає, що `2B ≤ (m · s - r · N) < 3B` для деякого цілого `r`.
5. Послідовно перебираючи `s` та звужуючи інтервали можливих значень `m`, атакуючий приблизно за `10⁶` запитів до сервера повністю відновлює відкритий текст `m` (наприклад, Pre-Master Secret сесії TLS) без володіння приватним ключем.

**Захист:** Повний перехід на RSA-OAEP або використання обробки з константним часом (англ. *constant-time*), де в разі помилки валідації PKCS#1 v1.5 сервер не повертає помилку, а генерує випадковий фіктивний симетричний ключ і продовжує рукостискання, що позбавляє зловмисника оракула.

### Атаки за часом виконання (Timing Attacks) та криптографічне засліплення

У 1996 році Пол Кочер довів можливість відновлення приватного ключа RSA шляхом точного вимірювання часу виконання операцій модульного піднесення до степеня.

У класичному алгоритмі піднесення до степеня біти ключа `d` обробляються послідовно:

```
s = 1;
for (int i = bits - 1; i >= 0; i--) {
    s = (s * s) mod N;            // Квадрат виконується завжди
    if ((d >> i) & 1) {
        s = (s * message) mod N;  // Додаткове множення ЛИШЕ якщо біт d_i == 1
    }
}
```

Якщо `d_i = 1`, операція займає більше процесорних тактів. Крім того, час виконання модульного множення залежить від значень вхідних слів через наявність операцій переносу. Вимірюючи різницю в часі відповіді на тисячі спеціально підібраних повідомлень, зловмисник біт за бітом відновлює приватний ключ `d`.

![Криптографічне засліплення (Blinding)](/root/eng/sf-security/rsa/img/rsa-blinding-side-channel-defense.svg)
*Криптографічне засліплення (Blinding): множення вхідних даних на випадковий фактор r^e усуває статистичний зв'язок між часом обчислення і значенням бітів ключа.*

Еталонним інженерним захистом від часових атак та аналізу споживання потужності (DPA) є **криптографічне засліплення** (англ. *Cryptographic Blinding*):

1. Перед виконанням приватного піднесення до степеня сервер генерує випадкове число `r ∈ ℤ_N*` за допомогою CSPRNG.
2. Вхідне повідомлення (або шифротекст `c`) засліплюється відкритим ключем `e`:
```
c' = (c · r^e) mod N
```
3. Виконується приватна операція над засліпленим значенням:
```
s' = (c')^d mod N = (c · r^e)^d mod N = (c^d · r^(e·d)) mod N = (m · r) mod N
```
4. Результат розсліплюється множенням на мультиплікативно обернене значення `r⁻¹ mod N`:
```
s = (s' · r⁻¹) mod N = (m · r · r⁻¹) mod N = m mod N
```

Оскільки число `r` змінюється для кожної операції, проміжні дані в процесорі є повністю випадковими, що робить вимірювання часу чи енергоспоживання марним для атакуючого.

### Апаратні збої та атака Белкоре на RSA-CRT

Якщо сервер використовує прискорення RSA-CRT, внесення апаратного збою (англ. *Fault Injection* — наприклад, короткочасний лазерний імпульс або перепад напруги живлення криптографічного чипа під час розрахунку `m_p`) призводить до катастрофічного зламу.

Нехай внаслідок збою значення `m_p` обчислено з помилкою як `m_p'`, тоді як `m_q = c^d_q mod q` обчислено вірно. Сформований підпис `s'` матиме властивості:

```
s' ≢ s (mod p)    [результат у модулі p пошкоджено]
s' ≡ s (mod q)    [результат у модулі q вірний]
```

Це означає, що різниця `(s')^e - m` ділиться націло на `q`, але не ділиться на `p`. Зловмисник обчислює найбільший спільний дільник за алгоритмом Евкліда за частку мілісекунди:

```
q = НСД((s')^e - m, N)
```

Один єдиний пошкоджений підпис миттєво факторизує модуль `N` і компрометує приватний ключ.

**Захист:** Обов'язкова верифікація згенерованого підпису відкритим ключем `(s^e mod N == m)` перед відправленням або використання подвійного обчислення.

## Сучасний стан RSA та постквантова перспектива

RSA залишається найпоширенішим асиметричним алгоритмом у спадкових протоколах (TLS 1.2, SSH, кодові підписи X.509, PGP), проте інженерні вимоги суттєво змінилися.

| Параметр | RSA-2048 | RSA-3072 | RSA-4096 | ECC (Ed25519 / P-256) |
|---|---|---|---|---|
| **Еквівалентна симетрична стійкість** | 112 бітів | 128 бітів | 140 бітів | 128 / 256 бітів |
| **Розмір відкритого ключа** | 256 байтів | 384 байти | 512 байтів | 32 / 64 байти |
| **Розмір підпису / шифротексту** | 256 байтів | 384 байти | 512 байтів | 64 байти |
| **Швидкість відкритої операції (e=65537)**| Дуже висока | Висока | Середня | Середня |
| **Швидкість приватної операції (CRT)** | Середня | Низька | Дуже низька | Дуже висока |
| **Рекомендація NIST / BSI** | Застарілий (фазується) | Дозволений до 2030+ | Дозволений | Рекомендований стандарт |

### Постквантова загроза: алгоритм Шора

Усі класичні асиметричні алгоритми на базі факторизації цілих чисел (RSA) та дискретного логарифма (DH, ECDSA, Ed25519) є вразливими до квантового алгоритму Пітера Шора.

На квантовому комп'ютері з достатньою кількістю логічних кубітів (близько 4000 стабільних кубітів для RSA-2048) період функції `f(x) = a^x mod N` знаходиться за поліноміальний час `O(k³)` за допомогою квантового перетворення Фур'є. Це призводить до миттєвого знаходження розкладу `N = p · q`.

У сучасних нових архітектурах RSA поступово витісняється еліптичними кривими (Ed25519/X25519 для швидкості та компактності), а також стандартизованими NIST постквантовими алгоритмами на базі решіток: ML-KEM (Kyber) для інкапсуляції ключів та ML-DSA (Dilithium) для цифрових підписів.

> 🔧 **Інженерний чеклист налаштування RSA:**
> 1. **Мінімальний розмір ключа:** Не менше 3072 бітів для нових довготривалих сертифікатів (2048 бітів допустимо лише як перехідний мінімум).
> 2. **Заборона сирого RSA:** Жодного піднесення до степеня без криптографічного доповнення.
> 3. **Схеми доповнення:** Використовувати виключно RSA-OAEP для шифрування та RSA-PSS для цифрового підпису. Повністю вимкнути PKCS#1 v1.5.
> 4. **Обов'язкове засліплення:** Активація Cryptographic Blinding для всіх операцій із приватним ключем для блокування атак сторонніми каналами.
> 5. **Захист CRT:** Перевірка згенерованого підпису відкритим ключем перед видачею назовні для запобігання атаці Белкоре.
