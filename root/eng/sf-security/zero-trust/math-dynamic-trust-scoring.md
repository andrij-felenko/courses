# 🧮 Математична модель динамічного індексу довіри та байєсової оцінки ризику

У класичній моделі безпеки довіра є бінарною: користувач або має дійсний пароль і повний доступ, або не має доступу взагалі. В архітектурі нульової довіри (Zero Trust) доступ є неперервною функцією ризику. Оскільки будь-який пристрій чи обліковий запис може бути скомпрометований уже після проходження початкової автентифікації, система ухвалення рішень (Policy Decision Point, PDP) зобов'язана безперервно перераховувати числовий показник надійності суб'єкта — **динамічний індекс довіри** (англ. *Dynamic Trust Score*, `T(t) ∈ [0, 100]`).

Ця математична вставка формалізує методику багатокритеріальної оцінки контексту, нелінійне зважування сигналів безпеки, часове експоненційне згасання довіри та апостеріорне байєсове оновлення ймовірності компрометації активної сесії.

---

### Вектор контекстних ознак та вагові коефіцієнти

У кожний момент часу `t` точка збору інформації (Policy Information Point, PIP) фіксує вектор із `n` нормалізованих сигналів телеметрії:

```
x(t) = [x₁, x₂, x₃, x₄, x₅]ᵀ,   де кожне xᵢ ∈ [0, 1]
```

Ознаки відображають стан різних рівнів системи (де `1.0` відповідає ідеальному стану, а `0.0` — максимальному ризику):
1. `x₁` — **Цілісність кінцевого пристрою (Device Posture)**: наявність увімкненого апаратного модуля TPM, активне повнодискове шифрування, статус служби EDR та актуальність оновлень операційної системи.
2. `x₂` — **Мережевий контекст і географічна правдоподібність (Geo & Network Velocity)**: оцінка стабільності IP-адреси, репутації автономної системи (ASN) та відсутності явища «неможливої швидкості переміщення» (*Impossible Travel*).
3. `x₃` — **Стійкість фактора автентифікації (Auth Strength)**: `1.0` для апаратного ключа FIDO2/WebAuthn з перевіркою присутності користувача, `0.6` для push-сповіщення у мобільному застосунку, `0.2` для одноразового пароля в SMS, `0.0` для базового пароля без другого фактора.
4. `x₄` — **Поведінкова ентропія (Behavioral Profiling)**: відповідність поточного часу запиту, типу виклику API та обсягу запитаних даних типовому історичному профілю роботи даного співробітника.
5. `x₅` — **Глобальний рівень загроз (Threat Intelligence)**: поточний індекс атак на інфраструктуру компанії та відсутність IP-адреси клієнта у публічних списках скомпрометованих вузлів (Botnet/Tor Exit Nodes).

Кожній ознаці `xᵢ` відповідає ваговий коефіцієнт `wᵢ > 0`, який відображає критичність фактора для конкретного ресурсу:

```
w = [w₁, w₂, w₃, w₄, w₅],   де ∑ wᵢ = 1
```

---

### Нелінійний розрахунок базового індексу довіри

Просте лінійне зважування `∑ wᵢ · xᵢ` має критичну ваду: якщо EDR виявив роботу шкідливого процесу (`x₁ = 0.0`), але користувач використав FIDO2-ключ (`x₃ = 1.0`) і знаходиться в офісі (`x₂ = 1.0`), лінійна сума видасть високий бал `0.75`. Це неприпустимо, оскільки наявність активного трояна на машині повністю нівелює всі інші позитивні фактори.

Тому підсумковий індекс довіри обчислюється через мультиплікативний коефіцієнт штрафу `V(x)` (критичні вето-фактори):

```
T_raw = 100 · (∑ᵢ₌₁ⁿ wᵢ · xᵢ) · ∏ⱼ₌₁ᵐ vⱼ(xⱼ)
```

Функція вето `vⱼ(xⱼ)` є кусково-гладкою сигмоїдою, яка обнуляє довіру при падінні критичного показника нижче безпечного порогу `θ`:

```
vⱼ(x)
= 1.0                               [безпечний стан: x ≥ θ, штрафу немає]
= 1 / (1 + exp(-k · (x - θ/2)))     [аномалія: x < θ, круте експоненційне згасання]
```

Де `k` — крутизна штрафної кривої (зазвичай `k = 20`), а `θ = 0.4` — поріг неприйнятного ризику.

### Модель часового згасання довіри (Exponential Trust Decay)

Довіра в парадигмі Zero Trust не є вічною: без активного повторного підтвердження автентичності будь-яка відкрита сесія з часом втрачає надійність через зростання ймовірності крадіжки токена або фізичного перехоплення пристрою.

Якщо протягом інтервалу часу `Δt` від суб'єкта не надходило свіжих криптографічних підтверджень, його індекс довіри експоненційно згасає до базового неавтентифікованого рівня `T_floor`:

```
T(t + Δt)
= T_floor + (T(t) - T_floor) · exp(-λ · Δt)     [експоненційне згасання за часом]
```

Де швидкість згасання `λ` визначається періодом напіврозпаду довіри `t_half` (наприклад, для привілейованих адміністраторів `t_half = 15` хвилин, для звичайних користувачів `t_half = 60` хвилин):

```
λ
= ln(2) / t_half                                [константа згасання]
```

### Байєсове оновлення ймовірності компрометації сесії

Під час тривалої сесії користувача система отримує дискретні події `E_k` (наприклад, зміну IP-адреси, запит до нетипової бази даних або спробу вивантажити 10 000 записів одночасно). Позначимо через `C` гіпотезу про те, що сесія скомпрометована, а через `C̄` — що сесія легітимна.

Апостеріорна ймовірність компрометації після настання події `E` обчислюється за теоремою Байєса:

```
P(C | E)
= P(E | C) · P(C) / P(E)                                   [формула Байєса]
= P(E | C) · P(C) / [P(E | C) · P(C) + P(E | C̄) · P(C̄)]    [формула повної ймовірності]
```

Для обчислення зручно перейти до логарифмічного відношення шансів (Log-Odds):

```
logit(P(C | E))
= ln(P(C | E) / (1 - P(C | E)))              [означення логіт-функції]
= ln(P(C) / P(C̄)) + ln(P(E | C) / P(E | C̄))   [теорема Байєса у формі шансів]
= logit(P(C)) + Λ(E)                         [адитивне додавання ваги свідчення]
```

Де `Λ(E) = ln(P(E | C) / P(E | C̄))` — вага доказу події `E` (англ. *Weight of Evidence*). Якщо спостережувана подія типова для зловмисника і неможлива для нормального користувача, `Λ(E) > 0`, що миттєво піднімає ймовірність `P(C)`.

### Покроковий приклад динамічного обчислення

Розглянемо практичний сценарій: інженер фінансового шлюзу підключається до системи.

**Початковий стан на момент автентифікації:**
- Ваги ресурсів: `w = [0.30, 0.20, 0.25, 0.15, 0.10]`
- Початкові параметри:
  - `x₁ = 1.0` (TPM валідовано, BitLocker увімкнено, EDR активний)
  - `x₂ = 0.95` (звична IP-підмережа офісу)
  - `x₃ = 1.0` (FIDO2 WebAuthn апаратний токен)
  - `x₄ = 0.90` (робочий час 11:30, звичний профіль)
  - `x₅ = 1.0` (чистий публічний IP)
- Апріорна ймовірність компрометації облікового запису: `P(C) = 0.001` (один випадок на 1000 сесій).

Розрахунок початкового індексу довіри:

```
T₀
= 100 · (0.30·1.0 + 0.20·0.95 + 0.25·1.0 + 0.15·0.90 + 0.10·1.0)  [зважування факторів]
= 100 · (0.30 + 0.19 + 0.25 + 0.135 + 0.10)                       [поелементне множення]
= 100 · 0.975                                                      [сума вагових вкладів]
= 97.5                                                            [стан: Довіра максимальна, доступ дозволено]
```

---

**Подія під час сесії (t = 45 хв):**
Користувач надіслав запит на експорт 50 000 платіжних карток, перебуваючи на новій IP-адресі іншого провайдера (подія `E₁`). 
Статистичні ймовірності такої поведінки:
- Для зловмисника: `P(E₁ | C) = 0.80` (типова ексфільтрація бази)
- Для легітимного інженера: `P(E₁ | C̄) = 0.0004` (експорт заборонено регламентом)

Обчислення логарифмічного відношення шансів та нової ймовірності:

```
logit(P(C))
= ln(0.001 / 0.999)    [підстановка апріорної ймовірності P(C)]
= ln(0.001001)         [розрахунок відношення шансів]
= -6.907               [натуральний логарифм апріорного шансу]

Λ(E₁)
= ln(0.80 / 0.0004)    [відношення правдоподібностей спостережуваної події]
= ln(2000)             [співвідношення частот події]
= 7.601                [вага доказу події]

logit(P(C | E₁))
= -6.907 + 7.601       [додавання ваги доказу до апріорного шансу]
= 0.694                [апостеріорний логіт компрометації]

P(C | E₁)
= 1 / (1 + exp(-0.694))   [перехід від логіту до апостеріорної ймовірності]
= 1 / (1 + 0.4996)        [обчислення експоненти]
= 0.6669                  [ймовірність компрометації підскочила до 66.7%]
```

Оновлені ознаки контексту в момент `t = 45 хв`:
- `x₂ = 0.30` (нова неперевірена підмережа)
- `x₄ = 0.05` (масова аномальна вибірка даних з бази)
- Вето-коефіцієнт спрацьовує через аномальну поведінку: `v₄(0.05) ≈ 0.20`

Перерахунок динамічного індексу довіри `T(45)`:

```
T_linear
= 0.30·1.0 + 0.20·0.30 + 0.25·1.0 + 0.15·0.05 + 0.10·1.0   [оновлене лінійне зважування]
= 0.30 + 0.06 + 0.25 + 0.0075 + 0.10                       [поелементне множення]
= 0.7175                                                   [сума]

T(45)
= 100 · 0.7175 · v₄(0.05) · (1 - P(C | E₁))                 [застосування вето та байєсової ймовірності]
= 100 · 0.7175 · 0.20 · (1 - 0.6669)                        [підстановка штрафного множника]
= 100 · 0.7175 · 0.20 · 0.3331                              [підсумкове множення]
= 4.78                                                      [стан: Критичний рівень загрози]
```

### Граничні пороги рішень рушія політик (PDP Matrix)

На основі розрахованого значення `T(t)` точка ухвалення рішень застосовує ступінчасту шкалу дій:

| Діапазон `T(t)` | Рівень довіри | Рішення PDP | Дія точки застосування (PEP) |
|---|---|---|---|
| **85 – 100** | Високий | `ALLOW` | Безперешкодний доступ до всіх дозволених API |
| **60 – 84** | Середній | `RESTRICTED` | Доступ лише до читання некритичних ресурсів |
| **30 – 59** | Низький | `STEP_UP_MFA` | Запит повторної біометричної верифікації через WebAuthn |
| **0 – 29** | Критичний | `TERMINATE` | Негайний відклик токена, розірвання сесії та сповіщення SOC |

У наведеному прикладі `T(45) = 4.78 < 30`, що призводить до миттєвого анулювання активного сесійного токена, примусового закриття сокета mTLS та блокування облікового запису до з'ясування обставин командою реагування на інциденти.
