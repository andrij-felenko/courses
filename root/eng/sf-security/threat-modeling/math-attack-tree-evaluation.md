# 🧮 Кількісний аналіз і булева алгебра дерев атак

Дерево атак дозволяє вийти за межі суто якісного опису загроз і побудувати формальну математичну модель поведінки нападника. Представивши цілі та вектори зламу у вигляді орієнтованого графа або дерева з логічними операторами, інженер може розрахувати ймовірність успіху атаки, мінімальний бюджет нападника, очікувану вигоду та знайти мінімальний розріз системи (англ. *minimal cut set*), який гарантовано нейтралізує загрозу з найменшими витратами на захист.

## Формальне визначення графа атак

Дерево атак формалізується як спрямоване ациклічне дерево `T = (V, E, L, g)`, де:
- `V` — скінченна множина вузлів (цілей та підцілей атаки);
- `E ⊂ V × V` — множина спрямованих ребер декомпозиції;
- `r ∈ V` — унікальний кореневий вузол (головна мета зловмисника);
- `L ⊂ V` — підмножина листкових вузлів (атомарні дії, які нападник виконує безпосередньо);
- `g: V \ L → {AND, OR}` — логічна функція типу вузла.

Для кожного проміжного вузла `v ∈ V \ L` позначимо множину його безпосередніх нащадків як `Children(v) = {u ∈ V | (v, u) ∈ E}`.

Кожен листковий вузол `l ∈ L` має вектор вимірних числових атрибутів:
- `c(l) ∈ ℝ⁺` — грошова вартість виконання атомарної атаки (бюджет зловмисника в доларах або гривнях);
- `p(l) ∈ [0, 1]` — апріорна ймовірність успіху атаки за умови виділення необхідних ресурсів;
- `t(l) ∈ ℝ⁺` — необхідний час виконання (у годинах чи днях);
- `s(l) ∈ {1, 2, 3, 4}` — необхідний рівень кваліфікації нападника (1 — скрипт-кідді, 2 — практик, 3 — експерт, 4 — спецслужба з необмеженим ресурсом).

## Знизу догори: розрахунок вартості та ймовірності

Обчислення атрибутів для складних цілей виконується рекурсивно від листків до кореня (підхід «знизу догори», англ. *bottom-up evaluation*).

### 1. Агрегація мінімальної вартості атаки `C(v)`

Раціональний нападник намагається мінімізувати власні витрати. Тому на розгалуженнях типу **OR** він обирає найдешевший з доступних векторів, а на вузлах типу **AND** зобов'язаний профінансувати всі обов'язкові етапи:

```
C(l) = c(l)                                              [базовий випадок для листка l ∈ L]
C(v) = min { C(u) | u ∈ Children(v) }                    [якщо g(v) = OR]
C(v) = ∑ { C(u) | u ∈ Children(v) }                      [якщо g(v) = AND]
```

### 2. Агрегація ймовірності успіху `P(v)`

Припускаючи взаємну статистичну незалежність виконання окремих атомарних дій у різних гілках, імовірність досягнення проміжної та кореневої мети обчислюється за законами теорії ймовірностей:

- Для вузла **AND** успіх вимагає одночасного успіху всіх нащадків (добуток незалежних подій):
```
P(v) = ∏ { P(u) | u ∈ Children(v) }                      [якщо g(v) = AND]
```

- Для вузла **OR** успіх настає, якщо спрацює хоча б один вектор атаки. Ймовірність протилежної події (всі атаки зазнали невдачі) дорівнює добутку ймовірностей провалу кожної гілки:
```
P(v) = 1 - ∏ { (1 - P(u)) | u ∈ Children(v) }            [якщо g(v) = OR]
```

### 3. Необхідний рівень майстерності `S(v)`

Рівень кваліфікації визначається найскладнішою ланкою на шляху атаки:
```
S(l) = s(l)                                              [базовий випадок для листка l ∈ L]
S(v) = min { S(u) | u ∈ Children(v) }                    [якщо g(v) = OR: вибір найпростішого шляху]
S(v) = max { S(u) | u ∈ Children(v) }                    [якщо g(v) = AND: вузьке місце за навичками]
```

## Функція корисності нападника та економічна доцільність

Нападник розпочинає атаку лише за умови, що його очікувана вигода перевищує вкладені кошти. Нехай `G` — фінансова або репутаційна вигода, яку нападник отримує в разі досягнення кореневої мети `r` (наприклад, сума викрадених коштів або вартість бази даних на чорному ринку).

Математичне сподівання чистого прибутку нападника (функція очікуваної корисності `U`) для конкретного обраного шляху атаки визначається рівнянням:

```
U = P(r) · G - C(r)
```

Критерій інженерної захищеності системи формулюється наступним чином:
```
U ≤ 0   або   C(r) > P(r) · G
```
Якщо для всіх можливих гілок дерева атак очікувана вигода від'ємна (`U < 0`), раціональний комерційний нападник відмовиться від спроби зламу на користь легших цілей.

## Повний покроковий числовий приклад

Розглянемо дерево атак для сценарію «Несанкціоноване переведення коштів з рахунку підприємства». Нехай потенційна сума викрадення становить `G = 1 000 000` грн.

Структура дерева має вигляд:
- Корінь `R` [OR]: Переказ 1 000 000 грн.
  - Гілка `A` [AND]: Підробка внутрішнього платіжного API-запиту.
    - Листок `L1`: Отримання API-ключа через таргетований фішинг розробника.
      - `c(L1) = 25 000` грн, `p(L1) = 0.20`, `s(L1) = 2`
    - Листок `L2`: Обхід IP-білого списку через підміну BGP-маршруту або VPN.
      - `c(L2) = 15 000` грн, `p(L2) = 0.30`, `s(L2) = 3`
  - Гілка `B` [AND]: Пряма модифікація балансу через SQL-ін'єкцію.
    - Листок `L3`: Виявлення сліпої SQL-ін'єкції у звітному модулі.
      - `c(L3) = 10 000` грн, `p(L3) = 0.10`, `s(L3) = 2`
    - Листок `L4`: Обхід сигнатурного WAF через генерацію поліморфного payload.
      - `c(L4) = 20 000` грн, `p(L4) = 0.25`, `s(L4) = 3`

### Крок 1. Розрахунок показників гілки `A` (Вузол AND)

```
C(A)
= C(L1) + C(L2)                                          [правило суми для AND]
= 25000 + 15000
= 40000 грн

P(A)
= P(L1) · P(L2)                                          [добуток незалежних подій для AND]
= 0.20 · 0.30
= 0.060 (6.0%)

S(A)
= max(s(L1), s(L2))                                      [максимум вимог до майстерності]
= max(2, 3)
= 3 (експерт)
```

Очікувана вигода нападника за вибору гілки `A`:
```
U(A)
= P(A) · G - C(A)                                         [формула очікуваної корисності]
= 0.060 · 1000000 - 40000                                 [підстановка параметрів гілки]
= 60000 - 40000                                           [розрахунок сподіваного доходу]
= +20 000 грн                                             [підсумкова вигода нападника]
```

Оскільки `U(A) = +20 000 > 0`, атака через гілку `A` є економічно привабливою для зловмисника.

### Крок 2. Розрахунок показників гілки `B` (Вузол AND)

```
C(B)
= C(L3) + C(L4)                                          [правило суми для AND]
= 10000 + 20000
= 30000 грн

P(B)
= P(L3) · P(L4)                                          [добуток незалежних подій для AND]
= 0.10 · 0.25
= 0.025 (2.5%)

S(B)
= max(s(L3), s(L4))                                      [максимум вимог до майстерності]
= max(2, 3)
= 3 (експерт)
```

Очікувана вигода нападника за вибору гілки `B`:
```
U(B)
= P(B) · G - C(B)                                         [формула очікуваної корисності]
= 0.025 · 1000000 - 30000                                 [підстановка параметрів гілки]
= 25000 - 30000                                           [розрахунок сподіваного доходу]
= -5 000 грн                                              [підсумковий збиток нападника]
```

Для гілки `B` очікувана вигода є від'ємною (`-5 000` грн). Раціональний зловмисник відкине цей шлях і зосередиться на гілці `A`.

### Крок 3. Агрегація для кореневого вузла `R` (Вузол OR)

Якщо нападник має можливість атакувати за обома напрямками одночасно або обирає найкращий:

```
C(R)
= min(C(A), C(B))                                        [найдешевший шлях]
= min(40000, 30000)
= 30000 грн

P(R)
= 1 - (1 - P(A)) · (1 - P(B))                            [загальна ймовірність успіху хоча б однієї атаки]
= 1 - (1 - 0.060) · (1 - 0.025)
= 1 - 0.940 · 0.975
= 1 - 0.9165
= 0.0835 (8.35%)
```

## Математика захисту: пошук мінімального розрізу (Minimal Cut Set)

Завдання архітектора безпеки полягає в протилежному: знайти такий мінімальний набір листкових вузлів `K ⊂ L`, блокування яких робить досягнення кореня `R` неможливим (`P(R) = 0`), мінімізуючи вартість впровадження контрзаходів `Cost(K)`.

Нехай вартість впровадження захисту на вузлах складає:
- `M(L1)` (впровадження апаратних FIDO2-ключів проти фішингу): `12 000` грн;
- `M(L2)` (перехід на mTLS з взаємною сертифікацією вузлів): `8 000` грн;
- `M(L3)` (параметризація всіх SQL-запитів в ORM): `5 000` грн;
- `M(L4)` (впровадження WAF нового покоління з аналізом поведінки): `22 000` грн.

Для того щоб заблокувати вузол **AND**, достатньо перекрити **хоча б один** з його дочірніх листків. Для блокування вузла **OR** необхідно заблокувати **всі** його гілки.

Множина допустимих розрізів для кореня `R` включає 4 комбінації:
1. `K1 = {L1, L3}`: `Cost(K1) = 12000 + 5000 = 17 000` грн.
2. `K2 = {L1, L4}`: `Cost(K2) = 12000 + 22000 = 34 000` грн.
3. `K3 = {L2, L3}`: `Cost(K3) = 8000 + 5000 = 13 000` грн.
4. `K4 = {L2, L4}`: `Cost(K4) = 8000 + 22000 = 30 000` грн.

Шляхом прямої оптимізації знаходимо глобальний мінімум:
```
min Cost(K) = Cost(K3) = Cost(L2) + Cost(L3) = 13 000 грн
```

**Висновок математичного аналізу:** Замість витрачання 47 000 грн на всі можливі засоби захисту або купівлі дорогого WAF за 22 000 грн, оптимальним інженерним рішенням є інвестиція 13 000 грн у дві конкретні точки: параметризацію SQL-запитів (`L3`) та впровадження mTLS між сервісами (`L2`). Це повністю перериває обидва вектори атак у дереві, зводячи ймовірність компрометації кореневої мети до нуля.
