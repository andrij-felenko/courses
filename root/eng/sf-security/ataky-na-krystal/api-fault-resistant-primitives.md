# 📋 Інтерфейс та специфікація примітивів захисту від апаратних збоїв

Ця специфікація визначає апаратні регістри контролю фізичної цілісності кристала мікроконтролера та програмний інтерфейс (C/C++ API) модуля захисту від апаратних збоїв (Fault Injection) і побічних каналів (Side-Channel Attacks).

## 1. Карта регістрів апаратного блоку захисту (Silicon Tamper & Glitch Controller)

Базова адреса периферійного блоку захисту кристала: `TAMPER_GLITCH_BASE = 0x40028000`. Усі регістри мають розрядність 32 біти та вимагають строго вирівняного 32-бітного доступу. Будь-яка спроба 8-бітного або 16-бітного звернення генерує апаратний виняток `BusFault`.

| Зміщення | Назва регістру | Повна назва | Доступ | Значення після скиду |
|---|---|---|---|---|
| `0x00` | `GLITCH_CR` | Glitch Detector Control Register | R/W | `0x00000000` |
| `0x04` | `GLITCH_SR` | Glitch Detector Status Register | R/W1C | `0x00000000` |
| `0x08` | `GLITCH_THRESH` | Glitch Threshold Configuration | R/W | `0x00000305` |
| `0x0C` | `SHIELD_CR` | Active Metal Shield Control | R/W | `0x00000000` |
| `0x10` | `SHIELD_SR` | Active Metal Shield Status | R | `0x00000001` |
| `0x14` | `TAMPER_WIPE_CR` | Emergency Zeroization Controller | R/W | `0x00000000` |
| `0x18` | `ROSC_JITTER_CR` | Ring Oscillator Jitter Generator | R/W | `0x00000000` |
| `0x1C` | `PANIC_LATCH_SR` | Hardware Security Latch Status | R | `0x00000000` |

### 1.1 Деталізація бітових полів та електричних параметрів

#### Регістр конфігурації детектора збоїв `GLITCH_CR` (Offset `0x00`)

```text
31             16 15      12 11   8 7   6 5   4 3   2 1   0
┌────────────────┬──────────┬──────┬─────┬─────┬─────┬─────┬───┐
│    RESERVED    │ V_WINDOW │ FLT  │ LFI │ CLK │ BOR │ IRQ │ EN│
└────────────────┴──────────┴──────┴─────┴─────┴─────┴─────┴───┘
```

- `EN` (Bit 0): Головний дозвіл роботи аналогового детектора збоїв. `0` — модуль вимкнено, `1` — активний безперервний моніторинг.
- `IRQ` (Bit 1): Тип реакції на виявлений збій. `0` — негайний апаратний скид процесорного ядра (Hardware Reset), `1` — генерація немаскованого переривання безпеки `NMI`.
- `BOR` (Bit 2): Дозвіл роботи швидкісної схеми Brown-Out Reset із часом спрацьовування менше 5 нс.
- `CLK` (Bit 3): Активація монітора тривалості тактових імпульсів. Відсікає імпульси з тривалістю `t_high < 4.5 нс` або `t_low < 4.5 нс`.
- `LFI` (Bit 4): Активація внутрішньої матриці кремнієвих фотодіодів для захисту від лазерного опромінення.
- `FLT` (Bits 8..11): Налаштування цифрового деглатч-фільтра для придушення комутаційного шуму шин живлення (тривалість від 0 до 15 тактів ядра).
- `V_WINDOW` (Bits 12..15): Ширина допустимого діапазону напруги ядра `Vdd_core` (від `0x0` — ±5% до `0xF` — ±25% від номінального 1.20 В).

#### Регістр статусу збоїв `GLITCH_SR` (Offset `0x04`)

Усі прапорці статусу очищаються записом одиниці (Read / Write-1-to-Clear).

- `VOLT_GLITCH_F` (Bit 0): Зафіксовано різке просідання або сплеск напруги живлення ядра з похідною `|dV/dt| > THRESH`.
- `CLOCK_GLITCH_F` (Bit 1): Зафіксовано порушення мінімальної тривалості тактового імпульсу.
- `LASER_DETECT_F` (Bit 2): Фотодіоди кристала зафіксували надлишковий фотострум (декапсуляція або оптичний імпульс).
- `OVER_VOLT_F` (Bit 3): Напруга живлення перевищила абсолютний максимум 1.45 В.
- `TAMPER_LATCH_F` (Bit 4): Апаратна фіксація вторгнення. Блокує доступ до криптографічних прискорювачів до повного зняття живлення.

#### Регістр конфігурації порогів `GLITCH_THRESH` (Offset `0x08`)

- `DV_DT_FALL` (Bits 0..7): Поріг чутливості до швидкості спаду напруги живлення (від 0.1 В/нс до 1.5 В/нс з кроком 0.05 В/нс).
- `DV_DT_RISE` (Bits 8..15): Поріг чутливості до швидкості сплеску напруги.
- `PULSE_MIN_LEN` (Bits 16..23): Мінімально допустима тривалість тактового імпульсу в пікосекундах (за замовчуванням 4500 пс).

#### Регістр активного металевого екрана `SHIELD_CR` (Offset `0x0C`)

- `SHIELD_EN` (Bit 0): Увімкнення генерації динамічного псевдовипадкового коду PRNG на провідниках шарів металізації M6/M7.
- `POLY_SEL` (Bits 4..7): Вибір генераторного полінома PRNG для зміни частотного спектра тестового сигналу.
- `AUTO_ZEROIZE` (Bit 8): Дозвіл автоматичного апаратного занулення батарейної пам'яті BBRAM за 1 такт при виявленні обриву чи замикання сітки.
- `INTEG_CHECK_DIV` (Bits 16..23): Дільник базової частоти перевірки цілісності екрана (від 1 до 256 тактів).

#### Регістр екстреного занулення `TAMPER_WIPE_CR` (Offset `0x14`)

- `FORCE_WIPE` (Bit 0): Програмна ініціалізація миттєвого занулення. Для активації вимагає попереднього запису магічного ключа розблокування `0xA55A1234` у регістр `TAMPER_WIPE_KEY`.
- `WIPE_SRAM` (Bit 1): Дозвіл автоматичного очищення внутрішньої оперативної пам'яті SRAM ядра при спрацьовуванні сенсорів.
- `WIPE_BBRAM` (Bit 2): Дозвіл очищення енергонезалежної батарейної пам'яті зберігання кореневих криптографічних ключів.
- `LOCK_INTERFACES` (Bit 3): Блокування зовнішніх інтерфейсів програмування JTAG, SWD та послідовних портів UART/SPI.

#### Регістр джитування генератора `ROSC_JITTER_CR` (Offset `0x18`)

- `JITTER_EN` (Bit 0): Увімкнення апаратної модуляції тактової частоти внутрішнього кільцевого генератора.
- `MOD_DEPTH` (Bits 4..7): Глибина фазової модуляції частоти (від ±1% до ±12% від номінальної частоти ядра).
- `ENTROPY_SRC` (Bits 8..9): Вибір джерела ентропії для модулятора (00: вбудований TRNG, 01: PRNG на базі LFSR).

## 2. Специфікація програмного інтерфейсу (C/C++ API)

### 2.1 Константи багатозначних токенів безпеки

:::tabs
```c
#include <stdint.h>

typedef uint32_t secure_token_t;

#define SECURE_TOKEN_TRUE      ((secure_token_t)0x55AA55AAU)
#define SECURE_TOKEN_FALSE     ((secure_token_t)0xAA55AA55U)
#define SECURE_TOKEN_INIT      ((secure_token_t)0x3C3C3C3CU)
#define SECURE_TOKEN_PANIC     ((secure_token_t)0xFFFFFFFFU)
```
```cpp
#include <cstdint>

namespace sec {

enum class Token : std::uint32_t {
    True  = 0x55AA55AAU,
    False = 0xAA55AA55U,
    Init  = 0x3C3C3C3CU,
    Panic = 0xFFFFFFFFU
};

} // namespace sec
```
:::

**Інваріант надійності:** бінарна інверсія між станами:
```text
SECURE_TOKEN_TRUE ^ SECURE_TOKEN_FALSE = 0xFFFFFFFF
Hamming_Distance(SECURE_TOKEN_TRUE, SECURE_TOKEN_FALSE) = 32
```

---

### 2.2 Програмні примітиви та криптографічні функції

#### `hardened_memcmp`
Порівняння двох блоків пам'яті з гарантовано постійним часом виконання.

:::tabs
```c
#include <stdint.h>
#include <stddef.h>

secure_token_t hardened_memcmp(const void *buf_a, const void *buf_b, size_t len);
```
```cpp
#include <cstdint>
#include <cstddef>
#include <span>

namespace sec {

[[nodiscard]] Token constant_time_compare(std::span<const std::uint8_t> a,
                                          std::span<const std::uint8_t> b) noexcept;

} // namespace sec
```
:::

- **Параметри:**
  - `buf_a`: Вказівник на перший блок пам'яті (обчислений хеш або підпис). Не може бути `NULL`.
  - `buf_b`: Вказівник на другий блок пам'яті (еталонний сертифікат). Не може бути `NULL`.
  - `len`: Кількість байтів для порівняння.
- **Повернене значення:**
  - `SECURE_TOKEN_TRUE` (`Token::True`): Усі `len` байтів абсолютно однакові.
  - `SECURE_TOKEN_FALSE` (`Token::False`): Виявлено розбіжність щонайменше в одному біті, або передано `NULL`.
- **Часова поведінка:** `O(len)`, суворо константна тривалість без дострокового виходу при першій розбіжності.

---

#### `hardened_verify_payload`
Комплексна двоетапна верифікація з контролем цілісності потоку виконання (Control Flow Integrity) та програмним джитуванням.

:::tabs
```c
#include <stdint.h>
#include <stddef.h>

secure_token_t hardened_verify_payload(const uint8_t *computed_mac,
                                       const uint8_t *expected_mac,
                                       size_t mac_len,
                                       uint32_t entropy);
```
```cpp
#include <cstdint>
#include <cstddef>
#include <span>

namespace sec {

class HardenedVerifier {
public:
    [[nodiscard]] static Token verify(std::span<const std::uint8_t> computed,
                                      std::span<const std::uint8_t> expected,
                                      std::uint32_t entropy) noexcept;
};

} // namespace sec
```
:::

- **Параметри:**
  - `computed_mac`: Буфер обчисленого імітовідбитка або підпису.
  - `expected_mac`: Буфер очікуваного еталона.
  - `mac_len`: Довжина криптографічного тегу в байтах.
  - `entropy`: 32-бітне псевдовипадкове число від апаратного TRNG для рандомізації часових затримок.
- **Вимоги до оточення (Preconditions):**
  - Апаратний блок TRNG має бути попередньо ініціалізований.
- **Пост-умови (Postconditions):**
  - Якщо внаслідок ін'єкції збою пропущено інструкцію або спотворено канарейку, функція не повертає керування, а виконує перехід у `secure_panic_trap()`.
- **Повертає:**
  - `SECURE_TOKEN_TRUE` виключно за умови успішного проходження обох взаємно зворотних перевірок та збігу всіх контрольних сум.

---

#### `secure_zeroize`
Гарантоване занулення буферів пам'яті без оптимізаційного видалення компілятором.

:::tabs
```c
#include <stddef.h>

void secure_zeroize(void *ptr, size_t len);
```
```cpp
#include <cstddef>
#include <span>
#include <cstdint>

namespace sec {

void secure_zeroize(std::span<std::uint8_t> buffer) noexcept;

} // namespace sec
```
:::

- **Параметри:**
  - `ptr`: Вказівник на чутливу пам'ять (ключі, паролі, вектори ініціалізації).
  - `len`: Розмір пам'яті в байтах.
- **Механізм надійності:** використання покажчиків типу `volatile` та апаратного бар'єра пам'яті `__asm__ volatile("" ::: "memory")`, що запобігає оптимізації *Dead Store Elimination*.

---

#### `secure_panic_trap`
Аварійний обробник перехоплення фізичного втручання в кристал.

:::tabs
```c
__attribute__((noreturn)) void secure_panic_trap(void);
```
```cpp
namespace sec {

[[noreturn]] void panic_trap() noexcept;

} // namespace sec
```
:::

- **Послідовність виконання операцій:**
  1. Блокування всіх апаратних переривань (`CPSID I`).
  2. Занулення внутрішніх регістрів ядра `R0`–`R12`, `LR`.
  3. Активація біта `FORCE_WIPE` у регістрі `TAMPER_WIPE_CR` для стирання ключів у BBRAM.
  4. Переведення процесора в нескінченний режим низького енергоспоживання `WFI` (Wait For Interrupt) без можливості виходу.

## 3. Матриця станів та життєвий цикл безпечного завантаження

Процес ініціалізації системи захисту кристала підпорядковується кінцевому автомату станів (FSM), реалізованому на апаратно-програмному рівні:

```text
[ Power-On Reset ]
        │
        ▼
[ 1. Апаратний самотест (BIST) ] ──(Помилка сенсора)──> [ Незворотне блокування ]
        │
        ▼
[ 2. Активація екрана M6/M7 та BOR ]
        │
        ▼
[ 3. Увімкнення джитування ROSC ]
        │
        ▼
[ 4. Hardened Secure Boot ] ───────(Збій/Підробка)────> [ Панічний капкан: Wipe ]
        │
        ▼ (SECURE_TOKEN_TRUE)
[ 5. Запуск основної прошивки ]
```

### Деталізація станів безпеки

1. **Power-On Reset:** початковий запуск живлення. Периферійні інтерфейси налагодження SWD/JTAG автоматично блокуються апаратною логікою за замовчуванням (Default Closed).
2. **Вбудоване самотестування (BIST):** перевірка цілісності внутрішніх опорних джерел Bandgap, сенсорів температури та аналогових компараторів. Будь-яке відхилення понад ±5% переводить кристал у стан перманентного апаратного блокування.
3. **Активація активного екрана:** на провідники шарів M6/M7 подається псевдовипадковий тестовий сигнал. Вмикаються аналогові монітори `dV/dt` та оптичні фотодіоди.
4. **Увімкнення джитування такту:** системне тактування перемикається на внутрішній кільцевий генератор ROSC із випадковою модуляцією частоти, що унеможливлює зовнішню синхронізацію осцилографа для атак DPA.
5. **Hardened Secure Boot:** виконання процедури перевірки цифрового підпису прошивки з використанням захищених багатозначних токенів і крокових канарейок цілісності.
6. **Штатне виконання:** передача керування перевіреному образу програми зі збереженням фонового моніторингу фізичних сенсорів цілісності кристала.

## 4. Матриця реакції системи на фізичні аномалії

| Аномалія / Збій | Джерело виявлення | Первинна реакція заліза | Реакція програмного рівня |
|---|---|---|---|
| **Просідання Vdd < 0.7 В на 20 нс** | Апаратний компаратор `GLITCH_CR` | Генерація `NMI` або миттєвий Reset | Перехоплення в `NMI_Handler`, виклик `secure_panic_trap()` |
| **Пропуск інструкції виклику функції** | Програмна канарейка `STEP_CANARY` | Відсутня (ядро виконує NOP) | Невідповідність `canary != expected`, перехід у панічний капкан |
| **Зміна біта статусу в регістрі** | Багатозначний токен `secure_token_t` | Відсутня | Токен не дорівнює `TRUE` і не дорівнює `FALSE` -> `panic_trap()` |
| **Опромінення кристала лазером** | Матриця фотодіодів `LFI` | Апаратне занулення BBRAM | `LASER_DETECT_F` викликає HardFault і блокування |
| **Спроба мікрозондування шин** | Активний екран `SHIELD_CR` | Апаратний обрив лінії PRNG | Миттєве блокування шини пам'яті, Tamper Latch |
| **Підвищення Vdd > 1.45 В (Over-voltage)** | Віконний компаратор `GLITCH_CR` | Апаратний скид шини живлення | Занулення регістрів та перехід у безпечний режим |
| **Високочастотний джиттер такту** | Монітор такту `PULSE_MIN_LEN` | Поглинання збійного імпульсу | Фіксація прапорця `CLOCK_GLITCH_F` |
