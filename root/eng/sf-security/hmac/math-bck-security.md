# 🧮 Математична модель Bellare-Canetti-Krawczyk: доведення стійкості HMAC як псевдовипадкової функції

Математичне обґрунтування надійності коду автентичності HMAC ґрунтується на формальній редукції безпеки, яка доводить: будь-який ефективний алгоритм злому HMAC автоматично означає порушення базових псевдовипадкових властивостей функції стиснення або побудову колізій внутрішнього стану при таємному векторі ініціалізації.

## Формальні моделі безпеки: EUF-CMA та PRF

У сучасній криптографії стійкість коду автентичності повідомлень оцінюють за двома взаємопов'язаними критеріями: екзистенційною непідроблюваністю та псевдовипадковістю.

### 1. Непідроблюваність за обраного відкритого тексту (EUF-CMA)

Модель EUF-CMA (англ. *Existential Unforgeability under Chosen-Message Attack*) описує здатність супротивника `A` підробити тег для нового повідомлення:

1. Оракул обирає випадковий таємний ключ `K` із простору ключів `𝒦`.
2. Супротивник `A` отримує доступ до оракула автентифікації та виконує `q` запитів для довільно обраних повідомлень `m₁, m₂, ..., m_q`, отримуючи валідні теги `t_i = MAC_K(m_i)`.
3. Супротивник перемагає, якщо створює пару `(m*, t*)`, де `t* = MAC_K(m*)`, за умови, що повідомлення `m*` ніколи не запитувалося в оракула раніше (`m* ∉ {m₁, ..., m_q}`).

Перевага супротивника (англ. *advantage*) у фальсифікації підпису позначається як `Adv_MAC^forge(A)` і визначається ймовірністю виграшу:

```
Adv_MAC^forge(A) = Pr[ Verify_K(m*, t*) = 1 ∧ m* ∉ {m₁, ..., m_q} ]
```

### 2. Псевдовипадкова функція (PRF)

Сильнішою криптографічною властивістю є невідрізненність виходів коду від ідеального випадкового оракула (англ. *Pseudorandom Function*, PRF).

Нехай `F_K: {0,1}* → {0,1}^L` — функція з ключем `K`, а `R: {0,1}* → {0,1}^L` — абсолютно випадкова функція (випадковий оракул), яка для кожного нового запиту повертає незалежну, рівномірно розподілену послідовність із `L` бітів.

Супротивник `A` має доступ до «чорного ящика», що містить або `F_K`, або `R`. Його мета — після серії з `q` запитів видати біт `1`, якщо він вважає, що працює з `F_K`, і `0` — якщо з `R`.

Перевага розрізнення визначається різницею ймовірностей:

```
Adv_F^prf(A) = | Pr[A^(F_K) = 1] - Pr[A^R = 1] |
```

Якщо для будь-якого алгоритму `A`, що працює за поліноміальний час `t` і робить `q` запитів, значення `Adv_F^prf(A)` є знехтовно малим, функція `F` є криптографічно стійкою PRF. Будь-яка стійка PRF автоматично гарантує стійкість коду автентичності EUF-CMA: здатність підробити новий тег негайно дала б спосіб відрізнити функцію від випадкової.

## Конструкція NMAC як теоретичний фундамент

Для аналізу вкладеної структури Белларе, Канетті та Кравчик (1996) ввели абстрактну схему **NMAC** (англ. *Nested MAC*), яка оперує двома незалежними випадковими ключами `K₁` та `K₂` довжиною `L` бітів.

Нехай `f: {0,1}^L × {0,1}^B → {0,1}^L` — базова функція стиснення геш-функції, де перший аргумент є вектором стану (довжиною `L`), а другий — блоком повідомлення (довжиною `B`).

Ітеративне розширення Меркле — Дамґорда на послідовність блоків `m = (m₁, m₂, ..., m_n)` позначається як `f*`:

```
h₀ = K₁                                 [ініціалізація таємним ключем K₁]
h_i = f(h_(i-1), m_i)                   [стискання блоків для i = 1, 2, ..., n]
f*(K₁, m) = h_n                         [фінальний вектор стану]
```

Схема NMAC визначається як суперпозиція двох викликів `f`:

```
NMAC_(K₁, K₂)(m) = f( K₂, f*(K₁, m) || pad_out )
```

Тут внутрішній каскад `f*(K₁, m)` стискає повідомлення `m` довільної довжини у `L`-бітний вектор стану за допомогою першого таємного ключа `K₁`. Зовнішній виклик функції `f` бере цей `L`-бітний вектор, доповнює його фіксованим заповненням `pad_out` до розміру повного блока `B` і обробляє за допомогою другого ключа `K₂`.

## Теорема стійкості NMAC (Редукція BCK)

Головна теорема Белларе, Канетті та Кравчика зводить безпеку NMAC до двох ізольованих математичних властивостей базової функції стиснення `f`.

### Умови теореми:

1. **Функція стиснення як PRF.** Функція `f` при використанні першого аргументу як ключа є стійкою псевдовипадковою функцією `f: {0,1}^L × {0,1}^B → {0,1}^L`. Перевага розрізнення позначається `Adv_f^prf`.
2. **Слабка стійкість до колізій (WCR).** Ітеративна функція `f*` є слабкостійкою до колізій (англ. *Weakly Collision-Resistant*, WCR). Це означає, що супротивнику складно знайти два різні повідомлення `m₁ ≠ m₂`, такі що `f*(K₁, m₁) = f*(K₁, m₂)`, коли ключ `K₁` є таємним і випадковим. Перевага позначається як `Adv_(f*)^wcr`.

### Формулювання теореми:

Для будь-якого розрізнювача `A` проти NMAC, що виконує `q` запитів сумарною довжиною не більше `σ` блоків за час `t`, існує розрізнювач `A₁` для функції `f` та алгоритм пошуку колізій `A₂` для `f*`, такі що:

```
Adv_NMAC^prf(t, q, σ) ≤ Adv_f^prf(t, q) + Adv_f^prf(t, q) + q² · Adv_(f*)^wcr(t, σ)
```

### Покроковий ланцюг доведення через гібридні ігри

Доведення здійснюється методом послідовних ігор (англ. *game-hopping*):

**Гра 0 (Справжня система).** Оракул ініціалізує незалежні випадкові ключі `K₁, K₂ ← {0,1}^L`. Для кожного запиту `m_i` повертається результат:

```
t_i = f(K₂, f*(K₁, m_i) || pad_out)
```

Ймовірність перемоги супротивника: `Pr[S₀] = Pr[A^(Game 0) = 1]`.

**Гра 1 (Усунення внутрішніх колізій).** Оракул обчислює внутрішні стани `h_i = f*(K₁, m_i)`. Нехай `Coll` — подія виникнення хоча б однієї колізії внутрішнього стану:

```
∃ i ≠ j : (m_i ≠ m_j) ∧ (f*(K₁, m_i) = f*(K₁, m_j))
```

Якщо подія `Coll` не відбулася, усі значення `h_i` є попарно різними. За лемою про різницю розподілів:

```
| Pr[S₀] - Pr[S₁] | ≤ Pr[Coll] ≤ (q · (q - 1) / 2) · Adv_(f*)^wcr(t, σ)
```

**Гра 2 (Ідеалізація внутрішнього каскаду).** Оскільки всі вхідні значення `h_i` унікальні, каскад `f*(K₁, ·)` можна замінити ідеальним випадковим генератором унікальних міток `u_i ← {0,1}^L`. Відмінність у поведінці оракула не перевищує переваги розрізнення внутрішньої функції стиснення:

```
| Pr[S₁] - Pr[S₂] | ≤ Adv_f^prf(t, q)
```

**Гра 3 (Ідеалізація зовнішньої функції).** Заміна зовнішньої функції стиснення `f(K₂, ·)` на ідеальну випадкову функцію `R: {0,1}^L → {0,1}^L`. Оскільки всі вхідні аргументи `u_i || pad_out` є унікальними, функція `R` для кожного запиту видає незалежне, рівномірне випадкове значення. Відмінність між Грою 2 і Грою 3 обмежена стійкістю зовнішньої PRF:

```
| Pr[S₂] - Pr[S₃] | ≤ Adv_f^prf(t, q)
```

У Грі 3 оракул є ідеальною випадковою функцією, де ймовірність розрізнення дорівнює нулю (`Pr[S₃] = Pr[A^R = 1]`).

Об'єднуючи нерівності за правилом трикутника:

```
Adv_NMAC^prf
= | Pr[S₀] - Pr[S₃] |                    [визначення переваги]
≤ | Pr[S₀] - Pr[S₁] | + | Pr[S₁] - Pr[S₂] | + | Pr[S₂] - Pr[S₃] |  [нерівність трикутника]
≤ q² · Adv_(f*)^wcr + Adv_f^prf + Adv_f^prf                         [підстановка оцінок ігор]
= 2 · Adv_f^prf + q² · Adv_(f*)^wcr                                [підсумок компонентів]
```

Це математично доводить: безпека NMAC вимагає від базової функції `f` лише властивості псевдовипадковості та неможливості знаходження колізій при невідомому початковому ключі `K₁`.

## Відмінність між WCR та класичною стійкістю до колізій (CR)

Фундаментальна перевага конструкції BCK полягає в різниці між двома поняттями колізійної стійкості:

1. **Класична стійкість до колізій (Collision Resistance, CR).** Супротивник знає публічний вектор `IV` і шукає два повідомлення `m₁ ≠ m₂` такі, що `H(m₁) = H(m₂)`. Пошук ведеться повністю офлайн без обмежень у кількості обчислень.
2. **Слабка стійкість до колізій на таємному ключі (Weak Collision Resistance, WCR).** Вектор `K₁` є таємним. Супротивник не може обчислювати внутрішній стан офлайн. Єдиний спосіб знайти колізію — надсилати запити до оракула та шукати колізії виходів.

Саме тому атаки Сяоюнь Ван (2004–2005) та проект SHAttered (2017), які зламали класичну стійкість CR для MD5 та SHA-1, виявилися абсолютно безсилими проти HMAC: знайти колізію, коли вектор `IV` замінено таємним випадковим значенням `K₁`, неможливо без повного розкриття самого ключа.

## Деривація ключів у HMAC та роль констант ipad/opad

HMAC усуває потребу у двох незалежних ключах `K₁` і `K₂`, формуючи їх із єдиного майстер-ключа `K` через константи `ipad` (`0x36`) та `opad` (`0x5C`):

```
K₁ = f( IV, (K' ⊕ ipad) )
K₂ = f( IV, (K' ⊕ opad) )
```

Де `K'` — нормалізований ключ довжиною `B` байтів.

### Алгебраїчний аналіз констант ipad та opad

Константи обрані з максимальною відстанню Геммінга:

```
ipad = 0x36 = 00110110₂
opad = 0x5C = 01011100₂
```

Обчислення побітової різниці:

```
ipad ⊕ opad
= 00110110₂ ⊕ 01011100₂   [побітове додавання за модулем 2]
= 01101010₂               [результат XOR]
= 0x6A                    [шістнадцятковий запис]
```

У кожному байті рівно 4 біти з 8 є протилежними. Це гарантує:

1. **Неперетинність просторів станів.** Жодні два блоки `(K' ⊕ ipad)` та `(K' ⊕ opad)` не можуть збігатися за жодного значення `K'`.
2. **Псевдовипадкова незалежність.** Якщо функція стиснення `f(IV, ·)` діє як надійний генератор випадкових бітів відносно вхідного повідомлення (Dual-PRF), субключі `K₁` та `K₂` є обчислювально незалежними.

Повна редукція безпеки HMAC відносно NMAC:

```
Adv_HMAC^prf ≤ Adv_NMAC^prf + 2 · Adv_f^(dual-prf)
```

## Нормалізація ключів: теорема про довгі ключі

Стандарт регламентує попередню обробку ключа:

```
K' = H(K) || 0^(B - L)    [якщо довжина |K| > B]
K' = K || 0^(B - |K|)     [якщо довжина |K| ≤ B]
```

### Чому стискання ключа H(K) безпечне?

Якщо ключ `K` має довжину понад `B` байтів (наприклад, 1024 біти для SHA-256), його пряме додавання з маскою переповнило б перший блок. Заміна `K` на `H(K)` спирається на стійкість геш-функції до пошуку прообразів (англ. *Preimage Resistance*):

1. Ентропія ключа `H(K)` становить `L` бітів (256 бітів для SHA-256), що дорівнює максимальній криптографічній міцності алгоритму.
2. Знайти інший ключ `K* ≠ K`, який дає той самий `K'`, вимагає обернення геш-функції зі складністю `2^L`.
3. Доповнення нулями `0^(B - L)` однозначно фіксує довжину блока та запобігає неоднозначності розбору.

## Парадокс днів народження та часові межі зміни ключів

Імовірність появи внутрішньої колізії після обробки `q` повідомлень за теоремою про дні народження становить:

```
P_collision(q)
= 1 - ∏_(i=1)^(q-1) (1 - i / 2^L)       [точна ймовірність відсутності збігів]
≈ 1 - exp( - q · (q - 1) / (2 · 2^L) )  [наближення Тейлора для малих показників]
≈ q² / (2 · 2^L)                        [лінійна апроксимація експоненти]
= q² / 2^(L + 1)                        [остаточна оцінка ймовірності]
```

Для SHA-256 (`L = 256` бітів):

```
q_max ≈ √( 2 · 2²⁵⁶ · ln(1 / (1 - P)) )
```

При допустимому порозі ризику `P = 2⁻³²`:

```
q_safe ≈ √( 2 · 2²⁵⁶ · 2⁻³² ) = √( 2²²⁵ ) ≈ 2¹¹² повідомлень
```

Це означає, що один і той самий ключ HMAC-SHA256 може безпечно підписати до `2¹¹²` пакетів даних без жодного ризику виникнення внутрішніх колізій, що на багато порядків перевищує технічний ресурс будь-якої сучасної мережевої системи.

## Переглянуте доведення Белларе (2006): безпека без колізійної стійкості

У 2006 році Міхір Белларе опублікував працю «New Proofs for NMAC and HMAC: Security without Collision-Resistance», у якій суттєво послабив початкові припущення теореми 1996 року.

У класичному доведенні 1996 року вимагалося, щоб внутрішній каскад `f*` був слабкостійким до колізій (WCR). Проте практичний злам MD5 та SHA-1 продемонстрував, що стискальні функції реальних алгоритмів не є абсолютно стійкими до пошуку колізій.

Белларе довів, що HMAC залишається стійкою псевдовипадковою функцією за умови, що функція стиснення `f` задовольняє властивість **PRF з блоковим зв'язуванням** (англ. *Prefix-free PRF* або *Chaining PRF*):

1. Якщо функція `f(h, x)` розглядається як PRF, де ключем виступає вектор стану `h`, а аргументом — блок `x`.
2. Навіть якщо супротивник знає або може знайти колізії стискальної функції з публічним `IV`, він не може використати їх для розрізнення виходів HMAC, оскільки проміжний стан `h₁ = f(IV, K' ⊕ ipad)` залишається для нього прихованим і непередбачуваним.
3. Доведення 2006 року показало, що стійкість HMAC не руйнується навіть за наявності практичних колізій у відкритій геш-функції, пояснивши феномен неушкодженості HMAC-MD5 після атак 2004 року.

## Межа стійкості усіченого тегу (Truncated HMAC)

У багатьох високопродуктивних мережевих протоколах (зокрема IPsec та SRTP) повний 256-бітний або 512-бітний вихід HMAC зрізають до перших `t` бітів (наприклад, `t = 96` або `t = 128` бітів) для економії пропускної здатності каналу.

Формальний аналіз безпеки усіченого HMAC дає таку верхню межу переваги супротивника у фальсифікації підпису:

```
Adv_(Trunc-HMAC)^forge(t, q_s, q_v) ≤ Adv_HMAC^prf(t, q_s + q_v) + q_v / 2^t
```

Де:
- `q_s` — кількість запитів на генерацію підпису до легітимного оракула (Signing Queries).
- `q_v` — кількість спроб підробки, надісланих на перевірку приймачу (Verification Queries).
- `2^t` — потужність простору усічених тегів.

З цієї нерівності випливають фундаментальні інженерні висновки:

1. Скорочення тегу до `t` бітів збільшує ймовірність разового сліпого вгадування підпису до `2^(-t)`. Якщо приймач дозволяє супротивнику виконати `q_v` спроб перевірки без блокування сесії, математичне сподівання успішної підробки становить `q_v / 2^t`.
2. Проте скорочення довжини вихідного тегу жодним чином не полегшує відновлення таємного ключа `K` чи знаходження внутрішніх колізій стану: складність атаки на внутрішній каскад залишається рівною `2^(L/2)` операцій, де `L` — повний розмір вектора стану геш-функції (`L = 256` для HMAC-SHA256).

## Порівняння з губчастими функціями: перехід до KMAC (NIST SP 800-185)

З появою стандарту SHA-3 на базі перестановочної архітектури Keccak (Sponge Construction) математична необхідність у вкладеній конструкції HMAC відпала.

У губчастій конструкції внутрішній стан складається з бітів швидкості `r` та бітів ємності `c` (де `r + c = 1600` бітів для Keccak). Після обробки повідомлення вихідний дайджест витискається лише з ділянки швидкості `r`, тоді як ділянка ємності `c` залишається повністю прихованою. Оскільки вихід геш-функції не розкриває повного вектора стану (ділянка `c` невідома), атака подовження довжини стає математично неможливою за самою природою губки.

Це дозволило NIST стандартизувати спрощений механізм **KMAC** (англ. *Keccak Message Authentication Code*, NIST SP 800-185):

```
KMAC(K, m, L, S) = cSHAKE( K || m, L, "KMAC", S )
```

KMAC здійснює лише один прохід над повідомленням шляхом простого склеювання `K || m`, досягаючи повної стійкості PRF без масок `ipad`/`opad` та без подвійного обчислення гешу. Проте для класичних функцій сімейств MD5, SHA-1 та SHA-2, побудованих за принципом Меркле — Дамґорда, двоетапна вкладена конструкція HMAC залишається єдиним математично доведеним бар'єром захисту.

## Формальна модель деривації ключів HKDF (RFC 5869)

У 2010 році Хуго Кравчик розширив математичну модель HMAC, створивши стандартну функцію деривації ключів **HKDF** (англ. *HMAC-based Extract-and-Expand Key Derivation Function*). Вона розділяє процес формування ключів на дві строго доведені фази:

### 1. Фаза вилучення ентропії (HKDF-Extract)

Перетворює сире, нерівномірне джерело ентропії `IKM` (наприклад, результат протоколу обміну Діффі — Геллмана) на псевдовипадковий псевдоключ `PRK` фіксованої довжини `L`:

```
PRK = HMAC_Hash( Salt, IKM )
```

За лемою про залишковий геш (Leftover Hash Lemma), якщо `Salt` є випадковим значенням (навіть публічним), HMAC діє як універсальний екстрактор випадковості (англ. *Randomness Extractor*), концентруючи мін-ентропію нерівномірного джерела у рівномірний статистичний розподіл `PRK`.

### 2. Фаза розширення (HKDF-Expand)

Генерує послідовність вихідних ключів довільної сумарної довжини `OKM` за допомогою HMAC у режимі зворотного зв'язку (Feedback PRF):

```
T(0) = порожній рядок
T(1) = HMAC_Hash( PRK, T(0) || info || 0x01 )
T(2) = HMAC_Hash( PRK, T(1) || info || 0x02 )
T(i) = HMAC_Hash( PRK, T(i-1) || info || byte(i) )
OKM  = T(1) || T(2) || ... || T(N)
```

Де `info` — контекстні дані протоколу (наприклад, рядок `"tls13 key"`). Математично доведено, що вихід `OKM` є обчислювально невідрізненним від істинно випадкової послідовності бітів доти, доки HMAC є стійкою PRF. Завдяки цій редукції HKDF став фундаментом криптографічного захисту в протоколах TLS 1.3, QUIC, SSHv2 та Signal.
