# 📋 Системні інтерфейси ізоляції та керування привілеями в Linux

Ця вставка містить системний довідник функцій, системних викликів, прапорців ядра та структур даних, призначених для реалізації принципу найменших привілеїв (скидання прав процесу, керування POSIX capabilities, блокування розширення повноважень, фільтрація Seccomp-BPF та порівняння з моделлю `pledge`/`unveil`).

## 1. Скидання ідентифікаторів користувача та групи

У традиційній моделі дискреційного доступу Unix процес володіє трьома ідентифікаторами користувача (UID) та групи (GID): реальним (англ. *real*), ефективним (англ. *effective*) та збереженим (англ. *saved*).

### Системний виклик `setresuid` / `setresgid`

Виклики `setresuid` та `setresgid` встановлюють усі три ідентифікатори одночасно, що гарантує повну незворотність скидання привілеїв суперкористувача (`root`).

```c
#define _GNU_SOURCE
#include <unistd.h>

int setresuid(uid_t ruid, uid_t euid, uid_t suid);
int setresgid(gid_t rgid, gid_t egid, gid_t sgid);
```

#### Параметри
- `ruid` / `rgid`: реальний ідентифікатор (визначає фізичного власника процесу та право надсилати сигнали через `kill`).
- `euid` / `egid`: ефективний ідентифікатор (використовується підсистемами ядра для перевірки прав доступу до файлової системи, сокетів та об'єктів IPC).
- `suid` / `sgid`: збережений ідентифікатор (дозволяє процесу тимчасово відновлювати вихідні привілеї; якщо він не скинутий у непривілейоване значення, зловмисник зможе викликати `seteuid(0)`).
- Передача значення `(uid_t)-1` або `(gid_t)-1` залишає відповідний ідентифікатор без змін.

#### Коди повернення
- `0`: успішне встановлення всіх трьох ідентифікаторів.
- `-1`: виникла помилка; `errno` встановлюється у значення:
  - `EPERM`: викликаючий процес не має привілею `CAP_SETUID` / `CAP_SETGID` і намагається встановити значення, відмінне від поточного реального, ефективного або збереженого.
  - `EINVAL`: передано неприпустимий числовий ідентифікатор.

### Очищення списку додаткових груп: `setgroups`

Перед скиданням основного UID/GID процес зобов'язаний скинути таблицю додаткових груп (англ. *supplementary groups*), інакше він збереже права доступу до файлів, дозволених для груп `wheel`, `sudo` або `docker`.

```c
#include <grp.h>

int setgroups(size_t size, const gid_t *list);
```
- Для повного скидання додаткових груп передається `setgroups(0, NULL)`. Невиконання цієї операції є класичною вразливістю збереження залишкових привілеїв.

## 2. Блокування підняття привілеїв: `PR_SET_NO_NEW_PRIVS`

Системний виклик `prctl` із прапорцем `PR_SET_NO_NEW_PRIVS` створює незворотну апаратну та системну гарантію ядра, що викликаючий процес та всі його дочірні нащадки ніколи не зможуть отримати додаткові привілеї через двійкові файли з бітами `setuid`/`setgid` або файлові capabilities (file capabilities).

```c
#include <sys/prctl.h>

int prctl(int option, unsigned long arg2, unsigned long arg3,
          unsigned long arg4, unsigned long arg5);
```

### Використання
```c
prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);
```

#### Властивості прапорця
- Операція є **строго односторонньою**: після встановлення значення `1` не існує жодного системного виклику (навіть із правами `CAP_SYS_ADMIN`), здатного скинути прапорець назад у `0`.
- Прапорець автоматично успадковується через `fork`, `vfork`, `clone` та зберігається при виконанні `execve`.
- Встановлення `PR_SET_NO_NEW_PRIVS = 1` є обов'язковою передумовою для завантаження Seccomp-фільтрів непривілейованим процесом без наявності `CAP_SYS_ADMIN`.

## 3. POSIX Capabilities: гранулярні повноваження ядра

Ядро Linux поділяє необмежену владу суперкористувача `root` на набір із 41 дискретного привілею (заголовок `<linux/capability.h>`).

### Таблиця критичних capabilities

| Константа | Номер | Дозволені операції | Ризик надлишковості |
|:---|:---:|:---|:---|
| `CAP_NET_BIND_SERVICE` | 10 | Прив'язка до привілейованих портів (< 1024) | Мінімальний (дозволяє слухати порти 80/443) |
| `CAP_NET_RAW` | 13 | Створення raw-сокетів та перехоплення пакетів | Дозволяє підробляти мережеві пакети та IP-адреси |
| `CAP_DAC_OVERRIDE` | 1 | Обхід перевірок прав читання, запису та виконання файлів | Повний доступ до всіх файлів локальної FS |
| `CAP_SYS_PTRACE` | 19 | Трасування інших процесів через `ptrace` та читання пам'яті | Дозволяє ін'єкцію шеллкоду в чужі процеси |
| `CAP_SYS_ADMIN` | 21 | Монтування FS, керування namespaces, завантаження eBPF | Фактичний еквівалент повного контролю (`root`) |
| `CAP_SETUID` | 7 | Довільна зміна UID процесу та підробка ідентичності | Дозволяє відновити UID 0 |

### П'ять наборів повноважень у дескрипторі задачі

Кожен процес у ядрі Linux містить 5 наборів бітових масок capabilities:
1. **Effective (`CAP_EFFECTIVE`):** Множина прав, які ядро перевіряє в поточний момент виконання системної операції.
2. **Permitted (`CAP_PERMITTED`):** Граничний набір прав, які процес може додати у свій Effective набір без повторної автентифікації.
3. **Inheritable (`CAP_INHERITABLE`):** Права, які зберігаються при виклику `execve`, якщо виконуваний бінарний файл має відповідні біти у файлових атрибутах.
4. **Bounding Set (`CAP_BSET`):** Верхня межа прав, яку процес і його нащадки можуть отримати в принципі. Видалення capability з bounding set є незворотним.
5. **Ambient Set (`CAP_AMBIENT`):** Права, які автоматично зберігаються при `execve` для непривілейованих двійкових файлів без встановлених файлових атрибутів.

### Структури та виклики бібліотеки `libcap`

```c
#include <sys/capability.h>

cap_t cap_get_proc(void);
int cap_set_proc(cap_t cap_p);
int cap_set_flag(cap_t cap_p, cap_flag_t flag, int ncap,
                 const cap_value_t *caps, cap_flag_value_t value);
int cap_free(void *obj_d);
```

## 4. Обмеження простору системних викликів: Seccomp-BPF

Підсистема Seccomp (Secure Computing mode) дозволяє процесу декларувати білий список дозволених системних викликів. Усі незареєстровані виклики перехоплюються віртуальною машиною BPF і призводять до негайного блокування.

### Системний виклик `seccomp`

```c
#include <linux/seccomp.h>
#include <linux/filter.h>
#include <sys/syscall.h>
#include <unistd.h>

int seccomp(unsigned int operation, unsigned int flags, void *args);
```

#### Режими роботи
- `SECCOMP_SET_MODE_STRICT` (0): дозволяє лише 4 виклики: `read()`, `write()`, `_exit()` та `sigreturn()`. Будь-який інший виклик миттєво завершує процес сигналом `SIGKILL`.
- `SECCOMP_SET_MODE_FILTER` (1): застосовує користувацьку програму BPF (`struct sock_fprog`), яка аналізує номер виклику та його аргументи.

### Структура `seccomp_data`

Під час кожного системного виклику BPF-фільтр отримує вхідний контекст у форматі структури:

```c
struct seccomp_data {
    int nr;                    /* Номер системного виклику (SYS_read, SYS_write тощо) */
    __u32 arch;                /* Архітектура процесора (AUDIT_ARCH_X86_64 тощо) */
    __u64 instruction_pointer; /* Лічильник інструкцій CPU на момент виклику */
    __u64 args[6];             /* 6 аргументів системного виклику */
};
```

### Вердикти фільтрації Seccomp

| Вердикт | Значення | Дія ядра над процесом |
|:---|:---:|:---|
| `SECCOMP_RET_KILL_PROCESS` | `0x80000000` | Негайне аварійне завершення всіх потоків процесу |
| `SECCOMP_RET_KILL_THREAD` | `0x00000000` | Завершення викликаючого потоку |
| `SECCOMP_RET_TRAP` | `0x00030000` | Надсилання сигналу `SIGSYS` обробнику процесу |
| `SECCOMP_RET_ERRNO` | `0x00050000` | Блокування виклику та повернення помилки (наприклад, `EPERM`) |
| `SECCOMP_RET_TRACE` | `0x7ff00000` | Повідомлення налагоджувачу через `ptrace` |
| `SECCOMP_RET_ALLOW` | `0x7fff0000` | Дозвіл на штатне виконання системного виклику |

## 5. Альтернативний підхід OpenBSD: `pledge` та `unveil`

На відміну від низькорівневої віртуальної машини BPF у Linux, операційна система OpenBSD пропонує лаконічний декларативний підхід до принципу найменших привілеїв через виклики `pledge` та `unveil`.

### Системний виклик `pledge`

```c
#include <unistd.h>

int pledge(const char *promises, const char *execpromises);
```

#### Категорії промісів (promises):
- `"stdio"`: базовий ввід-вивід, робота з пам'яттю (`mprotect`, `brk`), отримання часу.
- `"rpath"`: читання файлів та директорій.
- `"wpath"`: запис у наявні файли.
- `"cpath"`: створення та видалення файлів (`creat`, `unlink`, `mkdir`).
- `"inet"`: робота з мережевими сокетами IPv4/IPv6 (`socket`, `connect`, `bind`, `listen`).
- `"dns"`: резолвінг доменних імен через `/etc/resolv.conf`.

Будь-який наступний виклик `pledge` може лише **звужувати** раніше оголошений список промісів (наприклад, від `"stdio rpath inet"` до `"stdio"` після завантаження конфігурації та завершення мережевого обміну). Спроба розширити список карається негайним аварійним завершенням (`SIGABRT`).

### Системний виклик `unveil`

```c
#include <unistd.h>

int unveil(const char *path, const char *permissions);
```

Виклик `unveil` обмежує видимість файлової системи лише явно вказаними шляхами:
- `permissions`: комбінація символів `"r"` (читання), `"w"` (запис), `"x"` (виконання), `"c"` (створення/видалення).
- Виклик `unveil(NULL, NULL)` повністю фіксує стан таблиці дозволів: після цього жоден новий шлях не може бути відкритий для процесу.

## 6. Канонічний алгоритм повної деескалації прав у демоні

Для захисту від збереження прихованих каналів витоку привілеїв у системному демоні застосовується сувора послідовність етапів:

1. **Привілейований старт:** відкриття сокетів на портах < 1024, зчитування приватних сертифікатів TLS, ініціалізація майстер-дескрипторів аудиту.
2. **Ізоляція файлової системи:** виклик `chroot("/var/empty")` та перехід у кореневу директорію `chdir("/")`.
3. **Очищення додаткових груп:** `setgroups(0, NULL)`.
4. **Скидання реального, ефективного та збереженого UID/GID:** `setresgid(uid, uid, uid)` та `setresuid(uid, uid, uid)`.
5. **Очищення Capabilities:** скидання всіх бітових масок `cap_set_proc(empty_caps)`.
6. **Одностороння блокування нових привілеїв:** `prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0)`.
7. **Встановлення Seccomp-фільтра:** активація білого списку системних викликів через `seccomp(SECCOMP_SET_MODE_FILTER, 0, &fprog)`.

Порушення цього порядку (наприклад, зміна UID до очищення `setgroups` або завантаження Seccomp перед відкриттям потрібних сокетів) призводить або до раптового аварійного завершення, або до виникнення критичних дір у безпеці.
