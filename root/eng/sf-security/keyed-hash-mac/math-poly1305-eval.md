# 🧮 Поліноміальне оцінювання Poly1305 та універсальне гешування

Універсальне гешування Картера — Веґмана будує коди автентичності повідомлень на базі алгебраїчного оцінювання многочлена над скінченним полем з наступним одноразовим маскуванням результату. Алгоритм Poly1305, розроблений Деніелом Бернштейном, оптимізує цю схему для екстремальної швидкості на процесорах загального призначення без спеціалізованих апаратних інструкцій. Повідомлення розглядається як набір коефіцієнтів многочлена, аргументом якого слугує секретний ключ `r`, а обчислення проводяться за модулем спеціально обраного простого числа `2¹³⁰ - 5`.

---

## 1. Скінченне поле GF(2¹³⁰ - 5) та арифметика псевдопростих чисел Мерсенна

Для побудови майже-універсального сімейства геш-функцій над потоком 128-бітних блоків необхідне скінченне поле `F_p`, характеристика якого перевищує максимальне значення блоку `2¹²⁸`. Вибір простого модуля `p` визначає як криптографічну надійність, так і обчислювальну складність операції редукції.

Число `p = 2¹³⁰ - 5` є простим числом (так званим псевдопростим числом Мерсенна або числом типу Кренделла). Головна властивість арифметики за цим модулем полягає у тотожності:

```
2¹³⁰ ≡ 5 (mod (2¹³⁰ - 5))
```

Нехай у процесі множення двох чисел у полі отримано 260-бітне проміжне значення `Z`. Його можна представити у вигляді двох частин: молодших 130 бітів `Z_low` та старших 130 бітів `Z_high`:

```
Z = Z_high · 2¹³⁰ + Z_low
```

Застосовуючи модульну редукцію за правилом еквівалентності степеня двійки:

```
Z mod (2¹³⁰ - 5)
= (Z_high · 2¹³⁰ + Z_low) mod (2¹³⁰ - 5)      [розклад числа за основою 2¹³⁰]
= (Z_high · 5 + Z_low) mod (2¹³⁰ - 5)          [підстановка 2¹³⁰ ≡ 5 mod p]
```

Це перетворення замінює важку операцію цілочисельного ділення з остачею (яка на типовому процесорі вимагає десятків тактів конвеєра) на один бітовий зсув вліво на 2 позиції та одне додавання:

```
5 · Z_high = (Z_high << 2) + Z_high
```

Отриманий результат `Z_low + 5 · Z_high` має довжину щонайбільше 133 біти. Повторення операції для залишку старших 3 бітів повністю зводить число до діапазону `[0, 2¹³⁰ + 3]`, після чого остаточне зведення до діапазону `[0, p - 1]` вимагає лише одного умовного віднімання `p` у константному часі.

## 2. Кодування повідомлення та додавання розділювального біта

Повідомлення `M` довільної довжини розбивається на послідовність 16-байтних (128-бітних) блоків `c₁, c₂, ..., c_L`. Останній блок `c_L` може містити від 1 до 16 байтів.

Кожен 16-байтний фрагмент інтерпретується як беззнакове ціле число у порядку байтів little-endian. Для усунення неоднозначності, коли блоки мають різну довжину або закінчуються нульовими байтами, до кожного блоку обов'язково дописується один додатковий біт зі значенням `1` безпосередньо після останнього значущого байта:

```
c_i = Byte_0 + Byte_1 · 2⁸ + Byte_2 · 2¹⁶ + ... + Byte_{k-1} · 2⁸⁽ᵏ⁻¹⁾ + 1 · 2⁸ᵏ
```

Для повного 16-байтного блоку (`k = 16`) дописується біт у позицію 128, що перетворює його на 129-бітне число в діапазоні `[2¹²⁸, 2¹²⁹ - 1]`:

```
c_i = Block_Bytes + 2¹²⁸
```

Для неповного блоку довжиною `k < 16` байтів додається доданок `2⁸ᵏ`. Це ін'єктивне перетворення гарантує, що повідомлення `0x41` (1 байт) та `0x41 0x00` (2 байти) перетворюються на різні числові значення: `0x41 + 2⁸ = 0x0141` та `0x0041 + 2¹⁶ = 0x010041`. Жодна пара різних повідомлень не може породити однаковий вектор коефіцієнтів `(c₁, ..., c_L)`.

## 3. Затискання коефіцієнта r (Clamping)

Секретний ключ Poly1305 має розмір 32 байти і складається з двох 16-байтних половин: `(r, s)`. Перша половина `r` визначає коефіцієнт обчислення полінома, а друга половина `s` є одноразовою маскою шифрування.

Перед початком обчислень над 16-байтовим вектором `r` виконується операція бітового затискання (англ. *clamping*). Масив байтів `r[0..15]` очищується від певних бітів за допомогою порозрядного `AND`:

```
r[3]  &= 0x0F    [обнулення старших 4 бітів]
r[7]  &= 0x0F    [обнулення старших 4 бітів]
r[11] &= 0x0F    [обнулення старших 4 бітів]
r[15] &= 0x0F    [обнулення старших 4 бітів]

r[4]  &= 0xFC    [обнулення молодших 2 бітів]
r[8]  &= 0xFC    [обнулення молодших 2 бітів]
r[12] &= 0xFC    [обнулення молодших 2 бітів]
```

Затискання скидає рівно 22 біти ключа в 0, залишаючи `128 - 22 = 106` бітів повної ентропії.

> 🔧 **Навіщо це потрібно в інженерній реалізації.**
> Коли 128-бітне число `r` множиться на 130-бітний акумулятор `a`, алгоритми представляють числа у вигляді трьох 44-бітних або п'яти 26-бітних фрагментів (limb). Обнулення старших бітів гарантує, що при множенні проміжні суми добутків не перевищують розрядну сітку 64-бітного регістра. Обнулення молодших бітів дозволяє виконувати додавання помножених на 5 коефіцієнтів безпосередньо без попереднього розповсюдження бітів переносу (carry). Це забезпечує максимальну швидкість без ризику виникнення арифметичного переповнення.

## 4. Схема Горнера та фінальне маскування

Значення автентифікаційного полінома для послідовності коефіцієнтів `c₁, c₂, ..., c_L` задається виразом:

```
Poly(r, M) = (c₁ · rᴸ + c₂ · rᴸ⁻¹ + ... + c_L · r) mod (2¹³⁰ - 5)
```

Обчислення виконується послідовно за схемою Горнера. Акумулятор `a` ініціалізується нулем `a₀ = 0`. Для кожного наступного блоку `c_i` виконується ітераційний крок:

```
a_i = ((a_{i-1} + c_i) · r) mod (2¹³⁰ - 5)
```

Порядок обчислення розгортається у такий ланцюг:

```
a₁ = (c₁ · r) mod p
a₂ = ((a₁ + c₂) · r) mod p = (c₁ · r² + c₂ · r) mod p
...
a_L = (c₁ · rᴸ + c₂ · rᴸ⁻¹ + ... + c_L · r) mod p
```

Після обробки останнього блоку `c_L` проміжне 130-бітне значення `a_L` редукується до строгого діапазону `[0, p - 1]`.

Фінальний 16-байтний тег автентичності `Tag` формується додаванням 128-бітного секретного числа `s` за модулем `2¹²⁸`:

```
Tag = (a_L + s) mod 2¹²⁸
```

Операція `+ s mod 2¹²⁸` виконує роль одноразового шифру (гаммування Вернама) над результатом алгебраїчного гешування, приховуючи значення `a_L` від спостерігача.

## 5. Доведення теоретико-ймовірнісної стійкості Картера — Веґмана

Стійкість схеми базується на фундаментальній теоремі алгебри: будь-який ненульовий многочлен степеня `d` над полем `F_p` має не більше ніж `d` коренів.

Нехай зловмисник намагається підробити тег для нового повідомлення `M' ≠ M` довжиною `L'` блоків, знаючи перехоплений тег `Tag = (Poly(r, M) + s) mod 2¹²⁸` для легітимного повідомлення `M` довжиною `L` блоків під тією самою парою ключів `(r, s)`.

Різниця значень поліномів для двох повідомлень утворює новий многочлен `Δ(r)`:

```
Δ(r) = Poly(r, M) - Poly(r, M') (mod p)
```

Степінь многочлена `Δ(r)` не перевищує `max(L, L')`. Оскільки `M ≠ M'`, за рахунок обов'язкового кодування розділювальних бітів многочлен `Δ(r)` не є тотожним нулем. Отже, рівняння `Δ(r) ≡ 0 (mod p)` має щонайбільше `max(L, L')` розв'язків у полі `F_p`.

Коефіцієнт `r` обирається рівномірно випадково з множини `S_r` затиснутих ключів. Потужність цієї множини становить:

```
|S_r| = 2¹⁰⁶
```

Ймовірність того, що випадково обраний секретний ключ `r` виявиться одним із коренів різницевого многочлена (що дозволить зловмиснику вгадати збіг `Poly(r, M) ≡ Poly(r, M') mod p`), обмежена відношенням кількості коренів до розміру простору ключів:

```
P[колізія] ≤ max(L, L') / 2¹⁰⁶
```

З урахуванням того, що додавання маски `s` виконується за модулем `2¹²⁸`, а не за модулем `p`, виникає незначне зміщення ймовірностей на границях поля (ефект редукції `p > 2¹²⁸`). Суворе доведення Бернштейна враховує цей перегин і встановлює точну верхню межу переваги зловмисника `Adv`:

```
Adv_Poly1305 ≤ (8 · L) / 2¹⁰⁶
```

Для повідомлення довжиною 1 МБ (що становить `L = 1048576 / 16 = 65536 = 2¹⁶` блоків) максимальна ймовірність успішної підробки одного тегу дорівнює:

```
P_forge ≤ (8 · 2¹⁶) / 2¹⁰⁶ = 2¹⁹ / 2¹⁰⁶ = 2⁻⁸⁷
```

Значення `2⁻⁸⁷` є мізерно малим: зловмиснику знадобилося б надіслати в середньому `2⁸⁶` підроблених пакетів, щоб хоча б один був визнаний сервером валідним.

## 6. Катастрофа повторного використання пари (r, s)

Якщо та сама пара ключів `(r, s)` використовується для автентифікації двох різних повідомлень `M₁` та `M₂` з тегами `Tag₁` та `Tag₂`:

```
Tag₁ = (Poly(r, M₁) + s) mod 2¹²⁸
Tag₂ = (Poly(r, M₂) + s) mod 2¹²⁸
```

Зловмисник віднімає отримані теги:

```
Tag₁ - Tag₂ ≡ Poly(r, M₁) - Poly(r, M₂) (mod 2¹²⁸)
```

Маскуючий секрет `s` повністю взаємознищується. Отримане рівняння є звичайним алгебраїчним рівнянням від однієї невідомої змінної `r`. Знаходження коренів многочлена степеня `L` над полем `GF(2¹³⁰ - 5)` здійснюється за поліноміальний час (наприклад, за допомогою алгоритму Берлекампа або алгоритму Кантора — Цассенгауза).

Відновивши ключ `r`, зловмисник тривіально обчислює `s = (Tag₁ - Poly(r, M₁)) mod 2¹²⁸`. Після цього повний секрет зламано: атакуючий може самостійно створювати валідні теги Poly1305 для будь-яких фальшивих повідомлень довільної довжини.

Саме тому в сучасних криптографічних протоколах (таких як ChaCha20-Poly1305 у TLS 1.3 та SSH) ключ `(r, s)` ніколи не є довготривалим: він динамічно генерується заново для кожного окремого пакета шляхом шифрування нульового блоку потоковим шифром ChaCha20 з унікальним лічильником пакета (Nonce).
