# 🔌 Захищений елемент (Secure Element / SAM)

Захищений елемент (*Secure Element*, SE) — це спеціалізований апаратний мікроконтролер із високим ступенем фізичного й криптографічного захисту, призначений для безпечного зберігання секретних ключів, сертифікатів та виконання криптографічних операцій у середовищі, що піддається атакам. 

У системах RFID та NFC Secure Element використовується в трьох основних конструктивних втіленнях:
1. **SAM-модуль (Secure Application Module):** Захищена смарт-картка у форматі SIM/ID-000, яка вставляється у слот NFC-зчитувача для автентифікації карток та зберігання Master-ключів системи.
2. **Вбудований чип eSE (Embedded Secure Element):** Ізольована мікросхема, розпаяна безпосередньо на материнській платі смартфона чи контролера.
3. **UICC / SIM-картка з підтримкою SWP:** Захищений елемент оператора зв'язку, що з'єднується з NFC-контролером через спеціалізовану однопровідну шину SWP (Single Wire Protocol).

---

### 1. Внутрішня схемотехніка та ізоляція системних шин

На відміну от універсальних мікроконтролерів (де пам'ять, ALU та шина даних є відкритими для зондування), кристал Secure Element проектується за принципом повної ізоляції внутрішніх ресурсів.

```
       ┌──────────────────────────────────────────────────────────────────┐
       │                Secure Element (Кристал EAL6+)                   │
       │                                                                  │
       │  ┌────────────────────┐          ┌────────────────────────────┐  │
       │  │ Спеціалізоване ядро│          │ Апаратні акселератори      │  │
       │  │ (32-біт Secure RISC)│◄────────►│ - AES-128/256 (Constant-T)  │  │
       │  │ + MPU (Memory Prot)│          │ - ECC (P-256/P-384/Ed25519) │  │
       │  └─────────┬──────────┘          │ - RSA-2048/4096            │  │
       │            │                     └────────────────────────────┘  │
       │            │  Зашифрована шина                                   │
       │  ┌─────────┴──────────┐          ┌────────────────────────────┐  │
       │  │ Захищена EEPROM/   │          │ Апаратний TRNG             │  │
       │  │ Flash (Scrambling) │          │ (Аналогова ентропія p-n)   │  │
       │  └────────────────────┘          └────────────────────────────┘  │
       │                                                                  │
       │  ──────────────────────────────────────────────────────────────  │
       │     Активний захисний шар (Active Tamper Mesh + Glitch Sensors)  │
       └────────────────────────────┬─────────────────────────────────────┘
                                    │
                       Шина ISO 7816 / SWP / I2C
```

#### Ключові апаратно-програмні блоки

1. **Криптографічний процесор-акселератор:** Виконує обчислення симетричних (AES-128/256, 3DES) та асиметричних (RSA до 4096 бітів, еліптичні криві ECC) алгоритмів за заздалегідь визначену рівну кількість тактів (*Constant-Time Execution*). Це унеможливлює витік ключів через часовий аналіз (*Timing Attacks*).
2. **Апаратний генератор справді випадкових чисел (TRNG):** Витягує фізичну ентропію з теплового та квантового шуму p-n переходу аналогової частини чипа. Відповідає вимогам специфікацій NIST SP 800-90A та AIS-31 (Class PTG.2), гарантуючи відсутність повторюваності векторів запиту (*nonces*).
3. **Шифрування пам'яті та скремблювання (Memory Scrambling):** Вміст Flash, EEPROM та SRAM зберігається в зашифрованому вигляді із застосуванням динамічної адресної заміни (скремблювання). Ключ шифрування пам'яті генерується апаратно при виготовленні кристала й не може бути зчитаний навіть через відлагоджувальні інтерфейси.

### 2. Захист від фізичного розтину та побічних каналів

Специфікація Secure Element вимагає відповідності найвищим стандартам сумісності **Common Criteria (CC EAL5+ / EAL6+)** та **EMVCo**. Це досягається за допомогою багаторівневої системи антизламу:

* **Активна захисна сітка (Active Shield / Tamper Mesh):** Верхній шар металізації напівпровідникового кристала повністю покритий сіткою мікропровідників шириною у частки мікрона, якими постійно протікає високочастотний контрольний сигнал. Спроба механічного спилювання обгортки корпусу або мікрозондування розриває провідник або змінює його імпеданс, що миттєво запускає процедуру апаратного стирання Master-ключів (*Zeroization*).
* **Спеціалізовані датчики довкілля:**
  * *Датчик напруги (Voltage Glitch Detector):* Фіксує спроби подачі коротких провалів або сплесків напруги живлення, призначених для збою лічильника команд процесора (PC) та пропуску інструкцій перевірки підпису.
  * *Датчик тактової частоти (Clock Glitch Detector):* Моніторить стабільність зовнішнього тактового сигналу, блокуючи спроби прискорення або зупинки процесів.
  * *Оптичні та світлові детектори:* Фіксують ультрафіолетове або лазерне опромінення кристала, що запобігає атакам локального впровадження помилок (*Fault Injection / Optical Glitching*).
* **Придушення побічних випромінювань (SPA/DPA Countermeasures):** Для унеможливлення аналізу споживання струму (DPA) криптопроцесор оснащений внутрішніми ємнісними фільтрами та генератором "рожевого шуму", який накладає на криву струму випадкові флуктуації.

### 3. Фізичні інтерфейси підключення SE та SAM

Залежно від архітектури пристрою, Secure Element підключається до NFC-контролера чи центрального процесора за допомогою трьох основних інтерфейсів:

| Інтерфейс | Кількість ліній | Протокол | Сфера застосування |
| :--- | :--- | :--- | :--- |
| **ISO/IEC 7816-3** | 4 (VCC, GND, CLK, I/O) | T=0 / T=1 APDU | SAM-модулі у платіжних та транспортних зчитувачах |
| **SWP (Single Wire)**| 1 (лінія C6 SIM-карти)| S2C / SWP бітовий | Зв'язок між NFC-чипом смартфона та SIM-карткою (UICC) |
| **I2C / SPI (Secure)**| 2–4 лінії | APDU over I2C/SPI | Вбудовані чипи eSE у смартфонах та смарт-годинниках |

#### Робота SAM-модуля у зчитувачах

У захищених терміналах контролер зчитувача не зберігає секретні Master-ключі у своїй внутрішній Flash-пам'яті (яка може бути зчитана через JTAG або SWD). Натомість зчитувач перенаправляє всі зчитані з картки користувача кадри безпосередньо у внутрішній SAM-модуль. SAM-модуль виконує перевірку підпису у власному безпечному ядрі й повертає зчитувачу лише двійковий результат: «Автентифікація успішна» або «Підпис недійсний».

### 4. Режими емуляції та розмежування HCE vs eSE

Сучасні смартфони з NFC підтримують два альтернативні шляхи обробки безконтактних транзакцій:

1. **Апаратний Secure Element (eSE):** Платіжні реквізити (картки Visa/Mastercard) зберігаються в ізольованому eSE. Під час прикладання смартфона до термінала NFC-контролер комутує радіоканал безпосередньо на eSE в обхід основної операційної системи Android/iOS. Навіть якщо операційна система смартфона повністю компрометована вірусами або Root-правами, зловмисник не може витягнути Master-ключі з чипа eSE.
2. **Програмна емуляція картки (HCE — Host Card Emulation):** Якщо апаратний eSE відсутній, обробка APDU здійснюється програмно на рівні ОС Android. Для захисту даних HCE використовує одноразові сесійні токени (*Limited Use Keys*, LUK), які регулярно оновлюються через хмарний сервер. При вичерпанні ліміту токенів або відсутності інтернету проведення транзакцій стає неможливим.
