# ⚙️ Реалізація One-Time Pad та криптоаналіз повторного використання ключа

Шифр одноразового блокнота (*One-Time Pad*) з математичної точки зору є найпростішим із можливих криптографічних алгоритмів: шифрування та дешифрування зводяться до однієї побітової операції `XOR`. Проте на практиці цей шифр є найвибагливішим до умов експлуатації: найменше відхилення від теорії — використання псевдовипадкового генератора замість справжньої ентропії або повторне застосування хоча б кількох байтів ключа — миттєво перетворює незламний шифр на цілковито відкритий текст. Тут розібрано повноцінну реалізацію одноразового шифрування мовами Python та C++, роботу з системними джерелами ентропії, безпечне затирання пам'яті, статистичний аналіз індексу збігів, атаку статистичного голосування для багатократного блокнота, фізичні носії та регламенти зберігання ключів, теоретико-інформаційну автентифікацію Вегмана-Картера, порівняння з сучасними потоковими шифрами, а також практичний скрипт атаки *Crib Dragging*, який автоматично відновлює зміст повідомлень у разі повторного використання ключа.

### 1. Архітектура та інженерні вимоги до безпеки

Програмне втілення схеми досконалої таємниці спирається на три взаємопов'язані складові, кожна з яких є критичною для збереження теоретичних гарантій Шеннона:

1. **Криптографічно стійка генерація ключа (CSPRNG):** звичайні бібліотечні генератори псевдовипадкових чисел (наприклад, стандартна функція `rand()` у C або модуль `random` у Python) є детермінованими лінійними конгруентними алгоритмами або вихорами Мерсенна (*Mersenne Twister*). Такі генератори оптимізовані під швидкість та рівномірність розподілу в статистичних симуляціях Монте-Карло, але абсолютно позбавлені криптографічної стійкості. Знаючи лише 624 вихідних 32-бітних значення вихору Мерсенна, криптоаналітик за мілісекунди повністю реконструює внутрішній стан масиву генератора і безпомилково обчислює всі наступні та попередні ключі. Для шифру Вернама обов'язково використовувати спеціальні інтерфейси операційної системи, які безперервно збирають ентропію фізичних процесів ядра (тремтіння тактових генераторів, таймінги апаратних переривань від дисків та мережевих карт, тепловий шум на переходах кремнієвих кристалів): системні виклики `getrandom()` у Linux, `arc4random_buf()` у BSD/macOS або функцію `BCryptGenRandom()` у Windows Cryptography API.
2. **Побітове перетворення:** повідомлення та випадковий ключ однакової довжини побайтово додаються за модулем 2 (`XOR`). Операція є симетричною та інволютивною: шифрування та розшифрування здійснюються точно тією самою процедурою без зміни логіки.
3. **Безпечне очищення та блокування пам'яті (Secure Erasure & Memory Locking):** після завершення дешифрування або відправлення повідомлення буфер секретного ключа повинен бути негайно та гарантовано перезаписаний нулями або випадковими байтами. Стандартні виклики `memset()` або вихід із локальної області видимості часто оптимізуються компілятором: якщо компілятор бачить, що буфер після заповнення більше не читається, він має право повністю видалити інструкції запису (*Dead Store Elimination*). Щоб гарантувати фізичне затирання пам'яті в RAM, необхідно використовувати спеціальні системні бар'єри: `explicit_bzero()` у POSIX, `SecureZeroMemory()` у Windows або `std::atomic_signal_fence()` у сучасному C++. Додатково сторінки пам'яті з ключем блокують системними викликами `mlock()` у Linux або `VirtualLock()` у Windows, що забороняє операційній системі витісняти секретні ключі у файл підкачки на жорсткому диску чи SSD (*swap file*).

### 2. Апаратні джерела випадковості: TRNG, RdRand та пули ентропії

Щоб зрозуміти, звідки операційна система бере справжню ентропію для одноразового блокнота, погляньмо на апаратну архітектуру сучасних комп'ютерів:

1. **Фізичні генератори справжніх випадкових чисел (TRNG):** сучасні процесори x86-64 (Intel та AMD) містять вбудовані апаратні схеми, побудовані на кільцевих генераторах (*ring oscillators*) та тепловому шумі Джонсона-Найквіста на резистивних елементах кристала. Інструкція процесора `RDRAND` вичитує вихід криптографічного генератора AES-CBC-MAC, який безперервно підживлюється апаратним шумом, а інструкція `RDSEED` надає доступ до сирої фізичної ентропії, що відповідає стандарту NIST SP 800-90B.
2. **Пул ентропії ядра операційної системи (`/dev/urandom` та `getrandom`):** ядро Linux накопичує ентропію з мікросекундних флуктуацій часу між апаратними перериваннями клавіатури, миші, контролерів дисків (NVMe/SATA) та мережевих інтерфейсів. Ця випадковість змішується в пулі ядра через криптографічну хеш-функцію або потік ChaCha20. Системний виклик `getrandom()` у сучасних версіях ядра гарантує, що процес буде заблоковано лише на кілька мілісекунд під час первинного завантаження системи, доки пул ядра не збере 128 бітів справжньої ентропії, після чого генератор переходить у режим безперервної та безпечної видачі байтів.

### 4. Статистичний криптоаналіз: індекс збігів для виявлення Two-Time Pad

Перед запуском атаки відновлення тексту криптоаналітику необхідно автоматично визначити, чи дійсно два перехоплених шифротексти `c₁` та `c₂` були зашифровані на тому самому ключі. Якщо шифротексти використовували різні незалежні ключі `k₁` та `k₂`, то `c₁ ⊕ c₂ = m₁ ⊕ m₂ ⊕ k₁ ⊕ k₂` залишається абсолютно рівномірним шумом. Але якщо ключ був спільним, у різниці `c₁ ⊕ c₂ = m₁ ⊕ m₂` виникають статистичні кореляції природної мови.

Головним математичним інструментом для такої детекції є **індекс збігів** (*Index of Coincidence*, `IC`), запропонований Вільямом Фрідманом:

```
IC = (∑ f_i · (f_i - 1)) / (N · (N - 1))
```

де `f_i` — кількість входжень кожного можливого байта `i ∈ {0, ..., 255}` у масиві довжини `N`.

Теоретичні значення індексу збігів для різних потоків:
- Для абсолютно випадкового рівномірного 8-бітного шуму: `IC_rand = 1 / 256 ≈ 0.003906`.
- Для стандартного англійського тексту в кодуванні ASCII: `IC_eng ≈ 0.065`.
- Для побайтового `XOR` двох незалежних англійських текстів `m₁ ⊕ m₂`: `IC_diff ≈ 0.038`–`0.045`.

Якщо обчислене значення `IC(c₁ ⊕ c₂)` перевищує поріг `0.025`, аналізатор із надійністю понад 99% фіксує повторне використання ключа і передає дані до модуля Crib Dragging.

### 5. Криптоаналіз: атака Crib Dragging при повторному використанні ключа

Найнебезпечнішою вразливістю в практичному застосуванні одноразового блокнота є помилка повторного використання ключа (*Two-Time Pad*). Якщо два різні відкриті повідомлення `m₁` та `m₂` зашифровані на тому самому ключі `k`:

```
c₁ = m₁ ⊕ k
c₂ = m₂ ⊕ k
```

Перехопивши шифротексти `c₁` та `c₂`, супротивник просто складає їх побітово операцією `XOR`:

```
c₁ ⊕ c₂ = (m₁ ⊕ k) ⊕ (m₂ ⊕ k) = m₁ ⊕ m₂ ⊕ (k ⊕ k) = m₁ ⊕ m₂
```

Секретний ключ `k` повністю самознищується, оскільки будь-яке число у парі з самим собою дає нуль (`k ⊕ k = 0`). У розпорядженні криптоаналітика залишається величина `D = m₁ ⊕ m₂`.

Оскільки природні мови (англійська, українська) мають високу надлишковість, `m₁ ⊕ m₂` не є випадковим шумом. Особливу роль відіграє символ пробілу в таблиці ASCII:
- Код пробілу дорівнює `0x20` (у двійковому вигляді `0010 0000`).
- Коди великих літер латинського алфавіту лежать у діапазоні `0x41`–`0x5A` (`A`–`Z`), малих — `0x61`–`0x7A` (`a`–`z`).
- Коли символ літери піддається `XOR` із пробілом (`0x20`), змінюється рівно один 5-й біт: велика літера перетворюється на відповідну малу, а мала — на велику!
- Якщо результат `D[i]` лежить у діапазоні `0x41`–`0x5A` або `0x61`–`0x7A`, це майже напевно означає, що в одному з двох повідомлень на позиції `i` стояв символ пробілу, а в іншому — відповідна літера.

**Техніка сковзання здогадок (Crib Dragging):**
1. Криптоаналітик бере типове слово, яке з високою ймовірністю зустрічається в текстах даної тематики (слово-здогадка або *crib*), наприклад `" the "`, `"ATTACK"`, `"PRESIDENT"`.
2. Це слово по черзі накладається операцією `XOR` на всі можливі зміщення `offset` у буфері різниці `D = m₁ ⊕ m₂`:
   ```
   Candidate₂[offset ... offset+L] = D[offset ... offset+L] ⊕ Crib
   ```
3. Якщо на зсуві `offset` у першому повідомленні `m₁` дійсно стояло слово `Crib`, то `Candidate₂` покаже справжній фрагмент відкритого тексту другого повідомлення `m₂`!
4. Якщо отримані байти утворюють читабельні друковані символи людської мови, криптоаналітик фіксує знайдений фрагмент другого тексту і починає використовувати його вже як новий crib для розгортання решти першого тексту.

### 6. Багатократний блокнот: атака статистичного голосування (Many-Time Pad)

Якщо з необережності або системного збою один і той самий ключ `k` був використаний не двічі, а для шифрування множини повідомлень `c₁, c₂, ..., c_M` (де `M ≥ 5`), криптоаналітику більше не потрібно навіть підбирати слова-здогадки: відкриті тексти відновлюються повністю автоматично за допомогою **статистичного голосування за пробілами**.

**Алгоритм атаки Many-Time Pad:**
1. Для кожної позиції байта `p` обчислюються всі попарні різниці між шифротекстами: `D_{i,j}[p] = c_i[p] ⊕ c_j[p] = m_i[p] ⊕ m_j[p]`.
2. Зафіксуємо одне конкретне повідомлення `m_i` на позиції `p`. Порахуємо, скільки разів значення `D_{i,j}[p]` для всіх інших повідомлень `j ≠ i` виявилося літерою латинського алфавіту (`0x41`–`0x5A` або `0x61`–`0x7A`).
3. Якщо на позиції `p` у повідомленні `m_i` дійсно стоїть пробіл `0x20`, то майже для всіх `j ≠ i` (де в повідомленнях `m_j` стоять звичайні літери) значення `D_{i,j}[p]` потрапить у діапазон літер. Якщо частка таких збігів перевищує 70%–80%, алгоритм однозначно маркує `m_i[p] = 0x20` (пробіл).
4. Одразу після визначення пробілу секретний байт ключа відновлюється тривіально: `k[p] = c_i[p] ⊕ 0x20`.
5. Знаючи відновлений байт ключа `k[p]`, алгоритм миттєво дешифрує символ на позиції `p` у **всіх** інших `M - 1` повідомленнях: `m_j[p] = c_j[p] ⊕ k[p]`.

За наявності 10–15 повідомлень однакової довжини цей метод відновлює понад 95% усього відкритого тексту за частки секунди без участі людини.

### 7. Фізичні носії та регламенти знищення одноразових ключів

У військових та дипломатичних відомствах надійність One-Time Pad історично спиралася не стільки на математику, скільки на жорсткі процедурні протоколи поводження з фізичними носіями:

1. **Формати друку блокнотів:** аркуші друкували у вигляді 5-значних літерних чи цифрових груп (наприклад, по 50 груп на сторінку). Кожна сторінка мала серійний номер, дату випуску та контрольний код цілісності (контрольну суму або хеш заголовка сторінки). Сторінки виготовляли на легкозаймистому нітроцелюлозному папері (*flash-paper*) або водорозчинному папері, який миттєво займався від іскри запальнички без залишку попелу чи розчинявся за лічені секунди у склянці води.
2. **Апаратні модулі безпеки (HSM), аудит та оптичні діоди даних:** у сучасних урядових системах одноразові ключі генеруються в захищених кімнатах (*SCIF*) і передаються через односпрямовані волоконно-оптичні канали (*data diodes*), де зворотний зв'язок фізично неможливий через відсутність зворотного лазера. Системи ведуть невразливий криптографічний журнал обліку використання кожного сегмента ключа. Після зчитування ключового блоку з пам'яті контролер надсилає високовольтний імпульс на схему захищеного затирання або фізично перепалює напівпровідникові перемички мікросхеми (*anti-fuse*), роблячи повторне зчитування того самого ключа апаратно неможливим.

### 8. Теоретико-інформаційна автентифікація: схема Вегмана-Картера

Найпоширенішою помилкою при проєктуванні захищених каналів є ототожнення таємності з цілісністю. One-Time Pad є **податливим** (*malleable*): зміна будь-якого біта в шифротексті призводить до детермінованої інверсії того самого біта у відкритому тексті після розшифрування.

Щоб забезпечити незламну автентифікацію без порушення інформаційно-теоретичної стійкості Шеннона, Марк Вегман та Лоуренс Картер (*Mark N. Wegman*, *J. Lawrence Carter*) у 1981 році запропонували конструкцію **одноразового коду автентифікації повідомлень** (*One-Time MAC*):

1. Сторони ділять секретний ключ на дві частини: ключ шифрування `k_enc` та пару ключів автентифікації `(h_key, m_pad)`.
2. Відкрите повідомлення розбивається на блоки та розглядається як коефіцієнти полінома над скінченним полем `GF(2^{128})`.
3. Тег автентифікації обчислюється як значення полінома в секретній точці `h_key`, до якого додається одноразова маска `m_pad`:
   ```
   Tag = PolyEval(h_key, m) ⊕ m_pad
   ```

Якщо маска `m_pad` використовується рівно один раз, супротивник не має можливості підробити тег для будь-якого зміненого повідомлення `m'` з імовірністю, вищою за `deg(Poly) / 2^{128} ≈ 0`. Цей принцип сьогодні лежить в основі найшвидших сучасних протоколів автентифікації, таких як Poly1305 та GHASH.

### 9. Зв'язок із сучасними потоковими шифрами (ChaCha20 та AES-CTR)

Усі сучасні симетричні **потокові шифри** (англ. *stream ciphers*), такі як ChaCha20 або блоковий шифр AES у режимі лічильника (AES-CTR), є прямими обчислювальними нащадками шифру Вернама.

Замість передачі гігабайтного фізичного блокнота потоковий шифр бере короткий фіксований ключ (наприклад, 256 бітів) та унікальний одноразовий номер повідомлення (**nonce** або *Number used ONCE*, наприклад 96 бітів). Криптографічний алгоритм генерує з пари `(Key, Nonce)` псевдовипадковий потік байтів необмеженої довжини (**keystream**), який потім додається до відкритого тексту операцією `XOR`:

```
c = m ⊕ Keystream(Key, Nonce)
```

З цього зв'язку випливає найважливіший практичний закон сучасної криптографії: **повторне використання пари `(Key, Nonce)` у ChaCha20 або AES-GCM є точно такою самою фатальною катастрофою Two-Time Pad, як і в класичному шифрі Вернама**.

Якщо два пакети зашифровані одним ключем із однаковим `Nonce`:
```
c₁ ⊕ c₂ = (m₁ ⊕ Keystream) ⊕ (m₂ ⊕ Keystream) = m₁ ⊕ m₂
```

Генератор гами повністю вилучається, і супротивник запускає атаку Crib Dragging над трафіком HTTPS або Wi-Fi. Саме ця вразливість повторного використання лічильників лежала в основі знаменитої атаки **KRACK** (*Key Reinstallation Attack*, 2017) проти протоколу WPA2, де зловмисник змушував Wi-Fi роутер повторно ініціалізувати лічильник потокового шифру, що дозволяло розшифровувати бездротовий інтернет-трафік на льоту.

### 10. Підводні камені та практичні обмеження

При розробці захищених систем на основі потокових або одноразових алгоритмів інженери часто припускаються типових системних помилок:

1. **Відсутність захисту від модифікації (Malleability):** One-Time Pad гарантує абсолютну конфіденційність, але забезпечує **нульову цілісність даних**. Якщо активний супротивник під час передачі в каналі зв'язку змінить `i`-й біт шифротексту `c'[i] = c[i] ⊕ 1`, то під час розшифрування у відкритому тексті одержувача точно так само інвертується `i`-й біт: `m'[i] = m[i] ⊕ 1`. Без обов'язкового шару автентифікації повідомлення (наприклад, поліноміального коду Poly1305 або HMAC) супротивник може маніпулювати сумами грошових переказів чи командами керування обладнанням без знання секретного ключа.
2. **Виснаження апаратного пулу ентропії:** спроба згенерувати гігабайти випадкових одноразових ключів на мікроконтролерах чи віртуальних машинах без апаратного джерела шуму може призвести до блокування системного виклику `getrandom()` або небезпечної деградації генератора до псевдовипадкового стану.
3. **Логістичний парадокс розподілу ключів:** для передачі секретного повідомлення розміром `N` мегабайтів відправник зобов'язаний заздалегідь передати одержувачу захищеним каналом ключ розміром точно `N` мегабайтів. Якщо сторони вже володіють абсолютно захищеним каналом такої пропускної здатності, вони могли б передати саме повідомлення безпосередньо без шифрування. Саме тому One-Time Pad історично застосовується лише у вузьких дипломатичних та військових лініях зв'язку з попередньо доставленими блокнотами, тоді як глобальна мережа Інтернет використовує обчислювально стійку асиметричну криптографію.
