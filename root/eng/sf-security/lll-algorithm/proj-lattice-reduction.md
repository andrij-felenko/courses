# ⚙️ Практикум LLL: реалізація алгоритму та криптоаналіз рюкзака

Реалізація LLL-алгоритму вимагає подолання двох протилежних інженерних викликів: необхідності збереження високої чисельної точності при ортогоналізації Грама — Шмідта та забезпечення максимальної швидкодії під час багаторазових розмірних редукцій та перестановок векторів.

---

### Архітектура та чисельні виклики редукції

Під час роботи класичного LLL-алгоритму над цілочисельними ґратками вектори базису `b_1, ..., b_n` залишаються цілими на кожному кроці, оскільки всі коефіцієнти розмірної редукції `q = ⌊μ_{k,j}⌉` є цілими числами. Проте коефіцієнти Грама — Шмідта `μ_{i,j}` та норми ортогональних векторів `‖b_i*‖²` є раціональними числами.

У точній арифметиці знаменник дробу `μ_{i,j}` може досягати величини квадрата визначника підґратки `d_j = (det Λ_j)²`. Для розмірностей `n ≥ 50` це призводить до чисел довжиною у сотні бітів. Постійне скорочення дробів через обчислення найбільшого спільного дільника суттєво уповільнює виконання.

Тому в практичних бібліотеках (таких як NTL, fplll, FLINT) використовують комбінований підхід:
1. **Базисні вектори `B`** зберігають як точні 64-бітні або багаторозрядні цілі числа (`int64_t` або `mpz_t`).
2. **Ортогональні вектори `B*` та коефіцієнти `μ`** обчислюють у числах із рухомою комою подвійної точності (`double` або `long double` з 80-бітною мантисою x87).
3. Після серії перестановок або у разі виявлення наближення `|μ_{i,j} - 1/2| < ε` виконують локальну переортогоналізацію, щоб уникнути накопичення похибок заокруглення.

#### Вибір структури даних та пам'яті
Вектори базису зберігають у рядковому форматі (row-major order). Це забезпечує локальність кеш-пам'яті процесора під час виконання найчастішої операції — лінійної комбінації векторів `b_k ← b_k - q · b_j` (операція AXPY у термінології BLAS). Оскільки довжина вектора `m` зазвичай перевищує кілька десятків елементів, послідовний доступ до пам'яті дозволяє компілятору автоматично застосовувати SIMD-інструкції (AVX-512, AVX2).

Крім того, операція обміну векторів `swap_rows` у мові C реалізується простим обміном двох вказівників на рядки за час `O(1)`, без необхідності копіювання `m` елементів. У C++ аналогічна поведінка досягається викликом `std::swap(basis_[k], basis_[k-1])`, що виконує швидкий обмін внутрішніх буферів динамічних векторів без виділення додаткової пам'яті.

#### Метод ортогоналізації: CGS проти MGS та поворотів Ґівенса
Класичний процес Грама — Шмідта (Classical Gram-Schmidt, CGS) є чисельно нестабільним через швидке накопичення похибок округлення при відніманні великих проєкцій. У модифікованому процесі (Modified Gram-Schmidt, MGS) кожен вектор ортогоналізується послідовно відносно оновлених проміжних результатів, що кардинально підвищує стійкість.

Найвищу чисельну надійність забезпечують ортогональні повороти Ґівенса (Givens rotations), які діють безпосередньо на матрицю `B`, зберігаючи її норму без обчислення скалярних добутків у стовпчиках. Замість явного збереження векторів `b_i*` та матриці `M` підтримують QR-розклад матриці базису:

```
B = Q · R
```

де `Q` — матриця з ортогональними стовпчиками (`Qᵀ Q = I`), а `R` — верхньотрикутна матриця. Діагональні елементи `R_{i,i}` відповідають нормам ортогональних векторів `‖b_i*‖`, а позадіагональні елементи пов'язані з коефіцієнтами проєкції співвідношенням `R_{j,i} = μ_{i,j} · R_{j,j}`.

Коли алгоритм міняє місцями два сусідні вектори `b_{k-1}` та `b_k`, у матриці `R` виникає один ненульовий піддіагональний елемент на позиції `(k, k-1)` (матриця набуває форми Хессенберга). Застосування одного двовимірного повороту Ґівенса `G(k-1, k, θ)` до рядків `k-1` та `k` матриці `R` миттєво повертає її до строго верхньотрикутного вигляду всього за `O(n)` операцій, повністю усуваючи потребу в повторному перерахунку процесу Грама — Шмідта з нуля.

### Тонкощі реалізації розмірного редукування

Розмірне редукування є внутрішнім серцем алгоритму. Його мета — зробити коефіцієнти проєкції `μ_{k,j}` меншими або рівними `1/2` за абсолютною величиною.

Проте порядок виконання віднімання векторів є критичним:
- Якщо редукувати коефіцієнти у прямому порядку (від `j = 0` до `j = k-1`), то віднімання вектора `b_j` із коефіцієнтом `q` змінить проєкції вектора `b_k` на всі попередні напрямки `b_l*` (`l < j`), оскільки сам вектор `b_j` містить ненульові складові вздовж `b_l*`. В результаті раніше редуковані коефіцієнти `μ_{k,l}` знову перевищать `1/2`.
- Тому розмірне редукування завжди виконують **у зворотному порядку** — від `j = k-1` спадаючи до `j = 0`. Коли ми віднімаємо вектор `b_j`, він має нульові складові вздовж векторів `b_l*` для всіх `l > j`. Це гарантує, що вже скориговані коефіцієнти `μ_{k,l}` для більших індексів `l > j` залишаться незмінними.

Також особливої уваги потребує заокруглення напівцілих чисел (наприклад, коли `μ = 0.5` або `μ = -0.5`). Використання симетричного заокруглення до найближчого парного або стандартної функції `round()` запобігає систематичному дрейфу коефіцієнтів в один бік.

Під час оновлення коефіцієнтів матриці `mu` у функції `size_reduce` замість повного переобчислення скалярних добутків застосовують швидку формулу коригування:

```
mu[k][l] -= q * mu[j][l]   для всіх l < j
mu[k][j] -= q
```

Ця формула виконується за час `O(j)`, що робить розмірне редукування значно швидшим за пряму ортогоналізацію.

### Повна реалізація LLL-алгоритму мовами C та C++

Нижче наведено самодостатню реалізацію LLL-алгоритму, що підтримує довільну розмірність ґратки, реалізує процеси Грама — Шмідта, розмірне редукування та умову Ловаса з параметром `δ = 3/4`.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>
#include <stdint.h>
#include <math.h>

#define LLL_DELTA 0.75

typedef struct {
    int rows;
    int cols;
    int64_t **data;
} IntMatrix;

typedef struct {
    int rows;
    int cols;
    double **data;
} DoubleMatrix;

IntMatrix create_int_matrix(int rows, int cols) {
    IntMatrix m;
    m.rows = rows;
    m.cols = cols;
    m.data = (int64_t **)malloc(rows * sizeof(int64_t *));
    for (int i = 0; i < rows; i++) {
        m.data[i] = (int64_t *)calloc(cols, sizeof(int64_t));
    }
    return m;
}

void free_int_matrix(IntMatrix *m) {
    if (!m || !m->data) return;
    for (int i = 0; i < m->rows; i++) {
        free(m->data[i]);
    }
    free(m->data);
    m->data = NULL;
}

DoubleMatrix create_double_matrix(int rows, int cols) {
    DoubleMatrix m;
    m.rows = rows;
    m.cols = cols;
    m.data = (double **)malloc(rows * sizeof(double *));
    for (int i = 0; i < rows; i++) {
        m.data[i] = (double *)calloc(cols, sizeof(double));
    }
    return m;
}

void free_double_matrix(DoubleMatrix *m) {
    if (!m || !m->data) return;
    for (int i = 0; i < m->rows; i++) {
        free(m->data[i]);
    }
    free(m->data);
    m->data = NULL;
}

/* Обчислення скалярного добутку дійсних векторів */
double dot_product_double(const double *u, const double *v, int dim) {
    double sum = 0.0;
    for (int i = 0; i < dim; i++) {
        sum += u[i] * v[i];
    }
    return sum;
}

/* Оновлення ортогоналізації Грама — Шмідта */
void compute_gram_schmidt(const IntMatrix *B, DoubleMatrix *B_star, DoubleMatrix *mu, double *B_star_norm_sq) {
    int n = B->rows;
    int m = B->cols;

    for (int i = 0; i < n; i++) {
        for (int c = 0; c < m; c++) {
            B_star->data[i][c] = (double)B->data[i][c];
        }

        for (int j = 0; j < i; j++) {
            double dot = 0.0;
            for (int c = 0; c < m; c++) {
                dot += (double)B->data[i][c] * B_star->data[j][c];
            }
            mu->data[i][j] = dot / B_star_norm_sq[j];

            for (int c = 0; c < m; c++) {
                B_star->data[i][c] -= mu->data[i][j] * B_star->data[j][c];
            }
        }
        mu->data[i][i] = 1.0;
        B_star_norm_sq[i] = dot_product_double(B_star->data[i], B_star->data[i], m);
    }
}

/* Розмірне редукування вектора b_k відносно b_j */
void size_reduce(IntMatrix *B, DoubleMatrix *mu, int k, int j) {
    if (fabs(mu->data[k][j]) > 0.5) {
        int64_t q = (int64_t)round(mu->data[k][j]);
        for (int c = 0; c < B->cols; c++) {
            B->data[k][c] -= q * B->data[j][c];
        }
        for (int l = 0; l < j; l++) {
            mu->data[k][l] -= (double)q * mu->data[j][l];
        }
        mu->data[k][j] -= (double)q;
    }
}

/* Обмін двох векторів місцями */
void swap_rows(IntMatrix *B, int i, int j) {
    int64_t *tmp = B->data[i];
    B->data[i] = B->data[j];
    B->data[j] = tmp;
}

/* Головна функція LLL-редукції */
void lll_reduce(IntMatrix *B, double delta) {
    int n = B->rows;
    int m = B->cols;

    DoubleMatrix B_star = create_double_matrix(n, m);
    DoubleMatrix mu = create_double_matrix(n, n);
    double *B_star_norm_sq = (double *)malloc(n * sizeof(double));

    compute_gram_schmidt(B, &B_star, &mu, B_star_norm_sq);

    int k = 1;
    while (k < n) {
        /* Крок 1: Розмірне редукування для пари (k, k-1) */
        size_reduce(B, &mu, k, k - 1);

        /* Крок 2: Перевірка умови Ловаса */
        double lhs = B_star_norm_sq[k];
        double rhs = (delta - mu.data[k][k - 1] * mu.data[k][k - 1]) * B_star_norm_sq[k - 1];

        if (lhs < rhs) {
            /* Умова Ловаса порушена -> Обмін b_k та b_{k-1} */
            swap_rows(B, k, k - 1);
            compute_gram_schmidt(B, &B_star, &mu, B_star_norm_sq);
            if (k > 1) {
                k--;
            }
        } else {
            /* Умова виконана -> Повне розмірне редукування для всіх j < k-1 */
            for (int j = k - 2; j >= 0; j--) {
                size_reduce(B, &mu, k, j);
            }
            k++;
        }
    }

    free(B_star_norm_sq);
    free_double_matrix(&B_star);
    free_double_matrix(&mu);
}
```

```cpp
#include <iostream>
#include <vector>
#include <cmath>
#include <cstdint>
#include <iomanip>
#include <algorithm>
#include <span>
#include <optional>

class Lattice {
public:
    explicit Lattice(std::vector<std::vector<int64_t>> basis)
        : basis_(std::move(basis)),
          n_(static_cast<int>(basis_.size())),
          m_(static_cast<int>(basis_.empty() ? 0 : basis_[0].size())) {}

    [[nodiscard]] int rows() const noexcept { return n_; }
    [[nodiscard]] int cols() const noexcept { return m_; }
    [[nodiscard]] const std::vector<int64_t>& operator[](size_t i) const { return basis_[i]; }
    [[nodiscard]] std::vector<int64_t>& operator[](size_t i) { return basis_[i]; }

    void reduce(double delta = 0.75) {
        if (n_ <= 1) return;

        std::vector<std::vector<double>> b_star(n_, std::vector<double>(m_, 0.0));
        std::vector<std::vector<double>> mu(n_, std::vector<double>(n_, 0.0));
        std::vector<double> b_star_sq(n_, 0.0);

        compute_gso(b_star, mu, b_star_sq);

        int k = 1;
        while (k < n_) {
            // Розмірне редукування для сусіднього вектора
            size_reduce(k, k - 1, mu);

            // Перевірка умови Ловаса
            const double lhs = b_star_sq[k];
            const double rhs = (delta - mu[k][k - 1] * mu[k][k - 1]) * b_star_sq[k - 1];

            if (lhs < rhs) {
                // Обмін та крок назад
                std::swap(basis_[k], basis_[k - 1]);
                compute_gso(b_star, mu, b_star_sq);
                if (k > 1) {
                    k--;
                }
            } else {
                // Повне розмірне редукування для попередніх напрямків
                for (int j = k - 2; j >= 0; j--) {
                    size_reduce(k, j, mu);
                }
                k++;
            }
        }
    }

private:
    void compute_gso(std::vector<std::vector<double>>& b_star,
                     std::vector<std::vector<double>>& mu,
                     std::vector<double>& b_star_sq) const {
        for (int i = 0; i < n_; i++) {
            for (int c = 0; c < m_; c++) {
                b_star[i][c] = static_cast<double>(basis_[i][c]);
            }
            for (int j = 0; j < i; j++) {
                double dot = 0.0;
                for (int c = 0; c < m_; c++) {
                    dot += static_cast<double>(basis_[i][c]) * b_star[j][c];
                }
                mu[i][j] = dot / b_star_sq[j];
                for (int c = 0; c < m_; c++) {
                    b_star[i][c] -= mu[i][j] * b_star[j][c];
                }
            }
            mu[i][i] = 1.0;
            double norm_sq = 0.0;
            for (int c = 0; c < m_; c++) {
                norm_sq += b_star[i][c] * b_star[i][c];
            }
            b_star_sq[i] = norm_sq;
        }
    }

    void size_reduce(int k, int j, std::vector<std::vector<double>>& mu) {
        if (std::abs(mu[k][j]) > 0.5) {
            const auto q = static_cast<int64_t>(std::round(mu[k][j]));
            for (int c = 0; c < m_; c++) {
                basis_[k][c] -= q * basis_[j][c];
            }
            for (int l = 0; l < j; l++) {
                mu[k][l] -= static_cast<double>(q) * mu[j][l];
            }
            mu[k][j] -= static_cast<double>(q);
        }
    }

    std::vector<std::vector<int64_t>> basis_;
    int n_;
    int m_;
};
```

### Криптоаналіз задачі рюкзака (Subset Sum) на практиці

Розглянемо практичний приклад використання наведеного коду для розв'язання задачі про суму підмножин (Subset Sum), на якій базувалася класична асиметрична криптосистема Меркля — Геллмана.

#### Постановка задачі та поняття щільності рюкзака
Нехай задано відкритий набір цілих ваг `a = (a_1, a_2, ..., a_n)` та зашифроване повідомлення — скалярну цільову суму `S`:

```
S = ∑_{i=1}^n x_i · a_i,   де x_i ∈ {0, 1}
```

Складність розв'язання задачі рюкзака визначається її **щільністю** (density) `d`:

```
d = n / max_{1 ≤ i ≤ n} log₂(a_i)
```

- Якщо щільність висока (`d > 1`), простір розв'язків містить експоненційно багато випадкових комбінацій бітів, що дають ту саму суму `S`.
- Якщо щільність низька (`d < 0.9408`), розв'язок майже напевно єдиний і відповідає аномально короткому вектору в спеціально сконструйованій ґратці.

У 1985 році Джеффрі Лагаріас та Ендрю Одляжко довели, що для `d < 0.6463` задачу рюкзака можна поліноміально розв'язати через LLL. У 1992 році Клос, Жу, Ламаккіа, Одляжко, Шнорр та Штерн (алгоритм CJLOSS) підвищили цю межу до `d < 0.9408`.

#### Побудова матриці вкладення ґратки CJLOSS
Для відновлення секретного двійкового вектора `x = (x_1, ..., x_n)` будують ґратку вкладення розмірності `(n+1) × (n+1)`:

```
B = 
[  1   0  ...  0   N · a₁ ]
[  0   1  ...  0   N · a₂ ]
[ ... ... ... ...    ...  ]
[  0   0  ...  1   N · aₙ ]
[  1/2 1/2 .. 1/2  N · S  ]
```

де масштабний коефіцієнт `N > 1/2 · √n`. Щоб зберегти цілочисельність матриці, всі елементи множать на `2`:

```
B' = 
[  2   0  ...  0   2 · N · a₁ ]
[  0   2  ...  0   2 · N · a₂ ]
[ ... ... ... ...      ...    ]
[  0   0  ...  2   2 · N · aₙ ]
[  1   1  ...  1   2 · N · S  ]
```

Розглянемо лінійну комбінацію рядків матриці з коефіцієнтами `(x_1, x_2, ..., x_n, -1)`:
- Перші `n` координат утворюють вектор з елементів `2 · x_i - 1 ∈ {-1, +1}`.
- Остання координата дорівнює `2N · (∑ x_i a_i - S) = 0`.

Довжина цього вектора складає всього `√n`, тоді як усі інші нетривіальні вектори ґратки за рахунок коефіцієнта `N` мають довжину щонайменше `2N > √n`. Після виконання LLL-редукції цей вектор виявляється найкоротшим і займає перші рядки редукованого базису. Секретні біти `x_i` відновлюються за простою формулою:

```
x_i = (v_i + 1) / 2
```

Нижче наведено завершений модуль розв'язання задачі рюкзака:

:::tabs
```c
/* Практичний розв'язок задачі рюкзака через LLL */
void solve_knapsack(const int64_t *weights, int n, int64_t target_sum) {
    int dim = n + 1;
    IntMatrix B = create_int_matrix(dim, dim);
    int64_t N = (int64_t)ceil(0.5 * sqrt((double)n)) + 10;

    for (int i = 0; i < n; i++) {
        B.data[i][i] = 2;
        B.data[i][n] = 2 * N * weights[i];

    lll_reduce(&B, LLL_DELTA);

    /* Пошук вектора розв'язку */
    bool found = false;
    for (int row = 0; row < dim; row++) {
        if (B.data[row][n] == 0) {
            bool valid = true;
            for (int j = 0; j < n; j++) {
                if (abs((int)B.data[row][j]) != 1) {
                    valid = false;
                    break;
                }
            }
            if (valid) {
                printf("Знайдено секретний бітовий вектор x: [ ");
                for (int j = 0; j < n; j++) {
                    int bit = (B.data[row][0] > 0) ? (B.data[row][j] > 0 ? 1 : 0) : (B.data[row][j] < 0 ? 1 : 0);
                    printf("%d ", bit);
                }
                printf("]\n");
                found = true;
                break;
            }
        }
    }

    if (!found) {
        printf("Розв'язок не знайдено (потрібна вища щільність або більший параметр delta).\n");
    }

    free_int_matrix(&B);
}
```

### Знаходження цілочисельних лінійних співвідношень та мінімальних многочленів

Ще одним потужним інженерним застосуванням LLL є **знаходження цілочисельних залежностей** між набором дійсних чисел `α_1, α_2, ..., α_n ∈ ℝ` (алгоритм знаходження цілочисельних лінійних зв'язків).

Задача полягає у знаходженні такого ненульового набору цілих чисел `m_1, m_2, ..., m_n ∈ ℤ`, для якого:

```
∑_{i=1}^n m_i · α_i = 0
```

#### Алгоритм знаходження мінімального многочлена алгебраїчного числа
Нехай відомо чисельне значення деякого алгебраїчного числа `α` з високою точністю (наприклад, `α = 1.414213562373...`). Ми хочемо знайти незвідний многочлен `P(x) = c_d x^d + ... + c_1 x + c_0 ∈ ℤ[x]`, коренем якого є `α`.

Для цього формують вектор степенів `(1, α, α², ..., α^d)` і будують ґратку розмірності `(d+2) × (d+1)` або `(d+1) × (d+2)` з великим масштабним коефіцієнтом `M = 10^K`:

```
B = 
[  1   0   ...  0   ⌊M · 1⌋    ]
[  0   1   ...  0   ⌊M · α⌋    ]
[  0   0   ...  0   ⌊M · α²⌋   ]
[ ... ...  ... ...    ...      ]
[  0   0   ...  1   ⌊M · αᵈ⌋   ]
```

Після виконання LLL-редукції найкоротший вектор `v = (c_0, c_1, ..., c_d, ε)` містить у перших `d+1` позиціях точні цілі коефіцієнти мінімального многочлена `c_0 + c_1 α + ... + c_d α^d ≈ 0`.

---

### Одночасне діофантове наближення

Класична теорема Діріхле стверджує, що для будь-яких дійсних чисел `α_1, ..., α_n` та будь-якого цілого обмеження `Q > 1` існує спільний цілочисельний знаменник `1 ≤ q ≤ Q` та цілі чисельники `p_1, ..., p_n ∈ ℤ` такі, що:

```
|q · α_i - p_i| ≤ Q^{-1/n}   для всіх i = 1, ..., n
```

Знаходження такого знаменника `q` прямим перебором вимагає `O(Q)` кроків, що нездійсненно для великих `Q`.

За допомогою LLL задача зводиться до пошуку короткого вектора у ґратці розмірності `(n+1)` з матрицею базису:

```
B = 
[  2^K · α₁   2^K · α₂  ...  2^K · αₙ   1 / Q  ]
[   -2^K         0      ...     0         0    ]
[     0        -2^K     ...     0         0    ]
[   ...         ...     ...    ...       ...   ]
[     0          0      ...   -2^K        0    ]
```

Лінійна комбінація рядків із коефіцієнтом `q` для першого рядка та `p_i` для інших рядків утворює вектор із координатами `(2^K (q α_1 - p_1), ..., 2^K (q α_n - p_n), q / Q)`. Редукція ґратки знаходить гарантоване наближення за поліноміальний час.

### Цілочисельне лінійне програмування у фіксованій розмірності (Алгоритм Хендріка Ленстри)

У загальному випадку задача цілочисельного лінійного програмування (ILP) є NP-повною. Проте у 1983 році Хендрік Ленстра зробив фундаментальне відкриття: якщо розмірність простору `d` є фіксованою константою, задачу ILP можна розв'язати за поліноміальний час `O(poly(L))`, де `L` — розмір вхідних даних.

Ключовим інструментом методу Ленстри є редукція ґраток:
1. За допомогою афінного перетворення опуклий багатогранник обмежень `K ⊂ ℝ^d` переводять у «майже сферичне» тіло (еліпсоїд Джона).
2. Застосовують LLL-редукцію до ґратки `ℤ^d` у трансформованому просторі.
3. Отримують так званий «тонкий напрямок» — вектор нормалі, вздовж якого багатогранник `K` має невелику ширину `w(K)`.
4. Багатогранник розрізають на обмежену кількість паралельних гіперплощин (число яких залежить виключно від розмірності `d`, наприклад, не більше `2^{O(d²)}`), зводячи задачу розмірності `d` до скінченного набору підзадач меншої розмірності `d-1`.

Цей результат остаточно закріпив геометрію ґраток як фундаментальний інструмент дискретної оптимізації.

### Застосування у криптоаналізі RSA: метод Копперсміта

У 1996 році Дон Копперсміт показав, як за допомогою LLL знаходити малі цілочисельні корені модульних многочленів.

Нехай дано нормований многочлен `f(x) = x^d + a_{d-1} x^{d-1} + ... + a_0` степеня `d`, і ми шукаємо невідомий цілий корінь `x_0`, для якого:

```
f(x_0) ≡ 0 mod N
```

де модуль `N` є складеним числом невідомої факторизації, а величина кореня обмежена відомою межею `|x_0| < X`.

Копперсміт побудував сімейство допоміжних многочленів:

```
g_{i,j}(x) = x^i · N^{m - j} · f(x)^j
```

де кожен такий многочлен автоматично задовольняє умову `g_{i,j}(x_0) ≡ 0 mod N^m`.

Якщо скласти матрицю ґратки з коефіцієнтів многочленів `g_{i,j}(x · X)` і застосувати LLL-редукцію, перший вектор редукованого базису відповідатиме многочлену `h(x)`, евклідова норма коефіцієнтів якого задовольняє нерівність:

```
‖h(x · X)‖ < N^m / √dim
```

За лемою Хаугрейва, якщо ця нерівність виконується, то рівність `h(x_0) = 0` справджується **не за модулем `N^m`, а строго над кільцем цілих чисел `ℤ`!** Знаходження коренів многочлена `h(x)` над `ℤ` є тривіальною чисельною задачею (методом Ньютона або розкладом над `ℚ[x]`).

Це дозволяє за поліноміальний час знаходити будь-який корінь, що не перевищує межу Копперсміта `X = N^{1/d}`. Зокрема, для RSA з відкритим експонентом `e = 3` (шифрування повідомлень із відомим шаблоном або спільними заголовками) метод відновлює весь відкритий текст повідомлення без знання секретного ключа `d`.

### Порівняльний аналіз якості редукції: кореневий фактор Ерміта

Якість редукції базису в криптоаналізі та постквантовій криптографії оцінюють за допомогою **кореневого фактора Ерміта** (root Hermite factor) `δ_0`:

```
‖b_1‖ = δ_0^n · (det Λ)^{1 / n}
```

Чим ближче значення `δ_0` до одиниці, тим коротшим є перший знайдений вектор і тим глибшою є редукція:

| Алгоритм редукції | Значення `δ_0` | Часова складність для `n = 100` | Сфера застосування |
| :--- | :--- | :--- | :--- |
| **LLL (δ = 0.75)** | `≈ 1.0219` | Мілісекунди | Швидкий попередній фільтр, рюкзаки низької щільності |
| **LLL (δ = 0.99)** | `≈ 1.0185` | Десятки мілісекунд | Знаходження поліноміальних залежностей, атака Копперсміта |
| **BKZ-20** | `≈ 1.0128` | Секунди | Злам схем на ґратках середньої розмірності |
| **BKZ-40** | `≈ 1.0090` | Хвилини | Криптоаналіз NTRU з малим модулем |
| **BKZ-60+** | `≈ 1.0065` | Години / дні | Оцінка стійкості стандартів NIST (Kyber, Dilithium) |

Як видно з таблиці, класичний LLL забезпечує неперевершену швидкість, проте для зламу криптографічних схем із високими вимогами до ортогональності його використовують як внутрішній базовий блок у складі блочного алгоритму BKZ.

### Методологія тестування та бенчмаркінгу на випадкових ґратках

Для всебічної перевірки коректності реалізації LLL-алгоритму використовують стандартний набір тестових сценаріїв:

#### 1. Ґратки Гольдштейна — Майєра (Goldstein — Mayer)
Ці ґратки генеруються шляхом вибору випадкового великого простого числа `p` та випадкового цілочисельного вектора `u ∈ ℤ_p^{n-1}`. Базис складається з діагональних векторів `p · e_i` та одного вектора `(u_1, u_2, ..., u_{n-1}, 1)`. Така ґратка має відомий детермінант `det(Λ) = p` і слугує стандартним калібрувальним тестом для вимірювання часу виконання та фактора Ерміта.

#### 2. Перевірка інваріантів під час редукції
Надійна тестова обв'язка повинна перевіряти три обов'язкові алгебраїчні інваріанти:
- **Інваріантність ґратки:** визначник матриці Грама `det(Bᵀ B)` до і після редукції повинен збігатися з абсолютною точністю (перевіряється в точних цілих числах або за модулем великого простого числа).
- **Виконання розмірного редукування:** після завершення алгоритму кожен коефіцієнт Грама — Шмідта повинен задовольняти строгу умову `|μ_{i,j}| ≤ 0.5000001`.
- **Виконання умови Ловаса:** для кожної сусідньої пари векторів має виконуватися нерівність `‖b_k*‖² ≥ (δ - μ_{k,k-1}²) ‖b_{k-1}*‖²`.

#### 3. Порівняння з промисловими бібліотеками (fplll, NTL)
Під час компіляції оптимізованого коду прапорцями `-O3 -march=native -ffast-math` нативна реалізація мовами C/C++ повинна демонструвати час редукції випадкової ґратки розмірності `n = 60` у межах 20–50 мілісекунд на сучасному процесорі x86-64.

### Профілювання продуктивності та сучасні оптимізації

Під час аналізу профілю виконання LLL-алгоритму на великих розмірностях (`n ≥ 100`) час розподіляється наступним чином:
- Близько `70–80%` процесорного часу витрачається на операції розмірного редукування (`b_k ← b_k - q · b_j`).
- Близько `15–20%` часу займає оновлення коефіцієнтів ортогоналізації Грама — Шмідта або матриці поворотів `R`.
- Менше `5%` часу припадає на перевірку умови Ловаса та керування циклом.

Для досягнення максимальної продуктивності в сучасних бібліотеках застосовують такі оптимізації:

#### 1. Векторизація SIMD та вирівнювання пам'яті
Масиви векторів вирівнюють на межу 32 або 64 байтів (`posix_memalign` або `std::aligned_alloc`). Це дозволяє компілятору генерувати інструкції `vfmadd213pd` та `vmovapd`, обробляючи по 4 або 8 чисел з рухомою комою за один такт процесора.

#### 2. Блочний паралелізм та поділ на підґратки
Хоча класичний крок умови Ловаса є строго послідовним, розмірне редукування вектора `b_k` відносно незалежних блоків попередніх векторів можна виконувати паралельно на кількох ядрах процесора за допомогою OpenMP або потоків std::jthread.

#### 3. Раннє виявлення завершення
Якщо протягом повного проходу по всіх індексах від `1` до `n` жодного разу не виникло потреби в обміні векторів `b_k ↔ b_{k-1}`, базис уже є повністю LLL-редукованим, і повторні перевірки негайно зупиняються.

### Інженерні пастки та рекомендації з налагодження

Під час промислової експлуатації LLL-редукції необхідно враховувати специфічні підводні камені:

#### 1. Чисельна втрата точності в `double` (Numerical Instability)
Якщо координати початкових векторів перевищують `2⁵³` (розрядність мантиси типу `double`), похибки заокруглення при обчисленні `mu[i][j]` накопичуються. В результаті умова Ловаса може циклічно перемикатися в обидва боки: алгоритм виконує обмін `b_k ↔ b_{k-1}`, на наступному кроці знову бачить порушення умови й повертає вектори назад, потрапляючи у нескінченний цикл.

*Рішення:*
- Використовувати алгоритм `L²` Нгуєна — Стеле, який динамічно адаптує бітову точність мантиси від `53` бітів до `128` або `256` бітів.
- Зберігати матрицю Грама `G_{i,j} = ⟨b_i, b_j⟩` у точних цілих числах великої розрядності.

#### 2. Вибір параметра Ловаса `δ`
Теоретичний діапазон параметра становить `1/4 < δ ≤ 1`. 
- При `δ = 0.75` кількість операцій обміну мінімальна, що забезпечує найвищу швидкість виконання алгоритму.
- При `δ = 0.99` базис виходить значно якіснішим (коротшим та ближчим до взаємної ортогональності), що критично для криптографічних атак на межі щільності, але час виконання зростає на 30–40%.
- При `δ = 1.0` алгоритм формально втрачає строгу гарантію поліноміального часу у найгіршому випадку.

#### 3. Нульові вектори та лінійна залежність
Якщо вхідний набір містить лінійно залежні вектори, у процесі Грама — Шмідта з'явиться нульовий вектор `b_i* = 0`, що призведе до ділення на нуль при обчисленні `μ_{k,i}`. У виробничих бібліотеках лінійно залежні вектори автоматично виявляються за умовою `‖b_i*‖² < 10⁻¹²`, видаляються з базису або переміщуються у фінальні рядки матриці.
