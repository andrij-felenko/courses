# 🧮 Математика екстракції: мін-ентропія, універсальне гешування та коректор фон Неймана

У криптографічному аналізі оцінка якості випадковості спирається не на середню інформативність сигналу, а на найгірший можливий сценарій для захисника — максимальну ймовірність, з якою супротивник здатен вгадати значення з однієї спроби. Ця вставка розгортає математичний апарат, що пов'язує спектр ентропій Реньї, формулює лему про залишковий геш (Leftover Hash Lemma), описує лінійні екстрактори на базі матриць Тепліца та строго доводить усунення статистичного зміщення коректором Джона фон Неймана.

## Спектр ентропій Реньї та місце мін-ентропії

Нехай `X` — дискретна випадкова величина, що набуває значень із скінченної множини `Ω` з розподілом ймовірностей `P(X = x) = p(x)`. Узагальнене однопараметричне сімейство ентропій Альфреда Реньї (Alfréd Rényi) порядку `α` (де `α ≥ 0`, `α ≠ 1`) визначається як нормалізований логарифм суми ступенів ймовірностей:

```
H_α(X) = 1 / (1 − α) · log₂( ∑_{x ∈ Ω} p(x)^α )
```

У граничних випадках параметру `α` це сімейство породжує чотири фундаментальні величини теорії інформації та криптографії:

1. **Макс-ентропія, або ентропія Гартлі (`α = 0`):** логарифм потужності носія розподілу (кількості подій з ненульовою ймовірністю):
```
H₀(X) = log₂ |{x ∈ Ω : p(x) > 0}|
```

2. **Ентропія Шеннона (`α → 1`):** середня невизначеність випадкової величини, що обчислюється за правилом Лопіталя при наближенні `α` до одиниці:
```
H₁(X) = lim_{α → 1} H_α(X) = − ∑_{x ∈ Ω} p(x) · log₂ p(x)
```

3. **Колізійна ентропія (`α = 2`):** логарифм імовірності того, що два незалежні однаково розподілені випробування випадкової величини `X` дадуть однаковий результат (колізію `x₁ = x₂`):
```
H₂(X) = −log₂( ∑_{x ∈ Ω} p(x)² )
```

4. **Мін-ентропія (`α → ∞`):** від'ємний двійковий логарифм імовірності найімовірнішого елемента множини `Ω`:
```
H_∞(X) = lim_{α → ∞} H_α(X) = −log₂( max_{x ∈ Ω} p(x) )
```

Між цими величинами діє строга монотонна нерівність для будь-якого нерівномірного розподілу:

```
H₀(X) ≥ H₁(X) ≥ H₂(X) ≥ H_∞(X)
```

Рівність між усіма чотирма метриками досягається виключно тоді, коли розподіл є строго рівномірним на всій множині `Ω` (`p(x) = 1 / |Ω|`).

### Чому Шеннонівської ентропії недостатньо для безпеки

Розгляньмо практичний приклад небезпеки орієнтації на середній інформаційний вміст. Нехай сенсор формує 64-бітне значення. Припустимо, що через збій у схемі з імовірністю `p = ½` джерело повертає фіксовану константу `0x0000000000000000`, а з імовірністю `1 − p = ½` повертає одне з `2⁶⁴ − 1` решти значень з абсолютно рівномірною ймовірністю `1 / (2 · (2⁶⁴ − 1))`.

Обчислімо ентропію Шеннона `H₁(X)`:

```
H₁(X)
= − ( ½ · log₂(½) + (2⁶⁴ − 1) · [ 1 / (2 · (2⁶⁴ − 1)) ] · log₂( 1 / (2 · (2⁶⁴ − 1)) ) )
= − ( −½ + ½ · ( −1 − log₂(2⁶⁴ − 1) ) )
= ½ + ½ · ( 1 + log₂(2⁶⁴ − 1) )
≈ ½ + ½ · (1 + 64)
= 33 біти    [високий середній інформаційний вміст]
```

Ентропія Шеннона показує понад 32 біти непевності. Стандартний тест стиснення або оцінювач Шеннона вважатиме такий потік наполовину випадковим. Проте мін-ентропія цього джерела становить:

```
H_∞(X)
= −log₂( max_{x} p(x) )
= −log₂( ½ )
= 1 біт    [реальна криптографічна стійкість]
```

Супротивник, який завжди перевіряє значення `0`, угадує вихід генератора в половині всіх спроб (`50%` успіху). Для створення 256-бітного симетричного ключа з такого джерела потрібно взяти не `256 / 33 ≈ 8` відліків, а щонайменше `256 / 1 = 256` повних відліків. Криптографічна стійкість системи гарантується виключно показником `H_∞(X)`.

## Лема про залишковий геш (Leftover Hash Lemma)

Якщо фізичне джерело генерує `n`-бітний рядок `X` із мін-ентропією `H_∞(X) = k < n`, цей рядок містить статистичні нерівномірності й не може слугувати криптографічним ключем безпосередньо. Потрібен детермінований екстрактор ентропії, що стискає `n` слабких бітів у `m` бітів (`m < k`), статистична відстань яких від ідеального рівномірного розподілу `U_m` є зневажливо малою.

Нехай `H = { h : {0, 1}ⁿ → {0, 1}ᵐ }` — сімейство функцій. Воно називається **2-універсальним** (англ. *2-universal hash family*), якщо для будь-якої пари різних входів `x₁ ≠ x₂`:

```
P_{h ∈ H}( h(x₁) = h(x₂) ) ≤ 2⁻ᵐ
```

**Формулювання леми (Impagliazzo, Levin, Luby, 1989):**  
Нехай `X` — випадкова величина над множиною `{0, 1}ⁿ` з мін-ентропією `H_∞(X) ≥ k`. Нехай `H` — 2-універсальне сімейство геш-функцій із `{0, 1}ⁿ` у `{0, 1}ᵐ`. Нехай функція `h` обирається з `H` рівномірно й незалежно від `X`. Тоді статистична відстань (відстань за варіацією) `Δ` між розподілом пари `(h, h(X))` та розподілом пари з ідеальним випадковим вектором `(h, U_m)` обмежена зверху:

```
Δ( (h, h(X)), (h, U_m) )
= ½ · ∑_{y, g} | P(h=g, h(X)=y) − P(h=g, U_m=y) |
≤ ½ · √( 2^{m − k} )
```

### Виведення граничної довжини екстрагованого блоку

Нехай розробник вимагає, щоб згенерований блок відрізнявся від ідеального шуму з відстанню не більше ніж `ε = 2⁻ˢ` (де `s` — параметр запасу безпеки, наприклад `s = 64`):

```
½ · √( 2^{m − k} ) ≤ 2⁻ˢ
√( 2^{m − k} ) ≤ 2 · 2⁻ˢ = 2^{1 − s}
2^{m − k} ≤ 2^{2 − 2s}
m − k ≤ 2 − 2s
m ≤ k − 2s + 2    [верхня межа довжини безпечного виходу]
```

Звідси випливає фундаментальне інженерне правило: щоб отримати `m = 256` криптографічних бітів із похибкою не більше `2⁻⁶⁴`, сире джерело має накопичити блок з мін-ентропією щонайменше:

```
k ≥ m + 2s − 2 = 256 + 128 − 2 = 382 біти мін-ентропії
```

Різниця `k − m = 126` бітів — це так звана «ентропійна плата» (entropy loss), необхідна для компенсації можливих відхилень від 2-універсальності та забезпечення невідрізненності від чистого шуму.

## Лінійні екстрактори на матрицях Тепліца

В апаратних реалізаціях ASIC та FPGA універсальне гешування реалізують за допомогою множення вхідного вектора на випадкову **матрицю Тепліца** (Toeplitz matrix) розміром `m × n` над полем `GF(2)`.

Матриця `T` є тепліцевою, якщо всі елементи вздовж кожної низхідної діагоналі рівні між собою: `T[i, j] = t_{i − j}`. Для визначення матриці розміром `m × n` потрібно зберегти лише `n + m − 1` випадкових бітів насіння:

```
T = [ t₀      t₋₁     t₋₂     …  t_{1−n} ]
    [ t₁      t₀      t₋₁     …  t_{2−n} ]
    [ t₂      t₁      t₀      …  t_{3−n} ]
    [ …       …       …       …  …       ]
    [ t_{m−1} t_{m−2} t_{m−3} …  t_{m−n} ]
```

Обчислення вихідного вектора `y = T · x (mod 2)` у бітовій формі:

```
y[i] = ⊕_{j=0}^{n-1} ( T[i, j] ∧ x[j] )
```

Сімейство всіх таких матриць утворює строгий 2-універсальний екстрактор. Його обчислення потребує лише регістрів зсуву з лінійними зворотними зв'язками (LFSR) та матриці елементів XOR, що дозволяє виконувати екстракцію без затримок конвеєра на частотах понад 1 ГГц.

## Математичне доведення коректора Джона фон Неймана

Нехай фізичне джерело генерує послідовність незалежних бітів `b₁, b₂, b₃, …` зі сталим, але невідомим зміщенням:

```
P(bᵢ = 1) = p
P(bᵢ = 0) = 1 − p = q    [де p ≠ ½]
```

Алгоритм фон Неймана групує вхідний потік у неперетинні пари `(b₂ₖ₋₁, b₂ₖ)` та застосовує наступне відображення:

```
(0, 1) ↦ 0
(1, 0) ↦ 1
(0, 0) ↦ відкинути (∅)
(1, 1) ↦ відкинути (∅)
```

### Доведення незміщеності виходу

Оскільки послідовні відліки фізичного шуму вважаються взаємно незалежними, ймовірність появи кожної пари дорівнює добутку ймовірностей її компонентів:

```
P( (0, 1) ) = P(b₁=0) · P(b₂=1) = (1 − p) · p = q · p
P( (1, 0) ) = P(b₁=1) · P(b₂=0) = p · (1 − p) = p · q
P( (0, 0) ) = P(b₁=0) · P(b₂=0) = (1 − p)² = q²
P( (1, 1) ) = P(b₁=1) · P(b₂=1) = p²
```

Повна ймовірність того, що довільна пара згенерує вихідний біт:

```
P_accept = P( (0, 1) ) + P( (1, 0) ) = 2 · p · (1 − p)
```

Обчислімо умовну ймовірність отримання вихідного нуля за умови, що пара була прийнята:

```
P( вихід = 0 | пара прийнята )
= P( (0, 1) ) / P_accept
= ( q · p ) / ( 2 · p · q )
= ½    [доведення ідеальної симетрії]
```

Аналогічно для одиниці:

```
P( вихід = 1 | пара прийнята )
= P( (1, 0) ) / P_accept
= ( p · q ) / ( 2 · p · q )
= ½
```

### Пропускна здатність та крайові випадки

Ефективність коректора (відношення кількості вихідних бітів до кількості вхідних) дорівнює:

```
η(p) = P_accept / 2 = p · (1 − p)
```

Максимальна теоретична продуктивність досягається при `p = ½`, де `η(½) = ¼ = 25%`. Якщо джерело сильно асиметричне (наприклад, `p = 0.8`), вихідна швидкість падає до:

```
η(0.8) = 0.8 · (1 − 0.8) = 0.16 = 16% від вхідного потоку
```

**Критичне припущення теореми:** доведення строго спирається на **повну статистичну незалежність** бітів у парі (`P(b₂ | b₁) = P(b₂)`). Якщо фізичний шум має часову пам'ять або автокореляцію (наприклад, через інерційність компаратора або паразитну ємність, що утримує попередній стан), рівність `P(01) = P(10)` руйнується:

```
P( (0, 1) ) = P(b₁=0) · P(b₂=1 | b₁=0)
P( (1, 0) ) = P(b₁=1) · P(b₂=0 | b₁=1)
```

Якщо `P(b₂=1 | b₁=0) ≠ P(b₂=0 | b₁=1)`, вихід коректора фон Неймана залишається зміщеним. У таких випадках перед коректором необхідно або застосовувати апаратне проріджування відліків у часі, або використовувати універсальні екстрактори на основі криптографічних геш-функцій.
