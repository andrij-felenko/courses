# 📋 Інтерфейси ентропії ядра Linux: системні виклики та псевдофайли

Отримання криптографічно стійких випадкових байтів у середовищі Linux вимагає чіткого розуміння семантики блокування ядра на ранніх етапах завантаження системи. Цей довідник описує публічні інтерфейси підсистеми випадковості: системний виклик `getrandom(2)`, функцію стандартної бібліотеки `getentropy(3)`, спеціальні символьні пристрої `/dev/random` та `/dev/urandom`, параметри конфігурації у псевдофайловій системі `/proc/sys/kernel/random/`, операції `ioctl` для керування пулом, а також механізми інтеграції служб ініціалізації на ранньому старті.

## Системний виклик `getrandom(2)`

Системний виклик додано в ядро Linux 3.17 для усунення критичних проблем безпеки: вичерпання пулу файлових дескрипторів у пісочницях (chroot/seccomp), небезпеки передчасного читання неініціалізованого `/dev/urandom` та блокування `/dev/random` на серверах без активного вводу.

### Сигнатура інтерфейсу

:::tabs
```c
#include <sys/random.h>
#include <sys/types.h>

ssize_t getrandom(void *buf, size_t buflen, unsigned int flags);
```
```cpp
#include <sys/random.h>
#include <cstddef>
#include <span>
#include <system_error>

namespace sys {
    [[nodiscard]] std::error_code get_random(std::span<std::byte> buffer, unsigned int flags = 0) noexcept;
}
```
:::

### Прапорці керування (`flags`)

| Прапорець | Числове значення | Семантика та поведінка ядра |
| :--- | :--- | :--- |
| `0` (за замовчуванням) | `0x0000` | Читає випадкові байти з головного CRNG (ChaCha20). Якщо ядро ще **не досягло** стану `crng_ready()`, виклик **блокує** потік до накопичення 256 бітів ентропії. Після ініціалізації виклик ніколи не блокується. |
| `GRND_NONBLOCK` | `0x0001` | Не блокувати процес. Якщо стан `crng_ready()` ще не досягнуто, системний виклик негайно завершується з кодом помилки `-1`, а змінній `errno` присвоюється значення `EAGAIN`. |
| `GRND_RANDOM` | `0x0002` | Історичний прапорець вибору пулу. Починаючи з версії Linux 5.6, використовує той самий ChaCha20 CRNG, що й стандартний режим, але враховує залишок оціненої ентропії у лічильнику ядра. |
| `GRND_INSECURE` | `0x0400` | Додано в Linux 5.6. Дозволяє отримати байти навіть тоді, коли стан `crng_ready()` ще не настано (використовується для некриптографічних задач, наприклад ініціалізації хеш-таблиць або перемішування списків). |

### Коди помилок (`errno`)

- `EAGAIN`: прапорець `GRND_NONBLOCK` встановлено, але ядро ще не накопичило необхідні 256 бітів ентропії;
- `EINTR`: системний виклик було перервано обробником сигналу під час блокуючого очікування ініціалізації;
- `EFAULT`: адреса буфера `buf` лежить за межами доступного адресного простору викликаючого процесу;
- `EINVAL`: передано невідомі прапорці або значення `buflen` перевищує максимальну дозволену межу `33554431` байтів (32 МБ - 1 байт).

### Внутрішня поведінка та атомарність

Якщо запитаний розмір `buflen ≤ 256` байтів, системний виклик гарантує **атомарність повернення**: після виходу зі стану блокування процес отримує всі запитані байти без переривання іншими потоками чи сигналами. Якщо `buflen > 256`, ядро розбиває генерацію на чанки, і виклик може повернути меншу кількість байтів (`ret < buflen`), якщо його виконання було перервано сигналом операційної системи.

## Бібліотечна функція `getentropy(3)`

Стандартний інтерфейс (POSIX.1-2024 / OpenBSD / C23 / glibc 2.25+ / musl), спеціально створений для безпечної генерації насіння та ключів у просторі користувача без відкриття файлових дескрипторів.

### Сигнатура інтерфейсу

:::tabs
```c
#include <unistd.h>

int getentropy(void *buffer, size_t length);
```
```cpp
#include <unistd.h>
#include <cstddef>
#include <span>
#include <system_error>

namespace sys {
    [[nodiscard]] std::error_code get_entropy(std::span<std::byte> buffer) noexcept;
}
```
:::

### Специфікація поведінки

1. **Жорстке обмеження розміру:** довжина `length` не може перевищувати `256` байтів за один виклик. Якщо `length > 256`, функція негайно завершується з помилкою `-1` та встановлює `errno = EIO`.
2. **Гарантія безпеки:** функція завжди блокує виконання, якщо CSPRNG ядра ще не ініціалізовано, і гарантує повернення байтів з повною криптографічною ентропією.
3. **Неперервність:** виклик не переривається сигналами операційної системи (`EINTR` обробляється всередині бібліотеки glibc шляхом автоматичного повтору циклу виклику).
4. **Коди повернення:** повертає `0` при успішному заповненні буфера або `-1` у разі помилки (`EFAULT` чи `EIO`).

## Порівняння спеціальних файлів `/dev/random` та `/dev/urandom`

Історична модель двох символьних пристроїв створювала суттєві труднощі для інженерів через різні моделі блокування:

| Критерій | `/dev/random` (до Linux 5.6) | `/dev/random` (Linux 5.6+) | `/dev/urandom` (усі версії) |
| :--- | :--- | :--- | :--- |
| **Поведінка під час старту** | Блокує до збору ентропії | Блокує до `crng_ready` | **Не блокує** (видає небезпечні передбачувані байти на ранньому старті!) |
| **Поведінка під час роботи** | Блокує при нульовому лічильнику | **Не блокує** ніколи | **Не блокує** ніколи |
| **Криптографічний рушій** | Оцінювач ентропії + SHA-1 | ChaCha20 CRNG | ChaCha20 CRNG (після старту) |
| **Потреба файлового дескриптора** | Так (`open`/`read`/`close`) | Так (`open`/`read`/`close`) | Так (`open`/`read`/`close`) |
| **Ризик вичерпання дескрипторів** | Присутній | Присутній | Присутній |

### Семантика опитування через `poll(2)` та `select(2)`

Програми, що очікують на готовність ентропії ядра без блокування основного циклу подій, можуть відкрити файл `/dev/random` з прапорцем `O_RDONLY | O_NONBLOCK` і підписатися на подію готовності читання `POLLIN`. Ядро активує дескриптор для читання лише тоді, коли рівень ініціалізації досяг `crng_ready()`. Для `/dev/urandom` виклик `poll(2)` завжди негайно повертає готовність до читання, незалежно від реального стану ініціалізації ентропії, що робить опитування `/dev/urandom` марним для перевірки безпеки.

## Псевдофайли ядра (`/proc/sys/kernel/random/`)

Ядро Linux надає низку діагностичних вузлів у віртуальній файловій системі `/proc`:

- **`/proc/sys/kernel/random/entropy_avail`:** показує поточну оцінку ентропії в бітах, доступну для підсистеми випадковості. У сучасних ядрах із ChaCha20 після ініціалізації це значення зафіксоване на рівні `256`.
- **`/proc/sys/kernel/random/poolsize`:** розмір основного пулу ентропії ядра в бітах (для сучасних ядер становить `256`).
- **`/proc/sys/kernel/random/boot_id`:** унікальний 128-бітний UUID, що генерується ядром один раз під час завантаження системи і залишається незмінним до перезавантаження.
- **`/proc/sys/kernel/random/urandom_min_reseed_secs`:** інтервал у секундах, після закінчення якого ядро автоматично виконує пересіювання (reseed) головного ChaCha20 CRNG за наявності свіжої ентропії (за замовчуванням `300` секунд).
- **`/proc/sys/kernel/random/write_wakeup_threshold`:** поріг у бітах ентропії, при падінні нижче якого ядро будить фонові процеси, що очікують на запис у `/dev/random`.

## Керування пулом через `ioctl(2)`

Простір користувача (зокрема привілейовані демони на кшталт `rngd` або `haveged`) може взаємодіяти з пулом випадковості за допомогою спеціальних керуючих викликів `ioctl` над відкритим дескриптором `/dev/random`:

- **`RNDGETENTCNT`:** повертає поточну кількість бітів оціненої ентропії у пулі ядра.
- **`RNDADDTOENTCNT`:** додає вказане число до внутрішнього лічильника оціненої ентропії (вимагає привілеїв `CAP_SYS_ADMIN`).
- **`RNDADDENTROPY`:** записує буфер сирих байтів у вхідний накопичувач ядра із зазначенням оціненого вмісту ентропії в бітах.
- **`RNDZAPENTCNT` та `RNDCLEARPOOL`:** скидають лічильник ентропії та очищають вхідні пули ядра.

## Завантаження та збереження стану ентропії (systemd-random-seed)

На вбудованих пристроях та серверах без батарейного годинника реального часу (RTC) системний демон ініціалізації (systemd) використовує спеціальний механізм збереження зерна між перезавантаженнями:

1. **При вимкненні ОС:** служба `systemd-random-seed.service` зчитує 512 випадкових байтів з `/dev/urandom` і зберігає їх у файл на диску `/var/lib/systemd/random-seed`.
2. **При старті ОС:** служба читає збережений файл, передає його вміст у ядро шляхом запису в `/dev/urandom` або через `ioctl(RNDADDENTROPY)` та негайно перезаписує файл новим згенерованим зерном, запобігаючи повторному використанню того самого насіння після аварійного відключення живлення.
3. **Параметри завантаження ядра:** за допомогою параметрів ядра `random.trust_cpu=on` та `random.trust_bootloader=on` адміністратор може дозволити ядру миттєво ініціалізувати стан `crng_ready` за допомогою апаратних інструкцій процесора або зерна, переданого завантажувачем EFI / U-Boot.

## Робота в багатопотокових процесах та клонування (fork)

Критичною небезпекою користувацьких CSPRNG (наприклад, усередині OpenSSL або mbedTLS) є системний виклик `fork(2)`:
- Якщо батьківський процес ініціалізував локальний генератор псевдовипадкових чисел у пам'яті, то після виклику `fork(2)` дочірній процес отримує повну копію адресного простору з ідентичним внутрішнім станом генератора.
- Якщо обидва процеси одночасно згенерують сесійні ключі, ці ключі виявляться ідентичними.
- Щоб запобігти цьому, користувацькі бібліотеки реєструють обробники `pthread_atfork()` або викликають системний виклик `getrandom(2)` на кожну операцію засівання. Системний виклик `getrandom(2)` не має стану в просторі користувача й автоматично захищений від дублювання після форку на рівні ядра Linux.

## Програмні приклади безпечного читання випадковості

:::tabs
```c
#include <sys/random.h>
#include <unistd.h>
#include <errno.h>
#include <stdint.h>
#include <stdbool.h>

/* Безпечне наповнення буфера довільного розміру через getrandom з обробкою сигналів */
bool secure_random_bytes(void *buf, size_t len) {
    uint8_t *ptr = (uint8_t *)buf;
    size_t remaining = len;

    while (remaining > 0) {
        ssize_t ret = getrandom(ptr, remaining, 0);
        if (ret < 0) {
            if (errno == EINTR) {
                continue; /* Перервано сигналом ОС — повторити спробу */
            }
            return false; /* Критична системна помилка */
        }
        ptr += ret;
        remaining -= (size_t)ret;
    }
    return true;
}
```
```cpp
#include <sys/random.h>
#include <cstddef>
#include <cstdint>
#include <span>
#include <array>
#include <expected>
#include <system_error>

namespace crypto {

[[nodiscard]] inline std::expected<void, std::error_code> fill_random(std::span<std::byte> buffer) noexcept {
    std::byte* ptr = buffer.data();
    std::size_t remaining = buffer.size();

    while (remaining > 0) {
        ssize_t ret = ::getrandom(ptr, remaining, 0);
        if (ret < 0) {
            if (errno == EINTR) {
                continue;
            }
            return std::unexpected(std::error_code(errno, std::generic_category()));
        }
        ptr += ret;
        remaining -= static_cast<std::size_t>(ret);
    }
    return {};
}

template <std::size_t N>
[[nodiscard]] inline std::expected<std::array<std::byte, N>, std::error_code> generate_random_bytes() noexcept {
    std::array<std::byte, N> buf{};
    if (auto res = fill_random(std::span<std::byte>(buf)); !res) {
        return std::unexpected(res.error());
    }
    return buf;
}

} // namespace crypto
```
:::
