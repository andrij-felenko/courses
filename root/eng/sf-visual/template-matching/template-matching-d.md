Уяви маніпулятор автоматизованої лінії поверхневого монтажу, який встановлює мікросхему в корпусі BGA на друковану плату. Точність позиціювання контактних майданчиків має бути кращою за 15 мікрометрів, інакше під час паяння виникнуть короткі замикання або обриви. Плата надходить конвеєром з механічним люфтом у 2–3 міліметри та випадковим кутовим перекосом. Щоби компенсувати цей зсув, камера верхнього огляду шукає на кутах плати заздалегідь витравлені реперні мітки (англ. *fiducial markers*) — невеликі мідні кола або хрестики фіксованого розміру `32 × 32` пікселі. Коли мітки знайдено, математика перераховує координати всіх контактів і робот опускає компонент точно в ціль.

Але тут виникає проблема освітлення. Заводський цех освітлюють змінні джерела світла, металева поверхня міді дає дзеркальні відблиски, окиснений метал темніє, а яскравість сусідніх ділянок плати коливається в рази. Якщо порівнювати фрагмент кадру з еталонним зображенням мітки наївним відніманням яскравості, відблиск зсуне оцінку на десятки пікселів, плата буде зіпсована, а лінія зупиниться. Для надійної прив'язки потрібен алгоритм, який знаходить точне положення мітки незалежно від коливань яскравості та контрасту, працює за частки мілісекунди й не вимагає навчання важких нейромереж. Цей підхід називають **зіставленням за шаблоном** (англ. *template matching*).

Зіставлення за шаблоном є фундаментальною опорою комп'ютерного зору: воно не намагається «зрозуміти» сцену, а вимірює математичну подібність між відомим еталонним матричним вікном та кожною можливою позицією на вхідному кадрі.

> 🔧 **Навіщо це.** Шаблон — це найпростіший і найнадійніший орієнтир для систем реального часу. Позиціювання друкованих плат на лініях SMD-монтажу, оптичне супроводження цілі в головках самонаведення, вирівнювання знімків у медичних томографах, детекція дефектів на кремнієвих пластинах та візуальна одометрія роботів спираються на кореляційні мітки. Там, де нейромережі дають непередбачувану похибку або вимагають потужних графічних прискорювачів, зіставлення з шаблоном забезпечує детерміновану субпіксельну точність на скромному мікроконтролері.

## Чотири міри схожості: від різниці до кореляції

Нехай вхідне монохромне зображення `I` має розмір `W × H` пікселів, а еталонний шаблон `T` — розмір `M × N` пікселів, де `M ≪ W` та `N ≪ H`. Ми шукаємо координати `(x, y)` на зображенні `I`, де вміст фрагмента розміром `M × N` найкраще збігається з шаблоном `T`.

Щоб порівняти дві матриці чисел, їх зіставляють попіксельно за допомогою певної метрики схожості або дистанції. Історично виникло чотири основні підходи, кожен з яких має власну обчислювальну ціну та стійкість до завад.

```
       Шаблон T (M × N)
        ┌──────┐
        │  *   │
        └──────┘
           │
           ▼ ковзає по кадру
┌──────────────────────────────┐
│                              │
│       ┌──────┐               │
│       │ I(x,y)│               │ Зображення I (W × H)
│       └──────┘               │
│                              │
└──────────────────────────────┘
```

### 1. Сума абсолютних різниць (SAD)

Найпростіший спосіб оцінити розбіжність між двома вікнами — порахувати модулі різниць яскравостей для кожного пікселя та скласти їх разом (метрика `L₁`):

```
SAD(x, y) = ∑ [ | I(x + u, y + v) − T(u, v) | ]
```

де сума береться по всіх пікселях шаблону: `u ∈ [0, M−1]`, `v ∈ [0, N−1]`.

Найкращий збіг відповідає точці глобального мінімуму `SAD(x, y)`. Якщо зображення ідентичне шаблону, `SAD = 0`. Головна перевага SAD — швидкість: операція вимагає лише віднімання, взяття модуля та додавання. Процесори архітектури x86 містять апаратну інструкцію `PSADBW`, яка обчислює суму абсолютних різниць для восьми або шістнадцяти байтів за один такт. SAD також стійка до поодиноких викидів (англ. *salt-and-pepper noise*), оскільки похибка одиничного пікселя росте лінійно, а не квадратично.

Проте SAD катастрофічно чутлива до змін освітлення. Якщо весь кадр стане світлішим лише на 10 одиниць яскравості (`I'(u, v) = I(u, v) + 10`), значення SAD зросте на `10 · M · N`, і мінімум зміститься в довільну темнішу область сцени.

### 2. Сума квадратичних різниць (SSD)

Сума квадратичних різниць (англ. *Sum of Squared Differences*, SSD) відповідає квадрату евклідової відстані `L₂²` між двома багатовимірними векторами пікселів:

```
SSD(x, y) = ∑ [ ( I(x + u, y + v) − T(u, v) )² ]
```

Квадрат різниці сильніше штрафує великі локальні відхилення, що робить функцію відгуку навколо точки точного збігу більш гострою та виразною, ніж у SAD. Розкриємо дужки під знаком суми:

```
SSD(x, y) = ∑ I(x+u, y+v)² − 2 · ∑ [ I(x+u, y+v) · T(u, v) ] + ∑ T(u, v)²
```

Погляньмо на три складові отриманого виразу:
1. `∑ T(u, v)²` — енергія шаблону. Оскільки шаблон фіксований, це число є константою `C_T` і не залежить від координат `(x, y)`.
2. `∑ [ I(x+u, y+v) · T(u, v) ]` — пряма крос-кореляція між зображенням та шаблоном. Вона входить зі знаком «мінус», отже, мінімізація SSD вимагає максимізації цього перехресного добутку.
3. `∑ I(x+u, y+v)²` — локальна енергія фрагмента зображення під вікном шаблону. Ця величина постійно змінюється під час руху вікна по кадру.

### 3. Сира крос-кореляція (Cross-Correlation, CC)

Якщо знехтувати зміною локальної енергії зображення `∑ I²` та вважати її приблизно сталою, мінімізація SSD спрощується до максимізації прямого попіксельного добутку:

```
R_CC(x, y) = ∑ [ I(x + u, y + v) · T(u, v) ]
```

Саме цей вираз являє собою класичну дискретну згортку зображення з перевернутим шаблоном `T(−u, −v)`. Здавалося б, обчислювати лише добуток вигідно — його можна миттєво порахувати через швидке перетворення Фур'є.

Але тут криється небезпечна пастка, яку в комп'ютерному зорі називають **енергетичним зміщенням**. Сира крос-кореляція реагує не на подібність структури, а на абсолютну величину добутку чисел. Якщо на кадрі є велика біла пляма (відблиск світла, біла стіна або металевий корпус), пікселі `I` там мають максимальні значення (наприклад, 255). Множення будь-якого шаблону на ці великі числа дасть величезне значення `R_CC`, яке значно перевищить кореляцію на справжній цілі, якщо ціль затінена або має менший контраст. Сира кореляція завжди тягнеться до найяскравіших зон сцени.

![Порівняння відгуку метрик схожості](/root/eng/sf-visual/template-matching/img/metric-comparison.svg)
*Порівняння відгуку сирої крос-кореляції та нормалізованої кореляції ZNCC на зображенні з відблиском. Сира кореляція максимізується на яскравій плямі через високу локальну енергію пікселів, тоді як ZNCC завдяки центруванню та нормуванню дає чіткий глобальний пік строго на фізичному маркері.*

### 4. Нормалізована крос-кореляція з нульовим середнім (ZNCC)

Щоб усунути вплив змінної яскравості та зробити метрику стійкою до відблисків, значення фрагмента та шаблону піддають двом операціям:
1. **Центрування:** від кожного пікселя віднімають його локальне середнє значення (`I − Ī` та `T − T̄`). Це прибирає будь-яке фонове засвічення.
2. **Нормування:** центрований сигнал ділять на його корінь з енергії (стандартне відхилення `σ`). Це приводить вектор будь-якого контрасту до одиничної довжини.

Формула коефіцієнта нормалізованої крос-кореляції (ZNCC, або коефіцієнта кореляції Пірсона для двовимірних матриць) має вигляд:

```
R_ZNCC(x, y) = ∑ [ (I(x+u, y+v) − Ī_{x,y}) · (T(u, v) − T̄) ] / Знаменник(x, y)

де Знаменник(x, y) = √[ ∑ (I(x+u, y+v) − Ī_{x,y})² · ∑ (T(u, v) − T̄)² ]
```

Локальне середнє фрагмента під вікном `(x, y)` обчислюється як:

```
Ī_{x,y} = (1 / (M · N)) · ∑ I(x + u, y + v)
```

Значення `R_ZNCC` строго обмежене діапазоном `[−1.0, +1.0]`:
- `+1.0` — ідеальний пропорційний збіг форми шаблону та фрагмента;
- `0.0` — відсутність лінійної кореляції (шум, некорельовані структури);
- `−1.0` — ідеальний негативний збіг (інвертовані кольори: біле стало чорним, чорне — білим).

Детальний історичний огляд того, як розвивалися ці міри від оптичних голограм до алгоритмів реального часу, наведено у вставці про [історію розвитку кореляційних методів від оптичних фільтрів до алгоритму Льюїса](root:sf-visual/template-matching/hist-template-matching.md).

## Інваріантність ZNCC: чому сонце та тіні не збивають приціл

Головна математична цінність ZNCC полягає в її абсолютній інваріантності до лінійних (афінних) змін освітлення. Припустимо, що внаслідок зміни експозиції чи ввімкнення прожектора яскравість кожного пікселя сцени змінилася за правилом:

```
I'(u, v) = α · I(u, v) + β
```

де `α > 0` — коефіцієнт контрасту, а `β ∈ ℝ` — загальне адитивне зміщення яскравості.

Подивимося, як поводяться чисельник і знаменник ZNCC під дією цих перетворень:
1. **Знищення зміщення `β`:** середнє значення нового фрагмента дорівнює `Ī' = α · Ī + β`. Коли ми віднімаємо середнє від пікселя, отримуємо `I'(u, v) − Ī' = (α·I + β) − (α·Ī + β) = α · (I(u, v) − Ī)`. Адитивна константа `β` взаємно скорочується і зникає з виразу.
2. **Знищення масштабу `α`:** у чисельнику з'являється множник `α`: `∑ [ α · (I − Ī) · (T − T̄) ] = α · ∑ [ (I − Ī) · (T − T̄) ]`. У знаменнику дисперсія масштабується як `√[ ∑ (α · (I − Ī))² ] = √(α²) · √[ ∑ (I − Ī)² ] = α · σ_I`.
3. Множник `α` у чисельнику та знаменнику скорочується: `R(I', T) = (α / α) · R(I, T) = R(I, T)`.

![Геометрична сутність ZNCC у багатовимірному просторі](/root/eng/sf-visual/template-matching/img/ncc-vector-geometry.svg)
*Геометрична інтерпретація ZNCC у просторі розмірності D = M·N. Центрування проектує вектори фрагмента й шаблону на гіперплощину нульового середнього (знищуючи адитивне засвічення β), а нормування проектує їх на одиничну сферу (знищуючи мультиплікативний контраст α). Скалярний добуток нормованих векторів дорівнює косинусу кута θ між ними.*

Геометрично фрагмент розміром `M × N` є точкою у багатовимірному просторі `ℝᴷ` (де `K = M · N`). Центрування проектує цей вектор на гіперплощину нульового середнього `∑ xᵢ = 0`. Ділення на стандартне відхилення проектує його на одиничну гіперсферу. Значення ZNCC — це просто косинус кута `θ` між двома одиничними векторами на цій сфері:

```
R_ZNCC = cos(θ) = ⟨ u_I, u_T ⟩
```

Строге алгебраїчне виведення цієї рівності, доведення обмеженості коефіцієнта через нерівність Коші–Буняковського–Шварца, матричний оператор центрування та зв'язок із нормалізованою евклідовою відстанню наведено у [строгому математичному виведенні інваріантності ZNCC](root:sf-visual/template-matching/math-ncc-invariance.md).

## Інтегральні карти (SAT): дисперсія за вісім звернень

Незважаючи на ідеальну стійкість ZNCC, наївне обчислення формули в лоб є вкрай повільним. Для кадру `1920 × 1080` і шаблону `64 × 64` знаменник вимагає переобчислення суми `∑ I` та суми квадратів `∑ I²` у двох мільйонах вікон. Якщо рахувати ці суми звичайними циклами, процесор виконуватиме понад 8 мільярдів операцій читання з пам'яті на кадр.

Прорив у швидкодії досягається завдяки **інтегральним зображенням** (англ. *Summed Area Tables*, SAT), запропонованим Френком Кроу 1984 року.

Ми створюємо дві допоміжні матриці того самого розміру, що й кадр:
1. Таблиця сум першого порядку `S(x, y) = ∑_{i≤x, j≤y} I(i, j)`.
2. Таблиця сум другого порядку `S₂(x, y) = ∑_{i≤x, j≤y} I(i, j)²`.

Обидві таблиці будуються одночасно за один-єдиний послідовний прохід по вхідному кадру:

```
S(x, y)  = I(x, y) + S(x−1, y) + S(x, y−1) − S(x−1, y−1)
S₂(x, y) = I(x, y)² + S₂(x−1, y) + S₂(x, y−1) − S₂(x−1, y−1)
```

![Інтегральні зображення для обчислення локальної статистики](/root/eng/sf-visual/template-matching/img/integral-images-fast-ncc.svg)
*Швидке обчислення локального середнього та дисперсії через інтегральні карти накопичених сум S та S₂. Сума значень у довільному вікні довільного розміру обчислюється рівно за 4 звернення до кутових елементів таблиці.*

Коли таблиці побудовано, сума яскравостей у будь-якому прямокутному вікні з верхнім лівим кутом `(x, y)` та розміром `(w, h)` знаходиться за формулою чотирьох вершин:

```
Sum(x, y, w, h) = S(x+w−1, y+h−1) − S(x−1, y+h−1) − S(x+w−1, y−1) + S(x−1, y−1)
```

Аналогічно за 4 звернення до `S₂` обчислюється сума квадратів `SqSum`. Тоді локальна дисперсія вікна (енергія центрованого фрагмента) знаходиться миттєво:

```
Var_I = SqSum − ( (Sum)² / (w · h) )
```

Складність обчислення знаменника ZNCC стає рівною `O(1)` — вона не залежить від розміру шаблону. Чи шаблон має розмір `16 × 16`, чи `256 × 256`, обчислення локальної енергії завжди потребує рівно 8 звернень до пам'яті.

## Частотний домен: теорема про кореляцію та фазове зіставляння

Інтегральні карти прискорюють знаменник, але в чисельнику залишається скалярний добуток `∑ I(u,v) · T(u,v)`. Для великих шаблонів (наприклад, `128 × 128` або `256 × 256`) пряме обчислення чисельника займає 95% часу.

Тут на допомогу приходить гармонічний аналіз. Згідно з **теоремою про згортку**, просторова кореляція двох сигналів еквівалентна поелементному множенню їхніх спектрів Фур'є з комплексним спряженням:

```
I ⋆ T = ℱ⁻¹ { ℱ{I} · (ℱ{T})* }
```

де `ℱ` — пряме двовимірне дискретне перетворення Фур'є (2D FFT), `ℱ⁻¹` — зворотне перетворення (2D IFFT), а зірочка `*` позначає комплексне спряження (`(a + j·b)* = a − j·b`).

Обчислювальна складність просторового множення становить `O(W · H · M · N)`. Складність через 2D FFT дорівнює `O(W · H · log(W · H))` і взагалі не залежить від розміру шаблону. Точка перетину ефективності (англ. *crossover point*) зазвичай лежить в районі `M, N ≈ 32`: для менших шаблонів просторовий цикл швидший через локальність кешу, а для більших шаблонів частотний метод дає багаторазову перевагу.

### Фазова кореляція (Phase Correlation)

Якщо ми шукаємо лише відносний зсув `(Δx, Δy)` між двома кадрами однакового розміру (наприклад, для стабілізації відео чи зшивання панорам), частотний метод дає ще більш елегантне рішення — **фазову кореляцію**.

Нехай `I₂(x, y) = I₁(x − Δx, y − Δy)`. За теоремою про зсув Фур'є:

```
F₂(u, v) = F₁(u, v) · e^{ −j 2π ( (u·Δx / W) + (v·Δy / H) ) }
```

Амплітудні спектри обох зображень однакові (`|F₂| = |F₁|`), а вся інформація про рух зосереджена виключно у фазовому зсуві. Обчислимо нормалізований крос-спектр потужності:

```
R(u, v) = ( F₁(u, v)* · F₂(u, v) ) / | F₁(u, v)* · F₂(u, v) |
        = e^{ −j 2π ( (u·Δx / W) + (v·Δy / H) ) }
```

![Конвеєр фазової кореляції через 2D FFT](/root/eng/sf-visual/template-matching/img/fft-phase-correlation-pipeline.svg)
*Фазова кореляція у частотному домені. Зображення та шаблон переводяться у спектри через 2D FFT, крос-спектр нормалізується за модулем амплітуди, а зворотне перетворення Фур'є дає гострий дельта-імпульс Дірака строго в точці просторового зміщення.*

Здійснюючи зворотне перетворення Фур'є `ℱ⁻¹{ R(u, v) }`, ми отримуємо дискретну дельта-функцію Дірака:

```
r(x, y) = δ(x − Δx, y − Δy)
```

На матриці просторового відгуку виникає ідеально гострий одиночний пік висотою `1.0` рівно в координатах `(Δx, Δy)`, тоді як у всіх інших точках значення близькі до нуля. Фазова кореляція практично нечутлива до рівномірного шуму та монотонних змін освітлення, оскільки амплітудна нормалізація зрівнює внесок усіх просторових частот.

## Багаторівневий пірамідальний пошук: Coarse-to-Fine

Найефективніший інженерний спосіб прискорення просторового зіставлення на вбудованих системах — використання пірамід зображень (англ. *Image Pyramids*).

Замість того, щоб сканувати кожен піксель full-HD кадру, ми створюємо ієрархію зменшених копій кадру та шаблону (піраміду Гауса):
- **Рівень L2 (грубий, 1/4 масштабу):** розмір кадру `240 × 135`, шаблон `16 × 16`. Кількість пікселів зменшена у 16 разів. Повний перебір по всьому полю L2 виконується за лічені мікросекунди і знаходить приблизну точку максимуму `(x₂, y₂)`.
- **Рівень L1 (проміжний, 1/2 масштабу):** знайдена точка проектується на рівень L1: `(x₁₀, y₁₀) = (2·x₂, 2·y₂)`. Пошук ведеться не по всьому кадру, а лише у вузькому вікні радіусом `±δ` пікселів (типово `δ = 3..4`) навколо прогнозованої точки. Замість десятків тисяч точок ми перевіряємо лише `(2δ + 1)² = 49..81` позицію.
- **Рівень L0 (оригінальний кадр, 1/1):** точка з рівня L1 проектується на повний кадр `(x₀₀, y₀₀) = (2·x₁, 2·y₁)` і фінально уточнюється у вікні `±δ`.

![Багаторівневий пірамідальний пошук Coarse-to-Fine](/root/eng/sf-visual/template-matching/img/pyramid-coarse-to-fine.svg)
*Пірамідальний пошук: на грубому рівні L2 виконується швидкий повний перебір усього кадру, після чого на рівнях L1 та L0 пошук звужується до локального вікна в радіусі ±δ пікселів навколо знайденого піку, скорочуючи кількість перевірок у сотні разів.*

Пірамідальний підхід дає прискорення у 50–300 разів порівняно з повним перебором. Єдине обмеження піраміди — шаблон не повинен бути надто дрібним (меншим за 8–10 пікселів на верхньому рівні), інакше при зменшенні масштабу його високі частоти згладяться і пік кореляції розмиється.

## Субпіксельна локалізація: вихід за межі піксельної сітки

Після знаходження дискретного максимуму `(x*, y*)` реальний центр об'єкта у неперервному фізичному просторі лежить десь поруч — між пікселями. Для багатьох завдань (наведення верстатів, вимірювання деформацій, оптична стабілізація) потрібна точність у 0.05–0.1 пікселя.

Оскільки функція кореляції `R(x, y)` біля максимуму є гладкою куполоподібною поверхнею, її локальний окіл `3 × 3` можна апроксимувати параболою:

```
R(x) ≈ a · (x − x*)² + b · (x − x*) + c
```

Взявши похідну та прирівнявши її до нуля, знаходимо субпіксельне зміщення вершини параболи за трьома дискретними відліками `R_{-1} = R(x*−1, y*)`, `R_0 = R(x*, y*)` та `R_{+1} = R(x*+1, y*)`:

```
δx = ( R_{+1} − R_{-1} ) / [ 2 · ( 2·R_0 − R_{-1} − R_{+1} ) ]
```

Аналогічно за вертикальними сусідами `R(x*, y*−1)` та `R(x*, y*+1)` обчислюється зміщення `δy`. Фінальні координати цілі `(x* + δx, y* + δy)` мають точність до сотих часток пікселя без збільшення роздільної здатності камери.

## Поведінка при геометричних деформаціях і вибір порогу

Класичне зіставлення за шаблоном передбачає чистий просторовий зсув (трансляцію `Δx, Δy`). Якщо об'єкт у сцені зазнає обертання або зміни масштабу, кореляційний відгук починає деградувати:

1. **Обертання (Rotation):** при куті повороту понад `±3°..5°` значення `R_ZNCC` різко падає нижче `0.5`, оскільки пікселі шаблону більше не накладаються на відповідні структури. Для розв'язання цієї проблеми в промислових сканерах генерують банк повернених шаблонів `T_θ` з кроком 1°–2° або переходять до інваріантних дескрипторів ключових точок.
2. **Масштаб (Scale):** зміна відстані до камери на `±5%` розмиває пік кореляції. У пірамідальних схемах це компенсують створенням масштабованих версій шаблону (піраміда шаблону).
3. **Вибір порогу прийняття рішення (Thresholding):**
   - `R > 0.85`: впевнений точний збіг (висока контрастність, відсутність геометричних перекосів);
   - `0.70 ≤ R ≤ 0.85`: прийнятний збіг з можливим частковим затіненням або легким шумом;
   - `R < 0.70`: відхилення кандидата (хибне спрацьовування або невідповідний об'єкт).

## Порівняння підходів та вибір інструменту

Обираючи метод зіставлення для конкретного проекту, інженер зважає на компроміс між швидкістю, пам'яттю та інваріантністю:

| Метод | Складність на точку | Стійкість до освітлення `α·I + β` | Субпіксельна точність | Основне застосування |
|---|---|---|---|---|
| **SAD** | `O(M · N)` (інструкції `PSADBW`) | Низька (зсув `β` руйнує збіг) | Потребує інтерполяції | Стереозрение, кодування відео (H.264/HEVC) |
| **SSD** | `O(M · N)` | Низька | Параболічний фіт | Трекінг точок за Лукасом–Канаде |
| **ZNCC (прямий)** | `O(M · N)` | Ідеальна | Параболічний фіт | Локальне зіставлення невеликих патчів |
| **ZNCC + SAT** | `O(M · N)` чисельник, `O(1)` знаменник | Ідеальна | Параболічний фіт | Пошук маркерів на платах, промисловий контроль |
| **Піраміда ZNCC** | `O(1)` в середньому | Ідеальна | Багаторівневий параболічний фіт | Швидкісний пошук міток у реальному часі |
| **Phase Correlation** | `O(W H log(W H))` | Висока (до монотонних змін) | Інтерполяція спектра | Стабілізація відео, зшивання панорам, одометрія |

Повний працюючий код усіх описаних компонентів — від обчислення інтегральних карт та швидкого ZNCC до пірамідального спуску та субпіксельного параболічного фіта — наведено у практичній вставці з [повною реалізацією конвеєра на C та C++ з пірамідою й оптимізаціями](root:sf-visual/template-matching/proj-template-matching.md).

## Зіставлення шаблону в реальному коді

Нижче наведено мінімальний приклад використання ZNCC-зіставлення на практиці:

**Обчислення коефіцієнта ZNCC для одного вікна.**
:::tabs
```c
#include <stdint.h>
#include <math.h>

// Обчислення ZNCC для одного фрагмента зображення
float compute_zncc_window(const uint8_t *img, int img_stride,
                          const uint8_t *tpl, int tpl_stride,
                          int w, int h) {
    double sum_i = 0.0, sum_t = 0.0;
    const double area = (double)(w * h);

    for (int y = 0; y < h; ++y) {
        const uint8_t *i_ptr = img + y * img_stride;
        const uint8_t *t_ptr = tpl + y * tpl_stride;
        for (int x = 0; x < w; ++x) {
            sum_i += (double)i_ptr[x];
            sum_t += (double)t_ptr[x];
        }
    }

    const double mean_i = sum_i / area;
    const double mean_t = sum_t / area;

    double num = 0.0;
    double var_i = 0.0;
    double var_t = 0.0;

    for (int y = 0; y < h; ++y) {
        const uint8_t *i_ptr = img + y * img_stride;
        const uint8_t *t_ptr = tpl + y * tpl_stride;
        for (int x = 0; x < w; ++x) {
            const double di = (double)i_ptr[x] - mean_i;
            const double dt = (double)t_ptr[x] - mean_t;
            num += di * dt;
            var_i += di * di;
            var_t += dt * dt;
        }
    }

    const double denom = sqrt(var_i * var_t);
    if (denom < 1e-7) return 0.0f; // Однорідне поле
    return (float)(num / denom);
}
```

#include <vector>
#include <span>
#include <cstdint>
#include <cmath>
#include <numeric>

// Обчислення ZNCC для одного фрагмента зображення
[[nodiscard]] float compute_zncc_window(std::span<const uint8_t> img, int img_stride,
                                        std::span<const uint8_t> tpl, int tpl_stride,
                                        int w, int h) noexcept {
    double sum_i = 0.0;
    double sum_t = 0.0;
    const double area = static_cast<double>(w * h);

    for (int y = 0; y < h; ++y) {
        const uint8_t *i_ptr = img.data() + y * img_stride;
        const uint8_t *t_ptr = tpl.data() + y * tpl_stride;
        for (int x = 0; x < w; ++x) {
            sum_i += static_cast<double>(i_ptr[x]);
            sum_t += static_cast<double>(t_ptr[x]);
        }
    }

    const double mean_i = sum_i / area;
    const double mean_t = sum_t / area;

    double num = 0.0;
    double var_i = 0.0;
    double var_t = 0.0;

    for (int y = 0; y < h; ++y) {
        const uint8_t *i_ptr = img.data() + y * img_stride;
        const uint8_t *t_ptr = tpl.data() + y * tpl_stride;
        for (int x = 0; x < w; ++x) {
            const double di = static_cast<double>(i_ptr[x]) - mean_i;
            const double dt = static_cast<double>(t_ptr[x]) - mean_t;
            num += di * dt;
            var_i += di * di;
            var_t += dt * dt;
        }
    }

    const double denom = std::sqrt(var_i * var_t);
    if (denom < 1e-7) return 0.0f; // Однорідне поле
    return static_cast<float>(num / denom);
}
