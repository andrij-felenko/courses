# 🧮 Математичні основи планування: векторний Bin Packing та евристики ранжування

Задача розміщення завдань на кластері серверів є класичною задачею комбінаторної оптимізації. У термінах теорії алгоритмів вона формулюється як **багатовимірна векторна задача пакування в контейнери (англ. *d-dimensional Vector Bin Packing Problem*, `d-VBP`)**: необхідно розмістити множину об'єктів із багатовимірними векторами вимог у мінімальну кількість контейнерів фіксованої місткості без перевищення лімітів за жодним із вимірів.

Оскільки у виробничому кластері поди надходять динамічно в режимі реального часу, планувальник розв'язує **онлайн-варіант** цієї задачі, використовуючи евристичні вагові функції для багатокритеріального ранжування вузлів.

## 1. Формалізація задачі кластерного планування

Нехай кластер складається з `M` гетерогенних вузлів `N = { N₁, N₂, ..., N_M }`.

Кожен вузол `Nⱼ` характеризується вектором доступних (алокованих) ресурсів у `D` вимірах (CPU, RAM, GPU, дисковий простір, дескриптори відкритих файлів):
```
Cⱼ = ( c_{j,1}, c_{j,2}, ..., c_{j,D} ) ∈ ℝ₊ᴰ
```

На кожному вузлі `Nⱼ` вже виконується множина подів `𝒫(Nⱼ)`. Сумарне споживання ресурсів вузла визначається як векторний підсумок вимог усіх розміщених на ньому подів:
```
Uⱼ = ∑ [ rₚ ]  де  p ∈ 𝒫(Nⱼ),  rₚ = ( r_{p,1}, r_{p,2}, ..., r_{p,D} )
```

Коли в чергу планування надходить новий под `P` із вектором вимог `r = ( r₁, r₂, ..., r_D )`, планувальник повинен знайти оптимальний вузол `j* ∈ {1, ..., M}`, що задовольняє два критерії:

1. **Умова допустимості (Feasibility Invariant):**
```
Uⱼ + r ≤ Cⱼ  [покомпонентно для всіх вимірів k ∈ {1, ..., D}]
( u_{j,k} + rₖ ) ≤ c_{j,k}  ∀ k ∈ {1, ..., D}
```
Якщо для вузла `Nⱼ` хоча б за одним ресурсом `k` сума перевищує місткість `c_{j,k}`, вузол відсікається на фазі фільтрації (Predicates / Filtering).

2. **Критерій оптимізації:**
Обрати вузол `j*`, який максимізує зважену цільову функцію корисності (Score):
```
j* = arg max [ Score(Nⱼ, P) ]  серед усіх допустимих вузлів
```

## 2. Теоретична складність та NP-повнота

Класична одновимірна задача пакування в контейнери (`1-VBP`) належить до класу NP-важких задач у сильному сенсі (NP-hard in the strong sense). Це доводиться зведенням до задачі розбиття множини чисел на підмножини однакової суми (Partition Problem).

Для `D ≥ 2` вимірів задача векторного пакування стає значно важчою:
- **Теорема про апроксимацію (Garey, Graham, Johnson, 1976):** Для довільного `D ≥ 2` не існує поліноміального алгоритму з коефіцієнтом апроксимації, меншим ніж `D`, якщо `P ≠ NP`.
- **Онлайн-обмеження:** В онлайн-постановці (коли майбутні запити невідомі наперед) будь-який детермінований алгоритм має нижню межу конкурентного відношення (competitive ratio) не менше `D + 1 - ε`.

Через неможливість точного обчислення глобального оптимуму за поліноміальний час (латентність шедулера має складати 2–20 мс на под), оркестратори використовують поліноміальні жадібні евристики (Greedy Online Heuristics) часової складності `O(M · D)`.

## 3. Дві фундаментальні філософії розміщення

Під час розробки евристичних функцій інженери стикаються з вибором між двома взаємовиключними стратегіями:

1. **Консолідація та ущільнення (Bin-Packing / MostAllocated):**
   Планувальник намагається заповнити окремі сервери «під зав'язку» (до 90–95% утилізації), залишаючи решту машин у кластері повністю порожніми.
   - *Переваги:* Економічна ефективність у хмарі (порожні вузли можна вимкнути через [автоскейл](topic:sf-release/autoscaling), заощаджуючи бюджет компанії).
   - *Недоліки:* Високий ризик деградації продуктивності («галасливі сусіди» / Noisy Neighbors) та каскадний збій сотень процесів при апаратному виході з ладу одного перевантаженого сервера.

2. **Рівномірне розсіювання (Spread / LeastAllocated):**
   Планувальник спрямовує кожен новий под на той сервер, де прямо зараз зафіксовано найменше навантаження.
   - *Переваги:* Мінімізація радіуса ураження (Blast Radius Reduction), рівномірне розсіювання тепла по серверних стійках та великий запас потужності на випадок різких стрибків трафіку.
   - *Недоліки:* Розпорошення ресурсів, що унеможливлює вимкнення серверів для економії енергії.

## 4. Математика вагового оцінювання (Scoring Functions)

Після відсікання недопустимих вузлів шедулер ранжує решту кандидатів за допомогою лінійної комбінації нормалізованих плагінів пріоритетів:

```
Score(N, P) = ∑ [ wᵢ · Priorityᵢ(N, P) ] ÷ ∑ [ wᵢ ]
```
де:
- `Priorityᵢ(N, P) ∈ [0, 100]` — бал конкретного плагіна оцінювання для вузла `N` та пода `P`;
- `wᵢ ∈ ℝ₊` — вага відповідного плагіна в конфігурації планувальника.

Розглянемо виведення та математичну логіку двох фундаментальних плагінів: `LeastAllocatedPriority` та `BalancedResourceAllocation`.

---

### Плагін 1: Рівномірний розподіл (LeastAllocatedPriority)

Мета плагіна — спрямовувати навантаження на найменш завантажені сервери для мінімізації радіуса ураження при апаратних збоях та запобігання тепловим перевантаженням окремих стійок.

Нехай для вузла `N` після теоретичного розміщення пода `P`:
- `C_cpu`, `C_mem` — сумарна місткість CPU та оперативної пам'яті вузла;
- `U_cpu`, `U_mem` — сумарне споживання CPU та пам'яті з урахуванням нового пода (`U = U_current + r_P`).

Формула розрахунку бала за шкалою від 0 до 100:

```
Score_least(N) = 100 · [ (1 - U_cpu / C_cpu) + (1 - U_mem / C_mem) ] ÷ 2
```

**Кроковий розрахунок:**
```
Score_least(N)
= 50 · [ (C_cpu - U_cpu) / C_cpu + (C_mem - U_mem) / C_mem ]   [розподільчий закон]
= 50 · [ Free_cpu_fraction + Free_mem_fraction ]             [визначення вільних часток]
```

Якщо вузол повністю вільний (`U = 0`), бал дорівнює `100 · (1 + 1) / 2 = 100`.
Якщо вузол заповнений під 100% (`U = C`), бал дорівнює `100 · (0 + 0) / 2 = 0`.

---

### Плагін 2: Мінімізація фрагментації (BalancedResourceAllocation)

Головна проблема незалежного виділення ресурсів полягає в утворенні **заблокованої місткості (Stranded Capacity)**: якщо вузол вичерпав 100% CPU, але використав лише 20% пам'яті, залишок у 80% RAM стає непридатним для використання іншими стандартними подами й простоює даремно.

Плагін збалансованого розподілу максимізує схожість пропорцій споживання ресурсів, мінімізуючи дисперсію завантаження між різними вимірами.

Нехай частки виділених ресурсів вузла складають:
```
f_cpu = U_cpu / C_cpu ∈ [0, 1]
f_mem = U_mem / C_mem ∈ [0, 1]
```

Середнє завантаження вузла:
```
μ = ( f_cpu + f_mem ) ÷ 2
```

Дисперсія виділення ресурсів у 2D просторі:
```
σ² = [ (f_cpu - μ)² + (f_mem - μ)² ] ÷ 2
```

Підставимо `μ` у формулу дисперсії:
```
(f_cpu - μ) = f_cpu - (f_cpu + f_mem) / 2 = (f_cpu - f_mem) / 2
(f_mem - μ) = f_mem - (f_cpu + f_mem) / 2 = -(f_cpu - f_mem) / 2

σ² = [ ((f_cpu - f_mem)/2)² + (-(f_cpu - f_mem)/2)² ] ÷ 2
   = [ 2 · (f_cpu - f_mem)² / 4 ] ÷ 2
   = (f_cpu - f_mem)² ÷ 4
```

Стандартне відхилення дорівнює:
```
σ = | f_cpu - f_mem | ÷ 2
```

Оркестратор перетворює різницю часток у нормалізований бал від 0 до 100 за формулою:
```
Score_balanced(N) = 100 · [ 1 - | f_cpu - f_mem | ]
```

Якщо споживання CPU та пам'яті ідеально збігається у відсотковому відношенні (наприклад, 60% CPU і 60% RAM), різниця `|0.6 - 0.6| = 0`, і вузол отримує максимальну оцінку 100 балів.

## 5. Числовий приклад розрахунку та порівняння вузлів

Нехай планується под `P` із вимогами: `r = (CPU: 2 ядра, RAM: 4 ГБ)`.

Розглядаються два кандидати з однаковою місткістю `C = (CPU: 16 ядер, RAM: 32 ГБ)`:
- **Вузол A:** поточне навантаження `(CPU: 10 ядер, RAM: 20 ГБ)`.
- **Вузол B:** поточне навантаження `(CPU: 14 ядер, RAM: 4 ГБ)`.

### Розрахунок для Вузла A (Співмірне завантаження):
1. Сумарне навантаження після розміщення:
   - CPU: `10 + 2 = 12` ядер → `f_cpu = 12 / 16 = 0.75` (75%)
   - RAM: `20 + 4 = 24` ГБ → `f_mem = 24 / 32 = 0.75` (75%)
2. Розрахунок балів:
```
Score_least(A)    = 100 · [ (1 - 0.75) + (1 - 0.75) ] ÷ 2 = 100 · 0.25 = 25.0
Score_balanced(A) = 100 · [ 1 - | 0.75 - 0.75 | ] = 100 · 1.0 = 100.0
```

### Розрахунок для Вузла B (Перекошене завантаження):
1. Сумарне навантаження після розміщення:
   - CPU: `14 + 2 = 16` ядер → `f_cpu = 16 / 16 = 1.00` (100%)
   - RAM: `4 + 4 = 8` ГБ → `f_mem = 8 / 32 = 0.25` (25%)
2. Розрахунок балів:
```
Score_least(B)    = 100 · [ (1 - 1.00) + (1 - 0.25) ] ÷ 2 = 100 · 0.375 = 37.5
Score_balanced(B) = 100 · [ 1 - | 1.00 - 0.25 | ] = 100 · (1 - 0.75) = 25.0
```

### Підсумкове рішення:
Якщо планувальник має рівні вагові коефіцієнти `w_least = 1.0` та `w_balanced = 2.0`:
```
Weighted_Score(A) = ( 1.0 · 25.0 + 2.0 · 100.0 ) ÷ 3.0 = 225.0 ÷ 3.0 = 75.0
Weighted_Score(B) = ( 1.0 · 37.5 + 2.0 · 25.0 ) ÷ 3.0  = 87.5 ÷ 3.0  = 29.17
```
Вузол A перемагає з великим відривом (`75.0 > 29.17`), оскільки розміщення на вузлі B призвело б до повної втрати 24 ГБ оперативної пам'яті (заблокована місткість при нульовому залишку CPU).

## 6. Геометрична інтерпретація в багатовимірному просторі

У загальному випадку для `D` вимірів ресурсів вектор використання нормалізується до одиничного гіперкуба `[0, 1]^D`:
```
v⃗ = ( f₁, f₂, ..., f_D )  де  fₖ = Uₖ / Cₖ
```

Ідеальний стан вузла відповідає діагоналі гіперкуба `v⃗_ideal = (α, α, ..., α)`, де всі ресурси споживаються рівномірно.

Відхилення від ідеалу розраховується як евклідова відстань у нормалізованому просторі до головної діагоналі або як косинусна подібність (Cosine Similarity) між вектором запиту пода `r⃗` та вектором вільного залишку вузла `(C⃗ - U⃗)`:

```
cos(θ) = ( r⃗ · (C⃗ - U⃗) ) ÷ ( ‖r⃗‖ · ‖C⃗ - U⃗‖ )
```

Коли кут `θ → 0` (`cos(θ) → 1`), форма запиту пода ідеально повторює форму залишку ресурсів на сервері, мінімізуючи утворення геометричних пустот у кластерному пулі.
