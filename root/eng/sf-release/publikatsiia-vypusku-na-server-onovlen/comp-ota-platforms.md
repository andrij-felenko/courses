# 🔌 Архітектурне порівняння серверів оновлень: Eclipse hawkBit, Mender Server, AWS IoT OTA та RAUC/SWUpdate бекенди

Вибір архітектури сервера оновлень визначає, як інженерна команда керує життєвим циклом вбудованого програмного забезпечення, які обчислювальні ресурси споживає інфраструктура доставки і наскільки надійно захищений ланцюг постачання артефактів. У сучасній інженерній практиці виділяють чотири провідні парадигми побудови керуючої площини (OTA Control Plane): модульні платформи масштабу підприємства (Eclipse hawkBit), спеціалізовані екосистемні сервери (Mender Server), повністю керовані хмарні сервіси (AWS IoT OTA / Jobs) та легковагі кастомні бекенди на основі статичних CDN і відкритих клієнтських агентів (RAUC / SWUpdate).

Кожна з цих платформ базується на відмінних архітектурних припущеннях щодо природи артефактів, моделі зв'язку з пристроями, формату маніфестів та розподілу відповідальності між сервером і клієнтом.

## 1. Eclipse hawkBit: модульність, розподілені набори та масштаби підприємства

**Eclipse hawkBit** — це серверна Java-платформа з відкритим вихідним кодом (розроблена під егідою Eclipse Foundation та Bosch), спроєктована для обслуговування сотень мільйонів промислових вузлів, телематичних блоків та компонентів «розумного міста».

### Архітектурні особливості:
- **Модель даних «Distribution Set»:** hawkBit не розглядає прошивку як один монолітний бінарник. Реліз представляє собою набір взаємопов'язаних модулів ПЗ (Software Modules). Кожен модуль може належати до власного типу: образ базової ОС Linux (rootfs), мікрокод мікроконтролера керування живленням (MCU firmware), бітстрім FPGA, конфігураційний пакет або JVM-додаток.
- **Два інтерфейси зв'язку:**
  1. *DDI (Direct Device Integration API)* — легковажний REST/HTTP API для прямого опитування сервером пристроями (pull-модель через короткі або довгі HTTP-запити).
  2. *DMF (Device Management Federation)* — асинхронний інтерфейс на базі протоколів AMQP/MQTT для підключення через брокери повідомлень та сторонні шлюзи керування пристроями (наприклад, Eclipse Hono або Bosch IoT Hub).
- **Масштабованість і зберігання:** hawkBit спирається на реляційну СУБД (PostgreSQL / MariaDB) для збереження топології парку та маніфестів, а власне бінарні файли зберігає у зовнішньому об'єктному сховищі (S3, MinIO або сумісні API).

hawkBit ідеально підходить для великих виробничих підприємств і автомобільних концернів, де один фізичний виріб (наприклад, автомобіль чи промисловий станок) містить десятки різних обчислювальних модулів, що оновлюються незалежно, але вимагають скоординованого релізного узгодження.

## 2. Mender Server: глибока оптимізація для вбудованого Linux

**Mender Server** від компанії Northern.tech — це сучасна мікросервісна керуюча площина, написана мовою Go, оптимізована для обслуговування пристроїв під керуванням вбудованого Linux (зокрема систем, зібраних за допомогою Yocto Project / OpenEmbedded або Debian).

### Архітектурні особливості:
- **Орієнтація на контейнерний формат `.mender`:** Сервер оперує стандартизованими пакетами Mender Artifact. Під час завантаження артефакту сервер парсить заголовок архіву, автоматично валідує цифровий підпис і витягує метадані сумісності типів пристроїв (`device_type`), виключаючи людські помилки ручного заповнення форм.
- **Динамічний інвентар та автогрупування:** Клієнти періодично відправляють на сервер набори атрибутів стану (поточна версія ядра, IP-адреса, рівень сигналу модему, ревізія плати). Mender дозволяє створювати динамічні групи пристроїв на основі фільтрів атрибутів і автоматично прив'язувати розгортання до цих груп.
- **Підтримка дельта-оновлень:** Сервер підтримує інтеграцію з генератором двійкових різниць (mender-artifact delta), що дозволяє публікувати релізи, які зменшують мережевий трафік на 80–95% у порівнянні з передачею повного образу rootfs.

Mender є оптимальним вибором для продуктових компаній, які створюють складні IoT-пристрої, шлюзи автоматизації та медичне обладнання на базі архітектур ARM/x86 під Linux і прагнуть отримати надійний інструмент «з коробки» без тривалої корпоративної інтеграції.

## 3. AWS IoT Jobs та AWS IoT OTA: хмарно-нативний підхід

**AWS IoT OTA** — це спеціалізований компонент екосистеми Amazon Web Services, призначений для оновлення мікроконтролерів під керуванням FreeRTOS та вбудованих Linux-комп'ютерів (через AWS IoT Greengrass).

### Архітектурні особливості:
- **Двоканальна модель (MQTT Control + HTTPS Data):** Сповіщення про наявність нового релізу, призначення завдань та звіти про прогрес передаються через постійне двостороннє з'єднання MQTT (сервіс AWS IoT Core). Власне бінарний payload завантажується безпосередньо з Amazon S3 за допомогою короткоживучих підписаних посилань (Presigned URLs) через протокол HTTPS або потоково блоками через MQTT (для пристроїв без повноцінного HTTP-стеку).
- **Інтеграція з AWS KMS та AWS Signer:** Процес підпису прошивки повністю інтегрований із хмарним модулем апаратного захисту ключів (Cloud HSM). Інженер відправляє бінарний файл у сервіс AWS Signer, який накладає асиметричний підпис (ECDSA SHA-256 або RSA) і автоматично формує документ релізного завдання (Job Document).
- **Бессерверна оркестрація:** Кампанії оновлення налаштовуються через стандартні механізми AWS IoT Jobs з автоматичним контролем швидкості розгортання (rollout rate) та пороговими значеннями аварійного скасування.

AWS IoT OTA є природним вибором для інженерних команд, чия бекенд-інфраструктура вже побудована на сервісах AWS, а парк пристроїв включає як мікроконтролери з мінімальним обсягом RAM (ESP32, STM32), так і повноцінні Linux-вузли.

## 4. RAUC / SWUpdate власні HTTP/CDN-бекенди

Для систем із критичними вимогами до суверенітету даних, ізольованих контурів без виходу в публічний інтернет (air-gapped environments) або проектів із жорстким обмеженням бюджету інженери будують легковагі бекенди на основі CDN навколо відкритих клієнтських агентів **RAUC** (Robust Auto-Update Controller) або **SWUpdate**.

### Архітектурні особливості:
- **Статичний хостинг маніфестів:** Серверна частина зводиться до статичного сховища (Nginx, MinIO, CloudFront), де публікуються підписані файли маніфестів та бінарні бандли (`.raucb` або `.swu`).
- **Клієнтоцентрична безпека:** Уся валідація зосереджена на боці клієнтського демона RAUC. Демон містить вбудоване сховище відкритих ключів або кореневих x509-сертифікатів і здійснює криптографічну перевірку підпису CMS/PKCS#7 у момент потокового зчитування з HTTP-сервера.
- **Мінімальні експлуатаційні витрати:** Відсутність важких керуючих серверів бази даних дозволяє обслуговувати мільйонний парк пристроїв за допомогою звичайної CDN-мережі з кешуванням на крайових серверах.

Цей підхід обирають оборонні підприємства, виробники залізничної та критичної енергетичної інфраструктури, де централізований хмарний контроль не допускається регламентами безпеки.

## Зведена порівняльна матриця

| Критерій порівняння | Eclipse hawkBit | Mender Server | AWS IoT OTA | Кастомний RAUC/SWUpdate CDN |
|---|---|---|---|---|
| **Модель розгортання** | Self-hosted (Java/Spring Boot) | Self-hosted (Go) / SaaS Cloud | Повністю керований SaaS (AWS) | Статичний CDN / Nginx / MinIO |
| **Парадигма артефактів** | Multi-module Distribution Set | Контейнери `.mender` + дельти | Двійкові файли + Job Document | Бандли `.raucb` / `.swu` |
| **Протоколи керування** | HTTP REST (DDI) / AMQP (DMF) | HTTP/HTTPS REST / WebSockets | MQTT (Jobs) + HTTPS (S3) | HTTP/HTTPS REST (Pull) |
| **Криптографічний підпис** | Залежить від модуля / зовнішній | Вбудований RSA/ECDSA/Ed25519 | AWS Signer / KMS (ECDSA/RSA) | x509 CMS (PKCS#7) / RSA / ECDSA |
| **Підтримувані цілі** | Linux, RTOS, MCU, контейнери | Переважно Embedded Linux | FreeRTOS, MCU, Linux Greengrass | Embedded Linux |
| **Складність експлуатації** | Висока (JVM, DB, RabbitMQ) | Середня (Docker/Kubernetes) | Низька (Cloud Managed) | Мінімальна (Static Files) |
| **Оркестрація хвиль (Rollout)** | Розвинена (кампанії, ліміти) | Розвинена (динамічні когорти) | Розвинена (IoT Job rate limits) | Реалізується самостійно |

## Критерії прийняття інженерного рішення

1. **Якщо ваш пристрій — це складний комплекс із декількох контролерів (Linux SoC + STM32 MCU + FPGA):** Обирайте **Eclipse hawkBit**, оскільки його модель Distribution Set спроектована саме для атомарної координації гетерогенних компонентів.
2. **Якщо ваш парк складається з монолітних Linux-плат (ARM Cortex-A / x86) на базі Yocto:** Обирайте **Mender Server**, який забезпечує найвищу швидкість інтеграції, нативні A/B-слоти та готові засоби дельта-компресії.
3. **Якщо уся телеметрія пристроїв вже передається в AWS IoT Core:** Обирайте **AWS IoT OTA**, щоб уникнути підтримки власного бекенду та безшовно інтегрувати випуск із конвеєрами AWS CodePipeline та CloudWatch.
4. **Якщо система працює в замкненій локальній мережі підприємства або вимагає сертифікації за найвищими стандартами криптографії x509:** Будуйте кастомну схему на основі **RAUC** та надійного статичного веб-сервера з авторизацією за клієнтськими сертифікатами (mTLS).
