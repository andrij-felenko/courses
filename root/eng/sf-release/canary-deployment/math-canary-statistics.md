# 🧮 Статистичний арбітраж канарки: непараметричні критерії, Z-тест пропорцій та розрахунок часу спостереження

Автоматизований аналіз канаркового розгортання (англ. *Automated Canary Analysis*, ACA) базується на математичному порівнянні телеметрії двох вибірок: контрольної групи (попередня стабільна версія `v1`, яку називають *Baseline*) та експериментальної групи (кандидат на реліз `v2`, або *Canary*).

Головна складність статистичної оцінки полягає в тому, що часові ряди виробничих розподілених систем (затримки мережевих відповідей, тривалість пауз збирача сміття, споживання пам'яті, обсяги черг) **категорично не підпорядковуються нормальному (гаусовому) розподілу**. Затримки сервісів мають виражену правосторонню асиметрію з «важкими хвостами» (англ. *heavy-tailed distribution*), містять мультимодальні піки через періодичні блокування та поодинокі аномальні викиди.

Застосування класичних параметричних показників — вибіркового середнього арифметичного та стандартного відхилення (а також класичного t-критерію Стьюдента) — призводить або до пропуску критичних деградацій, або до лавини хибних спрацьовувань:
* **Чутливість до викидів:** один випадковий запит із затримкою у 10 секунд (наприклад, через тайм-аут DNS-резолвера) піднімає середнє арифметичне тисячі швидких 10-мілісекундних запитів з 10 мс до 20 мс, хоча 99.9% системи функціонує бездоганно.
* **Приховування хвостових деградацій:** якщо через баг у новому коді 2% запитів сповільнилися вдесятеро, вибіркове середнє значення збільшиться лише на 18%, проте перцентиль `p99` зросте на 900%, що для високонавантаженої системи означає каскадну відмову.

Тому сучасний канарковий арбітраж спирається на надійні математичні моделі: **непараметричний ранговий критерій Манна-Вітні** для неперервних розподілів затримок, **Z-критерій рівності двох частот** для біноміальних частот помилок, **непараметричні довірчі інтервали квантилів**, **критерій Колмогорова-Смірнова** для порівняння форми функцій розподілу, **процедуру контролю хибних відкриттів** (FDR) при оцінці множинних метрик та **модель багаторівневої скорингової агрегації**.

## 1. Непараметричний ранговий критерій Манна-Вітні (Mann-Whitney U Test)

Ранговий критерій Манна-Вітні (також відомий як критерій Вілкоксона для двох незалежних вибірок) перевіряє нульову гіпотезу про те, що розподіли двох генеральних сукупностей є стохастично еквівалентними.

Якщо обрати випадкове значення затримки з розподілу бейзлайну `X` та випадкове значення з розподілу канарки `Y`, нульова та альтернативна гіпотези формулюються так:

```text
H₀: P(Y > X) = P(X > Y) = 0.5  (розподіли затримок ідентичні)
H₁: P(Y > X) > 0.5            (затримки канарки стохастично більші за бейзлайн)
```

Критерій не вимагає симетричності чи нормальності розподілу, оскільки оперує не абсолютними значеннями затримок, а їхніми **рангами** (порядковими номерами у відсортованому об'єднаному масиві).

### Математичний алгоритм обчислення

Нехай вибірка затримок бейзлайну містить `n₁` спостережень `X = {x₁, x₂, ..., x_n₁}`, а вибірка канарки — `n₂` спостережень `Y = {y₁, y₂, ..., y_n₂}`.

1. **Об'єднання та ранжування:** Усі `N = n₁ + n₂` значень об'єднуються в єдиний масив і сортуються за зростанням. Кожному елементу присвоюється порядковий ранг від `1` до `N`. Якщо кілька значень збігаються (зв'язані ранги), кожному елементу цієї групи присвоюється їхній середній арифметичний ранг.
2. **Підсумовування рангів:** Обчислюються суми рангів для першої (`R₁`) та другої (`R₂`) вибірок:
   ```text
   R₁ = ∑ rank(xᵢ)
   R₂ = ∑ rank(yⱼ)
   ```
   Контрольна тотожність для перевірки правильності обчислень:
   ```text
   R₁ + R₂ = N · (N + 1) / 2
   ```
3. **Обчислення статистики Манна-Вітні:**
   Кількість інверсій (випадків, де значення однієї вибірки перевершують значення іншої) обчислюється за формулами:
   ```text
   U₁ = n₁ · n₂ + (n₁ · (n₁ + 1)) / 2 - R₁
   U₂ = n₁ · n₂ + (n₂ · (n₂ + 1)) / 2 - R₂
   ```
   Властивість інваріантності:
   ```text
   U₁ + U₂ = n₁ · n₂
   ```
   Статистика `U` визначається як менше з двох значень: `U = min(U₁, U₂)`.

### Апроксимація нормальним розподілом для великих вибірок (`n₁, n₂ ≥ 20`)

За центральною граничною теоремою, при обсягах вибірок понад 20 спостережень розподіл статистики `U` апроксимується нормальним законом з математичним сподіванням `μ_U` та дисперсією `σ_U²`:

```text
μ_U = (n₁ · n₂) / 2

σ_U² = (n₁ · n₂ · (n₁ + n₂ + 1)) / 12
```

Якщо у вибірці присутня велика кількість однакових затримок (зв'язані ранги), дисперсія коригується фактором зв'язок:

```text
σ_{U, adj}² = (n₁ · n₂ / 12) · [ (N + 1) - ∑ (t_k³ - t_k) / (N · (N - 1)) ]
```

де `t_k` — кількість однакових значень у `k`-й групі зв'язаних рангів.

Нормована Z-статистика обчислюється з поправкою на неперервність `+0.5`:

```text
Z = (U - μ_U + 0.5) / σ_U
```

Якщо абсолютне значення `|Z|` перевищує критичний поріг для заданого рівня значущості `α` (наприклад, для одностороннього тесту при `α = 0.05` критичне значення `Z_крит = 1.645`), нульова гіпотеза `H₀` відкидається: канарка демонструє статистично значущу деградацію продуктивності.

### Покроковий числовий приклад розрахунку Mann-Whitney U

Розглянемо дві вибірки затримок відповідей у мілісекундах (по `n₁ = 8` запитів для бейзлайну та `n₂ = 8` запитів для канарки):

```text
Бейзлайн (X): [ 12.1, 14.5, 15.0, 16.2, 18.0, 19.4, 21.0, 24.5 ]
Канарка   (Y): [ 14.8, 16.5, 18.2, 20.1, 22.0, 25.0, 27.5, 31.0 ]
```

Об'єднаний відсортований масив із рангами (`N = 16`):

| Значення (мс) | Джерело | Ранг |
|---|---|---|
| 12.1 | Baseline | 1 |
| 14.5 | Baseline | 2 |
| 14.8 | Canary | 3 |
| 15.0 | Baseline | 4 |
| 16.2 | Baseline | 5 |
| 16.5 | Canary | 6 |
| 18.0 | Baseline | 7 |
| 18.2 | Canary | 8 |
| 19.4 | Baseline | 9 |
| 20.1 | Canary | 10 |
| 21.0 | Baseline | 11 |
| 22.0 | Canary | 12 |
| 24.5 | Baseline | 13 |
| 25.0 | Canary | 14 |
| 27.5 | Canary | 15 |
| 31.0 | Canary | 16 |

Підсумуємо ранги:
```text
R₁ (Baseline) = 1 + 2 + 4 + 5 + 7 + 9 + 11 + 13 = 52
R₂ (Canary)   = 3 + 6 + 8 + 10 + 12 + 14 + 15 + 16 = 84
```

Перевірка суми рангів:
```text
R₁ + R₂
= 52 + 84           [додавання отриманих сум]
= 136               [фактична сума]

N · (N + 1) / 2
= 16 · 17 / 2       [теоретична формула суми перших N чисел]
= 136               [контрольні суми зійшлися точно]
```

Обчислимо статистику `U₁` та `U₂`:
```text
U₁
= n₁ · n₂ + (n₁ · (n₁ + 1)) / 2 - R₁   [загальна формула U₁]
= 8 · 8 + (8 · 9) / 2 - 52            [підстановка n₁=8, n₂=8, R₁=52]
= 64 + 36 - 52                         [проміжне обчислення]
= 48                                   [значення U₁]

U₂
= n₁ · n₂ + (n₂ · (n₂ + 1)) / 2 - R₂   [загальна формула U₂]
= 8 · 8 + (8 · 9) / 2 - 84            [підстановка n₁=8, n₂=8, R₂=84]
= 64 + 36 - 84                         [проміжне обчислення]
= 16                                   [значення U₂]
```

Перевірка інваріанта:
```text
U₁ + U₂ = 48 + 16 = 64 = n₁ · n₂ (8 · 8 = 64).
```

Виберемо статистику `U = min(U₁, U₂) = 16`.

Обчислимо параметри теоретичного розподілу:
```text
μ_U
= (n₁ · n₂) / 2     [математичне сподівання]
= (8 · 8) / 2       [підстановка чисел]
= 32.0              [центр розподілу]

σ_U²
= (n₁ · n₂ · (n₁ + n₂ + 1)) / 12   [дисперсія U]
= (8 · 8 · 17) / 12                [підстановка n₁=8, n₂=8, N+1=17]
= 1088 / 12                        [ділення]
= 90.667                           [дисперсія]

σ_U
= √(90.667)         [квадратний корінь із дисперсії]
≈ 9.522             [стандартне відхилення статистики U]
```

Обчислюємо нормалізоване значення Z-оцінки:
```text
Z
= (U - μ_U + 0.5) / σ_U    [формула стандартизації з поправкою]
= (16 - 32 + 0.5) / 9.522  [підстановка U=16, μ=32, σ=9.522]
= -15.5 / 9.522            [чисельник]
≈ -1.628                   [Z-оцінка для вибірки]
```

Для критичного рівня `α = 0.05` одностороннє критичне значення становить `-1.645`. Оскільки `Z = -1.628` розташоване в зоні незначущості (`-1.628 > -1.645`), на вибірці з 8 запитів відмінність ще не досягла статистичної достовірності (тест вимагає додаткового часу спостереження). Проте якби вибірка налічувала 20 запитів із тим самим зміщенням, `Z` перевищило б `-2.5`, і реліз було б заблоковано.

## 2. Непараметричні довірчі інтервали для квантилів затримок (p95, p99)

При аналізі перцентилів затримок інженери часто намагаються обчислити точкове значення квантиля `q` (наприклад, `q = 0.99`) і безпосередньо порівняти два числа. Проте точкові оцінки вибіркових квантилів мають високу випадкову дисперсію.

Для побудови непараметричного довірчого інтервалу для квантиля `q` порядку `1 - α` використовують порядкові статистики та біноміальний розподіл.

Нехай варіаційний ряд вибірки обсягом `n` має вигляд:
```text
x_{(1)} ≤ x_{(2)} ≤ ... ≤ x_{(n)}
```

Індекс нижньої межі `j` та верхньої межі `k` довірчого інтервалу визначаються з умов біноміального розподілу `B(n, q)`:

```text
j ≈ n · q - Z_{α/2} · √( n · q · (1 - q) )
k ≈ n · q + Z_{α/2} · √( n · q · (1 - q) ) + 1
```

Справжнє значення перцентиля генеральної сукупності лежить у діапазоні `[ x_{(j)}, x_{(k)} ]` з надійністю `1 - α`. Якщо нижня межа довірчого інтервалу канарки `x_{(j), canary}` строго більша за верхню межу бейзлайну `x_{(k), baseline}`, конвеєр фіксує статистично доведене погіршення перцентиля затримки без необхідності параметричного моделювання.

## 3. Двовибірковий критерій Колмогорова-Смірнова (Kolmogorov-Smirnov Test)

На відміну від критерію Манна-Вітні, який передусім чутливий до зсуву медіани (локаційного зсуву розподілів), двовибірковий критерій Колмогорова-Смірнова оцінює максимальну абсолютну розбіжність між емпіричними функціями розподілу (англ. *Empirical Cumulative Distribution Function*, ECDF) двох вибірок.

Нехай `F₁(x)` — емпірична функція розподілу затримок бейзлайну, а `F₂(x)` — емпірична функція розподілу затримок канарки:

```text
F₁(x) = (кількість елементів у X ≤ x) / n₁
F₂(x) = (кількість елементів у Y ≤ x) / n₂
```

Статистика критерію `D` визначається як точна верхня грань (супремум) модулів різниці між двома функціями:

```text
D = sup_x | F₁(x) - F₂(x) |
```

Критичне значення `D_crit` для рівня значущості `α = 0.05` обчислюється за асимптотичною формулою:

```text
D_crit = 1.36 · √( (n₁ + n₂) / (n₁ · n₂) )
```

Якщо обчислена статистика `D > D_crit`, нульова гіпотеза про однаковість розподілів відкидається. Критерій Колмогорова-Смірнова особливо ефективний для виявлення бімодальних розщеплень, коли медіана залишається незмінною, але частина запитів формує другий пік затримок через періодичні збої кешування.

## 4. Z-критерій порівняння двох біноміальних частот помилок (Two-Proportion Z-Test)

Частота помилок (англ. *Error Rate*, частка відповідей `HTTP 5xx` від загальної кількості запитів) підпорядковується біноміальному розподілу `B(n, p)`. Якщо сервіс обробив `n` запитів і повернув `k` помилок, вибіркова частка помилок становить `p̂ = k / n`.

Для порівняння двох частот перевіряється гіпотеза про те, що канарковий реліз не збільшив частку помилок порівняно з бейзлайном:
```text
H₀: p_canary = p_baseline
H₁: p_canary > p_baseline (частота помилок канарки вища)
```

### Формули тестування

Нехай бейзлайн зафіксував `k₁` помилок на `n₁` запитах (`p̂₁ = k₁ / n₁`), а канарка — `k₂` помилок на `n₂` запитах (`p̂₂ = k₂ / n₂`).

1. **Об'єднана частка помилок (Pooled Proportion):**
   Оскільки нульова гіпотеза припускає рівність `p₁ = p₂ = p`, найкращою оцінкою спільного параметра є об'єднана частка:
   ```text
   p̂ = (k₁ + k₂) / (n₁ + n₂)
   ```
2. **Стандартна помилка різниці частот (Standard Error):**
   ```text
   SE = √( p̂ · (1 - p̂) · (1/n₁ + 1/n₂) )
   ```
3. **Z-статистика:**
   ```text
   Z = (p̂₂ - p̂₁) / SE
   ```

Якщо `Z ≥ 1.645` (для `α = 0.05`) або `Z ≥ 2.326` (для `α = 0.01`), гіпотеза `H₀` відкидається: частка помилок канарки статистично значуще вища за базовий рівень.

---

### Робочий числовий приклад розрахунку Z-тесту помилок

Протягом 5-хвилинного вікна спостереження отримано такі метрики:
* **Бейзлайн:** `n₁ = 50 000` запитів, виявлено `k₁ = 25` помилок (`p̂₁ = 25 / 50000 = 0.00050` або `0.050%`).
* **Канарка:** `n₂ = 50 000` запитів, виявлено `k₂ = 48` помилок (`p̂₂ = 48 / 50000 = 0.00096` або `0.096%`).

Обчислимо об'єднану частку помилок `p̂`:
```text
p̂
= (k₁ + k₂) / (n₁ + n₂)           [об'єднання вибірок]
= (25 + 48) / (50000 + 50000)     [підстановка чисел]
= 73 / 100000                     [проміжне значення]
= 0.00073                         [об'єднана частка помилок]
```

Обчислимо стандартну помилку `SE`:
```text
1 - p̂
= 1 - 0.00073                        [віднімання частки помилок від одиниці]
= 0.99927                            [ймовірність успішного запиту]

(1/n₁ + 1/n₂)
= 1/50000 + 1/50000                  [сума обернених обсягів вибірок]
= 2 / 50000                          [зведення дробів до спільного знаменника]
= 0.00004                            [коефіцієнт масштабу дисперсії]

SE
= √( 0.00073 · 0.99927 · 0.00004 )   [підстановка у формулу SE]
= √( 0.000729467 · 0.00004 )         [добуток частот]
= √( 0.0000000291787 )               [підкореневий вираз]
≈ 0.0001708                          [стандартна помилка різниці частот]
```

Обчислимо Z-статистику:
```text
Z
= (p̂₂ - p̂₁) / SE                     [формула Z-критерію]
= (0.00096 - 0.00050) / 0.0001708    [підстановка вибіркових частот]
= 0.00046 / 0.0001708                [абсолютна різниця частот]
≈ 2.693                              [значення критерію Z]
```

Оскільки `Z = 2.693 > 2.326` (критичне значення для `α = 0.01`), ймовірність того, що різниця викликана випадковим шумом, становить менше `0.35%` (`p-value = 0.0035`). Контролер прогресивної доставки фіксує статистично достовірну деградацію надійності релізу та ініціює аварійний відкіт.

## 5. Математичний розрахунок обсягу вибірки та часу витримки (Bake Time)

Поширеною інженерною помилкою є передчасне ухвалення рішення контролером через нестачу статистичної потужності вибірки. Якщо на канарковий вузол спрямувати лише 1% трафіку і зробити зріз через 30 секунд, вибірка міститиме надто мало запитів, щоб відрізнити реальну зміну від випадкового коливання.

Щоб гарантовано виявити деградацію величиною `Δ` із заданою **похибкою першого роду** `α` (ймовірність хибної тривоги) та **статистичною потужністю** `1 - β` (ймовірність успішного виявлення реального дефекту), мінімальний розмір вибірки `n` для кожної з двох груп обчислюється за формулою Лемана:

```text
n ≥ 2 · (Z_{α/2} + Z_β)² · σ² / Δ²
```

Де:
* `Z_{α/2}` — квантиль стандартного нормального розподілу для рівня значущості `α` (для `α = 0.05`, `Z_{0.025} = 1.96`);
* `Z_β` — квантиль для статистичної потужності `1 - β` (для потужності `80%`, `β = 0.20`, `Z_{0.20} = 0.842`);
* `σ²` — оцінка дисперсії досліджуваної метрики на бейзлайні;
* `Δ` — мінімальний розмір ефекту (англ. *Minimum Detectable Effect*, MDE), який система зобов'язана зафіксувати (наприклад, зростання затримки на `5 мс`).

### Перехід від кількості запитів до часу витримки

Якщо загальний вхідний потік сервісу становить `QPS_total` запитів на секунду, а вага канаркового трафіку дорівнює `w` (де `0 < w ≤ 1`), швидкість надходження запитів на канарку становить:
```text
QPS_canary = QPS_total · w
```

Мінімальний необхідний час спостереження (англ. *bake time*) `T_min` у секундах дорівнює:
```text
T_min = n / QPS_canary = n / (QPS_total · w)
```

### Робочий числовий приклад розрахунку часу витримки

Нехай маємо сервіс із такими характеристиками:
* Загальне навантаження: `QPS_total = 2 000` запитів на секунду.
* Вага канаркового кроку: `w = 0.02` (2% трафіку).
* Дисперсія затримки на бейзлайні: `σ = 15 мс` (тобто `σ² = 225`).
* Вимога: виявити деградацію затримки на `Δ = 3 мс` із надійністю `α = 0.05` (`Z_{α/2} = 1.96`) та потужністю `90%` (`β = 0.10`, `Z_β = 1.282`).

Обчислимо необхідну кількість запитів `n`:
```text
(Z_{α/2} + Z_β)²
= (1.960 + 1.282)²   [сума квантилів]
= (3.242)²           [квадрат суми]
≈ 10.511             [множник потужності]

n
= 2 · 10.511 · 225 / (3)²   [підстановка σ²=225, Δ=3]
= 4729.95 / 9               [ділення на квадрат ефекту]
≈ 526                       [мінімальна кількість запитів для кожної групи]
```

Обчислимо `QPS_canary` та мінімальний час спостереження `T_min`:
```text
QPS_canary
= 2000 · 0.02        [множення загального QPS на частку канарки 0.02]
= 40 запитів/с       [швидкість надходження запитів на канарку]

T_min
= n / QPS_canary     [ділення необхідного обсягу на швидкість надходження]
= 526 / 40           [підстановка n=526 та QPS=40]
≈ 13.15 секунди      [мінімальний час витримки спостереження]
```


Якщо ж мета полягає у виявленні делікатної зміни частоти помилок з `0.1%` до `0.15%` (`Δ = 0.0005`), формула біноміального тесту вимагатиме понад `180 000` запитів, що при навантаженні `40 QPS` дасть мінімальний час витримки `T_min = 180000 / 40 = 4500 с = 75 хвилин`. Це математично доводить, чому кроки канаркового розгортання для низькочастотних бізнес-метрик вимагають тривалих часових вікон.

## 6. Контроль множинної перевірки гіпотез: процедура Бенджаміні-Гохберга (FDR)

У реальних виробничих середовищах контролер автоматизованого аналізу порівнює не одну, а десятки метрик одночасно: затримки `p50`, `p90`, `p99`, споживання CPU, пам'ять, паузи збирача сміття GC, дисковий ввід-вивід та кілька десятків бізнес-показників (наприклад, `m = 50` незалежних статистичних тестів).

Якщо кожен тест виконується зі стандартним рівнем значущості `α = 0.05`, групова ймовірність отримання хоча б одного хибнопозитивного результату (англ. *Family-Wise Error Rate*, FWER) стрімко зростає:

```text
α_family = 1 - (1 - α)^m = 1 - (1 - 0.05)⁵⁰ = 1 - (0.95)⁵⁰ ≈ 1 - 0.0769 = 0.9231 (92.31%)
```

Тобто при аналізі 50 метрик ідеально справного релізу з імовірністю 92.3% хоча б одна метрика випадково вийде за допустимі межі, спровокувавши помилковий відкіт.

### Покроковий алгоритм Бенджаміні-Гохберга (Benjamini-Hochberg Procedure)

Для запобігання хибним відкатам застосовують контроль частки хибних відкриттів (англ. *False Discovery Rate*, FDR). Алгоритм впорядковує отримані `p`-значення всіх `m` метрик і динамічно коригує поріг відсікання:

1. Отримують `p`-значення для кожної з `m` метрик: `p₁, p₂, ..., p_m`.
2. Сортують їх за зростанням: `p_{(1)} ≤ p_{(2)} ≤ ... ≤ p_{(m)}`.
3. Для кожного рангу `i` обчислюють критичний поріг `(i / m) · Q`, де `Q` — цільовий рівень FDR (зазвичай `Q = 0.05`).
4. Знаходять найбільший індекс `k`, для якого виконується умова:
   ```text
   p_{(k)} ≤ (k / m) · Q
   ```
5. Усі метрики з індексами `i = 1, 2, ..., k` визнаються статистично значущими деградаціями, а всі інші відхилення з індексами `i > k` вважаються допустимим статистичним шумом.

Розглянемо числовий приклад для 5 метрик (`m = 5`, `Q = 0.05`):

| Метрика | Обчислене `p`-значення | Ранг `i` | Поріг `(i/5) · 0.05` | Рішення арбітра |
|---|---|---|---|---|
| Частота помилок 5xx | 0.003 | 1 | 0.010 | **Деградація (p ≤ 0.010)** |
| Затримка p99 | 0.015 | 2 | 0.020 | **Деградація (p ≤ 0.020)** |
| Паузи збирача GC | 0.038 | 3 | 0.030 | Шум (p > 0.030) |
| Споживання CPU | 0.045 | 4 | 0.040 | Шум (p > 0.040) |
| Мережевий трафік | 0.220 | 5 | 0.050 | Шум (p > 0.050) |

У цьому прикладі найбільший індекс `k = 2` (для затримки p99 `0.015 ≤ 0.020`). Тільки помилки 5xx та затримка p99 визнаються реальними аномаліями, тоді як коливання GC та CPU коректно відфільтровано як шум.

## 7. Багаторівнева модель скорингу (Kayenta Scoring Model)

На фінальному етапі арбітражу результати всіх окремих статистичних перевірок агрегуються в єдиний числовий показник — **Canary Score** (від `0` до `100` балів).

Метрики групуються за трьома ієрархічними доменами:
1. **Системні метрики (System Health, вага `W_sys`):** CPU, пам'ять, файлові дескриптори, мережеві переповтори.
2. **Метрики сервісу (Service Health, вага `W_svc`):** затримки запитів, частота 5xx відповідей, розміри черг.
3. **Бізнес-показники (Business Health, вага `W_biz`):** завершені транзакції, конверсії, створені сесії.

Кожна група отримує оцінку успішності `S_g` як частку метрик, що пройшли перевірку:

```text
S_g = (кількість успішних метрик у групі g) / (загальна кількість метрик у групі g) · 100
```

Підсумковий бал обчислюється як зважене середнє:

```text
Score = (W_sys · S_sys + W_svc · S_svc + W_biz · S_biz) / (W_sys + W_svc + W_biz)
```

## 8. Адаптивні пороги та урахування добової сезонності

Параметри дисперсії `σ²` та фонова частота помилок у живих системах ніколи не є константами: вони коливаються залежно від часу доби та географічного розподілу користувачів (добова сезонність, англ. *diurnal pattern*). Під час вечірнього піку навантаження фонова затримка природно зростає через підвищену насиченість мережевих інтерфейсів та черг бази даних.

Якщо застосовувати жорсткі статичні пороги (наприклад, абсолютний ліміт `p99 ≤ 50 мс`), конвеєр неминуче стикатиметься з двома класами помилок:
1. **Хибні тривоги в години пік:** реліз у піковий час буде заблоковано через природне сезонне зростання загального навантаження, навіть якщо нова версія працює ідеально.
2. **Пропуск дефектів у години спаду:** реліз о 4:00 ранку, який містить деградацію продуктивності на 200%, може вкластися у статичний ліміт 50 мс через мізерний трафік, і дефект буде виявлено лише вдень, коли він вразить 100% аудиторії.

Щоб усунути вплив сезонності, статистичний аналіз канарки виконує оцінку виключно **відносного відхилення канарки від синхронного бейзлайну в тому самому часовому вікні**, а не від історичних констант. Коефіцієнт відносної деградації `δ` обчислюється як:

```text
δ = (Median_canary - Median_baseline) / Median_baseline
```

Довірчий інтервал для коефіцієнта `δ` будується методом бутстрепу (англ. *bootstrap resampling*) на основі паралельних вибірок. Це гарантує математичну інваріантність канаркового арбітражу до будь-яких загальносистемних коливань навантаження.
