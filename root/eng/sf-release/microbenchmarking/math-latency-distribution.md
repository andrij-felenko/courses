# 🧮 Статистика вимірювання затримок: чому середнє бреше та як рахувати перцентилі

Математичний аналіз результатів мікробенчмаркінгу вимагає повної відмови від припущення про нормальний (гауссівський) розподіл вимірюваних величин. Час виконання комп'ютерної інструкції чи функції фундаментально несиметричний: він обмежений знизу апаратним мінімумом затримки конвеєра й не може бути меншим за нуль, але має необмежений довгий «хвіст» праворуч через промахи кешу, переривання операційної системи та конкуренцію за системну шину. Спроба описати такий процес двома числами — вибірковим середнім арифметичним і стандартним відхиленням — призводить до хибних інженерних висновків.

## Чому часові затримки не підкоряються розподілу Гаусса

Нормальний розподіл у теорії ймовірностей виникає тоді, коли підсумкова величина є сумою великої кількості незалежних однакових випадкових збурень (центральна гранична теорема). У мікроархітектурі процесора шум є принципово іншим:

1. **Жорстка ліва межа (фізичний бар'єр):**
   Час виконання `T` обмежений знизу константою `t[min] > 0`, що визначається довжиною критичного шляху інструкцій та тактовою частотою ядра. Імовірність отримати значення `T < t[min]` дорівнює нулю. Симетричний гауссівський дзвін із центром біля `t[min]` неминуче приписував би ненульову ймовірність фізично неможливим від'ємним чи заниженим часам.

2. **Багатомодальність (ієрархія дискретних станів):**
   Вибірка затримок не формує єдиний плавний пік. Вона складається з суміші кількох окремих підрозподілів (мод), кожен із яких відповідає конкретному апаратному стану:
   - Мода 1: попадання в L1-кеш інструкцій та даних (~1–4 такти);
   - Мода 2: попадання в L2/L3-кеш (~12–40 тактів);
   - Мода 3: звернення до оперативної пам'яті DRAM (~150–250 тактів);
   - Мода 4: перемикання контексту ядра ОС або обробка апаратного переривання (~5000–50000 тактів).

3. **Важкі правосторонні хвости (Heavy Tails):**
   Поодинокі системні події (скидання сторінок пам'яті, TLB-промахи, переривання таймера ОС) дають викиди, що на 3–4 порядки перевищують типовий час виконання функції.

```
μ_sample
= (1 / N) · ∑ t[i]      [формула вибіркового середнього арифметичного]
```

Оскільки у формулі середнього кожен елемент `t[i]` має однакову вагу `1 / N`, один-єдиний викид із затримкою 50 мкс серед 1000 замірів по 5 нс зміщує середнє з 5.00 нс до 54.95 нс:

```
μ_with_outlier
= (999 · 5 + 1 · 50000) / 1000
= (4995 + 50000) / 1000
= 54995 / 1000
= 54.995 нс             [середнє завищено в 11 разів через один викид]
```

Середнє арифметичне 55 нс потрапляє в порожню зону густини ймовірності, де процесор насправді не провів жодної ітерації.

## Розрахунок емпіричних квантилів і перцентилів

Для стійкого опису несиметричних розподілів застосовують рангову статистику та функцію емпіричного розподілу (Empirical Cumulative Distribution Function, ECDF).

Нехай у результаті `N` вимірювань отримано масив чисел `{t₁, t₂, ..., t_N}`. Впорядкуємо його за зростанням, отримавши варіаційний ряд (порядок за зростанням):

```
t(1) ≤ t(2) ≤ t(3) ≤ ... ≤ t(N)
```

Емпірична функція розподілу `F_N(t)` визначає частку спостережень, час яких не перевищує порогового значення `t`:

```
F_N(t)
= (1 / N) · ∑ I(t[i] ≤ t)   [де I — індикаторна функція, рівна 1 якщо t[i] ≤ t, і 0 інакше]
```

Квантилем рівня `p` (де `0 < p < 1`) називається значення `Q(p)`, нижче якого лежить частка `p` усіх спостережень вибірки:

```
Q(p)
= inf { t : F_N(t) ≥ p }    [найменше значення затримки з накопиченою ймовірністю ≥ p]
```

У мікробенчмаркінгу квантилі традиційно виражають у відсотках і називають **перцентилями** (від лат. *per centum* — на сотню):
- `p50` (50-й перцентиль, або **медіана**): типовий час виконання, що ділить відсортовану вибірку навпіл. 50% ітерацій завершилися швидше за медіану, 50% — повільніше. Медіана абсолютно нечутлива до одиничних гігантських викидів.
- `p90`, `p95`: показники стабільності роботи під легким системним шумом.
- `p99`, `p99.9` («довгий хвіст», tail latency): затримка в найгірших сценаріях, критично важлива для систем реального часу та високонавантажених сервісів із жорсткими угодами про рівень обслуговування (SLA).

### Алгоритм лінійної інтерполяції перцентилів

Для неперервної оцінки перцентиля `p` на дискретній вибірці розміру `N` застосовують стандартну лінійну інтерполяцію між сусідніми рангами:

1. Обчислюємо дійсний індекс позиції `k`:
```
k
= p · (N − 1) + 1       [розрахунок дробового рангу в 1-індексованому масиві]
```

2. Виділяємо цілу частину `i = ⌊k⌋` та дробовий залишок `f = k − i` (де `0 ≤ f < 1`).

3. Значення перцентиля обчислюється як зважена сума двох сусідніх елементів:
```
Q(p)
= t(i) + f · (t(i+1) − t(i))  [лінійна інтерполяція між значеннями t(i) та t(i+1)]
```

### Покроковий приклад розрахунку

Нехай маємо вибірку з `N = 10` замірів затримки хешування (в наносекундах), впорядковану за зростанням:
`{ 4.1, 4.2, 4.2, 4.3, 4.4, 4.5, 4.8, 5.1, 14.2, 85.0 }`

Обчислимо медіану `p50` (`p = 0.50`):
```
k_50
= 0.50 · (10 − 1) + 1
= 0.50 · 9 + 1
= 4.5 + 1
= 5.5                   [індекс між 5-м і 6-м елементами]

p50
= t(5) + 0.5 · (t(6) − t(5))
= 4.4 + 0.5 · (4.5 − 4.4)
= 4.4 + 0.5 · 0.1
= 4.45 нс               [медіанна затримка]
```

Обчислимо 90-й перцентиль `p90` (`p = 0.90`):
```
k_90
= 0.90 · (10 − 1) + 1
= 0.90 · 9 + 1
= 8.1 + 1
= 9.1                   [індекс між 9-м і 10-м елементами]

p90
= t(9) + 0.1 · (t(10) − t(9))
= 14.2 + 0.1 · (85.0 − 14.2)
= 14.2 + 0.1 · 70.8
= 14.2 + 7.08
= 21.28 нс              [90% замірів вклалися в 21.28 нс]
```

Для порівняння, середнє арифметичне цієї ж вибірки:
`μ = (4.1 + 4.2 + 4.2 + 4.3 + 4.4 + 4.5 + 4.8 + 5.1 + 14.2 + 85.0) / 10 = 134.8 / 10 = 13.48 нс`.
Середнє завищує типовий час виконання утричі через єдиний промах у пам'ять `85.0 нс`.

## Стійкі міри розсіювання: IQR та MAD

Замість середньоквадратичного відхилення `σ`, яке так само руйнується квадратами викидів, для оцінки розкиду вимірів використовують непараметричні метрики:

### 1. Інтерквартильний розмах (Interquartile Range, IQR)
Різниця між третім квартилем `Q₃` (`p75`) та першим квартилем `Q₁` (`p25`). Він охоплює центральні 50% усіх спостережень:

```
IQR
= Q₃ − Q₁               [інтерквартильний розмах: діапазон центральної половини розподілу]
```

Правило Тьюкі для виявлення аномальних викидів (Outliers): спостереження вважається викидом, якщо воно виходить за межі діапазону:
`[ Q₁ − 1.5 · IQR,  Q₃ + 1.5 · IQR ]`

### 2. Медіанне абсолютне відхилення (Median Absolute Deviation, MAD)
Медіана абсолютних відхилень кожного заміру від загальної медіани вибірки:

```
MAD
= median(| t[i] − median(T) |)  [стійка оцінка масштабу розкиду]
```

Для приведення `MAD` до масштабу звичного стандартного відхилення нормального розподілу використовують масштабний коефіцієнт `1.4826`:
`σ_est ≈ 1.4826 · MAD`.

## Непараметричне порівняння бенчмарків: Бутстреп

Коли інженер оптимізує алгоритм і отримує дві вибірки — до оптимізації `A = {t_A}` та після `B = {t_B}`, як математично довести, що прискорення є статистично значущим, а не результатом випадкового збігу?

Застосовувати t-критерій Стьюдента не можна через ненормальність розподілів. Надійним методом є **непараметричний бутстреп** (Bootstrap):
1. З емпіричної вибірки `A` розміру `N` генерують `B = 10000` псевдовибірок того самого розміру `N` шляхом випадкового вибору з поверненням (resampling with replacement).
2. Для кожної псевдовибірки обчислюють медіану `p50*` або `p99*`.
3. Отримують емпіричний розподіл самої медіани та знаходять її 95%-й довірчий інтервал `[L_A, R_A]`.
4. Якщо 95%-й інтервал медіани версії `B` не перетинається з інтервалом версії `A`, гіпотеза про реальне прискорення підтверджена зі статистичною надійністю `p < 0.05`.
