# 🧮 Закон універсальної масштабованості та ціна когерентності кешу

Математичний аналіз продуктивності багатоядерних систем демонструє, чому архітектура зі спільною пам'яттю зазнає деградації при збільшенні кількості процесорних ядер, тоді як архітектура Thread-per-core зі структурою Shared-Nothing зберігає близьку до лінійної масштабованість.

### Від закону Амдала до закону універсальної масштабованості Гюнтера

Класичний закон Амдала (Amdahl's Law, 1967 рік) визначає прискорення обчислень `S(N)` при використанні `N` процесорних ядер за наявності частки послідовного коду `σ` (де `0 ≤ σ ≤ 1`):

```
S(N) = N / (1 + σ·(N - 1))
```

Закон Амдала стверджує, що при необмеженому збільшенні кількості процесорів `N → ∞` прискорення монотонно зростає, наближаючись до асимптотичної теоретичної межі `1 / σ`. Проте на реальних серверах із 32, 64 чи 128 ядрами емпіричні вимірювання показують іншу динаміку: після досягнення деякої оптимальної кількості ядер `N_opt` загальна пропускна здатність системи починає стрімко падати. Це явище отримало назву **ретроградної масштабованості** (*retrograde scalability*).

Причина полягає в тому, що закон Амдала не враховує взаємодію між самими паралельними процесорами. Він припускає, що додавання нового ядра є безкоштовним і не створює перешкод для вже працюючих ядер. На практиці ж кожне додаткове ядро, що звертається до спільної пам'яті, створює додатковий трафік інвалідації кешу та завантажує спільні комутаційні шини міжпроцесорного зв'язку.

У 1993 році австралійський фізик та комп'ютерний аналітик Ніл Гюнтер (Neil J. Gunther) сформулював **Закон універсальної масштабованості** (USL — *Universal Scalability Law*). Гюнтер ввів у модель другий фундаментальний параметр — коефіцієнт когерентності та між'ядерної взаємодії `κ` (*coherence / crosstalk penalty*):

```
C(N) = N / (1 + σ·(N - 1) + κ·N·(N - 1))
```

Параметри моделі відображають фізичні процеси в обчислювальному вузлі:
- `C(N)` — відносне збільшення продуктивності (коефіцієнт масштабованості системи);
- `N` — кількість активних фізичних ядер процесора;
- `σ` (*sigma*) — коефіцієнт конкуренції (*contention*): частка часу, яку потоки проводять у послідовному очікуванні спільних ресурсів (черги до м'ютексів, критичні секції);
- `κ` (*kappa*) — коефіцієнт узгодженості когерентності (*coherency delay*): накладні витрати на передачу та інвалідацію кеш-ліній між ядрами за протоколами MESI/MOESI через міжпроцесорну шину.

Коли процесори обмінюються даними через спільну пам'ять, кожен вузол повинен узгоджувати стан своїх кеш-ліній з усіма іншими вузлами. Якщо в системі працює `N` ядер, кількість потенційних спрямованих каналів конфлікту зростає квадратично: кожне з `N` ядер взаємодіє з `(N - 1)` сусідами. Це породжує член `κ·N·(N - 1)`, який при великих `N` починає домінувати над лінійним чисельником.

### Математичний вивід оптимальної точки масштабування

Член `κ·N·(N - 1)` у знаменнику функції закону Гюнтера виникає внаслідок того, що в системі зі спільною змінюваною пам'яттю кожне з `N` ядер має потенціал інвалідувати кеш-лінії будь-якого з решти `(N - 1)` ядер. Загальна кількість парних зв'язків когерентності зростає пропорційно числу комбінацій:

```
Pairs = N·(N - 1) / 2
```

Знайдемо точку екстремуму функції `C(N)`, продиференціювавши вираз за змінною `N` та прирівнявши похідну до нуля:

```
d/dN [ C(N) ]
= d/dN [ N · (1 - σ + σ·N + κ·N² - κ·N)⁻¹ ]                [розкриття дужок у знаменнику]
= (1 - σ - κ·N²) / (1 + σ·(N - 1) + κ·N·(N - 1))²          [правило диференціювання частки]
```

Прирівнюємо чисельник похідної до нуля для знаходження точки максимуму:

```
1 - σ - κ·N² = 0
= κ·N² = 1 - σ                                            [перенесення членів]
= N_opt = √((1 - σ) / κ)                                  [витягнення квадратного кореня]
```

Значення `N_opt` визначає критичну кількість ядер, після якої додавання нових процесорів знижує загальну пропускну здатність системи. Якщо кількість фізичних ядер у сервері перевищує `N_opt`, кожен додатковий процесор погіршує роботу системи, оскільки час на узгодження кешів перевищує корисну обчислювальну роботу.

### Числовий розрахунок: спільна пам'ять проти Thread-per-core

Розглянемо практичний приклад високонавантаженого сервера бази даних із 64 ядрами (`N = 64`).

#### Випадок 1: Традиційний пул потоків зі спільною пам'яттю
У системі з пулом потоків частка послідовних блокувань становить `σ = 0.02` (2% часу в м'ютексах), а накладні витрати на інвалідацію кешу складають `κ = 0.001` (0.1%):

Розрахуємо оптимальну кількість ядер:

```
N_opt = √((1 - 0.02) / 0.001)
= √(0.98 / 0.001)                                         [ділення]
= √980                                                    [спрощення]
≈ 31.3 ядер                                               [максимум на 31 ядрі]
```

Розрахуємо коефіцієнт масштабованості для 32 та 64 ядер:

```
C(32)
= 32 / (1 + 0.02·31 + 0.001·32·31)
= 32 / (1 + 0.62 + 0.992)                                 [обчислення компонентів]
= 32 / 2.612
≈ 12.25                                                   [ефективність 38% від лінійної]

C(64)
= 64 / (1 + 0.02·63 + 0.001·64·63)
= 64 / (1 + 1.26 + 4.032)                                 [квадратичний штраф когерентності 4.032]
= 64 / 6.292
≈ 10.17                                                   [падіння продуктивності!]
```

**Аналіз результату:** При переході від 32 до 64 ядер загальна пропускна здатність сервера зі спільною пам'яттю впала з `12.25` до `10.17` (деградація на 17%), незважаючи на подвоєння апаратних ресурсів. Це класичний прояв ретроградної масштабованості.

#### Випадок 2: Архітектура Thread-per-core (Shared-Nothing)
В архітектурі Thread-per-core кожне ядро працює виключно зі своїм шардом даних, тому паразитний обмін кеш-лініями повністю усунуто: `κ = 0`. Частка послідовного коду зводиться до мінімальних накладних витрат на пакетований обмін повідомленнями: `σ = 0.0005`:

```
C_TPC(64)
= 64 / (1 + 0.0005·63 + 0·64·63)
= 64 / (1 + 0.0315 + 0)                                   [нульовий штраф когерентності]
= 64 / 1.0315
≈ 62.04                                                   [97% від ідеального лінійного прискорення!]
```

Завдяки усуненню коефіцієнта `κ` знаменник перестає зростати квадратично, забезпечуючи практично лінійне прискорення навіть при масштабуванні до сотень ядер на сокеті.

### Апаратна ціна інвалідації кеш-ліній у тактах CPU

Щоб зрозуміти фізичну природу коефіцієнта `κ`, зіставимо час доступу до даних у тактах процесора на мікроархітектурі x86-64 (тактова частота 3.2 ГГц, тривалість такту `τ ≈ 0.31` нс):

| Рівень пам'яті | Стан MESI | Затримка (такти CPU) | Затримка (наносекунди) |
|---|---|---|---|
| L1 Data Cache (локальний) | Modified / Exclusive | 4–5 тактів | ~1.2–1.5 нс |
| L2 Cache (локальний) | Exclusive | 12–14 тактів | ~3.8–4.4 нс |
| L3 Cache (спільний на кристалі) | Shared | 40–50 тактів | ~12.5–15.6 нс |
| Локальна оперативна пам'ять NUMA | Uncached | 150–180 тактів | ~46–56 нс |
| Віддалена оперативна пам'ять NUMA | Remote Socket | 350–450 тактів | ~110–140 нс |
| **Cache Line Bounce (між сокетами)** | **Invalidation `BusRdX`** | **250–400 тактів** | **~80–125 нс** |

Якщо два потоки виконують цикл атомарного оновлення CAS (`Compare-And-Swap`) над спільним лічильником:

```
while (!counter.compare_exchange_weak(expected, expected + 1)) {
    // повторна спроба через конфлікт інвалідації
}
```

У разі колізії кожна невдала ітерація генерує транзакцію інвалідації кешу, спалюючи щонайменше 300 тактів процесора на міжсокетний обмін. При 64 конкуруючих ядрах ймовірність успішного захоплення змінної падає пропорційно `1 / N`, а сумарні витрати процесорного часу зростають за квадратичним законом `O(N²)`, що цілком узгоджується з моделлю Гюнтера.

Фізична пропускна здатність міжпроцесорної шини стає жорстким апаратним лімітом. Якщо шина зв'язку здатна передавати до 20 мільйонів транзакцій інвалідації на секунду, а кожен запис генерує одну транзакцію, система фізично не зможе виконати більше 20 мільйонів оновлень на секунду на всі ядра разом. Ізоляція даних за принципом Shared-Nothing усуває ці транзакції, дозволяючи кожному ядру виконувати сотні мільйонів локальних записів у секунду паралельно.

Саме тому ізоляція даних за принципом Shared-Nothing є єдиним математично обґрунтованим способом досягнення високої масштабованості на багатоядерних серверах: вона перетворює квадратичний закон міжпроцесорних втрат `O(N²)` на строго лінійне зростання `O(N)`.
