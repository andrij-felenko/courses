# 🧮 Математична модель ціни синхронізації та закон Амдала

Ця математична вставка містить формальний вивід та кількісний аналіз втрат продуктивності під час забезпечення потокової безпеки за допомогою замків: від класичного закону Амдала для критичних секцій до моделі теорії черг Ерланга, аналізу порогу ефективності замків читачів-письменників та Універсального закону масштабованості Гюнтера (USL), що враховує витрати на когерентність процесорних кешів.

---

### 1. Закон Амдала: межа масштабованості послідовних критичних секцій

Коли алгоритм розпаралелюється на `N` незалежних процесорних ядер, частина коду виконується строго послідовно через необхідність захисту спільного стану замками взаємного виключення (критичні секції).

Нехай:
- `s` — частка часу роботи програми, що витрачається у послідовних критичних секціях (`0 ≤ s ≤ 1`).
- `p = 1 - s` — частка часу, що виконується ідеально паралельно без міжпотокових взаємодій.
- `N` — кількість доступних фізичних процесорних ядер.
- `T₁` — час виконання програми на одному процесорному ядрі.

Загальний час виконання на `N` ядрах `T(N)` становить:

```
T(N) = T₁·s + (T₁·(1 - s)) / N
```

Коефіцієнт прискорення `S(N)` визначається як відношення часу на одному ядрі до часу на `N` ядрах:

```
S(N)
= T₁ / T(N)                                    [означення коефіцієнта прискорення]
= T₁ / (T₁·s + (T₁·(1 - s)) / N)              [підстановка виразу для T(N)]
= 1 / (s + (1 - s) / N)                        [скорочення на T₁]
```

При необмеженому збільшенні кількості ядер (`N → ∞`) член `(1 - s) / N` прямує до нуля, і теоретична межа прискорення становить:

```
S_max
= lim(N → ∞) [1 / (s + (1 - s) / N)]          [граничний перехід при N прямує до нескінченності]
= 1 / s                                        [асимптотична стеля закону Амдала]
```

#### Числовий приклад 1: ціна 5% критичної секції
Якщо блокування спільного стану займає лише `s = 0.05` (5% загального часу виконання), максимальне прискорення всієї системи не може перевищити:

```
S_max
= 1 / 0.05                                     [підстановка s = 0.05]
= 20                                           [максимальне теоретичне прискорення]
```

Навіть якщо виділити 1000 процесорних ядер, система ніколи не запрацює швидше, ніж у 20 разів відносно одного ядра, а 98% апаратних ресурсів простоюватимуть в очікуванні звільнення замка.

### 2. Теорія черг: модель M/M/1 для конкуренції за м'ютекс

Закон Амдала припускає, що очікування замка не створює додаткових накладних витрат. Проте в реальних операційних системах замки створюють черги потоків.

Розглянемо критичну секцію як систему масового обслуговування з одним каналом (м'ютексом) типу **M/M/1**:
- `λ` — середня частота запитів на захоплення замка від усіх потоків разом (запитів/с).
- `μ` — середня пропускна здатність критичної секції (операцій/с), де `1/μ` — середня тривалість утримання замка.
- `ρ = λ / μ` — коефіцієнт завантаження замка (`0 ≤ ρ < 1`).

Середній час очікування потоку в черзі до моменту захоплення замка `W_q` виводиться з формули Хінчина-Поллачека:

```
W_q
= ρ / (μ·(1 - ρ))                              [середній час очікування в черзі M/M/1]
= λ / (μ·(μ - λ))                              [підстановка коефіцієнта завантаження ρ = λ / μ]
```

Коли сумарний потік запитів `λ` наближається до пропускної здатності `μ` (`ρ → 1`), знаменник `(1 - ρ)` прямує до нуля, і час очікування зростає експоненційно до нескінченності.

#### Розрахунок затримки при зростанні навантаження:
Нехай критична секція триває `1/μ = 10` мкс (`μ = 100 000` оп/с).

1. При `ρ = 0.5` (50% завантаження замка):
```
W_q
= 0.5 / (100000 · (1 - 0.5))                   [підстановка ρ = 0.5 та μ = 100000]
= 0.5 / 50000                                  [обчислення знаменника: 100000 · 0.5 = 50000]
= 0.00001 с = 10 мкс                           [час очікування дорівнює часу роботи]
```

2. При `ρ = 0.9` (90% завантаження замка):
```
W_q
= 0.9 / (100000 · (1 - 0.9))                   [підстановка ρ = 0.9 та μ = 100000]
= 0.9 / 10000                                  [обчислення знаменника: 100000 · 0.1 = 10000]
= 0.00009 с = 90 мкс                           [затримка зросла у 9 разів]
```

3. При `ρ = 0.99` (99% завантаження замка):
```
W_q
= 0.99 / (100000 · (1 - 0.99))                 [підстановка ρ = 0.99 та μ = 100000]
= 0.99 / 1000                                  [обчислення знаменника: 100000 · 0.01 = 1000]
= 0.00099 с = 990 мкс                          [затримка зросла майже у 100 разів!]
```

### 3. Математичний поріг вигідності замків читачів-письменників (RW-Lock)

Поширеною інженерною оптимізацією є заміна ексклюзивного м'ютекса на замок читачів-письменників (Shared/Exclusive Lock, наприклад `std::shared_mutex`), що дозволяє кільком читачам одночасно перебувати в критичній секції.

Проте замок читачів-письменників має вищі внутрішні накладні витрати: кожне захоплення на читання вимагає виконання атомарної інструкції модифікації внутрішнього лічильника читачів (наприклад, `atomic_fetch_add`), що викликає переміщення кеш-лінії замка між процесорними ядрами.

Нехай:
- `C_m` — накладні витрати на одне захоплення/звільнення простого м'ютекса (тактові цикли).
- `C_rw` — накладні витрати на одне захоплення/звільнення RW-замка (`C_rw ≈ 2.5·C_m` через складнішу атомарну логіку).
- `R` — частка операцій читання серед усіх звернень до об'єкта (`0 ≤ R ≤ 1`).
- `W = 1 - R` — частка операцій запису.
- `T_crit` — середня тривалість корисної роботи всередині критичної секції.

Середня тривалість операції для простого м'ютекса за наявності `N` конкуруючих читачів:

```
T_mutex = C_m + T_crit
```

Для замка читачів-письменників читачі виконуються паралельно, але накладні витрати на читання становлять `C_rw`, а операції запису блокують усіх:

```
T_rwlock = R · (C_rw + T_crit / N) + (1 - R) · (C_rw + T_crit)
```

#### Знаходження порогу беззбитковості (Break-Even Threshold):
RW-замок забезпечує реальний виграш у пропускній здатності лише тоді, коли `T_rwlock < T_mutex`. Розв'яжемо нерівність відносно частки читань `R`:

```
R_min
= (C_rw - C_m) / (T_crit · (1 - 1/N))          [мінімальна частка читачів для окупності RW-замка]
```

Якщо тривалість критичної секції `T_crit` дуже мала (наприклад, 10–20 тактів на читання цілочисельного поля), знаменник стає меншим за різницю накладних витрат чисельника. У цьому випадку `R_min > 1`, що означає: **RW-замок буде повільнішим за звичайний м'ютекс за будь-якого співвідношення читачів і письменників!**

### 4. Універсальний закон масштабованості Гюнтера (USL)

Закон Амдала прогнозує, що зі зростанням кількості ядер продуктивність монотонно зростає до горизонтального плато `1/s`. На практиці ж при перевищенні певного порогу ядер загальна продуктивність системи починає **падати** (ретроградне масштабування).

Причиною цього є апаратна когерентність кешів (протоколи MESI/MOESI): ядра процесора змушені постійно передавати одна одній кеш-лінії спільних замків і даних через між'ядерну шину.

Ніл Гюнтер (Neil J. Gunther) розробив **Універсальний закон масштабованості (Universal Scalability Law, USL)**, який додає квадратичний член міжособових взаємодій:

```
C(N) = N / (1 + σ·(N - 1) + κ·N·(N - 1))
```

де:
- `C(N)` — відносна пропускна здатність (масштабованість системи відносно 1 ядра).
- `N` — кількість потоків або процесорних ядер.
- `σ` (sigma) — коефіцієнт конкуренції за послідовний ресурс (конкуренція замків, аналог `s` в законі Амдала).
- `κ` (kappa) — коефіцієнт затримок когерентності кешів та узгодження стану (квадратичний штраф зв'язку `O(N²)`).

#### Знаходження точки оптимуму (максимальної пропускної здатності):
Для знаходження кількості ядер `N_max`, за якої пропускна здатність досягає глобального максимуму, візьмемо похідну від функції `C(N)` за `N` і прирівняємо її до нуля:

```
N_max
= √((1 - σ) / κ)                               [екстремум функції масштабованості USL]
```

Якщо додати більше ядер, ніж `N_max`, продуктивність системи зменшиться через те, що витрати на між'ядерний трафік перевищать корисну паралельну роботу.

#### Числовий приклад 2: розрахунок піку продуктивності системи
Нехай для багатопотокового сервера із синхронізацією замками виміряно параметри:
- Коефіцієнт конкуренції замків `σ = 0.02` (2%).
- Коефіцієнт когерентності `κ = 0.0005` (0.05%).

Обчислимо оптимальну кількість ядер `N_max`:

```
N_max
= √((1 - 0.02) / 0.0005)                       [підстановка значень σ = 0.02 та κ = 0.0005]
= √(0.98 / 0.0005)                             [віднімання в чисельнику: 1 - 0.02 = 0.98]
= √1960                                        [ділення: 0.98 / 0.0005 = 1960]
≈ 44.27                                        [оптимальна точка: 44 процесорні ядра]
```

Обчислимо пікову пропускну здатність `C(44)`:

```
C(44)
= 44 / (1 + 0.02·43 + 0.0005·44·43)            [підстановка N = 44, N - 1 = 43]
= 44 / (1 + 0.86 + 0.946)                      [обчислення добутків: 0.02·43=0.86 та 0.0005·44·43=0.946]
= 44 / 2.806                                   [додавання в знаменнику: 1 + 0.86 + 0.946 = 2.806]
≈ 15.68                                        [пікове прискорення на 44 ядрах]
```

Якщо ж підключити 128 процесорних ядер:

```
C(128)
= 128 / (1 + 0.02·127 + 0.0005·128·127)        [підстановка N = 128, N - 1 = 127]
= 128 / (1 + 2.54 + 8.128)                     [обчислення добутків: 0.02·127=2.54 та 0.0005·128·127=8.128]
= 128 / 11.668                                 [додавання в знаменнику: 1 + 2.54 + 8.128 = 11.668]
≈ 10.97                                        [продуктивність впала на 30% від піку!]
```

### Інженерні висновки

Математичний аналіз доводить такі фундаментальні закономірності:
1. **Зменшення довжини критичної секції:** Скорочення тривалості утримання замка підвищує асимптотичну стелю системи згідно із законом Амдала.
2. **Усунення черг очікування:** Навіть ідеально оптимізовані замки під високим навантаженням створюють експоненційні затримки в черзі згідно з моделлю `M/M/1`.
3. **Обережність із RW-замками:** Застосування замків читачів-письменників виправдане лише за тривалих операцій читання (`T_crit >> C_rw`) та частки читань `R > 90%`.
4. **Уникнення спільних мутацій:** Спільний стан із синхронізацією породжує квадратичні втрати когерентності `O(N²)`, що неминуче призводить до спаду продуктивності на великих багатоядерних кластерах (закон Гюнтера).
5. **Архітектурний оптимум:** Єдиний спосіб досягти необмеженого лінійного масштабування — перехід до архітектур без спільного мутабельного стану: незмінності (Immutability), локальної пам'яті (TLS) та ізольованих акторів.
