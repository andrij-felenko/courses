# 📋 Порівняльна довідка потокобезпечних і реентрабельних функцій POSIX

Ця довідкова специфікація надає вичерпну матрицю сигнатур, вимог до буферів пам'яті та семантики безпеки застарілих однопотокових функцій стандартної бібліотеки C (libc) у порівнянні з їхніми сучасними реентрабельними та потокобезпечними аналогами стандарту POSIX.1-2008 / C11.

---

### 1. Синтаксичний аналіз рядків (String Tokenization)

Застаріла функція `strtok()` спирається на внутрішній статичний вказівник у бібліотеці, що робить її небезпечною для одночасного виклику з різних потоків або всередині вкладених циклів. Її сучасний двійник `strtok_r()` вимагає передачі адреси зовнішнього вказівника контексту, що виділяється викликачем на стеку.

```c
#include <string.h>

/* ЗАСТАРІЛА / ПОТОКОНЕБЕЗПЕЧНА (Unsafe / Non-reentrant) */
char *strtok(char *str, const char *delim);

/* РЕЕНТРАБЕЛЬНА ТА ПОТОКОБЕЗПЕЧНА (Reentrant & Thread-Safe) */
char *strtok_r(char *str, const char *delim, char **saveptr);
```

#### Параметри та контракт `strtok_r`:
- `str`: Вказівник на рядок, що розбирається (під час першого виклику), або `NULL` (під час наступних викликів для продовження розбору).
- `delim`: Рядок, що містить множину символів-роздільників.
- `saveptr`: Вказівник на змінну типу `char*`, яку викликач виділяє у власному стековому фреймі. Функція використовує її для збереження поточного положення між ітераціями.
- **Повертає:** Вказівник на початок знайденої лексеми або `NULL`, якщо лексем більше немає.
- **Особливість модифікації:** Обидві функції модифікують вхідний масив `str`, записуючи нуль-символ `\0` на місце знайденого роздільника. Якщо два потоки передадуть один і той самий рядок у `strtok_r()`, виникне гонка даних над вмістом рядка, попри використання різних змінних `saveptr`.

### 2. Календарний час і форматування дат (Time & Date Conversion)

Класичні функції перетворення секундного лічильника епохи Unix (`time_t`) повертають вказівники на статичні структури `struct tm` або статичні символьні масиви в сегменті даних бібліотеки. Потокобезпечні аналоги стандарту POSIX.1c вимагають, щоб викликач передав адресу структури або буфера фіксованого розміру.

```c
#include <time.h>

/* ЗАСТАРІЛІ ФУНКЦІЇ (Статичний буфер повернення) */
struct tm *gmtime(const time_t *timep);
struct tm *localtime(const time_t *timep);
char *asctime(const struct tm *tm);
char *ctime(const time_t *timep);

/* РЕЕНТРАБЕЛЬНІ ДВІЙНИКИ СТАНДАРТУ POSIX */
struct tm *gmtime_r(const time_t *timep, struct tm *result);
struct tm *localtime_r(const time_t *timep, struct tm *result);
char *asctime_r(const struct tm *tm, char *buf);
char *ctime_r(const time_t *timep, char *buf);
```

#### Вимоги до виділення пам'яті:
- Для `gmtime_r()` та `localtime_r()`: параметр `result` повинен вказувати на дійсну структуру `struct tm`, виділену викликачем на стеку або в купі.
- Для `asctime_r()` та `ctime_r()`: буфер `buf` повинен мати ємність щонайменше **26 байтів** (включно із символом кінця рядка `\0`). Передача меншого масиву призводить до невизначеної поведінки та пошкодження стека.
- **Повертають:** Вказівник на переданий буфер у разі успіху або `NULL` у разі помилки валідації діапазону значень.

### 3. Генерація псевдовипадкових чисел (Pseudorandom Number Generators)

Традиційний генератор `rand()` використовує глобальний прихований стан початкового числа (seed). Паралельний виклик кількома потоками призводить до гонки за стан генератора та викривлення статистичного розподілу випадкових чисел. Реентрабельний інтерфейс `rand_r()` приймає вказівник на локальний стан.

```c
#include <stdlib.h>

/* ЗАСТАРІЛА / НЕБЕЗПЕЧНА */
int rand(void);
void srand(unsigned int seed);

/* РЕЕНТРАБЕЛЬНИЙ АНАЛОГ POSIX */
int rand_r(unsigned int *seedp);
```

#### Семантика `rand_r`:
- `seedp`: Вказівник на ціле число без знаку, що зберігає поточний стан послідовності. Кожен потік може підтримувати власне незалежне значення `seed`, забезпечуючи повну детермінованість і повторюваність випадкових послідовностей. Для криптографічно стійких задач стандарт POSIX рекомендує використовувати виклик `getentropy()` або зчитування з `/dev/urandom`.

### 4. Текстовий опис системних помилок (System Error Messages)

Функція `strerror()` повертає вказівник на статичний символьний масив, вміст якого може перезаписуватися наступними викликами `strerror()` з інших потоків.

```c
#include <string.h>

/* ЗАСТАРІЛА ФУНКЦІЯ (Повертає статичний рядок) */
char *strerror(int errnum);

/* ВАРІАНТ 1: POSIX.1-2001 (XSI-Compliant) */
int strerror_r(int errnum, char *buf, size_t buflen);

/* ВАРІАНТ 2: GNU-Specific (glibc за наявності _GNU_SOURCE) */
char *strerror_r(int errnum, char *buf, size_t buflen);
```

#### Порівняння варіантів `strerror_r`:
- **XSI-версія (POSIX стандарт):** Завжди копіює текст повідомлення у буфер `buf` довжиною `buflen`. Повертає `0` у разі успіху або позитивне число помилки (наприклад, `ERANGE`, якщо буфер замалий, або `EINVAL`, якщо код помилки невідомий).
- **GNU-версія:** Може повернути вказівник безпосередньо на незмінний статичний рядок у таблиці констант бібліотеки (без копіювання), або записати повідомлення у `buf` і повернути адресу `buf`. У багатопотокових кросплатформних бібліотеках для коректного вибору сигнатури перевіряють макроси `(_POSIX_C_SOURCE >= 200112L) && !defined(_GNU_SOURCE)`.

### 5. Бази даних користувачів та груп (User and Group Databases)

Функції читання системних записів `/etc/passwd` та `/etc/group` у традиційному варіанті повертають вказівник на єдину внутрішню статичну структуру. Реентрабельні версії вимагають передачі як цільової структури, так і додаткового робочого буфера для збереження текстових полів (ім'я користувача, хеш пароля, повне ім'я, домашній каталог та оболонка).

```c
#include <sys/types.h>
#include <pwd.h>
#include <grp.h>

/* ЗАСТАРІЛІ ОДНОПОТОКОВІ ФУНКЦІЇ */
struct passwd *getpwnam(const char *name);
struct passwd *getpwuid(uid_t uid);
struct group  *getgrnam(const char *name);
struct group  *getgrgid(gid_t gid);

/* РЕЕНТРАБЕЛЬНІ АНАЛОГИ POSIX */
int getpwnam_r(const char *name, struct passwd *pwd,
               char *buf, size_t buflen, struct passwd **result);
int getpwuid_r(uid_t uid, struct passwd *pwd,
               char *buf, size_t buflen, struct passwd **result);
int getgrnam_r(const char *name, struct group *grp,
               char *buf, size_t buflen, struct group **result);
int getgrgid_r(gid_t gid, struct group *grp,
               char *buf, size_t buflen, struct group **result);
```

#### Контракт виклику та виділення пам'яті:
- Рекомендований початковий розмір робочого буфера `buflen` отримують через системний запит `sysconf(_SC_GETPW_R_SIZE_MAX)` (типово від 1024 до 4096 байтів). Якщо `sysconf` повертає `-1`, стандарт рекомендує виділяти 16 КіБ.
- Якщо переданий буфер замалий для збереження всіх рядків користувача, функція повертає код помилки `ERANGE`, що вимагає динамічного збільшення масиву (наприклад, подвоєння ємності через `realloc`) та повторного виклику.
- У разі успішного знаходження запису змінна `*result` вказує на `pwd`, а у разі відсутності такого користувача — приймає значення `NULL` при поверненні нульового коду помилки.

### 6. Мережеве перетворення адрес та імен (Network Name Resolution)

Історична функція `gethostbyname()` повертала вказівник на статичну структуру `struct hostent` і не підтримувала протокол IPv6. У сучасному стандарті POSIX.1-2001 її повністю замінено універсальним, потокобезпечним та реентрабельним інтерфейсом `getaddrinfo()`.

```c
#include <sys/types.h>
#include <sys/socket.h>
#include <netdb.h>

/* ЗАСТАРІЛА / ОГОЛОШЕНА НЕБЕЗПЕЧНОЮ (POSIX.1-2008 Deprecated) */
struct hostent *gethostbyname(const char *name);

/* СУЧАСНИЙ РЕЕНТРАБЕЛЬНИЙ ТА ПОТОКОБЕЗПЕЧНИЙ СТАНДАРТ */
int getaddrinfo(const char *node, const char *service,
                const struct addrinfo *hints,
                struct addrinfo **res);

void freeaddrinfo(struct addrinfo *res);

int getnameinfo(const struct sockaddr *addr, socklen_t addrlen,
                char *host, socklen_t hostlen,
                char *serv, socklen_t servlen, int flags);
```

#### Переваги та контракт `getaddrinfo`:
- **Потокова безпека:** Пам'ять для результату виділяється динамічно під час кожного виклику; функція не має побічних ефектів на глобальний стан.
- **Підтримка стеків протоколів:** Повна прозора підтримка адрес IPv4 та IPv6 через єдину абстракцію сокетних адрес `struct sockaddr`.
- **Очищення ресурсів:** Звільнення пам'яті виділеного зв'язаного списку адрес обов'язково здійснюється викликом `freeaddrinfo()`.

### 7. Читання каталогів файлової системи (Directory Streams)

Цікавий історичний випадок становить функція `readdir()`. Спочатку комітет POSIX запропонував реентрабельну версію `readdir_r()`. Проте згодом виявилося, що точне обчислення максимальної довжини імені файлу (`NAME_MAX`) у буфері є платформозалежним і схильним до помилок переповнення буфера через макрос `offsetof`.

У стандарті POSIX.1-2008 функцію `readdir_r()` було офіційно оголошено **застарілою (deprecated)**, а для базової функції `readdir()` було введено строгу специфікацію: вона зобов'язана бути потокобезпечною за умови, що різні потоки оперують різними дескрипторами каталогів `DIR*`.

```c
#include <dirent.h>

/* РЕКОМЕНДОВАНИЙ СТАНДАРТ POSIX.1-2008:
   Потокобезпечний для незалежних дескрипторів DIR* */
struct dirent *readdir(DIR *dirp);

/* ЗАСТАРІЛА ВЕРСІЯ (Не рекомендована до використання) */
int readdir_r(DIR *dirp, struct dirent *entry, struct dirent **result);
```

### 8. Потокове введення-виведення та явне блокування дескрипторів (I/O Locking)

Стандарт POSIX.1 вимагає, щоб усі стандартні операції введення-виведення над дескрипторами потоків `FILE*` (`printf`, `fprintf`, `fread`, `fwrite`, `fgetc`) були потокобезпечними за замовчуванням завдяки внутрішнім замкам дескриптора. Проте для високопродуктивних циклів читання посимвольного вводу блокування на кожен байт створює надмірні накладні витрати.

Для розв'язання цієї проблеми стандарт надає явні функції управління замками дескриптора та їхні швидкі неблокувальні варіанти:

```c
#include <stdio.h>

/* ЯВНЕ ЗАХОПЛЕННЯ ТА ЗВІЛЬНЕННЯ ВНУТРІШНЬОГО ЗАМКА ПОТОКУ */
void flockfile(FILE *filehandle);
int  ftrylockfile(FILE *filehandle);
void funlockfile(FILE *filehandle);

/* ШВИДКІ НЕБЛОКУВАЛЬНІ ОПЕРАЦІЇ (Викликаються лише всередині flockfile) */
int getc_unlocked(FILE *stream);
int getchar_unlocked(void);
int putc_unlocked(int c, FILE *stream);
int putchar_unlocked(int c);
```

#### Правило використання неблокувального I/O:
Виклики із суфіксом `_unlocked` є повністю потоконебезпечними самі по собі. Їх дозволено використовувати лише тоді, коли викликач попередньо захопив замок дескриптора через `flockfile(stream)` і гарантовано звільнить його через `funlockfile(stream)` після завершення циклу обробки.

### Зведена матриця відповідності інтерфейсів

| Категорія | Застарілий потоконебезпечний виклик | Сучасний реентрабельний аналог POSIX | Механізм ізоляції стану |
|---|---|---|---|
| **Рядки** | `strtok()` | `strtok_r()` | Вказівник контексту викликача (`char**`) |
| **Час (UTC)** | `gmtime()` | `gmtime_r()` | Структура `struct tm` на стеку |
| **Час (Локальний)** | `localtime()` | `localtime_r()` | Структура `struct tm` на стеку |
| **Форматування часу**| `asctime()`, `ctime()` | `asctime_r()`, `ctime_r()` | Буфер викликача (мін. 26 байтів) |
| **Випадкові числа** | `rand()` | `rand_r()` | Локальний лічильник зерна (`unsigned int*`) |
| **Помилки ОС** | `strerror()` | `strerror_r()` | Буфер символів викликача |
| **Облікові записи** | `getpwuid()`, `getpwnam()` | `getpwuid_r()`, `getpwnam_r()` | Структура та буфер рядків викликача |
| **Мережеві адреси** | `gethostbyname()` | `getaddrinfo()` | Динамічний зв'язаний список структур |
