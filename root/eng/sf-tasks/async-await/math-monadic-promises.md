# 🧮 Алгебра промісів: монада продовжень та автосплющення

Асинхронний обчислювальний конвеєр спирається на суворі математичні закономірності теорії категорій. Проміс є практичним інженерним втіленням **монади продовжень** (англ. *Continuation Monad*), яка перетворює композицію відкладених дій у часі на формальну алгебраїчну структуру над типами даних.

Розуміння алгебраїчної природи асинхронності дозволяє строго довести, чому ланцюжки операцій можна вільно перегруповувати, як гарантується збереження порядку обчислень та де саме прагматичні реалізації мов програмування свідомо відступають від чистої математики.

## Монадичні закони обчислювальних контейнерів

У теорії категорій монада над категорією типів складається з трьох компонентів:
1. **Конструктор типів** `M`, який зі звичайного типу `T` будує обчислювальний контекст `M[T]`. Для промісів цим контекстом є `Promise<T>` — значення типу `T`, загорнуте у часову невизначеність.
2. **Одинична функція (Unit / Return)** `η : T → M[T]`, яка переносить чисте значення у монадичний контекст без побічних ефектів. У JavaScript це `Promise.resolve(x)`.
3. **Операція зв'язування (Bind / FlatMap)** `>>= : M[T] × (T → M[U]) → M[U]`, яка витягує обчислене значення з першого контейнера, застосовує до нього функцію трансформації та повертає новий контейнер.

Для композиції функцій виду `f : A → M[B]` у теорії категорій використовується **стрілка Клейслі** (англ. *Kleisli arrow*), де оператор композиції `>=>` визначається через зв'язування:

```
(f >=> g)(x) = f(x) >>= g
```

Щоб структура утворювала валідну категорію Клейслі та повноцінну монаду, операції повинні задовольняти три фундаментальні закони для будь-яких функцій `f : T → M[U]` та `g : U → M[V]`:

### 1. Ліва одиниця (Left Identity)
Загортання значення в контейнер і негайне застосування операції зв'язування еквівалентне прямому виклику функції над цим значенням:

```
Promise.resolve(x).then(f)
= f(x)                      [застосування η не змінює семантики f]
```

Цей закон гарантує відсутність прихованих побічних ефектів при переході від чистого значення до асинхронного контейнера.

### 2. Права одиниця (Right Identity)
Застосування оператора зв'язування з функцією одиничного загортання над уже існуючим контейнером повертає вихідний контейнер без змін:

```
m.then(x => Promise.resolve(x))
= m                         [витягнення і повторне загортання є тотожністю]
```

Цей закон гарантує, що розпакування та повторне запакування значення не спотворює стан самого проміса.

### 3. Асоціативність (Associativity)
Послідовне застосування двох трансформацій у ланцюжку не залежить від того, як саме згруповані дужки обчислення:

```
(m.then(f)).then(g)
= m.then(x => f(x).then(g)) [порядок композиції обчислень збережено]
```

Завдяки асоціативності розробник може будувати конвеєри довільної довжини у плоскому стилі, не турбуючись про внутрішнє деревоподібне групування підзадач.

## Монада продовжень (Continuation Monad)

Формально проміс моделюється як функтор продовження. Нехай `R` — множина можливих кінцевих результатів обчислення всієї програми. Тоді тип обчислення, що повертає `A`, задається функцією вищого порядку:

```
Cont[R, A] = (A → R) → R
```

Конструктор приймає функцію продовження `k : A → R` («що робити далі») і повертає кінцевий результат `R`.

Операції функтора та монади над продовженнями мають строгий вигляд:

1. **Функторний map**:
```
fmap(h, m) = λk. m(λa. k(h(a)))
```
Функція `h : A → B` трансформує проміжне значення `a` перед тим, як віддати його продовженню `k`.

2. **Монадичний bind**:
```
bind(m, f) = λk. m(λa. f(a)(k))
```
Контейнер `m` видобуває значення `a`, передає його у функцію `f : A → Cont[R, B]`, яка повертає новий контейнер продовжень, що врешті викликає підсумкове продовження `k`.

Проміс відрізняється від класичної чистої монади продовжень тим, що він є **жадібним (eager)** і **мемоізованим**: виклик асинхронної дії починається негайно в момент створення об'єкта, а отриманий результат кешується в полях автомата станів, щоб роздаватися всім наступним підписникам без повторного запуску операції.

## Автосплющення: чому Promise у JavaScript є псевдомонадою

У класичних типізованих функційних мовах (Haskell, Scala, PureScript) операції відображення значення розділені строго за типами:
- **Функторний `map`**: `(T → U) → (M[T] → M[U])`. Якщо передати функцію `f : T → M[U]`, типізатор збереже структуру й поверне вкладений контейнер `M[M[U]]`.
- **Монадичний `flatMap / bind`**: `(T → M[U]) → (M[T] → M[U])`. Вимагає повернення саме контейнера і запобігає появі зайвої вкладеності.

Специфікація JavaScript Promises/A+ свідомо відійшла від цієї математичної строгості задля ергономіки імперативних інженерів. Метод `.then(f)` поєднує в собі обидві операції динамічно за правилом розгортання промісів (англ. *Promise Resolution Procedure*):

Якщо результат виклику `y = f(x)` є об'єктом із методом `then` (так званий *Thenable*), рушій рекурсивно розпаковує його доти, доки не отримає базове значення:

```
Promise.resolve(Promise.resolve(42))
= Promise.resolve(42)       [рекурсивне сплющення Promise<Promise<T>> → Promise<T>]
= 42 у термінах результату
```

Через це вкладений тип `Promise<Promise<T>>` у мові JavaScript принципово неможливо створити: тип не є чистою категоріальною монадою, оскільки конструктор не комутує вільно сам із собою, а автоматично колапсує шари. Це порушує параметричний поліморфізм, але усуває цілий клас помилок, пов'язаних із випадковим створенням «промісів над промісами».

## Формальний аналіз: стиль передачі продовжень (CPS)

Прямий стиль обчислень спирається на неявний стек процесора:

```
f : A → B
res = f(arg)                [повернення значення через регістр процесора]
```

У неблокуючій системі після виклику `f` стек розмотується до циклу подій. Щоб обчислення не втратило мету, його переводять у **стиль передачі продовжень** (англ. *Continuation-Passing Style*, скорочено CPS). Продовження (continuation) — це функція `k`, яка описує «все, що програма має зробити з результатом далі».

Математична сигнатура CPS-перетворення над функцією `f : A → B`:

```
f_cps : A × (B → ⊥) → ⊥
```

де `⊥` позначає завершення гілки обчислення (вихід у цикл подій або передачу керування диспетчеру).

Розглянемо послідовне виконання трьох кроків `A → B → C → D`:

У синхронній формі композиція функцій задається математичним добутком операторів:

```
result = h(g(f(x)))
```

У CPS-формі кожна функція приймає свій аргумент та наступний крок:

```
f_cps(x, (res_f) =>
  g_cps(res_f, (res_g) =>
    h_cps(res_g, (res_h) =>
      complete(res_h)
    )
  )
)
```

Ця формула математично доводить, чому виникає «піраміда вкладень» (Callback Hell): кожен наступний оператор композиції синтаксично стає аргументом попереднього, заглиблюючи рівень вкладеності коду на `O(N)`, де `N` — кількість послідовних кроків.

Проміс трансформує вкладення CPS у лінійну композицію монадних продовжень:

```
Promise.resolve(x)
  .then(f)                  [крок 1: A → Promise<B>]
  .then(g)                  [крок 2: B → Promise<C>]
  .then(h)                  [крок 3: C → Promise<D>]
```

Вкладеність глибини `N` перетворюється на асоціативний ланцюг довжини `N` з фіксованою глибиною коду `O(1)`.

## Розщеплення продовжень: алгебра помилок

Звичайна функція має один вихід (значення). Асинхронна дія є дуальною: вона завершується або значенням `T`, або винятком `E`. Монада промісів формалізує це як біпродовження (англ. *bi-continuation*):

```
Promise[T, E] ≅ ( (T → ⊥) × (E → ⊥) ) → ⊥
```

Конструкція містить два незалежні канали передачі сигналів:
1. **Канал успіху (Resolved)**: якщо кожен `f_i` завершується коректно, дані йдуть за ланцюжком `onFulfilled`.
2. **Канал збою (Rejected)**: якщо будь-яка ланка породжує виняток `e ∈ E`, виконання каналу успіху негайно припиняється, а значення помилки транслюється вниз за ланцюгом до першого обробника `onRejected` (`.catch()`).

Формальний закон спливання помилки у бімонадній структурі:

```
m_rejected(err).then(f, g)
= g(err)                    [якщо g визначено]
= m_rejected(err)           [якщо g пропущено: нейтральний пропуск ланки]
```

Це забезпечує повну еквівалентність математичної семантики розмотування стеку винятків (англ. *exception bubbling*) у системі, де фізичного стеку викликів уже не існує.
