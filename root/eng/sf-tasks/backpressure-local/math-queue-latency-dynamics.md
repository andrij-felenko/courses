# 🧮 Математика черг, затримок та динаміки водяних знаків

Коли між двома компонентами локальної системи виникає розрив продуктивності, стан буфера визначається співвідношенням двох величин: інтенсивності вхідного потоку `\lambda` (елементів за секунду) та пропускної здатності споживача `\mu` (елементів за секунду). Без регулювання зворотного тиску будь-яке тимчасове чи постійне перевищення `\lambda > \mu` неминуче призводить до монотонного накопичення елементів у пам'яті. За законом Літтла це накопичення миттєво перетворює доданий обсяг черги на лінійне зростання затримки обробки (bufferbloat), погіршуючи якість сервісу системи в сотні разів.

### Динамічний баланс черги та час до вичерпання пам'яті

Нехай `Q(t)` — кількість елементів, які перебувають у буфері в момент часу `t`. Швидкість зміни довжини черги задається диференціальним рівнянням балансу:

```
dQ(t) / dt = \lambda(t) - \mu(t)
```

Якщо інтенсивності надходження та обробки є сталими, довжина черги в момент часу `t` визначається інтегралом:

```
Q(t)
= Q(0) + \int₀ᵗ (\lambda - \mu) d\tau     [інтегрування різниці швидкостей]
= Q(0) + (\lambda - \mu) · t              [при сталих швидкостях \lambda та \mu]
```

Розглянемо випадок, коли виробник генерує дані зі швидкістю `\lambda = 100 000` повідомлень/с, а споживач опрацьовує їх зі швидкістю `\mu = 20 000` повідомлень/с. Нехай кожне повідомлення разом із дескриптором займає в оперативній пам'яті `S = 256` байтів, початковий стан черги `Q(0) = 0`, а вільний обсяг доступної оперативної пам'яті процесу становить `M_{free} = 1` ГБ (`1 073 741 824` байти).

Кількість повідомлень, яка спричинить вичерпання всієї пам'яті (Out Of Memory):

```
Q_{max} = M_{free} / S
= 1 073 741 824 / 256                    [ділення пам'яті на розмір елемента]
= 4 194 304 повідомлення
```

Час `t_{OOM}`, за який процес повністю вичерпає оперативну пам'ять і буде знищений операційною системою:

```
t_{OOM}
= Q_{max} / (\lambda - \mu)              [час заповнення граничного обсягу]
= 4 194 304 / (100 000 - 20 000)         [підстановка числових значень]
= 4 194 304 / 80 000                     [швидкість накопичення елементів]
≈ 52.43 секунди
```

Менше ніж за одну хвилину неконтрольоване джерело призводить до аварійної зупинки застосунку.

### Закон Літтла та ефект роздуття буфера (Bufferbloat)

Фундаментальна теорема теорії масового обслуговування — **закон Літтла** (Джон Літтл, 1961) — стверджує, що середня кількість заявок у стаціонарній системі `L` дорівнює добутку середньої інтенсивності вхідного потоку `\lambda` на середній час перебування заявки в системі `W`:

```
L = \lambda · W
```

У стані насичення буфера, коли система працює на граничній пропускній здатності `\mu`, середня затримка очікування елемента в черзі `W_{queue}` визначається її ємністю `Q`:

```
W_{queue} = Q / \mu
```

Порівняємо дві конфігурації черги при пропускній здатності споживача `\mu = 1 000` запитів/с:

1. **Необмежена (або надмірно велика) черга `Q₁ = 50 000` елементів:**
```
W₁
= 50 000 / 1 000                         [закон Літтла для великого буфера]
= 50 секунд
```
Користувач, чий запит потрапив у кінець черги, чекає відповіді майже хвилину. Для більшості клієнтських HTTP/RPC з'єднань цей час перевищує типовий тайм-аут (3–5 с), тому клієнт розриває з'єднання, а сервер продовжує марно витрачати ресурси CPU на обробку «мертвих» запитів.

2. **Обмежена черга з протитиском `Q₂ = 100` елементів:**
```
W₂
= 100 / 1 000                            [закон Літтла для малого буфера]
= 0.1 секунди (100 мілісекунд)
```
Завдяки протитиску затримка системи гарантовано не перевищує 100 мс. Протитиск не знижує сумарну продуктивність системи, а виключає накопичення застарілих даних.

### Гістерезис водяних знаків: частота перемикань та стабільність

Найпростіший спосіб реалізації протитиску — використання одного порогу `N_{thresh}`: якщо `Q(t) \ge N_{thresh}`, виробник блокується; тільки-но `Q(t) < N_{thresh}`, виробник одразу прокидається.

Проаналізуємо поведінку системи з одним порогом `N_{thresh} = 1 000`. Нехай черга заповнена до 1 000 елементів:
1. Виробник намагається записати 1 001-й елемент і блокується.
2. Споживач вилучає 1 елемент: `Q = 999`.
3. Виробник негайно розблоковується планувальником ОС, записує 1 елемент: `Q = 1 000` і знову блокується.

Час, за який черга зменшується на 1 елемент:

```
t_{drain} = 1 / \mu
```

Час, за який черга збільшується на 1 елемент:

```
t_{fill} = 1 / (\lambda - \mu)
```

Період повного циклу автоколивань одного порогу `T_{single}`:

```
T_{single}
= t_{fill} + t_{drain}                   [тривалість одного циклу блокування]
= 1 / (\lambda - \mu) + 1 / \mu          [підстановка елементарних часів]
= \lambda / (\mu · (\lambda - \mu))      [зведення дробів до спільного знаменника]
```

Частота перемикань контексту `f_{single}`:

```
f_{single}
= 1 / T_{single}                         [обернена величина до періоду]
= (\mu · (\lambda - \mu)) / \lambda      [частота коливань з одним порогом]
```

Обчислимо частоту для `\lambda = 60 000` оп/с та `\mu = 40 000` оп/с:

```
f_{single}
= (40 000 · (60 000 - 40 000)) / 60 000  [підстановка швидкостей]
= (40 000 · 20 000) / 60 000             [обчислення добутку]
= 800 000 000 / 60 000                   [ділення]
≈ 13 333 Гц (13.33 тисячі перемикань на секунду)
```

Система витрачає до 40% загальної потужності ядер процесора виключно на безперервне перемикання контексту ядра (context switch overhead, 1–3 мкс на операцію) та інвалідацію кеш-ліній (cache thrashing).

#### Введення гістерезису: два водяні знаки (HWM та LWM)

Для усунення деренчання вводять два пороги:
- **Верхній водяний знак (High Watermark, HWM):** рівень, при досягненні якого виробник призупиняється.
- **Нижній водяний знак (Low Watermark, LWM):** рівень, до якого черга повинна спорожніти, перш ніж виробник отримає дозвіл продовжити роботу.

Ширина зони гістерезису:

```
\Delta H = HWM - LWM
```

Розрахуємо тривалість фаз у системі з гістерезисом:

1. **Фаза наповнення (від LWM до HWM):** Виробник і споживач працюють одночасно. За час `t_{fill}` у чергу додається `\Delta H` елементів:
```
t_{fill} = \Delta H / (\lambda - \mu)
```

2. **Фаза дренажу (від HWM до LWM):** Виробник спить. Працює лише споживач, який вилучає `\Delta H` елементів:
```
t_{drain} = \Delta H / \mu
```

Сумарний період циклу перемикання з гістерезисом `T_{hyst}`:

```
T_{hyst}
= t_{fill} + t_{drain}                   [загальний час фази наповнення і дренажу]
= \Delta H / (\lambda - \mu) + \Delta H / \mu  [підстановка формул фаз]
= \Delta H · (1 / (\lambda - \mu) + 1 / \mu)   [винесення \Delta H за дужки]
= \Delta H · T_{single}                  [зв'язок із періодом однопорогової системи]
```

Частота перемикань з гістерезисом `f_{hyst}`:

```
f_{hyst}
= 1 / T_{hyst}                           [обернена величина]
= 1 / (\Delta H · T_{single})            [підстановка зв'язку періодів]
= f_{single} / \Delta H                  [зменшення частоти рівно в \Delta H разів]
```

Якщо встановити ємність буфера `N = 1 000`, `HWM = 800` (80%), `LWM = 300` (30%), ширина гістерезису становитиме:

```
\Delta H = 800 - 300 = 500 елементів
```

Нова частота перемикань контексту:

```
f_{hyst}
= 13 333 / 500                           [ділення на ширину зони гістерезису]
≈ 26.66 Гц
```

Частота системних перемикань падає з 13 333 Гц до всього 26.6 Гц — у 500 разів. Процесор переходить від постійних блокувань до пакетної обробки даних великими порціями, що максимізує ефективність кешу команд та даних (L1/L2 data cache locality).

### Оптимальний вибір розміру буфера: локальний добуток затримки на смугу

У розподілених мережах розмір буфера розраховується за формулою добутку затримки на смугу (Bandwidth-Delay Product, BDP). Для локальних багатопотокових систем діє той самий принцип:

```
BDP_{local} = \mu · RTT_{switch}
```

де `RTT_{switch}` — час кругової затримки між моментом, коли споживач надіслав сигнал пробудження, і моментом, коли потік-виробник фізично прокинувся на ядрі CPU і записав першу порцію байтів (типово 5–25 мікросекунд для потоків POSIX у Linux).

Щоб споживач не простоював під час пробудження виробника, нижній водяний знак `LWM` повинен задовольняти нерівність:

```
LWM \ge \mu · RTT_{switch}
```

Якщо `\mu = 500 000` елементів/с, а `RTT_{switch} = 20` мкс (`0.00002` с):

```
LWM_{min}
= 500 000 · 0.00002                      [добуток швидкості на час перемикання]
= 10 елементів
```

Встановлення `LWM = 128` та `HWM = 512` при ємності кільцевого буфера `N = 1024` гарантує 100% утилізацію обчислювальної потужності споживача при мінімально можливій затримці черги.
