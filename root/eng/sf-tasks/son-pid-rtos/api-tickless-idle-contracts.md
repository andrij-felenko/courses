# 📋 Інтерфейси та системні контракти енергозбереження й Idle Task у FreeRTOS

Управління енергоспоживанням та робота фонової задачі в операційній системі реального часу FreeRTOS спираються на суворий набір конфігураційних макросів, системних хуків і ядерних функцій синхронізації часу. Неправильне використання контексту виклику (наприклад, звернення до блокуючих API всередині `vApplicationIdleHook` або відсутність атомарного маскування переривань у `vPortSuppressTicksAndSleep`) призводить до взаємних блокувань планувальника, розсинхронізації системної шкали та непередбачуваного споживання струму. Цей довідник визначає точні сигнатури, системні контракти, гарантії атомарності та вимоги до безпеки пам'яті для всіх елементів підсистеми керування живленням і задачі простою.

---

### 1. Конфігураційні макроси `FreeRTOSConfig.h`

Керування поведінкою задачі Idle Task та безтикового режиму здійснюється на етапі компіляції ядра.

| Макрос | Тип / Значення | Призначення та поведінка планувальника |
|---|---|---|
| `configUSE_TICKLESS_IDLE` | `0` | **Вимкнено.** Системний таймер SysTick генерує безперервні періодичні переривання з частотою `configTICK_RATE_HZ`. При відсутності готових задач ядро просто виконує `__WFI()`. |
| `configUSE_TICKLESS_IDLE` | `1` | **Стандартний безтиковий режим ARM Cortex-M.** Ядро зупиняє або перепрограмовує вбудований SysTick на інтервал простою. Дозволяє занурюватися лише в неглибокий сон Sleep, оскільки SysTick зупиняється в глибоких режимах Stop через вимкнення HCLK. |
| `configUSE_TICKLESS_IDLE` | `2` | **Користувацький безтиковий режим.** Планувальник передає керування користувацькій функції `vPortSuppressTicksAndSleep()` або `vApplicationSleep()`, дозволяючи використовувати низькоспоживаючий таймер LPTIM/RTC та режими глибокого сну Stop 1/2. |
| `configEXPECTED_IDLE_TIME_BEFORE_SLEEP` | `TickType_t` (за замовчуванням `2`) | Мінімальна кількість системних тактів простою, необхідна для активації безтикового режиму. Якщо час до найближчого дедлайну менший за цей поріг, система не зупиняє генератор тиків, уникаючи енергетичних втрат на перехідні процеси. |
| `configUSE_IDLE_HOOK` | `0` або `1` | Дозвіл компіляції виклику користувацької функції зворотного виклику `vApplicationIdleHook()`. |
| `configIDLE_SHOULD_YIELD` | `0` або `1` | Якщо встановлено в `1`, задача Idle Task негайно передає залишок свого кванту часу (`taskYIELD()`), якщо в системі є користувацькі задачі з однаковим пріоритетом `tskIDLE_PRIORITY` (0). |

### 2. Системний хук фонової задачі: `vApplicationIdleHook`

Хук простою викликається на кожній ітерації нескінченного циклу фонової задачі `prvIdleTask`, коли в системі немає готових до виконання задач вищого пріоритету.

```c
void vApplicationIdleHook(void);
```

#### Контракт виконання та обмеження
- **Контекст виклику:** Режим задачі (Thread Mode), стек задачі Idle Task (`configMINIMAL_STACK_SIZE`), пріоритет `tskIDLE_PRIORITY` (0).
- **Блокуючі виклики:** **СУВОРО ЗАБОРОНЕНО.** Будь-який виклик функцій з ненульовим таймаутом (`vTaskDelay()`, `xQueueReceive(..., portMAX_DELAY)`, `xSemaphoreTake(..., timeout)`) переводить Idle Task у стан Blocked, що порушує фундаментальний інваріант RTOS (CPU залишається без активної задачі) і викликає падіння системи через Kernel Panic або Assert.
- **Обов'язки очищення:** Якщо хук містить тривалі обчислення, він повинен періодично повертати керування, щоб `prvIdleTask` могла викликати `prvCheckTasksWaitingTermination()` для звільнення динамічної пам'яті самовидалених задач.
- **Дозволені дії:** Скидання апаратного сторожового таймера (Watchdog), розрахунок статистики завантаження центрального процесора, фонова перевірка контрольних сум Flash-пам'яті (CRC), вичитування накопичених логів.

### 3. Функція зупинки та відновлення тактів: `vPortSuppressTicksAndSleep`

Головна точка входу для користувацької реалізації безтикового режиму (`configUSE_TICKLESS_IDLE == 2`).

```c
void vPortSuppressTicksAndSleep(TickType_t xExpectedIdleTime);
```

#### Параметри
- `xExpectedIdleTime` (`TickType_t`): Розрахований планувальником інтервал простою в системних тактах до моменту розблокування найближчої заблокованої задачі.

#### Протокол реалізації (Обов'язкова послідовність дій)
1. **Зупинка SysTick:** Скидання біта `SysTick_CTRL_ENABLE_Msk` у регістрі `SysTick->CTRL`.
2. **Перерахунок тактів:** Обчислення необхідної кількості імпульсів низькочастотного таймера (LPTIM) з урахуванням апаратного подільника та поправки на затримку розгону генераторів (Wakeup Compensation).
3. **Вхід у критичну секцію ядра:** Виклик `__disable_irq()` (або встановлення `BASEPRI`), виконання бар'єрів пам'яті `__DSB()` та `__ISB()`.
4. **Підтвердження стану сну:** Виклик `eTaskConfirmSleepModeStatus()`. Якщо повернено `eAbortSleep`, перехід у сон негайно скасовується.
5. **Запуск LPTIM:** Запис періоду в регістр `LPTIM_ARR`, очищення прапорців переривань, старт в однократному режимі (Single Mode).
6. **Налаштування режиму живлення:** Встановлення біта `SLEEPDEEP` у регістрі `SCB->SCR` та вибір режиму Stop 1/2 у підсистемі `PWR`.
7. **Вхід у сон:** Виконання інструкції `__WFI()`.
8. **Пробудження та відновлення тактування:** Скидання біта `SLEEPDEEP`, повторний запуск та стабілізація високочастотних генераторів (HSI/HSE/PLL).
9. **Визначення фактичного часу сну:** Зчитування лічильника `LPTIM_CNT` (з урахуванням подвійної вибірки для подолання асинхронності тактових доменів).
10. **Компенсація часу ядра:** Виклик `vTaskStepTick(xCompletedTicks)`.
11. **Перезапуск SysTick:** Очищення поточного значення `SysTick->VAL = 0` та повторна активація біта генерації переривань.
12. **Відкриття переривань:** Виклик `__enable_irq()`, що дозволяє контролеру NVIC негайно викликати обробники пробуджуючих подій.

### 4. Допоміжні макроси обробки сну: `configPRE_SLEEP_PROCESSING` та `configPOST_SLEEP_PROCESSING`

Застосовуються у стандартному безтиковому режимі (`configUSE_TICKLESS_IDLE == 1`) або як додаткові хуки підсистеми Power Management.

```c
configPRE_SLEEP_PROCESSING(xModifiableIdleTime);
configPOST_SLEEP_PROCESSING(xExpectedIdleTime);
```

| Елемент | Контекст | Призначення |
|---|---|---|
| `configPRE_SLEEP_PROCESSING(xModifiableIdleTime)` | Викликається всередині критичної секції безпосередньо перед виконанням інструкції `__WFI()`. | Дозволяє користувачеві вимкнути тактування периферійних модулів (GPIO, UART, ADC), налаштувати піни у високий імпеданс або зменшити `xModifiableIdleTime` до 0 для примусового скасування засинання. |
| `configPOST_SLEEP_PROCESSING(xExpectedIdleTime)` | Викликається одразу після виходу ядра з режиму `__WFI()` до відновлення переривань. | Дозволяє увімкнути живлення периферії, відновити конфігурацію виводів I/O та стабілізувати аналогові модулі перед виконанням прикладного коду. |

### 5. Функція перевірки готовності планувальника: `eTaskConfirmSleepModeStatus`

Дозволяє уникнути стану перегонів (Race Condition), коли асинхронна подія розблокувала задачу між моментом розрахунку часу сну та моментом зупинки процесора.

```c
eSleepModeStatus eTaskConfirmSleepModeStatus(void);
```

#### Можливі значення повернення (`eSleepModeStatus`)

| Статус | Значення | Необхідна дія хука сну |
|---|---|---|
| `eAbortSleep` | `0` | **Сон скасовано.** Під час підготовки до сну виникло переривання або задача перейшла у стан Ready. Хук зобов'язаний негайно перезапустити SysTick, відкрити переривання й вийти без переходу в Stop/WFI. |
| `eStandardSleep` | `1` | **Дозволено звичайний сон.** У системі є заблоковані задачі з кінцевим таймаутом; сон триватиме до спрацьовування таймера LPTIM або зовнішнього переривання. |
| `eNoTasksWaitingTimeout` | `2` | **Нескінченний сон.** Жодна задача не очікує на таймаут (всі задачі заблоковані на невизначений термін `portMAX_DELAY` або призупинені). Таймер сну можна не запускати; пробудження відбудеться виключно за зовнішньою подією (EXTI). |

### 6. Функція кроку системного часу: `vTaskStepTick`

Оновлює внутрішній монотонний лічильник `xTickCount` та здійснює перерахунок черг очікування після тривалого безтикового сну.

```c
void vTaskStepTick(TickType_t xTicksToJump);
```

#### Контракт виконання
- **Контекст:** Обов'язково викликається **всередині критичної секції** (`portDISABLE_INTERRUPTS()` / `__disable_irq()`), коли генератор SysTick зупинено.
- **Аргумент `xTicksToJump`:** Кількість повних системних тактів, які система фактично провела в режимі низького споживання. Якщо `xTicksToJump` перевищує розрахований час до найближчого дедлайну, значення обмежується ядром.
- **Поведінка ядра:**
  1. `xTickCount` збільшується на значення `xTicksToJump`.
  2. Якщо нове значення `xTickCount` досягло або перевищило `xNextTaskUnblockTime`, планувальник вилучає готові задачі зі списку `pxDelayedTaskList` і переносить їх до списків `pxReadyTasksLists`.
  3. Якщо розблокована задача має пріоритет, вищий за поточну активну, планувальник виставляє прапорець перемикання контексту через переривання PendSV.

### 7. Внутрішні контракти диспетчеризації та очищення ресурсів

Робота підсистеми низького енергоспоживання тісно пов'язана з внутрішніми механізмами планувальника, які гарантують безпеку пам'яті та коректність переходу між станами.

#### Механізм очищення пам'яті `prvCheckTasksWaitingTermination`
Коли будь-яка задача виконує самовидалення через `vTaskDelete(NULL)`, її дескриптор додається до системного списку `xTasksWaitingTermination`. Задача простою `prvIdleTask` під час кожної ітерації викликає функцію:

```c
static void prvCheckTasksWaitingTermination(void);
```

- **Призначення:** Вилучення блоків `TCB_t` та масивів стеків зі списку термінації та виклик `vPortFree()` для кожного з них.
- **Вимога до планування:** Якщо високорівневі задачі споживають 100% часу процесора, ця функція не виконується, що призводить до прогресуючого виснаження динамічної пам'яті (Memory Leak).
- **Гарантія безпеки:** Звільнення виконується в контексті стеку `prvIdleTask`, що виключає ризик пошкодження стекової пам'яті потоку, який видаляється.

#### Механізм захисту планувальника `vTaskSuspendAll` та `xTaskResumeAll`
Перед викликом `portSUPPRESS_TICKS_AND_SLEEP()` ядро призупиняє планувальник викликом `vTaskSuspendAll()`. Це запобігає перемиканню контексту під час розрахунку часових інтервалів:
- Будь-які переривання, які спрацьовують у проміжку до повного маскування, успішно виконуються.
- Якщо переривання розблокувало нову задачу, вона поміщається у тимчасовий список `xPendingReadyList`.
- Після пробудження ядра та виклику `xTaskResumeAll()` планувальник обробляє накопичені задачі з `xPendingReadyList` та виконує негайне витіснення контексту за пріоритетом.

### 8. Матриця контекстів та гарантій безпеки

Зведена таблиця правил виклику функцій підсистеми живлення та фонової задачі:

| Функція / Макрос | Контекст виклику | Рівень переривань | Дозволені блокуючі API | Безпека виклику з ISR |
|---|---|---|---|---|
| `vApplicationIdleHook` | Задача (Idle Task) | Переривання дозволені | **Ні (0 таймаут)** | Ні |
| `vPortSuppressTicksAndSleep` | Задача (Idle Task) | Переривання замасковані | **Ні** | Ні |
| `eTaskConfirmSleepModeStatus` | Критична секція | Переривання замасковані | **Ні** | Ні |
| `vTaskStepTick` | Критична секція | Переривання замасковані | **Ні** | Ні |
| `configPRE_SLEEP_PROCESSING` | Критична секція | Переривання замасковані | **Ні** | Ні |
| `configPOST_SLEEP_PROCESSING` | Критична секція | Переривання замасковані | **Ні** | Ні |

### 9. Інтеграція з діагностичними інструментами та трасуванням

Для профілювання тривалості сну та енергоспоживання у FreeRTOS інтегровані макроси трасування (Trace Hooks), сумісні з аналізаторами Segger SystemView та Percepio Tracealyzer:

| Макрос трасування | Момент спрацьовування | Дані для енергетичного аудиту |
|---|---|---|
| `traceLOW_POWER_IDLE_BEGIN(xExpectedIdleTime)` | Безпосередньо перед зупинкою генератора SysTick та входом у сон. | Фіксує плановий інтервал сну `xExpectedIdleTime` та позначає початок фази низького енергоспоживання на часовій діаграмі. |
| `traceLOW_POWER_IDLE_END()` | Одразу після відновлення частоти тактування HCLK та виконання кроку `vTaskStepTick`. | Дозволяє розрахувати реальну тривалість перебування в режимі Stop та оцінити співвідношення між плановими та асинхронними пробудженнями. |
| `traceTASK_SWITCHED_IN()` | Момент завантаження контексту `prvIdleTask`. | Позначає перехід системи у фоновий стан, сигналізуючи про відсутність активної роботи в прикладних потоках. |
