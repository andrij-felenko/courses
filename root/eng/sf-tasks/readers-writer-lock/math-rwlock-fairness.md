# 🧮 Імовірнісна модель голодування та ціна когерентності кешу

Математичний аналіз замка читачів-письменника дозволяє кількісно розрахувати дві фундаментальні характеристики: імовірність голодування письменника за пріоритету читачів та апаратні витрати процесора на підтримку когерентності кешів при паралельних зверненнях на багатьох ядрах.

### 1. Модель Пуассона та ймовірність вільного ресурсу

Розгляньмо систему, в якій запити на читання надходять за законом Пуассона з інтенсивністю λ_r (запитів за секунду), а тривалість перебування читача в критичній секції розподілена експоненційно з середнім часом 1 / μ_r (де μ_r — інтенсивність обслуговування).

Оскільки читачі не блокують один одного і працюють повністю паралельно, потік читачів усередині замка поводиться як класична система масового обслуговування M/M/∞ (нескінченна кількість паралельних обслуговуючих приладів).

Стаціонарний розподіл кількості одночасних читачів N_r у системі підпорядковується закону Пуассона з параметром навантаження:

```text
ρ = λ_r / μ_r    [безрозмірний коефіцієнт навантаження черги]
```

Імовірність того, що в довільний момент часу t у критичній секції перебуває рівно k читачів, визначається формулою:

```text
P(N_r = k) = (ρ^k / k!) · e^(-ρ)    [стаціонарний розподіл кількості читачів]
```

Для того щоб письменник зміг захопити замок за політики пріоритету читачів (Reader-preference), лічильник читачів повинен впасти до нуля (N_r = 0). Імовірність цього стану дорівнює:

```text
P(N_r = 0) = e^(-ρ)            [ймовірність відсутності активних читачів]
           = e^(-λ_r / μ_r)    [вираз через інтенсивності потоку та обслуговування]
```

#### Розрахунок затухання ймовірності

Розгляньмо поведінку системи при різних значеннях безрозмірного навантаження ρ:
- Якщо навантаження ρ = 0.5 (середня тривалість читання вдвічі менша за інтервал між запитами):  
  ймовірність вільного стану P(N_r = 0) = e^(-0.5) ≈ 0.6065 (тобто 60.7% часу ресурс вільний для запису).
- Якщо навантаження ρ = 2.0 (читання триває вдвічі довше за інтервал надходження):  
  ймовірність вільного стану P(N_r = 0) = e^(-2.0) ≈ 0.1353 (лише 13.5% часу).
- Якщо навантаження ρ = 5.0 (інтенсивний паралельний потік читання):  
  ймовірність вільного стану P(N_r = 0) = e^(-5.0) ≈ 0.0067 (лише 0.67% часу).
- Якщо навантаження ρ = 10.0 (високонавантажений сервіс, 10 паралельних читань у середньому):  
  ймовірність вільного стану P(N_r = 0) = e^(-10.0) ≈ 0.000045 (менше 0.005% часу).

При ρ ≥ 5 імовірність застати ресурс вільним експоненційно спадає до нуля. Оскільки нові читачі підключаються до ресурсу швидше, ніж звільняються попередні, часові проміжки між виходами окремих читачів перекриваються неперервним ланцюгом.

### 2. Математичне сподівання часу очікування письменника

За пріоритету читачів середній час очікування письменника E[W_w] до першого моменту повного звільнення ресурсу описується теорією періодів зайнятості для системи M/M/∞:

```text
E[W_w] = (e^ρ − 1) / λ_r    [теоретичний час очікування до повного спорожнення черги]
```

Коли навантаження ρ < 1, експоненту можна розкласти в ряд Тейлора: e^ρ − 1 ≈ ρ = λ_r / μ_r, звідки отримуємо лінійне наближення:

```text
E[W_w] = (e^ρ − 1) / λ_r        [точний вираз очікування]
       ≈ ρ / λ_r                [наближення Тейлора e^ρ − 1 ≈ ρ при малих ρ]
       = (λ_r / μ_r) / λ_r      [підстановка визначення параметра навантаження]
       = 1 / μ_r                [середня тривалість завершення одного читання]
```

Тобто при малому навантаженні письменник чекає в середньому лише час завершення одного читання.

Проте щойно навантаження ρ перевищує одиницю (ρ > 1), очікування починає зростати експоненційно:
- При навантаженні ρ = 5: E[W_w] = (e^5 − 1) / λ_r ≈ 147.4 / λ_r (затримка зростає у 147 разів).
- При навантаженні ρ = 10: E[W_w] = (e^10 − 1) / λ_r ≈ 22025 / λ_r (затримка зростає у 22 000 разів).

При навантаженні ρ = 10 письменник чекає в 22 000 разів довше, ніж при поодиноких запитах. Це строге математичне доведення неминучості голодування письменника (writer starvation) у read-heavy системах без зміни політики на пріоритет запису або FIFO.

### 3. Апаратна ціна когерентності кешу (Cache Line Bouncing)

На багатоядерних процесорах (SMP-системах) операція взяття розділюваного блокування читача `read_lock` виконує атомарну інструкцію (наприклад, `LOCK XADD` на архітектурі x86-64 або пару `LDREX/STREX` на ARM).

Нехай у системі працює C процесорних ядер, кожне з яких одночасно виконує читання спільних даних. Хоча самі дані не модифікуються, спільний лічильник `reader_count` розташований в одному 64-байтовому рядку кешу L1/L2.

Згідно з протоколом когерентності MESI/MOESI:
1. Коли ядро Core_A виконує атомарний інкремент `fetch_add`, воно зобов'язане перевести стан рядка кешу у власному L1/L2 з Shared (S) у стан Modified (M).
2. Для цього ядро надсилає через спільну кільцеву шину або матричну мережу (Ring Bus / Mesh Interconnect) широкомовне повідомлення про інвалідацію (Read-For-Ownership, RFO).
3. Усі інші (C − 1) ядра скидають свій рядок у стан Invalid (I).
4. Наступне ядро Core_B, виконуючи свій `read_lock`, стикається з промахом кешу (L1/L2 Cache Miss) і змушене запитувати оновлений рядок із пам'яті або кешу L3.

Загальна кількість між'ядерних повідомлень інвалідації при одночасному вході C читачів оцінюється квадратичною залежністю від кількості ядер:

```text
Трафік шини = O(C^2)    [квадратичне зростання кількості RFO-інвалідацій між ядрами]
```

Час однієї інвалідації та передачі рядка між ядрами складає від 40 до 120 тактів процесора (на відміну від 4 тактів при читанні з локального L1-кешу). За наявності 64 ядер сумарні накладні витрати на чергування інвалідацій (cache line bouncing) перевищують час виконання самої корисної операції читання в десятки разів.

Саме тому в багатоядерних системах високого навантаження перехід від централізованого лічильника до розподілених Per-CPU замків знижує трафік шини з O(C^2) до O(1) для читачів, усуваючи апаратне вузьке місце.
