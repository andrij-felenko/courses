# Бар'єри пам'яті: впорядкування операцій

<preknowlist>
- [Атомні операції](root:sf-tasks/atomic-ops) — базові атомарні примітиви читання й запису.
</preknowlist>

Коли кілька процесорних ядер у багатопроцесорній системі працюють з тими самими комірками оперативної пам'яті, звичайне присвоєння змінних у C-коді не гарантує, що інші ядра побачать ці зміни у тому самому порядку. Сучасні суперскалярні процесори та оптимізуючі компілятори мають право переставляти місцями інструкції читання й запису (Out-of-Order execution) задля досягнення максимальної швидкодії.

Бар'єри пам'яті (memory barriers / memory fences) — це спеціальні примітиви компілятора та апаратні інструкції CPU, які встановлюють суворі межі та забороняють перевпорядкування операцій читання й запису крізь визначену точку коду.

## Чому виникає перевпорядкування операцій

Головна причина перевпорядкування — прагнення уникнути тривалих простоїв обчислювального конвеєра процесора під час повільного доступу до системної оперативної пам'яті DRAM. Зчитування даних із пам'яті займає сотні тактів CPU, тоді як виконання інструкції у регістрі триває частки такту. Тому оптимізація доступу до пам'яті виконується на двох незалежних рівнях:

1. **Рівень компілятора (Compiler Reordering):** Компілятор GCC або Clang переставляє асемблерні інструкції місцями, зберігає значення змінних у регістрах ядра замість RAM та виносить читання з циклів, якщо у межах одного потоку між ними немає прямої дата-залежності. Компілятор також може об'єднувати окремі записи у один ширший запис або видаляти читання, якщо бачить код лише одного потоку.
2. **Рівень апаратури процесора (Hardware Out-of-Order Execution):** Ядро процесора скидає нові дані у локальний буфер відкладеного запису (Store Buffer) і продовжує виконання наступних інструкцій ще до того, як запис потрапить у спільний кеш L3 чи RAM. У той же час черги інвалідації кешу (Invalidate Queues) можуть затримувати оновлення даних на приймаючому ядрі.

Слід розрізняти апаратну когерентність кешу (Cache Coherence) та впорядкування пам'яті (Memory Ordering). Протокол когерентності MESI гарантує, що всі ядра бачать узгоджений стан однієї комірки пам'яті. Проте порядок оновлення різних комірок пам'яті без використання бар'єрів не гарантується.

Без застосування бар'єрів пам'яті потік-споживач на одному ядрі може побачити оновлений прапорець готовності, але зчитати застаріле значення самих даних з локального кешу.

Детальну історію позапорядкового виконання процесорів, слабку модель пам'яті DEC Alpha та вилучення макроса `smp_read_barrier_depends()` у ядрі Linux висвітлено у вставці [Історія позапорядкового виконання та моделей пам'яті CPU](root:sf-tasks/memory-barriers/hist-out-of-order-cpu.md).

## Основні види бар'єрів пам'яті у ядрі Linux

Ядро Linux розділяє примітиви впорядкування на три основні категорії:

### 1. Бар'єр компілятора (`barrier()`)

Макрос `barrier()` зупиняє оптимізації компілятора, не генеруючи жодної апаратної інструкції процесора:

```c
#define barrier() __asm__ __volatile__("": : :"memory")
```

Директива `"memory"` у списку зіпсованих регістрів змушує компілятор скинути всі локальні значення з регістрів у оперативну пам'ять до точки бар'єра та заново прочитати необхідні змінні з пам'яті після нього.

Для захисту окремих змінних ядро використовує макроси `READ_ONCE()` та `WRITE_ONCE()`, які гарантують атомарність завантаження та збереження типів розміром до ширини машинного слова. Вони захищають від розщеплення доступу (Byte Tearing), подвійного запису та оптимізаційного винесення читань із циклу.

### 2. Апаратні SMP-бар'єри

У багатопроцесорних системах використовуються три класичних примітиви впорядкування:
- `smp_wmb()` — бар'єр запису (Write Memory Barrier). Гарантує, що всі записи до бар'єра стануть видимими іншим ядрам раніше за будь-який запис після нього.
- `smp_rmb()` — бар'єр читання (Read Memory Barrier). Гарантує впорядкування читань до і після бар'єра.
- `smp_mb()` — повний двосторонній бар'єр пам'яті. Забороняє будь-яке перевпорядкування читань і записів у обох напрямках. На x86-64 ядро генерує для нього атомарну операцію з префіксом `LOCK` над вершиною стека, а на ARM64 — `DMB ISH`.

### 3. Бар'єри введення-виведення (MMIO Barriers)

При взаємодії з апаратними пристроями через шину PCIe (наприклад, підготовка DMA-буферів у RAM та сповіщення пристрою через MMIO-регістр Doorbell) використовуються обов'язкові апаратні бар'єри `wmb()`, `rmb()` та `mb()` — на x86-64 це справжні `SFENCE`, `LFENCE` і `MFENCE`. Вони примушують мости шини PCIe скинути буфери відкладених записів (Posted Writes) у регістри пристрою раніше виконання наступних команд.

Повний перелік макросів ядра, описи сигнатур, правила контрольних залежностей та таблицю розгортання в асемблер x86-64 і ARM64 містить [Довідник бар'єрів пам'яті в ядрі Linux](root:sf-tasks/memory-barriers/api-kernel-memory-barriers.md).

## Семантика Acquire / Release

У сучасному ядрі Linux та стандартах C11/C++11 замість важких симетричних бар'єрів використовується семантика **Acquire / Release**, яка вибудовує причинно-наслідковий зв'язок (Happens-Before Relationship) між виробником і споживачем:

- **`smp_store_release(ptr, val)` (Release-запис):** Записує значення та ставить бар'єр ЗВЕРХУ, перед самим записом. Жоден попередній запис чи читання не може опуститися нижче цієї межі.
- **`smp_load_acquire(ptr)` (Acquire-читання):** Зчитує значення та ставить бар'єр ЗНИЗУ, одразу після читання. Жодне наступне читання чи запис не може бути виконане спекулятивно до цієї межі.

:::tabs
```c
// Передача даних між ядрами у ядрі Linux (C)
// Потік 1 (Виробник)
payload = 42;
smp_store_release(&flag, 1);

// Потік 2 (Споживач)
if (smp_load_acquire(&flag) == 1) {
    pr_info("Data: %d\n", payload); // Гарантовано 42!
}
```
```cpp
// Передача даних у користувацькому просторі (C++17)
// Потік 1 (Виробник)
payload = 42;
flag.store(1, std::memory_order_release);

// Потік 2 (Споживач)
if (flag.load(std::memory_order_acquire) == 1) {
    std::cout << "Data: " << payload << "\n"; // Гарантовано 42!
}
```
:::

На архітектурі ARM64 семантика Acquire-Release розгортається у високоефективні апаратні інструкції `STLR` та `LDAR`, які виконуються конвеєром майже безкоштовно у порівнянні з важкими бар'єрами `DMB`.

Примітиви Acquire-Release забезпечують коректність безблокувальних алгоритмів без надмірної зупинки процесорного конвеєра. Вони захищають від гонок за даними та гарантують послідовність читання полів структури.

Практичну реалізацію безблокувального алгоритму на основі Acquire-Release семантики та RCU наведено у вставці [Безблокувальний стек Трайбера на Acquire-Release](root:sf-tasks/memory-barriers/proj-lockfree-stack.md).

> 🔧 **Навіщо це.** Повний бар'єр `smp_mb()` — найдорожчий примітив упорядкування. Заміна його парою `smp_store_release()` та `smp_load_acquire()` не коштує на x86-64 нічого, а на ARM64 зводить бар'єр до однієї інструкції — і саме на цій парі побудовано безблокувальні кільцеві буфери, публікацію вказівників у RCU та черги повідомлень усередині ядра.
