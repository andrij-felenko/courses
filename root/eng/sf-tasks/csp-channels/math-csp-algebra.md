# 🧮 Алгебра процесів CSP: сліди, відмови та дивергенція

Формальна математична модель CSP (Communicating Sequential Processes) — це алгебра процесів, розроблена Чарльзом Ентоні Річардом Гоаром для строгого моделювання, верифікації та доведення коректності паралельних обчислювальних систем. На відміну від емпіричного аналізу багатопотоковості, де стан системи оцінюється вмістом спільних комірок пам'яті, алгебра CSP моделює поведінку компонентів виключно через дискретні комунікаційні події та простори взаємодії з оточенням.

### Абетка подій та термінальні процеси

Фундаментальною одиницею взаємодії в алгебрі CSP є **подія** (*event*). Подія є неподільним, атомарним актом комунікації або внутрішнього переходу, що не має протяжності в часі. Передача значення `v` через іменований канал `c` формалізується парою подій: запис `c.v` та зчитування `c.v`.

Кожен процес `P` строго визначається разом зі своєю **абеткою** `αP` — замкненою множиною всіх потенційних подій, у яких цей процес має право брати участь:

```
αP = {e₁, e₂, ..., eₙ}
```

Процес ніколи не може генерувати події поза межами власної абетки. Якщо дві системи виконуються паралельно, події, що належать одночасно абеткам обох систем, вимагають їхньої обов'язкової одночасної синхронізації.

В алгебрі визначено два базові термінальні процеси:
1. `STOP` — процес-глухий кут (мертве блокування, deadlock). Він має фіксовану абетку `α(STOP) = A`, але фізично не здатний виконати жодної події зі своєї абетки. Слід його поведінки містить виключно порожній запис:
```
tr(STOP) = {<>}
```
2. `SKIP` — процес успішного термінального завершення. Він виконує спеціальну службову подію `✓` (tick), що позначає коректний фініш, після чого переходить у стан `STOP`.

### Семантика слідів (Traces Model)

Поведінка процесу в часі фіксується у вигляді **сліду** (*trace*) — скінченної впорядкованої послідовності подій із його абетки. Слід записується у кутових дужках `s = <e₁, e₂, ..., eₖ>`, а конкатенація двох послідовностей позначається символом `^`. Порожній слід (стан до початку будь-яких дій) позначається як `<>`.

Множина всіх можливих слідів процесу `tr(P) ⊆ (αP)*` підпорядковується фундаментальним алгебраїчним аксіомам:
1. **Непорожність множини:** Порожній слід завжди є елементом множини слідів будь-якого процесу (`<> ∈ tr(P)`).
2. **Замкненість за префіксами:** Якщо складена послідовність `s ^ t` належить `tr(P)`, то будь-який її початковий відрізок `s` також обов'язково належить `tr(P)`.

Для фільтрації слідів застосовується оператор обмеження (проєкції) `s ↾ A`, який видаляє зі сліду `s` усі події, що не входять до підмножини `A ⊆ αP`.

### Алгебраїчні оператори комбінації процесів

Алгебра CSP надає систему фундаментальних операторів, за допомогою яких будуються складні паралельні структури:

#### 1. Префіксація події (Prefixing): `a -> P`
Процес очікує настання події `a ∈ αP`. Після того, як подія `a` відбувається, система продовжує функціонувати як процес `P`:

```
tr(a -> P) = {<>} ∪ {<a> ^ s | s ∈ tr(P)}
```

#### 2. Детермінований зовнішній вибір (External Choice): `P □ Q`
Зовнішнє оточення визначає, яка подія відбудеться першою. Якщо перша запропонована подія належить абетці процесу `P`, система переходить у стан `P`. Якщо ж першою активується подія процесу `Q`, система поводиться як `Q`:

```
tr(P □ Q) = tr(P) ∪ tr(Q)
```
Цей оператор є математичною основою для конструкції `select` або `alt` у мовах програмування.

#### 3. Недетермінований внутрішній вибір (Internal Choice): `P ⊓ Q`
Система самостійно й автономно обирає одну з гілок поведінки за внутрішніми факторами, непідконтрольними зовнішньому спостерігачеві. На рівні простої семантики слідів `tr(P ⊓ Q) = tr(P) ∪ tr(Q)`, проте в моделі відмов ці вибори строго розрізняються.

#### 4. Паралельна композиція із синхронізацією: `P || Q`
Процеси `P` та `Q` виконуються паралельно. Для подій із перетину абеток `αP ∩ αQ` вимагається обов'язкова одночасна участь обох процесів (синхронне рандеву). Події, специфічні лише для одного процесу, виконуються незалежно:

```
tr(P || Q) = {s ∈ (αP ∪ αQ)* | (s ↾ αP) ∈ tr(P) ∧ (s ↾ αQ) ∈ tr(Q)}
```

#### 5. Приховування подій (Hiding / Abstraction): `P \ A`
Події з підмножини `A` стають внутрішніми для підсистеми і перетворюються на невидимі для зовнішнього середовища мовчазні переходи `τ` (*tau-transitions*).

### Покроковий математичний приклад: Моделювання синхронного буфера

Розглянемо процес одноразового буфера `BUFFER`, що циклічно приймає повідомлення `in` і віддає `out`:

```
BUFFER = (in -> (out -> BUFFER))
```

Розгорнемо множину можливих слідів процесу крок за кроком:

```
tr(BUFFER)
= {<>} ∪ {<in> ^ s | s ∈ tr(out -> BUFFER)}          [розгортання префікса in]
= {<>, <in>} ∪ {<in, out> ^ s | s ∈ tr(BUFFER)}     [розгортання префікса out]
= {<>, <in>, <in, out>, <in, out, in>, ...}         [індуктивне замикання]
```

Якщо підключити до цього буфера генератор `PROD = (in -> PROD)` паралельно: `SYSTEM = PROD || BUFFER` з абеткою `{in, out}`:
- Оскільки подія `in ∈ αPROD ∩ αBUFFER`, генератор не здатний згенерувати друге повідомлення `in`, доки буфер не виконає парну операцію `out`.
- Слід системи строго чергується: `tr(SYSTEM) = {<>, <in>, <in, out>, <in, out, in>, ...}`. Математично доведено, що переповнення або втрата даних неможливі за будь-якої швидкості генератора.

### Модель відмов та дивергенції (Failures-Divergences Model)

Проста семантика слідів не здатна розрізнити життєздатну систему від системи з дедлоком. Розглянемо два процеси з однаковою абеткою `{a, b, c}`:

```
P = a -> (b -> STOP □ c -> STOP)
Q = (a -> b -> STOP) ⊓ (a -> c -> STOP)
```

Обидва процеси мають ідентичні множини слідів: `{<>, <a>, <a, b>, <a, c>}`. Проте процес `P` після виконання події `a` готовий прийняти як `b`, так і `c` (вибір робить оточення). Натомість процес `Q` після події `a` вже внутрішньо обрав одну з гілок: якщо він обрав гілку `b`, а оточення пропонує подію `c`, настає дедлок.

Для розв'язання цієї проблеми в CSP введено **трійку семантики** `(Traces, Failures, Divergences)`:

1. **Множина відмов (Failures):** Пара `(s, X)`, де `s ∈ tr(P)` — виконаний слід, а `X ⊆ αP` — множина подій (**refusal set**), які процес може відмовитися виконати після сліду `s`:
```
failures(P) = {(s, X) | s ∈ tr(P) ∧ P після s відмовляється від усіх e ∈ X}
```
Для нашого прикладу після сліду `<a>`:
- Для `P`: `(<a>, {b, c}) ∉ failures(P)`, бо процес готовий прийняти або `b`, або `c`.
- Для `Q`: `(<a>, {b}) ∈ failures(Q)` та `(<a>, {c}) ∈ failures(Q)`, оскільки після внутрішнього вибору процес гарантовано відкидає одну з альтернатив.

2. **Множина дивергенцій (Divergences):** Множина слідів `s`, після яких процес потрапляє в нескінченний внутрішній цикл невидимих переходів `τ` (livelock / divergence), перестаючи реагувати на зовнішні події:
```
divergences(P) = {s ^ t | процес після s генерує нескінченний ланцюг переходів P \ A}
```

### Алгебраїчні закони еквівалентності та редукції

Процеси в CSP підпорядковуються строгим законам еквівалентності, що дозволяє оптимізувати та спрощувати паралельні специфікації:

1. **Комутативність та асоціативність вибору:**
```
P □ Q = Q □ P
P □ (Q □ R) = (P □ Q) □ R
P ⊓ Q = Q ⊓ P
P ⊓ (Q ⊓ R) = (P ⊓ Q) ⊓ R
```

2. **Ідемпотентність вибору:**
```
P □ P = P
P ⊓ P = P
```

3. **Дистрибутивність вибору:**
```
P □ (Q ⊓ R) = (P □ Q) ⊓ (P □ R)
P ⊓ (Q □ R) = (P ⊓ Q) □ (P ⊓ R)
```

4. **Закон розгортання паралельної композиції (Expansion Law):**
Якщо `P = (a -> P')` та `Q = (b -> Q')`:
- Якщо `a = b` та `a ∈ αP ∩ αQ`:
```
P || Q = a -> (P' || Q')
```
- Якщо `a ≠ b` та `a, b ∉ αP ∩ αQ`:
```
P || Q = (a -> (P' || Q)) □ (b -> (P || Q'))
```
- Якщо `a ∈ αP ∩ αQ`, але `b ∉ αP ∩ αQ`:
```
P || Q = b -> (P || Q')
```

### Теорема про свободу від взаємного блокування

У довільній замкненій мережі процесів `N = P₁ || P₂ || ... || Pₖ`, що взаємодіють через типізовані канали, відсутність взаємного блокування (Deadlock Freedom) математично гарантується за одночасного виконання двох критеріїв:

1. **Ациклічність топології комунікаційного графа:** Граф інформаційних потоків між процесами є напрямленим ациклічним графом (DAG), що фундаментально усуває можливість утворення циклічного очікування ресурсів.
2. **Узгодженість множин відмов (Refusal Compatibility):** Для кожного спільного каналу зв'язку `c = αPᵢ ∩ αPⱼ` множини відмов узгоджені в усіх досяжних станах:
```
∀ s ∈ tr(N): (s ↾ αPᵢ, {c}) ∈ failures(Pᵢ) ⇒ (s ↾ αPⱼ, {c}) ∉ failures(Pⱼ)
```
Це відношення доводить, що в момент, коли один із процесів блокується на каналі `c`, його партнер обов'язково готовий виконати комплементарну дію, гарантуючи прогрес системи без тупикових станів.
