# 🧮 Математика та алгоритми чесного розподілу черг: DRR та WFQ

У мультиарендних розподілених системах спільний обчислювальний вузол, черга завдань або мережевий шлюз одночасно обслуговує потоки запитів від багатьох незалежних орендарів. Якщо всі запити накопичуються в єдиному буфері за принципом FIFO (First-In, First-Out), клієнт із високою інтенсивністю трафіку або великим розміром повідомлень неминуче витісняє запити інших клієнтів. Це явище призводить до ресурсного голодування (starvation) та неконтрольованого зростання затримок для добросовісних сусідів по системі.

Для запобігання монополізації спільних ресурсів теорія масового обслуговування застосовує математичний критерій максимальної мін-максної справедливості (Max-Min Fairness), модель узагальненого поділу процесора (Generalized Processor Sharing, GPS) та високоефективні алгоритми дискретного планування: зважену справедливу чергу (Weighted Fair Queuing, WFQ) та дефіцитний круговий огляд (Deficit Round Robin, DRR).

---

## Критерій справедливості Max-Min Fairness

Нехай система має спільну фіксовану пропускну здатність `C` (виміряну в операціях на секунду або байтах за одиницю часу), яку необхідно розділити між `n` орендарями. Кожен орендар `i` заявляє власний попит на ресурс `r[i]`, а система виділяє йому фактичну частку `a[i]`.

Розподіл часток `a = (a[1], a[2], ..., a[n])` називається **Max-Min Fair**, якщо неможливо збільшити виділення ресурсу для будь-якого орендаря `i` без зменшення виділення іншому орендарю `j`, який уже отримує меншу або рівну частку (`a[j] ≤ a[i]`).

### Формальний алгоритм розподілу Max-Min часток

Математична процедура обчислення часток спирається на ітеративне насичення попиту орендарів:

1. Спільна пропускна здатність ділиться порівну між усіма активними орендарями, утворюючи початковий рівень відсікання `f_init = C / n`.
2. Якщо попит орендаря `r[i]` не перевищує середню частку (`r[i] ≤ f_init`), система виділяє йому рівно стільки ресурсу, скільки він просить: `a[i] = r[i]`.
3. Невикористаний залишок ресурсу акумулюється та перерозподіляється порівну між рештою орендарів, чий попит залишився незадоволеним.
4. Процес повторюється ітеративно, доки вся доступна ємність `C` не буде розподілена, або доки попити всіх орендарів не будуть повністю задоволені.

Формально для довільного орендаря `i` виділена частка описується виразом:

```
a[i] = min(r[i], f)
```

де `f` — єдиний пороговий рівень відсікання (fair share threshold), що визначається з рівняння балансу ресурсів:

```
∑ min(r[i], f) = C      [сума виділених часток дорівнює пропускній здатності]
```

### Покроковий приклад розрахунку Max-Min часток

Розглянемо систему з пропускною здатністю `C = 100` запитів/с та чотирма активними орендарями з попитами:
`r[1] = 10`, `r[2] = 20`, `r[3] = 40`, `r[4] = 80`.

Розрахунок виконується покроково:

```
Крок 1: Початкова рівна частка для 4 орендарів
f_init = C ÷ n
= 100 ÷ 4              [ділення загального ресурсу на 4 орендарів]
= 25

Крок 2: Задоволення орендарів із попитом менше f_init
a[1] = min(10, 25) = 10 [попит 10 повністю задоволено]
a[2] = min(20, 25) = 20 [попит 20 повністю задоволено]

Крок 3: Обчислення залишку ресурсу та нового порогу для орендарів 3 і 4
C_rem = C − (a[1] + a[2])
= 100 − (10 + 20)      [віднімання вже виділених часток]
= 70                   [нерозподілений залишок ресурсу]

f_new = C_rem ÷ 2
= 70 ÷ 2               [ділення залишку порівну між двома незадоволеними клієнтами]
= 35

Крок 4: Фінальні виділені частки
a[3] = min(40, 35) = 35 [попит 40 обмежується рівнем f_new = 35]
a[4] = min(80, 35) = 35 [попит 80 обмежується рівнем f_new = 35]

Перевірка балансу:
10 + 20 + 35 + 35 = 100 [весь ресурс 100 розподілено повністю]
```

Орендар 4 із гігантським попитом (80 запитів/с) не зміг забрати ресурси у дрібних клієнтів: орендарі 1 і 2 отримали 100% необхідного трафіку, а клієнти 3 і 4 порівну поділили весь залишок потужності.

## Ідеальна модель Generalized Processor Sharing (GPS) та WFQ

У неперервному часі ідеальну мін-максну справедливість реалізує теоретична модель **Generalized Processor Sharing (GPS)**. Кожен орендар `i` має призначену вагу `w[i]`. У будь-який момент часу `t` множина активних орендарів `B(t)` (тих, чиї черги містять непорожні дані) ділить ресурс зі швидкістю:

```
R[i](t) = C · (w[i] ÷ ∑ w[j])    [де сума береться по всіх j ∈ B(t)]
```

Модель GPS є недосяжним математичним ідеалом для дискретних пакетних систем: повідомлення та HTTP-запити неподільні й не можуть передаватися по окремих бітах паралельно через єдиний сокет чи процесорне ядро.

Алгоритм **Weighted Fair Queuing (WFQ)** симулює неперервний час GPS у дискретних подіях за допомогою концепції віртуального часу `V(t)`.

Коли пакет `k` розміром `L[k]` прибуває в чергу орендаря `i` у фізичний момент часу `t`, алгоритм WFQ розраховує дві мітки: віртуальний час початку обробки `S[i, k]` та віртуальний час завершення `F[i, k]`:

```
S[i, k] = max(V(t), F[i, k−1])
F[i, k] = S[i, k] + (L[k] ÷ w[i])
```

Диспетчер WFQ завжди вибирає для відправки той пакет серед усіх черг, який має найменший розрахований віртуальний час завершення `F[i, k]`.

### Обчислювальна складність WFQ та її межі

Для вибору пакета з мінімальним значенням `F` серед `N` активних черг диспетчер WFQ змушений підтримувати пріоритетну чергу на базі двійкової купи (Binary Heap). Це дає алгоритмічну складність `O(log N)` на кожен відправлений пакет:

```
Складність операцій у WFQ:
- Вставка пакета в купу:      O(log N)
- Пошук та вилучення мін. F:   O(log N)
- Оновлення віртуального часу: O(N) або O(log N)
```

При навантаженні в сотні тисяч або мільйони мережевих пакетів на секунду накладні витрати на балансування двійкового дерева в пам'яті процесора створюють критичне вузьке місце.

## Алгоритм Deficit Round Robin (DRR) зі складністю O(1)

Щоб подолати обмеження `O(log N)`, інженери М. Шрікішна та Дж. Варгіс у 1996 році розробили алгоритм **Deficit Round Robin (DRR)**, який забезпечує точний чесний розподіл пакетів довільного змінного розміру з константною часовою складністю `O(1)` на операцію.

### Структури даних алгоритму DRR

Для кожного орендаря `i` диспетчер підтримує:
* `Q[i]` — індивідуальну FIFO-чергу пакетів або запитів;
* `Quantum[i]` — фіксований базовий квант ресурсу (у байтах), який додається до балансу черги під час кожного кругового обходу;
* `DC[i]` (Deficit Counter) — накопичений лічильник дефіциту (баланс невикористаних байтів). Початкове значення `DC[i] = 0`.

### Логіка роботи диспетчера DRR

Диспетчер обходить черги орендарів по замкненому колу (Round Robin):

1. Якщо черга орендаря `Q[i]` містить пакети, її лічильник дефіциту поповнюється на величину кванта:
   ```
   DC[i] = DC[i] + Quantum[i]
   ```
2. Диспетчер перевіряє розмір першого пакета на початку черги `L(head)`. Поки черга непорожня і розмір чергового пакета не перевищує накопичений дефіцит (`L(head) ≤ DC[i]`):
   - Пакет вилучається з черги `Q[i]` і передається на фізичну обробку.
   - Лічильник дефіциту зменшується на точний розмір відправленого пакета:
     ```
     DC[i] = DC[i] − L(head)
     ```
3. Якщо черга спорожніла в процесі відправки, невикористаний дефіцит скидається в нуль, щоб запобігти нечесному накопиченню переваги в майбутньому:
   ```
   DC[i] = 0   [якщо черга Q[i] порожня — дефіцит анулюється]
   ```
4. Якщо черга ще містить пакети, але розмір наступного пакета перевищує залишок `DC[i]`, диспетчер зберігає поточний залишок `DC[i]` для наступного раунду і негайно переходить до черги наступного орендаря `i + 1`.

## Покрокове математичне трасування роботи DRR

Розглянемо систему з трьох активних черг із однаковими квантами: `Quantum = 500` байтів для всіх орендарів.

Початковий стан черг:
* Черга 1 (Tenant 1): Пакети `[P1_1 = 400 B, P1_2 = 300 B, P1_3 = 200 B]`
* Черга 2 (Tenant 2): Пакети `[P2_1 = 800 B, P2_2 = 200 B]`
* Черга 3 (Tenant 3): Пакети `[P3_1 = 150 B, P3_2 = 150 B]`

### Раунд 1

```
Черга 1 (Tenant 1):
1. Нарахування кванта: DC[1] = 0 + 500 = 500 байтів.
2. Пакет P1_1 (400 B): 400 ≤ 500 → ПАКЕТ ВІДПРАВЛЕНО.
   Оновлення дефіциту: DC[1] = 500 − 400 = 100 байтів.
3. Пакет P1_2 (300 B): 300 > 100 → ПАКЕТ НЕ ВМІЩУЄТЬСЯ.
   Залишок DC[1] = 100 байтів переноситься на наступний раунд.

Черга 2 (Tenant 2):
1. Нарахування кванта: DC[2] = 0 + 500 = 500 байтів.
2. Пакет P2_1 (800 B): 800 > 500 → ПАКЕТ НЕ ВМІЩУЄТЬСЯ.
   Жоден пакет не відправлено. Залишок DC[2] = 500 переноситься на раунд 2.

Черга 3 (Tenant 3):
1. Нарахування кванта: DC[3] = 0 + 500 = 500 байтів.
2. Пакет P3_1 (150 B): 150 ≤ 500 → ПАКЕТ ВІДПРАВЛЕНО.
   DC[3] = 500 − 150 = 350 байтів.
3. Пакет P3_2 (150 B): 150 ≤ 350 → ПАКЕТ ВІДПРАВЛЕНО.
   DC[3] = 350 − 150 = 200 байтів.
4. Черга 3 спорожніла → DC[3] = 0 (скидання дефіциту).

Підсумок Раунду 1: Відправлено пакети [P1_1, P3_1, P3_2].
Стан дефіциту: DC[1] = 100 B, DC[2] = 500 B, DC[3] = 0 B.
```

### Раунд 2

```
Черга 1 (Tenant 1):
1. Нарахування кванта: DC[1] = 100 + 500 = 600 байтів.
2. Пакет P1_2 (300 B): 300 ≤ 600 → ПАКЕТ ВІДПРАВЛЕНО.
   DC[1] = 600 − 300 = 300 байтів.
3. Пакет P1_3 (200 B): 200 ≤ 300 → ПАКЕТ ВІДПРАВЛЕНО.
   DC[1] = 300 − 200 = 100 байтів.
4. Черга 1 спорожніла → DC[1] = 0 (скидання дефіциту).

Черга 2 (Tenant 2):
1. Нарахування кванта: DC[2] = 500 + 500 = 1000 байтів.
2. Пакет P2_1 (800 B): 800 ≤ 1000 → ПАКЕТ ВІДПРАВЛЕНО.
   DC[2] = 1000 − 800 = 200 байтів.
3. Пакет P2_2 (200 B): 200 ≤ 200 → ПАКЕТ ВІДПРАВЛЕНО.
   DC[2] = 200 − 200 = 0 байтів.
4. Черга 2 спорожніла → DC[2] = 0.

Черга 3 (Tenant 3):
1. Черга порожня → пропускається диспетчером.

Підсумок Раунду 2: Відправлено пакети [P1_2, P1_3, P2_1, P2_2].
Всі черги повністю спустошені з ідеальним збереженням справедливості часток.
```

Трасування наочно демонструє ключову перевагу DRR: великий пакет орендаря 2 (800 байт) не заблокував обробку дрібних пакетів сусідніх черг у першому раунді, але отримав повне право на передачу в другому раунді завдяки коректному накопиченню невикористаного дефіцитного балансу.
