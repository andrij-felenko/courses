# 🧮 Математичний аналіз конвеєрів: пропускна здатність, Little's Law та динаміка буферів

Конвеєрна архітектура з'єднує незалежні вузли обробки (фільтри) через буферизовані канали передачі. Щоб спроєктувати надійну систему без втрат повідомлень і неконтрольованого зростання затримок, необхідно формалізувати зв'язок між продуктивністю окремих стадій, розміром буферів та сумарною пропускною здатністю.

## 1. Детерміністична модель конвеєра та вузьке місце (Bottleneck)

Розглянемо лінійний конвеєр із `N` послідовних фільтрів `F₁, F₂, …, F_N`.
Кожен фільтр `F_i` характеризується середнім часом обслуговування одного повідомлення `S_i` (секунд на повідомлення) або інтенсивністю обслуговування `μ_i` (повідомлень на секунду):

```
μ_i = 1 / S_i
```

На вхід першого фільтра надходить потік повідомлень з інтенсивністю `λ` (повідомлень на секунду).

### Послідовна обробка проти конвеєрної

Якщо всі `N` операцій виконуються в єдиному монолітному потоці без проміжної буферизації, загальний час обробки одного повідомлення `T_seq` дорівнює сумі часів усіх стадій:

```
T_seq = S₁ + S₂ + … + S_N = ∑_{i=1}^N S_i
```

Пропускна здатність монолітного обробника без паралелізму становить:

```
P_seq = 1 / T_seq = 1 / (∑_{i=1}^N S_i)
```

У конвеєрній архітектурі всі `N` фільтрів працюють одночасно й незалежно над різними повідомленнями потоку. Період видачі готових повідомлень із конвеєра (такт конвеєра `T_cycle`) визначається найповільнішою стадією:

```
T_cycle = max(S₁, S₂, …, S_N) = 1 / (min(μ₁, μ₂, …, μ_N))
```

Найповільніший фільтр конвеєра називається **вузьким місцем** (англ. *bottleneck stage*):

```
μ_bottleneck = min_{i=1..N} (μ_i)
```

Максимальна теоретична пропускна здатність конвеєра в стаціонарному режимі обмежена цим вузьким місцем:

```
P_max = μ_bottleneck = 1 / (max_{i=1..N} S_i)
```

### Прискорення конвеєра для пакету з M повідомлень

Час, необхідний для повної обробки партії з `M` повідомлень у конвеєрі, складається з часу заповнення конвеєра першим повідомленням (`T_seq`) та часу виходу решти `(M - 1)` повідомлень із тактом `T_cycle`:

```
T_pipe(M) = T_seq + (M - 1)·T_cycle
```

Коефіцієнт прискорення конвеєра `Speedup(M)` порівняно з послідовним виконанням `M·T_seq`:

```
Speedup(M) = (M · T_seq) / (T_seq + (M - 1)·T_cycle)

При M → ∞:
lim_{M → ∞} Speedup(M) = T_seq / T_cycle = (∑_{i=1}^N S_i) / (max_{i=1..N} S_i)
```

Якщо всі стадії конвеєра ідеально збалансовані (`S₁ = S₂ = … = S_N = S`), тоді `T_seq = N·S`, `T_cycle = S`, і максимальне прискорення прямує до `N` (кількості стадій).

## 2. Стохастична модель конвеєра як мережі Джексона (Jackson Networks)

У реальних розподілених системах повідомлення надходять нерівномірно (пуассонівський потік з інтенсивністю `λ`), а час обробки на кожній стадії є випадковою величиною, що описується експоненційним розподілом із параметром `μ_i`. Це призводить до виникнення черг у проміжних каналах між фільтрами.

### Теорема Берка (Burke's Theorem) та незалежність стадій

Згідно з теоремою Берка, вихідний потік стаціонарної системи масового обслуговування типу `M/M/1` з вхідною інтенсивністю `λ` та інтенсивністю обслуговування `μ > λ` також є пуассонівським процесом із тією самою інтенсивністю `λ`.

З цього випливає критичний архітектурний висновок для лінійних конвеєрів:
1. Якщо вхідний потік першого фільтра є пуассонівським, то вихідний потік першого фільтра (який одночасно є вхідним потоком для другого каналу) також є строго пуассонівським із параметром `λ`.
2. Кожна проміжна черга конвеєра в стаціонарному стані функціонує як незалежна система `M/M/1`.
3. Спільний розподіл імовірностей знаходження `n_i` повідомлень на кожній з `N` стадій розпадається на добуток маргінальних розподілів (теорема Джексона про мультиплікативну форму):

```
P(n₁, n₂, …, n_N) = ∏_{i=1}^N P_i(n_i) = ∏_{i=1}^N (1 - ρ_i) · ρ_i^{n_i}
```

де `ρ_i = λ / μ_i` — коефіцієнт завантаження `i`-ї стадії.

### Умова стаціонарності конвеєра

Щоб черги в каналах не зростали нескінченно, для кожного фільтра має виконуватися умова стійкості:

```
ρ_i < 1   ⇒   λ < μ_i   для всіх i ∈ {1, …, N}
```

Звідси випливає фундаментальне обмеження на вхідний трафік:

```
λ < μ_bottleneck = min_{i=1..N} (μ_i)
```

### Розрахунок затримок і довжини черг за формулами Ерланга-Літтла

Для кожної окремої `i`-ї стадії конвеєра:

1. Середня кількість повідомлень у черзі каналу `L_{q,i}`:
```
L_{q,i} = ρ_i² / (1 - ρ_i)
```

2. Середня загальна кількість повідомлень у вузлі `i` (в черзі + на обробці у фільтрі) `L_i`:
```
L_i = ρ_i / (1 - ρ_i)
```

3. Середній час очікування повідомлення в черзі каналу `W_{q,i}`:
```
W_{q,i} = ρ_i / (μ_i · (1 - ρ_i))
```

4. Середній повний час перебування повідомлення на `i`-й стадії `W_i` (час у черзі каналу + чистий час обробки):

```
W_i = W_{q,i} + S_i
= ρ_i / (μ_i · (1 - ρ_i)) + 1 / μ_i             [підстановка W_{q,i} та S_i = 1/μ_i]
= (ρ_i + (1 - ρ_i)) / (μ_i · (1 - ρ_i))         [зведення до спільного знаменника]
= 1 / (μ_i · (1 - ρ_i))                         [спрощення чисельника: ρ_i + 1 - ρ_i = 1]
= 1 / (μ_i - λ)                                 [розкриття дужок: μ_i·(1 - λ/μ_i) = μ_i - λ]
```

### Наскрізна затримка конвеєра (End-to-End Latency)

Сумарний середній час проходження повідомлення крізь увесь конвеєр від джерела до фінального приймача `W_total`:

```
W_total = ∑_{i=1}^N W_i = ∑_{i=1}^N 1 / (μ_i - λ)
```

Згідно із **Законом Літтла** (Little's Law), середня загальна кількість повідомлень, які одночасно перебувають у польоті всередині конвеєра `L_total`:

```
L_total = λ · W_total = ∑_{i=1}^N λ / (μ_i - λ) = ∑_{i=1}^N ρ_i / (1 - ρ_i)
```

## 3. Оцінка хвостових затримок (Tail Latency Percentiles)

Середній час перебування `W_i` не дає повного уявлення про стабільність системи, оскільки для SLA критичними є процентилі затримок (p95, p99, p99.9).

Для системи `M/M/1` функція розподілу повного часу перебування `W_i` має експоненційний вигляд:

```
F_{W_i}(t) = P(W_i ≤ t) = 1 - e^{-(μ_i - λ) · t}
```

Звідси `p`-й перцентиль затримки `t_p` (час, у межі якого вкладається частка `p` запитів) виводиться аналітично:

```
1 - e^{-(μ_i - λ) · t_p} = p
e^{-(μ_i - λ) · t_p} = 1 - p
-(μ_i - λ) · t_p = ln(1 - p)
t_p = - ln(1 - p) / (μ_i - λ)
```

### Порівняння перцентилів окремої стадії

* **Медіана (p50, `p = 0.50`):**
```
t_{50} = - ln(0.50) / (μ_i - λ) ≈ 0.693 / (μ_i - λ) = 0.693 · W_i
```

* **95-й перцентиль (p95, `p = 0.95`):**
```
t_{95} = - ln(0.05) / (μ_i - λ) ≈ 2.996 / (μ_i - λ) ≈ 3.00 · W_i
```

* **99-й перцентиль (p99, `p = 0.99`):**
```
t_{99} = - ln(0.01) / (μ_i - λ) ≈ 4.605 / (μ_i - λ) ≈ 4.61 · W_i
```

* **99.9-й перцентиль (p99.9, `p = 0.999`):**
```
t_{99.9} = - ln(0.001) / (μ_i - λ) ≈ 6.908 / (μ_i - λ) ≈ 6.91 · W_i
```

Для збалансованого конвеєра з `N` однакових стадій сума `N` незалежних експоненційних величин підпорядковується **розподілу Ерланга** (Erlang-N distribution) із параметром форми `N` та параметром масштабу `(μ - λ)`. Це пояснює, чому хвостова затримка конвеєра формується переважно найгарячішою стадією з максимальним завантаженням `ρ_max`.

## 4. Вплив дисперсії часу обробки: наближення Кінгмана для G/G/1

У практичних системах час виконання фільтрів рідко буває строго експоненційним. Фільтри можуть зазнавати пауз збирання сміття (GC pauses), скидання буферів на SSD або затримок звернення до зовнішніх баз даних.

Для оцінки затримок при довільних розподілах інтервалів надходження та часу обслуговування застосовують **формулу Кінгмана** (Kingman's Heavy-Traffic Approximation):

```
W_{q,i} ≈ (ρ_i / (1 - ρ_i)) · ((C_{a,i}² + C_{s,i}²) / 2) · (1 / μ_i)
```

де:
* `C_{a,i} = σ_{a,i} / E[t_a]` — коефіцієнт варіації інтервалів надходження повідомлень (для пуассонівського потоку `C_a = 1`);
* `C_{s,i} = σ_{s,i} / E[S_i]` — коефіцієнт варіації часу обслуговування фільтра `F_i` (для експоненційного `C_s = 1`, для детерміністичного `C_s = 0`, для важких хвостів `C_s > 2`).

### Чому висока дисперсія руйнує конвеєр

Розглянемо вплив коефіцієнта варіації `C_s` на чергу при завантаженні стадії `ρ = 0.8`:

1. **Ідеально детерміністичний фільтр (`C_s = 0`, `C_a = 1`):**
```
W_q = (0.8 / 0.2) · ((1 + 0) / 2) · (1 / μ) = 4 · 0.5 · (1 / μ) = 2.0 / μ
```

2. **Стандартний експоненційний фільтр (`C_s = 1`, `C_a = 1`):**
```
W_q = (0.8 / 0.2) · ((1 + 1) / 2) · (1 / μ) = 4 · 1.0 · (1 / μ) = 4.0 / μ   [у 2 рази більше]
```

3. **Фільтр із важким хвостом затримок (`C_s = 3`, `C_a = 1`):**
```
W_q = (0.8 / 0.2) · ((1 + 9) / 2) · (1 / μ) = 4 · 5.0 · (1 / μ) = 20.0 / μ  [у 10 разів більше]
```

Це доводить: нестабільність часу роботи фільтра (висока дисперсія через мікропаузи чи повільні мережеві запити) здатна роздути чергу в каналі вдесятеро навіть без збільшення середнього навантаження.

## 5. Математика паралельного злиття (Fork-Join Latency)

У топології з розгалуженням (Splitter) повідомлення розділяється на `m` паралельних потоків, які одночасно обробляються `m` незалежними фільтрами, після чого агрегатор (Join) очікує завершення найповільнішої гілки.

Нехай час обробки на кожній із `m` гілок є незалежною експоненційною випадковою величиною `X_k \sim \text{Exp}(\mu)` із функцією розподілу `F(x) = 1 - e^{-\mu x}`.

Функція розподілу часу завершення найповільнішої стадії `Y = \max(X₁, X₂, …, X_m)`:

```
F_Y(t) = P(max(X₁, …, X_m) ≤ t) = ∏_{k=1}^m P(X_k ≤ t) = (1 - e^{-μ t})^m
```

Математичне сподівання часу агрегації (очікування найповільнішого фільтра):

```
E[Y] = ∫₀^∞ (1 - F_Y(t)) dt
= ∫₀^∞ (1 - (1 - e^{-μ t})^m) dt
= (1 / μ) · ∑_{k=1}^m (1 / k)
= H_m / μ
```

де `H_m = 1 + 1/2 + 1/3 + … + 1/m` — `m`-те гармонічне число.

Оскільки для великих `m` асимптотика гармонічного ряду становить `H_m \approx \ln(m) + \gamma` (де `\gamma \approx 0.5772` — стала Ейлера-Маскероні):

```
E[Y] ≈ (ln(m) + 0.5772) / μ
```

### Практичний наслідок ефекту відстаючого (Straggler Effect)

* При `m = 1` (одна гілка): `E[Y] = 1 / μ = S`.
* При `m = 4` паралельні гілки: `E[Y] = (1 + 1/2 + 1/3 + 1/4) / μ = 2.083 · S` (затримка подвоюється).
* При `m = 16` паралельних гілок: `E[Y] = H_{16} / μ = 3.381 · S` (затримка зростає у 3.4 раза).

Широке розгалуження в конвеєрі завжди зміщує середню затримку вправо: що більше паралельних гілок чекає агрегатор, то вища ймовірність того, що хоча б один фільтр натрапить на статистичний сплеск затримки.

## 6. Нерівномірність хешування (Key Skew) у партиційованих каналах

Коли канал розбивається на `P` паралельних партицій за ключем повідомлення (`Partition = Hash(Key) % P`), реальний трафік часто розподілений нерівномірно (закон Ципфа, Zipfian distribution):

```
P(Key = k) = (1 / k^s) / (∑_{j=1}^M 1 / j^s)
```

де `s` — параметр концентрації (для інтернет-трафіку `s \approx 0.8..1.2`).

Якщо найпопулярніший ключ `Key = 1` генерує частку `p_max = P(1)` від усього вхідного потоку `λ`, навантаження на найгарячішу партицію становить:

```
λ_{hot} = λ · p_max
```

### Умова відсутності затору на гарячій партиції

Для запобігання переповненню найгарячішої партиції продуктивність відповідного фільтра повинна задовольняти умову:

```
μ_{partition} > λ · p_max
```

Якщо `p_max = 0.30` (30% трафіку припадає на одного супер-клієнта), то навіть при `P = 100` партиціях одна партиція отримує 30% навантаження, і масштабування решти 99 партицій не допомагає. Це доводить необхідність внесення випадкової солі (Salting keys) для важких ключів конвеєра.

## 7. Амортизація накладних витрат через мікробатчінг (Micro-batching)

Для зменшення накладних витрат на синхронізацію м'ютексів та мережеві виклики фільтри об'єднують повідомлення в мікробатчі розміром `B` елементів.

Сумарний час обробки одного мікробатчу розміром `B` складається з фіксованих витрат на заголовок/синхронізацію `T_{fixed}` та змінного часу обробки кожного елемента `S`:

```
T_{batch}(B) = T_{fixed} + B · S
```

Середній питомий час обробки одного повідомлення:

```
S_{eff}(B) = T_{batch}(B) / B = (T_{fixed} / B) + S
```

При збільшенні розміру пачки `B`:
* Ефективна інтенсивність обслуговування зростає: `lim_{B \to \infty} μ_{eff}(B) = 1 / S`;
* Додаткова середня затримка накопичення пачки в буфері зростає лінійно: `W_{accum} \approx B / (2 · λ)`.

Оптимальний розмір мікробатчу `B_{opt}` мінімізує сумарну затримку за умови дотримання бюджету часу `T_{budget}`:

```
B_{opt} = min(⌊2 · λ · (T_{budget} - S)⌋, K / 2)
```

## 8. Модель обмеженого буфера (M/M/1/K) та розрахунок протитиску

У промислових системах канали мають скінченну місткість `K` повідомлень. Коли черга заповнюється до `K`, наступне повідомлення або блокує попередній фільтр (протитиск), або відкидається (при відсутності протитиску).

Система масового обслуговування `M/M/1/K` із місткістю буфера `K` характеризується ймовірністю відмови `P_loss` (ймовірністю того, що в системі вже є `K` елементів):

```
P_loss = P_K = ((1 - ρ) / (1 - ρ^{K+1})) · ρ^K   [при ρ ≠ 1]
```

Ефективна пропускна здатність стадії з обмеженим буфером:

```
λ_eff = λ · (1 - P_loss)
```

### Запобігання переповненню та розрахунок порогу High Watermark

Щоб сигнал протитиску встиг зупинити попередній фільтр до того, як буфер каналу фізично переповниться і призведе до втрати повідомлень, поріг активації протитиску (High Watermark `H`) повинен враховувати затримку доставки сигналу `RTT_{signal}`:

```
K - H ≥ λ_peak · RTT_{signal}
```

де:
* `K` — максимальна місткість буфера каналу (кількість повідомлень);
* `H` — поріг заповненості буфера, при досягненні якого надсилається сигнал «PAUSE»;
* `λ_peak` — максимальна миттєва швидкість генерації повідомлень попереднім фільтром;
* `RTT_{signal}` — мережевий або міжпроцесний час проходження сигналу зупинки назад до джерела.

```
H ≤ K - λ_peak · RTT_{signal}
```

### Поглинання імпульсного сплеску (Burst Absorption)

Якщо джерело генерує раптовий сплеск трафіку з інтенсивністю `λ_burst > μ` тривалістю `T_burst`, розмір буфера `B`, необхідний для поглинання сплеску без втрат і без активації протитиску, розраховується з інтегрального балансу:

```
B ≥ (λ_burst - μ) · T_burst
```

Якщо за час `T_burst` надходить `N_burst = λ_burst · T_burst` повідомлень, а фільтр устигає опрацювати `N_proc = μ · T_burst`, надлишок накопичується в черзі.

## 8. Розрахунок пам'яті для віконних агрегацій (State Memory Sizing)

Для станних фільтрів, які реалізують ковзне вікно (Sliding Window) тривалістю `T_w` секунд із кроком зсуву `\Delta t`, середня кількість одночасно збережених у стані повідомлень `N_{state}` визначається законом Літтла:

```
N_{state} = λ · T_w
```

Сумарний обсяг оперативної пам'яті `M_{RAM}`, необхідний для зберігання стану одного ключа партиції:

```
M_{RAM} = N_{state} · (sizeof(Payload) + Overhead_{RocksDB})
```

де `Overhead_{RocksDB} \approx 32..64` байти на запис для індексів LSM-дерева та метаданих версіонування.

Якщо система відстежує `U` унікальних користувачів одночасно в активному вікні (наприклад, `U = 100 000` активних сесій, `\lambda_{user} = 2 msg/s`, `T_w = 300 s`, `sizeof(Payload) = 256 B`), загальний розмір стану розраховується як:

```
N_{total} = U · (λ_{user} · T_w) = 100 000 · (2 · 300) = 60 000 000 записів
M_{total} = 60 000 000 · (256 + 48) B = 60 000 000 · 304 B ≈ 18.24 GB RAM
```

Цей розрахунок визначає вимоги до оперативної пам'яті кластера обробки потоків та оцінює тривалість створення розподіленого чекпоїнту на диск.

## 9. Модель надійності конвеєра: послідовна система та коефіцієнт готовності

Розглянемо надійність конвеєра як послідовного з'єднання `N` незалежних фільтрів. Якщо відмова будь-якого фільтра призводить до зупинки відповідного етапу обробки, а ймовірність безвідмовної роботи `i`-го фільтра впродовж часу `t` описується експоненційним законом `R_i(t) = e^{-\lambda_{f,i} · t}` (де `\lambda_{f,i}` — інтенсивність відмов `i`-ї стадії), тоді надійність усього конвеєра `R_{total}(t)`:

```
R_{total}(t) = ∏_{i=1}^N R_i(t) = e^{-(\sum_{i=1}^N λ_{f,i}) · t}
```

Середній час між відмовами конвеєра (Mean Time Between Failures, MTBF):

```
MTBF_{total} = 1 / (∑_{i=1}^N λ_{f,i}) = 1 / (∑_{i=1}^N (1 / MTBF_i))
```

### Коефіцієнт доступності (Availability) з буферизованими каналами

Якщо фільтри з'єднані синхронно без проміжних черг, доступність системи дорівнює добутку доступностей окремих вузлів:

```
A_{sync} = ∏_{i=1}^N A_i
```

Для 5 стадій з доступністю `A_i = 0.99` (99%):

```
A_{sync} = 0.99⁵ ≈ 0.951   (95.1% доступності — простій понад 17 днів на рік)
```

Введення буферизованих каналів із персистентними чергами ізолює відмови: короткочасний збій фільтра `F_i` тривалістю `T_{repair} < B / λ` не зупиняє роботу попередніх стадій конвеєра, підвищуючи сумарну доступність системи до рівня доступності брокера повідомлень (`A_{system} \approx A_{broker} \ge 0.9999`).

## 10. Покроковий числовий приклад розрахунку тристадійного конвеєра

**Умова задачі:**
Конвеєр обробки платіжних транзакцій складається з 3 стадій:
* Стадія 1 (Десеріалізація і перевірка підпису): `S₁ = 0.5 мс` (`μ₁ = 2000 msg/s`)
* Стадія 2 (Антифрод ML-скоринг — вузьке місце): `S₂ = 2.0 мс` (`μ₂ = 500 msg/s`)
* Стадія 3 (Запис у базу даних): `S₃ = 1.0 мс` (`μ₃ = 1000 msg/s`)

На вхід надходить пуассонівський потік `λ = 400 msg/s`.

**1. Розрахунок коефіцієнтів завантаження стадій:**
```
ρ₁ = 400 / 2000 = 0.20   (20% навантаження — стабільний легкий вузол)
ρ₂ = 400 / 500  = 0.80   (80% навантаження — гаряча стадія, вузьке місце)
ρ₃ = 400 / 1000 = 0.40   (40% навантаження — помірне завантаження)
```

**2. Розрахунок середнього часу перебування на кожній стадії (`W_i = 1 / (μ_i - λ)`):**
```
W₁ = 1 / (2000 - 400) = 1 / 1600 = 0.000625 с = 0.625 мс
W₂ = 1 / (500 - 400)  = 1 / 100  = 0.010000 с = 10.000 мс
W₃ = 1 / (1000 - 400) = 1 / 600  = 0.001667 с = 1.667 мс
```

**3. Розрахунок перцентилів затримок для найповільнішої стадії 2:**
```
W_{2,p50} = - ln(0.50) / 100 = 0.00693 с = 6.93 мс
W_{2,p95} = - ln(0.05) / 100 = 0.02996 с = 29.96 мс
W_{2,p99} = - ln(0.01) / 100 = 0.04605 с = 46.05 мс
```

**4. Сумарна середня затримка (End-to-End Latency):**
```
W_total = W₁ + W₂ + W₃
= 0.625 + 10.000 + 1.667      [підстановка розрахованих значень затримок стадій]
= 12.292 мс                   [арифметичне додавання затримок усіх трьох стадій]
```

Зверніть увагу: хоча чистий час обчислень трьох стадій становить лише `0.5 + 2.0 + 1.0 = 3.5 мс`, черга на вузькому місці (стадія 2 при завантаженні `ρ₂ = 0.8`) збільшує сумарну затримку до `12.292 мс`, а 99-й перцентиль затримки перевищує `48 мс`.

**5. Загальна кількість повідомлень у конвеєрі за законом Літтла:**
```
L_total = λ · W_total
= 400 · 0.012292              [застосування закону Літтла для інтенсивності 400 msg/s]
= 4.917 повідомлень           [добуток інтенсивності потоку на наскрізну затримку]
```

**6. Усунення вузького місця через паралельні воркери (Competing Consumers):**
Якщо на стадію 2 виділити пул із `m = 4` паралельних воркерів, сумарна інтенсивність обслуговування стадії 2 зросте до `μ₂' = 4 · 500 = 2000 msg/s`.

* Нове завантаження стадії 2: `ρ₂' = 400 / 2000 = 0.20`.
* Новий час перебування на стадії 2: `W₂' = 1 / (2000 - 400) = 0.625 мс`.
* Нова загальна затримка: `W_total' = 0.625 + 0.625 + 1.667 = 2.917 мс`.
* Новий 99-й перцентиль стадії 2: `W_{2,p99}' = - ln(0.01) / 1600 = 0.00288 с = 2.88 мс`.

Завдяки паралелізації вузького місця наскрізна затримка конвеєра скоротилася в 4.2 раза (з `12.29 мс` до `2.92 мс`), а хвостова затримка p99 зменшилася в 16 разів (з `46.05 мс` до `2.88 мс`).
