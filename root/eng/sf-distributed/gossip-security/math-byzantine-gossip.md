# 🧮 Математичне моделювання візантійського зараження та стійкості Brahms

У класичних епідемічних протоколах поширення інформації описується моделлю простих випадкових блукань або дифузії в однорідному графі, де кожен вузол чесно передає отримане оновлення `k` випадковим сусідам. Проте присутність візантійських вузлів докорінно змінює ймовірнісні характеристики системи: зловмисники можуть саботувати передачу (скидати пакети), поширювати еквівокаційні повідомлення або намагатися захопити топологію випадкової вибірки (Peer Sampling).

Нижче наведено строгий математичний аналіз трьох ключових аспектів безпеки епідемічних мереж: критичного коефіцієнта розгалуження (fanout) для подолання візантійського блокування, швидкості виявлення еквівокації та верхньої межі частки зловмисних вузлів у таблицях маршрутизації протоколу Brahms.

## 1. Поріг перколяції та критичний Fanout при відмовах зв'язку

Нехай мережа складається з `N` вузлів, серед яких `B` вузлів є візантійськими, а `H = N - B` — чесними. Позначимо частку візантійських вузлів як `f = B / N`.

Припустимо, що візантійські вузли застосовують стратегію «чорної діри» (Blackhole attack): вони приймають усі gossip-повідомлення, але ніколи не пересилають їх далі. Чесний вузол обирає `k` випадкових сусідів рівномірно з усієї популяції `N`.

Імовірність `p_h` того, що випадково обраний сусід є чесним:

```
p_h = (N - B) / N = 1 - f
```

Для успішного лавиноподібного поширення (епідемічного спалаху) очікувана кількість нових чесних вузлів, інфікованих одним чесним вузлом на початковій фазі, повинна перевищувати одиницю (умова надкритичного розгалуженого процесу Гальтона — Ватсона):

```
R₀ = k · p_h > 1
```

Підставимо ймовірність вибору чесного вузла:

```
k · (1 - f) > 1
k > 1 / (1 - f)
```

Звідси отримуємо мінімальний теоретичний поріг розгалуження `k_{min}` для забезпечення збіжності:

```
k_{min} = ⌈ 1 / (1 - f) ⌉
```

Для класичного візантійського порогу `f = 1/3` (33.3% зловмисників):

```
k > 1 / (1 - 1/3)
= 1 / (2/3)           [арифметичне спрощення частки]
= 1.5                 [отже k ≥ 2]
```

Проте поріг `k = 2` гарантує лише те, що епідемія не згасне миттєво. Щоб гарантувати доставку оновлення до всіх `H` чесних вузлів з імовірністю не менше `1 - ε` (де `ε` — допустима ймовірність невдачі, наприклад `10⁻⁶`), розмір fanout повинен враховувати хвіст розподілу невдалих контактів на фінальній фазі («проблема колекціонера купонів»).

Нехай на раунді `t` залишається `u_t` неінфікованих чесних вузлів. Імовірність того, що конкретний неінфікований чесний вузол не буде обраний жодним із `i_t` інфікованих чесних вузлів:

```
P(вузол не обрано) = (1 - 1/N)^(k · i_t)
≈ e^(-k · i_t / N)    [наближення для великих N через границю другого чудового степеня]
```

Для гарантованого покриття всього кластера за `O(log N)` раундів з надійністю `1 - ε` системний коефіцієнт `k` розраховується за формулою:

```
k ≥ (ln(N) + ln(1/ε)) / (1 - f)
```

**Приклад розрахунку:** Для кластера з `N = 10 000` вузлів при візантійській частці `f = 0.2` (20%) та цільовій надійності `ε = 10⁻⁴`:

```
ln(10 000) ≈ 9.2103
ln(1 / 10⁻⁴) = ln(10 000) ≈ 9.2103
Сума в чисельнику = 9.2103 + 9.2103 = 18.4206
Знаменник = 1 - 0.2 = 0.8
k ≥ 18.4206 / 0.8
= 23.025             [округлюємо вгору до цілого числа: k = 24]
```

## 2. Динаміка поширення доказу еквівокації (Fraud Proof)

Візантійський вузол `M` намагається розколоти мережу, надіславши повідомлення `m₁` із послідовністю `seq = S` одній групі чесних вузлів `A`, а повідомлення `m₂` (`m₁ ≠ m₂`) з тим самим `seq = S` — іншій групі `B`.

Нехай розміри груп складають `|A| = α · H` та `|B| = (1 - α) · H`.

Доказ еквівокації `P_{fraud} = (m₁, m₂, σ_M(m₁), σ_M(m₂))` формується в момент, коли будь-який чесний вузол із групи `A` отримує повідомлення `m₂` від групи `B`, або навпаки.

Імовірність `P_{cross}` того, що в даному раунді випадковий вибір вузла з групи `A` потрапить у групу `B`:

```
P_{cross} = |B| / N = (1 - α) · (1 - f)
```

Сумарна кількість перехресних контактів між групами за один раунд gossip-обміну з розгалуженням `k`:

```
E[X_{cross}]
= |A| · k · P_{cross}                         [за означенням матсподівання контактів]
= (α · H) · k · ((1 - α) · (H / N))          [підстановка розміру групи |A| та ймовірності]
= α · (1 - α) · k · (1 - f)² · N             [винесення множника (H / N)² = (1 - f)²]
```

Оскільки `α · (1 - α) ≥ (1/N) · (1 - 1/N)` для будь-якого непорожнього розбиття, математичне сподівання кількості перехресних контактів досягає мінімуму при `α = 1/N` (один вузол отримав `m₁`, решта `m₂`), і максимуму при симетричному розколі `α = 0.5`:

```
E[X_{cross}]_{max} = 0.25 · k · (1 - f)² · N
```

Для `N = 1000`, `k = 6`, `f = 0.1`:

```
E[X_{cross}]_{max}
= 0.25 · 6 · (0.9)² · 1000                    [підстановка числових параметрів]
= 1.5 · 0.81 · 1000                           [множення коефіцієнтів]
= 1215 контактів на раунд
```

Навіть при найгіршому для виявлення розколі (`α = 1 / H`, коли лише один чесний вузол отримав альтернативну гілку), імовірність того, що жоден з його `k` контактів не принесе альтернативну версію з решти мережі за `t` раундів, спадає експоненційно:

```
P(не виявлено за t раундів)
= (1 - (1 - f) · (1 - 1/H))^(k · t)           [ймовірність k·t незалежних невиборів]
≈ e^(-k · t · (1 - f))                        [наближення експонентою для великих H]
```

Для `k = 6` та `f = 0.2` імовірність приховати еквівокацію довше 3 раундів становить:

```
P(t = 3)
≈ e^(-6 · 3 · 0.8)                            [підстановка k=6, t=3, f=0.2]
= e^(-14.4)                                   [арифметичне обчислення степеня]
≈ 5.57 · 10⁻⁷
```

Це доводить, що криптографічно підписана еквівокація гарантовано виявляється чесною більшістю практично миттєво (`≤ 3` раунди), після чого генерований доказ `P_{fraud}` поширюється за стандартні `O(log N)` раундів і назавжди блокує зловмисника.

## 3. Математична межа стійкості вибірки сусідів у протоколі Brahms

Протокол Brahms призначений для побудови незміщеного сервісу вибірки сусідів (Peer Sampling) в умовах, коли візантійські вузли надсилають необмежену кількість повідомлень Push, намагаючись захопити таблиці маршрутизації (Routing Tables) чесних вузлів (Eclipse-атака).

Нехай кожен вузол підтримує таблицю розміром `V` (view size). У кожному раунді склад таблиці оновлюється за трьома джерелами:
1. Частка `α` формується з отриманих `Push`-запитів.
2. Частка `β` формується з відповідей на `Pull`-запити.
3. Частка `γ = 1 - α - β` формується з незалежного рандомізованого семплера (Unbiased Sampler) на основі випадкових блукань (Random Walks) довжини `l` та min-wise хешування.

Нехай `f` — частка візантійських вузлів у системі, а `ρ_t` — середня частка візантійських вузлів у таблицях маршрутизації чесних вузлів на раунді `t`.

Зловмисники можуть згенерувати довільну кількість `Push`-запитів, тому у найгіршому випадку вся частка `α` стає візантійською (100% забруднення Push-компоненти).

Частка візантійських записів у компоненти `Pull` відповідає поточному стану таблиць на попередньому кроці, тобто `ρ_t`.

Компонента семплера `γ` використовує випадкове блукання довжини `l = O(log N)` з поліноміальними хеш-функціями `h_j(x)`. Завдяки властивості марковського перемішування (mixing time) експандера та min-wise хешування, імовірність того, що випадкове блукання завершиться на візантійському вузлі, обмежена зверху величиною:

```
P(Sampler = Byzantine) ≤ f + δ(l)
```

де `δ(l) = λ^l` — експоненційно малий зсув, зумовлений другим за модулем власним значенням `λ < 1` матриці переходів графа зв'язності. Для `l ≥ 2 · log(N) / log(1/λ)` величина `δ(l) → 0`.

Рівняння динаміки частки візантійських вузлів у таблиці маршрутизації `ρ_{t+1}`:

```
ρ_{t+1} = α · 1 + β · ρ_t + γ · (f + δ)
```

У стаціонарному стані рівноваги (`ρ_{t+1} = ρ_t = ρ*`):

```
ρ*
= α + β · ρ* + γ · f                          [рівновага: заміна ρ_{t+1} = ρ_t = ρ* при δ -> 0]
```

Згрупуємо члени з `ρ*`:

```
ρ* · (1 - β) = α + γ · f
```

Оскільки `γ = 1 - α - β`, підставимо його:

```
ρ*
= (α + (1 - α - β) · f) / (1 - β)             [підстановка γ = 1 - α - β та ділення на (1 - β)]
= (α · (1 - f) + (1 - β) · f) / (1 - β)       [розкриття дужок у чисельнику: α + f - α·f - β·f]
= f + α · (1 - f) / (1 - β)                   [поділ на спільний знаменник (1 - β)]
```

Щоб система залишалася працездатною і візантійські вузли не змогли ізолювати чесний вузол (стан затемнення або Eclipse), частка зловмисників у таблиці `ρ*` повинна бути строго меншою за критичний поріг розриву графа `ρ_{crit} < 1` (на практиці `ρ* < 0.5`).

Для параметрів протоколу Brahms за замовчуванням:
- `α = 0.1` (10% Push)
- `β = 0.1` (10% Pull)
- `γ = 0.8` (80% Sampler)

При частці зловмисників у мережі `f = 0.2` (20%):

```
ρ* = 0.2 + (0.1 · (1 - 0.2)) / (1 - 0.1)
= 0.2 + (0.1 · 0.8) / 0.9      [множення чисельника]
= 0.2 + 0.08 / 0.9            [ділення дробу]
= 0.2 + 0.0889
= 0.2889                      [28.89% візантійських вузлів у таблиці]
```

**Висновок аналізу:** Навіть якщо ботнет надсилає нескінченний шторм `Push`-повідомлень, частка зловмисників у таблиці чесного вузла зростає лише з 20% до 28.89%, що залишає понад 71% гарантовано чесних зв'язків. Це строго унеможливлює ізоляцію вузла та доводить стійкість Brahms до Sybil-атак та спроб затемнення.
