# 🧮 Математика кворумів: принцип Діріхле, перетин множин та оцінка доступності

Щоб розподілена система гарантувала повернення найсвіжішого значення без центрального координатора, множини вузлів запису та читання мусять перетинатися за будь-яких умов. Цей математичний розбір містить комбінаторне доведення нерівності кворуму через принцип включень-виключень, узагальнення на випадок зваженого голосування Гіффорда, розрахунок імовірності застарілого читання при послаблених кворумах за гіпергеометричним розподілом, а також аналіз доступності, корельованих відмов та латентності через порядкові статистики.

## Комбінаторне доведення перетину кворумів

Нехай кластер складається з множини `S` реплік, загальна кількість яких дорівнює `|S| = N`. Кожен вузол має унікальний ідентифікатор `s[i] ∈ S`, де `i ∈ {1, 2, ..., N}`. Усі репліки є рівноправними, кожна має рівно один голос.

Коли клієнт виконує операцію запису, оновлення надсилається вузлам кластера, і операція вважається завершеною лише після отримання підтверджень від підмножини `W ⊆ S` розміром `|W| = w`. Аналогічно, операція читання опитує підмножину реплік `R ⊆ S` розміром `|R| = r`.

Позначимо через `W ∩ R` перетин множин вузлів, тобто множину тих реплік, які одночасно брали участь і в останньому підтвердженому записі, і в поточному читанні. За класичною формулою потужності об'єднання двох скінченних множин (принцип включень-виключень):

```
|W ∪ R|
= |W| + |R| - |W ∩ R|   [принцип включень-виключень для двох множин]
```

Оскільки обидві підмножини є частинами загального простору реплік `S` (тобто `W ⊆ S` та `R ⊆ S`), їхнє об'єднання також є підмножиною `S`, тобто `(W ∪ R) ⊆ S`. Звідси випливає верхня межа потужності об'єднання:

```
|W ∪ R| ≤ |S| = N
```

Підставимо формулу потужності об'єднання в нерівність:

```
|W| + |R| - |W ∩ R| ≤ N
w + r - |W ∩ R| ≤ N
|W ∩ R| ≥ w + r - N
```

Якщо конфігурація системи задовольняє умову `w + r > N`, тобто `w + r ≥ N + 1` для цілих чисел, ми отримуємо строгу нижню оцінку потужності перетину:

```
|W ∩ R|
≥ (N + 1) - N   [підстановка мінімального цілого значення w + r = N + 1]
= 1             [гарантована наявність щонайменше одного спільного вузла]
```

**Висновок:** Якщо сума розмірів кворуму запису `w` та кворуму читання `r` строго перевищує загальну кількість реплік `N`, потужність перетину `|W ∩ R|` не може бути меншою за `1`. Це означає, що за будь-якого вибору підмножин `W` та `R` існує щонайменше `w + r - N` спільних вузлів, які гарантовано отримали останній підтверджений запис і були опитані під час читання.

```
N = 5, w = 3, r = 3:
|W ∩ R|
≥ 3 + 3 - 5   [підстановка параметрів у формулу перетину]
= 1           [щонайменше 1 вузол гарантовано несе актуальну версію]

N = 5, w = 4, r = 3:
|W ∩ R|
≥ 4 + 3 - 5   [підстановка параметрів у формулу перетину]
= 2           [щонайменше 2 вузли гарантовано в перетині]
```

Цей результат є прямим наслідком комбінаторного [принципу Діріхле](topic:math-logic/pigeonhole-principle): якщо ми маємо `N` комірок і намагаємося сумарно розмістити в них `w + r` позначок (де `w` комірок позначено як «записано», а `r` комірок як «прочитано»), і загальна кількість позначок `w + r > N`, то за принципом шухляд щонайменше одна комірка обов'язково отримає дві позначки одночасно.

## Узагальнення Гіффорда: зважене кворумне голосування

У класичній моделі Девіда Гіффорда (1979) кожному вузлу `s[i] ∈ S` присвоюється невід'ємна цілочисельна вага (кількість голосів) `v[i] ≥ 0`. Це дозволяє гнучко враховувати гетерогенність серверів, виділяючи потужнішим або надійнішим машинам більшу вагу.

Загальна сума голосів у системі дорівнює:

```
V = ∑_{i=1}^{N} v[i]
```

Для довільної підмножини вузлів `X ⊆ S` її сумарна вага визначається як `V(X) = ∑_{s[i] ∈ X} v[i]`. Операція запису повинна зібрати підмножину вузлів `W`, таку що `V(W) ≥ W_{votes}`, а операція читання — підмножину `R`, таку що `V(R) ≥ R_{votes}`.

Дві фундаментальні теореми Гіффорда формулюють умови безпеки:

### 1. Гарантія свіжості читань
Щоб кожне читання перетиналася хоча б з однією реплікою останнього запису за вагою, сума порогів голосів повинна перевищувати загальну кількість голосів:

```
R_{votes} + W_{votes} > V
```

Доведення аналогічне дискретному випадку: оскільки `V(W ∪ R) = V(W) + V(R) - V(W ∩ R) ≤ V`, маємо `V(W ∩ R) ≥ V(W) + V(R) - V ≥ R_{votes} + W_{votes} - V ≥ 1`. Отже, сумарна вага перетину становить щонайменше 1 голос, що гарантує наявність актуальної версії.

### 2. Запобігання конфліктам паралельних записів
Щоб два незалежні записи не могли одночасно отримати кворум підтверджень і розділити історію системи на дві несумісні гілки (Split-Brain), кворум запису повинен становити строгу більшість від загальної кількості голосів:

```
2 · W_{votes} > V   (тобто W_{votes} > V / 2)
```

Якщо ця умова виконана, будь-які два кворуми запису `W_1` та `W_2` обов'язково перетинаються щонайменше по одному вузлу: `V(W_1 ∩ W_2) ≥ 2 · W_{votes} - V ≥ 1`. Вузол у перетині відхилить старіший або конкурентний запис, гарантуючи лінійний порядок оновлень.

## Імовірність застарілого читання при неповному кворумі

Розглянемо випадок, коли система заради зниження затримки або підвищення доступності налаштована так, що умова строгого перетину порушується:

```
w + r ≤ N
```

У такій конфігурації перетин `W ∩ R` може виявитися порожнім (`|W ∩ R| = 0`). Якщо операція читання потрапить на підмножину реплік, жодна з яких не входить до `W`, клієнт прочитає застаріле значення (stale read).

Обчислимо точну ймовірність такої події. Нехай у системі з `N` вузлів успішно виконано запис на випадкову підмножину з `w` вузлів. Отже, у кластері є рівно `w` оновлених вузлів та `N - w` застарілих вузлів.

Клієнт виконує читання, випадковим чином обираючи `r` вузлів із загальної кількості `N`. Загальна кількість способів обрати `r` вузлів із `N` задається біноміальним коефіцієнтом `C(N, r)`.

Кількість способів обрати `r` вузлів виключно серед `N - w` застарілих вузлів дорівнює `C(N - w, r)`.

За класичним гіпергеометричним розподілом імовірність того, що в прочитаній вибірці опиниться рівно `k` оновлених вузлів, виражається формулою:

```
P(|W ∩ R| = k) = [C(w, k) · C(N - w, r - k)] ÷ C(N, r)
```

Імовірність критичної помилки консистентності (повної відсутності перетину, тобто `k = 0`) дорівнює:

```
P(|W ∩ R| = 0) = C(N - w, r) ÷ C(N, r)
```

Розгорнемо формулу через факторіали для аналізу:

```
P(|W ∩ R| = 0)
= [(N - w)! ÷ (r! · (N - w - r)!)] ÷ [N! ÷ (r! · (N - r)!)]   [розкриття біноміальних коефіцієнтів]
= [(N - w)! · (N - r)!] ÷ [N! · (N - w - r)!]                 [скорочення r! та перетворення дробу]
= ∏_{i=0}^{r-1} (N - w - i) ÷ (N - i)                         [почленний розклад через спадні добутки]
```

### Числовий приклад розрахунку ризику

Нехай `N = 5`, кворум запису `w = 2`, кворум читання `r = 2`. Сума `w + r = 4 < 5` (умова перетину не виконується).

Розрахуємо ймовірність повернення застарілих даних:

```
P(|W ∩ R| = 0)
= C(5 - 2, 2) ÷ C(5, 2)   [підстановка параметрів N=5, w=2, r=2]
= C(3, 2) ÷ C(5, 2)       [обчислення різниці N - w = 3]
= 3 ÷ 10                  [обчислення комбінацій C(3,2)=3 та C(5,2)=10]
= 0.30                    [десятковий дріб: 30 % ризику застарілого читання]
```

Тобто майже кожен третій запит на читання (`30 %`) повертатиме застарілий стан, якщо в системі не встиг відпрацювати фоновий процес синхронізації.

Для порівняння зведемо ймовірності застарілого читання `P(stale)` для різних конфігурацій при `N = 5`:

| Конфігурація (w, r) | Сума w + r | Чи є строгий кворум? | P(\|W ∩ R\| = 0) | Імовірність перетину P(\|W ∩ R\| ≥ 1) |
| :--- | :--- | :--- | :--- | :--- |
| `w = 1, r = 1` | 2 | Ні | `C(4, 1) / C(5, 1) = 80 %` | 20 % |
| `w = 2, r = 1` | 3 | Ні | `C(3, 1) / C(5, 1) = 60 %` | 40 % |
| `w = 2, r = 2` | 4 | Ні | `C(3, 2) / C(5, 2) = 30 %` | 70 % |
| `w = 3, r = 2` | 5 | Ні (w+r = N) | `C(2, 2) / C(5, 2) = 10 %` | 90 % |
| `w = 3, r = 3` | 6 | **Так (w+r > N)** | `0 %` | **100 %** |
| `w = 4, r = 2` | 6 | **Так (w+r > N)** | `0 %` | **100 %** |

Зверніть увагу на рядок `w = 3, r = 2`, де `w + r = 5 = N`. Навіть коли сума кворумів дорівнює розміру кластера, ймовірність промаху становить `10 %`! Строгу гарантію дає лише строга нерівність `w + r > N`.

## Математична модель доступності (Availability)

Кворумні системи проєктуються не лише заради узгодженості, але й для стійкості до відмов вузлів. Розглянемо ймовірність успішного виконання операції в кластері з `N` вузлів, де кожен окремий вузол доступний незалежно від інших з імовірністю `p ∈ (0, 1)`.

Кількість доступних вузлів `K` у довільний момент часу є біноміальною випадковою величиною `K ~ Binomial(N, p)`:

```
P(K = k) = C(N, k) · p^k · (1 - p)^{N - k}
```

Операція, що вимагає кворуму розміром `Q` (де `Q = w` для запису або `Q = r` для читання), буде успішною тоді й тільки тоді, коли кількість працюючих вузлів `K` не менша за `Q`:

```
A(N, Q, p) = ∑_{k=Q}^{N} C(N, k) · p^k · (1 - p)^{N - k}
```

### Порівняння однолідерної моделі та кворумної реплікації

Розглянемо надійність вузла `p = 0.99` (доступність окремого сервера 99%, або два дев'ятки):

**1. Однолідерна система (Single Leader, N = 3):**
Для виконання запису обов'язково потрібен конкретний призначений лідер. Якщо лідер недоступний, запис неможливий (до завершення виборів).
```
A_leader = p = 0.99 (99 %)
```

**2. Кворумна більшість (N = 3, Q = 2):**
Запис успішний, якщо працюють хоча б 2 вузли з 3:
```
A(3, 2, 0.99)
= C(3, 2) · (0.99)² · (0.01)¹ + C(3, 3) · (0.99)³ · (0.01)⁰   [розгортання біноміальної суми для k=2 та k=3]
= 3 · 0.9801 · 0.01 + 1 · 0.970299 · 1                        [обчислення коефіцієнтів і степенів]
= 0.029403 + 0.970299                                         [додавання ймовірностей]
= 0.999702                                                    [підсумок: 99.97 % доступності]
```
Кворум підняв доступність з двох дев'яток (`0.99`) до майже чотирьох дев'яток (`0.9997`), скоротивши ймовірність простою з `1 %` до `0.03 %` (у 33 рази).

**3. Кворумна більшість (N = 5, Q = 3):**
Запис успішний, якщо працюють хоча б 3 вузли з 5:
```
A(5, 3, 0.99)
= C(5, 3) · p³ · (1-p)² + C(5, 4) · p⁴ · (1-p)¹ + C(5, 5) · p⁵ · (1-p)⁰   [сума для k=3, 4, 5]
= 10 · (0.99)³ · (0.0001) + 5 · (0.99)⁴ · (0.01) + 1 · (0.99)⁵            [підстановка p = 0.99]
= 10 · 0.970299 · 0.0001 + 5 · 0.960596 · 0.01 + 0.950990                [обчислення добутків]
= 0.000970 + 0.048030 + 0.950990                                         [підсумовування доданків]
= 0.999990                                                               [підсумок: 99.999 % (п'ять дев'яток)]
```
Кластер із 5 вузлів дає п'ять дев'яток доступності (`99.999 %`), допускаючи одночасну відмову будь-яких двох серверів.

## Корельовані відмови вузлів та фактор стійок (Rack Awareness)

Біноміальна модель припускає абсолютну незалежність збоїв серверів. Проте в реальних дата-центрах відмови часто є корельованими: знеструмлення стійки (PDU Failure) або збій комутатора Top-of-Rack (ToR Switch) одночасно вимикає всі 20 чи 40 серверів, розташованих у ній.

Нехай кластер складається з `N = 3` реплік. Припустимо, що ймовірність локального збою окремого сервера дорівнює `q_{node} = 0.01`, а ймовірність збою всієї стійки — `q_{rack} = 0.005`.

**Випадок 1: Наївне розміщення (усі 3 репліки в одній стійці).**
Якщо стійка знеструмлюється, усі 3 репліки гинуть одночасно. Ймовірність втрати кворуму:
```
P(Fail)
= q_{rack} + (1 - q_{rack}) · [3 · q_{node}² · (1 - q_{node}) + q_{node}³]   [формула повної ймовірності збою]
≈ 0.005 + 0.995 · [0.000297 + 0.000001]                                      [підстановка числових значень]
= 0.005 + 0.000296                                                           [додавання доданків]
= 0.005296                                                                   [доступність лише 99.47 %]
```
Спільна стійка звела нанівець перевагу трьох реплік: доступність обмежується надійністю однієї шафи.

**Випадок 2: Розподіл по трьох різних стійках (Rack-Awareness).**
Кожна репліка живиться від власної незалежної стійки. Повна ймовірність відмови одного вузла становить `q_{eff} = 1 - (1 - q_{node})(1 - q_{rack}) = 0.01 + 0.005 - 0.00005 = 0.01495`.
Оскільки стійки незалежні, втрата двох або більше вузлів становить:
```
P(Fail)
= C(3, 2) · q_{eff}² · (1 - q_{eff}) + C(3, 3) · q_{eff}³   [біноміальна ймовірність втрати кворуму]
= 3 · (0.01495)² · (0.98505) + (0.01495)³                   [обчислення добутків]
= 3 · 0.0002235 · 0.98505 + 0.0000033                       [підстановка квадратів]
= 0.000660 + 0.000003                                       [сума]
= 0.000663                                                  [доступність 99.933 %]
```
Фізичне рознесення реплік по окремих стійках скоротило ймовірність простою у 8 разів.

## Моделювання затримки через порядкові статистики

Коли координатор надсилає запит до `N` реплік паралельно, час відповіді кожної репліки `T[i]` є незалежною неперервною випадковою величиною з функцією розподілу `F(t) = P(T ≤ t)` та щільністю `f(t)`.

Координатор не чекає на всі `N` відповідей: йому достатньо дочекатися найшвидших `Q` підтверджень. Час очікування кворуму `T_{quorum}` точно описується `Q`-ю порядковою статистикою вибірки обсягу `N`:

```
T_{quorum} = T_{(Q)}
```

де `T_{(1)} ≤ T_{(2)} ≤ ... ≤ T_{(Q)} ≤ ... ≤ T_{(N)}`.

Функція розподілу ймовірностей для `Q`-ї порядкової статистики задається виразом:

```
F_{T_{(Q)}}(t) = P(T_{(Q)} ≤ t) = ∑_{k=Q}^{N} C(N, k) · [F(t)]^k · [1 - F(t)]^{N - k}
```

### Ефект хвоста затримки (Tail Latency Elimination)

Припустимо, що затримка відповіді окремої репліки `T` має логнормальний розподіл із довгим правим хвостом (через випадкові паузи Garbage Collection, дисковий ввід-вивід або мережеві колізії). Нехай 99-й перцентиль затримки одного вузла становить `t_{99} = 100 мс`, тоді як медіана — лише `t_{50} = 5 мс`.

Якщо операція вимагає повної згоди всіх вузлів (`Q = N`, суворе підтвердження):
```
P(T_{(N)} ≤ t) = [F(t)]^N
```
Для `N = 5`, щоб операція вклалася в 5 мс, потрібно, щоб усі 5 вузлів одночасно відповіли швидше за медіану:
```
P(T_{(5)} ≤ 5 мс)
= (0.50)⁵   [піднесення медіанної ймовірності до степеня N=5]
= 0.03125   [лише 3.1 % операцій виконаються швидше за 5 мс]
```
У 96.9% випадків операція очікуватиме найповільнішого учасника, стрімко деградуючи до затримок порядку 100 мс.

Якщо ж використовується кворум більшості `Q = 3` при `N = 5`:
```
P(T_{(3)} ≤ 5 мс)
= ∑_{k=3}^{5} C(5, k) · (0.50)^k · (0.50)^{5-k}   [формула порядкової статистики для Q=3]
= (10 + 5 + 1) · (0.50)⁵                          [винесення спільного множника (0.5)^5]
= 16 · 0.03125                                    [обчислення добутку суми коефіцієнтів]
= 0.50                                            [рівно 50 % операцій вкладаються в 5 мс!]
```

**Висновок:** Кворумний вибір `Q < N` ефективно відсікає `N - Q` найповільніших вузлів (tail latency). Завдяки цьому загальна затримка кворумної системи набагато ближча до середніх затримок окремих серверів і стійка до випадкових викидів продуктивності на окремих репліках.
