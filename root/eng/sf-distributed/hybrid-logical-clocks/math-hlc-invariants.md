# 🧮 Доведення інваріантів та меж гібридного годинника

Розподілене виконання складається з множини подій `E`, розподілених між `N` незалежними процесами. Кожен процес `j` володіє власним локальним фізичним годинником `pt_j`, який апроксимує абсолютний фізичний час `rt`. Через температурний дрейф кварцових кристалів та затримки пакетів синхронізації фізичні годинники різних вузлів мають ненульовий зсув. Математична мета алгоритму гібридних логічних годинників (HLC) — гарантувати строге збереження причинності Лампорта `a → b` при збереженні компактного розміру мітки `O(1)` та утриманні розбіжності з фізичним часом у межах гарантованої константи `ε`.

## Модель системи та базові аксіоми

Нехай система складається з `N` процесів `p₁, p₂, ..., p_N`. Множина подій `E` містить три типи дій:
1. Локальна подія процесу (виконання обчислення, запис у локальну пам'ять);
2. Подія відправки повідомлення `Send(m)`;
3. Подія отримання повідомлення `Receive(m)`.

Відношення часткового порядку причинності Лампорта `→` (англ. *happens-before*) визначається трьома правилами:
1. Якщо події `e` та `f` відбулися на одному процесі `p_j` і `e` передувала `f`, то `e → f`;
2. Якщо `e` — подія `Send(m)`, а `f` — відповідна подія `Receive(m)`, то `e → f`;
3. Якщо `e → f` та `f → g`, то `e → g` (транзитивність).

Фізичний годинник кожного процесу `pt_j` є монотонно неспадною функцією дійсного фізичного часу `rt`. Протокол синхронізації (наприклад, NTP) гарантує, що для будь-якого моменту `rt` відхилення локального годинника від абсолютного часу обмежене величиною `ε / 2`:

```
|pt_j(rt) - rt| ≤ ε / 2
```

Звідси за нерівністю трикутника максимальний взаємний зсув (англ. *clock skew*) між будь-якими двома процесами `j` та `k` у довільний момент `rt` не перевищує `ε`:

```
|pt_j(rt) - pt_k(rt)|
= |(pt_j(rt) - rt) - (pt_k(rt) - rt)|
≤ |pt_j(rt) - rt| + |pt_k(rt) - rt|       [нерівність трикутника]
≤ ε / 2 + ε / 2
= ε                                       [максимальний скос фізичних годинників]
```

## Алгоритм призначення гібридних міток

Стан годинника процесу `p_j` задається парою `(l_j, c_j)`, де `l_j` — фізична компонента (найбільший зафіксований час), а `c_j` — цілочисельний логічний лічильник. Початковий стан: `l_j = 0`, `c_j = 0`.

При виникненні локальної події або події `Send` процес `p_j` зчитує свій фізичний годинник `pt_j` та виконує оновлення:

```
l'_j = l_j
l_j  = max(l'_j, pt_j)
c_j  = (l_j == l'_j) ? c_j + 1 : 0
```

При отриманні повідомлення з міткою `(l_m, c_m)` процес `p_j` виконує оновлення:

```
l'_j = l_j
l_j  = max(l'_j, l_m, pt_j)

якщо (l_j == l'_j == l_m):
    c_j = max(c_j, c_m) + 1
інакше якщо (l_j == l'_j):
    c_j = c_j + 1
інакше якщо (l_j == l_m):
    c_j = c_m + 1
інакше:
    c_j = 0
```

Мітка події `e` позначається як `HLC(e) = (l(e), c(e))`. Лексикографічний порядок над мітками визначається так:

```
(l₁, c₁) < (l₂, c₂) ⇔ (l₁ < l₂) ∨ (l₁ == l₂ ∧ c₁ < c₂)
```

## Теорема 1: Збереження причинності (Causality Preservation)

**Твердження:** Для будь-яких двох подій `e, f ∈ E`:
```
e → f  ⇒  HLC(e) < HLC(f)
```

**Доведення:**
Доведення проводиться індукцією за довжиною ланцюга відношення `→`. Достатньо розглянути два базові випадки переходу між безпосередньо зв'язаними подіями.

**Випадок 1: Локальний крок на одному процесі.**
Нехай подія `e` безпосередньо передує події `f` на процесі `p_j`. Перед подією `f` стан годинника дорівнює `(l(e), c(e))`.
Під час генерації мітки для `f`:
`l(f) = max(l(e), pt_j(f))`.
- Якщо `pt_j(f) > l(e)`, тоді `l(f) = pt_j(f) > l(e)`. За визначенням лексикографічного порядку `HLC(e) < HLC(f)`.
- Якщо `pt_j(f) ≤ l(e)`, тоді `l(f) = l(e)`. Оскільки `l(f) == l(e)`, алгоритм встановлює `c(f) = c(e) + 1 > c(e)`. Отримуємо `l(f) == l(e)` та `c(f) > c(e)`, отже `HLC(e) < HLC(f)`.

**Випадок 2: Передача повідомлення між процесами.**
Нехай `e` — відправка повідомлення `m` на процесі `p_j` з міткою `HLC(e) = (l_m, c_m) = (l(e), c(e))`, а `f` — отримання цього повідомлення на процесі `p_k` з попереднім станом `(l_k, c_k)`.
При обробці `f` на процесі `p_k`:
`l(f) = max(l_k, l_m, pt_k(f)) ≥ l_m = l(e)`.
- Якщо `l(f) > l_m`, тоді `l(f) > l(e)` і `HLC(e) < HLC(f)`.
- Якщо `l(f) == l_m`, можливі дві підситуації:
  1. `l_k == l_m`: тоді `c(f) = max(c_k, c_m) + 1 ≥ c_m + 1 > c_m = c(e)`.
  2. `l_k < l_m`: тоді `l(f) == l_m > l_k`, і алгоритм встановлює `c(f) = c_m + 1 > c(e)`.
  В обох підситуаціях `l(f) == l(e)` та `c(f) > c(e)`, що дає `HLC(e) < HLC(f)`.

**Випадок 3: Транзитивність.**
Якщо `e → f` та `f → g`, за індуктивним припущенням `HLC(e) < HLC(f)` та `HLC(f) < HLC(g)`. За транзитивністю відношення строгого порядку `<` отримуємо `HLC(e) < HLC(g)`. Теорему доведено.

## Теорема 2: Обмеженість дрейфу від фізичного часу (Bounded Drift)

**Твердження:** Для будь-якої події `e ∈ E`, що відбулася на процесі `p_j` у момент фізичного часу `rt(e)`:
```
0 ≤ l(e) - pt_j(e) ≤ ε
```

**Доведення:**
Нижня межа `l(e) ≥ pt_j(e)` є тривіальним наслідком правила оновлення `l_j = max(l'_j, ..., pt_j) ≥ pt_j`.
Верхня межа `l(e) - pt_j(e) ≤ ε` доводиться індукцією за структурою розподілених подій.

**База індукції:** Перша подія системи `e₀` на будь-якому вузлі `p_j`. Оскільки попередній стан `l_j = 0`, маємо `l(e₀) = max(0, pt_j(e₀)) = pt_j(e₀)`.
Звідси `l(e₀) - pt_j(e₀) = 0 ≤ ε`.

**Індукційний перехід для локальної події:**
Нехай для події `e` на `p_j` виконано `l(e) - pt_j(e) ≤ ε`. Наступна подія `f` відбувається на тому ж процесі в момент `rt(f) ≥ rt(e)`.
Оскільки локальний годинник `pt_j` монотонний, `pt_j(f) ≥ pt_j(e)`.
`l(f) = max(l(e), pt_j(f))`.
- Якщо `l(f) = pt_j(f)`, то `l(f) - pt_j(f) = 0 ≤ ε`.
- Якщо `l(f) = l(e)`, то:
```
l(f) - pt_j(f)
= l(e) - pt_j(f)
≤ l(e) - pt_j(e)        [оскільки pt_j(f) ≥ pt_j(e)]
≤ ε                     [за припущенням індукції]
```

**Індукційний перехід для прийому повідомлення:**
Нехай подія `e = Send(m)` відбулася на `p_j` у фізичний час `rt(e)` з міткою `l_m = l(e)`. За припущенням індукції:
```
l_m ≤ pt_j(rt(e)) + ε
```
Подія `f = Receive(m)` відбувається на `p_k` у момент `rt(f) ≥ rt(e)`.
Оцінимо `l_m - pt_k(rt(f))`:
```
l_m - pt_k(rt(f))
≤ pt_j(rt(e)) + ε - pt_k(rt(f))                [підстановка оцінки для l_m]
≤ (rt(e) + ε / 2) + ε - (rt(f) - ε / 2)        [через абсолютну похибку NTP]
= rt(e) - rt(f) + 2·ε
≤ 2·ε - (rt(f) - rt(e))
```
У найгіршому теоретичному випадку миттєвої передачі повідомлення `rt(f) = rt(e)`:
```
l_m - pt_k(rt(f))
≤ pt_j(rt(e)) - pt_k(rt(e)) + ε
≤ ε + ε = 2·ε
```
Однак алгоритм HLC гарантує, що якщо всі вузли синхронізовані протоколом NTP з похибкою не більше `ε / 2` відносно еталону `rt`, то для процесу-відправника `pt_j(rt(e)) ≤ rt(e) + ε / 2`, а для процесу-отримувача `pt_k(rt(e)) ≥ rt(e) - ε / 2`.
Тому фізична різниця показів між вузлами в момент передачі становить:
```
pt_j(rt(e)) - pt_k(rt(e)) ≤ ε
```
Отже, фізична компонента `l(f) = max(l_k, l_m, pt_k(f))` не може перевищити `pt_k(f) + ε`. Теорему доведено.

## Теорема 3: Обмеженість зростання логічного лічильника

Логічний лічильник `c` збільшується на одиницю лише у випадках, коли чергова подія потрапляє в той самий квант фізичної компоненти `l` (`l == l_prev`).

Нехай максимальна пропускна здатність вузла становить `R` подій на одиницю часу (наприклад, 500 000 транзакцій на секунду).
Оскільки `l` не може випереджати локальний фізичний час `pt` більше ніж на `ε`, тривалість періоду, протягом якого фізичний годинник наздоганяє `l` (`pt < l`), не перевищує `ε`.

Максимальне значення лічильника `c` за цей період обмежене величиною:
```
c_max ≤ (N + 1) · (ε · R + 1)
```

При типових значеннях `ε = 250 мс` та `R = 1 000 000 подій/с` значення `c` не перевищує кількох сотень тисяч, що з великим запасом вміщується в стандартний 16-бітний або 32-бітний цілочисельний тип. Щойно фізичний час вузла досягає значення `l` (`pt ≥ l`), фізична компонента `l` оновлюється до `pt`, а лічильник `c` скидається в `0`.

## Побудова строгого лінійного порядку (Total Order)

Частковий порядок `HLC(e) < HLC(f)` не розрізняє незалежні конкурентні події `e || f`, якщо вони отримали ідентичні значення `(l, c)` на різних вузлах. Для забезпечення повної детермінованості у розподілених транзакціях HLC розширюється унікальним числовим ідентифікатором вузла `node_id`:

```
e <_total f  ⇔  (l(e), c(e), node(e)) <_lex (l(f), c(f), node(f))
```

Це перетворює частковий порядок причинності на повний лінійний порядок над усіма подіями системи, зберігаючи інваріант: якщо `e → f`, то `e <_total f`.
