# 🧮 Математика експоненційного відступу та джитера

У розподілених системах повторні спроби перетворюють лінійний потік запитів на динамічний процес зі зворотним зв'язком. Якщо ймовірність успішної обробки запиту сервером залежить від сумарної інтенсивності вхідного потоку, необдумана стратегія відступу здатна перевести систему зі стабільного стану в режим нескінченної черги та повного паралічу.

Математичний аналіз алгоритмів відступу дозволяє кількісно оцінити два протилежні критерії:
1. **Мінімізація часу очікування клієнта (Client Latency):** як швидко окремий клієнт отримає успішну відповідь після завершення тимчасового збою.
2. **Мінімізація пікового навантаження на сервер (Server Workload / Peak Density):** наскільки рівномірно розподіляються повторні спроби у часі та чи не створюють вони перевищення пропускної здатності черг обслуговування.

## Формальна модель параметрів відступу

Нехай клієнт виконує послідовність спроб `i = 0, 1, 2, ..., M`, де `i = 0` відповідає початковому запиту, а `i ≥ 1` — повторним спробам після невдачі.

Визначимо базові параметри системи:
* `t₀` — початковий базовий інтервал затримки (Base Backoff Interval, наприклад `100 мс`);
* `t_max` — верхня межа зрізання інтервалу (Cap Ceiling, наприклад `30 с`);
* `b` — основа експоненційного множника (Multiplicative Factor, зазвичай `b = 2`);
* `v(i)` — детерміністична стеля затримки для `i`-ї спроби:

```
v(i) = min(t_max, t₀ · bⁱ)
```

## Ймовірнісні моделі випадкового шуму (Джитера)

Рандомізація затримки (джитер) перетворює детерміністичний час очікування `t(i)` на неперервну випадкову величину `T(i)` з певною функцією густини ймовірності `f(t)` на інтервалі `[0, t_max]`.

Розглянемо три класичні математичні моделі джитера.

### 1. Повний джитер (Full Jitter)

У моделі повного джитера випадкова величина затримки `T_FJ(i)` має рівномірний розподіл `U(0, v(i))` на повному діапазоні від нуля до поточної експоненційної стелі `v(i)`:

```
T_FJ(i) ~ U(0, v(i))
```

Функція густини ймовірності `f_FJ(t)` має вигляд:

```
f_FJ(t) = 1 / v(i),   якщо 0 ≤ t ≤ v(i)
f_FJ(t) = 0,          якщо t < 0 або t > v(i)
```

Обчислимо математичне сподівання часу затримки `E[T_FJ(i)]`:

```
E[T_FJ(i)]
= ∫₀^{v(i)} t · f_FJ(t) dt         [означення математичного сподівання]
= ∫₀^{v(i)} (t / v(i)) dt          [підстановка густини рівномірного розподілу]
= (1 / v(i)) · [t² / 2]₀^{v(i)}    [інтегрування степеневої функції]
= (1 / v(i)) · (v(i)² / 2)         [підстановка меж інтегрування]
= v(i) / 2                         [скорочення на v(i)]
```

Обчислимо дисперсію затримки `Var(T_FJ(i))`:

```
Var(T_FJ(i))
= E[T_FJ(i)²] - (E[T_FJ(i)])²                  [формула дисперсії через моменти]
= ∫₀^{v(i)} (t² / v(i)) dt - (v(i) / 2)²       [підстановка інтеграла другого моменту]
= (1 / v(i)) · [t³ / 3]₀^{v(i)} - v(i)² / 4    [обчислення первісної]
= v(i)² / 3 - v(i)² / 4                        [зведення до спільного знаменника]
= (4 · v(i)² - 3 · v(i)²) / 12                 [алгебраїчне спрощення]
= v(i)² / 12                                   [підсумкова дисперсія Full Jitter]
```

### 2. Рівний джитер (Equal Jitter)

Модель рівного джитера фіксує половину поточного інтервалу `v(i) / 2` як гарантовану детерміністичну паузу, а другу половину рандомізує за рівномірним розподілом `U(0, v(i) / 2)`:

```
T_EJ(i) = (v(i) / 2) + U(0, v(i) / 2)
```

Функція густини ймовірності `f_EJ(t)` зосереджена на зсунутому відрізку `[v(i) / 2, v(i)]`:

```
f_EJ(t) = 2 / v(i),   якщо v(i) / 2 ≤ t ≤ v(i)
f_EJ(t) = 0,          поза цим інтервалом
```

Математичне сподівання затримки `E[T_EJ(i)]`:

```
E[T_EJ(i)]
= E[v(i) / 2] + E[U(0, v(i) / 2)]    [лінійність математичного сподівання]
= v(i) / 2 + (v(i) / 2) / 2          [сподівання рівномірного розподілу]
= v(i) / 2 + v(i) / 4                [арифметика дробів]
= 3 · v(i) / 4                       [підсумкове середнє Equal Jitter]
```

Дисперсія Equal Jitter `Var(T_EJ(i))`:

```
Var(T_EJ(i))
= Var(v(i) / 2 + U(0, v(i) / 2))     [детерміністична константа не змінює дисперсію]
= Var(U(0, v(i) / 2))                [властивість дисперсії зсунутої величини]
= (v(i) / 2)² / 12                   [формула дисперсії рівномірного розподілу для ширини v(i)/2]
= (v(i)² / 4) / 12                   [піднесення до квадрата]
= v(i)² / 48                         [підсумкова дисперсія Equal Jitter]
```

Дисперсія рівного джитера вчетверо менша за дисперсію повного джитера (`v(i)² / 48` проти `v(i)² / 12`). Це гарантує клієнту передбачувану нижню межу паузи, але збільшує концентрацію запитів на вужчому проміжку часу.

### 3. Декорельований джитер (Decorrelated Jitter)

У декорельованому відступі кожна наступна затримка обчислюється не від фіксованого кроку `t₀ · 2ⁱ`, а на основі фактичного випадкового значення затримки попередньої спроби `t_{prev}`:

```
t₀ = base
t_{i} = min(t_max, U(t₀, 3 · t_{i-1}))
```

Декорельований джитер утворює однорідний марковський випадковий процес із пам'яттю першого порядку. Його розподіл не є строго симетричним або рівномірним, оскільки верхня межа випадкового діапазону множиться на `3`, тоді як нижня завжди залишається рівною `t₀`.

Математичне сподівання `E[T_DJ(i) | t_{i-1}]` за умови, що значення не досягло `t_max`:

```
E[T_DJ(i) | t_{i-1}]
= (t₀ + 3 · t_{i-1}) / 2
= 0.5 · t₀ + 1.5 · t_{i-1}
```

Коефіцієнт зростання математичного сподівання становить `1.5` за спробу, що забезпечує плавне експоненційне зростання середньої затримки, одночасно розширюючи діапазон розсіювання запитів уже на перших двох ітераціях.

## Модель пікового навантаження при синхронній відмові N клієнтів

Розглянемо систему з `N` незалежних клієнтів, які одночасно отримують помилку (наприклад, скидання TCP-з'єднань через 400-мілісекундний failover бази даних) у момент часу `t = 0`.

Нехай пропускна здатність відновленого бекенда становить `C` запитів на секунду, а час обробки одного запиту дорівнює `τ` (вікно взаємного витіснення ресурсів).

### 1. Без джитера: детерміністичний сплеск (Dirac Delta Spike)

При детерміністичному експоненційному відступі кожен клієнт встановлює затримку `t(1) = v(1) = t₀ · 2¹`.

Миттєва інтенсивність вхідного потоку `λ(t)` описується сумою дельта-функцій Дірака:

```
λ(t) = N · δ(t - v(1))
```

Усі `N` запитів надходять у вузький часовий інтервал `Δt → 0`. Якщо `N > C · Δt`, черга вхідних сокетів `listen backlog` ядра операційної системи миттєво переповнюється. Сервер скидає надлишкові TCP SYN або повертає HTTP 503, змушуючи всі `N` клієнтів знову синхронно перейти на спробу `i = 2` з інтервалом `v(2) = t₀ · 2²`.

Виникає автоколивальний процес із періодом подвоєння, де амплітуда піків навантаження дорівнює повному розміру клієнтської бази `N`.

### 2. Full Jitter: рівномірна щільність навантаження

При використанні Full Jitter моменти відправки запитів `N` клієнтами розподілені незалежно та однаково за законом `U(0, v(1))`.

Інтенсивність потоку `λ_FJ(t)` на інтервалі `[0, v(1)]` є константою:

```
λ_FJ(t) = N / v(1) = N / (2 · t₀)
```

Пікова швидкість надходження запитів падає в сотні разів:

```
λ_peak(Full Jitter) / λ_peak(No Jitter) ≈ 1 / (v(1) · δ_burst)
```

Для того щоб бекенд успішно впорався з відновленням без повторних відмов, достатньо виконання умови безпечної ємності:

```
λ_FJ(t) ≤ C
⇒ N / v(1) ≤ C
⇒ v(1) ≥ N / C
```

Звідси випливає мінімально необхідна ширина вікна першого відступу для безпечного гасіння хвилі з `N` одночасних збоїв:

```
t₀ ≥ N / (2 · C)
```

**Числовий розрахунок:**
Нехай `N = 10 000` клієнтів, ємність бекенда `C = 2 000` запитів/с.
Мінімальний базовий відступ `t₀`:

```
t₀ ≥ 10 000 / (2 · 2 000) = 10 000 / 4 000 = 2.5 секунди.
```

Якщо базовий інтервал обрано рівним `2.5 с`, інтенсивність потоку повторів становитиме `10 000 / 5.0 с = 2 000` запитів/с, що строго дорівнює граничній пропускній здатності сервера і виключає виникнення черги.

## Ймовірність колізії запитів у вікні обробки

Нехай сервер здатний обробляти одночасно лише один запит до критичної секції бази даних тривалістю `τ`. Колізією вважається подія, коли принаймні два клієнти потрапляють в один і той самий інтервал часу шириною `2 · τ`.

Для `N` клієнтів, чиї спроби розподілені на інтервалі `W = v(i)`:

Ймовірність того, що випадково обраний клієнт `j` не потрапить у вікно `2 · τ` навколо моменту відправки клієнта `k`, дорівнює:

```
P(без колізії з одним клієнтом) = 1 - (2 · τ / W)
```

Ймовірність повної відсутності колізій для фіксованого клієнта серед решти `(N - 1)` конкурентів (за припущення `2 · τ ≪ W`):

```
P(no collision)
= (1 - 2 · τ / W)^{N - 1}
≈ 1 - (N - 1) · (2 · τ / W)    [наближення першого порядку бінома Ньютона]
```

Звідси ймовірність виникнення конфлікту за ресурс для окремого запиту становить:

```
P(collision) ≈ (2 · (N - 1) · τ) / W = (2 · (N - 1) · τ) / min(t_max, t₀ · 2ⁱ)
```

Формула наочно демонструє, що подвоєння вікна відступу на кожній ітерації (`W = t₀ · 2ⁱ`) скорочує ймовірність колізій рівно вдвічі, що забезпечує геометричну збіжність алгоритму до успішного виконання за малу кількість спроб `i ≤ 4`.

## Теорія масового обслуговування: динаміка черги M/M/1 з повторами

Розглянемо систему масового обслуговування з інтенсивністю первинного вхідного пуассонівського потоку `λ₀` та експоненційною інтенсивністю обслуговування сервером `μ`.

Нехай кожен запит, що не отримав негайної відповіді або завершився помилкою через переповнення буфера черги, повертається в систему як повторний запит із середньою затримкою відступу `D = E[T]`.

Позначимо через `p` ймовірність того, що окрема спроба виявиться невдалою. Сумарна інтенсивність вхідного потоку на сервер `λ_total` складається з нових транзакцій та нескінченного ряду повторних спроб:

```
λ_total
= λ₀ + λ₀ · p + λ₀ · p² + λ₀ · p³ + ...
= λ₀ · ∑_{k=0}^{∞} pᵏ
= λ₀ / (1 - p)      [сума нескінченної геометричної прогресії при p < 1]
```

Коефіцієнт завантаження системи `ρ` визначається відношенням сумарного потоку до продуктивності сервера:

```
ρ = λ_total / μ = λ₀ / (μ · (1 - p))
```

Для системи M/M/1 середня довжина черги `L_q` та середня затримка перебування запиту в черзі `W_q` виражаються через `ρ`:

```
L_q = ρ² / (1 - ρ)
W_q = ρ / (μ · (1 - ρ))
```

### Фазовий перехід та точка біфуркації (Catastrophic Collapse)

Якщо ймовірність помилки `p` залежить від завантаження сервера за монотонно зростаючою функцією `p = g(ρ)` (наприклад, через скидання пакетів при переповненні пулу потоків або черги сокетів):

```
ρ = λ₀ / (μ · (1 - g(ρ)))
⇒ λ₀ = μ · ρ · (1 - g(ρ))
```

Функція корисної пропускної здатності `f(ρ) = μ · ρ · (1 - g(ρ))` досягає максимуму в деякій критичній точці `ρ_crit`. Якщо первинне навантаження `λ₀` перевищує критичне значення `λ_max = f(ρ_crit)`:
* Стаціонарного розв'язку не існує.
* Завантаження стрибком переходить до `ρ → 1.0`.
* Середній час очікування `W_q → ∞`.
* Система зазнає катастрофічного колапсу (Cascading Failure), де 100% ресурсів сервера витрачаються на обробку повторних спроб, які клієнти вже обірвали за власними таймаутами.

## Алгебра множення повторів у багаторівневих графах викликів

Розглянемо спрямований ациклічний граф (DAG) мікросервісів глибиною `H`, де кожен рівень виконує виклик до наступного.

Нехай кожен сервіс на шляху налаштований на виконання не більше `r` повторних спроб (`r ≥ 1`) у разі виявлення помилки від свого безпосереднього нащадка:

```
Рівень 0 (Клієнт / API Gateway) ──> Рівень 1 ──> Рівень 2 ──> ... ──> Рівень H (Бекенд)
```

Якщо вузол найглибшого рівня `H` виходить із ладу і стабільно повертає помилку:
* Вузол рівня `H - 1` виконує `r` спроб до вузла `H`.
* Вузол рівня `H - 2`, не отримавши успішної відповіді від `H - 1`, повторює свій запит `r` разів. Кожна з цих спроб змушує `H - 1` знову виконати `r` спроб до `H`. Кількість викликів, що досягають вузла `H`, становить `r · r = r²`.
* По індукції, для дерева глибиною `H` кількість запитів `Q(H)`, що атакують збійний вузол `H` від одного клієнтського запиту на вході системи, дорівнює:

```
Q(H) = rᴴ
```

При глибині ланцюжка `H = 4` та стандартній конфігурації `r = 3` коефіцієнт ампліфікації навантаження становить:

```
Q(4) = 3⁴ = 81 запит на один початковий виклик.
```

Це доводить теорему про неприпустимість незалежних локальних повторів у глибині розподіленої архітектури: повтори повинні бути дозволені виключно на зовнішньому периметрі системи (Edge Gateway) або суворо лімітуватися спільним бюджетом.

## Математична модель бюджету повторів (Retry Budget)

Механізм бюджету повторів запобігає перевищенню критичної точки `ρ_crit` шляхом жорсткого обмеження частки повторного трафіку відносно загального обсягу успішних транзакцій.

Нехай токенний кошик має параметри:
* `C_token` — максимальна місткість кошика (Token Capacity);
* `r_deposit` — коефіцієнт поповнення (наприклад, `0.1` токена за кожен успішний запит зі статусом `200 OK`);
* `c_cost` — вартість однієї повторної спроби (`1.0` токен);
* `T_window` — розмір ковзного вікна оцінки швидкості.

Баланс токенів `B(t)` у момент часу `t` змінюється за рівнянням:

```
dB(t)/dt = r_deposit · λ_success(t) - c_cost · λ_retry(t)
за умови 0 ≤ B(t) ≤ C_token
```

У стаціонарному режимі максимальна частка повторів `R_max` обмежена строгою константою:

```
λ_retry_max
= (r_deposit / c_cost) · λ_success
= (0.1 / 1.0) · λ_success
= 0.10 · λ_success (тобто не більше 10% від корисного навантаження)
```

Під час тривалого збою, коли `λ_success → 0`, запас токенів вичерпується за час:

```
t_exhaust = B(0) / (c_cost · λ_retry_initial)
```

Після моменту `t_exhaust` швидкість повторних спроб примусово обнуляється (`λ_retry = 0`), що переводить клієнти в режим негайного повернення помилки (Fast-Fail) та гарантує незмінність сумарного потоку `λ_total ≤ λ₀`, унеможливлюючи перехід системи через критичну точку біфуркації.

## Математика хеджованих запитів (Hedged Requests) та важкохвості розподіли

Хеджування — це стратегія надсилання дублюючого запиту до альтернативного вузла-репліки до отримання відповіді на перший запит, якщо затримка першого перевищила певний квантиль `T_hedge` (зазвичай 95-й процентиль `p95`).

Нехай час відповіді сервера описується неперервною випадковою величиною `X` із функцією розподілу `F(x) = P(X ≤ x)`.

Якщо клієнт відправляє перший запит у `t = 0`, а дублюючий запит до незалежної репліки у `t = T_hedge`, результуючий час виконання транзакції `Y` визначається як мінімум двох випадкових величин:

```
Y = min(X₁, T_hedge + X₂)
```

Функція розподілу результуючого часу `F_Y(y)` для `y > T_hedge` при незалежних репліках:

```
P(Y > y)
= P(X₁ > y) · P(T_hedge + X₂ > y)      [незалежність реплік: добуток ймовірностей]
= (1 - F(y)) · (1 - F(y - T_hedge))    [вираження через функцію розподілу F(x)]
```

Звідси функція розподілу часу виконання хеджованого виклику:

```
F_Y(y) = 1 - (1 - F(y)) · (1 - F(y - T_hedge))
```

### Чому повтори ефективні для розподілів Парето і марні для експоненційних

У класичній теорії ймовірностей експоненційний розподіл часу обслуговування `F(t) = 1 - e^{-λ t}` володіє властивістю відсутності пам'яті (Memorylessness):

```
P(X > t + s | X > t) = P(X > s)
```

Для системи без пам'яті інформація про те, що запит уже триває `t` секунд, не дає жодної користі: залишковий час очікування має точно такий самий розподіл, як і час обробки абсолютно нового запиту. Скасування та перезапуск запиту в такій системі лише марнує вже витрачену роботу сервера без зменшення сумарного часу.

Однак у реальних розподілених системах затримки підпорядковуються важкохвостим розподілам (Heavy-Tailed Distributions), зокрема розподілу Парето з функцією виживання:

```
P(X > x) = (x_m / x)^α,   при x ≥ x_m, α > 0
```

Для розподілу Парето умовна ймовірність затримки демонструє ефект старіння (Positive Aging / Hazard Rate Decrease):

```
P(X > t + s | X > t)
= ((t + s) / t)^{-α}
> P(X > s) = (x_m / s)^α    [при великих t]
```

Це математично доводить, що якщо запит застряг у хвості розподілу (`t ≫ x_m`, наприклад через паузу збирача сміття GC або тимчасове блокування потоку на одному конкретному екземплярі), ймовірність того, що він завершиться швидко, стрімко спадає. Відправка паралельного дубліката (хеджування) на іншу «свіжу» репліку повертає час виконання у зону високої щільності ймовірності біля `x_m`, скорочуючи квантилі високого порядку `p99.9` у десятки разів.

### Оптимізація порогу хеджування

Задача оптимізації полягає у виборі такого порогу `T_hedge`, який мінімізує зважену функцію вартості:

```
Cost(T_hedge) = E[Y(T_hedge)] + γ · ΔLoad(T_hedge)
```

де `γ` — штрафний коефіцієнт вартості додаткового процесорного часу. Диференціюючи функцію вартості за `T_hedge`, отримуємо аналітичну умову оптимуму для розподілів із показником форми Парето `1 < α < 2`:

```
T_opt = x_m · (1 + (α - 1) / γ)^{1 / α}
```

У практичних системах вибір `T_hedge = p95` забезпечує значення, що відрізняється від теоретичного оптимуму менш ніж на 4%, гарантуючи надійне відсікання аномальних затримок при жорстко контрольованому 5-відсотковому навантаженні.

### Приклад розрахунку квантилів

Нехай базовий час відповіді `X` має розподіл із медіаною `p50 = 10 мс` та важким хвостом `p99 = 200 мс`, а поріг хеджування обрано як `T_hedge = p95 = 50 мс`.

Ймовірність того, що хеджована операція перевищить 200 мс:

```
P(Y > 200 мс)
= P(X₁ > 200 мс) · P(X₂ > 150 мс)     [незалежні репліки: T_hedge = 50 мс]
= 0.01 · 0.02                          [підстановка значень хвостів розподілу]
= 0.0002                               [числовий добуток: 0.02%]
```

Квантиль `p99.9` затримки падає з 500 мс до менш ніж 65 мс. При цьому додаткове навантаження на кластер становить лише частку запитів, що перевищили поріг `T_hedge`:

```
ΔLoad = 1 - F(T_hedge) = 1 - 0.95 = 5%
```

Хеджування скорочує затримку в хвості розподілу на порядок ціною збільшення трафіку лише на 5%, що робить його математично виправданим інструментом оптимізації затримок у високонавантажених кластерах.

## Порівняльний аналіз характеристик стратегій

У зведеній таблиці наведено аналітичні та експериментальні характеристики для базових параметрів `t₀ = 100 мс`, `t_max = 30 с`, `b = 2` на 4-й повторній спробі (`i = 4`, де `v(4) = min(30, 0.1 · 16) = 1.6 с`):

| Параметр / Метрика | Без джитера (No Jitter) | Full Jitter | Equal Jitter | Decorrelated Jitter |
| :--- | :--- | :--- | :--- | :--- |
| **Формула затримки `t(i)`** | `v(i)` | `U(0, v(i))` | `v(i)/2 + U(0, v(i)/2)` | `U(t₀, 3 · t_{prev})` |
| **Діапазон на 4-й спробі** | строго `1.6 с` | `[0, 1.6] с` | `[0.8, 1.6] с` | `[0.1, 4.8] с` (варіативний) |
| **Середня затримка `E[T]`** | `1.60 с` | `0.80 с` | `1.20 с` | `≈ 1.35 с` |
| **Дисперсія `Var(T)`** | `0.00 с²` | `0.213 с²` | `0.053 с²` | `≈ 0.680 с²` |
| **Пікова щільність запитів** | Максимальна (`N / Δt`) | Мінімальна (`N / 1.6`) | Середня (`N / 0.8`) | Мінімальна (`N / 4.7`) |
| **Ризик фазового захоплення** | 100% (гарантований) | 0% (відсутній) | Низький (< 5%) | 0% (відсутній) |
| **Сумарна робота сервера** | Катастрофічна | Оптимальна (1.0x) | Помірна (1.3x) | Оптимальна (1.05x) |

Математичний висновок однозначний: **Full Jitter** забезпечує мінімальне математичне сподівання клієнтської затримки (`v(i) / 2`) за одночасного досягнення найнижчої пікової щільності навантаження на відновлюваний бекенд, тоді як **Retry Budget** унеможливлює катастрофічний фазовий перехід системи у стан блокування.
