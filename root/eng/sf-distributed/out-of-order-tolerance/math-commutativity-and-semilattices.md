# 🧮 Алгебра безладу: напівґратки, монотонність та сходження станів

У розподілених системах повідомлення прибувають із довільними затримками, дублюються або міняються місцями. Якщо система вимагає координації для відновлення суворого порядку кожного повідомлення, її пропускна здатність падає до швидкості єдиного координатора. Математична альтернатива — побудувати простір станів і функцію переходів так, щоб фінальний стан системи був інваріантним відносно будь-якої перестановки вхідного потоку подій. Цей розділ формалізує умови безкоординаційного сходження через алгебраїчні структури — напівґратки, часткові порядки та монотонні відображення.

## Алгебраїчний фундамент: структура напівґратки злиття

Нехай `S` — множина всіх можливих станів вузла або розподіленого регістра. Визначимо бінарну операцію злиття `⊔ : S × S → S` (англ. *join / merge*, від лат. *jungere* — з'єднувати), яка приймає два довільні стани й обчислює їхній спільний результуючий стан.

Щоб система гарантовано сходилася до одного й того самого результату за будь-якого порядку доставки повідомлень, алгебраїчна пара `⟨S, ⊔⟩` повинна утворювати **комутативну напівґратку злиття** (англ. *join-semilattice*). Це накладає на операцію `⊔` три фундаментальні аксіоматичні вимоги:

1. **Ідемпотентність** (від лат. *idem* — той самий, та *potens* — здатний):
```
x ⊔ x = x      [повторне застосування оновлення не змінює вже досягнутого стану]
```
2. **Комутативність** (від лат. *commutare* — міняти місцями, змінювати):
```
x ⊔ y = y ⊔ x      [порядок надходження двох оновлень не впливає на результат]
```
3. **Асоціативність** (від лат. *associare* — з'єднувати, групувати):
```
(x ⊔ y) ⊔ z = x ⊔ (y ⊔ z)      [групування повідомлень у мережеві батчі не спотворює результат]
```

Якщо розподілений вузол стартує з початкового стану `s₀ ∈ S` і отримує послідовність оновлень `E = {e₁, e₂, ..., eₙ}`, де кожне оновлення `eᵢ` є елементом `S` (або породжує стан `sᵢ`), то результуючий стан обчислюється як ланцюг послідовних злиттів:

```
s_final = s₀ ⊔ e₁ ⊔ e₂ ⊔ ... ⊔ eₙ
```

Завдяки асоціативності та комутативності результат операції не залежить від розстановки дужок і від будь-якої бієкції (перестановки) індексів `π : {1, ..., n} → {1, ..., n}`:

```
s₀ ⊔ e₁ ⊔ e₂ ⊔ ... ⊔ eₙ
= s₀ ⊔ e_π(1) ⊔ e_π(2) ⊔ ... ⊔ e_π(n)      [комутативність і асоціативність напівґратки]
```

А завдяки ідемпотентності мережеве дублювання повідомлень `eᵢ` усувається природно без потреби у виділеному сховищі дедуплікації:

```
s ⊔ eᵢ ⊔ eᵢ
= s ⊔ (eᵢ ⊔ eᵢ)      [асоціативність операції злиття]
= s ⊔ eᵢ             [ідемпотентність: eᵢ ⊔ eᵢ = eᵢ]
```

## Частковий порядок та теорема про точну верхню межу

Будь-яка напівґратка злиття `⟨S, ⊔⟩` однозначно індукує відношення **часткового порядку** `≤` на множині станів `S`.

Визначимо відношення `≤` наступним чином: для будь-яких `x, y ∈ S`
```
x ≤ y ⇔ x ⊔ y = y
```

Твердження `x ≤ y` інтуїтивно означає: «стан `y` містить у собі всю інформацію зі стану `x`, а можливо й додаткові новіші дані». Доведемо, що це відношення задовольняє всі три класичні аксіоми часткового порядку (рефлексивність, антисиметричність, транзитивність):

```
1. Рефлексивність:
x ⊔ x = x ⇒ x ≤ x      [випливає з аксіоми ідемпотентності]

2. Антисиметричність:
Нехай x ≤ y та y ≤ x.
x ⊔ y = y              [за визначенням x ≤ y]
y ⊔ x = x              [за визначенням y ≤ x]
x = y ⊔ x = x ⊔ y = y  [комутативність ⊔: x = y]

3. Транзитивність:
Нехай x ≤ y та y ≤ z, тобто x ⊔ y = y та y ⊔ z = z.
x ⊔ z
= x ⊔ (y ⊔ z)          [підстановка y ⊔ z замість z]
= (x ⊔ y) ⊔ z          [асоціативність ⊔]
= y ⊔ z                [підстановка y замість x ⊔ y]
= z                    [підстановка z замість y ⊔ z]
Отже, x ⊔ z = z ⇒ x ≤ z.
```

З алгебраїчного погляду операція `x ⊔ y` є **точною верхньою межею** (лат. *supremum*, або найменшою верхньою гранню — *Least Upper Bound, LUB*) для підмножини `{x, y}` відносно порядку `≤`:
1. `x ≤ (x ⊔ y)`, оскільки `x ⊔ (x ⊔ y) = (x ⊔ x) ⊔ y = x ⊔ y`.
2. `y ≤ (x ⊔ y)`, оскільки `y ⊔ (x ⊔ y) = (y ⊔ y) ⊔ x = y ⊔ x = x ⊔ y`.
3. Якщо для деякого стану `z ∈ S` виконується `x ≤ z` та `y ≤ z`, то `(x ⊔ y) ≤ z`:
```
(x ⊔ y) ⊔ z
= x ⊔ (y ⊔ z)          [асоціативність]
= x ⊔ z                [оскільки y ≤ z ⇒ y ⊔ z = z]
= z                    [оскільки x ≤ z ⇒ x ⊔ z = z]
```

Це означає, що незалежно від послідовності надходження оновлень стан вузла монотонно зростає вздовж решітки порядку й неминуче сходиться до супремуму множини всіх надісланих фактів:

```
s_converged = sup(E) = ⨆_{e ∈ E} e
```

## Монотонні функції переходів і CALM-теорема

Розглянемо розподілену систему не просто як пасивне сховище, а як обчислювальний конвеєр. Нехай `f : S → T` — функція обчислення бізнес-результату або запиту.

Функція `f` називається **монотонною** (від грец. *μονοτονία* — збереження напрямку), якщо для будь-яких станів `x, y ∈ S`:
```
x ≤_S y ⇒ f(x) ≤_T f(y)
```

Математичний наслідок для розподілених систем формулюється як **CALM-теорема** (англ. *Consistency As Logical Monotonicity*, доведена Джозефом Геллерштейном та співавторами у 2010 році):
> Програма може бути узгоджено обчислена в розподіленій системі без жодної координації (блокувань, консенсусу, бар'єрів) тоді й лише тоді, коли її логіка є монотонною.

Якщо функція монотонна, отримання нових повідомлень (навіть із довільним запізненням) лише додає нову інформацію до результату `f(x)`, але ніколи не скасовує й не спростовує раніше зроблені монотонні висновки:

```
s_t1 ≤ s_t2 ⇒ f(s_t1) ≤ f(s_t2)      [нове знання не анулює старого]
```

Не-монотонні операції (наприклад, перевірка «чи баланс строго дорівнює нулю?», підрахунок точного розміру множини в певний момент часу, видалення без надгробка) вимагають оператора заперечення або квантора загальності над незавершеним станом. Вони не можуть бути толерантними до безладу без додаткової синхронізації або бар'єрів очікування (Watermark).

## Конструктивні приклади розподілених напівґраток

### 1. Позитивно-негативний лічильник (PN-Counter)

Розглянемо розподілений лічильник для системи з `n` вузлів. Звичайне ціле число `int` із операцією додавання не утворює напівґратку, оскільки додавання не є ідемпотентним `x + x ≠ x`.

Щоб зробити лічильник толерантним до дублікатів і перевпорядкування, розіб'ємо стан на два вектори розмірності `n`: вектор інкрементів `P` та вектор декрементів `N`.

```
Стан лічильника: S = ⟨P, N⟩, де P, N ∈ ℕⁿ
P = [p₁, p₂, ..., pₙ]  (де pᵢ — кількість додань вузлом i)
N = [n₁, n₂, ..., nₙ]  (де nᵢ — кількість віднімань вузлом i)

Операція злиття двох станів A = ⟨P_A, N_A⟩ та B = ⟨P_B, N_B⟩:
A ⊔ B = ⟨ [max(p_{A,1}, p_{B,1}), ..., max(p_{A,n}, p_{B,n})],
          [max(n_{A,1}, n_{B,1}), ..., max(n_{A,n}, n_{B,n})] ⟩

Функція зчитування скалярного значення:
Value(S) = ∑_{i=1}^{n} pᵢ - ∑_{i=1}^{n} nᵢ
```

Оскільки покомпонентний максимум `max(a, b)` є комутативним, асоціативним та ідемпотентним, злиття станів `A ⊔ B` гарантовано утворює напівґратку. Будь-які інкременти та декременти можуть передаватися між серверами в довільному порядку та довільну кількість разів — підсумкове значення завжди буде точним і однаковим на всіх репліках.

### 2. Регістр «Останній запис перемагає» (LWW-Register)

Нехай стан регістру — це пара `⟨v, t, n_id⟩`, де `v ∈ V` — значення, `t ∈ ℕ` — строго монотонна часова мітка (наприклад, логічний час Лампорта), а `n_id ∈ ℕ` — унікальний ідентифікатор вузла для детермінованого розв'язання нічиїх.

Операція злиття визначається через лексикографічний максимум:
```
⟨v₁, t₁, id₁⟩ ⊔ ⟨v₂, t₂, id₂⟩ =
  якщо t₁ > t₂                      → ⟨v₁, t₁, id₁⟩
  якщо t₂ > t₁                      → ⟨v₂, t₂, id₂⟩
  якщо t₁ = t₂ та id₁ > id₂         → ⟨v₁, t₁, id₁⟩
  інакше                             → ⟨v₂, t₂, id₂⟩
```

Перевіримо властивості напівґратки для послідовності з трьох оновлень, що надійшли в зворотному порядку через мережеві затримки: `e₁ = ⟨"A", 100, 1⟩`, `e₂ = ⟨"B", 105, 2⟩`, `e₃ = ⟨"C", 102, 1⟩`.

```
Порядок прибуття на вузол: e₂ → e₃ → e₁

Крок 1: s₁ = e₂ = ⟨"B", 105, 2⟩
Крок 2: s₂ = s₁ ⊔ e₃ = ⟨"B", 105, 2⟩ ⊔ ⟨"C", 102, 1⟩
            = ⟨"B", 105, 2⟩             [оскільки мітка 105 > 102]
Крок 3: s₃ = s₂ ⊔ e₁ = ⟨"B", 105, 2⟩ ⊔ ⟨"A", 100, 1⟩
            = ⟨"B", 105, 2⟩             [оскільки мітка 105 > 100]

Підсумок: s_final = ⟨"B", 105, 2⟩
```

Запізнілі оновлення `e₃` та `e₁` монотонно поглинаються операцією злиття. Результат залишається строго незмінним при будь-якій із `3! = 6` можливих перестановок надходження пакетів.

### 3. Додавання та видалення в OR-Set (Observed-Remove Set)

У множині з підтримкою видалення без координації елемент зберігається разом із множиною унікальних тегів додавання `AddTags` та множиною тегів видалення `RemoveTags` (надгробків):

```
Стан множини: S = ⟨AddSet, RemoveSet⟩
де AddSet ⊆ (Element × Tag), RemoveSet ⊆ Tag

Операція злиття двох реплік A та B:
A ⊔ B = ⟨AddSet_A ∪ AddSet_B, RemoveSet_A ∪ RemoveSet_B⟩

Предикат наявності елемента x у множині:
Contains(S, x) ⇔ ∃ tag : ⟨x, tag⟩ ∈ AddSet ∧ tag ∉ RemoveSet
```

Оскільки операція об'єднання множин `∪` є комутативною, асоціативною та ідемпотентною, структура `⟨S, ⊔⟩` є напівґраткою. Якщо операція видалення елемента `x` (додавання тегу в `RemoveSet`) прибуває на репліку раніше, ніж саме додавання `⟨x, tag⟩` (унаслідок асиметричної затримки каналів), система записує надгробок у `RemoveSet`. Коли запізнілий пакет додавання нарешті надходить, предикат `Contains` миттєво повертає `false`, оскільки згенерований тег уже зафіксований у множині видалених.

## Межі застосовності алгебраїчної толерантності

Комутативні напівґратки забезпечують повну стійкість до безладу, проте накладають фундаментальні математичні обмеження:
1. **Зростання метаданих:** Для дедуплікації та розв'язання конфліктів структури змушені зберігати монотонні маркери (надгробки, векторні годинники, множини тегів), розмір яких монотонно зростає з часом.
2. **Неможливість глобальних інваріантів без координації:** Інваріанти на кшталт «сума балансів двох користувачів `A + B ≥ 0`» або «кількість проданих квитків `≤ 100`» не можуть бути виражені через комутативну напівґратку для операцій зменшення ліміту. Операція `withdraw(x)` не комутує з умовою вичерпання спільного залишку, тому для збереження глобальних обмежень система змушена переходити від безкоординаційних напівґраток до протоколів кворумів або консенсусу.
