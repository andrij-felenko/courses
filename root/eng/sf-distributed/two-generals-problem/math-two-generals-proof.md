# 🧮 Математичне доведення неможливості консенсусу над ненадійним каналом

Цей документ містить строге математичне доведення теореми про неможливість досягнення детермінованого консенсусу двома процесами через канал зв'язку з можливими втратами повідомлень методом індукції за довжиною траси та через структури Кріпке епістемічної логіки.

## Формальна модель системи

Розглянемо розподілену систему, що складається з двох процесів (вузлів) `p_1` та `p_2` і ненадійного дуплексного каналу зв'язку `C`.

### Процеси та стани
Кожен процес `p_i` (`i ∈ {1, 2}`) формалізується як детермінований скінченний або нескінченний автомат:
* `S_i` — множина локальних станів процесу `p_i`.
* `s_i^0 ∈ S_i` — початковий стан процесу `p_i`.
* `M` — скінченний алфавіт повідомлень, які можуть передаватися каналом.
* `δ_i: S_i × (M ∪ {∅}) → S_i × (M ∪ {∅})` — детермінована функція переходів, яка за поточним станом і отриманим повідомленням (або його відсутністю `∅`) обчислює новий стан та повідомлення для відправки.
* `decide_i: S_i → {0, 1, ⊥}` — функція прийняття рішення, де `0` означає «відбій/відступ», `1` — «атака/коміт», а `⊥` — «рішення ще не прийнято».

### Канал зв'язку та події
Канал зв'язку `C` може доставляти повідомлення або втрачати їх:
* Якщо процес `p_1` відправляє повідомлення `m ∈ M`, подія в каналі може набувати одного з двох значень:
  * `DELIVER(m)` — повідомлення успішно доставлено процесу `p_2`.
  * `DROP(m)` — повідомлення безповоротно втрачено (стерто каналом).

Канал не спотворює вміст повідомлень і не генерує фантомних пакетів (відсутність візантійських спотворень).

### Виконання системи
Виконання (траса) `E` — це послідовність конфігурацій `(s_1^0, s_2^0) → (s_1^1, s_2^1) → ... → (s_1^k, s_2^k)`, породжена чергою відправлених і доставлених або втрачених повідомлень.

Позначимо через `hist_i(E)` локальну історію спостережень процесу `p_i` у виконанні `E` (послідовність внутрішніх станів, відправлених і фактично отриманих повідомлень). Оскільки процес є детермінованим автоматом, його рішення однозначно визначається його локальною історією:

```
decide_i(E) = decide_i(hist_i(E))
```

## Формальні вимоги до протоколу консенсусу

Протокол `P` є коректним детермінованим алгоритмом консенсусу, якщо для будь-якого виконання `E` виконуються три умови:

1. **Одностайність (Agreement):**
```
∀ E: (decide_1(E) ≠ ⊥ ∧ decide_2(E) ≠ ⊥) ⇒ decide_1(E) = decide_2(E)
```
Жодне виконання не може призвести до того, що один процес вирішить `1`, а інший — `0`.

2. **Слушність (Validity):**
* Якщо канал втрачає абсолютно всі повідомлення від самого початку (`∀ m: DROP(m)`), процеси не мають права приймати рішення `1`:
```
E_null = (всі повідомлення втрачено) ⇒ decide_1(E_null) = decide_2(E_null) = 0
```
* Існує бодай одне бездефектне виконання `E_good`, у якому всі повідомлення доставляються і обидва процеси вирішують `1`:
```
∃ E_good: decide_1(E_good) = decide_2(E_good) = 1
```

3. **Завершуваність (Termination):**
Для будь-якого виконання `E`, у якому зв'язок зрештою дозволяє передати достатню кількість пакетів, обидва процеси за скінченний час переходять зі стану `⊥` до термінального рішення:
```
∀ i ∈ {1, 2}: ∃ t_term: ∀ t ≥ t_term: decide_i(s_i^t) ∈ {0, 1}
```

## Теорема про неможливість консенсусу

> **Теорема (Jim Gray, 1978):**
> У моделі системи з двома процесами та ненадійним каналом зв'язку з імовірністю втрати повідомлень `p > 0` не існує детермінованого протоколу, який одночасно задовольняє вимоги Agreement, Validity та Termination.

### Доведення від супротивного через індукцію за довжиною траси

Припустимо протилежне: нехай існує коректний детермінований протокол `P`, який задовольняє всі три умови.

З умови Termination та Validity випливає, що існує виконання `E`, у якому обидва процеси вирішують `1`, надіславши скінченну кількість повідомлень `k ≥ 1`.

Розглянемо множину всіх можливих успішних виконань, де процеси доходять рішення `decide_1 = decide_2 = 1`. Оскільки кількість повідомлень у кожному такому виконанні є натуральним числом, за принципом цілкомвпорядкованості множини натуральних чисел існує виконання `E_min` із **найменшою можливою кількістю успішно доставлених повідомлень** `k`.

Нехай у виконанні `E_min` послідовність доставлених повідомлень має вигляд:
```
M(E_min) = ⟨m_1, m_2, m_3, ..., m_k⟩
```
де `m_k` — останнє успішно передане повідомлення в системі (надіслане, без обмеження загальності, процесом `p_1` до `p_2`).

За визначенням `E_min`:
```
decide_1(E_min) = 1
decide_2(E_min) = 1
```

Тепер побудуємо суміжне виконання `E'`, яке відрізняється від `E_min` лише однією подією: останнє повідомлення `m_k` **втрачається в каналі** (`DROP(m_k)`).
Усі попередні повідомлення `⟨m_1, m_2, ..., m_{k-1}⟩` доставляються точно так само, як і в `E_min`.

Проаналізуємо локальні історії обох процесів у виконанні `E'`:

1. **Для процесу-відправника `p_1`:**
Процес `p_1` сформував повідомлення `m_k` на основі своєї локальної історії `hist_1` після відправки/отримання перших `k-1` повідомлень і передав його в мережевий сокет. Оскільки процес не отримує миттєвого зворотного зв'язку від самого факту польоту пакета крізь простір, його локальний стан у момент прийняття рішення не залежить від того, чи згорів пакет у дорозі:
```
hist_1(E') = hist_1(E_min)
```
Оскільки протокол детермінований:
```
decide_1(E') = decide_1(hist_1(E')) = decide_1(hist_1(E_min)) = 1
```

2. **Для процесу-одержувача `p_2`:**
Процес `p_2` у виконанні `E'` не отримав повідомлення `m_k`.
Проте за припущенням протокол `P` є абсолютно надійним і гарантує властивість **Agreement** для будь-яких трас, включно з трасою `E'`.
Оскільки `decide_1(E') = 1`, процес `p_2` зобов'язаний також прийняти рішення `1`:
```
decide_2(E') = 1
```

Отже, у виконанні `E'` обидва процеси вирішили `1`:
```
decide_1(E') = 1  ∧  decide_2(E') = 1
```

Але виконання `E'` містить лише `k - 1` успішно доставлених повідомлень:
```
M(E') = ⟨m_1, m_2, ..., m_{k-1}⟩
```

Це означає, що повідомлення `m_k` було повністю надлишковим для прийняття рішення `1`. Ми отримали успішне виконання `E'` з кількістю повідомлень `k - 1`, що суперечить вихідному припущенню про те, що `k` — це мінімальна кількість повідомлень для досягнення консенсусу `1`.

Застосовуючи цей крок індуктивно, ми зводимо кількість необхідних повідомлень від `k` до `k - 1`, від `k - 1` до `k - 2`, і зрештою до `k = 0`.

Але для `k = 0` виконання `E_0` є трасою, де взагалі не було доставлено жодного повідомлення.
За властивістю **Validity**:
```
decide_1(E_0) = decide_2(E_0) = 0
```
Водночас за нашим індуктивним ланцюгом:
```
decide_1(E_0) = decide_2(E_0) = 1
```

Отримано фундаментальну суперечність (`0 = 1`). Отже, вихідне припущення про існування детермінованого протоколу консенсусу `P` є хибним.

Теорему доведено. `■`

## Епістемічне доведення через спільне знання (Halpern & Moses)

Епістемічна логіка дозволяє довести неможливість консенсусу через топологічну зв'язність простору можливих світів.

### Модель Кріпке для розподіленої системи
Нехай `Ω` — множина всіх можливих глобальних станів (світів) системи `ω = (s_1, s_2, channel_state)`.

Визначимо відношення нерозрізненності `~_i` для процесу `p_i`:
```
ω ~_i ω'  ⇔  s_i(ω) = s_i(ω')
```
Світи `ω` та `ω'` є еквівалентними для процесу `p_i`, якщо його локальний стан у цих світах ідентичний.

Оператор знання процесу `p_i` визначається як:
```
(M, ω) ⊨ K_i(φ)  ⇔  ∀ ω' ∈ Ω: (ω ~_i ω' ⇒ (M, ω') ⊨ φ)
```
(Процес `p_i` знає факт `φ`, якщо `φ` істинне в усіх світах, нерозрізненних для `p_i`).

Оператор взаємного знання першого порядку:
```
E^1(φ) ≡ K_1(φ) ∧ K_2(φ)
```

Оператор взаємного знання порядку `k`:
```
E^k(φ) ≡ E(E^{k-1}(φ))
```

Оператор спільного знання (Common Knowledge):
```
C(φ) ≡ ⋀_{k=1}^∞ E^k(φ)
```

### Лема про необхідність спільного знання для одночасних дій
Для того, щоб два процеси детерміновано виконали дію `A` в один і той самий логічний момент часу за відсутності спільної пам'яті, факт готовності до дії `φ` мусить бути спільним знанням:

```
Дія A виконується детерміновано  ⇒  C(φ)
```

### Недосяжність спільного знання у зв'язному графі світів
Розглянемо граф станів, де вершинами є можливі світи `ω ∈ Ω`, а ребрами — відношення нерозрізненності `~_1` та `~_2`.

Нехай `ω_k` — стан після успішної доставки `k` повідомлень, де нібито досягнуто `C(φ)`.
Розглянемо ланцюг переходів:
```
ω_k  ~_1  ω_{k, drop}  ~_2  ω_{k-1}  ~_1  ω_{k-1, drop}  ~_2  ...  ~_1  ω_0
```

1. У стані `ω_k` надіслано останній пакет `m_k`. Процес `p_1` не знає, чи пакет доставлено, тому `ω_k ~_1 ω_{k, drop}`.
2. У стані `ω_{k, drop}` процес `p_2` не отримав `m_k`. Його стан ідентичний станову `ω_{k-1}`, де `m_k` взагалі не відправлявся, тому `ω_{k, drop} ~_2 ω_{k-1}`.

Оскільки всі можливі виконання системи з'єднані скінченним ланцюгом нерозрізненності з нульовим станом `ω_0`, у якому `(M, ω_0) ⊭ φ`:

```
∀ k < ∞: (M, ω_k) ⊭ C(φ)
```

Стан спільного знання `C(φ)` не може бути сформований за скінченну кількість кроків у жодній системі, де граф переходів містить ребра втрати повідомлень.

Звідси консенсус є математично недосяжним.
