# 🧮 Математика колізій та ефективності дедуплікації в CAS

Контентно-адресовані сховища (CAS) покладаються на два фундаментальні математичні стовпи: криптографічну мізерність імовірності колізій хеш-функцій та статистичну модель розбиття неструктурованого потоку даних на контентно-визначені фрагменти (Content-Defined Chunking, CDC).

---

### 1. Імовірність колізій та парадокс днів народження

У сховищі, адресованому за вмістом, збіг хешів двох різних блоків даних (колізія) призводить до незворотної катастрофи: система вважає новий блок ідентичним старому і перезаписує посилання або ігнорує запис, що спричиняє непомітну втрату інформації (*silent data corruption*).

Нехай криптографічна хеш-функція генерує дайджест довжиною `b` бітів. Загальна кількість можливих унікальних хеш-значень становить:

```
N = 2ᵇ
```

Якщо в систему послідовно додається `n` випадкових унікальних об'єктів, імовірність `P_no_coll(n)` того, що всі `n` об'єктів отримають строго різні хеші, дорівнює добутку умовних імовірностей для кожного послідовного кроку:

```
P_no_coll(n)
= (1 - 0/N) · (1 - 1/N) · (1 - 2/N) · ... · (1 - (n - 1)/N)    [добуток імовірностей кожного кроку]
= ∏_{i=0}^{n-1} (1 - i/N)                                      [компактний запис добутку]
```

Застосуємо наближення Тейлора першого порядку `1 - x ≈ e⁻ˣ` для малих значень аргументу `x = i/N` (оскільки `i << N`):

```
P_no_coll(n)
≈ ∏_{i=0}^{n-1} e^(-i / N)                                      [наближення 1 - x ≈ e^(-x)]
= e^( - ∑_{i=0}^{n-1} i / N )                                   [властивість експоненти: добуток степенів]
= e^( - (n · (n - 1)) / (2 · N) )                              [сума арифметичної прогресії]
≈ e^( - n² / (2 · N) )                                          [для великих n: n · (n - 1) ≈ n²]
```

Тоді підсумкова ймовірність виникнення хоча б однієї випадкової колізії `P_coll(n)` виражається як:

```
P_coll(n)
= 1 - P_no_coll(n)                                              [імовірність протилежної події]
≈ 1 - e^( - n² / (2 · 2ᵇ) )                                     [підстановка N = 2ᵇ]
```

Для значень `n² << 2ᵇ` експоненту можна розкласти в ряд `e^(-y) ≈ 1 - y`, що дає класичну формулу оцінки ризику парадоксу днів народження:

```
P_coll(n) ≈ n² / (2 · 2ᵇ) = n² / 2ᵇ⁺¹
```

### 2. Розрахунок імовірності для реальних масштабів сховищ

Оцінимо ймовірність колізії для хмарного об'єктного сховища екзобайтного масштабу, що містить `n = 10¹²` (один трильйон) об'єктів та `n = 10¹⁸` (один квінтильйон) об'єктів при різній розрядності хешу `b`.

**1. Випадок 128 біт (алгоритми MD5, MurmurHash3):**
Для `b = 128`, `2ᵇ = 2¹²⁸ ≈ 3.40 · 10³⁸`.

```
P_coll(10¹²)
≈ (10¹²)² / (2 · 2¹²⁸)                                          [формула колізії для трильйона об'єктів]
= 10²⁴ / (6.80 · 10³⁸)                                          [піднесення до квадрата]
≈ 1.47 · 10⁻¹⁵                                                  [імовірність колізії]
```

```
P_coll(10¹⁸)
≈ (10¹⁸)² / (2 · 2¹²⁸)                                          [для квінтильйона об'єктів]
= 10³⁶ / (6.80 · 10³⁸)                                          [піднесення до квадрата]
≈ 1.47 · 10⁻³ ≈ 0.15%                                           [неприпустимо високий ризик: 1 випадок із 680]
```

**2. Випадок 160 біт (алгоритм SHA-1 у ранньому Git):**
Для `b = 160`, `2ᵇ = 2¹⁶⁰ ≈ 1.46 · 10⁴⁸`.

```
P_coll(10¹⁸)
≈ (10¹⁸)² / (2 · 2¹⁶⁰)                                          [для квінтильйона об'єктів]
= 10³⁶ / (2.92 · 10⁴⁸)                                          [піднесення до квадрата]
≈ 3.42 · 10⁻¹³                                                  [вкрай мала випадкова колізія]
```

**3. Випадок 256 біт (алгоритми SHA-256, BLAKE3 у сучасному CAS):**
Для `b = 256`, `2ᵇ = 2²⁵⁶ ≈ 1.1579 · 10⁷⁷`.

```
P_coll(10¹⁸)
≈ (10¹⁸)² / (2 · 2²⁵⁶)                                          [для квінтильйона об'єктів]
= 10³⁶ / (2.3158 · 10⁷⁷)                                        [піднесення до квадрата]
≈ 4.31 · 10⁻⁴²                                                  [астрономічно зникаюча величина]
```

Для фізичного порівняння: ймовірність того, що апаратний модуль пам'яті сервера DDR5 зазнає невиправленої помилки біта (Uncorrectable Multi-bit Error) через фонові космічні промені протягом однієї секунди, становить близько `10⁻¹²`. Отже, математичний ризик колізії SHA-256 у квінтильйон разів нижчий за фізичну відмову кремнієвих транзисторів сервера.

### 3. Математична модель дедуплікації та розбиття даних

Нехай система зберігає сукупний масив файлів загальним нестисненим обсягом `S_raw` байтів. Після проходження контенту крізь CAS-конвеєр та усунення однакових блоків унікальний фізичний обсяг становить `S_unique` байтів.

Коефіцієнт дедуплікації `R_dedup` та відсоток економії дискового простору `ΔS` виражаються співвідношеннями:

```
R_dedup = S_raw / S_unique

ΔS = (1 - 1 / R_dedup) · 100% = ((S_raw - S_unique) / S_raw) · 100%
```

Якщо система зберігає 100 ТБ даних, а унікальні блоки займають 20 ТБ:
```
R_dedup = 100 / 20 = 5.0 (або 5:1)
ΔS = (1 - 1/5.0) · 100% = 80% економії простору
```

### 4. Проблема зсуву меж у блоковому розбитті (Boundary Shift Problem)

Розглянемо файл довжиною `K` байтів. 

**1. Фіксований крок (Fixed-size Chunking):**
Файл ділиться на статичні блоки розміром `B` (наприклад, `B = 64 КБ`):
```
Межі_блоків = {0, B, 2B, 3B, ..., m·B}
```

Якщо на початок файлу вставляється `k` нових байтів (де `1 ≤ k < B`), нові межі зміщуються:
```
Нові_межі = {0, B, 2B, ...} -> вміст блоку i' відповідає зрізу [i·B - k, (i+1)·B - k]
```

Оскільки вміст кожного блоку змінився через бітовий зсув, криптографічні хеші всіх `m` блоків змінюються лавиноподібно:
```
Ефективність_дедуплікації = 0%
```

**2. Контентно-визначене розбиття (Content-Defined Chunking, CDC):**
У CDC межа блоку визначається не лічильником байтів, а значенням хешу ковзного вікна довжиною `w` (зазвичай `w = 48` або `64` байти) над потоком даних.

Нехай `H_w(x)` — хеш полінома Рабіна або алгоритму FastCDC над вікном байтів, що закінчується в позиції `x`. Межа чанка оголошується в точці `x`, якщо молодші `m` бітів хешу збігаються з нульовою маскою:

```
H_w(x) mod 2ᵐ = 0
```

Імовірність `p` того, що довільний байт задовольнить умову межі:

```
p = 1 / 2ᵐ = 1 / D
```

де `D = 2ᵐ` — цільовий середній розмір чанка (наприклад, для `m = 13`, `D = 2¹³ = 8192` байти, тобто 8 КБ).

Довжина чанка `L` є дискретною випадковою величиною з геометричним розподілом із параметром успіху `p`:

```
P(L = k) = (1 - p)^(k - 1) · p                                  [ймовірність отримати межу рівно на k-му байті]
```

Математичне сподівання довжини чанка `E[L]` та дисперсія `Var(L)` дорівнюють:

```
E[L]
= ∑_{k=1}^{∞} k · P(L = k)                                      [означення математичного сподівання]
= ∑_{k=1}^{∞} k · (1 - p)^(k - 1) · p                           [підстановка ймовірності]
= 1 / p = D                                                     [сума ряду: E[L] = 2ᵐ]

Var(L) = (1 - p) / p² = D · (D - 1) ≈ D²
```

Коли в початок файлу додаються `k` нових байтів, алгоритм CDC обчислює новий перший чанк. Але щойно ковзне вікно проходить точку вставки та натрапляє на наступну характерну комбінацію бітів усередині незміненого тексту, межа чанка відновлюється за тим самим вмістом.

Усі наступні чанки `2, 3, ..., m` отримують точно такі самі межі та ідентичні хеші. Кількість змінених блоків суворо обмежена одиницею незалежно від розміру файлу:

```
Збережена_дедуплікація ≈ (m - 1) / m ≈ 1 - D / K
```

Для файлу розміром 100 МБ (`K = 100` МБ) із середнім чанком 8 КБ (`D = 8` КБ) дедуплікація після довільної вставки в середину тексту зберігає:

```
Збережена_частка = 1 - 8192 / 104857600 ≈ 99.992%
```

### 5. Нормалізація довжини чанка у FastCDC

Класичний геометричний розподіл має високу дисперсію `Var(L) ≈ D²`, що призводить до появи як надто малих чанків (накладні витрати на метадані), так і надто великих (втрата дедуплікації).

Алгоритм FastCDC вирішує цю проблему нормалізацією за двома межами: мінімальним розміром `Min` (наприклад, `Min = D / 4`) та максимальним розміром `Max` (наприклад, `Max = D · 4`), а також динамічною зміною маски:

1. На інтервалі `[0, Min)` перевірка маски взагалі вимикається: алгоритм безумовно пропускає байти, ліквідуючи мікрочанки.
2. На інтервалі `[Min, Norm)` застосовується жорсткіша маска з більшою кількістю нульових бітів (`m + 1` біт).
3. На інтервалі `[Norm, Max)` застосовується м'якша маска (`m - 1` біт), що прискорює пошук межі до досягнення `Max`.
4. Якщо позиція досягає `Max`, межа ставиться примусово.

Це стискає розподіл довжини чанка навколо цільового значення `D`, зменшуючи дисперсію у 4–6 разів при збереженні понад 98% теоретичного потенціалу дедуплікації.

### 6. Закон Ціпфа та економіка дедуплікації на масштабі

Розподіл популярності однакових фрагментів даних у великих сховищах (зокрема у репозиторіях вихідного коду чи веб-асетах) підпорядковується емпіричному закону Ціпфа: частота появи `k`-го за популярністю унікального блоку `f(k)` обернено пропорційна його рангу:

```
f(k) = C / k^s
```

де `s ≈ 1` — показник ступеня, а `C` — нормувальна константа.

Це означає, що відносно невелика частка найпопулярніших спільних бібліотек (як-от базові шари контейнерів, популярні NPM-пакети React чи Lodash) генерує левову частку звернень та дублікатів. Завдяки контентній адресації CAS-сховище отримує логарифмічне уповільнення зростання фізичного обсягу: при лінійному збільшенні кількості користувацьких релізів загальний необхідний дисковий простір зростає пропорційно `ln(n)`, що перетворює CAS на економічно найвигіднішу архітектуру довготривалого зберігання.
