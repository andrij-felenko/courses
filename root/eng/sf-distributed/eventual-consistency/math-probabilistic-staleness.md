# 🧮 Імовірнісна оцінка застарілості даних (PBS) та математика збіжності

У системах із кінцевою узгодженістю головне інженерне питання звучить не як «чи зійдуться дані взагалі?», а як **«з якою ймовірністю читач отримає свіже значення через `Δt` мілісекунд після запису?»** та **«яка ймовірність того, що дані відстають не більше ніж на `k` версій?»**.

Цей розділ розгортає повний математичний апарат:
1. **Комбінаторику часткових кворумів** у статичному стані;
2. **Динамічну модель PBS (Probabilistic Bounded Staleness)** із неперервним часом мережевих затримок;
3. **Ймовірнісну модель `k`-застарілості** за Пуассонівського потоку оновлень;
4. **Ланцюги Маркова та поглинальні стани** в епідемічних протоколах фонової анти-ентропії;
5. **Алгебраїчні властивості напівґраток (Join-Semilattices)** у безконфліктних типах даних (CRDT);
6. **Теорію часткового порядку векторних годинників** та ймовірність виникнення паралельних гілок;
7. **Математику усікання векторних годинників** та межі помилкової конкурентності;
8. **Кількісне порівняння Read-Repair та фонової анти-ентропії**;
9. **Оцінку складності та обсягу трафіку** при звірці станів за деревами Меркла.

## 1. Комбінаторика часткових кворумів (Статична модель)

Нехай дані реплікуються на `N` фізичних вузлів. Для кожної операції запису клієнт очікує підтвердження від `W` довільних вузлів (`W ≤ N`), а для операції читання опитує `R` довільних вузлів (`R ≤ N`).

Якщо виконується класична нерівність кворумного перетину `R + W > N`, то за принципом Діріхле множина оновлених вузлів `W_set` та множина опитаних вузлів `R_set` обов'язково мають непорожній перетин:

```
|W_set ∩ R_set| ≥ R + W - N ≥ 1
```

У цьому разі ймовірність читання застарілих даних дорівнює нулю (`P(stale) = 0`).

Однак для зменшення латентності в георозподілених системах часто обирають часткові або слабкі кворуми (Sloppy Quorums), де `R + W ≤ N` (наприклад, конфігурація `N = 5, W = 2, R = 2`, де `R + W = 4 ≤ 5`).

### Ймовірність нульового перетину за гіпергеометричним розподілом

Нехай координатор запису випадково й рівномірно обирає підмножину `W_set ⊂ S` розміром `|W_set| = W` серед усіх `N` вузлів. Координатор читання незалежно обирає підмножину `R_set ⊂ S` розміром `|R_set| = R`.

Загальна кількість способів обрати `R` вузлів із `N` становить:

```
Кількість вибірок читання = C(N, R) = N! / (R! · (N - R)!)
```

Операція читання поверне застарілий стан (не зачепить жодного оновленого вузла) тоді й лише тоді, коли всі `R` вузлів будуть обрані виключно з множини `N - W` неоновлених вузлів. Кількість таких несприятливих конфігурацій дорівнює `C(N - W, R)`.

Звідси ймовірність отримання застарілого значення в статичній моделі визначається формулою гіпергеометричного розподілу:

```
P(stale | N, W, R) = C(N - W, R) / C(N, R)
```

Розпишемо покрокове обчислення для типового кластера `N = 5, W = 2, R = 2`:

```
C(5 - 2, 2)
= C(3, 2)               [віднімання: N - W = 5 - 2 = 3]
= 3! / (2! · (3 - 2)!)  [формула комбінацій C(n, k)]
= 3                      [кількість способів обрати 2 вузли з 3 неоновлених]

C(5, 2)
= 5! / (2! · (5 - 2)!)  [загальна кількість вибірок розміром 2]
= (5 · 4) / (2 · 1)     [скорочення факторіалів 5! / 3!]
= 10                    [загальна кількість пар серед 5 вузлів]

P(stale)
= 3 / 10                [ділення сприятливих варіантів на загальну кількість]
= 0.30                  [ймовірність застарілого читання 30%]
```

Ймовірність отримати актуальні свіжі дані (`P(fresh) = 1 - P(stale)`) дорівнює:

```
P(fresh | N=5, W=2, R=2)
= 1 - 0.30              [доповнення до повної ймовірності]
= 0.70                  [ймовірність свіжого читання 70%]
```

### Розподіл потужності перетину кворумів

У загальному випадку операція читання може зачепити `k` оновлених вузлів (`0 ≤ k ≤ min(W, R)`). Ймовірність того, що в кворум читання потрапить рівно `k` свіжих реплік, становить:

```
P(|W_set ∩ R_set| = k) = [ C(W, k) · C(N - W, R - k) ] / C(N, R)
```

Для кластера `N = 5, W = 2, R = 2`:
- `k = 0` (застаріле читання): `[C(2,0) · C(3,2)] / C(5,2) = [1 · 3] / 10 = 0.30` (30%);
- `k = 1` (один свіжий вузол): `[C(2,1) · C(3,1)] / C(5,2) = [2 · 3] / 10 = 0.60` (60%);
- `k = 2` (обидва свіжі вузли): `[C(2,2) · C(3,0)] / C(5,2) = [1 · 1] / 10 = 0.10` (10%).

Математичне сподівання кількості оновлених вузлів у вибірці читання становить:

```
E[k]
= R · (W / N)           [властивість гіпергеометричного розподілу]
= 2 · (2 / 5)           [підстановка R=2, W=2, N=5]
= 0.80                  [середня кількість свіжих вузлів у запиті]
```

## 2. Динамічна модель PBS (Probabilistic Bounded Staleness)

У динамічній системі оновлення поширюється мережею асинхронно. Що більше часу `Δt` минуло від моменту підтвердження запису до початку читання, то більше реплік встигли отримати й застосувати оновлення у фоні.

Теорія **імовірнісної обмеженої застарілості** (PBS, розроблена Пітером Бейлісом, Аланом Фекіте, Алі Ґодсі та Джозефом Геллерстайном) формалізує дві метрики:
1. `(k, Δt)-staleness`: ймовірність того, що запит читання через час `Δt` після запису версії `v` поверне значення версії `≥ v - k`;
2. `t-staleness`: максимальний вік спостережуваних даних у фізичних одиницях часу.

### Неперервна часова модель передачі повідомлень

Нехай затримка доставки та застосування повідомлення реплікації від координатора до довільної репліки `i` є випадковою величиною `L_w` із функцією розподілу ймовірностей (Cumulative Distribution Function, CDF):

```
F_w(t) = P(L_w ≤ t)
```

Затримка опитування репліки під час операції читання (час проходження запиту туди й назад, RTT) є випадковою величиною `L_r` із функцією розподілу `F_r(t) = P(L_r ≤ t)` та густиною ймовірності `f_r(t) = d F_r(t) / dt`.

Нехай операція читання ініціюється через час `Δt` після того, як координатор запису відправив оновлення реплікам.

Для конкретної репліки `i`, оновлення буде успішно прочитано, якщо момент доставки запису `L_w` передує моменту завершення читання з цієї репліки `Δt + L_r`.

Ймовірність `p_i(Δt)` того, що репліка `i` містить свіжі дані на момент зчитування, обчислюється через інтеграл згортки:

```
p_i(Δt)
= P(L_w ≤ Δt + L_r)                      [умова прибуття запису раніше за відповідь читання]
= ∫₀^∞ P(L_w ≤ Δt + t_r) · f_r(t_r) dt_r  [інтегрування за всіма значеннями затримки читання t_r]
= ∫₀^∞ F_w(Δt + t_r) · f_r(t_r) dt_r     [вираження через функцію розподілу запису F_w]
```

### Приклад розрахунку з експоненційним розподілом затримок мережі

Припустимо, що час фонової реплікації має експоненційний розподіл із параметром інтенсивності `λ` (середній час реплікації `E[L_w] = 1/λ = 20 мс`, тобто `λ = 0.05 мс⁻¹`), а затримка читання фіксована й становить `t_r = 10 мс`:

```
F_w(t) = 1 - e^(-λ · t),   для t ≥ 0
```

Тоді ймовірність успішного оновлення окремої репліки через інтервал `Δt` дорівнює:

```
p(Δt)
= 1 - e^(-λ · (Δt + t_r))     [підстановка експоненційного закону розподілу]
= 1 - e^(-0.05 · (Δt + 10))   [підстановка параметрів λ = 0.05 та t_r = 10 мс]
```

Обчислимо значення `p(Δt)` для інтервалів `Δt = 0 мс`, `Δt = 40 мс` та `Δt = 100 мс`:

```
1. При Δt = 0 мс (негайне читання):
   p(0)
   = 1 - e^(-0.05 · (0 + 10))  [підстановка Δt = 0]
   = 1 - e^(-0.5)              [обчислення показника 0.05 · 10 = 0.5]
   ≈ 1 - 0.6065                [значення експоненти e^(-0.5)]
   = 0.3935                    [частка оновлених вузлів 39.35%]

2. При Δt = 40 мс:
   p(40)
   = 1 - e^(-0.05 · (40 + 10)) [підстановка Δt = 40]
   = 1 - e^(-2.5)              [обчислення показника 0.05 · 50 = 2.5]
   ≈ 1 - 0.0821                [значення експоненти e^(-2.5)]
   = 0.9179                    [частка оновлених вузлів 91.79%]

3. При Δt = 100 мс:
   p(100)
   = 1 - e^(-0.05 · (100 + 10)) [підстановка Δt = 100]
   = 1 - e^(-5.5)               [обчислення показника 0.05 · 110 = 5.5]
   ≈ 1 - 0.0041                 [значення експоненти e^(-5.5)]
   = 0.9959                     [частка оновлених вузлів 99.59%]
```

### Ймовірність свіжого читання для кворуму з R вузлів

Нехай кількість оновлених реплік у кластері з `N` вузлів у момент `Δt` є випадковою величиною `M`, що має біноміальний розподіл `M ~ Binomial(N, p(Δt))`.

Операція читання опитує випадкову підмножину з `R` реплік. Ймовірність того, що серед `R` опитаних вузлів **хоча б один** містить свіже оновлення, за формулою повної ймовірності дорівнює:

```
P(fresh | Δt) = 1 - ∑_{m=0}^{N} P(M = m) · [ C(N - m, R) / C(N, R) ]
```

де:
- `P(M = m) = C(N, m) · [p(Δt)]ᵐ · [1 - p(Δt)]^(N - m)` — ймовірність того, що рівно `m` із `N` реплік уже отримали оновлення;
- `C(N - m, R) / C(N, R)` — умовна ймовірність того, що всі `R` опитаних вузлів виявилися серед `N - m` застарілих (якщо `N - m < R`, цей дріб вважається рівним нулю).

Для кластера `N = 5, R = 2` та часу затримки `Δt = 40 мс` (де `p = 0.9179`):

```
P(stale | Δt = 40 мс)
= P(M=0)·C(5,2)/10 + P(M=1)·C(4,2)/10 + P(M=2)·C(3,2)/10 + P(M=3)·C(2,2)/10  [розклад за повною групою подій]
≈ 0.0000 + 0.0002 + 0.0028 + 0.0152                                             [сума ймовірностей для m ≤ 3]
≈ 0.0182                                                                        [ймовірність застарілого читання 1.82%]

P(fresh | Δt = 40 мс)
= 1 - 0.0182                                                                    [доповнення до 1]
= 0.9818                                                                        [ймовірність свіжого читання 98.18%]
```

## 3. Модель `k`-застарілості за Пуассонівського потоку записів

У реальних системах операції запису надходять безперервним потоком. Нехай нові версії для одного ключа надходять як Пуассонівський процес з інтенсивністю `λ_w` (кількість записів на секунду).

Нехай час повної реплікації одного запису на випадковий вузол має експоненційний розподіл із параметром `μ` (інтенсивність реплікації).

### Розподіл відставання версій на одній репліці

Кількість невідтворених оновлень `K` на окремому вузлі моделюється як стан системи масового обслуговування `M/M/∞`. Стаціонарний розподіл кількості відсталих версій є Пуассонівським із параметром навантаження `ρ = λ_w / μ`:

```
P(K = j) = (ρʲ · e^(-ρ)) / j!,   для j = 0, 1, 2, ...
```

Якщо операція читання опитує один вузол (`R = 1`), ймовірність того, що зчитане значення відстає не більше ніж на `k` версій від найновішого, становить:

```
P(K ≤ k) = ∑_{j=0}^{k} (ρʲ · e^(-ρ)) / j!
```

Для системи, де записи надходять кожні 100 мс (`λ_w = 10 с⁻¹`), а реплікація триває в середньому 20 мс (`μ = 50 с⁻¹`), параметр навантаження становить `ρ = 10 / 50 = 0.20`:

```
P(K = 0)
= e^(-0.20)              [підстановка j = 0]
≈ 0.8187                 [частка ідеально свіжих читань 81.87%]

P(K = 1)
= 0.20 · e^(-0.20)       [підстановка j = 1]
≈ 0.1637                 [відставання рівно на 1 версію 16.37%]

P(K = 2)
= (0.20² / 2) · e^(-0.20)[підстановка j = 2]
≈ 0.0164                 [відставання на 2 версії 1.64%]

P(K ≤ 1)
= P(K = 0) + P(K = 1)    [сума ймовірностей для відставання ≤ 1]
= 0.8187 + 0.1637
= 0.9824                 [ймовірність відхилення ≤ 1 становить 98.24%]
```

## 4. Ланцюги Маркова та поглинальні стани в протоколах Anti-Entropy

Коли клієнтські операції припиняються, система переходить у фазу автономної фонової синхронізації (Anti-Entropy). Найпоширенішим механізмом є епідемічні протоколи пліток (Gossip Protocols).

### Марковська модель розповсюдження інформації

Нехай кластер складається з `N` вузлів. Позначимо через `S_t ∈ {1, 2, ..., N}` кількість вузлів, які володіють оновленням на дискретному кроці `t`.

Процес `{S_t, t ≥ 0}` є однорідним марковським ланцюгом із простором станів `{1, 2, ..., N}` та єдиним поглинальним станом `N`.

У Push-протоколі кожен із `i` оновлених вузлів незалежно обирає випадкового партнера для передачі оновлення. Ймовірність того, що конкретний неоновлений вузол отримає хоча б одне повідомлення, дорівнює:

```
q(i) = 1 - (1 - 1/N)ⁱ
```

Кількість новоінфікованих вузлів за один раунд має біноміальний розподіл `Binomial(N - i, q(i))`. Елементи матриці ймовірностей переходів `P_{i, j} = P(S_{t+1} = j | S_t = i)` для `j ≥ i` обчислюються як:

```
P_{i, j} = C(N - i, j - i) · [q(i)]^(j - i) · [1 - q(i)]^(N - j)
```

Для `j < i` ймовірність `P_{i, j} = 0`, оскільки оновлення не можуть зникати (монотонне зростання).

### Математичне сподівання часу до повної збіжності

Матриця переходів `P` містить перехідні стани `{1, 2, ..., N-1}` (підматриця `Q` розміру `(N-1) × (N-1)`) та поглинальний стан `N`.

Фундаментальна матриця поглинального ланцюга Маркова визначається як:

```
M_fund = (I - Q)⁻¹
```

Вектор середнього часу до поглинання (досягнення 100% узгодженості) обчислюється множенням фундаментальної матриці на одиничний вектор:

```
E[T] = M_fund · 1
```

Середня тривалість окремого кроку переходу зі стану `i` до стану `i + Δi` наближається гармонічним рядом:

```
E[T_conv] ≈ ∑_{i=1}^{N-1} 1 / E[Δi | S=i]
```

Для Push-Pull протоколу динаміка на початку дає `E[Δi] ≈ 2 · i` (експоненційне зростання), а наприкінці `E[Δ(N-i)] ≈ (N-i)² / N` (квадратичне згасання залишку).

Звідси асимптотичне математичне сподівання кількості раундів до повної узгодженості в кластері з `N` вузлів дорівнює:

```
E[T_conv] = log₃(N) + ln(ln(N)) + O(1)
```

Для кластера з `N = 1000` серверів при тривалості раунду пліток у 200 мілісекунд:

```
log₃(1000)
= ln(1000) / ln(3)     [формула переходу до натурального логарифма]
≈ 6.907 / 1.0986
≈ 6.28                  [раундів у фазі експоненційного розширення]

ln(ln(1000))
= ln(6.907)             [логарифм від 6.907]
≈ 1.93                  [раундів у фазі фінального дозбирування]

E[T_conv]
= 6.28 + 1.93           [сума раундів двох фаз]
≈ 8.21                  [середня кількість раундів]

Час_збіжності
= 8.21 · 200 мс         [множення на інтервал раунду]
≈ 1.64 с                [повний час досягнення узгодженості]
```

## 5. Алгебраїчний фундамент збіжності: напівґратки в CRDT

Щоб система гарантувала сильну кінцеву узгодженість (Strong Eventual Consistency, SEC), стан вузлів мусить утворювати **напівґратку об'єднання** (Join-Semilattice).

Напівґратка — це пара `(S, ⊔)`, де `S` — множина можливих станів, а `⊔: S × S → S` — бінарна операція злиття (Join), що задовольняє три аксіоми для будь-яких станів `a, b, c ∈ S`:

```
1. Асоціативність:
   (a ⊔ b) ⊔ c = a ⊔ (b ⊔ c)
   [Порядок групування пакетів у мережі не впливає на результат]

2. Комутативність:
   a ⊔ b = b ⊔ a
   [Порядок прибуття повідомлень від різних реплік не має значення]

3. Ідемпотентність:
   a ⊔ a = a
   [Повторна доставка дублікатів повідомлень не змінює стан]
```

### Частковий порядок і монотонність зростання

Операція `⊔` природно індукує частковий порядок `≤` на множині станів `S`:

```
a ≤ b  ⇔  a ⊔ b = b
```

Стан `b` вважається «новішим» або «повнішим» за `a`, якщо їхнє злиття повертає `b`.

Будь-яка локальна мутація на вузлі `f: S → S` повинна бути **монотонно зростаючою** відносно цього порядку:

```
∀ s ∈ S : s ≤ f(s)
```

Якщо всі мутації монотонно зростають, а злиття є точним supremum (найменшою верхньою гранню) у напівґратці, то для будь-якої множини оновлень `U = {u₁, u₂, ..., uₘ}` стан будь-якої репліки, що отримала `U`, дорівнює:

```
Стан = s₀ ⊔ u₁ ⊔ u₂ ⊔ ... ⊔ uₘ
```

Оскільки операція `⊔` комутативна й асоціативна, результат не залежить від порядку отримання оновлень, а завдяки ідемпотентності — не чутливий до дублікатів.

## 6. Теорія векторних годинників та виявлення конкурентності

Для довільних двох станів системи `A` та `B` із векторними годинниками `V_A` та `V_B` довжини `M` (де `M` — кількість активних реплік) частковий порядок визначається так:

```
1. V_A ≤ V_B  ⇔  (∀ i ∈ [1..M] : V_A[i] ≤ V_B[i])
2. V_A < V_B  ⇔  (V_A ≤ V_B) ∧ (∃ i ∈ [1..M] : V_A[i] < V_B[i])
3. V_A ∥ V_B  ⇔  ¬(V_A ≤ V_B) ∧ ¬(V_B ≤ V_A)   [Конкурентні записи / Конфлікт]
```

Якщо `V_A < V_B`, запис `B` причинно передує запису `A` (нащадок заміщує предка без конфлікту). Якщо `V_A ∥ V_B`, записи виникли незалежно й утворюють паралельні гілки (двійники / siblings).

### Операція злиття векторних годинників

Коли вузол отримує два конкурентні стани `V_A` та `V_B`, новий векторний годинник після злиття обчислюється як покомпонентний максимум:

```
V_merged[i] = max(V_A[i], V_B[i]),   для всіх i ∈ [1..M]
```

Операція покомпонентного максимуму `max(·, ·)` є комутативною, асоціативною та ідемпотентною, тобто векторні годинники утворюють класичну напівґратку `(ℕᴹ, max)`.

## 7. Математика усікання векторних годинників (Pruning Bounds)

Коли кількість клієнтів або вузлів зростає, розмір вектора версій збільшується лінійно `O(M)`. Щоб запобігти неконтрольованому зростанню метаданих, системи обмежують розмір вектора фіксованим числом записів `K_max` (наприклад, `K_max = 10` у Dynamo), видаляючи найстаріші записи за фізичною часовою міткою.

Усікання вектора порушує строгість часткового порядку: якщо запис предка було видалено з вектора `V_A`, система більше не може довести `V_B ≤ V_A`. Як наслідок, послідовні причинні записи помилково класифікуються як конкурентні (`V_A ∥ V_B`), породжуючи фантомні конфлікти (False Concurrency).

Нехай `T_prune` — часовий горизонт збереження записів у векторі, а `Δt_net` — випадкова затримка реплікації між вузлами. Ймовірність виникнення хибного конфлікту через усікання дорівнює ймовірності того, що затримка реплікації перевищить горизонт зберігання:

```
P(false_conflict) = P(Δt_net > T_prune) = 1 - F_net(T_prune)
```

Якщо `F_net(t)` — експоненційний розподіл із середнім часом 1 секунда (`λ = 1 с⁻¹`), а горизонт усікання встановлено на `T_prune = 60 секунд`:

```
P(false_conflict)
= e^(-1 · 60)            [підстановка λ=1 та t=60]
≈ 8.7 · 10⁻²⁷            [математично нехтовна величина]
```

## 8. Кількісне порівняння Read-Repair та фонової анти-ентропії

У розподіленому сховищі виправлення розходжень відбувається двома шляхами:
1. **Read-Repair:** реактивно під час читання клієнтом;
2. **Фонова анти-ентропія:** періодично за розкладом пліток або звірки дерев Меркла.

Нехай частота запитів читання до конкретного ключа становить `q_r` (запитів/с), а період фонової анти-ентропії становить `T_gossip` (секунд).

Ймовірність того, що розбіжність буде виправлена через операцію читання раніше, ніж спрацює фоновий процес пліток, визначається формулою ймовірності появи хоча б одного читання у вікні `[0, T_gossip]`:

```
P(repaired_by_read) = 1 - e^(-q_r · T_gossip)
```

Для гарячих ключів (`q_r = 100 зап/с`, `T_gossip = 60 с`):

```
P(repaired_by_read)
= 1 - e^(-100 · 60)      [підстановка q_r = 100 та T = 60]
= 1 - e^(-6000)          [обчислення експоненти]
≈ 1.0                    [гарантоване виправлення на читанні (100%)]
```

Для холодних ключів (`q_r = 0.001 зап/с` — один запит на 15 хвилин, `T_gossip = 60 с`):

```
P(repaired_by_read)
= 1 - e^(-0.001 · 60)    [підстановка q_r = 0.001 та T = 60]
= 1 - e^(-0.06)          [показник 0.06]
≈ 0.058                  [лише 5.8% виправляються на читанні]
```

**Інженерний висновок:** Read-Repair ідеально обслуговує 20% найгарячіших ключів (закон Парето), забезпечуючи майже миттєву збіжність за рахунок природного читацького трафіку. Фонова анти-ентропія є незамінною для решти 80% холодних даних, які рідко читаються клієнтами.

## 9. Складність звірки стану за деревами Меркла

Під час фонової анти-ентропії репліки повинні швидко знаходити, які саме ключі розійшлися, без передачі всього масиву даних через мережу. Для цього діапазони ключів організують у **дерева Меркла** (Merkle Trees) — бінарні дерева хешів.

Нехай підмножина даних містить `K` ключів. Дерево Меркла має висоту:

```
H = ⌈log₂ K⌉
```

Кожен листовий вузол містить `хеш(ключ, значення)`. Кожен внутрішній вузол містить `хеш(лівий_нащадок + правий_нащадок)`.

### Теорема про кількість мережевих порівнянь при розходженні d ключів

Якщо дві репліки мають ідентичний стан (`d = 0`), вони порівнюють лише один хеш у корені дерева:

```
Складність при d = 0: O(1) хеш-порівнянь, 0 байт переданих даних.
```

Нехай стани двох реплік відрізняються рівно на `d` ключів (`1 ≤ d ≪ K`).

На кожному рівні дерева `l` (від кореня `l = 0` до листків `l = H`) кількість розбіжних вузлів не може перевищувати `d`, але також не може перевищувати загальну кількість вузлів на цьому рівні `2ˡ`.

Загальна кількість вузлів, які координатор мусить завантажити й порівняти для локалізації всіх `d` конфліктів, строго обмежена сумою:

```
Кількість порівнянь C(K, d)
= ∑_{l=0}^{H} min(2ˡ, 2 · d)
= ∑_{l=0}^{⌊log₂ d⌋} 2ˡ  +  ∑_{l=⌊log₂ d⌋ + 1}^{H} 2 · d
= (2 · d - 1)  +  2 · d · (H - ⌊log₂ d⌋)
= O(d · (H - log₂ d))
= O(d · log₂(K / d))
```

### Числовий приклад ефективності дерева Меркла

Нехай таблиця містить `K = 1 048 576` записів (`2²⁰` ключів, `H = 20`). Після мережевого збою на репліці розійшлися `d = 4` записи.

1. **Без дерева Меркла (наївна звірка):**
   Потрібно передати та перевірити всі `1 048 576` ключів із контрольною сумою кожного рядка. При розмірі запису 1 КБ це вимагає `1 ГБ` мережевого трафіку.

2. **Із деревом Меркла:**
   Обчислимо кількість порівнянь за виведеною формулою:

```
C(K=2²⁰, d=4)
= (2 · 4 - 1) + 2 · 4 · (20 - log₂(4))  [підстановка K = 2²⁰, H = 20 та d = 4 у формулу]
= 7 + 8 · (20 - 2)                       [обчислення 2·4 - 1 = 7 та log₂(4) = 2]
= 7 + 8 · 18                             [різниця рівнів 20 - 2 = 18]
= 7 + 144                                [множення 8 · 18 = 144]
= 151                                    [загальна кількість хеш-порівнянь]
```

Замість передачі мільйона записів репліки обмінюються лише `151` 32-байтним хешем (`≈ 4.8 КБ` трафіку), після чого передають безпосередньо 4 змінені рядки (`4 КБ`).

**Прискорення за обсягом трафіку перевищує 100 000 разів.**

Математичний апарат PBS, марковських ланцюгів та напівґраток доводить: кінцева узгодженість є строго керованою системою з детермінованими ймовірнісними межами та надзвичайно швидкою фоновою збіжністю `O(log N)`.
