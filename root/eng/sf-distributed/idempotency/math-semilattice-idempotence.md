# 🧮 Алгебра ідемпотентності: напівґратки, монотонність і ймовірність колізій

Ця вставка розбирає строгий математичний апарат ідемпотентних операцій: алгебраїчні структури напівґраток, доведення збіжності розподілених станів без блокувань за теоремою CALM, математику безконфліктних реплікованих типів даних (CRDT) та ймовірнісний розрахунок колізій ідентифікаторів запитів (UUID) за парадоксом днів народження.

## 1. Алгебраїчні структури: від напівгруп до напівґраток

В абстрактній алгебрі операція над множиною визначається набором аксіом, що описують її поведінку при комбінуванні елементів.

Нехай `S` — множина можливих станів розподіленої системи, а `⊔` (символ операції об'єднання або злиття станів, англ. *join*) — бінарна операція над цією множиною:

```
⊔ : S × S → S
```

Алгебраїчна система `(S, ⊔)` називається **ідемпотентною верхньою напівґраткою** (*join-semilattice*), якщо для будь-яких елементів `a, b, c ∈ S` одночасно виконуються три фундаментальні аксіоми:

1. **Асоціативність**: порядок групування послідовних операцій не впливає на кінцевий результат:

```
(a ⊔ b) ⊔ c = a ⊔ (b ⊔ c)
```

У розподілених системах асоціативність гарантує, що повідомлення або дельти станів можна довільно групувати в мережеві батчі та пакети без спотворення логічного результату.

2. **Комутативність**: порядок розташування операндів не має значення:

```
a ⊔ b = b ⊔ a
```

Комутативність забезпечує стійкість до перевпорядкування пакетів: якщо через затримки маршрутизації повідомлення `b` надійшло раніше за повідомлення `a`, результуючий стан вузла буде ідентичним нормальному порядку надходження.

3. **Ідемпотентність**: застосування операції до двох однакових операндів повертає той самий операнд:

```
a ⊔ a = a
```

Ідемпотентність гарантує стійкість до мережевих дублікатів: якщо вузол отримує одну й ту саму копію повідомлення багатократно через клієнтські повтори (*retries*), стан системи не подвоюється і не зазнає додаткових мутацій.

Якщо множина `S` має також нейтральний елемент `⊥` (*bottom*, початковий порожній стан такий, що `a ⊔ ⊥ = a` для будь-якого `a ∈ S`), структура утворює **ідемпотентний обмежений комутативний моноїд** (*bounded join-semilattice*).

## 2. Порядок і монотонність у напівґратках

Між алгебраїчним означенням напівґратки через операцію `⊔` та порядковим означенням через частковий порядок існує пряма еквівалентність.

Операція `⊔` природно породжує на множині `S` відношення часткового порядку `≤`:

```
a ≤ b  ⇔  a ⊔ b = b
```

Інтуїтивний зміст цього виразу полягає в тому, що стан `b` є «більшим» або «пізнішим / повнішим» за стан `a`, оскільки об'єднання `a` та `b` нічого нового до `b` не додає.

Доведемо, що відношення `≤`, визначене через `a ⊔ b = b`, задовольняє всі три аксіоми часткового порядку:

### 1. Рефлексивність (`a ≤ a` для будь-якого `a ∈ S`)
```
a ⊔ a
= a              [аксіома ідемпотентності: a ⊔ a = a]
```
З рівності `a ⊔ a = a` за означенням випливає `a ≤ a`.

### 2. Антисиметричність (якщо `a ≤ b` та `b ≤ a`, то `a = b`)
З умови `a ≤ b` маємо `a ⊔ b = b`. З умови `b ≤ a` маємо `b ⊔ a = a`.
```
a
= b ⊔ a          [з рівності b ⊔ a = a]
= a ⊔ b          [аксіома комутативності: b ⊔ a = a ⊔ b]
= b              [з рівності a ⊔ b = b]
```
Отже, `a = b`.

### 3. Транзитивність (якщо `a ≤ b` та `b ≤ c`, то `a ≤ c`)
З умови `a ≤ b` маємо `a ⊔ b = b`. З умови `b ≤ c` маємо `b ⊔ c = c`.
Перевіримо вираз `a ⊔ c`:
```
a ⊔ c
= a ⊔ (b ⊔ c)    [підстановка: c = b ⊔ c]
= (a ⊔ b) ⊔ c    [аксіома асоціативності]
= b ⊔ c          [підстановка: a ⊔ b = b]
= c              [підстановка: b ⊔ c = c]
```
З отриманої рівності `a ⊔ c = c` за означенням випливає `a ≤ c`.

### 4. Монотонність операції злиття (Monotonicity)

Критичною властивістю для розподілених систем є монотонність самої операції `⊔` відносно введеного часткового порядку `≤`:

```
∀ a, b, c ∈ S : (a ≤ b) ⇒ (a ⊔ c ≤ b ⊔ c)
```

Доведемо це твердження строго:
Нехай `a ≤ b`, що за означенням означає `a ⊔ b = b`.
Розглянемо вираз `(a ⊔ c) ⊔ (b ⊔ c)`:

```
(a ⊔ c) ⊔ (b ⊔ c)
= a ⊔ (c ⊔ (b ⊔ c))   [аксіома асоціативності]
= a ⊔ ((b ⊔ c) ⊔ c)   [аксіома комутативності]
= a ⊔ (b ⊔ (c ⊔ c))   [аксіома асоціативності]
= a ⊔ (b ⊔ c)         [аксіома ідемпотентності: c ⊔ c = c]
= (a ⊔ b) ⊔ c         [аксіома асоціативності]
= b ⊔ c               [підстановка з умови a ≤ b: a ⊔ b = b]
```

Оскільки `(a ⊔ c) ⊔ (b ⊔ c) = (b ⊔ c)`, за означенням часткового порядку це рівносильно:

```
a ⊔ c ≤ b ⊔ c
```

Це доводить, що будь-яке нове повідомлення `c`, що надходить на репліку, або збільшує стан системи в частковому порядку, або залишає його незмінним, але ніколи не може «зменшити» стан або повернути систему в минуле.

### 5. Гомоморфізми напівґраток (Semilattice Homomorphisms)

У розподіленій аналітиці та обчисленнях часто необхідно трансформувати стан із однієї предметної області в іншу (наприклад, перетворити векторний лічильник у скалярне число або спроєктувати стан у матеріалізоване представлення).

Відображення `h : S → T` між двома напівґратками `(S, ⊔_S)` та `(T, ⊔_T)` називається **гомоморфізмом напівґраток**, якщо воно зберігає операцію злиття для будь-яких елементів `a, b ∈ S`:

```
h(a ⊔_S b) = h(a) ⊔_T h(b)
```

Збереження операції злиття гарантує, що трансформацію даних можна виконувати як до об'єднання реплік, так і після нього:

```
h(S_local ⊔ S_remote) = h(S_local) ⊔ h(S_remote)
```

Це дозволяє переносити важкі аналітичні агрегації безпосередньо на кінцеві вузли (Push-down aggregation) без втрати узгодженості результату.

### 6. Ідемпотентні напівкільця та тропічна алгебра

Окремим класом алгебраїчних структур, що застосовуються в алгоритмах маршрутизації та аналізу мережевих графів (наприклад, протоколи BGP, OSPF, алгоритм Флойда-Воршелла), є **ідемпотентні напівкільця** (*dioids / tropical semirings*).

Напівкільце `(K, ⊕, ⊗, 0_K, 1_K)` називається ідемпотентним, якщо його операція додавання `⊕` є ідемпотентною:

```
a ⊕ a = a    [для будь-якого a ∈ K]
```

Класичним прикладом є **тропічне напівкільце мінімуму** (*Min-Plus algebra*), де:
* Множина `K = ℝ ∪ {+∞}`;
* Додавання: `a ⊕ b = min(a, b)`;
* Множення: `a ⊗ b = a + b`;
* Нейтральний елемент за додаванням: `0_K = +∞`;
* Нейтральний елемент за множенням: `1_K = 0`.

### 7. Дуальність решіток: нижні напівґратки та повні решітки

Поряд із верхньою напівґраткою `(S, ⊔)` у математиці існує дуальна структура — **нижня напівґратка** (*meet-semilattice*) `(S, ⊓)`, де бінарна операція `⊓` (*meet*, найбільша нижня грань / інфімум) також є асоціативною, комутативною та ідемпотентною:

```
a ⊓ a = a
```

Якщо множина станів `S` підтримує обидві операції `⊔` та `⊓`, які пов'язані законами поглинання:

```
a ⊔ (a ⊓ b) = a
a ⊓ (a ⊔ b) = a
```

структура утворює **повну решітку** (*lattice*). У розподілених транзакціях повні решітки дозволяють не лише накопичувати оновлення (через `⊔`), але й обчислювати гарантовано спільний узгоджений зріз глобального стану (через `⊓`), що використовується в алгоритмах збирання сміття (*garbage collection*) та безпечного зсуву горизонту консенсусу.

## 3. Математика безконфліктних реплікованих типів (CRDT)

На ідемпотентних напівґратках базується теорія стан-орієнтованих безконфліктних реплікованих типів даних (State-based CRDT / CvRDT), розроблена Марком Шапірою (Marc Shapiro) та його співавторами 2011 року.

У CvRDT репліки обмінюються своїми повними станами, а злиття отриманого віддаленого стану з локальним здійснюється виключно через ідемпотентний оператор `⊔`. Розглянемо два класичні приклади.

### 1. Зростаючий лічильник (G-Counter)

У системі з `n` вузлів стан лічильника представляється вектором невід'ємних цілих чисел довжини `n`:

```
V = [v₁, v₂, ..., vₙ],    де vᵢ ∈ ℕ₀
```

Кожен вузол `i` має ексклюзивне право інкрементувати лише власну координату `vᵢ`:

```
increment(i): vᵢ := vᵢ + 1
```

Операція злиття двох векторів `A` та `B` визначається як покомпонентний максимум:

```
A ⊔ B = [max(a₁, b₁), max(a₂, b₂), ..., max(aₙ, bₙ)]
```

Перевіримо ідемпотентність оператора злиття:

```
(A ⊔ A)ᵢ
= max(aᵢ, aᵢ)
= aᵢ             [властивість функції максимуму: max(x, x) = x]
```

Оскільки `max(aᵢ, bᵢ) = max(bᵢ, aᵢ)` (комутативність) та `max(max(aᵢ, bᵢ), cᵢ) = max(aᵢ, max(bᵢ, cᵢ))` (асоціативність), операція утворює ідемпотентну напівґратку. Читання глобального значення лічильника є простою сумою компонентів:

```
value(V) = ∑ vᵢ    [де i від 1 до n]
```

### 2. Двосторонній лічильник (PN-Counter)

Якщо система вимагає не лише збільшення, але й зменшення значення (наприклад, баланс інвентарю або лічильник активних сесій), простий `G-Counter` не підходить, оскільки декремент порушує монотонне зростання.

Для збереження ідемпотентності застосовують композицію двох незалежних `G-Counter`:
* `P` (Positive) — вектор інкрементів;
* `N` (Negative) — вектор декрементів.

Стан об'єкта представляється парою векторів `(P, N)`. Злиття двох станів `(P₁, N₁) ⊔ (P₂, N₂)` визначається як покомпонентний максимум для обох векторів окремо:

```
(P₁, N₁) ⊔ (P₂, N₂) = (P₁ ⊔ P₂, N₁ ⊔ N₂)
```

Оскільки обидві половини є ідемпотентними напівґратками, прямий добуток напівґраток також є ідемпотентною напівґраткою. Поточне значення лічильника визначається як різниця їхніх сум:

```
value(P, N) = (∑ pᵢ) - (∑ nᵢ)    [де i від 1 до n]
```

### 3. Двофазна множина (2P-Set) та множина зі спостережуваним видаленням (OR-Set)

У класичній `2P-Set` (Two-Phase Set) видалення є остаточним (*tombstone*): елемент, доданий до множини `AddSet`, може бути переміщений до множини видалених `RemoveSet`, після чого його неможливо додати повторно.

Для підтримки багаторазового додавання й видалення того самого логічного значення застосовують **OR-Set** (Observed-Remove Set). При кожному додаванні елемента `e` генерується унікальний тег `u = UUIDv4()`:

* Стан репліки: множина пар `S ⊆ E × U` (елемент + унікальний тег).
* Додавання елемента `e`: `Add(e) ⇒ S := S ∪ {(e, generate_uuid())}`.
* Видалення елемента `e`: знайти всі пари `(e, u) ∈ S`, видимі в поточній репліці в момент видалення, і додати їх до множини `TombstoneSet`.
* Злиття двох реплік: `(S₁, T₁) ⊔ (S₂, T₂) = (S₁ ∪ S₂, T₁ ∪ T₂)`.

Оскільки теоретико-множинне об'єднання `∪` є ідемпотентним, комутативним і асоціативним, операція злиття реплік гарантує строгу математичну збіжність навіть за наявності паралельних операцій додавання та видалення на різних континентах.

### 4. Векторні годинники та причинна монотонність

Векторні годинники (*Vector Clocks*) дозволяють встановити причинно-наслідковий порядок (*causal ordering*) між подіями в системі без синхронізації фізичних годинників.

Нехай `V_A` та `V_B` — вектори логічного часу двох вузлів. Відношення причинного слідування `V_A < V_B` («подія A сталася строго раніше за подію B») визначається як:

```
V_A < V_B  ⇔  (∀ i : V_A[i] ≤ V_B[i]) ∧ (∃ j : V_A[j] < V_B[j])
```

Операція синхронізації годинників при отриманні повідомлення є класичним ідемпотентним злиттям:

```
V_local := V_local ⊔ V_incoming
= [max(V_local[1], V_incoming[1]), ..., max(V_local[n], V_incoming[n])]
```

Повторний прихід уже обробленого повідомлення не змінює векторного годинника приймача, оскільки `max(vᵢ, vᵢ) = vᵢ`.

### 5. Множина з перемогою останнього запису (LWW-Element-Set)

Множина `LWW-Element-Set` підтримує додавання та видалення елементів без централізованого блокування. Стан складається з двох внутрішніх множин пар «елемент-таймстемп»:
* `AddSet` — множина доданих елементів із міткою часу `(e, t_add)`;
* `RemoveSet` — множина видалених елементів із міткою часу `(e, t_remove)`.

Операція злиття двох реплік `S₁ = (A₁, R₁)` та `S₂ = (A₂, R₂)` визначається як теоретико-множинне об'єднання:

```
S₁ ⊔ S₂ = (A₁ ∪ A₂, R₁ ∪ R₂)
```

Оскільки операція об'єднання звичайних множин `∪` є природно ідемпотентною (`A ∪ A = A`), комутативною та асоціативною, злиття реплік є строго ідемпотентним.

Предикат присутності елемента `e` в результуючій множині визначається порівнянням максимальних таймстемпів:

```
contains(e) ⇔ ∃ (e, t_a) ∈ AddSet : (∀ (e, t_r) ∈ RemoveSet ⇒ t_a > t_r)
```

Скільки б разів репліки не надсилали одна одній свої стани через зашумлену мережу, операція `∪` не створює дублікатів і гарантує абсолютну збіжність станів на всіх вузлах.

## 4. Доведення детермінованої збіжності та теорема CALM

Розглянемо розподілену систему, де вузол отримує послідовність пакетів оновлень `M = {m₁, m₂, ..., mₖ}`. Через асинхронну природу мережі пакети можуть затримуватися, доставлятися з порушенням первинного порядку та дублюватися довільну кількість разів.

Нехай `p = (x₁, x₂, ..., xₙ)` — довільний фактично отриманий потік повідомлень, де кожен елемент `xᵢ ∈ M`, а загальна кількість повідомлень `n ≥ k`.

Позначимо результуючий стан вузла після обробки потоку `p` над початковим станом `S₀` як:

```
S(p) = S₀ ⊔ x₁ ⊔ x₂ ⊔ ... ⊔ xₙ
```

### Теорема про збіжність за напівґраткою

Якщо операція `⊔` утворює ідемпотентну напівґратку, то для будь-яких двох потоків повідомлень `p` та `q`, які містять однакову множину унікальних оновлень `set(p) = set(q) = M`, результуючі стани системи є тотожними:

```
S(p) = S(q) = S₀ ⊔ ( ⊔_{m ∈ M} m )
```

### Доведення

Нехай `p = (x₁, x₂, ..., xₙ)`.

Крок 1. Завдяки асоціативності та комутативності операції `⊔`, ми можемо переставити елементи потоку `p` так, щоб усі дублікати кожного унікального повідомлення `mᵢ ∈ M` стояли поруч:

```
S(p)
= S₀ ⊔ (m₁ ⊔ ... ⊔ m₁) ⊔ (m₂ ⊔ ... ⊔ m₂) ⊔ ... ⊔ (mₖ ⊔ ... ⊔ mₖ)  [комутативність і асоціативність]
```

Крок 2. Розглянемо кожну групу однакових повідомлень довжиною `rᵢ ≥ 1`. Доведемо за індукцією, що об'єднання будь-якої скінченної кількості однакових елементів тотожне одному елементу:
* База індукції (`rᵢ = 1`): `mᵢ = mᵢ` (тривіально).
* Крок індукції: припустимо, що для `rᵢ = j` виконується `⊔ʲ mᵢ = mᵢ`. Тоді для `rᵢ = j + 1`:

```
(⊔ʲ mᵢ) ⊔ mᵢ
= mᵢ ⊔ mᵢ        [за припущенням індукції]
= mᵢ             [аксіома ідемпотентності: a ⊔ a = a]
```

Крок 3. Замінюючи кожну групу дублікатів її єдиним екземпляром, отримуємо:

```
S(p) = S₀ ⊔ m₁ ⊔ m₂ ⊔ ... ⊔ mₖ
```

Оскільки вихідний порядок елементів та кратність їх появи в потоці `p` повністю зникли з фінального виразу, будь-який інший потік `q` з тією самою множиною `M` після аналогічних перетворень дасть абсолютно тотожний стан `S(q) = S(p)`.

Це доведення становить математичний фундамент **теореми CALM** (*Consistency As Logical Monotonicity*, Геллерштейн та ін., 2010 рік): **програма в розподіленій системі може досягти узгодженості без дорогих координаційних бар'єрів і блокувань тоді й лише тоді, коли її обчислення є логічно монотонними (виражаються через ідемпотентні напівґратки)**.

## 5. Ймовірнісний аналіз колізій ідентифікаторів запитів

У системах із синтезованою ідемпотентністю клієнти генерують унікальні токени запитів (*Idempotency Keys*), спираючись на генератори псевдовипадкових чисел. Якщо два різних клієнтських запити випадково отримають однаковий ідентифікатор, сервер сприйме другий запит як дублікат першого і проігнорує нову дію, повернувши закешований результат попередньої операції.

Оцінимо ймовірність виникнення хоча б однієї колізії серед `k` випадково згенерованих ключів у просторі розміром `N = 2ᵇ` (де `b` — бітова розрядність ключа).

### Строгий вивід через парадокс днів народження

Ймовірність того, що всі `k` згенерованих ключів є строго попарно різними (колізій немає), визначається добутком умовних ймовірностей:

```
P(no_collision)
= 1 · (1 - 1/N) · (1 - 2/N) · ... · (1 - (k - 1)/N)   [добуток умовних ймовірностей без колізій]
= ∏_{i=0}^{k-1} (1 - i/N)                              [згортання добутку за індексом i]
```

Застосуємо розклад експоненти в ряд Тейлора: для малих значень `x` (`x ≪ 1`) маємо `1 - x ≈ exp(-x - x²/2)`. Обмежуючись першим членом наближення `1 - i/N ≈ exp(-i/N)`:

```
P(no_collision)
≈ ∏_{i=0}^{k-1} exp(- i / N)
= exp(- ∑_{i=0}^{k-1} (i / N))        [властивість експоненти: exp(A) · exp(B) = exp(A + B)]
= exp(- (1 / N) · ∑_{i=0}^{k-1} i)
= exp(- (k · (k - 1)) / (2·N))        [сума арифметичної прогресії: ∑_{i=0}^{k-1} i = k(k-1)/2]
```

Для великих значень `k` (`k ≫ 1`) вираз спрощується до `exp(- k² / (2·N))`.

Ймовірність виникнення **хоча б однієї колізії** `P(collision) = 1 - P(no_collision)`:

```
P(collision)
= 1 - exp(- k² / (2·N))
```

Для значень `k² ≪ 2N`, використовуючи наближення `1 - exp(-y) ≈ y`:

```
P(collision) ≈ k² / (2·N)
```

### Кількість запитів до досягнення заданого порогу ризику

Знайдемо кількість запитів `k`, при якій ймовірність колізії досягає заданого значення `p`:

```
1 - exp(- k² / (2·N)) = p
exp(- k² / (2·N)) = 1 - p
- k² / (2·N) = ln(1 - p)
k = √( 2·N · ln(1 / (1 - p)) )
```

При `p = 0.5` (ймовірність колізії 50 %, точка парадоксу днів народження):

```
k ≈ √( 2 · ln(2) · N ) ≈ √( 1.3863 · N ) ≈ 1.1774 · √N
```

### Порівняльна таблиця просторів ідентифікаторів

Проаналізуємо різні розрядності ключів для розподіленої системи, що обробляє 1 мільярд (`k = 10⁹`) транзакцій на добу:

| Тип ключа | Біти (`b`) | Розмір простору (`N = 2ᵇ`) | Кількість `k` до 50% колізії | Ймовірність колізії на 10⁹ запитів |
| :--- | :--- | :--- | :--- | :--- |
| **32-бітний ID** | 32 | `4.29 · 10⁹` | `7.71 · 10⁴` (77 тис.) | `≈ 1.0` (100 % катастрофа) |
| **64-бітний Snowflake / FNV** | 64 | `1.84 · 10¹⁹` | `5.06 · 10⁹` (5 млрд) | `2.71 · 10⁻²` (**2.71 % на добу**) |
| **128-бітний UUIDv4** | 122* | `5.32 · 10³⁶` | `2.71 · 10¹⁸` | `9.40 · 10⁻²⁰` (абсолютний нуль) |
| **256-бітний SHA-256** | 256 | `1.16 · 10⁷⁷` | `4.01 · 10³⁸` | `4.32 · 10⁻⁵⁹` (неможливо фізично) |

*\*Примітка: У стандартному UUIDv4 із 128 бітів 6 бітів зарезервовано під версію та варіант, тому ефективна ентропія становить 122 біти.*

## Висновок

Математичний аналіз встановлює два жорсткі інженерні імперативи:
1. **Збіжність без блокувань:** Для створення масштабованих сховищ стан системи зобов'язаний проектуватися як ідемпотентна напівґратка `(S, ≤, ⊔)`. Це повністю знімає проблему перевпорядкування та дублювання мережевих повідомлень.
2. **Розрядність токенів:** Будь-який синтезований ключ ідемпотентності повинен мати розрядність **не менше 128 біт** (UUIDv4). 64-бітні ідентифікатори у високонавантажених системах генерують неприпустимі 2.7 % колізій щодня, призводячи до прихованого псування даних.
