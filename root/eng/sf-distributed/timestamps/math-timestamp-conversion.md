# 🧮 Перетворення форматів міток часу та модульне розгортання лічильників

Математичний апарат обробки часових міток у розподілених інформаційних системах спирається на дві фундаментальні задачі: точне перетворення між різнорідними поданнями часу з фіксованою комою без накопичення похибок округлення та однозначне розгортання обмежених циклічних лічильників у нескінченну монотонну шкалу. Ця вставка містить строгі алгебраїчні виведення формул перерахунку між форматами NTP, PTP та суб-наносекундними полями корекції, розрахунок шумів квантування, математичні моделі лінійної регресії для оцінки дрейфу частоти, статистику девіації Аллана для оцінки стабільності генераторів, моделювання фізичної асиметрії середовища поширення сигналу, теорію стійкості сервопетлі фазового автопідстроювання (PI-контролера годинника), а також формальне доведення теореми модульного розгортання лічильників за умов мережевого джитеру та перевпорядкування пакетів.

---

### 1. Двійкова арифметика з фіксованою комою: формат NTP (32.32)

Протокол NTP представляє час як беззнакове 64-бітне число з фіксованою комою, де старші 32 біти відповідають цілим секундам, а молодші 32 біти — двійковому дробу секунди. Одиниця молодшого розряду дробової частини (квант часу) дорівнює:

```
q_NTP = 2⁻³² секунди
      = 1 / 4294967296 с
      ≈ 0.23283064365386962890625 · 10⁻⁹ с
      ≈ 232.83 пікосекунди
```

#### Пряме перетворення: наносекунди в дріб NTP

Нехай задано цілочисельне значення наносекунд `N` у діапазоні `0 ≤ N < 10⁹`. Необхідно знайти 32-бітне дробове число `F`, яке мінімізує похибку апроксимації величини `N / 10⁹`.

Точне математичне співвідношення має вигляд:

```
F / 2³² ≈ N / 10⁹
F = round( (N · 2³²) / 10⁹ )
  = floor( (N · 2³² + 5 · 10⁸) / 10⁹ )
```

Оскільки безпосереднє обчислення добутку `N · 2³²` для максимального значення `N = 999 999 999` дає величину `≈ 4.295 · 10¹⁸`, проміжний результат вимагає 64-бітного беззнакового цілого (`uint64_t`), що повністю вміщується у стандартні регістри сучасних процесорів:

```
N · 2³² = 999999999 · 4294967296
        = 4294967291705032704 < 2⁶⁴ - 1  (18446744073709551615)
```

Покрокове виведення алгоритму цілочисельного ділення з округленням до найближчого:

```
F = ( (uint64_t)N << 32 ) + 500000000ULL
F = F / 1000000000ULL
```

#### Зворотне перетворення: дріб NTP у наносекунди

Нехай отримано 32-бітний дріб NTP `F ∈ [0, 2³² - 1]`. Значення в наносекундах `N` визначається множенням на базу `10⁹` та діленням на `2³²`:

```
N = round( (F · 10⁹) / 2³² )
  = floor( (F · 10⁹ + 2³¹) / 2³² )
```

У двійковій арифметиці ділення на `2³²` є тривіальною операцією побітового зсуву вправо на 32 розряди або вибору старшого 32-бітного слова з 64-бітного регістрового результату:

```
Добуток:
P = (uint64_t)F · 1000000000ULL + 0x80000000ULL   [додавання 2³¹ для округлення]

Зсув:
N = (uint32_t)(P >> 32)                            [еквівалентно діленню на 2³²]
```

Максимальне значення добутку `(2³² - 1) · 10⁹ + 2³¹ = 4 294 967 297 147 483 647 < 2⁶⁴`, що гарантує абсолютну відсутність арифметичного переповнення 64-бітних типів даних.

#### Оптимізація для 32-бітних архітектур без апаратного ділення

На мікроконтролерах без швидкого 64-бітного ділення перетворення наносекунд у дріб NTP можна виконати через множення на попередньо розраховану зворотну константу. Запишемо дріб `2³² / 10⁹` як ціле число зі зсувом:

```
K = round( (2³² / 10⁹) · 2³² )        [цільове значення масштабованого коефіцієнта]
  = round( 4.294967296 · 4294967296 )  [обчислення десяткового дробу]
  = 18446744073                        [округлення до найближчого цілого, 0x44B82FA09]
```

Розкладемо коефіцієнт `K` на суму: `K = 4 · 2³² + K_rem`, де `K_rem = 1266874377` (`0x4B82FA09`). Тоді обчислення зводиться до:

```
F = (N · 4) + ( ( (uint64_t)N · 1266874377ULL ) >> 32 )
```

Цей вираз містить лише одне 32×32→64 множення та зсуви, що виконується за кілька тактів процесора на архітектурах ARM Cortex-M або RISC-V без виклику бібліотечних функцій ділення.

#### Аналіз похибки квантування та дисперсії

Дискретизація неперервного часу створює шум квантування `ε_q ∈ [-q/2, +q/2]`. Якщо припустити рівномірний розподіл похибки на інтервалі кванта `q`, математичне сподівання шуму дорівнює нулю (`E[ε_q] = 0`), а дисперсія становить:

```
σ_q² = ∫_{-q/2}^{+q/2} x² · (1/q) dx
     = [ x³ / (3·q) ]_{-q/2}^{+q/2}
     = ( (q/2)³ - (-q/2)³ ) / (3·q)
     = ( 2 · q³ / 8 ) / (3·q)
     = q² / 12
```

Для розглянутих стандартів середньоквадратичне відхилення шуму квантування становить:
* **NTP (232.8 пс):** `σ_q = 232.8 пс / √12 ≈ 67.2 пс`.
* **PTP цілочисельний (1 нс):** `σ_q = 1000 пс / √12 ≈ 288.7 пс`.
* **PTP CorrectionField (15.26 фс):** `σ_q = 15.26 фс / √12 ≈ 4.4 фс`.

Звідси видно, що 64-бітне суб-наносекундне поле корекції PTP забезпечує запас точності на чотири порядки вищий, ніж сам лічильник наносекунд, що унеможливлює деградацію точності синхронізації навіть при проходженні пакета через сотні комутаторів.

### 2. Формат IEEE 1588 PTP та масштабовані поля корекції

Стандарт IEEE 1588 визначає 80-бітну структуру часової мітки `Timestamp`, що складається з 48-бітного поля секунд та 32-бітного поля наносекунд:

```
Timestamp = {
    uint48_t seconds;      // [0 .. 2⁴⁸ - 1]
    uint32_t nanoseconds;  // [0 .. 999 999 999]
}
```

Повний час у лінійній наносекундній шкалі `T_ns` обчислюється як:

```
T_ns = seconds · 10⁹ + nanoseconds
```

#### Масштабоване поле корекції (CorrectionField)

Для виключення похибок накопичення при проходженні пакетів через ланцюг комутаторів (Transparent Clocks) PTP використовує 64-бітне знакове поле корекції `correctionField`, значення якого виражається в одиницях **наносекунд, масштабованих на 2¹⁶** (Sub-nanoseconds):

```
Квант поля корекції:
q_corr = 2⁻¹⁶ нс
       = 1 / 65536 нс
       ≈ 0.0000152587890625 нс
       ≈ 15.258 фемтосекунди
```

Зв'язок між дробовим часом затримки в наносекундах `τ_ns` та цілочисельним значенням поля корекції `CF`:

```
CF = round( τ_ns · 2¹⁶ )
   = floor( τ_ns · 65536 + 0.5 )
```

Якщо комутатор зафіксував час входу кадру `t_in` та час виходу `t_out` за допомогою внутрішнього апаратного годинника з роздільною здатністю `Δt = 10` нс (частота 100 МГц) та фазовим інтерполятором з точністю `0.1` нс, час перебування пакета в пристрої (Residence Time) становить:

```
t_residence = t_out - t_in
CF_new = CF_old + ( (uint64_t)t_residence << 16 ) + sub_ns_fraction
```

У прозорих годинниках типу End-to-End (E2E) поле корекції накопичує виключно час перебування пакета всередині вузла (`t_residence`). У прозорих годинниках типу Peer-to-Peer (P2P) до цього значення комутатор додатково додає заздалегідь виміряну затримку вхідної фізичної лінії зв'язку (`t_peer_delay` або `t_pdelay`), що повністю звільняє кінцевий ведений вузол від необхідності надсилати власні зондувальні запити вимірювання затримки поширення.

#### Перетворення PTP Timestamp ↔ NTP Timestamp

Для взаємодії шкал NTP та PTP необхідно враховувати два фактори: відмінність епох (епоха NTP починається 1 січня 1900 року, PTP/TAI — 1 січня 1970 року; різниця становить точно `2 208 988 800` секунд) та зсув шкали UTC відносно атомної шкали TAI через високосні секунди:

```
T_PTP = T_UTC + ΔT_leap
T_NTP = T_UTC + 2208988800 с
```

Формула безпосереднього перетворення секундного та дробового компонентів:

```
1. PTP → NTP:
   NTP_sec  = PTP_sec + 2208988800ULL - ΔT_leap
   NTP_frac = ( ((uint64_t)PTP_nsec << 32) + 500000000ULL ) / 1000000000ULL

2. NTP → PTP:
   PTP_sec  = NTP_sec - 2208988800ULL + ΔT_leap
   PTP_nsec = ( ((uint64_t)NTP_frac · 1000000000ULL) + 0x80000000ULL ) >> 32
```

### 3. Статистична обробка міток, девіація Аллана та моделі регресії

При зіставленні апаратного годинника мережевої карти PHC з системним таймером центрального процесора (TSC або ARM Generic Timer) або при обробці серій вимірювань затримки виникає задача статистичної оцінки стабільності генератора та параметрів лінійного зв'язку шкал часу: миттєвого фазового зсуву (Phase Offset `β`) та відносного дрейфу частот (Frequency Skew / Drift `α`).

#### Статистика стабільності частоти: двовибіркова девіація Аллана (ADEV)

Звичайна вибіркова дисперсія стає розбіжною при наявності низькочастотних шумів типу флікер-шуму частоти (1/f) або випадкового блукання частоти (Random Walk FM). Для кількісної оцінки стабільності генератора міток застосовується девіація Аллана `σ_y(τ)`:

```
σ_y²(τ) = ( 1 / (2 · (M - 1)) ) · ∑_{i=1}^{M-1} ( ȳ_{i+1} - ȳ_i )²
```

Тут `ȳ_i` — середнє відносне відхилення частоти на інтервалі інтегрування `τ = m · τ_0`, обчислене за послідовністю фазових міток часу `x_k`:

```
ȳ_i = ( x_{(i+1)·m} - x_{i·m} ) / τ
```

| Тип опорного генератора | Власна стабільність (ADEV на `τ=1 с`) | Температурний дрейф | Область застосування у таймстемпінгу |
|:---|:---:|:---:|:---:|
| **Звичайний кварц (XO)** | `10⁻⁷ .. 10⁻⁸` (10–100 нс/с) | 20–50 ppm | Базові мережеві карти, програмний сокетний стек |
| **Термокомпенсований (TCXO)** | `10⁻⁹ .. 10⁻¹⁰` (0.1–1 нс/с) | 0.5–2 ppm | Промислові PTP IEEE 1588 адаптери, базові станції |
| **Термостатований (OCXO)** | `10⁻¹¹ .. 10⁻¹²` (10–100 пс/с) | 0.001–0.05 ppm | Магістральні телеком-вузли, Grandmaster Clocks |

Знання девіації Аллана дозволяє оптимально налаштувати період між пакетами синхронізації `T_sync`: він повинен лежати в точці мінімуму кривої ADEV, де білий шум фази переходить у шум частоти.

#### Метод найменших квадратів (Ordinary Least Squares)

Позначимо через `x_i` показання таймера процесора у вибірці `i`, а через `y_i` — відповідне показання годинника PHC. Лінійний зв'язок задається рівнянням `y_i = α · x_i + β + e_i`. Для ковзного вікна з `M` останніх вимірювань оцінки коефіцієнтів `α̂` та `β̂` визначаються мінімізацією суми квадратів нев'язок:

```
Обчислення проміжних сум:
S_x  = ∑_{i=1}^M x_i
S_y  = ∑_{i=1}^M y_i
S_xx = ∑_{i=1}^M x_i²
S_xy = ∑_{i=1}^M (x_i · y_i)

Оцінка нахилу (коефіцієнта частоти):
α̂ = ( M · S_xy - S_x · S_y ) / ( M · S_xx - S_x² )

Оцінка зсуву фази (Offset):
β̂ = ( S_y - α̂ · S_x ) / M
```

Зміщення частоти генератора у частинах на мільйон (PPM) відносно номіналу розраховується як `Drift_PPM = (α̂ - 1.0) · 10⁶`.

#### Відкидання статистичних викидів (Outlier Rejection)

Оскільки окремі звернення до шини PCIe можуть затримуватися перериваннями процесора чи конкурентним трафіком DMA, вибірки з великою тривалістю кругової затримки `delay_i = x_{i, post} - x_{i, pre}` викривляють оцінку регресії. Для очищення даних застосовується фільтрація за медіанним абсолютним відхиленням (Median Absolute Deviation, MAD):

```
1. Знаходиться медіана затримок:
   m_delay = median( {delay_1, delay_2, ..., delay_M} )

2. Обчислюється MAD:
   MAD = median( {|delay_i - m_delay|} )

3. Критерій відбору якісних вибірок:
   |delay_i - m_delay| ≤ 2.5 · 1.4826 · MAD
```

Вибірки, що не відповідають цьому критерію, відкидаються до запуску регресійного розрахунку, що знижує випадковий джитер оцінки фази з мікросекундного рівня до десятків наносекунд.

### 4. Моделювання фізичної асиметрії середовища поширення сигналу

У протоколах двостороннього обміну мітками часу (PTP або NTP) базове рівняння оцінки розсинхрону годинників спирається на гіпотезу симетричності каналу зв'язку. Нехай `t_1` — час виходу пакета `Sync` з ведучого пристрою (Master), `t_2` — час його прибуття на ведений пристрій (Slave), `t_3` — час відправки запиту `Delay_Req` веденим, а `t_4` — час його прийому ведучим.

Якщо пряма затримка `d_ms` та зворотна затримка `d_sm` різняться на величину асиметрії `Δ_asym`:

```
d_ms = d_mean + Δ_asym
d_sm = d_mean - Δ_asym
```

Тоді виміряні часові інтервали пов'язані з істинним фазовим зсувом `θ = T_slave - T_master` рівняннями:

```
t_2 - t_1 = θ + d_ms = θ + d_mean + Δ_asym
t_4 - t_3 = -θ + d_sm = -θ + d_mean - Δ_asym
```

Стандартна оцінка зсуву без урахування асиметрії дає:

```
θ_calc = ( (t_2 - t_1) - (t_4 - t_3) ) / 2                  [базова формула зсуву PTP]
       = ( (θ + d_mean + Δ_asym) - (-θ + d_mean - Δ_asym) ) / 2 [підстановка виміряних інтервалів]
       = ( 2·θ + 2·Δ_asym ) / 2                             [розкриття дужок та скорочення d_mean]
       = θ + Δ_asym                                         [результуючий зсув із похибкою асиметрії]
```

Таким чином, будь-яка неврахована асиметрія лінії зв'язку `Δ_asym` безпосередньо транслюється у систематичну похибку синхронізації часу `1:1`.

#### Фізичні джерела асиметрії в оптичних та мідних середовищах

1. **Різниця оптичних довжин хвиль у волокні (WDM / BiDi):** При використанні двонаправлених оптичних трансиверів BiDi передача в прямому напрямку відбувається на довжині хвилі `λ_1 = 1310` нм, а у зворотному — `λ_2 = 1490` нм або `1550` нм. Через хроматичну дисперсію кварцового скла ефективні показники заломлення різняться: `n(1310 нм) ≈ 1.4677`, `n(1550 нм) ≈ 1.4682`. На оптичній лінії довжиною `L = 20` км різниця часу поширення становить:
```
Δ_prop = ( L · (n_2 - n_1) ) / c
       = ( 20000 м · 0.0005 ) / ( 2.99792458 · 10⁸ м/с )
       ≈ 33.35 наносекунди
```
2. **Асиметрія затримок трансиверів PHY (SerDes Pipeline):** Конвеєри кодування 8b/10b або 64b/66b у передавачі та приймачі фізичного рівня (PHY) містять буфери еластичності (Elasticity Buffers), які вносять детерміновані, але неоднакові затримки `t_tx_phy ≠ t_rx_phy` (типово від 15 до 60 нс).
3. **Числовий розрахунок компенсації для мереж 10G-EPON:** Для лінії довжиною `L = 10` км із довжинами хвиль 1270 нм (Upstream, `n_1 = 1.4685`) та 1577 нм (Downstream, `n_2 = 1.4679`) різниця показників дорівнює `Δn = -0.0006`. Відповідна асиметрія становить `Δ_asym = (10000 · (-0.0006)) / 3·10⁸ = -20.01` нс. Запис значення `-20.01` нс у поле `asymmetryCorrection` повністю усуває цю зміщеність:

```
asymmetryCorrection = -20.01 нс
θ_true = θ_calc - (-20.01 нс) = θ_calc + 20.01 нс
```

### 5. Динаміка сервопетлі PI-контролера годинника

Отримані оцінки фазового зсуву `θ_k` та відносної частоти використовуються для замкненого керування апаратним годинником через пропорційно-інтегральний (PI) сервоконтролер (Clock Servo).

#### Різницеві рівняння цифрового контролера

Нехай на кроці синхронізації `k` обчислено миттєву похибку фази `e_k = θ_k`. Вихідний керівний вплив підстроювання частоти `u_k` (у ppb) розраховується за схемою:

```
Пропорційна складова:
P_k = K_p · e_k

Інтегральна складова (накопичений дрейф генератора):
I_k = I_{k-1} + K_i · e_k · T_sync

Керівний сигнал:
u_k = P_k + I_k
```

Тут `T_sync` — період між пакетами синхронізації (наприклад, 1/8 с, 1/16 с або 1 с).

#### Умова стійкості та характеристичне рівняння

У z-просторі передавальна функція замкненої системи від похибки вхідних міток до вихідного часу годинника описується виразом:

```
H(z) = ( (K_p + K_i · T) · z - K_p ) / ( z² + (K_p + K_i · T - 2) · z + (1 - K_p) )
```

Для забезпечення аперіодичного перехідного процесу без перерегулювання (Critical Damping) коефіцієнти петлі обираються відповідно до власної резонансної частоти `ω_n` та коефіцієнта демпфування `ζ = 1.0`:

```
K_p = 2 · ζ · ω_n = 2 · ω_n
K_i = ω_n²
```

Якщо власний шум кварцового генератора характеризується температурним дрейфом `10` ppb/°C, типове значення смуги пропускання петлі встановлюється на рівні `ω_n = 0.05 .. 0.2` рад/с, що забезпечує ефективне придушення високочастотного мережевого джитеру вибірок (Phase Jitter) при збереженні швидкої реакції на повільний температурний дрейф кристала (Wander).

### 6. Теорема модульного розгортання лічильників (Unwrapping Theorem)

У багатьох прикладних протоколах реального часу (RTP, апаратні таймери захоплення мікроконтролерів, лічильники інтервалів) мітка часу передається як обмежене беззнакове `N`-бітне число, що функціонує в кільці лишків за модулем `2^N`:

```
t_k ∈ ℤ / 2ᴺℤ = {0, 1, 2, ..., 2ᴺ - 1}
```

Нехай `T_continuous(t)` — монотонна неперервна фізична часова шкала, а `t_k` — дискретні спостереження цієї шкали за модулем `2^N` у моменти надходження вибірок `k = 0, 1, 2, ...`:

```
t_k = T_continuous(t_k) mod 2ᴺ
```

Потрібно побудувати рекурентну послідовність `U_k ∈ ℤ` (64-бітний монотонний час), яка точно відновлює повне неперервне значення `T_continuous(t_k)` без втрати обертів лічильника.

#### Формулювання теореми

> **Теорема про однозначне відновлення:**  
> Якщо для будь-яких двох послідовних вибірок `k-1` та `k` істинний приріст часу `ΔT = T_continuous(t_k) - T_continuous(t_{k-1})` обмежений за абсолютною величиною половиною динамічного діапазону лічильника:
> ```
> -2^(N-1) ≤ ΔT < 2^(N-1)
> ```
> то значення приросту `ΔT` однозначно визначається через операцію віднімання в кільці `ℤ / 2ᴺℤ` з інтерпретацією результату як знакового числа в доповняльному коді:
> ```
> δ_k = (intN_t)( (uintN_t)t_k - (uintN_t)t_{k-1} )
> ```
> А розгорнуте 64-бітне значення часу обчислюється як:
> ```
> U_k = U_{k-1} + δ_k
> ```

#### Доведення теореми

За означенням операції взяття за модулем:

```
t_k ≡ T_continuous(t_k) (mod 2ᴺ)
t_{k-1} ≡ T_continuous(t_{k-1}) (mod 2ᴺ)
```

Віднімемо другу рівність від першої:

```
(t_k - t_{k-1}) mod 2ᴺ ≡ ( T_continuous(t_k) - T_continuous(t_{k-1}) ) mod 2ᴺ
d ≡ ΔT (mod 2ᴺ)
```

Тут `d = (uintN_t)(t_k - t_{k-1})` — беззнакова різниця в діапазоні `[0, 2^N - 1]`.

Розглянемо відображення знакового приведення типу `(intN_t)d`:
У двійковому доповняльному коді розрядна сітка `N` бітів інтерпретує числа від `0` до `2^(N-1) - 1` як додатні, а числа від `2^(N-1)` до `2^N - 1` як від'ємні, віднімаючи `2^N`:

```
δ_k = { d,          якщо 0 ≤ d < 2^(N-1)
      { d - 2ᴺ,     якщо 2^(N-1) ≤ d < 2ᴺ
```

Оскільки за умовою теореми `-2^(N-1) ≤ ΔT < 2^(N-1)`, у цьому інтервалі існує **рівно одне** число, конгруентне `d` за модулем `2^N`:

1. Якщо `0 ≤ ΔT < 2^(N-1)`, то `d = ΔT`. Приведення типу дає `δ_k = d = ΔT`.
2. Якщо `-2^(N-1) ≤ ΔT < 0`, то `d = ΔT + 2^N`. Оскільки `2^(N-1) ≤ d < 2^N`, приведення типу повертає `δ_k = d - 2^N = (ΔT + 2^N) - 2^N = ΔT`.

Отже, в усіх випадках `δ_k = ΔT`. Теорему доведено.

#### Геометрична та практична інтерпретація випадків

```
Випадок 1: Звичайний плин часу (без переповнення)
  t_{k-1} = 1000,  t_k = 1500
  d = 1500 - 1000 = 500
  δ_k = +500

Випадок 2: Переповнення 32-бітного лічильника через нуль
  t_{k-1} = 0xFFFFFF00 (4 294 967 040)
  t_k     = 0x00000100 (256)
  d = 0x00000100 - 0xFFFFFF00 = 0x00000200 (512)
  δ_k = +512  [лічильник коректно розпізнано як такий, що збільшився на 512]

Випадок 3: Перевпорядкування пакетів у мережі (прихід пізнішого пакета першим)
  t_{k-1} = 0x00000100 (256)
  t_k     = 0xFFFFFF00 (4 294 967 040)
  d = 0xFFFFFF00 - 0x00000100 = 0xFFFFFE00
  δ_k = (int32_t)0xFFFFFE00 = -512  [пакет з минулого, дельта від'ємна]
```

### 7. Розрахунок параметрів для RTP-потоків різного типу

У протоколі RTP (RFC 3550) мітка часу збільшується відповідно до частоти дискретизації джерела інформації. Період повного циклічного обертання лічильника `T_wrap` та максимальний допустимий інтервал між пакетами `T_max_gap` визначаються формулами:

```
T_wrap = 2³² / f_sampling
T_max_gap = 2³¹ / f_sampling
```

| Тип медіа / Кодек | Частота `f_s` | Квант часу | Період переповнення `T_wrap` | Граничний інтервал `T_max_gap` |
|:---|:---:|:---:|:---:|:---:|
| **Відео (H.264, HEVC, AV1)** | 90 000 Гц | 11.111 мкс | ~13.256 годин (47 721.8 с) | ~6.628 годин |
| **Аудіо високої якості (Opus, PCM)** | 48 000 Гц | 20.833 мкс | ~24.855 годин (89 478.5 с) | ~12.427 годин |
| **Аудіо телефонії (G.711, AMR)** | 8 000 Гц | 125.000 мкс | ~6.214 діб (536 870.9 с) | ~3.107 діб |
| **Апаратний лічильник PHC** | 1 000 000 000 Гц | 1.000 нс | ~4.295 секунди | ~2.147 секунди |

Для апаратного таймера з частотою 1 ГГц лічильник наносекунд переповнюється кожні 4.295 секунди. Це доводить необхідність періодичного зчитування лічильника PHC драйвером операційної системи з інтервалом не менше ніж раз на 1–2 секунди для підтримки безперервної 64-бітної шкали часу.

#include <stdint.h>
#include <stdbool.h>

// ── 1. Перетворення NTP <-> Наносекунди ──────────────────────────────────────

uint32_t nsec_to_ntp_fraction(uint32_t nsec) {
    if (nsec >= 1000000000U) {
        nsec = 999999999U;
    }
    uint64_scaled = ((uint64_t)nsec << 32) + 500000000ULL;
    return (uint32_t)(scaled / 1000000000ULL);
}

uint32_t ntp_fraction_to_nsec(uint32_t ntp_frac) {
    uint64_t prod = (uint64_t)ntp_frac * 1000000000ULL + 0x80000000ULL;
    return (uint32_t)(prod >> 32);
}

// ── 2. Модульне розгортання 32-бітного лічильника у 64-бітну шкалу ───────────

typedef struct {
    uint32_t last_raw;
    int64_t  unwrapped;
    bool     initialized;
} TimestampUnwrapper32;

void unwrapper32_init(TimestampUnwrapper32 *u) {
    u->last_raw = 0;
    u->unwrapped = 0;
    u->initialized = false;
}

int64_t unwrapper32_update(TimestampUnwrapper32 *u, uint32_t raw_ts) {
    if (!u->initialized) {
        u->last_raw = raw_ts;
        u->unwrapped = (int64_t)raw_ts;
        u->initialized = true;
        return u->unwrapped;
    }

    // Знакова 32-бітна різниця автоматично обробляє перехід через нуль
    int32_t delta = (int32_t)(raw_ts - u->last_raw);
    u->unwrapped += (int64_t)delta;
    u->last_raw = raw_ts;

    return u->unwrapped;
}

#include <cstdint>
#include <concepts>
#include <limits>
#include <optional>
#include <type_traits>

// ── 1. Конвертер форматів часових міток ──────────────────────────────────────

class TimestampConverter {
public:
    static constexpr uint64_t NTP_TO_UNIX_EPOCH_OFFSET = 2208988800ULL;

    [[nodiscard]] static constexpr uint32_t nsec_to_ntp_fraction(uint32_t nsec) noexcept {
        if (nsec >= 1'000'000'000U) {
            nsec = 999'999'999U;
        }
        uint64_t scaled = (static_cast<uint64_t>(nsec) << 32) + 500'000'000ULL;
        return static_cast<uint32_t>(scaled / 1'000'000'000ULL);
    }

    [[nodiscard]] static constexpr uint32_t ntp_fraction_to_nsec(uint32_t ntp_frac) noexcept {
        uint64_t prod = static_cast<uint64_t>(ntp_frac) * 1'000'000'000ULL + 0x8000'0000ULL;
        return static_cast<uint32_t>(prod >> 32);
    }

    [[nodiscard]] static constexpr int64_t scale_to_sub_nanoseconds(int64_t nsec, uint16_t sub_ns_frac = 0) noexcept {
        return (nsec << 16) | (sub_ns_frac & 0xFFFF);
    }

    [[nodiscard]] static constexpr int64_t sub_nanoseconds_to_nsec(int64_t correction_field) noexcept {
        return correction_field >> 16;
    }
};

// ── 2. Узагальнений розгортач циклічних лічильників (Unwrapper) ───────────────

template <std::unsigned_integral RawType, std::signed_integral OutputType = int64_t>
class ModularTimestampUnwrapper {
    using SignedDiffType = std::make_signed_t<RawType>;

    std::optional<RawType> last_raw_{};
    OutputType accumulated_epoch_{0};

public:
    constexpr void reset() noexcept {
        last_raw_.reset();
        accumulated_epoch_ = 0;
    }

    [[nodiscard]] OutputType update(RawType raw_value) noexcept {
        if (!last_raw_.has_value()) {
            last_raw_ = raw_value;
            accumulated_epoch_ = static_cast<OutputType>(raw_value);
            return accumulated_epoch_;
        }

        // Обчислення знакової різниці в модульному просторі
        SignedDiffType delta = static_cast<SignedDiffType>(raw_value - *last_raw_);
        accumulated_epoch_ += static_cast<OutputType>(delta);
        last_raw_ = raw_value;

        return accumulated_epoch_;
    }

    [[nodiscard]] OutputType current_value() const noexcept {
        return accumulated_epoch_;
    }
};

// Спеціалізація для 32-бітного RTP та апаратних таймерів
using RtpTimestampUnwrapper = ModularTimestampUnwrapper<uint32_t, int64_t>;
