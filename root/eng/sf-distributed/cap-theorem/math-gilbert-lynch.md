# 🧮 Формальна модель і доведення Гілберта і Лінч (2002)

Ця математична вставка містить суворе формулювання моделі автоматів введення-виведення (I/O Automata), повне доведення неможливості побудови атомарного розподіленого регістра за наявності мережевого розділення (Gilbert & Lynch, 2002), аналіз імовірнісних протоколів та виведення теоретичних меж латентності в моделі PACELC (Abadi, 2012).

## 1. Формальна модель розподіленої системи

Розподілену систему моделюють як множину незалежних детермінованих або ймовірнісних вузлів (автоматів) `V = {p₁, p₂, ..., pₙ}`, з'єднаних каналами передачі повідомлень.

Кожен вузол `pᵢ` має внутрішній простір станів, переходи між якими відбуваються під дією трьох типів подій:
1. **Події виклику (Invocations):** надходження запиту від зовнішнього клієнта (наприклад, `inv(Write(v))` або `inv(Read())`).
2. **Події відповіді (Responses):** повернення результату клієнту (наприклад, `res(OK)` або `res(v)`).
3. **Мережеві події:** відправлення повідомлення `send(m, pⱼ)` та отримання повідомлення `recv(m, pᵢ)`.

**Виконанням (Execution)** системи називають послідовність чергування станів і подій:

```
E = s₀, e₁, s₁, e₂, s₂, ..., eₖ, sₖ
```

### Модель асинхронної мережі (Asynchronous Network)
В асинхронній мережі не існує глобального фізичного годинника та верхньої гарантованої межі часу доставки повідомлень. Якщо повідомлення `m` відправлене вузлом `p₁` до `p₂`, час доставки `t_recv - t_send` може бути довільно великим, але скінченним у штатному режимі.

### Модель розділення мережі (Network Partition)
Мережевим розділенням називають стан, за якого множина вузлів `V` розбивається на дві непорожні підмножини `G₁` та `G₂` такі, що:

```
G₁ ∩ G₂ = ∅           [множини не перетинаються]
G₁ ∪ G₂ = V           [об'єднання покриває весь кластер]
∀ pᵢ ∈ G₁, pⱼ ∈ G₂:   [усі повідомлення між групами губляться]
```

Для будь-якого повідомлення `m`, відправленого з `G₁` до `G₂` (або навпаки), подія `recv(m)` ніколи не настає у виконанні `E`.

## 2. Формальні визначення властивостей

Розподілений об'єкт моделює спільний атомарний регістр (англ. *Read/Write Register*), який підтримує дві операції: `Write(v)` (запис значення `v`) та `Read()` (читання поточного значення).

Початковий стан регістра містить константу `v₀`.

Кожна операція `op` починається подією виклику `inv(op)` і завершується подією відповіді `res(op)`. Проміжком часу операції є інтервал:

```
I(op) = [t_start(op), t_finish(op)]
```

### Визначення 1: Лінеаризовність (Atomic Consistency / C)
Виконання `E` називають лінеаризовним (атомарно узгодженим), якщо існує повний строгий порядок `<` на множині всіх завершених операцій `Ops(E)`, який задовольняє дві умови:

1. **Узгодженість із реальним часом (Real-time order preservation):**
Якщо операція `op₁` завершилася в абсолютному часі раніше, ніж почалася операція `op₂`, то `op₁` зобов'язана передувати `op₂` у порядку лінеаризації:

```
t_finish(op₁) < t_start(op₂) ⇒ op₁ < op₂
```

2. **Семантика послідовного регістра (Sequential register semantics):**
Кожна операція читання `Read()` повертає значення останньої операції запису `Write(v)`, яка передує їй у відношенні `<` (або початкове значення `v₀`, якщо жодного попереднього запису немає):

```
val(Read()) = val(max_{<} { w ∈ Writes | w < Read() })
```

### Визначення 2: Доступність (Availability / A)
Розподілена система вважається доступною, якщо кожен запит від клієнта до будь-якого незакритиого (справного) вузла гарантовано повертає відповідь за скінченну кількість локальних кроків:

```
∀ op, inv(op) ∈ E ⇒ ∃ res(op) ∈ E : t_finish(op) < ∞
```

Відповідь не може бути помилкою збою або відхиленням операції (як-от HTTP 500 чи нескінченне очікування); вона зобов'язана бути успішним результатом за семантикою регістра.

## 3. Доведення неможливості для асинхронної мережі (Теорема 1)

**Формулювання теореми (Gilbert & Lynch, 2002):**
В асинхронній мережі з можливістю мережевого розділення не існує розподіленого алгоритму, який гарантує одночасно лінеаризовність (C) та доступність (A).

### Доведення (від супротивного)

Припустимо, що існує детермінований протокол `P`, який на кластері `V` гарантує і лінеаризовність, і доступність за будь-якого мережевого розділення.

Нехай множина вузлів розбита на дві ізольовані групи: `G₁` та `G₂`. Усі повідомлення між `G₁` та `G₂` губляться мережею.

Побудуємо ланцюг із трьох суперечливих виконань.

#### Крок 1: Побудова виконання α (Запис у групі G₁)
Нехай у момент часу `t₁` клієнт надсилає запит на запис нового значення `v₁` (де `v₁ ≠ v₀`) до вузла `p₁ ∈ G₁`:

```
inv(Write(v₁)) на вузлі p₁ ∈ G₁
```

Оскільки за припущенням система володіє властивістю **Доступності (Availability)**, вузол `p₁` зобов'язаний повернути успішну відповідь за скінченний час `t₂` (`t₂ < ∞`), не отримавши жодного повідомлення від вузлів із групи `G₂` (оскільки мережа між `G₁` та `G₂` розділена).

Операція `Write(v₁)` успішно завершується в момент `t₂`:

```
t_start(Write) = t₁
t_finish(Write) = t₂
t₁ ≤ t₂ < ∞
```

#### Крок 2: Побудова виконання β (Читання в групі G₂)
Розглянемо незалежне виконання `β`, де мережа також розділена на `G₁` та `G₂`, але операція запису `Write(v₁)` у групі `G₁` взагалі не викликалася.

У момент часу `t₃` (де `t₃ > t₂`) клієнт надсилає запит на читання до вузла `p₂ ∈ G₂`:

```
inv(Read()) на вузлі p₂ ∈ G₂
```

За властивістю Доступності вузол `p₂` зобов'язаний повернути відповідь у момент `t₄` (`t₄ < ∞`), не чекаючи повідомлень від `G₁`.

Оскільки в системі не відбувалося жодних записів, єдиним лінеаризовним значенням для повернення є початковий стан регістра:

```
val(Read()) = v₀
```

#### Крок 3: Побудова об'єднаного виконання γ
Тепер сконструюємо виконання `γ`, у якому:
1. Мережа залишається повністю розділеною між `G₁` та `G₂`.
2. У момент `t₁` на вузлі `p₁ ∈ G₁` виконується операція `Write(v₁)`, яка завершується в момент `t₂` (як у виконанні `α`).
3. У момент `t₃` (де `t₃ > t₂`) на вузлі `p₂ ∈ G₂` виконується операція `Read()`, яка завершується в момент `t₄` (як у виконанні `β`).

Розглянемо локальний стан вузлів групи `G₂` у виконанні `γ`:
Оскільки жодне повідомлення з `G₁` не дійшло до `G₂` через розділення каналу, історія локальних подій і переходів станів на кожному вузлі `p ∈ G₂` у виконанні `γ` є **абсолютно ідентичною** (нерозрізненною) до виконання `β`:

```
LocalState(G₂, γ) ≡ LocalState(G₂, β)
```

Через повну нерозрізненність станів вузол `p₂` у виконанні `γ` зобов'язаний виконати ті самі дії, що й у `β`, і повернути клієнту значення:

```
val(Read()) = v₀
```

#### Крок 4: Отримання суперечності
Перевіримо виконання `γ` на відповідність визначенню **Лінеаризовності**:

1. За часовими мітками виконання операція `Write(v₁)` строго передує операції `Read()` у реальному фізичному часі:

```
t_finish(Write(v₁)) = t₂ < t₃ = t_start(Read())
⇒ Write(v₁) < Read()    [за умовою узгодженості з реальним часом]
```

2. За семантикою послідовного регістра операція читання `Read()` зобов'язана повернути значення останнього завершеного запису, тобто `v₁`:

```
val(Read())
= val(Write(v₁))        [за семантикою регістра]
= v₁                    [підстановка записаного значення]
```

3. Але у виконанні `γ` вузол `p₂` повернув:

```
val(Read()) = v₀ ≠ v₁
```

Отримали строгу логічну суперечність: `v₁ = v₀` при `v₁ ≠ v₀`.

Отже, наше початкове припущення хибне. Не існує алгоритму, здатного одночасно гарантувати лінеаризовність і доступність в асинхронній мережі з розділенням.

## 4. Аналіз імовірнісних та рандомізованих алгоритмів

Чи можна обійти теорему CAP, використовуючи ймовірнісні протоколи (наприклад, підкидання випадкової монети або gossip-алгоритми)?

Нехай протокол `P_rand` є ймовірнісним автоматом. У кожному кроці перехід стану визначається випадковою величиною `R`.
Визначимо ймовірнісну доступність (англ. *Probabilistic Availability*): для будь-якої операції `op` імовірність її успішного завершення за скінченний час дорівнює одиниці:

```
P(t_finish(op) < ∞) = 1
```

Якщо мережеве розділення є перманентним, то в ізольованій групі `G₂` ймовірнісний розподіл локальних спостережень `Dist(LocalState(G₂))` залишається абсолютно незалежним від того, чи відбувся запис у групі `G₁`.
Отже, для будь-якого розподілу відповідей `P(val(Read()) = v₁)` у групі `G₂` справедлива нерівність:

```
P(val(Read()) = v₁ | Write(v₁) в G₁) = P(val(Read()) = v₁ | Запису не було)
```

Якщо алгоритм повертає `v₁` з імовірністю `p > 0`, він із тією самою ймовірністю `p` поверне `v₁` у системі, де запису ніколи не було, що спричиняє помилку фантомного читання (порушення безпеки). Якщо ж `p = 0`, алгоритм завжди повертає `v₀`, що порушує лінеаризовність з імовірністю 1.

Таким чином, рандомізація не здатна подолати фундаментальне обмеження теореми CAP.

## 5. Частково синхронна модель і межі затримки (Теорема 2)

Гілберт і Лінч також дослідили частково синхронну модель (англ. *Partially Synchronous Network*), де:
- Кожен вузол має локальний фізичний годинник із гарантованою максимальною швидкістю дрейфу `ρ`:

```
(1 - ρ)·(t₂ - t₁) ≤ Clock(t₂) - Clock(t₁) ≤ (1 + ρ)·(t₂ - t₁)
```

- Час доставки будь-якого повідомлення в штатному режимі не перевищує відомої константи `Δ`.

### Теорема про часткову синхронність
Якщо в частково синхронній системі стається мережеве розділення тривалістю `T > Δ`, система постає перед вибором:
1. Якщо протокол вимагає завершення операцій за час `T_timeout < T`, система зводиться до асинхронного випадку й порушує лінеаризовність (втрата C).
2. Якщо протокол гарантує лінеаризовність, будь-яка операція на вузлах ізольованої меншості зобов'язана чекати часу `T_wait ≥ T` до відновлення каналу зв'язку, що порушує гарантію миттєвої доступності (втрата A).

## 6. Математичне виведення нижньої межі латентності в моделі PACELC

Модель PACELC стверджує, що в штатному режимі за відсутності розділення (Else) існує неминучий компроміс між латентністю (L) та узгодженістю (C).

Розглянемо кластер із двох вузлів `p₁` та `p₂`, розташованих у географічно віддалених регіонах із мінімальним часом проходження сигналу в один бік `d = RTT / 2`.

Нехай клієнт викликає `Write(v)` на вузлі `p₁`, а інший клієнт викликає `Read()` на вузлі `p₂`.
Позначимо через `L(Write)` час виконання операції запису, а через `L(Read)` — час виконання операції читання.

Для забезпечення лінеаризовності операція `Read()`, яка починається в момент `t_finish(Write) + ε` (де `ε → 0`), зобов'язана повернути значення `v`.

Інформація про запис `Write(v)` може потрапити з вузла `p₁` на вузол `p₂` лише через мережеве повідомлення. Мінімальний фізичний час доставки цього повідомлення дорівнює `d`.

Звідси випливає фундаментальна теорема Лінч про суму затримок:

```
L(Write) + L(Read) ≥ d = RTT / 2
```

### Висновок для інженерних архітектур:
1. **Строга узгодженість (PC/EC):** якщо система гарантує локальне швидке читання (`L(Read) ≈ 0`), операція запису зобов'язана здійснити синхронний раунд реплікації:

```
L(Write) ≥ RTT
```

2. **Низька латентність (PA/EL):** якщо система вимагає миттєвого підтвердження запису на локальному вузлі (`L(Write) ≈ 0`) та миттєвого читання на віддаленому вузлі (`L(Read) ≈ 0`), то сума затримок `0 + 0 < d`, що робить передачу нового значення фізично неможливою. Така система математично зобов'язана погодитися на кінцеву узгодженість (Eventual Consistency) і допускати застарілі читання на інтервалі часу `[0, d]`.

## 7. Теорема про стелю причинної узгодженості (Mahajan et al., 2011)

Виникає фундаментальне математичне питання: якщо лінеаризовність (C) недосяжна в доступній (AP) системі під час розділення, то **яка найсильніша модель консистентності залишається математично можливою**?

У 2011 році Прінстонська дослідницька група (Mahajan, Alvisi, Dahlin) опублікувала теорему про межу узгодженості (англ. *Consistency Hierarchy Boundary*).

### Визначення: Відношення причинності (Happens-Before / →)
Для будь-яких двох операцій `op₁` та `op₂` у системі відношення причинності `op₁ → op₂` виконується тоді й лише тоді, коли:
1. **Порядок процесу (Program Order):** обидві операції виконані одним і тим самим клієнтом (або вузлом), і `op₁` передує `op₂`.
2. **Передача через повідомлення (Message Passing):** `op₁` є операцією запису `Write(v)`, а `op₂` є операцією читання `Read()`, яка повернула значення `v` (клієнт прочитав результат запису іншого клієнта).
3. **Транзитивність:** якщо `op₁ → op₂` та `op₂ → op₃`, то `op₁ → op₃`.

### Визначення: Причинна узгодженість (Causal Consistency)
Система є причинно узгодженою, якщо для кожного вузла `pᵢ` існує локальний лінійний порядок `<ᵢ` над множиною всіх відомих йому операцій, такий що:
1. Порядок `<ᵢ` узгоджений із відношенням причинності:

```
∀ op₁, op₂ : (op₁ → op₂) ⇒ (op₁ <ᵢ op₂)
```

2. Кожне читання повертає значення останнього запису в локальному порядку `<ᵢ`.

### Теорема Махаджана (2011)
1. **Неможливість послідовної узгодженості:** У мережі з можливістю розділення не існує повністю доступного (AP) протоколу, що гарантує послідовну узгодженість (Sequential Consistency).
2. **Досяжність причинної узгодженості:** Існує повністю доступний (AP) протокол на базі векторних годинників і причинних бар'єрів (Causal Barriers), який гарантує причинну узгодженість за будь-яких мережевих розділень.

**Висновок:** Причинна узгодженість є точною теоретичною стелею (англ. *causal consistency ceiling*) для систем із гарантованою доступністю під час аварій мережі.

## 8. Кількісна оцінка застарілості даних (Bounded Staleness)

У системах квадранта **PA/EL** компроміс вимірюється не бінарно, а через функцію застарілості (англ. *Staleness*).

Нехай `t_w` — фізичний час завершення останнього запису `Write(v)` на координаторі, а `t_r` — фізичний час виконання читання `Read()` на віддаленій репліці (`t_r > t_w`). Якщо репліка повертає застаріле значення версії `k - m` замість свіжої версії `k`, визначимо дві метрики розходження:

1. **Часова застарілість (Time-based Staleness, Δt):**

```
Δt = t_r - t_w
```

2. **Версійна застарілість (Version-based Staleness, Δk):**

```
Δk = Version(Current) - Version(Returned)
```

Якщо швидкість генерації записів у системі обмежена константою `λ` (записів на секунду), а максимальний час доставки повідомлення в штатному режимі обмежений константою `Δ_max`, то максимальна версійна застарілість у квадранті PA/EL строго обмежена зверху:

```
E[Δk] ≤ λ · Δ_max
```

Це дозволяє інженерним системам (наприклад, Azure Cosmos DB Bounded Staleness) надавати строгі математичні SLA на свіжість даних без блокування операцій читання.

## 9. Зв'язок із теоремою FLP (Fischer-Lynch-Paterson, 1985)

Теорема CAP тісно пов'язана з класичною теоремою неможливості FLP:
- **FLP (1985):** доводить неможливість досягнення детермінованого консенсусу в асинхронній мережі за наявності хоча б одного відмовленого вузла (Crash Failure).
- **Gilbert & Lynch (2002):** доводить неможливість підтримки лінеаризовного спільного стану за наявності розділення зв'язку між підмножинами справних вузлів.

Обидві теореми окреслюють фундаментальні межі розподілених обчислень: будь-яка спроба подолати ці межі інженерними трюками є або звуженням припущень про надійність мережі, або переходом до слабших моделей консистентності.
