# 🧮 Математичне виведення меж візантійського консенсусу та геометрія кворумів

Розподілений консенсус в умовах візантійських збоїв вимагає строгого математичного обґрунтування двох фундаментальних величин: мінімальної кількості вузлів `N` для протидії `f` зрадникам та розміру кворуму `Q`, необхідного для гарантії безпеки (Safety) та живучості (Liveness).

Нижче наведено формальне виведення межі Лампорта, аналіз впливу синхронності мережі та алгебраїчне доведення інваріанта збереження стану під час переходу між видами (View Change).

## 1. Неможливість консенсусу при N ≤ 3f для непідписаних повідомлень

Доведемо теорему Лампорта-Шостака-Піза (1982): якщо вузли взаємодіють через непідписані (усні) повідомлення, не існує детермінованого алгоритму досягнення консенсусу за умови `N ≤ 3f`.

### Базовий випадок: N = 3, f = 1

Розглянемо систему з трьох процесів: Генерал-командувач `G` та два лейтенанти `L1`, `L2`. Кожен вузол має прийняти бінарне рішення `v ∈ {0, 1}`. Припустимо, що існує коректний протокол.

Побудуємо два нерозрізнені сценарії виконання:

```
Сценарій 1 (Командувач G — зрадник):
  G відправляє команду "1" до лейтенанта L1.
  G відправляє команду "0" до лейтенанта L2.
  L1 повідомляє L2: "Командувач наказав 1".
  L2 повідомляє L1: "Командувач наказав 0".
  Стан L1: отримав (від G: 1, від L2: 0). За вимогою слушності (Validity) L1 зобов'язаний вирішити 1.

Сценарій 2 (Лейтенант L2 — зрадник):
  G — чесний і відправляє команду "1" обом лейтенантам.
  L2 бреше лейтенанту L1: "Командувач сказав мені 0".
  Стан L1: отримав (від G: 1, від L2: 0).
```

Для вузла `L1` множина локальних спостережень у Сценарії 1 та Сценарії 2 є абсолютно ідентичною:
```
Вхідний вектор L1 в Сценарії 1 = Вхідний вектор L1 в Сценарії 2 = { від G: 1, від L2: 0 }
```

Оскільки алгоритм є детермінованим, вузол `L1` зобов'язаний прийняти одне й те саме рішення в обох сценаріях.
* У Сценарії 2 командувач чесний і запропонував `1`, отже за вимогою слушності (Validity) `L1` повинен вирішити `1`.
* За симетрією побудови, вузол `L2` у Сценарії 1 за умови чесного командувача `G`, який запропонував `0`, зобов'язаний вирішити `0`.
* Отже, у Сценарії 1 чесний вузол `L1` вирішує `1`, а чесний вузол `L2` вирішує `0`.

Це прямо порушує вимогу одностайності (Agreement): `v_L1 ≠ v_L2`. Таким чином, для системи з `N = 3` процесів за наявності `f = 1` візантійського вузла детермінований консенсус неможливий.

### Загальний випадок: редукція через супервузли до N ≤ 3f

Припустимо від супротивного, що існує протокол для довільної кількості вузлів `N ≤ 3f` за наявності `f` зрадників.

Розіб'ємо множину всіх `N` процесів на три неперетинні підмножини `A`, `B`, `C` такі, що кожна підмножина містить не більше ніж `f` вузлів:
```
|A| ≤ f,   |B| ≤ f,   |C| ≤ f,   |A| + |B| + |C| = N ≤ 3f
```

Об'єднаємо всі процеси всередині кожної підмножини в один віртуальний процес (супервузол). Супервузол `A` виконує алгоритм за всі процеси множини `A`, обмінюючись повідомленнями із супервузлами `B` та `C`. Оскільки підмножина `C` налічує не більше ніж `f` процесів, перехід усіх вузлів множини `C` у візантійський стан еквівалентний наявності максимум `f` зрадників у вихідній системі.

Ми отримали еквівалентну систему з трьох процесів (`A`, `B`, `C`) з одним візантійським учасником (`C`), для якої консенсус неможливий згідно з базовим доведенням.

Отже, необхідною умовою розв'язності візантійського консенсусу без криптографічних підписів є:
```
N ≥ 3f + 1
```

## 2. Розрахунок розміру кворуму в асинхронних BFT-системах

В асинхронній мережі повідомлення можуть затримуватися на довільний час без верхньої межі. Протокол узгодження зобов'язаний задовольняти дві фундаментальні вимоги:

1. **Живучість (Liveness):** Протокол не має права очікувати на повідомлення від усіх `N` вузлів, оскільки `f` вузлів можуть зазнати аварійної зупинки й ніколи не надіслати відповіді. Тому розмір кворуму `Q` не може перевищувати `N - f`:
```
Q ≤ N - f         [гарантія уникнення блокування через f відсутніх вузлів]
```

2. **Безпека (Safety):** Серед отриманих `Q` повідомлень до `f` відповідей можуть надходити від активних візантійських вузлів, які скоординовано брешуть. Щоб чесні вузли складали абсолютну більшість у вибірці й могли диктувати результат, кількість чесних відповідей `Q - f` повинна строго перевищувати кількість зрадників `f`:
```
Q - f > f
Q ≥ 2f + 1        [умова домінування чесних вузлів у прийнятті рішення]
```

Поєднуючи обидві нерівності при мінімальному розмірі кластера `N = 3f + 1`:
```
2f + 1 ≤ Q ≤ (3f + 1) - f
2f + 1 ≤ Q ≤ 2f + 1
⇒ Q = 2f + 1
```

Розмір кворуму `Q = 2f + 1` є єдино можливим значенням, що одночасно гарантує завершуваність без очікування `f` мовчазних реплік та захист від спотворення результату `f` активними зрадниками.

## 3. Теорема про перетин кворумів

Доведемо, що будь-які два кворуми розміром `2f + 1` у системі з `N = 3f + 1` реплік гарантовано містять щонайменше один спільний чесний вузол.

Нехай `Q1` та `Q2` — два довільні кворуми розміром `|Q1| = |Q2| = 2f + 1`.

За теоремою про потужність об'єднання скінченних множин:
```
|Q1 ∩ Q2| = |Q1| + |Q2| - |Q1 ∪ Q2|
```

Оскільки об'єднання `Q1 ∪ Q2` є підмножиною всієї множини реплік кластера, його розмір не може перевищувати загальну кількість вузлів `N = 3f + 1`:
```
|Q1 ∪ Q2| ≤ 3f + 1
```

Підставимо ці вирази у формулу перетину:
```
|Q1 ∩ Q2| ≥ (2f + 1) + (2f + 1) - (3f + 1)     [підстановка розмірів кворумів]
|Q1 ∩ Q2| ≥ 4f + 2 - 3f - 1                    [розкриття дужок]
|Q1 ∩ Q2| ≥ f + 1                              [алгебраїчне спрощення]
```

Отже, будь-які два кворуми перетинаються щонайменше по `f + 1` вузлах.

Оцінимо кількість гарантовано чесних вузлів `H` у перетині `Q1 ∩ Q2`, враховуючи, що в усій системі існує щонайбільше `f` візантійських вузлів:
```
H = |Q1 ∩ Q2| - f_byzantine
H ≥ (f + 1) - f
H ≥ 1
```

Оскільки в перетині присутній щонайменше один чесний вузол, а чесний вузол строго виконує алгоритм і ніколи не голосує двічі за різні пропозиції для одного слота в межах одного виду, неможливо сформувати два дійсні сертифікати підтвердження для суперечливих транзакцій.

## 4. Доведення незмінності стану під час зміни виду (Cross-View Invariant)

Розглянемо найскладніший випадок безпеки: транзакція `m` була зафіксована (Committed-Local) бодай однією чесною реплікою `R` у виді `v`, після чого лідер виду `v` зазнав збою, і кластер ініціював процедуру зміни виду на `v + 1`. Доведемо, що транзакція `m` обов'язково увійде до нового виду `v + 1` під тим самим номером слота `n`.

1. Якщо чесна репліка `R` зафіксувала транзакцію `m` на слоті `n` у виді `v`, вона отримала сертифікат фіксації, який спирається на наявність підготовленого сертифіката (Prepared Certificate) у кворумі з `2f + 1` вузлів. Позначимо цей кворум як `Q_commit`.
2. Кожен чесний вузол із кворуму `Q_commit` зберіг повідомлення `Prepare` для слота `n` із дайджестом `d = Hash(m)` у своєму локальному журналі.
3. Для переходу у новий вид `v + 1` новий лідер зобов'язаний зібрати кворум із `2f + 1` повідомлень `VIEW-CHANGE` (включно з власним). Позначимо цей кворум як `Q_vc`.
4. Обчислимо перетин кворуму фіксації `Q_commit` та кворуму зміни виду `Q_vc`:
```
|Q_commit ∩ Q_vc| ≥ (2f + 1) + (2f + 1) - (3f + 1) = f + 1
```
5. Серед `f + 1` спільних вузлів щонайменше `(f + 1) - f = 1` вузол є **чесним**.
6. Цей чесний вузол передає свій підготовлений сертифікат для пари `(n, d)` у повідомленні `VIEW-CHANGE` новому лідеру.
7. Згідно з алгоритмом формування повідомлення `NEW-VIEW`, новий лідер обирає для слота `n` той запис, який має підготовлений сертифікат із найвищим номером виду. Оскільки чесний вузол надав дійсний сертифікат, новий лідер **зобов'язаний включити запит m у повідомлення NEW-VIEW** під номером `n`.

Цим завершується математичне доведення властивості Safety для протоколу PBFT за довільної кількості змін видів координатора.
