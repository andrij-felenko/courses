# 🧮 Математичний аналіз дефектів пам'яті в алгоритмах March C- та March X

Будь-яка комірка статичної оперативної пам'яті (SRAM) є транзисторною структурою (типово 6T-елемент на базі двох перехресно сполучених інверторів), яка перебуває під постійним впливом паразитних ємностей сусідніх провідників, витоків діелектрика та завад по шинах живлення. Простий послідовний запис довільного числа з наступним читанням не здатен виявити складні дефекти кремнію: наприклад, коли запис у сусідню комірку інвертує значення поточної або коли дешифратор адреси обирає два фізичні рядки одночасно. Щоб гарантувати працездатність масиву пам'яті за стандартами функційної безпеки IEC 60730 Class B та IEC 61508, застосовують математично верифіковані алгоритми маршування — **March X** та **March C-**.

```
Простір станів масиву пам'яті:
  A = {0, 1, 2, ..., N - 1}       [множина адрес N слів/комірок]
  S = (s_0, s_1, ..., s_{N-1})    [вектор стану комірок, s_i ∈ {0, 1}]
```

## Математичні моделі несправностей ОЗП

Для аналізу повноти тестового покриття алгоритмів діагностики стандарти надійності виділяють п'ять фундаментальних класів дефектів кремнієвого масиву пам'яті.

### 1. Несправність залипання (Stuck-At Fault — SAF)

Стан комірки s_i жорстко зафіксований на рівні логічного нуля або логічної одиниці через замикання затвора на шину живлення або землю. Стан комірки не змінюється при спробі запису протилежного значення. Дефект виникає через пробій підзатворного діелектрика або металеві мікроперемички між провідниками живлення.

```
SAF0 (залипання 0):  ∀ w ∈ {0, 1} -> s_i = 0
SAF1 (залипання 1):  ∀ w ∈ {0, 1} -> s_i = 1
```

### 2. Дефект переходу (Transition Fault — TF)

Комірка здатна зберігати обидва логічні рівні, але не може виконати один із двох можливих переходів (0 -> 1 або 1 -> 0). Зазвичай це наслідок деградації підтягуючого p-канального транзистора (PMOS) або стікаючого n-канального транзистора (NMOS) у комірці 6T-SRAM, через що струму перезаряду ємності вузла недостатньо для перемикання тригера за відведений такт тактового сигналу.

```
TF(0->1) [дефект висхідного переходу]:  s_i = 0  і  write(1) -> s_i = 0
TF(1->0) [дефект низхідного переходу]:  s_i = 1  і  write(0) -> s_i = 1
```

### 3. Дефект дешифратора адреси (Address Decoder Fault — AF)

Порушення в логіці адресних дешифраторів (обрив або замикання ліній адресної шини всередині кристала) призводить до одного з чотирьох вироджених станів:
1. За адресою A_x жодна комірка не стає доступною (обрив адреси);
2. Фізична комірка C_x не адресується жодною адресою шини;
3. За адресою A_x одночасно вибираються декілька фізичних комірок C_x, C_y (множинний вибір рядка або стовпця);
4. Фізична комірка C_x обирається за кількома різними адресами A_x, A_y (колізія дублювання або накладання адресного простору).

```
Порушення бієкції адресації:
  Address(A_x) -> {C_x, C_y}    [колізія множинного вибору]
  Address(A_x) = Address(A_y)   [колізія дублювання адрес]
```

### 4. Дефекти зв'язаності комірок (Coupling Faults — CF)

Зміна стану або операція над коміркою-агресором (Aggressor, адреса j) несанкціоновано змінює стан комірки-жертви (Victim, адреса i), де i ≠ j. Фізичною причиною є ємнісні та індуктивні наведення між паралельними лініями розрядів (Bitlines) або підкладковий витік заряду між близько розташованими транзисторами сусідніх комірок матриці.

* **Інверсійний взаємний вплив (Inversion Coupling Fault — CFin):** перехід 0 -> 1 або 1 -> 0 в комірці j інвертує біт у комірці i.
```
CFin<0->1; inv>:  s_j : 0 -> 1  викликає  s_i <- NOT(s_i)
CFin<1->0; inv>:  s_j : 1 -> 0  викликає  s_i <- NOT(s_i)
```

* **Ідемпотентний взаємний вплив (Idempotent Coupling Fault — CFid):** перехід в агресорі примусово встановлює фіксоване значення у жертві незалежно від її попереднього стану.
```
CFid<0->1; 0>:  s_j : 0 -> 1  викликає  s_i <- 0
CFid<0->1; 1>:  s_j : 0 -> 1  викликає  s_i <- 1
CFid<1->0; 0>:  s_j : 1 -> 0  викликає  s_i <- 0
CFid<1->0; 1>:  s_j : 1 -> 0  викликає  s_i <- 1
```

* **Статичний взаємний вплив (State Coupling Fault — CFst):** наявність певного постійного логічного стану в агресорі примушує жертву утримувати фіксований рівень.
```
CFst<0; 1>:  s_j = 0  примушує  s_i <- 1
CFst<1; 0>:  s_j = 1  примушує  s_i <- 0
```

### 5. Чутливість до шаблону оточення (Neighborhood Pattern Sensitive Faults — NPSF)

Складніший клас дефектів, коли стан комірки змінюється не від одного агресора, а лише за певної комбінації логічних станів дев'яти навколишніх комірок (активний та пасивний масив 3х3 у фізичній топології пам'яті). Алгоритми сімейства March C- виявляють значну частину таких патернів завдяки чергуванню проходів інверсії.

## Формальна мова запису March-тестів

Тест масиву записується як упорядкована послідовність маршових елементів M_k. Кожен елемент визначає напрямок сканування адресного простору та послідовність атомарних операцій над кожною поточною адресою:

```
Синтаксис маршового елемента:
  ⇑   [висхідне сканування: адреси строго зростають від 0 до N - 1]
  ⇓   [низхідне сканування: адреси строго спадають від N - 1 до 0]
  ⇕   [довільний напрямок сканування: порядок адрес не має значення]
  w0  [запис логічного 0 у поточну комірку]
  w1  [запис логічної 1 у поточну комірку]
  r0  [зчитування комірки та верифікація очікуваного 0]
  r1  [зчитування комірки та верифікація очікуваної 1]
```

## Алгоритм March X (складність 6N операцій)

March X — це базовий чотирифазний тест, призначений для швидкої перевірки базових дефектів без надлишкових перехресних прогонів.

```
Структура тесту March X:
  M0: ⇕ (w0)
  M1: ⇑ (r0, w1)
  M2: ⇓ (r1, w0)
  M3: ⇕ (r0)
```

### Покроковий аналіз покриття March X

```
Крок M0 [⇕ w0]:
  Операцій = N
  Дія      = ініціалізація всього масиву нулями

Крок M1 [⇑ (r0, w1)]:
  Операцій = 2N
  Дія      = зчитуємо 0 (ловить SAF1 і попередні помилки ініціалізації);
             записуємо 1 (ініціює перехід 0->1, ловить TF 0->1);
             сенсибілізує CF від молодших адрес до старших.

Крок M2 [⇓ (r1, w0)]:
  Операцій = 2N
  Дія      = зчитуємо 1 (ловить SAF0 та нездійснені переходи 0->1 з M1);
             записуємо 0 (ініціює перехід 1->0, ловить TF 1->0);
             сенсибілізує CF від старших адрес до молодших.

Крок M3 [⇕ r0]:
  Операцій = N
  Дія      = фінальна верифікація повернення масиву в стан 0;
             ловить нездійснені переходи 1->0 з кроку M2.

Загальна кількість операцій доступу до пам'яті:
  Total_Ops(March_X) = N + 2N + 2N + N = 6N
```

**Обмеження March X:** Алгоритм March X гарантовано виявляє SAF, TF, незв'язані CFin та дефекти адресації AF, проте не здатен повністю локалізувати зв'язані ідемпотентні дефекти (CFid), якщо стан агресора відновлюється до моменту зчитування жертви. Якщо комірка j змінила стан комірки i, але наступний крок циклу перезаписав комірку i правильним значенням до її перевірки, дефект залишається замаскованим.

## Алгоритм March C- (складність 10N операцій)

Алгоритм March C- є «золотим стандартом» вимог IEC 60730 Annex H та IEC 61508 для оперативної пам'яті мікроконтролерів класу надійності Class B / SIL 2. Він складається з шести маршових фаз.

```
Структура тесту March C-:
  M0: ⇕ (w0)
  M1: ⇑ (r0, w1)
  M2: ⇑ (r1, w0)
  M3: ⇓ (r0, w1)
  M4: ⇓ (r1, w0)
  M5: ⇕ (r0)
```

### Детальна схема доведення повноти покриття March C-

Доведення повноти спирається на умови ван де Гоора (A.J. van de Goor), які формулюють необхідні та достатні умови для виявлення всіх простих та зв'язаних дефектів пам'яті.

```
Фаза M0: ⇕ (w0)
  Вхідний стан: довільний
  Операція    : запис 0 для всіх i від 0 до N-1
  Результат   : S = (0, 0, 0, ..., 0)

Фаза M1: ⇑ (r0, w1)  [Висхідний прохід]
  Для i від 0 до N-1:
    1. Читання: r0 на комірці i.
       Якщо s_i = 1 -> виявлено SAF1 або помилку адресації AF.
    2. Запис: w1 на комірці i (генерує фронт 0 -> 1).
       Сенсибілізує дефекти CFin/CFid для всіх сусідніх комірок j > i.
  Результат фази: S = (1, 1, 1, ..., 1)

Фаза M2: ⇑ (r1, w0)  [Висхідний прохід інверсії]
  Для i від 0 до N-1:
    1. Читання: r1 на комірці i.
       Якщо s_i = 0 -> виявлено дефект TF(0->1), SAF0 або CFid від комірок j < i.
    2. Запис: w0 на комірці i (генерує фронт 1 -> 0).
       Сенсибілізує дефекти низхідного переходу для комірок j > i.
  Результат фази: S = (0, 0, 0, ..., 0)

Фаза M3: ⇓ (r0, w1)  [Низхідний прохід]
  Для i від N-1 до 0:
    1. Читання: r0 на комірці i.
       Якщо s_i = 1 -> виявлено вплив переходу 1->0 сусідніх комірок або дефект AF.
    2. Запис: w1 на комірці i (генерує фронт 0 -> 1 у зворотній адресації).
       Сенсибілізує дефекти для комірок j < i.
  Результат фази: S = (1, 1, 1, ..., 1)

Фаза M4: ⇓ (r1, w0)  [Низхідний прохід інверсії]
  Для i від N-1 до 0:
    1. Читання: r1 на комірці i.
       Якщо s_i = 0 -> виявлено TF(0->1) у зворотному напрямку або CFid від j > i.
    2. Запис: w0 на комірці i.
       Сенсибілізує дефекти для j < i.
  Результат фази: S = (0, 0, 0, ..., 0)

Фаза M5: ⇕ (r0)  [Фінальне зчитування]
  Для i від 0 до N-1:
    1. Читання: r0 на комірці i.
       Якщо s_i = 1 -> виявлено TF(1->0) на фазі M4 або нерозкритий CFst.
```

### Доведення виявлення дефектів адресації (AF Proof)

Припустимо наявність дефекту дешифратора, коли адреса A_x помилково відображається на комірку C_y (де y > x), а адреса A_y вибирає ту саму комірку C_y.
1. На фазі M1 під час висхідного руху за адресою A_x у комірку C_y записується одиниця (w1);
2. Коли сканування доходить до адреси A_y, операція читання r0 зчитує комірку C_y і виявляє значення 1 замість очікуваного 0;
3. Помилка дешифрації виявляється на фазі M1.

Якщо ж дефект має зворотний напрямок (адреса A_y відображається на комірку C_x, де y > x):
1. На фазі M1 запис за адресою A_y затре значення в C_x одиницею;
2. На фазі M2 читання r1 за адресою A_x прочитає 1, але запише 0;
3. Під час подальшого просування на фазі M2 читання r1 за адресою A_y прочитає комірку C_x, де вже лежить 0, і миттєво зафіксує збій.

Таким чином, парні висхідні (⇑) та низхідні (⇓) фази гарантують математичну симетрію перевірки, виключаючи сліпі зони дешифрації.

### Математичний підрахунок кількості операцій March C-

```
  M0 (w0)         = 1N операцій
  M1 (r0, w1)     = 2N операцій
  M2 (r1, w0)     = 2N операцій
  M3 (r0, w1)     = 2N операцій
  M4 (r1, w0)     = 2N операцій
  M5 (r0)         = 1N операцій
  -------------------------------------------------------------
  Загалом доступу = 1N + 2N + 2N + 2N + 2N + 1N = 10N операцій
```

## Вплив фізичної топології та чергування бітів (Bit-Striping)

У сучасних мікроконтролерах логічна адреса слова (32-бітного) не відповідає суміжним фізичним транзисторам на кремнії. Для оптимізації площі кристала застосовують мультиплексування стовпців (*Column Multiplexing* або *Bit-Striping*): біт 0 слова знаходиться у стовпці 0, біт 1 — у стовпці 4, біт 2 — у стовпці 8 тощо.

Сусідами по кремнію для біта 0 слова K є біт 0 слів K-1 та K+1 або біти інших слів. Алгоритм March C- виконується над повними словами (`uint32_t`), тому наведена математична модель 10N операцій автоматично масштабується на всі 32 розряди паралельно:
* Операція `w0` записує `0x00000000`;
* Операція `w1` записує `0xFFFFFFFF`;
* Операція `r0` перевіряє `word == 0x00000000`;
* Операція `r1` перевіряє `word == 0xFFFFFFFF`.

Це забезпечує одночасну перевірку всіх паралельних ліній даних шини і гарантує виявлення мікрокоротких замикань між сусідніми розрядними провідниками шини даних без збільшення кількості тактів процесора.

## Порівняльний аналіз дефектного покриття

| Клас несправності пам'яті | Наївний шаблон (0x55 / 0xAA) | March X (6N) | March C- (10N) |
| :--- | :--- | :--- | :--- |
| **SAF** (Stuck-At Fault) | 100% | 100% | 100% |
| **TF** (Transition Fault) | 0% (немає перевірки після зміни) | 100% | 100% |
| **AF** (Address Decoder Fault) | Частково (~20–30%) | 100% | 100% |
| **CFin** (Inversion Coupling) | 0% (маскується) | 100% (незв'язані) | 100% (усі) |
| **CFid** (Idempotent Coupling) | 0% | Частково (~50%) | 100% |
| **Складність алгоритму** | **2N ... 4N** | **6N** | **10N** |

З таблиці чітко видно, чому стандарти безпеки забороняють спрощені методи запису констант у пам'ять: наївний запис 0x55555555 та 0xAAAAAAAA перевіряє виключно цілісність шини даних і прості залипання бітів комірки (SAF), повністю ігноруючи перехресні дефекти адресації та динамічні наведення між сусідніми транзисторами матриці SRAM.
