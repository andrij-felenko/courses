# Системний інтерфейс перемикання контексту планувальника

Інтерфейс перемикання контексту (англ. *context switch*) є ядром операційної системи реального часу або диспетчера розподілу часу. Він забезпечує збереження поточного обчислювального стану одного процесу (значень робочих регістрів процесора, покажчика стека, регістра прапорців та лічильника команд) і відновлення збереженого стану іншого процесу. Мета цього інтерфейсу — зробити операцію передачі фізичного процесора абсолютно прозорою для самої задачі: після відновлення задача продовжує виконання з тієї самої машинної інструкції, ніби переривання взагалі не відбувалося.

## Організація кадру контексту та блоку TCB

Контекст задачі утворює спеціалізована структура пам'яті — кадр збереження регістрів на вершині індивідуального стека задачі. Контрольний блок задачі (@@en|TCB@@) зберігає актуальний покажчик стека `sp`, пріоритет та виділений ліміт квантів часу:

```c
typedef struct {
    uint32_t r4_r11[8];  // Програмно збережені регістри архітектури
    uint32_t r0_r3[4];   // Апаратно збережені аргументи функцій
    uint32_t r12;        // Регістр тимчасових даних
    uint32_t lr;         // Регістр зв'язку (адреса повернення)
    uint32_t pc;         // Лічильник інструкцій (поточна точка виконання)
    uint32_t psr;        // Регістр стану процесора та прапорців
} context_frame_t;

typedef struct tcb {
    void *stack_ptr;            // Вершина стека із збереженим кадром контексту
    uint8_t priority;          // Рівень пріоритету задачі
    uint32_t time_slice_left;  // Залишок кванта часу в тіках
    struct tcb *next;          // Зв'язок у черзі готових задач
} tcb_t;
```

## Сценарії використання інтерфейсу

### 1. Добровільна передача керування (кооперативний виклик)
Задача викликає функцію добровільного завершення свого кванта часу, віддаючи процесор іншій готовій задачі:

```c
// Виклик кооперативного планування з коду задачі
void worker_task(void *param) {
    while (1) {
        process_batch_item();
        sched_yield(); // Добровільна передача залишку кванта
    }
}
```

### 2. Примусове витіснення за таймерним квантом (преемптивний виклик)
Обробник системного тіка зменшує залишок часу активної задачі. Коли квант вичерпано, генерується відкладене апаратне переривання зміни контексту:

```c
// Виклик з обробника апаратного переривання таймера
void SysTick_Handler(void) {
    sched_tick_handler();
}
```

## Довідка функцій інтерфейсу планувальника

### `void sched_init_stack(tcb_t *task, void *stack_top, void (*entry)(void *), void *arg)`
- **Призначення**: формує початковий кадр контексту на вершині виділеного стека нової задачі, імітуючи стан процесора після виклику переривання.
- **Параметри**:
  - `task` — покажчик на контрольний блок задачі (TCB).
  - `stack_top` — початкова адреса вершини стека (повинна бути вирівняна за межею 8 байтів).
  - `entry` — адреса точки входу функції задачі.
  - `arg` — покажчик на користувацькі аргументи, що передаються у перший регістр аргументів (`r0`).
- **Інваріанти**: регістр стану `psr` ініціалізується зі встановленим бітом режиму Thumb/виконання, інакше виникає апаратне виключення при першому вході.

### `void sched_yield(void)`
- **Призначення**: ініціює негайне витіснення поточної задачі на користь наступного процесу в черзі готовності.
- **Параметри**: відсутні.
- **Повертає**: функція повертає керування лише після того, як планувальник знову вибере цю задачу для виконання.

### `void sched_tick_handler(void)`
- **Призначення**: оновлює внутрішній лічильник системного часу та контролює вичерпання виділеного кванта поточної задачі.
- **Поведінка**: якщо лічильник `time_slice_left` досягає 0, планувальник скидає його у початкове значення і виставляє прапорець виклику низькопріоритетного обробника зміни контексту.

### `void sched_switch_context(tcb_t **current_tcb, tcb_t *next_tcb)`
- **Призначення**: низькорівнева асемблерна процедура збереження та завантаження блоку регістрів між двома задачами.
- **Параметри**:
  - `current_tcb` — подвійний покажчик на TCB активної задачі, куди записується оновлений `stack_ptr`.
  - `next_tcb` — покажчик на TCB задачі, з вершини стека якої вибираються збережені значення регістрів.
- **Безпека та обмеження**: виконується виключно за заблокованих переривань або в обробнику виключення найнижчого пріоритету (наприклад, PendSV) для виключення вкладеного пошкодження стека.
