# Математичний аналіз накладних витрат квантування часу

Розподіл процесорного часу між кількома задачами за допомогою квантування дозволяє досягти високої чутливості системи до зовнішніх подій, але вимагає регулярних витрат обчислювальних тактів ядра на службові операції. Кожне перемикання контексту супроводжується збереженням регістрів процесора, роботою алгоритму планувальника та відновленням стану нової задачі. Зменшення розміру кванта покращує час реакції, проте різко збільшує частку втраченої продуктивності.

## Модель втрати процесорного часу

Позначимо тактову частоту процесорного ядра через `f_cpu`. Нехай тривалість одного кванта часу становить `T_slice`, час виконання апаратного обробника таймерного переривання дорівнює `t_isr`, а час збереження й відновлення регістрів задачі при зміні контексту становить `t_ctx`.

Сумарний непродуктивний час `t_overhead` за один період квантування визначається як сума витрат на обробник таймера та перемикання контексту:

```
t_overhead = t_isr + t_ctx               [підсумовування компонентів службових витрат]
```

Ця величина показує абсолютну тривалість часу, коли ядро виконує виключно службові системні інструкції операційної системи.

Частку втраченої обчислювальної спроможності процесора `eta` знаходять через відношення службового часу до загальної тривалості кванта:

```
eta = t_overhead ÷ T_slice
    = (t_isr + t_ctx) ÷ T_slice          [підстановка складових накладного часу]
```

Отримане відношення демонструє гіперболічну залежність накладних витрат від тривалості кванта: при наближенні `T_slice` до тривалості `t_overhead` частка втрат прямує до одиниці, тобто процесор припиняє виконувати прикладний код і займається лише перемиканням задач.

Корисний коефіцієнт використання обчислювального ядра `U_useful` визначається залишком потужності після вирахування службових витрат:

```
U_useful = 1 - eta
         = 1 - (t_isr + t_ctx) ÷ T_slice [підстановка частки накладних витрат]
```

З формули видно, що для збереження високої ефективності (`U_useful ≥ 0.95`) тривалість кванта часу повинна перевищувати накладні витрати щонайменше у 20 разів.

## Розрахунок максимальної затримки відгуку

Розглянемо систему з кількістю готових задач `N`, що виконуються за карусельним алгоритмом розподілу часу (@@en|Round-Robin@@). У найгіршому випадку подія розблокування задачі настає одразу після того, як вона віддала свій квант часу.

Максимальний час очікування задачі `L_max` до наступного отримання процесора складається з тривалості корисних квантів усіх інших `N - 1` задач та накладних витрат на всі проміжні перемикання контексту:

```
L_max = (N - 1) × T_slice + N × t_ctx    [сумарний час кругового циклу Round-Robin]
```

Цей вираз формулює фундаментальний інженерний компроміс: зменшення `T_slice` пропорційно зменшує максимальну затримку відгуку `L_max`, але неминуче збільшує відносні втрати `eta`.

## Розрахунок на числовому прикладі

**Умова розрахунку**: 32-бітний мікроконтролер працює на тактовій частоті `f_cpu = 48` МГц. Обробник таймерного переривання займає `C_isr = 120` тактів процесора, а повне перемикання контексту задачі потребує `C_ctx = 360` тактів. Кількість активних задач у системі становить `N = 4`. Порівняємо накладні витрати та максимальну затримку відгуку для двох значень кванта: `T_slice1 = 10` мс та `T_slice2 = 100` мкс.

Обчислимо абсолютну тривалість службових операцій `t_isr` та `t_ctx` у секундах:

```
t_isr = 120 ÷ (48 × 10⁶)
      = 2.5 × 10⁻⁶ с
      = 2.5 мкс                         [тривалість обробника таймера]

t_ctx = 360 ÷ (48 × 10⁶)
      = 7.5 × 10⁻⁶ с
      = 7.5 мкс                         [тривалість збереження й завантаження TCB]

t_overhead = 2.5 + 7.5
           = 10.0 мкс                   [сумарні накладні витрати на одне перемикання]
```

Розрахуємо накладні витрати та затримку для кванта `T_slice1 = 10` мс (10000 мкс):

```
eta₁ = 10.0 ÷ 10000.0
     = 0.001                            [частка накладних витрат становить 0.1%]

L_max1 = (4 - 1) × 10.0 + 4 × 0.0075
       = 30.0 + 0.03
       = 30.03 мс                       [максимальна затримка реакції задачі]
```

Розрахуємо накладні витрати та затримку для кванта `T_slice2 = 100` мкс:

```
eta₂ = 10.0 ÷ 100.0
     = 0.10                             [частка накладних витрат зросла до 10.0%]

L_max2 = (4 - 1) × 0.100 + 4 × 0.0075
       = 0.300 + 0.030
       = 0.330 мс                       [максимальна затримка скоротилася до 330 мкс]
```

**Інженерний висновок**: Зменшення кванта в 100 разів покращило швидкість реакції системи з 30 мс до 330 мкс, проте втрати процесорної потужності зросли з невідчутних `0.1%` до критичних `10.0%`. Для вбудованих пристроїв загального призначення оптимальним компромісом є вибір кванта в межах від 1 до 10 мілісекунд (частота системного тіка від 100 Гц до 1000 Гц).
