# Граф станів та таблиця переходів

Формалізація логіки керуючого автомата спирається на апарат дискретної математики та теорії орієнтованих графів. Скінченний автомат описують математичним кортежем (лат. *manipulus* — зв'язка, набір елементів) із п'яти складових: множини внутрішніх станів `S`, вхідного алфавіту подій `Σ` (грец. @@el|sigma@@), функції переходів `δ` (грец. @@el|delta@@), початкового стану `s₀` та множини вихідних реакцій `Λ` (грец. @@el|lambda@@). Граф станів перетворює ці абстрактні множини на наочну топологічну схему, де кожен вузол відповідає елементу множини станів, а напрямлені дуги фіксують дозволені траєкторії зміни контексту.

## Алгебрична модель детермінованого автомата

Вбудовані системи вимагають строгої детермінованості: для кожного стану системи та будь-якої вхідної події повинен існувати рівно один однозначний наступний стан. Математично функція переходів детермінованого автомата (@@en|deterministic finite automaton@@) задається як відображення декартового добутку множини станів і множини вхідних сигналів у множину станів:

```
δ: S × Σ → S
```

Якщо множина станів налічує `|S| = n` елементів, а множина вхідних подій містить `|Σ| = m` сигналів, простір можливих комбінацій системи описується матрицею переходів розмірністю `n × m`. Елемент матриці на перетині рядка поточного стану `sᵢ` та стовпця вхідної події `eⱼ` визначає цільовий стан `sₖ`.

Перевірка коректності автомата вимагає виконання двох фундаментальних критеріїв: повноти та детермінованості. Повнота означає, що для кожної пари `(s, e)` визначено реакцію, навіть якщо вона полягає в явному збереженні поточного стану (петля переходу). Детермінованість вимагає відсутності неоднозначностей: якщо перехід зі стану залежить від логічних предикатів (умов) `C₁` та `C₂`, ці умови не повинні перетинатися в часі.

Обчислимо перетин умов двох потенційних переходів за таймером утримання кнопки для перевірки детермінізму:

```
C_перетин
= C₁ ∧ C₂                [визначення одночасності спрацьовування]
= (t ≥ T_HOLD) ∧ (t < T_HOLD) [підстановка предикатів переходів]
= 0                      [закон несуперечності булевої алгебри]
```

Отриманий нульовий результат доводить, що переходи взаємно виключають один одного, тому автомат ні за яких обставин не отримає двох конкуруючих цільових станів на одному кроці дискретного часу.

## Матриця суміжності та досяжність станів

Топологічні властивості автомата досліджують за допомогою матриці суміжності графа станів. Нехай автомат має `n` станів. Матриця суміжності `A` розмірності `n × n` формується за правилом: елемент `A[i][j] = 1`, якщо існує хоча б одна подія, яка переводить систему зі стану `sᵢ` у стан `sⱼ`, та `A[i][j] = 0` за відсутності прямого переходу.

Діагностика структури графа виконується алгебричним аналізом рядків та стовпців матриці:

1. **Тупиковий стан (deadlock):** якщо для рядка `i` сума всіх елементів дорівнює нулю (`∑ⱼ A[i][j] = 0`), зі стану `sᵢ` немає жодного виходу. Для циклічної прошивки це свідчить про зависання логіки.
2. **Недосяжний стан (unreachable state):** якщо для стовпця `j` (де `j ≠ 0`) сума всіх елементів дорівнює нулю (`∑ᵢ A[i][j] = 0`), у стан `sⱼ` не веде жодна траєкторія, тобто відповідний код у пам'яті мікроконтролера є мертвим.

Кількість можливих шляхів довжиною `k` кроків між будь-якою парою станів визначається піднесенням матриці суміжності до степеня `k`. Матриця повної досяжності `R` обчислюється підсумовуванням степенів матриці суміжності від нульового до `(n - 1)`:

```
R
= I + A + A² + ... + Aⁿ⁻¹ [матричний ряд досяжності за n-1 кроків]
```

де `I` — одинична матриця розміру `n × n`. Якщо в матриці `R` рядок початкового стану `s₀` містить нульовий елемент у стовпці `k`, це строге математичне свідчення, що стан `sₖ` недосяжний із початкового конфігурування за будь-якої послідовності подій.

## Табличне представлення в пам'яті програм

У вбудованих системах граф переходів відображається у пам'ять мікроконтролера у формі двовимірного масиву або списку суміжності. Якщо матриця переходів щільна (більшість подій викликають переходи), таблиця переходів розміщується у флеш-пам'яті (Flash ROM) як константний масив:

| Поточний стан `S` | Подія `EV_PRESS` | Подія `EV_TIMEOUT` | Подія `EV_RELEASE` |
| :--- | :--- | :--- | :--- |
| `STATE_IDLE` | `STATE_DEBOUNCE` | `STATE_IDLE` | `STATE_IDLE` |
| `STATE_DEBOUNCE`| `STATE_DEBOUNCE` | `STATE_PRESSED` | `STATE_IDLE` |
| `STATE_PRESSED` | `STATE_HOLD` | `STATE_PRESSED` | `STATE_RELEASED` |
| `STATE_HOLD` | `STATE_HOLD` | `STATE_HOLD` | `STATE_RELEASED` |
| `STATE_RELEASED`| `STATE_IDLE` | `STATE_IDLE` | `STATE_IDLE` |

Пряма індексація за формулою `nextState = transitionTable[currentState][event]` забезпечує константну часову складність `O(1)` для кроку автомата, що критично для обробників переривань та високошвидкісних протокольних стеків.
