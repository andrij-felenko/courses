# Математика дрейфу кварца та розрахунок плавного підлаштування часу

Будь-який кварцовий резонатор у складі мікроконтролера має фізичну похибку номінальної частоти. Відхилення спричиняється технологічним розкидом виготовлення пластини кварцу, старінням кристала та залежністю коливань від температури навколишнього середовища. Математичний опис цього дрейфу (@@en|clock drift@@) дозволяє точно розрахувати темп накопичення фазової помилки та налаштувати контур плавного зведення часу (@@en|clock slewing@@) без порушення монотонності системної шкали.

## Температурна модель та накопичення похибки

Відносна нестабільність частоти кварцового резонатора вимірюється в мільйонних частках (@@en|parts per million, PPM@@). Для стандартного годинникового кварцу з номінальною частотою 32.768 кГц залежність частоти від температури описується параболічною функцією:

```
Δf / f₀ = -B × (T - T₀)²
```

де `B` — параболічний температурний коефіцієнт (зазвичай `0.035` @@en|PPM@@/°C² для кварцу зрізу XY), `T₀` — точка перегину кривої (кімнатна температура `+25` °C), а `T` — поточна робоча температура кристала.

Якщо температура приладу становить `+60` °C, температурне відхилення частоти обчислюється так:

```
Δf / f₀
= -0.035 × (60 - 25)²    [підстановка робочої температури]
= -0.035 × 35²           [різниця від точки перегину]
= -0.035 × 1225          [піднесення до квадрата]
= -42.875                [відносне відхилення у PPM]
```

Значення `-42.875` @@en|PPM@@ означає, що за кожну секунду фізичного часу внутрішній лічильник недораховує `42.875` мікросекунди. Загальна фазова похибка часу `ΔT` за інтервал спостереження `t` є інтегралом відносного зсуву частоти:

```
ΔT(t)
= ∫₀ᵗ (Δf(τ) / f₀) dτ    [інтегральне накопичення фазового зсуву]
= (Δf / f₀) × t          [для квазістатичної температури]
```

За інтервал у 24 години (`t = 86400` с) накопичене відставання годинника становить:

```
ΔT_доба
= -42.875 × 10⁻⁶ × 86400 [перемноження відносного зсуву на добу]
= -3.7044 с              [накопичений добовий зсув шкали]
```

За місяць автономної роботи без корекції годинник відстане майже на дві хвилини.

## Математика плавного зведення часу (slewing)

Коли зовнішній еталон (@@en|GNSS@@ або сервер @@en|NTP@@) надає точну мітку епохи `T_ref`, у системі виникає миттєва фазова розбіжність `e = T_ref - T_wall`. Ступенева зміна `T_wall` неприпустима, оскільки при поспішанні годинника це призведе до від'ємного кроку часу `dt < 0`.

Алгоритм @@en|slewing@@ вводить до монотонного лічильника лінійну поправку швидкості `R_adj` (швидкість підлаштування). Реальний календарний час на поточному кроці обчислюється за формулою:

```
T_wall(t) = T_uptime(t) + T_offset(t)
```

де `T_offset(t)` — динамічний зсув, перша похідна якого дорівнює коефіцієнту корекції:

```
d(T_offset) / dt = R_adj
```

Для виключення дестабілізації підсистем мікроконтролера швидкість підлаштування жорстко лімітується допустимим діапазоном `[-R_max, +R_max]`. Стандартний максимум у вбудованих операційних системах складає `R_max = 500` @@en|PPM@@ (`0.0005`).

Розрахунок тривалості плавного зведення часу `t_conv` за умови постійного ліміту швидкості визначається діленням фазової похибки на максимальну швидкість компенсації:

```
t_conv
= |e| / R_max            [час компенсації при насиченні регулятора]
```

Розрахуємо тривалість усунення похибки `e = 250` мілісекунд при максимальному зсуві швидкості `500` @@en|PPM@@:

```
t_conv
= 0.250 с / 0.0005       [ділення похибки на граничну швидкість]
= 500 с                  [тривалість фазового зведення]
```

За 500 секунд (8.3 хвилини) шкала часу приладу повністю та неперервно збігається з еталоном. Похідна відліку `dT_wall / dt` весь цей час залишається строго додатною:

```
dT_wall / dt
= 1 + R_adj              [похідна ходу коригованого часу]
= 1 - 0.0005             [у разі сповільнення поспішаючого годинника]
= 0.9995 > 0             [строга монотонність збережена]
```

Це доводить, що час у системі ніколи не повертає назад, унеможливлюючи деградацію часових рядів та збої планувальника завдань.
