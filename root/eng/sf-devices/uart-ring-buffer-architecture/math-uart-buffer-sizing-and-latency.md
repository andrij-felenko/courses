# Математичний розрахунок обсягу буфера UART та аналіз затримок

Асинхронний послідовний інтерфейс UART передає символи з постійною швидкістю, визначеною бітрейтом передавача. Якщо програма мікроконтролера виконує обчислювально містку операцію, запис спалах-пам'яті або обслуговує вище за пріоритетом переривання, зчитування чергового байта з апаратного регістра затримується. Для запобігання втраті даних через апаратне переповнення (@@en|overrun error@@) вхідний потік спрямовують у кільцевий буфер. Задача розробника — математично обґрунтувати мінімальний розмір цього буфера під найгірший сценарій системної затримки.

## Розрахунок інтервалу передачі байта

Позначимо швидкість передачі інтерфейсу через `B` (виражену в бітах за секунду, або бодах). У стандартному режимі передачі `8N1` кожен корисний байт обрамляється одним стартовим та одним стоповим бітами, утворюючи фрейм загальною довжиною `N_frame = 10` бітів.

Тривалість прийому одного байта `t_byte` виражається через відношення кількості бітів фрейму до швидкості передачі:

```
t_byte = N_frame ÷ B
       = 10 ÷ B                          [тривалість надходження одного фрейму UART]
```

Отримана величина визначає мінімальний часовий інтервал між послідовними апаратними перериваннями прийому байта.

## Визначення мінімального обсягу буфера під затримку споживача

Нехай максимальний час блокування або найгірша затримка реакції основного потоку обробки становить `T_delay_max` (у секундах). Цей час включає роботу монолітних функцій, критичних секцій із замаскованими перериваннями та накладні витрати планувальника.

Мінімальна кількість байтів `N_min`, яку буфер повинен гарантовано вмістити за час блокування споживача, визначається формулою:

```
N_min = ⌈T_delay_max ÷ t_byte⌉
      = ⌈(T_delay_max × B) ÷ 10⌉        [розрахунок мінімальної місткості буфера]
```

Оператор округлення до більшого цілого `⌈...⌉` гарантує, що навіть частково прийнятий байт не спричинить переповнення черги.

Оскільки для ефективної індексації розмір кільцевого буфера обирають як степінь двійки (`SIZE = 2ᵏ`), фінальний інженерний обсяг буфера `SIZE_buf` визначається піднесенням двійки до найближчого достатнього степеня:

```
k = ⌈log₂(N_min + 1)⌉
SIZE_buf = 2ᵏ                            [вибір обсягу у вигляді степеня двійки]
```

Додавання одиниці `+ 1` враховує класичний інваріант кільцевого буфера, де один слот залишається порожнім для розрізнення станів повної заповненості та порожнечі за індексами `head` та `tail`.

## Розрахунок на числовому прикладі

**Умова розрахунку**: Модуль бездротового зв'язку передає потік телеметрії через UART на швидкості `B = 115200` біт/с. Прошивка мікроконтролера періодично виконує секторне стирання блоку спалах-пам'яті, під час якого ядро зайняте активним очікуванням апаратного прапорця протягом `T_delay_max = 12` мілісекунд (`0.012` с).

Розрахуємо тривалість передачі одного байта `t_byte`:

```
t_byte = 10 ÷ 115200
       ≈ 8.6806 × 10⁻⁵ с
       ≈ 86.81 мкс                       [час надходження одного байта]
```

Обчислимо кількість байтів, що надійде від передавача за час очікування пам'яті:

```
N_min = ⌈0.012 ÷ (8.6806 × 10⁻⁵)⌉
      = ⌈138.24⌉
      = 139                              [мінімальна кількість накопичених байтів]
```

Визначимо оптимальний інженерний розмір кільцевого буфера:

```
N_req = 139 + 1
      = 140                              [з урахуванням службового слота інваріанта]

k = ⌈log₂(140)⌉
  = ⌈7.129⌉
  = 8                                    [показник степеня двійки]

SIZE_buf = 2⁸
         = 256 байтів                    [фінальний виділений розмір буфера]
```

**Інженерний висновок**: Буфер розміром 128 байтів був би недостатнім і призвів би до втрати щонайменше 11 байтів при кожній операції роботи з пам'яттю (`139 - 128 = 11`). Виділення буфера на 256 байтів повністю поглинає часовий сплеск і забезпечує 83% запас надійності під час непередбачених затримок процесора.
