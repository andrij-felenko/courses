# Індексація кільцевого буфера та розрахунок латентності

Організація черги вводу для високошвидкісного інтерфейсу UART спирається на апаратну та алгоритмічну оптимізацію індексних розрахунків. Класична операція взяття остачі від ділення (@@en|modulo operator@@) на багатьох мікроконтролерних ядрах вимагає виконання інструкції ділення, що збільшує час перебування в обробнику переривання. Застосування ступеня двійки для ємності буфера замінює арифметичне ділення побітовою маскою та дозволяє аналітично розрахувати граничний допустимий час реакції фонового коду без втрати даних.

## Арифметика побітової маски замість ділення

Нехай розмір масиву кільцевого буфера становить `C = 2ᵏ` елементів, де `k` — натуральне число. У класичній кільцевій черзі наступне положення вказівника запису чи читання визначається циклічним нарощенням:

```
next = (current + 1) mod C
```

Якщо `C` є степенем двійки, двійковий запис числа `C` являє собою одиницю з `k` нулями: `10...0₂`. Відповідно, величина `M = C - 1` містить рівно `k` одиниць у молодших розрядах: `01...1₂`. Для будь-якого цілого числа `x` результат взяття за модулем `2ᵏ` збігається з побітовим кон'юнктивним множенням:

```
x mod 2ᵏ = x & (2ᵏ - 1)
```

Перевіримо перехід індексу через межу масиву розміром `C = 16` (`k = 4`, `M = 15 = 1111₂`) при `current = 15`:

```
next
= (15 + 1) & 15          [підстановка значень у побітову формулу]
= 16 & 15                [додавання одиниці]
= 10000₂ & 01111₂        [побітове представлення]
= 00000₂ = 0             [скидання індексу на початок буфера]
```

На 32-бітних ядрах Cortex-M0/M3/M4 апаратне ділення (`UDIV`) виконується за 2–12 тактів процесора або реалізується програмно в бібліотеці часу виконання. Натомість побітова операція `AND` займає рівно 1 такт і часто об'єднується з командою завантаження зі зсувом, що усуває накладні витрати в обробнику `USART_RX_IRQHandler`.

## Розрахунок заповненості та вільного простору

В однопотоковій черзі з одним виробником і одним споживачем (@@en|single-producer single-consumer, SPSC@@) стан повноти відрізняють від стану порожнечі резервуванням однієї невикористаної комірки (`N_max = C - 1`). Кількість байтів, які очікують на вичитування `L`, обчислюється через різницю вказівників `head` та `tail`:

```
L = (head - tail) & M
```

Розрахуємо заповненість буфера ємністю `C = 64` (`M = 63`) для випадку, коли вказівник запису зробив кільцевий оберт (`head = 5`), а споживач ще обробляє хвіст (`tail = 58`):

```
L
= (5 - 58) & 63          [різниця індексів із від'ємним проміжним результатом]
= (-53) & 63             [доповняльний код: -53 ≡ 11...11001011₂]
= 203₂ & 00111111₂       [накладання 6-бітної маски]
= 11₂ = 11               [фактично в буфері знаходиться 11 байтів]
```

Доповняльний код цілих чисел автоматично нівелює знак від'ємної різниці при накладанні маски.

## Гранична латентність фонового потоку (WCET)

Критичним параметром надійності прошивки є граничний час реакції фонового циклу (@@en|worst-case execution time, WCET@@), протягом якого буфер не переповниться при безперервному потоці символів.

Швидкість надходження байтів `R_byte` при стандартному форматі кадру UART (1 старт-біт, 8 бітів даних, 1 стоп-біт — разом 10 бітів) становить `Baud / 10`. Час надходження одного байта дорівнює:

```
T_byte = 10 / Baud
```

Максимальний час затримки споживача `T_wcet` до виникнення переповнення при робочій місткості `N_max` обчислюється так:

```
T_wcet = N_max × T_byte
```

Розрахуємо граничну затримку для швидкості `115200` бод при ємності буфера `C = 256` байтів (`N_max = 255`):

```
T_byte
= 10 / 115200            [тривалість 10 бітових інтервалів]
≈ 86.8 × 10⁻⁶ с          [86.8 мікросекунди на байт]
```

```
T_wcet
= 255 × 86.8 × 10⁻⁶ с    [множення корисної ємності на час байта]
≈ 0.02213 с              [гранична латентність 22.13 мілісекунди]
```

Якщо виконання блокуючої функції у фоновому циклі перевищить 22.13 мс, апаратне FIFO приймача переповниться, і дані будуть безповоротно втрачені. Для швидкості `921600` бод допустимий час реакції для того ж буфера скорочується до:

```
T_wcet
= 255 × (10 / 921600)    [розрахунок для швидкості 921600 бод]
= 255 × 1.085 × 10⁻⁵ с   [час передачі байта 10.85 мкс]
≈ 0.00277 с              [гранична латентність 2.77 мілісекунди]
```

Ці розрахунки диктують інженеру мінімальний розмір оперативної пам'яті під буфер з огляду на тривалість найдовшої неподільної операції в системі.
