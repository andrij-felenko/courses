# Контракт портування LVGL: HAL дисплея та пристроїв введення

Графічна бібліотека LVGL розроблена за принципом суворої ізоляції ядра рендерингу від фізичної апаратури. Взаємодія з контролерами дисплеїв, шинами передачі даних (SPI, QSPI, I8080, FMC, RGB LTDC) та сенсорними панелями здійснюється через фіксований набір структур і зворотних викликів (Hardware Abstraction Layer).

Уся апаратна специфіка — адреси регістрів, полярність сигналів, конфігурація контролера DMA та таймінги шини — інкапсулюється всередині користувацьких функцій зворотного виклику. Графічне ядро оперує виключно абстрактними прямокутними областями пам'яті та координатами.

## 1. Рівень драйвера дисплея (Display HAL)

Драйвер дисплея відповідає за надання буферів пам'яті для рендерингу, передачу готових піксельних масивів у фізичний контролер та узгодження геометрії екрана.

### Специфікація та інваріанти функцій зворотного виклику

Кожна функція зворотного виклику в структурі `lv_disp_drv_t` виконує строго визначену системну роль:

1. **`flush_cb` (Обов'язковий зворотний виклик скидання буфера)**:
   - **Сигнатура**: `void (*)(lv_disp_drv_t *drv, const lv_area_t *area, lv_color_t *color_p)`.
   - **Контракт**: Функція повинна відправити масив пікселів `color_p`, що описує прямокутник `area`, у контролер екрана.
   - **Інваріант**: Після закінчення передачі (синхронно у блокуючому режимі або всередині обробника переривання DMA/ISR в асинхронному режимі) **обов'язково** має бути викликана функція `lv_disp_flush_ready(drv)`. Якщо цей виклик пропущено, графічний конвеєр назавжди зависне в очікуванні звільнення буфера.

2. **`rounder_cb` (Опційний зворотний виклик заокруглення координат)**:
   - **Сигнатура**: `void (*)(lv_disp_drv_t *drv, lv_area_t *area)`.
   - **Контракт**: Дозволяє модифікувати координати брудної області перед початком рендерингу. Це необхідно для контролерів, які не підтримують довільну попіксельну адресацію.
   - **Типові сценарії застосування**:
     - Монохромні дисплеї (наприклад, SSD1306 з вертикальною організацією сторінок по 8 пікселів): координати `y1` та `y2` мають округлюватися до меж байта (`y1 &= ~0x07; y2 |= 0x07`).
     - Дисплеї зі стисненням або парною адресацією (ST7789 у режимах 2-byte alignment): координати `x1` округлюються до парних значень, а `x2` — до непарних.
     - Апаратні декодери JPEG: округлення до блоків 8×8 або 16×16 пікселів.

3. **`set_px_cb` (Опційний зворотний виклик попіксельного запису)**:
   - **Сигнатура**: `void (*)(lv_disp_drv_t *drv, uint8_t *buf, lv_coord_t buf_w, lv_coord_t x, lv_coord_t y, lv_color_t color, lv_opa_t opa)`.
   - **Контракт**: Перевизначає стандартну процедуру запису пікселя у буфер рендерингу. Використовується для нестандартних форматів кольору (монохромний 1 біт на піксель, 2-бітний градаційний монохром, 4-бітний колір або панелі e-Paper).
   - **Механізм адресації**: Наприклад, для 1-бітного монохромного екрана SSD1306 піксель записується як маска біта:
     ```
     uint32_t byte_index = (y / 8) * buf_w + x;
     if (color.full) buf[byte_index] |= (1 << (y % 8));
     else buf[byte_index] &= ~(1 << (y % 8));
     ```

4. **`clean_dcache_cb` (Опційний зворотний виклик очищення кешу)**:
   - **Сигнатура**: `void (*)(lv_disp_drv_t *drv)`.
   - **Контракт**: Викликається ядром LVGL безпосередньо перед викликом `flush_cb`. Дозволяє централізовано виконати скидання кешу даних процесора (L1 D-Cache Clean) для адреси поточного активного буфера, щоб контролер DMA прочитав актуальні растрові дані з фізичного ОЗП.

### Керування декількома дисплеями (Multi-Display Support)

LVGL дозволяє підключати до одного мікроконтролера декілька фізичних екранів різного типу (наприклад, основний кольоровий TFT-дисплей через SPI та допоміжний монохромний OLED-екран по I2C):

- Кожен дисплей реєструється окремою структурою `lv_disp_drv_t` зі своїми індивідуальними буферами.
- Функція `lv_disp_drv_register()` повертає покажчик `lv_disp_t*`.
- Функція `lv_disp_set_default(disp)` встановлює екран за замовчуванням, на якому створюються нові вікна та віджети.
- Об'єкти на конкретному екрані створюються явним зазначенням кореневого екрана: `lv_obj_create(lv_disp_get_scr_act(disp2))`.

### Специфікація функції `read_cb`

Функція зворотного виклику `read_cb` періодично опитується рушієм (за замовчуванням кожні 30 мс).

- **Для типу `LV_INDEV_TYPE_POINTER` (тачскрін)**:
  - Якщо палець торкається екрана: `data->state = LV_INDEV_STATE_PRESSED`, а `data->point.x` та `data->point.y` заповнюються поточними координатами.
  - Якщо палець відпущено: `data->state = LV_INDEV_STATE_RELEASED`. Поля координат зберігають значення останньої точки дотику.
- **Для типу `LV_INDEV_TYPE_ENCODER`**:
  - Поле `data->enc_diff` отримує значення зміни кроків (наприклад, `+1` при повороті за годинниковою стрілкою або `-1` проти).
  - Поле `data->state` фіксує натискання центральної кнопки енкодера.
- **Прапорець `data->continue_reading`**:
  - Якщо сенсорний контролер підтримує буферизацію кількох послідовних точок жестів (FIFO), драйвер може виставити `data->continue_reading = true`. Рушій негайно викличе `read_cb` знову без очікування наступного 30-мс періоду, вичитуючи весь буфер до нуля.

## 3. Математика геометричних областей (`lv_area_t`)

Координатна система LVGL використовує замкнені інтервали: прямокутник описується структурою `lv_area_t`, де граничні пікселі `x1, y1, x2, y2` включені в площу об'єкта.

```
Ширина = area.x2 - area.x1 + 1
Висота = area.y2 - area.y1 + 1
Площа  = Ширина · Висота
```

### Основні математичні операції над областями

1. **`bool _lv_area_intersect(lv_area_t *res, const lv_area_t *a1, const lv_area_t *a2)`**:
   Обчислює прямокутник перетину двох областей. Якщо прямокутники не перетинаються, функція повертає `false`, а координати `res` залишаються невизначеними. Використовується на кожному кроці графічного конвеєра для відсікання невидимих об'єктів (Clipping).
2. **`void _lv_area_join(lv_area_t *res, const lv_area_t *a1, const lv_area_t *a2)`**:
   Будує мінімальний спільний обмежувальний прямокутник (bounding box), що одночасно накриває обидві області `a1` та `a2`. Використовується оптимізатором брудних прямокутників для об'єднання суміжних областей інвалідації.
3. **`bool _lv_area_is_in(const lv_area_t *ain, const lv_area_t *aholder, lv_coord_t radius)`**:
   Перевіряє, чи область `ain` повністю лежить усередині прямокутника `aholder` з урахуванням радіуса закруглення кутів.

## 4. Конфігураційні параметри ядра (`lv_conf.h`)

Файл `lv_conf.h` задає статичну конфігурацію графічної підсистеми під час компіляції:

| Макрос | Типове значення | Пояснення та системний вплив |
|---|---|---|
| `LV_COLOR_DEPTH` | `16` | Розрядність кольору внутрішнього конвеєра: `1` (монохром), `8` (RGB332), `16` (RGB565), `32` (ARGB8888). |
| `LV_COLOR_16_SWAP` | `0` або `1` | Апаратний байтовий реверс (Big-Endian) для 16-бітних SPI-дисплеїв. Дозволяє надсилати 16-бітний колір через 8-бітний SPI без побайтової перестановки в CPU. |
| `LV_MEM_CUSTOM` | `0` | Вибір менеджера динамічної пам'яті. При `0` використовується внутрішній статичний пул LVGL (`LV_MEM_SIZE`); при `1` виклики перенаправляються на `malloc`/`free` або `pvPortMalloc`. |
| `LV_MEM_SIZE` | `(32U * 1024U)` | Розмір виділеного пулу пам'яті для створення дерев віджетів, стилів, таймерів та анімацій. |
| `LV_DISP_DEF_REFR_PERIOD` | `30` | Базовий період оновлення екрана в мілісекундах (~33 FPS). Зменшення значення до `16` підвищує плавність анімацій до 60 FPS ціною збільшення навантаження на процесор. |
| `LV_INDEV_DEF_READ_PERIOD` | `30` | Період опитування зареєстрованих сенсорних контролерів у мілісекундах. |
| `LV_USE_GPU_STM32_DMA2D` | `1` | Активація апаратної підтримки графічного прискорювача Chrom-ART (DMA2D) для мікроконтролерів STM32. |
| `LV_DPI_DEF` | `130` | Кількість точок на дюйм (Dots Per Inch) за замовчуванням для розрахунку фізичних розмірів віджетів і шрифтів. |

## 5. Системний тік часу: контракт `lv_tick_inc`

Для розрахунку плавності анімацій, відліку періодів опитування та виявлення довгих натискань (Long-Press) рушій LVGL вимагає монотонного джерела часу:

- Системний таймер SysTick або таймерний хук FreeRTOS повинен періодично викликати функцію `lv_tick_inc(uint32_t tick_period)`.
- Типовий крок тіка становить 1 мілісекунду (`lv_tick_inc(1)`).
- Якщо `lv_tick_inc()` не викликається або блокується іншими перериваннями з вищим пріоритетом, анімації сповільнюються, а події жестів перестають розпізнаватися.
