# Математичний розрахунок затримок та місткості черги робіт

Черга робіт у системі реального часу діє як буфер між асинхронними подіями апаратного рівня та єдиним потоком-виконавцем. Якщо частота надходження подій перевищує швидкість їх обробки робочим потоком, черга неминуче переповнюється, що призводить до втрати подій або відхилення нових завдань. Для забезпечення стабільності системи інженер повинен математично обґрунтувати мінімальну місткість черги та оцінити максимальний час очікування завдання в черзі перед початком його виконання.

## Модель черги та коефіцієнт навантаження

Нехай середня частота надходження завдань у чергу становить `lambda` (подій за секунду), а середній час виконання одного завдання потоком робітника дорівнює `t_serv` (у секундах).

Швидкість обслуговування завдань `mu` визначається як зворотна величина до часу виконання:

```
mu = 1 ÷ t_serv                          [інтенсивність обслуговування завдань потоком]
```

Ця величина характеризує максимальну кількість робіт, яку потік здатен виконати за одну секунду за умови безперервної зайнятості.

Коефіцієнт завантаження системи `rho` визначається як добуток інтенсивності надходження на середній час обслуговування:

```
rho = lambda ÷ mu
    = lambda × t_serv                    [коефіцієнт завантаження черги робіт]
```

Отриманий коефіцієнт є фундаментальним критерієм стабільності системи:
- Якщо `rho < 1`, система є ергодичною та стабільною: середня довжина черги залишається скінченною.
- Якщо `rho ≥ 1`, черга необмежено зростає в часі, і жоден кінцевий буфер пам'яті не здатний запобігти переповненню.

## Оцінка середнього часу очікування та довжини черги

За теорією масового обслуговування середній час очікування роботи в черзі `W_wait` до початку її безпосереднього виконання виражається через час обслуговування та коефіцієнт завантаження:

```
W_wait = (rho × t_serv) ÷ (1 - rho)      [середній час перебування в черзі очікування]
```

З формули видно, що при наближенні завантаження ядра до 100% (`rho → 1`) час очікування асимптотично прямує до нескінченності.

Середня кількість завдань у черзі `L_q` визначається за формулою Літтла як добуток інтенсивності надходження на час очікування:

```
L_q = lambda × W_wait
    = (rho²) ÷ (1 - rho)                 [середня довжина черги очікування]
```

Цей вираз дозволяє оцінити математичне сподівання кількості зайнятих слотів пам'яті за стаціонарного режиму роботи.

## Розрахунок місткості при пакетному сплеску подій

В апаратурі події часто надходять не рівномірно, а пачками (пакетний сплеск або @@en|burst@@). Нехай за короткий інтервал часу `t_burst` у систему надходить `N_burst` запитів від датчиків або мережевих інтерфейсів.

Максимальна необхідна місткість черги `Q_req` для запобігання втраті подій визначається різницею між кількістю нових запитів та кількістю робіт, які потік встигає виконати за час сплеску:

```
N_processed = ⌊t_burst ÷ t_serv⌋         [кількість робіт, оброблених під час сплеску]
Q_req = N_burst - N_processed            [необхідний розмір буфера для утримання сплеску]
```

Якщо розмір черги менший за `Q_req`, система втрачає інформацію через переповнення.

## Розрахунок на числовому прикладі

**Умова розрахунку**: Датчик вібрації генерує в середньому `lambda = 250` подій на секунду. Обробка однієї події (зчитування по SPI та запис у кільцевий буфер) займає `t_serv = 2.0` мілісекунди (`0.002` с). Під час механічного удару виникає сплеск із `N_burst = 20` подій за часовий інтервал `t_burst = 10` мілісекунд (`0.01` с).

Розрахуємо коефіцієнт навантаження системи `rho`:

```
rho = 250 × 0.002
    = 0.50                               [завантаження потоку становить 50%]
```

Обчислимо середній час очікування `W_wait` та середню довжину черги `L_q`:

```
W_wait = (0.50 × 0.002) ÷ (1 - 0.50)
       = 0.001 ÷ 0.50
       = 0.002 с
       = 2.0 мс                          [середній час очікування в черзі]

L_q = (0.50²) ÷ (1 - 0.50)
    = 0.25 ÷ 0.50
    = 0.5                            [у середньому в черзі перебуває менше одного елемента]
```

Розрахуємо необхідну місткість буфера черги під час сплеску `N_burst = 20` за `t_burst = 10` мс:

```
N_processed = ⌊0.010 ÷ 0.002⌋
            = 5                          [робітник встигає виконати 5 завдань під час удару]

Q_req = 20 - 5
      = 15                               [необхідний буфер на 15 елементів]
```

**Інженерний висновок**: Хоча середнє стаціонарне навантаження становить лише 50%, місткість черги на 4 чи 8 елементів призвела б до гарантованої втрати даних під час удару. Для надійної роботи буфер черги повинен містити не менше 16 слотів (найближчий степінь двійки до `Q_req`), що забезпечує безаварійну роботу під час максимальних пікових навантажень.
