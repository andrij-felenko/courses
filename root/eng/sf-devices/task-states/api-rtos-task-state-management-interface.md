# Програмний інтерфейс керування станами задач у RTOS

У багатозадачних операційних системах реального часу (@@en|RTOS@@) прикладний код не взаємодіє з регістрами процесора та стеком напряму. Натомість ядро системи надає стандартизований прикладний програмний інтерфейс (англ. *Application Programming Interface*, або @@en|API@@) для контролю життєвого циклу задач: створення, переведення в стан очікування, примусового призупинення, відновлення та опитування поточного статусу. Цей інтерфейс абстрагує механізми перемикання контексту й гарантує збереження цілісності внутрішніх черг планувальника.

## Архітектурна будова та призначення викликів

Керування життєвим циклом задачі зосереджено навколо її дескриптора або маніпулятора (англ. *handle*) `TaskHandle_t`, який вказує на внутрішній контрольний блок задачі (@@en|TCB@@). Якщо функція приймає значення `NULL` замість дескриптора, дія застосовується до поточної задачі, що виконується в цей момент на фізичному ядрі.

Інтерфейс розділено на дві функціональні категорії:
1. **Виклики контексту задач**: функції, призначені для виконання виключно в потоках задач (наприклад, `vTaskDelay`, `vTaskSuspend`). Вони можуть переводити задачу в стан блокування й викликати планувальник.
2. **Виклики контексту переривань**: спеціалізовані функції з суфіксом `FromISR` (наприклад, `xTaskResumeFromISR`). Вони не можуть блокувати виконання і повертають прапорець потреби в негайному перемиканні контексту після завершення обробника апаратного переривання.

## Сценарії використання та приклади

### 1. Добровільне блокування на фіксований час
Задача звільняє процесорне ядро на період `xTicksToDelay` системних квантів часу, переходячи зі стану `eRunning` у стан `eBlocked`:

```c
// Переведення поточної задачі в стан блокування на 50 системних тіків
vTaskDelay(pdMS_TO_TICKS(50));
```

### 2. Призупинення та асинхронне відновлення з переривання
Захист критичної операції запису спалах-пам'яті від втручання фонової задачі з подальшим розблокуванням:

```c
// Призупинення фонової задачі обробки телеметрії
vTaskSuspend(xTelemetryTaskHandle);

// Відновлення задачі з обробника апаратного переривання кнопки
BaseType_t xYieldRequired = xTaskResumeFromISR(xTelemetryTaskHandle);
portYIELD_FROM_ISR(xYieldRequired);
```

## Довідка функцій та типів даних

### Перелік станів задачі (`eTaskState`)

| Значення константи | Стан задачі | Опис поведінки в планувальнику |
| :--- | :--- | :--- |
| `eRunning` | Виконання | Задача виконується процесором у поточний момент часу |
| `eReady` | Готовність | Задача готова до виконання і розміщена в черзі готових процесів |
| `eBlocked` | Очікування | Задача очікує подію або вичерпання таймауту; кванти не виділяються |
| `eSuspended` | Призупинення | Задача виключена з планування; відновлюється лише явним викликом |
| `eDeleted` | Знищена | Пам'ять TCB та стека очікує очищення системною задачею очищення |

### Системні виклики керування станами

#### `void vTaskDelay(const TickType_t xTicksToDelay)`
- **Призначення**: переводить поточну виконувану задачу у стан `eBlocked` на задану кількість системних квантів.
- **Параметри**: `xTicksToDelay` — тривалість затримки в системних тіках (конвертується макросом `pdMS_TO_TICKS`).
- **Повертає**: нічого.
- **Інваріанти**: викликається лише з контексту задачі; при передачі `0` викликає добровільний перерозподіл часу між готовими задачами однакового пріоритету (`taskYIELD`).

#### `void vTaskDelayUntil(TickType_t * const pxPreviousWakeTime, const TickType_t xTimeIncrement)`
- **Призначення**: забезпечує суворо періодичне виконання задачі без накопичення часового дрейфу, вираховуючи абсолютний момент наступного пробудження.
- **Параметри**: `pxPreviousWakeTime` — покажчик на змінну часу останнього пробудження; `xTimeIncrement` — бажаний період циклу.
- **Повертає**: нічого.

#### `void vTaskSuspend(TaskHandle_t xTaskToSuspend)`
- **Призначення**: примусово вилучає вказану задачу з усіх черг планувальника й переводить її в стан `eSuspended`.
- **Параметри**: `xTaskToSuspend` — дескриптор задачі або `NULL` для призупинення самої себе.
- **Повертає**: нічого.

#### `void vTaskResume(TaskHandle_t xTaskToResume)`
- **Призначення**: повертає призупинену задачу зі стану `eSuspended` у стан `eReady`.
- **Параметри**: `xTaskToResume` — дескриптор задачі (не може бути `NULL`).
- **Повертає**: нічого.
- **Інваріанти**: якщо задача не перебувала в стані `eSuspended`, виклик ігнорується без виникнення системної помилки.

#### `BaseType_t xTaskResumeFromISR(TaskHandle_t xTaskToResume)`
- **Призначення**: безпечне відновлення призупиненої задачі з контексту апаратного переривання.
- **Параметри**: `xTaskToResume` — дескриптор задачі.
- **Повертає**: `pdTRUE`, якщо пріоритет розблокованої задачі вищий за поточний виконуваний потік і потрібне перемикання контексту; інакше `pdFALSE`.

#### `eTaskState eTaskGetState(TaskHandle_t xTask)`
- **Призначення**: діагностичне опитування поточного стану задачі.
- **Параметри**: `xTask` — дескриптор цільової задачі.
- **Повертає**: значення переліку `eTaskState` (`eReady`, `eRunning`, `eBlocked`, `eSuspended`, `eDeleted`).
- **Коди помилок та безпека**: функція є атомарною щодо критичних секцій планувальника, але повернений стан може змінитися одразу після повернення, якщо на систему впливають апаратні переривання.
