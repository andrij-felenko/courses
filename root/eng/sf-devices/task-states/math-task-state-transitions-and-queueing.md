# Математична модель переходів станів та розрахунок черг планувальника

Функціонування планувальника операційної системи реального часу спирається на апарат теорії масового обслуговування (теорії черг) та марковських ланцюгів дискретних станів. Математичне моделювання переходів між станами задач дозволяє аналітично довести стійкість системи, розрахувати найгірший час відгуку на зовнішні переривання (@@en|worst-case response time, WCRT@@) та гарантувати відсутність зриву дедлайнів у критичних підсистемах.

## Модель станів та граф переходів

Життєвий цикл задачі описується орієнтованим графом переходів між чотирма взаємовиключними станами: `Running` (R), `Ready` (Q), `Blocked` (B) та `Suspended` (S). 

Множина дозволених переходів системи `T` містить строго фіксовані дуги:
```
T = {(R, Q), (Q, R), (R, B), (B, Q), (R, S), (Q, S), (B, S), (S, Q)}
```

Критичний інваріант полягає у відсутності прямого переходу `(B, R)`: подія розблокування (закінчення таймауту або поява семафора) переводить задачу виключно у чергу готовності `Q`. Тільки планувальник має математичне право перевести задачу зі стану `Q` у стан `R`.

## Найгірший час затримки реакції (Latency WCRT)

Для системи з витісненням за фіксованими пріоритетами найгірший час затримки реакції `L_max` для задачі з найвищим пріоритетом `Task_H` визначається тривалістю блокування планувальника:

```
L_max = t_crit + t_isr + t_ctx
```

де `t_crit` — найдовша критична секція в системі, під час якої переривання повністю вимкнені (`taskENTER_CRITICAL()`), `t_isr` — тривалість виконання коду обробника переривання, що пробуджує задачу, а `t_ctx` — час збереження та відновлення контексту регістрів процесора.

Розрахуємо максимальну латентність для процесора з тактовою частотою `160` МГц при параметрах:
- Максимальна тривалість критичної секції: `500` тактів;
- Час виконання ISR: `800` тактів;
- Час перемикання контексту: `300` тактів.

Обчислюємо період одного такту процесора `t_cycle`:

```
t_cycle
= 1 / 160000000          [ділення одиниці на частоту 160 МГц]
= 6.25 × 10⁻⁹ с = 6.25 нс [тривалість одного такту]
```

Сумарна кількість тактів затримки:

```
N_total
= 500 + 800 + 300        [додавання тактів критичної секції, ISR та контексту]
= 1600 тактів            [повні витрати на пробудження]
```

Граничний час реакції системи:

```
L_max
= 1600 × 6.25 × 10⁻⁹ с   [перемноження кількості тактів на період]
= 1.0 × 10⁻⁵ с = 10.0 мкс [максимальна затримка реакції]
```

Високопріоритетна задача гарантовано перейде у стан `Running` не пізніше ніж через 10 мікросекунд після фізичного фронту на виводі.

## Критерій утилізації процесора (Межа Лю-Лейланда)

Якщо в системі виконується набір із `n` періодичних задач із часом виконання `Cᵢ` та періодом повторення `Tᵢ`, коефіцієнт сумарного завантаження процесора `U` дорівнює:

```
U = ∑ᵢ₌₁ⁿ (Cᵢ / Tᵢ)
```

Класична теорема Лю-Лейланда (@@en|Liu-Layland bound@@, 1973 рік) стверджує, що для статичного пріоритетного планування Rate Monotonic гарантоване виконання всіх задач без пропуску дедлайнів забезпечується за умови:

```
U ≤ n × (2^(1/n) - 1)
```

Для трьох періодичних задач (`n = 3`) граничний поріг завантаження обчислюється так:

```
U_bound
= 3 × (2^(1/3) - 1)       [формула Лю-Лейланда для n=3]
= 3 × (1.25992 - 1)      [обчислення кореня третього степеня з двох]
= 3 × 0.25992            [віднімання одиниці]
≈ 0.77976                [теоретична межа 77.97 %]
```

При зростанні кількості задач до нескінченності (`n → ∞`) межа прямує до асимптотичного значення:

```
U_inf
= ln(2)                  [граничний перехід при n прямуючому до нескінченності]
≈ 0.69315                [теоретичний поріг 69.31 %]
```

Якщо сумарне обчислювальне навантаження системи не перевищує 69.3 %, жодна задача системи гарантовано не пропустить свій часовий дедлайн, а черги готовності `Ready` не зростатимуть нескінченно.
