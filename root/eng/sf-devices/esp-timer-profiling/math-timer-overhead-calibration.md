# Математична модель калібрування накладних витрат таймера

Вимірювання тривалості виконання ділянки коду за допомогою системного таймера або лічильника тактів процесора неминуче спотворюється накладними витратами (англ. *overhead*) самого виклику функції хронометрування. Час, що витрачається на зчитування регістрів, збереження значень на стек та повернення з підпрограми, додається до чистої тривалості тестованого алгоритму. Для отримання об'єктивних метрик інженер повинен математично оцінити систематичну та випадкову похибки вимірювального інструменту й виконати процедуру калібрування.

## Модель спотворення результату вимірювання

Позначимо істинну тривалість виконання досліджуваного фрагмента коду через `T_true`. Нехай час, зафіксований таймером на початку ділянки, дорівнює `t_start`, а час після завершення ділянки становить `t_end`.

Сирий результат вимірювання `T_raw` визначається різницею часових міток:

```
T_raw = t_end - t_start                  [сирий результат вимірювання часу]
```

У реальній системі виклик функції фіксації часу на початку займає інтервал `t_cal1`, а виклик наприкінці — інтервал `t_cal2`. Крім того, на результат впливають випадкові фактори: промахи кеш-пам'яті інструкцій, переривання від периферії та конфлікти на системній шині.

Повний математичний вираз для сирого заміру подається через суму істинного часу, систематичного накладного часу `t_overhead` та випадкової похибки `epsilon`:

```
T_raw = T_true + t_overhead + epsilon    [адитивна модель вимірювального тракту]
```

де систематичний оверхед визначається часом двох послідовних викликів функції таймера без корисного навантаження між ними:

```
t_overhead = t_cal1 + t_cal2             [сумарний систематичний оверхед виклику]
```

## Статистичне калібрування та усунення оверхеду

Оскільки поодинокий замір накладних витрат може зазнати впливу випадкової завади `epsilon`, оцінку систематичного зсуву проводять статистично на серії з `N_samples` холостих замірів (замірів порожньої операції).

Нехай `t_bench[i]` — результат `i`-го вимірювання порожньої ділянки коду. Систематичний оверхед калібрування `T_bias` оцінюється як мінімальне або медіанне значення з вибірки:

```
T_bias = min(t_bench[0], t_bench[1], ..., t_bench[N_samples - 1]) [мінімальний оверхед]
```

Вибір оператора мінімуму `min(...)` замість середнього арифметичного є строгим стандартом профілювання вбудованих систем: мінімальний замір відповідає ситуації, коли код інструментарію вже завантажений у кеш-пам'ять інструкцій L1, конвеєр процесора заповнений, а системні переривання не втручалися у виконання.

Відкалібрована (чиста) тривалість виконання корисного коду `T_clean` обчислюється відніманням виявленого систематичного зміщення:

```
T_clean = max(0, T_raw - T_bias)         [очищений від оверхеду час виконання]
```

Оператор `max(0, ...)` гарантує відсутність фізично неможливих від'ємних значень часу у випадку мікроскопічних коливань тактової синхронізації.

## Розрахунок на числовому прикладі

**Умова розрахунку**: Проводиться профілювання швидкої функції фільтрації за допомогою лічильника циклів CPU. Частота ядра становить `f_cpu = 240` МГц (тривалість одного такту `T_cycle = 4.167` нс). Серія з 5 холостих вимірювань показала такі значення в тактах: `t_bench = {42, 38, 38, 45, 39}`. Сире вимірювання тестової функції дало `T_raw = 186` тактів.

Знайдемо калібрувальне зміщення оверхеду `T_bias`:

```
T_bias = min(42, 38, 38, 45, 39)
       = 38 тактів                       [мінімальний систематичний оверхед інструменту]
```

Розрахуємо очищену кількість тактів виконання функції `T_clean`:

```
T_clean = 186 - 38
        = 148 тактів                     [чистий час роботи алгоритму]
```

Переведемо отримані значення у фізичний час у наносекундах:

```
t_overhead_ns = 38 ÷ (240 × 10⁶)
              ≈ 1.583 × 10⁻⁷ с
              ≈ 158.3 нс                 [абсолютна тривалість накладних витрат]

t_clean_ns = 148 ÷ (240 × 10⁶)
           ≈ 6.167 × 10⁻⁷ с
           ≈ 616.7 нс                    [чистий фізичний час роботи функції]
```

Частка похибки невідкаліброваного заміру складає:

```
delta_err = 38 ÷ 148
          ≈ 0.2568                       [похибка становила 25.7%]
```

**Інженерний висновок**: Без урахування калібрування оверхеду оцінка тривалості функції була б завищена на 25.7%, що призвело б до помилкових висновків щодо оптимізації алгоритму. Віднімання медіанного або мінімального зміщення є обов'язковим для ділянок коду тривалістю менше 1000 тактів.
