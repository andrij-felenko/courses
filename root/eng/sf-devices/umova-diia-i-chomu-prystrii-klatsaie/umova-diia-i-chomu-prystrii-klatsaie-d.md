# Умова, дія і чому пристрій клацає: поріг із гістерезисом

<preknowlist>
- [АЦП і квантування сигналу](root:hw-analog/adc) — як неперервна фізична величина перетворюється на дискретні коди й де виникає шум квантування.
- [Компаратор](root:hw-analog/comparator) — базовий принцип порівняння двох напруг з формуванням бінарного результату.
- [Головний цикл super-loop](root:sf-devices/super-loop) — синхронна періодична обробка входів і кроки обчислення автоматів.
- [Тригер Шмітта в аналоговій схемотехніці](root:hw-analog/schmitt-trigger) — апаратна петля гістерезису через позитивний зворотний зв'язок на операційному підсилювачі.
</preknowlist>

Електричний водонагрівач потужністю 2.5 кВт керується мікроконтролером, який щосекунди зчитує покази термодатчика NTC через 12-розрядний [АЦП](root:hw-analog/adc) та замикає силове електромеханічне реле. Якщо в прошивці записано наївну умову «якщо температура нижча за 25.0°C — увімкнути ТЕН, інакше вимкнути», то в момент, коли вода нагрівається рівно до 24.99°C, пристрій перетворюється на автогенератор імпульсів. Тепловий шум вимірювального тракту та наведення від силової мережі амплітудою всього ±15 мВ змушують виміряне число коливатися довкола порога десятки разів на секунду. Силове реле починає несамовито брязкати з частотою опитування, контакти вигорають у безперервній електричній дузі за лічені години, а імпульсні перешкоди по шині живлення спричиняють апаратне зависання мікроконтролера.

Ця аварійна поведінка відома в інженерії як брязкіт контактів або деренчання реле (англ. *relay chattering*). Вона виникає не через дефект заліза чи помилку сенсора, а через фундаментальну ваду алгоритмічного мислення: спробу ухвалити однозначне дискретне рішення над неперервним зашумленим сигналом без залучення внутрішньої пам'яті стану.

## Анатомія аварії: пастка безпам'ятного порівняння

Розглянемо найпоширенішу структуру наївного коду вбудованих систем — безпосередній переклад правил «умова → дія» (англ. *Condition-Action Rules*):

:::tabs
```c
#include <stdbool.h>

void relay_set_power(bool enable);

void temperature_control_step(float current_temperature) {
    const float THRESHOLD = 25.0f;

    if (current_temperature < THRESHOLD) {
        relay_set_power(true);   /* Увімкнути нагрів */
    } else {
        relay_set_power(false);  /* Вимкнути нагрів */
    }
}
```
```cpp
namespace embedded::naive {

void SetRelayPower(bool enable) noexcept;

void TemperatureControlStep(float current_temperature) noexcept {
    constexpr float Threshold = 25.0f;

    if (current_temperature < Threshold) {
        SetRelayPower(true);   // Увімкнути нагрів
    } else {
        SetRelayPower(false);  // Вимкнути нагрів
    }
}

} // namespace embedded::naive
```
:::

Математично ця функція є безпам'ятним відображенням: її вихід у момент часу `k` повністю визначається виключно вхідним значенням `x[k]`. Вона не знає, що відбувалося на кроці `k-1`, був нагрівач щойно увімкнений чи вимкнений, і в якому фізичному напрямку рухається процес.

У реальному світі виміряний сигнал сенсора `x[k]` ніколи не дорівнює ідеальній фізичній величині `T(t)`. Він є сумою істинного повільного фізичного процесу та випадкового високочастотного шуму:

```
x[k] = T(t_k) + n[k]
```

де `n[k]` — випадковий процес із нульовим математичним сподіванням та середньоквадратичним відхиленням `σ`.

Коли температура повільно наближається до порогової лінії `THRESHOLD = 25.0°C`, випадковий додаток `n[k]` на кожному такті перекидає сумарне значення `x[k]` то вище, то нижче порога. Оскільки порогова лінія має нульову товщину, будь-яка нескінченно мала флуктуація змінює логічний результат `x[k] < THRESHOLD` на протилежний.

![Проблема брязкоту стану при єдиному порозі компаратора](/root/eng/sf-devices/umova-diia-i-chomu-prystrii-klatsaie/img/chattering-problem.svg)
*Зашумлений аналоговий сигнал перетинає нульову ширину наївного порога багатократно за короткий інтервал часу. Безпам'ятна порогова функція перетворює ці мікрофлуктуації на серію високочастотних комутацій силового виконавчого механізму (Relay Chattering).*

Наслідки брязкоту стану для фізичного пристрою катастрофічні:

1. **Ерозія та зварювання контактів реле**: кожне розмикання під індуктивним або резистивним навантаженням генерує електричну дугу. Реле, розраховане на 100 000 спрацьовувань за весь термін служби, вичерпує ресурс за кілька хвилин роботи на частоті 50 Гц.
2. **Теплове руйнування напівпровідникових ключів**: для силових польових транзисторів (MOSFET / IGBT) часті перемикання означають багаторазове проходження через активну лінійну зону з високим виділенням динамічної потужності `P_sw = f_sw · E_on_off`, що призводить до миттєвого перегріву кристала.
3. **Шторм подій у програмній архітектурі**: якщо зміна стану генерує подію в RTOS-чергу або надсилає мережеве повідомлення через шину керування, система зазнає перевантаження буферів повідомлень (англ. *event queue overflow*), що блокує роботу сусідніх критичних потоків.
4. **Акустичне роздратування користувача**: безперервне клацання механічних контактів або зумерів сприймається людиною як несправність і брак виробу.

## Фізична природа шуму: чому лінія не буває тонкою

Інженери-початківці часто вважають, що шум можна повністю усунути «якіснішим датчиком» або «правильною схемотехнікою». Проте шум у вимірювальному тракті — це фундаментальна фізична властивість матерії.

Вимірювальний тракт містить три непереборні джерела стохастичних флуктуацій:

1. **Тепловий шум Джонсона-Найквіста**: породжується хаотичним тепловим рухом носіїв заряду в будь-якому резистивному елементі (термісторі, дільнику напруги, внутрішньому опорі джерела сигналу). Навіть у стані ідеальної температурної рівноваги спектральна густина напруги шуму становить `e_n = √(4 · k_B · T · R)`.
2. **Шум квантування [АЦП](root:hw-analog/adc)**: перетворення неперервної напруги в дискретний код породжує похибку округлення з дисперсією `σ_q = LSB / √12`.
3. **Електромагнітні наведення (EMI)**: комутація сусідніх цифрових ліній, робота ШІМ-драйверів, імпульсних стабілізаторів напруги та радіомодулів наводить високочастотні струми на вимірювальні доріжки друкованої плати.

### Електричний паразитний зворотний зв'язок (Ground Bounce)

Існує ще один підступний фізичний ефект, про який часто забувають розробники програмного забезпечення. Коли мікроконтролер подає сигнал на ввімкнення потужного навантаження (наприклад, котушки реле струмом 100 мА або ТЕНу струмом 10 А), струм у колі живлення стрибкоподібно зростає. 

Через скінченний опір та індуктивність доріжок заземлення друкованої плати потенціал аналогової землі на частки мілісекунди зміщується на кілька десятків мілівольтів (явище *Ground Bounce*). Опорна напруга або аналоговий вхід [АЦП](root:hw-analog/adc) бачить це зміщення як миттєвий стрибок вимірюваного сигналу!

Якщо поріг не має запасу по напрузі, це зміщення землі миттєво повертає сигнал за порогову лінію, змушуючи програму негайно вимкнути реле. Вимкнення реле повертає землю на місце, сигнал знову перетинає поріг, і реле вмикається знову. Виникає замкнена автоколивна система через паразитний зв'язок по живленню, яку неможливо подолати без програмного розведення порогів.

Математичне виведення взаємозв'язку між розмахом шуму, розрядністю перетворювача та надійністю порогових рішень детально розібрано в [математичному розрахунку необхідної ширини мертвої зони від шуму сенсора](root:sf-devices/umova-diia-i-chomu-prystrii-klatsaie/math-sensor-noise-deadband.md).

З цього випливає ключовий закон розробки вбудованих систем: **порогове рішення ніколи не повинно прийматися за єдиною математичною точкою**. Між умовами ввімкнення та вимкнення зобов'язана існувати скінченна просторова або числова дистанція.

## Гістерезис: дві межі та збереження стану

Термін **гістерезис** походить від грецького слова *hystéresis* (грец. *hystéresis* — відставання, запізнення). В теорії систем цим терміном позначають явище, за якого реакція системи на зовнішній вплив залежить не лише від поточного значення цього впливу, але й від **попередньої історії станів**.

В аналоговій схемотехніці для боротьби з шумом використовують [тригер Шмітта](root:hw-analog/schmitt-trigger), де позитивний зворотний зв'язок операційного підсилювача штучно розсуває пороги перемикання. У програмній інженерії той самий принцип реалізується через введення двох роздільних порогових меж:

- `T_high` (верхній поріг): значення, досягнення якого необхідне для переходу в активний стан;
- `T_low` (нижній поріг): значення, нижче якого сигнал мусить опуститися для повернення в неактивний стан;
- `Δ = T_high - T_low` (мертва зона, англ. *Deadband*): зона нечутливості, всередині якої система **забороняє зміну поточного стану**.

![Статична характеристика гістерезисного компаратора з двома порогами](/root/eng/sf-devices/umova-diia-i-chomu-prystrii-klatsaie/img/hysteresis-loop.svg)
*Петля гістерезису: перехід 0 → 1 відбувається лише при перевищенні верхнього порога T_high, а зворотний перехід 1 → 0 — лише при спаді нижче T_low. Усередині мертвої зони (Deadband) вихід зберігає свій попередній стан.*

### Симетричне та несиметричне формулювання порогів

Залежно від фізики керованого процесу пороги задають одним із двох способів.

#### 1. Симетричний гістерезис (уставка ± напівзона)
Застосовується в регуляторах, де потрібно утримувати величину довкола центрального номіналу (англ. *Setpoint*, `SP`):

```
T_high = SP + (Δ / 2)
T_low  = SP - (Δ / 2)
```

Наприклад, у кліматичній системі з уставкою `SP = 22.0°C` та мертвою зоною `Δ = 2.0°C` кондиціонер увімкнеться при `23.0°C`, а вимкнеться лише після охолодження до `21.0°C`.

#### 2. Несиметричний гістерезис (прямі пороги On/Off)
Застосовується, коли фізична динаміка системи в прямому та зворотному напрямках суттєво відрізняється:

- **Заряджання літієвого акумулятора**: зарядний пристрій вимикається при досягненні максимальної напруги відсічки `V_max = 4.20 В`, але повторно починає заряд лише тоді, коли внаслідок саморозряду або споживання напруга впаде нижче `V_recharge = 4.05 В`. Тут пороги `4.20 В` та `4.05 В` задаються явно з міркувань деградації хімічної структури літієвих елементів.
- **Наповнення накопичувального бака**: насос вмикається за нижнім критичним рівнем `15 %`, а вимикається за верхнім рівнем `95 %`. Симетричне завдання довкола середнього рівня `55 % ± 40 %` було б неприродним для технологічного опису.
- **Охолодження потужного процесора**: вентилятор стартує на повній швидкості при нагріві кристала до `75°C`, але скидає оберти до нуля лише після глибокого охолодження радіатора до `50°C`, що запобігає постійному розгону та гальмуванню крильчатки кулера.

## Апаратний тригер Шмітта проти програмного гістерезису

Чому програмний гістерезис став стандартом у сучасних мікроконтролерних пристроях, витіснивши аналогові схеми на компараторах?

| Критерій порівняння | Апаратний тригер Шмітта (ОП + резистори) | Програмний предикат у прошивці |
|---|---|---|
| **Гнучкість налаштування** | Фіксовані пороги, задані номіналами резисторів обв'язки | Будь-які пороги, налаштовні через ПЗ, MQTT або екран меню |
| **Складність плати (BOM)** | Додаткові мікросхеми компараторів, прецизійні резистори | Нульова (сигнал іде напряму на вхід АЦП мікроконтролера) |
| **Температурний дрейф** | Залежить від температурного коефіцієнта (ТКС) зовнішніх резисторів | Відсутній (цифрова математика абсолютно стабільна) |
| **Швидкодія реакції** | Наносекунди (обмежується смугою пропускання ОП) | Мікросекунди або мілісекунди (визначається періодом опитування) |
| **Асиметрія та адаптивність** | Складна аналогова схема з комутацією діодами | Кілька рядків коду з довільною логікою зміни меж |

Апаратний гістерезис залишається незамінним для надшвидких аварійних захистів (захист силових транзисторів інвертора від короткого замикання за 50 наносекунд). Усі інші завдання технологічного керування (температура, тиск, рівень рідини, напруга живлення) набагато надійніше, дешевше та точніше вирішуються програмним гістерезисом.

## Мінімально безпечна ширина мертвої зони: правило 6σ

Якою має бути ширина мертвої зони `Δ`?

Якщо зробити `Δ` занадто великою, пристрій втратить точність регулювання: температура коливатиметься у надто широкому коридорі. Якщо ж зробити `Δ` занадто малим, амплітуда піків шуму перевищить відстань між порогами, і брязкіт повернеться.

Для випадкового шуму з нормальним розподілом та середньоквадратичним відхиленням `σ` ймовірність того, що випадковий викид перетне інтервал `Δ`, підпорядковується правилу гаусових хвостів:

- При `Δ = 2·σ`: ймовірність викиду `~2.28 %`. При частоті опитування 100 Гц кожні кілька секунд виникатиме помилкове перемикання.
- При `Δ = 4·σ`: ймовірність викиду `~0.003 %`. Помилки трапляються кілька разів на добу.
- При `Δ = 6·σ`: ймовірність викиду `~10⁻⁹`. Помилкове перемикання стається в середньому раз на сотні діб безперервної роботи.
- При `Δ = 8·σ`: ймовірність викиду `~10⁻¹⁵`. Практично абсолютна стійкість до шуму протягом десятиліть.

> 🔧 **Золоте правило розробника:**  
> Мінімальна ширина мертвої зони повинна складати не менше ніж 6 середньоквадратичних відхилень повного шуму тракту:  
> `Δ ≥ 6·σ_total`  
> Якщо технологічний допуск вимагає вужчої петлі, ніж `6·σ_total`, заборонено звужувати програмну мертву зону — спершу слід знизити `σ_total` за допомогою апаратного RC-фільтра або програмного усереднення (ковзного середнього / IIR-фільтра).

## Гістерезис як скінченний автомат (FSM)

Введення гістерезису докорінно змінює архітектурний тип програми: вона перестає бути безпам'ятною комбінаційною логікою і перетворюється на **дискретний скінченний автомат** (англ. *Finite State Machine*, FSM).

У такій системі вихід визначається не лише поточним вимірюванням, а парою `(Поточний_Стан, Вхідне_Значення)`.

![Автоматний граф переходів із гістерезисною мертвою зоною](/root/eng/sf-devices/umova-diia-i-chomu-prystrii-klatsaie/img/fsm-hysteresis-table.svg)
*Граф автоматних переходів: при знаходженні сигналу всередині мертвої зони спрацьовують петлі утримання стану (Self-loops), що забезпечує стабільність виходу.*

Таблиця переходів автомата для нагрівача формулюється наступним чином:

| Поточний стан | Умова вхідного сигналу `T` | Наступний стан | Дія на виході |
|---|---|---|---|
| `HEATER_OFF` | `T < T_low` (занадто холодно) | `HEATER_ON` | Увімкнути реле (`actuator = 1`) |
| `HEATER_OFF` | `T ≥ T_low` (норма або тепло) | `HEATER_OFF` | Залишити вимкненим (`actuator = 0`) |
| `HEATER_ON` | `T > T_high` (нагріто до межі) | `HEATER_OFF` | Вимкнути реле (`actuator = 0`) |
| `HEATER_ON` | `T ≤ T_high` (ще триває нагрів) | `HEATER_ON` | Залишити увімкненим (`actuator = 1`) |

Зверніть увагу на діапазон `T_low ≤ T ≤ T_high`:
- Якщо автомат зайшов у цю зону зі стану `HEATER_OFF`, він залишається в `HEATER_OFF`.
- Якщо автомат зайшов у цю зону зі стану `HEATER_ON`, він залишається в `HEATER_ON`.

Саме це і є бістабільна пам'ять стану: всередині мертвої зони система зберігає попереднє рішення, повністю ігноруючи будь-які високочастотні коливання шуму.

## Пастки реалізації та крайові випадки

Навіть при розумінні теорії гістерезису розробники регулярно припускаються типових інженерних помилок під час кодування.

### 1. Проблема холодного старту всередині мертвої зони

Що повинен робити пристрій, якщо в момент подачі живлення або після перезавантаження сторожовим таймером [watchdog](root:sf-devices/watchdog) температура опинилася акурат посередині: `T_low < T_start < T_high`?

Попереднього стану в оперативній пам'яті ще немає. Тут існує два підходи:
1. **Консервативний безпечний стан (Safe Inactive)**: за замовчуванням вихід залишається вимкненим (`0`), доки сигнал явно не опуститься нижче `T_low`. Це стандарт для більшості силових нагрівачів та приводів.
2. **Агресивна ініціалізація (Aggressive Active)**: якщо система критично важлива (наприклад вентиляція в шахті), вихід активується, якщо сигнал не опустився нижче `T_low`.

Вибір стратегії старту повинен бути явним архітектурним рішенням, а не наслідком випадкового сміття в неініціалізованій змінній RAM.

### 2. Динамічна переконфігурація уставки на льоту

Якщо користувач через екран або веб-інтерфейс змінює уставку `SP` під час роботи системи, нові пороги `T_low` та `T_high` зміщуються.

Типова помилка — скидати об'єкт компаратора в початковий стан під час зміни уставки. Це призводить до короткочасного розриву силового контактора. Коректна реалізація оновлює лише числові межі в структурі конфігурації, не торкаючись прапорця поточного стану.

### 3. Комбінація гістерезису з часовим антидребезгом

Для важкого силового обладнання (наприклад, фреонових компресорів промислових холодильників) одного лише амплітудного гістерезису буває недостатньо. Якщо теплоносія мало, температура може реально змінюватися на кілька градусів за кілька секунд. 

Часті пуски компресора призводять до гідроударів та перегріву пускових обмоток двигуна. Тому амплітудний гістерезис обов'язково доповнюють часовим обмеженням — [мінімальним часом утримання стану](root:sf-devices/minimalnyi-chas-stanu-zatrymka-i-antydrebezh), який забороняє повторне ввімкнення компресора раніше, ніж через 180–300 секунд після попереднього вимкнення.

Для складних систем із подієвими лічильниками також застосовують [механізм валідації N з M](root:sf-devices/n-z-m-i-histerezys-na-podiiakh).

## Програмний модуль порогового предикату на C та C++

Наведемо компактний, але строго ізольований модуль компаратора з гістерезисом, готовий до інтеграції в цикли опитування [super-loop](root:sf-devices/super-loop) або задачі RTOS.

Повний код бібліотеки з підтримкою цілочисельної арифметики фіксованої крапки та розширеними стратегіями ініціалізації наведено у [бібліотеці порогових предикатів з гістерезисом](root:sf-devices/umova-diia-i-chomu-prystrii-klatsaie/proj-threshold-predicate.md).

```c
#include <stdbool.h>

/* Конфігурація: незмінні параметри меж */
typedef struct {
    float low_threshold;   /* Поріг вимкнення */
    float high_threshold;  /* Поріг увімкнення */
} hysteresis_config_t;

/* Стан: мутабельна пам'ять автомата */
typedef struct {
    bool current_output;   /* Поточний логічний рівень (1 / 0) */
    bool is_initialized;   /* Прапорець першого проходу */
} hysteresis_state_t;

/**
 * @brief Обчислення нового стану за поточним вимірюванням
 */
bool hysteresis_step(const hysteresis_config_t *cfg, 
                     hysteresis_state_t *state, 
                     float input_value) {
    if (!state->is_initialized) {
        /* Холодний старт: увімкнено лише якщо строго вище верхньої межі */
        state->current_output = (input_value >= cfg->high_threshold);
        state->is_initialized = true;
        return state->current_output;
    }

    if (state->current_output) {
        /* Зараз увімкнено: вимикаємо лише при спаді нижче low_threshold */
        if (input_value <= cfg->low_threshold) {
            state->current_output = false;
        }
    } else {
        /* Зараз вимкнено: вмикаємо лише при підйомі вище high_threshold */
        if (input_value >= cfg->high_threshold) {
            state->current_output = true;
        }
    }

    return state->current_output;
}
```
```cpp
#include <concepts>

namespace embedded::control {

template <typename T>
requires std::floating_point<T> || std::integral<T>
class HysteresisPredicate {
public:
    constexpr HysteresisPredicate(T low_threshold, T high_threshold) noexcept
        : low_(low_threshold), high_(high_threshold) {}

    [[nodiscard]] constexpr bool Update(T input_value) noexcept {
        if (!initialized_) {
            state_ = (input_value >= high_);
            initialized_ = true;
            return state_;
        }

        if (state_) {
            if (input_value <= low_) {
                state_ = false;
            }
        } else {
            if (input_value >= high_) {
                state_ = true;
            }
        }

        return state_;
    }

    [[nodiscard]] constexpr bool GetState() const noexcept { return state_; }
    constexpr void Reset() noexcept { state_ = false; initialized_ = false; }

private:
    T low_{};
    T high_{};
    bool state_{false};
    bool initialized_{false};
};

} // namespace embedded::control
```

## Інженерний підсумок

1. **Безпам'ятне порогове порівняння аналогових величин — це дефект проектування.** Єдиний поріг перетворює будь-який зашумлений сигнал на генератор брязкоту на межі переходу.
2. **Гістерезис вимагає двох порогів.** Верхній поріг визначає увімкнення, нижній — вимкнення, а відстань між ними утворює мертву зону нечутливості `Δ`.
3. **Ширина мертвої зони диктується фізикою шуму.** Завжди розраховуйте або вимірюйте повний середньоквадратичний шум тракту `σ_total` та обирайте `Δ ≥ 6·σ_total`.
4. **Компаратор із гістерезисом — це скінченний автомат.** Збереження попереднього стану всередині мертвої зони забезпечує абсолютну нечутливість до перешкод будь-якої форми, амплітуда яких не перевищує ширину петлі.
