# Програмний та апаратний дебаунсер кнопок: автомат станів, зсувний регістр та RS-засувка

Цей проєкт демонструє побудову надійних систем придушення брязкоту контактів у вбудованих системах реального часу. Проєкт містить схемотехнічний розрахунок апаратного захисту, реалізацію неблокуючого автомата станів (FSM) та оптимізований алгоритм зсувного регістра для швидкого опитування багатьох входів.

## Схемотехнічний розрахунок апаратної RS-засувки та RC-фільтра

Для критичних промислових органів керування (наприклад, аварійних кнопок E-Stop або кінцевих вимикачів верстатів) застосовують апаратну схему захисту від брязкоту. Вона гарантує стабільний логічний сигнал незалежно від стану процесорного ядра.

### Схема RS-засувки на базі елементів NAND (74HC00)

Перемикач типу SPDT (Single Pole Double Throw) перемикає рухомий контакт між двома нерухомими полюсами: нормальним замкненим (NC) та нормальним розімкненим (NO). Полюси підтягнуті до напруги живлення резисторами 10 кОм і підключені до входів асинхронного RS-тригера на двох елементах 2-NAND:

```
VCC ──[ R1 10k ]──┬── /SET (NAND 1 Pin 1)
                  │
             NO o─┘
                  \  o── GND (Рухомий контакт)
             NC o─┐
                  │
VCC ──[ R2 10k ]──┴── /RESET (NAND 2 Pin 5)
```

При першому ж мікродотику рухомого контакту до полюса NO вхід `/SET` замикається на землю, формуючи логічний 0. Вихід тригера Q миттєво встановлюється в 1. Наступні механічні відскоки рухомого контакту призводять лише до розмикання кола, повертаючи вхід `/SET` до 1 через підтягувальний резистор. Оскільки стан `/SET = 1, /RESET = 1` є станом збереження інформації, вихід Q залишається нерухомим. Лише коли перемикач повністю перелетить на полюс NC, тригер скинеться. Затримка реакції схеми дорівнює затримці поширення логічного вентиля (близько 10 нс), що на шість порядків швидше за будь-який програмний опитувач.

## Архітектура програмного модуля FSM

Для масових кнопкових інтерфейсів без додаткових мікросхем реалізовано програмний автомат станів, наведений у файлах [debouncer.h](root:sf-devices/switch-debounce/proj-hardware-schmitt-latch-debounce/c/debouncer.h) та [debouncer.c](root:sf-devices/switch-debounce/proj-hardware-schmitt-latch-debounce/c/debouncer.c).

Головна перевага автомата полягає у повній відсутності блокуючих викликів: функція `debouncer_update_fsm()` викликається періодично (наприклад, із системного тіка 1–5 мс) і повертає події через enum `btn_event_t`:

```c
typedef enum {
    BTN_EVENT_NONE = 0,
    BTN_EVENT_PRESSED,
    BTN_EVENT_RELEASED,
    BTN_EVENT_LONG_PRESS
} btn_event_t;
```

### Алгоритм фільтрації станів

Структура `debouncer_t` інкапсулює поточний стан кнопки та лічильники часу:

```c
typedef struct {
    btn_state_t state;
    uint16_t debounce_timer_ms;
    uint16_t hold_timer_ms;
    uint16_t debounce_threshold_ms;
    uint16_t long_press_threshold_ms;
    bool long_press_fired;
    uint16_t shift_history;
} debouncer_t;
```

При отриманні першого сигналу натискання автомат переходить у стан `BTN_STATE_DEBOUNCE_PRESS`. Всі подальші мікроперепади накопичують час `debounce_timer_ms`. Лише коли вхідний сигнал утримується активним безперервно протягом `debounce_threshold_ms` (типово 20 мс), автомат підтверджує перехід у `BTN_STATE_PRESSED` та генерує подію `BTN_EVENT_PRESSED`.

Аналогічна фільтрація виконується при розмиканні: стан `BTN_STATE_DEBOUNCE_RELEASE` відсікає брязкіт відпускання контактів перед генерацією `BTN_EVENT_RELEASED`.

## Оптимізована фільтрація через зсувний регістр

Для систем із жорстким обмеженням пам'яті (наприклад, матричні клавіатури на 64 клавіші) функція `debouncer_update_shift()` реалізує побітовий інтегратор:

```c
bool debouncer_update_shift(debouncer_t *btn, bool raw_pressed) {
    if (!btn) return false;
    btn->shift_history = (uint16_t)((btn->shift_history << 1) | (raw_pressed ? 1 : 0));
    return ((btn->shift_history & 0x00FF) == 0x00FF);
}
```

Кожне зчитування зсуває бітову маску ліворуч. Якщо пін опитується кожні 2.5 мс, умова `(shift_history & 0xFF) == 0xFF` гарантує, що вхідний сигнал залишався стабільним протягом 8 послідовних опитувань (сумарно 20 мс). Цей алгоритм вимагає лише 2 байти оперативної пам'яті на один вхід і виконується за 4 процесорні інструкції ARM Cortex-M.
