# 📋 Інтерфейс і структури даних requests

Бібліотека `requests` побудована на чіткому розділенні обов'язків між окремими структурами даних, де кожен об'єкт відповідає за ізольовану фазу життєвого циклу HTTP-транзакції. На відміну від монолітних бібліотек, де конфігурація з'єднання, формування заголовків і читання байтів змішані в єдиному дескрипторі, тут потік даних проходить крізь послідовність спеціалізованих моделей: від декларативного опису наміру до фізичного сокетного потоку та фінального об'єкта відповіді.

Цей довідник містить систематичний опис публічних класів, їхніх внутрішніх атрибутів, сигнатур ключових методів, життєвих циклів та повної ієрархії винятків, необхідних для проектування надійних системних інтеграцій.

## Огляд основних класів та архітектурне призначення

В основі бібліотеки лежить конвеєр із шести ключових класів:

1. `Session` (модуль `requests.sessions`): Головний координатор клієнтського стану. Сесія утримує постійні налаштування між множинними викликами (глобальні заголовки, параметри автентифікації, перевірку сертифікатів TLS, сховище cookie `CookieJar`), реєструє транспортні адаптери та керує пулами відкритих TCP-з'єднань.
2. `Request` (модуль `requests.models`): Декларативний контейнер параметрів. Він представляє сирий, ще не оброблений запит у тому вигляді, в якому його сформував користувач (словники Python, об'єкти форм, неперетворені рядки).
3. `PreparedRequest` (модуль `requests.models`): Повністю скомпільований і нормалізований зліпок HTTP-запиту. Всі компоненти приведені до стандартів IETF (percent-encoding для URL, заголовки у структурі `CaseInsensitiveDict`, серіалізоване двійкове тіло, обчислена довжина `Content-Length`). Саме цей об'єкт передається в транспортний адаптер для надсилання в мережу.
4. `Response` (модуль `requests.models`): Об'єкт відповіді, що інкапсулює статус-код, заголовки сервера, розпаковане тіло, посилання на сирий сокетний потік `urllib3.response.HTTPResponse`, історію проміжних редиректів та виміряний час затримки мережі.
5. `HTTPAdapter` (модуль `requests.adapters`): Базова реалізація транспортного адаптера, що транслює універсальний `PreparedRequest` у виклики менеджера пулів `urllib3.PoolManager`.
6. `CaseInsensitiveDict` (модуль `requests.structures`): Спеціалізована реалізація асоціативного масиву, що реалізує інтерфейс `MutableMapping`, але ігнорує регістр символів під час пошуку ключів відповідно до вимог стандарту RFC 7230 для HTTP-заголовків.

## Клас Session: сигнатури методів та керування станом

Об'єкт `Session` надає повний набір методів для виконання запитів усіх стандартних методів HTTP (`get`, `post`, `put`, `delete`, `patch`, `head`, `options`), які є зручними обгортками над базовим методом `request()`:

```python
class Session:
    def request(
        self,
        method: str,
        url: str,
        params: Optional[Union[Dict[str, Any], List[Tuple[str, Any]], bytes]] = None,
        data: Optional[Union[Dict[str, Any], List[Tuple[str, Any]], bytes, IO]] = None,
        headers: Optional[Dict[str, str]] = None,
        cookies: Optional[Union[Dict[str, str], CookieJar]] = None,
        files: Optional[Dict[str, Any]] = None,
        auth: Optional[Union[Tuple[str, str], AuthBase, Callable]] = None,
        timeout: Optional[Union[float, Tuple[float, float]]] = None,
        allow_redirects: bool = True,
        proxies: Optional[Dict[str, str]] = None,
        hooks: Optional[Dict[str, List[Callable]]] = None,
        stream: Optional[bool] = None,
        verify: Optional[Union[bool, str]] = None,
        cert: Optional[Union[str, Tuple[str, str]]] = None,
        json: Optional[Any] = None,
    ) -> Response:
        ...

    def prepare_request(self, request: Request) -> PreparedRequest:
        ...

    def send(self, request: PreparedRequest, **kwargs: Any) -> Response:
        ...

    def mount(self, prefix: str, adapter: BaseAdapter) -> None:
        ...

    def close(self) -> None:
        ...
```

### Детальний опис параметрів методу request()

- `method`: Текстовий ідентифікатор HTTP-дієслова (`GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `HEAD`, `OPTIONS`). Метод нормалізується до верхнього регістру під час підготовки.
- `url`: Повний уніфікований покажчик ресурсу (включно зі схемою та хостом). Якщо схема відсутня, генерується виняток `MissingSchema`.
- `params`: Словник або послідовність кортежів `(ключ, значення)`, які під час підготовки запиту серіалізуються у рядок запиту URL (`query string`) з обов'язковим відсотковим кодуванням усіх зарезервованих та не-ASCII символів.
- `data`: Дані для тіла запиту. Якщо передано словник, він кодується у формат форми `application/x-www-form-urlencoded`. Якщо передано байти або рядок, вони відправляються без змін. Якщо передано файлоподібний об'єкт або генератор, дані відправляються потоково.
- `json`: Структура даних Python (словник, список), яка автоматично серіалізується в рядок JSON у кодуванні UTF-8 із автоматичним додаванням заголовка `Content-Type: application/json`.
- `headers`: Словник користувацьких заголовків HTTP. Ці заголовки зливаються із глобальними заголовками сесії `session.headers`, перекриваючи однакові ключі.
- `cookies`: Колекція cookie для цього конкретного запиту. Зливається з внутрішнім об'єктом сесії `session.cookies`.
- `files`: Словник для формування багатокомпонентного тіла `multipart/form-data`. Дозволяє передавати файлові дескриптори, бінарні буфери та вказувати кастомні MIME-типи для окремих частин.
- `auth`: Об'єкт автентифікації. Може бути кортежем `(ім'я_користувача, пароль)` для автоматичної генерації заголовка `Authorization: Basic`, або екземпляром класу, успадкованого від `requests.auth.AuthBase` (наприклад, `HTTPDigestAuth`).
- `timeout`: Максимальний час очікування операцій. Може бути заданий єдиним числом (загальний ліміт) або кортежем `(connect_timeout, read_timeout)`, що дозволяє розділити час на встановлення TCP/TLS-з'єднання та час очікування отримання байтів від сервера.
- `allow_redirects`: Булевий прапорець, що дозволяє автоматичний перехід за статус-кодами 3xx. За замовчуванням увімкнений для всіх методів, окрім `HEAD`.
- `proxies`: Словник маршрутизації через проксі-сервери виду `{'http': 'http://proxy.corp:8080', 'https': 'https://secure.proxy:8443'}`.
- `stream`: Булевий прапорець управління сокетним потоком. Якщо `False` (за замовчуванням), бібліотека негайно зчитує все тіло відповіді в пам'ять і повертає сокет у пул. Якщо `True`, з'єднання залишається відкритим для потокового читання частинами.
- `verify`: Булевий прапорець перевірки валідності TLS-сертифіката сервера або рядок із шляхом до локального файлу з набором довірених сертифікатів CA (PEM-файл).
- `cert`: Шлях до локального клієнтського TLS-сертифіката або кортеж із двох шляхів `(cert_path, key_path)` для взаємної автентифікації клієнта й сервера (mTLS).

## Структура та поля об'єкта PreparedRequest

Об'єкт `PreparedRequest` містить повністю зібрані, нормалізовані та готові до надсилання атрибути:

- `method: str` — Нормалізований рядок HTTP-методу у верхньому регістрі.
- `url: str` — Повний нормалізований URL. Містить схему, перетворене за стандартом IDNA доменне ім'я та закодовані символи шляху й рядка запиту.
- `headers: CaseInsensitiveDict` — Фінальний асоціативний масив заголовків запиту з урахуванням глобальних значень сесії та автоматично згенерованих службових заголовків (`Content-Length`, `Content-Type`, `User-Agent`, `Host`).
- `body: Union[bytes, str, Any]` — Серіалізоване тіло запиту у вигляді двійкових байтів або відкритого потокового ітератора.
- `hooks: Dict[str, List[Callable]]` — Словник зареєстрованих функцій зворотного виклику для обробки подій життєвого циклу.
- `_cookies: CookieJar` — Сховище cookie, сформоване для цього запиту на основі правил зіставлення доменів і шляхів.

## Структура, властивості та методи об'єкта Response

Об'єкт `Response` представляє отриману від сервера відповідь і містить повний набір діагностичних та прикладних атрибутів:

- `status_code: int` — Числовий тризначний статус-код відповіді HTTP (200, 301, 403, 500 тощо).
- `reason: str` — Текстове пояснення статусу, надіслане сервером у першому рядку відповіді (наприклад, "OK", "Not Found").
- `headers: CaseInsensitiveDict` — Заголовки відповіді сервера, доступні без урахування регістру символів.
- `content: bytes` — Незмінний бінарний буфер тіла відповіді. Якщо сервер відправив стиснені дані з заголовком `Content-Encoding: gzip`, байти автоматично декомпресуються під час першого звернення.
- `text: str` — Декодоване текстове представлення відповіді у вигляді рядка Unicode. Декодування виконується за таблицею символів, вказаною в атрибуті `encoding`.
- `encoding: Optional[str]` — Рядок кодування (наприклад, `'utf-8'`, `'cp1251'`), визначений із заголовка `Content-Type` або отриманий за допомогою евристичного аналізу байтів.
- `raw: urllib3.response.HTTPResponse` — Низькорівневий об'єкт сокетного потоку рушія `urllib3`.
- `url: str` — Фінальний URL ресурсу після проходження всіх проміжних перенаправлень.
- `history: List[Response]` — Хронологічний список проміжних об'єктів відповіді, отриманих під час виконання ланцюжка редиректів.
- `cookies: RequestsCookieJar` — Колекція cookie, встановлених сервером у цій відповіді через заголовки `Set-Cookie`.
- `elapsed: datetime.timedelta` — Інтервал часу між відправленням байтів запиту в сокет та отриманням першого байта заголовків відповіді від сервера.
- `request: PreparedRequest` — Посилання на підготовлений запит, результатом якого стала ця відповідь.

### Методи класу Response

- `raise_for_status() -> None`: Перевіряє атрибут `status_code`. Якщо код перебуває в діапазоні `400–499` (клієнтська помилка) або `500–599` (серверна помилка), метод генерує виняток `requests.exceptions.HTTPError` із детальним описом помилки та посиланням на об'єкт відповіді. Якщо статус успішний (`2xx`) або інформаційний (`1xx`/`3xx`), метод нічого не робить.
- `json(**kwargs: Any) -> Any`: Виконує парсинг тіла відповіді за допомогою функції `json.loads()`. Якщо тіло не містить валідного JSON, генерується виняток `requests.exceptions.JSONDecodeError`.
- `iter_content(chunk_size: int = 1, decode_unicode: bool = False) -> Iterator[Union[bytes, str]]`: Ітератор для потокового зчитування сирих байтів відповіді блоками фіксованого розміру `chunk_size`. Запобігає завантаженню великих файлів у пам'ять процесу.
- `iter_lines(chunk_size: int = 512, decode_unicode: bool = False, delimiter: Optional[Union[bytes, str]] = None) -> Iterator[Union[bytes, str]]`: Потоковий ітератор для читання відповіді рядок за рядком. Автоматично обробляє символи перенесення рядків `\n` або користувацькі роздільники, що робить його базовим інструментом для роботи з протоколами потокової передачі подій (Server-Sent Events, SSE).
- `close() -> None`: Явно закриває сокетний потік і повертає базове TCP-з'єднання в пул `HTTPConnectionPool`. Метод є обов'язковим для виклику в режимі `stream=True`, якщо потік не було вичитано повністю.

## Повна ієрархія винятків requests

Усі виняткові ситуації, що виникають під час підготовки, надсилання та обробки HTTP-транзакцій, походять від базового класу `RequestException`. Це дозволяє програмам використовувати як загальний перехоплювач для будь-яких проблем із мережею, так і гранулярну обробку специфічних збоїв:

```
Exception / IOError
└── RequestException (базовий клас для всіх помилок бібліотеки)
    ├── HTTPError (помилки статус-кодів 4xx / 5xx, викликані через raise_for_status())
    ├── PathURLRequired (передано некоректний URL без шляху до ресурсу)
    ├── InvalidURL (синтаксично некоректний або неприпустимий URL)
    │   └── InvalidProxyURL (некоректна адреса проксі-сервера)
    ├── InvalidSchema (невідома або незареєстрована схема протоколу)
    ├── MissingSchema (URL передано без схеми, наприклад "example.com" замість "http://example.com")
    ├── URLRequired (виклик виконано без обов'язкового аргументу URL)
    ├── TooManyRedirects (перевищено встановлений ліміт циклічних або послідовних редиректів)
    ├── UnrewindableBodyError (неможливість повторно зчитати потік тіла під час повторної спроби)
    ├── RetryError (вичерпано ліміт повторних спроб транспортного адаптера)
    ├── JSONDecodeError (тіло відповіді не вдалося декодувати як валідний JSON)
    ├── ConnectionError (низькорівневий мережевий збій з'єднання)
    │   ├── ProxyError (неможливість встановити з'єднання з проміжним проксі-сервером)
    │   └── SSLError (помилка криптографічного рукостискання TLS або невалідний сертифікат)
    └── Timeout (перевищено допустимий ліміт часу виконання операції)
        ├── ConnectTimeout (таймаут встановлення з'єднання на етапі TCP SYN/ACK або TLS)
        └── ReadTimeout (таймаут очікування надходження чергової порції байтів у відкритому сокеті)
```

Така структура винятків гарантує, що жодна низькорівнева помилка сокетів операційної системи (наприклад, системний `socket.error` чи `ssl.SSLError`) не просочується у прикладний код безпосередньо: всі вони перехоплюються транспортним адаптером і транслюються у відповідні дочірні класи `RequestException`.
