# 📜 Історія ієрархічних даних у базах: від навігаційних мереж до SQL-рекурсії

У 1965 році компанія Rockwell International у співпраці з IBM розпочала розробку автоматизованої системи обліку компонентів для місячної програми «Аполлон». Ракета-носій «Сатурн-5» та космічний корабель складалися з понад двох мільйонів окремих деталей: від гігантських паливних баків і рідинних ракетних двигунів F-1 до дрібних ущільнювальних кілець і клапанів. Кожен вузол складався з підвузлів, ті — з менших блоків, утворюючи глибоку деревоподібну структуру специфікації виробів (Bill of Materials, BOM). Будь-яка інженерна зміна в конструкції вимагала миттєвого перерахунку маси апарата, перевірки залежностей і оновлення виробничих графіків постачальників.

Для розв'язання цієї задачі IBM створила систему IMS (Information Management System), яка базувалася на чистій ієрархічній моделі даних. У системі IMS дані фізично зберігалися у вигляді дерев на магнітних стрічках та дискових барабанах, де кожен дочірній сегмент містив апаратний дисковий покажчик на свій батьківський сегмент. Доступ до компонентів відбувався за допомогою навігаційних команд операційної системи (`GET UNIQUE`, `GET NEXT`), які буквально крокували по дискових адресах від кореня дерева до потрібного листка.

У 1971 році комітет CODASYL (Conference on Data Systems Languages) стандартизував мережеву модель даних DBTG, розширивши ієрархічну концепцію до довільних графів. Мережева модель дозволила вузлу мати кількох батьків через систему наборів (`SET`), проте зберегла головний архітектурний принцип: програміст мусив вручну маніпулювати вказівниками та підтримувати стан курсора у пам'яті комп'ютера.

## Реляційна революція Кодда та втрата рекурсії

У 1970 році британський математик Едгар Кодд (Edgar F. Codd) опублікував фундаментальну працю, яка запропонувала реляційну модель даних. Кодд довів, що фізичні вказівники на дискові адреси створюють нерозривну залежність між логікою програми та фізичним розташуванням байтів на магнітних носіях. Щоб звільнити розробників від низькорівневої навігації, реляційна модель ввела першу нормальну форму (1NF): дані організовуються виключно у пласкі двовимірні таблиці, де кожен атрибут є атомарним скалярним значенням.

Цей теоретичний тріумф створив фундаментальний математичний парадокс для обробки ієрархій. Класична реляційна алгебра Кодда базується на логіці першого порядку (численні кортежів першого порядку). У ній визначено операції проекції, селекції, декартового добутку, об'єднання та різниці множин. Проте реляційна алгебра володіє властивістю обмеженої виразності: вона принципово не здатна обчислити транзитивне замикання графа довільної глибини за допомогою фіксованого реляційного виразу.

У реляційній таблиці зі списком суміжності `(id, parent_id)` можна вибрати дітей кореня за один оператор з'єднання (`JOIN`). Можна вибрати онуків за два `JOIN`. Але якщо дерево має довільну глибину `N`, невідому на момент складання запиту, стандартний SQL-89 вимагав або виконання `N` послідовних запитів із клієнтської програми, або створення монструозних збережених процедур із тимчасовими таблицями та курсорами.

## Пропрієтарні розширення: поява CONNECT BY

У 1979 році молода компанія Relational Software Inc. (яка згодом змінила назву на Oracle Corporation) випустила першу комерційну версію СУБД Oracle v2. Зіткнувшись із потребами великих промислових підприємств у розгортанні специфікацій виробів (BOM), співзасновник компанії Боб Майнер (Bob Miner) додав до діалекту SQL нестандартне пропрієтарне розширення: конструкцію `CONNECT BY ... PRIOR` та оператор `START WITH`.

```sql
SELECT level, part_id, name
FROM bill_of_materials
START WITH parent_id IS NULL
CONNECT BY PRIOR part_id = parent_id;
```

Цей синтаксис дозволив рушію Oracle самостійно виконувати обхід дерева в глибину під час сканування рядків таблиці. Проте рішення залишалося пропрієтарним стандартом однієї компанії: воно було відсутнє у системі IBM DB2, Informix, Sybase та ранніх відкритих базах даних, що унеможливлювало перенесення складних промислових баз між різними СУБД.

## Вкладені множини Джо Селко (1996)

У 1996 році американський інженер і член комітету зі стандартизації ANSI SQL Джо Селко (Joe Celko) опублікував у своїй знаменитій книзі «SQL for Smarties: Advanced SQL Programming» альтернативну математичну модель представлення дерев — **модель вкладених множин** (Nested Sets Model).

Селко запропонував замінити вказівники на батьківські вузли топологічним інтервальним кодуванням на основі обходу дерева в глибину. Кожен вузол отримував два числових атрибути: лівий ключ `lft` та правий ключ `rgt`. Дерево перетворювалося на систему геометрично вкладених числових інтервалів:

```sql
SELECT node.*
FROM categories AS parent
JOIN categories AS node
  ON node.lft BETWEEN parent.lft AND parent.rgt
WHERE parent.id = 1;
```

Винахід Селко спричинив справжню сенсацію в середовищі реляційних розробників середини 1990-х років. Запит на отримання повного піддерева або агрегації всіх нащадків на довільну глибину тепер записувався одним найпростішим оператором `SELECT` без жодних рекурсивних викликів, процедур чи пропрієтарних розширень. Запит виконувався за мікросекунди завдяки стандартному індексному діапазонному скануванню (B-Tree range scan).

Проте масове впровадження моделі вкладених множин у високонавантажених інтернет-магазинах та контент-системах початку 2000-х років виявило її зворотний бік: катастрофічну вартість модифікації даних. Додавання одного нового листка вимагало блокування таблиці та зсуву числових ключів у половині всіх рядків бази даних, що призводило до взаємних блокувань (deadlocks) у багатокористувацькому середовищі.

## Стандартизація рекурсивних запитів: SQL:1999 (SQL3)

Необхідність декларативної та переносимої рекурсії призвела до багаторічної роботи комітетів ANSI та ISO. У 1999 році було ухвалено новий міжнародний стандарт ISO/IEC 9075:1999 (неофіційно відомий як SQL:1999 або SQL3). Стандарт увів концепцію узагальнених табличних виразів (Common Table Expressions, CTE) із ключовим словом `WITH RECURSIVE`.

Рекурсивний CTE визначив математично строгу семантику обчислення найменшої фіксованої точки (least fixed point):
1. **Якірний член (Anchor Member):** початкове базове відношення `R₀`.
2. **Рекурсивний член (Recursive Member):** відображення `f(Rᵢ)`, що з'єднує попередній шар із цільовою таблицею.
3. **Об'єднання:** `UNION ALL` накопичує кортежі в результуючий набір доти, доки черговий крок не поверне порожню множину (`R_{k+1} = ∅`).

Починаючи з IBM DB2 та Microsoft SQL Server 2005, підтримка `WITH RECURSIVE` з'явилася в усіх ключових реляційних системах: PostgreSQL реалізував її у версії 8.4 (2009 рік), SQLite — у версії 3.8.3 (2014 рік), а MySQL — у версії 8.0 (2018 рік).

## Сучасний ландшафт: Таблиці замикання та розширення ltree

У 2000-х роках із розвитком високонавантажених веб-платформ сформувалися ще дві практичні парадигми:

1. **Матеріалізований шлях із розширенням `ltree`:** у 2002 році Федір Сигаєв та Олег Бартунов розробили для СУБД PostgreSQL тип даних `ltree`, оптимізований для збереження ієрархічних шляхів у вигляді міток із крапками (`Top.Science.Astronomy`). Завдяки спеціалізованим GiST-індексам префіксний пошук та пошук за регулярними виразами над шляхами досягли швидкості B-дерев при збереженні легкості переміщення гілок.
2. **Таблиця замикання (Closure Table):** у 2010 році Білл Карвін (Bill Karwin) у книзі «SQL Antipatterns» систематизував патерн винесення транзитивного замикання у спеціалізовану таблицю-міст `(ancestor_id, descendant_id, depth)`. Цей підхід став галузевим стандартом для систем, де потрібна максимальна швидкість довільних ієрархічних вибірок без блокувань основної таблиці при вставці нових вузлів.

Еволюція ієрархічних структур у базах даних пройшла повне діалектичне коло: від фізичних вказівників ранніх СУБД 1960-х років через строгий математичний пуризм Кодда до сучасного синтезу рекурсивних табличних виразів, префіксних індексів та транзитивних таблиць замикання.
