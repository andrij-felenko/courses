# 🧮 Математичний аналіз колізій імовірнісних ID та похибки наближених лічильників

При проєктуванні систем генерації унікальних ідентифікаторів та обліку високоінтенсивних подій інженер стикається з двома суто ймовірнісними явищами: ризиком випадкового дублювання ключів у незв'язаних генераторах та дисперсією похибки при логарифмічному стисненні лічильників у пам'яті.

Інтуїтивне уявлення про те, що для колізії в просторі з `N` значень потрібно згенерувати близько `N/2` ключів, є грубою помилкою. Через комбінаторне зростання кількості можливих пар імовірність зіткнення зростає квадратично, що робить точний математичний розрахунок критично важливим для забезпечення цілісності розподілених баз даних.

Нижче наведено строгі математичні виведення меж колізій, аналіз пікового навантаження за розподілом Пуассона та доведення незміщеності імовірнісного лічильника Морріса разом із границями похибки за нерівністю Чебишова.

### 1. Парадокс днів народження та межі колізій у просторі ID

Нехай `N` — загальна кількість можливих станів простору ідентифікатора, а `k` — кількість згенерованих ключів за фіксований проміжок часу. Припускається, що генератор псевдовипадкових чисел генерує значення з рівномірним дискретним розподілом.

Ймовірність того, що всі `k` згенерованих ідентифікаторів виявляться суворо унікальними (подія без колізій), дорівнює добутку умовних ймовірностей для кожного наступного згенерованого значення:

```
P(без колізій)
= 1 · (1 - 1/N) · (1 - 2/N) · ... · (1 - (k - 1)/N)    [теорема множення ймовірностей]
= ∏_{i=1}^{k-1} (1 - i/N)                              [згортка послідовності у добуток]
```

Для значень `i ≪ N` застосуємо розклад експоненціальної функції в ряд Тейлора: `e^(-x) = 1 - x + x²/2 - ... ≈ 1 - x`:

```
∏_{i=1}^{k-1} (1 - i/N)
≈ ∏_{i=1}^{k-1} e^(-i / N)                             [наближення Тейлора: 1 - x ≈ e^(-x)]
= e^(- (1/N) · ∑_{i=1}^{k-1} i)                        [властивість степенів добутку]
= e^(- (k(k - 1)) / (2N))                              [сума арифметичної прогресії: k(k-1)/2]
```

Отже, загальна ймовірність виникнення щонайменше однієї колізії `P(колізія) = 1 - P(без колізій)` виражається замкненою формулою:

```
P(колізія)
= 1 - e^(- k² / (2N))                                  [для великих k: k(k-1) ≈ k²]
≈ k² / (2N)                                            [при малих ймовірностях: 1 - e^(-x) ≈ x]
```

#### Розрахунок граничної кількості операцій

Знайдемо критичну кількість згенерованих ключів `k`, при якій ймовірність колізії досягає заданого порогу `p`:

```
p = 1 - e^(- k² / (2N))                                [вихідне рівняння ймовірності]
⇒ e^(- k² / (2N)) = 1 - p                              [ізоляція експоненти]
⇒ - k² / (2N) = ln(1 - p)                              [логарифмування обох частин]
⇒ k² = - 2N · ln(1 - p)                                [множення на -2N]
⇒ k = √(2N · ln(1 / (1 - p)))                          [вилучення кореня: -ln(1-p) = ln(1/(1-p))]
```

Застосуємо цю формулу до різних форматів ідентифікаторів:

**1. Випадковий UUIDv4 (122 біти ентропії, `N = 2¹²² ≈ 5.3169 · 10³⁶`):**
Щоб отримати ймовірність колізії `p = 10⁻⁹` (один шанс на мільярд):
```
k = √(2 · 2¹²² · ln(1 / (1 - 10⁻⁹)))                   [підстановка параметрів N та p]
≈ √(2 · 5.3169 · 10³⁶ · 10⁻⁹)                          [наближення: ln(1 / (1 - 10⁻⁹)) ≈ 10⁻⁹]
≈ √(1.0633 · 10²⁸)                                     [перемноження констант під коренем]
≈ 3.26 · 10¹³ ідентифікаторів                          [обчислення квадратного кореня]
```
Висновок: системі потрібно згенерувати понад 32 трильйони UUIDv4, щоб отримати ризик виникнення бодай однієї колізії в `10⁻⁹`.

**2. UUIDv7 у межах однієї мілісекунди (74 біти ентропії, `N = 2⁷⁴ ≈ 1.8889 · 10²²`):**
Для `p = 10⁻⁹` в межах тієї самої мілісекунди:
```
k = √(2 · 2⁷⁴ · 10⁻⁹)                                  [підстановка 74 бітів ентропії]
≈ √(2 · 1.8889 · 10²² · 10⁻⁹)                          [множення на ймовірність колізії]
≈ √(3.7778 · 10¹³)                                     [обчислення підкореневого виразу]
≈ 6.14 · 10⁶ ідентифікаторів на мілісекунду            [обчислення квадратного кореня]
```
Висновок: повністю децентралізований кластер може безпечно генерувати понад 6 мільйонів UUIDv7 за одну мілісекунду (понад 6 мільярдів ID на секунду) із ризиком колізії менше `10⁻⁹`.

### 2. Ймовірність переповнення мілісекундного лічильника Snowflake (Пуассонівський сплеск)

У схемі Twitter Snowflake локальний лічильник обмежений 12 бітами (`M = 4095` значень на мілісекунду). Якщо вхідний потік запитів на один генератор підпорядковується пуассонівському процесу з середньою інтенсивністю `λ` запитів за мілісекунду, ймовірність того, що за одну мілісекунду надійде рівно `m` запитів, описується формулою Пуассона:

```
P(K = m) = (λᵐ · e^(-λ)) / m!                          [розподіл Пуассона]
```

Ймовірність переповнення лічильника `P(K > M)`, яка змушує генератор блокувати робочий потік до настання наступної мілісекунди (Spin-wait очікування таймера), становить:

```
P(K > M) = 1 - ∑_{m=0}^{M} ((λᵐ · e^(-λ)) / m!)        [доповнення до суми ймовірностей]
```

Якщо середнє навантаження на ноду становить `λ = 1000` запитів/мс, застосуємо нормальне наближення розподілу Пуассона `N(μ = λ, σ² = λ)`:

```
Z = (M - λ) / √λ                                       [стандартизація випадкової величини]
= (4095 - 1000) / √1000                                [підстановка значень M = 4095, λ = 1000]
= 3095 / 31.6227                                       [обчислення знаменника: √1000 ≈ 31.6227]
≈ 97.87                                                [ділення: Z-оцінка перевищення]
```

Ймовірність перевищення 97 стандартних відхилень у гауссовому розподілі прямує до нуля (`P < 10⁻¹⁰⁰`), що математично доводить абсолютну стійкість 12-бітного лічильника до випадкових флуктуацій пуассонівського трафіку при середньому завантаженні до 1000 req/ms.

### 3. Математичний аналіз імовірнісного лічильника Морріса (Approximate Counting)

Імовірнісний лічильник Роберта Морріса (Robert Morris, 1978) дозволяє підраховувати до `n` подій у пам'яті обсягом лише `log₂(log₂(n))` бітів. Замість точного збереження значення `n`, у 8-бітному регістрі зберігається логарифмічний показник `v`.

#### Алгоритм
1. Початковий стан: `v = 0`.
2. При надходженні кожної нової події згенерувати випадкове число `r ∈ [0, 1)`.
3. Якщо `r < 2^(-v)`, виконати `v = v + 1`. Інакше `v` залишається без змін.
4. Оцінка реальної кількості подій: `n̂ = 2ᵛ - 1`.

#### Доведення математичного сподівання (Unbiased Expectation)

Доведемо методом математичної індукції, що після `n` подій математичне сподівання оцінки `E[2^(v_n) - 1] = n`.

**База індукції (`n = 0`):**
```
v₀ = 0                                                 [початковий стан лічильника]
E[2⁰ - 1] = 1 - 1 = 0                                  [обчислення бази]
```

**Крок індукції (`n → n + 1`):**
Нехай після `n` кроків стан лічильника дорівнює `v_n`. З ймовірністю `2^(-v_n)` значення стане `v_n + 1`, а з ймовірністю `1 - 2^(-v_n)` залишиться `v_n`.

Обчислимо умовне математичне сподівання величини `2^(v_{n+1})`:

```
E[2^(v_{n+1}) | v_n]
= 2^(v_n + 1) · 2^(-v_n) + 2^(v_n) · (1 - 2^(-v_n))    [визначення сподівання: ∑ x_i · p_i]
= 2 · 2^(v_n) · 2^(-v_n) + 2^(v_n) - 2^(v_n) · 2^(-v_n) [розкриття дужок]
= 2 · 1 + 2^(v_n) - 1                                  [скорочення: 2^v · 2^(-v) = 1]
= 2^(v_n) + 1                                          [арифметика: 2 - 1 = 1]
```

Застосовуючи закон повного математичного сподівання:

```
E[2^(v_{n+1}) - 1]
= E[ E[2^(v_{n+1}) | v_n] ] - 1                        [закон повного сподівання]
= E[ 2^(v_n) + 1 ] - 1                                 [підстановка умовного сподівання]
= E[ 2^(v_n) - 1 ] + 1                                 [лінійність математичного сподівання]
= n + 1                                                [за припущенням індукції: E[2^v_n - 1] = n]
```

Твердження доведено: оцінка лічильника Морріса є строго незміщеною для будь-якого значення `n`.

#### Дисперсія та відносна похибка (Relative Standard Error)

Аналогічно, обчислюючи сподівання квадрата величини `E[(2ᵛ)²]`, виводимо точну формулу дисперсії лічильника Морріса:

```
Var[n̂_n] = E[n̂_n²] - (E[n̂_n])²                        [визначення дисперсії]
= n(n - 1) / 2                                         [аналітичне виведення суми квадратів]
```

Стандартне відхилення оцінки `σ` та відносна стандартна похибка (RSE):

```
σ = √(n(n - 1) / 2) ≈ n / √2                           [стандартне відхилення для великих n]

RSE = σ / n                                            [визначення відносної стандартної похибки]
≈ (n / √2) / n                                         [підстановка наближеного значення σ]
= 1 / √2                                               [скорочення n]
≈ 0.7071 (70.7%)                                       [числове значення відносної похибки]
```

#### Межі відхилення за нерівністю Чебишова

Оцінимо ймовірність того, що відновлене значення `n̂` відхилиться від справжньої кількості подій `n` більш ніж на відносну похибку `ε`:

```
P(|n̂ - n| ≥ ε · n)
≤ Var[n̂] / (ε² · n²)                                  [нерівність Чебишова: P(|X-μ|≥k) ≤ Var/k²]
= (n(n - 1) / 2) / (ε² · n²)                           [підстановка точної дисперсії Var[n̂]]
≈ 1 / (2 · ε²)                                         [спрощення для великих значень n]
```

Для гарантування відхилення не більше ніж на `ε = 50%` з імовірністю 90% достатньо агрегувати середнє значення по кількох паралельних лічильниках Морріса.

#### Порівняння з дисперсією алгоритму HyperLogLog

На відміну від лічильника Морріса, де відносна похибка залишається постійною (~70% для базової моделі), алгоритм HyperLogLog підраховує кількість унікальних елементів через розподіл нулів у префіксах хеш-значень.

Відносна стандартна похибка HyperLogLog залежить виключно від кількості регістрів `m`:

```
RSE_{HLL} ≈ 1.04 / √m
```

При виділенні 1024 регістрів (1 КБ оперативної пам'яті):
```
RSE_{HLL} ≈ 1.04 / √1024 = 1.04 / 32 ≈ 0.0325 (3.25%)
```

Це демонструє чітке розділення задач: лічильник Морріса призначений для логарифмічного підрахунку повторюваних потокових подій (загальної кількості пакетів чи переходів), тоді як HyperLogLog оптимізований для оцінки потужності множин (унікальних ідентифікаторів) з високою точністю.

#### Узагальнений лічильник Морріса з масштабним коефіцієнтом `a`

Для зниження відносної похибки базовий алгоритм модифікують правилом переходу з імовірністю `p = a^(-v)` (де `a > 1`, наприклад `a = 2^(1/2) = √2 ≈ 1.414` або `a = 1.08`):

```
n̂ = (aᵛ - 1) / (a - 1)                                 [узагальнена формула відновлення числа]

Var[n̂] = ((a - 1) / 2) · n(n - 1)                      [дисперсія узагальненого лічильника]

RSE ≈ √((a - 1) / 2)                                   [відносна похибка через коефіцієнт a]
```

При виборі коефіцієнта `a = 1.08`:
```
RSE ≈ √((1.08 - 1) / 2)                                [підстановка a = 1.08]
= √(0.08 / 2)                                          [обчислення чисельника: 1.08 - 1 = 0.08]
= √0.04                                                [ділення: 0.08 / 2 = 0.04]
= 0.20 (20%)                                           [добування квадратного кореня]
```

Цей результат демонструє фундаментальний інженерний компроміс: зменшуючи крок зростання `a`, ми знижуємо похибку вимірювання до прийнятних 20%, зберігаючи здатність підраховувати десятки мільйонів подій у компактному 8-бітному регістрі.
