# 🧮 Математичний аналіз висоти та заповнення B-дерева

Ця вставка надає строге математичне виведення меж висоти, мінімальної та максимальної місткості ключів, коефіцієнта заповнення вузлів і кількості дискових операцій вводу-виводу для B-дерева мінімального ступеня `t ≥ 2` (або порядку `m = 2t`). Розрахунки доводять, що B-дерево забезпечує суворо логарифмічну висоту навіть при катастрофічно несприятливих послідовностях вставок.

## Початкові інваріанти та параметри розгалуження

Для побудови математичної моделі B-дерева введемо формальне поняття мінімального ступеня `t ≥ 2`. Параметр `t` задає нижню межу кількості дочірніх вказівників для кожного внутрішнього вузла, крім кореня. На основі цього параметра формулюються фундаментальні інваріанти, які зберігаються після виконання будь-якої модифікуючої операції:

- **Інваріант 1 (Кількість ключів у вузлах)**: Кожен вузол, крім кореня, містить щонайменше `t - 1` ключів і щонайбільше `2t - 1` ключів. Внутрішній вузол, який містить `k` ключів, завжди має строго `k + 1` дочірніх вказівників.
- **Інваріант 2 (Корінь дерева)**: Якщо дерево не порожнє, корінь містить щонайменше 1 ключ. Якщо корінь є внутрішнім вузлом (тобто дерево має висоту `h ≥ 1`), він має щонайменше 2 дочірні вказівники. Максимальна кількість ключів у корені така сама, як і в інших вузлах — `2t - 1`.
- **Інваріант 3 (Ідеальне балансування за висотою)**: Усі листки знаходяться на однаковій глибині `h`. Глибина визначається як довжина шляху (кількість ребер) від кореневого вузла до будь-якого листка. Дерево, що складається лише з кореневого листка, має висоту `h = 0`.
- **Інваріант 4 (Упорядкованість та розгалуження)**: Ключі всередині кожного вузла `x` відсортовані у строго зростаючому порядку: `key[1] < key[2] < ... < key[n]`. Для будь-якого ключа `k`, збереженого у піддереві з коренем у `child[i]`, виконується нерівність `key[i-1] < k < key[i]` (де крайні межі формально поширюються на мінус та плюс нескінченність).

Позначимо через `N` загальну кількість ключів, збережених у B-дереві висоти `h`. Знайдемо точний зв'язок між `N`, `t` та `h`.

## Виведення верхньої межі висоти у найгіршому випадку

Найгірший випадок з точки зору висоти настає тоді, коли B-дерево висоти `h` містить мінімально можливу кількість ключів `N_min`. У такому стані кожен вузол заповнений на абсолютизованому мінімумі: корінь містить строго 1 ключ, а кожен інший вузол містить строго `t - 1` ключів.

Проведемо покроковий підрахунок мінімальної кількості вузлів та ключів на кожному рівні дерева від кореня (`i = 0`) до листків (`i = h`):

1. На рівні `i = 0` (корінь) розташований строго 1 вузол, який містить мінімум `1` ключ.
2. На рівні `i = 1` корінь має щонайменше 2 дочірні вказівники, отже на першому рівні розміщено щонайменше `2` вузли. Кожен з цих вузлів містить мінімум `t - 1` ключів, що дає сумарно `2 · (t - 1)` ключів на даному рівні.
3. На рівні `i = 2` кожен з 2 вузлів першого рівня має щонайменше `t` дочірніх вказівників. Отже, на другому рівні розташовано щонайменше `2 · t` вузлів. Загальна кількість ключів на рівні 2 становить `2 · t · (t - 1)`.
4. За індукцією, для довільного рівня `i` (де `1 ≤ i ≤ h`) кількість вузлів становить щонайменше `2 · t^(i-1)`, а кількість ключів на цьому рівні є добутком кількості вузлів на мінімальне число ключів у вузлі: `2 · t^(i-1) · (t - 1)`.

Обчислимо загальну мінімальну кількість ключів `N`, підсумувавши значення по всіх рівнях від `i = 0` до `i = h`:

```
N
≥ 1 + ∑_{i=1}^{h} (2 · t^(i-1) · (t - 1))     [підсумовування ключів по всіх рівнях]
= 1 + 2 · (t - 1) · ∑_{i=1}^{h} t^(i-1)      [винесення константи (t - 1) за знак суми]
= 1 + 2 · (t - 1) · ((t^h - 1) / (t - 1))    [застосування формули суми геометричної прогресії]
= 1 + 2 · (t^h - 1)                          [скорочення співмножника (t - 1)]
= 2 · t^h - 1                                [остаточна виражена мінімальна місткість]
```

Тепер виразимо висоту `h` через кількість ключів `N`. Для цього проведемо послідовні алгебраїчні перетворення отриманої нерівності:

```
N ≥ 2 · t^h - 1
⇒ N + 1 ≥ 2 · t^h                   [додавання одиниці до обох частин нерівності]
⇒ (N + 1) / 2 ≥ t^h                 [ділення обох частин на 2]
⇒ log_t ((N + 1) / 2) ≥ h           [логарифмування за основою t]
⇒ h ≤ log_t ((N + 1) / 2)           [остаточна верхня межа висоти]
```

Отже, висота B-дерева мінімального ступеня `t` з `N` ключами строго обмежена зверху математичним виразом:
`h ≤ ⌊log_t ((N + 1) / 2)⌋`.

Цей фундаментальний результат доводить, що навіть якщо всі вузли заповнені лише наполовину, висота B-дерева зростає строго логарифмічно з основою `t`. Оскільки параметр `t` у реальних дискових системах обирають великим (наприклад, `t = 128` або `t = 256`), основа логарифма робить висоту дерева вражаюче малою.

## Виведення нижньої межі висоти у найкращому випадку

Найкращий випадок з точки зору висоти (найменша можлива глибина для збереження `N` ключів) досягається тоді, коли кожен вузол B-дерева заповнений максимально, тобто містить `2t - 1` ключів та має `2t` дочірніх вказівників.

Обчислимо максимальну кількість ключів `N_max` у B-дереві висоти `h`:

1. На рівні `i = 0` розташований 1 вузол, який містить `2t - 1` ключів.
2. На рівні `i = 1` розміщено `2t` вузлів, кожен містить `2t - 1` ключів, що дає `2t · (2t - 1)` ключів.
3. На рівні `i = 2` розташовано `(2t)²` вузлів, які містять `(2t)² · (2t - 1)` ключів.
4. На довільному рівні `i` розміщено `(2t)^i` вузлів з сумарною кількістю ключів `(2t)^i · (2t - 1)`.

Просумуємо ключі по всіх рівнях від `i = 0` до `i = h`:

```
N_max
= ∑_{i=0}^{h} ((2t)^i · (2t - 1))            [сума ключів по всіх рівнях дерева]
= (2t - 1) · ∑_{i=0}^{h} (2t)^i               [винесення спільного множника (2t - 1)]
= (2t - 1) · (((2t)^(h+1) - 1) / (2t - 1))   [формула суми геометричної прогресії для основи 2t]
= (2t)^(h+1) - 1                             [скорочення множника (2t - 1)]
```

Виразимо нижню межу висоти `h_min` через `N`:

```
N ≤ (2t)^(h+1) - 1
⇒ N + 1 ≤ (2t)^(h+1)                [додавання одиниці]
⇒ log_{2t} (N + 1) ≤ h + 1          [логарифмування за основою 2t]
⇒ h ≥ log_{2t} (N + 1) - 1          [нижня межа висоти]
```

Поєднуючи обидві межі, отримуємо строгий теорематичний інтервал для висоти B-дерева довільної конфігурації:

`⌈log_{2t} (N + 1)⌉ - 1 ≤ h ≤ ⌊log_t ((N + 1) / 2)⌋`.

## Числовий розрахунок для дискової сторінки 4 КБ та 1 мільярда ключів

Щоб оцінити практичне значення математичних меж, виконаємо розрахунок для реальних параметрів баз даних та файлових систем. Припустимо, що ми будуємо індекс для `N = 1 000 000 000` (1 мільярд) записів. Розмір дискової сторінки становить `PAGE_SIZE = 4096` байтів (4 КБ).

Нехай кожен ключ має розмір 8 байтів (64-бітне ціле число), а кожен дисковий вказівник на дочірню сторінку займає 8 байтів.

Визначимо максимальний ступінь `2t` та мінімальний ступінь `t`:
- Вузол B-дерева з `k` ключами містить `k` ключів та `k + 1` вказівників.
- Загальний обсяг вузла у байтах для `2t - 1` ключів становить:
  `Size = (2t - 1) · 8 + (2t) · 8 = 16t - 8 + 16t = 32t - 8` байтів.
- З урахуванням службового заголовка сторінки (наприклад, 64 байти на прапори, LSN та лічильники) на ключі та вказівники залишається `4096 - 64 = 4032` байти.
- Складаємо нерівність: `32t - 8 ≤ 4032 ⇒ 32t ≤ 4040 ⇒ t ≤ 126.25`.
- Приймаємо `t = 126`. Відповідно, максимальна кількість ключів у вузлі становить `2t - 1 = 251`, а максимальна кількість дочірніх вказівників — `2t = 252`.

Обчислимо граничні значення висоти `h` для `N = 10⁹` та `t = 126`:

1. **Найкращий випадок (вузли заповнені на 100%)**:
```
h_min
= log₂₅₂ (10⁹ + 1) - 1
= (log₁₀ (10⁹) / log₁₀ (252)) - 1     [перехід до десяткового логарифма]
= (9.0 / 2.4014) - 1
= 3.747 - 1
= 2.747
```
Це означає, що при повному заповненні сторінок висота дерева становить строго `h = 3` (корінь, один внутрішній рівень та рівень листків).

2. **Найгірший випадок (вузли заповнені на 50%)**:
```
h_max
= log₁₂₆ ((10⁹ + 1) / 2)
= log₁₂₆ (500 000 000)
= log₁₀ (500 000 000) / log₁₀ (126)   [перехід до десяткового логарифма]
= 8.69897 / 2.10037
= 4.141
```
У найгіршому випадку висота дерева становить строго `h = 4` рівні.

Порівняємо цей результат із бінарним збалансованим деревом пошуку (наприклад, АВЛ-деревом), збереженим на диску. Для `N = 10⁹` записів висота АВЛ-дерева обчислюється як:
`h_AVL ≈ 1.44 · log₂ (10⁹) ≈ 1.44 · 29.897 ≈ 43` рівні.

Якщо кожен вузол АВЛ-дерева розташований у окремому дисковому блоці, пошук запису вимагатиме до 43 дискових операцій вводу-виводу (I/O). У випадку B-дерева з розміром сторінки 4 КБ той самий пошук вимагає не більше 4 дискових I/O.

Коефіцієнт скорочення кількості звернень до диска обчислюється як:
`Ratio = h_AVL / h_BTree = 43 / 4 ≈ 10.75` разів.

З урахуванням того, що кожне фізичне читання з твердотільного накопичувача (SSD) займає близько 20–50 мікросекунд, а з механічного диска (HDD) — 10 мілісекунд, скорочення кількості I/O у 10.75 разів зменшує загальний час виконання запиту з 430 мілісекунд до 40 мілісекунд на HDD і з 1.5 мілісекунди до 120 мікросекунд на SSD.

## Математичний аналіз інваріантів вилучення: Запозичення та Злиття

При вилученні ключа з B-дерева вимагається дотримання інваріанту: жоден вузол (крім кореня) не повинен мати менше `t - 1` ключів. Якщо після вилучення вузол досягає критичного стану з `t - 2` ключами (дефіцит вузла), структура балансується одним із двох математичних механізмів: запозиченням (перерозподілом) або злиттям.

Проаналізуємо математичну коректність двох сценаріїв:

1. **Сценарій А: Запозичення у сусіднього вузла (Обертання)**:
   - Умова застосування: Один із безпосередніх сусідів (лівий або правий) містить `n_sibling ≥ t` ключів.
   - Механізм: Ключ із батьківського вузла переміщується у дефіцитний вузол, а один із ключів сусіда (крайній правий для лівого сусіда або крайній лівий для правого) піднімається на місце батьківського ключа.
   - Підрахунок ключів після операції:
     - Дефіцитний вузол отримує 1 ключ: `(t - 2) + 1 = t - 1` ключів. Вузол відновлює мінімальний інваріант.
     - Сусідній вузол віддає 1 ключ: `n_sibling - 1 ≥ t - 1` ключів. Сусідній вузол залишається коректним.
     - Кількість ключів у батьківському вузлі залишається незмінною (`n_parent`).
   - Результат: Висота дерева не змінюється, операція завершується локально за `O(1)` операцій I/O.

2. **Сценарій Б: Злиття двох вузлів (Merge)**:
   - Умова застосування: Обидва суміжні сусідні вузли містять строго мінімальну кількість ключів: `n_sibling = t - 1`.
   - Механізм: Дефіцитний вузол (`t - 2` ключів), сусідній вузол (`t - 1` ключів) та роздільний ключ із батьківського вузла (1 ключ) об'єднуються в один новий вузол.
   - Доведення коректності обсягу об'єднаного вузла `n_merged`:
     ```
     n_merged
     = (t - 2) + (t - 1) + 1             [сума ключів трьох компонентів]
     = t - 2 + t - 1 + 1
     = 2t - 2                            [точно підходить під межу max (2t - 1)]
     ```
   - Зауважимо, що `2t - 2 ≤ 2t - 1`. Отже, об'єднаний вузол є повністю коректним вузлом B-дерева і не потребує подальшого розщеплення!
   - Наслідок для батьківського вузла: З батьківського вузла вилучається 1 ключ. Якщо батьківський вузол мав `t - 1` ключів, він у свою чергу стає дефіцитним. Процес злиття поширюється вгору до кореня.
   - Крайовий випадок (Зменшення висоти дерева): Якщо корінь містив строго 1 ключ і відбулося злиття двох його єдиних дочірніх вузлів, корінь стає порожнім (`0` ключів). Об'єднаний вузол стає новим коренем B-дерева, і висота дерева `h` зменшується строго на 1. Це **єдиний** спосіб, у який B-дерево зменшує свою висоту.

## Послідовна вставка ключів та асиметрія заповнення

Особливий практичний інтерес становить математичний аналіз поведінки B-дерева при вставці строго монотонно зростаючої послідовності ключів (наприклад, первинні ключі `AUTO_INCREMENT` у реляційних базах даних або часові мітки `TIMESTAMP`).

При монотонній вставці нові ключі завжди потрапляють у найправіший листок B-дерева. Проаналізуємо процес розщеплення найправішого вузла:

1. Найправіший вузол стає переповненим, досягаючи `2t - 1` ключів.
2. Виконується розщеплення: лівий новий вузол отримує перші `t - 1` ключів, медіанний ключ `t` піднімається до батьківського вузла, а правий новий вузол отримує решту `t - 1` ключів.
3. Усі наступні вставлені ключі будуть більшими за медіану, тому вони потраплятимуть виключно у правий новий вузол.
4. Лівий новий вузол більше ніколи не отримає жодного нового ключа. Він назавжди залишається заповненим строго на `t - 1` ключів (тобто на 50%).

Доведемо, що середня щільність заповнення B-дерева при стандартній послідовній вставці наближається до 50%:

```
U_sequential
= (t - 1) / (2t - 1)
≈ 50%                                [при t → ∞]
```

Саме тому сучасні СУБД (зокрема PostgreSQL та InnoDB) реалізують спеціальну оптимізацію правого розщеплення (англ. *right-leaning split* або *sequential insertion optimization*): якщо СУБД виявляє послідовну вставку у крайній правий листок, медіана обирається не посередині, а на крайній правій позиції. У результаті лівий вузол залишається заповненим на 100% (`2t - 1` ключів), а правий вузол створюється порожнім. Це підвищує щільність заповнення індексу при послідовній вставці з 50% до майже 100%.

## Амортизаційний аналіз операцій розщеплення (Метод потенціалів)

Коли при вставці ключа B-дерево натрапляє на переповнений вузол з `2t - 1` ключами, виконується операція розщеплення (англ. *split*). Вузол ділиться на два нових вузли по `t - 1` ключів у кожному, а медіанний ключ піднімається до батьківського вузла. У найгіршому випадку розщеплення може поширюватися рекурсивно від листка до кореня, виконуючи `h` розщеплень за одну вставку.

Доведемо за допомогою **методу потенціалів** (англ. *potential method*), що амортизована вартість операції розщеплення становить `O(1)`.

Визначимо потенціал `Φ(T)` B-дерева `T` як кількість переповнених вузлів (вузлів, що містять строго `2t - 1` ключів):

`Φ(T) = c · (кількість вузлів з 2t - 1 ключами)`, де `c` — позитивна константа, що відповідає вартості розщеплення одного вузла.

Проаналізуємо зміну потенціалу `ΔΦ = Φ(T') - Φ(T)` при виконанні розщеплення одного переповненого вузла:
1. До розщеплення вузол був переповнений (`2t - 1` ключів), отже він робив внесок `c` у загальний потенціал.
2. Після розщеплення утворюються два нових вузли, кожен з яких містить `t - 1` ключів. Оскільки `t - 1 < 2t - 1`, жоден із цих двох нових вузлів не є переповненим. Їхній внесок у потенціал дорівнює 0.
3. Медіанний ключ піднімається до батьківського вузла. Якщо батьківський вузол до цього не був переповнений, він може стати переповненим, що збільшує потенціал максимум на `c`.
4. Таким чином, при одному каскадному розщепленні зникнення переповненого вузла зменшує потенціал на `c`. Зміна потенціалу становить `ΔΦ = -c` (або `ΔΦ = 0` для останньої ланки ланцюжка).

Нехай за одну вставку відбулося `k` каскадних розщеплень. Реальна вартість операції становить `C_real = k · c + O(1)`.

Обчислимо амортизовану вартість `C_amortized`:

```
C_amortized
= C_real + ΔΦ                        [означення амортизованої вартості]
= (k · c + O(1)) + (Φ(T') - Φ(T))
```

Оскільки кожне з перших `k - 1` розщеплень знищує один переповнений вузол і створює новий переповнений вузол рівнем вище, загальна зміна потенціалу для `k` розщеплень дорівнює:
`ΔΦ ≤ -k · c + c`.

Підставляємо значення у формулу амортизованої вартості:

```
C_amortized
≤ (k · c + O(1)) + (-k · c + c)
= c + O(1)
= O(1)                               [стала амортизована складність]
```

Це доводить важливу фундаментальну властивість: хоча окрема вставка може вимагати `O(h)` розщеплень у найгіршому випадку, середня амортизована кількість розщеплень на одну вставку у послідовності з `M` операцій не перевищує `O(1)`.

## Особливості B* дерева та коефіцієнт заповнення 66.7%

Модифікація **B* дерево** (англ. *B*-tree*), запропонована Дональдом Кнутом, підвищує мінімальний інваріант заповнення вузлів з 50% до 66.7% (`2/3`). Це досягається зміною механізму обробки переповнень: замість негайного розщеплення вузла при досягненні `2t - 1` ключів, B* дерево намагається перерозподілити (запозичити) ключі з суміжним сусіднім вузлом.

Якщо сусідній вузол також заповнений, виконується **подвійне розщеплення**: два переповнені вузли об'єднуються з новим елементом і розщеплюються на три нові вузли, кожен з яких виявляється заповненим строго на `2/3`.

Порівняємо математичні показники B-дерева та B* дерева:

| Параметр | Стандартне B-дерево | Модифікація B* дерево |
| :--- | :--- | :--- |
| **Мінімальне заповнення вузла** | `⌈m/2⌉ - 1 ≈ 50%` | `⌈(2m - 1)/3⌉ ≈ 66.7%` |
| **Середній коефіцієнт заповнення** | `ln(2) ≈ 69.3%` | `2 · ln(1.5) ≈ 81.1%` |
| **Верхня межа висоти h_max** | `log_{m/2} (N)` | `log_{2m/3} (N)` |
| **Складність розщеплення** | 1 вузол → 2 вузли | 2 вузли → 3 вузли |

Підвищення середнього заповнення з 69.3% до 81.1% дозволяє скоротити загальний обсяг дискової пам'яті, необхідної для збереження того самого індексу, приблизно на 15%, а також пропорційно зменшити висоту дерева для граничних випадків.
