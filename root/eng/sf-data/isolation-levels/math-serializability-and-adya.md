# 🧮 Графи серіалізовності та формалізація ізоляції Адьї

Щоб однозначно довести, чи є довільний паралельний розклад виконання транзакцій коректним, інтуїтивних словесних описів недостатньо: потрібен строгий математичний апарат теорії графів. Теорія серіалізовності формалізує виконання транзакцій як послідовність атомарних операцій над спільним простором об'єктів і зводить перевірку узгодженості системи до задачі пошуку спрямованих циклів у графі залежностей.

Фундаментальний прорив у цій галузі здійснив дослідник Массачусетського технологічного інституту (MIT) Атул Адья у своїй докторській дисертації 1999 року під керівництвом Барбари Лісков. Адья побудував універсальну теорію узагальненої ізоляції, яка математично точно класифікує будь-які рівні узгодженості через типи ребер у графі прямої серіалізації (*Direct Serialization Graph, DSG*) незалежно від того, як саме СУБД керує паралелізмом — через блокування, мітки часу чи багатоверсійність (MVCC).

## Формальна модель транзакційного розкладу

Нехай дано скінченну множину транзакцій `T = {T₁, T₂, ..., Tₙ}`. Кожна транзакція `Tᵢ` є частково впорядкованою послідовністю базових операцій над іменованими елементами даних `x, y, z ∈ D`:

- `rᵢ[x]` — транзакція `Tᵢ` читає значення об'єкта `x`.
- `wᵢ[x]` — транзакція `Tᵢ` записує нове значення об'єкта `x`.
- `cᵢ` — транзакція `Tᵢ` успішно фіксується (`COMMIT`).
- `aᵢ` — транзакція `Tᵢ` скасовується (`ABORT`).

**Розкладом (історією виконання) `S`** над множиною транзакцій `T` називається частковий порядок операцій, який зберігає внутрішній порядок операцій усередині кожної окремої транзакції `Tᵢ`:

```
∀ Tᵢ ∈ T, ∀ o₁, o₂ ∈ Tᵢ : (o₁ <_Tᵢ o₂) ⇒ (o₁ <_S o₂)
```

Дві операції `oᵢ, oⱼ ∈ S` називаються **конфліктними (*Conflicting Operations*)**, якщо вони задовольняють три обов'язкові умови:
1. Вони належать різним транзакціям (`i ≠ j`).
2. Вони звертаються до одного й того самого елемента даних (`x`).
3. Щонайменше одна з цих двох операцій є записом (`w`).

Існує три типи парних конфліктів операцій:
- **Запис після запису (Write-Write / ww)**: `wᵢ[x]` та `wⱼ[x]`.
- **Читання після запису (Write-Read / wr)**: `wᵢ[x]` та `rⱼ[x]` (прямий потік даних від `Tᵢ` до `Tⱼ`).
- **Запис після читання (Read-Write / rw)**: `rᵢ[x]` та `wⱼ[x]` (антизалежність: `Tᵢ` прочитала версію `x`, яку згодом затерла або замінила `Tⱼ`).

## Граф прямої серіалізації (DSG)

Для будь-якого зафіксованого розкладу `S` будується спрямований граф прямої серіалізації `DSG(S) = (V, E)`:

- **Множина вершин `V`**: усі успішно зафіксовані транзакції `Tᵢ ∈ T` (для яких `cᵢ ∈ S`).
- **Множина ребер `E`**: спрямовані дуги трьох типів між транзакціями `Tᵢ → Tⱼ`:

1. **Ребро прямої залежності за записом (`Tᵢ ──ww──> Tⱼ`)**:
   Існує елемент `x`, такий що `wᵢ[x] <_S wⱼ[x]`, і між ними немає іншого запису `wₖ[x]`.

2. **Ребро прямої залежності за читанням (`Tᵢ ──wr──> Tⱼ`)**:
   Існує елемент `x`, такий що `Tⱼ` читає значення `x`, записане саме транзакцією `Tᵢ` (`wᵢ[x] <_S rⱼ[x]`).

3. **Ребро прямої антизалежності (`Tᵢ ──rw──> Tⱼ`)**:
   Існує елемент `x`, такий що `Tᵢ` читає версію `x`, попередню щодо версії, яку створює `Tⱼ` (`rᵢ[x] <_S wⱼ[x]`).

## Теорема про конфліктну серіалізовність (Conflict Serializability, CSR)

Розклад `S` називається конфліктно еквівалентним послідовному розкладу `S_serial`, якщо порядок виконання будь-якої пари конфліктних операцій у `S` і `S_serial` збігається.

**Класична теорема серіалізовності:**
Розклад `S` є конфліктно серіалізовним тоді й лише тоді, коли його граф серіалізації `DSG(S)` не містить спрямованих циклів:

```
S ∈ CSR  ⟺  Acyclic(DSG(S))
```

Доведення випливає з топологічного сортування: якщо `DSG(S)` є ациклічним орієнтованим графом (DAG), його вершини можна впорядкувати в лінійну послідовність `T_π(1), T_π(2), ..., T_π(n)`. Будь-яка пара конфліктних операцій виконуватиметься в точному порядку номерів топологічної черги, що еквівалентно послідовному запуску транзакцій по черзі.

## Формалізація рівнів ізоляції за Адьєю

Атул Адья узагальнив класифікацію рівнів ізоляції, виразивши відсутність феноменів через заборону певних типів циклів у графі `DSG`:

### Феномен G0 (Брудний запис / Dirty Write)
Граф залежностей містить спрямований цикл, складений виключно з `ww`-ребер:
```
Cycle_ww: T₁ ──ww──> T₂ ──ww──> ... ──ww──> T₁
```
Рівень **PL-1** (Portable Level 1) гарантує відсутність циклів `G0`. Усі транзакції впорядковані за монопольними записами.

### Феномен G1 (Брудне читання / Dirty Read)
Виникає, коли транзакція `Tⱼ` читає проміжний або скасований стан від `Tᵢ`. У термінах DSG це відповідає наявності циклів, що містять `wr`-ребра з незафіксованими транзакціями, або розриву причинно-наслідкового порядку.
Рівень **PL-2** (еквівалент строгого `Read Committed`) забороняє феномени `G0` та `G1`.

### Феномен G2 (Антизалежні цикли / Anti-dependency Cycles)
Граф залежностей містить цикл, у якому присутнє щонайменше одне `rw`-ребро антизалежності:
```
Cycle_rw: T₁ ──rw──> T₂ ──(any)──> ... ──(any)──> T₁
```
Рівень **PL-3** (повна серіалізовність) вимагає повної ациклічності графа `DSG` за всіма типами ребер (`ww ∪ wr ∪ rw`).

## Знімкова ізоляція та теорема Фекете-Кехіла

Під знімковою ізоляцією (Snapshot Isolation, SI) рушій гарантує, що кожна транзакція читає дані з фіксованого знімка стану. Це автоматично забороняє цикли, складені лише з `ww`-ребер (через правило першого запису) та `wr`-ребер (через читання лише зафіксованих версій).

Проте під Snapshot Isolation можливі цикли, утворені ребрами антизалежності `rw`.

**Теорема Алана Фекете та Майкла Кехіла (2008):**
Будь-який несеріалізовний розклад під Snapshot Isolation містить у графі `DSG` підграф вигляду **небезпечної структури (*Dangerous Structure*)**:

```
T_in  ──rw──>  T_pivot  ──rw──>  T_out
```

де транзакція `T_pivot` має водночас:
1. Вхідне ребро антизалежності `T_in ──rw──> T_pivot` (прочитала версію, змінену `T_pivot`).
2. Вихідне ребро антизалежності `T_pivot ──rw──> T_out` (прочитала версію, змінену `T_out`).

При цьому транзакції `T_in` та `T_out` можуть бути однією й тією самою транзакцією (цикл довжини 2, як у випадку класичного Write Skew).

### Доведення достатності для рушіїв SSI

Якщо в графі `DSG` виникає цикл `T₁ → T₂ → ... → Tₖ → T₁`, то через властивості знімків часу фіксації в ньому не можуть бути лише ребра `ww` або `wr`. Отже, цикл зобов'язаний містити щонайменше два ребра антизалежності `rw`.

Оскільки кількість вершин у циклі скінченна, у будь-якому циклі з кількома `rw`-ребрами обов'язково знайдеться вершина, яка має вхідне `rw`-ребро та вихідний `rw`-шлях. У граничному випадку двох суміжних `rw`-ребер ця вершина стає транзакцією-півотом (`T_pivot`).

Цей математичний результат ліг в основу практичного алгоритму **Serializable Snapshot Isolation (SSI)**:
- Рушій відстежує легковагі мітки читання (`SIREAD` locks).
- Для кожної активної транзакції підтримуються два бітові прапорці: `inConflict` (є вхідне `rw`-ребро) та `outConflict` (є вихідне `rw`-ребро).
- Якщо обидва прапорці стають `true` (`inConflict ∧ outConflict = true`), транзакція ідентифікується як потенційний півот небезпечного циклу.
- СУБД негайно відкочує одну з конфліктних транзакцій з кодом помилки `40001` (`serialization_failure`), що гарантує математичну ациклічність `DSG` без застосування важких блокувань пам'яті.
