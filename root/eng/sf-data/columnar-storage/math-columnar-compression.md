# 🧮 Математичні основи стовпцевого стиснення та пропускної здатності шини

Стовпцеве зберігання даних базується на двох математичних і фізичних факторах: різкому зменшенні ентропії інформаційного потоку при розщепленні кортежів та мультиплікативному виграші пропускної здатності пам'яті (Memory Bandwidth Multiplier) при декомпресії в регістрах CPU.

---

## 1. Інформаційна ентропія Шеннона: Рядки проти стовпців

Кількість інформації, необхідна для збереження випадкової величини `X` з множиною можливих значень `S = {x₁, x₂, ..., x_n}` та розподілом ймовірностей `P(X = x_i) = p_i`, визначається **інформаційною ентропією Шеннона**:

```
H(X) = - ∑ [p_i · log₂(p_i)]
```

Розглянемо реляційну таблицю з `K` атрибутами (стовпцями) `A₁, A₂, ..., A_K`. Нехай кортеж `R` є складеною випадковою величиною `R = (A₁, A₂, ..., A_K)`.

### Ентропія рядкового потоку (NSM)
У рядковому розкладі рушій бази даних бачить послідовність суміжних байтів, що утворюють спільний розподіл кортежу. Спільна ентропія `H(A₁, A₂, ..., A_K)` обмежена сумою ентропій окремих полів:

```
H(A₁, A₂, ..., A_K) ≤ H(A₁) + H(A₂) + ... + H(A_K)
```

Оскільки сусідні байти в рядковому потоці належать атрибутам із принципово різною природою (наприклад, 64-бітне ціле число `ID`, текстовий рядок `Ім'я`, 32-бітне число з плаваючою комою `Сума` та 8-бітний прапорець `Статус`), байтовий потік має надзвичайно високу локальну ентропію:
- Імовірності появи різних байтів вирівнюються (`p_i ≈ 1/256`);
- Умовна ймовірність наступного байта за умови попереднього на межі полів прямує до випадкового розподілу:

```
P(Byte_{i+1} | Byte_i) ≈ P(Byte_{i+1})
```

Блочні алгоритми стиснення загального призначення (LZ4, ZSTD, Deflate), засновані на пошуку однакових повторюваних підрядків у ковзному вікні (Lempel-Ziv), стикаються з низькою щільністю повторень через вкраплення випадкових числових та плаваючих значень між текстовими рядками.

### Ентропія стовпцевого потоку (DSM)
При стовпцевому розкладі кожен атрибут `A_k` обробляється як ізольована послідовність однорідних значень однакового типу. 

1. **Низька потужність алфавіту (Small Cardinality):** Якщо стовпець `Статус` приймає лише 4 можливі значення `{"NEW", "PAID", "CANCELLED", "REFUND"}` з імовірностями `p₁ = 0.70`, `p₂ = 0.20`, `p₃ = 0.08`, `p₄ = 0.02`, то теоретична ентропія одного значення становить:

```
H(Статус) = - [0.70·log₂(0.70) + 0.20·log₂(0.20) + 0.08·log₂(0.08) + 0.02·log₂(0.02)]
          = - [0.70·(-0.5146) + 0.20·(-2.3219) + 0.08·(-3.6438) + 0.02·(-5.6438)]
          = - [-0.3602 - 0.4644 - 0.2915 - 0.1129]
          = 1.229 біта на значення
```

Замість збереження рядків завдовжки до 10 байтів (80 бітів), ентропійна межа дозволяє закодувати кожне значення всього у `1.23` біта, даючи теоретичний коефіцієнт стиснення:

```
CR = 80 / 1.229 ≈ 65.1  (зменшення обсягу в 65 разів)
```

2. **Впорядкованість та автокореляція:** Якщо стовпець відсортований за первинним ключем або часом, умовна ентропія сусідніх елементів прямує до нуля:

```
H(A_k[i] | A_k[i-1]) → 0
```

## 2. Математика бітового пакування та Frame of Reference (FoR)

Нехай задано блок із `N` цілих чисел стовпця: `X = [x₀, x₁, ..., x_{N-1}]`.

Класичне представлення кожного числа в пам'яті вимагає фіксованої розрядності `W` бітів (наприклад, `W = 32` або `W = 64`).

### Алгоритм Frame of Reference
1. Знаходимо мінімальне та максимальне значення в блоці:

```
x_min = min(x₀, x₁, ..., x_{N-1})
x_max = max(x₀, x₁, ..., x_{N-1})
```

2. Обчислюємо максимальну дельту (розмах значень):

```
Δ_max = x_max - x_min
```

3. Необхідна кількість бітів `b` для збереження будь-якого значення зі зміщенням відносно `x_min` визначається формулою:

```
b = ⌈log₂(Δ_max + 1)⌉
```

4. Кожне вихідне значення `x_i` трансформується у зміщене значення `y_i`:

```
y_i = x_i - x_min,   де 0 ≤ y_i ≤ Δ_max
```

### Розрахунок коефіцієнта стиснення FoR
Початковий обсяг пам'яті для блоку з `N` значень:

```
S_raw = N · W   (бітів)
```

Стиснений обсяг пам'яті:

```
S_for = Header + N · b
      = (W + 8) + N · ⌈log₂(Δ_max + 1)⌉   (бітів)
```

де `Header` містить значення `x_min` (`W` бітів) та розрядність `b` (8 бітів).

**Числовий приклад:**
Нехай блок містить `N = 1024` значень 64-бітних міток часу в мілісекундах (`W = 64`), що охоплюють період в 1 секунду (`Δ_max = 1000` мс):

```
S_raw = 1024 · 64 = 65 536 бітів (8 192 байти)

b = ⌈log₂(1000 + 1)⌉ = ⌈9.967⌉ = 10 бітів

S_for = (64 + 8) + 1024 · 10 = 72 + 10 240 = 10 312 бітів (1 289 байтів)

CR = S_raw / S_for = 65 536 / 10 312 ≈ 6.355  (стиснення у 6.35 раза)
```

## 3. Математичний поріг ефективності RLE (Run-Length Encoding)

Стиснення серіями однакових значень кодує потік повторень трійками або парами `(value, run_length)`.

Нехай масив довжиною `N` елементів розбивається на `M` неперервних однорідних серій із середньою довжиною серії `L_avg = N / M`.

### Формула вартості зберігання
- **Сирий масив:** `N · W_val` бітів.
- **RLE потік:** `M · (W_val + W_len)` бітів, де `W_val` — розрядність значення, `W_len` — розрядність лічильника довжини (зазвичай 16 або 32 біти).

RLE дає виграш у просторі тоді й лише тоді, коли:

```
M · (W_val + W_len) < N · W_val
```

Поділимо обидві частини на `M · W_val`:

```
1 + (W_len / W_val) < N / M

L_avg > 1 + (W_len / W_val)
```

```
Критичний поріг довжини серії для вигідності RLE:

L_crit = 1 + (W_len / W_val)
```

### Аналіз випадків:
1. **Для 64-бітних цілих чисел (`W_val = 64`) з 16-бітним лічильником (`W_len = 16`):**

```
L_crit = 1 + (16 / 64) = 1.25
```

Якщо середня довжина серії перевищує всього `1.25` елемента, RLE вже скорочує обсяг пам'яті.

2. **Для 8-бітних байтів (`W_val = 8`) з 16-бітним лічильником (`W_len = 16`):**

```
L_crit = 1 + (16 / 8) = 3.0
```

Для коротких типів даних середня довжина серії повинна бути строго більшою за 3 елементи, інакше RLE збільшить обсяг файлу (викликає негативне стиснення).

## 4. Модель Roofline: Ефективна пропускна здатність шини та закон Амдала

Головна перевага стовпцевого стиснення полягає не лише в економії дискового простору, а в подоланні фізичного ліміту шини передачі даних між накопичувачем, оперативною пам'яттю та процесором.

Нехай:
- `BW_raw` — фізична пропускна здатність шини (наприклад, PCIe 4.0 x4 NVMe SSD: `BW_raw = 7.0` ГБ/с, або канал оперативної пам'яті DDR5: `BW_raw = 40.0` ГБ/с);
- `CR` — коефіцієнт стиснення стовпця (`CR = S_raw / S_compressed`);
- `D_core` — швидкість декомпресії алгоритму на одне ядро CPU (наприклад, для апаратного SIMD Bit-Unpacking: `D_core = 12.0` ГБ/с; для LZ4: `D_core = 3.5` ГБ/с);
- `N_cores` — кількість обчислювальних ядер CPU, задіяних у паралельному скануванні.

### Рівняння ефективної пропускної здатності (Effective Bandwidth)
Час, необхідний для отримання та підготовки `V` гігабайтів сирих даних у регістрах процесора:

```
T_total = max(T_transfer, T_decompress)
```

де:

```
T_transfer   = (V / CR) / BW_raw      [час передачі стисненого обсягу шиною]
T_decompress = V / (N_cores · D_core)  [час розпакування ядрами CPU]
```

Тоді ефективна пропускна здатність системи `BW_eff = V / T_total`:

```
BW_eff = min(BW_raw · CR, N_cores · D_core)
```

```
   Ефективна пропускна здатність
   ▲
   │                              Обмеження процесором (CPU-Bound)
   │                           ┌───────────────────────────────────
   │                          ╱│  BW_eff = N_cores · D_core
   │                         ╱ │
   │  Обмеження шиною       ╱  │
   │  (I/O Bound)          ╱   │
   │  BW_eff = BW_raw · CR╱    │
   │                     ╱     │
   │                    ╱      │
   └───────────────────┴───────┴────────────────────────────────► Коефіцієнт стиснення (CR)
                      CR_crit
```

### Критична точка балансу (Balance Point)
Точка, в якій шина введення-виведення і процесорні ядра повністю збалансовані:

```
BW_raw · CR_crit = N_cores · D_core

CR_crit = (N_cores · D_core) / BW_raw
```

**Практичний розрахунок:**
Нехай сервер виконує аналітичний запит на 8 ядрах (`N_cores = 8`), зчитуючи дані з NVMe SSD (`BW_raw = 7.0` ГБ/с) за допомогою швидкого стовпцевого розпакувальника (`D_core = 5.0` ГБ/с):

```
Сумарна потужність декомпресії CPU = 8 · 5.0 = 40.0 ГБ/с

CR_crit = 40.0 / 7.0 ≈ 5.71
```

- Якщо стовпцеві дані стиснені у `CR = 5.0` разів, система залишається в зоні **I/O-Bound**:
  `BW_eff = 7.0 · 5.0 = 35.0` ГБ/с сирих даних обробляється процесором за секунду!
- Фізичний носій віддає 7 ГБ/с, але завдяки стовпцевому стисненню обчислювальне ядро отримує еквівалент 35 ГБ/с.

Цей математичний ефект пояснює, чому стиснені стовпцеві бази даних виконують аналітичні запити швидше, ніж читання сирих нестиснених масивів із пам'яті.
