# 🧮 Ентропійний аналіз та математичне обґрунтування алгоритмів стиснення часових рядів

Високий ступінь стиснення даних у спеціалізованих сховищах часових рядів (зменшення обсягу в 10–15 разів без втрати точності) ґрунтується на фундаментальних закономірностях теорії інформації Клода Шенона. Послідовності вимірів телеметрії та системного моніторингу мають високу надмірність через часову локальність та фізичну неперервність процесів, які вони описують. Застосування каскадних диференційних перетворень усуває кореляційні зв'язки, знижуючи інформаційну ентропію джерела даних до часток біта на один вимір.

## Ентропія часових міток: перехід від абсолютного часу до різниць другого порядку

Нехай задано послідовність монотонно зростаючих дискретних часових міток `T = (t₀, t₁, t₂, ..., tₙ)`, де виміри здійснюються автоматизованим агентом моніторингу з номінальним інтервалом опитування `I` (наприклад, `I = 15000` мс, тобто вибірка кожні 15 секунд). 

Через неминучі затримки в планувальнику завдань операційної системи, завантаженість процесора та коливання затримок передачі пакетів у комп'ютерній мережі реальний момент зняття виміру відхиляється від ідеальної сітки. Момент виміру описується моделлю випадкового процесу з дискретним часом:

```
t[k] = t[0] + k·I + ε[k]
```
де `ε[k]` — випадкова величина часового джитера (похибки таймінгу), що має нульове математичне сподівання `E[ε[k]] = 0` та малу дисперсію `σ²` (зазвичай `σ < 50` мс для сучасних локальних мереж).

### 1. Ентропія сирих абсолютних часових міток
Якщо кодувати значення `t[k]` як пряме 64-бітне ціле число (UNIX-час у мілісекундах від початку епохи), простір можливих дискретних станів джерела охоплює весь діапазон `2⁶⁴`. Якщо вважати всі стани рівноймовірними на заданому інтервалі моніторингу, інформаційна ентропія Шенона для такого дискретного джерела становить:

```
H(T) = log₂(N_states)
     = log₂(2⁶⁴)
     = 64 біти на точку
```

Збереження 64 бітів для кожної часової точки є вкрай нераціональним, оскільки значення `t[k]` містить величезну надмірність: кожна наступна точка майже повністю детермінована попередньою історією та константою інтервалу `I`.

### 2. Ентропія різниці першого порядку (Delta: `Δ[k]`)
Першим кроком зниження ентропії є перехід від абсолютних міток до перших різниць між сусідніми вимірами:

```
Δ[k] = t[k] - t[k-1]
     = (t[0] + k·I + ε[k]) - (t[0] + (k-1)·I + ε[k-1])
     = I + (ε[k] - ε[k-1])
```
Величина `Δ[k]` є випадковою величиною, зосередженою навколо фіксованого значення інтервалу `I`. Проте для безпосереднього збереження `Δ[k]` необхідно виділяти розрядність, достатню для представлення базового інтервалу (наприклад, для інтервалу `I = 15000` мс потрібно щонайменше `⌈log₂(15000)⌉ = 14` бітів). Крім того, при зміні частоти збору метрик або неоднорідності конфігурації діапазон перших дельт змінюється.

### 3. Ентропія різниці другого порядку (Delta-of-Delta: `DOD[k]`)
Щоб повністю позбутися залежності від абсолютного значення базового інтервалу `I`, обчислюється різниця між двома послідовними дельтами — дельта дельт (англ. *Delta-of-Delta*):

```
DOD[k] = Δ[k] - Δ[k-1]
       = (I + ε[k] - ε[k-1]) - (I + ε[k-1] - ε[k-2])
       = ε[k] - 2·ε[k-1] + ε[k-2]
```
Математичне сподівання випадкової величини `DOD[k]` дорівнює нулю: `E[DOD[k]] = 0`. Дисперсія різниці незалежних випадкових величин виражається через дисперсію початкового джитера:

```
Var(DOD[k]) = Var(ε[k]) + 4·Var(ε[k-1]) + Var(ε[k-2])
            = σ² + 4·σ² + σ²
            = 6·σ²
```
Оскільки внутрішні цикли таймерів більшості систем збору телеметрії вирівняні за фіксованим таймером (`sleep(I)`), понад 90–98% усіх послідовних вимірів мають строго ідентичну похибку або виконуються без затримок (`ε[k] = ε[k-1] = ε[k-2]`). Це призводить до того, що `DOD[k] = 0` для абсолютної більшості точок.

Розрахуємо теоретичну ентропію Шенона для дискретного джерела `DOD`, припустивши, що ймовірність ідеального інтервалу `P(DOD = 0) = 0.95`, а решта 5% імовірності рівномірно розподілена серед 32 можливих значень джитера в інтервалі `[-16, 16]` (`P(DOD = j) = 0.05 / 32 ≈ 0.00156`):

```
H(DOD) = - ∑ P(x) · log₂(P(x))
       = - [ 0.95 · log₂(0.95) + 32 · (0.00156 · log₂(0.00156)) ]
       = - [ 0.95 · (-0.0740) + 0.05 · (-9.324) ]
       = - [ -0.0703 - 0.4662 ]
       = 0.5365 біта на вимір
```

Префіксне кодування Gorilla наближається до цієї теоретичної межі. Для найбільш імовірного випадку `DOD = 0` призначається найкоротший код довжиною 1 біт (`'0'`). Для невеликого джитера `DOD ∈ [-63, 64]` виділяється префікс `'10'` та 7 бітів значення (загалом 9 бітів). Середня теоретична довжина кодового слова становить:

```
L_avg = 0.95 · 1 + 0.05 · 9
      = 0.95 + 0.45
      = 1.40 біта на часову мітку
```
Це означає, що часова мітка стискається від 64 бітів до середнього значення 1.4 біта — зменшення обсягу більш ніж у 45 разів.

## Математичне обґрунтування XOR-стиснення дійсних чисел (IEEE 754)

Число з рухомою комою подвійної точності (64 біти) за стандартом IEEE 754 складається з трьох функціональних частин:
- 1 знаковий біт `s`
- 11 бітів зміщеного порядку `e`
- 52 біти дробової частини мантиси `m`

Числове значення відновлюється за формулою:

```
v = (-1)ˢ · 2ᵉ⁻¹⁰²³ · (1 + ∑_{i=1}^{52} m[i] · 2⁻ⁱ)
```

### Липшицева неперервність фізичних процесів
Абсолютна більшість показників телеметрії (температура датчиків, використання оперативної пам'яті, напруга живлення, завантаження процесорних ядер, лічильники мережевих пакетів) є дискретними відліками неперервних процесів реального світу. Неперервні процеси мають обмежену швидкість зміни в часі, тобто задовольняють умову Липшиця:

```
|f(t[k]) - f(t[k-1])| ≤ K · |t[k] - t[k-1]|
```
де `K` — максимальна швидкість зміни параметра (константа Липшиця).

Для малого інтервалу дискретизації `Δt = 15` секунд абсолютна зміна величини `|v[k] - v[k-1]| ≤ K · Δt` є малою порівняно з поточною величиною `v[k]`.

Розглянемо побітову операцію виключного «АБО» (`XOR`) між двійковими образами двох послідовних дійсних чисел:

```
R = bits(v[k]) ⊕ bits(v[k-1])
```

1. **Знаковий розряд `s`:** Оскільки більшість технічних метрик є суто додатними величинами (`v ≥ 0`), знаковий біт дорівнює нулю в обох числах, тому `s[k] ⊕ s[k-1] = 0`.
2. **Порядок числа `e`:** При малих відносних змінах порядок величини не змінюється (`e[k] = e[k-1]`). Це призводить до появи 11 послідовних нулів у бітовому результаті `XOR`: `e[k] ⊕ e[k-1] = 00000000000₂`.
3. **Старші розряди мантиси `m`:** Старші розряди мантиси відповідають за найвагоміші частини числа. Якщо відносна зміна величини `δ = |Δv / v| ≪ 1`, то перші `M` бітів мантиси повністю збігаються, де `M ≈ ⌊-log₂(δ)⌋`.

Сумарна кількість провідних нульових бітів у двійковому числі `R` дорівнює:

```
N_leading = 1 (знак) + 11 (порядок) + M (мантиса)
          ≥ 12 + M бітів
```

Якщо метрика за 15 секунд змінилася менш ніж на 0.1% (`δ ≤ 0.001`), кількість однакових бітів мантиси `M = ⌊-log₂(0.001)⌋ = 9`, звідки:

```
N_leading ≥ 12 + 9 = 21 біт
```

### Довжина кодового слова Gorilla XOR

Нехай `L = 64 - N_leading - N_trailing` — довжина значущої частини бітового образу `XOR`. Середня кількість бітів для кодування одного значення `float64` розраховується на основі трьох можливих станів:
1. Повна незмінність значення (`Δv = 0`, типово для лічильників у стані спокою) з імовірністю `P(Δv = 0) = 0.60`. Кодується 1 бітом `'0'`.
2. Зміна значення в межах попереднього вікна з імовірністю `P(same_window) = 0.30` (при довжині `L = 12` значущих бітів). Кодується 2 бітами контролю (`'10'`) + 12 бітами значення.
3. Зміна меж значущого вікна з імовірністю `P(new_window) = 0.10`. Кодується 2 бітами контролю (`'11'`) + 5 бітами кількості провідних нулів + 6 бітами довжини + 12 бітами значення.

Математичне сподівання довжини коду:

```
Cost(v) = P(Δv = 0) · 1 + P(same_window) · (2 + L) + P(new_window) · (2 + 5 + 6 + L)
        = 0.60 · 1 + 0.30 · (2 + 12) + 0.10 · (13 + 12)
        = 0.60 + 0.30 · 14 + 0.10 · 25
        = 0.60 + 4.20 + 2.50
        = 7.30 бітів на 64-бітне дійсне число
```

### Загальний баланс стиснення часового ряду

Сумарна середня вага однієї точки виміру `(timestamp, value)` становить:

```
Cost_total = Cost(timestamp) + Cost(value)
           = 1.40 біта + 7.30 бітів
           = 8.70 бітів ≈ 1.09 байта
```

Порівняно з нестисненим форматом 16 байтів (128 бітів), досягається результуючий коефіцієнт стиснення:

```
Compression_Ratio = 128 / 8.70
                  ≈ 14.71
```

Цей результат підтверджує, що поєднання різниць другого порядку для часових міток із побітовим XOR-стисненням чисел із рухомою комою усуває надмірність корельованих даних і наближає розмір збереженої інформації до теоретичної ентропійної межі.
