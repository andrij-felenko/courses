# 🧮 Математична модель вартості запитів та розрахунок селективності

Оптимізатор запитів реляційної СУБД порівнює конкуруючі фізичні плани за єдиною метрикою — **обчисленою вартістю** (англ. *estimated cost*). Вартість не вимірюється в секундах чи мілісекундах, оскільки час виконання залежить від поточного навантаження на сервер, температури кешу операційної системи та характеристик конкретного процесора. Натомість вартість — це абстрактне безрозмірне число, де за базову одиницю вимірювання `1.0` традиційно прийнято витрати на зчитування однієї 8-кілобайтної сторінки з диска при послідовному доступі.

## 1. Базові параметри фізичної моделі витрат

Модель витрат (на прикладі PostgreSQL) оперує п'ятьма фундаментальними ваговими коефіцієнтами, що розділяють дисковий ввід-вивід (I/O) та обчислювальні витрати процесора (CPU):

```
seq_page_cost        = 1.0     [вартість послідовного читання 1 сторінки з диска]
random_page_cost     = 4.0     [вартість випадкового читання 1 сторінки для HDD (на SSD: 1.1..1.5)]
cpu_tuple_cost       = 0.01    [вартість обробки 1 кортежу рушієм СУБД]
cpu_index_tuple_cost = 0.005   [вартість обробки 1 запису в індексі під час пошуку]
cpu_operator_cost    = 0.0025  [вартість обчислення одного оператора або предикату у WHERE]
```

Фізичний зміст параметра `random_page_cost = 4.0` випливає з механіки обертання пластин традиційних жорстких дисків (HDD): механічний рух голівки на довільну доріжку триває близько 4–10 мілісекунд, тоді як послідовне читання сусідніх секторів відбувається на повній швидкості обертання шпинделя без затримок позиціонування. На сучасних твердотільних накопичувачах (NVMe SSD) затримка випадкового читання наближається до послідовного, тому системні адміністратори знижують `random_page_cost` до `1.1–1.25`, що заохочує оптимізатор частіше обирати індекси.

Загальна вартість будь-якого вузла дерева плану складається з двох компонентів:
- **Початкова вартість (startup cost):** витрати, необхідні для підготовки вузла до видачі першого рядка (наприклад, повна побудова хеш-таблиці або виконання сортування).
- **Повна вартість (total cost):** сумарні витрати на отримання абсолютно всіх кортежів, що відповідають умовам запиту.

## 2. Розрахунок вартості послідовного сканування (Seq Scan)

Послідовне сканування зчитує абсолютно всі сторінки таблиці від першої до останньої, після чого для кожного знайденого рядка обчислює предикати фільтрації.

Нехай:
- `N_pages` — загальна кількість сторінок таблиці в купі (heap pages);
- `N_tuples` — загальна кількість рядків у таблиці;
- `N_preds` — кількість умов у виразі `WHERE`.

Початкова вартість послідовного сканування дорівнює нулю (`startup = 0.0`), оскільки перший же прочитаний рядок може бути одразу відданий нагору без очікування решти даних. Повна вартість розраховується як зважена сума дискових та обчислювальних операцій:

```
Cost_seq = N_pages · seq_page_cost + N_tuples · cpu_tuple_cost + N_tuples · N_preds · cpu_operator_cost
```

Розглянемо таблицю `orders` з параметрами:
`N_pages = 10000`, `N_tuples = 1000000`, `N_preds = 1` (одна умова `status = 'paid'`).

Покроковий розрахунок вартості:

```
Cost_seq_io  = 10000 · 1.0000    = 10000.0   [дисковий ввід-вивід: читання 10000 сторінок]
Cost_seq_tup = 1000000 · 0.0100  = 10000.0   [процесор: отримання 1000000 кортежів]
Cost_seq_op  = 1000000 · 0.0025  = 2500.0    [процесор: обчислення предиката status для кожного рядка]

Cost_seq_total
= Cost_seq_io + Cost_seq_tup + Cost_seq_op        [сума компонентів вводу-виводу та обчислень]
= 10000.0 + 10000.0 + 2500.0                      [підстановка порахованих значень]
= 22500.0                                         [загальна вартість Seq Scan в умовних одиницях]
```

## 3. Математика селективності (Selectivity)

**Селективність** `sel ∈ [0, 1]` — це очікувана ймовірність того, що довільно обраний рядок таблиці задовольнить умову фільтрації. Кількість очікуваних рядків на виході оператора (кардинальність, `rows`) обчислюється як `N_tuples · sel`.

### А. Предикат точної рівності (`column = value`)

1. Якщо значення `value` присутнє у списку найчастіших значень каталогу (Most Common Values, MCV), його селективність береться безпосередньо з масиву емпіричних частот `most_common_freqs`:
```
sel = freq(value)
```

2. Якщо значення відсутнє в MCV, воно належить до рівномірної частини розподілу серед решти `n_distinct` унікальних значень стовпця:
```
sel = (1 - sum(most_common_freqs) - null_frac) / (n_distinct - len(MCV))
```
За відсутності списку MCV та базової гіпотези про рівномірний розподіл формулу спрощують:
```
sel = (1 - null_frac) / n_distinct
```

### Б. Діапазонний предикат (`column < value`) за гістограмою

Каталог зберігає межі `K` однакових за кількістю рядків кошиків гістограми (histogram bounds): `[b_0, b_1, b_2, ..., b_K]`.

Якщо значення `value` потрапляє між межами кошика `[b_i, b_{i+1}]`, селективність розраховується методом лінійної інтерполяції:

```
Frac_full_buckets = i / K                                     [частка повністю пройдених кошиків ліворуч]
Frac_current_bucket = (value - b_i) / ((b_{i+1} - b_i) · K)   [частка поточного кошика]

sel = Frac_full_buckets + Frac_current_bucket
```

### В. Комбінація предикатів (`AND`, `OR`)

За базовою гіпотезою про статистичну незалежність стовпців імовірності перемножуються або об'єднуються:
```
sel(A AND B) = sel(A) · sel(B)                                [правило множення ймовірностей]
sel(A OR B)  = sel(A) + sel(B) - sel(A) · sel(B)              [ймовірність об'єднання подій]
```

## 4. Розрахунок вартості сканування за індексом (Index Scan)

Сканування за B-деревом складається з трьох послідовних кроків:
1. Спуск від кореня до листка індексного дерева: висота дерева `H_tree` випадкових читань.
2. Прохід по листках індексу: зчитування частини сторінок індексу `N_idx_pages · sel` та обробка `N_tuples · sel` індексних записів.
3. Доступ до купи (таблиці): отримання `N_tuples · sel` рядків через випадкові читання сторінок таблиці.

Нехай:
- `H_tree = 3` (висота B-дерева);
- `N_idx_pages = 2500` (кількість сторінок індексу);
- `sel` — селективність умови;
- `N_pages = 10000`, `N_tuples = 1000000`.

Формула початкової вартості (спуск до першого листка індексу):
```
Cost_idx_startup
= H_tree · random_page_cost + cpu_operator_cost   [випадковий спуск по дереву до листка + обчислення оператора]
= 3 · 4.0 + 0.0025                                [підстановка числових значень]
= 12.0025                                         [початкова вартість умовних одиниць]
```

Формула повної вартості Index Scan враховує доступ до сторінок індексу та наступне видобування рядків із купи:
```
Cost_idx_total = Cost_idx_startup + ceil(N_idx_pages · sel) · seq_page_cost + (N_tuples · sel) · cpu_index_tuple_cost + (N_pages · (1 - (1 - 1/N_pages)^(N_tuples · sel))) · random_page_cost + (N_tuples · sel) · cpu_tuple_cost + (N_tuples · sel) · cpu_operator_cost
```

Формула Мак-Крейта `1 - (1 - 1/N_pages)^K` оцінює кількість унікальних сторінок таблиці, які доведеться завантажити для `K = N_tuples · sel` випадково обраних рядків. При малій селективності (`sel < 0.05`) кількість звернень до сторінок майже точно дорівнює кількості відібраних рядків `K`, тобто `min(N_pages, K)`.

## 5. Точка перетину вартостей (Tipping Point)

Розрахуємо точну вартість індексного сканування для різних значень селективності `sel` і знайдемо поріг, коли індексний пошук стає дорожчим за повне послідовне сканування таблиці (`Cost_seq = 22500.0`).

### Приклад 1: `sel = 0.001` (0.1%, 1000 рядків)

```
N_rows_found = 1000000 · 0.001 = 1000

Cost_idx_pages = ceil(2500 · 0.001) · 1.0 = 3.0   [читання 3 сторінок індексу]
Cost_idx_eval  = 1000 · 0.005 = 5.0                [обробка 1000 записів індексу]
Cost_heap_io   = 1000 · 4.0 = 4000.0               [1000 випадкових читань сторінок купи]
Cost_heap_tup  = 1000 · 0.01 = 10.0                [отримання 1000 кортежів]
Cost_heap_op   = 1000 · 0.0025 = 2.5               [перевірка умов]

Cost_idx_total
= 12.0025 + 3.0 + 5.0 + 4000.0 + 10.0 + 2.5       [сума стартапу, читань індексу та випадкового доступу до купи]
= 4032.5                                          [Index Scan виграє у Seq Scan у 5.5 разів (4032.5 < 22500.0)]
```

### Приклад 2: `sel = 0.01` (1.0%, 10 000 рядків)

```
N_rows_found = 1000000 · 0.01 = 10000

Cost_idx_pages = ceil(2500 · 0.01) · 1.0 = 25.0
Cost_idx_eval  = 10000 · 0.005 = 50.0
Cost_heap_io   = (10000 · (1 - (1 - 1/10000)^10000)) · 4.0   [формула Мак-Крейта для унікальних сторінок]
               = (10000 · 0.6321) · 4.0                      [частка завантажених сторінок таблиці]
               = 6321 · 4.0 = 25284.0                        [випадковий I/O перевищив усю вартість таблиці!]
Cost_heap_tup  = 10000 · 0.01 = 100.0
Cost_heap_op   = 10000 · 0.0025 = 25.0

Cost_idx_total
= 12.0025 + 25.0 + 50.0 + 25284.0 + 100.0 + 25.0  [сума всіх складових індексного сканування]
= 25496.0                                         [Index Scan вже програє Seq Scan (25496.0 > 22500.0)]
```

### Визначення критичного порогу

Знайдемо селективність `sel*`, при якій `Cost_idx(sel*) = Cost_seq`:

```
Cost_idx(sel) ≈ 12.0 + 2500 · sel · 1.0 + sel · 1000000 · (0.005 + 0.01 + 0.0025) + N_heap_io · random_page_cost

Для HDD (random_page_cost = 4.0):
22500 = 12.0 + 2500 · sel + 17500 · sel + (10000 · (1 - exp(-100 · sel))) · 4.0
Розв'язок: sel* ≈ 0.038 (3.8% таблиці, або 38 000 рядків).

Для SSD (random_page_cost = 1.1):
22500 = 12.0 + 2500 · sel + 17500 · sel + (10000 · (1 - exp(-100 · sel))) · 1.1
Розв'язок: sel* ≈ 0.165 (16.5% таблиці, або 165 000 рядків).
```

## 6. Моделювання вартості операторів з'єднання

Оцінка вартості операторів з'єднання залежить від кардинальності обох джерел та наявності індексів.

### А. Вкладений цикл (Nested Loop)

Нехай зовнішнє джерело повертає `N_outer` рядків, а внутрішнє — `N_inner`. Загальна вартість:

```
Cost_nested_loop = Cost_outer_total + N_outer · Cost_inner_path + N_outer · N_inner_matched · cpu_tuple_cost
```

Якщо внутрішнє джерело сканується за індексом, `Cost_inner_path` є малим (індексний спуск), і алгоритм дає мінімальну вартість при `N_outer < 100`. Якщо внутрішнього індексу немає, `Cost_inner_path` дорівнює вартості повного послідовного сканування `Cost_seq(B)`, що призводить до квадратичного зростання `N_outer · Cost_seq(B)`.

### Б. З'єднання хешуванням (Hash Join)

Початкова вартість включає повне читання внутрішньої таблиці та заповнення хеш-таблиці в пам'яті:

```
Cost_hash_startup = Cost_inner_total + N_inner · cpu_operator_cost   [повне читання внутрішньої таблиці + побудова хеш-таблиці]
Cost_hash_total   = Cost_hash_startup + Cost_outer_total + N_outer · cpu_operator_cost + (N_outer · sel_join) · cpu_tuple_cost   [стартап + сканування зовнішньої таблиці + зондування хешу + видобування кортежів]
```

Якщо розмір внутрішньої таблиці перевищує `work_mem`, до вартості додаються витрати на запис та повторне читання дискових батчів: `2 · N_spilled_pages · seq_page_cost`.

Цей математичний аналіз доводить фундаментальну закономірність: **вибір між індексами та послідовним читанням, як і вибір алгоритму з'єднання, цілком диктується селективністю та співвідношенням дискових і процесорних витрат**. Щойно селективність перевищує 3–5% на традиційних дисках або 15–20% на NVMe-накопичувачах, оптимізатор математично строго віддає перевагу послідовним проходам і хеш-таблицям.
