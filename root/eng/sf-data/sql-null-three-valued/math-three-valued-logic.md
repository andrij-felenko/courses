# 🧮 Алгебраїчна структура тризначної логіки Клини та решітка істинності

Тризначна логіка SQL базується на сильній тризначній логіці Стівена Коула Кліні (Stephen Cole Kleene, 1938), яка у математичній літературі позначається як `K3`. На відміну від класичної булевої алгебри, що оперує двохелементною множиною істиннісних значень `B₂ = {0, 1}` (де 0 відповідає `FALSE`, а 1 — `TRUE`), алгебраїчна система Клини будується над триелементною множиною:

```
L₃ = {0, 1/2, 1}
```

де значення `0` позначає хибність (`FALSE`), `1` — істинність (`TRUE`), а `1/2` — невизначеність або невідомість (`UNKNOWN`).

## Решітка істинності та визначення базових зв'язок

Множина `L₃` утворює лінійно впорядковану дистрибутивну ґратку (решітку) за відношенням природного порядку числових значень:

```
0 < 1/2 < 1   (FALSE < UNKNOWN < TRUE)
```

Операції кон'юнкції (`∧`, в SQL — `AND`), диз'юнкції (`∨`, в SQL — `OR`) та заперечення (`¬`, в SQL — `NOT`) визначаються через операції точної нижньої межі (infimum, найменша грань), точної верхньої межі (supremum, найбільша грань) та арифметичного доповнення:

```
val(A ∧ B) = min(val(A), val(B))
val(A ∨ B) = max(val(A), val(B))
val(¬A)    = 1 - val(A)
```

Ці три операції утворюють повну функціональну систему для обчислення будь-яких складених логічних виразів над множиною `L₃`.

### Таблиці істинності зв'язок Клини K3

Таблиця оператора `AND` (мінімум за значеннями операндів):

| `AND` (`∧`) | `FALSE` (0) | `UNKNOWN` (1/2) | `TRUE` (1) |
|---|---|---|---|
| **`FALSE` (0)** | `FALSE` (0) | `FALSE` (0) | `FALSE` (0) |
| **`UNKNOWN` (1/2)** | `FALSE` (0) | `UNKNOWN` (1/2) | `UNKNOWN` (1/2) |
| **`TRUE` (1)** | `FALSE` (0) | `UNKNOWN` (1/2) | `TRUE` (1) |

Таблиця оператора `OR` (максимум за значеннями операндів):

| `OR` (`∨`) | `FALSE` (0) | `UNKNOWN` (1/2) | `TRUE` (1) |
|---|---|---|---|
| **`FALSE` (0)** | `FALSE` (0) | `UNKNOWN` (1/2) | `TRUE` (1) |
| **`UNKNOWN` (1/2)** | `UNKNOWN` (1/2) | `UNKNOWN` (1/2) | `TRUE` (1) |
| **`TRUE` (1)** | `TRUE` (1) | `TRUE` (1) | `TRUE` (1) |

Таблиця заперечення `NOT`:

| `A` | `NOT A` (`¬A`) |
|---|---|
| `FALSE` (0) | `TRUE` (1) |
| `UNKNOWN` (1/2) | `UNKNOWN` (1/2) |
| `TRUE` (1) | `FALSE` (0) |

## Порівняння трьох систем тризначної логіки: Клини, Бочвара та Лукасевича

У математичній логіці існують три різні системи тризначної логіки, що по-різному трактують невизначений стан:

1. **Сильна логіка Клини (`K3`):** невідомий стан `1/2` інтерпретується як «дійсне значення існує (0 або 1), але наразі невідоме системі». Тому якщо один операнд гарантує результат незалежно від другого (`FALSE AND x = FALSE`, `TRUE OR x = TRUE`), вираз обчислюється до детермінованого значення навіть за наявності `1/2`. Саме цю систему обрано для мови SQL.
2. **Слабка логіка Клини / логіка Бочвара (`B3`):** невизначений стан `1/2` трактується як «беззмістовність, помилка або зависання обчислень» (інфекційна логіка). Будь-яка операція з `1/2` негайно повертає `1/2`. У логіці Бочвара `UNKNOWN AND FALSE = UNKNOWN`, що робить її непридатною для баз даних, оскільки одна порожня комірка руйнувала б усі складні фільтри.
3. **Логіка Лукасевича (`Ł3`):** вводить спеціальну імплікацію `A → B = min(1, 1 - val(A) + val(B))`. У системі Лукасевича вираз `UNKNOWN → UNKNOWN` дорівнює `TRUE` (1), оскільки будь-яке невідоме висловлювання тягне саме себе. У логіці Клини та SQL імплікація `A → B` виражається через `¬A ∨ B`, тому `UNKNOWN → UNKNOWN` дає `UNKNOWN`.

## Збереження законів де Моргана та дистрибутивності

Алгебра `(L₃, ∧, ∨, ¬, 0, 1)` є алгеброю де Моргана (квазібулевою алгеброю). У ній зберігаються всі фундаментальні властивості булевих операцій, крім законів доповнення:
* Комутативність: `A ∧ B = B ∧ A`, `A ∨ B = B ∨ A`.
* Асоціативність: `(A ∧ B) ∧ C = A ∧ (B ∧ C)`, `(A ∨ B) ∨ C = A ∨ (B ∨ C)`.
* Дистрибутивність: `A ∧ (B ∨ C) = (A ∧ B) ∨ (A ∧ C)`.
* Подвійне заперечення: `¬(¬A) = A`.

### Алгебраїчне доведення законів де Моргана у K3

Перевірка першого закону де Моргана `¬(A ∧ B) = ¬A ∨ ¬B`:

```
val(¬(A ∧ B))
= 1 - min(val(A), val(B))         [означення заперечення та кон'юнкції]
= max(1 - val(A), 1 - val(B))     [алгебраїчна тотожність: 1 - min(x,y) = max(1-x, 1-y)]
= val(¬A ∨ ¬B)                    [означення диз'юнкції над запереченнями]
```

Перевірка другого закону де Моргана `¬(A ∨ B) = ¬A ∧ ¬B`:

```
val(¬(A ∨ B))
= 1 - max(val(A), val(B))         [означення заперечення та диз'юнкції]
= min(1 - val(A), 1 - val(B))     [алгебраїчна тотожність: 1 - max(x,y) = min(1-x, 1-y)]
= val(¬A ∧ ¬B)                    [означення кон'юнкції над запереченнями]
```

Ці тотожності дозволяють оптимізатору запитів реляційної СУБД вільно застосовувати закони де Моргана для спрощення предикатів у планах виконання запитів без ризику змінити тризначний результат.

## Руйнування класичних законів: виключене третє та несуперечність

У класичній булевій алгебрі вирази `p ∨ ¬p` (закон виключеного третього, *tertium non datur*) та `¬(p ∧ ¬p)` (закон несуперечності) є тавтологіями, тобто набувають значення `1` при будь-якій оцінці змінної `p`.

Головна теорема логіки Клини стверджує: **у системі `K3` не існує жодної тавтології**. Якщо кожній змінній у формулі присвоїти значення `1/2`, результат формули неминуче дорівнюватиме `1/2`.

### 1. Оцінка закону виключеного третього для невизначеного стану

Нехай `val(p) = 1/2` (`UNKNOWN`). Обчислимо значення формули `p ∨ ¬p`:

```
val(p ∨ ¬p)
= max(val(p), val(¬p))            [означення диз'юнкції через максимум]
= max(1/2, 1 - 1/2)               [підстановка значення p = 1/2 та заперечення]
= max(1/2, 1/2)                   [арифметика віднімання]
= 1/2                             [UNKNOWN замість очікуваного TRUE]
```

Висновок: вираз `p OR NOT p` не гарантує повернення рядка в запиті SQL, оскільки для рядків з `NULL` вираз набуває значення `UNKNOWN`.

### 2. Оцінка закону несуперечності для невизначеного стану

Нехай `val(p) = 1/2` (`UNKNOWN`). Обчислимо значення формули `p ∧ ¬p`:

```
val(p ∧ ¬p)
= min(val(p), val(¬p))            [означення кон'юнкції через мінімум]
= min(1/2, 1 - 1/2)               [підстановка значення p = 1/2 та заперечення]
= min(1/2, 1/2)                   [арифметика віднімання]
= 1/2                             [UNKNOWN замість очікуваного FALSE]
```

Заперечення несуперечності `¬(p ∧ ¬p)` також дорівнює `1 - 1/2 = 1/2` (`UNKNOWN`), що руйнує класичне булеве доведення від супротивного.

## Порядок інформативності Скотта (Порядок знання)

Окрім порядку істинності `0 < 1/2 < 1`, множина `L₃` володіє другим частковим порядком — порядком інформативності (знання), який у теорії доменів Дениса Скотта позначається як `≤_k`:

```
        0       1
         \     /
          \   /
           1/2
```

Формально:
* `1/2 ≤_k 0`
* `1/2 ≤_k 1`
* `0` та `1` є непорівнюваними між собою (`0 ≰_k 1` та `1 ≰_k 0`).

У цьому впорядкуванні стан `1/2` позначає дно решітки (нуль інформації, відсутність даних), тоді як стани `0` та `1` є максимальними елементами, що представляють повну визначеність.

### Теорема про монотонність логічних зв'язок

Усі операції сильної логіки Клини (`∧`, `∨`, `¬`) є строго монотонними відображеннями відносно порядку знання `≤_k`.

Якщо `x₁ ≤_k y₁` та `x₂ ≤_k y₂`, то:
* `(x₁ ∧ x₂) ≤_k (y₁ ∧ y₂)`
* `(x₁ ∨ x₂) ≤_k (y₁ ∨ y₂)`
* `¬x₁ ≤_k ¬y₁`

З практичної точки зору реляційних баз даних монотонність означає: якщо невідоме значення `1/2` в деякій комірці таблиці оновити дійсним значенням (`0` або `1`), результат будь-якого вже обчисленого виразу або залишиться незмінним, або уточниться від `UNKNOWN` до `TRUE`/`FALSE`. Проте результат ніколи не зможе інвертуватися з раніше визначеного `TRUE` на `FALSE` чи навпаки. Ця теорема є математичним гарантом узгодженості транзакційного оновлення неповної інформації в реляційних СУБД.

## Функціональна неповність та оператор розпізнавання

Базис зв'язок `{∧, ∨, ¬}` у системі Клини `K3` є функціонально неповним: за його допомогою неможливо виразити унарний оператор виділення дійсності (твердження Бочвара або предикат `IS NULL` у SQL):

```
IS_TRUE(x) = 1, якщо x = 1; інакше 0
IS_UNKNOWN(x) = 1, якщо x = 1/2; інакше 0
```

Оскільки всі функції, побудовані з `{∧, ∨, ¬}`, обов'язково переводять кортеж `(1/2, ..., 1/2)` у значення `1/2`, неможливо отримати результат `1` або `0` суто засобами тризначних зв'язок без залучення спеціальних зовнішніх операторів мови SQL (`IS NULL` та `IS NOT NULL`). Введення оператора `IS NULL` розширює алгебру Клини до повної системи, повертаючи реляційній моделі здатність строго розрізняти наявність та відсутність даних на метаінформаційному рівні.
