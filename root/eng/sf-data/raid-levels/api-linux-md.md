# 📋 Інтерфейс Linux mdadm та sysfs: керування та моніторинг програмних RAID-масивів

Підсистема ядра Linux `md` (Multiple Devices) забезпечує універсальну програмну реалізацію дискових масивів RAID 0, 1, 4, 5, 6, 10 та MULTIPATH. У цій довідковій вставці описано внутрішню архітектуру драйвера `md`, формат суперблока метаданих, інтерфейс командного рядка утиліти `mdadm`, параметри конфігураційного файла `/etc/mdadm/mdadm.conf`, простір віртуальних файлів ядра `/proc/mdstat` та системний інтерфейс управління `sysfs` (`/sys/block/mdX/md/`).

## 1. Внутрішня архітектура підсистеми md у ядрі Linux

Драйвер `md` живе у підсистемі блокового введення-виведення ядра Linux (`drivers/md/`). Він створює віртуальний блоковий пристрій `/dev/mdX`, який перехоплює структурні запити `struct bio` від файлових систем (ext4, XFS, Btrfs) або менеджерів томів LVM.

Коли файлова система надсилає запит на запис блоку у віртуальний пристрій `/dev/md0`, підсистема `md` виконує наступну послідовність дій:

1. **Розщеплення BIO-запиту:** Головний вектор `bio` розбивається на підзапити до конкретних фізичних дискових пристроїв відповідно до конфігурації масиву.
2. **Виділення страйпової структури (Stripe Head):** Для масивів RAID 5 та RAID 6 ядро виділяє із заздалегідь зарезервованого пулу пам'яті структуру `struct stripe_head`. Ця структура містить буферні сторінки для кожного з `N` дисків страйпа.
3. **Обчислення паритету у кеші:** Якщо запис є частковим (Partial Stripe Write), ядро ініціює зчитування старих блоків даних та паритету у кеш страйпів (`stripe_cache`), після чого робочі потоки ядра `mdX_raid5` обчислюють новий паритет.
4. **Асинхронна відправка I/O:** Сформовані `bio`-запити відправляються драйверам нижнього рівня (SATA/NVMe контролерам) за допомогою функції `submit_bio_noacct()`.

Розмір кешу страйпів обмежується параметром `stripe_cache_size`. Загальний обсяг оперативної пам'яті, що виділяється під кеш страйпів масиву з `N` дисків, обчислюється за формулою:

```
RAM_bytes = stripe_cache_size · N · 4096                [пам'ять для кешу страйпів у байтах]
```

При значеннях `stripe_cache_size = 4096` для масиву з `N = 8` дисків ядро виділяє `4096 · 8 · 4096 = 134 217 728` байтів (128 МБ) надшвидкої кеш-пам'яті, що дає змогу суттєво нівелювати штраф на запис RAID 5 під випадковим навантаженням.

## 2. Структура метаданих суперблоку (Superblock Version 1.2)

Драйвер `md` зберігає конфігураційну інформацію про масив у спеціалізованій структурі — **суперблоці RAID**. У сучасних дистрибутивах Linux стандартом є версія метаданих `1.2`.

Суперблок версії `1.2` розміщується за зсувом **4096 байтів (4 КБ)** від початку кожного фізичного накопичувача, що унеможливлює випадкове перекриття зі старими таблицями розділів MBR або заголовками файлових систем.

Основними полями суперблоку `1.2` є:
- **Magic Number (`0xa92b4efc`):** Магічне 32-бітно число для автовиявлення суперблоку драйвером ядра.
- **UUID масиву:** 128-бітний унікальний ідентифікатор масиву, який залишається незмінним при перенесенні дисків між різними фізичними серверами або контролерами.
- **Event Counter:** 64-бітний лічильник подій запису. При кожній модифікації масиву лічильник збільшується на 1. Під час збирання масиву `mdadm` порівнює лічильники подій на всіх дисках: диск із меншим лічильником вважається застарілим (Out-of-sync) і відправляється на відбудову.
- **Array Geometry:** Поля `level`, `layout`, `chunk_size`, `raid_disks`, які точно описують конфігурацію масиву.
- **Device Role Array:** Масив ролей, у якому вказано фізичний номер кожного диска в геометрії страйпа (`0, 1, ..., N-1`) або позначку `0xfe` (Spare) чи `0xff` (Faulty).

## 3. Утиліта mdadm: синтаксис та режими роботи

Утиліта `mdadm` (Multiple Disk Admin) є основним користувацьким інструментом для створення, адміністрування, моніторингу та діагностики дискових масивів ядра Linux. Вона працює безпосередньо через системні виклики `ioctl` із драйвером `drivers/md/md.c`.

Загальний синтаксис команды `mdadm`:
```bash
mdadm [MODE] <device> [OPTIONS] <component-devices>
```

Основні режими роботи `mdadm` наведено в таблиці нижче:

| Режим (`MODE`) | Опис та призначення | Приклад команди |
| :--- | :--- | :--- |
| **`--create` (`-C`)** | Створення нового RAID-масиву із записом метаданих на диски. | `mdadm --create /dev/md0 --level=5 --raid-devices=4 /dev/sd[b-e]` |
| **`--detail` (`-D`)** | Виведення вичерпної детальної інформації про масив. | `mdadm --detail /dev/md0` |
| **`--manage`** | Оперативне керування (позначення диска як збійного, видалення, додавання). | `mdadm --manage /dev/md0 --fail /dev/sdb --remove /dev/sdb` |
| **`--assemble` (`-A`)** | Збирання та активація існуючого масиву після перезавантаження. | `mdadm --assemble /dev/md0 /dev/sd[b-e]` |
| **`--grow` (`-G`)** | Зміна конфігурації «на льоту» (міграція рівня RAID, додавання дисків, зміна Chunk Size). | `mdadm --grow /dev/md0 --raid-devices=5 --add /dev/sdf` |
| **`--stop` (`-S`)** | Деактивація та зупинка дискового масиву. | `mdadm --stop /dev/md0` |
| **`--examine` (`-E`)** | Читання та аналіз суперблоку RAID безпосередньо з фізичного накопичувача. | `mdadm --examine /dev/sdb1` |

### Ключові опції створення масиву (`--create`)

- `--level=` (`-l`): Рівень RAID (`0`, `1`, `5`, `6`, `10`). Визначає геометрію розподілу даних та алгоритм паритету.
- `--raid-devices=` (`-n`): Кількість активних накопичувачів у масиві.
- `--spare-devices=` (`-x`): Кількість резервних дисків гарячої заміни (Hot Spare), які перебувають у режимі очікування і підключаються автоматично у разі збою.
- `--chunk=` (`-c`): Розмір страйп-юніта (Stripe Unit Size) у кілобайтах (за замовчуванням `512K`). Вибір цього параметра є вирішальним для продуктивності: для баз даних з малими блоками запису (8KB/16KB) обирають `64K` або `128K`, для потокового відео та великих файлів — `512K` або `1024K`.
- `--layout=` (`-p`): Схема розташування паритету для RAID 5 та RAID 6 (значення: `left-symmetric`, `left-asymmetric`, `right-symmetric`, `right-asymmetric`). Алгоритм `left-symmetric` забезпечує найкращу продуктивність послідовного читання.
- `--metadata=` (`-e`): Версія метаданих суперблоку (`1.2` за замовчуванням).

## 4. Конфігураційний файл /etc/mdadm/mdadm.conf

Конфігураційний файл `/etc/mdadm/mdadm.conf` використовується інструментами ініціалізації ОС (initramfs / systemd) для автоматичного виявлення та збирання масивів під час завантаження системи.

Приклад типового конфігураційного файла:
```text
# Дефолтний пошук усіх дискових пристроїв
DEVICE partitions

# Політика сповіщень демона моніторингу mdadm --monitor
MAILADDR admin@example.com

# Автоматичне сканування масивів за UUID суперблоків
ARRAY /dev/md0 metadata=1.2 UUID=e2f3d4c5:b6a78901:f2345678:9abc0123
ARRAY /dev/md1 metadata=1.2 UUID=a1b2c3d4:e5f67890:12345678:90abcdef
```

Для автоматичної генерації конфігураційного файла за поточним станом системи застосовується команда:
```bash
mdadm --detail --scan >> /etc/mdadm/mdadm.conf
```

## 5. Інтерфейси ядра: /proc/mdstat та sysfs

Підсистема ядра Linux експортує поточний стан усіх дискових масивів через віртуальні файлові системи `/proc` та `/sys`.

### Аналіз стану через /proc/mdstat

Файл `/proc/mdstat` надає миттєвий текстовий зріз стану активних масивів.

Приклад вмісту `/proc/mdstat` у нормальному стані:
```text
Personalities : [raid1] [raid6] [raid5] [raid4] 
md0 : active raid5 sde[3] sdd[2] sdc[1] sdb[0]
      5859372288 blocks super 1.2 level 5, 512k chunk, algorithm 2 [4/4] [UUUU]
      
unused devices: <none>
```

Приклад вмісту під час відбудови (Rebuild) після заміни диска `sdb`:
```text
md0 : active raid5 sdb[4](S) sde[3] sdd[2] sdc[1]
      5859372288 blocks super 1.2 level 5, 512k chunk, algorithm 2 [4/3] [_UUU]
      [=>...................]  rebuild =  8.4% (164100480/1953124096) finish=142.5min speed=209180K/sec
```

Пояснення атрибутів:
- `[4/4] [UUUU]`: Загальна кількість дисків / кількість активних дисків. Літера `U` (Up) означає справний диск, підкреслення `_` означає відсутній або збійний диск.
- `algorithm 2`: Алгоритм розташування паритету (`2 = Left-Symmetric`).
- `rebuild = 8.4%`: Прогрес відбудови масиву, розрахований час завершення (`finish`) та поточна швидкість зчитування/запису (`speed`).

### Керування через sysfs (/sys/block/mdX/md/)

Системний інтерфейс `/sys/block/mdX/md/` дозволяє зчитувати метрики продуктивності та налаштовувати параметри ядра під час виконання без виклику зовнішніх утиліт.

| Параметр sysfs | Тип | Значення та призначення |
| :--- | :--- | :--- |
| `array_state` | Read / Write | Стан масиву: `clear`, `inactive`, `suspended`, `readonly`, `read-auto`, `clean`, `active`, `write-pending`, `stripe-staging`. Запис `read-auto` переводить масив у режим автоматичного монтажу. |
| `sync_action` | Read / Write | Поточна операція синхронізації: `idle`, `reshape`, `resync`, `recovery`, `check`, `repair`. Запис `check` запускає фонову перевірку паритету. |
| `degraded` | Read Only | Лічильник кількості відсутніх або збійних дисків у масиві (0 — масив повністю справний). |
| `mismatch_cnt` | Read Only | Кількість розбіжностей сектора паритету, виявлених під час виконання `check`. Значення `> 0` свідчить про приховане пошкодження даних (Silent Data Corruption). |
| `stripe_cache_size` | Read / Write | Розмір кешу страйпів у сторінках пам'яті (4KB) на диск. Збільшення з 256 до 8192 суттєво підвищує швидкість запису RAID 5/6 ціною споживання RAM. |
| `sync_speed_min` | Read / Write | Мінімально гарантована швидкість фонової відбудови у КБ/с (за замовчуванням `1000`). |
| `sync_speed_max` | Read / Write | Максимально дозволена швидкість відбудови у КБ/с для запобігання деградації I/O системних застосунків. |
| `group_thread_cnt` | Read / Write | Кількість робочих потоків ядра для паралельного обчислення XOR/GF(2^8) паритету на багатоядерних CPU. |

## 6. Практичні сценарії обслуговування масивів

Нижче наведено покрокові інструкції для типових операцій адміністрування.

### 6.1. Усунення аварії при відмові диска

У разі виходу накопичувача `/dev/sdc` з ладу послідовність дій адміністратора є наступною:

1. Позначити диск як збійний у драйвері ядра:
   ```bash
   mdadm --manage /dev/md0 --fail /dev/sdc
   ```
2. Безпечно вилучити пристрій з конфігурації масиву:
   ```bash
   mdadm --manage /dev/md0 --remove /dev/sdc
   ```
3. Після фізичної заміни диска на новий накопичувач `/dev/sdf` додати його у масив:
   ```bash
   mdadm --manage /dev/md0 --add /dev/sdf
   ```
4. Прискорити відбудову через підключення додаткової RAM під кеш страйпів:
   ```bash
   echo 16384 > /sys/block/md0/md/stripe_cache_size
   echo 250000 > /sys/block/md0/md/sync_speed_min
   ```

### 6.2. Розширення масиву «на льоту» (Online Array Expansion)

Утиліта `mdadm` дозволяє додавати нові диски та змінювати рівень RAID без зупинки файлової системи (Live Migration).

Наприклад, для додавання 5-го диска `/dev/sdg` у масив RAID 5 з 4 дисків виконують:
```bash
# 1. Додавання нового диска як Hot Spare
mdadm --manage /dev/md0 --add /dev/sdg

# 2. Перебудова геометрії масиву (Reshaping) на 5 активних дисків
mdadm --grow /dev/md0 --raid-devices=5
```

Процес `reshape` переобчислює індекси всіх страйпів та зміщує блоки даних по п'яти дисках. Відстежувати перебіг можна через `cat /proc/mdstat`.

### 6.3. Міграція рівня RAID (RAID 5 -> RAID 6)

Для підвищення відмовостійкості масив RAID 5 можна трансформувати у RAID 6 додаванням диска подвійного паритету:
```bash
# Додавання резервного диска
mdadm --manage /dev/md0 --add /dev/sdh

# Запуск міграції рівня на RAID 6
mdadm --grow /dev/md0 --level=6 --raid-devices=6
```

Після завершення операції драйвер ядра заповнює додатковий ротаційний паритет `Q` на основі арифметики полів Галуа `GF(2^8)`.

### 6.4. Періодичний моніторинг цілісності (Scrubbing)

Для запобігання прихованому пошкодженню секторів (Silent Data Corruption) системний адміністратор налаштовує регулярне фонове перечитування секторів за розкладом cron:

```bash
# Запуск перевірки паритету для md0
echo check > /sys/block/md0/md/sync_action
```

Драйвер ядра послідовно читає кожен страйп, переобчислює XOR-паритет та порівнює його зі збереженим блоком паритету. Якщо виявляється розбіжність, значення лічильника `/sys/block/md0/md/mismatch_cnt` збільшується. Якщо використати `echo repair > /sys/block/md0/md/sync_action`, ядро примусово перепише блок паритету новими обчисленими даними.
