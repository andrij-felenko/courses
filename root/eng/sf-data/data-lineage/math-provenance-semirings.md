# 🧮 Алгебра походження даних: напівкільця Provenance Semirings

У класичній реляційній моделі даних Едгара Кодда реляційна алгебра оперує множинами кортежів. Якщо два кортежі з різних вхідних таблиць після з'єднання та проекції утворюють однаковий вихідний рядок, стандартна семантика множин усуває дублікати й повертає одне значення. У результаті цієї операції втрачається критична інформація: які саме первинні рядки, з яких джерел і за якими правилами сформували цей вихідний стан. Якщо один із вхідних рядків буде змінено, видалено або визнано скомпрометованим, неможливо аналітично з'ясувати, чи збережеться результуючий запис у базі даних без повного повторного виконання всього обчислювального конвеєра.

Математичний апарат напівкілець походження (англ. *Provenance Semirings*), сформульований Тоддом Ґріном, Григорісом Карвунаракісом та Валеріо Танненом у 2007 році, розв'язує цю проблему через формалізм `K`-відношень. Він замінює двійкову наявність кортежу (наявний/відсутній) анотацією з абстрактного напівкільця `K`, перетворюючи реляційну алгебру на універсальну систему обчислення походження, безпекових рівнів доступу, кратності та ймовірностей.

---

### Алгебраїчна структура комутативного напівкільця

Комутативне напівкільце — це алгебраїчна структура `(K, ⊕, ⊗, 0, 1)`, що складається з множини елементів `K`, двох бінарних операцій `⊕` (додавання) та `⊗` (множення) і двох виділених нейтральних елементів `0` та `1`, які задовольняють такі аксіоми для довільних елементів `a, b, c ∈ K`:

1. **Комутативний моноїд додавання `(K, ⊕, 0)`:**
   * Асоціативність: `(a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)`
   * Комутативність: `a ⊕ b = b ⊕ a`
   * Нейтральний елемент: `a ⊕ 0 = a`
2. **Комутативний моноїд множення `(K, ⊗, 1)`:**
   * Асоціативність: `(a ⊗ b) ⊗ c = a ⊗ (b ⊗ c)`
   * Комутативність: `a ⊗ b = b ⊗ a`
   * Нейтральний елемент: `a ⊗ 1 = a`
3. **Дистрибутивність множення відносно додавання:**
   * `a ⊗ (b ⊕ c) = (a ⊗ b) ⊕ (a ⊗ c)`
4. **Анулювання нулем:**
   * `a ⊗ 0 = 0 ⊗ a = 0`

**Семантична інтуїція операцій у базах даних:**
* **Операція додавання `⊕` (альтернативні шляхи походження):** відображає наявність кількох незалежних способів отримати один і той самий результат у базі даних (наприклад, об'єднання `UNION` двох таблиць або усунення дублікатів під час проекції `SELECT DISTINCT`). Результат присутній, якщо він виведений з першого джерела **АБО** з другого.
* **Операція множення `⊗` (композиція та спільна залежність):** відображає одночасну участь кількох елементів у створенні вихідного рядка (наприклад, з'єднання `JOIN` між двома таблицями чи застосування фільтра). Результат формується лише тоді, коли присутній лівий кортеж **ТА** присутній правий кортеж.

### Формалізм `K`-реляційної алгебри

Нехай `U` — фіксована множина всіх можливих кортежів даної схеми. `K`-відношення `R` визначається як функція з скінченним носієм:

```
R: U → K
```

де значення `R(t) ∈ K` є анотацією походження кортежу `t`. Якщо кортеж `t` відсутній у базі даних, його анотація приймає значення нейтрального елемента додавання: `R(t) = 0`.

Базові операції реляційної алгебри позитивних реляційних запитів (RA+) над `K`-відношеннями визначаються за допомогою операцій напівкільця:

**1. Об'єднання відношень (Union `R₁ ∪ R₂`):**
```
(R₁ ∪ R₂)(t) = R₁(t) ⊕ R₂(t)
```
Якщо кортеж присутній в обох вхідних таблицях, його вихідна анотація дорівнює сумі анотацій.

**2. Природне з'єднання (Natural Join `R₁ ⋈ R₂`):**
```
(R₁ ⋈ R₂)(t) = R₁(t[R₁]) ⊗ R₂(t[R₂])
```
де `t[R₁]` та `t[R₂]` — проекції з'єднаного кортежу `t` на схеми таблиць `R₁` та `R₂`. Анотація результату є добутком анотацій вхідних кортежів.

**3. Проекція (Projection `π_A(R)`):**
```
(π_A(R))(t) = ⨁_{t': π_A(t') = t} R(t')
```
Усі вхідні кортежі `t'`, які під час відкидання нецільових стовпців переходять у однаковий результуючий кортеж `t`, сумуються через операцію `⊕`.

**4. Селекція / Фільтрація (Selection `σ_θ(R)`):**
```
(σ_θ(R))(t) = R(t) ⊗ θ(t)
```
де функція предиката `θ(t) = 1`, якщо кортеж `t` задовольняє умову `θ`, і `θ(t) = 0`, якщо умова порушена.

### Ієрархія напівкілець: від Булевого стану до універсальних поліномів

Вибір конкретної множини `K` та операцій `(⊕, ⊗)` визначає тип аналітичної задачі, яка розв'язується над графом даних:

| Тип аналізу | Напівкільце `K` | Операція `⊕` | Операція `⊗` | `0` | `1` | Практичне застосування |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Класична реляційна модель (Set semantics)** | Булеве напівкільце `𝔹 = {0, 1}` | `∨` (диз'юнкція) | `∧` (кон'юнкція) | `0` | `1` | Стандартна перевірка наявності запису в таблиці. |
| **Мультимножинна модель (Bag semantics)** | Натуральні числа `ℕ` | `+` (додавання) | `×` (множення) | `0` | `1` | Обчислення кількості дублікатів рядка (SQL ALL). |
| **Why-provenance (Мінімальні свідки)** | Позитивні булеві формули `PosBool(X)` | `∨` | `∧` | `⊥` | `⊤` | Визначення критичних наборів первинних рядків, достатніх для виведення результату. |
| **How-provenance (Універсальні поліноми)** | Поліноми над змінними `ℕ[X]` | `+` | `·` | `0` | `1` | Точний алгебраїчний вираз походження даних; є вільним напівкільцем над `X`. |
| **Рівні безпеки (Security Lattice)** | Решітка допуску `(𝕃, min, max)` | `min` (найнижчий) | `max` (найвищий) | `TopSecret` | `Public` | Автоматичне обчислення мінімального рівня доступу для перегляду зведеного звіту. |
| **Вартість і затримка (Cost Semiring)** | Тропічне напівкільце `(ℝ⁺ ∪ {∞}, min, +)` | `min` (найдешевший) | `+` (сума затримок) | `∞` | `0` | Оцінка сумарної вартості або часу затримки передачі кортежу через конвеєр. |

### Властивість універсальності поліноміального напівкільця

Напівкільце многочленів з натуральними коефіцієнтами `ℕ[X]`, де кожному вхідному кортежу `t_i` зіставлено унікальну формальну змінну `x_i ∈ X`, є **вільним комутативним напівкільцем**. 

Це означає, що поліном How-provenance містить повну інформацію про обчислення. Для будь-якого іншого напівкільця `K` існує єдиний гомоморфізм `h: ℕ[X] → K`, який дозволяє отримати результат у `K` простим відображенням змінних без повторного виконання запиту над самою базою даних:

```
h(P(x₁, x₂, ..., x_n)) = P(h(x₁), h(x₂), ..., h(x_n))
```

Наприклад, якщо ми знаємо поліном походження рядка, ми можемо за константний час перевірити:
1. **Чи збережеться рядок при видаленні запису `x₁`:** підставити `x₁ = 0` у булевому напівкільці `𝔹`.
2. **Яка кратність дублікатів рядка:** підставити одиниці замість усіх змінних у напівкільці натуральних чисел `ℕ`.
3. **Яка затримка формування рядка:** підставити значення часу відгуку кожного джерела в тропічному напівкільці.

### Наскрізний числовий розрахунок полінома походження

Розглянемо дві таблиці у сховищі даних: таблицю облікових записів користувачів `Users` (U) та таблицю транзакцій `Transactions` (T). Кожному рядку надано унікальну символьну анотацію:

**Таблиця `Users` (U):**
* `u₁ = (user_id: 10, country: "UA")` з тегом `a₁`
* `u₂ = (user_id: 20, country: "PL")` з тегом `a₂`

**Таблиця `Transactions` (T):**
* `t₁ = (tx_id: 501, user_id: 10, amount: 100)` з тегом `b₁`
* `t₂ = (tx_id: 502, user_id: 10, amount: 250)` з тегом `b₂`
* `t₃ = (tx_id: 503, user_id: 20, amount: 400)` з тегом `b₃`

Виконується аналітичний запит для побудови звіту: *«Знайти країни, користувачі з яких здійснили транзакції»*:

```
Q = π_{country}(Users ⋈_{Users.user_id = Transactions.user_id} Transactions)
```

Обчислимо поліном походження для значення результату `("UA")` крок за кроком:

```
Provenance("UA")
= (π_{country}(U ⋈ T))("UA")                                   [застосування означення проекції π]
= ⨁_{row: row.country = "UA"} (U ⋈ T)(row)                     [групування кортежів, де country = "UA"]
= (U ⋈ T)(u₁ ⋈ t₁) ⊕ (U ⋈ T)(u₁ ⋈ t₂)                          [підстановка з'єднаних кортежів (u₁⋈t₁) та (u₁⋈t₂)]
= (U(u₁) ⊗ T(t₁)) ⊕ (U(u₁) ⊗ T(t₂))                            [застосування означення природного з'єднання ⋈]
= (a₁ ⊗ b₁) ⊕ (a₁ ⊗ b₂)                                        [підстановка символьних тегів рядків]
= a₁ ⊗ (b₁ ⊕ b₂)                                               [дистрибутивність: винесення спільного множника a₁]
```

Отриманий поліном `P = a₁ · b₁ + a₁ · b₂ = a₁ · (b₁ + b₂)` описує повну структуру залежностей:

1. **Аналіз стійкості до видалення (Impact of Deletion):**
   * Якщо транзакція `t₁` скасовується і видаляється з первинної бази (`b₁ = 0`), оцінимо значення полінома:
     ```
     P_{b₁=0}
     = a₁ · (0 + b₂)                                           [підстановка нуля замість змінної b₁]
     = a₁ · b₂                                                 [нейтральний елемент додавання: 0 + b₂ = b₂]
     ```
     Оскільки `a₁ · b₂ ≠ 0`, рядок `("UA")` гарантовано залишається у звіті завдяки транзакції `b₂`.
   * Якщо видаляється профіль користувача `u₁` (`a₁ = 0`):
     ```
     P_{a₁=0}
     = 0 · (b₁ + b₂)                                           [підстановка нуля замість змінної a₁]
     = 0                                                       [анулювання множенням на нуль]
     ```
     Рядок `("UA")` миттєво зникає з результату.

2. **Оцінка безпеки доступу (Security Evaluation):**
   Нехай профіль `a₁` має рівень секретності `Public` (відкритий), транзакція `b₁` — `Restricted` (обмежений), а транзакція `b₂` — `Secret` (таємний). Застосуємо гомоморфізм у напівкільце безпеки `(𝕃, min, max)`:
   ```
   Security("UA")
   = max(Public, min(Restricted, Secret))                      [підстановка рівнів безпеки у вираз a₁ ⊗ (b₁ ⊕ b₂)]
   = max(Public, Restricted)                                   [операція min обирає менш суворий рівень допуску]
   = Restricted                                                [операція max визначає обов'язковий допуск для перегляду]
   ```
   Отже, користувач із допуском `Restricted` має право бачити цей агрегований рядок, оскільки його можна підтвердити відкритою інформацією `a₁` та транзакцією `b₁`.

Теорія напівкілець доводить, що простеження даних — це не просто емпіричне малювання стрілок на діаграмах, а строга алгебраїчна дисципліна, яка дозволяє формально верифікувати коректність обчислень у будь-якому конвеєрі даних.
