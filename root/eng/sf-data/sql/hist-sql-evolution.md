# 📜 Історія виникнення SQL: від SEQUEL до міжнародного стандарту

Коли у 1970 році Едгар Кодд опублікував математичні основи реляційної моделі, робота з даними вимагала володіння апаратом математичної логіки першого порядку та реляційної алгебри. Вирази на зразок `π_{name}(σ_{salary > 5000}(Employees ⋈ Departments))` були бездоганними з погляду формальної коректності, але абсолютно недоступними для прикладних програмістів системної обробки інформації та бізнес-аналітиків 1970-х років. Щоб перетворити теоретичну модель на комерційний інструмент, лабораторії IBM у Сан-Хосе знадобилася мова, яка поєднувала б математичну строгість реляційного числення з людиночитаним синтаксисом англійської ділової прози.

## Зародження SEQUEL у надрах проєкту System R (1974–1975)

У 1973 році молоді дослідники IBM Дональд Чемберлін (Donald Chamberlin) та Реймонд Бойс (Raymond Boyce) розпочали роботу над інтерфейсом користувача для експериментальної реляційної системи System R. Вони поставили за мету створити мову для людей, які не мають фундаментальної математичної підготовки, але регулярно формулюють складні аналітичні запити до сховищ даних.

Початковий варіант мови отримав назву **SQUARE** (Specifying Queries As Relational Expressions). Він спирався на специфічну двовимірну нотацію з підрядковими індексами для проекцій та надрядковими для позиційних умов вибірки. Практичні випробування показали, що набір таких виразів на телетайпах і терміналах того часу є вкрай незручним і призводить до частих помилок друку.

У 1974 році Чемберлін і Бойс опублікували статтю «SEQUEL: A Structured English Query Language», де запропонували лінійний синтаксис на основі ключових слів природної англійської мови: `SELECT` (вибрати), `FROM` (звідки), `WHERE` (де / за умови). Мова будувалася навколо концепції блоку запиту:

```sql
SELECT NAME, SALARY
FROM EMPLOYEES
WHERE DEPT = 'ACCOUNTING'
```

Реймонд Бойс трагічно помер у 1974 році у віці 26 років невдовзі після представлення мови, залишивши по собі також нормальну форму Бойса — Кодда (BCNF). Дональд Чемберлін продовжив розвиток системи разом із командою розробників System R.

Коли у 1977 році IBM готувала випуск документації до оновленої версії SEQUEL/2, виявилося, що торговельна марка «SEQUEL» уже була зареєстрована британською авіабудівною компанією Hawker Siddeley для позначення бортового електронного обладнання. Щоб уникнути судового позову, інженери скоротили назву до абревіатури **SQL** (Structured Query Language). Попри те, що офіційно SQL вимовляється як послідовність окремих літер («ес-к’ю-ел»), історична вимова «сіквел» збереглася в середовищі інженерів до сьогодні.

## Конкуренція парадигм: SQL проти QUEL (1976–1982)

Паралельно з IBM у Каліфорнійському університеті в Берклі під керівництвом Майкла Стоунбрейкера (Michael Stonebraker) розроблялася альтернативна реляційна СУБД Ingres. Стоунбрейкер створив власну мову запитів — **QUEL** (Query Language), яка базувалася на численні кортежів Кодда.

QUEL мала значно чистішу та ортогональнішу математичну граматику порівняно з раннім SQL:
- У QUEL не було специфічних нестиковок між агрегатними функціями та підзапитами.
- Операції фільтрації та проекції формулювалися без суперечливих правил псевдонімів.
- Мова не мала неоднозначностей під час роботи з тризначною логікою порівнянь.

Однак корпоративна вага IBM та швидкість комерціалізації вирішили долю протистояння. У 1977 році підприємець Ларрі Еллісон (Larry Ellison) разом із Бобом Майнером (Bob Miner) та Едом Оутсом (Ed Oates) ознайомився з відкритими технічними звітами IBM про архітектуру System R та синтаксис мови SQL. Зрозумівши комерційний потенціал технології, вони заснували компанію Software Development Laboratories (згодом перейменовану на Relational Software Inc., а пізніше — Oracle Corporation).

У 1979 році Relational Software випустила на ринок систему **Oracle V2** для міні-комп'ютерів DEC PDP-11 та VAX. Це була перша комерційно доступна реляційна база даних із підтримкою SQL. Сама IBM запізнилася з комерційним релізом: її система SQL/DS для мейнфреймів з'явилася лише в 1981 році, а флагманська DB2 — у 1983 році.

Поява Oracle та DB2 спричинила мережевий ефект: великі корпоративні замовники почали вимагати підтримку SQL від усіх постачальників програмного забезпечення, що витіснило Ingres QUEL на периферію ринку та закріпило SQL як де-факто стандарт галузі.

## Епоха стандартизації: Еволюція ANSI/ISO SQL

Швидке зростання ринку призвело до фрагментації: кожен виробник СКБД додавав власні синтаксичні діалекти, специфічні типи даних та нестандартні системні функції. Для захисту інвестицій клієнтів у прикладний код Американський національний інститут стандартів (ANSI) та Міжнародна організація зі стандартизації (ISO) розпочали процес формальної стандартизації мови.

```
SQL-86 (ANSI X3.135-1986 / ISO 9075:1987)
  └─ Базова фіксація граматики: SELECT, INSERT, UPDATE, DELETE
     Відсутність оголошення первинних і зовнішніх ключів у DDL

SQL-89 (ANSI X3.135-1989)
  └─ Додано підтримку обмежень цілісності: PRIMARY KEY, UNIQUE, FOREIGN KEY (REFERENCES)

SQL-92 (SQL2, ISO/IEC 9075:1992)
  └─ Поворотний стандарт: явний синтаксис JOIN (INNER, LEFT, RIGHT, FULL, CROSS)
     Підтримка виразів CASE, скалярних підзапитів, тимчасових таблиць, SQLSTATE

SQL:1999 (SQL3, ISO/IEC 9075:1999)
  └─ Рекурсивні спільні табличні вирази (WITH RECURSIVE)
     Віконні функції OVER (PARTITION BY ... ORDER BY ...)
     Тригери, користувацькі типи (UDT), регулярні вирази

SQL:2003
  └─ Специфікація XML (SQL/XML), конструкція MERGE, генерація послідовностей

SQL:2011
  └─ Темпоральні таблиці (періоди системного та дійсного часу)

SQL:2016
  └─ Вбудована підтримка та оператори для документів формату JSON

SQL:2023 (ISO/IEC 9075:2023)
  └─ Графові запити на основі властивостей (Property Graph Queries, SQL/PGQ)
     Подальше розширення функцій опрацювання JSON
```

### Ключові віхи розвитку мови

Найважливішим етапом розвитку став стандарт **SQL-92**. До його появи з'єднання таблиць записувалося виключно через перелік у секції `FROM` із фільтром у `WHERE`:

```sql
/* Застарілий синтаксис (до SQL-92) */
SELECT o.id, c.name
FROM orders o, customers c
WHERE o.customer_id = c.id AND o.total > 1000;
```

Такий підхід змішував умови з'єднання відношень та умови фільтрації кортежів, що унеможливлювало перевірку повноти плану на етапі синтаксичного аналізу та ускладнювало написання зовнішніх з'єднань (outer joins). Стандарт SQL-92 ввів явний оператор `JOIN ... ON ...`, що став основою сучасного аналізу запитів:

```sql
/* Стандартний явний синтаксис SQL-92 */
SELECT o.id, c.name
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE o.total > 1000;
```

Стандарт **SQL:1999** подолав фундаментальне теоретичне обмеження реляційної алгебри — нездатність обчислювати транзитивні замикання графів та ієрархій. Завдяки введенню рекурсивних запитів `WITH RECURSIVE` SQL став повною за Тюрінгом мовою програмування.

Стандарт **SQL:2023** інтегрував у реляційний простір можливості графових баз даних через специфікацію **SQL/PGQ** (Property Graph Queries), надавши змогу знаходити шляхи у графах за допомогою синтаксису зіставлення зразків (`MATCH (a)-[:FRIEND_OF]->(b)`), зберігаючи водночас транзакційні гарантії та оптимізаційні можливості реляційного рушія.

Еволюція мови демонструє збереження її ядра: декларативний принцип «описуй результат, а не спосіб його отримання», закладений Чемберліном і Бойсом у 1974 році, залишається незмінним фундаментом роботи з даними вже понад півстоліття.
