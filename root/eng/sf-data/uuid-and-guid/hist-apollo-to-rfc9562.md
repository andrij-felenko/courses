# 📜 Від Apollo NCS до RFC 9562: як 128-бітний ідентифікатор став світовим стандартом

Коли в середині 1980-х років розподілені обчислювальні мережі вийшли за межі експериментальних лабораторій, інженери зіткнулися з принциповою перепоною: як вузлам мережі посилатися на віддалені процедури, інтерфейси та файлові об'єкти без центрального сервера реєстрації імен. Будь-яка централізована база даних вимагала синхронного мережевого звернення для виділення чергового порядкового номера, що створювало єдину точку відмови й критичне вузьке місце за затримкою.

Відповіддю на цей виклик стала концепція універсального унікального ідентифікатора, розроблена в стінах компанії Apollo Computer для системи Network Computing System (NCS) у 1987 році. Інженери Джим Вей (Jim Wei) та Пол Ліч (Paul Leach) запропонували фіксований 128-бітний двійковий ідентифікатор UID (Unique Identifier), який складався з 48-бітної апаратної MAC-адреси мережевої карти, 32-бітного лічильника часу та прапорців локального стану. Поєднання фізичної унікальності мережевого інтерфейсу та монотонності системного годинника гарантувало, що два незалежні комп'ютери Apollo ніколи не згенерують однаковий ідентифікатор, навіть перебуваючи в ізольованих сегментах локальної мережі.

### Стандартизація в OSF DCE 1.1

На початку 1990-х років консорціум Open Software Foundation (OSF) обрав систему Apollo NCS за основу для свого амбітного стандарту розподіленого обчислювального середовища — Distributed Computing Environment (DCE). У версії DCE 1.1 RPC утиліту генерації та сам двійковий формат перейменували на UUID (Universally Unique Identifier).

Саме у специфікації OSF DCE з'явилася перша формальна класифікація версій та бітова розкладка, знайома розробникам і сьогодні. Часову мітку перевели на 60-бітне число з дискретністю 100 наносекунд, відраховане від опівночі 15 жовтня 1582 року — дати введення григоріанського календаря папою Григорієм XIII. Такий вибір виключав накладання дат із системами, що рахували час від початку епохи Unix (1970 рік), і забезпечував запас безперервного ходу годинника аж до 3400 року нашої ери.

Для запобігання колізіям під час переведення годинника назад або клонування системи OSF додала 14-бітне поле послідовності годинника (`clock_seq`), яке збільшувалося щоразу, коли годинник виявлявся немонотонним. Ця схема отримала назву UUID версії 1.

### Траєкторія Microsoft: поява GUID і COM

Паралельно з розвитком Unix-середовища компанія Microsoft у 1993 році розробляла компонентну модель Component Object Model (COM) для операційної системи Windows NT. Щоб незалежні постачальники програмного забезпечення могли реєструвати класи (`CLSID`) та двійкові інтерфейси (`IID`) у системному реєстрі без координації з Редмондом, Microsoft запозичила специфікацію UUID з OSF DCE, назвавши її глобально унікальним ідентифікатором — GUID (Globally Unique Identifier).

Функція Windows API `CoCreateGuid()` стала основним генератором ідентифікаторів у світі Windows. Проте реалізація Microsoft містила архітектурну відмінність у способі збереження структури в оперативній пам'яті: якщо стандарт DCE визначав передачу полів у мережевому порядку байтів (Big-Endian), то структура `GUID` у пам'яті процесорів архітектури x86 зберігала поля `Data1`, `Data2` та `Data3` у порядку Little-Endian. Ця розбіжність стала джерелом системних помилок інтероперабельності на наступні десятиліття.

У 1999 році спалахнув гучний скандал довкола конфіденційності, пов'язаний із поширенням поштового хробака Melissa. Слідчі виявили, що документи Microsoft Word та ідентифікатори COM містили UUIDv1, у 48-бітній частині яких зберігалася реальна фізична MAC-адреса мережевої карти комп'ютера автора вірусу. Це дозволило правоохоронцям прямо зіставити заражений файл із фізичним апаратним забезпеченням конкретного підозрюваного. Стало очевидним, що виставлення апаратних адрес у глобальний простір становить серйозну загрозу приватності користувачів.

### RFC 4122: єдиний стандарт Інтернету

У відповідь на накопичені проблеми та з метою уніфікації форматів інженери Пол Ліч (Microsoft), Майкл Міллінг (VeriSign) та Річ Зальц (DataPower) у липні 2005 року випустили стандарт IETF **RFC 4122** під назвою «A Universally Unique IDentifier (UUID) URN Namespace».

Стандарт RFC 4122 канонізував чотири основні версії UUID:
1. **Версія 1**: класична схема на базі 60-бітного григоріанського часу та MAC-адреси (із рекомендацією використовувати випадкове 48-бітне число з піднятим бітом Multicast замість справжньої апаратної адреси заради приватності).
2. **Версія 3**: детермінований ідентифікатор, обчислений через геш MD5 від простору імен і довільного рядка.
3. **Версія 4**: повністю псевдовипадковий ідентифікатор, де 122 зі 128 бітів заповнюються криптографічно стійким генератором випадкових чисел (CSPRNG).
4. **Версія 5**: аналог версії 3, але на базі стійкішого криптографічного гешу SHA-1.

Саме UUIDv4 став фактичним стандартом для вебзастосунків, мікросервісів та розподілених баз даних завдяки простоті генерації без звернення до апаратного годинника чи мережевих карт.

### Криза випадковості та шлях до RFC 9562

Масовий перехід індустрії на реляційні та NoSQL бази даних у 2010-х роках виявив фундаментальну ваду випадкового UUIDv4. Випадковий розподіл 128-бітних значень руйнував локальність даних у структурах індексів B-Tree та LSM-Tree. При кожній вставці нового рядка СКБД мусила модифікувати випадкову сторінку індексу на диску, що спричиняло масове розщеплення сторінок (page splits), падіння коефіцієнта заповнення до 50% і катастрофічну деградацію пропускної здатності дискової підсистеми.

Спільнота розробників відповіла появою неофіційних форматів: ULID (Universally Unique Lexicographically Sortable Identifier, запропонований Алізайном Фірастою у 2016 році), KSUID (Segment, 2017) та Snowflake (Twitter, 2010). Усі вони базувалися на єдиному принципі: старші біти ідентифікатора мусять містити часову мітку Unix, забезпечуючи природне хронологічне сортування.

Бачачи роздробленість екосистеми, робоча група IETF на чолі з Бредом Пібоді (Brad Peabody) та Кайзером Девісом (Kyzer Davis) підготувала масштабний перегляд стандарту. У травні 2024 року IETF опублікувала **RFC 9562**, який повністю замінив і скасував застарілий RFC 4122.

Новий стандарт ввів три офіційні версії:
- **UUIDv6**: перевпорядкована версія UUIDv1 для сумісності з легасі-системами, де часова мітка розташована старшими бітами вперед.
- **UUIDv7**: сучасний стандарт розподілених ідентифікаторів, що комбінує 48-бітний час Unix у мілісекундах, 12-бітну субмілісекундну точність/лічильник і 62 біти криптографічної випадковості.
- **UUIDv8**: гнучкий формат для нестандартних корпоративних та апаратних розкладок зі збереженням стандартного 128-бітного пакування.

Шлях від експериментального ідентифікатора робочих станцій Apollo до сучасного стандарту RFC 9562 зайняв майже чотири десятиліття. Сьогодні 128-бітний UUID залишається універсальною основою безреєстрової координації розподілених систем планетарного масштабу.
