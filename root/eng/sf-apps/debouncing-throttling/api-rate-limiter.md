# 📋 Специфікація інтерфейсів debounce та throttle

Довідкова специфікація контрактів, сигнатур, структур даних, часових інваріантів та методів керування життєвим циклом для сімейства функцій-обмежувачів частоти викликів (`debounce`, `throttle` та `rafThrottle`).

Усі наведені інтерфейси реалізують строгий розподіл відповідальності між отриманням вхідного потоку подій, квантуванням часу та безпосереднім виконанням цільового коду.

## Структури конфігурації та типи даних

```ts
export interface DebounceOptions {
  leading?: boolean;
  trailing?: boolean;
  maxWait?: number;
}

export interface ThrottleOptions {
  leading?: boolean;
  trailing?: boolean;
}

export interface DebouncedFunction<TArgs extends any[], TReturn> {
  (...args: TArgs): TReturn | undefined;
  cancel(): void;
  flush(): TReturn | undefined;
  isPending(): boolean;
}

export interface RafThrottledFunction<TArgs extends any[]> {
  (...args: TArgs): void;
  cancel(): void;
}
```

## Функція `debounce`

Створює функцію-обгортку, яка відкладає виконання цільової функції `fn` доти, доки від моменту останнього надходження вхідної події не мине інтервал затишшя тривалістю `wait` мілісекунд, або доки сумарний час очікування не досягне граничного ліміту `maxWait`.

### Сигнатура

```ts
function debounce<TArgs extends any[], TReturn>(
  fn: (...args: TArgs) => TReturn,
  wait: number,
  options?: DebounceOptions
): DebouncedFunction<TArgs, TReturn>;
```

### Детальний опис параметрів

- `fn`: Цільова функція довільної арності, виконання якої необхідно прорідити. Функція може бути як синхронною, так і асинхронною (повертати `Promise`). Обгортка гарантує передачу останнього збереженого контексту `this` та актуального набору аргументів під час фактичного запуску.
- `wait`: Числове значення затримки в мілісекундах. Визначає тривалість «вікна тиші», протягом якого не повинно відбуватися жодного нового виклику обгортки для того, щоб спрацював відкладений запуск на задньому фронті. Значення автоматично приводиться до невід'ємного числа.
- `options.leading`: Булевий прапорець (за замовчуванням `false`). Якщо встановлено в `true`, функція викликається негайно на першу подію в серії, після чого переходить у режим очікування затишшя, блокуючи проміжні повторні виклики.
- `options.trailing`: Булевий прапорець (за замовчуванням `true`). Якщо встановлено в `true`, функція викликається після завершення інтервалу затишшя `wait` з останніми переданими аргументами. Якщо обидва прапорці `leading` та `trailing` встановлено в `true`, функція викликається двічі: перший раз негайно на старті, другий раз — наприкінці серії подій (лише за умови, що під час паузи надходили проміжні виклики).
- `options.maxWait`: Числове обмеження максимального часу затримки в мілісекундах (за замовчуванням вимкнено). Встановлює жорстку верхню межу між моментом першої події у серії та фактичним виконанням `fn`. Якщо значення `maxWait` менше за `wait`, воно автоматично нормалізується до величини `wait`.

### Семантика повертаного значення

Виклик функції-обгортки повертає значення типу `TReturn | undefined`.

Якщо функція ще жодного разу не виконувалася (наприклад, перебуває у стані очікування першого заднього фронту), обгортка повертає `undefined`. Якщо цільова функція вже виконувалася на передньому фронті або на попередніх ітераціях, обгортка повертає збережений результат останнього фактичного виконання. Це дозволяє використовувати дебаунс у місцях, де очікується стабільне значення стану.

### Методи життєвого циклу обгортки

Екземпляр `DebouncedFunction` містить три допоміжні методи для інтеграції з життєвим циклом клієнтських компонентів:

#### Метод `cancel(): void`
- Примусово зупиняє активний макрозадачний таймер (`clearTimeout`).
- Обнуляє внутрішні посилання на аргументи виклику (`lastArgs = undefined`) та контекст (`lastThis = undefined`), дозволяючи збирачу сміття негайно звільнити ресурси.
- Скидає часові лічильники `lastCallTime` та `lastInvokeTime` у нуль.
- Після виклику `cancel()` наступне надходження події розглядається ядром як абсолютно новий старт серії, що викликає виконання `leadingEdge` у разі ввімкненого прапорця `leading`.

#### Метод `flush(): TReturn | undefined`
- Якщо в поточний момент часу є запланований таймер очікування, негайно скасовує його та синхронно викликає цільову функцію `fn` з останніми збереженими аргументами.
- Повертає щойно обчислений результат виконання `fn`.
- Якщо функція перебувала у стані спокою (немає активного таймера), метод повертає результат попереднього виконання без повторного запуску `fn`.
- Застосовується перед збереженням форм, закриттям модальних вікон або відправкою звітів на сервер, коли неприпустимо втрачати останні дані користувача, що перебувають у черзі очікування.

#### Метод `isPending(): boolean`
- Повертає булеве значення `true`, якщо в системі існує активний відкладений таймер або очікування `maxWait`, і `false`, якщо функція перебуває у стані спокою (idle).

## Функція `throttle`

Створює функцію-обгортку, яка гарантує періодичне виконання цільової функції `fn` не частіше ніж один раз за заданий фіксований квант часу `wait`.

### Сигнатура

```ts
function throttle<TArgs extends any[], TReturn>(
  fn: (...args: TArgs) => TReturn,
  wait: number,
  options?: ThrottleOptions
): DebouncedFunction<TArgs, TReturn>;
```

### Параметри

- `fn`: Цільова функція, частоту виконання якої необхідно обмежити.
- `wait`: Тривалість часового вікна (кванта) в мілісекундах.
- `options.leading`: Булевий прапорець (за замовчуванням `true`). Дозволяє негайний виклик на старті кожного нового часового вікна.
- `options.trailing`: Булевий прапорець (за замовчуванням `true`). Дозволяє відкладений виклик наприкінці часового вікна з останніми отриманими координатами або значеннями, якщо під час вікна надходили додаткові події.

### Математичний зв'язок із ядром `debounce`

Тротлінг є окремим випадком дебаунсу з примусовим обмеженням максимального часу очікування. Семантично виклик `throttle(fn, wait, options)` повністю еквівалентний такій конфігурації ядра:

```ts
debounce(fn, wait, {
  leading: options.leading ?? true,
  trailing: options.trailing ?? true,
  maxWait: wait,
})
```

## Функція `rafThrottle`

Спеціалізований механізм квантування, призначений для задач прямої маніпуляції з деревом DOM, синхронізації стилів анімації, обробки перетягування (Drag & Drop) та відстеження вказівника миші на Canvas.

На відміну від таймерів `setTimeout`, які працюють у черзі макрозадач із нефіксованим джиттером операційної системи, `rafThrottle` прив'язує виконання функції безпосередньо до фази підготовки кадру браузера (VSync).

### Сигнатура

```ts
function rafThrottle<TArgs extends any[]>(
  fn: (...args: TArgs) => void
): RafThrottledFunction<TArgs>;
```

### Поведінкові інваріанти `rafThrottle`

1. **Коалесценція подій у кадрі.** Якщо між двома послідовними кадрами монітора (інтервал 16.67 мс для 60 Гц або 8.33 мс для 120 Гц) надходить 20 подій `pointermove`, обгортка зберігає лише останні координати `(x, y)` і планує рівно один виклик `requestAnimationFrame`. Усі проміжні значення відкидаються без навантаження на конвеєр розрахунку макета (Layout) та малювання (Paint).
2. **Автоматична пауза у фонових вкладках.** Браузери повністю призупиняють виклики `requestAnimationFrame`, коли вкладка стає неактивною (`document.hidden === true`). Завдяки цьому `rafThrottle` автоматично припиняє споживання ресурсів процесора та батареї пристрою без необхідності ручного контролю фонового стану.
3. **Метод `cancel()`.** Викликає системну функцію `cancelAnimationFrame(rafId)` та очищає внутрішні посилання на аргументи, запобігаючи виконанню застарілих дій після демонтажу віджета.

## Порівняльна матриця конфігурацій обмежувачів

Нижче наведено порівняльний аналіз режимів роботи обмежувачів за основними технічними характеристиками:

| Режим | Початковий відгук | Поведінка під час серії | Фінальний стан | Оптимальна сфера застосування |
| :--- | :--- | :--- | :--- | :--- |
| **Trailing Debounce** (`leading: false, trailing: true`) | Затримка на `wait` мс | Блокується (таймер скидається) | Виконується через `wait` мс після останньої події | Автодоповнення пошуку, валідація полів форми, автозбереження чернетки. |
| **Leading Debounce** (`leading: true, trailing: false`) | Негайний (0 мс) | Ігнорується до настання паузи `wait` | Не виконується | Захист кнопок від подвійного кліку, запобігання дублюванню відправки замовлення. |
| **Debounce + maxWait** (`trailing: true, maxWait: T`) | Затримка на `wait` мс | Періодично спрацьовує кожні `maxWait` мс при шквалі | Виконується через `wait` після затишшя | Автозбереження коду в онлайн-редакторах під час швидкого безперервного набору. |
| **Throttle (leading + trailing)** (`leading: true, trailing: true`) | Негайний (0 мс) | Спрацьовує не частіше 1 разу на `wait` мс | Гарантовано виконується з фінальними даними | Нескінченна прокрутка (infinite scroll), індикатори читання статті (scroll spy). |
| **rafThrottle** (`requestAnimationFrame`) | Синхронізовано з VSync (0..16.6 мс) | Рівно 1 виклик на один кадр дисплея | Гарантовано оновлює останню позицію | Перетягування елементів (Drag & Drop), малювання на Canvas, анімація курсора. |

## Крайові випадки та гарантії надійності

### Обробка помилок та винятків
Якщо цільова функція `fn` викидає синхронний виняток (`throw new Error()`), виняток поширюється у стек виклику поточного тіку таймера або функції-обгортки. При цьому внутрішній стан обмежувача залишається коректним: дескриптор `timerId` очищається, а часова мітка `lastInvokeTime` фіксує момент спроби виконання, запобігаючи зацикленню помилки.

У разі передачі асинхронної функції, що повертає `Promise`, обмежувач не перехоплює відхилені проміси (rejections) автоматично. Клієнтський код повинен самостійно додавати обробники `.catch()` або використовувати конструкції `try/catch` всередині переданого колбека, щоб уникнути подій `unhandledrejection`.

### Затискання таймерів у фонових вкладках (Timer Clamping)
Згідно зі специфікацією HTML Living Standard, браузери примусово обмежують мінімальний інтервал вкладених таймерів `setTimeout` до 4 мілісекунд, а для неактивних фонових вкладок — до 1000 мілісекунд (для збереження енергії акумулятора). Розробники повинні враховувати, що `debounce` або `throttle` із параметром `wait: 100` у фоновій вкладці виконуватиметься з реальною дискретністю приблизно 1000 мс. Якщо для фонової синхронізації потрібна точна часова сітка, завдання слід виносити у Web Worker, де таймери не піддаються фоновому тротлінгу рендерингу.
