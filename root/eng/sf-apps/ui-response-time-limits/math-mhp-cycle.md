# 🧮 Математична модель Human Processor: перцептивний, когнітивний і моторний цикли

Модель процесора людини (*Model Human Processor*, MHP), запропонована Стюартом Кардом, Томасом Мораном та Алленом Ньюеллом у 1983 році, описує когнітивну систему людини за аналогією з обчислювальною архітектурою: сенсорні буфери пам'яті, конвеєр дискретних процесорів із фіксованими циклами квантування та робоча пам'ять із характеристичним експоненційним згасанням інформації.

Ця модель дає змогу математично розрахувати час реакції оператора на стимули, проаналізувати стійкість візуально-моторного зворотного зв'язку та строго довести фундаментальні часові пороги взаємодії.

## Часові константи підсистем людини

Кожен із трьох процесорів моделі MHP має власний цикл квантування часу, який усереднюється за результатами хронометричних психофізичних експериментів. Оскільки параметри різняться залежно від фізіологічного стану, віку та рівня натренованості оператора, модель задає діапазон значень: «номінальне» (середньостатистичне), «швидке» (досвідчений або зосереджений користувач) та «повільне» (втомлений або непопереджений користувач).

```
T_p (перцептивний процесор) = 100 мс   [діапазон: 50 – 200 мс]
T_c (когнітивний процесор)   =  70 мс   [діапазон: 25 – 170 мс]
T_m (моторний процесор)      =  70 мс   [діапазон: 30 – 100 мс]
```

Сенсорна зорова пам'ять (*Visual Image Store*, VIS) зберігає нестиснутий зоровий образ протягом часу:

```
tau_vis = 200 мс   [діапазон: 90 – 1000 мс]
```

Робоча короткострокова пам'ять (*Working Memory*, WM) має місткість `7 ± 2` інформаційні чанки (за Міллером, 1956) або `4 ± 1` чанки для складних некорельованих понять (за Кованом, 2001) із часом напіврозпаду неповторюваного чанка:

```
tau_wm = 7.0 с   [діапазон: 5 – 226 с залежно від кількості чанків]
```

## Розрахунок часу простої реакції

Час простої сенсомоторної реакції `T_sr` (*Simple Reaction Time*) — це тривалість від моменту появи візуального стимулу на екрані (наприклад, зміна кольору індикатора) до моменту фізичного натискання клавіші користувачем.

У найпростішому випадку конвеєр складається з послідовного спрацьовування трьох процесорів:

```
T_sr = T_p + T_c + T_m
```

Розрахунок для трьох режимів оператора:

**1. Номінальний розрахунок (середній користувач):**

```
T_sr_nom
= T_p_nom + T_c_nom + T_m_nom    [сума трьох стадій конвеєра]
= 100 + 70 + 70                  [підстановка середніх значень у мс]
= 240 мс                         [номінальний час простої реакції]
```

**2. Швидкий режим (висока готовність і очікування стимулу):**

```
T_sr_fast
= T_p_fast + T_c_fast + T_m_fast [мінімальні значення діапазонів]
= 50 + 25 + 30                   [підстановка екстремумів у мс]
= 105 мс                         [фізіологічна нижня межа реакції]
```

**3. Повільний режим (розсіяна увага або несподіваний стимул):**

```
T_sr_slow
= T_p_slow + T_c_slow + T_m_slow [максимальні значення діапазонів]
= 200 + 170 + 100                [підстановка верхніх меж у мс]
= 470 мс                         [час реакції при розсіяній увазі]
```

Звідси видно: навіть при максимальній концентрації людина не здатна фізично зреагувати на візуальну подію швидше ніж за `≈100 мс`.

## Час вибору за законом Гіка-Гаймана

Коли користувач повинен не просто зреагувати на єдиний сигнал, а вибрати один із `n` рівноймовірних варіантів (наприклад, пункт випадаючого списку або кнопку на панелі), когнітивний процесор виконує кілька циклів зіставлення інформації.

Час прийняття рішення моделюється законом Гіка-Гаймана (*Hick-Hyman Law*), де когнітивна складова пропорційна ентропії вибору:

```
T_choice = T_p + I_c · log2(n + 1) + T_m
```

де `I_c` — коефіцієнт когнітивної обробки біта інформації (типово `I_c ≈ T_c ≈ 70–100 мс/біт`).

**Розрахунок часу реакції для меню з n = 8 пунктів:**

```
T_choice_8
= T_p + T_c · log2(8 + 1) + T_m    [формула вибору з 8 альтернатив]
= 100 + 70 · log2(9) + 70          [підстановка номінальних параметрів]
= 100 + 70 · 3.170 + 70            [log2(9) ≈ 3.170 біт]
= 100 + 221.9 + 70                 [час когнітивного зіставлення]
≈ 392 мс                           [сумарний час вибору та натискання]
```

Кожне подвоєння варіантів вибору в інтерфейсі додає приблизно `70 мс` до затримки реакції людини.

## Замкнений контур візуально-моторного керування

Коли користувач виконує неперервну коригувальну дію (наприклад, тягне повзунок слайдера, вирівнює вікно мишею або веде курсор до дрібної цілі), мозок працює в режимі замкненого контуру зворотного зв'язку зі зворотним зв'язком від дисплея.

Кожен крок коригування траєкторії руху пальця/миші займає один повний цикл петлі:

```
T_loop = T_p + T_c + T_m + T_sys
```

де `T_sys` — час затримки між апаратною подією миші та відображенням оновленого пікселя на екрані монітора.

Якщо системна затримка задовольняє умову:

```
T_sys ≤ T_p   (тобто T_sys ≤ 100 мс)
```

мозок встигає зінтегрувати новий візуальний стан у той самий перцептивний квант, у якому триває моторний контроль. Рух сприймається як гладкий, а помилка позиціювання компенсується без коливань навколо цілі.

Якщо ж затримка системи перевищує перцептивний квант (`T_sys > 100 мс`), виникає фазовий зсув у контурі керування. Моторний процесор генерує наступну мікрокоманду руху на основі застарілого візуального кадру. Це призводить до динамічного перевищення амплітуди (*overshoot*) і змушує людину робити додаткові коливальні рухи для наведення на ціль.

## Модель згасання робочої пам'яті та поріг 10 секунд

Ймовірність збереження одиниці інформації (чанка контексту поточної задачі) в робочій пам'яті без активного повторення описується експоненційною моделлю згасання:

```
P_retain(t) = e^(-t / tau_wm)
```

де `tau_wm ≈ 7.0 с` — стала часу розпаду активного сліду пам'яті при когнітивному завантаженні іншими процесами (за дослідженнями Петерсона й Петерсон, 1959).

Обчислимо частку збереженого контексту задачі для різних пауз очікування відповіді від системи:

**1. Пауза t = 0.1 с (поріг прямої маніпуляції):**

```
P_retain(0.1)
= e^(-0.1 / 7.0)      [підстановка t = 0.1 с та tau = 7.0 с]
= e^(-0.0143)         [показник степеня]
≈ 0.986               [збережено 98.6% контексту]
```

**2. Пауза t = 1.0 с (поріг збереження потоку думок):**

```
P_retain(1.0)
= e^(-1.0 / 7.0)      [підстановка t = 1.0 с]
= e^(-0.1429)         [показник степеня]
≈ 0.867               [збережено 86.7% контексту]
```

При затримці в 1 секунду понад 86% асоціативних зв'язків поточної підзадачі залишаються активними в робочій пам'яті. Людина продовжує міркування без додаткових зусиль на пригадування.

**3. Пауза t = 5.0 с (проміжний поріг системного тайм-ауту):**

```
P_retain(5.0)
= e^(-5.0 / 7.0)      [підстановка t = 5.0 с]
= e^(-0.7143)         [показник степеня]
≈ 0.489               [збережено лише 48.9% контексту]
```

**4. Пауза t = 10.0 с (поріг утримання фокусу уваги):**

```
P_retain(10.0)
= e^(-10.0 / 7.0)     [підстановка t = 10.0 с]
= e^(-1.4286)         [показник степеня]
≈ 0.240               [збережено лише 24.0% контексту]
```

При затримці в 10 секунд рівень збереження контексту падає нижче 25%. Мозок фіксує зупинку припливу інформації та перемикає увагу на інші зовнішні або внутрішні стимули.

Щоб відновити контекст після такої паузи, користувач змушений повторно зчитувати інформацію з довгострокової пам'яті або інтерфейсу, що створює вимірюваний штраф перемикання задач (*task switching cost*) тривалістю від 2 до 15 секунд.

## Математичний баланс кадрового бюджету рендерингу

Для неперервного кінестетичного руху (скрол, drag-and-drop, анімація переходу) критичним є збереження частоти кадрів дисплея `f_refresh`.

Тривалість одного кадрового інтервалу `T_frame`:

```
T_frame = 1000 / f_refresh
```

Розрахунок для стандартних частот оновлення дисплеїв:

```
T_frame_60  = 1000 / 60  ≈ 16.667 мс
T_frame_120 = 1000 / 120 ≈  8.333 мс
T_frame_144 = 1000 / 144 ≈  6.944 мс
```

Увесь цей час не належить коду користувацького застосунку. Двигун платформи (Chromium, WebKit, Cocoa, Android View) виконує обов'язкові службові фази підготовки кадру:
- `T_style` — перерахунок каскадних стилів (*Recalculate Style*);
- `T_layout` — розрахунок геометрії та координат елементів (*Reflow/Layout*);
- `T_paint` — запис інструкцій малювання шарів (*Paint/DisplayList*);
- `T_composite` — передача текстур у GPU та очікування VSync (*GPU Raster & Swap*).

Сумарні накладні витрати рушія `T_engine`:

```
T_engine = T_style + T_layout + T_paint + T_composite
```

При 60 Гц середні накладні витрати оптимізованого браузера складають `T_engine ≈ 6.0–8.0 мс`. Звідси виводиться реальний бюджет коду розробника `T_app`:

```
T_app_60
= T_frame_60 - T_engine_60    [залишок часу на користувацький код]
= 16.67 - 6.67                [підстановка номінальних значень]
= 10.00 мс                    [граничний бюджет скриптів на кадр]
```

Для екранів 120 Гц (*ProMotion*) при `T_engine ≈ 4.0 мс`:

```
T_app_120
= T_frame_120 - T_engine_120  [залишок для 120 Гц]
= 8.33 - 4.33                 [підстановка значень для 120 Гц]
= 4.00 мс                     [жорсткий ліміт для high-refresh дисплеїв]
```

Будь-який скрипт або синхронний обробник події, який виконується довше 10 мс (при 60 Гц) або 4 мс (при 120 Гц), неминуче призводить до пропуску кадру (*dropped frame / jank*).
