# ⚙️ Розплутати павутину: чотири глобали, чотири шви

## Що на столі

Ось сервіс продовження передплат. Він працює в проді, приносить гроші, його ніхто не чіпав два роки — і всередині нього чотири глобали: конфіг, годинник, логер, лічильник.

:::tabs
```python
# billing.py
import logging
from datetime import datetime, timedelta

settings = {"fee_rate": 0.02, "grace_days": 3, "period_days": 30}   # глобал 1: конфіг
renewals_total = 0                                                  # глобал 2: лічильник
log = logging.getLogger("billing")                                  # глобал 3: логер


def renew(sub):
    global renewals_total
    now = datetime.now()                                            # глобал 4: годинник
    deadline = sub.paid_until + timedelta(days=settings["grace_days"])
    if now > deadline:
        log.warning("sub %s: пільговий строк вичерпано", sub.id)
        return Renewal("expired", 0.0, sub.paid_until)
    amount = round(sub.plan_price * (1 + settings["fee_rate"]), 2)
    sub.paid_until = now + timedelta(days=settings["period_days"])
    renewals_total += 1
    log.info("sub %s: продовжено на %.2f", sub.id, amount)
    return Renewal("ok", amount, sub.paid_until)
```
```ts
// billing.ts
export const settings = { feeRate: 0.02, graceDays: 3, periodDays: 30 }; // глобал 1: конфіг
export let renewalsTotal = 0;                                            // глобал 2: лічильник
const log = console;                                                     // глобал 3: логер

export function renew(sub: Subscription): Renewal {
  const now = new Date();                                                // глобал 4: годинник
  const deadline = addDays(sub.paidUntil, settings.graceDays);
  if (now.getTime() > deadline.getTime()) {
    log.warn(`sub ${sub.id}: пільговий строк вичерпано`);
    return { status: "expired", amount: 0, paidUntil: sub.paidUntil };
  }
  const amount = Math.round(sub.planPrice * (1 + settings.feeRate) * 100) / 100;
  sub.paidUntil = addDays(now, settings.periodDays);
  renewalsTotal += 1;
  log.info(`sub ${sub.id}: продовжено на ${amount.toFixed(2)}`);
  return { status: "ok", amount, paidUntil: sub.paidUntil };
}
```
:::

Логіка тут проста: якщо строк оплати минув більш ніж на пільгові дні — передплата згасла; інакше беремо платіж, посуваємо оплачений строк на місяць уперед, рахуємо й логуємо. Двадцять рядків.

І в цих двадцяти рядках уже два роки живе баг, який щомісяця віддає задарма шість відсотків сервісу. Він не ховається — він у рядку `sub.paid_until = now + timedelta(...)`, на видноті. Просто його **нічим побачити**: жоден тест, який можна написати над цим кодом, на цей рядок не дивиться. Розплутування ми почнемо не з архітектури, а звідси — бо саме тут видно, за що ми платимо глобальним станом насправді.

## Дилема, з якої треба вийти

Спокуса очевидна: переписати `renew` начисто, з нормальними параметрами. І хибна — бо переписувати без тестів означає міняти поведінку наосліп, а поведінка цього коду в проді сьогодні і є специфікацією (усе, що клієнти вважають нормою, — тут). Потрібні тести. А щоб написати тести, треба... змінити код, бо в нинішньому вигляді він не тестується. Майкл Фезерс назвав це **дилемою легасі-коду**: щоб безпечно міняти код, потрібні тести; щоб завести тести, треба міняти код.

Вихід із цього кола він же й дав — **шов (англ. *seam*)**. Означення з його книжки «Working Effectively with Legacy Code» (Prentice Hall, вересень 2004) дослівне й напрочуд точне: шов — це місце, де можна змінити поведінку програми, **не редагуючи в цьому місці**. Ключове — «не редагуючи»: тест мусить дістати іншу поведінку, а рядки самої функції лишаються недоторканими. І кожен шов має **точку вмикання** — місце, де ти вирішуєш, котру з поведінок узяти цього разу.

Оце й уся стратегія. Спершу — знайти шви, які мова дає задарма (хай навіть бридкі), заводити ними тести; потім — замінити бридкі шви чесними; потім — прибрати риштування. Чотири глобали, чотири окремі історії, і головна з них — годинник.

## Живий годинник — це не незручність, а викреслена вісь

Спробуймо написати тест до `renew` як є.

:::tabs
```python
def test_renew():
    sub = Subscription("s-1", 100.0, paid_until=datetime.now())
    r = renew(sub)
    assert r.status == "ok"
    assert r.amount == 102.0
    assert abs((sub.paid_until - (datetime.now() + timedelta(days=30))).total_seconds()) < 1
```
```ts
test("renew", () => {
  const sub: Subscription = { id: "s-1", planPrice: 100, paidUntil: new Date() };
  const r = renew(sub);
  expect(r.status).toBe("ok");
  expect(r.amount).toBe(102);
  expect(Math.abs(sub.paidUntil.getTime() - addDays(new Date(), 30).getTime())).toBeLessThan(1000);
});
```
:::

Тест зелений — в обох мовах, перевірено: розбіжність нульова. І він абсолютно сліпий.

Придивімося, **чому саме** сліпий, — тут ховається найцінніше в усій цій історії. Позначмо `Δ` — на скільки платіж спізнився відносно оплаченого строку:

```
Δ = now − paid_until          (0 ≤ Δ ≤ пільгові дні — інакше передплата згасла)

як є:      paid_until' = now + 30д = (paid_until + Δ) + 30д = (paid_until + 30д) + Δ
як слід:   paid_until' = paid_until + 30д

похибка = Δ
```

Похибка того рядка дорівнює **рівно Δ** — жодного округлення, жодних «залежить». А тепер погляньмо на тест: щоб побудувати передплату, він змушений відштовхнутися від `datetime.now()`, бо іншої точки на осі часу в нього немає. Тобто він ставить `Δ = 0`. А при `Δ = 0` похибка тотожно нульова.

![Вісь Δ — на скільки платіж спізнився, від 0 до 3 днів; синя пряма «похибка = Δ» піднімається від нуля; червона точка й пунктир на Δ=0 із підписом «живий годинник ставить тест рівно сюди: Δ = 0 — а тут похибка тотожно 0»; зелена смуга під віссю «FixedClock: уся вісь доступна»](img/untangle-blind-axis.svg)

*Годинник — це вхід функції. Глобальний годинник фіксує цей вхід в одній-єдиній точці: «зараз». Похибка бага росте з відстані від цієї точки — і в самій точці дорівнює нулю. Єдиний тест, який можна написати з живим годинником, — це рівно той тест, який цього бага не бачить.*

> 🔧 **Навіщо це.** Тут зручно міряти вагу глобального стану точною міркою. Кажуть зазвичай так: глобали роблять тести крихкими, змушують до ритуалів «зберегти-відновити», плодять мерехтіння. Усе правда, але це дрібниці порівняно з тим, що видно на цій осі: **глобальний вхід не ускладнює тестування — він викреслює цілу вісь із простору входів.** Не «важко зловити» — а математично неможливо, скільки тестів не пиши. Ось справжня ціна: не незручність, а сліпа зона, форму якої ти навіть не бачиш, поки не заведеш шов.

Скільки коштує ця конкретна сліпа зона — рахується на серветці. Якщо платежі стабільно спізнюються в середньому на два дні:

```
період триває  30 + Δ = 32 дні замість 30
циклів на рік:  365 / 30 = 12.17   як слід
                365 / 32 = 11.41   як є
втрата = Δ / (період + Δ) = 2 / 32 = 6.25 % сервісу задарма — щомісяця, роками
```

За дванадцять продовжень поспіль із затримкою два дні день списання відповзає рівно на 24 дні (перевірено: `2027-01-20` замість `2026-12-27`). Дрейф не самовиправляється — кожне продовження додає свій `Δ` і ніколи його не вертає.

## Крок 0: сітка через брудний шов

Перш ніж чіпати бодай символ, треба сітка. І ось перша користь із означення Фезерса: шов не мусить бути гарним — він мусить бути. Python дає такий шов задарма: ім'я `datetime` у модулі `billing` можна підмінити **ззовні**, не торкаючись `renew`. У TypeScript те саме роблять фальшиві таймери.

:::tabs
```python
from unittest.mock import patch

def test_характеризація_продовження_із_запізненням():
    """Пришпилює ФАКТИЧНУ поведінку — включно з багом. Це не «правильно», це «як є»."""
    billing.renewals_total = 0
    with patch("billing.datetime") as dt:            # ← шов: точка вмикання ззовні
        dt.now.return_value = datetime(2026, 3, 3, 9, 0)
        sub = Subscription("s-1", 100.0, paid_until=datetime(2026, 3, 1, 0, 0))
        r = billing.renew(sub)
        assert r.status == "ok"
        assert r.amount == 102.0
        assert sub.paid_until == datetime(2026, 4, 2, 9, 0)   # ← ФАКТ, а не бажане
        assert billing.renewals_total == 1
```
```ts
import { vi } from "vitest";

test("характеризація: продовження із запізненням", () => {
  vi.useFakeTimers();                                        // ← шов: точка вмикання ззовні
  vi.setSystemTime(new Date(Date.UTC(2026, 2, 3, 9, 0)));
  try {
    const sub: Subscription = { id: "s-1", planPrice: 100, paidUntil: utc(2026, 3, 1) };
    const r = renew(sub);
    expect(r.status).toBe("ok");
    expect(r.amount).toBe(102);
    expect(sub.paidUntil).toEqual(utc(2026, 4, 2, 9));        // ← ФАКТ, а не бажане
  } finally {
    vi.useRealTimers();
  }
});
```
:::

Такий тест зветься **характеризаційним** — теж термін Фезерса. Його призначення не сказати «правильно», а сказати «отак воно поводиться зараз». Різниця принципова: побачивши в тесті `2026-04-02 09:00` замість очікуваного `2026-03-31`, рука сама тягнеться «виправити». Не тягнися. Спершу зафіксуй факт, і хай він побуде зафіксованим — це і є сітка. Судити, чи факт правильний, будемо окремим кроком і свідомо.

Конфіг має свій дармовий шов — теж бридкий, теж робочий:

```python
def test_із_іншою_ставкою():
    saved = dict(billing.settings)
    billing.settings["fee_rate"] = 0.10          # ← лізу в чужий глобал руками
    try:
        assert billing.renew(sub).amount == 110.0
    finally:
        billing.settings.clear()                 # ← і не забути прибрати за собою,
        billing.settings.update(saved)           #    інакше отруїш сусідній тест
```

Обидва шви працюють (перевірено), обидва — риштування. Ціну видно одразу: `patch("billing.datetime")` знає, що `renew` смикає ім'я `datetime` **саме з модуля `billing`**. Перейменуєш імпорт, винесеш функцію в сусідній модуль — тест упаде `AttributeError`, хоча поведінка не змінилася ні на йоту. Брудний шов кріпиться не до поведінки, а до нутрощів. Жити на такому не можна; перелізти через провалля — можна.

## Шов 1: годинник

Тепер, під сіткою, витягуємо перший вхід на світло. Форми дві, і вибір між ними змістовний, а не смаковий.

**Перша — просто параметр:** `def renew(sub, now)`. Найчесніше, що буває: жодного інтерфейсу, жодного об'єкта, вхід є вхід. Для функції-листка, яка ухвалює одне рішення й повертає значення, це правильна відповідь, і зупинятися варто на ній.

**Друга — порт `Clock`:** об'єкт із методом `now()`, який кладуть у конструктор. Дорожче на один інтерфейс, але виправдано, коли об'єкт живе довго й питає час не раз (перевірити строк, проставити мітку, порахувати затримку) — інакше `now` доведеться тягати параметром крізь усі методи, і ти лише переклав проблему на поверх вище. Наш `Billing` саме такий, тож беремо порт.

:::tabs
```python
from typing import Protocol

class Clock(Protocol):
    def now(self) -> datetime: ...

class SystemClock:
    def now(self) -> datetime:
        return datetime.now()

class FixedClock:
    def __init__(self, moment: datetime) -> None:
        self._moment = moment
    def now(self) -> datetime:
        return self._moment
```
```ts
export interface Clock {
  now(): Date;
}

export const systemClock: Clock = {
  now: () => new Date(),
};

export class FixedClock implements Clock {
  constructor(private readonly moment: Date) {}
  now(): Date {
    return new Date(this.moment);   // копія: тест не зможе зіпсувати еталон
  }
}
```
:::

І тепер найважливіше правило всієї роботи, за яке платять кров'ю ті, хто його не знає: **заведення шва — це рефакторинг. Поведінка не міняється. Сітка мусить лишитися зеленою.**

Тобто на цьому кроці `renew` дістає час із `self._clock.now()` замість `datetime.now()` — і **баг лишається на місці**. Рядок `sub.paid_until = now + timedelta(...)` не чіпаємо. Характеризаційний тест переписуємо з `patch` на `FixedClock` — і він так само стверджує `2026-04-02 09:00`, так само зелений. Ми не полагодили нічого; ми лише зробили вхід видимим.

![Чотири кроки ліворуч направо: «1 · брудний шов — monkeypatch ззовні, характеризаційний тест» (сітка зелена), «2 · чесний шов — залежність у конструктор, поведінка та сама» (сітка лишається зеленою), «3 · виправлення — now+30д → paid_until+30д, поведінка міняється» (сітка червоніє свідомо), «4 · зняти риштування — брудний шов видалено, тест б'ється в чесний» (сітка зелена назавжди)](img/untangle-ratchet.svg)

*Храповик: сітка червоніє рівно один раз — там, де ти сам це вирішив. Заведеш шов і полагодиш баг одним комітом — і коли щось відвалиться, не знатимеш, від якої з двох половин.*

І аж тоді, **окремим кроком**, — питання до бізнесу, а не до себе: чи має запізнілий платіж посувати день списання? Відповідь тут не технічна. І ось найтонше в усій історії: **шов не просто уможливив тест — він уможливив саме питання.** Раніше цю розмову не можна було навіть почати, бо поведінку не було чим показати; тепер вона демонструється трьома рядками. Продукт каже «ні, день списання прибитий» — отже, це баг, і його виправлення міняє поведінку свідомо: характеризаційний тест червоніє, ти дивишся на нього і **переписуєш очікування з відкритими очима**.

А далі відкривається вся вісь — тести, яких не існувало в природі. Зверни увагу на `build`: після одного шва він знає рівно про одну залежність. Конфіг і лічильник поки що глобальні — їхня черга попереду, і змішувати не будемо.

:::tabs
```python
def build(clock):
    return Billing(clock=clock)          # поки що залежність рівно одна

def test_запізнілий_платіж_не_посуває_день_списання():
    svc = build(FixedClock(datetime(2026, 3, 3, 9, 0)))       # платіж на 2-й день пільги
    sub = Subscription("s-1", 100.0, paid_until=datetime(2026, 3, 1, 0, 0))
    assert svc.renew(sub).status == "ok"
    assert sub.paid_until == datetime(2026, 3, 31, 0, 0)      # + рівно 30д від СТРОКУ

def test_рівно_межа_пільгового_строку():
    svc = build(FixedClock(datetime(2026, 3, 4, 0, 0)))       # секунда в секунду
    sub = Subscription("s-1", 100.0, paid_until=datetime(2026, 3, 1, 0, 0))
    assert svc.renew(sub).status == "ok"

def test_на_секунду_пізніше_межі():
    svc = build(FixedClock(datetime(2026, 3, 4, 0, 0, 1)))
    sub = Subscription("s-1", 100.0, paid_until=datetime(2026, 3, 1, 0, 0))
    assert svc.renew(sub).status == "expired"
    assert sub.paid_until == datetime(2026, 3, 1, 0, 0)       # згасла — строк не рухаємо

def test_високосне_29_лютого():
    svc = build(FixedClock(datetime(2024, 2, 29, 12, 0)))
    sub = Subscription("s-1", 100.0, paid_until=datetime(2024, 2, 29, 0, 0))
    svc.renew(sub)
    assert sub.paid_until == datetime(2024, 3, 30, 0, 0)

def test_дванадцять_продовжень_без_дрейфу():
    sub = Subscription("s-1", 100.0, paid_until=datetime(2026, 1, 1))
    for _ in range(12):
        build(FixedClock(sub.paid_until + timedelta(days=2))).renew(sub)   # щоразу +2д
    assert sub.paid_until == datetime(2026, 1, 1) + timedelta(days=360)    # дрейф 0
```
```ts
const build = (clock: Clock) => new Billing(clock);   // поки що залежність рівно одна
const utc = (y: number, m: number, d: number, h = 0, mi = 0, s = 0) =>
  new Date(Date.UTC(y, m - 1, d, h, mi, s));

test("запізнілий платіж не посуває день списання", () => {
  const svc = build(new FixedClock(utc(2026, 3, 3, 9)));      // платіж на 2-й день пільги
  const sub: Subscription = { id: "s-1", planPrice: 100, paidUntil: utc(2026, 3, 1) };
  expect(svc.renew(sub).status).toBe("ok");
  expect(sub.paidUntil).toEqual(utc(2026, 3, 31));            // + рівно 30д від СТРОКУ
});

test("на секунду пізніше межі", () => {
  const svc = build(new FixedClock(utc(2026, 3, 4, 0, 0, 1)));
  const sub: Subscription = { id: "s-1", planPrice: 100, paidUntil: utc(2026, 3, 1) };
  expect(svc.renew(sub).status).toBe("expired");
  expect(sub.paidUntil).toEqual(utc(2026, 3, 1));             // згасла — строк не рухаємо
});

test("дванадцять продовжень без дрейфу", () => {
  const sub: Subscription = { id: "s-1", planPrice: 100, paidUntil: utc(2026, 1, 1) };
  for (let i = 0; i < 12; i++) {
    build(new FixedClock(addDays(sub.paidUntil, 2))).renew(sub);           // щоразу +2д
  }
  expect(sub.paidUntil).toEqual(addDays(utc(2026, 1, 1), 360));            // дрейф 0
});
```
:::

Межа пільгового строку — секунда в секунду. Секунда по межі. Двадцять дев'яте лютого. Дванадцять продовжень поспіль, кожне із затримкою. Жоден із цих тестів не був можливий учора — не «незручний», а неможливий: усі вони живуть при `Δ ≠ 0`, тобто на осі, якої не існувало.

І ще один зиск, менш очевидний: питання «який саме годинник» тепер має **одне місце**, де на нього відповідають. Настінний час чи монотонний, локальна зона чи UTC — поки `datetime.now()` розсипаний по сорока файлах, це сорок відповідей, і всі різні; за портом — одна. Це не дрібниця: «чи минув строк» і «скільки тривала операція» — питання до **різних** годинників, і плутати їх в одному порті теж не варто — див. [настінний час проти монотонного](root:sf-apps/monotonic-vs-wall-time).

## Шов 2: конфіг

Найпростіший із чотирьох, і саме тому вартий уваги: тут легко перестаратися.

Механіка очевидна — глобальний словник стає **замороженим значенням** у конструкторі:

:::tabs
```python
from dataclasses import dataclass

@dataclass(frozen=True)
class BillingConfig:
    fee_rate: float
    grace_days: int
    period_days: int
```
```ts
export type BillingConfig = Readonly<{
  feeRate: number;
  graceDays: number;
  periodDays: number;
}>;
```
:::

Слово `frozen` (і `Readonly`) тут не косметика. Передати мутабельний словник у конструктор — означає лише переселити червону клітину, а не прибрати її: посилання спільне, і хто завгодно, хто його має, досі крутить ставку в тебе за спиною. Небезпеку знімає [незмінність](root:sf-apps/immutability), а не факт передавання. Перевірено: `CFG.fee_rate = 0.5` → `FrozenInstanceError: cannot assign to field 'fee_rate'`. Отут спільність стає безпечною.

Читання світу — змінних оточення, файлу, секретів — переїжджає туди, де йому місце: у [корінь композиції](root:sf-apps/di-container). Сервіс не знає ні про `os.environ`, ні про формат файлу; він знає лише, що йому дали три числа.

```python
# main.py — єдине місце, де програма читає світ
def build() -> Billing:
    cfg = BillingConfig(
        fee_rate=float(os.environ["FEE_RATE"]),
        grace_days=int(os.environ["GRACE_DAYS"]),
        period_days=int(os.environ["PERIOD_DAYS"]),
    )
    return Billing(cfg=cfg, clock=SystemClock(), metrics=Metrics())
```

А тепер пастка, у яку падають рівно на цьому кроці. Спокуса — завести один `AppConfig` на сорок полів і впорснути його всім. Формально глобал зник; насправді ти зробив [локатор служб](root:sf-apps/service-locator) із гарним ім'ям: у сигнатурі написано `cfg`, а що звідти візьмуть — знову невідомо, доки не прочитаєш тіло. Сигнатура знову бреше — просто тихіше. Тому `BillingConfig` має рівно ті три поля, які `Billing` справді читає: дивишся на конструктор — бачиш усе, від чого залежить. Про це докладніше — у [проєктуванні конфігурації](root:sf-apps/config-design).

## Шов 3: лічильник — глобал, який не можна прибрати

Годинник і конфіг піддалися однаково: обидва — входи, обидва просто передали. З лічильником цей рецепт не працює, і корисно зрозуміти чому.

`renewals_total` мусить **пережити виклик** і мусить бути **спільним** — у тому й уся його суть: лічильник, який кожен виклик заводить собі свій, нічого не рахує. Це стан, який не можна ні заморозити (він на те й лічильник, щоб мінятися), ні передати значенням (передаси копію — втратиш підрахунок). Прибрати його неможливо. Можна лише **дати йому власника**.

Помітно це, до речі, вже на брудному шві. У Python `billing.renewals_total = 0` перед тестом — бридко, але працює. А в TypeScript із модулями ESM той самий рух просто **заборонено**: імпортоване зв'язування доступне лише на читання, і `renewalsTotal = 0` падає з `TypeError: Assignment to constant variable`. Щоб обнулити глобал із тесту, довелося б експортувати `resetForTests()` — бойовий код, який існує винятково заради тестів, тобто течу видно вже в публічному інтерфейсі модуля. Мова тут просто голосніше каже те, що в Python лише шепоче.

:::tabs
```python
import threading

class Metrics:
    def __init__(self) -> None:
        self._lock = threading.Lock()
        self._counts: dict[str, int] = {}

    def bump(self, name: str) -> None:
        with self._lock:                                    # рівно ОДНЕ місце мутації
            self._counts[name] = self._counts.get(name, 0) + 1

    def value(self, name: str) -> int:
        with self._lock:
            return self._counts.get(name, 0)
```
```ts
export class Metrics {
  // у Node цикл подій однопотоковий — замок тут не потрібен і був би обманом
  private readonly counts = new Map<string, number>();

  bump(name: string): void {
    this.counts.set(name, (this.counts.get(name) ?? 0) + 1);
  }

  value(name: string): number {
    return this.counts.get(name) ?? 0;
  }
}
```
:::

Різниця між вкладками тут змістовна, а не синтаксична. У Python замок потрібен; у Node всередині одного циклу подій — ні, і ставити його було б удаванням безпеки, якої нема від чого захищати. Але щойно з'являються `worker_threads` чи кластер із чотирьох процесів — спільність вертається, тільки вже **між** процесами, і жоден замок у пам'яті її не врятує: лічильники доведеться зводити назовні (у Prometheus, у Redis). Порядок дій той самий: спершу назви власника, потім вирішуй, як він захищає свій стан.

І тепер — вимір, заради якого варто було ставити дослід. Той самий глобальний лічильник, вісім потоків, CPython 3.12.10, `sys.setswitchinterval(1e-6)`:

```
total += 1                              →  400000 / 400000   загублено 0
counts["ok"] = counts.get("ok", 0) + 1  →   93928 / 400000   загублено 306072  (76 %)
```

Прочитай ці два рядки ще раз. Логіка однакова: прочитати, додати одиницю, записати. Втрати різняться від нуля до трьох чвертей. Чому?

```
total += 1                          counts["ok"] = counts.get("ok", 0) + 1
  LOAD_GLOBAL  total                  LOAD_GLOBAL  counts
  LOAD_CONST   1                      LOAD_ATTR    get
  BINARY_OP    +=                     CALL         2        ← ТОЧКА ПЕРЕМИКАННЯ ПОТОКІВ
  STORE_GLOBAL total                  BINARY_OP    +
  ← жодного виклику, жодного          LOAD_GLOBAL  counts
    зворотного стрибка                STORE_SUBSCR
```

Річ у тім, що інтерпретатор **не перемикає потоки між кожними двома байткодами** — це поширена вигадка, яку досі переписують блоги. Після зміни «перевіряти переривач лише після викликів і на зворотних стрибках» (злита в CPython у березні 2021, тобто з 3.10) точки перемикання — це виклики й зворотні стрибки, і більше ніде. У послідовності `LOAD_GLOBAL → BINARY_OP → STORE_GLOBAL` немає ні того, ні того — тож перемикання туди не втиснеться, і `+= 1` виявляється атомарним. **Випадково.** А варто замінити число на словник — «рахуймо ще й за планами», цілком невинна зміна — як усередині read-modify-write з'являється `CALL`, а з ним і точка перемикання рівно між читанням і записом. Три чверті інкрементів у смітник.

> 🔧 **Навіщо це.** Це найкращий аргумент за власника, який я знаю, — і він не про гонки. Твій `+= 1` сьогодні безпечний не тому, що ти щось правильно зробив, а тому, що компілятор цієї версії CPython згенерував послідовність без виклику всередині. Це не властивість твого коду — це властивість чужої оптимізації 2021 року. Оновиш мову, поміняєш `int` на `dict`, перейдеш на вільнопотокову збірку (PEP 703: у 3.13 — експериментальна, у 3.14 — офіційно підтримувана, окремий бінарник `python3.14t`), де GIL немає взагалі, — і випадковість зникне, а код не зміниться ні на символ. Правильність, яка спирається на таке, — це не правильність, а везіння з невідомим строком придатності. Механіка гонок — окрема тема про [атомарність і гонки](root:sf-tasks/atomicity-races); тут важить інше: за `Metrics.bump()` мутація має **одне** місце, і замок кладеться туди один раз. При розсипаному по п'ятнадцяти файлах `renewals_total += 1` це п'ятнадцять місць — і ти ніколи не знатимеш, чи знайшов усі.

Другий зиск від власника — тестовий, і він майже безкоштовний:

```python
def test_лічильники_не_течуть_між_тестами():
    a, b = Metrics(), Metrics()
    build(FixedClock(datetime(2026, 3, 1)), metrics=a).renew(sub)
    assert a.value("renewals_ok") == 1
    assert b.value("renewals_ok") == 0     # свіжий власник — свіжі нулі
```

Жодного `setUp`, який обнуляє глобал, жодного `tearDown`, який його вертає, жодної залежності від порядку запуску. Тести можна ганяти паралельно — `pytest -n auto`, `vitest --threads` — і вони не подеруться за спільну змінну, бо спільної змінної більше немає. Перевірено й друге: `Metrics` під замком, вісім потоків по 20 000 — `160000`, жодної втрати. Тепер безпека не випадкова, а обрана.

## Шов 4: логер — той, який ми вирішуємо не заводити

Лишився четвертий глобал, і саме тут проєкт розплутування або дорослішає, або перетворюється на догму.

Спокусливо чинити «послідовно»: витягли три — витягнемо й логер. Але спершу спитаймо, чому взагалі три попередні треба було витягати. Не тому, що вони глобальні. А тому, що логіка з них **читає**, і прочитане вертається в рішення: годинник вирішує `expired` чи `ok`, конфіг вирішує суму. Ось де справжній критерій.

![Таблиця з чотирьох рядків: годинник — вхід, вертається в рішення (expired чи ok), вирок «витягти у шов: порт Clock»; конфіг — вхід, вертається в рішення (суму), вирок «витягти у шов: заморожене значення»; лічильник — вхід і вихід (read-modify-write), у логіку не вертається, у тест вертається, вирок «дати власника: Metrics із замком»; логер — лише вихід, чистий стік, назад не вертається, вирок «лишити фоновим — свідомо»](img/untangle-seam-ladder.svg)

*Один критерій дає всі чотири вироки — включно з четвертим. Тому «логер лишається» — не поблажка собі й не непослідовність, а той самий критерій, доведений до кінця.*

Логер — **чистий стік**: логіка в нього пише й ніколи з нього не читає. Перемішалися рядки в логу — прикро, але сума платежу від цього не зміниться. Тягнути його крізь двадцять шарів конструкторів заради одного `log.info` — коштує більше, ніж дає; такі [наскрізні служби](root:sf-apps/cross-cutting-concerns) на те й наскрізні. Лишаємо **фоновим** (англ. *ambient* — той, що довкола) — свідомо й з причиною.

А шов, потрібний тестам, у логера вже є — його дала стандартна бібліотека, і впорскувати нічого:

```python
def test_згаслу_передплату_видно_в_лозі():
    recs = []
    class Cap(logging.Handler):
        def emit(self, record): recs.append(record.getMessage())
    h = Cap()
    billing.log.addHandler(h)          # ← точка вмикання: підміняємо ПРИЗНАЧЕННЯ, не логер
    try:
        billing.renew(sub)
        assert any("продовжено" in m for m in recs)
    finally:
        billing.log.removeHandler(h)
```

Це шов у точному сенсі Фезерса: поведінка змінилася (рядки полетіли в список замість консолі), у `renew` не відредаговано нічого. Той самий трюк у pytest робить `caplog`, у vitest — `vi.spyOn(console, "info")`.

Але критерій треба вміти застосовувати й у зворотний бік — бо логер перестає бути стоком частіше, ніж здається. Три випадки, коли вирок міняється:

- **Логіка починає з нього читати.** `if log.isEnabledFor(DEBUG): payload = collect_everything()` — і раптом рівень логування впливає на те, що виконається. Якщо `collect_everything()` має побічні ефекти, рівень логування став входом бізнес-логіки. Тепер це не стік.
- **Лог стає доказом.** Журнал списань, який має витримати аудит, — це вже не логер, а вихід, за який ти відповідаєш перед регулятором. Такий вихід перевіряють тестами предметно, отже його впорскують явно — не `log`, а вузький `AuditSink` у конструкторі. Це вже [журнал подій](root:sf-distributed/event-log), а не логування.
- **Лог кермує.** Метрику з логів завели в алерт, алерт — в автоскейлер. Формально логіка з логу не читає; фактично лог замкнувся назад у систему. Критерій той самий, просто петля довша.

Поки жодного з трьох немає — логер лишається глобальним, і це правильна відповідь, а не лінощі. Різниця між свідомим винятком і недбальством — рівно в тому, чи можеш ти назвати умову, за якої виняток перестане діяти. Тут можеш: три пункти вище.

## Що з цього вийшло

Чотири глобали — три шви й одне обґрунтоване «ні». Сервіс тепер каже правду про себе просто конструктором:

:::tabs
```python
class Billing:
    def __init__(self, cfg: BillingConfig, clock: Clock, metrics: Metrics) -> None:
        self._cfg = cfg
        self._clock = clock
        self._metrics = metrics

    def renew(self, sub: Subscription) -> Renewal:
        now = self._clock.now()
        deadline = sub.paid_until + timedelta(days=self._cfg.grace_days)
        if now > deadline:
            log.warning("sub %s: пільговий строк вичерпано", sub.id)
            self._metrics.bump("renewals_expired")
            return Renewal("expired", 0.0, sub.paid_until)
        amount = round(sub.plan_price * (1 + self._cfg.fee_rate), 2)
        sub.paid_until = sub.paid_until + timedelta(days=self._cfg.period_days)
        self._metrics.bump("renewals_ok")
        log.info("sub %s: продовжено на %.2f", sub.id, amount)
        return Renewal("ok", amount, sub.paid_until)
```
```ts
export class Billing {
  constructor(
    private readonly cfg: BillingConfig,
    private readonly clock: Clock,
    private readonly metrics: Metrics,
  ) {}

  renew(sub: Subscription): Renewal {
    const now = this.clock.now();
    const deadline = addDays(sub.paidUntil, this.cfg.graceDays);
    if (now.getTime() > deadline.getTime()) {
      log.warn(`sub ${sub.id}: пільговий строк вичерпано`);
      this.metrics.bump("renewals_expired");
      return { status: "expired", amount: 0, paidUntil: sub.paidUntil };
    }
    const amount = Math.round(sub.planPrice * (1 + this.cfg.feeRate) * 100) / 100;
    sub.paidUntil = addDays(sub.paidUntil, this.cfg.periodDays);
    this.metrics.bump("renewals_ok");
    log.info(`sub ${sub.id}: продовжено на ${amount.toFixed(2)}`);
    return { status: "ok", amount, paidUntil: sub.paidUntil };
  }
}
```
:::

Тіло `renew` майже не змінилося — і це добра ознака: ми не переписували логіку, ми виводили залежності з тіні. Дивишся на конструктор — бачиш рівно три речі, від яких `Billing` залежить, і жодної, про яку не сказано. Спосіб, у який це зроблено, зветься [впровадженням залежностей](root:sf-apps/dependency-injection); тут важить не назва, а те, що сигнатура перестала брехати.

## Складність і пастки

**Шов і виправлення в одному коміті.** Найдорожча помилка, і найспокусливіша: ти вже бачиш баг, рука сама править. Не правь. Шов зберігає поведінку, виправлення її міняє; злиті докупи, вони роблять червоний тест нерозв'язною загадкою — зламав рефакторинг чи виправлення? Розділяй завжди: комітом, а не наміром.

**Риштування, яке лишилося назавжди.** Брудний шов зробив свою справу — прибери його. Інакше через рік уся тека тестів складається з `patch("...")` і `vi.mock("...")`, і вони перевіряють не поведінку, а нутрощі: кожне перейменування — червоно, кожен рефакторинг — день на латання тестів. Тести починають утримувати не поведінку, а форму коду, і люди тихо перестають рефакторити взагалі. Ознака здоров'я проста: після четвертого кроку в тестах не має лишитися жодної згадки про `billing.datetime`.

**Шов, який протікає.** Шов не існує, доки щось не забороняє його обійти. Досить одного `datetime.now()` у глибині — і `FixedClock` у тесті зелений, а прод має інший час. Тому останнім рухом кожного шва йде **гейт**, який ловить обхід механічно:

```toml
# pyproject.toml — ruff
[tool.ruff.lint]
extend-select = ["DTZ"]     # flake8-datetimez: DTZ005 ловить datetime.now() без tz
```

```js
// eslint.config.js — годинник читають лише в корені композиції
rules: {
  "no-restricted-syntax": [
    "error",
    { selector: "NewExpression[callee.name='Date'][arguments.length=0]",
      message: "час беруть із Clock; new Date() — лише в composition root" },
    { selector: "CallExpression[callee.object.name='Date'][callee.property.name='now']",
      message: "час беруть із Clock; Date.now() — лише в composition root" },
  ],
}
```

Плюс виняток рівно для одного файлу — кореня композиції. Без цього шов протримається до першого поспіху.

**Лавина параметрів.** Витягнув годинник — і `now` поповз крізь дванадцять шарів: контролер → служба → доменний об'єкт → допоміжна функція. Це не провина шва, це його діагноз: шов підсвітив, що шари розкладені не так. Ліки не в тому, щоб вернути глобал, а в тому, щоб рішення про час ухвалювали **на краю**, а всередину передавали вже готове значення — [функціональне ядро й імперативна оболонка](root:sf-apps/functional-core-imperative-shell) саме про цю лінію. Оболонка питає котра година; ядро дістає `now` як звичайний аргумент і нічого про годинники не знає.

**Впорскувати все підряд.** Зворотна крайність: `Clock` у функції, яка форматує рядок; `Metrics` у чистому обчисленні знижки; конструктор на дев'ять залежностей. Критерій із таблиці ріже цю догму під корінь: витягуємо те, що логіка **читає** й від чого залежить рішення. Решта — ні. Дев'ять залежностей у конструкторі — не перемога дисципліни, а сигнал, що клас робить дев'ять справ.

**Великий вибух.** Спокуса зробити всі чотири шви одним рухом «поки не забув контекст» — і на третій день опинитися з гілкою на 60 файлів, яку страшно зливати. Порядок один: один шов — одна сітка — один комітабельний стан, у якому прод живий. Черга швів теж не випадкова: першим іде той, що відкриває найбільшу сліпу зону на одиницю ризику. Годинник відкрив цілу вісь входів — тому й був першим; логер не відкривав нічого — тому й лишився. Коли обсяг лякає й хочеться натомість переписати начисто, це окрема розмова з давно відомою відповіддю: [переписати чи відрефакторити](root:sf-apps/rewrite-vs-refactor).

Двадцять рядків, чотири глобали, три шви й один вимір, який виявився цікавішим за всі поради. Найважче в цій роботі — не техніка: жоден із кроків вище не складніший за годину. Найважче — втриматися й не виправити баг у ту саму мить, коли ти його нарешті побачив.
