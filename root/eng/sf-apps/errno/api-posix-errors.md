# 📋 Довідник стандартних кодів помилок POSIX

Стандарт POSIX.1 (IEEE Std 1003.1) визначає уніфікований набір символічних констант помилок, оголошених у системному заголовному файлі `<errno.h>`. Числові значення цих констант є додатними цілими числами типу `int`. Числове значення кожного коду може відрізнятися між різними сімействами операційних систем (наприклад, між Linux, FreeBSD, OpenBSD, Solaris та macOS). Тому переносне програмне забезпечення ніколи не використовує «магічні» числові літерали, а завжди оперує виключно символічними назвами макросів.

Нижче наведено повний структурований довідник кодів помилок, згрупований за функціональними підсистемами ядра. Для кожної помилки наведено її символічне ім'я, типове числове значення на платформі Linux x86-64, офіційний опис стандарту POSIX, системні виклики-джерела, умови генерації в надрах ядра та детальні стратегії програмної реакції.

## 1. Файлова система, дескриптори та блокові накопичувачі

У підсистемі віртуальної файлової системи (VFS) помилки виникають через відсутність файлових об'єктів, конфлікти прав доступу, вичерпання дискового простору або руйнування апаратних дескрипторів.

### `ENOENT` (код 2, No such file or directory)
- **Джерела**: системні виклики `open()`, `openat()`, `stat()`, `lstat()`, `access()`, `unlink()`, `rename()`, `chdir()`, `opendir()`, `execve()`.
- **Механізм ядра**: підсистема розпізнавання шляхів (path lookup) у ядрі перевіряє ланцюжок записів каталогів (dentry cache / inode). Якщо зазначеного імені файлу або проміжного каталогу не існує, ядро припиняє обхід дерева й повертає `-ENOENT`. Також код виникає, коли шлях веде на «бите» символічне посилання (dangling symlink), цільовий файл якого видалено.
- **Стратегія обробки**: для операцій відкриття конфігурації це сигнал створити файл із параметрами за замовчуванням; для веб-серверів та REST API — основа для повернення клієнтського статусу `404 Not Found`.

### `EBADF` (код 9, Bad file descriptor)
- **Джерела**: системні виклики `read()`, `write()`, `close()`, `fcntl()`, `ioctl()`, `fstat()`, `fsync()`, `lseek()`.
- **Механізм ядра**: передане числове значення дескриптора або є від'ємним, або перевищує розмір таблиці дескрипторів процесу, або вказує на порожній слот у масиві відкритих файлів `files_struct`. Також виникає при спробі виклику `write()` над дескриптором, відкритим виключно з прапорцем `O_RDONLY`.
- **Стратегія обробки**: у 99% випадків це грубий дефект логіки програми (подвійне закриття дескриптора `double close` або гонитва дескрипторів між нитками). Вимагає негайного виправлення коду та assert-перевірок у налагоджувальних збірках.

### `EEXIST` (код 17, File exists)
- **Джерела**: системні виклики `open()` з комбінацією прапорців `O_CREAT | O_EXCL`, `mkdir()`, `link()`, `symlink()`, `bind()` для сокетів UNIX-домену.
- **Механізм ядра**: ядро перевіряє таблицю каталогу й виявляє, що об'єкт із таким іменем уже зареєстровано.
- **Стратегія обробки**: основа алгоритмів безпечного створення тимчасових файлів та захоплення атомарних блокувань (lock-files). При отриманні `EEXIST` програма генерує нове унікальне ім'я або переходить у режим очікування звільнення блокування.

### `ENOSPC` (код 28, No space left on device)
- **Джерела**: системні виклики `write()`, `pwrite()`, `pwritev()`, `truncate()`, `ftruncate()`, `fallocate()`, `mkdir()`.
- **Механізм ядра**: драйвер файлової системи (ext4, XFS, btrfs, ZFS) виявив вичерпання вільних блоків накопичувача або досягнення дискової квоти користувача.
- **Стратегія обробки**: припинити приймання нових даних, очистити тимчасові буфери кешу, скинути аварійний лог і сповістити систему моніторингу про дефіцит накопичувача.

### `EMFILE` (код 24, Too many open files)
- **Джерела**: системні виклики `open()`, `socket()`, `pipe()`, `accept()`, `accept4()`, `dup()`, `dup2()`, `epoll_create1()`.
- **Механізм ядра**: кількість відкритих дескрипторів у поточному процесі досягла встановленого м'якого ліміту `RLIMIT_NOFILE`.
- **Стратегія обробки**: припинити виклики `accept()` на слухаючих сокетах, закрити неактивні фонові з'єднання або динамічно підвищити ліміт через `setrlimit()`.

### `ENFILE` (код 23, Too many open files in system)
- **Джерела**: будь-які системні виклики, що створюють нові структури файлів.
- **Механізм ядра**: вичерпано глобальну місткість системної таблиці відкритих файлів ядра (`/proc/sys/fs/file-max`).
- **Стратегія обробки**: загальносистемна криза ресурсів операційної системи; вимагає втручання адміністратора або масштабування контейнера.

## 2. Мережевий стек, потокові та дейтаграмні сокети

Мережеві операції взаємодіють з асинхронною природою мережевих стеків TCP/IP, де стан з'єднання змінюється незалежно від коду програми.

### `EAGAIN` та `EWOULDBLOCK` (код 11, Resource temporarily unavailable)
- **Джерела**: системні виклики `read()`, `write()`, `recv()`, `send()`, `recvmsg()`, `sendmsg()`, `accept()`, `connect()`.
- **Механізм ядра**: дескриптор сокета перебуває в неблокуючому режимі (`O_NONBLOCK`). Для операцій читання це означає, що буфер прийому сокета (sk_receive_queue) порожній. Для операцій запису — буфер відправки (sk_write_queue) заповнений, і стек TCP чекає підтверджень ACK від віддаленого вузла.
- **Стратегія обробки**: це штатна ситуація в асинхронному вводі-виводі. Програма повертає керування в цикл подій (`epoll_wait`, `kqueue`), підписавшись на події `EPOLLIN` або `EPOLLOUT`.

### `ECONNREFUSED` (код 111, Connection refused)
- **Джерела**: системний виклик `connect()`.
- **Механізм ядра**: цільовий хост відповів пакетом TCP з прапорцем `RST` (Reset), що свідчить про відсутність процесу, який прослуховує вказаний порт, або про переповнення черги `listen(backlog)` на віддаленому сервері.
- **Стратегія обробки**: повторити спробу підключення з експоненційною затримкою (exponential backoff) або перемкнутися на резервний вузол кластера.

### `ECONNRESET` (код 104, Connection reset by peer)
- **Джерела**: системні виклики `read()`, `write()`, `recv()`, `send()`.
- **Механізм ядра**: віддалена сторона примусово закрила сокет, коли в її буферах ще залишалися непрочитані дані, або віддалений процес аварійно завершився, змусивши ядро надіслати TCP RST.
- **Стратегія обробки**: закрити локальний сокет через `close()`, очистити стан сесії та сповістити вищі рівні застосунку про розрив зв'язку.

### `EPIPE` (код 32, Broken pipe)
- **Джерела**: системні виклики `write()`, `send()`, `sendto()`.
- **Механізм ядра**: спроба відправлення даних у сокет або канал (pipe), інший кінець якого вже повністю закрито. Якщо програма не перехоплює сигнал `SIGPIPE`, операційна система негайно знищує процес.
- **Стратегія обробки**: встановити обробник `signal(SIGPIPE, SIG_IGN)` або передавати прапорець `MSG_NOSIGNAL` у `send()`; при отриманні `EPIPE` закрити власний дескриптор.

### `ETIMEDOUT` (код 110, Connection timed out)
- **Джерела**: системні виклики `connect()`, `send()`, `recv()`.
- **Механізм ядра**: вичерпано ліміт часу очікування встановлення з'єднання TCP (SYN retransmits) або вичерпано інтервал перевірки життєздатності з'єднання TCP Keepalive без отримання відповідей.
- **Стратегія обробки**: ініціювати процедуру перепідключення через резервні IP-адреси DNS або повідомити користувача про недоступність мережевого маршруту.

### `EADDRINUSE` (код 98, Address already in use)
- **Джерела**: системний виклик `bind()`.
- **Механізм ядра**: запитана комбінація IP-адреси та порту вже прив'язана іншим відкритим сокетом, або перебуває в системному стані очікування закриття `TIME_WAIT`.
- **Стратегія обробки**: обов'язково встановлювати прапорець сокета `setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &one, sizeof(one))` перед кожним викликом `bind()`.

### `EINPROGRESS` (код 115, Operation now in progress)
- **Джерела**: системний виклик `connect()` на неблокуючому сокеті.
- **Механізм ядра**: ядро відправило початковий пакет TCP SYN і перевело з'єднання в стан тристороннього рукостискання. Оскільки виклик неблокуючий, він повертає керування негайно.
- **Стратегія обробки**: зареєструвати сокет в `epoll` на подію `EPOLLOUT`. Коли подія спрацює, прочитати статус завершення через `getsockopt(fd, SOL_SOCKET, SO_ERROR, &err, &len)`.

## 3. Сигнали, процеси та керування потоками

### `EINTR` (код 4, Interrupted system call)
- **Джерела**: блокуючі виклики `read()`, `write()`, `select()`, `poll()`, `epoll_wait()`, `sem_wait()`, `nanosleep()`.
- **Механізм ядра**: виконання повільного системного виклику було призупинено через надходження асинхронного сигналу процесу. Ядро виконало signal handler у просторі користувача й повернуло керування.
- **Стратегія обробки**: якщо програма не отримала сигнал завершення (`SIGTERM`, `SIGINT`), негайно повторити системний виклик у циклі `while`.

### `ECHILD` (код 10, No child processes)
- **Джерела**: системні виклики `wait()`, `waitpid()`, `waitid()`.
- **Механізм ядра**: у викликаючого процесу немає дочірніх процесів, або всі створені нащадки вже були зібрані попередніми викликами `wait()`, або встановлено прапорець `SA_NOCLDWAIT`.
- **Стратегія обробки**: вийти з циклу збирання статусів нащадків; це ознака завершення всіх дочірніх задач.

### `ESRCH` (код 3, No such process)
- **Джерела**: системні виклики `kill()`, `tgkill()`, `pthread_kill()`, `getpriority()`, `setpriority()`.
- **Механізм ядра**: у системній таблиці процесів відсутній запис із зазначеним числовим ідентифікатором PID або TID.
- **Стратегія обробки**: цільовий процес або нитка вже завершила роботу; очистити кеш ідентифікаторів у системі нагляду.

## 4. Пам'ять, захист адресного простору та привілеї

### `EFAULT` (код 14, Bad address)
- **Джерела**: будь-які системні виклики, що приймають вказівники на буфери пам'яті (`read`, `write`, `stat`, `ioctl`).
- **Механізм ядра**: обробник виклику в ядрі викликав функцію `copy_from_user()` або `copy_to_user()`, яка зіткнулася з невідображеною сторінкою віртуальної пам'яті (page fault), недійсним вказівником (`NULL` або вихід за межі стека) чи спробою запису в сторінку з правами тільки для читання (PROT_READ).
- **Стратегія обробки**: критичний баг у коді програми (порушення пам'яті). Підлягає негайному виправленню за допомогою AddressSanitizer або Valgrind.

### `ENOMEM` (код 12, Cannot allocate memory)
- **Джерела**: системні виклики `mmap()`, `brk()`, `fork()`, `clone()`, `execve()`.
- **Механізм ядра**: ядро не змогло виділити нові сторінки віртуального адресного простору або перевищено ліміти пам'яті cgroups / swap.
- **Стратегія обробки**: звільнити службові кеші в пам'яті, відхилити обробку поточного запиту або коректно завершити роботу з логуванням браку RAM.

### `EACCES` (код 13, Permission denied)
- **Джерела**: системні виклики `open()`, `creat()`, `access()`, `execve()`, `chmod()`.
- **Механізм ядра**: файлова операція відхилена дискреційним контролем доступу (DAC) або модулями безпеки Linux (SELinux, AppArmor).
- **Стратегія обробки**: сповістити користувача про відсутність прав доступу до файлу; повтор операції без зміни прав є марним.

### `EPERM` (код 1, Operation not permitted)
- **Джерела**: системні виклики `kill()`, `setuid()`, `chown()`, `mount()`, `socket(AF_PACKET)`.
- **Механізм ядра**: операція вимагає спеціальних системних можливостей (Linux Capabilities, наприклад `CAP_SYS_ADMIN`, `CAP_NET_RAW`), якими поточний процес не володіє.
- **Стратегія обробки**: фатальна помилка конфігурації оточення запуску або прав сервісу.

### `EINVAL` (код 22, Invalid argument)
- **Джерела**: будь-який системний виклик.
- **Механізм ядра**: перевірка вхідних аргументів у коді ядра виявила непідтримуваний прапорець, невірний розмір структури, передачу від'ємного розміру буфера або невідому команду `ioctl`.
- **Стратегія обробки**: виправлення помилок у вихідному коді або оновлення заголовних файлів ядра.

### `ERANGE` (код 34, Numerical result out of range)
- **Джерела**: математичні функції бібліотеки C, функції чисельного перетворення рядків `strtol()`, `strtoll()`, `strtod()`.
- **Механізм ядра**: результат обчислення не може бути представлений цільовим числовим типом даних через переповнення (overflow) або втрату порядку (underflow).
- **Стратегія обробки**: сигналізація про некоректність вхідних числових даних, відхилення перетворення.
