# 🧮 Математика розв'язання конфліктів: частковий порядок векторних годинників, напівґратки та ймовірність колізій LWW

Узгодження розбіжних реплік в офлайн-перших системах спирається на алгебраїчні структури та ймовірнісні оцінки. Коли зв'язок розривається, клієнти генерують стани паралельно, утворюючи дерево розгалужень, яке синхронізатор мусить детерміністично звести до єдиного значення.

Формалізація цього процесу вимагає визначення трьох математичних апаратів: відношення причинності на векторах версій, оцінки похибки фізичних годинників при впорядкуванні подій та алгебраїчних законів напівґраток, що гарантують збіжність без блокувань.

## 1. Частковий порядок та причинність векторних годинників

Для розподіленої системи з `N` автономних клієнтів стан причинного часу кожного вузла описується вектором цілих чисел:

```
V = [v₁, v₂, ..., v_N],  де v_i ∈ ℕ₀
```

Кожен елемент `v_i` відображає кількість локальних подій, згенерованих вузлом `i`, про які відомо поточному вектору.

На множині таких векторів вводиться строге відношення часткового порядку:

```
V_A ≤ V_B  :⟺  ∀k ∈ {1..N}: V_A[k] ≤ V_B[k]
V_A < V_B  :⟺  (V_A ≤ V_B) ∧ (V_A ≠ V_B)
```

Математичний зміст нерівності `V_A < V_B` полягає в тому, що стан `S_B` причинно слідує за станом `S_A`. Тобто автор стану `B` перед здійсненням своєї правки гарантовано бачив і врахував усі зміни, зафіксовані у стані `A`.

Якщо для пари векторів не виконується жодна з нерівностей:

```
V_A ≰ V_B  ∧  V_B ≰ V_A  ⟹  V_A ∥ V_B  [стани є конкурентними / конфліктними]
```

Конкурентність `V_A ∥ V_B` є математичним доказом наявності конфлікту: обидва клієнти внесли зміни паралельно в умовах розриву зв'язку, не знаючи про існування правок одне одного.

## 2. Імовірність хибного впорядкування в Last-Write-Wins (LWW)

Стратегія Last-Write-Wins розв'язує конкурентні конфлікти шляхом редукції часткового порядку до лінійного за допомогою показів локальних фізичних годинників пристроїв `τ`.

Нехай дві незалежні події `A` та `B` відбулися у реальні фізичні моменти часу `t_A` та `t_B`. Оскільки годинники клієнтських пристроїв синхронізуються через NTP з певною похибкою, виміряні часові мітки містять випадковий дрейф:

```
τ_A = t_A + ε_A,  де ε_A ∼ N(0, σ²)
τ_B = t_B + ε_B,  де ε_B ∼ N(0, σ²)
```

де `σ` — середньоквадратичне відхилення похибки годинника пристрою від еталонного атомного часу UTC.

Різниця локальних часових міток двох подій:

```
Δτ = τ_B − τ_A = (t_B − t_A) + (ε_B − ε_A)
```

Оскільки похибки `ε_A` та `ε_B` є незалежними нормальними випадковими величинами, їхня різниця `Z = ε_B − ε_A` також підпорядковується нормальному розподілу:

```
Z ∼ N(0, 2σ²)
```

Імовірність `P_loss` того, що подія `B`, яка об'єктивно сталася пізніше у фізичному часі (`t_B > t_A`), отримає меншу локальну мітку (`τ_B < τ_A`) і буде безповоротно перезаписана старішою подією `A`:

```
P_loss = P(Δτ < 0) = P(Z < −(t_B − t_A))
P_loss = Φ( −(t_B − t_A) / (σ · √2) )
```

де `Φ(x)` — функція розподілу стандартного нормального закону.

**Числовий розрахунок ризику втрати оновлення:**
Якщо типова похибка мобільного годинника становить `σ = 250` мс, а дві конкурентні правки від різних людей надійшли з інтервалом `Δt = t_B − t_A = 100` мс:

```
аргумент = −100 / (250 · 1.4142) = −100 / 353.55 = −0.2828
P_loss = Φ(−0.2828) ≈ 0.3887  (38.9% ймовірність втрати даних)
```

Цей розрахунок наочно доводить: у високонавантажених системах або при спільній роботі користувачів наївний LWW без логічних годинників призводить до втрати майже третини паралельних правок.

## 3. Алгебра збіжності: напівґратки та CRDT

Для досягнення сильної кінцевої узгодженості (англ. *Strong Eventual Consistency*, SEC) простір станів репліки проектують як математичну структуру **об'єднавчої напівґратки** (англ. *join-semilattice*) `⟨S, ⊔⟩`.

Бінарна операція злиття станів `⊔ : S × S → S` зобов'язана строго задовольняти три фундаментальні алгебраїчні аксіоми для будь-яких станів `a, b, c ∈ S`:

```
a ⊔ b = b ⊔ a                 [комутативність: порядок прибуття пакетів не впливає на підсумок]
(a ⊔ b) ⊔ c = a ⊔ (b ⊔ c)     [асоціативність: довільне групування дельт дає той самий стан]
a ⊔ a = a                     [ідемпотентність: повторна обробка дублікатів абсолютно безпечна]
```

На основі операції `⊔` на просторі станів природним чином визначається відношення часткового порядку переходів:

```
a ⊑ b  :⟺  a ⊔ b = b
```

Це означає, що кожна нова мутація або злиття може лише монотонно підвищувати стан у напівґратці (`a ⊑ a ⊔ b`). Оскільки множина змін скінченна, будь-яка послідовність злиття гарантовано збігається до найменшої верхньої межі (англ. *Least Upper Bound / join*), яка є єдиною для всієї множини отриманих дельт.

### Доведення збіжності для довільного графа доставки

Нехай дві репліки `R₁` та `R₂` стартують зі спільного початкового стану `s₀`. У процесі роботи репліка `R₁` генерує множину локальних оновлень `U₁ = {u₁,₁, u₁,₂}`, а репліка `R₂` генерує `U₂ = {u₂,₁, u₂,₂}`.

Кінцевий стан репліки `R₁` після отримання пакетів від `R₂`:

```
S(R₁) = (((s₀ ⊔ u₁,₁) ⊔ u₁,₂) ⊔ u₂,₁) ⊔ u₂,₂
```

Кінцевий стан репліки `R₂` після отримання пакетів від `R₁` у зворотному порядку:

```
S(R₂) = (((s₀ ⊔ u₂,₂) ⊔ u₂,₁) ⊔ u₁,₂) ⊔ u₁,₁
```

Завдяки асоціативності та комутативності операції `⊔`:

```
S(R₁) = s₀ ⊔ u₁,₁ ⊔ u₁,₂ ⊔ u₂,₁ ⊔ u₂,₂
S(R₂) = s₀ ⊔ u₂,₂ ⊔ u₂,₁ ⊔ u₁,₂ ⊔ u₁,₁ = s₀ ⊔ u₁,₁ ⊔ u₁,₂ ⊔ u₂,₁ ⊔ u₂,₂
S(R₁) = S(R₂)
```

Обидві репліки гарантовано приходять до однакового стану без необхідності блокувального консенсусу (такого як Paxos або Raft).

### Практичний приклад: LWW-Element-Set з надгробками

Структура множини з підтримкою видалення складається з двох внутрішніх напівґраток: множини доданих елементів `A` та множини видалених елементів `R` (надгробків / tombstones):

```
S = ⟨A, R⟩,  де A, R ⊆ E × ℝ⁺  (пара: значення елемента + мітка часу)
```

Операція злиття двох незалежних копій `S₁ = ⟨A₁, R₁⟩` та `S₂ = ⟨A₂, R₂⟩`:

```
S_merge = S₁ ⊔ S₂ = ⟨A₁ ∪ A₂, R₁ ∪ R₂⟩
```

Предикат фактичної наявності елемента `e` у результуючій множині `S_merge`:

```
t_add(e) = max({t : (e, t) ∈ A} ∪ {0})
t_rem(e) = max({t : (e, t) ∈ R} ∪ {0})
e ∈ S_merge  ⟺  t_add(e) > t_rem(e)
```

Оскільки теоретико-множинне об'єднання `∪` є комутативним, асоціативним та ідемпотентним, злиття `S₁ ⊔ S₂ = S₂ ⊔ S₁` гарантує математичну збіжність реплік без участі центрального сервера.

## 4. Дисперсія та математичне сподівання Full Jitter Backoff

При повторному підключенні флоту клієнтів після аварії на лінії час затримки перед `k`-ю спробою розраховується з випадковим розсіюванням (Full Jitter):

```
T_max(k) = min( T_ceiling, T_base · 2ᵏ )
T_wait(k) ∼ Uniform( 0, T_max(k) )
```

Математичне сподівання часу паузи клієнта:

```
E[T_wait(k)] = T_max(k) / 2
```

Дисперсія часу очікування:

```
Var[T_wait(k)] = (T_max(k))² / 12
```

Якщо до сервера одночасно намагаються підключитися `M` клієнтів, щільність потоку запитів при використанні випадкового джитеру зменшується з дельта-піку величиною `M` запитів в одну мікросекунду до рівномірного розподілу з інтенсивністю:

```
λ(t) = M / T_max(k)
```

Це знижує пікове навантаження на мережеві шлюзи відновленого сервера в десятки разів, повністю ліквідуючи небезпеку виникнення резонансних штормів повторів.

## 5. Обмеження росту пам'яті: матричні годинники та збирання надгробків

Головним практичним викликом напівґраток із надгробками (tombstones) є невпинне зростання обсягу пам'яті. Щоб безпечно видалити запис про видалення `(e, t) ∈ R` без ризику «воскресіння» елемента старою реплікою, система повинна знати, що абсолютно всі `N` вузлів мережі вже отримали інформацію про це видалення.

Для цього використовують розширення векторних годинників — **матричні годинники** (англ. *Matrix Clocks*) розмірності `N × N`:

```
M[i, j] = час репліки j, про який знає репліка i
```

Безпечний поріг збирання сміття (Garbage Collection Watermark) для репліки `i`:

```
T_safe = min_{k=1..N} ( M[k, i] )
```

Будь-який надгробок із часовою міткою `t < T_safe` можна фізично видалити з локального диска, оскільки всі вузли розподіленої системи гарантовано перетнули цей часовий горизонт.
