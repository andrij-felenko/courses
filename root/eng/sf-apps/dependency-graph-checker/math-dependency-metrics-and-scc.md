# 🧮 Математичний апарат аналізу графів залежностей: метрики, інваріанти та SCC

Структурний аналіз програмного коду опирається на дискретну математику та теорію орієнтованих графів. Будь-яка архітектурна конфігурація — від внутрішніх пакетів монолітного застосунку до топології мікросервісів у розподіленому кластері — формалізується як орієнтований граф із накладеними алгебраїчними та топологічними обмеженнями.

## 1. Формальне визначення графа залежностей

Нехай архітектура системи представлена скінченним орієнтованим графом:
```
G = (V, E)
```
де:
- `V = {v₁, v₂, ..., vₙ}` — множина архітектурних вузлів (пакетів, модулів, мікросервісів, просторів імен), де `|V| = n`;
- `E ⊆ V × V` — множина орієнтованих ребер, де впорядкована пара `(u, v) ∈ E` позначає, що вузол `u` безпосередньо залежить від вузла `v` (викликає його функції, імпортує типи, надсилає мережеві RPC-запити або читає спільну таблицю БД). Кількість ребер `|E| = m`.

### Матриця суміжності та обчислення шляхів

Зв'язки між вузлами графа описуються бінарною матрицею суміжності `A ∈ {0, 1}ⁿˣⁿ`:
```
A[i, j] = 1,  якщо (vᵢ, vⱼ) ∈ E
A[i, j] = 0,  якщо (vᵢ, vⱼ) ∉ E
```

Кількість орієнтованих шляхів довжини `k` між вузлами `vᵢ` та `vⱼ` визначається `k`-тим матричним степенем матриці суміжності `Aᵏ`. Для елемента `(Aᵏ)[i, j]`:
```
(Aᵏ)[i, j] = ∑ (A[i, p₁] · A[p₁, p₂] · ... · A[pₖ₋₁, j])
```

Вузол `vᵢ` бере участь у циклі довжини `k ≥ 1` тоді й лише тоді, коли відповідний діагональний елемент степеня матриці є строго додатним:
```
(Aᵏ)[i, i] > 0
```

### Матриця досяжності та транзитивне замикання

Повна транзитивна залежність між вузлами системи виражається матрицею досяжності (англ. *reachability matrix*) `R ∈ {0, 1}ⁿˣⁿ`, яка є булевою сумою перших `n - 1` степенів матриці суміжності:
```
R = A ∨ A² ∨ A³ ∨ ... ∨ Aⁿ⁻¹
```

У матриці досяжності:
- `R[i, j] = 1` означає, що зміна у модулі `vⱼ` може транзитивно вплинути на модуль `vᵢ` (існує прямий або опосередкований ланцюжок залежностей `vᵢ → ... → vⱼ`);
- `R[i, i] = 1` свідчить про наявність циклічної залежності, яка повертається у вузол `vᵢ`.

## 2. Теорема Тар'яна та знаходження сильно зв'язаних компонентів

Циклічні залежності в графі `G` утворюють **сильно зв'язані компоненти** (англ. *Strongly Connected Components*, SCC). 

Підграф `G' = (V', E')` називається сильно зв'язаним, якщо для будь-якої пари вершин `u, v ∈ V'` існує орієнтований шлях `u ↦ v` та орієнтований шлях `v ↦ u`. Максимальний за включенням сильно зв'язаний підграф є сильно зв'язаною компонентою.

У 1972 році Роберт Тар'ян (англ. *Robert E. Tarjan*) довів теорему, яка дозволяє знайти всі SCC графа за лінійний час `O(|V| + |E|)` за один прохід пошуку в глибину (DFS).

### Інваріанти обходу в глибину: dfn та lowlink

Під час DFS-обходу кожній вершині `u ∈ V` присвоюються два числові індекси:
1. `dfn[u]` (або `discovery time`): порядковий номер першого відвідування вершини `u` лічильником обходу;
2. `lowlink[u]`: найменший номер `dfn`, досяжний із піддерева обходу DFS вершини `u` через не більше ніж одне зворотне або поперечне ребро у вузол, що все ще перебуває в поточному стеку алгоритму.

Рекурентне співвідношення для `lowlink[u]`:
```
lowlink[u] = min(
    dfn[u],
    min { lowlink[v] | (u, v) ∈ E є деревом DFS },
    min { dfn[w]     | (u, w) ∈ E є зворотним або поперечним ребром, де w ∈ Stack }
)
```

### Критерій кореня компоненти

**Теорема (Тар'ян, 1972):**
Вершина `u` є коренем сильно зв'язаної компоненти (першою вершиною цієї компоненти, відвіданою під час DFS) тоді й лише тоді, коли:
```
lowlink[u] = dfn[u]
```

*Доведення інваріанту:*
1. Якщо `lowlink[u] < dfn[u]`, то з піддерева вершини `u` існує ребро у вершину `w`, відвідану раніше за `u` (`dfn[w] < dfn[u]`), причому `w` є предком `u` у дереві DFS або належить тому самому стеку. Отже, існує шлях `u ↦ w` і шлях `w ↦ u`, що означає, що `u` та `w` належать одній SCC, корінь якої лежить вище `u`;
2. Якщо `lowlink[u] = dfn[u]`, то жодна вершина в піддереві DFS вершини `u` не має орієнтованих ребер у вузли, відвідані раніше за `u` і досі активні в стеку. Отже, вершина `u` разом з усіма вершинами, що лежать вище неї в поточному стеку, утворює замкнену максимальну сильно зв'язану компоненту.

Витягування вершин зі стека до моменту зняття самої вершини `u` дає повний склад поточної SCC за час, пропорційний кількості елементів компоненти.

## 3. Матричне формулювання обмежень шарової архітектури

Нехай для графа системи `G = (V, E)` визначено функцію відображення вузлів на дискретні рівні (шари) ієрархії:
```
λ: V → {0, 1, 2, ..., K}
```
де `λ(u)` — номер шару (наприклад, `λ = 0` — Infrastructure, `λ = 1` — Domain Core, `λ = 2` — Application Layer, `λ = 3` — Presentation Layer).

### Правило строгої ієрархії залежностей

Штатна архітектурна дисципліна вимагає, щоб залежності спрямовувалися лише з вищих шарів до нижчих або всередині того самого шару:
```
∀ (u, v) ∈ E: λ(u) ≥ λ(v)   [або строге λ(u) > λ(v) для заборони горизонтальних зв'язків]
```

### Матриця порушень (Violation Matrix)

Побудуємо фіксовану матрицю архітектурних порушень `M ∈ {0, 1}ⁿˣⁿ`:
```
M[i, j] = 1,  якщо λ(vᵢ) < λ(vⱼ)   [нижчий шар залежить від вищого — зворотний виклик]
M[i, j] = 0,  якщо λ(vᵢ) ≥ λ(vⱼ)   [дозволений напрямок залежності]
```

Тоді сумарна кількість архітектурних порушень у системі дорівнює 1-нормі покомпонентного добутку Адамара (англ. *Hadamard product*) матриці суміжності `A` та матриці порушень `M`:
```
V_count = || A ∘ M ||₁ = ∑ᵢ ∑ⱼ (A[i, j] · M[i, j])
```

Архітектура задовольняє шарові обмеження тоді й лише тоді, коли:
```
A ∘ M = 0  (нульова матриця)
```

## 4. Метрики стабільності, абстрактності та відхилення

Для кількісної оцінки структури окремого модуля `u ∈ V` обчислюються локальні метрики зчеплення:

### 1. Аферентне зчеплення (Afferent Coupling, C_a)
Кількість зовнішніх вузлів, які залежать від модуля `u` (вхідний напівстепінь вершини):
```
C_a(u) = deg⁻(u) = |{ v ∈ V | (v, u) ∈ E }| = ∑ᵢ A[i, u]
```

### 2. Еферентне зчеплення (Efferent Coupling, C_e)
Кількість зовнішніх вузлів, від яких залежить модуль `u` (вихідний напівстепінь вершини):
```
C_e(u) = deg⁺(u) = |{ w ∈ V | (u, w) ∈ E }| = ∑ⱼ A[u, j]
```

### 3. Коефіцієнт нестабільності (Instability, I)
Відношення вихідних залежностей до загальної кількості зв'язків модуля:
```
I(u) = C_e(u) / (C_a(u) + C_e(u)),   якщо C_a(u) + C_e(u) > 0
I(u) = 0,                            якщо C_a(u) + C_e(u) = 0
```
Властивості:
- `I(u) = 0`: модуль абсолютно стабільний (жодної вихідної залежності, безліч залежних клієнтів). Будь-яка зміна інтерфейсу такого модуля має найвищу ціну переписування в системі;
- `I(u) = 1`: модуль абсолютно нестабільний / гнучкий (залежить від інших, від нього ніхто не залежить). Модуль легко модифікувати без впливу на сусідів.

### 4. Коефіцієнт абстрактності (Abstractness, A)
Частка абстрактних типів (інтерфейсів, чистих абстрактних класів, протоколів) `N_a(u)` серед загальної кількості класів і структур `N_c(u)` у модулі `u`:
```
A(u) = N_a(u) / N_c(u),   де N_c(u) > 0
```
Діапазон: `A(u) ∈ [0, 1]`.

### 5. Відстань від Головної послідовності (Distance from Main Sequence, D)
Принцип стабільних абстракцій стверджує: модуль повинен бути настільки абстрактним, наскільки він стабільний. Ідеальний баланс задається лінією Головної послідовності:
```
A(u) + I(u) = 1
```

Нормована відстань модуля `u` від ідеальної прямої:
```
D(u) = |A(u) + I(u) - 1|
```
Діапазон: `D(u) ∈ [0, 1]`.
- Якщо `D(u) ≈ 0`, модуль знаходиться в гармонійному балансі (наприклад, стабільне абстрактне ядро `A=0.8, I=0.2` або конкретний гнучкий адаптер `A=0.1, I=0.9`);
- Якщо `D(u) → 1` при `A(u) → 0, I(u) → 0`, модуль потрапляє в **Зону болю** (англ. *Zone of Pain*): монолітний конкретний код із високою зв'язністю, зміна якого ламає сотні залежних вузлів;
- Якщо `D(u) → 1` при `A(u) → 1, I(u) → 1`, модуль потрапляє в **Зону марності** (англ. *Zone of Uselessness*): надмірна кількість абстракцій та інтерфейсів, які не мають реальних клієнтів і ускладнюють навігацію кодом.

## 5. Глобальні метрики заплутаності графа

Для оцінки якості системи в цілому використовуються агреговані метрики:

### Коефіцієнт циклічної заплутаності (Tangling Ratio, τ)
Частка вершин графа, що беруть участь у нетривіальних сильно зв'язаних компонентах (розміром `|SCC| > 1`):
```
τ(G) = ( ∑ |C| ) / |V|,   де C ∈ SCC(G) та |C| > 1
```
Для ідеального DAG (ациклічного графа) `τ(G) = 0`. Якщо `τ(G) → 1`, система практично перетворилася на єдиний монолітний клубок залежностей.

### Густина графа залежностей (Edge Density, ρ)
Відношення фактичної кількості ребер до теоретично можливої кількості в повному орієнтованому графі без петель:
```
ρ(G) = |E| / (|V| · (|V| - 1))
```
Зростання `ρ(G)` у процесі життєвого циклу проєкту сигналізує про деградацію модульних меж і неконтрольоване зростання міжмодульного зчеплення.
