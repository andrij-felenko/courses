# 📋 Інтерфейс та формат сертифікатів резолюційних доведень DRAT та LRAT

Перевірка коректності відповідей `UNSAT`, згенерованих автоматизованими розв'язувачами проблеми здійсненності булевих формул (SAT solvers), спирається на стандартизовані траси резолюційних доведень. Сучасна індустрія формальної верифікації вимагає від розв'язувачів формування зовнішніх сертифікатів у форматах **DRUP** (Deletion Reverse Unit Propagation), **DRAT** (Deletion Resolution Asymmetric Tautology) або **LRAT** (Lineated RAT). 

Ця вставка містить довідковий опис синтаксису, бінарного кодування, семантики та програмного інтерфейсу (API) виводу сертифікатів резолюційних доведень, а також інструкції з використання інструментів верифікації `drat-trim` та `lrat-check`.

## 1. Архітектура та ієрархія форматів резолюційних сертифікатів

Траса резолюційного доведення — це послідовність синтаксичних дій над диз'юнктами, яка дозволяє зовнішньому незалежному перевіряльнику (checker) відтворити ланцюжок елімінацій до виводу порожнього диз'юнкта `⊥`.

### Семантика правил перевірки RUP та RAT

Перевірка додавання кожного нового диз'юнкта у сертифікаті спирається на два головні дедуктивні критерії:

1. **Reverse Unit Propagation (RUP)**:
   Диз'юнкт `C = (l₁ ∨ l₂ ∨ ... ∨ l_k)` має властивість RUP відносно поточного басейну дизюнктів `F`, якщо тимчасове додавання заперечень усіх його літералів `{¬l₁, ¬l₂, ..., ¬l_k}` як одиничних дизюнктів до `F` вимушує виникнення конфлікту за допомогою лише поширення одиничних літералів (Unit Propagation). Перевірка RUP дозволяє підтвердити, що диз'юнкт `C` є семантичним наслідком формули, не будуючи явне дерево резолюцій.

2. **Resolution Asymmetric Tautology (RAT)**:
   Диз'юнкт `C` має властивість RAT відносно `F` за першим літералом `p ∈ C` (pivot), якщо для кожного диз'юнкта `D ∈ F`, який містить протилежний літерал `¬p ∈ D`, резольвента `Res_p(C, D) = (C \ {p}) ∪ (D \ {¬p})` володіє властивістю RUP відносно `F`. Властивість RAT є більш потужною, ніж RUP, і дозволяє записувати в трасу кроки усунення змінних за алгоритмом Цейтіна та блокування хронологічних гілок.

### Специфікація форматів сертифікатів

Перевірка траси залежно від обраного стандарту має різну складність та вимоги до обсягу пам'яті:

| Формат | Повна назва | Опис та механізм перевірки | Відносна обчислювальна складність перевірки |
| :--- | :--- | :--- | :--- |
| **RUP** | Reverse Unit Propagation | Формат містить перелік доданих диз'юнктів. Кожен доданий диз'юнкт `C` перевіряється шляхом тимчасового заперечення його літералів `¬C` та виконання поширення одиничних дизюнктів (Unit Propagation) до виявлення конфлікту. | `O(N · M)` (потрібен пошук заперечених диз'юнктів) |
| **DRUP** | Deletion RUP | Розширює RUP операцією видалення `d`. Дозволяє явно вказувати, які конфліктні диз'юнкти більше не потрібні, що зменшує обсяг пам'яті перевіряльника у десятки разів. | `O(N · M)` |
| **DRAT** | Deletion Resolution Asymmetric Tautology | Стандарт змагань SAT Competition з 2014 року. Підтримує вивід складніших резолюційних кроків (блоки хронологічного заперечення, техніки усунення змінних за алгоритмами Цейтіна та узагальненої резолюції). | `O(N · log M)` |
| **LRAT** | Lineated DRAT | Розширює DRAT явними ідентифікаторами диз'юнктів-посилок. Перевіряльник не шукає посилки у базі даних, а одразу бере вказані ID, що дає лінійну швидкість перевірки `O(N)` та дозволяє формально верифікувати сам перевіряльник у Coq/Isabelle. | `O(N)` (лінійний час від розміру траси) |

## 2. Синтаксична граматика текстового формату DRAT

Текстовий файл траси DRAT використовує синтаксис, схожий на DIMACS CNF, і містить серію рядків додавання та видалення диз'юнктів. Кожен рядок описує один резолюційний крок.

### Граматика у формі Бэкуса — Науера (BNF)

```
<drat-trace>   ::= { <drat-line> }
<drat-line>    ::= [ "d" <whitespaces> ] <literal-list> "0" <newline>
<literal-list> ::= <literal> { <whitespaces> <literal> }
<literal>      ::= <nonzero-integer>
<whitespaces>  ::= { " " | "\t" }
<newline>      ::= "\n" | "\r\n"
```

Кожен літерал подається цілим числом зі знаком (`+1`, `-2`, `3`). Число `0` слугує обов'язковим термінатором рядка диз'юнкта.

### Практичний приклад текстової траси DRAT

Припустимо, початкова КНФ-формула містить диз'юнкти `1: (1 ∨ 2)` та `2: (-1 ∨ 2)`. Нижче наведено трасу DRAT, що додає резольвенту `(2)`, видаляє початковий диз'юнкт `(1 ∨ 2)` і завершує вивід порожнім диз'юнктом `0`:

```dimacs
2 0
d 1 2 0
0
```

- **Рядок `2 0`**: додає новий резольвентний диз'юнкт `(2)`. Перевіряльник перевіряє, що `(2)` випливає з наявної КНФ за допомогою RUP або RAT (резолюція між `1 ∨ 2` та `-1 ∨ 2` за змінною `1`).
- **Рядок `d 1 2 0`**: префікс `d` (deletion) вказує перевіряльнику вилучити диз'юнкт `1 ∨ 2` з оперативної пам'яті.
- **Рядок `0`**: додає порожній диз'юнкт `⊥` (термінатор траси), що підтверджує успішне спростування.

## 3. Граматика та специфікація формату LRAT

Формат LRAT (Lineated RAT) вирішує проблему квадратичної складності перевірки RUP, вимагаючи після кожного доданого диз'юнкта явного переліку ідентифікаторів диз'юнктів, що утворюють ланцюжок резолюцій.

### Синтаксис рядка LRAT

```
<line-id> <added-clause-literals> 0 <proof-chain-ids> 0 \n
d <deleted-clause-id-1> <deleted-clause-id-2> ... 0 \n
```

- `<line-id>`: унікальний зростаючий ідентифікатор диз'юнкта (починаючи з `N + 1`, де `N` — кількість початкових дизюнктів).
- `<proof-chain-ids>`: список ID дизюнктів, які використовуються у ланцюжку поширення одиничних літералів RUP. Якщо крок спирається на RAT, після від'ємного ID диз'юнкта вказуються ID диз'юнктів-посилок для кожного резолюційного розгалуження.

### Приклад траси LRAT

```dimacs
1 1 2 0 0
2 -1 2 0 0
3 1 -2 0 0
4 -1 -2 0 0
5 2 0 1 2 0
6 -2 0 3 4 0
7 0 5 6 0
```

*Пояснення кроків LRAT:*
- Рядки 1–4: визначення початкових диз'юнктів формули з присвоєнням їм ID 1, 2, 3, 4.
- Рядок 5: додавання диз'юнкта `(2)` під ID 5. Посилки резолюції явно вказано після першого `0`: диз'юнкти `1` та `2`.
- Рядок 6: додавання диз'юнкта `(-2)` під ID 6 з посилок `3` та `4`.
- Рядок 7: додавання порожнього диз'юнкта `0` під ID 7 з посилок `5` та `6`.

Завдяки наявності явних ID перевіряльник `lrat-check` виконує верифікацію за лінійний час `O(N)`, не витрачаючи час на пошук диз'юнктів у базі даних.

## 4. Бінарний формат стиснення Binary DRAT

Для великих індустріальних задач текстовий файл траси DRAT може важити десятки гігабайтів. Бінарний формат Binary DRAT зменшує обсяг файлу в 3–5 разів за рахунок кодування змінних байтами змінної довжини (Variable-Byte Encoding / LEB128).

### Схема бінарного кодування байтів

Кожна дія починається з одного характерного байта:
- `a` (ASCII `0x61` = 'a'): операція додавання диз'юнкта.
- `d` (ASCII `0x64` = 'd'): операція видалення диз'юнкта.

Кожен літерал `L` кодується беззнаковим цілим числом `U`:

```
U = (L > 0) ? (2 · L) : (2 · (-L) + 1)
```

Число `U` записується у 7-бітових фрагментах. Старший біт кожного байта (Bit 7) слугує прапорцем продовження (1 — попереду є ще байти літерала, 0 — останній байт літерала). Диз'юнкт завершується байтом `0x00`.

## 5. Програмний інтерфейс (C / C++ API) для логування резолюції

Нижче наведено специфікацію API, яке вбудовується в ядро SAT-розв'язувача для логування резолюційного сертифіката.

:::tabs
```c
#ifndef DRAT_PROOF_LOGGER_H
#define DRAT_PROOF_LOGGER_H

#include <stdio.h>
#include <stdbool.h>

// Контекст реєстратора траси
typedef struct {
    FILE *file;
    bool binary_mode;
    size_t added_clauses;
    size_t deleted_clauses;
} ProofLogger;

// Ініціалізація реєстратора
ProofLogger* proof_logger_open(const char *filename, bool binary_mode);

// Запис додавання диз'юнкта резолюції (завершується 0 у масиві lits)
void proof_logger_add_clause(ProofLogger *logger, const int *lits, size_t size);

// Запис видалення диз'юнкта
void proof_logger_delete_clause(ProofLogger *logger, const int *lits, size_t size);

// Закриття траси з записом порожнього диз'юнкта ⊥
void proof_logger_close(ProofLogger *logger);

#endif // DRAT_PROOF_LOGGER_H
```
```cpp
#ifndef DRAT_PROOF_LOGGER_HPP
#define DRAT_PROOF_LOGGER_HPP

#include <fstream>
#include <filesystem>
#include <vector>
#include <span>

namespace drat {

class ProofLogger {
private:
    std::ofstream file_;
    bool binary_mode_{false};
    size_t added_clauses_{0};
    size_t deleted_clauses_{0};

public:
    explicit ProofLogger(const std::filesystem::path& path, bool binary_mode = false);
    ~ProofLogger();

    ProofLogger(const ProofLogger&) = delete;
    ProofLogger& operator=(const ProofLogger&) = delete;
    ProofLogger(ProofLogger&&) noexcept = default;
    ProofLogger& operator=(ProofLogger&&) noexcept = default;

    void add_clause(std::span<const int> lits);
    void delete_clause(std::span<const int> lits);
    void close();

    [[nodiscard]] size_t added_count() const noexcept { return added_clauses_; }
    [[nodiscard]] size_t deleted_count() const noexcept { return deleted_clauses_; }
};

} // namespace drat

#endif // DRAT_PROOF_LOGGER_HPP
```

## 6. Утиліти перевірки та діагностика помилок

Для перевірки генерованих сертифікатів у командному рядку використовуються дві утиліти:

1. **`drat-trim`**: офіційна утиліта підтвердження DRAT-сертифікатів.
   ```bash
   drat-trim formula.cnf proof.drat -c proof.lrat
   ```
   *Призначення:* Перевіряє DRAT-трасу відносно формули `formula.cnf` і зворотним ходом будує оптимізовану LRAT-трасу `proof.lrat`, видаляючи некорисні резолюційні гілки.

2. **`lrat-check`**: формально верифікований перевіряльник лінійних трас.
   ```bash
   lrat-check formula.cnf proof.lrat
   ```
   *Призначення:* Спростовує `UNSAT` за лінійний час `O(N)`, гарантуючи відсутність помилок верифікатора.

### Типові коди та повідомлення про помилки верифікації

- `VERIFICATION SUCCESSFUL (FAILED TO SATISFY / UNSAT)`: траса коректна, порожній диз'юнкт `⊥` успішно доведено.
- `ERROR: RUP check failed for clause`: доданий диз'юнкт не є семантичним наслідком попередніх дизюнктів за допомогою поширення одиничних літералів (помилка у розв'язувачі).
- `ERROR: RAT check failed for pivot literal`: резольвента за pivot-літералом не пройшла перевірку RUP.
- `ERROR: Invalid Clause ID`: вказаний ID у файлі LRAT не існує або був видалений раніше.
