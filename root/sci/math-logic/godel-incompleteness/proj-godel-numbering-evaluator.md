# ⚙️ Реалізація нумерації Ґеделя та автоматична перевірка формальних доведень

Практична реалізація підсистеми синтаксичного кодування, декодування та формальної верифікації доведень для іграшкової мови арифметики першого порядку демонструє втілення концептуальних ідей Курта Ґеделя у реальних обчислювальних структурах даних, формальних AST-деревах та алгоритмах кодування через степені простих чисел.

## 1. Архітектура синтаксичних структур та алгоритму кодування

У формальній логіці та теорії обчислень арифметизація синтаксису вимагає побудови чіткого відображення між текстовими формулами та числовими значеннями. Програмний комплекс складається з трьох ключових системних модулів:

1. **Синтаксичні токени та AST-представлення виразів:** кожна формула або терм описується вузлом рекурсивного дерева (константа `Zero`, наступник `Succ`, змінна `Var`, добуток, додавання, заперечення, імпликація, квантор існування). Кожному базовому символу алфавіту відповідає унікальний цілочисельний ідентифікатор `1..11`.
2. **Модуль кодування та декодування Ґеделя (Gödel Encoder/Decoder):** перетворює вхідний вектор токенів у унікальне велике натуральне число та здійснює зворотну реконструкцію вихідного рядка шляхом розкладу числа на прості множники відповідно до Основної теореми арифметики.
3. **Верифікатор доведень (Proof Checker):** перевіряє скінченну послідовність формул `φ₁, φ₂, ..., φ⡭` на відповідність аксіомам формальної арифметики та правилу виведення Modus Ponens (`A` та `A → B` ⊢ `B`).

Для забезпечення чистоти мовної моделі та порівняння системних підходів надано два варіанти реалізації: низькорівневий варіант мовою **C** та сучасний типубезпечний варіант мовою **C++** з використанням RAII, умних вказівників, шаблонів та обробки помилок через `std::expected`.

## 3. Детальний розбір механізму кодування та розкладу на прості множники

Основний алгоритм кодування базується на зв'язку між порядковим номером токена у послідовності та послідовними простими числами `p₁, p₂, p₃, ...`. Кожен токен `sᵢ` перетворюється на показник степеня відповідного простого числа `pᵢˢⁱ`.

Розглянемо покроково, як відбувається обчислення для виразу `¬ ( x = 0 )`:

1. Перший токен `¬` має тип `TOK_NOT = 6`. Він зіставляється з першим простим числом `p₁ = 2`. Обчислюється фактор `2⁶ = 64`.
2. Другий токен `(` має тип `TOK_LPAR = 10`. Він зіставляється з другим простим числом `p₂ = 3`. Обчислюється фактор `3¹⁰ = 59049`.
3. Третій токен `x` має тип `TOK_VAR = 9`. Він зіставляється з третім простим числом `p₃ = 5`. Обчислюється фактор `5⁹ = 1953125`.
4. Четвертий токен `=` має тип `TOK_EQ = 5`. Він зіставляється з четвертим простим числом `p₄ = 7`. Обчислюється фактор `7⁵ = 16807`.
5. П'ятий токен `0` має тип `TOK_ZERO = 1`. Він зіставляється з п'ятим простим числом `p₅ = 11`. Обчислюється фактор `11¹ = 11`.
6. Шостий токен `)` має тип `TOK_RPAR = 11`. Він зіставляється з шостим простим числом `p₆ = 13`. Обчислюється фактор `13¹¹ = 1792160394037`.

Загальний Ґеделів номер для такої короткої формули дорівнює добутку всіх шести факторів:

```
g = 2⁶ · 3¹⁰ · 5⁹ · 7⁵ · 11¹ · 13¹¹
```

Цей добуток є унікальним натуральним числом. Завдяки Основній теоремі арифметики, довільне натуральне число `g > 1` розкладається на прості множники єдиним чином. Зворотна процедура декодування послідовно ділить число `g` на `p₁`, рахуючи кількість ділень без залишку до одержання показника `s₁`, після чого переходить до `p₂` і так далі.

## 4. Алгоритмічний верифікатор правил виведення Modus Ponens

Формальне доведення у синтаксичній системі являє собою вектор формул `[F₁, F₂, ..., F⡭]`, де кожна формула `F⡭` або є аксіомою, або одержана з попередніх формул `Fᵢ`, `Fⱼ` (`i, j < k`) за допомогою правила виведення Modus Ponens:

```
З формул  A  та  A → B  виводиться  B
```

Реалізований функціонал `verify_modus_ponens` у класах C та C++ виконує строгу підстрокову перевірку рівності токенів:

1. Перевіряється, чи довжина формули-посилки `A → B` строго дорівнює сумі довжин `A`, `B` та одного токена оператора імпликації.
2. Здійснюється поелементне порівняння префікса формули `A → B` з токенами формули `A`.
3. Перевіряється наявність токена `TOK_IMPL` безпосередньо після префікса.
4. Здійснюється поелементне порівняння суфікса формули `A → B` з токенами формули `B`.

Якщо всі чотири умови виконуються, виведення вважається синтаксично коректним.

## 5. Простеження та розбір крайових випадків у модулях кодування

Під час синтаксичного кодування та верифікації реальних логічних виразів виникають специфічні крайові випадки, які потребують обробки на рівні структури даних:

- **Порожні послідовності токенів:** якщо кодувальнику передати порожній масив токенів `count == 0`, функція повертає 1 (нейтральний елемент по множенню). Проте верифікатор вважає порожню формулу синтаксично некоректною.
- **Переповнення розрядності цілих чисел:** для виразів довжиною понад 12 токенів значення Ґеделевого номера перевищує межу 64-бітного цілого `18 446 744 073 709 551 615`. У практичних SMT-доводчиках та верифікаторах використовується довготривала арифметика довільної точності (`BigInt`).
- **Синтаксичний конфлікт змінних:** при генерації Ґеделевих номерів для формул із закладеною рекурсією (як у діагональній лемі) важливо уникати затінення вільних змінних зв'язаними кванторами. Модуль підставлення здійснює альфа-конверсію (перейменування зв'язаних змінних) перед виконанням підставлення.

## 6. Обчислювальна складність та порівняння системних підходів

У наведеній реалізації застосовується прямолінійний підхід до розкладу натуральних чисел на прості множники. З обчислювальної точки зору слід звернути увагу на такі апаратні обмеження:

1. **Експоненціальний ріст чисел Ґеделя:** оскільки кодування використовує степеневий добуток `p₁ˢ¹ · p₂ˢ² · ... · p⡭ˢᵏ`, навіть для коротких формул з 10 токенів значення Ґеделевого номера швидко перевищує межі стандартних 64-бітних цілочисельних типів `uint64_t`. Для повноцінної верифікації реальних логічних систем вимагається використання бібліотек довгої арифметики довільної точності (таких як GMP або `std::bigint`).
2. **Алгоритмічна складність верифікації:** перевірка формального доведення довжини `M` кроків з максимальними кодами формул `N` вимагає часу `O(M · log N)`, що є примітивно-рекурсивним процесом і виконується за поліноміальний час від довжини доведення.
3. **Типобезпека C++ проти C:** C++ варіант забезпечує повну відсутність витоків пам'яті за рахунок контейнера `std::vector` та обробляє помилки через `std::expected` без небезпечних покажчиків і ручного управління пам'яттю `malloc/free`.
