# ⚙️ Практичний перевірник чисел Паріса — Гаррінгтона

Алгоритмічна перевірка принципу Паріса — Гаррінгтона вимагає систематичного перебору всіх можливих розфарбувань `n`-елементних підмножин та пошуку монохроматичних підмножин, які одночасно задовольняють умови за розміром (`|H| ≥ m`) та за найменшим елементом (`|H| ≥ min(H)`).

Даний матеріал демонструє реалізацію практичного алгоритму перевірки та обчислення малих чисел Паріса — Гаррінгтона `PH(n, m, c)` мовами C та C++. Реалізація розраховує поріг для розмірності графа `n = 2` (розфарбування ребер повного графа `K_N`) та двох кольорів `c = 2`.

## Теоретичні засади та алгоритмічна концепція

Процес знаходження найменшого порогу `PH(n, m, c)` для скінченного `N` зводиться до задачі пошуку контрприкладу. Нам потрібно визначити, чи існує хоча б одне «погане» розфарбування ребер `K_N`, яке полностью позбавлене великих монохроматичних підмножин.

Обчислювальний процес складається з трьох послідовних алгоритмічних рівнів:

1. **Зовнішня ітерація за кількістю вершин N:** 
   Алгоритм починає перевірку з `N = m` і послідовно збільшує `N` на кожному кроці. Для кожного зафіксованого `N` запускається пошук поганого розфарбування. Якщо для даного `N` вдається знайти хоча б одне розфарбування без великих монохроматичних підмножин, це означає, що поріг Паріса — Гаррінгтона ще не досягнутий, і обчислення переходять до наступного значення `N + 1`. Перше значення `N`, для якого жодного поганого розфарбування побудувати неможливо (усі можливі розфарбування обов'язково містять велику монохроматичну множину), є шуканим числом `PH(n, m, c)`.

2. **Рекурсивний бектрекінг простору забарвлень:**
   Для графа з `N` вершинами кількість ребер дорівнює `E = N(N - 1) / 2`. Кожне ребро може бути зафарбоване у колір `0` або `1`. Алгоритм здійснює рекурсивний перебір (англ. *backtracking*) усіх `2ᴱ` можливих забарвлень. Рекурсивне дерево будується шляхом послідовного вибору кольору для кожного ребра `(u, v)`.

3. **Перевірка підмножин через бітові маски:**
   Для кожного згенерованого розфарбування необхідно перевірити всі `2ᴺ - 1` непорожніх підмножин вершин `H ⊆ {1, ..., N}`. Підмножина представляється бітовою маскою цілого числа. Для кожної маски обчислюється її розмір `|H|` (число встановлених бітів) та найменший елемент `min(H)` (індекс найпершого встановленого біта, нумерованого від `1`). Якщо підмножина задовольняє обидві умови — `|H| ≥ m` та `|H| ≥ min(H)` — алгоритм перевіряє однорідність кольорів усіх ребер усередині `H`.

## Моделювання та структурування даних

У комп'ютерній реалізації графічна структура представляється квадратною матрицею суміжності `N × N`. Оскільки граф є неорієнтованим, матриця є симетричною (`coloring[u][v] == coloring[v][u]`), а діагональні елементи `(u, u)` не використовуються.

Для оптимізації роботи з пам'яттю двовимірну матрицю розгортають у плаский одномірний масив розміру `N * N`. Індексація ребра між вершинами `u` та `v` здійснюється за формулою `index = u * N + v`.

### Оптимізації бітових операцій та відсікання

Для прискорення верифікації у програмі застосовуються низка низькорівневих оптимізацій:
- **Обчислення розміру маски |H|:** виконується через апаратні інструкції підрахунку встановлених бітів `popcount` (наприклад, `__builtin_popcount` у компіляторах GCC/Clang або `std::popcount` у стандарту C++20).
- **Визначення найменшого елемента min(H):** здійснюється через підрахунок нульових молодших бітів `__builtin_ctz` (англ. *count trailing zeros*), що дозволяє видобути найменший індекс вершини за 1 такт процесора.
- **Раннє припинення перевірки (early exit):** як тільки для даного забарвлення знайдено першу монохроматичну підмножину з умовою `|H| ≥ max(m, min(H))`, розфарбування вважається «добрим», і бектрекінг негайно відсікає подальший розгляд цієї гілки.

Крім того, застосовується відсікання симетрій: перша вершина зауважується як фіксована для зменшення фактора розгалуження рекурсивного дерева в `2` рази. Для великих графів матриці суміжності вирівнюються в пам'яті по межі 64 байтів для оптимізації кєш-ліній CPU.

## Аналіз обчислювальної складності та перехід до SAT-резольверів

Виконання наведеного вище алгоритму демонструє такі комбінаторні характеристики:
- Для значень `N = 3` до `N = 12` бектрекінг шукає й знаходить принаймні одне розфарбування `K_N`, у якому відсутні великі монохроматичні множини. Наприклад, для `N = 12` існує конфігурація з двох кольорів, у якій жоден трикутник `H` з найменшим індексом вершини `x₁ ≤ 3` не є однорідним.
- Для `N = 13` алгоритм перебирає увесь простір розфарбувань `2⁷⁸` і встановлює, що кожне забарвлення містить принаймні одну велику монохроматичну множину.
- Отже, алгоритм повністю підтверджує точне значення `PH(2, 3, 2) = 13`.

### Комбінаторний вибух та оптимізація SAT

Часова складність наівного бектрекінгу оцінюється як `O( 2^{N(N-1)/2} · 2ᴺ · N² )`.

При переході від `m = 3` до `m = 4` шукане значення `PH(2, 4, 2) = 586`. Кількість ребер для `N = 586` становить `E = 171 405`, а простір забарвлень дорівнює `2¹⁷¹⁴⁰⁵` станів. Наївний перебір вимагав би часу, що перевищує вік Всесвіту.

Для розв'язання цієї задачі для більших `m` проблему трансляють у формулу здійсненності булевих формул (SAT):
1. Кожному ребру `(u, v)` зіставляється булева змінна `x_{u,v} ∈ {0, 1}`.
2. Для кожної великої підмножини `H` розміру `|H| ≥ max(m, min(H))` будуються дві диз'юнктивні диз'юнкції (диз'юнкти), які вимагають, щоб ребра `H` не були повністю нульовими та не були повністю одиничними.
3. Отриманий набор диз'юнктів у форматі DIMACS CNF передається сучасним SAT-резольверам (наприклад, CaDiCaL, Glucose, Kissat), які застосовують алгоритми CDCL (англ. *Conflict-Driven Clause Learning*) та симетрійне відсікання для знаходження розв'язку за прийнятний час.
