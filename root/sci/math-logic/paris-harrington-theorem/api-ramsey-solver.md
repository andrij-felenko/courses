# 📋 Інтерфейс бібліотеки верифікації графічних забарвлень

Специфікація інтерфейсу програмного модуля `libphramsey` визначає контракти викликів, структури даних та функції верифікації для аналізу підсиленого принципу Рамсея (теореми Паріса — Гаррінгтона) на графах та гіперграфах.

Цей модуль призначено для використання у складі програмних систем формальної верифікації, автоматичного доведення теорем та дослідницьких інструментів комбінаторного аналізу. Інтерфейс забезпечує потокобезпечне обчислення параметрів розфарбування, перевірку умов великих множин та пошук мінімальних порогів `PH(n, m, c)`.

Модуль надає розробникам можливість налаштовувати параметри розмірності, встановлювати жорсткі тайм-аути для запобігання нескінченному зависанню обчислювальних потоків та збирати детальну статистику перевірених підмножин і розфарбувань. Інтерфейс підтримує модульне розширення для інтеграції із зовнішніми SAT-резольверами.

## Архітектурні засади та безпека пам'яті

Пакет `libphramsey` побудовано за принципами мінімального накладного витрачання ресурсів та повної ізоляції обчислювальних контекстів. Основні архітектурні гарантії бібліотеки включають:
- **Відсутність побічних ефектів:** Жодна з API-функцій не використовує статичний або глобальний стан, що дозволяє виконувати паралельні виклики у багатопотокових середовищах без блокування контексту.
- **Строгий контроль виділення ресурсів:** Усі масиви для збереження забарвлень та бітових масок виділяються динамічно з обов'язковою перевіркою результату `NULL`. У разі виникнення помилок пам'ять повністю звільняється.
- **Передбачуваність завершення:** Для довготривалих переборів підтримується тайм-аут `timeout_ms`, після закінчення якого функція призупиняє пошук та повертає код `PH_ERROR_TIMEOUT`.
- **Інвар'янтність типів:** Інтерфейс гарантує двійкову сумісність C ABI між різними версіями компіляторів та платформ.

Крім того, бібліотека підтримує користувацькі алокатори пам'яті для вбудованих систем із жорстким обмеженням кучі.

## Послідовність викликів та життєвий цикл об'єкта верифікації

Стандартний сценарій використання бібліотеки розробником передбачає чотири послідовні фази виконання:
1. **Фаза ініціалізації конфігурації:** Створення локального екземпляра `ph_config_t` та його первинна заповненість дефолтними значеннями за допомогою виклику `ph_config_init`. Розробник налаштовує параметри `target_m`, `dimension`, `num_colors` та часовий ліміт `timeout_ms`.
2. **Фаза розподілу ресурсів:** Виклик основної функції `ph_compute_bound`, яка автоматично алокує потрібну кількість оперативної пам'яті під матриці розфарбування `N × N` та бітові кеші підмножин.
3. **Фаза обчислювального пошуку:** Алгоритм здійснює покроковий перебір забарвлень та бітових масок, оновлюючи статистику у структурі `ph_result_t`.
4. **Фаза завершення та діагностики:** Обчислювальний модуль повертає відповідний статус `ph_status_t`, а викличувана програма аналізує отримані результати й звільняє виділені буфери.

У разі повернення статусу помилки всі проміжні масиви гарантовано очищаються для запобігання витокам пам'яті.

## Детальний опис структур даних та інтерфейсів

Розглянемо базові типи даних, які формують програмний контракт модуля `libphramsey`.

### 1. Перелічувальний тип статусів `ph_status_t`

Усі функції API повертають значення статусів для однозначної ідентифікації результату або причини відмови.

:::tabs
```c
typedef enum {
    PH_SUCCESS                  = 0,  // Операція завершилася успішно
    PH_ERROR_INVALID_PARAM      = 1,  // Некоректні вхідні параметри
    PH_ERROR_OUT_OF_MEMORY      = 2,  // Недостатньо оперативної пам'яті
    PH_ERROR_TIMEOUT            = 3,  // Перевищено ліміт часу обчислення
    PH_FOUND_BAD_COLORING       = 4,  // Знайдено контрприклад (погане розфарбування)
    PH_NO_BAD_COLORING_EXISTS   = 5   // Доведено відсутність контрприкладів
} ph_status_t;
```
```cpp
enum class PhStatus : int32_t {
    Success                 = 0,  // Операція завершилася успішно
    ErrorInvalidParam       = 1,  // Некоректні вхідні параметри
    ErrorOutOfMemory        = 2,  // Недостатньо оперативної пам'яті
    ErrorTimeout            = 3,  // Перевищено ліміт часу обчислення
    FoundBadColoring        = 4,  // Знайдено контрприклад (погане розфарбування)
    NoBadColoringExists     = 5   // Доведено відсутність контрприкладів
};
```
:::

Семантика кодів помилок та кожна з гілок обробки мають чітку математичну логіку:
- `PH_SUCCESS` / `PhStatus::Success`: функцію виконано успішно, усі передані буфери є валідними.
- `PH_ERROR_INVALID_PARAM` / `PhStatus::ErrorInvalidParam`: некоректні числові межі, зокрема якщо `dimension < 1` або `num_colors < 1`.
- `PH_ERROR_OUT_OF_MEMORY` / `PhStatus::ErrorOutOfMemory`: помилка виділення бувера у разі вичерпання кучі.
- `PH_ERROR_TIMEOUT` / `PhStatus::ErrorTimeout`: обчислювальний потік перевищив заданий ліміт часу `timeout_ms`.
- `PH_FOUND_BAD_COLORING` / `PhStatus::FoundBadColoring`: знайдено контрприклад забарвлення без великих однорідних підмножин.
- `PH_NO_BAD_COLORING_EXISTS` / `PhStatus::NoBadColoringExists`: доведено, що всі розфарбування містять велику монохроматичну множину.

### 2. Конфігураційна структура `ph_config_t`

Визначає математичні та обчислювальні параметри пошуку:

:::tabs
```c
typedef struct {
    uint32_t dimension;          // Розмірність гіперребер n (n = 2 для звичайних графів)
    uint32_t target_m;           // Мінімальний поріг розміру монохроматичної множини |H| >= m
    uint32_t num_colors;         // Кількість кольорів c >= 1
    uint32_t max_nodes_N;        // Максимальна кількість вершин N для перевірки
    uint64_t timeout_ms;         // Ліміт часу виконання у мілісекундах (0 - без ліміту)
    bool     enable_memoization; // Прапор увімкнення кешування підструктур
} ph_config_t;
```
```cpp
struct PhConfig {
    std::uint32_t dimension{2};          // Розмірність гіперребер n
    std::uint32_t target_m{3};           // Поріг розміру монохроматичної множини
    std::uint32_t num_colors{2};         // Кількість кольорів c
    std::uint32_t max_nodes_N{30};       // Максимальна кількість вершин N
    std::uint64_t timeout_ms{0};         // Ліміт часу виконання у мілісекундах
    bool          enable_memoization{true}; // Кешування підструктур
};
```
:::

Опис алгоритмічного впливу кожного поля структури:
- `dimension`: визначає розмірність підмножин `n`. При `n = 2` обробляються звичайні графи, при `n = 3` — 3-гіперграфи.
- `target_m`: встановлює нижню межу розміру монохроматичної підмножини `|H| ≥ m`.
- `num_colors`: задає кількість доступних кольорів `c` у функції розфарбування.
- `max_nodes_N`: обмежує максимальну кількість вершин `N` під час автоматичного покрокового перебору.
- `timeout_ms`: примусово зупиняє розраховувальний потік після збігання вказаної кількості мілісекунд.
- `enable_memoization`: активує таблиці підрахунку ізоморфних підмножин для скорочення повторних обчислень.

### 3. Структура підсумкових результатів `ph_result_t`

Слугує для збору підсумкових обчислювальних метрик та профілювання роботи алгоритму:

:::tabs
```c
typedef struct {
    ph_status_t status;             // Підсумковий статус виконання
    uint32_t    computed_N;         // Знайдене значення числа PH(n, m, c) або 0
    uint64_t    subsets_checked;    // Загальна кількість перевірених підмножин вершин
    uint64_t    colorings_tested;   // Кількість згенерованих та оцінених забарвлень
    double      execution_time_sec; // Час обчислень у секундах з плаваючою крапкою
} ph_result_t;
```
```cpp
struct PhResult {
    PhStatus      status{PhStatus::Success}; // Підсумковий статус виконання
    std::uint32_t computed_N{0};             // Знайдене значення числа PH(n, m, c)
    std::uint64_t subsets_checked{0};        // Кількість перевірених підмножин вершин
    std::uint64_t colorings_tested{0};       // Кількість оцінених забарвлень
    double        execution_time_sec{0.0};   // Час обчислень у секундах
};
```

## Інтеграція із SAT-резольверами та розширені режими

Для обчислення порогів при `m ≥ 4` модуль `libphramsey` підтримує експорт комбінаторних обмежень у форматах CNF (англ. *Conjunctive Normal Form*).

### Генерація диз'юнктів для формату DIMACS CNF

Процедура трансляції перетворює кожну умову принципу Паріса — Гаррінгтона на логічні диз'юнкти. Для графа з `N` вершинами створюються булеві змінні `P_{u,v}` для кожного ребра.

Для кожної підмножини `H ⊆ {1, ..., N}`, яка є великою (`|H| ≥ min(H)`) та має розмір `|H| ≥ m`, генеруються два диз'юнкти:
1. Заборона монохроматичності кольору 0: принаймні одне ребро в `H` має колір 1.
2. Заборона монохроматичності кольору 1: принаймні одне ребро в `H` має колір 0.

Транслятор записує сформований набір у файл формату DIMACS, що дозволяє передавати його зовнішнім резольверам CaDiCaL або Kissat.

### Приклад обробки та діагностики помилок

При виклику API розробник повинен завжди аналізувати повернутий статус:

:::tabs
```c
ph_config_t config;
ph_config_init(&config);
config.target_m = 3;
config.num_colors = 2;

ph_result_t result;
ph_status_t st = ph_compute_bound(&config, &result);

if (st == PH_SUCCESS) {
    printf("Обчислено поріг PH: %u за %.3f сек.\n", 
           result.computed_N, result.execution_time_sec);
} else if (st == PH_ERROR_TIMEOUT) {
    fprintf(stderr, "Обчислення перервано за тайм-аутом.\n");
}
```
```cpp
PhConfig config;
config.target_m = 3;
config.num_colors = 2;

PhResult result = compute_bound(config);
if (result.status == PhStatus::Success) {
    std::cout << "Обчислено поріг PH: " << result.computed_N
              << " за " << result.execution_time_sec << " сек.\n";
} else if (result.status == PhStatus::ErrorTimeout) {
    std::cerr << "Обчислення перервано за тайм-аутом.\n";
}
```
:::

## Обмеження за пам'яттю, потокобезпечність та вибух складності

Оскільки кількість підмножин для графа з `N` вершинами дорівнює `2ᴺ`, а кількість розфарбувань ребер для `c = 2` становить `2^{N(N-1)/2}`, використання бібліотеки вимагає дотримання суворих обчислювальних застережень:

1. **Граничний розмір `N ≤ 30` для наївного бектрекінгу:**
   Для значення `N = 30` кількість можливих ребер становить `435`, а простір шуканих забарвлень становить `2⁴³⁵` станів, що унеможливлює повний перебір без використання SAT-резольверів або симетрійних скорочень.
2. **Параметр `n ≥ 3` (Гіперграфи):**
   При `n = 3` функція `PH(3, m, c)` досягає рівня вежі експонент, тому практична обчислюваність обмнежується значеннями `m ≤ 4`.
3. **Потокобезпечність (Thread-safety):**
   Бібліотека не використовує глобальних змінних стану та є повністю потокобезпечною (англ. *thread-safe*). Різні паралельні нитки можуть одночасно викликати `ph_compute_bound` з власними екземплярами `ph_config_t`.
