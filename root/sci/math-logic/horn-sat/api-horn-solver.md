# 📋 Інтерфейс та специфікація Horn-SAT Solver C/C++ API

Даний документ являє собою повну довідкову специфікацію програмного інтерфейсу (API) та контракту взаємодії для бібліотеки розв'язання задачі здійснюваності хорнівських диз'юнктів (Horn-SAT Solver). Бібліотека реалізує лінійний алгоритм Даулінґа — Ґальє та надає стабільні інтерфейси для мов C (стандарт C99) та C++ (стандарт C++20).

## Загальний огляд контракту та життєвого циклу

Бібліотека призначена для швидкої оцінки здійснюваності хорнівських формул, виведення логічних наслідків у експертних системах, перевірки обмежень цілісності у базах даних та аналізу прав доступу.

### Основні концепції

- **Змінна (`HornVar` / `Var`):** Ціле число в діапазоні від `0` до `V - 1`, де `V` — загальна кількість оголошених змінних.
- **Диз'юнкт Хорна:** Булева кон'юнкція умов (тіло), що імплікує один атом або суперечність (голова).
- **Мінімальна модель:** У разі здійснюваності формули бібліотека гарантує повернення єдиної мінімальної за включенням модели `Mₘᵢₙ`, у якій значення `1` мають тільки ті змінні, чия істинність є неминучим наслідком заданих фактів і правил.

### Стан екземпляра розв'язувача

Екземпляр розв'язувача перебуває в одному з трьох станів:
1. **`UNINITIALIZED`:** Пам'ять не виділено або об'єкт знищено.
2. **`BUILDING`:** Процес додавання фактів, правил та обмежень. Початковий стан після створення.
3. **`SOLVED`:** Виконано виклики розв'язання. Формулу зафіксовано, обчислено статус (`SAT` / `UNSAT`) та масив істинності моделей.

```
       +------------------+
       |  UNINITIALIZED   |
       +------------------+
                 |
        create() | free()
                 v
       +------------------+  add_fact() / add_rule()
       |     BUILDING     |--------------------------+
       +------------------+                          |
                 |                                   | (накопичення формули)
         solve() |                                   v
                 +---------------------------->+-----------+
                                               | BUILDING  |
                                               +-----------+
                                                     |
                                             solve() |
                                                     v
                                              +--------------+
                                              |    SOLVED    |
                                              +--------------+
```

## Специфікація типів даних C та C++ API

:::tabs
```c
typedef int32_t HornVar;
typedef int32_t HornClauseId;

#define HORN_VAR_NONE ((HornVar)-1)

typedef enum {
    HORN_OK = 0,
    HORN_RESULT_SAT = 1,
    HORN_RESULT_UNSAT = 2,
    HORN_ERR_NULL_POINTER = -1,
    HORN_ERR_INVALID_VAR = -2,
    HORN_ERR_INVALID_STATE = -3,
    HORN_ERR_OUT_OF_MEMORY = -4,
    HORN_ERR_DUPLICATE_LITERAL = -5
} HornErrorCode;

typedef struct HornSolverC HornSolverC;
```
```cpp
namespace horn {

using Var = int32_t;
inline constexpr Var VarNone = -1;

enum class SolutionStatus : uint8_t {
    Sat,
    Unsat
};

enum class ErrorCode : int32_t {
    Ok = 0,
    NullPointer = -1,
    InvalidVar = -2,
    InvalidState = -3,
    OutOfMemory = -4,
    DuplicateLiteral = -5
};

class HornSolver;

} // namespace horn
```
:::

## Зведена таблиця функцій C та методів C++ API

| Функція C API | Метод C++ API | Опис і призначення | Часова складність |
| :--- | :--- | :--- | :--- |
| `horn_solver_create(num_vars)` | `HornSolver(num_vars)` | Створює новий екземпляр розв'язувача для `num_vars` змінних. | `O(V)` |
| `horn_solver_free(solver)` | `~HornSolver()` | Звільняє всі ресурси та пам'ять екземпляра (RAII у C++). | `O(V + N)` |
| `horn_solver_reset(solver)` | `reset()` | Очищає всі додані диз'юнкти, залишаючи кількість змінних. | `O(V + N)` |
| `horn_solver_add_fact(solver, head)` | `add_fact(head)` | Додає безумовний факт `⊤ → head`. | `O(1)` |
| `horn_solver_add_rule(s, b, len, head)` | `add_rule(body, head)` | Додає стверджувальне правило `(body[0] ∧ ...) → head`. | `O(k)` |
| `horn_solver_add_constraint(s, b, len)` | `add_constraint(body)` | Додає негативне обмеження `(body[0] ∧ ...) → ⊥`. | `O(m)` |
| `horn_solver_solve(solver)` | `solve()` | Обчислює здійснюваність та будує мінімальну модель. | `O(V + N)` |
| `horn_solver_get_value(solver, var)` | `is_true(var)` | Повертає значення змінної (`1` або `0`) у обчисленій моделі. | `O(1)` |
| `horn_solver_get_model(s, out_buf)` | `model()` | Отримує доступа до масиву моделі розміром `V`. | `O(V)` |

## Детальні підписи та контракти методів

### Створення екземпляра (Construction)

:::tabs
```c
HornSolverC* horn_solver_create(size_t num_vars);
```
```cpp
explicit HornSolver::HornSolver(size_t num_vars);
```
:::

- **Призначення:** Виділяє пам'ять і ініціалізує розв'язувач для роботи зі змінними `0 .. num_vars - 1`.
- **Параметри:** `num_vars` — загальна кількість змінних у системі. Значення має бути `> 0`.
- **Повертає:** Покажчик на `HornSolverC` при успіху або `NULL` при недостатній пам'яті (у C); у C++ конструює об'єкт або кидає `std::bad_alloc`.
- **Прекондиція:** `num_vars > 0`.
- **Посткондиція:** Створений розв'язувач перебуває у стані `BUILDING`.

### Ствердження факту (Fact Addition)

:::tabs
```c
HornErrorCode horn_solver_add_fact(HornSolverC* solver, HornVar head);
```
```cpp
void HornSolver::add_fact(Var head);
```
:::

- **Призначення:** Сверджує факт `head = 1`.
- **Параметри:** 
  - `head` — індекс змінної `0 <= head < num_vars`.
- **Повертає:** `HORN_OK` при успіху, або відповідний код помилки у C; у C++ кидає `std::invalid_argument` у разі некоректного індексу.
- **Прекондиція:** стан `BUILDING`, `0 <= head < num_vars`.

### Додавання правила (Rule Addition)

:::tabs
```c
HornErrorCode horn_solver_add_rule(
    HornSolverC* solver,
    const HornVar* body,
    size_t body_size,
    HornVar head
);
```
```cpp
void HornSolver::add_rule(std::span<const Var> body, Var head);
```
:::

- **Призначення:** Додає імпликаційне правило `(body[0] ∧ body[1] ∧ ... ∧ body[body_size-1]) → head`.
- **Параметри:**
  - `body` — масив або `std::span` індексів змінних у лівій частині. Якщо `body_size == 0`, виклик еквівалентний `add_fact`.
  - `head` — змінна-висновок (`0 <= head < num_vars`).
- **Повертає:** `HORN_OK` або код помилки у C; `void` або виняток у C++.

### Додавання обмеження цілісності (Constraint Addition)

:::tabs
```c
HornErrorCode horn_solver_add_constraint(
    HornSolverC* solver,
    const HornVar* body,
    size_t body_size
);
```
```cpp
void HornSolver::add_constraint(std::span<const Var> body);
```
:::

- **Призначення:** Додає обмеження цілісності `(body[0] ∧ ... ∧ body[body_size-1]) → ⊥`.
- **Параметри:** `body` — масив змінних умові (`body_size > 0`).

### Обчислення здійснюваності (Solving)

:::tabs
```c
HornErrorCode horn_solver_solve(HornSolverC* solver);
```
```cpp
SolutionStatus HornSolver::solve();
```
:::

- **Призначення:** Запускає каскад поширення одиниць Даулінґа — Ґальє.
- **Повертає:** `HORN_RESULT_SAT` (`SolutionStatus::Sat`) якщо формула здійсненна, або `HORN_RESULT_UNSAT` (`SolutionStatus::Unsat`) якщо виявлено суперечність.
- **Посткондиція:** Розв'язувач переходить у стан `SOLVED`.

## Детальний опис кодів помилок

У C API функції повертають цілочисельний код `HornErrorCode`. У C++ API виклики перевіряють входження змінних та кидають стандартні винятки `std::invalid_argument` або `std::out_of_range`.

```
  Код помилки C API       Значення   Опис причини виникнення
─────────────────────────────────────────────────────────────────────────────
  HORN_OK                     0      Операцію виконано успішно.
  HORN_RESULT_SAT             1      Формула є здійсненною (SAT).
  HORN_RESULT_UNSAT           2      Формула є суперечливою (UNSAT).
  HORN_ERR_NULL_POINTER      -1      Передано нульовий покажчик solver == NULL.
  HORN_ERR_INVALID_VAR       -2      Передано індекс змінної var < 0 або var >= V.
  HORN_ERR_INVALID_STATE     -3      Спроба додати диз'юнкт після виклика solve().
  HORN_ERR_OUT_OF_MEMORY     -4      Не вдалося виділити пам'ять у системному купі.
  HORN_ERR_DUPLICATE_LITERAL -5      Тіло диз'юнкта містить дубльовані змінні.
```

## Інваріанти та крайові випадки (Edge Cases)

Поведінка розв'язувача строго визначена на всіх гранічних та нестандартних конфігураціях формул.

### 1. Порожня формула (запропоновано 0 диз'юнктів)
Якщо після створення `HornSolver(V)` не було додано жодного факту чи правила, виклик `solve()` повертає `SAT`. Усі змінні `xᵢ` отримують значення `0`. Це є коректним, оскільки порожня множина `∅` є мінімальною моделлю для порожнього набору правил.

### 2. Формули без фактів (тільки правила та обмеження)
Якщо формула містить правила вигляду `(x₁ ∧ x₂) → x₃` та обмеження `(x₄ ∧ x₅) → ⊥`, але не містить жодного факту `⊤ → q`, черга ініціалізується порожньою. Алгоритм зупиняється за `O(1)` і повертає `SAT` із тотожно нульовою моделлю `M = {0, 0, ..., 0}`.

### 3. Безпосередньо суперечливі факти (`A = 1` та `A → ⊥`)
Якщо до формули додано факт `⊤ → A` та обмеження `A → ⊥`:
1. При додаванні факт `A` потрапляє в чергу і `assignment[A] = 1`.
2. На першому ж кроці `solve()` змінна `A` виймається з черги, декрементує лічильник обмеження `A → ⊥` до 0 і негайно викликає повернення `UNSAT`.

### 4. Тавтологічні правила (`A → A`)
Правила вигляду `A → A` додаються у списки суміжності `body_adj[A]`. Якщо `A` стає 1, декремент лічильника робить `count = 0` і намагається встановити `assignment[A] = 1`. Оскільки `assignment[A]` вже дорівнює 1, змінна повторно у чергу не додається. Тавтології не впливають на результат та не спричиняють нескінченних циклів.

## Управління пам'яттю та ресурсами (Memory Lifecycle)

Специфікація вимагає строгой дисципліни управління динамічною пам'яттю:

1. **C API:**
   - Кожен успішний виклик `horn_solver_create` має парний виклик `horn_solver_free`.
   - Усі внутрішні вузли списків суміжності `AdjNode`, масиви лічильників та черги звільняються в `horn_solver_free`.
   - Клієнтський код не повинен зберігати покажчики на внутрішні масиви після виклику `horn_solver_free`.

2. **C++ API:**
   - Клас `horn::HornSolver` дотримується принципу RAII (Resource Acquisition Is Initialization).
   - При виході об'єкта зі сфери видимості деструктор автоматично вивільняє весь задіяний обсяг оперативної пам'яті.
   - Завдяки `std::unique_ptr<Impl>` клас не транслює внутрішні заголовочні файли структури у зовнішні модулі (Pimpl Idiom).

## Гарантії обчислювальної складності та пам'яті

Розв'язувач забезпечує суворі асимптотичні верхні межі:

- **Часова складність:**
  - `horn_solver_create / HornSolver()`: `O(V)`
  - `add_rule / add_constraint`: `O(k)`, де `k` — кількість літералів у тілі диз'юнкта.
  - `solve()`: `O(V + N)`, де `V` — кількість змінних, `N = ∑ kᵢ` — загальна кількість літералів у всіх умовах диз'юнктів.
- **Просторова складність:**
  - Обсяг пам'яті у байтах: `S(V, N) = c₁ · V + c₂ · N + c₃ · C`, де `C` — кількість диз'юнктів.
  - Для `V = 10⁶` змінних та `N = 5 · 10⁶` літералів загальний обсяг пам'яті становить близько 45 МБ, що дозволяє виконувати розв'язання в оперативній пам'яті мікроконтролерів та мобільних пристроїв.

### Потокобезпечність (Thread Safety)

- **Різні екземпляри:** Різні об'єкти `HornSolver` у різних потоках є повністю незалежними і можуть конструюватися, заповнюватися та розв'язуватися паралельно без блокувань (Thread-safe).
- **Один екземпляр:** Одночасне додавання диз'юнктів з кількох потоків в один об'єкт без зовнішньої синхронізації є незахищеним (Data Race). Рекомендується будувати формулу в одному потоці, після чого викликати `solve()` і читати модель `model()` з багатьох потоків паралельно.
