# 📋 Специфікація програмного інтерфейсу FGH Engine

Цей довідник містить повну специфікацію програмованого інтерфейсу (API) та типів даних C/C++ бібліотеки `fgh_engine` для побудови синтаксичних дерев ординалів у канонічній формі Кантора, обчислення фундаментальних послідовностей та керування виконанням швидкозростаючої ієрархії.

Програмна бібліотека призначена для символьного аналізу, рекурсивного розгортання та покрокового спрощення ординальних виразів у діапазоні від нульового ординала до межі арифметики Пеано `ε₀`. Вона надає розробникам двошаровий програмний інтерфейс: низькорівневий C API з функціональним стилем і ручним керуванням пам'яттю та високорівневий об'єктно-орієнтований C++ wrapper, який забезпечує строгу безпеку ресурсів і типізації за сучасними стандартами.

Головним завданням специфікації є визначення єдиного стандарту обміну даними між внутрішнім символьним редуктором та зовнішніми модулями аналізу складності. Це дозволяє легко інтегрувати двигун у наявні системи автоматизованої верифікації коду, компілятори та середовища формальних доведень.

## Архітектурний огляд та принципи володіння пам'яттю

Під час розробки програмованого інтерфейсу для обчислення швидкозростаючих функцій ключовим питанням є дисципліна володіння пам'яттю (англ. *memory ownership contract*). Оскільки символьна редукція ординалів створює сотні тисяч тимчасових піддерев для кожного обчислювального кроку, найменша недбалість у керуванні динамічною пам'яттю спричиняє масовані витоки або передчасне звільнення ресурсів (англ. *use-after-free*).

У низькорівневому C API діє суворе правило: будь-яка функція, яка повертає новий вказівник на `OrdinalNode`, передає повну відповідальність за його звільнення викликаючій стороні. Викликаючий код зобов'язаний явно викликати `ord_free()` для кожного отриманого результату. Для запобігання пошкодженню початкових даних функції редукції ніколи не модифікують передане синтаксичне дерево in-place, а будують повністю новий вузол.

У високорівневому C++ API володіння ресурсами повністю автоматизовано за допомогою шаблону `std::unique_ptr<OrdinalNode>`. Конструктори класу `fgh::Ordinal` повертають семантичні розумні вказівники, що унеможливлює витоки пам'яті навіть при виникненні виняткових ситуацій або при достроковому перериванні рекурсії за часовими лімітами.

## Публічні структури даних та типи C API

Основою низькорівневого програмованого інтерфейсу C є три фундаментальні структури даних: перелічувальний тип `OrdinalKind`, структура синтаксичного вузла `OrdinalNode` та структура збору метрик виконання `EvaluationStats`. Кожна з цих структур виконує чітко відведену роль у процесі побудови, валідації та обчислення синтаксичного дерева ординальних чисел.

### `OrdinalKind` (Тип вузла ординала)
Перелічувальний тип визначення категорії вузла в синтаксичному дереві Кантора:

| Значення | Символьна назва | Математичний зміст | Опис |
| :--- | :--- | :--- | :--- |
| `0` | `ORD_ZERO` | `0` | Нульовий ординал (нейтральний елемент додавання). |
| `1` | `ORD_FINITE` | `k ∈ ℕ` | Скінченне натуральне число `k > 0`. |
| `2` | `ORD_TERM` | `ω^exp · c + tail` | Канонічний трансфінітний доданок форми Кантора. |

Тип `OrdinalKind` визначає активну ветку union-подібної інтерпретації вузла. Для вузла `ORD_ZERO` всі інші поля структури ігноруються. Для `ORD_FINITE` активним є лише числове поле `finite_val`. Для `ORD_TERM` використовуються вказівники `exponent`, `coeff` та `tail`.

### `OrdinalNode` (Структура вузла AST)
Поля абстрактного синтаксичного дерева, що моделює ординали Кантора у пам'яті комп'ютера:

:::tabs
@tab C
```c
typedef struct OrdinalNode {
    OrdinalKind kind;           /* Категорія вузла (ZERO / FINITE / TERM) */
    uint64_t finite_val;        /* Числове значення (для ORD_FINITE) */
    struct OrdinalNode* exponent;/* Вказівник на показник степеня (для ORD_TERM) */
    uint64_t coeff;             /* Множник натурального коефіцієнта (c >= 1) */
    struct OrdinalNode* tail;    /* Праве піддерево-хвіст суми Кантора */
} OrdinalNode;
```

@tab C++
```cpp
struct OrdinalNode {
    OrdinalKind kind{OrdinalKind::Zero};
    uint64_t finite_val{0};
    std::unique_ptr<OrdinalNode> exponent{nullptr};
    uint64_t coeff{0};
    std::unique_ptr<OrdinalNode> tail{nullptr};
};
```
:::

Вказівник `exponent` посилається на інший вузол `OrdinalNode`, що дозволяє формувати рекурсивні вежі степеней омеги довільної висоти. Поле `tail` моделює суму доданків форми Кантора з меншими показниками степеня. Кожне виділення вузла вимагає обов'язкової санітизації нульових вказівників.

Структура вирівняна по межі 8 байт (64 біти) для забезпечення максимальної швидкодії на сучасних процесорних архітектурах x86-64 та ARM64. Розмір структури у пам'яті становить 40 байт.

### `EvaluationStats` (Метрики виконання та телеметрія)
Структура моніторингу процесів обчислення та контролю обчислювальних ресурсів:

| Поле | Тип | Опис |
| :--- | :--- | :--- |
| `total_steps` | `uint64_t` | Загальна кількість рекурсивних підстановок і кроків редукції. |
| `max_depth` | `uint64_t` | Пикова глибина обчислювального стека рекурсії. |
| `current_depth` | `uint64_t` | Поточний рівень рекурсивного занурення. |
| `limit_exceeded` | `bool` | Прапорець переривання за перевищенням стелі кроків (`max_steps`). |

Завдяки структурі `EvaluationStats` викликаюча програма отримує точний зріз обчислювальної складності редукції ординала, що дозволяє досліджувати ресурсоємність алгоритмів без ризику неконтрольованого аварійного завершення чи переповнення системного стека.

## Детальна специфікація функцій C API

Публічний C-інтерфейс бібліотеки розділено на три чіткі групи: функціональні конструктори вузлів, деструктори та процедури алгоритмічного аналізу і редукції.

### 1. Функція `ord_create_zero`
- **Сигнатура:** `OrdinalNode* ord_create_zero(void);`
- **Призначення:** Виділяє пам'ять та повертає новий вузол `ORD_ZERO`.
- **Повертане значення:** Вказівник на створений вузол або `NULL` при виснаженні системної пам'яті.
- **Складність:** `O(1)` за часом та пам'яттю.

### 2. Функція `ord_create_finite`
- **Сигнатура:** `OrdinalNode* ord_create_finite(uint64_t val);`
- **Призначення:** Створює вузол скінченного ординала. Якщо передано `val == 0`, функція автоматично перенаправляє виклик на `ord_create_zero()`, гарантуючи канонічність подання.
- **Параметри:** `val` — натуральне число (`val ∈ ℕ`).

### 3. Функція `ord_create_term`
- **Сигнатура:** `OrdinalNode* ord_create_term(OrdinalNode* exp, uint64_t coeff, OrdinalNode* tail);`
- **Призначення:** Конструює трансфінітний доданок Кантора `ω^exp · coeff + tail`.
- **Параметри:**
  - `exp` — вказівник на синтаксичне дерево показника степеня.
  - `coeff` — натуральний коефіцієнт (`coeff ≥ 1`).
  - `tail` — вказівник на решту суми або `NULL` (якщо хвоста немає).
- **Зауваження:** Передані вказівники `exp` та `tail` стають складовими частинами нового дерева і будуть звільнені разом із ним при виклику `ord_free()`.

### 4. Функція `ord_free`
- **Сигнатура:** `void ord_free(OrdinalNode* node);`
- **Призначення:** Рекурсивно обходить синтаксичне дерево та звільняє виділені блоки пам'яті.
- **Беспечність:** Передавання вказівника `NULL` є коректною операцією і не викликає помилок (no-op).

### 5. Функція `ord_is_limit`
- **Сигнатура:** `bool ord_is_limit(const OrdinalNode* node);`
- **Призначення:** Перевіряє, чи є ординал граничним (тобто чи завершується його форма Кантора трансфінітним показником без скінченного доданка).
- **Повертане значення:** `true`, якщо ординал є граничним; `false`, якщо ординал дорівнює 0 або є ординалом-наступником.

### 6. Функція `ord_fundamental_sequence`
- **Сигнатура:** `OrdinalNode* ord_fundamental_sequence(const OrdinalNode* lambda, uint64_t n);`
- **Призначення:** Обчислює `n`-й елемент фундаментальної послідовності `λ[n]` для граничного ординала `λ`.
- **Алгоритм:** Застосовує канонічні правила Вайнера — Швіхтенберга залежно від структури показника степеня.
- **Повертане значення:** Нове синтаксичне дерево ординала `λ[n]`.

### 7. Функція `fgh_eval`
- **Сигнатура:** `uint64_t fgh_eval(OrdinalNode* alpha, uint64_t n, EvaluationStats* stats, uint64_t max_steps);`
- **Призначення:** Виконує обчислення значення функції швидкозростаючої ієрархії `F_α(n)`.
- **Параметри:**
  - `alpha` — вказівник на ординальний індекс `α`.
  - `n` — вхідний аргумент функції.
  - `stats` — вказівник на структуру для збору метричних даних.
  - `max_steps` — захисна стеля максимальної кількості кроків редукції.
- **Опис роботи:** Функція інкрементує лічильники стека, перевіряє ліміти, виконує символьну редукцію та рекурсивний обчислювальний цикл.

## Високорівневий інтерфейс C++ Wrapper (`fgh::Engine`)

У мові C++ реалізовано високорівневе об'єктне обгортання навколо C API. Усі динамічні вказівники автоматично інкапсульовано у розумні вказівники `std::unique_ptr<OrdinalNode>`, а логіка побудови та редукції винесена у класи `fgh::Ordinal` та `fgh::Evaluator`.

Обгортка забезпечує незмінність початкового ординала завдяки нативному методу `clone()`, який виконує глибоке копіювання синтаксичного дерева перед кожною підстановкою фундаментальної послідовності. Це гарантує повну побічну безпеку при багаторазових обчисленнях.

```cpp
namespace fgh {

class Ordinal {
public:
    static OrdinalPtr make_zero();
    static OrdinalPtr make_finite(uint64_t val);
    static OrdinalPtr make_term(OrdinalPtr exp, uint64_t coeff, OrdinalPtr tail = nullptr);

    OrdinalPtr clone() const;
    bool is_limit() const;
    OrdinalPtr fundamental_sequence(uint64_t n) const;
};

class Evaluator {
public:
    explicit Evaluator(uint64_t max_steps = 1000000);
    
    uint64_t eval(const OrdinalNode* alpha, uint64_t n, EvalStats& stats);
};

} // namespace fgh
```

## Таблиця помилок, режимів та кодів повернення

Під час проведения символьних підстановок обчислювальний двигун аналізує коректність синтаксичного дерева та дотримання безпечних лімітів обчислювальних ресурсів.

| Код / Стан | Опис | Дія двигуна |
| :--- | :--- | :--- |
| `FGH_SUCCESS` | Успішне обчислення `F_α(n)` в межах стелі кроків. | Повертає обчислене значення `uint64_t`. |
| `FGH_ERR_STEP_LIMIT` | Досягнуто ліміт `total_steps > max_steps`. | Встановлює `stats.limit_exceeded = true`, повертає поточний акумулятор. |
| `FGH_ERR_NULL_NODE` | Передано вказівник `NULL`. | Трактується як `ORD_ZERO` (F₀(n) = n + 1). |
| `FGH_ERR_INVALID_CNF` | Некоректний порядок показників у формі Кантора. | Поведінка некоректна, рекомендується санітизація. |

## Багатопоточність та зауваження щодо реінтеграбельності

Обчислювальний двигун `fgh_engine` є повністю реінтерабельним (англ. *reentrant*) та потокобезпечним за умов дотримання наступних вимог:
1. Різні потоки виконання не повинні одночасно модифікувати одні й ті самі екземпляри синтаксичних дерев без зовнішньої синхронізації (м'ютексів).
2. Структура `EvaluationStats` повинна передаватися окремо для кожного потоку (наприклад, через локальні змінні стека або `thread_local` ресурси).
3. Виклики конструкторів та процедур редукції є чисто обчислювальними і не використовують глобального чи статичного стану, що робить C API легко інтегровним у паралельні обчислювальні системи.

Використання даної специфікації гарантує повну програмну сумісність при розробці аналізаторів складності систем переписування термів, дослідженні недовідних логічних тверджень та інтеграції з автоматичними доводжувачами теорем.
