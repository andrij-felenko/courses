# Модель-чекер для структур Кріпке на C++17

У цьому проєкті ми розробимо простий, але практичний скрипт модель-чекера на мові C++17. Він моделює класичну 5-компонентну структуру Кріпке M = (S, S0, R, AP, L) та дозволяє перевіряти істинність базових логічних формул у станах системи. Це чудовий спосіб побачити, як абстрактні математичні концепти перетворюються на реальний алгоритмічний код, з яким працюють розробники.

### Компоненти структури Кріпке у коді

Згадаймо п'ять елементів, з яких формально складається структура:
1. S — множина станів (у коді це просто ідентифікатори або числові індекси).
2. S0 — початкові стани системи (підмножина множини S).
3. R — відношення переходу (орієнтовані ребра між станами, що описують динаміку).
4. AP — атомарні висловлювання (факти, які нас цікавлять).
5. L — функція розмітки, яка кожному стану ставить у відповідність набір істинних у ньому висловлювань.

Для реалізації ми використаємо стандартні контейнери бібліотеки C++: `std::set` для множин, `std::map` для відображень (функцій) та `std::string` для представлення атомарних висловлювань.

### Як це працює алгоритмічно?

Ми визначили клас `KripkeStructure`, який повністю інкапсулює п'ять елементів формальної моделі. 
1. Змінні-члени класу `S`, `S0`, `R`, `AP`, `L` точно відповідають математичному визначенню M = (S, S0, R, AP, L). Ми використовуємо множини (`std::set`), оскільки математично це дійсно неврегульовані набори унікальних елементів. Функція розмітки реалізована через словник (`std::map`), що відображає ідентифікатор стану на підмножину істинних у ньому висловлювань.
2. Метод `isTrueInState` безпосередньо моделює відношення задоволеності (знак ⊨). Виклик `model.isTrueInState(s, p)` є програмним еквівалентом математичного запису s ⊨ p.
3. Метод `isReachableFromInitial` демонструє базовий алгоритм перевірки моделі (model checking). Він використовує пошук у ширину (BFS) від початкових станів S0, щоб з'ясувати, чи система взагалі здатна колись досягти стану, де істинне висловлювання `p`. Це спрощений аналог перевірки формули темпоральної логіки «колись у майбутньому відбудеться p».

Цей скрипт доводить, що структури Кріпке — це не абстрактні фікції, а цілком конкретні графи переходів, якими комп'ютер може алгоритмічно подорожувати та аналізувати набір їхніх властивостей. Ви можете легко розширити цей скелет, додавши перевірку більш складних булевих операцій (заперечення, імплікації) або повноцінний алгоритм для перевірки формул логіки дерев обчислень чи лінійної темпоральної логіки. 

Наприклад, для обробки формул із запереченням достатньо додати метод, який перевіряє відсутність `p` у множині розмітки для заданого стану. Якщо вам потрібно перевірити, чи система завжди (в усіх досяжних станах) задовольняє певну умову безпеки, алгоритм обходу графа можна модифікувати так, щоб він повідомляв про помилку, щойно знайде стан, де умова безпеки порушується. Такий підхід лежить в основі роботи промислових верифікаторів, що застосовуються для тестування мікропроцесорів та критичного програмного забезпечення, наприклад, систем керування польотами літаків. Користуючись цією моделлю, інженери можуть гарантувати відсутність мертвих блокувань у багатонитковому коді, просто створивши відповідний граф станів потоків.
