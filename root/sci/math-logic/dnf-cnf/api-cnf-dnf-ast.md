# 📋 Внутрішнє представлення ДНФ та КНФ у логічних рушіях

Цей документ визначає програмні інтерфейси, структури даних, специфікації формату даних та макети пам'яті для ефективного представлення диз'юнктивних (ДНФ) та кон'юнктивних (КНФ) нормальних форм у сучасних логічних рушіях, промислових SAT-розв'язувачах (MiniSAT, Z3, CaDiCaL), системах автоматичного синтезу цифрових мікросхем (EDA/Yosys, Berkeley ABC) та бібліотеках бінарних діаграм рішень (BDD/CUDD).

## 1. Знакова цілочисельна кодифікація літералів

Для досягнення максимальної швидкості обробки та мінімізації витоків пам'яті промислові інструменти відмовляються від строкових імен змінних (`"x1"`, `"var_A"`) на користь знакового цілочисельного кодування (Signed Integer Encoding).

### 1.1. Стандартне кодування DIMACS / MiniSAT

Кожній оригінальній логічній змінній присвоюється унікальний додатний цілочисельний індекс `v ∈ {1, 2, ..., N}`.
- **Позитивний літерал `xᵥ`** кодується додатним цілим числом `+v`.
- **Негативний літерал `¬xᵥ`** кодується від'ємним цілим числом `-v`.
- **Число `0`** використовується виключно як термінатор (маркер кінця диз'юнкта у масивах) і не може бути індексом змінної.

```
Змінні:         A = 1, B = 2, C = 3
Диз'юнкт (A ∨ ¬B ∨ C)   -->  [ 1, -2, 3 ]
Кон'юнкт (¬A ∧ B ∧ ¬C)  -->  [ -1, 2, -3 ]
```

### 1.2. Бітове кодування MiniSAT / Z3 (Zero-indexed Packed Literals)

У високопродуктивних C++ SAT-розв'язувачах змінні нумеруються з нуля `v ∈ {0, 1, ..., N-1}`, а літерал упаковується в один беззнаковий 32-бітовий інтеджер `Lit`:

```
Lit = (v << 1) | sign
```

де `sign = 0` для позитивного літерала `xᵥ` та `sign = 1` для негативного літерала `¬xᵥ`.

**Математичні оптимізації Packed Literals:**
- Заперечення літерала: `Lit_neg = Lit ^ 1` (одна інструкція XOR).
- Отримання індексу змінної: `Var = Lit >> 1` (одна інструкція зсуву).
- Перевірка знака: `IsNegative = Lit & 1` (одна інструкція AND).

Завдяки цьому бітовому упаковуванню масив спостережуваних літералів (Watched Literals) у SAT-солвері обробляється за допомогою прямих індексацій векторів переходів без жодних розгалужень у коді CPU.

## 2. Специфікація текстового формату DIMACS CNF

Формат DIMACS CNF є стандартом de facto для обміну даними між кодерами Цейтіна, трансляторами логічних схем та SAT-розв'язувачами.

### 2.1. Грамматика та структура документа

Файл складається з трьох послідовних блоків:
1. **Секція коментарів (починається з `c`):** Зберігає метаінформацію, таблицю відповідності символьних імен змінних їхнім індексам (Symbol Table).
2. **Рядок заголовка (Problem Line `p cnf <VARS> <CLAUSES>`):** Оголошує кількість змінних та диз'юнктів для попереднього виділення векторів у пам'яті.
3. **Секція диз'юнктів:** Текстовий перелік літералів, розділених пробілами, де кожен диз'юнкт завершується `0`.

```
c =====================================================================
c Символьна таблиця: 1=A, 2=B, 3=C
c Згенеровано для формули: (A ∨ ¬B) ∧ (¬A ∨ C)
c =====================================================================
p cnf 3 2
1 -2 0
-1 3 0
```

### 2.2. Інваріанти парсера DIMACS CNF

Промисловий парсер зобов'язаний контролювати наступні крайові умови:
- Індекс будь-якого літерала `|l|` не повинен перевищувати оголошене значення `<VARS>`.
- Диз'юнкт з єдиним літералом (`1 0`) є одиничним диз'юнктом (Unit Clause) і змушує солвер зафіксувати присвоєння змінної до початку пошуку.
- Порожній диз'юнкт (два нулі поспіль `0 0`) означає вхідну суперечливість формули (UNSAT).

## 3. Макети пам'яті для КНФ та ДНФ (Clause Vector vs Flat Array)

Представлення формули у пам'яті розробляють з урахуванням локальності даних у кеш-пам'яті L1/L2 процесора (Cache Locality).

### 3.1. Двовимірний вектор (Vector of Vectors / `std::vector<std::vector<Lit>>`)

Найпростіший структурний макет, де формула є списком диз'юнктів, а кожен диз'юнкт — динамічним масивом літералів.

```cpp
using Lit = int32_t;
using Clause = std::vector<Lit>;
using CNFFormula = std::vector<Clause>;
```

*Переваги:* Проста динамічна модифікація (додавання нових диз'юнктів під час навчання CDCL-солвера, вилучення скорочених диз'юнктів).
*Недоліки:* Фрагментація пам'яті (каскад `malloc`), промахи кешу (Cache Misses) через розкиданість диз'юнктів за довільними адресами оперативної пам'яті.

### 3.2. Плоский безперервний масив (Flat Zero-Terminated Array)

Усі диз'юнкти формули зберігаються в єдиному суцільному блоці пам'яті `std::vector<Lit>`, розділені термінаторами `0`.

```
Формула КНФ: (1 ∨ -2) ∧ (-1 ∨ 3 ∨ 4) ∧ (2 ∨ -4)
Масив пам'яті: [ 1, -2, 0, -1, 3, 4, 0, 2, -4, 0 ]
```

Для швидкого доступу використовується додатковий вектор зсувів (Clause Offsets): `Offsets = [0, 3, 7]`.

*Переваги:*
- Абсолютна кеш-локальність: при послідовному перегляді диз'юнктів процесор вибірково завантажує кеш-лінії цілими блоками.
- Мінімальні витрати пам'яті: оверхед становить лише 4 байти на диз'юнкт (розділювач `0`).

## 4. Внутрішня база даних диз'юнктів та схема двох спостережуваних літералів (Two-Watched Literals)

У сучасних CDCL SAT-розв'язувачах перевірка виконання КНФ під час підстановки нових значень здійснюється за допомогою алгоритму **Two-Watched Literals (2WL)**.

### 4.1. Контракт схеми Two-Watched Literals

Замість перегляду всіх літералів у кожному диз'юнкті при кожній зміні змінної, у кожному диз'юнкті обираються два вказівники на спостережувані літерали `watch1` та `watch2`.

**Інваріант 2WL:**
1. Доки хоча б один із двох спостережуваних літералів дорівнює `1` або є незасвоєним (Unassigned), диз'юнкт гарантовано не може стати суперечливим.
2. Сканування диз'юнкта відбувається **виключно тоді**, коли один із двох спостережуваних літералів приймає значення `0`.
3. Якщо під час сканування знайдено новий незасвоєний літерал, вказівник переміщується на нього. Якщо нового літерала немає, а другий спостережуваний літерал незасвоєний — виводиться одинична імплікація (Unit Propagation). Якщо ж обидва спостережувані літерали дорівнюють `0` — зафіксовано конфлікт (Conflict).

Схема 2WL дозволяє здійснювати мільйони кроків дедукції за секунду, оскільки понад 90% диз'юнктів взагалі не потребують звернення до пам'яті при зміні значень змінних.

### 4.2. Метрика LBD (Literal Block Distance) та збір сміття

Під час роботи CDCL-солвер ґенерує сотні тисяч нових навчених диз'юнктів (Learned Clauses). Для запобігання переповненню пам'яті використовують метрику LBD (Gilles Audemard, Laurent Simon, 2009):
- **LBD диз'юнкта:** Кількість різних рівнів прийняття рішень (Decision Levels), з яких утворені літерали даного диз'юнкта.
- Диз'юнкти з `LBD = 2` називаються бінарними блоками (Glue Clauses) — вони є надзвичайно цінними і **ніколи не вилучаються** з бази даних.
- Диз'юнкти з високим `LBD > 12` періодично видаляються під час фази збору сміття (Garbage Collection).

## 5. Внутрішнє представлення у формі синтаксичних дерев AST

Для синтаксичного конвертера та символьних обчислень використовується N-арне абстрактне синтаксичне дерево (Flattened AST).

```cpp
#include <vector>
#include <string>

enum class ASTOp { Var, Not, And, Or };

struct ASTNode {
    ASTOp op;
    int var_id{0}; // Заповнюється, якщо op == Var
    std::vector<ASTNode> children; // Для And/Or містить n аргументів
};
```

### Інваріанти структури AST:
1. **Інваріант NNF (Negation Normal Form):** Оператор `Not` може міститися виключно на рівні безпосередніх батьків вузлів `Var`.
2. **Інваріант сплющення (Flattening Invariant):** Вузол `And` не може мати дочірнім вузлом інший вузол `And`; аналогічно `Or` не може бути дитиною `Or`. Усі однорідні оператори об'єднуються в єдиний список `children`.
3. **Інваріант ДНФ / КНФ:**
   - Для **ДНФ**: Кореневий вузол має тип `Or`, усі його діти — тип `And`, усі діти вузлів `And` — унарні літерали (`Var` або `Not(Var)`).
   - Для **КНФ**: Кореневий вузол має тип `And`, усі його діти — тип `Or`, усі діти вузлів `Or` — унарні літерали (`Var` або `Not(Var)`).

## 6. Специфікація апаратного інтерфейсу PLA / Berkeley PLA Format

Для представлення ДНФ у системах логічного синтезу мікросхем (EDA, Berkeley SIS, ABC) використовується матричний стандарт PLA (Programmable Logic Array). ДНФ записується у вигляді кубічного покриття (Cubic Cover Structure):

```
.i 3           # Кількість вхідних змінних (A, B, C)
.o 1           # Кількість виходів
.ilb A B C     # Імена вхідних сигналів
.ob F          # Назва вихідного сигналу
.p 3           # Кількість термів (кон'юнктів) у ДНФ
11- 1          # (A ∧ B)
0-1 1          # (¬A ∧ C)
1-0 1          # (A ∧ ¬C)
.e
```

**Семантика кубічного кодування:**
- Символ `1`: Змінна входить до кон'юнкта без заперечення.
- Символ `0`: Змінна входить до кон'юнкта з запереченням.
- Символ `-`: Змінна відсутня у даному кон'юнкті (Don't Care position).

Матриця PLA прямо відображається на програмовані логічні матриці апаратного забезпечення, де кожен рядок програмує один транзисторний ланцюг АБО-матриці.

## 7. Бітсетові макети для малої кількості змінних (`n ≤ 64`) та SIMD-паралелізм

Для швидкодіючих логічних симуляторів та GPU-обчислень при `n ≤ 64` кожна булева формула зберігається у вигляді 64-бітового інтеджера `uint64_t` (Truth Table Bitset).

```cpp
#include <cstdint>

// Таблиця істинності функції 3 змінних (2^3 = 8 біт)
using TruthTable8 = uint8_t;

// Операція AND двох формул - одна інструкція CPU:
TruthTable8 f_and(TruthTable8 f1, TruthTable8 f2) {
    return f1 & f2;
}

// Операція OR двох формул:
TruthTable8 f_or(TruthTable8 f1, TruthTable8 f2) {
    return f1 | f2;
}

// Операція NOT:
TruthTable8 f_not(TruthTable8 f1) {
    return ~f1;
}
```

При використанні вектора інструкцій AVX-512 (512-бітові регістри ZMM) один SIMD-вектор здатний одночасно зберігати та обробляти таблиці істинності для формул від 9 змінних (`2⁹ = 512` біт). Це забезпечує оцінку виконуваності тисяч ДНФ/КНФ термів за один векторний такт процесора.
