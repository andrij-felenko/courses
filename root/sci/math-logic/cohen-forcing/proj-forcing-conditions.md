# ⚙️ Симуляція побудови генерного фільтра: Алгоритмічний підхід

Коли ми вивчаємо метод форсингу в абстрактній теорії множин, він оперує нескінченними (часто незліченними) множинами у межах моделі теорії множин, розширюючи нескінченні простори новими елементами. Проте сама механіка форсингу — умови, частковий порядок, сумісність, щільні множини та генерні фільтри — має глибоко алгоритмічну природу. Ці концепції можна змоделювати програмою, якщо ми обмежимо наш всесвіт до скінченної симуляції і зведемо нескінченні щільні множини до ітеративного процесу.

## Постановка проблеми та алгоритмічна ідея

Наше завдання: алгоритмічно змоделювати процес, який у теорії множин Коена використовується для додавання нового «дійсного числа» (яке моделюється як нескінченна послідовність бітів) до існуючої моделі. Ми повинні побудувати так званий «генерний фільтр», який поступово збирає інформацію з безлічі окремих несуперечливих наближень (умов форсингу), щоб урешті-решт утворити повноцінний новий об'єкт. 

Алгоритмічно це виглядає як процес ітеративного уточнення. Ми починаємо з «порожньої» умови, яка не несе ніякої інформації. Потім ми послідовно зустрічаємо різні «вимоги» (щільні множини). На кожному кроці ми маємо підібрати таку нову умову, яка одночасно не суперечить усім попереднім рішенням (є сумісною) і при цьому задовольняє нову поточну вимогу. Цей процес гарантує, що кінцевий результат не матиме суперечностей і враховуватиме всі задані обмеження. 

## Архітектура симулятора (5-компонентна структура)

Програма на C++17 базується на п'яти компонентах, які прямо відображають математичні концепції форсингу:

1. **Структура `Condition`**: Окрема умова форсингу. Представляє часткову функцію (у нашій симуляції — відображення від індексу до конкретного біта).
2. **Перевірка розширення (`extends`)**: Метод, який перевіряє, чи є одна умова суворішою (містить більше інформації) за іншу.
3. **Механізм сумісності (`get_compatible_extension`)**: Алгоритм перевірки сумісності двох умов. Він визначає, чи можливо об'єднати дві умови без конфліктів (наприклад, коли обидві умови фіксують один і той самий біт, але різними значеннями).
4. **Репрезентація щільної множини (`DenseSet`)**: Замість зберігання нескінченних множин, ми моделюємо щільну множину як функціональний об'єкт (лямбду). Вона приймає будь-яку поточну умову і повертає її найближче розширення, яке належить цій щільній множині.
5. **Алгоритм Леми Ресівої-Сікорського (`build_generic_filter`)**: Головний цикл, який приймає набір щільних множин і будує генерний фільтр, ітеративно шукаючи сумісні розширення.

## Код симулятора

```cpp
#include <iostream>
#include <vector>
#include <map>
#include <optional>
#include <algorithm>
#include <functional>
#include <string>

// 1. Умова форсингу (часткова функція від індексу до біта).
// У пам'яті це std::map. Менша кількість записів означає "слабшу" умову.
// Більше записів = більше інформації (сильніша умова).
struct Condition {
    std::map<int, int> fixed_bits;

    // Уточнення: поточна умова <= other (поточна сильніша за other).
    // Поточна умова повинна містити ВСІ пари з other.
    bool extends(const Condition& other) const {
        for (const auto& [index, bit] : other.fixed_bits) {
            auto it = fixed_bits.find(index);
            if (it == fixed_bits.end() || it->second != bit) {
                return false;
            }
        }
        return true;
    }
    
    // Друк для відладки та візуалізації
    void print() const {
        std::cout << "{";
        for (const auto& [i, b] : fixed_bits) {
            std::cout << i << ":" << b << " ";
        }
        std::cout << "} ";
    }
};

// 2 & 3. Перевірка сумісності двох умов.
// Якщо вони фіксують різні значення для одного й того ж біта, вони несумісні (p ⊥ q).
// Якщо сумісні, повертає їхнє об'єднання — найслабшу умову, яка сильніша за обидві.
std::optional<Condition> get_compatible_extension(const Condition& p, const Condition& q) {
    Condition r = p;
    for (const auto& [index, bit] : q.fixed_bits) {
        auto it = r.fixed_bits.find(index);
        // Якщо індекс вже зафіксований і його значення відрізняється — конфлікт!
        if (it != r.fixed_bits.end() && it->second != bit) {
            return std::nullopt; // Несумісні
        }
        // Інакше додаємо нову інформацію до результату
        r.fixed_bits[index] = bit;
    }
    return r;
}

// 4. Щільна множина. 
// У реальному форсингу щільна множина нескінченна, тут моделюємо її як генератор.
// За визначенням, D є щільною, якщо для будь-якого p існує q в D, таке що q <= p.
struct DenseSet {
    std::string name;
    // Функція, що повертає розширення умови p, яке гарантовано належить цій щільній множині
    std::function<Condition(const Condition&)> get_extension_in_dense_set;
};

// 5. Алгоритм пошуку генерного фільтра.
// Фільтр має перетнутися з усіма заданими щільними множинами з D_list.
// Це прямий аналог побудови фільтра за лемою Ресівої-Сікорського для зліченного набору.
std::vector<Condition> build_generic_filter(
        const std::vector<DenseSet>& D_list, 
        Condition starting_condition = {}) 
{
    std::vector<Condition> filter;
    Condition current = starting_condition;
    filter.push_back(current);

    std::cout << "Starting filter generation...\n";

    // Ітеруємося по всіх вимогах (щільних множинах)
    for (const auto& D : D_list) {
        std::cout << "Meeting dense set: " << D.name << " -> ";
        
        // Знаходимо умову, яка сильніша за поточну і одночасно задовольняє D
        Condition next_cond = D.get_extension_in_dense_set(current);
        next_cond.print();
        std::cout << "\n";
        
        filter.push_back(next_cond);
        current = next_cond; // Наступний крок почнеться з цієї посиленої умови
    }

    return filter;
}

int main() {
    // Визначимо кілька щільних множин.
    // Наприклад: множина умов D_i = { p | p фіксує значення біта i }.
    // Очевидно, що ця множина є щільною: для будь-якої поточної умови, 
    // якщо біт 'i' ще не зафіксований, ми можемо розширити умову, додавши фіксацію цього біта.
    std::vector<DenseSet> dense_sets;
    for (int i = 0; i < 5; ++i) {
        dense_sets.push_back({
            "Bit " + std::to_string(i) + " is determined",
            [i](const Condition& p) -> Condition {
                Condition q = p;
                // Якщо біт ще не визначений, ми приймаємо рішення: фіксуємо його в 1
                // У справжньому форсингу це рішення залежить від конкретного генерного фільтра.
                if (q.fixed_bits.find(i) == q.fixed_bits.end()) {
                    q.fixed_bits[i] = 1; 
                }
                return q;
            }
        });
    }

    // Будуємо генерний фільтр починаючи з порожньої умови (ніякої інформації).
    Condition empty_condition;
    std::vector<Condition> G = build_generic_filter(dense_sets, empty_condition);

    std::cout << "\nFinal Filter (Union forms the new object): ";
    // Оскільки кожна наступна умова розширює попередню, остання умова у списку 
    // містить об'єднання всієї накопиченої інформації.
    G.back().print(); 
    std::cout << "\n";

    return 0;
}
```

## Покроковий розбір алгоритму та складність

Головний цикл симулятора обробляє список з `N` щільних множин. 
На кожному кроці ми викликаємо генератор розширення `get_extension_in_dense_set`, який бере поточну конфігурацію (вже зафіксовані біти у `std::map`) і додає до неї нові вимоги. Оскільки ми використовуємо `std::map`, операція пошуку та вставки має алгоритмічну складність O(log K), де K — це поточна кількість зафіксованих бітів. 

Для обробки `N` вимог, на кожній з яких ми можемо перевіряти або додавати до M нових бітів, загальна складність часу виконання становить приблизно O(N · M · log K). Витрати пам'яті є лінійними O(K), де K — загальна кількість фіксацій. Ця відносно низька обчислювальна складність дозволяє ефективно моделювати навіть великі процеси форсингу, замінюючи абстрактні нескінченні структури на їх генеративні аналоги.

Коли генерний фільтр `G` зустрічає всі щільні множини, що вимагають визначення біта `i` (для всіх заданих `i`), ми можемо розглядати об'єднання усіх умов у фільтрі. У світі теорії множин, саме це об'єднання нескінченного фільтра утворює тотальну функцію, яка й стає тим новим дійсним числом, якого не існувало в базовій моделі. У нашому скінченному симуляторі об'єднанням виступає остання умова у згенерованому масиві, адже вона акумулювала в собі всі попередні розширення. Це чудово ілюструє, як із фрагментарної часткової інформації виникає повноцінний, несуперечливий математичний об'єкт.
