# ⚙️ Практичне обчислення нерухомих точок: інтервальний аналізатор програм

Статичний аналіз коду дає змогу виявити помилки виходу за межі масивів, ділення на нуль, розіменування нульових вказівників та переповнення цілих чисел ще до запуску програми. Оскільки точний аналіз довільного вихідного коду неможливий через алгоритмічну нерозв'язність проблеми зупинки (теорема Райса та проблема Тюринга), промислові компілятори й верифікатори застосовують **абстрактну інтерпретацію** (Abstract Interpretation) Патріка та Радії Кузо.

Замість того, щоб намагатися виконати програму на всіх нескінченних комбінаціях вхідних даних, абстрактна інтерпретація відображає виконання коду в математичну структуру — **повну ґратку абстрактних станів**. Будь-який цикл або рекурсивна функція породжує систему монотонних рівнянь над цією ґраткою. Відповідно до теореми Тарського — Кнастера, найбільш точний, надійний і безпечний інваріант програми є **найменшою нерухомою точкою** монотонного абстрактного трансформатора `lfp(F#)`.

Нижче детально розібрано математичні засади абстрактного домену інтервалів, зв'язок Галуа, роботу алгоритму робочого списку (Worklist) на графі потоку керування, оператори розширення (widening) та звуження (narrowing), а також наведено повну реалізацію аналізатора мовами C та C++.

## Математичний міст: зв'язок Галуа між бетоном і абстракцією

Щоб статичний аналізатор гарантовано не пропускав помилок (властивість надійності, soundness), зв'язок між реальними значеннями у пам'яті комп'ютера та абстрактними інтервалами формалізується через **зв'язок Галуа** (Galois Connection).

Нехай `S` — множина всіх можливих конкретних станів пам'яті (наприклад, конкретні цілі числа, які змінна `x` приймає під час виконання). Конкретною областю аналізу є булеан `(P(S), ⊆)` — множина всіх підмножин станів, впорядкована за теоретико-множинним включенням `⊆`.

Абстрактною областю є повна ґратка інтервалів `(L_int, ⊑)`, де кожен елемент представляє діапазон можливих значень.

Між цими двома просторами діють два монотонні відображення:
1. **Функція абстракції `α: P(S) → L_int`**: перетворює довільну множину конкретних чисел на найменший інтервал, що її покриває:
```
α(∅) = ⊥
α({ -3, 2, 10 }) = [-3, 10]
```
2. **Функція конкретизації `γ: L_int → P(S)`**: перетворює абстрактний інтервал назад у множину конкретних значень:
```
γ(⊥) = ∅
γ([-3, 10]) = { n ∈ ℤ | -3 ≤ n ≤ 10 }
γ([-∞, +∞]) = ℤ
```

Пара функцій `(α, γ)` утворює зв'язок Галуа, якщо для будь-якої конкретної множини `C ⊆ ℤ` та будь-якого абстрактного інтервалу `A ∈ L_int` виконується фундаментальна еквівалентність:
```
α(C) ⊑ A  ⇔  C ⊆ γ(A)
```

Звідси випливає головна гарантія безпеки статичного аналізу: якщо конкретний оператор програми позначається через `F: P(S) → P(S)`, а його абстрактний двійник — через `F#: L_int → L_int`, то умова коректності вимагає:
```
∀ A ∈ L_int:  F(γ(A)) ⊆ γ(F#(A))
```
Якщо ця умова виконується, то згідно з теоремою Тарського — Кнастера найменша нерухома точка абстрактного трансформатора `lfp(F#)` гарантовано покриває всі реальні стани програми:
```
lfp(F) ⊆ γ(lfp(F#))
```
Це означає: якщо аналізатор довів, що на виході з циклу інтервал для індексу масиву `i` дорівнює `[0, 99]`, то під час реального виконання індекс ні за яких обставин не вийде за межі масиву розміром 100.

## Багатовимірний простір: ґратка станів середовища

У реальних програмах одночасно існує багато змінних `Var = { x_1, x_2, ..., x_k }`. Стан пам'яті моделюється функціональною ґраткою відображень (оточенням змінних):
```
Env = Var → L_int
```
Ця функціональна ґратка успадковує всі властивості повної ґратки:
- Порядок визначається поточково: `E_1 ⊑ E_2  ⇔  ∀ v ∈ Var: E_1(v) ⊑ E_2(v)`.
- Точна верхня грань обчислюється для кожної змінної окремо: `(E_1 ⊔ E_2)(v) = E_1(v) ⊔ E_2(v)`.
- Точна нижня грань: `(E_1 ⊓ E_2)(v) = E_1(v) ⊓ E_2(v)`.
- Найменший елемент середовища: `⊥_{Env}(v) = ⊥` для всіх `v ∈ Var`.

За теоремою Тарського — Кнастера добуток повних ґраток є повною ґраткою, а монотонні трансформатори над окремими змінними зберігають загальну монотонність усієї системи.

## Структура повної ґратки інтервалів

Побудуємо повну ґратку інтервалів `(L_int, ⊑, ⊔, ⊓, ⊥, ⊤)` для цілих чисел `ℤ`:
- **Елементи ґратки**: закриті відрізки `[l, u]`, де ліва межа `l ∈ ℤ ∪ {-∞}`, права межа `u ∈ ℤ ∪ {+∞}`, і `l ≤ u`. Крім того, додається особливий елемент `⊥` (ботом), який позначає порожню множину станів (недосяжний фрагмент програми).
- **Найбільший елемент (топ, `⊤`)**: інтервал `[-∞, +∞]`, що відповідає цілковитій відсутності інформації (змінна може мати будь-яке значення).
- **Найменший елемент (ботом, `⊥`)**: позначає відсутність будь-яких значень (код перед цією точкою або завершується аварійно, або зависає, або умова переходу туди ніколи не справджується).

Алгебраїчні операції ґратки визначаються таким чином:

### 1. Частковий порядок (інформаційне включення `⊑`)
Інтервал `[a, b]` вважається меншим за інтервал `[c, d]` у сенсі інформаційного порядку (позначається `[a, b] ⊑ [c, d]`), якщо `[a, b]` надає точнішу інформацію (містить менше значень):
```
[a, b] ⊑ [c, d]  ⇔  c ≤ a  та  b ≤ d
⊥ ⊑ X            [ботом є найточнішим станом]
X ⊑ ⊤            [топ є найменш точним станом]
```

### 2. Точна верхня грань (Join, `⊔`)
Операція `⊔` використовується в точках злиття потоків керування — наприклад, після блоку `if-else` або на вході в цикл, куди керування приходить або з ініціалізації, або з кінця попередньої ітерації:
```
[a, b] ⊔ [c, d] = [min(a, c), max(b, d)]
⊥ ⊔ X = X
X ⊔ ⊥ = X
```

### 3. Точна нижня грань (Meet, `⊓`)
Операція `⊓` використовується для фільтрації та уточнення знань після перевірки умов у розгалуженнях:
```
[a, b] ⊓ [c, d] = [max(a, c), min(b, d)]    (якщо max(a, c) ≤ min(b, d), інакше ⊥)
⊥ ⊓ X = ⊥
X ⊓ ⊥ = ⊥
```

## Інтервальна арифметика абстрактних трансформаторів

Щоб змоделювати виконання коду в абстрактному домені, необхідно визначити, як базові арифметичні та логічні операції діють на інтервалах.

Нехай задано два непустих інтервали `X = [a, b]` та `Y = [c, d]`:
- **Додавання:**
```
[a, b] + [c, d] = [a + c, b + d]
```
- **Віднімання:**
```
[a, b] - [c, d] = [a - d, b - c]
```
- **Множення:**
```
[a, b] · [c, d] = [min(ac, ad, bc, bd), max(ac, ad, bc, bd)]
```
- **Ділення на інтервал `[c, d]`:**
  Якщо інтервал знаменника містить нуль (`0 ∈ [c, d]`), аналізатор фіксує попередження про потенційне ділення на нуль (Division by Zero Warning). Якщо нуль вилучено або знаменник звужено, межі обчислюються через ділення крайніх точок з округленням до безпечного боку.
- **Умова фільтрації `x < k`:**
  Якщо перед розгалуженням змінна `x` мала інтервал `[l, u]`, то в гілці `true` (де умова виконується) новим інтервалом буде:
```
X_{true} = [l, u] ⊓ [-∞, k - 1]
```
  А в гілці `false` (де умова не виконується, тобто `x ≥ k`):
```
X_{false} = [l, u] ⊓ [k, +∞]
```

Усі перелічені трансформатори є монотонними функціями: якщо звузити вхідні інтервали, вихідний інтервал також або звузиться, або залишиться незмінним. Завдяки цьому композиція довільної кількості операцій утворює глобальний монотонний оператор програми `F#`.

## Граф потоку керування та алгоритм черги завдань (Worklist Algorithm)

У реальному компіляторі програма представляється у вигляді графа потоку керування (Control Flow Graph, CFG). Вузлами графа є базові блоки інструкцій, а ребрами — переходи між ними.

Для кожної точки програми `v` (входу або виходу з блоку) вводиться абстрактний стан `State[v]`. Виконання програми породжує систему ґраткових рівнянь:
```
State[v] = ⨆_{(u, v) ∈ InEdges} Transfer_{(u, v)}(State[u])
```
Для розв'язання цієї системи рівнянь застосовують алгоритм черги завдань (Worklist Algorithm):
1. **Ініціалізація:** Для початкової точки програми `Entry` встановлюється початковий стан (наприклад, аргументи функцій або глобальні змінні зі значенням `⊤` чи `[0, 0]`). Для всіх інших точок графа `v ≠ Entry` встановлюється `State[v] = ⊥`.
2. **Заповнення черги:** Усі ребра або блоки додаються до робочої черги `W`.
3. **Ітеративний цикл:** Поки черга `W` не порожня:
   - Вилучаємо блок `u` з черги.
   - Обчислюємо новий стан на виході: `NewState = Transfer_u(State[u])`.
   - Для кожного наступника `v` обчислюємо оновлений стан через операцію `⊔` (або `∇`, якщо `v` є заголовком циклу).
   - Якщо стан `State[v]` змінився, додаємо блок `v` назад у чергу `W`.
4. **Завершення:** Коли черга порожніє, система станів `State` досягає нерухомої точки.

Теорема Тарського — Кнастера гарантує, що якщо трансформатори монотонні, а ґратка станів задовольняє умову стабілізації, алгоритм черги завдань завжди знаходить найменшу нерухову точку системи.

## Проблема нескінченної висоти та оператор розширення (Widening)

Незважаючи на те, що ґратка `L_int` є повною, вона має **нескінченну висоту**: у ній існують нескінченні строго зростаючі ланцюги. Наприклад:
```
[0, 0] ⊏ [0, 1] ⊏ [0, 2] ⊏ [0, 3] ⊏ ... ⊏ [0, +∞]
```

Якщо ми спробуємо знайти нерухову точку для циклу:
```text
int x = 0;
while (x < 1000000) {
    x = x + 1;
}
```
за допомогою класичної ітерації Кліні `X_{n+1} = F#(X_n)`, аналізатор робитиме один мільйон кроків, послідовно обчислюючи `[0, 0]`, `[0, 1]`, `[0, 2]`, ..., поки не дійде до `[0, 1000000]`. Якщо ж межа циклу невідома на етапі компіляції (наприклад, читається з файлу або сокета), ітерація Кліні взагалі ніколи не завершиться.

Щоб подолати нескінченні ланцюги та гарантувати швидку збіжність аналізу за фіксовану кількість кроків, Патрік і Радія Кузо ввели **оператор розширення** (Widening, позначається символом `∇`).

Оператор розширення `∇: L_int × L_int → L_int` повинен задовольняти дві фундаментальні властивості:
1. **Мажорування (Upper Bound):** Для будь-яких двох інтервалів `X` та `Y` результат розширення містить обидва аргументи:
```
(X ⊔ Y) ⊑ (X ∇ Y)
```
2. **Гарантія скінченної стабілізації:** Для будь-якої нескінченної послідовності інтервалів послідовність, побудована за правилом `W_0 = X_0`, `W_{n+1} = W_n ∇ X_{n+1}`, стабілізується за скінченну кількість кроків (перестає строго зростати).

Для ґратки інтервалів оператор розширення визначається через відкидання нестабільних меж до нескінченності:
```
[a, b] ∇ [c, d] = [ if c < a then -∞ else a,
                    if d > b then +∞ else b ]
⊥ ∇ Y = Y
X ∇ ⊥ = X
```

### Як працює розширення на практиці

Поглянемо, як розширення обчислює інваріант для циклу `while (x < 100) { x = x + 1; }`:
- **Крок 0:** До початку аналізу циклу значення на вході: `X_0 = ⊥`.
- **Крок 1:** Початковий стан перед циклом `init = [0, 0]`.
  Об'єднуємо з нульовим наближенням: `X_1 = X_0 ∇ (init ⊔ F#(⊥)) = [0, 0]`.
- **Крок 2:** У тілі циклу `x` проходить умову `x < 100` і збільшується на 1: `[0, 0] + 1 = [1, 1]`.
  Злиття з початковим станом: `[0, 0] ⊔ [1, 1] = [0, 1]`.
  Застосовуємо розширення між старим станом `[0, 0]` та новим `[0, 1]`:
  Права межа зросла з 0 до 1 (`1 > 0`), отже оператор `∇` миттєво замінює її на `+∞`!
```
[0, 0] ∇ [0, 1] = [0, +∞]
```
- **Крок 3:** Підставляємо новий стан `[0, +∞]` у тіло циклу:
  Умова `x < 100` відсікає праву частину: `[0, +∞] ⊓ [-∞, 99] = [0, 99]`.
  Додаємо 1: `[0, 99] + 1 = [1, 100]`.
  Злиття: `[0, 0] ⊔ [1, 100] = [0, 100]`.
  Застосовуємо розширення: `[0, +∞] ∇ [0, 100] = [0, +∞]`.
  Стан стабілізувався! Знайдено постфіксну точку: `F#([0, +∞]) ⊑ [0, +∞]`.

Аналіз завершився всього за 3 ітерації замість 100! Проте отриманий інваріант `[0, +∞]` є надто грубим: він не дає змоги довести, що на виході з циклу `x == 100`.

## Оператор звуження (Narrowing) для відновлення точності

Щоб повернути втрачену під час розширення точність, застосовують **оператор звуження** (Narrowing, позначається символом `Δ`).

Якщо розширення рухається вгору по ґратці й знаходить безпечну постфіксну точку, то звуження запускає **спадну ітерацію**, яка спускається від постфіксної точки вниз до точної нерухомої точки:
```
N_0 = X_{стабілізоване}
N_{k+1} = N_k Δ F#(N_k)
```

Для ґратки інтервалів оператор звуження замінює нескінченні межі на точні кінцеві значення, якщо вони стабілізувалися:
```
[a, b] Δ [c, d] = [ if a == -∞ then c else a,
                    if b == +∞ then d else b ]
```

У нашому прикладі:
- Поточний стан: `N_0 = [0, +∞]`.
- Обчислюємо дію трансформатора: `F#([0, +∞]) = [0, 100]`.
- Застосовуємо звуження:
```
[0, +∞] Δ [0, 100] = [0, 100]
```
- Наступний крок: `F#([0, 100]) = [0, 100]`.
- Застосовуємо звуження: `[0, 100] Δ [0, 100] = [0, 100]`.

Звуження стабілізувалося за 2 кроки! Ми отримали максимально точну нерухому точку `[0, 100]`. Тепер на виході з циклу (де умова `x < 100` хибна, тобто `x ≥ 100`):
```
Exit = [0, 100] ⊓ [100, +∞] = [100, 100]
```
Аналізатор строго довів: після завершення циклу змінна `x` гарантовано має точне значення 100.

## Програмна реалізація інтервального аналізатора

Нижче наведено робочий код аналізатора мовами C та C++. Реалізації містять повну структуру інтервального домену з підтримкою нескінченностей, об'єднання (Join), перетину (Meet), розширення (Widening), звуження (Narrowing) та ітераційного розв'язувача нерухомої точки.

:::tabs
```c
#include <stdio.h>
#include <stdbool.h>
#include <limits.h>

/* Позначення нескінченностей через безпечні константи */
#define INF_POS  (LONG_MAX / 2)
#define INF_NEG  (LONG_MIN / 2)

/* Структура інтервалу в ґратці L_int */
typedef struct {
    long min;
    long max;
    bool is_bottom;
} Interval;

/* Створення найменшого елемента ґратки (ботом) */
static inline Interval interval_bottom(void) {
    Interval iv = {0, 0, true};
    return iv;
}

/* Створення інтервалу з перевіркою коректності меж */
static inline Interval interval_create(long min, long max) {
    if (min > max) return interval_bottom();
    Interval iv = {min, max, false};
    return iv;
}

/* Порівняння двох інтервалів на точну рівність */
static inline bool interval_equals(Interval a, Interval b) {
    if (a.is_bottom && b.is_bottom) return true;
    if (a.is_bottom || b.is_bottom) return false;
    return a.min == b.min && a.max == b.max;
}

/* Операція точної верхньої грані (Join, ⊔) */
static inline Interval interval_join(Interval a, Interval b) {
    if (a.is_bottom) return b;
    if (b.is_bottom) return a;
    long min = (a.min < b.min) ? a.min : b.min;
    long max = (a.max > b.max) ? a.max : b.max;
    return interval_create(min, max);
}

/* Операція точної нижньої грані (Meet, ⊓) */
static inline Interval interval_meet(Interval a, Interval b) {
    if (a.is_bottom || b.is_bottom) return interval_bottom();
    long min = (a.min > b.min) ? a.min : b.min;
    long max = (a.max < b.max) ? a.max : b.max;
    return interval_create(min, max);
}

/* Абстрактний трансформатор додавання константи */
static inline Interval interval_add_const(Interval a, long val) {
    if (a.is_bottom) return interval_bottom();
    long min = (a.min <= INF_NEG) ? INF_NEG : a.min + val;
    long max = (a.max >= INF_POS) ? INF_POS : a.max + val;
    return interval_create(min, max);
}

/* Оператор розширення (Widening, ∇) для швидкої збіжності */
static inline Interval interval_widen(Interval prev, Interval next) {
    if (prev.is_bottom) return next;
    if (next.is_bottom) return prev;
    long min = (next.min < prev.min) ? INF_NEG : prev.min;
    long max = (next.max > prev.max) ? INF_POS : prev.max;
    return interval_create(min, max);
}

/* Оператор звуження (Narrowing, Δ) для відновлення точності */
static inline Interval interval_narrow(Interval prev, Interval next) {
    if (prev.is_bottom || next.is_bottom) return interval_bottom();
    long min = (prev.min <= INF_NEG) ? next.min : prev.min;
    long max = (prev.max >= INF_POS) ? next.max : prev.max;
    return interval_create(min, max);
}

/* Друк інтервалу в консоль */
static void print_interval(const char *label, Interval iv) {
    printf("%-22s: ", label);
    if (iv.is_bottom) {
        printf("⊥ (недосяжний стан)\n");
    } else {
        printf("[");
        if (iv.min <= INF_NEG) printf("-∞"); else printf("%ld", iv.min);
        printf(", ");
        if (iv.max >= INF_POS) printf("+∞"); else printf("%ld", iv.max);
        printf("]\n");
    }
}

int main(void) {
    /* Моделюємо аналіз програми:
       int x = 0;
       while (x < 100) {
           x = x + 1;
       }
    */
    Interval init_state = interval_create(0, 0);
    Interval loop_head = interval_bottom();
    Interval guard = interval_create(INF_NEG, 99);

    /* Етап 1: Пошук постфіксної точки з розширенням (Widening) */
    printf("=== Етап 1: Ітерація розширення (Widening) ===\n");
    for (int iter = 1; iter <= 10; ++iter) {
        Interval in_loop = interval_meet(loop_head, guard);
        Interval step = interval_add_const(in_loop, 1);
        Interval combined = interval_join(init_state, step);
        Interval next_head = interval_widen(loop_head, combined);

        printf("Ітерація %d: ", iter);
        print_interval("loop_head", next_head);

        if (interval_equals(loop_head, next_head)) {
            printf("Постфіксну точку стабілізовано на кроці %d.\n\n", iter);
            break;
        }
        loop_head = next_head;
    }

    /* Етап 2: Уточнення значень оператором звуження (Narrowing) */
    printf("=== Етап 2: Ітерація звуження (Narrowing) ===\n");
    for (int iter = 1; iter <= 5; ++iter) {
        Interval in_loop = interval_meet(loop_head, guard);
        Interval step = interval_add_const(in_loop, 1);
        Interval combined = interval_join(init_state, step);
        Interval next_head = interval_narrow(loop_head, combined);

        printf("Ітерація %d: ", iter);
        print_interval("loop_head", next_head);

        if (interval_equals(loop_head, next_head)) {
            printf("Найменшу нерухому точку знайдено на кроці %d.\n\n", iter);
            break;
        }
        loop_head = next_head;
    }

    /* Фінальні інваріанти за теоремою Тарського — Кнастера */
    Interval body_inv = interval_meet(loop_head, guard);
    Interval exit_guard = interval_create(100, INF_POS);
    Interval exit_inv = interval_meet(loop_head, exit_guard);

    printf("=== Результати аналізу програми ===\n");
    print_interval("Інваріант на вході в цикл", loop_head);
    print_interval("Інваріант у тілі циклу", body_inv);
    print_interval("Інваріант на виході з циклу", exit_inv);

    return 0;
}
```

```cpp
class Interval {
public:
    static constexpr long kInfPos = std::numeric_limits<long>::max() / 2;
    static constexpr long kInfNeg = std::numeric_limits<long>::min() / 2;

    constexpr Interval() : is_bottom_(true), min_(0), max_(0) {}
    constexpr Interval(long min, long max) 
        : is_bottom_(min > max), min_(min), max_(max) {}

    static constexpr Interval Bottom() noexcept { return Interval(); }
    static constexpr Interval Top() noexcept { return Interval(kInfNeg, kInfPos); }

    [[nodiscard]] constexpr bool IsBottom() const noexcept { return is_bottom_; }
    [[nodiscard]] constexpr long Min() const noexcept { return min_; }
    [[nodiscard]] constexpr long Max() const noexcept { return max_; }

    constexpr bool operator==(const Interval& other) const noexcept {
        if (is_bottom_ && other.is_bottom_) return true;
        if (is_bottom_ || other.is_bottom_) return false;
        return min_ == other.min_ && max_ == other.max_;
    }

    constexpr bool operator!=(const Interval& other) const noexcept {
        return !(*this == other);
    }

    // Операція часткового порядку (включення знань)
    [[nodiscard]] constexpr bool Leq(const Interval& other) const noexcept {
        if (is_bottom_) return true;
        if (other.is_bottom_) return false;
        return other.min_ <= min_ && max_ <= other.max_;
    }

    // Операція точної верхньої грані (Join, ⊔)
    [[nodiscard]] Interval Join(const Interval& other) const noexcept {
        if (is_bottom_) return other;
        if (other.is_bottom_) return *this;
        return Interval(std::min(min_, other.min_), std::max(max_, other.max_));
    }

    // Операція точної нижньої грані (Meet, ⊓)
    [[nodiscard]] Interval Meet(const Interval& other) const noexcept {
        if (is_bottom_ || other.is_bottom_) return Bottom();
        long new_min = std::max(min_, other.min_);
        long new_max = std::min(max_, other.max_);
        return (new_min <= new_max) ? Interval(new_min, new_max) : Bottom();
    }

    // Абстрактний трансформатор додавання константи
    [[nodiscard]] Interval AddConst(long val) const noexcept {
        if (is_bottom_) return Bottom();
        long new_min = (min_ <= kInfNeg) ? kInfNeg : min_ + val;
        long new_max = (max_ >= kInfPos) ? kInfPos : max_ + val;
        return Interval(new_min, new_max);
    }

    // Оператор розширення (Widening, ∇)
    [[nodiscard]] Interval Widen(const Interval& next) const noexcept {
        if (is_bottom_) return next;
        if (next.is_bottom_) return *this;
        long new_min = (next.min_ < min_) ? kInfNeg : min_;
        long new_max = (next.max_ > max_) ? kInfPos : max_;
        return Interval(new_min, new_max);
    }

    // Оператор звуження (Narrowing, Δ)
    [[nodiscard]] Interval Narrow(const Interval& next) const noexcept {
        if (is_bottom_ || next.is_bottom_) return Bottom();
        long new_min = (min_ <= kInfNeg) ? next.min_ : min_;
        long new_max = (max_ >= kInfPos) ? next.max_ : max_;
        return Interval(new_min, new_max);
    }

    [[nodiscard]] std::string ToString() const {
        if (is_bottom_) return "⊥ (недосяжний стан)";
        std::string res = "[";
        res += (min_ <= kInfNeg) ? "-∞" : std::to_string(min_);
        res += ", ";
        res += (max_ >= kInfPos) ? "+∞" : std::to_string(max_);
        res += "]";
        return res;
    }

private:
    bool is_bottom_;
    long min_;
    long max_;
};
```

## Реляційні та нереляційні домени у промислових аналізаторах

Інтервальний домен є **нереляційним** (non-relational): він відстежує діапазон кожної змінної окремо, втрачаючи взаємозв'язки між різними змінними.

Розглянемо приклад коду:
```text
int y = x;
if (x < y) {
    // Цей блок недосяжний, оскільки x == y
    a[10] = 0;
}
```
Якщо для змінних `x` та `y` відомо лише, що `x ∈ [0, 100]` та `y ∈ [0, 100]`, нереляційний аналізатор інтервалів обчислить перетин `[0, 100] ⊓ [0, 100] = [0, 100]` і не зможе довести, що умова `x < y` нездійсненна. У результаті аналізатор видасть хибне попередження (false positive).

Щоб зберегти залежності між змінними, у компіляторах та системах верифікації використовують складніші реляційні ґратки:

1. **Ґратка різниць (Difference-Bound Matrices, DBM):**
   Відстежує нерівності вигляду `x - y ≤ c`. Дає змогу аналізувати зсуви покажчиків і таймери в системах реального часу.
2. **Ґратка октагонів (Octagon Domain):**
   Відстежує інваріанти вигляду `±x ± y ≤ c`. Дозволяє ефективно виявляти помилки в циклах із кількома індексами при поліноміальній складності `O(n³)`.
3. **Ґратка опуклих багатогранників (Polyhedra Domain):**
   Зберігає довільні лінійні нерівності вигляду `a_1 x_1 + a_2 x_2 + ... + a_n x_n ≤ c`. Забезпечує максимальну точність, але має експоненційну складність.

Незалежно від складності геометричної форми абстрактного домену (інтервал, октагон чи опуклий багатогранник), алгоритмічна основа залишається незмінною: побудова монотонного трансформатора та обчислення його нерухомої точки за теоремою Тарського — Кнастера.

## Практичне застосування у промисловості: Astrée, Infer та LLVM

Найвідомішим практичним тріумфом абстрактної інтерпретації на основі нерухомих точок є статичний аналізатор **Astrée** (Automated Static Analyzer for Embedded Software). Розроблений командою Патріка Кузо у Вищій нормальній школі Парижа (ENS), Astrée використовувався для повної автоматичної верифікації вбудованого програмного забезпечення управління польотом пасажирських літаків Airbus A340 та Airbus A380 (Fly-by-Wire control software).

Кодова база бортового комп'ютера Airbus містить сотні тисяч рядків коду на мові C з нескінченними циклами керування в реальному часі. Звичайне тестування не могло гарантувати відсутність рідкісних помилок переповнення. Аналізатор Astrée, обчисливши найменшу нерухову точку системи ґраткових рівнянь над комбінацією інтервального, октагонального та поліедрального доменів, математично довів повну відсутність помилок часу виконання (Zero Runtime Errors: жодного ділення на нуль, жодного виходу за межі масивів, жодного переповнення стека).

У сучасних інструментах розробки подібні алгоритми пошуку нерухомої точки працюють щодня:
- **Clang Static Analyzer:** обчислює нерухомі точки над графами розгорнутих шляхів виконання для пошуку витоків пам'яті (Memory Leaks) та використання звільненої пам'яті (Use-After-Free).
- **Infer (Meta):** використовує бі-абдукцію та абстрактну інтерпретацію над ґратками роздільної логіки (Separation Logic) для пошуку гонок даних (Data Races) та взаємних блокувань (Deadlocks) у багатопотокових сервісах на мільйони рядків коду.
- **Оптимізатори LLVM (Scalar Evolution & Value Tracking):** обчислюють консервативні діапазони значень для безпечної векторизації циклів та усунення зайвих перевірок меж масивів.

## Практичні пастки та крайові випадки у розробці аналізаторів

При проектуванні аналізаторів на основі нерухомих точок розробники стикаються з чотирма класичними інженерними пастками:

1. **Порушення монотонності в оптимізаціях:**
   Спроба додати «евристичне скорочення» інтервалу на окремих кроках може порушити монотонність трансформатора `F#`. Якщо монотонність втрачено, теорема Тарського — Кнастера перестає діяти: ітерації можуть потрапити в нескінченне зациклення між двома станами або пропустити реальну помилку виходу за межі пам'яті.
2. **Арифметика переповнення (Integer Overflow):**
   У реальних процесорах додавання чисел з обмеженою розрядністю (наприклад, 32-бітних `int32_t`) є циклічним: `2147483647 + 1 = -2147483648`. Якщо абстрактний трансформатор не моделює переповнення за модулем `2³²`, а використовує звичайну математичну арифметику, аналіз буде ненадійним (unsound). Промислові аналізатори розбивають інтервали при переповненні або насичують межі.
3. **Округлення чисел із рухомою комою (Floating-Point Soundness):**
   Якщо аналізатор використовує тип `double` для зберігання меж дійсних чисел, апаратне округлення IEEE-754 може випадково звузити інтервал (наприклад, `0.1` не має точного представлення у двійковій системі). Щоб гарантувати надійність, нижню межу необхідно завжди округлювати у напрямку `-∞`, а верхню — у напрямку `+∞`.
4. **Вибір порогів розширення (Widening with Thresholds):**
   Замість того, щоб одразу розширювати інтервал до `+∞`, ефективні аналізатори використовують масив статичних порогів (наприклад, константи `0, 1, 10, 100, 1024, MAX_PATH`, що зустрічаються в коді програми). Межа розширюється не до нескінченності, а до найближчої більшої константи з програми, що суттєво підвищує точність аналізу.
