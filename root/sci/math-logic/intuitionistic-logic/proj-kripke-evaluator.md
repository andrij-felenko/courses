# ⚙️ Обчислювач [Семантика Кріпке](topic:math-logic/kripke-semantics)

Цей проєкт демонструє практичну реалізацію оцінювача логічних формул на моделі Кріпке. У класичній логіці перевірка істинності формули виконується за допомогою простих таблиць істинності. В інтуїціоністській логіці ми маємо справу з направленим графом станів знання, що вимагає рекурсивного обходу.

### Постановка задачі

Нам необхідно написати алгоритм, який перевірятиме, чи є складна пропозиційна формула істинною в заданому світі. Світ Кріпке характеризується набором відомих у ньому фактів та списком доступних світів-нащадків, у яких знання розширюються. Відповідно до [Семантика Кріпке](topic:math-logic/kripke-semantics), істина проста (змінні, кон'юнкція та диз'юнкція) перевіряється локально. Складніша істина (імплікація та заперечення) вимагає перевірки всіх можливих майбутніх станів, щоб гарантувати стабільність знань. 

### Архітектурна логіка

Архітектура рішення базується на трьох основних стовпах:

1. **Абстрактне синтаксичне дерево (AST)**: Для репрезентації логічних формул застосовується рекурсивна структура вузлів. Використовуються розумні вказівники `std::shared_ptr` для забезпечення безпечного управління пам'яттю та уникнення витоків.
2. **Модель світів**: Вузли графу представляють світи Кріпке. Кожен світ містить множину `std::unordered_set` рядків (які символізують доведені атомарні змінні) та вектор вказівників на дочірні світи.
3. **Функція Evaluation**: Рекурсивний обхід AST. Якщо оператор вимагає майбутнього (наприклад, `IMPLIES` або `NOT`), алгоритм запускає додатковий обхід дерева світів у глибину, перевіряючи виконання інтуїціоністських умов.

### Покроковий розбір коду

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <memory>
#include <unordered_set>
#include <map>

// 1. Абстрактне синтаксичне дерево (AST) для формул
enum class Op { VAR, AND, OR, IMPLIES, NOT };

struct Formula {
    Op op;
    std::string name; // Для атомарних змінних
    std::shared_ptr<Formula> left;
    std::shared_ptr<Formula> right;

    static std::shared_ptr<Formula> Var(const std::string& n) {
        return std::make_shared<Formula>(Formula{Op::VAR, n, nullptr, nullptr});
    }
    static std::shared_ptr<Formula> Or(auto l, auto r) {
        return std::make_shared<Formula>(Formula{Op::OR, "", l, r});
    }
    static std::shared_ptr<Formula> Not(auto f) {
        return std::make_shared<Formula>(Formula{Op::NOT, "", f, nullptr});
    }
};

// 2. Світ у моделі Кріпке
struct World {
    std::string id;
    std::unordered_set<std::string> truths;
    std::vector<World*> children; // Майбутні стани (w <= w')
};

// 3. Логіка обчислення (Evaluation)
bool evaluate(World* w, std::shared_ptr<Formula> f) {
    switch (f->op) {
        case Op::VAR:
            // Змінна істинна, якщо вона є у множині відомих фактів цього світу.
            return w->truths.count(f->name) > 0;
            
        case Op::OR:
            // Диз'юнкція обчислюється як класична логічна сума в поточному світі.
            return evaluate(w, f->left) || evaluate(w, f->right);
            
        case Op::NOT:
            // w ⊩ ¬A <=> для всіх w' (w <= w'), w' НЕ ⊩ A
            // Спочатку перевіряємо поточний світ
            if (evaluate(w, f->left)) return false;
            // Потім рекурсивно перевіряємо всі доступні майбутні світи
            for (World* child : w->children) {
                if (!evaluate(child, f)) return false;
            }
            return true;
            
        default:
            return false;
    }
}

// 4. Точка входу та перевірка закону виключеного третього
int main() {
    // Будуємо модель: Root -> (Left, Right)
    World root{"Root", {}};
    World left{"Left", {"p"}};
    World right{"Right", {"q"}};
    root.children = {&left, &right};

    // Перевіряємо закон виключеного третього: p ∨ ¬p
    auto p = Formula::Var("p");
    auto not_p = Formula::Not(p);
    auto lem = Formula::Or(p, not_p);

    std::cout << "У світі Root, (p ∨ ¬p) є: " 
              << (evaluate(&root, lem) ? "Істина" : "Хиба") << "\n";
              
    // Очікуваний результат: Хиба. 
    // root не має p. Але root не має ¬p, бо світ left містить p.
    return 0;
}
```

Алгоритм рекурсивно проходить як структуру самої формули, так і структуру світів. Для логічного оператора "АБО" (`OR`), ми викликаємо функцію оцінки лише для поточного світу. Але для заперечення (`NOT`), яке в інтуїціонізмі має жорстку семантику обіцянки на всі майбутні стани, алгоритм неминуче повинен зазирнути в усі дочірні світи рекурсивно. Це дозволяє моделювати процес накопичення знань.

### Складність вводу/виводу та продуктивність

Обчислювальна складність цього алгоритму суттєво вища за класичні таблиці істинності. 

1. **Просторова складність**: `O(N)`, де N — глибина формули. Це пов'язано з глибиною стека викликів рекурсії при обході AST-дерева. Окрім того, граф світів займає `O(W * F)` простору, де W — кількість світів, а F — середня кількість доведених фактів у світі.
2. **Часова складність**: У найгіршому випадку, коли формула складається виключно з вкладених імплікацій або заперечень (які вимагають перевірки всього піддерева світів), часова складність дорівнює `O(W^D)`, де W — кількість світів, а D — глибина формули. Кожне розкриття імплікації запускає цикл по нащадках, і якщо всередині імплікації знову стоїть імплікація, обхід графу світів повторюється. Для практичних застосувань у сучасних системах доведення теорем використовуються значно ефективніші структури (бінарні діаграми рішень та мемоізація результатів), щоб уникнути експоненційного вибуху в часі.
