# ⚙️ Порахувати стелю самому: програма, що відтворює криву межі одного переходу

Замість вірити готовій цифрі «≈33%», відтворимо всю криву ККД(Eg) власноруч — невелика програма на Python інтегрує сонячний спектр, проганяє детальний баланс по кожному можливому порогу Eg і сама знаходить пік, а заразом точки кремнію та GaAs. Тоді кожне число стане перевірним: видно, з якої саме інтеграли воно виросло і яке припущення похитне його.

## Задача: не повірити цифрі, а відтворити криву

На вході в нас лише сонячний спектр і дві температури: гаряче Сонце (візьмімо його чорним тілом ~5800 K) і теплий елемент (300 K). На виході хочемо мати всю залежність — стелю ККД як функцію забороненої зони Eg, з піком десь коло 1.3 еВ, з кремнієм (1.12 еВ) і GaAs (1.42 еВ) на своїх місцях.

Вся фізика зводиться до одного балансу. Ідеальний елемент ловить кожен надпороговий фотон Сонця — це **генерація**. Але той самий елемент, що добре поглинає, за законом Кірхгофа так само добре й **світиться** сам, як усяке [нагріте тіло за своєї температури](root:ph-thermodynamics/planck-law-and-blackbody-spectrum) — і це власне світіння (випромінна рекомбінація) забирає носіїв назад. Різниця двох потоків, зібрана в найкращій робочій точці, і є та потужність, яку елемент віддає в коло. Порахувати цю різницю для кожного Eg — і є вся програма.

Мова — Python: задача суто обчислювальна (два інтеграли спектра плюс одномірний максимум), тут цінна прозорість і виразність запису, а не швидкість гарячого циклу. Уся програма — чиста стандартна бібліотека, жодної залежності; її можна запустити будь-де й побачити ті самі числа.

## Ідея: дві суми й один максимум

Для одного порога Eg робота вкладається в п'ять кроків.

```
1. N_gen  = скільки фотонів Сонця мають E ≥ Eg   (лічимо, не важимо енергію)
2. N_emit = скільки фотонів елемент випромінює сам за 300 K з E ≥ Eg
3. Jsc = q·N_gen ,  J0 = q·N_emit ,  Voc = (kT/q)·ln(Jsc/J0 + 1)
4. пробіг по V:  J(V) = Jsc − J0·(exp(qV/kT) − 1) ,  беремо max( J·V )
5. η(Eg) = Pmax / Pin
```

Крок 1 — це інтеграл планківського потоку від Eg до нескінченності. Крок 2 — той самий інтеграл, але вже для холодного елемента: скільки він світить сам. Уся інша механіка — шкільна алгебра діода. Обгорнувши це в цикл по всіх Eg, дістанемо криву; її максимум — і є межа.

Два зауваження, без яких числа поповзуть. По-перше, струм лічить **кількість** фотонів, а не їхню енергію — тому в кроці 1 інтегруємо потік фотонів, а не потужність. По-друге, Сонце на небі — це не півсфера, а маленький яскравий диск: його планківський потік доводиться «розводити» на тілесний кут цього диска, інакше на вході отримаємо потужність поверхні самого Сонця, а не земне одне сонце.

## Робочий код

```python
# -*- coding: utf-8 -*-
"""Крива межі одного переходу з першопринципів: інтегруємо планківський
потік фотонів, проганяємо детальний баланс по всіх порогах Eg, шукаємо пік.
Чиста стандартна бібліотека — жодних залежностей."""
import math

# ── фізичні сталі (SI) ──────────────────────────────────────────────
h  = 6.62607015e-34    # стала Планка, Дж·с
c  = 2.99792458e8      # швидкість світла, м/с
kB = 1.380649e-23      # стала Больцмана, Дж/К
q  = 1.602176634e-19   # заряд електрона, Кл

T_sun  = 5800.0        # температура фотосфери Сонця, К
T_cell = 300.0         # температура елемента, К

# Сонце — маленький диск (кутовий радіус 0.2665°), а не ціла півсфера.
# Тілесний кут цього диска «розводить» яскравий планківський потік
# до земного рівня ~одне сонце.
theta     = math.radians(0.2665)
OMEGA_SUN = 2*math.pi*(1 - math.cos(theta))     # ≈ 6.8e-5 ср

# ── планківський потік фотонів ──────────────────────────────────────
def photon_flux(E_eV, T):
    """Спектральна густина потоку фотонів чорного тіла за T:
    фотони за секунду на м², на стерадіан, на еВ."""
    x = E_eV*q / (kB*T)
    if x <= 0.0 or x > 700.0:        # захист від переповнення exp (див. пастки)
        return 0.0
    E = E_eV*q
    return (2.0/(h**3 * c**2)) * E*E / (math.exp(x) - 1.0) * q   # ×q: на еВ, не на Дж

# ── сітка енергій для інтегрування ──────────────────────────────────
DE = 0.002                                        # крок, еВ (див. пастку про збіжність)
EMIN, EMAX = 0.05, 6.0
GRID = [EMIN + DE*i for i in range(int((EMAX-EMIN)/DE) + 1)]

def integrate(f):
    """Сума прямокутників по сітці. Для гладкого планківського спектра
    цього досить: метод трапецій дав би те саме до четвертого знака."""
    return sum(f(E) for E in GRID) * DE

# падна потужність: інтеграл ЕНЕРГІЇ планківського потоку × тілесний кут диска
P_IN = OMEGA_SUN * integrate(lambda E: (E*q) * photon_flux(E, T_sun))

def photons_above(Eg, T):
    """Фотони за секунду на м² на стерадіан з енергією E ≥ Eg."""
    return sum(photon_flux(E, T) for E in GRID if E >= Eg) * DE

# ── детальний баланс для одного порога ──────────────────────────────
def efficiency(Eg):
    N_gen  = OMEGA_SUN * photons_above(Eg, T_sun)   # надпорогові фотони Сонця
    N_emit = math.pi   * photons_above(Eg, T_cell)  # власне світіння у півсферу
    Jsc = q * N_gen                                 # короткий струм
    J0  = q * N_emit                                # темновий струм насичення
    Voc = (kB*T_cell/q) * math.log(Jsc/J0 + 1.0)

    Pmax = Vmp = 0.0                                 # робоча точка макс. потужності
    STEPS = 1000
    for i in range(1, STEPS):
        V = Voc * i/STEPS
        J = Jsc - J0*(math.exp(q*V/(kB*T_cell)) - 1.0)
        if J < 0:                                    # за Voc струм уже від'ємний
            break
        if J*V > Pmax:
            Pmax, Vmp = J*V, V
    return dict(Eg=Eg, Jsc=Jsc, Voc=Voc, Pmax=Pmax,
                eta=Pmax/P_IN, FF=Pmax/(Jsc*Voc))

# ── крива η(Eg), пік і матеріали ────────────────────────────────────
if __name__ == "__main__":
    print("Падна потужність (чорне тіло %.0f K × Ω) = %.0f Вт/м²" % (T_sun, P_IN))

    gaps  = [0.40 + 0.01*i for i in range(261)]      # 0.40 … 3.00 еВ
    curve = [(Eg, efficiency(Eg)['eta']) for Eg in gaps]
    Eg_pk, eta_pk = max(curve, key=lambda p: p[1])
    print("Пік: Eg = %.2f еВ,  η = %.1f%%" % (Eg_pk, eta_pk*100))

    for name, Eg in [("Si", 1.12), ("GaAs", 1.42)]:
        m = efficiency(Eg)
        print("  %-4s Eg=%.2f еВ  η=%.1f%%  Voc=%.3f В  Jsc=%.0f А/м²  FF=%.2f"
              % (name, Eg, m['eta']*100, m['Voc'], m['Jsc'], m['FF']))
```

Запустивши, дістаємо криву й числа, з яких вона зіткана:

```
Падна потужність (чорне тіло 5800 K × Ω) = 1385 Вт/м²
Пік: Eg = 1.27 еВ,  η = 30.6%
  Si   Eg=1.12 еВ  η=30.1%  Voc=0.882 В  Jsc=543 А/м²  FF=0.87
  GaAs Eg=1.42 еВ  η=30.2%  Voc=1.162 В  Jsc=402 А/м²  FF=0.90
```

Пік чорнотільної моделі — 30.6% коло 1.27 еВ, і плато таке пологе, що кремній із GaAs, стоячи по різні його боки, дають майже однакові ~30%. Це рівно те, що 1961 року отримали Шоклі й Квайссер (≈30% при 1.1 еВ, Сонце — чорне тіло 6000 K), і те, з чого зіткана вся крива в теорії межі. Сорок рядків відтворюють результат, на який пішла окрема стаття в *Journal of Applied Physics*.

## Пастки, кожна — в одному рядку

Програма коротка, і кожна її неочевидність сидить в одному рядку. Розберімо чотири, бо кожна легко коштує кілька відсотків або й зовсім абсурдний результат.

### Крок сітки: де ховається півпроцента

Інтеграл ми беремо сумою прямокутників, а її точність цілком у кроці `DE`. Занадто грубий крок систематично **завищує** ККД і зсуває сам пік на клітинку. Ось як число сходиться, коли дрібнити сітку (той самий розрахунок при різних `DE`):

```
DE, еВ    N точок   η(1.34 еВ)   пік
0.050        120      30.64%      1.26 еВ / 30.71%
0.020        298      30.51%      1.26 еВ / 30.61%
0.010        596      30.51%      1.27 еВ / 30.60%
0.005       1191      30.50%      1.27 еВ / 30.59%
0.002       2976      30.49%      1.27 еВ / 30.59%
0.001       5951      30.49%      1.27 еВ / 30.59%
```

Грубий крок 0.05 еВ дає 30.64% замість 30.49% — зайвих 0.15 відсотка нізвідки, і пік «стрибає» між 1.26 та 1.27 еВ просто тому, що вершина потрапляє то в одну клітинку, то в сусідню. Від 0.005 еВ усе вже стабільне до другого знака. Мораль проста: результат чисельного інтегрування не має права залежати від кроку — дрібни його, доки число не перестане мінятися. Хочеш тієї самої точності вдесятеро дешевше — бери [метод трапецій замість прямокутників](root:math-numeric/numerical-integration): для гладкого спектра він збігається набагато швидше.

### Переповнення exp: одна сітка на дві температури

У рядку `photon_flux` стоїть `if x > 700: return 0.0`, і на нашій сітці до 6 еВ він **жодного разу не спрацьовує**. То навіщо він? Бо та сама функція обслуговує дві дуже різні температури. Показник `x = E/kT` для Сонця (5800 K) на краю сітки дорівнює лише ~12, а для елемента (300 K) — аж ~232. Поки `EMAX = 6` еВ, навіть 232 ще по зубах подвійній точності. Але прибери сторожа, розсунь сітку в далекий ультрафіолет «про запас» — і на ~18 еВ показник для холодного елемента перескочить 700, `math.exp` переповниться, і програма впаде:

```
math.exp(709) = 8.2e+307      # ще впритул під стелею double
math.exp(710) → OverflowError: math range error
```

Сторож рятує, але він — латка з магічним числом. Чистий фокус: переписати множник Бозе так, щоб великого показника взагалі не рахувати:

```python
def bose(x):
    # 1/(e^x − 1) без переповнення: для великих x чисельник e^(−x)
    # тихо занулюється до 0.0, а не вибухає в inf
    ex = math.exp(-x)
    return ex / (1.0 - ex)
```

Тепер `bose(710)` спокійно дає 0.0 (там і має бути нуль — фотонів такої енергії за 300 K немає), і жодного `if` та жодної магічної константи не треба. Це загальне правило [чисельної стійкості](root:math-numeric/numeric-stability): не борися з переповненням прапорцями — перепиши вираз так, щоб небезпечна операція не виникала. Той самий дух живе й у `Voc`: відношення `Jsc/J0` тут астрономічне (холодний елемент світить мізерно проти Сонця), але під логарифмом воно поводиться сумирно, тож `math.log(Jsc/J0 + 1)` рахується без сюрпризів.

### Тілесний кут: чому Ω на вході, а π на виході

Найглибший рядок — множники перед двома інтегралами: генерацію множимо на `OMEGA_SUN` (~6.8·10⁻⁵ ср), а власне світіння — на `math.pi`. Ця асиметрія не косметична, вона й є фізика межі. Сонце заливає елемент лише з крихітного тілесного кута свого диска; а світиться назад елемент у цілу півсферу над собою (π — уже з ламбертовим проєктуванням). Плутанина тут карається жорстоко: забудеш `OMEGA_SUN` — і на вході матимеш потужність поверхні самого Сонця (~64 МВт/м² замість ~1.4 кВт/м²), а ККД вийде часткою відсотка; переплутаєш π та Ω місцями — попливе напруга.

> 🔧 **Навіщо це.** Саме це відношення «мало влітає — багато вилітає» і породжує недобір напруги, який годі прибрати. `Voc = (kT/q)·ln(N_gen/N_emit)`: логарифм від'ємний рівно тому, що холодний елемент за 300 K світить незрівнянно тьмяніше, ніж заливає його Сонце за 5800 K, — але не нескінченно тьмяніше. Тобто у двох цих множниках, Ω та π, зашитий той самий термодинамічний податок, що й у ККД Карно між гарячим джерелом і теплим приймачем. Змінити правило гри можна лише фізично: сфокусувати сонце лінзою — і `N_gen` зросте, дріб під логарифмом підскочить, недобір напруги зменшиться. Оптика в цьому рядку — не деталь, а важіль стелі.

### Нормування: одне сонце — це скільки?

ККД — це `Pmax / Pin`, і все залежить від того, яку саме `Pin` ти взяв. Наша чорнотільна модель дає ~1385 Вт/м² — це порядок **сонячної сталої** (1361 Вт/м², рівень над атмосферою, спектр AM0). Але наземний стандарт AM1.5G, за яким рейтингують реальні панелі, нормують на рівно **1000 Вт/м²**: атмосфера з'їдає близько чверті потоку. Головне правило: чисельник і знаменник мають бути в **тому самому** спектрі. Візьмеш струм за одним спектром, а `Pin` — за іншим, і ККД зіпсується на десятки відсотків із порожнього місця.

## Швидше й ідіоматичніше: векторизація

За складністю програма — це `O(N_Eg · N_E)` на інтеграли плюс `O(N_Eg · N_V)` на пробіги напруги; при кількох тисячах точок спектра й кількох сотнях порогів це мільйони операцій — частка секунди, дарма що чистий Python. Але наукову версію пишуть на numpy, і не лише заради швидкості: обернений кумулятивний суматор робить «фотони вище порога» для **всіх** Eg одразу, за один прохід масиву.

```python
import numpy as np

E    = np.arange(0.05, 6.0, 0.002)                       # сітка енергій, еВ
x    = np.clip(E*q/(kB*T_sun), 1e-12, 700.0)             # обрізаємо хвіст — без inf
flux = (2/(h**3*c**2)) * (E*q)**2 / np.expm1(x) * q      # expm1 точний і для малих x

# «фотони з енергією ≥ E[k]» одразу для кожного k — суфіксна сума:
above = np.cumsum(flux[::-1])[::-1] * 0.002              # обернений кумсуматор

# тепер N_gen для будь-якого Eg — це проста вибірка above[k], без інтеграла
```

Тут два ідіоми варті уваги. `np.expm1(x)` рахує `exp(x) − 1` точно навіть коло нуля (звичайне `exp(x)-1` там втрачає значущі цифри — теж [чисельна стійкість](root:math-numeric/numeric-stability)), а `np.clip(..., 700)` знімає проблему переповнення відразу для всього масиву. І `np.cumsum(flux[::-1])[::-1]` — суфіксна сума: за один `O(N)`-прохід дістаємо інтеграл «згори» для кожного порога, після чого вся крива коштує ще `O(N_Eg)` вибірок замість `O(N_Eg · N_E)` повторних інтегралів. Прозорий цикл добрий, щоб зрозуміти, векторний — щоб рахувати серйозно.

## Від чорного тіла до реального спектра

Чорне тіло 5800 K — гладка й зручна модель, та реальне сонце крізь атмосферу має провали: смуги поглинання водяної пари, кисню й CO₂ вигризають зі спектра цілі шматки, надто в інфрачервоному. Щоб дістати канонічну цифру межі, планківську функцію міняють на **виміряний** спектр AM1.5G (його стандартну таблицю роздає NREL, норма ASTM G173). Змінюється лише джерело фотонів — увесь детальний баланс, уся емісія елемента лишаються ті самі:

```python
HC = 1239.84198     # E(еВ) = HC / λ(нм)

def am15_photons_above(Eg, wl, irr):
    """Фотони/с/м² з таблиці AM1.5G (λ у нм, irr у Вт/м²/нм) з E ≥ Eg,
    тобто з λ ≤ HC/Eg. Потужність ділимо на енергію фотона → потік."""
    lam_max, total = HC/Eg, 0.0
    for i in range(len(wl) - 1):
        if wl[i] > lam_max:
            break
        E_J   = (HC/wl[i]) * q          # енергія фотона, Дж
        total += (irr[i] / E_J) * (wl[i+1] - wl[i])
        # ↑ (Вт/м²/нм)/(Дж/фотон) · нм = фотони/с/м²
    return total
```

Одна тонкість нормування: табличний спектр AM1.5G — це вже потужність, що **доходить до землі** на м², тож множити його на тілесний кут Сонця не треба (розведення й розсіяння в атмосфері вже враховано), а `Pin` беремо просто 1000 Вт/м². Емісія ж елемента (`π · photons_above(Eg, 300)`) від спектра освітлення не залежить і лишається чорнотільною. Підставивши цю таблицю, той самий код дає **пік 1.34 еВ і η ≈ 33.7%** — канонічну межу одного переходу.

Чому пік зсунувся з 1.27 на 1.34 еВ? Бо провали атмосфери в інфрачервоному відбирають саме ті довгохвильові фотони, з яких годувався б матеріал із низьким порогом, — і оптимум трохи піднімається. Ось за що варто написати цю програму: 33.7% перестають бути числом із підручника й стають результатом, у якому видно кожну цеглину — сітку інтегрування, тілесний кут, нормування спектра — і кожну можна посмикати, щоб побачити, як стеля дихає.
