# ⚙️ Алгоритми точного й наближеного обчислення гармонічних чисел

У цій вставці наведено практичні алгоритми обчислення `H[n]` різними мовами програмування (C, C++, Python, TypeScript) з урахуванням чисельної стійкості, компенсації похибок накопичення, попарного підсумовування та асимптотичних наближень.

## 1. Чисельна нестабільність прямого підсумовування

Найпростіший спосіб обчислити `H[n]` — це цикл від `k = 1` до `n`, у якому накопичується сума `sum += 1.0 / k`. Проте в реальних чисельних обчисленнях цей прямий підхід приховує серйозну проблему: **втрату точності від поглинання малих доданків** (*catastrophic cancellation / precision loss*).

У форматі з плаваючою крапкою IEEE 754 одиночної точності (`float`, 32 біти) мантиса має 23 біти точності, що відповідає приблизно 7 десятковим цифрам. Коли накопичена сума `H[n]` досягає значення `16.0`, мінімальне число, яке можна додати до неї без втрати молодших бітів, дорівнює `16.0 × 2⁻²³ ≈ 1.9 × 10⁻⁶`. Якщо `k > 524288`, то значення доданка `1/k < 1.9 × 10⁻⁶`, і операція додавання `sum + 1.0/k` у форматі `float` перестає змінювати значення змінної `sum` взагалі. Цикл продовжує виконуватися і витрачати процесорний час, але сума повністю "замерзає" і повертає хибний результат.

У форматі подвійної точності (`double`, 64 біти) мантиса має 52 біти точності (близько 15–17 десяткових цифр). Замерзання відбувається при набагато більших `n`, але накопичення похибок округлення все одно суттєво спотворює останні знаки результату.

Існує чотири основних математичних та інженерних способи розв'язання цієї проблеми:
1. **Зворотне підсумовування:** додавати члени ряду у порядку від меншого до більшого (від `k = n` до `1`). Оскільки малі додатки спочатку додаються між собою, їхня сума поступово зростає і не поглинається одразу великим накопиченим значенням.
2. **Попарне підсумовування (Pairwise Summation):** рекурсивне розділення масиву доданків навпіл за принципом «розділяй і володарюй». Похибка накопичення зростає як `O(sqrt(log n) · ε)` замість `O(n · ε)`.
3. **Алгоритм Кахана (Kahan Summation Algorithm):** ведення додаткової змінної-компенсатора, яка зберігає втрачені при кожному додаванні молодші біти мантиси та повертає їх на наступному кроці.
4. **Асимптотична формула Ейлера — Маклорена:** для великих `n > 1000` виконання обчислення за `O(1)` операцій з гарантованою математичною точністю.

## 2. Покроковий розбір алгоритму Кахана

Алгоритм Кахана виправляє чисельну похибку шляхом зберігання малого залишку у змінній-компенсаторі `c`. На кожній ітерації з поточного додатка віднімається накопичена на попередньому кроці похибка `c`, результат додається до загальної суми, а різниця між фактичним приростом суми та очікуваним приростом зберігається у змінній `c` для компенсації на наступній ітерації.

Математична схема алгоритму Кахана на кожній ітерації `k` описується кроками:

```
y = (1/k) - c           [віднімання накопиченої похибки]
t = sum + y             [додавання до загальної суми]
c = (t - sum) - y       [визначення втрачених молодших бітів]
sum = t                 [оновлення суми]
```

Простежимо роботу цього алгоритму на конкретному чисельному прикладі `n = 4` для 32-бітного float:
- На кроці `k = 1`: `y = 1.0`, `sum = 1.0`, `c = 0.0`.
- На кроці `k = 2`: `y = 0.5`, `sum = 1.5`, `c = 0.0`.
- На кроці `k = 3`: `y = 0.33333334`, `sum = 1.8333334`, `c` зберігає низький біт різниці `0.00000003`.
- На кроці `k = 4`: `y = 0.25 - 0.00000003 = 0.24999997`, що дає точний результат `2.0833333` без втрати бітів.

Завдяки цій алгоритмічній компенсації ефективна точність підсумовування зростає так, ніби ми використовували тип даних із подвоєною довжиною мантиси (наприклад, 128-бітний float).

## 3. Пастки компилятора та векторних прапорців (-ffast-math)

У реальному програмуванні на C та C++ оптимізатори сучасних компіляторів (GCC, Clang, MSVC) можуть несподівано зруйнувати чисельну стійкість алгоритму Кахана при увімкненні прапорців агресивної оптимізації дійсної арифметики, таких як `-ffast-math` або `-Ofast`.

Стандарт IEEE 754 забороняє переасоціацію додавання `(a + b) + c ≠ a + (b + c)`, оскільки чисельні результати відрізняються через округлення. Проте прапорець `-ffast-math` дозволяє компілятору ігнорувати стандарт IEEE 754 і переупорядковувати вирази.

У результаті оптимізатор бачить у коді Кахана послідовність виразів `t = sum + y` та `c = (t - sum) - y` і робить математичне «спрощення»:

```
c = ((sum + y) - sum) - y = y - y = 0
```

Оптимізатор комбінує ці рядки і повністю викидає змінну `c` та обчислення компенсації! Код алгоритму Кахана дегенерує у звичайне пряме підсумовування `sum += 1/k` із тими ж похибками.

Щоб запобігти цьому руйнуванню у промисловому коді, застосовують три інженерних прийоми:
1. **Відключення `-ffast-math` для математичних файлів:** збірка модулів чисельного аналізу з прапорцями `-fno-fast-math` або `-fassociative-math`.
2. **Використання `volatile` або барерів оптимізації:** оголошення змінної `t` як `volatile double t = sum + y;` (запобігає усуненню компенсації компілятором).
3. **Використання асимптотичної формули Ейлера — Маклорена:** для великих `n > 1000` перехід на обчислення за `O(1)` взагалі не залежить від циклічних оптимізацій.

## 4. Паралельне попарне сумування (Parallel Pairwise Reduction)

Для прискорення підсумовування на багатоядерних процесорах (наприклад, у HPC або обробці великих даних) діапазон додавання `[1, n]` розбивають на `P` однакових блоків між потоками виконання `OpenMP` або `std::async`.

Кожен потік обчислює часткову суму свого діапазону `[start, end]` у зворотному порядку (від `end` до `start`), що гарантує високу точність у межах кожного потоку. Після завершення обчислень у потоках отримані часткові суми об'єднуються бінарним деревом редукції (Pairwise Tree Reduction).

Ця паралельна схема забезпечує як пропорційне прискорення у `P` разів по часу, так і суттєве зниження накопиченої похибки округлення, оскільки додавання часткових сум відбувається між числами близького порядку величини.

## 5. Комбінований алгоритм обчислення (Hybrid Evaluator)

На практиці обчислювальні системи та спеціалізовані бібліотеки застосовують гібридний підхід:
- Для малих та середніх `n ≤ 1000`: виконується точне підсумовування алгоритмом Кахана або зворотним циклом за `O(n)` часу.
- Для великих `n > 1000`: застосовується формула Ейлера — Маклорена `H[n] = ln n + γ + 1/(2n) - 1/(12n²) + 1/(120n⁴) - 1/(252n⁶)` за `O(1)` часу.

Розглянемо повну реалізацію цього гібридного оцінювача чотирма мовами програмування з обробкою крайових випадків (`n = 0`, переповнення, винятки).

#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <stdbool.h>

/* Стала Ейлера — Маскероні з точністю до 20 знаків */
#define EULER_MASCHERONI 0.57721566490153286060

typedef struct {
    double value;
    bool is_exact;
    const char* error_message;
} HarmonicResult;

/* Обчислення гармонічного числа алгоритмом Кахана (для n <= 1000) */
static double harmonic_kahan(unsigned long long n) {
    double sum = 0.0;
    double c = 0.0;
    for (unsigned long long k = 1; k <= n; ++k) {
        double y = (1.0 / (double)k) - c;
        double t = sum + y;
        c = (t - sum) - y;
        sum = t;
    }
    return sum;
}

/* Обчислення асимптотичною формулою Ейлера — Маклорена (для n > 1000) */
static double harmonic_asymptotic(unsigned long long n) {
    double nd = (double)n;
    double n2 = nd * nd;
    double n4 = n2 * n2;
    double n6 = n4 * n2;

    return log(nd) + EULER_MASCHERONI 
           + (1.0 / (2.0 * nd)) 
           - (1.0 / (12.0 * n2)) 
           + (1.0 / (120.0 * n4)) 
           - (1.0 / (252.0 * n6));
}

/* Головна гібридна функція API на C */
HarmonicResult compute_harmonic(unsigned long long n) {
    HarmonicResult res;
    res.error_message = NULL;

    if (n == 0) {
        res.value = 0.0;
        res.is_exact = false;
        res.error_message = "Гармонічне число H[0] не визначено (n має бути >= 1)";
        return res;
    }

    if (n <= 1000) {
        res.value = harmonic_kahan(n);
        res.is_exact = true;
    } else {
        res.value = harmonic_asymptotic(n);
        res.is_exact = false;
    }

    return res;
}

int main(void) {
    unsigned long long test_values[] = {1, 5, 10, 1000, 1000000};
    size_t count = sizeof(test_values) / sizeof(test_values[0]);

    for (size_t i = 0; i < count; ++i) {
        HarmonicResult r = compute_harmonic(test_values[i]);
        if (r.error_message) {
            printf("Помилка: %s\n", r.error_message);
        } else {
            printf("H[%llu] = %.15f (%s)\n", 
                   test_values[i], r.value, 
                   r.is_exact ? "точне сумування" : "асимптотика O(1)");
        }
    }
    return 0;
}

namespace math_algo {

constexpr double EULER_MASCHERONI = 0.57721566490153286060;

enum class HarmonicError {
    ZeroArgument,
    Overflow
};

class HarmonicCalculator {
public:
    // Повертає H[n] або помилку через std::expected
    [[nodiscard]] static std::expected<double, HarmonicError> compute(std::uint64_t n) noexcept {
        if (n == 0) {
            return std::unexpected(HarmonicError::ZeroArgument);
        }

        if (n <= 1000) {
            return compute_kahan(n);
        }
        return compute_asymptotic(n);
    }

    // Зворотне сумування для масиву доданків через std::span
    [[nodiscard]] static double sum_backward(std::span<const double> terms) noexcept {
        double total = 0.0;
        for (auto it = terms.rbegin(); it != terms.rend(); ++it) {
            total += *it;
        }
        return total;
    }

private:
    [[nodiscard]] static double compute_kahan(std::uint64_t n) noexcept {
        double sum = 0.0;
        double compensation = 0.0;
        for (std::uint64_t k = 1; k <= n; ++k) {
            const double y = (1.0 / static_cast<double>(k)) - compensation;
            const double t = sum + y;
            compensation = (t - sum) - y;
            sum = t;
        }
        return sum;
    }

    [[nodiscard]] static double compute_asymptotic(std::uint64_t n) noexcept {
        const double nd = static_cast<double>(n);
        const double n2 = nd * nd;
        const double n4 = n2 * n2;
        const double n6 = n4 * n2;

        return std::log(nd) + EULER_MASCHERONI 
               + (1.0 / (2.0 * nd)) 
               - (1.0 / (12.0 * n2)) 
               + (1.0 / (120.0 * n4)) 
               - (1.0 / (252.0 * n6));
    }
};

} // namespace math_algo

int main() {
    const std::vector<std::uint64_t> test_cases = {1, 5, 10, 1000, 1000000};

    }

const EULER_MASCHERONI = 0.57721566490153286060;

export interface HarmonicResult {
    n: number;
    value: number;
    method: 'kahan' | 'asymptotic';
}

export function computeHarmonic(n: number): HarmonicResult {
    if (!Number.isInteger(n) || n < 1) {
        throw new RangeError("Аргумент n повинен бути цілим числом >= 1");
    }

    if (n <= 1000) {
        let sum = 0.0;
        let c = 0.0;
        for (let k = 1; k <= n; k++) {
            const y = (1.0 / k) - c;
            const t = sum + y;
            c = (t - sum) - y;
            sum = t;
        }
        return { n, value: sum, method: 'kahan' };
    }

    const nd = n;
    const n2 = nd * nd;
    const n4 = n2 * n2;
    const n6 = n4 * n2;

    const val = Math.log(nd) + EULER_MASCHERONI
        + (1.0 / (2.0 * nd))
        - (1.0 / (12.0 * n2))
        + (1.0 / (120.0 * n4))
        - (1.0 / (252.0 * n6));

    return { n, value: val, method: 'asymptotic' };
}

## 7. Порівняння продуктивності та похибок

Для аналізу практичної ефективності різних алгоритмів обчислення гармонічних чисел наведено підсумкову порівняльну таблицю часової складності та точності:

| Метод обчислення | Складність по часу | Складність по пам'яті | Максимальна відносна похибка (`double`) |
| :--- | :--- | :--- | :--- |
| Пряме підсумовування (`1 → n`) | `O(n)` | `O(1)` | `≈ 10⁻¹²` при `n = 10⁶` (накопичення похибки) |
| Зворотне підсумовування (`n → 1`) | `O(n)` | `O(1)` | `≈ 10⁻¹⁵` при `n = 10⁶` |
| Алгоритм Кахана | `O(n)` | `O(1)` | `≈ 10⁻16` (межа `double`) |
| Асимптотика Ейлера — Маклорена | `O(1)` | `O(1)` | `< 10⁻¹⁵` для `n > 1000` |
| Точні дроби (Arbitrary Precision) | `O(n log n)` | `O(n log n)` | `0` (абсолютно точне раціональне значення) |

Використання алгоритму Кахана для малих `n` та формули Ейлера — Маклорена для великих `n` дає оптимальну швидкодію `O(1)` без жодної втрати точності в обчисленнях.
