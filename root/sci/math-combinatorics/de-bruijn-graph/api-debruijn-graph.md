# 📋 Інтерфейс та структура даних графа де Брейнена

Програмний інтерфейс (API), компактні бітові структури даних та специфікація модуля `DeBruijnGraph` забезпечують ефективне збереження мільйонів k-мерів у пам'яті під час аналізу геномних даних та мережевої маршрутизації.

## 1. Архітектурні вимоги та бітове кодування k-мерів

Під час обробки геномних даних людського геному (близько 3 мільярдів нуклеотидів) використання наївних текстових рядків `std::string` або класичних орієнтованих графів на покажчиках призводить до катастрофічних витрат пам'яті (сотні гігабайтів RAM). Для забезпечення роботи у межах оперативної пам'яті персонального комп'ютера або сервера модуль `DeBruijnGraph` застосовує **двобітове упаковування нуклеотидів** (англ. *2-bit DNA encoding*).

Чотири нуклеотидні основи ДНК `A`, `C`, `G`, `T` кодуються 2 бітами:

```
'A' (Аденін)    = 00
'C' (Цитозин)   = 01
'G' (Гуанін)    = 10
'T' (Тимін)     = 11
```

Один 64-бітний беззнаковий цілий тип `uint64_t` дозволяє повністю упакувати `k`-мер довжиною до `k = 32` нуклеотидів:

```
[ 2-bit ][ 2-bit ][ 2-bit ] ... [ 2-bit ]  --> uint64_t (до 32 нуклеотидів)
```

Для значень `k > 32` використовується динамічний бітовий вектор `bitset_kmer_t` або масив з двох `uint64_t` для `k <= 64`.

Операція комплементарного обернення ДНК (англ. *reverse complement*) для бітово-упакованого `k`-мера обчислюється за декілька інструкцій процесора через побітову інверсію `~` та дзеркальне розвертання бітових пар. ДНК є дволанцюговою молекулою, де пряма та зворотна комплементарна нитки є еквівалентними. Тому у сучасних біоінформатичних графах де Брейнена кожна вершина представляє канонічний `k`-мер — лексикографічний мінімум між самим `k`-мером та його комплементарним оберненням `canonical_kmer = min(kmer, reverse_complement(kmer))`.

## 2. Специфікація програмного інтерфейсу (C та C++ API)

Нижче наведено порівняльну специфікацію інтерфейсу модуля `DeBruijnGraph` мовами C та C++23. C-інтерфейс надає сумісний із POSIX Threads заголовок `debruijn_api.h`, а C++23 надає об'єктно-орієнтовану RAII-обгортку з `std::expected` та `std::string_view`.

### Деталізація функцій C API та ідіоматичного C++ API

- `dbg_init(k, initial_capacity)`: Створює екземпляр структури `debruijn_graph_ctx_t` у купі. Перевіряє, що параметр `k` є непарним і знаходиться у межах допустимого діапазону. Запитує пам'ять під таблицю відкритої адресації заданого розміру `initial_capacity`. Повертає валидний контекст або `NULL`, якщо пам'ять не вдалося виділити.
- `dbg_insert_read(ctx, sequence, seq_len)`: Приймає на вхід один нуклеотидний рядок. Перевіряє наявність некоректних символів (будь-які символи, крім `A`, `C`, `G`, `T`). Потім послідовно кодує рядок у 2-бітові `k`-мери, витягує префіксні та суфіксні `(k-1)`-мери і додає їх у граф, оновлюючи бітові маски `out_edges_mask` та `in_edges_mask`. Повертає `DEBRUIJN_SUCCESS` або `DEBRUIJN_ERROR_INVALID_READ`.
- `dbg_filter_low_coverage(ctx, min_coverage)`: Проходить по всіх вершинах хеш-таблиці та перевіряє лічильник `coverage`. Якщо лічильник нижчий за заданий поріг `min_coverage`, вершина та пов'язані з нею ребра маркуються як видалені. Повертає загальну кількість вичищених вершин.
- `dbg_compact_unitigs(ctx)`: Запускає алгоритм виявлення простих шляхів (англ. *unbranched paths*), де кожна внутрішня вершина має вхідний ступінь 1 та вихідний ступінь 1. Такі шляхи стискаються у єдине узагальнене ребро (юнітіґ), що зменшує кількість вершин у графі у десятки разів без втрати топологічної інформації.
- `dbg_find_eulerian_path(ctx, out_buffer, buffer_capacity, out_len)`: Знаходить вершини із нерівним ступенем (`in_deg != out_deg`) для визначення початку та кінця Ейлерового шляху. Якщо граф не задовольняє умові напів-Ейлерового графа, повертає `DEBRUIJN_ERROR_NOT_EULERIAN`. В іншому разі виконує ітеративний обхід і записує реконструйований рядок ДНК у наданий буфер.

## 3. Особливості C++ реалізації

1. **RAII та керування ресурсами.** Клас `DeBruijnGraph` автоматично вивільняє всю оперативну пам'ять у деструкторі. Копіювання об'єкта заборонено (`operator= delete`), оскільки граф може займати гігабайти RAM, проте підтримується ефективне переміщення (`move semantics`).
2. **Нульові копіювання (Zero-copy string_view).** Функція `insert_read` приймає `std::string_view`, що уможливлює передачу вказівників на безпосередній буфер пам'яті без проміжного копіювання рядків.
3. **Обробка помилок через `std::expected`.** На відміну від винятків (exceptions), які спричиняють накладні витрати на розгортання стека (stack unwinding), клас використовує `std::expected<T, ErrorCode>`, що забезпечує чітку та швидку перевірку статусу виконання операцій у високонавантажених обчислювальних циклах.

## 4. Опис типів даних та структур у пам'яті

Для досягнення максимальної щільності у пам'яті модуль `DeBruijnGraph` використовує три рівні представлення:

1. **2-bit Bit-packed K-mer Representation:**
   Кожен `k`-мер розглядається як ціле число `uint64_t`. Перехід між суміжними вершинами графа здійснюється бітовою операцією:
   ```
   next_kmer = ((curr_kmer << 2) | next_nucleotide_bits) & kmer_mask;
   ```
   де `kmer_mask = (1ULL << (2 * k)) - 1`.

2. **Bit-field Adjacency Mask (`uint8_t out_edges`):**
   Замість збереження списку покажчиків на суміжні вершини (що вимагає 8 байтів на кожне ребро), використовується 4-бітний прапорець у `uint8_t`:
   - Біт 0 (маска `0x01`): наявність вихідного ребра `A`.
   - Біт 1 (маска `0x02`): наявність вихідного ребра `C`.
   - Біт 2 (маска `0x04`): наявність вихідного ребра `G`.
   - Біт 3 (маска `0x08`): наявність вихідного ребра `T`.
   Це скорочує обсяг збереження ребер на 90%.

3. **Flat Compact Map (`flat_hash_map`):**
   Замість вузлів `std::unordered_map` із бічними покажчиками застосовується кеш-ефективна хеш-таблиця з відкритою адресацією (англ. *open-addressing flat hash map*), що гарантує локальність даних у L1/L2 кеші процесора.

## 5. Алгоритми спрощення графа та видалення шуму

Реальні дані секвенування містять помилки приладу (помилкові зчитування нуклеотидів із частотою ~0.1–1%). У графі де Брейнена це призводить до появи трьох типів топологічних спотворень, які підлягають автоматичній чистці:

1. **Тупикові гілки (Tips):**
   Помилка на краю зчитування створює короткий тупиковий шлях довжиною `L <= k`. Алгоритм `tip_clipping` знаходить усі вершини з вихідним ступенем 0 і якщо довжина шляху до вузла розгалуження менша за `2k`, цей шлях видаляється.

2. **Бульбашки (Bubbles):**
   Помилка або гетерозиготна мутація у середині зчитування розщеплює шлях на дві паралельні гілки, які згодом знову зливаються. Алгоритм `bubble_popping` знаходить вершини з `out-degree > 1`, відстежує розбіжні шляхи до точки злиття і вилучає гілку з меншим коефіцієнтом покриття `coverage`.

3. **Химерні ребра (Chimeric Edges):**
   Випадкові збіги помилкових `k`-мерів створюють поодинокі ребра між непов'язаними ділянками геному. Фільтр `filter_low_coverage` видаляє всі ребра, покриття яких менше за критичний поріг (наприклад, `coverage < 3`).

4. **Стиснення юнітігів (Unitig Compaction):**
   Після видалення шуму в графі залишаються довгі нерозгалужені ланцюжки вершин, де кожна вершина має вхідний ступінь 1 і вихідний ступінь 1 (`in-degree = 1, out-degree = 1`). Алгоритм стиснення замінює весь такий ланцюжок одним узагальненим супервузлом (юнітіґом), зберігаючи лише перший префікс та послідовність нових нуклеотидів.

## 6. Багатопотокова паралелізація побудови (Parallel Graph Construction)

При обробці терабайтних FASTA/FASTQ файлів на багатоядерних серверах побудова графа є вузьким місцем. Модуль `DeBruijnGraph` підтримує паралельну вставку зчитувань за допомогою OpenMP або POSIX Threads:

1. **Memory-Mapped I/O (`mmap`):** Вхідний файл FASTQ відображається безпосередньо у віртуальний адресний простір процесу, усуваючи буферизоване системне зчитування `read()`.
2. **Розбиття на блоки (Chunk Partitioning):** Файл ділиться на `T` незалежних блоків за межами рядків FASTQ, де `T` — кількість потоків обробки.
3. **Локальні підтаблиці (Thread-local Lock-free Buffers):** Кожен потік збирає локальну хеш-таблицю `k`-мерів у виділеній пам'яті.
4. **Паралельне злиття (Parallel Reduction):** Після завершення читання локальні підтаблиці об'єднуються у глобальну структуровану хеш-таблицю із застосуванням атомних інструкцій `std::atomic<uint8_t>` для оновлення бітових масок ребер.

## 7. Формати збереження на диску (GFA1 & GFA2)

Після спрощення та стиснення графа де Брейнена результуючі юнітіґи та зв'язки між ними експортуються у стандартні біоінформатичні текстові формати Graphical Fragment Assembly (GFA):

```
H  VN:Z:1.0
S  utg00001  ATGCGATCGATCGATCGATCG  LN:i:21  KC:i:45
S  utg00002  CGATCGATCGATCGATCGATC  LN:i:21  KC:i:42
L  utg00001  +  utg00002  +  19M
```

- Порядок `S` (Segment) визначає юнітіґ (назву, послідовність нуклеотидів, довжину `LN` та покриття `KC`).
- Порядок `L` (Link) визначає перекриття довжиною `k - 1` між двома юнітіґами із зазначенням орієнтації ниток (`+` або `-`).

## 10. Крайові випадки та обробка помилок

1. **Непарний розмір k-мера.**
   У біоінформатиці `k` завжди обирається **непарним** (наприклад, 21, 31, 55). Це унеможливлює утворення паліндромних `k`-мерів (рядків, які збігаються зі своїм зворотним комплементом), що запобігає виникненню небажаних самопетель та симетричних замкнених циклів у графі.
2. **Паліндромні k-мери.**
   Якщо значення `k` є парним, існує ймовірність утворення паліндромного `k`-мера (наприклад, `ATGCATGC`), який дорівнює своєму комплементарному оберненню. У цьому випадку ребро графа стає ненапрямленим або утворює самопетлю, що порушує орієнтованість графа де Брейнена та ламає алгоритм Гірхольцера.
