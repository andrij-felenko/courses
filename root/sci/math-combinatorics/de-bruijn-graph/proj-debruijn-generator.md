# ⚙️ Побудова графа де Брейнена та генерація послідовностей

Ця вставка містить алгоритмічну реалізацію побудови орієнтованого графа де Брейнена, пошуку Ейлерового циклу за допомогою модифікованого алгоритму Гірхольцера та генерації циклічних послідовностей де Брейнена мовами C та C++.

## 1. Постановка задачі та ідея алгоритму

Нехай задано цілі числа `k ≥ 2` (розмір алфавіту) та `n ≥ 1` (довжина вікна). Необхідно побудувати циклічний рядок `S` довжиною `kⁿ` над двозначним або довільним алфавітом `Σ = {0, 1, ..., k-1}`, у якому кожен підрядок довжиною `n` зустрічається як неперервний блок рівно один раз.

**Ідея розв'язання:**
1. Побудувати орієнтований граф де Брейнена `B(k, n)`:
   - Вершинами є списки `(n-1)`-вимірних вектора-префіксів.
   - Орієнтовані ребра описують переходи при додаванні нового символу зсуву `0, ..., k-1`.
2. Кожна вершина має вхідну та вихідну валентність `deg⁺(v) = deg⁻(v) = k`, тобто граф є балансованим Ейлеровим графом, у якому обхід усіх ребер гарантовано існує.
3. Застосувати **алгоритм Гірхольцера (Hierholzer's Algorithm)**:
   - Розпочати з довільної початкової вершини (наприклад, вершини з усіх нулів).
   - Рухатися по невикористаних ребрах, видаляючи (або помічаючи) пройдені ребра, та записувати переходи у локальний стек.
   - Коли рух застрягає у вершині (немає невикористаних вихідних ребер), поточна вершина додається до підсумкового Ейлерового циклу.
   - Результуючий список ребер, прочитаний у зворотному порядку, утворює послідовність символів зсуву.

Для оптимальної продуктивності в двійковому випадку `k = 2` номери вершин зберігаються як цілі числа від `0` до `2ⁿ⁻¹ - 1`. Зсув вершини `u` при виборі нового біта `b ∈ {0, 1}` обчислюється за допомогою бітового зсуву вліво та побітового маскування `v = ((u << 1) | b) & mask`, де `mask = 2ⁿ⁻¹ - 1`. Це дозволяє уникнути повільних текстових операцій та працювати безпосередньо в регістрах процесора.

## 2. Покроковий приклад трасування алгоритму для B(2, 3)

Простежимо роботу алгоритму Гірхольцера для двійкового графа `B(2, 3)` з 4 вершинами `{00, 01, 10, 11}` та 8 ребрами:

1. **Старт у вершині 0 (`00`):**
   - З `00` виходить ребро 1 (символ `1`), переходимо у вершину `01`. Стек вершин: `[00]`.
   - З `01` виходить ребро 1 (символ `1`), переходимо у вершину `11`. Стек вершин: `[00, 01]`.
   - З `11` виходить ребро 1 (символ `1`), самопетля `111`. Стек вершин: `[00, 01, 11]`.
   - З `11` виходить ребро 0 (символ `0`), переходимо у вершину `10`. Стек вершин: `[00, 01, 11, 11]`.
   - З `10` виходить ребро 1 (символ `1`), переходимо у вершину `01`. Стек вершин: `[00, 01, 11, 11, 10]`.
   - З `01` виходить ребро 0 (символ `0`), переходимо у вершину `10`. Стек вершин: `[00, 01, 11, 11, 10, 01]`.
   - З `10` виходить ребро 0 (символ `0`), переходимо у вершину `00`. Стек вершин: `[00, 01, 11, 11, 10, 01, 10]`.
   - З `00` виходить ребро 0 (символ `0`), самопетля `000`. Стек вершин: `[00, 01, 11, 11, 10, 01, 10, 00]`.
2. **Повернення зі стека (Backtracking):**
   Усі ребра вичерпано. Витягуючи символи зі стека у зворотному порядку, отримуємо прямохідну послідовність де Брейнена `00011101`.

## 4. Порівняльний аналіз реалізацій C проти C++

Порівняємо два підходи до побудови модуля генератора з точки зору архітектури системного коду:

1. **Модель C (Процедурна з явним виділенням пам'яті):**
   - Усі масиви виділяються через `malloc`/`calloc` у купі. Контекст `debruijn_graph_t` передається як перший аргумент кожної функції.
   - Відсутність винятків гарантує передбачуваний час виконання кожної інструкції, що критично для embedded-систем та мікроконтролерів без ОС.
   - Звільнення ресурсів потребує обов'язкового виклику `debruijn_free()`.

2. **Модель C++ (Об'єктно-орієнтована з RAII та `std::expected`):**
   - Використання контейнера `std::vector` усуває ризик витоку пам'яті: деструктор вектора автоматично звільняє купу при виході зі сфери видимості.
   - Повернення помилок через `std::expected<std::string, DeBruijnError>` позбавляє потреби у винятках та надає синтаксичну чіткість.
   - Резервування пам'яті через `reserve(num_edges_)` гарантує відсутність повторних реалокацій вектора під час обходу.

## 5. Алгоритмічний аналіз та складності

1. **Часова складність (Time Complexity):** `O(kⁿ)`.
   Алгоритм Гірхольцера обходить кожне з `|E| = kⁿ` ребер орієнтованого графа де Брейнена рівно один раз. На кожному кроці перехід до суміжної вершини та оновлення стека виконується за атомарний час `O(1)` завдяки прямому обчисленню бітового зсуву. Загальний час є строго лінійним від кількості ребер графа.
2. **Просторова складність (Space Complexity):** `O(kⁿ⁻¹)`.
   Масив лічильників вихідних ребер `adj_count` вимагає пам'яті під `|V| = kⁿ⁻¹` елементів. Стек ребер та вершин у найгіршому випадку містить до `kⁿ` елементів, що дає підсумкові витрати оперативної пам'яті `O(kⁿ)`.

## 6. Пастки реалізації та крайові випадки

1. **Переповнення стека при рекурсивному обході в глибину (DFS).**
   Пряма реалізація алгоритму Гірхольцера через рекурсивні виклики функції `dfs()` призводить до переповнення системного стека (англ. *stack overflow*) вже при `n ≥ 16`, оскільки глибина рекурсії сягає `kⁿ = 65536` і більше кадрів. У наведеному коді проблему усунуто за допомогою **явного ітеративного стека у купі (heap)**.
2. **Прямий та зворотний порядок зчитування.**
   При додаванні елементів до підсумкового списку під час повернення зі стека (post-order traversal) послідовність виходить інвертованою. Для отримання прямого Ейлерового циклу результат або інвертують, або зчитують у зворотному порядку, що гарантує збереження правил зсуву.
3. **Крайові випадки `n = 1`.**
   При `n = 1` граф містить єдину вершину порожнього префікса з `k` самопетлями. Алгоритм коректно обробляє цей випадок, виводячи послідовність усіх `k` символів алфавіту без провалів та нескінченних циклів.
4. **Неспряжені компоненти у неідеальних геномних графах.**
   При роботі з реальним ДНК-секвенуванням граф де Брейнена не є повністю ідеальним `B(k, n)` через наявність помилок секвенування та відсутніх `k`-мерів. У цьому випадку алгоритм Гірхольцера потребує додаткової перевірки на наявність декількох компонент зв'язності та балансування степенів джерела і стоку.
