# 📋 Інтерфейс профілів ICC та специфікація модулів керування кольором (CMM)

Специфікація Міжнародного колірного консорціуму (International Color Consortium — ICC) описує стандартний бінарний формат даних та програмний інтерфейс для міжплатформного обміну колірними даними. Профіль ICC є файлом дворазового узгодження, який переводить апаратно-залежні координати конкретного пристрою (RGB, CMYK, Multi-ink) в апаратно-незалежний простір зв'язку профілів (Profile Connection Space — PCS), в ролі якого виступає **CIE XYZ 1931** або **CIELAB (`L*a*b*`)**.

Модуль керування кольором (Color Management Module — CMM) є програмним двигуном, який інтерпретує таблиці профілю, обчислює 3D-інтерполяції та виконує колірне перетворення між пристроєм-джерелом та пристроєм-отримувачем.

У цьому розділі наведено детальну специфікацію бінарної структури заголовка ICC, таблиці тегів, чотирьох моделей рендерингу, топологію обчислювального конвеєра CMM та C-API контракт бібліотеки LittleCMS.

## 1. Заголовок профілю ICC (Header Structure)

Кожен профіль ICC починається зі строго вирівняного бінарного заголовка розміром ровно `128 байт`. Заголовок містить ключові метадані про тип пристрою, колірний простір пристрою, колірний простір PCS, опорну білу точку та унікальну ідентифікаційну контрольну суму.

Усі числові значення у бінарних полях заголовка зберігаються у мережевому порядку байтів (Big-Endian / MSB First).

| Зсув (байтів) | Розмір (байтів) | Поле | Опис та допустимі значення |
| :--- | :--- | :--- | :--- |
| `0..3` | 4 | `Profile Size` | Загальний розмір файлу профілю в байтах (Big-Endian `uint32`). |
| `4..7` | 4 | `CMM Type Signature` | Ідентифікатор рекомендованого CMM (наприклад, `'LCMS'` для LittleCMS або `'KCMS'` для Kodak CMM). |
| `8..11` | 4 | `Profile Version` | Версія специфікації ICC (наприклад, `0x04300000` для версії v4.3.0). |
| `12..15` | 4 | `Profile/Device Class` | Клас профілю: `'scnr'` (Input/Scanner), `'mntr'` (Display), `'prtr'` (Output/Printer), `'link'` (DeviceLink), `'spac'` (ColorSpace), `'abstract'` (Abstract). |
| `16..19` | 4 | `Data Color Space` | Колірний простір пристрою: `'RGB '`, `'CMYK'`, `'GRAY'`, `'8CLR'`. |
| `20..23` | 4 | `PCS` | Простір зв'язку профілю (PCS): `'XYZ '` або `'Lab '`. |
| `24..35` | 12 | `Date and Time` | Дата й час створення профілю (`uint16` × 6: рік, місяць, день, години, хвилини, секунди). |
| `36..39` | 4 | `File Signature` | Магічний чотирисимвольний рядок `'acsp'` (All Color Matching Profiles). |
| `40..43` | 4 | `Primary Platform` | Цільова операційна система: `'APPL'` (Apple), `'MSFT'` (Microsoft), `'SGI '`, `'SUNW'`. |
| `44..47` | 4 | `Profile Flags` | Прапори профілю (біт 0: вбудований у файл зображення, біт 1: використання обмежене автономно). |
| `48..51` | 4 | `Device Manufacturer` | Чотирисимвольний кодовий ідентифікатор виробника обладнання (наприклад, `'EPSO'`). |
| `52..55` | 4 | `Device Model` | Ідентифікатор моделі пристрою. |
| `56..63` | 8 | `Device Attributes` | Атрибути матеріалу носія: прозорий/відбиваючий, глянцевий/матовий, позитив/негатив. |
| `64..67` | 4 | `Rendering Intent` | Намір рендерингу за замовчуванням: `0` — Perceptual, `1` — Relative Colorimetric, `2` — Saturation, `3` — Absolute Colorimetric. |
| `68..79` | 12 | `PCS Illuminant` | Спектральне джерело освітлення PCS (завжди `D50`: `X=0.9642, Y=1.0000, Z=0.8249` у форматі `s15Fixed16Array`). |
| `80..83` | 4 | `Creator Signature` | Сигнатура програмного забезпечення, що створило профіль. |
| `84..99` | 16 | `Profile ID` | MD5-контрольна сума тіла профілю для однозначної ідентифікації. |
| `100..127` | 28 | `Reserved` | Зарезервовано ICC специфікацією, має містити нульові байти. |

## 2. Таблиця тегів (Tag Table) та типи елементів

Одразу після заголовка на зсуві `128` розміщена таблиця тегів. Вона є каталогом (індексом), який описує зміст та розташування даних всередині профілю.

Таблиця починається з `uint32` лічильника кількості тегів `Tag Count`, після якого слідує масив структур записів тегів (розміром `12 байт` кожен):

```
+-------------------------------------------------------------+
| Tag Count (4 байти, uint32 Big-Endian)                      |
+---------------------+--------------------+------------------+
| Tag Signature (4b)  | Offset (4b)        | Element Size (4b)|
+---------------------+--------------------+------------------+
| Tag Signature (4b)  | Offset (4b)        | Element Size (4b)|
+---------------------+--------------------+------------------+
```

### Основні обов'язкові теги для дисплейних профілів (`'mntr'`)

- **`'rXYZ'`, `'gXYZ'`, `'bXYZ'` (Red/Green/Blue Colorant Tags):** Тристимульні значення первинних випромінювачів дисплея (Червоного, Зеленого та Синього) у просторі CIE XYZ відносно опорного білого освітлення `D50` PCS (тип `XYZType`).
- **`'rTRC'`, `'gTRC'`, `'bTRC'` (Tone Reproduction Curves):** Криві відтворення тону для кожного з трьох каналів. Можуть задаватися як 1D-таблиця лукапу (тип `curveType`) або як параметрична математична формула передавальної гамма-функції (тип `parametricCurveType`).
- **`'wtpt'` (Media White Point Tag):** Абсолютна тристимульна точка білого випромінювача пристрою в освітленні `D50`.
- **`'bkpt'` (Media Black Point Tag):** Абсолютна точка чорного кольору пристрою.
- **`'chad'` (Chromatic Adaptation Tag):** Матриця `3×3` хроматичної адаптації Бредфорда, яка переводить білу точку пристрою до стандартного освітлення PCS `D50`.

### Основні обов'язкові теги для друкарських профілів (`'prtr'`)

Дисплейні матричні профілі не здатні описати складну нелінійну поверхню колірного охоплення багаторазових друкарських машин. Тому друкарські профілі використовують багатовимірні lookup-таблиці (CLUT):

- **`'A2B0'` (Device to PCS — Perceptual):** Таблиця перетворення з колірного простору пристрою (CMYK/RGB) у PCS для наміру Perceptual.
- **`'A2B1'` (Device to PCS — Relative Colorimetric):** Таблиця перетворення в PCS для наміру Relative Colorimetric.
- **`'A2B2'` (Device to PCS — Saturation):** Таблиця перетворення в PCS для наміру Saturation.
- **`'B2A0'`, `'B2A1'`, `'B2A2'` (PCS to Device):** Зворотні таблиці перетворення з простору PCS у колірний простір пристрою виводу.

## 3. Моделі рендерингу (Rendering Intents)

При здійсненні колірного переходу між двома пристроями з різними колірними охопленнями (наприклад, із широкого екрана Adobe RGB на вузьке поліграфічне охоплення CMYK газетного паперу) частина кольорів неминуче виходить за межі допустимого гамуту пристрою-отримувача. 

Модель рендерингу визначає математичну стратегію компресії або відсікання позагамутових кольорів CMM-модулем.

### 1. Перцептивний намір (Perceptual Intent — Intent 0)
- **Математичний принцип:** Усе колірне охоплення пристрою-джерела стискається пропорційно, щоб повністю вміститися в охоплення пристрою-отримувача.
- **Практична властивість:** Зберігаються відносні градації та гармонійні переходи між кольорами. Всі кольори зображення трохи змінюють свій абсолютний тон і насиченість, але зоровий контраст та об'єм зображення залишаються природними для ока.
- **Сфера застосування:** Художня фотографія, складні образотворчі зображення з багатьма плавними півтонами.

### 2. Відносний колориметричний (Relative Colorimetric — Intent 1)
- **Математичний принцип:** Кольори, які входять у колірне охоплення пристрою-отримувача, залишаються абсолютно незмінними. Кольори, що виходять за межі гамуту, відсікаються до найближчої доступної межі на спектральному локусі. Точка білого джерела масштабується до точки білого носія.
- **Практична властивість:** Забезпечує абсолютну точність збереження тону для всерединігамутових кольорів. Проте деталі в глибоких тінях чи надсильно насичених областях втрачаються через відсікання (кліпінг).
- **Сфера застосування:** Поліграфічний друк фірмових логотипів, векторна графіка, верстка веб-сторінок.

### 3. Насиченість / Графіка (Saturation Intent — Intent 2)
- **Математичний принцип:** Забезпечує максимально можливу колірну насиченість (чистоту) на шкоду точній передачі колірного тону та світлоти.
- **Практична властивість:** Кольори зміщуються на межу колірного охоплення носія для створення максимальної зорової яскравості.
- **Сфера застосування:** Бізнес-презентації, діаграми, інфографіка, рекламні банери.

### 4. Абсолютний колориметричний (Absolute Colorimetric — Intent 3)
- **Математичний принцип:** Аналогічний відносному колориметричному, але **без тональної адаптації білої точки**. Якщо білий колір на папері є жовтуватим, CMM додає жовтий пігмент навіть на чисто білі ділянки зображення.
- **Практична властивість:** Точно імітує колірний відтінок підкладки та паперу іншого пристрою.
- **Сфера застосування:** Контрактна кольоропроба перед масовим друком тиражу.

## 4. Конвеєр обробки даних у CMM (Pipeline Topology)

Модуль CMM будує конвеєр обробки на основі елементів тегів `lut8Type`, `lut16Type` або `lutmABType` (ICC v4). 

Обчислювальний конвеєр CMM складається з п'яти послідовних лінійних та нелінійних блоків:

```
[Вхідний колір] ──> [ A-Curves ] ──> [ CLUT 3D ] ──> [ M-Curves ] ──> [ Matrix 3x3 ] ──> [ B-Curves ] ──> [PCS]
```

1. **A-Curves (Криві входів):** Масив 1D-таблиць лукапу (1D LUT) для лінеаризації кожного каналу пристрою окремо.
2. **CLUT (Color Look-Up Table):** Тривимірна або чотиривимірна сітка колірного куба (зазвичай `33 × 33 × 33` або `65 × 65 × 65` вузлів). CMM виконує трилінійну або тетраедричну інтерполяцію між сусідніми вузлами сітки.
3. **M-Curves (Криві матрицювання):** 1D-криві корекції тону перед множенням на матрицю.
4. **Matrix (Матриця 3×3):** Лінійне перетворення між координатами.
5. **B-Curves (Криві виходів):** Остаточні 1D-криві для нормування координат перед виходом у PCS.

## 5. C-API контракт модуля керування кольором (на прикладі LittleCMS)

Стандартним відкритим C-інтерфейсом обробки профілів у промисловості є бібліотека `LittleCMS` (lcms2). Вона реалізує повний специфікований конвеєр ICC v4.

Нижче подано ключовий API-контракт бібліотеки LittleCMS:

:::tabs
```c
/* C (C99): Прямий C-API контракт бібліотеки LittleCMS (lcms2) */
#include <lcms2.h>

/* 1. Відкриття файлу профілю з диска або пам'яті */
cmsHPROFILE cmsOpenProfileFromFile(const char *FileName, const char *Access);
cmsHPROFILE cmsOpenProfileFromMem(const void *Buffer, cmsUInt32Number size);

/* 2. Створення віртуального профілю sRGB у пам'яті */
cmsHPROFILE cmsCreate_sRGBProfile(void);

/* 3. Створення трансформаційного конвеєра між двома профілями */
cmsHTRANSFORM cmsCreateTransform(
    cmsHPROFILE InputProfile,       /* Профіль джерела */
    cmsUInt32Number InputFormat,    /* Формат пікселів (наприклад TYPE_RGB_8) */
    cmsHPROFILE OutputProfile,      /* Профіль пристрою виводу */
    cmsUInt32Number OutputFormat,   /* Формат виводу (наприклад TYPE_CMYK_8) */
    cmsUInt32Number Intent,         /* Намір рендерингу (INTENT_PERCEPTUAL тощо) */
    cmsUInt32Number Flags           /* Прапори (наприклад cmsFLAGS_BLACKPOINTCOMPENSATION) */
);

/* 4. Виконання колірного перетворення над масивом пікселів */
void cmsDoTransform(
    cmsHTRANSFORM Transform,
    const void *InputBuffer,
    void *OutputBuffer,
    cmsUInt32Number Size            /* Кількість пікселів для обробки */
);

/* 5. Звільнення ресурсів */
void cmsDeleteTransform(cmsHTRANSFORM Transform);
cmsBool cmsCloseProfile(cmsHPROFILE hProfile);
```
```cpp
// C++ (C++20): Обгортка RAII навколо LittleCMS C-API для автоматичного керування ресурсами
#include <lcms2.h>
#include <memory>
#include <span>
#include <stdexcept>

namespace lcms {

struct ProfileDeleter {
    void operator()(cmsHPROFILE handle) const noexcept {
        if (handle) {
            cmsCloseProfile(handle);
        }
    }
};

struct TransformDeleter {
    void operator()(cmsHTRANSFORM handle) const noexcept {
        if (handle) {
            cmsDeleteTransform(handle);
        }
    }
};

using UniqueProfile = std::unique_ptr<void, ProfileDeleter>;
using UniqueTransform = std::unique_ptr<void, TransformDeleter>;

class ColorTransform {
private:
    UniqueTransform transform_;

public:
    ColorTransform(const UniqueProfile& in_profile, cmsUInt32Number in_format,
                   const UniqueProfile& out_profile, cmsUInt32Number out_format,
                   cmsUInt32Number intent = INTENT_PERCEPTUAL, cmsUInt32Number flags = 0) {
        cmsHTRANSFORM handle = cmsCreateTransform(
            in_profile.get(), in_format,
            out_profile.get(), out_format,
            intent, flags
        );
        if (!handle) {
            throw std::runtime_error("Не вдалося створити колірну трансформацію CMM");
        }
        transform_.reset(handle);
    }

    template <typename T_In, typename T_Out>
    void transform(std::span<const T_In> in_buffer, std::span<T_Out> out_buffer) const {
        if (in_buffer.size() > out_buffer.size()) {
            throw std::invalid_argument("Розмір вихідного буфера менший за вхідний");
        }
        cmsDoTransform(transform_.get(), in_buffer.data(), out_buffer.data(),
                       static_cast<cmsUInt32Number>(in_buffer.size()));
    }
};

} // namespace lcms
```
:::

Специфікація ICC забезпечує сувору математичну узгодженість при передачі зображень між різнорідними операційними системами, графічними редакторами та друкарським обладнанням.
