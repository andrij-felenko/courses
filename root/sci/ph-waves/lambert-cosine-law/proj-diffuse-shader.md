# ⚙️ Алгоритм ламбертового розсіювання та обчислення дифузного BRDF

Ця вставка містить практичні обчислювальні алгоритми ламбертового розсіювання світла, які застосовуються у 3D-рендерингу, комп'ютерній графіці, моделюванні сонячної інсоляції та трасуванні променів (Ray Tracing). Тут розібрано як класичний прямий розрахунок дифракційного/дифузного освітлення (Lambertian Diffuse Shading), так і генерацію випадкових напрямків розсіювання методом Монте-Карло з ваговим розподілом косинуса.

---

### 1. Обчислювальна модель ламбертової BRDF

У тривимірній графіці та фізично точній оптичній симуляції (Physically Based Rendering, PBR) поведінка світла на поверхні описується двонапрямковою функцією відображальної здатності (BRDF — *Bidirectional Reflectance Distribution Function*). 

За означенням BRDF `f_r(ω_i, ω_o)` є відношенням відбитої яскравість `dL_o(ω_o)` у напрямку спостереження `ω_o` до падаючої освітленості `dE_i(ω_i)`, створеної променем з напрямку `ω_i`:

```
f_r(ω_i, ω_o) = dL_o(ω_o) / dE_i(ω_i)
```

Для ідеально ламбертової поверхні з альбедо `ρ ∈ [0, 1]` (де `ρ` — частка відбитого світла, `0` — абсолютно чорне тіло, `1` — ідеально біла поверхня) відбита яскравість є однаковою у всіх напрямках півсфери (`L_o = const`). 

Згідно з математичним виводом інтегрування по півсфері, повному відбитому потоку відповідає коефіцієнт `π`. Отже, **ламбертова BRDF є постійною величиною**, яка не залежить ані від кута падіння `ω_i`, ані від кута спостереження `ω_o`:

```
f_r = ρ / π
```

Падаючий світловий потік створює на поверхні з нормаллю `N̂` від джерела з напрямком `L̂` освітленість, пропорційну скалярному добутку `(N̂ · L̂)`. Якщо кут падіння перевищує 90° (`N̂ · L̂ < 0`), поверхня відвернута від джерела й перебуває у власному затінку. Отже, відбита інтенсивність розраховується за формулою:

```
I_out = I_light · (ρ / π) · max(0, N̂ · L̂)
```

Ця формула використовується у графічних конвеєрах (OpenGL, Direct3D, Vulkan, Metal) для обчислення освітленості кожного фрагмента або вершини тривимірної сітки.

### 2. Алгоритми Монте-Карло та косинусно-зважений семплінг

У сучасних системах фотореалістичного рендерингу (Path Tracing) світловий потік обчислюється шляхом симуляції мільйонів випадкових траєкторій фотонів методом Монте-Карло.

Основне рівняння рендерингу (Kajiya Rendering Equation) вимагає обчислення інтеграла відбитої яскравості по півсфері напрямків `S²⁺`:

```
L_o(ω_o) = ∫_S²⁺ f_r · L_i(ω_i) · max(0, N̂ · ω_i) · dω_i
```

Для ламбертового матеріалу `f_r = ρ / π`, отже інтеграл набирає вигляду:

```
L_o(ω_o) = (ρ / π) · ∫_S²⁺ L_i(ω_i) · (N̂ · ω_i) · dω_i
```

Якщо генерувати напрямки променів `ω_i` рівномірно по півсфері, функція щільності ймовірності (PDF — *Probability Density Function*) буде постійною: `pdf_uniform = 1 / (2π)`. У цьому випадку кожен промінь доведеться множити на вагу `(N̂ · ω_i) = cos θ`. Для променів біля горизонту (`θ → 90°`) ця вага близька до нуля, що призводить до високої дисперсії (шуму) на підсумковому зображенні.

Щоб мінімізувати шум рендерингу, застосовують **косинусно-зважений семплінг півсфери** (*Cosine-weighted Hemisphere Sampling*). Напрямки променів генеруються з щільністю ймовірності, пропорційною косинусу кута:

```
pdf_cosine(θ) = cos θ / π
```

Для генерації таких напрямків за допомогою двох незалежних рівномірно розподілених випадкових чисел `u₁ ∈ [0, 1]` та `u₂ ∈ [0, 1]` використовується перетворення полярних координат:

```
r = √u₁
φ = 2 · π · u₂

x = r · cos φ = √u₁ · cos(2π u₂)
y = r · sin φ = √u₁ · sin(2π u₂)
z = √(1 - u₁)
```

Вектор `(x, y, z)` задає напрямок розсіяного променя в локальній системі координат, де нормаль спрямована вздовж осі Z (`N̂_local = (0, 0, 1)`). Для переходу до глобальних координат 3D-сцени будується ортонормований базис з дотичного вектора `T̂` (Tangent), бінормалі `B̂` (Bitangent) та нормалі `N̂`:

```
ω_global = T̂ · x + B̂ · y + N̂ · z
```

Головна перевага косинусно-зваженого семплінгу полягає в тому, що множник `cos θ` у рівнянні рендерингу точно скорочується з `cos θ` у знаменнику `pdf_cosine`, і вага кожного випущеного фотона стає просто рівною `ρ`. Це кардинально прискорює збіжність алгоритму Монте-Карло й робить картинку чистою за набагато меншу кількість семплів на піксель.

### 3. Калібрування фізичних одиниць випромінювання у двигуні

У фізично точних шейдерах розрахунок інтенсивності світла виконується в абсолютних фізичних одиницях. Для точкових джерел (Point Lights) параметр потужності задається в люменах `Φ_src`. Сила світла уздовж будь-якого напрямку при ізотропному випромінюванні становить `I_src = Φ_src / (4π)`.

Для плоских ламбертових випромінювачів (Area Lights) потужність задається яскравістю `L₀` (кд/м²) або повним потоком `Φ_total = π · L₀ · A_src`. Під час розрахунку освітленості пікселя на відстані `r` з урахуванням згасання додається фактор ділення на `r²`. Щоб уникнути ділення на нуль біля самого джерела, у знаменник вводять мале регуляризаційне значення `ε = 10⁻⁶`:

```
attenuation = 1.0 / (dist_sq + 1e-6)
```

Після обчислення підсумкової яскравості у лінійному просторі HDR (High Dynamic Range) значення кольору `L_hdr` необхідно перевести у діапазон від 0 до 1 для відображення на моніторі SDR. Для цього застосовують алгоритм тональної компресії (Tone Mapping) та гама-корекцію.

Класична операторна крива Reinhard Tone Mapping перетворює високу яскравість за формулою:

```
L_sdr = L_hdr / (1.0 + L_hdr)
```

А сучасна кінематографічна крива ACES (Academy Color Encoding System) враховує насиченість кольорів та S-подібний контраст:

```
L_aces = (L_hdr · (2.51 · L_hdr + 0.03)) / (L_hdr · (2.43 · L_hdr + 0.59) + 0.14)
```

Після тональної компресії застосовується стандартизована гама-корекція sRGB зі ступенем `1 / 2.2`:

```
Color_display = pow(L_aces, 1.0 / 2.2)
```

### 7. Інтеграція алгоритму в рушій Path Tracing

У повноцінному незміщеному рендерері Path Tracing алгоритм ламбертового розсіювання використовується на кожному дотику променя з дифузною поверхнею.

Повний цикл обробки одного відбиття в алгоритмі трасування шляхів складається з таких кроків:
1. **Перевірка перетину променя зі сценою:** Алгоритм знаходить найближчу точку перетину `P` та вектор нормалі `N̂`.
2. **Перевірка на випромінювання (Emissive material):** Якщо об'єкт у точці `P` є джерелом світла, його випромінювана яскравість `L_emit` додається до акумулятора світла.
3. **Косинусне вибіркоутворення (Sampling):** Викликається функція `sample_hemisphere_cosine(N̂)`, яка повертає новий випадковий напрямок випущеного променя `ω_next`.
4. **Рекурсивне відстеження (Ray bounce):** Новий промінь випускається з точки `P` у напрямку `ω_next`. Його колір множиться на альбедо поверхні `ρ`.
5. **Припинення шляху (Russian Roulette):** Щоб запобігти безкінечній рекурсії при багатьох відбиттях, застосовують метод «російської рулетки». На кожному відбитті після 3-го промінь із ймовірністю `q = 1 - max(ρ_r, ρ_g, ρ_b)` знищується, а промені, що вижили, масштабуються на множник `1 / (1 - q)` для збереження статистичної незміщеності результатом.

Завдяки тому, що функція семплінгу генерує напрямки за косинусним законом `pdf = cos θ / π`, ваговий фактор фотона спрощується до суто колірного альбедо `ρ`, що робить обчислювальний цикл трасування легким та позбавленим складних тригонометричних обчислень на кожному кроці.

### 8. Шейдери мовами GLSL та HLSL для графічних процесорів (GPU)

У графічних застосунках реального часу (іграх, CAD-системах, VR-симуляторах) ламбертів шейдинг обчислюється на GPU у фрагментних (піксельних) шейдерах. 

Нижче подано ідіоматичний еквівалент шейдера мовою **GLSL** (OpenGL / Vulkan):

```glsl
// GLSL Fragment Shader: Lambertian Diffuse Shading
#version 450 core

in vec3 v_WorldPos;
in vec3 v_WorldNormal;

out vec4 FragColor;

uniform vec3 u_LightPos;
uniform vec3 u_LightColor;
uniform vec3 u_Albedo;

const float PI = 3.14159265359;

void main() {
    vec3 N = normalize(v_WorldNormal);
    vec3 L = normalize(u_LightPos - v_WorldPos);
    
    // Скалярний добуток із відтинанням від'ємних значень
    float NdotL = max(dot(N, L), 0.0);
    
    // Ламбертова BRDF
    vec3 brdf = u_Albedo / PI;
    
    // Підсумковий дифузний колір
    vec3 diffuse = u_LightColor * brdf * NdotL;
    
    FragColor = vec4(diffuse, 1.0);
}
```

А ось відповідний фрагмент мовою **HLSL** (DirectX 11 / DirectX 12):

```hlsl
// HLSL Pixel Shader: Lambertian Diffuse Shading
cbuffer SceneBuffer : register(b0) {
    float3 u_LightPos;
    float3 u_LightColor;
    float3 u_Albedo;
};

struct PS_INPUT {
    float4 Position : SV_POSITION;
    float3 WorldPos : TEXCOORD0;
    float3 Normal   : NORMAL;
};

static const float PI = 3.14159265359;

float4 PSMain(PS_INPUT input) : SV_TARGET {
    float3 N = normalize(input.Normal);
    float3 L = normalize(u_LightPos - input.WorldPos);
    
    float NdotL = saturate(dot(N, L)); // saturate відтинає до [0, 1]
    float3 brdf = u_Albedo / PI;
    float3 diffuse = u_LightColor * brdf * NdotL;
    
    return float4(diffuse, 1.0);
}
```

Обидва шейдери демонструють абсолютну ізоморфність концепції: векторна нормалізація, скалярний добуток з відтинанням та ділення альбедо на константу `π`.

### 9. Зв'язок із фоновим затіненням (Ambient Occlusion)

Закон Ламберта лежить у основі алгоритмів обчислення **фонового затінення** (Ambient Occlusion, AO, SSAO, HBAO, GTAO).

Затінення Ambient Occlusion характеризує частку відкритого небесного півпростору, яку «бачить» точка поверхні `P`. Для ламбертового розсіювача коефіцієнт доступності довкілля `A(P)` обчислюється шляхом косинусно-зваженого інтегрування видимості `V(P, ω)` по півсфері:

```
A(P) = (1 / π) · ∫_S²⁺ V(P, ω) · max(0, N̂ · ω) · dω
```

Функція видимості `V(P, ω)` дорівнює `0`, якщо у напрямку `ω` на близькій відстані розташована перешкода (кут кутка, складка тканини, внутрішня стінка отвору), і `1`, якщо напрямок відкритий.

Оскільки інтегрування зважене за законом косинуса Ламберта, перешкоди, розташовані прямо над нормаллю (`θ ≈ 0°`), дають значно сильніше затінення, ніж перешкоди біля самого горизонту (`θ ≈ 90°`). Це математичне зважування дозволяє алгоритмам екранного затінення (SSAO / GTAO) будувати реалістичні м'які тіні у кутках приміщень і складинках складних 3D-моделей.

### 10. Векторна оптимізація SIMD та Lay-out даних SoA

У високонавантажених обчислювальних модулях (Offline Renderer, геодезичні фотограмметричні системи, моделювання радіаційного теплообміну супутників) обчислення ламбертового розсіювання для мільйонів трикутників стає «вузьким місцем» процесора.

Щоб досягти максимальної швидкодії на сучасних ЦП (x86-64 AVX-512 або ARM NEON), стандартне представлення даних «Масив структур» (AoS — *Array of Structures*):

```cpp
struct Vertex {
    float x, y, z;
    float nx, ny, nz;
    float r, g, b;
};
struct Vertex vertices[N];
```

рефакторять у представлення «Структура масивів» (SoA — *Structure of Arrays*):

```cpp
struct VertexBufferSoA {
    float *posX, *posY, *posZ;
    float *normX, *normY, *normZ;
    float *albedoR, *albedoG, *albedoB;
};
```

При SoA-компонуванні нормалі `normX`, `normY`, `normZ` лежать підряд у безперервних блоках пам'яті. Це дозволяє векторному завантажувачу завантажувати по 8 або 16 чисел `float` в один SIMD-регістр (`__m256` або `__m512`) за один тактовий цикл.

### 11. Алгоритм глобального освітлення Radiosity (Метод випромінювальності)

У системному моделюванні замкнених приміщень та архітектурній світлотехніці ламбертове розсіювання є основою методу **Radiosity** (випромінювальності).

На відміну от методів трасування променів, які рахують світло окремо для кожного пікселя екрана, метод Radiosity розбиває всі поверхні сцени на `N` плоских матерчатих елементів (патчів) `A_i`. Світимість (випромінюваність) кожного елемента `M_i` (Вт/м²) вважається постійною та строго ламбертовою по всій його площі.

Рівняння балансу енергії для `i`-го елемента описується системою лінійних алгебраїчних рівнянь:

```
M_i = M_emit,i + ρ_i · ∑_(j=1)ᴺ F_ij · M_j
```

де:
- `M_emit,i` — власна світимість елемента (якщо це лампа чи плафон);
- `ρ_i` — дифузне альбедо елемента;
- `F_ij` — геометричний конфігураційний фактор між елементами `A_i` та `A_j`.

У матричній формі ця система набирає вигляду:

```
[ I - R · F ] · M = M_emit
```

де `I` — одинична матриця `N × N`, `R = diag(ρ₁, ρ₂, ..., ρ_N)` — діагональна матриця альбедо, а `F` — матриця конфігураційних факторів.

Оскільки всі поверхні вважаються ламбертовими, геометрія перенесення світла між елементами `F_ij` описується точним інтегралом взаємної видимості:

```
F_ij = (1 / A_i) · ∬_(A_i) ∬_(A_j) (cos θ_i · cos θ_j / (π · r²)) · V_ij · dA_i dA_j
```

### 12. Фізична валідація та тести енергозбереження Шейдерів

Для гарантії того, що реалізація ламбертової BRDF у шейдерному рушії не порушує фундаментальні закони фізики, у розробці фізично точних графічних двигунів обов'язково впроваджують автоматизоване тестування (Unit Tests).

Головними фізичними інваріантами ламбертового розсіювача є:

1. **Невід'ємність (Positivity):** Для будь-яких напрямків `f_r(ω_i, ω_o) ≥ 0`.
2. **Взаємність Гельмгольца (Helmholtz Reciprocity):** Значення BRDF не змінюється при обміні місцями напрямку падіння та напрямку спостереження:
   ```
   f_r(ω_i, ω_o) = f_r(ω_o, ω_i)
   ```
   Для ламбертового матеріалу `f_r = ρ / π = const`, тому симетрія Гельмгольца виконується тотожно.
3. **Закон збереження енергії (Energy Conservation):** Сумарна відбита енергія не може перевищувати падаючу енергію:
   ```
   E_out = ∫_S²⁺ f_r · max(0, N̂ · ω_i) dω_i = ρ ≤ 1.0
   ```

### 13. Спектральний рендеринг проти триколірного простору (Spectral vs RGB Rendering)

У науковому моделюванні оптичних приладів та спецефектах вищої якості обчислення ламбертового розсіювання у триколірному просторі RGB замінюють **спектральним рендерингом** (Spectral Rendering).

Трикомпонентна модель RGB спирається на три довільно обрані довжини хвиль (червону, зелену та синю), що описують зір людини, але не передають об'єктивної фізики випромінювання. У спектральному рендерері діапазон видимого світла від 380 до 780 нм розбивається на `N` спектральних інтервалів (наприклад, 16, 32 або 64 канали з кроком 10 або 5 нм).

Коефіцієнт ламбертового відбиття (альбедо) задається як спектральна функція `ρ(λ)`:

```
f_r(λ) = ρ(λ) / π
```

На кожному кроці обчислення трасування шляхів для обраної довжини хвилі `λ_k` підсумковий відбитий потік обчислюється незалежно:

```
L_out(λ_k) = (ρ(λ_k) / π) · L_in(λ_k) · max(0, N̂ · L̂)
```

Переваги спектрального ламбертового рендерингу:
1. **Точне врахування метамеризму:** Матеріали з різними спектрами відбиття `ρ₁(λ)` та `ρ₂(λ)`, які здаються однаковими під сонячним світлом, показують відмінні відтінки під натрієвою чи світлодіодною лампою.
2. **Відсутність зсуву колірності (Color Bleeding Error):** При багаторазових дифузних відбитках у замкненому просторі (наприклад, червона підлога освітлює білу стіну) RGB-модель завищує або занижує насиченість кольору через нелінійне змішування широких смуг чутливості. Спектральне інтегрування дає точний фізичний результат.
3. **Фізична конверсія у тристимульні значення CIE XYZ:** Після обчислення спектрального спектра `L_out(λ)` перехід до екранних координат здійснюється за допомогою стандартних функцій колірного відповідності `x̄(λ)`, `ȳ(λ)`, `z̄(λ)` Міжнародної комісії з освітлення (CIE 1931):

```
X = ∫ L_out(λ) · x̄(λ) dλ
Y = ∫ L_out(λ) · ȳ(λ) dλ
Z = ∫ L_out(λ) · z̄(λ) dλ
```

Після цього матричним перетворенням `XYZ → Linear RGB` колір переводиться у лінійний простір монітора. Цей підхід забезпечує найвищий рівень фізичної правдивості у кінематографічному рендерингу та проектуванні світлотехніки. 

Застосування спектрального підходу виключає виникнення штучних колірних зсувів у розрахунках багаторазового перевідбиття між кольоровими ламбертовими поверхнями. Сучасні фізичні двигуни рендерингу (наприклад, Mitsuba 3, LuxCoreRender та Cycles) використовують цей спектральний підхід як основний обчислювальний режим для отримання еталонних зображень. Завдяки цьому результати рендерингу тотожно збігаються з фізичними вимірюваннями реальних макетів у лабораторних гоніофотометричних випробуваннях за міжнародними стандартами CIE 1931 та ISO 11664, що повністю гарантує найвищу точність і достовірність оптичної симуляції.

### 6. Типові пастки реалізації дифузного розсіювання

1. **Забутий коефіцієнт `1 / π`:** Поширеною помилкою початківців є використання виразу `I = I_light · ρ · (N · L)` без ділення на `π`. Це порушує фундаментальний закон збереження енергії: під час інтегрування відбитого потоку по півсфері виходить значення `2 · ρ`, тобто поверхня повертає вдвічі більше енергії, ніж отримала на свій вхід.
2. **Відсутність відтинання від'ємних значень (`max(0, N · L)`):** Якщо скалярний добуток `(N · L)` стає від'ємним, поверхня починає «відбивати від'ємне світло», що створює чорні плями й артефакти рендерингу на зворотних гранях 3D-моделей.
3. **Плутанина між рівномірним та косинусним семплінгом:** Під час трасування шляхів генерація рівномірного півсферичного напрямку вимагає додаткового зважування на `cos θ` в розрахунку ваги фотона. Використання косинусно-зваженого семплінгу (`r = √u1`) усуває потребу ділення на ймовірність `pdf = cos θ / π`, оскільки вибірка вже геометрічно адаптована під розподіл Ламберта.
4. **Гама-корекція та лінійний колірний простір:** Обчислення ламбертового шейдингу завжди мають виконуватися у **лінійному колірному просторі** (Linear RGB). Якщо вхідні текстури альбедо подані у просторі sRGB (що властиво стандартним картинкам JPEG/PNG), їх необхідно спочатку дегаммувати (`Color_linear = Color_sRGB ^ 2.2`), виконати ламбертів розрахунок, а перед виведенням на екран знову застосувати гама-корекцію (`Color_screen = Color_linear ^ (1/2.2)`). Нехтування цією процедурою призводить до неприродного «пережареного» вигляду тіней та втрати дифузних градієнтів.
