# 📋 Інтерфейс та специфікація модуля моделювання хвильової дифракції

Цей документ визначає повну програмну специфікацію та програмований інтерфейс (API) системної бібліотеки `libdiffract`, розробленої для чисельного розрахунку хвильових дифракційних полів у близькому (дифракція Френеля) та далекому (дифракція Фраунгофера) полях поширення світла. Бібліотека розроблена для застосування у фотолітографічних симуляторах, оптичних САПР, розрахунках діаграм спрямованості антени та віртуальних оптичних лабораторіях.

Специфікація описує концептуальну модель обчислювального двигуна, організацію пам'яті та кеш-оптимізацію буферів, структуру C/C++ ABI-інтерфейсу, контракт потокової безпеки, повний реєстр функцій, детальні описи структур даних, варіантів конфігурації, розширені таблиці статусів помилок, фізичні та чисельні обмеження.

---

### 1. Модель пам'яті, архітектура двигуна та одиниці вимірювання

Обчислювальний двигун `libdiffract` побудовано на принципі розділення опису геометричних сценаріїв (апертури, хвильового джерела, середовища) та виконання обчислень над матрицями комплексних амплітуд. 

Всі виклики обчислень здійснюються через ізольований об'єкт-дескриптор `diff_context_handle_t`. Контекст зберігає:
- Вирівняні масиви комплексних амплітуд входів та виходів у форматі `ComplexDouble` (з вирівнюванням за межею 64 байт для підтримки векторних інструкцій AVX-512 / ARM Neon);
- Кранчовані таблиці фазових множників Френеля та Фраунгофера;
- Попередньо скопійовані планувальники Швидкого Перетворення Фур'є (FFT execution plans);
- Тимчасові робочі буфери для виконання нульового доповнення (zero-padding) та двовимірної фільтрації.

#### Фізичні одиниці та системи координат

Усі фізичні параметри, що передаються в API або повертаються ним, використовують стандартну міжнародну систему одиниць СІ:
- Довжина хвилі світла `wavelength` — у метрах (`м`). Типовий діапазон: від екстремального ультрафіолету `13.5 нм` (`1.35e-8 м`) до мікрохвиль `10 мм` (`1.0e-2 м`).
- Поперечні координати апертури `(x', y')` та екрана `(x, y)` — у метрах (`м`).
- Відстань поширення `z` — у метрах (`м`).
- Напруженість електричного поля `E` — у вольтах на метр (`В/м`).
- Інтенсивність світла `I` — у ватах на квадратний метр (`Вт/м²`).
- Просторові кути `θ` — у радіанах.

Координатна система є правою декартовою системою:
- Площина апертури розташована при `z = 0`, із центром в точці `(0, 0, 0)`.
- Оптична вісь `Z` збігається з напрямком поширення первинного хвильового фронту.
- Площина спостереження (екран) розташована паралельно площині апертури на відстані `z > 0`.

### 2. Детальний опис структур даних та типів

#### Конфігурація джерела світла (`diff_source_config_t`)

Дана структура визначає електромагнітні властивості первинного випромінювання та оптичні характеристики проміжного середовища.

:::tabs
```c
typedef struct {
    double wavelength_m;      /* Довжина хвилі у вакуумі (м). Має бути строго > 0.0 */
    double refractive_index;  /* Показник заломлення середовища n (n >= 1.0, за замовчуванням 1.0) */
    double source_amplitude;  /* Пікова амплітуда поля E₀ (В/м, за замовчуванням 1.0) */
    double initial_phase_rad; /* Початкова фаза первинного фронту у радіанах (за замовчуванням 0.0) */
} diff_source_config_t;
```
```cpp
struct diff_source_config_t {
    double wavelength_m{532.0e-9};   // Довжина хвилі у вакуумі (м)
    double refractive_index{1.0};    // Показник заломлення середовища n
    double source_amplitude{1.0};    // Пікова амплітуда поля E₀ (В/м)
    double initial_phase_rad{0.0};   // Початкова фаза у радіанах
};
```
:::

*Поля структури:*
- `wavelength_m`: Довжина хвилі монохроматичного лазерного чи світлового джерела. Визначає хвильове число `k = 2π · n / λ`.
- `refractive_index`: Абсолютний показник заломлення середовища, у якому поширюється хвиля (наприклад, `1.0` для вакууму/повітря, `1.33` для води, `1.52` для оптичного скла).
- `source_amplitude`: Вхідна амплітуда електричного поля. Визначає нормування підсумкового розподілу інтенсивності `I₀ = 0.5 · ε₀ · c · n · E₀²`.
- `initial_phase_rad`: Початковий фазовий зсув на апертурі, що дозволяє моделювати фазово-зсунуті елементи або когерентні джерела зі зсувом фаз.

#### Перелічуваний тип апертури (`diff_aperture_type_t`)

:::tabs


```c
} diff_grid_config_t;
```

### 3. Повний реєстр функціональних викликів API

Нижче детально висвітлено специфікації системних викликів бібліотеки з описом початкових та кінцевих умов виконання.

#### Створення та знищення контексту

##### `diff_create_context`
:::tabs
```c
diff_status_t diff_create_context(
    const diff_source_config_t* source_cfg,
    const diff_grid_config_t* grid_cfg,
    diff_context_handle_t* out_handle
);
```
```cpp
[[nodiscard]] diff_status_t diff_create_context(
    const diff_source_config_t* source_cfg,
    const diff_grid_config_t* grid_cfg,
    diff_context_handle_t* out_handle
);
```
:::

Створює внутрішній обчислювальний контекст, здійснює перевірку некоректних фізичних значень (таких як нульова довжина хвилі, від'ємна відстань чи нульовий розмір сітки), виділяє пам'ять під комплекснозначні масиви полів та ініціалізує планувальник FFT. Якщо операція завершилася успішно, функція повертає статус `DIFF_SUCCESS` та записує валідний вказівник у `out_handle`.

##### `diff_destroy_context`
:::tabs
```c
diff_status_t diff_destroy_context(diff_context_handle_t handle);
```
```cpp
diff_status_t diff_destroy_context(diff_context_handle_t handle);
```
:::

Звільняє всі виділені динамічні буфери пам'яті, знищує створені планувальники FFT та анулює дескриптор. Передача недійсного чи вже звільненого дескриптора повертає статус помилки `DIFF_ERR_INVALID_HANDLE`.

---

#### Налаштування апертури та обчислення полів

##### `diff_set_aperture_slit`
:::tabs
```c
diff_status_t diff_set_aperture_slit(
    diff_context_handle_t handle,
    double slit_width_a
);
```
```cpp
diff_status_t diff_set_aperture_slit(
    diff_context_handle_t handle,
    double slit_width_a
);
```
:::

Задає одновимірну чи двовимірну апертуру у вигляді прямокутної щілини шириною `slit_width_a` метрів. Значення `slit_width_a` не повинно перевищувати фізичний розмір вікна сітки `aperture_size_x`.

##### `diff_set_aperture_circular`
:::tabs
```c
diff_status_t diff_set_aperture_circular(
    diff_context_handle_t handle,
    double diameter_D
);
```
```cpp
diff_status_t diff_set_aperture_circular(
    diff_context_handle_t handle,
    double diameter_D
);
```
:::

Задає кругову апертуру діаметром `diameter_D` метрів. Усі вузли у радіусі `ρ <= D/2` від центру системи отримають коефіцієнт пропускання `1.0`, а за його межами — `0.0`.

##### `diff_compute_field`
:::tabs
```c
diff_status_t diff_compute_field(
    diff_context_handle_t handle,
    diff_regime_t regime,
    double distance_z,
    double* out_intensity_array,
    double* out_phase_array
);
```
```cpp
diff_status_t diff_compute_field(
    diff_context_handle_t handle,
    diff_regime_t regime,
    double distance_z,
    double* out_intensity_array,
    double* out_phase_array
);
```
:::

Виконує повний розрахунок дифракційного поля у площині екрана спостереження на відстані `distance_z`. Результат записується у вихідний масив `out_intensity_array` (квадрат модуля амплітуди `|E|²` у `Вт/м²`). За наявності не-NULL вказівника `out_phase_array` записується розподіл фази в радіанах `[-π, +π]`.

### 4. Таблиця кодів помилок та статуси

Усі виклики API повертають код статусу `diff_status_t` зі значеннями:

| Код константи | Числове значення | Опис та причина виникнення | Рекомендований спосіб усунення |
| :--- | :---: | :--- | :--- |
| `DIFF_SUCCESS` | `0` | Операцію виконано успішно. | Продовжувати виконання програми. |
| `DIFF_ERR_INVALID_HANDLE` | `-1` | Передано недійсний або нульовий дескриптор `handle`. | Перевірити результати створення контексту `diff_create_context`. |
| `DIFF_ERR_INVALID_PARAM` | `-2` | Від'ємна або нульова довжина хвилі, відстань `z <= 0` або відсутні параметри. | Перевірити фізичні межі вхідних параметрів СІ. |
| `DIFF_ERR_OUT_OF_MEMORY` | `-3` | Не вдалося виділити буфер пам'яті під розрахункову сітку. | Зменшити розмір обчислювальної сітки `grid_nx * grid_ny`. |
| `DIFF_ERR_NYQUIST_VIOLATION` | `-4` | Крок сітки недостатній для обчислення осциляцій Френеля (порушення межі Найквіста). | Збільшити кількість вузлів `grid_nx` або збільшити відстань `z`. |
| `DIFF_ERR_NOT_SUPPORTED` | `-5` | Обраний режим обчислення не підтримується для даної геометрії. | Змінити режим розрахунку `diff_regime_t` на сумісний. |

### 5. Таблиця граничних параметрів та розрахункових обмежень

Для забезпечення точності чисельного інтегрування та уникнення чисельного аліасингу бібліотека накладає такі фізичні та обчислювальні межі:

| Параметр | Мінімальне значення | Максимальне значення | Фізична причина або наслідки порушення меж |
| :--- | :---: | :---: | :--- |
| Довжина хвилі `λ` | `10 нм` (EUV) | `10 мм` (мікрохвилі) | Оптимальний діапазон: `400–700 нм` (видиме світло). |
| Ширина щілини `a` | `0.1 · λ` | `100 мм` | При `a < λ` дифракційні максимуми вищих порядків зникають. |
| Відстань `z` | `5 · λ` | `1000 м` | Для режиму Фраунгофера вимагається `z ≫ a² / λ`. |
| Розмір сітки `grid_nx` | `64` | `8192` | Для найшвидшого обчислення FFT бажано використовувати степені `2ⁿ`. |
| Число Френеля `N_F` | `0.001` (Фраунгофер) | `50.0` (Френель) | При `N_F > 50` рекомендується режим точного інтегрування `EXACT_RS`. |

### 6. Приклад виклику API мовою C та C++

Подані приклади ілюструють повний цикл створення контексту, налаштування кругової апертури діаметром `0.1 мм`, виконання розрахунку далекої дифракції Фраунгофера для зеленого лазера `λ = 532 нм` та безаварійного звільнення обчислювальних ресурсів.

:::tabs
```c
/* C Usage Example */
#include <stdio.h>
#include <stdlib.h>
#include "diffract_api.h"

int main(void) {
    diff_source_config_t source = {
        .wavelength_m = 532.0e-9,
        .refractive_index = 1.0,
        .source_amplitude = 1.0,
        .initial_phase_rad = 0.0
    };

    diff_grid_config_t grid = {
        .aperture_size_x = 1.0e-3,
        .aperture_size_y = 1.0e-3,
        .grid_nx = 1024,
        .grid_ny = 1,
        .screen_size_x = 0.05,
        .screen_size_y = 0.05,
        .enable_zero_padding = true
    };

    diff_context_handle_t ctx = NULL;
    if (diff_create_context(&source, &grid, &ctx) != DIFF_SUCCESS) {
        fprintf(stderr, "Помилка створення контексту!\n");
        return 1;
    }

    diff_set_aperture_slit(ctx, 0.1e-3);

    double* intensity = (double*)malloc(sizeof(double) * grid.grid_nx);
    if (diff_compute_field(ctx, DIFF_REGIME_FRAUNHOFER, 1.5, intensity, NULL) == DIFF_SUCCESS) {
        printf("Центральна інтенсивність: %.4e Вт/м²\n", intensity[grid.grid_nx / 2]);
    }

    free(intensity);
    diff_destroy_context(ctx);
    return 0;
}
```
```cpp
// C++ Usage Example
#include <iostream>
#include <vector>
#include "diffract_api.h"

int main() {
    diff_source_config_t source{
        .wavelength_m = 532.0e-9, // Зелений лазер 532 нм
        .refractive_index = 1.0,
        .source_amplitude = 1.0
    };

    diff_grid_config_t grid{
        .aperture_size_x = 1.0e-3,
        .aperture_size_y = 1.0e-3,
        .grid_nx = 1024,
        .grid_ny = 1,
        .screen_size_x = 0.05,
        .screen_size_y = 0.05
    };

    diff_context_handle_t ctx = nullptr;
    if (diff_create_context(&source, &grid, &ctx) != DIFF_SUCCESS) {
        std::cerr << "Помилка створення контексту!\n";
        return 1;
    }

    diff_set_aperture_slit(ctx, 0.1e-3); // Щілина 0.1 мм

    std::vector<double> intensity(grid.grid_nx);
    diff_status_t status = diff_compute_field(
        ctx,
        DIFF_REGIME_FRAUNHOFER,
        1.5, // 1.5 метра до екрана
        intensity.data(),
        nullptr
    );

    if (status == DIFF_SUCCESS) {
        std::cout << "Центральний пік інтенсивності: " << intensity[grid.grid_nx / 2] << " Вт/м²\n";
    }

    diff_destroy_context(ctx);
    return 0;
}
```

### 7. Контракт потокової безпеки та специфікація продуктивності

Багатопотокова модель обчислювального двигуна підпорядковується таким фундаментальним гарантіям:

1. **Потокова безпека (Thread Safety):** 
   - Різні екземпляри контекстів (`diff_context_handle_t`), створені у різних потоках виконання, є **повністю ізольованими** і можуть обчислюватися паралельно без жодної синхронізації чи блокувань (Zero Locking).
   - Одночасний виклик функцій обчислення над **одним і тим самим** контекстом із двох різних потоків заборонений без зовнішнього мутекса або блокування запису.
2. **Векторизація SIMD та OpenMP:**
   - Внутрішні цикли сумування інтегралів Френеля та Фраунгофера векторизовані інструкціями AVX2 / AVX-512 та розподіляються між ядрами процесора за допомогою потоків OpenMP.
   - Для максимізації швидкодії масиви даних вирівняні за межею 64 байт (`alignas(64)`), що запобігає штрафам невирівняного читання з пам'яті (unaligned memory access penalties).

### 8. Діагностика помилок та журнал налагодження

При виникненні аномальних чисельних режимів або порушенні меж Найквіста бібліотека підтримує механізм детальної діагностики. Розробник може зареєструвати функцію зворотного виклику (callback):

:::tabs
```c
typedef void (*diff_log_callback_t)(int level, const char* message);
void diff_register_log_callback(diff_log_callback_t cb);
```
```cpp
using diff_log_callback_t = std::function<void(int level, std::string_view message)>;
void diff_register_log_callback(diff_log_callback_t cb);
```
:::

Це дозволяє логувати вказівки про автоматичне розширення розрахункового вікна, оцінки чисельної точності та пропозиції щодо переходу від Френеля до Фраунгофера.
