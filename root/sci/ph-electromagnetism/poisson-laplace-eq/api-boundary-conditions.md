# 📋 Інтерфейс та специфікація крайових задач електростатики

Цей документ являє собою формальний довідник специфікації та системний інтерфейс (англ. *API contract*) для програмних модулів розв'язання еліптичних крайових задач електростатики, що описуються диференціальними рівняннями Пуассона та Лапласа.

Довідник визначає структурні типи даних, контракти специфікації крайових умов, конфігурацію обчислювальних сіток, параметри алгоритмів релаксації, метрики збіжності, коди помилок та інтерфейсні сигнатури функцій для реалізації чисельних розв'язувачів у промислових пакетних середовищах та САПР.

## Математичне обґрунтування та класифікація типів крайових умов

Рівняння Пуассона `∇²φ = −ρ / ε₀` у замкненій області `Ω` належить до типу еліптичних диференціальних рівнянь у частинних похідних. Для того щоб крайова задача мала єдиний стійкий розв'язок (згідно з критерієм коректності за Адамаром), на зовнішніх граничних поверхнях `∂Ω` мусять бути строго задані крайові умови. Залежно від фізичної природи межі та специфікації вихідних даних у програмному інтерфейсі використовують п'ять базових класів крайових умов.

### 1. Умова Діріхле (Перший рід)

Крайова умова першого роду (умова Діріхле) встановлює фіксований розподіл потенціалу безпосередньо на граничній поверхні `Γ_D`:

```
φ(r) = V_zero(r),   r ∈ Γ_D
```

Фізично межа Діріхле описує контакт із металевими електродами, заземленими металевими корпусами приладів, шинами живлення або екранними поверхнями, потенціал яких підтримується постійним за допомогою зовнішніх джерел напруги.

З точки зору чисельної алгебри, задоволення умов Діріхле означає усунення відповідного рівняння зі спільної системи лінійних алгебраїчних рівнянь (СЛАУ). Значення потенціалу у вузлах `Γ_D` фіксуються як константи і переносяться у вектор правої частини для внутрішніх вузлів сітки. Наявність хоча б одного вузла Діріхле є необхідною умовою для забезпечення додатної визначеності матриці дискретизованого оператора Лапласа та усунення невизначеності потенціалу з точністю до довільної додатної сталої.

- **Поля специфікації API:** Скалярний потенціал `v_value` у вольтах [V].

### 2. Умова Неймана (Другий рід)

Крайова умова другого роду (умова Неймана) задає нормальну похідну потенціалу на граничній поверхні `Γ_N`:

```
∂φ / ∂n = n · ∇φ = −E_n(r) = (1 / ε) · σ(r),   r ∈ Γ_N
```

де `n` — зовнішній одиничний вектор нормалі до межі, `E_n` — нормальна складова електричного поля, `σ` — поверхнева густина електричного заряду.

Найпоширенішим частковим випадком є однорідна умова Неймана (`∂φ / ∂n = 0`), яка описує геометричні площини симетрії або ідеально ізольовані межі діелектрика, крізь які відсутній потік електричного зміщення `D_n = 0`. Силові лінії електричного поля біля межі однорідної умови Неймана є строго паралельними до граничної поверхні, а лінії рівного потенціалу (еквіпотенціалі) підходять до неї під прямим кутом `90°`.

При чисельній дискретизації за допомогою методу скінченно-різницевої сітки умова Неймана реалізується за допомогою шару фіктивних (привидних) вузлів, розташованих за межами обчислювальної області. Це дозволяє зберегти другий порядок точності апроксимації похідних `O(h²)` без спотворення симетрії п'ятидіагональної матриці.

- **Поля специфікації API:** Значення нормального градієнта `flux_value` у вольтах на метр [V/m].

### 3. Умова Робена (Третій рід / Змішана)

Крайова умова третього роду (змішана умова Робена) задає лінійну комбінацію значення потенціалу та його нормального градієнта на межі `Γ_R`:

```
a(r) · φ(r) + b(r) · (∂φ / ∂n) = c(r),   r ∈ Γ_R
```

де `a(r)`, `b(r)` та `c(r)` — задані просторові коефіцієнти специфікації.

Умова Робена застосовується при моделюванні тонких проміжних шарів діелектриків із високим опором, імпедансних граничних поверхонь, а також при формулюванні штучних асимптотичних поглинаючих умов (англ. *Radiation Boundary Conditions*) на віддалених межах обчислювальної області для моделювання відкритого нескінченного простору.

З інженерної точки зору, коефіцієнт `a(r)` характеризує власну провідність граничного шару, `b(r)` — ефективну діелектричну товщину, а `c(r)` описує еквівалентний зовнішній збуджуючий потенціал.

- **Поля специфікації API:** Коефіцієнти `alpha_coeff` (`a`), `beta_coeff` (`b`) та цільове значення `gamma_target` (`c`).

### 4. Умова незаземленого (плаваючого) провідника (Floating Conductor)

У багатьох електронних та високовольтних пристроях присутні металеві об'єкти (екрани, проміжні острівці маски, незаряджені корпуси), які не підключені до жодного джерела напруги. Потенціал поверхні такого провідника `Γ_F` є невідомим заздалегідь, але є суворо однаковим у всіх його точках завдяки високій електропровідності металу:

```
φ(r) = V_float = const,   r ∈ Γ_F
```

При цьому додатково задається сумарний вільний заряд `Q_total` на поверхні даного провідника:

```
∮_{Γ_F} ε · (∂φ / ∂n) dS = Q_total
```

Чисельна реалізація цієї умови вимагає зв'язування всіх вузлів поверхні провідника в єдину просторову супер-змінну та введення глобального інтегрального рівняння корекції потенціалу `V_float` на кожній ітерації чисельної релаксації.

- **Поля специфікації API:** Повний заряд `q_total` у кулонах [C].

### 5. Періодичні крайові умови (Periodic Boundary)

Періодичні умови зв'язують значення потенціалу та напруженості поля на двох протилежних межах `Γ_1` та `Γ_2` обчислювального блоку довжиною `L`:

```
φ(r + L) = φ(r) + ΔV,   r ∈ Γ_1
```

де `ΔV` — задана різниця потенціалів між періодичними комірками.

Ці умови є незамінними при моделюванні регулярних просторових структур: фотонно-кристалічних масивів, метаматеріалів, фазованих антенних решіток та нескінченних сіток інтегральних мікросхем. Вони дозволяють зменшити обчислювальний обсяг задачі до одного елементарного періоду структури (унітарної комірки).

- **Поля специфікації API:** Зсув потенціалу `delta_v` у вольтах [V] та вказівник на парну граничну поверхню `target_boundary_id`.

## Структурна специфікація геометрії сітки (Grid Geometry Specification)

Контракт специфікації обчислювальної сітки визначає просторову розмірність, кількість вузлів, кроки дискретизації, координати початку відліку та систему координат.

Обчислювальний модуль підтримує прямокутні регулярні та адаптивно-розтягнуті сітки у 2D та 3D просторах. Координати будь-якого вузла сітки з індексами `(i, j, k)` розраховуються за формулами:

```
x_i = origin_x + i · dx
y_j = origin_y + j · dy
z_k = origin_z + k · dz
```

де `i ∈ [0, nx - 1]`, `j ∈ [0, ny - 1]`, `k ∈ [0, nz - 1]`.

Для 2D задач розмірність `nz` приймається рівною `1`, а крок `dz` вважається нормалізованим товщинним фактором.

### Детальний опис полів конфігурації сітки

1. **`dim` (`uint32_t`):** Просторова розмірність обчислювальної задачі. Приймає значення `2` для плоских або аксіально-симетричних задач та `3` для повнооб'ємного 3D моделювання.
2. **`nx`, `ny`, `nz` (`size_t`):** Кількість вузлів дискретизації вздовж відповідних координатних осей. Допустимі значення мусять задовольняти нерівність `nx >= 3`, `ny >= 3` (і `nz >= 3` для 3D), що необхідно для формування внутрішніх і граничних вузлів.
3. **`dx`, `dy`, `dz` (`double`):** Просторові кроки сітки в метрах [m]. Усі кроки мусять бути строго додатними числами (`dx > 0.0`). Для уникнення похибок сіткової анізотропії рекомендовано підтримувати співвідношення кроків у межах `0.2 <= dx/dy <= 5.0`.
4. **`origin_x`, `origin_y`, `origin_z` (`double`):** Фізичні декартові координати початку відліку сітки (вузла `(0, 0, 0)`) у глобальній системі координат.
5. **`eps_r_default` (`double`):** Безрозмірна відносна діелектрична проникність фонового середовища за замовчуванням. Мусить бути не меншою за одиницю (`eps_r_default >= 1.0`).

### Матриця просторового розподілу діелектричної проникності

У неоднорідних середовищах (наприклад, межа розділу кремній-оксид у напівпровідниках або підкладка FR-4 у друкованих платах) діелектрична проникність змінюється від вузла до вузла. API надає додатковий масив `eps_r_array` розміром `nx * ny * nz`. При обчисленні коефіцієнтів 5-точкового шаблону для вузла `(i, j)` використовують гармонічне усереднення проникностей між сусідніми комірками:

```
ε_{i+1/2, j} = 2 · ε[i][j] · ε[i+1][j] / (ε[i][j] + ε[i+1][j])
```

Це гармонічне усереднення гарантує безумовне виконання закону збереження потоку електричного зміщення `D_n = const` на неоднорідних межах розділу діелектриків.

## Контракт конфігурації чисельного розв'язувача (Solver Configuration)

Об'єкт конфігурації чисельного розв'язувача визначає вибір алгоритму релаксації, параметри стійкості, критерії зупинки ітераційного процесу та правила векторизації обчислень.

### 1. Перелік алгоритмів розв'язання (`SolverAlgorithm`)

- **`SOLVER_JACOBI` (0):** Класичний метод простої ітерації Якобі. Потребує двох масивів потенціалу. Має повну незалежність вузлів, що робить його зручним для реалізації на графічних процесорах (GPU), але володіє найповільнішою збіжністю `O(N²)`.
- **`SOLVER_GAUSS_SEIDEL` (1):** Метод Гаусса-Зейделя з послідовним оновленням потенціалу «in-place». Збігається вдвічі швидше за метод Якобі та використовує лише один масив пам'яті. Застосовує червоно-чорне розфарбування вузлів (Red-Black Ordering) для розпаралелювання.
- **`SOLVER_SOR` (2):** Метод послідовної верхньої релаксації (Successive Over-Relaxation). Найефективніший серед простих ітераторів. Швидкість збіжності масштабується як `O(N)` при використанні оптимального параметра `ω`.
- **`SOLVER_PCG_ICCG` (3):** Предобумовлений метод сопряжених градієнтів з неповним розкладом Холецького. Найшвидший алгоритм для великих 3D розріджених систем, забезпечує збіжність за `O(√N)` ітерацій.
- **`SOLVER_MULTIGRID` (4):** Багатосітковий V-цикл (Multigrid). Досягає теоретично граничної швидкості `O(N_total)`, пригнічуючи як високочастотні, так і низькочастотні складові похибки на ієрархії сіток.

### 2. Точність збіжності (`tolerance`)

Параметр `tolerance` (`double`) визначає граничний порівняльний поріг зупинки ітерацій. Ітераційний процес припиняється, коли норма вектора похибки стає меншою за `tolerance`. Значення за замовчуванням дорівнює `1e-6`. Для високоточних розрахунків ємностей рекомендовано значення `1e-8` ... `1e-10`.

### 3. Максимальна кількість ітерацій (`max_iterations`)

Параметр `max_iterations` (`size_t`) задає верхню межу виконаних ітераційних циклів. Якщо за вказану кількість кроків задана точність `tolerance` не була досягнута, розв'язувач припиняє обчислення та повертає статус `ERR_MAX_ITER_EXCEEDED` разом із поточним досягнутим результатом. Значення за замовчуванням: `10000`.

### 4. Параметр релаксації SOR (`omega_override`)

Параметр `omega_override` (`double`) задає коефіцієнт релаксації `ω ∈ (0.0, 2.0)`. 

Якщо розробник вказує значення `0.0`, чисельний модуль автоматично розраховує спектрально-оптимальне значення параметра `ω_opt` за формулою:

```
ω_opt = 2 / (1 + sin(π / N_min))
```

де `N_min = min(nx, ny)`. Для значення `ω > 2.0` ітераційний процес стає математично нестійким і дивергує.

### 5. Метрика оцінки похибки (`residual_metric`)

Визначає формулу розрахунку норми неузгодженості системи:
- `0` (`L_INFINITY`): Оцінка за максимальним абсолютним відхиленням потенціалу між двома послідовними ітераціями серед усіх вузлів сітки: `max_{i,j} |φ^{(k+1)} − φ^{(k)}|`.
- `1` (`L2_RELATIVE`): Оцінка за відносною евклідовою нормою вектора залишку `||B − A Φ||_2 / ||B||_2`.

### 6. Налаштування обчислювального ядра, вирівнювання пам'яті та NUMA-архітектур

Для досягнення максимальної швидкості на сучасних багатопроцесорних архітектурах конфігурація розв'язувача містить параметри системного рівня:
- **`num_threads` (`uint32_t`):** Кількість паралельних потоків OpenMP. При `0` використовується автовизначення за кількістю фізичних ядер CPU.
- **`memory_alignment_bytes` (`size_t`):** Вирівнювання адреси пам'яті буферів (за замовчуванням `64` байти під інструкції AVX-512).
- **`numa_node_id` (`int32_t`):** Ідентифікатор вузла NUMA для прив'язки пам'яті до локального процесорного сокета (`first-touch policy`), що усуває міжсокетові затримки шини QPI/UPI.
- **`thread_affinity` (`bool`):** Жорстка прив'язка обчислювальних потоків до фізичних процесорних ядер (`OpenMP OMP_PROC_BIND=CLOSE`), що запобігає міграції потоків між кешами L2/L3.

## Попередня валідація конфігурації задачі (Pre-flight Task Validation)

Перед запуском обчислювального ітератора функція `poisson_api_validate_config()` виконує комплексну статичну перевірку фізичної та математичної коректності задачі:
1. **Перевірка усунення вільного зсуву Неймана:** Перевіряється наявність хоча б одного граничного вузла з умовою Діріхле чи Робена. Якщо в усій області задано виключно умови Неймана, матриця системи є виродженою (визначник дорівнює нулю), і API повертає помилку `ERR_UNBOUNDED_NEUMANN`.
2. **Валідація меж діелектричної проникності:** Перевіряється значення `eps_r >= 1.0` у всіх вузлах. Наявність від'ємних або нульових значення діелектричної проникності є фізично неприпустимою.
3. **Перевірка геометрії сітки:** Вимога `nx * ny * nz < max_allowed_memory`.

## Серіалізація та експорт обчислювальних сіток (Data Export Specification)

Для інтеграції розв'язувача у промислові САПР передбачено стандартний контракт експорту знайденого розподілу потенціалу та поля у бінарні та текстові формати.

### 1. Формат експорту HDF5 / VTK

Для 3D об'ємних полів використовується специфікація двовимірних і тривимірних прямокутних сіток VTK Structured Grid (`.vti`) або двовимірних бінарних контейнерів HDF5. Заголовний блок файлу містить метадані сітки (`GridGeometrySpec`), після чого записується суцільний масив значень потенціалів `phi` подвійної точності (`float64`) у форматі Little-Endian.

### 2. Формат JSON для конфігурації крайових умов

Передача конфігурації умов між високорівневими графічними оболонками (GUI) та обчислювальним ядром виконується у форматі JSON. Схема специфікації включає розділи `"geometry"`, `"solver_settings"` та масив `"boundaries"`. У розділі `"boundaries"` кожна межа задається об'єктом із полями `"type"`, `"value"`, `"normal_flux"` та відповідними географічними маркерами границь (наприклад, `"left"`, `"right"`, `"top"`, `"bottom"`).

## Структура результату обчислення (Execution Summary & Convergence Metrics)

Після закінчення чисельного розв'язання обчислювальний модуль повертає деталізовану структуру статистики виконання `SolverExecutionSummary`, яка містить параметри продуктивності та підсумкові інтегральні фізичні характеристики.

### Опис полів структури результату

1. **`status_code` (`uint32_t`):** Код підсумкового стану виконання (0 означає повний успіх, інші значення показують коди помилок).
2. **`iterations_spent` (`size_t`):** Фактична кількість ітерацій, витрачена розв'язувачем до зупинки.
3. **`final_residual` (`double`):** Фактично досягнуте значення норми залишку похибки на останній ітерації.
4. **`execution_time_ms` (`double`):** Чистий час роботи обчислювального ядра в мілісекундах (без урахування виділення пам'яті).
5. **`total_energy_joules` (`double`):** Повна електростатична енергія поля `W_e` в джоулях [J], обчислена об'ємним інтегруванням `W_e = ½ ∫ ε |∇φ|² dV`.
6. **`max_electric_field` (`double`):** Максимальне значення модуля напруженості електричного поля `|E_max|` у вольтах на метр [V/m], знайдене в області.

## Висновки щодо стандартів проектування інтерфейсу

Проектування системного API для фізичного чисельного моделювання вимагає дотримання таких принципових положень:
1. **Строга декомпозиція даних та обчислень:** Математична конфігурація (Boundary, Grid) мусить бути повністю відокремлена від ітераційного стану чисельного розв'язувача.
2. **Гарантія чисельної стійкості:** API повинен забезпечувати автоматичну валідацію вхідних параметрів (перевірка `eps_r >= 1.0`, `dx > 0`, наявність умов Діріхле для неусуненої симетрії Неймана) до початку важких ітераційних обчислень.
3. **Кросплатформна сумісність C/C++ ABI:** Поєднання чистої С-сумісної C-ABI структури та високорівневої C++23 RAII обгортки дозволяє інтегрувати розв'язувачі як у застарілі інженерні фортран-С ядра, так і в сучасні високорівневі C++/Qt та Python фреймворки.
