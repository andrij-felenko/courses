# 📋 Інтерфейс бібліотеки розрахунку електродинамічних сил і механічних напружень

Цей документ є повним специфікаційним довідником програмного інтерфейсу (API) бібліотеки `libwireforce`. Бібліотека призначена для проведення інженерних розрахунків електродинамічних сил взаємодії паралельних та кутових провідників, розрахунку амплітудних сил короткого замикання у трифазних шинопроводах, визначення механічних напружень вигину та перевірки міцності опорних ізоляторів згідно зі стандартами IEC 60865-1, DIN VDE 0103 та GOST 22782.

Бібліотека надає C-сумісний ABI високої продуктивності для інтеграції у системне програмне забезпечення, САПР (CAD/CAE), модулі симуляції електроенергетичних мереж та розподільчих пристроїв. Для C++ розробників надається високорівнева обгортка `wireforce.hpp` на базі стандарту C++20 з підтримкою безпечної семантики типів, обробки помилок через `std::expected` та відсутністю виділення пам'яті у динамічній купі (zero-allocation API).

---

### Архітектура та принципи проективання бібліотеки

Програмне ядро `libwireforce` розроблене з дотриманням найсуворіших вимог до надійності та детермінованості часу виконання, що застосовуються у критичному інженерному ПЗ. Основні архітектурні принципи включають:

1. **Гарантія ABI-сумісності та міжмовного зв'язування:** Усі публічні типи даних, переліки та структури мають фіксований вирівняний бінарний макет (C-compatible struct layout). Переліки явно приводяться до 32-бітного цілочисельного типу `int32_t`, що забезпечує безпроблемну інтеграцію мовами C, C++, Rust, Python (через `ctypes` або `cffi`), Go (через `cgo`) та C# (через P/Invoke). Бібліотека компілюється як у вигляді статичної бібліотеки (`.a` / `.lib`), так і у вигляді динамічної бібліотеки (`.so` / `.dll` / `.dylib`).
2. **Повна відсутність побічних ефектів та повної ізольованості пам'яті:** Жодна функція розрахункового ядра не здійснює викликів динамічного виділення пам'яті (`malloc()`, `free()`, `new`, `delete`), викликів системного введення-виведення або доступу до глобального стану. Всі обчислення є строго чистими функціями (*pure functions*), які є повністю потокобезпечними (*reentrant and thread-safe*). Це дозволяє розпаралелювати обчислення тисяч варіантів шинопроводів на багатьох ядрах процесора без використання блокувань або м'ютексів.
3. **Строга вхідна валідація та безпека обчислень:** Будь-які чисельні аргументи (струми, геометричні розміри, коефіцієнти) проходять попередню перевірку на діапазон допустимих фізичних значень. Бібліотека захищена від помилок ділення на нуль, виникнення неозначеностей `NaN` або `Inf`, а також арифметичного переповнення при зведенні великих струмів КЗ у квадрат.
4. **Кеш-локальність та оптимальність обчислень:** Всі обчислювальні структури мають розмір, що є кратним 64 байтам (розмір лінії кешу L1 сучасних процесорів x86_64 та ARM64). Це забезпечує максимальну швидкість обробки масивів даних при векторизації обчислень (AVX2 / NEON).

## 1. Загальні відомості та одиниці вимірювання

Усі обчислення у бібліотеці `libwireforce` виконуються суворо в міжнародній системі одиниць СІ. Для забезпечення найвищої обчислювальної точності та запобігання втратам значущих розрядів при розрахунках з великими струмами (десятки кілоампер) та малими геометричними відстанями (міліметри), всі плаваючі числа представлені типом подвійної точності `double` (IEEE 754 64-bit float).

### Докладний розбір вимірювальних величин

- **Початковий діючий струм короткого замикання (`I''k`):** Середньоквадратичне (діюче) значення періодичної складової струму короткого замикання у початковий момент часу. Враховує надперехідні індуктивні опори генераторів та трансформаторів мережі. Вимірюється у кілоамперах (кА).
- **Ударний струм короткого замикання (`i_th`):** Найбільше можливе миттєве значення струму короткого замикання з урахуванням згасаючої аперіодичної складової. Визначає максимальний пік магнітного поля та амплітуду динамічного удару на шини.
- **Ударний коефіцієнт (`k_th`):** Безрозмірний коефіцієнт, що характеризує відношення пікового значення струму до його амплітудного періодичного значення. Залежить від співвідношення активного опору `R` та реактивного опору `X` short-circuit кола.
- **Геометрична відстань між осями (`a`):** Найкоротша відстань між геометричними центрами мас перерізів паралельних провідників. Для трьох фаз L1, L2, L3 передбачається симетричне пласке розміщення з однаковим кроком `a`.
- **Довжина прольоту (`L_span`):** Відстань між центрами двох сусідніх опорних ізоляторів, на які спирається шина. Визначає згинний момент та власну механічну частоту вигину.
- **Момент опору перерізу (`W_z`):** Геометрична характеристика поперечного перерізу провідника, що характеризує його опір вигину відносно нейтральної осі. Для прямокутної шини товщиною `b` і висотою `h` дорівнює `W_z = b · h² / 6`.
- **Умовна межа плинності (`σ_0.2`):** Механічна характеристика матеріалу провідника, що відповідає напруженню, при якому залишкова пластична деформація досягає 0.2%. За стандартом IEC 60865-1 допустиме розрахункове напруження обмежене значенням `0.8 · σ_0.2`.

## 2. C API: Переліки та структури даних

Заголовочний файл: `libwireforce/wireforce.h`

### 2.1. Коди статусів та помилок (`wf_status_t`)

Кожна функція C API повертає цілочисельний код статусу `wf_status_t`. Від'ємні значення відповідають помилкам валідації або порушенням умов міцності, тоді як значення `0` (`WF_SUCCESS`) свідчить про успішне виконання обчислень.

```c
typedef enum wf_status {
    WF_SUCCESS                  =  0,  /* Операція виконана успішно */
    WF_ERR_NULL_POINTER         = -1,  /* Передано вказівник NULL */
    WF_ERR_INVALID_CURRENT      = -2,  /* Некоректне значення струму (<= 0) */
    WF_ERR_INVALID_DISTANCE     = -3,  /* Некоректна відстань між осями (<= 0) */
    WF_ERR_INVALID_SPAN         = -4,  /* Довжина прольоту <= 0 */
    WF_ERR_INVALID_GEOMETRY     = -5,  /* Від'ємні або нульові розміри шини */
    WF_ERR_INVALID_SHOCK_FACTOR = -6,  /* Ударний коефіцієнт k_th поза межами [1.0, 2.0] */
    WF_ERR_STRESS_EXCEEDED      = -10, /* Механічне напруження перевищує межу плинності */
    WF_ERR_INSULATOR_OVERLOAD   = -11  /* Навантаження на ізолятор перевищує допустиме */
} wf_status_t;
```

#### Докладний опис кожного коду помилки

- `WF_SUCCESS (0)`: Виклики функцій завершилися успішно, вхідні дані є коректними, а розраховані напруження та навантаження не перевищують допустимих норм.
- `WF_ERR_NULL_POINTER (-1)`: У функцію передано недійсний вказівник `NULL` замість адреси структури даних або вихідної змінної.
- `WF_ERR_INVALID_CURRENT (-2)`: Значення струму короткого замикання `I''k` є меншим або дорівнює нулю, або перевищує максимально припустиме фізичне значення 500 кА.
- `WF_ERR_INVALID_DISTANCE (-3)`: Відстань між осями фаз `a` є меншою або дорівнює нулю, що відповідає геометричному самоперетину провідників.
- `WF_ERR_INVALID_SPAN (-4)`: Довжина прольоту між ізоляторами `L_span` є меншою за допустиму технологічну межу 5 см або перевищує 20 метрів.
- `WF_ERR_INVALID_GEOMETRY (-5)`: Розміри поперечного перерізу шини (товщина `b` або висота `h`) є нульовими або від'ємними.
- `WF_ERR_INVALID_SHOCK_FACTOR (-6)`: Ударний коефіцієнт `k_th` лежить поза нормативним діапазоном `[1.00, 2.00]`.
- `WF_ERR_STRESS_EXCEEDED (-10)`: Обчислення виконано, але розраховане механічне напруження вигину `σ_max` перевищує допустиму межу `0.8 · σ_0.2`.
- `WF_ERR_INSULATOR_OVERLOAD (-11)`: Обчислення виконано, але динамічне навантаження на ізолятор перевищує його максимальне руйнівне зусилля.

### 2.6. Структура повних результатів аналізу (`wf_calc_result_t`)

У цю структуру записаються всі проміжні та кінцеві розрахункові величини.

```c
typedef struct wf_calc_result {
    double peak_current_ka;      /* Амплітуда ударного струму i_th, кА */
    double force_per_meter_kn_m; /* Максимальна динамічна сила на метр F_din, кН/м */
    double total_span_force_kn;  /* Сумарна динамічна сила на весь проліт, кН */
    double bending_moment_nm;    /* Максимальний розрахунковий згинний момент, Н·м */
    double bending_stress_mpa;   /* Виникаюче механічне напруження вигину σ, МПа */
    double insulator_load_kn;    /* Реактивне навантаження на опорний ізолятор, кН */
    double actual_safety_factor; /* Фактичний обрахований коефіцієнт запасу */
    bool is_stress_ok;           /* true = напруження шини не перевищує допустимого */
    bool is_insulator_ok;        /* true = ізолятор витримує механічне навантаження */
    bool is_overall_safe;        /* true = конструкція повністю відповідає нормативам */
} wf_calc_result_t;
```

## 3. C API: Опис функцій та специфікація викликів

### 3.1. Функція `wf_calculate_parallel_force`

Обчислює електродинамічну силу взаємодії двох паралельних провідників за класичною формулою Ампера.

```c
wf_status_t wf_calculate_parallel_force(
    double i1_amp,
    double i2_amp,
    double distance_m,
    double length_m,
    double* force_n
);
```

- **Параметри:**
  - `i1_amp`: Струм першого провідника в амперах. Може бути додатним або від'ємним.
  - `i2_amp`: Струм другого провідника в амперах.
  - `distance_m`: Відстань між осями провідників у метрах. Мусить бути `> 0`.
  - `length_m`: Довжина ділянки взаємодії у метрах. Мусить бути `> 0`.
  - `force_n`: Вихідний вказівник на змінну типу `double`. При поверненні містить силу в ньютонах. Додатне значення означає притягання (струми одного напрямку), від'ємне — відштовхування.
- **Повертає:** `WF_SUCCESS` у разі успіху; `WF_ERR_NULL_POINTER`, якщо `force_n == NULL`; `WF_ERR_INVALID_DISTANCE`, якщо `distance_m <= 0`.

### 3.2. Функція `wf_calculate_busbar_system`

Виконує комплексний аналіз динамічної стійкості трифазної шинної системи під час короткого замикання відповідно до стандарту IEC 60865-1.

```c
wf_status_t wf_calculate_busbar_system(
    const wf_wire_geometry_t* geo,
    const wf_sc_params_t* sc,
    const wf_material_limits_t* mat,
    wf_calc_result_t* res
);
```

- **Параметри:**
  - `geo`: Вказівник на структуру геометрії провідників.
  - `sc`: Вказівник на параметри короткого замикання.
  - `mat`: Вказівник на фізичні межі матеріалу та ізоляторів.
  - `res`: Вихідна структура для запису повних результатів.
- **Алгоритм роботи:**
  1. Перевіряє всі вхідні структури на `NULL`.
  2. Валідує коректність геометрії та струмів.
  3. Обчислює ударний струм `i_th = √2 · k_th · I''k`.
  4. Обчислює геометричний коефіцієнт `k_ij` для прямокутної шини.
  5. Розраховує питому динамічну силу `F_din` та згинний момент `M_max`.
  6. Обчислює розрахункове напруження вигину `σ = M_max / W_z` та порівнює його з `0.8 · σ_0.2`.
  7. Обчислює навантаження на ізолятор з урахуванням динамічного коефіцієнта перевантаження `1.1`.
  8. Заповнює вихідну структуру `res` і повертає статус.

### 3.3. Функція `wf_status_to_string`

Повертає текстовий рядок з розшифровкою коду статусу для логування та відображення у користувацькому інтерфейсі.

```c
const char* wf_status_to_string(wf_status_t status);
```

## 5. Докладні правила валідації параметрів та обробки помилок

Під час виклику функцій аналітичного ядра кожна вхідна величина перевіряється на відповідність допустимому діапазону. Перевірка здійснюється у суворо визначеному порядку:

1. **Перевірка вказівників:** Якщо будь-який із параметрів-вказівників має значення `NULL`, функція негайно припиняє виконання та повертає статус `WF_ERR_NULL_POINTER`.
2. **Перевірка геометрії:**
   - Якщо `distance_m <= 0.0` або `distance_m > 10.0`, повертається `WF_ERR_INVALID_DISTANCE`.
   - Якщо `span_length_m <= 0.0` або `span_length_m > 20.0`, повертається `WF_ERR_INVALID_SPAN`.
   - Якщо `bus_width_m <= 0.0` або `bus_height_m <= 0.0`, повертається `WF_ERR_INVALID_GEOMETRY`.
3. **Перевірка параметрів струму:**
   - Якщо `initial_ik_ka <= 0.0` або `initial_ik_ka > 500.0`, повертається `WF_ERR_INVALID_CURRENT`.
   - Якщо `shock_factor < 1.0` або `shock_factor > 2.0`, повертається `WF_ERR_INVALID_SHOCK_FACTOR`.

Якщо всі вхідні параметри є коректними, але розраховане механічне напруження вигину перевищує межу плинності `σ_0.2`, розрахунок заповнює структуру `res` реальними чисельними значеннями, але функція повертає код `WF_ERR_STRESS_EXCEEDED`, а прапорець `is_overall_safe` встановлюється у значення `false`. Аналогічно, при перевищенні зусилля на ізолятор повертається `WF_ERR_INSULATOR_OVERLOAD`.

## 6. C++20 Wrapper API (`wireforce.hpp`)

Для розробників мовою C++ бібліотека надає заголовочний файл `wireforce.hpp`, який повертає об'єкти `std::expected<T, Error>` замість сирих кодів помилок C. Це дозволяє писати виразний та безпечний код у сучасному стилі.

```cpp
#ifndef WIREFORCE_HPP
#define WIREFORCE_HPP

#include <expected>
#include <string_view>
#include <span>
#include "wireforce.h"

namespace wireforce {

enum class Error : int32_t {
    NullPointer         = WF_ERR_NULL_POINTER,
    InvalidCurrent      = WF_ERR_INVALID_CURRENT,
    InvalidDistance     = WF_ERR_INVALID_DISTANCE,
    InvalidSpan         = WF_ERR_INVALID_SPAN,
    InvalidGeometry     = WF_ERR_INVALID_GEOMETRY,
    InvalidShockFactor  = WF_ERR_INVALID_SHOCK_FACTOR,
    StressExceeded      = WF_ERR_STRESS_EXCEEDED,
    InsulatorOverload   = WF_ERR_INSULATOR_OVERLOAD
};

[[nodiscard]] constexpr std::string_view format_error(Error err) noexcept {
    return wf_status_to_string(static_cast<wf_status_t>(err));
}

class ForceCalculator {
public:
    [[nodiscard]] static std::expected<double, Error>
    parallel_wire_force(double i1_amp, double i2_amp, 
                        double distance_m, double length_m) noexcept 
    {
        double force = 0.0;
        const auto status = wf_calculate_parallel_force(
            i1_amp, i2_amp, distance_m, length_m, &force
        );
        if (status == WF_SUCCESS) {
            return force;
        }
        return std::unexpected(static_cast<Error>(status));
    }

    [[nodiscard]] static std::expected<wf_calc_result_t, Error>
    analyze_busbar(const wf_wire_geometry_t& geo,
                   const wf_sc_params_t& sc,
                   const wf_material_limits_t& mat) noexcept 
    {
        wf_calc_result_t result{};
        const auto status = wf_calculate_busbar_system(&geo, &sc, &mat, &result);
        if (status == WF_SUCCESS) {
            return result;
        }
        return std::unexpected(static_cast<Error>(status));
    }
};

} // namespace wireforce

#endif // WIREFORCE_HPP
```

## 7. Програмна інтеграція у САПР та інженерні обчислювальні комплекси

Розглянемо практичну архітектуру вбудовування розрахункового ядра `libwireforce` у тривимірні САПР (CAD) та системи автоматизованого проективання розподільчих пристроїв.

При виклику з плагіна CAD (наприклад, SolidWorks API або AutoCAD ObjectARX):
1. САПР передає 3D-координати осей фазних шин та точок розташування ізоляторів.
2. Проміжний адаптер перераховує векторні відстані у геометричний крок `a` та довжину прольоту `L_span`.
3. Викликається функція `wf_calculate_busbar_system()`.
4. Результати аналізу повертаються в CAD-систему: у разі перевищення напруження шини або зусилля на ізолятор підсвічуються червоним кольором на 3D-моделі щита.

## 8. Потокобезпека, паралельні обчислення та векторизація SIMD

При обробці великих тривимірних систем із сотнями шинних сегментів критично важливою є продуктивність обчислень. Жодна функція бібліотеки `libwireforce` не містить статичних або глобальних змінних, не використовує глобальний лок та не здійснює виділень у купі.

Висока продуктивність досягається також завдяки сумісності векторних даних із SIMD-інструкціями сучасних процесорів (AVX2 / AVX-512 / ARM NEON). Оскільки структура `wf_wire_geometry_t` упакована з послідовним вирівнюванням полів `double`, компилятор може завантажувати параметри чотирьох шинопроводів в один 256-бітний SIMD-реєстр YMM і обчислювати ударні сили `f_din` паралельно за один такт процесора.

Завдяки цьому для масового розрахунку варіантів шинопроводів можна використовувати паралельні цикли OpenMP або C++20 `std::execution::par`:

```cpp
std::vector<wf_wire_geometry_t> geometries = load_geometries();
std::vector<wf_calc_result_t> results(geometries.size());

std::transform(std::execution::par, geometries.begin(), geometries.end(), results.begin(),
    [&sc, &mat](const wf_wire_geometry_t& geo) {
        return wireforce::ForceCalculator::analyze_busbar(geo, sc, mat).value_or(wf_calc_result_t{});
    }
);
```

Такий підхід дозволяє обробляти понад 1,000,000 конфігурацій шинопроводів за секунду на сучасному багатоядерному процесорі.

## 9. Інтеграційні адаптери для мов високого рівня (Python, Rust, C#)

Бібліотека `libwireforce` надає вбудовану підтримку генерації обгорток для мов високого рівня:

- **Python (`wireforce_py`):** Забезпечує інтеграцію з обчислювальними бібліотеками NumPy та SciPy. Дозволяє передавати векторизовані масиви геометрій та струмів у C-функції без створення накладних витрат інтерпретатора.
- **Rust (`wireforce-rs`):** Надає безпечні *safe bindings* з перевіркою термінів життя (*lifetimes*) та інтеграцією з каркасом обробки помилок `Result<T, WireForceError>`.
- **C# / .NET (P/Invoke):** Надає DLL-імпорт `[DllImport("wireforce.dll")]` для використання у корпоративних інженерних системах на базі WPF / ASP.NET.

## 10. Регламент проведення верифікаційних випробувань

Перед впровадженням бібліотеки `libwireforce` у відповідальне інженерне ПЗ проведення верифікації розрахункового ядра є обов'язковим. 

Бібліотека постачається з комплексом юніт-тестів, які порівнюють розраховані сили з результатом лабораторних вимірювань на струмових вагах та результатами FEA-симуляцій COMSOL Multiphysics:
- **Тест А:** Взаємодія паралельних дротів завдовжки 1.0 м при струмах 100 А (відхилення розрахованої сили від формули Ампера не перевищує `10⁻⁶%`).
- **Тест Б:** Розрахунок трифазної системи шин 40 кА за стандартом IEC 60865-1 (збіг з еталонними тестовими даними стандарту з точністю до 5 значущих цифр).
- **Тест В:** Перевірка обробки граничних та некоректних даних (від'ємні струми, нульові відстані, вихід за межі масиву).

## 11. Приклад повного циклу використання C API

Нижче наведено приклад реальної інженерної програми мовою C, що розраховує трифазний шинопровід розподільчого щита 0.4 кВ та обробляє можливі відхилення:

```c
#include <stdio.h>
#include "wireforce.h"

int main(void) {
    /* 1. Задання геометрії шинопроводу 0.4 кВ */
    wf_wire_geometry_t geo = {
        .distance_m = 0.20,       /* 200 мм між фазами */
        .length_m = 1.00,         /* 1.0 м проліт між ізоляторами */
        .bus_width_m = 0.010,     /* 10 мм товщина */
        .bus_height_m = 0.100,    /* 100 мм висота */
        .inclination_rad = 0.0    /* Паралельне розташування */
    };

    /* 2. Параметри короткого замикання (I''k = 50 кА) */
    wf_sc_params_t sc = {
        .initial_ik_ka = 50.0,
        .shock_factor = 1.85,
        .frequency_hz = 50.0,
        .is_three_phase = true
    };

    /* 3. Характеристики матеріалу (Мідь M1t та ізолятор ІОР-10-7.5) */
    wf_material_limits_t mat = {
        .type = WF_MAT_COPPER_HARD,
        .yield_stress_mpa = 200.0,
        .max_insulator_kn = 7.5,
        .safety_factor_req = 1.25
    };

    wf_calc_result_t res;
    wf_status_t status = wf_calculate_busbar_system(&geo, &sc, &mat, &res);

    if (status == WF_SUCCESS) {
        printf("--- АНАЛІЗ УСПІШНИЙ ---\n");
        printf("Ударний струм КЗ: %.2f кА\n", res.peak_current_ka);
        printf("Сила на метр: %.2f кН/м\n", res.force_per_meter_kn_m);
        printf("Напруження в шині: %.2f МПа\n", res.bending_stress_mpa);
        printf("Навантаження на ізолятор: %.2f кН\n", res.insulator_load_kn);
        printf("Запас міцності: %.2f\n", res.actual_safety_factor);
    } else {
        printf("ПОМИЛКА РОЗРАХУНКУ: %s (код %d)\n", 
               wf_status_to_string(status), status);
    }

    return 0;
}
```
