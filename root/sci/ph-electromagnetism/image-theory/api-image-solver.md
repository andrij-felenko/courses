# 📋 Специфікація API бібліотеки обчислення полів дзеркальними зарядами

Даний документ містить повний технічний довідник та детальну специфікацію публічного програмувального інтерфейсу (API) C/C++ бібліотеки `libesimage` (поточна версія 2.4.0). Бібліотека призначена для високопродуктивного чисельного розрахунку тривимірних електростатичних полів, потенціалів, векторів напруженості, розподілу індукованого поверхневого заряду та кулонівських сил методом дзеркальних зображень у складних конфігураціях провідних та діелектричних середовищ.

Головною метою створення бібліотеки `libesimage` є надання швидкого, точного та числово стійкого обчислювального інструменту для розробників комп'ютерного програмного забезпечення фізичного моделювання, високочастотної системи автоматизованого проектування (САПР) друкованих плат, розрахунку антенних систем та аналізу електростатичної захищеності електронних приладів.

Бібліотека поставляється у вигляді статичної бібліотеки `libesimage.a` (або `esimage.lib` для систем Windows) та набору заголовочних файлів `esimage/solver.h` (C API) та `esimage/solver.hpp` (C++ API). Вона не має зовнішніх залежностей від чужих обчислювальних бібліотек, що забезпечує високу портативність та легкість інтеграції у будь-які кросплатформені проєкти.

Модуль обчислення полів розроблявся з урахуванням високих вимог до обчислювальної швидкодії при моделюванні складних просторових конфігурацій, що містять десятки реальних точкових зарядів.

---

### 1. Перелік типів даних та структур

Бібліотека надає строго типізовані C-сумісні типи даних та зручні класи-обгортки C++ для передачі просторових координат, характеристик джерел полів та типів граничних умов.

#### 1.1. `es_vec3_t` — Тривимірний вектор
Структура `es_vec3_t` використовується для задання радіус-векторів позицій у тривимірній декартовій системі координат `(x, y, z)`. Усі просторові координати вимірюються в метрах відповідно до міжнародної системи одиниць (СІ).

:::tabs
```c
typedef struct {
    double x; // Координата X у метрах [м]
    double y; // Координата Y у метрах [м]
    double z; // Координата Z у метрах [м]
} es_vec3_t;
```
```cpp
namespace libesimage {
struct Vector3D {
    double x{0.0}; // Координата X у метрах [м]
    double y{0.0}; // Координата Y у метрах [м]
    double z{0.0}; // Координата Z у метрах [м]
};
}
```
:::

#### 1.2. `es_charge_t` — Опис точкового заряду
Структура `es_charge_t` використовується для опису характеристик як реальних фізичних джерел полів, так і автоматично згенерованих дзеркальних зображень.

:::tabs
```c
typedef struct {
    es_vec3_t position; // Позиція заряду у просторі (x, y, z)
    double charge_val;  // Величина заряду в кулонах [Кл]
    bool is_image;      // Прапорець: false — реальний заряд, true — дзеркальний
    uint32_t id;        // Унікальний ідентифікатор заряду в системі
} es_charge_t;
```
```cpp
namespace libesimage {
struct PointCharge {
    Vector3D position;   // Позиція заряду у просторі
    double charge_val{0.0}; // Величина заряду [Кл]
    bool is_image{false};   // Прапорець дзеркального заряду
    uint32_t id{0};         // Унікальний ID заряду
};
}
```
:::

#### 1.3. `es_boundary_type_t` — Перелічувальний тип граничних умов
Перелічувальний тип `es_boundary_type_t` визначає геометричний тип провідного або діелектричного екрана, відносно якого розраховуються дзеркальні зображення.

| Значення константи | Опис геометрії провідної межі | Кількість дзеркальних зображень |
| :--- | :--- | :--- |
| `ES_BOUND_PLANE` | Заземлена площина `z = z_0` | `1` зображення на заряд |
| `ES_BOUND_SPHERE` | Заземлена сфера радіуса `R` з центром `O` | `1` інверсне зображення на заряд |
| `ES_BOUND_CORNER_90` | Кутовий відбивач під кутом `90°` | `3` зображення на заряд |
| `ES_BOUND_DIELECTRIC` | Межа двох діелектриків `ε₁` та `ε₂` | `1` зображення `q'` / `1` еквівалент `q''` |

#### 1.4. `es_solver_config_t` — Структура конфігурації солвера
Структура `es_solver_config_t` містить чисельні параметри геометрії, фізичні сталі середовищ та налаштування числової стійкості.

:::tabs
```c
typedef struct {
    es_boundary_type_t boundary_type; // Тип граничної умови
    double plane_z_coord;             // Z-координата площини [м] (для ES_BOUND_PLANE)
    es_vec3_t sphere_center;          // Центр сфери (для ES_BOUND_SPHERE)
    double sphere_radius;             // Радіус сфери [м] (для ES_BOUND_SPHERE)
    double eps1;                      // Проникність середовища 1 (для ES_BOUND_DIELECTRIC)
    double eps2;                      // Проникність середовища 2 (для ES_BOUND_DIELECTRIC)
    double singularity_cutoff;        // Поріг захисту від ділення на нуль [м] (default: 1e-12)
} es_solver_config_t;
```
```cpp
namespace libesimage {
enum class BoundaryType { Plane, Sphere, CornerReflector90, DielectricInterface };

struct SolverConfig {
    BoundaryType boundary_type{BoundaryType::Plane};
    double plane_z_coord{0.0};
    Vector3D sphere_center{0.0, 0.0, 0.0};
    double sphere_radius{1.0};
    double eps1{1.0};
    double eps2{1.0};
    double singularity_cutoff{1e-12};
};
}
```

### 2. Коди помилок та статус виконання

Усі функції бібліотеки, що повертають тип `es_status_t`, слідують стандартній угоді про коди помилок. Повернення значення `ES_SUCCESS` (нуль) гарантує успішне виконання операції. Від'ємні значення вказують на конкретну помилку.

При виникненні будь-якої помилки внутрішній стан розв'язувача залишається незмінним, що забезпечує транзакційність та гарантію стійкості до збоїв.

| Код помилки | Числове значення | Символьна назва | Опис і причина виникнення |
| :--- | :--- | :--- | :--- |
| `0` | `ES_SUCCESS` | Успішне виконання | Операцію виконано без помилок. |
| `-1` | `ES_ERR_NULL_POINTER` | Нульовий вказівник | Передано `NULL` у якості аргументу функції. |
| `-2` | `ES_ERR_INVALID_GEOMETRY` | Некоректна геометрія | Некоректний радіус сфери (`R <= 0`) або `ε₁ + ε₂ = 0`. |
| `-3` | `ES_ERR_INSIDE_CONDUCTOR` | Заряд усередині | Реальний заряд розміщено всередині провідника. |
| `-4` | `ES_ERR_SINGULARITY` | Числова сингулярність | Точка спостереження збігається з позицією заряду. |
| `-5` | `ES_ERR_OUT_OF_MEMORY` | Брак пам'яті | Не вдалося виділити динамічну пам'ять. |

### 3. Сигнатури функцій C API

#### 3.1. Управління життєвим циклом розв'язувача

Функції даної групи відповідають за ініціалізацію об'єкта розв'язувача полів у динамічній пам'яті, первинну конфігурацію геометрії та коректне звільнення виділених ресурсів після завершення обчислень.

:::tabs

Ця група містить обчислювальне ядро бібліотеки. Функції дозволяють обчислити скалярний потенціал `V`, вектор напруженості `E⃗`, густину поверхневого індукованого заряду `σ` та підсумкову кулонівську силу взаємодії `F⃗`.

:::tabs

### 4. Інтерфейс C++ (Обгортка об'єктно-орієнтованого API)

Для розробників сучасних застосунків мовою C++20 надається заголовочний клас-обгортка `libesimage::ElectrostaticSolver`, розташований у просторі імен `libesimage`. Він реалізує паттерн RAII та забезпечує автоматичне управління ресурсами.

Клас підтримує виключний контроль володіння ресурсами: конструктори та оператори копіювання заблоковані (`= delete`), тоді як семантика переміщення (`std::move`) повністю підтримується для збереження максимальної ефективності при роботі зі стандартними контейнерами `std::vector`.

```cpp
namespace libesimage {

class ElectrostaticSolver {
public:
    explicit ElectrostaticSolver(const SolverConfig& config = {});
    ~ElectrostaticSolver();

    // Заборона копіювання (RAII)
    ElectrostaticSolver(const ElectrostaticSolver&) = delete;
    ElectrostaticSolver& operator=(const ElectrostaticSolver&) = delete;

    // Дозвіл переміщення
    ElectrostaticSolver(ElectrostaticSolver&&) noexcept;
    ElectrostaticSolver& operator=(ElectrostaticSolver&&) noexcept;

    uint32_t add_charge(const Vector3D& position, double charge_val);
    void set_geometry(const SolverConfig& config);

    [[nodiscard]] double get_potential(const Vector3D& point) const;
    [[nodiscard]] Vector3D get_field(const Vector3D& point) const;
    [[nodiscard]] Vector3D get_force(uint32_t charge_id) const;
    [[nodiscard]] double get_surface_charge_density(const Vector3D& point) const;

    [[nodiscard]] std::span<const PointCharge> get_image_charges() const noexcept;

private:
    es_solver_t* m_handle{nullptr};
};

} // namespace libesimage
```

### 5. Потокобезпека та умови багатопотокового використання

1. **Багатопотокове читання даних (`const` операції):**
   Усі функції обчислення полів `es_solver_eval_potential`, `es_solver_eval_field` та `es_solver_eval_force` є повністю **потокобезпечними (reentrant)** для паралельного виклику з багатьох робочих потоків виконання (наприклад, при паралельному рендерингу 3D-сітки полів за допомогою OpenMP чи `std::async`), за умови, що конфігурація розв'язувача та список реальних зарядів не модифікуються під час обчислень.

2. **Модифікація конфігурації та стану:**
   Функції `es_solver_add_charge` та `es_solver_update_config` змінюють внутрішній стан розв'язувача і вимагають ексклюзивного блокування за допомогою примітивів синхронізації (`std::mutex` або `pthread_mutex_t`).

3. **Гарантії відсутності побічних ефектів:**
   Жодна з обчислювальних функцій `eval_*` не використовує статичних чи глобальних змінних та не модифікує внутрішній стан структури `es_solver_t`.

### 6. Повний приклад використання C API та C++ API

Для швидкого старту розробників нижче наведено детальні пояснення типових послідовностей викликів функцій створення розв'язувача, додавання джерел та обчислення полів.

#### 6.1. Послідовність викликів мовою C
При програмуванні на мові C розробник виконує такі обов'язкові кроки:
1. Запитує створення екземпляра розв'язувача функцією `es_solver_create()`.
2. Заповнює структуру конфігурації `es_solver_config_t` із заданням типу межі `ES_BOUND_PLANE` та координат площини `plane_z_coord = 0.0`.
3. Додає необхідну кількість реальних точкових зарядів через функцію `es_solver_add_charge()`.
4. Обчислює значення потенціалу та вектора напруженості у потрібних точках спостереження за допомогою функцій `es_solver_eval_potential()` та `es_solver_eval_field()`.
5. Після завершення обчислень обов'язково звільняє виділену динамічну пам'ять викликом `es_solver_destroy()`.

#### 6.2. Послідовність викликів мовою C++
При програмуванні на мові C++20 розробник кодує обчислення значно простіше та безпечніше:
1. Створює об'єкт розв'язувача на стеку: `libesimage::ElectrostaticSolver solver`.
2. Додає реальні заряди методом `solver.add_charge({0.0, 0.0, 0.05}, 1.0e-6)`.
3. Отримує вектор напруженості через `auto e = solver.get_field({0.0, 0.0, 0.01})`.
4. Звільнення усіх виділених ресурсів відбувається автоматично деструктором об'єкта при виході з області видимості.

### 7. Таблиця одиниць вимірювання СІ

Використання єдиної міжнародної системи одиниць СІ є обов'язковою умовою коректної роботи з бібліотекою `libesimage`. Усі фізичні сталі (включаючи електричну сталу `ε₀ ≈ 8.8541878128e-12 Кл²/(Н·м²)`) жорстко зафіксовані у СІ.

| Фізична величина | Позначення у коді | Одиниця вимірювання в СІ | Базові одиниці СІ |
| :--- | :--- | :--- | :--- |
| Електричний потенціал `V` | `double` | Вольт [В] | `кг·м² / (с³·А)` |
| Вектор напруженості `E` | `es_vec3_t` | Вольт на метр [В/м] | `кг·м / (с³·А)` |
| Кулонівська сила `F` | `es_vec3_t` | Ньютон [Н] | `кг·м / с²` |
| Поверхнева густина `σ` | `double` | Кулон на м² [Кл/м²] | `А·с / м²` |
| Електричний заряд `q` | `double` | Кулон [Кл] | `А·с` |
