### Концептуальна архітектура бібліотеки

Програмний комплекс побудований за принципом суворого розділення геометричного опису домену, чисельного математичного ядра та модуля вилучення фізичних параметрів. Користувач задає двовимірну або тривимірну дискретну сітку, на якій розміщуються вузли провідників, діелектричних середовищ та електродів джерел живлення.

Математичне ядро підтримує кілька методів розв'язання дискретизованих систем рівнянь Лапласа та Пуассона: послідовну верхню релаксацію (SOR), метод спряжених градієнтів (CG) та багатосітковий метод (Multigrid). Після отримання стійкого поля потенціалів модуль аналізу автоматично обчислює градієнти поля на поверхні провідників та відновлює поверхневу густину заряду `σ_surf` за граничними умовами Гаусса.

### Переліки та структури даних

Усі класи та структури бібліотеки розташовані у просторі назв `ElectroDynamics`. Ниже наведено повний набір структур даних, які визначають геометрію сітки, фізичні параметри матеріалів та конфігурацію чисельного солівера.

Типи крайових умов описують роль кожного дискретного вузла обчислювальної сітки у розрахунковій схемі. Вузол вільної зони (`FreeSpace`) відповідає діелектрику (повітря, субстрат FR-4), де розв'язується рівняння Лапласа `ΔV = 0`. Вузол об'єму провідника (`ConductorBulk`) відповідає електронейтральній товщі металу з фіксованою провідністю `σ`. Вузол фіксованого потенціалу (`DirichletFix`) описує контактні майданчики клем джерела живлення, де потенціал утримується жорстко. Вузол міжфазної межі (`InterfaceBoundary`) визначає стик двох матеріалів із різними провідностями, де відбувається стрибок поля.

### Фізичний зміст та регулювання параметрів `SolverConfig`

Кожен параметр структури `SolverConfig` безпосередньо впливає на чисельну стійкість, точність та швидкість обчислення поверневих зарядів:

1. **Крок дискретизації сітки `mesh_step_m` (`h`):** Крок просторової сітки визначає мінімальний геометричний елемент, який розрізняє солівер. Для точного розрахунку скупчення заряду на вигинах мікросмукових ліній крок `h` повинен бути щонайменше в 5–10 разів меншим за ширину провідного каналу. Зменшення кроку вдвічі збільшує обсяг потрібної пам'яті у 4 рази (для 2D) й кількість ітерацій у 4 рази.
2. **Параметр верхньої релаксації `relaxation_omega` (`ω`):** У математичному ядрі SOR параметр `ω` визначає прискорення збіжності ітерацій Гаусса-Зайделя. Для прямокутної сітки розміром `N × N` теоретичний оптимум становить `ω_opt = 2 / (1 + sin(π / N))`. Для сітки `256 × 256` оптимальне значення дорівнює близько 1.925. Якщо встановити `ω >= 2.0`, чисельний процес стає нестійким, і метод повертає статус `SolverStatus::DivergentSystem`.
3. **Поріг збіжності `tolerance_volts`:** Ітераційний процес зупиняється, коли максимальна абсолютна зміна потенціалу між двома послідовними кроками у будь-якому вузлі сітки `max |V_new - V_old|` стає меншою за `tolerance_volts`. Значення `1e-7` В забезпечує точність обчислення поверхневого заряду на рівні 0.1%.
4. **Прапорець обчислення вектора Пойнтінга `enable_poynting_calc`:** При включенні цього прапорця солівер після обчислення потенціалу `V` додатково розраховує циркуляцію магнітного поля `B` від струмів провідника та знаходить векторний добуток `S = (1 / μ0) · (E × B)` у кожній точці діелектрика.

### Алгоритмічні особливості соліверних двигунів (`SolverEngine`)

Бібліотека надає три математичні ядра, оптимізовані під різні класи фізичних задач:

- **`SOR_Relaxation` (Послідовна верхня релаксація):** Оптимальний вибір для сіток середнього розміру (до `512 × 512` вузлів). Метод має мінімальне використання оперативної пам'яті, оскільки оновлює потенціал безпосередньо у вихідному масиві. Не потребує виділення додаткових робочих векторів.
- **`ConjugateGradient` (Метод спряжених градієнтів):** Використовується для розряджених симетричних матриць, що виникають при наявності складної криволінійної геометрії. Забезпечує гарантовану квадратну збіжність за число ітерацій, пропорційне `sqrt(N)`. Потребує додаткового виділення трьох векторів розміру сітки для зберігання напрямків спуску та неузгодженостей.
- **`MultigridFDM` (Багатосітковий метод):** Призначений для великомасштабного тривимірного моделювання (понад `1e6` вузлів). Алгоритм будує ієрархію сіток різної роздільної здатності (V-цикл або W-цикл). Згладжування високочастотних помилок відбувається на дрібній сітці, а довгохвильові компоненти потенціалу розв'язуються на грубій сітці. Це дає лінійну алгоритмічну складність `O(N)` за часом розрахунку.

### Детальні гарантії безпеки та інваріанти виконання

Інтерфейс бібліотеки побудовано з урахуванням суворих вимог сучасної системної розробки мовою C++:

1. **Інкапсуляція пам'яті через Pimpl:** Шаблон реалізації Pimpl (`std::unique_ptr<Impl>`) приховує всі внутрішні векторні масиви, алгоритми індексування та сторонні бібліотечні залежності від заголовкових файлів клієнта. Це гарантує стабільність ABI (Application Binary Interface) при зміні внутрішнього чисельного ядра.
2. **Нульове копіювання з `std::span`:** Метод `get_mesh_data()` повертає `std::span<const GridNode>`, який надає прямий доступ для читання до внутрішнього масиву вузлів без виділення додаткової пам'яті. Клієнтський код не може випадково змінить обчислені значення потенціалу чи заряду.
3. **Обробка помилок та винятки:** Метод `compute()` повертає `SolverStatus` і не викидає винятків при звичайних чисельних відхиленнях. Однак при некоректних аргументах у методах доступу (наприклад, вихід за межі сітки `ix >= grid_nx`) викидається стандартний виняток `std::out_of_range`.
4. **Потокобезпечність читання:** Після завершення роботи методу `compute()` об'єкт `SurfaceChargeSolver` є константним. Клієнтські потоки можуть одночасно та безпечно викликати методи `get_surface_charge()`, `get_poynting_flux_watts()` та `export_to_csv()` без використання блокувальних примітивів (мутексів).

### Розрахунок ресурсоємності та пам'яті

Використання пам'яті обчислювальною сіткою розраховується за формулою:

```
Memory_Bytes = NX × NY × sizeof(GridNode) [формула обсягу пам'яті для 2D сітки]
```

Оскільки структура `GridNode` вирівняна по межі 16 байт і має розмір 48 байт, сітка розміром $1024 \times 1024$ вузлів потребує близько 50 МБ оперативної пам'яті. Для тривимірної сітки $512 \times 512 \times 512$ обсяг пам'яті досягає 6.4 ГБ, що робить використання багатосіткового солівера `MultigridFDM` обов'язковим для ефективного кешування L3 процессора.

Згенерований файл CSV призначений для обробки у відкритих аналітичних пакетах і має наступну структуру колонок:

```csv

10,50,0.0050,0.0250,12.000000,0.0000e+00,0.0000e+00,0.0000e+00,2

51,60,0.0255,0.0300,11.450212,1.1204e-09,1.4180e+02,0.0000e+00,1
```

Кожен рядок текстового файла відповідає одному дискретному вузлу сітки. Експорт у формат VTK (Visualization Toolkit) створює двовимірну прямокутну сітку `StructuredPoints`, яка дозволяє візуалізувати тривимірні ізоповерхні потенціалу, векторні поля Пойнтінга та просторовий розподіл поверхневого заряду `σ_surf` у графічному пакеті ParaView.
