# ⚙️ Алгоритм трасування силових ліній і контурів еквіпотенціалей

Ця практична вставка містить алгоритм чисельного розрахунку й побудови карти векторного поля — трасування силових ліній методом Рунге — Кутти 4-го порядку (RK4) та побудови контурів еквіпотенціалей методом маршуючих квадратів (*Marching Squares*) для довільної системи точкових електричних зарядів.

## Математична постанова задачі чисельного трасування

Силова лінія електричного поля є орієнтованою кривою `r(s) = (x(s), y(s))` на площині, дотичний вектор до якої у кожній точці паралельний вектору напруженості електричного поля `E(r)`. Математично це зводиться до розв'язання задачі Коші для системи двох звичайних диференціальних рівнянь першого порядку, аргументом у яких виступає довжина дуги `s`:

```
dx / ds = E_x(x, y) / |E(x, y)|
dy / ds = E_y(x, y) / |E(x, y)|
```

Тут нормування на модуль поля `|E| = √(E_x² + E_y²)` є критично важливим: воно гарантує, що вектор швидкості трасування вздовж дуги має одиничну довжину (`|(dx/ds, dy/ds)| = 1`), тому чисельний крок `ds` виражає геометричну довжину зміщення у метрах чи пікселях, незалежно від того, наскільки слабким чи сильним є поле в цій точці.

Найпростіший чисельний метод Ейлера обчислює наступну точку за формулою `r_{k+1} = r_k + u(r_k) · ds`, де `u = E / |E|`. Проте для силових ліній із високою кривиною (наприклад, поблизу точкових зарядів чи в області дипольних дуг) метод Ейлера має локальну похибку порядку `O(ds²)` і глобальну похибку `O(ds)`. Це призводить до того, що розрахована лінія швидко «вилітає» з істинної колової або еліптичної траєкторії, спірально віддаляючись від джерела та демонструючи хибну самоперетинність.

Щоб забезпечити високу точність із локальною похибкою `O(ds⁵)` та глобальною похибкою `O(ds⁴)`, застосовують **класичний метод Рунге — Кутти 4-го порядку (RK4)**. На кожному кроці алгоритм обчислює чотири проміжні оцінки напрямку поля:

1. `k₁ = u(r_k)` — напрямок поля на початку кроку.
2. `k₂ = u(r_k + 0.5 · ds · k₁)` — напрямок поля в середній точці, знайти за допомогою `k₁`.
3. `k₃ = u(r_k + 0.5 · ds · k₂)` — друга оцінка напрямку в середній точці, знайдена за допомогою `k₂`.
4. `k₄ = u(r_k + ds · k₃)` — оцінка напрямку наприкінці кроку, знайдена за допомогою `k₃`.

Остаточне переміщення обчислюється як зважене середнє чотирьох векторів:

```
r_{k+1} = r_k + (ds / 6) · (k₁ + 2·k₂ + 2·k₃ + k₄)
```

## Борьба із сингулярностями та крайові умови

При чисельному розрахунку полів точкових зарядів виникають три специфічні інженерно-обчислювальні проблеми:

### 1. Сингулярність поблизу точкового заряду
Поле точкового заряду описується законом обернених квадратів `E = k · q / r²`. При наближенні крізь чисельний крок до точки розташування заряду `r → 0` модуль поля прямує до нескінченності (`E → ∞`). Якщо трасер підходить занадто близько до центру заряду, обчислення частки `0/0` викликає числове переповнення (*NaN* або *Inf*), або трасер перескочить через центр заряду й почне хаотично гасати по сітці.

Для нейтралізації сингулярності навколо кожного заряду `q_i` задають радіус відсікання `R_cutoff` (зазвичай `0.02–0.03` від розміру сітки). Якщо поточна точка трасування потрапляє у сферичний окіл будь-якого заряду (`|r - r_c| < R_cutoff`), трасування даної силової лінії негайно припиняється, а лінія вважається такою, що увійшла в сток.

### 2. Густина випромінювання ліній з джерела
Щоб картина силових ліній правильно передавала величину заряду джерела, кількість ліній `N_lines`, що виходять із заряду `q`, повинна бути строго пропорційною величині цього заряду (`N_lines = C · |q|`). Початкові точки трасування розміщують на малому колі радіуса `R_start > R_cutoff` навколо заряду під рівномірними кутами:

```
θ_k = 2 · π · k / N_lines,   k = 0, 1, ..., N_lines − 1
x_start = x_c + R_start · cos(θ_k)
y_start = y_c + R_start · sin(θ_k)
```

Для додатних зарядів напрямок трасування вибирається за полем (`+ds`), для від'ємних — проти поля (`−ds`).

## Математичний порівняльний аналіз чисельних методів інтегрування

При чисельному розрахунку силових ліній вибір алгоритму інтегрування диференціального рівняння `dr/ds = E(r) / |E(r)|` фундаментально впливає на топологічну коректність отриманої карти поля.

### Метод Ейлера 1-го порядку
Найпростіший метод Ейлера обчислює нову точку за формулою:

```
r_{k+1} = r_k + (E(r_k) / |E(r_k)|) · ds
```

Метод Ейлера володіє локальною похибкою порядку `O(ds²)` та глобальною похибкою `O(ds)`. Для колових та еліптичних силових ліній (наприклад, у полі диполя або двох однойменних зарядів) метод Ейлера постійно зміщується у бік зовнішньої нормалі до кривої. В результаті розрахована силова лінія замість замкнення на від'ємному заряді або відходу на нескінченність по спіралі віддаляється від джерела, створюючи дефекти самоперетину та хибного накопичення помилки.

### Класичний метод Рунге — Кутти 4-го порядку (RK4)
Метод RK4 компенсує кривину силової лінії шляхом чотириразового виклику вектора поля на кожному кроці. Оскільки локальна похибка метода становить `O(ds⁵)`, а глобальна похибка `O(ds⁴)`, трасувальник зберігає концентричну геометрію колових та еліптичних ліній навіть при помірних кроках `ds ≈ 0.01`.

### Адаптивний метод Рунге — Кутти — Фельберга (RKF45)
У зонах високої кривизни поля (поблизу точкових зарядів або гострих кутів провідників) постійний крок `ds` є недосконалим: малий крок уповільнює розрахунок у далеких однорідних областях, а великий крок викликає втрату точності біля джерел.

Для усунення цього недоліку застосовують адаптивний алгоритм **Рунге — Кутти — Фельберга 4/5 порядку (RKF45)**. На кожному кроці алгоритм обчислює два значення нової точки: `r₄` (4-го порядку точності) та `r₅` (5-го порядку точності), за допомогою 6 оцінок вектора поля.

Локальна похибка оцінюється як модуль різниці двох векторів:

```
err = |r₅ − r₄|
```

Новий адаптивний крок `ds_new` обчислюється автоматично за формулою з коефіцієнтом запасу `0.84`:

```
ds_new = 0.84 · ds · (tol / err)^(1/5)
```

- Якщо `err > tol` (похибка перевищує допустимий поріг), крок `r_{k+1}` відкидається, крок зменшується (`ds = ds_new`) і обчислення повторюється.
- Якщо `err ≤ tol`, крок приймається, точка додається до лінії, а наступний крок збільшується (`ds = min(ds_new, ds_max)`).

Завдяки адаптації трасувальник автоматично стискає крок до мікронів біля зарядів та розширює його у відкритому просторі, забезпечуючи максимальну точність при мінімальних обчислювальних витратах.

## Алгоритм побудови контурів еквіпотенціалей (Marching Squares) та розв'язання сідлових двозначностей

Побудова ізоліній скалярного потенціалу `V(x, y) = V_target` здійснюється двовимірним алгоритмом **маршуючих квадратів** (*Marching Squares*):

1. Область розрахунку покривається прямокутною сіткою вузлів `(x_i, y_j)`.
2. У кожному вузлі обчислюється значення скалярного потенціалу `V_ij = ∑ (k · q_k / r_k)`.
3. Кожна осередкова комірка сітки (квадрат із 4 вузлів: вершини 0-1-2-3 за годинниковою стрілкою) перевіряється на перетин із рівнем `V_target`. Вузлу з `V ≥ V_target` призначають біт `1`, інакше `0`. 4 вузли утворюють 4-бітний індекс `index = b₃b₂b₁b₀` (від 0 до 15).
4. Точки перетину контуру з ребрами квадрата знаходять за допомогою лінійної інтерполяції:
   ```
   t = (V_target − V₁) / (V₂ − V₁)
   x_intersect = x₁ + t · (x₂ − x₁)
   y_intersect = y₁ + t · (y₂ − y₁)
   ```

### Усунення сідлових двозначностей (Ambiguity Resolution)
З 16 можливих бітових конфігурацій дві конфігурації є топологічно двозначними:
- **Конфігурація 5 (`0101`):** діагонально протилежні вершини 1 та 3 знаходяться вище `V_target`, а 0 та 2 — нижче.
- **Конфігурація 10 (`1010`):** діагонально протилежні вершини 0 та 2 знаходяться вище `V_target`, а 1 та 3 — нижче.

У цих випадках через один квадрат проходять дві ізолінії, які можуть з'єднуватися двома різними способами (неперетинні дуги або перетинний сідловий хрест).

Для правильного розв'язання двозначності обчислюють значення потенціалу у центральній точці квадрата за формулою білінійної інтерполяції:

```
V_center = (1 / 4) · (V₀ + V₁ + V₂ + V₃)
```

- Якщо `V_center ≥ V_target`, контурні лінії з'єднують діагональні вершини вищого потенціалу.
- Якщо `V_center < V_target`, лінії з'єднують вершини нижчого потенціалу.

Це гарантує топологічну строгість побудованих еквіпотенціалей та відсутність хибного розриву контурів у сідлових точках нейтрального поля.

## Аналіз швидкодії та оптимальний вибір параметра кроку ds

При виборі величини кроку чисельного інтегрування `ds` виникає компроміс між обчислювальною складністю та точністю геометрії:

- **Занадто великий крок (`ds > 0.05`):** трасер «зрізає» дуги великої кривизни, що призводить до видимих зламів ліній, порушення ортогональності з еквіпотенціалями та хибного проходження крізь окіл зарядів.
- **Занадто малий крок (`ds < 0.001`):** кількість обчислень вектора поля `E(r)` зростає пропорційно `1/ds`. Оскільки кожен виклик `calcField` вимагає сумування за всіма `N_charges` зарядами, загальна складність трасування `M` ліній довжиною `K` кроків стає `O(M · K · N_charges)`. При `ds = 0.0001` програма може завісати при інтерактивному рендерингу.
- **Оптимальний вибір (`ds ≈ 0.005–0.01`):** у поєднанні з методом RK4 такий крок забезпечує гладкі криві без видимих апроксимаційних дефектів при високій швидкодії (розрахунок карти з 50 ліній займає менше 5 мілісекунд).

## Оптимізація обчислювальної швидкодії та паралельне трасування

При симуляції складних полів у тривимірному просторі або при розрахунку систем із тисячами точкових зарядів чи елементарних поверхових зарядів (у методі граничних елементів, BEM) обчислювальна складність стає головним обмежувальним фактором.

### 1. Паралельне трасування ліній (Multi-Threading через OpenMP)
Оскільки кожна силова лінія починається від власної початкової точки випромінювання й трасується абсолютно незалежно від інших ліній, задача трасування є ідеально паралельною (*embarrassingly parallel*). У C++ алгоритмі генерація карти полів паралелізується директивою OpenMP без жодних блокувань та м'ютексів:

```cpp
#pragma omp parallel for schedule(dynamic)
for (int i = 0; i < numLines; ++i) {
    // Трасування окремої силової лінії в незалежному потоці
}
```

Динамічний розподіл кроків `schedule(dynamic)` є критичним, оскільки лінії, що входять у стоки поблизу, завершуються за десятки кроків, тоді як лінії, що йдуть на нескінченність, вимагають максимальної кількості `maxSteps` інтегрувань.

### 2. SIMD-векторизація обчислення поля (AVX-256 / FMA)
Функція обчислення вектора поля `calcField` виконує сумування Кулонівського внеску від усіх `N` зарядів для кожної точки:

```
E_x = ∑ (k · q_i · (x − x_i) / ((x − x_i)² + (y − y_i)²)^(3/2))
```

Цей обчислювальний цикл векторизується за допомогою інструкцій AVX-256 або AVX-512. Регістри векторного процесора дозволяють одночасно обчислювати відстані `r^2` та компоненти полів одразу для 4 або 8 зарядів за один тактовий цикл, що прискорює розрахунок у 3–5 разів.

### 3. Неперервна упаковка пам'яті (Contiguous Data Layout)
Використання суцільних векторних буферів `std::vector<Point2D>` замість зв'язаних списків `std::list` у C++ гарантує високу локувальність даних у кєш-пам'яті першого та другого рівнів (L1/L2 Cache), запобігаючи кєш-промахам при частій ітерації по точках кривої.

## Захист від обчислювальних пасток та крайові випадки

При розробці чисельних трасувальників силових ліній слід передбачити обробку чотирьох специфічних обчислювальних пасток:

1. **Колізія з поверхнями провідників:** якщо трасер наближається до поверхні заземленого електрода довільної форми, крокування мусить зупинятися точно на межі розділу. Для цього перевіряють перетин відрізка `(r_k, r_{k+1})` із полігональною сіткою провідника методом променя.
2. **Втрата точності плаваючої коми біля тісних диполів:** при віддаленні від тісного диполя (`d << r`) вектори полів від додатного й від'ємного зарядів майже повністю віднімаються (`E_+ ≈ −E_-`). Пряме віднімання близьких чисел викликає катастрофічну втрату значущих розрядів плаваючої коми (чисельна скасування). Для усунення цього дефекту на великих відстанях сумування за зарядами замінюють безпосередньо розкладом за дипольними та квадрупольними моментами.
3. **Обхід сідлових точок застою:** у точках застою (`E = 0`) напрямок поля є невизначеним. Якщо силова лінія влучає в окіл сідлової точки, трасувальник може зациклитися чи почати хаотичні осциляції. Для запобігання цього алгоритм перевіряє модуль поля: якщо `|E| < ε`, трасування даного відрізка негайно припиняється.

## Експорт інженерних даних та графічні формати (SVG, VTK, ParaView)

Результати чисельного трасування полів експортуються у два формати для інженерного аналізу та документації:

1. **Векторний формат SVG (Scalable Vector Graphics):**
   Масив точок кожної силової лінії перетворюється на елемент кривої `<path d="M x0 y0 L x1 y1 L x2 y2 ..."/>`. Завдяки векторній природі, зображення зберігає абсолютну чіткість при будь-якому масштабуванні у документації та веб-інтерфейсах.

2. **Формат тривимірних сіток VTK (VTK PolyData XML / `.vtp`):**
   Для об'ємного 3D моделювання у пакетах ParaView або ANSYS лінії зберігаються у формі тривимірних поліліній (*VTK_POLY_LINE*) з атрибутивними полями модуля напруженості `|E|` та скалярного потенціалу `V` у кожному вузлі. Це дозволяє будувати об'ємні кольорові трубки полів, проводити зрізи та аналізувати локальні градієнти у складному обладнанні.

3. **Вилучення матриці ємностей `C_ij`:**
   Шляхом чисельного підрахунку кількості силових ліній `N_ij`, які виходять з провідника `i` і входять у провідник `j`, алгоритм автоматично будує **матрицю часткових ємностей** для багатопровідникових систем (наприклад, для багатожильних кабелів або диференціальних шин PCB), що є необхідним етапом аналізу цілісності сигналів (*Signal Integrity*) у сучасній мікроелектроніці.

## Приклад інженерного розрахунку та бенчмарк швидкодії

Розглянемо практичний приклад розрахунку поля високовольтного електрода під напругою `100` кВ, розташованого поблизу заземленої поверхні. 

Чисельний трасувальник виконує дискретизацію поверхні електрода на `N_seeds = 64` початкові точки випромінювання силових ліній. У кожній точці трасування за алгоритмом RK4 обчислюється локальна напруженість поля `|E|`. Якщо напруженість поля перевищує межу діелектричної міцності ізоляції (`3.0` МВ/м для повітря чи `15.0` МВ/м для елегазу SF6), програма автоматично підсвічує відповідну силову лінію червоним кольором як небезпечний канал діелектричного пробою.

### Порівняльний бенчмарк швидкодії мов розробки:
Для карти з `100` силових ліній тривалістю `1000` кроків кожна (`100 000` обчислень векторів поля RK4 у системі з 10 зарядів):

- **Python (чисті цикли Python):** `420` мілісекунд (через інтерпретаційні накладні витрати CPython).
- **Python + NumPy (векторизовані масиви):** `35` мілісекунд (прискорення у 12 разів за рахунок C-ядра NumPy).
- **C++ (однопотоковий виконавець g++ -O3):** `4.2` мілісекунди (прискорення у 100 разів порівняно з чистим Python).
- **C++ + OpenMP (8 ядер CPU):** `0.7` мілісекунд (прискорення у 600 разів, що забезпечує інтерактивний рендеринг у реальному часі зі швидкістю понад 1000 кадрів на секунду).

Цей порівняльний аналіз показує, що для інтерактивних графічних інструментів наочного навчання доречно використовувати Python з бібліотеками Matplotlib/NumPy, тоді як для промислових CAD-систем розрахунку ізоляції високовольтного обладнання критичні модулі трасування необхідно реалізовувати мовою C++ з використанням багатопотоковості та SIMD-інструкцій.

### Архітектура програмного забезпечення та патерни проектування
У промислових симуляторах електромагнітних полів клас трасування розробляється з дотриманням принципів об'єктно-орієнтованого проектування (SOLID). Інтерфейс обчислювача полів абстрагується за допомогою шаблону «Стратегія» (*Strategy Pattern*), що дозволяє підключати різні фізичні моделі полів — точкові заряди, аналітичні конформні мапування або сіткові розв'язки методом скінченних елементів (FEM) — без зміни основного коду трасувальника RK4.

Обробка виняткових ситуацій (таких як вихід силової лінії у нескінченність або потрапляння у нейтральну точку застою) здійснюється через RAII-обгортки (*Resource Acquisition Is Initialization*), що гарантує збереження всіх накопичених геодезичних точок лінії та відсутність витоків пам'яті навіть при передчасному перериванні обчислювального потоку.
