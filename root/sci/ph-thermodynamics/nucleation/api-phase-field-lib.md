# 🔌 Довідник інтерфейсу: C та C++ API бібліотеки фазового поля PhaseFieldLib

Ця вставка містить вичерпну документацію програмного інтерфейсу (API) бібліотеки `PhaseFieldLib`, призначеної для чисельного розв'язку нелінійних континуальних рівнянь Кана—Гілліарда та Аллена—Кана на двовимірних та тривимірних сітках. Ми наведемо детальний аналіз сигнатур функцій мовою C, ідіоматичний C++20 обгортковий інтерфейс, структуру параметрів, правила потокобезпечності, обробку помилок, інтеграцію з мовою Python та приклад використання.

---

### 1. Загальна архітектура бібліотеки та специфікація типів

Загальна архітектура бібліотеки `PhaseFieldLib` побудована за принципом двошарового поділу відповідальності між обчислювальним ядром та високорівневими абстракціями. Такий підхід забезпечує максимальну продуктивність виконання на низькому рівні разом із високим рівнем безпеки типів та зручністю використання у високорівневому коді.

При розробці високопродуктивних наукових бібліотек вибір чистого двошарового інтерфейсу є загальноприйнятим стандартом. Нижній рівень являє собою чисто Си-сумісну двонарну поверхню (C ABI), яка виключає проблеми сумісності компіляторів, декорації імен та розбіжностей ABI між різними версіями мови C++. Завдяки цьому обчислювальний модуль може бути легко скомпільований у вигляді динамічної бібліотеки та завантажений у будь-яке обчислювальне середовище.

Верхній рівень бібліотеки являє собою сучасну обгортку мовою C++20, створену за принципом *zero-overhead abstraction* (абстракції з нульовими накладними витратами). Всі методи C++ обгортки вбудовуються безпосередньо у виклики Си-функцій, ліквідуючи будь-які проміжні витрати на виклики віртуальних функцій або додаткову індирекцію вказівників.

Розробка такого двошарового API дозволяє досягти універсальності: низькорівневе ядро можна легко портувати на системи з підтримкою графічних прискорювачів GPU без зміни зовнішнього інтерфейсу для кінцевих користувачів. Практичний досвід підтверджує високу ефективність цієї схеми при вирішенні масштабних задач фазового поля.

Крім того, дана архітектурна модель дозволяє розробникам будувати власні модулі аналізу даних поверх базового чисельного ядра. Використання стандартних C ABI типів уможливлює зв'язування з найширшим спектром мов програмування та обчислювальних платформ.

#### Двошарова архітектура бібліотеки

1. **Нижній рівень (C ABI):** високопродуктивне обчислювальне ядро з префіксом `pf_`, написане на чистому C99 для забезпечення повної ABI-сумісності з будь-якими мовами програмування (Python, Fortran, Rust, Julia, MATLAB).
2. **Верхній рівень (C++20 API):** об'єктно-орієнтований C++20 заголовочний інтерфейс у просторі назв `phasefield::`, який забезпечує RAII-управління пам'яттю, роботу із неволодіючими зрізами `std::span`, безвиняткову обробку помилок та підтримку статичного поліморфізму.

#### Детальний аналіз структури конфігурації `pf_config_t`

Структура `pf_config_t` слугує єдиним контейнером для передачі всіх географічних та фізичних параметрів моделі фазового поля. Вона об'єднує розмірність сітки `nx` та `ny`, які задають кількість дискретних вузлів уздовж кожної просторової осі.

Крок сітки `dx` визначає просторову роздільну здатність. З фізичної точки зору, крок `dx` повинен бути достатньо малим, щоб розмита міжфазна межа товщиною `W = √(2κ)` описувалася принаймні 4–6 вузлами сітки. Якщо крок `dx` обрано занадто великим, міжфазна межа стає гострою на сітці, що призводить до чисельного ефекту «залипання» межі (так званого сіткового анізотропного пінінгу).

Параметр `dt` задає дискретний крок інтегрування за часом. Оскільки рівняння Кана—Гілліарда містить четверту просторову похідну, вибір кроку `dt` строго обмежений умовою стійкості фон Неймана.

Градієнтний коефіцієнт `kappa` (`κ`) визначає питому поверхневу енергію міжфазної межі. Збільшення значення `κ` призводить до потовщення перехідного шару між фазами та зростання міжфазного натягу.

Параметр `mobility` (`M`) визначає кінетичну рухливість компонентів. У найпростішій формулюванні мобільність є сталою величиною, проте у складніших фазових моделях вона може залежати від локальної концентрації чи температури.

Прапорець `use_openmp` управляє вибором паралельного режиму виконання. При значенні `1` обчислювальне ядро розподіляє просторові цикли між доступними ядрами центрального процесора за допомогою технології OpenMP.

:::tabs
=== C
```c
typedef struct {
    size_t nx;            /* Кількість вузлів по осі X */
    size_t ny;            /* Кількість вузлів по осі Y */
    double dx;            /* Крок сітки h (безрозмірний) */
    double dt;            /* Крок часової інтеграції Δt */
    double kappa;         /* Градієнтний коефіцієнт κ (енергія межі) */
    double mobility;      /* Мобільність атомів M */
    int use_openmp;       /* Прапорець ввімкнення паралелізму OpenMP (1 або 0) */
} pf_config_t;
```

### 2. Повний опис функцій Си-інтерфейсу (C API)

Усі C-функції бібліотеки розроблені за стандартами строгої реентрабельності та потокобезпечності. Вони не використовують внутрішніх глобальних або статичних мутабельних змінних. Кожна функція приймає вказівник на екземпляр сітки і повертає цілочисельний код помилки `pf_error_t`.

#### `pf_grid_create` — Виділення ресурсів та ініціалізація структури сітки

Функція `pf_grid_create` виконує повний цикл створення об'єкта 2D сітки. Вона виділяє пам'ять під непрозору структуру `pf_grid_2d_t` та три внутрішні двовимірні масиви: поле концентрації `c`, поле хімічного потенціалу `μ` та проміжний буфер оновлення `c_next`.

Для досягнення максимальної швидкості обчислень виділення пам'яті здійснюється через системний виклик `posix_memalign` (або `_aligned_malloc` на платформі Windows) з вирівнюванням адреси за межею 64 байти. Це ґарантує, що векторні SIMD-інструкції (AVX-512 та AVX2) завантажують дані з пам'яті у процесорні регістри за один такт без додаткових штрафних затримок невирівняного доступу.

- **Сигнатура:**
:::tabs
=== C
```c
int pf_grid_create(pf_grid_2d_t** grid, const pf_config_t* config);
```
=== C++
```cpp
// C++ RAII-конструктор класу створює та ініціалізує сітку
explicit PhaseFieldSolver2D(const pf_config_t& config);
```
:::

- **Детальний опис параметрів:**
  - `grid`: Подвійний вказівник на непрозору структуру сітки. У разі успіху функція записує сюди адресу виділеного об'єкта.
  - `config`: Вказівник на заповнену структуру конфігурації.
- **Логіка перевірки помилок:** Якщо `grid` або `config` дорівнюють `NULL`, функція негайно повертає `PF_ERR_INVALID_ARG`. Якщо параметри `nx`, `ny`, `dx`, `dt`, `kappa` або `mobility` мають від'ємні або нульові значення, повертається `PF_ERR_INVALID_ARG`. Якщо системі не вистачає оперативної пам'яті для виділення масивів, повертається `PF_ERR_OUT_OF_MEMORY`.

#### `pf_grid_destroy` — Безпечне звільнення пам'яті

Функція `pf_grid_destroy` виконує коректну деалокацію всіх виділених вирівняних буферів та самої структури сітки.

- **Сигнатура:**
:::tabs
=== C
```c
int pf_grid_destroy(pf_grid_2d_t* grid);
```
=== C++
```cpp
// У C++ деструктор std::unique_ptr викликає pf_grid_destroy автоматично
~PhaseFieldSolver2D() = default;
```
:::

- **Опис виконання:** Функція послідовно викликає звільнення пам'яті для масивів `c`, `mu`, `c_next` та структури `grid`. Передавання нульового вказівника `NULL` є безпечним і не викликає аварійного завершення програми.

#### `pf_init_uniform_with_noise` — Генерація початкового стану

Функція `pf_init_uniform_with_noise` ініціалізує поле концентрації однорідним значенням із додаванням просторово білого шуму малої амплітуди.

- **Сигнатура:**
:::tabs
=== C
```c
int pf_init_uniform_with_noise(pf_grid_2d_t* grid, double c_mean, double noise_amp);
```
=== C++
```cpp
void initialize_uniform(double c_mean = 0.0, double noise_amp = 0.1);
```
:::

- **Фізичний зміст:** Для запуску спінодального розпаду система повинна отримати первинні флуктуації складу. Функція заповнює кожен вузол значенням `c(i,j) = c_mean + δc`, де `δc` — псевдовипадкове число з рівномірного інтервалу `[− noise_amp / 2, + noise_amp / 2]`. Використання генератора Mersenne Twister (MT19937) забезпечує високу якість статистичного розподілу флуктуацій.

#### `pf_step_explicit` — Виконання одного кроку часової інтеграції

Функція `pf_step_explicit` реалізує один повний часовий крок інтегрування рівняння Кана—Гілліарда за двостадійною різничною схемою Ейлера.

- **Сигнатура:**
:::tabs
=== C
```c
int pf_step_explicit(pf_grid_2d_t* grid);
```
=== C++
```cpp
void step();
```
:::

- **Алгоритмічна послідовність:**
  1. На першому проході по сітці для кожного вузла обчислюється лапласіан концентрації `∇²c` за допомогою 5-точкового різничного шаблону і розраховується хімічний потенціал `μ = c³ − c − κ ∇²c`.
  2. На другому проході обчислюється лапласіан хімічного потенціалу `∇²μ` і виконується часове оновлення концентрації `c_next = c + Δt M ∇²μ`.
  3. Наприкінці здійснюється швидкий обмін вказівників між `c` та `c_next` без копіювання масивів.
- **Перевірка нестійкості:** Функція вимірює граничне значення `dt_max = dx⁴ / (8 M κ)`. Якщо фактичний крок `dt` у конфігурації перевищує це значення, обчислення перериваються з поверненням коду `PF_ERR_UNSTABLE_TIMESTEP`.

#### `pf_compute_free_energy` — Обчислення повної вільної енергії

Функція `pf_compute_free_energy` виконує розрахунок дискретного аналога функціонала вільної енергії Кана—Гілліарда по всьому об'єму сітки.

- **Сигнатура:**
:::tabs
=== C
```c
int pf_compute_free_energy(const pf_grid_2d_t* grid, double* out_energy);
```
=== C++
```cpp
[[nodiscard]] double get_free_energy() const;
```
:::

- **Опис інтегрування:** Сумуються об'ємні внески вільної енергії `(1/4)c⁴ − (1/2)c²` та градієнтні внески `(1/2)κ(∇c)²`. Результат множиться на площу комірки `dx²`. Повернуте значення використовується для перевірки виконання другого закону термодинаміки (`dF/dt <= 0`).

### 4. Детальний розбір C++ обгортки та шаблони проектування

Розглянемо ключові архітектурні рішення, закладені у реалізацію C++ класу `PhaseFieldSolver2D`.

#### 1. Управління ресурсами за принципом RAII

У Си-інтерфейсі розробник зобов'язаний вручну стежити за симетричністю викликів `pf_grid_create` та `pf_grid_destroy`. У випадку виникнення виключень або раннього повернення з функції легко припуститися витоку пам'яті.

У C++ реалізації використання `std::unique_ptr` із власним видалячем `GridDeleter` гарантує, що деструктор `pf_grid_destroy` буде викликаний автоматично при виході об'єкта `PhaseFieldSolver2D` з області видимості. Це повністю усуває загрозу витоків пам'яті навіть при генерації виключень у суміжному коді.

#### 2. Заборона небезпечного копіювання та підтримка переміщення

Оскільки об'єкт сітки володіє великими масивами динамічної пам'яті у купі, випадкове копіювання за умовчанням може призвести до подвійного звільнення пам'яті (*double free*) або неконтрольованого падіння продуктивності.

Тому для класу `PhaseFieldSolver2D` копіювальні конструктор та оператор присвоєння повинні бути явним чином видалені (`= delete`), тоді як конструктор переміщення (*move constructor*) забезпечує швидку передачу володіння ресурсом за час `O(1)`.

#### 3. Використання сучасного типу `std::span`

Метод `get_concentration_span` повертає безпечний неволодіючий зріз даних `std::span<const double>`. Це дозволяє передавати посилання на масив концентрації у зовнішні графічні або аналітичні процедури без створення додаткових копій векторів у пам'яті і з можливістю застосування методів стандартної бібліотеки `std::ranges`.

### 5. Потокобезпечність, паралелізм та інтеграція з іншими мовами

#### 1. Гарантії потокобезпечності (*Thread Safety Model*)

- **Незалежні об'єкти (Thread-safe for distinct instances):** Два або більше паралельних потоків виконання можуть одночасно викликати будь-які функції бібліотеки `PhaseFieldLib`, якщо кожному потоку передано власний незалежний екземпляр сітки `pf_grid_2d_t`.
- **Внутрішній паралелізм OpenMP:** Якщо прапорець `use_openmp` встановлено в `1`, функція `pf_step_explicit` самостійно розпаралелює внутрішні двовимірні цикли між ядрами центрального процесора за допомогою системного пулу потоків.
- **Заборона спільного редагування:** Одночасний виклик модифікуючих методів (`pf_step_explicit` або `pf_init_uniform_with_noise`) з різних потоків для одного й того самого об'єкта сітки без зовнішніх мутексів є суворо забороненим, оскільки це призводить до стану гонитви даних (*data race*).

#### 3. Поглиблений аналіз помилок та обробка виключень

Система діагностики помилок бібліотеки `PhaseFieldLib` базується на детермінованих кодах повернення enum `pf_error_t`. У C++ обгортці кожен код помилки перетворюється у відповідний тип стандартного виключення `std::runtime_error` або `std::invalid_argument`.

Код `PF_ERR_INVALID_ARG` вказує на логічну помилку у виклику функції (наприклад, виклик з вказівником `NULL` або передачу некоректного кроку сітки `dx <= 0`).

Код `PF_ERR_OUT_OF_MEMORY` генерується при вичерпанні оперативної пам'яті системи під час спроби створення сітки великої розмірності (наприклад, `4096 × 4096 × 4096` у 3D моделюванні).

Код `PF_ERR_UNSTABLE_TIMESTEP` виникає при автоматичній превентивній перевірці часового кроку `dt`. Обчислювальне ядро вираховує спектральну межу нестійкості фон Неймана і попереджає користувача про загрозу розбіжності.

Код `PF_ERR_DIVERGENCE` сигналізує про катастрофічне виникнення значень `NaN` або `Inf` у масиві концентрацій у процесі обчислень, що свідчить про накопичення чисельних похибок округлення або вихід системи за межі фізично припустимого діапазону.

Впровадження цієї системи кодів помилок забезпечує стійку роботу науково-дослідних комплексів і запобігає аварійним зупинкам при тривалих обчислювальних експериментах. Завдяки високій стандартизації кодів помилок бібліотека відповідає вимогам до промислових симуляційних систем і мінімізує час на зневадження кодів.

#### 4. Пастки при роботі з API та крайові випадки

1. **Нехтування перевіркою кодів повернення.** Завжди аналізуйте повернуте значення `pf_error_t`. Якщо під час симуляції через неправильно підібраний крок за часом виникає числова нестійкість (значення `NaN` або `Inf`), функція перериває роботу і повертає код `PF_ERR_DIVERGENCE`. Подальше виконання алгоритму над розбіжними масивами марнує час.
2. **Передача некоректних фізичних параметрів.** При кроці сітки `dx <= 0` або від'ємному коефіцієнті `kappa <= 0` функція створення сітки негайно переривається з кодом `PF_ERR_INVALID_ARG`.
3. **Витік пам'яті при роботі через Си-інтерфейс.** У разі використання викликів Си-функцій напряму без використання C++ обгортки пам'ятайте про обов'язковість виклику `pf_grid_destroy`. Виклик `pf_grid_create` у довготривалому циклі без звільнення ресурсів призведе до вичерпання оперативної пам'яті системи.
4. **Некоректна робота у багатопотоковому середовищі.** Виклик модифікуючих функцій з кількох потоків для однієї і тієї ж сітки без використання системних примітивів синхронізації (таких як `std::mutex` або `pthread_mutex_t`) призведе до невизначеної поведінки (*undefined behavior*) через руйнування цілісності внутрішніх масивів.

Завдяки дотриманню наведених стандартів проектування бібліотека `PhaseFieldLib` забезпечує високу надійність, гнучкість та обчислювальну ефективність при вирішенні складних наукових та інженерних задач комп'ютерного матеріалознавства та фізичної кінетики. Вона створює універсальну основу для розробки потужних прикладних симуляторів фазових переходів у матеріалознавстві, що спрощує створення сучасного наукового софту.
