# 📋 Інтерфейс та структура даних термодинамічного розв'язувача

Цей довідник визначає специфікацію програмного інтерфейсу (API), конвенції пам'яті, структури даних, фізичні константи, правила знаків та контракти викликів для модулів розрахунку Першого закону термодинаміки. Інтерфейс призначено для обчислення термодинамічних станів, ізопроцесів і термодинамічних циклів як у закритих системах (зміна внутрішньої енергії, теплота, робота розширення), так і у відкритих проточних системах (ентальпійний баланс, технічна робота, потік маси).

### 1. Фундаментальні константи та правила знаків

#### Таблиця термодинамічних констант
Нижче наведено значення фізичних констант, прийняті у системі SI згідно з рішеннями XXVI Генеральної конференції з мір і ваг (CGPM):

| Символ | Назва константи | Значення в SI | Одиниця вимірювання |
| :--- | :--- | :--- | :--- |
| `R` | Універсальна газова стала | `8.314462618` | Дж / (моль · К) |
| `N_A` | Число Авогадро | `6.02214076 × 10²³` | моль⁻¹ |
| `k_B` | Стала Больцмана (`R / N_A`) | `1.380649 × 10⁻²³` | Дж / К |
| `V_m0` | Молярний об'єм ідеального газу (273.15 K, 101 325 Па) | `0.022413996` | м³ / моль |
| `P_std` | Стандартний атмосферний тиск | `101 325.0` | Па (Н/м²) |
| `T_std` | Стандартна абсолютна температура | `273.15` | К (0 °C) |

#### Конвенція знаків Першого закону термодинаміки
Залежно від галузі вживають дві системи знаків. Бібліотечний розв'язувач строго дотримується **класичної інженерної конвенції (Клаузіус / термодинаміка двигунів)**, де корисна робота розширення газу вважається додатною:

| Величина | Знак `+` (Позитивний) | Знак `-` (Негативний) |
| :--- | :--- | :--- |
| **Теплота `Q`** | Тепло **підводиться** до системи від термостата | Тепло **відводиться** від системи |
| **Робота `W`** | Система **виконує роботу** над довкіллям (розширення) | Зовнішні сили **виконують роботу** над системою (стиснення) |
| **Внутрішня енергія `ΔU`** | Температура / енергія системи **зростає** (`U₂ > U₁`) | Температура / енергія системи **падає** (`U₂ < U₁`) |

У фізико-хімічній конвенції IUPAC робота виражається як `W_IUPAC = -W_eng`, а Перший закон записується у формі `ΔU = Q + W_IUPAC`. Розв'язувач забезпечує функціональні прапорці конверсії між цими системами для забезпечення сумісності з хімічними симуляторами.

### 2. Специфікація структур даних та архітектура пам'яті

Для забезпечення високої обчислювальної продуктивності та сумісності з бінарними викликами (ABI) структури даних розділено на три рівні:
1. **Рівень стану (`ThermoState` / `State`):** Містить фундаментальні макроскопічні величини `P`, `V`, `T`. Використовує подвійну точність `double` (64 біти) для забезпечення відносної похибки не більше `10⁻¹²`.
2. **Рівень середовища (`GasProperties`):** Зберігає постійні фізико-хімічні характеристики робочого тіла (молярну масу, число ступенів вільності, молярні теплоємності та показник адіабати).
3. **Рівень процесу (`ProcessRecord`):** Зберігає повний термодинамічний паспорт відбутого процесу (початковий стан, кінцевий стан, обсяг виконаної роботи `W`, підведене тепло `Q`, зміну внутрішньої енергії `ΔU` та зміну ентальпії `ΔH`).

#### Бінарна сумісність та ABI C-інтерфейсу
Заголовочний файл `thermo_api.h` розроблено за стандартом C99 з урахуванням прямої сумісності з C++. Усі структури є POD-типами (*Plain Old Data*) із фіксованим вирівнюванням полів по межі 8 байтів. Це дозволяє використовувати бібліотеку безпосередньо у викликах FFI з інших мов (Python, Rust, C#, Go).

:::tabs
```c
/* thermo_api.h - Заголовочний файл C-інтерфейсу термодинамічного розв'язувача */
#ifndef THERMO_API_H
#define THERMO_API_H

#ifdef __cplusplus
extern "C" {
#endif

/* Помилки виконання розрахунку */
typedef enum {
    THERMO_SUCCESS = 0,
    THERMO_ERR_INVALID_PRESSURE = -1,
    THERMO_ERR_INVALID_VOLUME = -2,
    THERMO_ERR_INVALID_TEMP = -3,
    THERMO_ERR_INVALID_MOLES = -4,
    THERMO_ERR_CONVERGENCE_FAILED = -5
} ThermoStatus;

/* Макроскопічний стан системи */
typedef struct {
    double p; /* Абсолютний тиск [Па] */
    double v; /* Повний об'єм [м³] */
    double t; /* Абсолютна температура [К] */
} ThermoState;

/* Термодинамічні властивості робочого тіла (газу) */
typedef struct {
    double molar_mass;          /* Молярна маса [кг/моль] */
    double degrees_of_freedom;  /* Число ступенів вільності i (3, 5, 6) */
    double c_v;                 /* Молярна ізохорна теплоємність [Дж/(моль·К)] */
    double c_p;                 /* Молярна ізобарна теплоємність [Дж/(моль·К)] */
    double gamma;               /* Показник адіабати (c_p / c_v) */
} GasProperties;

/* Результат розрахунку термодинамічного процесу */
typedef struct {
    ThermoState initial_state;
    ThermoState final_state;
    double n_moles;     /* Кількість речовини [моль] */
    double work;        /* Механічна робота W [Дж] */
    double heat;        /* Передане тепло Q [Дж] */
    double delta_u;     /* Зміна внутрішньої енергії dU [Дж] */
    double delta_h;     /* Зміна ентальпії dH [Дж] */
} ProcessRecord;

#ifdef __cplusplus
}
#endif

#endif /* THERMO_API_H */
```
```cpp
// thermo_api.hpp - Заголовочний файл C++23 інтерфейсу термодинамічного розв'язувача
#ifndef THERMO_API_HPP
#define THERMO_API_HPP

#include <expected>
#include <string_view>
#include <concepts>

namespace thermo::api {

enum class Status {
    Success = 0,
    InvalidPressure,
    InvalidVolume,
    InvalidTemperature,
    InvalidMoles,
    ConvergenceFailed
};

struct State {
    double p{0.0}; // [Па]
    double v{0.0}; // [м³]
    double t{0.0}; // [К]
};

struct GasProperties {
    double molar_mass{0.02897};        // [кг/моль]
    double degrees_of_freedom{5.0};    // i
    double c_v{20.786};                // [Дж/(моль·К)]
    double c_p{29.101};                // [Дж/(моль·К)]
    double gamma{1.400};               // C_p / C_v
};

struct ProcessRecord {
    State initial_state;
    State final_state;
    double n_moles{1.0};
    double work{0.0};     // W [Дж]
    double heat{0.0};     // Q [Дж]
    double delta_u{0.0};  // dU [Дж]
    double delta_h{0.0};  // dH [Дж]
};

} // namespace thermo::api

#endif // THERMO_API_HPP
```

### 3. Детальний опис помилок та стратегій обробки

Коди помилок переліку `ThermoStatus` / `thermo::api::Status` гарантують передбачувану обробку некоректних даних без передчасного аварійного завершення програми:

1. **`THERMO_ERR_INVALID_PRESSURE` (`Status::InvalidPressure`):** Виникає, якщо тиск `P ≤ 0`. Негативний або нульовий абсолютний тиск є фізично неможливим для термодинамічних систем.
2. **`THERMO_ERR_INVALID_VOLUME` (`Status::InvalidVolume`):** Виникає при спробі обчислити стан із `V ≤ 0`.
3. **`THERMO_ERR_INVALID_TEMP` (`Status::InvalidTemperature`):** Повертається, якщо температура `T ≤ 0 K` (досягнення або перетин абсолютного нуля заборонено Третім законом термодинаміки).
4. **`THERMO_ERR_INVALID_MOLES` (`Status::InvalidMoles`):** Виникає при кількості речовини `n ≤ 0`.
5. **`THERMO_ERR_CONVERGENCE_FAILED` (`Status::ConvergenceFailed`):** Виникає у розв'язувачах реальних газів Ван дер Ваальса чи Редліха — Квонга, якщо чисельний метод Ньютона — Рафсона не збігається за встановлене число ітерацій.

### 4. Контракт функцій розрахунку процесів (API Contract)

#### 1. Розрахунок стану за рівнянням Клапейрона — Менделєєва
- **Функція:** `thermo_state_calc_missing()`
- **Вхід:** Два відомих параметри з трійки `(P, V, T)` та кількість молей `n`.
- **Вихід:** Повністю заповнена структура `ThermoState`.
- **Гарантія:** `P · V == n · R · T` з відносною точністю до `10⁻⁹`.
- **Передумова:** Вхідні параметри повинні бути суворо додатними (`P > 0`, `V > 0`, `T > 0`, `n > 0`).

:::tabs
```c
ThermoStatus thermo_state_from_pv(double p, double v, double n_moles, ThermoState *out_state);
ThermoStatus thermo_state_from_pt(double p, double t, double n_moles, ThermoState *out_state);
ThermoStatus thermo_state_from_vt(double v, double t, double n_moles, ThermoState *out_state);
```

#### 2. Розрахунок класичних термодинамічних процесів
- **Функція:** `thermo_process_solve()`
- **Вхід:** `GasProperties`, початковий `ThermoState`, тип процесу, цільовий параметр (кінцевий `V` або `T`).
- **Вихід:** Заповнений `ProcessRecord` із розрахованими `work`, `heat`, `delta_u`, `delta_h`.
- **Математичні інваріанти:**
  - `ProcessRecord.heat == ProcessRecord.delta_u + ProcessRecord.work` (Перший закон термодинаміки).
  - `ProcessRecord.delta_h == ProcessRecord.delta_u + (P2*V2 - P1*V1)` (Зв'язок ентальпії та внутрішньої енергії).

:::tabs

### 6. Перший закон для відкритих систем із потоком речовини

У стаціонарних відкритих системах (компресори, турбіни, сопла, теплообмінники) речовина неперервно протікає крізь контрольний об'єм. Баланс енергії Першого закону на одиницю маси потоку виражається через **ентальпію** `h = u + P · v`:

```
q - w_технічна = (h₂ - h₁) + ½ · (v₂² - v₁²) + g · (z₂ - z₁)
```

Де:
- `q` — питоме тепло, підведене до контрольного об'єму [Дж/кг];
- `w_технічна` — корисна технічна робота на валу турбіни чи компресора [Дж/кг];
- `h = u + P·v` — питома ентальпія потоку [Дж/кг];
- `½ (v₂² - v₁²)` — зміна питомої кінетичної енергії потоку зі швидкістю `v` [Дж/кг];
- `g (z₂ - z₁)` — зміна питомої потенціальної енергії потоку на висоті `z` [Дж/кг].

#### Спеціальні випадки для елементів теплових машин:
1. **Парова або газова турбіна (`q ≈ 0`, `ΔE_кінет ≈ 0`):** `w_технічна = h₁ - h₂` (технічна робота виробляється за рахунок падіння ентальпії).
2. **Компресор або насос (`q ≈ 0`):** `w_технічна = h₂ - h₁` (технічна робота витрачається на підвищення ентальпії та тиску).
3. **Дроселювання (дросельний вентиль, ефект Джоуля — Томсона):** `q = 0`, `w = 0` `⇒` `h₁ = h₂` (**ізоентальпійний процес**).
4. **Теплообмінник (котел, конденсатор):** `w_технічна = 0` `⇒` `q = h₂ - h₁` (передане тепло дорівнює зміні ентальпії теплоносія).

### 7. Інтеграція з реальним програмним забезпеченням

Для використання бібліотеки в реальних інженерних пакетах (наприклад, системах автоматизованого проектування газових мереж чи розрахунку автомобільних двигунів) дотримуються таких правил:

1. **Потокобезпечність (Thread-Safety):** Усі обчислювальні функції розв'язувача є чистими функціями (*pure functions*), які не мають внутрішнього стану та глобальних змінних. Вони можуть безпечно викликатися паралельно з багатьох потоків без додаткових блокувань.
2. **Точність обчислень та IEEE 754:** Усі проміжні значення розраховуються у 64-бітному форматі `double`. При виконанні циклічних розрахунків рекомендується перевіряти сумарний енергетичний баланс `∑ ΔU == 0` із допуском `ε = 10⁻⁸`.
3. **Конверсія одиниць вимірювання:** API працює виключно у базових одиницях SI (Паскалі, кубічні метри, Кельвіни, Джоулі, молі). Перетворення із барів, атмосфер, літрів чи градусів Цельсія повинно виконуватися на рівні вхідних обгортальних модулів до виклику ядра розв'язувача.
