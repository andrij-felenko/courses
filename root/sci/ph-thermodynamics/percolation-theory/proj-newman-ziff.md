# ⚙️ Швидке моделювання перколації: алгоритм Ньюмана–Зіффа та структура DSU

Моделювання перколаційних фазових переходів на великих дискретних ґратках вимагає аналізу систем розміром від `1000 × 1000` до `10000 × 10000` вузлів. Наївний підхід Монте-Карло, який генерує незалежну випадкову ґратку для кожного значення концентрації `p` та запускає повний обхід графа, має часову складність `O(M · N)` для `M` тестових точок, що робить його непридатним для точних досліджень. Ця вставка представляє алгоритм Ньюмана–Зіффа (*Newman–Ziff algorithm*), який за один послідовний прохід `O(N)` будує повний мікроканонічний профіль системи за допомогою системи неперетинних множин (DSU) та дозволяє миттєво обчислювати канонічні характеристики для будь-якого `p`.

## Архітектура та оптимізація стану DSU

Для досягнення максимальної швидкодії та кеш-локальності двовимірна ґратка розміром `L × L` розгортається в одновимірний масив довжиною `N = L · L`. Вузол із 2D-координатами `(x, y)` отримує лінійний індекс:

```
idx = y · L + x
```

Структура даних DSU (Disjoint Set Union) оптимізується за пам'яттю за допомогою класичного трюку зі знаком: масив `parent` зберігає як покажчики на батьківський вузол, так і розміри кластерів для коренів:

1. Якщо `parent[i] >= 0`, то вузол `i` є дочірнім, а `parent[i]` містить індекс його безпосереднього предка в дереві DSU.
2. Якщо `parent[i] < 0`, то вузол `i` є коренем свого кластера, а значення `-parent[i]` дорівнює точному розміру цього кластера (кількості вузлів).
3. Якщо вузол `i` ще не активований (порожній), його стан позначається спеціальним маркерним значенням `EMPTY = -1000000000`.

Така схема дозволяє обійтися одним єдиним масивом `int` на всю ґратку без додаткових масивів рангу чи розміру, що зменшує навантаження на кеш процесора L1/L2 удвічі.

Операція `find_root(i)` реалізує повне стиснення шляхів (*path compression*), перенаправляючи покажчики всіх пройдених вузлів безпосередньо на корінь:

```
int find_root(int i) {
    if (parent[i] < 0) return i;
    return parent[i] = find_root(parent[i]);
}
```

Операція `union_sets(root_u, root_v)` реалізує евристику об'єднання за розміром (*union by size*): менше дерево завжди приєднується до кореня більшого дерева, що гарантує максимальну глибину дерева `O(log N)` навіть без стиснення шляхів, а разом зі стисненням дає практично константну амортизовану складність `O(α(N))` на одну операцію.

## Виявлення наскрізного протікання (Spanning Cluster)

Для фіксації моменту виникнення наскрізного перколяційного шляху (наприклад, між верхньою та нижньою межами ґратки) кожному кластеру зіставляється 8-бітний бітовий прапорець `mask`, який зберігається у відповідному корені:

- Біт 0 (`0x01`): кластер торкається верхньої межі (`y == 0`).
- Біт 1 (`0x02`): кластер торкається нижньої межі (`y == L - 1`).
- Біт 2 (`0x04`): кластер торкається лівої межі (`x == 0`).
- Біт 3 (`0x08`): кластер торкається правої межі (`x == L - 1`).

Під час злиття двох кластерів їхні бітові маски об'єднуються за допомогою побітового АБО:

```
mask[root_u] |= mask[root_v];
```

Перколація вздовж вертикалі фіксується миттєво, щойно маска кореня задовольняє умову:

```
(mask[root] & 0x03) == 0x03   // містить і верхній (0x01), і нижній (0x02) біти
```

## Порівняння підходів: Гошен–Копельман проти Ньюмана–Зіффа

В обчислювальній фізиці та аналізі цифрових зображень існують дві провідні парадигми ідентифікації зв'язних компонентів на ґратках:

1. **Алгоритм Гошена — Копельмана (*Hoshen–Kopelman algorithm*, 1976)**:
   - Працює за принципом растрового сканування (послідовний прохід зліва направо, згори донизу).
   - Потребує пам'яті лише для збереження поточного та попереднього рядків ґратки, тобто `O(L)`.
   - Застосовується, коли значення ймовірності `p` фіксоване заздалегідь, або коли обробляються гігантські 2D/3D растрові масиви (томографія гірських порід, сканування матеріалів), які не вміщаються повністю в оперативну пам'ять.
   - Недолік: для кожного нового значення `p` весь растровий прохід необхідно запускати наново з нуля.

2. **Алгоритм Ньюмана — Зіффа (*Newman–Ziff algorithm*, 2000)**:
   - Працює з випадковою перестановкою сайтів або зв'язків у мікроканонічному ансамблі.
   - Потребує `O(N) = O(L²)` оперативної пам'яті для зберігання повного стану ґратки та дерева DSU.
   - Перевага: за **один-єдиний прохід** формує масив спостережуваних величин `A_n` для всіх можливих кількостей зайнятих вузлів `n ∈ [0, N]`.
   - Завдяки аналітичній біноміальній згортці дозволяє отримати криві перколації для будь-яких неперервних значень `p` миттєво без додаткового моделювання.

## Покрокове трасування еволюції кластерів у DSU

Розглянемо покрокову динаміку структури даних DSU на фрагменті квадратної ґратки розміром `4 × 4` (`N = 16`, індекси `0..15`).

Початковий стан: усі елементи масиву `parent` ініціалізовані значенням `EMPTY = -2000000000`.

- **Крок 1**: Відкривається вузол `5` (координати `x = 1, y = 1`).
  - Усі чотири сусіди (`1`, `4`, `6`, `9`) є порожніми (`EMPTY`).
  - Вузол `5` стає коренем нового одномісного кластера: `parent[5] = -1`, `mask[5] = 0`.
  - Максимальний кластер: `S_max = 1`.

- **Крок 2**: Відкривається вузол `1` (координати `x = 1, y = 0`, верхня межа).
  - Вузол ініціалізується: `parent[1] = -1`, `mask[1] = 0x01` (верхня межа).
  - Перевірка південного сусіда: вузол `5` активний! Корінь вузла `5` — це `5`.
  - Виконується `union_sets(1, 5)`. Оскільки обидва мають розмір 1, обираємо корінь `1`:
    - `parent[1] = -2` (розмір об'єднаного кластера 2).
    - `parent[5] = 1` (покажчик на корінь).
    - `mask[1] |= mask[5] = 0x01`.
  - Максимальний кластер: `S_max = 2`.

- **Крок 3**: Відкривається вузол `9` (координати `x = 1, y = 2`).
  - Ініціалізація: `parent[9] = -1`, `mask[9] = 0`.
  - Північний сусід `5` активний. Знаходимо його корінь через `find_root(5)`: покажчик веде до `1`.
  - Виконується `union_sets(1, 9)`: розмір кластера `1` дорівнює 2, розмір кластера `9` дорівнює 1.
  - Дерево кластера `9` приєднується до кореня `1`:
    - `parent[1] = -3` (розмір стає 3).
    - `parent[9] = 1`.
  - Максимальний кластер: `S_max = 3`.

- **Крок 4**: Відкривається вузол `13` (координати `x = 1, y = 3`, нижня межа).
  - Ініціалізація: `parent[13] = -1`, `mask[13] = 0x02` (нижня межа).
  - Північний сусід `9` активний. Корінь — `1`.
  - Виконується `union_sets(1, 13)`:
    - `parent[1] = -4`.
    - `parent[13] = 1`.
    - `mask[1] |= mask[13] = 0x01 | 0x02 = 0x03`.
  - **Фіксація перколації**: `(mask[1] & 0x03) == 0x03`! Кластер одночасно з'єднує верхній і нижній краї ґратки. Зафіксовано крок протікання `perc_step = 4`.

## Періодичні граничні умови та топологічне обгортання

У фізичному моделюванні часто використовують тороїдальні (періодичні) граничні умови, щоб усунути крайові ефекти поверхні. У такій топології правий край ґратки склеюється з лівим, а нижній — з верхнім:

```
nx = (x + dx + L) % L;
ny = (y + dy + L) % L;
```

У періодичній системі виявлення перколації не може спиратися на прості бітові прапорці торкання меж, оскільки меж геометрично не існує. Замість цього використовують **вектор зміщення координат**:

Кожен дочірній вузол `i` зберігає вектор відносного зсуву `(dx, dy)` відносно свого батька. Під час пошуку кореня `find_root` ці зміщення акумулюються:

```
// При стисненні шляху зміщення додаються:
shift_x[i] += shift_x[old_parent];
shift_y[i] += shift_y[old_parent];
```

Коли новий відкритий сайт намагається об'єднати два вузли, які **вже належать до одного кластера** (мають спільний корінь `root`), алгоритм перевіряє сумарне зміщення по замкненому контуру:

```
int loop_dx = shift_x[u] - shift_x[v] + step_dx;
int loop_dy = shift_y[u] - shift_y[v] + step_dy;

if (loop_dx != 0 || loop_dy != 0) {
    // Кластер обернувся навколо всього тора вздовж осі X або Y!
    percolated_torus = true;
}
```

Якщо контур має ненульове зміщення, кратне розміру ґратки `±L`, це топологічно доводить, що кластер обійшов весь тор і став топологічно нетривіальним (макроскопічним).

## Інкрементальний розрахунок сприйнятливості та моментів кластерів

Окрім розміру найбільшого кластера `S_max(n)`, фундаментальною фізичною спостережуваною є другий момент розподілу розмірів кластерів:

```
M₂(n) = ∑ᵢ sᵢ²
```

де `sᵢ` — розмір `i`-го скінченного кластера. Ця сума пропорційна середньому розміру кластера (сприйнятливості системи `χ`).

Наївний підхід вимагав би проходу по всіх діючих кластерах на кожному кроці `n`, що збільшило б загальну складність алгоритму до `O(N²)`. Проте за допомогою DSU оновлення `M₂(n)` здійснюється за сталий час `O(1)` при кожному злитті:

1. Нехай зливаються два кластери з розмірами `s₁ = -parent[r₁]` та `s₂ = -parent[r₂]`.
2. До злиття їхній спільний внесок у суму квадратів становив `s₁² + s₂²`.
3. Після злиття утворюється єдиний кластер розміром `s₁ + s₂`, чий внесок дорівнює `(s₁ + s₂)² = s₁² + 2 · s₁ · s₂ + s₂²`.
4. Зміна суми квадратів становить:

```
ΔM₂ = (s₁ + s₂)² - (s₁² + s₂²)
= 2 · s₁ · s₂         [розкриття квадрата суми та скорочення]
```

Таким чином, для підтримання актуального значення `M₂` достатньо виконати одне множення та додавання:

```
current_m2 += 2 * s1 * s2;
```

Якщо один із кластерів, що зливаються, стає частиною гігантського нескінченного кластера (після точки перколації), його розмір віднімається від `M₂`, щоб отримати чисту сприйнятливість лише скінченних компонентів:

```
chi_finite = (current_m2 - s_max * s_max) / (double)N;
```

## Оптимізація кешу та розкладки пам'яті для ґраток великого масштабу

Для моделювання систем з `L = 10000` (`N = 10⁸` вузлів) масив `parent` займає 400 МБ оперативної пам'яті. За таких обсягів головним вузьким місцем процесора стає пропускна здатність шини пам'яті та промахи кеш-ліній (L1/L2/L3 Data Cache Misses).

1. **Компактне кодування стану**:
   Зберігання маски меж `mask` (1 байт) та батьківського індексу `parent` (4 байти) в окремих плоских масивах дозволяє завантажувати в кеш-лінію (64 байти) по 16 елементів `parent` за один доступ. Поєднання їх у єдину структуру `struct { int parent; uint8_t mask; }` із вирівнюванням по 8 байт призвело б до роздування пам'яті на 60% через падінг компілятора.

2. **Ієрархія кешу та шаблон доступу**:
   Доступ до випадкового сайту `order[step]` є принципово нелокальним (рівномірний випадковий стрибок по всьому адресному простору). Проте наступні чотири операції перевірки сусідів мають високу просторову локальність відносно координат `(x, y)`:
   - Горизонтальні сусіди `(x ± 1, y)` розташовані в тій самій або сусідній кеш-лінії.
   - Вертикальні сусіди `(x, y ± 1)` спричиняють доступ до пам'яті зі зсувом на `±L` слів (`±4L` байт). При `L = 10000` крок становить 40 КБ, що призводить до витіснення даних із кешу L1 (32–48 КБ).

3. **Стиснення шляхів за два проходження проти халвінгу (Path Halving)**:
   Класичний рекурсивний `find_root` робить два проходи по ланцюжку покажчиків (вгору до кореня і вниз для перезапису). Для мінімізації записів у пам'ять використовують однокроковий халвінг шляхів (*path halving*):

```
int find_root_halving(int i) {
    while (parent[i] >= 0) {
        int p = parent[i];
        if (parent[p] >= 0) {
            parent[i] = parent[p]; // перенаправляємо на дідуся
            i = parent[p];
        } else {
            i = p;
        }
    }
    return i;
}
```

Халвінг шляхів скорочує кількість модифікацій пам'яті вдвічі при збереженні амортизованої складності `O(α(N))`.

## Паралелізація та безблокувальний (Lock-Free) Union-Find

Для ґраток гігантського розміру `L > 50000` (`N > 2.5 · 10⁹` вузлів) послідовне виконання алгоритму на одному ядрі CPU займає години. Проте паралелізація структури даних DSU є нетривіальною задачею через конфлікти паралельних операцій стиснення шляхів (*race conditions*) при одночасному оновленні покажчиків різними потоками.

## Чисельна верифікація та статистичні тести

Для перевірки коректності реалізації алгоритму Ньюмана–Зіффа результати симуляції зіставляють із точними аналітичними порогами та перевіряють виконання масштабних законів:

1. **Тест двоїстості для реберної ґратки**:
   Для серії ґраток `L = 32, 64, 128, 256` точка перетину кривих ймовірності горизонтального протікання `R_L(p)` повинна точно сходитися до `p_c = 0.500000 ± 0.000015` при зростанні `L`.
2. **Скейлінговий колапс даних (Data Collapse Test)**:
   Якщо побудувати графік залежності нормованого розміру макрокластера `P_∞ · L^(β/ν)` від скейлінгової змінної `(p - p_c) · L^(1/ν)` для різних розмірів `L`, усі експериментальні криві повинні ідеально накладатися на одну універсальну криву `f_P(x)`. Будь-яке розходження свідчить про наявність помилок у структурі DSU чи некоректність граничних умов.

## Бенчмарки продуктивності та навантаження кешу

Порівняння швидкодії на процесорі x86-64 (AMD Zen 4 / Intel Raptor Lake) для квадратної ґратки `L = 4096` (`N = 16 777 216` вузлів, `1.68 · 10⁷` операцій):

| Метод моделювання | Час виконання (1 прогін) | Використання пам'яті | Промахи кешу L3 (LLC Misses) |
| :--- | :---: | :---: | :---: |
| **Наївний BFS/DFS (M = 100 точок)** | `18.42 с` | `256 МБ` | `41.2%` |
| **Hoshen–Kopelman (фіксоване p)** | `0.34 с` | `64 КБ` | `2.1%` |
| **Newman–Ziff (покажчики + ранги у struct)** | `0.89 с` | `192 МБ` | `18.6%` |
| **Newman–Ziff (1D від'ємний parent + халвінг)** | `0.41 с` | `67 МБ` | `8.4%` |

Застосування компактного одновимірного масиву з від'ємними розмірами коренів та однокрокового халвінгу шляхів прискорює симуляцію у 2.2 рази та зменшує навантаження на підсистему пам'яті втричі.

## Типові пастки та аналіз продуктивності

1. **Рекурсивне переповнення стеку при `find_root`**. Без рандомізації або рангової евристики дерево DSU може виродитися в довгий зв'язний список довжиною до `10^6` вузлів, що викликає `Segmentation Fault` через вичерпання стеку викликів. Застосування `union by size` гарантує логарифмічну глибину дерева `≤ 20` навіть для ґраток `10000 × 10000`, що робить рекурсивне стиснення шляхів абсолютно безпечним.
2. **Локальність даних у пам'яті**. Доступ до сусідів `(nx, ny)` за лінійним індексом `ny * L + nx` спричиняє стрибки пам'яті на `±L` позицій для вертикальних сусідів. Для ґраток великого розміру це призводить до промахів кешу L3. Для максимізації пропускної здатності рекомендується вирівнювати розмір рядка `L` за межею кеш-лінії (64 байти).
3. **Числова стійкість біноміальної згортки**. Пряме обчислення біноміального розподілу `C(N, n) · pⁿ · (1 - p)ᴺ⁻ⁿ` переповнює тип `double` вже при `N > 1000`. Логарифмування факторіалів та нормалізація експоненти відносно моди розподілу дозволяють виконувати згортку для систем довільного розміру `N = 10⁸` без втрати точності.
4. **Випадкові генератори**. Стандартна функція `rand()` з бібліотеки `stdlib.h` має низький період `2^31 - 1` та демонструє помітні псевдовипадкові кореляції на великих масивах. Для наукового моделювання слід використовувати генератори класу `xorshift64`, `PCG` або `std::mt19937_64` з простором станів `2^64` або вище.
