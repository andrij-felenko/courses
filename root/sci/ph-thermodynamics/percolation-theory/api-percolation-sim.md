# 📋 Інтерфейс бібліотеки та моделі перколаційного аналізу

Довідник публічного програмного інтерфейсу (API) та конфігураційних структур бібліотеки `libpercolate` для чисельного моделювання та статистичного аналізу перколаційних явищ у двовимірних та тривимірних дискретних ґратках, а також у суцільних середовищах.

## Архітектура та принцип побудови бібліотеки

Бібліотека `libpercolate` спроектована для високоефективного чисельного аналізу геометричних фазових переходів у середовищах із випадковим розподілом провідних елементів. Вона підтримує моделювання як вузлової (site), так і зв'язкової (bond) перколації на дискретних решітках різної просторової симетрії (квадратній, трикутній, стільниковій, простій кубічній, об'ємно-центрованій, гранецентрованій та на деревах Келі).

Архітектура бібліотеки модульно розділена на три незалежні обчислювальні рівні:
1. **Рівень конфігурації та генерації станів**: відповідає за ініціалізацію об'єму ґратки, вибір генератора псевдовипадкових чисел та створення топологічної матриці зв'язків. Підтримує вибір генератора `std::mt19937_64` або апаратного джерела `std::random_device`.
2. **Рівень аналізу зв'язаності (Обчислювальний рушій)**: реалізує високооптимізовані алгоритми маркування кластерів (включаючи алгоритм Гошена — Копельмана з DSU та модифікований алгоритм Леата для росту окремих кластерів).
3. **Рівень експорту результатів та статистичної обробки**: розраховує параметр порядку `P_∞(p)`, середній розмір скінченного кластера `χ(p)`, перевіряє наявність наскрізного протікання по осях координатної системи, виділяє проводимий кістяк (backbone) та форматує вихідні дані у JSON чи VTK класи для подальшої візуалізації.

## 2. Конфігураційні структури

Конфігураційні об'єкти задають усі геометричні та алгоритмічні параметри до початку виконання обчислень. Вони передаються за посиланням у обчислювальний рушій `PercolationEngine`.

### PercolationConfig

Основна структура налаштування окремого обчислювального експерименту. Вона визначає просторові розміри ґратки, ймовірність заповнення `p`, зародиш генератора випадкових чисел та необхідність проведення додаткових трудомістких обчислень (таких як виділення струмопровідного кістяка чи оцінка фрактальної розмірності методом покриття квадратними сітками).

:::code api-percolation-sim/cpp/percolationconfig.cpp

### MonteCarloSweepConfig

Параметри автоматичного Монте-Карло сканування по всьому діапазону ймовірностей `p`. Використовується для побудови кривих фазових переходів, розрахунку критичних показників та точного локалізування порогу `p_c`.

```cpp
struct MonteCarloSweepConfig {
    double p_start {0.1};            // Початкове значення p
    double p_end {0.9};              // Кінцеве значення p
    double p_step {0.01};            // Крок зміни p
    uint32_t trials_per_step {1000}; // Кількість незалежних прогонів на кожному крокi
    uint32_t num_threads {0};        // Кількість потоків OpenMP/POSIX (0 - авто)
};
```

## 3. Вихідні структури результатів та описи полів

Після завершення сканування ґратки обчислювальний рушій заповнює деталізовану структуру статистичних показників експерименту.

### ClusterAnalysisResult

Підсумкова статистика кластерного розподілу для одного експерименту. Включає макроскопічні параметри порядку, розміри найбільших кластерів, прапорці протікання по координатних осях та гістограму розподілу кластерів за розмірами `n_s(p)`.

- `occupied_fraction`: Дійсна частка відкритих вузлів у згенерованій матриці.
- `total_clusters`: Загальна кількість розпізнаних ізольованих кластерів.
- `max_cluster_size`: Кількість відкритих вузлів у найбільшому зв'язаному кластері.
- `p_infinite`: Потужність протікаючого кластера `P_∞ = max_cluster_size / (N_total * p)`.
- `mean_cluster_size_chi`: Середній розмір скінченного кластера `χ(p)`.
- `has_spanning_x / y / z`: Булеві прапорці наявності зв'язаного містка від початкової до кінцевої грані по відповідній осі.

:::code api-percolation-sim/cpp/clusteranalysisresult.cpp

### PercolationStatus (Коди помилок та відповідей)

Усі функції API повертають перелічуваний код статусу виконання. Значення `PERC_SUCCESS` (0) свідчить про успішне завершення обчислення, тоді як від'ємні значення сигналізують про конкретні помилки ініціалізації чи пам'яті.

```cpp
enum class PercolationStatus : int32_t {
    PERC_SUCCESS              =  0, // Операція успішно завершена
    PERC_ERR_INVALID_DIM      = -1, // Некоректні розміри ґратки (наприклад, 0)
    PERC_ERR_INVALID_PROB     = -2, // p поза межами [0.0, 1.0]
    PERC_ERR_OUT_OF_MEMORY    = -3, // Помилка виділення буферів пам'яті
    PERC_ERR_ALGORITHM_FAIL   = -4, // Невдача аналізу DSU
    PERC_ERR_FILE_IO          = -5  // Помилка запису файлів результатів
};
```

## 6. Багатопотокова обробка та OpenMP сканування

Для прискорення статистичного накопичення тисяч незалежних Монте-Карло вибірок функція `run_monte_carlo_sweep` реалізує паралелізм за допомогою OpenMP. Кожен обчислювальний потік отримує власну незалежну копію об'єкта `PercolationEngine` із унікальним зародишем генератора `seed + thread_id`.

Масштабованість по кількості ядер є майже ідеальною (лінійне прискорення), оскільки обчислення для різних значень `p` та різних зародишів не мають спільного розділюваного стану та не потребують м'ютексних блокувань.

Розрахунок споживання пам'яті для 3D ґратки розміром `N × N × N`:
- Масив стану ґратки (`uint8_t`): `N³` байтів.
- Масив міток кластерів (`int32_t`): `4 · N³` байтів.
- Масив DSU батьківських посилань: `2 · N³` байтів.
- Загальний обсяг оперативної пам'яті: `M ≈ 7 · N³` байтів. Для `N = 400` в 3D це вимагає приблизно `448 МБ` RAM на один потік.

## 7. Інтерфейс командного рядка (CLI Tool)

Для швидкого проведення обчислювальних експериментів у консольному середовищі або інтеграції в автоматизовані скрипти обробки даних бібліотека містить автономний утилітний модуль `percolate-cli`.

### Синтаксис виклику

Команда приймає параметри сітки, режими перколації та шляхи для експорту структурованих звітів у форматах JSON чи VTK:

```bash
percolate-cli --dim 500x500 --lattice square --mode site -p 0.59274 --output report.json
```

### Прапорці та параметри конфігурації CLI

| Прапор | Значення за замовчуванням | Опис призначення |
| :--- | :--- | :--- |
| `--dim <NxNy[z]>` | `100x100` | Розміри ґратки (наприклад `200x200` або `100x100x100`) |
| `--lattice <type>` | `square` | Тип ґратки: `square`, `triangular`, `honeycomb`, `cubic` |
| `--mode <mode>` | `site` | Режим: `site` (узлова) або `bond` (зв'язкова) |
| `-p, --prob <float>` | `0.5` | Ймовірність відкриття `p` у діапазоні `[0.0, 1.0]` |
| `--sweep` | *off* | Режим автоматичного сканування по діапазону ймовірностей |
| `--p-start <float>` | `0.1` | Старт сканування (використовується разом із `--sweep`) |
| `--p-end <float>` | `0.9` | Кінець сканування (використовується разом із `--sweep`) |
| `--p-step <float>` | `0.01` | Крок зміни ймовірності сканування |
| `--trials <int>` | `1000` | Кількість Монте-Карло ітерацій на кожному кроці `p` |
| `--seed <uint64>` | `0` | Зародиш ГПСЧ для точного відтворення експерименту |
| `--output <file>` | *stdout* | Шлях до файла для збереження звіту (`.json` або `.csv`) |
| `--export-vtk <file>` | *none* | Шлях для експорту 3D карти кластерів у форматі VTK |

## 8. Формат JSON звіту та експорт у ParaView (VTK)

При використанні прапорця `--output report.json` консольна утиліта створює деталізований JSON документ, який містить усі вхідні параметри, вираховані статистичні характеристики та показники продуктивності обчислювального рушія.

Формат VTK (`.vtk` / `.vti`), який експортується через метод `export_vtk()`, являє собою стандартний структурований прямокутний контейнер двійкових даних (*Structured Points*). Він містить скалярне поле `ClusterID` для кожного вузла ґратки, що дає змогу візуалізувати просторовий розподіл кластерів та перколаційного містка у професійній утиліті візуалізації ParaView.

```json
{
  "simulation": {
    "dimensions": [500, 500, 1],
    "lattice_topology": "SQUARE_2D",
    "percolation_mode": "SITE_PERCOLATION",
    "target_p": 0.59274,
    "actual_occupied_fraction": 0.592764,
    "random_seed": 987654321
  },
  "results": {
    "has_spanning_cluster": true,
    "total_clusters": 4120,
    "max_cluster_size": 184512,
    "p_infinite": 0.74586,
    "mean_cluster_size_chi": 142.85,
    "estimated_fractal_dimension": 1.892,
    "spanning_directions": {
      "x_axis": true,
      "y_axis": true
    }
  },
  "performance": {
    "execution_time_ms": 14.2,
    "algorithm": "Hoshen-Kopelman with DSU path compression"
  }
}
```
