# 📋 Інтерфейс фазового простору та симплектичних інтеграторів

У даному довідковому інтерфейсі наведено вичерпну специфікацію програмних контрактів, структур даних, математичних типів та функціональних викликів для бібліотечних модулів, призначених для моделювання гамільтонової динаміки, моніторингу фазового об'єму та перевірки виконання тотожності Ліувілля у чисельних обчисленнях.

```
                   АРХІТЕКТУРА ІНТЕРФЕЙСУ ФАЗОВОГО ПРОСТОРУ
                                      │
     ┌────────────────────────────────┼────────────────────────────────┐
     │                                │                                │
     ▼                                ▼                                ▼
[PhaseState]                    [HamiltonianSystem]             [SymplecticIntegrator]
Вектори (q, p),                Обчислення градієнтів            Кроки за часом,
розмірність, метадані           ∂H/∂q та ∂H/∂p                   збереження det J = 1
```

## 1. Концепція архітектурних контрактів та проектування

При розробці високопродуктивного програмного забезпечення для моделювання астрофізичних орбіт, обчислення траєкторій пучків у прискорювачах, молекулярної динаміки складних білкових структур чи еволюції плазми у термоядерних реакторах виникає фундаментальна потреба строго розділити математичну модель фізичної системи (функцію Гамільтона та її похідні) від числового алгоритму інтегрування у часі.

Теорема Ліувілля вимагає, щоб будь-який консервативний чисельний алгоритм зберігав точний фазовий об'єм. Для забезпечення цієї вимоги на програмному рівні даний інтерфейс надає чотири фундаментальні об'єктні абстракції:

1. **Представлення стану фазового простору (`PhaseState`):** Оптимізована за пам'яттю структура, яка зберігає вектори узагальнених координат `q` та узагальнених імпульсів `p` для `N` ступенів вільності, а також часові метадані й фазові норми.
2. **Контракт фізичної моделі (`IHamiltonianSystem`):** Абстрактний інтерфейс, який обчислює точні аналітичні або чисельні градієнти `∂H/∂q` та `∂H/∂p`, а також матрицю Гессе (других частинних похідних) для перевірки нульової дивергенції фазового поля швидкостей.
3. **Контракт числового інтегрування (`IIntegrator`):** Поліморфний інтерфейс розрахунку часового кроку, який надає гарантії щодо збереження симплектичної форми та інваріантності визначника Якобі `det J ≡ 1.0`.
4. **Модуль моніторингу фазової міри (`PhaseVolumeTracker`):** Спеціалізований клас аналізу та числової верифікації виконання теореми Ліувілля для ансамблю фазових точок.

## 2. Базові типи даних та класи станів

### `PhaseState` — Стан у фазовому просторі

Контракт представлення вектора стану для `N` ступенів вільності (загальна розмірність фазового простору дорівнює `2N`).

| Поле / Метод | Тип даних | Опис |
| :--- | :--- | :--- |
| `dim` | `std::size_t` | Кількість ступенів вільності `N` (довжина векторів `q` та `p` дорівнює `N`). |
| `q` | `std::vector<double>` | Вектор узагальнених координат `(q₁, q₂, ..., q_N)`. |
| `p` | `std::vector<double>` | Вектор узагальнених імпульсів `(p₁, p₂, ..., p_N)`. |
| `t` | `double` | Поточний фізичний час системи у секундах або безрозмірних одиницях. |
| `phase_norm()` | `double` | Обчислює евклідову норму станів у фазовому просторі: `√(∑ qᵢ² + ∑ pᵢ²)`. |

Структура `PhaseState` проектується з урахуванням вимог до послідовного розміщення даних у оперативній пам'яті (англ. *contiguous memory layout*). Масиви координат `q` та імпульсів `p` зберігаються у неперервних блоках пам'яті, що забезпечує максимальну ефективність використання кеш-пам'яті процесора (L1/L2 data cache) та дозволяє автовекторизацію обчислень інструкціями SIMD (AVX-2, AVX-512, ARM NEON).

Діагностична функція `phase_norm()` використовується для моніторингу загальної амплітуди відхилення системи у фазовому просторі та виявлення числової нестійкості.

:::code api-phase-space/cpp/phasestate-stan-u-fazovomu.cpp

При роботі зі структурами `PhaseState` бібліотека гарантує відсутність прихованого копіювання даних (англ. *zero-copy semantics*): усі передачі станів у функції обчислення градієнтів здійснюються за незмінними посиланнями `const PhaseState&`.

## 3. Інтерфейс Гамільтонової системи

### `IHamiltonianSystem` — Абстрактний контракт фізичної моделі

Будь-яка фізична модель (гармонічний осцилятор, подвійний маятник, проблема Кеплера N тіл, рух частинки у магнітному полі), для якої перевіряється теорема Ліувілля, має реалізовувати абстрактний інтерфейс `IHamiltonianSystem`.

| Метод | Вхідні параметри | Повертане значення | Вимоги та винятки |
| :--- | :--- | :--- | :--- |
| `compute_energy` | `const PhaseState& state` | `double` | Обчислення значення функції Гамільтона `H(q, p, t)`. Має бути гладкою функцією класу `C²`. |
| `compute_gradients` | `const PhaseState& state, std::vector<double>& dq_dt, std::vector<double>& dp_dt` | `void` | Обчислює похідні `dqᵢ/dt = ∂H/∂pᵢ` та `dpᵢ/dt = -∂H/∂qᵢ`. |
| `compute_hessian` | `const PhaseState& state, std::vector<double>& hessian_matrix` | `void` | Обчислює матрицю Других похідних розміру `2N × 2N` для прямої перевірки `∇ · v = 0`. |

:::code api-phase-space/cpp/ihamiltoniansystem.cpp

Контракт вимагає, щоб метод `compute_gradients` не виконував динамічного виділення пам'яті (`malloc` або `new`) під час обчислень, а заповнював наперед виділені вектори-буфери `dq_dt` та `dp_dt`. Це повністю усуває системні затримки на виділення пам'яті у гарячих обчислювальних циклах інтегрування.

Метод `compute_hessian` обчислює симетричну матрицю Других частинних похідних Гамільтоніана:

```
Hessian = ┌                                         ┐
          │  ∂²H/∂qᵢ∂qⱼ           ∂²H/∂qᵢ∂pⱼ        │
          │                                         │
          │  ∂²H/∂pᵢ∂qⱼ           ∂²H/∂pᵢ∂pⱼ        │
          └                                         ┘
```

Ця матриця використовується монітором для точної чисельної перевірки виконання умови Шварца `∂²H/∂qᵢ∂pᵢ = ∂²H/∂pᵢ∂qᵢ` та перевірки тотожності нульової дивергенції `∇ · v ≡ 0`.

## 4. Інтерфейс симплектичних та несимплектичних інтеграторів

### `IIntegrator` — Контракт числового інтегрування

Класи інтеграторів відповідають за переведення стану `PhaseState` від моменту `t` до моменту `t + dt`. Вони поділяються на класичні (несимплектичні) та симплектичні схеми.

| Інтегратор | Метод розрахунку | Гарантія симплектичності | Збереження фазового об'єму |
| :--- | :--- | :--- | :--- |
| `ExplicitEuler` | Явний першого порядку | Ні | Ні (`det J = 1 + ω² Δt² > 1`) |
| `ImplicitEuler` | Неявний першого порядку | Ні | Ні (`det J = 1 / (1 + ω² Δt²) < 1`) |
| `SymplecticEuler` | Першого/другого порядку | Так | **Так (`det J ≡ 1.000000`)** |
| `VerletLeapfrog` | Стормера-Верле другого порядку | Так | **Так (`det J ≡ 1.000000`)** |
| `Ruth4thOrder` | Симплектичний четвертого порядку | Так | **Так (`det J ≡ 1.000000`)** |

:::code api-phase-space/cpp/iintegrator-kontrakt.cpp

Симплектичні інтегратори проектуються за принципом зсуву канонічних змінних. Наприклад, у симплектичному методі Ейлера-Кромера оновлення імпульсу виконується на основі поточної координати, а оновлення координати — на основі вже **нового** імпульсу. Ця несиметрія перетворює матрицю кріку на відображення з визначником `det J ≡ 1.000000`, що строго зберігає фазовий об'єм системи.

## 5. Інтерфейс відстеження фазового об'єму та якобіана

### `PhaseVolumeTracker` — Моніторинг теореми Ліувілля

Класс `PhaseVolumeTracker` використовується для прямого обчислення визначника Якобі `det J` та вимірювання деформації фазового об'єму ансамблю частинок під час моделювання.

| Метод | Опис | Повертане значення |
| :--- | :--- | :--- |
| `compute_jacobian` | Обчислює матрицю частинних похідних `∂z(t)/∂z(0)` чисельним диференціюванням. | `std::vector<double>` (`2N × 2N`) |
| `compute_jacobian_determinant` | Обчислює визначник матриці Якобі `det J(t)`. | `double` (для гамільтонових систем `≡ 1.0`) |
| `compute_ensemble_volume` | Обчислює гіпероб'єм `Ω(t)` методом опуклої оболонки або Монте-Карло. | `double` |
| `verify_liouville_theorem` | Перевіряє відхилення `\|det J - 1.0\|` з заданим допуском `eps`. | `bool` |

Для підсумкової статистичної оцінки стану системи використовується об'єкт метрик `VolumeMetrics`.

:::code api-phase-space/cpp/phasevolumetracker.cpp

Алгоритм `calculate_hull_volume` підтримує двовимірний розрахунок через формулу Гаусса (галасових шнурків) для 2D фазових проекцій, а також алгоритми Монте-Карло для обчислення фазових гіпероб'ємів у вищих вимірах `2N > 2`.

## 6. Алгоритми чисельного диференціювання та обчислення Якобіана

Обчислення матриці Якобі `J_ij = ∂z_i(t) / ∂z_j(0)` є критично важливою операцією для перевірки виконання теореми Ліувілля. Бібліотека надає два класичні алгоритми чисельного обчислення Якобіана:

1. **Центральна різницева схема (Central Difference Scheme):**
   Для кожної компоненти початкового стану `z_j(0)` виконується мале прирощення `+eps` та `-eps`:
   ```
   J_ij ≈ ( z_i(z₀ + eps · e_j, t) - z_i(z₀ - eps · e_j, t) ) / (2 · eps)
   ```
   Цей метод має точність `O(eps²)` і вимагає `4N` додаткових обчислень траєкторії на кожен крок аналізу.

2. **Варіаційні рівняння (Variational Equations):**
   Матриця Якобі `J(t)` обчислюється одночасно з основними рівняннями руху через інтегрування матричного диференціального рівняння:
   ```
   dJ / dt = M(q, p, t) · J(t),   J(0) = I
   ```
   де `M = ∂v/∂z` — матриця градієнта поля швидкостей розміру `2N × 2N`. Цей підхід забезпечує точність обчислення Якобіана на рівні точності самого інтегратора.

після обчислення матриці Якобі її визначник `det J` розраховується за допомогою LU-розкладу матриці із вибором головного елемента по стовпчиках (алгоритм Пауля Дуліттла), що запобігає втраті точності числової сітки.

## 7. Особливості паралельного обчислення й потокобезпечність

Під час роботи з великими статистичними ансамблями (`10⁴ – 10⁶` фазових точок) обчислення еволюції кожної точки ансамблю є повністю незалежним від інших частинок (англ. *embarrassingly parallel computation*).

Контракт `IHamiltonianSystem` розроблено як **потокобезпечний незмінний об'єкт** (англ. *thread-safe const object*). Метод `compute_gradients` не змінює внутрішній стан системи, що дозволяє виконувати паралельні виклики з багатьох обчислювальних потоків OpenMP, POSIX threads або GPU-ядер CUDA без використання блокувань (м'ютексів).

:::code api-phase-space/cpp/7-osoblyvosti-paralelnoho.cpp

Під час паралельного обчислення кожен потік працює з власними наперед виділеними буферами пам'яті для градієнтів, що виключає стан гонитви за даними (англ. *data race*) та запобігає фальшивому сумісному використанню кеш-ліній (англ. *false sharing*).

## 8. Таблиця кодів помилок та винятків

У випадку виникнення нестійкості чисельного інтегрування чи виходу системи за межі допустимого фазового простору обчислювальне ядро повертає стандартизовані коди помилок.

| Код помилки | Константа C++ | Причина виклику | Дія системи |
| :--- | :--- | :--- | :--- |
| `0x00` | `SUCCESS` | Операцію виконано успішно. | Продовження обчислювального циклу. |
| `0x01` | `ERR_NON_CONSERVATIVE` | Дивергенція `∇ · v ≠ 0` через наявність тертя. | Попередження: теорема Ліувілля не виконується. |
| `0x02` | `ERR_VOLUME_BLOWUP` | `det J > 1.5` через нестійкість несимплектичного алгоритму. | Аварійна зупинка, зменшення кроку `dt`. |
| `0x03` | `ERR_PHASE_SINGULARITY` | Визначник Якобі `det J = 0` (виродження координатної сітки). | Виняток топології фазового простору. |
| `0x04` | `ERR_NAN_DETECTOR` | Виявлено значення `NaN` або `Inf` у фазовому векторі. | Аварійна зупинка обчислення ансамблю. |

Обробка виняткових ситуацій проектується за принципом строгої гарантії безпеки винятків (англ. *strong exception guarantee*): у випадку виникнення помилки обчислення стан об'єкта `PhaseState` повертається до останнього коректного часового шагу.
