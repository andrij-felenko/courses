# ⚙️ Плавучий буй: осадка числом і період гойдання

Закон Архімеда вкладається в один рядок — сила дорівнює вазі витісненої рідини, F = ρ·g·V. Та щойно від голої сили переходиш до конкретного плавучого тіла, виринають два питання, на які цей рядок сам собою не відповідає, бо в ньому сховане невідоме V. Кинули буй у воду — **як глибоко він сяде**? Хвиля притопила його й відпустила — **як він гойдатиметься і з яким періодом**? Для рівненького бруска на обидва питання є олівцеві відповіді. Для справжньої форми — кулі, пляшки, корпусу з обводами — олівець пасує, і на сцену виходить обчислення. Зберемо маленьку робочу програму, що відповідає на обидва питання числом, і дорогою натрапимо на кілька пасток, через які наївний код тихо бреше — видає гарний графік, за яким немає фізики.

## Задача 1. Осадка як корінь рівняння

Плавуче тіло тоне рівно доти, доки витіснена вода не зважить стільки ж, скільки воно саме, — і на тому спиняється. Це і є рівновага, з неї все й читається. Прирівняймо вагу тіла до ваги витісненої води:

```
ρ_тіла · g · V_повний = ρ_води · g · V_занурений(d)
```

Прискорення g стоїть по обидва боки й скорочується — плавучість про нього не знає. Лишається

```
V_занурений(d) = (ρ_тіла / ρ_води) · V_повний
```

Права частина — стала: густини й повний об'єм відомі наперед. Ліва росте з осадкою d: що глибше сидить тіло, то більше води воно витісняє. Осадка — це та єдина глибина, за якої ліва частина доганяє праву.

Для тіла зі **сталим перерізом** — бруса чи циліндра, поставленого сторч, — витіснений об'єм просто A·d, і осадка виходить в один рядок, без жодного пошуку:

```
d = (ρ_тіла / ρ_води) · L
```

Дерев'яний брус (ρ = 600 кг/м³) заввишки 0.6 м сяде на d = 0.6·0.6 = 0.36 м — трохи більш ніж по плечі. Просто, поки переріз не міняється з глибиною.

А тепер візьми кулю. Її переріз біжить від нуля на дні до найширшого кола посередині й знову до нуля вгорі — і зв'язок «глибше → більше об'єму» перестає бути прямою лінією. Витіснений кулею об'єм на глибині d — це об'єм **кульового сегмента**:

```
V_занурений(d) = π · d² · (R − d/3)
```

Підстав це у рівновагу — і дістанеш кубічне рівняння на d. Його ще можна розв'язати в радикалах, та для грушоподібного буя чи корпусу з обводами формули немає **взагалі** — є лише таблиця перерізів на різній висоті. Отож поставмо задачу так, щоб байдуже було до форми: шукаймо **корінь** функції

```
f(d) = V_занурений(d) − (ρ_тіла / ρ_води) · V_повний
```

— ту глибину, де f перетинає нуль.

Ідея, як його впіймати, спирається на одну властивість: f **монотонно росте**, бо глибше завжди означає більше витісненого. На поверхні (d = 0) тіло не витісняє нічого, тож f(0) < 0; занурене по маківку — витісняє весь свій об'єм, і f(H) > 0. Корінь затиснутий між цими знаками, і він там **один**. Найнадійніший спосіб його стиснути — **половинний поділ (бісекція)**: береш кінці з різними знаками, ділиш проміжок навпіл, лишаєш ту половину, де знак усе ще міняється, і повторюєш. Щокроку невизначеність меншає вдвічі: за 40 поділів проміжок [0, 0.2 м] стискається до 0.2 / 2⁴⁰ ≈ 2·10⁻¹³ м — точніше, ніж має сенс. Бісекція не найшвидша: [метод Ньютона — Рафсона](topic:math-numeric/newton-raphson) з його квадратичною збіжністю знайшов би корінь за кілька кроків замість сорока. Але Ньютонові потрібна похідна й добра початкова здогадка, і на пологій ділянці чи біля країв відрізка [0, H] він залюбки вистрибне за межі тіла й розбіжиться. Бісекція ж не має де зірватися: якщо корінь затиснутий, а функція неперервна, вона збіжна **завжди**. Для одноразового розрахунку осадки надійність варта тих зайвих поділів.

Бісекція щокроку вдвічі звужує відрізок, де ховається корінь, аж поки не затисне його впритул.](img/draft-root.svg)

*Осадку знаходять як корінь: де крива витісненого об'єму перетне рівень «вага тіла». Половинний поділ гарантовано доводить до кореня, бо крива монотонна — глибше завжди витісняє більше.*

Ось увесь пошук осадки в робочому коді. Мова — Python: тут важить прозорість фізики, а не сирі такти, і читабельна чисельна логіка коштовніша за швидкодію.

```python
import math

RHO_WATER = 1000.0   # густина води, кг/м³
G = 9.81             # м/с²

def bisect(f, lo, hi, tol=1e-10, itmax=100):
    """Половинний поділ. f(lo) і f(hi) МУСЯТЬ мати різні знаки."""
    flo, fhi = f(lo), f(hi)
    if flo == 0.0: return lo
    if fhi == 0.0: return hi
    if (flo < 0) == (fhi < 0):
        raise ValueError("корінь не затиснутий: однакові знаки на кінцях")
    for _ in range(itmax):
        mid = 0.5 * (lo + hi)
        fm = f(mid)
        if fm == 0.0 or 0.5 * (hi - lo) < tol:
            return mid
        if (flo < 0) == (fm < 0):
            lo, flo = mid, fm      # корінь у правій половині
        else:
            hi, fhi = mid, fm      # корінь у лівій половині
    return 0.5 * (lo + hi)

def sphere_submerged_volume(d, R):
    """Об'єм кульового сегмента висоти d: куля радіуса R занурена на глибину d."""
    d = min(max(d, 0.0), 2 * R)
    return math.pi * d * d * (R - d / 3.0)

def draft(rho_body, total_volume, submerged_volume, h_max):
    """Осадка d із рівноваги: витіснений об'єм = (ρ_тіла/ρ_води)·V_повний."""
    target = (rho_body / RHO_WATER) * total_volume
    return bisect(lambda d: submerged_volume(d) - target, 0.0, h_max)

R = 0.10                                    # радіус кулі, м
rho_body = 600.0                            # дерево, кг/м³
V_total = 4.0 / 3.0 * math.pi * R ** 3
d = draft(rho_body, V_total,
          lambda z: sphere_submerged_volume(z, R), h_max=2 * R)
print("осадка кулі: d = %.4f м" % d)        # → 0.1134 м
```

Дерев'яна куля радіуса 10 см сідає на **0.1134 м** — трохи нижче за екватор (той на 0.10 м), як і має бути: густина 0.6 від води жене занурення за половину, аж поки вужчий верх кулі не догодить рівновазі. Кубічне рівняння розв'язане, а ми навіть не згадали слово «кубічне» — бісекція знайшла корінь із самого монотонного профілю.

> 🔧 **Навіщо це.** Той самий десяток рядків рахує осадку чого завгодно, аби ви вміли назвати витіснений об'єм як функцію глибини: понтона, катамарана, ватерлінії завантаженого судна. Замініть `sphere_submerged_volume` на профіль свого корпусу — і код не помітить різниці, бо він шукає корінь, а не розв'язує конкретну формулу.

І тут причаїлася **перша пастка** — відрізок пошуку. Спокуса задати `h_max = R` (мовляв, куля ж не сяде глибше за радіус) обертається крахом: наша куля тоне **за** екватор, на 0.1134 > 0.10, тож на кінцях [0, R] функція f від'ємна з обох боків — корінь не затиснутий, і чесний `bisect` кине виняток замість того, щоб збрехати. Правильний відрізок — **уся можлива висота** тіла [0, H], у кулі це [0, 2R]. Бісекція вимагає не вгаданого діапазону, а такого, що напевно накриває корінь; краще ширший, ніж хитріший.

А чи справді код працюватиме для форми **без** формули сегмента — лише за профілем перерізу? Перевірмо, підмінивши точний об'єм чисельним інтегралом площі перерізу по глибині (площа перерізу кулі на висоті z — це коло радіуса² = z·(2R − z)):

```python
def submerged_volume_by_profile(d, area_of_depth, n=2000):
    """Витіснений об'єм для БУДЬ-ЯКОГО профілю A(z) — метод трапецій."""
    step = d / n
    s = 0.5 * (area_of_depth(0.0) + area_of_depth(d))
    for i in range(1, n):
        s += area_of_depth(i * step)
    return s * step

area = lambda z: math.pi * z * (2 * R - z)          # переріз кулі на глибині z
print(submerged_volume_by_profile(d, area))         # 2.513274e-03
print(sphere_submerged_volume(d, R))                # 2.513274e-03 — збіг
```

Обидва дають **2.513274·10⁻³ м³** — інтеграл профілю точно ліг на формулу сегмента. Отже, шлях «таблиця перерізів → інтеграл → корінь» працює, і саме ним рахують осадку справжніх корпусів, де жодної замкненої формули немає.

## Задача 2. Гойдання: мале притоплення робить пружину

Тепер притопимо плавуче тіло на невеличке x нижче рівноваги й відпустимо. Що його поверне? Занурившись на зайве x, тіло витісняє додатковий об'єм A·x, де A — площа його перерізу **на рівні води** (ватерлінійна площа). Цей зайвий витіснений об'єм додає виштовхування ρ_води·g·A·x, спрямоване вгору, а вага не змінилася — тож на тіло діє непогашена повертальна сила:

```
F = − ρ_води · g · A · x
```

Придивіться: сила рівно пропорційна зсуву й спрямована проти нього. Це буква в букву закон пружини Гука з жорсткістю k = ρ_води·g·A — тільки «пружину» тут робить не метал, а сама вода, що прибуває витіснитися. А сила, пропорційна зсуву й супротивна йому, породжує [простий гармонічний рух](topic:ph-waves/harmonic-oscillator). Другий закон Ньютона m·ẍ = −k·x дає коливання з

```
ω² = ρ_води · g · A / m        T = 2π / ω = 2π · √( m / (ρ_води·g·A) )
```

І тут ховається дрібна перлина. Для тіла зі сталим перерізом маса m = ρ_тіла·A·L, а осадку ми вже знаємо: d = (ρ_тіла/ρ_води)·L. Підставмо це в період — площа A й густини скорочуються, лишаючи

```
T = 2π · √( d / g )
```

Період гойдання бруска дорівнює періоду **маятника, чия довжина — це осадка**. Плаваючий по шию стовп заввишки з осадку 0.36 м колишеться так само, як нитяний маятник завдовжки 0.36 м: T = 2π·√(0.36/9.81) = 1.204 с. Ні маса, ні площа, ні густина поодинці на період не впливають — усе через одну осадку. Для кулі переріз на рівні води A = π·d·(2R − d) = 0.0309 м², і той самий закон дає T = 0.5726 с.

Ідея перевірки прямолінійна: візьмімо закон Ньютона як диференціальне рівняння, **проінтегруймо його числом**, виміряймо період безпосередньо з насимульованого x(t) і звірмо з аналітичним T. Якщо код правильний і крок дібраний — вони мусять збігтися. Тут і чигає найковарніша пастка проєкту.

```python
import numpy as np

def make_bob(rho_body, total_volume, waterplane_area):
    m = rho_body * total_volume
    omega2 = RHO_WATER * G * waterplane_area / m
    return omega2, 2 * np.pi / np.sqrt(omega2)      # (ω², аналітичний період)

Awp = math.pi * d * (2 * R - d)                     # площа на рівні води
omega2, T = make_bob(rho_body, V_total, Awp)

def accel(x):
    return -omega2 * x                              # притоплення → повертальна сила

def step_euler(x, v, h):                            # ЯВНИЙ Ейлер
    return x + v * h, v + accel(x) * h

def step_symplectic(x, v, h):                       # напівнеявний (Ейлер — Кромер)
    v = v + accel(x) * h                            # спершу швидкість…
    x = x + v * h                                   # …тоді координата за НОВОЮ швидкістю
    return x, v

def step_rk4(x, v, h):                              # Рунге — Кутта 4-го порядку
    def f(x, v): return v, accel(x)
    k1x, k1v = f(x, v)
    k2x, k2v = f(x + 0.5*h*k1x, v + 0.5*h*k1v)
    k3x, k3v = f(x + 0.5*h*k2x, v + 0.5*h*k2v)
    k4x, k4v = f(x + h*k3x,     v + h*k3v)
    x += h/6.0 * (k1x + 2*k2x + 2*k3x + k4x)
    v += h/6.0 * (k1v + 2*k2v + 2*k3v + k4v)
    return x, v

def simulate(step, x0, v0, h, steps):
    xs = [x0]
    x, v = x0, v0
    for _ in range(steps):
        x, v = step(x, v, h)
        xs.append(x)
    return np.array(xs)

def period_from_zeros(xs, h):
    """Період — середня відстань між висхідними перетинами нуля (з інтерполяцією)."""
    cross = [(i - 1 - xs[i-1] / (xs[i] - xs[i-1]))
             for i in range(1, len(xs))
             if xs[i-1] <= 0 < xs[i]]
    return float(np.mean(np.diff(cross))) * h

N = 60                       # кроків на період
h = T / N
steps = N * 12               # дванадцять періодів гойдання
x0 = 0.02                    # притопили на 2 см і відпустили

for name, step in [("Ейлер", step_euler),
                   ("симплектичний", step_symplectic),
                   ("RK4", step_rk4)]:
    xs = simulate(step, x0, 0.0, h, steps)
    print("%-13s T=%.5f с   амплітуда наприкінці %.3f м"
          % (name, period_from_zeros(xs, h), abs(xs[-N:]).max()))
print("%-13s T=%.5f с" % ("аналітичний", T))
```

Вивід — і одразу видно, хто збрехав:

```
Ейлер         T=0.57466 с   амплітуда наприкінці 0.977 м   ← роздулося!
симплектичний T=0.57231 с   амплітуда наприкінці 0.020 м
RK4           T=0.57258 с   амплітуда наприкінці 0.020 м
аналітичний   T=0.57258 с
```

Симплектичний метод і RK4 повернули період аналітичного майже точно (RK4 — до п'ятого знака) і чесно втримали амплітуду коло 2 см, з якими буй відпустили. А **явний Ейлер** роздув гойдання з 2 см до майже метра — буй, що сам себе розхитує до небес із нічого. Це не груба похибка малого кроку. Це системна вада.

### Чому явний Ейлер підкачує енергію

Розберімо один крок Ейлера для коливання. Він бере нахил **на початку** кроку й лінійно продовжує його на весь крок уперед. Для маятника, що завертає по колу у площині «координата — швидкість», такий прямий відрізок завжди зрізає навпростець **назовні** дуги — щокроку трохи далі від центра. Порахувати можна точно: за один крок амплітуда множиться на √(1 + ω²·h²). Цей множник **більший за одиницю за будь-якого** h > 0. Немає такого дрібного кроку, що його виправить: зменшиш h — сповільниш роздування, але воно нікуди не подінеться, енергія росте необмежено. У нашому буї з цілком пристойним кроком h = T/60 за 12 періодів накопичилося √(1+ω²h²) у степені 720 — множення амплітуди в ~50 разів (з 2 см до метра) і енергії в 2573 рази. Явний Ейлер для консервативного коливання не наближено неправильний — він якісно неправильний, вигадує енергію з повітря.

Ліки — інтегратор, що поважає збереження. Найдешевші з усіх — **переставити два рядки**. Онови спершу швидкість за старою координатою, а тоді координату — за **новою** швидкістю. Ця дрібна перестановка перетворює явний Ейлер на **напівнеявний (симплектичний) Ейлер**, він же метод Ейлера — Кромера. Замість спіралі назовні метод жене замкнену орбіту: він зберігає не саму механічну енергію, а близьку до неї «тіньову» величину, тому амплітуда злегка дихає біля правильної, нікуди не тікаючи. Що переставлений порядок дає стійкі розв'язки для коливань за будь-якої тривалості рахунку, показав фізик Ален Кромер 1981 року в короткій замітці «Stable solutions using the Euler approximation» (*Amer. J. Phys.* 49, 455). Стійкий цей метод, поки ω·h < 2 — тобто поки на період припадає більш ніж π кроків; за нашого h (енергія 0.996 від початкової, період відхилився на −0.05 %) — з великим запасом.

Ще точніший — **метод Рунге — Кутти 4-го порядку**, який німецькі математики Карл Рунге (1895) і Вільгельм Кутта (1901) виточили в Ґеттінгені саме як заміну грубому Ейлерові. Він важить нахил у чотирьох точках кроку — на початку, двічі посередині, у кінці — і зважено їх усереднює, через що його похибка спадає як h⁴. Тому й період у нас збігся з аналітичним до 0.0001 %, а енергія протрималась 0.999987. Але й у RK4 є стеля: на уявній осі він стійкий лише поки ω·h ≲ 2.83 (це 2√2); переступиш — і навіть він вибухне. Тобто крок вибирають не за принципом «аби не вибухнуло», а за принципом «аби **розділити** період»: кілька десятків кроків на період, щоб синусоїда була гладенька, а не ледве трималась на межі стійкості. Ціле сімейство таких схем — від простого Ейлера до неявних і адаптивних — це окрема наука, [числові методи розв'язку звичайних диференціальних рівнянь](topic:math-numeric/numerical-ode); буй показує головний із її уроків наочно.

*Той самий закон Ньютона, три способи проінтегрувати. Явний Ейлер вигадує енергію й розкручує коливання; напівнеявний Ейлер і RK4 стережуть орбіту. Вибір інтегратора вирішує, побачите ви фізику чи міраж.*

## Де модель ламається — і чому це варто знати

Наша «пружина» F = −ρ_води·g·A·x — це **лінеаризація** довкола рівноваги, чинна лише для малого x, бо в неї вшита стала площа A на рівні води. У справжньої кулі ця площа міняється, щойно тіло помітно вирине чи занурене глибше, і повертальна сила перестає бути прямою лінією. Наскільки це важить, легко зміряти тим самим кодом, якщо годувати `accel` справжньою силою від об'єму сегмента, а не її лінійним наближенням. Виходить, що період залежить від розмаху: притоплення на 5 мм подовжує період на якісь 0.03 %, на 2 см — на 0.5 %, а на 5 см — уже на 3.4 %. Щойно період починає залежати від амплітуди — ви покинули лінійний світ, і аналітична T = 2π√(m/(ρgA)) стала лише наближенням для дрібних хвиль.

Дві справжні речі ідеальна модель ще й зовсім промовчала:

- **Приєднана маса.** Гойдаючись, буй тягне за собою прилеглий шар води — і рухається так, ніби став важчим за власну масу. Ефективна маса більша, тож справжній період **довший** за наш ідеальний. Для тіла на кшталт півсфери приєднана маса — це помітна частка власної, і в морі знехтувати нею не можна.
- **Загасання.** В'язке тертя і — головне на воді — **хвилі, які буй сам випромінює** з кожним махом, крадуть енергію. Реальний буй гойдається не вічно: розмах поволі згасає до спокою. Гірка іронія в тім, що чесно змоделювати це згасання — значить додати рівно те відбирання енергії, яке нестійкий Ейлер підробляв, тільки із **зворотним** знаком.

Ось чому корабельні інженери рахують період хитавиці не нашою формулою в один рядок, а з повною гідродинамікою: ватерлінійна площа гуляє з креном, додаються приєднана маса й загасання, форма корпусу заходить уся. Але кістяк під усім цим — виштовхування, лінеаризоване в пружину, — той самий, що в нашій програмі. Дві дюжини рядків Python не замінять гідродинамічного розрахунку, зате показують його серце голим: осадка — це корінь рівняння рівноваги, гойдання — це та сама рівновага, розхитана на крок убік, а вся точність відповіді впирається не в фізику, а в те, чи вміє ваш інтегратор не вигадувати енергію.
