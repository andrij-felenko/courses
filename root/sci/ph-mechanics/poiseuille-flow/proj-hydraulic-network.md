# ⚙️ Мережа труб у коді: гідравлічний опір за законом Ома

<preknowlist>
- [Закон Ома](root:hw-analog/ohms-law) — струм = напруга / опір; уся аналогія тримається на цій формі зв'язку трьох величин.
- [В'язкість](root:ph-mechanics/viscosity) — внутрішнє тертя рідини; її коефіцієнт μ входить в опір труби й задає, наскільки важко тече рідина.
- [Лінійні системи](root:math-algebra/linear-systems) — розв'язування Ax = b; метод вузлів зводить цілу мережу труб саме до однієї такої системи.
</preknowlist>

Одна труба під натиском — задача на олівець: порахував опір, поділив тиск, дістав витрату. Але справжня гідравліка рідко буває однією трубою. Колектор поливної системи розгалужується на десяток гілок; охолоджувальний контур веде рідину крізь сплетіння каналів; мікрофлюїдний чип на склі — це лабіринт із перемичками; навіть груба модель кровообігу — мережа судин, що діляться й знову зливаються. Питання те саме, лише помножене: подавши на вхід відомий натиск, скільки протече крізь кожну окрему гілку і який тиск установиться в кожному вузлі-розгалуженні?

Для двох труб це ще рахується руками. Для мережі з перемичками — уже ні: витрати в гілках переплетені, тиск у кожному вузлі залежить від усіх сусідніх, і «розкрутити» клубок послідовним діленням не виходить. Потрібен метод, який бере **довільну** мережу й видає повний розподіл. І він є — готовий, обкатаний десятиліттями. Тільки не в гідравліці, а в електротехніці.

## Ідея: труба — це резистор

Закон Пуазейля для одної труби можна переписати так, щоб проступила його справжня природа. Згорнемо все, крім натиску, в одну величину — **гідравлічний опір**:

```
Q = Δp / R_гідр ,    R_гідр = 8 μ L / (π R⁴)      [Па·с/м³]
```

Витрата = натиск, поділений на опір. Це слово в слово [закон Ома: струм = напруга / опір](root:hw-analog/ohms-law). І схожість не поверхнева — це справжня аналогія, у якій кожна величина має точного двійника:

```
різниця тисків Δp   ↔   напруга U         (що жене потік)
витрата Q           ↔   струм I           (що тече)
гідравлічний опір   ↔   електричний опір   (що заважає)
```

Щойно рівняння має ту саму форму, **кожен трюк із теорії кіл переноситься задарма**. Дві труби одна за одною — опори додаються, як послідовні резистори. Дві труби пліч-о-пліч — обернені опори додаються, як паралельні. А для мереж будь-якої заплутаності електрики вже сто років користуються **методом вузлових потенціалів** — і його теж можна взяти цілком. Це не вправа уяви: проєктувальники мікрофлюїдних чипів буквально креслять свій канал як резисторну схему й розв'язують її, ще перш ніж травити скло, — бо порахувати мережу опорів на порядки дешевше, ніж переробляти чип.

Серце методу вузлів — простий фізичний факт. У будь-якому вузлі-розгалуженні рідина не накопичується й не зникає: скільки її втекло за секунду, стільки й притекло (течія стала, рідина нестислива). Це закон збереження, і він дослівно збігається з [першим законом Кірхгофа — сума струмів у вузлі дорівнює нулю](root:hw-analog/kirchhoff-laws), тільки замість струму I стоїть витрата Q. Запиши по одному такому балансу на кожен вузол із невідомим тиском — дістанеш систему лінійних рівнянь на ці тиски. Розв'яжи її — і кожна витрата в гілці випливе з Q = Δp/R.

## Опір труби й закони її додавання

Почнемо з цеглинок. Опір однієї труби — пряма підстановка геометрії та в'язкості; витрата — одне ділення. Уся арифметика ведеться в СІ (метри, паскалі, Па·с), і це не дрібниця, до якої ми ще повернемось.

```py
import math

MU_WATER = 1.0e-3   # Па·с — в'язкість води при ~20 °C

def pipe_resistance(radius, length, mu):
    """Гідравлічний опір круглої труби за Пуазейлем, [Па·с/м³].
    radius, length — у метрах; mu — у Па·с. Уся сила — у radius**4."""
    return 8.0 * mu * length / (math.pi * radius**4)

def flow(dp, R):
    """Витрата крізь опір R під натиском dp:  Q = dp / R, [м³/с]."""
    return dp / R
```

Тепер правила з'єднання. Вони — точна калька з електрики, тому й доводити їх наново не треба, досить перекласти. **Послідовно** (труба за трубою): крізь обидві тече та сама витрата, а натиски на подолання кожної додаються — отже опори складаються. **Паралельно** (труби пліч-о-пліч між тими самими двома вузлами): на кожній однаковий натиск, а витрати зливаються — отже додаються провідності (обернені опори), і сумарний опір менший за найменший з гілок.

```py
def series(resistances):
    """Опори одна за одною — просто додаються."""
    return sum(resistances)

def parallel(resistances):
    """Опори пліч-о-пліч — обернені додаються (провідності складаються)."""
    return 1.0 / sum(1.0 / R for R in resistances)
```

**Приклад: дві труби, послідовно й паралельно.** Труба 1 — радіус 1.0 мм; труба 2 — вужча, 0.8 мм; обидві завдовжки 20 см, рідина вода. Натиск на з'єднанні Δ*p* = 1000 Па.

```
R1 = 8·10⁻³·0.2 / (π·(1.0·10⁻³)⁴) = 5.09·10⁸  Па·с/м³
R2 = 8·10⁻³·0.2 / (π·(0.8·10⁻³)⁴) = 1.24·10⁹  Па·с/м³   (вужча → твердіша у (1/0.8)⁴ ≈ 2.44 раза)

послідовно:  R = R1 + R2               = 1.75·10⁹   →  Q = 1000/R = 5.71·10⁻⁷ м³/с ≈ 0.57 мл/с
паралельно:  R = 1/(1/R1 + 1/R2)       = 3.61·10⁸   →  Q =         2.77·10⁻⁶ м³/с ≈ 2.77 мл/с
             (перевірка: Q = Q1 + Q2 = 1.96·10⁻⁶ + 0.80·10⁻⁶ = 2.77·10⁻⁶ ✓)
```

Дві однакові за призначенням труби, а витрата різниться майже вп'ятеро — лише через спосіб з'єднання. Послідовно вони душать одна одну (опори складаються), паралельно — розвантажують (додається пропускна здатність). Але щойно мережа перестає розкладатися на чисті «послідовно» та «паралельно», ці дві функції безсилі. Тоді за роботу береться метод вузлів.

## Метод вузлів: мережа як лінійна система

Ідея буквальна. У кожному вузлі з невідомим тиском випишемо баланс витрат: сума всіх Q, що витікають у сусідні вузли, дорівнює нулю. Витрата по трубі між вузлами *i* та *j* дорівнює (*pᵢ* − *pⱼ*)·*g*, де *g* = 1/*R* — **провідність** труби. Розкриваємо дужки — і кожне рівняння виходить лінійним щодо тисків. Зберемо коефіцієнти в матрицю *G*, невідомі тиски — у вектор, а внески вузлів із **заданим** тиском (джерела, стоки) перекинемо в праву частину. Дістанемо систему *G·p = b*, яку лишається розв'язати.

Матрицю *G* збираємо одним проходом по трубах. Кожна труба з провідністю *g* додає *g* на діагональ обох своїх вузлів (сумарна провідність вузла) і віднімає *g* на позадіагональ між ними (зв'язок). Якщо на іншому кінці труби — вузол із заданим тиском, його внесок іде не в матрицю, а в праву частину.

```py
def solve_network(pipes, pressures):
    """pipes: список (u, v, R) — труба між вузлами u,v з опором R (напрям байдужий).
    pressures: {вузол: тиск} — ЗАДАНІ (граничні) тиски: джерела й стоки.
    Повертає (p, Q): p[вузол] — тиск у кожному вузлі; Q[(u,v)] — витрата з u в v."""
    nodes = set(pressures)
    for u, v, R in pipes:
        nodes.add(u); nodes.add(v)
    unknown = sorted(n for n in nodes if n not in pressures)   # вузли без заданого тиску
    idx = {n: i for i, n in enumerate(unknown)}
    m = len(unknown)

    G = [[0.0] * m for _ in range(m)]        # матриця провідностей
    b = [0.0] * m                            # права частина
    for u, v, R in pipes:
        g = 1.0 / R
        for a, c in ((u, v), (v, u)):        # труба симетрична: внесок з обох боків
            if a in idx:
                i = idx[a]
                G[i][i] += g                 # діагональ: сума провідностей вузла
                if c in idx:
                    G[i][idx[c]] -= g        # позадіагональ: −провідність зв'язку
                else:
                    b[i] += g * pressures[c]  # сусід із заданим тиском → у праву частину

    p_unknown = solve_linear(G, b)
    p = dict(pressures)
    for n, i in idx.items():
        p[n] = p_unknown[i]

    # витрати по трубах: Q = (p_u − p_v)/R, додатна — від u до v
    Q = {(u, v): (p[u] - p[v]) / R for u, v, R in pipes}
    return p, Q
```

Лишилося розв'язати саму систему. Для невеликої мережі досить прямого [методу Гаусса — виключення невідомих із вибором головного елемента](root:math-algebra/linear-systems); нікотрих бібліотек не треба, щоб було видно, що всередині немає магії:

```py
def solve_linear(A, b):
    """Розв'язати A·x = b (щільна невелика система) методом Гаусса
    з вибором головного елемента за стовпцем. A — рядки, b — вектор."""
    n = len(b)
    M = [row[:] + [b[i]] for i, row in enumerate(A)]   # робоча копія з правою частиною
    for col in range(n):
        piv = max(range(col, n), key=lambda r: abs(M[r][col]))   # головний елемент
        if abs(M[piv][col]) < 1e-300:
            raise ValueError("вироджена система: немає єдиного розв'язку")
        M[col], M[piv] = M[piv], M[col]
        for r in range(col + 1, n):          # прямий хід: занулюємо стовпець нижче
            f = M[r][col] / M[col][col]
            for c in range(col, n + 1):
                M[r][c] -= f * M[col][c]
    x = [0.0] * n
    for i in range(n - 1, -1, -1):           # зворотний хід
        s = M[i][n] - sum(M[i][c] * x[c] for c in range(i + 1, n))
        x[i] = s / M[i][i]
    return x
```

> 🔧 **Навіщо це.** Той самий десяток рядків рахує геть різні речі: розкладку мікрофлюїдного чипа (де кожен канал — опір, а треба, щоб проби зустрілися в потрібній пропорції), баланс водогінної мережі району, тиск у гілках системи охолодження, розподіл припливу в припливно-витяжній вентиляції. Скрізь, де рідина чи газ тече мережею під натиском і течія лишається плавною, інженер не інтегрує рівняння руху — він зводить усе до опорів і розв'язує лінійну систему. Дешевше порахувати сотню варіантів схеми, ніж змонтувати бодай один.

## Приклад: мережа-місток, яку не звести

Візьмемо мережу, що зумисне **не** розкладається на послідовні й паралельні шматки, — топологію містка (її ще звуть мостом Вітстона). Чотири вузли: **A** — джерело під тиском 1000 Па, **D** — стік із тиском 0, а між ними два внутрішні вузли **B** і **C**, зшиті п'ятьма трубами, зокрема поперечним «містком» B–C. Саме перемичка все псує: жодну пару труб тут не можна оголосити «просто послідовними» чи «просто паралельними», тож формули додавання пасують — а метод вузлів бере її без запинки.

```py
mu = MU_WATER
def R(r_mm, L_cm):                            # зручний конструктор опору з міліметрів
    return pipe_resistance(r_mm * 1e-3, L_cm * 1e-2, mu)

pipes = [
    ("A", "B", R(1.0, 10)),                   # 2.55·10⁸
    ("A", "C", R(0.8, 10)),                   # 6.22·10⁸
    ("B", "C", R(0.6, 10)),                   # 1.96·10⁹  ← місток (найвужчий → найтвердіший)
    ("B", "D", R(0.8, 10)),                   # 6.22·10⁸
    ("C", "D", R(1.0, 10)),                   # 2.55·10⁸
]
pressures = {"A": 1000.0, "D": 0.0}           # Па
p, Q = solve_network(pipes, pressures)
```

Прогін дає повний розподіл — тиски в обох невідомих вузлах і витрату в кожній із п'яти гілок:

```
тиски у вузлах:      p_B ≈ 677 Па      p_C ≈ 323 Па        (p_A = 1000, p_D = 0)
витрати (×10⁻⁶ м³/с):
   A→B  1.27     A→C  1.09            ← з джерела виходить 1.27 + 1.09 = 2.36
   B→D  1.09     C→D  1.27            ← у стік входить те саме 2.36  ✓ збережено
   B→C  0.18                          ← місток несе мало
повна витрата мережі  Q ≈ 2.36·10⁻⁶ м³/с;  еквівалентний опір  R_екв = Δp/Q ≈ 4.24·10⁸ Па·с/м³
```

*Розв'язана мережа: у вузлах — тиски, у гілках — витрати (товщина стрілки ∝ витраті). Місток B–C несе всього 0.18 проти 1.27 у крайніх трубах. Тиски B і C склалися в 1000 не випадково — мережа симетрична, і баланс сам це впорядкував.*

Кілька речей у цій відповіді варті ока. По-перше, витрати збігаються на вході й виході (2.36 = 2.36) і в кожному вузлі окремо — це не підганяння, а **наслідок** того, що ми будували матрицю саме з балансів; збереження вбудоване в метод. По-друге, місток несе мізер (0.18 проти 1.27) — бо він і найвужчий, і тиски його кінців близькі. Тут ховається знайомий електрикам факт: якби плечі містка були **збалансовані** (R_AB/R_BD = R_AC/R_CD), тиски B і C зрівнялися б і поперечна труба не несла б **нічого** — точнісінько умова рівноваги моста Вітстона, перенесена в гідравліку. Наша мережа розбалансована, тож крапля крізь місток таки біжить, з B у C.

## Прогін на чутливість: один R⁴ душить усю мережу

Тепер випробуймо на мережі те, чим сумнозвісний закон Пуазейля, — люту чутливість до радіуса. Звузьмо **одну** трубу, вхідну A–B, удвічі: радіус із 1.0 до 0.5 мм. Її власний опір підскочить у 2⁴ = 16 разів. Що станеться з цілою мережею? Змінюємо один рядок і розв'язуємо наново:

```py
pipes[0] = ("A", "B", R(0.5, 10))            # радіус A–B: 1.0 → 0.5 мм, опір ×16
p2, Q2 = solve_network(pipes, pressures)
```

```
було:    повна витрата 2.36·10⁻⁶ м³/с
стало:   повна витрата 1.36·10⁻⁶ м³/с        ← упала до 58%, тобто майже навпіл
тиски:   p_B ≈ 164 Па (було 677),  p_C ≈ 280 Па (було 323)
місток:  Q(B→C) ≈ −0.06            ← ЗМІНИВ ЗНАК: тепер тече C→B, а не B→C
```

Придушили одну трубу з п'яти — і пропускна здатність усієї мережі впала майже вдвічі. Мало того, потік **переклався**: раніше вхід A–B ніс більше за A–C (1.27 проти 1.09), тепер несе втричі менше (0.21 проти 1.16) — рідина обтікає задавлену гілку через сусідню. І місток розвернувся: вузол B, відрізаний тепер тонкою A–B, просів у тиску нижче за C, тож крапля крізь перемичку побігла назад. Ось де метод вузлів показує силу, якої олівцем не дістати: він не лише каже, **на скільки** впала витрата, а й показує, як потік сам перерозподілився по всій мережі у відповідь на одну зміну. Саме так тонкий шар накипу в одній ділянці труби чи наліт в одній артерії підступно душить систему цілком — а не лише свою гілку.

## Складність і пастки

Алгоритм короткий, але за його простотою — кілька місць, де легко зламати або собі, або фізиці. Перелічмо чесно.

**Одиниці — усе в СІ, і R⁴ карає безжально.** Радіус — у метрах, не міліметрах; довжина — у метрах; в'язкість — у Па·с. Забудеш перевести міліметри — і через `radius**4` опір поїде у 10¹² разів, а мережа «потече» цілком неправдоподібно. Через четвертий степінь навіть дрібна плутанина в одиницях довжини дає не десятки відсотків, а порядки. Тому конструктор `R(r_mm, L_cm)` у прикладі бере зручні одиниці й переводить їх в одному місці — це не косметика, а сторож від найчастішої помилки.

**Опір лінійний лише в ламінарному режимі.** Уся будова — сталий опір, лінійна система — стоїть на законі Пуазейля, а він чинний, тільки поки течія плавна, шарувата. Розжени рідину до вихорів — і [число Рейнольдса перевалить за критичне ≈ 2300](root:ph-mechanics/reynolds-number), настане турбулентність, а опір **перестане бути сталим**: він почне рости з витратою, залежність Q від Δp викривиться, і єдиний матричний розв'язок утратить чинність. Тому чесний код мусить після розв'язання **перевірити Re в кожній гілці** й попередити, якщо десь вилізли з ламінарної зони: там числа з таблиці вже брешуть. Метод не відмовляє — відмовляє аналогія під ним.

**Стала течія, нестислива рідина, жорсткі стінки.** Матриця провідностей описує **усталений** стан. Гідравлічний удар, пульсівний кровотік, розгін насоса — це вже нестала гідравліка, де до опору додаються «гідравлічна індуктивність» (інерція стовпа рідини) та «ємність» (податливі стінки чи стисливий газ). Аналогія з колом і тут тримається — але то вже RLC-коло, а не чиста мережа резисторів, і наш разовий розв'язок його не покриває.

**Мережа мусить мати опору — інакше система вироджена.** Потрібен щонайменше один вузол із **заданим** тиском (джерело, стік або просто опорний нуль). Без такої «землі» тиски визначені лише з точністю до сталої — додай до всіх однакову величину, витрати не зміняться, — і матриця стає виродженою, `solve_linear` справедливо кине помилку. Фізично це та сама вимога, що й у колі: десь треба заземлитися. До речі, зібрана матриця *G* — це зважений граф-лапласіан мережі: симетричний, з додатними діагоналями; заземлення одного вузла робить його оборотним, а разом гарантує єдиний розв'язок.

**Ньютонівська рідина.** Метод припускає, що в'язкість μ — стала. Для води, олії, повітря це так. Для крові — ні: її в'язкість залежить від швидкості зсуву й ширини судини, тож опір судини сам залежить від витрати, і система знову стає нелінійною. Іронія та сама, що й з усім законом Пуазейля: він народився з пошуку правила крові, а служить простим рідинам; для крові мережа опорів — лише перше наближення.

**Про швидкодію — без страху.** Збирання матриці — один прохід по трубах, O(гілок). Прямий метод Гаусса коштує O(n³) для *n* невідомих вузлів, та реальні мережі **розріджені** (кожен вузол зшитий із кількома сусідами, не з усіма), тож на великих схемах беруть розріджені розв'язувачі, а для щільної дрібної системи згодиться й `numpy.linalg.solve(G, b)` замість саморобного Гаусса — той самий результат в один рядок. Вузьке місце тут ніколи не в арифметиці, а в тому, щоб не збрехати з одиницями й режимом течії.

## Що винести

Труба поводиться як резистор для рідини, і це не метафора, а робочий інструмент: натиск грає роль напруги, витрата — струму, гідравлічний опір 8μL/(πR⁴) — електричного опору, і закон Пуазейля має ту саму форму, що й закон Ома. Звідси задарма прибувають правила з'єднань (послідовно — опори додаються, паралельно — провідності) і, головне, метод вузлових потенціалів: баланс витрат у кожному вузлі — це закон Кірхгофа, він дає лінійну систему на тиски, а її розв'язок віддає весь розподіл потоку по мережі. Кількадесят рядків коду рахують те, чого олівцем не взяти, — мережу-місток, перерозподіл потоку у відповідь на звуження однієї гілки, лютий обвал витрати від четвертого степеня радіуса. Уся ця сила чинна рівно доти, доки течія лишається плавною й усталеною: щойно вона зривається у вихори або перестає бути стаціонарною, сталий опір бреше, а разом із ним і вся зручна лінійна картина. Тому останній рядок будь-якого такого розрахунку — не значення витрати, а тиха перевірка, що число Рейнольдса ще не вивело нас із того світу, де труба справді резистор.
