# 🛩️ Калькулятор льотної якості: поляра, швидкості й дальність

Відношення підйому до опору дорівнює відношенню коефіцієнтів, L/D = CL/CD, — але це рівність для **однієї** постави крила, для одного кута атаки. Реальне крило працює в цілому діапазоні кутів, і кожен із них — це інший CL, інша швидкість, інша вертикальна швидкість зниження й інша дальність. Пілотові чи конструкторові мало знати, що «десь там є максимум якості»: йому потрібні числа. З якою швидкістю летіти, щоб дотягти найдалі? З якою — щоб протриматися в повітрі найдовше? Скільки я пролечу з цієї висоти, і що зробить із цим зустрічний вітер?

Виявляється, усі ці числа випливають з **одного рядка** — рівняння поляри опору. Напишемо калькулятор, який бере кілька фізичних сталих апарата й видає повну льотну картину. Уся програма — це та поляра плюс дві похідні.

## Задача

На вході — те, що можна знайти в довіднику або зміряти в аеродинамічній трубі:

- **маса** m (кг) — через неї вага W = m·g;
- **площа крила** S (м²);
- **розмах** b (м), або одразу видовження Λ = b²/S;
- **паразитний опір за нульового підйому** CD0 — стала частина опору, тертя й лобовий тиск, що не залежить від підйому;
- **коефіцієнт Освальда** e — наскільки розподіл підйому по розмаху далекий від ідеального еліптичного (для реального крила e ≈ 0.7…0.9);
- **густина повітря** ρ (кг/м³).

На виході потрібно порахувати:

- **(L/D)max** і той єдиний **CL***, за якого якість найбільша;
- **швидкість найкращого планування** V_bg — на ній апарат летить найдалі з даної висоти;
- **швидкість мінімального зниження** V_ms і саму **вертикальну швидкість зниження** (sink) — на ній апарат тримається в повітрі найдовше;
- **досяжну дальність** планування з висоти h, з чесною поправкою на вітер;
- і те, заради чого й названо цю вставку, — **швидкість, яку варто летіти** проти вітру, щоб пройти над землею якнайдалі.

## Ідея: одна поляра, з якої випливає все

Опір крила має дві природи — паразитну (тертя об обшивку, лобовий тиск) і індуктивну (плата за сам підйом, вихори на кінцях крила). У коефіцієнтах це один короткий рядок, **поляра опору**:

```
CD = CD0 + CL² / (π·e·Λ)
```

Перший доданок сталий — паразитний опір байдужий до підйому. Другий росте як квадрат CL — що більший підйом збирає крило, то сильніші кінцеві вихори. Позначмо множник індуктивного доданка одним символом, щоб не тягати дріб:

```
k = 1 / (π·e·Λ)        →        CD = CD0 + k·CL²
```

Тепер уся механіка — це проста алгебра над цим рядком.

**Де максимум якості.** Якість L/D = CL / (CD0 + k·CL²). Прирівняймо похідну по CL до нуля — чисельник похідної дає умову CD0 = k·CL². Це разюче: у точці найкращої якості **індуктивний опір точно дорівнює паразитному**, а повний опір рівно вдвічі більший за паразитний, CD = 2·CD0. Звідси одразу найкращий коефіцієнт підйому й сама стеля якості:

```
CL*      = √(CD0 / k) = √(CD0·π·e·Λ)
(L/D)max = CL* / (2·CD0) = 1 / (2·√(CD0·k)) = ½·√(π·e·Λ / CD0)
```

Остання форма варта того, щоб зупинитися: стеля якості росте як корінь із видовження й корінь із чистоти обшивки (1/√CD0). Ось чому в планера крила такі довгі, а обшивка така вилизана — обидва важелі під коренем, і обидва тиснуть в один бік.

**Як перейти від CL до швидкості.** Підйом тримає вагу. У пологому плануванні кут малий, тож L ≈ W, а підйом — це [напір потоку q = ½·ρ·V², помножений на площу й на CL](topic:ph-mechanics/dynamic-pressure). Прирівнявши до ваги й виразивши швидкість:

```
½·ρ·V²·S·CL = W        →        V = √( 2·W / (ρ·S·CL) )
```

Кожному CL відповідає своя швидкість. Летиш на CL* — маєш V_bg, швидкість найкращого планування.

**Де мінімальне зниження.** Вертикальна швидкість зниження (sink) — це та частка швидкості, що йде вниз: sink = V·sin γ, а через баланс сил sin γ = D/W ≈ D/L. Отже

```
sink = V / (L/D) = V · CD / CL
```

Уважно: найповільніше зниження — це **не** те саме, що найкраща якість. Підставивши V(CL), дістанемо sink ∝ CD / CL^1.5, і мінімум цього виразу лежить в іншій точці: CL_ms = √3·CL*. Там індуктивний опір **утричі** більший за паразитний, а швидкість виходить меншою:

```
CL_ms = √3 · CL*        V_ms = V_bg / ⁴√3 ≈ 0.76 · V_bg
```

Дві різні цілі — дві різні швидкості. **Найкраще планування** — це найпологіша траєкторія, найдалі по землі; летиш швидше. **Мінімальне зниження** — найповільніший спуск, найдовше в повітрі; летиш повільніше й трохи «крутіше» по дальності. Планерист вибирає перше, щоб дотягти до наступного висхідного потоку, і друге, щоб виграти час, поки той потік шукає.

```py
from dataclasses import dataclass
from math import pi, sqrt

@dataclass
class Glider:
    m: float          # маса, кг
    S: float          # площа крила, м²
    b: float          # розмах, м
    CD0: float        # паразитний опір за нульового підйому
    e: float          # коефіцієнт Освальда
    rho: float = 1.225   # густина повітря, кг/м³
    g: float = 9.81

    @property
    def W(self):   return self.m * self.g            # вага, Н
    @property
    def Lam(self): return self.b**2 / self.S         # видовження Λ
    @property
    def k(self):   return 1.0 / (pi * self.e * self.Lam)   # множник індуктивного опору

    def CD(self, CL):                                # поляра опору одним рядком
        return self.CD0 + self.k * CL**2

    @property
    def CL_best(self):                               # CL максимальної якості: індукт. = паразит.
        return sqrt(self.CD0 / self.k)
    @property
    def LD_max(self):
        return 1.0 / (2.0 * sqrt(self.CD0 * self.k))

    def speed(self, CL):                             # швидкість для даного CL (пологе планування, L≈W)
        return sqrt(2.0 * self.W / (self.rho * self.S * CL))

    @property
    def V_bg(self):                                  # швидкість найкращого планування
        return self.speed(self.CL_best)

    @property
    def CL_minsink(self):                            # мінімальне зниження: індукт. = 3·паразит.
        return sqrt(3.0) * self.CL_best
    @property
    def V_ms(self):
        return self.speed(self.CL_minsink)

    def sink(self, V):                               # вертикальна швидкість зниження на швидкості V
        CL = 2.0 * self.W / (self.rho * V*V * self.S)
        return V * self.CD(CL) / CL                  # = V / (L/D)

    def reach(self, h, headwind=0.0):                # проста дальність із висоти з поправкою на вітер
        return self.LD_max * h * (1.0 - headwind / self.V_bg)

    def speed_to_fly(self, headwind=0.0):            # оптимальна швидкість проти вітру
        # максимізуємо (V − вітер)/sink(V) — дотична з точки (вітер, 0) до поляри
        best_V, best_gr = self.V_bg, -1.0
        V = self.V_ms * 0.7
        while V < self.V_bg * 2.2:
            gr = (V - headwind) / self.sink(V)
            if gr > best_gr:
                best_gr, best_V = gr, V
            V += 0.02
        return best_V, best_gr                       # швидкість (м/с) і якість над землею
```
```cpp
#include <cmath>

// Бортовий обчислювач планування: жодної купи, самі float — як у кабінному приладі.
struct Glider {
    float m, S, b, CD0, e;        // маса, площа, розмах, паразит. опір, к-т Освальда
    float rho = 1.225f, g = 9.81f;
};

static const float PI_F = 3.14159265f;

static inline float weight(const Glider& a) { return a.m * a.g; }
static inline float aspect(const Glider& a) { return a.b * a.b / a.S; }
static inline float k_ind(const Glider& a)  { return 1.0f / (PI_F * a.e * aspect(a)); }

// швидкість для заданого CL (пологе планування, L ≈ W)
static inline float speed(const Glider& a, float CL) {
    return sqrtf(2.0f * weight(a) / (a.rho * a.S * CL));
}
// вертикальне зниження на швидкості V
static inline float sink(const Glider& a, float V) {
    float CL = 2.0f * weight(a) / (a.rho * V * V * a.S);
    float CD = a.CD0 + k_ind(a) * CL * CL;
    return V * CD / CL;                              // = V / (L/D)
}

float ld_max(const Glider& a) {
    return 1.0f / (2.0f * sqrtf(a.CD0 * k_ind(a)));
}
float v_best_glide(const Glider& a) {
    float CL_best = sqrtf(a.CD0 / k_ind(a));
    return speed(a, CL_best);
}
// швидкість-щоб-летіти проти вітру: дотична з точки (вітер, 0) до поляри
float speed_to_fly(const Glider& a, float headwind) {
    float best_V = v_best_glide(a), best_gr = -1.0f;
    for (float V = 15.0f; V < 60.0f; V += 0.05f) {
        float gr = (V - headwind) / sink(a, V);
        if (gr > best_gr) { best_gr = gr; best_V = V; }
    }
    return best_V;
}
```

## Швидкість-щоб-летіти: чому проти вітру летять швидше

Найпростіша поправка на вітер — та, що в методі `reach`: помножити дальність на (1 − вітер/V_bg). Вона припускає, що ти й далі летиш на V_bg. Але це **не оптимально**. Проти зустрічного вітру кожна зайва секунда в повітрі — це секунда, за яку вітер зносить тебе назад; вигідно летіти **швидше**, щоб провести в повітрі менше часу, навіть ціною трохи гіршої якості. За попутного вітру — навпаки, повільніше.

Це видно геометрично на **полярі планера** — кривій зниження від швидкості. Найкраще планування у штиль — це точка, куди приходить дотична **з початку координат**: пряма з найменшим нахилом sink/V, тобто з найбільшим V/sink = L/D. Тепер зсунемо початок відліку праворуч на швидкість вітру — у точку (w, 0) — і проведімо дотичну звідти. Вона торкається поляри **правіше**, на більшій швидкості: це і є швидкість, яку варто летіти.

![Поляра планера — зниження від швидкості. Дотична з початку координат торкається кривої в точці найкращого планування V_bg. Дно кривої — точка мінімального зниження V_ms, на меншій швидкості. Дотична, проведена не з нуля, а з точки зустрічного вітру (w, 0), торкається кривої правіше — на більшій швидкості: це швидкість-щоб-летіти проти вітру.](img/speed-to-fly.svg)
*Три швидкості з однієї кривої. Дно поляри дає мінімальне зниження (найдовше в повітрі). Дотична з нуля дає найкраще планування (найдалі у штиль). Зсунеш початок дотичної на вітер — і точка дотику з'їде праворуч: проти вітру треба летіти швидше.*

Порахуймо різницю чесно. Метод `speed_to_fly` просто шукає максимум відношення (V − вітер)/sink(V):

```py
V, gr = g.speed_to_fly(headwind=10)
print(f"дальність з 2000 м, штиль          = {g.reach(2000)/1000:5.1f} км")
print(f"…проти вітру 10 м/с (на V_bg)       = {g.reach(2000,10)/1000:5.1f} км")
print(f"…проти вітру 10 м/с (швидк.-летіти) = {gr*2000/1000:5.1f} км, летіти {V:.0f} м/с = {V*3.6:.0f} км/год")
```

```
дальність з 2000 м, штиль          =  92.0 км
…проти вітру 10 м/с (на V_bg)       =  59.5 км
…проти вітру 10 м/с (швидк.-летіти) =  61.4 км, летіти 32 м/с = 115 км/год
```

Зустрічний вітер 10 м/с з'їв третину дальності — з 92 до 59.5 км. А якщо замість завченої V_bg = 102 км/год летіти на розрахованій 115 км/год, дальність над землею підростає до 61.4 км: майже два зайві кілометри з нічого, самим лише правильним вибором швидкості. Для помірного вітру виграш скромний, кілька відсотків, але він **росте** з силою вітру, а надто — коли повітря навколо саме опускається.

Саме цю ідею 1950-х довів до практики американський планерист **Пол Мак-Креді** (Paul MacCready) — триразовий чемпіон США й перший американець-чемпіон світу з планерного спорту. Його узагальнення враховує ще й вертикальний рух повітряної маси та очікувану силу наступного висхідного потоку: початок дотичної зсувають донизу на швидкість зниження повітря й угору на очікуваний набір. Результат живе в кожній кабіні як **кільце Мак-Креді** на варіометрі — простий круговий покажчик, що каже, яку швидкість тримати між потоками. Наш `speed_to_fly` — це найпростіший його випадок: штиль по вертикалі, лише зустрічний вітер.

> 🔧 **Навіщо це.** Той самий калькулятор — це вже майже логіка бортового обчислювача планування. Дай йому поточну висоту, вітер і сталі свого апарата — і він скаже дві речі, від яких залежить безпека: чи дотягнеш ти до смуги (дальність) і з якою швидкістю для цього летіти (швидкість-щоб-летіти). Бортовий варіант у C++-вкладці навмисне без динамічної пам'яті й без подвійної точності — щоб той самий розрахунок ішов на копійчаному мікроконтролері приладу.

## Складність і пастки

Модель тримається на кількох припущеннях, і кожне має межу, за якою число з калькулятора починає брехати.

- **CD0 та e — не сталі, а величини режиму.** Випущене шасі, закрилки, інтерцептори різко піднімають CD0; коефіцієнт Освальда e падає на великих кутах атаки, коли потік біля зриву починає відриватися, і залежить від положення механізації. Одна поляра — це знімок одної конфігурації. Справжні бортові обчислювачі тримають кілька полярів (чиста, із шасі, із закрилками) або підганяють CD0(конфіг) і e(CL).
- **Стисливість на великих швидкостях.** Рядок CD = CD0 + k·CL² мовчки припускає, що повітря нестисливе. За критичного числа Маха над крилом народжується хвильовий опір, CD0 підскакує, і залежність «паразитний ∝ V²» ламається. Для планера це неважливо, а от для швидкого літака модель треба обмежити малими Махами (нижче ≈ 0.5…0.6) або дописати хвильовий доданок.
- **У CL є стеля — зрив.** Поляра дійсна лише до CL_max: [нижче за V_ms, підходячи до зривної швидкості, крило не просто зношується сильніше — воно перестає нести](topic:ph-mechanics/fixed-wing-lift). У коді CL треба обмежувати згори, інакше формула радо видасть швидкість, на якій апарат уже впав би.
- **Приладна швидкість проти істинної.** V = √(2W/(ρSCL)) дає **істинну** швидкість (TAS). Густина ρ падає з висотою, тож той самий CL на висоті означає більшу істинну швидкість: на 3000 м V_bg цього планера — уже 118 км/год проти 102 біля землі, хоча якість L/D та сама. **Аеродинамічна якість від висоти не залежить, а швидкості — залежать**; прилад показує приладну швидкість (за напором), і саме її пілот тримає незмінною.
- **Баласт.** Заллєш у крила водяний баласт — зросте W, і **всі** швидкості поповзуть угору як √W, а от форма поляри й (L/D)max не зміняться ні на йоту. Ось навіщо гоночні планери возять воду: летіти під тим самим кутом планування, але швидше; перед посадкою воду зливають.
- **Пологий кут.** Заміна L = W·cos γ на L ≈ W бездоганна для якості понад сім, але для «сараю» з якістю близько одиниці [дає помітну похибку, і масштаб та число Рейнольдса тут теж міняють картину](topic:ph-mechanics/similarity-scaling) — тоді треба тримати cos γ чесно.

За всім цим стоїть проста думка, з якої варто піти. Ціла льотна карта апарата — стеля якості, дві характерні швидкості, зниження, дальність, швидкість-щоб-летіти — розгортається з **одного рядка**, поляри CD = CD0 + k·CL². Калькулятор не робить нічого хитрого: він бере цей рядок, знаходить дві його похідні й підставляє густину та вагу. Уся аеродинаміка вже сидить у трьох числах — CD0, e і Λ; решта — арифметика.
