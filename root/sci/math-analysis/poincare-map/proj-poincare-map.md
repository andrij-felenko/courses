# ⚙️ Практична реалізація відображення Пуанкаре: алгоритми перетину та чисельне інтегрування

Ця вставка містить практичні алгоритми та повну програмну реалізацію побудови відображення Пуанкаре для нелінійних динамічних систем на мовах C та C++. Розглянуто проблему точного виявлення моментів перетину секущої поверхні, метод Ено, кубічну інтерполяцію Ерміта, адаптивне інтегрування, реконструкцію за Такеном, паралелізацію обчислень, діагностику стиснення фазового простору, чисельне обчислення показників Ляпунова, векторну оптимізацію SIMD, обробку крайових випадків, формати зберігання даних HDF5/Binary, профільовування, інтеграцію в системи комп'ютерного моделювання та пост-обробку.

---

### Постановка обчислювальної задачі

Чисельна побудова відображення Пуанкаре для системи звичайних диференціальних рівнянь `d(x)/dt = f(x, t)` полягає у генеруванні масиву дискретних точок `{x₀, x₁, x₂, ..., xₙ}`, у яких фазова траєкторія перетинає секущу поверхню `Σ = { x ∣ g(x) = 0 }` у фіксованому напрямку.

Класичне інтегрування диференціальних рівнянь методом Рунґе-Кутти 4-го порядку (RK4) здійснюється з кроком по часу `Δt`. Під час інтегрування траєкторія обчислюється у дискретній послідовності моментів часу `tₖ = t₀ + k·Δt`. 

Головна практична проблема полягає у тому, що жодна точка `tₖ` звичайно не потрапляє строго на секущу поверхню `g(x) = 0`. У момент часу `tₖ` система знаходиться з одного боку поверхні (`g(xₖ) < 0`), а на наступному кроці `tₖ₊₁` перелітає за неї (`g(xₖ₊₁) > 0`).

```
+-----------------------------------------------------------------------------------+
|               СХЕМА АЛГОРИТМУ ПОБУДОВИ ПЕРЕРІЗУ ПУАНКАРЕ                          |
+-----------------------------------------------------------------------------------+
| 1. Крок інтегрування ODE: x(tₖ) ──► x(tₖ + Δt) за методом RK4 / RKF45            |
| 2. Перевірка умови перетину: g(xₖ) · g(xₖ₊₁) < 0   та   ∇g · f > 0                |
| 3. Пошук кореня: точне визначення t* ∈ (tₖ, tₖ₊₁) де g(x(t*)) = 0 (Ено/Ерміт)    |
| 4. Запис точки перетину: збереження стану x* = x(t*) у буфер відображення         |
+-----------------------------------------------------------------------------------+
```

Просте збереження стану `xₖ₊₁` замість точної точки перетину призводить до похибки порядку `O(Δt)`. При великих проміжках часу ця похибка накопичується та повністю спотворює фрактальну структуру дивного атрактора. Для забезпечення високої точності (наприклад, `10⁻¹²`) застосовуються спеціальні алгоритми уточнення кореня перетину.

### Алгоритми уточнення точки перетину секущої поверхні

#### 1. Метод Ено (Hénon's Method)

Метод Мішеля Ено є найелегантнішим алгоритмом, оскільки він не вимагає ітераційного підбору кореня. При виявленні зміни знака `g(xₖ) · g(xₖ₊₁) < 0` система тимчасово змінює незалежну змінну з часу `t` на секущу функцію `g`.

Розглянемо автономну диференціальну систему у векторній формі:

```
dx/dt = f₁(x, y, z)
dy/dt = f₂(x, y, z)
dz/dt = f₃(x, y, z)
```

Припустимо, що секуща поверхня задається плоскою умовою `x = c` (тобто `g(x, y, z) = x - c = 0`). Оскільки у точці перетину вектор фазової швидкості `dx/dt = f₁(x, y, z) ≠ 0` не дорівнює нулю за умовою трансверсальності, ми приймаємо координату `x` за нову незалежну змінну замість часу `t`.

Нова диференціальна система, де незалежною змінною виступає координата `x`, має вигляд:

```
dy/dx = f₂(x, y, z) / f₁(x, y, z)
dz/dx = f₃(x, y, z) / f₁(x, y, z)
dt/dx = 1 / f₁(x, y, z)
```

Виконуючи всього один крок інтегрування за методом Рунґе-Кутти від поточного стану `xₖ` до цільового значення `x = c` з кроком `h_x = c - xₖ`, ми отримуємо точний стан `(y*, z*)` та точний час `t*` безпосередньо на секущій поверхні `x = c` без використання будь-яких ітераційних циклів.

#### 2. Кубічна інтерполяція Ерміта

Якщо переобчислення векторного поля `f` для зміненої системи є складним (наприклад, при використанні стороннього розв'язувача диференціальних рівнянь), застосовується кубічний інтерполяційний поліном Ерміта.

Оскільки на кроці `[tₖ, tₖ₊₁]` відомі вектори станів `xₖ, xₖ₊₁` та вектори фазових швидкостей `vₖ = f(xₖ), vₖ₊₁ = f(xₖ₊₁)`, інтерполяційний стан `x̂(s)` для безрозмірного часу `s = (t - tₖ)/Δt ∈ [0, 1]` задається кубічною базисною формулою Ерміта:

```
x̂(s) = (1 - 3s² + 2s³)·xₖ + s²·(3 - 2s)·xₖ₊₁ + Δt·s·(1 - s)²·vₖ + Δt·s²·(s - 1)·vₖ₊₁
```

Точка перетину `s*` шукається як корінь одновимірного скалярного рівняння:

```
g(x̂(s*)) = 0
```

Завдяки кубічній точності полінома Ерміта, локальна похибка обчислення стану `x̂(s*)` має порядок `O(Δt⁴)`, що ідеально узгоджується з точністю класичного методу Рунґе-Кутти 4-го порядку. Точний корінь `s*` знаходить за 3-4 ітерації методу Ньютона-Рафсона:

```
s_new = s_old - g(x̂(s_old)) / ( ∇g(x̂(s_old)) · dx̂/ds ∣ₛ₋ₒₗ₉ )
```

### Реконструкція перерізу з експериментального часового ряду (Метод запізнення Такена)

У багатьох практичних фізичних та інженерних експериментах аналітик не має доступу до повного вектора фазового стану `(x, y, z)`, а вимірює лише один скалярний часовий ряд `x(tₖ) = x(t₀ + k·Δt)`.

Згідно з теоремою Такена про вкладення, повний тривимірний фазовий портрет та відповідне відображення Пуанкаре відновлюються за допомогою векторів затримки у покадровому вимірі `d_emb = 3`:

```
Y[k] = ( x(t[k]),  x(t[k] + τ_delay),  x(t[k] + 2·τ_delay) )
```

Час затримки `τ_delay` вибирається за першим нулем автокореляційної функції або за першим мінімумом взаємної інформації.

Після побудови відновленого часового ряду вектори `Y[k]` перевіряються на перетин секущої площини `Σ_recon = { Y ∣ Y₂ = c }`. Точки дискретного перетину `(Y₁(t*), Y₃(t*))` формують експериментальне відображення Пуанкаре, яке є повністю топологічно еквівалентним (дифреоморфним) справжньому відображенню у фазовому просторі вихідної фізичної системи. Цей практичний метод обчислення широко застосовується в аналізі серцевих ритмів у біомедицині, турбулентних коливань потоку у гідродинаміці, діагностиці вібрацій турбін у енергетиці, моніторингу сейсмічних коливань у геології, радіофізиці, кліматології, акустиці та аналізі складних фінансових часових рядів.

### Адаптивний контроль кроку інтегрування (Рунґе-Кутта-Фельберґ RKF45)

Для підвищення швидкодії чисельних розрахунків при обчисленні тривалих хаотичних траєкторій використовується метод Рунґе-Кутти-Фельберґа 5-го порядку з адаптивним вибором кроку (RKF45).

На кожному кроці інтегрування обчислюються два наближення розв'язку: розв'язок 4-го порядку `x₄` та розв'язок 5-го порядку `x₅`. Оцінка локальної чисельної похибки визначається різницею векторів:

```
E_est = ∥ x₅ - x₄ ∥
```

Новий адаптивний крок інтегрування `Δt_new` розраховується за формулою:

```
Δt_new = S · Δt_current · ( Tol / E_est )⁰ˑ²
```

де `S ≈ 0.9` — коефіцієнт безпеки, а `Tol` — задана допустима чисельна похибка (наприклад, `10⁻¹⁰`).

Якщо похибка `E_est > Tol`, крок бракується та переобчислюється з меншим `Δt`. Якщо `E_est ≤ Tol`, крок приймається, а перевірка секущої умови `g(xₖ) · g(xₖ₊₁) < 0` здійснюється вже на адаптивно підібраній сітці.

### Обчислення чисельних множників Флоке та лінеаризованої матриці Якобі

Окрім побудови точок перетину, інженерна задача розрахунку відображення Пуанкаре часто вимагає автоматичного обчислення матриці Якобі `DP(x*)` для оцінки стійкості нерухомої точки `x*`.

Для цього разом із вихідною нелінійною системою `dx/dt = f(x)` одночасно інтегрується матричне рівняння у варіаціях для `N × N` матриці `Y(t)`:

```
dY/dt = Df( x(t) ) · Y(t),   з початковою умовою Y(0) = I
```

У момент завершення періоду `t = T` матриця `Y(T)` дає матрицю монодромії `M`. 

Щоб отримати `(N-1) × (N-1)` матрицю Якобі відображення Пуанкаре `DP(x*)` у дотичному просторі до секущої поверхні `Σ`, застосовується формула проектування:

```
DP(x*) = P_proj · M · ( I - f(x*) · ∇g(x*)ᵀ / ( ∇g(x*) · f(x*) ) )
```

де `P_proj` — матричний оператор проекції з `Rⁿ` на `(N-1)`-вимірну секущу площину `Σ`.

Обчислення власних значень цієї проектованої матриці `DP(x*)` за допомогою стандартних програмних бібліотек (наприклад, функцій `dgeev` з LAPACK чи модуля `Eigen::EigenSolver` у C++) надає чисельні значення множників Флоке `μᵢ`, що дозволяє автоматично класифікувати стійкість знайдених граничних циклів.

### Практичний розрахунок спектра показників Ляпунова методологією Бенеттіна

Для чисельної оцінки швидкості експоненційного розходження початково близьких траєкторій у перерізі Пуанкаре застосовується метод ортогоналізації Грама-Шмідта (алгоритм Бенеттіна).

1. Разом з основною траєкторією `xₖ` ітерується набір із `N - 1` ортонормованих базисних векторів відхилення `{v₁, v₂, ..., vₙ₋₁}` у дотичному просторі секущої поверхні.
2. При кожному кроці відображення Пуанкаре `x[k+1] = P(x[k])` вектори відхилення множаться на лінеаризовану матрицю Якобі `wᵢ = DP(x[k]) · vᵢ`.
3. Для запобігання паралельному вирівнюванню всіх векторів уздовж напрямку найбільшого зростання виконується процедура ортогоналізації Грама-Шмідта:

```
u₁ = w₁
e₁ = u₁ / ∥u₁∥

u₂ = w₂ - (w₂ · e₁) · e₁
e₂ = u₂ / ∥u₂∥

...
```

4. Показники Ляпунова `λᵢ` обчислюються як середнє логарифмів коефіцієнтів нормування `dᵢ = ∥uᵢ∥` на тривалому інтервалі `K` ітерацій:

```
λᵢ = (1 / (K · T_avg)) · ∑_{k=1}ᵀ ln( dᵢ⁽ᵏ⁾ )
```

Якщо старший показник `λ₁ > 0`, обчислювальна програма видає фінальний висновок про наявність детермінованого хаосу у досліджуваній системі.

### Векторна SIMD оптимізація та паралелізація обчислень

Для досягнення максимальної обчислювальної продуктивності на сучасних багатиядерних процесорах x86_64 та ARM64 використовується сполучення векторних SIMD-інструкцій (AVX-512 чи ARM Neon) з багатопотоковим виконанням.

#### 1. SIMD-векторизація кроку Рунґе-Кутти
Замість послідовного обчислення однієї траєкторії `(x, v)`, алгоритм обробляє вектор із 4, 8 або 16 незалежних початкових умов або значень параметрів одночасно за допомогою векторних регістрів `__m256d` чи `__m512d`. 

Векторні оператори макросів AVX2 обчислюють коефіцієнти `k₁, k₂, k₃, k₄` для 4 траєкторій за один такт процесора, підвищуючи обчислювальну щільність (FLOP/s) майже у 3.8 раза порівняно зі скалярним кодом.

#### 2. Багатопотокова сітка параметрів
При побудові 2D карт режиму коливань (наприклад, на площині параметрів «амплітуда `f₀` — частота `ω`») область аналізу розбивається на прямокутну сітку `1000 × 1000` вузлів. Кожен потік пулу робіт виконує автономний цикл збору точок перерізу Пуанкаре для своєї чанки параметрів, що гарантує відсутність взаємних блокувань м'ютексів (Lock-free parallelism).

### Повна практична реалізація на мовах C та C++

Нижче наведено робочу реалізацію побудови стробоскопічного перерізу Пуанкаре для осцилятора Дуффінга:

```
d²x/dt² + γ·(dx/dt) - x + x³ = f₀·cos(ω·t)
```

:::tabs
```c
/* Implementation in C (C99 standard) */
#include <stdio.h>
#include <stdlib.h>
#include <math.h>

#define PI 3.14159265358979323846

/* Структура стану 2D осцилятора */
typedef struct {
    double x;   /* координата зміщення */
    double v;   /* швидкість dx/dt */
} State;

/* Параметри осцилятора Дуффінга */
typedef struct {
    double gamma; /* коефіцієнт згасання */
    double f0;    /* амплітуда зовнішнього збудження */
    double omega; /* частота збудження */
} DuffingParams;

/* Правими частини диференціальних рівнянь: dx/dt = v, dv/dt = ... */
static void duffing_rhs(const State* s, double t, const DuffingParams* p, double* dx, double* dv) {
    *dx = s->v;
    *dv = -p->gamma * s->v + s->x - s->x * s->x * s->x + p->f0 * cos(p->omega * t);
}

/* Один крок інтегрування методом Рунґе-Кутти 4-го порядку (RK4) */
static State rk4_step(State s, double t, double dt, const DuffingParams* p) {
    double k1_x, k1_v;
    double k2_x, k2_v;
    double k3_x, k3_v;
    double k4_x, k4_v;

    duffing_rhs(&s, t, p, &k1_x, &k1_v);

    State s2 = { s.x + 0.5 * dt * k1_x, s.v + 0.5 * dt * k1_v };
    duffing_rhs(&s2, t + 0.5 * dt, p, &k2_x, &k2_v);

    State s3 = { s.x + 0.5 * dt * k2_x, s.v + 0.5 * dt * k2_v };
    duffing_rhs(&s3, t + 0.5 * dt, p, &k3_x, &k3_v);

    State s4 = { s.x + dt * k3_x, s.v + dt * k3_v };
    duffing_rhs(&s4, t + dt, p, &k4_x, &k4_v);

    State result;
    result.x = s.x + (dt / 6.0) * (k1_x + 2.0 * k2_x + 2.0 * k3_x + k4_x);
    result.v = s.v + (dt / 6.0) * (k1_v + 2.0 * k2_v + 2.0 * k3_v + k4_v);
    return result;
}

/* Інтерполяція Ерміта для знаходження стану у точний момент часу t_target */
static State hermite_interpolate(State s1, State s2, double t1, double dt, double t_target, const DuffingParams* p) {
    double s = (t_target - t1) / dt;
    double v1_x, v1_v, v2_x, v2_v;

    duffing_rhs(&s1, t1, p, &v1_x, &v1_v);
    duffing_rhs(&s2, t1 + dt, p, &v2_x, &v2_v);

    double h00 = (1.0 - 3.0 * s * s + 2.0 * s * s * s);
    double h10 = s * (1.0 - s) * (1.0 - s);
    double h01 = s * s * (3.0 - 2.0 * s);
    double h11 = s * s * (s - 1.0);

    State res;
    res.x = h00 * s1.x + h10 * dt * v1_x + h01 * s2.x + h11 * dt * v2_x;
    res.v = h00 * s1.v + h10 * dt * v1_v + h01 * s2.v + h11 * dt * v2_v;
    return res;
}

int main(void) {
    DuffingParams params = { .gamma = 0.2, .f0 = 0.3, .omega = 1.0 };

    double T_period = 2.0 * PI / params.omega;
    double dt = T_period / 500.0; /* 500 кроків на один період збудження */

    State current_state = { .x = 0.1, .v = 0.0 };
    double current_time = 0.0;

    /* Пропускаємо перехідний процес (1000 періодів) */
    size_t transient_periods = 1000;
    size_t steps_per_period = 500;

    for (size_t i = 0; i < transient_periods * steps_per_period; ++i) {
        current_state = rk4_step(current_state, current_time, dt, &params);
        current_time += dt;
    }

    /* Збираємо 5000 точок стробоскопічного перерізу Пуанкаре */
    size_t target_points = 5000;
    double next_cross_time = current_time + T_period;

    FILE* out_file = fopen("poincare_section.dat", "w");
    if (!out_file) {
        perror("Не вдалося відкрити файл для запису");
        return EXIT_FAILURE;
    }

    size_t collected = 0;
    while (collected < target_points) {
        State next_state = rk4_step(current_state, current_time, dt, &params);
        double next_time = current_time + dt;

        /* Перевіряємо, чи перенули ми момент стробоскопічного спалаху */
        if (current_time <= next_cross_time && next_time > next_cross_time) {
            State exact = hermite_interpolate(current_state, next_state, current_time, dt, next_cross_time, &params);
            fprintf(out_file, "%.8f\t%.8f\n", exact.x, exact.v);

            collected++;
            next_cross_time += T_period;
        }

        current_state = next_state;
        current_time = next_time;
    }

    fclose(out_file);
    printf("Обчислення завершено. Записано точок у poincare_section.dat\n");
    return EXIT_SUCCESS;
}
```

```cpp
// Implementation in C++ (C++20 standard)
#include <iostream>
#include <vector>
#include <fstream>
#include <cmath>
#include <numbers>
#include <span>
#include <concepts>
#include <expected>

namespace poincare {

struct State {
    double x{0.0};
    double v{0.0};
};

struct SystemParameters {
    double gamma{0.2};
    double f0{0.3};
    double omega{1.0};
};

enum class SectionError {
    FileOpenFailure,
    IntegrationDivergence,
    InvalidParameters
};

class DuffingSystem {
public:
    explicit DuffingSystem(SystemParameters params) : params_(params) {}

    [[nodiscard]] constexpr State rhs(State s, double t) const noexcept {
        return {
            .x = s.v,
            .v = -params_.gamma * s.v + s.x - s.x * s.x * s.x + params_.f0 * std::cos(params_.omega * t)
        };
    }

    [[nodiscard]] State rk4_step(State s, double t, double dt) const noexcept {
        const auto k1 = rhs(s, t);
        const auto k2 = rhs({s.x + 0.5 * dt * k1.x, s.v + 0.5 * dt * k1.v}, t + 0.5 * dt);
        const auto k3 = rhs({s.x + 0.5 * dt * k2.x, s.v + 0.5 * dt * k2.v}, t + 0.5 * dt);
        const auto k4 = rhs({s.x + dt * k3.x, s.v + dt * k3.v}, t + dt);

        return {
            s.x + (dt / 6.0) * (k1.x + 2.0 * k2.x + 2.0 * k3.x + k4.x),
            s.v + (dt / 6.0) * (k1.v + 2.0 * k2.v + 2.0 * k3.v + k4.v)
        };
    }

    [[nodiscard]] State interpolate(State s1, State s2, double t1, double dt, double t_target) const noexcept {
        const double s = (t_target - t1) / dt;
        const auto v1 = rhs(s1, t1);
        const auto v2 = rhs(s2, t1 + dt);

        const double h00 = (1.0 - 3.0 * s * s + 2.0 * s * s * s);
        const double h10 = s * (1.0 - s) * (1.0 - s);
        const double h01 = s * s * (3.0 - 2.0 * s);
        const double h11 = s * s * (s - 1.0);

        return {
            h00 * s1.x + h10 * dt * v1.x + h01 * s2.x + h11 * dt * v1.x,
            h00 * s1.v + h10 * dt * v1.v + h01 * s2.v + h11 * dt * v2.v
        };
    }

    [[nodiscard]] double period() const noexcept {
        return 2.0 * std::numbers::pi / params_.omega;
    }

private:
    SystemParameters params_;
};

class SectionCollector {
public:
    explicit SectionCollector(DuffingSystem sys) : system_(std::move(sys)) {}

    std::expected<std::vector<State>, SectionError> compute_section(
        State initial_state, 
        std::size_t transient_periods, 
        std::size_t num_points, 
        std::size_t steps_per_period) 
    {
        if (steps_per_period == 0 || num_points == 0) {
            return std::unexpected(SectionError::InvalidParameters);
        }

        const double T = system_.period();
        const double dt = T / static_cast<double>(steps_per_period);

        State state = initial_state;
        double t = 0.0;

        // Пропускаємо перехідний режим (transient response)
        for (std::size_t i = 0; i < transient_periods * steps_per_period; ++i) {
            state = system_.rk4_step(state, t, dt);
            t += dt;
            if (std::isnan(state.x) || std::isnan(state.v)) {
                return std::unexpected(SectionError::IntegrationDivergence);
            }
        }

        std::vector<State> section_points;
        section_points.reserve(num_points);

        double next_cross_time = t + T;

        while (section_points.size() < num_points) {
            State next_state = system_.rk4_step(state, t, dt);
            double next_t = t + dt;

            if (t <= next_cross_time && next_t > next_cross_time) {
                State exact = system_.interpolate(state, next_state, t, dt, next_cross_time);
                section_points.push_back(exact);
                next_cross_time += T;
            }

            state = next_state;
            t = next_t;
        }

        return section_points;
    }

private:
    DuffingSystem system_;
};

} // namespace poincare

int main() {
    using namespace poincare;

    SystemParameters params{ .gamma = 0.2, .f0 = 0.3, .omega = 1.0 };
    DuffingSystem system(params);
    SectionCollector collector(system);

    State start{ .x = 0.1, .v = 0.0 };
    auto result = collector.compute_section(start, 1000, 5000, 500);

    if (!result) {
        std::cerr << "Помилка обчислення перерізу Пуанкаре!\n";
        return 1;
    }

    std::ofstream out("poincare_cpp.dat");
    if (!out.is_open()) {
        std::cerr << "Не вдалося відкрити файл poincare_cpp.dat\n";
        return 1;
    }

    for (const auto& pt : *result) {
        out << pt.x << "\t" << pt.v << "\n";
    }

    std::cout << "Успішно обчислено " << result->size() << " точок перерізу Пуанкаре (C++20).\n";
    return 0;
}
```

### Аналіз архітектури коду та вибір ідіом мов C і C++

Наведені C та C++ реалізації демонструють ідіоматичні відмінності системного проектування алгоритмів динамічної фізики.

#### 1. Модульність та керування пам'яттю у C
У програмі на C розрахунок спирається на явні структури `State` та `DuffingParams`. Передача параметрів здійснюється через вказівники для уникнення накладних витрат на копіювання. Вивід точок здійснюється безпосередньо у потік `FILE*`, що усуває потребу у великих динамічних масивах.

#### 2. Безпека типів та RAII у C++20
Версія на C++20 використовує можливості сучасного стандарту:
- **Об'єктно-орієнтований дизайн:** Клас `DuffingSystem` капсулює праву частину рівнянь та параметри, а клас `SectionCollector` відповідає за процедуру збору точок перетину.
- **Типобезпечна обробка помилок:** Замість кодів повернення чи винятків використовується тип `std::expected<std::vector<State>, SectionError>`, який зобов'язує викликаючий код явно обробити ситуацію розбіжності розв'язку.
- **Можливості C++20:** Використання констант вирази `constexpr`, простору імен `std::numbers::pi`, зрізів `std::span` та конструкції `nodiscard` гарантує максимальну продуктивність компиляції.

### Формати збереження великомасштабних даних перетину (Binary та HDF5)

При тривалому високоточному обчисленні перерізу Пуанкаре для багатовимірних систем (наприклад, 6D астрономічна задача `N` тіл або 100D просторово-розподілена модель турбулентності) обсяг записаних точок сягає гігабайтів.

Запис даних у текстовому CSV/TSV форматі є неефективним з двох причин:
1. **Швидкість диску:** Перетворення чисел із плаваючою комою у текстовий рядковий формат `fprintf(file, "%f")` витрачає до 60% загального часу виконання програми.
2. **Втрата точності:** Текстове закруглення числа `0.12345678901234567` до 8 десяткових знаків усуває останні біти мантиси, знижуючи точність.

Завжди використовуйте двійковий запис прямого дампа пам'яті (`fwrite` у C або `ofstream::write` у C++) чи стандартизований формат контейнерів HDF5 / NetCDF:

Двійковий формат забезпечує у 5–10 разів вищу швидкість збереження та гарантує точне бітове збереження IEEE 754 мантиси без втрати інформації.

### Паралелізація обчислень сітки біфуркаційних діаграм

При побудові біфуркаційних діаграм перерізу Пуанкаре вимагається обчислити відображення для тисяч різних значень керуючого параметра `λ ∈ [λ_min, λ_max]`. Оскільки розрахунок траєкторії для кожного параметра `λᵢ` є повністю незалежним, ця задача є ідеально паралельною (Embarrassingly Parallel).

У C++ для паралелізації циклу за параметрами застосовуються потоки OpenMP або стандартизовані алгоритми C++17/C++20 із заголовочного файла `<execution>`:

```cpp
#include <execution>
#include <algorithm>

std::vector<double> lambda_values = generate_parameter_grid(0.1, 0.5, 1000);
std::vector<std::vector<State>> bif_diagram(lambda_values.size());

std::transform(std::execution::par, 
               lambda_values.begin(), lambda_values.end(), 
               bif_diagram.begin(),
               [](double lambda) {
                   SystemParameters params{ .gamma = 0.2, .f0 = lambda, .omega = 1.0 };
                   DuffingSystem sys(params);
                   SectionCollector collector(sys);
                   auto res = collector.compute_section({0.1, 0.0}, 1000, 200, 500);
                   return res ? *res : std::vector<State>{};
               });
```

Використання `std::execution::par` дозволяє лінійно масштабувати обчислення за кількістю ядер процесора, зменшуючи час побудови біфуркаційної діаграми з кількох хвилин до кількох секунд.

### Крайові випадки та чисельна стійкість

При розробці високопродуктивного софту для чисельного розрахунку відображення Пуанкаре необхідно передбачити обробку таких виключних ситуацій:

1. **Дотичний перетин (Loss of Transversality):** Якщо траєкторія торкається поверхні під малим кутом `∇g · f ≈ 0`, пошук кореня методом Ньютона може дивергувати. Програма повинна відкидати такі точки за порогом `∣∇g · f∣ < ε_tangent`.
2. **Розбіжність інтегрування (Unbounded Motion):** У неутримувальних потенціалах (наприклад, у м'якому осциляторі Дуффінга) при великих амплітудах стан `x(t)` прямує до нескінченності. Програма повинна перевіряти масив на `std::isnan` чи `std::isinf` і переривати обчислення з поверненням помилки.
3. **Застрягання у перехідних режимах:** При близьких до біфуркації параметрах (критичне сповільнення) перехідний процес може тривати десятки тисяч періодів. Оцінка стаціонарності повинна аналізувати дисперсію останніх `N` перетинів.

### Чисельні пастки та оптимізація продуктивності

При проведення високопродуктивних розрахунків відображення Пуанкаре слід враховувати кілька важливих чисельних факторів:

#### 1. Усунення перехідних процесів (Transient Response)
Будь-яка дисипативна система потребує часу для того, щоб початковий стан `x₀` втягнувся у стійкий атрактор. Обов'язково пропускайте перші 500–2000 періодів збудження (`transient_periods`), не записуючи їхні точки у переріз Пуанкаре. Якщо записати початкові точки, на картинці перерізу виникне розмитий хвіст перехідного процесів, який буде хибно сприйнято як хаос.

#### 2. Оптимізація пам'яті та уникання динамічного перерозподілу
При накопиченні мільйонів точок у довгих хаотичних траєкторіях постійні виклики `realloc` у C або неконтрольоване розширення `std::vector::push_back` у C++ викликають суттєві затримки. Завжди застосовуйте попереднє зарезервування пам'яті за допомогою `vector::reserve()` або виділяйте стаціонарний кільцевий буфер.

#### 3. Машинна точність чисел із плаваючою комою
Визначення перетинів у системах із сильною дисипацією (де множники Флоке досягають `10⁻⁸`) вимагає використання подвійної точності `double` (64 біти) або розширеної точності `long double` (80 бітів). Використання 32-бітного типу `float` небезпечне: накопичення округлювальних похибок швидко розмиває тонку фрактальну структуру атрактора, імітуючи штучний обчислювальний шум.

#### 4. Автоматична діагностика періодичності
Для автоматичного визначення періоду руху у програмах аналізу будується матриця евклідових відстаней між послідовними точками перетину `d(i, j) = ∥xᵢ - xⱼ∥`. Якщо існує таке ціле `N`, що `d(i, i+N) < ε_tol` для всіх `i`, система автоматично ідентифікує граничний цикл періоду `N·T`.
