# ⚙️ Обчислення числа обумовленості, діагностика матриць Гільберта та регуляризація Тихонова

Число обумовленості визначає, скільки десяткових розрядів точності втратить комп'ютер під час розв'язання лінійної системи `A · x = b`. Цей практичний розбір містить повну алгоритмічну реалізацію методів оцінки числа обумовленості, генератор патологічних матриць Гільберта та Вандермонда, прямий чисельний експеримент із порівняння одинарної (`float32`) та подвійної (`float64`) точності за стандартом IEEE 754, математичний аналіз L-кривої для підбору параметра згладжування, алгоритми компенсаційного сумування Кехена, стабілізацію фільтрів Калмана у формі Джозефа, а також чисельний фільтр Тихонова та методи передобумовлення для стабілізації нестійких систем.

---

### 1. Архітектура та чисельні пастки оцінки обумовленості

Для точного обчислення числа обумовленості за евклідовою 2-нормою `cond₂(A) = σ_max / σ_min` необхідно виконати повний сингулярний розклад (SVD) матриці `A`. Обчислювальна складність SVD для матриці розміру `n × n` становить порядку `O(n³)` операцій із високим константним множником (приблизно `12n³` операцій для двокрокового алгоритму Голуба — Кагана). Якщо задача полягає лише у розв'язанні системи рівнянь, витрачати такий обсяг обчислень лише на діагностику є невиправдано дорогим.

У промислових математичних бібліотеках рівня LAPACK (процедури `sgecon` та `dgecon`) для швидкої діагностики великих систем використовують **алгоритм оцінки 1-норми Хагера — Хайема** (англ. *Hager-Higham 1-norm condition estimator*):

```
cond₁(A) = ‖A‖₁ · ‖A⁻¹‖₁
```

Алгоритм Хагера розглядає обчислення норми `‖B‖₁` (де `B = A⁻¹`) як задачу оптимізації опуклої функції на одиничній сфері за 1-нормою:

```
max_{‖x‖₁ ≤ 1} ‖B · x‖₁
```

Головна перевага цього підходу полягає в тому, що алгоритм ніколи не обчислює саму обернену матрицю `A⁻¹` у явному вигляді (яке вимагало б `O(n³)` операцій та супроводжувалося додатковими похибками). Натомість він використовує вже готовий `LU`-розклад матриці коефіцієнтів `A = P · L · U` і на кожній ітерації розв'язує всього дві трикутні системи:

```
1. Прямий хід оператора:  A · y = x      (знаходження y = A⁻¹ · x)
2. Спряжений хід:         Aᵀ · z = sign(y) (знаходження z = (A⁻¹)ᵀ · sign(y))
```

Вектор `x` оновлюється як одиничний базисний вектор `e_k`, де індекс `k` відповідає координаті з максимальним модулем у векторі `z` (`k = argmax |z_i|`). Якщо на черговому кроці величина `‖z‖_∞ ≤ zᵀ · x`, процес зупиняється, а знайдена норма `‖y‖₁` приймається як оцінка `‖A⁻¹‖₁`. Для переважної більшості практичних матриць алгоритм Хайема збігається всього за 3–5 ітерацій, що дає точність оцінки норми `‖A⁻¹‖₁` у межах коефіцієнта 2–3 при обчислювальних витратах лише `O(n²)` операцій.

### 2. Чому частковий півотинг не рятує від поганої обумовленості

Серед інженерів-початківців поширена омана, нібито застосування методу Гаусса з вибором головного елемента по стовпцю (частковий півотинг, *partial pivoting*) здатне подолати числову нестійкість будь-якої невиродженої матриці.

Це небезпечна ілюзія. Частковий півотинг розв'язує виключно внутрішню алгоритмічну проблему: він гарантує, що множники виключення `l_ik = a_ik / a_kk` за модулем ніколи не перевищують одиниці (`|l_ik| ≤ 1`). Завдяки цьому проміжні числа не розганяються за розрядну сітку комп'ютера, і алгоритм стає **зворотно стійким за Вілкінсоном**:

```
(A + ΔA) · x_comp = b,    де ‖ΔA‖ / ‖A‖ = O(ε_mach)
```

Але якщо сама матриця `A` має величезне число обумовленості `cond(A) ≫ 1`, то це мізерне зворотне збурення `ΔA` на рівні машинного епсилона підсилюється геометрією вихідного оператора в мільярди разів. Півотинг забезпечує бездоганну роботу самого розв'язувача, але не може виправити виродженість фізичної системи.

### 3. Порівняння методів: нормальні рівняння проти QR-розкладу

Розглянемо практичний випадок перевизначеної системи найменших квадратів `A · x ≈ b`, де матриця `A` має розмір `100 × 4` з числом обумовленості `cond₂(A) = 10⁴`.

Якщо інженер розв'язує задачу методом нормальних рівнянь `(Aᵀ · A) · x = Aᵀ · b`:
1. Обчислюється матриця Грама `Aᵀ · A`. При множенні матриць через похибки заокруглення утворюється збурення на рівні `ε_mach`.
2. Число обумовленості матриці `Aᵀ · A` подвоює степінь і стає `(10⁴)² = 10⁸`.
3. При розв'язанні в одинарній точності `float32` (де доступно лише 7 знаків) система втрачає всі значущі цифри, видаючи `100%` похибки.

Якщо ж замість формування `Aᵀ · A` застосовується **QR-розклад на базі відбиттів Хаусхолдера** (*Householder reflections*) `A = Q · R`:
1. Ортогональна матриця `Q` формується як добуток унітарних операторів відбиття `H_k = I - 2 · v_k · v_kᵀ / (v_kᵀ · v_k)`.
2. Ортогональні перетворення мають число обумовленості `cond₂(Q) = 1` і абсолютно не підсилюють шум.
3. Трикутна матриця `R` зберігає вихідне число обумовленості `cond₂(R) = 10⁴`.
4. Розв'язання трикутної системи `R · x = Qᵀ · b` у форматі `float32` зберігає 3 повноцінні значущі цифри, уникаючи чисельної катастрофи.

### 4. Реалізація алгоритмів розрахунку та чисельного експерименту

- Повноцінний розв'язувач лінійних систем методом Гаусса з вибором головного елемента.

- Алгоритм регуляризації Тихонова, що додає згладжуючий член `λ² · I` для придушення нестійкості.

import numpy as np

def hilbert_matrix(n: int, dtype=np.float64) -> np.ndarray:
    """Генерація матриці Гільберта H[i, j] = 1 / (i + j + 1)."""
    i, j = np.ogrid[:n, :n]
    return (1.0 / (i + j + 1)).astype(dtype)

def solve_gaussian_elimination(A: np.ndarray, b: np.ndarray) -> np.ndarray:
    """Метод Гаусса з вибором головного елемента по стовпцю (частковий півотинг)."""
    A_work = A.copy()
    b_work = b.copy()
    n = len(b_work)

    for k in range(n - 1):
        # Вибір головного елемента
        pivot = np.argmax(np.abs(A_work[k:, k])) + k
        if np.abs(A_work[pivot, k]) < 1e-15:
            raise ValueError("Матриця чисельно сингулярна")
        
        # Перестановка рядків
        if pivot != k:
            A_work[[k, pivot]] = A_work[[pivot, k]]
            b_work[[k, pivot]] = b_work[[pivot, k]]

        # Прямий хід виключення
        for i in range(k + 1, n):
            factor = A_work[i, k] / A_work[k, k]
            A_work[i, k:] -= factor * A_work[k, k:]
            b_work[i] -= factor * b_work[k]

    # Зворотна підстановка
    x = np.zeros_like(b_work)
    for i in range(n - 1, -1, -1):
        x[i] = (b_work[i] - np.dot(A_work[i, i + 1:], x[i + 1:])) / A_work[i, i]

    return x

def tikhonov_regularization(A: np.ndarray, b: np.ndarray, lam: float) -> np.ndarray:
    """Регуляризація Тихонова: (AᵀA + λ²I) x = Aᵀb."""
    n = A.shape[1]
    AtA = np.dot(A.T, A)
    Atb = np.dot(A.T, b)
    reg_matrix = AtA + (lam ** 2) * np.eye(n, dtype=A.dtype)
    return solve_gaussian_elimination(reg_matrix, Atb)

    print(f"{'Розмір n':>8} | {'cond_2(H_n)':>14} | {'Похибка float32':>18} | {'Похибка float64':>18}")

    for n in range(2, 11):

        H64 = hilbert_matrix(n, dtype=np.float64)
        x_exact64 = np.ones(n, dtype=np.float64)
        b64 = np.dot(H64, x_exact64)
        
        # Одинарна точність (float32)
        H32 = hilbert_matrix(n, dtype=np.float32)
        x_exact32 = np.ones(n, dtype=np.float32)
        b32 = np.dot(H32, x_exact32)

        # Обчислення точного cond_2 через SVD
        U, s, Vt = np.linalg.svd(H64)
        cond2 = s[0] / s[-1]

        # Розв'язання в float32
        try:
            x_comp32 = solve_gaussian_elimination(H32, b32)
            err32 = np.linalg.norm(x_comp32 - x_exact32) / np.linalg.norm(x_exact32)

#include <stdio.h>
#include <stdlib.h>
#include <math.h>

/* Створення динамічної матриці розміру n x n */
static double* allocate_matrix(int n) {
    return (double*)malloc((size_t)(n * n) * sizeof(double));
}

/* Генерація матриці Гільберта H[i, j] = 1.0 / (i + j + 1) */
static void fill_hilbert(int n, double* H) {
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            H[i * n + j] = 1.0 / ((double)(i + j + 1));
        }
    }
}

/* Обчислення норми 1 матриці: максимум сум абсолютних значень по стовпцях */
static double norm_1(int n, const double* A) {
    double max_col = 0.0;
    for (int j = 0; j < n; ++j) {
        double col_sum = 0.0;
        for (int i = 0; i < n; ++i) {
            col_sum += fabs(A[i * n + j]);
        }
        if (col_sum > max_col) {
            max_col = col_sum;
        }
    }
    return max_col;
}

/* Розв'язання A * x = b методом Гаусса з частковим півотингом */
static int solve_gauss(int n, const double* A, const double* b, double* x) {
    double* A_w = allocate_matrix(n);
    double* b_w = (double*)malloc((size_t)n * sizeof(double));
    if (!A_w || !b_w) {
        free(A_w);
        free(b_w);
        return -1;
    }

    for (int i = 0; i < n * n; ++i) A_w[i] = A[i];
    for (int i = 0; i < n; ++i) b_w[i] = b[i];

    for (int k = 0; k < n - 1; ++k) {
        int pivot = k;
        double max_val = fabs(A_w[k * n + k]);
        for (int i = k + 1; i < n; ++i) {
            double v = fabs(A_w[i * n + k]);
            if (v > max_val) {
                max_val = v;
                pivot = i;
            }
        }

        if (max_val < 1e-15) {
            free(A_w);
            free(b_w);
            return -1; /* Матриця чисельно сингулярна */
        }

        if (pivot != k) {
            for (int j = k; j < n; ++j) {
                double tmp = A_w[k * n + j];
                A_w[k * n + j] = A_w[pivot * n + j];
                A_w[pivot * n + j] = tmp;
            }
            double tmp_b = b_w[k];
            b_w[k] = b_w[pivot];
            b_w[pivot] = tmp_b;
        }

        for (int i = k + 1; i < n; ++i) {
            double factor = A_w[i * n + k] / A_w[k * n + k];
            for (int j = k; j < n; ++j) {
                A_w[i * n + j] -= factor * A_w[k * n + j];
            }
            b_w[i] -= factor * b_w[k];
        }
    }

    /* Зворотний хід */
    for (int i = n - 1; i >= 0; --i) {
        double sum = 0.0;
        for (int j = i + 1; j < n; ++j) {
            sum += A_w[i * n + j] * x[j];
        }
        x[i] = (b_w[i] - sum) / A_w[i * n + i];
    }

    free(A_w);
    free(b_w);
    return 0;
}

/* Регуляризація Тихонова: (AᵀA + λ²I) x = Aᵀb */
static int solve_tikhonov(int n, const double* A, const double* b, double lambda, double* x) {
    double* AtA = allocate_matrix(n);
    double* Atb = (double*)malloc((size_t)n * sizeof(double));
    if (!AtA || !Atb) {
        free(AtA);
        free(Atb);
        return -1;
    }

    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            double sum = 0.0;
            for (int k = 0; k < n; ++k) {
                sum += A[k * n + i] * A[k * n + j];
            }
            if (i == j) sum += lambda * lambda;
            AtA[i * n + j] = sum;
        }
        double b_sum = 0.0;
        for (int k = 0; k < n; ++k) {
            b_sum += A[k * n + i] * b[k];
        }
        Atb[i] = b_sum;
    }

    int res = solve_gauss(n, AtA, Atb, x);
    free(AtA);
    free(Atb);
    return res;
}

int main(void) {
    int n = 4;
    double* H = allocate_matrix(n);
    double* x_exact = (double*)malloc((size_t)n * sizeof(double));
    double* b = (double*)malloc((size_t)n * sizeof(double));
    double* x_comp = (double*)malloc((size_t)n * sizeof(double));
    double* x_reg = (double*)malloc((size_t)n * sizeof(double));

    fill_hilbert(n, H);
    for (int i = 0; i < n; ++i) x_exact[i] = 1.0;

    /* b = H * x_exact */
    for (int i = 0; i < n; ++i) {
        b[i] = 0.0;
        for (int j = 0; j < n; ++j) {
            b[i] += H[i * n + j] * x_exact[j];
        }
    }

    solve_gauss(n, H, b, x_comp);
    solve_tikhonov(n, H, b, 1e-4, x_reg);

    printf("H_4 norm_1 = %.4f\n", norm_1(n, H));
    printf("Розв'язок Гаусса: [%.6f, %.6f, %.6f, %.6f]\n", x_comp[0], x_comp[1], x_comp[2], x_comp[3]);
    printf("Регуляризований:  [%.6f, %.6f, %.6f, %.6f]\n", x_reg[0], x_reg[1], x_reg[2], x_reg[3]);

    free(H);
    free(x_exact);
    free(b);
    free(x_comp);
    free(x_reg);
    return 0;
}

#include <iostream>
#include <vector>
#include <span>
#include <cmath>
#include <iomanip>
#include <expected>
#include <string>

enum class SolverError {
    SingularMatrix,
    DimensionMismatch,
    AllocationFailure
};

class Matrix {
public:
    int rows;
    int cols;
    std::vector<double> data;

    Matrix(int r, int c, double init_val = 0.0)
        : rows(r), cols(c), data(static_cast<size_t>(r * c), init_val) {}

    [[nodiscard]] double& operator()(int r, int c) noexcept {
        return data[static_cast<size_t>(r * cols + c)];
    }

    [[nodiscard]] double operator()(int r, int c) const noexcept {
        return data[static_cast<size_t>(r * cols + c)];
    }

    [[nodiscard]] static Matrix make_hilbert(int n) {
        Matrix H(n, n);
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < n; ++j) {
                H(i, j) = 1.0 / static_cast<double>(i + j + 1);
            }
        }
        return H;
    }

    [[nodiscard]] double norm_1() const noexcept {
        double max_col = 0.0;
        for (int j = 0; j < cols; ++j) {
            double sum = 0.0;
            for (int i = 0; i < rows; ++i) {
                sum += std::abs((*this)(i, j));
            }
            if (sum > max_col) max_col = sum;
        }
        return max_col;
    }
};

[[nodiscard]] std::vector<double> mat_vec_mul(const Matrix& A, std::span<const double> x) {
    std::vector<double> b(static_cast<size_t>(A.rows), 0.0);
    for (int i = 0; i < A.rows; ++i) {
        for (int j = 0; j < A.cols; ++j) {
            b[static_cast<size_t>(i)] += A(i, j) * x[static_cast<size_t>(j)];
        }
    }
    return b;
}

[[nodiscard]] std::expected<std::vector<double>, SolverError> solve_gauss(
    Matrix A, 
    std::vector<double> b
) {
    const int n = A.rows;
    if (A.cols != n || static_cast<int>(b.size()) != n) {
        return std::unexpected(SolverError::DimensionMismatch);
    }

    for (int k = 0; k < n - 1; ++k) {
        int pivot = k;
        double max_val = std::abs(A(k, k));
        for (int i = k + 1; i < n; ++i) {
            double v = std::abs(A(i, k));
            if (v > max_val) {
                max_val = v;
                pivot = i;
            }
        }

        if (max_val < 1e-15) {
            return std::unexpected(SolverError::SingularMatrix);
        }

        if (pivot != k) {
            for (int j = k; j < n; ++j) {
                std::swap(A(k, j), A(pivot, j));
            }
            std::swap(b[static_cast<size_t>(k)], b[static_cast<size_t>(pivot)]);
        }

        for (int i = k + 1; i < n; ++i) {
            double factor = A(i, k) / A(k, k);
            for (int j = k; j < n; ++j) {
                A(i, j) -= factor * A(k, j);
            }
            b[static_cast<size_t>(i)] -= factor * b[static_cast<size_t>(k)];
        }
    }

    if (std::abs(A(n - 1, n - 1)) < 1e-15) {
        return std::unexpected(SolverError::SingularMatrix);
    }

    std::vector<double> x(static_cast<size_t>(n), 0.0);
    for (int i = n - 1; i >= 0; --i) {
        double sum = 0.0;
        for (int j = i + 1; j < n; ++j) {
            sum += A(i, j) * x[static_cast<size_t>(j)];
        }
        x[static_cast<size_t>(i)] = (b[static_cast<size_t>(i)] - sum) / A(i, i);
    }

    return x;
}

[[nodiscard]] std::expected<std::vector<double>, SolverError> solve_tikhonov(
    const Matrix& A,
    std::span<const double> b,
    double lambda
) {
    const int n = A.cols;
    Matrix AtA(n, n, 0.0);
    std::vector<double> Atb(static_cast<size_t>(n), 0.0);

    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            double sum = 0.0;
            for (int k = 0; k < A.rows; ++k) {
                sum += A(k, i) * A(k, j);
            }
            if (i == j) sum += lambda * lambda;
            AtA(i, j) = sum;
        }
        double b_sum = 0.0;
        for (int k = 0; k < A.rows; ++k) {
            b_sum += A(k, i) * b[static_cast<size_t>(k)];
        }
        Atb[static_cast<size_t>(i)] = b_sum;
    }

    return solve_gauss(std::move(AtA), std::move(Atb));
}

int main() {
    const int n = 6;
    auto H = Matrix::make_hilbert(n);
    std::vector<double> x_exact(static_cast<size_t>(n), 1.0);

    std::cout << std::scientific << std::setprecision(4);
    std::cout << "Норма ‖H_6‖₁ = " << H.norm_1() << "\n\n";

### 6. Підбір параметра Тихонова: критерій L-кривої

У реальних інженерних застосуваннях виникає ключове питання: **як вибрати оптимальне значення параметра регуляризації `λ`?**

Якщо вибрати `λ` занадто малим (`λ → 0`), матриця `(Aᵀ·A + λ²·I)` залишиться погано обумовленою, і залишковий шум вимірювань вибухне у розв'язку. Якщо вибрати `λ` занадто великим (`λ ≫ 1`), система стане надзвичайно стабільною, але розв'язок буде надмірно згладженим і спотвореним (велике систематичне зміщення, *bias*).

Основним інструментом автоматичного вибору `λ` є **критерій L-кривої** (англ. *L-curve criterion*), розроблений Пером Крістіаном Гансеном (*Per Christian Hansen*). Якщо побудувати графік у подвійному логарифмічному масштабі:

```
Вісь X: log ‖A · x_λ - b‖₂    [норма нев'язки моделі]
Вісь Y: log ‖x_λ‖₂            [норма самого розв'язку]
```

то для різних значень `λ ∈ (0, ∞)` крива набуває характерної форми латинської літери **L**:
- **Вертикальне плече (малі `λ`):** норма нев'язки майже не зменшується, але норма розв'язку `‖x_λ‖` стрімко злітає вгору через підсилення шумів.
- **Горизонтальне плече (великі `λ`):** розв'язок має малу норму, але нев'язка моделі швидко зростає через надмірне огрублення.
- **Точка кута L-кривої (максимальна кривина):** відповідає математично оптимальному компромісу між точністю відтворення даних та стабільністю розв'язку.

Знаходження кута L-кривої або застосування методу узагальненої крос-валідації (англ. *Generalized Cross-Validation, GCV*) дозволяє повністю автоматизувати стабілізацію обчислень навіть для систем із патологічно високим числом обумовленості.

### 7. Передобумовлення (Preconditioning) як інженерна практика

У випадках, коли матриця є погано обумовленою не через внутрішню виродженість фізичної моделі, а через невдалий вибір одиниць вимірювання (наприклад, змішування мікросекунд із роками або нанометрів із кілометрами), розв'язання можна стабілізувати без внесення штучного зміщення за допомогою **передобумовлення** (англ. *preconditioning*).

Замість вихідної системи `A · x = b` розв'язують еквівалентну систему:

```
M⁻¹ · A · x = M⁻¹ · b
```

де матриця `M` (передобумовлювач) вибирається таким чином, щоб виконувалися дві суперечливі вимоги:
1. Матриця `M` повинна бути максимально близькою до `A`, щоб оператор `M⁻¹ · A ≈ I` мав число обумовленості `cond(M⁻¹ · A) ≈ 1`.
2. Система `M · y = r` повинна розв'язуватися надзвичайно швидко (за час `O(n)` або `O(n log n)`).

Найпростішим варіантом є **діагональне передобумовлення (метод Якобі)**, де `M = diag(a₁₁, a₂₂, …, aₙₙ)`. Воно нормує кожен рядок матриці на його власний діагональний елемент, усуваючи масштабний перекіс між рівняннями. Для симетричних розріджених систем, що виникають у методі скінченних елементів, золотим стандартом є **неповний розклад Холецького (IC)** або **неповний LU-розклад (ILU)**, які зменшують число обумовленості на 4–6 порядків і дозволяють ітераційним методам Крилова (таким як метод спряжених градієнтів, GMRES) збігатися за лічені ітерації.

### 8. Апаратні інструкції FMA та компенсаційне сумування Кехена

При обчисленні скалярного добутку векторів `s = ∑ a_i · b_i` або множенні матриць стандартне послідовне додавання накопичує похибку, яка пропорційна довжині вектора `O(n · ε_mach)`.

Для збереження точності в критичних розрахунках сучасні архітектури процесорів та числові алгоритми застосовують два потужні інструменти:

#### 1. Апаратна інструкція Fused Multiply-Add (FMA)
Інструкція `FMA` (включена у стандарт IEEE 754-2008 та підтримується наборами команд x86 AVX2/AVX-512 та ARM NEON) обчислює вираз:

```
res = (a · b) + c
```

за один машинний такт із **єдиним заокругленням у кінці**. Звичайний компілятор без FMA виконує спершу множення `tmp = round(a * b)`, а потім додавання `res = round(tmp + c)`, що породжує подвійне розсіювання похибки в молодших бітах мантиси. Використання FMA не лише подвоює швидкість множення матриць, але й усуває проміжні похибки скорочення розрядів.

#### 2. Алгоритм сумування Кехена (Kahan Compensated Summation)
Якщо необхідно скласти довгий масив чисел із великим розкидом амплітуд, додавання малого числа до великої поточної суми призводить до повної втрати молодших бітів малого доданка. Алгоритм Вільяма Кехена вводить додаткову змінну компенсації `c`, яка запам'ятовує втрачені при додаванні молодші біти:

```
sum = 0.0
c = 0.0    // компенсація втрачених бітів

for x in data:
    y = x - c             // віднімаємо накопичену похибку від поточного доданка
    t = sum + y           // додаємо до загальної суми (молодші біти y можуть загубитися)
    c = (t - sum) - y     // обчислюємо фактично втрачені біти: (t - sum) відновлює y, мінус y дає залишок
    sum = t               // оновлюємо суму
```

Завдяки цьому компенсованому циклу накопичена похибка сумування зменшується з `O(n · ε)` до `O(2ε + n · ε²)`, фактично забезпечуючи точність подвійної розрядності без переходу на важкі типи даних довільної точності.

### 9. Поліноміальна інтерполяція: рівномірна сітка проти вузлів Чебишова

Покажемо, як вибір вузлів інтерполяції змінює число обумовленості матриці Вандермонда `V_n` на відрізку `[-1, 1]`.

1. **Рівномірна сітка вузлів:** `x_k = -1 + 2(k - 1) / (n - 1)`. При зростанні `n` визначник матриці стрімко падає, а число обумовленості зростає експоненційно:
   - `n = 5`: `cond₂(V₅) ≈ 3.8 × 10²` (втрата 2–3 знаків).
   - `n = 10`: `cond₂(V₁₀) ≈ 2.1 × 10⁶` (одинарна точність на межі).
   - `n = 15`: `cond₂(V₁₅) ≈ 1.4 × 10¹⁰` (одинарна точність видає шум).
   - `n = 20`: `cond₂(V₂₀) ≈ 1.1 × 10¹⁴` (подвійна точність на межі).

2. **Вузли Чебишова першого роду:** `x_k = cos((2k - 1)π / (2n))`. Згущення точок біля країв відрізка придушує крайові осциляції полінома та мінімізує норму константи Лебега:
   - Перехід до базису поліномів Чебишова `T_k(x)` перетворює матрицю системи на ортогональну матрицю з дискретним косинусним перетворенням (DCT), для якої `cond₂(T) = √2 = 1.414` для будь-якого `n`!

Це найважливіший практичний урок чисельного аналізу: **замість боротьби з поганою обумовленістю патологічної матриці слід переформулювати задачу в ортогональному базисі, де обумовленість ідеальна за побудовою**.

### 10. Стабільність коваріаційних матриць у фільтрах Калмана

У бортових навігаційних системах автопілотів та безпілотників стан апарата оцінюється за допомогою розширеного фільтра Калмана (EKF). Центральним елементом фільтра є матриця коваріації похибок оцінки стану `P`, яка математично зобов'язана бути симетричною і строго додатно визначеною (`P = Pᵀ > 0`, усі власні значення `λ_i > 0`).

Стандартна теоретична формула корекції коваріації має вигляд:

```
P_{k|k} = (I - K_k · H_k) · P_{k|k-1}
```

де `K_k` — коефіцієнт підсилення Калмана, а `H_k` — матриця моделі спостережень.

У цифровій арифметиці зі скінченною розрядністю ця проста формула є **чисельно нестійкою**:
1. Множення `(I - K · H) · P` не є алгебраїчно симетричною операцією. Похибки заокруглення в молодших бітах призводять до того, що матриця `P` втрачає симетрію (`p_ij ≠ p_ji`).
2. Якщо вимірювання є високоточними (шум сенсора `R → 0`), матриця спостережень стає погано обумовленою, і множення призводить до катастрофічного скорочення розрядів. Власні значення матриці `P` опускаються нижче нуля (`λ_min < 0`), що означає фізично абсурдну «від'ємну дисперсію» похибки координат і призводить до миттєвого розбігання фільтра та аварії апарата.

Для усунення цієї нестійкості застосовують **стабілізовану форму Джозефа** (*Joseph stabilized update*):

```
P_{k|k} = (I - K_k · H_k) · P_{k|k-1} · (I - K_k · H_k)ᵀ + K_k · R_k · K_kᵀ
```

Обидва доданки у формі Джозефа мають структуру `M · A · Mᵀ`, де `A > 0`. Завдяки цьому матриця `P_{k|k}` гарантовано залишається симетричною та строго додатно визначеною при будь-яких накопичених похибках заокруглення процесора. Для систем із критичними вимогами до надійності застосовують алгоритми факторизації квадратного кореня (SRIF / Square Root Information Filter), які оновлюють безпосередньо трикутний фактор Холецького `S` (`P = S · Sᵀ`), автоматично зменшуючи число обумовленості коваріаційної задачі вдвічі: `cond(S) = √cond(P)`.

### 11. Чисельне профілювання та оптимізація під кеш-пам'ять

При розв'язанні великих систем лінійних рівнянь на сучасних багатоядерних процесорах швидкість обчислень лімітується не стільки тактовою частотою арифметичних блоків, скільки пропускною здатністю підсистеми оперативної пам'яті (пам'яттєвий бар'єр, *memory wall*).

Для досягнення максимальної продуктивності та збереження точності застосовують такі архітектурні прийоми:
1. **Порядок обходу матриць у пам'яті:** мова C зберігає двовимірні масиви за рядками (*row-major*), тоді як Fortran та бібліотека BLAS/LAPACK — за стовпцями (*column-major*). Прямий хід методу Гаусса та модифікований алгоритм Грама — Шмідта для QR-розкладу виконують операції над стовпцями. Звернення до елементів стовпця у форматі *row-major* викликає промах кеш-пам'яті першого рівня (L1 cache miss) на кожному кроці. Організація даних у неперервні блоки вздовж напрямку обчислень прискорює факторизацію у 5–10 разів.
2. **Блочні алгоритми BLAS-3:** класичні алгоритми Гаусса працюють з окремими векторами (рівень BLAS-2, складність `O(n²)` звернень до пам'яті на `O(n²)` обчислень). Блочні алгоритми LAPACK розбивають матрицю на панелі шириною `n_b = 32` або `64` стовпці, зводячи основну роботу до множення матричних блоків (`dgemm`, рівень BLAS-3). Це дозволяє тримати блоки у швидкісній кеш-пам'яті L2/L3 і виконувати до `O(n³)` арифметичних дій при мінімальному навантаженні на системну шину RAM.
3. **Автоматична SIMD-векторизація:** використання компіляторних прапорців векторизації (`-O3 -march=native -ffast-math`) дозволяє процесору задіяти 256-бітні та 512-бітні векторні регістри YMM/ZMM, обробляючи одночасно 4 або 8 чисел подвійної точності за один машинний такт. Проте для погано обумовлених систем опцію `-ffast-math` слід застосовувати з обережністю, оскільки вона дозволяє компілятору довільно змінювати асоціативність операцій додавання, що може додатково збурити обчислення на рівні молодших розрядів мантиси.

### 12. Інженерний чекліст діагностики лінійних систем

При проектуванні математичних рушіїв та вбудованих обчислювачів інженеру рекомендується виконувати такий покроковий аудит:
1. **Перевірка динамічного діапазону коефіцієнтів:** якщо елементи матриці різняться більше ніж на `10⁴`, обов'язково застосовувати рівноваження за рядками та стовпцями (`D_r · A · D_c`).
2. **Швидка оцінка 1-норми за Хайемом:** обчислювати процедуру `dgecon` після LU-розкладу. Якщо оцінка `rcond = 1 / cond₁(A)` падає нижче `10⁻⁵` для `float32` або нижче `10⁻¹²` для `float64`, генерувати попередження про загрозу втрати розрядів.
3. **Заборона нормальних рівнянь:** для будь-якої задачі регресії замість `(AᵀA)⁻¹ Aᵀb` використовувати QR-розклад на базі відбиттів Хаусхолдера.
4. **Регуляризація Тихонова для зашумлених даних:** додавати згладжуючий член `λ² · I`, підбираючи `λ` за кутом L-кривої або методом крос-валідації.
5. **Симетризація коваріаційних матриць:** у кожному ітераційному циклі явно виконувати операцію `P = (P + Pᵀ) / 2` або використовувати факторизацію квадратного кореня.
