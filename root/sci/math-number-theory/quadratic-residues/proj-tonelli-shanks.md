# ⚙️ Алгоритм Тонеллі-Шенкса та обчислення символів Лежандра/Якобі

Ця практична вставка містить покроковий аналіз алгоритмів перевірки квадратичних лишків (символи Лежандра та Якобі), а також алгоритму Тонеллі-Шенкса для знаходження квадратного кореня за модулем простого числа `p`. Наведено математичні інваріанти, покрокове простеження обчислень, розбір крайових випадків, підйом розв'язків за лемою Гензеля, прискорення Монтгомері, зв'язок з алгоритмом Поліґа-Геллмана, стиснення точок еліптичних кривих, криптосистему Рабіна, тест простоти Соловея-Штрассена, генератор Blum Blum Shub, порівняльний аналіз із методом Чиполли, апаратне векторне прискорення AVX-512, інтеграцію з BIGNUM у криптобібліотеках та повні реалізації мовами C та C++ з захистом від переповнення 64-бітових цілих чисел.

---

### Постановка задачі та математичний конвеєр

Розв'язування порівнянь другого степеня вигляду `x² ≡ a (mod p)` є фундаментальною задачею у прикладному аналізі чисел та асиметричній криптографії. Якщо просте число `p` є малим (наприклад, `p < 1000`), корінь можна знайти банальним перебором за час `O(p)`. Проте для великих простих чисел, які використовуються у криптографічних протоколах (від 256 біт до 4096 біт), перебір є принципово неможливим, оскільки вимагатиме більше операцій, ніж атомів у спостережуваному Всесвіті.

Потрібно знайти ефективний алгоритм із логарифмічною складністю `O(log⁴ p)` або `O(log² p)` за кількістю множень.

Математичний конвеєр розв'язання складається з трьох послідовних етапів:

1. **Перевірка спроможності розв'язку:**
   Перш ніж запускати процедуру добування кореня, обчислити символ Лежандра `(a/p)` за допомогою критерію Ейлера `a^((p-1)/2) mod p`. Якщо `(a/p) = -1`, це означає, що число `a` є квадратичним нелишком і порівняння не має жодного розв'язку у полі `ℤₚ`. У такому разі алгоритм негайно завершує роботу.
   Швидке визначення некоректності запиту на першому кроці запобігає ресурсоємним обчисленням у силівській 2-підгрупі та захищає серверні додатки від атак типу «відмова в обслуговуванні» (DoS).

2. **Окремі оптимізовані випадки:**
   - Якщо `a ≡ 0 (mod p)`, єдиним розв'язком є `x = 0`.
   - Якщо `p ≡ 3 (mod 4)`, показник `(p+1)/4` є цілим числом. Корінь обчислюється за один крок модульного піднесення до степеня: `x ≡ a^((p+1)/4) (mod p)`.
   - Якщо `p ≡ 5 (mod 8)`, показник `(p-5)/8` є цілим числом. Розв'язок дається формулою `x ≡ a^((p+3)/8) (mod p)`, якщо `a^((p-1)/4) ≡ 1 (mod p)`, або `x ≡ a^((p+3)/8) · 2^((p-1)/4) (mod p)` у протилежному випадку.

3. **Загальний алгоритм Тонеллі-Шенкса:**
   Застосовується у найскладнішому випадку, коли `p ≡ 1 (mod 4)`. У цьому разі група `ℤₚ*` містить високий степінь двійки у своєму порядку `p - 1`, і обчислення кореня вимагає узгодження інваріантів у силівській 2-підгрупі.

### Механізм алгоритму Тонеллі-Шенкса та його інваріанти

Алгоритм, запропонований Альбертом Тонеллі у 1891 році та незалежно відкритий Деніелом Шенксом у 1972 році, спирається на розклад порядку мультиплікативної групи `p - 1 = 2ˢ · q`, де `q` — непарне ціле число, а `s ≥ 1`.

#### Кроки алгоритму:

1. **Факторизація 2-компоненти:**
   Виділити з `p - 1` максимальний степінь двійки, обчисливши `s` та `q` такі, що `p - 1 = 2ˢ · q` з непарним `q`.

2. **Пошук квадратичного нелишку:**
   Знайти довільний квадратичний нелишок `z` за модулем `p` (тобто таке `z`, що `(z/p) = -1`). Оскільки рівно 50% елементів групи `ℤₚ*` є нелишками, імовірнісний вибір числа `z ∈ {2, 3, 4, ...}` знаходить нелишок в середньому за 2 спроби. На основі `z` обчислюється генератор 2-групи `c ≡ z^q (mod p)`.

3. **Ініціалізація змінних інваріанта:**
   - `R ≡ a^((q+1)/2) (mod p)` (початкове наближення кореня).
   - `t ≡ a^q (mod p)` (інваріант помилки).
   - `M = s` (поточний порядок у 2-групі).

   На кожному кроці алгоритму підтримується фундаментальний алгебраїчний інваріант:
   
   ```
   R² ≡ a · t (mod p)
   ```

   Якщо `t ≡ 1 (mod p)`, то `R² ≡ a · 1 ≡ a (mod p)`, що означає, що `R` є шуканим квадратним коренем!

4. **Основний цикл корекції t:**
   Якщо `t ≢ 1 (mod p)`, то елемент `t` належить до підгрупи коренів з одиниці степеня `2ˢ⁻¹`. Алгоритм шукає найменше ціле число `m` (`0 < m < M`), таке що:

   ```
   t^(2ᵐ) ≡ 1 (mod p)
   ```

   Знайшовши `m`, обчислюємо коефіцієнт корекції `b ≡ c^(2ᴹ⁻ᵐ⁻¹) (mod p)`. Оновлюємо змінні:
   - `R ⟵ (R · b) mod p`
   - `t ⟵ (t · b²) mod p`
   - `c ⟵ b² mod p`
   - `M ⟵ m`

   Після кожного оновлення інваріант `R² ≡ a · t (mod p)` зберігається, а новий порядок елемента `t` стає строго меншим за попередній (`m < M`). Це гарантує, що максимум за `s` кроків `t` перетвориться на `1`.

### Алгебраїчний зв'язок з алгоритмом Поліґа-Геллмана

Алгоритм Тонеллі-Шенкса концептуально можна розглядати як частковий випадок алгоритму Поліґа-Геллмана (Pohlig-Hellman algorithm) для знаходження дискретного логарифма у силівській 2-підгрупі.

Оскільки порядок групи `ℤₚ*` дорівнює `p - 1 = 2ˢ · q`, елемент `t = a^q (mod p)` задовольняє тотожність `t^(2ˢ) ≡ a^(2ˢ·q) = a^(p-1) ≡ 1 (mod p)`.
Це означає, що елемент `t` належить до циклічної 2-групи порядку `2ˢ`, яка породжується генератором `c = z^q (mod p)`.

Задача зменшення помилки `t` еквівалентна знаходженню такого цілого показника `k ∈ [0, 2ˢ - 1]`, що:

```
c^k ≡ t⁻¹ (mod p)
```

Алгоритм Тонеллі-Шенкса обчислює двійкові біти числа `k = k₀ + k₁·2 + k₂·4 + ... + kₛ₋₁·2ˢ⁻¹` послідовно від молодших бітів до старших за допомогою логарифмічних перевірок степеня `t^(2ᵐ) ≡ 1 (mod p)`. Саме тому кожна ітерація зменшує порядок елемента `t` як мінімум удвічі.

### Покрокове простеження алгоритму на двох конкретних прикладах

#### Приклад 1: Розв'язання x² ≡ 5 (mod 41)

1. **Перевірка:** `p = 41`, `a = 5`.
   Критерій Ейлера: `5^((41-1)/2) = 5²⁰ mod 41`.
   `5² = 25 ≡ -16 (mod 41)`, `5⁴ ≡ 256 ≡ 10 (mod 41)`, `5²⁰ ≡ 10⁵ ≡ 1 (mod 41)`.
   Символ Лежандра `(5/41) = 1` — число 5 є квадратичним лишком!

2. **Факторизація p - 1:**
   `41 - 1 = 40 = 2³ · 5`. Отже, `s = 3`, `q = 5`.

3. **Пошук нелишку z:**
   - `z = 2`: `2²⁰ mod 41 = (2¹⁰)² mod 41 = (1024 mod 41)² = (40)² ≡ (-1)² ≡ 1`. 2 — лишок.
   - `z = 3`: `3²⁰ mod 41 = (3⁴)⁵ mod 41 = (81)⁵ mod 41 = (-1)⁵ ≡ -1`. 3 — квадратичний нелишок!
   - Обчислюємо генератор `c ≡ z^q ≡ 3⁵ ≡ 243 ≡ 38 ≡ -3 (mod 41)`.

4. **Початкові значення:**
   - `R ≡ a^((q+1)/2) ≡ 5³ ≡ 125 ≡ 2 (mod 41)`.
   - `t ≡ a^q ≡ 5⁵ ≡ 3125 ≡ 9 (mod 41)`.
   - `M = s = 3`.
   - Перевірка інваріанта: `R² = 4`, `a · t = 5 · 9 = 45 ≡ 4 (mod 41)`. Інваріант `R² ≡ a · t` виконується!

5. **Ітерація 1 основного циклу:**
   - `t = 9 ≢ 1 (mod 41)`.
   - Шукаємо `m`: `t¹ = 9 ≢ 1`, `t² = 9² = 81 ≡ -1 ≢ 1`, `t⁴ = (-1)² = 1 (mod 41)`. Отже, `m = 2`.
   - Обчислюємо `b ≡ c^(2ᴹ⁻ᵐ⁻¹) ≡ c^(2³⁻²⁻¹) ≡ c²¹ ≡ c¹ ≡ 38 (mod 41)`.
   - Оновлюємо значення:
     - `b² = 38² ≡ (-3)² = 9 (mod 41)`.
     - `R ⟵ (R · b) mod 41 = 2 · 38 = 76 ≡ 35 (mod 41)`.
     - `t ⟵ (t · b²) mod 41 = 9 · 9 = 81 ≡ 40 ≡ -1 (mod 41)`.
     - `c ⟵ b² = 9 (mod 41)`.
     - `M ⟵ m = 2`.
   - Перевірка інваріанта: `R² = 35² ≡ (-6)² = 36 ≡ -5 (mod 41)`. `a · t = 5 · (-1) = -5 (mod 41)`. Інваріант знову виконується!

6. **Ітерація 2 основного циклу:**
   - `t = 40 ≢ 1 (mod 41)`.
   - Шукаємо `m`: `t¹ = 40 ≢ 1`, `t² = 40² ≡ (-1)² = 1 (mod 41)`. Отже, `m = 1`.
   - Обчислюємо `b ≡ c^(2²⁻¹⁻¹) ≡ c¹ = 9 (mod 41)`.
   - Оновлюємо значення:
     - `b² = 9² = 81 ≡ 40 (mod 41)`.
     - `R ⟵ (R · b) mod 41 = 35 · 9 = 315 ≡ 28 (mod 41)`.
     - `t ⟵ (t · b²) mod 41 = 40 · 40 = 1600 ≡ 1 (mod 41)`.
     - `c ⟵ 40 (mod 41)`.
     - `M ⟵ m = 1`.

7. **Завершення:**
   `t = 1 (mod 41)`. Алгоритм зупиняється!
   Перший корінь: `x₁ = R = 28`.
   Другий корінь: `x₂ = p - R = 41 - 28 = 13`.

#### Приклад 2: Розв'язання x² ≡ 2 (mod 17)

1. **Перевірка:** `p = 17`, `a = 2`.
   Критерій Ейлера: `2^((17-1)/2) = 2⁸ mod 17 = 256 mod 17 = 1`.
   Число 2 є квадратичним лишком за модулем 17!

2. **Факторизація p - 1:**
   `17 - 1 = 16 = 2⁴ · 1`. Отже, `s = 4`, `q = 1`.

3. **Пошук нелишку z:**
   - `z = 3`: `3⁸ mod 17 = (3⁴)² mod 17 = (81 mod 17)² = (13)² ≡ (-4)² = 16 ≡ -1 (mod 17)`.
   - `z = 3` є нелишком! Generator `c ≡ z^q ≡ 3¹ ≡ 3 (mod 17)`.

4. **Початкові значення:**
   - `R ≡ a^((q+1)/2) ≡ 2¹ ≡ 2 (mod 17)`.
   - `t ≡ a^q ≡ 2¹ ≡ 2 (mod 17)`.
   - `M = s = 4`.

5. **Ітераційний шлях:**
   - Ітерація 1: `t = 2`. `2² = 4`, `2⁴ = 16 ≡ -1`, `2⁸ ≡ 1`. Порядок `m = 3`.
     `b = c^(2⁴⁻³⁻¹) = c¹ = 3`.
     `R ⟵ 2 · 3 = 6 (mod 17)`.
     `t ⟵ 2 · 9 = 18 ≡ 1 (mod 17)`.
   - Завершення за одну ітерацію!
   - Корені: `x₁ = 6`, `x₂ = 17 - 6 = 11`.
   - Перевірка: `6² = 36 = 2 · 17 + 2 ≡ 2 (mod 17)` ✓.

### Підйом розв'язків за лемою Гензеля (Hensel's Lemma Lifting)

Часто у практичних задачах (наприклад, у p-адичному аналізі чи криптографічних порівняннях) виникає потреба знайти корінь за модулем степеня простого числа `x² ≡ a (mod pᵏ)`.

Замість обчислень з нуля для великого модуля `pᵏ`, лема Гензеля дозволяє ітеративно «піднімати» розв'язок `x₁` за модулем `p` до розв'язку `xₖ` за модулем `pᵏ`.

#### Алгоритм підйому:

Якщо відомо розв'язок `xₖ`, такий що `xₖ² ≡ a (mod pᵏ)`, ми шукаємо розв'язок `xₖ₊₁` за модулем `pᵏ⁺¹` у вигляді:

```
xₖ₊₁ = xₖ + t · pᵏ
```

Підставивши цей вираз у порівняння `xₖ₊₁² ≡ a (mod pᵏ⁺¹)`:

```
(xₖ + t · pᵏ)² = xₖ² + 2 · xₖ · t · pᵏ + t² · p²ᵏ ≡ a (mod pᵏ⁺¹)
```

Оскільки `2k ≥ k + 1` для `k ≥ 1`, доданок `t² · p²ᵏ` зникає за модулем `pᵏ⁺¹`:

```
xₖ² + 2 · xₖ · t · pᵏ ≡ a (mod pᵏ⁺¹)
```

Поділивши обидві частини на `pᵏ` (оскільки `xₖ² - a` ділиться на `pᵏ`), отримуємо лінійне порівняння відносно `t`:

```
2 · xₖ · t ≡ (a - xₖ²) / pᵏ (mod p)
```

Оскільки `xₖ ≢ 0 (mod p)` та `p` непарне, число `2 · xₖ` є оберненим за модулем `p`. Отже, коефіціент `t` обчислюється однозначно:

```
t ≡ ((a - xₖ²) / pᵏ) · (2 · xₖ)⁻¹ (mod p)
```

Завдяки лемі Гензеля складна задача розв'язування `x² ≡ a (mod pᵏ)` вимагає лише одного виклику Тонеллі-Шенкса за модулем `p`, після чого розв'язок уточнюється за `O(k)` простих лінійних кроків!

### Апаратне прискорення: Редукція Монтгомері та інструкції AVX-512IFMA

У промислових реалізаціях криптографічних алгоритмів (наприклад, у криптопровайдерах HSM та процесорних інструкціях AVX-512) найдорожчою операцією є класичне ділення `(a · b) % p`. Операція ділення на непідхожий модуль `p` потребує значно більше тактів процесора, ніж множення.

Для прискорення модульного множення у циклі Тонеллі-Шенкса застосовують **простір Монтгомері**.

Обирається число `R = 2⁶⁴` (або `2²⁵⁶`), яке є більшим за `p` та взаємно простим із `p`. Кожне ціле число `x` переводиться у форму Монтгомері:

```
x̄ = (x · R) mod p
```

Множення двох чисел у формі Монтгомері вимагає обчислення виразу `REDUC(x̄ · ȳ)`, де функція `REDUC(T)` обчислює `(T · R⁻¹) mod p` **без жодної операції ділення на p**!

Сучасні серверні процесори (Intel Ice Lake, AMD Genoa) надають спеціалізований набір векторних інструкцій `AVX-512IFMA` (Integer Fused Multiply-Add), такі як `vpmadd52luq` та `vpmadd52huq`. Вони дозволяють виконувати 52-бітові множення у 64-бітних регістрах за 1 такт CPU, прискорюючи модульне множення у редукції Монтгомері в кілька разів.

### Масштабування для довільної довгої арифметики (OpenSSL BIGNUM)

При переході від 64-бітних цілих чисел до криптографічних ключів розміром 256–4096 біт типу `uint64_t` недостатньо. У промислових криптобібліотеках (таких як OpenSSL чи BoringSSL) обчислення виконуються через структуру `BIGNUM` та контекст модульної арифметики `BN_CTX`.

Алгоритмічний контур Тонеллі-Шенкса зберігається без змін:
- Замість `pow_mod` використовується `BN_mod_exp()`, який базується на піднесенні до степеня методом вікна (Windowed Exponentiation) у форматі Монтгомері `BN_MONT_CTX`.
- Замість базового перебору нелишку `z` викликається генератор криптографічно стійких випадкових чисел `RAND_bytes()` для швидкого пошуку кандидату `z` з результатом `BN_kronecker(z, p) == -1`.
- Усі тимчасові змінні `R, t, c, b` виділяються у спеціально зарезервованій пам'яті context `BN_CTX_start()`, щоб уникнути динамічного виділення пам'яті на кожній ітерації циклу.

Впровадження у форматі BIGNUM дозволяє виконувати розв'язання рівнянь другого степеня над 256-бітними еліптичними полями secp256k1 та 4096-бітними модулями за лічені мікросекунди, забезпечуючи високу продуктивність захищених з'єднань TLS 1.3 та криптографічних підписів.

### Детальний розбір функціональних блоків програмного коду

У реалізації мовами C та C++ кожна функція відповідає за свій математичний шар:

1. **Функція `mul_mod(a, b, mod)`:**
   При множенні двох 64-бітних цілих чисел `a` та `b`, чий розмір сягає `2⁶³`, звичайний оператор `a * b` викликає непровідне переповнення 64-бітного регістра CPU (overflow). Щоб уникнути пошкодження даних, на системах із підтримкою GCC/Clang використовується розширений 128-бітний тип `unsigned __int128`. Для інших систем передбачено безпечний фолбек — логарифмічне додавання з підвоєнням (Russian Peasant Multiplication), яке виконує множення за `O(log b)` кроків без виходу за межі 64 біт.

2. **Функція `pow_mod(base, exp, mod)`:**
   Реалізує алгоритм швидкого двопотокового піднесення до степеня (Square-and-Multiply). Цикл розкладає показник `exp` у двійкову систему. Замість `exp` послідовних множень виконується лише `O(log exp)` піднесень до квадрата та множень.

3. **Функція `jacobi_symbol(a, n)`:**
   Обчислити символ Якобі без знання простих множників числа `n`. Алгоритм заснований на законі квадратичної взаємності Якобі. Цикл поступово зменшує `a` та `n`, виділяючи парні фактори 2 (за застосуванням доповняльного закону `(2/n) = (-1)^((n²-1)/8)`) та здійснюючи інверсію `(a/n) ⟵ (n/a)` з урахуванням знака `(-1)^(((a-1)/2)·((n-1)/2))`. Часова складність становить `O(log² n)`.

4. **Шаблонний розв'язувач `QuadraticResidueSolver` у C++20:**
   Реалізований з використанням концепту `UnsignedInteger` (`concept UnsignedInteger = std::is_unsigned_v<T> && sizeof(T) >= 4;`). Повертає безпечний тип `std::optional<SquareRoots>`, унеможливлюючи помилки звернення до невизначених коренів.

### Прикладні застосування у криптографії та числовому аналізі

#### 1. Стиснення точок на еліптичних кривих (ECC Point Decompression)

У сучасних криптосистемах на еліптичних кривих (secp256k1 у Bitcoin/Ethereum, Ed25519) точка кривої задається рівнянням Вайєрштрасса:

```
y² = x³ + a·x + b (mod p)
```

Для економії мережевого трафіку та місця у блокчейні точку передають у «стиснутому» вигляді: передають лише 256-бітну координату `x` та один біт парності для `y`. Одержувач обчислює `α = x³ + a·x + b mod p`. Оскільки `y² = α`, координата `y` обчислюється як квадратний корінь з `α` за допомогою алгоритму Тонеллі-Шенкса. Біт парності визначає, який із двох коренів `y` чи `p - y` слід обрати.

#### 2. Дешифрування у криптосистемі Рабіна (Rabin Cryptosystem)

У криптосистемі Рабіна відкритим ключем є модуль `n = p · q`, де `p` та `q` — секретні прості числа вигляду `p ≡ q ≡ 3 (mod 4)`.
Зашифрування повідомлення `m` виконується квадратичним відображенням:

```
c = m² mod n
```

Для розшифрування одержувач, знаючи факторизацію `n = p·q`, знаходить квадратні корені з `c` за модулем `p` та за модулем `q`:
- `m_p ≡ c^((p+1)/4) (mod p)`
- `m_q ≡ c^((q+1)/4) (mod q)`

Після цього за допомогою **Китайської теореми про залишки** (CRT) відновлюються 4 можливі значення `m` mod `n`. Стійкість схеми Рабіна строго доведена: її злам математично еквівалентний факторизації числа `n`.

#### 3. Тест простоти Соловея-Штрассена (Solovay-Strassen Primality Test)

Тест Соловея-Штрассена перевіряє, чи є непарне число `n` простим. Для випадково обраного `a ∈ [2, n-1]` обчислюється:
- Символ Якобі `j = (a/n)` за допомогою швидко розрахункового алгоритму Якобі `O(log² n)`.
- Показник Ейлера `e = a^((n-1)/2) mod n`.

Якщо `j == 0` або `e ≢ j (mod n)`, число `n` є гарантовано складеним! Якщо ж `e ≡ j (mod n)`, число `n` називається псевдопростим Ейлера за основою `a`. Для будь-якого складеного `n` ймовірність того, що випадкове `a` обдурить тест, не перевищує 50%. Повторивши тест `k` разів з різними `a`, імовірність помилки зменшується до `(1/2)кількість_ітерацій`.

#### 4. Генератор псевдовипадкових чисел Blum Blum Shub (BBS)

Генератор BBS генерує криптографічно стійкі послідовності біт. Модуль `n = p · q` створюється як добуток двох великих простих чисел Блюма (`p ≡ q ≡ 3 mod 4`).
Послідовність стану будується за рекурентною формулою:

```
xₖ₊₁ = xₖ² mod n
```

Вихідний біт на кожному кроці — це молодший біт `xₖ mod 2` (або біт парності). Визначати наступний біт послідовності без знання факторизації `n` дорівнює розв'язанню задачі розрізнення квадратичних лишків за складним модулем (Quadratic Residuosity Problem).

#### 5. Квадратичне сито (Quadratic Sieve) та факторизація чисел

У найшвидших алгоритмах факторизації великих чисел (квадратичне сито та алгоритм загального поля чисел NFS) шукаються пари цілих чисел `x` та `y` такі, що:

```
x² ≡ y² (mod n)    та    x ≢ ±y (mod n)
```

Тоді `x² - y² = (x - y)(x + y)` ділиться на `n`. Обчисливши `НСД(x - y, n)`, з ймовірністю принаймні 50% отримують нетривіальний дільник числа `n`. Квадратичні лишки слугують фундаментом побудови вектора гладких чисел у ситі.

### Порівняльний аналіз: Тонеллі-Шенкс проти Чиполли

| Параметр | Алгоритм Тонеллі-Шенкса | Алгоритм Чиполли |
| :--- | :--- | :--- |
| **Основа алгоритму** | Розклад 2-підгрупи `p - 1 = 2ˢ · q` | Розширення полів `𝔽ₚ² = 𝔽ₚ[√ω]` |
| **Складність (найкращий випадок)** | `O(log p)` при `s = 1` (`p ≡ 3 mod 4`) | `O(log p)` множень у `𝔽ₚ²` |
| **Складність (найгірший випадок)** | `O(s² + log p)` при великому `s` | `O(log p)` суворо детермінована |
| **Захист від сторонніх каналів** | Важко зробити constant-time при змінному `s` | Легко реалізувати constant-time |
| **Потреба у нелишку** | Потрібен один `z`: `(z/p) = -1` | Потрібен `t`: `(t² - a / p) = -1` |

Порівняння показує, що для криптографічних протоколів з незмінним `p` алгоритм Тонеллі-Шенкса є лідером за швидкістю, тоді як алгоритм Чиполли простіший для константних систем захисту від витоку інформації. У розробці власного криптографічного софту слід чітко балансувати між швидкістю виконання 2-групового підходу та стійкістю розширення полів.

### Програмна реалізація мовами C та C++

У реалізаціях нижче особлива увага приділена безпеці 64-бітового множення за модулем `(a · b) mod m`. Щоб уникнути переповнення типів при `m ≈ 2⁶⁴`, використовується вбудований тип `__int128` (для компіляторів GCC/Clang) або алгоритм безпечного множення з подвоєнням.

```c
/* C11 / Posix implementation of Tonelli-Shanks Algorithm */
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>

/* Безпечне 64-бітне множення за модулем: (a * b) % mod з захистом від переповнення */
static uint64_t mul_mod(uint64_t a, uint64_t b, uint64_t mod) {
#if defined(__SIZEOF_INT128__)
    return (uint64_t)(((unsigned __int128)a * b) % mod);
#else
    uint64_t res = 0;
    a %= mod;
    while (b > 0) {
        if (b & 1) res = (res + a >= mod) ? (res + a - mod) : (res + a);
        a = (a + a >= mod) ? (a + a - mod) : (a + a);
        b >>= 1;
    }
    return res;
#endif
}

/* Модульне піднесення до степеня: (base^exp) % mod */
static uint64_t pow_mod(uint64_t base, uint64_t exp, uint64_t mod) {
    uint64_t res = 1;
    base %= mod;
    while (exp > 0) {
        if (exp & 1) res = mul_mod(res, base, mod);
        base = mul_mod(base, base, mod);
        exp >>= 1;
    }
    return res;
}

/* Обчислення символу Лежандра (a / p) через критерій Ейлера */
int legendre_symbol(uint64_t a, uint64_t p) {
    if (a % p == 0) return 0;
    uint64_t res = pow_mod(a, (p - 1) / 2, p);
    return (res == 1) ? 1 : -1;
}

/* Обчислення символу Якобі (a / n) для довільного непарного n */
int jacobi_symbol(int64_t a, int64_t n) {
    if (n <= 0 || (n & 1) == 0) return 0;
    a %= n;
    if (a < 0) a += n;
    
    int result = 1;
    while (a != 0) {
        while ((a & 1) == 0) {
            a >>= 1;
            int64_t n_mod8 = n & 7;
            if (n_mod8 == 3 || n_mod8 == 5) {
                result = -result;
            }
        }
        int64_t temp = a;
        a = n;
        n = temp;
        
        if ((a & 3) == 3 && (n & 3) == 3) {
            result = -result;
        }
        a %= n;
    }
    return (n == 1) ? result : 0;
}

/* Розв'язання рівняння x^2 ≡ a (mod p) алгоритмом Тонеллі-Шенкса */
bool tonelli_shanks(uint64_t a, uint64_t p, uint64_t *root1, uint64_t *root2) {
    a %= p;
    if (a == 0) {
        *root1 = 0;
        *root2 = 0;
        return true;
    }
    
    if (legendre_symbol(a, p) != 1) {
        return false; /* Квадратичний нелишок — розв'язків немає */
    }
    
    /* Окремий випадок p ≡ 3 (mod 4) */
    if ((p & 3) == 3) {
        uint64_t r = pow_mod(a, (p + 1) / 4, p);
        *root1 = r;
        *root2 = p - r;
        return true;
    }
    
    /* 1. Факторизація p - 1 = q * 2^s */
    uint64_t q = p - 1;
    uint64_t s = 0;
    while ((q & 1) == 0) {
        q >>= 1;
        s++;
    }
    
    /* 2. Пошук нелишку z */
    uint64_t z = 2;
    while (legendre_symbol(z, p) != -1) {
        z++;
    }
    
    /* 3. Ініціалізація інваріантів */
    uint64_t c = pow_mod(z, q, p);
    uint64_t r = pow_mod(a, (q + 1) / 2, p);
    uint64_t t = pow_mod(a, q, p);
    uint64_t m = s;
    
    /* 4. Основний цикл зменшення порядків */
    while (t != 1) {
        uint64_t t2i = t;
        uint64_t i = 0;
        for (i = 1; i < m; i++) {
            t2i = mul_mod(t2i, t2i, p);
            if (t2i == 1) break;
        }
        
        if (i == m) return false; /* Захист (не повинен спрацювати) */
        
        uint64_t b = pow_mod(c, 1ULL << (m - i - 1), p);
        r = mul_mod(r, b, p);
        uint64_t b2 = mul_mod(b, b, p);
        t = mul_mod(t, b2, p);
        c = b2;
        m = i;
    }
    
    *root1 = r;
    *root2 = p - r;
    return true;
}

int main(void) {
    uint64_t p = 1000000007ULL; /* 10^9 + 7 */
    uint64_t a = 5ULL;
    uint64_t r1 = 0, r2 = 0;
    
    if (tonelli_shanks(a, p, &r1, &r2)) {
        printf("Квадратні корені з %glu mod %glu: %glu та %glu\n", 
               (double)a, (double)p, (double)r1, (double)r2);
        printf("Перевірка: (%glu^2) mod %glu = %glu\n", 
               (double)r1, (double)p, (double)mul_mod(r1, r1, p));
    } else {
        printf("Число %glu не є квадратичним лишком mod %glu\n", (double)a, (double)p);
    }
    return 0;
}
```

```cpp
// C++20 Idiomatic Implementation using Modern Metaprogramming & Types
#include <iostream>
#include <optional>
#include <cstdint>
#include <concepts>
#include <utility>

namespace numtheory {

// Концепт цілочисельного типу
template <typename T>
concept UnsignedInteger = std::is_unsigned_v<T> && sizeof(T) >= 4;

// Клас Модульної Арифметики із захистом від переповнення
template <UnsignedInteger T>
class ModularArithmetic {
public:
    static constexpr T mul(T a, T b, T mod) noexcept {
#if defined(__SIZEOF_INT128__)
        if constexpr (sizeof(T) <= 8) {
            return static_cast<T>((static_cast<unsigned __int128>(a) * b) % mod);
        }
#endif
        T res = 0;
        a %= mod;
        while (b > 0) {
            if (b & 1) res = (res >= mod - a) ? (res + a - mod) : (res + a);
            a = (a >= mod - a) ? (a + a - mod) : (a + a);
            b >>= 1;
        }
        return res;
    }

    static constexpr T pow(T base, T exp, T mod) noexcept {
        T res = 1;
        base %= mod;
        while (exp > 0) {
            if (exp & 1) res = mul(res, base, mod);
            base = mul(base, base, mod);
            exp >>= 1;
        }
        return res;
    }

    static constexpr int legendre(T a, T p) noexcept {
        if (a % p == 0) return 0;
        T res = pow(a, (p - 1) / 2, p);
        return (res == 1) ? 1 : -1;
    }
};

// Результат добування кореня
struct SquareRoots {
    std::uint64_t root1;
    std::uint64_t root2;
};

// Клас розв'язувача порівняння x^2 ≡ a (mod p)
class QuadraticResidueSolver {
public:
    using Arith = ModularArithmetic<std::uint64_t>;

    static std::optional<SquareRoots> solve(std::uint64_t a, std::uint64_t p) {
        a %= p;
        if (a == 0) return SquareRoots{0, 0};
        
        if (Arith::legendre(a, p) != 1) {
            return std::nullopt; // Квадратичний нелишок
        }

        // Швидка гілка для p ≡ 3 (mod 4)
        if ((p & 3) == 3) {
            std::uint64_t r = Arith::pow(a, (p + 1) / 4, p);
            return SquareRoots{r, p - r};
        }

        // Алгоритм Тонеллі-Шенкса для p ≡ 1 (mod 4)
        std::uint64_t q = p - 1;
        std::uint64_t s = 0;
        while ((q & 1) == 0) {
            q >>= 1;
            s++;
        }

        std::uint64_t z = 2;
        while (Arith::legendre(z, p) != -1) {
            z++;
        }

        std::uint64_t c = Arith::pow(z, q, p);
        std::uint64_t r = Arith::pow(a, (q + 1) / 2, p);
        std::uint64_t t = Arith::pow(a, q, p);
        std::uint64_t m = s;

        while (t != 1) {
            std::uint64_t t2i = t;
            std::uint64_t i = 0;
            for (i = 1; i < m; ++i) {
                t2i = Arith::mul(t2i, t2i, p);
                if (t2i == 1) break;
            }

            if (i == m) return std::nullopt;

            std::uint64_t b = Arith::pow(c, 1ULL << (m - i - 1), p);
            r = Arith::mul(r, b, p);
            std::uint64_t b2 = Arith::mul(b, b, p);
            t = Arith::mul(t, b2, p);
            c = b2;
            m = i;
        }

        return SquareRoots{r, p - r};
    }
};

} // namespace numtheory

int main() {
    constexpr std::uint64_t p = 1000000007ULL;
    constexpr std::uint64_t a = 5ULL;

    if (auto roots = numtheory::QuadraticResidueSolver::solve(a, p)) {
        std::cout << "Корені рівняння x^2 ≡ " << a << " (mod " << p << "):\n";
        std::cout << "x1 = " << roots->root1 << "\n";
        std::cout << "x2 = " << roots->root2 << "\n";
        
        std::uint64_t check = numtheory::ModularArithmetic<std::uint64_t>::mul(roots->root1, roots->root1, p);
        std::cout << "Перевірка: " << roots->root1 << "^2 mod " << p << " = " << check << "\n";
    } else {
        std::cout << "Розв'язку не існує!\n";
    }
    return 0;
}
```

### Практичні пастки, переповнення та криптографічний захист

1. **Захист від атак по сторонніх каналах (Side-Channel Attacks):**
   У реальних криптографічних бібліотеках (наприклад, OpenSSL, libsodium чи secp256k1) базова реалізація Тонеллі-Шенкса не може використовуватися у сирому вигляді, оскільки кількість ітерацій циклу та значення індексів `m` залежать від секретних даних. Це створює загрозу атак за часом виконання (Timing Attacks). У криптопровайдерах застосовують константний час виконання (constant-time operations) або алгоритм Чиполли з фантомними множеннями.

2. **Захист від арифметичного переповнення 64-бітних цілих:**
   При розрахунках з модулями `p > 2³²` звичайне множення `(a * b)` перевищує межу `2⁶⁴ - 1` (наприклад, `(2⁶³ - 1)² ≈ 2¹²⁶`). У реалізації C та C++ додано обгортку `mul_mod`, яка використовує розширений тип `unsigned __int128`. Якщо компілятор не підтримує 128-бітні типи, застосовується алгоритм "Russian Peasant Multiplication" із логарифмічним додаванням.

3. **Складність у найгіршому випадку:**
   Найгірший випадок для алгоритму Тонеллі-Шенкса виникає, коли `p - 1 = 2ˢ · q` має дуже велике значення `s` (наприклад, для простих чисел Ферма `Fₖ = 2^(2^k) + 1`). У цьому разі цикл може виконувати до `O(s²)` множень. Для таких значень `p` алгоритм Чиполли є переважним, оскільки його час є суворо детермінованим `O(log p)`.
