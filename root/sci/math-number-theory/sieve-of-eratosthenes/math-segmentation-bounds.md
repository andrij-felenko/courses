# 🧮 Математичний аналіз складності та вибір оптимуму сегмента

Ця вставка містить строгі математичні доведення просторової та часової складності сегментованого решета, аналіз асимптотики кеш-промахів, оцінку коефіцієнтів стиснення для коліс факторів Modulo 30 та Modulo 210, а також математичне обґрунтування вибору оптимального розміру сегмента.

## 1. Доведення достатності базових простих чисел до √N

Головне математичне твердження, на якому базується сегментація: *Для ідентифікації всіх складених чисел у будь-якому діапазоні [L, R], де R ≤ N, достатньо мати список простих чисел, які не перевищують √N.*

### Доведення

Нехай `n` — довільне складене натуральне число, таке що `1 < n ≤ N`.
За Основною теоремою арифметики число `n` можна подати у вигляді добутку принаймні двох множників, більших за 1:

```
n = a · b,  де  1 < a ≤ b < n
```

Припустимо від супротивного, що обидва множники `a` та `b` строго більші за `√n`:

```
a > √n  та  b > √n
```

Перемноживши ці дві нерівності, отримаємо:

```
a · b > √n · √n = n
```

Але `a · b = n`, отже отримаємо очевидну суперечність: `n > n`.

Отже, наша вихідна гіпотеза була хибною, і принаймні один із множників повинен задовольняти нерівність `a ≤ √n`. Оскільки `a > 1`, за Основною теоремою арифметики число `a` має хоча б один простий дільник `p`. Звідси випливає фундаментальний зв'язок:

```
p ≤ a ≤ √n ≤ √N
```

Тобто будь-яке складене число `n ≤ N` обов'язково має принаймні один простий дільник `p`, що не перевищує `√N`. Якщо число в інтервалі `[L, R]` не ділиться на жодне просте число `p ≤ √N` (і саме не є одним із цих базових простих чисел), воно гарантовано є простим. Доведення повністю завершено.

## 2. Обчислення загальної кількості операцій викреслювання

Під час просіювання інтервалу від 2 до N кожне просте число `p ≤ √N` викреслює свої кратні. Кількість кратних числа `p` на інтервалі довжиною N становить приблизно `N / p`.

Загальна кількість операцій викреслювання `T(N)` виражається математичною сумою:

```
T(N) = ∑_{p ≤ √N} (N / p) = N · ∑_{p ≤ √N} (1 / p)
```

Для аналітичної оцінки суми обернених простих чисел застосовується друга теорема Мертенса, доведена французьким математиком Франсуа Мертенсом у 1874 році:

```
∑_{p ≤ X} (1 / p) = ln(ln X) + M + O(1 / ln X)
```

де `M ≈ 0.2614972128...` — константа Мейсселя-Мертенса.

Підставивши `X = √N` у теорему Мертенса, виконуємо послідовні логарифмічні перетворення:

```
∑_{p ≤ √N} (1 / p)
= ln(ln(N^(1/2))) + M + O(1 / ln √N)       [за теоремою Мертенса для X = √N]
= ln((1/2) · ln N) + M + O(1 / ln N)       [властивість логарифма: ln(a^b) = b · ln a]
= ln(ln N) - ln 2 + M + O(1 / ln N)        [властивість логарифма: ln(a / 2) = ln a - ln 2]
```

Підставляємо отриманий виражений результат у вихідну формулу для оцінки `T(N)`:

```
T(N)
= N · (ln(ln N) - ln 2 + M + O(1 / ln N))  [підстановка суми обернених простих чисел]
= N · ln(ln N) + O(N)                       [групування константних доданків у O(N)]
```

Отже, часова складність решета становить `O(N log log N)`. Оскільки подвійний логарифм `log log N` зростає надзвичайно повільно (наприклад, для `N = 10¹⁸` значення `ln(ln N) ≈ 3.72`), середня кількість операцій викреслювання на одне число залишається практично константною для будь-яких реальних обчислень.

## 3. Модель кеш-промахів: Класичне vs Сегментоване решето

Для аналізу продуктивності на реальному процесорі важливо враховувати не лише арифметичні операції, а й кількість промахів повз кеш пам'яті (Cache Misses).

Нехай `L_line` — розмір лінії кешу в байтах (зазвичай 64 байти = 512 біт).

### 3.1. Класичне решето

При використанні суцільного масиву розміром `N` бітів:
- Для малих простих чисел `p < L_line` декілька викреслювань потрапляють у одну лінію кешу.
- Для великих простих чисел `p > L_line` кожне викреслювання звертається до нової кеш-лінії, що спричиняє промах кешу L1/L2/L3 і звернення до оперативної пам'яті (DRAM).

Сумарна кількість кеш-промахів у класичному решетові оцінюється як:

```
Q_classic(N)
= O(N / L_line + ∑_{L_line < p ≤ √N} (N / p))   [сума промахів за лініями кешу]
= O(N · log(log N) / L_line)                     [підстановка оцінки суми обернених простих]
```

При великих `N` масив не вміщується у кеш, і процесор постійно застопорюється в очікуванні даних із DRAM.

### 3.2. Сегментоване решето

Розглянемо просіювання масиву розміром `N`, розбитого на `N / S` сегментів розміром `S` бітів кожен, де `S` підібрано так, щоб повністю вміщуватися в L1d-кеш процесора (`S ≤ C_L1`).

1. Кожен сегмент завантажується в L1-кеш. Кількість кеш-промахів на завантаження самого сегмента становить `S / L_line`.
2. Усі викреслювання базовими простими числами `p ≤ √N` виконуються над даними, що вже знаходяться в L1-кеші. Звернень до DRAM під час викреслювання немає (`0` кеш-промахів).
3. Сумарна кількість кеш-промахів для всіх `N / S` сегментів:

```
Q_segmented(N)
= (N / S) · (S / L_line) + O(√N)    [добуток кількості сегментів на промахи сегмента]
= N / L_line + O(√N)                [скорочення S у чисельнику та знаменнику]
```

Зауважте: коефіцієнт `log log N` повністю зникає з асимптотики кеш-промахів! Сумарна кількість звернень до DRAM становить мінімально можливе значення `N / L_line` (одноразове потокове читання/запис). Це пояснює прискорення у 5–20 разів на практиці.

## 4. Виведення формули початкового кратного у блоці

Для обробки сегмента `[L, R]` базовим простим числом `p` необхідно знайти найменше ціле число `start`, таке що:

```
start ≥ L,   start ≥ p²,   start ≡ 0 (mod p)
```

1. Найменше кратне `p`, яке не менше за `L`, виражається через округлення вгору (целюла):

```
k = ⌈L / p⌉ = ⌊(L + p - 1) / p⌋
```

2. Перше кратне у діапазоні:

```
start_candidate = k · p = ⌊(L + p - 1) / p⌋ · p
```

3. Враховуючи, що всі складені числа, менші за `p²`, вже були викреслені меншими простими числами `q < p`, ми можемо починати викреслювання одразу з `p²`:

```
start = max(p · p, ⌊(L + p - 1) / p⌋ · p)
```

4. Відносний індекс у локальному масиві `mark[0 .. S-1]`:

```
local_index = start - L
```

Усі наступні кратні у блоці отримують локальні індекси: `local_index + p`, `local_index + 2p`, `local_index + 3p`... доки індекс не перевищить `S - 1`.

## 5. Алгебраїчна густина коліс факторів (Wheel Factorization)

Для аналітичної оцінки ефективності колеса факторів обчислимо коефіцієнт зменшення кількості елементів через функцію Ейлера `φ(n)`.

Функція Ейлера `φ(n)` визначає кількість натуральних чисел, не більших за `n`, які є взаємно простими з `n`.

### 5.1. Колесо Modulo 30 (2 · 3 · 5 = 30)

Обчислюємо значення функції Ейлера для `n = 30`:

```
φ(30)
= 30 · (1 - 1/2) · (1 - 1/3) · (1 - 1/5)    [мультиплікативна формула Ейлера]
= 30 · (1/2) · (2/3) · (4/5)                [обчислення різниць у дужках]
= 8                                         [перемноження дробових множників]
```

Густина кандидатів у прості числа становить `8 / 30 = 4 / 15 ≈ 26.67%`. Коефіцієнт стиснення становить `30 / 8 = 3.75`.

### 5.2. Колесо Modulo 210 (2 · 3 · 5 · 7 = 210)

Обчислюємо значення функції Ейлера для `n = 210`:

```
φ(210)
= 210 · (1 - 1/2) · (1 - 1/3) · (1 - 1/5) · (1 - 1/7)  [мультиплікативна формула Ейлера]
= 210 · (1/2) · (2/3) · (4/5) · (6/7)                   [обчислення різниць у дужках]
= 48                                                    [перемноження дробових множників]
```

Густина кандидатів становить `48 / 210 = 8 / 35 ≈ 22.86%`. Коефіцієнт стиснення становить `210 / 48 = 4.375`.

Перехід від Modulo 30 до Modulo 210 дозволяє відсіяти додатково 3.81% числа кандидатів, проте вимагає зберігання більшої маски остач у пам'яті.

## 6. Вибір математичного оптимуму розміру сегмента S

Знайдемо математичний оптимум для розміру сегмента `S`.

Нехай `C_L1` — розмір L1-кешу даних (наприклад, 32 KB = 262 144 біти).

1. **Якщо `S > C_L1`:** масив сегмента переповнює L1-кеш і витісняється в L2 або L3-кеш, що призводить до зростання затримки доступу з 1–2 тактів до 10–40 тактів CPU.
2. **Якщо `S << C_L1`:** розмір сегмента занадто малий, через що накладні витрати на ініціалізацію циклів, перезапуск потоків та обчислення початкових зсувів `start` для кожного з `π(√N)` базових простих чисел стають більшими за час самого викреслювання.

Оптимальний розмір сегмента становить:

```
S_opt = C_L1   (у байтах або бітах відповідно до структури mark)
```

Для сучасних x86_64 та ARM64 процесорів оптимальне значення `S` лежить у межах від `16 KB` до `64 KB` на один потік обчислень.
