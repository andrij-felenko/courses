# ⚙️ Алгоритми пошуку степенів та перевірки умов Віферіха

Практичне дослідження діофантова рівняння `xᵃ - yᵇ = 1` вимагає ефективних алгоритмів генерації точних степенів, модульного фільтрування потенційних кандидатів та обчислення порівнянь Віферіха для великих простих чисел. Хоча теорема Міхайлеску гарантує відсутність розв'язків, окрім `3² - 2³ = 1`, розробка обчислювального верифікатора дає змогу наочно продемонструвати швидке зростання інтервалів між досконалими степенями, вивчити ефекти переповнення цілочисельних типів та перевірити відсутність взаємних пар Віферіха у заданій числовій області.

У цьому практичному дослідженні розглянуто три ключові алгоритмічні блоки:
1. Алгоритм генерації та сортування точних степенів `u^v` у заданому діапазоні `[2, N]` із видаленням еквівалентних представлень.
2. Модульні фільтри лишок для швидкого відсіювання пар кандидатів.
3. Ефективна реалізація модульного піднесення до степеня та перевірки подвійної умови простих Віферіха за допомогою 128-бітної арифметики.

## Обчислювальна складність та алгоритм генерації степенів

Точним степенем (perfect power) називається натуральне число вигляду `u^v`, де основа `u ≥ 2` та показник `v ≥ 2` є цілими числами. Перші точні степені утворюють послідовність: 4, 8, 9, 16, 25, 27, 32, 36, 49, 64, 81, 100, 121, 125, 128, 144, 169, 196, 216, 225, 243, 256, ...

Для генерації всіх точних степенів, що не перевищують задану верхню межу `N`, не потрібно перебирати всі основи до `N`. Оскільки найменшим можливим показником є `v = 2`, основа `u` не може перевищувати квадратний корінь `√N`.

Для кожної основи `u ∈ [2, ⌊√N⌋]` ми обчислюємо послідовні степені `u², u³, u⁴, ...` доти, доки значення не перевищить `N`. Кількість степенів для фіксованої основи `u` дорівнює `⌊log_u N⌋`.

Загальна кількість точних степенів `P(N)`, що не перевищують `N`, оцінюється асимптотичною формулою:

```
P(N) = √N + ∛N + ∜N + … = O(√N)
```

Головний внесок дають квадрати `u²`, кількість яких дорівнює `⌊√N⌋ - 1`. Куби `u³` додають близько `∛N` нових значень, а старші степені дають нехтовно малий приріст. Для `N = 10¹²` загальна кількість точних степенів складає лише близько `10⁶` елементів.

Під час генерації виникає проблема дублювання значень, які мають кілька представлень у вигляді степеня. Наприклад:

```
16 = 4² = 2⁴
64 = 8² = 4³ = 2⁶
81 = 9² = 3⁴
256 = 16² = 4⁴ = 2⁸
```

Щоб видалити дублікати, згенерований масив пар `(значення, основа, показник)` сортується за значенням, після чого суміжні елементи з однаковим значенням об'єднуються або видаляються.

Складність сортування масиву розміром `O(√N)` складає:

```
O(√N · log N)
```

за часом та `O(√N)` за пам'яттю. Для `N = 10⁹` сортування займає менше ніж 0.05 секунди на сучасному процесорі.

## Модульні фільтри та арифметичні обмеження

Перш ніж виконувати повний обчислювальний аналіз великих степенів, у практичній теорії чисел застосовують **модульні фільтри** (residual sieves). Вони спираються на те, що точні степені за певним модулем `m` можуть набувати лише вузької підмножини остач.

Розглянемо остачі точних квадратів `x²` за малими модулями:

```
x² ≡ 0, 1 (mod 3)            [квадрат ніколи не дає остачу 2 mod 3]
x² ≡ 0, 1, 4 (mod 8)         [квадрат дає лише 0, 1, 4 mod 8]
x² ≡ 0, 1, 4, 9, 5, 3 (mod 7)
```

Аналогічно для точних кубів `y³`:

```
y³ ≡ 0, 1, 6 (mod 7)
y³ ≡ 0, 1, 8 (mod 9)
y³ ≡ 0, 1, 5, 8, 12 (mod 13)
```

Якщо припустити рівність `x² - y³ = 1`, перевіримо можливі остачі за модулем 7:

```
x² mod 7 ∈ {0, 1, 3, 4, 5, 6}
y³ mod 7 ∈ {0, 1, 6}
y³ + 1 mod 7 ∈ {1, 2, 0}
```

Спільними можливими остачами для `x²` та `y³ + 1` за модулем 7 є лише `{0, 1}`. Це означає, що будь-який потенційний розв'язок мусить задовольняти порівняння `x² ≡ 0` або `1 (mod 7)`. Поєднання перевірок за кількома модулями (3, 4, 7, 8, 9, 11, 13, 16) дозволяє відкинути понад 99.9% кандидатів без виконання коштовних операцій високої точності.

## Проблема переповнення та 128-бітна арифметика Віферіха

Для перевірки умови Віферіха `p^(q-1) ≡ 1 (mod q²)` необхідно обчислити степінь за модулем `q²`.

Для простого числа `q = 1093` (перше просте Віферіха за основою 2) модуль `q²` дорівнює:

```
q² = 1093² = 1 194 649
```

Проте для великих простих чисел `q ≈ 10⁹` модуль `q²` сягає значення `10¹⁸`, що є близьким до межі стандартного 64-бітного беззнакового типу `uint64_t` (`2⁶⁴ - 1 ≈ 1.84 × 10¹⁹`).

Під час виконання модульного множення `(a · b) mod q²`, де `a, b < q² ≈ 10¹⁸`, проміжний добуток `a · b` може досягати `10³⁶`. Це перевищує 64-бітну сітку і призводить до мовчазного цілочисельного переповнення (overflow), що спотворює результати обчислень.

Для вирішення цієї проблеми у мовах C та C++ застосовується розширений 128-бітний тип `unsigned __int128`, який підтримується компіляторами GCC та Clang. Він дозволяє виконувати множення 64-бітних чисел із збереженням повного 128-бітного результату без втрати старших розрядів:

```
uint64_t res = (unsigned __int128)a * b % mod;
```

Алгоритм бінарного піднесення до степеня (exponentiation by squaring) виконує обчислення `p^(q-1) mod q²` за `O(log q)` кроків, виконуючи на кожному кроці піднесення до квадрата та модульне множення.

## Порівняльний аналіз реалізацій C та C++

Порівнюючи наведені реалізації C та C++, варто відзначити ключові ідіоматичні відмінності:

1. **Управління пам'яттю та динамічними масивами**:
   - У версії мовою C виділення пам'яті здійснюється вручну через `malloc()` та `realloc()` з явним відстеженням поточного обсягу `capacity` та кількості елементів `count`. Необхідна обов'язкова перевірка повертаваного вказівника на `NULL` після кожного розширення масиву. Освободження пам'яті виконується вручну за допомогою `free()`.
   - У версії мовою C++ використовується стандартний контейнер `std::vector<PowerItem>`, який автоматично керує виділенням та звільненням пам'яті за принципом RAII (Resource Acquisition Is Initialization). Метод `reserve()` дозволяє уникнути зайвих повторних локацій пам'яті.

2. **Сортування та видалення дублікатів**:
   - Версія C використовує функцію стандартної бібліотеки `qsort()`, яка приймає вказівник на універсальну функцію порівняння `compare_powers(const void*, const void*)`. Це вимагає приведення типів вказівників і унеможливлює інлайнінг (inlining) порівняння компілятором.
   - Версія C++ застосовує шаблонний алгоритм `std::sort()` із лямбда-виразом, який піддається повному інлайнінгу компілятором, що забезпечує у 2–3 рази вищу швидкість сортування. Видалення дублікатів виконується комбінацією `std::unique()` та `vector::erase()`.

3. **Гарантія безпеки та обробка переповнення**:
   - В обох мовах для захисту від переповнення 64-бітного цілого числа під час множення `val *= u` використовується умова `limit / u < val`. Якщо ця умова виконується, подальше множення призведе до виходу за межі `2⁶⁴ - 1`, тому цикл переривається.
   - Проміжні 128-бітні обчислення в алгоритмі `mod_pow` виконано за допомогою типізації `unsigned __int128`, що забезпечує коректне обчислення остач для простих чисел упевнено вище `10⁹`.

## Емпіричні результати перевірки

Під час виконання програми для межі `N = 10¹²` алгоритм генерує 1 001 547 точних степенів. У результаті повного сканування масиву знаходиться єдина пара сусідніх степенів:

```
3² - 2³ = 9 - 8 = 1
```

Жодної іншої пари з різницею 1 у діапазоні до `10¹²` не виявлено. Найближчими іншими кандидатами серед невеликих чисел є пара `(25, 27)` із різницею `27 - 25 = 2` (`3³ - 5² = 2`) та пара `(121, 125)` із різницею `125 - 121 = 4` (`5³ - 11² = 4`).

Перевірка умови простих Віферіха для малих простих чисел показує, що хоча окремі прості числа задовольняють умову `p^(q-1) ≡ 1 (mod q²)` для деяких основ (наприклад, `p = 2` та `q = 1093`), жодної подвійної взаємної пари `(p, q)`, де одночасно виконуються обидва порівняння, в обчислених діапазонах не існує, що повністю узгоджується з теоретичним доведенням Міхайлеску.
