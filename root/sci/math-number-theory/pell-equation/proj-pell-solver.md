# ⚙️ Алгоритм пошуку фундаментального розв'язку рівняння Пелля

У цьому інженерному розділі детально розглядається, аналізується та реалізується обчислювальний алгоритм для знаходження найменшого додатного цілочисельного розв'язку (фундаментального розв'язку) квадратичного діофантового рівняння Пелля виду:

```
x² - d·y² = 1
```

де параметр `d` є додатним цілим числом, яке не є точним квадратом.

Алгоритм базується на класичній аналітичній теорії розкладу квадратичної ірраціональності `√d` у періодичний ланцюговий (неперервний) дріб та послідовному обчисленні чисельників і знаменників підхідних дробів `pₙ / qₙ`. Усі обчислення виконуються суворо у цілих числах без використання арифметики з плаваючою крапкою, що гарантує абсолютну точність та запобігає помилкам заокруглення.

---

## 1. Алгоритмічна ідея та рекурентні співвідношення

Будь-який квадратний ірраціонал `√d` (де `d` не є повним квадратом) розкладається у нескінченний періодичний ланцюговий дріб вигляду:

```
√d = [a₀; (a₁, a₂, ..., a_k, 2a₀)]
```

де:
- `a₀ = ⌊√d⌋` — ціла частина значення `√d`;
- `a₁, a₂, ..., a_k` — коефіцієнти періоду розкладу (неповні частки);
- `k` — довжина періоду (без урахування подвоєного кінцевого елемента `2a₀`).

### Рекурентний алгоритм генерації коефіцієнтів

Пряме обчислення дробової частини `√d - a₀` у числах із плаваючою крапкою призводить до швидкої втрати молодших розрядів і накопичення похибок уже на 5–7 кроці ітерацій. Тому в обчислювальній теорії чисел застосовується цілочисельний алгоритм трьох рекурентних послідовностей `mₙ`, `dₙ` та `aₙ`:

```
m₀ = 0,   d₀ = 1,   a₀ = ⌊√d⌋
mₙ₊₁ = dₙ·aₙ - mₙ
dₙ₊₁ = (d - mₙ₊₁²) / dₙ
aₙ₊₁ = ⌊(a₀ + mₙ₊₁) / dₙ₊₁⌋
```

Усі проміжні значення `mₙ`, `dₙ` та `aₙ` є строго цілими додатними числами. Зокрема, різниця `d - mₙ₊₁²` на кожному кроці гарантовано ділиться націло на `dₙ` без остачі за алгебраїчною властивістю квадратичних ірраціональностей.

### Рекурентність підхідних дробів

Паралельно з обчисленням коефіцієнтів розкладу `aₙ` обчислюються чисельники `pₙ` та знаменники `qₙ` підхідних дробів `pₙ / qₙ` за двочленовими лінійними рекурентними формулами:

```
p₋₂ = 0,   p₋₁ = 1,   pₙ = aₙ·pₙ₋₁ + pₙ₋₂
q₋₂ = 1,   q₋₁ = 0,   qₙ = aₙ·qₙ₋₁ + qₙ₋₂
```

Ці формули еквівалентні послідовному множенню унімодулярних матриць переходу другого порядку:

```
[pₙ,  pₙ₋₁]   =   [pₙ₋₁, pₙ₋₂] · [aₙ, 1]
[qₙ,  qₙ₋₁]       [qₙ₋₁, qₙ₋₂]   [1,  0]
```

### Умова зупинки та критерій парності періоду

Алгоритм послідовно генерує підхідні дроби і перевіряє умову розв'язку рівняння Пелля:

```
pₙ² - d·qₙ² = 1
```

Згідно з фундаментальною теоремою Лагранжа про структуру ланцюгових дробів:
1. Якщо довжина періоду `k` є **парним числом**, перший же повний період приводить до розв'язку з нормою `+1`. Фундаментальний розв'язок досягається на кроці `n = k - 1`, тобто `(x₁, y₁) = (p_{k-1}, q_{k-1})`.
2. Якщо довжина періоду `k` є **непарним числом**, перший період завершується розв'язком звідного негативного рівняння: `p_{k-1}² - d·q_{k-1}² = -1`. У цьому випадку для отримання розв'язку з `+1` алгоритм автоматично продовжує генерацію підхідних дробів на другий повний період, і фундаментальний розв'язок для `+1` гарантовано досягається на кроці `n = 2k - 1`: `(x₁, y₁) = (p_{2k-1}, q_{2k-1})`.

## 2. Аналіз крайових випадків та переповнення цілочисельних типів

Під час розробки надійного промислового розв'язувача рівняння Пелля необхідно забезпечити строгу обробку крайових та аварійних ситуацій:

### 1. Перевірка на точний квадрат (Невиродженість задачі)
Якщо вхідний параметр `d` є точним квадратом (`d = k²`), рівняння набуває вигляду:

```
x² - k²·y² = (x - k·y)·(x + k·y) = 1
```

Оскільки множники `(x - k·y)` та `(x + k·y)` є цілими числами, їхній добуток може дорівнювати одиниці лише у випадку, коли обидва множники одночасно дорівнюють `1` або `-1`. Звідси `2·k·y = 0`, що дає єдиний тривіальний розв'язок `y = 0, x = 1`.

Усі нетривіальні додатні розв'язки з `y > 0` для квадратного `d` принципово відсутні. Алгоритм зобов'язаний негайно виявляти цей випадок за допомогою перевірки `⌊√d⌋² == d` на етапі ініціалізації і коректно сигналізувати про відсутність розв'язку без запуску нескінченного циклу.

### 2. Валідація некоректних вхідних параметрів
Для значень `d ≤ 1` або від'ємних чисел рівняння Пелля втрачає класичний діофантовий зміст:
- При `d = 0`: рівняння `x² = 1` має лише тривіальні розв'язки `x = ±1` при довільному `y`;
- При `d < 0`: рівняння `x² + |d|·y² = 1` має скінченну кількість розв'язків (лише `x = ±1, y = 0`).

Тому функція розв'язання повинна містити вхідну валідацію `d >= 2`.

### 3. Експоненціальний ріст чисельників та переповнення 64-бітних регістрів
Значення розв'язків `x` та `y` зростають як геометрична прогресія `(√d + ⌊√d⌋)ⁿ`. Навіть для відносно невеликих значень `d` довжина періоду `k` може досягати сотень кроків, а розв'язок виходить за межі стандартних 64-бітних цілих типів процесора (`uint64_t` / `unsigned long long`, максимум `2⁶⁴ - 1 ≈ 1.84 · 10¹⁹`):

- Для `d = 13`: `x = 649, y = 180` (вміщується у 16 біт, 3 цифри);
- Для `d = 61`: `x = 1766319049, y = 226153980` (вміщується у 32 біти, 10 цифр);
- Для `d = 67`: `x = 48842, y = 5967` (вміщується у 16 біт, 5 цифр);
- Для `d = 109`: `x = 158070671986249, y = 15140424455100` (вміщується у 64 біти, 15 цифр);
- Для `d = 991`: `x = 379516400906811930638014896080` (містить 30 десяткових знаків і фатально переповнює 64 біти);
- Для `d = 4729494` (задача Архімеда): `x` містить понад 206 545 десяткових знаків.

Для запобігання невизначеної поведінки (`Undefined Behavior`) або зациклення через переповнення беззнакових типів розв'язувач повинен виконувати попередню перевірку арифметичного переповнення перед кожною операцією множення та додавання:

```text
// Перевірка множення a * b
if (b > 0 && a > UINT64_MAX / b) {
    // виявлено переповнення!
}

// Перевірка додавання a + b
if (UINT64_MAX - a < b) {
    // виявлено переповнення!
}
```

## 3. Детальні покрокові трасування алгоритму

### Трасування для d = 13 (Непарний період k = 5, n = 9)

Розглянемо випадок `d = 13` (`√13 ≈ 3.60555`, `a₀ = ⌊√13⌋ = 3`):

1. **Ініціалізація**:
   `m₀ = 0, d₀ = 1, a₀ = 3`.
   `p₋₁ = 1, p₀ = 3`, `q₋₁ = 0, q₀ = 1`.
   Перевірка: `3² - 13·1² = 9 - 13 = -4 ≠ 1`.

2. **Крок 1**:
   `m₁ = 1·3 - 0 = 3`
   `d₁ = (13 - 3²) / 1 = 4`
   `a₁ = ⌊(3 + 3) / 4⌋ = 1`
   `p₁ = 1·3 + 1 = 4`, `q₁ = 1·1 + 0 = 1`
   Перевірка: `4² - 13·1² = 16 - 13 = 3 ≠ 1`.

3. **Крок 2**:
   `m₂ = 4·1 - 3 = 1`
   `d₂ = (13 - 1²) / 4 = 3`
   `a₂ = ⌊(3 + 1) / 3⌋ = 1`
   `p₂ = 1·4 + 3 = 7`, `q₂ = 1·1 + 1 = 2`
   Перевірка: `7² - 13·2² = 49 - 52 = -3 ≠ 1`.

4. **Крок 3**:
   `m₃ = 3·1 - 1 = 2`
   `d₃ = (13 - 2²) / 3 = 3`
   `a₃ = ⌊(3 + 2) / 3⌋ = 1`
   `p₃ = 1·7 + 4 = 11`, `q₃ = 1·2 + 1 = 3`
   Перевірка: `11² - 13·3² = 121 - 117 = 4 ≠ 1`.

5. **Крок 4**:
   `m₄ = 3·1 - 2 = 1`
   `d₄ = (13 - 1²) / 3 = 4`
   `a₄ = ⌊(3 + 1) / 4⌋ = 1`
   `p₄ = 1·11 + 7 = 18`, `q₄ = 1·3 + 2 = 5`
   Перевірка: `18² - 13·5² = 324 - 325 = -1` (досягнуто розв'язок негативного рівняння наприкінці періоду `k = 5`!).

6. **Крок 5 (Початок другого періоду)**:
   `m₅ = 4·1 - 1 = 3`
   `d₅ = (13 - 3²) / 4 = 1`
   `a₅ = ⌊(3 + 3) / 1⌋ = 6`
   `p₅ = 6·18 + 11 = 119`, `q₅ = 6·5 + 3 = 33`
   Перевірка: `119² - 13·33² = 14161 - 14157 = 4 ≠ 1`.

7. **Кроки 6–8**:
   Послідовно обчислюються підхідні дроби:
   - `p₆/q₆ = 137/38` (`137² - 13·38² = -3`)
   - `p₇/q₇ = 256/71` (`256² - 13·71² = 3`)
   - `p₈/q₈ = 393/109` (`393² - 13·109² = -4`)

8. **Крок 9 (Кінець подвоєного періоду n = 2k - 1 = 9)**:
   `m₉ = 3·1 - 2 = 1`, `d₉ = 4`, `a₉ = 1`.
   `p₉ = 1·393 + 256 = 649`
   `q₉ = 1·109 + 71 = 180`
   Перевірка розв'язку:
   `649² - 13·180² = 421201 - 13·32400 = 421201 - 421200 = 1`!

Фундаментальний розв'язок успішно знайдено: **`x = 649, y = 180`**.

### Трасування для d = 61 (Виклик Ферма)

Для `d = 61` (`√61 ≈ 7.8102`, `a₀ = 7`):
Розклад у ланцюговий дріб має період `k = 11`:

```
√61 = [7; (1, 4, 3, 1, 2, 2, 1, 3, 4, 1, 14)]
```

Оскільки довжина періоду `k = 11` є непарною, алгоритм виконує 22 ітерації:
- На кроці `n = 10` підхідний дріб `p₁₀ / q₁₀ = 29718 / 3805` дає `29718² - 61·3805² = -1`.
- На кроці `n = 21` підхідний дріб `p₂₁ / q₂₁ = 1766319049 / 226153980` дає точний розв'язок:

```
1766319049² - 61·226153980² = 1
```

Усі проміжні значення бездоганно вміщуються у стандартний 64-бітний діапазон.

## 4. Архітектура програмних реалізацій мовами C та C++

У проекті реалізовано дві повністю сумісні та ідіоматичні версії алгоритму:

### Особливості реалізації мовою C
1. **Структура повернення `PellSolutionC`**: містить результуючі координати `x`, `y` та два логічні прапорці: `found` (чи знайдено розв'язок) та `overflow` (чи сталося арифметичне переповнення 64-бітного діапазону).
2. **Чисті функції без динамічної пам'яті**: функція `solve_pell_c` виконується на стеку з нульовими накладними витратами на виділення пам'яті (`Zero Heap Allocation`), що гарантує високу швидкість та придатність для вбудованих систем.
3. **Строгий контроль переповнення**: інлайн-хелпер `check_mul_overflow_u64` перевіряє верхні межі перед виконанням апаратного множення.

### Особливості реалізації мовою C++
1. **Типобезпечний `std::optional<PellSolution>`**: замість сигнальних чисел чи вихідних параметрів за вказівником метод повертає об'єкт `std::optional`, який містить структуру розв'язку або значення `std::nullopt` у разі виявлення квадрата чи переповнення.
2. **Інкапсуляція у клас `PellSolver`**: логіка розв'язання інкапсульована у статичний метод класу без потреби створення екземплярів (патерн Utility Class).
3. **Стандартні ліміти `<limits>`**: використання констант `std::numeric_limits<std::uint64_t>::max()` замість макросів препроцесора.

## 5. Порівняльний аналіз: Неперервні дроби проти методу Чукравала

У практичному програмному інжинірингу розглядаються два алгоритмічні підходи до розв'язання рівняння Пелля:

### 1. Метод неперервних дробів (Лагранж)
- **Переваги**:
  - Лінійний кінцевий автомат з чотирма змінними стану `(m, d_val, p, q)`.
  - Відсутність потреби у модульній арифметиці чи пошуку обернених елементів.
  - Надзвичайно проста та передбачувана реалізація на будь-якій мові програмування.
- **Недоліки**:
  - Для непарних періодів `k` змушений проходити подвійне коло (`2k` ітерацій).
  - Послідовно перебирає всі підхідні дроби без можливості пропуску проміжних кроків.

### 2. Циклічний метод Чукравала (Брахмагупта, Бхаскара II)
- **Переваги**:
  - Двосторонній вибір `|m² - d| → min` перестрибує повільні проміжні підхідні дроби, зменшуючи кількість ітерацій у середньому на 30–40%.
  - Спеціальні правила зупинки Бхаскари дозволяють миттєво отримати розв'язок за один алгебраїчний крок при досягненні `k ∈ {-1, ±2, ±4}`.
- **Недоліки**:
  - Вимагає додаткових обчислень розширеного алгоритму Евкліда для знаходження `b⁻¹ mod |k|` на кожній ітерації.

## 6. Оцінка складності та розширення до довгої арифметики (BigInt)

### Часова та просторова складність
1. **Часова складність**: Кількість ітерацій ланцюгового дробу обмежена довжиною періоду `k = O(√d · log d)`. На кожному кроці виконується фіксована кількість цілочисельних операцій `O(1)`. Таким чином, загальна часова складність для 64-бітних чисел становить `O(√d · log d)`.
2. **Просторова складність**: Алгоритм вимагає `O(1)` пам'яті, оскільки у робочому циклі зберігаються лише два останні значення підхідних дробів (`p_curr`, `p_prev1`, `q_curr`, `q_prev1`).

### Стратегія розширення до довільної точності (BigInt)
Для обчислення розв'язків для довільних великих значень `d` (наприклад, `d = 991` або задачі Архімеда `d = 4729494`) 64-бітні змінні `p_curr`, `q_curr` замінюються на класи довгої арифметики:
- У C++: бібліотека `boost::multiprecision::cpp_int` або `mpz_class` з бібліотеки GNU Multiple Precision Arithmetic Library (GMP).
- У C: прямі виклики функцій `mpz_t`, `mpz_mul`, `mpz_add` з бібліотеки GMP.

Оскільки всі математичні рекурентні формули переходів та логіка циклу залишаються повністю незмінними, перехід до довгої арифметики здійснюється без заміни архітектурного ядра алгоритму.

## 7. Генерація вищих розв'язків через бінарне піднесення матриць до степеня

Після того, як алгоритм знайшов мінімальний фундаментальний розв'язок `(x₁, y₁)`, постає інженерне завдання швидкої генерації `n`-го розв'язку `(xₙ, yₙ)` для великих значень індексу `n ∈ Z_+`.

Послідовне множення фундаментальної одиниці `ε₁ = x₁ + y₁·√d` у кільці `Z[√d]` вимагає `O(n)` операцій множення. Проте в обчислювальній практиці застосовується алгоритм **бінарного матричного піднесення до степеня** за час `O(log n)`.

### Матрична форма оператора Пелля

Введемо матрицю повороту в псевдоевклідовому просторі:

```text
M = [x₁,  d·y₁]
    [y₁,  x₁  ]
```

Визначник матриці `M` точно дорівнює значенню квадратичної норми Пелля:

```text
det(M) = x₁² - d·y₁² = 1
```

Будь-який `n`-й розв'язок `(xₙ, yₙ)` виражається як результат множення вектора початкового стану `[1, 0]ᵀ` на матрицю `M` у степені `n`:

```text
[xₙ]   =   Mⁿ · [1]
[yₙ]            [0]
```

Завдяки асоціативності матричного множення матриця `Mⁿ` обчислюється за схемою швидкого піднесення до степеня (метод двійкового розкладу степеня):
1. Якщо `n` парне: `Mⁿ = (M^(n/2))²`;
2. Якщо `n` непарне: `Mⁿ = M · M^(n-1)`.

Це дозволяє генерувати мільйонний розв'язок рівняння Пелля всього за `≈ 20` кроків матричного множення з використанням довгої арифметики.

## 8. Апаратна оптимізація та робота процесорних регістрів (x86-64)

Для досягнення максимальної продуктивності обчислень розв'язувач спроектовано з урахуванням архітектури сучасних мікропроцесорів та компіляторної оптимізації.

### Розподіл змінних у регістрах ЦП (Zero Cache-Miss)
У робочому циклі розв'язання рівняння Пелля беруть участь рівно 7 цілочисельних 64-бітних змінних:
- Поточні параметри ланцюгового дробу: `m`, `d_val`, `a`;
- Чисельники підхідних дробів: `p_prev1`, `p_curr`;
- Знаменники підхідних дробів: `q_prev1`, `q_curr`.

На 64-бітній архітектурі x86-64 (System V ABI або Microsoft x64 ABI) компілятори GCC, Clang та MSVC автоматично розміщують усі 7 змінних у регістрах загального призначення процесора: `RAX`, `RBX`, `RCX`, `RDX`, `RSI`, `RDI`, `R8`–`R11`.

Завдяки цьому під час виконання циклу:
1. Повністю відсутні звернення до оперативної пам'яті (RAM) та кеш-пам'яті першого рівня (L1 Cache);
2. Робочий цикл виконується виключно в надшвидких апаратних регістрах із нульовими затримками доступу (`0 latency cycles`);
3. Конвеєр процесора досягає максимальної швидкості диспетчеризації інструкцій (`Instructions Per Cycle` близький до теоретичного піку архітектури).

### Апаратний контроль прапорця переповнення (OF)
У коді на C функція `check_mul_overflow_u64` перевіряє умову `a > UINT64_MAX / b`. Сучасні оптимізуючі компілятори замінюють цей подвійний код на одну апаратну процесорну інструкцію множення `mulq` або `mulx` (набір інструкцій BMI2) з наступною перевіркою прапорця переповнення процесора `OF` (`Overflow Flag`) або `CF` (`Carry Flag`) за допомогою інструкції умовного переходу `jo` / `jc`. Це зводить накладні витрати на перевірку безпеки практично до нуля.

## 9. Емпіричний розподіл довжин періодів та поведінка для d ∈ [2, 1000]

Розподіл довжини періоду розкладу `k(d)` та величини фундаментального розв'язку має виражений нелінійний, хаотичний характер:

1. **Короткі періоди (k = 1, 2)**:
   - Якщо `d = a₀² + 1`, розклад має вигляд `√d = [a₀; (2a₀)]` з довжиною періоду `k = 1`. Розв'язок негативного рівняння: `x = a₀, y = 1`.
   - Якщо `d = a₀² + 2`, розклад має вигляд `√d = [a₀; (a₀, 2a₀)]` з парним періодом `k = 2`. Розв'язок: `x = a₀² + 1, y = a₀`.

2. **Аномально довгі періоди та гігантські розв'язки**:
   - Для `d = 991`: довжина періоду досягає `k = 60`, а фундаментальний розв'язок містить 30 десяткових цифр (`x ≈ 3.79 · 10²⁹`).
   - Для `d = 1000`: `√1000 = [31; (1, 1, 1, 1, 62)]` з періодом `k = 6`, де розв'язок становить `x = 394901227, y = 12487827`.

Така поведінка підтверджує аналітичну оцінку Шанкса: середнє значення довжини періоду зростає як `O(√d · ln d)`, проте локальні флуктуації залежать від розкладу числа `d` на прості множники та структури групи класів ідеалів квадратичного поля `Q(√d)`.

## 10. Модульне тестування та верифікація діофантових інваріантів

Для промислової верифікації розв'язувача розробляється трирівнева система автоматизованих тестів:

### 1. Тести коректності розв'язку (Критерій рівності одиниці)
Для кожної знайденої пари `(x, y)` виконується пряма підстановка у квадратичну форму:

```text
x² - d·y² == 1
```

У разі використання 64-бітних типів тестуюча процедура виконує перевірку за допомогою безпечного типу `unsigned __int128` або довгої арифметики, що повністю виключає хибнопозитивні результати через переповнення під час самої перевірки.

### 2. Тести мінімальності (Фундаментальність розв'язку)
Тестовий стенд підтверджує, що знайдена пара `(x, y)` є справді **найменшим** додатним розв'язком. Для цього перевіряється, що для всіх цілих значень `y' ∈ [1, y - 1]` величина `1 + d·(y')²` не є точним квадратом цілого числа.

### 3. Набір крайових та стрес-тестів
- **Тест на точні квадрати**: для `d ∈ {4, 9, 16, 25, 36, 49, 64, 81, 100, 144, 225, 10000}` алгоритм повинен негайно повернути `found = false` (`std::nullopt`) за час `O(1)`;
- **Класичні історичні контрольні точки**:
  - `d = 2`: `(x, y) = (3, 2)`
  - `d = 3`: `(x, y) = (2, 1)`
  - `d = 5`: `(x, y) = (9, 4)`
  - `d = 13`: `(x, y) = (649, 180)`
  - `d = 61`: `(x, y) = (1766319049, 226153980)`
  - `d = 67`: `(x, y) = (48842, 5967)`
  - `d = 109`: `(x, y) = (158070671986249, 15140424455100)`
- **Тест на коректне виявлення 64-бітного переповнення**: для `d = 991` алгоритм повинен встановити прапорець `overflow = true` (`std::nullopt`) без аварійного завершення процесу.
