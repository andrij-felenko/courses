# ⚙️ Інженерна реалізація точкової арифметики на еліптичних кривих над скінченними полями

Практична інженерна реалізація базових операцій точкової арифметики на еліптичній кривій у формі Вейєрштрасса `y² ≡ x³ + a·x + b (mod p)` над скінченним простим полем `𝔽ₚ` мовами C, C++ та Python. 

Стаття розглядає представлення точок в афінних та проективних координатах Якобі, багаторозрядну модульну арифметику, редукцію Монтгомері, алгоритми скалярного множення (Double-and-Add, віконні методи, wNAF, драбину Монтгомері у сталий час та алгоритм GLV), розширені координати Едвардса, алгоритм Тонеллі–Шенкса для стиснення точок, методи захисту від атак по побічних каналах (SPA, DPA, таймінг-атаки, атаки на кеш), перевірки валідності вхідних даних, тестування за стандартами Wycheproof, інженерний чекліст аудиту безпеки та протокол обміну ключами Діффі–Геллмана на еліптичних кривих (ECDH).

## 1. Архітектурні виклики програмної реалізації точкової арифметики

На відміну від чистої алгебраїчної теорії, де операції розглядаються над абстрактними нескінченними полями, комп'ютерна реалізація криптографії на еліптичних кривих стикається з комплексом жорстких інженерних вимог:

1. **Математична коректність та детермінована обробка виняткових станів:**
   Операції додавання та подвоєння повинні детерміновано та коректно обробляти нейтральний елемент `O` (точку на нескінченності), взаємно протилежні точки `P + (-P) = O`, а також випадок точок з нульовою ординатою `y = 0`, де дотична лінія є вертикальною і подвоєння дає `2·P = O`. Програмна логіка не має права допускати аварійного завершення (паніки або ділення на нуль) при отриманні будь-яких валідних або невалідних точок.

2. **Обчислювальна продуктивність та мінімізація інверсій:**
   В афінних координатах кожна операція додавання чи подвоєння точок вимагає знаходження оберненого елемента за модулем `p` (обчислення `(x₂ - x₁)⁻¹ mod p` або `(2·y₁)⁻¹ mod p`). Обчислення модульної інверсії за допомогою Розширеного алгоритму Евкліда або Малої теореми Ферма (`a⁻¹ ≡ aᵖ⁻² mod p`) вимагає `O(log² p)` операцій, що у 30–80 разів перевищує час одного множення у полі. При 256-бітному скалярі наївна афінна арифметика стає головним пляшковим горлом. Для усунення цієї проблеми точки переводять у проективні координати Якобі `(X : Y : Z)`, де ділення замінюються кількома множеннями та піднесеннями до квадрата, а єдина модульна інверсія виконується лише один раз наприкінці обчислень.

3. **Захист від атак по побічних каналах (Side-Channel Attacks):**
   Час виконання криптографічних підпрограм, профілі споживання електричної енергії процесором та сліди звернень до кеш-пам'яті першого рівня не повинні залежати від бітів секретного ключа `k`. Умовні переходи `if/else`, що виконуються залежно від значень бітів секретного скаляра, створюють фатальні вразливості до атак за часом (Timing Attacks) та простого аналізу енергоспоживання (Simple Power Analysis, SPA). Для захисту застосовують алгоритми зі сталим часом виконання (Constant-Time Execution), такі як драбина Монтгомері та побітовий умовний обмін точок (CSWAP).

```
        Афінні координати (x, y)          Проективні координати Якобі (X : Y : Z)
        ------------------------          ----------------------------------------
        1 інверсія + 2–3 множення         12–16 множень + піднесень до квадрата
        Складність: O(log² p) на крок     Складність: O(log p) на крок
        (Повільно через часті інверсії)   (Швидко, інверсія лише 1 раз у фіналі)
```

## 2. Модульна арифметика над скінченними простими полями 𝔽ₚ

Усі алгебраїчні операції над координатами точок виконуються у скінченному полі залишків `𝔽ₚ = ℤ / pℤ`, де `p` — непарне просте число.

```
+---------------------------------------------------------------------------------------+
| Операція над елементами 𝔽ₚ    | Позначення | Алгоритм реалізації         | Відносна ціна |
+-------------------------------+------------+-----------------------------+---------------+
| Додавання (a + b) mod p       | A          | Додавання з корекцією -p    | 1 (базова)    |
| Віднімання (a - b) mod p      | S_sub      | Віднімання з корекцією +p   | 1             |
| Множення (a · b) mod p        | M          | Добуток __int128 + редукція | 3 – 5         |
| Квадрат a² mod p              | S          | Оптимізований квадрат       | 2.5 – 4       |
| Піднесення до степеня aᵉ mod p| Exp        | Square-and-Multiply         | ≈ 1.5 log(e) M|
| Обернення a⁻¹ mod p           | I          | Розширений алгоритм Евкліда | 60 – 120 M    |
+---------------------------------------------------------------------------------------+
```

### 1. Представлення великих чисел у багаторозрядній арифметиці (Multi-precision Limbs)
У промислових криптографічних бібліотеках (таких як libsecp256k1, OpenSSL, BoringSSL) 256-бітне ціле число не вміщується в один регістр процесора і представляється масивом машинних слів (кінцівок або лімбів):
- на 64-бітних архітектурах (x86_64, ARM64): 4 лімби по 64 біти (`uint64_t limbs[4]`);
- на 32-бітних архітектурах (ARM Cortex-M, x86): 8 лімбів по 32 біти (`uint32_t limbs[8]`).

При додаванні двох багаторозрядних чисел обчислення виконується покроково від молодшого лімба до старшого з переносом біта переповнення (Carry):
```
carry = 0
for i from 0 to 3:
    sum = A[i] + B[i] + carry
    carry = (sum < A[i]) or (carry == 1 and sum == A[i])
    R[i] = sum
```

### 2. Модульне додавання та віднімання без розгалужень
У мовах низького рівня (C, ASM) додавання та віднімання реалізуються з урахуванням захисту від цілочисельного переповнення та без умовних переходів:
```
// Модульне додавання: результат у діапазоні [0, p-1]
int64_t r = a + b;
int64_t mask = -((r >= p) ? 1 : 0);
r -= (p & mask);

// Модульне віднімання
int64_t r = a - b;
int64_t mask = -((r < 0) ? 1 : 0);
r += (p & mask);
```

### 3. Модульне множення та редукція Монтгомері (Montgomery Reduction)
При звичайному множенні двох чисел за модулем `p` спочатку обчислюється повний добуток `T = a · b` подвійної розрядності (512 біт для 256-бітних чисел), після чого виконується повільне ділення на `p` для знаходження залишку `T mod p`.

Для прискорення множення Пітер Монтгомері (1985) запропонував перехід у **простір Монтгомері**:
- Обирається число `R = 2²⁵⁶ > p`, взаємно просте з `p`.
- Число `x` відображається у форму Монтгомері: `x̃ = (x · R) mod p`.
- Додавання у формі Монтгомері зберігається: `x̃ + ỹ = (x + y) · R mod p`.
- Множення у формі Монтгомері обчислюється за допомогою швидкого алгоритму **REDC**:
```
REDC(x̃ · ỹ) = (x̃ · ỹ · R⁻¹) mod p = (x · R · y · R · R⁻¹) mod p = (x · y · R) mod p
```
Алгоритм REDC замінює важке ділення на `p` звичайними побітовими зсувами праворуч на розрядність `R`, що робить серійні множення у 2–3 рази швидшими.

### 4. Спеціальні прості числа (Псевдо-Мерсенна та числа Солінаса)
Криптографічні стандарти використовують прості числа спеціальної форми, для яких ділення замінюється кількома операціями додавання та віднімання:
- **Крива Curve25519 (`p = 2²⁵⁵ - 19`):** Оскільки `2²⁵⁵ ≡ 19 (mod p)`, будь-який старший переповнений розряд `x_high · 2²⁵⁵` миттєво зводиться множенням на невелику константу `19`: `x_low + 19 · x_high mod p`.
- **Крива NIST P-256 (`p₂₅₆ = 2²⁵⁶ - 2²²⁴ + 2¹⁹² + 2⁹⁶ - 1`):** Редукція 512-бітного добутку виконується за алгоритмом Джерома Солінаса шляхом додавання і віднімання 8 фіксованих 32-бітних слів без жодного множення.

### 5. Знаходження оберненого елемента (Розширений алгоритм Евкліда)
Для ненульового елемента `b ∈ 𝔽ₚ*` розширений алгоритм Евкліда знаходить пару цілих чисел `x, y`, які задовольняють тотожність Безу:
```
b · x + p · y = gcd(b, p) = 1
```
Взявши це рівняння за модулем `p`, маємо `b · x ≡ 1 (mod p)`, тобто `x mod p = b⁻¹ mod p`.

Алгоритм підтримує дві пари змінних:
- пару залишків `(r₀, r₁)`, що ініціалізується як `(p, b)`;
- пару коефіцієнтів `(t₀, t₁)`, що ініціалізується як `(0, 1)`.

На кожному кроці циклу обчислюється неповна частка `q = r₀ / r₁`, після чого вектори оновлюються:
```
(r₀, r₁) ← (r₁, r₀ - q · r₁)
(t₀, t₁) ← (t₁, t₀ - q · t₁)
```
Цикл завершується, коли `r₁ = 0`. Тоді значення `r₀` дорівнює `gcd(b, p)`. Якщо `r₀ = 1`, то обернений елемент дорівнює `t₀ mod p`. Якщо `r₀ > 1`, елемент `b` ділить `p`, тому оберненого елемента не існує.

## 3. Афінна точкова арифметика: формули, обґрунтування та крайові випадки

Нехай еліптична крива задана коротким рівнянням Вейєрштрасса:
```
E: y² ≡ x³ + a·x + b (mod p)
```
де дискримінант `Δ = -16 · (4·a³ + 27·b²) ≢ 0 (mod p)`.

### 1. Подвоєння точки `R = 2·P`, де `P = (x₁, y₁)`
Якщо `P = O` або `y₁ ≡ 0 (mod p)`, дотична пряма до кривої є вертикальною і перетинає криву у нескінченно віддаленій точці `O`. У цьому випадку `2·P = O`.

Якщо `y₁ ≢ 0 (mod p)`, нахил дотичної прямої `λ` знаходиться через неявне диференціювання рівняння кривої `2·y · dy = (3·x² + a) · dx`:
```
λ = (3·x₁² + a) · (2·y₁)⁻¹ mod p
```
Підставляючи пряму `y = λ·(x - x₁) + y₁` у рівняння кривої та застосовуючи теорему Вієта для коренів кубічного многочлена (з урахуванням кратності 2 точки дотику `x₁`):
```
x₁ + x₁ + x₃ = λ²  ⇒  x₃ = λ² - 2·x₁ mod p
y₃ = λ·(x₁ - x₃) - y₁ mod p
```

### 2. Додавання нерівних точок `R = P + Q`, де `P = (x₁, y₁)` та `Q = (x₂, y₂)`
- **Випадок 1 (`P = O`):** `O + Q = Q`.
- **Випадок 2 (`Q = O`):** `P + O = P`.
- **Випадок 3 (`x₁ = x₂` та `y₁ ≡ -y₂ mod p`):** Точки лежать на одній вертикальній прямій і є взаємно протилежними: `P + (-P) = O`.
- **Випадок 4 (`x₁ = x₂` та `y₁ = y₂`):** Точки збігаються, виконується алгоритм подвоєння `2·P`.
- **Випадок 5 (`x₁ ≠ x₂`):** Пряма є січною з нахилом:
```
λ = (y₂ - y₁) · (x₂ - x₁)⁻¹ mod p
```
За теоремою Вієта сума трьох коренів дорівнює `λ²`:
```
x₁ + x₂ + x₃ = λ²  ⇒  x₃ = λ² - x₁ - x₂ mod p
y₃ = λ·(x₁ - x₃) - y₁ mod p
```

## 4. Детальний числовий розбір та верифікація для P=(3,6) над 𝔽₉₇

Для практичної верифікації реалізації розглянемо еліптичну криву над полем `𝔽₉₇` (`p = 97`):
```
y² ≡ x³ + 2·x + 3 (mod 97)
```
Параметри кривої: `a = 2`, `b = 3`, `p = 97`. Візьмемо точку `P = (3, 6)`.

### Перевірка належності точки P кривій:
```
Ліва частина:  y² = 6² = 36 mod 97
Права частина: x³ + 2x + 3 = 3³ + 2·3 + 3 = 27 + 6 + 3 = 36 mod 97
```
Рівність виконується, точка `P = (3, 6)` належить кривій.

### Крок 1: Подвоєння точки `2·P = (x₂, y₂)`
Обчислюємо нахил дотичної `λ`:
```
λ = (3 · 3² + 2) · (2 · 6)⁻¹ mod 97
  = (27 + 2) · 12⁻¹ mod 97
  = 29 · 12⁻¹ mod 97
```
Знайдемо `12⁻¹ mod 97` за алгоритмом Евкліда: `12 · 89 = 1068 = 11 · 97 + 1 ≡ 1 mod 97`, отже `12⁻¹ ≡ 89 mod 97`.
```
λ = 29 · 89 mod 97 = 2581 mod 97 = 59
```
Обчислюємо координати точки `2·P`:
```
x₂ = 59² - 2 · 3 mod 97
   = 3481 - 6 mod 97 = 3475 mod 97 = 80

y₂ = 59 · (3 - 80) - 6 mod 97
   = 59 · (-77) - 6 mod 97
   = -4543 - 6 mod 97 = -4549 mod 97 = 10   [-4549 + 47·97 = 10]
```
Отримано: **`2·P = (80, 10)`**.

Перевіримо належність `(80, 10)` кривій: `10² = 100 ≡ 3 mod 97`, а `80³ + 2·80 + 3 = 512000 + 160 + 3 = 512163 = 5280 · 97 + 3 ≡ 3 mod 97`. [OK]

### Крок 2: Додавання `3·P = 2·P + P`
Додаємо точку `2·P = (80, 10)` та точку `P = (3, 6)`:
```
λ = (10 - 6) · (80 - 3)⁻¹ mod 97
  = 4 · 77⁻¹ mod 97
```
Оскільки `77 ≡ -20 mod 97`, знайдемо `-20⁻¹ mod 97`: `20 · 34 = 680 = 7 · 97 + 1 ≡ 1 mod 97`, отже `77⁻¹ ≡ -34 ≡ 63 mod 97`.
```
λ = 4 · 63 mod 97 = 252 mod 97 = 58
```
Обчислюємо координати точки `3·P`:
```
x₃ = 58² - 80 - 3 mod 97
   = 3364 - 83 mod 97 = 3281 mod 97 = 80   [3281 = 33·97 + 80]

y₃ = 58 · (80 - 80) - 10 mod 97
   = 58 · 0 - 10 mod 97 = -10 mod 97 = 87
```
Отримано: **`3·P = (80, 87)`**.

Зверніть увагу: `y₃ = 87 = 97 - 10 = -y₂`. Тобто точка `3·P = (80, 87)` є протилежною до точки `2·P = (80, 10)`, тобто **`3·P = - (2·P)`**. Звідси випливає фундаментальна тотожність: `3·P + 2·P = 5·P = O`.

### Крок 3: Подвоєння `4·P = 2·(2·P)`
Подвоїмо точку `2·P = (80, 10)`:
```
λ = (3 · 80² + 2) · (2 · 10)⁻¹ mod 97
  = (3 · 6400 + 2) · 20⁻¹ mod 97
  = (19202) · 20⁻¹ mod 97
  = 93 · 34 mod 97 = 3162 mod 97 = 58   [19202 = 197·97 + 93; 3162 = 32·97 + 58]

x₄ = 58² - 2 · 80 mod 97
   = 3364 - 160 mod 97 = 3204 mod 97 = 3   [3204 = 33·97 + 3]

y₄ = 58 · (80 - 3) - 10 mod 97
   = 58 · 77 - 10 mod 97
   = 4466 - 10 mod 97 = 4456 mod 97 = 91   [4456 = 45·97 + 91]
```
Отримано: **`4·P = (3, 91)`**.

Зауважимо: `y₄ = 91 = 97 - 6 = -y_P`, отже **`4·P = -P`**.

### Крок 4: Додавання `5·P = 4·P + P`
Додаємо точку `4·P = (3, 91)` та `P = (3, 6)`:
Оскільки `x₁ = x₂ = 3`, а сума ординат `y₁ + y₂ = 91 + 6 = 97 ≡ 0 (mod 97)`, пряма через ці точки є вертикальною. За правилом колінеарності результатом є **нейтральний елемент групи `O`**:
```
5·P = O
```

Ці розрахунки строго доводять, що базова точка `P = (3, 6)` породжує **циклічну підгрупу порядку `n = 5`**:
```
⟨P⟩ = { 1·P = (3, 6),  2·P = (80, 10),  3·P = (80, 87),  4·P = (3, 91),  5·P = O }
```

## 5. Алгоритми скалярного множення: Double-and-Add, віконні методи та wNAF

Операція скалярного множення `R = k · P` (додавання точки `P` до себе `k` разів) є фундаментальною операцією у протоколах ECDH, ECDSA та EdDSA.

### 1. Двійковий алгоритм Double-and-Add
Алгоритм сканує двійкові розряди скаляра `k`:

```
result = O
addend = P
while k > 0:
    if k & 1:
        result = point_add(result, addend)
    addend = point_double(addend)
    k >>= 1
return result
```

Розглянемо покрокове виконання алгоритму для скаляра `k = 5` (двійкове представлення `101₂`) та базової точки `P = (3, 6)` над `𝔽₉₇`:

- **Ініціалізація:**
  `result = O` (точка на нескінченності), `addend = P = (3, 6)`, `k = 5` (`101₂`).

- **Ітерація 1 (молодший біт b₀ = 1):**
  - Біт `k & 1 == 1` ⇒ виконуємо додавання: `result = result + addend = O + (3, 6) = (3, 6)`.
  - Подвоюємо доданок для наступного розряду: `addend = 2·P = (80, 10)`.
  - Зсуваємо скаляр праворуч: `k = 5 >> 1 = 2` (`10₂`).

- **Ітерація 2 (середній біт b₁ = 0):**
  - Біт `k & 1 == 0` ⇒ операція додавання пропускається, `result` залишається рівним `(3, 6)`.
  - Подвоюємо доданок для наступного розряду: `addend = 2·(2·P) = 4·P = (3, 91)`.
  - Зсуваємо скаляр праворуч: `k = 2 >> 1 = 1` (`1₂`).

- **Ітерація 3 (старший біт b₂ = 1):**
  - Біт `k & 1 == 1` ⇒ виконуємо додавання: `result = result + addend = (3, 6) + (3, 91)`.
  - Оскільки точки `(3, 6)` та `(3, 91)` взаємно протилежні, їхня сума дає `result = O`.
  - Подвоюємо доданок: `addend = 2·(4·P) = 8·P = 3·P = (80, 87)`.
  - Зсуваємо скаляр праворуч: `k = 1 >> 1 = 0`.

- **Завершення роботи:**
  Скаляр `k = 0`, цикл завершується. Алгоритм повертає результат **`5·P = O`**.

### Трасування алгоритму для інших значень скаляра `k`:
- **`k = 1` (`1₂`):** Виконується 1 додавання: `result = O + P = (3, 6)`.
- **`k = 2` (`10₂`):** Крок 1 (`b₀ = 0`): `result = O`, `addend = 2·P = (80, 10)`. Крок 2 (`b₁ = 1`): `result = O + (80, 10) = (80, 10)`.
- **`k = 3` (`11₂`):** Крок 1 (`b₀ = 1`): `result = P = (3, 6)`, `addend = 2·P = (80, 10)`. Крок 2 (`b₁ = 1`): `result = (3, 6) + (80, 10) = 3·P = (80, 87)`.
- **`k = 4` (`100₂`):** Крок 1 (`b₀ = 0`): `result = O`, `addend = 2·P = (80, 10)`. Крок 2 (`b₁ = 0`): `result = O`, `addend = 4·P = (3, 91)`. Крок 3 (`b₂ = 1`): `result = O + (3, 91) = 4·P = (3, 91)`.

### 2. Метод вікон фіксованого розміру (Fixed-Window Method)
Для прискорення обчислень скаляр `k` розбивається на блоки (вікна) шириною `w` бітів. Перед початком множення будується невелика таблиця передобчислених кратних точок:
```
T = { 1·P, 2·P, 3·P, ..., (2ʷ - 1)·P }
```
На кожному кроці поточний результат `w` разів подвоюється, після чого виконується лише одне додавання відповідного елемента з таблиці: `result = 2ʷ · result + T[d_i]`. Це скорочує кількість операцій додавання у `w` разів за рахунок невеликих витрат пам'яті.

### 3. Несуміжні форми представлення (Non-Adjacent Form, wNAF)
Оскільки віднімання точки на еліптичній кривій `P - Q = P + (-Q)` обчислюється з тією самою швидкістю, що й додавання (достатньо змінити знак ординати `y_Q ↦ p - y_Q`), скаляр `k` можна представити у знаковій двійковій системі з цифрами `{0, ±1, ±3, ..., ±(2ʷ⁻¹ - 1)}`.

Несуміжна форма **wNAF (Width-w Non-Adjacent Form)** гарантує, що серед будь-яких `w` послідовних цифр є щонайбільше одна ненульова. Це знижує середню щільність ненульових коефіцієнтів до `1 / (w + 1)`, що скорочує кількість операцій точкового додавання на 33–50% порівняно зі звичайним двійковим розкладом.

## 6. Проективні координати Якобі: оптимізація швидкодії

Для усунення повільної операції знаходження оберненого елемента на кожному кроці скалярного множення точки переводять у **проективні координати Якобі** `(X : Y : Z)`.

### Зв'язок між афінними та якобієвими координатами:
```
x = X / Z²
y = Y / Z³
```
Точка на нескінченності `O` представляється трійкою `(1 : 1 : 0)` або будь-якою точкою з `Z = 0`.

Підставляючи ці вирази у коротке рівняння Вейєрштрасса `y² = x³ + a·x + b` та домножуючи на `Z⁶`, отримуємо однорідне рівняння:
```
Y² = X³ + a·X·Z⁴ + b·Z⁶ (mod p)
```

```
+---------------------------------------------------------------------------------------+
| Система координат    | Представлення точки  | Подвоєння (2·P)   | Додавання (P + Q)   |
+----------------------+----------------------+-------------------+---------------------+
| Афінна               | (x, y)               | 1 I + 2 M + 2 S   | 1 I + 2 M + 1 S     |
| Однорідна проективна | (X : Y : Z), x=X/Z   | 7 M + 5 S         | 12 M + 2 S          |
| Якобі                | (X : Y : Z), x=X/Z²  | 4 M + 6 S (3M+5S) | 12 M + 4 S          |
| Модифікована Якобі   | (X : Y : Z : a·Z⁴)   | 4 M + 4 S         | 13 M + 5 S          |
| Чудновського Якобі   | (X : Y : Z : Z² : Z³)| 5 M + 4 S         | 11 M + 3 S (змішане)|
+---------------------------------------------------------------------------------------+
```

### 1. Формули подвоєння у координатах Якобі (Jacobian Doubling):
Нехай задано точку `P = (X₁, Y₁, Z₁)`. Обчислимо `2·P = (X₃, Y₃, Z₃)`:
1. `S = 4 · X₁ · Y₁² mod p`
2. `M = 3 · X₁² + a · Z₁⁴ mod p`  *(якщо `a = -3 mod p`, то `M = 3 · (X₁ - Z₁²) · (X₁ + Z₁²)`, що скорочує 2 множення)*
3. `X₃ = M² - 2·S mod p`
4. `Y₃ = M · (S - X₃) - 8 · Y₁⁴ mod p`
5. `Z₃ = 2 · Y₁ · Z₁ mod p`

### 2. Формули додавання у координатах Якобі (Jacobian Addition):
Нехай задано дві точки `P = (X₁, Y₁, Z₁)` та `Q = (X₂, Y₂, Z₂)`. Обчислимо `P + Q = (X₃, Y₃, Z₃)`:
1. `U₁ = X₁ · Z₂² mod p`,  `U₂ = X₂ · Z₁² mod p`
2. `S₁ = Y₁ · Z₂³ mod p`,  `S₂ = Y₂ · Z₁³ mod p`
3. Якщо `U₁ == U₂`:
   - якщо `S₁ == S₂`, точки збігаються ⇒ викликаємо `jacobian_double(P)`.
   - якщо `S₁ != S₂`, точки протилежні ⇒ повертаємо `JacobianPoint::infinity()`.
4. `H = U₂ - U₁ mod p`
5. `r = S₂ - S₁ mod p`
6. `H² = H · H mod p`,  `H³ = H · H² mod p`
7. `X₃ = r² - H³ - 2 · U₁ · H² mod p`
8. `Y₃ = r · (U₁ · H² - X₃) - S₁ · H³ mod p`
9. `Z₃ = H · Z₁ · Z₂ mod p`

### 3. Зведення координат Якобі до афінного вигляду:
Виконується лише один раз після завершення всього циклу скалярного множення:
```
z_inv = mod_inverse(Z, p)
z_inv2 = z_inv · z_inv mod p
z_inv3 = z_inv2 · z_inv mod p
x = X · z_inv2 mod p
y = Y · z_inv3 mod p
```

## 7. Захист від атак по побічних каналах: Драбина Монтгомері, рандомізація та CSWAP

При наївній реалізації алгоритму Double-and-Add час виконання та профіль споживання електричної енергії процесором прямо залежать від значення поточного біта скаляра `k_i`:
- якщо `k_i = 0`: виконується лише подвоєння (`double`);
- якщо `k_i = 1`: виконується і подвоєння, і додавання (`double + add`).

Зловмисник, вимірюючи електромагнітне випромінювання або час обробки пакетів, може повністю відновити значення приватного ключа `k`.

### 1. Драбина Монтгомері (Montgomery Ladder):
Драбина Монтгомері усуває розгалуження, підтримуючи пару змінних точок `R₀` та `R₁`, для яких на кожному кроці виконується інваріант: `R₁ - R₀ = P`.

```
R0 = O
R1 = P
for i from (bit_length - 1) down to 0:
    bit = (k >> i) & 1
    CSWAP(bit, R0, R1)
    R1 = point_add(R0, R1)
    R0 = point_double(R0)
    CSWAP(bit, R0, R1)
return R0
```

На кожному кроці циклу **завжди виконується рівно одне додавання та рівно одне подвоєння**, незалежно від значення біта `k_i`. Це забезпечує абсолютний захист від атак за часом (Timing Attacks) та простого аналізу потужності (SPA).

### 2. Побітовий умовний обмін точок (Constant-Time CSWAP):
Операція `CSWAP(bit, A, B)` міняє місцями значення двох точок `A` та `B`, якщо `bit = 1`, і залишає їх незмінними, якщо `bit = 0`, без використання інструкцій умовного переходу процесора:

@tab C
:::code proj-ecc-point-arithmetic/c/problema-vytoku.c

@tab C++

:::

Маска `mask = -(bit & 1)` формує або всі нульові біти (`0x0000000000000000` при `bit = 0`), або всі одиничні біти (`0xFFFFFFFFFFFFFFFF` при `bit = 1`). Операція побітового `XOR` (`^`) виконується у процесорі за сталу кількість тактів.

### 3. Рандомізація координат та скаляра (Blinding Countermeasures)
Для протидії складним статистичним атакам диференціального аналізу потужності (DPA) застосовують рандомізацію:
- **Рандомізація проективних координат (Projective Randomization):** Перед початком обчислень точка `(X : Y : Z)` рандомізується множенням на випадкове ненульове число `c ∈ 𝔽ₚ*`:
  ```
  (X : Y : Z) ↦ (c² · X : c³ · Y : c · Z) mod p
  ```
  Це змінює всі проміжні значення у регістрах процесора при кожному новому запуску, зберігаючи афінні координати незмінними.
- **Рандомізація скаляра (Scalar Blinding):** До приватного ключа `k` додається випадкове кратне порядку базової точки `n`:
  ```
  k' = k + r · n
  ```
  Оскільки `n · P = O`, результат залишається математично точним `k' · P = k · P + r · (n · P) = k · P + O = k · P`, але побітовий шаблон скаляра стає непередбачуваним для зловмисника.

## 8. Стиснення точок (Point Compression) та алгоритм Тонеллі–Шенкса

Оскільки ордината `y` задовольняє рівняння `y² ≡ x³ + a·x + b (mod p)`, для кожного значення `x` існують лише два можливих значення ординати: `y` та `p - y`. Для непарного простого модуля одне з цих чисел є парним, а інше — непарним.

Це дозволяє стиснути точку вдвічі: замість передачі обох координат `(x, y)` передають лише абсцису `x` та 1 біт парності ординати.

### Формат стандарту SECG SEC 1:
- `0x00`: точка на нескінченності `O`.
- `0x02 || x`: точка з **парною** ординатою `y` (`y % 2 == 0`).
- `0x03 || x`: точка з **непарною** ординатою `y` (`y % 2 == 1`).
- `0x04 || x || y`: нестиснений формат (передаються обидві координати).

### Алгоритм декомпресії:
1. Зчитуємо заголовок (0x02 або 0x03) та координату `x`.
2. Обчислюємо праву частину рівняння: `rhs = x³ + a·x + b mod p`.
3. Знаходимо квадратний корінь `y = sqrt(rhs) mod p`:
   - Якщо `p ≡ 3 (mod 4)`: використовується пряма формула Ейлера `y = rhs^((p + 1) / 4) mod p`.
   - Якщо `p ≡ 1 (mod 4)`: застосовується **алгоритм Тонеллі–Шенкса**, який факторизує `p - 1 = q · 2ˢ`, знаходить квадратичний нелишок `z` та ітеративно обчислює корінь у 2-підгрупі.
4. Перевіряємо, чи є `rhs` квадратичним лишком за критерієм Ейлера: `rhs^((p-1)/2) ≡ 1 mod p`. Якщо ні, точка не належить кривій і відхиляється.
5. Порівнюємо парність `y % 2` із заголовком. Якщо парність не збігається, обираємо симетричний корінь `y = p - y`.

## 9. Протокол обміну ключами Діффі–Геллмана на еліптичних кривих (ECDH)

Протокол ECDH дозволяє двом учасникам (Алісі та Бобу) сформувати ідентичний таємний сеансовий ключ через публічний незахищений канал зв'язку.

```
Аліса (приватний d_A ∈ [1, n-1])               Боб (приватний d_B ∈ [1, n-1])
Публічний: Q_A = d_A · P                       Публічний: Q_B = d_B · P
         |                                              |
         +----------------> Відкритий обмін ----------->|
         |                   (Q_A, Q_B)                 |
         |<---------------------------------------------+
         |                                              |
Обчислює: S_A = d_A · Q_B                      Обчислює: S_B = d_B · Q_A
              = d_A · (d_B · P)                             = d_B · (d_A · P)
```

Завдяки асоціативності та комутативності скалярного множення:
```
S_A = d_A · (d_B · P) = (d_A · d_B) · P = d_B · (d_A · P) = S_B = S
```
Координата `x_S` спільної точки `S = (x_S, y_S)` подається на вхід криптографічної функції формування ключів (HKDF-SHA256) для генерації симетричного ключа AES-GCM.

### Контрольний числовий розрахунок ECDH над 𝔽₉₇:
- Крива: `y² = x³ + 2·x + 3 (mod 97)`, базова точка `P = (3, 6)`, порядок групи `n = 5`.
- **Аліса:** обирає секрет `d_A = 2` ⇒ обчислює публічний ключ `Q_A = 2·P = (80, 10)`.
- **Боб:** обирає секрет `d_B = 3` ⇒ обчислює публічний ключ `Q_B = 3·P = (80, 87)`.
- **Обчислення секрету Алісою:** `S_A = 2 · Q_B = 2 · (80, 87) = 2 · (3·P) = 6·P = 1·P = (3, 6)`.
- **Обчислення секрету Бобом:** `S_B = 3 · Q_A = 3 · (80, 10) = 3 · (2·P) = 6·P = 1·P = (3, 6)`.
- Обидві сторони отримують спільний секретний `x`-ключ: **`x_S = 3`**.

## 10. Багаторозрядне множення Карацуби та метод Comba

У високопродуктивних криптографічних бібліотеках операція множення 256-бітних чисел є основним споживачем циклів процесора.

### 1. Алгоритм Карацуби (Karatsuba Multiplication)
Класичне шкільне множення двох `n`-розрядних чисел вимагає `O(n²)` множень машинних слів (для 4 лімбів: `4 × 4 = 16` множень). Анатолій Карацуба (1960) запропонував метод розбиття на дві частини:
```
A = A₁ · 2¹²⁸ + A₀,   B = B₁ · 2¹²⁸ + B₀
```
Замість 4 множень обчислюються лише 3:
1. `z₀ = A₀ · B₀`
2. `z₂ = A₁ · B₁`
3. `z₁ = (A₀ + A₁) · (B₀ + B₁) - z₀ - z₂`

Підсумковий добуток відновлюється за формулою: `A · B = z₂ · 2²⁵⁶ + z₁ · 2¹²⁸ + z₀`. Це знижує асимптотичну складність до `O(n^{\log₂ 3}) \approx O(n^{1.585})`.

### 2. Метод стовпчикового накопичення Comba
Для фіксованого невеликого числа лімбів (4 або 8) найкращу продуктивність забезпечує метод Comba. На відміну від шкільного множення, де проміжні добутки записуються у пам'ять, метод Comba обчислює вихідні лімби по стовпчиках, акумулюючи суму добутків `∑ A_i · B_j` (де `i + j = k`) у трьох 64-бітних регістрах процесора `(r₂, r₁, r₀)`. Це мінімізує кількість операцій звернення до оперативної пам'яті та кешу (L1/L2).

## 11. Оптимізація скалярного множення за допомогою ендоморфізмів (Метод GLV)

На спеціальних класах еліптичних кривих, що мають додатковий ендоморфізм малого степеня (Комплексне множення, CM), скалярне множення можна значно прискорити за допомогою **методу Галланта–Ламберта–Ванстоуна (GLV, 2001)**.

Найвідомішим прикладом кривої GLV є крива **secp256k1** (`y² = x³ + 7` над `𝔽ₚ` з `j = 0`), що використовується у мережах Bitcoin та Ethereum:
- На цій кривій існує ефективно обчислюваний ендоморфізм `ϕ(x, y) = (β · x, y)`, де `β³ ≡ 1 (mod p)` (`β ≠ 1`).
- Дія ендоморфізму на точки групи еквівалентна скалярному множенню на корінь характеристичного рівняння `λ`: `ϕ(P) = λ · P`, де `λ² + λ + 1 ≡ 0 (mod n)`.

### Схема методу GLV:
1. Довільний 256-бітний скаляр `k` за допомогою двійкового алгоритму Евкліда на гратці розкладається на пару 128-бітних скалярів `(k₁, k₂)`:
   ```
   k ≡ k₁ + k₂ · λ (mod n),   де |k₁|, |k₂| < √n \approx 2¹²⁸
   ```
2. Обчислення `k · P` зводиться до суми двох скалярних добутків удвічі меншої розрядності:
   ```
   k · P = k₁ · P + k₂ · ϕ(P)
   ```
3. Точка `ϕ(P) = (β · x_P, y_P)` знаходиться за 1 звичайне множення у полі без жодного подвоєння точок.
4. Обидва 128-бітні множення виконуються одночасно в одному циклі за допомогою **алгоритму Штрауса–Шаміра (Multi-Scalar Multiplication)**. Це дає **прискорення скалярного множення на 30–40%**!

## 12. Арифметика на скручених кривих Едвардса (Ed25519) та кривих Монтгомері (X25519)

Сучасні криптографічні стандарти (RFC 7748, RFC 8032) все частіше віддають перевагу альтернативним алгебраїчним моделям еліптичних кривих через їхню підвищену стійкість та відсутність виняткових станів.

### 1. Скручені криві Едвардса (Twisted Edwards Curves)
Рівняння кривої:
```
a·x² + y² = 1 + d·x²·y²
```
Найважливішою інженерною властивістю скручених кривих Едвардса є наявність **повних формул додавання (Complete Addition Formulas)**:
```
x₃ = (x₁·y₂ + y₁·x₂) / (1 + d·x₁·x₂·y₁·y₂)
y₃ = (y₁·y₂ - a·x₁·x₂) / (1 - d·x₁·x₂·y₁·y₂)
```
Якщо параметр `a` є квадратичним лишком у полі `𝔽ₚ`, а `d` — квадратичним нелишком, то знаменники `1 ± d·x₁·x₂·y₁·y₂` **ніколи не дорівнюють нулю** для будь-яких точок кривої! Формули працюють абсолютно однаково для `P ≠ Q`, для подвоєння `P = Q`, для протилежних точок `P + (-P) = (0, 1)` та для нейтрального елемента `(0, 1)`. Це повністю виключає будь-які розгалуження в програмному коді, гарантуючи природний захист від таймінг-атак.

У розширених координатах Едвардса `(X : Y : Z : T)` (де `T = X · Y / Z`) додавання виконується за **8 множень у полі (8M + 1D)** без жодної інверсії.

### 2. Криві Монтгомері та арифметика лише за X-координатою (X-only Arithmetic)
Рівняння кривої:
```
B·y² = x³ + A·x² + x
```
Для протоколу обміну ключами X25519 ордината `y` взагалі не обчислюється і не зберігається. Використовуючи проективні координати `(X : Z)` (де `x = X / Z`), диференціальне додавання точок `P + Q` обчислюється лише на основі координат `P`, `Q` та відомої різниці `P - Q`:
```
X_{P+Q} = Z_{P-Q} · [ (X_P - Z_P) · (X_Q + Z_Q) + (X_P + Z_P) · (X_Q - Z_Q) ]²
Z_{P+Q} = X_{P-Q} · [ (X_P - Z_P) · (X_Q + Z_Q) - (X_P + Z_P) · (X_Q - Z_Q) ]²
```
Скалярне множення виконується на драбині Монтгомері за **5 множень та 4 квадрати (5M + 4S)** на кожен біт скаляра без умовних переходів, що робить X25519 найшвидшим та найбезпечнішим протоколом ECDH у сучасному інтернеті.

## 13. Тестування, стандарти безпеки (Wycheproof) та диференціальний фазинг

Для гарантії надійності промислового криптографічного коду розробники застосовують трирівневу систему верифікації:

1. **Тестові вектори NIST CAVP та Project Wycheproof (Google):**
   Набори контрольних векторів Wycheproof спеціально розроблені для виявлення прихованих дефектів у граничних випадках:
   - спроба обробки точок нульової координати `(0, y)` та `(x, 0)`;
   - передача точок малої підгрупи (Small Subgroup Confinement);
   - передача недійсних точок з протилежних викрутів кривої (Twist Security);
   - екстремальні значення скалярів: `k = 0`, `k = 1`, `k = n - 1`, `k = n`, `k = n + 1`, `k = 2²⁵⁶ - 1`.

2. **Властивості інваріантів у Property-Based Testing:**
   Тестові генератори перевіряють виконання алгебраїчних тотожностей на мільйонах псевдовипадкових точок:
   - Комутативність: `P + Q == Q + P`
   - Асоціативність: `(P + Q) + R == P + (Q + R)`
   - Дистрибутивність: `(k₁ + k₂) · P == k₁ · P + k₂ · P`
   - Подвійне скалярне множення: `k₁ · (k₂ · P) == (k₁ · k₂ mod n) · P`
   - Нейтральний елемент: `P + O == P` та `n · P == O`
   - Протилежний елемент: `P + (-P) == O`

3. **Диференціальний фазинг (Differential Fuzzing):**
   Використовуючи інструменти автоматизованого тестування (libFuzzer, AFL++), виходи розробленого модуля безперервно порівнюються з результатами еталонних верифікованих криптографічних бібліотек (OpenSSL, libsecp256k1) для виявлення будь-яких невідповідностей у часі чи значеннях.

## 14. Інженерний чекліст аудиту безпеки криптографічного коду

Перед розгортанням криптографічного модуля у промисловій системі проводиться обов'язковий аудит за 8 ключовими критеріями:

1. **Constant-Time Execution (Виконання у сталий час):** Усі підпрограми множення, обернення, порівняння та серіалізації не містять розгалужень `if/else` чи індексацій масивів, що залежать від секретних скалярів або секретних координат.
2. **Безпечне очищення пам'яті (Secure Zeroization):** Буфери, що містили приватні ключі або проміжні скаляри, очищаються за допомогою спеціальних функцій, які компілятор не має права оптимізувати (`explicit_bzero`, `SecureZeroMemory` або `volatile` покажчики).
3. **Канонічна валідація вхідних даних (Canonical Encoding):** Усі вхідні координати перевіряються на належність діапазону `[0, p - 1]`. Значення `x >= p` категорично відхиляються для запобігання атакам з неоднозначністю представлення (Malleability Attacks).
4. **Перевірка належності кривій (On-Curve Validation):** Кожна точка, отримана від зовнішнього джерела, перевіряється на задоволення рівняння кривої `y² ≡ x³ + a·x + b (mod p)`.
5. **Перевірка порядку підгрупи (Subgroup Membership):** Виконується перевірка `n · Q == O`, щоб запобігти атакам на малі підгрупи.
6. **Криптографічний генератор випадкових чисел (CSPRNG):** Тимчасові секретні ключі та nonces генеруються виключно через системні криптографічні джерела ентропії (`/dev/urandom`, `getrandom`, `CryptGenRandom`).
7. **Детерміновані підписи (RFC 6979 / Ed25519):** Одноразовий nonce `k` обчислюється детерміновано як HMAC від приватного ключа та повідомлення, що повністю усуває загрозу витоку ключа через збій генератора випадкових чисел.
8. **Стійкість до викрутів (Twist Security):** Використовуються криві, для яких квадратичний викрут також має простий або майже простий порядок (як у Curve25519), що унеможливлює атаки на викрутах навіть при пропуску валідації.

### 3. Особливості Python-реалізації:
- **Підтримка необмеженої розрядності:** Python автоматично оперує довгими цілими числами, що дозволяє без змін коду запускати тести на реальних криптографічних кривих будь-якого розміру (NIST P-256, secp256k1, Curve25519, NIST P-521).

## 17. Валідація точок та захист від атак на некоректні криві (Invalid Curve Attacks)

Під час прийому публічного ключа або довільної точки `Q` від зовнішнього клієнта або через мережевий сокет криптографічний модуль зобов'язаний виконувати 3 обов'язкові перевірки валідності перед виконанням будь-яких операцій точкової арифметики:

1. **Належність полю 𝔽ₚ:**
   Перевірити, що координати `x` та `y` є коректними цілими числами у діапазоні `[0, p - 1]`.

2. **Перевірка рівняння кривої (On-Curve Check):**
   Підставити `(x, y)` у рівняння `y² ≡ x³ + a·x + b (mod p)`. Якщо рівність не справджується, точка належить іншій алгебраїчній кривій і підлягає негайному відхиленню.

3. **Перевірка порядку підгрупи (Subgroup Membership Check):**
   Переконатися, що точка `Q` належить великій підгрупі простого порядку `n`, перевіривши `n · Q == O`.

Нехтування цими перевірками дозволяє зловмиснику надіслати спеціально підібрану точку `Q'`, яка лежить на іншій («викрученій») кривій з малим гладким порядком групи. Обчисливши спільний секрет на такій точці, сервер обчислює `d · Q'`, що дозволяє атакуючому відновити залишки секретного ключа `d mod p_i` для малих дільників і повністю зламати приватний ключ за допомогою Китайської теореми про залишки (CRT). 

У реальних криптографічних протоколах (наприклад TLS 1.3 або Signal) валідація відсікає атаки ще до виклику скалярного множення. Поєднання валідації вхідних точок, виконання у сталий час за драбиною Монтгомері, використання координат Якобі та захисту пам'яті забезпечує промисловий рівень надійності та математичної неуразливості криптосистем на еліптичних кривих.
