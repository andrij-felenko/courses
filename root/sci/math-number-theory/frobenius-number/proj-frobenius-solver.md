# Програмний розв'язок задачі Фробеніуса (C++)

Хоча для двох базових елементівів існує проста [Формула Сильвестра](topic:math-number-theory/sylvester-frobenius-formula), для трьох і більше базових елементівів задача стає значно складнішою. У загальному випадку вона є NP-складною. Проте для конкретних невеликих значень ми можемо використати алгоритмічний підхід. У цьому проєкті ми реалізуємо універсальний розв'язувач на C++17, який використовує підхід на основі теорії графів (найкоротші шляхи на графі залишків) для знаходження числа Фробеніуса.

## 1. Концепція та підхід

Алгоритм базується на пошуку найкоротшого шляху. Нехай a₁ — найменший з базових елементівів. Ми розглядатимемо всі числа за модулем a₁. Для кожної остачі r ∈ {0, 1, ..., a₁−1} ми хочемо знайти найменшу суму M[r], яку можна утворити з наявних базових елементівів так, щоб M[r] ≡ r (mod a₁).

Якщо ми знаємо масив M[r], ми можемо гарантовано утворити будь-яку суму S ≡ r (mod a₁), якщо S ≥ M[r] (просто додаючи a₁ потрібну кількість разів). Отже, найбільше число, яке не можна утворити, буде дорівнювати:
g = max(M[r]) − a₁, для всіх r, де M[r] ≠ 0.

Для знаходження масиву M[r] ми будуємо орієнтований граф, де вершини — це остачі від 0 до a₁−1. З кожної вершини u існує ребро у вершину (u + a_i) mod a₁ з вагою a_i для всіх інших базових елементівів a_i. Тоді M[r] — це довжина найкоротшого шляху від вершини 0 до вершини r. Оскільки ваги додатні, ми можемо використати алгоритм Дейкстри.

## 2. Підготовка проєкту

Створіть файл `frobenius_solver.cpp`. Переконайтеся, що ваш компілятор підтримує C++17 (прапорець `-std=c++17`). Ми будемо використовувати стандартні бібліотеки `<iostream>`, `<vector>`, `<queue>`, та `<numeric>` для обчислення найбільшого спільного дільника (НСД).

## 3. Реалізація алгоритму Дейкстри

Нижче наведено повний код, який приймає вектор базових елементівів генераторів і знаходить число Фробеніуса.

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <numeric>
#include <algorithm>
#include <stdexcept>

// Функція для обчислення НСД кількох чисел
long long get_gcd(const std::vector<long long>& coins) {
    long long res = coins[0];
    for (size_t i = 1; i < coins.size(); ++i) {
        res = std::gcd(res, coins[i]);
    }
    return res;
}

// Головна функція
long long frobenius_number(std::vector<long long> coins) {
    if (coins.empty()) throw std::invalid_argument("Масив не може бути порожнім");
    
    // Відкидаємо нулі та сортуємо
    coins.erase(std::remove(coins.begin(), coins.end(), 0), coins.end());
    if (coins.empty()) throw std::invalid_argument("Повинні бути ненульові базових елементів");
    
    std::sort(coins.begin(), coins.end());
    
    if (get_gcd(coins) != 1) {
        throw std::invalid_argument("Найбільший спільний дільник має бути 1");
    }
    
    long long a1 = coins[0];
    if (a1 == 1) return -1; // Усі натуральні числа досяжні
    
    // Відстані (найменші суми для кожної остачі)
    const long long INF = 1e18;
    std::vector<long long> M(a1, INF);
    M[0] = 0;
    
    // Пріоритетна черга для Дейкстри: пара {відстань, вершина}
    using pii = std::pair<long long, int>;
    std::priority_queue<pii, std::vector<pii>, std::greater<pii>> pq;
    pq.push({0, 0});
    
    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();
        
        if (d > M[u]) continue;
        
        for (size_t i = 1; i < coins.size(); ++i) {
            long long weight = coins[i];
            int v = (u + weight) % a1;
            
            if (M[u] + weight < M[v]) {
                M[v] = M[u] + weight;
                pq.push({M[v], v});
            }
        }
    }
    
    long long max_M = 0;
    for (int i = 1; i < a1; ++i) {
        if (M[i] > max_M) {
            max_M = M[i];
        }
    }
    
    return max_M - a1;
}
```

## 4. Тестування та використання

Додамо функцію `main` для перевірки нашої реалізації. Ми перевіримо два випадки: відомий приклад для n=2 (базових елементів 3 і 5) та складніший випадок для n=3.

```cpp
int main() {
    try {
        std::vector<long long> coins2 = {3, 5};
        std::cout << "g(3, 5) = " << frobenius_number(coins2) << std::endl;
        
        std::vector<long long> coins3 = {6, 9, 20};
        std::cout << "g(6, 9, 20) = " << frobenius_number(coins3) << std::endl;
        
    } catch (const std::exception& e) {
        std::cerr << "Помилка: " << e.what() << std::endl;
    }
    return 0;
}
```

При виконанні програма виведе:
g(3, 5) = 7
g(6, 9, 20) = 43

## 5. Огляд та масштабованість

Цей метод набагато ефективніший за простий перебір. Часова складність алгоритму становить O(a₁ · k · log(a₁)), де a₁ — найменший базових елементів, а k — кількість базових елементівів. Він працює миттєво навіть для значень a₁ порядку 10⁵. Це демонструє, як розумне використання графів та модульної арифметики дозволяє звести задачу, що загалом є NP-складною, до дуже швидкого розв'язку для практичних діапазонів значень.
