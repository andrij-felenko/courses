# 🔍 Тест простоти Ферма: сказати «складене», не знайшовши жодного дільника

Мала теорема Ферма, прочитана як контрапозиція, дає найдешевший спосіб перевірити багатоцифрове число на простоту: замість нездійсненного перебору дільників ми виконуємо кілька модульних піднесень до степеня й у разі складеності отримуємо **строгий алгебраїчний сертифікат**, не знаючи при цьому жодного конкретного множника числа. Саме цей механізм лежить в основі швидкої генерації простих чисел для ключів криптосистеми RSA.

<preknowlist>
- [Модульна арифметика](root:math-number-theory/modular-arithmetic) — запис a ≡ b (mod n) означає однакову остачу при діленні на n; додавати, множити й підносити до степеня можна безпосередньо над класами лишків 0 … n−1.
- [НСД і взаємна простота](root:math-number-theory/gcd-euclidean) — коли найбільший спільний дільник двох чисел дорівнює 1, вони не мають спільних простих множників і є взаємно простими.
</preknowlist>

## Проблема перебору: чому факторизація безсила

Сучасна асиметрична криптографія тримається на великих простих числах. Наприклад, для створення ключів криптосистеми RSA стандартної довжини 2048 бітів потрібно згенерувати два випадкових простих числа p та q довжиною по 1024 біти (близько 300 десяткових цифр кожне), після чого обчислити їхній добуток n = p · q. Безпека RSA гарантується тим, що знаючи лише n, жоден комп'ютер у світі не здатний розкласти його назад на множники p та q за розумний час.

Але тут виникає фундаментальне інженерне питання: якщо розкласти трьохсотцифрове число n на множники неможливо, то **як ми взагалі переконуємося, що знайдені випадкові кандидати p та q самі є простими числами?**

Класичний метод перебору всіх потенційних дільників d від 2 до √n (пробний поділ) тут принципово непридатний:
- для стоцифрового числа n значення √n має близько 50 десяткових цифр (порядку 10⁵⁰);
- навіть якби суперкомп'ютер перевіряв 10¹⁸ дільників за секунду (один ексафлопс), повний перебір забрав би близько 10³² секунд, що на багато порядків перевищує вік усього нашого Всесвіту (близько 10¹⁷ секунд).

Щоб будувати криптографічні ключі за мілісекунди, потрібен алгоритм зовсім іншої природи — тест, який здатен винести остаточний вирок «число складене» **без знаходження будь-якого дільника**. Саме таким зондом виступає мала теорема Ферма.

## Математичний принцип: контрапозиція замість поділу

Мала теорема Ферма стверджує пряме твердження: якщо p — просте число, то для будь-якої основи a, не кратної p (тобто НСД(a, p) = 1), виконується конгруенція:

```
aᵖ⁻¹ ≡ 1 (mod p)
```

Застосуємо до цього твердження логічну операцію [контрапозиції](root:math-logic/mathematical-induction) (якщо з A випливає B, то із заперечення B гарантовано випливає заперечення A):

```
aⁿ⁻¹ ≢ 1 (mod n)   ⟹   n — гарантовано складене число
```

Ось фундаментальний принцип тесту Ферма: якщо для деякого числа a виявилося, що остача від ділення aⁿ⁻¹ на n відмінна від 1, то число n **гарантовано не є простим**.

Таку основу a називають **свідком складеності за Ферма** (Fermat witness). Знаходження хоча б одного свідка a є неспростовним математичним доказом складеності n. При цьому ми отримуємо чистий алгебраїчний сертифікат складеності: ми достеменно знаємо, що n розкладається на множники, хоча не знаємо жодного з них.

### Зворотний бік: брехуни Ферма та псевдопрості числа

Що відбувається, коли для деякої основи a конгруенція виконується, тобто aⁿ⁻¹ ≡ 1 (mod n)?
Чи доводить це простоту n? **Ні, не доводить.**

Існують складені числа n, які для деяких конкретних основ a поводяться так само, як прості. Складене число n, для якого aⁿ⁻¹ ≡ 1 (mod n), називають **псевдопростим числом Ферма за основою a**, а саму таку основу a — **брехуном Ферма** (Fermat liar).

Тому тест Ферма є **одностороннім імовірнісним тестом**:
- вердикт `false` («складене») — є 100% строгим детермінованим доказом;
- вердикт `true` («імовірно просте») — є лише статистичною гіпотезою.

Щоб зменшити ймовірність помилки, тест запускають послідовно для k різних випадкових основ a₁, a₂, …, a_k. Якщо хоча б одна основа виявиться свідком, кандидат миттєво відкидається; якщо ж усі k основ дали одиницю, ймовірність складеності стає надзвичайно малою.

## Двигун: бінарне піднесення до степеня за модулем

Уся обчислювальна робота тесту зводиться до обчислення виразу `a^(n−1) mod n`. Але якщо число n має сотні цифр, показник n − 1 є астрономічним. Пряме послідовне множення a · a · … · a вимагало б n − 2 операцій, що так само неможливо, як і перебір дільників.

Розв'язок полягає в алгоритмі **швидкого піднесення до степеня за модулем (Square-and-Multiply)**.
Показник e = n − 1 подається у двійковому вигляді:

```
e = b_m · 2ᵐ + b_{m−1} · 2^{m−1} + … + b₁ · 2¹ + b₀ · 2⁰,   де b_i ∈ {0, 1}
```

Алгоритм підносить основу до квадрата на кожному кроці (формуючи сходинки a², a⁴, a⁸, a¹⁶, …) і домножує накопичений результат на поточну сходинку лише тоді, коли відповідний біт b_i дорівнює 1.

Головна властивість модульної арифметики: взяття залишку `mod n` можна виконувати **після кожного множення**, завдяки чому проміжні результати ніколи не перевищують величини n²:

```python
def modpow(base: int, exp: int, mod: int) -> int:
    result = 1
    base %= mod
    while exp > 0:
        if exp & 1:                         # якщо молодший біт дорівнює 1
            result = (result * base) % mod  # домножуємо результат на поточну сходинку
        base = (base * base) % mod          # підносимо сходинку до квадрата
        exp >>= 1                           # зсуваємо показник на один біт праворуч
    return result
```

Кількість операцій множення при такому підході становить не більше 2 · ⌊log₂ n⌋. Для стоцифрового числа n це менше ніж 700 множень замість 10¹⁰⁰.

### Особливості реалізацій та захист від переповнення

1. **Python:** завдяки вбудованій довгій арифметиці довільної точності (`PyLongObject`) та оптимізованій функції `pow(a, exp, mod)` мова повністю позбавляє програміста турбот про переповнення розрядів.
2. **C:** у мові C для 64-бітних цілих чисел типу `uint64_t` множення двох залишків a та b, менших за m ≈ 2⁶⁴, дає добуток до 2¹²⁸. Звичайне 64-бітне множення `a * b` призведе до тихого переповнення зі скиданням старших бітів. Щоб уникнути помилки, проміжний добуток приводять до 128-бітного цілого типу `unsigned __int128`, що підтримується компіляторами GCC та Clang.

## Покрокове трасування роботи алгоритму

Простежимо роботу тесту на конкретних числових прикладах із повною деталізацією кожного кроку.

### Приклад 1: складене псевдопросте число n = 341 = 11 · 31

Показник степеня e = n − 1 = 340. У двійковій системі числення:

```
340 = 256 + 64 + 16 + 4 = (101010100)₂
```

1. **Тестування за основою a = 2:**
   Обчислюємо послідовні квадрати двійки за модулем 341:
   - 2¹ = 2
   - 2² = 4
   - 2⁴ = 16
   - 2⁸ = 256
   - 2¹⁶ = 256² = 65536 = 192 · 341 + 64 ≡ 64 (mod 341)
   - 2³² = 64² = 4096 = 12 · 341 + 4 ≡ 4 (mod 341)
   - 2⁶⁴ = 4² = 16 (mod 341)
   - 2¹²⁸ = 16² = 256 (mod 341)
   - 2²⁵⁶ = 256² ≡ 64 (mod 341)

   Збираємо добуток під бітами одиниць (біти 256, 64, 16, 4):
   ```
   2³⁴⁰ = 2²⁵⁶ · 2⁶⁴ · 2¹⁶ · 2⁴ ≡ 64 · 16 · 64 · 16 = (64 · 16)² = 1024² (mod 341)
   1024 = 3 · 341 + 1 ≡ 1 (mod 341)
   1024² ≡ 1² = 1 (mod 341)
   ```
   Основа a = 2 видала результат 1: число 341 є псевдопростим за основою 2, а сама двійка — брехуном.

2. **Тестування за основою a = 3:**
   Обчислюємо 3³⁴⁰ mod 341:
   - 3¹ = 3, 3² = 9, 3⁴ = 81
   - 3⁸ = 81² = 6561 = 19 · 341 + 82 ≡ 82 (mod 341)
   - 3¹⁶ = 82² = 6724 = 19 · 341 + 245 ≡ 245 ≡ −96 (mod 341)
   - 3³² = (−96)² = 9216 = 27 · 341 + 9 ≡ 9 (mod 341)
   - 3⁶⁴ = 9² = 81 (mod 341)
   - 3¹²⁸ = 81² ≡ 82 (mod 341)
   - 3²⁵⁶ = 82² ≡ 245 (mod 341)

   Збираємо добуток:
   ```
   3³⁴⁰ = 3²⁵⁶ · 3⁶⁴ · 3¹⁶ · 3⁴ ≡ 245 · 81 · 245 · 81 = (245 · 81)² (mod 341)
   245 · 81 = 19845 = 58 · 341 + 67 ≡ 67 (mod 341)
   67² = 4489 = 13 · 341 + 56 ≡ 56 (mod 341)
   ```
   Оскільки 56 ≠ 1, основа a = 3 є свідком: число 341 **остаточно визнано складеним**.

### Приклад 2: просте число n = 13

Показник степеня e = n − 1 = 12 = (1100)₂.
Перевіримо основи a = 2, 3, 5:
- для a = 2: 2¹² = (2⁴)³ = 16³ ≡ 3³ = 27 = 2 · 13 + 1 ≡ 1 (mod 13);
- для a = 3: 3¹² = (3³)⁴ = 27⁴ ≡ 1⁴ = 1 (mod 13);
- для a = 5: 5¹² = (5²)⁶ = 25⁶ ≡ (−1)⁶ = 1 (mod 13).
Усі основи дали 1, кандидат проходить тест.

## Пастки: структура чисел Кармайкла

Чи можна повністю покладатися на тест Ферма, якщо брати велику кількість випадкових основ (наприклад, k = 100)?

Виявляється, що ні. Існують дивовижні складені числа, які задовольняють конгруенцію aⁿ⁻¹ ≡ 1 (mod n) **для абсолютно всіх взаємно простих основ a**. Такі числа називають **числами Кармайкла** (або абсолютними псевдопростими).

1899 року німецький математик Альвін Корсельт сформулював точний критерій:
Складене число n є числом Кармайкла тоді й лише тоді, коли:
1. n є вільним від квадратів (не ділиться на p² для жодного простого p);
2. для кожного простого дільника p числа n різниця p − 1 націло ділить n − 1:

```
(p − 1)  ділить  (n − 1)
```

### Розбір найменшого числа Кармайкла: n = 561 = 3 · 11 · 17

Показник n − 1 = 560.
Перевіримо дільники:
- для p₁ = 3: p₁ − 1 = 2; 560 = 2 · 280 (ділиться націло);
- для p₂ = 11: p₂ − 1 = 10; 560 = 10 · 56 (ділиться націло);
- для p₃ = 17: p₃ − 1 = 16; 560 = 16 · 35 (ділиться націло).

Універсальний показник [функції Кармайкла](root:math-number-theory/carmichael-function) для 561:

```
λ(561) = НСК(3−1, 11−1, 17−1) = НСК(2, 10, 16) = 80
```

Оскільки 560 = 80 · 7, для будь-якого a, взаємно простого з 561, маємо:

```
a⁵⁶⁰ = (a⁸⁰)⁷ ≡ 1⁷ = 1 (mod 561)
```

### Розбір другого числа Кармайкла: n = 1105 = 5 · 13 · 17

Показник n − 1 = 1104.
Перевіримо умови Корсельта:
1. Число 1105 вільне від квадратів (5, 13, 17 — перші степені).
2. Подільність дільників:
   - для p₁ = 5: p₁ − 1 = 4; 1104 = 4 · 276 (ділиться націло);
   - для p₂ = 13: p₂ − 1 = 12; 1104 = 12 · 92 (ділиться націло);
   - для p₃ = 17: p₃ − 1 = 16; 1104 = 16 · 69 (ділиться націло).

Функція Кармайкла: λ(1105) = НСК(4, 12, 16) = 48.
Оскільки 1104 = 48 · 23, для будь-якої взаємно простої основи a маємо a¹¹⁰⁴ = (a⁴⁸)²³ ≡ 1²³ = 1 (mod 1105).
Наприклад, обчисливши 2¹¹⁰⁴ mod 1105 або 3¹¹⁰⁴ mod 1105, ми щоразу отримуємо 1. Конгруенція Ферма абсолютно сліпа перед числом 1105.

![Дві смужки основ a = 2 … 14. Для 341 серед основ трапляються зелені свідки (aⁿ⁻¹ ≢ 1) — тест його ловить. Для числа Кармайкла 561 жодної зеленої: кожна взаємно проста основа червона (aⁿ⁻¹ ≡ 1, брехун), а сірі — основи зі спільним дільником, що викривають складеність не конгруенцією, а випадковим множником](/root/sci/math-number-theory/fermat-little-theorem/img/witness-liar.svg)

*Ліворуч від кожної клітинки — основа a, усередині — доля aⁿ⁻¹ mod n. У 341 є зелені свідки, тож кілька основ його викривають. У 561 зелених немає взагалі: усі взаємно прості основи брешуть, і конгруенція Ферма безсила — лишаються тільки сірі «випадкові» влучення в дільник, яких у великих чисел Кармайкла практично не буває.*

1994 року Вільям Олфорд, Ендрю Ґранвіль та Карл Померанс довели, що чисел Кармайкла нескінченно багато, тому збільшенням кількості основ k сліпу пляму тесту Ферма усунути неможливо.

## Інженерний конвеєр у криптографічних бібліотеках (OpenSSL)

У реальних криптографічних бібліотеках промислового рівня (OpenSSL, BoringSSL, Libgcrypt) генерація простих чисел ніколи не виконується одним «сирим» алгоритмом. Процес побудовано як багатоступеневий конвеєр оптимізацій, де швидкі й дешеві евристики стоять на початку, а важкі й математично строгі перевірки — наприкінці.

Типовий конвеєр генерації великого простого кандидата (функція `BN_generate_prime_ex` в OpenSSL):

1. **Генерація псевдовипадкового двійкового блоку:** генератор випадкових чисел криптографічної стійкості (CSPRNG) генерує послідовність бітів потрібної довжини (наприклад, 1024 біти). Старші два біти встановлюються в одиницю (щоб добуток двох чисел гарантовано мав довжину 2048 бітів), а молодший біт виставляється в 1, відкидаючи всі парні числа:

```
candidate |= 1;                      // гарантуємо непарність
candidate |= (1ULL << (bits - 1));   // фіксуємо старший розряд
```

2. **Попереднє просіювання малими простими числами (Pre-sieving):** перед запуском будь-якого піднесення до степеня кандидат n ділиться з остачею на таблицю перших кількох сотень малих простих чисел (3, 5, 7, 11, 13, …, 2048).
   - Чому це критично: за [теоремою Мертенса](root:math-number-theory/prime-numbers), перевірка подільності на перші 2000 простих чисел миттєво відсіює понад 88% усіх випадкових непарних складених кандидатів.
   - Час виконання: операція ділення 1024-бітного числа на звичайне 16-бітне мале просте число триває мікросекунди і не потребує важких матричних чи степеневих множень.

3. **Швидкий фільтр Ферма за основою 2:** кандидат, який пройшов просіювання, тестується одним піднесенням 2ⁿ⁻¹ mod n. Якщо отримано не одиницю, кандидат відкидається за одну операцію.

4. **Тест Міллера — Рабіна з нормативною кількістю раундів:** кандидати, що подолали попередні бар'єри, проходять серію раундів тесту Міллера — Рабіна. Кількість раундів регламентується криптографічними стандартами безпеки (FIPS 186-5, NIST SP 800-56B). Для 1024-бітних чисел зазвичай виконується від 4 до 8 раундів із випадковими основами, а також перевірка за тестом Люка — Лемера (тест Бейлі — Померанса — Селфріджа — Ваґстаффа, BPSW), що гарантує відсутність відомих контрприкладів.

## Алгоритмічні оптимізації: метод Монтгомері та Constant-Time виконання

Усередині циклу square-and-multiply найдорожчою операцією є не саме множення чисел, а операція взяття остачі `x % n`, оскільки класичне ділення багатоцифрових чисел у стовпчик вимагає десятків тактів процесора на кожен розряд.

Щоб уникнути повільного ділення, у всіх криптографічних процесорах застосовують **множення Монтгомері (Montgomery modular multiplication)**.
Ідея Пітера Монтгомері (1985) полягає у переході в спеціальний простір лишків: замість числа x зберігається його образ x̃ = x · R mod n, де R = 2ᵏ — степінь двійки, що перевищує n (наприклад, R = 2¹⁰²⁴).

У просторі Монтгомері операція множення двох чисел з подальшим зведенням за модулем замінюється на звичайні побітові зсуви праворуч та додавання, повністю виключаючи операцію ділення. Перехід у простір Монтгомері та вихід із нього коштують лише два додаткових множення на весь тест, тоді як сотні проміжних кроків square-and-multiply прискорюються у 3–5 разів.

### Захист від атак за сторонніми каналами (Side-Channel Attacks)

У системах захисту інформації базовий цикл `if (exp & 1)` несе приховану небезпеку: розгалуження в коді призводить до різного часу виконання та різного споживання енергії процесором залежно від того, чи дорівнює поточний біт показника 0 або 1.

Вимірюючи точний час операції (Timing Attack) або аналізуючи коливання струму в ланцюзі живлення мікроконтролера (Differential Power Analysis, DPA), зловмисник може повністю відновити біти секретного показника.

Щоб запобігти витоку інформації, у криптографічному ПЗ використовують **алгоритми постійного часу (Constant-Time)** та **драбину Монтгомері (Montgomery ladder)**: на кожному біті показника процесор виконує строго фіксовану кількість операцій (одне піднесення до квадрата й одне множення), незалежно від значення біта, а результат вибирається за допомогою безрозгалужених побітових масок (bitwise masking).

## Еволюція: перехід до тесту Міллера — Рабіна

Щоб подолати проблему чисел Кармайкла, 1976–1980 років Ґері Міллер та Майкл Рабін створили [тест Міллера — Рабіна](root:math-number-theory/miller-rabin).

Ідея полягає в тому, щоб аналізувати не лише фінальний степінь aⁿ⁻¹, а весь ланцюжок проміжних квадратів.
Подамо n − 1 у вигляді:

```
n − 1 = 2ˢ · d,   де d — непарне число
```

Алгоритм обчислює початковий елемент x₀ = aᵈ mod n, а потім послідовно підносить його до квадрата s разів:

```
x₁ = x₀² mod n,   x₂ = x₁² mod n,   …,   x_s = aⁿ⁻¹ mod n
```

Якщо n — просте число, то в полі ℤ/nℤ рівняння x² ≡ 1 (mod n) має **рівно два розв'язки: x ≡ 1 та x ≡ −1**.
Якщо ж на якомусь проміжному кроці піднесення до квадрата з'явилося число x, таке що:

```
x² ≡ 1 (mod n),   але   x ≢ 1  та  x ≢ −1 (mod n)
```

то x називають **нетривіальним квадратним коренем з одиниці**. За простим модулем таких коренів не буває ніколи; їхня поява — 100% доказ складеності n. Більше того, числа НСД(x − 1, n) та НСД(x + 1, n) дають нетривіальні дільники n.

Майкл Рабін строго довів, що для **будь-якого** складеного числа n (включаючи абсолютно всі числа Кармайкла) щонайменше 75% (три чверті) всіх можливих основ a є свідками Міллера — Рабіна.
Тому після k незалежних перевірок імовірність пропустити складене число оцінюється зверху як:

```
P(помилки) ≤ (1/4)ᵏ = 2⁻²ᵏ
```

При k = 40 імовірність помилки становить менше 2⁻⁸⁰ ≈ 10⁻²⁴, що в мільярди разів менше за ймовірність апаратного збою процесора чи впливу космічних променів на пам'ять сервера.

Тест Ферма лишається історично першим, концептуально найпростішим і найшвидшим фільтром простоти, а його математичні засади сформували фундамент сучасної комп'ютерної теорії чисел.
