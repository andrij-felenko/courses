# ⚙️ Реалізація підйому Гензеля: корені та факторизація

Ця практична вставка містить готові до використання реалізації лінійного та квадратичного підйому Гензеля для пошуку коренів многочленів за модулем `pᵏ`, а також інженерний аналіз підйому розкладу многочленів на множники. Вона розкриває архітектурні особливості обчислення модульних коренів, аналіз обчислювальної складності, оптимізацію пам'яті, низькорівневе профілювання та захист від цілочисельного переповнення.

## 1. Архітектурні принципи та вибір типів даних

Реалізація модульного підйому Гензеля у високопродуктивних системах вимагає суворого дотримання чотирьох інженерних вимог:

1. **Захист від від'ємних остач (Truncated Division):**
   У мовах програмування C та C++ оператор `%` реалізує усічене ділення (*truncated division* за стандартами ISO C99 та ISO C++11), при якому знак остачі збігається зі знаком діленого (наприклад, `-7 % 3 = -1`, а не `2`). Оскільки модульна арифметика в теорії чисел працює виключно в невід'ємному кільці лишків `Z/nZ = {0, 1, ..., n - 1}`, будь-який результат операції `%` має додатково нормалізуватися допоміжною функцією:
   ```c
   static inline int64_t mod_pos(int64_t val, int64_t m) {
       int64_t rem = val % m;
       return (rem < 0) ? rem + m : rem;
   }
   ```

2. **Захист від цілочисельного переповнення під час множення:**
   Підйом кореня за модулем `pᵏ` вимагає обчислення проміжних добутків `f(a_k) · [f'(a_k)]⁻¹ (mod p^{2k})` або акумуляції в схемі Горнера `result * x + coeff`. Навіть якщо вхідні коефіцієнти вміщуються в 32-бітний тип `int32_t`, їхній добуток може досягати `2⁶²`, що переповнює знаковий тип `int64_t`. У криптографічних застосуваннях та при роботі з великими степенями модуля слід застосовувати 64-бітні беззнакові типи `uint64_t`, вбудований 128-бітний тип `__int128_t` (доступний у компіляторах GCC та Clang) або бібліотеки довгої арифметики (GNU MPFR / GMP / FLINT).

3. **Схема Горнера для оцінки многочлена та його похідної:**
   Пряме обчислення степенів `xᵐ` вимагає `O(deg²)` операцій множення та накопичує великі проміжні значення. Схема Горнера перегруповує операції у вкладені дужки:
   ```
   f(x) = c₀ + x·(c₁ + x·(c₂ + ... + x·(c_{n-1} + x·c_n)...))
   ```
   Це скорочує кількість операцій множення до `O(deg)` та дозволяє застосовувати модульне приведення після кожного додавання коефіцієнта.

4. **Розділення випадків регулярного та виродженого підйому:**
   Якщо `f'(a₁) ≡ 0 (mod p)`, прямий підйом неможливий через відсутність оберненого елемента в полі `F_p`. Архітектура бібліотеки повинна повертати явні коди помилок (`HenselStatus` у C або `std::optional<LiftResult>` / `std::expected` у C++), а не завершувати процес аварійним діленням на нуль.

## 2. Алгоритми лінійного та квадратичного підйому коренів

Вхідні дані для алгоритму підйому:
- Масив цілих коефіцієнтів многочлена `poly = [c₀, c₁, ..., c_n]` для `f(x) = ∑ c_i · xⁱ`;
- Просте число `p`;
- Цільовий цілий показник степеня `k ≥ 1`;
- Початковий простий корінь `r₁ ∈ {0, 1, ..., p - 1}`, такий що `f(r₁) ≡ 0 (mod p)` та `f'(r₁) ≢ 0 (mod p)`.

Вихідні дані:
- Унікальне ціле число `a_k ∈ {0, 1, ..., pᵏ - 1}`, для якого `f(a_k) ≡ 0 (mod pᵏ)` та `a_k ≡ r₁ (mod p)`.

## 3. Детальний покроковий аналіз реалізованих функцій

### Функція `mod_inverse` (Розширений алгоритм Евкліда)

Функція знаходить мультиплікативний обернений елемент `x = a⁻¹ (mod m)` такий, що `a · x ≡ 1 (mod m)`.

Вона розв'язує лінійне діофантове рівняння Безу:

```
a · x + m · y = gcd(a, m)
```

Алгоритм підтримує інваріант послідовних залишків та коефіцієнтів:
- Якщо `gcd(a, m) = 1`, коефіцієнт `x` після зведення до діапазону `[0, m - 1]` є шуканим оберненим елементом;
- Якщо `gcd(a, m) > 1`, оберненого елемента не існує в кільці `Z/mZ`, і функція повертає `false` або `std::nullopt`.

Асимптотична складність операції становить `O(log(min(a, m)))` операцій ділення.

### Схема Горнера: `eval_poly` та `eval_derivative`

Обидві функції реалізують ітераційний підхід зі зворотною індексацією:
- `eval_poly` починає зі старшого коефіцієнта `poly[deg]` і на кожному кроці множить накопичений результат на `x`, додаючи наступний молодший коефіцієнт;
- `eval_derivative` обчислює значення формальної похідної многочлена:
  ```
  f'(x) = ∑_{i=1}^n i · c_i · x^{i-1}
  ```
  Коефіцієнт кожного монома множиться на свій степінь `i` безпосередньо в циклі Горнера.

Кожен проміжний результат негайно приводиться за модулем `mod`, що запобігає переповненню розрядної сітки процесора.

### Порівняльний аналіз: Лінійний підйом проти Квадратичного

| Характеристика | Лінійний підйом (`hensel_lift_linear`) | Квадратичний підйом (`hensel_lift_quadratic`) |
|---|---|---|
| **Зростання степеня модуля** | `p¹ → p² → p³ → ... → pᵏ` (по `+1`) | `p¹ → p² → p⁴ → p⁸ → ... → p^{2ᵐ}` (подвоєння) |
| **Кількість ітерацій** | `k - 1` | `⌈log₂(k)⌉` |
| **Обчислення оберненого `(f')⁻¹`** | **1 раз** за малим модулем `p` | На кожній ітерації за модулем `p^{2ⁱ}` |
| **Асимптотична складність** | `O(k · deg(f))` модульних операцій | `O(log(k) · M(k · log p) · deg(f))` |
| **Оптимальна зона вжитку** | Малі степені (`k ≤ 16`), фіксований `f'` | Великі степені (`k ≥ 64`), криптографія |

**Інженерний висновок:** Для малих степенів `k ≤ 16` лінійний підйом часто працює швидше за рахунок відсутності необхідності повторного обчислення оберненої похідної за зростаючими модулями. Для високої точності (`k = 128, 256, 1024` біт) квадратичний метод Ньютона суттєво перевершує лінійний завдяки логарифмічній кількості кроків.

## 4. Покрокове трасування виконання коду

Щоб простежити роботу алгоритму на рівні окремих змінних і регістрів пам'яті, розглянемо покрокове виконання двох прикладів.

### Трасування лінійного підйому (`f(x) = x² - 7 ≡ 0 (mod 3⁵)`)

Вхідні параметри: `poly = [-7, 0, 1]`, `deg = 2`, `p = 3`, `target_k = 5`, `r₁ = 1`.

1. **Ініціалізація:**
   - `current_root = 1`.
   - Похідна: `f'(1) = 2 · 1 = 2 ≡ 2 (mod 3) ≠ 0`.
   - Обернений елемент: `v = mod_inverse(2, 3) = 2` (оскільки `2 · 2 = 4 ≡ 1 (mod 3)`).
   - Початковий степінь: `p_pow = 3`.

2. **Ітерація 1 (`step = 1`, підйом до `p² = 9`):**
   - `p_next = 3 · 3 = 9`.
   - `f_val = eval_poly(poly, 2, 1, 9) = (1² - 7) mod 9 = -6 mod 9 = 3`.
   - `q = f_val / p_pow = (-6) / 3 = -2`.
   - Поправка: `t = mod_pos(-(-2) · 2, 3) = mod_pos(4, 3) = 1`.
   - Оновлений корінь: `current_root = 1 + 1 · 3 = 4`.
   - `p_pow = 9`.

3. **Ітерація 2 (`step = 2`, підйом до `p³ = 27`):**
   - `p_next = 9 · 3 = 27`.
   - `f_val = (4² - 7) mod 27 = 9 mod 27 = 9`.
   - `q = 9 / 9 = 1`.
   - Поправка: `t = mod_pos(-1 · 2, 3) = mod_pos(-2, 3) = 1`.
   - Оновлений корінь: `current_root = 4 + 1 · 9 = 13`.
   - `p_pow = 27`.

4. **Ітерація 3 (`step = 3`, підйом до `p⁴ = 81`):**
   - `p_next = 27 · 3 = 81`.
   - `f_val = (13² - 7) mod 81 = (169 - 7) mod 81 = 162 mod 81 = 0`.
   - `q = 162 / 27 = 6 ≡ 0 (mod 3)`.
   - Поправка: `t = mod_pos(-0 · 2, 3) = 0`.
   - Оновлений корінь: `current_root = 13 + 0 · 27 = 13`.
   - `p_pow = 81`.

5. **Ітерація 4 (`step = 4`, підйом до `p⁵ = 243`):**
   - `p_next = 81 · 3 = 243`.
   - `f_val = (13² - 7) mod 243 = 162 mod 243 = 162`.
   - `q = 162 / 81 = 2`.
   - Поправка: `t = mod_pos(-2 · 2, 3) = mod_pos(-4, 3) = 2`.
   - Оновлений корінь: `current_root = 13 + 2 · 81 = 13 + 162 = 175`.
   - `p_pow = 243`.

6. **Результат:** Знайдено корінь `175 (mod 243)`. Перевірка: `175² - 7 = 30625 - 7 = 30618 = 126 · 243 ≡ 0 (mod 243)`.

### Трасування квадратичного підйому (`f(x) = x³ - 2 ≡ 0 (mod 5⁴)`)

Вхідні параметри: `poly = [-2, 0, 0, 1]`, `deg = 3`, `p = 5`, `target_k = 4`, `r₁ = 3`.

1. **Ініціалізація:**
   - `root = 3`.
   - `current_mod = 5`.
   - `target_mod = 5⁴ = 625`.

2. **Ітерація 1 (подвоєння `5 → 25`):**
   - `next_mod = 5² = 25`.
   - `f_val = eval_poly(poly, 3, 3, 25) = (3³ - 2) mod 25 = 25 mod 25 = 0`.
   - `df_val = eval_derivative(poly, 3, 3, 25) = (3 · 3²) mod 25 = 27 mod 25 = 2`.
   - `inv_df = mod_inverse(2, 25) = 13` (бо `2 · 13 = 26 ≡ 1 (mod 25)`).
   - `delta = mod_pos(0 · 13, 25) = 0`.
   - `root = mod_pos(3 - 0, 25) = 3`.
   - `current_mod = 25`.

3. **Ітерація 2 (подвоєння `25 → 625`):**
   - `next_mod = 25² = 625`.
   - `f_val = (3³ - 2) mod 625 = 25`.
   - `df_val = (3 · 3²) mod 625 = 27`.
   - `inv_df = mod_inverse(27, 625) = 394` (бо `27 · 394 = 10638 = 17 · 625 + 1 ≡ 1 (mod 625)`).
   - `delta = mod_pos(25 · 394, 625) = mod_pos(9850, 625) = 475`.
   - `root = mod_pos(3 - 475, 625) = mod_pos(-472, 625) = 153`.
   - `current_mod = 625`.

4. **Результат:** Знайдено корінь `153 (mod 625)`.

## 5. Конвеєр розкладу многочленів на множники (Hensel Factorization Pipeline)

У комп'ютерній алгебрі (CAS) лема Гензеля використовується як фундаментальний міст для розкладання многочленів із цілими коефіцієнтами `f(x) ∈ Z[x]` на незвідні множники.

### Повний конвеєр алгоритму Берлекампа — Цассенгауза:

1. **Зведення до вільного від квадратів многочлена (Square-Free Factorization):**
   Обчислюється найбільший спільний дільник багаточлена та його похідної: `d(x) = gcd(f(x), f'(x))`. Багаточлен ділиться на `d(x)` для усунення кратних множників.

2. **Факторизація в скінченному полі `F_p[x]`:**
   Обирається мале просте число `p`, для якого старший коефіцієнт `f(x)` не ділиться на `p`, а редукція `f(x) mod p` залишається вільною від квадратів. За допомогою швидкого алгоритму Кантора — Цассенгауза знаходять незвідні унітарні множники:
   ```
   f(x) ≡ g₁(x) · h₁(x) (mod p)
   ```

3. **Обчислення межі Міньотта (Mignotte's Bound):**
   Щоб визначити, до якого саме степеня `pᵏ` необхідно піднімати модульні множники, обчислюють теоретичну верхню межу абсолютних значень коефіцієнтів будь-якого справжнього дільника `g(x) | f(x)` у кільці `Z[x]`. За нерівністю Міньотта:
   ```
   ||g||_∞ ≤ C(n, ⌊n/2⌋) · √{n + 1} · ||f||_∞
   ```
   де `||f||_∞ = max |c_i|` — висота багаточлена (найбільший за модулем коефіцієнт). Показник степеня `k` обирається з умови `pᵏ > 2 · B`, де `B` — межа Міньотта.

4. **Підйом розкладу за лемою Гензеля:**
   Розклад `g₁(x) · h₁(x) (mod p)` піднімається до `g_k(x) · h_k(x) (mod pᵏ)`.

5. **Реконструкція цілих коефіцієнтів:**
   Модульні коефіцієнти з напівінтервалу `[0, pᵏ - 1]` переводяться в симетричний цілочисельний діапазон `(-pᵏ/2, pᵏ/2]`. Якщо многочлен `g_k(x)` ділить `f(x)` у кільці `Z[x]`, знайдено справжній дільник.

## 6. Алгоритм поліноміального Безу над скінченним полем (PolyExtGCD)

Для підйому факторизації многочленів фундаментальне значення має обчислення поліноміальної тотожності Безу `α(x) · g(x) + β(x) · h(x) ≡ 1 (mod p)` над скінченним полем `F_p[x]`.

### Механізм поліноміального розширеного алгоритму Евкліда:

1. **Вхідні дані:** Два взаємно прості монічні многочлени `g(x), h(x) ∈ F_p[x]`.
2. **Ініціалізація векторів залишків та коефіцієнтів:**
   ```
   r₀(x) = g(x),   s₀(x) = 1,   t₀(x) = 0
   r₁(x) = h(x),   s₁(x) = 0,   t₁(x) = 1
   ```
3. **Ітераційний цикл ділення многочленів з остачею:**
   Поки `deg(r_i) > 0`:
   - Знаходимо частку `q_i(x)` та остачу `r_{i+1}(x)` такі, що `r_{i-1}(x) = q_i(x) · r_i(x) + r_{i+1}(x)` у полі `F_p[x]`;
   - Оновлюємо коефіцієнти: `s_{i+1}(x) = s_{i-1}(x) - q_i(x) · s_i(x)` та `t_{i+1}(x) = t_{i-1}(x) - q_i(x) · t_i(x)`.
4. **Нормалізація на старший коефіцієнт:**
   На останньому кроці остача `r_m(x) = c ∈ F_p \ {0}` є константою. Помноживши коефіцієнти на `c⁻¹ (mod p)`, отримуємо шукані многочлени:
   ```
   α(x) = s_m(x) · c⁻¹ (mod p),   β(x) = t_m(x) · c⁻¹ (mod p)
   ```
   причому автоматично виконуються обмеження степенів: `deg(α) < deg(h)` та `deg(β) < deg(g)`.

## 7. Оптимізації у промислових математичних бібліотеках (FLINT, NTL, PARI/GP)

У сучасних високопродуктивних бібліотеках комп'ютерної алгебри підйом Гензеля реалізовано з використанням чотирьох передових інженерних оптимізацій:

1. **Підстановка Кронекера (Kronecker Substitution):**
   Многочлени великого ступеня упаковуються у надвеликі цілі числа шляхом підстановки `X = 2^B`, де `B` перевищує максимальну бітову довжину можливих коефіцієнтів добутку. Поліноміальне множення зводиться до єдиного множення довгих чисел за алгоритмом Шьонгаґе — Штрассена або FFT, що зменшує складність до майже лінійної `O(N · log N)`.

2. **Деревоподібний підйом (Tree-Based Multifactor Lifting):**
   При факторизації на багато множників `f ≡ g₁ · g₂ · ... · g_r (mod p)` фактори об'єднують у бінарне дерево: на першому рівні піднімають добуток `(g₁...g_{r/2}) · (g_{r/2+1}...g_r)`, а потім рекурсивно спускаються до листя. Це зменшує загальну кількість поліноміальних множень у рази.

3. **Раннє відсікання (Early Termination Heuristic):**
   Замість очікування досягнення повної межі Міньотта `pᵏ > 2B`, алгоритм на проміжних кроках (наприклад, кожні 16 бітів) перевіряє, чи ділить реконструйований многочлен `g_k(x)` вихідний `f(x)` у `Z[x]`. Для більшості реальних многочленів справжні дільники виявляються задовго до песимістичної теоретичної межі Міньотта.

4. **Монтгомері-арифметика для модульних обчислень:**
   При роботі з фіксованим модулем `M = pᵏ` операції ділення замінюються на множення Монтгомері: перетворення числа у форму `a~ = (a · R) mod M` (де `R = 2⁶⁴` або `2¹²⁸`) дозволяє виконувати модульне множення за допомогою зсувів та бітових масок без використання повільної процесорної інструкції `div`.

## 8. Інтеграція з бібліотеками довгої арифметики (GMP / Boost.Multiprecision)

Для задач криптографії та комп'ютерної алгебри, де модуль `pᵏ` досягає 1024–4096 бітів, стандартних типів `int64_t` та `__int128_t` стає недостатньо. У таких випадках алгоритм підйому Гензеля інтегрують із бібліотеками довгої арифметики:

1. **Використання GNU MP (GMP) у C:**
   Кожна модульна змінна представляється типом `mpz_t`. Модульне інвертування виконується функцією `mpz_invert(inv_v, df, current_mod)`, а оцінка полінома за схемою Горнера здійснюється циклічним викликом `mpz_mul`, `mpz_add` та `mpz_mod`.
2. **Використання `boost::multiprecision::cpp_int` у C++:**
   Завдяки перевантаженню операторів шаблонний клас `HenselSolver<cpp_int>` працює з довільною розрядністю без зміни вихідного алгоритмічного коду:
   ```cpp
   #include <boost/multiprecision/cpp_int.hpp>
   using boost::multiprecision::cpp_int;

   // Підйом кореня многочлена x^2 - 7 до модуля 3^1000 (близько 1585 десяткових знаків)
   std::vector<cpp_int> poly = {-7, 0, 1};
   auto big_root = HenselSolver::lift_quadratic(poly, cpp_int(3), 1000, cpp_int(1));
   ```
3. **Керування пам'яттю у великих циклах:**
   При роботі з `mpz_t` критично уникати повторної ініціалізації (`mpz_init`) всередині циклів підйому. Змінні `p_pow`, `f_val`, `q` ініціалізуються один раз перед початком циклу, що запобігає фрагментації динамічної пам'яті.

## 9. Покроковий розбір підйому факторизації многочлена: x⁴ + 1 (mod 25)

Розглянемо практичний числовий приклад роботи алгоритму факторизації для многочлена `f(x) = x⁴ + 1` над простим числом `p = 5`:

1. **Факторизація в полі F₅:**
   Оскільки `1 ≡ -4 (mod 5)`, маємо `f(x) ≡ x⁴ - 4 = (x² - 2)(x² + 2) (mod 5)`.
   Позначимо `g₁(x) = x² - 2` та `h₁(x) = x² + 2`.

2. **Тотожність Безу:**
   Обчислимо різницю: `h₁(x) - g₁(x) = 4 ≡ -1 (mod 5)`.
   Помноживши на `-1 ≡ 4 (mod 5)`, отримуємо `(-1)·h₁(x) + 1·g₁(x) = 1 (mod 5)`.
   Звідси `α(x) = 1` та `β(x) = 4`.

3. **Обчислення нев'язки за модулем 5² = 25:**
   - Початковий добуток: `g₁(x) · h₁(x) = (x² - 2)(x² + 2) = x⁴ - 4`.
   - Різниця з вихідним поліномом: `f(x) - g₁h₁ = (x⁴ + 1) - (x⁴ - 4) = 5`.
   - Нев'язка: `m₁(x) = 5 / 5 = 1`.

4. **Поправки та підняті множники:**
   - `u(x) ≡ (β(x) · m₁(x)) mod g₁(x) = (4 · 1) mod (x² - 2) = 4`.
   - `v(x) ≡ (α(x) · m₁(x)) mod h₁(x) = (1 · 1) mod (x² + 2) = 1`.
   - Підняті многочлени за модулем 25:
     ```
     g₂(x) = g₁(x) + u(x) · 5 = (x² - 2) + 20 = x² + 18 ≡ x² - 7 (mod 25)
     h₂(x) = h₁(x) + v(x) · 5 = (x² + 2) + 5 = x² + 7 (mod 25)
     ```

5. **Перевірка:** `g₂(x) · h₂(x) = (x² - 7)(x² + 7) = x⁴ - 49 = x⁴ + 1 - 50 ≡ x⁴ + 1 (mod 25)`.
   Розклад піднято абсолютно точно за один крок без жодного варіанту перебору коефіцієнтів.

## 10. Безпека та криптографічний захист від атак сторонніми каналами (Constant-Time Lifting)

У криптографічних застосуваннях (зокрема при знаходженні модульних коренів для приватних ключів у схемах RSA та криптосистемі Рабіна) алгоритм підйому Гензеля має бути захищений від атак за часом виконання (*Timing Attacks*) та енергоспоживанням (*Power Analysis*):

1. **Усунення умовних переходів, що залежать від секретних даних (Branchless Select):**
   Операція вибору між значеннями або коригування від'ємного залишку повинна виконуватися за константний час за допомогою побітових масок:
   ```c
   static inline int64_t ct_select(int64_t mask, int64_t a, int64_t b) {
       return (a & mask) | (b & ~mask);
   }
   ```
2. **Константний час розширеного алгоритму Евкліда:**
   Кількість ітерацій алгоритму інвертування фіксується заздалегідь (наприклад, рівно `2 · ⌈log₂(m)⌉` кроків за алгоритмом Бернштейна — Янга), що повністю унеможливлює витік бітів модуля через час виконання.

Нижче наведено результати вимірювання продуктивності алгоритмів лінійного та квадратичного підйому на процесорі x86-64 (AVX2, GCC 13, прапор `-O3`):

## 12. Крайові випадки та діагностика типових помилок

При розробці та експлуатації алгоритмів підйому Гензеля виникають чотири типові крайові ситуації:

1. **Вироджений корінь (`f'(r₁) ≡ 0 (mod p)`):**
   Виникає, коли корінь є кратним або розгалуженим. Звичайна лема Гензеля завершується відхиленням. Для таких коренів необхідно перевіряти умову нормування `v_p(f(r₁)) ≥ 2 · v_p(f'(r₁)) + 1` та застосовувати узагальнений підйом.

2. **Немонічні багаточлени (`c_n ≠ 1`):**
   Якщо старший коефіцієнт багаточлена `c_n` не дорівнює одиниці, підйом факторів вимагає попередньої заміни змінної: многочлен домножують на `c_n^{n-1}` і виконують підстановку `y = c_n · x`, перетворюючи `f(x)` на унітарний многочлен відносно `y`.

3. **Паразитні фактори (Swinnerton-Dyer Polynomials):**
   Деякі многочлени (наприклад, многочлени Свіннертона — Даєра `∏ (x ± √2 ± √3 ± √5)`) є незвідними в `Z[x]`, але розпадаються на лінійні та квадратичні множники за будь-яким простим модулем `p`. У таких випадках окремі підняті множники не є дільниками в `Z[x]`, і алгоритм повинен комбінувати підняті множники по групах (підбір підмножин), щоб знайти справжні незвідні компоненти.

4. **Переповнення знакового типу при обчисленні `p_next = p_pow * p`:**
   При досягненні `p_pow > INT64_MAX / p` множення призводить до невизначеної поведінки (UB). У production-коді перед множенням обов'язково виконують перевірку переповнення або переходять на модульні операції без зміни базового типу.
