# 📋 Порівняльний довідник моделей цілочислового ділення у мовах програмування та архітектурах систем

Цей довідковий матеріал містить систематизовані порівняльні таблиці моделей цілочислового ділення, операторів остачі, апаратних інструкцій CPU та механізмів обробки виняткових ситуацій у мовах програмування та системних архітектурах. Довідник слугує практичним керманичем під час міжмовної інтеграції, портування системного коду та розробки міжплатформних обчислювальних бібліотек.

## Поняття моделей цілочислового ділення та їхня класифікація

У сучасній розробці програмного забезпечення використовуються три основні математичні моделі ділення цілих чисел зі остачею: усічене ділення, ділення за підлогою та евклідове ділення. Будь-яка модель цілочислового ділення для діленого `a` та дільника `b` зобов’язана задовольняти фундаментальне співвідношення диз'юнктного розкладу:

```
a = q · b + r
```

де `q` — ціла частка, а `r` — ціла остача. Оскільки для нецілого відношення `a / b` існує нескінченна множина пар `(q, r)`, що задовольняють це рівняння, кожна модель ділення фіксує власне функціональне правило округлення частки `q`:

1. **Усічене ділення** (англ. *Truncated division*): частка округлюється вбік нуля `q = trunc(a / b)`. Остача `r` обчислюється як `r = a - q · b` і завжди має той самий знак, що й ділене `a` (або дорівнює нулю). Ця модель є стандартом для більшості системних мов програмування (C99, C++, Rust, Java), оскільки вона прямо відповідає апаратним інструкціям процесорів x86 та ARM.
2. **Ділення за підлогою** (англ. *Floored division*): частка округлюється вбік мінус нескінченності `q = ⌊a / b⌋`. Остача `r` завжди має той самий знак, що й дільник `b` (або дорівнює нулю). Ця модель збережена у мовах Python, Julia та Lua, оскільки вона забезпечує строгу циклічну періодичність остачі незалежно від знака діленого.
3. **Евклідове ділення** (англ. *Euclidean division*): остача `r` задовольняє строгу нерівність `0 ≤ r < |b|` для будь-якого операнда `a`. Частка `q` дорівнює `⌊a / b⌋`, якщо `b > 0`, і `⌈a / b⌉`, якщо `b < 0`. Ця модель є найзручнішою для теорії чисел, алгебраїчних структур та криптографії, оскільки класи лишків за модулем `b` утворюють стандартизовану множину `{0, 1, …, |b| - 1}`.

## Деталізований аналіз специфікацій мов програмування

### 1. Мови сімейства C та C++ (C99, C11, C23, C++11, C++20, C++23)
До стандартів C99 та C++11 ділення від'ємних цілих чисел у мовах C (K&R C, C89) та C++ (C++98) залишалося залежним від реалізації компілятора (англ. *implementation-defined behavior*). Компілятори для мейнфреймів або спеціалізованих ДСП містили варіанти з діленням за підлогою.

Починаючи зі стандарту **ISO/IEC 9899:1999 (C99)** та **ISO/IEC 14882:2011 (C++11)**, мовна специфікація строго зафіксувала:
- Оператор `/` для цілочислових операндів виконує алгебраїчне усіхнення дробової частини вбік нуля (`truncation toward zero`).
- Оператор `%` задовольняє сувору мовну тотожність `(a / b) * b + (a % b) == a`.

Звідси прямо випливає, що знак остачі `a % b` завжди збігається зі знаком діленого `a` (якщо остача не нульова).

Числові приклади усіхчення у C99/C++11:
- `-7 / 3 == -2` та `-7 % 3 == -1` (оскільки `-2 * 3 + (-1) == -7`).
- `7 / -3 == -2` та `7 % -3 == 1` (оскільки `-2 * -3 + 1 == 7`).
- `-7 / -3 == 2` та `-7 % -3 == -1` (оскільки `2 * -3 + (-1) == -7`).

У стандартах C++20 та C23 також зафіксовано, що зсув від'ємного знакового числа праворуч `a >> k` виконує саме арифметичний зсув (із заповненням старших бітів знаковим бітом), що математично еквівалентно діленню за підлогою `⌊a / 2^k⌋`.

Для одночасного отримання частки та остачі за один виклик стандартна бібліотека C надає функції `div()`, `ldiv()`, `lldiv()`, `imaxdiv()`, що повертають структури `div_t`, `ldiv_t`, `lldiv_t`, `imaxdiv_t`. Поля цих структур `quot` та `rem` обчислюються в єдиному апаратному циклі. Заголовки POSIX та C99 вимагають використання цих функцій, коли обидва значення потрібні одночасно. Комп’ютерні ABI (System V AMD64 ABI та Windows x64 ABI) оптимізують такі повернення, передаючи структури через паралельні регістри `RAX` (частка) та `RDX` (остача).

### 2. Мова Python (Python 2.2+, Python 3)
Творець Python Ґвідо ван Россум прийняв рішення використовувати ділення за підлогою для цілочислового оператора `//` та відповідний йому оператор остачі `%`.

Головна причина полягала у збереженні математичної неперервності при перетині нуля. Наприклад, якщо ми перераховуємо індекс часової мітки у секундах до хвилин, додатний часовий проміжок `0..59` секунд належить хвилині `0`. Усічене ділення віднесла б від'ємний проміжок `-59..-1` секунд також до хвилини `0`, що створило б аномальну розширену нульову хвилину тривалістю 120 секунд. Натомість ділення за підлогою Python відносить `-59..-1` секунд до хвилини `-1`, забезпечуючи рівні 60-секундні інтервали вздовж всієї числової осі.

Приклади поведінки у Python 3:
- `-7 // 3 == -3` та `-7 % 3 == 2` (оскільки `-3 * 3 + 2 == -7`).
- `7 // -3 == -3` та `7 % -3 == -2` (оскільки `-3 * -3 + (-2) == 7`).

### 3. Мова Rust
Мова системного програмування Rust наслідує високу швидкодію C/C++ для базових операторів `/` та `%`, за замовчуванням виконуючи усіхнене ділення. Однак стандартна бібліотека `std` надає явні, високопродуктивні методи для обчислення евклідового ділення:
- `a.div_euclid(b)` — повертає евклідову частку.
- `a.rem_euclid(b)` — повертає строго невід'ємну евклідову остачу `0 ≤ r < |b|`.

Це дозволяє розробникам Rust поєднувати максимальну апаратну швидкість оператора `/` у системному коді з математичною строгістю методів `euclid` у теорії чисел.

### 4. Мова Java та віртуальна машина JVM

У специфікації віртуальної машини Java (англ. *Java Virtual Machine Specification*) базові байткод-інструкції цілочислового ділення `idiv` (для 32-бітних `int`) та `ldiv` (для 64-бітних `long`), а також інструкції остачі `irem` та `lrem` реалізують виключно **усічене ділення** (Truncated Division).

Особливості платформи Java:
- Спроба ділення на нуль `a / 0` для цілих типів завжди викликає виняток часу виконання `java.lang.ArithmeticException: / by zero`.
- Переповнення діапазону `Integer.MIN_VALUE / -1` не викликає винятку і не призводить до аварії: байткод `idiv` тихо повертає значення `Integer.MIN_VALUE` (оскільки `-2147483648 / -1 = -2147483648` у 32-бітній арифметиці переповнення).
- До версії Java 8 мова не мала підтримки беззнакового ділення та ділення за підлогою.
- Починаючи з Java 8 (JSR 335), стандартний клас `java.lang.Math` отримав спеціалізовані методи для роботи з моделлю підлоги та беззнаковими числами:
  - `Math.floorDiv(x, y)`: повертає частку ділення за підлогою `⌊x / y⌋`. Наприклад, `Math.floorDiv(-7, 3)` повертає `-3`.
  - `Math.floorMod(x, y)`: повертає модульну остачу зі знаком дільника `y`. Наприклад, `Math.floorMod(-7, 3)` повертає `2`.
  - `Integer.divideUnsigned(x, y)` та `Integer.remainderUnsigned(x, y)`: інтерпретують бітові послідовності аргументів як беззнакові 32-бітні цілі числа і виконують ділення без знака.

### 5. Мова JavaScript та середовища ECMAScript

У мові JavaScript семантика операцій ділення має унікальну специфіку через подвійну природу числових типів:

1. **Тип `Number` (64-бітне дійсне число подвійної точності IEEE 754):**
   - Усі арифметичні оператори за замовчуванням працюють з числами з плаваючою крапкою. Вираз `7 / 3` повертає `2.3333333333333335`, а не ціле число.
   - Ділення на нуль не викликає винятку: `7 / 0` повертає `Infinity`, `-7 / 0` повертає `-Infinity`, а `0 / 0` повертає `NaN`.
   - Оператор остачі `%` для `Number` виконує усічену остачу за стандартом IEEE 754: `-7 % 3` дає `-1`.
   - Для отримання цілої частки розробники використовують `Math.trunc(a / b)` (усічення до нуля) або `Math.floor(a / b)` (підлога).
   - Побітове «або з нулем» `(a / b) | 0` примусово перетворює результат на 32-бітне ціле зі знаком (Int32) з округленням до нуля, проте цей метод обмежує діапазон до `[-2³¹, 2³¹ - 1]`.

2. **Тип `BigInt` (цілі числа довільної точності, стандарт ES2020):**
   - Оператор `/` для `BigInt` виконує строго цілочислове **усічене ділення**: `7n / 3n === 2n`, `-7n / 3n === -2n`.
   - Оператор `%` повертає усічену остачу зі знаком діленого: `-7n % 3n === -1n`.
   - Ділення на нуль `7n / 0n` викликає виняток `RangeError: Division by zero`.
   - Переповнення для `BigInt` неможливе, тому `(-2147483648n) / -1n` повертає точне додатне значення `2147483648n`.

### 6. Мова C# та платформа .NET CLR

Платформа .NET на рівні проміжної мови CIL (Common Intermediate Language) надає інструкції `div` (знакове ділення), `div.un` (беззнакове ділення), `rem` (знакова остача) та `rem.un` (беззнакова остача):
- Оператори `/` та `%` у C# реалізують усічене ділення C-стилю.
- Обробка переповнення `int.MinValue / -1` залежить від прапорця компіляції або блоку `checked` / `unchecked`:
  - У контексті `unchecked` (за замовчуванням для більшості проєктів) переповнення ігнорується, повертаючи `int.MinValue`.
  - У контексті `checked` середовище виконання генерує виняток `System.OverflowException: Arithmetic operation resulted in an overflow`.
- Ділення на нуль цілих типів завжди викликає виняток `System.DivideByZeroException`.
- Статичний метод `Math.DivRem(a, b, out remainder)` обчислює частку та остачу одночасно, дозволяючи JIT-компілятору оптимізувати операцію в одну інструкцію `IDIV` на архітектурах x86-64.

### 7. Мови Go та Swift

1. **Мова Go:**
   - Специфікація мови Go (The Go Programming Language Specification) фіксує усічене ділення для цілих операндів.
   - Ділення на цілочисловий нуль під час виконання викликає паніку середовища `panic: runtime error: integer divide by zero`.
   - Для константних виразів ділення на нуль (`const x = 5 / 0`) призводить до помилки компіляції ще на етапі синтаксичного аналізу.

2. **Мова Swift:**
   - Мова Swift орієнтована на максимальну арифметичну безпеку (англ. *arithmetic safety*).
   - За замовчуванням оператор `/` виконує усічене ділення, але будь-яке ділення на нуль або переповнення `Int.min / -1` призводить до негайної фатальної аварії середовища (англ. *fatal runtime error / trap*).
   - Для контрольованої обробки переповнень протокол `BinaryInteger` містить методи з поверненням звіту: `a.dividedReportingOverflow(by: b)` та `a.remainderReportingOverflow(dividingBy: b)`, які повертають кортеж `(partialValue, overflow)`.

### 8. Наукові, функційні та скриптові мови (Julia, Haskell, Ada, Erlang, Ruby, Lua)

У мовах, орієнтованих на алгебраїчні структури та числове моделювання, надаються симетричні пари функцій:
- У **Julia**: матриця операцій охоплює `div(a, b)` (усічення), `fld(a, b)` (підлога), `cld(a, b)` (стеля), `rem(a, b)` (усічена остача зі знаком діленого) та `mod(a, b)` (підлогова остача зі знаком дільника). Також підтримується оператор дробового ділення `//` для точної раціональної арифметики.
- У **Haskell**: функції стандартного модуля `Prelude` розділені за принципом: `quot` та `rem` виконують усічене ділення (Truncated), тоді як `div` та `mod` реалізують ділення за підлогою (Floored).
- У **Ada**: мова розрізняє оператор `rem` (залишок згідно з усіченою моделлю C99) та оператор `mod` (модуль згідно зі строгою евклідовою моделлю, де остача завжди невід'ємна для додатного модуля).
- У **Ruby**: оператор цілочислового ділення `/` реалізує ділення за підлогою (`-7 / 3 == -3`), тоді як метод `.remainder(b)` обчислює усічену остачу C-стилю.
- У **Lua**: починаючи з версії Lua 5.3 з підтримкою цілих чисел, оператор `//` реалізує ділення за підлогою, а оператор `%` повертає відповідну підлогову остачу зі знаком дільника.

## Операнди WebAssembly (WASM) та байткод-віртуальні машини

У стек-орієнтованому байткоді WebAssembly специфікація W3C розрізняє знакові та беззнакові інструкції цілочислового ділення на рівні двійкових опкодів:

1. `i32.div_s` / `i64.div_s`: виконують **знакове усічене ділення** (Truncated Division) для 32-бітних та 64-бітних цілих чисел.
2. `i32.div_u` / `i64.div_u`: виконують беззнакове цілочислове ділення.
3. `i32.rem_s` / `i64.rem_s`: обчислюють знакову остачу усіхченого ділення зі знаком діленого.
4. `i32.rem_u` / `i64.rem_u`: обчислюють беззнакову остачу.

Якщо операнд дільника дорівнює `0`, будь-яка з цих інструкцій WebAssembly викликає миттєву пастку середовища виконання (англ. *unreachable trap*), перериваючи виконання модуля WASM.

## Особливості обчислень у базах даних та мовах запитів (SQL)

У системах управління базами даних (СУБД) операції цілочислового ділення та обчислення остачі відіграють ключову роль при партиціонуванні таблиць, групуванні часових рядів та обчисленні хеш-індексів:

1. **PostgreSQL:**
   - Оператор `/` для цілочислових типів (`integer`, `bigint`) виконує **усічене ділення** (C-стиль).
   - Функція `div(y, x)` повертає усіхнену частку.
   - Оператор `%` або функція `mod(y, x)` повертає остачу зі знаком діленого `y`. Для отримання евклідової невід'ємної остачі в SQL використовується вираз `((y % x) + x) % x`.

2. **MySQL / MariaDB:**
   - Оператор `/` за замовчуванням виконує ділення у плаваючій крапці з поверненням типу `DECIMAL` або `DOUBLE`.
   - Оператор `DIV` реалізує **цілочислове усічене ділення** (наприклад, `-7 DIV 3 == -2`).
   - Оператор `%` або `MOD` повертає усіхнену остачу зі знаком діленого (`-7 MOD 3 == -1`).

3. **SQLite:**
   - Оператор `/` виконує цілочислове ділення, якщо обидва операнди є цілими числами, із усіченням до нуля.
   - Оператор `%` повертає остачу зі знаком лівого операнда.

4. **Oracle Database:**
   - Функція `TRUNC(a / b)` повертає усіхнену частку.
   - Функція `MOD(a, b)` повертає остачу, обчислену за моделью усічення `a - b * TRUNC(a / b)`.
   - Функція `REMAINDER(a, b)` обчислює остачу за стандартом IEEE 754 (з округленням до найближчого цілого).

## Шейдерні мови графічних процесорів (HLSL, GLSL, MSL, SPIR-V)

Під час виконання обчислень на графічних процесорах (GPU) у шейдерах обробки текстур, воксельних сіток та трасування променів моделі ділення мають свої синтаксичні та апаратні особливості:

1. **GLSL (OpenGL Shading Language / Vulkan):**
   - Оператори `/` та `%` для цілочислових векторів (`ivec2`, `ivec3`, `ivec4`) виконують усіхнене ділення C-стилю.
   - Вбудована функція `floor(x)` працює з векторами з плаваючою крапкою (`vec4`) і повертає математичну підлогу.
   - Вбудована функція `mod(x, y)` для `vec4` обчислюється за формулою ділення за підлогою: `x - y * floor(x / y)`. Отже, `mod()` у GLSL реалізує саме підлогову модель Python, а не усічену модель C!

2. **HLSL (High-Level Shader Language / Direct3D):**
   - Оператор `/` для `int4` виконує усіхнене ділення.
   - Вбудована функція `fmod(x, y)` реалізує усічену остачу C-стилю `x - y * trunc(x / y)`.

3. **SPIR-V (Standard Portable Intermediate Representation):**
   - Проміжне представлення Vulkan містить окремі опкоди `OpSDiv` (усічене ділення) та `OpSRem` (усічена остача), а також `OpSMod` (підлогова остача).

## Специфікація апаратних інструкцій процесорних архітектур

Кожна процесорна архітектура визначає свій набір інструкцій АЛУ для ділення знакових цілих чисел (англ. *Signed Division*). Нижче наведено зведену таблицю характеристик для 5 провідних апаратних платформ:

| Архітектура (ISA) | Інструкції ділення (Signed) | Режими округлення АЛУ | Регістри операндів / результату | Обробка ділення на 0 | Обробка переповнення (`MIN / -1`) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **x86 / x86-64** | `IDIV r/m32` (32-bit)<br>`IDIV r/m64` (64-bit) | Усічення до нуля (Truncated) | Ділене: `EDX:EAX`<br>Частка: `EAX`, Остача: `EDX` | Апаратне переривання `#DE` (сигнал `SIGFPE`) | Апаратне переривання `#DE` (сигнал `SIGFPE`) |
| **ARM64 (AArch64)** | `SDIV Xd, Xn, Xm`<br>`MSUB Xd, Xn, Xm, Xa` | Усічення до нуля (Truncated) | Окремі 64-бітні регістри загального призначення | Повертає `0` у цільовий регістр (без винятку) | Повертає `INT64_MIN` у регістр (без винятку) |
| **RISC-V (RV32I/64I)** | `DIV d, a, b` (частка)<br>`REM d, a, b` (остача) | Усічення до нуля (Truncated) | Окремі регістри `x1..x31` для частки та остачі | Повертає `-1` для частки, `a` для остачі | Повертає `INT_MIN` для частки, `0` для остачі |
| **MIPS32 / MIPS64** | `DIV rs, rt`<br>`MFHI rd` / `MFLO rd` | Усічення до нуля (Truncated) | Окремі регістри спецпризначення `HI` (остача) та `LO` (частка) | Записує невизначене значення у `HI/LO`, виняток перевіряється програмно | Записує переповнене значення у `LO`, виняток перевіряється програмно |
| **WebAssembly (WASM)** | `i32.div_s`, `i64.div_s`<br>`i32.rem_s`, `i64.rem_s` | Усічення до нуля (Truncated) | Стек виразів WASM | Пастка середовища виконання (англ. *runtime trap*) | Пастка середовища виконання (англ. *runtime trap*) |

### Особливості апаратного виконання інструкцій CPU

#### 1. Архітектура x86-64
Інструкція `IDIV` є спареною операцією: вона одночасно обчислює частку та остачу за один процесорний цикл обчислення.

Для 32-бітного ділення ділене має бути знаково розширене у 64-бітну пару регістрів `EDX:EAX` за допомогою інструкції `CDQ` (англ. *Convert Doubleword to Quadword*). Якщо перед виконанням `IDIV` регістр `EDX` не заповнений знаковим бітом `EAX`, виникає помилка хибної остачі або хибне апаратне переривання `#DE`.

Приклад ассемблерного коду x86-64 для ділення `a / b`:
```assembly
mov eax, dword ptr [rbp-4]  ; Завантажуємо ділене a у EAX
cdq                         ; Знаково розширюємо EAX у EDX:EAX (EDX отримує старший біт)
idiv dword ptr [rbp-8]      ; Виконуємо IDIV: EAX = a / b (усічення), EDX = a % b
```

Процесорний прапор заповнення `OF` (Overflow Flag) та `CF` (Carry Flag) встановлюються у невизначений стан після `IDIV`.

#### 2. Архітектура ARM64 (AArch64)
На відміну від x86, архітектура ARM64 розділяє ділення та обчислення остачі на дві незалежні інструкції:
- Інструкція `SDIV Xd, Xn, Xm` обчислює лише частку `Xd = Xn / Xm`.
- Для обчислення остачі використовується інструкція помножити-відняти `MSUB Xr, Xq, Xm, Xn`, яка обчислює `Xr = Xn - Xq * Xm`.

Приклад ассемблерного коду ARM64:
```assembly
sdiv x2, x0, x1             ; x2 = x0 / x1 (усічена частка)
msub x3, x2, x1, x0         ; x3 = x0 - (x2 * x1) = x0 % x1 (остача)
```

Крім того, ARM64 **ніколи не ґенерує апаратних винятків** при діленні на нуль або переповненні `INT64_MIN / -1`, замість цього записуючи у цільовий регістр зафіксовані специфікацією константи. Це вимагає від компіляторів C/C++ вставляти умовні перевірки перед інструкцією `SDIV`, якщо мовний стандарт вимагає генерації сигналів.

#### 3. Архітектура RISC-V
Специфікація RISC-V розширила підхід ARM64, зробивши обробку крайніх випадків повністю безтраповою (англ. *trap-free*):
- `DIV(a, 0) == -1`
- `REM(a, 0) == a`
- `DIV(INT_MIN, -1) == INT_MIN`
- `REM(INT_MIN, -1) == 0`

Це позбавляє процесорний конвеєр RISC-V від необхідності перевіряти прапори переповнення на етапі виконання ділення.

## Взаємодія з плаваючою крапкою стандарта IEEE 754

Під час роботи з дійсними числами одинарної та подвійної точності (`float` та `double`) стандарт IEEE 754 визначає чотири режими округлення цілої частини, які реалізуються у системних математичних бібліотеках C/C++ (`<math.h>` / `<cmath>`):

1. `floor(x)`: обчислює `⌊x⌋` (підлога, округлення вбік `-∞`).
2. `ceil(x)`: обчислює `⌈x⌉` (стеля, округлення вбік `+∞`).
3. `trunc(x)`: обчислює `trunc(x)` (усічення, округлення вбік `0`).
4. `round(x)`: округлення до найближчого цілого (напівцілі значення округлюються від нуля).
5. `rint(x)` / `nearbyint(x)`: округлення до найближчого цілого згідно з поточним режимом FPU (англ. *banker's rounding*, округлення до найближчого парного).

Для ділення чисел із плаваючою крапкою стандарт IEEE 754 надає дві окремі функції остачі:
- `fmod(x, y)`: повертає остачу усіченого ділення `x - trunc(x / y) * y`, де остача має знак `x`.
- `remainder(x, y)`: повертає остачу від ділення до найближчого цілого `x - n * y`, де `n` — найближче ціле до `x / y`.

## Компіляторні оптимізації та векторизація цілочислового ділення в LLVM та GCC

Оскільки інструкція апаратного ділення (`IDIV` на x86 або `SDIV` на ARM) потребує від 10 до 45 процесорних тактів і блокує апаратний конвеєр виконання, оптимізувальні компілятори (LLVM/Clang, GCC, MSVC) застосовують багаторівневу систему перетворень.

### Проміжне представлення LLVM IR

У компіляторній інфраструктурі LLVM операції цілочислового ділення представлені чотирма базовими інструкціями SSA-форми:
- `sdiv <type> %a, %b`: знакова частка усіченого ділення (Signed Truncated Division).
- `udiv <type> %a, %b`: беззнакова частка ділення.
- `srem <type> %a, %b`: знакова остача усіченого ділення (знак збігається зі знаком діленого `%a`).
- `urem <type> %a, %b`: беззнакова остача.

Інструкції ділення можуть містити спеціальний прапорець `exact` (наприклад, `sdiv exact i32 %a, %b`). Цей прапорець повідомляє оптимізатору, що ділене `%a` ділиться на дільник `%b` без остачі (`%a % %b == 0`). Наявність `exact` дозволяє оптимізатору замінити операцію ділення на звичайний арифметичний зсув праворуч або множення на модульне обернене значення, що є значно швидшим.

### Заміна ділення на константу множенням на зворотне число (Reciprocal Multiplication)

Під час оптимізації виразів ділення на константний дільник `d` (наприклад, `x / 10`) фази `InstCombine` та `SelectionDAG` замінюють інструкцію `sdiv` або `udiv` на послідовність з трьох швидких операцій:
1. Множення діленого на попередньо обчислену цілочислову константу `M` у розширеній розрядній сітці (інструкція `IMUL` або `MUL`).
2. Вилучення старших бітів добутку (висока половина регістрової пари).
3. Арифметичний або логічний зсув праворуч на фіксовану кількість бітів `s`.

Це скорочує час виконання операції з 25–40 тактів до 3–4 тактів, а також дозволяє процесору виконувати інші інструкції паралельно завдяки позачерговому виконанню (англ. *out-of-order execution*).

### Проблема векторизації (SIMD)

Сучасні векторні набори інструкцій процесорів x86 (SSE2, AVX2, AVX-512) та ARM (NEON, SVE) **не містять векторних інструкцій цілочислового ділення** над векторами типу `__m256i` чи `int32x4_t`.

Причина полягає в апаратній складності: один апаратний дільник Radix-4 чи Radix-8 SRT вимагає значної площі кремнієвого кристала та високого енергоспоживання. Розміщення 8 або 16 незалежних апаратних дільників у кожному 512-бітному векторному конвеєрі зробило б кристал процесора надмірно гарячим і дорогим.

Для векторизації циклів з цілочисловим діленням застосовують два підходи:
1. **Векторне множення на зворотні константи (Бібліотека `libdivide`):**
   Якщо дільник однаковий для всіх елементів масиву, для нього попередньо генерується вектор магічних множників `M`, після чого ділення 8 цілих чисел одночасно виконується через пару інструкцій `_mm256_mul_epu32` та `_mm256_srli_epi64`.
2. **Конвертація у векторні дійсні числа:**
   Якщо дільники є змінними для кожного елемента вектора, цілі числа перетворюють у формат одинарної точності `float` (`_mm256_cvtepi32_ps`), виконують векторне ділення з плаваючою крапкою `_mm256_div_ps` (яке апаратно підтримується векторними FPU), а потім повертають результат назад у цілі числа з усіченням (`_mm256_cvttps_epi32`). Цей метод обмежений діапазоном 24 бітів мантиси `float` (цілі числа до `16 777 216` діляться абсолютно точно).

## Формальні математичні співвідношення та формули взаємного перетворення моделей

Для реалізації міжмовної взаємодії між модулями C++, Python та Rust наведено точні алгебраїчні формули взаємного перетворення між трьома моделями ділення.

Позначимо через `q_t, r_t` частку та остачу усіченого ділення (C99, Rust, Java), через `q_f, r_f` — частку та остачу ділення за підлогою (Python, Lua), а через `q_e, r_e` — частку та остачу евклідового ділення.

Фундаментальні співвідношення між моделями:

```
[Усічене до Підлоги]
q_f = q_t - 1,    якщо r_t ≠ 0 та sgn(a) ≠ sgn(b)
q_f = q_t,        в усіх інших випадках

r_f = r_t + b,    якщо r_t ≠ 0 та sgn(a) ≠ sgn(b)
r_f = r_t,        в усіх інших випадках
```

```
[Усічене до Евклідового]
q_e = q_t - 1,    якщо r_t < 0 та b > 0
q_e = q_t + 1,    якщо r_t < 0 та b < 0
q_e = q_t,        якщо r_t ≥ 0

r_e = r_t + |b|,  якщо r_t < 0
r_e = r_t,        якщо r_t ≥ 0
```

```
[Підлога до Евклідового]
q_e = q_f,        якщо b > 0
q_e = q_f + 1,    якщо b < 0 та r_f ≠ 0
q_e = q_f,        якщо b < 0 та r_f = 0

r_e = r_f,        якщо b > 0
r_e = r_f - b,    якщо b < 0 та r_f ≠ 0
r_e = 0,          якщо b < 0 та r_f = 0
```

### Збереження періодичності в кільцях лишків

Математична перевага підлогової та евклідової моделей полягає у збереженні алгебраїчного гомоморфізму при відображенні цілих чисел `ℤ` у кільце лишків `ℤ / mℤ` для додатного модуля `m > 0`.

Для будь-якого цілого `a` евклідова остача `r_e` задовольняє умову:

```
0 ≤ r_e < m
```

Це означає, що при послідовному зменшенні координати `a` значення остачі циклічно повторює послідовність `m-1, m-2, …, 1, 0, m-1, …` без будь-яких стрибків або розширень нульового інтервалу. На противагу цьому, усічена остача `r_t` у точці `a = 0` містить розрив симетрії, повертаючи від'ємні значення `-1, -2, …` ліворуч від нуля, що руйнує кільцеву періодичність.

1. **Для системного програмування на C/C++:**
   Перед виконанням операторів `/` та `%` із динамічними даними завжди додавайте перевірки `is_safe_division()`.

2. **Для міжмовного портування коду (C++ ↔ Python):**
   Пам'ятайте, що вираз `a % b` у C++ для від'ємного `a` поверне від'ємне число, а у Python — додатне. Для портування коду Python у C++ використовуйте функцію `floor_div()` або `((a % b) + b) % b` для додатного дільника `b > 0`.

3. **Для низькорівневих бітових зсувів:**
   Ніколи не виконуйте зсув `a >> k` на величину `k`, що дорівнює або перевищує розмір розрядної сітки типу (32 або 64 біти). Завжди застосовуйте явну маску: `k & 31` або `k & 63`. Перевіряйте специфікацію ABI для цільової архітектури перед векторизацією цілочислового ділення у низькорівневих модулях.
