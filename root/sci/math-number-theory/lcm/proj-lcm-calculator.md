# Проєкт: Безпечний калькулятор НСК для великих наборів даних

## 1. Постановка проблеми (Problem Statement)

У сучасному програмуванні обробка великих масивів даних часто вимагає знаходження періодичності або спільного знаменника для багатьох різнорідних подій. Наприклад, у системах реального часу, коли різні процеси мають власні цикли оновлення (наприклад, 30 мс, 42 мс і 54 мс), планувальнику операційної системи необхідно знати глобальний цикл, через який всі ці процеси знову синхронізуються. Математично це завдання зводиться до обчислення Найменшого спільного кратного (НСК) для великого масиву чисел.

Проте, наївна реалізація алгоритму НСК стикається з критичною проблемою: **цілочисельне переповнення (Integer Overflow)**. Навіть якщо вхідні числа невеликі, їхній добуток може легко перевищити максимальне значення, яке може зберігатися у стандартних 32-бітних або 64-бітних типах даних. Якщо ми спробуємо обчислити НСК для масиву `{1000000, 2000000, 3000000}` за допомогою класичної формули `(a * b) / gcd(a, b)`, проміжний добуток `1000000 * 2000000` дасть `2000000000000`, що вже викличе переповнення 32-бітного цілого числа. Результатом стане некоректне, часто від'ємне значення, що призведе до краху логіки всієї програми. 

Мета цього проєкту — розробити надійний, промисловий скрипт мовою C++17, який безпечно обчислює НСК для масивів чисел, запобігаючи проміжному переповненню та коректно обробляючи крайові випадки (наприклад, масиви з нулями або порожні масиви).

## 2. Архітектурна логіка алгоритму

Алгоритм базується на двох ключових стовпах: безпечній формулі обчислення НСК для пари чисел та принципі асоціативності для розширення на масиви.

**Безпечна формула:**
Математична рівність `a · b = gcd(a, b) · lcm(a, b)` дає нам базову формулу `lcm = (a · b) / gcd`. Щоб уникнути переповнення на етапі `a · b`, ми користуємося властивістю асоціативності множення та ділення. Оскільки `gcd(a, b)` гарантовано є дільником числа `a`, то операція `a / gcd(a, b)` завжди дає ціле число і виконується без остачі. Тому ми трансформуємо алгоритм у такий вигляд:
`lcm(a, b) = (a / gcd(a, b)) · b`. 
Ця проста перестановка операцій гарантує, що проміжне значення ніколи не буде більшим за кінцеве НСК, що кардинально знижує ризик переповнення.

**Асоціативність для масивів:**
НСК має властивість асоціативності: `lcm(a, b, c) = lcm(lcm(a, b), c)`. Це дозволяє нам використовувати шаблон проєктування "Згортка" (Reduce / Fold). Ми ініціалізуємо акумулятор першим елементом масиву, а потім ітеративно оновлюємо його, застосовуючи функцію парного НСК до акумулятора та кожного наступного елемента масиву.

## 3. Крок за кроком: розбір коду (Step-by-step Breakdown)

Реалізація складається з двох основних функцій: низькорівневої безпечної операції та високорівневої обгортки для обробки колекцій. Ми використовуємо стандартну бібліотеку `<numeric>`, яка починаючи з C++17 надає оптимізовану та надійну функцію `std::gcd`.

```cpp
#include <iostream>
#include <vector>
#include <numeric>
#include <cmath>

// 1. Компонент безпечного НСК для пари
long long safe_lcm(long long a, long long b) {
    // Крайовий випадок 1: захист від ділення на нуль
    if (a == 0 || b == 0) {
        return 0;
    }
    
    // Крайовий випадок 2: нормалізація від'ємних чисел
    // НСК за визначенням є додатним числом
    a = std::abs(a);
    b = std::abs(b);
    
    // Ядро алгоритму: ділення передує множенню
    return (a / std::gcd(a, b)) * b;
}

// 2. Компонент згортки для масиву
long long array_lcm(const std::vector<long long>& numbers) {
    // Захист від порожнього вводу
    if (numbers.empty()) {
        return 0;
    }
    
    long long result = numbers[0];
    
    for (size_t i = 1; i < numbers.size(); ++i) {
        // Оптимізація раннього виходу (Early Exit)
        if (result == 0) {
            break;
        }
        result = safe_lcm(result, numbers[i]);
    }
    
    return result;
}
```

Давайте детально розглянемо 5-компонентну структуру захисту в цьому коді:
1. **Превентивний захист від ділення на нуль:** Якщо `a` або `b` дорівнює 0, їхнє НСК логічно дорівнює нулю. Ми повертаємо 0 миттєво. Якби ми цього не зробили, виклик `std::gcd` міг би відпрацювати, але наступні операції могли б призвести до помилок.
2. **Очищення від знаків:** Оператор `std::abs` гарантує, що результат завжди буде строгим натуральним числом, навіть якщо вхідний масив містив від'ємні зміщення.
3. **Запобігання переповненню (Core Security):** Вираз `(a / std::gcd(a, b)) * b` виконує зменшення операнда `a` *до* того, як він буде помножений на `b`.
4. **Обробка порожнього масиву:** Функція `array_lcm` відразу перевіряє `.empty()`, захищаючи від помилок сегментації (segfault) при спробі доступу до `numbers[0]`.
5. **Ранній вихід (Short-circuit Evaluation):** У циклі ми перевіряємо `if (result == 0)`. Якщо на якомусь етапі ми зустріли число 0, НСК всього масиву автоматично стає 0. Продовжувати цикл і викликати обчислення НСД для решти мільйона елементів — це безглузда трата ресурсів процесора. Завдяки цій оптимізації ми економимо час.

## 4. Аналіз складності (I/O Complexity Analysis)

Аналіз нашого скрипту демонструє високу ефективність алгоритму як щодо використання часу, так і пам'яті.

**Часова складність (Time Complexity):**
Обчислення найбільшого спільного дільника `std::gcd(a, b)` реалізоване через алгоритм Евкліда, який працює за логарифмічний час: О(log(min(a, b))). 
Якщо розмір вхідного масиву дорівнює `N`, ми виконуємо операцію `safe_lcm` рівно `N - 1` разів. Таким чином, загальна найгірша часова складність становить **О(N · log M)**, де `M` — максимальне значення серед усіх елементів масиву. Це надзвичайно швидко. Навіть для масиву з мільйона елементів скрипт виконається за долі секунди. У найкращому випадку (якщо масив порожній або містить нуль на початку), завдяки оптимізації раннього виходу, складність падає до **О(1)**.

**Просторова складність (Space / Memory Complexity):**
Скрипт не створює жодних нових колекцій чи масивів під час роботи. Ми використовуємо лише декілька локальних змінних (`result`, ітератор `i`, та параметри `a` і `b`). Незалежно від розміру вхідного вектора `numbers`, об'єм додаткової пам'яті залишається постійним. Тому просторова складність становить **О(1)** (константна пам'ять).

Цей інструмент є надійним блоком для побудови будь-яких високопродуктивних систем, що працюють із циклами та періодами.
