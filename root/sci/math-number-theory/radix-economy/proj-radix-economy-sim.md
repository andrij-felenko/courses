# Симуляція апаратних витрат різних основ числення

Для того щоб абстрактні математичні формули з логарифмами та похідними стали більш відчутними, ми можемо перевірити їх на практиці. Найкращий спосіб це зробити — написати комп'ютерну програму, яка симулюватиме апаратні витрати (кількість логічних вентилів та їхніх станів) для різних систем числення при спробі зберегти великий обсяг інформації. Наша мета — підтвердити теоретичні розрахунки суворими дискретними обчисленнями.

## Постановка задачі

Ми маємо певне велике число N, яке символізує певний обсяг інформації, що необхідно зберегти в пам'яті комп'ютера. Уявімо, що N = 1 мільярд (10⁹). Нам потрібно розрахувати необхідну кількість фізичних розрядів та загальні апаратні витрати для збереження цього числа у кількох популярних системах числення: двійковій (b=2), трійковій (b=3), четвірковій (b=4), вісімковій (b=8), десятковій (b=10) та шістнадцятковій (b=16). Після цього ми маємо порівняти їхню ефективність, взявши за еталон двійкову систему.

## Архітектурна логіка скрипта

Програма працюватиме за таким алгоритмом:
1. Визначаємо цільове число N.
2. Для кожної досліджуваної основи b обчислюємо точну цілу кількість розрядів (digits), необхідну для запису числа N. Це досягається обчисленням логарифма N за основою b та округленням результату в більшу сторону за допомогою функції стелі (ceil).
3. Обчислюємо загальні апаратні витрати як добуток основи b (кількості станів на один розряд) на розраховану кількість розрядів.
4. Знаходимо коефіцієнт ефективності кожної системи відносно двійкової бази шляхом ділення апаратних витрат двійкової системи на витрати поточної системи. Якщо коефіцієнт > 1.0, система ефективніша за двійкову. Якщо < 1.0 — менш ефективна.
5. Виводимо результати у вигляді акуратної таблиці для зручного порівняння.

## Покроковий розбір коду

Нижче наведено практичну реалізацію цієї логіки мовою C++.

```cpp
#include <iostream>
#include <cmath>
#include <iomanip>
#include <vector>
#include <string>

// Структура для зберігання результатів для однієї основи
struct RadixResult {
    int base;
    int digits_needed;
    int total_hardware_cost;
    double efficiency_ratio;
};

// Головна обчислювальна функція для оцінки економічності
RadixResult calculate_economy(int base, double target_number, int reference_cost) {
    RadixResult res;
    res.base = base;
    
    // Кількість розрядів: обчислюємо логарифм за основою b і беремо стелю
    // std::log() обчислює натуральний логарифм. Використовуємо властивість log_b(x) = ln(x) / ln(b)
    res.digits_needed = static_cast<int>(std::ceil(std::log(target_number) / std::log(base)));
    
    // Загальні апаратні витрати: кількість розрядів помножена на кількість станів
    res.total_hardware_cost = base * res.digits_needed;
    
    // Ефективність відносно двійкової системи (якщо reference_cost задано)
    if (reference_cost > 0) {
        res.efficiency_ratio = static_cast<double>(reference_cost) / res.total_hardware_cost;
    } else {
        res.efficiency_ratio = 1.0;
    }
    return res;
}

int main() {
    // Цільове число для зберігання: 1 мільярд (10^9)
    double target_N = 1e9;
    
    std::cout << "Аналіз апаратних витрат для збереження числа N = 1,000,000,000\n";
    std::cout << std::string(65, '-') << "\n";
    std::cout << std::setw(10) << "Основа" 
              << std::setw(15) << "Розрядів" 
              << std::setw(20) << "Загальні витрати" 
              << std::setw(20) << "Ефективність (до b=2)" << "\n";
    std::cout << std::string(65, '-') << "\n";

    // Спочатку розраховуємо метрики для двійкової системи, щоб мати еталон для порівняння
    RadixResult ref_result = calculate_economy(2, target_N, 0);
    int ref_cost = ref_result.total_hardware_cost;

    // Масив основ для аналізу
    std::vector<int> bases_to_test = {2, 3, 4, 8, 10, 16};

    // Проходимо по всіх основах та обчислюємо їхню економічність
    for (int b : bases_to_test) {
        RadixResult r = calculate_economy(b, target_N, ref_cost);
        std::cout << std::setw(10) << r.base 
                  << std::setw(15) << r.digits_needed 
                  << std::setw(20) << r.total_hardware_cost 
                  << std::fixed << std::setprecision(3) << std::setw(18) << r.efficiency_ratio << "x\n";
    }

    return 0;
}
```

## Аналіз складності вводу-виводу (I/O complexity)

Вивід цієї програми наочно демонструє та підтверджує всі наші попередні математичні розрахунки:
1. **Двійкова система (b=2)** для збереження 1 мільярда вимагає 30 двійкових розрядів (оскільки 2³⁰ ≈ 1.07 · 10⁹). Загальні витрати становлять 30 · 2 = 60 одиниць обладнання.
2. **Трійкова система (b=3)** потребує лише 19 розрядів (3¹⁹ ≈ 1.16 · 10⁹). Її загальні апаратні витрати становлять 19 · 3 = 57. Це абсолютний мінімум серед усіх перевірених основ! Її ефективність становить 1.053x порівняно з двійковою (тобто вона на 5.3% економічніша).
3. **Четвіркова система (b=4)** потребує 15 розрядів, а її витрати 15 · 4 = 60. Це феноменально підтверджує алгебраїчний висновок, що ефективність систем з основами 2 та 4 є абсолютно ідентичною.
4. **Десятковій системі (b=10)** потрібно найменше розрядів — лише 9, але оскільки кожен з них містить 10 станів, загальні витрати злітають до величезних 90 одиниць. Її ефективність падає до 0.667x, тобто вона на третину гірша за двійкову.

Цей практичний експеримент із дискретними (цілими) значеннями повністю підтверджує аналітичну теорію неперервних функцій: незважаючи на те, що трійкова система вимагає більшої кількості розрядів, ніж десяткова чи шістнадцяткова, її загальна апаратна складність є абсолютно мінімальною, і вона є беззаперечним лідером серед усіх цілочисельних систем числення.
