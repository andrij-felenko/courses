# ⚙️ Код навколо λ(n): свідок, що менше не можна, і показник, який справді працює

Сама формула λ(n) віддає лише число. Робочий інструмент має зробити ще три речі: порахувати λ(n) без похибки на аномалії двійки, **пред'явити свідка** — основу, чиє кільце степенів завдовжки точно λ(n), а отже живий доказ, що коротший показник нікого не поверне до одиниці, — і нарешті витратити λ там, де φ був би марнотратством: у піднесенні до степеня за модулем і в таємному показнику RSA. Зберемо цей набір мовою Python: уся робота тут — число-теоретична бухгалтерія, а не гарячий цикл, тож виразність важить більше за лічені такти.

## λ(n) як робочий обчислювач

Почнімо з фундаменту, на якому стоятиме решта. Формула λ(n) = НСК(λ(p^k)) прямо ділиться на три кроки: розклади n на прості, візьми λ від кожного простого степеня, склади [найменшим спільним кратним](root:math-number-theory/lcm). Розкладемо ці кроки на окремі функції — не з естетики, а тому що розклад на прості знадобиться ще раз, коли шукатимемо порядок основи.

```py
from math import gcd

def factorize(n):
    """Розклад n на прості: список пар (p, k) для кожного p^k."""
    factors, p = [], 2
    while p * p <= n:
        if n % p == 0:
            k = 0
            while n % p == 0:
                n //= p; k += 1
            factors.append((p, k))
        p += 1
    if n > 1:                       # лишився один простий дільник у першому степені
        factors.append((n, 1))
    return factors

def lcm(a, b):
    return a // gcd(a, b) * b

def lambda_prime_power(p, k):
    """λ(p^k) для одного простого степеня — з аномалією двійки."""
    if p == 2:
        if k == 1: return 1         # λ(2)   = 1
        if k == 2: return 2         # λ(4)   = 2
        return 1 << (k - 2)         # λ(2^k) = 2^(k-2) для k ≥ 3
    return (p - 1) * p ** (k - 1)   # непарне просте: λ = φ(p^k)

def carmichael_lambda(n):
    """λ(n) = НСК по простих степенях розкладу n."""
    result = 1
    for p, k in factorize(n):
        result = lcm(result, lambda_prime_power(p, k))
    return result

assert carmichael_lambda(8)    == 2
assert carmichael_lambda(360)  == 12
assert carmichael_lambda(3233) == 780
```

Уся тонкість зібралась у `lambda_prime_power`: для непарного простого показник збігається з Ейлеровим φ(p^k), а двійка вимагає трьох окремих випадків. Пропустити бодай один — і число попливе; чому саме половина й чому саме три випадки, розберемо серед пасток нижче.

Ціна обчислення — це ціна розкладу n на прості, і більше нічого: НСК та степені тут копійчані. Для випадкового n розклад миттєвий, а для добутку двох великих простих n = p·q він рівно такий самий важкий, як зламати RSA. У тому й фокус: хто будує ключ, той уже знає p і q, тож λ(p·q) = НСК(p−1, q−1) дістається задарма — саме там, де вона потрібна найбільше.

## Свідок: основа, чиє кільце має повну довжину λ(n)

Формула запевняє, що λ(n) — універсальний показник (a^λ ≡ 1 для всіх взаємно простих a) і що він досяжний. Та доказ на папері — одне, а інструмент має **вручити** свідка: конкретну основу g, яку жоден показник, менший за λ(n), не поверне до одиниці. Маючи таку g, мінімальність λ можна перевірити дослідом, а не приймати на віру.

Спершу потрібен [мультиплікативний порядок](root:math-number-theory/multiplicative-order) основи — ord(a), найменший m з a^m ≡ 1 (mod n). Наївний перебір m = 1, 2, 3, … марнотратний. Є коротший шлях, і він спирається на саму λ: порядок кожної основи неодмінно ділить λ(n). Тож почнімо з λ(n) як зі стелі й послідовно викидаймо з неї прості множники, доки показник ще повертає a до одиниці.

```py
def multiplicative_order(a, n):
    """ord(a): найменший m>0 з a^m ≡ 1 (mod n). Взаємна простота обов'язкова."""
    if gcd(a, n) != 1:
        raise ValueError("порядок визначено лише за gcd(a, n) = 1")
    order = carmichael_lambda(n)            # ord(a) неодмінно ділить λ(n)
    for p, _ in factorize(order):
        while order % p == 0 and pow(a, order // p, n) == 1:
            order //= p                     # цей простий множник у показнику зайвий
    return order

assert multiplicative_order(3, 8)  == 2
assert multiplicative_order(2, 11) == 10   # 2 — первісний корінь за модулем 11
```

Тепер сам свідок. Найпростіше — перебирати основи й повернути першу, чий порядок дорівнює λ(n): таких основ чимало, тож перебір короткий. Але він спирається на щастя. Свідка можна **сконструювати** напевно, і ця конструкція водночас є доказ мінімальности.

Ключ — операція, що з двох основ порядків o₁ та o₂ будує одну основу порядку рівно НСК(o₁, o₂). Розкладімо L = НСК(o₁, o₂) на прості степені. Кожен степінь p^e присутній хоча б в одному з o₁, o₂ — бо НСК бере більший із двох показників. Візьмімо цей p^e з тієї основи, чий порядок на нього ділиться: піднесення x^(o/p^e) дає елемент порядку точно p^e. Перемножмо здобуті шматки — їхні порядки попарно взаємно прості, тому порядок добутку дорівнює добуткові порядків, тобто L.

```py
def combine(x, ox, y, oy, n):
    """З двох основ (порядки ox, oy) зібрати одну порядку НСК(ox, oy)."""
    z, oz = 1, 1
    for p, k in factorize(lcm(ox, oy)):
        pe = p ** k
        base, ob = (x, ox) if ox % pe == 0 else (y, oy)
        z = z * pow(base, ob // pe, n) % n  # шматок порядку рівно p^k
        oz *= pe
    return z, oz

def max_order_witness(n):
    """Основа g, взаємно проста з n, чий порядок дорівнює точно λ(n)."""
    target, g, g_ord, a = carmichael_lambda(n), 1, 1, 1
    while g_ord != target:
        a += 1
        if gcd(a, n) != 1:
            continue
        g, g_ord = combine(g, g_ord, a, multiplicative_order(a, n), n)
    return g
```

Перевіримо на 360, де λ(360) = 12:

```py
g = max_order_witness(360)                        # g = 223
assert multiplicative_order(g, 360) == 12         # кільце завдовжки рівно λ
assert all(pow(g, m, 360) != 1 for m in range(1, 12))
```

Останній рядок і є вся суть. Основа 223 не повертається до одиниці на жодному кроці від 1 до 11 — уперше лише на дванадцятому. Отже жоден показник, менший за 12, не універсальний: він спотикається бодай на цій одній основі. А що дванадцятий степінь усіх таки повертає, знаємо з формули. Двоє разом і означають, що λ(360) = 12 — не просто придатний показник, а найменший.

> 🔧 **Навіщо це.** Свідок перетворює λ з «показника, що працює» на «показник, менший за який не працює» — і це перевіряється в рантаймі, а не приймається з довіри до теореми. Та сама конструкція `combine` у щасливому випадку λ(n) = φ(n) будує [первісний корінь](root:math-number-theory/primitive-root) — одну основу, що породжує всю групу лишків; поза цим випадком вона дає найдовший цикл, який узагалі можливий, коли повного породжувача не існує.

## Скільки насправді економимо: λ проти φ

Наскільки коротший показник дає λ? Порахуймо обидві функції на діапазоні поряд:

```py
def euler_phi(n):
    r = n
    for p, _ in factorize(n):
        r -= r // p
    return r

for n in [15, 24, 36, 105, 561, 1024]:
    phi, lam = euler_phi(n), carmichael_lambda(n)
    print(f"n={n:5d}   φ={phi:5d}   λ={lam:4d}   φ/λ={phi // lam}")
```

```
n=   15   φ=    8   λ=   4   φ/λ=2
n=   24   φ=    8   λ=   2   φ/λ=4
n=   36   φ=   12   λ=   6   φ/λ=2
n=  105   φ=   48   λ=  12   φ/λ=4
n=  561   φ=  320   λ=  80   φ/λ=4
n= 1024   φ=  512   λ= 256   φ/λ=2
```

Розрив між φ і λ росте з кількістю різних непарних простих у розкладі: кожне непарне просте вносить у показник спільну двійку (у ньому сидить парне p − 1), і НСК ту двійку зараховує один раз, а добуток — щоразу заново. Три різні непарні прості (як у 105 = 3·5·7 чи 561 = 3·11·17) — і Ейлерів показник уже вчетверо задовгий.

![Діапазон n від 2 до 40: для кожного n сіра порожня точка — φ(n), зелена повна — λ(n), а стрижень між ними показує зайве в Ейлеровому показнику; на простих обидві точки збігаються на верхній оболонці, на складених із кількома простими зелена різко просідає до низу](img/lambda-vs-phi.svg)

*Сірі точки φ(n) дертися вгору до діагоналі простих: для простого n маємо φ = λ = n − 1, і зелена точка сидить просто на сірій. Та щойно n збирає кілька простих, зелена λ падає до низу графіка — стрижень між точками і є та частина Ейлерового показника, яку λ відкидає задарма.*

## Застосування 1: коротший показник у піднесенні за модулем

Правило, заради якого все й затівалось: за взаємної простоти a і n

```
a^e ≡ a^(e mod λ(n))   (mod n)
```

— показник можна зменшувати не за φ(n), а за меншим λ(n). У звичайному [швидкому піднесенні до степеня за модулем](root:math-number-theory/modular-exponentiation) це просто трохи менше множень. Та по-справжньому λ незамінна там, де сам показник — велетень, якого ні записати, ні обчислити: у вежі степенів b^c. Число b^c може мати мільярди цифр, але його остача за модулем λ(n) — маленька, і саме її досить.

```py
def tower_mod(a, b, c, n):
    """a^(b^c) mod n за взаємної простоти a і n — без матеріалізації b^c."""
    assert gcd(a, n) == 1
    inner = pow(b, c, carmichael_lambda(n))   # b^c, згорнуте за λ(n)
    return pow(a, inner, n)

assert tower_mod(7, 7, 7, 100) == pow(7, 7 ** 7, 100) == 43
```

Тут 7⁷ ще можна виписати, але прийом масштабується: для 7^(7^(7^7)) показник уже не помістити в жодну пам'ять, і згортання кожного поверху за своєю λ (рекурсивно вниз) — єдиний шлях крізь. λ(n) стискає невиписуваний показник до кількох десятків біт — під log₂λ(n).

## Застосування 2: таємний показник RSA живе на λ

У [RSA](root:sf-security/rsa) таємний показник d — це [обернений](root:math-number-theory/modular-inverse) до відкритого e за деяким модулем. Класичний виклад бере модулем φ(n); стандарт PKCS #1 (RFC 8017) бере λ(n) = НСК(p − 1, q − 1), і виходить менший d — коротший показник, менше множень у кожному розшифруванні й підписі.

```py
p, q = 61, 53
n, e = p * q, 17                 # n = 3233
phi = (p - 1) * (q - 1)          # 3120
lam = lcm(p - 1, q - 1)          # 780
d_phi = pow(e, -1, phi)          # 2753
d_lam = pow(e, -1, lam)          # 413

msg = 123
c = pow(msg, e, n)
assert pow(c, d_lam, n) == msg
assert pow(c, d_phi, n) == msg   # обидва показники розшифровують
```

Тут ховається промовиста дрібниця. Класичний підручниковий приклад RSA — саме n = 3233, e = 17 — майже завжди наводить d = 413. А 413 — це обернений до 17 за модулем **λ** (413·17 ≡ 1 mod 780), а не за модулем φ (там вийшло б 2753). Коротше з двох чисел стало «канонічним» d рівно тому, що реалізації йдуть за PKCS #1 і рахують на λ.

У λ є й друга перевага, тонша за швидкість. Для числа без квадратів n = p·q рівність m^(1 + t·λ(n)) ≡ m (mod n) справджується для **будь-якого** m — байдуже, взаємно просте воно з n чи ділиться на p. Класичне доведення через теорему Ейлера на таких m спотикається й латається окремо; на λ винятку немає:

```py
assert pow(pow(p, e, n), d_lam, n) == p   # повідомлення, кратне p, теж вертається
```

## Пастки

**Аномалія двійки — і обидві її сторожі.** Це найпідступніший рядок усього набору. Спокуса написати одну гілку `2^(k−2)` велика, але вона правдива лише для k ≥ 3. Без сторожі на k = 2 функція віддасть λ(4) = 2^0 = 1 — і згортання показника за цим числом зіпсує результат:

```py
def lambda_buggy(p, k):          # забули сторожу k == 2
    if p == 2:
        return 1 if k == 1 else 1 << (k - 2)
    return (p - 1) * p ** (k - 1)

assert lambda_buggy(2, 2) == 1                 # ХИБА: насправді λ(4) = 2
assert pow(3, 3, 4) == 3                       # 3³ ≡ 3 (mod 4)
assert pow(3, 3 % 1, 4) == 1                   # 3⁰ = 1 ≠ 3 — згортання зламане
```

Бік небезпеки тут важливий. λ, узята **завеликою** (скажімо, φ замість λ, без аномалії), лише марнотратна — показник довший, та він усе одно універсальний, результат правильний. А λ, узята **замалою**, як хибне λ(4) = 1, псує коректність: згорни за нею показник — і відповідь зміниться. Аномалія робить справжню λ саме **меншою** за наївну формулу, тож три випадки для двійки треба вписати точно; безпечного округлення тут немає.

**Взаємна простота — умова, без якої згортання неправдиве.** Правило a^e ≡ a^(e mod λ) тримається лише за gcd(a, n) = 1. Досить основі поділити спільний множник із модулем — і рівність падає:

```py
n, a = 12, 2                     # gcd(2, 12) = 2 ≠ 1
lam = carmichael_lambda(n)       # λ(12) = 2
assert pow(a, 3, n) == 8
assert pow(a, 3 % lam, n) == 2   # 2^(3 mod 2) = 2¹ = 2 ≠ 8
```

І окремо — та сама рівність з RSA, m^(1 + t·λ) ≡ m, що працює для **всіх** m, зокрема й не взаємно простих. Це не суперечність, а інше твердження: воно спирається на те, що n без квадратів, і на особливу форму показника «1 + кратне λ». Не варто розтягувати його на загальний випадок: звичайне згортання довільного показника вимагає gcd(a, n) = 1, і крапка.

## Ціна всього набору

Кожна функція тут — тонкий шар піднесень за модулем над одним важким кроком, розкладом n на прості. `carmichael_lambda` коштує рівно розклад; `multiplicative_order`, маючи вже λ, — це O(log²n) множень; свідок — жменя `combine`; обидва застосування — одинокі виклики `pow`. Отже весь набір дешевий рівно тоді, коли розклад n уже в руках — тобто в момент породження ключа RSA, де λ не просто оптимізація, а той самий модуль, на якому схема стоїть.
