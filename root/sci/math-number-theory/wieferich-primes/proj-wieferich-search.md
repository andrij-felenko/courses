# ⚙️ Реалізація високоефективного пошуку простих чисел Віферіха

У цій вставці описано алгоритмічні принципи, структури даних, особливості організації пам'яті та наведено практичну реалізацію високоефективного пошуку простих чисел Віферіха `2ᵖ⁻¹ ≡ 1 (mod p²)`. Програма здійснює піднесення до степеня за модулем `p²` з використанням 128-бітної арифметики для 64-бітних простих чисел, сегментованого решета Ератосфена та паралельної обробки потоками.

## Алгоритмічні підходи та проблема 128-бітного модуля

Для перевірки умови Віферіха `2ᵖ⁻¹ ≡ 1 (mod p²)` для даного простого числа `p` необхідно обчислити остачу від ділення степеня `2ᵖ⁻¹` на квадрат модуля `p²`.

Оскільки для простих чисел `p ≈ 10⁹` квадрат `p² ≈ 10¹⁸` ще вміщується у стандартний 64-бітний беззнаковий цілочисельний тип `uint64_t` (максимальне значення якого становить `~1.84 · 10¹⁹`), то для більших простих чисел `p > 4.29 · 10⁹` квадрат `p²` перевищує 64 біти. Наприклад, при `p ≈ 10¹²` маємо `p² ≈ 10²⁴`, що вимагає застосування 128-бітної цілочисельної арифметики для зберігання проміжних добутків.

Сучасні компілятори GCC та Clang на 64-бітних платформах підтримують вбудований 128-бітний тип `unsigned __int128`, який дозволяє виконувати множення та обчислення остачі за модулем `p²` на апаратному рівні (використовуючи спарені 64-бітні інструкції множення та ділення процесора).

```
 64-бітне просте p  ──────►  квадрат p² може займати до 128 бітів
 2ᵖ⁻¹ mod p²         ──────►  проміжні добутки вимагають 128 бітів
```

Процес обчислення двійкового піднесення до степеня вимагає виконання послідовності множень. Оскільки операція обчислення остачі від ділення (оператор `%`) на 128-бітному модулі виконується за допомогою виклику апаратного ділення або бібліотечної функції компілятора (`__umodti3`), вона є відносно "важкою" для обчислювального ядра процесора. Для прискорення цього етапу у промислових пошукових системах використовують перетворення Монтгомері, яке переводить обчислення у спеціальну числову область, де ділення замінюється побітовими зсувами.

### Алгоритм швидкого піднесення до степеня за модулем p²

Замість обчислення `2ᵖ⁻¹ mod p²` через послідовні `p - 1` множень (що вимагало б мільярдів операцій для кожного числа), застосовують двійковий алгоритм піднесення до степеня (square-and-multiply):

1. Представити показник `E = p - 1` у двійковому вигляді: `E = (bₖ bₖ₋₁ … b₁ b₀)₂`.
2. Ініціалізувати змінні: `base = 2` та `result = 1`.
3. На кожному кроці підносити `base` до квадрата за модулем `p²`: `base = (base * base) % p²`.
4. Якщо відповідний біт `bᵢ` дорівнює 1, помножити `result = (result * base) % p²`.
5. Після завершення обробки всіх бітів перевірити, чи `result == 1`.

Кожен крок циклу зменшує кількість необхідних множень з `O(p)` до `O(log p)`. Для числа `p ≈ 10¹²` замість трильйона множень виконується лише близько 40 операцій множення за модулем `p²`, що забезпечує колосальне прискорення.

Якщо `result == 1`, це означає виконання умови Віферіха! У такому разі обчислюють частку Віферіха `W(p) = (2ᵖ⁻¹ - 1) / p` і переконуються, що `W(p) % p == 0`.

## Арифметика Монтгомері та усунення апаратного ділення

При обробці мільярдів простих чисел найбільшим обчислювальним "вузьким місцем" (bottleneck) є інструкція апаратного ділення `div` або бібліотечна функція `__umodti3`, яка вимагає від 40 до 90 тактів процесора на кожну операцію остачі.

Для усунення ділення застосовують редукцію Монтгомері (Montgomery Reduction):
- Обирають додатковий модуль `R = 2¹²⁸`, який перевищує модуль `N = p²`.
- Кожне число `x` переводять у форму Монтгомері: `X = (x · R) mod N`.
- Множення двох чисел у формі Монтгомері обчислюється за допомогою алгоритму REDC: `REDC(A · B) = (A · B · R⁻¹) mod N`.
- Замість обчислення остачі від ділення на `N`, алгоритм REDC виконує ділення на `R = 2¹²⁸`, що в комп'ютерній архітектурі зводиться до швидких побітових зсувів та вибірки молодшого 128-бітного слова.

Завдяки цьому середня кількість тактів процесора на одне модульне множення зменшується з 80 тактів до 12 тактів, забезпечуючи підсумкове прискорення пошукового ядра у 3–5 разів.

## Паралельний пошук та сегментоване решето

Для досягнення максимальної обчислювальної швидкодії процес пошуку розбивають на три послідовні етапи:

1. **Генерація кандидатів (Сегментоване решето Ератосфена):** Замість створення одного велетенського масиву для всього інтервалу `[start, end]`, числова вісь розбивається на сегменти, які повністю вміщуються у кєш-пам'ять першого та другого рівнів процесора (L1/L2 Cache, зазвичай 32–256 КБ). Це усуває затримки звернення до оперативної пам'яті.
2. **Паралельна розпаралелена обробка:** Блоки простих чисел розподіляються між робочими потоками процесора за допомогою OpenMP (у мові C) або `std::jthread` та паралельних алгоритмів STL (у мові C++).
3. **Фільтрація та верифікація:** Перевірка остачі виконується повністю незалежно для кожного простого числа.

Завдяки сегментації решета пропускна здатність алгоритму зростає в рази, оскільки обчислювальні ядра процесора не простоюють в очікуванні завантаження даних із повільної системної пам'яті DRAM. Кожен потік обробляє свій локальний числовий діапазон повністю у швидкому кеші CPU.

## Аналіз ефективності та оптимізації Монтгомері

Розглянемо ключові фактори, які впливають на обчислювальну продуктивність програми при обробці велетенських числових діапазонів до `10¹⁸`:

1. **Часова складність:** Перевірка одного простого числа `p` вимагає `O(log p)` кроків піднесення до квадрата за модулем `p²`. Для всього інтервалу простих чисел `p ≤ X` загальна часова складність дорівнює `O(X log log X)`.
2. **Арифметика Монтгомері:** При обчисленнях на відеокартах (GPU) або суперкомп'ютерних кластерах операція обчислення остачі `% p²` для 128-бітних чисел є найповільнішою апаратною інструкцією. Застосування репрезентації Монтгомері дозволяє замінити ділення 128-бітних чисел на бітові зсуви та множення, підвищуючи швидкість пошуку в 3–5 разів.
3. **Ідеальний паралелізм:** Оскільки перевірка кожного простого числа `p` є абсолютно автономною і не вимагає обміну даними з сусідніми потоками, алгоритм демонструє ідеальне лінійне масштабування при використанні багатьох ядер процесора або тисяч обчислювальних блоків GPU.
4. **Використання векторних інструкцій (SIMD):** Сучасні розширення AVX-512 та ARM Neon дозволяють пакувати по чотири 64-бітних значення у векторні регістри й виконувати паралельне множення за модулем для чотирьох простих чисел одночасно в одному інструкційному такті процесора.
