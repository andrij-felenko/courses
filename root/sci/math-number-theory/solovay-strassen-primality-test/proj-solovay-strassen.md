# ⚙️ Реалізація тесту Соловея–Штрассена мовами C та C++

Призначення цієї вставки — надати інженерний і математичний аналіз програмної реалізації алгоритму перевірки простоти Соловея–Штрассена. У ній детально розібрано архітектуру обчислення модульного піднесення до степеня з захистом від арифметичного переповнення, двобічний алгоритм обчислення символу Якобі за квадратичним законом взаємності, коректне генерація випадкових випробувальних основ без системного зсуву (bias), а також представлено робочий, обчислювально оптимізований вихідний код мовами C та C++.

## 1. Архітектурні компоненти та обчислювальна складність

Програмна реалізація тесту Соловея–Штрассена вимагає побудови трьох незалежних обчислювальних модулів, кожен із яких розв'язує окрему арифметичну задачу:

1. **Модуль запобігання переповненню та модульного множення:** 
   При роботі з 64-бітними беззнаковими цілими числами (`uint64_t`) добуток двох чисел `a` та `b`, близьких до `2⁶⁴ - 1`, досягає `2¹²⁸ - 2⁶⁵ + 1`. Звичайне 64-бітне множення призводить до втрати старших бітів та руйнування коректності обчислень. Для розв'язання цієї проблеми в мові C та C++ застосовується розширення розрядності компілятора `unsigned __int128`, яке виконує точне 128-бітне множення з наступним взяттям остачі за модулем `n`.

2. **Модуль бінарного піднесення до степеня за модулем (`power_mod`):**
   Обчислення значення `a^((n-1)/2) mod n` виконується методом правостороннього двійкового розкладу показника степеня (Binary Exponentiation / Square-and-Multiply). Алгоритм сканує біти показника степеня від молодшого до старшого: на кожному кроці основа підноситься до квадрата за модулем `n`, а якщо поточний біт показника дорівнює 1, поточний результат множиться на піднесену основу. Це зменшує кількість множень із `(n - 1) / 2` до `O(log n)`.

3. **Модуль обчислення символу Якобі без факторизації (`jacobi_symbol`):**
   Замість розкладу числа `n` на прості множники (що є обчислювально нездійсненним для великих чисел), символ Якобі `(a / n)` обчислюється ітеративним застосуванням квадратичного закону взаємності. Алгоритм послідовно виділяє з чисельника `a` максимальний степінь двійки `2ᵏ`, коригує знак результату на основі остачі знаменника `n mod 8`, виконує інверсію чисельника та знаменника `(a, n) ↦ (n, a)` із коригуванням знака на основі остач `a mod 4` та `n mod 4`, і бере остачу `a mod n`. Процес триває до тих пір, поки `a` не стане дорівнювати 0.

4. **Модуль генерації випробувальних основ та перевірки конгруентності:**
   Для кожного з `k` раундів обирається випадкова основа `a ∈ [2, n - 1]`. Використовується умова `НСД(a, n) > 1` для швидкого виявлення складених чисел, чий дільник випадково збігся з основою `a`. Потім обчислюється `x = a^((n-1)/2) mod n` та символ Якобі `J = (a / n) mod n`. Якщо `J = -1`, його значення у кільці остач `ℤ/nℤ` відображається у `n - 1`. Якщо `x ≠ J mod n`, число оголошується складеним.

### 3.1. Захист від переповнення при 64-бітній арифметиці

Під час обчислення модульного множення `(a * b) % mod` виникає типова проблема арифметичного переповнення 64-бітних регістрів процесора. Якщо `a = 2⁶⁴ - 59` та `b = 2⁶⁴ - 59`, то їхній добуток досягає приблизно `3.4 · 10³⁸`, що вимагає 128 бітів для точного представлення. 

У наведеній реалізації застосовано приведення типів `(unsigned __int128)a * b`. Сучасні 64-бітні процесори архітектури x86-64 виконують цю операцію за допомогою однієї апаратної інструкції `mulx` або `mul`, яка записує 128-бітне значення у пару регістрів `RAX:RDX`, після чого інструкція `div` виконує ділення з остачею.

Для систем, де 128-бітні типи не підтримуються компілятором (наприклад, деякі 32-бітні мікроконтролери), піднесення до степеня та множення вимагають реалізації алгоритму Русичного множення (Add-and-Shift Multiplication / Modular Multiplication) із часовою складністю `O(log mod)` на кожне множення:

### 3.2. Алгоритм обчислення символу Якобі без ділення

Функція `jacobi_symbol` реалізує розрахунок знаків без виконання вартісної операції ділення з остачею на кожній ітерації. Основний час роботи займає внутрішній цикл виділення парності:

:::tabs
```c
while (a % 2 == 0) {
    a /= 2;
    int64_t n_mod8 = n % 8;
    if (n_mod8 == 3 || n_mod8 == 5) {
        result = -result;
    }
}
```
```cpp
while (a % 2 == 0) {
    a /= 2;
    const std::int64_t n_mod8 = n % 8;
    if (n_mod8 == 3 || n_mod8 == 5) {
        result = -result;
    }
}
```
:::

Оскільки `n` є непарним числом, його остача за модулем 8 залежить лише від трьох молодших бітів `n & 7`. Умова `n_mod8 == 3 || n_mod8 == 5` випливає з другої додаткової теореми квадратичного закону взаємності:

```
(2 / n) = (-1)^((n² - 1) / 8)
```

Якщо `n ≡ 1` або `7 (mod 8)`, то `n² - 1` ділиться на 16, отже `(n² - 1) / 8` є парним і `(2 / n) = +1`. Якщо ж `n ≡ 3` або `5 (mod 8)`, то `(n² - 1) / 8` є непарним і `(2 / n) = -1`.

Після виділення всіх степенів двійки чисельник `a` стає непарним. Далі застосовується інверсія `std::swap(a, n)` та корекція знака:

:::tabs
```c
if (a % 4 == 3 && n % 4 == 3) {
    result = -result;
}
```
```cpp
if (a % 4 == 3 && n % 4 == 3) {
    result = -result;
}
```
:::

Це є безпосереднім втіленням Закону квадратичної взаємності: `(a / n) = -(n / a)` тоді й лише тоді, коли обидва числа `a` та `n` мають остачу 3 при діленні на 4 (тобто `a ≡ 3 mod 4` та `n ≡ 3 mod 4`).

### 3.3. Ліквідація системного зсуву генератора випадкових чисел (Random Bias)

Поширеною помилкою при реалізації ймовірнісних алгоритмів є використання виразу `rand() % (n - 3)`. Стандартна функція `rand()` у бібліотеці C C-StdLib повертає значення в діапазоні від 0 до `RAND_MAX` (яке на багатьох платформах дорівнює всього `32767`). Застосування операції взяття остачі `%` до обмеженого діапазону призводить до двох критичних дефектів:
1. **Неможливість тестування великих чисел:** Якщо `n > RAND_MAX`, випробовуватися будуть лише перші `32767` основ, а вищі основи взагалі ніколи не пройдуть перевірку.
2. **Нерівномірність розподілу (Modulo Bias):** Молодші значення остач отримують вищу ймовірність випадіння, що порушує вимогу незалежного вибору рівномірно розподіленої основи в `[2, n - 1]`.

У наведеній реалізації мовою C проблему розв'язано через конкатенацію декількох 16-бітних фрагментів `rand()` та застосування алгоритму Rejection Sampling. У C++ застосовано стандартний 64-бітний генератор Вихру Мерсенна `std::mt19937_64` разом із `std::uniform_int_distribution<std::uint64_t>`, що забезпечує абсолютно рівномірний розподіл псевдовипадкових чисел у довільному діапазоні аж до `2⁶⁴ - 1`.

### 3.4. Виявлення чисел Кармайкла на практиці

У демонстраційних масивах `candidates` першими трьома елементами є найвідоміші числа Кармайкла: `561`, `1105` та `1729`.

Під час запуску програми наведений код викриває їх за кілька ітерацій:
- Для `561 = 3 · 11 · 17`: при виборі основи `a = 5` функція `power_mod(5, 280, 561)` повертає `67`, тоді як `jacobi_symbol(5, 561)` повертає `1`. Порівняння `67 != 1` негайно перериває цикл і повертає `false` (Складене).
- Для `1729 = 7 · 13 · 19` (число Харді–Рамануджана): основа `a = 2` дає `power_mod(2, 864, 1729) = 1`, а `jacobi_symbol(2, 1729) = 1` (брехун Ейлера). Проте вже наступна основа `a = 5` дає `power_mod(5, 864, 1729) = 1728` (що відповідає `-1`), тоді як `jacobi_symbol(5, 1729) = 1`. Порівняння `1728 != 1` викриває складність числа `1729`.

### 3.5. Оцінка продуктивності та порівняння часової складності

Часова складність одного раунду алгоритму складається з:
1. `O(log n)` операцій для НСД (алгоритм Євкліда).
2. `O(log n)` модульних множень для піднесення до степеня `power_mod`.
3. `O(log n)` ітерацій скорочення для символу Якобі `jacobi_symbol`.

Оскільки кожне модульне множення 64-бітних чисел займає `O(1)` інструкцій процесора, один раунд тесту вимагає менше `200` інструкцій CPU навіть для чисел порядку `10¹⁸`. Виконання `k = 30` раундів займає частки мікросекунди, що дає можливість миттєво генерувати прості числа в практичних завданнях.
