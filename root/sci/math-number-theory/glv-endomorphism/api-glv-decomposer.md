# 📋 Інтерфейс декомпозитора та конфігуратор кривих GLV/GLS

Ця вставка є довідником програмного інтерфейсу (API) бібліотеки GLV/GLS, що описує структури даних, конфігурації еліптичних кривих, інтерфейси декомпозиції, системні виклики та коди помилок.

Програмний інтерфейс призначений для інтеграції прискореного скалярного множення на еліптичних кривих у високонавантажені криптографічні бібліотеки (такі як `libsecp256k1`, `arkworks-rs`, `gnark` та системні криптопровайдери ОС).

## 1. Загальні принципи проектування та інтерфейсні гарантії

При розробці даного API дотримуються п'яти фундаментальних криптографічних та системних вимог:

Гарантія константного часу виконання (Constant-Time Invariant): Усі функції, що приймають скаляр `k` або виконують точкові операції, гарантують однакову кількість процесних тактів незалежно від значень вхідних даних. Уся обробка секретних ключів виконується без умовних операторів розгалуження, а також без використання операцій ділення з довільною тривалістю виконання. Заборонено використання динамічного виділення пам'яті (`malloc`/`free`) під час виконання математичних операцій, що виключає затримки на виклики ядра операційної системи.

Безпека використання пам'яті (Memory Hygiene): Усі тимчасові структури, які містять секретні скаляри або коефіцієнти декомпозиції, очищаються за допомогою спеціальної функції `glv_secure_zero()` перед виходом із функцій. Ця функція запобігає оптимізації видалення "мертвого коду" компілятором і гарантує, що чутливі дані у стеку процесора знищуються відразу після завершення обчислень.

Потокобезпечність (Thread Safety): Усі об'єкти конфігурацій кривих `glv_curve_config_2d_t` є строго незмінними (`read-only`) після ініціалізації. Кілька паралельних потоків можуть безпечно використовувати одну спільну конфігурацію без блокувань чи м'ютексів, що є критичним для багатопотокових серверів валідації транзакцій.

Відсутність зовнішніх залежностей (Zero Dependencies): Реалізація опирається виключно на базовий стандарт мови C99 (або C++20) та не вимагає сторонніх математичних бібліотек великих чисел (таких як GMP або OpenSSL BN), що спрощує аудит безпеки та портативність на вбудовані платформи без операційної системи.

Передбачувана обробка помилок (Predictable Error Handling): Жодна функція API не викликає аварійного завершення програми (panic або abort). Усі некоректні вхідні дані обробляються поверненням відповідного від'ємного статусного коду із зануленням вихідних буферів.

## 2. Коди відповідей та статусів (Error Codes)

Усі функції декомпозиції та скалярного множення повертають 32-бітне ціле число зі знаком (`glv_status_t`), яке відповідає статусу виконання операції:

| Константа статусу | Значення | Опис |
| :--- | :--- | :--- |
| `GLV_SUCCESS` | `0` | Операція завершилась успішно. |
| `GLV_ERR_NULL_POINTER` | `-1` | Вхідний або вихідний вказівник дорівнює `NULL`. |
| `GLV_ERR_INVALID_SCALAR` | `-2` | Скаляр `k` знаходиться поза допустимим діапазоном `[1, r - 1]`. |
| `GLV_ERR_POINT_NOT_ON_CURVE` | `-3` | Вхідна точка `P` не задовольняє рівняння кривої. |
| `GLV_ERR_UNSUPPORTED_CURVE` | `-4` | Передана конфігурація кривої не підтримує обраний ендоморфізм. |
| `GLV_ERR_DECOMPOSITION_FAILED` | `-5` | Алгоритм Бабаї не зміг знизити норму залишку до заданої межі. |

Повернення будь-якого від'ємного статусу гарантує, що результуючі структури даних були занулені, а операція скалярного множення не повернула неповних чи спотворених точок.

## 3. Основні структури даних

### Конфігурація кривої GLV 2D (`glv_curve_config_2d_t`)

Структура містить математичні константи еліптичної кривої, необхідні для виконання 2D-декомпозиції GLV:

:::tabs
```c
typedef struct {
    const char *curve_name;       /* Текстовий ідентифікатор кривої (наприклад "secp256k1") */
    uint64_t p[4];                /* Просте число модуля поля F_p */
    uint64_t r[4];                /* Порядок підгрупи точок кривої r */
    uint64_t beta[4];             /* Кубічний корінь з одиниці u полі F_p (beta^3 = 1 mod p) */
    uint64_t lambda[4];           /* Власне значення ендоморфізму (lambda^2 + lambda + 1 = 0 mod r) */
    
    /* Матриця короткого базису ґратки L */
    uint64_t b11[2];              /* Елемент b11 (128 бітів) */
    uint64_t b12[2];              /* Елемент b12 (128 бітів) */
    uint64_t b21[2];              /* Елемент b21 (128 бітів) */
    uint64_t b22[2];              /* Елемент b22 (128 бітів) */
    
    /* Розширені константи фіксованої точності для константного ділення */
    uint64_t g1[4];               /* g1 = floor(2^384 * b22 / r) */
    uint64_t g2[4];               /* g2 = floor(2^384 * b21 / r) */
    uint16_t fixed_shift;         /* Величина побітового зсуву (зазвичай 384) */
} glv_curve_config_2d_t;
```
```cpp
namespace crypto::glv {

struct CurveConfig2D {
    std::string_view curve_name;            // Текстовий ідентифікатор кривої
    std::array<uint64_t, 4> p{};            // Просте число модуля поля F_p
    std::array<uint64_t, 4> r{};            // Порядок підгрупи точок кривої r
    std::array<uint64_t, 4> beta{};         // Кубічний корінь з одиниці у полі F_p
    std::array<uint64_t, 4> lambda{};       // Власне значення ендоморфізму
    
    std::array<uint64_t, 2> b11{};          // Елемент b11 короткого базису
    std::array<uint64_t, 2> b12{};          // Елемент b12 короткого базису
    std::array<uint64_t, 2> b21{};          // Елемент b21 короткого базису
    std::array<uint64_t, 2> b22{};          // Елемент b22 короткого базису
    
    std::array<uint64_t, 4> g1{};           // Константа масштабування g1
    std::array<uint64_t, 4> g2{};           // Константа масштабування g2
    uint16_t fixed_shift{384};              // Величина побітового зсуву
};

} // namespace crypto::glv
```
:::

Кожне поле даної структури має строго визначене числове призначення. Масив `p` описує 256-бітний модуль поля у форматі Little-Endian. Масив `r` визначає порядок кривої. Константи `b11, b12, b21, b22` утворюють матрицю редукованого базису Гаусса. Поля `g1` та `g2` зберігають 256-бітні коефіцієнти масштабування.

Поле `fixed_shift` визначає кількість бітів дробової точності при множенні на масштабовані константи `g1` та `g2`. Для 256-бітного порядку кривої значення `fixed_shift = 384` забезпечує абсолютну точність цілочисельного округлення без втрати молодших бітів.

### Результат 2D-декомпозиції (`glv_split_2d_t`)

Структура зберігає розкладені 128-бітні скаляри та їхні знакові маски:

:::tabs
```c
typedef struct {
    uint64_t k1[2];               /* Модуль першого скаляра k1 (128 бітів) */
    uint64_t k2[2];               /* Модуль другого скаляра k2 (128 бітів) */
    uint8_t k1_is_negative;       /* 1 якщо k1 від'ємний, інакше 0 */
    uint8_t k2_is_negative;       /* 1 якщо k2 від'ємний, інакше 0 */
} glv_split_2d_t;
```
```cpp
namespace crypto::glv {

struct Split2D {
    std::array<uint64_t, 2> k1{};           // Модуль першого скаляра k1
    std::array<uint64_t, 2> k2{};           // Модуль другого скаляра k2
    bool k1_is_negative{false};             // Прапор знака k1
    bool k2_is_negative{false};             // Прапор знака k2
};

} // namespace crypto::glv
```
:::

Поля `k1` та `k2` представляють абсолютні значення знайдених коефіцієнтів розкладу. Прапори `k1_is_negative` та `k2_is_negative` показують знак відповідного скаляра.

### Результат 4D-декомпозиції GLS (`glv_split_4d_t`)

Структура зберігає чотири 64-бітних скаляри для комбінованого GLV/GLS розкладу:

:::tabs
```c
typedef struct {
    uint64_t k[4];                /* Чотири скаляри k1, k2, k3, k4 (по 64 біти кожен) */
    uint8_t flags_negative;       /* Бітова маска знаків (біт i відповідає k_i) */
} glv_split_4d_t;
```
```cpp
namespace crypto::glv {

struct Split4D {
    std::array<uint64_t, 4> k{};            // Чотири 64-бітних скаляри k1..k4
    uint8_t flags_negative{0};              // Бітова маска знаків
};

} // namespace crypto::glv
```
:::

Ця структура оптимізована під 64-бітну архітектуру сучасних серверних процесорів x86-64 та ARM64.

## 5. Покрокове керівництво з інтеграції та розширення FFI

Для підключення даного API до проектів мовами Rust, Go або Python використовуються механізми Foreign Function Interface (FFI).

### Інтеграція у Rust (через `bindgen`)

У мові Rust створення безпечної обгортки (safe wrapper) навколо C-API реалізується за допомогою наступного паттерну:

```rust
pub struct GlvCurveConfig {
    inner: glv_curve_config_2d_t,
}

impl GlvCurveConfig {
    pub fn new(curve_name: &str) -> Result<Self, GlvError> {
        let mut config = std::mem::MaybeUninit::uninit();
        let c_name = std::ffi::CString::new(curve_name)?;
        unsafe {
            let status = glv_init_curve_2d(config.as_mut_ptr(), c_name.as_ptr());
            if status == 0 {
                Ok(Self { inner: config.assume_init() })
            } else {
                Err(GlvError::from_status(status))
            }
        }
    }
}
```

Обгортка на мові Rust гарантує автоматичне виклики знищення пам'яті (RAII) та виключає можливість передачі нульових вказівників у систему.

### Інтеграція у Go (через `cgo`)

У мові Go інтеграція виконується напряму через заголовочний файл `glv_decomposer.h`:

```go
// #include "glv_decomposer.h"
import "C"
import "unsafe"

func DecomposeScalar(scalar [4]uint64, config *C.glv_curve_config_2d_t) (C.glv_split_2d_t, error) {
    var split C.glv_split_2d_t
    status := C.glv_decompose_2d(&split, (*C.uint64_t)(unsafe.Pointer(&scalar[0])), config)
    if status != 0 {
        return split, fmt.Errorf("GLV decomposition failed with status: %d", status)
    }
    return split, nil
}
```

Використання `cgo` дозволяє легко підключати високопродуктивний C-модуль декомпозиції до криптографічних сервісів на мові Go без накладних витрат на міжпроцесну взаємодію.

## 7. Особливості обробки крайових випадків та виняткових станів

При обробці вхідних даних криптографічний декомпозитор враховує наступні виняткові випадки:

Крайові значення скалярів `k = 0` або `k = 1`: Скаляр `k = 0` є неприпустимим у криптосистемах ECDSA/Schnorr. При передачі `k = 0` функція `glv_decompose_2d()` повертає `GLV_ERR_INVALID_SCALAR` без виконання математичних дій. При `k = 1` декомпозиція повертає `k1 = 1, k2 = 0`.

Точки нескінченності `O`: Якщо вхідна точка `P` є точкою нескінченності (`Z = 0` у координатах Якобі), скалярне множення повертає результат `O` за константний час.

Обробка витоків пам'яті та сигналів переривання: При виклику `glv_mul_2d()` у середовищі з багаторазовими перериваннями процесора (наприклад, драйвери ядра Linux або ОС реального часу FreeRTOS), проміжні вектори зберігаються на стек-фреймі та автоматично очищаються при поверненні значення.

## 8. Життєвий цикл та діаграма станів декомпозитора

Схема життєвого циклу обробки скаляра у внутрішньому конвеєрі декомпозитора показує попотоковий рух даних:

```
[Початковий скаляр k (256b)]
             │
             ▼
  ┌──────────────────────┐
  │  glv_decompose_2d()  │ ──► (Фіксоване множення g1, g2 без div)
  └──────────────────────┘
             │
             ▼
  ┌──────────────────────┐
  │ glv_split_2d_t (128b)│ ──► (Пара k1, k2 та знакові маски)
  └──────────────────────┘
             │
             ▼
  ┌──────────────────────┐
  │  glv_apply_endom()   │ ──► (Обчислення phi(P) = (beta*X: Y: Z))
  └──────────────────────┘
             │
             ▼
  ┌──────────────────────┐
  │    glv_mul_2d()      │ ──► (128-бітний константний цикл Штрауса)
  └──────────────────────┘
             │
             ▼
[Результат Q = [k]P (X:Y:Z)]
```

Для забезпечення кеш-локальності інструкцій процесора (L1 Instruction Cache) усі функції скалярного множення згруповані в один лінкований модуль. Це мінімізує промахи інструкцій кешу під час інтенсивної підписной навантаженості.
