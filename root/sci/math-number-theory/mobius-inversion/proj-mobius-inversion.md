# ⚙️ Практичні алгоритми та обчислення обернення Мьобіуса

Цей практичний посібник розглядає високопродуктивні обчислювальні алгоритми, пов'язані з оберненням Мьобіуса: лінійне решето для побудови таблиць значень `μ(n)`, метод блокового ділення для обчислення гіперболічних сум за час `O(√N)` та алгоритм підрахунку кількості взаємно простих пар.

## 1. Побудова таблиці значень Мьобіуса за допомогою лінійного решета

Для швидкої обробки масових чисельно-теоретичних запитів необхідно вміти обчислювати значення `μ(n)` для всіх `n ∈ [1, N]` за лінійний час `O(N)` та лінійну пам'ять `O(N)`.

Звичайний решетоподібний підхід підсумовування за дільниками вимагає `O(N log N)` кроків, що є занадто повільним при `N > 10⁷`. Проте, оскільки `μ(n)` є мультиплікативною функцією, її значення на кожному цілому числі можна обчислити одночасно з генерацією простих чисел у лінійному решеті Ератосфена-Ейлера.

### Алгоритмічна ідея та інваріанти циклу:
1. Масив `primes` зберігає всі знайдені прості числа у порядку зростання.
2. Булевий масив `is_prime` відстежує прості числа.
3. Масив `mu` зберігає значення `μ(n)`.
4. Базовий випадок: `mu[1] = 1`.
5. Для кожного числа `i` від `2` до `N`:
   - Якщо `i` — просте (тобто `is_prime[i] == true`), додаємо його до списку `primes` та встановлюємо `mu[i] = -1`, оскільки просте число має один простий множник (`r = 1`).
   - Проходимо по всіх елементах `p ∈ primes`, таких що `p · i ≤ N`:
     - Позначаємо число `p · i` як складене (`is_prime[p · i] = false`).
     - Якщо `i` ділиться на `p` (`i % p == 0`), це означає, що число `p · i` ділиться на квадрат `p²`. Згідно з означенням функції Мьобіуса, встановлюємо `mu[p · i] = 0`. Обов'язково перериваємо внутрішній цикл (`break`), оскільки будь-яке наступне просте число буде більшим за мінімальний простий дільник числа `i`, а отже, складене число `p' · i` буде помарковане пізніше своїм власним найменшим простим множником.
     - Якщо `i` не ділиться на `p` (`i % p != 0`), то `p` та `i` є взаємно простими. За властивістю мультиплікативності `mu[p · i] = mu[p] · mu[i] = -mu[i]`.

### Покроковий простежувальний розбір для N = 10:
Розглянемо виконати алгоритму лінійного решета крок за кроком для `N = 10`:
- **Початковий стан:** `mu[1] = 1`, `primes = []`, `is_prime = [true, ..., true]`.
- **Крок i = 2:** `2` є простим. Додаємо `2` до `primes = [2]`, встановлюємо `mu[2] = -1`.
  - Внутрішній цикл `p = 2`: `p * i = 4 <= 10`. Позначаємо `is_prime[4] = false`. Оскільки `2 % 2 == 0`, встановлюємо `mu[4] = 0` та робимо `break`.
- **Крок i = 3:** `3` є простим. Додаємо `3` до `primes = [2, 3]`, встановлюємо `mu[3] = -1`.
  - Внутрішній цикл `p = 2`: `p * i = 6 <= 10`. `is_prime[6] = false`. `3 % 2 != 0` ➔ `mu[6] = -mu[3] = 1`.
  - Внутрішній цикл `p = 3`: `p * i = 9 <= 10`. `is_prime[9] = false`. `3 % 3 == 0` ➔ `mu[9] = 0`, робимо `break`.
- **Крок i = 4:** `4` вже складене.
  - Внутрішній цикл `p = 2`: `p * i = 8 <= 10`. `is_prime[8] = false`. `4 % 2 == 0` ➔ `mu[8] = 0`, робимо `break`.
- **Крок i = 5:** `5` є простим. Додаємо `5` до `primes = [2, 3, 5]`, встановлюємо `mu[5] = -1`.
  - Внутрішній цикл `p = 2`: `p * i = 10 <= 10`. `is_prime[10] = false`. `5 % 2 != 0` ➔ `mu[10] = -mu[5] = 1`.
  - Наступні `p * i > 10`, цикл виходить.
- **Підсумковий масив `mu` для 1..10:** `[1, -1, -1, 0, -1, 1, -1, 0, 0, 1]`.

Кожне складене число було помарковано рівно один раз своїм найменшим простим множником, що гарантує підсумкову лінійну складність `O(N)`.

:::tabs
```py
def build_mobius_sieve(n: int) -> tuple[list[int], list[int]]:
    """
    Обчислює масив значень mu[1..N] та список простих чисел за час O(N).
    """
    mu = [0] * (n + 1)
    is_prime = [True] * (n + 1)
    primes = []

    mu[1] = 1
    is_prime[0] = is_prime[1] = False

    for i in range(2, n + 1):
        if is_prime[i]:
            primes.append(i)
            mu[i] = -1

        for p in primes:
            if p * i > n:
                break
            is_prime[p * i] = False
            if i % p == 0:
                mu[p * i] = 0
                break
            else:
                mu[p * i] = -mu[i]

    return mu, primes
```
```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

typedef struct {
    int* mu;
    int* primes;
    int prime_count;
} mobius_sieve_t;

mobius_sieve_t create_mobius_sieve(int n) {
    mobius_sieve_t res;
    res.mu = (int*)malloc((n + 1) * sizeof(int));
    res.primes = (int*)malloc((n + 1) * sizeof(int));
    bool* is_prime = (bool*)malloc((n + 1) * sizeof(bool));
    res.prime_count = 0;

    for (int i = 0; i <= n; i++) {
        is_prime[i] = true;
        res.mu[i] = 0;
    }
    res.mu[1] = 1;
    is_prime[0] = is_prime[1] = false;

    for (int i = 2; i <= n; i++) {
        if (is_prime[i]) {
            res.primes[res.prime_count++] = i;
            res.mu[i] = -1;
        }
        for (int j = 0; j < res.prime_count; j++) {
            int p = res.primes[j];
            if (p * i > n) break;
            is_prime[p * i] = false;
            if (i % p == 0) {
                res.mu[p * i] = 0;
                break;
            } else {
                res.mu[p * i] = -res.mu[i];
            }
        }
    }

    free(is_prime);
    return res;
}

void free_mobius_sieve(mobius_sieve_t* sieve) {
    free(sieve->mu);
    free(sieve->primes);
    sieve->mu = NULL;
    sieve->primes = NULL;
}
```
```cpp
#include <vector>
#include <cstdint>
#include <iostream>

struct MobiusSieve {
    std::vector<int32_t> mu;
    std::vector<int32_t> primes;

    explicit MobiusSieve(size_t n) : mu(n + 1, 0) {
        std::vector<bool> is_prime(n + 1, true);
        mu[1] = 1;
        is_prime[0] = is_prime[1] = false;

        primes.reserve(n / 10);

        for (size_t i = 2; i <= n; ++i) {
            if (is_prime[i]) {
                primes.push_back(static_cast<int32_t>(i));
                mu[i] = -1;
            }
            for (int32_t p : primes) {
                if (p * i > n) break;
                is_prime[p * i] = false;
                if (i % p == 0) {
                    mu[p * i] = 0;
                    break;
                } else {
                    mu[p * i] = -mu[i];
                }
            }
        }
    }
};
```

## 2. Метод блокового ділення для обчислення сум у O(√N)

Багато чисельно-теоретичних задач вимагають обчислення сум вигляду:

```
S(N) = ∑_{d=1}^N μ(d) · f( ⌊N / d⌋ )
```

Пряме підсумовування від `d = 1` до `N` вимагає `O(N)` операцій. Проте ціла частина ділення `k = ⌊N / d⌋` набуває лише невеликої кількості унікальних значень.

### Ключове лематичне спостереження:
Для будь-якого цілого `N` кількість різних значень `⌊N / d⌋` при `1 ≤ d ≤ N` не перевищує `2 · √N`:
- Для `d ≤ √N` значення `d` набуває не більше `√N` різних варіантів.
- Для `d > √N` частка `k = ⌊N / d⌋ < √N` також набуває не більше `√N` різних цілих значень.

Якщо для поточного лівого краю `L` обчислити `k = ⌊N / L⌋`, то максимальне значення правого краю `R`, на якому `⌊N / R⌋ = k`, визначається за абсолютною формулою:

```
R = ⌊ N / ⌊N / L⌋ ⌋ = ⌊ N / k ⌋
```

Усі `d ∈ [L, R]` мають одне й те саме значення `⌊N / d⌋ = k`. Отже, суму по цьому діапазону можна зафіксувати за одну операцію:

```
∑_{d=L}^R μ(d) · f(k) = f(k) · [ M(R) - M(L - 1) ]
```

де `M(x) = ∑_{i=1}^x μ(i)` — префіксна сума значень функції Мьобіуса (функція Мертенса).

### Алгоритм підрахунку кількості взаємно простих пар
Застосуємо метод блокового ділення для обчислення кількості взаємно простих пар `(i, j)` у квадратній ґратці `1 ≤ i, j ≤ N`.

Як доведено у теорії, ця кількість дорівнює `K(N) = ∑_{d=1}^N μ(d) · ⌊N / d⌋²`.

1. Спочатку за допомогою лінійного решета будуємо масив `mu` для всіх `1 ≤ d ≤ N`.
2. Обчислимо масив префіксних сум `pref_m[i] = pref_m[i-1] + mu[i]`.
3. Ініціалізуємо змінні `total_pairs = 0` та ліву межу `L = 1`.
4. У циклі поки `L ≤ N`:
   - Знаходимо значення частки `k = N / L`.
   - Обчислюємо праву межу блоку `R = N / k`.
   - Сума значень Мьобіуса на блоці `[L, R]` дорівнює `sum_mu = pref_m[R] - pref_m[L - 1]`.
   - Додаємо до загального суми добуток `sum_mu · (k · k)`.
   - Зсуваємо ліву межу на наступний блок: `L = R + 1`.

### Простежувальний розбір блоків для N = 10:
Для `N = 10` префіксні суми `pref_m` для `0..10` дорівнюють `[0, 1, 0, -1, -1, -2, -1, -2, -2, -2, -1]`.
- **Блок 1 (L = 1):** `k = 10 / 1 = 10`. `R = 10 / 10 = 1`. Блок `[1, 1]`. `sum_mu = pref_m[1] - pref_m[0] = 1 - 0 = 1`. Додаток: `1 · 10² = 100`. `L` стає `2`.
- **Блок 2 (L = 2):** `k = 10 / 2 = 5`. `R = 10 / 5 = 2`. Блок `[2, 2]`. `sum_mu = pref_m[2] - pref_m[1] = 0 - 1 = -1`. Додаток: `-1 · 5² = -25`. `L` стає `3`.
- **Блок 3 (L = 3):** `k = 10 / 3 = 3`. `R = 10 / 3 = 3`. Блок `[3, 3]`. `sum_mu = pref_m[3] - pref_m[2] = -1 - 0 = -1`. Додаток: `-1 · 3² = -9`. `L` стає `4`.
- **Блок 4 (L = 4):** `k = 10 / 4 = 2`. `R = 10 / 2 = 5`. Блок `[4, 5]`. `sum_mu = pref_m[5] - pref_m[3] = -2 - (-1) = -1`. Додаток: `-1 · 2² = -4`. `L` стає `6`.
- **Блок 5 (L = 6):** `k = 10 / 6 = 1`. `R = 10 / 1 = 10`. Блок `[6, 10]`. `sum_mu = pref_m[10] - pref_m[5] = -1 - (-2) = 1`. Додаток: `1 · 1² = 1`. `L` стає `11`.
- **Підсумок:** `100 - 25 - 9 - 4 + 1 = 63` взаємно простих пар.

Замість 10 кроків ми виконали лише 5 блокових операцій. При `N = 10⁶` кількість кроків зменшується з 1,000,000 до 2,000.

:::tabs
```py
def count_coprime_pairs(n: int) -> int:
    """
    Обчислює кількість взаємно простих пар (i, j) таких, що 1 <= i, j <= N.
    Складність: O(N) на преобробку + O(√N) на обчислення суми.
    """
    mu, _ = build_mobius_sieve(n)

    # Побудова масиву префіксних сум M(x)
    pref_m = [0] * (n + 1)
    for i in range(1, n + 1):
        pref_m[i] = pref_m[i - 1] + mu[i]

    total_pairs = 0
    l = 1

    # Блокове підсумовування за O(√N) кроків
    while l <= n:
        k = n // l
        r = n // k
        block_sum_mu = pref_m[r] - pref_m[l - 1]
        total_pairs += block_sum_mu * (k * k)
        l = r + 1

    return total_pairs
```
```c
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

long long count_coprime_pairs(int n) {
    mobius_sieve_t sieve = create_mobius_sieve(n);
    long long* pref_m = (long long*)malloc((n + 1) * sizeof(long long));
    pref_m[0] = 0;
    for (int i = 1; i <= n; i++) {
        pref_m[i] = pref_m[i - 1] + sieve.mu[i];
    }

    long long total_pairs = 0;
    int l = 1;

    while (l <= n) {
        int k = n / l;
        int r = n / k;
        long long block_sum_mu = pref_m[r] - pref_m[l - 1];
        total_pairs += block_sum_mu * ((long long)k * k);
        l = r + 1;
    }

    free(pref_m);
    free_mobius_sieve(&sieve);
    return total_pairs;
}
```
```cpp
#include <vector>
#include <cstdint>
#include <iostream>

uint64_t count_coprime_pairs_fast(int32_t n) {
    MobiusSieve sieve(n);
    std::vector<int64_t> pref_m(n + 1, 0);

    for (size_t i = 1; i <= static_cast<size_t>(n); ++i) {
        pref_m[i] = pref_m[i - 1] + sieve.mu[i];
    }

    uint64_t total_pairs = 0;
    int32_t l = 1;

    while (l <= n) {
        int32_t k = n / l;
        int32_t r = n / k;
        int64_t block_sum_mu = pref_m[r] - pref_m[l - 1];
        total_pairs += static_cast<uint64_t>(block_sum_mu) * static_cast<uint64_t>(k) * static_cast<uint64_t>(k);
        l = r + 1;
    }

    return total_pairs;
}
```

## 3. Сублінійні алгоритми (Ду Сито та Min_25)

Для гігантських значень `N > 10⁹` лінійне побудування масиву префіксних сум виділяє занадто багато пам'яті (кілька гігабайт), що стає неприйнятним.

Сучасні обчислювальні алгоритми використовують сублінійні підходи, такі як **алгоритм Дю (Du Sieve)**, який дозволяє обчислити `M(N) = ∑_{i=1}^N μ(i)` за час `O(N^{2/3})` з використання пам'яті лише `O(N^{2/3})`.

### Алгоритмічна ідея сублінійного обчислення M(N):
Згортка `μ * 1 = e` дає фундаментальне рекурентне співвідношення для префіксної суми:

```
∑_{i=1}^N (μ * 1)(i) = ∑_{i=1}^N e(i) = 1
```

Розкриваючи внутрішню згортку та змінюючи порядок підсумовування, отримуємо:

```
∑_{d=1}^N M( ⌊N / d⌋ ) = 1   ⇒   M(N) = 1 - ∑_{d=2}^N M( ⌊N / d⌋ )
```

Ця формула дозволяє обчислити `M(N)` рекурсивно!
- Для малих `x ≤ N^{2/3}` значення `M(x)` попередньо обчислюються за допомогою лінійного решета за `O(N^{2/3})` та зберігаються у звичайному масиві.
- Для великих `x > N^{2/3}` значення `M(x)` обчислюються рекурсивно за наведеною формулою з використанням блокового ділення та хеш-таблиці (або розрідженого масиву за індексами `N / x`) для запам'ятовування вже обчислених значень (мемоізації).

Завдяки цьому час обчислення `M(N)` зменшується з `O(N)` до `O(N^{2/3})`, що дозволяє обчислювати префіксні суми Мьобіуса для `N = 10¹¹` за частки секунди на звичайному процесорі.

## 4. Практичні пастки та оптимізація пам'яті

1. **Переповнення типів даних:**
   Значення сум вигляду `k * k` або `(n / l) * (n / l)` для `N = 10⁶` досягають `10¹²`, що виходить за межі стандартного 32-бітного цілого `int32_t`. Завжди використовуйте 64-бітні цілі типи (`long long` у C, `int64_t` / `uint64_t` у C++, `int` у Python).

2. **Кешовування префіксних сум та локальність даних:**
   Побудова префіксного масиву `pref_m` вимагає суцільного виділення пам'яті. У C та C++ використання неперервних векторів `std::vector<int64_t>` забезпечує ідеальну кеш-локальність процесора при підсумовуванні блоків, що в 5-10 разів прискорює обчислення порівняно зі списковими структурами даних.
