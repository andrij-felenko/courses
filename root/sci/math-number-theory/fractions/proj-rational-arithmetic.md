# ⚙️ Реалізація класу точної арифметики звичайних дробів

Ця програма показує створення надійного класу точної раціональної арифметики мовами C та C++. Реалізація вирішує проблему накопичення помилок округлення чисел із плаваючою крапкою (IEEE 754) у фінансових, геометричних та комп'ютерно-алгебраїчних обчисленнях за допомогою автоматичного скорочення дробів через найбільший спільний дільник (НСД) та підтримки точності чисельника й знаменника.

## 1. Архітектурні вимоги та математичні інваріанти

При розробці типів даних для роботи зі звичайними дробами у програмному забезпеченні критичної надійності виникає потреба вирішення двох фундаментальних проблем: гарантування канонічності представлення даних та захисту від арифметичного переповнення типів фіксованої розрядності.

### Чотири інваріанти раціонального об'єкта

Кожен екземпляр раціонального числа у пам'яті комп'ютера мусить неперервно підтримувати чотири базові інваріанти:

1. **Канонічна форма знаків:** Знаменник завжди є строго додатним натуральним числом (`den > 0`). Знак раціонального числа зберігається виключно у чисельнику (`num`). Якщо чисельник і знаменник від'ємні (`num < 0` та `den < 0`), їхні знаки інвертуються у додатні. Якщо від'ємним є знаменник (`den < 0`), знак мінуса переноситься на чисельник. Це усуває проблему подвійної репрезентації одного й того самого від'ємного дробу як `(-a)/b` та `a/(-b)`.
2. **Гарантована нескоротність:** Чисельник і знаменник є взаємно простими числами:
```
gcd(|num|, den) = 1                [інваріант нескоротності]
```
Будь-який дріб скорочується на свій найбільший спільний дільник одразу під час конструювання або після завершення кожної арифметичної операції. Це мінімізує обсяг пам'яті та запобігає зайвому зростанню розрядності при проміжних обчисленнях.
3. **Строга обробка ділення на нуль:** Знаменник не може дорівнювати нулю (`den ≠ 0`). Спроба створити дріб із `den = 0` або виконати ділення на нульовий дріб (`num = 0`) є грубим порушенням математичного контракту. У мові C це обробляється поверненням прапорця помилки через вказівник або спеціальним кодом статусу. У мові C++ реалізується генерація стандартних винятків `std::invalid_argument` або `std::domain_error`.
4. **Захист від цілочисельного переповнення:** Прямолінійне обчислення суми двох дробів `a/b + c/d = (a · d + b · c) / (b · d)` вимагає множення знаменників `b · d`. Якщо обидва знаменники близькі до `2^30`, їхній добуток досягає `2^60`, що наближається до верхньої межі знакового 64-бітного цілого типу `int64_t` (`2^63 - 1`). Застосування попереднього ділення на `gcd(b, d)` знижує порядок проміжних значень у кілька разів.

## 3. Детальний аналіз алгоритмічних оптимізацій

### 1. Додавання та віднімання через найменший спільний знаменник

Найпростіша реалізація додавання звичайних дробів `a/b + c/d` обчислює суму як `(a · d + b · c) / (b · d)`. Однак такий підхід призводить до невиправдано високого зростання розрядності чисельника та знаменника.

Оптимальний алгоритм використовує НСД знаменників:
```
g = gcd(b, d)                          [пошук НСД знаменників]
b' = b / g,   d' = d / g               [обчислення додаткових множників]
N = a · d' + c · b'                    [результуючий чисельник]
M = b · d'                             [найменший спільний знаменник]
```
Після обчислення `N` та `M` проводиться остаточне скорочення на `g_res = gcd(N, M)`. Оскільки `b'` та `d'` є меншими за `b` та `d` у `g` разів, проміжні множення `a · d'` здійснюються з меншими числами, що зменшує ймовірність переповнення типу у `g` разів.

### 2. Множення зі скороченням навхрест

Прямолінійне множення двох дробів `r1 = a/b` та `r2 = c/d` обчислює чисельник `a · c` та знаменник `b · d`, після чого скорочує результат на `gcd(a · c, b · d)`. Проте добутки `a · c` та `b · d` можуть викликати цілочисельне переповнення ще до виконання скорочення.

Оптимальний підхід полягає у попередньому скороченні "навхрест":
```
g1 = gcd(a, d)                         [НСД першого чисельника та другого знаменника]
g2 = gcd(c, b)                         [НСД другого чисельника та першого знаменника]

a' = a / g1,   d' = d / g1             [скорочення першої пари]
c' = c / g2,   b' = b / g2             [скорочення другої пари]

num = a' · c'                          [результуючий чисельник]
den = b' · d'                          [результуючий знаменник]
```

Оскільки вихідні дроби `a/b` та `c/d` вже були нескоротними (`gcd(a, b) = 1` та `gcd(c, d) = 1`), чисельник `a'` та знаменник `b'` є взаємно простими із `d'` та `c'`. Отже, оновлений дріб `(a' · c') / (b' · d')` є **гарантовано нескоротним**, i додаткове обчислення НСД наприкінці не потрібне.

### 3. Порівняння двох звичайних дробів без переповнення

Для порівняння двох дробів `a/b` та `c/d` (де `b > 0, d > 0`) найпростіша перевірка рівності або нерівності полягає у порівнянні хрестових добутків:
```
a · d  проти  b · c                    [хрестовий добуток для порівняння]
```

Однак якщо знаменники великі, добутки `a · d` можуть переповнювати 64-бітний діапазон. В оптимізованій арифметиці порівняння виконується через цілочисельне ділення з остачею:
```
q1 = a / b,   r1 = a % b               [ціла частина та остача першого дробу]
q2 = c / d,   r2 = c % d               [ціла частина та остача другого дробу]
```
Якщо `q1 ≠ q2`, то результат порівняння визначається цілими частинами `q1` та `q2`. Якщо ж `q1 = q2`, порівняння рекурсивно зводиться до порівняння знаменників та остач: `d / r2` проти `b / r1`. Це забезпечує точне порівняння за `O(log(min(b, d)))` кроків без ризику переповнення.

## 4. Організація пам'яті та лінійна вирівняність об'єкта

У мові C++ клас `Rational` містить два приватні члени даних `m_num` та `m_den` типу `std::int64_t`.

Завдяки цьому розмір екземпляра у пам'яті становить точно 16 байт (8 байт на чисельник + 8 байт на знаменник):
```
+-------------------+-------------------+
|  m_num (8 байт)   |  m_den (8 байт)   |
+-------------------+-------------------+
```

Об'єкт є Trivially Copyable та підтримує передачу за значенням через регістри процесора x86-64 / ARM64. Метод `constexpr` дозволяє виконувати раціональну арифметику безпосередньо під час компіляції (compile-time evaluation), обчислюючи дробові константи на етапі збирання проєкту.

## 5. Порівняльний аналіз формату точних дробів із плаваючою та фіксованою крапкою

У комп'ютерній інженерії вибір числового представлення є компромісом між швидкістю, обсягом пам'яті та точністю обчислень.

| Властивість / Формат | Звичайні дроби (`Rational`) | Плаваюча крапка (`IEEE 754 double`) | Фіксована крапка (`Fixed-Point`) |
| :--- | :--- | :--- | :--- |
| **Точність обчислень** | Абсолютно точна (0 помилок) | Приблизна (накопичення округлень) | Фіксована дискретність (`1/2^k`) |
| **Представлення 1/3** | Точно `1/3` | `0.33333333333333331482...` (помилка) | `0.33333333...` (неточно) |
| **Апаратна підтримка** | Програмна (інструкції ALU + Евклід) | Апаратна FPU (FADD, FMUL) | Швидка цілочисельна ALU |
| **Обсяг пам'яті** | 16 байт (`int64` + `int64`) | 8 байт | 4 або 8 байт |
| **Швидкість операцій** | Повільніша через НСД `gcd` | Дуже висока (1-3 такти CPU) | Максимальна (1 такт CPU) |

Використання класу звичайних дробів є виправданим у комп'ютерній алгебрі (CAS), обчисленні інваріантів у комбінаториці, фінансовому обліку коштів, а також при вирішенні лінійних систем діофантових рівнянь, де навіть мінімальна помилка округлення у першому знаку призводить до спотворення фінального результату.
