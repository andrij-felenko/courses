# ⚙️ Реалізація класу точної арифметики звичайних дробів

Ця практична розробка демонструє проєктування та створення високоефективного й надійного класу точної раціональної арифметики мовами C та C++. Реалізація усуває фундаментальну проблему накопичення похибок округлення чисел із плаваючою крапкою стандарту IEEE 754 у комп'ютерній геометрії, фінансових розрахунках, комп'ютерній алгебрі та системах автоматизованого проєктування за допомогою автоматичного скорочення дробів через найбільший спільний дільник (НСД), контролю знаків і захисту від арифметичного переповнення.

## 1. Архітектурні вимоги та фундаментальні інваріанти

При розробці типів даних для роботи зі звичайними дробами у програмному забезпеченні підвищеної надійності виникає потреба одночасного вирішення двох ключових завдань: гарантування канонічності представлення даних у пам'яті та мінімізації ризику переповнення розрядної сітки процесора.

### Чотири інваріанти раціонального об'єкта

Кожен екземпляр раціонального числа у пам'яті комп'ютера мусить безперервно підтримувати чотири базові інваріанти стану:

1. **Канонічна форма знаків:**
Знаменник дробу завжди є строго додатним цілим числом (`den > 0`). Знак раціонального числа зберігається виключно у чисельнику (`num`). Якщо при конструюванні або в результаті операції чисельник і знаменник є від'ємними (`num < 0` та `den < 0`), їхні знаки взаємно інвертуються у додатні. Якщо від'ємним є знаменник (`den < 0`), знак мінуса переноситься на чисельник. Це усуває проблему подвійної репрезентації одного й того самого від'ємного дробу як `(-a)/b` та `a/(-b)` і спрощує побітове порівняння об'єктів.

2. **Гарантована нескоротність:**
Чисельник і знаменник є взаємно простими числами:
```
gcd(|num|, den) = 1                [інваріант нескоротності]
```
Будь-який дріб нормалізується (ділиться на свій найбільший спільний дільник) одразу під час конструювання або після завершення кожної арифметичної операції. Це мінімізує величину чисел у регістрах процесора та запобігає зайвому лавиноподібному зростанню розрядності при послідовних проміжних обчисленнях.

3. **Строгий контракт обробки нуля:**
Знаменник дробу не може дорівнювати нулю (`den ≠ 0`). Спроба створити дріб із `den = 0` або виконати ділення на нульовий дріб (`num = 0`) є грубим порушенням математичного контракту. У мові C це обробляється поверненням спеціального коду помилки переліку `rational_status_t` (`RATIONAL_ERR_ZERO_DENOMINATOR` або `RATIONAL_ERR_DIV_BY_ZERO`). У мові C++ реалізується генерація стандартних винятків `std::invalid_argument` або `std::domain_error`.

4. **Мінімізація проміжних переповнень:**
Прямолінійне обчислення суми двох дробів `a/b + c/d = (a · d + b · c) / (b · d)` вимагає обчислення добутку знаменників `b · d`. Якщо обидва знаменники близькі до `2^31`, їхній добуток досягає `2^62`, що наближається до верхньої межі знакового 64-бітного цілого типу `int64_t` (`2^63 - 1`). Застосування попереднього ділення на `gcd(b, d)` знижує розрядність проміжних множень у `gcd(b, d)` разів, зберігаючи обчислення в межах 64-бітного діапазону.

## 3. Детальний математичний аналіз алгоритмічних оптимізацій

Реалізація раціональної арифметики вимагає оптимізації кожної базової операції для запобігання передчасному арифметичному переповненню типів фіксованої довжини.

### 1. Додавання та віднімання через найменший спільний знаменник

Прямолінійне додавання двох звичайних дробів `a/b + c/d` обчислює суму за шкільною формулою `(a · d + b · c) / (b · d)`. Якщо знаменники `b` та `d` мають великий спільний дільник (наприклад, `b = 10^9, d = 10^9`), їхній добуток дорівнює `10^18`, що майже вичерпує діапазон 64-бітного цілого числа, хоча спільний знаменник насправді дорівнює лише `10^9`.

Оптимальний алгоритм використовує найменший спільний знаменник через НСД:
```
g = gcd(b, d)                          [обчислення НСД знаменників]
b' = b / g,   d' = d / g               [додаткові скорочені множники]
N = a · d' + c · b'                    [результуючий чисельник]
M = b · d'                             [найменший спільний знаменник: lcm(b, d)]
```

Після обчислення `N` та `M` проводиться остаточна нормалізація на `g_res = gcd(|N|, M)`. Оскільки `b'` та `d'` у `g` разів менші за вихідні знаменники `b` та `d`, проміжні множення `a · d'` та `c · b'` не призводять до виходу за межі розрядності, а результуючий знаменник `M` є строго найменшим спільним кратним `lcm(b, d) = (b · d) / g`.

### 2. Множення та ділення зі скороченням навхрест

При множенні двох дробів `r1 = a/b` та `r2 = c/d` пряме перемноження `(a · c) / (b · d)` може спричинити переповнення чисельника або знаменника навіть тоді, коли кінцевий скорочений дріб чудово поміщається у 64 біти (наприклад, `(10^9 / 7) · (7 / 10^9) = 1/1`).

Оптимальний підхід здійснює попереднє скорочення перехресних пар чисел:
```
g1 = gcd(|a|, d)                       [НСД першого чисельника та другого знаменника]
g2 = gcd(|c|, b)                       [НСД другого чисельника та першого знаменника]

a' = a / g1,   d' = d / g1             [попереднє скорочення першої пари]
c' = c / g2,   b' = b / g2             [попереднє скорочення другої пари]

num = a' · c'                          [фінальний чисельник]
den = b' · d'                          [фінальний знаменник]
```

**Теорема про збереження нескоротності:** Якщо вихідні дроби `a/b` та `c/d` були нескоротними (`gcd(|a|, b) = 1` та `gcd(|c|, d) = 1`), то обчислений дріб `(a' · c') / (b' · d')` є **гарантовано нескоротним**.

*Доведення:* Будь-який спільний простий дільник `p` чисел `(a' · c')` та `(b' · d')` повинен ділити один із множників чисельника (`a'` або `c'`) та один із множників знаменника (`b'` або `d'`).
- Якщо `p | a'` та `p | b'`, це суперечить вихідній нескоротності `gcd(|a|, b) = 1`.
- Якщо `p | a'` та `p | d'`, це суперечить тому, що пара `(a, d)` була повністю скорочена на `g1 = gcd(|a|, d)`.
- Якщо `p | c'` та `p | b'`, це суперечить тому, що пара `(c, b)` була повністю скорочена на `g2 = gcd(|c|, b)`.
- Якщо `p | c'` та `p | d'`, це суперечить вихідній нескоротності `gcd(|c|, d) = 1`.

Отже, `gcd(|num|, den) = 1`, i повторне обчислення НСД наприкінці операції множення взагалі не потрібне, що дає значний виграш у швидкодії.

Операція ділення `(a/b) / (c/d)` зводиться до множення на обернений дріб `(a/b) · (d/c)` за умови попередньої перевірки `c ≠ 0`.

### 3. Безпечне порівняння дробів без 64-бітного переповнення

Для визначення відношення порядку між двома дробами `a/b` та `c/d` (де `b > 0, d > 0`) наївна перевірка порівнює хрестові добутки:
```
a · d  проти  b · c                    [хрестовий добуток для порівняння]
```

Якщо знаменники `b` та `d` перевищують `3 · 10^9`, обчислення добутку `a · d` виходить за межі `int64_t` і призводить до хибного результату через переповнення знакового біта.

В алгоритмічно досконалій раціональній арифметиці порівняння здійснюється за допомогою покрокового алгоритму евклідового ділення з остачею:
```
q1 = a / b,   r1 = a % b               [ціла частина та остача першого дробу]
q2 = c / d,   r2 = c % d               [ціла частина та остача другого дробу]
```

1. Якщо цілі частини не рівні (`q1 ≠ q2`), результат порівняння повністю визначається знаком нерівності `q1` проти `q2`.
2. Якщо цілі частини збігаються (`q1 = q2`), то нерівність `r1 / b < r2 / d` еквівалентна оберненій нерівності знаменників:
```
d / r2 < b / r1                        [інверсія порівняння залишків]
```
3. Алгоритм рекурсивно або в ітеративному циклі переходить до порівняння пари нових дробів `d / r2` та `b / r1`.

Оскільки залишки `r1` та `r2` строго спадають на кожній ітерації за властивістю алгоритму Евкліда, алгоритм порівняння завершується максимум за `O(log(min(b, d)))` кроків, виконуючи виключно операції ділення в межах вихідних значень без ризику переповнення.

### 4. Бінарне піднесення до цілого степеня

Піднесення раціонального числа `r` до цілого степеня `exp` здійснюється за алгоритмом швидкого піднесення до степеня (швидке множення за двійковим розкладом показника):
- Якщо `exp = 0`, результат дорівнює `1/1`.
- Якщо `exp < 0`, дріб інвертується `(b/a)` (за умови `a ≠ 0`), а показник замінюється на `-exp`.
- Для додатного показника `exp` обчислення виконується за `O(log exp)` множень:
```
result = 1/1,   base = a/b
while (exp > 0) {
    if (exp % 2 == 1) result = result · base
    base = base · base
    exp = exp / 2
}
```

## 4. Оптимізація обчислення НСД: Двійковий алгоритм Стейна

Швидкодія операцій нормалізації дробів безпосередньо залежить від ефективності функції знаходження найбільшого спільного дільника `gcd`.

Класичний алгоритм Евкліда на кожному кроці виконує команду цілочисельного ділення з остачею `a % b`. На сучасних процесорах архітектури x86-64 та ARM інструкція ділення `idiv` є відносно повільною і вимагає від 15 до 40 тактів процесора (залежно від мікроархітектури та розрядності операндів).

У високонавантажених бібліотеках раціональної арифметики класичний алгоритм часто замінюють на **двійковий алгоритм Евкліда** (алгоритм Стейна), який замінює важкі операції ділення на швидкі побітові зсуви, віднімання та операцію підрахунку кількості нульових молодших бітів (англ. *count trailing zeros*, інструкція `tzcnt` або `__builtin_ctzll`):

```
1. Якщо a = 0 або b = 0, повертаємо a | b;
2. Знаходимо спільний двійковий степінь: k = ctz(a | b);
3. Зсуваємо a праворуч: a >>= ctz(a);
4. Поки b ≠ 0:
     b >>= ctz(b);
     якщо a > b, міняємо місцями a та b;
     b = b - a;
5. Повертаємо a << k.
```

Оскільки побітові зсуви та віднімання виконуються процесором за 1 такт, алгоритм Стейна забезпечує прискорення нормалізації раціональних чисел на 30–45% у порівнянні з класичним діленням з остачею.

## 5. Організація пам'яті та апаратна ефективність

Екземпляр раціонального числа містить два 64-бітних знакових цілих поля `num` та `den`:
```
+-----------------------------------+-----------------------------------+
|          num (8 байтів)           |          den (8 байтів)           |
+-----------------------------------+-----------------------------------+
|<--------------------------- 16 байтів ------------------------------->|
```

### Переваги низькорівневої організації:

1. **Фіксований компактний розмір (16 байтів):**
Структура займає рівно 16 байтів і вирівняна за 8-байтовою межею. Вона не містить динамічних вказівників, таблиць віртуальних методів (`vptr`) чи службових заголовків пам'яті.

2. **Відсутність динамічного виділення пам'яті:**
На відміну від універсальних бібліотек довгої арифметики (таких як GNU MP `mpq_t` або Boost.Multiprecision), де кожен чисельник і знаменник виділяються у динамічній купі (heap allocation), об'єкт `Rational` повністю розміщується на стеку або у кеші процесора L1. Це усуває накладні витрати на виклики `malloc`/`free`, фрагментацію пам'яті та промахи кешу (cache misses), забезпечуючи прискорення операцій у 10–50 разів.

3. **Передача через регістри процесора (System V x86-64 ABI):**
Згідно зі специфікацією System V ABI для архітектури x86-64, структури розміром до 16 байтів класифікуються як два восьмибайтові цілі числа (`INTEGER`) і передаються у функції та повертаються безпосередньо через пари регістрів загального призначення `rdi/rsi` та `rax/rdx`, без використання повільного доступу до оперативної пам'яті.

4. **Підтримка обчислень під час компіляції (`constexpr`):**
Усі конструктори та базові оператори у мові C++ можуть бути оголошені з кваліфікатором `constexpr`. Це дозволяє компілятору виконувати скорочення дробів та раціональну арифметику безпосередньо на етапі трансляції коду, підставляючи у бінарний файл готові числові константи з нульовою вартістю виконання у runtime.

## 6. Парсинг та перетворення рядків і десяткових чисел

У практичних застосунках клас звичайних дробів часто взаємодіє з текстовими форматами введення та виведення (JSON, XML, конфігураційні файли, користувацький ввід).

### 1. Парсинг рядкових представлень
Повнофункціональний клас раціональних чисел підтримує парсинг трьох поширених текстових форматів:
- **Канонічний дріб:** рядки виду `"7/12"`, `"-5/18"`, `"+3/4"`;
- **Ціле число:** рядки виду `"42"`, `"-100"`, які автоматично перетворюються на дроби зі знаменником `1` (`42/1`, `-100/1`);
- **Мішаний дріб:** рядки виду `"2 1/3"` (дві цілих одна третина), які розгортаються у чистий дріб `(2 · 3 + 1) / 3 = 7/3`.

### 2. Точне перетворення десяткових дробів
Будь-який скінченний десятковий дріб із `k` знаками після коми можна точно перетворити на звичайний дріб без використання проміжного типу `double` (який вносить похибку двійкового округлення):
```
0.125  ⇒  125 / 10³ = 125 / 1000  ⇒  gcd(125, 1000) = 125  ⇒  1 / 8
```
Періодичні десяткові дроби також переводяться у звичайні за класичною алгебраїчною формулою: наприклад, дріб `0.(3)` перетворюється на `3/9 = 1/3`, а дріб `0.1(6)` — на `(16 - 1) / 90 = 15/90 = 1/6`.

## 7. Практичні інженерні сценарії використання

Точна арифметика звичайних дробів є незамінним інструментом у низці прикладних галузей, де наближені обчислення з плаваючою крапкою призводять до критичних помилок:

### 1. Комп'ютерна геометрія та САПР (CAD)
В алгоритмах обчислення перетину многокутників, тріангуляції Делоне та побудови діаграм Вороного ключовими є так звані геометричні предикати орієнтації (наприклад, визначення того, з якого боку від прямої лежить точка через знак визначника матриці 3×3). При використанні типу `double` неминучі похибки округлення можуть призвести до топологічних парадоксів: точка перетину прямих може виявитися по інший бік площини, утворюючи самоперетинні контури та провокуючи нескінченні цикли у скануючих алгоритмах (Sweepline). Раціональна арифметика гарантує абсолютну топологічну коректність геометричних моделей.

### 2. Фінансовий облік та криптовалютні транзакції
У міжнародних фінансових розрахунках, розподілі дивідендів та смарт-контрактах сума часток мусить дорівнювати рівно 100% без втрати навіть мінімальної дробової частини цента. Якщо ділити 100 доларів порівну між трьома бенефіціарами у форматі з плаваючою крапкою, кожен отримає `33.333333...`, що в сумі дасть `99.999999...`, викликаючи розбалансування бухгалтерського балансу. Дроби `100/3` зберігають точну балансову суму без втрати коштів.

### 3. Комп'ютерна алгебра та матричні обчислення
При розв'язанні систем лінійних алгебраїчних рівнянь методом Гаусса або обчисленні обернених матриць накопичення похибок у `float/double` швидко призводить до повної втрати значущих цифр для погано обумовлених матриць (велике число обумовленості). Раціональна арифметика дозволяє знайти точні символьні розв'язки лінійних систем без наближень.

## 8. Стратегія тестування та верифікація алгебраїчних інваріантів

Для гарантування абсолютної надійності раціонального класу застосовується комбінація модульного тестування крайових випадків та тестування на основі властивостей (англ. *property-based testing*):

### 1. Перевірка алгебраїчних аксіом на випадкових вибірках
За допомогою генераторів псевдовипадкових 64-бітних цілих чисел формуються трійки раціональних операндів `a, b, c ∈ Q` для автоматичної перевірки збереження законів поля:
- **Комутативність:** `a + b == b + a` та `a · b == b · a`;
- **Асоціативність:** `(a + b) + c == a + (b + c)` та `(a · b) · c == a · (b · c)`;
- **Дистрибутивність:** `a · (b + c) == a · b + a · c`;
- **Існування обернених:** `a + (-a) == 0/1` та `a · (1/a) == 1/1` (для `a ≠ 0`);
- **Транзитивність порядку:** якщо `a < b` та `b < c`, то `a < c`.

### 2. Граничні вектори тестування
Окремий набір тестів перевіряє поведінку класу на межах розрядності:
- Нульовий чисельник: конструювання `0/100` та `0/(-5)` мусить канонічно нормалізуватися до `0/1`;
- Граничні значення знаків: перевірка дробів із максимально можливими 64-бітними знаменниками `1 / INT64_MAX` та чисельниками `INT64_MAX / 1`;
- Обробка ділення на нуль: верифікація генерації винятку `std::domain_error` у C++ та повернення коду статусу `RATIONAL_ERR_DIV_BY_ZERO` у C;
- Тестування циклічного переходу при порівнянні: дроби `1000000000 / 3000000001` проти `1000000001 / 3000000004`.

## 9. Порівняльний аналіз числових форматів

| Характеристика / Формат | Звичайні дроби (`Rational<int64>`) | Плаваюча крапка (`double` IEEE 754) | Фіксована крапка (`Fixed-Point Q32.32`) | Довгі дроби (`mpq_t` GNU MP) |
| :--- | :--- | :--- | :--- | :--- |
| **Математична точність** | Абсолютна (0 похибки) | Наближена (53 біти мантиси) | Фіксований крок (`1/2^32`) | Абсолютна нескінченна |
| **Представлення 1/3** | Точно `1/3` | `0.3333333333333333148...` | `0.3333333332557...` | Точно `1/3` |
| **Розмір у пам'яті** | 16 байтів | 8 байтів | 8 байтів | Від 32 байтів + купа |
| **Динамічна пам'ять** | Ні (тільки стек/регістри) | Ні (FPU регістри) | Ні (ALU регістри) | Так (`malloc` на кожну дію) |
| **Швидкодія операцій** | Висока (десятки тактів CPU) | Ультрависока (1–3 такти FPU) | Максимальна (1 такт ALU) | Низька (тисячі тактів) |
| **Сфера застосування** | САПР, геометрія, фінанси | Фізика, графіка, нейромережі | DSP, мікроконтролери, аудіо | Символьна комп'ютерна алгебра |

Розроблений клас раціональних чисел пропонує оптимальний компроміс: він забезпечує абсолютну математичну точність при збереженні високої швидкодії та нульових накладних витрат на керування динамічною пам'яттю.
