# 📋 Інтерфейс та протокольні специфікації розкладу Цекендорфа

Ця вставка містить повну специфікацію API кодувальника Цекендорфа, бітового формату самосинхронізовного потоку даних (Fibonacci Coding), таблиці розрядів та параметрів часової і просторової складності для апаратних і програмних реалізацій.

## Призначення та сфера застосування інтерфейсу

Фібоначчієве кодування та система числення Цекендорфа застосовуються у системах передачі даних із високим рівнем завад, у стисненні цілочислових масивів (наприклад, індексів у пошукових системах), а також у спеціалізованих апаратних обчислювачах. Головною перевагою цього формату перед класичними двійковими кодами є вроджена властивість самосинхронізації: при втраті або спотворенні бітів у каналі зв'язку декодер здатний відновити межу наступного кодового слова безпосередньо за першою ж комбінацією `11`.

Наведений нижче програмний та протокольний інтерфейс визначає стандартизований спосіб взаємодії між модулем формування фібоначчієвих розрядів, бітовим потоковим писачем та декодером. Інтерфейс гарантує захист від переповнення 64-бітових регістрів, валідацію відсутності заборонених сусідніх одиниць у вхідних даних та узгоджену поведінку для граничних значень.

## 1. Специфікація двійково-фібоначчієвого розрядного сімейства

У фібоначчієвій системі числення вага розряду `i` визначається як `i`-й член послідовності Фібоначчі `Fᵢ₊₂` (де `F₂ = 1`). Вибір початку нумерації з `F₂ = 1` та `F₃ = 2` є фундаментальною вимогою для забезпечення єдиності розкладу, оскільки включення двох перших елементів `F₀ = 0` чи `F₁ = 1` створило б нескінченну кількість еквівалентних записів одного й того самого числа.

## 2. Протокол самосинхронізовного потоку даних (Fibonacci Coding)

Фібоначчієве кодування цілих чисел (Еліаса-Фібоначчі) є префіксним самосинхронізовним кодом змінної довжини. Його структура базується на тому факті, що канонічний розклад Цекендорфа ніколи не містить двох одиниць поспіль у довільній позиції бітового вектора.

### Бітовий формат кодового слова

Кожне кодове слово у мережевому або файловому потоці записується молодшими бітами вперед, після чого додається один термінальний одиничний біт:

```
[b₀] [b₁] [b₂] … [bₖ] [1]
 │    │    │      │    └── Завершальний маркер термінації (завжди 1)
 └────┴────┴──────┴────── Біти розкладу Цекендорфа у порядку зростання вагових коефіцієнтів
```

Оскільки канонічний розклад Цекендорфа **забороняє** наявність двох одиниць поспіль (`bⱼ = 1` та `bⱼ₊₁ = 1` неможливі всередині числа), комбінація двох одиниць підряд `11` у кодовому потоці виникає **виключно** на межі кодового слова, де останній одиничний біт числа з'єднується із термінатором `1`.

### Алгоритм декодування потоку бітів

Процес розбору суцільного бітового потоку виконується наступним чином:

1. Зчитувати біти з потоку по одному у зсувний регістр або віконний буфер довжиною 2 біти.
2. Якщо виявлено підпослідовність `11`, це означає досягнення межі поточного кодового слова.
3. Вилучити останню термінальну одиницю з прочитаної послідовності.
4. Збережені біти `b₀, b₁, …, bₖ` утворюють канонічний розклад Цекендорфа.
5. Обчислити десяткове значення як суму `N = ∑_{i=0}^k bᵢ · Fᵢ₊₂`.
6. Скинути стан зсувного регістра та перейти до обробки наступного кодового слова.

## 3. Специфікація програмного інтерфейсу (C / C++ API)

Для забезпечення сумісності із високоефективними обчислювальними модулями C та C++ розроблено двоієрархічний API. Низькорівневий інтерфейс C працює із сирими буферами пам'яті без динамічного виділення, тоді як високорівневий C++ API використовує безпечні контейнери та механізми обробки помилок.

### Стек помилок та статусні коди

## 4. Оцінка складності алгоритмів та ресурсоємності

Аналіз часової та просторової складності алгоритмів кодування й декодування Цекендорфа показує їхню високу ефективність у порівнянні з іншими універсальними кодами (наприклад, кодами Гамма або Дельта Еліаса):

| Операція | Часова складність (Best/Worst) | Просторова складність | Примітки |
| :--- | :--- | :--- | :--- |
| **Жадібне кодування `encode()`** | `O(log_φ N)` | `O(log_φ N)` | Бінарний пошук або лінійне сканування таблиці Фібоначчі |
| **Декодування `decode()`** | `O(k)` (де `k` — кількість бітів) | `O(1)` | Сумування попередньо обчислених табличних значень |
| **Потокова синхронізація** | `O(1)` на біт | `O(1)` | Виявлення першої пари `11` у вікні довжиною 2 біти |
| **Пряме додавання розкладів** | `O(k)` | `O(k)` | Нормалізація бітового вектора правилами `011→100` та `0200→1001` |

Кількість розрядів `k`, необхідних для запису числа `N`, обчислюється як `k = ⌊log_φ(N · √5)⌋ − 1`. Для 64-бітових чисел максимальна довжина бітового вектора не перевищує 91 біт, що робить статичне виділення буферів пам'яті вкрай компактним.

## 5. Граничні випадки, валідація та обробка помилок

Під час практичної експлуатації кодувальників та декодерів Цекендорфа необхідно враховувати наступні крайові умови:

1. **Вхідне значення `N = 0`:** У класичній теоремі Цекендорфа розклад визначений для натуральних чисел `N ≥ 1`. Для `N = 0` повертається порожній бітовий масив (довжина 0), або генерується статусний код `ZECK_ERROR_OVERFLOW`, якщо нуль заборонений у конкретній підсистемі.
2. **Переповнення 64-бітового цілого типом даних:** Число Фібоначчі `F₉₂` перевищує максимальне значення `2⁶⁴ − 1` (`F₉₂ = 7540113804746346429`). Будь-яка спроба задекодувати потік бітів із включеним розрядом `i ≥ 91` має відсікатися на етапі валідації.
3. **Некоректний потік бітів (порушення канонічності):** Якщо під час декодування вхідного вектора бітів виявлено сусідні одиниці `bits[i] == 1 && bits[i+1] == 1` до кінця слова, декодер зупиняє розбір із помилкою `ZECK_ERROR_INVALID_STREAM`. Це свідчить про спотворення даних або спробу декодувати звичайний двійковий код замість коду Цекендорфа.
4. **Втрата синхронізації у каналі зв'язку:** Якщо через завади один біт у потоці інвертувався `0 → 1`, це може створити хибний маркер `11` раніше часу. У цьому випадку декодер завершує поточне слово із помилковим значенням, але **автоматично відновлює** правильно орієнтовані межі для всіх наступних слів, як тільки зустріне наступну справжню пару `11`.
5. **Апаратна підтримка та регістрове відображення:** У спеціалізованих FPGA та ПЛІС декодер Цекендорфа реалізується у вигляді зсувного регістра з паралельним кінцевим автоматом (FSM), який порівнює поточний біт із попереднім на наявність логічного `AND` між `bᵢ` та `bᵢ₋₁`. Це забезпечує виявлення термінатора за 1 тактовий імпульс без споживання додаткової пам'яті.
