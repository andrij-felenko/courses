# ⚙️ Обчислення згортки та префіксних сум арифметичних функцій

Обчислення значень арифметичних функцій для великих числових діапазонів `1 ≤ n ≤ N` та знаходження їхніх суматорних функцій (префіксних сум) `S_f(X) = ∑_{n ≤ X} f(n)` є фундаментальною практичною задачею в обчислювальній теорії чисел, аналізі криптографічних протоколів та алгоритмічній оптимізації. Пряме обчислення за означенням вимагає знаходження дільників або факторизації для кожного числа окремо і потребує `O(N √N)` або `O(N log N)` часу. Для великих масивів даних це є неприпустимо повільним. 

Нижче наведено детальний аналіз двох ключових оптимізованих алгоритмів: лінійного решета для масового обчислення будь-яких мультиплікативних функцій за час `O(N)` та сублінійного алгоритму Дю (Du Sieve) для знаходження префіксних сум за час `O(N^(2/3))` без виділення гігабайтів оперативної пам'яті.

## 1. Лінійне решето для мультиплікативних функцій за O(N)

Класичне решето Ератосфена викреслює кратні числа з часовою складністю `O(N log log N)`. Проте для одночасного обчислення значень мультиплікативних функцій воно має серйозний недолік: одне й те саме складене число відвідується багаторазово для кожного свого простого множника. Наприклад, число `30 = 2 · 3 · 5` відвідується тричі (як кратне двійки, трійки та п'ятірки), що призводить до зайвих перезаписів пам'яті та руйнує строгу мультиплікативну рекурентність.

Лінійне решето (розроблене Ератосфеном, Матіясевичем та Причардом) усуває цю дубльовану роботу. Воно гарантує фундаментальну властивість: **кожне складене число `n` відвідується і оновлюється рівно один раз** — під час перемноження його найменшого простого дільника `p = min_prime(n)` на частку `i = n / p`.

### Механізм збереження мультиплікативності

Будь-яка мультиплікативна функція `f(n)` повністю визначається своїми значеннями на степенях простих чисел `f(p^k)`. Під час проходу лінійного решета зберігаються три основні динамічні масиви:
- `primes` — динамічний список усіх простих чисел, знайдених на поточному етапі;
- `min_prime_pow` — значення найвищого степеня найменшого простого множника `p₁^{k₁}`, що ділить поточне число `n`;
- `f` — результуючий масив обчислених значень арифметичної функції `f(n)`.

Алгоритм обходу працює наступним чином. Для кожного цілого числа `i` від `2` до `N`:

1. **Ідентифікація простого числа:** Якщо число `i` не було відвідане жодним меншим дільником, воно є простим. Додаємо його до списку `primes`, а значення функції `f(i)` встановлюємо безпосередньо згідно з базовим означенням для простого аргументу `f(p)`. Значення `min_prime_pow[i]` встановлюємо рівним самому числу `p`.
2. **Генерація складених чисел:** Перебираємо послідовно прості числа `p` зі списку `primes`. Складене число `next = i · p` отримує обчислене значення функції за однією з двох взаємовиключних гілок:
   - **Гілка 1: `i` не ділиться на `p` (`gcd(i, p) = 1`).** У цьому випадку `p` є строго меншим за всі прості множники числа `i`. Тому `p` стає новим найменшим простим множником числа `next`, показник якого дорівнює `1`. За мультиплікативністю маємо `f(i · p) = f(i) · f(p)`. Значення `min_prime_pow[next]` встановлюємо рівним `p`.
   - **Гілка 2: `i` ділиться на `p` (`i % p == 0`).** Це означає, що `p` вже входить до розкладу `i` і є його найменшим простим множником. Тому показник степеня простого `p` у числі `next = i · p` збільшується на одиницю: якщо `i = p^k · m` (де `gcd(m, p) = 1`), то `next = p^{k+1} · m`.
     - Якщо `i == min_prime_pow[i]`, то число `i = p^k` вже було чистим степенем простого. Тоді `next = p^{k+1}` також є чистим степенем, і ми обчислюємо `f(p^{k+1})` за явною аналітичною формулою степеня, а `min_prime_pow[next] = next`.
     - Якщо ж `i > min_prime_pow[i]`, то відокремлюємо чистий степінь найменшого простого `P = min_prime_pow[i] · p = p^{k+1}` від взаємно простої частини `m = next / P`. За мультиплікативністю маємо `f(next) = f(m) · f(P)`, а `min_prime_pow[next] = P`.
     - **Критичний оператор `break`:** Після обробки випадку `i % p == 0` внутрішній цикл перебору простих чисел **негайно переривається**.

Чому оператор `break` є математично необхідним? Нехай `p` — найменший простий дільник числа `i`. Якщо ми продовжимо цикл і візьмемо наступне просте число `p' > p`, то для утвореного числа `next' = i · p'` найменшим простим множником буде `p`, а не `p'`. Отже, число `next'` буде згенероване пізніше — коли зовнішній цикл дійде до значення `i' = (i · p') / p`. Якщо не виконати `break`, кожне складене число буде відвідане стільки разів, скільки різних простих множників воно має. Оператор `break` забезпечує рівно один візит на кожне складене число, гарантуючи часову складність `O(N)`.

### Покрокове простеження (trace) лінійного решета для N = 12

Простежимо покроково виконання алгоритму для обчислення функції Мебіуса `μ` та функції Ейлера `φ` на діапазоні від 2 до 12:

- `i = 2`: не позначене → просте. Додаємо `2` до `primes = [2]`. `μ(2) = -1`, `φ(2) = 1`, `min_pow[2] = 2`.
  - Внутрішній цикл: `p = 2` → `next = 2 · 2 = 4`. Оскільки `2 % 2 == 0`, випадок гілки 2: `min_pow[4] = 4`, `μ(4) = 0`, `φ(4) = 2`. Виконуємо `break`.
- `i = 3`: не позначене → просте. Додаємо `3` до `primes = [2, 3]`. `μ(3) = -1`, `φ(3) = 2`, `min_pow[3] = 3`.
  - Внутрішній цикл: `p = 2` → `next = 3 · 2 = 6`. `3 % 2 ≠ 0` (гілка 1): `min_pow[6] = 2`, `μ(6) = μ(3) · μ(2) = 1`, `φ(6) = φ(3) · φ(2) = 2`.
  - `p = 3` → `next = 3 · 3 = 9`. `3 % 3 == 0` (гілка 2): `min_pow[9] = 9`, `μ(9) = 0`, `φ(9) = 6`. Виконуємо `break`.
- `i = 4`: складене (`min_pow[4] = 4`).
  - Внутрішній цикл: `p = 2` → `next = 4 · 2 = 8`. `4 % 2 == 0` (гілка 2): `min_pow[8] = 8`, `μ(8) = 0`, `φ(8) = 4`. Виконуємо `break`.
- `i = 5`: не позначене → просте. Додаємо `5` до `primes = [2, 3, 5]`. `μ(5) = -1`, `φ(5) = 4`, `min_pow[5] = 5`.
  - `p = 2` → `next = 10`. `5 % 2 ≠ 0`: `min_pow[10] = 2`, `μ(10) = μ(5) μ(2) = 1`, `φ(10) = φ(5) φ(2) = 4`.
  - `p = 3` → `next = 15 > 12` (виходить за межі `N = 12`, цикл завершується).
- `i = 6`: складене (`min_pow[6] = 2`).
  - `p = 2` → `next = 6 · 2 = 12`. `6 % 2 == 0` (гілка 2): `min_pow[6] · 2 = 4`, `m = 12 / 4 = 3`. За мультиплікативністю `μ(12) = μ(3) · μ(4) = -1 · 0 = 0`, `φ(12) = φ(3) · φ(4) = 2 · 2 = 4`. Виконуємо `break`.

Кожне складене число `4, 6, 8, 9, 10, 12` було згенеровано рівно один раз.

## 2. Сублінійне решето Дю (Du Sieve) для префіксних сум за O(N^(2/3))

Якщо перед інженером стоїть задача знайти глобальну суматорну величину `S_f(N) = ∑_{i=1}^N f(i)` для масштабного діапазону `N = 10¹¹`, лінійне решето зазнає поразки через неможливість виділення масиву пам'яті: масив на `10¹¹` 64-бітних цілих чисел вимагатиме майже терабайт оперативної пам'яті.

Сублінійне решето Дю (Du Sieve) розв'язує цю задачу без створення повного масиву значень. Воно спирається на алгебраїчну тотожність згортки функції `f` із підібраною супутньою функцією `g`:

```
(f * g)(n) = ∑_{d|n} f(d) g(n/d)
```

Просумуємо обидві частини рівності від `1` до `N`:

```
∑_{i=1}^N (f * g)(i)
= ∑_{i=1}^N ∑_{d|i} f(d) g(i/d)                      [розгортка подвійної суми]
= ∑_{m=1}^N g(m) ( ∑_{k=1}^{⌊N/m⌋} f(k) )             [зміна порядку підсумовування при i = m·k]
= ∑_{m=1}^N g(m) S_f( ⌊N/m⌋ )                         [заміна внутрішньої суми на префіксну суму S_f]
```

Відокремимо перший доданок при `m = 1` (де `g(1) S_f(N)`):

```
∑_{i=1}^N (f * g)(i) = g(1) S_f(N) + ∑_{m=2}^N g(m) S_f( ⌊N/m⌋ )
```

Переносячи суму та ділячи на `g(1) ≠ 0`, отримуємо фундаментальну рекурентну формулу для обчислення шуканої префіксної суми `S_f(N)`:

```
g(1) S_f(N) = ∑_{i=1}^N (f * g)(i) − ∑_{m=2}^N g(m) S_f( ⌊N/m⌋ )
```

### Вибір супутньої функції та блокова оптимізація

Щоб рекурентна формула обчислювалася швидко, супутню функцію `g` обирають так, щоб:
1. Префіксна сума для `g`: `S_g(x) = ∑_{i=1}^x g(i)` мала просту замкнену формулу обчислення за час `O(1)`.
2. Префіксна сума для результуючої згортки `h = f * g`: `S_h(x) = ∑_{i=1}^x (f * g)(i)` також обчислювалася за час `O(1)`.

#### Приклади вибору пар для класичних функцій

1. **Для функції Мебіуса `f = μ`:**
   Обираємо `g = 1`. Тоді згортка `f * g = μ * 1 = ε`. 
   Префіксна сума `S_ε(N) = 1` для будь-якого `N ≥ 1`, а `S_1(x) = ⌊x⌋`. Формула для функції Мертенса `M(N) = ∑_{i=1}^N μ(i)` набуває вигляду:
   ```
   M(N) = 1 − ∑_{m=2}^N M( ⌊N / m⌋ )
   ```

2. **Для функції Ейлера `f = φ`:**
   Обираємо `g = 1`. Тоді згортка `f * g = φ * 1 = id`.
   Префіксна сума `S_{id}(N) = N(N + 1)/2`. Формула для суми Ейлера `Φ(N) = ∑_{i=1}^N φ(i)` набуває вигляду:
   ```
   Φ(N) = ( N(N + 1) / 2 ) − ∑_{m=2}^N Φ( ⌊N / m⌋ )
   ```

### Техніка блокового ділення (кореневе розбиття)

У рекурентній сумі `∑_{m=2}^N g(m) S_f(⌊N/m⌋)` значення аргументу `⌊N / m⌋` набуває не `N`, а щонайбільше `2 ⌊√N⌋` різних цілочисельних значень. 

Справді:
- Для `m ≤ √N` існує не більше `√N` різних значень `m`.
- Для `m > √N` частка `⌊N / m⌋ < √N`, тобто вона може набувати лише цілих значень від `1` до `⌊√N⌋`.

Групуючи підряд розташовані індекси `m` з однаковим значенням частки `k = ⌊N / m⌋` у неперетинні інтервали `[l, r]`, де лівий край — `l`, а максимальний правий край блоку обчислюється формулою:

```
r = ⌊ N / ⌊N / l⌋ ⌋
```

Для всього діапазону `m ∈ [l, r]` значення `S_f(⌊N / m⌋)` є сталим і дорівнює `S_f(⌊N / l⌋)`. Тому весь блок доданків обчислюється за один крок:

```
∑_{m=l}^r g(m) S_f( ⌊N/m⌋ ) = S_f( ⌊N/l⌋ ) · ( S_g(r) − S_g(l - 1) )
```

### Доведення складності O(N^(2/3))

Якщо обчислювати рекурсію суто з мемоізацією, час складатиме `O(N^(3/4))`. Проте якщо заздалегідь перед-обчислити лінійним решетом значення `S_f(x)` для всіх малих `x ≤ K = N^(2/3)` у звичайний масив, а більші значення `x > K` обчислювати рекурсивно з кешуванням, часова складність оптимізується.

Оцінимо сумарний час:
- Час роботи лінійного решета для `x ≤ K`: `O(K)`.
- Час рекурсивного обчислення для значень `⌊N / i⌋ > K`:
  ```
  ∑_{i ≤ N/K} O( √(N / i) ) ≈ ∫_1^{N/K} √(N / x) dx = O( √(N) · √(N / K) ) = O( N / √K )
  ```

Мінімізуємо підсумковий час `T(N) = O(K + N / √K)`. Прирівнюючи `K = N / √K`, маємо `K^{3/2} = N`, звідки оптимальний поріг становить **`K = N^(2/3)`**.

Підставляючи `K = N^(2/3)`, отримуємо:
- Час роботи решета: `O(N^(2/3))`.
- Час рекурсивних викликів: `O(N / √(N^(2/3))) = O(N / N^(1/3)) = O(N^(2/3))`.
- Необхідна пам'ять: `O(K) = O(N^(2/3))`.

Для `N = 10¹¹` величина `N^(2/3) ≈ 2.15 · 10⁷`, що вимагає лише близько 170 МБ оперативної пам'яті замість 800 ГБ!

### Покроковий числовий приклад обчислення функції Мертенса M(100)

Простежимо покроково роботу алгоритму Дю для знаходження значення функції Мертенса `M(100) = ∑_{i=1}^{100} μ(i)`.

Формула рекурсії має вигляд `M(100) = 1 − ∑_{m=2}^{100} M(⌊100 / m⌋)`.

Розіб'ємо діапазон `m ∈ [2, 100]` на блоки з однаковим значенням частки `k = ⌊100 / m⌋`:
1. Блок `m ∈ [2, 2]`: `k = 50`, довжина `1`. Внесок: `1 · M(50)`.

9. Блок `m ∈ [10, 10]`: `k = 10`, довжина `1`. Внесок: `1 · M(10)`.

∑_{m=2}^{100} M(⌊100/m⌋)

## 3. Згортка на решітці дільників через швидке дзета-перетворення (FZT / SOS DP)

Якщо перед нами стоїть задача обчислити згортку Діріхле двох довільних функцій `h(d) = (f * g)(d)` для **всіх** дільників `d` одного фіксованого складеного числа `N = p₁^{k₁} · … · p_r^{k_r}`, наївне перемноження за парами вимагає `O(d(N)²)` операцій.

Використовуючи ізоморфізм решітки дільників із багатовимірною сіткою показників степенів `[0, k₁] × … × [0, k_r]`, задачу можна звести до швидкого дзета-перетворення (Fast Zeta Transform / Sum Over Subsets DP).

Алгоритм виконує `r` послідовних проходів динамічного програмування — по одному для кожного простого множника `p_i`. На кроці `i` для кожного дільника `d`, що ділиться на `p_i`, виконується додавання:

```
f[d] = f[d] + f[d / p_i]
```

Цей метод зменшує складність із квадратичної `O(d(N)²)` до суворо лінійно-логарифмічної:

```
O( r · d(N) ) = O( d(N) · ∑_{i=1}^r 1 ) = O( ω(N) · d(N) )
```

Для чисел із сотнями тисяч дільників цей підхід прискорює обчислення у тисячі разів.

## 4. Сегментоване решето для паралельних обчислень на CPU

Для обчислення значень на гігантських відрізках `[L, R]`, де `R - L ≤ 10⁹`, а `R ≤ 10¹⁴`, лінійне решето не підходить через брак пам'яті під індекси `i ≤ R`. 

У таких випадках застосовують **сегментоване решето**:
1. Знаходять базові прості числа до порогу `√R` за допомогою класичного лінійного решета (вимагає лише кілька мегабайтів RAM).
2. Розбивають цільовий відрізок `[L, R]` на компактні сегменти розміру `B ≈ 32 768` елементів (розмір кеш-пам'яті першого рівня L1D процесора).
3. Кожен потік процесора бере свій сегмент і викреслює кратні числа базових простих чисел, повністю утримуючи дані у надшвидкому кеші процесора.

Сегментоване решето забезпечує майже ідеальне лінійне прискорення на багатоядерних процесорах (OpenMP / SIMD AVX-512) та є стандартом у сучасних системах розподіленого пошуку простих чисел.

## 7. Пряме обчислення згортки довільних масивів за O(N log N)

Якщо потрібно обчислити масив згортки `h[n] = (f * g)[n]` для довільних числових масивів `f[1..N]` та `g[1..N]`, які не є мультиплікативними і не мають аналітичних формул, пряме обчислення за означенням виконують за гармонічним алгоритмом:

```
for i from 1 to N:
    for j from 1 to ⌊N / i⌋:
        h[i * j] += f[i] * g[j]
```

Оцінимо кількість арифметичних ітерацій:
```
∑_{i=1}^N ⌊N / i⌋ = N · ∑_{i=1}^N (1 / i) = N · ( ln N + γ + O(1/N) ) = N ln N + O(N)
```

Таким чином, повна згортка двох довільних масивів довжиною `N = 10⁷` потребує лише `N ln N ≈ 1.6 · 10⁸` операцій, що виконується сучасним процесором менш ніж за 0.15 секунди.

Для забезпечення максимальної локальності даних у кеші масив `h` обробляють послідовно: зовнішній цикл перебирає `i`, а внутрішній крокує з фіксованим кроком `i`, що дозволяє апаратному блоку вибірки інструкцій (hardware prefetcher) завантажувати дані без кеш-промахів.

## 8. Алгоритм знаходження оберненої функції для довільного масиву за O(N log N)

Аналогічно, якщо задано довільний масив `f[1..N]` із ненульовим першим елементом `f[1] ≠ 0`, його обернений відносно згортки масив `g = f⁻¹` можна знайти за час `O(N log N)` методом послідовного виключення:

1. Встановлюємо `g[1] = 1.0 / f[1]`.
2. Створюємо допоміжний масив `cur[1..N]`, ініціалізований нулями.
3. Для кожного індексу `i` від `1` до `N`:
   - Якщо `i > 1`, обчислюємо `g[i] = - cur[i] / f[1]`.
   - Оновлюємо значення `cur[i · j] += g[i] · f[j]` для всіх `j ≥ 2` таких, що `i · j ≤ N`.

Загальна кількість операцій знову становить `∑_{i=1}^N ⌊N/i⌋ = O(N log N)`.

## 9. Низькорівнева оптимізація: SIMD векторні інструкції та вирівнювання пам'яті

Для досягнення граничної швидкодії на сучасних архітектурах x86-64 (Intel Core, AMD Zen) та ARM64 (Apple Silicon, Neoverse) застосовують апаратні векторизації:

1. **Векторизація за допомогою AVX2 / AVX-512:**
   Операції блокового додавання `cur[i * j] += g[i] * f[j]` векторизуються інструкціями злитого множення-додавання `_mm256_fmadd_pd` або `_mm512_fmadd_pd`, які обробляють 4 або 8 чисел подвійної точності за один такт процесора.
2. **Вирівнювання пам'яті (Memory Alignment):**
   Усі великі масиви виділяються за допомогою системних викликів вирівнювання `posix_memalign` або `_aligned_malloc` за межею 64 байтів. Це гарантує, що жодна векторна інструкція не перетинає границю двох різних кеш-ліній (усунення ефекту *cache line split*).
3. **Використання інструкцій `_mm_prefetch`:**
   У сублінійному алгоритмі Дю перед виконанням стрибка до віддаленої адреси `large_cache[⌊N/m⌋]` надсилається апаратна підказка `_mm_prefetch((const char*)&large_cache[idx], _MM_HINT_T0)`, яка завантажує рядок у кеш L1 за кількасот тактів до безпосереднього звернення.

## 11. Математичне доведення формули правого краю блоку r = ⌊N / ⌊N / l⌋⌋

У сублінійних решетах ключовою є формула знаходження максимального цілого числа `r`, для якого `⌊N / r⌋ = ⌊N / l⌋`.

**Теорема.** Нехай `k = ⌊N / l⌋`. Тоді найбільшим цілим числом `r ≥ l`, для якого `⌊N / r⌋ = k`, є число `r = ⌊N / k⌋`.

**Доведення:**
1. За означенням цілої частини маємо подвійну нерівність `k ≤ N / l < k + 1`. З лівої нерівності `k ≤ N / l` випливає `l ≤ N / k`. Оскільки `l` — ціле число, маємо `l ≤ ⌊N / k⌋ = r`.
2. Перевіримо, що для числа `r = ⌊N / k⌋` частка `⌊N / r⌋` дорівнює `k`:
   Оскільки `r ≤ N / k`, маємо `N / r ≥ k`, отже `⌊N / r⌋ ≥ k`.
   З іншого боку, `r = ⌊N / k⌋ > N / k - 1 = (N - k) / k`.
   Тоді `N / (r + 1) < N / (N / k) = k`. Оскільки `r + 1 > N / k`, будь-яке число більше за `r` дасть частку, строго меншу за `k`.
3. Отже `r = ⌊N / ⌊N / l⌋⌋` є точним супремумом (максимумом) відрізка постійності частки цілого ділення.

## 12. Криптографічні застосування: швидкі тотієнти у RSA та ECC

В асиметричній криптографії та схемах цифрового підпису обчислення арифметичних функцій та згортки є базовою складовою:

1. **Генерація ключів RSA:** Для модуля `N = p · q` обчислюється функція Ейлера `φ(N) = (p - 1)(q - 1)` та [функція Кармайкла](root:math-number-theory/carmichael-function) `λ(N) = lcm(p - 1, q - 1)`. Закритий ключ `d` знаходиться як модульне обернене `d ≡ e⁻¹ (mod λ(N))` за допомогою розширеного алгоритму Евкліда.
2. **Підрахунок точок на еліптичних кривих (алгоритм Шуфа-Елкіса-Аткіна):** Порядок групи точок еліптичної кривої `E(𝔽_q)` визначається формулою `|E(𝔽_q)| = q + 1 - t`, де слід Фробеніуса `t` задовольняє оцінку Хассе `|t| ≤ 2 √q`. Для знаходження `t` застосовують обернення Мебіуса та поділ на поліноми розкладу.
3. **Генерація псевдовипадкових послідовностей (BBS-генератор):** Стійкість генератора Блюма-Блюма-Шуба базується на складності обчислення квадратичних залишків та функції Мебіуса без знання розкладу модуля на прості множники.

## 13. Профілювання продуктивності та верифікація алгоритмів

При впровадженні високопродуктивних алгоритмів обчислення згортки у виробничий код критично важливим є етап інженерного профілювання та модульного тестування:

1. **Профілювання кеш-пам'яті за допомогою Linux perf та Cachegrind:**
   Для перевірки ефективності лінійного та сублінійного решета використовують команду `perf stat -e L1-dcache-loads,L1-dcache-load-misses,LLC-load-misses ./du_sieve`. Якісна реалізація з подвійним масивом повинна мати коефіцієнт кеш-промахів L1D менше 3%, а промахів кешу останнього рівня (LLC) — менше 0.1%.
2. **Модульна верифікація через математичні інваріанти:**
   Перед запуском на гігантських діапазонах `N = 10¹¹` коректність роботи обов'язково перевіряється набором тестових інваріантів:
   - Перевірка тотожності `∑_{i=1}^n φ(i) = (1/2) (1 + ∑_{i=1}^n μ(i) ⌊n/i⌋²)`.
   - Перевірка рівності `M(n) = ∑_{i=1}^n μ(i)` супроти наївного підрахунку з факторизацією для всіх `n ≤ 10 000`.
   - Граничні тести на спеціальних числах: чисті степені простих `n = 2^{30}`, прайморіали `n = 2 · 3 · 5 · 7 · 11 · 13 · 17 · 19` та повні квадрати `n = k²`.
3. **Прапорці компілятора та керування потоками виконання:**
   Для отримання максимальної продуктивності компіляторам GCC та Clang передають прапорці `-O3 -march=native -mavx2 -mfma -flto -fno-math-errno`. При паралельній обробці відрізків між потоками організовують безблокувальні черги (lock-free ring buffers) із розподілом задач за принципом крадіжки роботи (work stealing), що виключає затримки на системних м'ютексах та забезпечує рівномірне навантаження всіх ядер сучасного багатопотокового процесора.
4. **Оптимізація пам'яті на NUMA-системах та підтримка Huge Pages:**
   На багатопроцесорних серверах із NUMA-архітектурою пам'ять для кожного робочого потоку виділяється локально на відповідному сокеті (first-touch policy). Для масивів розміром понад 64 МБ використовують сторінки пам'яті розміром 2 МБ (Transparent Huge Pages) через `madvise(..., MADV_HUGEPAGE)`, що зменшує навантаження на буфер асоціативної трансляції (TLB) та скорочує час доступу до пам'яті ще на 12-15%.

| **Гармонічне обернення масиву** | `O(N log N)` | `O(N)` | `N ≤ 10⁷` | Знаходження оберненого масиву `f⁻¹` |
| **Сублінійне решето Дю (Du Sieve)** | `O(N^(2/3))` | `O(N^(2/3))` | `N ≤ 10¹¹` | Префіксні суми функцій зі зручною згорткою (`μ`, `φ`, `d`) |
| **Решето Міна-Баха (Min25 Sieve)** | `O(N^(2/3))` | `O(N^(2/3))` | `N ≤ 10¹¹` | Префіксні суми довільних функцій без простої згортки |
| **Сегментоване паралельне решето** | `O(N)` (багатопотокове) | `O(√N + B)` | `R ≤ 10¹⁴, R-L ≤ 10⁹` | Обчислення значень на віддалених числових відрізках |
| **Швидке дзета-перетворення (SOS DP)** | `O(ω(N) · d(N))` | `O(d(N))` | Дільники числа `N` | Повна згортка на решітці дільників одного великого числа |
| **Полард-ро + Міллер-Рабін** | `O(N^(1/4))` | `O(1)` | `N ≤ 10¹⁸`–`10²⁴` | Ізольовані значення функцій для криптографічних модулів |

Завдяки цим алгоритмічним інструментам теорія арифметичних функцій та згортки Діріхле перетворюється із суто абстрактної математичної конструкції на високоефективний прикладний інструмент сучасної комп'ютерної інженерії.
