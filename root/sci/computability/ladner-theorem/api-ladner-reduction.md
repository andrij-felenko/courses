# 📋 Специфікація класів складності, контрактів зведення та типів NP-задач

Цей довідник містить формальний опис типів обчислювальних складностей, контрактів поліномних зведень та класифікаційної таблиці задач за категоріями P, NP-Intermediate та NP-Complete.

## Контракти обчислювальних інтерфейсів та моделі верифікації

У системному аналізі складності кожна проблема представлена у вигляді строгих інтерфейсних контрактів розпізнавання, перевірки та перетворення вхідних даних. Ці контракти формалізують відношення між вхідним рядком, недетермінованим свідком (сертифікатом) та часовим бюджетом, що виділяється алгоритму.

Для обчислювальної системи важливо мати точні визначення типів даних. Вхідний екземпляр задачі описується як рядкова послідовність символів скінченного алфавіту. Перевірка належності вхідного екземпляра до шуканої мови виконується через один із трьох фундаментальних інтерфейсів: розпізнаватель (детермінований розв'язок), верифікатор (недетермінована перевірка) або перекладач зведення (поліномна функція перетворення).

### 1. Контракт задачі розпізнавання (`DecisionProblem<T>`)

Інтерфейс розпізнавателя визначає стандартні операції для будь-якої задачі з класу NP. Кожна конкретна проблема має реалізувати перевірку синтаксичної коректності входу, обчислення розміру вхідних даних та детерміновану процедуру прийняття рішення.

```
Interface: DecisionProblem<Instance>
--------------------------------------------------------------------------------
Метод                 | Повертане значення | Опис контракту
--------------------------------------------------------------------------------
is_valid_instance(x)  | bool               | Перевіряє синтаксичну коректність входу
decide(x)             | bool               | Визначає належність входу x до мови L
get_instance_size(x)  | size_t             | Повертає довжину входу n = |x|
--------------------------------------------------------------------------------
```

Обминути обчислювальні складності детермінованого розв'язання в інтерфейсі розпізнавателя вдається лише тоді, коли для мови існує поліномний алгоритм `decide(x)`, час роботи якого обмежено `O(n^k)`. Якщо такий алгоритм невідомий, задача переходить у розряд недетермінованого аналізу за допомогою верифікатора.

### 2. Контракт недетермінованого верифікатора (`PolynomialVerifier<Instance, Certificate>`)

Інтерфейс верифікатора відповідає класичному визначенню класу NP через свідка. Замість самостійного пошуку відповіді, верифікатор отримує зовнішній сертифікат довільної форми та перевіряє його коректність за детермінований поліномний час від довжини початкового входу.

```
Interface: PolynomialVerifier<Instance, Certificate>
--------------------------------------------------------------------------------
Параметр              | Тип                | Обмеження складності
--------------------------------------------------------------------------------
instance (x)          | Instance           | Довжина n = |x|
certificate (w)       | Certificate        | Довжина |w| ≤ p(n)
verify(x, w)          | bool               | Час виконання T_verify(n) ≤ q(n)
--------------------------------------------------------------------------------
Властивість класу NP  | x ∈ L  ⇔  ∃ w (|w| ≤ p(n) ∧ verify(x, w) == true)
--------------------------------------------------------------------------------
```

Сертифікат `w` виступає у ролі підтвердження ствердної відповіді. Наприклад, для задачі SAT сертифікатом є підстановка істиннісних значень булевих змінних; для задачі ізоморфізму графів — бієкція перестановки вершин. Якщо вхідний екземпляр не належить до мови, жоден сертифікат `w` обмеженого розміру `p(n)` не змусить функцію `verify(x, w)` повернути `true`.

### 3. Контракт поліномного зведення Карпа (`PolynomialReduction<A, B>`)

Інтерфейс поліномного зведення визначає функціональний перекладач між двома задачами. Головна умова зведення полягає в тому, що трансформація вхідних даних має зберігати ствердну відповідь і виконуватися за часовий бюджет, який обмежується поліномом від розміру вихідного входу.

```
Interface: PolynomialReduction<InstanceA, InstanceB>
--------------------------------------------------------------------------------
Функція зведення      | R: InstanceA → InstanceB
Часова складність     | T_R(n) ≤ p(n), де n = |x|
Розмірна складність   | |R(x)| ≤ p(n)
--------------------------------------------------------------------------------
Сувора інваріантність  | ∀ x ∈ InstanceA:  x ∈ L_A  ⇔  R(x) ∈ L_B
--------------------------------------------------------------------------------
```

Зведення Карпа гарантує, що якщо ми маємо швидкий вирішувач для задачі `B`, ми автоматично отримуємо швидкий вирішувач для задачі `A` шляхом обчислення `decide_A(x) = decide_B(R(x))`. Якщо ж задача `A` є доведено важкою, то й задача `B` не може бути простішою за `A`.

## Класифікаційна матриця класів складності

У теоретичній інформатиці клас NP розпадається на кілька ключових структурних областей залежно від наявності детермінованого розв'язку та зводимості до NP-повних проблем. Якщо припущення про нееквівалентність класів P та NP є вірним, внутрішня геометрична організація складностей набуває специфічного трикомпонентного поділу.

Класифікація включає не лише стандартні класи P та NP-Complete, а й клас NP-Intermediate (NPI), відкритий теоремою Леднера, та клас `NP ∩ coNP`, мови якого володіють короткими свідками як для ствердної, так і для заперечної відповіді.

Нижче наведено порівняльну специфікацію основних структурних класів у межах класу NP за умови `P ≠ NP`. Таблиця описує характерні контракти поведінки, наявність швидких детермінованих алгоритмів та можливість поліномного зведення найважчої задачі SAT до даної категорії.

```
========================================================================================================================
Клас складності   | Характеристичний контракт      | Існування швидкого    | Зведення SAT ≤ₚ L | Приклади задач
                  |                               | детермінованого розв. |                   |
========================================================================================================================
Class P           | T_solver(n) ≤ p(n)            | ТАК (детерміновано за | НІ (якщо P ≠ NP)  | 2-SAT, Eulerian Path,
                  | V_verifier(n) ≤ p(n)          | поліномний час)       |                   | Shortest Path, Minimum Spanning Tree
------------------------------------------------------------------------------------------------------------------------
Class NPI         | L ∈ NP \ P,                   | НІ (не існує          | НІ (за теоремою   | Штучна мова Леднера A,
(NP-Intermediate) | SAT ≰ₚ L                      | поліномного розв.)    | Леднера)          | Ізоморфізм графів (кандидат),
                  |                               |                       |                   | Факторизація цілих чисел (кандидат)
------------------------------------------------------------------------------------------------------------------------
Class NPC         | L ∈ NP,                       | НІ (якщо P ≠ NP)      | ТАК (за           | SAT, 3-SAT, Clique,
(NP-Complete)     | ∀ A ∈ NP: A ≤ₚ L              |                       | визначенням)      | Hamiltonian Cycle, Vertex Cover
------------------------------------------------------------------------------------------------------------------------

                  |                               | ні для класичних СВ)  | (колапс PH)       | Дискретний логарифм
========================================================================================================================
```

## Специфікація типів зведень та їхня ієрархія

Відношення зведення є основним інструментом для порівняння відносної складності двох обчислювальних проблем. Залежно від того, як саме перетворюються вхідні дані та як виконуються запити до цільової проблеми, у теорії складності розрізняють три основні рівні зведень: зведення Карпа (багато-один), зведення Левіна (із збереженням свідків) та зведення Тюринга (оракульне зведення з багатьма запитами).

Зведення за Карпом використовується у більшості класичних доведень NP-повноти та є основою для теореми Леднера. Воно вимагає побудови єдиного екземпляра цільової задачі. Зведення за Тюрингом є більш загальним, оскільки дозволяє викликати оракул цільової задачі довільну поліномну кількість разів усередині детермінованого алгоритму. Зведення за Левіним додатково вимагає наявності поліномної функції, яка перетворює сертифікат розв'язку цільової задачі назад у сертифікат розв'язку вихідної задачі.

```
------------------------------------------------------------------------------------------------------------------------
Тип зведення              | Означення та контракт                            | Сфера застосування у теорії Леднера
------------------------------------------------------------------------------------------------------------------------
Зведення Карпа (Karp)      | x ∈ A  ⇔  R(x) ∈ B,  T_R(n) ≤ p(n)              | Канонічні NP-повні задачі, класичне
(m-reduction ≤ₚ)          | Поліномне зведення з одним запитом               | доведення теореми Леднера
------------------------------------------------------------------------------------------------------------------------
Зведення Левіна (Levin)    | Поліномне зведення Карпа R(x) разом з             | Зведення розв'язків та свідків між
(search-reduction ≤ₚˡ)    | поліномним перетворенням свідка w_B → w_A        | пошуковими задачею з NP
------------------------------------------------------------------------------------------------------------------------
Зведення Тюринга (Turing) | Доступ до оракула B за O(1) часу,                 | Узагальнена щільність ступенів складності,
(oracle-reduction ≤ₚᵀ)    | поліномна кількість поліномних запитів           | ієрархія оракульних класів
------------------------------------------------------------------------------------------------------------------------
```

## Таблиця кандидатів у природні NP-проміжні задачі

Оскільки формальне доведення теореми Леднера спирається на штучну мову, побудовану методом падінгу та сповільненої діагоналізації, практичний інтерес представляють природні математичні задачі, які тривалий час опираються спробам знайти поліномний розв'язок, але при цьому не показують ознак NP-повноти.

Нижче наведено специфікацію головних математичних проблем, які розглядаються науковою спільнотою як реальні кандидати на статус NP-проміжних. Для кожної проблеми вказано вхідні дані, поточний найкращий асимптотичний бар'єр алгоритмів розв'язання та обчислювальні причини, чому ця задача навряд чи є NP-повною.

```
------------------------------------------------------------------------------------------------------------------------
Назва проблеми               | Вхідні дані               | Поточний найкращий        | Чому вважається NP-проміжною
                             |                           | часовий бар'єр            |
------------------------------------------------------------------------------------------------------------------------
Ізоморфізм графів            | Два графи G₁ та G₂        | Квазіполіномний час       | Не належить до P (класично), але не
(Graph Isomorphism)          |                           | 2^(O((log n)^c)) (Бабаї)  | є NP-повною (інакше PH колапсує)
------------------------------------------------------------------------------------------------------------------------

(Integer Factorization)      |                           | час NFS: exp(O(n^(1/3)))  | її NP-повноту малоймовірною
------------------------------------------------------------------------------------------------------------------------
Дискретний логарифм          | g, h, p (в групі Z_p*)    | Метод сита числового поля  | Належить до NP ∩ coNP; квантово

------------------------------------------------------------------------------------------------------------------------

(MCSP)                       | та розмір s               | перебір)                  | NP-повнота суперечила б криптографії

```

Кожна з цих кандидатних проблем володіє глибокими алгебраїчними та комбінаторними симетріями. Наприклад, задача ізоморфізму графів дозволяє будувати низькорангові інтерактивні протоколи підтвердження знання без розкриття перестановки. Задачі факторизації та дискретного логарифмування спираються на арифметичні властивості скінченних полів та кілець. Саме ця додаткова алгебраїчна структура перешкоджає доведенню NP-повноти, оскільки загальні NP-повні задачі (такі як SAT чи Clique) повністю позбавлені подібної структури.

## Аксіоматичні інваріанти структури ступенів Леднера

Алгебраїчна структура ступенів поліномної зводимості під відношенням Карпа або Тюринга утворює напівґратку із заданими фундаментальними інваріантами:

1. **Транзитивність відношення**: Якщо задача `A` поліномно зводиться до `B`, а `B` поліномно зводиться до `C`, то `A` обов'язково поліномно зводиться до `C`. Це дозволяє будувати ланцюжки зведень та класифікувати задачі за еквівалентними класами.
2. **Рефлексивність**: Для будь-якої мови `A` тотожне перетворення забезпечує зведення `A ≤ₚ A`.
3. **Верхня межа (SAT)**: Для будь-якої мови `L ∈ NP` за теоремою Кука — Левіна виконується зведення `L ≤ₚ SAT`. Еквівалентні за складністю мови утворюють найвищий ступінь NP-повноти.
4. **Нижня межа (Клас P)**: Усі нетривіальні мови з класу P є еквівалентними відносно поліномного зведення та утворюють найнижчий ступінь складності. Будь-яка мова з P може бути поліномно зведена до будь-якої непорожньої мови з NP.
5. **Аксіома щільності (Density Axiom)**: Для будь-яких двох мов `A, B ∈ NP` таких, що `A <ₚ B` (де `A ≤ₚ B`, але `B ≰ₚ A`), завжди існує така мова `C ∈ NP`, що `A <ₚ C <ₚ B`. Це гарантує відсутність ізольованих проміжків у геометрії класу NP.
6. **Відсутність мінімальних ступенів вище P**: У напівґратці ступенів NP не існує «найменшої» не-поліномної мови: для будь-якої мови `A ∈ NP \ P` існує проміжна мова `C ∈ NP \ P` така, що `C <ₚ A`.
