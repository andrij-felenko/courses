# 🧮 Математичний апарат конкурентного аналізу

Ця математична вставка містить суворе формальне визначення конкурентного співвідношення (Competitive Ratio), класифікацію типів супротивників (Adversary Models) та доведення нижніх меж для детермінованих і рандомізованих онлайнових алгоритмів за допомогою принципу мінімаксу Яо. Вона дає необхідний апарат для доведення гарантій якості онлайнових розв'язків.

## Формальне визначення c-конкурентності

Нехай задано онлайнову задачу оптимізації з простором вхідних послідовностей запитів Ω. Послідовність запитів приходить покроково:
```
σ = (r₁, r₂, ..., r_m) ∈ Ω
```
Онлайновий алгоритм ALG мусить прийняти незворотне рішення на кожному кроці i, спираючись лише на префікс запитів (r₁, r₂, ..., r_i), не знаючи майбутніх запитів (r_{i+1}, ..., r_m).

Позначимо через C(ALG, σ) загальну вартість або витрати алгоритму ALG на обслуговування всієї послідовності σ.

Офлайновий оптимальний алгоритм (позначуваний як OPT) має повний доступ до всієї послідовності σ від самого початку. Його вартість C(OPT, σ) є глобальним мінімумом витрат серед усіх можливих допустимих послідовностей рішень:
```
C(OPT, σ) = min_{рішення} C(рішення, σ)
```

### Строга та асимптотична конкурентність

**Означення 1 (Строга c-конкурентність).** Детермінований онлайновий алгоритм ALG називається *строго c-конкурентним* (strictly c-competitive), якщо існує константа c ≥ 1 така, що для будь-якої вхідної послідовності σ виконується нерівність:
```
C(ALG, σ) ≤ c · C(OPT, σ)
```

**Означення 2 (Асимптотична c-конкурентність).** Онлайн-алгоритм ALG називається *c-конкурентним з адитивною константою α*, якщо існують константи c ≥ 1 та α ≥ 0 такі, що для будь-якої послідовності σ:
```
C(ALG, σ) ≤ c · C(OPT, σ) + α
```
Константа α не повинна залежати від довжини послідовності σ (вона може залежати лише від початкового стану системи, наприклад, початкового вмісту кешу).

**Означення 3 (Конкурентне співвідношення).** *Конкурентне співвідношення* (Competitive Ratio) алгоритму ALG — це найменше значення c, для якого ALG є c-конкурентним:
```
c_ALG = inf { c ≥ 1 | ∃ α ≥ 0 : ∀ σ, C(ALG, σ) ≤ c · C(OPT, σ) + α }
```
Якщо наведена нерівність не виконується для жодного скінченного c, алгоритм називається *неконкурентним* (uncompetitive, c_ALG = ∞).

## Ієрархія супротивників (Adversary Models)

Коли онлайновий алгоритм використовує рандомізацію (підкидання монет), його вартість C(ALG, σ) стає випадковою величиною. Щоб формалізувати аналіз рандомізованих алгоритмів, симулюють гру проти абстрактного *супротивника* (Adversary), який генерує послідовність σ. Залежно від обсягу інформації, доступної супротивнику під час виконання алгоритму, виділяють три класи:

### 1. Забудькуватий супротивник (Oblivious Adversary)

Забудькуватий супротивник мусить сформувати й зафіксувати всю послідовність запитів σ **до початку виконання** онлайнового алгоритму. Супротивник знає код і вірогіднісний розподіл випадкових виборів ALG, але **не бачить** конкретних результатів підкидання монет алгоритмом під час обробки запитів.

**Умова конкурентності:**
```
E[ C(ALG, σ) ] ≤ c · C(OPT, σ) + α
```
де математичне очікування E[...] розраховується за всіма випадковими виборами ALG на фіксованій послідовності σ.

### 2. Адаптивний онлайновий супротивник (Adaptive Online Adversary)

Адаптивний онлайновий супротивник вибирає кожен наступний запит r_i в режимі реального часу, **спостерігаючи** за всіма попередніми кроками та випадковими рішеннями, прийнятими ALG на кроках (1, ..., i-1). Водночас сам супротивник мусить обслуговувати свої запити в режимі онлайн паралельно з ALG.

**Умова конкурентності:**
```
E[ C(ALG, σ) ] ≤ c · E[ C(ADAPT_ONLINE, σ) ] + α
```

### 3. Адаптивний офлайновий супротивник (Adaptive Offline Adversary)

Адаптивний офлайновий супротивник генерує запити адаптивно (бачачи всі випадкові кроки ALG), але після завершення всієї послідовності σ він сплачує ідеальну офлайнову вартість C(OPT, σ), розраховану для згенерованої послідовності.

**Умова конкурентності:**
```
E[ C(ALG, σ) ] ≤ c · E[ C(OPT, σ) ] + α
```

Для будь-якого рандомізованого алгоритму коефіцієнти конкурентності відносно цих супротивників задовольняють ієрархію:
```
c (Oblivious) ≤ c (Adaptive Online) ≤ c (Adaptive Offline)
```

## Нижні межі та принцип мінімаксу Яо

Як довести, що жоден алгоритм даного класу не може досягти конкурентного співвідношення кращого за декілька фіксованих значень? Для цього використовують **Принцип мінімаксу Яо (Yao's Minimax Principle)**.

Принцип Яо стверджує, що для оцінки рандомізованих алгоритмів проти забудькуватого супротивника можна досліджувати *детерміновані алгоритми на ймовірнісному розподілі вхідних даних*.

**Теорема (Принцип Яо для онлайнових алгоритмів).** Нехай p — ймовірнісний розподіл на множині вхідних послідовностей Ω. Нехай D — множина всіх детермінованих онлайнових алгоритмів для даної задачі. Якщо для будь-якого детермінованого алгоритму ALG ∈ D очікувана вартість на розподілі p задовольняє:
```
E_σ~p [ C(ALG, σ) ] ≥ c · E_σ~p [ C(OPT, σ) ]
```
тоді конкурентне співвідношення будь-якого рандомізованого онлайнового алгоритму R проти забудькуватого супротивника оцінюється знизу як:
```
c_R ≥ c
```

## Доведення фундаментальних нижніх меж

### Теорема 1 (Нижня межа для детермінованого пейджингу).
Для кешу розміру k та порожнього початкового стану, конкурентне співвідношення будь-якого детермінованого онлайнового алгоритму заміни сторінок є не меншим за k.

*Доведення.*
Розглянемо систему з (k + 1) можливих сторінок {1, 2, ..., k + 1} та кешем розміру k. Початковий вміст кешу детермінованого алгоритму ALG дорівнює {1, 2, ..., k}.

Супротивник будує послідовність σ крок за кроком за наступним правилом: на кроці i супротивник запитує єдину сторінку r_i, якої **немає** в кеші алгоритму ALG на цьому кроці.

Оскільки на кожному кроці кеш містить k сторінок із (k + 1) можливих, така сторінка r_i завжди існує й визначається однозначно.

1. **Вартість ALG**: Оскільки на кожному кроці r_i відсутня у кеші ALG, алгоритм робить промах на КОЖНОМУ кроці:
```
C(ALG, σ) = m   (для послідовності довжини m)
```

2. **Вартість OPT**: Офлайновий алгоритм OPT знає всю послідовність з m запитів. Розіб'ємо m запитів на фази. Кожна фаза містить k різних сторінок. За принципом Діріхле, існує принаймні одна сторінка з (k + 1), яка ЖОДНОГО разу не запитується протягом цієї фази. OPT залишає саме цю сторінку поза кешем.
Таким чином, OPT робить лише 1 промах за кожні k запитів:
```
C(OPT, σ) ≤ m / k + 1
```

3. **Співвідношення**:
```
c = C(ALG, σ) / C(OPT, σ) ≥ m / (m / k + 1) → k  при m → ∞
```
Отже, c_ALG ≥ k. Теорему доведено. ■

### Теорема 2 (Нижня межа для рандомізованого пейджингу).
Конкурентне співвідношення будь-якого рандомізованого алгоритму заміни сторінок проти забудькуватого супротивника для кешу розміру k не може бути меншим за H_k ≈ ln k.

*Доведення (за принципом Яо).*
Встановимо рівномірний ймовірнісний розподіл p на послідовностях з (k + 1) сторінок: кожен новий запит r_i вибирається випадково та рівномірно з-поміж усіх (k + 1) сторінок.

Для будь-якого детермінованого алгоритму ALG імовірність того, що випадково вибрана сторінка відсутня у кеші розміру k, становить:
```
P(промах на кроці i) = 1 / (k + 1)
```
Тому очікувана кількість промахів детермінованого алгоритму на послідовності довжини m дорівнює:
```
E[ C(ALG, σ) ] = m / (k + 1)
```

Для офлайнового алгоритму OPT середня кількість запитів між двома послідовними промахами відповідає класичній «задачі колекціонера купонів» (Coupon Collector's Problem). Щоб побачити всі (k + 1) різних сторінок, у середньому потрібно зробити:
```
(k + 1) · (1/1 + 1/2 + 1/3 + ... + 1/k) = (k + 1) · H_k
```
запитів. Отже, очікувана кількість промахів OPT на m запитах становить:
```
E[ C(OPT, σ) ] ≈ m / ((k + 1) · H_k)
```

За принципом мінімаксу Яо, обчислюємо нижню межу співвідношення:
```
c ≥ E[ C(ALG, σ) ] / E[ C(OPT, σ) ] = (m / (k + 1)) / (m / ((k + 1) · H_k)) = H_k
```
Отже, жоден рандомізований алгоритм не може мати конкурентне співвідношення менше за H_k ≈ ln k. Теорему доведено. ■
