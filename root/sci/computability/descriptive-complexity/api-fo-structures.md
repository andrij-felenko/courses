# 📋 Інтерфейс реляційних структур та обчислювача логічних формул

Цей документ надає вичерпну технічну специфікацію програмного інтерфейсу (API) системного рушія обчислення формул логіки першого порядку (First-Order Logic Engine) та програмного опису скінченних реляційних математичних структур. Документ містить вичерпний структурний довідник, специфікації типів даних, описи форматів синтаксичних дерев, правила маніпуляції середовищем зв'язування змінних, сигнатури функцій та контракти виконання мовами C та C++, а також інженерні характеристики обчислювальної складності, оптимізаційних пасів та обробки виняткових ситуацій.

## 1. Архітектура програмного інтерфейсу та базові концепції

Пакет інтерфейсів надає обчислювальний механізм для опису та аналізу скінченних математичних структур виду `A = (U, R₁, R₂, ..., Rₘ)`, де `U = {0, 1, ..., n-1}` є скінченним доменом цілочисельних елементів, а `Rᵢ` — n-арними реляційними відношеннями.

Основне завдання програмного інтерфейсу полягає у наданні декларативного середовища, яке дозволяє розробнику:
1. Програмно сконструювати реляційну структуру (модель графа, схеми бази даних чи мережевої топології).
2. Заповнити відношення кортежами даних відповідної арності `aᵢ`.
3. Побудувати абстрактне синтаксичне дерево (AST) декларативної формули логіки першого порядку з використанням атомарних предикатів, логічних операторів та кванторів.
4. Запустити рекурсивний обчислювач перевірки моделей (Model Checker) для визначення істинності формули на побудованій структурі.

### Докладний опис концепцій реляційного рушія

Усі математичні об'єкти у представленій бібліотеці описуються через універсальну концепцію сигнатури. Кожне відношення `Rᵢ` має власну арність `aᵢ` (кількість параметрів). Елементи домену репрезентуються беззнаковими цілими числами `size_t` у діапазоні від `0` до `domain_size - 1`.

Для оптимізації роботи з пам'яттю кортежі реляційних відношень зберігаються у вигляді плоских лінійних масивів (Flat Arrays), де для відношення арності `a` елементи `k`-го кортежу займають позиції від `k * a` до `(k + 1) * a - 1`. Це забезпечує максимальну локальність даних у кеші процесора (L1/L2 Cache Locality) та виключає накладні витрати на вказівники при скануванні відношень під час оцінки кванторів.

### Основні типи констант та перелічень

```
Таблиця 1. Перелічення фонових типів AST-вузлів (FO_NodeType)
┌──────────────────┬───────┬────────────────────────────────────────────────────────┐
│ Ідентифікатор    │ Код   │ Опис та обчислювальний семантичний контракт            │
├──────────────────┼───────┼────────────────────────────────────────────────────────┤
│ FO_NODE_PRED_REL │ 0x01  │ Перевірка відношення R(x₁, ..., xₐ) арності a           │
│ FO_NODE_PRED_EQ  │ 0x02  │ Атомарна рівність x_i == x_j                           │
│ FO_NODE_PRED_LT  │ 0x03  │ Вбудований порядок x_i < x_j у впорядкованій структурі  │
│ FO_NODE_NOT      │ 0x10  │ Унарне логічне заперечення ¬φ                          │
│ FO_NODE_AND      │ 0x11  │ Бінарна логічна кон'юнкція φ₁ ∧ φ₂                     │
│ FO_NODE_OR       │ 0x12  │ Бінарна логічна диз'юнкція φ₁ ∨ φ₂                     │
│ FO_NODE_IMPL     │ 0x13  │ Логічна імплікація φ₁ → φ₂                             │
│ FO_NODE_EXISTS   │ 0x20  │ Екзистенційний квантор ∃x φ                             │
│ FO_NODE_FORALL   │ 0x21  │ Універсальний квантор ∀x φ                             │
│ FO_NODE_LFP      │ 0x30  │ Оператор найменшої нерухомої точки [LFP_{R,x} φ](y)    │
│ FO_NODE_TC       │ 0x31  │ Оператор транзитивного замикання [TC_{x,y} φ](u, v)    │
└──────────────────┴───────┴────────────────────────────────────────────────────────┘
```

Розглянемо детальніше семантику кожного логічного типу вузла. Атомарні предикати `FO_NODE_PRED_REL` звертаються до вхідної реляційної структури та перевіряють, чи належить кортеж поточних значень змінних до вказаного відношення `R`. Вузли `FO_NODE_PRED_EQ` та `FO_NODE_PRED_LT` виконують покомпонентне порівняння скалярних значень елементів домену.

Логічні вузли `FO_NODE_AND` та `FO_NODE_OR` комбінують результати двох піддерев. Вони реалізують семантику короткого замикання (Short-Circuit Evaluation): якщо лівий операнд кон'юнкції повернув `false`, правий операнд не обчислюється; аналогічно, якщо лівий операнд диз'юнкції повернув `true`, обчислення правій гілки скасовується.

Кванторні вузли `FO_NODE_EXISTS` та `FO_NODE_FORALL` існують для реалізації ітераційного обходу всього домену елементів `U`. Вони послідовно призначають ідентифікатору змінної `var_id` значення від `0` до `domain_size - 1` у середовищі обчислень та передають контроль внутрішньому піддереву формули.

## 2. Специфікація структур даних та сигнатур API (C та C++)

Нижче наведено порівняльний програмний інтерфейс обчислювального рушія. Версія C виражена низькорівневими C-структурами із явним керуванням пам'яттю, а версія C++ — об'єктно-орієнтованим класовим інтерфейсом із автоматичним керуванням ресурсами через RAII (`std::unique_ptr` та `std::vector`).

### Детальний контракти інтерфейсних функцій C API

- `fo_structure_create(domain_size, has_order)`: Виділяє динамічну пам'ять для структури `FOStructure`, встановлює розмір домену `n` та ініціалізує порожній масив відношень. Якщо `has_order = true`, автоматично створюється віртуальне бінарне відношення порядку `<`.
- `fo_structure_add_relation(struct_ptr, name, arity)`: Створює нове порожнє відношення з вказаним ім'ям та арністю. Повертає унікальний числовий ідентифікатор відношення `relation_idx` для швидкого доступу за індексом замість пошуку за ім'ям.
- `fo_relation_add_tuple(struct_ptr, relation_idx, tuple)`: Додає новий кортеж елементів. Кожен елемент `tuple[i]` перевіряється на відповідність вимозі `tuple[i] < domain_size`. При перевищенні межі повертається `false` і вставка скасовується.
- `fo_evaluate(node, struct_ptr, env)`: Головна рекурсивна функція оцінки істинності. Функція приймає корінь AST-дерева, вказівник на структуру та фрейм змінних `FOEnvironment`. Повертає булеве значення `true` або `false`.

// =========================================================================
// 1. УПРАВЛІННЯ РЕЛЯЦІЙНИМИ СТРУКТУРАМИ ТА AST-ВУЗЛАМИ У C++
// =========================================================================

namespace fo_logic {

enum class NodeType : uint8_t {
    PredRel, PredEq, PredLt, Not, And, Or, Implies, Exists, ForAll, Lfp, Tc
};

class Structure {
public:
    explicit Structure(size_t domain_size, bool has_order = false);
    ~Structure() = default;

    Structure(const Structure&) = delete;
    Structure& operator=(const Structure&) = delete;
    Structure(Structure&&) noexcept = default;
    Structure& operator=(Structure&&) noexcept = default;

    size_t add_relation(std::string_view name, size_t arity);
    bool add_tuple(size_t relation_idx, const std::vector<size_t>& tuple);

    [[nodiscard]] size_t domain_size() const noexcept;
    [[nodiscard]] bool has_order() const noexcept;
    [[nodiscard]] bool contains_tuple(size_t relation_idx, const std::vector<size_t>& tuple) const;

private:
    struct Relation {
        std::string name;
        size_t arity;
        std::vector<size_t> flat_tuples;
    };
    size_t domain_size_;
    bool has_order_;
    std::vector<Relation> relations_;
};

class Environment {
public:
    Environment() = default;
    void bind(int var_id, size_t val) { bindings_[var_id] = val; }
    [[nodiscard]] size_t get(int var_id) const { return bindings_.at(var_id); }
    void unbind(int var_id) { bindings_.erase(var_id); }

private:
    std::unordered_map<int, size_t> bindings_;
};

class ASTNode {
public:
    virtual ~ASTNode() = default;
    [[nodiscard]] virtual NodeType type() const noexcept = 0;
    [[nodiscard]] virtual bool evaluate(const Structure& st, Environment& env) const = 0;
};

using NodePtr = std::unique_ptr<ASTNode>;

NodePtr make_relation_pred(size_t rel_idx, std::vector<int> var_ids);
NodePtr make_eq_pred(int var1, int var2);
NodePtr make_lt_pred(int var1, int var2);
NodePtr make_not(NodePtr child);
NodePtr make_and(NodePtr left, NodePtr right);
NodePtr make_or(NodePtr left, NodePtr right);
NodePtr make_exists(int var_id, NodePtr body);
NodePtr make_forall(int var_id, NodePtr body);

class ModelChecker {
public:
    explicit ModelChecker(const Structure& st) : structure_(st) {}

    [[nodiscard]] bool verify(const ASTNode& formula) {
        Environment env;
        return formula.evaluate(structure_, env);
    }

private:
    const Structure& structure_;
};

} // namespace fo_logic

### Покроковий розбір реалізації мовою C++

Версія C++ забезпечує строгу семантику володіння об'єктами:
- **Клас `Structure`:** Надає методи `add_relation()` та `add_tuple()`. Метод `contains_tuple()` виконує швидку перевірку наявності кортежу у плоскому масиві `flat_tuples`.
- **Клас `Environment`:** Використовує хеш-таблицю `std::unordered_map<int, size_t>` для збереження зв'язування змінних. Метод `bind()` реєструє нову змінну, а `unbind()` видаляє її при виході з області дії квантора.
- **Класи `ASTNode` та `NodePtr`:** Використання розумних вказівників `std::unique_ptr<ASTNode>` гарантує унікальне володіння піддеревами та автоматичне рекурсивне звільнення пам'яті у деструкторах без ризику витоків пам'яті (Memory Leaks).

## 3. Оптимізаційні паси та проходження AST-дерева

Перед запуском процесу перевірки модельний обчислювач виконує низку статичних оптимізаційних пасів над синтаксичним деревом формули:

1. **Згортання констант (Constant Folding):** Підформули, які не містять вільних змінних чи кванторів, обчислюються один раз на етапі компіляції формули.
2. **Проштовхування кванторів углиб (Quantifier Push-Down):** Квантори `∃x` або `∀x` проштовхуються крізь кон'юнкції або диз'юнкції якомога ближче до атомарних предикатів, де змінна `x` безпосередньо використовується. Це зменшує дублювання обчислень під час ітерацій.
3. **Альфа-конверсія та перейменування:** Автоматичне перейменування конфліктних імен змінних для запобігання тінізації вкладених кванторів.
4. **Усунення подвійних заперечень:** Заміна піддерев виду `¬(¬φ)` на вихідну формулу `φ`.
5. **Спрощення тотожностей:** Спрощення виразів виду `φ ∧ ⊤` до `φ` або `φ ∨ ⊥` до `φ`.

## 4. Обробка помилок та виняткові ситуації

Під час виконання викликів методів обчислювальний рушій гарантує обробку та виявлення таких виняткових ситуацій:

1. **FO_ERR_INVALID_DOMAIN_ELEMENT (Код -101):** Генерується при спробі вставити кортеж або прив'язати змінну до значення `v ≥ domain_size`. У C API функція повертає `false`, у C++ API генерується виняток `std::invalid_argument`.
2. **FO_ERR_UNBOUND_VARIABLE (Код -102):** Генерується при обчисленні атомарного предиката, якщо якась із його змінних відсутня у `FOEnvironment`. Рушій припиняє обчислення та повертає помилку.
3. **FO_ERR_ARITY_MISMATCH (Код -103):** Виникає, якщо кількість переданих ідентифікаторів змінних не відповідає оголошеній арності відношення.
4. **FO_ERR_FIXED_POINT_NON_MONOTONE (Код -201):** Генерується обчислювачем оператора LFP, якщо предикатна змінна `R` входить під непарною кількістю заперечень `NOT`, що порушує монотонність оператора.
5. **FO_ERR_NULL_NODE (Код -301):** Передано нульовий вказівник на вузол AST-дерева під час рекурсивного обходу.

## 5. Профіль обчислювальної складності операцій API

```
Таблиця 2. Асимптотичний профіль ресурсів для операцій API
┌───────────────────────────┬──────────────────┬──────────────────┬────────────────────────┐
│ Операція API              │ Часова складність│ Просторова склад.│ Примітка / Обмеження   │
├───────────────────────────┼──────────────────┼──────────────────┼────────────────────────┤
│ fo_structure_create       │ O(1)             │ O(1)             │ Ініціалізація домену   │
│ fo_relation_add_tuple     │ O(arity)         │ O(arity)         │ Вставка кортежу        │
│ fo_evaluate (FO Formula)  │ O(|φ| · nᵏ)      │ O(k)             │ k — кванторна глибина  │
│ fo_evaluate (FO+TC)       │ O(|φ| · nᵏ⁺²)    │ O(n²)            │ Матриця досяжності     │
│ fo_evaluate (FO+LFP)      │ O(|φ| · nᵏ⁺ᵃ)    │ O(nᵃ)            │ a — арність точки      │
└───────────────────────────┴──────────────────┴──────────────────┴────────────────────────┘
```

З аналізу профілю видно, що основний внесок у часову складність робить обчислення кванторних виразів `fo_evaluate`. Пам'ять при цьому зростає лише лінійно від кванторної глибини `O(k)`, що робить інтерпретатор надзвичайно ефективним з погляду використання оперативної пам'яті.

## 6. Приклад повного опису використання API

Нижче наведено практичний сценарій використання C++ API для створення графа та перевірки логічного запиту щодо наявності орієнтованого трикутника `K₃`:

1. **Ініціалізація графа:** Створюється об'єкт `Structure g(5)` на 5 вершинах.
2. **Додавання ребер:** Метод `add_relation("E", 2)` реєструє бінарне відношення ребер. Викликами `add_tuple()` додаються ребра `(0, 1)`, `(1, 2)` та `(2, 0)`.
3. **Побудова формули:** Фабричними функціями конструюється формула `∃x ∃y ∃z (E(x,y) ∧ E(y,z) ∧ E(z,x))`.
4. **Виконання перевірки:** Об'єкт `ModelChecker checker(g)` запускає метод `verify()`, який повертає `true`.
