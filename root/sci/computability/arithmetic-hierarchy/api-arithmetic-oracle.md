# 📋 Інтерфейс аналізу арифметичних префіксів та оракула градусів

Даний документ описує повний контракт програмування та специфікацію типізованого системного інтерфейсу (API) для логічного аналізу арифметичних формул першого порядку, обчислення їхнього канонічного класу в арифметичній ієрархії (`Σ♁⁰`, `Π♁⁰`, `Δ♁⁰`), контролю згортання кванторів через бієкцію Кантора та безпечної взаємодії з абстрактними оракулами послідовних стрибків Тюринга `0⁽ⁿ⁾`.

## 1. Призначення інтерфейсу та сфера застосування

Бібліотека надає уніфікований C/C++ інструментарій для символьного розбору, верифікації та класифікації арифметичних предикатів над множиною натуральних чисел `ℕ`. Основне призначення інтерфейсу полягає у наданні програмним системам статичного аналізу, автоматичного доведення теорем (SMT-солверам) та інструментам верифікації коду засобів для:
- Автоматичного приведення довільних префіксних формул до канонічного вигляду зі строгим чергуванням кванторів `∃` та `∀`.
- Визначення точного мінімального рівня арифметичної ієрархії (`Σ♁⁰` чи `Π♁⁰`) для заданої логічної специфікації.
- Розрахунку необхідного рівня оракула Тюринга `0⁽ⁿ⁾`, який вимагається для алгоритмічної симуляції або перелічуваності предиката.
- Безпечного кодування та декодування векторів вхідних змінних через ітероване парування Кантора без ризику виходу за межі розрядності цілих чисел.

Архітектура даного API розроблена за принципом мінімального системного оверхеду (zero-cost abstraction) та забезпечує повну відсутність побічних ефектів, що робить його придатним як для високонавантажених компіляторних аналізаторів, так і для систем реального часу.

## 3. Опис функціонального інтерфейсу та алгоритмічний механізм

### 3.1. Синтаксичний аналіз та класифікація формул

Головна функція розбору `ah_classify_prefix` приймає послідовність кванторів та здійснює їхній повний синтаксичний аналіз.

Механізм виконання функції складається з декількох послідовних етапів:

1. **Етап валідації вхідних даних:** Функція перевіряє, що вказівники `quants` та `info` не є нульовими (`NULL`). Також здійснюється перевірка символьних ідентифікаторів змінних на коректність формату.
2. **Етап сепарації обмежених кванторів:** Програмується фільтрація: квантори з прапорцем `is_bounded == true` пропускаються при аналізі чергувань, бо вони обчислюються за скінченний час та належать до класу `Δ₀⁰`.
3. **Етап алгоритмічного згортання Кантора:** Сусідні необмежені квантори одного типу (наприклад, декілька `EXISTS` поспіль) групуються в один мета-квантор. Це моделює використання функції парування Кантора `⟨a, b⟩`, яка згортає декілька змінних у єдиний натуральний код без втрати інформації.
4. **Етап формування підсумкового класу:** Якщо після фільтрації необмежених кванторів не залишилося, предикат класифікується як `AH_CLASS_DELTA_0`. Якщо перший необмежений квантор у згорнутому ланцюжку є `EXISTS`, формується клас `AH_CLASS_SIGMA_N`, де `n` дорівнює кількості згорнутих мета-кванторів. Якщо перший квантор `FORALL`, формується клас `AH_CLASS_PI_N`.
5. **Розрахунок оракульних вимог:** За теоремою Поста, для класу рівня `n > 0` розраховується номер необхідного оракульного стрибка `oracle_jump_required = n - 1`.

### Поведінка при крайових випадках (Edge Cases)

Реалізація аналізатора розрахована на стійку обробку нетипових та граничних ситуацій:

1. **Порожній масив кванторів (`count == 0`):** Якщо у формулі взагалі немає кванторів, предикат розглядається як чисто арифметичне обчислюване вираження. Функція `ah_classify_prefix` повертає клас `AH_CLASS_DELTA_0`, встановлює `level_n = 0`, `oracle_jump_required = 0`, `is_decidable = true` та повертає статус `AH_SUCCESS`.
2. **Лише обмежені квантори:** Якщо всі квантори у формулі мають `is_bounded == true`, результат тотожний відсутності кванторів: класифікується як `AH_CLASS_DELTA_0`, оскільки обмежені квантори не вимагають нескінченного пошуку та можуть бути повністю розгорнуті в скінченну кон'юнкцію чи диз'юнкцію.
3. **Чергування з великою кількістю однакових кванторів:** Наприклад, `∃x₁ ∃x₂ ∃x₃ ∃x₄ ∀y₁ ∀y₂`. Алгоритм згортання Кантора зводить цей ланцюжок до 2 мета-кванторів (`∃X ∀Y`). Початкова кількість `raw_quantifier_count = 6` зменшується до `contracted_count = 2`, і формула класифікується як `AH_CLASS_SIGMA_N` з `level_n = 2`.
4. **Переповнення типу цілих чисел у паруванні Кантора:** Функція парування `⟨x, y⟩` виконує множення `(x + y) * (x + y + 1)`. При великих значеннях `x` або `y` (понад `2³² - 1`) під час множення може виникнути 64-бітне переповнення. Інтерфейс гарантує виявлення переповнення перед виконанням множення та повертає код `AH_ERR_INTEGER_OVERFLOW`, запобігаючи невизначеній поведінці (undefined behavior).
5. **Багатопотокова безпека (Thread Safety):** Усі функції бібліотеки є чисто функціональними (stateless) та не використовують глобального або статичного змінного стану. Виклики `ah_classify_prefix` та `ah_cantor_encode` є повністю потокобезпечними (reentrant) та можуть паралельно виконуватися у довільній кількості робочих потоків без додаткових блокувань чи м'ютексів.

## 5. Покрокове трасування роботи аналізатора на реальному прикладі

Для кращого розуміння функціонування даного API простежимо покроковий шлях аналізу префікса формули, яка перевіряє тотальність алгоритму.

Розглянемо вихідний префікс формули тотальності:

```
∀x ∃s T(e, x, s)
```

Вхідний масив кванторів містить два елементи:
1. Елемент 0: `kind = AH_QUANT_FORALL`, `var_symbol = "x"`, `is_bounded = false`.
2. Елемент 1: `kind = AH_QUANT_EXISTS`, `var_symbol = "s"`, `is_bounded = false`.

### Покроковий процес виконання у функції `ah_classify_prefix`:

1. **Ініціалізація:** Функція отримує масив з двох кванторів.
2. **Перевірка обмежень:** Обидва квантори мають `is_bounded == false`, отже, жоден з них не ігнорується.
3. **Аналіз чергувань:**
   - Перший квантор — `FORALL` над змінною `x`.
   - Другий квантор — `EXISTS` над змінною `s`.
   - Оскільки типи кванторів є різними (`FORALL` змінюється на `EXISTS`), згортання не об'єднує їх. Кількість мета-кванторів лишається `contracted_count = 2`.
4. **Визначення класу:**
   - Перший квантор у префіксі — `FORALL`. Отже, присвоюється клас `AH_CLASS_PI_N`.
   - Кількість чергувань `n = 2`. Формується позначення класу `Π₂⁰`.
5. **Обчислення оракула:**
   - Розраховується `oracle_jump_required = 2 - 1 = 1`.
   - Це означає, що для перевірки тотальності потрібен оракул першого стрибка Тюринга `0' = K` (проблема зупинки).
6. **Формування прапорців:**
   - `is_decidable = false` (оскільки `level_n > 0`).
   - `is_recursively_enumerable = false` (оскільки клас `Π₂⁰` є вищим за `Σ₁⁰`).
