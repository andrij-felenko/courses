# 📋 Інтерфейс та контракти псевдовипадкового генератора складності

Інтерфейсний контракт модуля псевдовипадкового генератора складності регулює точний розподіл відповідальності між генератором бітів, комбінаторним дизайном підмножин, базовою складною функцією та контролером статистичних розрізнювачів. Цей довідковий документ визначає публічні типи даних, структуру конфігураційних параметрів, протоколи помилок, сигнатури викликів та вимоги до обчислювальних ресурсів для реалізації дерандомізаційних псевдовипадкових генераторів (насамперед моделі Нісана–Вігдерсона).

---

## 1. Специфікація типів даних та структур

Типи даних модулю розроблено з урахуванням суворої строкатості параметрів складності, дотримання нульових витоків пам'яті та коректного представлення бітових масивів. Кожна структура виконує чітко розмежовану роль в інкапсуляції обчислювального контексту генератора.

### 1.1 Коди відповідей та помилок (`nw_status_t`)

Усі функції публічного API повертають детермінований код статусу `nw_status_t`. Це дозволяє викликаючій стороні обробляти помилки на етапі конфігурації без використання механізмів винятків у сирому середовищі C.

| Код статусу | Числове значення | Опис та семантика виклику |
| :--- | :---: | :--- |
| `NW_SUCCESS` | `0` | Операція завершилася успішно, результати обчислення валідні. |
| `NW_ERR_NULL_PTR` | `-1` | Передано вказівник `NULL` для обов'язкових аргументів функції. |
| `NW_ERR_INVALID_PARAM` | `-2` | Неприпустимі значення параметрів дизайну (`l > d`, `γ >= l` або `m == 0`). |
| `NW_ERR_DESIGN_VIOLATION` | `-3` | Перетин підмножин дизайну перевищує задану межу `γ` для якоїсь пари індексів. |
| `NW_ERR_SEED_TOO_SHORT` | `-4` | Наданий буфер насіння коротший за оголошену довжину `d` бітів. |
| `NW_ERR_OUT_OF_MEMORY` | `-5` | Не вдалося виділити динамічну пам'ять під матрицю дизайну або таблицю істинності. |

### 1.2 Структура комбінаторного дизайну (`nw_design_config_t`)

Конфігураційна структура утримує всі фундаментальні асимптотичні параметри складності генератора:

:::tabs
```c
typedef struct {
    size_t seed_length_d;      /* Загальна довжина вхідного насіння d у бітах */
    size_t subset_length_l;    /* Розмір кожної підмножини S_i (вхід базової функції) */
    size_t output_length_m;    /* Кількість згенерованих псевдовипадкових бітів m */
    size_t max_intersection_g; /* Максимально дозволений перетин |S_i ∩ S_j| <= γ */
} nw_design_config_t;
```
```cpp
struct DesignConfig {
    std::size_t seed_length_d{0};      // Довжина насіння d
    std::size_t subset_length_l{0};    // Розмір підмножини l
    std::size_t output_length_m{0};    // Довжина виходу m
    std::size_t max_intersection_g{0}; // Максимальний перетин gamma
};
```
:::

Виклики функцій з цією структурою перевіряють наступні обчислювальні інваріанти:
- Довжина вхідного насіння `seed_length_d` повинна бути строго більшою за розмір підмножини `subset_length_l`.
- Максимально дозволений перетин `max_intersection_g` має бути строго меншим за `subset_length_l` (найкраще значення `γ = O(log m)`).
- Кількість вихідних бітів `output_length_m` визначає підсумковий коефіцієнт розширення насіння `m / d`.

### 1.3 Контекст генератора (`nw_generator_ctx_t`)

Контекст зберігає внутрішній стан NW PRG, включаючи попередньо згенеровану матрицю підмножин та масив таблиці істинності складної булевої функції `f`:

:::tabs
```c
typedef struct {
    nw_design_config_t config; /* Конфігураційні параметри дизайну */
    uint32_t **design_matrix;  /* Двовимірний масив індексів розміру m x l */
    uint8_t *truth_table;       /* Таблиця істинності складної функції розміру 2^l біт */
    bool is_initialized;       /* Прапорець завершення ініціалізації */
} nw_generator_ctx_t;
```
```cpp
struct GeneratorContext {
    DesignConfig config;
    std::vector<std::vector<std::size_t>> design_matrix;
    std::vector<uint8_t> truth_table;
    bool is_initialized{false};
};
```
:::

Управління пам'яттю контексту в C вимагає обов'язкового виклику парної функції `nw_generator_destroy` для уникнення витоків пам'яті в двовимірній матриці `design_matrix`. У C++ реалізації виділення та звільнення ресурсів керується деструкторами векторів `std::vector` (RAII).

### 1.4 Структура статистичного розрізнювача (`nw_distinguisher_t`)

Структура розрізнювача описує булеву схему або ефективний алгоритм `D`, який намагається відрізнити псевдовипадкові рядки виходу PRG від справжнього хаосу:

:::tabs
```c
typedef uint8_t (*nw_eval_func_t)(const uint8_t *bits, size_t len, void *user_data);

typedef struct {
    const char *name;          /* Текстовий ідентифікатор типу розрізнювача */
    size_t target_circuit_size;/* Схемна складність S розрізнювача */
    nw_eval_func_t eval_func;  /* Вказівник на функцію обчислення схеми D(w) */
    void *user_data;           /* Користувацький контекст для схеми */
} nw_distinguisher_t;
```
```cpp
using DistinguisherEvaluator = std::function<uint8_t(std::span<const uint8_t>)>;

struct Distinguisher {
    std::string name;
    std::size_t target_circuit_size{0};
    DistinguisherEvaluator eval_func;
};
```
:::

Вказана функція `eval_func` приймає масив бітів довжини `m` і повертає біт `1` (якщо вважає рядок випадковим) або `0` (якщо вважає рядок виходом PRG).

## 2. Публічний інтерфейс функцій (C та C++ API)

Модуль надає три основні операції життєвого циклу: створення контексту, генерація потоку бітів та знищення контексту.

### 2.1 Ініціалізація контексту дизайну (`nw_design_create`)

:::tabs
```c
nw_status_t nw_design_create(
    nw_generator_ctx_t **ctx,
    const nw_design_config_t *config,
    const uint8_t *truth_table,
    size_t truth_table_bytes
);
```
```cpp
std::expected<GeneratorContext, nw_status_t> createDesign(
    const DesignConfig& config,
    std::span<const uint8_t> truth_table
);
```
:::

- **Призначення**: Створює та ініціалізує контекст NW PRG, розподіляє пам'ять під матрицю дизайну та валідує параметри.
- **Вхідні параметри**:
  - `config`: Структура з оголошеними параметрами `d, l, m, γ`.
  - `truth_table`: Масив бітів таблиці істинності функції `f`. Повинен мати довжину принаймні `2^l / 8` байтів.
- **Предумови**: `config->subset_length_l <= config->seed_length_d`, `config->max_intersection_g < config->subset_length_l`.
- **Постумови**: Перевірено виконання умов дизайну для всіх пара наборів `i ≠ j`. У разі успіху C-версія повертає `NW_SUCCESS`, а C++20 версія повертає новий екземпляр `GeneratorContext`.

### 2.2 Розгортання псевдовипадкової послідовності (`nw_generate_stream`)

:::tabs
```c
nw_status_t nw_generate_stream(
    const nw_generator_ctx_t *ctx,
    const uint8_t *seed_bytes,
    size_t seed_bytes_len,
    uint8_t *out_bits_buffer,
    size_t out_bits_capacity
);
```
```cpp
std::expected<std::vector<uint8_t>, nw_status_t> generateStream(
    const GeneratorContext& ctx,
    std::span<const uint8_t> seed
);
```
:::

- **Призначення**: Приймає короткий бітовий вектор насіння та обчислює `m` псевдовипадкових бітів.
- **Вхідні параметри**:
  - `ctx`: Валідний ініціалізований контекст генератора.
  - `seed`: Масив насіння довжиною принаймні `d` бітів.
- **Особливості виконання**: Операція обчислення є констатною за часом для фіксованої довжини `m`, що гарантує стійкість до таймінгових атак.

## 3. Оцінка розрізнювачів та обчислення переваги (`Advantage`)

Для формальної перевірки нерозрізненності згенерованої послідовності реалізується тестовий контролер статистичної переваги:

:::tabs
```c
typedef struct {
    double prob_prg;      /* Імовірність Pr[D(G(s)) = 1] */
    double prob_random;   /* Імовірність Pr[D(r) = 1] */
    double advantage;     /* Перевага |prob_prg - prob_random| */
    size_t total_samples; /* Кількість випробувань */
} nw_test_result_t;

nw_status_t nw_evaluate_distinguisher(
    const nw_generator_ctx_t *ctx,
    const nw_distinguisher_t *distinguisher,
    size_t num_samples,
    nw_test_result_t *result
);
```
```cpp
struct TestResult {
    double prob_prg{0.0};
    double prob_random{0.0};
    double advantage{0.0};
    std::size_t total_samples{0};
};

std::expected<TestResult, nw_status_t> evaluateDistinguisher(
    const GeneratorContext& ctx,
    const Distinguisher& distinguisher,
    std::size_t num_samples
);
```
:::

### Алгоритм обчислення переваги
1. Проводиться `num_samples` ітерацій: на кожній генератор повертає `G(s)` для випадкового насіння `s`, а схема `D` обчислює `D(G(s))`.
2. Одночасно генерується `num_samples` абсолютно випадкових рядків `r` тієї ж довжини `m`, над якими обчислюється `D(r)`.
3. Оцінюється статистична перевага за формулою:

```
Adv_D(NW) = | (1 / N) * ∑ D(G(s_i)) - (1 / N) * ∑ D(r_i) |
```

Якщо обчислена перевага `Adv_D(NW)` є меншою за заданий поріг `ε`, схема `D` вважається обдуреною генератором.

## 4. Специфікація обгортки мовою C++20

Для об'єктно-орієнтованих систем надається C++20 клас `NisanWigdersonEngine`, який обгортає низькорівневий C API з дотриманням семантики RAII:

```cpp
#include <span>
#include <vector>
#include <memory>
#include <expected>

class NisanWigdersonEngine {
public:
    explicit NisanWigdersonEngine(
        const DesignConfig& config,
        std::span<const uint8_t> truth_table
    );
    
    ~NisanWigdersonEngine() = default;
    NisanWigdersonEngine(const NisanWigdersonEngine&) = delete;
    NisanWigdersonEngine& operator=(const NisanWigdersonEngine&) = delete;
    NisanWigdersonEngine(NisanWigdersonEngine&&) noexcept = default;
    NisanWigdersonEngine& operator=(NisanWigdersonEngine&&) noexcept = default;

    [[nodiscard]] std::expected<std::vector<uint8_t>, nw_status_t> 
    generateStream(std::span<const uint8_t> seed) const noexcept;
};
```

Використання `std::expected` дозволяє передавати коди помилок `nw_status_t` без генерації винятків у критичних за продуктивністю алгоритмах. Метод `generateStream` призначений для безпечного виклику з багатьох потоків виконання одночасно, оскільки екземпляр класу є незмінним після конструювання.

## 5. Обробка крайових випадків та відновлення після помилок

У критичних високонавантажених обчислювальних середовищах модуль NW PRG забезпечує детерміноване відновлення після помилок:

1. **Неприпустима довжина насіння (`NW_ERR_SEED_TOO_SHORT`)**: Якщо розробник передає буфер насіння, розмір якого менший за конфігураційну довжину `d`, генератор перериває обчислення до моменту звернення до пам'яті і повертає відповідний код помилки, не змінюючи вміст вихідного буфера.
2. **Переповнення вихідного буфера**: При виклику `nw_generate_stream` система перевіряє ємність вихідного буфера `out_bits_capacity`. Якщо зазначена ємність менша за обчислену вихідну довжину `m`, виклик відхиляється з кодом `NW_ERR_INVALID_PARAM`.
3. **Порушення умов дизайну при створенні (`NW_ERR_DESIGN_VIOLATION`)**: Якщо користувач передає власну матрицю підмножин, функція створення `nw_design_create` проводить повну перевірку перетинів між усіма парами `i ≠ j`. У разі виявлення хоча б одного перетину, що перевищує `γ`, створення скасовується, а виділена пам'ять повертається операційній системі.

## 6. Таблиця допустимих параметрів складності

При виборі конфігураційних параметрів генератора необхідно дотримуватись наступних співвідношень для забезпечення бажаного рівня дерандомізації:

| Режим дерандомізації | Довжина `d` (Seed) | Розмір `l` | Довжина `m` | Перетин `γ` | Складність `Size(f)` | Результат для `BPP` |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **Експоненціальний** | `O(log m)` | `c · log m` | `m` | `log m` | `2^(Ω(l))` | `P = BPP` (Повна дерандомізація) |
| **Субекспоненціальний** | `m^ε` | `m^(ε/2)` | `m` | `O(log m)` | `2^(l^δ)` | `BPP ⊆ DTIME(2^(n^ε))` |
| **Поліноміальний** | `m / 2` | `m / 4` | `m` | `m / 8` | `poly(l)` | Слабка дерандомізація |

## 7. Обмеження та безпека пам'яті (Safety Rules)

1. **Заборона модифікації матриці дизайну**: Матриця `design_matrix` є незмінною після етапу ініціалізації. Будь-які спроби запису під час генерації викликають undefined behavior.
2. **Константний час проектування**: Вибірка бітів `z|S_i` здійснюється за фіксований час без умовних розгалужень, залежних від значень насіння `z`, для запобігання витокам через побічні канали таймінгу.
3. **Обмеження розміру таблиці істинності**: Конфігурація обмежена `l <= 20`, оскільки розмір масиву таблиці істинності зростає як `2^l` бітів (при `l = 20` розмір становить 1 Мбайт, при `l = 30` — 128 Мбайт).
4. **Валідація буферів виходу**: Функція `nw_generate_stream` обов'язково перевіряє `out_bits_capacity >= config.output_length_m` для запобігання переповненню буфера.
5. **Багатопотокова безпека**: Контекст `nw_generator_ctx_t` є безпечним для паралельного зчитування з багатьох потоків без застосування блокувань м'ютексів.
