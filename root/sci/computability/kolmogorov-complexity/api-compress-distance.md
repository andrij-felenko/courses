# 📋 Інтерфейс та контракт метрики NCD

Програмний інтерфейс (API) бібліотеки NCD (Normalized Compression Distance) задає строгий контракт, конфігураційні параметри, структури даних та правила виклику для оцінки алгоритмічної подібності бінарних об'єктів.

## 1. Загальна концепція та контракт інтерфейсу

Бібліотека надає низькорівневий C API та об'єктно-орієнтовану C++ обгортку для обчислення нормалізованої стиснювальної відстані між бінарними буферами в пам'яті, масивами файлів та для побудови матриць подібності.

### Апаратні та програмні вимоги
- **Сумісність C API:** C99 та новіші (заголовок `ncd_core.h`).
- **Сумісність C++ API:** C++20 / C++23 (заголовок `ncd.hpp`, вимагає підтримки `std::span` та `std::expected`).
- **Залежності:** Опціонально залінковані бібліотеки `libz` (zlib), `libbz2`, `liblzma` та `libzstd`. За їх відсутності бібліотека фолбечиться на вбудований беззалежносний компресор RLE/LZ77.

### Аксіоми контракту відстані
Для будь-якої реалізації NCD гарантуються такі математичні та інженерні властивості поверненого значення `d = NCD(x, y)`:

1. **Обмеженість діапазону:** Значення `d` завжди лежить в інтервалі від `0.0` до `1.0 + ε` (де `ε` — мала похибка заголовка компресора). Значення від'ємні чи більші за `1.0 + ε` автоматично нормуються функцією до межових `0.0` або `1.0`.
2. **Самоподібність:** `NCD(x, x) ≈ 0.0`. Для більшості стиснювачів значення `NCD(x, x)` лежить у межах від `0.0` до `0.05`.
3. **Симетрія:** `NCD(x, y) = NCD(y, x)`. Якщо обраний компресор виявляє легку асиметрію через внутрішні стратегії кодування, бібліотека гарантує симетричність через симетризований виклик `min(C(xy), C(yx))`.
4. **Монотонність:** Якщо `x` є підрядком `y`, то `C(xy) ≈ C(y)` і `NCD(x, y)` задовольняє нерівність трикутника з іншими об'єктами.

### Детальний опис функцій, параметрів та кодів помилок

#### 1. Структура конфігурації `ncd_config_t`
- `engine`: Визначає внутрішній алгоритм стиснення. Значення за замовчуванням `NCD_ENGINE_ZSTD` забезпечує найкращий баланс між швидкістю стиснення (до 400 МБ/с) та розміром вікна (до 128 МБ).
- `level`: Рівень стиснення. Для `ZSTD` допустимий діапазон від 1 до 22. Вищі рівні збільшують час стиснення, але покращують точність оцінки `K(x)`. Для швидкодії у системних сервісах рекомендується рівень 3.
- `window_size`: Максимальний розмір ковзного вікна у байтах. Значення 0 означає використання розміру вікна за замовчуванням для даного рушія (32 КБ для zlib, 900 КБ для bzip2, 128 МБ для zstd).
- `threads`: Кількість паралельних потоків виконання при матричних обчисленнях.

#### 2. Контракт процедури `ncd_compute_pair`
Процедура виконує послідовність із трьох стиснень:
1. Обчислює розмір стисненого першого буфера `C(a)`.
2. Обчислює розмір стисненого другого буфера `C(b)`.
3. Виділяє тимчасову пам'ять під конкатенацію `ab` розміром `size_a + size_b`, копіює туди обидва буфери послідовно і обчислює розмір стисненої конкатенації `C(ab)`.
4. Обчислює підсумкове значення `NCD = (C(ab) - min(C(a), C(b))) / max(C(a), C(b))` та нормує результат до інтервалу `[0.0, 1.0]`.

В разі невдалого виділення тимчасової пам'яті функція негайно повертає код `NCD_ERR_ALLOC_FAILED` без модифікації значення за вказівником `out_distance`. Вхідні буфери залишаються незмінними.

#### 3. Контракт процедури `ncd_compute_matrix`
Процедура призначена для пакетного порівняння `N` об'єктів. Матриця розміром `count × count` записується в одновимірний масив `out_matrix` за формулою індексації `out_matrix[i * count + j]`.
- Елементи головної діагоналі `out_matrix[i * count + i]` автоматично заповнюються нулями `0.0`.
- Оскільки відстань NCD є симетричною, функція обчислює лише значення для верхнього трикутника `i < j`, а значення для нижнього трикутника `j < i` дзеркально копіюються `out_matrix[j * count + i] = out_matrix[i * count + j]`. Це зменшує обсяг обчислень удвічі.
- Якщо `threads > 1`, обчислення незалежних пар розподіляються між робочими потоками через пули потоків POSIX Threads або OpenMP.

#### 4. Життєвий цикл пам'яті та нульове копіювання (Zero-Copy)
- **Управління пам'яттю у C API:** Клієнтський код повністю відповідає за створення та звільнення вхідних буферів `buf_a` та `buf_b`. Функції бібліотеки NCD не приймають володіння над переданими вказівниками й не звільняють їх. Тимчасовий буфер конкатенації `ab` виділяється у купі під час виклику та гарантовано звільняється перед поверненням керування з процедури.
- **Нульове копіювання у C++ API:** Використання `std::span<const uint8_t>` у C++20 дозволяє передавати посилання на довільні неперервні ділянки пам'яті (вектори `std::vector`, рядки `std::string_view` або ставі масиви) без здійснення жодного проміжного копіювання вхідних байтів.

#### 5. Обробка помилок та діагностика
- `NCD_ERR_NULL_POINTER`: Передано вказівник `NULL` у списки буферів чи конфігурацію. Програма мусить перевірити валідність вказівників перед викликом.
- `NCD_ERR_EMPTY_BUFFER`: Обидва порівнювані буфери мають довжину 0 байтів.
- `NCD_ERR_ALLOC_FAILED`: Не вдалося виділити пам'ять у купі під тимчасову конкатенацію `ab`. Слід зменшити розмір оброблюваних блоків або звільнити пам'ять.
- `NCD_ERR_INVALID_ENGINE`: Запитуваний рушій компресії (наприклад, `NCD_ENGINE_LZMA`) не було ввімкнено під час збірки бібліотеки.

## 3. Консольний інтерфейс (CLI Interface)

Інструмент командного рядка `ncd-tool` слугує для швидкого розрахунку матриць відстаней між файлами та побудови дендрограм без написання коду.

### CLI Прапори та опції

| Прапорець | Аргумент | За замовчуванням | Опис |
| :--- | :--- | :--- | :--- |
| `-e, --engine` | `zlib\|bzip2\|lzma\|zstd` | `zstd` | Алгоритм стиснення для оцінки $C(x)$ |
| `-l, --level` | `1..22` | `3` | Рівень стиснення компресора |
| `-o, --output` | `<path>` | `stdout` | Файл для збереження результату |
| `-f, --format` | `text\|json\|csv\|phylip` | `text` | Формат матриці виводу |
| `-j, --threads` | `<int>` | `auto` | Кількість робочих потоків |
| `--verbose` | — | off | Вивід деліметрії та компресійних коефіцієнтів |

### Детальні сценарії використання CLI

#### 1. Порівняння двох файлів вихідного коду
```bash
ncd-tool --engine zstd main_v1.cpp main_v2.cpp
```
Виводить у стандартний потік єдине число (наприклад, `0.0412`), яке показує алгоритмічну відстань між версіями файлу.

#### 2. Побудова матриці для біоінформатики у форматі PHYLIP
```bash
ncd-tool -e lzma -f phylip -o dist.phy ./dna_samples/*.fasta
```
Зчитує всі FASTA-файли з каталогу, обчислює відстані за допомогою LZMA (що забезпечує максимальну глибину пошуку повторів у ДНК) і записує матрицю у форматі PHYLIP, придатному для побудови філогенетичних дерев у програмах PHYLIP або FastME.

#### 3. Масова кластеризація шкідливого коду у формат JSON
```bash
ncd-tool --format json -j 8 ./malware_samples/* > matrix.json
```
Використовує 8 паралельних потоків для аналізу вибірки вірусних файлів і генерує JSON-звіт із детальною інформацією про розміри файлів та матрицю відстаней.

## 4. Формат виводу матриці (JSON Schema)

При виклику з прапорцем `--format json` або через API повертається така структура:

```json
{
  "engine": "zstd",
  "compression_level": 3,
  "count": 3,
  "labels": ["sample_A.bin", "sample_B.bin", "sample_C.bin"],
  "compressed_sizes": [1024, 1040, 4096],
  "matrix": [
    [0.0000, 0.0452, 0.8912],
    [0.0452, 0.0000, 0.8875],
    [0.8912, 0.8875, 0.0000]
  ]
}
```

## 5. Продуктивність та порівняльні характеристики рушіїв

| Алгоритм | Швидкість стиснення | Ефективність оцінки $K(x)$ | Максимальне вікно | Рекомендована сфера застосування |
| :--- | :--- | :--- | :--- | :--- |
| **Zlib** | 150 МБ/с | Середня | 32 КБ | Малі рядки, embedded-пристрої |
| **Bzip2** | 15 МБ/с | Висока | 900 КБ | Повторювані тексті та вихідний код |
| **LZMA** | 4 МБ/с | Гранична | 1 ГБ | ДНК, геноміка, великі файлові корпуси |
| **Zstd** | 400 МБ/с | Висока | 128 МБ | **Основний за замовчуванням** (вірусний аналіз, мережеві дамп) |
