# 𝒰 Математичні доведення та константа Чайтіна

Фундаментальні результати алгоритмічної теорії інформації — теорема інваріантності Колмогорова, необчислюваність складності `K(x)` через формалізований парадокс Беррі, нерівність Крафта–Чайтіна для префіксних кодів, теорема про симетрію алгоритмічної інформації та властивості константи Чайтіна `Ω` — спираються на строгі формальні доведення.

## 1. Строге доведення теореми інваріантності

Нехай `𝒰` — універсальна частина частково-рекурсивна функція (універсальна машина Тюринга), яка бере на вхід програму `p ∈ {0,1}*` та вхідні дані `y ∈ {0,1}*` і повертає результат `𝒰(p, y) ∈ {0,1}*`. За відсутності додаткового входу `y` вважаємо `𝒰(p) = 𝒰(p, ε)`.

Проста складність за Колмогоровим рядка `x` відносно обчислювача `M` визначається як:

```
K_M(x) = min { |p| : M(p) = x }
```

Якщо таких `p` не існує, `K_M(x) = ∞`.

**Теорема (Інваріантність Колмогорова):** Існує така універсальна машина Тюринга `𝒰`, що для будь-якого іншого обчислювача `M` знайдеться стала `c_M`, залежна лише від `M`, що для всіх `x ∈ {0,1}*`:

```
K_𝒰(x) ≤ K_M(x) + c_M
```

**Доведення:**
Оскільки `𝒰` є універсальною машиною Тюринга, вона здатна здекодувати та зсимулювати роботу будь-якого обчислювача `M`. Фіксуємо ефективну кодування номерів машин Тюринга. Нехай `code(M)` — скінченний бінарний рядок, що кодує програму-симулятор для машини `M` на універсальній машині `𝒰`.

Конструюємо універсальну програму для `𝒰`, яка отримує на вхід пару `⟨code(M), p⟩`. Для збереження префіксно розпізнаваної межі між `code(M)` та `p` дублюємо кожен біт `code(M)` і додаємо маркер `01` наприкінці. Позначимо це кодування як `prefix(code(M))`. Довжина цього префікса:

```
|prefix(code(M))| = 2 · |code(M)| + 2
```

Тоді для будь-якої програми `p`, яка змушує `M` вивести `x` (`M(p) = x`), машина `𝒰` на вхідному рядку `p' = prefix(code(M)) p` спочатку зчитує та розшифровує `code(M)`, а потім запускає симуляцію `M(p)`. Оскільки `M(p) = x`, маємо `𝒰(p') = x`.

Оцінюємо довжину програми `p'`:

```
|p'| = |prefix(code(M))| + |p|
     = |p| + (2·|code(M)| + 2)          [розбиття на програму p та префікс коду M]
     = |p| + c_M                        [де c_M = 2·|code(M)| + 2 = const]
```

Усілок мінімуму за всіма `p`, що дають `M(p) = x`:

```
K_𝒰(x) = min { |p'| : 𝒰(p') = x }
       ≤ min { |p| + c_M : M(p) = x }
       = K_M(x) + c_M
```

Шо й треба було довести. Наслідок: для двох різних універсальних машин `𝒰₁` та `𝒰₂`:

```
|K_𝒰₁(x) - K_𝒰₂(x)| ≤ max(c_𝒰₁, c_𝒰₂) = O(1)
```

## 2. Підрахунковий аргумент та існування нестиснюваних рядків

Оцінимо кількість рядків, які можна стиснути алгоритмічно хоча б на `k` біт.

**Теорема (Існування випадкових рядків):** Для будь-якої довжини `n` і будь-якого `k ≥ 1` кількість рядків `x` довжини `n`, для яких `K(x) < n - k`, менша ніж `2ⁿ⁻ᵏ`.

**Доведення:**
Загальна кількість бінарних рядків довжини `n` дорівнює `2ⁿ`.
Загальна кількість усіх можливих програм `p` довжиною строго менше ніж `n - k` дорівнює сумі геометричної прогресії:

```
N_program = ∑_{j=0}^{n-k-1} 2ʲ
          = 2ⁿ⁻ᵏ - 1                    [сума powers 2⁰ + 2¹ + ... + 2ⁿ⁻ᵏ⁻¹]
          < 2ⁿ⁻ᵏ
```

Оскільки кожна програма `p` може вивести на детермінованій універсальній машині `𝒰` не більше одного рядка `x`, кількість DISTINCT рядків `x` довжини `n`, для яких існує програма довжини `< n - k`, не може перевищувати кількості таких програм:

```
Count({ x ∈ {0,1}ⁿ : K(x) < n - k }) ≤ N_program = 2ⁿ⁻ᵏ - 1 < 2ⁿ⁻ᵏ
```

Поділивши на загальну кількість рядків `2ⁿ`, отримуємо частку стиснюваних рядків:

```
Fraction(K(x) < n - k) < (2ⁿ⁻ᵏ) / 2ⁿ = 2⁻ᵏ
```

При `k = 1` частка рядків зі складністю `K(x) < n - 1` менша ніж `1/2` (менше ніж 50%).
При `k = 10` частка стиснюваних на 10 біт рядків менша ніж `2⁻¹⁰ ≈ 0.00097` (менше ніж 0.1%).

Отже, принаймні один рядок `x` довжини `n` задовольняє нерівності `K(x) ≥ n`. Такий рядок називається **алгоритмічно несжимаємим** або **випадковим за Колмогоровим**.

## 3. Необчислюваність складності K(x) та парадокс Беррі

**Теорема (Необчислюваність):** Функція `K(x): {0,1}* → ℕ` не є частково-рекурсивною (тобто не існує алгоритму, який за вхідним рядком `x` обчислює `K(x)` і зупиняється).

**Доведення (Формалізований парадокс Беррі):**
Припустимо від супротивного, що існує алгоритм (програма `eval_K(x)`), який за скінченний час обчислює значення `K(x)` для будь-якого `x ∈ {0,1}*`.

Використовуючи `eval_K`, побудуємо нову програму `find_complex(n)`, яка бере на вхід натуральне число `n` і виконує такі кроки:

1. Перебирає всі бінарні рядки `x` у лексикографічному порядку: `ε, 0, 1, 00, 01, 10, 11, 000, ...`
2. Для кожного рядка `x` викликає `eval_K(x)`.
3. Щойно знайдено перший рядок `x₀`, для якого `eval_K(x₀) ≥ n`, програма `find_complex(n)` виводить `x₀` і зупиняється.

Оцінимо довжину коду самої програми `find_complex(n)`:
- Текст коду процедури перебору, виклику `eval_K` та порівняння має детерміновану сталу довжину `C_code`.
- Значення `n` подається як бінарне число, яке вимагає `⌈log₂ n⌉` біт для кодування.

Отже, повна довжина програми `find_complex(n)` дорівнює:

```
|p_n| = log₂ n + O(1)
```

За побудовою, ця програма `p_n` на універсальній машині `𝒰` виводить саме рядок `x₀`. Тому за означенням складності за Колмогоровим:

```
K(x₀) ≤ |p_n| = log₂ n + O(1)
```

Проте за умовою зупинки процедури `find_complex(n)` рядок `x₀` задовольняє умови:

```
K(x₀) ≥ n
```

Об'єднуючи дві нерівності, отримуємо для всіх `n ∈ ℕ`:

```
n ≤ K(x₀) ≤ log₂ n + C
```

Оскільки логарифмічна функція `log₂ n` зростає строго повільніше за лінійну функцію `n`, існує таке достатньо велике значення `n` (наприклад, для якого `n > log₂ n + C`), при якому ця нерівність стає суперечливою (`1000 ≤ log₂ 1000 + C`).

Отримана суперечність доводить, що припущення про існування алгоритму `eval_K` було хибним. Отже, функція `K(x)` є **алгоритмічно необчислюваною**.

## 4. Префіксна складність K(x) та нерівність Крафта–Чайтіна

У простій складності `C(x)` межа програми `p` визначається ззовні. Це створює аномалію: для складності парованого рядка `(x, y)` не справджується строга адитивність `C(x, y) ≤ C(x) + C(y) + O(1)`, оскільки потрібно додатково згадувати довжину `|x|` для розділення коду двох програм.

Щоб усунути цю ваду, Колмогоров, Левін та Чайтін змінили модель: вхідна програма `p` мусить бути **префіксним кодом** — машина Тюринга зчитує біти `p` зі стрічки один за одним і сама визначає момент завершення програми, не вимагаючи маркера кінця. Таку складність позначають `K(x)` (або `K_prefix(x)`).

**Нерівність Крафта–Чайтіна:** Нехай `(l₁, x₁), (l₂, x₂), ...` — обчислювана послідовність пар, де `l_i ∈ ℕ`, a `x_i ∈ {0,1}*`, така що:

```
∑_i 2⁻ˡⁱ ≤ 1
```

Тоді існує така префіксна універсальна машина Тюринга `𝒰`, що для кожного `i` існує програма `p_i` довжиною `|p_i| = l_i`, яка виводить `𝒰(p_i) = x_i`.

Наслідок: для префіксної складності строго виконуються властивості:

```
1) K(x) ≤ |x| + 2 log₂ |x| + O(1)
2) K(x, y) ≤ K(x) + K(y) + O(1)          [суб-адитивність]
```

## 5. Теорема про симетрію алгоритмічної інформації

У класичній теорії Шеннона взаємна інформація між двома випадковими величинами є строго симетричною: `I(X; Y) = I(Y; X) = H(X) + H(Y) - H(X, Y)`.

Левін і Колмогоров довели аналогічну теорему для індивідуальних об'єктів у префіксній складності.

**Означення (Алгоритмічна взаємна інформація):** Алгоритмічна взаємна інформація між двома рядками `x` та `y` визначається як:

```
I(x : y) = K(x) + K(y) - K(x, y)
```

**Теорема (Симетрія алгоритмічної інформації Барздіня–Колмогорова–Левіна):** З точністю до логарифмічного додатка `O(log K(x, y))` алгоритмічна взаємна інформація є симетричною, і справджується ланцюгове правило:

```
K(x, y) = K(x) + K(y | x, K(x)) + O(1)
```

Це означає, що інформація, яку `x` містить про `y`, з точністю до константи дорівнює інформації, яку `y` містить про `x`.

## 6. Константа Чайтіна Ω та її необчислюваність

Для префіксної універсальної машини `𝒰` означимо ймовірність зупинки (константу Чайтіна `Ω`):

```
Ω = ∑_{p: 𝒰(p)↓} 2⁻|p|
```

Оскільки множина програм `{p : 𝒰(p)↓}` утворює префіксний код, за нерівністю Крафта сума `Ω` строго збігається і задовольняє `0 < Ω < 1`.

**Властивості константи `Ω`:**

1. **Гранично-перелічувана (Lower semi-computable):** Існує алгоритмічна послідовність раціональних чисел `Ω₁, Ω₂, ...`, яка монотонно зростає і прямує до `Ω` при `n → ∞`.
2. **Алгоритмічно випадкова (Martin-Löf Random):** Рядок з перших `n` бітів двійкового розкладу `Ω` має префіксну складність:

```
K(Ω₁Ω₂...Ωₙ) ≥ n - O(1)
```

3. **Заражена нерозв'язністю:** Якщо відомі перші `n` бітів двійкового розкладу `Ω`, можна обчислити раціональне наближення `Ω_k ≥ Ω₁...Ωₙ`. Усі програми `p` довжиною `|p| ≤ n`, які не зупинилися до кроку `k`, вже ніколи не зупиняться. Це дозволяє за скінчений час розв'язати проблему зупинки для абсолютно всіх програм довжиною `≤ n`.

Таким чином, число `Ω` втілює в собі граничний обсяг математичного знання, який неможливо стиснути жодним коротшим алгоритмом.
