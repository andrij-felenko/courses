# ⚙️ Точний лічильник #SAT: розгалузитись і скласти

Ось робочий лічильник моделей — програма, що для булевої формули повертає **точне** число здійсненних наборів, і не тупим переглядом усіх 2ⁿ комбінацій, а пошуком, який відрубує цілі гілки, щойно відповідь у них визначена. Головний трюк уміщається в одне речення: там, де розв'язувач питав «**чи є** набір?» і зупинявся на першому знайденому, лічильник питає «**скільки** їх?» — розгалужується за значенням змінної й **додає** числа обох гілок. Нижче ми зберемо такий лічильник від найпростішого еталона до версії з поширенням одиничних диз'юнктів і кешуванням незалежних компонент, крок за кроком і з робочим кодом.

## Задача й чому наївний перебір не годиться

Формула в кон'юнктивній нормальній формі (КНФ) — це кон'юнкція клауз, де кожна клауза — диз'юнкція літералів (змінна xᵢ або її заперечення ¬xᵢ); набір значень усіх змінних, за якого вся формула істинна, зветься **моделлю** (здійсненним набором). Питання «чи є хоч одна модель?» розв'язує класичний пошук — [задача здійсненності (SAT)](root:computability/boolean-satisfiability). Наше питання інше: **порахувати** всі моделі. Це #SAT — рахункова сестра SAT.

Найпростіший спосіб очевидний: пройти всі 2ⁿ наборів і полічити ті, що задовольняють формулу. Для n = 20 це мільйон перевірок — мить; для n = 40 це вже трильйон, години; для n = 60 наборів більше, ніж секунд від Великого вибуху. [Асимптотика O(2ⁿ)](root:computability/asymptotic-complexity) робить прямий перебір непридатним рівно там, де задача стає цікавою. Нам потрібен спосіб **не заглядати** в більшість наборів — обрубувати їх пачками.

Почнімо, однак, саме з перебору: він короткий, очевидно правильний і стане нам за еталон, з яким ми звірятимемо розумніший лічильник. Домовимося про подання. Літерал — ціле число: додатне v означає «xᵥ істинна», від'ємне −v означає «¬xᵥ». Клауза — вектор літералів, формула — вектор клауз.

```cpp
#include <vector>
#include <string>
#include <unordered_map>
#include <algorithm>
#include <cstdint>
#include <cstdio>
using std::vector;

using Lit    = int;                  // v>0 → xᵥ істинна;  v<0 → ¬x|v|
using Clause = vector<Lit>;          // диз'юнкція літералів
using CNF    = vector<Clause>;       // кон'юнкція клауз
using Count  = unsigned long long;   // лічильник моделей (вміщає до 2⁶³)

inline int var(Lit L)       { return L > 0 ? L : -L; }               // номер змінної літерала
inline int bits(uint64_t m) { int k = 0; for (; m; m &= m - 1) ++k; return k; }  // популяція одиниць

// Еталон: прямий перебір усіх 2ⁿ наборів. Лише для звірки на малих n.
Count bruteForce(const CNF& F, int n) {
    Count models = 0;
    for (uint64_t a = 0; a < (1ULL << n); ++a) {       // a — набір: біт (v-1) = значення xᵥ
        bool ok = true;
        for (const Clause& c : F) {
            bool sat = false;
            for (Lit L : c)
                if (((a >> (var(L) - 1)) & 1) == (Count)(L > 0)) { sat = true; break; }
            if (!sat) { ok = false; break; }
        }
        models += ok;
    }
    return models;
}
```

Цей код — визначення #SAT, записане буквально: пробіжись по всіх наборах, для кожного перевір усі клаузи, полічи задоволені. Він правильний за побудовою, але живе тільки до n ≈ 25. Тепер — як не перебирати все.

## Ідея: розгалузитись за змінною й скласти гілки

Візьмімо будь-яку змінну xᵥ формули F. Кожна модель F або має xᵥ = 1, або xᵥ = 0 — третього немає, і ці два випадки не перетинаються. Тож

```
модель(F)  =  модель(F з xᵥ=1)  +  модель(F з xᵥ=0)
```

Це вже весь скелет. Підставивши xᵥ = 1, ми **спрощуємо** формулу: клаузи, де є літерал xᵥ, стають істинними й зникають; з решти клауз зникає хибний тепер літерал ¬xᵥ. Симетрично для xᵥ = 0. Далі те саме рекурсивно з іншою змінною — виростає **дерево розгалужень**, а число моделей збирається знизу вгору додаванням.

Дерево має дві межі, де рекурсія спиняється. Перша: якась клауза спорожніла — усі її літерали виявилися хибні, задовольнити її вже нічим. Ця гілка суперечлива, вона дає **0** моделей. Друга, тонша й важливіша: клауз **не лишилося** зовсім — усі задоволені. Тоді решта ще не зафіксованих змінних **вільні**: формулі байдуже до їхніх значень, тож кожна незалежно може бути 0 чи 1. Якщо вільних змінних *f*, ця гілка дає не одну модель, а **2ᶠ**. Проґавити цей множник — найпоширеніша помилка в лічильниках; до неї ще повернемось.

![Дерево лічильника #SAT: корінь — формула F з чотирьох змінних, перша розвилка за x₁ ділить її на дві гілки, кожна далі спрощується поширенням одиничних клауз або новою розвилкою; листки повертають 2^(вільні змінні) або 0 за суперечності, а числа збираються догори додаванням до 8](img/count-tree.svg)
*Не перебір 2⁴ = 16 наборів, а пошук. Корінь ділиться за x₁; ліва гілка (x₁=1) через одиничну клаузу форсує x₃ і лишає x₂, x₄ вільними — це 2² = 4 моделі; права (x₁=0) розгалужується ще раз за x₂, даючи 4 + 0. Догори числа гілок **складаються**: 4 + 4 = 8. Суперечлива гілка приносить 0, задоволена — 2^(вільні).*

Щоб спрощення не писати двічі, винесемо його в окрему функцію: присвоїти літералові значення «істина» й повернути нову, зменшену формулу, а спорожнілу клаузу відзначити як конфлікт.

```cpp
// Присвоїти літералові L значення «істина» й спростити формулу:
//   клаузу з L викидаємо (задоволена); з решти прибираємо ¬L (хибний літерал).
// Порожня клауза → конфлікт (через out-параметр).
CNF assign(const CNF& F, Lit L, bool& conflict) {
    CNF out;
    out.reserve(F.size());
    for (const Clause& c : F) {
        bool satisfied = false;
        Clause reduced;
        for (Lit m : c) {
            if (m ==  L) { satisfied = true; break; }   // істинний літерал → клауза знята
            if (m == -L) continue;                       // хибний літерал → викинути
            reduced.push_back(m);
        }
        if (satisfied) continue;
        if (reduced.empty()) { conflict = true; return out; }   // порожня клауза → суперечність
        out.push_back(std::move(reduced));
    }
    return out;
}
```

## Одиничні диз'юнкти: форсовані ходи

Перш ніж навмання розгалужуватись, варто вичерпати **вимушені** висновки. Якщо в формулі є клауза з одного літерала — **одиничний диз'юнкт** (наприклад просто `(x₃)`), — то щоб її задовольнити, x₃ **мусить** бути 1. Тут нема чого перебирати: одне зі значень одразу вбиває всю формулу, тож вибору немає. Присвоюємо форсоване значення, спрощуємо — і часто спрощення народжує нову одиничну клаузу, яка форсує наступну змінну, і так каскадом. Це **поширення одиничних диз'юнктів** (unit propagation): дешевий крок, що зрізає цілі піддерева, які інакше довелося б обходити розгалуженням (одна з двох гілок була б негайним конфліктом).

Тепер зберемо лічильник. Він приймає формулу, повне число змінних n і лічильник уже зафіксованих змінних `assigned`; повертає число моделей.

```cpp
// Точний лічильник: розгалуження за змінною + додавання гілок, з поширенням
// одиничних диз'юнктів. assigned — скільки змінних уже зафіксовано.
Count countDPLL(CNF F, int n, int assigned) {
    for (bool changed = true; changed; ) {             // 1. поширення одиничних диз'юнктів
        changed = false;
        for (const Clause& c : F)
            if (c.size() == 1) {                       // клауза з одного літерала форсує його
                bool conflict = false;
                F = assign(F, c[0], conflict);
                ++assigned;                            // ця змінна тепер зафіксована
                if (conflict) return 0;                // суперечність → 0 моделей у цій гілці
                changed = true;
                break;                                 // F змінилась — переглянути заново
            }
    }
    if (F.empty())                                     // 2. база: клауз нема — решта змінних вільні
        return (Count)1 << (n - assigned);             //    2^(вільні),   n - assigned < 64

    int v = var(F[0][0]);                              // 3. розвилка за першою-ліпшою змінною
    bool cf1 = false, cf0 = false;
    CNF F1 = assign(F,  v, cf1);                        //    xᵥ = 1
    CNF F0 = assign(F, -v, cf0);                        //    xᵥ = 0
    Count s1 = cf1 ? 0 : countDPLL(std::move(F1), n, assigned + 1);
    Count s0 = cf0 ? 0 : countDPLL(std::move(F0), n, assigned + 1);
    return s1 + s0;                                     //    СКЛАДАЄМО обидві гілки
}
```

Три частини читаються прямо як задум: спершу вичерпуємо форсовані ходи, потім перевіряємо межі (клауз немає → вільні змінні дають 2^(вільні); суперечність спіймана раніше поверненням 0), і лише тоді розгалужуємось, додаючи результати обох половин. Це і є перетворення «розв'язати» на «розгалузитись і скласти»: той самий кістяк, що в SAT-розв'язувачі, тільки замість «знайшли модель — стоп» ми **сумуємо** внески всіх гілок.

> 🔧 **Навіщо це.** Уся правильність числа тримається на рядку `(Count)1 << (n - assigned)`. Вільні змінні — це не «нуль моделей» і не «одна модель», а **2 у степені їхньої кількості**: кожна незалежно подвоює відповідь. Забути цей множник — недолічити рівно у 2^(вільні) разів; а порахувати вільною змінну, яку насправді вже зафіксувало поширення (не збільшивши `assigned`), — навпаки, **подвоїти** її внесок і завищити результат. Обидва промахи мовчазні: код працює, тести на крихітних формулах без вільних змінних проходять, а число неправильне. Тому будь-який лічильник моделей передусім перевіряють не на швидкість, а на точність обліку — звіркою з прямим перебором на малих входах, як нижче.

Зберемо все й проженемо на формулі з малюнка — тій самій, яку ми розібрали в дереві:

```cpp
int main() {
    // F = (x1 ∨ x2 ∨ ¬x3) · (¬x1 ∨ x3) · (x2 ∨ x3),   x4 — вільна.   n = 4.
    CNF F = { {1, 2, -3}, {-1, 3}, {2, 3} };
    int n = 4;
    std::printf("перебір : %llu\n", bruteForce(F, n));    // 8
    std::printf("DPLL    : %llu\n", countDPLL(F, n, 0));  // 8
}
```

Перебір обходить усі 16 наборів і знаходить 8 моделей (4 здійсненні набори над x₁, x₂, x₃, кожен подвоєний вільною x₄). Лічильник дістає ту саму вісімку, заглянувши лише в кілька вузлів дерева: гілка x₁ = 1 через одиничну клаузу (x₃) згорнулась одразу в 2² = 4, права гілка дала 4 + 0. Числа збіглися — облік правильний.

## Незалежні компоненти й кеш: множити й не рахувати двічі

Розгалуження з поширенням уже набагато краще за перебір, але на великих формулах дерево все одно розростається. Два прийоми зрізають його ще різкіше, і обидва — про **структуру** формули.

Перший. Уявіть, що після кількох присвоєнь формула розпалась на групи клауз, які **не ділять жодної спільної змінної**. Тоді вибір у одній групі ніяк не впливає на іншу — вони незалежні. Число моделей усієї формули — не сума, а **добуток** чисел моделей кожної групи: будь-яку модель однієї частини можна з'єднати з будь-якою моделлю іншої. Ці групи — **зв'язні компоненти** графа, де змінні сусідні, коли трапились в одній клаузі; знайти їх — робота [об'єднання-пошуку (union-find)](root:sf-algorithms/union-find). Замість одного дерева на всі змінні ми рахуємо кілька маленьких дерев і множимо їхні відповіді — а це різниця між 2^(a+b) і 2ᵃ + 2ᵇ.

![Незалежні компоненти множаться, а не додаються: формула G розпадається на компоненту з x₁, x₂ (рівно одна змінна істинна → 2 моделі) і компоненту з x₃, x₄ (диз'юнкція → 3 моделі); жодної спільної змінної, тож усього 2 × 3 = 6, а однакову підформулу беруть із кешу без нового дерева](img/components-cache.svg)
*Дві незалежні компоненти. Клаузи над {x₁, x₂} і над {x₃, x₄} не ділять змінних, тож їхні числа моделей **множаться**: 2 × 3 = 6. Той самий трюк вкладено рекурсивно, а щойно та сама підформула трапляється в іншій гілці — її число беруть із кешу, не будуючи піддерево вдруге.*

Другий прийом — **кешування**. Під час пошуку одна й та сама підформула виринає в різних гілках дерева знову й знову. Порахувати її число моделей раз, покласти в таблицю за канонічним ключем і далі просто **діставати** готове — це звичайна [мемоізація](root:sf-algorithms/memoization), яка перетворює дерево повторних обчислень на граф без повторів. Саме кешування компонент відрізняє навчальний лічильник від промислового.

Щоб усе це поєдналось із вільними змінними без плутанини, змінимо погляд на облік. Зробимо ядро `core(F)`, яке рахує моделі **рівно над тими змінними, що з'являються у F** — не більше й не менше. Тоді добуток компонент коректний: кожна компонента знає лише свої змінні, а вільні (ті, кого немає в жодній клаузі) множаться окремим 2^(вільні) на самому верху. І головне: значення `core(F)` залежить **тільки** від F — тож його можна безпечно класти в кеш за ключем самої формули.

```cpp
uint64_t varsMask(const CNF& F) {                  // маска змінних, що з'являються у F
    uint64_t m = 0;
    for (const Clause& c : F) for (Lit L : c) m |= 1ULL << (var(L) - 1);
    return m;
}

struct DSU {                                       // об'єднання-пошук: змінні однієї компоненти
    vector<int> p;
    DSU(int n) : p(n) { for (int i = 0; i < n; ++i) p[i] = i; }
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }
    void unite(int a, int b) { p[find(a)] = find(b); }
};

// Розкласти формулу на незалежні компоненти (клаузи без спільних змінних).
vector<CNF> decompose(const CNF& F, int n) {
    DSU dsu(n);
    for (const Clause& c : F)
        for (size_t i = 1; i < c.size(); ++i)
            dsu.unite(var(c[0]) - 1, var(c[i]) - 1);   // усі змінні клаузи — в один клас
    std::unordered_map<int, CNF> groups;
    for (const Clause& c : F)
        groups[dsu.find(var(c[0]) - 1)].push_back(c);  // клауза йде до кореня свого класу
    vector<CNF> out;
    for (auto& kv : groups) out.push_back(std::move(kv.second));
    return out;
}

// Канонічний ключ компоненти: відсортовані літерали в клаузах, відсортовані клаузи.
std::string key(CNF F) {
    for (Clause& c : F) std::sort(c.begin(), c.end());
    std::sort(F.begin(), F.end());
    std::string s;
    for (const Clause& c : F) { for (Lit L : c) { s += std::to_string(L); s += ','; } s += ';'; }
    return s;
}

// core(F): число моделей НАД РІВНО тими змінними, що з'являються у F.
// Залежить лише від F → безпечно кешується за key(F).
Count core(const CNF& F, int n, std::unordered_map<std::string, Count>& cache) {
    if (F.empty()) return 1;                        // жодної змінної → одна порожня модель
    std::string k = key(F);
    auto it = cache.find(k);
    if (it != cache.end()) return it->second;       // готове число — без нового піддерева

    uint64_t Vin = varsMask(F);
    vector<CNF> comps = decompose(F, n);
    Count result;
    if (comps.size() > 1) {                         // незалежні компоненти → числа МНОЖАТЬСЯ
        result = 1;
        for (const CNF& Fi : comps) result *= core(Fi, n, cache);
    } else {                                        // одна компонента → розгалуження + додавання
        int v = var(F[0][0]);
        bool cf1 = false, cf0 = false;
        CNF F1 = assign(F,  v, cf1);
        CNF F0 = assign(F, -v, cf0);
        uint64_t drop1 = Vin & ~varsMask(F1) & ~(1ULL << (v - 1));  // змінні, що випали в гілці
        uint64_t drop0 = Vin & ~varsMask(F0) & ~(1ULL << (v - 1));
        Count s1 = cf1 ? 0 : core(F1, n, cache) << bits(drop1);     // × 2^(вільні в гілці)
        Count s0 = cf0 ? 0 : core(F0, n, cache) << bits(drop0);
        result = s1 + s0;
    }
    cache[k] = result;
    return result;
}

// Повний лічильник: core над змінними-учасницями × 2^(змінні поза всіма клаузами).
Count countModels(const CNF& F, int n) {
    std::unordered_map<std::string, Count> cache;
    int freeTop = n - bits(varsMask(F));            // змінні, яких нема в жодній клаузі
    return core(F, n, cache) << freeTop;            // × 2^(вільні верхнього рівня)
}
```

Тут проступає та сама відмінність, що й у теорії: незалежні компоненти **множаться** (добуток `result *= core(Fi, …)`), а гілки однієї змінної **додаються** (`s1 + s0`). Множник `2^(вільні)` тепер з'являється лише там, де змінна справді випадає з розгляду: у гілці, де присвоєння звільнило змінну (`drop1`, `drop0`), і на верху, де є змінні поза всіма клаузами (`freeTop`). Додавши третій рядок `countModels(F, n)` у `main`, дістанемо ту саму **8** — і на формулі з двох незалежних компонент `(x₁∨x₂)·(¬x₁∨¬x₂)·(x₃∨x₄)` кеш-лічильник поверне 2 × 3 = 6, розібравши її на дві половинки замість одного дерева на чотири змінні.

Ідея не нова. Розширити класичний пошук [DPLL](root:computability/boolean-satisfiability) (Девіс, Патнем, Логеман, Лавленд, 1962) лічбою першими докладно описали Бірнбаум і Лозінскі (Elazar Birnbaum, Eliezer Lozinskii, «The Good Old Davis-Putnam Procedure Helps Counting Models», 1999) — їхній алгоритм CDP і є цей `countDPLL`. Розклад на зв'язні компоненти для підрахунку додали Баярдо й Пегушек (Roberto Bayardo, Joseph Pehoushek, «Counting Models Using Connected Components», 2000), а кешування компонент довів до промислового рівня sharpSAT Марка Терлі (Marc Thurley, 2006) — донині один з основних точних лічильників.

## Складність: чому гірший випадок неминуче експоненційний

Скільки коштує цей пошук? У гіршому разі — стільки ж, скільки перебір: дерево розгалужень може мати до 2ⁿ листків, і жодне поширення чи кешування не рятує. Інакше й бути не може, і це не вада реалізації, а закон. #SAT — #P-повна задача; умій ми рахувати її швидко (за поліном), ми б задарма й **розв'язували** SAT (число моделей більше нуля ⟺ формула здійсненна), а звідси випливало б P = #P — рівність, у яку не вірить ніхто. Тож поліномного лічильника моделей на всіх формулах бути не може, поки стоять ці припущення; експонента в гіршому разі — ціна, а не недоробка.

Але «гірший випадок» і «типовий випадок» — різні речі, і саме тут прийоми окупаються. Поширення одиничних диз'юнктів вирізає гілки, приречені на конфлікт. Розклад на компоненти міняє 2^(a+b) на 2ᵃ + 2ᵇ щоразу, коли формула розпадається. Кеш прибирає повторний рахунок однакових підформул. На **структурованих** формулах — таких, що майже розсипаються на слабко пов'язані шматки, — дерево обрізається так, що час стає практичним, а на формулах обмеженої «ширини» розкладу кешування компонент дає навіть поліном. Уся інженерія точних лічильників — це боротьба за те, щоб реальна формула трималась якнайдалі від свого експоненційного гіршого випадку.

## Пастки

**Облік вільних змінних.** Це головна й найтихіша помилка, тож повторимо. Модель — це присвоєння **всім** n змінним; змінна, якої формула не згадує (уся спрощена або з самого початку відсутня), вільна, і кожна така **подвоює** число моделей. Лист дерева повертає не 1, а 2^(вільні). Дзеркальний промах — порахувати вільною змінну, яку вже зафіксувало поширення: тоді її внесок подвоюється двічі. У `countDPLL` за це відповідає точність `assigned`, у `core` — маски `drop`; збийте будь-яку — і число тихо поїде в рази.

**Переповнення лічильника.** Моделей буває до 2ⁿ. `unsigned long long` тримає до 2⁶⁴ − 1, тож надійний він лише десь до n ≈ 63; далі лічильник **мовчки** переповнюється й обертається по колу, видаючи правдоподібне, але хибне мале число. Для великих формул беруть `__int128` або довгу арифметику (велике ціле). Окрема тонкість того ж роду — `1ULL << k`: зсув на k ≥ 64 у C++ **не визначений**, тож множник 2^(вільні) на великому n треба рахувати обережно, а не зсувом. Ця родина тихих помилок — саме [переповнення й обгортання](root:sf-lang/overflow-wraparound).

**Ключ кешу.** `core` кешує компоненту за її клаузами, тож ключ мусить бути **канонічним** — з відсортованими літералами й клаузами, інакше та сама підформула в іншому порядку не впізнається й даремно порахується знову. Тонший недобір: дві компоненти, однакові з точністю до **перейменування** змінних (та сама структура над іншими номерами), мають однакове число моделей, але різні ключі — щоб ловити й такі збіги, промислові лічильники нормалізують ще й імена змінних. Наш ключ цього не робить — свідомий компроміс на користь простоти.

**Вибір змінної для розвилки.** `var(F[0][0])` — найпростіший вибір, і на правильність він не впливає ніяк. А от на швидкість — величезно: вдало обрана змінна розсікає формулу на незалежні компоненти на кілька кроків раніше. Евристики вибору — окрема велика тема самих лічильників, і саме вони найчастіше вирішують, за секунди задача полічиться чи за добу.
