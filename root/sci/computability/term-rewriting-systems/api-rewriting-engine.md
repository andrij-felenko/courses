# 📋 Специфікація інтерфейсу рушія переписування термів

У цій специфікації зафіксовано архітектурний контракт, структури даних, сигнатури функцій для C та C++, коди помилок, інваріанти пам'яті та підсистеми індексації для продуктивної бібліотеки синтаксичного переписування термів першого порядку та автоматичного поповнення систем рівнянь за алгоритмом Кнута-Бендікса.

## 1. Архітектурний контракт та інваріанти системи

Бібліотека надає модульний інтерфейс для конструювання синтаксичних дерев, синтаксичної уніфікації, обчислення критичних пар, покрокової редукції виразів та автоматичного виведення канонічних систем правил.

### 1.1. Інваріанти життєвого циклу об'єктів
1. **Незмінність вузлів (Immutability):** Після створення об'єкт `Term` є абсолютно незмінним (константним). Будь-яка модифікація (заміна підтерма, застосування підстановки) породжує новий терм або перевикористовує існуючі піддерева без мутації оригінального виразу. Це гарантує цілісність даних у багатопотокових середовищах без необхідності блокування м'ютексів.
2. **Ідемпотентність нормалізації:** Якщо терм `t` нормалізовано до нормальної форми `t↓`, повторний виклик функції спрощення над `t↓` гарантовано повертає той самий об'єкт за час `O(1)` або `O(|t|)` без виділення нової динамічної пам'яті.
3. **Ізоляція пам'яті підстановок:** Підстановка `Substitution` є асоціативним контейнером, що зберігає зв'язування імен змінних із вказівниками на незмінні терми. Знищення або модифікація контейнера підстановки не впливає на життєвий цикл збережених термів.
4. **Потокобезпечність (Thread Safety):** Операції читання, уніфікації, зіставлення та редукції над незмінними термами є повністю реентрантними та потокобезпечними (`const-thread-safe`). Модифікація списку правил або конфігурації вимагає зовнішньої синхронізації.

## 3. Специфікація функцій ядра API (C++ Interface)

Нижче наведено формальний контракт основних функцій підсистеми AST, уніфікації, редукції та поповнення.

### 3.1. Створення та інспекція термів

#### `TermPtr make_variable(std::string_view name)`
- **Призначення:** Створює новий незмінний вузол синтаксичної змінної.
- **Параметри:** `name` — непорожній рядок, що ідентифікує змінну.
- **Повертає:** Вказівник на незмінний об'єкт `Term`.
- **Передмови:** `name.length() > 0`.
- **Постумови:** `result->kind == NodeKind::Variable`, `result->args.empty() == true`, `result->size == 1`, `result->depth == 1`.
- **Часова складність:** `O(1)`.

#### `TermPtr make_function(std::string_view name, std::vector<TermPtr> args)`
- **Призначення:** Створює складений функціональний терм або константу (при порожньому векторі `args`).
- **Параметри:** `name` — ім'я функціонального символу; `args` — вектор валідних вказівників на аргументи.
- **Повертає:** Вказівник на незмінний об'єкт `Term`.
- **Передмови:** Жоден елемент `args[i]` не є `nullptr`.
- **Постумови:** `result->kind == NodeKind::Function`, `result->size == 1 + sum(args[i]->size)`.
- **Часова складність:** `O(k)`, де `k = args.size()`.

#### `bool contains_variable(TermPtr term, std::string_view var_name)`
- **Призначення:** Перевіряє синтаксичне входження змінної `var_name` у вираз `term` (occurs check).
- **Часова складність:** `O(|term|)` у найгіршому випадку.

#### `TermPtr replace_subterm(TermPtr root, const std::vector<size_t>& position, TermPtr replacement)`
- **Призначення:** Замінює підтерм у позиції `position` на вираз `replacement`, повертаючи новий корінь дерева.
- **Передмови:** Позиція `position` існує у дереві `root`.
- **Часова складність:** `O(depth(root))`.

---

### 3.2. Зіставлення та уніфікація

#### `bool match_pattern(TermPtr pattern, TermPtr target, Substitution& subst)`
- **Призначення:** Одностороннє зіставлення за зразком: знаходить таку підстановку `subst`, що `pattern[subst] ≡ target`.
- **Параметри:**
  - `pattern` — терм-зразок (може містити вільні змінні).
  - `target` — цільовий терм (змінні розглядаються як жорсткі константи).
  - `subst` — вихідна підстановка, що поповнюється новими зв'язуваннями.
- **Повертає:** `true`, якщо зіставлення успішне; `false`, якщо структури несумісні.
- **Часова складність:** `O(|pattern|)`.

#### `std::optional<Substitution> unify(TermPtr s, TermPtr t)`
- **Призначення:** Двостороння уніфікація першого порядку за алгоритмом Робінсона з обов'язковою перевіркою циклічних входжень (Occurs Check).
- **Параметри:** `s`, `t` — довільні терми, що можуть одночасно містити змінні.
- **Повертає:** Найзагальніший уніфікатор `std::optional<Substitution>`, або `std::nullopt`, якщо уніфікація неможлива (структурний конфлікт або циклічне посилання).
- **Часова складність:** `O(|s| · |t|)` для стандартного алгоритму; `O(|s| + |t|)` при використанні структур Union-Find на графах еквівалентності.

---

### 3.3. Редукція та нормалізація

#### `TermPtr rewrite_step(TermPtr term, const std::vector<RewriteRule>& rules, ReductionStrategy strategy)`
- **Призначення:** Виконує рівно один крок паралельної або послідовної редукції виразу `term` за множиною правил `rules` відповідно до обраної стратегії.
- **Повертає:** Новий редукований терм або вихідний терм, якщо жодне правило не є застосовним.
- **Часова складність:** `O(|rules| · |term|)`.

#### `TermPtr normalize(TermPtr term, const std::vector<RewriteRule>& rules, ReductionStrategy strategy, size_t max_steps)`
- **Призначення:** Обчислює нормальну форму виразу `term` шляхом ітеративного застосування `rewrite_step` до досягнення нередуковного стану або вичерпання ліміту кроків `max_steps`.
- **Повертає:** Нередуковний терм `term↓_rules`.
- **Винятки/Помилки:** Якщо ліміт `max_steps` вичерпано, повертає поточний проміжний вираз та фіксує код попередження.

---

### 3.4. Порядки редукції та поповнення

#### `bool lpo_compare(TermPtr s, TermPtr t, const std::unordered_map<std::string, Symbol>& signature)`
- **Призначення:** Перевіряє, чи виконується строга нерівність `s >_lpo t` за лексикографічним деревним порядком відносно пріоритетів символів у сигнатурі.
- **Повертає:** `true`, якщо `s` строго перевершує `t` за LPO; `false` в іншому випадку.
- **Інваріант:** Якщо `lpo_compare(s, t) == true`, то `lpo_compare(t, s) == false` (асиметричність) та `s != t` (іррефлексивність).

#### `CompletionResult knuth_bendix_complete(std::vector<std::pair<TermPtr, TermPtr>> equations, const std::unordered_map<std::string, Symbol>& signature, const CompletionConfig& config)`
- **Призначення:** Виконує повний цикл алгоритму Кнута-Бендікса над множиною симетричних рівнянь, автоматично орієнтуючи їх за порядком LPO та поповнюючи систему критичними парами до досягнення канонічного стану.
- **Конфігурація `CompletionConfig`:**
  - `max_iterations`: максимальна кількість доданих правил (дефолт: 1000).
  - `max_critical_pairs`: ліміт черги критичних пар (дефолт: 10000).
  - `enable_inter_reduction`: прапорець увімкнення взаємного спрощення правил (дефолт: `true`).
- **Повертає структуру `CompletionResult`:**
  - `status`: статус завершення (`Success`, `UnorientableEquation` тощо).
  - `rules`: фінальний вектор канонічних правил `RewriteRule`.
  - `unresolved_equations`: список рівнянь, які не вдалося орієнтувати.

## 5. Підсистема терм-індексації: Дискримінаційні дерева

Для роботи з великими базами правил (від 1000 до 1 000 000 правил) лінійне сканування замінюється на пошук через дискримінаційне дерево (Discrimination Tree).

### 5.1. Принцип дії та інтерфейс індексатора
Дискримінаційне дерево є префіксним деревом (Trie), що індексує лінеаризовані терми у префіксному записі:
- Змінні кодуються узагальненим символом `*` (Wildcard).
- Кожен шлях від кореня до листка відповідає лівій частині певного правила.
- Запит зіставлення `dtree_find_matches(tree, target_term)` повертає всі застосовні правила за час `O(depth(target_term))` без перегляду всієї бази знань.

## 6. Парсери та серіалізатори виразів

Бібліотека містить модуль трансляції між рядковими представленнями та внутрішнім AST:
1. **S-вирази (S-Expressions):** Префіксний запис у стилі Lisp/Scheme `(* (i x) x)`. Використовується для надійного збереження та міжмовного обміну.
2. **Інфіксний парсер з таблицею пріоритетів:** Дозволяє розбирати стандартні математичні вирази на кшталт `(x * y) * z = x * (y * z)` з урахуванням асоціативності та пріоритету бінарних операцій.
3. **Генератор візуалізації Graphviz Dot:** Функція `export_to_dot(TermPtr term)` генерує вихідний код у форматі `.dot` для графічного відображення дерева розбору.

## 7. Детальний покроковий сценарій використання бібліотеки

Типовий робочий процес взаємодії клієнтського коду з бібліотекою складається з п'яти послідовних фаз:

### 7.1. Фаза 1: Ініціалізація сигнатури та пріоритетів
Клієнтський модуль створює дескриптори функціональних символів і призначає їм строгі пріоритети для забезпечення коректної орієнтації правил у порядку LPO:

### 7.3. Фаза 3: Виклик процедури поповнення Кнута-Бендікса
Клієнт передає аксіоми до рушія поповнення, отримуючи повністю канонізовану систему правил:


### 7.4. Фаза 4: Нормалізація виразів та автоматичне доведення теорем
Для перевірки довільної рівності `lhs = rhs` клієнт нормалізує обидві частини отриманою канонічною системою правил:
```cpp
// Перевірка теореми: (x * y) * (i(y) * i(x)) = e
auto query_lhs = mul(mul(x, y), mul(inv(y), inv(x)));
auto norm_lhs = trs::normalize(query_lhs, res.rules, trs::ReductionStrategy::Innermost, 1000);
auto norm_rhs = trs::normalize(e, res.rules, trs::ReductionStrategy::Innermost, 1000);

if (norm_lhs == norm_rhs) {
    std::cout << "Теорему доведено автоматично: " << norm_lhs->name << "\n";
}
```

## 8. Підсистема діагностики та зворотних викликів (Callbacks)

Для детального аналізу та профілювання процесу поповнення бібліотека підтримує механізм зворотних викликів:
- **`OnRuleAddedHook`:** Викликається щоразу, коли нова орієнтована рівність додається до списку правил `R`. Дозволяє візуалізувати динаміку зростання бази знань у реальному часі.
- **`OnCriticalPairGeneratedHook`:** Повідомляє про кожне знайдене накладання лівих частин та фіксує нормалізовані результати обох гілок розгалуження.
- **`OnInterReductionStepHook`:** Фіксує факти видалення надлишкових старих правил у результаті лівої редукції або модифікацію правих частин за правою редукцією.

Ці інтерфейси дозволяють легко інтегрувати рушій у графічні налагоджувачі компіляторів та інтерактивні середовища автоматичного доведення теорем.

## 10. Керування чергою критичних пар та справедливість вибору

Процедура поповнення Кнута-Бендікса критично залежить від порядку вибору пар із робочої черги `eq_queue`:
1. **Черга за розміром термів (Size-Ordered Priority Queue):** Пари впорядковуються за сумарною кількістю символів `size(s) + size(t)`. Це забезпечує стратегію найкоротших доведень і перешкоджає роздуванню проміжних виразів.
2. **Справедливість (Fairness Invariant):** Алгоритм гарантує, що жодна критична пара не залишається в черзі нескінченно довго. Якщо стратегія черги не є строго FIFO, бібліотека застосовує лічильник старіння (aging counter), підвищуючи пріоритет старих пар після кожних 100 ітерацій.
3. **Фільтрація дублікатів та тривіальних пар:** Пари вигляду `⟨t, t⟩` негайно відкидаються на етапі додавання в чергу, скорочуючи кількість зайвих редукцій на 40–80%.

## 12. Безпека винятків та модель обробки помилок

Бібліотека реалізує сувору гарантію безпеки винятків (Strong Exception Guarantee):
- Якщо під час конструювання терма, уніфікації або поповнення стається збій пам'яті (`std::bad_alloc`), стан системи не пошкоджується, а всі частково створені структури автоматично очищуються через деструктори розумних покажчиків.
- Функції C-API ніколи не генерують апаратних винятків або паніки: будь-яка критична помилка конвертується у відповідний числовий код результату із збереженням валідності арени пам'яті.

## 13. Сумісність із форматами SMT-LIB2 та TPTP

Бібліотека підтримує пряму трансляцію та завантаження задач із міжнародних стандартів автоматичного доведення теорем:
- **Стандарт TPTP (Thousands of Problems for Theorem Provers):** Підтримується розбір файлів формул у форматі `cnf(...)` та `fof(...)` з виділенням унітарних рівностей для процедури поповнення.
- **Формат SMT-LIB версії 2.6:** Підтримується імпорт та експорт команд `(assert (= s t))` у логіці `QF_UF` (теорія неінтерпретованих функцій з рівністю).

## 14. Таблиця хеш-консингу та автоматичне прибирання сміття

Для екстремально високих навантажень бібліотека надає підсистему інтернування термів `HashConsingTable`:
- Кожен унікальний підтерм отримує унікальний глобальний числовий ідентифікатор `TermId`.
- Повторні створення синтаксично тотожних виразів повертають наявний екземпляр із таблиці з лічильником посилань, зводячи перевірку рівності до порівняння цілих чисел `id1 == id2`.
- Підсистема збору сміття (`gc_sweep`) автоматично видаляє з таблиці вузли, на які більше немає зовнішніх активних посилань від правил або клієнтського коду.

## 15. Інтеграція з іншими мовами через FFI (Rust, Python)

Чистий двійковий інтерфейс (ABI) мови C дозволяє створювати нативні обгортки для інших екосистем без накладних витрат маршалінгу:
- **Rust:** Бібліотека експортує крейт `trs-sys` з безпечними RAII-типами `Term` та `CompletionEngine`, що реалізують типажні інтерфейси `Send` та `Sync`.
- **Python (ctypes / cffi):** Модуль `pytrs` надає перевантажені магічні методи `__add__`, `__mul__`, `__eq__` над символьними виразами, транслюючи виклики безпосередньо у скомпільовану бібліотеку `libtrs.so` / `trs.dll`.

## 16. Багатопотокова архітектура та паралельне поповнення

У багатопотокових обчислювальних середовищах алгоритм Кнута-Бендікса масштабується за допомогою паралельного дослідження критичних пар:
- Робочі потоки (Worker Threads) вибирають незалежні пари `⟨s, t⟩` зі спільної конкурентної черги `LockFreeQueue` за принципом крадіжки задач (Work Stealing), що вирівнює обчислювальне навантаження на багатоядерних процесорах.
- Нормалізація обох гілок розгалуження виконується паралельно без будь-яких блокувань пам'яті, оскільки самі терми та множина активних правил є повністю незмінними константними структурами даних.
- Додавання нових орієнтованих правил до глобального списку та запуск взаємного спрощення координується єдиним потоком-координатором через механізм епох (Epoch-Based Synchronization) та атомарну заміну покажчиків кореня бази знань.

Усі функції високого рівня, що виконують синтаксичний аналіз, поповнення та трансформацію, повертають уніфіковані коди результатів з детальним описом контексту.

## 18. Гарантії продуктивності та вимоги до середовища

1. **Споживання пам'яті:**
   - Кожен вузол `Term` займає фіксований базовий розмір `sizeof(Term) = 48` байтів + пам'ять під динамічний масив аргументів `std::vector<TermPtr>`.
   - Завдяки спільним вказівникам `std::shared_ptr` глибина дублювання піддерев усувається, забезпечуючи лінійне зростання пам'яті `O(N)` від сумарного розміру унікальних підтермів.
2. **Швидкодія операцій:**
   - Перевірка рівності за покажчиками: `O(1)`.
   - Повне структурне порівняння двох термів: `O(min(|s|, |t|))`.
   - Зіставлення одного правила: `O(|lhs|)`.
   - Пошук критичної пари: `O(|lhs₁| · |lhs₂|)`.
   - Запит до дискримінаційного дерева: `O(depth(target))`.
3. **Сумісність компіляторів:**
   - C++: Стандарт C++17 або новіший (GCC >= 8.0, Clang >= 7.0, MSVC >= 2019).
   - C: Стандарт C99 або новіший із підтримкою стандартної бібліотеки POSIX/C runtime.

Ця специфікація забезпечує повний контракт для створення надійних та швидких підсистем комп'ютерної алгебри, оптимізаторів компіляторів та автоматичних довідників теорем.
