# ⚙️ Обхід межі Ω(N log N): практична реалізація Counting Sort та Radix Sort

Теорема про нижню межу сортування `Ω(n log n)` є непохитною для алгоритмів, що порівнюють елементи за допомогою компаратора `a < b`. Проте в системній розробці виникає потреба сортувати мільярди цілочисельних ключів, IP-адрес чи хешів із максимально можливою швидкістю.

У цій вставці ми розберемо реалізацію алгоритмів **Сортування підрахунком (Counting Sort)** та **Порозрядного сортування (Radix Sort)**, які обходять межу `Ω(n log n)` і досягають **лінійного часу `O(n)`**.

---

## Чому це працює: індексування замість порівняння

Нижня межа `Ω(n log n)` згасає, коли ми відмовляємося від абстрактного компаратора й беремо до уваги **внутрішнє представлення даних**.

Замість того, щоб ставити елементам запитання «Хто з вас більший?», лінійні алгоритми розглядають кожен елемент як індекс масиву чи послідовність розрядів (байтів або бітів).

### 1. Сортування підрахунком (Counting Sort)
Нехай масив складається з N цілих чисел у діапазоні від `0` до `K - 1`.
Ідея алгоритму:
1. Створити масив частот `counts` розміром K, заповнений нулями.
2. Пройти по вхідному масиву й для кожного елемента `val` зробити `counts[val]++`.
3. Обчислити префіксні суми в масиві `counts`, щоб дізнатися точну фінальну позицію кожного елемента.
4. Скопіювати елементи у вихідний масив у зворотному порядку для збереження **стабільності** (збереження порядку однакових елементів).

**Складність:** Час `O(N + K)`, Пам'ять `O(N + K)`.
**Обмеження:** Якщо `K = O(N)` (наприклад, числа від 0 до 1 000 000), алгоритм працює за строго лінійний час `O(N)`. Але якщо `K = 2⁶⁴` (64-бітні числа), створити масив `counts` розміром 2⁶⁴ неможливо.

---

### 2. Порозрядне сортування (Radix Sort)
Щоб сортувати великі числа (наприклад, 32-бітні цілі числа) без витрат терабайтів пам'яті під `counts`, використовують LSD (Least Significant Digit) Radix Sort.

Ідея:
1. Розбити кожне 32-бітне число на `d = 4` розряди по 8 бітів (байтів). Кожен байт набуває значень від `0` до `K = 255`.
2. Виконати `d` послідовних проходів стабільного Counting Sort, починаючи з наймолодшого байта (молодші 8 бітів) до найстаршого (старші 8 бітів).
3. Після d-го проходу масив буде повністю впорядкований!

**Складність:** Час `O(d · (N + K))`. Для 32-бітних чисел при `d = 4` та `K = 256` маємо `4 · (N + 256) = O(N)`!

---

## Реалізація Counting Sort та Radix Sort

Нижче наведено робочу та ідіоматичну реалізацію обох алгоритмів мовами C++ та Python.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <cstdint>
#include <chrono>

// 1. Сортування підрахунком для невід'ємних цілих чисел
void counting_sort(std::vector<int>& arr) {
    if (arr.empty()) return;

    int max_val = *std::max_element(arr.begin(), arr.end());
    std::vector<int> count(max_val + 1, 0);
    std::vector<int> output(arr.size());

    // Підрахунок частот
    for (int x : arr) {
        count[x]++;
    }

    // Префіксні суми
    for (int i = 1; i <= max_val; ++i) {
        count[i] += count[i - 1];
    }

    // Запис у вихідний масив із кінця (для стабільності)
    for (int i = static_cast<int>(arr.size()) - 1; i >= 0; --i) {
        output[count[arr[i]] - 1] = arr[i];
        count[arr[i]]--;
    }

    arr = std::move(output);
}

// 2. Порозрядне сортування (LSD Radix Sort) для 32-бітних unsigned int
void radix_sort_u32(std::vector<uint32_t>& arr) {
    if (arr.size() <= 1) return;

    const size_t n = arr.size();
    std::vector<uint32_t> temp(n);

    // 4 проходи по 8 бітів (байт за байтом)
    for (int shift = 0; shift < 32; shift += 8) {
        uint32_t count[256] = {0};

        // Підрахунок частот поточного байта
        for (size_t i = 0; i < n; ++i) {
            uint8_t byte_val = (arr[i] >> shift) & 0xFF;
            count[byte_val]++;
        }

        // Префіксні суми
        uint32_t total = 0;
        for (int i = 0; i < 256; ++i) {
            uint32_t old_c = count[i];
            count[i] = total;
            total += old_c;
        }

        // Розподіл елементів по кошиках
        for (size_t i = 0; i < n; ++i) {
            uint8_t byte_val = (arr[i] >> shift) & 0xFF;
            temp[count[byte_val]++] = arr[i];
        }

        arr.swap(temp);
    }
}

int main() {
    std::vector<uint32_t> data = {0x00A1F012, 0x00000005, 0x12345678, 0x00A1E000, 0x00000001};
    
    std::cout << "Перед сортуванням:\n";
    for (auto x : data) std::cout << std::hex << "0x" << x << " ";
    std::cout << "\n\n";

    radix_sort_u32(data);

    std::cout << "Після Radix Sort (O(N)):\n";
    for (auto x : data) std::cout << std::hex << "0x" << x << " ";
    std::cout << std::dec << "\n";

    return 0;
}
```

```py
from typing import List

def counting_sort(arr: List[int]) -> List[int]:
    """Сортування підрахунком для невід'ємних цілих чисел."""
    if not arr:
        return []

    max_val = max(arr)
    count = [0] * (max_val + 1)
    output = [0] * len(arr)

    # Підрахунок частот
    for x in arr:
        count[x] += 1

    # Префіксні суми
    for i in range(1, max_val + 1):
        count[i] += count[i - 1]

    # Запис у вихідний масив із кінця (стабільність)
    for x in reversed(arr):
        output[count[x] - 1] = x
        count[x] -= 1

    return output


def radix_sort_u32(arr: List[int]) -> List[int]:
    """Порозрядне сортування (LSD Radix Sort) для 32-бітних чисел по 8 бітів."""
    if len(arr) <= 1:
        return list(arr)

    res = list(arr)
    n = len(res)

    # 4 проходи (по 8 бітів: 0, 8, 16, 24)
    for shift in range(0, 32, 8):
        count = [0] * 256
        temp = [0] * n

        # Підрахунок частот для поточного байта
        for x in res:
            byte_val = (x >> shift) & 0xFF
            count[byte_val] += 1

        # Префіксні суми
        total = 0
        for i in range(256):
            old_c = count[i]
            count[i] = total
            total += old_c

        # Розподіл елементів
        for x in res:
            byte_val = (x >> shift) & 0xFF
            temp[count[byte_val]] = x
            count[byte_val] += 1

        res = temp

    return res


# Перевірка роботи
if __name__ == "__main__":
    data = [0x00A1F012, 0x00000005, 0x12345678, 0x00A1E000, 0x00000001]
    print("Початковий масив:", [hex(x) for x in data])
    sorted_data = radix_sort_u32(data)
    print("Відсортований масив:", [hex(x) for x in sorted_data])
```

## Практичне порівняння та пастки

Чому ж Radix Sort не витіснив `std::sort` та Quicksort з усіх бібліотек?

| Критерій | Сортування порівняннями (`std::sort`) | Порозрядне сортування (`Radix Sort`) |
| :--- | :--- | :--- |
| **Складність по часу** | `O(N log N)` | `O(d · (N + K))` (фактично `O(N)`) |
| **Додаткова пам'ять** | `O(log N)` (in-place) | `O(N + K)` (потрібен буферний масив) |
| **Локальність кешу (L1/L2)** | Висока (послідовний доступ) | Середня/низька при великих кошиках |
| **Універсальність** | Будь-які типи даних із компаратором | Лише цілі числа, байтові рядки, фіксовані ключі |
| **Константа виконання** | Дуже мала (SIMD, пропуски гілок) | Вища (робота з префіксними сумами) |

### Коли обирати Radix Sort:
1. **Великі масиви примітивних типів:** Коли N > 100 000 і треба сортувати 32-бітні чи 64-бітні цілі числа, IP-адреси чи timestamp-і.
2. **GPU та паралельні обчислення:** Radix Sort чудово паралелиться на графічних процесорах (CUDA/OpenCL), де тисячі ядер можуть одночасно будувати гістограми префіксних сум.

### Коли обійтися `std::sort`:
1. **Малі масиви (N < 1000):** На малих масивах `O(N log N)` алгоритм випереджає `Radix Sort` за рахунок того, що він не виділяє додаткову пам'ять у купі та краще ловить L1-кеш.
2. **Складні об'єкти без швидкого ключа:** Якщо сортуються довільні структури даних за багатьма критеріями або текстові рядки змінної довжини.
