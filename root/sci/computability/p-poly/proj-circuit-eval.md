# ⚙️ Реалізація оцінювача булевих схем із поліноміальною підказкою

Ця програмна вставка демонструє практичну реалізацію універсального оцінювача булевих схем для неоднорідної моделі складності P/poly. Модель P/poly розширює стандартні обчислювальні системи можливістю використання додаткового вектора інформації — підказки `aₙ`, яка залежить виключно від довжини вхідних даних `n = |x|`. У практичному програмному забезпеченні та апаратних системах логічного синтезу така концепція відповідає виконанню обчислень за допомогою спрямованого ациклічного графа (DAG), де кожен вузол представляє базову булеву операцію, а листки графа отримують значення як з динамічного вхідного буфера даних, так і зі статично зконфігурованого регістру підказки.

Розроблений алгоритм оцінює схему за один лінійний прохід, що вимагає попереднього топологічного сортування гейтів. Оскільки кожна схема `Cₙ` оперує вхідними даними фіксованої довжини, масив елементів логічної схеми можна розмістити в безперервному блоці пам'яті, мінімізуючи промахи кеш-пам'яті першого рівня (L1 Data Cache) та виключаючи динамічне виділення пам'яті безпосередньо під час обробки сигналів.

## Архітектурний механізм обчислювального графа

Процес обчислення булевої схеми `Cₙ(x, aₙ)` розбивається на три послідовні фази, кожна з яких має суворе математичне та обчислювальне обґрунтування:

1. **Ініціалізація та валідація конфігурації:** Перевіряється дотримання топологічного порядку (індекси вхідних аргументів будь-якого гейта `k` повинні бути суворо меншими за `k`). Це гарантує відсутність циклічних залежностей та усуває потребу у повторних проходах чи рекурсивному обході графа у глибину (DFS).
2. **Завантаження входів та підказок:** Листові вузли типу `GATE_INPUT_X` мапяться на відповідні зсуви вхідного масиву `x`, а вузли `GATE_ADVICE_A` отримують значення з вектора підказки `aₙ`.
3. **Лінійне обчислення вентилів:** Двигун послідовно ітерується від гейта `0` до гейта `N-1`, обчислюючи логічний стан кожного елемента на основі вже розрахованих значений його попередників. Значення останнього вентиля в масиві визначає підсумковий вихід схеми (0 або 1).

## Організація пам'яті та кеш-ефективність

При обробці мільйонів вхідних векторів на секунду традиційний об'єктно-орієнтований підхід зі створенням окремих вузлів у купі (Heap) виявляється катастрофічно повільним через промахи кешу та overhead на вказівники. Замість побудови зв'язаних списків або дерев у пам'яті, наша реалізація використовує концепцію **Structure of Arrays (SoA)** або щільно упакованого масиву структур (**Array of Structures — AoS**).

Оскільки індекси входів `in1` та `in2` є цілими числами фіксованого розміру, весь DAG схеми `Cₙ` представлений як один суцільний вектор у пам'яті. Коли процесор ітерується по масиву вентилів, попередні обчислені значення вже знаходяться в швидкому кеші L1/L2, адже вони були записані у сусідні комірки масиву `values` на попередніх ітераціях.

Нижче наведено повну реалізацію оцінювача мовами C та C++. У версії для C висвітлено низькорівневе управління пам'яттю, роботу зі структурами даних без прихованих накладних витрат та перевірку межових умов за допомогою кодів повернення. У версії для C++ застосовано сучасні стандарти мови (C++20), зокрема безпечну роботу з пам'яттю через `std::span`, автоматичне управління ресурсами на основі принципу RAII, строгу типізацію enum-класів та обробку виняткових ситуацій.

## Покрокове трасування виконання та аналіз пам'яті

Розглянемо покрокову зміну внутрішнього стану обчислювального масиву `values` під час проходження демонстраційного тестового випадку, в якому вхідний бітовий вектор `x = [1, 0]`, а підказка `a_n = [0]`.

| Крок (Гейт) | Тип вентиля | Параметри / Входи | Обчислене значення | Логічне обґрунтування |
| :--- | :--- | :--- | :--- | :--- |
| `values[0]` | `GATE_INPUT_X` | `param_idx = 0` | `1` | Зчитування першого біта входу `x[0]` |
| `values[1]` | `GATE_INPUT_X` | `param_idx = 1` | `0` | Зчитування другого біта входу `x[1]` |
| `values[2]` | `GATE_ADVICE_A` | `param_idx = 0` | `0` | Зчитування біта підказки `a_n[0]` |
| `values[3]` | `GATE_NOT` | `in1 = 2` | `1` | Інверсія значення підказки `!values[2] = !0` |
| `values[4]` | `GATE_AND` | `in1 = 0, in2 = 1` | `0` | Логічне І між входами `values[0] && values[1] = 1 && 0` |
| `values[5]` | `GATE_OR` | `in1 = 4, in2 = 3` | `1` | Логічне АБО: `values[4] || values[3] = 0 || 1` (Вихід схеми) |

Як видно з трасування, підсумковий вихід становить `1` (TRUE). Якщо змінити вектор підказки на `a_n = [1]`, вентиль `values[3]` дасть `0`, що змінить вихідний результат схеми `values[5]` на `0`. Це наочно ілюструє, як підказка зовнішньо модифікує функціональність схеми без зміни її графічної топології.

## Аналіз часової та просторової складності

З точки зору обчислювальних ресурсів, запропонований оцінювач демонструє строго детерміновані характеристики:

- **Часова складність:** `O(N)`, де `N` — загальна кількість гейтів у схемі (`num_gates`). Кожен гейт обробляється за фіксований час `O(1)` завдяки використанню прямої адресації масиву. Оскільки для класу P/poly кількість гейтів обмежена поліномом від довжини входу `N ≤ p(n)`, підсумковий час виконання є суворо поліноміальним `O(p(n))`.
- **Просторова складність:** `O(N)` додаткової пам'яті для збереження проміжних результатів вентилів у масиві `values`. Оскільки `N ≤ p(n)`, споживання пам'яті задовольняє вимогам поліноміальної просторової складності.

У критичних до швидкодії застосуваннях масив `values` можна оптимізувати, бітово упаковуючи значення (8 вентилів у один байт) або застосовуючи алгоритми повторного використання комірок пам'яті для вентилів, виходи яких більше не запитуються наступними елементами DAG.

## Потенційні апаратні пастки та межові випадки

Під час розробки та розгортання оцінювачів моделей типу P/poly необхідно враховувати наступні інженерні обмеження:

1. **Порушення ациклічності (Цикли в графі):** Якщо індекси входів `in1` або `in2` посилаються на поточний або наступні вентилі (`in1 >= i`), оцінювач прочитає сміття з неініціалізованої пам'яті або потрапить у безкінечний логічний резонанс. Для запобігання цьому обов'язковим є етап попередньої валідації графа.
2. **Вихід за межі масиву підказки:** Якщо опис схеми посилається на `g.param_idx >= num_advice`, оцінювач повинен перехоплювати помилку або повертати безпечне дефолтне значення (0). Використання `std::span` у версії C++ упереджує вихід за межі масиву на етапі перевірки розміру контейнера.
3. **Експоненційне зростання підказки:** Незважаючи на теоретичне поліноміальне обмеження `|a_n| <= p(n)`, для практичних задач високих ступенів (наприклад, `n^5`) розмір файлу схеми та підказки може досягати гігабайтів, викликаючи вичерпання RAM або провали у продуктивності через роботу зі свопом.

## Оптимізація та SIMD-паралелізм

Для досягнення максимальної продуктивності на сучасних процесорах x86_64 та ARM v8/v9 обчислення булевих схем можна розпаралелити за допомогою SIMD-інструкцій (AVX-512, ARM Neon). Оскільки одна й та сама схема `Cₙ` виконується для багатьох вхідних векторів `x^{(1)}, x^{(2)}, ..., x^{(64)}`, ми можемо обчислювати 64 різні вхідні пакети даних **одночасно** за один прохід по графу схеми.

У цьому випадку кожна комірка масиву `values[i]` містить не один біт `uint8_t`, а 64-бітовий регістр `uint64_t`. Оператор `GATE_AND` перетворюється на одну побітову інструкцію `AND` (`_mm512_and_si512`), а `GATE_OR` — на побітове `OR`. Такий векторний підхід піднімає пропускну здатність обчислювального двигуна у 64 рази без збільшення кількості гейтів у схемі, перетворюючи теоретичну модель P/poly на потужний інструмент високошвидкісної обробки даних у логічному синтезі та криптоаналізі.
