# Формальні граматики: правила виводу та форми Бекуса–Наура

<preknowlist>
- [Формальна мова](root:computability/formal-language) — алфавіт Σ, слово, множина всіх слів Σ*; мова як довільна підмножина допустимих ланцюжків.
- [Теорія множин](root:math-logic/set-theory) — кортежі, декартовий добуток, відношення належності та бінарні операції над множинами.
- [Регулярні мови](root:computability/regular-languages) — скінченні автомати, регулярні вирази та їхні принципові обмеження щодо вкладених структур.
- [Магазинні автомати](root:computability/pushdown-automata) — розпізнавання мов зі стековою пам'яттю, що забезпечує синтаксичний аналіз вкладеності.
</preknowlist>

Компілятор не може перевірити правильність вихідного коду програми, звіряючи його з готовим словником усіх дозволених текстів: таких текстів нескінченно багато, а їхня довжина нічим не обмежена. Звичайні регулярні вирази також безсилі, щойно у виразі з'являються парні дужки довільної глибини або вкладені блоки `if-else`: скінченний автомат не має пам'яті, щоб порахувати кількість відкритих і закритих конструкцій. Щоб однозначно описати синтаксис нескінченної мови за допомогою скінченного опису, потрібен механізм, який не перелічує готові слова, а задає правила їхнього покрокового конструювання.

Таким механізмом є генеративна система підстановок, яка стартує з єдиного узагальненого поняття й послідовно розгортає його в конкретний ланцюжок символів.

**Формальна граматика** (грец. *grammatikē*, від *grámma* — «буква, напис», та лат. *forma* — «обрис, зовнішній вигляд») — це математична четвірка `G = (V, Σ, R, S)`, що складається зі скінченного набору синтаксичних змінних, алфавіту цільових символів, множини правил переписування та виділеного початкового символу. Замість аналізу всього тексту одразу граматика зводить перевірку структури до послідовного застосування елементарних правил підстановки.

## Анатомія граматики: чотири компоненти

Будь-яка формальна граматика строго визначається кортежем із чотирьох множин:

```
G = (V, Σ, R, S)
```

де кожен елемент виконує власну незмінну роль у системі переписування:

1. `V` (або `N`) — скінченна множина **нетермінальних символів** (лат. *terminus* — «межа, край»; нетермінал — проміжний синтаксичний маркер, що підлягає заміні). Нетермінали позначають структурні категорії мови: `<вираз>`, `<інструкція>`, `<оголошення_функції>`. Вони слугують «будівельним риштуванням» процесу побудови тексту і ніколи не з'являються в кінцевому слові. За домовленістю їх позначають великими латинськими літерами `A, B, C, S` або описовими назвами в кутових дужках.
2. `Σ` — скінченна множина **термінальних символів** (алфавіт цільової мови). Це неподільні атомарні літери, цифри, ключові слова й оператори (`if`, `while`, `+`, `(`, `42`, `id`), із яких складається кінцевий текст програми. Множини нетерміналів і терміналів за означенням не перетинаються: `V ∩ Σ = ∅`. Їхнє об'єднання `V ∪ Σ` утворює повний словник граматики.
3. `R` — скінченна множина **правил виводу** (продукцій, лат. *productio* — «подовження, виробництво»). Кожне правило задає дозволену заміну одного підрядка на інший і має вигляд:
```
α → β
```
де ліва частина `α` обов'язково містить хоча б один нетермінальний символ (`α ∈ (V ∪ Σ)* V (V ∪ Σ)*`), а права частина `β` є довільним скінченним ланцюжком із терміналів та нетерміналів (`β ∈ (V ∪ Σ)*`). Якщо права частина є порожнім рядком (`β = ε`), правило називають `ε`-продукцією або стираючим правилом.
4. `S ∈ V` — виділений **початковий (стартовий) символ**, з якого починається будь-яке виведення слів у граматиці.

> 🔧 **Навіщо це.** Розділення символів на термінали та нетермінали дає змогу відокремити лексичний рівень від синтаксичного. Лексичний аналізатор перетворює потік байтів на термінали (`Σ`), а синтаксичний аналізатор оперує структурою через нетермінали (`V`), не піклуючись про кодування символів чи пробіли між ними.

## Відношення виведення та мова граматики

Процес породження рядків граматикою полягає в покроковій заміні підрядків за правилами з множини `R`.

Нехай маємо рядок `γ = u α v`, де `u, v ∈ (V ∪ Σ)*`, і в граматиці існує правило `α → β ∈ R`. Заміна підрядка `α` на `β` утворює новий рядок `δ = u β v`. Таку однократну трансформацію називають **безпосереднім виведенням** (лат. *derivatio* — «відведення, походження») і позначають подвійною стрілкою:

```
u α v  ⇒  u β v
```

Якщо один рядок перетворюється на інший за нуль, один або декілька послідовних кроків застосування правил:

```
γ₀  ⇒  γ₁  ⇒  γ₂  ⇒  …  ⇒  γ_k      (k ≥ 0)
```

то кажуть, що рядок `γ_k` виводиться з рядка `γ₀`, і позначають це відношення через рефлексивно-транзитивне замикання:

```
γ₀  ⇒*  γ_k
```

Будь-який проміжний ланцюжок `α ∈ (V ∪ Σ)*`, який можна вивести зі стартового символу (`S ⇒* α`), називають **вивідною формою** (англ. *sentential form*). Якщо вивідна форма містить виключно термінальні символи (`w ∈ Σ*`), вона є повноцінним словом мови.

**Мова, породжена граматикою `G`** (позначається `L(G)`), — це множина всіх термінальних слів, які можна вивести зі стартового символу `S`:

```
L(G) = { w ∈ Σ* | S ⇒* w }
```

Дві граматики `G₁` та `G₂` називають **еквівалентними**, якщо вони породжують ту саму мову: `L(G₁) = L(G₂)`. Вони можуть мати абсолютно різні множини нетерміналів, різну кількість правил і різну внутрішню структуру, але множина допустимих кінцевих слів у них є тотожною.

### Лівостороннє та правостороннє виведення

Коли вивідна форма містить декілька нетерміналів одночасно, на кожному кроці постає вибір: який саме нетермінал замінювати першим.

- **Лівостороннє виведення** (англ. *leftmost derivation*, позначається `⇒_lm`): на кожному кроці замінюється крайній лівий нетермінал серед усіх присутніх у поточній формі.
- **Правостороннє виведення** (англ. *rightmost derivation*, позначається `⇒_rm`): на кожному кроці замінюється крайній правий нетермінал (канонічний порядок у висхідних парсерах).

Розглянемо просту граматику виразів із правилами `S → S + S | id`. Для слова `id + id + id` лівостороннє виведення розгортається так:

```
S  ⇒_lm  S + S
   ⇒_lm  id + S
   ⇒_lm  id + S + S
   ⇒_lm  id + id + S
   ⇒_lm  id + id + id
```

Правостороннє виведення для того самого слова обирає праві змінні:

```
S  ⇒_rm  S + S
   ⇒_rm  S + id
   ⇒_rm  S + S + id
   ⇒_rm  S + id + id
   ⇒_rm  id + id + id
```

Порядок розкриття нетерміналів не змінює кінцевого термінального рядка, проте фіксований напрямок виведення критично важливий для детермінованих алгоритмів синтаксичного аналізу.

## Ієрархія Чомскі: чотири класи правил

Властивості породженої мови повністю визначаються тим, які саме обмеження накладаються на форму продукцій `α → β`. 1956 року Ноам Чомскі класифікував усі формальні граматики на чотири вкладені класи, відомі як [ієрархія Чомскі](root:computability/chomsky-hierarchy):

| Тип | Назва класу граматик | Обмеження на продукції `α → β` | Модель автомата-розпізнавача | Пам'ять автомата |
|---|---|---|---|---|
| **Тип 0** | Необмежені (Unrestricted) | `α ∈ (V ∪ Σ)* V (V ∪ Σ)*`, `β ∈ (V ∪ Σ)*` (без обмежень) | [Машина Тюринга](root:computability/turing-machine) | Необмежена двобічна стрічка |
| **Тип 1** | Контекстно-залежні (CSG) | `\|α\| ≤ \|β\|` (правило не вкорочує рядок, крім `S → ε`) | [Лінійно обмежений автомат](root:computability/linear-bounded-automaton) | Стрічка, обмежена довжиною входу |
| **Тип 2** | Контекстно-вільні (CFG) | `A → β`, де `A ∈ V`, `β ∈ (V ∪ Σ)*` (ліворуч рівно один нетермінал) | [Магазинний автомат](root:computability/pushdown-automata) | Стек необмеженої глибини (LIFO) |
| **Тип 3** | Регулярні (Regular) | `A → a B` або `A → a` (праволінійні), де `A, B ∈ V`, `a ∈ Σ` | [Скінченний автомат](root:computability/finite-automata) | Лише скінченна кількість станів |

Ця класифікація виявляє фундаментальний зв'язок між синтаксичними правилами та теорією обчислюваності:
- **Регулярні граматики (Тип 3)** описують лексичні токени: числа, ідентифікатори, ключові слова. Їх розпізнають скінченні автомати за лінійний час `O(n)` без використання додаткової пам'яті.
- **Контекстно-вільні граматики (Тип 2)** описують синтаксичні конструкції: арифметичні вирази, оператори розгалуження, блоки коду та виклики функцій. Вони вимагають магазинної пам'яті (стека) для контролю вкладеності.
- **Контекстно-залежні граматики (Тип 1)** дозволяють виразити залежності між віддаленими частинами програми, як-от перевірку рівності кількості трьох символів `aⁿ bⁿ cⁿ` або відповідність оголошення типу його використанню.
- **Необмежені граматики (Тип 0)** еквівалентні універсальним машинам Тюринга і здатні породжувати будь-яку рекурсивно-зліченну множину слів.

Детальний аналіз математичних властивостей кожного поверху ієрархії, автоматних моделей та меж їхньої виразності наведено у статті [Ієрархія Чомського](root:computability/chomsky-hierarchy).

## Контекстно-вільні граматики (CFG)

Контекстно-вільна граматика (англ. *Context-Free Grammar*, CFG) є фундаментальним інструментом опису мов програмування. Її визначальна риса закладена в самій назві: ліва частина будь-якого правила містить **рівно один нетермінальний символ**:

```
A → α      (A ∈ V,  α ∈ (V ∪ Σ)*)
```

Це означає, що нетермінал `A` можна замінити на ланцюжок `α` **у будь-якому контексті**, незалежно від того, які символи оточують `A` ліворуч чи праворуч у поточній вивідній формі.

### Приклад: мова збалансованих дужок

Розглянемо мову `L = { aⁿ bⁿ | n ≥ 1 }` (рівна кількість символів `a` та `b`), яка не є регулярною і не може бути розпізнана скінченним автоматом. Контекстно-вільна граматика для цієї мови містить усього дві продукції:

```
S → a S b
S → a b
```

Виведення слова `aaabbb`:

```
S  ⇒  a S b
   ⇒  a a S b b
   ⇒  a a a b b b
```

Один нетермінал `S` виступає симетричною точкою росту: кожне застосування рекурсивного правила `S → a S b` одночасно додає один термінал `a` ліворуч і один термінал `b` праворуч. Завдяки цьому баланс символів підтримується автоматично на кожному кроці виведення.

Аналогічно, мова правильних дужкових структур довільного виду (мова Діка) описується граматикою:

```
S → ( S ) S | ε
```

де правило `S → ( S ) S` дозволяє як вкладати дужки всередину `( S )`, так і конкатенувати їх послідовно через правий хвіст `S`.

## Форми Бекуса–Наура: BNF та EBNF

У теоретичних математичних працях правила граматики записують через стрілку `→`. Проте під час створення мови ALGOL 60 Джон Бекус і Петер Наур розробили стандартизовану текстову нотацію для комп'ютерного набору, публікації та друку специфікацій, яка отримала назву **форма Бекуса–Наура** (англ. *Backus-Naur Form*, BNF). Історію створення цієї метамови та її конвергенцію з лінгвістичною теорією Чомскі викладено у вставці [Від мовознавства до компіляторів: як народилися форми Бекуса–Наура](root:computability/formal-grammar/hist-backus-naur.md).

У класичній BNF:
- Нетермінальні поняття записують у кутових дужках: `<вираз>`, `<число>`.
- Стрілка продукції `→` позначається складеним символом `::=`.
- Альтернативні варіанти одного правила розділяються вертикальною рискою `|`.

```bnf
<Expr>   ::= <Expr> "+" <Term> | <Term>
<Term>   ::= <Term> "*" <Factor> | <Factor>
<Factor> ::= "(" <Expr> ")" | <Number>
```

### Розширена форма Бекуса–Наура (EBNF)

Класична BNF вимагає створення допоміжних рекурсивних правил навіть для простого переліку повторюваних елементів (як-от список параметрів через кому). Щоб усунути цю громіздкість, було введено розширення **EBNF** (стандартизоване як ISO/IEC 14977):
- **Опціональність `[ ... ]`**: конструкція всередині квадратних дужок може зустрічатися 0 або 1 раз.
- **Повторення `{ ... }`**: конструкція у фігурних дужках може повторюватися 0 або більше разів (еквівалент зірочки Кліні).
- **Групування `( ... )`**: вибір альтернатив усередині виразу без створення окремого правила.
- **Термінальні рядки в лапках**: `"const"`, `'+'`.

Той самий синтаксис арифметичних виразів у нотації EBNF набуває компактного вигляду:

```ebnf
Expr   = Term , { ( "+" | "-" ) , Term } ;
Term   = Factor , { ( "*" | "/" ) , Factor } ;
Factor = ( "(" , Expr , ")" ) | Number ;
```

Повний довідник синтаксичних операторів, правил пріоритету та порівняння стандартів ISO EBNF і IETF ABNF наведено у вставці [Довідник синтаксичних нотацій: BNF, EBNF та ABNF](root:computability/formal-grammar/api-ebnf-notation.md).

### Синтаксичні діаграми (Railroad Diagrams)

Графічним еквівалентом правил EBNF є синтаксичні діаграми-«рейки». Кожне правило зображується як залізнична колія з одним входом ліворуч і одним виходом праворуч. Нетермінали позначаються прямокутниками, термінали — заокругленими блоками, розгалуження відповідають альтернативам `|`, а зворотні петлі — повторенням `{...}`.

![Синтаксична діаграма EBNF для арифметичного виразу](/root/sci/computability/formal-grammar/img/ebnf-railroad.svg)
*Синтаксична діаграма (Railroad Diagram) для правила виразу. Прямий шлях пропускає повторення, а зворотна петля знизу дозволяє додавати довільну кількість операторів і термів.*

## Дерева виводу (Parse Trees)

Послідовність застосування правил можна представити у вигляді ієрархічного графа — **дерева виводу** (синтаксичного дерева, англ. *parse tree*, грец. *sýntaxis* — «побудова, спільний порядок»).

Дерево виводу для контекстно-вільної граматики `G = (V, Σ, R, S)` задовольняє такі структурні умови:
1. Корінь дерева позначений стартовим символом `S`.
2. Кожен внутрішній вузол позначений нетерміналом `A ∈ V`.
3. Якщо внутрішній вузол `A` має нащадків `X₁, X₂, …, X_k` (зліва направо), то в граматиці обов'язково існує правило `A → X₁ X₂ … X_k ∈ R`.
4. Кожен листок дерева позначений терміналом `a ∈ Σ` або порожнім словом `ε`.

Якщо виписати всі листки дерева зліва направо, отримаємо слово `w ∈ Σ*`. Цей ланцюжок листків називають **кроною дерева** (англ. *yield of the tree*).

![Дерево виводу виразу x + y * z](/root/sci/computability/formal-grammar/img/parse-tree-expression.svg)
*Дерево виводу виразу x + y * z. Вузол множення T розташований глибше в дереві, ніж вузол додавання E, що фіксує виконання операції множення першою.*

Дерево виводу наочно фіксує семантичний зміст виразу. Оскільки операція множення `*` розкривається всередині нетермінала `T`, її піддерево лежить глибше за піддерево додавання `+`. Під час обчислення дерева знизу вгору добуток `y * z` буде обчислено раніше, ніж суму з `x`.

## Проблема неоднозначності (Ambiguity)

Граматика `G` називається **неоднозначною** (лат. *ambiguitas* — «двозначність, невизначеність»), якщо для деякого слова `w ∈ L(G)` існує **два або більше різних дерев виводу** (або, що еквівалентно, два різних лівосторонніх виведення).

### Неоднозначність в арифметичних виразах

Розглянемо наївну граматику виразів без пріоритетів:

```
E → E + E | E * E | id
```

Для рядка `id + id * id` можна побудувати два різних дерева:
1. Перше дерево групує `(id + id) * id`: операція `+` виконується першою (результат для `2 + 3 * 4` дорівнює `20`).
2. Друге дерево групує `id + (id * id)`: операція `*` виконується першою (результат дорівнює `14`).

Така граматика непридатна для компілятора, оскільки вона допускає різне семантичне тлумачення одного й того самого вихідного коду.

### Проблема «завислого else» (Dangling Else)

Класичним прикладом неоднозначності в реальних мовах програмування (C, C++, Java, Pascal) є конструкція умовного переходу `if-then-else`. Наївна граматика інструкцій має вигляд:

```bnf
<Stmt> ::= "if" <Cond> "then" <Stmt>
         | "if" <Cond> "then" <Stmt> "else" <Stmt>
         | "other"
```

Розглянемо вкладений рядок:

```
if c1 then if c2 then s1 else s2
```

![Неоднозначність dangling else](/root/sci/computability/formal-grammar/img/dangling-else-ambiguity.svg)
*Два можливих дерева виводу для вкладеного if-else. Варіант А прив'язує else до ближчого if (c2); Варіант Б — до дальшого if (c1).*

Для компілятора ця різниця є критичною:
- У варіанті А інструкція `s2` виконається, якщо `c1 = true` і `c2 = false`.
- У варіанті Б інструкція `s2` виконається, якщо `c1 = false`.

Щоб розв'язати цю проблему, граматику або модифікують, явно розділяючи інструкції на «замкнені» (ті, що обов'язково містять гілку `else`) та «відкриті»:

```bnf
<Stmt>        ::= <MatchedStmt> | <OpenStmt>
<MatchedStmt> ::= "if" <Cond> "then" <MatchedStmt> "else" <MatchedStmt>
                | "other"
<OpenStmt>    ::= "if" <Cond> "then" <Stmt>
                | "if" <Cond> "then" <MatchedStmt> "else" <OpenStmt>
```

або додають зовнішнє правило розв'язання конфліктів у парсері: *«гілка else завжди прив'язується до найближчого попереднього if»*.

### Істотна неоднозначність мов

Чи завжди можна позбутися неоднозначності, переписавши граматику? Виявляється, що ні.

Існують так звані **істотно неоднозначні контекстно-вільні мови** (англ. *inherently ambiguous languages*). Для таких мов **будь-яка** контекстно-вільна граматика, що їх породжує, обов'язково буде неоднозначною.

Класичний приклад — мова:

```
L = { aⁿ bⁿ cᵐ dᵐ | n, m ≥ 1 } ∪ { aⁿ bᵐ cᵐ dⁿ | n, m ≥ 1 }
```

Для будь-якого слова вигляду `aⁿ bⁿ cⁿ dⁿ` (де `n = m`) будь-яка граматика для `L` зможе побудувати щонайменше два принципово різні дерева виводу: одне через перевірку рівності кількості `a` та `b`, а друге — через перевірку рівності `a` та `d`.

> ⚠️ **Межа алгоритмічної розв'язності.** Загальна задача: *«Перевірити, чи є задана довільна КС-граматика однозначною»* — є **алгоритмічно нерозв'язною** (вона зводиться до проблеми відповідностей Поста). Не існує універсального алгоритму, який міг би гарантувати однозначність довільної граматики. Саме тому автори компіляторів обмежуються вужчими, детермінованими підкласами граматик: `LL(k)`, `LR(k)` та `LALR(1)`.

## Нормальна форма Чомскі (CNF)

Для доведення теоретичних теорем (наприклад, [леми про розростання для КС-мов](root:computability/regular-languages)) та побудови універсальних алгоритмів розпізнавання довільні КС-граматики приводять до канонічного вигляду.

Граматика перебуває в **нормальній формі Чомскі** (англ. *Chomsky Normal Form*, CNF), якщо всі її правила мають вигляд:

```
A → B C      (де A, B, C ∈ V,  B, C ≠ S)
A → a        (де A ∈ V,  a ∈ Σ)
S → ε        (дозволяється тільки якщо ε ∈ L(G))
```

![Конвеєр нормалізації CNF](/root/sci/computability/formal-grammar/img/cnf-pipeline.svg)
*П'ятиетапний конвеєр приведення КС-граматики до нормальної форми Чомскі. Кожен крок усуває певний структурний надлишок.*

Нормалізація виконується за п'ять послідовних кроків:
1. **START**: створення нового стартового символу `S₀ → S`, щоб стартовий символ не зустрічався в правих частинах правил.
2. **NULL**: вилучення правил `A → ε` (крім `S₀ → ε`) шляхом розмноження правил із пропуском анульовних символів.
3. **UNIT**: вилучення ланцюгових правил `A → B` шляхом підстановки правих частин для всіх досяжних пар.
4. **TERM**: заміна терміналів у довгих правилах на окремі нетермінали `T_a → a`.
5. **BIN**: каскадне розбиття довгих правил `A → B₁ B₂ … B_k` на пари бінарних правил.

Повне математичне обґрунтування алгоритму, доведення збереження еквівалентності мови та покроковий приклад перетворення наведено у вставці [Алгоритм приведення контекстно-вільної граматики до нормальної форми Чомскі](root:computability/formal-grammar/math-cnf-transformation.md).

CNF гарантує, що для будь-якого слова довжини `n` дерево виводу має висоту щонайбільше `n` і розгортається рівно за `2n − 1` кроків, що уможливлює розпізнавання слів за поліноміальний час `O(n³)` алгоритмом Кока–Янгера–Касамі (CYK).

## Синтаксичний аналіз на практиці

У реальних трансляторах граматика слугує проєктною схемою для генерації або ручного написання синтаксичного аналізатора (парсера).

Існує два основні підходи до розбору:
- **Низхідний аналіз (Top-Down):** дерево будується від кореня `S` до листків. Найпопулярнішим представником є **метод рекурсивного спуску** (англ. *recursive descent*), де кожному нетерміналу відповідає функція в коді.
- **Висхідний аналіз (Bottom-Up):** дерево збирається від вхідних терміналів до кореня `S` за допомогою операцій зсуву (shift) та згортки (reduce). Цей метод використовується у генераторах парсерів (Yacc, Bison).

Повну працюючу реалізацію синтаксичного аналізатора виразів мовами C та C++ з побудовою виведення та обчисленням результату наведено у вставці [Синтаксичний аналізатор арифметичних виразів: рекурсивний спуск на основі BNF](root:computability/formal-grammar/proj-recursive-descent.md).

Нижче наведено фрагмент, що ілюструє ядро рекурсивного розбору правила `Expr → Term { ('+' | '-') Term }`:

:::tabs
```c
/* Обробка правила <Expr> ::= <Term> { ("+" | "-") <Term> } */
double parse_expr(Parser *p) {
    double left = parse_term(p);

    while (p->current.type == TOK_PLUS || p->current.type == TOK_MINUS) {
        TokenType op = p->current.type;
        next_token(p);
        double right = parse_term(p);

        if (op == TOK_PLUS) {
            left += right;
        } else {
            left -= right;
        }
    }
    return left;
}
```
```cpp
// Обробка правила Expr = Term , { ( "+" | "-" ) , Term } ;
std::expected<double, std::string> Parser::parse_expr() {
    auto left_res = parse_term();
    if (!left_res) return left_res;
    double left = *left_res;

    while (current_.type == TokenType::Plus || current_.type == TokenType::Minus) {
        TokenType op = current_.type;
        advance();
        auto right_res = parse_term();
        if (!right_res) return right_res;
        double right = *right_res;

        if (op == TokenType::Plus) {
            left += right;
        } else {
            left -= right;
        }
    }
    return left;
}
```
:::

Код парсера безпосередньо відображає структуру EBNF-правила: нетермінал `Term` викликається як підпрограма, а цикл `while` реалізує повторення `{...}`.

## Межі контекстно-вільної моделі

Попри свою універсальність, контекстно-вільні граматики не здатні описати всі аспекти реальних мов програмування:
1. **Відповідність оголошення та використання змінних:** перевірка, чи була змінна оголошена перед використанням, зводиться до розпізнавання мови дублікатів `{ w w | w ∈ Σ* }`, яка належить до контекстно-залежних мов (Тип 1).
2. **Перевірка типів та узгодження кількості аргументів:** функція очікує 3 аргументи, а передано 4 — ця властивість не вкладається в чистий синтаксис CFG.

З цієї причини архітектура всіх сучасних компіляторів розділена на два рівні:
- **Синтаксис (CFG / BNF)** перевіряє виключно форму конструкцій (дужки, оператори, блоки) та будує абстрактне синтаксичне дерево (AST).
- **Семантичний аналізатор** (таблиця символів, система виведення типів) виконує контекстну перевірку поверх уже побудованого дерева.

Такий поділ робить розробку компіляторів модульною, масштабованою та математично верифікованою.
