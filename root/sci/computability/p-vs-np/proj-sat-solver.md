# ⚙️ Межа на практиці: CDCL/DPLL SAT-соловер та експоненційний фазовий перехід 3-SAT

Попри те, що фундаментальне питання про тотожність P та NP залишається математично відкритим, інженери зіштовхуються з межею обчислювальної складності щодня. Сучасні промислові інструменти — **SAT-соловери** (програми для розв'язання задачі здійсненності булевих формул у кон'юнктивній нормальній формі) — лежать у основі формальної верифікації мікропроцесорів (Intel, AMD, ARM), автоматичного синтезу логічних схем, виявлення вразливостей у програмному забезпеченні, планивання задач у розподілених системах та автоматизованого доведення теорем у системах SMT (Satisfiability Modulo Theories).

У цій вставці наведено практичну реалізацію класичного алгоритму **DPLL** (Davis–Putnam–Logemann–Loveland) — фундаменту сучасних **CDCL** (Conflict-Driven Clause Learning) соловери. Ми детально розберемо два ключові механізми прискорення пошуку — **поширення одиничних диз'юнктів** (*unit propagation*) та **усунення чистих літералів** (*pure literal elimination*), простежимо покрокову роботу алгоритму на конкретних прикладах, розглянемо трансформацію Цейтіна для перекладу довільних логічних схем у КНФ, а також наочно продемонструємо явище **фазового переходу** (phase transition), де час виконання програми вибухає експоненційно.

## 1. Архітектура та механізми DPLL і CDCL

Формула у кон'юнктивній нормальній формі (КНФ / CNF) є кон'юнкцією (операція І / AND) диз'юнктів (операція АБО / OR), кожен із яких складається з літералів (змінних або їхніх заперечень).

Наприклад, формула від 3 змінних `x₁, x₂, x₃`:
```
(x₁ ∨ ¬x₂) ∧ (x₂ ∨ x₃) ∧ (¬x₁ ∨ ¬x₃)
```

Сліпий перебір усіх можливих `2ⁿ` комбінацій значень змінних швидко стає неможливим уже для `n = 50` (понад `10¹⁵` операцій). Алгоритм DPLL покращує сліпий пошук за допомогою трьох ключових механізмів:

### 1. Unit Propagation (Поширення одиничних диз'юнктів)

Це головний двигун швидкодії SAT-соловера. Одиничним диз'юнктом (unit clause) називається диз'юнкт, у якому за поточного часткового призначення змінних усі літерали, крім одного, вже оцінені як `False` (хибні), а останній літерал `L` залишається неоціненим.

Щоб увесь диз'юнкт залишався істинним, ми **зобов'язані** призначити літералу `L` значення `True`. Це вимушене призначення не є вибором гілки — воно є детермінованим наслідком попередніх рішень. Призначення `L = True` миттєво робить інші диз'юнкти одиничними, запускаючи ланцюгову реакцію (*unit propagation cascade*). У сучасних соловерах до 90% усіх змінних оцінюються саме через unit propagation без створення нових гілок рекурсії.

### 2. Pure Literal Elimination (Усунення чистих літералів)

Чистим літералом називається змінна, яка у всій формулі з'являється лише в одного знака: або тільки як `x_i`, або тільки як `¬x_i`. Якщо змінна з'являється лише позитивно, їй можна відразу присвоїти `True`, бо це призначення не може порушити жоден диз'юнкт. Усунення чистих літералів дозволяє зменшити розмірності формули без створення гілок пошуку.

### 3. Chronological Backtracking (Хронологічне повернення)

Якщо unit propagation та pure literal elimination не можуть зробити жодного вимушеного шагу, алгоритм робить евристичний **вибір** (decision): обирає неоцінену змінну `x` і присвоює їй `True`. Якщо в результаті поширення виникає конфлікт (порожній диз'юнкт, де всі літерали стали `False`), алгоритм скасовує останні присвоєння (*backtrack*) і пробує альтернативну гілку `x = False`.

```
                    [ Вхідна CNF Формула ]
                              │
             ┌────────────────┴────────────────┐
             ▼                                 ▼
   [ Unit Propagation ]             [ Pure Literal Elimination ]
             │                                 │
             └────────────────┬────────────────┘
                              │
             ┌────────────────┴────────────────┐
             ▼                                 ▼
     [ Виклик конфлікту? ]           [ Усі задоволені? ]
      (Порожній диз'юнкт)             (Формула істинна)
             │                                 │
       (Так) ▼                           (Так) ▼
      Backtrack                         Повернути SAT
    (Спробувати-x)                    (Вивести свідок)
             │
          (Ні) ▼
    [ Обрати нову змінну x ] ──► Рекурсивний виклик DPLL
```

## 2. Від DPLL до CDCL: Промислові оптимізації

Сучасні промислові соловери (MiniSat, Glucose, Z3, CVC5) розширюють DPLL до архітектури **CDCL** (Conflict-Driven Clause Learning):

### 1. Аналіз конфліктів та навчання диз'юнктів (Clause Learning)

Коли виникає конфлікт (порожній диз'юнкт), CDCL будує граф імплікацій (*implication graph*), де вузлами є призначення змінних, а ребрами — диз'юнкти, що викликали unit propagation. Соловер аналізує причинно-наслідковий ланцюжок від рішень до суперечності і шукає Перший унікальний пункт імплікації (First Unique Implication Point, 1UIP). На основі 1UIP будується новий диз'юнкт-конфлікт (*learned clause*), який додається до формули. Цей новий диз'юнкт відсікає цілі класи аналогічних хибних гілок пошуку.

Граф імплікацій будується в динаміці: кожна змінна `v`, оцінена через unit propagation диз'юнктом `C`, отримує ребра від усіх інших змінних `u ∈ C \ {v}` до `v`. Конфліктний вузол `Λ` утворюється, коли одна й та сама змінна отримує протилежні значення. Поріз (cut) графа імплікацій, що відокремлює рішення від конфлікту і містить 1UIP, визначає коефіцієнти нового вивченого диз'юнкту:

```
[ Decision x=1 (d=3) ] ──► (x ∨ ¬y) ──► [ y=1 ] ──┐
                                                 ├─► [ Конфлікт Λ ]
[ Decision z=0 (d=3) ] ──► (z ∨ ¬y ∨ ¬w) ─► [ w=1 ] ──┘
```

1UIP виступає як найкоротша вузлова точка на поточному рівні прийняття рішень, пов'язана з конфліктом. Використання 1UIP для побудови диз'юнкту гарантує, що новий вивчений диз'юнкт містить рівно один літерал із поточного рівня прийняття рішень `d`, що робить його одиничним (unit clause) одразу після нехронологічного бектрекінгу.

### 2. Нехронологічне повернення (Non-chronological Backjumping)

Використовуючи вивчений диз'юнкт, CDCL обчислює другий за величиною рівень прийняття рішень у новому диз'юнкті та здійснює нехронологічний стрибок назад на кілька рівнів рекурсії вгору (наприклад, від рівня `d=10` одразу до рівня `d=2`), минаючи десятки непотрібних гілок перебору, де суперечність була неминучою.

### 3. Схема спостережуваних літералів (2-Watched Literals)

Замість переобчислення стану всіх диз'юнктів при кожній зміні змінної, CDCL підтримує в кожному диз'юнкті вказівники лише на **два не-хибні літерали**. Диз'юнкт перевіряється лише тоді, коли один із двох спостережуваних літералів стає хибним. Якщо вдається знайти альтернативний не-хибний літерал, вказівник переміщується на нього; якщо ні — диз'юнкт стає одиничним або порожнім. Це зменшує складність оновлення стану формули з `O(|Formula|)` до `O(1)` для більшості змінних.

Двовекторний механізм 2-Watched Literals є інженерним шедевром: під час бектрекінгу соловерові взагалі не потрібно оновлювати вказівники спостереження, оскільки скасування присвоєння повертає літерал у стан `Unassigned`, що не порушує інваріант присутності двох не-хиблих літералів у диз'юнкті.

### 4. Евристика VSIDS (Variable State Independent Decaying Sum)

Підтримує рейтинг змінних `A(v)`, який зростає кожного разу, коли змінна бере участь у створенні конфліктного диз'юнкту: `A(v) ← A(v) + δ`. Крок приросту regular згасає: `δ ← δ / γ` (де `γ = 0.95`). Якщо `A(v)` перевищує поріг `10¹⁰⁰`, усі рейтинги помножуються на `10⁻²⁰` для відвернення переповнення float. Соловер віддає перевагу вибору змінних з найвищим `A(v)`, фокусуючи обчислення на поточних "гарячих" ділянках формули.

### 5. Перезапуски (Restarts)

Періодичне скидання поточного дерева рішень із збереженням вивчених диз'юнктів (наприклад, за послідовністю Любі `1, 1, 2, 1, 1, 2, 4, ...` або експоненційним графіком) дозволяє соловеру вирватися з невдалих гілок пошуку та досліджувати нові області простору рішень.

### 6. Скорочення бази вивчених диз'юнктів (Clause Database Reduction)

Оскільки кількість вивчених диз'юнктів швидко зростає після кожного конфлікту, пам'ять соловера може переповнитися. Промислові соловери періодично видаляють найменш корисні вивчені диз'юнкти (наприклад, оцінюючи їх за метрикою LBD — Literal Block Distance, яка вимірює кількість різних рівнів прийняття рішень у диз'юнкті).

## 3. Покрокове простеження роботи DPLL на конкретних прикладах

### Приклад 1: Виконувана формула (SAT)

Розглянемо формулу від 4 змінних `x₁, x₂, x₃, x₄` із 6 диз'юнктами:

```
C₁: (x₁ ∨ x₂)
C₂: (¬x₁ ∨ x₃)
C₃: (¬x₂ ∨ x₄)
C₄: (¬x₃ ∨ ¬x₄)
C₅: (x₁ ∨ ¬x₄)
C₆: (¬x₁ ∨ ¬x₂)
```

Простежимо роботу алгоритму DPLL покроково:

1. **Крок 1 (Decision):** Жоден диз'юнкт не є одиничним. Робимо вибір: `x₁ = True`.
2. **Крок 2 (Unit Propagation):**
   - У диз'юнкті `C₆: (¬x₁ ∨ ¬x₂)` літерал `¬x₁` став `False`. Диз'юнкт перетворився на одиничний `(¬x₂)`. Вимушено призначаємо `x₂ = False`.
   - У диз'юнкті `C₂: (¬x₁ ∨ x₃)` літерал `¬x₁` став `False`. Диз'юнкт перетворився на одиничний `(x₃)`. Вимушено призначаємо `x₃ = True`.
3. **Крок 3 (Дальший Unit Propagation):**
   - Розглядаємо `C₄: (¬x₃ ∨ ¬x₄)`. Оскільки `x₃ = True`, літерал `¬x₃` є `False`. Диз'юнкт став одиничним `(¬x₄)`. Вимушено призначаємо `x₄ = False`.
4. **Крок 4 (Перевірка виконання):**
   - Перевіряємо `C₁: (x₁ ∨ x₂)` — `x₁ = True` (Sat).
   - Перевіряємо `C₃: (¬x₂ ∨ x₄)` — `x₂ = False` ⇒ `¬x₂ = True` (Sat).
   - Перевіряємо `C₅: (x₁ ∨ ¬x₄)` — `x₁ = True` (Sat).
   - Усі 6 диз'юнктів істинні! Алгоритм завершується з відповіддю **SAT** та свідком: `(x₁=1, x₂=0, x₃=1, x₄=0)`.

### Приклад 2: Виклики конфлікту та хронологічне повернення (Backtracking)

Розглянемо формулу з 3 змінних `x₁, x₂, x₃`:

```
C₁: (x₁ ∨ x₂)
C₂: (x₁ ∨ ¬x₂)
C₃: (¬x₁ ∨ x₃)
C₄: (¬x₁ ∨ ¬x₃)
```

1. **Крок 1 (Decision):** Обираємо `x₁ = True`.
2. **Крок 2 (Unit Propagation):**
   - У `C₃: (¬x₁ ∨ x₃)` літерал `¬x₁ = False` ⇒ вимушено `x₃ = True`.
   - У `C₄: (¬x₁ ∨ ¬x₃)` літерал `¬x₁ = False` та `¬x₃ = False` ⇒ порожній диз'юнкт! Конфлікт!
3. **Крок 3 (Backtrack):** Скасовуємо `x₃` та `x₁ = True`. Випробовуємо альтернативну гілку: `x₁ = False`.
4. **Крок 4 (Unit Propagation у новій гілці):**
   - У `C₁: (x₁ ∨ x₂)` літерал `x₁ = False` ⇒ вимушено `x₂ = True`.
   - У `C₂: (x₁ ∨ ¬x₂)` літерал `x₁ = False` та `¬x₂ = False` ⇒ порожній диз'юнкт! Другий конфлікт!
5. **Висновок:** Обидві гілки для `x₁` дали конфлікт. Алгоритм повертає **UNSAT**.

## 4. Трансформація Цейтіна: Зведення довільних схем до КНФ

На практиці інженерні задачі рідко описуються формулами у КНФ — частіше це комбінаторні логічні схеми із вентилями AND, OR, NOT, XOR, NAND, NOR.

Наївне розкриття дужок за законами дистрибутивності для перетворення схеми на КНФ вимагає **експоненційного росту розміру** формули `O(2ⁿ)`. Щоб уникнути цього, використовують **трансформацію Цейтіна** (Григорій Цейтін, 1968), яка будує еквівалентну КНФ-формулу **поліноміального розміру** `O(N)` ціною введення допоміжних змінних для кожного логічного вентиля.

### Приклад кодування вентилів у КНФ за Цейтіним:

1. **Вентиль І (AND): `y ⇔ (a ∧ b)`**
   Еквівалентна КНФ містить 3 диз'юнкти:
   ```
   (¬a ∨ ¬b ∨ y) ∧ (a ∨ ¬y) ∧ (b ∨ ¬y)
   ```

2. **Вентиль АБО (OR): `y ⇔ (a ∨ b)`**
   Еквівалентна КНФ містить 3 диз'юнкти:
   ```
   (a ∨ b ∨ ¬y) ∧ (¬a ∨ y) ∧ (¬b ∨ y)
   ```

3. **Вентиль НІ (NOT): `y ⇔ ¬a`**
   Еквівалентна КНФ містить 2 диз'юнкти:
   ```
   (a ∨ y) ∧ (¬a ∨ ¬y)
   ```

4. **Вентиль Виключне АБО (XOR): `y ⇔ (a ⊕ b)`**
   Еквівалентна КНФ містить 4 диз'юнкти:
   ```
   (¬a ∨ ¬b ∨ ¬y) ∧ (a ∨ b ∨ ¬y) ∧ (a ∨ ¬b ∨ y) ∧ (¬a ∨ b ∨ y)
   ```

5. **Вентиль І-НІ (NAND): `y ⇔ ¬(a ∧ b)`**
   Еквівалентна КНФ містить 3 диз'юнкти:
   ```
   (¬a ∨ ¬b ∨ ¬y) ∧ (a ∨ y) ∧ (b ∨ y)
   ```

6. **Вентиль АБО-НІ (NOR): `y ⇔ ¬(a ∨ b)`**
   Еквівалентна КНФ містить 3 диз'юнкти:
   ```
   (a ∨ b ∨ y) ∧ (¬a ∨ ¬y) ∧ (¬b ∨ ¬y)
   ```

### Кодування суматора (Full Adder) у КНФ

Розглянемо приклад побудови КНФ для 1-бітного суматора з переносом:
- `Sum = A ⊕ B ⊕ C_in`
- `C_out = (A ∧ B) ∨ (C_in ∧ (A ⊕ B))`

Увівши допоміжні змінні `y₁ = A ⊕ B`, `y₂ = A ∧ B`, `y₃ = C_in ∧ y₁`, ми виражаємо схему суматора у КНФ із 14 диз'юнктів за лінійний час від кількості вентилів. Кожна проміжна змінна фіксує вихід конкретного логічного елемента, що запобігає дублюванню піддерев логічних виразів. Завдяки трансформації Цейтіна будь-яка програма або логічна схема розміру `N` перекладається у КНФ-формулу з `O(N)` змінних та `O(N)` диз'юнктів за лінійний час.

### Фізична аналогія: Модель спінового скла

Фазовий перехід у 3-SAT є близьким аналогом термодинамічних фазових переходів у статистичній фізиці (модель спінового скла / Spin Glass Model). Кожна змінна відповідає спину `s_i ∈ {-1, +1}`, а диз'юнкти виступають в ролі нелінійних взаємодій між трійками спінів. 
- При низькій щільності `α < α_c` система перебуває у "парамагнітній" фазі з великою кількістю мінімумів вільній енергії (задовольняючих наборів).
- При критичній щільності `α = α_c ≈ 4.267` ландшафт енергії фраґментується на гігантську кількість ізольованих "метастабільних" станів, розділених високими енергетичними бар'єрами, що й спричиняє сповільнення алгоритмів локального та рекурсивного пошуку.

### Розширення до SMT (Satisfiability Modulo Theories) та DPLL(T)

У промисловій верифікації чистого пропозиційного SAT недостатньо — вирази містять математичні функції, нерівності над цілими числами чи бітові вектори (наприклад, `x + 2*y ≤ 5 ∧ f(x) ≠ f(y)`). Розширення **DPLL(T)** поєднує SAT-ядро з теорією `T` (наприклад, Linear Integer Arithmetic LIA або Bit-Vectors BV). SAT-ядро працює з булевими абстракціями атомарних тверджень `p₁ = (x + 2*y ≤ 5)`. Коли SAT-ядро знаходить часткове призначення, спеціалізований `T`-соловер перевіряє сумісність математичних рівнянь. Якщо виявляється математична суперечність, `T`-соловер виводить нову конфліктну КНФ-секвенцію `¬p₁ ∨ ¬p₂` і повертає її в SAT-двигун, що запускає нехронологічний бектрекінг CDCL.

Стандартам інформаційного обміну для SMT-проблем є формат **SMT-LIB 2.6**, який визначає точні теорії (QF_LIA, QF_BV, QF_UF). Промислові соловери Z3 та CVC5 поєднують онлайн-поширення `T`-теорій із попередньою спрощувальною обробкою КНФ (subsumption, variable elimination), досягаючи високої ефективності на мільйонах промислових тестів. Використання DPLL(T) у сучасних системах підтверджує, що практичне розв'язання обчислювальних задач спирається на синергію абстрактного булевого пошуку з предметно-орієнтованими алгебраїчними інваріантами.

### Порівняльне простеження DPLL проти CDCL для формули принцип Діріхле (PHP_n)

Принцип Діріхле (Pigeonhole Principle, `PHP_n`) стверджує, що неможливо розкласти `n+1` голубів у `n` кліток так, щоб у кожній клітці було не більше одного голуба. Кодування `PHP_n` у КНФ створює структуру з `O(n²)` змінних та `O(n³)` диз'юнктів.

- Класичний алгоритм **DPLL** без вивчення диз'юнктів вимагає експоненційного часу `2^{Ω(n)}` для доведення невиконуваності `PHP_n`, оскільки він щоразу повторює однакові суперечливі гілки перебору для різних комбінацій голубів.
- Алгоритм **CDCL** із вивченням диз'юнктів виводить диз'юнкти-конфлікти на основі 1UIP, що доказово еквівалентно системі резолюцій. Завдяки цьому CDCL здатний доводити UNSAT для багатьох структурних задач за поліноміальний або квазіполіноміальний час.

Огляд сучасної інженерії SAT-соловерів показує, як алгоритмічна думка змогла освоїти важкі комбінаторні простори. Хоча експоненційний вибух на межі фазового переходу залишається нездоланним у найгіршому випадку, поєднання CDCL, трансформації Цейтіна та DPLL(T) дозволяє ефективно вирішувати мільйони виробничих задач реального світу.

### Практичний висновок для інженера:

1. **"Прості" підзони:** При `α < 3.5` формула має колосальну кількість задовольняючих наборів, тому перша ж гілка рекурсії знаходить розв'язок. При `α > 5.0` формула містить так багато суперечностей, що unit propagation виявляє їх на перших рівнях дерева.
2. **"Важка" зона фазового переходу:** На межі `α_c ≈ 4.267` формула не має вимушених одиночних диз'юнктів на початку, але й розв'язків залишилися одиниці. Соловер змушений виконувати майже повний перебір експоненційного дерева `2ⁿ`.
3. **Промислове значення:** Виробничі КНФ-формули (наприклад, із формальної верифікації криптопроцесорів та оптимізації компіляторів) мають чітку й виражену логічну структуру та симетрії, а не є хаотично випадковими. Інженери розробляють соловери так, щоб ефективно виявляти цю внутрішню структуру, згортати еквівалентні підформули та надійно уникати потрапляння у фазовий перехід.
