# ⚙️ Емуляція оператора нерухомої точки та Y-комбінатора на C та C++

У математичній теорії обчислень функція вважається повноцінно обчислюваною без необхідності вводити глобальні імена, стан або таблиці символів. Теорема Кліні про нерухому точку та комбінаторні числення гарантують, що будь-яке рекурсивне визначення можна звести до знаходження нерухомої точки функціонала вищого порядку: `Y(F) = F(Y(F))`. Цей проект демонструє, як реалізувати оператор нерухомої точки мовами C та C++, щоб обчислювати рекурсивні алгоритми (факторіал, числа Фібоначчі, функцію Аккермана, динамічне програмування) виключно через анонімне самопосилання та функціональні замикання.

## Концепція нерухомої точки функціонала

Звичайна рекурсивна функція факторіала спирається на власне глобальне ім'я для здійснення повторного виклику:

:::tabs
```c
uint64_t factorial(uint64_t n) {
    return (n == 0) ? 1 : n * factorial(n - 1);
}
```
```cpp
auto factorial(uint64_t n) -> uint64_t {
    return (n == 0) ? 1 : n * factorial(n - 1);
}
```
:::

Якщо прибрати глобальне ім'я `factorial`, функція втрачає здатність викликати себе. Щоб повернути рекурсію, ми виносимо крок самовиклику в аргумент. Ми перетворюємо алгоритм на функціонал вищого порядку `F`, який першим аргументом приймає функцію кроку `self`, а другим — вхідні дані `n`:

```
F = λself. λn. (n == 0 ? 1 : n * self(n - 1))
```

Оператор нерухомої точки `fix` приймає такий функціонал `F` і повертає нову функцію `f = fix(F)`, яка володіє фундаментальною властивістю нерухомої точки:

```
f(n) = F(f, n)
```

Завдяки цьому функція `F` може виконувати стільки рекурсивних кроків, скільки потрібно для обчислення результату, не знаючи при цьому свого власного імені у вихідному коді чи адреси в таблиці символів лінкера.

## Відмінність між Y-комбінатором та Z-комбінатором у строгих мовах

У класичному лінивому лямбда-численні (call-by-name) нерухома точка виражається канонічним Y-комбінатором Гаскелла Каррі:

```
Y = λf. (λx. f (x x)) (λx. f (x x))
```

Проте в мовах зі строгим обчисленням аргументів (call-by-value), таких як C та C++, застосування класичного Y-комбінатора призводить до миттєвого переповнення стека (stack overflow). У виразі `(λx. f (x x))` підвираз `(x x)` намагається обчислитися до того, як керування буде передане в тіло функції `f`, породжуючи нескінченний цикл розгортання без виконання корисних інструкцій.

Для строгих мов використовується так званий **Z-комбінатор** (або аплікативний комбінатор нерухомої точки), який відкладає обчислення наступного рекурсивного кроку через додаткову функціональну обгортку:

```
Z = λf. (λx. f (λv. x x v)) (λx. f (λv. x x v))
```

Ця затримка обчислення (η-розширення) гарантує, що наступний рекурсивний крок виконується лише тоді, коли алгоритм дійсно звертається до функції `self` з конкретним аргументом.

## Покрокове трасування стека викликів

Розглянемо внутрішню динаміку пам'яті під час виконання виклику `factorial(3)` в C++ реалізації:

1. **Ініціація:** Користувач викликає `factorial(3)`. Об'єкт `FixedPoint` перехоплює виклик у методі `operator()(3)` і викликає збережену лямбда-функцію: `func(*this, 3)`.
2. **Перший стек-фрейм:** У тілі лямбди параметр `self` стає константним посиланням на об'єкт `FixedPoint`, а `n = 3`. Умова `n == 0` є хибною, тому обчислюється складений вираз `3 * self(2)`.
3. **Другий стек-фрейм:** Вираз `self(2)` знову активує метод `operator()(2)` того самого екземпляра `FixedPoint`, який повторно викликає `func(*this, 2)`. Обчислюється підвираз `2 * self(1)`.
4. **Третій стек-фрейм:** Виклик `self(1)` аналогічно породжує вираз `1 * self(0)`.
5. **Базовий випадок (зупинка рекурсії):** Виклик `self(0)` переходить у гілку умови `n == 0` і повертає константу `1` без повторної активації посилання `self`.
6. **Згортання ланцюга викликів:** Результати послідовно підставляються назад: `1 * 1 = 1`, далі `2 * 1 = 2`, і на верхньому рівні `3 * 2 = 6`.

## Архітектурний аналіз та практичні висновки

1. **Трансляція анонімних функціоналів компілятором:** Компілятор C++ транслює лямбда-вираз в анонімний клас із перевантаженим `operator()`. Оскільки клас `FixedPoint` не містить віртуальних функцій і не виділяє динамічну пам'ять, оптимізатор (GCC/Clang на рівнях `-O2` або `-O3`) повністю інлайнить усі проміжні виклики диспетчера, перетворюючи чисту комбінаторну рекурсію на компактний асемблерний цикл без жодних накладних витрат часу виконання.
2. **Усунення глобального зв'язування:** Відсутність глобального імені дозволяє створювати рекурсивні алгоритми безпосередньо всередині локальних блоків коду, передавати їх як аргументи іншим функціям вищого порядку та безпечно комбінувати в багатопотокових середовищах без ризику конфлікту просторів імен. Це основа функціонального стилю програмування та побудови складних пайплайнів обробки даних.
3. **Управління глибиною стека та мемоізація:** У немемоізованих розгалужених рекурсіях (як-от наївний Фібоначчі або функція Аккермана) кількість фреймів стека зростає експоненційно. Поєднання оператора нерухомої точки з декоратором мемоізації дозволяє перехоплювати однакові аргументи на рівні диспетчера, кардинально знижуючи часову складність алгоритму (наприклад, з `O(2ⁿ)` до `O(n)`) без зміни вихідного математичного запису рекурсивного рівняння.
4. **Еволюція стандарту C++23 (Deducing This):** У стандарті C++23 з'явилася можливість явного визначення об'єкта `this` у параметрах функції (`explicit object parameter`), що дозволяє писати саморекурсивні лямбда-функції без окремої шаблонної обгортки:
   ```cpp
   auto fact = [](this auto self, uint64_t n) -> uint64_t {
       return (n == 0) ? 1 : n * self(n - 1);
   };
   ```
   Ця синтаксична конструкція є прямою стандартизацією оператора нерухомої точки на рівні ядра мови C++.
5. **Зв'язок із денотаційною семантикою:** У денотаційній семантиці мов програмування кожна рекурсивна функція розглядається саме як нерухома точка відповідного оператора над доменом значень. Реалізація `make_fixed` на рівні мови є прямим втіленням теоретико-доменної семантики Скотта у виконуваному машинному коді.
