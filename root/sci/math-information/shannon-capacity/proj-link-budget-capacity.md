# ⚙️ Розрахунок енергетичного бюджету лінка та граничної ємності каналу

Під час проєктування бездротових, кабельних та оптичних мереж зв'язку інженер стикається із задачею оцінки граничної пропускної здатності каналу на основі вихідних параметрів передавача, фізичного середовища поширення хвиль, антенно-фідерного тракту та чутливості приймального модуля. Нижче наведено детальний теоретичний аналіз енергетичного бюджету радіолінії (англ. *link budget*), розрахунок рівня [теплового шуму Найквіста](topic:hw-analog/resistor-noise), визначення підсумкового відношення сигнал/шум (`SNR`), обчислення теоретичної ємності за формулою Шеннона та визначення практично досяжної бітової швидкості з урахуванням розриву Шеннона для сучасних схем [адаптивної модуляції та кодування (MCS)](topic:com-modulation/adaptive-modulation).

### Фізична модель розрахунку енергетичного бюджету

Розрахунок надійності та швидкості будь-якої лінії зв'язку починається з визначення двох ключових величин на вході демодулятора: повної потужності прийнятого сигналу `P_rx` та сумарної потужності шумів і завад `N_total`.

#### 1. Рівняння передачі Фріїса та згасання в середовищі

Потужність високочастотного сигналу на клемах антени приймача визначається логарифмічним рівнянням балансу потужностей:

```
P_rx [дБм] = P_tx [дБм] + G_tx [дБі] - L_tx_cable [дБ] - L_path [дБ] + G_rx [дБі] - L_rx_cable [дБ]
```

Де:
- `P_tx` (дБм) — вихідна потужність передавача в [децибелах до мілівата](topic:com-medium/power-decibels).
- `G_tx`, `G_rx` (дБі) — коефіцієнти підсилення передавальної та приймальної антен відносно ідеального ізотропного випромінювача.
- `L_tx_cable`, `L_rx_cable` (дБ) — омічні втрати сигналу у високочастотних коаксіальних кабелях, роз'ємах та узгоджувальних фільтрах.
- `L_path` (дБ) — загасання електромагнітної хвилі на трасі поширення. Для вільного простору (англ. *Free Space Path Loss*, FSPL) на відстані `d` метрів при частоті `f` герців згасання становить:

```
FSPL [дБ] = 20 · log₁₀(d) + 20 · log₁₀(f) + 20 · log₁₀(4π / c)
FSPL [дБ] = 20 · log₁₀(d [км]) + 20 · log₁₀(f [МГц]) + 32.44    [згасання у вільному просторі]
```

У реальних міських умовах або всередині приміщень до згасання додаються втрати на проникнення крізь стіни (від 3–5 дБ для гіпсокартону до 20–30 дБ для залізобетону), дифракція на кутах будівель та логнормальні завмирання через багатопроменеве поширення.

#### 2. Тепловий шум та коефіцієнт шуму приймального тракту

Навіть за повної відсутності зовнішніх штучних завад будь-який радіоприймач обмежений фундаментальним тепловим шумом руху електронів в антени та першому каскаді малошумного підсилювача (LNA).

Спектральна густина потужності білого теплового шуму при абсолютній температурі `T = 290 К` становить:

```
N₀ = k_B · T₀ = 1.380649 · 10⁻²³ · 290 ≈ 4.0039 · 10⁻²¹ Вт/Гц
N₀ [дБм/Гц] = 10 · log₁₀(4.0039 · 10⁻¹⁸ мВт) ≈ -173.98 дБм/Гц ≈ -174.0 дБм/Гц
```

Сумарна потужність шуму на вході приймача залежить від ширини смуги пропускання каналу `B` та коефіцієнта шуму приймача `NF` (англ. *Noise Figure*):

```
N_thermal [дБм] = -174.0 + 10 · log₁₀(B [Гц])
N_total [дБм] = N_thermal [дБм] + NF [дБ]    [повний рівень шуму у смузі каналу]
```

Коефіцієнт шуму багатокаскадного приймача обчислюється за формулою Гаральда Фріїса:

```
F_total = F₁ + (F₂ - 1) / G₁ + (F₃ - 1) / (G₁ · G₂)    [формула шуму Фріїса]
```

З цієї формули випливає критичне інженерне правило: перший каскад приймача (малошумний підсилювач LNA) повинен мати якомога менший власний коефіцієнт шуму `F₁` і високий коефіцієнт підсилення `G₁`. Якщо між антеною та LNA поставити довгий кабель із втратами 3 дБ, це еквівалентно зростанню коефіцієнта шуму всієї системи на 3 дБ, що вдвічі знижує підсумкове `SNR` і відтинає значну частину шеннонівської ємності.

#### 3. Чутливість приймача та мінімально допустимий поріг

Мінімальна потужність радіосигналу на вході приймача, за якої демодулятор здатен виділити корисну інформацію із заданою ймовірністю бітової помилки `BER`, називається **чутливістю приймача** (англ. *receiver sensitivity*, `P_sens`):

```
P_sens [дБм] = N_thermal [дБм] + NF [дБ] + SNR_min [дБ] + L_impl [дБ]
```

Де:
- `SNR_min` (дБ) — мінімальне відношення сигнал/шум, необхідне для обраного формату модуляції та швидкості завадостійкого кодування.
- `L_impl` (дБ) — технологічні апаратні втрати реалізації (англ. *implementation loss*, типово 1.5–3.0 дБ), зумовлені неідеальністю цифрових фільтрів, похибками квантування АЦП та неточністю оцінки фази каналу.

Якщо потужність прийнятого сигналу вища за чутливість (`P_rx > P_sens`), різниця `M = P_rx - P_sens` утворює **енергетичний запас лінії** (англ. *link margin*), який гарантує стабільність каналу під час сезонних змін погоди та переміщення терміналів.

#### 4. Відношення сигнал/шум та ємність за Шенноном

Різниця між прийнятою потужністю сигналу та сумарним шумом дає лінійне та логарифмічне відношення `SNR`:

```
SNR [дБ] = P_rx [дБм] - N_total [дБм]
SNR_lin = 10^(SNR [дБ] / 10)
```

Теоретична ємність за Шенноном визначає граничну швидкість передачі без помилок:

```
C = B · log₂(1 + SNR_lin)    [теоретична ємність каналу, біт/с]
η = C / B = log₂(1 + SNR_lin) [спектральна ефективність, біт/с/Гц]
```

#### 5. Практична бітова швидкість та розрив Шеннона

Реальні алгоритми модуляції та завадостійкого кодування не досягають теоретичної межі через обмежену довжину кодового слова, дискретність сузір'їв QAM та втрати на синхронізацію. Практичну бітову швидкість оцінюють за формулою з коефіцієнтом розриву Гапа `Γ` (англ. *Shannon gap*):

```
C_practical = B · log₂(1 + SNR_lin / Γ_lin)    [практична бітова швидкість лінії]
```

Значення розриву Шеннона залежить від технології кодування:
- Для незкодованої модуляції `M-QAM` за вимоги `BER = 10⁻⁵`: `Γ ≈ 8.5 – 9.0 дБ`.
- Для згорткових кодів із декодуванням Вітербі (стандарти Wi-Fi 802.11a/g): `Γ ≈ 4.0 – 5.0 дБ`.
- Для сучасних кодів [LDPC (Low-Density Parity-Check)](topic:com-modulation/fec-codes) та полярних кодів (Wi-Fi 6/7, 5G NR): `Γ ≈ 1.5 – 2.5 дБ`.

### Програмна реалізація інженерного калькулятора

Програма розраховує енергетичний бюджет лінії, рівень теплового шуму, відношення `SNR`, теоретичну ємність Шеннона та практичну швидкість для трьох принципово різних сценаріїв:
1. **Wi-Fi 6 (802.11ax)**: робота на частоті 5.18 ГГц у смузі 80 МГц на короткій дистанції в приміщенні з високим `SNR`.
2. **5G NR Sub-6 GHz**: міська стільникова лінія на частоті 3.5 ГГц у смузі 100 МГц на відстані 800 метрів.
3. **LoRa 868 МГц**: енергоефективна лінія Інтернету речей (IoT) на дистанції 10 км у смузі 125 кГц, де сигнал працює глибоко під рівнем шуму (`SNR < 0 дБ`).

```c
#include <stdio.h>
#include <math.h>

typedef struct {
    const char* name;
    double freq_hz;        // несуча частота, Гц
    double bandwidth_hz;   // ширина смуги B, Гц
    double tx_power_dbm;   // потужність передавача P_tx, дБм
    double tx_gain_dbi;    // коефіцієнт підсилення антени передавача G_tx, дБі
    double rx_gain_dbi;    // коефіцієнт підсилення антени приймача G_rx, дБі
    double path_loss_db;   // сумарні втрати сигналу на трасі, дБ
    double noise_fig_db;   // коефіцієнт шуму приймача NF, дБ
    double shannon_gap_db; // розрив Шеннона для вибраного типу FEC, дБ
} LinkParams;

typedef struct {
    double noise_floor_dbm; // поріг шуму у смузі, дБм
    double rx_power_dbm;    // потужність сигналу на вході приймача, дБм
    double snr_db;          // відношення сигнал/шум, дБ
    double snr_linear;      // відношення сигнал/шум у лінійній шкалі (рази)
    double capacity_bps;    // теоретична ємність за Шенноном, біт/с
    double practical_bps;   // практично досяжна швидкість, біт/с
    double spectral_eff;    // спектральна ефективність, біт/с/Гц
} LinkResult;

LinkResult calculate_link_capacity(const LinkParams* link) {
    LinkResult res;
    // Спектральна густина теплового шуму при 290 К: -174.0 дБм/Гц
    const double thermal_density_dbm = -174.0;
    
    // 1. Повний рівень шуму у смузі: N_total = -174 + 10*log10(B) + NF
    res.noise_floor_dbm = thermal_density_dbm + 10.0 * log10(link->bandwidth_hz) + link->noise_fig_db;
    
    // 2. Потужність сигналу на приймачі: P_rx = P_tx + G_tx + G_rx - PathLoss
    res.rx_power_dbm = link->tx_power_dbm + link->tx_gain_dbi + link->rx_gain_dbi - link->path_loss_db;
    
    // 3. Відношення сигнал/шум
    res.snr_db = res.rx_power_dbm - res.noise_floor_dbm;
    res.snr_linear = pow(10.0, res.snr_db / 10.0);
    
    // 4. Теоретична ємність Шеннона: C = B * log2(1 + SNR)
    res.capacity_bps = link->bandwidth_hz * (log(1.0 + res.snr_linear) / log(2.0));
    res.spectral_eff = res.capacity_bps / link->bandwidth_hz;
    
    // 5. Практична швидкість із розривом Гапа Gamma
    double gap_linear = pow(10.0, link->shannon_gap_db / 10.0);
    res.practical_bps = link->bandwidth_hz * (log(1.0 + res.snr_linear / gap_linear) / log(2.0));
    
    return res;
}

void print_link_report(const LinkParams* p, const LinkResult* r) {
    printf("====================================================\n");
    printf("Сценарій: %s\n", p->name);
    printf("----------------------------------------------------\n");
    printf("  Частота / смуга:       %.2f ГГц / %.2f МГц\n", p->freq_hz / 1e9, p->bandwidth_hz / 1e6);
    printf("  Рівень шуму N_total:   %.2f дБм\n", r->noise_floor_dbm);
    printf("  Прийнятий сигнал P_rx: %.2f дБм\n", r->rx_power_dbm);
    printf("  Відношення SNR:        %.2f дБ (x%.3f)\n", r->snr_db, r->snr_linear);
    printf("  Спектральна ефективн.: %.2f біт/с/Гц\n", r->spectral_eff);
    printf("  Ємність Шеннона C:     %.2f Мбіт/с\n", r->capacity_bps / 1e6);
    printf("  Практична швидкість:   %.2f Мбіт/с (розрив %.1f дБ)\n\n", 
           r->practical_bps / 1e6, p->shannon_gap_db);
}

            .rx_gain_dbi = 3.0,
            .path_loss_db = 68.0,
            .noise_fig_db = 6.0,
            .shannon_gap_db = 2.0 // сучасний LDPC код
        },
        {

            .freq_hz = 3.5e9,
            .bandwidth_hz = 100.0e6,
            .tx_power_dbm = 43.0,
            .tx_gain_dbi = 15.0,
            .rx_gain_dbi = 0.0,
            .path_loss_db = 112.0,
            .noise_fig_db = 7.0,
```

```python
    name: str
    freq_hz: float        # несуча частота, Гц
    bandwidth_hz: float   # ширина смуги B, Гц
    tx_power_dbm: float   # потужність передавача P_tx, дБм
    tx_gain_dbi: float    # коефіцієнт підсилення антени передавача G_tx, дБі
    rx_gain_dbi: float    # коефіцієнт підсилення антени приймача G_rx, дБі
    path_loss_db: float   # втрати сигналу на трасі, дБ
    noise_fig_db: float   # коефіцієнт шуму приймача NF, дБ
    shannon_gap_db: float # розрив Шеннона для коду, дБ

@dataclass(frozen=True)
class LinkResult:
    noise_floor_dbm: float # поріг шуму, дБм
    rx_power_dbm: float    # потужність сигналу на вході приймача, дБм
    snr_db: float          # відношення сигнал/шум, дБ
    snr_linear: float      # відношення сигнал/шум у лінійній шкалі
    capacity_bps: float    # теоретична ємність за Шенноном, біт/с
    practical_bps: float   # практично досяжна швидкість, біт/с
    spectral_eff: float    # спектральна ефективність, біт/с/Гц

def calculate_link(link: LinkParams) -> LinkResult:
    thermal_density_dbm = -174.0  # спектральна густина теплового шуму при T = 290 K
    
    # 1. Повний рівень шуму у смузі: N_total = -174 + 10*log10(B) + NF
    noise_floor = thermal_density_dbm + 10.0 * math.log10(link.bandwidth_hz) + link.noise_fig_db
    
    # 2. Потужність на приймачі: P_rx = P_tx + G_tx + G_rx - PathLoss
    rx_power = link.tx_power_dbm + link.tx_gain_dbi + link.rx_gain_dbi - link.path_loss_db
    
    # 3. Відношення сигнал/шум
    snr_db = rx_power - noise_floor
    snr_lin = 10.0 ** (snr_db / 10.0)
    
    # 4. Теоретична ємність за Шенноном: C = B * log2(1 + SNR)
    capacity = link.bandwidth_hz * math.log2(1.0 + snr_lin)
    spectral_eff = capacity / link.bandwidth_hz
    
    # 5. Практична швидкість із розривом Гапа Gamma
    gap_lin = 10.0 ** (link.shannon_gap_db / 10.0)
    practical = link.bandwidth_hz * math.log2(1.0 + snr_lin / gap_lin)
    
    return LinkResult(
        noise_floor_dbm=noise_floor,
        rx_power_dbm=rx_power,
        snr_db=snr_db,
        snr_linear=snr_lin,
        capacity_bps=capacity,
        practical_bps=practical,
        spectral_eff=spectral_eff
    )

if __name__ == '__main__':
    scenarios = [
        LinkParams("Wi-Fi 6 (802.11ax, 5 ГГц, кімната 5 м)", 5.18e9, 80e6, 20.0, 3.0, 3.0, 68.0, 6.0, 2.0),
        LinkParams("5G NR (Sub-6 GHz, міська забудова 800 м)", 3.5e9, 100e6, 43.0, 15.0, 0.0, 112.0, 7.0, 2.0),
        LinkParams("LoRa (868 МГц, дальній лінк IoT 10 км)", 868e6, 125e3, 14.0, 2.0, 2.0, 140.0, 5.0, 1.5),
    ]
    
    for sc in scenarios:
        res = calculate_link(sc)
        print("====================================================")
        print(f"Сценарій: {sc.name}")
        print("----------------------------------------------------")
        print(f"  Частота / смуга:       {sc.freq_hz / 1e9:.2f} ГГц / {sc.bandwidth_hz / 1e6:.2f} МГц")
        print(f"  Рівень шуму N_total:   {res.noise_floor_dbm:.2f} дБм")
        print(f"  Прийнятий сигнал P_rx: {res.rx_power_dbm:.2f} дБм")
        print(f"  Відношення SNR:        {res.snr_db:.2f} дБ (x{res.snr_linear:.3f})")
        print(f"  Спектральна ефективн.: {res.spectral_eff:.2f} біт/с/Гц")
        print(f"  Ємність Шеннона C:     {res.capacity_bps / 1e6:.2f} Мбіт/с")
        print(f"  Практична швидкість:   {res.practical_bps / 1e6:.2f} Мбіт/с (розрив {sc.shannon_gap_db:.1f} дБ)\n")
```

### Інженерний аналіз граничних випадків та неідеальностей апаратури

Отримані в результаті моделювання цифри демонструють, як теоретичні формули стикаються з фізичними обмеженнями кремнієвих трансиверів та антених систем:

1. **Запас на завмирання (Fade Margin) та надійність доступності**:
   У бездротових каналах через рух об'єктів виникає інтерференція хвиль, що призводить до швидких релеївських завмирань (Rayleigh fading), глибина яких може сягати 20–30 дБ. Якщо середнє відношення `SNR` становить `+20 дБ`, це не означає, що канал працюватиме постійно. Для забезпечення доступності каналу 99.9% часу інженер закладає запас на завмирання `Fade Margin` близько `15–20 дБ`, що зменшує розрахункову швидкість для гарантованого трафіку.

2. **Фазовий шум гетеродинів та поріг EVM**:
   Для підтримки надвисоких порядків модуляції (1024-QAM та 4096-QAM у Wi-Fi 7) критичним фактором стає фазовий джиттер локальних генераторів (PLL). Фазовий шум дисперсії `σ_φ²` накладає жорстку стелю на максимальне відношення сигнал/шум системи: `SNR_max ≈ 1 / σ_φ²`. Навіть якщо потужність передавача нескінченно велика, фазовий шум не дозволяє розрізнити 4096 точок сузір'я, якщо коефіцієнт похибки модуляції (EVM) перевищує `-38 дБ` (1.25%).

3. **Пік-фактор (PAPR) та лінійність підсилювачів потужності**:
   Багаточастотні сигнали OFDM з тисячами піднесучих мають нормальний розподіл амплітуди, через що відношення пікової потужності до середньої (англ. *Peak-to-Average Power Ratio*, PAPR) сягає 10–12 дБ. Щоб уникнути нелінійного обмеження верхівок радіохвиль та викривлення сузір'я QAM, вихідний підсилювач потужності (PA) змушений працювати зі значним зниженням середньої потужності (англ. *Power Back-off* на 6–9 дБ). Це зменшує коефіцієнт корисної дії передавача (PAE) до 15–25%, перетворюючи більшу частину енергії батареї на тепло.

4. **Механізм декодування LDPC та м'які рішення (Soft LLR)**:
   Приймач не просто ухвалює жорстке рішення «0» або «1» для кожного біта. Демодулятор обчислює логарифмічне відношення правдоподібності (англ. *Log-Likelihood Ratio*, LLR):

```
LLR(yᵢ) = ln( P(yᵢ | xᵢ = +1) / P(yᵢ | xᵢ = -1) ) = (2 / σ²) · yᵢ
```

   Ці неперервні дійсні числа передаються на граф Таннера ітеративного LDPC-декодера, де алгоритм поширення довіри (Belief Propagation) обмінюється ймовірностями між вузлами змінних та вузлами перевірок. Використання «м'якої» інформації скорочує розрив до межі Шеннона на додаткові 2.0 дБ порівняно з жорсткими схемами декодування.

### Міліметрові хвилі (mmWave 24–71 ГГц) та суб-терагерцові лінії

При переході у високочастотні діапазони міліметрових хвиль (діапазони FR2 у 5G NR: 28 ГГц, 39 ГГц, 60 ГГц) характер енергетичного бюджету різко змінюється через специфіку поширення хвиль в атмосфері:

1. **Атмосферне поглинання газами (модель ITU-R P.676)**:
   Молекули кисню `O₂` мають резонансний пік поглинання на частоті `60 ГГц`, що створює додаткове згасання близько `15 дБ/км`. З одного боку, це обмежує радіус дії безліцензійних мереж WiGig (802.11ad/ay) межами однієї кімнати, але з іншого боку — дозволяє багаторазово повторно використовувати ті самі частоти у сусідніх приміщеннях без взаємних завад. На частотах 28 ГГц та 39 ГГц діють «вікна прозорості» з поглинанням менше ніж `0.1 дБ/км`.

2. **Згасання у гідрометеорах (дощ, туман за ITU-R P.838)**:
   Довжина хвилі на частотах 30–80 ГГц стає сумірною з розміром крапель дощу (1–5 мм), що викликає сильне розсіювання електромагнітної енергії. Питоме згасання під час сильної зливи (інтенсивність опадів `50 мм/год`) сягає `10–25 дБ/км`. Для компенсації таких раптових втрат міліметрові радіорелейні лінії зв'язку використовують динамічне адаптивне перемикання модуляції: під час ясної погоди лінія працює в режимі 1024-QAM, а під час грози миттєво перемикається на QPSK, запобігаючи аварійному розриву зв'язку.

3. **Фазовані антенні решітки та діаграмоутворення (Beamforming)**:
   Оскільки довжина хвилі міліметрового діапазону становить лише кілька міліметрів (`λ = c / f ≈ 5 мм` при 60 ГГц), на мікросхемі площею в кілька квадратних сантиметрів розміщують фазовані антенні решітки з сотнями випромінювальних елементів. Синхронне керування фазозсувачами концентрує випромінювання у вузький промінь із коефіцієнтом підсилення `G_array = 10 · log₁₀(N_elements) дБі`. Це дозволяє компенсувати високе згасання у вільному просторі та забезпечити гігабітні швидкості на дистанціях у кілька сотень метрів.

4. **Нумерологія піднесучих OFDM у 5G NR**:
   На високих частотах фазовий шум генераторів значно зростає. Щоб запобігти взаємному перекриттю піднесучих через фазовий джиттер, стандарт 5G NR масштабує відстань між піднесучими за експоненційним законом `Δf = 15 · 2^μ кГц`:
   - `μ = 0`: `Δf = 15 кГц` (класичний діапазон Sub-1 GHz, FDD).
   - `μ = 1`: `Δf = 30 кГц` (середній діапазон C-band 3.5 ГГц).
   - `μ = 2`: `Δf = 60 кГц` (високошвидкісні сценарії).
   - `μ = 3`: `Δf = 120 кГц` (міліметровий діапазон FR2 28/39 ГГц).
   - `μ = 4`: `Δf = 240 кГц` (служебні канали синхронізації SSB на mmWave).

### Тіньові завмирання та супутникові лінії LEO/GEO

Під час планування покриття стільникових мереж великі перешкоди (пагорби, хмарочоси) викликають повільні варіації потужності сигналу — логнормальні тіньові завмирання (англ. *shadow fading*) зі стандартним відхиленням `σ_shadow ≈ 6 – 10 дБ`. Імовірність аварійного обриву зв'язку (англ. *outage probability*) на краю стільника обчислюється через інтеграл помилок Гаусса:

```
P_outage = Q( (P_rx_avg - P_sens) / σ_shadow )
```

У супутникових мережах зв'язку проявляється фундаментальна відмінність між низькоорбітальними сузір'ями (LEO, такими як Starlink на висоті 550 км) та геостаціонарними супутниками (GEO на висоті 35 786 км):
- **Геостаціонарні супутники (GEO)**: через величезну відстань згасання у вільному просторі досягає `FSPL ≈ 210 дБ` у Ka-діапазоні (30 ГГц), а затримка поширення сигналу становить `RTT ≈ 500 – 600 мс`. Станція повинна використовувати великі параболічні дзеркала діаметром 1–2 метри для компенсації втрат.
- **Низькоорбітальні супутники (LEO)**: відстань скорочується у 60 разів, що зменшує `FSPL` на `35 дБ` і знижує затримку до `RTT ≈ 25 – 35 мс`. Проте орбітальна швидкість супутника `v ≈ 7.5 км/с` породжує гігантський доплерівський зсув частоти `Δf_D = f_c · (v / c) ≈ ±60 кГц` на частоті 28 ГГц. Для збереження шеннонівської ємності приймач повинен кожні кілька мікросекунд коригувати фазу й частоту гетеродина за допомогою цифрових петель ФАПЧ.

### Розрахунок розміру транспортного блоку (TBS) у 5G NR

У стільникових мережах 5G NR передача даних здійснюється транспортними блоками (англ. *Transport Blocks*, TB). Процедура обчислення розміру блоку `TBS` (стандарт 3GPP TS 38.214) базується на виділених ресурсних блоках та шеннонівській спектральній ефективності:

1. **Кількість ресурсних елементів у слоті**:
   Кожен ресурсний блок (PRB) містить 12 піднесучих на 14 OFDM-символів у слоті (сумарно 168 елементів RE). Від цієї кількості віднімаються опорні сигнали DMRS (`N_DMRS ≈ 24..36 RE`) та службові захисні поля `N_oh`:

```
N_RE' = 12 · 14 - N_DMRS - N_oh    [кількість доступних RE на один PRB]
N_RE_total = min(156, N_RE') · N_PRB    [сумарне число RE у виділеній смузі]
```

2. **Проміжна кількість інформаційних бітів**:
   За таблицею MCS обирається порядок модуляції `Q_m` (наприклад, `Q_m = 8` для 256-QAM) та цільова швидкість LDPC-кодування `R = targetCodeRate / 1024`:

```
N_info = N_RE_total · Q_m · R
```

3. **Квантування та вибір графа LDPC**:
   Якщо `N_info ≤ 3824`, використовується базовий граф LDPC BG2 (призначений для малих блоків даних); якщо `N_info > 3824`, обирається базовий граф BG1 (великі високошвидкісні блоки з довжиною сегмента до `K_cb = 8448` бітів). Кінцевий розмір `TBS` округлюється до найближчого допустимого табличного значення за формулою квантування `TBS = 8 · C · ⌈(N_info + 24) / (8 · C)⌉ - 24`, де `C` — кількість LDPC-сегментів.

### Циклічний префікс (Cyclic Prefix) та захист від інтерференції

У багатопроменевому каналі сигнали із затримкою викликають міжсимвольну інтерференцію (ISI) та руйнують ортогональність піднесучих OFDM (ICI). Для усунення цього ефекту на початку кожного OFDM-символу додається копія його закінчення — **циклічний префікс** (англ. *Cyclic Prefix*, CP).

Тривалість циклічного префікса `T_cp` повинна перевищувати максимальну затримку відбитих променів у каналі (`T_cp > τ_max`). У стандарті 5G NR при `Δf = 30 кГц` тривалість корисного символу становить `T_data = 1 / Δf ≈ 33.33 мкс`, а тривалість нормального циклічного префікса — `T_cp ≈ 2.34 мкс`.

Циклічний префікс перетворює лінійну згортку сигналу з імпульсною характеристикою середовища на циклічну згортку. Завдяки дискретному перетворенню Фур'є (FFT) у приймачі частотно-селективний матричний канал діагоналізується, перетворюючись на набір простих паралельних неколізійних скалярних множень `Y_k = H_k · X_k + Z_k`. Платою за цю ідеальну ортогоналізацію є енергетичні та часові втрати ємності:

```
η_CP = T_data / (T_data + T_cp) = 33.33 / (33.33 + 2.34) ≈ 93.4%
```

Ці 6.6% втрат є ціною захисту від спотворень, яка дозволяє витягувати понад 90% теоретичної ємності Шеннона в найскладніших урбаністичних середовищах.

### Від фізичної ємності до корисної швидкості мережі (Goodput)

Обчислена за формулою Шеннона величина `C` є теоретичною швидкістю передачі безперервного потоку бітів на рівні фізичного середовища (L1 PHY). Реальна корисна швидкість для користувацьких даних (англ. *goodput*) на транспортному рівні TCP/IP завжди нижча через накладні витрати протокольного стека:

- **Синхронізація та захисні інтервали**: преамбули, пілотні піднесучі для оцінки каналу (CSI) та циклічний префікс (Cyclic Prefix) в OFDM для усунення дисперсії займають 10–20% часу кадру.
- **Службові заголовки**: заголовки кадрів Ethernet/Wi-Fi (L2 MAC), пакетів IPv4/IPv6 (L3) та сегментів TCP/UDP (L4) додають 40–80 байтів навантаження на кожен пакет даних.
- **Підтвердження та повторні передачі**: механізми квитування HARQ та ARQ генерують зворотний потік службових пакетів (ACK/NACK), забираючи частину пропускної здатності.

У підсумку реальна корисна швидкість передачі файлів у правильно спроєктованій мережі становить приблизно **75–85%** від розрахованої практичної фізичної швидкості `C_practical`.
