# ⚙️ Програмне обчислення біноміальних коефіцієнтів та комбінацій

Пряме обчислення біноміального коефіцієнта за класичною формулою `C(n, k) = n! / (k! · (n - k)!)` через проміжне знаходження факторіалів на комп'ютері швидко призводить до обчислювального глухого кута. Головна причина полягає у вибуховому зростанні факторіальної функції: вже значення `21!` дорівнює `51 090 942 171 709 440 000`, що перевищує межу діапазону стандартного 64-бітного беззнакового цілого типу `uint64_t` (`18.4 × 10¹⁸`). При цьому підсумкове значення коефіцієнта `C(21, 10) = 352 716` є порівняно невеликим і без проблем вміщується навіть у 32-бітне ціле число.

Цей парадокс вимагає застосування спеціалізованих числових алгоритмів, які запобігають проміжному переповненню та забезпечують високу швидкість обчислень. Нижче наведено детальний аналіз трьох основних підходів: мультиплікативного методу скасування множників, динамічного програмування за трикутником Паскаля та оптимізованого алгоритму обчислення комбінацій за модулем простого числа з використанням Малої теореми Ферма та теореми Люка.

### 1. Мультиплікативний алгоритм O(k) без проміжного переповнення

#### Математичне обґрунтування та порядок операцій

Замість обчислення окремих великих факторіалів чисельника та знаменника, вираз `C(n, k)` подають у вигляді послідовного добутку `k` дробових співмножників:

```
C(n, k) = ∏ᵢ₌₁ᵏ (n - k + i) / i = [ (n - k + 1) / 1 ] · [ (n - k + 2) / 2 ] · … · [ n / k ]
```

Для мінімізації кількості ітерацій спочатку застосовують властивість симетрії біноміальних коефіцієнтів: якщо `k > n - k`, ми замінюємо `k` на `n - k`. Це гарантує, що кількість множень і ділень не перевищуватиме `n / 2`.

Головне математичне питання полягає у тому, чи можна виконувати ділення на `i` безпосередньо під час обчислення циклу у цілочисельній арифметиці без виникнення остачі та дробової частини?

Відповідь є ствердною. Розглянувши проміжний добуток перших `i` кроків циклу:

```
Pᵢ = ∏ⱼ₌₁ⁱ (n - k + j) = (n - k + 1) · (n - k + 2) · … · (n - k + i)
```

ми бачимо, що `Pᵢ` являє собою добуток `i` послідовних цілих чисел. За фундаментальною властивістю цілих чисел, добуток будь-яких `i` послідовних цілих чисел **завжди без остачі ділиться на i!**. Отже, після множення поточного акумулятора на `(n - k + i)` результат гарантовано ділиться на `i` націло.

Завдяки цьому ми виконуємо операції за схемою `res = (res * (n - k + i)) / i` повністю у цілочисельних типах даних.

#### Граничні можливості 64-бітної арифметики

Хоча мультиплікативний метод запобігає обчисленню факторіалів, проміжний добуток `res * (n - k + i)` усе ж може викликати переповнення 64-бітного регістра, якщо підсумковий біноміальний коефіцієнт `C(n, k)` наближається до `2⁶⁴ - 1`. Для беззнакового типу `uint64_t` максимальним значенням `n`, для якого можна гарантовано обчислити **будь-який** коефіцієнт `C(n, k)` цим методом, є `n = 62` (оскільки `C(62, 31) ≈ 4.65 × 10¹⁸ < 2⁶⁴`). Для `n ≥ 63` серединні коефіцієнти вимагають перевірки на переповнення або використання 128-бітних типів (`__int128` у GCC/Clang).

### 2. Динамічне програмування за трикутником Паскаля O(n·k)

#### Оптимізація використання пам'яті до одного вектору O(k)

У ситуаціях, коли математична система працює у кільці лишків або над алгебраїчною структурою, де операція цілочисельного ділення не визначена або є надто дорогою, коефіцієнти обчислюють за допомогою додавання на основі рекурентності Паскаля:

```
C(i, j) = C(i - 1, j - 1) + C(i - 1, j)
```

Пряма двовимірна таблична реалізація вимагала б створення матриці розміром `n × k`, що потребує `O(n · k)` пам'яті. Проте помітивши, що обчислення `i`-го рядка трикутника Паскаля спирається виключно на елементи `(i - 1)`-го рядка, обсяг необхідної пам'яті можна скоротити до одного одновимірного вектору `dp` довжини `k + 1`.

Головний прийом оптимізації полягає у **зворотному напрямку обходу внутрішнього циклу** (від `j = min(i, k)` до `j = 1`). Чому зворотний обхід є критично важливим?

Якщо оновлювати масив зліва направо (`j = 1 … k`), значення `dp[j - 1]` буде перезаписано новим значенням з поточного `i`-го рядка ще до того, як воно буде використане для обчислення `dp[j]`. Це призведе до повторного врахування доданків та спотворення результатів. При обході справа наліво значення `dp[j - 1]` зберігає значення з попереднього `(i - 1)`-го рядка, що гарантує сувору відповідність тотожності Паскаля.

### 3. Модулярні комбінації C(n, k) mod p за допомогою Малої теореми Ферма

У комбінаторних задачах та олімпіадному програмуванні результати розкладу біномів часто вимагають знайти за модулем великого простого числа `p` (найчастіше `p = 10⁹ + 7` або `p = 998 244 353`).

У кільці лишків `ℤ/pℤ` операція ділення на `k!` еквівалентна множенню на **модулярно-обернений елемент** `(k!)⁻¹ mod p`. За Малою теоремою Ферма, для будь-якого цілого числа `a`, не кратного простому `p`, виконується співвідношення `aᵖ⁻¹ ≡ 1 (mod p)`. Помноживши обидві частини на `a⁻¹`, отримуємо явну формулу для обчислення оберненого елемента:

```
a⁻¹ ≡ aᵖ⁻² (mod p)
```

Отже, модулярний біноміальний коефіцієнт обчислюється як:

```
C(n, k) ≡ n! · (k!)ᵖ⁻² · ((n - k)!)ᵖ⁻² (mod p)
```

#### Лінійне попереднє обчислення за O(N) та відповідь за O(1)

Якщо в програмі потрібно обробляти тисячі запитів `C(n, k) mod p` для різних `n` та `k` до заданого масиву `N`, ми виконуємо попереднє обчислення двох масивів:
1. Масив факторіалів `fact[i] = i! mod p`.
2. Масив обернених факторіалів `invFact[i] = (i!)⁻¹ mod p`.

Замість того щоб обчислювати `invFact[i]` для кожного `i` окремо за допомогою швидкого піднесення до степеня `p - 2` за `O(log p)`, застосовують ефективну лінійну рекурентність справа наліво. Спочатку знаходять обернений факторіал лише для максимального елемента `invFact[N] = (N!)ᵖ⁻² mod p`, а потім рухаються назад за формулою:

```
invFact[i - 1] = invFact[i] · i (mod p)
```

Це дозволяє за час `O(N)` підготувати всі масиви і надалі відповідати на будь-який запит `C(n, k) mod p` за точний час **O(1)**.

### 4. Теорема Люка для гігантських параметрів n та k (n, k ≥ p)

Якщо значення `n` та `k` перевищують просте число `p` (наприклад, `n = 10¹⁸`, а модуль `p = 10⁵`), масив факторіалів неможливо розмістити в пам'яті, і для багатьох значень `n!` виявиться `n! ≡ 0 (mod p)`.

Для розв'язання цієї проблеми застосовують **теорему Люка** (англ. *Lucas' Theorem*). Записують `n` та `k` у `p`-арній системі числення:

```
n = n₀ + n₁·p + n₂·p² + … + nₘ·pᵐ
k = k₀ + k₁·p + k₂·p² + … + kₘ·pᵐ
```

Теорема Люка стверджує, що біноміальний коефіцієнт `C(n, k)` за модулем `p` дорівнює добутку біноміальних коефіцієнтів, обчислених для окремих `p`-арних цифр:

```
C(n, k) ≡ ∏ᵢ₌₀ᵐ C(nᵢ, kᵢ) (mod p)
```

Оскільки кожна цифра `nᵢ` та `kᵢ` строго менша за `p` (`0 ≤ nᵢ, kᵢ < p`), кожен малий коефіцієнт `C(nᵢ, kᵢ)` можна обчислити за допомогою передзавантаженої таблиці факторіалів малого розміру `p`. Якщо для деякої позиції `i` виявиться `kᵢ > nᵢ`, відповідний коефіцієнт `C(nᵢ, kᵢ) = 0`, і увесь добуток `C(n, k)` миттєво дорівнює 0 mod p.

Теорема Люка дозволяє обчислювати біноміальні коефіцієнти для довільно великих 64-бітних цілих чисел `n` та `k` за логарифмічний час `O(p + logₚ n)`.
