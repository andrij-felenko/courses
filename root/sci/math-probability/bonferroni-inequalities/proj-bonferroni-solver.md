# ⚙️ Алгоритмічна реалізація та зрізане обчислення

Практичне обчислення ймовірностей у великих дискретних системах — таких як мережі зв'язку, інтегральні електронні схеми, або булеві ДНФ-формули великої розмірності — вимагає компромісу між точністю та обчислювальними ресурсами. Точна формула принципу включень-виключень вимагає підсумовування `2ⁿ - 1` доданків. Для системи з `n = 50` подій це вимагає обчислення понад `10¹⁵` комбінацій перетинів, що робить точний розрахунок практично неможливим за розумний час.

Нерівності Бонферроні дозволяють розірвати це експоненційне прокляття розмірності. Обробляючи лише перші `k` порядків перетинів, вони знижують обчислювальну складність з експоненційної `O(2ⁿ)` до поліноміальної `O(nᵏ)`. Оскільки для багатьох практичних систем залежності вищих порядків згасають експоненційно, урізання на `k = 2` або `k = 3` надає надзвичайно вузькі межі для ймовірності відмови системи при кардинальному скороченні часу обчислень.

## Алгоритмічна модель та підрахунок сумарних перетинів `Sᵣ`

Для набору `n` подій `A₁, A₂, ..., A♮` алгоритм приймає на вхід:
1. Кількість подій `n` та індивідуальні ймовірності `P(Aᵢ)` для `i = 1 ... n`.
2. Зворотний виклик або оракул для обчислення ймовірності спільного перетину довільної підмножини подій `P(A_{i₁} ∩ A_{i₂} ∩ ... ∩ A_{iᵣ})`.
3. Граничний порядок урізання `k ≤ n`.

Алгоритм послідовно генерує всі `C(n, r)` комбінацій індексів для кожного порядку `r = 1 ... k`, акумулює суми `Sᵣ`, та обчислює поточні верхні та нижні межі Бонферроні.

### Способи генерації комбінацій: Рекурсивний перебір проти алгоритму Госпера

Для генерації всіх підмножин індексів розмірності `r` з множини `{0, 1, ..., n-1}` алгоритми використовують один із двох підходів:

1. **Рекурсивний перебір з поверненням (Backtracking):**
   Алгоритм будує комбінації шляхом поступового заповнення буфера індексів `comb_buf[depth]`. На кожному кроці рекурсії індекс збільшується щонайменше на 1, що гарантує впорядкованість `i₁ < i₂ < ... < iᵣ`. Перевагою підходу є мінімальні витрати пам'яті (`O(k)` стека) та простота реалізації.

2. **Ітеративний алгоритм Госпера (Gosper's Hack):**
   Для малого `r` комбінації можна представляти бітовими масками довжини `n` з `r` встановленими одиничними бітами. Алгоритм Госпера знаходить наступну за лексикографічним порядком маску з такою ж кількістю одиниць за допомогою швидких бітових інструкцій без використання рекурсії. Це забезпечує ідеальну локальність даних у кеші процесора.

### Покрокове простеження обчислення на прикладі системи з 5 серверів

Щоб зрозуміти внутрішню динаміку роботи алгоритму, розглянемо простежену роботу обчислювача для 5 серверів бази даних (`n = 5`). Подією `Aᵢ` є відмова `i`-го сервера протягом доби.

Нехай індивідуальні ймовірності відмови станують:
```
P(A₁) = 0.05,  P(A₂) = 0.04,  P(A₃) = 0.06,  P(A₄) = 0.03,  P(A₅) = 0.05
```

**Крок 1: Обчислення `S₁` (Порядок `r = 1`)**
Алгоритм підсумовує індивідуальні ймовірності за всіма 5 серверами:
```
S₁ = 0.05 + 0.04 + 0.06 + 0.03 + 0.05 = 0.23
```
На даному етапі (`k = 1`, непарний порядок) алгоритм встановлює верхню межу Буля:
```
Upper Bound = 0.23,  Lower Bound = 0.00
Gap = 0.23 - 0.00 = 0.23
```

**Крок 2: Обчислення `S₂` (Порядок `r = 2`)**
Алгоритм рекурсивно генерує `C(5, 2) = 10` парних комбінацій індексів та запитує оракул перетинів:
- `(0, 1)`: `P(A₁ ∩ A₂) = 0.002`
- `(0, 2)`: `P(A₁ ∩ A₃) = 0.003`
- `(0, 3)`: `P(A₁ ∩ A₄) = 0.001`
- `(0, 4)`: `P(A₁ ∩ A₅) = 0.002`
- `(1, 2)`: `P(A₂ ∩ A₃) = 0.002`
- `(1, 3)`: `P(A₂ ∩ A₄) = 0.001`
- `(1, 4)`: `P(A₂ ∩ A₅) = 0.001`
- `(2, 3)`: `P(A₃ ∩ A₄) = 0.002`
- `(2, 4)`: `P(A₃ ∩ A₅) = 0.003`
- `(3, 4)`: `P(A₄ ∩ A₅) = 0.001`

Сума парних перетинів становить:
```
S₂ = 0.002 + 0.003 + 0.001 + 0.002 + 0.002 + 0.001 + 0.001 + 0.002 + 0.003 + 0.001 = 0.018
```
На даному етапі (`k = 2`, парний порядок) алгоритм обчислює нижню межу:
```
Lower Bound = S₁ - S₂ = 0.23 - 0.018 = 0.212
Upper Bound = 0.230
Gap = 0.230 - 0.212 = 0.018
```
Усього за 15 викликів оракула (замість 31 у повному виразі) алгоритм локалізував імовірність аварії у вузькому діапазоні `[0.212, 0.230]` з максимальною помилкою не більше 1.8%.

## Числова стійкість та запобігання втраті значущих розрядів

Під час підсумовування доданків у принципі включень-виключень виникає проблема числової нестійкості (помилка значущості або катастрофічне анулювання). Оскільки значення `Sᵣ` можуть бути дуже великими числами, що чергуються за знаком (`S₁ - S₂ + S₃ - ...`), пряме віднімання близьких за величиною чисел з рухомою крапкою призводить до втрати точних розрядів.

Для нівелювання цієї проблеми в реалізації використовуються два підходи:
1. **Накопичення у подвійній точності (`double` / IEEE 754):** Акумуляція сум `Sᵣ` виконується в окремих змінних підвищеної точності перед їх додаванням чи відніманням від загальної суми.
2. **Монотонне звуження меж:** Для запобігання ситуації, коли через похибки округлення нижня межа стає більшою за верхню, реалізація застосовує функції операторів `std::min` та `std::max` для підтримки монотонності коридору ймовірності `[0.0, 1.0]`.

| Порядок `k` | Оцінка Бонферроні | Кількість доданків `∑_{r=1}ᵏ C(n, r)` | Обчислювальна складність |
| :--- | :--- | :--- | :--- |
| **`k = 1`** | Нерівність Буля (верхня) | 50 | `O(n)` |

| **`k = 4`** | Межа Бонферроні 4-го порядку (нижня) | 251,175 | `O(n⁴)` |

### Оптимізація обчислення `Sᵣ` для випадкових ДНФ-формул через бітові маски

У задачах підрахунку виконання булевих формул у ДНФ (диз'юнктивна нормальна форма) кожна подія `Aᵢ` відповідає події задоволення `i`-го кон'юнкта (диз'юнкта). Для набору диз'юнктів перетин `A_{i₁} ∩ ... ∩ A_{iᵣ}` дорівнює 0, якщо серед них є протилежні літерали (наприклад, `xⱼ` та `¬xⱼ`). 

Алгоритм використовує бітові операції SIMD (AVX2 / AVX-512) для попередньої фільтрації несумісних комбінацій: кожен диз'юнкт кодується двома бітовими масками (маска позитивних літералів `pos_mask` та маска негативних літералів `neg_mask`). Перевірка сумісності двох диз'юнктів виконується однією інструкцією `(clause1.pos_mask & clause2.neg_mask) != 0`. Якщо бітовий перетин не порожній, комбінація миттєво відкидається без виклику дорогої процедури аналізу. Це дозволяє прискорити обчислення `Sᵣ` у десятки разів на розріджених булевих формулах великої розмірності.

## Тестування та моніторинг коректності реалізації

Для перевірки коректності функціонування обчислювача використовується метод синтетичного верифікування на трьох базових імовірнісних моделях:

1. **Модель взаємно диз'юнктних подій (`P(Aᵢ ∩ Aⱼ) = 0`):**
   Алгоритм повинен видавати точну рівність `S₁ = P(⋃ Aᵢ)` вже на першому порядку `k = 1`, а `Sᵣ = 0` для всіх `r ≥ 2`.
2. **Модель повністю незалежних подій однаковості (`P(Aᵢ) = p`):**
   Отримані значення `Sᵣ` порівнюються з теоретичним виразом `C(n, r) · pʳ`. Похибка обчислень не повинна перевищувати машинне машинного округлення `1e-15`.
3. **Модель вкладених подій (`A₁ ⊂ A₂ ⊂ ... ⊂ A♮`):**
   Ймовірність об'єднання тотожно дорівнює `max P(Aᵢ) = P(A♮)`. Перевіряється монотонна збіжність меж Бонферроні до значення `P(A♮)`.
