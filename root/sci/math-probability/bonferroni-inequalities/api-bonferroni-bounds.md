# 📋 Інтерфейс модуля оцінки ймовірносної надійності

Модуль `bonferroni_bounds` надає уніфікований програмний інтерфейс для детермінованого обчислення верхніх та нижніх меж ймовірностей об'єднання складних залежних подій. Його розроблено для прямої інтеграції у високопродуктивні обчислювальні системи: модулі підрахунку модельних рішень у SAT-соловерах (#SAT), системи аналізу виправності та надійності складних графових мереж, а також статичні аналізатори актуарних та фінансових ризиків.

Головна мета інтерфейсу — абстрагувати користувача від складних комбінаторних обчислень та надати просту, числово стійку обгортку, яка приймає оракул ймовірностей перетинів і повертає коридор ймовірностей із підтвердженою високою точністю. Інтерфейс спроектовано з урахуванням суворих вимог до системного програмування: відсутність прихованого динамічного виділення пам'яті під час повторних викликів, повна потокова безпека (thread-safety) та можливість використання як у мові C, так і в сучасних стандартах C++.

## Архітектура та контракт взаємодії

Інтерфейс модуля базується на моделі "Оракул — Акумулятор". Користувач не передає модулю повний граф або матрицю залежностей усіх подій, оскільки для великих систем (`n > 100`) така структура вимагала б експоненційного обсягу пам'яті. Натомість користувач надає вказівник на функцію-зворотний виклик (callback oracle), яка вміє обчислювати ймовірність спільного перетину для довільного заданого набору індексів `P(A_{i₁} ∩ A_{i₂} ∩ ... ∩ A_{iᵣ})`.

Модуль бере на себе всю комбінаторну роботу з генерації підмножин індексів порядку `r = 1 ... k`, накопичення часткових сум `Sᵣ`, обчислення чергових значень нерівностей Бонферроні та контроль числової стійкості (відстеження втрати значущих розрядів при відніманні близьких чисел).

### Життєвий цикл обчислювального процесу та автомат станів

Взаємодія з модулем підпорядковується чіткому автомату станів (State Machine), що гарантує відсутність витоків пам'яті та невизначеної поведінки (Undefined Behavior):

1. **Стан `Uninitialized` (Неініціалізовано):** Пам'ять під структуру результатів та конфігурацію ще не виділена або містить невизначені дані. Користувач викликає `bonferroni_config_init()`.
2. **Стан `Configured` (Сконфігуровано):** Встановлено бажаний порядок `k`, поріг точності `ε` та прапори оптимізації. 
3. **Стан `Computing` (Обчислення):** Головна функція `bonferroni_compute()` рекурсивно або ітеративно здійснює виклики оракула для комбінацій порядків `r = 1 ... k`. На кожному порядку оракул повертає значення перетину, які накопичуються в акумуляторах високої точності.
4. **Стан `Finished` (Завершено успішно):** Усі суми `Sᵣ` обчислено, перевірено монотонність меж і заповнено підсумкову структуру результатів `bonferroni_bounds_t`.
5. **Стан `Freed` (Звільнено):** Користувач викликає `bonferroni_bounds_free()`, що повертає виділену системну пам'ять купі (heap).

### Гарантії потокової безпеки та керування пам'яттю

1. **Відсутність глобального стану:** Усі структури даних та контексти обчислення передаються через параметри функцій. Модуль не використовує статичні чи глобальні змінні, що дозволяє паралельно виконувати обчислення у кількох незалежних потоках виконання.
2. **Контроль виділення пам'яті:** Усі буфери, необхідні для генерації комбінацій та зберігання суміжних сум `Sᵣ`, виділяються єдиним блоком під час ініціалізації розрахунку. Для середовищ із суворими обмеженнями (embedded або real-time) надається функція розрахунку необхідного розміру буфера `bonferroni_required_memory_bytes()`, що дозволяє передати статично виділений масив пам'яті користувача.
3. **Обробка виняткових ситуацій у C++:** Реалізація C++ використовує семантику `std::expected` замість винятків (exceptions), що робить її придатною для критичних систем без підтримки RTTI та unwinding стека.

Нижче наведено декларації публічних інтерфейсів модуля мовами C та C++.

```c
#ifndef BONFERRONI_BOUNDS_H
#define BONFERRONI_BOUNDS_H

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

#ifdef __cplusplus
extern "C" {
#endif

/** Коди помилок виконання модуля */
typedef enum {
    BONFERRONI_OK                   =  0,
    BONFERRONI_ERR_INVALID_PARAM    = -1,
    BONFERRONI_ERR_OUT_OF_MEMORY    = -2,
    BONFERRONI_ERR_ORACLE_FAILURE   = -3,
    BONFERRONI_ERR_PRECISION_LOSS   = -4,
    BONFERRONI_ERR_BUFFER_TOO_SMALL = -5
} bonferroni_error_t;

/** Конфігураційні параметри для обчислення меж */
typedef struct {
    size_t max_order;           /* Максимальний порядок k (1..n) */
    double target_precision;    /* Бажаний допустимий зазор між межами (верхня - нижня) */
    bool enable_early_stop;     /* Зупинка обчислень при досягненні target_precision */
    uint32_t flags;             /* Прапори оптимізації (0 - за замовчуванням) */
} bonferroni_config_t;

/** Результат обчислення меж Бонферроні */
typedef struct {
    double upper_bound;         /* Оцінка зверху P(⋃ Aᵢ) <= upper_bound */
    double lower_bound;         /* Оцінка знизу P(⋃ Aᵢ) >= lower_bound */
    double confidence_gap;      /* Поточна різниця (upper_bound - lower_bound) */
    double* s_terms;            /* Масив розрахованих сум S_1, S_2 ... S_k (розмір max_order + 1) */
    size_t evaluated_order;     /* Фактично обчислений порядок k */
    bonferroni_error_t status;  /* Статус завершення */
} bonferroni_bounds_t;

/** Сигнатура оракула обчислення перетинів */
typedef double (*bonferroni_oracle_fn)(const size_t* event_indices, size_t count, void* context);

/**
 * Ініціалізація структури конфігурації за замовчуванням.
 */
void bonferroni_config_init(bonferroni_config_t* cfg);

/**
 * Обчислення обсягу оперативної пам'яті (у байтах), необхідного для виконання
 * обчислення для n подій та порядку max_k.
 */
size_t bonferroni_required_memory_bytes(size_t event_count, size_t max_k);

/**
 * Головна функція розрахунку меж Бонферроні.
 * 
 * @param event_count  Загальна кількість подій n (n >= 1)
 * @param oracle       Вказівник на функцію-оракул перетинів
 * @param context      Користувацький контекст для оракула
 * @param cfg          Конфігурація (якщо NULL, використовуються параметри за замовчуванням)
 * @param out_bounds   Вказівник на вихідну структуру результатів
 * @return BONFERRONI_OK у разі успіху, або код помилки
 */
bonferroni_error_t bonferroni_compute(
    size_t event_count,
    bonferroni_oracle_fn oracle,
    void* context,
    const bonferroni_config_t* cfg,
    bonferroni_bounds_t* out_bounds
);

/**
 * Звільнення ресурсів, виділених під структуру результатів.
 */
void bonferroni_bounds_free(bonferroni_bounds_t* bounds);

#ifdef __cplusplus
}
#endif

#endif /* BONFERRONI_BOUNDS_H */
```

```cpp
#ifndef BONFERRONI_BOUNDS_HPP
#define BONFERRONI_BOUNDS_HPP

#include <vector>
#include <functional>
#include <span>
#include <expected>
#include <system_error>

namespace bonferroni {

enum class ErrorCode {
    InvalidParameter = 1,
    OutOfMemory,
    OracleFailure,
    PrecisionLoss,
    BufferTooSmall
};

std::error_code make_error_code(ErrorCode ec);

struct Config {
    size_t maxOrder{2};
    double targetPrecision{1e-5};
    bool autoEarlyStop{true};
};

struct BoundsResult {
    double upperBound{1.0};
    double lowerBound{0.0};
    std::vector<double> sTerms;
    size_t evaluatedOrder{0};

    [[nodiscard]] double gap() const noexcept {
        return upperBound - lowerBound;
    }
};

using OracleFunction = std::function<double(std::span<const size_t>)>;

class Evaluator {
public:
    explicit Evaluator(Config config = {}) : config_(config) {}

    [[nodiscard]] std::expected<BoundsResult, ErrorCode> compute(
        size_t eventCount, 
        const OracleFunction& oracle
    ) const;

private:
    Config config_;
};

} // namespace bonferroni

#endif /* BONFERRONI_BOUNDS_HPP */
```

## Детальний опис параметрів та семантики викликів

Поведінка модуля розрахунку регулюється набором конфігураційних параметрів, які встановлюють компроміс між точністю та витратами процесорного часу.

### Основні параметри керування:

1. **`event_count` / `eventCount` (`size_t`):**
   Кількість індивідуальних подій `n` у системі. Повинна бути не меншою за 1. Якщо `n = 1`, модуль відразу повертає значення ймовірності `P(A₁)`, отримане від оракула, для обох меж (`upper_bound = lower_bound = P(A₁)`).

2. **`max_order` / `maxOrder` (`size_t`):**
   Граничний порядок truncation `k`. Визначає, що модуль обчислюватиме суми перетинів `Sᵣ` лише для `r = 1, 2, ..., k`. Якщо значення `k > n`, воно автоматично зменшується до `n`. Значення `k = 1` відповідає нерівності Буля (верхня межа), `k = 2` надає другу нерівність Бонферроні (нижня межа), `k = 3` додає третій порядок (покращена верхня межа) і так далі.

3. **`target_precision` (`double`):**
   Допустима ширина інтервалу невизначеності `ε = upper_bound - lower_bound`. Якщо в процесі підраховування на черговому кроці `r` різниця між поточними верхньою та нижньою межами стає меншою за `ε`, алгоритм перериває обчислення раніше досягнення `max_order`, заощаджуючи процесорний час.

4. **`oracle` (`bonferroni_oracle_fn` / `OracleFunction`):**
   Функція зворотного виклику, яка приймає масив індексів подій розмірності `r` і повертає значення `P(A_{i₁} ∩ ... ∩ A_{iᵣ})`. Масив індексів завжди відсортований за зростанням (`i₁ < i₂ < ... < iᵣ`). Якщо оракул не здатний обчислити ймовірність для даної комбінації, він повинен повернути від'ємне значення (наприклад, `-1.0`), що слугує сигналом для модуля згенерувати помилку `BONFERRONI_ERR_ORACLE_FAILURE`.

## Детальна семантика повернення кодових статусів та крайових випадків

Модуль надає суворі гарантії відносно крайових та аномальних обчислювальних ситуацій:

1. **Корекція числової немонотонності (`BONFERRONI_ERR_PRECISION_LOSS`):**
   У випадку опрацювання довгого ряду доданків `Sᵣ` з великим `k` накопичення похибок округлення стандарту IEEE 754 може призвести до того, що нижня оцінка обчислення стане трохи більшою за верхню оцінку (`lower_bound > upper_bound`). При виявленні цієї аномалії модуль примусово коригує `lower_bound = upper_bound`, записує у результат поточну різницю і повертає статус `BONFERRONI_ERR_PRECISION_LOSS`.

2. **Гарантія коридору `[0.0, 1.0]`:**
   Оскільки нерівності перших порядків (наприклад, нерівність Буля `S₁`) можуть давати суму ймовірностей, що перевищує `1.0`, модуль автоматично обрізає значення верхньої межі за порогом `1.0`. Аналогічно, якщо оцінка другого порядку `S₁ - S₂` стає від'ємною через високу парну корельованість подій, нижня межа автоматично обрізається за порогом `0.0`.

3. **Код повернення `BONFERRONI_ERR_OUT_OF_MEMORY`:**
   Виникає виключно при невдачі виділення системної пам'яті під внутрішній комбінаторний буфер. Якщо використовується версія функції з попередньо виділеним користувацьким буфером, ця помилка не виникає ніколи.

4. **Код повернення `BONFERRONI_ERR_INVALID_PARAM`:**
   Повертається у разі передачі переданого нульового вказівника на функцію оракула або при нульовому значенні `n`.

## Рекомендації з інтеграції та сумісності з ABI

Для забезпечення повної сумісності між різними компіляторами (GCC, Clang, MSVC) C-інтерфейс гарантує стандартну C-угоду про виклики (`cdecl`). Усі внутрішні структури даних мають стандартне вирівнювання (alignment) 8 байт для 64-бітних архітектур x86-64 та ARM64.

При використанні модуля в багатопотокових обчислювальних вузлах рекомендується передавати у функцію `bonferroni_compute` унікальний екземпляр контексту `void* context` для кожного потоку, щоб уникнути блокувань (lock contention) при доступі до оракула.
