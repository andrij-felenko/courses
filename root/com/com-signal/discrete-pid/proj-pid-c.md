# ⚙️ Надійний дискретний ПІД на C: структура, крок, захисти

## Задача

Формула ПІД коротка, але «гола» — три члени й нічого більше. У реальній прошивці навколо них стоїть удвічі більше коду: збереження стану між тактами, затиск інтеграла, фільтр похідної, обмеження виходу, скидання при старті. Без цієї обв'язки регулятор красиво виглядає на папері, а в залізі смикається чи перекидає апарат. Мета — один самодостатній модуль на C, який можна викликати з таймерного переривання й бути певним, що жодна з відомих аварій ПІД не станеться: ні розгін інтеграла, ні поштовх похідної від зміни завдання, ні вимога неможливого від мотора, ні стрибок у першу ж секунду.

## Ідея

Регулятор має **пам'ять** — інтеграл і попередній вимір живуть від такту до такту, тож тримати їх у локальних змінних не можна. Складемо весь стан і всі коефіцієнти в одну структуру `PID`, а всю роботу одного такту — в одну функцію `pid_step()`. Параметри (коефіцієнти, межі, стала фільтра) задаємо раз при ініціалізації; далі гаряча функція лише читає вимір і повертає вплив.

Чотири захисти лягають у тіло `pid_step()` у строгому порядку. **Антивіндап** (anti-windup, англ. *wind up* — «накручувати») затискає інтеграл одразу після його оновлення, доки той не просочився у вихід. **Похідну беремо від виміру**, а не від помилки, і згладжуємо її однополюсним фільтром (та сама вправа, що й [ковзне експоненційне середнє](topic:com-signal/ema)). **Вихід** притискаємо до фізичних меж виконавчого органу. **Скидання** обнуляє пам'ять при ввімкненні. Окремо передбачимо чесний **виміряний** крок `dt` як аргумент — щоб навіть за нерівних викликів I та D рахувалися з правильним масштабом часу.

## Код

Спершу структура — увесь стан і вся настройка регулятора в одному місці. Поля з підкресленням-комантарем «стан» переживають виклики; решта — параметри:

```c
#include <stdint.h>

typedef struct {
    /* параметри (задаємо при ініціалізації) */
    float kp, ki, kd;        /* коефіцієнти П, І, Д                       */
    float tau;               /* стала фільтра похідної, с (≈ 1/(2πfc))    */
    float i_min, i_max;      /* межі інтеграла (антивіндап)               */
    float u_min, u_max;      /* межі виходу (фізичні межі виконавчого)    */
    /* стан (живе між тактами) */
    float integral;          /* накопичений інтеграл                      */
    float meas_prev;         /* вимір на попередньому такті               */
    float deriv_f;           /* відфільтрована похідна                    */
} PID;

void pid_init(PID *c, float kp, float ki, float kd, float tau,
              float i_min, float i_max, float u_min, float u_max)
{
    c->kp = kp;  c->ki = ki;  c->kd = kd;  c->tau = tau;
    c->i_min = i_min;  c->i_max = i_max;
    c->u_min = u_min;  c->u_max = u_max;
    c->integral = 0.0f;  c->meas_prev = 0.0f;  c->deriv_f = 0.0f;
}

static inline float clampf(float x, float lo, float hi)
{
    if (x < lo) return lo;
    if (x > hi) return hi;
    return x;
}
```

Тепер гаряча функція. Її викликають **рівномірно** кожні `dt` секунд — найкраще з таймерного переривання; `dt` передаємо як аргумент, щоб у разі нерівних викликів підставити **фактичний** крок, а не номінальний:

:::tabs
```c
float pid_step(PID *c, float setpoint, float meas, float dt)
{
    float e = setpoint - meas;                       /* помилка                      */

    /* I: накопичуємо й ОДРАЗУ затискаємо (антивіндап) */
    c->integral += e * dt;
    c->integral = clampf(c->integral, c->i_min, c->i_max);

    /* D: від виміру (не від помилки) → нема поштовху на зміну завдання */
    float deriv = (c->meas_prev - meas) / dt;        /* = −d(meas)/dt                */
    /* однополюсний ФНЧ на похідну: гасить шумові сплески */
    float a = dt / (dt + c->tau);                    /* 0 < a ≤ 1                    */
    c->deriv_f += (deriv - c->deriv_f) * a;

    /* сума трьох складових */
    float u = c->kp * e + c->ki * c->integral + c->kd * c->deriv_f;

    /* межі виконавчого органу */
    u = clampf(u, c->u_min, c->u_max);

    c->meas_prev = meas;                             /* запам'ятати для наступного   */
    return u;
}

/* скидання стану — викликати при зброєнні/зльоті, перш ніж контур піде в роботу */
void pid_reset(PID *c, float meas)
{
    c->integral = 0.0f;
    c->meas_prev = meas;        /* щоб перша похідна була 0, а не сплеск */
    c->deriv_f = 0.0f;
}
```
```python
def _clamp(x, lo, hi):
    return lo if x < lo else hi if x > hi else x


class PID:
    """Дискретний ПІД зі станом і чотирма захистами (той самий модуль, що на C)."""

    def __init__(self, kp, ki, kd, tau, i_min, i_max, u_min, u_max):
        # параметри (задаємо при ініціалізації)
        self.kp, self.ki, self.kd = kp, ki, kd
        self.tau = tau                    # стала фільтра похідної, с
        self.i_min, self.i_max = i_min, i_max   # межі інтеграла (антивіндап)
        self.u_min, self.u_max = u_min, u_max   # межі виходу (виконавчий орган)
        # стан (живе між тактами)
        self.integral = 0.0               # накопичений інтеграл
        self.meas_prev = 0.0              # вимір на попередньому такті
        self.deriv_f = 0.0                # відфільтрована похідна

    def step(self, setpoint, meas, dt):
        e = setpoint - meas                           # помилка

        # I: накопичуємо й ОДРАЗУ затискаємо (антивіндап)
        self.integral += e * dt
        self.integral = _clamp(self.integral, self.i_min, self.i_max)

        # D: від виміру (не від помилки) → нема поштовху на зміну завдання
        deriv = (self.meas_prev - meas) / dt          # = −d(meas)/dt
        # однополюсний ФНЧ на похідну: гасить шумові сплески
        a = dt / (dt + self.tau)                      # 0 < a ≤ 1
        self.deriv_f += (deriv - self.deriv_f) * a

        # сума трьох складових
        u = self.kp * e + self.ki * self.integral + self.kd * self.deriv_f

        # межі виконавчого органу
        u = _clamp(u, self.u_min, self.u_max)

        self.meas_prev = meas                         # запам'ятати для наступного
        return u

    def reset(self, meas):
        """Скидання стану — при зброєнні/зльоті, перш ніж контур піде в роботу."""
        self.integral = 0.0
        self.meas_prev = meas      # щоб перша похідна була 0, а не сплеск
        self.deriv_f = 0.0
```
:::

Порядок дій тут не випадковий. Інтеграл оновлюємо й затискаємо **до** того, як скласти `u` — інакше роздутий за насичення інтеграл устиг би просочитися у вихід ще цього такту. Похідну рахуємо від `meas`, тож стрибок `setpoint` на неї не впливає взагалі. А `pid_reset` ставить `meas_prev = meas` (а не нуль) — інакше перша ж похідна після ввімкнення була б `(0 − meas)/dt`, тобто фальшивий сплеск.

## Worked-приклад: один такт на 200 Гц

Візьмемо контур кутової швидкості з `kp = 0.8`, `ki = 12`, `kd = 0.02`, сталою фільтра `tau = 0.004` с і періодом `dt = 1/200 = 0.005` с. Нехай завдання `setpoint = 30`°/с, поточний вимір `meas = 24`°/с, попередній `meas_prev = 22`°/с, а накопичений інтеграл уже `integral = 1.5`. Пройдімо `pid_step` по числах:

```
e        = 30 − 24            = 6.0          °/с
integral = 1.5 + 6.0·0.005    = 1.530        (у межах → не затиснуто)
deriv    = (22 − 24)/0.005    = −400         °/с²   (вимір зростає → від'ємна)
a        = 0.005/(0.005+0.004)= 0.5556
deriv_f  = 0 + (−400 − 0)·0.5556 = −222.2          (перший такт: фільтр стартує з 0)
u_П      = 0.8 · 6.0          = 4.800
u_І      = 12  · 1.530        = 18.360
u_Д      = 0.02 · (−222.2)    = −4.444
u        = 4.800 + 18.360 − 4.444 = 18.716
u        = clamp(18.716, −100, 100) = 18.716        (у межах → без зрізу)
```

Видно роль кожного члена: П тягне до завдання пропорційно до помилки (6°/с → +4.8), І додає вже накопичений «борг» (+18.36 — він тут найвагоміший), а Д **гальмує**: вимір росте, тож від'ємна похідна знімає −4.44 і пом'якшує підхід до завдання, гасячи майбутній переліт. Фільтр на першому такті лише наполовину пропустив сирий −400 (множник `a = 0.556`), тож сплеск не вистрелив у вихід повністю — у цьому й суть згладжування.

Якби тут не було затиску виходу, а `u_min/u_max` дорівнювали б, скажімо, ±15, то `clamp(18.716, −15, 15)` дав би рівно `15` — мотор уже на максимумі, і регулятор «розумів» би, що більшого вимагати марно. Саме в такому насиченні антивіндап і рятує: інтеграл не накручувався б далі, поки вихід уперся в межу.

## Складність і пастки на МК

**Вартість — O(1) на такт:** кілька множень, додавань, одне ділення й дві пари порівнянь. На ядрі з апаратною рухомою комою (Cortex-M4/M7, ESP32) це одиниці мікросекунд — мізер супроти решти такту (читання давачів, поєднання). Та характерні граблі варто знати наперед:

- **Забути про стан.** Найтиповіша помилка початківця: зробити `integral` чи `meas_prev` локальною змінною в `pid_step`. Тоді вони обнуляються щотакту, і ні інтеграл, ні похідна просто не працюють. Стан **мусить** жити в структурі (або бути статичним), що переживає виклики.
- **Ділення на dt у похідній.** Якщо `dt` випадково нуль (подвійний виклик в один тік, збій таймера) — поділ на нуль дасть `inf`/`nan`, що отруїть і вихід, і весь подальший стан. Захист: відкинути такт із `dt <= 0` або взяти мінімальний поріг.
- **Плаваючий крок.** Якщо викликати ПІД «коли дійдуть руки» в головному циклі, `dt` гуляє від такту до такту, і навіть з виміряним `dt` шум похідної росте. Найнадійніше — таймерне переривання з точно рівним періодом; виміряний `dt` — рятівний резерв, а не норма.
- **Скидання при ввімкненні.** Не викликати `pid_reset` перед зброєнням — і накопичений за простою інтеграл «вистрелить» апарат у першу ж секунду (різновид windup). Скидати треба в момент переходу контуру в роботу, обов'язково з `meas_prev = meas`.
- **Цілочисельний варіант.** На 8-бітному чипі без FPU `float` повільний, і ПІД переписують на [фіксовану кому](topic:com-signal/fixed-point-implementation). Тоді головна небезпека — переповнення `integral` (єдиний член, що накопичується необмежено): тримати його в широкому типі (32/64 біти) і обов'язково затискати — антивіндап тут рятує одразу від двох бід, накопичувального насичення й арифметичного переповнення.
- **Інкрементна форма як альтернатива.** Цей модуль — класична **позиційна** форма (рахує `u` цілком). Коли виконавчий орган сам інтегрує (кроковий двигун) або потрібне перемикання режимів без ривка, зручніша **інкрементна** форма: рахувати приріст `Δu` за такт і додавати до попереднього виходу; вона має природну стійкість до windup, але потребує власної обережності з межами.

## Підсумок

Робочий дискретний ПІД на C — це структура зі станом плюс одна гаряча функція з чотирма захистами в правильному порядку: накопичити й **одразу затиснути** інтеграл, узяти похідну **від виміру** й **відфільтрувати** її, скласти три члени, **обмежити** вихід, запам'ятати вимір. Окрема `pid_reset` обнуляє пам'ять при старті. Саме ця обв'язка, а не сама формула, відрізняє регулятор, що впевнено тримає апарат, від того, що смикається; тому закладають її **наперед**, не чекаючи, поки кожна з відомих аварій дасться взнаки.
