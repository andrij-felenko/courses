# ⚙️ Один сигнал, два фільтри: коефіцієнт K сходиться до 1−α

Комплементарний фільтр і фільтр Калмана в усталеному режимі — це **той самий** фільтр; ця вставка доводить рівність не алгеброю, а числами: синтезуємо один шумний сигнал IMU, женемо його крізь обидва фільтри й друкуємо, як коефіцієнт Калмана K щотакту сходиться **рівно** до 1−α, аж поки дві оцінки не збіжаться до останнього знака. Мова — C: злиття кутів живе в гарячому такті мікроконтролера, де рахують саме нею.

<preknowlist>
- [Фільтр Калмана](root:com-signal/kalman-filter) — цикл predict/update: передбачення штовхає оцінку й **розширює** дисперсію P, оновлення зважує вимір коефіцієнтом K = P⁻/(P⁻+R) і **стягує** P.
- [Комплементарний фільтр](root:com-signal/complementary-filter) — один рядок θ = α·(θ+ω·dt) + (1−α)·z із наперед заданим α десь коло 0.98–0.99.
- [Нормальний розподіл](root:math-probability/normal-distribution) — шум акселерометра беремо гаусовим, N(0, σ²); σ = 3° означає дисперсію R = σ² = 9.
- [Середнє й дисперсія](root:math-probability/mean-variance) — Q і R у фільтрі це **дисперсії** (розкид у квадраті одиниці), і плутанина з їхніми одиницями — головна практична пастка.
</preknowlist>

## Задача

Один синтетичний сигнал, два фільтри, три числа на виході.

Сигнал беремо чесний до давачів. Істинний кут θ(t) гладко коливається. Гіроскоп віддає **істинну кутову швидкість плюс сталий зсув нуля** — саме той зсув, що потім розповзається в дрейф. Акселерометр віддає **істинний кут плюс гаусів шум**. Обидва фільтри годуємо тим самим потоком — інакше порівняння втрачає сенс.

Фільтри:

1. **комплементарний** з фіксованим α;
2. **скалярний Калман**: predict `θ += ω·dt; P += Q`, update `K = P⁻/(P⁻+R); θ += K·(z−θ); P = (1−K)·P⁻`.

Показати числом три речі: (1) K сходиться до сталого K_∞; (2) K_∞ = 1−α буква в букву; (3) при α = 1−K_∞ обидві оцінки на тому самому сигналі однакові до похибки заокруглення. Числа — того самого режиму, що й у теорії: dt = 0.01 c (100 Гц), Q = 0.001, R = 9.

## Ідея

Ключ — у тому, **від чого залежить K**. Гляньте на його рекурсію: `P⁻ = P + Q`, `K = P⁻/(P⁻+R)`, `P = (1−K)·P⁻`. У ній немає жодного виміру z, жодної швидкості ω — самі лише P, Q, R. Отже, **розклад коефіцієнта K по тактах не залежить від даних узагалі**: він визначений наперед, щойно ви обрали Q, R і початкову дисперсію P₀. Це й є та машинерія, яку комплементарний фільтр «заморожує»: якщо K однаково сходиться до K_∞ хоч на якому сигналі, його можна порахувати раз — і вписати як α = 1−K_∞.

> 🔧 **Навіщо це.** Те, що розклад K не залежить від вимірів, — не курйоз, а інженерний важіль. Гейн можна порахувати **офлайн**, ще до польоту, і зашити готовим числом K_∞, зовсім прибравши ділення з гарячого такту. Саме цим і є комплементарний фільтр: Калман, у якого розв'язок рекурсії дисперсії винесено за межі реального часу. Коли режим сталий, «дорогий» фільтр і «дешевий» — це та сама арифметика, лише порахована в різні моменти.

Звідси й план перевірки. Спершу проженемо саму лише рекурсію дисперсії, **без сигналу**, і подивимось, як K падає від майже одиниці (нічого не знаємо про кут — жадібно віримо першим вимірам) до K_∞. Тоді візьмемо це K_∞, покладемо α = 1−K_∞ і проженемо **той самий** шумний сигнал крізь обидва фільтри, стартувавши з однакового кута. Якщо тотожність правдива, різниця оцінок має лежати на рівні машинного нуля — не «близько», а до чотирнадцятого знака.

## Робочий код

```c
#include <stdio.h>
#include <math.h>
#include <stdint.h>

#define PI   3.14159265358979323846
#define DT   0.01     /* крок, с (100 Гц)                */
#define Q    0.001    /* шум моделі, град² за такт        */
#define R    9.0      /* шум акселерометра, град² (σ = 3°) */
#define BIAS 1.0      /* сталий зсув нуля гіроскопа, град/с */

/* усталений коефіцієнт Калмана — корінь рівняння рівноваги */
static double kalman_gain_inf(void) {
    double Pm = (Q + sqrt(Q*Q + 4.0*Q*R)) / 2.0;   /* стала дисперсія передбачення */
    return Pm / (Pm + R);
}

/* відтворюваний шум: 31-бітний LCG + перетворення Бокса–Мюллера */
static uint32_t rng = 2026u;
static double urand(void) {                        /* рівномірне [0,1) */
    rng = (1103515245u*rng + 12345u) & 0x7fffffffu;
    return rng / 2147483648.0;
}
static double gauss(double sigma) {                /* вибірка з N(0, σ²) */
    double u1 = urand(), u2 = urand();
    if (u1 < 1e-12) u1 = 1e-12;                     /* log(0) заборонено */
    return sigma * sqrt(-2.0*log(u1)) * cos(2.0*PI*u2);
}

/* синтез: істинний кут і його похідна — кутова швидкість */
static double true_angle(double t) { return 20.0*sin(2.0*PI*0.2*t); }
static double true_rate (double t) { return 20.0*2.0*PI*0.2*cos(2.0*PI*0.2*t); }

int main(void) {
    const double Kinf  = kalman_gain_inf();
    const double alpha = 1.0 - Kinf;               /* комплементарний бере це число */
    printf("K_inf = %.7f   alpha = 1-K_inf = %.7f   1-alpha = %.7f\n\n",
           Kinf, alpha, 1.0 - alpha);

    /* ── Фаза A: коефіцієнт сходиться сам, без жодного виміру ── */
    printf("phase A: gain convergence (data-independent)\n");
    printf("   n          P-           K\n");
    double P = 900.0;                              /* σ₀ = 30°: про кут нічого не відомо */
    for (int n = 1; n <= 1200; ++n) {
        double Pm = P + Q;                         /* передбачення розширює дисперсію */
        double K  = Pm / (Pm + R);                 /* оновлення: частка довіри виміру */
        P = (1.0 - K) * Pm;                        /* вимір стягує дисперсію */
        if (n==1||n==2||n==3||n==5||n==10||n==20||n==50||n==100||n==200||n==500)
            printf("%4d  %11.6f  %11.7f\n", n, Pm, K);
    }
    printf("  ... -> K_inf = %.7f\n\n", Kinf);

    /* ── Фаза B: заморожений Калман = комплементарний, буква в букву ── */
    printf("phase B: same signal, equal start, Kalman gain frozen at K_inf\n");
    printf("   n     theta_comp   theta_kalman       diff\n");
    double th_c = true_angle(0.0) + gauss(3.0);    /* спільний старт: перший відлік акселя */
    double th_k = th_c;
    double Pk = (Q + sqrt(Q*Q + 4.0*Q*R)) / 2.0 - Q;   /* Pk+Q = P⁻∞  →  K ≡ K_inf */
    double maxd = 0.0;
    for (int n = 1; n <= 500; ++n) {
        double t = n * DT;
        double w = true_rate(t) + BIAS;            /* гіроскоп: швидкість + зсув */
        double z = true_angle(t) + gauss(3.0);     /* акселерометр: кут + шум  */

        th_c = alpha*(th_c + w*DT) + (1.0 - alpha)*z;   /* комплементарний */

        double thm = th_k + w*DT;                  /* Калман — predict */
        double Pm  = Pk + Q;
        double K   = Pm / (Pm + R);                /* Калман — update  */
        th_k = thm + K*(z - thm);
        Pk   = (1.0 - K) * Pm;

        double d = th_k - th_c;
        if (fabs(d) > maxd) maxd = fabs(d);
        if (n==1||n==2||n==10||n==100||n==500)
            printf("%4d  %11.6f  %11.6f  %10.2e\n", n, th_c, th_k, d);
    }
    printf("  max |theta_kalman - theta_comp| = %.2e  (last bit of double)\n", maxd);
    return 0;
}
```

Збірка звичайна: `cc fusion.c -lm -o fusion`. LCG із фіксованим зерном 2026 навмисний — без нього кожен запуск давав би інший шум і числа не відтворити; тут той самий сигнал повторюється байт у байт, тож і результат перевіряється.

## Що друкує програма

**Фаза A — сходження коефіцієнта, добуте без жодного виміру:**

```
K_inf = 0.0104855   alpha = 1-K_inf = 0.9895145   1-alpha = 0.0104855

phase A: gain convergence (data-independent)
   n          P-           K
   1   900.001000    0.9900990
   2     8.911891    0.4975405
   3     4.478864    0.3322880
   5     2.246267    0.1997345
  10     1.002410    0.1002169
  20     0.480264    0.0506593
  50     0.200193    0.0217596
 100     0.122233    0.0133995
 200     0.098272    0.0108011
 500     0.095375    0.0104861
  ... -> K_inf = 0.0104855
```

Прочитати варто дві речі. Перша: попервах, поки Q мізерне проти P, коефіцієнт іде майже точно як **K[n] ≈ 1/(n + R/P₀) = 1/(n + 0.01)** — 0.99, 0.50, 0.33, 0.20, 0.10… Це гейн звичайного **накопичувального середнього**: невпевнений фільтр просто усереднює всі виміри порівну, бо йому нема на що спертися, крім них. Друга: усереднення не триває вічно — за кілька сотень тактів K вирівнюється й застигає на K_∞ = 0.0105. Спиняє його додача Q: щотакту вона не дає дисперсії впасти до нуля, тож пам'ять фільтра лишається **скінченною** — замість дедалі ширшого вікна виходить стале, експоненційне. K_∞ — гейн саме цього усталеного вікна.

І воно збігається з α: `1 − alpha = 0.0104855 = K_inf`, знак у знак. Практики, що десятиліттями підбирали 0.98–0.99 для дронів руками, насправді навпомацки розв'язували оце рівняння рівноваги.

**Фаза B — той самий сигнал крізь обидва фільтри, старт із однакового кута, K заморожено на K_∞:**

```
phase B: same signal, equal start, Kalman gain frozen at K_inf
   n     theta_comp   theta_kalman       diff
   1    -4.019439    -4.019439    -8.88e-16
   2    -3.694339    -3.694339    -8.88e-16
  10    -1.350682    -1.350682    -1.78e-15
 100    17.697500    17.697500    -1.42e-14
 500     1.149221     1.149221    -1.55e-15
  max |theta_kalman - theta_comp| = 3.20e-14  (last bit of double)
```

Колонка `diff` — уся суть. Дві **різні** формули (одна через α й (1−α), друга через K і нев'язку z−θ⁻) на тому самому вході дають однакове число з точністю **чотирнадцяти знаків**; розбіжність 3·10⁻¹⁴ — це вже не поведінка фільтрів, а останній біт `double`. У сталому режимі це буквально один фільтр, записаний двома способами.

А що, як вони стартують **не** з однакового кута? Тоді спрацьовує ще чистіша тотожність. Поставте початковий кут Калмана на 10° убік і лишіть K = K_∞ — різниця двох оцінок на **будь-якому** спільному сигналі підкоряється рівно

```
d[n] = 10·(1 − K_∞)ⁿ = 10·0.9895145ⁿ
 n=1     9.895          n=400    0.1475
 n=100   3.485          n=1000   0.000264
```

бо в різниці двох **однакових** рекурсій увесь сигнал — і ω, і z — скорочується, лишається тільки згасання з множником (1−K_∞) за такт. Хоч звідки стартуй, за кілька секунд оцінки злипаються. Це і є доказ, що фільтр один: він **забуває** початкову незгоду з тією самою сталою часу, з якою душить шум.

## Складність і пастки

Обидва фільтри — O(1) за часом і пам'яттю на такт: ні історії, ні виділень, лише кілька чисел стану. Комплементарний — два множення й два додавання, **жодного ділення**, тож крутиться навіть на 8-бітному ядрі без FPU на цілих із фіксованою комою. Скалярний Калман — та сама дешевина плюс **одне ділення** на такт у `K = P⁻/(P⁻+R)`, а ділення на малих MCU найдорожче. Звідси практична петля: якщо режим сталий, порахуйте K_∞ офлайн і викиньте ділення — і ви **буквально** дістали комплементарний фільтр. Він і є оптимізація Калмана, у якій сталий K винесено з гарячого такту.

Пастки, на яких спотикаються найчастіше:

- **Одиниці Q і R.** Обидва — дисперсії, тобто квадрат одиниці кута. Тримаєте кут у градусах — R = σ_акс² у град², Q теж у град². Перейшли на радіани — усе в рад² (числа інші в 57.3² ≈ 3283 рази). Змішати градуси з радіанами в одному фільтрі — типовий тихий баг: фільтр не падає, просто дає неправильну довіру й тихо бреше.
- **Q прив'язане до dt, R — ні.** R — властивість давача, від такту не залежить. А Q — це скільки недовіри до моделі **набігає за один крок**: коротший крок — менше дрейфу за крок — менше Q. Подвоїли частоту (dt удвічі менший) — Q треба приблизно вдвічі зменшити, інакше фільтр стане надто нервовим. Забути перерахувати Q при зміні частоти — часта причина того, що «на іншій платі поводиться інакше».
- **dt — виміряний, не номінальний.** І `θ += ω·dt`, і `P += Q` крокують реальним часом. Якщо цикл джитерить, беріть **фактичний** інтервал між тактами, а не «100 Гц з даташита»: на дешевому таймері номінал і факт легко різняться на відсотки, і кут поволі повзе.
- **P₀ великим, не нульовим.** Стартова дисперсія каже, наскільки ви не певні початкового кута. Візьмете P₀ малим — фільтр упреться в стартову оцінку й довго ігноруватиме виміри (K стартує низьким, збіжність млява). Візьмете великим (як 900 = 30² вище) — перші виміри вбираються майже повністю, і фільтр швидко ловить кут. P₀ = 0 — пастка: фільтр повірить у початкове припущення як в істину й глухне до давача.
- **Порядок predict → update.** Спершу штовхнути гіроскопом і **розширити** P, тоді злити вимір і **стягнути** P. Переставите — застосуєте свіжий вимір до непосунутого стану й не тим P: оцінка з'їде на такт і ще й отримає хибну певність. Один такт = рівно один predict і рівно один update, з часово узгодженою парою (ω, z).
- **K скалярного фільтра завжди в [0,1].** Вискочив за межі — шукайте помилку знаку чи одиниць у P, Q, R (наприклад, від'ємне R від переплутаного σ²). Це дешева вбудована перевірка справності: одне `assert(0.0 <= K && K <= 1.0)` ловить половину дурних багів ще на столі.
