# Інерціальне числення позиції

<preknowlist>
- [Одометрія](root:com-signal/odometry) — виведення положення через інтегрування швидкості та накопичення кутового дрейфу.
- [Акселерометр](root:hw-sensing/accelerometer) — вимірювання питомої сили (реакції опори) у зв'язаній системі координат.
- [Гіроскоп](root:hw-sensing/gyroscope) — вимірювання миттєвої кутової швидкості обертання тіла.
- [Комплементарний фільтр](root:com-signal/complementary-filter) — злиття вимірювань гіроскопа та акселерометра для стабілізації орієнтації.
- [Фільтр Калмана](root:com-signal/kalman-filter) — оптимальне рекурсивне оцінювання стану при наявності шумів процесу та вимірювань.
</preknowlist>

Автономний підводний апарат занурюється під суцільний шар арктичної криги або швидкісний безпілотник потрапляє в зону суцільного радіоелектронного придушення, де супутникові сигнали GNSS повністю зникають. Бортовий комп'ютер більше не має зовнішніх маяків, радіосигналів чи оптичних орієнтирів, але зобов'язаний щомиті знати координати, швидкість і просторове положення апарата для утримання траєкторії польоту. Єдине джерело інформації, яке неможливо заглушити чи заблокувати ззовні, — це власний блок інерціальних вимірювань (IMU, англ. *Inertial Measurement Unit*), що складається з тривісного акселерометра та тривісного гіроскопа. Проте якщо прошивка апарата наївно проінтегрує виміряні прискорення у швидкість, а швидкість — у координати, уже через 30 секунд розрахункова позиція відлетить від справжньої на сотні метрів через непомітний нахил корпусу відносно гравітаційного поля Землі.

Інерціальне числення позиції (англ. *inertial dead reckoning*, від латинського *inertia* — «бездіяльність, збереження стану руху») — це метод визначення траєкторії та координат рухомого об'єкта шляхом неперервного інтегрування його власного кінематичного прискорення та кутової швидкості без використання зовнішніх опорних орієнтирів. Метод ґрунтується на законах класичної механіки Ньютона: якщо відоме початкове положення й початкова швидкість, то вимірювання прискорення в кожну мить часу дозволяє математично відновити весь наступний шлях.

> 🔧 **Навіщо це.** Інерціальне числення є хребтом навігації сучасних безпілотників, крилатих ракет, підводних човнів, пішохідних навігаційних систем та роботів-кур'єрів. Воно працює з високою частотою (200–1000 Гц), забезпечуючи миттєвий відгук системи керування без затримок радіоканалу та згладжуючи перебої супутникової навігації в тунелях, міських каньйонах та під час маневрів.

## Що насправді вимірює інерціальний давач

Перша помилка розробника-початківця полягає в переконанні, що тривісний акселерометр вимірює другу похідну від координати апарата в просторі. Це фізично неможливо через принцип еквівалентності Ейнштейна: жоден замкнений всередині корпусу прилад не здатен розрізнити дію гравітаційного поля та прискорення самої системи відліку.

Акселерометр вимірює не кінематичне прискорення `a = d²p/dt²`, а так звану **питому силу** (англ. *specific force*) `f` — суму всіх негравітаційних сил, що діють на чутливу масу давача, поділену на величину цієї маси. Фізично це пружна реакція опори або підвісу кремнієвого кристала, яка утримує тестову масу від вільного падіння:

```
f = a − g                                   [визначення питомої сили]
a = f + g                                   [істинне кінематичне прискорення]
```

Тут `g` — вектор прискорення вільного падіння Землі (`≈ 9.80665 м/с²`). Розглянемо два базові фізичні стани:

1. **Датчик нерухомо лежить на столі:**
   Його кінематичне прискорення дорівнює нулю (`a = 0`). Опора столу штовхає датчик угору проти сили тяжіння, тому чутлива маса деформує кремнієві п'єзорезистори. Акселерометр вимірює вектор питомої сили величиною рівно `+1g` (`+9.81 м/с²`), спрямований **вертикально вгору**.
2. **Датчик вільно падає у вакуумі:**
   На нього діє лише сила тяжіння, що розганяє його з прискоренням `a = g`. Реакція опори відсутня, пружини не деформовані, тому виміряна питома сила дорівнює нулю (`f = 0`).

Вимірювання здійснюються у **зв'язаній системі координат** (англ. *Body frame*, позначається індексом `b`), яка жорстко зафіксована на корпусі апарата (наприклад, вісь X — вперед, Y — вправо, Z — вниз). Щоб знайти зміну координат у географічному просторі, вектор `fᵇ` необхідно спочатку математично перетворити в нерухому **навігаційну систему координат** (англ. *Navigation frame*, індекс `n`, наприклад NED: North — Північ, East — Схід, Down — Вниз), і лише після цього відняти земне тяжіння.

## Системи координат у навігації

Для коректного математичного опису інерціального руху розрізняють чотири основні системи відліку:

1. **Інерціальна система координат ECI (Earth-Centered Inertial, індекс `i`):**
   Початок координат розташований у центрі мас Землі. Осі зафіксовані відносно далеких зірок і не обертаються разом із планетою. Саме в цій системі справедливі закони Ньютона `F = m·a` у чистій формі.
2. **Грінвіцька геоцентрична система ECEF (Earth-Centered Earth-Fixed, індекс `e`):**
   Початок координат у центрі Землі, але осі жорстко прив'язані до географічної сітки й обертаються разом із планетою зі швидкістю `ω_e ≈ 7.292115 · 10⁻⁵ рад/с`.
3. **Локальна навігаційна система NED (North-East-Down, індекс `n`):**
   Початок прив'язаний до точки старту або поточної позиції апарата. Вісь X спрямована на географічну Північ по дотичній до меридіана, вісь Y — на Схід по паралелі, вісь Z — вертикально вниз вздовж вектора сили тяжіння (до центру Землі).
4. **Зв'язана система координат корпусу FRD (Forward-Right-Down, індекс `b`):**
   Початок у центрі мас апарата. Вісь X спрямована вздовж поздовжньої осі (ніс апарата), вісь Y — у правий борт/крило, вісь Z — перпендикулярно днищу вниз.

Перехід між зв'язаною системою `b` та навігаційною системою `n` виконується за допомогою ортогональної матриці напрямних косинусів `R_bⁿ` або унітарного кватерніона орієнтації `q`.

## Кінематика безплатформного числення (Strapdown INS)

В історичних навігаційних комплексах середини XX століття датчики розміщувалися на важких карданних платформах, які гіромотори примусово утримували в горизонтальній площині незалежно від поворотів літака (докладніше про цей розвиток — у [хроніці карданних і безплатформних навігаційних систем](root:com-signal/dead-reckoning/hist-dead-reckoning.md)). У сучасних безплатформних інерціальних навігаційних системах (БІНС, англ. *Strapdown INS*) датчики жорстко припаяні до друкованої плати, а вся просторова стабілізація виконується цифровим процесором на кожному кроці часу `Δt`.

![Конвеєр безплатформного інерціального числення](/root/com/com-signal/dead-reckoning/img/strapdown-mechanization.svg)
*Конвеєр обробки даних у БІНС: кутова швидкість гіроскопа інтегрується в кватерніон орієнтації, вектор питомої сили повертається у навігаційну систему координат, після чого віднімається вектор гравітації та виконується подвійне інтегрування.*

Повний конвеєр механізації БІНС складається з п'яти послідовних ланок:

### 1. Інтегрування орієнтації

Гіроскоп вимірює вектор кутової швидкості обертання корпусу відносно інерціального простору `ωᵇ = [ω_x, ω_y, ω_z]ᵀ`. Орієнтацію апарата найефективніше представляти одиничним кватерніоном `q = [w, x, y, z]ᵀ`.

За крок дискретизації `Δt` обчислюється вектор приросту кута `Δθ = ωᵇ · Δt` та його норма `||Δθ|| = √(Δθ_x² + Δθ_y² + Δθ_z²)`. Кватерніон приросту повороту `Δq` обчислюється за формулою Родріга:

```
Δq = [ cos(||Δθ|| / 2),  (sin(||Δθ|| / 2) / ||Δθ||) · Δθ ]ᵀ
```

Поточна орієнтація оновлюється кватерніонним множенням із обов'язковою подальшою нормалізацією для усунення похибок обчислень з плаваючою комою:

```
q[k+1] = q[k] ⊗ Δq
q[k+1] = q[k+1] / ||q[k+1]||                [запобігання накопиченню похибки норми]
```

### 2. Перетворення координат питомої сили

За кватерніоном `q` розраховується матриця напрямних косинусів `R_bⁿ` (ортогональна матриця повороту розміром 3×3):

```
         [ 1 - 2(y²+z²)    2(xy - wz)    2(xz + wy) ]
R_bⁿ =   [   2(xy + wz)  1 - 2(x²+z²)    2(yz - wx) ]
         [   2(xz - wy)    2(yz + wx)  1 - 2(x²+y²) ]
```

Виміряний акселерометром вектор питомої сили повертається у навігаційну площину:

```
fⁿ = R_bⁿ · fᵇ                              [питома сила в системі NED]
```

### 3. Компенсація сили тяжіння

У системі координат NED вісь Down спрямована до центру Землі, тому вектор гравітації дорівнює `gⁿ = [0, 0, +g]ᵀ`. Оскільки для нерухомого об'єкта акселерометр спрямований угору і показує `f_z = −g`, істинне кінематичне прискорення знаходиться додаванням вектору гравітації:

```
aⁿ = fⁿ + gⁿ                                [компенсація тяжіння в NED]
```

Якщо використовується система ENU (East-North-Up), де вісь Z спрямована вгору, вектор тяжіння віднімається: `aⁿ = fⁿ − [0, 0, g]ᵀ`.

### 4. Інтегрування швидкості

Прискорення інтегрується для знаходження лінійної швидкості. Для зменшення числової похибки застосовується трапецеїдальне наближення:

```
vⁿ[k+1] = vⁿ[k] + 1/2 · (aⁿ[k] + aⁿ[k+1]) · Δt
```

### 5. Інтегрування положення

Швидкість інтегрується для оновлення тривимірних координат (широта, довгота, висота або локальні метри `x, y, z`):

```
pⁿ[k+1] = pⁿ[k] + 1/2 · (vⁿ[k] + vⁿ[k+1]) · Δt
```

## Віднімання сили тяжіння та геометричний витік орієнтації

Чому інерціальне числення вимагає бездоганної точності гіроскопів? Сила тяжіння Землі `g ≈ 9.81 м/с²` — колосальна величина порівняно з типовими корисними прискореннями маневрів робота (`0.1–2.0 м/с²`).

![Витік сили тяжіння через кутову похибку орієнтації](/root/com/com-signal/dead-reckoning/img/gravity-leakage.svg)
*Геометрія витоку сили тяжіння: за наявності кутової похибки орієнтації δθ вектор віднімання ĝ не збігається зі справжньою вертикаллю, породжуючи хибне горизонтальне прискорення δa ≈ g · δθ.*

Якщо алгоритм оцінки орієнтації має кутову похибку нахилу `δθ` (по тангажу чи крену), вектор скомпенсованої сили тяжіння повертається на цей кут відносно дійсної фізичної вертикалі. У результаті проекція гравітації не компенсується повністю по вертикалі та створює хибне горизонтальне прискорення:

```
δa_horiz = g · sin(δθ) ≈ g · δθ             [при малих кутах нахилу]
```

Оцінимо масштаб катастрофи для зовсім крихітної кутової похибки в одну десяту градуса:

```
δθ = 0.1° = 0.001745 рад

δa = 9.80665 м/с² · sin(0.001745)
   ≈ 9.80665 · 0.001745
   ≈ 0.0171 м/с²
```

Це прискорення виникає на рівному місці, коли робот нерухомо стоїть на підлозі. Проінтегруємо його за часом:

```
За t = 10 секунд:
δv = δa · t = 0.0171 · 10 = 0.171 м/с
δp = 1/2 · δa · t² = 0.5 · 0.0171 · 100 = 0.855 м

За t = 60 секунд (1 хвилина):
δv = 0.0171 · 60 = 1.03 м/с
δp = 0.5 · 0.0171 · 3600 = 30.8 метра!

За t = 300 секунд (5 хвилин):
δv = 0.0171 · 300 = 5.13 м/с
δp = 0.5 · 0.0171 · 90000 = 770 метрів!
```

Похибка всього у 0.1° змушує навігаційний алгоритм вважати, що через 5 хвилин нерухомий апарат мчить зі швидкістю 18 км/год і перебуває майже за кілометр від початкової точки.

## Анатомія накопичення похибок: лінійний, квадратичний і кубічний дрейф

Похибки інерціального числення складаються з внесків чотирьох фундаментальних джерел, кожне з яких підпорядковується власному закону зростання в часі.

![Закони росту похибок позиції з часом](/root/com/com-signal/dead-reckoning/img/error-growth-curves.svg)
*Порівняння динаміки накопичення помилок: початкова швидкість дає лінійний ріст (t), зміщення акселерометра — квадратичний (t²), а дрейф гіроскопа через витік гравітації розбігається як куб часу (t³).*

### 1. Початкова похибка швидкості `δv₀` → Лінійний ріст (`~ t`)

Якщо в момент втрати GNSS швидкість апарата була визначена з помилкою `δv₀`, ця помилка залишається постійною константою під інтегралом швидкості:

```
δv(t) = δv₀
δp(t) = ∫ δv₀ dt = δv₀ · t                  [лінійне накопичення похибки позиції]
```

Похибка початкової швидкості у `0.1 м/с` дає зсув координат на `6 метрів` за хвилину.

### 2. Зміщення нуля акселерометра `b_a` → Квадратичний ріст (`~ t²`)

Реальний MEMS-акселерометр має систематичний зсув нуля (bias) `b_a` через внутрішні напруження кремнію та температуру. Цей постійний зсув двічі інтегрується за часом:

```
δv(t) = ∫ b_a dt = b_a · t                  [лінійний ріст швидкості]
δp(t) = ∬ b_a dt² = 1/2 · b_a · t²          [квадратичний ріст координат]
```

Для типового споживчого акселерометра зі зміщенням `b_a = 10 мг ≈ 0.098 м/с²` квадратична похибка координат за 1 хвилину становить `0.5 · 0.098 · 3600 ≈ 176 метрів`.

### 3. Дрейф нуля гіроскопа `b_g` → КУБІЧНИЙ ріст (`~ t³`)

Найнебезпечнішим джерелом дрейфу є систематичний відхід нуля гіроскопа (bias) `b_g` (вимірюється в `рад/с` або `°/год`). Кутова похибка орієнтації лінійно зростає з часом: `δθ(t) = b_g · t`.

Як було доведено в попередньому розділі, кутовий нахил породжує хибне горизонтальне прискорення від сили тяжіння: `δa(t) = g · δθ(t) = g · b_g · t`.

Проінтегрувавши це лінійно зростаюче прискорення двічі, отримуємо кубічну залежність:

```
δv(t) = ∫ (g · b_g · t) dt = 1/2 · g · b_g · t²      [квадратичний ріст швидкості]
δp(t) = ∬ (g · b_g · t) dt² = 1/6 · g · b_g · t³     [КУБІЧНИЙ РІСТ ПОЗИЦІЇ]
```

Повне математичне виведення матричних рівнянь похибок БІНС, розрахунок випадкових блукань (Random Walk) та опис періоду коливань Шулера наведено у [математичному аналізі розповсюдження похибок в інерціальній навігації](root:com-signal/dead-reckoning/math-error-propagation.md).

| Клас давача | Дрейф гіроскопа `b_g` | Зсув акселерометра `b_a` | Дрейф позиції за 10 с | Дрейф позиції за 60 с | Дрейф позиції за 300 с (5 хв) |
|---|---|---|---|---|---|
| **Споживчий MEMS** (смартфони, хобі-дрони) | 20 °/год (0.0001 рад/с) | 10 мг (0.098 м/с²) | 5.0 м | 211 м | 4.8 км |
| **Тактичний MEMS / FOG** (промислові БПЛА) | 0.5 °/год (2.4·10⁻⁶ рад/с) | 0.5 мг (0.0049 м/с²) | 0.25 м | 9.1 м | 230 м |
| **Авіаційний навігаційний RLG** (літаки) | 0.005 °/год (2.4·10⁻⁸ рад/с) | 0.02 мг (0.0002 м/с²) | 0.01 м | 0.36 м | 9.2 м |

З таблиці видно: розімкнене інерціальне числення на дешевих MEMS-давачах є працездатним максимум протягом 5–15 секунд. Після цього без зовнішніх виправлень похибка стає неприпустимою.

## Джерела інструментальних похибок IMU

Окрім постійного зсуву нуля, фізичні MEMS-давачі мають низку спотворень, які необхідно компенсувати на етапі первинної обробки сигналів:

1. **Нестабільність зміщення нуля під час роботи (In-Run Bias Instability):**
   Зсув нуля не є абсолютно сталою величиною. Він повільно блукає (фліккер-шум `1/f`) під дією теплових флуктуацій та механічних релаксацій кремнію.
2. **Похибка масштабного коефіцієнта (Scale Factor Error):**
   Коефіцієнт перетворення напруги АЦП або цифрових відліків у фізичні `м/с²` та `рад/с` має похибку калібрування (від 0.1% у дешевих чіпів до 0.001% у тактичних). При швидких обертах чи різких маневрах це призводить до недооцінки або переоцінки кута повороту.
3. **Неортогональність осей чутливості (Cross-Axis Sensitivity):**
   Кристали акселерометрів і гіроскопів монтуються в корпус мікросхеми з технологічним перекосом на частки градуса. У результаті прискорення вздовж осі X створює хибний паразитний сигнал на осях Y та Z. Для усунення цього ефекту матрицю сирих замірів множать на матрицю неортогональності 3×3.
4. **Чутливість гіроскопа до лінійних прискорень (g-sensitivity):**
   Кремнієві балки гіроскопів MEMS коливаються під дією сили Коріоліса, але сильні лінійні удари та вібрації деформують підвіс, породжуючи хибний сигнал кутової швидкості `ω_err = S_g · a`.

## Комплексування БІНС із зовнішніми джерелами інформації

Оскільки чиста БІНС є подвійним розімкненим інтегратором, вона завжди нестійка. Щоб перетворити її на довготривалу надійну систему, інерціальні розрахунки обов'язково комплексують із давачами прямого вимірювання швидкості або обмеженнями руху за допомогою фільтра Калмана стану помилок (ESKF, англ. *Error-State Extended Kalman Filter*).

![Архітектура комплексування БІНС](/root/com/com-signal/dead-reckoning/img/wheel-ins-fusion.svg)
*Архітектура комплексування БІНС: високочастотний контур інтегрує IMU на частоті 500 Гц, а низькочастотний фільтр похибок (ESKF) порівнює швидкість БІНС з одометрією коліс та ZUPT і скидає накопичений дрейф.*

### Концепція фільтра стану помилок (ESKF)

У класичному розширеному фільтрі Калмана (EKF) вектор стану містить повні нелінійні координати, швидкість та кватерніон. Це створює дві великі проблеми:
- Кватерніон орієнтації містить 4 компоненти, але має лише 3 ступені свободи через умову одиничної норми `qᵀ·q = 1`. Матриця коваріації 4×4 стає сингулярною (виродженою).
- Нелінійні кінематичні рівняння вимагають розрахунку складних якобіанів на кожному такті високої частоти.

В архітектурі **ESKF** повний стан системи розділяється на дві частини:

```
x_total = x_nominal ⊕ δx                     [сума номінального стану та вектора помилок]
```

1. **Номінальний стан `x_nominal` (великі нелінійні величини):**
   Інтегрується напряму за швидкими вимірюваннями IMU (200–1000 Гц) через дискретну кінематику БІНС без жодного фільтра Калмана.
2. **Вектор стану помилок `δx` (малі лінійні величини):**
   Включає похибки позиції `δp`, швидкості `δv`, 3-компонентний вектор кутової помилки `δθ` та зміщення давачів `δb_a`, `δb_g`. Оскільки помилки завжди малі, для них діють абсолютно строгі лінійні диференціальні рівняння.

Коли приходить повільне вимірювання (одометрія коліс, оптичний потік, ZUPT або GNSS), ESKF обчислює поправки `δx`, коригує номінальний стан `x_nominal` і миттєво скидає (обнуляє) оцінений вектор помилок `δx ← 0`.

### 1. Одометрія коліс (Wheel Odometry)

Для наземних колісних роботів енкодери на колесах дають пряме вимірювання швидкості руху вперед `v_wheel` у зв'язаній системі координат апарата: `v_wheelᵇ = [v_wheel, 0, 0]ᵀ`.

Повернувши виміряну швидкість у навігаційну систему за поточною орієнтацією `R_bⁿ`, обчислюють вектор нев'язки швидкості:

```
Δv = v_insⁿ − R_bⁿ · v_wheelᵇ
```

Ця нев'язка подається у фільтр Калмана, який:
- Миттєво коригує накопичену швидкість БІНС, переводячи квадратичний ріст похибки координат у лінійний;
- Робить спостережуваними кути нахилу та зміщення акселерометра `b_a`, оновлюючи їх калібрувальні оцінки прямо під час руху.

### 2. Неголономні кінематичні обмеження (NHC)

Колісний транспортний засіб чи автомобіль за нормальних умов котиться вперед без бокового заносу і не відривається від дорожнього полотна. Це накладає неголономні зв'язки (англ. *Non-Holonomic Constraints*, NHC) на проекції швидкості в системі корпусу:

```
v_lateralᵇ  = v_yᵇ ≈ 0                      [відсутність бокового ковзання]
v_verticalᵇ = v_zᵇ ≈ 0                      [рух у площині контакту]
```

Введення цих двох псевдовимірювань у фільтр Калмана блокує накопичення дрейфу швидкості по боковій та вертикальній осях навіть у моменти, коли датчики коліс тимчасово пробуксовують.

### 3. Оптичний потік (Optical Flow)

Для літаючих дронів та складських роботів на днищі встановлюють спрямовану вниз швидкісну камеру (наприклад, PMW3901). Камера порівнює сусідні кадри й обчислює кутовий зсув пікселів `(Δx, Δy)`. Помноживши кутову швидкість пікселів на висоту над підлогою (отриману від лазерного далекоміра), одержують вектор швидкості відносно землі в системі корпусу `(v_xᵇ, v_yᵇ)`. Комплексування оптичного потоку з БІНС дозволяє квадрокоптеру мертво зависати над однією точкою в закритих приміщеннях без GPS.

### 4. Оновлення при нульовій швидкості (Zero-Velocity Update, ZUPT)

Коли робот зупиняється на світлофорі, підводний апарат лягає на дно або нога крокуючого робота стає на землю в опорній фазі кроку, його справжня фізична швидкість гарантовано дорівнює нулю (`v = 0`).

Детектор нерухомості перевіряє дві умови:
1. Модуль повної кутової швидкості не перевищує поріг шуму: `||ωᵇ|| < ε_ω` (наприклад, `< 0.05 рад/с`);
2. Модуль виміряної питомої сили близький до прискорення тяжіння: `| ||fᵇ|| − g | < ε_a` (наприклад, `< 0.2 м/с²`).

Щойно детектор фіксує спокій, алгоритм виконує процедуру **ZUPT**: у фільтр Калмана надходить вимірювання нульової швидкості `z = v_ins − [0, 0, 0]ᵀ`. Це дозволяє:
- Повністю скинути накопичену похибку швидкості до нуля;
- Зафіксувати координати на час зупинки;
- Оцінити та скомпенсувати поточний дрейф гіроскопа `b_g`, оскільки будь-яка зміна орієнтації під час нерухомості є чистою похибкою давача.

## Дискретний інтегратор БІНС

Розглянемо базовий обчислювальний цикл модуля БІНС мовами C та C++. Детальний модуль з повноцінним тестовим середовищем наведено у [проекті дискретної БІНС із компенсацією гравітації та ZUPT](root:com-signal/dead-reckoning/proj-strapdown-integrator.md).

```c
#include <math.h>

#define G_MSS 9.80665f

typedef struct { float x, y, z; } Vector3;
typedef struct { float w, x, y, z; } Quaternion;

typedef struct {
    Vector3 pos;      /* Позиція в NED [м] */
    Vector3 vel;      /* Швидкість в NED [м/с] */
    Quaternion q;     /* Орієнтація Body -> Nav */
    Vector3 prev_acc; /* Прискорення попереднього кроку */
} InsEngine;

void ins_step(InsEngine *ins, Vector3 acc_b, Vector3 gyro_b, float dt) {
    /* 1. Оновлення кватерніона орієнтації через приріст кута */
    Vector3 d_th = {gyro_b.x * dt, gyro_b.y * dt, gyro_b.z * dt};
    float th_len = sqrtf(d_th.x * d_th.x + d_th.y * d_th.y + d_th.z * d_th.z);

    Quaternion dq;
    if (th_len > 1e-7f) {
        float half = 0.5f * th_len;
        float s = sinf(half) / th_len;
        dq = (Quaternion){cosf(half), d_th.x * s, d_th.y * s, d_th.z * s};
    } else {
        dq = (Quaternion){1.0f, 0.5f * d_th.x, 0.5f * d_th.y, 0.5f * d_th.z};
    }

    /* Кватерніонне множення ins->q = ins->q * dq */
    Quaternion q_new = {
        ins->q.w * dq.w - ins->q.x * dq.x - ins->q.y * dq.y - ins->q.z * dq.z,
        ins->q.w * dq.x + ins->q.x * dq.w + ins->q.y * dq.z - ins->q.z * dq.y,
        ins->q.w * dq.y - ins->q.x * dq.z + ins->q.y * dq.w + ins->q.z * dq.x,
        ins->q.w * dq.z + ins->q.x * dq.y - ins->q.y * dq.x + ins->q.z * dq.w
    };

    /* Нормалізація кватерніона */
    float q_norm = sqrtf(q_new.w * q_new.w + q_new.x * q_new.x + q_new.y * q_new.y + q_new.z * q_new.z);
    ins->q = (Quaternion){q_new.w / q_norm, q_new.x / q_norm, q_new.y / q_norm, q_new.z / q_norm};

    /* 2. Побудова матриці повороту R_b2n та поворот прискорення */
    float qw = ins->q.w, qx = ins->q.x, qy = ins->q.y, qz = ins->q.z;
    float r00 = 1.0f - 2.0f * (qy * qy + qz * qz);
    float r01 = 2.0f * (qx * qy - qw * qz);
    float r02 = 2.0f * (qx * qz + qw * qy);
    float r10 = 2.0f * (qx * qy + qw * qz);
    float r11 = 1.0f - 2.0f * (qx * qx + qz * qz);
    float r12 = 2.0f * (qy * qz - qw * qx);
    float r20 = 2.0f * (qx * qz - qw * qy);
    float r21 = 2.0f * (qy * qz + qw * qx);
    float r22 = 1.0f - 2.0f * (qx * qx + qy * qy);

    Vector3 f_nav = {
        r00 * acc_b.x + r01 * acc_b.y + r02 * acc_b.z,
        r10 * acc_b.x + r11 * acc_b.y + r12 * acc_b.z,
        r20 * acc_b.x + r21 * acc_b.y + r22 * acc_b.z
    };

    /* 3. Компенсація сили тяжіння: a_nav = f_nav + [0, 0, +g] */
    Vector3 cur_acc = {f_nav.x, f_nav.y, f_nav.z + G_MSS};

    /* 4. Трапецеїдальне інтегрування швидкості та позиції */
    Vector3 next_vel = {
        ins->vel.x + 0.5f * (ins->prev_acc.x + cur_acc.x) * dt,
        ins->vel.y + 0.5f * (ins->prev_acc.y + cur_acc.y) * dt,
        ins->vel.z + 0.5f * (ins->prev_acc.z + cur_acc.z) * dt
    };

    ins->pos.x += 0.5f * (ins->vel.x + next_vel.x) * dt;
    ins->pos.y += 0.5f * (ins->vel.y + next_vel.y) * dt;
    ins->pos.z += 0.5f * (ins->vel.z + next_vel.z) * dt;

    ins->vel = next_vel;
    ins->prev_acc = cur_acc;
}
```

```cpp
#include <cmath>
#include <array>

namespace nav {

constexpr float G_MSS = 9.80665f;

struct Vector3 {
    float x{0.0f}, y{0.0f}, z{0.0f};

    constexpr Vector3 operator+(const Vector3& o) const noexcept { return {x + o.x, y + o.y, z + o.z}; }
    constexpr Vector3 operator-(const Vector3& o) const noexcept { return {x - o.x, y - o.y, z - o.z}; }
    constexpr Vector3 operator*(float s) const noexcept { return {x * s, y * s, z * s}; }
    [[nodiscard]] float norm() const noexcept { return std::sqrt(x * x + y * y + z * z); }
};

struct Quaternion {
    float w{1.0f}, x{0.0f}, y{0.0f}, z{0.0f};

    [[nodiscard]] Quaternion normalized() const noexcept {
        const float n = std::sqrt(w * w + x * x + y * y + z * z);
        return (n < 1e-8f) ? Quaternion{1.0f, 0.0f, 0.0f, 0.0f} : Quaternion{w / n, x / n, y / n, z / n};
    }

    [[nodiscard]] constexpr Quaternion operator*(const Quaternion& b) const noexcept {
        return {
            w * b.w - x * b.x - y * b.y - z * b.z,
            w * b.x + x * b.w + y * b.z - z * b.y,
            w * b.y - x * b.z + y * b.w + z * b.x,
            w * b.z + x * b.y - y * b.x + z * b.w
        };
    }
};

class InsEngine {
public:
    void step(const Vector3& acc_b, const Vector3& gyro_b, float dt) noexcept {
        /* 1. Оновлення кватерніона орієнтації */
        const Vector3 d_th = gyro_b * dt;
        const float th_len = d_th.norm();

        Quaternion dq;
        if (th_len > 1e-7f) {
            const float half = 0.5f * th_len;
            const float s = std::sin(half) / th_len;
            dq = {std::cos(half), d_th.x * s, d_th.y * s, d_th.z * s};
        } else {
            dq = {1.0f, 0.5f * d_th.x, 0.5f * d_th.y, 0.5f * d_th.z};
        }
        q_ = (q_ * dq).normalized();

        /* 2. Поворот питомої сили в навігаційну систему NED */
        const float qw = q_.w, qx = q_.x, qy = q_.y, qz = q_.z;
        const Vector3 f_nav{
            (1.0f - 2.0f * (qy * qy + qz * qz)) * acc_b.x + 2.0f * (qx * qy - qw * qz) * acc_b.y + 2.0f * (qx * qz + qw * qy) * acc_b.z,
            2.0f * (qx * qy + qw * qz) * acc_b.x + (1.0f - 2.0f * (qx * qx + qz * qz)) * acc_b.y + 2.0f * (qy * qz - qw * qx) * acc_b.z,
            2.0f * (qx * qz - qw * qy) * acc_b.x + 2.0f * (qy * qz + qw * qx) * acc_b.y + (1.0f - 2.0f * (qx * qx + qy * qy)) * acc_b.z
        };

        /* 3. Компенсація сили тяжіння */
        const Vector3 cur_acc = f_nav + Vector3{0.0f, 0.0f, G_MSS};

        /* 4. Трапецеїдальне інтегрування швидкості та координат */
        const Vector3 next_vel = vel_ + (prev_acc_ + cur_acc) * (0.5f * dt);
        pos_ = pos_ + (vel_ + next_vel) * (0.5f * dt);

        vel_ = next_vel;
        prev_acc_ = cur_acc;
    }

    [[nodiscard]] const Vector3& position() const noexcept { return pos_; }
    [[nodiscard]] const Vector3& velocity() const noexcept { return vel_; }
    [[nodiscard]] const Quaternion& orientation() const noexcept { return q_; }

private:
    Vector3 pos_{0.0f, 0.0f, 0.0f};
    Vector3 vel_{0.0f, 0.0f, 0.0f};
    Quaternion q_{1.0f, 0.0f, 0.0f, 0.0f};
    Vector3 prev_acc_{0.0f, 0.0f, 0.0f};
};

} // namespace nav
```

## Інженерний підсумок

Інерціальне числення позиції — це фундаментальний метод автономного визначення руху, що спирається на пряме інтегрування питомої сили та кутової швидкості. Його незамінність зумовлена повною незалежністю від зовнішнього середовища, стійкістю до завад і здатністю працювати на частотах до 1 кГц.

Водночас необхідність постійної компенсації сили тяжіння `g` робить інерціальну навігацію критично залежною від якості оцінки орієнтації: будь-який дрейф гіроскопа викликає кубічне накопичення похибок координат (`~ 1/6 g b_g t³`). У практичній робототехніці та авіації чисте інерціальне числення використовується як високочастотне ядро прогнозу (предиктор стану), яке надійно стабілізується фільтрами стану помилок (ESKF) за даними одометрії коліс, оптичного потоку, детектора ZUPT або супутникових вимірювань.
