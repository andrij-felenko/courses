# 📋 Специфікація параметрів, контракт інтерфейсу та конфігураційні профілі WSOLA

Конфігурація алгоритму WSOLA базується на системному виборі набору взаємопов'язаних часових констант. Кожен параметр безпосередньо впливає на фізичні характеристики звукового тракту: нижню граничну частоту коректного зшивання, збереження динамічних атак, обчислювальну складність та алгоритмічну затримку конвеєра реального часу.

### Базові параметри конфігурації

| Параметр | Позначення | Типовий діапазон | Одиниця | Фізичний зміст та вплив на сигнал |
| :--- | :--- | :--- | :--- | :--- |
| **Частота дискретизації** | `fs` | 8000–48000 | Гц | Визначає масштаб переведення часових мілісекунд у дискретні відліки. |
| **Довжина кадру** | `N` | 15–35 (512–2048) | мс (відліки) | Довжина віконної функції. Завелике значення розмиває транзієнти; замале — спричиняє спотворення басів. |
| **Крок синтезу** | `Hₛ` | `N / 2` або `N / 4` | відліки | Фіксована відстань між центрами вікон на виході. Задає ступінь перекриття (50% або 75%). |
| **Радіус пошуку** | `Δ` | 8–18 (128–1024) | мс (відліки) | Область допуску фазового зсуву `[-Δ, +Δ]`. Мусить покривати період найнижчої цільової частоти `1 / f_min`. |
| **Довжина шаблону** | `L` | `N / 2` або `Hₛ` | відліки | Довжина сегмента еталонного зіставлення для обчислення кореляційної суми. |
| **Коефіцієнт темпу** | `α` | 0.4–2.5 | безрозмірний | Відношення `Hₐ / Hₛ`. Значення `> 1.0` прискорюють звук, `< 1.0` — сповільнюють. |

### Фізичний зміст та граничні умови параметрів

#### 1. Довжина кадру аналізу та синтезу (`N`, `frame_size`)
Довжина кадру визначає тривалість сегмента сигналу, який обробляється як єдине неподільне ціле.
- **Нижня межа (`N < 15` мс):** Якщо розмір кадру стає меншим за 15 мс, у вікно не вміщується навіть один повний період низькочастотних складових сигналу (чоловічий голос 80–120 Гц має період 8.3–12.5 мс). У результаті віконна функція обрізає хвилю, що спричиняє паразитну амплітудну модуляцію низьких частот і втрату насиченості басів.
- **Верхня межа (`N > 40` мс):** При надмірно великих кадрах алгоритм починає захоплювати нестаціонарні ділянки мови — швидку зміну голосних звуків, дифтонги та короткі приголосні. Це викликає акустичний ефект ревербераційного розмиття мови та роздвоєння швидких складів.
- **Оптимальний вибір:** Для людського мовлення рекомендовано обирати `N` у межах 20–30 мс (960–1440 відліків при частоті 48 кГц); для поліфонічної музики та симфонічних записів — 30–40 мс.

#### 2. Радіус вікна пошуку (`Δ`, `seek_range`)
Радіус пошуку визначає часовий люфт, у межах якого кореляційний рушій має право змістити точку взяття наступного кадру відносно номінальної позиції `k · Hₐ`.
- **Правило покриття періоду:** Щоб алгоритм гарантовано знайшов точку збігу фази для будь-якого вхідного гармонічного коливання, інтервал `[-Δ, +Δ]` повинен покривати принаймні один повний період найнижчої очікуваної частоти `f_min`:
  `Δ ≥ fs / f_min`
  Для людського голосу з `f_min = 70` Гц мінімальний радіус становить `Δ ≈ 14.3` мс (686 відліків при 48 кГц).
- **Наслідки замалого `Δ`:** Якщо `Δ` менший за період сигналу, корелятор не зможе дійти до найближчого синфазного гребеня хвилі й буде змушений обрати протифазну точку, що викличе злам фази, тріск і спад амплітуди.
- **Наслідки завеликого `Δ`:** Надлишковий радіус (понад 25 мс) збільшує обчислювальну складність пропорційно `2Δ + 1` і може спричинити випадкове перескакування між різними складами або нотами, створюючи ефект нерівномірного тремоло в темпі мовлення.

#### 3. Довжина еталонного шаблону (`L`, `template_size`)
Сегмент довжиною `L` відліків визначає вікно інтегрування при обчисленні скалярного добутку.
- **Стійкість до шуму:** Збільшення `L` підвищує статистичну стійкість кореляційного піку в зашумлених умовах, оскільки випадкові шумові сплески взаємно гасяться при інтегруванні на довшому інтервалі.
- **Рекомендація:** Зазвичай `L` обирають рівним кроку синтезу `Hₛ` (`N / 2`). Це забезпечує точне оцінювання збігу форми хвилі саме на тій ділянці, яка безпосередньо братиме участь у зшиванні з попереднім кадром.

### Розрахунок затримок та вимог до пам'яті

Усі внутрішні масиви рушія WSOLA мають фіксований розмір, що дозволяє виконувати статичне виділення пам'яті без динамічного купового фрагментування:

```
1. Розрахунок мінімального радіуса пошуку за нижньою частотою:
   Δ_min = fs / f_min    [f_min = 70 Гц → Δ = 48000 / 70 ≈ 686 відліків]

2. Мінімальна алгоритмічна затримка конвеєра:
   T_latency = (N + Δ) / fs    [наприклад: (1440 + 600) / 48000 = 42.5 мс]

3. Розмір вхідного кільцевого буфера:
   Buf_in = 2 · (N + Δ) + Hₛ    [забезпечує збереження історії та lookahead]

4. Розмір вихідного акумулятора overlap-add:
   Buf_out = N + Hₛ             [гарантує коректне накладання вікон]

5. Кількість операцій множення-додавання (MAC) на один кадр:
   Complexity_MAC = (2 · Δ + 1) · L    [для L = 720, Δ = 600 → ~865 000 MAC]
```

### Багатоканальна обробка та фазова синхронізація стереосигналу

При обробці стереофонічного або багатоканального аудіо (5.1, 7.1) застосування незалежного алгоритму WSOLA для кожного каналу категорично заборонене. Якщо лівий і правий канали знайдуть навіть незначно відмінні оптимальні зсуви `δ_left ≠ δ_right` (наприклад, різниця всього в 5–10 відліків), це призведе до фазового розсинхрону між каналами. У результаті стереопанорама повністю розпадеться, локалізація джерел звуку у просторі зникне, а центральний монофонічний образ (вокал по центру) зазнає деструктивної інтерференції при прослуховуванні в моно.

Для збереження моносумісності та незмінності стереобази застосовують стратегію жорсткої фазової синхронізації (*Stereo Phase-Locking*):
1. **Створення монофонічного опорного сигналу:** Вхідні канали підсумовуються в один монопотік: `x_mono[n] = 0.5 · (x_left[n] + x_right[n])`.
2. **Єдиний кореляційний пошук:** Оптимальне зміщення `δ_opt` обчислюється один раз виключно на монофонічному сигналі `x_mono`.
3. **Синхронне зшивання всіх каналів:** Знайдене значення `δ_opt` одночасно застосовується до лівого, правого та всіх інших каналів при вирізанні кадрів і накладанні вікон.

### Контракт інтерфейсу функцій рушія (C API)

#### `wsola_create`
- **Сигнатура:** `wsola_stream_t* wsola_create(int frame_size, int seek_range, float tempo);`
- **Призначення:** Виділяє пам'ять під дескриптор рушія, обчислює вагові коефіцієнти вікна Ганна та виділяє робочі кільцеві буфери входу й виходу.
- **Вхідні параметри:**
  - `frame_size`: Довжина кадру `N` у відліках (повинна бути парним додатним числом).
  - `seek_range`: Радіус пошуку `Δ` у відліках.
  - `tempo`: Початковий коефіцієнт темпу `α` (діапазон `0.4`–`2.5`).
- **Повертає:** Вказівник на екземпляр або `NULL` при нестачі оперативної пам'яті.

#### `wsola_set_tempo`
- **Сигнатура:** `void wsola_set_tempo(wsola_stream_t *w, float tempo);`
- **Призначення:** Динамічно змінює коефіцієнт масштабування темпу без перезапуску рушія та без втрати накопиченої фази попередніх кадрів.
- **Вхідні параметри:**
  - `w`: Вказівник на структуру рушія.
  - `tempo`: Нове значення коефіцієнта темпу `α`.

#### `wsola_push_input`
- **Сигнатура:** `int wsola_push_input(wsola_stream_t *w, const float *src, int count);`
- **Призначення:** Записує нову порцію відліків у кільцевий вхідний буфер. Якщо місця недостатньо, виконує внутрішнє ущільнення невикористаних даних.
- **Вхідні параметри:**
  - `w`: Вказівник на структуру.
  - `src`: Вказівник на масив вхідних аудіовідліків.
  - `count`: Кількість переданих відліків.
- **Повертає:** Кількість фактично скопійованих відліків.

#### `wsola_process_frame`
- **Сигнатура:** `int wsola_process_frame(wsola_stream_t *w);`
- **Призначення:** Перевіряє наявність достатнього заглядання вперед у вхідному буфері, обчислює кореляцію, знаходить оптимальний зсув `δ`, накладає вікно та додає новий кадр у вихідний буфер акумуляції.
- **Повертає:** `1` у разі успішного синтезу одного кадру (`Hₛ` відліків); `0`, якщо у вхідному буфері недостатньо даних для заглядання вперед (потрібно підвантажити нові відліки через `wsola_push_input`).

#### `wsola_pull_output`
- **Сигнатура:** `int wsola_pull_output(wsola_stream_t *w, float *dst, int max_count);`
- **Призначення:** Вивантажує готові синтезовані аудіовідліки з вихідного акумулятора та зсуває залишок буфера на відповідну кількість позицій уліво.
- **Вхідні параметри:**
  - `w`: Вказівник на структуру.
  - `dst`: Цільовий буфер пам'яті.
  - `max_count`: Максимальна місткість цільового масиву.
- **Повертає:** Кількість фактично зчитаних відліків.
