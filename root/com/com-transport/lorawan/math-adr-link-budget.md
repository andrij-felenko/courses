# 🧮 Математична модель адаптивного керування швидкістю (ADR) та пропускної здатності LoRaWAN

Коли автономний датчик перебуває на відстані кількох сотень метрів від шлюзу з прямою радіовидимістю, використання максимального коефіцієнта розширення SF12 та граничної потужності випромінювання +14 дБм є критичною інженерною помилкою. Повільний чирп на SF12 займає радіоефір понад одну секунду на кожну посилку, створюючи завади іншим вузлам і марно розряджаючи батарею струмом 30–40 мА. Натомість скорочення тривалості передачі за допомогою адаптивного переходу на SF7 скорочує час перебування в ефірі у 25–30 разів, знижуючи споживання енергії на той самий коефіцієнт.

Для оптимізації радіолінії мережевий сервер LoRaWAN реалізує алгоритм адаптивного керування швидкістю — ADR (англ. *Adaptive Data Rate*). Розгляньмо строгу математичну модель розрахунку запасу відношення сигналу до шуму, покрокового зниження потужності передавача, аналізу енергетичного бюджету батареї та впливу цих змін на ймовірність колізій, ефект захоплення сигналу, пряме виправлення помилок (FEC) і сумарну місткість мережі.

### 1. Межі чутливості та граничні рівні SNR для чирпової модуляції

Фізичний рівень LoRa базується на модуляції з розширенням спектра чирпами (CSS). Кожен крок коефіцієнта розширення `SF` (від 7 до 12) збільшує кількість чирпів на символ у 2 рази, що дає додатковий виграш від обробки сигналу (англ. *Processing Gain*) близько 2.5–3.0 дБ.

Здатність приймача демодулювати сигнал нижче рівня теплового шуму визначається мінімально необхідним відношенням потужності сигналу до шуму в смузі пропускання (англ. *Signal-to-Noise Ratio*, SNR). Експериментально та аналітично визначені граничні рівні детектування `SNR_limit` для смуги пропускання `BW = 125 кГц` становлять:

| Схема модуляції (Data Rate) | Коефіцієнт розширення | Граничний SNR демодуляції `SNR_limit` | Чутливість приймача `S` (дБм) |
| :--- | :--- | :--- | :--- |
| **DR5** | SF7 / 125 кГц | −7.5 дБ | −123.0 дБм |
| **DR4** | SF8 / 125 кГц | −10.0 дБ | −126.0 дБм |
| **DR3** | SF9 / 125 кГц | −12.5 дБ | −128.5 дБм |
| **DR2** | SF10 / 125 кГц | −15.0 дБ | −131.0 дБм |
| **DR1** | SF11 / 125 кГц | −17.5 дБ | −133.5 дБм |
| **DR0** | SF12 / 125 кГц | −20.0 дБ | −136.5 дБм |

Чутливість приймача `S` пов'язана з тепловим шумом `N_th` та коефіцієнтом шуму приймального тракту `NF` (типово 6 дБ) рівнянням:

```
N_th = −174 + 10·log10(BW)                        [потужність теплового шуму Джонсона-Найквіста]
     = −174 + 10·log10(125000)                    [підстановка смуги BW = 125 кГц]
     = −174 + 51.0                                [обчислення логарифма: 10·log10(125000) ≈ 51.0]
     = −123.0 дБм                                 [результат шуму в смузі 125 кГц]
```

```
S = N_th + NF + SNR_limit                         [розрахунок чутливості за шумом і порогом SNR]
  = −123.0 + 6.0 + (−20.0)                        [підстановка N_th, NF = 6 дБ та SNR_limit для SF12]
  = −137.0 дБм                                    [гранична чутливість на SF12]
```

### 2. Математичний алгоритм розрахунку запасу лінії та кроків ADR

Мережевий сервер (Network Server) накопичує історію вимірювань якості сигналу для кожного стаціонарного кінцевого пристрою. Алгоритм виконується над ковзним вікном з `N` останніх висхідних пакетів (стандартно `N = 20`).

Для кожного пакета `k ∈ [1, N]` шлюзи фіксують виміряне значення відношення сигналу до шуму `SNR[k]`. Якщо один і той самий пакет прийнято кількома шлюзами, обирається максимальне значення серед усіх станцій.

#### Крок 1: Оцінка якості каналу

Замість середнього арифметичного, яке чутливе до випадкових короткочасних завмирань, сервер обчислює максимальний SNR серед накопиченої вибірки:

```
SNR_max = max(SNR[1], SNR[2], ..., SNR[N])
```

Вибір максимуму обґрунтований тим, що короткочасні завмирання компенсуються додатковим статичним запасом надійності, тоді як максимальне значення точніше відображає справжній потенціал прямого радіоканалу без спотворень.

#### Крок 2: Обчислення надлишкового запасу каналу

Надлишковий запас лінії зв'язку `SNR_margin` показує, на скільки децибелів прийнятий сигнал перевищує мінімальний поріг надійної демодуляції з урахуванням апаратного запасу надійності:

```
SNR_margin = SNR_max − SNR_limit(DR_current) − Device_Margin
```

Тут:
- `DR_current` — поточна швидкість передачі, на якій працює пристрій;
- `SNR_limit(DR_current)` — табличний поріг демодуляції для поточної швидкості (наприклад, −20.0 дБ для SF12);
- `Device_Margin` — інженерний запас надійності (англ. *Safety Margin*), що захищає від температурного дрейфу, вологості, зміни листя на деревах та випадкових завмирань (за замовчуванням `Device_Margin = 10.0 дБ`).

#### Крок 3: Визначення кількості дискретних кроків оптимізації

Оскільки кожна зміна Data Rate на один рівень (зменшення SF на 1) або зменшення потужності передавача на один рівень вимагає запасу в 2.5–3.0 дБ, кількість доступних кроків оптимізації `N_step` обчислюється діленням запасу на дискретний крок квантування 3.0 дБ з округленням униз:

```
N_step = floor(SNR_margin / 3.0)
```

Якщо `N_step ≤ 0`, якість зв'язку не дозволяє оптимізувати параметри — пристрій залишає поточний Data Rate або переходить на надійніший режим.

Якщо `N_step > 0`, сервер розподіляє доступні кроки між підвищенням Data Rate та зниженням потужності передавача:

1. **Етап підвищення швидкості (зниження SF):**
   Поки `N_step > 0` і `DR < DR_max` (для EU868 `DR_max = DR5`, що відповідає SF7):
   ```
   DR_new = DR_current + 1
   N_step = N_step − 1
   ```
2. **Етап зниження потужності передавача (TX Power):**
   Якщо після досягнення максимальної швидкості `DR = DR5` (SF7) залишаються невикористані кроки `N_step > 0`, сервер знижує потужність передавача `P_tx` дискретними кроками по 2 дБм від максимальної (+14 дБм для EU868) до мінімальної (+2 дБм):
   ```
   TX_Power_Level = min(N_step, Max_TX_Power_Index)
   P_tx_new = P_tx_max − 2 · TX_Power_Level
   ```

#### Приклад покрокового розрахунку ADR

Пристрій надсилає пакети на швидкості `DR0` (SF12 / 125 кГц, `SNR_limit = −20.0 дБ`) з максимальною потужністю передавача `P_tx = +14 дБм`. Протягом 20 пакетів максимальний виміряний SNR на шлюзі становив `SNR_max = −3.5 дБ`.

Розрахуємо нові параметри зв'язку:

```
SNR_margin = SNR_max − SNR_limit(DR0) − Device_Margin  [формула запасу каналу зв'язку]
           = −3.5 − (−20.0) − 10.0                     [підстановка виміряного SNR_max та порогів]
           = −3.5 + 20.0 − 10.0                        [розкриття дужок: −(−20.0) = +20.0]
           = 6.5 дБ                                    [надлишковий запас каналу]
```

```
N_step = floor(6.5 / 3.0)                              [квантування запасу з кроком 3 дБ]
       = floor(2.166)                                  [ділення: 6.5 / 3.0 ≈ 2.166]
       = 2                                             [округлення вниз: доступно 2 кроки]
```

Розподіл кроків:
- Крок 1: DR0 (SF12) → DR1 (SF11), залишок кроків `N_step = 1`;
- Крок 2: DR1 (SF11) → DR2 (SF10), залишок кроків `N_step = 0`.

Результат для команди `LinkADRReq`:
Новий Data Rate: `DR2` (SF10 / 125 кГц);
Нова потужність: `TXPower 0` (+14 дБм).

### 3. Точна математична модель часу перебування в ефірі (Time on Air)

Час перебування пакета в ефірі `ToA` складається з тривалості передачі преамбули `T_preamble` та тривалості передачі корисного навантаження `T_payload`:

```
ToA = T_preamble + T_payload
```

Тривалість одного символа `T_sym` прямо пропорційна коефіцієнту розширення `SF` і обернено пропорційна ширині смуги `BW`:

```
T_sym = 2^SF / BW
```

Тривалість преамбули з фіксованою кількістю символів `N_pre` (типово 8 символів) та додаванням 4.25 обов'язкових символів синхронізації становить:

```
T_preamble = (N_pre + 4.25) · T_sym               [базова формула тривалості преамбули]
           = (8 + 4.25) · (2^SF / BW)             [підстановка N_pre = 8 та формули T_sym]
           = 12.25 · (2^SF / BW)                  [спрощення: 8 + 4.25 = 12.25]
```

Кількість символів у корисному навантаженні `N_payload` враховує розмір даних `PL` (у байтах), наявність заголовка, контрольну суму CRC, швидкість кодування FEC `CR` (від 1 до 4 для `4/5 ... 4/8`) та оптимізацію низької швидкості (англ. *Low Data Rate Optimization*, DE):

```
N_payload = 8 + max(ceil((8·PL − 4·SF + 28 + 16·CRC − 20·IH) / (4·(SF − 2·DE))) · (CR + 4), 0)
```

Тут:
- `PL` — довжина корисного навантаження в байтах;
- `CRC = 1` для висхідного каналу (Uplink), `CRC = 0` для низхідного (Downlink);
- `IH = 0` (явний заголовок кадру, Explicit Header);
- `DE = 1` для SF11 та SF12 при BW 125 кГц (вмикається оптимізація низької швидкості), `DE = 0` для SF7..SF10;
- `CR = 1` для стандартного кодування FEC 4/5.

Порівняння тривалості передачі пакета розміром `PL = 20 байтів` (типовий кадр телеметрії) на різних швидкостях при `BW = 125 кГц`:

```
SF7,  CR 4/5:  T_sym = 1.024 мс,   ToA = 12.25·1.024 + 43·1.024   = 56.6 мс
SF8,  CR 4/5:  T_sym = 2.048 мс,   ToA = 12.25·2.048 + 38·2.048   = 102.9 мс
SF9,  CR 4/5:  T_sym = 4.096 мс,   ToA = 12.25·4.096 + 36·4.096   = 197.6 мс
SF10, CR 4/5:  T_sym = 8.192 мс,   ToA = 12.25·8.192 + 34·8.192   = 378.9 мс
SF11, CR 4/5:  T_sym = 16.384 мс,  ToA = 12.25·16.384 + 33·16.384 = 741.4 мс
SF12, CR 4/5:  T_sym = 32.768 мс,  ToA = 12.25·32.768 + 29·32.768 = 1318.9 мс
```

Перехід від SF12 до SF7 скорочує час перебування передавача в ефірі з 1318.9 мс до 56.6 мс — у 23.3 раза.

### 4. Вплив прямого виправлення помилок (FEC) та ймовірність спотворення пакета (PER)

У протоколі LoRa застосовується згорткове кодування з кодом Хеммінга. Параметр швидкості кодування (англ. *Coding Rate*, CR) задає співвідношення корисних інформаційних бітів до переданих кодових бітів:

```
R_code = 4 / (4 + CR)
```

Для значень `CR ∈ {1, 2, 3, 4}` швидкість кодування становить відповідно 4/5, 4/6, 4/7 та 4/8. 

Вплив швидкості кодування на стійкість каналу визначається здатністю декодера виправляти поодинокі та подвійні помилки символів:
- При `CR = 1` (код 4/5) додається 1 біт парності: декодер здатен виявити 1 помилку в 5-бітному блоці, але не може її виправити;
- При `CR = 2` (код 4/6) додається 2 біти: виявляється до 2 помилок;
- При `CR = 3` (код 4/7) та `CR = 4` (код 4/8): код Хеммінга забезпечує гарантоване виправлення 1 бітової помилки в кожному 4-бітному півбайті даних.

Ймовірність помилки на біт (англ. *Bit Error Rate*, BER) для некогерентної демодуляції CSS-сигналу в адитивному білому гаусовому шумі (AWGN) залежить від відношення енергії біта до спектральної густини потужності шуму `Eb/N0`:

```
P_bit ≈ Q(sqrt(2 · Eb/N0 · R_code · 2^SF / SF))
```

Ймовірність втрати всього пакета (англ. *Packet Error Rate*, PER) довжиною `N_bytes` байтів при незалежних бітових помилках без виправлення визначається як:

```
PER = 1 − (1 − P_bit)^(8 · N_bytes)
```

Зниження швидкості кодування з 4/5 до 4/8 збільшує час перебування в ефірі на 25–60%, проте зсуває круту ділянку кривої PER у бік менших значень SNR на 1.5–2.0 дБ. Це дозволяє приймати пакети в умовах імпульсних радіозавад, коли класичне збільшення потужності передавача є неефективним або забороненим регуляторними нормами.

### 5. Розрахунок енергоспоживання та терміну служби батареї

Енергетичні витрати кінцевого вузла за один цикл виходу на зв'язок `E_cycle` складаються з трьох компонентів: енергії передачі пакета `E_tx`, енергії очікування та прийому у вікнах RX1/RX2 `E_rx` і фонової енергії сну `E_sleep` за період між сеансами `T_interval`:

```
E_tx = V_bat · I_tx · ToA
E_rx = V_bat · I_rx · T_rx_window
E_sleep = V_bat · I_sleep · (T_interval − ToA − T_rx_window)

E_cycle = E_tx + E_rx + E_sleep
```

Розглянемо типовий датчик з напругою живлення `V_bat = 3.6 В` від літій-тіонілхлоридної батареї (LiSOCl2) ємністю `C_bat = 2400 мА·год` (`Q_bat = 2400 · 3600 = 8.64 · 10^6 мА·с` або `E_total = 31104 Дж`).

Параметри споживання трансивера SX1262:
- Струм передачі при `P_tx = +14 дБм`: `I_tx = 22 мА`;
- Струм передачі при зниженій потужності `P_tx = +2 дБм`: `I_tx = 10 мА`;
- Струм прийому в активному вікні: `I_rx = 5 мА`, тривалість відкриття вікна `T_rx_window = 10 мс`;
- Струм глибокого сну мікроконтролера й радіомодуля: `I_sleep = 1.8 мкА` (`0.0018 мА`);
- Період відправлення телеметрії (20 байтів): `T_interval = 900 с` (кожні 15 хвилин).

#### Порівняльний розрахунок автономності для SF12 та SF7

**Варіант 1: Робота на SF12 без оптимізації (+14 дБм)**
```
ToA = 1.319 с
E_tx = 3.6 В · 22 мА · 1.319 с = 104.46 мДж
E_rx = 3.6 В · 5 мА · 0.010 с = 0.18 мДж
E_sleep = 3.6 В · 0.0018 мА · (900 − 1.319 − 0.010) с = 5.82 мДж

E_cycle = 104.46 + 0.18 + 5.82 = 110.46 мДж
```

```
I_avg = E_cycle / (V_bat · T_interval)                 [формула еквівалентного середнього струму]
      = 110.46 мДж / (3.6 В · 900 с)                   [підстановка енергії циклу та періоду 15 хв]
      = 0.0341 мА                                      [середній струм 34.1 мкА]
```

```
T_life = C_bat / I_avg                                 [оцінка часу розряду батареї]
       = 2400 мА·год / 0.0341 мА                       [підстановка ємності 2400 мА·год]
       = 70381 годин                                   [теоретичний час роботи без саморозряду ≈ 8.0 років]
```

**Варіант 2: Робота на SF7 після оптимізації ADR (+2 дБм)**
```
ToA = 0.0566 с
E_tx = 3.6 В · 10 мА · 0.0566 с = 2.04 мДж
E_rx = 3.6 В · 5 мА · 0.010 с = 0.18 мДж
E_sleep = 3.6 В · 0.0018 мА · (900 − 0.0566 − 0.010) с = 5.83 мДж

E_cycle = 2.04 + 0.18 + 5.83 = 8.05 мДж
```

```
I_avg = E_cycle / (V_bat · T_interval)                 [формула еквівалентного середнього струму]
      = 8.05 мДж / (3.6 В · 900 с)                     [підстановка оптимізованої енергії циклу]
      = 0.00248 мА                                     [середній струм 2.48 мкА]
```

```
T_life = C_bat / I_avg                                 [оцінка часу розряду батареї]
       = 2400 мА·год / 0.00248 мА                      [підстановка ємності 2400 мА·год]
       = 967741 годин                                  [теоретичний час роботи]
```

Зниження швидкості та потужності зменшує витрати енергії на одну передачу з 104.46 мДж до 2.04 мДж — у 51 раз. Енергія передачі стає меншою за фонову енергію сну мікроконтролера.

### 6. Багатоканальний стрибок та нормативні обмеження робочого циклу (Duty Cycle)

У європейському діапазоні EU868 нормативні документи ETSI EN 300 220 обмежують коефіцієнт використання радіоефіру (англ. *Duty Cycle*, DC) величиною 1% для піддіапазону G1 (868.0–868.6 МГц). Це означає, що сумарний час випромінювання передавача не може перевищувати 36 секунд протягом будь-якої однієї години (`T_hour = 3600 с`).

Мінімальний час паузи передавача між двома послідовними передачами `T_off` розраховується за формулою:

```
T_off = ToA · (1 − DC) / DC
```

Для допустимого робочого циклу `DC = 1% = 0.01`:

```
T_off = ToA · (1 − 0.01) / 0.01                   [підстановка нормативного DC = 1%]
      = ToA · 0.99 / 0.01                         [віднімання в чисельнику: 1 − 0.01 = 0.99]
      = 99 · ToA                                  [ділення на 0.01: множення на 99]
```

Порівняння обов'язкової паузи `T_off` для передачі 20-байтного пакета:
- На швидкості SF12 (`ToA = 1.319 с`): `T_off = 99 · 1.319 с = 130.58 с` (понад 2 хвилини примусового мовчання);
- На швидкості SF7 (`ToA = 0.0566 с`): `T_off = 99 · 0.0566 с = 5.60 с` (менше 6 секунд паузи).

Якщо вузол працює на 8 незалежних каналах і застосовує псевдовипадковий стрибок частоти (англ. *Channel Hopping*), обмеження робочого циклу розраховується індивідуально для кожного піддіапазону, що дозволяє суттєво підвищити швидкість реакції пристрою на критичні події.

### 7. Вплив ADR на колізії та сумарну місткість мережі (Pure ALOHA)

Оскільки кінцеві пристрої LoRaWAN Class A виходять у радіоефір асинхронно без попереднього прослуховування каналу (LBT), доступ до середовища описується моделлю чистого ALOHA.

Нехай у зоні покриття шлюзу працює `M` датчиків, кожен з яких генерує один пакет з тривалістю в ефірі `ToA` за середній період часу `T_period`. Тоді сумарне навантаження на один частотний канал (інтенсивність трафіку `G`) виражається як:

```
G = (M · ToA) / T_period
```

Згідно з пуассонівським розподілом випадкових подій, уразливий часовий інтервал, протягом якого будь-яка інша передача спричинить колізію, дорівнює подвійній тривалості пакета `2 · ToA`. Відповідно, ймовірність успішної доставки пакета без колізій `P_succ` та нормована пропускна здатність каналу `S` становлять:

```
P_succ = e^(−2 · G)

S = G · P_succ = G · e^(−2 · G)
```

Максимальна теоретична місткість каналу ALOHA досягається при `G = 0.5` і становить:

```
S_max = 0.5 · e^(−1) ≈ 0.184   (18.4% від максимальної пропускної здатності)
```

#### Ефект захоплення сигналу (Capture Effect)

У реальному радіоефірі колізія двох пакетів з однаковим SF на одній частоті не завжди веде до втрати обох повідомлень. Якщо один із сигналів приходить на вхід демодулятора з потужністю, що перевищує потужність завади на величину порогу співканального захисту `Delta_P` (для LoRa `Delta_P ≈ 6 дБ`), приймач успішно фіксує і демодулює сильніший пакет.

З урахуванням ефекту захоплення ймовірність успішного прийому сильнішого сигналу `P_capture` коригується за формулою:

```
P_capture = P_succ + P_collision · P(P_wanted − P_interferer ≥ 6 дБ)
```

Просторова розбіжність вузлів (пристрої розташовані на різній відстані від базової станції) створює різницю рівнів потужності через втрати на трасі (англ. *Path Loss*), завдяки чому реальна пропускна здатність мережі зростає на 20–35% порівняно з ідеальною моделлю ALOHA.

#### Порівняльний аналіз мережі з 1000 пристроїв

Розглянемо мережу з `M = 1000` датчиків, кожен з яких надсилає 20 байтів даних кожні `T_period = 60 секунд` на одному частотному каналі.

**Сценарій А: Усі пристрої зафіксовані на SF12 (без ADR)**
```
ToA = 1.319 с
G = (1000 · 1.319) / 60 = 21.98

P_succ = e^(−2 · 21.98) = e^(−43.96) ≈ 7.3 · 10^(−20) ≈ 0%
```
Канал повністю перевантажений колізіями, жоден пакет не доходить до шлюзу.

**Сценарій Б: Завдяки роботі ADR більшість пристроїв переведено на SF7**
```
ToA = 0.0566 с
G = (1000 · 0.0566) / 60 = 0.943

P_succ = e^(−2 · 0.943) = e^(−1.886) ≈ 0.151   (15.1% успіху на одному каналі)
```

Якщо мережа використовує 8 паралельних частотних каналів, навантаження на один канал зменшується у 8 разів:

```
G_8ch = 0.943 / 8 = 0.118

P_succ_8ch = e^(−2 · 0.118) = e^(−0.236) ≈ 0.790   (79.0% успішних доставок)
```

А враховуючи квазіортогональність чирпів із різними SF, пристрої на різних швидкостях не створюють взаємних колізій навіть на одній частоті. Це доводить, що динамічне зниження SF за допомогою алгоритму ADR є ключовим фактором масштабування мережі LoRaWAN від сотень до сотень тисяч пристроїв на один шлюз.
