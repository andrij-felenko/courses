# 🧮 Математичні критерії селекції сот та естафетного перемикання

Ця математична вставка містить аналітичне виведення S-критерію придатності соти (Cell Selection S-criterion) та рівнянь події A3 для естафетної передачі (Handover Event A3), а також розрахунок фільтрації шару L3 і захисту від ефекту «пінг-понгу».

## Природа радіозавмирань та необхідність математичної фільтрації

Сигнал, який приймає мобільний пристрій під час руху, зазнає двох принципово різних видів затухання в просторі:
1. **Повільні затінення (Slow Shadowing):** викликані огинанням рельєфу місцевості, пагорбів та великих будівель. Описуються логнормальним розподілом і змінюються на дистанціях у десятки метрів.
2. **Швидкі багатопроменеві завмирання (Fast Rayleigh Fading):** викликані інтерференцією сотень відбитих хвиль від доріг, стін та транспорту. При швидкості руху 60–120 км/год і частоті 1800 МГц довжина хвилі становить близько 16 см, а локальні інтерференційні мінімуми (провали сигналу на 20–30 dB) виникають через кожні кілька мілісекунд.

Якщо алгоритм керування мобільністю спиратиметься на миттєві вимірювання фізичного рівня L1, модем здійснюватиме сотні помилкових перемикань між щоглами на хвилину. Тому стандарти 3GPP впроваджують двоступеневий математичний апарат: цифрову фільтрацію шару L3 та параметричний гістерезис із часовою затримкою (Time-to-Trigger).

## S-критерій придатності соти (Cell Selection S-Criterion)

При увімкненні або втраті зв'язку пристрій сканує радіоефір і вибирає найкращу соту з доступних у списку PLMN. Сота вважається придатною для вибору (Cell Selection) та переобрання (Cell Reselection) згідно зі стандартом 3GPP TS 36.304, якщо одночасно виконуються два критерії: за рівнем потужності та за якістю сигналу.

```text
S_rxlev > 0    [умова достатності потужності сигналу]
S_qual  > 0    [умова достатності якості та завадозахищеності]
```

### Рівняння компонента рівня потужності

Компонент рівня потужності враховує виміряне значення RSRP, мінімально допустимий поріг оператора та компенсацію потужності передавача пристрою:

```text
S_rxlev = Q_rxlevmeas - (Q_rxlevmin + Q_rxlevminoffset) - P_compensation - Q_offset_temp
```

Де змінні мають такий фізичний зміст:
* `Q_rxlevmeas` — виміряне значення RSRP у dBm;
* `Q_rxlevmin` — мінімальний рівень сигналу для доступу до соти (передається в SIB1, типово від -128 dBm до -115 dBm);
* `Q_rxlevminoffset` — зсув порогу (використовується при періодичному скануванні у роумінгу, типово 0 dB);
* `P_compensation` — штраф за обмеження максимальної потужності передавача пристрою (UL Power Class);
* `Q_offset_temp` — тимчасовий зсув при частих невдалих спробах випадкового доступу (PRACH).

Величина компенсації потужності передавача розраховується як:

```text
P_compensation = max(P_EMAX - P_PowerClass, 0)
```

Де `P_EMAX` — максимально дозволена вихідна потужність у соті (з SIB1, типово +23 dBm), а `P_PowerClass` — максимальна апаратна потужність передавача пристрою (для класу 3 — +23 dBm, для класу 5 — +20 dBm).

### Рівняння компонента якості сигналу

Компонент якості сигналу гарантує, що співвідношення енергії опорних символів до рівня інтерференції та шуму є достатнім для надійного декодування каналу керування PDCCH:

```text
S_qual = Q_qualmeas - (Q_qualmin + Q_qualminoffset) - Q_offset_temp
```

де `Q_qualmeas` — виміряне значення RSRQ у dB, а `Q_qualmin` — мінімальний рівень RSRQ із блоку SIB1 (типово від -19.5 dB до -16.0 dB).

### Числовий приклад обчислення S-критерію

Нехай базовою станцією транслюються такі параметри в блоці SIB1:
* `Q_rxlevmin = -120 dBm`;
* `Q_qualmin = -18 dB`;
* `P_EMAX = 23 dBm`.

Пристрій класу потужності `P_PowerClass = 23 dBm` провів вимірювання опорних сигналів і отримав:
* `Q_rxlevmeas = -108 dBm`;
* `Q_qualmeas = -13.5 dB`.

Покроковий розрахунок придатності соти:

```text
P_compensation = max(23 - 23, 0) = 0 dB           [компенсація потужності не потрібна]
S_rxlev        = -108 - (-120 + 0) - 0 - 0 = 12 dB [запас за потужністю становить +12 dB > 0]
S_qual         = -13.5 - (-18.0 + 0) - 0   = 4.5 dB [запас за якістю становить +4.5 dB > 0]
```

Оскільки обидві нерівності `S_rxlev > 0` та `S_qual > 0` виконуються, сота успішно проходить критерій придатності й пристрій розпочинає процедуру RACH.

## R-критерій переобрання соти в режимі очікування (Cell Reselection)

Коли пристрій перебуває в стані `RRC_IDLE`, він періодично ранжує поточну соту `s` та сусідні соти `n` за ранговим R-критерієм (3GPP TS 36.304):

```text
R_s = Q_meas_s + Q_hyst
R_n = Q_meas_n - Q_offset
```

де `Q_hyst` — гістерезис переобрання для поточної соти (задається в SIB3/SIB4, типово 2..4 dB), а `Q_offset` — індивідуальне зміщення частоти або соти. Нова сота обирається для переходу лише тоді, коли її ранг перевищує ранг поточної соти (`R_n > R_s`) протягом інтервалу часу `Treselection` (типово 1..2 секунди).

## Рівняння події естафети A3 (Handover Event A3)

Подія A3 виникає в активному режимі `RRC_CONNECTED`, коли виміряний рівень сигналу сусідньої соти (Target Cell) стає кращим за поточну соту (Serving Cell) на величину зміщення з урахуванням конфігурованого гістерезису.

### Умова виникнення події A3 (Entering Condition)

Пристрій фіксує виконання умови A3 для сусідньої соти, якщо справедлива нерівність:

```text
M_n + O_fn + O_cn - Hys > M_s + O_fs + O_cs + Off
```

Де компоненти рівняння визначаються так:
* `M_n` — фільтроване вимірювання сусідньої соти (RSRP у dBm або RSRQ у dB);
* `O_fn` — частотне зміщення сусідньої несучої (Frequency Offset);
* `O_cn` — індивідуальне зміщення соти (Cell Individual Offset, CIO);
* `Hys` — параметр гістерезису події A3 (Hysteresis, типово 1.0 .. 3.0 dB);
* `M_s` — фільтроване вимірювання поточної соти (RSRP у dBm);
* `O_fs` — частотне зміщення поточної несучої;
* `O_cs` — індивідуальний зсув поточної соти;
* `Off` — абсолютний зсув події A3 (a3-Offset, типово 2.0 .. 3.0 dB).

### Умова виходу з події A3 (Leaving Condition)

Подія A3 скасовується, якщо до закінчення таймера `Time-to-Trigger` сигнал сусідньої соти падає нижче межі виходу:

```text
M_n + O_fn + O_cn + Hys < M_s + O_fs + O_cs + Off
```

Різниця між межею входу та межею виходу утворює коридор шириною `2 · Hys`, що виключає дрижання тригера на граничних значеннях.

## Фільтрація вимірювань рівня L3 та розрахунок Time-to-Trigger

Щоб швидкі завмирання Релея (Rayleigh fast fading) та випадковий шум не викликали помилкових хендоверів, сирі вимірювання фізичного рівня L1 усереднюються рекурсивним цифровим фільтром першого порядку (IIR) на рівні L3 RRC:

```text
F_n = (1 - a) · F_{n-1} + a · M_n
```

де ваговий коефіцієнт `a` обчислюється через параметр фільтрації `k` (задається в RRCConnectionReconfiguration через `filterCoefficient`):

```text
a = 2^(-k / 4)
```

При стандартному значенні `k = 4`:
```text
a   = 2^(-4 / 4) = 2^(-1) = 0.5
F_n = 0.5 · F_{n-1} + 0.5 · M_n
```

### Динаміка придушення ефекту «пінг-понгу»

Розглянемо випадок руху пристрою між двома сотами, де параметри радіомережі сконфігуровано так:
* `Hys = 2.0 dB`;
* `Off = 1.5 dB`;
* `O_fn = O_cn = O_fs = O_cs = 0 dB`;
* `Time-to-Trigger (TTT) = 160 ms`.

Поріг входу для сусідньої соти:

```text
M_n - M_s > Off + Hys = 1.5 + 2.0 = 3.5 dB
```

Поріг виходу для сусідньої соти:

```text
M_n - M_s < Off - Hys = 1.5 - 2.0 = -0.5 dB
```

Завдяки сумісній дії гістерезису (3.5 dB запасу над рівнем поточної соти) та таймера `TTT` (160 мс безперервного домінування сигналу):
1. Короткочасні сплески інтерференції та дифракційні тіні тривалістю менше 160 мс не викликають відправлення звіту `MeasurementReport`.
2. Після успішного переходу на цільову соту зворотний хендовер стане можливим лише тоді, коли стара станція стане кращою вже за нову на ті самі 3.5 dB протягом наступних 160 мс. Це повністю виключає циклічні перемикання між станціями.
