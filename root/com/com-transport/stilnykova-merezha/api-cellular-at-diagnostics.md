# 📋 Інтерфейс AT-команд діагностики соти та радіоканалу

Цей довідник містить повний опис синтаксису, параметрів, кодів статусів та правил перерахунку стандартизованих 3GPP AT-команд і розширених інженерних режимів для зчитування метрик радіоканалу, стану реєстрації та топології стільникової мережі.

Командний інтерфейс Hayes AT (ATtention), стандартизований для мобільних систем у специфікаціях 3GPP TS 27.005 та TS 27.007, є основним протоколом взаємодії між керуючим мікроконтролером (DTE — Data Terminal Equipment) та стільниковим радіомодемом (DCE — Data Circuit-terminating Equipment) через послідовний інтерфейс UART або віртуальний USB CDC-ACM порт.

## Організація сесії обміну та правила взаємодії

Кожна AT-команда починається з префікса `AT` (у будь-якому регістрі) і завершується символом повернення каретки `<CR>` (код `0x0D`). Модем відповідає рядком, що містить корисне навантаження, та підтвердженням завершення транзакції: результуючим кодом `OK`, `ERROR` або розширеним кодом помилки `+CME ERROR: <err>`.

Усі команди діагностики поділяються на чотири синтаксичні типи:
1. **Тестова команда (`AT+<cmd>=?`):** повертає діапазон підтримуваних параметрів та форматів відповіді.
2. **Команда читання (`AT+<cmd>?`):** повертає поточні налаштування або стан підсистеми.
3. **Команда запису (`AT+<cmd>=<p1>,<p2>`):** встановлює нові параметри конфігурації.
4. **Команда виконання (`AT+<cmd>`):** запускає дію або одноразове вимірювання.

Окрім синхронних відповідей типу «запит-відповідь», модем використовує асинхронні повідомлення — Unsolicited Result Codes (URC). URC передаються модемом за власною ініціативою в момент виникнення мережевої події (наприклад, перехід між зонами відстеження `+CEREG`, вхідний виклик `RING` або втрата зв'язку `NO CARRIER`). Керуюча програма повинна розділяти синхронні відповіді та асинхронні URC, що можуть надійти посеред виконання іншої команди.

## Стандартні команди якості сигналу (3GPP TS 27.007)

### AT+CSQ (Signal Quality)

Команда `AT+CSQ` є базовою інструкцією для швидкої оцінки рівня сигналу та коефіцієнта бітових помилок. Вона підтримується всіма поколіннями стільникових модулів (GSM, UMTS, LTE, NB-IoT, 5G).

```text
Синтаксис запиту:    AT+CSQ
Формат відповіді:    +CSQ: <rssi>,<ber>
                     OK
```

Параметр `<rssi>` відображає інтегральну потужність сигналу в усьому радіочастотному каналі. Значення індексу від 0 до 31 перераховується в децибел-мілівати (dBm) за лінійним законом. Індекс 99 означає, що модем знаходиться в процесі пошуку мережі, радіотракт вимкнено або вимірювання неможливе.

| Параметр | Діапазон | Опис фізичної величини | Формула перерахунку |
|:---|:---|:---|:---|
| `<rssi>` | 0 | Рівень сигналу ≤ -113 dBm | -113 dBm |
| | 1 | Рівень сигналу -111 dBm | -111 dBm |
| | 2..30 | Крок квантування 2 dBm | `P = -113 + 2 · rssi` (dBm) |
| | 31 | Рівень сигналу ≥ -51 dBm | -51 dBm |
| | 99 | Рівень невідомий або не може бути виміряний | Немає сигналу / помилка RF |
| `<ber>` | 0..7 | Коефіцієнт бітових помилок (RXQUAL у GSM) | `BER` у межах [0.2%, 12.8%] за шкалою 3GPP |
| | 99 | Значення невідоме або не підтримується (типово для LTE/5G) | Не застосовується у пакетному режимі |

Практичне обмеження `AT+CSQ` у мережах LTE полягає в тому, що RSSI вимірює загальну енергію каналу. Якщо поруч працює потужна сусідня станція на тій самій частоті, RSSI може показувати високе значення (наприклад, індекс 25, що відповідає -63 dBm), тоді як корисний сигнал через завади буде повністю деградований. Для точної діагностики LTE та 5G слід використовувати розширену команду `AT+CESQ`.

### AT+CESQ (Extended Signal Quality)

Команда `AT+CESQ` повертає окремі показники для різних технологій радіодоступу, включно з потужністю опорних символів (RSRP) та якістю опорних сигналів (RSRQ) для LTE та 5G.

```text
Синтаксис запиту:    AT+CESQ
Формат відповіді:    +CESQ: <rxlev>,<ber>,<rscp>,<ecno>,<rsrq>,<rsrp>
                     OK
```

Поля, які не стосуються поточної активної технології радіодоступу (RAT), повертаються зі значенням 99 (для 2G) або 255 (для 3G/LTE). Наприклад, у режимі LTE відповідь має вигляд `+CESQ: 99,99,255,255,24,65`.

| Параметр | Діапазон | Опис фізичної величини | Формула перерахунку у фізичні одиниці |
|:---|:---|:---|:---|
| `<rxlev>` | 0..63, 99 | Рівень сигналу 2G (RXLEV) | `0 = < -110 dBm`, `63 = >= -48 dBm`, крок 1 dBm |
| `<ber>` | 0..7, 99 | Бітові помилки 2G (BER) | Стандартні градації RXQUAL |
| `<rscp>` | 0..96, 255 | Потужність коду 3G (RSCP) | `P = -120 + rscp` (dBm), `0 = < -120 dBm`, `96 = >= -25 dBm` |
| `<ecno>` | 0..49, 255 | Співвідношення енергії на чип до шуму 3G | `Ec/N0 = -24 + 0.5 · ecno` (dB) |
| `<rsrq>` | 0..34, 255 | Якість опорних сигналів LTE/5G (RSRQ) | `RSRQ = -19.5 + 0.5 · rsrq` (dB) |
| | 0 | `RSRQ < -19.5 dB` | Гранично зашумлений канал |
| | 34 | `RSRQ >= -3.0 dB` | Ідеальний чистий канал без навантаження |
| | 255 | Не визначено або пристрій не в LTE/5G | Немає покриття LTE/5G |
| `<rsrp>` | 0..97, 255 | Потужність опорних сигналів LTE/5G (RSRP) | `RSRP = -140 + rsrp` (dBm) |
| | 0 | `RSRP < -140 dBm` | Нижче порогу чутливості приймача |
| | 97 | `RSRP >= -44 dBm` | Максимальна потужність біля антени |
| | 255 | Не визначено або пристрій не в LTE/5G | Немає покриття LTE/5G |

## Реєстрація в мережі та відстеження топології

### AT+CREG / AT+CEREG / AT+C5GREG (Network Registration Status)

Контроль стану реєстрації здійснюється трьома спеціалізованими командами:
* `AT+CREG`: реєстрація в мережах комутації каналів (GSM/2G CS, дзвінки та SMS);
* `AT+CEREG`: реєстрація в мережі пакетної передачі EPS (LTE 4G, NB-IoT, LTE-M);
* `AT+C5GREG`: реєстрація в мережі 5G System (5GS NR).

```text
Синтаксис запиту:    AT+CEREG?
Формат відповіді:    +CEREG: <n>,<stat>[,[<tac>],[<ci>],[<Act>][,<cause_type>,<reject_cause>]]
                     OK

Конфігурація URC:    AT+CEREG=<n>
```

Параметр `<n>` задає рівень деталізації та вмикає надсилання URC-сповіщень при кожній зміні базової станції або зони відстеження.

| Параметр `<n>` | Режим індикації URC |
|:---|:---|
| 0 | Вимкнути URC (тільки опитування через `AT+CEREG?`) |
| 1 | Увімкнути базовий URC: `+CEREG: <stat>` |
| 2 | Увімкнути розширений URC з параметрами соти: `+CEREG: <stat>,<tac>,<ci>,<Act>` |
| 3 | Увімкнути URC з кодами причин відхилення реєстрації: `+CEREG: <stat>,<tac>,<ci>,<Act>,<cause_type>,<reject_cause>` |

Коди статусу реєстрації `<stat>` однозначно визначають поточний стан радіозв'язку:

| Значення `<stat>` | Стан реєстрації | Фізичний зміст та поведінка модему |
|:---|:---|:---|
| 0 | Not registered, not searching | Модем не шукає мережу (радіомодуль вимкнено через `AT+CFUN=0` або відсутня SIM) |
| 1 | Registered, home network | Успішна реєстрація в домашній мережі оператора |
| 2 | Not registered, searching | Сканування радіоефіру, виявлення PSS/SSS, спроби входу |
| 3 | Registration denied | Відхилено ядром мережі (некоректний IMSI, блокування оператором) |
| 4 | Unknown | Стан невизначений (втрата несучої, аварія радіотракту) |
| 5 | Registered, roaming | Успішна реєстрація в мережі національного чи міжнародного роумінгу |

Додаткові поля розширеного формату дозволяють однозначно ідентифікувати базову станцію:
* `<tac>`: Tracking Area Code у вигляді шістнадцяткового 16-бітного числа (наприклад `"1A2F"`).
* `<ci>`: Cell Identity у вигляді шістнадцяткового 28-бітного числа (наприклад `"05B2A01"`). Перші 20 біт ідентифікують сам вузол eNodeB (eNodeB ID = `0x05B2A` = 23338), а останні 8 біт — локальний номер сектора (`0x01`).
* `<Act>`: технологія радіодоступу (0 = GSM, 2 = UTRAN, 7 = E-UTRAN LTE, 8 = eMTC, 9 = NB-IoT, 12 = 5G NR).

## Вибір оператора та сканування ефіру

### AT+COPS (Operator Selection)

Команда `AT+COPS` керує вибором оператора зв'язку, дозволяє переглядати поточну мережу та ініціювати примусове сканування доступних стільникових мереж.

```text
Синтаксис запиту:    AT+COPS?
Формат відповіді:    +COPS: <mode>[,<format>,<oper>[,<AcT>]]
                     OK

Синтаксис сканування: AT+COPS=?
Формат списку:       +COPS: (stat, "long_name", "short_name", "numeric_plmn", AcT), ...
```

| Параметр | Значення | Опис |
|:---|:---|:---|
| `<mode>` | 0 | Автоматичний вибір оператора за списком пріоритетів на SIM-картці |
| | 1 | Ручний вибір оператора (вимагає передачі параметрів `<format>` та `<oper>`) |
| | 2 | Примусове відключення від мережі (Deregister / від'єднання від радіоефіру) |
| | 3 | Встановлення лише формату повернення імені для наступних запитів |
| | 4 | Ручний вибір із автоматичним поверненням до автовибору у разі відмови |
| `<format>` | 0 | Довгий алфавітний формат (наприклад, `"Kyivstar"`) |
| | 1 | Скорочений алфавітний формат (наприклад, `"KS"`) |
| | 2 | Числовий формат ідентифікатора PLMN (MCC+MNC, наприклад `"25503"`) |
| `<AcT>` | 0..12 | Технологія доступу підключеної мережі |

Виконання команди сканування `AT+COPS=?` є блокуючою операцією, яка може тривати від 30 до 180 секунд. Модем послідовно перебирає всі підтримувані радіодіапазони, виявляє синхросигнали сот і зчитує блоки SIB1 для формування повного списку доступних мереж з їхніми статусами (доступна, поточна, заборонена).

## Пропрієтарні інженерні команди (Quectel +QENG)

Для отримання детальних радіопараметрів, що не входять до стандартів 3GPP (таких як фізичний ідентифікатор соти PCI, номер каналу EARFCN, відношення сигнал/шум SINR, індекс якості CQI та список сусідніх сот), виробники модемів надають розширені команди. Для модулів Quectel (серії EC25, EG25, BG96, RG500) стандартом де-факто є команда `AT+QENG`.

```text
Синтаксис запиту:    AT+QENG="servingcell"
```

### Формат відповіді для мережі LTE:
```text
+QENG: "servingcell",<state>,"LTE",<is_tdd>,<mcc>,<mnc>,<cellid>,<pcid>,<earfcn>,<freq_band_ind>,<ul_bandwidth>,<dl_bandwidth>,<tac>,<rsrp>,<rsrq>,<rssi>,<sinr>,<cqi>,<tx_power>,<srxlev>
OK
```

| Поле відповіді | Приклад | Фізичний зміст та діагностичне значення |
|:---|:---|:---|
| `<state>` | `"CONNECT"` | Стан RRC-з'єднання: `"NOCONN"` (RRC_IDLE) або `"CONNECT"` (RRC_CONNECTED) |
| `<is_tdd>` | `"FDD"` | Режим дуплексу: частотний (FDD) або часовий (TDD) |
| `<mcc>`, `<mnc>` | `255`, `03` | Код країни (Україна) та код оператора |
| `<cellid>` | `05B2A01` | Глобальний 28-бітний ідентифікатор соти в шістнадцятковому форматі |
| `<pcid>` | `142` | Physical Cell ID (0..503), фізичний ідентифікатор сектора |
| `<earfcn>` | `1300` | Номер радіоканалу несучої (Band 3, 1800 МГц) |
| `<freq_band_ind>` | `3` | Номер робочого діапазону LTE (Band 3) |
| `<dl_bandwidth>` | `5` | Ширина низхідної смуги: 0=1.4, 1=3, 2=5, 3=10, 4=15, 5=20 МГц |
| `<tac>` | `1A2F` | Tracking Area Code у шістнадцятковому вигляді |
| `<rsrp>` | `-85` | Потужність опорних символів безпосередньо в dBm |
| `<rsrq>` | `-9` | Якість опорних сигналів безпосередньо в dB |
| `<rssi>` | `-58` | Загальна широкосмугова потужність у dBm |
| `<sinr>` | `18` | Відношення сигнал/шум-плюс-інтерференція в dB (0..30 dB) |
| `<cqi>` | `12` | Channel Quality Indicator (1..15, визначає схему модуляції для шедулера) |

### Запит сусідніх сот (Neighbour Cells):
```text
Синтаксис запиту:    AT+QENG="neighbourcell"
```

Команда повертає список суміжних сот на тій самій частоті (Intra-frequency) та на інших частотах (Inter-frequency) із зазначенням їхніх EARFCN, PCI, RSRP та RSRQ. Моніторинг цих параметрів дозволяє вбудованому пристрою завчасно прогнозувати наближення естафетного перемикання або втрати покриття основної станції.

## Обробка помилок та типові коди завершення

У разі відмови виконання команди модем повертає розширений код помилки за стандартом 3GPP TS 27.007 (при увімкненому режимі `AT+CMEE=1`):

| Код помилки | Константа 3GPP | Причина виникнення та спосіб усунення |
|:---|:---|:---|
| `+CME ERROR: 10` | SIM not inserted | Фізична відсутність SIM-картки або брудні контакти слота |
| `+CME ERROR: 11` | SIM PIN required | Потрібно ввести PIN-код за допомогою `AT+CPIN="0000"` |
| `+CME ERROR: 13` | SIM failure | Апаратний збій чіпа SIM-картки або несумісність рівнів напруги (1.8V / 3.0V) |
| `+CME ERROR: 30` | No network service | Відсутність радіопокриття або пошкодження коаксіального кабелю антени |
| `+CME ERROR: 100` | Unknown error | Внутрішній тайм-аут стека радіопротоколів модему |
| `+CME ERROR: 107` | GPRS services not allowed | Тарифний план абонента не підтримує передачу пакетних даних |
