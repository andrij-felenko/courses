# 📋 Довідник структур маніфестів HLS (M3U8) та MPEG-DASH (MPD)

У цьому довіднику наведено повну специфікацію синтаксису, структурних інваріантів, атрибутів та поведінкових контрактів маніфестів Apple HLS (RFC 8216 / RFC 8216bis) та MPEG-DASH (ISO/IEC 23009-1), а також бінарну ієрархію атомів медіаконтейнера CMAF fMP4 (ISO/IEC 23000-19).

---

### 1. Архітектурна модель та синтаксис Apple HLS

Протокол Apple HTTP Live Streaming (HLS) організовує трансляцію за допомогою текстових файлів плейлистів у кодуванні UTF-8 із розширенням `.m3u8`. Плейлисти будуються на основі розширеного формату M3U та використовують директиви-теги, що починаються з префікса `#EXT`.

Усі теги в HLS є чутливими до регістру і діляться на дві ієрархічні категорії:
1. **Головний плейлист (Multivariant Playlist або Master Playlist):** точка входу для клієнта. Описує доступні альтернативні варіанти потоку (відео різної чіткості, багатомівні аудіодоріжки, субтитри) та пов'язує їх через спільні групи.
2. **Медіа-плейлист (Media Playlist):** індекс конкретного медіапотоку. Містить упорядкований за часом список посилань на файли медіасегментів (чанків) із зазначенням їхньої точної тривалості.

```m3u8
#EXTM3U
#EXT-X-VERSION:7
#EXT-X-INDEPENDENT-SEGMENTS

#EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="audio-aac",NAME="Українська",DEFAULT=YES,AUTOSELECT=YES,LANGUAGE="uk",URI="audio_uk.m3u8"
#EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="audio-aac",NAME="English",DEFAULT=NO,AUTOSELECT=YES,LANGUAGE="en",URI="audio_en.m3u8"

#EXT-X-STREAM-INF:BANDWIDTH=6000000,AVERAGE-BANDWIDTH=5500000,RESOLUTION=1920x1080,FRAME-RATE=60.000,CODECS="avc1.64002a,mp4a.40.2",AUDIO="audio-aac"
1080p/index.m3u8

#EXT-X-STREAM-INF:BANDWIDTH=3000000,AVERAGE-BANDWIDTH=2800000,RESOLUTION=1280x720,FRAME-RATE=60.000,CODECS="avc1.4d401f,mp4a.40.2",AUDIO="audio-aac"
720p/index.m3u8

#EXT-X-STREAM-INF:BANDWIDTH=1200000,AVERAGE-BANDWIDTH=1100000,RESOLUTION=854x480,FRAME-RATE=30.000,CODECS="avc1.4d401e,mp4a.40.2",AUDIO="audio-aac"
480p/index.m3u8
```

#### Довідник директив головного плейлиста HLS

Директива `#EXTM3U` є обов'язковим заголовком першого рядка будь-якого коректного HLS-файлу. Якщо файл не починається з цього рядка, парсер відеоплеєра зобов'язаний негайно відхилити документ як невалідний.

Директива `#EXT-X-VERSION` вказує на мінімальну версію клієнтського протоколу, необхідну для коректної інтерпретації тегів. Для сучасних потоків на базі контейнера fMP4 обов'язковою є версія 7 або вище.

Директива `#EXT-X-INDEPENDENT-SEGMENTS` декларує глобальний контракт: кожен медіасегмент у всіх дочірніх плейлистах починається із замкненого ключового кадру (Closed GOP IDR-кадру) і може декодуватися абсолютно автономно без декодування попередніх або наступних сегментів. Наявність цього тегу дозволяє ABR-рушію безшовно перемикати якість на межі будь-якого сегмента.

Директива `#EXT-X-MEDIA` описує додаткові медіаресурси, які транслюються окремо від основного відео:
- `TYPE`: вказує на тип медіапотоку (`AUDIO`, `SUBTITLES`, `CLOSED-CAPTIONS`, `VIDEO`).
- `GROUP-ID`: символьний ідентифікатор групи, за яким тег зв'язується з відповідним атрибутом `AUDIO="group-id"` у відеоплейлистах.
- `NAME`: людиночитана назва доріжки для відображення в інтерфейсі вибору мови користувачем.
- `DEFAULT`: прапорець `YES` або `NO`, який вказує, чи слід обирати цю доріжку за замовчуванням при першому запуску.
- `AUTOSELECT`: дозволяє плеєру автоматично вибрати доріжку відповідно до мовних налаштувань операційної системи користувача.
- `LANGUAGE`: мовний код у стандарті ISO 639-1 або ISO 639-2.
- `URI`: відносний або абсолютний шлях до медіа-плейлиста цієї доріжки.

Директива `#EXT-X-STREAM-INF` передує URI-посиланню на медіа-плейлист конкретної відеоякості та задає параметри потоку:
- `BANDWIDTH`: ціле число, що виражає піковий бітрейт потоку в бітах за секунду. Враховує відеодані, аудіодані та протокольний оверхед контейнера. ABR-рушій використовує цей параметр для перевірки відповідності пропускній здатності каналу.
- `AVERAGE-BANDWIDTH`: середній бітрейт за весь хронометраж відео. Використовується прогресивними алгоритмами для точнішого планування заповнення буфера.
- `RESOLUTION`: розмір відеокадру в пікселях у форматі `ШиринаxВисота` (наприклад, `1920x1080`).
- `FRAME-RATE`: максимальна частота кадрів у потоці у вигляді десяткового дробу (наприклад, `60.000` або `29.970`).
- `CODECS`: рядок у подвійних лапках, що містить стандартизовані за RFC 6381 ідентифікатори кодеків та профілів. Наприклад, рядок `"avc1.64002a,mp4a.40.2"` вказує на відеокодек H.264 High Profile Level 4.2 та аудіокодек AAC-LC.
- `AUDIO`: рядок, який посилається на ідентифікатор `GROUP-ID` відповідної аудіодоріжки.

### 2. Специфікація медіа-плейлиста HLS

Медіа-плейлист описує конкретну доріжку і перелічує послідовність чанків. Залежно від типу мовлення, плейлист функціонує в одному з двох режимів:
- **Відео на вимогу (VoD, Video on Demand):** статичний документ, який містить вичерпний перелік усіх сегментів фільму і закінчується обов'язковим термінальним тегом `#EXT-X-ENDLIST`. Плеєр завантажує його один раз на початку сесії.
- **Прямий ефір (Live Streaming):** динамічний документ, який представляє ковзне вікно трансляції (Sliding Window). Нові сегменти дописуються в кінець файлу, а застарілі чанки видаляються з початку. Тег `#EXT-X-ENDLIST` відсутній. Плеєр періодично перезавантажує плейлист із періодом, що дорівнює тривалості одного чанка.

```m3u8
#EXTM3U
#EXT-X-VERSION:7
#EXT-X-TARGETDURATION:6
#EXT-X-MEDIA-SEQUENCE:1042
#EXT-X-PLAYLIST-TYPE:VOD

#EXT-X-MAP:URI="init.mp4"

#EXTINF:6.000,
segment_1042.m4s
#EXTINF:6.000,
segment_1043.m4s
#EXTINF:5.833,
segment_1044.m4s

#EXT-X-ENDLIST
```

#### Довідник директив медіа-плейлиста

Директива `#EXT-X-TARGETDURATION` є критично важливим обов'язковим параметром. Вона задає верхню межу тривалості будь-якого медіасегмента в цьому плейлисті в цілих секундах. Жоден наступний тег `#EXTINF` не може мати тривалість, яка після математичного заокруглення перевищує `TARGETDURATION`. Порушення цього правила вважається фатальною помилкою синтаксису HLS.

Директива `#EXT-X-MEDIA-SEQUENCE` визначає цілочисельний порядковий номер першого сегмента, наведеного у файлі плейлиста. У Live-трансляціях під час випадання найстарішого чанка з ковзного вікна значення `MEDIA-SEQUENCE` інкрементується на одиницю. Це дає змогу клієнтському плеєру однозначно співвідносити чанки між різними оновленнями плейлиста.

Директива `#EXT-X-MAP` є обов'язковою для сегментів у форматі fragmented MP4 (`fMP4`). Вона вказує URI-посилання на ініціалізаційний сегмент (`init.mp4`), що містить метадані контейнера (атоми `ftyp` та `moov`). Без попереднього згодовування ініціалізаційного сегмента апаратний декодер не може розпакувати медійні чанки `.m4s`.

Директива `#EXTINF` передує посиланню на кожен окремий медіафайл. Вона задає точну астрономічну тривалість сегмента в секундах із десятковою крапкою (наприклад, `#EXTINF:6.000,`). Необов'язковий рядок після коми може містити довільну назву сегмента.

Директива `#EXT-X-DISCONTINUITY` встановлюється між двома сегментами, якщо між ними відбувається кардинальна зміна характеристик потоку: скидання часових міток декодера (PTS/DTS), зміна формату стиснення, роздільної здатності чи частоти кадрів (типово виникає при вставці динамічної реклами Server-Side Ad Insertion). Побачивши цей тег, відеоплеєр скидає внутрішній стан конвеєра декодування, уникаючи зависання.

Директива `#EXT-X-BYTERANGE` дозволяє розбити один великий суцільний медіафайл на логічні чанки. Вона приймає параметр у форматі `довжина@зміщення` (у байтах), наказуючи відеоплеєру завантажувати чанк через стандартний HTTP-заголовок `Range: bytes=offset-(offset+length-1)`.

Директива `#EXT-X-ENDLIST` сигналізує про повне завершення медіапотоку. Отримавши цей тег, плеєр знає, що нових сегментів не з'явиться, і припиняє фонові опитування сервера.

### 3. Специфікація наднизької затримки (Low-Latency HLS)

Стандарт LL-HLS (Apple RFC 8216bis) зменшує відставання від прямого ефіру з 15–30 секунд до 1.5–3 секунд за рахунок генерації мікросегментів (Parts) тривалістю 200–330 мілісекунд.

```m3u8
#EXT-X-SERVER-CONTROL:CAN-BLOCK-RELOAD=YES,PART-HOLD-BACK=0.600,CAN-SKIP-UNTIL=12.0
#EXT-X-PART-INF:PART-TARGET=0.200

#EXT-X-PART:DURATION=0.200,URI="part_1045.0.m4s",INDEPENDENT=YES
#EXT-X-PART:DURATION=0.200,URI="part_1045.1.m4s"
#EXT-X-PART:DURATION=0.200,URI="part_1045.2.m4s"
#EXTINF:0.600,
segment_1045.m4s

#EXT-X-PRELOAD-HINT:TYPE=PART,URI="part_1046.0.m4s"
#EXT-X-RENDITION-REPORT:URI="../720p/index.m3u8",LAST-MSN=1045,LAST-PART=2
```

#### Специфікація директив LL-HLS:

- `#EXT-X-SERVER-CONTROL`: повідомляє про підтримку сервером розширених функцій керування трафіком. Параметр `CAN-BLOCK-RELOAD=YES` активує механізм блокуючого завантаження плейлиста (Blocking Playlist Reload): клієнт надсилає запит на наступний маніфест заздалегідь із HTTP-параметрами `_HLS_msn=1046&_HLS_part=0`. Сервер утримує HTTP-з'єднання відкритим і надсилає відповідь у ту саму мілісекунду, коли новий мікрочанк записується кодером.
- `#EXT-X-PART-INF`: декларує цільову максимальну тривалість мікрочанка `PART-TARGET` у секундах.
- `#EXT-X-PART`: оголошує готовий до завантаження мікросегмент. Якщо мікросегмент починається з I-кадру, додається прапорець `INDEPENDENT=YES`.
- `#EXT-X-PRELOAD-HINT`: передає клієнту попереднє посилання на наступний мікрочанк, генерація якого ще триває в оперативній пам'яті транскодера. Клієнт може відкрити HTTP GET-запит на цей ресурс до того, як файл буде фізично завершено на диску.
- `#EXT-X-RENDITION-REPORT`: передає клієнту статус найсвіжіших сегментів в інших паралельних якостях без необхідності окремо завантажувати їхні повні маніфести, що мінімізує мережеві накладні витрати ABR-рушія.

### 4. Специфікація MPEG-DASH (ISO/IEC 23009-1)

Стандарт MPEG-DASH (Dynamic Adaptive Streaming over HTTP) використовує уніфікований XML-маніфест **MPD** (Media Presentation Description). Документ організований за суворою деревоподібною структурою чотирьох рівнів:

```
[MPD] — Кореневий опис медіасесії (параметри буфера, тип трансляції)
  └── [Period] — Часовий відрізок контенту (основна програма, реклама)
        ├── [AdaptationSet] — Набір потоків одного типу (Відео AVC, Відео HEVC, Аудіо)
        │     ├── [Representation id="1080p"] — Конкретний бітрейт і роздільна здатність
        │     │     └── [SegmentTemplate] — Математичний шаблон формування адрес чанків
        │     └── [Representation id="720p"]
        └── [AdaptationSet] — Набір аудіодоріжок
              └── [Representation id="audio_uk"]
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<MPD xmlns="urn:mpeg:dash:schema:mpd:2011"
     profiles="urn:mpeg:dash:profile:isoff-live:2011"
     type="dynamic"
     availabilityStartTime="2026-08-18T12:00:00Z"
     publishTime="2026-08-18T12:30:00Z"
     minBufferTime="PT2.0S"
     suggestedPresentationDelay="PT3.0S"
     maxSegmentDuration="PT2.0S">

  <Period id="P1" start="PT0S">
    <!-- Набір відеопотоків -->
    <AdaptationSet id="0"
                   contentType="video"
                   mimeType="video/mp4"
                   segmentAlignment="true"
                   subsegmentAlignment="true"
                   startWithSAP="1">

      <SegmentTemplate timescale="90000"
                       initialization="video/init-$RepresentationID$.mp4"
                       media="video/chunk-$RepresentationID$-$Number%05d$.m4s"
                       startNumber="1">
        <SegmentTimeline>
          <S t="0" d="180000" r="150" />
        </SegmentTimeline>
      </SegmentTemplate>

      <Representation id="1080p"
                      bandwidth="6000000"
                      width="1920"
                      height="1080"
                      frameRate="60/1"
                      codecs="avc1.64002a" />

      <Representation id="720p"
                      bandwidth="3000000"
                      width="1280"
                      height="720"
                      frameRate="60/1"
                      codecs="avc1.4d401f" />

      <Representation id="480p"
                      bandwidth="1200000"
                      width="854"
                      height="480"
                      frameRate="30/1"
                      codecs="avc1.4d401e" />
    </AdaptationSet>

    <!-- Набір аудіопотоків -->
    <AdaptationSet id="1"
                   contentType="audio"
                   mimeType="audio/mp4"
                   lang="uk"
                   segmentAlignment="true">

      <SegmentTemplate timescale="48000"
                       initialization="audio/init-$RepresentationID$.mp4"
                       media="audio/chunk-$RepresentationID$-$Number%05d$.m4s"
                       startNumber="1">
        <SegmentTimeline>
          <S t="0" d="96000" r="150" />
        </SegmentTimeline>
      </SegmentTemplate>

      <Representation id="audio_uk"
                      bandwidth="128000"
                      audioSamplingRate="48000"
                      codecs="mp4a.40.2" />
    </AdaptationSet>
  </Period>
</MPD>
```

#### Довідник XML-елементів та атрибутів MPEG-DASH

Елемент `<MPD>` є кореневим вузлом документа. Атрибут `type` приймає значення `static` для записів або `dynamic` для прямого ефіру. Атрибут `minBufferTime` визначає нормативний мінімальний розмір буфера у форматі тривалості ISO 8601 (наприклад, `PT2.0S` означає 2 секунди). Атрибут `availabilityStartTime` задає точний момент початку трансляції за шкалою UTC, що дозволяє клієнтському плеєру синхронізувати номер поточного живого сегмента без постійного опитування маніфесту.

Елемент `<Period>` групує медіаконтент на часовій шкалі. Якщо трансляція містить рекламні паузи з іншими параметрами кодування, кожна рекламна вставка оформлюється як окремий елемент `<Period>` зі своїм атрибутом `start` та тривалістю `duration`.

Елемент `<AdaptationSet>` об'єднує альтернативні варіанти одного медіатипу. Атрибут `segmentAlignment="true"` є найсуворішим інваріантом стандарту: він гарантує, що границі сегментів у всіх представленнях всередині набору повністю синхронізовані в часі. Атрибут `startWithSAP="1"` підтверджує, що кожен сегмент починається із замкненого точки доступу Stream Access Point (Closed IDR).

Елемент `<Representation>` задає характеристики конкретного потоку: `bandwidth` (бітрейт у біт/с), `width` та `height` (геометричні розміри), `frameRate` (частота кадрів) та рядок кодека `codecs`.

Елемент `<SegmentTemplate>` автоматизує генерацію адрес чанків без перелічування кожного файлу:
- Атрибут `timescale` вказує внутрішню частоту дискретизації таймлайну (наприклад, 90 000 Гц для відео, 48 000 Гц для аудіо).
- Атрибути `initialization` та `media` містять шаблони посилань зі спеціальними змінними підстановки:
  - `$RepresentationID$`: підставляє ідентифікатор якості (наприклад, `1080p`).
  - `$Number%05d$`: підставляє порядковий номер сегмента, форматований нулями до ширини 5 знаків (`00001`, `00002`).
  - `$Time$`: підставляє точний час початку сегмента в одиницях `timescale`.
  - `$Bandwidth$`: підставляє бітрейт потоку.

Таблиця `<SegmentTimeline>` містить перелік елементів `<S>`: атрибут `t` вказує час початку, `d` — тривалість чанка в тиках, `r` — кількість однакових повторень поспіль.

### 5. Бінарна ієрархія атомів контейнера CMAF fMP4

Специфікація CMAF (Common Media Application Format, ISO/IEC 23000-19) уніфікує медіаконтейнер для HLS та DASH на базі фрагментованого MP4 (ISO/IEC 14496-12 ISO-BMFF). Потік розбивається на два типи блоків:

#### 1. Ініціалізаційний блок (CMAF Header / `init.mp4`)

Файл завантажується відеоплеєром один раз при старті або перемиканні доріжки:
- `ftyp` (File Type Box): оголошує сумісність із брендами `cmfc`, `iso6`, `mp41`.
- `moov` (Movie Box): містить глобальні дескриптори треків:
  - `mvhd`: параметри часових шкал та загальної координатної сітки.
  - `trak`: опис конкретної медіадоріжки (відео або аудіо).
  - `mdia` -> `minf` -> `stbl` -> `stsd`: дескриптор кодека (SPS/PPS-параметри для H.264, VPS/SPS/PPS для HEVC). Медіадані відсутні.

#### 2. Медіафрагмент (CMAF Fragment / `chunk.m4s`)

Кожен 2-секундний чанк є атомарним файлом із двох кореневих боксів:
- `moof` (Movie Fragment Box): містить метадані кадрів фрагмента:
  - `mfhd`: порядковий номер фрагмента.
  - `traf`: дескриптор треку фрагмента.
  - `tfdt`: 64-бітне значення точної часової мітки першого кадру чанка (Base Media Decode Time).
  - `trun`: таблиця властивостей кожного кадру (тривалість `sample_duration`, розмір у байтах `sample_size`, прапорець ключового кадру `sample_flags`, зміщення композиції `sample_composition_time_offset`).
- `mdat` (Media Data Box): неперервний бінарний масив закодованих кадрів (NAL-юнітів). Завдяки таблиці `trun` декодер миттєво знаходить будь-який кадр у блоці `mdat` без лінійного сканування файлу.

### 6. Специфікація шифрування та систем захисту контенту (DRM / CENC)

Сучасні маніфести містять директиви для апаратного захисту комерційного відеоконтенту через системи цифрового керування правами (DRM, Digital Rights Management) за стандартом Common Encryption (CENC, ISO/IEC 23001-7).

#### Специфікація ключів у Apple HLS: директива `#EXT-X-KEY`

```m3u8
#EXT-X-KEY:METHOD=SAMPLE-AES,URI="skd://fairplay.example.com/key?id=1042",KEYFORMAT="com.apple.streamingkeydelivery",KEYFORMATVERSIONS="1"
```

##### Довідник атрибутів `#EXT-X-KEY`:
- `METHOD`: метод шифрування даних. `NONE` — відкритий потік; `AES-128` — поблокове симетричне шифрування всього чанка за стандартом AES-CBC з 128-бітним ключем; `SAMPLE-AES` — вибіркове шифрування окремих NAL-юнітів відеокадрів (використовується в системі Apple FairPlay).
- `URI`: адреса сервера видачі ліцензій (Key Server). Для протоколу FairPlay використовується спеціальна схема `skd://` (Streaming Key Delivery).
- `KEYFORMAT`: символьний ідентифікатор системи шифрування (наприклад, `"com.apple.streamingkeydelivery"` для FairPlay або `"identity"` для звичайного симетричного AES).
- `IV`: 128-бітний шістнадцятковий вектор ініціалізації (наприклад, `IV=0x1234567890abcdef1234567890abcdef`). Якщо опущений, за вектор ініціалізації береться порядковий номер сегмента `MEDIA-SEQUENCE`.

#### Специфікація систем захисту в MPEG-DASH: елемент `<ContentProtection>`

У маніфестах DASH дескриптори систем DRM розміщуються всередині блоку `<AdaptationSet>`:

```xml
<ContentProtection schemeIdUri="urn:mpeg:dash:mp4protection:2011" value="cenc" />

<!-- Google Widevine DRM -->
<ContentProtection schemeIdUri="urn:uuid:edef8ba9-79d6-4ace-a3c8-27dcd51d21ed">
  <cenc:pssh>AAAAMHBzc2gAAAAA7e+LqXnWSs6jyCfc1R0h7QAAAAAQAAACAAAA...</cenc:pssh>
</ContentProtection>

<!-- Microsoft PlayReady DRM -->
<ContentProtection schemeIdUri="urn:uuid:9a04f079-9840-4286-ab92-e65be0885f95">
  <mspr:pro>GAMAAAEAAQCsAzwAV1JNSEVBREVSIHhtbG5zPSJodHRwOi8vc2NoZW1hcy5taWNyb3NvZnQuY29tL0RST.../mspr:pro>
</ContentProtection>
```

##### Інваріанти елемента `<ContentProtection>`:
- `schemeIdUri="urn:mpeg:dash:mp4protection:2011"`: сигналізує про використання спільного шифрування CENC із 128-бітними ключами AES у режимі лічильника (`ctr1`) або зчеплення блоків (`cbcs`).
- `schemeIdUri="urn:uuid:edef8ba9-79d6-4ace-a3c8-27dcd51d21ed"`: стандартизований UUID системи Google Widevine Modular.
- `schemeIdUri="urn:uuid:9a04f079-9840-4286-ab92-e65be0885f95"`: стандартизований UUID системи Microsoft PlayReady.
- Тег `<cenc:pssh>`: містить закодований у Base64 бінарний бокс `pssh` (Protection System Specific Header), який відеоплеєр передає в апаратний модуль дешифрування CDM (Content Decryption Module) для отримання ключів від сервера ліцензій.

### 7. Правила HTTP-кешування та політики CDN для маніфестів і сегментів

Ефективність доставки адаптивного відео безпосередньо залежить від правильного налаштування HTTP-заголовків керування кешуванням на проміжних вузлах мережі доставки контенту (CDN Edge Servers).

#### 1. Політика для статичних медіасегментів (`.m4s`, `.ts`, `init.mp4`)
Оскільки сегменти є незмінними контентно-адресованими файлами, для них застосовують максимальний час зберігання в кеші:

```http
HTTP/1.1 200 OK
Content-Type: video/iso.segment
Cache-Control: public, max-age=31536000, immutable
Access-Control-Allow-Origin: *
Access-Control-Expose-Headers: Content-Length, Date
```

Заголовок `immutable` повідомляє браузеру та CDN, що файл гарантовано ніколи не зміниться на сервері, повністю забороняючи надсилання перевірочних HTTP-запитів `If-Modified-Since` або `If-None-Match`.

#### 2. Політика для живих плейлистів (Live Media Playlists)
У прямому ефірі динамічний плейлист постійно оновлюється з появою нових чанків. Кешування такого файлу довше ніж на тривалість одного сегмента зламає трансляцію:

```http
HTTP/1.1 200 OK
Content-Type: application/vnd.apple.mpegurl
Cache-Control: no-cache, no-store, must-revalidate, max-age=1
Age: 0
Access-Control-Allow-Origin: *
```

Для Live HLS сервер Origin встановлює `max-age` рівним половині тривалості сегмента (наприклад, `max-age=1` при 2-секундних чанках) або використовує блокуюче опитування HTTP/2 Server Push, щоб граничні вузли CDN не віддавали застарілі списки сегментів.
