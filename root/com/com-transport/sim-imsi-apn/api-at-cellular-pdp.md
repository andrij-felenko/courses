# 📋 Інтерфейс AT-команд 3GPP TS 27.007 для конфігурації PDP-контекстів та SIM

Специфікація **3GPP TS 27.007** («AT command set for User Equipment (UE)») та пов'язані стандарти 3GPP TS 27.005 і 3GPP TS 27.010 визначають уніфікований командний інтерфейс, через який хост-контролер взаємодіє з базовим процесором стільникового модема. Цей інтерфейс забезпечує прямий доступ до файлової системи смарт-картки UICC/USIM, опитування фізичних характеристик радіосигналу, реєстрацію в сотах мобільних операторів та повний життєвий цикл сесій пакетних даних (контекстів PDP / EPS Bearers / PDU Sessions).

Нижче наведено повний технічний довідник параметрів, синтаксису команд, режимів передачі даних, розширеного керування енергозбереженням та таблиць діагностичних статусних кодів.

---

### 1. Керування контекстами пакетних даних (PDP Context / EPS Bearer)

У термінології стільникових мереж контекст протоколу пакетних даних (**PDP Context**) є набором мережевих параметрів (тип протоколу, назва точки доступу APN, виділена IP-адреса, параметри якості обслуговування QoS), що однозначно ідентифікують логічний канал зв'язку між мобільним терміналом та опорною мережею.

#### `AT+CGDCONT` — Визначення конфігураційного профілю PDP-контексту

Команда створює або модифікує профіль контексту даних із заданим числовим ідентифікатором (`cid`).

**Повний синтаксис запису:**
```text
AT+CGDCONT=[<cid>[,<PDP_type>[,<APN>[,<PDP_addr>[,<data_comp>[,<head_comp>[,<IPv4AddrAlloc>[,<emergency_flag>[,<P-CSCF_discovery>[,<IM_CN_Signalling_Flag_Ind>[,<NSLPI>[,<SecurePkt>[,<IPv4_MTU_discovery>[,<Local_Addr_Ind>[,<Non-IP_MTU_discovery>]]]]]]]]]]]]]]]
```

**Детальний опис базових параметрів:**

| Параметр | Тип | Опис та діапазон значень |
|---|---|---|
| `<cid>` | Integer | Ідентифікатор контексту даних (Context Identifier, від `1` до `16` або до `31` у новітніх чипсетах). Значення `cid=1` у переважній більшості архітектур зарезервовано як головний контекст за замовчуванням (*Default EPS Bearer*), що автоматично підіймається при реєстрації в мережах LTE/5G. |
| `<PDP_type>` | String | Тип мережевого протоколу передачі даних:<br>• `"IP"` — протокол IPv4 (виділяється 32-бітна адреса);<br>• `"IPV6"` — протокол IPv6 (виділяється 64-бітний префікс інтерфейсу);<br>• `"IPV4V6"` — подвійний стек (Dual-Stack), модем одночасно отримує незалежні адреси IPv4 та IPv6;<br>• `"Non-IP"` — передача сирих даних без IP-заголовків (режим 3GPP Cellular IoT / NB-IoT Data over NAS);<br>• `"Ethernet"` — передача Ethernet-фреймів 2-го рівня (специфікація 5G Core Rel-15+). |
| `<APN>` | String | Текстовий рядок точки доступу (*Access Point Name*), що визначає цільовий пакетний шлюз (наприклад, `"internet"`, `"iot.vodafone.com"`, `"corporate.vpn"`). Порожній рядок `""` вказує модему запитати підписку за замовчуванням з бази даних HSS/UDM. |
| `<PDP_addr>` | String | Бажана статична адреса термінала. Для динамічного призначення залишається `"0.0.0.0"` або опускається. |
| `<data_comp>` | Integer | Апаратна компресія корисного навантаження даних:<br>• `0` — компресію вимкнено (рекомендовано);<br>• `1` — V.42bis;<br>• `2` — V.44. |
| `<head_comp>` | Integer | Компресія заголовків мережевих пакетів:<br>• `0` — компресію вимкнено;<br>• `1` — RFC 1144 (компресія заголовків TCP/IP Van Jacobson для повільних ліній);<br>• `2` — RFC 2507;<br>• `3` — RFC 3095 (ROHC, Robust Header Compression — застосовується у VoLTE). |
| `<IPv4AddrAlloc>` | Integer | Метод виділення адреси IPv4:<br>• `0` — через сигнальні опції протоколу (NAS PCO, типовий метод у LTE);<br>• `1` — через протокол динамічної конфігурації вузла (DHCPv4). |

**Спеціальні команди опитування:**
* `AT+CGDCONT?` — зчитує поточний перелік усіх збережених профілів контекстів;
* `AT+CGDCONT=?` — повертає діапазон підтримуваних значень та доступних типів протоколів для конкретного модема.

#### `AT+CGACT` — Активація та деактивація сесії зв'язку

Команда ініціює процедуру сигналізації для переведення одного або декількох сконфігурованих профілів у стан `ACTIVE` (створення GTP-тунелів в опорній мережі) або `INACTIVE` (вивільнення ресурсів радіоканалу).

**Синтаксис:**
```text
AT+CGACT=<state>[,<cid>[,<cid>...]]
```

**Параметри:**
* `<state>`: `1` — активувати контекст; `0` — деактивувати контекст.
* `<cid>`: перелік цільових ідентифікаторів контекстів. Якщо параметр пропущено, команда застосовується до всіх наявних профілів.

При виклику `AT+CGACT=1,1` модем генерує повідомлення `Activate PDP Context Request` (у 2G/3G) або `PDN Connectivity Request` (у 4G). Час виконання команди може досягати 15–30 секунд у разі затримок сигналізації на боці опорної мережі оператора, тому хост-контролер повинен встановлювати розширений таймаут очікування відповіді.

---

#### `AT+CGDATA` — Перехід у режим прямої передачі даних

Команда перемикає інтерфейс послідовного порту UART модема з командного режиму AT у прозорий режим передачі пакетів даних (*Data Mode*) з використанням протоколу канального рівня (наприклад, PPP або raw IP).

**Синтаксис:**
```text
AT+CGDATA="<L2P>",<cid>
```
* `<L2P>` — протокол 2-го рівня (Layer 2 Protocol): `"PPP"` (Point-to-Point Protocol), `"M-COMM"` (виробничий режим модема) або `"NULL"` (сирий безпосередній потік IP-пакетів).

---

#### `AT+CGPADDR` — Отримання виділених IP-адрес

Повертає поточні мережеві адреси, призначені шлюзом PGW/UPF для вказаного ідентифікатора контексту після успішної активації.

**Формат відповіді:**
```text
+CGPADDR: <cid>,"<IP_address>"[,"<IPv6_address>"]
```

---

#### `AT+CGCONTRDP` — Зчитування розширених динамічних параметрів маршрутизації

Команда повертає повний спектр мережевих налаштувань, отриманих від вузла PGW через контейнер параметрів конфігурації протоколу (**PCO**, *Protocol Configuration Options*).

**Синтаксис:**
```text
AT+CGCONTRDP[=<cid>]
```

**Формат відповіді:**
```text
+CGCONTRDP: <cid>,<bearer_id>,"<apn>","<ip_addr_and_subnet_mask>","<gw_addr>","<dns_prim>","<dns_sec>","<p_cscf_prim>","<p_cscf_sec>",...,[<mtu>]
```

**Поля відповіді:**
1. `<cid>` — ідентифікатор контексту;
2. `<bearer_id>` — унікальний ідентифікатор радіоканалу (EPS Bearer ID, призначений базовою станцією);
3. `<apn>` — фактично підтверджена назва точки доступу (після обробки домашнім HSS);
4. `<ip_addr_and_subnet_mask>` — призначена IP-адреса та маска підмережі;
5. `<gw_addr>` — адреса шлюзу за замовчуванням;
6. `<dns_prim>`, `<dns_sec>` — IP-адреси первинного та вторинного серверів DNS;
7. `<p_cscf_prim>`, `<p_cscf_sec>` — адреси серверів сигналізації SIP/IMS для голосових викликів VoLTE;
8. `<mtu>` — рекомендований максимальний розмір блоку передачі даних для стільникового каналу (зазвичай 1420–1500 байтів).

### 2. Автентифікація в корпоративних точках доступу APN

Закриті корпоративні APN для захисту від несанкціонованого входу вимагають передачі облікових даних користувача за протоколами **PAP** (*Password Authentication Protocol*) або **CHAP** (*Challenge Handshake Authentication Protocol*).

#### `AT+CGAUTH` — Стандартна автентифікація 3GPP TS 27.007

**Синтаксис:**
```text
AT+CGAUTH=<cid>,<auth_prot>,"<password>","<username>"
```

**Параметри `<auth_prot>`:**
* `0` — Автентифікацію вимкнено (None);
* `1` — Протокол PAP (пароль передається у відкритому вигляді всередині шифрованого тунелю сигналізації NAS);
* `2` — Протокол CHAP (перевірка за схемою виклик-відповідь на основі хешу MD5);
* `3` — Автоматичний вибір протоколу (PAP або CHAP за запитом шлюзу PGW).

#### `AT$QCPDPP` — Специфікація для чипсетів Qualcomm

На багатьох модемах (Quectel EC25, SIMCom SIM7600, Telit LE910) використовується фірмова команда Qualcomm:
```text
AT$QCPDPP=<cid>,<auth_prot>,"<password>","<username>"
```

### 3. Низькорівневий доступ до файлової системи смарт-картки SIM

#### `AT+CPIN` — Керування статусом захисту SIM

Команда перевіряє готовність криптографічного чипа або передає персональний код розблокування.

* `AT+CPIN?` — опитування стану.
* `AT+CPIN="<PIN>"` — надсилання 4-значного коду PIN1.
* `AT+CPIN="<PUK>","<NEW_PIN>"` — розблокування картки 8-значним PUK-кодом після вичерпання спроб введення PIN.

**Можливі значення статусу `+CPIN:`:**
* `READY` — смарт-картка готова до виконання криптографічних операцій;
* `SIM PIN` — картка заблокована і очікує введення PIN1;
* `SIM PUK` — картка заблокована і вимагає PUK1;
* `SIM PIN2` / `SIM PUK2` — блокування додаткових службових функцій (FDN — фіксовані номери);
* `NOT INSERTED` — картка фізично відсутня або порушено контакт на лініях SIM_CLK/SIM_DATA.

---

#### `AT+CRSM` — Обмежений доступ до файлової системи SIM (*Restricted SIM Access*)

Команда `AT+CRSM` дозволяє хост-контролеру надсилати елементарні команди стандарту ISO/IEC 7816-4 безпосередньо до файлів смарт-картки без розгортання повного стека протоколів смарт-карт.

**Синтаксис:**
```text
AT+CRSM=<command>,<fileid>[,<p1>,<p2>,<p3>[,<data>[,<pathid>]]]
```

**Параметри:**
* `<command>`: числовий код команди APDU:
  * `176` (`0xB0`) — `READ BINARY` (читання байтів із прозорого файлу);
  * `178` (`0xB2`) — `READ RECORD` (читання фіксованого запису);
  * `214` (`0xD6`) — `UPDATE BINARY` (запис байтів у прозорий файл);
  * `220` (`0xDC`) — `UPDATE RECORD` (модифікація запису в лінійному файлі);
  * `192` (`0xC0`) — `GET RESPONSE` (отримання розширеного звіту статусу).
* `<fileid>`: 16-бітний ідентифікатор цільового файлу (наприклад, `12258` для `EF_ICCID`, `28423` для `EF_IMSI`).
* `<p1>`, `<p2>`, `<p3>`: стандартні параметри ISO/IEC 7816:
  * `<p1>, <p2>` — зміщення в байтах (Offset) від початку файлу або номер запису (Record Number);
  * `<p3>` — кількість байтів для читання або довжина блоку запису.
* `<data>`: шістнадцятковий рядок даних для операцій запису.

**Формат відповіді:**
```text
+CRSM: <sw1>,<sw2>,"<response_data>"
```

**Таблиця інтерпретації статусних байтів смарт-картки (SW1 / SW2):**

| Байти `SW1 SW2` | Значення та інженерна інтерпретація |
|---|---|
| `90 00` | **Успішне виконання команди (Normal completion)** |
| `91 XX` | Успішно, смарт-картка має додаткову проактивну подію для термінала (SIM Toolkit) |
| `98 04` | **Помилка автентифікації (MAC Failure)** — виявлено спробу підробки базової станції |
| `98 05` | **Розсинхронізація лічильника SQN (Sync Failure)** — потрібна ресинхронізація AUTS |
| `67 00` | Неправильна довжина поля `L_c` або `L_e` (Wrong length) |
| `6A 82` | **Файл не знайдено (File not found)** — зазначений `fileid` відсутній у поточному каталозі |
| `69 82` | Порушено умови безпеки (Security status not satisfied — потрібне введення PIN-коду) |

### 4. Опитування стану реєстрації та якості сигналу

#### `AT+CEREG` — Реєстрація в мережі 4G LTE (*EPS Network Registration Status*)

**Синтаксис конфігурації:**
```text
AT+CEREG=<n>   [0: вимкнути URC, 1: увімкнути базові сповіщення, 2: розширені сповіщення з кодом соти TAC/CI]
```

**Формат відповіді `AT+CEREG?`:**
```text
+CEREG: <n>,<stat>[,<tac>,<ci>[,<AcT>]]
```

**Значення параметра `<stat>`:**
* `0` — Пристрій не зареєстрований, пошук базових станцій не виконується;
* `1` — **Пристрій успішно зареєстровано в домашній мережі (Home Network)**;
* `2` — Пристрій не зареєстрований, триває активний пошук мережі та вимірювання сотових сигналів;
* `3` — **Реєстрацію відхилено мережею (Registration Denied)**;
* `4` — Невідомий стан (помилка модема або тимчасова втрата радіочастотного тракту);
* `5` — **Пристрій зареєстровано в роумінгу (Roaming Network)**.

---

#### `AT+CESQ` — Розширені показники якості сигналу LTE/5G

На відміну від застарілої команди `AT+CSQ`, що надавала лише усереднений рівень сигналу без прив'язки до смуги частот, команда `AT+CESQ` надає прецизійні радіочастотні метрики:

**Формат відповіді:**
```text
+CESQ: <rxlev>,<ber>,<rscp>,<ecno>,<rsrq>,<rsrp>
```

* **RSRP (Reference Signal Received Power, параметр `<rsrp>`):** абсолютний рівень потужності пілотних сигналів базової станції в діапазоні від -140 дБм до -44 дБм:
```
RSRP (дБм) = <rsrp> - 140
```
Значення вище -85 дБм свідчить про відмінний прийом; нижче -115 дБм — про граничну межу впевненого зв'язку.

* **RSRQ (Reference Signal Received Quality, параметр `<rsrq>`):** якість отриманого опорного сигналу з урахуванням внутрішньоканальної інтерференції та загального шуму в діапазоні від -19.5 дБ до -3 дБ:
```
RSRQ (дБ) = (<rsrq> · 0.5) - 19.5
```
Значення вище -10 дБ свідчить про низький рівень завад; значення нижче -15 дБ вказує на високу завантаженість соти іншими абонентами або наявність сильної міжканальної інтерференції.

### 5. Енергозбереження: режими PSM та eDRX

Для автономних пристроїв інтернету речей, що живляться від батарей (розумні лічильники, трекери, сейсмічні датчики), стандарти 3GPP Release 12/13 передбачають спеціальні механізми зниження енергоспоживання при збереженні активного PDP-контексту.

```
┌────────────────────────────────────────────────────────────────────────┐
│ Часова шкала переходу в режим глибокого сну PSM:                      │
│                                                                        │
│ [ Передача даних ] ──> [ Таймер T3324 (Active Timer) ] ──> [ Сон PSM ] │
│   (Струм: 100-300 мА)   (Прийом вхідних даних: 10-30 мА)  (T3412: 3 мкА)│
│                          Модем доступний для пейджингу    Модем вимкнений│
└────────────────────────────────────────────────────────────────────────┘
```

#### `AT+CPSMS` — Конфігурація режиму глибокого сну (*Power Saving Mode, PSM*)

У режимі PSM модем повністю вимикає приймач і передавач, знижуючи струм споживання до `2–5 мкА`, проте зберігає зареєстрований стан в опорній мережі та відкритий PDP-контекст. Мережа знає, що термінал спить, і не відключає його за неактивність.

**Синтаксис:**
```text
AT+CPSMS=<mode>[,<Requested_Periodic_RAU>[,<Requested_GPRS_READY_timer>[,<Requested_Periodic_TAU>[,<Requested_Active_Time>]]]]
```

* `<mode>`: `1` — увімкнути PSM, `0` — вимкнути PSM.
* `<Requested_Periodic_TAU>` (таймер `T3412`): періодичність пробудження для підтвердження присутності (наприклад, раз на 24 години).
* `<Requested_Active_Time>` (таймер `T3324`): час, протягом якого модем залишається в активному режимі після передачі пакета для прийому можливих відповідей від сервера (наприклад, 10 секунд).

### 6. Мультиплексування каналів за протоколом 3GPP TS 27.010 (CMUX)

Якщо пристрій підключено до модема через один фізичний UART, передача даних у режимі `AT+CGDATA` заблокувала б можливість паралельного опитування рівня сигналу або відправки SMS. Для вирішення цієї проблеми застосовується протокол мультиплексування **CMUX** (3GPP TS 27.010).

Після відправки команди `AT+CMUX=0` фізичний послідовний інтерфейс перетворюється на кілька незалежних віртуальних логічних каналів (**DLCI**, *Data Link Connection Identifier*):
* **DLCI 0:** службовий канал сигналізації та керування потоком;
* **DLCI 1:** перший віртуальний канал AT-команд (опитування CSQ, CEREG, GPS);
* **DLCI 2:** другий віртуальний канал для транзиту пакетних даних PPP або IP-стека;
* **DLCI 3:** виділений канал для надсилання та отримання SMS/VoLTE сигналізації.

### 7. Таблиця розширених кодів помилок модема (+CME ERROR)

| Код | Назва помилки | Фізична причина та інженерна дія |
|---|---|---|
| `10` | `SIM not inserted` | Відсутній контакт із чипом SIM, тримач відкритий або збій живлення лінії VCC. |
| `11` | `SIM PIN required` | Картка заблокована. Потрібно надіслати `AT+CPIN="<pin>"`. |
| `12` | `SIM PUK required` | Вичерпано 3 спроби введення PIN. Потрібно ввести PUK. |
| `13` | `SIM failure` | Апаратна аварія смарт-картки (збій внутрішньої Flash, вихід з ладу крипточипа). |
| `14` | `SIM busy` | Картка виконує внутрішні криптографічні розрахунки або оновлює файлову систему. |
| `30` | `No network service` | Відсутній радіосигнал або базова станція не підтримує заданий стандарт (RAT). |
| `103` | `Illegal MS` | Мережа відхилила модем за підозрою у використанні невалідного або клонованого IMEI. |
| `106` | `Illegal ME` | Обладнання заблоковано в чорному списку операторів (база EIR крадених телефонів). |
| `107` | `GPRS services not allowed` | У підписці абонента відключено пакетні дані (SIM-карта лише для голосу). |
| `132` | `Service option not supported` | Запитаний тип PDP (наприклад, IPv6) не підтримується опорною мережею. |
| `133` | `Service option not subscribed` | Назва APN не прописана в підписці абонента на сервері HSS. |
| `134` | `Service option temporarily out of order` | Тимчасовий збій шлюзу PGW/SGW на боці оператора (потрібно повторити спробу). |
| `149` | `PDP authentication failure` | Помилка логіна/пароля в командах `AT+CGAUTH` або `AT$QCPDPP`. |
