# 🧮 Алгоритмічний набір Milenage та криптографічний протокол 3GPP AKA

Взаємна автентифікація мобільного термінала та опорної мережі стільникового зв'язку (3G UMTS, 4G LTE та 5G NR) спирається на протокол **3GPP AKA** (*Authentication and Key Agreement*, 3GPP TS 33.102) та стандартизований алгоритмічний набір **Milenage** (3GPP TS 35.205 / TS 35.206). Цей криптографічний механізм розв'язує фундаментальну суперечність бездротового зв'язку: оператор і користувач повинні взаємно підтвердити автентичність один одного та виробити спільні сесійні ключі шифрування й контролю цілісності через відкритий ненадійний радіоефір, ніколи не передаючи в канал постійний секретний ключ `Ki`.

Нижче наведено покроковий математичний апарат обчислення функцій набору Milenage, структуру векторів автентифікації та процедуру обробки розсинхронізації лічильників послідовності.

---

### 1. Вхідні параметри та конфігурація оператора

Алгоритми Milenage базуються на симетричному блочному шифрі **AES-128** (Rijndael) із довжиною блоку 128 бітів та розміром ключа 128 бітів.

Набір оперує такими величинами:

* `Ki` (128 бітів) — індивідуальний довгостроковий секретний ключ абонента, прошитий у захищеній пам'яті карти USIM і збережений у центрі автентифікації AuC/HSS оператора;
* `RAND` (128 бітів) — випадкове число-виклик, що генерується апаратним TRNG центрі автентифікації мережі для кожного сеансу;
* `SQN` (48 бітів) — лічильник послідовності (*Sequence Number*), що монотонно зростає і запобігає атакам повторного відтворення (replay attacks);
* `AMF` (16 бітів) — поле керування автентифікацією (*Authentication Management Field*), що задає службові прапорці та версію алгоритму;
* `OP` (128 бітів) — секретний конфігураційний параметр оператора (*Operator Variant Algorithm Configuration Field*), спільний для всіх SIM-карт певної мережі;
* `OPc` (128 бітів) — похідне значення від `OP` та `Ki`, яке записується на USIM замість відкритого `OP`, щоб викрадення однієї карти не скомпрометувало весь пул оператора.

#### Обчислення похідного параметра `OPc`

Похідний параметр `OPc` розраховується за формулою:

```
TEMP = AES-128(Ki, OP)        [шифрування блоку OP ключем Ki]
OPc  = TEMP ⊕ OP              [побітове додавання за модулем 2 з вихідним OP]
```

Якщо карта або центр автентифікації використовує `OPc`, пряме значення `OP` більше не потрібне для подальших розрахунків.

### 2. Математична структура функцій Milenage (f1–f5)

Набір Milenage визначає сім базових криптографічних функцій:
1. `f1` — обчислення мережевого коду автентифікації повідомлення `MAC-A` (Message Authentication Code);
2. `f1*` — обчислення коду автентифікації при повторній синхронізації `MAC-S`;
3. `f2` — генерація очікуваної відповіді термінала `RES` / `XRES`;
4. `f3` — генерація 128-бітного сесійного ключа шифрування `CK` (*Cipher Key*);
5. `f4` — генерація 128-бітного сесійного ключа контролю цілісності `IK` (*Integrity Key*);
6. `f5` — генерація 48-бітного ключа анонімності `AK` (*Anonymity Key*) для маскування лічильника `SQN`;
7. `f5*` — генерація ключа анонімності `AK` при повторній синхронізації.

#### Базові нормативні константи (3GPP TS 35.206)

Для забезпечення незалежності вихідних значень функцій застосовуються фіксовані циклічні зсуви `r1..r5` (кількість бітів) та 128-бітні константи додавання `c1..c5`:

```
r1 = 64,  r2 = 0,   r3 = 32,  r4 = 64,  r5 = 96
c1 = 00000000 00000000 00000000 00000000 (у шістнадцятковому вигляді)
c2 = 00000000 00000000 00000000 00000001 (молодший біт = 1)
c3 = 00000000 00000000 00000000 00000002
c4 = 00000000 00000000 00000000 00000004
c5 = 00000000 00000000 00000000 00000008
```

#### Крок 1: Обчислення проміжного блоку `TEMP`

На першому кроці формується 128-бітний блок шляхом маскування випадкового числа `RAND`:

```
TEMP = AES-128(Ki, RAND ⊕ OPc)   [шифрування замаскованого виклику RAND на ключі Ki]
```

#### Крок 2: Обчислення коду автентифікації мережі `MAC-A` (функція `f1`)

Формується 128-бітний конкатенований блок `IN1`:

```
IN1 = SQN[48] || AMF[16] || SQN[48] || AMF[16]   [дублювання лічильника та поля керування до 128 бітів]
```

Далі виконується циклічний зсув `TEMP` вліво на `r1 = 64` біти та шифрування:

```
ROT1 = (TEMP <<< 64)                             [циклічний зсув проміжного блоку на 64 біти]
VAL1 = ROT1 ⊕ IN1 ⊕ c1                           [накладання маски IN1 та константи c1]
OUT1 = AES-128(Ki, VAL1 ⊕ OPc) ⊕ OPc             [фінальний раунд AES та XOR з OPc]
MAC-A = OUT1[0..63]                              [виділення старших 64 бітів як автентифікаційного тегу]
```

#### Крок 3: Обчислення відповіді `RES` (функція `f2`) та ключа анонімності `AK` (функція `f5`)

Для функцій `f2` та `f5` використовується константа `c2` та нульовий зсув `r2 = 0`:

```
ROT2 = TEMP                                      [зсув r2 = 0, блок залишається без змін]
VAL2 = ROT2 ⊕ c2                                 [накладання константи c2 на проміжний блок]
OUT2 = AES-128(Ki, VAL2 ⊕ OPc) ⊕ OPc             [раунд AES на ключі Ki]
RES  = OUT2[64..127]                             [молодші 64 біти призначаються як відгук термінала RES/XRES]
AK   = OUT2[0..47]                               [старші 48 бітів призначаються як ключ анонімності AK]
```

#### Крок 4: Обчислення сесійного ключа шифрування `CK` (функція `f3`)

Для вироблення ключа `CK` застосовується циклічний зсув на `r3 = 32` біти та константа `c3`:

```
ROT3 = (TEMP <<< 32)                             [циклічний зсув TEMP на 32 біти вліво]
VAL3 = ROT3 ⊕ c3                                 [накладання константи c3]
CK   = AES-128(Ki, VAL3 ⊕ OPc) ⊕ OPc             [128-бітний ключ шифрування каналу трафіку]
```

#### Крок 5: Обчислення сесійного ключа цілісності `IK` (функція `f4`)

Для вироблення ключа `IK` застосовується зсув на `r4 = 64` біти та константа `c4`:

```
ROT4 = (TEMP <<< 64)                             [циклічний зсув TEMP на 64 біти вліво]
VAL4 = ROT4 ⊕ c4                                 [накладання константи c4]
IK   = AES-128(Ki, VAL4 ⊕ OPc) ⊕ OPc             [128-бітний ключ контролю цілісності сигналізації]
```

### 3. Формування та верифікація вектора автентифікації

Операторський центр автентифікації AuC/HSS генерує 5-компонентний вектор автентифікації `AV` (*Authentication Vector*):

```
AUTN = (SQN ⊕ AK) || AMF || MAC-A   [128-бітний токен автентифікації мережі]
AV   = (RAND, AUTN, XRES, CK, IK)   [повний кортеж вектора автентифікації]
```

Мережа надсилає мобільному терміналу лише пару `(RAND, AUTN)`.

```
Мережа (MME/HSS)                                  Мобільний термінал (UE / USIM)
       │                                                         │
       │─────── Запит автентифікації: (RAND, AUTN) ─────────────>│
       │                                                         │
       │                                              [ 1. Обчислення AK = f5(Ki, RAND) ]
       │                                              [ 2. Відновлення SQN = (SQN ⊕ AK) ⊕ AK ]
       │                                              [ 3. Обчислення XMAC = f1(Ki, SQN, RAND, AMF) ]
       │                                              [ 4. Перевірка: XMAC == MAC-A ? ]
       │                                              [ 5. Перевірка свіжості: SQN > SQN_max ? ]
       │                                              [ 6. Обчислення RES = f2, CK = f3, IK = f4 ]
       │                                                         │
       │<────── Відповідь автентифікації: RES ───────────────────│
       │                                                         │
[ Порівняння: RES == XRES ? ]                                    │
[ Взаємна довіра встановлена ]                                   │
```

#### Алгоритм дій всередині смарт-карти USIM

1. Карта отримує `RAND` та `AUTN = ConcSQN || AMF || MAC-A` через інтерфейс APDU.
2. Карта запускає AES-128 з внутрішнім ключем `Ki` та обчислює `AK = f5(Ki, RAND)`.
3. Виконується зняття маски з лічильника:
```
SQN = ConcSQN ⊕ AK     [відновлення відкритого значення SQN]
```
4. Карта розраховує очікуваний код автентифікації мережі `XMAC = f1(Ki, SQN, RAND, AMF)`.
5. **Верифікація мережі:** Якщо `XMAC ≠ MAC-A`, карта фіксує спробу атаки підробленої базової станції (*MAC Failure*) та повертає помилку `SW = 98 04`. Процедура негайно припиняється.
6. **Перевірка лічильника:** Якщо `XMAC == MAC-A`, карта порівнює `SQN` із внутрішнім максимальним зафіксованим значенням `SQN_max`. Якщо значення застаріле або знаходиться поза допустимим вікном перевірки (Replay Attack), карта ініціює процедуру синхронізації (*Sync Failure*, `SW = 98 05`).
7. Якщо обидві перевірки пройшли успішно, USIM оновлює свій стан `SQN_max = SQN`, розраховує `RES = f2(Ki, RAND)`, `CK = f3(Ki, RAND)`, `IK = f4(Ki, RAND)` і повертає `RES` терміналу.

---

### 4. Процедура синхронізації лічильників послідовності (AUTS)

Якщо при успішній перевірці `MAC-A` виявлено, що лічильник `SQN` оператора відстав від внутрішнього лічильника `SQN_MS` карти або перескочив вікно вперед (наприклад, через збій у базі даних HSS або заміну SIM між кількома пристроями), карта генерує токен ресинхронізації `AUTS` (*Authentication Token for Synchronization*).

Для захисту значення `SQN_MS` застосовуються функції `f1*` та `f5*`:

```
AK*   = f5*(Ki, RAND)                     [генерація маскувального ключа ресинхронізації]
MAC-S = f1*(Ki, SQN_MS, RAND, AMF)        [генерація коду підтвердження ресинхронізації]
AUTS  = (SQN_MS ⊕ AK*) || MAC-S           [112-бітний токен (48 бітів замаскованого лічильника + 64 біти MAC-S)]
```

Термінал передає повідомлення `Authentication Failure (Cause: Synch Failure, AUTS)` назад до MME та HSS.

Центр автентифікації HSS виконує такі кроки:
1. За отриманим `RAND` та збереженим ключем `Ki` обчислює `AK* = f5*(Ki, RAND)`.
2. Відновлює реальний лічильник карти `SQN_MS = (SQN_MS ⊕ AK*) ⊕ AK*`.
3. Перевіряє `MAC-S` за допомогою функції `f1*`.
4. Якщо підпис коректний, HSS оновлює свій генератор послідовностей так, щоб наступні вектори генерувалися з `SQN > SQN_MS`, і надсилає новий вектор `(RAND_new, AUTN_new)`.

Завдяки такій структурі набору Milenage протокол 3GPP AKA унеможливлює як компрометацію постійного ключа `Ki`, так і атаки відтворення старих сеансів зв'язку чи маніпуляції фальшивими викликами з боку перехоплювачів IMSI.
