# 📋 Довідник синтаксису 3GPP TS 27.007 та розширених AT-команд

Цей довідник містить повну специфікацію граматики синтаксису AT-команд згідно зі стандартами ITU-T V.250, 3GPP TS 27.007 (керування термінальним обладнанням стільникових мереж) та 3GPP TS 27.005 (служба повідомлень SMS), а також реєстр стандартних кодів результатів, повідомлень про помилки CME/CMS та типові конфігураційні послідовності для вбудованих систем.

## 1. Анатомія командного рядка та чотири синтаксичні форми

Кожен командний рядок, що надсилається хост-контролером (DTE — *Data Terminal Equipment*) до модема (DCE — *Data Circuit-terminating Equipment*), починається з префікса `AT` (або `at`) і завершується символом повернення каретки `<CR>` (ASCII `0x0D`, у коді мовами C/C++ позначається як `\r`). Символ переведення рядка `<LF>` (`0x0A` або `\n`) на вході модема ігнорується або сприймається як порожній розділювач.

У відповідь модем завжди формує кадр, обрамлений парою `<CR><LF>` на початку та наприкінці:
```
<CR><LF><Тіло відповіді або URC><CR><LF>
```

Згідно з 3GPP TS 27.007, усі розширені стільникові команди (з префіксом `+`) підтримують до чотирьох синтаксичних форм виклику:

| Тип синтаксису | Формат запиту | Призначення | Приклад запиту та відповіді |
|---|---|---|---|
| **Тестування (Test)** | `AT+<CMD>=?` | Запит списку підтримуваних параметрів і діапазонів значень | `AT+COPS=?`<br>`+COPS: (1,"Kyivstar","KS","25503",7),(0-4),(0-2)`<br>`OK` |
| **Читання (Read)** | `AT+<CMD>?` | Опитування поточного робочого стану або налаштування | `AT+CREG?`<br>`+CREG: 2,1,"1A2B","003C4D",7`<br>`OK` |
| **Запис (Write / Set)** | `AT+<CMD>=<p1>,<p2>...` | Встановлення нових значень конфігураційних параметрів | `AT+CGDCONT=1,"IP","internet"`<br>`OK` |
| **Виконання (Execution)** | `AT+<CMD>` | Запуск дії з параметрами за замовчуванням без аргументів | `AT+CGACT=1,1`<br>`OK` |

### Спеціальний режим введення даних (Prompt `> `)

Для команд, які передають довільні двійкові або текстові дані змінного розміру (відправка SMS через `AT+CMGS` або відправка сирих TCP/UDP пакетів у сокет через `AT+QISEND` / `AT+CIPSEND`), модем використовує проміжний стан промпту.

Після отримання команди модем повертає символ `>` і пробіл (`0x3E 0x20`) **без символів `<CR><LF>`**:
```
Хост  → AT+CMGS="+380501234567"\r
Модем → \r\n> 
Хост  → Текст повідомлення або байти пакету + <Ctrl+Z> (0x1A)
Модем → \r\n+CMGS: 42\r\n\r\nOK\r\n
```
Якщо хост вирішує скасувати передачу даних після появи промпту `>`, він надсилає символ `<ESC>` (ASCII `0x1B`).

## 2. Фінальні коди результатів та розширена діагностика помилок (CME / CMS)

Кожна транзакція завершується поверненням одного з фінальних кодів результату (*Final Result Codes*). Стандартні базові коди визначені в ITU-T V.250:

- `OK` — команду успішно розпізнано та виконано.
- `CONNECT [<speed>]` — з'єднання встановлено, модем перейшов у прозорий режим передачі даних.
- `RING` — виявлено сигнал вхідного виклику.
- `NO CARRIER` — зв'язок не встановлено або віддалена сторона розірвала з'єднання.
- `ERROR` — синтаксична помилка, невідома команда або апаратний збій.
- `NO DIALTONE` — у телефонній лінії відсутній сигнал готовності станції.
- `BUSY` — лінія абонента зайнята.
- `NO ANSWER` — віддалена сторона не відповідає протягом часу очікування (регістр S7).

### Налаштування звітування про помилки (`AT+CMEE`)

За замовчуванням при виникненні будь-якої помилки модем повертає лише сухий рядок `ERROR`. Для вбудованої системи це неприпустимо, оскільки неможливо розрізнити відсутність SIM-картки, неправильний APN чи відсутність покриття мережі.

Режим розширених помилок вмикається командою:
```
AT+CMEE=0  → Повертати тільки "ERROR"
AT+CMEE=1  → Повертати числовий код "+CME ERROR: <err>"
AT+CMEE=2  → Повертати числовий код і текстовий опис "+CME ERROR: SIM PIN required"
```

### Стандартні коди помилок обладнання та мережі CME (3GPP TS 27.007)

| Код CME | Текстова назва | Опис та рекомендована реакція хост-контролера |
|---|---|---|
| `0` | Phone failure | Апаратний збій радіотракту або процесора baseband (вимагає перезапуску модема) |
| `3` | Operation not allowed | Дія заборонена у поточному стані (наприклад, спроба з'єднання без реєстрації) |
| `4` | Operation not supported | Команда не підтримується прошивкою або конфігурацією модуля |
| `5` | PH-SIM PIN required | SIM-картка заблокована під конкретного оператора (Network Lock) |
| `10` | SIM not inserted | SIM-картка фізично не виявлена в слоті (перевірити детекцію контакту SIM_DET) |
| `11` | SIM PIN required | Необхідно ввести 4-значний PIN-код командою `AT+CPIN="XXXX"` |
| `12` | SIM PUK required | SIM заблокована після 3 невдалих спроб PIN, потрібен 8-значний PUK-код |
| `13` | SIM failure | Помилка обміну з SIM-карткою по шині ISO 7816 (окислення контактів / збій напруги) |
| `14` | SIM busy | Картка зайнята внутрішніми операціями (зачекати 500 мс і повторити запит) |
| `16` | Incorrect password | Введено невірний пароль блокування або PIN |
| `17` | SIM PIN2 required | Потрібен PIN2 для доступу до захищених лічильників чи списку FDN |
| `18` | SIM PUK2 required | Потрібен PUK2 для розблокування PIN2 |
| `20` | Memory full | Пам'ять SMS або телефонної книги переповнена |
| `21` | Invalid index | Запитано неіснуючий індекс комірки пам'яті SMS |
| `22` | Not found | Запитаний запис не знайдено |
| `30` | No network service | Відсутній радіосигнал стільникової мережі (пошук соти) |
| `32` | Emergency calls only | Доступні лише екстрені виклики (відсутня авторизація в мережі / відмова оператора) |
| `100` | Unknown error | Невизначена внутрішня помилка |

### Стандартні коди помилок служби SMS CMS (3GPP TS 27.005)

| Код CMS | Текстова назва | Опис причини помилки |
|---|---|---|
| `300` | ME failure | Збій апаратного забезпечення термінала (Mobile Equipment) |
| `301` | SMS service reserved | Служба SMS тимчасово зарезервована внутрішнім процесом |
| `302` | Operation not allowed | Дія з SMS заборонена у поточному стані |
| `304` | Invalid PDU mode parameter | Некоректні байти PDU-пакета (помилка форматування хостом) |
| `305` | Invalid text mode parameter | Некоректні параметри в текстовому режимі SMS (`AT+CMGF=1`) |
| `310` | SIM not inserted | Відсутня SIM-картка для збереження чи відправки повідомлення |
| `321` | SMS storage failure | Збій сховища повідомлень SIM / Flash-пам'яті |
| `330` | SC address unknown | Не вказано номер SMS-центру оператора (`AT+CSCA`) |
| `500` | Unknown error | Невідома мережева помилка відправки повідомлення |

## 3. Реєстр базових команд стільникового зв'язку (3GPP TS 27.007)

### 3.1. Ідентифікація пристрою та стан SIM-картки

```
ATI                    → Базова інформація про виробника, модель та версію прошивки
AT+CGMI                → Запит назви виробника (наприклад, "Quectel", "SIMCom", "u-blox")
AT+CGMM                → Запит повної назви моделі модуля (наприклад, "BG95-M3", "SIM7600E")
AT+CGMR                → Запит повної версії релізу мікропрограми baseband
AT+CGSN                → Читання міжнародного ідентифікатора обладнання IMEI (15 цифр)
AT+CIMI                → Читання міжнародного ідентифікатора абонента IMSI з SIM-картки
AT+CCID                → Читання унікального серійного номера чипа SIM-картки (ICCID)
AT+CPIN?               → Перевірка готовності SIM (повертає +CPIN: READY або PIN required)
AT+CPIN="1234"         → Введення PIN-коду для розблокування
```

### 3.2. Радіопараметри та якість сигналу (`AT+CSQ`)

Команда опитування якості сигналу повертає два цілочисельних значення:
```
AT+CSQ
+CSQ: <rssi>,<ber>
OK
```

Шкала значень `rssi` (індикатор рівня сигналу):
- `0`: Менше або дорівнює -113 дБм (гранично слабкий зв'язок або його відсутність);
- `1`: -111 дБм;
- `2...30`: від -109 дБм до -53 дБм із кроком 2 дБм на одиницю шкали;
- `31`: -51 дБм або вище (ідеальний рівень сигналу безпосередньо біля базової станції);
- `99`: Невідомо або не виявлено.

Формула перерахунку RSSI у потужність у дБм:
```
P_dBm = -113 + (rssi · 2)    [для діапазону 0 ≤ rssi ≤ 31]
```

Значення `ber` (коефіцієнт бітових помилок на каналі):
- `0...7`: градації коефіцієнта помилок від < 0.2% до > 8.0%;
- `99`: Не виміряно або не підтримується.

### 3.3. Реєстрація в мережі (`+CREG`, `+CGREG`, `+CEREG`)

Для моніторингу стану підключення до сотової мережі використовуються три взаємодоповнюючі команди:
- `AT+CREG?` — реєстрація у мережі з комутацією каналів (CS — дзвінки та SMS у GSM/UMTS);
- `AT+CGREG?` — реєстрація у пакетній мережі GPRS/EDGE (2G/3G Packet Switched);
- `AT+CEREG?` — реєстрація у мережі LTE (EPS — Evolved Packet System, включаючи LTE-M та NB-IoT).

Команда конфігурації URC для LTE:
```
AT+CEREG=2             → Увімкнути розширені URC з кодом локації (TAC) та ідентифікатором соти (Cell ID)
```

Статуси реєстрації `<stat>`:
- `0`: Не зареєстровано, пошук мережі не ведеться;
- `1`: Зареєстровано в домашній мережі (*Home Network*);
- `2`: Не зареєстровано, ведеться активний пошук базової станції (*Searching*);
- `3`: Реєстрацію відхилено оператором (*Registration Denied*);
- `4`: Невідомий стан;
- `5`: Зареєстровано в роумінгу (*Roaming*).

### 3.4. Налаштування контексту PDP (Packet Data Protocol)

Перед встановленням інтернет-з'єднання необхідно налаштувати профіль точки доступу (APN — *Access Point Name*):

```
AT+CGDCONT=1,"IP","internet"     → Профіль 1: протокол IPv4, точка доступу "internet"
AT+CGDCONT=2,"IPV4V6","iot.apn"  → Профіль 2: подвійний стек IPv4/IPv6
AT+CGACT=1,1                     → Активація контексту PDP номер 1
AT+CGPADDR=1                     → Опитування призначеної IP-адреси пристрою
```

## 4. Керування енергозбереженням: DTR-сон, eDRX та PSM

Для автономних датчиків та приладів із живленням від акумулятора критично важливо переводити модем у мікроспоживання:

### Керування сном через апаратний контакт DTR
```
AT+CSCLK=1 (або AT+QSCLK=1)
```
- Якщо хост підтягує лінію `DTR` до високого рівня (1.8V / 3.3V), модем вимикає тактування UART і засинає (споживання падає до 1–3 мА).
- Щоб надіслати команду, хост опускає `DTR` у низький рівень (0V), чекає 20–50 мс для пробудження модуля й надсилає `AT`.

### Режим глибокого енергозбереження PSM (Power Saving Mode, 3GPP Rel.12)
```
AT+CPSMS=1,,,"01000011","00000010"
```
У режимі PSM модем повністю вимикає радіотракт і переходить у стан сну зі споживанням близько 3–5 мкА, зберігаючи реєстрацію в мережі без потреби в повторній тривалій процедурі Attach.

Параметри таймерів кодуються 8-бітними двійковими рядками:
1. **Таймер періодичного оновлення зони відстеження TAU (T3412):** Задає період, через який модем прокидається і підтверджує присутність у мережі (наприклад, кожні 3 години або 24 години).
2. **Таймер активності (T3324):** Задає час (наприклад, 4 секунди), протягом якого модем залишається в активному режимі після відправки пакета, щоб прийняти вхідні дані від сервера, перш ніж знову заснути.
