# 📋 Довідник префіксів IPv4, масок, хостів і розрахунок підмереж

Безкласова адресація CIDR (англ. *Classless Inter-Domain Routing*, RFC 1519 / RFC 4632) стандартизує спосіб розбиття 32-бітного адресного простору IPv4 на префікси довільної бітової довжини. На відміну від застарілих фіксованих класів A, B та C, кожен префікс визначається кількістю старших одиничних бітів у масці підмережі, що позначається скісною рискою (наприклад, `/24` означає 24 одиниці в масці).

Цей довідник містить повну класифікацію префіксів IPv4 від `/0` до `/32`, правила двійкової арифметики для обчислення параметрів підмереж, аналіз граничних випадків (RFC 3021, RFC 1918, CGNAT), конфігурацію префіксних списків у мережевих операційних системах (Cisco IOS, Junos), принципи захисту маршрутизації (RPKI, фільтрація Bogon) та системні команди взаємодії з таблицями маршрутизації.

### Архітектурні категорії префіксів та їхнє практичне використання

За функціональним призначенням усі префікси CIDR поділяються на п'ять діапазонів:

1. **Глобальні магістральні супермережі (`/0` – `/8`):**
   Використовуються на рівні міжнародних транзитних операторів Tier-1 та регіональних інтернет-реєстраторів (RIR). Префікс `0.0.0.0/0` є основою маршрутизації за замовчуванням: він покриває абсолютно весь адресний простір, але має мінімальний пріоритет (нульову довжину збігу). Префікс `/4` виділено для багатоадресної розсилки (Multicast), а блок `/8` в історичному розподілі складав основу адресного простору великих технологічних компаній та військових відомств США.

2. **Провайдерські та операторські блоки (`/9` – `/16`):**
   Це діапазон, у якому регіональні реєстратори (ARIN, RIPE NCC, APNIC, LACNIC, AFRINIC) виділяють великі пули для національних провайдерів інтернету та хмарних платформ (AWS, Google Cloud, Microsoft Azure). У цьому ж діапазоні стандартизовано спеціальні функціональні простори: операторський транзитний CGNAT (`100.64.0.0/10` за стандартом RFC 6598) та приватну корпоративну мережу `172.16.0.0/12` (RFC 1918).

3. **Підприємства, кампуси та мінімальні маршрутизовані блоки (`/17` – `/24`):**
   Блоки від `/20` до `/23` виділяються середнім компаніям, фінансовим установам та операторам дата-центрів. Префікс `/24` (256 адрес) є **найсуворішим рубежем глобального Інтернету**: за загальноприйнятою політикою операторів зв'язку, магістральні маршрутизатори BGP відкидають (фільтрують) будь-які публічні анонси, довші за `/24` (наприклад, `/25` чи `/28`). Це захищає світову таблицю маршрутизації від фрагментації та переповнення пам'яті.

4. **Локальні підмережі, VLAN та робочі групи (`/25` – `/29`):**
   Діапазон активного використання всередині приватних корпоративних та дата-центрових мереж. Префікс `/25` (128 IP) або `/26` (64 IP) зазвичай призначається під великий поверх офісу або пул бездротового доступу Wi-Fi. Префікси `/27` (32 IP) та `/28` (16 IP) є стандартними для серверних стійок, кластерів віртуалізації та ізольованих сегментів DMZ. Префікс `/29` (8 IP, 6 корисних хостів) типово виділяється для відмовостійких шлюзів, де працюють протоколи віртуалізації маршрутизаторів VRRP чи HSRP (дві фізичні IP роутерів + одна спільна VIP + адреси моніторингу).

5. **Канали «точка-точка» та хостові маршрути (`/30` – `/32`):**
   Використовуються для інфраструктурних лінків та адресації окремих вузлів. Префікс `/30` історично застосовувався для з'єднання двох маршрутизаторів (4 адреси: мережа, шлюз A, шлюз B, широкомовлення). Префікс `/31` згідно з RFC 3021 повністю усунув марнування адрес на лінках P2P. Префікс `/32` позначає конкретну 32-бітну адресу без підмережі: він налаштовується на віртуальних інтерфейсах Loopback для стабільної роботи протоколів BGP та OSPF.

### Математичний апарат і формули розрахунку підмереж

Для довільного префікса довжиною `n` бітів (`0 <= n <= 32`) діють фундаментальні математичні співвідношення:

1. **Кількість хостових бітів:**
   Кількість молодших бітів, виділених під адресацію пристроїв усередині мережі:
   ```
   h = 32 - n
   ```

2. **Загальна ємність підмережі:**
   Сумарна кількість можливих комбінацій значень хостових бітів:
   ```
   N_total = 2^h = 2^(32 - n)
   ```

3. **Кількість корисних (призначуваних) адрес хостів:**
   У стандартних підмережах від `/0` до `/30` перша та остання адреси зарезервовані протоколом IP:
   ```
   N_usable = 2^(32 - n) - 2
   ```
   - Перша адреса (всі біти хоста `0`) — **Адреса мережі** (Network Identifier).
   - Остання адреса (всі біти хоста `1`) — **Спрямована широкомовна адреса** (Directed Broadcast Address).

4. **Граничний випадок RFC 3021 (Префікс `/31`):**
   На з'єднаннях типу «точка-точка» між двома маршрутизаторами широкомовні повідомлення не потрібні, оскільки середовище не містить інших учасників. За стандартом RFC 3021 адреса з нульовим хостовим бітом призначається першому маршрутизатору, а адреса з одиничним — другому. Обидві адреси стають робочими хостами:
   ```
   N_usable = 2^(32 - 31) = 2^1 = 2 хости (без віднімання двох службових адрес)
   ```

5. **Двійковий розрахунок адреси мережі:**
   Обчислюється операцією побітового кон'юнктивного множення (логічне «І», AND) між IP-адресою вузла та маскою підмережі:
   ```
   Network_IP = Host_IP & Subnet_Mask
   ```

6. **Двійковий розрахунок широкомовної адреси:**
   Обчислюється побітовою диз'юнкцією (логічне «АБО», OR) адреси мережі з інверсною маскою (Wildcard):
   ```
   Broadcast_IP = Network_IP | (~Subnet_Mask)
   ```

7. **Інверсна маска (Wildcard Mask):**
   Маска, де біти префікса дорівнюють `0`, а біти хоста — `1`. Вона використовується в списках контролю доступу (ACL) мережевого обладнання та фільтрах протоколів динамічної маршрутизації:
   ```
   Wildcard_Mask = ~Subnet_Mask = 255.255.255.255 - Subnet_Mask
   ```

### Покроковий приклад ручного двійкового розрахунку

Розгляньмо практичний розрахунок параметрів підмережі для робочої станції з адресою `198.51.100.75/27`.

```
Крок 1. Визначення маски та кількості бітів:
  Префікс: /27 -> 27 одиниць і 5 нулів.
  Двійкова маска: 11111111 . 11111111 . 11111111 . 11100000
  Десяткова маска: 255.255.255.224

Крок 2. Розрахунок ємності:
  Хостових бітів: h = 32 - 27 = 5
  Усього адрес:   2^5 = 32
  Робочих хостів: 32 - 2 = 30 хостів

Крок 3. Побітове обчислення адреси мережі:
  IP:   198.51.100.75  -> 11000110 . 00110011 . 01100100 . 01001011
  Mask: 255.255.255.224-> 11111111 . 11111111 . 11111111 . 11100000
  -------------------------------------------------------------------
  AND:  198.51.100.64  -> 11000110 . 00110011 . 01100100 . 01000000
  -> Адреса мережі: 198.51.100.64

Крок 4. Побітове обчислення широкомовної адреси:
  Інверсна маска (Wildcard): 0.0.0.31 (00000000.00000000.00000000.00011111)
  Network: 198.51.100.64 -> 11000110 . 00110011 . 01100100 . 01000000
  Wildcard:      0.0.0.31-> 00000000 . 00000000 . 00000000 . 00011111
  -------------------------------------------------------------------
  OR:      198.51.100.95 -> 11000110 . 00110011 . 01100100 . 01011111
  -> Широкомовна адреса: 198.51.100.95

Крок 5. Визначення діапазону робочих хостів:
  Перший призначуваний хост: 198.51.100.64 + 1 = 198.51.100.65
  Останній призначуваний хост: 198.51.100.95 - 1 = 198.51.100.94
```

### Фільтрація префіксів: Cisco Prefix-Lists та Juniper Route-Filters

У промисловій конфігурації протоколів BGP та OSPF фільтрація анонсів здійснюється за допомогою спеціальних префіксних списків (Prefix-Lists), які зіставляють як мережеву адресу, так і діапазон дозволених довжин масок за допомогою операторів `ge` (greater or equal, більше або рівно) та `le` (less or equal, менше або рівно).

#### 1. Синтаксис Cisco IOS / NX-OS / Arista EOS

```text
! Дозволити тільки точний префікс 198.51.100.0/22:
ip prefix-list FILTER-EXACT seq 10 permit 198.51.100.0/22

! Дозволити сам префікс 198.51.100.0/22 та будь-які його підмережі до /24 включно:
ip prefix-list FILTER-SUB seq 10 permit 198.51.100.0/22 le 24

! Дозволити лише підмережі розміром від /24 до /26 всередині блоку 198.51.100.0/22:
ip prefix-list FILTER-RANGE seq 10 permit 198.51.100.0/22 ge 24 le 26

! Дозволити стандартний маршрут за замовчуванням (Default Route):
ip prefix-list FILTER-DEFAULT seq 10 permit 0.0.0.0/0

! Дозволити будь-який публічний маршрут Інтернету (від /0 до /24):
ip prefix-list INTERNET-IN seq 10 permit 0.0.0.0/0 le 24
```

#### 2. Синтаксис Juniper Junos OS

```text
policy-statement BGP-INBOUND-POLICY {
    term ACCEPT-SUPERNET {
        from {
            /* Дозволяє префікс /22 та його суб-мережі до /24 */
            route-filter 198.51.100.0/22 prefix-length-range /22-/24;
        }
        then accept;
    }
    term REJECT-OTHERS {
        then reject;
    }
}
```

### Спеціальні адресні простори за стандартами RFC

У глобальному просторі IPv4 виділено стандартизовані блоки префіксів, які мають спеціальне призначення і не підлягають стандартній маршрутизації в публічному Інтернеті:

- **Приватні адресні простори (RFC 1918):**
  Використовуються виключно всередині локальних мереж підприємств та домашніх користувачів:
  - `10.0.0.0/8` — один блок на 16 777 216 адрес (діапазон `10.0.0.0 – 10.255.255.255`);
  - `172.16.0.0/12` — 16 суміжних блоків розміру `/16`, сумарно 1 048 576 адрес (`172.16.0.0 – 172.31.255.255`);
  - `192.168.0.0/16` — 256 суміжних блоків розміру `/24`, сумарно 65 536 адрес (`192.168.0.0 – 192.168.255.255`).

- **Провайдерський транзитний CGNAT (RFC 6598):**
  Блок `100.64.0.0/10` (4 194 304 адреси) виділений спеціально для технології Carrier-Grade NAT. Він використовується інтернет-провайдерами для адресації WAN-портів абонентських роутерів без конфліктів із домашніми приватними підмережами клієнтів (`192.168.x.x`).

- **Автоматична локальна адресація Link-Local / APIPA (RFC 3927):**
  Блок `169.254.0.0/16` (65 536 адрес) використовується операційними системами для автоматичного призначення собі IP-адреси у разі збою або відсутності сервера DHCP. Трафік цього блоку суворо заборонено маршрутизувати через будь-який шлюз.

- **Документаційні діапазони (RFC 5737):**
  Три блоки, призначені для використання в підручниках, прикладах та технічній документації (трафік до них відкидається маршрутизаторами Інтернету):
  - `192.0.2.0/24` (TEST-NET-1);
  - `198.51.100.0/24` (TEST-NET-2);
  - `203.0.113.0/24` (TEST-NET-3).

- **Системні та службові блоки:**
  - `0.0.0.0/8` (RFC 1122) — «цей хост / ця мережа» (джерело DHCP-запитів);
  - `127.0.0.0/8` (RFC 1122) — петльовий інтерфейс Loopback для внутрішньосистемного обміну (`127.0.0.1`);
  - `224.0.0.0/4` (RFC 5771) — багатоадресні групи Multicast (OSPF, RIPv2, PIM);
  - `240.0.0.0/4` (RFC 1112) — зарезервовано для майбутніх досліджень (колишній Клас E);
  - `255.255.255.255/32` (RFC 919) — обмежене широкомовлення в межах канального рівня (Limited Broadcast).

### Безпека маршрутизації: RPKI, ROA та фільтрація Bogon

З появою безкласової маршрутизації та правила Longest Prefix Match виникла специфічна вразливість — **перехоплення префіксів** (англ. *BGP Prefix Hijacking*). Оскільки маршрутизатор завжди віддає перевагу точнішому (довшому) префіксу, зловмисна або помилково налаштована автономна система може анонсувати чужий блок адреси дрібнішим префіксом (наприклад, анонсувати підмережу `/24` зсередини легітимного чужого блоку `/22`). За правилом LPM увесь світовий трафік до цієї підмережі попрямує до зловмисника, оскільки `/24` має вищий пріоритет за `/22`.

Для захисту від таких атак у сучасному Інтернеті впроваджено два захисних механізми:

1. **Фільтрація Bogon (Bogon Filtering):**
   Маршрутизатори провайдерів автоматично блокують анонси префіксів, які належать приватним (RFC 1918), зарезервованим (RFC 5737) або ще не виділеним організацією IANA блокам IP-адрес (так звані Fullbogons).
2. **Криптографічна валідація RPKI (Resource Public Key Infrastructure):**
   Власник префікса реєструє у криптографічній базі RIR спеціальний цифровий сертифікат — **ROA** (англ. *Route Origin Authorization*). У сертифікаті фіксуються три параметри:
   - номер автономної системи, яка має право анонсувати блок (Origin ASN);
   - сам префікс (наприклад, `198.51.100.0/22`);
   - максимальна дозволена довжина суб-префікса `MaxLength` (наприклад, `/24`).
   Якщо стороння AS спробує анонсувати дрібніший префікс `/25` або блок із неавторизованого ASN, магістральні BGP-роутери з підтримкою валідації позначають маршрут як `Invalid` і повністю відкидають його.

### Зведена таблиця стандартних префіксів IPv6

У протоколі IPv6 відмовилися від десяткових масок: адресація базується виключно на бітовій довжині префікса:

| Префікс IPv6 | Кількість бітів хоста | Загальна кількість адрес | Архітектурна роль за RFC 4291 / RFC 6177 |
|:---|---:|---:|:---|
| **/128** | 0 бітів | 1 адреса | Одиночний хост, Loopback (`::1/128`), точковий маршрут |
| **/127** | 1 біт | 2 адреси | Міжмаршрутизаторні P2P канали (RFC 6164) |
| **/64** | 64 біти | 18 446 744 073 709 551 616 | Стандартний розмір підмережі для SLAAC |
| **/56** | 72 біти | 256 підмереж `/64` | Стандартне виділення для малого бізнесу / домашнього підключення |
| **/48** | 80 бітів | 65 536 підмереж `/64` | Стандартний блок корпоративного кампусу чи дата-центру |
| **/32** | 96 бітів | 4 294 967 296 підмереж `/64` | Стандартний блок виділення RIR для інтернет-провайдера (LIR) |
| **/29** | 99 бітів | 34 359 738 368 підмереж `/64` | Великі транзитні оператори зв'язку Tier-1 |
| **/3** | 125 бітів | 1/8 простору IPv6 | Глобальний маршрутизований простір Global Unicast (`2000::/3`) |

### Системний інтерфейс операційних систем для конфігурації CIDR

Сучасні операційні системи підтримують повний набір системних утиліт для маніпуляції CIDR-префіксами, перегляду таблиць маршрутизації та обчислення параметрів підмереж.

#### 1. Linux (стек `iproute2`)

```bash
# Перегляд інтерфейсів із префіксами у CIDR-форматі:
ip -4 addr show

# Призначення IP-адреси з префіксом /26 на мережевий адаптер:
sudo ip addr add 198.51.100.45/26 dev eth0

# Додавання статичного маршруту для агрегованого блоку /22 через шлюз:
sudo ip route add 198.51.100.0/22 via 10.0.0.1 dev eth0

# Перевірка вибору маршруту за правилом Longest Prefix Match для конкретної IP:
ip route get 198.51.100.45
# Виводить вихідний інтерфейс, точний співпалий префікс та адресу next-hop.

# Автоматичний розрахунок параметрів підмережі через ipcalc:
ipcalc 198.51.100.45/26
```

#### 2. Windows (PowerShell та командний рядок)

```powershell
# Перегляд активних префіксів на мережевих адаптерах:
Get-NetIPAddress -AddressFamily IPv4 | Format-Table IPAddress, PrefixLength, InterfaceAlias

# Встановлення статичної IP-адреси з CIDR-префіксом /26:
New-NetIPAddress -InterfaceAlias "Ethernet0" -IPAddress "198.51.100.45" -PrefixLength 26 -DefaultGateway "198.51.100.1"

# Додавання агрегованого маршруту:
New-NetRoute -DestinationPrefix "198.51.100.0/22" -InterfaceAlias "Ethernet0" -NextHop "10.0.0.1"
```

#### 3. FreeBSD / macOS (BSD CLI)

```bash
# Призначення адреси з префіксом через ifconfig:
sudo ifconfig em0 inet 198.51.100.45/26

# Додавання маршруту для підмережі:
sudo route add -net 198.51.100.0/22 10.0.0.1

# Перегляд системної таблиці пересилання:
netstat -rn -f inet
```
