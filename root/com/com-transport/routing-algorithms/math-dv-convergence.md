# 🧮 Математика збіжності та проблеми відліку до нескінченності

Ця вставка містить математичне обґрунтування збіжності алгоритму дистанційно-векторної маршрутизації (розподіленого алгоритму Беллмана–Форда), алгебраїчне формулювання у тропічному напівкільці, доведення стискаючого відображення у нормі максимуму, аналіз асинхронного режиму за умовами Берцекаса–Ціцікліса, покроковий чисельний приклад розрахунку, строгий аналіз феномену «відліку до нескінченності» (англ. *Count-to-Infinity Problem*), а також математичні доведення методів розщеплення горизонту та отруйного реверсу.

### Математична формалізація дистанційно-векторного алгоритму

Розглянемо зважений орієнтований граф `G = (V, E)`, де `V = {v_1, v_2, ..., v_n}` — множина з `n` вершин (маршрутизаторів), а `E ⊆ V × V` — множина спрямованих ребер (ліній зв'язку). Кожному ребру `(i, j) ∈ E` приписано вагу `c(i, j) > 0`, що виражає затримку або вартість передачі даних. Якщо ребра між `i` та `j` не існує, вважаємо `c(i, j) = ∞`. Для кожного вузла `i` вартість до самого себе дорівнює `c(i, i) = 0`.

Позначимо через `N(i) = {v ∈ V : (i, v) ∈ E, v ≠ i}` множину прямих фізичних сусідів вузла `i`. Кожен вузол `i` зберігає у пам'яті локальну матрицю оцінок або вектор оціночних відстаней `D[i] = [d_i(y) : y ∈ V]`, де `d_i(y)` — поточна відома вартість найкоротшого шляху від `i` до вершини `y`.

Алгоритм працює ітеративно шляхом обміну векторами між сусідніми вузлами. Базове рекурентне співвідношення для вузла `i` при отриманні векторів від усіх сусідів `v ∈ N(i)` описується рівнянням Беллмана–Форда:

```
d_i(y) = min_{v ∈ N(i) ∪ {i}} { c(i, v) + d_v(y) }
```

При цьому наступний хоп (англ. *next hop*) `next_i(y)` визначається як сусід `v*`, на якому досягається мінімум:

```
next_i(y) = argmin_{v ∈ N(i)} { c(i, v) + d_v(y) }
```

### Алгебраїчне формулювання у тропічному напівкільці (Min-Plus Algebra)

Дистанційно-векторний алгоритм можна красиво формалізувати в термінах **тропічного напівкільця** (англ. *Tropical Semiring* чи *Min-Plus Algebra*). 

Розглянемо алгебраїчну структуру `(ℝ ∪ {+∞}, ⊕, ⊗)`, де додавання визначається як мінімум, а множення — як звичайне додавання дійсних чисел:

```
a ⊕ b = min(a, b)
a ⊗ b = a + b
```

Нейтральним елементом відносно операції `⊕` є `+∞` (оскільки `min(a, +∞) = a`), а нейтральним елементом відносно `⊗` є `0` (оскільки `a + 0 = a`).

Нехай `W` — матриця суміжності графа розміром `n × n`, де `W[i, j] = c(i, j)`.
Нехай `D^(k)` — матриця найкоротших відстаней на ітерації `k`, де `D^(0) = W`.

Тоді ітерація розподіленого алгоритму Беллмана–Форда еквівалентна матричному множенню в тропічному напівкільці:

```
D^(k+1) = D^(k) ⊕ W
```

де елемент матриці обчислюється як:

```
D^(k+1)[i, j] = ⊕_{m=1}^{n} ( D^(k)[i, m] ⊗ W[m, j] )
              = min_{m=1..n} { D^(k)[i, m] + W[m, j] }
```

Це алгебраїчне формулювання показує, що `k`-та степінь матриці суміжності `W^(⊗ k)` у тропічному напівкільці містить найкоротші відстані між усіма парами вершин шляхами довжиною не більше `k` ребер. Оскільки граф містить `n` вершин і не має від'ємних циклів, стаціонарна матриця найкоротших відстаней `D*` досягається при `k = n - 1`:

```
D* = W ⊕ W^(⊗ 2) ⊕ W^(⊗ 3) ⊕ ... ⊕ W^(⊗ n-1)
```

### Доведення стискаючого відображення (Contraction Mapping)

Для доведення єдиності нерухомої точки `D*` та стискаючого характеру оператора оновлень розглянемо простір векторів відстаней із нормою максимуму (англ. *Supremum Norm* або *L_∞ norm*):

```
||D_1 - D_2||_∞ = max_{i, y ∈ V} | d_1,i(y) - d_2,i(y) |
```

Нехай `F(D)` — оператор Bellman-Ford, що переводить вектор оцінок `D` у новий вектор оцінок `F(D)` за правилом:

```
(F(D))_i(y) = min_{v ∈ N(i)} { c(i, v) + d_v(y) }
```

Розглянемо два довільних вектори оцінок `D_1` та `D_2`. Для будь-якої фіксованої вершини `i` та мети `y` маємо:

```
(F(D_1))_i(y) - (F(D_2))_i(y)
= min_{v ∈ N(i)} { c(i, v) + d_1,v(y) } - min_{u ∈ N(i)} { c(i, u) + d_2,u(y) }
```

Нехай мінімум для `D_2` досягається на вершині `u*`. Тоді:

```
(F(D_1))_i(y) - (F(D_2))_i(y)
≤ (c(i, u*) + d_1,u*(y)) - (c(i, u*) + d_2,u*(y))
= d_1,u*(y) - d_2,u*(y)
≤ max_{v} | d_1,v(y) - d_2,v(y) |
≤ ||D_1 - D_2||_∞
```

З міркувань симетрії аналогічне за модулем обмеження виконується в протилежну сторону:

```
| (F(D_1))_i(y) - (F(D_2))_i(y) | ≤ ||D_1 - D_2||_∞
```

Взявши максимум по всіх `i` та `y`, отримуємо:

```
||F(D_1) - F(D_2)||_∞ ≤ ||D_1 - D_2||_∞
```

Це доводить, що оператор Беллмана–Форда є **нерозтягуючим відображенням** (англ. *non-expansive mapping*), а на графі без від'ємних циклів при підрахунку шляхів довжиною до `n - 1` він стає строго стискаючим (англ. *strictly contracting*). За теоремою Банаха про нерухому точку, це ґарантує існування єдиної стійкої розв'язки `D* = F(D*)`.

### Доведення збіжності за стаціонарної топології

**Теорема 1 (Збіжність розподіленого Беллмана–Форда).** Якщо топологія графа `G` та ваги ребер `c(u, v)` лишаються незмінними, а повідомлення між сусідніми вузлами доставляються за скінченний час, то для будь-якого стартового стану векторів `D[i]` послідовність оновлень збігається до точних найкоротших відстаней `d_i*(y)` за не більше ніж `|V| - 1` синхронних ітерацій.

**Доведення (за індукцією за довжиною шляху в ребрах):**

Позначимо через `d_i^(k)(y)` оцінку відстані від `i` до `y` після `k` ітерацій алгоритму.

*База індукції (`k = 1`):*
Для будь-якої пари вузлів `i` та `y`, де найкоротший шлях складається з 1 ребра (тобто `y ∈ N(i)` і ребро `(i, y)` є найкоротшим шляхом), після першого обміну векторами маємо:

```
d_i^(1)(y)
= min_{v ∈ N(i)} { c(i, v) + d_v^(0)(y) }    [рівняння Беллмана–Форда на ітерації 1]
= c(i, y) + d_y^(0)(y)                      [мінімум досягається на прямому ребрі]
= c(i, y) + 0                               [відстань вузла до самого себе]
= d_i*(y)                                   [точна вартість найкоротшого шляху]
```

Отже, для всіх шляхів довжиною в 1 ребро оцінки є точними після 1-ї ітерації.

*Індукційний крок:*
Припустимо, що після `k` ітерацій оцінки `d_v^(k)(y)` є точними для всіх найкоротших шляхів, що складаються з не більше ніж `k` ребер. Розглянемо найкоротший шлях від `i` до `y`, що складається з `k + 1` ребер. Нехай першим ребром цього шляху є `(i, w)`, де `w ∈ N(i)`. Тоді решта шляху від `w` до `y` містить `k` ребер і є найкоротшим шляхом від `w` до `y`.

За індукційним припущенням:

```
d_w^(k)(y) = d_w*(y)
```

На ітерації `k + 1` вузол `i` обчислює:

```
d_i^(k+1)(y)
= min_{v ∈ N(i)} { c(i, v) + d_v^(k)(y) }   [рівняння оновлення Беллмана–Форда]
≤ c(i, w) + d_w^(k)(y)                      [вибір оптимального сусіда w]
= c(i, w) + d_w*(y)                         [за індукційним припущенням]
= d_i*(y)                                   [визначення найкоротшого шляху]
```

Оскільки оцінки знизу обмежені справжніми найкоротшими відстанями `d_i*(y)` (через невід'ємність ваг ребер), маємо `d_i^(k+1)(y) = d_i*(y)`.

Оскільки у графі без від'ємних циклів будь-який найпростіший шлях містить не більше ніж `|V| - 1` ребер, за `|V| - 1` ітерацій усі оцінки `d_i(y)` збігаються до строго точних значень `d_i*(y)`. Теорему доведено.

### Аналіз асинхронної збіжності за умови Берцекаса–Ціцікліса

У реальних комп'ютерних мережах вузли не мають спільних тактових генераторів та обмінюються векторами **асинхронно**. Нехай `T_i` — множина моментів часу, коли вузол `i` здійснює обчислення та розсилає свій вектор, а `t_{v, i}` — затримка передачі повідомлення від `v` до `i`.

Припускаємо виконання двох умов асинхронності Берцекаса–Ціцікліса:
1. **Часткова надійність**: жоден вузол не припиняє обчислення назавжди (для кожного `t` існує `t' > t` таке, що `t' ∈ T_i`).
2. **Обмеженість затримок**: затримка поширення повідомлень не прямує до нескінченності (існує `B > 0` таке, що `t - t_{v, i} ≤ B`).

**Теорема 2 (Асинхронна збіжність).** За умов часткової надійності та обмеженості затримок асинхронний дистанційно-векторний алгоритм збігається до точного вектора `D*` за скінченний час від будь-якого початкового стану.

### Практичний розбір 4-вузлової мережі: Покрокова матриця оновлень

Для наочності простежимо збіжність алгоритму на конкретному графі з 4 вузлів (`A, B, C, D`), з'єднаних ребрами:
- `(A, B) = 1`
- `(B, C) = 3`
- `(A, C) = 7`
- `(C, D) = 2`
- `(B, D) = 8`

Запишемо початкову матрицю суміжності `D^(0)` на ітерації 0, коли кожен вузол знає лише прямі зв'язки з сусідами:

```
    A   B   C   D
A [ 0   1   7   ∞ ]
B [ 1   0   3   8 ]
C [ 7   3   0   2 ]
D [ ∞   8   2   0 ]
```

**Ітерація 1 (перший обмін векторами між сусідами):**

Вузол `A` отримує вектор від `B`: `[1, 0, 3, 8]` та від `C`: `[7, 3, 0, 2]`.
Обчислюємо оновлення для `A`:
- `d_A(C) = min(7, c(A,B) + d_B(C)) = min(7, 1 + 3) = 4`  [оновлено!]
- `d_A(D) = min(∞, c(A,B) + d_B(D), c(A,C) + d_C(D)) = min(∞, 1 + 8, 7 + 2) = 9` [оновлено!]

Вузол `B` отримує вектор від `C`: `[7, 3, 0, 2]`.
- `d_B(D) = min(8, c(B,C) + d_C(D)) = min(8, 3 + 2) = 5`  [оновлено!]

Матриця оцінок `D^(1)` після ітерації 1:

```
    A   B   C   D
A [ 0   1   4   9 ]
B [ 1   0   3   5 ]
C [ 4   3   0   2 ]
D [ 9   5   2   0 ]
```

**Ітерація 2 (другий обмін векторами):**

Вузол `A` отримує від `B` оновлене значення `d_B(D) = 5`.
Обчислюємо:
- `d_A(D) = min(9, c(A,B) + d_B(D)) = min(9, 1 + 5) = 6`  [оновлено!]

Матриця оцінок `D^(2)` після ітерації 2:

```
    A   B   C   D
A [ 0   1   4   6 ]
B [ 1   0   3   5 ]
C [ 4   3   0   2 ]
D [ 6   5   2   0 ]
```

На ітерації 3 подальші обчислення за рівнянням Беллмана–Форда не змінюють жодної оцінки. Система досягла фіксованої точки (англ. *fixed point*) `D^(3) = D^(2) = D*`. Збіжність завершилася за 2 ітерації, що менше за теоретичну межу `|V| - 1 = 3`.

### Алгебраїчний аналіз проблеми «відліку до нескінченності»

Проблема виникає при погіршенні або обриві ліній зв'язку, коли вузли утворюють циклічні залежності у своїх таблицях маршрутизації.

Розглянемо лінійний граф із 3 вузлів: `A — B — C`.
Нехай ваги ребер дорівнюють `c(A, B) = 1` та `c(B, C) = 1`.

У початковому стаціонарному стані маємо такі оцінки відстані до цільового вузла `C`:
- `d_C(C) = 0`
- `d_B(C) = 1` (маршрут через пряме ребро `B → C`, `next_B(C) = C`)
- `d_A(C) = 2` (маршрут через `A → B → C`, `next_A(C) = B`)

Припустимо, що на моменту часу `t_0` ребро `(B, C)` обривається. Вузол `B` фіксує втрату прямого лінка: `c(B, C) = ∞`.

Проте вузол `B` все ще має в пам'яті останній вектор від `A`, де `d_A(C) = 2`. Вузол `B` не знає, що шлях від `A` до `C` насправді проходив через сам вузол `B`!

На кроці 1 вузол `B` оновлює свою оцінку за рівнянням Беллмана–Форда:

```
d_B^(1)(C)
= c(B, A) + d_A(C)                          [переобчислення через вузол A]
= 1 + 2                                     [підстановка відомих оцінок]
= 3                                         [нова помилкова оцінка B]
```

Вузол `B` обирає новим наступним хопом `next_B(C) = A` і розсилає свій новий вектор із `d_B(C) = 3`.

На кроці 2 вузол `A` отримує вектор від `B`. Оскільки маршрут `A` до `C` йшов через `B`, вузол `A` мусить переобчислити свою відстань через нове значення `d_B(C)`:

```
d_A^(2)(C)
= c(A, B) + d_B^(1)(C)                      [переобчислення через оновлений вектор B]
= 1 + 3                                     [підстановка нової оцінки d_B]
= 4                                         [нарощування помилкової відстані A]
```

Вузол `A` розсилає вектор із `d_A(C) = 4`. На кроці 3 вузол `B` отримує цей анонс і обчислює:

```
d_B^(3)(C)
= c(B, A) + d_A^(2)(C)                      [переобчислення B через нову оцінку A]
= 1 + 4                                     [підстановка чергового значення]
= 5                                         [подальше монотонне зростання]
```

Шляхом математичної індукції легко показати, що на кроці `m` оцінки задовольняють співвідношенням:

```
d_B^(2m-1)(C) = 2m + 1
d_A^(2m)(C)   = 2m + 2
```

Оскільки `m → ∞`, оцінки відстаней монотонно зростають до нескінченності `∞`. Процес зупиняється лише тоді, коли оцінка досягає штучно заданого порогу нескінченності (наприклад, `16` у протоколі RIP). До цього моменту пакети, адресовані `C`, безкінечно циркулюють між `A` та `B`, виснажуючи канал та спричиняючи петлю маршрутизації.

### Математичне доведення ефективності Poison Reverse (отруйного реверсу)

Для усунення петель між двома сусідніми вузлами застосовують правило **розщеплення горизонту з отруйним реверсом** (англ. *Split Horizon with Poison Reverse*).

**Формальне правило:** Якщо вузол `B` використовує вузол `A` як `next_B(y)` для досягнення мети `y`, то при анонсуванні свого вектора вузлу `A` вузол `B` зобов'язаний передати `d_B(y) = ∞`.

**Доведення блокування двовузлових петель:**

Розглянемо той самий граф `A — B — C` після обриву ребра `(B, C)`.

У початковому стані `next_A(C) = B`. Згідно з правилом отруйного реверсу, вузол `A` при відправці вектора вузлу `B` анонсує:

```
d_A(C) = ∞  [для вузла B]
```

Водночас для решти сусідів (якби вони були) `A` анонсує чесне значення `d_A(C) = 2`.

Коли ребро `(B, C)` падає (`c(B, C) = ∞`), вузол `B` намагається обчислити нову відстань за рівнянням Беллмана–Форда:

```
d_B^(1)(C)
= min_{v ∈ N(B)} { c(B, v) + d_v(C) }       [рівняння Беллмана–Форда при втраті лінка]
= c(B, A) + d_A(C)                          [єдиний доступний сусід A]
= 1 + ∞                                     [отруйний анонс d_A(C) = ∞ від A]
= ∞                                         [негане виявлення недосяжності]
```

Завдяки отруйному реверсу вузол `B` негайно бачить, що через `A` дістатися до `C` неможливо. Вузол `B` миттєво встановлює `d_B(C) = ∞` та оголошує мережу `C` недосяжною за 1 крок, повністю запобігаючи виникненню проблеми відліку до нескінченності.

### Обмеження Poison Reverse: Тривузлові петлі (3-Node Loops)

Попри ефективність проти двовузлових петель, отруйний реверс **не ґарантує** відсутності петель, якщо в циклі беруть участь 3 або більше вузлів.

Розглянемо трикутник з 3 вузлів `A`, `B`, `C`, які з'єднані з цільовим вузлом `D`:
- `c(A, D) = 10`
- `c(B, D) = 1` через ребро `(B, D)`
- `c(C, B) = 1`, `c(A, C) = 1`

Припускаємо, що у стаціонарному стані:
- `next_B(D) = D`, `d_B(D) = 1`
- `next_C(D) = B`, `d_C(D) = 2`
- `next_A(D) = C`, `d_A(D) = 3`

Оскільки `A` іде через `C`, а `C` іде через `B`:
- `C` анонсує `d_C(D) = ∞` для `B` (Poison Reverse).
- `A` анонсує `d_A(D) = ∞` для `C` (Poison Reverse).
- Однак `A` НЕ анонсує `∞` для `B`, бо `next_A(D)` дорівнює `C`, а не `B`! Тому `A` надсилає `B` оцінку `d_A(D) = 3`.

Тепер нехай ребро `(B, D)` падає (`c(B, D) = ∞`).
1. Вузол `B` бачить `d_C(D) = ∞` від `C`, але бачить `d_A(D) = 3` від `A`!
2. Вузол `B` вибирає новий шлях до `D` через `A`:

```
d_B(D) = c(B, A) + d_A(D) = 1 + 3 = 4
```

3. Вузол `B` обирає `next_B(D) = A`. Тепер маємо циклічну залежність: `B → A → C → B`!
4. Вузли `A`, `B`, `C` починають нескінченно нарощувати свої оцінки по колу, поки значення не досягнуть нескінченності.

Це доводить, що локальні правила (Poison Reverse) не здатні повністю ліквідувати петлі у довільних графах, що й стало головним математичним стимулом для переходу до алгоритмів стану зв'язків (Link-State) та шляхово-векторних протоколів (Path-Vector).

### Математична оцінка методу утримання (Hold-Down Timers) та затоплення LSA

Щоб тимчасово ізолювати вузли від нестабільних анонсів при погіршенні лінків, вводиться таймер утримання (англ. *Hold-Down Timer*).

Якщо вузол отримує анонс про те, що відстань до вузла `y` зросла або досягла `∞`, він переводить маршрут до `y` у стан `HOLD_DOWN` на фіксований час `T_hold`. Протягом `T_hold` вузол відкидає будь-які нові анонси від сусідів про альтернативні шляхи до `y`, за винятком випадку, коли шлях пропонується з відстанню, що строго менша за початкову стійку оцінку.

Математично це блокує нерівності типу `d_B^(m)(C) > d_B^(0)(C)` протягом часу `T_hold`, що перевищує максимальну затримку розповсюдження `max(t_{v,i}) \cdot |V|`. Математична тривалість таймера повинна задовольняти умові:

```
T_hold > ( |V| - 1 ) · ( T_update + T_prop )
```

де `T_update` — інтервал між відправками векторів, а `T_prop` — максимальна затримка в лінії. Це гарантує, що анонс про недосяжність досягне всіх вузлів мережі до того, як будь-хто з них почне приймати застарілі кругові анонси.

У протоколах стану зв'язків (Link-State) зациклення розповсюдження LSA блокується за допомогою строгого математичного порядку на парах `(Sequence_Number, Age)`. Пакети LSA з меншим порядковим номером `Seq` або граничним значенням `MaxAge` вважаються застарілими й негайно відкидаються:

```
LSA_1 > LSA_2 ⇔ (Seq_1 > Seq_2) ∨ (Seq_1 = Seq_2 ∧ Age_1 < Age_2)
```

Це гарантує, що затоплення LSA є скінченним і завершується за `O(|E|)` кроків на будь-якому зв'язаному графі, надаючи алгоритму Дейкстри повністю коректну матрицю суміжності.

### Математична складність політик Path-Vector та осциляції BGP (BGP Wedgie)

На відміну від Distance-Vector та Link-State, де збіжність гарантується мінімізацією скалярної метрики (довжини або затримки), у шляхово-векторних протоколах (BGP) кожен вузол застосовує локальну функцію ранжування маршрутів `Pref_i: Routes → ℝ`, яка може не задовольняти транзитивності глобальної оптимізації.

У праці Гріффіна (англ. *Timothy G. Griffin*), Шеперда (англ. *F. Bruce Shepherd*) та Вілкеса (англ. *Gordon Wilfong*) 2002 року показано, що BGP з автономними політиками еквівалентний задачі **Stable Paths Problem (SPP)**. 

Якщо граф локальних уподобань містить некоректну циклічну залежність типу **DISAGREE** або **BAD GADGET**, система не має жодної стійкої розв'язки або потрапляє в нескінченні осциляції анонсів (явище **BGP Wedgie**). Доведено, що перевірка наявності стійкої розв'язки у довільній мережі з BGP-політиками є **NP-повною задачею**. Для гарантії збіжності BGP у глобальному Інтернеті використовують строгі правила ієрархії Гао–Рекхтера (англ. *Gao-Rexford Model*):
1. **Customer > Peer > Provider:** Шляхи від клієнтів завжди віддаються перевазі над шляхами від пірів або провайдерів.
2. **Топологічна ациклічність графіку комерційних відносин:** Граф орієнтованих зв'язків «клієнт → провайдер» не містить орієнтованих циклів.

Дотримання цих двох умов гарантує існування єдиної стійкої розв'язки та збіжність BGP за скінченний час.

| **Складність повідомлень** | `O(|V| * |E|)` | `O(|V| * |E|)` | `O(|E|)` затоплення |
