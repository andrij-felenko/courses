# 🧮 Алгоритми канального стрибка BLE: математичний апарат CSA #1 та CSA #2

Бездротовий радіообмін у відкритому неліцензованому діапазоні 2.4 ГГц ISM підпорядковується фундаментальним законам електродинаміки та хвильової фізики. Коли електромагнітна хвиля випромінюється антеною передавача всередині приміщення або промислового цеху, вона багаторазово відбивається від стін, металевих перегородок, бетонних перекриттів та рухомих об'єктів. У точці прийому сумарне електромагнітне поле формується як векторна суперпозиція великої кількості променів із різними амплітудами та фазовими зсувами.

---

## 1. Фізична та статистична природа радіозавад у діапазоні 2.4 ГГц

Статистичний розподіл амплітуди результуючого сигналу за відсутності прямої видимості описується розподілом Релея (*Rayleigh fading*). Через різницю в довжині пройдених шляхів виникає часовий розкид затримки (*delay spread*) `σ_τ`, який у типових закритих приміщеннях становить від 50 до 250 нс.

Цьому розкиду затримок відповідає смуга когерентності радіоканалу `B_c`, у межах якої амплітудно-частотна характеристика середовища залишається відносно рівномірною:

```
B_c ≈ 1 / (2 · π · σ_τ)
```

При розкиді затримки `σ_τ = 100 нс` смуга когерентності дорівнює приблизно 1.6 МГц. Це означає, що якщо на одній частоті інтерферуючі промені складаються у протифазі, утворюючи глибокий деструктивний нуль із падінням потужності сигналу на 20–30 дБ (частотно-вибіркове завмирання), то на сусідній частоті, віддаленій на 2.0 МГц, ті самі промені можуть додаватися синфазно, забезпечуючи високий рівень прийому.

Саме тому весь діапазон Bluetooth Low Energy 2400.0–2483.5 МГц розбито на 40 каналів із фіксованим міжцентровим кроком 2.0 МГц. Якщо радіолінія фіксується на одній статичній несучій, випадковий просторовий зсув приймача на чверть довжини хвилі (близько 3.1 см для частоти 2.4 ГГц) здатний повністю розірвати зв'язок. Єдиним математично надійним захистом є постійна зміна частоти — псевдовипадковий канальний стрибок (англ. *Frequency-Hopping Spread Spectrum*, FHSS).

## 2. Частотна сітка та бітова маска Channel Map

Центральна частота каналу з фізичним індексом `k` (`k ∈ [0, 39]`) розраховується за лінійним законом:

```
f(k) = 2402 + k · 2.0 МГц
```

Канали 37 (2402 МГц), 38 (2426 МГц) та 39 (2480 МГц) виділені для первинного рекламування і не беруть участі у передачі прикладних даних. Канали з індексами 0–36 формують множину з 37 каналів передачі даних.

Якість кожного з 37 каналів постійно оцінюється ведучим (Master/Central) за рівнем бітових помилок CRC та потужністю сторонніх шумів RSSI. Поточний стан радіоефіру фіксується у 37-бітній структурі **Channel Map** (`usedChannelMap`):

```
usedChannelMap = [b₀, b₁, b₂, ..., b₃₆]
де b_k = 1, якщо канал k вільний від завад та дозволений для роботи;
   b_k = 0, якщо канал k вимкнений через високий рівень шуму чи блокування Wi-Fi.
```

Кількість дозволених каналів позначається як `k_used` (`numUsedChannels`). Згідно зі специфікацією Bluetooth Core Specification, робота можлива лише тоді, коли активними залишаються щонайменше 2 канали (`2 ≤ k_used ≤ 37`).

## 3. Алгоритм CSA #1: лінійна конгруентність та ремапінг

Алгоритм CSA #1 застосовувався у версіях Bluetooth 4.0, 4.1 та 4.2. Його математичною основою є лінійний рекурентний генератор у скінченному кільці лишків `ℤ / 37ℤ`.

### 3.1. Генерація невідображеного каналу (Unmapped Channel)

Для кожної нової події з'єднання з порядковим номером `n` обчислюється проміжний індекс `unmappedChannel[n]`:

```
unmappedChannel[n] = (lastUnmappedChannel + Hop_Increment) mod 37
```

* `lastUnmappedChannel` — невідображений канал попередньої події зв'язку (для першої події після з'єднання `lastUnmappedChannel = 0`).
* `Hop_Increment` — псевдовипадкове ціле число з множини `[5, 16]`, яке обирається Master і фіксується у кадрі `CONNECT_IND`.

#### Доведення повноти періоду послідовності
Розглянемо циклічну групу за додаванням `(ℤ / 37ℤ, +)`. Оскільки порядок групи дорівнює простому числу 37, кожен ненульовий елемент групи є її генератором (твірним елементом). Для будь-якого `Hop_Increment ∈ [5, 16]` найбільший спільний дільник із числом 37 дорівнює одиниці:

```
НСД(Hop_Increment, 37) = 1
```

Звідси випливає фундаментальна теорема: порядок елемента `Hop_Increment` у групі `ℤ / 37ℤ` дорівнює точно 37. Тобто послідовність `unmappedChannel[n]` утворює замкнену циклічну перестановку довжини 37:

```
{unmappedChannel[0], unmappedChannel[1], ..., unmappedChannel[36]} = {0, 1, 2, ..., 36}
```

Жоден канал не повторюється двічі, доки не будуть вичерпані всі 37 можливих значень.

### 3.2. Алгоритм заміщення (Channel Remapping) у CSA #1

Якщо обчислений `unmappedChannel[n]` позначений у бітовій масці `usedChannelMap` як активний (`b[unmappedChannel[n]] == 1`), він негайно призначається для радіообміну:

```
transmissionChannel[n] = unmappedChannel[n]
```

Якщо ж `unmappedChannel[n]` вимкнений (`b[unmappedChannel[n]] == 0`), контролер відображає його на множину дозволених каналів за формулою модульного ремапінгу:

```
remappingIndex = unmappedChannel[n] mod k_used
transmissionChannel[n] = sortedUsedChannels[remappingIndex]
```

де `sortedUsedChannels` — масив фізичних номерів активних каналів, упорядкований за зростанням індексів.

### 3.3. Покроковий числовий приклад траєкторії CSA #1

Простежимо роботу алгоритму для перших п'яти послідовних подій з'єднання (`connEvent = 0, 1, 2, 3, 4`).

Нехай задано такі початкові умови:
* `Hop_Increment = 9`
* Дозволені лише 8 каналів: `sortedUsedChannels = [1, 4, 10, 15, 20, 25, 30, 35]` (`k_used = 8`)
* Початковий стан перед подією 0: `lastUnmappedChannel = 0`

Розрахуємо стан для кожної події покроково:

```
Подія 0:
  unmappedChannel[0] = (0 + 9) mod 37 = 9
  Перевірка активності каналу 9: відсутній у списку sortedUsedChannels (вимкнений).
  remappingIndex = 9 mod 8 = 1
  transmissionChannel[0] = sortedUsedChannels[1] = 4 (Частота: 2410 МГц)
  lastUnmappedChannel = 9

Подія 1:
  unmappedChannel[1] = (9 + 9) mod 37 = 18
  Перевірка активності каналу 18: вимкнений.
  remappingIndex = 18 mod 8 = 2
  transmissionChannel[1] = sortedUsedChannels[2] = 10 (Частота: 2422 МГц)
  lastUnmappedChannel = 18

Подія 2:
  unmappedChannel[2] = (18 + 9) mod 37 = 27
  Перевірка активності каналу 27: вимкнений.
  remappingIndex = 27 mod 8 = 3
  transmissionChannel[2] = sortedUsedChannels[3] = 15 (Частота: 2432 МГц)
  lastUnmappedChannel = 27

Подія 3:
  unmappedChannel[3] = (27 + 9) mod 37 = 36
  Перевірка активності каналу 36: вимкнений.
  remappingIndex = 36 mod 8 = 4
  transmissionChannel[3] = sortedUsedChannels[4] = 20 (Частота: 2442 МГц)
  lastUnmappedChannel = 36

Подія 4:
  unmappedChannel[4] = (36 + 9) mod 37 = 45 mod 37 = 8
  Перевірка активності каналу 8: вимкнений.
  remappingIndex = 8 mod 8 = 0
  transmissionChannel[4] = sortedUsedChannels[0] = 1 (Частота: 2404 МГц)
  lastUnmappedChannel = 8
```

З наведеного числового прикладу чітко видно детерміновану закономірність: послідовність вибору каналів суворо повторює циклічний порядок елементів у масиві дозволених частот.

### 3.4. Математичний аналіз нерівномірності ремапінгу в CSA #1

Головним теоретичним дефектом алгоритму CSA #1 є спотворення рівномірного розподілу ймовірностей при заміщенні заблокованих каналів.

Нехай загальна кількість активних каналів дорівнює `k_used`, а кількість заблокованих каналів становить `M = 37 - k_used`. Усі 37 невідображених значень рівноймовірні з апріорною ймовірністю `P(unmapped = x) = 1/37`.

Коли заблокований канал відображається через операцію `unmappedChannel mod k_used`, цілочисельне ділення 37 на `k_used` дає частку `q` та залишок `r`:

```
37 = q · k_used + r, де 0 ≤ r < k_used
```

Це означає, що перші `r` індексів масиву `sortedUsedChannels` (з індексами від 0 до `r - 1`) отримуватимуть на один можливий вихідний канал більше, ніж решта `k_used - r` індексів. Ймовірність вибору каналу `sortedUsedChannels[i]` становить:

```
P(channel = sortedUsedChannels[i]) = (q + 1) / 37, для 0 ≤ i < r
P(channel = sortedUsedChannels[i]) = q / 37,       для r ≤ i < k_used
```

Наприклад, якщо через потужні широкосмугові завади Wi-Fi активними залишаються лише `k_used = 12` каналів:

```
37 = 3 · 12 + 1  ==>  q = 3, r = 1
```

Перший елемент масиву `sortedUsedChannels[0]` буде обиратися з імовірністю `(3 + 1) / 37 = 4 / 37 ≈ 10.8%`, тоді як усі інші 11 каналів отримуватимуть лише `3 / 37 ≈ 8.1%`. Канал з нульовим індексом зазнаватиме на 33% більшого навантаження, що підвищує ймовірність взаємних колізій із сусідніми пристроями.

## 4. Алгоритм CSA #2: псевдовипадкові перестановки Bluetooth 5.0

Щоб повністю усунути лінійну періодичність, ліквідувати спотворення ймовірностей ремапінгу та унеможливити передбачуваність траєкторій стрибків, у специфікацію Bluetooth 5.0 було введено алгоритм **CSA #2**.

Математичний апарат CSA #2 побудований на трьох концепціях:
1. Генерація 16-бітного псевдовипадкового числа на основі конгруентного множення на спеціальну константу.
2. Нелінійна бітова перестановка (розгортання бітових тетрад і байтів).
3. Псевдовипадковий ремапінг без зміщення ймовірностей через множення на розрядну сітку.

```
                              Архітектура конвеєра CSA #2
                                           │
       connEventCounter (16 біт) ──────────┴────────── accessAddress (32 біти)
                                           │
                                           ▼
       1. Початкове комбінування: var_a = connEventCounter ^ accessAddress[15:0]
                                           │
                                           ▼
       2. Перше конгруентне множення: prn_a = (var_a · 0x2EAB) mod 65536
                                           │
                                           ▼
       3. Перестановка та змішування: var_b = Permutation(prn_a) ^ accessAddress[31:16]
                                           │
                                           ▼
       4. Друге конгруентне множення: prn_b = (var_b · 0x2EAB) mod 65536
                                           │
                                           ▼
       5. Формування результату: prn_e = Permutation(prn_b)
                                           │
                                           ▼
       6. Невідображений канал: unmappedChannel = prn_e mod 37
                                           │
                   ┌───────────────────────┴───────────────────────┐
                   ▼                                               ▼
        Канал активний у масці                         Канал заблокований у масці
                   │                                               │
                   ▼                                               ▼
        transmissionChannel                             7. Незміщений ремапінг:
          = unmappedChannel                                 prn_r = Permutation(prn_e)
                                                            index = (k_used · prn_r) >> 16
                                                            transmissionChannel
                                                              = sortedUsedChannels[index]
```

### 4.1. Алгебраїчна функція бітової перестановки Permutation(v)

Функція `Permutation(v)` виконує дзеркальне розгортання бітів усередині кожного з двох байтів 16-бітного слова `v`:

```
Permutation(v) = (bit_rev_8(v[15:8]) << 8) | bit_rev_8(v[7:0])
```

Функція `bit_rev_8(B)` розгортає 8-бітний вектор `B = (b₇, b₆, b₅, b₄, b₃, b₂, b₁, b₀)` у зворотному порядку:

```
bit_rev_8(b₇b₆b₅b₄b₃b₂b₁b₀) = b₀b₁b₂b₃b₄b₅b₆b₇
```

У двійковій алгебрі ця операція еквівалентна множенню вектора бітів на зворотну одиничну матрицю розмірності 8×8 над полем `GF(2)`:

```
┌ b₀ ┐   ┌ 0 0 0 0 0 0 0 1 ┐ ┌ b₇ ┐
│ b₁ │   │ 0 0 0 0 0 0 1 0 │ │ b₆ │
│ b₂ │   │ 0 0 0 0 0 1 0 0 │ │ b₅ │
│ b₃ │ = │ 0 0 0 0 1 0 0 0 │ · │ b₄ │
│ b₄ │   │ 0 0 0 1 0 0 0 0 │ │ b₃ │
│ b₅ │   │ 0 0 1 0 0 0 0 0 │ │ b₂ │
│ b₆ │   │ 0 1 0 0 0 0 0 0 │ │ b₁ │
└ b₇ ┘   └ 1 0 0 0 0 0 0 0 ┘ └ b₀ ┘
```

Така перестановка знищує лінійну кореляцію між сусідніми бітами лічильника подій, розсіюючи ентропію молодших бітів по всій розрядній сітці слова.

### 4.2. Магічна константа множника 0x2EAB

Множник `0x2EAB` (десяткове 11947) обрано розробниками стандарту на основі спектрального тесту Дональда Кнута для лінійних конгруентних генераторів над кільцем `ℤ / 2¹⁶ℤ`.

Число 11947 задовольняє таким властивостям:
1. `11947 ≡ 3 (mod 8)` — це забезпечує максимальну довжину періоду генератора для парних модулів виду `2^m`.
2. Константа `0x2EAB` у двійковому представленні має вигляд `0010 1110 1010 1011b`, де одиничні біти рівномірно розподілені по розрядах, що гарантує швидке лавинне поширення одиниць під час додавання часткових добутків у схемі апаратного помножувача.

### 4.3. Математика незміщеного ремапінгу (Unbiased Pseudo-Random Remapping)

Коли невідображений канал `unmappedChannel` потрапляє на вимкнену частоту, CSA #2 обчислює новий індекс без використання операції взяття залишку `mod k_used`.

Замість цього береться додаткове псевдовипадкове число `prn_r = Permutation(prn_e)`, яке інтерпретується як дріб `F = prn_r / 65536` на одиничному відрізку `[0, 1)`. Множення цього дробу на кількість дозволених каналів `k_used` розбиває відрізок на `k_used` абсолютно рівних інтервалів:

```
remappingIndex = ⌊ k_used · (prn_r / 65536) ⌋ = (k_used · prn_r) >> 16
```

Оскільки число 65536 у багато разів перевищує максимальну кількість каналів 37 (`65536 / 37 ≈ 1771.24`), кожен активний канал отримує від 1771 до 1772 дискретних квантів псевдовипадкового числа. Відхилення ймовірності вибору між різними каналами становить менше ніж `1 / 65536 ≈ 0.0015%`, що забезпечує ідеально плоский спектральний розподіл випромінювання.

### 4.4. Покроковий розрахунок CSA #2 для послідовних подій

Простежимо роботу CSA #2 для трьох послідовних подій (`connEventCounter = 100, 101, 102`) при адресі сесії `accessAddress = 0xA5B3C1D2`:

```
accessAddress[15:0] = 0xC1D2
accessAddress[31:16] = 0xA5B3

Подія 100 (0x0064):
  1. var_a = 0x0064 ^ 0xC1D2 = 0xC1B6 (49590)
  2. prn_a = (49590 · 11947) mod 65536 = 592451730 mod 65536 = 0x5D72 (23922)
  3. Permutation(0x5D72):
     bit_rev_8(0x5D = 01011101b) = 10111010b = 0xBA
     bit_rev_8(0x72 = 01110010b) = 01001110b = 0x4E
     Permutation(0x5D72) = 0xBA4E
  4. var_b = 0xBA4E ^ 0xA5B3 = 0x1FFD (8189)
  5. prn_b = (8189 · 11947) mod 65536 = 97833983 mod 65536 = 0x0C7F (3199)
  6. prn_e = Permutation(0x0C7F):
     bit_rev_8(0x0C) = 0x30, bit_rev_8(0x7F) = 0xFE ==> prn_e = 0x30FE (12542)
  7. unmappedChannel = 12542 mod 37 = 36 (Частота: 2476 МГц)

Подія 101 (0x0065):
  1. var_a = 0x0065 ^ 0xC1D2 = 0xC1B7
  2. prn_a = (49591 · 11947) mod 65536 = 0x8C1D (35869)
  3. Permutation(0x8C1D) = 0x31B8
  4. var_b = 0x31B8 ^ 0xA5B3 = 0x940B (37899)
  5. prn_b = (37899 · 11947) mod 65536 = 0x5B5D (23389)
  6. prn_e = Permutation(0x5B5D) = 0xDABA (56000)
  7. unmappedChannel = 56000 mod 37 = 19 (Частота: 2440 МГц)
```

Зміна молодшого біта лічильника подій (із 100 на 101) викликала повну перебудову всіх 16 бітів проміжних станів: канал стрибнув із 36 на 19 (зсув на 34 МГц), що повністю виключає кореляцію між сусідніми кроками.

## 5. Підтримка піделементів (Sub-event Channel Selection)

У розширеннях Bluetooth 5.0+ з'явилася можливість передачі пачок пакетів всередині однієї події з'єднання на різних частотах (наприклад, для ізохронних потоків LE Audio, Periodic Advertising with Responses — PAwR та періодичної реклами).

Алгоритм CSA #2 підтримує генерацію частоти для кожного окремого піделемента (*sub-event*) без зміни глобального лічильника `connEventCounter`:

```
unmappedChannel(subEvent) = (prn_e + subEvent) mod 37
```

де `subEvent` — цілочисельний лічильник пакетів у межах поточного сеансу (`0, 1, 2, ...`). Це дозволяє навіть усередині одного вікна обміну `T_IFS` здійснювати стрибки між різними частотами, захищаючи довгі масиви даних від імпульсних завад.

У режимі PAwR (Bluetooth 5.4) тисячі міток електронних цінників (ESL) прослуховують призначені їм індивідуальні підінтервали часу. Генерація псевдовипадкового каналу для кожного піделемента запобігає блокуванню радіолінії широкосмуговим Wi-Fi шумом навіть під час опитування тисяч пристроїв за одну секунду.

## 6. Синхронізація оновлення Channel Map та лічильник Instant

Коли ведучий виявляє нові джерела завад і вирішує змінити конфігурацію дозволених каналів, він не може застосувати нову маску `usedChannelMap` негайно: якщо пакет із новою маскою загубиться в ефірі, Slave залишиться на старій сітці частот, і зв'язок миттєво розірветься.

Для безпечного переходу використовується механізм відкладеної синхронізації через лічильник **Instant**:
1. Ведучий надсилає пакет керування `LL_CHANNEL_MAP_IND`, у якому передає нову маску та абсолютне значення лічильника подій `Instant`.
2. Значення `Instant` встановлюється із запасом: `Instant ≥ connEventCounter + 6`. Це гарантує, що сторони матимуть щонайменше 6 подій зв'язку для успішної доставки та підтвердження кадру навіть за наявності серйозних завад.
3. До настання події з номером `Instant` обидва пристрої продовжують обчислювати робочі частоти за старою маскою.
4. У момент настання події, коли `connEventCounter == Instant`, обидва контролери одночасно і синхронно замінюють збережену бітову маску на нову. Якщо до моменту `Instant` підтвердження не надійшло, з'єднання негайно аварійно розривається з кодом помилки `0x28` (*Instant Passed*), оскільки несинхронізована зміна частотної карти унеможливлює подальший радіообмін.

## 7. Спектральна ентропія та ймовірність колізій

Для оцінки якості псевдовипадкового розподілу частот використовується інформаційна ентропія Шеннона:

```
H(X) = - ∑ P(channel = i) · log₂(P(channel = i))
```

Для 37 каналів передачі даних теоретичний максимум ентропії (ідеально рівномірний білий шум) становить:

```
H_max = log₂(37) ≈ 5.20945 біт
```

Статистичні вимірювання показують, що алгоритм **CSA #2** забезпечує практичну ентропію `H ≈ 5.2089 біт` незалежно від кількості заблокованих каналів, тоді як для застарілого **CSA #1** при блокуванні 25 каналів ентропія падає нижче 3.52 біт через спотворення ремапінгу.

Коефіцієнт спектральної площинності SFM (*Spectral Flatness Measure*), що розраховується як відношення середнього геометричного потужності спектральних складових до середнього арифметичного:

```
SFM = exp( (1/N) · ∑ ln(S(f_i)) ) / ( (1/N) · ∑ S(f_i) )
```

для CSA #2 наближається до `1.0` (ідеальний білий шум), тоді як для CSA #1 опускається до `0.65–0.75`.

Ця різниця безпосередньо впливає на ймовірність колізій `P_collision` між двома незалежними некоординованими мережами BLE:

```
P_collision(CSA #2) = k_overlap / (k₁ · k₂)
P_collision(CSA #1) = ∑ P_i² > k_overlap / (k₁ · k₂)
```

Застосування алгоритму CSA #2 мінімізує взаємне глушіння пристроїв у щільних бездротових середовищах, скорочує кількість повторних передач ARQ та безпосередньо подовжує термін служби батареї автономних сенсорів.

Окрім того, обчислювальна складність CSA #2 оптимізована для виконання на 32-розрядних ядрах ARM Cortex-M без використання апаратного ділення: усі множення виконуються за один такт ALU, а бітові перестановки транслюються компілятором в інструкцію розгортання бітів `RBIT` або зсувні маски. Це гарантує, що розрахунок частоти для кожної події з'єднання виконується менш ніж за 50 наносекунд, не створюючи затримок перед запуском синтезатора частоти радіотрансивера. Завдяки цьому протокол зберігає детерміновані часові інтервали передачі навіть на малопотужних процесорах із тактовою частотою 16–32 МГц.
