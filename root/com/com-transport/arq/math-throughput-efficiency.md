# 🧮 Виведення формул ефективності та пропускної здатності протоколів ARQ

Аналітичний розрахунок коефіцієнта використання каналу зв'язку та пропускної здатності для протоколів Stop-and-Wait, Go-Back-N і Selective Repeat дозволяє точно обрати розмір передавального вікна, розрахувати таймаут повтору та оцінити граничні втрати швидкості за відомої ймовірності помилки кадру й фізичної затримки поширення сигналу.

---

## Загальна модель часового бюджету та визначення ефективності

Для кількісного зіставлення протоколів повторної передачі розглянемо повнодуплексний канал зв'язку з бітовою швидкістю `R` біт/с. Передавач надсилає інформаційні кадри фіксованої довжини `L` бітів, а приймач повертає службові пакети підтвердження (`ACK`/`NACK`) довжиною `L_ack` бітів. Фізична відстань між вузлами становить `d` метрів, а швидкість поширення електромагнітної хвилі в середовищі дорівнює `v` м/с.

Часові складові одного елементарного циклу передачі:

1. **Час випромінювання кадру даних (`t_frame`):**
```
t_frame = L / R
```

2. **Час поширення сигналу в середовищі (`t_prop`):**
```
t_prop = d / v
```

3. **Час випромінювання службового підтвердження (`t_ack`):**
```
t_ack = L_ack / R
```

4. **Час апаратної обробки та перевірки контрольної суми CRC на приймачі (`t_proc`).** У сучасних контролерах `t_proc` і `t_ack` на кілька порядків менші за `t_frame` та `t_prop`, тому для спрощення аналітичних викладок приймається `t_proc ≈ 0` та `t_ack ≈ 0`.

Повна затримка кругового обігу сигналу (англ. *Round-Trip Time*, `RTT`) визначає мінімальний інтервал від початку передачі першого біта кадру до моменту отримання відповіді:

```
RTT = t_frame + 2 · t_prop + t_proc + t_ack
≈ t_frame + 2 · t_prop      [при t_proc ≈ 0, t_ack ≈ 0]
```

Ключовим безрозмірним параметром каналу є **нормалізована затримка поширення** `a`:

```
a = t_prop / t_frame = (d · R) / (v · L)
```

Параметр `a` відображає відношення просторової довжини каналу до довжини пакета. Якщо `a = 10`, це означає, що за час передачі одного кадру сигнал долає лише `1/10` відстані до приймача, а у фізичному середовищі може одночасно перебувати до `10` пакетів у прямому напрямку.

Нехай `P_f` — імовірність того, що кадр даних буде пошкоджено завадою або втрачено в каналі (`0 ≤ P_f < 1`). Вважаємо зворотний канал для `ACK` ідеальним або включаємо ймовірність втрати `ACK` до сумарної ймовірності збою циклу `P_f`.

**Коефіцієнтом використання каналу** (англ. *Throughput Efficiency* або *Channel Utilization*, `η`) називають відношення часу, витраченого на успішну передачу корисних даних, до повного середнього часу, необхідного для їх гарантованої доставки:

```
η = t_frame / T_avg
```

Реальна корисна пропускна здатність каналу (англ. *Goodput*, `S`) виражається через `η` і бітову швидкість `R`:

```
S = R · η
```

## Виведення формули для Stop-and-Wait ARQ

У протоколі Stop-and-Wait передавач відправляє рівно один кадр і повністю зупиняє роботу до отримання підтвердження `ACK` або закінчення таймауту повторної передачі `RTO`.

Мінімальний час одного циклу передачі за відсутності помилок:

```
T_0 = t_frame + 2 · t_prop = t_frame · (1 + 2·a)
```

Якщо кадр пошкоджено, передавач чекає закінчення таймауту `RTO`. Оптимальне значення таймауту встановлюється рівним часу очікування `ACK`: `RTO = T_0`. Отже, кожна невдала спроба передачі займає інтервал `T_0`.

Кількість спроб передачі `K`, необхідних для першого успішного прийому кадру, є дискретною випадковою величиною з геометричним розподілом:
- 1 спроба (успіх з першого разу): ймовірність `1 - P_f`;
- 2 спроби (1 помилка + 1 успіх): ймовірність `P_f · (1 - P_f)`;
- `k` спроб (`k - 1` помилок + 1 успіх): ймовірність `P_f^(k-1) · (1 - P_f)`.

Математичне сподівання кількості спроб `E[K]` обчислюється через суму нескінченного ряду:

```
E[K]
= ∑ (k = 1 .. ∞) k · P_f^(k-1) · (1 - P_f)      [означення математичного сподівання]
= (1 - P_f) · ∑ (k = 1 .. ∞) k · P_f^(k-1)     [винесення константи за знак суми]
= (1 - P_f) · d/d(P_f) [ ∑ (k = 0 .. ∞) P_f^k ] [диференціювання степеневого ряду]
= (1 - P_f) · d/d(P_f) [ 1 / (1 - P_f) ]        [сума нескінченної геометричної прогресії]
= (1 - P_f) · 1 / (1 - P_f)²                    [похідна складеної функції]
= 1 / (1 - P_f)                                 [скорочення на (1 - P_f)]
```

Середній сумарний час `T_avg`, необхідний для успішної доставки одного кадру:

```
T_avg
= E[K] · T_0
= (1 / (1 - P_f)) · t_frame · (1 + 2·a)         [підстановка E[K] та T_0]
= t_frame · (1 + 2·a) / (1 - P_f)
```

Підставляючи `T_avg` у формулу коефіцієнта використання каналу `η`, отримуємо остаточний вираз для Stop-and-Wait ARQ:

```
η_SW
= t_frame / T_avg
= t_frame / (t_frame · (1 + 2·a) / (1 - P_f))   [підстановка T_avg]
= (1 - P_f) / (1 + 2·a)                         [остаточна формула Stop-and-Wait]
```

### Аналіз граничних станів Stop-and-Wait

1. **Ідеальний короткий канал (`a → 0`, `P_f = 0`):**
```
η_SW = (1 - 0) / (1 + 0) = 1.0   (100% утилізації лінії)
```

2. **Канал із великою затримкою (`a >> 1`, наприклад `a = 100`, `P_f = 0`):**
```
η_SW = 1 / (1 + 200) = 1 / 201 ≈ 0.00497   (менше 0.5% пропускної здатності)
```
Навіть за повної відсутності фізичних помилок 99.5% часу передавач марно простоює в очікуванні відлуння сигналу.

## Виведення формули для Go-Back-N ARQ

У протоколі Go-Back-N передавач використовує ковзне вікно розміром `N` кадрів, надсилаючи блоки безперервно один за одним. Приймач має нульовий буфер не за порядком (англ. *Zero out-of-order buffer*) і приймає виключно кадр із суворо очікуваним номером `R_next`. Усі кадри, що надійшли після втраченого, приймач відкидає без збереження.

Для повного завантаження лінії розмір вікна `N` повинен покривати час кругового циклу:

```
N_opt ≥ 1 + 2·a
```

### Випадок 1: Розмір вікна достатній (`N ≥ 1 + 2·a`)

Коли `N ≥ 1 + 2·a`, передавач не зупиняється через очікування підтверджень за відсутності помилок. Час, що витрачається на кожну спробу передачі одного кадру, дорівнює точно `t_frame`.

Якщо передача кадру виявилася невдалою (ймовірність `P_f`), приймач відкидає як цей зіпсований кадр, так і наступні `N - 1` кадрів, які передавач уже встиг виштовхнути в канал у межах відкритого вікна `N`. Після спливання таймауту або отримання повторного `ACK` передавач повертається назад і повторно надсилає всю групу з `N` кадрів.

Таким чином:
- Успішна передача з першої спроби займає `1` кадровий інтервал `t_frame` (ймовірність `1 - P_f`);
- Невдала спроба коштує рівно `N` кадрових інтервалів `t_frame` марно переданих та відкинутих блоків.

Середня кількість відправлених кадрових слотів `E[M]` для доставки одного корисного пакета:

```
E[M]
= 1 · (1 - P_f) + (1 + N) · P_f · (1 - P_f) + (1 + 2·N) · P_f² · (1 - P_f) + ...
= (1 - P_f) · ∑ (i = 0 .. ∞) (1 + i·N) · P_f^i
= (1 - P_f) · [ ∑ (i = 0 .. ∞) P_f^i + N · ∑ (i = 0 .. ∞) i · P_f^i ]
= (1 - P_f) · [ 1 / (1 - P_f) + N · P_f / (1 - P_f)² ]
= 1 + N · P_f / (1 - P_f)
= (1 - P_f + N · P_f) / (1 - P_f)
= (1 + (N - 1) · P_f) / (1 - P_f)
```

Ефективність `η_GBN` при `N ≥ 1 + 2·a` дорівнює оберненій величині до середньої кількості переданих слотів:

```
η_GBN
= 1 / E[M]
= (1 - P_f) / (1 + (N - 1) · P_f)               [для N ≥ 1 + 2·a]
```

### Випадок 2: Розмір вікна недостатній (`N < 1 + 2·a`)

Якщо розмір вікна `N` менший за затримку кругового циклу `1 + 2·a`, передавач вичерпує вікно до приходу першого `ACK` і змушений простоювати. Канал недовантажується пропорційно коефіцієнту `N / (1 + 2·a)`:

```
η_GBN
= (N / (1 + 2·a)) · (1 / E[M])
= (N · (1 - P_f)) / ((1 + 2·a) · (1 + (N - 1) · P_f))   [для N < 1 + 2·a]
```

При `N = 1` формула Go-Back-N точно вироджується у формулу Stop-and-Wait:

```
η_GBN (N=1)
= (1 · (1 - P_f)) / ((1 + 2·a) · (1 + 0 · P_f))
= (1 - P_f) / (1 + 2·a) = η_SW                  [повний збіг]
```

## Виведення формули для Selective Repeat ARQ

У протоколі вибіркового повтору (англ. *Selective Repeat*, SR) приймач обладнаний буфером упорядкування розміром `W_rx = W`. Якщо один із кадрів губиться, приймач продовжує приймати наступні неушкоджені кадри, зберігає їх у пам'яті та підтверджує індивідуальними або вибірковими квитанціями `SACK`.

Передавач повторює **виключно пошкоджений кадр**, не чіпаючи коректно прийняті сусідні пакети.

Оскільки кожна передача кожного кадру є незалежною подією з імовірністю успіху `1 - P_f`, середня кількість передач для кожного окремого кадру дорівнює:

```
E[K] = 1 / (1 - P_f)
```

### Випадок 1: Розмір вікна достатній (`W ≥ 1 + 2·a`)

Коли передавальне вікно `W` повністю покриває конвеєр кругового обігу (`W ≥ 1 + 2·a`), передавач ніколи не припиняє відправку нових даних або вибіркових повторів. Усі надіслані кадри (крім повторів зіпсованих) є корисними:

```
η_SR
= 1 / E[K]
= 1 / (1 / (1 - P_f))
= 1 - P_f                                       [для W ≥ 1 + 2·a]
```

**Фундаментальний результат:** ефективність Selective Repeat за достатнього розміру вікна **взагалі не залежить від затримки каналу `a`**, а визначається виключно фізичною якістю лінії зв'язку `P_f`.

### Випадок 2: Розмір вікна недостатній (`W < 1 + 2·a`)

Якщо вікно `W` замале, передавач вичерпує буфер і простоює в очікуванні `ACK`/`SACK`:

```
η_SR
= (W / (1 + 2·a)) · (1 - P_f)                   [для W < 1 + 2·a]
```

## Математична модель гібридного ARQ (HARQ)

У класичних схемах ARQ кожна невдала спроба повністю анулюється: приймач відкидає зашумлений пакет, навіть якщо `95%` або `99%` його бітів були прийняті безпомилково. Гібридний ARQ (англ. *Hybrid ARQ*, HARQ) зберігає м'які рішення демодулятора (логарифмічні відношення правдоподібності, LLR) у спеціальному буфері та об'єднує їх з енергією або паритетними бітами наступних повторів.

### 1. Chase Combining (HARQ-CC): накопичення енергії сигналу

У схемі Chase Combining кожна повторна передача містить абсолютно ідентичну копію початкового кодового блоку (однакова кодова швидкість `R_0` та індекс версії надлишковості `RV = 0`).

Нехай на `k`-й спробі передачі демодулятор формує вектор м'яких рішень (LLR) для кожного біта кодового слова:

```
LLR_k(b_i) = ln( P(b_i = 0 | y_k) / P(b_i = 1 | y_k) )
```

У гауссівському каналі з білим шумом (AWGN) та відношенням сигнал/шум `SNR = E_s / N_0` софт-комбінування полягає в поелементному алгебраїчному додаванні LLR усіх отриманих копій:

```
LLR_total(b_i) = ∑ (j = 1 .. k) LLR_j(b_i)
```

Оскільки корисні сигнали в копіях когерентно збігаються за фазою та амплітудою, а шуми на різних спробах є взаємно незалежними, сумарне відношення сигнал/шум після `k` спроб зростає строго лінійно:

```
SNR_eff(k)
= k · SNR                                       [лінійне накопичення енергії копій]
```

У логарифмічному масштабі кожен повтор збільшує ефективне SNR на:

```
ΔSNR(дБ) = 10 · lg(2) ≈ 3.01 дБ                 [для подвоєння кількості копій]
```

Ймовірність помилки кадру на `k`-му кроці `P_f(k)` швидко спадає зі зростанням `k`. Якщо канальний кодер FEC має круту характеристику («водоспадну» криву декодування), імовірність помилки після `k` об'єднань описується функцією:

```
P_f(k) ≈ Q( √(2 · k · SNR · d_min) )
```
де `d_min` — мінімальна кодова відстань, а `Q(x)` — хвостова функція стандартного нормального розподілу.

Середня кількість передач для одного блоку в HARQ-CC:

```
E[K_CC] = 1 + P_f(1) + P_f(1)·P_f(2) + P_f(1)·P_f(2)·P_f(3) + ...
= 1 + ∑ (m = 1 .. M_max - 1) ∏ (j = 1 .. m) P_f(j)
```
де `M_max` — максимальна дозволена кількість спроб (у 3GPP LTE/5G типово `M_max = 4` або `8`).

Оскільки `P_f(2) << P_f(1)`, сума в ряді обривається практично після другого члена. Коефіцієнт використання каналу для HARQ-CC з віконним механізмом на `N_proc` паралельних процесів становить:

```
η_HARQ_CC = R_code · (1 - P_residual) / E[K_CC]
```
де `R_code = K_info / N_coded` — базова швидкість кодера FEC, а `P_residual` — ймовірність невиправної помилки після `M_max` спроб:

```
P_residual = ∏ (j = 1 .. M_max) P_f(j)
```

### 2. Incremental Redundancy (HARQ-IR): адаптивна кодова швидкість

У схемі інкрементальної надлишковості (англ. *Incremental Redundancy*, IR) базова материнська кодова швидкість вибирається дуже низькою (наприклад, `R_mother = 1/3` для Turbo-коду або `R_mother = 1/5` для LDPC в 5G NR).

Під час першої передачі кодове слово піддається сильному пунктуванню (англ. *Puncturing*): передаються лише систематичні (інформаційні) біти та мінімальна кількість паритету, що забезпечує високу ефективну початкову швидкість `R_eff(1) = 3/4` або `4/5` (індекс `RV = 0`).

Якщо приймач фіксує помилку CRC, передавач на другій спробі надсилає **не копію**, а раніше виколоті паритетні біти (індекс `RV = 1` або `RV = 2`). Приймач об'єднує м'які рішення:

```
R_eff(k) = K_info / (N_1 + N_2 + ... + N_k)
```

Після `k` спроб еквівалентна швидкість коду падає:
- 1-ша спроба: передано `N_1` бітів → швидкість `R_1 = 3/4`;
- 2-га спроба: передано `N_1 + N_2` бітів → швидкість `R_2 = 1/2`;
- 3-тя спроба: передано `N_1 + N_2 + N_3` бітів → швидкість `R_3 = 1/3`.

Кодовий виграш від розширення кодового блоку значно перевищує простий енергетичний приріст `+3 дБ` у Chase Combining. За теоремою Шеннона максимальна спектральна ефективність, якої досягає HARQ-IR в адаптивному каналі, наближається до межі пропускної здатності:

```
η_HARQ_IR ≈ min [ R_max, C(SNR) ] = min [ R_max, log₂(1 + SNR) ]
```

Це перетворює HARQ-IR на самоналагоджувану систему передачі: при високому SNR пакет проходить з першої спроби з максимальною швидкістю `R_max`, а при глибокому завмиранні автоматично добирає потрібну кількість паритету до гарантованого декодування.

## Статистика затримки та розподіл часу доставки (Jitter)

Для прикладних систем реального часу (потокове аудіо/відео, керування безпілотниками, промислова автоматизація) важлива не лише середня пропускна здатність `η`, а й розподіл випадкової величини затримки доставки пакета `D`.

### 1. Функція розподілу затримки в Stop-and-Wait та Selective Repeat

У каналі з постійним часом кругового обігу `RTT` та незалежною ймовірністю помилки кадру `P_f` затримка доставки кадру `D_k` (час від постановки в чергу до успішного прийому) набуває дискретних значень:

```
D_k = t_frame + t_prop + (k - 1) · RTT
```
де `k` — номер спроби, на якій кадр був успішно прийнятий (`k = 1, 2, 3, ...`).

Ймовірність того, що пакет буде доставлено рівно за `k` спроб, підпорядковується геометричному закону:

```
P(K = k) = P_f^(k-1) · (1 - P_f)
```

Кумулятивна функція розподілу (англ. *Cumulative Distribution Function*, `CDF`) визначає ймовірність того, що пакет буде успішно доставлений не пізніше, ніж за `M` спроб (тобто за час `D ≤ D_max(M)`):

```
F_D(M)
= P(K ≤ M)
= ∑ (k = 1 .. M) P_f^(k-1) · (1 - P_f)
= (1 - P_f) · (1 - P_f^M) / (1 - P_f)           [сума скінченної геометричної прогресії]
= 1 - P_f^M                                     [імовірність успіху за ≤ M спроб]
```

### 2. Квантилі затримки та хвостова затримка (Tail Latency)

Нехай задано цільову надійність доставки `1 - ε` (наприклад, `99.9%`, тобто `ε = 10⁻³`). Мінімальна кількість спроб `M_req`, необхідна для досягнення цієї надійності:

```
1 - P_f^M_req ≥ 1 - ε
P_f^M_req ≤ ε
M_req · ln(P_f) ≤ ln(ε)
M_req ≥ ⌈ ln(ε) / ln(P_f) ⌉                     [бо ln(P_f) < 0, знак нерівності змінюється]
```

Максимальна гарантована затримка для 99.9-го перцентиля (`D_99.9`):

```
D_99.9 = t_frame + t_prop + ( ⌈ ln(0.001) / ln(P_f) ⌉ - 1 ) · RTT
```

### 3. Числовий приклад розрахунку квантилів затримки

Розгляньмо канал зв'язку телеметрії БПЛА з параметрами:
- Затримка кругового обігу: `RTT = 20` мс;
- Час передачі кадру: `t_frame = 2` мс;
- Час поширення в один бік: `t_prop = 9` мс;
- Імовірність спотворення пакета через завади: `P_f = 0.1` (10%).

Розрахунок затримок за перцентилями:

1. **Медіанна затримка (50-й перцентиль, `k = 1`):**
```
D_50 = 2 + 9 = 11 мс    (90% пакетів доходять за 11 мс)
```

2. **99-й перцентиль (`ε = 0.01`):**
```
M_99 = ⌈ ln(0.01) / ln(0.1) ⌉ = ⌈ (-4.605) / (-2.302) ⌉ = 2 спроби
D_99 = 11 мс + (2 - 1) · 20 мс = 31 мс
```

3. **99.9-й перцентиль (`ε = 0.001`):**
```
M_99.9 = ⌈ ln(0.001) / ln(0.1) ⌉ = ⌈ (-6.908) / (-2.302) ⌉ = 3 спроби
D_99.9 = 11 мс + (3 - 1) · 20 мс = 51 мс
```

4. **99.99-й перцентиль (`ε = 0.0001`):**
```
M_99.99 = ⌈ ln(0.0001) / ln(0.1) ⌉ = 4 спроби
D_99.99 = 11 мс + 3 · 20 мс = 71 мс
```

Цей результат пояснює феномен **блокування початку черги** (англ. *Head-of-Line Blocking*, HoL): якщо прикладний рівень вимагає строгого збереження послідовності байтів (як у протоколі TCP), втрата одного-єдиного пакета затримує видачу всіх наступних успішно отриманих пакетів на величину до `71` мс, що викликає ривки та деградацію інтерактивних систем керування. Для уникнення HoL-блокування протоколи реального часу (QUIC, WebRTC, RTP/UDP) або застосовують частково надійний ARQ (з обмеженням часу життя пакета), або передають критичні потоки в незалежних паралельних сесіях.

## Зведена порівняльна таблиця та числові розрахунки

Зведена система аналітичних формул:

| Протокол | Ефективність `η` (за `Window ≥ 1 + 2·a`) | Обмеження розміру вікна | Буфер приймача | Чутливість до затримки `a` |
| :--- | :--- | :--- | :--- | :--- |
| **Stop-and-Wait** | `η = (1 - P_f) / (1 + 2·a)` | `N = 1` | `0` байтів | Екстремальна (`~ 1/a`) |
| **Go-Back-N** | `η = (1 - P_f) / (1 + (N - 1) · P_f)` | `W_tx ≤ 2^k - 1` | `0` байтів | Висока при великих `N · P_f` |
| **Selective Repeat** | `η = 1 - P_f` | `W_tx = W_rx ≤ 2^(k-1)` | `W · L` байтів | Відсутня (за `W ≥ 1 + 2a`) |
| **HARQ-CC** | `η = R_code · (1 - P_res) / E[K_CC]` | `N_proc` процесів | `N_proc · L_llr` | Низька (локальний RTT PHY) |
| **HARQ-IR** | `η ≈ min[R_max, C(SNR)]` | `N_proc` процесів | `N_proc · L_llr` | Мінімальна (адаптація до каналу) |

### Числовий приклад 1: Оптоволоконна магістраль через континент

Параметри лінії:
- Швидкість: `R = 10` Гбіт/с (`10¹⁰` біт/с);
- Довжина траси: `d = 3000` км (`3 · 10⁶` м);
- Швидкість у волокні: `v = 2 · 10⁸` м/с;
- Довжина кадру (Ethernet Jumbo): `L = 9000` байтів = `72 000` бітів;
- Імовірність помилки кадру: `P_f = 10⁻³` (`0.001`).

Розрахунок параметрів затримки:
```
t_frame = 72 000 / 10¹⁰ = 7.2 · 10⁻⁶ с = 7.2 мкс
t_prop = 3 · 10⁶ / (2 · 10⁸) = 0.015 с = 15 мс = 15 000 мкс
a = t_prop / t_frame = 15 000 / 7.2 ≈ 2083.3
N_opt = 1 + 2 · a = 1 + 4166.6 ≈ 4168 кадрів
```

Розрахунок ефективності та реальної пропускної здатності `S = R · η`:

1. **Stop-and-Wait:**
```
η_SW = (1 - 0.001) / (1 + 2 · 2083.3) = 0.999 / 4167.6 ≈ 0.0002397
S_SW = 10 000 Мбіт/с · 0.0002397 ≈ 2.397 Мбіт/с
```
(Швидкість впала з `10 000` Мбіт/с до `2.4` Мбіт/с — деградація у `4170` разів!)

2. **Go-Back-N (вікно `N = 4168`):**
```
η_GBN = (1 - 0.001) / (1 + (4168 - 1) · 0.001) = 0.999 / (1 + 4.167) = 0.999 / 5.167 ≈ 0.1933
S_GBN = 10 000 Мбіт/с · 0.1933 ≈ 1933 Мбіт/с = 1.933 Гбіт/с
```
(Втрачено понад 80% ємності каналу через групові повтори при `P_f = 0.1%`).

3. **Selective Repeat (вікно `W = 4168`):**
```
η_SR = 1 - 0.001 = 0.999
S_SR = 10 000 Мбіт/с · 0.999 = 9990 Мбіт/с = 9.99 Гбіт/с
```
(Практично повне збереження гігабітної швидкості лінії).

### Числовий приклад 2: Супутниковий геостаціонарний канал (GEO)

Параметри супутникового ретранслятора:
- Швидкість: `R = 20` Мбіт/с;
- Довжина кадру: `L = 1500` байтів = `12 000` бітів;
- Час поширення в обидва боки: `2 · t_prop = 500` мс;
- Імовірність помилки кадру: `P_f = 0.05` (5%).

Розрахунок:
```
t_frame = 12 000 / (20 · 10⁶) = 0.0006 с = 0.6 мс
a = t_prop / t_frame = 250 / 0.6 ≈ 416.67
N_opt = 1 + 2 · a = 1 + 833.33 = 835 кадрів
```

Порівняння пропускної здатності:
```
η_SW = (1 - 0.05) / (1 + 833.33) = 0.95 / 834.33 ≈ 0.001138  → S = 22.8 кбіт/с
η_GBN = (1 - 0.05) / (1 + 834 · 0.05) = 0.95 / (1 + 41.7) = 0.95 / 42.7 ≈ 0.0222 → S = 445 кбіт/с
η_SR = 1 - 0.05 = 0.95 → S = 19.0 Мбіт/с
```

Ці розрахунки наочно демонструють, чому в сучасних бездротових, супутникових та магістральних мережах протоколи Stop-and-Wait і Go-Back-N повністю витіснені схемами Selective Repeat та гібридним ARQ (HARQ).
