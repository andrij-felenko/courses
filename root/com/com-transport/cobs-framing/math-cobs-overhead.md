# 🧮 Математичний аналіз оверхеду: COBS проти SLIP, PPP та біт-стаффінгу

Математичний аналіз накладних витрат кадрування встановлює точні аналітичні межі та ймовірнісний розподіл додаткових байтів у каналі зв'язку, доводячи, чому COBS мінімізує обсяг службових даних порівняно з класичними методами екранування.

---

## Формалізація простору повідомлень та оператора кадрування

Нехай канал передачі даних оперує дискретним алфавітом октетів `B = {0, 1, 2, ..., 255}`, потужність якого становить `|B| = 256`. Вхідне повідомлення (корисне навантаження) довжиною `N` октетних позицій є вектором у просторі послідовностей:

```
X = (x₁, x₂, ..., x_N),  x_i ∈ B,  N ≥ 0
```

Простір усіх можливих корисних повідомлень довжини `N` має потужність `|B^N| = 256^N`.

Кадруванням називають ін'єктивне відображення `F: B^N → (B \ {D})^* · D`, яке перетворює довільний вхідний вектор `X` на закодовану послідовність октетних значень, де октет `D ∈ B` є спеціальним виділеним розділювачем кадру (англ. *frame delimiter*).

Фундаментальною вимогою коректності кадрування є виконання двох інваріантів:
1. **Інваріант виключення розділювача:** Жоден елемент закодованого тіла послідовності, крім фінального символу, не може набувати значення `D`.
2. **Інваріант однозначного відновлення:** Відображення `F` є строго оборотним (існує ліве обернене відображення `F⁻¹`), тобто для будь-яких двох різних повідомлень `X₁ ≠ X₂` їхні закодовані образи не збігаються: `F(X₁) ≠ F(X₂)`.

Позначимо через `L(X)` довжину закодованого тіла повідомлення без урахування кінцевого розділювача `D`.

**Абсолютними накладними витратами (оверхедом, англ. *overhead*)** називають різницю між довжиною закодованого тіла та початковою довжиною корисних даних:

```
O(X) = L(X) - N
```

**Відносними накладними витратами** називають частку додаткових байтів відносно початкового обсягу корисного навантаження:

```
ω(X) = O(X) / N = (L(X) - N) / N
```

Для аналізу надійності та детермінізму виділення буферів вбудованих систем ключове значення мають три метрики:
* `O_min(N) = min_{X ∈ B^N} O(X)` — найкращий випадок;
* `O_max(N) = max_{X ∈ B^N} O(X)` — найгірший випадок (гарантована верхня межа);
* `E[O(X)]` — математичне сподівання накладних витрат при рівномірному випадковому розподілі вхідних байтів.

## Строге аналітичне виведення верхньої межі оверхеду COBS

В алгоритмі COBS як унікальний розділювач обирається нульовий октет `D = 0x00`.

Нехай довільний вхідний масив `X` довжиною `N` містить рівно `k` нульових байтів (`0 ≤ k ≤ N`), розташованих на позиціях `p₁, p₂, ..., p_k`. Ці нулі природно розбивають масив на `k + 1` сегментів, кожен із яких складається виключно з ненульових байтів алфавіту `B \ {0}`:

```
X = (S₀, 0, S₁, 0, S₂, ..., 0, S_k)
```

Позначимо кількість ненульових байтів у кожному сегменті `S_i` через `l_i = |S_i| ≥ 0`. Оскільки повна кількість ненульових байтів дорівнює `N - k`, сума довжин усіх сегментів задовольняє рівність:

```
∑_{i=0}^{k} l_i = N - k
```

За правилами алгоритму COBS кожен неперервний сегмент ненульових байтів довжиною `l_i` розбивається на підблоки розміром не більше ніж `254` байти. Кількість підблоків `b_i`, на які розпадається `i`-й сегмент, точно дорівнює:

```
b_i = ⌊l_i / 254⌋ + 1
```

Кожен такий підблок отримує рівно один байт покажчика зміщення `c ∈ {1, 2, ..., 255}`. При цьому самі `k` нульових байтів вихідного масиву повністю поглинаються покажчиками й не займають місця в закодованому потоці.

Повна довжина закодованого повідомлення `L(X)` складається із суми довжин усіх ненульових байтів та суми всіх доданих байтів покажчиків:

```
L(X)
= ∑_{i=0}^{k} l_i + ∑_{i=0}^{k} b_i             [довжина даних плюс кількість покажчиків]
= (N - k) + ∑_{i=0}^{k} (⌊l_i / 254⌋ + 1)      [підставили суму l_i та формулу b_i]
= (N - k) + (k + 1) + ∑_{i=0}^{k} ⌊l_i / 254⌋ [винесли одиницю з кожного з (k+1) доданків]
= N + 1 + ∑_{i=0}^{k} ⌊l_i / 254⌋             [спростили різницю: (N - k) + (k + 1) = N + 1]
```

Оцінимо максимальне значення суми цілих частин за допомогою властивості субадитивності функції округлення донизу:

```
∑_{i=0}^{k} ⌊l_i / 254⌋
≤ ⌊(∑_{i=0}^{k} l_i) / 254⌋                   [субадитивність операції floor]
= ⌊(N - k) / 254⌋                             [підставили ∑ l_i = N - k]
```

Підставляючи отриману оцінку у вираз для довжини `L(X)`, маємо нерівність:

```
L(X) ≤ N + 1 + ⌊(N - k) / 254⌋
```

Оскільки кількість нульових байтів `k` є невід'ємним цілим числом (`k ≥ 0`), функція `⌊(N - k) / 254⌋` є монотонно незростаючою за змінною `k`. Свого абсолютного максимуму вона досягає при мінімально можливому значенні `k = 0`, тобто коли у вхідному повідомленні **взагалі немає нульових байтів**:

```
L_max(N)
= N + 1 + ⌊N / 254⌋                           [підставили k = 0 у нерівність максимуму]
= N + ⌈N / 254⌉                               [алгебраїчна тотожність: 1 + ⌊N/254⌋ = ⌈N/254⌉ для N > 0]
```

Звідси випливає строга теорема про максимальний оверхед COBS.

> **Теорема (Верхня межа оверхеду COBS):**
> Для будь-якого вхідного повідомлення довжиною `N > 0` октетів абсолютні накладні витрати алгоритму COBS не перевищують величини:
> ```
> O_max(N) = ⌈N / 254⌉
> ```

Для порожнього масиву `N = 0` алгоритм формує один початковий байт покажчика `0x01`:
```
L(0) = 1  [покажчик зміщення 0x01 для порожнього блоку]
O(0) = 1  [один байт оверхеду]
```

Дослідимо асимптотичну поведінку відносного оверхеду при необмеженому зростанні розміру пакета `N`:

```
ω_max(N)
= ⌈N / 254⌉ / N                               [означення відносного оверхеду]
≤ (N / 254 + 1) / N                            [властивість стелі: ⌈x⌉ < x + 1]
= 1 / 254 + 1 / N                              [почленний поділ на N]
```

Обчислюючи границю при `N → ∞`, отримуємо граничну константу накладних витрат:

```
lim_{N→∞} ω_max(N)
= lim_{N→∞} (1 / 254 + 1 / N)                 [підставили формулу оцінки]
= 1 / 254                                      [границя 1/N прямує до 0]
≈ 0.00393700787... (0.3937%)
```

Це фундаментальний результат: **у найгіршому випадку накладні витрати COBS ніколи не перевищують 0.4% від обсягу корисного навантаження**.

## Інформаційно-теоретична оцінка та ентропійна ціна вилучення нуля

Цікаво оцінити алгоритм COBS з точки зору теорії інформації Клода Шеннона.

Початковий вхідний потік байтів оперує алфавітом із 256 символів. Максимальна ентропія одного вхідного октету становить:

```
H_in = log₂(256) = 8.0 бітів на байт
```

Закодоване тіло кадру COBS повністю виключає символ `0x00`, тобто оперує зменшеним алфавітом із 255 символів (`1..255`). Максимальна ентропія одного закодованого символу становить:

```
H_out = log₂(255)
≈ 7.994353436... бітів на байт
```

Втрата інформаційної ємності на кожен переданий байт дорівнює:

```
ΔH = H_in - H_out
= 8.0 - 7.994353436                            [підстановка значень ентропій]
≈ 0.005646564 бітів на байт                    [обчислення різниці]
```

Щоб передати ту саму кількість інформації за допомогою 255-символьного алфавіту, теоретично необхідне відносне розширення довжини потоку:

```
ΔL / L = (H_in / H_out) - 1
= (8.0 / 7.994353436) - 1                      [підстановка відношення ентропій]
≈ 0.0007063 (0.0706%)                          [обчислення теоретичного надлишку]
```

Алгоритм COBS додає `1 / 254 ≈ 0.3937%` у найгіршому випадку та `0.23%` у середньому, що надзвичайно близько до абсолютного теоретичного мінімуму Шеннона для будь-яких систем виключення символу без побітового стиснення.

## Розрахунок корисної пропускної здатності каналу UART (Goodput)

Для інженерів систем зв'язку критично важливо оцінювати ефективну швидкість передачі корисних даних (англ. *Goodput*), яка враховує як фізичний оверхед UART (старт-біт, 8 бітів даних, стоп-біт у форматі 8N1 — разом 10 бітів на кожен байт), так і оверхед кадрування COBS.

Час передачі пакета корисного навантаження довжиною `N` байтів на швидкості `BaudRate` біт/с виражається формулою:

```
T_frame(N) = (10 · L_total(N)) / BaudRate
= (10 · (N + ⌈N / 254⌉ + 1)) / BaudRate
```

Корисна бітова швидкість передавача визначається як:

```
Goodput(N) = (8 · N) / T_frame(N)
= (0.8 · BaudRate) · (N / (N + ⌈N / 254⌉ + 1))
```

Для стандартних швидкостей послідовного порту UART маємо такі значення максимального Goodput при розмірі пакета `N = 254` байти:
* **UART 115 200 біт/с:** `Goodput = 0.8 · 115200 · (254 / 256) ≈ 91 440` біт/с (або 11.43 Кбайт/с).
* **UART 921 600 біт/с:** `Goodput = 0.8 · 921600 · (254 / 256) ≈ 731 520` біт/с (або 91.44 Кбайт/с).
* **UART 3 000 000 біт/с:** `Goodput = 0.8 · 3000000 · (254 / 256) ≈ 2 381 250` біт/с (або 297.65 Кбайт/с).

Завдяки фіксованому оверхеду COBS корисна швидкість відрізняється від теоретичного максимуму UART 8N1 менше ніж на 0.78% для будь-яких пакетів розміром понад 250 байтів.

## Математичний аналіз модифікації COBS/R

Модифікація COBS/R усуває додатковий байт зміщення для останнього блоку даних у випадках, коли значення останнього байта `d_last` перевищує довжину цього блоку `L` (`d_last ≥ L + 1`).

Позначимо через `P_R` ймовірність того, що випадковий пакет дозволить застосувати оптимізацію COBS/R.

Припустимо, що довжина фінального блоку `L` рівномірно розподілена в діапазоні `1..254`, а значення останнього байта `d_last` незалежно розподілене на множині `{1..255}`.

Ймовірність виконання умови `d_last ≥ L + 1` для фіксованого `L` дорівнює:

```
P(d_last ≥ L + 1 | L)
= (255 - L) / 255                              [кількість сприятливих значень байта]
```

Усереднюючи за всіма можливими довжинами фінального блоку `L ∈ {1..254}`:

```
P_R
= (1 / 254) · ∑_{L=1}^{254} ((255 - L) / 255)  [математичне сподівання умовної ймовірності]
= (1 / (254 · 255)) · ∑_{j=1}^{254} j          [заміна індексу j = 255 - L]
= (1 / (254 · 255)) · ((254 · 255) / 2)        [сума арифметичної прогресії]
= 1 / 2                                        [скорочення дробів]
= 0.50 (50.0%)
```

Якщо ж останній байт пакета є молодшим байтом контрольної суми CRC (розподіл якого близький до ідеально рівномірного на `0..255`), а середня довжина фінального блоку невелика (`L ≈ 10`), ймовірність спрацювання COBS/R сягає:

```
P(d_last ≥ 11)
= (255 - 10) / 255                             [кількість сприятливих значень для L = 10]
= 245 / 255                                    [обчислення різниці в чисельнику]
≈ 0.9608 (96.08%)                              [ділення та переведення у відсотки]
```

Таким чином, для 96% реальних пакетів телеметрії із захистом CRC алгоритм COBS/R забезпечує **абсолютно нульовий оверхед кадрування** (довжина закодованого масиву точно дорівнює довжині вхідного пакета плюс 1 байт кінцевого розділювача `0x00`).

## Комбінаторний аналіз розподілу довжин блоків

Щоб глибше зрозуміти поведінку алгоритму, розглянемо комбінаторну структуру розбиття повідомлення на блоки.

Нехай вхідне повідомлення довжиною `N` містить `k` нулів. Кількість способів розташувати `k` нулів серед `N` позицій дорівнює біноміальному коефіцієнту `C(N, k) = N! / (k! · (N - k)!)`.

Кожне таке розташування нулів однозначно задає композицію числа `N - k` на `k + 1` невід'ємних доданків `(l₀, l₁, ..., l_k)`. 

Загальна кількість доданих байтів покажчиків визначається кількістю доданків, що перевищують `254`. Якщо кожен `l_i < 254`, загальна кількість покажчиків становить строго `k + 1`.

У результаті закодоване повідомлення має точну довжину:
```
L(X) = (N - k) + (k + 1) = N + 1
```

Це показує дивовижну властивість алгоритму COBS: **для будь-якого повідомлення, у якому між нулями немає проміжків більше ніж 254 байти, оверхед становить рівно 1 байт**, незалежно від того, скільки нулів було у вихідному масиві (хоч 1, хоч 100, хоч 1000).

Кожен нуль у вхідному масиві знищується, зменшуючи довжину даних на 1 байт, але водночас породжує новий блок, додаючи 1 байт покажчика. Ці дві дії взаємно компенсують одна одну з точністю до одного початкового байта зміщення.

## Ймовірнісний аналіз оверхеду на випадкових потоках даних

Розгляньмо модель випадкового джерела даних, у якому кожен вхідний байт `x_i` є незалежною однаково розподіленою випадковою величиною (англ. *i.i.d.*) з рівномірним розподілом на множині `B`:

```
P(x_i = v) = 1 / 256,  ∀ v ∈ {0, 1, ..., 255}
```

Ймовірність того, що довільний байт є нулем, дорівнює `p₀ = P(x_i = 0) = 1 / 256`, а ймовірність ненульового байта становить `q₀ = P(x_i ≠ 0) = 255 / 256`.

Довжина неперервної серії ненульових байтів між двома сусідніми нулями є дискретною випадковою величиною `L_run`, яка підпорядковується геометричному розподілу:

```
P(L_run = m) = q₀^m · p₀ = (255 / 256)^m · (1 / 256),  m = 0, 1, 2, ...
```

Математичне сподівання довжини ненульової серії становить:

```
E[L_run]
= q₀ / p₀                                      [математичне сподівання геометричного розподілу]
= (255 / 256) / (1 / 256)                      [підставили ймовірності q0 та p0]
= 255 октетних позицій
```

Ймовірність того, що серія ненульових байтів перевищить максимальну довжину блоку `254` і спричинить вставку додаткового покажчика `0xFF`, дорівнює:

```
P(L_run ≥ 254)
= q₀²⁵⁴                                        [ймовірність відсутності нуля на 254 позиціях поспіль]
= (255 / 256)²⁵⁴                               [підставили значення q0]
≈ 0.370163 (37.0163%)
```

Ймовірність появи серії довжиною щонайменше `2 · 254 = 508` байтів становить:

```
P(L_run ≥ 508)
= q₀⁵⁰⁸                                        [ймовірність відсутності нуля на 508 позиціях]
= ((255 / 256)²⁵⁴)²                            [піднесення до квадрата]
≈ 0.370163²
≈ 0.13702 (13.702%)
```

Математичне сподівання кількості додаткових покажчиків `0xFF`, спричинених переповненням блоків у сегменті, обчислюється як сума ймовірностей хвоста геометричного розподілу:

```
E[⌊L_run / 254⌋]
= ∑_{j=1}^{∞} P(L_run ≥ 254 · j)
= ∑_{j=1}^{∞} (q₀²⁵⁴)^j                        [сума нескінченної геометричної прогресії]
= q₀²⁵⁴ / (1 - q₀²⁵⁴)                          [формула суми прогресії: a / (1 - r)]
= 0.370163 / (1 - 0.370163)                    [підставили обчислене значення]
≈ 0.587714
```

Оскільки середня кількість сегментів у повідомленні довжиною `N` становить `E[k + 1] = N / 256 + 1`, середнє значення загальної довжини закодованого повідомлення COBS виражається формулою:

```
E[L_COBS(N)]
= N + 1 + (N / 256 + 1) · (q₀²⁵⁴ / (1 - q₀²⁵⁴)) [підставили математичні сподівання]
≈ N + 1 + (N / 256) · 0.587714
= N + 1 + 0.0022957 · N
```

Таким чином, для випадкових двійкових даних середній оверхед COBS становить лише **0.23% плюс 1 байт**, що навіть менше за теоретичну верхню межу 0.39%.

## Математичний аналіз екранування SLIP (RFC 1055)

У протоколі SLIP розділювачем є октет `END = 0xC0`. Для запобігання появі `0xC0` у даних використовується екрануючий октет `ESC = 0xDB`.

Якщо вхідний байт `x_i ∈ {0xC0, 0xDB}`, алгоритм підміняє його двома байтами (`0xDB 0xDC` або `0xDB 0xDD`). Будь-який інший байт транслюється без змін.

Довжина закодованого тіла повідомлення SLIP виражається сумою:

```
L_SLIP(X) = N + ∑_{i=1}^{N} I(x_i ∈ {0xC0, 0xDB})
```
де `I(·)` — індикаторна випадкова величина, що набуває значення 1, якщо умова виконана, та 0 в іншому випадку.

### 1. Найгірший випадок SLIP
Якщо всі байти вхідного повідомлення складаються виключно із символів `0xC0` або `0xDB`:
```
L_max_SLIP(N) = 2 · N                         [кожен байт породив 2 байти в потоці]
O_max_SLIP(N) = N                             [рівно N додаткових байтів екранування]
ω_max_SLIP(N) = 1.0 (100.0%)                  [розмір подвоївся на 100%]
```

### 2. Найкращий випадок SLIP
Якщо в повідомленні немає жодного символу `0xC0` та `0xDB`:
```
L_min_SLIP(N) = N                             [жоден байт не екранувався]
O_min_SLIP(N) = 0                             [нуль додаткових байтів]
ω_min_SLIP(N) = 0.0 (0.0%)                    [нульовий оверхед]
```

### 3. Ймовірнісні характеристики SLIP
Ймовірність появи байта, що потребує екранування у випадковому рівномірному потоці:

```
p_slip = P(x_i ∈ {0xC0, 0xDB})
= 2 / 256                                      [два заборонені символи з 256 можливих]
= 1 / 128                                      [скоротили дріб на 2]
≈ 0.0078125 (0.78125%)
```

Математичне сподівання накладних витрат SLIP:

```
E[O_SLIP(N)]
= E[∑_{i=1}^{N} I(x_i ∈ {0xC0, 0xDB})]
= ∑_{i=1}^{N} E[I(x_i ∈ {0xC0, 0xDB})]         [лінійність математичного сподівання суми]
= N · p_slip                                   [сума N однакових ймовірностей]
= N / 128                                      [підставили p_slip = 1/128]
≈ 0.0078125 · N (0.78125%)
```

Дисперсія оверхеду SLIP підпорядковується закону біноміального розподілу `Bin(N, p_slip)`:

```
Var(O_SLIP(N))
= N · p_slip · (1 - p_slip)                    [формула дисперсії біноміального розподілу]
= N · (1 / 128) · (127 / 128)                  [підставили значення ймовірності успіху та невдачі]
= (127 · N) / 16384                            [перемножили знаменники: 128 * 128 = 16384]
≈ 0.00775146 · N
```

Стандартне відхилення зростає пропорційно кореню з довжини: `σ = √(Var) ≈ 0.08804 · √N`.

## Математичний аналіз протоколу PPP (RFC 1662)

У протоколі PPP для асинхронних ліній обов'язковому екрануванню підлягають розділювач `0x7E`, escape-октет `0x7D`, а також керуючі символи таблиці ASCII `0x00..0x1F` (за замовчуванням конфігурації карти контрольних символів ACCM).

Кількість екранованих символів становить `K = 1 (0x7E) + 1 (0x7D) + 32 (ASCII 0x00..0x1F) = 34` значення.

Ймовірність екранування випадкового байта:

```
p_ppp = 34 / 256
= 17 / 128                                     [скоротили дріб на 2]
≈ 0.1328125 (13.28125%)
```

Математичне сподівання накладних витрат PPP:

```
E[O_PPP(N)]
= N · p_ppp                                    [математичне сподівання біноміального розподілу]
= (17 · N) / 128                               [підставили ймовірність 17/128]
≈ 0.1328125 · N (13.28%)
```

Для двійкового трафіку середній оверхед PPP становить майже `13.3%`, а найгірший випадок сягає `100%` (подвоєння довжини кадру).

## Порівняння з біт-стаффінгом HDLC (Синхронні канали)

У синхронному біт-стаффінгу HDLC після кожних п'яти поспіль одиничних бітів `'11111'` передавач вставляє нульовий біт `'0'`.

### 1. Найгірший випадок біт-стаффінгу
Вхідний потік складається із суцільних одиниць (`0xFF 0xFF ...`). Кожні 5 бітів породжують 1 біт надлишковості:

```
L_max_HDLC(M) = M + ⌊M / 5⌋                   [де M = 8 · N — кількість бітів навантаження]
O_max_HDLC(M) = ⌊M / 5⌋
ω_max_HDLC = 1 / 5 = 20.0%                    [максимальний оверхед становить рівно 20%]
```

### 2. Середній випадок біт-стаффінгу для випадкових бітів
Ймовірність того, що 5 послідовних бітів є одиницями:

```
p_bit
= (1 / 2)⁵                                     [ймовірність п'яти незалежних одиниць поспіль]
= 1 / 32                                       [піднесення 2 до п'ятого степеня]
= 0.03125 (3.125%)
```

## Марковська модель відновлення синхронізації при шумі

Розглянемо поведінку потокового декодера в умовах каналу зв'язку з випадковою інверсією бітів (модель двійкового симетричного каналу BSC з ймовірністю бітової помилки `p_e`).

Ймовірність спотворення одного байта в каналі дорівнює:
```
P_byte_err = 1 - (1 - p_e)⁸ ≈ 8 · p_e  (при p_e << 1)
```

Розглянемо стани приймача як ланцюг Маркова з двома макростанами:
* `S_SYNC`: Приймач перебуває в синхронізованому стані (коректно відстежує межі блоків COBS).
* `S_LOST`: Приймач втратив синхронізацію внаслідок спотворення покажчика зміщення `Code`.

Матриця перехідних ймовірностей для марковського процесу прийому чергового байта має вигляд:

```
P = [ P(SYNC → SYNC)  P(SYNC → LOST) ]
    [ P(LOST → SYNC)  P(LOST → LOST) ]
```

1. **Ймовірність втрати синхронізації `P(SYNC → LOST)`:** Відбувається лише тоді, коли спотворюється байт покажчика `Code` або байт даних перетворюється на `0x00`. Для кадру довжиною `N` байтів це становить приблизно `P_loss ≈ (N / 254 + 1) · P_byte_err`.
2. **Ймовірність повернення в синхронізм `P(LOST → SYNC)`:** Приймач у стані `S_LOST` переходить у стан `S_SYNC` відразу після отримання наступного справжнього розділювача `0x00`. Оскільки розділювач передається наприкінці кожного кадру, час перебування в стані розсинхронізації суворо обмежений тривалістю одного кадру.

Середній час відновлення синхронізації (англ. *Mean Time to Resynchronize*, MTTR):

```
MTTR_COBS = 1 кадр
```

Для порівняння, у протоколах без унікального розділювача (наприклад, протоколах на базі довжини поля `Length-Field Framing`), спотворення байта довжини призводить до зсуву парсера на довільну кількість байтів і може спричинити втрату десятків наступних пакетів поспіль, доки випадково не зійдеться контрольна сума одного з хибних зміщень.

## Зведена аналітична таблиця та числові приклади

У таблиці порівнюються математичні характеристики розглянутих методів кадрування для довільного розміру пакета `N`:

| Метрика | COBS | SLIP (RFC 1055) | PPP (Default ACCM) | HDLC (Bit-stuffing) |
|---|---|---|---|---|
| **Мінімальний оверхед `O_min`** | `1` байт | `0` байтів | `0` байтів | `0` бітів |
| **Середній оверхед `E[O]`** | `≈ 0.23% · N + 1` | `≈ 0.78% · N` | `≈ 13.28% · N` | `≈ 3.125% · M` |
| **Найгірший оверхед `O_max`** | `⌈N / 254⌉` | `N` (+100%) | `N` (+100%) | `0.2 · M` (+20%) |
| **Макс. відносний оверхед `ω_max`** | **`0.3937%`** | **`100.0%`** | **`100.0%`** | **`20.0%`** |
| **Дисперсія оверхеду** | `≈ 0` (сталий) | `0.00775 · N` | `0.11517 · N` | `0.03027 · M` |

### Практичний розрахунок розміру буфера прийому для апаратних трансиверів

Розрахуємо гарантований розмір буфера прийому `Buffer_size` (із врахуванням кінцевого розділювача `0x00`) для типових розмірів корисного навантаження вбудованих протоколів:

```
Формула буфера COBS: Buffer_COBS = N + ⌈N / 254⌉ + 1
Формула буфера SLIP: Buffer_SLIP = 2 · N + 1
```

1. **Короткий пакет IMU (`N = 32` байти):**
   ```
   Buffer_COBS = 32 + 1 + 1 = 34 байти     [оверхед 2 байти]
   Buffer_SLIP = 2 · 32 + 1 = 65 байтів    [оверхед 33 байти]
   ```

2. **Пакет телеметрії польотного контролера (`N = 254` байти):**
   ```
   Buffer_COBS = 254 + 1 + 1 = 256 байтів  [оверхед 2 байти]
   Buffer_SLIP = 2 · 254 + 1 = 509 байтів  [оверхед 255 байтів]
   ```

3. **Складна телеметрія або кадр CAN-FD (`N = 512` байтів):**
   ```
   Buffer_COBS = 512 + 3 + 1 = 516 байтів  [оверхед 4 байти]
   Buffer_SLIP = 2 · 512 + 1 = 1025 байтів [оверхед 513 байтів]
   ```

4. **Стандартний Ethernet MTU (`N = 1500` байтів):**
   ```
   Buffer_COBS = 1500 + 6 + 1 = 1507 байтів [оверхед 7 байтів]
   Buffer_SLIP = 2 · 1500 + 1 = 3001 байт   [оверхед 1501 байт]
   ```

5. **Максимальний розмір кадру IPv4 (`N = 65535` байтів):**
   ```
   Buffer_COBS = 65535 + 258 + 1 = 65794 байти [оверхед 259 байтів, тобто 0.395%]
   Buffer_SLIP = 2 · 65535 + 1 = 131071 байт   [оверхед 65536 байтів, тобто 100.0%]
   ```

Математичний аналіз однозначно демонструє, що алгоритм COBS перетворює непередбачуване роздуття пам'яті на суворо детерміновану характеристику каналу зв'язку, дозволяючи проектувальникам систем реального часу виділяти мінімально можливі буфери DMA з гарантією відсутності переповнення.
