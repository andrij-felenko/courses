# 📋 3GPP AT-команди вибору технології радіодоступу та керування живленням

Цей довідник містить повну специфікацію стандартизованих AT-команд 3GPP (стандарти TS 27.007, TS 27.005, TS 24.008 та TS 24.301), що керують вибором покоління стільникового зв'язку (RAT, Radio Access Technology), відстеженням статусу реєстрації в мережах 2G/3G/4G/5G, конфігурацією діапазонів частот (Band Locking), вимірюванням радіотелеметрії та налаштуванням енергоощадних режимів PSM і eDRX у вбудованих модемах.

---

### 1. Вибір технології радіодоступу (RAT Selection)

У пристроях, оснащених мультистандартними модемами, неправильне налаштування автоматичного пошуку (Auto-Scan) призводить до непродуктивної витрати заряду батареї: модем може витрачати від 30 до 120 секунд на сканування вимкнених діапазонів 2G або 3G перед тим, як перейти до пошуку доступної мережі LTE чи 5G.

#### Стандартна команда 3GPP: `+WS46` (Select Wireless Network)

Встановлює категорію бездротової мережі на глобальному рівні протокольного стека.

- **Синтаксис запису:** `AT+WS46=<n>`
- **Синтаксис читання:** `AT+WS46?`
- **Синтаксис тестування:** `AT+WS46=?`

| Параметр `<n>` | Технологія бездротового зв'язку | Опис режиму |
|---|---|---|
| `12` | 2G GSM / GPRS / EDGE | Виключно мережі GSM (блокує сканування UTRAN/E-UTRAN) |
| `22` | 3G UTRAN | Виключно мережі UMTS / WCDMA / HSPA |
| `28` | 4G E-UTRAN | Виключно мережі LTE (Cat.1, Cat.4, Cat.1bis) |
| `30` | 5G 5GS (NG-RAN) | Виключно мережі 5G New Radio |
| `255` | Автоматичний вибір (Auto) | Пошук за пріоритетом SIM-карти (5G → 4G → 3G → 2G) |

#### Поширені розширення виробників модемів

Оскільки стандарт `+WS46` підтримується виробниками чіпсетів неоднорідно, у практичній розробці для зменшення часу реєстрації застосовують спеціалізовані команди виробників:

- **Quectel (EC21, EC25, BG95, EG915, RG500):**
  - Синтаксис: `AT+QCFG="nwscanmode",<mode>,1`
  - `0`: Автоматичний вибір (2G / 3G / 4G / 5G)
  - `1`: Тільки 2G (GSM Only)
  - `2`: Тільки 3G (WCDMA Only)
  - `3`: Тільки 4G (LTE Only)
- **SIMCom (SIM7000, SIM7600, SIM800, A7670, SIM8200):**
  - Синтаксис: `AT+CNMP=<mode>`
  - `2`: Automatic
  - `13`: GSM Only
  - `14`: WCDMA Only
  - `38`: LTE Only
  - `55`: 5G NR Only
- **u-blox (SARA-R4, SARA-R5, LARA-R6, LEXI-R10):**
  - Синтаксис: `AT+URAT=<selected_AcT>[,<preferred_AcT1>]`
  - `0`: GSM / GPRS / eGPRS
  - `2`: UTRAN
  - `3`: LTE (Cat.1 / Cat.4 / Cat.M1)
  - `8`: NB-IoT

### 2. Фіксація частотних діапазонів (Band Locking)

Якщо пристрій експлуатується в конкретному регіоні, сканування всіх підтримуваних модемом смуг (наприклад, смуг B1, B2, B3, B4, B5, B7, B8, B12, B20, B28) збільшує час холодного старту до 45–90 секунд і створює пікове споживання струму. Фіксація дозволених діапазонів (Band Masking) скорочує час входу в мережу до 2–4 секунд.

Кодування маски діапазонів LTE виконується у вигляді шістнадцяткового числа (HEX Bitmask), де `n`-й біт відповідає смузі `Band n` (`біт 0` = Band 1, `біт 2` = Band 3, `біт 7` = Band 8, `біт 19` = Band 20):

- **Quectel:** `AT+QCFG="band",<gsmbandval>,<ltebandval>,<tdsbandval>,1`
  - Приклад: `AT+QCFG="band",0,80084,0,1` — фіксує виключно європейські смуги LTE Band 3 (`0x4`), Band 8 (`0x80`), Band 20 (`0x80000`), сума маски = `0x80084`.
- **SIMCom:** `AT+CBANDCFG="LTE",<band1>,<band2>,...`
  - Приклад: `AT+CBANDCFG="LTE",3,8,20` — дозволяє роботу лише на смугах 3, 8 та 20.

### 3. Вибір оператора та примусовий режим зв'язку: `+COPS`

Команда `+COPS` (Operator Selection) контролює режим пошуку мережі та дозволяє зафіксувати технологію радіодоступу через параметр `<AcT>` (Access Technology).

- **Синтаксис запису:** `AT+COPS=<mode>[,<format>[,<oper>[,<AcT>]]]`
- **Синтаксис читання:** `AT+COPS?` → повертає `+COPS: <mode>[,<format>,<oper>,<AcT>]`
- **Синтаксис пошуку:** `AT+COPS=?` → запускає сканування ефіру (блокує UART на 15–120 секунд).

#### Параметри команди `+COPS`

| Параметр | Значення | Опис |
|---|---|---|
| `<mode>` | `0` | Автоматичний вибір оператора (`<oper>` ігнорується) |
| | `1` | Ручний вибір оператора (модем підключається лише до вказаного `<oper>`) |
| | `2` | Примусове відключення від радіомережі (Deregister from network) |
| | `3` | Встановлення формату імені для виводу (`<format>`) без зміни реєстрації |
| | `4` | Ручний вибір із переходом в автоматичний при невдачі (Manual/Automatic) |
| `<format>` | `0` | Довгий буквений формат (Long alphanumeric string, наприклад `"Kyivstar"`) |
| | `1` | Короткий буквений формат (Short alphanumeric string, наприклад `"UA-KS"`) |
| | `2` | Числовий код PLMN: MCC+MNC (наприклад `"25501"`, `"25503"`, `"25506"`) |
| `<AcT>` | `0` | GSM |
| | `1` | GSM Compact |
| | `2` | UTRAN (3G WCDMA / HSPA) |
| | `3` | GSM w/EGPRS |
| | `4` | UTRAN w/HSDPA |
| | `5` | UTRAN w/HSUPA |
| | `6` | UTRAN w/HSDPA and HSUPA |
| | `7` | E-UTRAN (4G LTE) |
| | `8` | E-UTRAN with NB-S1 (NB-IoT) |
| | `9` | E-UTRAN with Cat.M1 (LTE-M) |
| | `11` | 5G NR (NG-RAN) |
| | `13` | 5G NR with RedCap |

### 4. Статус реєстрації в мережі: `+CREG`, `+CGREG`, `+CEREG`, `+C5GREG`

Різні покоління зв'язку використовують різні домени реєстрації в ядрі мережі:
- `+CREG`: реєстрація в домені комутації каналів CS (Circuit Switched: дзвінки та SMS у 2G/3G).
- `+CGREG`: реєстрація в домені комутації пакетів PS (Packet Switched: GPRS/EDGE/3G Packet Core).
- `+CEREG`: реєстрація в домені EPS (Evolved Packet System: 4G LTE).
- `+C5GREG`: реєстрація в домені 5GS (5G System Core).

- **Синтаксис запису:** `AT+CEREG=<n>` (де `<n>=1` вмикає короткі повідомлення URC, `<n>=2` вмикає розширені з кодом зони TAC/LAC та Cell ID).
- **Синтаксис читання:** `AT+CEREG?` → повертає `+CEREG: <n>,<stat>[,<tac>,<ci>[,<AcT>]]`

#### Таблиця статусів реєстрації `<stat>`

| Код `<stat>` | Стан реєстрації | Інженерне значення для алгоритму прошивки |
|---|---|---|
| `0` | Not registered, not searching | Модем не шукає мережу (радіомодуль вимкнено або відсутня SIM-карта) |
| `1` | Registered, home network | Успішно зареєстровано в домашній мережі оператора |
| `2` | Not registered, searching | Триває активний пошук базової станції або сканування діапазонів |
| `3` | Registration denied | Відмовлено в реєстрації (недійсна SIM, блокування оператором, відсутність контракту) |
| `4` | Unknown | Стан невизначений (помилка радіотракту або вихід за межі зони покриття) |
| `5` | Registered, roaming | Успішно зареєстровано в режимі національного чи міжнародного роумінгу |
| `8` | Emergency bearer services only | Доступні лише екстрені виклики (немає доступу до пакетної передачі) |
| `9` | Registered for CSFB | Зареєстровано в роумінгу з підтримкою Circuit Switched Fallback |
| `10` | Emergency services in roaming | Екстрені виклики в роумінгу |

### 5. Вимірювання якості радіосигналу: `+CSQ` та `+CESQ`

Класична команда `+CSQ` розроблена для 2G і повертає узагальнений показник RSSI, який у сучасних мережах 4G/5G не відображає реальної якості каналу через наявність внутрішньосмугових завад та багатовходових антен.

#### Класичний індикатор: `+CSQ`

- **Синтаксис читання:** `AT+CSQ` → `+CSQ: <rssi>,<ber>`

| Параметр | Діапазон | Формула перерахунку в фізичні одиниці |
|---|---|---|
| `<rssi>` | `0..31` | `dBm = -113 + (rssi · 2)`. Значення `0` = -113 dBm або гірше, `31` = -51 dBm або краще. `99` = Not known / undetectable. |
| `<ber>` | `0..7` | Коефіцієнт бітових помилок RXQUAL (тільки для 2G). `99` = Not known. |

#### Розширений індикатор 3GPP: `+CESQ` (Extended Signal Quality)

Команда `+CESQ` повертає роздільні фізичні параметри для кожного покоління:

- **Синтаксис:** `AT+CESQ` → `+CESQ: <rxlev>,<ber>,<rscp>,<ecno>,<rsrq>,<rsrp>`

| Показник | Покоління | Опис та діапазон | Формула обчислення |
|---|---|---|---|
| `<rxlev>` | 2G GSM | Рівень сигналу приймача (`0..63`, `99`) | `dBm = -110 + rxlev` |
| `<ber>` | 2G GSM | Рівень бітових помилок (`0..7`, `99`) | За таблицею 3GPP TS 45.008 |
| `<rscp>` | 3G UMTS | Received Signal Code Power (`0..96`, `255`) | `dBm = -120 + rscp` |
| `<ecno>` | 3G UMTS | Відношення енергії чипа до шуму (`0..49`, `255`) | `dB = -24 + (ecno · 0.5)` |
| `<rsrq>` | 4G / 5G | Reference Signal Received Quality (`0..34`, `255`) | `dB = -19.5 + (rsrq · 0.5)` (норма: > -10 dB, поріг: -19.5 dB) |
| `<rsrp>` | 4G / 5G | Reference Signal Received Power (`0..97`, `255`) | `dBm = -140 + rsrp` (чудовий: > -85 dBm, задовільний: -95..-105 dBm, поріг: -120 dBm) |

### 6. Керування енергоощадними режимами: `+CPSMS` (PSM) та `+CEDRXS` (eDRX)

Режими PSM та eDRX доступні в мережах 4G (LTE Cat.1, Cat.1bis, LTE-M, NB-IoT) та 5G (NR, RedCap). Вони узгоджуються з базовою станцією під час процедури прикріплення (Attach) або періодичного оновлення зони відстеження (TAU).

#### Команда `+CPSMS`: Power Saving Mode

- **Синтаксис запису:** `AT+CPSMS=[<mode>[,<Req_Periodic-RAU>[,<Req_GPRS-READY-timer>[,<Req_Periodic-TAU>[,<Req_Active-Time>]]]]]`
- **Синтаксис читання:** `AT+CPSMS?` → `+CPSMS: <mode>,[...],[...],<Req_Periodic-TAU>,<Req_Active-Time>`

Таймери кодуються у вигляді 8-бітного рядка `b8 b7 b6 b5 b4 b3 b2 b1`, де перші 3 біти (`b8..b6`) задають масштаб одиниці часу (базовий множник), а останні 5 бітів (`b5..b1`) — двійкове число від 0 до 31.

##### Кодування таймера періодичного TAU `T3412` (період глибокого сну PSM):

| Біти `b8 b7 b6` | Базовий множник (одиниця часу) | Приклад значення `"01000101"` |
|---|---|---|
| `000` | 10 хвилин | Множник `010` = 10 годин |
| `001` | 1 година | Значення `00101` = 5 |
| `010` | 10 годин | **Результат:** 5 × 10 годин = 50 годин сну |
| `011` | 2 секунди | |
| `100` | 30 секунд | |
| `101` | 1 хвилина | |
| `110` | 320 годин | Максимальний період: 31 × 320 год ≈ 413 діб |
| `111` | Таймер деактивовано | |

##### Кодування активного таймера `T3324` (час готовності до прийому пейджингу після завершення передачі):

| Біти `b8 b7 b6` | Базовий множник | Приклад значення `"00100100"` |
|---|---|---|
| `000` | 2 секунди | Множник `001` = 1 хвилина |
| `001` | 1 хвилина | Значення `00100` = 4 |
| `010` | 6 децихвилин (6 хвилин) | **Результат:** 4 × 1 хв = 4 хвилини активності |
| `111` | Таймер деактивовано | |

#### Команда `+CEDRXS`: Extended Discontinuous Reception (eDRX)

- **Синтаксис запису:** `AT+CEDRXS=<mode>[,<AcT-type>[,<Req_eDRX_value>]]`

| Параметр | Значення | Опис |
|---|---|---|
| `<mode>` | `0` | Вимкнути eDRX |
| | `1` | Увімкнути eDRX |
| | `2` | Увімкнути eDRX та автоматичні URC-сповіщення `+CEDRXP:` |
| `<AcT-type>` | `1` | EC-GSM-IoT (2G) |
| | `2` | GSM (2G) |
| | `3` | UTRAN (3G) |
| | `4` | E-UTRAN (4G LTE Cat.1 / Cat.4 / Cat.1bis) |
| | `5` | E-UTRAN with NB-S1 (NB-IoT) |
| `<Req_eDRX_value>` | `"0000"` .. `"1111"` | 4-бітний код періоду циклу DRX (від 5.12 с до 2621.44 с) |

### 7. Керування станом живлення радіотракту: `+CFUN` та лінії DTR/RI

Для керування загальним енергоспоживанням модема використовуються як програмні команди, так і апаратні виводи GPIO мікроконтролера.

#### Команда `+CFUN`: Phone Functionality

- **Синтаксис:** `AT+CFUN=<fun>[,<rst>]`

| Параметр `<fun>` | Режим функціональності | Споживання струму | Стан радіотракту |
|---|---|---|---|
| `0` | Мінімальна функціональність (Minimum functionality) | 1–3 мА | Радіотракт RF та SIM-інтерфейс вимкнено, AT-порт активний |
| `1` | Повна функціональність (Full functionality) | 15–300 мА | Радіотракт увімкнено, реєстрація в мережі активна |
| `4` | Режим польоту (Flight mode / Disable RF) | 1–3 мА | Радіотракт RF вимкнено, SIM-карта залишається заживленою |

Параметр `<rst>=1` змушує модем перезавантажитися (Software Reset) після встановлення рівня функціональності.

#### Апаратні лінії сну DTR та пробудження RI

- **Лінія DTR (Data Terminal Ready):** керує сном модема через команду `AT+QSCLK=1` (Quectel) або `AT+CSCLK=1` (SIMCom). При встановленні високого рівня на вході DTR модем переводить внутрішній процесор у режим сну зі споживанням менше 1 мА, вимикаючи тактування UART. Опускання DTR у низький рівень миттєво пробуджує інтерфейс керування.
- **Лінія RI (Ring Indicator):** сигналізує хост-контролеру про вхідні події (URC). Коли модем перебуває в режимі сну eDRX і базова станція надсилає вхідний пакет даних або SMS, лінія RI опускається в низький рівень на 120 мс, генеруючи зовнішнє апаратне переривання на вході мікроконтролера.

### 8. Розширені коди помилок: `+CME ERROR`

У разі виникнення збоїв під час виклику AT-команд увімкнення розширеного виводу помилок `AT+CMEE=2` змушує модем повертати текстові описи замість лаконічного `ERROR`:

| Код CME | Текстове повідомлення | Причина помилки та коригувальна дія прошивки |
|---|---|---|
| `10` | SIM not inserted | SIM-карта відсутня, брудні контакти або відпаяно слот |
| `11` | SIM PIN required | SIM-карта заблокована, вимагає введення `AT+CPIN=<PIN>` |
| `12` | SIM PUK required | Вичерпано спроби введення PIN, вимагає розблокування PUK-кодом |
| `13` | SIM failure | Апаратний збій SIM-карти або непідтримувана напруга (3.0 В замість 1.8 В) |
| `14` | SIM busy | SIM-карта зайнята внутрішньою ініціалізацією телефонної книги |
| `17` | SIM PIN2 required | Потрібен PIN2 для доступу до захищених функцій (FDN) |
| `30` | No network service | Відсутній радіосигнал у вибраних діапазонах |
| `32` | Network not allowed | Оператор відхилив запит (немає роумінгової угоди або заблоковано IMSI) |
| `100` | Unknown error | Внутрішній збій стека модема, потрібен перезапуск по лінії `RESET_N` |

### 9. Типовий лог налаштування модема в терміналі

Приклад ініціалізації модема 4G Cat.1bis із фіксацією стандарту LTE, обмеженням діапазонів, контролем якості та активацією PSM:

```text
// 1. Перевірка зв'язку та вимкнення луни
AT
OK
ATE0
OK

// 2. Увімкнення розширеного виводу помилок
AT+CMEE=2
OK

// 3. Фіксація стандарту LTE Only та вимкнення 2G/3G
AT+WS46=28
OK

// 4. Маскування діапазонів під смуги B3, B8, B20 (HEX 0x80084)
AT+QCFG="band",0,80084,0,1
OK

// 5. Увімкнення розширених сповіщень про статус реєстрації в 4G
AT+CEREG=2
OK

// 6. Налаштування PSM: період сну TAU T3412 = 24 години, активний час T3324 = 10 секунд
// T3412: "00111000" (001 = 1 год, 11000 = 24 -> 24 години)
// T3324: "00000101" (000 = 2 сек, 00101 = 5 -> 10 секунд)
AT+CPSMS=1,,,"00111000","00000101"
OK

// 7. Запит вимірювання якості каналу
AT+CESQ
+CESQ: 99,99,255,255,28,62
OK
// Інтерпретація: RSRQ = -19.5 + 28*0.5 = -5.5 dB (відмінно), RSRP = -140 + 62 = -78 dBm (відмінно)

// 8. Перевірка статусу реєстрації в мережі
AT+CEREG?
+CEREG: 2,1,"1A0F","034B8C11",7
OK
// Зареєстровано в домашній мережі (1), TAC=0x1A0F, CellID=0x034B8C11, AcT=7 (E-UTRAN LTE)
```
