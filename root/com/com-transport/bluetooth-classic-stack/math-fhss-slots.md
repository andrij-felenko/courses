# 🧮 Розрахунок часового бюджету слотів FHSS та пропускної здатності BR/EDR

Фізичний рівень радіозв'язку Bluetooth Classic використовує метод псевдовипадкового перемикання робочої частоти (англ. *Frequency Hopping Spread Spectrum*, FHSS) у неліцензованому діапазоні [ISM 2.4 ГГц](topic:sys-notary/ism-bands). Для математичного аналізу часового бюджету та розрахунку граничної пропускної здатності необхідно розглянути структуру сітки частот, таймінг слотів Baseband, затримки переналаштування синтезатора частот і формат канальних пакетів.

```
       0 мкс               366 мкс                 625 мкс
       ┌──────────────────────┬──────────────────────┐
       │   ПЕРЕДАЧА ДАНИХ     │  ПЕРЕНАЛАШТУВАННЯ    │
       │   ПАКЕТА (DH1)       │  СИНТЕЗАТОРА (FHSS)  │
       │   366 мкс ефіру      │  259 мкс паузи       │
       └──────────────────────┴──────────────────────┘
       ▲                                             ▲
       │ ═══════════════ СЛОТ 1 ════════════════════ │
```

### Математична модель сітки частот та генератора стрибків

Діапазон ISM від 2400.0 до 2483.5 МГц розбивається на 79 радіочастотних каналів із кроком 1.0 МГц. Центральна частота каналу з індексом `k` (`k ∈ [0, 78]`) визначається формулою:

```
f[k] = 2402 + k  [МГц]
```

Для запобігання позасмуговому випромінюванню передбачено захисні смуги:
- Нижня захисна смуга: 2.0 МГц (від 2400.0 до 2402.0 МГц).
- Верхня захисна смуга: 3.5 МГц (від 2480.0 до 2483.5 МГц).

Швидкість перемикання частот становить рівно 1600 стрибків за секунду у звичайному режимі передавання даних (Connection State). Тривалість одного слота ефірного часу `T_slot` розраховується як:

```
T_slot = 1 / 1600
       = 0.000625 с
       = 625 мкс
```

Внутрішній апаратний годинник контролера Baseband (`CLK`) тактується генератором із частотою 3.2 кГц. Період одного такту годинника дорівнює:

```
T_tick = 1 / 3200
       = 0.0003125 с
       = 312.5 мкс
```

Таким чином, один слот ефірного часу Bluetooth відповідає рівно двом тактам годинника `CLK` (`625 мкс = 2 · 312.5 мкс`). Стан годинника описується 28-бітним лічильником `CLK[27:0]`:
- Біт `CLK[0]` перемикається кожні 312.5 мкс і визначає фазу всередині слота (початок чи середина).
- Біт `CLK[1]` перемикається кожні 625 мкс і задає зміну номера слота.
- Біт `CLK[2]` перемикається кожні 1.25 мс і визначає пару слотів дуплексу TDD: парний слот `CLK[1] = 0` (передача Master) та непарний слот `CLK[1] = 1` (передача Slave).

Номер каналу для наступного стрибка `k` обчислюється спеціальним апаратним перестановочним генератором на основі 24 молодших бітів апаратної адреси ведучого пристрою (LAP, англ. *Lower Address Part*) та поточного значення лічильника слотів `CLK[27:1]`.

### Подвоєна швидкість перемикання частот у режимах пошуку та підключення (Inquiry та Page)

Під час процедур пошуку пристроїв (Inquiry) та безпосереднього пейджингу (Page) передавач не знає точного значення годинника віддаленого вузла. Щоб скоротити час встановлення зв'язку, швидкість стрибків підвищується вдвічі: з 1600 до **3200 стрибків за секунду** (`T_hop = 312.5 мкс`).

У межах одного 625-мікросекундного слота передавач встигає надіслати два короткі 68-бітні пакети ідентифікації ID на двох різних радіочастотах `f1` та `f2`, витрачаючи по 68 мкс на передавання та 244.5 мкс на перебудову синтезатора для кожного стрибка:

```
0 мкс           68 мкс     312.5 мкс       380.5 мкс   625 мкс
┌───────────────┬──────────┬───────────────┬───────────┐
│ ID на част. f1│ Зміна f2 │ ID на част. f2│  Зміна f3 │
└───────────────┴──────────┴───────────────┴───────────┘
```

32 частоти процедури пейджингу діляться на два потяги по 16 частот (A-train та B-train). Ведений пристрій у режимі `Page Scan` слухає одну фіксовану частоту протягом вікна `T_w_page = 11.25 мс` (18 слотів), змінюючи частоту кожні `T_i_page = 1.28 с` (режим `R1`).

Математичний розрахунок максимального та середнього часу підключення:
1. Якщо годинник `CLK` віддаленого пристрою відомий (збережений після Inquiry), ведучий одразу обирає правильний 16-частотний поїзд: максимальний час затримки становить лише один цикл обходу поїзда `T_train = 16 · 1.25 мс = 20 мс`.
2. Якщо інформація про годинник відсутня, ведучий передає поїзд A протягом `N_page = 128` повторів (1.28 с), після чого перемикається на поїзд B: максимальний час підключення сягає `T_max = 2.56 с`, а середнє математичне сподівання часу з'єднання становить `T_avg ≈ 0.64 с`.

### Часовий бюджет слота та тривалість переналаштування синтезатора

Оскільки кожен новий слот починається на іншій частоті, аналоговий синтезатор частоти радіотракту (PLL) потребує скінченного часу для перебудови гетеродина на нову частоту та стабілізації фази (PLL Lock Time).

У 1-слотовому пакеті базової швидкості (наприклад, DH1) максимальна тривалість радіовипромінювання обмежена 366 мкс. Часовий бюджет розподіляється так:

```
T_slot
= T_tx + T_guard                   [загальний баланс слота]
= 366 мкс + 259 мкс               [366 мкс передача, 259 мкс синтезатор]
= 625 мкс                          [номінальна довжина слота]
```

Захисний інтервал `T_guard = 259 мкс` забезпечує достатній запас для переходу радіочастотного тракту на наступний канал із сітки 79 частот, комутації антени між режимами прийому й передачі (RX/TX turnaround) та синхронізації корелятора приймача.

#### Багатослотові пакети (3-слотові та 5-слотові)

Для підвищення коефіцієнта корисної дії ефіру специфікація Bluetooth визначає багатослотові пакети, під час передачі яких радіочастота залишається незмінною протягом усього пакету:

1. **3-слотовий пакет (DH3 / DM3)**:
   - Номінальна тривалість: `3 · 625 мкс = 1875 мкс`.
   - Максимальний час передачі: `T_tx = 1622 мкс`.
   - Захисний інтервал наприкінці 3-го слота: `T_guard = 1875 - 1622 = 253 мкс`.
   - Протягом 3 слотів частота зафіксована. Наступний стрибок відбувається на частоту, яка відповідає значенню лічильника `CLK` у 4-му слоті (проміжні частоти просто пропускаються).

2. **5-слотовий пакет (DH5 / DM5)**:
   - Номінальна тривалість: `5 · 625 мкс = 3125 мкс`.
   - Максимальний час передачі: `T_tx = 2870 мкс`.
   - Захисний інтервал наприкінці 5-го слота: `T_guard = 3125 - 2870 = 255 мкс`.
   - За рахунок скорочення кількості переходів синтезатора корисне завантаження ефіру зростає з 58.5% (у 1-слотових пакетах) до 91.8% (у 5-слотових пакетах).

### Розрахунок пропускної здатності пакетів базової швидкості (BR, 1 Мбіт/с)

На базовій швидкості (Basic Rate) модуляція GFSK передає рівно 1 біт на один мікросекундний символ (бітова швидкість радіоканалу `R_raw = 1 000 000 біт/с`).

Структура оверхеду кадру Baseband:
- **Access Code**: 72 біти (72 мкс) — преамбула (4 біти), слово синхронізації Sync Word (64 біти), трейлер (4 біти).
- **Packet Header**: 54 біти (54 мкс) — 18 корисних бітів заголовка, захищених потрійним повторенням FEC 1/3 (`18 · 3 = 54`).
- **Payload Header**: 1 байт (8 мкс) для 1-слотових або 2 байти (16 мкс) для багатослотових пакетів.
- **CRC-16**: 16 бітів (16 мкс) для пакетів безперервного контролю помилок (DM/DH).

Розглянемо передавання асиметричного потоку (Master передає великі пакети даних, Slave повертає 1-слотовий пакет підтвердження DH1 / NULL):

#### 1. Пакет DH1 (Data High Rate 1-Slot)
- Максимальний обсяг корисного навантаження: 27 байтів.
- Часовий цикл обміну (Round-Trip Time): 1 слот передачі + 1 слот відповіді = 2 слоти = 1250 мкс.

```
Швидкість_DH1
= (27 байтів · 8 бітів/байт) ÷ 0.00125 с   [обсяг корисних бітів на період 2 слотів]
= 216 бітів ÷ 0.00125 с                    [обчислення загальної кількості бітів]
= 172 800 біт/с                            [розрахунок бітової швидкості]
= 172.8 кбіт/с                             [переведення значення у кбіт/с]
```

#### 2. Пакет DM1 (Data Medium Rate 1-Slot із кодуванням FEC 2/3)
- Корисне навантаження захищене вкороченим кодом Геммінга (10, 15).
- Максимальний обсяг корисного навантаження: 17 байтів.

```
Швидкість_DM1
= (17 байтів · 8 бітів/байт) ÷ 0.00125 с   [корисне навантаження DM1 за 2 слоти]
= 136 бітів ÷ 0.00125 с                    [обчислення сумарних корисних бітів]
= 108 800 біт/с                            [розрахунок бітової швидкості]
= 108.8 кбіт/с                             [переведення значення у кбіт/с]
```

#### 3. Пакет DH3 (Data High Rate 3-Slot)
- Максимальний обсяг корисного навантаження: 183 байти.
- Часовий цикл: 3 слоти передачі + 1 слот відповіді = 4 слоти = 2500 мкс.

```
Швидкість_DH3
= (183 байти · 8 бітів/байт) ÷ 0.0025 с    [обсяг даних DH3 на період 4 слотів]
= 1464 біти ÷ 0.0025 с                     [обчислення сумарних бітів кадру]
= 585 600 біт/с                            [розрахунок бітової швидкості]
= 585.6 кбіт/с                             [переведення значення у кбіт/с]
```

#### 4. Пакет DM3 (Data Medium Rate 3-Slot із кодуванням FEC 2/3)
- Максимальний обсяг корисного навантаження: 121 байт.

```
Швидкість_DM3
= (121 байт · 8 бітів/байт) ÷ 0.0025 с     [корисні дані DM3 за період 4 слотів]
= 968 бітів ÷ 0.0025 с                     [обчислення корисних бітів з FEC]
= 387 200 біт/с                            [розрахунок бітової швидкості]
= 387.2 кбіт/с                             [переведення значення у кбіт/с]
```

#### 5. Пакет DH5 (Data High Rate 5-Slot)
- Максимальний обсяг корисного навантаження: 339 байтів.
- Часовий цикл асиметричного зв'язку: 5 слотів вперед + 1 слот назад = 6 слотів = 3750 мкс.

```
Швидкість_DH5_асим
= (339 байтів · 8 бітів/байт) ÷ 0.00375 с  [корисний обсяг DH5 на 6 слотів циклу]
= 2712 бітів ÷ 0.00375 с                   [обчислення повного корисного кадру]
= 723 200 біт/с                            [розрахунок бітової швидкості прямого каналу]
= 723.2 кбіт/с                             [переведення значення у кбіт/с]
```

Зворотний канал у цьому режимі забезпечує пропускну здатність передавання підтверджень:

```
Швидкість_DH1_зворотна
= (27 байтів · 8 бітів/байт) ÷ 0.00375 с   [пакет DH1 зворотного каналу на 6 слотів]
= 216 бітів ÷ 0.00375 с                    [обчислення бітів підтвердження]
= 57 600 біт/с                             [розрахунок бітової швидкості зворотного каналу]
= 57.6 кбіт/с                              [переведення значення у кбіт/с]
```

При симетричному повнодуплексному обміні пакетами DH5 в обох напрямках повний цикл становить 5 слотів + 5 слотів = 10 слотів = 6250 мкс:

```
Швидкість_DH5_симетрична
= (339 байтів · 8 бітів/байт) ÷ 0.00625 с  [корисні дані на 10 слотів повного дуплексу]
= 2712 бітів ÷ 0.00625 с                   [обчислення бітів одного напрямку]
= 433 920 біт/с                            [розрахунок симетричної швидкості]
= 433.92 кбіт/с                            [переведення значення у кбіт/с в кожен бік]
```

### Розрахунок пропускної здатності пакетів підвищеної швидкості (EDR 2 Мбіт/с та 3 Мбіт/с)

У специфікації Bluetooth 2.0+EDR заголовок пакета (Access Code та Packet Header) завжди передається базовою модуляцією GFSK на швидкості 1 Мбіт/с для збереження зворотної сумісності з усіма пристроями в пікомережі. Після заголовка вставляється захисний інтервал синхронізації (Guard Time 4.75–5.25 мкс та Sync Sequence 11 мкс), після чого тіло корисного навантаження передається фазовою модуляцією [PSK](topic:com-modulation/fsk-psk):
- **EDR 2 Мбіт/с (π/4-DQPSK)**: 2 біти на символ.
- **EDR 3 Мбіт/с (8DPSK)**: 3 біти на символ.

#### 1. Пакет 2-DH5 (π/4-DQPSK, 2 Мбіт/с)
- Максимальний обсяг корисного навантаження: 679 байтів.
- Часовий цикл асиметричного каналу: 5 слотів вперед + 1 слот назад = 3750 мкс.

```
Швидкість_2DH5_асим
= (679 байтів · 8 бітів/байт) ÷ 0.00375 с  [корисні дані 2-DH5 за 6 слотів асиметрії]
= 5432 біти ÷ 0.00375 с                    [обчислення сумарних бітів EDR 2 Мбіт/с]
= 1 448 533 біт/с                          [розрахунок асиметричної швидкості]
= 1448.53 кбіт/с                           [переведення значення у кбіт/с (≈ 1.45 Мбіт/с)]
```

Симетрична швидкість 2-DH5 (цикл 10 слотів = 6250 мкс):

```
Швидкість_2DH5_сим
= (679 байтів · 8 бітів/байт) ÷ 0.00625 с  [корисні дані на 10 слотів дуплексу 2-DH5]
= 5432 біти ÷ 0.00625 с                    [обчислення бітів кадру в один бік]
= 869 120 біт/с                            [розрахунок симетричної швидкості EDR 2 Мбіт/с]
= 869.12 кбіт/с                            [переведення значення у кбіт/с]
```

#### 2. Пакет 3-DH5 (8DPSK, 3 Мбіт/с)
- Максимальний обсяг корисного навантаження: 1021 байт.
- Часовий цикл асиметричного каналу: 5 слотів вперед + 1 слот назад = 3750 мкс.

```
Швидкість_3DH5_асим
= (1021 байт · 8 бітів/байт) ÷ 0.00375 с   [корисні дані 3-DH5 за 6 слотів асиметрії]
= 8168 бітів ÷ 0.00375 с                   [обчислення сумарних бітів EDR 3 Мбіт/с]
= 2 178 133 біт/с                          [розрахунок асиметричної швидкості]
= 2178.13 кбіт/с                           [переведення значення у кбіт/с (≈ 2.18 Мбіт/с)]
```

Симетрична швидкість 3-DH5 (цикл 10 слотів = 6250 мкс):

```
Швидкість_3DH5_сим
= (1021 байт · 8 бітів/байт) ÷ 0.00625 с   [корисні дані на 10 слотів дуплексу 3-DH5]
= 8168 бітів ÷ 0.00625 с                   [обчислення бітів кадру в один бік]
= 1 306 880 біт/с                          [розрахунок симетричної швидкості EDR 3 Мбіт/с]
= 1306.88 кбіт/с                           [переведення значення у кбіт/с (≈ 1.31 Мбіт/с)]
```

### Розрахунок параметрів голосових каналів реального часу (SCO та eSCO)

Для передавання синхронного мовного трафіку без затримок протокол Baseband виділяє суворо періодичні пари слотів із фіксованим інтервалом `T_SCO`:

1. **Канал HV1 (High Quality Voice 1)**:
   - Кодується потрійним повторенням FEC 1/3 (на 10 корисних байтів аудіо передається 30 байтів ефіру).
   - Інтервал опитування: `T_SCO = 2 слоти` (кожен парний слот — передача Master, кожен непарний — відповідь Slave).
   - Ефірне завантаження каналу становить `100%` (пікомережа не може передавати інші дані ACL).
   - Швидкість корисного аудіо: `(10 байтів · 8 бітів) / 0.00125 с = 80 бітів / 0.00125 с = 64.0 кбіт/с` (стандартне оцифрування PCM/CVSD 8 кГц × 8 біт).

2. **Канал HV2**:
   - Кодується скороченим кодом Геммінга FEC 2/3 (на 20 байтів аудіо передається 30 байтів ефіру).
   - Інтервал: `T_SCO = 4 слоти` (2.5 мс).
   - Завантаження ефіру: `50%` (2 слоти зайнято голосом, 2 слоти вільні для ACL).
   - Швидкість аудіо: `(20 байтів · 8) / 0.0025 с = 160 / 0.0025 с = 64.0 кбіт/с`.

3. **Канал HV3**:
   - Дані передаються без захисту FEC (усі 30 байтів слота — корисне аудіо).
   - Інтервал: `T_SCO = 6 слотів` (3.75 мс).
   - Завантаження ефіру: `33.3%` (2 слоти голос, 4 слоти вільні для трафіку даних або двох додаткових гарнітур HV3).
   - Швидкість аудіо: `(30 байтів · 8) / 0.00375 с = 240 / 0.00375 с = 64.0 кбіт/с`.

4. **Розширені канали eSCO (Enhanced SCO)**:
   - На відміну від legacy SCO, канали eSCO підтримують вікно повторного передавання `W_eSCO` (Retransmission Window) за наявності помилок CRC, що дозволяє передавати широкосмуговий звук HD Voice (кодек mSBC, 16 кГц) за допомогою пакетів 2-EV3 та 3-EV3 зі збереженням пропускної здатності для даних.

### Математична модель адаптивної перебудови частоти (AFH)

У середовищі зі щільним розташуванням точок доступу [Wi-Fi (IEEE 802.11)](topic:com-transport/wifi) смуга шириною 20 або 40 МГц виявляється постійно зайнятою. Якщо Bluetooth використовує класичний генератор по всіх 79 каналах, ймовірність потрапляння у смугу завад шириною 22 МГц (типовий спектр сигналу Wi-Fi DSSS/OFDM) становить:

```
P_collision
= B_wifi / B_bluetooth                     [відношення смуги завади Wi-Fi до смуги Bluetooth]
= 22 МГц / 79 МГц                          [підстановка спектральних смуг каналів]
≈ 27.85%                                   [розрахунок імовірності перекриття в ефірі]
```

Майже кожен четвертий пакет зазнає спотворення та вимагає повтору ARQ, що призводить до падіння реальної пропускної здатності на 30–50%.

#### Алгоритм класифікації та ремапінгу каналів AFH

Механізм Adaptive Frequency Hopping (AFH) динамічно зменшує робочу множину каналів до підмножини «чистих» каналів `N_used` (`20 ≤ N_used ≤ 79` за вимогами регуляторів FCC):

```
                        ПСЕВДОВИПАДКОВИЙ ГЕНЕРАТОР FHSS
                                       │
                                       ▼
                       Індекс каналу k ∈ [0, 78]
                                       │
                                       ▼
                         ┌───────────────────────────┐
                         │   КАРТА КАНАЛІВ AFH_MAP   │
                         └─────────────┬─────────────┘
                                       │
                    ┌──────────────────┴──────────────────┐
                    │                                     │
             Канал k «чистий»                      Канал k «зашумлений»
             (AFH_MAP[k] == 1)                     (AFH_MAP[k] == 0)
                    │                                     │
                    ▼                                     ▼
             Використовуємо f[k]              f_afh = MapTable[k mod N_used]
                                              (Псевдовипадкове заміщення)
```

1. **Моніторинг завад (Channel Assessment)**: контролер вимірює лічильники помилок CRC та рівень фонового шуму RSSI для кожної з 79 частот, формуючи бітову маску `AFH_Channel_Map` (79 бітів).
2. **Узгодження карти через LMP**: ведучий пристрій надсилає пакет `LMP_set_AFH`, який призначає єдину таблицю стану каналів для всіх ведених у пікомережі з фіксованого моменту часу `AFH_Instant`.
3. **Функція ремапінгу (Aliasing Function)**: якщо псевдовипадковий генератор базового алгоритму обирає заблокований канал із маски, значення перераховується за формулою заміщення на один із дозволених вільних каналів:
   ```
   f_actual = MapTable[k mod N_used]
   ```

Після активації AFH із блокуванням 22 зашумлених каналів Wi-Fi робоча множина скорочується до `N_used = 57`. Ймовірність радіоколізії падає до 0%, а пропускна здатність відновлюється до номінальних теоретичних максимумів.

### Розрахунок енергетичної ефективності та вибору довжини пакетів

При проектуванні вбудованих пристроїв вибір типу пакету є фундаментальним компромісом між пропускною здатністю, стійкістю до завад та енергоспоживанням:

1. **Коефіцієнт корисного використання ефіру (Airtime Efficiency)**:
   - Для пакету DH1 корисні дані займають `(27 · 8) / 1000 = 216 мкс` з 625 мкс слота, що дає ефективність `216 / 625 = 34.56%`.
   - Для пакету DH5 корисні дані займають `(339 · 8) / 1000 = 2712 мкс` з 3125 мкс п'яти слотів, що дає ефективність `2712 / 3125 = 86.78%`.
   - Таким чином, використання 5-слотових пакетів підвищує ефективність використання батареї у 2.5 рази завдяки радикальному зменшенню кількості пауз на роботу синтезатора частот.

2. **Ймовірність втрати кадру в зашумленому каналі**:
   Якщо ймовірність бітової помилки в ефірі становить `BER = p`, ймовірність успішного прийому пакету без помилок розраховується як `P_succ = (1 - p)^N`, де `N` — повна бітова довжина пакету в ефірі.
   Для довгого пакету DH5 (`N = 2870 бітів`) при `BER = 10^-3` ймовірність успіху становить `(1 - 0.001)^2870 ≈ 5.6%` (майже всі пакети пошкоджуються і вимагають ARQ-повторів).
   Для короткого пакету DM1 із кодуванням [FEC](topic:com-modulation/fec-codes) зв'язок залишається стабільним навіть при високих рівнях завад.

Саме тому алгоритми динамічного вибору швидкості (Rate Adaptation) у драйверах Bluetooth автоматично переходять на 5-слотові пакети 3-DH5 за високого співвідношення сигнал/шум (SNR) і знижують довжину до 1-слотових пакетів DM1 у складних умовах завад від мереж [Wi-Fi](topic:com-transport/wifi).
