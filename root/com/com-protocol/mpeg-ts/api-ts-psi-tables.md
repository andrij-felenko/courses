# 📋 Довідник двійкових структур MPEG-TS та таблиць PSI/SI

Цей довідник містить повну побайтову та побітову специфікацію двійкових заголовків транспортного пакета MPEG-TS (ISO/IEC 13818-1 / ITU-T H.222.0), формат адаптаційного поля, правила фрагментації та синтаксис секцій службових таблиць PSI (PAT, PMT), каталог стандартних дескрипторів та структуру кадру PES (Packetized Elementary Stream), необхідні для низькорівневої розробки мережевих аналізаторів, демультиплексорів та систем мовлення.

---

### 1. Заголовок транспортного пакета TS (4 байти / 32 біти)

Кожен 188-байтний пакет MPEG-TS починається з обов'язкового 4-байтового фіксованого заголовка, що передається в порядку від старшого байта до молодшого (Big-Endian). Корисне навантаження пакета не може перевищувати 184 байти.

```
Біти:    0..7        8     9      10     11..23        24..25  26..27  28..31
Поле:   [SyncByte]  [TEI] [PUSI] [Prio] [     PID    ] [ TSC ] [ AFC ] [  CC  ]
Розмір:   8 бітів    1 біт 1 біт  1 біт    13 бітів     2 біти  2 біти  4 біти
```

#### Повний опис бітових полів заголовка:

1. **Sync Byte (8 бітів, фіксоване значення `0x47` / `01000111₂`)**:
   * Маркер початку кадру пакета. Служить апаратним якорем для фазування зсувного регістра приймача.
   * *Особливість фізичного рівня DVB*: при передачі через ефірний або супутниковий канал для кожного восьмого пакета в суперкадрі значення байта синхронізації інвертується модулятором у `0xB8` (`10111000₂`). Це дозволяє апаратному дескремблеру DVB синхронізувати псевдовипадкову послідовність PRBS (ініціалізація генератора розсіювання енергії). Перед передачею на рівень демультиплексора демодулятор відновлює стандартне значення `0x47`.

2. **Transport Error Indicator (TEI, 1 біт, маска `0x80` у 2-му байті)**:
   * Прапорець фатальної помилки канального рівня.
   * Виставляється в `1` апаратним демодулятором (наприклад, декодером коду Ріда-Соломона `RS(204, 188)` або LDPC/BCH у DVB-T2/S2), коли кількість бітових спотворень у 188-байтному блоці перевищила корекційну здатність коду.
   * *Інваріант обробки*: демультиплексор зобов'язаний негайно відкинути пакет із `TEI = 1`. Обробка пошкодженого заголовка чи корисних даних заборонена, оскільки це може призвести до збою стану аналізатора або переповнення буферів декодера.

3. **Payload Unit Start Indicator (PUSI, 1 біт, маска `0x40` у 2-му байті)**:
   * Ознака початку нової інформаційної сутності в корисному навантаженні:
     * **Для пакетів із медіаданими (PES)**: значення `1` свідчить про те, що корисне навантаження пакета починається з першого байта заголовка нового кадру PES (стартовий префікс `0x000001`). Якщо `PUSI = 0`, пакет містить продовження раніше розпочатого PES-кадру.
     * **Для пакетів зі службовими таблицями (PSI/SI)**: значення `1` вказує на наявність 1-байтового поля зміщення `Pointer Field` на початку корисного навантаження.
     * Якщо пакет не містить корисного навантаження (`AFC = 0x20`), біт PUSI зобов'язаний дорівнювати `0`.

4. **Transport Priority (1 біт, маска `0x20` у 2-му байті)**:
   * Прапорець пріоритету доставки. При значенні `1` позначає найвищий пріоритет поточного пакета серед усіх пакетів з однаковим PID (наприклад, передача ключового I-кадру відео або екстреного сповіщення). Використовується чергами планувальників у статистичних мультиплексорах.

5. **PID (Packet Identifier, 13 бітів, маска `0x1FFF` у 2-му та 3-му байтах)**:
   * Унікальний ідентифікатор логічного каналу. Визначає тип та приналежність даних у діапазоні від `0x0000` до `0x1FFF` (всього `8192` доступні адреси).
   * Видобувається за формулою: `PID = ((buf[1] & 0x1F) << 8) | buf[2]`.

6. **Transport Scrambling Control (TSC, 2 біти, маска `0xC0` у 4-му байті)**:
   * Режим скремблювання (шифрування) корисного навантаження системою умовного доступу (Conditional Access):
     * `00₂` (`0x00`) — потік не зашифрований (відкритий доступ);
     * `01₂` (`0x40`) — зарезервовано стандартом ISO/IEC;
     * `10₂` (`0x80`) — зашифровано парним оперативним ключем (Even Control Word);
     * `11₂` (`0xC0`) — зашифровано непарним оперативним ключем (Odd Control Word).
   * Заголовок TS та адаптаційне поле **завжди передаються відкритими**; шифрується виключно поле Payload.

7. **Adaptation Field Control (AFC, 2 біти, маска `0x30` у 4-му байті)**:
   * Визначає наявність та порядок слідування адаптаційного поля і корисних даних:
     * `00₂` (`0x00`) — зарезервовано стандартом (недійсний пакет, підлягає відкиданню);
     * `01₂` (`0x10`) — пакет містить лише корисні дані (Payload, 184 байти);
     * `10₂` (`0x20`) — пакет містить лише адаптаційне поле (Adaptation Field, без Payload);
     * `11₂` (`0x30`) — спочатку передається адаптаційне поле, а за ним корисні дані.

8. **Continuity Counter (CC, 4 біти, маска `0x0F` у 4-му байті)**:
   * Циклічний 4-бітний лічильник послідовності від `0` до `15` (`0x0`..`0xF`).
   * *Правила інкременту*: збільшується на `1` для кожного наступного пакета з тим самим PID, який містить корисні дані (`AFC = 0x10` або `0x30`).
   * *Винятки*: лічильник CC **не збільшується**, якщо пакет містить лише адаптаційне поле (`AFC = 0x20`), або якщо пакет є заповнювальним Null-пакетом (`PID = 0x1FFF`). Дублювання значення CC допускається лише при повторній передачі ідентичного пакета.

#### Реєстр зарезервованих ідентифікаторів PID:

| Діапазон PID | Стандартне призначення | Опис сутності |
| :--- | :--- | :--- |
| `0x0000` | **PAT (Program Association Table)** | Коренева таблиця мультиплексу: зв'язок номерів програм із PID їхніх таблиць PMT. |
| `0x0001` | **CAT (Conditional Access Table)** | Таблиця умовного доступу: прив'язка систем шифрування до потоків EMM. |
| `0x0002` | **TSDT (Transport Stream Description Table)** | Опис параметрів фізичного мультиплексу. |
| `0x0003..0x000F` | Зарезервовано ISO/IEC | Системні розширення стандарту. |
| `0x0010` | **DVB NIT / ST** | Network Information Table: параметри модуляції, частоти та супутників. |
| `0x0011` | **DVB SDT / BAT** | Service Description Table: назви телеканалів, провайдери мовлення. |
| `0x0012` | **DVB EIT** | Event Information Table: електронний телегід (EPG), розклад передач. |
| `0x0014` | **DVB TDT / TOT** | Time and Date Table: всесвітній координований час UTC та місцевий часовий пояс. |
| `0x0015..0x001F` | Зарезервовано DVB / ATSC | Службові таблиці синхронізації передавачів (MIP) та сигналізації. |
| `0x0020..0x1FFE` | Вільний простір призначень | Використовується для PMT, елементарних потоків відео, аудіо, даних KLV. |
| `0x1FFF` | **Null Packet** | Порожній пакет заповнення для вирівнювання постійного бітрейту (CBR). |

### 2. Адаптаційне поле (Adaptation Field)

Адаптаційне поле розміщується безпосередньо після 4-байтового заголовка TS (починаючи з 4-го байта пакета), якщо значення бітів `AFC` дорівнює `10₂` або `11₂`.

```
Байт:   [ 0 ]         [ 1 ]         [ 2 .. 7 ]       [ 8 .. N ]
Поле:   [ AF Length ] [ 8 Flags ]   [ Опційний PCR ] [ Stuffing Bytes 0xFF ]
Розмір:   1 байт        1 байт        6 байтів         змінний (0..182 байти)
```

#### Поля адаптаційного поля:

1. **AF Length (8 бітів)**: довжина решти адаптаційного поля в байтах (не враховуючи сам байт довжини). Можливі значення від `0` до `183`. Значення `0` дозволене для швидкої вставки 1 байта заповнення.
2. **Байт прапорців конфігурації (Flags, 8 бітів)**:
   * **Біт 7 (Discontinuity Indicator)**: встановлюється в `1`, коли в потоці стається стрибок системної часової шкали PCR або розрив лічильника Continuity Counter (наприклад, при динамічному перемиканні джерел сигналу чи врізці реклами).
   * **Біт 6 (Random Access Indicator)**: встановлюється в `1`, якщо наступний заголовок PES містить точку довільного доступу (ключовий I-кадр або IDR NAL-юніт H.264/HEVC), що дозволяє починати декодування без очікування попередніх кадрів.
   * **Біт 5 (Elementary Stream Priority Indicator)**: високий прикладний пріоритет корисних даних.
   * **Біт 4 (PCR Flag)**: сигналізує про наявність 6-байтового поля опорного годинника Program Clock Reference.
   * **Біт 3 (OPCR Flag)**: сигналізує про наявність 6-байтового поля вихідного годинника Original PCR (використовується при перекодуванні та ремультиплексуванні).
   * **Біт 2 (Splicing Point Flag)**: наявність 1-байтового поля `splice_countdown` (зворотний відлік кількості пакетів до точки безшовного монтажу).
   * **Біт 1 (Transport Private Data Flag)**: наявність блоку користувацьких даних (довжина + масив байтів).
   * **Біт 0 (Adaptation Field Extension Flag)**: наявність блоку розширення адаптаційного поля.

3. **Program Clock Reference (PCR, 6 байтів / 48 бітів)**:
   Присутній, якщо `PCR_flag == 1`. Містить відлік системного часу STC передавача:
   ```
   [ PCR_Base (33 біти) ] [ Reserved 6 бітів (0x3F) ] [ PCR_Extension (9 бітів) ]
   ```
   * `PCR_Base`: 33-бітний лічильник тактової частоти `90` кГц (від `0` до `2³³ - 1`).
   * `PCR_Extension`: 9-бітний лічильник тактової частоти `27` МГц із циклом скидання `300` (значення від `0` до `299`).
   * Повне системне значення: `PCR_Total = PCR_Base × 300 + PCR_Extension`.

4. **Байтове набивання (Stuffing Bytes, масив значень `0xFF`)**:
   Усі байти адаптаційного поля, що залишилися після прапорців та опційних полів до досягнення межі корисних даних, заповнюються значенням `0xFF`. Демультиплексор ігнорує ці байти.

### 3. Загальний синтаксис секції таблиць PSI (Program Specific Information)

Всі службові таблиці стандарту MPEG-TS (PAT, PMT, CAT, NIT, SDT) фрагментуються на одну або декілька **секцій таблиць** (англ. *Table Sections*), максимальна довжина яких становить `1024` байти (для стандарту PSI) або `4096` байтів (для приватних таблиць DVB/SI).

Якщо пакет TS містить початок нової секції (`PUSI = 1`), першим байтом корисного навантаження є **`Pointer Field`** (8 бітів). Воно вказує зміщення в байтах від кінця самого поля покажчика до першого байта секції таблиці (`table_id`). Якщо попередня секція завершилася в попередньому пакеті, `Pointer Field = 0x00`.

#### Двійкова структура стандартної довгої секції PSI:

```
Байт:   [ 0 ]        [ 1 .. 2 ]      [ 3 .. 4 ]        [ 5 ]        [ 6 ]        [ 7 ]
Поле:   [ Table ID ] [ Sec Length ]  [ Table ID Ext ]  [ Ver / CNI] [ Sec Num ]  [ Last Sec ]
```

1. **`table_id` (8 бітів)**: числовий код типу таблиці:
   * `0x00` — PAT (Program Association Table);
   * `0x01` — CAT (Conditional Access Table);
   * `0x02` — PMT (Program Map Table);
   * `0x03` — TSDT (Transport Stream Description Table);
   * `0x40` / `0x41` — DVB NIT (Network Information Table, поточна / інша мережа);
   * `0x42` / `0x46` — DVB SDT (Service Description Table, поточний / інший мультиплекс);
   * `0x4E` / `0x4F` — DVB EIT (Event Information Table, поточна подія).

2. **`section_syntax_indicator` (1 біт, старший біт 1-го байта)**: завжди `1` для стандартних довгих секцій із заголовком версії та контрольним сумою CRC-32.
3. **`section_length` (12 бітів, маска `0x0FFF`)**: довжина залишку секції в байтах, рахуючи від наступного байта до кінця секції (включаючи 4 байти CRC-32).
4. **`table_id_extension` (16 бітів)**: контекстний ідентифікатор таблиці:
   * У таблиці PAT: `transport_stream_id` (номер транспортного потоку);
   * У таблиці PMT: `program_number` (номер телевізійної програми / сервісу).
5. **`version_number` (5 бітів, біти 5..1 у 5-му байті)**: номер версії таблиці (від `0` до `31`). При будь-якій зміні складу потоків чи конфігурації генератор інкрементує версію на `1` (після `31` скидається на `0`).
6. **`current_next_indicator` (1 біт, молодший біт 5-го байта)**:
   * `1` — таблиця є активною прямо зараз (Current);
   * `0` — таблиця передається заздалегідь і набуде чинності після наступної зміни версії (Next).
7. **`section_number` (8 бітів)**: порядковий номер поточної секції (починається з `0x00`).
8. **`last_section_number` (8 бітів)**: номер останньої секції в даному наборі таблиці. Дозволяє зібрати багатосекційну таблицю з розрізнених пакетів.
9. **`CRC_32` (32 біти, останні 4 байти секції)**: контрольна сума над усіма байтами секції від `table_id` до кінця корисних даних. Використовує поліном `0x04C11DB7` з початковим значенням регістрів `0xFFFFFFFF`.

### 4. Структура таблиці зв'язку програм (PAT)

Таблиця PAT транслюється **виключно на `PID = 0x0000`** із `table_id = 0x00`. Вона містить цикл 4-байтових записів про всі програми мультиплексу:

```
Байт:   [ 0 .. 1 ]          [ 2 .. 3 ]
Поле:   [ Program Number ]  [ Reserved 3b (111) ] [ Program Map PID (13 бітів) ]
```

* **`program_number` (16 бітів)**: номер програми (телеканалу):
  * Якщо `program_number == 0x0000`, відповідний PID вказує на таблицю опису мережі **NIT (Network Information Table)**;
  * Якщо `program_number > 0x0000`, відповідний PID вказує на таблицю карти даної програми **PMT (Program Map Table)**.
* **`program_map_PID` (13 бітів)**: видобувається за формулою `((buf[2] & 0x1F) << 8) | buf[3]`.

### 5. Структура таблиці карти програми (PMT)

Таблиця PMT транслюється на персональному PID, вказаному в PAT, і має `table_id = 0x02`. Поле `table_id_extension` містить `program_number`.

#### Поля корисного навантаження PMT:

1. **`PCR_PID` (13 бітів, байти 8..9 секції)**: номер PID, у пакетах якого передаються мітки часу PCR для даної програми. Якщо програма не має власної часової бази, вказується `0x1FFF`.
2. **`program_info_length` (12 бітів, байти 10..11 секції)**: сумарна довжина глобальних дескрипторів програми (дескриптори систем умовного доступу CA, реєстрації тощо).
3. **Глобальні дескриптори програми**: масив дескрипторів формату `[Tag (1B)] [Length (1B)] [Data...]`.
4. **Цикл елементарних потоків (Elementary Streams Loop)**: послідовність описів медіапотоків, що входять до складу програми.

#### Структура запису елементарного потоку:

```
Байт 0:      [ Stream Type (8 бітів) ]
Байт 1..2:   [ Reserved 3b (111) ] [ Elementary PID (13 бітів) ]
Байт 3..4:   [ Reserved 4b (1111) ] [ ES Info Length (12 бітів) ]
Байт 5..N:   [ Дескриптори потоку (мова, параметри кодека) ]
```

#### Стандартні коди типів потоків (`Stream Type`):

| Код Stream Type | Назва стандарту | Типове застосування |
| :--- | :--- | :--- |
| `0x01` | ISO/IEC 11172-2 Video | Відеокодек MPEG-1 Video |
| `0x02` | ISO/IEC 13818-2 Video | Відеокодек MPEG-2 Video (SDTV / DVD) |
| `0x03` | ISO/IEC 11172-3 Audio | Аудіокодек MPEG-1 Audio Layer II/III (MP2/MP3) |
| `0x04` | ISO/IEC 13818-3 Audio | Багатоканальне аудіо MPEG-2 Audio |
| `0x06` | ISO/IEC 13818-1 PES Private Data | **Телеметрія дронів KLV/MISB**, субтитри DVB, AC-3 у DVB |
| `0x0F` | ISO/IEC 13818-7 Audio (AAC with ADTS) | Аудіо Advanced Audio Coding (DVB-T2, ISDB-T, OTT) |
| `0x11` | ISO/IEC 14496-3 Audio (AAC with LATM) | Стрімінгове мовлення аудіо |
| `0x1B` | ITU-T H.264 / ISO/IEC 14496-10 (AVC) | Відео високої чіткості HDTV (1080p), камери БПЛА |
| `0x24` | ITU-T H.265 / ISO/IEC 23008-2 (HEVC) | Відео 4K/UHDTV, сучасні розвідувальні дрони |
| `0x81` | ATSC A/52 AC-3 Audio | Аудіопотік Dolby Digital у стандарті ATSC (США) |
| `0x86` | SCTE-35 Cueing | Цифрові маркери точок динамічної врізки реклами |

### 6. Каталог стандартних дескрипторів MPEG-TS та DVB/SI

Дескриптори розміщуються в секціях PMT, SDT та NIT для уточнення параметрів медіапотоків. Кожен дескриптор має уніфікований формат: `[ Descriptor Tag (1B) ] [ Descriptor Length (1B) ] [ Data (Length Bytes) ]`.

* **Registration Descriptor (`Tag = 0x05`)**: реєструє 4-символьний ідентифікатор формату приватного потоку (Format Identifier). Наприклад, значення `KLVA` (`0x4B4C5641`) реєструє потік метаданих телеметрії БПЛА за стандартом MISB 0601 / STANAG 4609; значення `HDMV` — потік диска Blu-ray; `AC-3` — потік звуку Dolby.
* **CA Descriptor (`Tag = 0x09`)**: описує систему шифрування умовного доступу: містить 16-бітний `CA_system_ID` та `CA_PID`, у якому транслюються повідомлення керування правами ECM.
* **ISO 639 Language Descriptor (`Tag = 0x0A`)**: визначає 3-літерний код мови аудіодоріжки або субтитрів (наприклад, `ukr`, `eng`, `deu`) за стандартом ISO 639-2 та тип аудіо (основний діалог, коментар для людей із вадами зору тощо).
* **Maximum Bitrate Descriptor (`Tag = 0x0E`)**: декларує максимальний миттєвий бітрейт елементарного потоку в одиницях по 50 байт/с.
* **Stream Identifier Descriptor (`Tag = 0x52`, DVB)**: містить 1-байтовий тег `component_tag`, який однозначно зв'язує медіапотік із текстовим описом каналу в таблиці SDT.

### 7. Заголовок пакета PES (Packetized Elementary Stream)

Перед фрагментацією на пакети TS стиснені кадри кодеків об'єднуються в кадри PES, які несуть мітки представлення PTS та декодування DTS.

```
Байт:   [ 0 .. 2 ]         [ 3 ]         [ 4 .. 5 ]         [ 6 .. 8 ]         [ 9 .. N ]
Поле:   [ Start Code 0x000001 ] [ Stream ID ] [ PES Packet Length ] [ Опційні прапорці ] [ PTS / DTS мітки ]
Розмір:   3 байти            1 байт        2 байти            3 байти            змінний
```

#### Поля заголовка PES:

1. **Packet Start Code Prefix (24 біти)**: фіксована двійкова послідовність `0x000001` (`00000000 00000000 00000001₂`).
2. **Stream ID (8 бітів)**: тип та номер елементарного потоку:
   * `0xBD` — Private Stream 1 (аудіо AC-3, субтитри, телеметрія KLV);
   * `0xBE` — Padding Stream (заповнення буфера);
   * `0xC0..0xDF` — Аудіопотоки MPEG/AAC (номери 0..31);
   * `0xE0..0xEF` — Відеопотоки MPEG-2/H.264/HEVC (номери 0..15).
3. **PES Packet Length (16 бітів)**: довжина даних PES, що слідують за цим полем. Значення `0x0000` дозволене виключно для відеотрансляцій, де розмір відеокадру перевищує 65535 байтів (необмежена довжина).
4. **Опційний заголовок PES (3 байти)**:
   * **PTS_DTS_flags (біти 7..6 у 7-му байті)**:
     * `00₂` — мітки часу відсутні;
     * `10₂` — присутня лише 5-байтова мітка **PTS**;
     * `11₂` — присутні обидві мітки: 5 байтів **PTS** та 5 байтів **DTS** (10 байтів разом).
   * **PES_header_data_length (8 бітів у 8-му байті)**: довжина поля міток часу та дескрипторів розширення.

#### Формат 33-бітних міток часу PTS та DTS:

Мітка часу займає 5 байтів і розбивається на 3 бітові секції, переміжовані маркерними бітами `1` (для гарантії, що комбінація бітів ніколи не утворить фальшивий префікс `0x000001`):

```
Байт 0: [ 4 біти: 0010 (PTS) або 0011 (PTS при DTS) або 0001 (DTS) ] [ PTS 32..30 (3b) ] [ Маркер 1 (1b) ]
Байт 1: [ PTS 29..22 (8 бітів) ]
Байт 2: [ PTS 21..15 (7 бітів) ] [ Маркер 1 (1b) ]
Байт 3: [ PTS 14..7  (8 бітів) ]
Байт 4: [ PTS 6..0   (7 бітів) ] [ Маркер 1 (1b) ]
```

Видобування значення мітки в тактах 90 кГц:
```
PTS = ((buf[0] & 0x0E) << 29) | (buf[1] << 22) | ((buf[2] & 0xFE) << 14) | (buf[3] << 7) | ((buf[4] & 0xFE) >> 1)
```
Часова позиція в секундах: `T_sec = PTS / 90000.0`.
