# 📋 Довідник функціональних кодів і кадрів Modbus

Цей довідник містить специфікацію кадрів протоколу Modbus, детальний опис функціональних кодів (Function Codes), таблицю кодів винятків (Exception Codes) та правила формування заголовків для послідовного транспорту (Modbus RTU) і мережевого стеку (Modbus TCP).

---

## 1. Таблиця функціональних кодів (Function Codes)

Протокол Modbus визначає коди функцій у діапазоні від `1` до `127` (`0x01..0x7F`). Коди від `128` до `255` (`0x80..0xFF`) зарезервовано для відповідей-винятків (Exception Responses).

| Код (Hex) | Код (Dec) | Назва функції | Область пам'яті | Доступ | Опис |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `0x01` | 1 | Read Coils | Coils (`0x`) | Read | Читання від 1 до 2000 дискретних виходів (прапорців) |
| `0x02` | 2 | Read Discrete Inputs | Discrete Inputs (`1x`) | Read | Читання від 1 до 2000 дискретних входів |
| `0x03` | 3 | Read Holding Registers | Holding Registers (`4x`) | Read | Читання від 1 до 125 16-бітних регістрів зберігання |
| `0x04` | 4 | Read Input Registers | Input Registers (`3x`) | Read | Читання від 1 до 125 16-бітних вхідних регістрів |
| `0x05` | 5 | Write Single Coil | Coils (`0x`) | Write | Запис одного прапорця (`0xFF00` = ON, `0x0000` = OFF) |
| `0x06` | 6 | Write Single Register | Holding Registers (`4x`) | Write | Запис одного 16-бітного регістра |
| `0x0F` | 15 | Write Multiple Coils | Coils (`0x`) | Write | Запис групи прапорців (до 1968 біт) |
| `0x10` | 16 | Write Multiple Registers | Holding Registers (`4x`) | Write | Запис групи 16-бітних регістрів (до 123 регістрів) |
| `0x16` | 22 | Mask Write Register | Holding Registers (`4x`) | Write | Маскований запис регістра (AND-маска та OR-маска) |
| `0x17` | 23 | Read/Write Multiple | Holding Registers (`4x`) | R/W | Одночасне читання та запис регістрів за одну транзакцію |

---

## 2. Формати кадрів PDU для основних операцій

### Читання регістрів зберігання (Read Holding Registers, FC `0x03`)

Функція призначена для зчитування вмісту послідовного блоку 16-бітних регістрів зберігання.

**Запит від Майстра (Request PDU):**
- **Байт 0:** `0x03` (Код функції)
- **Байти 1–2:** Початкова адреса PDU (PDU Address, `0x0000..0xFFFF`, Big-Endian)
- **Байти 3–4:** Кількість регістрів `N` (`0x0001..0x007D`, до 125 регістрів, Big-Endian)

**Відповідь Слейва (Response PDU):**
- **Байт 0:** `0x03` (Код функції)
- **Байт 1:** Кількість наступних байтів даних `2 * N`
- **Байти 2..(1 + 2*N):** Значення регістрів (по 2 байти на регістр у форматі Big-Endian)

---

### Читання вхідних регістрів (Read Input Registers, FC `0x04`)

Функція зчитує вміст аналогових входів пристрою (тільки для читання). Формат повністю ідентичний коду `0x03`.

**Запит від Майстра (Request PDU):**
- **Байт 0:** `0x04` (Код функції)
- **Байти 1–2:** Початкова адреса PDU (`0x0000..0xFFFF`, Big-Endian)
- **Байти 3–4:** Кількість регістрів `N` (`1..125`, Big-Endian)

**Відповідь Слейва (Response PDU):**
- **Байт 0:** `0x04` (Код функції)
- **Байт 1:** Кількість байтів даних `2 * N`
- **Байти 2..(1 + 2*N):** Значення регістрів (Big-Endian)

---

### Запис одного регістра (Write Single Register, FC `0x06`)

Функція записує нове значення в один 16-бітний регістр зберігання.

**Запит від Майстра (Request PDU):**
- **Байт 0:** `0x06` (Код функції)
- **Байти 1–2:** Адреса регістра (PDU Address, Big-Endian)
- **Байти 3–4:** Значення регістра (16-бітне значення `0x0000..0xFFFF`, Big-Endian)

**Відповідь Слейва (Response PDU):**
- Повне ехо запиту (точна копія 5 байтів PDU запиту при успішному виконанні)

---

### Запис декількох регістрів (Write Multiple Registers, FC `0x10`)

Функція виконує атомарний запис послідовного блоку 16-бітних регістрів.

**Запит від Майстра (Request PDU):**
- **Байт 0:** `0x10` (Код функції)
- **Байти 1–2:** Початкова адреса (PDU Address, Big-Endian)
- **Байти 3–4:** Кількість регістрів `N` (`1..123`, Big-Endian)
- **Байт 5:** Кількість байтів даних `2 * N`
- **Байти 6..(5 + 2*N):** Дані для запису (Big-Endian)

**Відповідь Слейва (Response PDU):**
- **Байт 0:** `0x10` (Код функції)
- **Байти 1–2:** Початкова адреса (Big-Endian)
- **Байти 3–4:** Кількість успішно записаних регістрів `N` (Big-Endian)

---

### Маскований запис регістра (Mask Write Register, FC `0x16`)

Функція `0x16` призначена для побітового модифікування вмісту регістра зберігання без ризику перезапису інших бітів.

Формула перерахунку значення регістра:
`Result = (Current_Value AND And_Mask) OR (Or_Mask AND (NOT And_Mask))`

**Запит від Майстра (Request PDU):**
- **Байт 0:** `0x16` (Код функції)
- **Байти 1–2:** Адреса регістра (PDU Address, Big-Endian)
- **Байти 3–4:** Маска `And_Mask` (16 біт, Big-Endian)
- **Байти 5–6:** Маска `Or_Mask` (16 біт, Big-Endian)

**Відповідь Слейва (Response PDU):**
- Повне ехо кадри запиту (7 байтів PDU)

## 3. Обробка помилок та коди винятків (Exception Codes)

Якщо Слейв приймає кадр без помилок контрольної суми CRC, але не може виконати запит, він повертає **кадр винятку**.

Формат PDU винятку:
- **Байт 0:** `Код_Функції | 0x80` (встановлюється старший біт `0x80`, наприклад `0x03` → `0x83`)
- **Байт 1:** `Код_Винятку` (1 байт)

### Таблиця кодів винятків Modbus

| Код (Hex) | Назва винятку | Опис причини |
| :--- | :--- | :--- |
| `0x01` | Illegal Function | Запитуваний код функції не підтримується даним пристроєм. |
| `0x02` | Illegal Data Address | Адреса регістра або їхня комбінація виходить за межі доступної пам'яті пристрою. |
| `0x03` | Illegal Data Value | Значення у полях запиту перевищує допустимі межі (наприклад, `N = 0` або `N > 125`). |
| `0x04` | Server Device Failure | Невідновлювана апаратна або програмна помилка пристрою під час виконання операції. |
| `0x05` | Acknowledge | Пристрій прийняв запит, але операція вимагає тривалого часу (запобігання таймауту). |
| `0x06` | Server Device Busy | Пристрій зайнятий виконанням тривалої команди; Майстер має повторити запит пізніше. |
| `0x08` | Memory Parity Error | Помилка парності при зчитуванні з енергонезалежної пам'яті (EEPROM/Flash). |
| `0x0A` | Gateway Path Unavailable | Мережевий шлюз не мостовує запит до веденої шини (відсутня маршрутизація). |
| `0x0B` | Gateway Target Failed | Шлюз відправив запит на ведену шину, але не отримав відповіді від цільового пристрою. |

## 4. Транспортні обгортки ADU (RTU vs TCP)

### Modbus RTU ADU (Послідовний транспорт)

Формат кадру на лініях RS-485/RS-232:

`[Slave Address (1 B)] + [PDU (1..253 B)] + [CRC-16 (2 B, LSB first)]`

- **Slave Address:** `0` — широкомовний запит (Broadcast, без відповіді); `1..247` — індивідуальні адреси ведених пристроїв; `248..255` — зарезервовані адреси.
- **CRC-16:** Обчислюється за поліномом `0xA001` від байта адреси до останнього байта PDU включно. Передається молодшим байтом уперед (Little-Endian).

---

### Modbus TCP MBAP Header (Мережевий транспорт)

У мережах Ethernet поверх TCP (порт `502`) PDU передує **7-байтний заголовок MBAP** (Modbus Application Protocol Header):

| Байт | Поле | Розмір | Опис |
| :--- | :--- | :--- | :--- |
| 0–1 | Transaction Identifier | 2 байти | Ідентифікатор транзакції (копіюється у відповідь для зв'язування запиту) |
| 2–3 | Protocol Identifier | 2 байти | Завжди `0x0000` для протоколу Modbus |
| 4–5 | Length | 2 байти | Кількість наступних байтів у кадрі (включаючи `Unit ID` та `PDU`) |
| 6 | Unit Identifier | 1 байт | Адреса Слейва (використовується при шлюзуванні TCP → RTU; за замовчуванням `0xFF` або `0x01`) |

## 5. Правила адресації: Modicon notation проти PDU offset

В інженерній документації обладнання використовують традиційну нотацію Modicon (1-based з префіксом таблиці), тоді як у байтах протоколу передається безпосередній зсув (0-based 16-бітне число):

- **Holding Register `40001`** → Таблиця Holding (`4x`), PDU адреса = `0x0000` (`0`)
- **Holding Register `40108`** → Таблиця Holding (`4x`), PDU адреса = `0x006B` (`107`)
- **Input Register `30005`** → Таблиця Input (`3x`), PDU адреса = `0x0004` (`4`)
- **Discrete Input `10017`** → Таблиця Discrete (`1x`), PDU адреса = `0x0010` (`16`)
- **Coil `00001`** → Таблиця Coils (`0x`), PDU адреса = `0x0000` (`0`)
