# 📋 Формати речень NMEA 0183: поля, ідентифікатори та коди станів

Довідкова специфікація визначає повну граматику синтаксису, словник ідентифікаторів джерел даних (Talker ID), посимвольне розташування полів у навігаційних реченнях GGA, RMC, GSA, GSV, VTG, ZDA, GLL, класифікацію пропрієтарних речень вендорів, а також числові коди режимів фіксу та алгоритм верифікації контрольної суми NMEA 0183.

### Загальний синтаксис кадру NMEA 0183

Будь-яке стандартне повідомлення NMEA 0183 передається як друкований рядок ASCII в однобайтовому кодуванні (8 бітів даних, без біта парності, 1 стоп-біт: 8-N-1) з фіксованими правилами обрамлення:

```
$<TalkerID><SentenceFormatter>,<Поле 1>,<Поле 2>,...,<Поле N>*<Checksum><CR><LF>
```

Кожне речення формується відповідно до суворих правил, які забезпечують потокове розпізнавання повідомлень без необхідності знати загальну довжину кадру наперед.

| Елемент синтаксису | Довжина (байти) | Опис та правила валідації |
| :--- | :--- | :--- |
| **Префікс початку** | 1 байт | Символ `$` (`0x24`) для стандартних речень або `!` (`0x21`) для інкапсульованих (AIS). |
| **Talker ID** | 2 байти | Дволітерний ASCII-код джерела даних (супутникове сузір'я, датчик, автопілот). |
| **Sentence Formatter** | 3 байти | Трилітерний ASCII-код типу повідомлення (`GGA`, `RMC`, `GSA`, `GSV`, `VTG` тощо). |
| **Роздільник полів** | 1 байт | Кома `,` (`0x2C`). Якщо значення параметра відсутнє, передаються дві коми поспіль `,,`. |
| **Поля даних** | Змінна | Числа з рухомою комою, цілі числа, літерні індикатори або рядки ASCII. |
| **Роздільник суми** | 1 байт | Символ зірочки `*` (`0x2A`), що позначає кінець полів даних. |
| **Контрольна сума** | 2 байти | 8-бітна сума XOR усіх символів між `$` та `*`, представлена двома шістнадцятковими цифрами `00`–`FF`. |
| **Термінатор рядка** | 2 байти | Послідовність `\r\n`: символ повернення каретки `0x0D` (`<CR>`) та переведення рядка `0x0A` (`<LF>`). |

#### Граничні обмеження стандарту NMEA 0183

1. **Максимальний розмір кадру**: загальна довжина повного речення від початкового символу `$` (або `!`) до кінцевого байта `<LF>` (`0x0A`) включно не повинна перевищувати **82 символи**. Це обмеження було запроваджено в 1983 році для гарантії того, що 8-бітні мікроконтролери з малою ємністю ОЗП (наприклад, Intel 8051 або Motorola 68HC11) зможуть виділити під рядковий буфер фіксований статичний масив розміром 84 байти без ризику переповнення стека чи динамічної пам'яті.
2. **Обробка пропущених і порожніх полів**: якщо приймач або датчик не зміг виміряти певну фізичну величину (наприклад, відсутній сигнал диференційної поправки DGPS або не під'єднано магнітний компас), відповідне поле залишається абсолютно порожнім. У потоці символів це відображається двома комами поспіль: `,,`. Парсер зобов'язаний коректно обробляти такі порожні значення, не зсуваючи індекси наступних полів.
3. **Регістр символів**: усі ідентифікатори Talker ID, Sentence Formatter, літерні коди півкуль (`N`, `S`, `E`, `W`), індикатори режимів (`A`, `V`, `D`, `E`, `M`, `S`, `N`) та шістнадцяткові цифри контрольної суми формуються **виключно у верхньому регістрі** (*Uppercase*).

### Словник ідентифікаторів джерел (Talker ID)

Префікс Talker ID визначає, яка саме апаратна підсистема або навігаційне сузір'я сформувало повідомлення:

| Код Talker | Навігаційна система / Тип пристрою | Примітки |
| :--- | :--- | :--- |
| `GP` | **GPS** (Global Positioning System, США) | Найпоширеніший префікс для односистемних приймачів. |
| `GL` | **ГЛОНАСС** (GLONASS, РФ) | Позиціювання суто за супутниками ГЛОНАСС. |
| `GA` | **Galileo** (Європейський Союз) | Позиціювання за європейським цивільним сузір'ям. |
| `GB` / `BD` | **BeiDou** (КНР) | `BD` — застарілий код BeiDou-2; `GB` — офіційний код стандарту NMEA 4.10+. |
| `QZ` | **QZSS** (Quasi-Zenith Satellite System, Японія) | Регіональна квазізенітна система підсилення. |
| `GN` | **Multi-GNSS (Комбінований розв'язок)** | Позиція обчислена за сумісним використанням кількох сузір'їв. |
| `HC` | **Heading Compass** | Магнітний або супутниковий компас (курс судна). |
| `II` | **Integrated Instrumentation** | Інтегрована бортова навігаційна система. |
| `SD` | **Depth Sounder** | Ехолот (вимірювання глибини під кілем). |
| `VW` | **Speed Log (Mechanical / Water)** | Механічний відносний лаг (швидкість відносно води). |
| `AI` | **AIS (Automatic Identification System)** | Транспондер автоматичної ідентифікації суден. |

### Детальна специфікація навігаційних речень

#### 1. Речення $xxGGA — Дані фіксу глобального позиціювання

Речення GGA транслює час, географічні координати, рівень достовірності вимірювань, число задіяних супутників, горизонтальний фактор точності та висоту над геоїдом і еліпсоїдом.

```
$GNGGA,123519.00,4807.0382,N,01131.0000,E,1,08,0.9,545.4,M,46.9,M,1.2,0042*75
```

Кожне поле речення має суворо фіксоване семантичне призначення:

- **Поле 0 (`$GNGGA`)**: ідентифікатор кадру. Префікс `GN` вказує на комбінований розв'язок декількох супутникових сузір'їв, а `GGA` — на формат Global Positioning System Fix Data.
- **Поле 1 (`123519.00`)**: час за всесвітнім координованим часом (UTC) у форматі `hhmmss.sss`. Тут `12` годин, `35` хвилин, `19.00` секунд. Дробова частина секунд може містити від двох до трьох знаків залежно від частоти видачі навігаційних даних приймачем.
- **Поле 2 (`4807.0382`)**: географічна широта у форматі градусів та десяткових часток мінути `ddmm.mmmm`. Перші дві цифри `48` відповідають градусам, а наступні `07.0382` — мінутам дуги.
- **Поле 3 (`N`)**: покажчик півкулі широти. Символ `N` позначає північну широту (*North*), а символ `S` — південну широту (*South*).
- **Поле 4 (`01131.0000`)**: географічна довгота у форматі `dddmm.mmmm`. Перші три цифри `011` відповідають цілим градусам (довгота змінюється від 000° до 180°), а цифри `31.0000` — мінутам дуги. Провідний нуль у розряді сотень градусів є обов'язковим.
- **Поле 5 (`E`)**: покажчик півкулі довготи. Символ `E` позначає східну довготу (*East*), символ `W` — західну довготу (*West*).
- **Поле 6 (`1`)**: числовий код якості фіксу позиціювання. Це ключовий статусний прапорець для польотних контролерів дронів та автопілотів.
- **Поле 7 (`08`)**: кількість космічних апаратів, які беруть участь в обчисленні поточної навігаційної оцінки (від 00 до 24 і більше).
- **Поле 8 (`0.9`)**: горизонтальний фактор зниження точності HDOP (*Horizontal Dilution of Precision*). Що менше це значення, то компактніший просторовий еліпс похибки.
- **Поле 9 (`545.4`)**: ортометрична висота антени приймача над середнім рівнем моря MSL (*Mean Sea Level*), тобто висота над геоїдом.
- **Поле 10 (`M`)**: одиниця вимірювання висоти над рівнем моря — метри (*Meters*).
- **Поле 11 (`46.9`)**: геоїдальна розбіжність (*Geoidal Separation*), тобто висота поверхні геоїда над гладким відліковим еліпсоїдом WGS-84 у точці вимірювання.
- **Поле 12 (`M`)**: одиниця вимірювання геоїдального перевищення — метри (*Meters*).
- **Поле 13 (`1.2`)**: вік диференційних поправок у секундах з моменту останнього отримання коригувального пакету RTCM/RTK. Для звичайного автономного GPS це поле лишається порожнім `,,`.
- **Поле 14 (`0042`)**: ідентифікатор базової опорної станції DGPS (від 0000 до 1023).
- **Поле 15 (`*75`)**: роздільник `*` та двозначна шістнадцяткова контрольна сума XOR.

| Код якості | Назва режиму | Фізичний зміст та типова точність |
| :---: | :--- | :--- |
| `0` | **Недійсний / Без фіксу** | Супутників недостатньо для розв'язку навігаційної задачі (похибка не визначена). |
| `1` | **Автономний GPS (SPS)** | Стандартний цивільний режим позиціювання за кодом C/A (точність 2.0–5.0 м). |
| `2` | **Диференційний GPS (DGPS)** | Прийом кодових поправок від наземних станцій або супутників SBAS (точність 0.5–1.5 м). |
| `3` | **Військовий PPS** | Точне позиціювання за P(Y)-кодом для авторизованих користувачів. |
| `4` | **RTK Fixed (Фазовий фікс)** | Сантиметрове позиціювання з розв'язаною фазовою неоднозначністю цілих хвиль (точність 1–2 см). |
| `5` | **RTK Float (Плаваючий RTK)** | Фазовий розв'язок з плаваючою оцінкою неоднозначності (точність 10–50 см). |
| `6` | **Dead Reckoning (Інерційний)** | Оцінка координат за датчиками руху (IMU, одометр) без супутникового сигналу. |
| `7` | **Ручний режим (Manual)** | Координати примусово задані оператором у конфігурації. |
| `8` | **Симуляція (Simulation)** | Тестовий вивід сигналів від апаратного імітатора GNSS. |

#### 2. Речення $xxRMC — Рекомендований навігаційний мінімум

Речення RMC є найбільш універсальним навігаційним повідомленням: воно містить час, дату, координати, швидкість руху та істинний курс судна.

```
$GNRMC,123519.00,A,4807.0382,N,01131.0000,E,022.4,084.4,230324,003.1,W,A,S*1D
```

- **Поле 1 (`123519.00`)**: час UTC у форматі `hhmmss.sss`.
- **Поле 2 (`A`)**: загальний статус валідності навігаційних даних. Значення `A` (*Active*) вказує на коректний фікс і достовірні координати; значення `V` (*Void*) сигналізує навігаційному комп'ютеру, що прилад перебуває в стані пошуку супутників і координати не можуть використовуватися для автопілотування.
- **Поле 3–4 (`4807.0382,N`)**: географічна широта та півкуля.
- **Поле 5–6 (`01131.0000,E`)**: географічна довгота та півкуля.
- **Поле 7 (`022.4`)**: шляхова швидкість відносно ґрунту SOG (*Speed Over Ground*), виміряна в **морських вузлах** (1 міжнародний вузол дорівнює 1.852 км/год або приблизно 0.5144 м/с).
- **Поле 8 (`084.4`)**: істинний шляховий кут руху COG (*Course Over Ground*) у градусах відносно географічної півночі (від 000.0° до 359.9°).
- **Поле 9 (`230324`)**: поточна календарна дата за всесвітнім часом UTC у форматі `ddmmyy` (23 березня 2024 року).
- **Поле 10–11 (`003.1,W`)**: величина та напрямок магнітного схилення (*Magnetic Variation*) у градусах. Покажчик `W` позначає західне схилення, `E` — східне схилення.
- **Поле 12 (`A`)**: індикатор режиму позиціювання FAA (введений у версії NMEA 2.3).
- **Поле 13 (`S`)**: статус навігаційної безпеки (введений у версії NMEA 4.10+): `S` — безпечний фікс (*Safe*), `C` — застереження (*Caution*), `U` — небезпечний (*Unsafe*), `V` — недійсний (*Not Valid*).

| Код FAA | Режим позиціювання | Опис |
| :---: | :--- | :--- |
| `A` | **Autonomous** | Автономне одноточкове визначення координат без зовнішніх поправок. |
| `D` | **Differential** | Диференційний режим з використанням базових станцій або супутників SBAS. |
| `E` | **Estimated (Dead Reckoning)** | Обчислення позиції за швидкістю, курсом та часом за відсутності супутників. |
| `M` | **Manual** | Ручне введення координат у терміналі. |
| `S` | **Simulator** | Робота в режимі апаратного тестування та емуляції. |
| `N` | **Data Not Valid** | Відсутність фіксу або недостовірні спостереження. |

#### 3. Речення $xxGSA — DOP-фактори та активні супутники

Речення GSA транслює геометричні фактори зниження точності (DOP) та перелік ідентифікаторів PRN супутників, які безпосередньо беруть участь у розрахунку координат.

```
$GNGSA,A,3,04,05,09,12,24,28,32,,,,,,1.8,1.0,1.5,1*1E
```

- **Поле 1 (`A`)**: режим вибору розмірності розв'язку. `M` позначає примусовий ручний вибір режиму 2D або 3D; `A` вказує на автоматичний перехід між 2D (при 3 супутниках) та 3D (при 4 і більше супутниках).
- **Поле 2 (`3`)**: режим фіксу. Значення `1` означає відсутність фіксу; `2` — 2D-фікс (висота фіксована або не обчислюється); `3` — повноцінний 3D-фікс (обчислюються широта, довгота та висота).
- **Поля 3–14**: рівно 12 слотів для запису номерів PRN супутників, які беруть участь у розрахунку. Якщо в розв'язку задіяно 7 супутників, останні 5 слотів залишаються порожніми `,,,,,`.
- **Поле 15 (`1.8`)**: просторовий фактор зниження точності PDOP (*Position Dilution of Precision*).
- **Поле 16 (`1.0`)**: горизонтальний фактор зниження точності HDOP (*Horizontal Dilution of Precision*).
- **Поле 17 (`1.5`)**: вертикальний фактор зниження точності VDOP (*Vertical Dilution of Precision*).
- **Поле 18 (`1`)**: ідентифікатор супутникової системи GNSS System ID (NMEA 4.10+): `1` — GPS, `2` — GLONASS, `3` — Galileo, `4` — BeiDou, `5` — QZSS, `6` — NavIC.

#### 4. Речення $xxGSV — Параметри супутників у зоні видимості

Речення GSV передає детальну інформацію про кожен видимий супутник над горизонтом: кут елевації (піднесення), азимут та рівень сигналу. Оскільки в одне речення вміщуються дані максимум про 4 супутники, повідомлення розбивається на групу з декількох послідовних речень.

```
$GPGSV,3,1,11,03,03,111,00,04,15,270,36,06,01,010,00,13,06,292,38,1*74
```

- **Поле 1 (`3`)**: загальна кількість речень GSV у поточному багатопакетному блоці (від 1 до 9).
- **Поле 2 (`1`)**: порядковий номер поточного речення всередині групи (від 1 до 9).
- **Поле 3 (`11`)**: загальна кількість супутників даного сузір'я, виявлених приймачем у зоні прямої видимості над радіогоризонтом.
- **Поля 4–7 (Супутник 1)**: четвірка параметрів:
  1. `03`: системний номер супутника (PRN для GPS або номер орбітального слота для ГЛОНАСС).
  2. `03`: кут елевації (піднесення над лінією горизонту) у градусах від 00° до 90°.
  3. `111`: географічний азимут супутника у градусах від 000° до 359° (відлік за годинниковою стрілкою від півночі).
  4. `00`: відношення потужності несучої до спектральної густини шуму C/N0 (*Carrier-to-Noise density ratio*), виражене в dB-Hz (від 00 до 99). Якщо супутник супроводжується за кодом, значення зазвичай становить 35–50 dB-Hz; якщо сигнал втрачено або шукається, поле лишається порожнім або містить `00`.
- **Поля 8–11, 12–15, 16–19**: аналогічні блоки для другого, третього та четвертого супутників відповідно.
- **Поле 20 (`1`)**: ідентифікатор сигналу Signal ID стандарту NMEA 4.10+ (`1` для GPS L1 C/A, `2` для L2 CL, `5` для L5).

#### 5. Речення $xxVTG — Вектор швидкості та курсу

Речення VTG дублює вектор руху судна в різних одиницях вимірювання (вузли та кілометри за годину) відносно істинного та магнітного меридіанів.

```
$GNVTG,084.4,T,087.5,M,022.4,N,041.5,K,A*23
```

- **Поля 1–2 (`084.4,T`)**: істинний курс руху у градусах (`T` = True).
- **Поля 3–4 (`087.5,M`)**: курс відносно магнітної півночі у градусах (`M` = Magnetic).
- **Поля 5–6 (`022.4,N`)**: швидкість руху в морських вузлах (`N` = Knots).
- **Поля 7–8 (`041.5,K`)**: швидкість руху в кілометрах на годину (`K` = Kilometers per hour).
- **Поле 9 (`A`)**: індикатор режиму позиціювання FAA (`A`, `D`, `E`, `N`).

---

#### 6. Речення $xxZDA — Точний астрономічний час і дата UTC

Речення ZDA транслює повну часову мітку з урахуванням чотиризначного року та зміщення місцевого часового поясу.

```
$GNZDA,123519.00,23,03,2024,02,00*7D
```

- **Поле 1 (`123519.00`)**: час UTC (`hhmmss.ss`).
- **Поле 2 (`23`)**: день місяця (від 01 до 31).
- **Поле 3 (`03`)**: місяць року (від 01 до 12).
- **Поле 4 (`2024`)**: чотиризначний календарний рік за григоріанським календарем.
- **Поле 5 (`02`)**: зміщення місцевого часового поясу в годинах відносно UTC (від 00 до ±13).
- **Поле 6 (`00`)**: зміщення часового поясу у хвилинах (від 00 до 59).

---

#### 7. Речення $xxGLL — Географічна позиція (широта та довгота)

Речення GLL є компактним форматом передачі координат та часу для приладів з обмеженою швидкістю каналу зв'язку.

```
$GNGLL,4807.0382,N,01131.0000,E,123519.00,A,A*7B
```

- **Поля 1–2 (`4807.0382,N`)**: широта та півкуля.
- **Поля 3–4 (`01131.0000,E`)**: довгота та півкуля.
- **Поле 5 (`123519.00`)**: час взяття відліку за UTC (`hhmmss.ss`).
- **Поле 6 (`A`)**: статус даних (`A` — дійсні, `V` — недійсні).
- **Поле 7 (`A`)**: індикатор режиму FAA (`A`, `D`, `E`, `N`).

### Пропрієтарні речення виробників (Префікс $P)

Стандарт NMEA 0183 дозволяє виробникам обладнання розширювати базовий набір повідомлень власними службовими та конфігураційними реченнями. Будь-яке пропрієтарне речення починається з префікса `$P`, за яким слідує трилітерний код компанії:

- **`$PUBX,...`**: пропрієтарні речення компанії **u-blox** (наприклад, `$PUBX,00` — розширений навігаційний статус з оцінкою дисперсії похибок координат 3D-Fix, `$PUBX,40` — налаштування частоти виводу речень NMEA).
- **`$PMTK,...`**: керуючі речення чипсетів **MediaTek / MTK** (налаштування швидкості порту baud rate, наприклад `$PMTK251,115200*1F`, або конфігурація частоти видачі пакетів від 1 до 10 Гц, наприклад `$PMTK220,100*2F` для 10 Гц).
- **`$PGRME,...`**: речення компанії **Garmin** для передачі оцінки просторової похибки позиціювання HPE (*Horizontal Position Error*) та VPE (*Vertical Position Error*) у метрах.
- **`$PASHR,...`**: високоточні геодезичні речення компанії **Ashtech** (дані про крен, диферент і курс двоантенних інтерферометричних RTK-систем).

---

### Інкапсульовані речення (Префікс !)

Для передачі нетекстових двійкових структур (наприклад, повідомлень автоматичної ідентифікаційної системи AIS або диференційних поправок RTCM) стандарт NMEA 0183 передбачає спеціальні інкапсульовані речення, що починаються із символу оклику `!`:

```
!AIVDM,1,1,,B,13aEO:0P000Oh08E`R>00?vN0000,0*3B
```

Двійковий потік корисного навантаження розбивається на 6-бітні блоки. До кожного 6-бітного значення додається зміщення `0x30` (число 48); якщо отримане значення перевищує `0x57` (число 87), до нього додається додаткове зміщення `0x08`, щоб уникнути колізій із керуючими символами ASCII (комами, зірочками та символами нового рядка). Такий формат називається 6-бітним броньованим ASCII (*6-bit Armored ASCII*).

---

### Алгоритм обчислення та верифікації контрольної суми

Контрольна сума NMEA 0183 обчислюється як побайтове порозрядне виключне АБО (побітовий оператор XOR, `⊕`) для всіх друкованих символів ASCII, розташованих **суворо між символом `$` (або `!`) та символом `*`**. Самі символи `$`, `*`, а також кінцеві `<CR><LF>` до розрахунку суми не входять.

```
Сума_XOR = Символ[1] ⊕ Символ[2] ⊕ ... ⊕ Символ[k]
```

Отримане 8-бітне значення форматується у вигляді двох шістнадцяткових символів у верхньому регістрі (`0`–`9`, `A`–`F`). Якщо розрахована сума становить менше `0x10`, обов'язково додається провідний нуль (наприклад, сума `0x05` записується як `*05`, а не `*5`).
