# 🧮 ZigZag кодування для чисел зі знаком

У комп'ютерних системах цілі числа зі знаком майже повсюдно зберігаються у додатковому коді (two's complement). У цій системі числення старший розряд машинного слова відіграє роль знакового біта. Для 32-бітного регістра число `0` записується як `0x00000000`, додатне число `1` — як `0x00000001`, а від'ємне число `−1` — як бітова послідовність з усіх одиниць `0xFFFFFFFF`. Для 64-бітних регістрів число `−1` набуває вигляду `0xFFFFFFFFFFFFFFFF`.

Коли таке від'ємне число потрапляє на вхід алгоритму стиснення цілих чисел Base-128 Varint, виникає фундаментальна невідповідність між математичною величиною числа та його двійковим представленням. Алгоритм Varint розбиває вхідне значення на 7-бітні блоки й зупиняє пакування лише тоді, коли всі старші біти, що залишилися, дорівнюють нулю. Оскільки в числі `−1` усі біти встановлені в `1`, пакувальник змушений виписати максимальну кількість байтів: 5 байтів для 32-бітного поля та 10 байтів для 64-бітного поля.

У результаті мале за абсолютною величиною значення `−1` (наприклад, похибка давача або від'ємна температура) створює на дроті максимальне навантаження у 10 байтів, тоді як додатне число `1` займає рівно один байт `0x01`. Якщо канал зв'язку передає тисячі знакових відліків на секунду, надлишкове розширення від'ємних чисел збільшує споживання трафіку у кілька разів.

ZigZag кодування розв'язує цю асиметрію: воно задає взаємно однозначне відображення (бієкцію) множини цілих чисел зі знаком на множину невід'ємних цілих чисел так, щоб числа з малим абсолютним значенням отримували малі числові коди незалежно від знака.

```
n:     0   -1    1   -2    2   -3    3   -4    4
       ↓    ↓    ↓    ↓    ↓    ↓    ↓    ↓    ↓
z:     0    1    2    3    4    5    6    7    8
```

## Математичне означення бієкції

Для цілого числа `n`, що належить множині цілих чисел, відображення `f(n)` на множину невід'ємних цілих чисел визначається кусково-лінійною функцією:

```
f(n) = 2 * n         [для n ≥ 0: парні невід'ємні числа]
f(n) = 2 * |n| - 1   [для n < 0: непарні додатні числа]
```

Обернене відображення `g(z)`, де `z` — невід'ємне ціле число, відновлює початкове знакове число за молодшим бітом парності:

```
g(z) = z / 2         [якщо z парне, тобто z mod 2 = 0]
g(z) = -(z + 1) / 2  [якщо z непарне, тобто z mod 2 = 1]
```

Ця функція гарантує, що для будь-якого цілого `n` довжина двійкового запису результату `f(n)` не перевищує подвоєної кількості значущих бітів модуля числа. Будь-яке знакове число в діапазоні від `−64` до `63` після ZigZag кодування гарантовано вкладається в один 7-бітний блок і кодується рівно одним байтом Varint. Числа від `−8192` до `8191` вкладаються у два байти, а від `−1048576` до `1048575` — у три байти.

## Формальне доведення взаємної однозначності (бієктивності)

Щоб довести, що перетворення ZigZag є коректним кодуванням без втрати інформації, необхідно довести дві властивості: ін'єктивність (різні вхідні числа дають різні коди) та сюр'єктивність (будь-який беззнаковий код відповідає дійсному цілому числу).

### 1. Доведення ін'єктивності

Нехай маємо два цілих числа `a` та `b`, для яких `f(a) = f(b)`. Розглянемо три можливі випадки:

1. **Обидва числа невід'ємні (`a ≥ 0`, `b ≥ 0`)**:
   За означенням функції:
   `f(a) = 2 * a`
   `f(b) = 2 * b`
   Оскільки `2 * a = 2 * b`, діленням на 2 отримуємо `a = b`.

2. **Обидва числа від'ємні (`a < 0`, `b < 0`)**:
   За означенням функції:
   `f(a) = -2 * a - 1`
   `f(b) = -2 * b - 1`
   Прирівнюючи вирази:
   `-2 * a - 1 = -2 * b - 1`
   `-2 * a = -2 * b`
   Діленням на -2 отримуємо `a = b`.

3. **Числа мають різні знаки (`a ≥ 0`, `b < 0`)**:
   За означенням `f(a) = 2 * a` є парним числом, оскільки ділиться на 2 без залишку.
   Значення `f(b) = -2 * b - 1 = 2 * (-b - 1) + 1` є непарним числом.
   Оскільки парне число ніколи не дорівнює непарному, рівність `f(a) = f(b)` неможлива.

Отже, рівність `f(a) = f(b)` виконується тоді й лише тоді, коли `a = b`. Ін'єктивність доведено.

### 2. Доведення сюр'єктивності

Нехай задано довільне невід'ємне ціле число `z ≥ 0`.
Якщо `z` є парним числом, існує ціле `k ≥ 0` таке, що `z = 2 * k`. Обираючи `n = k ≥ 0`, маємо `f(n) = 2 * k = z`.
Якщо `z` є непарним числом, існує ціле `k ≥ 0` таке, що `z = 2 * k + 1`. Обираючи `n = -(k + 1) < 0`, маємо:
`f(n) = 2 * |-(k + 1)| - 1 = 2 * (k + 1) - 1 = 2 * k + 1 = z`.

Отже, для будь-якого невід'ємного цілого числа `z` існує єдиний прообраз `n`, що доводить сюр'єктивність і бієктивність відображення.

## Побітова реалізація для регістрів фіксованої розрядності

На сучасних мікропроцесорах виконання умовних переходів `if (n < 0)` призводить до скидання конвеєра інструкцій (*pipeline flush*) у разі помилки передбачення переходу (*branch misprediction*). У системі додаткового коду знаковий арифметичний зсув праворуч дозволяє обчислити функцію `f(n)` за дві апаратні інструкції без жодного умовного переходу.

Нехай `w` — розрядність регістра процесора (32 для `sint32` або 64 для `sint64`). Арифметичний зсув `n >> (w - 1)` розмножує знаковий біт по всій розрядній сітці машинного слова:

```
n >> 31 = 0x00000000 =  0   [якщо n ≥ 0: старший біт дорівнював 0]
n >> 31 = 0xFFFFFFFF = -1   [якщо n < 0: старший біт дорівнював 1]
```

Загальна формула прямого перетворення через побітове виключне АБО (XOR):

```
z = (n << 1) ^ (n >> (w - 1))
```

Розгляньмо покрокове обчислення для додатного числа `n = 2` у 32-бітному регістрі:

```
n            = 0x00000002   [десяткове число 2]
n << 1       = 0x00000004   [логічний зсув ліворуч на 1 біт]
n >> 31      = 0x00000000   [арифметичний зсув знака]
z            = 0x00000004   [0x00000004 XOR 0x00000000]
             = 4            [десятковий результат перетворення]
```

Розгляньмо покрокове обчислення для від'ємного числа `n = -2` у 32-бітному регістрі:

```
n            = 0xFFFFFFFE   [десяткове число -2 у додатковому коді]
n << 1       = 0xFFFFFFFC   [зсув ліворуч вивільняє молодший нульовий біт]
n >> 31      = 0xFFFFFFFF   [знакова маска з усіх одиниць]
z            = 0x00000003   [0xFFFFFFFC XOR 0xFFFFFFFF, побітова інверсія]
             = 3            [десятковий результат перетворення]
```

Операція `(n << 1)` множить модуль числа на 2 та вивільняє молодший нульовий біт. Операція `XOR` із маскою `0xFFFFFFFF` інвертує всі розряди отриманого результату, що відповідає операції взяття побітового доповнення `~x`. За фундаментальною властивістю додаткового коду для будь-якого цілого `x`:

```
~x           = -x - 1       [побітове доповнення у додатковому коді]
(n << 1) ^ -1 = ~(2 * n)    [підстановка маски 0xFFFFFFFF]
             = -(2 * n) - 1 [застосування тотожності додаткового коду]
             = 2 * |n| - 1  [оскільки для від'ємного n маємо -n = |n|]
```

Алгебраїчна функція та побітовий вираз дають математично тотожний результат для всіх значень діапазону.

## Алгоритм відновлення числа (розкодування)

Для відновлення початкового знакового значення `n` із закодованого беззнакового цілого `z` використовується молодший біт парності `(z & 1)`:

```
n = (z >> 1) ^ -(z & 1)
```

Оператор `(z >> 1)` виконує логічний зсув беззнакового числа праворуч на одну позицію. Вираз `-(z & 1)` формує знакову маску завдяки операції унарного мінуса у додатковому коді:

```
-(0 & 1) = -0 =  0x00000000   [для парного z: маска з нулів]
-(1 & 1) = -1 =  0xFFFFFFFF   [для непарного z: маска з одиниць]
```

Розгляньмо розкодування непарного значення `z = 3` (початкове `n = -2`):

```
z            = 0x00000003   [закодоване беззнакове значення 3]
z >> 1       = 0x00000001   [логічний зсув праворуч]
z & 1        = 0x00000001   [молодший біт парності дорівнює 1]
-(z & 1)     = 0xFFFFFFFF   [унарний мінус створює маску -1]
n            = 0xFFFFFFFE   [0x00000001 XOR 0xFFFFFFFF]
             = -2           [відновлене знакове ціле число]
```

Розгляньмо розкодування парного значення `z = 4` (початкове `n = 2`):

```
z            = 0x00000004   [закодоване беззнакове значення 4]
z >> 1       = 0x00000002   [логічний зсув праворуч]
z & 1        = 0x00000000   [молодший біт парності дорівнює 0]
-(z & 1)     = 0x00000000   [маска з нулів]
n            = 0x00000002   [0x00000002 XOR 0x00000000]
             = 2            [відновлене знакове ціле число]
```

## Граничні випадки та поведінка на межах типів даних

Діапазон представлення 32-бітного знакового цілого типу `int32_t` становить від `−2147483648` (`-2^31`) до `2147483647` (`2^31 - 1`).

Для додатного максимуму `n = 2147483647` (`0x7FFFFFFF`):

```
n << 1       = 0xFFFFFFFE   [зсув ліворуч на 1 біт]
n >> 31      = 0x00000000   [маска знака]
z            = 0xFFFFFFFE   [4294967294 у десятковому записі]
```

Для від'ємного мінімуму `n = -2147483648` (`0x80000000`):

```
n << 1       = 0x00000000   [втрата біта переповнення у беззнаковому зсуві]
n >> 31      = 0xFFFFFFFF   [маска знака]
z            = 0xFFFFFFFF   [4294967295 у десятковому записі]
```

Обидва граничні значення строго вкладаються в діапазон беззнакового 32-бітного типу `uint32_t` (від `0` до `4294967295`) і без спотворень відновлюються зворотним перетворенням.

## Апаратна трансляція та процесорні інструкції

На мікроконтролерах архітектури ARM Cortex-M (набір інструкцій Thumb-2) кодування ZigZag компілюється в три базові інструкції:

```asm
ASRS  r1, r0, #31    ; r1 = n >> 31 (знакова маска в регістрі r1)
LSLS  r0, r0, #1     ; r0 = n << 1 (зсув вихідного числа ліворуч)
EORS  r0, r0, r1     ; r0 = r0 ^ r1 (підсумковий результат z у регістрі r0)
```

На архітектурі RISC-V (набір інструкцій RV32I) послідовність залишається триінструкційною:

```asm
srai  t0, a0, 31     ; t0 = a0 >> 31 (арифметичний зсув)
slli  a0, a0, 1      ; a0 = a0 << 1
xor   a0, a0, t0     ; a0 = a0 ^ t0
```

На процесорах x86-64 операція зворотного розкодування транслюється в інструкції зсуву та умовного віднімання:

```asm
mov   eax, edi
sar   eax, 31        ; розмноження знакового біта
xor   eax, edi       ; побітове виключне АБО
shr   edi, 1         ; зсув праворуч
sub   edi, eax       ; відновлення вихідного числа
```

Кожна з цих послідовностей виконується за 2–3 такти процесора, не потребує доступу до оперативної пам'яті й не створює точок розгалуження конвеєра.

## Вплив на ентропію даних та стиснення потоку

Коли послідовність знакових відліків (наприклад, дельти вимірювань акселерометра або різниці часових міток) обробляється алгоритмом ZigZag, розподіл значень зміщується в область малих чисел `0, 1, 2, 3...`.

Більшість старших байтів у таких потоках стають нульовими. Це кардинально покращує коефіцієнт стиснення універсальними алгоритмами стиснення без втрат (такими як Deflate, LZ4, Zstandard або Snappy), оскільки вхідний потік отримує низьку інформаційну ентропію за Шенноном і високу концентрацію повторюваних нульових послідовностей.
