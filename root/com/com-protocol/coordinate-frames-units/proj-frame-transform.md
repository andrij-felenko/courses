# ⚙️ Реалізація перетворень координат та векторів орієнтації

При розробці бортових шлюзів телеметрії, драйверів автопілотів та вузлів інтеграції ROS–MAVLink (наприклад, [пакета MAVLink](root:sys-dron/mavlink-packet) та робототехнічних мостів) виникає постійна потреба у швидкому й строгому перетворенні геометричних величин між несумісними системами координат. Обчислення виконуються у контурах реального часу з частотою від 100 до 1000 Гц: будь-яка затримка, виділення динамічної пам'яті чи чисельна нестабільність у цих функціях безпосередньо впливає на стійкість навігаційного фільтра оцінки стану (EKF) та якість стабілізації апарата.

Нижче наведено вичерпний інженерний розбір математичних механізмів перетворення, аналіз крайових випадків та оптимізовані алгоритми мовами C і C++ для виконання чотирьох ключових класів перетворень: конвертації локальних базисів NED ⇄ ENU, перетворення зв'язаних базисів корпусу FRD ⇄ FLU, геодезичної проєкції WGS84 у локальну площину NED та швидкого повороту векторів у просторі за допомогою кватерніонів без застосування ресурсомістких матриць напрямних косинусів.

---

### 1. Перетворення локальних декартових базисів: NED ⇄ ENU

Локальні навігаційні системи координат описують положення та рух апарата у дотичній до земного сфероїда площині. Авіаційний базис NED (North-East-Down) спрямовує вісь X на Північ, Y на Схід, а Z вниз; робототехнічний базис ENU (East-North-Up) спрямовує X на Схід, Y на Північ, а Z вгору.

#### Алгебраїчний механізм та властивості симетрії

Перехід між цими базисами здійснюється одночасною перестановкою горизонтальних компонент та інверсією вертикальної компоненти:

```
x_enu =  y_ned       [Східний компонент стає першою віссю ENU]
y_enu =  x_ned       [Північний компонент стає другою віссю ENU]
z_enu = -z_ned       [Висота вгору дорівнює від'ємній глибині вниз]
```

Зворотне перетворення від ENU до NED має повністю симетричну структуру:

```
x_ned =  y_enu       [Північний компонент відновлюється з другої осі ENU]
y_ned =  x_enu       [Східний компонент відновлюється з першої осі ENU]
z_ned = -z_enu       [Глибина вниз дорівнює інвертованій висоті вгору]
```

Оскільки матриця перетворення є інволютивною (тобто її квадрат дорівнює одиничній матриці `T² = I`), пряме і зворотне перетворення виконуються абсолютно ідентичним набором інструкцій процесора. На сучасних архітектурах ARM Cortex-M4/M7/M33 та x86_64 ці функції транслюються компілятором у кілька регістрових інструкцій копіювання зі зміною знака одного регістра з рухомою комою (інструкція `VNEG` або `xorps`), що не створює жодного навантаження на обчислювальний конвеєр.

#### Перетворення векторів швидкості, прискорення та матриць коваріації

Аналогічне перетворення застосовується до векторів лінійної швидкості `(vx, vy, vz)` та лінійного прискорення `(ax, ay, az)`. 

Однак під час передачі оцінок точності (коваріаційних матриць позиції та швидкості `P` розміром 3 × 3 або 6 × 6) просте перепризначення елементів діагоналі є недостатнім. Повна коваріаційна матриця у системі ENU обчислюється через матричний добуток:

```
P_enu = T · P_ned · Tᵀ
```

Оскільки матриця `T` містить нулі та одиниці, елементи результуючої матриці коваріації обчислюються безпосередньо:
* Дисперсії по діагоналі: `Var(X_enu) = Var(Y_ned)`, `Var(Y_enu) = Var(X_ned)`, `Var(Z_enu) = Var(Z_ned)`.
* Взаємні коваріації: `Cov(X_enu, Y_enu) = Cov(Y_ned, X_ned)`, `Cov(X_enu, Z_enu) = -Cov(Y_ned, Z_ned)`, `Cov(Y_enu, Z_enu) = -Cov(X_ned, Z_ned)`.

### 2. Перетворення зв'язаних базисів корпусу: Body FRD ⇄ Body FLU

Зв'язані координати описують просторове розташування сенсорів (IMU, оптичних камер, лідарів) та векторів сили тяги відносно центру мас апарата.

#### Алгебраїчний механізм

Авіаційний базис FRD орієнтує осі: X вперед (Forward), Y праворуч (Right), Z вниз (Down). Робототехнічний базис FLU орієнтує осі: X вперед (Forward), Y ліворуч (Left), Z вгору (Up).

Поздовжня вісь руху залишається незмінною для обох систем, тоді як бічна та вертикальна осі дзеркально інвертуються:

```
x_flu =  x_frd       [Ніс апарата спрямований вперед в обох системах]
y_flu = -y_frd       [Ліва сторона протилежна правій]
z_flu = -z_frd       [Верхня кришка протилежна днищу]
```

Зворотний перехід здійснюється за тими самими правилами:

```
x_frd =  x_flu
y_frd = -y_flu
z_frd = -z_flu
```

#### Особливість трансформації кутових швидкостей та моментів

При передачі даних гіроскопа `(p, q, r)` (де `p` — кутова швидкість крену навколо поздовжньої осі, `q` — тангажу навколо поперечної осі, `r` — рискання навколо вертикальної осі) зміна знаків осей `Y` та `Z` змінює додатний напрямок обертання:
* Кутова швидкість крену: `p_flu = p_frd`.
* Кутова швидкість тангажу: `q_flu = -q_frd` (у FRD підйом носа додатний, у FLU — від'ємний).
* Кутова швидкість рискання: `r_flu = -r_frd` (у FRD поворот за годинниковою стрілкою додатний, у FLU — від'ємний).

### 3. Проєкція геодезичних координат WGS84 у локальну площину NED

Перетворення глобальних кутових координат широти `lat`, довготи `lon` та абсолютної висоти `alt` у метричні зміщення `(x, y, z)` відносно точки відліку Home (`lat_0`, `lon_0`, `alt_0`) є ключовим етапом роботи навігаційного фільтра.

#### Модель еліпсоїда WGS84 та радіуси кривини

Земля не є ідеальною сферою: радіус кривини поверхні залежить як від широти спостереження, так і від азимутального напрямку руху. Спрощена сферична модель із середнім радіусом `R = 6371 км` призводить до похибки масштабу до 20 метрів на дистанції у кілька кілометрів на широтах 45°…60°.

Для забезпечення високої точності застосовують параметри референц-еліпсоїда WGS84:
* Велика екваторіальна піввісь: `a = 6 378 137.0 м`.
* Коефіцієнт стиснення еліпсоїда: `f = 1 / 298.257223563`.
* Квадрат першого ексцентриситету: `e² = 2·f - f² ≈ 0.00669437999014`.

На заданій опорній широті точки старту `ϕ₀` розраховують два головні радіуси кривини:

1. **Радіус кривини меридіанного перерізу `M(ϕ₀)`** (визначає довжину дуги в 1° уздовж меридіана з півдня на північ):
   ```
   M(ϕ₀) = [ a · (1 - e²) ] / [ 1 - e²·sin²(ϕ₀) ]^(3/2)
   ```

2. **Радіус кривини першого вертикала `N(ϕ₀)`** (радіус кривини перерізу, перпендикулярного до меридіана, що визначає відстань уздовж паралелі зі сходу на захід):
   ```
   N(ϕ₀) = a / √(1 - e²·sin²(ϕ₀))
   ```

#### Формули розрахунку локальних координат

Кутові різниці широти `Δϕ` та довготи `Δλ` переводяться в радіани. Зміщення у метричній системі NED обчислюються за формулами:

```
Δϕ = (lat - lat_0) · (π / 180)
Δλ = (lon - lon_0) · (π / 180)

x_ned = Δϕ · (M(ϕ₀) + alt_0)
y_ned = Δλ · (N(ϕ₀) + alt_0) · cos(ϕ₀)
z_ned = -(alt - alt_0)
```

#### Аналіз крайових випадків та перетину меридіана 180°

Під час практичного програмування необхідно враховувати два критичні крайові випадки:

1. **Перетин лінії зміни дат (меридіан 180° / −180°):** Якщо точка Home розташована на довготі `+179.99°`, а апарат змістився на довготу `-179.99°`, просте арифметичне віднімання дасть `Δλ = -359.98°`, що відповідає помилковому стрибку на протилежний бік планети (зміщення у 40 000 км). Для коректного обчислення найкоротшої дуги довготу завжди нормалізують через функцію `atan2`:
   ```
   d_lon = atan2( sin(d_lambda), cos(d_lambda) )
   ```
2. **Полярні області (`ϕ₀ → ±90°`):** Біля полюсів множник `cos(ϕ₀) → 0`, через що довготні лінії сходяться в одну точку і декартова проєкція зазнає сильного спотворення. Навігація в межах 1° від полюсів вимагає переходу на полярну стереографічну проєкцію або роботу в глобальних геоцентричних координатах ECEF.

### 4. Швидкий поворот вектора за допомогою кватерніона

У контурах орієнтації та компенсації гравітації автопілот повинен багаторазово повертати тривимірні вектори між зв'язаним базисом корпусу та навігаційним базисом (наприклад, переносити виміряне акселерометром питоме прискорення у світову систему NED для віднімання вектора `g`).

#### Алгоритм Родрігеса проти матричного множення

Пряме перетворення вектора через кватерніонне множення Гамільтона вимагає подвійного добутку:
```
v_rot = q ⊗ (0, v) ⊗ q*
```
Пряме виконання цієї формули вимагає 32 множень та 24 додавань з рухомою комою.

Алгоритм оптимізується за векторною формулою Родрігеса, яка виключає множення на нульові компоненти:

```
q_v = [q.x, q.y, q.z]ᵀ        [векторна частина кватерніона]
t = 2 · (q_v × v)            [проміжний векторний добуток]
v_rot = v + q.w · t + (q_v × t)
```

#### Підрахунок обчислювальної складності:
* Обчислення проміжного вектора `t = 2 · (q_v × v)`: 6 множень, 3 віднімання.
* Обчислення другого векторного добутку `q_v × t`: 6 множень, 3 віднімання.
* Додавання складових `v + q.w · t + (q_v × t)`: 3 множення, 6 додавань.
* **Разом:** 15 множень та 12 операцій додавання/віднімання.

Цей алгоритм працює у понад два рази швидше за пряме обчислення подвійного кватерніонного добутку і не вимагає попередньої побудови повної матриці напрямних косинусів $3 \times 3$.

### 6. Покроковий чисельний розрахунок та перевірка інваріантів

Розглянемо практичний приклад роботи бібліотеки для безпілотного апарата:

#### Приклад 1. Геодезичне зміщення в районі міста Києва:
* **Точка старту Home:** Широта `50.450000° N`, Довгота `30.520000° E`, Висота `120.0 м` AMSL.
* **Цільова точка Waypoint:** Широта `50.451000° N` (+0.001°), Довгота `30.522000° E` (+0.002°), Висота `150.0 м` AMSL (+30 м).

Обчислення радіусів кривини для `ϕ₀ = 50.45°`:
1. `sin(ϕ₀) = 0.77107`, `cos(ϕ₀) = 0.63675`.
2. Знаменник `denom = 1 - 0.00669438 · (0.77107)² = 0.996020`.
3. Радіус меридіана: `M(ϕ₀) = 6 372 956 м`.
4. Радіус першого вертикала: `N(ϕ₀) = 6 390 873 м`.

Розрахунок локальних зміщень NED:
* `x_ned = (0.001 · π / 180) · (6 372 956 + 120) = +111.23 м` (зміщення на Північ на 111.23 м).
* `y_ned = (0.002 · π / 180) · (6 390 873 + 120) · 0.63675 = +142.06 м` (зміщення на Схід на 142.06 м).
* `z_ned = -(150.0 - 120.0) = -30.00 м` (висота 30 м угору відповідає `Z = -30 м` у системі NED).

#### Приклад 2. Поворот вектора сили тяги:
* У зв'язаній системі FRD вектор тяги чотирьох моторів квадрокоптера спрямований вертикально вгору крізь дах, що у системі координат корпусу відповідає від'ємній осі Z: `F_body = [0, 0, -20.0 Н]ᵀ`.
* Квадрокоптер завис горизонтально з нульовими кутами крену й тангажу, але розвернутий носом на Схід (кут курсу `ψ = 90°`, кватерніон `q = [cos(45°), 0, 0, sin(45°)] = [0.7071, 0, 0, 0.7071]ᵀ`).
* Застосування функції `quaternion_rotate_vector(q, F_body)` дає вектор тяги у світовій системі NED: `F_world = [0, 0, -20.0 Н]ᵀ`. Вектор тяги строго компенсує вагу апарата і не створює бічних прискорень, незалежно від азимутального курсу розвороту.
