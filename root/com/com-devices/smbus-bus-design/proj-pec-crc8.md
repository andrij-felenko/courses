# ⚙️ Обчислення та перевірка контрольної суми PEC (CRC-8)

Практична інженерна реалізація алгоритму контролю помилок пакетів **PEC** (*Packet Error Checking*) для шини SMBus: математична модель полінома, побітовий розрахунок через зсувні регістри, оптимізована генерація таблиць пошуку (LUT), потокове накопичення залишку через межі повторного старту (*Repeated START*), математичний аналіз виявлення помилок, автомат станів веденого пристрою, емуляція ведучого через програмний Bit-Banging, взаємодія з дескрипторами DMA, діагностика за допомогою логічних аналізаторів та повний робочий модуль валідації транзакцій мовами C і сучасним C++.

У промислових, серверних та автомобільних системах шина SMBus часто прокладається поруч із силовими імпульсними перетворювачами напруги (VRM), електродвигунами та потужними ключами комутації батарей. Короткочасна електромагнітна завада здатна перекинути один або кілька бітів на лінії SDA саме в момент високого рівня тактового сигналу SCL. Оскільки класичний інтерфейс I2C перевіряє лише поодинокий біт підтвердження ACK після кожного байта, приймач не має жодної можливості помітити спотворення корисних даних. Механізм PEC усуває цю вразливість, додаючи до кінця кожного кадру 8-бітний циклічний надлишковий код [CRC-8](topic:com-modulation/crc-algorithm), що охоплює абсолютно всі передані байти — від першого адресного байта до останнього поля даних.

---

### Математична модель полінома SMBus PEC

Алгоритм PEC базується на поліноміальному діленні за модулем 2 у полі Галуа GF(2). Стандарт SMBus (починаючи з версії 1.1) жорстко фіксує утворюючий поліном:

```
C(x) = x⁸ + x² + x¹ + 1
```

У двійковому представленні поліном 8-го степеня записується 9 бітами:
```
1 0 0 0 0 0 1 1 1 b  =  0x107
```
Оскільки старший біт `x⁸` (9-й біт) завжди дорівнює одиниці для будь-якого 8-бітного полінома, в програмних реалізаціях використовують його 8-бітну «зрізану» константу: **`0x07`**.

#### Фундаментальні параметри стандарту SMBus PEC:
- **Ширина залишку:** 8 біт (`uint8_t`);
- **Утворюючий поліном:** `0x07` (`x⁸ + x² + x + 1`);
- **Початкове значення залишку (*Initial Value*):** `0x00` (нульовий початковий стан акумулятора);
- **Прямий напрямок передачі (*Reflect In = False*):** Байти надходять у розрахунок старшим бітом (*MSB first*) уперед;
- **Прямий вихідний результат (*Reflect Out = False*):** Отриманий залишок не реверсується біт за бітом;
- **Фінальне маскування (*XOR Out*):** `0x00` (значення не інвертується перед відправкою на шину);
- **Контрольний залишок для тестового рядка "123456789":** `0xF4`.

> ⚠️ **Відмінність від інших стандартів CRC-8:** На відміну від популярного полінома [1-Wire / Dallas Maxim](topic:com-devices/one-wire) (`0x31` / `0x8C`), де дані обробляються молодшим бітом уперед (*LSB first*), SMBus PEC працює виключно у прямому порядку (*MSB first*). Спроба застосувати готову функцію CRC-8 з бібліотек 1-Wire без адаптації бітового порядку призведе до повної невідповідності контрольних сум на шині.

### Математичний аналіз спроможності виявлення помилок

Поліном `C(x) = x⁸ + x² + x + 1` обрано розробниками стандарту SMBus не випадково. Він володіє специфічними алгебраїчними властивостями, оптимізованими для коротких пакетів довжиною до 34 байтів (максимальний розмір кадру SMBus 2.0):

1. **100% виявлення поодиноких помилок (Single-bit Errors):** Будь-яке спотворення одного біта в повідомленні довільної довжини гарантовано призводить до ненульового синдрому помилки, оскільки поліном містить ненульовий молодший член `x⁰ = 1`.
2. **100% виявлення подвійних помилок (Double-bit Errors):** Поліном гарантує виявлення будь-яких двох спотворених бітів у межах блоку довжиною до 119 бітів (відстань Геммінга HD=4 для пакетів типового розміру).
3. **100% виявлення непарної кількості помилок:** Оскільки многочлен ділиться на `(x + 1)` у полі GF(2), будь-яка непарна кількість перекинутих бітів (1, 3, 5, 7 тощо) дає гарантовано ненульовий залишок.
4. **100% виявлення пакетних спалахів завад (Burst Errors) довжиною до 8 бітів:** Якщо імпульсна завада від комутації індуктивного навантаження спотворює до 8 сусідніх бітів поспіль, CRC-8 виявляє такий збій із ймовірністю 1.0 (100%).
5. **Для довгих випадкових спотворень (> 8 бітів):** Ймовірність пропуску помилки становить `1 / 2⁸ = 1 / 256 ≈ 0.39%`, тобто 99.61% випадкових спотворень відкидаються приймачем.

### Покроковий розбір обчислення залишку

Щоб побачити, як біти взаємодіють з утворюючим поліномом, простежимо обробку одного байта `0x5A` (`01011010b`) при нульовому початковому стані регістру CRC:

```
Крок 0: Вхідний байт = 01011010b, Поточний CRC = 00000000b
Крок 1: Зсув вліво. Старший біт = 0. CRC = 00000000b
Крок 2: Зсув вліво. Старший біт = 1. CRC = (00000000b << 1) ^ 00000111b = 00000111b (0x07)
Крок 3: Зсув вліво. Старший біт = 0. CRC = 00000111b << 1 = 00001110b (0x0E)
Крок 4: Зсув вліво. Старший біт = 1. CRC = (00001110b << 1) ^ 00000111b = 00011101b (0x1D)
Крок 5: Зсув вліво. Старший біт = 1. CRC = (00011101b << 1) ^ 00000111b = 00111011b (0x3B)
Крок 6: Зсув вліво. Старший біт = 0. CRC = 00111011b << 1 = 01110110b (0x76)
Крок 7: Зсув вліво. Старший біт = 1. CRC = (01110110b << 1) ^ 00000111b = 11101101b (0xED)
Крок 8: Зсув вліво. Старший біт = 0. CRC = (11101101b << 1) ^ 00000111b = 11011011b (0xDB)
Фінальний залишок після першого байта = 0xDB
```

Кожен наступний байт транзакції підмішується до отриманого проміжного залишку `0xDB` через операцію XOR і знову проходить 8 кроків зсуву.

### Побітовий алгоритм обчислення (Bit-by-Bit Shift Register)

Для глибокого розуміння апаратної логіки розглянемо лінійний зсувний регістр зі зворотним зв'язком (LFSR). На кожному тактовому імпульсі поточний біт повідомлення додається за модулем 2 (XOR) до найстаршого біта регістра (біт 7). Якщо результат дорівнює 1, регістр зсувається вліво на 1 розряд, а у молодші розряди підмішується маска полінома `0x07`. Якщо результат дорівнює 0, виконується простий зсув вліво без операції XOR:

```
Вхідний байт D (8 бітів)
   │
   ▼
[ Біт 7 ] ──► (XOR) ───► [Чи старший біт = 1?] ──► Так ──► (crc << 1) ^ 0x07
                ▲                               └──► Ні  ──► (crc << 1)
                │
 Поточний стан CRC[7]
```

Цей базовий алгоритм вимагає мінімального обсягу оперативної пам'яті (лише один 8-бітний регістр) і ідеально підходить для мікроконтролерів із жорстко обмеженими ресурсами (наприклад, 8-бітних контролерів акумуляторних батарей PIC або 8051).

### Табличне прискорення (Lookup Table / LUT)

У високопродуктивних системах, де ведучий процесор обслуговує десятки транзакцій на частотах 400 кГц або 1 МГц, порозрядний цикл із 8 ітерацій на кожен байт створює помітне навантаження на процесор. Оскільки вхідний символ обмежений 256 можливими значеннями, операцію ділення 8 бітів на константний поліном можна попередньо обчислити й зберегти в таблиці з 256 байтів.

Для кожного байта даних оновлення проміжного залишку зводиться до єдиної інструкції вибірки з пам'яті:
```
crc = smbus_crc8_table[crc ^ new_byte];
```
Це скорочує час обчислення до `O(1)` операцій на кожен байт і усуває умовні переходи, забезпечуючи константний час виконання (*constant-time execution*), що є критично важливим для захисту криптографічних протоколів від атак за сторонніми каналами (*timing attacks*).

### Потокове накопичення залишку у складених транзакціях

Найпоширеніша помилка розробників-початківців — обчислення PEC лише від корисних даних або скидання акумулятора CRC між фазами транзакції. 

Специфікація SMBus вимагає, щоб байт PEC формувався як результат неперервного поліноміального ділення **всього потоку байтів**, переданих між умовами СТАРТ та СТОП:

1. **Фаза запису регістра:** У потік CRC входять байт адреси веденого з бітом `Wr` (наприклад, `0x5A`) та код команди `Cmd Code` (наприклад, `0x08`).
2. **Фаза повторного старту (Repeated START):** Незважаючи на те, що умова `Sr` не передає фізичних бітів даних, вона змінює напрямок шини на читання. Наступний байт адреси веденого з бітом `Rd` (наприклад, `0x5B`) **зобов'язаний увійти до потоку CRC** як черговий вхідний байт!
3. **Фаза читання даних:** Усі прийняті від веденого байти (`DataLow`, `DataHigh`, а у блокових транзакціях — і лічильник `Byte Count`) послідовно подаються в акумулятор CRC.
4. **Фінал:** Розраховане 8-бітне значення порівнюється з байтом PEC, надісланим веденим пристроєм перед сигналом СТОП.

```
Транзакція Read Word:
┌──────────────┬──────────┬──────────────┬─────────┬──────────┬──────────┐
│ Addr + Wr(0) │ Cmd Code │ Addr + Rd(1) │ DataLow │ DataHigh │ PEC Byte │
└──────────────┴──────────┴──────────────┴─────────┴──────────┴──────────┘
 └─────────────────────── Охоплено CRC-8 ─────────────────────┘ 
```

Розглянемо приклад блокового запису **Block Write** рядка `"BAT1"` (4 байти) у регістр `0x20` (DeviceName) пристрою з адресою `0x0B` (`0x16` при записі):
- Байт 1: Адреса запису = `0x16`
- Байт 2: Код команди = `0x20`
- Байт 3: Лічильник `Byte Count` = `0x04`
- Байти 4..7: Символи даних = `'B'` (`0x42`), `'A'` (`0x41`), `'T'` (`0x54`), `'1'` (`0x31`)
- Байт 8: Байт PEC = результат послідовного пропускання всіх 7 попередніх байтів через поліном `0x07`.

Якщо під час перевірки розрахований ведучим залишок точно дорівнює отриманому байту PEC (або якщо пропустити сам байт PEC через функцію оновлення і отримати фінальний залишок `0x00`), транзакція вважається повністю валідною.

### Автомат станів веденого пристрою з перевіркою PEC

При розробці прошивки веденого пристрою (наприклад, цифрового давача струму або контролера батареї на базі STM32/ESP32) обробка PEC вимагає чіткого керування лінією підтвердження на рівні переривань шини:

```
[Подія START] ──► Скинути акумулятор CRC = 0x00
      │
      ▼
[Прийом адреси веденого (Wr)] ──► crc = update(crc, addr_wr) ──► Видати ACK
      │
      ▼
[Прийом коду команди (Cmd)] ──► crc = update(crc, cmd) ──► Видати ACK
      │
      ▼
[Прийом байтів даних Data[i]] ──► crc = update(crc, data[i]) ──► Видати ACK
      │
      ▼
[Прийом фінального байта PEC] ──► Порівняти rx_pec == crc:
                                     ├─ Збіг  ──► Видати ACK, застосувати дані до регістрів
                                     └─ Помилка ──► Видати NACK, відкинути дані, виставити статус PECERR
```

Цей алгоритм гарантує, що жодне спотворене завадою значення не потрапить у робочі регістри налаштувань, запобігаючи аварійним режимам роботи апаратної частини.

### Програмний емулятор ведучого з перевіркою тайм-ауту t_TIMEOUT

Коли мікроконтролер не має апаратного блоку SMBus або виводи перепризначені на довільні ніжки GPIO, ведучий реалізується програмним методом (*Bit-Banging*). Програмний драйвер зобов'язаний вимірювати тривалість утримання лінії SCL у нульовому стані веденим пристроєм (*Clock Stretching*) і примусово переривати транзакцію, якщо затримка перевищує ліміт `t_TIMEOUT` (25–35 мс).

Нижче наведено фрагмент логіки керування лініями та контролю тайм-ауту:

```
Функція очікування відпускання SCL веденим:
  Початок відліку таймера t0
  Поки SCL == 0:
    Якщо (час() - t0) > 35 мс:
      Виставити прапорець помилки ETIMEDOUT
      Сформувати апаратне скидання шини 9 тактами
      Повернути статус BusTimeout
```

### Поведінка при колізіях та втраті арбітражу

У багатомайстрових системах (*Multi-Master*) два контролери можуть одночасно почати транзакцію до одного або різних ведених. Якщо ведучий виставляє на лінію SDA логічну 1, але датчик напруги фіксує 0 (інший ведучий притягнув шину до нуля), фіксується втрата арбітражу (*Arbitration Lost*):

1. **Негайне відключення вихідного драйвера:** Переможений ведучий негайно вимикає свій вихідний каскад SDA і переходить у режим пасивного слухача.
2. **Скидання розрахунку PEC:** Акумулятор CRC перериває розрахунок перерваного повідомлення і переініціалізується нулем для відстеження поточної транзакції переможця.
3. **Повтор після звільнення шини:** Після виявлення сигналу СТОП та паузи `t_BUF` переможений ведучий повторює свою транзакцію з чистого аркуша.

### Діагностика та аналіз пакетів у PulseView / Saleae Logic

Під час налагодження обміну на фізичній шині за допомогою цифрового логічного аналізатора декодер протоколу `I2C / SMBus` налаштовується з такими параметрами:
- **Protocol:** `SMBus`;
- **PEC Calculation:** `Enabled`;
- **CRC Polynomial:** `0x07` (`x^8 + x^2 + x + 1`);
- **Initial Value:** `0x00`;
- **Bit Order:** `MSB First`.

Аналізатор автоматично підсвічує байт PEC зеленим кольором при збігу контрольної суми або червоним кольором у разі виявлення помилки, що дозволяє миттєво локалізувати джерело апаратних спотворень на осцилограмі. Крім того, тригер логічного аналізатора можна налаштувати на умову виставлення сигналу NACK на 9-му такті після байта PEC, що забезпечує автоматичний запис саме тих аномальних транзакцій, які зазнали впливу перешкод.

### Апаратна підтримка PEC у мікроконтролерах та DMA

Сучасні мікроконтролери (STM32, NXP Kinetis, TI MSPM0) мають вбудований у периферійний блок I2C апаратний обчислювач PEC з підтримкою прямого доступу до пам'яті (DMA):

1. **Активація:** Встановлення біта `I2C_CR1_PECEN` вмикає внутрішній автомат CRC-8.
2. **Робота під час передачі:** При відправці даних апаратний блок автоматично пропускає кожен байт через зсувний регістр. Перед формуванням сигналу СТОП програма або контролер DMA встановлює біт `I2C_CR1_PEC`, після чого апаратний блок автоматично виставляє накопичений залишок PEC на лінію SDA.
3. **Робота під час прийому з DMA:** При блоковому прийомі контролер DMA пересилає дані прямо в оперативну пам'ять. Останній байт вважається байтом PEC. Якщо він не збігається з внутрішнім регістром `I2C_SR2_PEC`, апаратний блок виставляє прапорець переривання помилки `I2C_SR1_PECERR` та автоматично надсилає сигнал NACK на шину, не вимагаючи від центрального процесора ручного побайтового розрахунку.
4. **Ланцюжки дескрипторів (Scatter-Gather DMA):** У складних мережевих стеках контролер DMA налаштовується ланцюжком із двох дескрипторів: перший дескриптор перекачує корисні байти в буфер користувача, другий — читає контрольний байт PEC у службовий регістр перевірки статусу без створення переривань на кожен окремий байт.

### Робоча реалізація на C та C++

Наведений нижче програмний модуль містить повний набір функцій для роботи з SMBus PEC:
- Генерацію таблиці пошуку в пам'яті (C) або на етапі компіляції (`constexpr` у C++);
- Потоковий оновлювач акумулятора CRC;
- Функцію формування кадру запису Write Word з розрахунком PEC;
- Функцію валідації прийнятого кадру читання Read Word з перевіркою PEC;
- Функцію розрахунку PEC для блокових транзакцій Block Write/Read;
- Автомат веденого приймача `smbus_slave_process_write_word()`, що ілюструє повний цикл перевірки цілісності;
- Модуль автоматизованого самотестування (*Self-Test Harness*), що перевіряє еталонні вектори та виявлення поодиноких і пакетних бітових збоїв;
- Безпечні обгортки на базі `std::span`, `std::expected` та типізованих структур у C++.

```c
#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <assert.h>

#define SMBUS_CRC8_POLYNOMIAL 0x07

static uint8_t smbus_crc8_lut[256];
static bool lut_initialized = false;

/* Генерація таблиці пошуку 256 байтів для полінома x^8 + x^2 + x + 1 */
void smbus_crc8_init_table(void) {
    for (int i = 0; i < 256; ++i) {
        uint8_t curr = (uint8_t)i;
        for (int bit = 0; bit < 8; ++bit) {
            if (curr & 0x80) {
                curr = (uint8_t)((curr << 1) ^ SMBUS_CRC8_POLYNOMIAL);
            } else {
                curr = (uint8_t)(curr << 1);
            }
        }
        smbus_crc8_lut[i] = curr;
    }
    lut_initialized = true;
}

/* Оновлення біжучого залишку CRC-8 одним байтом */
uint8_t smbus_crc8_update(uint8_t crc, uint8_t data) {
    if (!lut_initialized) {
        smbus_crc8_init_table();
    }
    return smbus_crc8_lut[crc ^ data];
}

/* Обчислення PEC для масиву байтів довільної довжини */
uint8_t smbus_crc8_block(uint8_t initial_crc, const uint8_t *data, size_t len) {
    uint8_t crc = initial_crc;
    for (size_t i = 0; i < len; ++i) {
        crc = smbus_crc8_update(crc, data[i]);
    }
    return crc;
}

/* Розрахунок PEC для транзакції Write Word:
   Потік: [SlaveAddr | Wr] -> [Command] -> [DataLow] -> [DataHigh] */
uint8_t smbus_calc_write_word_pec(uint8_t slave_addr_7bit, uint8_t cmd, uint16_t word_val) {
    uint8_t addr_wr = (uint8_t)(slave_addr_7bit << 1); // R/W = 0 (Write)
    uint8_t data_low = (uint8_t)(word_val & 0xFF);
    uint8_t data_high = (uint8_t)((word_val >> 8) & 0xFF);

    uint8_t crc = 0x00;
    crc = smbus_crc8_update(crc, addr_wr);
    crc = smbus_crc8_update(crc, cmd);
    crc = smbus_crc8_update(crc, data_low);
    crc = smbus_crc8_update(crc, data_high);
    return crc;
}

/* Перевірка цілісності транзакції Read Word:
   Потік: [SlaveAddr | Wr] -> [Command] -> [SlaveAddr | Rd] -> [DataLow] -> [DataHigh] */
bool smbus_verify_read_word_pec(uint8_t slave_addr_7bit, uint8_t cmd,
                                uint8_t data_low, uint8_t data_high, uint8_t rx_pec) {
    uint8_t addr_wr = (uint8_t)(slave_addr_7bit << 1);          // R/W = 0
    uint8_t addr_rd = (uint8_t)((slave_addr_7bit << 1) | 0x01); // R/W = 1

    uint8_t crc = 0x00;
    crc = smbus_crc8_update(crc, addr_wr);
    crc = smbus_crc8_update(crc, cmd);
    crc = smbus_crc8_update(crc, addr_rd);
    crc = smbus_crc8_update(crc, data_low);
    crc = smbus_crc8_update(crc, data_high);

    return (crc == rx_pec);
}

/* Розрахунок PEC для транзакції Block Write:
   Потік: [SlaveAddr | Wr] -> [Command] -> [Byte Count N] -> [Data 1 .. N] */
uint8_t smbus_calc_block_write_pec(uint8_t slave_addr_7bit, uint8_t cmd,
                                   const uint8_t *data, uint8_t length) {
    uint8_t addr_wr = (uint8_t)(slave_addr_7bit << 1);
    uint8_t crc = 0x00;
    crc = smbus_crc8_update(crc, addr_wr);
    crc = smbus_crc8_update(crc, cmd);
    crc = smbus_crc8_update(crc, length);
    for (uint8_t i = 0; i < length; ++i) {
        crc = smbus_crc8_update(crc, data[i]);
    }
    return crc;
}

/* Логіка обробки прийому кадру Write Word веденим пристроєм */
bool smbus_slave_process_write_word(uint8_t slave_addr_7bit, uint8_t cmd,
                                    uint8_t low, uint8_t high, uint8_t rx_pec,
                                    uint16_t *out_valid_word) {
    uint8_t expected_pec = smbus_calc_write_word_pec(slave_addr_7bit, cmd,
                                                     (uint16_t)((high << 8) | low));
    if (expected_pec != rx_pec) {
        return false; // Відкинути пошкоджені дані
    }
    if (out_valid_word != NULL) {
        *out_valid_word = (uint16_t)((high << 8) | low);
    }
    return true; // Дані верифіковано успішно
}

/* Автоматизований тест алгоритму */
bool smbus_pec_run_selftest(void) {
    /* Стандартний тестовий вектор: рядок "123456789" -> 0xF4 */
    const uint8_t test_vector[] = {0x31, 0x32, 0x33, 0x34, 0x35, 0x36, 0x37, 0x38, 0x39};
    uint8_t crc = smbus_crc8_block(0x00, test_vector, sizeof(test_vector));
    if (crc != 0xF4) {
        return false;
    }

    /* Тест Write Word: Адреса 0x16 (0x2C на шині), Команда 0x09 (Voltage), Значення 0x0FA0 (4000 мВ) */
    uint8_t pec = smbus_calc_write_word_pec(0x16, 0x09, 0x0FA0);
    /* Спотворення одного біта в даних мусить гарантовано змінити PEC */
    uint8_t corrupted_pec = smbus_calc_write_word_pec(0x16, 0x09, 0x0FA1);
    if (pec == corrupted_pec) {
        return false;
    }

    uint16_t received_val = 0;
    if (!smbus_slave_process_write_word(0x16, 0x09, 0xA0, 0x0F, pec, &received_val)) {
        return false;
    }
    if (received_val != 0x0FA0) {
        return false;
    }

    return true;
}
```

```cpp
#include <cstdint>
#include <cstddef>
#include <array>
#include <span>
#include <expected>

namespace smbus {

inline constexpr uint8_t POLYNOMIAL = 0x07;

/* Генерація таблиці пошуку на етапі компіляції (zero runtime overhead) */
consteval std::array<uint8_t, 256> generate_crc8_table() noexcept {
    std::array<uint8_t, 256> table{};
    for (size_t i = 0; i < 256; ++i) {
        auto curr = static_cast<uint8_t>(i);
        for (size_t bit = 0; bit < 8; ++bit) {
            if (curr & 0x80) {
                curr = static_cast<uint8_t>((curr << 1) ^ POLYNOMIAL);
            } else {
                curr = static_cast<uint8_t>(curr << 1);
            }
        }
        table[i] = curr;
    }
    return table;
}

inline constexpr auto CRC8_LUT = generate_crc8_table();

/* Клас потокового обчислювача PEC */
class PecCalculator {
public:
    constexpr PecCalculator() noexcept = default;

    constexpr void update(uint8_t byte) noexcept {
        m_crc = CRC8_LUT[m_crc ^ byte];
    }

    constexpr void update(std::span<const uint8_t> bytes) noexcept {
        for (uint8_t b : bytes) {
            m_crc = CRC8_LUT[m_crc ^ b];
        }
    }

    [[nodiscard]] constexpr uint8_t value() const noexcept {
        return m_crc;
    }

    constexpr void reset() noexcept {
        m_crc = 0x00;
    }

private:
    uint8_t m_crc{0x00};
};

enum class Error {
    PecMismatch,
    BusTimeout,
    NackReceived
};

/* Обчислення PEC для транзакції Write Word */
[[nodiscard]] constexpr uint8_t calc_write_word_pec(uint8_t slave_addr_7bit,
                                                    uint8_t cmd,
                                                    uint16_t value) noexcept {
    PecCalculator calc;
    const uint8_t addr_wr = static_cast<uint8_t>(slave_addr_7bit << 1);
    const auto data_low = static_cast<uint8_t>(value & 0xFF);
    const auto data_high = static_cast<uint8_t>((value >> 8) & 0xFF);

    calc.update(addr_wr);
    calc.update(cmd);
    calc.update(data_low);
    calc.update(data_high);
    return calc.value();
}

/* Перевірка цілісності транзакції Read Word */
[[nodiscard]] constexpr std::expected<uint16_t, Error> verify_read_word(
    uint8_t slave_addr_7bit,
    uint8_t cmd,
    uint8_t data_low,
    uint8_t data_high,
    uint8_t rx_pec) noexcept {

    PecCalculator calc;
    const uint8_t addr_wr = static_cast<uint8_t>(slave_addr_7bit << 1);
    const uint8_t addr_rd = static_cast<uint8_t>((slave_addr_7bit << 1) | 0x01);

    calc.update(addr_wr);
    calc.update(cmd);
    calc.update(addr_rd);
    calc.update(data_low);
    calc.update(data_high);

    if (calc.value() != rx_pec) {
        return std::unexpected(Error::PecMismatch);
    }

    const auto result = static_cast<uint16_t>((static_cast<uint16_t>(data_high) << 8) | data_low);
    return result;
}

/* Обчислення PEC для транзакції Block Write */
[[nodiscard]] constexpr uint8_t calc_block_write_pec(uint8_t slave_addr_7bit,
                                                     uint8_t cmd,
                                                     std::span<const uint8_t> data) noexcept {
    PecCalculator calc;
    const uint8_t addr_wr = static_cast<uint8_t>(slave_addr_7bit << 1);
    const auto length = static_cast<uint8_t>(data.size());

    calc.update(addr_wr);
    calc.update(cmd);
    calc.update(length);
    calc.update(data);
    return calc.value();
}

/* Логіка обробки прийому кадру Write Word веденим пристроєм у C++ */
[[nodiscard]] constexpr std::expected<uint16_t, Error> slave_process_write_word(
    uint8_t slave_addr_7bit,
    uint8_t cmd,
    uint8_t low,
    uint8_t high,
    uint8_t rx_pec) noexcept {

    const uint16_t val = static_cast<uint16_t>((static_cast<uint16_t>(high) << 8) | low);
    const uint8_t expected = calc_write_word_pec(slave_addr_7bit, cmd, val);
    if (expected != rx_pec) {
        return std::unexpected(Error::PecMismatch);
    }
    return val;
}

/* Compile-time перевірка еталонного вектора та логіки верифікації */
static_assert([]() consteval {
    constexpr std::array<uint8_t, 9> test_vec = {0x31, 0x32, 0x33, 0x34, 0x35, 0x36, 0x37, 0x38, 0x39};
    PecCalculator calc;
    calc.update(test_vec);
    if (calc.value() != 0xF4) return false;

    auto res = slave_process_write_word(0x16, 0x09, 0xA0, 0x0F, calc_write_word_pec(0x16, 0x09, 0x0FA0));
    return res.has_value() && res.value() == 0x0FA0;
}(), "Помилка розрахунку еталонного вектора SMBus PEC");

} // namespace smbus
```

### Практичний розбір інженерних пасток

При впровадженні та налагодженні підтримки PEC у реальних мікроконтролерних проєктах найчастіше виникають чотири критичні помилки:

1. **Неправильна обробка сигналу NACK на фінальному байті читання.** У транзакціях читання ведучий повинен відповісти сигналом ACK на останній байт даних, щоб ведений зрозумів: обмін продовжується і зараз необхідно виставити байт PEC. Лише після прийому самого байта PEC ведучий зобов'язаний виставити фінальний сигнал NACK перед формуванням умови СТОП. Якщо ведучий виставить NACK одразу на останньому байті даних (як у класичному I2C), ведений пристрій миттєво відпустить лінію SDA, сприйме це як дострокове переривання зв'язку і не видасть байт PEC.
2. **Пропуск повторної адреси читання в транзакціях Repeated START.** Багато інженерів помилково вважають, що контрольна сума рахується лише від корисних даних та коду команди. Пропуск байта `[SlaveAddr | Rd]` у фазі читання — найпоширеніша причина, чому апаратний блок обчислення PEC у мікроконтролерах STM32 або чипсетах Intel повертає помилку `PECERR` при абсолютно коректних даних на осцилографі.
3. **Плутанина з порядком байтів (Endianness).** Специфікація SMBus вимагає передачі 16-бітних слів у форматі Little-Endian: спочатку молодший байт `DataLow`, потім старший байт `DataHigh`. Оскільки в потік CRC байти потрапляють у хронологічному порядку їх появи на дротах, подача `DataHigh` першим призведе до абсолютно іншого фінального залишку CRC.
4. **Апаратний блок CRC у мікроконтролерах.** Більшість сучасних мікроконтролерів (STM32, NXP LPC, ESP32) мають вбудований периферійний модуль I2C із апаратною підтримкою SMBus. При встановленні біта `PECEN` (PEC Enable) у регістрах конфігурації модуль автоматично генерує та перевіряє PEC без участі процесора. Однак якщо ведучий здійснює програмну емуляцію шини (*Bit-Banging* через GPIO), наведені вище функції табличного розрахунку є єдиним способом гарантувати стовідсоткову сумісність зі специфікацією SMBus.
