# 📋 Специфікація протокольних транзакцій SMBus

Повний технічний довідник структур даних, часових діаграм, бітових прапорців та форматів пакетів шини SMBus (*System Management Bus* версій 2.0, 3.0 та 3.2), необхідний системним програмістам, розробникам драйверів операційних систем та інженерам вбудованих систем для коректної реалізації взаємодії з апаратною периферією.

На відміну від інтерфейсу I2C, де протокол обмежується лише пересиланням послідовності неструктурованих 8-бітних байтів, специфікація SMBus регламентує фіксований набір стандартизованих транзакцій. Кожна транзакція чітко визначає семантику адресного байта, коду команди (*Command Code*), лічильника довжини (*Byte Count*), порядок байтів (*Little-Endian*) та позицію байта перевірки цілісності пакета (*Packet Error Checking* — PEC).

---

### Умовні позначення в діаграмах пакетів

Усі подальші описи транзакцій використовують стандартизовані позначення специфікації SMBus. Кожен прямокутник позначає 8-бітний байт або 1-бітний сигнал керування на шині із зазначенням сторони, яка формує сигнал:
- **[M]** — сигнал генерує ведучий пристрій (**Master / Host Controller**);
- **[S]** — сигнал генерує ведений пристрій (**Slave / Target Device**).

| Символ | Опис сигналу | Формує | Значення на лініях SDA / SCL |
| :--- | :--- | :---: | :--- |
| **S** | Умова СТАРТ (*START Condition*) | [M] | Спадний перепад на SDA при високому рівні SCL |
| **Sr** | Повторний СТАРТ (*Repeated START*) | [M] | Спадний перепад на SDA без попереднього СТОПу |
| **P** | Умова СТОП (*STOP Condition*) | [M] | Зростаючий перепад на SDA при високому рівні SCL |
| **Wr** | Біт напрямку «Запис» (*Write bit*) | [M] | Логічний 0 на 8-му такті адресного байта |
| **Rd** | Біт напрямку «Читання» (*Read bit*) | [M] | Логічна 1 на 8-му такті адресного байта |
| **A** | Сигнал підтвердження (*ACK*) | [S]/[M] | Лінія SDA притягнута до 0 під час 9-го такту SCL |
| **N** | Сигнал непідтвердження (*NACK*) | [S]/[M] | Лінія SDA відпущена у високий стан (1) на 9-му такті |
| **Cmd** | Код команди / адреса регістра | [M] | 8-бітний номер регістра або команди (0x00–0xFF) |
| **Data** | Байт корисних даних | [M]/[S] | 8-бітне значення |
| **Count** | Лічильник байтів (*Byte Count*) | [M]/[S] | Кількість наступних байтів даних (1..32 в SMBus 2.0, 1..255 в 3.0) |
| **PEC** | Байт перевірки пакета (*Packet Error Code*) | [M]/[S] | 8-бітний код CRC-8 полінома `x^8 + x^2 + x + 1` |

### Базові транзакції без адресації регістрів

#### 1. Quick Command (Швидка команда)
Транзакція складається лише з адресного байта без подальшої передачі даних. Використовується для найпростішого опитування присутності пристрою на шині (сканування адрес), вмикання/вимикання живлення або перемикання однобітного стану веденого.

```
Без PEC:
 1      7       1    1   1
+---+---------+----+---+---+
| S | Address | R/W| A | P |
+---+---------+----+---+---+
 [M]    [M]     [M] [S] [M]
```

**Механізм та застосування:**
- Утиліта `i2cdetect` у Linux за замовчуванням надсилає Quick Command для кожної адреси простору 0x03–0x77. Якщо ведений відповідає сигналом ACK (0), пристрій вважається активним на шині.
- Окремі прості контролери живлення трактують біт `R/W` як команду зміни стану: біт 0 (`Wr`) переводить вихід ключа у вимкнений стан, біт 1 (`Rd`) — у ввімкнений стан.
- Контроль помилок PEC для Quick Command не застосовується, оскільки транзакція не містить поля корисних даних, а сам адресний біт підтверджується безпосередньо сигналом ACK веденого.

#### 2. Send Byte (Надіслати байт)
Ведучий надсилає один байт веденому пристрою без попереднього зазначення коду команди чи номера регістра.

```
Без PEC:
 1      7       1    1       8        1   1
+---+---------+----+---+------------+---+---+
| S | Address | Wr | A |  Data Byte | A | P |
+---+---------+----+---+------------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S] [M]

З контролем PEC:
 1      7       1    1       8        1      8       1   1
+---+---------+----+---+------------+---+----------+---+---+
| S | Address | Wr | A |  Data Byte | A | PEC Byte | A | P |
+---+---------+----+---+------------+---+----------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S]    [M]     [S] [M]
```

**Механізм та застосування:**
- Застосовується для передачі однобайтних команд прямої дії: скидання автомата станів, переведення в режим низького енергоспоживання, ініціалізація внутрішнього калібрування давача.
- При увімкненому PEC ведучий обчислює CRC-8 від сукупності двох байтів: `[Address + Wr]` та `[Data Byte]`. Якщо ведений фіксує невідповідність розрахованого залишку переданому PEC, він зобов'язаний виставити сигнал NACK на 9-му такті та проігнорувати отриманий байт даних.

#### 3. Receive Byte (Прийняти байт)
Ведучий зчитує один байт від веденого пристрою без попереднього надсилання номера регістра.

```
Без PEC:
 1      7       1    1       8        1   1
+---+---------+----+---+------------+---+---+
| S | Address | Rd | A |  Data Byte | N | P |
+---+---------+----+---+------------+---+---+
 [M]    [M]    [M]  [S]      [S]     [M] [M]

З контролем PEC:
 1      7       1    1       8        1      8       1   1
+---+---------+----+---+------------+---+----------+---+---+
| S | Address | Rd | A |  Data Byte | A | PEC Byte | N | P |
+---+---------+----+---+------------+---+----------+---+---+
 [M]    [M]    [M]  [S]      [S]     [M]    [S]     [M] [M]
```

**Механізм та застосування:**
- Ведений віддає значення з поточного положення свого внутрішнього покажчика адреси. Застосовується в пристроях із циклічним буфером (наприклад, зчитування чергового байта з FIFO давача або аналого-цифрового перетворювача).
- **Критична відмінність у сигналах підтвердження:** Без PEC ведучий підтверджує прийом байта сигналом NACK, повідомляючи веденому про завершення читання перед сигналом STOP. При увімкненому PEC ведучий зобов'язаний виставити **ACK** після байта даних, прийняти від веденого байт PEC і лише після нього згенерувати фінальний **NACK**.

### Транзакції прямого доступу до регістрів (Byte / Word)

Усі транзакції читання та запису 16-бітних слів у специфікації SMBus строго підпорядковані порядку **Little-Endian**: молодший байт (*DataLow*) завжди передається першим, а старший байт (*DataHigh*) — другим.

#### 4. Write Byte (Запис байта в регістр)
Запис 8-бітного значення у вказаний регістр веденого пристрою.

```
Без PEC:
 1      7       1    1       8        1       8        1   1
+---+---------+----+---+------------+---+------------+---+---+
| S | Address | Wr | A |  Cmd Code  | A |  Data Byte | A | P |
+---+---------+----+---+------------+---+------------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S]     [M]      [S] [M]

З контролем PEC:
 1      7       1    1       8        1       8        1      8       1   1
+---+---------+----+---+------------+---+------------+---+----------+---+---+
| S | Address | Wr | A |  Cmd Code  | A |  Data Byte | A | PEC Byte | A | P |
+---+---------+----+---+------------+---+------------+---+----------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S]     [M]      [S]    [M]     [S] [M]
```

**Механізм та застосування:**
- Стандартний спосіб налаштування 8-бітних регістрів конфігурації: встановлення порогів спрацьовування компараторів, коефіцієнтів підсилення АЦП, масок переривань.
- Потік для розрахунку PEC включає 3 байти: `[Address + Wr]`, `[Cmd Code]` та `[Data Byte]`.

#### 5. Write Word (Запис 16-бітного слова)
Запис 16-бітного значення у вказаний регістр веденого двома послідовними байтами.

```
Без PEC:
 1      7       1    1       8        1       8        1       8        1   1
+---+---------+----+---+------------+---+------------+---+------------+---+---+
| S | Address | Wr | A |  Cmd Code  | A |  DataLow   | A |  DataHigh  | A | P |
+---+---------+----+---+------------+---+------------+---+------------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S]     [M]      [S]     [M]      [S] [M]

З контролем PEC:
 1      7       1    1       8        1       8        1       8        1      8       1   1
+---+---------+----+---+------------+---+------------+---+------------+---+----------+---+---+
| S | Address | Wr | A |  Cmd Code  | A |  DataLow   | A |  DataHigh  | A | PEC Byte | A | P |
+---+---------+----+---+------------+---+------------+---+------------+---+----------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S]     [M]      [S]     [M]      [S]    [M]     [S] [M]
```

**Механізм та застосування:**
- Застосовується для встановлення лімітів напруги та струму в блоках живлення PMBus, налаштування 16-бітних ЦАП та занесення калібрувальних коефіцієнтів у газові лічильники батарей.
- Байт `DataLow` містить біти [7:0], байт `DataHigh` — біти [15:8].

#### 6. Read Byte (Зчитування байта з регістра)
Складена двофазна транзакція: фаза запису номера регістра, повторний старт (*Repeated START*), фаза читання 8-бітного значення.

```
Без PEC:
 1      7       1    1       8        1   1      7       1    1       8        1   1
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+---+
| S | Address | Wr | A |  Cmd Code  | A | Sr| Address | Rd | A |  Data Byte | N | P |
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S] [M]   [M]     [M]  [S]     [S]      [M] [M]

З контролем PEC:
 1      7       1    1       8        1   1      7       1    1       8        1      8       1   1
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+----------+---+---+
| S | Address | Wr | A |  Cmd Code  | A | Sr| Address | Rd | A |  Data Byte | A | PEC Byte | N | P |
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+----------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S] [M]   [M]     [M]  [S]     [S]      [M]    [S]     [M] [M]
```

**Механізм та розрахунок PEC:**
- Зчитування стану статусних регістрів (наявність живлення від мережі, прапорці помилок, стан готовності даних).
- **Особливість обчислення PEC у двофазних транзакціях:** У розрахунок контрольної суми входять **всі** передані байти, включно з повторною адресою читання. Вхідний потік CRC: `[Address + Wr] → [Cmd Code] → [Address + Rd] → [Data Byte]`.

#### 7. Read Word (Зчитування 16-бітного слова)
Зчитування 16-бітного параметра (наприклад, поточної температури, напруги батареї або споживаної потужності).

```
Без PEC:
 1      7       1    1       8        1   1      7       1    1       8        1       8        1   1
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+------------+---+---+
| S | Address | Wr | A |  Cmd Code  | A | Sr| Address | Rd | A |  DataLow   | A |  DataHigh  | N | P |
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+------------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S] [M]   [M]     [M]  [S]     [S]      [M]     [S]      [M] [M]

З контролем PEC:
 1      7       1    1       8        1   1      7       1    1       8        1       8        1      8       1   1
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+------------+---+----------+---+---+
| S | Address | Wr | A |  Cmd Code  | A | Sr| Address | Rd | A |  DataLow   | A |  DataHigh  | A | PEC Byte | N | P |
+---+---------+----+---+------------+---+---+---------+----+---+------------+---+------------+---+----------+---+---+
 [M]    [M]    [M]  [S]      [M]     [S] [M]   [M]     [M]  [S]     [S]      [M]     [S]      [M]    [S]     [M] [M]
```

**Механізм та застосування:**
- Класичний протокол взаємодії з термодавачами (LM75, TMP100) та акумуляторними контролерами (BQ20z65, MAX17205).
- Ведучий обчислює 16-бітне значення за формулою `(DataHigh << 8) | DataLow`.
- Потік для розрахунку PEC: `[Address + Wr] → [Cmd Code] → [Address + Rd] → [DataLow] → [DataHigh]`.

### Складні та блокові транзакції

#### 8. Process Call (Процедурний виклик)
Атомарна операція типу «запит-відповідь» (*Remote Procedure Call*): ведучий надсилає код команди та 16 біт вхідних параметрів (DataLow + DataHigh), після чого без звільнення шини через Repeated START миттєво зчитує 16 біт обчисленого веденим результату (OutLow + OutHigh).

```
Без PEC:
 1      7       1    1     8     1     8     1     8     1   1      7       1    1     8     1     8     1   1
+---+---------+----+---+-------+---+-------+---+-------+---+---+---------+----+---+-------+---+-------+---+---+
| S | Address | Wr | A |  Cmd  | A | InLow | A | InHigh| A | Sr| Address | Rd | A | OutLow| A |OutHigh| N | P |
+---+---------+----+---+-------+---+-------+---+-------+---+---+---------+----+---+-------+---+-------+---+---+
 [M]    [M]    [M]  [S]   [M]   [S]   [M]   [S]   [M]   [S] [M]   [M]     [M]  [S]   [S]   [M]   [S]   [M] [M]

З контролем PEC:
... [Sr] [Address Rd] [A] [OutLow] [A] [OutHigh] [A] [PEC Byte] [N] [P]
```

**Механізм та застосування:**
- Використовується в ситуаціях, коли ведений пристрій повинен виконати обчислення на основі наданих ведучим аргументів: наприклад, розрахунок залишкового часу роботи акумулятора при заданому прогнозному струмі навантаження.
- Неподільність через Repeated START гарантує, що інший ведучий у багатомайстровій системі не змінить вхідні параметри між фазою запису та фазою читання.

#### 9. Block Write (Блоковий запис)
Запис блоку даних змінної довжини. Обов'язкове поле **Byte Count N** (від 1 до 32 байтів у специфікації SMBus 2.0 або до 255 байтів у SMBus 3.0) явно задає кількість наступних байтів даних.

```
Без PEC:
 1      7       1    1     8     1       8        1       8        1         8        1   1
+---+---------+----+---+-------+---+------------+---+------------+---+     +------------+---+---+
| S | Address | Wr | A |  Cmd  | A |Byte Count N| A |   Data 1   | A | ... |   Data N   | A | P |
+---+---------+----+---+-------+---+------------+---+------------+---+     +------------+---+---+
 [M]    [M]    [M]  [S]   [M]   [S]     [M]      [S]     [M]      [S]            [M]      [S] [M]

З контролем PEC:
... [Data N] [A] [PEC Byte] [A] [P]
```

**Механізм та застосування:**
- Оновлення рядкових параметрів у пам'яті пристроїв: серійного номера, імені виробника, текстової назви моделі акумулятора.
- Запис прошивки мікроконтролера або таблиць калібрування.

#### 10. Block Read (Блокове зчитування)
Ведучий надсилає код команди, після чого ведений пристрій повертає лічильник довжини `Byte Count N`, а потім передає рівно `N` байтів даних.

```
Без PEC:
 1    7     1   1    8    1  1    7     1   1       8        1       8        1         8        1   1
+--+------+---+--+------+--+--+------+---+--+------------+--+------------+--+     +------------+--+---+
| S| Addr | Wr| A|  Cmd | A|Sr| Addr | Rd| A|Byte Count N| A|   Data 1   | A| ... |   Data N   | N| P |
+--+------+---+--+------+--+--+------+---+--+------------+--+------------+--+     +------------+--+---+
 [M]  [M]   [M] [S]  [M]  [S][M]  [M]   [M] [S]     [S]     [M]     [S]     [M]           [S]     [M][M]

З контролем PEC:
... [Data N] [A] [PEC Byte] [N] [P]
```

**Механізм та застосування:**
- Зчитування інформації виробника, текстових рядків дескрипторів ACPI, масивів телеметрії (наприклад, повної карти напруг окремих комірок батареї).
- Завдяки наявності поля `Byte Count` контролер прямого доступу до пам'яті (DMA) чи драйвер ядра операційної системи може точно налаштувати розмір буфера прийому без попереднього знання специфікації конкретного веденого чипа.

#### 11. Block Write-Block Read Process Call
Комбінована транзакція, що поєднує передачу блоку вхідних даних завдовжки `M` байтів (із власним полем `Byte Count M`) та наступне зчитування блоку відповіді завдовжки `N` байтів (із полем `Byte Count N`).

```
З контролем PEC:
[S] [Addr Wr] [A] [Cmd] [A] [Count M] [A] [Data 1..M] [A] 
[Sr] [Addr Rd] [A] [Count N] [A] [Data 1..N] [A] [PEC Byte] [N] [P]
```

**Механізм та застосування:**
- Використовується в протоколах криптографічної аутентифікації акумуляторів та модулів розширення: ведучий передає блок випадкового запиту (*Challenge*), ведений виконує обчислення електронного підпису або хешу та повертає блок відповіді (*Response*).

### Системні протоколи сповіщення

#### 12. Host Notify Protocol (Протокол сповіщення хоста)
Механізм, за допомогою якого автономний ведений пристрій (наприклад, інтелектуальний зарядний пристрій або Smart Battery) сам виступає в ролі тимчасового ведучого і надсилає повідомлення про зміну свого стану на фіксовану системну адресу хоста **SMBus Host Address** (`0001 000b` = `0x08`).

```
 1        7          1    1       8        1       8        1       8        1   1
+---+--------------+----+---+------------+---+------------+---+------------+---+---+
| S | Host Addr 0x8| Wr | A | Device Addr| A |  DataLow   | A |  DataHigh  | A | P |
+---+--------------+----+---+------------+---+------------+---+------------+---+---+
 [S]      [S]       [S]  [M]     [S]      [M]     [S]      [M]     [S]      [M] [S]
```

**Параметри протоколу:**
- **Host Address:** Завжди фіксоване значення `0x08` (байт на шині `0x10` з бітом `Wr` = 0).
- **Device Address:** 7-бітна апаратна адреса пристрою-джерела сповіщення (байт містить адресу, зсунуту вліво на 1 біт).
- **DataLow / DataHigh:** 16-бітний код події (наприклад, перехід на резервне живлення, критичний рівень розряду, виявлення перегріву).
- Дозволяє системному контролеру дізнаватися про критичні події без використання постійного програмного опитування шини.

#### 13. Alert Response Protocol (Протокол відповіді на SMBALERT#)
Коли один або кілька ведених пристроїв притягують лінію асинхронного переривання SMBALERT# до нуля, хост-контролер ініціює зчитування зі спеціальної адреси **Alert Response Address (ARA)** — `0001 100b` (`0x0C` у 7-бітному форматі, байт на шині `0x19` з бітом Rd = 1).

```
 1        7         1    1       8        1   1
+---+-------------+----+---+------------+---+---+
| S | ARA (0x0C)  | Rd | A | Device Addr| N | P |
+---+-------------+----+---+------------+---+---+
 [M]      [M]      [M]  [S]     [S]      [M] [M]
```

**Порядок обробки колізій та арбітражу:**
1. Усі ведені, у яких активовано сигнал тривоги, одночасно відгукуються на адресу `0x0C` сигналом ACK.
2. На наступних 8 тактах кожен збуджений пристрій починає видавати на лінію SDA власну 7-бітну апаратну адресу.
3. Завдяки схемі відкритого стоку перемагає пристрій із **найменшим числовим значенням адреси** (оскільки нульові біти його адреси притягують лінію до нуля, перемагаючи одиничні біти суперників).
4. Переможений пристрій миттєво фіксує втрату арбітражу і вимикає свій передавач до наступного опитування ARA.
5. Переможець отримує підтвердження від хоста і відпускає лінію SMBALERT#.
6. Якщо після завершення транзакції лінія SMBALERT# залишається притягнутою до нуля, хост виконує повторне зчитування ARA, обслуговуючи наступного за пріоритетом веденого.

### Динамічна конфігурація адрес (SMBus ARP)

Специфікація SMBus 2.0 впровадила протокол **Address Resolution Protocol (ARP)** для автоматичного призначення 7-бітних адрес веденим пристроям під час завантаження системи. Це усуває конфлікти однакових мікросхем на одній шині без використання механічних перемикачів або додаткових адресних ніжок.

Кожен ARP-сумісний пристрій має заводський 128-бітний унікальний ідентифікатор **UDID** (*Unique Device Identifier*), що включає:
- 16 біт типу інтерфейсу та можливостей пристрою;
- 16 біт коду виробника (Vendor ID);
- 16 біт ідентифікатора сімейства чипів (Device ID);
- 16 біт номера ревізії кристала;
- 64 біти унікального серійного номера кристала.

Процедура призначення адрес виконується хостом за зарезервованою адресою **SMBus Device Default Address** (`1100 001b` = `0x61`):
1. **Prepare to ARP:** Хост широкомовно переводить усі неналаштовані пристрої в стан готовності до переліку.
2. **Get UDID (General):** Хост надсилає запит на зчитування 128-бітного UDID. Усі неконфігуровані ведені беруть участь у побітовому арбітражі. Пристрій із найменшим значенням UDID перемагає і передає свій повний ідентифікатор хосту.
3. **Assign Address:** Хост надсилає транзакцію призначення адреси, вказуючи зчитаний UDID та бажану нову 7-бітну адресу (наприклад, `0x34`). Переможець зберігає нову адресу, виходить зі стану переліку і більше не бере участі в арбітражі UDID.
4. Процес повторюється доти, доки на черговий запит `Get UDID` жоден ведений не виставить підтвердження ACK.

### Стандартні команди Smart Battery System (SBS 1.1)

Для ілюстрації практичного застосування набору транзакцій нижче наведено фрагмент стандартної карти регістрів акумуляторного блоку Smart Battery (`Smart Battery Data Specification 1.1`), доступного за адресою `0x0B`:

| Код команди | Назва регістра | Тип транзакції | Опис та одиниці вимірювання |
| :---: | :--- | :--- | :--- |
| `0x00` | `ManufacturerAccess` | Read / Write Word | Доступ до службових функцій та режимів калібрування |
| `0x08` | `Temperature` | Read Word | Поточна температура комірок у десятих долях Кельвіна (0.1 K) |
| `0x09` | `Voltage` | Read Word | Загальна напруга батарейного стека в мілівольтах (мВ) |
| `0x0A` | `Current` | Read Word | Миттєвий струм у міліамперах (мА, знакове 16-бітне число) |
| `0x0D` | `RelativeStateOfCharge` | Read Word | Відносний залишок заряду у відсотках (0–100%) |
| `0x10` | `FullChargeCapacity` | Read Word | Повна ємність при повному заряді в міліампер-годинах (мА·год) |
| `0x18` | `DesignCapacity` | Read Word | Паспортна номінальна ємність нової батареї (мА·год) |
| `0x20` | `ManufacturerName` | Block Read | Текстовий рядок виробника (ASCII, поле Byte Count від 1 до 11) |
| `0x21` | `DeviceName` | Block Read | Текстова назва моделі акумулятора |
| `0x22` | `DeviceChemistry` | Block Read | Хімічний тип комірок (наприклад, "LION", "NiMH", "LiP") |

### Часові обмеження та параметри фізичного рівня

Специфікації SMBus 2.0 та 3.0 висувають суворі вимоги до часових інтервалів між перепадами сигналів, які зобов'язані витримувати як хост-контролери, так і підключені мікросхеми.

| Параметр | Позначення | SMBus 2.0 (100 кГц) | SMBus 3.0 (400 кГц) | SMBus 3.0 (1 МГц) | Опис параметра |
| :--- | :--- | :---: | :---: | :---: | :--- |
| Робоча частота | `f_SMB` | 10 ... 100 кГц | 10 ... 400 кГц | 10 ... 1000 кГц | Діапазон частот тактування лінії SCL |
| Тайм-аут скидання | `t_TIMEOUT` | 25 ... 35 мс | 25 ... 35 мс | 25 ... 35 мс | Максимальний час утримання SCL у стані 0 |
| Тривалість низького SCL | `t_LOW` | ≥ 4.7 мкс | ≥ 1.3 мкс | ≥ 0.5 мкс | Мінімальна ширина низького напівперіоду |
| Тривалість високого SCL | `t_HIGH` | ≥ 4.0 мкс | ≥ 0.6 мкс | ≥ 0.26 мкс | Мінімальна ширина високого напівперіоду |
| Час встановлення даних | `t_SU:DAT` | ≥ 250 нс | ≥ 100 нс | ≥ 50 нс | Час утримання SDA до зростаючого фронту SCL |
| Час утримання даних | `t_HD:DAT` | ≥ 300 нс | ≥ 300 нс | ≥ 0 нс | Час незмінності SDA після спадного фронту SCL |
| Інтервал вільної шини | `t_BUF` | ≥ 4.7 мкс | ≥ 1.3 мкс | ≥ 0.5 мкс | Пауза між сигналом СТОП і наступним СТАРТом |
| Кумулятивне розтягнення веденого | `t_LOW:SEXT` | ≤ 25 мс | ≤ 25 мс | ≤ 25 мс | Сумарний час утримання SCL веденим за повідомлення |
| Кумулятивне розтягнення ведучого | `t_LOW:MEXT` | ≤ 10 мс | ≤ 10 мс | ≤ 10 мс | Сумарний час утримання SCL ведучим між байтами |

### Обробка помилок та стратегія повторних спроб (Retry Policy)

Надійна реалізація хост-контролера або драйвера SMBus вимагає регламентованої поведінки при виникненні апаратних збоїв:

1. **Неотримання підтвердження (NACK на адресний байт або код команди):** Свідчить про те, що ведений пристрій вимкнений, перебуває у стані внутрішнього скидання або зайнятий тривалою операцією. Хост зобов'язаний згенерувати сигнал СТОП, витримати інтервал відновлення шини `t_BUF` (не менше 4.7 мкс) і виконати до 3 повторних спроб з експоненційною затримкою.
2. **Невідповідність контрольної суми PEC:** Сигналізує про спотворення бітів під впливом імпульсних завад. Хост відкидає прийнятий буфер, реєструє подію помилки в системному журналі та повторює транзакцію. Якщо 3 спроби поспіль повертають помилку PEC, драйвер сигналізує про апаратну несправність каналу зв'язку.
3. **Спрацьовування тайм-ауту t_TIMEOUT (шина застрягла в нулі):** Якщо лінія SCL або SDA залишається низькою понад 35 мс, хост-контролер виконує апаратне скидання власного кінцевого автомата (*SMBus Host Reset*), перемикає виводи в режим GPIO і генерує послідовність із 9 тактових імпульсів SCL з фінальним сигналом STOP для примусового скидання завислих ведених автоматів.

### Програмний інтерфейс ядра Linux (Linux I2C/SMBus API)

У просторі ядра Linux та через інтерфейс пристрою `/dev/i2c-N` доступні стандартні системні виклики та структури для виконання транзакцій SMBus.

:::tabs
```c
#include <linux/i2c.h>
#include <linux/i2c-dev.h>
#include <stdint.h>

#define I2C_SMBUS_QUICK             0
#define I2C_SMBUS_BYTE              1
#define I2C_SMBUS_BYTE_DATA         2
#define I2C_SMBUS_WORD_DATA         3
#define I2C_SMBUS_PROC_CALL         4
#define I2C_SMBUS_BLOCK_DATA        5
#define I2C_SMBUS_I2C_BLOCK_DATA    8
#define I2C_SMBUS_BLOCK_PROC_CALL   9

#define I2C_SMBUS_READ  1
#define I2C_SMBUS_WRITE 0

union i2c_smbus_data {
    uint8_t  byte;
    uint16_t word;
    uint8_t  block[I2C_SMBUS_BLOCK_MAX + 2]; /* block[0] = лічильник довжини */
};

struct i2c_smbus_ioctl_data {
    uint8_t read_write;                  /* I2C_SMBUS_READ або I2C_SMBUS_WRITE */
    uint8_t command;                     /* Код команди (Command Code) */
    uint32_t size;                       /* Тип транзакції (I2C_SMBUS_*) */
    union i2c_smbus_data *data;          /* Покажчик на буфер даних */
};
```
```cpp
#include <cstdint>
#include <cstddef>
#include <array>

namespace smbus::uapi {

inline constexpr size_t BLOCK_MAX = 32;

enum class Direction : uint8_t {
    Write = 0,
    Read  = 1
};

enum class TransactionSize : uint32_t {
    Quick           = 0,
    Byte            = 1,
    ByteData        = 2,
    WordData        = 3,
    ProcCall        = 4,
    BlockData       = 5,
    I2cBlockData    = 8,
    BlockProcCall   = 9
};

union SmbusDataBuffer {
    uint8_t  byte;
    uint16_t word;
    std::array<uint8_t, BLOCK_MAX + 2> block;
};

struct SmbusIoctlArgs {
    Direction        direction{Direction::Read};
    uint8_t          command{0};
    TransactionSize  size{TransactionSize::ByteData};
    SmbusDataBuffer* data{nullptr};
};

} // namespace smbus::uapi
```

#### Стандартні функції ядра Linux для драйверів пристроїв
У драйверах ядра Linux функції-обгортки підсистеми I2C/SMBus приховують пряме керування регістрами хост-контролера:

- `s32 i2c_smbus_read_byte_data(const struct i2c_client *client, u8 command)` — виконує транзакцію Read Byte; повертає значення байта (0..255) або від'ємний код помилки (`-EIO`, `-ENXIO`, `-ETIMEDOUT`).
- `s32 i2c_smbus_write_byte_data(const struct i2c_client *client, u8 command, u8 value)` — виконує транзакцію Write Byte; повертає 0 при успіху або від'ємний код помилки.
- `s32 i2c_smbus_read_word_data(const struct i2c_client *client, u8 command)` — виконує транзакцію Read Word; повертає 16-бітне слово або від'ємний код помилки.
- `s32 i2c_smbus_write_word_data(const struct i2c_client *client, u8 command, u16 value)` — виконує транзакцію Write Word; повертає 0 при успіху.
- `s32 i2c_smbus_read_block_data(const struct i2c_client *client, u8 command, u8 *values)` — зчитує блок даних; повертає кількість прочитаних байтів `Byte Count` або від'ємний код помилки.
- `s32 i2c_smbus_process_call(const struct i2c_client *client, u8 command, u16 value)` — виконує процедурний виклик Process Call; повертає 16-бітне обчислене значення веденого.

Якщо в драйвері клієнта активовано прапорець `I2C_CLIENT_PEC`, підсистема `i2c-core` автоматично додає розрахунок та перевірку байта PEC для кожної з перелічених функцій, повертаючи помилку `-EBADMSG` при виявленні спотворення контрольної суми.
