# Команди та специфікація кадрів DShot

Керування сучасними електронними регуляторами швидкості (ESC) вимагає суворого дотримання часових інтервалів фізичного рівня, точного формування бітових масок та коректної послідовності передачі службових інструкцій. Цей довідник містить повну специфікацію часових параметрів лінійки стандартів DShot (DShot150, DShot300, DShot600, DShot1200), вимоги до електричного інтерфейсу та підтягувальних резисторів, алгоритми розрахунку контрольних сум для прямого та двостороннього режимів, вичерпну таблицю цифрових команд конфігурації регулятора, а також протокол розширеної телеметрії EDT (Extended DShot Telemetry).

## Часові параметри та стандарти швидкості DShot

Протокол DShot передає дані послідовними 16-бітними кадрами з використанням широтно-імпульсного кодування кожного окремого біта (PWM-based bit encoding). Кожен біт має суворо фіксований період `T_bit`, у межах якого логічний стан визначається тривалістю високого рівня `T_high`.

| Стандарт DShot | Бітрейт (кбіт/с) | Період біта `T_bit` | Логічний 0 (`T_0H`) | Логічна 1 (`T_1H`) | Допуск `T_high` | Тривалість кадру (16 біт) | Рекомендована частота PID |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **DShot150** | 150 кбіт/с | `6.67 мкс` | `2.50 мкс` (37.5%) | `5.00 мкс` (75.0%) | `±15%` | `106.72 мкс` | до 1 кГц |
| **DShot300** | 300 кбіт/с | `3.33 мкс` | `1.25 мкс` (37.5%) | `2.50 мкс` (75.0%) | `±15%` | `53.36 мкс` | 1–2 кГц |
| **DShot600** | 600 кбіт/с | `1.67 мкс` | `0.625 мкс` (37.5%)| `1.25 мкс` (75.0%) | `±15%` | `26.68 мкс` | 4–8 кГц |
| **DShot1200**| 1200 кбіт/с | `0.83 мкс` | `0.313 мкс` (37.5%)| `0.625 мкс` (75.0%) | `±15%` | `13.34 мкс` | 8–16 кГц |

Мінімальна міжкадрова пауза (Line Reset / Inter-frame Idle) становить не менше `20 мкс` для DShot150/300 та не менше `12 мкс` для DShot600/1200. Під час паузи лінія перебуває в стані логічного нуля (або логічної одиниці в інвертованому двосторонньому режимі), що слугує сигналом синхронізації та скидання вхідного кінцевого автомата декодера ESC.

## Електричний інтерфейс та узгодження ліній зв'язку

Фізичний рівень DShot використовує несиметричну передачу сигналів логіки CMOS із номінальною амплітудою `3.3 В` (окремі старі регулятори підтримують толерантність до `5.0 В`). 

### Односпрямований режим (Unidirectional DShot)
- Вихідний каскад польотного контролера налаштовується в двотактний режим (Push-Pull Output).
- Стан лінії за замовчуванням (Idle) — низький логічний рівень `0 В`.
- Передавач контролера примусово формує як наростаючі, так і спадні фронти з мінімальним вихідним опором драйвера піна (`R_out ≈ 25...40 Ом`).

### Двосторонній режим (Bi-directional DShot / Inverted DShot)
- Обидва пристрої (польотний контролер та регулятор ESC) підключаються до спільного провідника за схемою відкритого стоку (Open-Drain).
- Стан лінії за замовчуванням (Idle) — високий логічний рівень `3.3 В`.
- Інверсія сигналу: активний стан формується примусовим стягуванням лінії транзистором до землі (`0 В`), а пасивний стан відновлюється зовнішнім або внутрішнім підтягувальним резистором (Pull-Up Resistor).

```
R_pullup = 1.0...2.2 кОм    [рекомендований номінал зовнішнього Pull-Up для DShot600]
```

При використанні надто слабкої внутрішньої підтяжки мікроконтролера (`R_internal ≈ 30...50 кОм`) постійна часу заряду паразитної ємності кабелю (`C_cable ≈ 30...70 пФ`) становить `τ = R · C ≈ 1.5...3.5 мкс`. Це призводить до неприпустимого завалювання наростаючого фронту імпульсів у режимі DShot600, де весь період біта триває всього `1.67 мкс`. Для надійної роботи на швидкостях DShot600/1200 обов'язково встановлюють зовнішній резистор підтяжки номіналом `1 кОм` на платі польотного контролера.

## Структура 16-бітного кадру та алгоритм CRC

Кожен кадр передається старшим бітом уперед (MSB first) і складається з трьох функціональних полів:

```
[ Біт 15 .................... Біт 5 ] [ Біт 4 ] [ Біт 3 ... Біт 0 ]
  Дані газу / Команда (11 бітів)       TLM       CRC (4 біти)
```

- **Біти 15..5 (11 бітів)**: Значення газу або номер службової команди.
  - `0`: Motor Stop / Disarmed (двигун знеструмлений, активне гальмування або вільний вибіг залежно від налаштувань прошивки ESC).
  - `1...47`: Цифрові команди керування та конфігурації (DShot Commands).
  - `48...2047`: Робочий діапазон тяги (2000 градацій потужності). `48` відповідає мінімальному ненульовому газу (`0.0%`), а `2047` — максимальній тязі (`100.0%`).
- **Біт 4 (1 біт)**: Запит телеметрії (Telemetry Request, TLM). При значенні `1` регулятор зобов'язаний повернути пакет телеметрії (через окремий дріт UART або в напівдуплексній паузі Bi-directional DShot).
- **Біти 3..0 (4 біти)**: Контрольна сума (CRC / Checksum).

### Алгоритм обчислення контрольної суми кадру

Контрольна сума є 4-бітовою XOR-сумою трьох 4-бітних ніблів 12-бітного блоку `(Throttle_Data << 1) | TLM_Bit`:

```
data = (throttle_or_cmd << 1) | (tlm_bit & 0x01)
crc_normal = (data ^ (data >> 4) ^ (data >> 8)) & 0x0F
frame_normal = (data << 4) | crc_normal
```

Для стандарту **Bi-directional DShot (двосторонній DShot)** контрольна сума **інвертується**, щоб регулятор міг однозначно відрізнити запит двостороннього зв'язку від класичного односпрямованого кадру:

```
crc_bidir = (~(data ^ (data >> 4) ^ (data >> 8))) & 0x0F
frame_bidir = (data << 4) | crc_bidir
```

## Таблиця команд DShot (DShot Command Set)

Цифрові команди передаються в полі значення (біти 15..5) у діапазоні від `1` до `47`. Для захисту від випадкового спрацьовування через поодинокі збої на лінії діє обов'язкове правило протоколу:

1. Двигун повинен бути повністю зупинений (газ = `0`).
2. Команди конфігурації та зміни напрямку повинні бути відправлені **щонайменше 10 разів поспіль** (в окремих реалізаціях — не менше 6 разів) перед тим, як регулятор прийме їх до виконання.
3. Команди збереження налаштувань (`SAVE_SETTINGS`) вимагають паузи не менше `35 мс` після відправки для завершення запису у флеш-пам'ять EEPROM мікроконтролера ESC.

| Код команди | Назва макросу | Призначення та поведінка регулятора |
| :--- | :--- | :--- |
| `0` | `DSHOT_CMD_MOTOR_STOP` | Зняття тяги (Disarm), вимкнення силових ключів або активне утримання. |
| `1` | `DSHOT_CMD_BEACON1` | Звуковий сигнал мотором: тон 1 (найнижча частота). |
| `2` | `DSHOT_CMD_BEACON2` | Звуковий сигнал мотором: тон 2. |
| `3` | `DSHOT_CMD_BEACON3` | Звуковий сигнал мотором: тон 3. |
| `4` | `DSHOT_CMD_BEACON4` | Звуковий сигнал мотором: тон 4. |
| `5` | `DSHOT_CMD_BEACON5` | Звуковий сигнал мотором: тон 5 (найвища частота). |
| `6` | `DSHOT_CMD_ESC_INFO` | Запит інформаційного блоку ESC (версія прошивки, SN, тип MCU через TLM-UART). |
| `7` | `DSHOT_CMD_SPIN_DIRECTION_1` | Встановлення нормального (прямого) напрямку обертання двигуна (за годинниковою стрілкою / CW). |
| `8` | `DSHOT_CMD_SPIN_DIRECTION_2` | Встановлення реверсного напрямку обертання двигуна (проти годинникової стрілки / CCW). |
| `9` | `DSHOT_CMD_3D_MODE_OFF` | Вимкнення 3D-режиму (звичайний односпрямований діапазон 48..2047). |
| `10` | `DSHOT_CMD_3D_MODE_ON` | Увімкнення реверсивного 3D-режиму: 48..1047 — зворотний хід, 1048 — нейтраль/стоп, 1049..2047 — прямий хід. |
| `11` | `DSHOT_CMD_SETTINGS_REQUEST` | Запит поточного стану налаштувань регулятора. |
| `12` | `DSHOT_CMD_SAVE_SETTINGS` | Збереження тимчасових змін конфігурації в енергонезалежну пам'ять (Flash/EEPROM). |
| `13` | `DSHOT_CMD_EXTENDED_TELEMETRY_ENABLE` | Увімкнення розширеної телеметрії EDT (Extended DShot Telemetry) у потоці Bi-dir DShot. |
| `14` | `DSHOT_CMD_EXTENDED_TELEMETRY_DISABLE` | Вимкнення EDT (повернення до виключної передачі ERPM-пакетів). |
| `20` | `DSHOT_CMD_AUDIO_STREAM_MODE_ON_OFF` | Увімкнення/вимкнення режиму програвання мелодій через обмотки статора. |
| `21` | `DSHOT_CMD_SILENT_MODE_ON_OFF` | Увімкнення безшумного режиму комутації (пригнічення високочастотного писку ШІМ). |
| `42` | `DSHOT_CMD_SIGNAL_LINE_TELEMETRY_DISABLE` | Вимкнення передачі телеметрії через сигнальний провід. |
| `43` | `DSHOT_CMD_SIGNAL_LINE_TELEMETRY_ENABLE` | Увімкнення передачі телеметрії через сигнальний провід. |

## Специфікація розширеної телеметрії EDT (Extended DShot Telemetry)

У режимі двостороннього зв'язку (Bi-directional DShot) після отримання кадру керування регулятор надсилає у відповідь 16-бітний пакет телеметрії. Для забезпечення надійної синхронізації без окремої тактової лінії пакет кодується за стандартом GCR (Group Code Recording) 5b4b: кожні 4 біти корисних даних розгортаються в 5-бітний символ, у якому гарантовано відсутні послідовності з більш ніж двох нулів поспіль. Разом пакет відповіді містить 21 біт (4 ніблі по 5 бітів GCR + 1 завершальний фронт).

### Таблиця символів GCR (5b4b Mapping)

| Дані (4 біти Hex) | GCR Код (5 бітів Bin) | Дані (4 біти Hex) | GCR Код (5 бітів Bin) |
| :--- | :--- | :--- | :--- |
| `0x0` (`0000`) | `11001` (`0x19`) | `0x8` (`1000`) | `10010` (`0x12`) |
| `0x1` (`0001`) | `11011` (`0x1B`) | `0x9` (`1001`) | `10011` (`0x13`) |
| `0x2` (`0010`) | `10010` (`0x12`)* | `0xA` (`1010`) | `10110` (`0x16`) |
| `0x3` (`0011`) | `10011` (`0x13`)* | `0xB` (`1011`) | `10111` (`0x17`) |
| `0x4` (`0100`) | `11101` (`0x1D`) | `0xC` (`1100`) | `11010` (`0x1A`) |
| `0x5` (`0101`) | `10101` (`0x15`) | `0xD` (`1101`) | `01101` (`0x0D`) |
| `0x6` (`0110`) | `10110` (`0x16`)* | `0xE` (`1110`) | `01110` (`0x0E`) |
| `0x7` (`0111`) | `10111` (`0x17`)* | `0xF` (`1111`) | `01111` (`0x0F`) |

*(Примітка: Стандартний набір GCR гарантує достатню щільність логічних переходів `0 ↔ 1` для надійного відновлення тактового сигналу таймерним захопленням на стороні польотного контролера).*

### Структура 16-бітного пакета відповіді телеметрії

Після GCR-декодування 16-бітний потік містить 12 бітів корисного значення та 4 біти контрольної суми:

```
[ Біт 15 .................... Біт 4 ] [ Біт 3 ... Біт 0 ]
        Телеметричні дані (12 бітів)      CRC (4 біти)
```

Контрольна сума відповіді обчислюється як:

```
telemetry_crc = (~(data ^ (data >> 4) ^ (data >> 8))) & 0x0F
```

### Формат звичайного ERPM-пакета

Якщо режим EDT вимкнено, 12-бітне поле даних кодує період між комутаціями двигуна у форматі «мантиса зі зсувом» (Shifted Period Format):

- **Біти 15..13 (3 біти)**: Експонента зсуву (порядок `E`, значення `0...7`).
- **Біти 12..4 (9 бітів)**: Мантиса періоду (`M`, значення `0...511`).

Обчислення електричного періоду комутації `T_comm` у мікросекундах:

```
T_comm = (M << E) [мкс]
```

Розрахунок частоти обертання електричного поля (ERPM, Electrical Revolutions Per Minute) та механічних обертів ротора (RPM):

```
ERPM = 60000000 / (T_comm · 6) = 10000000 / T_comm
RPM = ERPM / (Кількість_пар_полюсів_ротора)
```

### Формат розширених кадрів EDT (Extended DShot Telemetry)

При активації EDT (`DSHOT_CMD_EXTENDED_TELEMETRY_ENABLE`) регулятор передає пакети телеметрії чергуванням. Біти 15..12 визначають тип телеметричного кадру:

| Тип кадру (Біти 15..12) | Назва параметра | Формат корисного навантаження (Біти 11..4) | Одиниці вимірювання |
| :--- | :--- | :--- | :--- |
| `0x0` | `EDT_TEMPERATURE` | Пряме ціле 8-бітне значення | Градуси Цельсія (`°C`) |
| `0x1` | `EDT_VOLTAGE` | Напруга силової шини: `U = Value · 0.01 В` | Вольти (`0.00...2.55 В` або шкала з дільником) |
| `0x2` | `EDT_CURRENT` | Струм споживання: `I = Value · 0.1 А` | Ампери (`0.0...25.5 А` або з множником) |
| `0x3` | `EDT_DEBUG1` | Лічильник збоїв комутації (Desync Counter) | Кількість помилок |
| `0x4` | `EDT_DEBUG2` | Спеціальні діагностичні прапорці статусу | Бітова маска помилок FET / драйвера |
| `0x8...0xF` | `EDT_ERPM` | Стандартний період ERPM (мантиса + зсув) | Частота обертання |

## Діагностика сигналу та типові несправності шини

При налагодженні зв'язку за допомогою логічного аналізатора або цифрового осцилографа стан інтерфейсу DShot оцінюють за такими критеріями:

1. **Контроль тривалості бітових інтервалів**:
   У режимі DShot600 тривалість високого стану логічного нуля повинна строго укладатися в межі `530...720 нс`, а логічної одиниці — в межі `1060...1440 нс`. Відхилення понад `±15%` свідчить про неправильний подільник частоти таймера або надмірну паразитну ємність лінії.
2. **Падіння амплітуди на заземленні (Ground Offset)**:
   При різкому збільшенні навантаження на мотори (Punch Out) рівень логічного нуля на вході ESC не повинен підніматися вище `0.6 В`. Перевищення цього значення вказує на тонкий земляний провід або відсутність витого шлейфа між польотним контролером та регулятором.
3. **Лічильник помилок CRC (CRC Error Rate)**:
   У справній системі частота помилок контрольної суми не повинна перевищувати `0.01%` (не більше 1 пошкодженого пакета на 10 000 успішних транзакцій). Зростання частки помилок понад `1%` свідчить про наведення від силових фазних дротів або занадто пологий фронт повернення лінії через слабкий підтягувальний резистор.
