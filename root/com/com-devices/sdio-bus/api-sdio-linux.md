# 📋 Референс протоколу команд SDIO та API драйверів ядра Linux

Специфікація SDIO (Secure Digital Input/Output) визначає дворівневу модель інтерфейсу: апаратний протокол передачі командних і даних кадрів через фізичні лінії шини та уніфікований програмний інтерфейс драйверів операційної системи. Кожен рівень має суворий контракт поведінки, часових затримок, форматів кадрів та правил обробки виняткових ситуацій. Нижче наведено вичерпний технічний опис бітових полів команд керування, структури системних регістрів CIA (Common Information Area) та функцій підсистеми SDIO ядра Linux.

---

## 1. Структура протокольних команд SDIO

Усі командні транзакції передаються по спільній двонаправленій сигнальній лінії CMD у формі фіксованих 48-бітних послідовностей. Передача кожного біта синхронізується за наростаючим фронтом тактового сигналу CLK. Кожна команда супроводжується обов'язковим обчисленням 7-бітної контрольної суми циклічного надлишкового коду (CRC7), що виключає хибне спрацьовування апаратних тригерів через електромагнітні завади.

```
Послідовність бітів на лінії CMD (48 бітів):
 47 46 45            40 39                                                8 7      1 0
+--+--+----------------+---------------------------------------------------+--------+--+
|S |T | Command Index  |                 Argument Field                    |  CRC7  |E |
|0 |1 | 6 бітів (індекс|                    32 біти                        | 7 бітів|1 |
+--+--+----------------+---------------------------------------------------+--------+--+
```

### Команда прямого доступу до регістрів (CMD52: IO_RW_DIRECT)

Команда `CMD52` розроблена для надшвидкого атомарного доступу до окремих 1-байтових регістрів керування. Головна інженерна перевага цієї команди полягає в тому, що транзакція виконується виключно через сигнальну лінію CMD і не займає шину даних DAT[0..3]. Це дозволяє ядру операційної системи опитувати статуси та квітувати переривання навіть тоді, коли на лініях даних триває очікування готовності периферійного буфера.

```
+---+---+--------+---+-----+-----+-------+-------------------+----------------+--------+---+
| S | T | Index  |R/W|Func | RAW | Stuff | Register Address  |   Write Data   |  CRC7  | E |
| 1 | 1 | 6 біт  | 1 |3 біт|  1  | 1 біт |      17 бітів     |     8 бітів    | 7 бітів| 1 |
+---+---+--------+---+-----+-----+-------+-------------------+----------------+--------+---+
 47  46  45    40  39 38 36  35    34     33               17 16             9  8     2  1  0
```

#### Детальний аналіз полів аргументу CMD52

1. **Start Bit (S, біт 47) та Transmission Bit (T, біт 46):** комбінація `01b` позначає початок кадру, переданого хостом. Зміна рівня з високого (High-Z із зовнішньою підтяжкою) на низький слугує фронтом запуску апаратного автомата прийому команди в периферійному контролері.
2. **Command Index (біти 45:40):** шестибітний код команди, що містить значення `110100b` (десяткове 52).
3. **R/W Flag (біт 39):** прапорець напрямку обміну. Значення `0` ініціює операцію читання (Read), а значення `1` — операцію запису (Write).
4. **Function Number (біти 38:36):** трибітна адреса цільової логічної функції. Значення `000b` відкриває доступ до службової зони CIA/CCCR (Функція 0). Значення від `001b` до `111b` адресують відповідні користувацькі функції (Функції 1..7). Звернення до номера функції, яка не оголошена в регістрі готовності `IO_READY`, негайно призводить до виставлення прапорця помилки `FUNCTION_NUMBER_ERROR` у відповіді пристрою.
5. **RAW Flag (Read After Write, біт 35):** прапорець модифікації зчитування. Під час операції запису (`R/W=1`):
   - Якщо `RAW = 0`, пристрій повертає у відповіді попередній стан адресованого регістру (значення, яке було записане до поточної транзакції).
   - Якщо `RAW = 1`, внутрішня логіка периферії спочатку фіксує новий байт у тригерах пам'яті регістру, а потім повертає це оновлене значення у полі даних відповіді. Це дозволяє реалізувати атомарну перевірку фактичного запису керуючого біта без виконання додаткової команди читання. При операції читання (`R/W=0`) біт RAW ігнорується та заповнюється нулем.
6. **Stuff Bit (біт 34):** зарезервований біт заповнення, який завжди встановлюється в логічний `0` для збереження вирівнювання адресного поля.
7. **Register Address (біти 33:17):** 17-бітне поле адреси регістру у просторі вибраної функції. Діапазон адрес становить від `0x00000` до `0x1FFFF` (рівно 131 072 байти, тобто 128 кілобайтів на кожну функцію).
8. **Write Data (біти 16:9):** вісім бітів корисних даних, які записуються в регістр. Якщо виконується операція читання (`R/W=0`), це поле не несе змістовного навантаження і заповнюється нулями (`0x00`).
9. **CRC7 (біти 8:2):** контрольна сума, що обчислюється за стандартизованим поліномом `G(x) = x⁷ + x³ + 1` над першими 40 бітами кадру. Помилка контрольної суми призводить до відкидання команди пристроєм без формування відповіді, що викликає спрацьовування тайм-ауту очікування команди (Command Timeout) на стороні хоста.
10. **End Bit (E, біт 0):** стоповий біт, який завжди дорівнює логічній `1`.

#### Формат та обробка відповіді R5 (IO_RW_DIRECT Response)

У відповідь на команду `CMD52` периферійний пристрій зобов'язаний надіслати 48-бітний кадр відповіді типу R5 через інтервал від 2 до 8 тактів (Ncr, Command Response Delay):

```
+---+---+--------+----------------+----------------+--------+---+
| S | T | Index  | Response Flags |   Read Data    |  CRC7  | E |
| 1 | 1 | 6 біт  |    8 бітів     |    8 бітів     | 7 бітів| 1 |
+---+---+--------+----------------+----------------+--------+---+
 47  46  45    40 39            32 31            24 23    17  0
```

Поле прапорців стану **Response Flags (біти 39:32)** містить діагностичну інформацію про результат транзакції:

- **Біт 39 (`COM_CRC_ERROR`):** сигналізує про помилку контрольної суми команди, отриманої пристроєм.
- **Біт 38 (`ILLEGAL_COMMAND`):** свідчить про те, що хост надіслав заборонену команду або звернувся до функції у стані, де операції вводу-виводу вимкнені.
- **Біти 37:36 (`IO_CURRENT_STATE`):** показують поточний робочий стан вбудованого автомата станів SDIO: `00b` — вимкнено (DIS, Disabled), `01b` — очікування команди (CMD), `10b` — передача даних (TRN, Transfer), `11b` — зарезервовано.
- **Біт 35 (`ERROR`):** загальний апаратний збій периферійного вузла.
- **Біт 33 (`FUNCTION_NUMBER_ERROR`):** спроба звернення до неіснуючого або вимкненого номера функції (наприклад, звернення до Функції 3 у пристрої, що підтримує лише Функції 1 та 2).
- **Біт 32 (`OUT_OF_RANGE`):** адреса регістру вийшла за межі фізично реалізованого адресного простору функції.
- **Read Data (біти 31:24):** вісім бітів даних, прочитаних з адресованого регістру (або підтверджене значення при `RAW=1`).

### Команда розширеного доступу (CMD53: IO_RW_EXTENDED)

Команда `CMD53` відкриває високошвидкісний пакетний або блоковий обмін даними. Сама команда налаштовує параметри сесії на лінії CMD, після чого безпосередня передача масиву байтів відбувається по лініях даних DAT[0..3] (або по одній лінії DAT0 в 1-бітному режимі).

```
+---+---+--------+---+-----+-----+---+-------------------+----------------+--------+---+
| S | T | Index  |R/W|Func |Block|Inc| Register Address  |   Byte/Block   |  CRC7  | E |
| 1 | 1 | 6 біт  | 1 |3 біт|  1  | 1 |      17 бітів     |     9 бітів    | 7 бітів| 1 |
+---+---+--------+---+-----+-----+---+-------------------+----------------+--------+---+
 47  46  45    40  39 38 36  35   34  33               17 16             8  7     1  0
```

#### Детальний аналіз полів аргументу CMD53

- **R/W Flag (біт 39):** `0` — читання даних із пристрою до пам'яті хоста; `1` — запис даних із пам'яті хоста до буфера пристрою.
- **Function Number (біти 38:36):** номер цільової функції (`0`..`7`).
- **Block Mode Flag (біт 35):** селектор одиниці вимірювання обсягу передачі:
  - `Block Mode = 0 (Byte Mode):` передача здійснюється у байтах. Поле `Byte/Block Count` вказує точну кількість байтів від 1 до 512 (значення `000000000b` кодує рівно 512 байтів). Байтовий режим оптимізований для коротких повідомлень керування, дескрипторів та заголовків пакетів, які не кратні розміру сектора.
  - `Block Mode = 1 (Block Mode):` передача ведеться цілими блоками фіксованого розміру. Поле `Byte/Block Count` задає кількість блоків від 1 до 511. Розмір одного блока попередньо програмується у регістрах FBR відповідної функції (наприклад, 512, 1024 або 2048 байтів).
- **Op Code / Address Increment (біт 34):** режим керування покажчиком адреси:
  - `Op Code = 0 (Fixed Address / FIFO Mode):` операція виконується за фіксованою адресою. Внутрішній покажчик адреси пристрою не змінюється після передачі кожного байта. Усі зчитані або записані байти спрямовуються в один і той самий апаратний регістр FIFO (наприклад, вікно приймання мережевих пакетів Wi-Fi).
  - `Op Code = 1 (Incrementing Address Mode):` апаратний автоінкремент адреси. Після передачі кожного байта внутрішній покажчик збільшується на одиницю. Це дозволяє за одну транзакцію зчитати чи прошити суцільний масив внутрішньої оперативної пам'яті (SRAM) або таблицю конфігураційних регістрів пристрою.
- **Register Address (біти 33:17):** 17-бітна початкова адреса цільового регістру або порту FIFO.
- **Byte/Block Count (біти 16:8):** 9-бітний лічильник обсягу передачі. У блоковому режимі значення `0` є зарезервованим і неприпустимим; допустимий діапазон становить від `1` до `511` блоків за одну команду.

#### Структура пакета даних на лініях DAT[0..3]

Після успішного обміну командою `CMD53` та отримання відповіді R5 починається фаза передачі даних. Кожен блок даних обрамляється власними контрольними бітами:

1. **Start Bit:** низький рівень `0` на всіх активних лініях даних.
2. **Data Payload:** корисні байти даних. У 4-бітному режимі старший напівбайт (біти 7:4) передається першим за тактом `CLK`, молодший (біти 3:0) — за наступним тактом.
3. **CRC16 per Line:** для кожної з чотирьох сигнальних ліній DAT0, DAT1, DAT2, DAT3 незалежно обчислюється 16-бітна контрольна сума за поліномом `G(x) = x¹⁶ + x¹² + x⁵ + 1`. Це гарантує локалізацію апаратних збоїв та перешкод на конкретній друкованій доріжці.
4. **End Bit:** високий рівень `1` на всіх лініях даних.
5. **Data Response Token (при записі):** після завершення передачі блока пристрій надсилає по лінії DAT0 3-бітний токен квітування: `010b` — дані прийнято успішно без помилок CRC; `101b` — виявлено помилку контрольної суми CRC16; `110b` — помилка запису у внутрішній буфер.
6. **Busy Signal:** пристрій утримує лінію DAT0 на низькому рівні (GND) доки триває фізичний запис даних із внутрішнього буфера в робочу пам'ять.

### Команда опитування робочих умов (CMD5: IO_SEND_OP_COND)

Команда `CMD5` є першим етапом процедури виявлення (Enumeration) периферійних модулів SDIO. На відміну від карт пам'яті, де використовується команда `ACMD41`, хост зобов'язаний надіслати `CMD5` безпосередньо після скидання шини командою `CMD0`.

- **Аргумент команди (32 біти):** хост передає бітову маску підтримуваних ним діапазонів напруги живлення (I/O OCR, Operating Conditions Register). Наприклад, біти 23:15 задають діапазон 2.7–3.6 В, а біт 24 сигналізує про підтримку перемикання на низьковольтний режим 1.8 В (UHS-I). Якщо хост бажає лише опитати можливості карти без встановлення робочого режиму, він передає нульовий аргумент `0x00000000`.
- **Формат відповіді R4 (32 біти аргументу):**
  - **Біт 31 (`C` / I/O Ready):** прапорець завершення внутрішньої ініціалізації живлення периферії. Якщо біт дорівнює `0`, хост зобов'язаний повторювати виклик `CMD5` у циклі опитування до отримання одиниці.
  - **Біти 30:28 (`Number of I/O Functions`):** загальна кількість підтримуваних пристроєм користувацьких функцій (від `001b` = одна функція до `111b` = сім функцій).
  - **Біт 27 (`Memory Present`):** сигналізує про наявність логіки SD Memory на тому самому фізичному модулі (Combo Card).
  - **Біти 23:0 (`I/O Voltage Profile`):** бітова маска діапазонів напруг, за яких модуль гарантує стабільну роботу.

## 2. Карта регістрів керування CIA (Function 0)

Простір Function 0 є обов'язковим для кожного SDIO-пристрою і містить загальну інформаційну зону **CIA (Common Information Area)**. Структурно цей простір поділено на три логічні секції:

```
0x00000 ┌────────────────────────────────────────────────────────┐
        │ CCCR (Card Common Control Registers): адреси 0x00..0x13│
0x000FF ├────────────────────────────────────────────────────────┤
        │ FBR (Function Basic Registers): 7 блоків по 256 байтів │
        │  - 0x00100..0x001FF: Регістри FBR для Функції 1        │
        │  - 0x00200..0x002FF: Регістри FBR для Функції 2        │
        │  - ...                                                 │
        │  - 0x00700..0x007FF: Регістри FBR для Функції 7        │
0x007FF ├────────────────────────────────────────────────────────┤
        │ CIS (Card Information Structure): адреси 0x0800..0x1FFFF│
        │ Послідовний ланцюжок кортежів характеристик (Tuples)   │
0x1FFFF └────────────────────────────────────────────────────────┘
```

### Регістри CCCR (Card Common Control Registers)

Регістри CCCR розташовані за базовими адресами `0x00000`–`0x00013` і забезпечують керування параметрами шини, розподілом переривань та станами живлення.

| Адреса | Назва регістру | Біти | Поля та функціональне призначення |
| :--- | :--- | :--- | :--- |
| **0x00** | `CCCR / SDIO Revision` | 7:4<br>3:0 | `SDIO_REV[3:0]`: код ревізії SDIO (`0x0` = 1.00, `0x1` = 1.10, `0x2` = 2.00, `0x3` = 3.00 UHS-I).<br>`CCCR_REV[3:0]`: версія структури CCCR (`0x0` = 1.00, `0x1` = 1.10, `0x2` = 2.00). |
| **0x01** | `SD Specification Version` | 3:0 | `SD_SPEC[3:0]`: базова фізична специфікація SD (`0` = 1.01, `1` = 1.10, `2` = 2.00, `3` = 3.00). |
| **0x02** | `IO_ENABLE (IOE)` | 7:1 | `IOE[7:1]`: маска активації функцій. Запис `1` у біт `n` подає живлення на логіку Функції `n` та виводить її з режиму глибокого сну. |
| **0x03** | `IO_READY (IOR)` | 7:1 | `IOR[7:1]`: маска готовності функцій (тільки читання). `1` у біті `n` свідчить про те, що внутрішні тактові генератори, PLL та пам'ять Функції `n` стабілізовані й готові до обміну через `CMD53`. |
| **0x04** | `INT_ENABLE (IEN)` | 7:1<br>0 | `IEN[7:1]`: бітова маска дозволу переривань для кожної окремої функції.<br>`IENM` (Master Interrupt Enable): глобальний дозвіл генерації внутрішньосмугового сигналу переривання на лінію DAT1. |
| **0x05** | `INT_PENDING (INTP)`| 7:1 | `INT[7:1]`: бітова маска очікуючих запитів на переривання (тільки читання). `1` у біті `n` означає, що джерело переривання всередині Функції `n` активне і потребує обслуговування драйвером. |
| **0x06** | `IO_ABORT / RESET` | 3<br>2:0 | `RES` (Software Reset): запис `1` ініціює повне програмне скидання всіх регістрів пристрою до заводських значень за замовчуванням.<br>`AS[2:0]`: негайне аварійне переривання поточної операції передачі `CMD53` для функції, вказаної цим номером. |
| **0x07** | `BUS_IF_CTRL` | 7<br>1:0 | `CD_DISABLE`: встановлення в `1` відключає внутрішній підтягуючий резистор 50 кОм на лінії DAT3 (Card Detect), щоб уникнути витоку струму під час високошвидкісної роботи.<br>`BUS_WIDTH[1:0]`: керування розрядністю шини (`00b` = 1-бітний режим через DAT0; `10b` = 4-бітний режим через DAT[0..3]). |

### Регістри базової конфігурації функцій (FBR, Function Basic Registers)

Для кожної з семи можливих функцій виділено стандартизований блок регістрів розміром 256 байтів. Базова адреса блоку FBR для функції `n` обчислюється за формулою:

```
Address_FBR(n) = 0x00100 · n
```

- **Адреса `0x00n00` (Standard SDIO Function Interface Code):**
  - Біти 3:0 (`STD_IF[3:0]`): визначають стандартизований тип периферійного модуля. Якщо пристрій реалізує стандартний клас (наприклад, `0x1` — UART, `0x2` — Bluetooth Type-A, `0x7` — Wi-Fi 802.11), операційна система може завантажити універсальний системний драйвер класу без звернення до специфічних драйверів виробника. Значення `0x0` вказує на нестандартний інтерфейс виробника (Vendor Specific).
  - Біт 6 (`CSA_SUP`): прапорець наявності області зберігання коду (Code Storage Area), яка дозволяє завантажувати мікропрограму (firmware) через виділене вікно регістрів FBR.
  - Біт 7 (`CSA_EN`): дозвіл доступу до області CSA.
- **Адреси `0x00n09:0x00n0B` (Function CIS Pointer):** 24-бітний вказівник на початок ланцюжка кортежів CIS, специфічних для даної Функції `n`.
- **Адреси `0x00n10:0x00n11` (Function Block Size):** 16-бітний регістр розміру блока (Block Size). За замовчуванням після скидання містить значення 0 (що вимагає обов'язкового налаштування хостом перед переходом у блоковий режим `CMD53`). Для мережевих адаптерів Wi-Fi сюди зазвичай записують значення `512` або `1536` байтів (для оптимізації під розмір кадру Ethernet MTU).

## 3. Ланцюжок кортежів CIS (Card Information Structure)

Структура CIS побудована у вигляді послідовного ланцюжка інформаційних блоків — кортежів (Tuples), успадкованих від стандарту PCMCIA. Кожен кортеж містить однобайтний ідентифікатор типу, однобайтний лічильник довжини тіла та саме тіло даних:

```
+--------------------+---------------------+-----------------------------------+
| Tuple Code (1 байт)| Tuple Link (1 байт) |       Tuple Data (N байтів)       |
+--------------------+---------------------+-----------------------------------+
```

1. **`CISTPL_NULL` (код `0x00`):** порожній байт заповнення, який ігнорується парсером ядра Linux.
2. **`CISTPL_MANFID` (код `0x20`, довжина 4 байти):** найважливіший кортеж ідентифікації обладнання. Містить 16-бітний код виробника (Manufacturer ID / Vendor ID) та 16-бітний код моделі пристрою (Part Number / Device ID). Саме на основі цих значень підсистема `udev` та ядро Linux підбирають відповідний модуль драйвера (наприклад, `vendor = 0x02d0, device = 0xa9a6` для бездротового чипа Broadcom BCM43438).
3. **`CISTPL_FUNCID` (код `0x21`, довжина 2 байти):** описує клас пристрою та сумісність із системними інтерфейсами живлення.
4. **`CISTPL_FUNCE` (код `0x22`, змінна довжина):** розширені параметри функціонування. Визначає максимальну пропускну здатність, піковий струм споживання, час виходу з режиму сну (Wakeup Time) та максимальний підтримуваний розмір блока даних.
5. **`CISTPL_END` (код `0xFF`):** термінальний кортеж, що позначає кінець інформаційного ланцюжка.

## 4. Програмний інтерфейс ядра Linux (Linux Kernel SDIO API)

У ядрі Linux взаємодія з SDIO-периферією побудована за трирівневою моделлю: драйвер хост-контролера (Host Driver, наприклад `sdhci.c`) реалізує фізичні транзакції, ядро підсистеми MMC (`drivers/mmc/core/`) координує блокування та черги, а функціональний клієнтський драйвер (Client Driver, наприклад `brcmfmac` чи `mwifiex`) реалізує бізнес-логіку пристрою.

```
                  ┌────────────────────────────────────────┐
                  │ Функціональний драйвер (Client Driver) │
                  │     (brcmfmac / mwifiex / btmtksdio)   │
                  └───────────────────┬────────────────────┘
                                      │
                                      ▼  API виклики ядра
                  ┌────────────────────────────────────────┐
                  │       Ядро підсистеми MMC / SDIO       │
                  │   sdio_bus.c / sdio_io.c / sdio_irq.c  │
                  └───────────────────┬────────────────────┘
                                      │
                                      ▼  struct mmc_host_ops
                  ┌────────────────────────────────────────┐
                  │       Драйвер хост-контролера          │
                  │        (sdhci.c / dw_mmc.c)            │
                  └────────────────────────────────────────┘
```

### Основні структури даних

Клієнтський драйвер описує таблицю сумісних ідентифікаторів за допомогою масиву структур `struct sdio_device_id` та реєструє інтерфейс через `struct sdio_driver`:

```c
#include <linux/mmc/sdio_func.h>
#include <linux/mmc/sdio_ids.h>

static const struct sdio_device_id my_sdio_ids[] = {
    { SDIO_DEVICE(0x02d0, 0xa9a6) }, /* Broadcom BCM43438 Wi-Fi */
    { SDIO_DEVICE_CLASS(SDIO_CLASS_WLAN) }, /* Будь-який стандартний Wi-Fi */
    { /* кінець таблиці */ }
};
MODULE_DEVICE_TABLE(sdio, my_sdio_ids);

static struct sdio_driver my_sdio_driver = {
    .name     = "my_sdio_wlan",
    .id_table = my_sdio_ids,
    .probe    = my_sdio_probe,
    .remove   = my_sdio_remove,
    .drv = {
        .owner = THIS_MODULE,
    },
};
```

### Детальний опис функцій підсистеми SDIO в ядрі Linux

#### 1. Синхронізація та захоплення контролера

- **`void sdio_claim_host(struct sdio_func *func);`**
  - **Призначення:** ексклюзивне захоплення м'ютекса хост-контролера шини.
  - **Механізм:** оскільки одна фізична шина SDIO може обслуговувати до 7 незалежних функцій одночасно (а також потік обробки внутрішньосмугових переривань `sdio_irq_thread`), будь-який обмін командами `CMD52` або `CMD53` категорично заборонено починати без попереднього захоплення блокування хоста. Функція переводить викликаючий процес у стан очікування, якщо шина зайнята іншою операцією.
  - **Контекст виклику:** виключно сплячий контекст (Process Context / Threaded IRQ). Заборонено викликати з апаратних обробників переривань (Hard IRQ) або під час утримання спінлоків (`spinlock_t`).

- **`void sdio_release_host(struct sdio_func *func);`**
  - **Призначення:** звільнення ексклюзивного блокування хост-контролера. Повинна викликатися негайно після завершення серії транзакцій для запобігання голодуванню інших функцій шини та потоку переривань.

---

#### 2. Керування станом живлення та налаштуванням функцій

- **`int sdio_enable_func(struct sdio_func *func);`**
  - **Призначення:** програмна активація функції на пристрої.
  - **Механізм:** функція атомарно зчитує регістр `IO_ENABLE` (CCCR 0x02), встановлює біт, що відповідає `func->num`, і записує оновлену маску назад через команду `CMD52`. Після цього функція переходить у цикл опитування регістру `IO_READY` (CCCR 0x03) з експоненційною затримкою доти, доки пристрій не підтвердить готовність відповідним бітом (або до спрацьовування тайм-ауту).
  - **Повертає:** `0` у разі успіху або від'ємний код системної помилки (наприклад `-ETIMEDOUT`, `-EIO`).

- **`int sdio_disable_func(struct sdio_func *func);`**
  - **Призначення:** деактивація функції для заощадження електроенергії. Скидає біт у регістрі `IO_ENABLE`.

- **`int sdio_set_block_size(struct sdio_func *func, unsigned blksz);`**
  - **Призначення:** встановлення розміру блока для пакетних передач `CMD53` у блоковому режимі.
  - **Механізм:** виконує запис молодшого та старшого байтів значення `blksz` у регістри FBR функції (`0x00n10` та `0x00n11`) через дві послідовні команди `CMD52`. Одночасно оновлює внутрішнє поле `func->cur_blksize` у структурі ядра, яке використовується підсистемою DMA для розрахунку дескрипторів передачі.

---

#### 3. Реєстрація та обробка переривань

- **`int sdio_claim_irq(struct sdio_func *func, sdio_irq_handler_t *handler);`**
  - **Призначення:** реєстрація функції зворотного виклику (Callback Handler) для обробки переривань від даної логічної функції.
  - **Механізм:** реєструє покажчик `handler` у структурі `func`, після чого модифікує регістр `INT_ENABLE` (CCCR 0x04), виставляючи біт дозволу переривання даної функції та глобальний біт `IENM`. Якщо це перше активоване переривання на шині, ядро запускає спеціальний системний потік `sdio_irq_thread` (або вмикає апаратне детектування спаду на лінії DAT1 у хост-контролері).
  - **Увага:** обробник `handler(struct sdio_func *func)` виконується у контексті потоку ядра з **вже захопленим** блокуванням хоста (`sdio_claim_host` викликано ядром заздалегідь). Тому всередині обробника заборонено повторно викликати `sdio_claim_host()` або `sdio_release_host()`.

- **`int sdio_release_irq(struct sdio_func *func);`**
  - **Призначення:** зняття обробника переривання та маскування біта у регістрі `INT_ENABLE` (CCCR 0x04).

---

#### 4. Функції прямого читання та запису регістрів (CMD52 Wrappers)

- **`u8 sdio_readb(struct sdio_func *func, unsigned int addr, int *err_ret);`**
  - Зчитує 1 байт з адреси `addr` простору функції `func->num`. Якщо передано ненульовий покажчик `err_ret`, у нього записується `0` або код помилки зв'язку.

- **`void sdio_writeb(struct sdio_func *func, u8 b, unsigned int addr, int *err_ret);`**
  - Записує байт `b` за адресою `addr`.

- **`u16 sdio_readw(struct sdio_func *func, unsigned int addr, int *err_ret);`**
  - Зчитує 16-бітне слово (два послідовні виклики `CMD52` або оптимізована транзакція `CMD53`).

- **`void sdio_writew(struct sdio_func *func, u16 b, unsigned int addr, int *err_ret);`**
  - Записує 16-бітне слово.

- **`u32 sdio_readl(struct sdio_func *func, unsigned int addr, int *err_ret);`**
  - Зчитує 32-бітне подвійне слово.

- **`void sdio_writel(struct sdio_func *func, u32 b, unsigned int addr, int *err_ret);`**
  - Записує 32-бітне подвійне слово.

---

#### 5. Функції пакетного та блокового обміну (CMD53 Wrappers)

- **`int sdio_memcpy_fromio(struct sdio_func *func, void *dst, unsigned int addr, int count);`**
  - **Призначення:** читання суцільного масиву пам'яті розміром `count` байтів із пристрою за адресою `addr` у буфер ядра `dst`.
  - **Механізм:** автоматично обирає між байтовим та блоковим режимами `CMD53` залежно від величини `count` та налаштованого `func->cur_blksize`. Прапорець автоінкременту адреси встановлюється в `Op Code = 1`.

- **`int sdio_memcpy_toio(struct sdio_func *func, unsigned int addr, void *src, int count);`**
  - **Призначення:** запис суцільного масиву пам'яті розміром `count` байтів із системного буфера `src` у простір пристрою за адресою `addr` (`Op Code = 1`).

- **`int sdio_readsb(struct sdio_func *func, void *dst, unsigned int addr, int count);`**
  - **Призначення:** потокове читання `count` байтів із фіксованого регістра FIFO за адресою `addr` (`Op Code = 0`). Покажчик адреси пристрою залишається незмінним під час усієї транзакції.

- **`int sdio_writesb(struct sdio_func *func, unsigned int addr, void *src, int count);`**
  - **Призначення:** потоковий запис `count` байтів у фіксований FIFO-порт `addr` (`Op Code = 0`). Основна функція для скидання вихідних мережевих пакетів у бездротовий передавач.
