# 🧮 Розрахунок деградації пропускної здатності та часових бюджетів SMBus

Ця вставка містить строге математичне виведення зміни частоти тактової лінії SCL, кількісну оцінку падіння корисної пропускної здатності шини I2C при виникненні затримок розтягування такту (*clock stretching*), розрахунок граничних опорів резисторів підтяжки та часових бюджетів таймаутів для специфікацій I2C та SMBus.

---

### 1. Фізична модель тактового циклу I2C та експоненційні фронти

Тактовий сигнал на лінії SCL формується взаємодією активних польових транзисторів із відкритим стоком (*open-drain*) або відкритим колектором та пасивного зовнішнього резистора підтяжки `R_p`. Повний період тактового сигналу `T_SCL` без розтягування складається з чотирьох часових інтервалів:

```
T_SCL = T_HIGH + T_LOW + t_r + t_f
```

де:
- `T_HIGH` — тривалість утримання лінії у високому логічному рівні внутрішнім таймером ведучого пристрою;
- `T_LOW` — тривалість активного утримання лінії в низькому логічному рівні внутрішнім транзистором ведучого;
- `t_r` — час наростання напруги (*rise time*) від порогового рівня `V_IL = 0.3 · V_DD` до `V_IH = 0.7 · V_DD`;
- `t_f` — час спаду напруги (*fall time*) від `V_IH = 0.7 · V_DD` до `V_IL = 0.3 · V_DD`.

Наростаючий фронт визначається процесом заряду сумарної паразитної ємності шини `C_b` (ємність провідників друкованої плати, виводів мікросхем та роз'ємів) через резистор `R_p`:

```
V(t) = V_DD · (1 - e^(-t / (R_p · C_b)))
```

Знайдемо моменти часу `t_1` та `t_2`, коли напруга досягає стандартизованих порогових значень логічного нуля `0.3 · V_DD` та логічної одиниці `0.7 · V_DD`:

```
0.3 · V_DD = V_DD · (1 - e^(-t_1 / (R_p · C_b)))
e^(-t_1 / (R_p · C_b)) = 0.7
-t_1 / (R_p · C_b) = ln(0.7)
t_1 = -R_p · C_b · ln(0.7) ≈ 0.35667 · R_p · C_b

0.7 · V_DD = V_DD · (1 - e^(-t_2 / (R_p · C_b)))
e^(-t_2 / (R_p · C_b)) = 0.3
-t_2 / (R_p · C_b) = ln(0.3)
t_2 = -R_p · C_b · ln(0.3) ≈ 1.20397 · R_p · C_b
```

Різниця `t_2 - t_1` дає аналітичний вираз для часу наростання фронту `t_r`:

```
t_r = t_2 - t_1
    = R_p · C_b · (-ln(0.3) - (-ln(0.7)))     [підстановка t_1 та t_2]
    = R_p · C_b · ln(0.7 / 0.3)               [властивість різниці логарифмів]
    = R_p · C_b · ln(7 / 3)                   [спрощення дробу]
    = R_p · C_b · ln(2.3333)
    ≈ 0.8473 · R_p · C_b
```

Спадний фронт формується розрядом паразитної ємності `C_b` на землю через опір відкритого каналу транзистора `R_on` (`R_on ≈ 5...20 Ом` для сучасних КМОН-драйверів):

```
t_f ≈ 0.8473 · R_on · C_b
```

Оскільки `R_on << R_p` (зазвичай `R_p = 1.5...10 кОм`), час спаду `t_f` становить одиниці наносекунд (`t_f ≈ 2...10 нс`) і є значно меншим за час наростання `t_r` (`t_r ≈ 100...300 нс`).

---

### 2. Граничні значення опору підтяжки `R_p` та зв'язок із розтягуванням

Для забезпечення стабільного відновлення високого рівня після зняття веденим блокування SCL, номінал `R_p` повинен знаходитися у строго визначеному діапазоні:

1. **Мінімальний опір `R_p,min`** обмежується максимальним допустимим струмом вихідного транзистора в низькому стані `I_OL,max` (за стандартом I2C `I_OL = 3 мА` при напрузі `V_OL = 0.4 В` для Standard і Fast-Mode):
   ```
   R_p,min = (V_DD - V_OL,max) / I_OL,max
   ```
   Для живлення `V_DD = 3.3 В` та `V_OL,max = 0.4 В`:
   ```
   R_p,min = (3.3 В - 0.4 В) / 3 мА = 2.9 В / 0.003 А ≈ 967 Ом
   ```

2. **Максимальний опір `R_p,max`** обмежується максимальним стандартизованим часом наростання `t_r,max` (для Standard-Mode `t_r,max = 1000 нс`, для Fast-Mode `t_r,max = 300 нс`):
   ```
   R_p,max = t_r,max / (0.8473 · C_b)
   ```
   Якщо сумарна ємність шини становить `C_b = 200 пФ`, для режиму Fast-Mode:
   ```
   R_p,max = 300 · 10⁻⁹ с / (0.8473 · 200 · 10⁻¹² Ф) ≈ 1770 Ом
   ```

Якщо опір `R_p` завищений або ємність `C_b` перевищує норму, наростаючий фронт після закінчення розтягування такту затягується. Провідний контролер I2C, зафіксувавши відпускання лінії транзистором, починає відлік фази `T_HIGH` лише після перетину порогу `V_IH`. Затягнутий фронт додатково збільшує фактичну тривалість такту на величину `Δt_rise = t_r - t_r,nominal`.

### 3. Модифікація тактового циклу при розтягуванні такту

Коли ведений пристрій утримує лінію SCL на рівні нуля протягом додаткового інтервалу часу `t_stretch`, фактична тривалість фази низького рівня збільшується:

```
T_LOW_actual = T_LOW_nominal + t_stretch
```

Фактичний період тактового сигналу `T_SCL_actual` набуває вигляду:

```
T_SCL_actual = T_HIGH + T_LOW_nominal + t_stretch + t_r + t_f
             = T_SCL_nominal + t_stretch
```

Відповідно, миттєва тактова частота шини `f_actual` падає за гіперболічним законом:

```
f_actual = 1 / (T_SCL_nominal + t_stretch)
         = f_nominal / (1 + f_nominal · t_stretch)    [перетворення через період f = 1/T]
```

**Приклад розрахунку миттєвої частоти:**
Нехай шина працює в режимі Fast-Mode з номінальною частотою `f_nominal = 400 кГц` (`T_SCL_nominal = 2.5 мкс`). Якщо мікроконтролер-ведений затримує обробку переривання на `t_stretch = 10 мкс`, миттєва частота цього такту складе:

```
f_actual = 1 / (2.5 мкс + 10 мкс)
         = 1 / 12.5 мкс               [додавання затримки t_stretch]
         = 80 кГц                     [обчислення миттєвої частоти]
```

Частота такту для цього конкретного біта зменшилася у 5 разів.

### 4. Пропускна здатність повної транзакції передачі даних

Розглянемо стандартну транзакцію запису або читання масиву з `N` байтів. Транзакція складається з наступних часових складових:
1. Формування умови START: тривалість `t_HD:STA` (час утримання стану старту).
2. Передачі адреси пристрою (7 біт адреси + 1 біт R/W + 1 біт ACK) = 9 тактів SCL.
3. Можливого розтягування такту веденим після прийому адреси: `t_stretch_addr`.
4. Передачі `N` інформаційних байтів, кожен із яких займає 9 тактів SCL (8 біт даних + 1 біт ACK/NACK).
5. Розтягування такту перед або після кожного байта даних: `t_stretch_data[k]` для `k = 1...N`.
6. Формування умови STOP: тривалість `t_SU:STO` (час встановлення стану стопу) та часу вільного стану шини `t_BUF`.

Загальний час виконання транзакції `T_total` дорівнює:

```
T_total = t_overhead + (1 + N) · 9 · T_SCL_nominal + t_stretch_addr + ∑(k=1..N) t_stretch_data[k]
```

де сумарні накладні витрати формування службових станів складають:

```
t_overhead = t_HD:STA + t_SU:STO + t_BUF
```

Корисна швидкість передачі даних `R_data` (у байтах за секунду) виражається формулою:

```
R_data = N / T_total
```

Корисна бітова швидкість `R_bit` (в бітах за секунду):

```
R_bit = (8 · N) / T_total
```

Коефіцієнт деградації пропускної здатності `η` визначається відношенням фактичної швидкості `R_data` до теоретичної максимальної швидкості `R_max` без розтягування:

```
η = T_total_nominal / T_total
  = (t_overhead + (1 + N) · 9 · T_SCL_nominal) / (t_overhead + (1 + N) · 9 · T_SCL_nominal + T_stretch_sum)  [підстановка формули T_total]
```

де `T_stretch_sum = t_stretch_addr + ∑(k=1..N) t_stretch_data[k]`.

### 5. Практичний розрахунок: аналіз роботи з I2C АЦП високої точності

**Вхідні інженерні параметри:**
- Режим шини: Fast-Mode (`f_nominal = 400 кГц`, `T_SCL_nominal = 2.5 мкс`).
- Накладні витрати кадру: `t_overhead = 1.3 мкс (t_HD:STA) + 0.6 мкс (t_SU:STO) + 1.3 мкс (t_BUF) = 3.2 мкс`.
- Розмір зчитування: `N = 2` байти (16-бітний виміряний відлік).
- Ведений пристрій: 24-бітний дельта-сигма АЦП із внутрішнім запуском перетворення за командою.
- Час реакції на адресу (збудження джерела опорної напруги та внутрішніх блоків): `t_stretch_addr = 5 мкс`.
- Час внутрішнього аналого-цифрового перетворення між адресним байтом і першим байтом даних: `t_stretch_data[1] = 60 мкс`.
- Час перенесення другого байта з внутрішнього регістра: `t_stretch_data[2] = 2 мкс`.

**Покроковий розрахунок:**

1. Номінальний час передачі адресного та двох інформаційних байтів (разом `3 · 9 = 27` тактів):
```
T_clocks_nominal = 27 · 2.5 мкс = 67.5 мкс
```

2. Номінальний час транзакції без затримок:
```
T_total_nominal = 3.2 мкс + 67.5 мкс = 70.7 мкс
```
Теоретична максимальна частота зчитування відліків без затримок:
```
F_sample_max = 1 / T_total_nominal
             = 1 / 70.7 мкс           [підстановка номінального часу]
             ≈ 14144 вибірок/с        [обчислення частоти дискретизації]
```

3. Сумарний час розтягування такту веденим:
```
T_stretch_sum = 5 мкс + 60 мкс + 2 мкс = 67 мкс
```

4. Фактичний час виконання повної транзакції:
```
T_total_actual = T_total_nominal + T_stretch_sum
               = 70.7 мкс + 67 мкс    [додавання затримок розтягування]
               = 137.7 мкс            [фактичний час транзакції]
```

5. Фактична швидкість оновлення даних:
```
F_sample_actual = 1 / 137.7 мкс
                ≈ 7262 вибірок/с      [фактична частота дискретизації]
```

6. Коефіцієнт деградації корисної пропускної здатності:
```
η = 70.7 мкс / 137.7 мкс ≈ 0.5134 (51.3% від теоретичного максимуму)
```

Через внутрішнє перетворення АЦП корисна пропускна здатність шини впала майже вдвічі, що необхідно враховувати під час проектування систем реального часу з фіксованим періодом квантування.

### 6. Вплив розтягування на джитер та детермінізм опитування

У системах керування давачами критичною вимогою є постійний інтервал дискретизації `T_sample` з мінімальним джитером (тремтінням фази) `σ_t`.

Якщо прошивка веденого мікроконтролера обслуговує запити I2C за допомогою програмних переривань ISR (Interrupt Service Routine), час відгуку `t_stretch` є випадковою величиною, що залежить від:
- Затримки входу в переривання (*interrupt latency*): `t_lat ≈ 12...24` тактів ядра MCU;
- Наявності вищих за пріоритетом переривань (наприклад, таймерів ШІМ або DMA): `t_block = 0...t_crit_max`;
- Поточного стану конвеєра інструкцій та блокувань критичних секцій `__disable_irq()`.

Математично інтервал між послідовними відліками `Δt_k` описується рівнянням:

```
Δt_k = T_poll_nominal + (t_stretch[k] - t_stretch[k-1])
```

Дисперсія інтервалу опитування `Var(Δt)` дорівнює:

```
Var(Δt) = 2 · Var(t_stretch) - 2 · Cov(t_stretch[k], t_stretch[k-1])
```

Якщо затримка `t_stretch` варіюється в межах від `2 мкс` до `45 мкс`, піковий джитер вибірки `J_pp` сягає:

```
J_pp = t_stretch_max - t_stretch_min = 45 мкс - 2 мкс = 43 мкс
```

Для систем цифрової обробки сигналів із частотою зрізу фільтра `f_c = 1 кГц` такий джитер породжує значний фазовий шум та паразитні гармоніки. Вирішенням проблеми є апаратне буферизування вибірок через FIFO з фіксацією міток часу від апаратного таймера безпосередньо в момент завершення перетворення АЦП, замість прив'язки до моменту читання по I2C.

### 7. Багатомайстровий арбітраж: розрахунок результуючого такту

Якщо на спільній шині присутні два ведучих `M_1` і `M_2`, які синхронно починають передачу з власними тактовими генераторами, їхні номінальні параметри можуть різнитися через дрейф RC-генераторів або різну конфігурацію дільників:

- Ведучий 1: `T_LOW1`, `T_HIGH1`
- Ведучий 2: `T_LOW2`, `T_HIGH2`
- Ведений пристрій: генерує затримку `t_stretch` під час фази низького рівня.

Завдяки схемотехніці монтажного «І» (*Wired-AND*), спільний рівень напруги SCL визначається логічним добутком станів вихідних транзисторів:

```
SCL_bus = SCL_M1 ∧ SCL_M2 ∧ SCL_Slave
```

Результуюча тривалість фази низького рівня `T_LOW_bus` на шині дорівнює максимальному значенню серед усіх пристроїв:

```
T_LOW_bus = max(T_LOW1, T_LOW2, t_stretch)
```

Фаза високого рівня `T_HIGH_bus` починається лише тоді, коли **всі** пристрої одночасно закривають свої вихідні транзистори (переходять у стан Hi-Z). Щойно лінія SCL піднімається до рівня `V_IH`, кожен ведучий запускає свій внутрішній лічильник підрахунку інтервалу `T_HIGH`. Перший ведучий, у якого закінчується таймер `T_HIGH`, знову притягує лінію SCL до нуля. Отже, тривалість високого рівня визначається найкоротшим таймером серед активних ведучих:

```
T_HIGH_bus = min(T_HIGH1, T_HIGH2)
```

Результуючий період шини при багатомайстровій синхронізації з урахуванням фронтів наростання та спаду:

```
T_SCL_sync = max(T_LOW1, T_LOW2, t_stretch) + min(T_HIGH1, T_HIGH2) + t_r + t_f
```

Це рівняння доводить фундаментальний принцип I2C: **найповільніший пристрій визначає тривалість низького рівня шини, а найшвидший ведучий визначає тривалість високого рівня**.

### 8. Часові бюджети та обмеження таймаутів SMBus

Стандарт SMBus (System Management Bus) базується на фізичному рівні I2C, але вводить жорсткі часові обмеження, щоб унеможливити безкінечне блокування шини при апаратних збоях або зависанні прошивки веденого мікроконтролера.

#### 8.1. Абсолютний таймаут утримання лінії SCL (`t_TIMEOUT`)

Згідно зі специфікацією SMBus v3.2, якщо лінія SCL утримується в стані LOW довше ніж `t_TIMEOUT`, будь-який пристрій зобов'язаний скинути свій внутрішній інтерфейсний автомат стану в початковий стан `IDLE` і відпустити лінії SDA та SCL.

Часові межі таймауту становлять:

```
25 мс ≤ t_TIMEOUT ≤ 35 мс
```

Максимально допустиме неперервне розтягування такту для одного біта:

```
t_stretch_bit_max = t_TIMEOUT_min = 25 мс
```

Якщо обробник переривання мікроконтролера утримує затвор транзистора довше 25 мс, контролер живлення або ведучий процесор класифікує це як аварію шини (*Bus Hang*) і примусово перезавантажує I2C-периферію.

#### 8.2. Кумулятивні бюджети розтягування такту

SMBus регламентує кумулятивний (накопичувальний) час низького рівня протягом однієї повної транзакції:

1. **`t_LOW:SEXT` (Cumulative Slave Clock Extension):**
   Сумарний час, на який ведений пристрій має право подовжувати низький рівень лінії SCL від початкової умови START до фінальної умови STOP у межах одного сеансу обміну:
   ```
   t_LOW:SEXT ≤ 25 мс
   ```
   Якщо транзакція містить `N` байтів, середнє допустиме розтягування на один байт обмежується величиною:
   ```
   t_stretch_per_byte_avg ≤ t_LOW:SEXT / (N + 1)
   ```
   Для транзакції з читанням блоку з 32 байтів:
   ```
   t_stretch_per_byte_avg ≤ 25 мс / 33 ≈ 757.5 мкс
   ```

2. **`t_LOW:MEXT` (Cumulative Master Clock Extension):**
   Сумарний додатковий час утримання низького рівня ведучим пристроєм (наприклад, коли ведучий робить програмні паузи між байтами для обслуговування внутрішнього буфера):
   ```
   t_LOW:MEXT ≤ 10 мс
   ```

3. **Мінімальна робоча частота SMBus:**
   Через наявність таймауту `t_TIMEOUT_max = 35 мс`, на відміну від базової специфікації I2C (де нижня робоча частота теоретично дорівнює 0 Гц), стандарт SMBus обмежує мінімальну частоту тактування:
   ```
   f_SMBUS_min = 1 / (t_TIMEOUT_min · 2) = 1 / (2 · 25 мс) = 10 кГц (для SMBus v1.x/2.0)
   ```

### 10. Енергетичні втрати при розтягуванні такту на лініях Open-Drain

Схемотехніка відкритого стоку має важливу енергетичну особливість: у пасивному стані високого рівня струм через резистор підтяжки `R_p` практично не протікає (лише мікроамперні струми витоку закритих польових транзисторів). Проте коли будь-який пристрій (ведучий чи ведений) притягує лінію SCL до нуля, через резистор `R_p` починає протікати постійний струм на землю:

```
I_pullup = (V_DD - V_OL) / R_p ≈ V_DD / R_p
```

Миттєва розсіювана потужність на резисторі підтяжки під час активного низького рівня:

```
P_pullup = I_pullup² · R_p = V_DD² / R_p
```

Енергія `E_stretch`, що розсіюється у вигляді тепла на резисторі `R_p` за час розтягування такту `t_stretch`:

```
E_stretch = P_pullup · t_stretch = (V_DD² / R_p) · t_stretch
```

**Порівняльний інженерний приклад:**
Нехай шина живиться від `V_DD = 3.3 В`, опір підтяжки `R_p = 2.2 кОм`. Постійний струм через відкритий транзистор становить `I_pullup = 3.3 В / 2200 Ом = 1.5 мА`.
Потужність, що виділяється: `P_pullup = (3.3)² / 2200 ≈ 4.95 мВт`.

1. **Без розтягування такту:** при частоті 100 кГц тривалість `T_LOW = 5 мкс`. За один такт розсіюється енергія:
   ```
   E_nominal = 4.95 мВт · 5 мкс = 24.75 нДж
   ```
2. **З розтягуванням такту:** якщо ведений мікроконтролер утримує лінію на час виконання складного обчислення або запису у Flash-пам'ять `t_stretch = 10 мс`:
   ```
   E_stretched = 4.95 мВт · 10 мс = 49.5 мкДж
   ```

Енерговитрати одного такту зросли у 2000 разів. Для автономних пристроїв із живленням від дискових літієвих батарейок (наприклад, CR2032 ємністю 220 мАг) часте та тривале розтягування такту веденими датчиками створює значне паразитне споживання струму (1.5 мА замість середнього споживання мікроконтролера в режимі сну 2...5 мкА), що може скоротити час автономної роботи приладу в кілька разів.

### 11. Математична модель латентності: DMA проти програмних переривань (ISR)

Час розтягування такту веденим пристроєм `t_stretch` складається з апаратних та програмних затримок обслуговування інтерфейсу:

```
t_stretch = t_hw_sync + t_core_latency + t_sw_exec
```

де:
- `t_hw_sync` — час внутрішньої синхронізації апаратного автомата I2C із системною шиною мікроконтролера (зазвичай 2...4 такти перифірійної шини APB/AHB, `t_hw_sync ≈ 25...50 нс` при частоті 80 МГц);
- `t_core_latency` — час від виставлення апаратного прапорця переривання (наприклад, `ADDR` або `RXNE`) до виконання першої інструкції обробника в ядрі (для архітектури ARM Cortex-M4 з конвеєром — 12 тактів ядра плюс час очікування виходу з критичних секцій `__disable_irq()`);
- `t_sw_exec` — час виконання коду обробника переривання, необхідний для зчитування даних із регістрів `I2C_RXDR` або запису в `I2C_TXDR`.

#### 11.1. Обслуговування через програмні переривання (ISR)

При програмній обробці кожен байт викликає переривання. Час обробника:

```
t_sw_exec_ISR = N_instructions / f_CPU
```

Якщо обробник займає 40 асемблерних інструкцій при частоті процесора `f_CPU = 16 МГц`:

```
t_sw_exec_ISR = 40 / (16 · 10⁶ с⁻¹) = 2.5 мкс
```

Сумарне розтягування для кожного байта:

```
t_stretch_ISR = 0.05 мкс + 0.75 мкс + 2.5 мкс = 3.3 мкс
```

Для шини Fast-Mode (`T_SCL = 2.5 мкс`) це понад 130% від періоду такту, що знижує пропускну здатність більш ніж удвічі.

#### 11.2. Обслуговування через прямий доступ до пам'яті (DMA)

При використанні контролера DMA апаратний блок I2C генерує запит `DMA_REQ` безпосередньо в момент заповнення регістра `RXDR` або звільнення `TXDR`. Затримка арбітражу шини DMA становить лише 1...3 такти системної шини:

```
t_stretch_DMA = t_hw_sync + t_dma_arbitration + t_bus_transfer
              = (3 / f_bus) + (2 / f_bus) + (1 / f_bus)       [підстановка тактів шини APB/AHB]
              = 6 / (80 · 10⁶ с⁻¹)                            [сумування тактів при f_bus = 80 МГц]
              = 75 нс                                         [обчислення затримки DMA]
```

Оскільки `75 нс << T_LOW_nominal` (для Fast-Mode `T_LOW = 1300 нс`), апаратний контролер DMA встигає зчитати або записати дані ще до того, як ведучий завершить формування фази низького рівня `T_LOW`.

**Висновок:** застосування каналів DMA у ведених вузлах повністю усуває програмне розтягування такту `t_stretch → 0`, забезпечуючи максимальну теоретичну швидкість передачі без затримок шини.

### 12. Зведена таблиця часових обмежень I2C та SMBus


| Параметр часової діаграми | Позначення | I2C Standard | I2C Fast-Mode | SMBus v3.2 (Standard) |
| :--- | :--- | :--- | :--- | :--- |
| Номінальна тактова частота `f_SCL` | `f_SCL` | 0...100 кГц | 0...400 кГц | 10...100 кГц |
| Мінімальний час високого рівня `T_HIGH` | `t_HIGH` | 4.0 мкс | 0.6 мкс | 4.0 мкс |
| Мінімальний час низького рівня `T_LOW` | `t_LOW` | 4.7 мкс | 1.3 мкс | 4.7 мкс |
| Максимальний час наростання `t_r` | `t_r` | 1000 нс | 300 нс | 1000 нс |
| Максимальний час спаду `t_f` | `t_f` | 300 нс | 300 нс | 300 нс |
| Максимальне розтягування одного біта | `t_stretch_max` | Не обмежено (∞) | Не обмежено (∞) | 25...35 мс (`t_TIMEOUT`) |

Розрахунок часових параметрів показує: розтягування такту є ефективним апаратним механізмом узгодження швидкостей різнорідних пристроїв, проте в системах із жорстким часовим детермінізмом часті або непередбачувані затримки веденого знижують реальну смугу пропускання шини в кілька разів і вимагають суворого контролю максимального часу виконання переривань у прошивці веденого мікроконтролера.
