# ⚙️ Розрахунок фізичних і корисних швидкостей ліній зв'язку

Під час проєктування апаратно-програмних інтерфейсів розробники постійно стикаються з розривом між заявленою виробником «швидкістю шини» та реальною пропускною здатністю, доступною прикладному програмному забезпеченню. Наприклад, мережевий адаптер Gigabit Ethernet формально працює на швидкості 1000 Мбіт/с, але вимірювання утилітою iperf3 показують лише 940–949 Мбіт/с корисної передачі. Бездротовий модуль Wi-Fi 6 заявляє швидкість фізичного рівня 1201 Мбіт/с, але реальне копіювання файлу триває зі швидкістю не більше 750–800 Мбіт/с.

Цей розрив не є ознакою дефекту чи несправності обладнання. Він зумовлений суворою математикою втрат на кожному рівні передавального тракту: від фізичної модуляції та лінійного кодування на рівні мікросхеми трансивера (PHY) до завадостійкого захисту (FEC), розбиття на пакети та накладних витрат мережевих стеків ОС.

Щоб точно прогнозувати та верифікувати поведінку системи зв'язку, необхідний розрахунковий інструмент, який крок за кроком перетворює параметри фізичного середовища (бодову швидкість, порядок модуляції, схему кодування) у вихідний корисний бітрейт (Goodput).

### Архітектура передавального тракту та математична модель втрат

Повний тракт передачі даних можна представити як каскад перетворювачів, кожен із яких або масштабує швидкість за рахунок фізичного пакування кількох бітів в один символ, або зменшує її через додавання службової надлишковості.

```
Боди (R_s) ──[ × k=log₂M ]──> Raw Bitrate ──[ × Line Code ]──> Gross Bitrate ──[ × FEC ]──> Net Bitrate ──[ × Headers ]──> Goodput
```

Розглянемо фізичний зміст кожного ступеня розрахунку:

#### 1. Бодова швидкість та кратність модуляції: від бодів до сирого бітрейту

На першому ступені аналоговий модулятор формує елементарні посилки сигналу (символи) з частотою `R_s` (бод). Якщо використовується двійковий сигнал (2-PAM або NRZ), кожен символ набуває одного з двох станів і переносить рівно 1 біт інформації. У багаторівневих та квадратурних схемах (M-PAM, M-PSK, M-QAM) один символ кодує точку в просторі станів із загальної кількості `M` варіантів:

```
k = log₂(M)  [біт/символ]
```

Якщо трансивер має кілька паралельних фізичних ліній зв'язку або просторових потоків `N_lanes` (наприклад, 4 виті пари в кабелі Ethernet або 4 лінії шини PCIe x4), сумарний сирий фізичний бітрейт лінії (Raw Line Rate) обчислюється як:

```
R_raw = R_s · k · N_lanes  [біт/с]
```

Ця величина показує, скільки двійкових розрядів за секунду фізично проходить крізь сукупність провідників чи радіоканалів.

#### 2. Лінійне кодування: усунення постійної складової та вирівнювання переходів

Сирий потік бітів не можна безпосередньо подавати на високошвидкісні диференціальні лінії з ємнісною розв'язкою (AC coupling). Довга послідовність однакових нулів чи одиниць зміщує постійну напругу на роздільних конденсаторах (DC wander) та позбавляє приймач перепадів напруги, необхідних для роботи схеми відновлення тактової частоти (Clock and Data Recovery, CDR).

Для розв'язання цієї проблеми застосовують блокове лінійне кодування:
- **Код Манчестер (10BASE-T):** кожен інформаційний біт замінюється двома напівбітами з обов'язковим перепадом у центрі. Ефективність становить `1/2` (втрата 50% пропускної здатності).
- **Код 8b/10b (PCIe 1.0/2.0, SATA, USB 3.0, Gigabit Ethernet 1000BASE-X):** кожні 8 бітів даних перетворюються на 10-бітний символ для підтримання нульового балансу постійного струму (Running Disparity). Ефективність становить `8/10 = 0.8` (втрата 20%).
- **Код 64b/66b (10GbE, PCIe 3.0+ 128b/130b):** дані скрамблуються псевдовипадковою послідовністю, а попереду додається 2-бітний синхронізаційний префікс. Ефективність становить `64/66 ≈ 0.9697` (втрата лише 3.03%).

Брутто-бітрейт (Gross Bitrate) після лінійного кодування дорівнює:

```
R_gross = R_raw · (k_line / n_line)  [біт/с]
```

#### 3. Завадостійке кодування каналу (FEC)

У високошвидкісних лініях із низьким запасом завадостійкості (Wi-Fi 6, 100G/400G Ethernet, PCIe 6.0) неминуче трапляються випадкові бітові помилки. Щоб не вимагати повторної передачі всього пакета, дані захищають кодами прямого виправлення помилок (Forward Error Correction, FEC): кодами Ріда-Соломона (RS-FEC), низькощілинними кодами (LDPC) або згортковими кодами.

Кодер додає перевірочні біти, зменшуючи швидкість передачі у відношенні кодової швидкості `R_fec = k_fec / n_fec`. Нетто-бітрейт каналу (Net Coded Bitrate) становить:

```
R_net = R_gross · (k_fec / n_fec)  [біт/с]
```

#### 4. Пакетизація та корисний Goodput

На мережевому та прикладному рівнях дані передаються блоками (кадрами або пакетами) фіксованого або змінного розміру. До кожного блоку корисної інформації розміром `L_payload` байтів додаються:
- Заголовки протоколів `L_headers` (наприклад, 14 байтів MAC Ethernet, 20 байтів IP, 20 байтів TCP).
- Службові поля фізичного та канального рівнів `L_overhead` (преамбула для синхронізації, 4-байтна контрольна сума FCS/CRC, обов'язковий інтервал між пакетами Inter-Frame Gap).

Реальна пропускна здатність, доступна застосунку користувача (Goodput), обчислюється як:

```
Goodput = R_net · (L_payload / (L_payload + L_headers + L_overhead))  [біт/с]
```

Підсумковий коефіцієнт корисної дії каналу виражається відношенням:

```
ККД = (Goodput / R_raw) · 100 %
```

### Покроковий розбір розрахунків для чотирьох типів ліній

Проаналізуємо, як працює математика калькулятора на кожному з чотирьох тестових інтерфейсів:

#### 1. Асинхронний інтерфейс UART (115200 8N1)
У мікроконтролерних системах лінія UART працює з двійковими рівнями напруги (2-PAM, `M = 2`, `k = 1` біт/бод). При налаштуванні `115200` передавач генерує рівно 115 200 прямокутних імпульсів на секунду.
- Сирий бітрейт становить: `115200 × 1 = 115 200` біт/с.
- У форматі 8N1 кожен корисний байт (8 бітів) обрамляється одним старт-бітом («0») та одним стоп-бітом («1»), утворюючи кадр із 10 бітів.
- Лінійне та завадостійке кодування відсутні (`1/1`).
- Ефективність кадрування дорівнює `8 / 10 = 0.80`.
- Корисний бітрейт (Goodput) становить: `115 200 × 0.80 = 92 160` біт/с (рівно 11 520 байт/с).
- Розрахунок наочно показує, чому спроба передати 115 200 байтів файлу через порт 115200 триває 10 секунд, а не 8: рівно 20% часу лінії забирає синхронізація старт-стоп.

#### 2. Дротовий Ethernet 1000BASE-T (Gigabit Ethernet)
Стандарт 1000BASE-T використовує чотири неекрановані виті пари кабелю категорії Cat5e.
- На кожній парі тактовий генератор трансивера працює з частотою 125 Мбод.
- Застосовується 5-рівнева амплітудна модуляція PAM-5. Чотири рівні несуть `k = log₂(4) = 2` біти інформації, а 5-й рівень використовується для треліс-кодування виправлення помилок та сигналів керування.
- Сирий бітрейт по 4 парах одночасно становить: `4 × 125 Мбод × 2 біти/символ = 1000 Мбіт/с` (1 Гбіт/с).
- При передачі стандартного IP-пакета з максимальним розміром корисного блоку MTU = 1500 байтів повний розмір кадру на дроті складається з: 1500B (IP payload) + 14B (Ethernet MAC) + 20B (IPv4 заголовок) + 20B (TCP заголовок) + 4B (контрольна сума FCS) + 8B (преамбула та SFD) + 12B (міжкадровий інтервал IFG) = 1578 байтів.
- Ефективність передачі становить `1500 / 1578 ≈ 0.9506` (95.06%).
- Реальний Goodput на рівні прикладного TCP-сокета дорівнює: `1000 Мбіт/с × 0.9506 ≈ 949.37 Мбіт/с` (близько 118.67 Мбайт/с). Розрахунок точно пояснює, чому жоден гігабітний тест iperf3 не перевищує 949 Мбіт/с.

#### 3. Високошвидкісна шина PCI Express 6.0 (x4 лінії)
Шина PCIe 6.0 перейшла з двійкового коду NRZ на чотирирівневу модуляцію PAM-4 (`M = 4`, `k = 2` біти на бод).
- Тактова частота символів становить `R_s = 32` Гбод (32 мільярди перемикань на секунду на лінію).
- Для слота x4 (4 паралельні лінії) сирий бітрейт сягає: `4 × 32 Гбод × 2 біти = 256 Гбіт/с` (32 Гбайт/с).
- У PCIe 6.0 скасовано традиційні коди 128b/130b. Дані передаються фіксованими пакетами FLIT (Flow Control Unit) розміром 256 байтів.
- У кожному 256-байтному FLIT рівно 14 байтів відведено під надпотужний код виправлення помилок RS-FEC (Reed-Solomon) та перевірочні байти CRC, що дає кодову швидкість `242 / 256 ≈ 0.9453`.
- Нетто-бітрейт після вирахування FEC становить `256 × (242 / 256) = 242 Гбіт/с`.
- З урахуванням заголовків TLP (Transaction Layer Packet) реальний потік даних становить близько 216 Гбіт/с (27 Гбайт/с), що дає загальний ККД лінії 84.38%.

#### 4. Бездротовий канал Wi-Fi 6 (802.11ax, 80 МГц, 1024-QAM)
У бездротовому середовищі 80 МГц смуга ділиться за технологією OFDM на 980 піднесучих корисних даних.
- Сумарна символьна швидкість усіх піднесучих становить `R_s ≈ 72.06` Мбод.
- Застосовується модуляція 1024-QAM (`M = 1024`, `k = 10` бітів на бод).
- Сирий бітрейт радіоефіру становить: `72.06 Мбод × 10 = 720.59 Мбіт/с`.
- Використовується завадостійкий код LDPC з кодовою швидкістю `5/6` (на кожні 5 бітів даних додається 1 біт надлишковості), що дає швидкість фізичного рівня (PHY Rate): `720.59 × (5/6) = 600.49 Мбіт/с`.
- З урахуванням бездротових заголовків кадру 802.11, блокових підтверджень Block ACK та міжкадрових пауз SIFS/DIFS реальний Goodput становить близько 565 Мбіт/с для агрегованих кадрів A-MPDU.

### Апаратна реалізація SerDes та корекція сигналу

Реалізація обчислених швидкостей у кремнії покладається на трансивери **SerDes** (англ. *Serializer/Deserializer*). Їхнє завдання — перетворити паралельну внутрішню шину процесора (наприклад, 64 біти на частоті 500 МГц) в один або кілька послідовних диференціальних потоків із частотою маніпуляції в десятки гігабод.

Фізичний блок SerDes містить:
1. **Синтезатор частоти на основі PLL (Phase-Locked Loop):** перетворює опорну частоту кварцового генератора (наприклад, 100 МГц) у тактову сітку бодової частоти (32 ГГц).
2. **Передавальний еквалайзер FFE (Feed-Forward Equalization):** формує передавальні символи з випереджальними та запізнілими відводами (pre-cursor і post-cursor taps). Це штучно спотворює амплітуду переданого сигналу у зворотний до затухання лінії бік (деемфазис), компенсуючи дисперсію друкованої плати ще до того, як імпульс зайде в лінію.
3. **Приймальний лінійний еквалайзер CTLE (Continuous-Time Linear Equalizer):** високочастотний аналоговий підсилювач, що вирівнює амплітудно-частотну характеристику в діапазоні до частоти Найквіста.
4. **Зворотний еквалайзер DFE (Decision-Feedback Equalizer):** цифрова схема зі зворотним зв'язком, яка віднімає хвости попередніх розпізнаних символів безпосередньо в момент стробування поточного рівня, ефективно розкриваючи «око» сигналу PAM-4.

У двійкових лініях NRZ для детектування достатньо простого аналогового компаратора з одним нульовим порогом. У лініях PAM-4 приймач мусить мати три високошвидкісні паралельні компаратори та прецизійний цифровий аналізатор рівнів. У схемах QAM високого порядку (1024-QAM) розпізнавання здійснюється повноцінним DSP-процесором з аналого-цифровими перетворювачами високої розрядності (ADC) на вході.

### Автоматизоване тестування та валідація на стенді

Під час верифікації мікросхем трансиверів та готових мережевих карт автоматизовані випробувальні стенди перевіряють фізичні характеристики каналу за допомогою тестерів бітових помилок **BERT** (англ. *Bit Error Rate Tester*).

Генератор BERT завантажує в передавач стандартизовані псевдовипадкові послідовності бітів:
- **PRBS7 (`2⁷ - 1 = 127` бітів):** для швидкого тестування простих ліній без глибокої пам'яті каналу.
- **PRBS15 (`2¹⁵ - 1 = 32767` бітів):** стандартний патерн для перевірки лінійних кодів 8b/10b та оптичних модулів.
- **PRBS31 (`2³¹ - 1 ≈ 2.14` млрд бітів):** для виявлення рідкісних резонансних завад і стрес-тестування еквалайзерів DFE на довгих пакетах однакових символів.

Приймач BERT підраховує кількість помилок на мільярд переданих бітів, будуючи **криву ванни** (англ. *Bathtub Curve*) — залежність імовірності помилки BER від фазового зміщення точки стробування відносно центру символу. На основі ширини кривої ванни на рівні `10⁻¹²` визначають сумарний джитер (Total Jitter, TJ), перевіряючи, чи забезпечує лінія стабільну роботу на розрахунковій бодовій швидкості.

### Практичні інженерні пастки та правила проєктування

Практична розробка систем передачі даних вимагає врахування таких критичних нюансів:

#### 1. Переповнення 32-бітних цілих чисел
Змінна типу `uint32_t` обмежена значенням `2³² - 1 ≈ 4 294 967 295` біт/с (близько 4.29 Гбіт/с). Обчислення сирого бітрейту інтерфейсу 10GbE, PCIe 4.0 або 100G Ethernet у стандартних одиницях `біт/с` без приведення до 64-бітного типу `uint64_t` або типу з рухомою крапкою `double` спричиняє миттєве арифметичне переповнення та спотворення розрахунків.

#### 2. Плутанина між десятковими та двійковими префіксами
Швидкості каналів зв'язку завжди стандартизуються в десятковій системі СІ: `1 Мбіт/с = 10⁶ біт/с = 1 000 000 біт/с`. Водночас розміри файлів у пам'яті комп'ютера та вивід багатьох системних утиліт рахуються в двійкових мегабайтах (мебібайтах): `1 МіБ = 2²⁰ байтів = 1 048 576 байтів = 8 388 608 бітів`. Тому мережевий потік 949 Мбіт/с відповідає швидкості запису файлу `949 000 000 / 8 388 608 ≈ 113.1` МіБ/с, що часто помилково трактують як падіння продуктивності.

#### 3. Вплив розміру пакета на пропускну здатність
Для каналів із фіксованим розміром заголовків критично важливим є розмір корисного навантаження (Payload). Якщо застосунок надсилає дрібні повідомлення (наприклад, пакети сенсорів або телеметрії розміром 64 байти), частка заголовків Ethernet + IP + TCP + FCS + IFG (разом 78 байтів) перевищує розмір самих даних. Ефективність лінії падає з 95% до `64 / (64 + 78) ≈ 45%`. Увімкнення механізму Jumbo Frames (MTU = 9000 байтів) у локальних мережах підвищує ефективність гігабітного Ethernet до `9000 / (9000 + 78) ≈ 99.14%`, збільшуючи корисний Goodput з 949 Мбіт/с до 991 Мбіт/с на тій самій незмінній бодовій швидкості 125 Мбод.

### Інструментальне вимірювання та діагностика на рівні ОС

Для перевірки відповідності розрахункових показників реальній поведінці апаратного забезпечення використовують спеціалізовані інструменти діагностики операційної системи Linux.

Утиліта `ethtool` дозволяє прочитати внутрішні апаратні лічильники трансивера PHY та мережевого контролера (MAC):

```bash
# Перегляд фізичних параметрів лінку: швидкість, дуплекс, автоузгодження
ethtool eth0

# Зчитування детальних лічильників помилок кадрування та FEC
ethtool -S eth0 | grep -E "fec|crc|drop|frame_err"
```

Для вимірювання чистого корисного Goodput на транспортному рівні TCP застосовують генератор навантаження `iperf3`:

```bash
# Запуск клієнта для вимірювання пропускної здатності TCP з фіксованим розміром вікна
iperf3 -c 192.168.1.10 -t 10 -i 1 -P 4
```

У виводі `iperf3` відображається точна швидкість надходження корисних байтів на сокет. Якщо виміряне значення значно відхиляється від розрахункового Goodput (наприклад, 820 Мбіт/с замість 949 Мбіт/с на гігабітному лінку), це вказує на одну з трьох причин:
1. Виникнення повторних передач пакетів (TCP retransmissions) через спотворення бітів у кабелі (лічильник `rx_crc_errors` в `ethtool -S`).
2. Недостатній розмір сокетних буферів TCP (`tcp_rmem` / `tcp_wmem` у `/proc/sys/net/ipv4/`), що обмежує добуток пропускної здатності на затримку (Bandwidth-Delay Product, BDP).
3. Надмірні затримки переривань мережевого адаптера (Interrupt Moderation / Adaptive RX/TX), які спричиняють затримку підтверджень ACK.

Апаратна верифікація фізичного рівня за допомогою цифрового осцилографа та аналізатора сигналів базується на знятті **очної діаграми** (англ. *Eye Diagram*). Ширина «ока» показує тривалість символу `T_s` (зворотну до бодової швидкості), а висота «ока» — запас до порогової напруги розпізнавання рівнів `M-PAM`. Зменшення висоти ока через затухання чи шуми призводить до зростання кількості некоригованих помилок FEC, змушуючи протокол знижувати бітрейт.
