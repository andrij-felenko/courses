# Регістрові карти та протоколи I²C-розширювачів

Ця довідкова специфікація містить повний опис адресного простору, призначення бітових полів, внутрішніх регістрових карт, правил адресації та часових діаграм популярних сімейств мікросхем I2C-розширювачів портів введення-виведення (`PCF8574`, `TCA9534`, `TCA9555`, `MCP23008`, `MCP23017`). Довідник призначений для розробників драйверів низького рівня, системних інженерів та розробників вбудованого ПЗ (*firmware*), яким необхідні точні зміщення регістрів, бітові маски ініціалізації та інваріанти протокольного обміну.

---

### 1. Безрегістрове сімейство: PCF8574 та PCF8575

Мікросхеми `PCF8574` (8 портів) та `PCF8575` (16 портів) виробництва NXP та Texas Instruments не мають внутрішнього покажчика регістрів (*Register Address Pointer*). Будь-який байт даних, надісланий на шину після адреси пристрою, інтерпретується внутрішньою логікою безпосередньо як новий стан вихідного порту.

#### 1.1. 7-бітний адресний простір

| Модель чіпа | Базовий префікс (біти 6..3) | Апаратні піни (біти 2..0) | Діапазон адрес I2C (7-bit Hex) |
| :--- | :--- | :--- | :--- |
| **PCF8574** | `0 1 0 0` | A2, A1, A0 | `0x20` .. `0x27` |
| **PCF8574A** | `0 1 1 1` | A2, A1, A0 | `0x38` .. `0x3F` |
| **PCF8575** | `0 1 0 0` | A2, A1, A0 | `0x20` .. `0x27` |
| **PCF8575C** | `0 1 1 1` | A2, A1, A0 | `0x38` .. `0x3F` |

Версії чіпа з літерою «A» та без неї мають абсолютно ідентичну кремнієву структуру і відрізняються виключно жорстко зашитим префіксом адреси. Це дозволяє встановити на одну фізичну шину до 16 мікросхем (8 × PCF8574 + 8 × PCF8574A), отримавши 128 портів без I2C-мультиплексорів.

#### 1.2. Протокол транзакцій PCF8574 (8-бітний)

Протокол взаємодії з PCF8574 є найбільш компактним серед усіх I2C-периферійних пристроїв, оскільки не вимагає фази передачі адреси регістра.

```
Операція запису (встановлення виходів P0..P7):
┌───────┬───────────────────────────────┬─────┬──────────────────────────────┬─────┬──────┐
│ START │ 7-біт адреса чіпа + W (біт 0) │ ACK │ Байт стану виходів (P7..P0)  │ ACK │ STOP │
└───────┴───────────────────────────────┴─────┴──────────────────────────────┴─────┴──────┘

Операція читання (зчитування входів P0..P7):
┌───────┬───────────────────────────────┬─────┬──────────────────────────────┬──────┬──────┐
│ START │ 7-біт адреса чіпа + R (біт 1) │ ACK │ Байт стану входів (P7..P0)   │ NACK │ STOP │
└───────┴───────────────────────────────┴─────┴──────────────────────────────┴──────┴──────┘
```

Якщо під час читання мікроконтролер надсилає підтвердження `ACK` замість `NACK`, розширювач продовжує видавати новий байт стану фізичних входів на кожні наступні 8 тактів SCL. Це дозволяє організувати швидкісне потокове зчитування стану пінів без повторної адресації пристрою.

#### 1.3. Протокол транзакцій PCF8575 (16-бітний)

У 16-бітному розширювачі PCF8575 дані передаються двобайтними словами. Перший надісланий або отриманий байт відповідає молодшому порту `P0..P7` (Port 0), другий — старшому порту `P10..P17` (Port 1):

```
Запис 16 бітів:
START -> [Addr + W] (ACK) -> [Байт P0..P7] (ACK) -> [Байт P10..P17] (ACK) -> STOP

Читання 16 бітів:
START -> [Addr + R] (ACK) -> [Байт P0..P7] (ACK) -> [Байт P10..P17] (NACK) -> STOP
```

### 2. Сімейство Texas Instruments / NXP: TCA9534 та TCA9555

Мікросхеми сімейств `TCA9534` (8 бітів), `PCA9554` (8 бітів) та `TCA9555` / `PCA9555` (16 бітів) використовують командний байт (*Command Byte*) як покажчик регістра. Виходи побудовані за повноцінною схемою Push-Pull зі справжнім тристабільним станом High-Z.

#### 2.1. Регістрова карта TCA9534 / PCA9554 (8-бітний розширювач)

| Командний байт | Назва регістра | Опис функції | Доступ | Стан за замовчуванням |
| :--- | :--- | :--- | :--- | :--- |
| `0x00` | **Input Port** | Реальний логічний стан фізичних виводів | Тільки читання (RO) | `XXXX XXXX` (від стану пінів) |
| `0x01` | **Output Port** | Вихідний регістр засувки стану виводів | Читання/Запис (RW) | `0xFF` (`1111 1111`) |
| `0x02` | **Polarity Inversion** | Інверсія полярності зчитування вхідних ліній | Читання/Запис (RW) | `0x00` (`0000 0000`) |
| `0x03` | **Configuration** | Регістр напрямку даних (1 = Вхід, 0 = Вихід) | Читання/Запис (RW) | `0xFF` (`1111 1111`) |

Детальний функціонал регістрів:
- **Input Port (`0x00`)**: є регістром «прямого відліку». Він не зберігає попереднє значення, а безпосередньо відображає поточні напруги на виводах чіпа, пропущені через вхідні тригери Шмітта та регістр інверсії полярності. Запис у цей регістр заборонено (ігнорується логікою).
- **Output Port (`0x01`)**: зберігає значення, які видаватимуться на піни, якщо вони налаштовані як виходи. Читання цього регістра повертає значення внутрішнього тригера засувки, а не реальний стан на пінах (що запобігає спотворенням при ємнісному навантаженні).
- **Polarity Inversion (`0x02`)**: дозволяє апаратно інвертувати біти регістра `Input Port`. Якщо біт встановлено в `1`, низька напруга на вході (0 В) буде прочитана процесором як логічна `1`. Це дозволяє нормалізувати роботу з кнопками типу «Active Low».
- **Configuration (`0x03`)**: керує тристабільними буферами. `1` вимикає обидва транзистори вихідного каскаду (стан High-Z із струмом витоку менше 1 мкА). `0` активує двотактний драйвер Push-Pull.

#### 2.2. Регістрова карта TCA9555 / PCA9555 (16-бітний розширювач)

У 16-бітних версіях порти розділені на дві 8-бітні групи: Port 0 (`P0_0..P0_7`) та Port 1 (`P1_0..P1_7`). Командний покажчик підтримує парний доступ:

| Командний байт | Символьна назва | Порт | Функціональне призначення | Стан за замовчуванням |
| :--- | :--- | :--- | :--- | :--- |
| `0x00` | `INPUT_PORT_0` | Port 0 | Вхідний регістр фізичних рівнів P0 | `XXXX XXXX` |
| `0x01` | `INPUT_PORT_1` | Port 1 | Вхідний регістр фізичних рівнів P1 | `XXXX XXXX` |
| `0x02` | `OUTPUT_PORT_0` | Port 0 | Вихідний регістр керування ключами P0 | `0xFF` |
| `0x03` | `OUTPUT_PORT_1` | Port 1 | Вихідний регістр керування ключами P1 | `0xFF` |
| `0x04` | `POLARITY_INV_0` | Port 0 | Інверсія полярності для входу P0 | `0x00` |
| `0x05` | `POLARITY_INV_1` | Port 1 | Інверсія полярності для входу P1 | `0x00` |
| `0x06` | `CONFIG_PORT_0` | Port 0 | Конфігурація напрямку P0 (1=In, 0=Out) | `0xFF` |
| `0x07` | `CONFIG_PORT_1` | Port 1 | Конфігурація напрямку P1 (1=In, 0=Out) | `0xFF` |

#### 2.3. Поведінка автоінкременту командного покажчика в TCA9555

Коли мікроконтролер виконує багатобайтний запис або читання, внутрішній покажчик регістрів чергується між парними портами:
- Якщо почати читання з адреси `0x00` (Input Port 0), наступний зчитаний байт надійде з адреси `0x01` (Input Port 1), третій байт — знову з `0x00`, і так далі.
- Якщо почати запис з адреси `0x06` (Configuration Port 0), другий байт буде записано в `0x07` (Configuration Port 1). Це дозволяє налаштувати всі 16 ліній однією безперервною I2C-транзакцією.

### 3. Сімейство Microchip: MCP23008 та MCP23017

Мікросхеми `MCP23008` (8 бітів) та `MCP23017` (16 бітів) є одними з найбільш функціонально насичених I2C-розширювачів. Вони містять апаратні регістри виявлення переривань із маскуванням, вбудовані підтягувальні резистори 100 кОм на кожному виводі та засувки фіксації стану `INTCAP`.

#### 3.1. Регістрова карта MCP23017 (Режими `BANK = 0` та `BANK = 1`)

Організація пам'яті MCP23017 визначається бітом `BANK` у службовому регістрі конфігурації `IOCON`. За замовчуванням після скидання `BANK = 0` (регістри портів A і B чергуються).

| Назва регістра | Адреса (BANK=0) | Адреса (BANK=1) | Призначення та функція | Стан за замовчуванням |
| :--- | :--- | :--- | :--- | :--- |
| **IODIRA** | `0x00` | `0x00` | Напрямок виводів Port A (1=Input, 0=Output) | `0xFF` |
| **IODIRB** | `0x01` | `0x10` | Напрямок виводів Port B (1=Input, 0=Output) | `0xFF` |
| **IPOLA** | `0x02` | `0x01` | Інверсія полярності входу Port A (1=Invert) | `0x00` |
| **IPOLB** | `0x03` | `0x11` | Інверсія полярності входу Port B (1=Invert) | `0x00` |
| **GPINTENA** | `0x04` | `0x02` | Дозвіл переривань за зміною для Port A | `0x00` |
| **GPINTENB** | `0x05` | `0x12` | Дозвіл переривань за зміною для Port B | `0x00` |
| **DEFVALA** | `0x06` | `0x03` | Еталонне значення за замовчуванням Port A | `0x00` |
| **DEFVALB** | `0x07` | `0x13` | Еталонне значення за замовчуванням Port B | `0x00` |
| **INTCONA** | `0x08` | `0x04` | Режим порівняння INT (1=DEFVAL, 0=Попередній) | `0x00` |
| **INTCONB** | `0x09` | `0x14` | Режим порівняння INT (1=DEFVAL, 0=Попередній) | `0x00` |
| **IOCON** | `0x0A` | `0x05` | Конфігурація поведінки чіпа та переривань | `0x00` |
| **IOCON** | `0x0B` | `0x15` | Дзеркало регістра IOCON | `0x00` |
| **GPPUA** | `0x0C` | `0x06` | Увімкнення внутрішніх підтяжок 100 кОм Port A | `0x00` |
| **GPPUB** | `0x0D` | `0x16` | Увімкнення внутрішніх підтяжок 100 кОм Port B | `0x00` |
| **INTFA** | `0x0E` | `0x07` | Прапорці переривань Port A (Хто згенерував) | `0x00` (RO) |
| **INTFB** | `0x0F` | `0x17` | Прапорці переривань Port B (Хто згенерував) | `0x00` (RO) |
| **INTCAPA** | `0x10` | `0x08` | Знімок стану ліній Port A в момент переривання | `0x00` (RO) |
| **INTCAPB** | `0x11` | `0x18` | Знімок стану ліній Port B в момент переривання | `0x00` (RO) |
| **GPIOA** | `0x12` | `0x09` | Читання реальних рівнів на пінах Port A | `0x00` |
| **GPIOB** | `0x13` | `0x19` | Читання реальних рівнів на пінах Port B | `0x00` |
| **OLATA** | `0x14` | `0x0A` | Засувка вихідних даних Port A | `0x00` |
| **OLATB** | `0x15` | `0x1A` | Засувка вихідних даних Port B | `0x00` |

#### 3.2. Детальна структура бітів регістра `IOCON`

Регістр `IOCON` (*I/O Expander Configuration Register*) керує внутрішньою логікою роботи процесорного інтерфейсу та сигнальних ліній переривання.

```
 Біти регістра IOCON:
┌───────┬────────┬───────┬────────┬──────┬─────┬────────┬───────┐
│ bit 7 │ bit 6  │ bit 5 │ bit 4  │bit 3 │bit 2│ bit 1  │ bit 0 │
├───────┼────────┼───────┼────────┼──────┼─────┼────────┼───────┤
│ BANK  │ MIRROR │ SEQOP │ DISSLW │ HAEN │ ODR │ INTPOL │   —   │
└───────┴────────┴───────┴────────┴──────┴─────┴────────┴───────┘
```

- **`bit 7: BANK` (Організація адресного простору)**:
  - `0`: Регістри портів A і B розташовані послідовно в парах (`IODIRA = 0x00`, `IODIRB = 0x01`). Це стандартний режим для роботи з 16-бітними словами, оскільки дозволяє читати та записувати обидва порти A і B через автоінкремент покажчика.
  - `1`: Регістри згруповані в окремі банки за портами (банк Port A: `0x00`..`0x0A`, банк Port B: `0x10`..`0x1A`). Цей режим збережено для зворотної сумісності з 8-бітними драйверами чіпа `MCP23008`.
- **`bit 6: MIRROR` (Об'єднання ліній переривань INTA та INTB)**:
  - `0`: Лінії переривання фізично незалежні (`INTA` сигналізує лише про події Port A, `INTB` — лише про Port B).
  - `1`: Лінії `INTA` та `INTB` внутрішньо з'єднані паралельно. Подія на будь-якому з 16 портів активує обидва виводи одночасно, що дозволяє підключити обидва порти до однієї ніжки мікроконтролера.
- **`bit 5: SEQOP` (Вимкнення автоінкременту покажчика адреси)**:
  - `0`: Автоінкремент увімкнено. Після запису або читання байта покажчик автоматично переходить до наступного регістра.
  - `1`: Автоінкремент вимкнено. Адресний покажчик не змінюється під час багатобайтної транзакції. Це дозволяє безперервно опитувати один і той самий регістр (наприклад, читати потік змін із `GPIOA` без постійного надсилання адреси).
- **`bit 4: DISSLW` (Контроль швидкості наростання лінії SDA)**:
  - `0`: Фільтр швидкості наростання (*Slew Rate Control*) увімкнено (стандарт для режиму I2C Fast Mode 400 кГц).
  - `1`: Фільтр вимкнено (для Standard Mode 100 кГц).
- **`bit 3: HAEN` (Апаратна адресація для версії SPI MCP23S17)**:
  - У I2C-версії MCP23017 цей біт не використовується (апаратна адресація на ніжках A0..A2 увімкнена завжди).
- **`bit 2: ODR` (Тип вихідного каскаду ліній INT)**:
  - `0`: Двотактний активний вихід Push-Pull (рівень визначається бітом `INTPOL`).
  - `1`: Вихід із відкритим стоком (*Open-Drain*). Потребує зовнішнього резистора підтяжки, дозволяє монтувати кілька ліній INT паралельно (Wired-OR).
- **`bit 1: INTPOL` (Полярність виходу INT у режимі Push-Pull)**:
  - `0`: Активний низький рівень (Active-Low, 0 В при виникненні події).
  - `1`: Активний високий рівень (Active-High, VDD при виникненні події).
- **`bit 0`**: Не реалізовано (завжди зчитується як `0`).

#### 3.3. Покроковий алгоритм ініціалізації переривань MCP23017

Щоб сконфігурувати розширювач для обслуговування кнопок з асинхронним перериванням на ніжках `GPA0..GPA3` та світлодіодів на `GPA4..GPA7`, виконують таку послідовність I2C-записів:

1. **Запис у `IOCON` (`0x0A`)**: надсилають `0x44` (встановлені біти `MIRROR=1` та `ODR=1`). Обидва виводи переривання об'єднуються у відкритий стік.
2. **Запис у `IODIRA` (`0x00`)**: надсилають `0x0F` (піни 0..3 — входи, піни 4..7 — виходи).
3. **Запис у `GPPUA` (`0x0C`)**: надсилають `0x0F` (увімкнення внутрішніх підтяжок 100 кОм до VDD на входах кнопок).
4. **Запис у `DEFVALA` (`0x06`)**: надсилають `0x0F` (очікуваний стан спокою для підтягнутих кнопок — логічна `1`).
5. **Запис у `INTCONA` (`0x08`)**: надсилають `0x0F` (порівняння стану входів із регістром `DEFVAL`). Переривання виникне лише тоді, коли кнопку притиснуть до землі (0 В).
6. **Запис у `GPINTENA` (`0x04`)**: надсилають `0x0F` (активація маски переривань для входів 0..3).
7. **Очищення залишкових прапорців**: виконують фіктивне читання регістра `GPIOA` або `INTCAPA`, щоб зняти випадкові переривання, які могли виникнути під час увімкнення живлення.

### 4. Протокол програмного скидання та спеціальні команди

Окрім апаратного скидання через окрему фізичну ніжку `/RESET`, стандарт I2C підтримує спеціальні загальносистемні команди, які розпізнаються більшістю сучасних розширювачів:

#### 4.1. Загальний виклик скидання (General Call Reset)

Мікросхеми сімейств TCA9555 та PCA9554 підтримують команду скидання за загальною адресою `0x00` (*General Call Address*):

```
START -> [Байт 0x00 (General Call)] -> ACK -> [Байт 0x06 (Software Reset)] -> ACK -> STOP
```

Отримавши цю послідовність, внутрішній кінцевий автомат розширювача виконує повне перезавантаження внутрішніх тригерів, аналогічне подачі живлення:
- Регістри конфігурації скидаються в стан за замовчуванням (усі піни переходять у режим входу `0xFF`).
- Регістри вихідних засувок повертаються до стану логічної одиниці.
- Лінії переривання `/INT` переходять у неактивний стан.

Це дозволяє мікроконтролеру відновити початковий стан усіх розширювачів на шині після збою програми за одну коротку транзакцію без смикання апаратних ліній живлення.

#### 4.2. Поведінка вхідних фільтрів викидів (Spike Suppression Filter)

На лініях `SDA` та `SCL` більшості сучасних розширювачів інтегровано апаратні фільтри придушення імпульсних завад (*Spike Suppression*). Внутрішня цифрова схема ігнорує будь-які імпульси напруги тривалістю менше `50 нс`. Це захищає шину від паразитних наведень комутації силових ключів, але вимагає від хост-контролера формування тактових імпульсів SCL тривалістю не менше `t_LOW ≥ 1.3 мкс` у стандартному режимі та `t_LOW ≥ 0.5 мкс` у Fast Mode.

### 5. Часові параметри та вимоги до таймінгів шини

Для забезпечення стабільного обміну на високих швидкостях (Fast Mode 400 кГц та High-Speed 1.7 МГц) цифрова логіка розширювачів вимагає дотримання ряду часових обмежень інтерфейсу I2C:

1. **Час встановлення та утримання умови START (`t_SU:STA` та `t_HD:STA`)**:
   - `t_HD:STA` (Hold Time for START): мінімальний інтервал утримання лінії SDA на нулі до спаду лінії SCL становить `0.6 мкс` у Fast Mode.
   - `t_SU:STA` (Setup Time for Repeated START): мінімальний інтервал від наростання SCL до спаду SDA при формуванні `Sr` становить `0.6 мкс`.
2. **Час дійсності даних (`t_VD:DAT`)**:
   - Максимальний час від спаду SCL до появи валідного рівня на SDA становить `0.9 мкс` у стандартному режимі та `0.45 мкс` у Fast Mode.
3. **Затримка формування сигналу переривання (`t_valid(INT)`)**:
   - Інтервал від зміни фізичного рівня на вході GPIO до спаду напруги на лінії `/INT` становить `≤ 4.0 мкс` для MCP23017 та `≤ 1.0 мкс` для TCA9555. Цей час визначається внутрішньою цифровою фільтрацією та синхронізацією вхідних тригерів.
4. **Час скидання переривання при зчитуванні (`t_clr(INT)`)**:
   - Лінія `/INT` повертається у високий стан (деактивується) на спадному фронті 8-го або 9-го тактового імпульсу SCL байта даних регістра `INTCAP` або `GPIO`.
5. **Вільний час шини між транзакціями (`t_BUF`)**:
   - Мінімальний інтервал між станом STOP попередньої транзакції та сигналом START наступної транзакції становить `4.7 мкс` для 100 кГц та `1.3 мкс` для 400 кГц.

### 6. Порівняльний аналіз сімейств розширювачів за виробниками

Вибір конкретної моделі I2C-розширювача залежить від архітектури системи, кількості ліній та вимог до швидкості й енергоспоживання:

1. **NXP / TI PCF8574 та PCF8575**:
   - *Переваги*: гранично простий протокол без адреси регістра; мінімальний розмір прошивки для керування; висока доступність на ринку.
   - *Недоліки*: слабкий квазідвосторонній вихід (неможливо живити світлодіоди високим рівнем); відсутність регістра полярності та маски переривань; максимальна частота шини лише 100 кГц (400 кГц тільки у версій з індексом T).
2. **Texas Instruments TCA9534, TCA9554 та TCA9555**:
   - *Переваги*: симетричні двотактні Push-Pull виходи до 25 мА; робота від низької напруги живлення (від 1.65 В); широкий робочий температурний діапазон (від -40°C до +125°C); надійний апаратний інтерфейс I2C Fast Mode 400 кГц.
   - *Недоліки*: відсутність вбудованих підтягувальних резисторів на виводах GPIO (потрібні зовнішні резистори для кнопок); відсутність регістра моментального знімка переривань `INTCAP`.
3. **Microchip MCP23008 та MCP23017**:
   - *Переваги*: максимальна функціональна насиченість; програмовані підтяжки 100 кОм на кожному піні; апаратні регістри `DEFVAL`, `INTCON`, `INTF` та `INTCAP`; підтримка швидкості High-Speed до 1.7 МГц; гнучка конфігурація переривань через регістр `IOCON`.
   - *Недоліки*: складніша регістрова карта; більший обсяг коду ініціалізації; чутливість до коректного вибору банку `BANK` при роботі з готовими бібліотеками.

---

### 7. Енергоспоживання та динамічна зміна напруги живлення

У системах з автономним живленням від акумуляторів або з динамічною зміною напруги (*Dynamic Voltage Scaling, DVS*) необхідно враховувати зміни струмів витоку та вхідних порогів:
- При зниженні напруги `VDD` з 5.0 В до 1.8 В типовий опір відкритих польових транзисторів `R_DS(on)` зростає у 2.5–3 рази, що пропорційно збільшує напругу насичення низького рівня `V_OL` при максимальному навантаженні.
- Струм внутрішніх підтяжок `GPPU` у MCP23017 визначається напругою живлення і падає з 50 мкА при 5 В до приблизно 18 мкА при 1.8 В.
- Для мінімізації струму спокою в режимі сну всі невикористані виводи розширювача обов'язково переводять у режим Push-Pull виходу та встановлюють на них рівень `0` або `1`, щоб унеможливити плаваючий стан буферів.
