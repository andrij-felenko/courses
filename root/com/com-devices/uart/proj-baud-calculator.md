# ⚙️ Алгоритм та код обчислення дробового дільника baud

Апаратний генератор швидкості передачі (*Baud Rate Generator*) у складі периферійного модуля UART перетворює високу системну частоту тактування мікроконтролера (`f_CLK`) у точну послідовність тактових імпульсів передискретизації (`f_oversample`). Оскільки бажана швидкість передачі в біт/с (наприклад, 9600, 115200 або 921600 біт/с) рідко є точним дільником частоти системної шини периферії (наприклад, 84 МГц, 72 МГц чи 16 МГц), апаратна частина використовує комбінацію **цілочисельного дільника (мантіси)** та **дробового дільника (фракції)**.

У цій практичній вставці детально розібрано математичну модель розрахунку апаратних регістрів, алгоритми аналізу квантування й часового джиттеру, вплив нестабільності кварцових та RC-генераторів на збереження синхронізації кадру, а також надано повний робочий код двома мовами (C та ідіоматичною C++). Наведений код виконує автоматичний розрахунок конфігураційного значення регістра `BRR` (*Baud Rate Register*) із суворим контролем гранично допустимої похибки.

---

### Математична модель апаратного дільника частоти

Загальна формула зв'язку між частотою тактування периферійної шини `f_CLK`, коефіцієнтом передискретизації `OVER` (зазвичай 16 або 8) та цільовою швидкістю `Baud` виглядає так:

```
USARTDIV = f_CLK / (OVER × Baud)
```

Значення `USARTDIV` є дійсним дробовим числом, яке складається з цілої частини `DIV_Mantissa` та дробової частини `DIV_Fraction`. Розрядність дробової частини залежить від конкретної архітектури кремнію. Наприклад, у більшості родин ARM Cortex-M під дробову частину виділяється **4 біти** (що відповідає сітці з 16 часток, тобто кроку 1/16).

Формула розкладу дійсної величини `USARTDIV` на відповідні регістрові значення:

```
DIV_Mantissa = floor(USARTDIV)
DIV_Fraction = round((USARTDIV - DIV_Mantissa) × 16)
```

Якщо при округленні `DIV_Fraction` досягає значення 16, воно переповнюється в нуль, а `DIV_Mantissa` збільшується на 1.

Підсумкове 16-бітове значення, яке записається в конфігураційний регістр `BRR`:

```
BRR = (DIV_Mantissa << 4) | (DIV_Fraction & 0x0F)
```

### Порівняльний аналіз архітектур дільників у різних мікроконтролерах

Різні родини мікроконтролерах вирішують задачу ділення частоти тактування по-різному:

1. **Архітектура AVR (ATmega328P / ATmega2560):**
   - Використовує тільки цілочисельний 12-бітовий дільник `UBRR`.
   - Формула: `UBRR = (f_CLK / (16 × Baud)) - 1`.
   - Нестача: На частоті 16 МГц при швидкості 115 200 біт/с `UBRR = 7.68`, що при округленні до 8 дає фактичну швидкість 111 111 біт/с і похибку **-3.55%** (перевищує норму ±2.5%).

2. **Архітектура ARM Cortex-M (STM32, NXP LPC):**
   - Використовує мантісу й 4-бітову фракцію у регістрі `BRR`.
   - Формула: `USARTDIV = f_CLK / (16 × Baud)`.
   - Перевага: Крок ділення зменшується в 16 разів, знижуючи похибку до **-0.08%** на тій самій частоті.

3. **Архітектура ESP32 / ESP32-S3:**
   - Використовує цілочисельний дільник `clk_div` (12 бітів) та дробовий дільник на базі масиву часток `a/b` (6 бітів).
   - Забезпечує практично 0% похибки на будь-якій швидкісті аж до 5 Мбіт/с.

### Обчислення реальної швидкості та відсотка похибки

Оскільки дробова частина квантується з кроком 1/16, фактична швидкість `Baud_actual`, яку згенерує апаратний блок, трохи відрізняється від запитаної `Baud_target`.

Кроки обчислення реальної швидкості та похибки:

```
DIV_actual = DIV_Mantissa + (DIV_Fraction / 16.0)
Baud_actual = f_CLK / (OVER × DIV_actual)
Error_percent = ((Baud_actual - Baud_target) / Baud_target) × 100%
```

#### Критерій допустимості похибки та бюджет затримок
Для надійної прийом-передачі 10-бітового кадру UART (8N1: 1 старт-біт, 8 бітів даних, 1 стоп-біт) загальна накопичена часова розбіжність між передавачем і приймачем не повинна перевищувати півбіта наприкінці кадру (5%). Це дає гранично допустиму похибку генератора швидкості **не більше ±2.5%** на кожній стороні каналу зв'язку. Якщо розрахована похибка перевищує 2.5%, зв'язок стає нестабільним і супроводжується помилками кадру (*Framing Error*).

#### Математичне виведення межі допустимого відхилення частоти
Розглянемо кадр 8N1 тривалістю 10 бітових інтервалів. Приймач започатковує відліки зі спадаючого фронту старт-біта (t = 0). Останній замір 8-го біта даних (D7) відбувається на 9.5 бітовому інтервалі від початку кадру (t = 9.5 × T_bit).

Щоб замір на 9.5-му бітовому інтервалі влучив усередину 8-го біта даних (між 9.0 та 10.0 бітовими інтервалами), абсолютна часова розбіжність Δt повинна задовольняти нерівність:

```
-0.5 × T_bit < 9.5 × ΔT_bit < +0.5 × T_bit
```

Ділення всіх частин нерівності на 9.5 × T_bit дає граничне відносне відхилення частот передавача й приймача:

```
| Δf / f | < 0.5 / 9.5 = 5.26%
```

Якщо розподілити цю похибку порівну між передавачем і приймачем (з урахуванням температурного дрейфу кварцу), максимальне допустиме відхилення для кожного пристрою становить **±2.5%**.

### Особливості розрахунку LPUART від низкочастотного кварцу (32.768 кГц)

У малоспоживаючих бездротових пристроях (наприклад, автономних давачах IoT) головний високочастотний генератор повністю вимикається для економії енергії. Периферійний модуль **LPUART** (*Low-Power UART*) продовжує працювати від годинникового кварцового резонатора `LSE` з частотою **32 768 Гц**.

Особливості математики LPUART:
- Для забезпечення швидкості 9600 біт/с при частоті тактування 32 768 Гц використовується розширений 20-бітовий дробовий дільник із масштабуванням 8192.
- Формула розрахунку `LPUARTDIV`:

```
LPUARTDIV = (256 × f_LSE) / Baud
          = (256 × 32768) / 9600
          = 8388608 / 9600 = 873.8133...
```

- Це дозволяє отримувати стандартні швидкості 300, 1200, 2400 та 9600 біт/с без запуску основного PLL мікроконтролера, знижуючи споживання струму з міліампер до одиниць мікроампер.

### Автоматичне визначення швидкості (Auto-Baud Rate Detection)

У деяких протоколах (наприклад, у мережах LIN або сервісних bootloader-модулях) швидкість передачі заздалегідь невідома. Модуль UART підтримує апаратний режим **Auto-Baud Detection**:

1. **Режим вимірювання за спадаючими фронтами (Mode 0 / Mode 1):** Приймач очікує надходження спеціального еталонного символу `0x55` (двійкове `01010101`). Оскільки в цьому символі логічні 0 та 1 чергуються кожен біт, апаратна схема вимірює тривалість між спадаючими фронтами за допомогою внутрішнього таймера.
2. **Розрахунок дільника у реальному часі:** Апаратний блок ділить виміряний інтервал часу на кількість бітів і самостійно записує отримане значення мантіси й фракції в регістр `BRR`. Процесор отримує прапорець `ABRF` (*Auto-Baud Rate Flag*) і продовжує прийом вже на автоматично підлаштованій швидкості.

### Специфічні та нестандартні швидкості передачі (MIDI, DMX512, LIN)

Окрім стандартного ряду RS-232 (9600, 115200 тощо), у промисловості та мультимедіа застосовують фіксовані нестандартні швидкості:

- **Музичний інтерфейс MIDI:** Швидкість ровно **31 250 біт/с** (отримується діленням 8 МГц на 16 × 16 = 256).
- **Світловий протокол DMX512:** Швидкість **250 000 біт/с** (для керування софітами та прожекторами).
- **Автомобільна шина LIN:** Швидкості **19 200 біт/с** або **9600 біт/с** з підвищеними вимогами до точності тактування.

Наведений нижче алгоритм універсально обчислює `BRR` для будь-якої з цих швидкостей.

### Програмна реалізація програмного біт-бенгінгу проти апаратного BRR

Для порівняння зрозуміємо різницю між апаратним дільником BRR та програмним формуванням швидкості (Bit-Banging):

- **Bit-Banging (Програмне нарізання часу):** Процесор використовує мікросекундну затримку (`delay_us()`) для установки стану GPIO-виводу. На швидкості 115 200 біт/с тривалість біта становить 8.68 мікросекунд. Будь-яке випадкове переривання від таймера чи DMA зміщує момент перемикання виводу на 1-2 мікросекунди, створюючи величезний джиттер.
- **Апаратний модуль BRR:** Дільник діє на рівні апаратного таймера кремнію. Тактові імпульси формуються строго за кожен такт шини без найменшого залучення процесора.

### Цілочисельна математика з округленням без плаваючої крапки

У ресурсообмежених вбудованих системах (наприклад, на базі ядер ARM Cortex-M0 або 8-бітових мікроконтролерів), використання бібліотек математики з плаваючою крапкою (`float` / `double`) призводить до роздування розміру прошивки на 4–10 кілобайтів та споживання десятків додаткових тактів ЦП.

Для ефективного обчислення дільника `BRR` застосовують **цілочисельну арифметику з масштабуванням**:

1. Замість ділення `f_CLK / (16 * Baud)` обчислюють масштабоване число `USARTDIV_x16`:

```
USARTDIV_x16 = (2 × f_CLK + Baud) / (2 × Baud)   [для 16x oversampling]
```

Додавання `Baud` у чисельнику виступає цілочисельним аналогом округлення до найближчого цілого (`round`).

2. Після цього мантісу та фракцію виділяють простими бітовими операціями:

```
DIV_Mantissa = USARTDIV_x16 / 16
DIV_Fraction = USARTDIV_x16 % 16
BRR = (DIV_Mantissa << 4) | (DIV_Fraction & 0x0F)
```

Цей цілочисельний алгоритм працює за **1-2 такти процесора** і не потребує бібліотек FPU.

### Аналіз джиттеру та фазових пульсацій дробового дільника

Дробовий дільник у складі UART працює за принципом тактового заковтування або чергування коефіцієнтів ділення. Якщо розраховане значення `DIV_Fraction` дорівнює 8 (що відповідає дробу 8/16 = 0.5), апаратний лічильник ділить системну частоту на змінне значення: один такт ділення виконується з коефіцієнтом `DIV_Mantissa`, а наступний — з коефіцієнтом `DIV_Mantissa + 1`.

У середньому за 16 тактів передискретизації результуюча частота виходить точно рівною бажаній. Проте на рівні окремих бітових інтервалів виникає часовий **джиттер (джатер)** — невеликі пульсації тривалості біта.

Завдяки тому, що приймач UART використовує 16-кратну передискретизацію та бере відліки в середині бітового інтервалу (на 7-му, 8-му та 9-му такті), цей мікроскопічний джиттер повністю поглинається внутрішнім фільтром і не впливає на якість прийому.

### Приклад покрокового розрахунку для частоти 42 МГц

**Вхідні дані:**
- Частота шини периферії: `f_CLK = 42 МГц = 42 000 000 Гц`.
- Бажана швидкість: `Baud_target = 115 200 біт/с`.
- Передискретизація: `OVER = 16`.

**Покроковий розрахунок:**

```
1. Знаходимо дійсне значення дільника:
   USARTDIV = 42000000 / (16 × 115200)
            = 42000000 / 1843200
            = 22.78645833...

2. Виділяємо цілу частину (мантісу):
   DIV_Mantissa = floor(22.78645833) = 22 = 0x16

3. Обчислюємо дробову частину в 16-х частках:
   Fraction_Raw = (22.78645833 - 22) × 16
                = 0.78645833 × 16
                = 12.583333...

4. Округлюємо до найближчого цілого:
   DIV_Fraction = round(12.583333) = 13 = 0x0D

5. Пакуємо в регістр BRR:
   BRR = (22 << 4) | 13
       = (0x16 << 4) | 0x0D
       = 0x0160 | 0x000D = 0x016D (365 у десятковій системі)

6. Перевіряємо фактичну швидкість та похибку:
   DIV_actual = 22 + (13 / 16.0) = 22.8125
   Baud_actual = 42000000 / (16 × 22.8125)
               = 42000000 / 365.0
               = 115068.49 біт/с

7. Оцінюємо похибку:
   Error = ((115068.49 - 115200) / 115200) × 100%
         = (-131.51 / 115200) × 100%
         = -0.114%  (Входить у допустиму норму ±2.5%)
```

### Аналіз крайніх випадків та вибрацій дільника

Під час проєктування розрахункового модуля розробник мусить враховувати чотири фундаментальні обмеження, пов'язані з фізикою кремнію:

1. **Мінімальний коефіцієнт ділення:** Значення мантіси `DIV_Mantissa` не може бути рівним 0. Якщо обрана частота `f_CLK` занадто мала, а швидкість `Baud` занадто висока (наприклад, `f_CLK = 1 МГц` при `Baud = 921 600`), мантіса дорівнюватиме 0. Драйвер мусить відхиляти таку конфігурацію як апаратно неможливу.
2. **Переповнення розрядності регістра BRR:** Більшість 32-бітових мікроконтролерів виділяють під регістр BRR 16 бітів. Це означає, що значення `BRR` не може перевищувати `0xFFFF` (65535). Якщо `f_CLK = 160 МГц`, а `Baud = 300 біт/с`, дільник перевищить розрядність регістра.
3. **Режим 8× oversampling проти 16× oversampling:** Якщо похибка генерації на 16× oversampling перевищує 2.5%, багато мікроконтролерів дозволяють перемкнути модуль UART у режим 8× oversampling (`OVER8 = 1`). Це подвоює частоту максімуму baud та зменшує крок мантіси, але знижує фільтруючу здатність приймача проти шумів.
4. **Нестабільність внутрішніх RC-генераторів:** Внутрішні RC-осцилятори мікроконтролерів (HSI) мають похибку частоти від ±1% до ±3% залежно від температури кристала. Якщо похибка дільника складає -1.5%, а RC-генератор відхилився на +2.0%, сумарна розбіжність перевищить 3.5%, викликаючи хаотичні спотворення даних. Для високих швидкостей (від 115200 біт/с і вище) застосування зовнішнього кварцового резонатора (HSE) є обов'язковим.

### Стратегія розробки модульних тестувань (Unit Testing)

Для гарантії надійності розрахункового модуля в серійних продуктах розробники створюють набір модульних тестів, які перевіряють виконання таких умов:

- Перевірка стандартизованого ряду швидкостей (9600, 19200, 38400, 57600, 115200, 230400, 460800, 921600 біт/с).
- Перевірка обробки нульових параметрів (`pclk_hz == 0` або `target_baud == 0`).
- Перевірка коректного відхилення конфігурації, коли похибка перевищує 2.5%.
- Перевірка граничного значення мантіси `0xFFFF`.

Покриття автоматизованими юніт-тестами алгоритму обчислення BRR гарантує відсутність прихованих багів при портуванні проекту на нові родини мікроконтролерів із різними частотами шин.

### Повна програмна реалізація розрахункового модуля

Нижче подано повний вихідний код модуля обчислення дільника `BRR` з підтримкою режимів 16× та 8× oversampling, розрахунком похибки та контролем виходу за межі діапазонів. Реалізація подана двома мовами — C та ідіоматичною C++.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>
#include <math.h>
#include <stddef.h>

/* Конфігураційне зведення дільника UART */
typedef struct {
    uint32_t brr_value;       /* Значення для запису в регістр BRR */
    uint32_t actual_baud;     /* Фактична згенерована швидкість */
    float error_percent;      /* Відсоток похибки відносно цілі */
    uint8_t oversampling;     /* Використаний коефіцієнт (16 або 8) */
    bool is_valid;            /* true, якщо похибка у межах ±2.5% */
} uart_baud_config_t;

/**
 * @brief Обчислює значення регістра BRR для UART з перевіркою похибки
 * @param pclk_hz Частота тактування периферійної шини у Гц
 * @param target_baud Бажана швидкість передачі в біт/с
 * @param allow_oversample8 Дозвіл перемикання на 8x oversampling при високій похибці
 * @param out_config Вказівник на структуру для збереження результату
 * @return true при успішному розрахунку, false при некоректних вхідних даних
 */
bool uart_calculate_brr(uint32_t pclk_hz, uint32_t target_baud, bool allow_oversample8, uart_baud_config_t *out_config) {
    if (pclk_hz == 0 || target_baud == 0 || out_config == NULL) {
        return false;
    }

    uint8_t selected_oversample = 16;
    uint32_t mantissa = 0;
    uint32_t fraction = 0;
    float best_error = 100.0f;
    uint32_t best_brr = 0;
    uint32_t best_actual_baud = 0;

    /* Пробуємо 16x oversampling, а при необхідності — 8x */
    for (uint8_t os = 16; os >= 8; os -= 8) {
        if (os == 8 && !allow_oversample8) {
            break;
        }

        /* USARTDIV = pclk_hz / (os * target_baud) */
        float usartdiv = (float)pclk_hz / (float)(os * target_baud);
        uint32_t m = (uint32_t)floorf(usartdiv);
        float frac_part = usartdiv - (float)m;

        uint32_t f = 0;
        if (os == 16) {
            f = (uint32_t)roundf(frac_part * 16.0f);
            if (f >= 16) { f = 0; m += 1; }
        } else {
            f = (uint32_t)roundf(frac_part * 8.0f);
            if (f >= 8) { f = 0; m += 1; }
        }

        /* Перевірка меж мантіси */
        if (m == 0 || m > 0xFFFF) {
            continue;
        }

        /* Фактичний дільник і швидкість */
        float div_actual = (os == 16) ? ((float)m + ((float)f / 16.0f)) : ((float)m + ((float)f / 8.0f));
        uint32_t actual_baud = (uint32_t)roundf((float)pclk_hz / ((float)os * div_actual));

        float error = fabsf(((float)actual_baud - (float)target_baud) / (float)target_baud) * 100.0f;

        if (error < best_error) {
            best_error = error;
            best_actual_baud = actual_baud;
            selected_oversample = os;
            if (os == 16) {
                best_brr = (m << 4) | (f & 0x0F);
            } else {
                /* Для 8x фракція пакується в 3 біти (0..2) */
                best_brr = (m << 4) | (f & 0x07);
            }
        }

        if (best_error <= 2.5f) {
            break; /* Допустима похибка досягнута */
        }
    }

    out_config->brr_value = best_brr;
    out_config->actual_baud = best_actual_baud;
    out_config->error_percent = best_error;
    out_config->oversampling = selected_oversample;
    out_config->is_valid = (best_error <= 2.5f);

    return out_config->is_valid;
}
```

```cpp
#include <cstdint>
#include <cmath>
#include <expected>
#include <system_error>

enum class BaudCalcError {
    InvalidParameters,
    PrescalerOutOfRange,
    ToleranceExceeded
};

struct BaudConfig {
    uint32_t brr_register{0};
    uint32_t actual_baud{0};
    float error_percent{0.0f};
    uint8_t oversampling{16};
};

class BaudRateCalculator {
public:
    static constexpr float MaxTolerancePercent = 2.5f;

    /**
     * @brief Обчислює конфігурацію BRR із суворою перевіркою типом C++23 std::expected
     */
    [[nodiscard]] static std::expected<BaudConfig, BaudCalcError> calculate(
        uint32_t pclk_hz, 
        uint32_t target_baud, 
        bool allow_oversample8 = false) noexcept 
    {
        if (pclk_hz == 0 || target_baud == 0) {
            return std::unexpected(BaudCalcError::InvalidParameters);
        }

        BaudConfig best_config{};
        float min_error = 100.0f;
        bool found = false;

        const uint8_t min_os = allow_oversample8 ? 8 : 16;

        for (uint8_t os = 16; os >= min_os; os -= 8) {
            const float usartdiv = static_cast<float>(pclk_hz) / static_cast<float>(os * target_baud);
            
            auto mantissa = static_cast<uint32_t>(std::floor(usartdiv));
            const float fraction_part = usartdiv - static_cast<float>(mantissa);
            const float frac_scale = static_cast<float>(os);
            auto fraction = static_cast<uint32_t>(std::round(fraction_part * frac_scale));

            if (fraction >= os) {
                fraction = 0;
                mantissa += 1;
            }

            if (mantissa == 0 || mantissa > 0xFFFF) {
                continue;
            }

            uint32_t brr = 0;
            if (os == 16) {
                brr = (mantissa << 4) | (fraction & 0x0F);
            } else {
                brr = (mantissa << 4) | (fraction & 0x07);
            }

            const float div_actual = static_cast<float>(mantissa) + (static_cast<float>(fraction) / static_cast<float>(os));
            const auto actual_baud = static_cast<uint32_t>(std::round(static_cast<float>(pclk_hz) / (static_cast<float>(os) * div_actual)));

            const float diff = static_cast<float>(actual_baud) - static_cast<float>(target_baud);
            const float error_pct = std::abs((diff / static_cast<float>(target_baud)) * 100.0f);

            if (error_pct < min_error) {
                min_error = error_pct;
                best_config = BaudConfig{
                    .brr_register = brr,
                    .actual_baud = actual_baud,
                    .error_percent = error_pct,
                    .oversampling = os
                };
                found = true;
            }

            if (min_error <= MaxTolerancePercent) {
                break;
            }
        }

        if (!found) {
            return std::unexpected(BaudCalcError::PrescalerOutOfRange);
        }

        if (best_config.error_percent > MaxTolerancePercent) {
            return std::unexpected(BaudCalcError::ToleranceExceeded);
        }

        return best_config;
    }
};
```

### Основні висновки для розробника

1. **Нехтування похибкою — головна причина збоїв на високих baud:** При налаштуванні нестандартних частот тактування (наприклад, 8 МГц від внутрішнього RC-генератора HSI) похибка генерації 115200 біт/с може перевищити 3.5%. Код повинен явним чином перевіряти похибку перед ініціалізацією порту.
2. **Використання дробового дільника є обов'язковим на високих швидкостях:** У мікроконтролерах без дробової частини (чисто цілочисельний прескалер) вибір швидкості 115200 або 921600 біт/с на частотах 16 МГц дає неприпустимі похибки. Дробовий дільник зменшує дискретність частоти в 16 разів, гарантуючи попадання у вказаний допуск.
3. **Автоматична перевірка допуску на етапі ініціалізації:** Вбудована перевірка у системній бібліотеці чи драйвері запобігає виходу виробу в серійне виробництво з прихованими дефектами синхронізації.
