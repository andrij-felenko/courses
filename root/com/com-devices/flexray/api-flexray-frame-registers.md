# 📋 Інтерфейс та структура регістрів кадру FlexRay

Контролер FlexRay (наприклад, NXP MFR4310, Freescale MFR4300, E-Ray від Robert Bosch GmbH або периферійні модулі в мікроконтролерах Infineon Aurix TC3xx та STMicroelectronics SPC5) взаємодіє з хост-процесором через спеціалізований інтерфейс CHI (Controller Host Interface). Цей інтерфейс включає двопортову оперативну пам'ять (Message RAM), регістри конфігурації кластера, регістри управління автомата станів POC (Protocol Operation Control) та регістри обробки переривань.

Для розробки низькорівневих драйверів (AUTOSAR FlexRay Driver / Fr) необхідно чітко розуміти бітовий розклад заголовка кадру, розподіл пам'яті буферів повідомлень та структуру конфігураційних регістрів контролера.

---

## Бітовий розклад заголовка кадру FlexRay (Header Segment)

Заголовок кадру має розмір рівно 5 байтів (40 бітів) і передається у форматі Big-Endian (старший біт MSB передається першим).

```
   Біт 39    38    37    36    35    34                    24 23                    12 11           1  0
  +-------+-----+-----+-----+-----+--------------------------+--------------------------+---------------+-----+
  | RES   | PPI | NFI | SFI | SFI |      Frame ID (11b)      |   Payload Length (12b)   | Header CRC(11b)| CC  |
  | (1b)  | (1b)| (1b)| (1b)| (1b)|    Слот 1 .. 2047         |   Кількість 16-біт слів   | Поліном 0x385 |(6b) |
  +-------+-----+-----+-----+-----+--------------------------+--------------------------+---------------+-----+
```

### Деталізація службових полів заголовка:

- **RES (Reserved Bit, 1 біт):** Зарезервоване поле. Завжди записується як `0`. Прийомом вимагає перевірки на `0` для забезпечення зворотної сумісності з майбутніми версіями стандарту.
- **PPI (Payload Preamble Indicator, 1 біт):** Прапорець наявності службової преамбули у векторі даних. У статичному сегменті значення `1` показує, що перші байти корисного навантаження (від 2 до 12 байтів) зайняті вектором мережевого управління (Network Management Vector). У динамічному сегменті значення `1` показує, що перші 2 байти даних містять ідентифікатор повідомлення (Message ID).
- **NFI (Null Frame Indicator, 1 біт):** Індикатор порожнього кадру. Значення `1` вказує на наявність дійсних даних у сегменті Payload. Значення `0` сигналізує про порожній кадр (Null Frame) — у цьому разі передається лише заголовок та CRC, а байти даних ігноруються приймачем. Порожні кадри передаються у статичних слотах, коли буфер передачі не оновлено новими даними.
- **Sync Frame Indicator (1 біт):** Прапорець кадру синхронізації. Значення `1` позначає, що цей кадр передається вузлом синхронізації (Sync Node) і бере участь у глобальному обчисленні корекції годинників (Offset та Rate) на всіх контролерах мережі.
- **Startup Frame Indicator (1 біт):** Прапорець кадру холодного старту. Значення `1` позначає, що кадр використовується для первинної ініціалізації та захоплення тактової частоти мережі при її включенні. Тільки кадри з `Startup = 1` мають право ініціювати лічильник циклів невизначеної мережі.
- **Frame ID (11 бітів):** Номер слота передачі (`1 .. 2047`). У статичному сегменті `Frame ID` визначає точний статичний слот TDMA, у якому передається кадр. У динамічному сегменті `Frame ID` задає пріоритет FTDMA (менше значення відповідає вищому пріоритету).
- **Payload Length (12 бітів):** Довжина корисного навантаження, виражена у 16-бітних словах (`0 .. 127` слів, що відповідає `0 .. 254` байтам). Усі кадри статичного сегмента мають мати однакову довжину Payload Length, задану глобальним параметром `gPayloadLengthStatic`.
- **Header CRC (11 бітів):** Контрольна сума заголовка. Обчислюється за поліномом `0x385` із початковим значенням `0x01A` над полями Sync Indicator, Startup Indicator, Frame ID та Payload Length.
- **Cycle Count (6 бітів):** Номер комунікаційного циклу (`0 .. 63`), у якому відправлено кадр.

## Регістрова карта контролера FlexRay (CHI Register Map)

Регістри контролера FlexRay розбито на чотири основні функціональні групи: конфігурація кластера, управління автоматою POC, статус шини та інтерфейс буферів повідомлень.

### 1. Регістри конфігурації кластера (Cluster Configuration Registers)

Ці регістри програмуються хост-процесором у стані POC `CONFIG` і визначають глобальну часову сітку всієї мережі FlexRay:

- **SUCC1 (Symbol Window & Cycle Execution Control):**
  - `CMD[3:0]` — команда управління POC (`0x1`: CONFIG, `0x2`: READY, `0x3`: WAKEUP, `0x4`: RUN, `0x7`: FREEZE).
  - `PBSY` — прапорець зайнятості контролера обробкою команди.
  - `TXST` — дозвіл передачі кадрів у статичному сегменті.
  - `TXD` — дозвіл передачі кадрів у динамічному сегменті.
- **SUCC2 (Clock Synchronization Control):**
  - `LTG[3:0]` — кількість втрачених кадрів синхронізації до виходу в аварійний стан `NORMAL PASSIVE`.
  - `LTGN[3:0]` — кількість втрачених кадрів синхронізації до переходу в стан `HALT`.
- **SUCC3 (Startup Control):**
  - `WCFG` — вибір режиму запуска (0: пасивна інтеграція Listen; 1: активний ColdStart).
- **PRTC1 (Physical Layer Protocol Control 1):**
  - `TSPX[5:0]` — тривалість статичного слота `gdStaticSlot` у макротакті (MT).
  - `BRP[1:0]` — дільник прескалера локального генератора для формування мікротакту (µt).
- **PRTC2 (Physical Layer Protocol Control 2):**
  - `MSL[11:0]` — тривалість динамічного мініслота `gdMinislot` у макротакті.
  - `NMS[13:0]` — загальна кількість мініслотів у динамічному сегменті `gNumberOfMinislots`.

## Пам'ять буферів повідомлень (Message RAM Layout)

Для обміну даними контролер FlexRay виділяє область двопортової пам'яті Message RAM. Кожен буфер повідомлення (Message Buffer, MB) має розмір від 16 до 264 байтів залежно від конфігурації і складається з трьох послідовних секцій:

```
+-------------------------------------------------------------------+
|                     MESSAGE BUFFER IN RAM                         |
+--------------------------+--------------------+-------------------+
| Header Section (4 Words) | Data Section       | Status Section    |
| (Control & Filter Bits)  | (Payload Bytes)    | (Slot Status)     |
+--------------------------+--------------------+-------------------+
```

### Сруктура Header Section буфера повідомлень:

- **Word 0:**
  - `CH[1:0]` — маска каналу (`01`: Channel A, `10`: Channel B, `11`: Channels A & B).
  - `FID[10:0]` — Frame ID кадру (`1 .. 2047`).
  - `CYC[6:0]` — фільтр за номером циклу (Base Cycle + Cycle Repetition `1, 2, 4, 8, 16, 32, 64`).
- **Word 1:**
  - `PLC[6:0]` — конфігурована довжина корисного навантаження в словах (Payload Length).
  - `HCRC[10:0]` — розрахований Header CRC кадру.
- **Word 2:**
  - `DPTR[15:0]` — вказівник на початок області даних (Data Section) у пам'яті Message RAM.
- **Word 3:**
  - `TXM` — режим передачі (0: реконфігурований буфер; 1: постійний виділений буфер).
  - `MBI` — прапорець дозволу переривання при передачі/прийомі цього буфера.

## Автомат станів POC та команди управління

Перехід контролера між станами виконується шляхом запису команд у поле `SUCC1.CMD`:

```
                    +-----------------------+
                    |  DEFAULT CONFIG STATE |
                    +-----------+-----------+
                                | SUCC1.CMD = 0x1 (CONFIG)
                                v
                    +-----------------------+
                    |     CONFIG STATE      |
                    +-----------+-----------+
                                | SUCC1.CMD = 0x2 (READY)
                                v
                    +-----------------------+
                    |     STANDBY STATE     |
                    +-----------+-----------+
                                | SUCC1.CMD = 0x4 (RUN)
                                v
                    +-----------------------+
                    |     STARTUP STATE     |
                    | (Integration/ColdStart|
                    +-----------+-----------+
                                | Clock Sync Locked
                                v
                    +-----------------------+
                    |  NORMAL ACTIVE STATE  |
                    +-----------------------+
```

### Крайові випадки та обробка помилок у регістрах статусу:

1. **Помилка Header CRC (Header CRC Error):** Якщо розрахований приймачем Header CRC не збігається зі значенням у кадри, контролер відкидає кадр, виставляє прапорець `SIR.HCE` та не оновлює відповідний буфер у Message RAM.
2. **Втрата синхронізації (Clock Sync Loss):** Якщо протягом `SUCC2.LTG` послідовних циклів контролер не приймає мінімально необхідну кількість Sync-кадрів, POC автоматично переходить зі стану `NORMAL ACTIVE` у `NORMAL PASSIVE`, де передача даних вимикається, а прийом продовжується. Якщо розсинхронізація триває понад `SUCC2.LTGN` циклів, контролер переходить у стан `HALT`.
3. **Конфлікт кадру холодного старту (ColdStart Collision):** Якщо два ColdStart-вузли одночасно надсилають CAS-символ, контролер виявляє колізію на лінії, скасовує процедуру старту, повертається в стан `LISTEN` і чекає випадковий інтервал часу перед повторною спробою.
