# 🧮 Алгоритм розподіленої синхронізації годинників у FlexRay

У мережах із часовим розділенням каналів за методом TDMA (Time-Division Multiple Access) кожен вузол зобов'язаний починати й завершувати передачу кадрів у суворо визначені часові інтервали. Оскільки локальні генератори частоти (кварцові резонатори) у різних електронних блоках керування (ECU) мають неминучі фізичні відхилення частоти через температурний дрейф, технологічні допуски виробництва та старіння компонентів, без постійного вирівнювання їхній локальний відлік часу неминуче розходиться. 

Припускаючи, що кварцовий резонатор автомобільного електронного блоку має відносну стабільність частоти `±50 ppm` (мільйонних часток, parts per million), за один комунікаційний цикл тривалістю `5 мс` відхилення часу двох незахищених годинників може досягти:

```
Δt_drift = 2 · (50 · 10⁻⁶) · (5 · 10⁻³ s) = 0.5 мкс = 500 нс
```

При швидкості передачі `10 Мбіт/с` тривалість одного біта становить рівно `100 нс`. Зміщення відліку на `500 нс` означає, що приймальний вузол зсунеться на 5 повних бітових інтервалів відносно відправника, повністю зруйнувавши детермінований розклад статичних слотів та спричинивши накладання кадрів сусідніх вузлів.

Для розв'язання цієї проблеми FlexRay застосовує повністю розподілений алгоритм синхронізації годинників без використання виділеного центрального майстра (Master), що виключає появу єдиної точки відмови (Single Point of Failure). Синхронізація спирається на двоуровневу часову ієрархію вузла та обчислення двох типів похибок: фазової (Offset) та частотної (Rate).

---

## Часова ієрархія: Мікротакти та Макротакти

Кожен контролер FlexRay оперує двома автономними шкалами часу:

1. **Мікротакт (Microtick, µt):** Незмінна апаратна одиниця часу, яка повністю визначається локальним кварцевим резонатором контролера та дільником частоти (наприклад, `1 µt = 12.5 нс` при частоті генератора 80 МГц). Мікротакт є найменшим дискретом часу вузла і не підлягає підлаштуванню.
2. **Макротакт (Macrotick, MT):** Глобальна синхронізована одиниця часу всієї мережі FlexRay. Тривалість одного макротакту є однаковою для всіх вузлів (типово `1.0 мкс`) і складається з певної цілої або дробової кількості мікротактів.

Кількість мікротактів у одному макротакті для вузла `i` визначається як:

```
N_µt(i) = T_MT / T_µt(i)
```

Оскільки частоти кварців відрізняються, чисте номінальне число `N_µt` є дробовим. Алгоритм синхронізації динамічно додає або віднімає мікротакти з макротактів для компенсації частотного дрейфу.

## Вимірювання часових відхилень у статичному сегменті

Під час статичного сегмента комунікаційного циклу виділені вузли синхронізації (Sync Nodes, від 2 до 15 вузлів у кластері) надсилають синхронізаційні кадри (Sync Frames) у належні їм статичні слоти.

Кожен приймальний вузол зчитує точний момент очікуваного приходу кадру `T_expected` (виражений у макротактному лічильнику та мікротактному залишку) та фактичний момент спостереження першого спадного фронту послідовності Byte Start Sequence (BSS) кадру `T_observed`.

Відхилення часу приходу кадру від Sync-вузла `k` обчислюється як різниця:

```
ΔT[k] = T_observed[k] − T_expected[k]
```

Значення `ΔT[k]` виражається у внутрішніх мікротактах (µt) вузла. Позитивне значення означає, що годинник відправника поспішає відносно приймача, а негативне — що відправник запізнюється. За один комунікаційний цикл вузол формує масив виміряних відхилень:

```
M = { ΔT[1], ΔT[2], ..., ΔT[k] }
```

## Алгоритм усереднення з відсіканням крайніх значень (Fault-Tolerant Midpoint, FTM)

Для захисту від збоїв окремих вузлів або викривлення сигналів на лінії FlexRay застосовує алгоритм Fault-Tolerant Midpoint (FTM). Алгоритм відкидає найменші та найбільші значення у відсортованому масиві вимірювань, а для решти значень обчислює середнє арифметичне.

Процедура обчислення FTM для масиву M із `k` елементів:

1. Сортування масиву виміряних відхилень за зростанням:
   ```
   M_sorted = { ΔT_(1), ΔT_(2), ..., ΔT_(k) }    де ΔT_(1) ≤ ΔT_(2) ≤ ... ≤ ΔT_(k)
   ```
2. Визначення кількості відсікуваних крайніх елементів `p` залежно від загальної кількості Sync-вузлів `k`:
   - Якщо `k = 1` або `2`: `p = 0` (відсікання відсутнє);
   - Якщо `3 ≤ k ≤ 7`: `p = 1` (відсікається 1 найменше і 1 найбільше значення);
   - Якщо `8 ≤ k ≤ 15`: `p = 2` (відсікається по 2 крайніх значення).

3. Обчислення зваженої середньої точки (Fault-Tolerant Midpoint):
   ```
   FTM(M) = ( ΔT_(p + 1) + ΔT_(k − p) ) / 2
   ```

Математично доведено, що якщо в мережі з `k` вузлів синхронізації присутні не більше ніж `p` некоректних відліків (візантійські помилки, апаратні збої генератора, наводки завад), викривлені значення потрапляють на краї відсортованого масиву `M_sorted` і повністю відсікаються алгоритмом FTM.

## Детальний числовий приклад обчислення корекцій

Розглянемо приклад для мережі з `k = 5` Sync-вузлами. Відповідно до специфікації, параметр відсікання становить `p = 1`.

Припустимо, що приймальний вузол за поточний комунікаційний цикл опитав 5 Sync-кадрів та виміряв наступні часові відхилення у своїх мікротактах:
- `ΔT[1] = +4 µt` (Sync-вузол №1 трішки поспішає);
- `ΔT[2] = -2 µt` (Sync-вузол №2 трішки запізнюється);
- `ΔT[3] = +18 µt` (Аварійний збійний відлік від Sync-вузла №3 із пошкодженим кварцом);
- `ΔT[4] = +1 µt` (Sync-вузол №4 майже ідеально синхронний);
- `ΔT[5] = -6 µt` (Sync-вузол №5 запізнюється через температурне прогрівання).

Крок 1. Сортування масиву виміряних відхилень за зростанням:
```
M_sorted = { -6, -2, +1, +4, +18 }
```

Крок 2. Відсікання `p = 1` найменшого та `p = 1` найбільшого відліків:
- Найменший елемент `ΔT_(1) = -6` вилучається.
- Найбільший елемент `ΔT_(5) = +18` (збійний) вилучається.
- Залишається внутрішній коридор дійсних відліків: `{ -2, +1, +4 }`.

Крок 3. Обчислення середнього значення FTM за межами збереженого дійсного коридору (`ΔT_(2) = -2` та `ΔT_(4) = +4`):
```
Offset_Correction = ( (-2) + (+4) ) / 2 = +1 µt
```

Як видно з розрахунку, аварійний збійний відлік `+18 µt` був повністю відкинений і не вплинув на підсумкове значення корекції.

## Застосування фазової та частотної корекцій у NIT

Обчислені значення корекцій застосовуються наприкінці циклу під час фази спокою шини Network Idle Time (NIT):

```
[Фазова корекція (Offset Correction)]
Offset_Correction = FTM( M_current )
= Зсув тривалості інтервалу NIT у мікротактах для поточного циклу

[Частотна корекція (Rate Correction)]
Rate_Correction = Offset_Correction[N] − Offset_Correction[N − 1]
= Зміна кількості мікротактів у макротакті для наступного циклу N+1
```

Обчислення виконуються за алгоритмом двоконтурного регулювання (Dual-Loop Control):
1. **Фазовий контур (Offset Loop):** Усуває миттєвий часовий зсув початку наступного циклу. Розрахована фазова корекція в мікротактах додається до номінальної тривалості NIT. Завдяки цьому наступний цикл починається синхронно на всіх вузлах мережі.
2. **Частотний контур (Rate Loop):** Ліквідує системну різницю частот локальних кварців. Якщо вузол фіксує утримуваний зсув фази з циклу в цикл, контролер змінює внутрішнє число мікротактів `N_µt` у кожному макротакті наступного циклу, плавно вирівнюючи швидкість ходу свого годинника під середньомережеву швидкість.

Завдяки цьому подвійному контуру FlexRay підтримує тривалу детерміновану синхронізацію з розкидом точок початку слотів менше `0.1 мкс` навіть при сильних змінах температури та напруги живлення.
