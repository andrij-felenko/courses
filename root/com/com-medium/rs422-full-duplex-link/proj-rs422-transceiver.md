# ⚙️ Практична схемотехніка та програмний стек трансивера RS-422

Інтеграція диференційного інтерфейсу RS-422 у вбудовані системи та промислові контролери вимагає правильного схемотехнічного узгодження логічних рівнів мікроконтролера з лінією передачі, надійного захисту вхідних каскадів від високовольтних сплесків та коректної програмної конфігурації послідовного порту. Повнодуплексна природа RS-422 звільняє розробника від керування напрямком передачі (пінами DE/RE), проте висуває суворі вимоги до термінування, топології друкованої плати та безпеки сигнальних кіл.

### Типова схемотехніка повнодуплексного вузла (MAX490 / ST422)

Для побудови повнодуплексного інтерфейсу RS-422 застосовують інтегральні трансивери у компактних 8-вивідних корпусах (наприклад, **MAX490**, **ST422**, **SN75179B** або **ADM490**). На відміну від мікросхем RS-485 (де виводи передавача та приймача об'єднані на спільній парі A/B), повнодуплексний трансивер містить повністю розділені передавальний і приймальний диференційні канали.

```
          +5V ───────────────┬───────────────────────────┐
                             │                          [+]
                           ┌─┴─┐ C1                     R_PU (1 кОм)
                           │   │ 100 нФ (кераміка)       │
                           └─┬─┘                         │
                             │                           │
                   ┌─────────┴─────────┐                 │
                   │ 8 (VCC)           │                 │
[ MCU UART TX ] ───┤ 4 (DI)      (Y) 5 ├──── TX+ (A) ────┼─────────────► Вита пара TX
                   │                   │                 │
                   │             (Z) 6 ├──── TX− (B) ────┼─────────────► (до веденого RX)
                   │                   │                 │
                   │             (A) 8 ├──── RX+ (A) ────┼──────┐
[ MCU UART RX ] ◄──┤ 1 (RO)            │                 │      │
                   │             (B) 7 ├──── RX− (B) ────┼──┐  [R_T] 120 Ом
                   │           4 (GND) │                 │  │   │
                   └─────────┬─────────┘                 │  └───┘
                             │                          [+]
                            [=] GND                     R_PD (1 кОм)
                                                         │
                                                        [=] GND
```

Функціональні вузли схеми та їхнє інженерне призначення:

1. **DI (Driver Input — Вхід передавача):**
   Логічний цифровий вхід передавача. Підключається безпосередньо до виводу TX апаратного модуля UART мікроконтролера. Більшість сучасних 5-вольтових трансиверів (наприклад, MAX490) мають входи з порогами TTL, що робить їх повністю сумісними з 3.3-вольтовими логічними рівнями мікроконтролерів STM32, ESP32 або ARM Cortex-M без необхідності встановлення додаткових перетворювачів рівнів.
2. **RO (Receiver Output — Вихід приймача):**
   Логічний цифровий вихід приймача. Підключається до виводу RX UART мікроконтролера. При живленні трансивера від +5 В вихід RO генерує рівні 0...5 В. Якщо мікроконтролер має толерантні до 5 В входи (5V-tolerant), вивід підключають напряму; якщо ж виводи контролера суто 3.3-вольтові, між виходом RO та входом MCU встановлюють резистивний дільник напруги (наприклад, 1.8 кОм / 3.3 кОм) або використовують трансивери з живленням +3.3 В (наприклад, **MAX3490** чи **SN65HVD3080**).
3. **Y та Z (TX+ / TX- — Виходи диференційного передавача):**
   Формують парафазну напругу з розмахом понад 2 В на навантаженні 100 Ом. Виводи захищають захисними діодами та самовідновними запобіжниками.
4. **A та B (RX+ / RX- — Входи диференційного приймача):**
   Вхідний каскад витримує синфазну напругу від -7 В до +7 В. Між цими виводами встановлюють термінальний резистор 120 Ом та резистори Failsafe зміщення.

### Розрахунок теплового розсіювання та потужності передавача

При високошвидкісній передачі даних на довгі лінії драйвер RS-422 розсіює помітну теплову потужність, яка складається з трьох фізичних компонентів:

1. **Статична потужність споживання внутрішньої логіки:**
   Визначається струмом спокою мікросхеми у пасивному стані:

```
P_quiescent = VCC · I_CC_idle
            = 5.0 В · 0.003 А = 15 мВт
```

2. **Потужність навантаження термінатора лінії:**
   При передачі корисного сигналу струм протікає через паралельний кінцевий резистор термінування `R_T = 120 Ом`. При середній диференційній вихідній напрузі `V_OD = 3.0 В` потужність у навантаженні становить:

```
P_term = (V_OD)² / R_T
       = (3.0)² / 120 = 9.0 / 120 = 75 мВт
```

   Ця потужність ділиться між відкритими вихідними ключами мікросхеми та самим зовнішнім резистором-термінатором.
3. **Динамічна потужність перезаряджання ємності кабелю:**
   На мегагерцових частотах сумарна погонна ємність довгого кабелю `C_cable` (типово 50–100 пФ на метр; для 100 м це становить близько 10 нФ) вимагає значного струму для постійного перезаряджання на кожному фронті перемикання біта:

```
P_dynamic = C_cable · (V_OD)² · f_data
```

   Для швидкості 5 Мбіт/с (`f = 2.5 МГц`) та кабелю 50 метрів (`C = 5 нФ`):

```
P_dynamic = 5·10⁻⁹ Ф · (3.0 В)² · 2.5·10⁶ Гц
          = 5·10⁻⁹ · 9 · 2.5·10⁶ = 112.5 мВт
```

Сумарна потужність розсіювання драйвера може перевищувати 200 мВт. Для надійного тепловідведення під мікросхемою на друкованій платі створюють суцільний мідний полігон землі (Thermal Ground Pad), з'єднаний із внутрішніми шарами плати кількома металізованими перехідними отворами.

### Багаторівневий захист від електростатики (ESD), перенапруг та зсуву потенціалів

У реальних умовах промисловий кабель RS-422 піддається впливу сильних електростатичних розрядів персоналу, індуктивних наведень від комутації силових контакторів та потужних мікросекундних імпульсів при грозових розрядах. Надійна схемотехніка вхідного каскаду вимагає застосування триступеневої схеми захисту:

```
 Лінія зв'язку   ┌──────────────┐   ┌───────────────┐   ┌──────────────┐   Трансивер
 (з боку поля) ──┤ Рівень 1:    ├───┤ Рівень 2:     ├───┤ Рівень 3:    ├─── (до виводів
                 │ Газорозрядник│   │ Самовідновний │   │ TVS-супресор │    мікросхеми)
                 │ GDT (грозо-  │   │ запобіжник    │   │ (швидкісний  │
                 │ захист 5 кВ) │   │ PTC (100 мА)  │   │ кліпер 12 В) │
                 └──────┬───────┘   └───────────────┘   └──────┬───────┘
                        │                                      │
                       [=] Корпусне заземлення (PE)           [=] Сигнальна земля (GND)
```

1. **Рівень 1 (Грубий захист великої енергії):**
   На вводі кабелю в пристрій між кожною сигнальною жилою та корпусною захисною землею (PE) встановлюють триполюсні газонаповнені розрядники (Gas Discharge Tubes, GDT) з напругою пробою 90–230 В. Вони здатні без руйнування відводити імпульсні струми амплітудою до 5–10 кА тривалістю 8/20 мкс, захищаючи апаратуру від прямих та наведених грозових сплесків.
2. **Рівень 2 (Струмообмеження та захист від тривалого замикання):**
   Послідовно в кожний сигнальний провідник включають полімерні терморезистори з позитивним температурним коефіцієнтом (PTC / PolySwitch) номіналом 10–30 Ом зі струмом спрацьовування 50–100 мА. При випадковому замиканні сигнального кабелю на промислову мережу живлення 24 В або 220 В струм короткого замикання нагріває полімер, його опір стрибкоподібно зростає до сотень кілоомів, безпечно розриваючи аварійне коло.
3. **Рівень 3 (Прецизійне швидкодіюче обмеження напруги):**
   Безпосередньо біля виводів трансивера встановлюють швидкодіючі напівпровідникові супресори TVS (наприклад, збірки **CDSOT23-SM712** або **SMAJ6.0CA**). Вони мають субнаносекундний час реакції (менше 1 нс) і жорстко зрізають залишковий імпульс напруги на безпечному рівні від -7 В до +12 В, скидаючи імпульсний струм у внутрішню сигнальну землю вузла.

### Правила трасування друкованої плати (PCB Layout)

Швидкісні диференційні лінії передавача та приймача RS-422 працюють із фронтами тривалістю в одиниці наносекунд, тому трасування друкованої плати підпорядковується законам високочастотного проектування:

- **Диференційний хвильовий опір:** Провідники ліній A і B трасують парою провідників із фіксованим проміжком для забезпечення контрольованого диференційного імпедансу `Z_diff = 100...120 Ом` (залежно від товщини діелектрика FR-4 та ширини доріжок).
- **Симетрія та узгодження довжин:** Довжини провідників прямого і зворотного сигналів всередині пари повинні бути суворо однаковими. Розсинхронізація довжин (Intra-pair skew) не повинна перевищувати 0.5–1 мм, інакше різниця в часі приходу фронтів перетворює частину диференційного сигналу на високочастотну синфазну заваду.
- **Неперервний полігон опорної землі:** Під диференційними парами на сусідньому шарі друкованої плати обов'язково повинен бути суцільний полігон сигнальної землі GND без вирізів, прорізів або розділових щілин. Будь-який розрив опорного шару змушує зворотний струм високої частоти шукати обхідний шлях, що різко збільшує паразитну індуктивність лінії та породжує перехресні завади (Crosstalk).
- **Розташування блокувальних конденсаторів:** Керамічний конденсатор живлення VCC (100 нФ X7R) розміщують на відстані не більше 2–3 мм від виводу 8 мікросхеми, використовуючи широкі доріжки для мінімізації паразитної індуктивності виводів.

### Програмна реалізація: повнодуплексний драйвер у середовищі POSIX / Linux

Оскільки RS-422 є повністю повнодуплексним апаратним каналом, на рівні операційної системи робота з адаптером RS-422 (підключеним через PCIe-карту, вбудований апаратний контролер UART або мікросхему FTDI FT232H/FT4232H) здійснюється через стандартні інтерфейси POSIX Termios без необхідності ручного керування лініями RTS чи RS-485 Direction.

Нижче наведено модулі для ініціалізації та повнодуплексного асинхронного обміну через порт RS-422.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <termios.h>

// Відкриття та налаштування порту RS-422 на задану швидкість
int rs422_open(const char *port_path, speed_t baud_rate) {
    int fd = open(port_path, O_RDWR | O_NOCTTY | O_NDELAY);
    if (fd < 0) {
        perror("Помилка відкриття порту RS-422");
        return -1;
    }

    // Скидаємо прапорець неблокуючого доступу для штатних операцій читання
    fcntl(fd, F_SETFL, 0);

    struct termios tty;
    if (tcgetattr(fd, &tty) != 0) {
        perror("Помилка отримання атрибутів termios");
        close(fd);
        return -1;
    }

    // Встановлення швидкості прийому та передачі
    cfsetispeed(&tty, baud_rate);
    cfsetospeed(&tty, baud_rate);

    // Формат кадру: 8 біт даних, 1 стоп-біт, без контролю парності (8N1)
    tty.c_cflag &= ~PARENB;         // Без біта парності
    tty.c_cflag &= ~CSTOPB;         // 1 стоп-біт (не 2)
    tty.c_cflag &= ~CSIZE;          // Скидання маски розміру символу
    tty.c_cflag |= CS8;             // 8 бітів на байт
    tty.c_cflag &= ~CRTSCTS;        // Без апаратного керування RTS/CTS
    tty.c_cflag |= (CLOCAL | CREAD);// Дозвіл прийому, ігнорування ліній модему

    // Сирий режим вводу (Raw input): відключення трансляції спецсимволів
    tty.c_lflag &= ~(ICANON | ECHO | ECHOE | ISIG);
    tty.c_iflag &= ~(IXON | IXOFF | IXANY); // Без програмного керування XON/XOFF
    tty.c_iflag &= ~(IGNBRK | BRKINT | PARMRK | ISTRIP | INLCR | IGNCR | ICRNL);

    // Сирий режим виводу (Raw output)
    tty.c_oflag &= ~OPOST;

    // Тайм-аути читання: блокування до приходу хоча б 1 байта або тайм-аут 100 мс
    tty.c_cc[VMIN] = 0;   // Мінімальна кількість байтів для завершення read()
    tty.c_cc[VTIME] = 1;  // Тайм-аут читання в децисекундах (1 = 100 мс)

    // Застосування налаштувань негайно
    if (tcsetattr(fd, TCSANOW, &tty) != 0) {
        perror("Помилка застосування налаштувань termios");
        close(fd);
        return -1;
    }

    // Очищення черг вхідного та вихідного буферів
    tcflush(fd, TCIOFLUSH);
    return fd;
}

// Повнодуплексна відправка блоку даних у лінію RS-422
ssize_t rs422_write_all(int fd, const uint8_t *data, size_t len) {
    size_t total_written = 0;
    while (total_written < len) {
        ssize_t written = write(fd, data + total_written, len - total_written);
        if (written < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        total_written += (size_t)written;
    }
    return (ssize_t)total_written;
}
```

```cpp
#include <iostream>
#include <span>
#include <string_view>
#include <system_error>
#include <expected>
#include <vector>
#include <cstdint>
#include <cstring>
#include <unistd.h>
#include <fcntl.h>
#include <termios.h>

class Rs422Port {
public:
    Rs422Port() noexcept : fd_{-1} {}
    ~Rs422Port() noexcept { close(); }

    Rs422Port(const Rs422Port&) = delete;
    Rs422Port& operator=(const Rs422Port&) = delete;

    Rs422Port(Rs422Port&& other) noexcept : fd_{other.fd_} {
        other.fd_ = -1;
    }

    Rs422Port& operator=(Rs422Port&& other) noexcept {
        if (this != &other) {
            close();
            fd_ = other.fd_;
            other.fd_ = -1;
        }
        return *this;
    }

    // Відкриття та налаштування порту RS-422 з використанням RAII
    static std::expected<Rs422Port, std::error_code> open_port(
        std::string_view path, speed_t baud_rate = B115200) noexcept 
    {
        int fd = ::open(path.data(), O_RDWR | O_NOCTTY | O_NDELAY);
        if (fd < 0) {
            return std::unexpected(std::error_code(errno, std::generic_category()));
        }

        ::fcntl(fd, F_SETFL, 0);

        termios tty{};
        if (::tcgetattr(fd, &tty) != 0) {
            auto err = std::error_code(errno, std::generic_category());
            ::close(fd);
            return std::unexpected(err);
        }

        ::cfsetispeed(&tty, baud_rate);
        ::cfsetospeed(&tty, baud_rate);

        // Режим 8N1 (8 бітів, без парності, 1 стоп-біт)
        tty.c_cflag &= ~PARENB;
        tty.c_cflag &= ~CSTOPB;
        tty.c_cflag &= ~CSIZE;
        tty.c_cflag |= CS8;
        tty.c_cflag &= ~CRTSCTS;
        tty.c_cflag |= (CLOCAL | CREAD);

        tty.c_lflag &= ~(ICANON | ECHO | ECHOE | ISIG);
        tty.c_iflag &= ~(IXON | IXOFF | IXANY | IGNBRK | BRKINT | PARMRK | ISTRIP | INLCR | IGNCR | ICRNL);
        tty.c_oflag &= ~OPOST;

        tty.c_cc[VMIN] = 0;
        tty.c_cc[VTIME] = 1; // 100 мс

        if (::tcsetattr(fd, TCSANOW, &tty) != 0) {
            auto err = std::error_code(errno, std::generic_category());
            ::close(fd);
            return std::unexpected(err);
        }

        ::tcflush(fd, TCIOFLUSH);
        Rs422Port port;
        port.fd_ = fd;
        return port;
    }

    void close() noexcept {
        if (fd_ >= 0) {
            ::close(fd_);
            fd_ = -1;
        }
    }

    [[nodiscard]] bool is_open() const noexcept { return fd_ >= 0; }

    // Відправка буфера у лінію передачі
    std::expected<size_t, std::error_code> send(std::span<const uint8_t> data) noexcept {
        size_t total_sent = 0;
        while (total_sent < data.size()) {
            ssize_t res = ::write(fd_, data.data() + total_sent, data.size() - total_sent);
            if (res < 0) {
                if (errno == EINTR) continue;
                return std::unexpected(std::error_code(errno, std::generic_category()));
            }
            total_sent += static_cast<size_t>(res);
        }
        return total_sent;
    }

    // Прийом даних із лінії у наданий буфер
    std::expected<size_t, std::error_code> receive(std::span<uint8_t> buffer) noexcept {
        ssize_t res = ::read(fd_, buffer.data(), buffer.size());
        if (res < 0) {
            if (errno == EINTR) return 0;
            return std::unexpected(std::error_code(errno, std::generic_category()));
        }
        return static_cast<size_t>(res);
    }

private:
    int fd_;
};
```

### Архітектура мікроконтролерного прийому через кільцевий буфер та DMA

При швидкостях передачі даних 1–10 Мбіт/с обробка кожного прийнятого байта через стандартні переривання UART посимвольно (Byte-by-Byte Interrupts) створює критичне навантаження на процесор мікроконтролера. При швидкості 10 Мбіт/с один байт надходить кожні 800 наносекунд: вхід у функцію обробника переривання (ISR) та вихід із неї просто не встигають завершитися, що викликає апаратне переповнення приймального регістра (Overrun Error) і втрату кадрів.

Для безперебійного високошвидкісного прийому реалізують наступну програмно-апаратну архітектуру:

1. **Прямий доступ до пам'яті (DMA) у циклічному режимі (Circular Mode):**
   Контролер DMA без участі центрального процесора переносить байти з регістра даних UART у заздалегідь виділений кільцевий буфер в оперативній пам'яті (SRAM).
2. **Детектування паузи в лінії (UART Idle Line Detection):**
   Мікроконтролер налаштовують на генерацію переривання за подією простою лінії (IDLE Interrupt), яке спрацьовує, коли після прийому пачки байтів лінія залишається у стані Mark протягом часу одного кадру (10–11 бітових інтервалів). Це дозволяє процесору прокидатися лише один раз після завершення прийому всього пакета даних, миттєво зчитувати поточний покажчик лічильника DMA та передавати сформований пакет у чергу завдань RTOS.
3. **Обробка апаратних помилок:**
   У коді обробника обов'язково контролюють прапорці помилок кадрування (Framing Error) та шуму (Noise Flag). Якщо лінія зв'язку короткочасно зазнала перешкоди, пошкоджений пакет відкидається на рівні контрольної суми (CRC-16 / CRC-32), а вхідний покажчик буфера синхронізується за наступним старт-бітом.

### Схемотехніка повної гальванічної ізоляції вузла RS-422

У випадках, коли пристрої зв'язку розташовані в різних будівлях або підключені до силових підстанцій із високим рівнем індустріальних завад, різниця потенціалів заземлення значно перевищує допустимий для стандартних трансиверів діапазон ±7 В. Щоб уникнути пошкодження обладнання та виникнення небезпечних для життя струмів, вузол зв'язку виконують за схемою **повної триканальної гальванічної ізоляції**:

```
 [ Логічна частина MCU ]        [ Бар'єр ізоляції 3–5 кВ ]        [ Польова частина RS-422 ]
   UART TX (DI)  ─────────────► [ Цифровий ємнісний      ] ─────► TX (DI) Трансивера
   UART RX (RO)  ◄───────────── [ ізолятор (ISO7742)     ] ◄───── RO Трансивера
                                [                        ]
   VCC_MCU (+3.3В/5В) ────────► [ Ізольований DC-DC      ] ─────► VCC_ISO (+5В)
   GND_MCU (Плата)   ────────► [ перетворювач (B0505S)   ] ─────► GND_ISO (Ізольована)
```

Архітектурні особливості ізольованого вузла:
1. **Швидкісні цифрові ізолятори:**
   Замість застарілих повільних оптопар із великим часом затримки (понад 100 нс) застосовують сучасні цифрові ізолятори на основі кремнієвих діоксидних ємнісних бар'єрів (серія **TI ISO7741 / ISO7742**) або мікротрансформаторів (**ADI ADuM1401 / ADuM1411**). Вони підтримують швидкість передачі даних до 100 Мбіт/с, мають часовий дрейф фронту менше 2 нс та витримують випробувальну напругу пробою до 5000 В RMS протягом 1 хвилини.
2. **Ізольоване вторинне живлення:**
   Для живлення польового каскаду трансивера встановлюють компактний DC-DC перетворювач із трансформаторною розв'язкою (наприклад, **B0505S-1WR3** або **Mornsun IB0505S**). Його вихідні кола `VCC_ISO` та `GND_ISO` є повністю плаваючими (Floating) відносно основної плати мікроконтролера.
3. **Правила розриву шарів на друкованій платі (Isolation Creepage):**
   Під мікросхемами ізолятора та перетворювача створюють суцільну розділову зону без міді (Keepout Zone) завширшки не менше 6.3–8.0 мм на всіх шарах плати. Це гарантує захист від поверхневого електричного пробою по діелектрику текстоліту FR-4 при накопиченні пилу та вологи.

### Апаратне керування потоком (RTS/CTS) у диференційних лініях

При передачі великих неперервних масивів даних на швидкостях понад 1 Мбіт/с приймальний буфер мікроконтролера або прикладного процесора може переповнитися через тимчасову зайнятість операційної системи іншими завданнями. Для запобігання втраті інформації використовують **апаратний контроль потоку (Hardware Flow Control)** за допомогою додаткових диференційних ліній RTS (Request to Send) та CTS (Clear to Send).

У 4-провідному тракті RS-422 для кожної лінії керування виділяється окрема вита пара:
- **Пара RTS (RTS+ / RTS-):** Передавач першого пристрою формує сигнал готовності свого приймача приймати чергову порцію даних.
- **Пара CTS (CTS+ / CTS-):** Приймальний вузол перевіряє рівень на лінії CTS перед відправкою кожного нового байта.

Фізичне обмеження на швидкість реакції апаратного контролю потоку накладає **час поширення сигналу по довгому кабелю (Propagation Delay)**:

При швидкості поширення електромагнітної хвилі `v ≈ 200 000 км/с` затримка проходження сигналу по кабелю довжиною 1000 метрів становить:

```
t_prop = Довжина / v_prop
       = 1000 м / 0.2 м/нс = 5000 нс = 5.0 мкс
```

Якщо прилад на швидкості 10 Мбіт/с (тривалість одного біта 100 нс, байта — 1.0 мкс) раптово скидає лінію RTS через заповнення буфера, віддалений передавач дізнається про цю подію лише через 5 мікросекунд. За цей час він встигне передати в лінію ще щонайменше 5 повних байтів, які вже перебувають у польоті всередині кабелю. 

Тому при проектуванні високошвидкісних ліній поріг генерації сигналу зупинки потоку (High-Water Mark) встановлюють заздалегідь — із резервом буфера, що дорівнює подвійному часу затримки лінії зв'язку:

```
N_reserve_bytes ≥ (2 · t_prop) / t_byte
```

Для лінії довжиною 1 км на швидкості 10 Мбіт/с розмір резервного запасу приймального буфера FIFO повинен становити не менше 10–16 байтів.

4. **Автоматизований тест зворотного замикання (Self-Test Loopback):**
   Для експрес-перевірки справності трансивера та мікроконтролера на виробництві або під час апаратної самодіагностики приладу виходи передавача `TX+` та `TX-` безпосередньо з'єднують короткими перемичками з відповідними входами `RX+` та `RX-` того самого пристрою (через навантажувальний термінатор 120 Ом). Прошивка мікроконтролера надсилає в лінію тестовий псевдовипадковий бітовий потік (PRBS-7 або тестові таблиці байтів) і перевіряє стовідсотковий побітовий збіг переданих та прийнятих даних на максимальній швидкості обміну без залучення зовнішнього вимірювального обладнання. Якщо виникають помилки бітів (Bit Errors), перевіряють якість паяння та рівень напруги живлення VCC.

### Практичні правила налагодження та діагностики

При виявленні збоїв у роботі лінії RS-422 інженерну перевірку виконують за покроковим діагностичним алгоритмом:

1. **Перевірка напруг у стані спокою (Idle Test):**
   За допомогою цифрового мультиметра вимірюють напругу між проводами пари на клемах приймача. Якщо на клемах `RX+` та `RX-` напруга відсутня (`V_diff ≈ 0 В`), це свідчить про обрив кабелю або відсутність резисторів Failsafe зміщення. Нормальна напруга пасивного стану повинна становити `V_A - V_B = +0.25...+0.35 В`.
2. **Осцилографічний аналіз форми сигналу (Eye Pattern):**
   Двоканальним осцилографом із диференційним щупом підключаються до кінців термінатора 120 Ом. Якщо на перепадах спостерігаються викиди амплітуди понад 50% («дзвін»), термінатор відсутній або його номінал не відповідає хвильовому опору кабелю. Якщо фронти затягнуті у пологі експоненти, а розмах сигналу падає нижче 1 В, кабель має надмірну довжину для обраної швидкості або завелику питому ємність.
3. **Вимірювання синфазного зсуву земель:**
   Вимірюють постійну та змінну напругу між сигнальною землею передавача (GND1) та землею приймача (GND2). Напруга не повинна перевищувати 7.0 В у будь-яких режимах роботи силового обладнання цеху. Перевищення цього порогу вимагає негайного встановлення гальванічної розв'язки.
