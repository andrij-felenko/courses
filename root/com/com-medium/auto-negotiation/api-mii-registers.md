# 📋 Карта регістрів MDIO автопогодження та бітові маски IEEE 802.3

Низькорівневе керування трансивером Ethernet (PHY) та отримання результатів узгодження швидкості й дуплексу здійснюється через послідовну двопровідну шину керування **MDIO/MDC** (англ. *Management Data Input/Output*, IEEE 802.3 Clause 22). Контролер доступу до середовища (MAC) зчитує та записує 16-розрядні регістри мікросхеми PHY для ініціалізації автопогодження, вибору підтримуваних технологій, опитування статусу апаратного лінка та обробки позаштатних станів.

Безпосередній доступ до регістрового простору необхідний під час написання системних драйверів операційних систем, мережевих завантажувачів (U-Boot), прошивок вбудованих мікроконтролерів (STM32, ESP32, i.MX) та діагностики апаратних несправностей лінії.

## 1. Загальний огляд адресного простору регістрів автопогодження

Стандарт IEEE 802.3 резервує перший блок із 32 регістрів (адреси `0x00`–`0x1F`) під базовий інтерфейс керування Clause 22. Перші 16 регістрів (`0x00`–`0x0F`) строго стандартизовані комітетом IEEE і мають ідентичне призначення у трансиверах усіх світових виробників (Broadcom, Realtek, Marvell, Texas Instruments, Microchip, Intel).

```general
Адреса   Абревіатура   Повна назва стандарту IEEE 802.3                           Призначення
0x00     BMCR          Basic Mode Control Register                                Базове керування режимами та перезапуск AN
0x01     BMSR          Basic Mode Status Register                                 Статус зв'язку, готовність AN, помилки лінка
0x02     PHYID1        PHY Identifier Register 1                                  Старші 16 бітів OUI виробника мікросхеми
0x03     PHYID2        PHY Identifier Register 2                                  Молодші 6 бітів OUI + модель + ревізія чипа
0x04     ANAR          Auto-Negotiation Advertisement Register                    Оголошення власних можливостей (Base Page)
0x05     ANLPAR        Auto-Negotiation Link Partner Ability Register             Прийнята сторінка лінк-партнера (Base Page)
0x06     ANER          Auto-Negotiation Expansion Register                        Статус розширення, детектування сторінок
0x07     ANNPTR        Auto-Negotiation Next Page Transmit Register               Передача наступної сторінки (Next Page)
0x08     ANNPRR        Auto-Negotiation Next Page Receive Register                Прийом наступної сторінки від партнера
0x09     1000CR        1000BASE-T Control Register                                Керування 1 Гбіт/с та Master/Slave
0x0A     1000SR        1000BASE-T Status Register                                 Статус Master/Slave та лічильник збоїв
0x0D     MMD_CTRL      MMD Access Control Register (Clause 22 direct to Clause 45) Селектор доступу до розширеного MMD
0x0E     MMD_DATA      MMD Access Data Register                                   Шина даних для звернення до регістрів MMD
0x0F     EXSR          Extended Status Register                                   Підтримка 1000BASE-X/T Full/Half
```

### Апаратна поведінка розрядів та типи доступу

Кожен біт регістрового простору MDIO має строго визначену апаратну логіку оновлення, яку драйвер повинен враховувати при проектуванні кінцевого автомата:

* **RW** (*Read/Write*): класичний регістр читання та прямого запису. Встановлене значення зберігається у внутрішніх тригерах до наступного циклу запису по шині MDIO або повного апаратного скидання;
* **RO** (*Read Only*): регістр лише для зчитування поточного стану внутрішніх апаратних вузлів, аналогових компараторів або лічильників помилок;
* **SC** (*Self-Clearing*): біт самостійно скидається в 0 внутрішньою логікою PHY після завершення відповідної операції. Наприклад, встановлення біта програмного скидання `BMCR.15 = 1` запускає скидання мікросхеми; чип утримує цей біт у стані `1` протягом усього циклу перезапуску генераторів і фільтрів (до 500 мс) і автоматично повертає його в `0`, щойно трансивер знову готовий приймати команди;
* **LH** (*Latching High*): біт фіксується у значенні 1 при виникненні певної події (наприклад, виявлення аварії віддаленого партнера або заклинювання передавача Jabber) і залишається в одиниці доти, доки програмний драйвер не прочитає цей регістр по шині MDIO. Перше читання повертає `1` і водночас скидає засувку в `0`. Якщо аварійний стан зник до моменту читання, засувка гарантує, що драйвер не пропустить подію;
* **LL** (*Latching Low*): біт падає в 0 при найменшому зникненні сигналу або втраті синхронізації і залишається нулем до моменту зчитування, навіть якщо фізичний лінк уже повністю відновився. Завдяки цьому програмний стек може виявити короткочасні розриви зв'язку («моргання» кабелю), які тривали лічені мілісекунди.

## 2. Базовий регістр керування BMCR (Register 0, 0x00)

Регістр `BMCR` (англ. *Basic Mode Control Register*) є головним органом керування роботою трансивера, конфігурацією дуплексу та ручним або автоматичним вибором швидкості.

```general
Біт     Назва          Тип   За замовчуванням  Опис та бітові комбінації
15      Reset          RW/SC 0                 1 = Програмне скидання PHY (триває до 500 мс)
14      Loopback       RW    0                 1 = Замикання цифрового тракту TX на RX (режим тестування)
13      Speed Select 0 RW    1                 Молодший біт ручного вибору швидкості (див. біт 6)
12      AN Enable      RW    1                 1 = Увімкнути Auto-Negotiation; 0 = Примусова швидкість
11      Power Down     RW    0                 1 = Переведення PHY в режим енергозбереження (Sleep)
10      Isolate        RW    0                 1 = Електрична ізоляція інтерфейсу MII від шини MAC
9       Restart AN     RW/SC 0                 1 = Примусовий перезапуск автопогодження (скидається в 0)
8       Duplex Mode    RW    1                 1 = Full-Duplex; 0 = Half-Duplex (діє лише при AN Enable = 0)
7       Collision Test RW    0                 1 = Генерація сигналу COL у відповідь на TX_EN
6       Speed Select 1 RW    0                 Старший біт ручного вибору швидкості
5..0    Reserved       RO    0                 Зарезервовано IEEE (повертає 0)
```

Детальний аналіз ключових бітів керування:

* **Reset (біт 15)**: запис одиниці ініціалізує повне апаратне перезавантаження аналогових фільтрів, скидання регістрів у значення за замовчуванням та рекалібрування внутрішніх джерел опорної напруги. Драйвер зобов'язаний опитувати цей біт у циклі перед виконанням будь-яких інших операцій;
* **Loopback (біт 14)**: перемикає цифровий інтерфейс MII/RGMII безпосередньо з входу передавача на вихід приймача в обхід аналогового каскаду та трансформаторів. Використовується для самодіагностики контролера MAC без підключення реального кабелю;
* **AN Enable (біт 12)**: вмикає або вимикає протокол автопогодження. Якщо біт дорівнює `0`, трансивер ігнорує будь-які імпульси FLP і примусово встановлює швидкість та дуплекс згідно зі значеннями бітів `13`, `6` та `8`;
* **Restart Auto-Negotiation (біт 9)**: запис `1` примушує трансивер скинути поточний стан переговорів, перейти у початковий стан `Transmit Disable` (пауза тиші) та знову почати передачу сторінок Base Page. Біт автоматично скидається в `0` після перезапуску;
* **Isolate (біт 10)**: переводить вихідні лінії даних і тактування інтерфейсу MII у стан високого імпедансу (Hi-Z), що дозволяє підключати кілька мікросхем PHY до спільної шини MAC;
* **Power Down (біт 11)**: вимикає всі внутрішні аналогові підсилювачі, вимикає генератори імпульсів FLP та переводить чип у стан мінімального енергоспоживання (струм споживання падає з десятків міліампер до мікроампер). Інтерфейс MDIO при цьому залишається повністю функціональним для прийому команди пробудження.

Таблиця декодування бітів швидкості при вимкненому автопогодженні (`AN Enable = 0`):

```general
Біт 6 (Speed 1)   Біт 13 (Speed 0)   Встановлена швидкість фізичного рівня
0                 0                  10 Мбіт/с (10BASE-T)
0                 1                  100 Мбіт/с (100BASE-TX)
1                 0                  1000 Мбіт/с (1000BASE-T)
1                 1                  Зарезервовано (у нових чипах: 10G/2.5G/5GBASE-T)
```

## 3. Базовий регістр статусу BMSR (Register 1, 0x01)

Регістр `BMSR` (англ. *Basic Mode Status Register*) інформує драйвер про фізичний стан лінії зв'язку, факт завершення переговорів та апаратні можливості чипа.

```general
Біт     Назва                Тип   Опис бітового прапорця
15      100BASE-T4 Able      RO    1 = Апаратна підтримка стандарту 100BASE-T4 (4 пари Cat3)
14      100BASE-TX Full Able RO    1 = Підтримка 100 Мбіт/с Full-Duplex
13      100BASE-TX Half Able RO    1 = Підтримка 100 Мбіт/с Half-Duplex
12      10BASE-T Full Able   RO    1 = Підтримка 10 Мбіт/с Full-Duplex
11      10BASE-T Half Able   RO    1 = Підтримка 10 Мбіт/с Half-Duplex
10      100BASE-T2 Full Able RO    1 = Підтримка 100BASE-T2 Full-Duplex (2 пари Cat3)
9       100BASE-T2 Half Able RO    1 = Підтримка 100BASE-T2 Half-Duplex
8       Extended Status Able RO    1 = Наявність розширеного регістру статусу EXSR (Reg 15)
7       Reserved             RO    Зарезервовано (повертає 0)
6       MF Preamble Suppress RO    1 = Підтримка кадру MDIO без початкової 32-бітної преамбули
5       AN Complete          RO    1 = Автопогодження успішно завершено (конфігурація валідна)
4       Remote Fault         RO/LH 1 = Виявлено помилку віддаленого партнера (скидається читанням)
3       AN Ability           RO    1 = Мікросхема PHY здатна виконувати Auto-Negotiation
2       Link Status          RO/LL 1 = Фізичний лінк піднято; 0 = Зникнення сигналу в лінії
1       Jabber Detect        RO/LH 1 = Виявлено заклинювання передавача (передача > 26 мс у 10BASE-T)
0       Extended Capability  RO    1 = Наявність базового набору регістрів 0x02–0x0F
```

Особливості обробки статусних бітів драйвером:

* **Auto-Negotiation Complete (біт 5)**: встановлюється в `1` тільки тоді, коли обмін сторінками повністю завершився, розв'язання пріоритетів виконано, і лінійний трансивер готовий до передачі даних. Якщо біт дорівнює `0`, вміст регістру `ANLPAR` вважається недійсним;
* **Link Status (біт 2)**: має властивість Latching Low. Якщо під час опитування драйвер отримав `0`, необхідно виконати друге зчитування: якщо друге зчитування повертає `1`, це свідчить про короткочасний перепад сигналу в минулому при збереженні активного зв'язку в поточний момент;
* **Remote Fault (біт 4)**: фіксує отримання біта `RF = 1` від віддаленого партнера. Свідчить про те, що лінк-партнер не бачить нашого сигналу (наприклад, через обрив однієї жили в кабелі або збій нашого передавача);
* **Jabber Detect (біт 1)**: у стандарті 10BASE-T захищає спільне середовище від несправного вузла, який безперервно утримує передавач увімкненим понад 26 мс (заклинювання). При виявленні такого стану PHY апаратно блокує вихід передавача.

## 4. Регістри оголошення сторінок ANAR та ANLPAR (Registers 4 та 5, 0x04, 0x05)

Регістр `ANAR` (англ. *Auto-Negotiation Advertisement Register*) формує 16-бітне слово базової сторінки (Base Page), яке передавач PHY транслює в лінію у вигляді імпульсів FLP. Регістр `ANLPAR` (англ. *Link Partner Ability Register*) зберігає слово Base Page, успішно прийняте й декодоване від віддаленого пристрою (або синтезоване блоком Parallel Detection).

Бітові поля регістрів 4 та 5 мають ідентичну структуру за стандартом IEEE 802.3 Clause 28:

```general
Біт     Поле Base Page    Тип у Reg 4   Опис бітового поля
15      NP (Next Page)    RW            1 = Запит на передачу наступних сторінок Next Page
14      ACK (Acknowledge) RO            1 = Підтвердження прийому 3 послідовних сторінок партнера
13      RF (Remote Fault) RW            1 = Сигналізація віддаленому партнеру про локальний збій
12      Extended Next Page RW           1 = Підтримка 48-бітної розширеної сторінки XNP (10GBASE-T)
11      Asymmetric PAUSE  RW            1 = Підтримка асиметричного керування потоком (Flow Control)
10      PAUSE (802.3x)    RW            1 = Підтримка симетричного повнодуплексного кадру PAUSE
9       100BASE-T4        RW            1 = Оголошення підтримки 100BASE-T4
8       100BASE-TX Full   RW            1 = Оголошення підтримки 100 Мбіт/с Full-Duplex
7       100BASE-TX Half   RW            1 = Оголошення підтримки 100 Мбіт/с Half-Duplex
6       10BASE-T Full     RW            1 = Оголошення підтримки 10 Мбіт/с Full-Duplex
5       10BASE-T Half     RW            1 = Оголошення підтримки 10 Мбіт/с Half-Duplex
4..0    Selector Field    RW            Поле вибору стандарту: 00001b = IEEE 802.3 CSMA/CD
```

### Матриця розв'язання режиму PAUSE (Flow Control)

Керування потоком за стандартом IEEE 802.3x дозволяє перевантаженому приймачу надсилати спеціальний кадр керування `PAUSE`, який змушує передавач на протилежному кінці призупинити трансляцію на вказаний інтервал квантів часу (512 бітових інтервалів на квант).

Розв'язання режиму роботи PAUSE здійснюється шляхом порівняння бітів `10` та `11` у регістрах `ANAR` та `ANLPAR`:

```general
Локальний (11:10)   Партнер (11:10)   Підсумок розв'язання Flow Control
00 (Без PAUSE)      Будь-який         Керування потоком вимкнено в обох напрямках
01 (Симетричний)    01 або 11         Симетричний PAUSE (обидва вузли надсилають і обробляють PAUSE)
01 (Симетричний)    10 або 00         Керування потоком вимкнено
10 (Асиметричний)   11                Локальний вузол надсилає PAUSE, партнер лише обробляє PAUSE
11 (Обидва)         10                Партнер надсилає PAUSE, локальний вузол лише обробляє PAUSE
11 (Обидва)         01 або 11         Симетричний PAUSE увімкнено
```

## 5. Регістр розширення автопогодження ANER (Register 6, 0x06)

Регістр `ANER` (англ. *Auto-Negotiation Expansion Register*) інформує драйвер про наявність розширених функцій, отримання нової сторінки та виникнення помилок паралельного детектування.

```general
Біт     Назва                  Тип   Опис бітового прапорця
15..7   Reserved               RO    Зарезервовано (повертає 0)
6       Receive NP Storage Loc RO    1 = Підтримка апаратного буфера для кількох Next Pages
5       Receive NP Location    RO    1 = Статус розташування пам'яті прийнятих Next Pages
4       Parallel Detection Fault RO/LH 1 = Помилка паралельного детектування (виявлено > 1 несучої)
3       Link Partner NP Able   RO    1 = Віддалений партнер підтримує обмін сторінками Next Page
2       Local NP Able          RO    1 = Локальний PHY підтримує обмін сторінками Next Page
1       Page Received          RO/LH 1 = Успішно прийнято та верифіковано нову сторінку даних
0       Link Partner AN Able   RO    1 = Лінк-партнер підтримує Auto-Negotiation (передає FLP)
```

Діагностичне значення біта `ANER.0` (Link Partner Auto-Negotiation Able):
Якщо під час опитування статус лінка `BMSR.2 == 1`, але біт `ANER.0 == 0`, це є прямим доказом того, що віддалений пристрій не брав участі в автопогодженні, а зв'язок встановлено за допомогою механізму **Parallel Detection**. У такому випадку драйвер повинен зафіксувати напівдуплексний режим та згенерувати попередження про можливий Duplex Mismatch.

## 6. Регістри передавання та прийому Next Page (Registers 7 та 8, 0x07, 0x08)

Регістри `ANNPTR` (0x07) та `ANNPRR` (0x08) забезпечують безпосередній програмний контроль над обміном додатковими 16-розрядними сторінками Next Page:

```general
Біт     Назва                Тип у Reg 7   Опис бітового поля
15      Next Page (NP)       RW            1 = Після цієї сторінки слідують інші; 0 = Остання сторінка
14      Reserved / ACK       RO            Зарезервовано в TX; біт ACK у прийнятому слові Reg 8
13      Message Page (MP)    RW            1 = Сторінка коду повідомлення; 0 = Неформатована сторінка даних
12      Acknowledge 2 (Ack2) RW            1 = Локальний вузол здатний виконати запит Message Page
11      Toggle (T)           RO            Біт чергування (апаратно інвертується у кожній сторінці)
10..0   Message / Data Code  RW            11-бітне корисне навантаження (код повідомлення або прапорці)
```

Послідовність програмного обміну сторінками Next Page:
1. Драйвер записує цільовий 11-бітний код і тип сторінки у регістр `0x07` (`ANNPTR`);
2. Встановлюється біт `NP = 1` (якщо планується відправка наступних сторінок) або `NP = 0` (для завершення);
3. Драйвер очікує підняття прапорця `ANER.1` (Page Received);
4. Зчитується прийняте 16-бітне слово від партнера з регістру `0x08` (`ANNPRR`);
5. Цикл повторюється доти, доки біт `NP` не стане рівним `0` в обох пристроїв.

## 7. Регістри гігабітного погодження 1000BASE-T (Registers 9 та 10, 0x09, 0x0A)

Для швидкості 1 Гбіт/с (IEEE 802.3ab Clause 40) обов'язковим є обмін розширеними параметрами тактування Master/Slave. Для цього виділено спеціалізовані регістри 9 та 10.

### Регістр 9: 1000BASE-T Control Register (0x09)

```general
Біт     Назва                 Тип  Опис бітового поля
15..13  Test Mode             RW   000 = Звичайний робочий режим
                                   001 = Test Mode 1 (передача тестових імпульсів форми)
                                   010 = Test Mode 2 (передача тактового сигналу Master)
                                   011 = Test Mode 3 (передача тактового сигналу Slave)
                                   100 = Test Mode 4 (передача тестової послідовності спотворень)
12      Master/Slave Manual   RW   1 = Увімкнути ручний вибір Master/Slave; 0 = Автоматичний
11      Master/Slave Value    RW   1 = Примусово MASTER; 0 = Примусово SLAVE (якщо біт 12 = 1)
10      Port Type             RW   1 = Multiport device (комутатор); 0 = Single-port (NIC)
9       1000BASE-T Full Able  RW   1 = Оголошення підтримки 1000BASE-T Full-Duplex
8       1000BASE-T Half Able  RW   1 = Оголошення підтримки 1000BASE-T Half-Duplex
7..0    Reserved              RW   Зарезервовано IEEE (за замовчуванням 0)
```

### Регістр 10: 1000BASE-T Status Register (0x0A)

```general
Біт     Назва                 Тип   Опис бітового прапорця
15      MS Configuration Fault RO/LH 1 = Помилка конфігурації Master/Slave (обидва Master або обидва Slave)
14      MS Resolution Result   RO    1 = Локальний PHY став MASTER; 0 = Локальний PHY став SLAVE
13      Local Receiver Status  RO    1 = Локальний приймач синхронізований (DSP та ехокомпенсація зійшлися)
12      Remote Receiver Status RO    1 = Віддалений приймач підтвердив власну синхронізацію
11      LP 1000BASE-T Full Able RO   1 = Партнер підтримує 1000BASE-T Full-Duplex
10      LP 1000BASE-T Half Able RO   1 = Партнер підтримує 1000BASE-T Half-Duplex
9..8    Reserved              RO    Зарезервовано (повертає 0)
7..0    Idle Error Count      RO/SC 8-бітний лічильник помилок символів IDLE (насичується на 255)
```

Діагностичне значення бітів регістру 10:
* **Master/Slave Configuration Fault (біт 15)**: фіксує конфлікт тактування. Якщо цей біт встановлено, зв'язок на швидкості 1 Гбіт/с ніколи не встановиться, поки не буде знято ручну фіксацію ролей у регістрі 9;
* **Local/Remote Receiver Status (біти 13 та 12)**: вказують на якість збіжності адаптивних еквалайзерів DSP. Якщо `Local Receiver Status == 1`, але `Remote Receiver Status == 0`, це свідчить про проблему в тракті передавача локального вузла або пошкодження кабелю в напрямку від нас до партнера;
* **Idle Error Count (біти 7..0)**: апаратний лічильник некоректних символів PAM-5 під час відсутності корисного трафіку. Збільшення цього лічильника свідчить про високий рівень перехресних завад (NEXT) або погану якість обтискання конектора RJ-45.

## 8. Доступ до розширених регістрів MMD (Clause 45 через Clause 22)

Сучасні розширення стандарту, такі як енергоефективний Ethernet **EEE** (IEEE 802.3az) та швидкості 10G/2.5G/5GBASE-T, використовують 32-розрядний простір регістрів **MMD** (англ. *MDIO Manageable Device*, Clause 45). Для мікроконтролерів із класичним контролером MAC Clause 22 доступ до цих регістрів реалізується через непряму адресацію за допомогою регістрів `0x0D` (`MMD_CTRL`) та `0x0E` (`MMD_DATA`).

Послідовність непрямого читання розширеного регістру MMD (Device `dev_addr`, Register `reg_addr`):
1. Записати в регістр `0x0D` значення `(0x0000 | dev_addr)` — режим встановлення адреси;
2. Записати в регістр `0x0E` цільову адресу `reg_addr`;
3. Записати в регістр `0x0D` значення `(0x4000 | dev_addr)` — режим читання/запису даних без автоінкременту;
4. Зчитати шукане значення з регістру `0x0E`.

Послідовність непрямого запису розширеного регістру MMD:
1. Записати в регістр `0x0D` значення `(0x0000 | dev_addr)`;
2. Записати в регістр `0x0E` цільову адресу `reg_addr`;
3. Записати в регістр `0x0D` значення `(0x4000 | dev_addr)`;
4. Записати нове значення в регістр `0x0E`.

Стандартні адреси MMD для перевірки Energy Efficient Ethernet (EEE):
* **Device 3, Register 20** (`0x03.0x0014` — PCS EEE Ability): біт 2 = 1000BASE-T EEE, біт 1 = 100BASE-TX EEE;
* **Device 7, Register 60** (`0x07.0x003C` — EEE Advertisement): оголошення локальної підтримки EEE;
* **Device 7, Register 61** (`0x07.0x003D` — EEE Link Partner Ability): оголошення підтримки EEE від партнера.

Стандартні адреси MMD для 10GBASE-T (IEEE 802.3an):
* **Device 7, Register 32** (`0x07.0x0020` — 10GBASE-T Control): біт 12 = 10GBASE-T Full-Duplex Ability;
* **Device 7, Register 33** (`0x07.0x0021` — 10GBASE-T Status): біт 11 = Link Partner 10GBASE-T Ability, біт 14 = Master/Slave Resolution Result для 10G.

## 9. Регістри бекплейнів Clause 73 та діагностика кабелю (TDR)

Для високошвидкісних об'єднувальних плат (Clause 73) та вбудованої діагностики кабелю сучасні PHY надають додаткові блоки регістрів MMD:

### Регістри автопогодження Clause 73 (MMD Device 7)

У високошвидкісних інтерфейсах бекплейнів (10GBASE-KR, 40GBASE-KR4, 100GBASE-KR4) обмін сторінками здійснюється 48-розрядними словами. Для керування цим процесом використовуються такі регістри MMD:
* **MMD 7, Register 0** (*AN Control 73*): біт 12 = Enable AN, біт 9 = Restart AN, біт 13 = Extended Next Page Enable;
* **MMD 7, Register 1** (*AN Status 73*): біт 5 = AN Complete, біт 2 = Link Status, біт 7 = Page Received;
* **MMD 7, Registers 16, 17, 18** (*AN Advertisement 73*): 48-розрядне слово локального оголошення технологій (10GBASE-KR, 40GBASE-KR4, параметри прямої корекції помилок FEC Clause 74/91);
* **MMD 7, Registers 19, 20, 21** (*AN Link Partner Ability 73*): 48-розрядне слово, прийняте від партнера по бекплейну.

### Вбудована рефлектометрія кабелю (TDR — Time Domain Reflectometry)

Більшість сучасних гігабітних PHY (Marvell Alaska, Realtek RTL8211, TI DP83867) містять апаратний блок імпульсної рефлектометрії часової області (**TDR**). Він дозволяє без спеціалізованого кабельного тестера визначити точне місце пошкодження витої пари:
* Драйвер ініціалізує TDR через пропрієтарний регістр керування (зазвичай у діапазоні `0x10`–`0x1F`);
* Передавач надсилає короткий імпульс у кожну з чотирьох пар і вимірює час повернення відбитої хвилі;
* Полярність відбитого імпульсу вказує на характер несправності:
  * **Позитивне відбиття** (той самий знак) — **обрив кабелю** (англ. *Open*, розімкнене коло, високий імпеданс);
  * **Негативне відбиття** (інвертований знак) — **коротке замикання** (англ. *Short*, нульовий опір між жилами).
* За часом затримки `t_delay` процесор обчислює точну відстань до місця обриву з точністю до 1 метра, спираючись на швидкість поширення сигналу у витій парі (`v ≈ 0.66·c ≈ 200 000 км/с`).
