# 📋 Інтерфейс цифрового моніторингу SFF-8472 (SFP DOM/DDM)

Ця специфікація описує апаратно-програмний інтерфейс цифрової діагностики та моніторингу (**DOM** — *Digital Optical Monitoring* / **DDM** — *Digital Diagnostic Monitoring*) оптичних приймально-передавальних модулів форм-факторів SFP, SFP+ та SFP28 згідно з промисловим стандартом **SFF-8472**.

### Фізичний рівень, розпіновка роз'єму та шина I2C

Інтерфейс моніторингу спирається на послідовну двопровідну шину **I2C** (*Inter-Integrated Circuit*), заведену на крайні контакти 20-пінового роз'єму SFP. Сигнали шини мають відкритий колектор і потребують зовнішніх підтягувальних резисторів (*pull-up*) номіналом 4.7–10 кОм до лінії живлення +3.3 В на материнській платі комутатора чи маршрутизатора.

```text
               СХЕМА ПІДКТЮЧЕННЯ ШИНИ I2C ТА СИГНАЛІВ КЕРУВАННЯ SFP
 ┌───────────────────────────────┐               ┌───────────────────────────────┐
 │   МАПЕР / КОМУТАТОР (HOST)    │               │    ОПТИЧНИЙ МОДУЛЬ (SFP)      │
 │                               │               │                               │
 │  +3.3V ──[R_pu]─── SCL (Pin 5)├───────────────┤SCL ──► Контроллер DOM (MCU)   │
 │  +3.3V ──[R_pu]─── SDA (Pin 4)├───────────────┼SDA ◄─► EEPROM 0xA0 / 0xA2      │
 │                               │               │                               │
 │  +3.3V ──[R_pu]─ Mod_ABS(Pin 6)├──────────────┤GND (Низький рівень присадки)  │
 │                   TX_Disable (2)├────────────►│Вимкнення лазера (High = Off)  │
 │  +3.3V ──[R_pu]─── TX_Fault (3)├──────────────┼Аварія лазера (Open Drain)     │
 │  +3.3V ──[R_pu]─── RX_LOS (15) ├──────────────┼Втрата сигналу (Open Drain)    │
 └───────────────────────────────┘               └───────────────────────────────┘
```

Розподіл критичних контактів 20-пінового роз'єму SFP, що відповідають за діагностику та життєвий цикл оптичного модуля:
- **Pin 2 (TX Disable):** Вхідний цифровий сигнал вимкнення передавача. Високий рівень (2.0…3.3 В) миттєво знеструмлює лазерний діод.
- **Pin 3 (TX Fault):** Вихідний сигнал апаратного збою лазера з відкритим колектором. Високий рівень свідчить про вихід струму зміщення лазера за безпечні межі або пробій драйвера.
- **Pin 4 (SDA):** Послідовна лінія даних шини I2C.
- **Pin 5 (SCL):** Послідовна лінія тактування шини I2C (тактова частота до 100 кГц, стандартний режим).
- **Pin 6 (Mod_ABS / MOD-DEF0):** Сигнал присутності модуля у слоті. На платі трансивера цей контакт жорстко заземлений на GND. Хост підтягує його до +3.3 В; коли модуль вставляють у порт, напруга падає до 0 В, сповіщаючи процесор комутатора про факт підключення обладнання (Hot-Plug Event).
- **Pin 15 (VCCR):** Живлення приймальної частини (+3.3 В ± 5%).
- **Pin 16 (VCCT):** Живлення передавальної частини (+3.3 В ± 5%).
- **Pin 15 (RX LOS):** Сигнал втрати оптичного сигналу на приймачі (*Loss of Signal*). Високий рівень свідчить про те, що оптична потужність на фотодіоді впала нижче порогу чутливості.

### Адресація пам'яті I2C та структура сторінок SFF-8472

Контролер трансивера відповідає на дві 7-бітні I2C-адреси. З точки зору процесора хоста пам'ять модуля представлена у вигляді двох логічних мікросхем EEPROM обсягом по 256 байтів кожна:

1. **Адреса `0xA0` (7-бітна адреса `0x50`):**
   Містить статичну інформацію про специфікацію оптичного трансивера: форм-фактор (SFP/SFP+), тип оптичного роз'єму (LC/SC), тип кабелю (SMF/MMF), довжину хвилі випромінювання (наприклад, 1310 нм), підтримувану швидкість (1.25G, 10G, 25G), назву виробника, артикул (Part Number), серійний номер та дату виготовлення.
2. **Адреса `0xA2` (7-бітна адреса `0x51`):**
   Описує таблицю цифрового моніторингу DOM/DDM реального часу.

```text
               КАРТА ПАМ'ЯТІ ІНТЕРФЕЙСУ SFF-8472 (АДРЕСА 0xA2 / 0x51)
 ┌───────────┬───────────────────────────────────────────────────────────┐
 │ Байт      │ Призначення та вміст                                      │
 ├───────────┼───────────────────────────────────────────────────────────┤
 │ 00 – 39   │ Порогові значення тривог і застережень (Alarm & Warning)  │
 │ 40 – 55   │ Зарезервовано для розширення специфікації                 │
 │ 56 – 91   │ Константи калібрування зовнішніх датчиків (Calibration)   │
 │ 92 – 94   │ Константа контрольної суми калібрувальних полів           │
 │ 95        │ Контрольна сума рядків 0..94 (CC_DMI)                     │
 │ 96 – 105  │ ДАТЧИКИ РЕАЛЬНОГО ЧАСУ (Real-Time Diagnostic Values)      │
 │ 106 – 109 │ Зарезервовано                                             │
 │ 110       │ Статусні прапорці стану (Data Ready, LOS, Soft TX Disable) │
 │ 111       │ Зарезервовано                                             │
 │ 112 – 117 │ Апаратні прапорці тривог (Alarm & Warning Flags)          │
 │ 118 – 119 │ Зарезервовано                                             │
 │ 120 – 127 │ Таблиця паролів та вибору сторінок (Page Select 127)      │
 │ 128 – 247 │ Паролезахищена користувацька таблиця EEPROM               │
 │ 248 – 255 │ Таблиця вендорських даних                                 │
 └───────────┴───────────────────────────────────────────────────────────┘
```

### Таблиця порогів тривог і застережень (Байти 00–39)

Перед початком експлуатації керувальне програмне забезпечення зчитує з байтів `00…39` таблиці `0xA2` фабричні межі безпечної роботи даної конкретної оптики:

- **Temp High/Low Alarm (Байти 00–03):** Абсолютні граничні температури кристала (наприклад, +85°C та -5°C). При виході за ці межі модуль може незворотно вийти з ладу.
- **Temp High/Low Warning (Байти 04–07):** Попереджувальні пороги температури (наприклад, +75°C та 0°C), що свідчать про проблеми з вентиляцією шафи.
- **Voltage High/Low Alarm (Байти 08–11):** Граничні напруги живлення (наприклад, 3.63 В та 2.97 В).
- **Bias High/Low Alarm (Байти 16–19):** Граничні струми зміщення лазера (наприклад, 80 мА та 2 мА).
- **TX Power High/Low Alarm (Байти 24–27):** Гранична вихідна оптична потужність (наприклад, +5.0 дБм та -4.0 дБм).
- **RX Power High/Low Alarm (Байти 32–35):** Гранична приймана потужність (наприклад, -2.0 дБм перевантаження та -24.0 дБм чутливість).

### Реєстри телеметрії реального часу (Байти 96–105)

Показники датчиків телеметрії оновлюються внутрішнім мікроконтролером оптичного модуля кожні 10–100 мс. Усі значення записані у формі 16-бітних цілих чисел у форматі Big-Endian (старший байт MSB передує молодшому LSB):

| Реєстри (MSB, LSB) | Назва параметра | Формат даних | Одиниця вимірювання | Формула перетворення |
|---|---|---|---|---|
| **96, 97** | Температура модуля (`Temp`) | 16-біт зі знаком (int16_t) | °C | `Temp_C = Value / 256.0` |
| **98, 99** | Напруга живлення (`VCC`) | 16-біт без знаку (uint16_t)| Вольт | `VCC_V = Value / 10000.0` |
| **100, 101**| Струм зміщення лазера (`TX Bias`)| 16-біт без знаку (uint16_t)| мА (міліампери) | `I_bias_mA = Value / 500.0` |
| **102, 103**| Вихідна потужність TX (`TX Power`)| 16-біт без знаку (uint16_t)| мВт / дБм | `P_tx_mW = Value / 10000.0` |
| **104, 105**| Вхідна потужність RX (`RX Power`)| 16-біт без знаку (uint16_t)| мВт / дБм | `P_rx_mW = Value / 10000.0` |

### Математика внутрішнього та зовнішнього калібрування

Стандарт SFF-8472 визначає два методи інтерпретації сирих чисел із байтів `96…105`. Спосіб калібрування вказується в прапорці **Bit 4 Byte 92** сторінки `0xA0`:

1. **Внутрішнє калібрування (*Internal Calibration*):**
   Мікроконтролер трансивера самостійно перераховує нелінійність своїх АЦП і записує в байти `96…105` вже остаточно відкалібровані двійкові значення. У 99% сучасних SFP+ модулів застосовується саме це калібрування. Формули лінійної конвертації:
   ```text
   T [°C]      = raw_int16(Byte 96, 97) / 256.0
   VCC [В]     = raw_uint16(Byte 98, 99) / 10000.0
   I_bias [мА] = raw_uint16(Byte 100, 101) / 500.0
   P_TX [мВт]  = raw_uint16(Byte 102, 103) / 10000.0
   P_RX [мВт]  = raw_uint16(Byte 104, 105) / 10000.0
   ```

   Логарифмічний перерахунок оптичної потужності з міліват у децибел-мілівати (дБм):
   ```text
   P [дБм] = 10 · log₁₀( P [мВт] )
   ```
   Якщо `raw_uint16 == 0`, виміряна потужність дорівнює нулю (світло відсутнє). У цьому разі логарифм прямує до мінус нескінченності, тому програма виставляє фіксований поріг відсутності сигналу `−40.0 дБм`.

2. **Зовнішнє калібрування (*External Calibration*):**
   У застарілих або спеціалізованих модулях байти `96…105` містять сирі значення АЦП. Хост-процесор зобов'язаний зчитати поліноміальні коефіцієнти калібрування з байтів `56…91` сторінки `0xA2` та застосувати їх за формулою:
   ```text
   P_real = Slope · Value_raw + Offset
   ```
   Для фотодіода RX використовується квадратний поліном четвертого порядку для компенсації нелінійності p-i-n кристала на малих рівнях потужності.

### Деталізована реалізація драйвера зчитування DOM (C та C++)

Нижче наведено робочі приклади декодування реєстрів SFF-8472, адаптовані для вбудованих систем зв'язку та Linux-систематичного опитування через `/dev/i2c-X` чи прошивки комутаторів.

```c
#include <stdio.h>
#include <stdint.h>
#include <stdbool.h>
#include <math.h>

// Повний набір інтерпретованих даних моніторингу SFF-8472
typedef struct {
    float temperature_c;       // Температура модуля (°C)
    float vcc_volts;           // Напруга живлення VCC (В)
    float tx_bias_ma;          // Струм зміщення лазерного діода (мА)
    float tx_power_mw;         // Вихідна потужність передавача (мВт)
    float tx_power_dbm;        // Вихідна потужність передавача (дБм)
    float rx_power_mw;         // Вхідна потужність приймача (мВт)
    float rx_power_dbm;        // Вхідна потужність приймача (дБм)
    bool data_ready;           // Прапорець готовності АЦП (Byte 110 Bit 0)
    bool rx_los;               // Сигнал втрати оптичного сигналу RX LOS
    bool tx_fault;             // Сигнал апаратної аварії лазера TX Fault
} sff8472_telemetry_t;

// Декодування 10-байтового телеметричного блоку (реєстри 96..105)
// та статусних байтів (110, 112)
bool parse_sff8472_page_a2(const uint8_t page_a2_bytes[128], sff8472_telemetry_t *out) {
    if (!page_a2_bytes || !out) return false;

    // 1. Температура: 16-бітний int зі знаком (MSB=Byte 96, LSB=Byte 97)
    int16_t raw_temp = (int16_t)((page_a2_bytes[96] << 8) | page_a2_bytes[97]);
    out->temperature_c = (float)raw_temp / 256.0f;

    // 2. Напруга живлення VCC: 16-бітний uint (Byte 98, 99)
    uint16_t raw_vcc = (uint16_t)((page_a2_bytes[98] << 8) | page_a2_bytes[99]);
    out->vcc_volts = (float)raw_vcc / 10000.0f;

    // 3. Струм зміщення лазера: 16-бітний uint (Byte 100, 101)
    uint16_t raw_bias = (uint16_t)((page_a2_bytes[100] << 8) | page_a2_bytes[101]);
    out->tx_bias_ma = (float)raw_bias / 500.0f;

    // 4. Оптична потужність TX: 16-бітний uint (Byte 102, 103)
    uint16_t raw_tx = (uint16_t)((page_a2_bytes[102] << 8) | page_a2_bytes[103]);
    out->tx_power_mw = (float)raw_tx / 10000.0f;
    if (out->tx_power_mw > 0.00001f) {
        out->tx_power_dbm = 10.0f * log10f(out->tx_power_mw);
    } else {
        out->tx_power_dbm = -40.0f; // Відсутність генерації світла
    }

    // 5. Оптична потужність RX: 16-бітний uint (Byte 104, 105)
    uint16_t raw_rx = (uint16_t)((page_a2_bytes[104] << 8) | page_a2_bytes[105]);
    out->rx_power_mw = (float)raw_rx / 10000.0f;
    if (out->rx_power_mw > 0.00001f) {
        out->rx_power_dbm = 10.0f * log10f(out->rx_power_mw);
    } else {
        out->rx_power_dbm = -40.0f; // Відсутність оптичного сигналу (LOS)
    }

    // 6. Аналіз статусних прапорців у Байтах 110 та 112
    uint8_t status_byte_110 = page_a2_bytes[110];
    out->data_ready = (status_byte_110 & 0x01) == 0; // Bit 0 == 0 означає Data Ready

    uint8_t flags_byte_112 = page_a2_bytes[112];
    out->tx_fault = (flags_byte_112 & (1 << 2)) != 0; // Bit 2 — TX Fault Alarm
    out->rx_los   = (flags_byte_112 & (1 << 1)) != 0; // Bit 1 — RX LOS Alarm

    return true;
}

int main(void) {
    // Тестовий масив пам'яті A2h (128 байт), згенерований SFP+ 10G-LR модулем
    uint8_t page_a2[128] = {0};

    // Заповнюємо значення реального часу (Byte 96..105)
    page_a2[96] = 0x23; page_a2[97] = 0x00; // Temp = 35.0 °C
    page_a2[98] = 0x81, page_a2[99] = 0x48; // VCC  = 3.31 В
    page_a2[100] = 0x24; page_a2[101] = 0x40; // Bias = 18.5 мА
    page_a2[102] = 0x31; page_a2[103] = 0x34; // TX   = 1.26 мВт (+1.0 дБм)
    page_a2[104] = 0x00; page_a2[105] = 0xC8; // RX   = 0.02 мВт (-17.0 дБм)

    sff8472_telemetry_t dom;
    if (parse_sff8472_page_a2(page_a2, &dom)) {
        printf("=== ТЕЛЕМЕТРІЯ ОПТИЧНОГО ТРАНСИВЕРА (SFF-8472) ===\n");
        printf("Готовність датчиків: %s\n", dom.data_ready ? "ГОТОВО" : "ОНОВЛЕННЯ");
        printf("Температура модуля:  %.2f °C\n", dom.temperature_c);
        printf("Напруга живлення:    %.2f В\n", dom.vcc_volts);
        printf("Струм зміщення TX:   %.2f мА\n", dom.tx_bias_ma);
        printf("Вихідна потужність:  %.3f мВт (%.2f дБм)\n", dom.tx_power_mw, dom.tx_power_dbm);
        printf("Приймана потужність: %.4f мВт (%.2f дБм)\n", dom.rx_power_mw, dom.rx_power_dbm);
        printf("Статус RX LOS:       %s\n", dom.rx_los ? "АВАРІЯ (НЕМАЄ СВІТЛА)" : "НОРМА (СИГНАЛ Є)");
        printf("Статус TX Fault:     %s\n", dom.tx_fault ? "АВАРІЯ ЛАЗЕРА" : "НОРМА");
    }

    return 0;
}
```

```cpp
#include <iostream>
#include <cstdint>
#include <cmath>
#include <span>
#include <expected>
#include <format>
#include <string_view>

namespace photonics::sff8472 {

struct DomTelemetry {
    float temperature_c{0.0f};
    float vcc_volts{0.0f};
    float tx_bias_ma{0.0f};
    float tx_power_mw{0.0f};
    float tx_power_dbm{-40.0f};
    float rx_power_mw{0.0f};
    float rx_power_dbm{-40.0f};
    bool data_ready{false};
    bool rx_los{false};
    bool tx_fault{false};
};

class Sff8472Decoder {
public:
    [[nodiscard]] static std::expected<DomTelemetry, std::string_view>
    parse_page_a2(std::span<const uint8_t, 128> page_a2) noexcept {
        DomTelemetry data{};

        // 1. Температура
        const auto raw_temp = static_cast<int16_t>((page_a2[96] << 8) | page_a2[97]);
        data.temperature_c = static_cast<float>(raw_temp) / 256.0f;

        // 2. Напруга VCC
        const auto raw_vcc = static_cast<uint16_t>((page_a2[98] << 8) | page_a2[99]);
        data.vcc_volts = static_cast<float>(raw_vcc) / 10000.0f;

        // 3. Струм зміщення лазера
        const auto raw_bias = static_cast<uint16_t>((page_a2[100] << 8) | page_a2[101]);
        data.tx_bias_ma = static_cast<float>(raw_bias) / 500.0f;

        // 4. Оптична потужність TX
        const auto raw_tx = static_cast<uint16_t>((page_a2[102] << 8) | page_a2[103]);
        data.tx_power_mw = static_cast<float>(raw_tx) / 10000.0f;
        if (data.tx_power_mw > 1e-5f) {
            data.tx_power_dbm = 10.0f * std::log10(data.tx_power_mw);
        }

        // 5. Оптична потужність RX
        const auto raw_rx = static_cast<uint16_t>((page_a2[104] << 8) | page_a2[105]);
        data.rx_power_mw = static_cast<float>(raw_rx) / 10000.0f;
        if (data.rx_power_mw > 1e-5f) {
            data.rx_power_dbm = 10.0f * std::log10(data.rx_power_mw);
        }

        // 6. Прапорці стану
        data.data_ready = (page_a2[110] & 0x01) == 0;
        data.tx_fault   = (page_a2[112] & (1 << 2)) != 0;
        data.rx_los     = (page_a2[112] & (1 << 1)) != 0;

        return data;
    }
};

} // namespace photonics::sff8472

int main() {
    using namespace photonics::sff8472;

    uint8_t page_a2_data[128] = {0};
    page_a2_data[96] = 0x23; page_a2_data[97] = 0x00; // 35.0 °C
    page_a2_data[98] = 0x81; page_a2_data[99] = 0x48; // 3.31 В
    page_a2_data[100] = 0x24; page_a2_data[101] = 0x40; // 18.5 мА
    page_a2_data[102] = 0x31; page_a2_data[103] = 0x34; // +1.0 дБм
    page_a2_data[104] = 0x00; page_a2_data[105] = 0xC8; // -17.0 дБм

    auto dom_result = Sff8472Decoder::parse_page_a2(page_a2_data);

    if (dom_result) {
        const auto& d = dom_result.value();
        std::cout << std::format("=== ДІАГНОСТИКА SFP МОДУЛЯ (C++23) ===\n");
        std::cout << std::format("Температура:      {:.2f} °C\n", d.temperature_c);
        std::cout << std::format("Напруга живлення: {:.2f} В\n", d.vcc_volts);
        std::cout << std::format("Струм зміщення:   {:.2f} мА\n", d.tx_bias_ma);
        std::cout << std::format("Вихідна потужність TX: {:.3f} мВт ({:.2f} дБм)\n", d.tx_power_mw, d.tx_power_dbm);
        std::cout << std::format("Приймана потужність RX: {:.4f} мВт ({:.2f} дБм)\n", d.rx_power_mw, d.rx_power_dbm);
        std::cout << std::format("Статус RX LOS:    {}\n", d.rx_los ? "АВАРІЯ (НЕМАЄ СИГНАЛУ)" : "ОК (СИГНАЛ Є)");
    } else {
        std::cerr << "Помилка декодування сторінки A2h: " << dom_result.error() << '\n';
    }

    return 0;
}
```

### Практичне застосування діагностики у серверних операційних системах

У Linux-системах виклик цифрової діагностики DOM здійснюється утилітою **ethtool** через системні виклики ioctl до драйвера мережевої карти:

```bash
# Зчитування телеметрії DOM оптичного модуля інтерфейсу eth0
ethtool -m eth0

# Приклад виводу утиліти ethtool на основі реєстрів SFF-8472:
# Identifier                : 0x03 (SFP)
# Extended identifier       : 0x04 (GBIC/SFP defined AC coupling)
# Connector                 : 0x07 (LC)
# Transceiver type          : 10G Ethernet 10GBASE-LR
# Laser bias current        : 18.500 mA
# Laser output power        : 1.2589 mW / 1.00 dBm
# Receiver signal average optical power : 0.0199 mW / -17.01 dBm
# Module temperature        : 35.00 degrees C
# Module voltage            : 3.3100 V
# Alarm/warning flags implemented : Yes
```

Завдяки стандарту SFF-8472 мережеві оператори автоматизовано виявляють зношені оптичні модулі (зростання `TX Bias`) та локалізують заломи волокна (падіння `RX Power`) ще до виникнення обриву зв'язку.
