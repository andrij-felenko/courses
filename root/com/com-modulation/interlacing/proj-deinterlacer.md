# ⚙️ Проєкт: Адаптивний до руху деінтерлейсер (Motion-Adaptive Deinterlacing)

Цей приклад показує програмну реалізацію адаптивного алгоритму деінтерлейсингу, який перетворює черезрядкові поля у прогресивні кадри на сучасних цифрових дисплеях, комбінуючи часове об'єднання (Weave) для статичних ділянок та просторову інтерполяцію (Bob) для рухомих об'єктів.

### Ідея та принципи побудови алгоритму

При відображенні аналогового черезрядкового відеосигналу на сучасних рідкокристалічних або OLED-дисплеях виникає необхідність відновлення відсутніх рядків у кожному полі. Оскільки матриця рідкокристалічного монітора оновлює всі пікселі одночасно, приймальний цифровий модуль має вирішити фундаментальну компромісну задачу між просторовою чіткістю та часовою цілісністю зображення.

Для обробки послідовності черезрядкових полів у цифрових відеопроцесорах використовують два базісних алгоритми:

1. **Weave (об'єднання полів):** рядки поточного непарного поля `t` та попереднього парного поля `t - 1` просто переплітаються у спільний кадровий буфер. Для статичних об'єктів це забезпечує максимально можливу вертикальну роздільність, оскільки повністю відновлюються всі 576 активних рядків кадру. Проте якщо об'єкт змістився у часовому проміжку між зйомкою полів (`20 мкс` у стандарту PAL), переплетення зсунутих контурів створює виснажливий артефакт **гребінки** (*combing*).

2. **Bob (просторова інтерполяція):** відсутній рядок обчислюється виключно за рахунок просторових сусідів у межах одного й того самого поля. Кожен відсутній рядок `y` розраховується як середнє арифметичне між верхнім рядком `y - 1` та нижнім рядком `y + 1` того ж поля. Це повністю усуває артефакт гребінки на рухомих об'єктах, проте вертикальна чіткість непорушного фону падає вдвічі, а горизонтальні межі набувають розмитої та східчастої структури.

### Детекція руху та вибір порогу

**Адаптивний до руху деінтерлейсер** (*motion-adaptive deinterlacer*) реалізує гібридний адаптивний підхід. Для кожного пікселя відновлюваного рядка обчислюється абсолютна різниця між значенням яскравості у поточному полі `curr_field` та значенням у попередньому полі тієї самої парності `prev_same_field`:

```
diff = | curr_field[y][x] - prev_same_field[y][x] |
```

- Якщо різниця `diff` менша за вибраний поріг руху `THRESHOLD` (ділянка визнається статичною) — застосовується алгоритм **Weave** для збереження 100% просторової деталізації зображення.
- Якщо різниця `diff` перевищує поріг (у даній точці виявлено рух) — алгоритм перемикається на просторове усереднення **Bob**, гарантовано блокуючи появу гребінки.

Значення порогу `THRESHOLD` зазвичай обирається у діапазоні `10 ... 20` градацій яскравості (при 8-бітному кодуванні `0 ... 255`). Занадто малий поріг викликає помилкові спрацьовування детектора руху через аналоговий шум у відеосигналі (в результаті статичний фон розмивається), тоді як занадто високий поріг пропускає дрібні рухи і залишає помітні сліди гребінки на межах повільних об'єктів.

### Пам'ять та обчислювальна складність

З точки зору обчислювальної складності, адаптивний алгоритм вимагає збереження принаймні трьох послідовних буферів полів (поточне поле, попереднє поле та попереднє поле тієї ж парності). Для роздільності PAL 720×576 це потребує близько 1.2 Мегабайта оперативної пам'яті для 8-бітних масивів яскравості. У реальних відеопроцесорах алгоритм розпаралелюють на SIMD-інструкціях (NEON, AVX2) або реалізують апаратно у плисах (FPGA).

Більш просунуті алгоритми (наприклад, ELA — *Edge-Based Line Averaging*) аналізують просторові градієнти яскравості уздовж діагональних напрямків під кутами 45° та 135°, відновлюючи відсутній рядок уздовж виявленого контуру об'єкта, що запобігає появі східчастості на похилих лініях.

### Застосування у FPV-обладнанні та OSD

У системах аналогового FPV-відеосигналу (наприклад, окулярах пілота FatShark, Skyzone чи приймачах RapidFIRE) алгоритми деінтерлейсингу відіграють критичну роль. Пілот FPV-дрона вимагає мінімально можливої затримки відображення (latency < 1 мс) при польоті на високій швидкості.

З цієї причини FPV-окуляри зазвичай працюють у швидкому режимі **Bob**, розгортаючи кожне поле негайно після його прийому, без очікування приходу наступного поля. Це дає нульову затримку кадрового буфера. Водночас для відображення OSD-телеметрії (текстових цифр напруги та швидкості) відеопроцесор використовує локальний адаптивний Weave, щоб символи телеметрії не тремтіли й залишалися чіткими.

Крім того, при використанні аналогового грабера (відеозахоплення через USB) для запису FPV-польоту на ПК, програмні деінтерлейсери (наприклад, у програмах OBS Studio або VLC) дозволяють перетворити 50i/60i поле у 50p/60p відеопотік із найвищою чіткістю за допомогою алгоритмів Yadif чи BBDIF. Практична реалізація нижче є готовим модулем для розширення відеопотоку.
