# ⚙️ Два декодери Ріда–Маллера мовою C: голосування і «зелена машина»

Ось два готові декодери, які можна вкласти у прошивку: **універсальний** мажоритарний декодер Ріда для будь-якого RM(r, m) і **швидкий** декодер першого порядку RM(1, m) через перетворення Волша–Адамара — той самий за суттю алгоритм, що його апаратно втілювала «зелена машина» Лабораторії реактивного руху, розкодовуючи знімки Марса. Мова — C, і не з примхи: тут немає ні польової арифметики, ні таблиць синдромів; кожен крок — це кілька XOR-ів та додавань цілих, тобто рівно та бітова робота на гарячому шляху, задля якої C і створений.

Теорія обіцяє: «кожен коефіцієнт видно крізь безліч незалежних перевірок, проголосуй більшістю — і переможеш». Декодер — це та обіцянка, дописана до останнього циклу. Тут — два способи її дотримати: один повільніший, зате працює для всіх параметрів; другий блискавичний, але лише для першого порядку.

## Подання: моном — це бітова маска

Занумеруймо 2ᵐ точок куба числом t ∈ [0, 2ᵐ). Кожну змінну подамо одним бітом номера точки, а **моном** (добуток кількох змінних) — бітовою **маскою** S: біт j маски стоїть, якщо змінна входить у добуток. Тоді значення монома в точці t обчислюється однією операцією:

```
моном x_S у точці t дорівнює 1   ⟺   (t & S) == S
```

— бо добуток змінних дорівнює одиниці лише там, де **всі** його змінні одиниці, тобто де всі біти маски S присутні в номері точки t. Степінь монома — це просто `popcount(S)`, число одиничних бітів маски.

Кодове слово — таблиця істинності функції: масив `code[t]` довжини n = 2ᵐ. Повідомлення — коефіцієнти полінома: масив `msg[S]`, у якому ненульові лише клітинки зі степенем не вище стелі, `popcount(S) ≤ r`. Закодувати означає обчислити функцію в усіх точках; а що моном живий у точці t саме тоді, коли S ⊆ t, то значення — це «сума за підмножинами за модулем 2»: `f(t) = ⊕_{S ⊆ t} msg[S]`. Її рахує один метелик за O(n·log n) — те саме [перетворення Жегалкіна (ANF)](topic:math-logic/zhegalkin-polynomial), що переганяє коефіцієнти в значення:

```c
#include <stdio.h>
#include <stdlib.h>

#define RM_MAXN 4096            /* вистачає до m = 12 (n = 4096) */

/* popcount = степінь монома (число змінних у добутку) */
static int popcount(unsigned x) {
    int c = 0;
    while (x) { c += (int)(x & 1u); x >>= 1; }
    return c;
}

/* Кодер RM(r,m): msg[] містить коефіцієнти (ненульові лише при popcount<=r).
   Один subset-sum-метелик перетворює коефіцієнти на таблицю значень. */
void rm_encode(int m, const int *msg, int *code) {
    int n = 1 << m;
    for (int t = 0; t < n; t++) code[t] = msg[t];
    for (int i = 0; i < m; i++)
        for (int t = 0; t < n; t++)
            if (t & (1 << i)) code[t] ^= code[t ^ (1 << i)];
}
```

XOR тут — це [додавання за модулем 2](topic:math-logic/boolean-algebra): уся арифметика коду саме така, тож ні кодер, ні обидва декодери жодного разу не виходять за межі цілочислової бітової логіки.

## Універсальний декодер Ріда: голосування згори вниз

Ключ до декодування — одна операційна тотожність. Візьмімо коефіцієнт при мономі S і **просумуймо (XOR) прийняте слово по всіх 2^|S| точках підкуба**, де змінні з S пробігають усі свої значення, а решта координат зафіксовані. Якщо функція має степінь не вищий за |S|, ця сума дорівнює рівно коефіцієнту a_S — усе інше в підкубі скорочується попарно й зникає в XOR. А фіксацій решти координат є 2^(m−|S|); отже, ми маємо **2^(m−|S|) незалежних оцінок** одного коефіцієнта — стільки ж голосів.

Чому голоси незалежні й чому більшість права? Бо ці підкуби **не перетинаються**: зсуви одного підкуба **розбивають** усі 2ᵐ точок на 2^(m−|S|) блоків без спільних точок. Одна перекручена каналом точка лежить рівно в одному блоці — псує рівно **один** голос. Тому поки помилок менше за половину голосів, зіпсовані завжди в меншості. Для найвищого степеня r голосів найменше — 2^(m−r) = d, — і саме це число задає [виправну здатність](topic:com-modulation/hamming-distance) ⌊(d−1)/2⌋.

Звідси весь алгоритм. Ідемо **згори вниз за степенями**: спершу голосуємо за всі коефіцієнти степеня r (їх видно напряму), віднімаємо їхній внесок із прийнятого — і задача сходить на степінь нижче; голосуємо за степінь r−1 по вже очищеному залишку, і так аж до вільного члена, що вирішується більшістю всіх бітів.

```c
/* Універсальний мажоритарний декодер Ріда для RM(r,m).
   recv[] — прийняте слово (n бітів 0/1); msg[] — відновлені коефіцієнти. */
void rm_decode_reed(int m, int r, const int *recv, int *msg) {
    int n = 1 << m;
    int work[RM_MAXN];
    for (int t = 0; t < n; t++) work[t] = recv[t];      /* робочий залишок */
    for (int S = 0; S < n; S++) msg[S] = 0;

    for (int s = r; s >= 0; s--) {
        /* 1. голосуємо за кожен коефіцієнт степеня s */
        for (int S = 0; S < n; S++) {
            if (popcount((unsigned)S) != s) continue;
            int comp = (n - 1) ^ S;                     /* координати поза S */
            int ones = 0, total = 0, y = comp;
            for (;;) {                                  /* y — зсув підкуба */
                int parity = 0, z = S;
                for (;;) {                              /* z — точка підкуба */
                    parity ^= work[y | z];
                    if (z == 0) break;
                    z = (z - 1) & S;
                }
                ones += parity; total++;
                if (y == 0) break;
                y = (y - 1) & comp;
            }
            msg[S] = (2 * ones > total) ? 1 : 0;        /* строга більшість */
        }
        /* 2. віднімаємо знайдений шар степеня s із залишку */
        for (int t = 0; t < n; t++) {
            int contrib = 0;
            for (int S = 0; S < n; S++)
                if (popcount((unsigned)S) == s && msg[S] && ((t & S) == S))
                    contrib ^= 1;
            work[t] ^= contrib;
        }
    }
}
```

Два вкладені цикли підмножин — це весь механізм. Зовнішній перебирає **зсуви** підкуба (підмаски доповнення `comp` — координати поза S), внутрішній — **точки** підкуба (підмаски самої S); XOR внутрішнього циклу дає один голос, зовнішній їх лічить. Класичний обхід підмасок `y = (y - 1) & comp` акуратно проходить усі підмаски, включно з порожньою й повною, і сам зупиняється на нулі.

## Наскрізний приклад: RM(1, 3) під одну помилку

Візьмімо код [8, 4, 4] і повідомлення (a₀; при x₁, x₂, x₃) = (1; 0, 1, 1), тобто f = 1 ⊕ x₂ ⊕ x₃. У масках коефіцієнтів це `msg[0]=1, msg[2]=1, msg[1]=1` (одновимірний моном xⱼ — це маска з одним бітом). Кодер дає:

```
code = 1 0 0 1 1 0 0 1      (вага 4 = d, як і належить коду [8,4,4])
```

Канал перевертає біт у точці 010 (індекс 2). Приймаємо `recv = 1 0 1 1 1 0 0 1`. Декодер Ріда на степені 1 голосує за коефіцієнт при кожній змінній — пари точок, що різняться лише в одному біті номера:

```
за x₁ (біт 2):  голоси  0 0 1 0  →  більшість 0  →  a = 0
за x₂ (біт 1):  голоси  1 1 1 0  →  більшість 1  →  a = 1
за x₃ (біт 0):  голоси  1 0 1 1  →  більшість 1  →  a = 1
```

Зіпсована точка щоразу псує один голос — і щоразу лишається в меншості. Далі декодер віднімає знайдену лінійну частину x₂ ⊕ x₃ від прийнятого й дістає залишок `1 1 0 1 1 1 1 1` — сім одиниць проти одного нуля; більшість дає a₀ = 1. Відновлено (1; 0, 1, 1) — точно те, що передавали.

> 🔧 **Навіщо саме голосування.** Жодного ділення, жодних таблиць синдромів: голос — це XOR кількох бітів, рішення — лічильник «чого більше, нулів чи одиниць». А головне, усі 2^(m−r) голосів за даний коефіцієнт незалежні, тож їх рахують **паралельно** — сотні однакових крихітних схем працюють водночас. Саме тому мажоритарний декодер лягає в залізо ще тоді, коли жодного придатного процесора на борту нема.

## Швидкий шлях RM(1, m): «зелена машина»

Для першого порядку є кардинально швидший спосіб — і саме він літав. Переведімо прийняті біти в ±1 (0 → +1, 1 → −1). Лінійна частина кодового слова тоді стає функцією **Волша** — вектором з ±1; різні лінійні частини дають **ортогональні** функції Волша, а їх рівно 2ᵐ. Вільний член a₀ лише перевертає знак усього вектора. Тому декодувати означає знайти функцію Волша, найбільш скорельовану з прийнятим (це і є декодування за максимальною правдоподібністю: найближче слово ⟺ найбільша кореляція), а знак кореляції відновить a₀. Наївно це 2^(m+1) кореляцій по n множень — але всі 2ᵐ кореляцій зв'язані спільною структурою, і **одне швидке перетворення Адамара** видає їх усі за O(n·log n):

```c
/* Швидкий декодер першого порядку RM(1,m) — «зелена машина».
   Одне перетворення Адамара дає всі 2^m кореляцій; пік — це відповідь. */
void rm_decode_fht(int m, const int *recv, int *msg) {
    int n = 1 << m;
    int H[RM_MAXN];
    for (int t = 0; t < n; t++) H[t] = 1 - 2 * recv[t];     /* 0→+1, 1→−1 */

    for (int len = 1; len < n; len <<= 1)                   /* швидкий Адамар */
        for (int i = 0; i < n; i += len << 1)
            for (int j = i; j < i + len; j++) {
                int u = H[j], v = H[j + len];
                H[j]       = u + v;
                H[j + len] = u - v;
            }

    int best = 0;                                           /* argmax |H[a]| */
    for (int a = 1; a < n; a++)
        if (abs(H[a]) > abs(H[best])) best = a;

    for (int S = 0; S < n; S++) msg[S] = 0;
    msg[0] = (H[best] < 0) ? 1 : 0;                         /* a0 — зі знаку */
    for (int i = 0; i < m; i++)                             /* a_i — біти піку */
        if (best & (1 << i)) msg[1 << i] = 1;
}
```

Метелик лише додає й віднімає — і за log₂ n кроків клітинка H[a] стає сумою `Σ_t (−1)^{popcount(a & t)} · R[t]`, тобто кореляцією прийнятого R з a-ю функцією Волша. Далі `argmax |H[a]|`: індекс піку дає лінійну частину (його біти — це коефіцієнти при змінних), а **знак** піку дає вільний член (плюс → a₀ = 0, мінус → a₀ = 1).

Проженімо той самий прийнятий вектор `recv = 1 0 1 1 1 0 0 1`. Після ±1: R = [−1, +1, −1, −1, −1, +1, +1, −1]. Одне перетворення дає спектр

```
     a =    0    1    2    3    4    5    6    7
   H[a] =  -2   -2    2   -6   -2   -2    2    2
```

Максимум за модулем — |−6| у клітинці a = 3 = `011`. Отже, лінійна частина x₂ ⊕ x₃, а знак мінус → a₀ = 1. Знову (1; 0, 1, 1) — тим самим одним проходом, без жодного перебору.

*Машина в роботі. Ті самі вісім бітів, переведені в ±1, проходять три кроки метелика — кожен лише додає й віднімає пари, — і на виході стоять усі вісім кореляцій одразу. Пік за модулем (тут −6 у клітинці 011) прямо називає найближче кодове слово: індекс — це змінні лінійної частини, знак — вільний член. Один прохід замість перебору всіх слів — ось чому це «швидкий» декодер.*

> 🔧 **М'яке рішення задарма.** Найцінніше не швидкість, а те, що метелику байдуже до рівно ±1. Подайте на вхід не тверді біти, а **реальні** відліки демодулятора (наскільки впевнено кожен схожий на 0 чи 1) — і те саме перетворення поверне зважені кореляції, а argmax дасть уже м'яке декодування за максимальною правдоподібністю. Саме так «зелена машина» витягала знімки зі слабкого сигналу: вона не рахувала перевернуті біти, а корелювала аналогові рівні — і кожні шість бітів яскравості пікселя, закодовані як RM(1, 5) = [32, 6, 16] (виправляє сім помилок на слово), поверталися одним Адамаровим проходом.

Зібравши три функції докупи, дістаємо повну програму, що кодує, псує один біт і розкодовує обома шляхами:

```c
int main(void) {
    int m = 3, r = 1, n = 1 << m;
    int msg[RM_MAXN] = {0}, code[RM_MAXN], recv[RM_MAXN], out[RM_MAXN];

    /* f = 1 ⊕ x₂ ⊕ x₃.  Маски: 1→x₃, 2→x₂, 4→x₁ */
    msg[0] = 1; msg[2] = 1; msg[1] = 1;

    rm_encode(m, msg, code);
    for (int t = 0; t < n; t++) recv[t] = code[t];
    recv[2] ^= 1;                          /* канал псує точку 010 = індекс 2 */

    rm_decode_reed(m, r, recv, out);
    printf("Рід:    a0=%d  x1=%d  x2=%d  x3=%d\n", out[0], out[4], out[2], out[1]);

    rm_decode_fht(m, recv, out);
    printf("Адамар: a0=%d  x1=%d  x2=%d  x3=%d\n", out[0], out[4], out[2], out[1]);
    return 0;
}
```

```
Адамар: a0=1  x1=0  x2=1  x3=1
```

## Складність і пастки

**Ціна.** Декодер Ріда коштує O(n·k): кожен із k коефіцієнтів голосується за один прохід по всіх n точках (два цикли підмасок разом торкаються рівно 2ᵐ клітинок), плюс стільки ж на віднімання шарів. Для високошвидкісних кодів k наближається до n, тобто до O(n²). Адамарів декодер — O(n·log n) і до того ж дає **глобально найближче** слово; плата за це — він лише для першого порядку.

**Парність голосів.** Число голосів 2^(m−s) — завжди степінь двійки, отже, **парне**. Тому можлива нічия: рівно половина голосів зіпсована. Строгий поріг `2*ones > total` розв'язує нічию на користь нуля — що при перевищенні межі буває помилкою. Межа виправлення тут t = 2^(m−r−1) − 1 = ⌊(d−1)/2⌋; для RM(1, 5) = [32, 6, 16] це сім помилок на слово. Рівно на t помилок голоси ще розходяться на користь правди; на t+1 нічия чи перевага брехні вже цілком реальні.

**Тихий збій.** Обидва декодери **завжди** щось повертають — прапорця «не вдалося» нема. Понад t помилок декодер Ріда видасть неправильне повідомлення, Адамарів — неправильне найближче слово, і жоден про це не попередить. Хочете виявляти провал — перевіряйте самі: перекодуйте відповідь і зіставте з прийнятим (завелика відстань — сигнал біди), а для Адамара дивіться **запас піку** — якщо найбільший |H| лише трохи вищий за наступний, рішення ненадійне.

**Кластер помилок — м'якший.** Кілька помилок в одному блоці підкуба псують той самий один голос, а **парне** їх число там навіть скорочується в XOR — тобто щільна пляма помилок декодерові Ріда легша за ту саму кількість, розсіяну по різних блоках. Гарантія ⌊(d−1)/2⌋ тримається для будь-якого розкладу, але найгірший випадок — саме розсіяний.

**Переповнення.** Значення в масиві H не виходять за межі [−n, n], тож `int` тримає навіть велетенські m; розганяти акумулятор до `long` не треба.

Обидва декодери — це та сама одна ідея у двох темпах. XOR по підкубу, що його теорія зве голосуванням, — це кілька рядків C; а ортогональність, що робить доказ можливим, робить один Адамарів прохід достатнім, щоб розкодувати цілий кадр. Перше зібрали з лічильників у 1954-му, друге привезло перші чіткі знімки іншої планети — і обидва вкладаються в пів екрана коду.
