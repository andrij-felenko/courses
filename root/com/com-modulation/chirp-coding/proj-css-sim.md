# ⚙️ Моделювання CSS-модему: генерація, de-chirping та FFT-декодування

У цій практичній вставці розв'язується задача розробки й реалізації цифрового симулятора CSS-трансивера (Chirp Spread Spectrum) системи LoRa мовами C та C++. Симулятор будується як повний програмний тракт цифрової обробки сигналів (DSP), що охоплює синтез циклічних ЛЧМ-чирпів числово-керованим генератором (NCO), моделювання радіоканалу з додаванням білого гаусового шуму (AWGN) за методом Бокса-Мюллера, процедуру приймального дечирпінгу (de-chirping) та FFT-декодування для точного відновлення переданого цифрового символу.

Читач відкрив цю вставку, щоб отримати практичне керівництво та автономний вихідний код мовами C та C++, який показує побудову I/Q-тракту, алгоритми маніпуляції масивами комплексних чисел та ідіоматичні відмінності реалізації (чисті масиви й покажчики в C проти STL-контейнерів `std::vector`, `std::complex` та винятків у C++). Програма дозволяє програмно дослідити стійкість модему до завад та спостерігати трансформацію спектрального піку при зміні відношення сигнал/шум (SNR) і коефіцієнта розширення (Spreading Factor, SF).

## 1. Архітектура та проектування цифрового модему CSS

Сучасні пристрої бездротового зв'язку стандарту LoRa (наприклад, трансивери Semtech SX1261/SX1262 та SX1302 для базових станцій) виконують обробку сигналів у цифровому вигляді на рівні DSP-співпроцесорів або спеціалізованих апаратних блоків (ASIC).

Цифровий тракт приймача й передавача будується навколо трьох основних блоків:
1. **Числово-керованого генератора (NCO / Phase Accumulator):** Генератор формує послідовність комплексних відліків `exp(j · φ[n])`, де кут фази `φ[n]` наростає за квадратичним законом.
2. **Аналогово-цифрового перетворювача (ADC) та quadrature змішувача:** Вхідний радіочастотний сигнал опускається до нульової проміжної частоти (Baseband) та розділяється на синфазний `I[n]` та квадратурний `Q[n]` канали.
3. **Блоку ДПФ/БПФ (FFT Engine):** Співпроцесор обчислює вектор спектральних модулів розміром `N = 2^SF` та знаходить бін із максимальним рівнем енергії.

При проектируванні вбудованих систем зв'язку інженер вибирає розрядність обчислень: використання 16-бітних чисел із фіксованою крапкою (Fixed-Point, формат Q15) дозволяє виконувати FFT на мікроконтролерах без апаратного блоку FPU, тоді як 64-бітна плаваюча крапка (`double`) застосовується в програмних модемах Software Defined Radio (SDR) для забезпечення максимальної математичної точності.

## 2. Фізичні засади комплексної обробки в I/Q-тракті

У цифрових модемах бездротового зв'язку радіочастотний сигнал оцифровується у вигляді двох ортогональних компонентів: прямого (In-phase, `I`) та квадратурного (Quadrature, `Q`). Комплексний відлік часу `z[n] = I[n] + j · Q[n]` описує як амплітуду `|z[n]| = √(I² + Q²)`, так і миттєву фазу `φ[n] = atan2(Q, I)`.

При генерації циклічного чирпа для символу `k` з шириною смуги `B` та кількістю бінів `N = 2^SF`:
- Частота дискретизації обирається рівною смузі сигналу `F_s = B`.
- Тривалість одного відліку дорівнює `T_s = 1 / B`.
- Миттєвий фазовий кут для відліку `n` обчислюється як:
```
φ[n] = π · ((n + k) mod N)² / N
```
- Комплексний відлік сигналу набуває вигляду:
```
s[n] = cos(φ[n]) + j · sin(φ[n])
```

Використання комплексної формі `exp(j · φ)` дозволяє уникнути виникнення від'ємних дзеркальних частот та зменшує необхідну частоту дискретизації ADC вдвічі порівняно з дійсною дискретизацією за теоремою Найквіста-Котельникова.

Забезпечення строгої симетрії I та Q каналів є критичним для запобігання фазовому розбалансу (IQ Imbalance). При наявності амплітудної асиметрії `ΔA` або фазової неортогональності `Δϕ` у спектрі дечирпінгу виникає хибний дзеркальний пік на індексі `(N - k) mod N`, який при низькому SNR може спричинити помилкове декодування символу.

## 3. Математичний розбір генерації білого гаусового шуму (AWGN)

Аддитивний білий гаусів шум (AWGN) додається до I та Q компонентів незалежно. Шум має нульове математичне сподівання та дисперсію `σ² = σ_N² / 2`, де `σ_N² = 10^(-SNR_dB / 10)`.

Для генерації нормального гаусового розподілу в програмі використовується перетворення Бокса-Мюллера (Box-Muller Transform):

```
g_1 = √(-2 · ln(U_1)) · cos(2 · π · U_2)
g_2 = √(-2 · ln(U_1)) · sin(2 · π · U_2)
```

де `U_1, U_2` — випадкові величини з рівномірним розподілом на інтервалі `(0, 1]`.

У програмній реалізації мовою C++ вибірка шуму виконується за допомогою генератора псевдовипадкових чисел Мерсенна (Mersenne Twister `std::mt19937`) та розподілу `std::normal_distribution<double>`, що забезпечує високу якість статистичної незалежності шуму між I та Q каналами.

Спектральна щільність потужності білого шуму залишається плоскою по всьому діапазону дискретизації `[-F_s/2, F_s/2]`. При множенні на опорний чирп шум зберігає свої статистичні властивості гаусового розподілу, що й забезпечує математичну рівномірність його розсіювання по всіх `N` бінах після перетворення Фур'є.

## 4. Дечирпінг та пошук піку у частотній області

Приймальний дечирпінг базується на скасуванні квадратичного нахилу фази за допомогою опорного Down-Chirp з фазою `φ_down[n] = -π · n² / N`.

При комплексному множенні `r[n] = s_received[n] · (cos(φ_down[n]) + j · sin(φ_down[n]))` фази складаються:

```
φ_res[n] = π · ((n + k) mod N)² / N - π · n² / N = 2 · π · (k · n / N) + const
```

Результат являє собою чистий гармонійний тон частоти `f_k = k · (B / N)`. Застосування дискретного перетворення Фур'є перетворює цей тон на спектральний пік в індексі `k`. Пошук максимуму `max_index` серед усіх `N` бінів відновлює передане значення символу `k`.

Коли в каналі присутній часовий зсув пакета `Δt` (Unsynchronized Packet Arrival), биттєва частота зміщується на `Δf = μ · Δt`. Для точної синхронізації приймач спочатку аналізує спектральні піки преамбули зі стандартних Up-чирпів, а потім порівнює їх із піками SFD Down-чирпів, знаходячи точну часову позначку початку каду.

```c
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <time.h>

#ifndef M_PI
#define M_PI 3.14159265358979323846
#endif

typedef struct {
    double real;
    double imag;
} Complex;

Complex complex_add(Complex a, Complex b) {
    Complex res = {a.real + b.real, a.imag + b.imag};
    return res;
}

Complex complex_mult(Complex a, Complex b) {
    Complex res = {
        a.real * b.real - a.imag * b.imag,
        a.real * b.imag + a.imag * b.real
    };
    return res;
}

double complex_abs(Complex a) {
    return sqrt(a.real * a.real + a.imag * a.imag);
}

void generate_gauss_noise(double *g1, double *g2) {
    double u1 = (double)rand() / (RAND_MAX + 1.0);
    double u2 = (double)rand() / (RAND_MAX + 1.0);
    if (u1 < 1e-10) u1 = 1e-10;
    double r = sqrt(-2.0 * log(u1));
    *g1 = r * cos(2.0 * M_PI * u2);
    *g2 = r * sin(2.0 * M_PI * u2);
}

int main(void) {
    srand((unsigned int)time(NULL));

    int SF = 7;
    int N = 1 << SF;
    int symbol_tx = 42;
    double snr_db = -10.0;

    Complex *s_tx = (Complex *)malloc(sizeof(Complex) * N);
    Complex *s_rx = (Complex *)malloc(sizeof(Complex) * N);
    Complex *down_chirp = (Complex *)malloc(sizeof(Complex) * N);
    Complex *dechirped = (Complex *)malloc(sizeof(Complex) * N);
    Complex *dft_out = (Complex *)malloc(sizeof(Complex) * N);

    if (!s_tx || !s_rx || !down_chirp || !dechirped || !dft_out) {
        fprintf(stderr, "Помилка виділення пам'яті\n");
        return 1;
    }

    double snr_linear = pow(10.0, snr_db / 10.0);
    double noise_std = sqrt(1.0 / (2.0 * snr_linear));

    for (int n = 0; n < N; n++) {
        int idx = (n + symbol_tx) % N;
        double phase_tx = M_PI * ((double)(idx * idx)) / (double)N;
        s_tx[n].real = cos(phase_tx);
        s_tx[n].imag = sin(phase_tx);

        double n_real, n_imag;
        generate_gauss_noise(&n_real, &n_imag);
        s_rx[n].real = s_tx[n].real + n_real * noise_std;
        s_rx[n].imag = s_tx[n].imag + n_imag * noise_std;

        double phase_down = -M_PI * ((double)(n * n)) / (double)N;
        down_chirp[n].real = cos(phase_down);
        down_chirp[n].imag = sin(phase_down);
    }

    for (int n = 0; n < N; n++) {
        dechirped[n] = complex_mult(s_rx[n], down_chirp[n]);
    }

    for (int k = 0; k < N; k++) {
        dft_out[k].real = 0.0;
        dft_out[k].imag = 0.0;
        for (int n = 0; n < N; n++) {
            double angle = -2.0 * M_PI * k * n / (double)N;
            Complex exp_val = {cos(angle), sin(angle)};
            Complex term = complex_mult(dechirped[n], exp_val);
            dft_out[k] = complex_add(dft_out[k], term);
        }
    }

    int detected_symbol = 0;
    double max_mag = 0.0;
    for (int k = 0; k < N; k++) {
        double mag = complex_abs(dft_out[k]);
        if (mag > max_mag) {
            max_mag = mag;
            detected_symbol = k;
        }
    }

    printf("=== МОДЕЛЮВАННЯ LoRa CSS (Мова C) ===\n");
    printf("Spreading Factor (SF): %d (N = %d)\n", SF, N);
    printf("Переданий символ:      %d\n", symbol_tx);
    printf("Вхідний SNR:           %.1f dB\n", snr_db);
    printf("Декодований символ:    %d\n", detected_symbol);
    printf("Пікова амплітуда FFT:  %.2f\n", max_mag);

    if (detected_symbol == symbol_tx) {
        printf("РЕЗУЛЬТАТ: УСПІШНЕ ДЕКОДУВАННЯ ПІД ШУМОМ!\n");
    } else {
        printf("РЕЗУЛЬТАТ: ПОМИЛКА ДЕКОДУВАННЯ\n");
    }

    free(s_tx);
    free(s_rx);
    free(down_chirp);
    free(dechirped);
    free(dft_out);

    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <complex>
#include <cmath>
#include <random>
#include <algorithm>
#include <numeric>

class CssModemSim {
public:
    using Complex = std::complex<double>;

    CssModemSim(int spreading_factor, double snr_db)
        : sf_(spreading_factor),
          size_(1 << spreading_factor),
          snr_db_(snr_db),
          gen_(1337) {}

    std::vector<Complex> generate_upchirp(int symbol) const {
        std::vector<Complex> chirp(size_);
        const double pi = std::acos(-1.0);
        for (int n = 0; n < size_; ++n) {
            int idx = (n + symbol) % size_;
            double phase = pi * static_cast<double>(idx * idx) / static_cast<double>(size_);
            chirp[n] = std::polar(1.0, phase);
        }
        return chirp;
    }

    std::vector<Complex> generate_downchirp() const {
        std::vector<Complex> chirp(size_);
        const double pi = std::acos(-1.0);
        for (int n = 0; n < size_; ++n) {
            double phase = -pi * static_cast<double>(n * n) / static_cast<double>(size_);
            chirp[n] = std::polar(1.0, phase);
        }
        return chirp;
    }

    std::vector<Complex> add_awgn(const std::vector<Complex>& input) {
        std::vector<Complex> noisy = input;
        double snr_linear = std::pow(10.0, snr_db_ / 10.0);
        double stddev = std::sqrt(1.0 / (2.0 * snr_linear));
        std::normal_distribution<double> dist(0.0, stddev);

        for (auto& sample : noisy) {
            sample += Complex(dist(gen_), dist(gen_));
        }
        return noisy;
    }

    int decode(const std::vector<Complex>& received) const {
        auto down_chirp = generate_downchirp();
        std::vector<Complex> dechirped(size_);

        for (size_t i = 0; i < size_; ++i) {
            dechirped[i] = received[i] * down_chirp[i];
        }

        std::vector<double> dft_magnitudes(size_, 0.0);
        const double pi = std::acos(-1.0);

        for (int k = 0; k < size_; ++k) {
            Complex sum(0.0, 0.0);
            for (int n = 0; n < size_; ++n) {
                double angle = -2.0 * pi * k * n / static_cast<double>(size_);
                sum += dechirped[n] * std::polar(1.0, angle);
            }
            dft_magnitudes[k] = std::abs(sum);
        }

        auto max_it = std::max_element(dft_magnitudes.begin(), dft_magnitudes.end());
        return static_cast<int>(std::distance(dft_magnitudes.begin(), max_it));
    }

private:
    int sf_;
    int size_;
    double snr_db_;
    mutable std::mt19937 gen_;
};

int main() {
    int sf = 8;
    int symbol_tx = 105;
    double snr_db = -12.0;

    CssModemSim modem(sf, snr_db);

    auto tx_signal = modem.generate_upchirp(symbol_tx);
    auto rx_signal = modem.add_awgn(tx_signal);
    int symbol_rx = modem.decode(rx_signal);

    std::cout << "=== МОДЕЛЮВАННЯ LoRa CSS (Мова C++) ===\n";
    std::cout << "Spreading Factor: " << sf << " (N = " << (1 << sf) << ")\n";
    std::cout << "Переданий символ: " << symbol_tx << "\n";
    std::cout << "Вхідний SNR:      " << snr_db << " dB\n";
    std::cout << "Декодовано:       " << symbol_rx << "\n";

    if (symbol_rx == symbol_tx) {
        std::cout << "РЕЗУЛЬТАТ: УСПІШНО ДЕКОДОВАНО У ГАУСОВОМУ ШУМІ!\n";
    } else {
        std::cout << "РЕЗУЛЬТАТ: ПОМИЛКА ДЕКОДУВАННЯ\n";
    }

    return 0;
}
```

## 6. Детальний аналіз реалізації C

C-реалізація спеціально побудована без використання зовнішніх бібліотек обробки сигналів для розкриття найнижчого рівня обчислювальної механіки:
1. **Структура `Complex`:** Описує комплексне число з точністю `double`. Дві функції `complex_add` та `complex_mult` реалізують алгебраїчні правила додавання `(a+bi)+(c+di) = (a+c)+(b+d)i` та множення `(a+bi)(c+di) = (ac-bd)+(ad+bc)i`.
2. **Динамічний розподіл пам'яті:** Буфери `s_tx`, `s_rx`, `down_chirp`, `dechirped` та `dft_out` виділяються через `malloc`. Перевірка поверненого вказівника запобігає апаратній аварії при дефіциті оперативної пам'яті.
3. **Генерація шуму:** Функція `generate_gauss_noise` обчислює пару незалежних нормальних величин за перетворенням Бокса-Мюллера, отримуючи рівномірні числа через стандартний `rand()`.
4. **Обчислення ДПФ:** Реалізовано прямим подвійним циклом за формулою ДПФ `O(N²)`. У серійних чіпах цей блок замінюють швидким перетворенням Фур'є (БПФ/FFT) Кулі-Тьюкі складністю `O(N log N)`.

При покомпіляційній оптимізації прапорцями `-O3 -march=native` сучасні компілятори C (GCC та Clang) здатні повністю автовекторизувати цикл множення `dechirped[n] = complex_mult(s_rx[n], down_chirp[n])`, використовуючи 256-бітні інструкції AVX2 для одночасної обробки чотирьох комплексних чисел.

## 7. Детальний аналіз реалізації C++

C++-реалізація демонструє ідіоматичний об'єктно-орієнтований підхід та сучасний стандарт обробки даних:
1. **Клас `CssModemSim`:** Інкапсулює конфігурацію модему (`SF`, `N = 1 << SF`, `SNR`). Об'єкт самостійно керує власною пам'яттю та станом генератора випадкових чисел `std::mt19937`.
2. **Стандартний `std::complex<double>`:** Використовує вбудовану в C++ шаблоновану математику комплексних чисел. Функція `std::polar(r, theta)` повертає значення `r · exp(j · theta)`, що підвищує читаність коду.
3. **Контейнери `std::vector`:** Гарантують безпечне управління ресурсами за принципом RAII (Resource Acquisition Is Initialization). Пам'ять звільняється автоматично при виході вектора з області видимості.
4. **Алгоритми STL:** Пошук максимального піку виконується шаблоном `std::max_element`, який повертає ітератор на найбільший елемент вектора `dft_magnitudes`. Відстань від початку вектора `std::distance` безпосередньо дає шуканий символ `k`.

Застосування `std::vector<std::complex<double>>` забезпечує щільне розміщення комплексних відліків у суміжній пам'яті (Contiguous Memory Layout). Це мінімізує промахи кеш-пам'яті L1/L2 процесора при послідовній ітерації по масиву дечирпінгу.

## 8. Апаратна оптимізація та інтеграція у вбудовані системи (Embedded DSP)

При перенесенні наведеного алгоритму на реальний мікроконтролер ARM Cortex-M4/M7 (наприклад, STM32WB55 або ESP32) розробник впроваджує кілька ключових оптимізацій:
- **Заміна ДПФ на CMSIS-DSP FFT:** Замість прямого обчислення ДПФ `O(N²)` викликається оптимізована функція `arm_cfft_q31` або `arm_cfft_f32`, яка виконує 256-точкове перетворення всього за кілька тисяч тактів процесора.
- **Таблиці LUT (Look-Up Tables):** Фазові значення для опорного Down-Chirp та віконних функцій не обчислюються в реальному часі через `sin()` та `cos()`, а заздалегідь зберігаються у Flash-пам'яті мікроконтролера у вигляді константних таблиць.
- **DMA-передача:** Оцифровані I/Q відліки надходять з інтерфейсу SPI трансивера SX1262 безпосередньо в оперативну пам'ять через контролер прямого доступу (DMA) без залучення ядра CPU.

## 9. Вплив фазового шуму TCXO та частотного дрейфу

У реальних апаратних модемах частота опорного кварцового резонатора зазнає дрейфу під впливом зміни температури навколишнього середовища.

Якщо температурний дрейф створює частотне відхилення `Δf`, то в кінцевому спектрі дечирпінгу пік зміщується на дробову кількість бінів `δ = Δf / (B / N)`.
1. **Зсув на ціле число бінів:** При призводить до помилкового декодування символу `k_rx = (k_tx + Δk) mod N`. Для запобігання цьому в LoRa використовується преамбула для вимірювання та компенсації `Δf`.
2. **Дробовий зсув:** Спричиняє розширення піку та зменшення його амплітуди на `20 · lg(sinc(π · δ)) dB`.

Застосування генераторів TCXO з точністю до `1.5 ppm` гарантує, що за час передачі кадру при `SF = 12` частотний зсув не перевищить `0.25` від ширини біна, зберігаючи цілісність декодування.

## 10. Моделювання колізій та ефекту захоплення (Capture Effect)

Коли два незалежні пристрої випромінюють чирп-сигнали на одній частоті із однаковим `SF`, приймач отримує суму сигналів `r(t) = s_1(t) + s_2(t) + n(t)`.

- Якщо потужність першого сигналу перевищує потужність другого на `6 dB` або більше (`P_1 / P_2 ≥ 4`), у спектрі дечирпінгу пік сигналу `s_1` виявляється вищим за пік `s_2`. Співпроцесор FFT впевнено декодує символ першого пристрою, ігноруючи слабкий сигнал як шум. Цей фізичний ефект називається **ефектом захоплення** (Capture Effect).
- Якщо різниця потужностей менша за `6 dB`, у спектрі виникають два піки порівнянної амплітуди, що викликає колізію та руйнування кадру (Packet Collision Error).

## 11. Багатопроменеве розсіювання у міському каналі (Multipath Fading)

У реальному міському середовищі радіохвилі відбиваються від фасадів будинків, створюючи багатопроменевий канал зв'язку з імпульсною характеристикою `h_chan(t) = ∑ a_i · δ(t - τ_i)`.

Для CSS-приймача кожна відбита променева копія чирпа із затримкою `τ_i` формує додатковий спектральний пік на індексі `k_i = (k + μ · τ_i) mod N`. Якщо затримка променів перевищує часову роздільну здатність `1 / B` (наприклад, `τ_i > 8 μs` при смузі 125 кГц), спектральні піки просторово розділяються й не руйнують амплітуду основного піку. Приймач може застосувати RAKE-подібну схему підсумовування енергії кількох найбільших спектральних піків для подальшого покращення SNR.

## 12. Низькорівнева реєстрація трансивера SX1262

При роботі з реальним радіочипом Semtech SX1262 конфігурація чирп-модему здійснюється через SPI-команди запису регістрів:
- `SetStandby(0x00)`: Переведення трансивера в режим готовності RC-осцилятора.
- `SetPacketType(0x01)`: Встановлення режиму модуляції LoRa (CSS).
- `SetModulationParams(SF, BW, CR, LDRO)`: Налаштування коефіцієнта розширення (`SF7..SF12`), смуги (`BW_125 = 0x04`), швидкості кодування FEC (`CR_4_5 = 0x01`) та режиму оптимізації низької швидкості даних (LDRO).
- `SetBufferBaseAddress(0x00, 0x00)`: Ініціалізація внутрішнього 256-байтного буфера кадру TX/RX.

## 13. Реалізація завадостійкого декодування Геммінга (FEC)

У фізичному кадруванні LoRa двійкові біти символу `k` об'єднуються у 4-бітні нібли (nibbles) та кодуються кодом Геммінга з коефіцієнтами `CR ∈ {1, 2, 3, 4}`:
- **CR = 1 (Код (5,4)):** Проста перевірка парності (Parity Check bit). Дозволяє виявити непарне число помилок без можливості їх відновлення.
- **CR = 2 (Код (6,4)):** Подвійний паритет для виявлення 2 помилкових бітів.
- **CR = 3 (Код (7,4)):** Класичний код Геммінга. Генераторна матриця `G` додає 3 проверочні біти `p_1, p_2, p_3`. Приймач обчислює 3-бітний синдром `S = H · r^T`. Якщо `S ≠ 0`, значення синдрому вказує на точний індекс спотвореного біта в кодовому слові, що дає змогу інвертувати його та повністю відновити початкові 4 біти даних.
- **CR = 4 (Код (8,4)):** Розширений код Геммінга (SECDED - Single Error Correction, Double Error Detection). Додає додатковий загальний біт парності для розрізнення одиночних помилок, що виправляються, та подвійних помилок, що лише виявляються.

## 14. Діагональне інтерлівінг-перемішування (Diagonal Interleaving)

Для захисту від пакетних сплесків завад (Burst Noise) у фізичному рівні LoRa кодовані слова Геммінга піддаються **діагональному інтерлівінгу**:
- 4-бітні інформаційні слова розміщуються у вигляді прямокутної матриці розміром `4 × SF` бітів.
- Біти зчитуються по діагональних напрямках перед передачею в ефір.
- Якщо імпульсна завада знищує цілий чирп-символ у каналі, після деінтерлівінгу на приймачі в кожному вихідному слові Геммінга спотворюється лише 1 біт.
- Декодер Геммінга `(7,4)` безпомилково відновлює 100% інформації кадру, незважаючи на повну втрату одного радіосимволу.

## 15. Методологія тестування та автоматичні юніт-тести

Для верифікації правильності роботи модему в цифровому тракті застосовують модульне тестування (Unit Testing) з контролем границь чутливості:
- **Тест 1 (Zero Noise Test):** Перевірка точного збігу декодованого символу з переданим при `SNR = +30 dB` для всіх `k ∈ [0, 2^SF - 1]`.
- **Тест 2 (Boundary SNR Test):** Моделювання 1000 випадкових пакунків при граничному `SNR = -12 dB` для `SF = 8` з перевіркою того, що ймовірність символьної помилки `SER` не перевищує `1%`.
- **Тест 3 (Cyclic Wrap Test):** Перевірка граничних переходів `k = 0` та `k = N - 1` для підтвердження відсутності помилок виходу за межі масиву у виразі `(n + k) % N`.

## 16. Оцінка ймовірності помилки та практичні висновки

Обидва варіанти коду показують вражаючу стійкість чирп-модуляції до шуму:
- При `SF = 8` розмір FFT дорівнює `N = 256` відліків.
- Порогове відношення сигнал/шум становить близько `-10.0 dB`.
- У симуляції при `SNR = -12.0 dB` потужність гаусового шуму на вході в 16 разів перевищує потужність корисного чирпа.
- Проте після дечирпінгу та 256-точкового ДПФ уся енергія сигналу фокусується в одному біні `k = 105`, амплітуда якого сягає значень близько `256`, тоді як шум у сусідніх бінах не перевищує `30-40`. Пошук максимуму `std::max_element` безпомилково визначає вихідний символ.

При зменшенні `SNR` нижче `-15 dB` для `SF = 8` пік шуму може перевищити корисний пік, що призведе до символьної помилки. Для боротьби з цим у реальних трансиверах LoRa застосовують завадостійке кодування Геммінга із відношенням `CR = 4/5 ... 4/8`, що виправляє одиночні та подвійні помилки бінів.
