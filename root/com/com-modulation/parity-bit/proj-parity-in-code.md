# ⚙️ Біт парності в коді: рахуємо, додаємо, перевіряємо

> ⚙️ Алгоритмічна вставка до теми про [біт парності](topic:com-modulation/parity-bit). Сама ідея коротка: парність — це [XOR](topic:hw-digital/xor-comparison) усіх бітів даних, один зайвий біт, що добиває кількість одиниць до парної (even) або непарної (odd). Тут ми перетворимо її на робочий C: порахуємо парність байта без циклу, спакуємо дані з бітом парності в одне слово й перевіримо його на боці приймача для обох домовленостей. Заразом стане видно, де така перевірка [мовчить](topic:sf-data/bit-flips) попри зіпсовані дані.

## Задача

Нам треба три маленькі цеглинки, з яких складають будь-яку перевірку парності в прошивці. Перша: за байтом даних дістати **один біт** — парність його одиниць. Друга: **спакувати** дані разом із цим бітом так, щоб усього виходило парне (чи непарне) число одиниць, і відправити. Третя: на приймачі **перерахувати** і сказати «ціле» чи «бите». Усе це має крутитися на крихітному мікроконтролері в обробнику переривання UART, тож дозволені лише дешеві операції — XOR, зсуви, маски; жодних таблиць і ділень.

## Ідея

Найпряміший спосіб порахувати парність байта — пройтися циклом по восьми бітах і поксорити їх. Він працює, але вісім ітерацій на кожен байт — забагато там, де байти течуть потоком. Швидше **скласти байт сам із собою зсувами** (XOR-згортка, *XOR folding*): спершу ксоримо верхню половину з нижньою, тоді половину половини й так далі, аж доки вся інформація про парність стечеться в наймолодший біт.

```c
        b = b ^ (b >> 4);   // зсунули старші 4 біти на молодші й поксорили
        b = b ^ (b >> 2);   // тепер парність 8 бітів живе в нижніх 2
        b = b ^ (b >> 1);   // …і нарешті — у найменшому біті
        parity = b & 1;     // 1, якщо одиниць було непарно
```

Чому це працює: XOR двох бітів дає 1 саме тоді, коли серед них непарне число одиниць, а XOR асоціативний і комутативний — тож можна ксорити біти будь-якими групами, результат не зміниться. Згортаючи байт навпіл тричі (8 → 4 → 2 → 1), ми за **три** операції замість восьми зводимо всю парність в один біт. Це і є той самий «XOR усіх бітів», тільки порахований розумно.

> 🔧 **Навіщо це.** Цей чотирирядковий прийом — те, що реально стоїть в обробнику UART чи в перевірці слова з регістра: він рахує парність за лічені такти, без циклу й без таблиці, і годиться навіть для 8-розрядного контролера, де кожна інструкція на рахунку. Той самий шаблон згортки зсувами лічить і кількість одиниць загалом (popcount), і парність ширших слів — досить додати ще один крок `>> 8`, `>> 16` для 16- та 32-бітних значень.

## Робочий код

Зберемо три функції: підрахунок парності, пакування слова й перевірку. Працюємо з 7 бітами даних і 1 бітом парності у старшому розряді байта — рівно так, як «7E1»/«7O1» у налаштуваннях послідовного порту (7 біт даних, even/odd, 1 стоповий).

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

// 1 — якщо серед одиниць байта непарне число (XOR усіх бітів)
static inline uint8_t parity_of(uint8_t b) {
    b ^= b >> 4;
    b ^= b >> 2;
    b ^= b >> 1;
    return b & 1u;
}

typedef enum { PARITY_EVEN, PARITY_ODD } parity_mode_t;

// Пакуємо 7 біт даних (0..0x7F) + біт парності у старший (8-й) розряд.
// even: загальна кількість одиниць у байті парна; odd: непарна.
uint8_t parity_encode(uint8_t data7, parity_mode_t mode) {
    uint8_t p = parity_of(data7 & 0x7Fu);   // парність самих даних
    if (mode == PARITY_ODD) p ^= 1u;        // для odd інвертуємо домовленість
    return (uint8_t)((p << 7) | (data7 & 0x7Fu));
}

// true — слово ціле за обраною домовленістю; false — помилка виявлена.
bool parity_check(uint8_t word, parity_mode_t mode) {
    uint8_t ones_odd = parity_of(word);     // парність усіх 8 бітів разом
    // even-домовленість вимагає парної суми (ones_odd == 0);
    // odd-домовленість вимагає непарної (ones_odd == 1).
    return ones_odd == (mode == PARITY_ODD ? 1u : 0u);
}
```
```python
from enum import Enum

# 1 — якщо серед одиниць байта непарне число (XOR усіх бітів)
def parity_of(b):
    b ^= b >> 4
    b ^= b >> 2
    b ^= b >> 1
    return b & 1

class ParityMode(Enum):
    EVEN = 0
    ODD = 1

# Пакуємо 7 біт даних (0..0x7F) + біт парності у старший (8-й) розряд.
# even: загальна кількість одиниць у байті парна; odd: непарна.
def parity_encode(data7, mode):
    p = parity_of(data7 & 0x7F)             # парність самих даних
    if mode == ParityMode.ODD:
        p ^= 1                              # для odd інвертуємо домовленість
    return (p << 7) | (data7 & 0x7F)

# True — слово ціле за обраною домовленістю; False — помилка виявлена.
def parity_check(word, mode):
    ones_odd = parity_of(word)              # парність усіх 8 бітів разом
    # even-домовленість вимагає парної суми (ones_odd == 0);
    # odd-домовленість вимагає непарної (ones_odd == 1).
    return ones_odd == (1 if mode == ParityMode.ODD else 0)
```
:::

Перевіримо на тому самому прикладі, що й у статті, — дані `1011011` (це `0x5B`, одиниць п'ять):

:::tabs
```c
uint8_t w = parity_encode(0x5B, PARITY_EVEN);  // p=1 (добили до парного) → w = 0xDB

parity_check(w, PARITY_EVEN);                   // true  — ціле ✓
parity_check(w ^ (1u << 2), PARITY_EVEN);       // false — 1 біт перевернувся, виявлено ✓
parity_check(w ^ (1u << 2) ^ (1u << 6), PARITY_EVEN); // true — 2 біти, ПРОПУЩЕНО ✗
```
```python
w = parity_encode(0x5B, ParityMode.EVEN)        # p=1 (добили до парного) → w = 0xDB

parity_check(w, ParityMode.EVEN)                        # True  — ціле ✓
parity_check(w ^ (1 << 2), ParityMode.EVEN)             # False — 1 біт перевернувся, виявлено ✓
parity_check(w ^ (1 << 2) ^ (1 << 6), ParityMode.EVEN)  # True — 2 біти, ПРОПУЩЕНО ✗
```
:::

Третій рядок — це і є сліпа пляма в коді: ми перевернули два біти, дані зіпсовані, а `parity_check` повертає `true`, бо парність кількості одиниць не змінилася. Жодна реалізація однобітної парності цього не зловить — це обмеження самого методу, а не коду.

## Пастки

Перша й найчастіша — **різні домовленості на кінцях**. Передавач кодує even, приймач перевіряє odd (або навпаки) — і кожен бездоганно цілий кадр приходить «битим». Симптом характерний: помилка не зрідка, а **на кожному** кадрі. Лікується одним: even/odd мусять збігатися з обох боків (у термінах порту — однакові «7E1» чи «7O1»).

Друга — **парність рахують не над тими бітами**. Якщо біт парності вже сидить у старшому розряді, а ви знову проганяєте через `parity_of` увесь байт під час кодування, то порахуєте парність разом із самим бітом парності й зіпсуєте слово. Тому `parity_encode` бере парність **тільки даних** (`data7 & 0x7F`), а `parity_check` — навпаки, **усього** слова разом із бітом.

Третя — спокуса повірити, що парність **виправляє**. Вона лише сигналить «десь є непарна помилка», але не каже де; відновити дані вона не може в принципі. Щойно треба не лише помітити, а й полагодити, однобітної парності замало — потрібен [код Геммінга](topic:com-modulation/hamming-code), де кілька бітів парності складаються в номер зіпсованого біта.
