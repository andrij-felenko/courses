# 🧮 Алгебра залишків у GF(2): лінійність і побудова таблиці LUT

Математична еквівалентність швидкого табличного обчислення CRC побітному зсувному регістру ґрунтується на фундаментальній властивості лінійності оператора взяття остачі в полі Галуа `GF(2)`: остача від суми двох многочленів тотожно дорівнює сумі їхніх окремих остач.

У двійковому полі Галуа `GF(2)` множина скалярних коефіцієнтів складається лише з двох чисел `{0, 1}`. Арифметичні операції додавання та віднімання в цьому полі повністю збігаються з порозрядною логічною функцією «виключного АБО» (`⊕`, XOR), а операція множення — з кон'юнкцією (`∧`, AND). Відсутність міжрозрядного переносу перетворює кільце многочленів `GF(2)[x]` на лінійний векторний простір над полем `GF(2)`. Ділення на фіксований твірний многочлен `G(x)` ступеня `n` є лінійним оператором редукції (відображенням з простору многочленів вищого степеня у підпростір залишків степеня менше `n`).

### Алгебраїчна структура кільця многочленів та лінійність оператора залишку

Розглянемо кільце многочленів `GF(2)[x]`. Будь-який двійковий блок даних довжиною `k` бітів однозначно задає многочлен `A(x) = a_{k-1}·x^{k-1} + ... + a_1·x + a_0`. 

За класичною теоремою про ділення з остачею в кільці многочленів над довільним полем, для будь-якого многочлена `A(x)` та ненульового твірного многочлена `G(x)` ступеня `n` існують єдині частка `Q_A(x)` і залишок `R_A(x)` такі, що виконується строга рівність:

```
A(x) = Q_A(x) · G(x) ⊕ R_A(x)
```

де степінь залишку строго обмежена розрядністю полінома: `deg(R_A(x)) < deg(G(x)) = n`. Позначимо операцію взяття остачі як `rem(A(x), G(x)) = R_A(x)`.

Дослідимо суму двох довільних двійкових повідомлень `A(x)` та `B(x)` однакової або різної довжини:

```
rem(A(x) ⊕ B(x), G(x))
= rem((Q_A(x)·G(x) ⊕ R_A(x)) ⊕ (Q_B(x)·G(x) ⊕ R_B(x)), G(x))     [підстановка розкладу многочленів A(x) та B(x)]
= rem((Q_A(x) ⊕ Q_B(x))·G(x) ⊕ (R_A(x) ⊕ R_B(x)), G(x))           [дистрибутивність множення в кільці GF(2)[x]]
= rem(R_A(x) ⊕ R_B(x), G(x))                                       [компоненти, кратні дільнику G(x), дають нульову остачу]
= R_A(x) ⊕ R_B(x)                                                  [оскільки deg(R_A ⊕ R_B) < n, редукція не потрібна]
= rem(A(x), G(x)) ⊕ rem(B(x), G(x))                                [за означенням окремих залишків R_A та R_B]
```

Ця теорема доводить, що взяття остачі в `GF(2)` є гомоморфізмом адитивних груп: залишок від побітової суми будь-якої кількості блоків дорівнює побітовій сумі залишків від кожного окремого блоку. Це дає змогу розділити довільний блок даних на окремі байти чи слова, знайти залишок для кожного фрагмента незалежно, а потім об'єднати результати через операцію XOR.

### Матричне подання та еволюція стану регістра

Зсувний регістр LFSR з `n` тригерів можна описати як вектор стану `S(t) = [s_{n-1}, s_{n-2}, ..., s_1, s_0]ᵀ`. Зміна стану за один такт описується лінійним матричним перетворенням над `GF(2)`:

```
S(t + 1) = M · S(t) ⊕ B · in(t)
```

де `M` — супровідна матриця Фробеніуса твірного многочлена `G(x)`, а `B = [0, 0, ..., 0, 1]ᵀ` — вектор введення вхідного біта `in(t)`.

Оскільки множення матриць є асоціативним, перехід через 8 тактів (обробка цілого байта) задається матрицею `M⁸`:

```
S(t + 8) = M⁸ · S(t) ⊕ ∑ (M^{7-i} · B · in(t + i))
```

Матриця `M⁸` та зсув на 8 тактів є повністю лінійними операціями. Це означає, що замість виконання восьми послідовних множень на матрицю `M` ми можемо один раз обчислити відгук регістра на всі 256 можливих комбінацій старшого байта.

### Декомпозиція побайтної обробки

Під час надходження чергового байта даних `D(x)` ступеня менше 8 поточний `n`-бітний стан регістра `C(x)` зсувається на 8 позицій вліво (множиться на `x⁸`), а новий байт додається у молодші розряди. У схемі MSB-first старший байт регістра `C_top(x)` (коефіцієнти при `xⁿ⁻¹ ... xⁿ⁻⁸`) витісняється зі зсувного регістра за межі розрядності `n`.

Позначимо поточний регістр як суму старшого байта та решти бітів:

```
C(x) = C_top(x) · xⁿ⁻⁸ ⊕ C_low(x)
```

де `deg(C_low(x)) < n - 8`. Новий стан регістра `C_next(x)` після введення вхідного байта `D(x)` дорівнює остачі від ділення зсунутого повідомлення:

```
C_next(x)
= rem((C(x) ⊕ D(x)·xⁿ⁻⁸) · x⁸, G(x))                               [зсув сумарного стану на 8 бітів вліво]
= rem((C_top(x)·xⁿ⁻⁸ ⊕ C_low(x) ⊕ D(x)·xⁿ⁻⁸) · x⁸, G(x))          [підстановка розкладу регістра C(x)]
= rem((C_top(x) ⊕ D(x))·xⁿ ⊕ C_low(x)·x⁸, G(x))                   [групування доданків при однакових степенях]
= rem((C_top(x) ⊕ D(x))·xⁿ, G(x)) ⊕ rem(C_low(x)·x⁸, G(x))        [застосування доведеної лінійності залишку]
= rem((C_top(x) ⊕ D(x))·xⁿ, G(x)) ⊕ (C_low(x) · x⁸)               [оскільки deg(C_low · x⁸) < n, остача збігається з аргументом]
```

Останній крок доводить принциповий алгоритмічний висновок: оновлення 32-бітного регістра складається з двох повністю незалежних операцій:

1. Звичайного бітового зсуву молодшої частини регістра вліво: `C_low(x) · x⁸` (у мовах програмування: `crc << 8`).
2. Додавання за модулем 2 заздалегідь обчисленого залишку для 8-бітного значення `I = C_top ⊕ D`: `rem(I · xⁿ, G(x))`.

Оскільки значення індексу `I` лежить у діапазоні від `0` до `255` (всього 256 можливих комбінацій одного байта), всі 256 значень многочлена `rem(I · xⁿ, G(x))` можна обчислити один раз і зберегти у таблиці пошуку `LUT[256]`.

### Рекурентна генерація таблиці залишків без операції ділення

Для побудови таблиці `LUT` не потрібно виконувати громіздке ділення «в стовпчик» для кожного з 256 чисел. Завдяки властивостям поля `GF(2)` значення `LUT[i]` для будь-якого байта `i` виводиться з побітного зсуву.

Нехай відомо значення залишку `rem(xⁱ, G(x))`. Тоді для наступного степеня `xⁱ⁺¹`:

```
rem(xⁱ⁺¹, G(x))
= rem(x · xⁱ, G(x))                                                 [винесення множника x]
= rem(x · rem(xⁱ, G(x)), G(x))                                      [властивість редукції залишку в кільці многочленів]
= (rem(xⁱ, G(x)) << 1) ⊕ (MSB ? G(x) : 0)                           [якщо старший біт дорівнює 1, віднімаємо константу полінома]
```

Для кожного з 256 елементів таблиці ми беремо байт `i` у старшому розряді `i << (n - 8)` і виконуємо 8 кроків рекурентного зсуву з умовним XOR на константу полінома `G(x)`.

У результаті отримуємо таблицю з 256 слів по `n` бітів, яка повністю замінює побітні цикли ділення на одну операцію індексації та один XOR. Це математично строго гарантує, що табличний розрахунок дає біт-у-біт ідентичний результат до побітного апаратного регістра LFSR.

### Алгебраїчні властивості незвідних поліномів

Вибір полінома `G(x)` визначає структуру фактор-кільця `GF(2)[x] / ⟨G(x)⟩`. Якщо `G(x)` є незвідним (irreducible) поліномом ступеня `n`, фактор-кільце є ізоморфним скінченному полю Галуа `GF(2ⁿ)`.

Якщо додатково `G(x)` є примітивним (primitive), змінна `x` є первісним елементом поля, а послідовність станів однорідного регістра LFSR без зовнішнього входу генерує псевдовипадкову M-послідовність максимального періоду:

```
T_{max} = 2ⁿ - 1
```

Для захисту даних часто використовують поліноми вигляду `G(x) = (x + 1) · P(x)`, де `P(x)` — примітивний поліном. Множник `(x + 1)` гарантує, що будь-який многочлен з непарною вагою Геммінга (непарною кількістю одиниць) не ділиться на `G(x)`, забезпечуючи 100% виявлення непарного числа бітових помилок.

### Узагальнення на багатобайтові стрибки

Цей самий принцип лінійної суперпозиції дозволяє будувати таблиці для стрибків довільної ширини `w` бітів (наприклад, `w = 16`, `32` або `64`). Якщо розбити вхідний вектор на кілька частин:

```
V(x) = V_k(x) · x^{8k} ⊕ V_{k-1}(x) · x^{8(k-1)} ⊕ ... ⊕ V_0(x)
```

то сумарна остача є побітовою сумою залишків від кожної зміщеної компоненти:

```
rem(V(x), G(x)) = rem(V_k(x)·x^{8k}, G(x)) ⊕ ... ⊕ rem(V_0(x), G(x))
```

Саме ця тотожність утворює математичну основу високопродуктивних паралельних алгоритмів Slice-by-4 та Slice-by-8, де замість послідовного зсуву регістр оновлюється за один спільний крок паралельного додавання залишків з кількох таблиць.
