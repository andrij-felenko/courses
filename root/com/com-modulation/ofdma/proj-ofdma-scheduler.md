# ⚙️ Двовимірний планувальник OFDMA: розподіл частотно-часових ресурсів

У сучасних бездротових мережах 4G LTE, 5G NR та Wi-Fi 6 планувальник фізичного рівня (MAC/PHY Scheduler) є центральним обчислювальним мозком базової станції або точки доступу. Його завдання — щомілісекунди розв'язувати задачу оптимізації: як розподілити дискретні кванти двовимірної часово-частотної сітки (ресурсні блоки PRB або ресурсні одиниці RU) між десятками активних абонентів, чиї черги пакетів, радіоумови та вимоги до затримок постійно змінюються.

На відміну від найпростіших схем почергового доступу Round-Robin, сучасний планувальник OFDMA спирається на алгоритм **пропорційної справедливості** (англ. *Proportional Fair*, PF). Він елегантно поєднує два взаємно суперечливі завдання: максимізує сумарну пропускну здатність сектору, використовуючи піки частотно-вибіркового каналу (виграш багатокористувацької різноманітності), і водночас гарантує справедливий розподіл ресурсів, щоб термінали на далекій межі радіопокриття не потрапляли в інформаційний голод.

## Теоретичний базис: функція корисності Келлі та 4 парадигми шедулінгу

Розподіл радіоресурсу в багатокористувацькому каналі спирається на теорію максимізації мережевої корисності (англ. *Network Utility Maximization*), сформульовану кембриджським математиком Френком Келлі (англ. *Frank Kelly*). Нехай `T_i` — довгострокова середня швидкість передачі даних `i`-го користувача. Загальна корисність системи визначається як сума індивідуальних функцій корисності `U(T_i)`:

```
max Σ_{i=1}^K U(T_i)
```

Залежно від вибору виду функції `U(T)` планувальник реалізує одну з чотирьох фундаментальних стратегій доступу:

1. **Максимальна пропускна здатність (Maximum Throughput / Max C/I, `U(T) = T`):**
   Планувальник завжди віддає кожен частотний блок тому абоненту, чий миттєвий сигнал `R_i,j` максимальний. Сумарна ємність стільника сягає абсолютного теоретичного максимуму, проте виникає повна дискримінація: 100% ресурсів захоплюють користувачі біля антени з прямим променем, тоді як абоненти на краю стільника (зі слабким SNR) повністю блокуються (`T_edge = 0`).

2. **Кругове обслуговування (Round-Robin / Fair Resource Allocation):**
   Частотні блоки діляться між усіма активними пристроями порівну в часі, незалежно від їхнього поточного стану каналу. Це забезпечує повну рівність виділеного ресурсу, але призводить до найнижчої сумарної пропускної здатності, оскільки станція марнує спектр, передаючи дані користувачам у моменти їхніх глибоких радіозавмирань.

3. **Макс-мінна справедливість (Max-Min Fairness, `U(T) = −(1/T)`):**
   Алгоритм максимізує швидкість найгіршого користувача (`max min_i T_i`), вирівнюючи пропускну здатність усіх абонентів до єдиного рівня. Це вимагає віддавати майже всі ресурсні блоки найслабшим терміналам, що катастрофічно знижує загальну ефективність сектору.

4. **Пропорційна справедливість (Proportional Fair, `U(T) = ln(T)`):**
   Функція корисності є логарифмічною. Похідна логарифма `U'(T) = 1/T` показує, що відносна цінність додаткового мегабіта для голодуючого користувача з `T = 1 Мбіт/с` є вдесятеро вищою, ніж для користувача з `T = 10 Мбіт/с`. 

Диференціювання логарифмічної корисності за часом породжує знамените правило шедулінгу Proportional Fair: для кожного ресурсного блоку `j` у слоті `t` обирається абонент `i^*`, який максимізує відношення:

```
i^*(j) = argmax_{i ∈ {1, ..., K}} ( R_i,j(t) / T_i(t) )
```

де `R_i,j(t)` — миттєва швидкість передачі, яку абонент `i` може отримати на блоці `j` у поточному слоті, а `T_i(t)` — його середня пропускна здатність, накопичена за попередній період спостереження.

Користувач дістає частотний блок не тоді, коли його сигнал сильніший за інших в абсолютному значенні, а тоді, коли його власний канал перебуває на **своєму особистому піку** відносно власного середнього рівня.

## Архітектура 2D-планувальника: від зворотного зв'язку до сітки PRB

У реальному цифровому сигнальному процесорі базової станції робота 2D-шедулера OFDMA розбита на 4 конвеєрні фази, що виконуються кожні 0.5 або 1.0 мс:

1. **Збір та деквантування звітів про канал (CSI / CQI Reporting):**
   Кожен активний термінал вимірює пілотні сигнали базової станції (CSI-RS у 5G, CRS у LTE) і надсилає назад індикатор якості каналу (Channel Quality Indicator, CQI від 0 до 15). Кожному значенню CQI відповідає спектральна ефективність, допустимий розмір кодового блоку та схема модуляції від QPSK 1/2 до 1024-QAM 5/6, розрахована на ймовірність помилки кадру BLER ≤ 10%.

2. **Бюджетування корисних ресурсних елементів (RE Budgeting):**
   Усередині кожного фізичного ресурсного блоку PRB (12 піднесних × 14 символів = 168 RE) частина елементів відводиться під службові потреби: опорні пілоти DMRS (від 12 до 24 RE), сигнали фазового стеження PTRS та канал керування PDCCH. Чистий простір під корисне навантаження даних зазвичай становить 130–144 RE на PRB.

3. **Двовимірний перебір матриці метрик `O(N_RB · K)`:**
   Для кожного ресурсного блоку `j ∈ {0, ..., N_RB−1}` планувальник обчислює метрику PF для всіх `K` кандидатів, черги яких містять дані, і знаходить максимум.

4. **Оновлення фільтра середньої швидкості (EWMA Tracking):**
   Після призначення всіх ресурсних блоків слота середня пропускна здатність кожного користувача оновлюється за допомогою експоненційного ковзного середнього:

```
T_i(t + 1) = (1 − 1/W) · T_i(t) + (1/W) · R_i_allocated(t)
```

де `W` — часове вікно згладжування (зазвичай `W = 100...500` слотів). Величина `W` визначає компроміс між латентністю справедливості та використанням багатокористувацької різноманітності: мале `W` швидше вирівнює швидкості, а велике `W` дозволяє довше вичікувати глибоких піків каналу.

## Повна програмна реалізація планувальника OFDMA

Нижче наведено самодостатню програму, яка моделює 4 абонентів у різних зонах радіопокриття, генерує для кожного частотно-вибірковий релеївський канал із доплерівським дрейфом фази, здійснює 2D-розподіл 25 ресурсних блоків (канал 20 МГц при Δf = 60 кГц або 5 МГц при Δf = 15 кГц) протягом 1000 слотів часу та підраховує підсумкову спектральну віддачу.

```c
#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include <string.h>

#define NUM_USERS 4
#define NUM_RBS 25
#define NUM_SLOTS 1000
#define EWMA_WINDOW 200.0f

typedef struct {
    int id;
    char name[32];
    float channel_snr_base;      /* Середній SNR користувача (дБ) */
    float fade_frequency_param;  /* Параметр частотного завмирання */
    float avg_throughput;        /* Накопичена середня швидкість (біт/слот) */
    unsigned long total_bits;    /* Сумарно передано бітів */
    int rbs_allocated_total;     /* Сумарно виділено RB */
} User;

/* Розрахунок досяжної швидкості на одному RB за формулою Шеннона з урахуванням MCS */
static float calculate_rb_capacity_bits(float snr_db) {
    float snr_linear = powf(10.0f, snr_db / 10.0f);
    /* 1 RB = 12 піднесних * 14 символів = 168 елементів.
       Корисні дані ~ 140 RE (з урахуванням RS пілотів) */
    float spectral_efficiency = log2f(1.0f + snr_linear);
    /* Обмеження реальною MCS: QPSK 1/2 (1 біт/RE) до 1024-QAM 5/6 (8.3 біт/RE) */
    if (spectral_efficiency < 0.5f) return 0.0f;
    if (spectral_efficiency > 8.0f) spectral_efficiency = 8.0f;
    return spectral_efficiency * 140.0f;
}

/* Генерація частотно-вибіркового завмирання Релея на кожному RB */
static float generate_instantaneous_snr(const User *u, int rb_idx, int slot_idx) {
    float freq_phase = (float)rb_idx * u->fade_frequency_param;
    float time_phase = (float)slot_idx * 0.05f + (float)u->id;
    float fast_fading = sinf(freq_phase + time_phase) * 6.0f + 
                        cosf(freq_phase * 2.1f + time_phase * 1.7f) * 4.0f;
    return u->channel_snr_base + fast_fading;
}

int main(void) {
    User users[NUM_USERS] = {
        {0, "UE-A (Центр стільника)", 24.0f, 0.45f, 100.0f, 0, 0},
        {1, "UE-B (Середня зона)",     18.0f, 0.75f, 100.0f, 0, 0},
        {2, "UE-C (Край стільника)",   10.0f, 0.30f, 100.0f, 0, 0},
        {3, "UE-D (IoT термінал)",      6.0f, 0.90f, 100.0f, 0, 0}
    };

    printf("=== Симуляція 2D OFDMA Proportional Fair шедулера ===\n");
    printf("Кількість користувачів: %d, Ресурсних блоків (RB): %d, Слотів: %d\n\n",
           NUM_USERS, NUM_RBS, NUM_SLOTS);

    for (int slot = 0; slot < NUM_SLOTS; ++slot) {
        float slot_bits_per_user[NUM_USERS] = {0.0f};
        int slot_rbs_per_user[NUM_USERS] = {0};

        /* Для кожного ресурсного блоку шукаємо найкращого користувача за PF метрикою */
        for (int rb = 0; rb < NUM_RBS; ++rb) {
            int best_user_idx = -1;
            float best_pf_metric = -1.0f;
            float best_rate_bits = 0.0f;

            for (int u = 0; u < NUM_USERS; ++u) {
                float snr = generate_instantaneous_snr(&users[u], rb, slot);
                float achievable_rate = calculate_rb_capacity_bits(snr);
                
                /* Метрика Proportional Fair: R_ij / T_i */
                float pf_metric = achievable_rate / users[u].avg_throughput;

                if (pf_metric > best_pf_metric) {
                    best_pf_metric = pf_metric;
                    best_user_idx = u;
                    best_rate_bits = achievable_rate;
                }
            }

            if (best_user_idx >= 0) {
                slot_bits_per_user[best_user_idx] += best_rate_bits;
                slot_rbs_per_user[best_user_idx]++;
            }
        }

        /* Оновлення середньої швидкості EWMA та сумарної статистики */
        for (int u = 0; u < NUM_USERS; ++u) {
            users[u].total_bits += (unsigned long)slot_bits_per_user[u];
            users[u].rbs_allocated_total += slot_rbs_per_user[u];

            users[u].avg_throughput = (1.0f - (1.0f / EWMA_WINDOW)) * users[u].avg_throughput +
                                      (1.0f / EWMA_WINDOW) * slot_bits_per_user[u];
        }
    }

    /* Підсумковий звіт */
    unsigned long total_system_bits = 0;
    printf("%-26s | %-12s | %-12s | %-12s\n", "Користувач", "Виділено RB", "Всього Мбіт", "Швидкість (Мбіт/с)");
    printf("-------------------------------------------------------------------------\n");

    for (int u = 0; u < NUM_USERS; ++u) {
        float mbits = (float)users[u].total_bits / 1000000.0f;
        float mbps = (float)users[u].total_bits / ((float)NUM_SLOTS * 0.001f * 1000000.0f);
        total_system_bits += users[u].total_bits;

        printf("%-26s | %10d RB | %10.2f Мб | %10.2f Мбіт/с\n",
               users[u].name, users[u].rbs_allocated_total, mbits, mbps);
    }

    float system_mbps = (float)total_system_bits / ((float)NUM_SLOTS * 0.001f * 1000000.0f);
    printf("-------------------------------------------------------------------------\n");
    printf("Сумарна пропускна здатність 20 МГц сектору OFDMA PF: %.2f Мбіт/с\n", system_mbps);

    return 0;
}
```

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <cmath>
#include <numeric>
#include <iomanip>
#include <algorithm>

struct User {
    int id;
    std::string name;
    float channel_snr_base;      // Середній SNR користувача (дБ)
    float fade_frequency_param;  // Параметр частотного завмирання
    float avg_throughput;        // Накопичена середня швидкість (біт/слот)
    uint64_t total_bits = 0;     // Сумарно передано бітів
    int rbs_allocated_total = 0; // Сумарно виділено RB
};

class OfdmaProportionalFairScheduler {
public:
    static constexpr int NUM_RBS = 25;
    static constexpr float EWMA_WINDOW = 200.0f;

    explicit OfdmaProportionalFairScheduler(std::vector<User> users)
        : users_(std::move(users)) {}

    void simulate(int num_slots) {
        for (int slot = 0; slot < num_slots; ++slot) {
            std::vector<float> slot_bits(users_.size(), 0.0f);
            std::vector<int> slot_rbs(users_.size(), 0);

            // Розподіл кожного ресурсного блоку
            for (int rb = 0; rb < NUM_RBS; ++rb) {
                int best_user = -1;
                float best_metric = -1.0f;
                float best_rate = 0.0f;

                for (size_t u = 0; u < users_.size(); ++u) {
                    float snr = get_instantaneous_snr(users_[u], rb, slot);
                    float achievable_rate = calculate_rb_capacity(snr);
                    float pf_metric = achievable_rate / users_[u].avg_throughput;

                    if (pf_metric > best_metric) {
                        best_metric = pf_metric;
                        best_user = static_cast<int>(u);
                        best_rate = achievable_rate;
                    }
                }

                if (best_user >= 0) {
                    slot_bits[best_user] += best_rate;
                    slot_rbs[best_user]++;
                }
            }

            // Оновлення ковзного середнього (EWMA)
            for (size_t u = 0; u < users_.size(); ++u) {
                users_[u].total_bits += static_cast<uint64_t>(slot_bits[u]);
                users_[u].rbs_allocated_total += slot_rbs[u];

                users_[u].avg_throughput = (1.0f - (1.0f / EWMA_WINDOW)) * users_[u].avg_throughput +
                                           (1.0f / EWMA_WINDOW) * slot_bits[u];
            }
        }
    }

    void print_report(int num_slots) const {
        std::cout << std::left << std::setw(28) << "Користувач" << " | "
                  << std::setw(12) << "Виділено RB" << " | "
                  << std::setw(12) << "Всього Мбіт" << " | "
                  << std::setw(16) << "Швидкість (Мбіт/с)" << "\n";
        std::cout << std::string(75, '-') << "\n";

        uint64_t total_system_bits = 0;
        for (const auto& u : users_) {
            float mbits = static_cast<float>(u.total_bits) / 1'000'000.0f;
            float mbps = static_cast<float>(u.total_bits) / (static_cast<float>(num_slots) * 0.001f * 1'000'000.0f);
            total_system_bits += u.total_bits;

            std::cout << std::left << std::setw(28) << u.name << " | "
                      << std::right << std::setw(9) << u.rbs_allocated_total << " RB | "
                      << std::fixed << std::setprecision(2)
                      << std::setw(9) << mbits << " Мб | "
                      << std::setw(13) << mbps << " Мбіт/с\n";
        }

        float system_mbps = static_cast<float>(total_system_bits) / (static_cast<float>(num_slots) * 0.001f * 1'000'000.0f);
        std::cout << std::string(75, '-') << "\n";
        std::cout << "Сумарна пропускна здатність 20 МГц сектору OFDMA PF: "
                  << std::fixed << std::setprecision(2) << system_mbps << " Мбіт/с\n";
    }

private:
    std::vector<User> users_;

    static float calculate_rb_capacity(float snr_db) {
        float snr_linear = std::pow(10.0f, snr_db / 10.0f);
        float spectral_efficiency = std::log2(1.0f + snr_linear);
        if (spectral_efficiency < 0.5f) return 0.0f;
        if (spectral_efficiency > 8.0f) spectral_efficiency = 8.0f;
        return spectral_efficiency * 140.0f;
    }

    static float get_instantaneous_snr(const User& u, int rb_idx, int slot_idx) {
        float freq_phase = static_cast<float>(rb_idx) * u.fade_frequency_param;
        float time_phase = static_cast<float>(slot_idx) * 0.05f + static_cast<float>(u.id);
        float fast_fading = std::sin(freq_phase + time_phase) * 6.0f + 
                            std::cos(freq_phase * 2.1f + time_phase * 1.7f) * 4.0f;
        return u.channel_snr_base + fast_fading;
    }
};

int main() {
    std::vector<User> initial_users = {
        {0, "UE-A (Центр стільника)", 24.0f, 0.45f, 100.0f},
        {1, "UE-B (Середня зона)",     18.0f, 0.75f, 100.0f},
        {2, "UE-C (Край стільника)",   10.0f, 0.30f, 100.0f},
        {3, "UE-D (IoT термінал)",      6.0f, 0.90f, 100.0f}
    };

    std::cout << "=== Симуляція 2D OFDMA Proportional Fair шедулера (C++) ===\n";
    constexpr int NUM_SLOTS = 1000;

    OfdmaProportionalFairScheduler scheduler(std::move(initial_users));
    scheduler.simulate(NUM_SLOTS);
    scheduler.print_report(NUM_SLOTS);

    return 0;
}
```

## Детальний розбір алгоритму та структури даних

У наведеній реалізації алгоритм симулятора відтворює всі ключові ланки конвеєра цифрового шедулера базової станції:

1. **Структура користувача (`User`):**
   Зберігає ідентифікатор, базовий рівень сигналу `channel_snr_base` (що моделює відстань до антени та повільне затінення логнормального типу), коефіцієнт просторової кореляції частотного завмирання `fade_frequency_param`, поточну оцінку середньої пропускної здатності `avg_throughput` та лічильники переданих бітів і виділених блоків.

2. **Моделювання частотно-селективного каналу (`generate_instantaneous_snr`):**
   Симулює багатопроменеву інтерференцію через суму гармонічних просторових компонент. Частотна фаза залежить від індексу блоку `rb_idx`, а часова фаза повільно еволюціонує зі зміною слота `slot_idx`, моделюючи доплерівський зсув від руху абонента.

3. **Мапування SNR у пропускну здатність (`calculate_rb_capacity`):**
   Переводить лінійне відношення сигнал/шум у спектральну ефективність за формулою Шеннона, обмежуючи її знизу порогом декодування QPSK 1/2 (0.5 біт/RE) та зверху граничною схемою 1024-QAM 5/6 (8.0 біт/RE). Отримана ефективність множиться на 140 корисних елементів RE в одному PRB.

4. **Двовимірний розподіл сітки:**
   Вкладений цикл перебирає всі `NUM_RBS` ресурсних блоків. Для кожного блоку обчислюється метрика `pf_metric = achievable_rate / users[u].avg_throughput`. Максимум метрики визначає переможця, що отримує даний частотний квант. Обчислювальна складність алгоритму становить `O(N_RB · K)` на кожен слот, що дозволяє виконувати його на апаратному FPGA/DSP за частки мікросекунди.

## Врахування вимог затримок та пріоритетів (QoS-Aware PF)

У реальних мережах пакети різних додатків мають принципово різні часові дедлайни: голосовий потік VoIP вимагає доставки протягом 20 мс, але має мізерний обсяг даних; навпаки, завантаження великого файлу (Best Effort) нечутливе до затримок, але потребує максимальної швидкості.

Для обслуговування змішаного трафіку метрику Proportional Fair модифікують введенням експоненційного штрафу за час очікування в черзі (алгоритм Exponential PF / Modified Largest Weighted Delay First, M-LWDF):

```
m_i,j(t) = a_i · W_i(t) · ( R_i,j(t) / T_i(t) )
```

де `W_i(t)` — час очікування найстарішого пакета на початку черги абонента `i` (Head-of-Line Delay), а `a_i` — коефіцієнт пріоритету класу обслуговування:

```
a_i = −ln(P_drop_i) / τ_max_i
```

де `τ_max_i` — гранично допустима затримка (наприклад, 20 мс для голосового пакета або 50 мс для потокового відео), а `P_drop_i` — допустима ймовірність відкидання пакета через прострочений дедлайн (наприклад, `10^{−3}`).

Якщо час очікування `W_i(t)` наближається до дедлайну `τ_max_i`, ваговий множник `a_i · W_i(t)` стрімко зростає, змушуючи планувальник негайно надати абоненту найближчий вільний блок RU26 навіть у тому разі, якщо його миттєвий сигнал не перебуває на піку. Це усуває джитер у реальному часі без втрати спектральної ефективності для решти фонового трафіку.

## Взаємодія планувальника з гібридним повторним запитом (HARQ)

У реальному протокольному стеку LTE/5G планувальник MAC-рівня не просто розподіляє нові дані (New Transmission), а управляє пулом паралельних процесів **гібридного автоматичного повторного запиту** (англ. *Hybrid Automatic Repeat reQuest*, HARQ).

Коли термінал не може декодувати транспортний блок, він надсилає базовій станції сигнал відхилення NACK. Базова станція генерує повторну передачу з інкрементним надлишковим кодуванням (Incremental Redundancy, IR):
1. **Пріоритет повторних передач:** повторні блоки HARQ Retransmissions отримують абсолютний пріоритет над первинними пакетами нових черг. Якщо повторна передача затримується, транспортний протокол TCP фіксує таймаут RTO і скидає розмір вікна перевантаження (congestion window), що катастрофічно обвалює швидкість застосунку.
2. **Асинхронний адаптивний HARQ у 5G NR:** на відміну від фіксованого синхронного таймінгу LTE, 5G дозволяє планувальнику переносити повторну передачу HARQ на інший частотний PRB і інший часовий слот, адаптуючись до зміни завмирань.

## Метрика справедливості Джейна (Jain's Fairness Index)

Для об'єктивної чисельної оцінки того, наскільки рівномірно планувальник розподіляє ресурс між користувачами, застосовується індекс справедливості Джейна:

```
J(T₁, T₂, ..., T_K) = ( Σ_{i=1}^K T_i )² / ( K · Σ_{i=1}^K T_i² )
```

де `T_i` — нормалізована пропускна здатність `i`-го користувача.

Властивості індексу Джейна:
- `J = 1.0` (100%): абсолютна рівність — усі користувачі отримують однакову швидкість (ідеальний Round-Robin або Max-Min Fairness);
- `J = 1/K`: максимальна дискримінація — один користувач захопив 100% спектра, решта `K - 1` отримують нуль (стратегія Max C/I);
- `J ≈ 0.80...0.90`: характерний робочий діапазон алгоритму Proportional Fair, який забезпечує збалансований компроміс між сумарною місткістю та рівноправністю.

## Звіт про стан буфера (Buffer Status Report, BSR) та черги WDRR

Перед тим як планувальник фізичного рівня виділить ресурсні блоки у висхідному каналі UL-OFDMA, базова станція повинна знати, скільки саме байтів накопичилося в чергах кожного абонента.

У стеку протоколів LTE/5G та Wi-Fi 6 цей зворотний зв'язок реалізується через **звіти про стан буфера** (англ. *Buffer Status Report*, BSR):
- **LTE/5G MAC BSR:** термінал квантує обсяг даних у 4 групах логічних каналів (Logical Channel Groups, LCG 0..3) за логарифмічною таблицею (від 0 байтів до понад 3 МБ) і надсилає BSR або у виділеному полі керування MAC subheader, або через короткий запит планування (Scheduling Request, SR) на каналі PUCCH;
- **Wi-Fi 6 BSRP:** точка доступу опитує станції кадром BSRP (Buffer Status Report Poll), у відповідь на який клієнти передають бітову карту черг TID (Traffic Identifier);
- **Дефіцитний циклічний шедулінг (Weighted Deficit Round-Robin, WDRR):** на рівні ядра Linux (підсистема `qdisc` та драйвер `mac80211`) перед передачею кадру в чергу апаратного передавача діє алгоритм WDRR. Він квантує вихідні пакети за класами пріоритету, гарантуючи, що жодна низькопріоритетна черга не заблокує виділення тригерних блоків RU26 для високопріоритетних пакетів управління мережею.

## Інтеграція планувальника ядра Linux з чергами FQ-CoDel

На вищих мережевих рівнях операційної системи Linux мережевий стек взаємодіє з драйвером OFDMA через підсистему дисциплін черг (Queueing Disciplines, `qdisc`). 

Для запобігання явищу роздування буферів (Bufferbloat), коли великий обсяг фонового завантаження забиває пам'ять і затримує чутливі до часу пакети, сучасні дистрибутиви застосовують алгоритм **Fair Queueing Controlled Delay (FQ-CoDel)** або **CAKE**:
1. **Хешування потоків за 5-tuple:** кожен мережевий потік (IP джерела, IP призначення, порти та протокол) потрапляє в окрему підчергу (Flow Queue);
2. **Дворівневе виділення квантів:** FQ-CoDel відстежує час перебування пакета в черзі (Sojourn Time). Якщо латентність черги перевищує 5 мс, алгоритм починає завчасне скидання пакетів (Early Drop / ECN) для сигналізації протоколу TCP про необхідність зменшити швидкість передачі;
3. **Формування агрегатів A-MPDU для OFDMA:** драйвер `mac80211` витягує кванти з черг FQ-CoDel, формує з них великі агреговані блоки A-MPDU і передає їх апаратному планувальнику чипсета, який мапує їх на виділені ресурсні блоки RU.

Завдяки цьому симбіозу черг FQ-CoDel на рівні сокетів та 2D-шедулера Proportional Fair на рівні радіочастотного PHY, бездротова мережа Wi-Fi 6 здатна одночасно підтримувати пікові швидкості гігабітного завантаження та ультранизький джитер у онлайн-іграх і відеоконференціях.

## Інженерні пастки реалізації OFDMA-планувальника

При перенесенні теоретичного алгоритму PF у драйвер реального чипсета виникають чотири критичні проблеми:

1. **Застарівання інформації про стан каналу (CSI Aging):**
   При русі автомобіля зі швидкістю 60 км/год на частоті 3.5 ГГц час когерентності каналу становить близько `T_c ≈ 9 / f_d ≈ 4.5 мс`. Якщо звіт про якість каналу CQI надійшов із запізненням у 5 мс, планувальник призначить блок на основі застарілого піку, який на момент передачі вже перетворився на глибоке завмирання. Це призводить до сплеску пакетних помилок BLER. Драйвер повинен фільтрувати CQI через предиктор Калмана або знижувати консервативність MCS.

2. **Накладні витрати сигналізації DCI (Signaling Overhead):**
   Квантування ресурсу на 100 окремих блоків вимагає повідомляти кожному абоненту, які саме блоки йому виділено. У LTE/5G для цього використовується канал керування PDCCH (Downlink Control Information, DCI). Якщо шедулер виділятиме блоки поодинці, бітова маска DCI роздується настільки, що «з'їсть» до 30% усієї пропускної здатності кадру. Тому стандарти групують сусідні PRB у неподільні групи — **Resource Block Groups (RBG)** розміром по 2, 4 або 8 блоків.

3. **Гранулярність звітів: Wideband CQI проти Subband CQI:**
   Передача точного значення SINR для кожного окремого PRB перевантажила б висхідний канал керування (PUCCH). Тому термінали передають комбінований звіт: один загальний Wideband CQI для всієї смуги плюс диференційні поправки (Subband Differential CQI ±2 дБ) лише для кількох найкращих субсмуг (M-Best Subbands).

4. **MAC Padding у зворотному каналі UL-OFDMA:**
   Якщо точка доступу Wi-Fi 6 виділяє однаковий часовий інтервал передачі (наприклад, 2 мс) для кількох клієнтів за кадром Trigger Frame, а одному з них треба відправити лише 100 байтів, решту виділеного часу передавач зобов'язаний заповнити порожніми байтами вирівнювання (MAC Padding). Неоптимальне групування абонентів нівелює виграш від паралелізму.

## Моніторинг та трасування OFDMA в ядрі Linux

У сучасних ядрах Linux робота бездротового планувальника Wi-Fi 6 (на базі драйверів `ath11k`, `ath12k` або `iwlwifi`) та підсистеми `mac80211` контролюється через інтерфейс подій ядра `ftrace` та утиліту `iw`:

```bash
# Перевірка підтримки OFDMA бездротовим інтерфейсом (HE capabilities)
iw phy phy0 info | grep -A 10 "HE Iftypes"

# Увімкнення трасування планувальника mac80211 через ftrace
echo 1 > /sys/kernel/debug/tracing/events/mac80211/mac80211_he_trigger_tx/enable
echo 1 > /sys/kernel/debug/tracing/events/mac80211/mac80211_he_ul_ofdma/enable

# Перегляд журналу розподілу ресурсних блоків RU у реальному часі
cat /sys/kernel/debug/tracing/trace_pipe
```

Для аналізу розподілу ресурсних блоків у реальних точках доступу під керуванням Linux/OpenWrt використовуються лічильники налагоджувальної файлової системи `debugfs`:

```bash
# Перевірка статистики виділених блоків RU (RU26, RU52, RU106, RU242)
cat /sys/kernel/debug/ath11k/qcn9074\ hw1.0_0000\:01\:00.0/mac0/he_stats

# Перевірка поточної таблиці активних асоціацій та призначених MCS
iw dev wlan0 station dump
```

Трасування дозволяє безпосередньо спостерігати призначені індекси RU, розрахункові значення MCS, частоту виникнення повторних передач та кількість байтів Padding для кожного активного з'єднання, виявляючи вузькі місця в налаштуваннях черг QoS.
