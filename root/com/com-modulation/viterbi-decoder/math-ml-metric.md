# 🧮 Метрика гілки з максимуму правдоподібності

Число, яке декодер вішає на кожне ребро ґратки, не беруть зі стелі — його змушує з'явитися одне-єдине питання: за якого переданого шляху прийняте найімовірніше? Виведімо це число до кінця — від імовірності до готової арифметики — і побачимо, чому на двійковому каналі воно стягується у відстань Геммінга, на гаусовому — у кореляцію, і чому це та сама формула у двох одежах.

## Максимум апостеріорної = максимум правдоподібності

Приймач хоче помилятися якнайрідше. Отримавши вектор **r**, він мусить назвати ту передану послідовність **v**, яка за цього **r** найімовірніша, — тобто максимізувати апостеріорну ймовірність P(**v** | **r**). За [формулою Баєса](root:math-probability/bayesian-estimation) вона розкладається:

```
P(v | r) = P(r | v) · P(v) / P(r)
```

Знаменник P(**r**) однаковий для всіх кандидатів — ми ж порівнюємо гіпотези за фіксованого прийнятого **r**, — тож на пошук максимуму він не впливає. Апріорна P(**v**) — імовірність, що саме цю послідовність надіслали; для звичайного потоку даних усі повідомлення однаково ймовірні, отже P(**v**) теж стала. Лишається чисте

```
argmax P(v | r)  =  argmax P(r | v)
   v                    v
```

Правило «обрати найправдоподібніший **v**» і є **максимум правдоподібності** (maximum likelihood). Тонкість, яку не можна проминути: рівність тримається лише за рівноймовірних кандидатів. Якби деякі послідовності були апріорі частіші, довелося б повернути множник P(**v**) — і оптимум зсунувся б. Для звичайного кодека це не так, тому декодер сміливо максимізує саму правдоподібність P(**r** | **v**).

## Чому ціна додається по ребрах

Максимізувати P(**r** | **v**) у лоб важко: це ймовірність цілого вектора. Її рятує одна фізична властивість каналу — **відсутність пам'яті**: кожен символ псується незалежно від сусідів. Тоді ймовірність прийняти весь **r** розпадається в добуток по символах:

```
P(r | v) = ∏ᵢ P(rᵢ | vᵢ)
```

Добуток незручний — доданки в ньому перемножуються, а не додаються, і максимум такого виразу шукати важко. Тому беремо логарифм. Він строго зростає, тож положення максимуму не зсуває, зате добуток перетворює на суму:

```
log P(r | v) = Σᵢ log P(rᵢ | vᵢ)
```

Ось стрижень усього. Логарифм правдоподібності **адитивний** уздовж послідовності. А кожне ребро ґратки [згорткового коду](root:com-modulation/convolutional-codes) несе свою жменьку символів **vᵢ** — отже, сума розпадається ще й **по ребрах**: кожному ребру можна приписати число, його внесок у сумарний логарифм. Перевернувши знак (щоб шукати мінімум, а не максимум), назвемо це число **метрикою гілки**:

```
γ(ребро) = − Σ    log P(rᵢ | vᵢ)
            i ∈ ребро
```

Метрика шляху — сума метрик його ребер; найправдоподібніший шлях має найменшу суму. Без адитивності жоден покроковий пошук був би неможливий: не-адитивну ціну не накопичиш ребро за ребром. Уся форма метрики тепер залежить лише від одного — від того, яке P(rᵢ | vᵢ) диктує канал. Розгляньмо два випадки, на яких стоїть уся практика.

## Двійковий канал: правдоподібність стягується у відстань Геммінга

На [двійковому симетричному каналі](root:math-information/binary-symmetric-channel) демодулятор уже зрізав кожну вибірку до біта й подекуди помилився — перевернув біт із імовірністю p < ½. Нехай кодове слово-кандидат розходиться з прийнятим у d позиціях із N. Кожна з d розбіжностей коштує множника p (там сталася помилка), кожен із N−d збігів — множника (1−p):

```
P(r | v) = pᵈ · (1−p)ᴺ⁻ᵈ
```

Логарифмуймо й згорнімо:

```
log P(r | v) = d·log p + (N−d)·log(1−p)
             = N·log(1−p) − d·[ log(1−p) − log p ]
             = N·log(1−p) − d·log((1−p)/p)
               └─ стала для всіх ─┘   └─ лише це залежить ─┘
                    кандидатів          від кандидата
```

Перший доданок N·log(1−p) однаковий для кожної гіпотези — на вибір не впливає. Усе вирішує другий. Множник log((1−p)/p): оскільки p < ½, дріб (1−p)/p більший за одиницю, а логарифм більшого за одиницю додатний. Отже,

```
log P(r | v) = стала − (додатне) · d       ⟹   максимум правдоподібності = мінімум d
```

Метрика гілки — це просто [відстань Геммінга](root:com-modulation/hamming-distance) між парою очікуваних виходів ребра й парою прийнятих бітів: скільки з них не збіглося. «Найближчий за Геммінгом» виявляється не довільним смаком, а прямим наслідком максимуму правдоподібності на двійковому каналі.

Тут ховається наслідок, вартий окремого рядка: конкретне значення p зникло. Аби воно було менше за ½, коефіцієнт додатний — і порядок кандидатів за метрикою той самий, хоч p = 0.1, хоч p = 0.4. Тому жорсткому декодерові не треба знати ймовірність помилки каналу: він порівнює самі d. А коефіцієнт log((1−p)/p) — це, до речі, і є вага одного неспівпадіння в одиницях [логарифма відношення правдоподібностей](root:math-information/log-likelihood-ratio): ціна, з якою одна помилка входить у суму.

## Гаусів канал: квадрат відстані, а тоді кореляція

Тепер демодулятор не зрізає рішення, а віддає декодерові саму аналогову вибірку. Передані символи — [двійкова фазова маніпуляція](root:com-modulation/fsk-psk): логічний 0 → sᵢ = +1, логічна 1 → sᵢ = −1. [Канал AWGN](root:math-information/awgn-channel) додає до кожного незалежний гаусів шум, rᵢ = sᵢ + шум, тож щільність прийняти rᵢ за переданого sᵢ — гаусіана:

```
P(rᵢ | sᵢ) = 1/√(2πσ²) · exp( −(rᵢ − sᵢ)² / 2σ² )
```

Логарифм правдоподібності всієї послідовності:

```
log P(r | v) = −(N/2)·log(2πσ²) − 1/(2σ²) · Σ (rᵢ − sᵢ)²
                └───── стала ─────┘   └ додатний множник ┘
```

Стала й додатний множник 1/2σ² положення максимуму не зсувають, тож максимум правдоподібності = **мінімум суми квадратів** Σ(rᵢ − sᵢ)². А це квадрат евклідової відстані між прийнятим вектором і символами кандидата: найправдоподібніший шлях геометрично найближчий до **r**. Розкриймо квадрат:

```
Σ (rᵢ − sᵢ)² = Σ rᵢ²  −  2·Σ rᵢsᵢ  +  Σ sᵢ²
               └стала┘              └ = N ┘
             та сама прийнята r     кожен (±1)² = 1
             для всіх кандидатів    для всіх кандидатів
```

Із трьох доданків два сталі: Σrᵢ² залежить лише від прийнятого (однакове для всіх гіпотез), а Σsᵢ² = N, бо кожен символ ±1 у квадраті дає 1. Лишається єдиний доданок, що відрізняє кандидатів, — доданок −2·Σrᵢsᵢ. Мінімізувати відстань — те саме, що **максимізувати кореляцію** Σrᵢsᵢ між прийнятою вибіркою й символами ребра.

За цим ховається чиста геометрія. Усі кодові кандидати ±1 лежать на сфері радіуса √N — у них однакова норма. А коли всі точки рівновіддалені від початку, найближча за евклідовою відстанню воднораз і найбільша за скалярним добутком: відстань і кореляція стають тим самим мірилом із протилежним знаком.

![Прийнята м'яка пара r = (+0.3, −0.9) як точка на площині r₀,r₁; чотири можливі мітки ребра — точки (±1,±1) у кутах, усі на пунктирному колі однакової норми √2; від r проведено відрізки-відстані до кожної мітки, найкоротший (до мітки 01 = (+1,−1)) виділено зеленим — це і є найближча мітка, вона ж дає найбільшу кореляцію](img/ml-geometry.svg)
*Мітки лежать на колі рівної норми, тож «найближча за відстанню» й «найбільша за кореляцією» — це та сама точка. Прийняте r кволо схилилося до +1 по першій осі й упевнено до −1 по другій, і найближчою виходить мітка 01 = (+1, −1).*

## Числовий приклад: обидва критерії — та сама мітка

Візьмімо одне ребро коду швидкості 1/2: воно несе два символи. Нехай демодулятор віддав м'яку пару r = (+0.3, −0.9) — перший символ кволо схилився до +1, другий упевнено до −1. Ребро може нести одну з чотирьох міток ±1; порахуймо для кожної кореляцію й квадрат відстані.

**Умова: прийнято r = (+0.3, −0.9); чотири можливі мітки ребра.**

```
мітка  символи s    кореляція  Σrᵢsᵢ                відстань²  Σ(rᵢ−sᵢ)²
 00   (+1, +1)    0.3·1  + (−0.9)·1   = −0.60   (0.3−1)² + (−0.9−1)² = 4.10
 01   (+1, −1)    0.3·1  + (−0.9)(−1) = +1.20   (0.3−1)² + (−0.9+1)² = 0.50   ←
 10   (−1, +1)    0.3(−1) + (−0.9)·1  = −1.20   (0.3+1)² + (−0.9−1)² = 5.30
 11   (−1, −1)    0.3(−1) + (−0.9)(−1)= +0.60   (0.3+1)² + (−0.9+1)² = 1.70
```

Максимум кореляції — мітка 01 (+1.20). Мінімум відстані — теж мітка 01 (0.50). Обидва критерії показали на ту саму мітку, і це не збіг. Перевірмо тотожність із розкриття квадрата: спільна стала C = Σrᵢ² + N = (0.3² + 0.9²) + 2 = 0.90 + 2 = 2.90, і кожен рядок стовпця відстаней зобов'язаний дорівнювати C − 2·(кореляція):

```
відстань² = C − 2·(кореляція) = 2.90 − 2·(кор)
   01:  2.90 − 2·(+1.20) = 0.50   ✓
   11:  2.90 − 2·(+0.60) = 1.70   ✓
   00:  2.90 − 2·(−0.60) = 4.10   ✓
   10:  2.90 − 2·(−1.20) = 5.30   ✓
```

Квадрат відстані — строго спадна лінійна функція кореляції. А спадна функція перевертає порядок, але не плутає його: найбільша кореляція неминуче дає найменшу відстань. Тому argmax Σrᵢsᵢ і argmin Σ(rᵢ−sᵢ)² завжди вказують на один і той самий кандидат — приклад лише унаочнив те, що тотожність гарантує наперед.

![Чотири мітки на площині «кореляція — квадрат відстані»: усі чотири точки (10, 00, 11, 01) лежать точно на одній спадній прямій d² = 2.90 − 2·кор; мітка 01 у правому нижньому кінці виділена зеленим з напрямними до осей — вона має найбільшу кореляцію +1.20 і воднораз найменшу відстань 0.50](img/metric-equiv.svg)
*Обидві м'які метрики — то одна спадна пряма. Рухаючись праворуч (більша кореляція), неминуче йдемо вниз (менша відстань), тож найбільша кореляція й найменша відстань — це один і той самий кінець прямої.*

Побіжно: жорсткий демодулятор тут узяв би самі знаки вибірок — (+, −) → біти (0, 1) → та сама мітка 01. Але м'яка метрика зберегла ще й запас: 0.50 проти найближчого суперника 1.70. Саме цей запас, підсумований уздовж шляху, і відрізняє шлях-переможець упевненіше, ніж голий підрахунок неспівпадінь.

## Один принцип, форму дає канал

Уся метрика гілки — то один вираз, −log P(rᵢ | vᵢ), проведений крізь конкретний канал до кінця:

```
argmax P(r | v)  =  argmin Σ ( −log P(rᵢ | vᵢ) )
   v                   v
        │
        ├─ двійковий канал (p < ½):   argmin Σ [rᵢ ≠ vᵢ]   = мінімум відстані Геммінга
        │
        └─ гаусів канал (±1):         argmin Σ (rᵢ − sᵢ)²   = максимум кореляції  Σ rᵢsᵢ
```

Мірило «найближчого» ніхто не обирає рукою — його однозначно диктує статистика каналу, а декодер лишається той самий: змінюється тільки число, яке блок метрик кладе на кожне ребро.
