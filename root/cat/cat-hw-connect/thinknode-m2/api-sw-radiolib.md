## Запуск радіомодуля в ефір

Щоб радіомодуль SX1262 міг приймати чи передавати сигнали, його потрібно перевести зі стану спокою в робочий режим, налаштувавши внутрішні регістри. Без правильної ініціалізації чип не знатиме, на якій частоті працювати і як обробляти дані. Бібліотека @@en|RadioLib@@ бере на себе низькорівневу роботу з SPI-шиною, надаючи зручний інтерфейс для старту.

Ініціалізація починається зі створення об'єкта модуля, якому передаються піни підключення: лінія вибору пристрою (NSS), лінія готовності (DIO1), скидання (NRST) та сигнал зайнятості (BUSY). За замовчуванням бібліотека спілкується з чипом через головну апаратну шину SPI мікроконтролера, але якщо їх кілька й радіомодуль підключено до іншої, у конструктор модуля додатковим параметром передають вказівник на потрібний екземпляр SPI-інтерфейсу, щоб команди йшли правильними лініями. Після цього викликається метод `begin()`, який встановлює базові параметри зв'язку, такі як частота і смуга пропускання, і перевіряє, чи чип фізично відповідає.

:::tabs
```cpp|arduino
#include <RadioLib.h>

// NSS, DIO1, NRST, BUSY
SX1262 radio = new Module(10, 2, 3, 9);

void setup() {
    // Ініціалізація з базовою частотою 868.0 МГц
    int state = radio.begin(868.0);
    if (state != RADIOLIB_ERR_NONE) {
        // Помилка ініціалізації
        while (true);
    }
}
```
:::

Якщо метод повертає `RADIOLIB_ERR_NONE`, модуль успішно налаштований і готовий до роботи в ефірі з типовими налаштуваннями LoRa. Якщо ж повернуто інший код, це найчастіше означає проблему з підключенням дротів або живленням.

## Параметри модуляції LoRa

Фізичні властивості радіоканалу визначають, як далеко і як швидко можна передавати дані. Щоб адаптувати зв'язок до поточних умов, ми змінюємо чотири головні параметри: частоту, фактор розширення, смугу пропускання та потужність передавача.

Частота (@@en|frequency@@) визначає робочий діапазон, наприклад 868 МГц. Змінити її можна методом `setFrequency()`. Фактор розширення (@@en|Spreading Factor@@, SF) впливає на чутливість і швидкість: що більший фактор (наприклад, 12 замість 7), то надійніший сигнал на великих відстанях, але тим довше він передається. Встановлюється через `setSpreadingFactor()`. 

Смуга пропускання (@@en|Bandwidth@@, BW) задає ширину спектра, який займає сигнал. Широка смуга (наприклад, 500 кГц) дає більшу швидкість, вузька (125 кГц) — кращу стійкість до завад. Налаштовується методом `setBandwidth()`. Потужність передавача впливає на силу сигналу, що випромінюється антеною. Її можна встановити в децибелах до мілівата (дБм) функцією `setOutputPower()`, зважаючи на апаратні обмеження модуля.

:::tabs
```cpp|arduino
// Налаштування параметрів для максимальної дальності
radio.setFrequency(868.1);
radio.setSpreadingFactor(12);
radio.setBandwidth(125.0);
radio.setOutputPower(22); // 22 дБм
```
:::

Змінюючи ці значення, можна балансувати між швидкістю передавання даних та дальністю зв'язку, підлаштовуючись під конкретну задачу.

Проте комбінувати ці налаштування довільно не вийде. Високий фактор розширення у поєднанні з вузькою смугою пропускання розтягують передавання пакета на секунди, через що приймач може втратити синхронізацію від найменшого дрейфу частоти. Тому для таких крайніх режимів радіомодуль вимагає вмикати логічну оптимізацію низьких швидкостей і застосовувати високостабільний опорний генератор (TCXO). Без цього чип не зможе розкодувати сигнал, RadioLib відхилить таку конфігурацію, а сам пристрій ризикує порушити законодавчі ліміти на безперервний час в ефірі.

## Приймання та передавання даних

Коли модуль налаштований, ми можемо надсилати пакети в ефір або слухати його. Передавання текстового рядка чи масиву байтів виконується методом `transmit()`. Ця функція блокує виконання програми, поки пакет повністю не вийде з антени. Щойно передавання завершено, метод повертає статус операції.

Для приймання даних використовується метод `receive()`. Він переводить модуль у режим слухання і чекає, поки з ефіру не надійде пакет, що відповідає поточним налаштуванням модуляції. Функція також блокуюча: вона зупиняє програму до отримання даних або до спрацювання таймауту. Отримані дані записуються у переданий рядок чи буфер.

:::tabs
```cpp|arduino
void loop() {
    // Відправляємо пакет
    String str = "Hello World";
    int state = radio.transmit(str);

    // Слухаємо ефір
    String response;
    state = radio.receive(response);
    if (state == RADIOLIB_ERR_NONE) {
        // Успішно отримали response
    }
}
```
:::

У повсякденних задачах такий двосторонній обмін дозволяє реалізувати опитування датчиків чи надсилання команд, хоч і зупиняє іншу роботу контролера під час очікування.

## Коди помилок і діагностика

Кожна функція взаємодії з радіомодулем повертає код стану, який показує, чи успішно пройшла операція. Бібліотека визначає нульовий код `RADIOLIB_ERR_NONE` як ознаку успіху. Усі від'ємні значення є помилками, і без їх перевірки неможливо побудувати надійний зв'язок.

Найпопулярніші помилки виникають під час очікування або через фізичні негаразди. Код `RADIOLIB_ERR_RX_TIMEOUT` означає, що за відведений час жоден пакет не прийшов, що є нормальною ситуацією при слуханні порожнього ефіру. Помилка `RADIOLIB_ERR_CRC_MISMATCH` вказує на те, що пакет отримано, але дані пошкодилися під час перельоту через завади. Якщо ж функції ініціалізації повертають `RADIOLIB_ERR_CHIP_NOT_FOUND`, мікроконтролер не бачить модуля на шині SPI.

Аналіз цих кодів дає змогу програмі автоматично повторити передавання, повідомити користувача про апаратну несправність чи проігнорувати пошкоджений пакет.
