<preknowlist>
- [Радіомодуль nRF24](root:cat-hw-connect/nrf24-radio) — як працює трансивер і навіщо йому лінії CE та CSN, щоб розуміти призначення макросів керування
</preknowlist>

## Замість апаратного хаосу

Без програмного прошарку розробнику доводиться вручну прописувати номери пінів та процедури ініціалізації для кожного модуля на платі. Коли виводи для SPI або ліній керування вказані прямо в коді як магічні числа, будь-яка зміна ревізії обладнання вимагає переписування десятків місць. Це призводить до помилок та апаратного хаосу, де логіка застосунку змішана з низькорівневим керуванням. 

Щоб уникнути цього, плата ThinkNode M2 надає пакет підтримки платформи (@@en|Board Support Package, BSP@@). Це програмний інтерфейс, який стандартизує звернення до периферії. Він ховає під собою фізичні підключення і надає готові функції для роботи з модулями на платі. Під капотом BSP зіставляє абстрактні імена, як-от `M2_RADIO_CSN`, із реальними виводами поточної версії плати, тому при зміні заліза достатньо підключити інший заголовний файл. Завдяки цьому код застосунку стає портативним і захищеним від змін у розводці.

## Макроси виводів плати

Фізичні контакти плати відображені у програмні імена для шин SPI, I2C та ліній керування радіо. Замість того, щоб запам'ятовувати, до якого виводу підключений сигнал `CSN` чи лінія даних, розробник використовує визначені макроси: `THINKNODE_PIN_SPI_MOSI`, `THINKNODE_PIN_SPI_MISO` і `THINKNODE_PIN_SPI_SCK` формують шину SPI, `THINKNODE_PIN_I2C_SDA` та `THINKNODE_PIN_I2C_SCL` відповідають за підключення I2C-датчиків, а `THINKNODE_PIN_RADIO_CE` й `THINKNODE_PIN_RADIO_CSN` безпосередньо керують трансивером. Такий підхід відв'язує код від конкретної розводки: якщо в наступній ревізії плати контакти переїдуть на інші виводи мікроконтролера, значення макросів оновляться в самому BSP, а користувацька логіка працюватиме без жодних змін.

Використання абстрактних імен виводів вберігає від конфліктів при підключенні датчиків та іншої зовнішньої периферії. Якщо ви підключаєте [радіомодуль nRF24](root:cat-hw-connect/nrf24-radio), вам достатньо передати у драйвер ці макроси. Інтерфейс гарантує, що визначені імена завжди відповідають правильним контактам поточної версії плати, незалежно від середовища розробки.

## Ініціалізація радіомодуля

Щоб підготувати радіомодуль до обміну даними, достатньо двох-трьох рядків коду. Інтерфейс надає готові функції для вмикання живлення та базового налаштування трансивера. Виклик функції ініціалізації приховує складну послідовність налаштування регістрів.

![Діаграма показує, як виклик функції `thinknode_radio_init` транслюється у послідовність команд по шині SPI для конфігурації регістрів радіомодуля.](img/bsp-radio-init.svg)
*Діаграма послідовності: як виклик функції ініціалізації перетворюється на серію звернень до регістрів радіомодуля через шину SPI.*

Функція ініціалізації самостійно підіймає шину SPI з потрібною частотою, смикає лінії вибору кристала та записує базові параметри каналу. Це дозволяє зосередитись на логіці передавання, замість того, щоб вивчати документацію на регістри трансивера.

За замовчуванням трансивер отримує базовий частотний канал, максимальну потужність та швидкість 1 Мбіт/с — це зроблено для того, щоб дві щойно ввімкнені плати гарантовано побачили одна одну. Якщо ефір на цій частоті зашумлений або для більшої дальності потрібно зменшити швидкість, ці налаштування змінюють: розробник заповнює структуру конфігурації власними значеннями каналу, адреси й швидкості та передає її у розширену функцію ініціалізації.

:::tabs
```c|esp-idf
#include "thinknode_bsp.h"

void app_main(void) {
    thinknode_bsp_init();
    
    // Ініціалізація радіомодуля з параметрами за замовчуванням
    if (thinknode_radio_init() == THINKNODE_OK) {
        // Трансивер готовий до роботи
    }
}
```
```cpp|arduino
#include <ThinkNodeBSP.h>

void setup() {
    ThinkNode.begin();
    
    // Ініціалізація радіомодуля з параметрами за замовчуванням
    if (ThinkNode.radio.begin()) {
        // Трансивер готовий до роботи
    }
}
```
:::

## Підключення до Wi-Fi

Інтерфейс плати значно спрощує інтеграцію з бездротовою мережею. Замість того, щоб самостійно розгортати обробники подій мережевого стека, ви викликаєте одну функцію, яка встановлює облікові дані та запускає процес підключення.

Функції BSP беруть на себе керування станами Wi-Fi модуля, приховуючи внутрішні асинхронні процеси аутентифікації. Вони дозволяють надійно підключати плату до мережі, просто вказавши ім'я мережі та пароль через виклик `bsp_wifi_connect("NetworkName", "Password")`. Ця функція не блокує систему, а лише передає облікові дані та запускає фоновий автомат станів. Інтерфейс також надає функції для опитування стану з'єднання, як-от `bsp_wifi_is_connected()`, щоб застосунок міг дізнатися, коли мережа доступна або якщо підключення розірвано. Такий неблокувальний механізм обходиться потребою регулярно перевіряти статус у головному циклі програми, але гарантує, що втрата зв'язку чи тривале очікування на відгук від маршрутизатора не заморозять інші задачі плати.

## Статуси та обробка помилок

Інтерфейс сигналізує про апаратні проблеми через коди повернення та прапорці статусу. Наприклад, якщо трансивер не відповідає по шині SPI або ініціалізація Wi-Fi завершилася тайм-аутом, функція поверне відповідний код помилки, а не зависне в нескінченному циклі.

Значення основних кодів повернення, таких як `THINKNODE_ERR_TIMEOUT` або `THINKNODE_ERR_NO_RESPONSE`, дозволяють писати код, що коректно реагує на збої обладнання: відірваний дріт шини SPI, відсутність живлення трансивера або його зависання. Якщо ігнорувати статуси, мікроконтролер може нескінченно чекати на апаратне переривання, якого ніколи не буде, або відправляти дані в нікуди, вважаючи операцію успішною. Перевірка цих кодів при виклику функцій ініціалізації є критичною, оскільки вона дає змогу застосунку повідомити користувача про несправність або спробувати апаратно перезапустити модуль замість тихого падіння. Наприклад, отримавши помилку відсутності відповіді, програма може смикнути лінію скидання і спробувати знову:

:::tabs
```c|esp-idf
thinknode_err_t err = thinknode_radio_init();
if (err == THINKNODE_ERR_NO_RESPONSE) {
    ESP_LOGE("RADIO", "Трансивер не відповідає по SPI.");
    thinknode_radio_hw_reset();
    /* Повторна спроба або перехід у безпечний режим */
} else if (err == THINKNODE_ERR_TIMEOUT) {
    ESP_LOGE("RADIO", "Тайм-аут ініціалізації.");
}
```
```cpp|arduino
thinknode_err_t err = thinknode_radio_init();
if (err == THINKNODE_ERR_NO_RESPONSE) {
    Serial.println("Помилка: трансивер не відповідає по SPI.");
    thinknode_radio_hw_reset();
    // Повторна спроба або перехід у безпечний режим
} else if (err == THINKNODE_ERR_TIMEOUT) {
    Serial.println("Помилка: тайм-аут ініціалізації.");
}
```
:::
