# ⚙️ Термометр на LCD 1602: температура й час без блимання

<preknowlist>
- [Керуємо LCD 1602 із коду](topic:cat-hw-actuators/lcd-1602/api-liquidcrystal.md) — конструктор `LiquidCrystal`, `begin`, `setCursor`, `print`, `createChar`/`write`: усі виклики, з яких зібрано цей прилад.
- [`millis()`](topic:sf-devices/millis-micros) — лічильник мілісекунд від старту; ним роблять неблокувальні паузи, не зупиняючи мікроконтролер.
- [ASCII і UTF-8](topic:sf-data/ascii-utf8) — літера в пам'яті це число-код; число `23.5` теж спершу збирають у текст, а тоді показують.
</preknowlist>

Зберімо з викликів `LiquidCrystal` закінчений прилад — маленький термометр, що показує температуру й час роботи та оновлюється, не блимаючи й не блокуючи мікроконтролер. Механіку кожного виклику — конструктор, `begin`, `createChar`, `setCursor` — розібрано в [API-довіднику «Керуємо LCD 1602 із коду»](topic:cat-hw-actuators/lcd-1602/api-liquidcrystal.md); тут ми лише складаємо з них робочий приклад.

## Ціль: «Temp: 23.5°C» і час, що йде щосекунди

Прилад міряє температуру й має показувати на 1602A рядок на кшталт:

```
Temp: 23.5°C
Uptime: 01:24
```

Начебто дрібниця — два рядки тексту. Але вже тут сидять усі типові виклики символьного дисплея. Число `23.5` — це не рядок у пам'яті, його треба зібрати з float у текст. Знак `°` (градус) заводська таблиця символів **не містить** — його доведеться намалювати самому в пам'яті дисплея (CGRAM). Час `01:24` оновлюється щосекунди, а отже, треба переписувати лише його, не блимаючи всім екраном. І все це — не заблокувавши мікроконтролер паузами на секунди.

## Збираємо прилад

**Ініціалізація й власний символ.** Сталу «шапку» — незмінні написи `Temp:` і `Uptime:` — малюємо **один раз** у `setup`, а значок градуса записуємо у комірку CGRAM №0 (без нього `°` просто нема звідки взяти).

```cpp
#include <LiquidCrystal.h>

LiquidCrystal lcd(8, 9, 4, 5, 6, 7);   // rs, e, d4, d5, d6, d7

// Значок градуса у комірку CGRAM №0
byte degree[8] = {
    0b01100, 0b10010, 0b10010, 0b01100,
    0b00000, 0b00000, 0b00000, 0b00000
};

void setup() {
    lcd.begin(16, 2);
    lcd.createChar(0, degree);      // записати «°» — обов'язково після begin()

    // Сталу «шапку» малюємо ОДИН раз; далі оновлюємо лише змінні поля
    lcd.setCursor(0, 0);
    lcd.print("Temp:      ");        // "Temp:" + місце під число
    lcd.setCursor(0, 1);
    lcd.print("Uptime: 00:00");
}
```

**Оновлення числа без блимання.** Ключ — не чистити екран, а перезаписувати лише клітинки числа, доповнюючи пробілами, щоб затерти хвіст попереднього значення (з `12.5` на `9.0` треба стерти зайву цифру).

```cpp
// Показати температуру в полі, що починається з (col=6, row=0)
void showTemp(float t) {
    lcd.setCursor(6, 0);
    lcd.print(t, 1);             // один знак після коми: "23.5"
    lcd.write(byte(0));          // символ градуса з комірки №0
    lcd.print("C ");             // "C" і пробіл-затирач хвоста старого числа
}

// Показати час роботи як MM:SS у полі з (col=8, row=1)
void showUptime(uint32_t seconds) {
    uint16_t mm = seconds / 60;
    uint8_t  ss = seconds % 60;
    lcd.setCursor(8, 1);
    if (mm < 10) lcd.print('0');
    lcd.print(mm);
    lcd.print(':');
    if (ss < 10) lcd.print('0');
    lcd.print(ss);
}
```

**Головний цикл — без `delay`, щоб не блокувати прилад.** Замість того щоб «спати» секунду (і на цей час осліпнути до всього іншого), звіряємося з годинником [`millis()`](topic:sf-devices/millis-micros) і оновлюємо екран, коли настав час. Дисплей повільний до людського ока — його немає сенсу переписувати частіше, ніж кілька разів на секунду.

```cpp
uint32_t lastTick = 0;
uint32_t uptimeSec = 0;

void loop() {
    uint32_t now = millis();
    if (now - lastTick >= 1000) {    // раз на секунду
        lastTick += 1000;
        uptimeSec++;

        float t = readTemperature();  // ваш давач: повертає °C як float
        showTemp(t);
        showUptime(uptimeSec);
    }

    // ...тут решта роботи приладу крутиться вільно, дисплей нікого не блокує...
}
```

Зверніть увагу на три рішення, що відрізняють робочий код від наївного «hello world». Сталу частину напису (`Temp:`, `Uptime:`) намальовано **один раз** у `setup` — її щоразу перемальовувати марно. Змінні поля оновлюються **точковим** `setCursor` + `print` **без** `clear()`, тому екран не блимає. І весь цикл **неблокувальний** — через `millis()`, а не `delay(1000)`, тож мікроконтролер устигає робити ще сто справ між оновленнями. Це і є різниця між навчальним прикладом і живим приладом.
