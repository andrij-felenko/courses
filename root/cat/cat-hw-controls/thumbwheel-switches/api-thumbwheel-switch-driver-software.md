## Призначення та архітектура драйвера

Безперервне зчитування набраних значень із декадних барабанних перемикачів у мікроконтролерних системах вимагає чіткого розмежування низькорівневого тактування шини та високорівневої математичної обробки двійково-десяткового коду. Спроба реалізувати опитування через прості затримки заблокує виконання основної програми мікроконтролера, а механічний брязкіт контактів або невалідні перехідні кодові комбінації під час прокручування барабана спричинять зчитування помилкових уставок.

Для вирішення цих задач програмний драйвер будують за трирівневою модульною архітектурою `@@en|layered architecture@@`. Перший рівень — апаратних абстракцій `@@en|Hardware Abstraction Layer@@` (`@@en|HAL@@`) — відповідає за низькорівневе тактування сигнальних ліній вводу-виводу або роботу з послідовним інтерфейсом зсувного регістра. Другий рівень — фільтрації та контролю станів `@@en|Debounce & Validation Layer@@` — виконує неблокуюче придушення брязкоту контактів і перевірку правильності кожної чотирибітової BCD-тетради. Третій рівень — прикладний `@@en|Application API@@` — надає розробнику зручні функції отримання готового підсумкового числа та прапорців стану. Подібно до того, як зчитуються статичні [DIP-перемикачі та джамперні блоки конфігурації](root:cat-hw-controls/dip-switches-and-configuration-blocks), драйвер барабанних перемикачів гарантує повну ізоляцію прикладної логіки від апаратних особливостей розводки.

![Блок-схема архітектури програмного драйвера BCD-перемикачів із виділенням рівнів HAL, фільтрації та API](img/thumbwheel-driver-software-architecture.svg)
*Двоуровнева архітектура драйвера: від читання зсувного регістра через HAL до цифрового фільтра та високорівневого API.*

Основними структурами даних драйвера є конфігураційна структура `thumbwheel_config_t`, яка описує апаратні ресурси, та дескриптор стану `thumbwheel_t` (від англ. @@en|state descriptor@@), що зберігає поточні значення, таймери та прапорці помилок. Дескриптор `thumbwheel_t` консолідує в собі внутрішній BCD-буфер `bcd_digits[]` для збереження сирих 4-бітових тетрад кожного декадного розряду, обчислене підсумкове цілочисельне значення `uint32_t raw_value`, а також таймер останньої зміни стану `last_change_time` для неблокуючої обробки інтервалів деонізації та брязкоту контактів. Окреме поле прапорців `status_flags` фіксує бітові маски помилок, включаючи прапор інвалідації тетради при виявленні невалідних псевдодекад (значення понад 9) та прапор перехідного стану (від англ. @@en|transient state flag@@) для ігнорування проміжних некоректних комбінацій під час фізичного прокручування барабана. Маска `status_flags` будується на окремих розрядних бітах: біт `THUMBWHEEL_FLAG_TRANSIENT` `(1U << 0)` виставляється пристроєм у момент механічного розмикання щіток між клацаннями ротора, вимагаючи повторного стробування до виходу на стійке значення, тоді як біти `THUMBWHEEL_ERR_INVALID_BCD` `(1U << 1)` та `THUMBWHEEL_ERR_PARITY` `(1U << 2)` позначають апаратну несправність дорожок плати кодування чи зсувного регістра, коли зчитаний 4-бітовий код перевищує число 9 або порушує парність. Використання атомарної бітової маски дозволяє прикладному коду перевіряти коректність даних одним логічним виразом `status_flags == 0` без покрокового обходу кожного розряду. Базове оголошення дескриптора мовою C має такий вигляд:

```c
typedef struct {
    uint8_t  bcd_digits[8];      // Внутрішній буфер 4-бітових BCD-тетрад розрядів
    uint32_t raw_value;          // Декодоване цілочисельне значення уставки
    uint32_t last_change_time;   // Таймер останньої зміни для фільтрації брязкоту (мс)
    uint32_t status_flags;       // Бітові прапорці помилок та перехідних станів
} thumbwheel_t;
```

Загальний байтовий обсяг пам'яті SRAM, необхідний для збереження одного примірника дескриптора `thumbwheel_t`, становить `N_bytes = 4 + 4 + 4 + 8 = 20 байт` (з урахуванням 8-байтового статичного BCD-буфера `bcd_digits[8]`, 32-бітного значення уставки `raw_value`, 32-бітного таймера `last_change_time` та 32-бітної маски `status_flags`), що робить його вкрай компактним для мікроконтролерів із обмеженими ресурсами пам'яті.

## Ініціалізація та конфігурація апаратури

Перед початком опитування барабанних перемикачів необхідно виконати ініціалізацію використаних виводів мікроконтролера та налаштувати параметри цифрового фільтра. Функції ініціалізації конфігурують напрямок ліній GPIO, встановлюють початкові логічні рівні на виводах тактування `CP` та завантаження `PL` зсувного регістра 74HC165, а також перевіряють інваріанти налаштувань.

У мові C конфігурування здійснюється передачею вказівника на структуру `thumbwheel_config_t` у функцію `thumbwheel_init()`:

У мові C++ ініціалізація реалізується через об'єктно-орієнтований клас `ThumbwheelDriver`:

```cpp
class ThumbwheelDriver {
public:
    ThumbwheelDriver(uint8_t pin_pl, uint8_t pin_clk, uint8_t pin_data, uint8_t num_decades, uint32_t debounce_ms = 10);
    bool begin();
    
private:
    uint8_t _pin_pl, _pin_clk, _pin_data, _num_decades;
    uint32_t _debounce_ms;
};
```

Під час виконання `thumbwheel_init()` або `begin()` драйвер перевіряє, щоб кількість декад `num_decades` не перевищувала максимально допустимого розміру буфера (зазвичай 8 розрядів для 32-бітового цілого числа), після чого переводить лінію `PL` у високий стан `1`, а лінію `CLK` у низький стан `0`. Одночасно процедура ініціалізації виконує верифікацію апаратних пінів GPIO на відсутність конфліктів призначення, перевіряючи, що номери ліній `pin_pl`, `pin_clk` та `pin_data` є унікальними і не дублюють один одного в конфігурації. У разі виявлення однакових або некоректних номерів пінів викликом повертається код помилки `THUMBWHEEL_ERR_INVALID_CONFIG`, що блокує подальше тактування апаратури. Також драйвер заздалегідь розраховує двійкові маски бітових зсувів та граничних значень для кожного розряду, формуючи бітові маски валідації BCD-тетрад `mask = 0x0F << (4 * i)` та маску активних бітів підсумкового реєстра, що прискорює послідовну фільтрацію в циклі опитування та унеможливлює апаратні накладання при випадковому перехресному призначенні ліній вводу-виводу.

Для гарантування завадостійкого фіксування даних на високих частотах мікроконтролера ініціалізація додатково обраховує мінімально необхідний інтервал часової затримки `t_delay_pl` між наростаючим фронтом лінії завантаження `PL` та першим тактовим фронтом `CLK`. Відповідно до специфікацій зсувного регістра 74HC165, час підготовки даних відносно такту (англ. @@en|setup time@@) становить `t_su = 20 нс`. У високопродуктивних мікроконтролерах із тактовою частотою ядра `f_CPU = 168 МГц` період одного процесорного такту становить всього `t_CYC = 1 ÷ f_CPU ≈ 5.95 нс`. Якщо програмно змінити рівень `PL` на `1` і в наступній інструкції одразу подати фронт `CLK`, часовий інтервал виявиться меншим за `20 нс`, що спричинить збій вичитання першого біта. Необхідна кількість пустих інструкцій затримки `N_nop` обчислюється виразом:

        N_nop = ⌈ t_su · f_CPU ⌉

**Розрахунок кількості інструкцій N_nop для t_su = 20 нс (20 · 10⁻⁹ с) при частоті ядра f_CPU = 168 МГц (168 · 10⁶ Гц):**

        N_nop = ⌈ (20 · 10⁻⁹) · (168 · 10⁶) ⌉
        = ⌈ 3.36 ⌉                                            [округлення до найближчого більшого цілого]
        = 4                                                   [кількість пустих інструкцій NOP]

Нарешті, на основі `t_high_min = t_low_min = 20 нс` та доданої затримки `N_nop` функція обраховує підсумкову граничну частоту тактування зсувного регістра `f_clk_max = 1 ÷ (t_high_min + t_low_min + t_delay_pl)`, що запобігає пропускам бітів у швидких обчислювальних ядрах.

Для безпосереднього зчитування накопичених паралельних даних зсувного регістра 74HC165 розроблено низкорівневу HAL-процедуру `thumbwheel_read_raw_bits()`. Спочатку функція формує коротке від'ємне стробування на лінії завантаження `PL` (від англійського @@en|Parallel Load@@), переводячи її в рівень `0` на час не менше `20 нс` для фіксації поточного стану BCD-контактів перемикачів у внутрішніх тригерах регістра, після чого повертає `PL` у високий стан `1`. Далі у циклі зчитування драйвер послідовно опитує лінію даних `pin_data` та формує строби тактування на лінії `CLK`:

## Функції опитування та обробка помилок

Опитування барабанних перемикачів здійснюється регулярним викликом неблокуючої функції оновлення `thumbwheel_update()` (або методу `update()` у C++) у фоновому циклі програми чи за стробом системного таймера. Функція вимірює інтервал часу з моменту останньої зміни коду: якщо набрана двійково-десяткова комбінація лишається незмінною протягом часу `debounce_ms`, драйвер підтверджує новий стан уставки та оновлює збережене цілочисельне значення, яке потім зчитується функціями `thumbwheel_get_value()` або `getValue()`. Для забезпечення завадостійкості без затримок виконання прикладний код регулярно викликає оновлення у головному циклі прошивки, перевіряючи валідність зчитаних даних і факт зміни уставки перед її застосуванням в автоматиці:

*Граф станів драйвера: від початкового опитування до підтвердження стійкої BCD-комбінації або виявлення помилок.*

При зчитуванні кожної 4-бітової тетради драйвер виконує побітову операцію виділення тетради `digit_k = (raw_data >> (k * 4)) & 0x0F` для кожного `k`-го розряду та перевіряє умову валідності BCD-кодування `M_valid = ¬(b₃ ∧ (b₂ ∨ b₁))`. Якщо значення тетради перебуває у діапазоні від `10` до `15` (`0x0A`–`0x0F`), це свідчить про перебування барабана у момент прокручування у перехідному стані `@@en|transient state@@` між замикачами контактів. У такому разі драйвер фіксує статус `THUMBWHEEL_ERR_TRANSIENT` і зберігає попереднє підтверджене значення уставки. Для обробки множинних помилок BCD під час одночасного зчитування кількох розрядів драйвер перед початком циклу скидає маску `status_flags = 0` і при виявленні невалідної псевдодекади в `k`-му розряді акумулює бітовий збій операцією `status_flags |= (1 << k)`. Алгоритм аналізу маски збоїв на прикладному рівні виконує побітову перевірку `status_flags & (1 << k)` для кожного розряду від `0` до `N-1`: якщо маска розряду містить `1`, драйвер локально блокує оновлення лише зіпсованої тетради у буфері `bcd_digits[k]`, зберігаючи її попереднє підтверджене значення, тоді як валідні тетради з `status_flags & (1 << k) == 0` успішно оновлюються. Це дозволяє пристрою продовжувати неблокуючу роботу та коректно зчитувати стабільні розряди навіть під час одночасного прокручування сусідніх барабанів оператором.

Для отримання декодованого числового значення використовують функції `thumbwheel_get_value()` (в C) або `getValue()` (в C++):

:::tabs
```c

uint32_t thumbwheel_get_value(const thumbwheel_t *dev);
thumbwheel_err_t thumbwheel_get_status(const thumbwheel_t *dev);
```


Декодування підсумкового числа виконується через поліноміальне згортання розрядів @@en|polynomial accumulation@@: розпаковані тетради перемножуються на відповідні вагові коефіцієнти ступенів десятки та підсумовуються у підсумкове ціле значення V = ∑ (Dₖ × 10ᵏ) для k від 0 до N - 1, де Dₖ — значення k-ї BCD-декади (від 0 до 9), а 10ᵏ — її десяткова вага.

**Обчислення на прикладі:** для 4-декадного перемикача з набраним значенням 4729, де старша декада тисяч D₃ = 4, сотень D₂ = 7, десятків D₁ = 2 та одиниць D₀ = 9, покроковий розрахунок має вигляд:

```
V = D₃ × 10³ + D₂ × 10² + D₁ × 10¹ + D₀ × 10⁰    [поліноміальне розкладання за базисом 10]
  = 4 × 1000 + 7 × 100 + 2 × 10 + 9 × 1         [підстановка вагових коефіцієнтів та значення тетрад]
  = 4000 + 700 + 20 + 9                         [обчислення проміжних розрядних добутків]
  = 4729                                        [підсумовування розрядних внесків]
```

Такий підхід забезпечує швидке та завадостійке перетворення набраних уставок у скалярне цілочисельне значення без блокування процесора та без використання обчислювально містких операцій з рухомою комою.

V = ∑ (D_k × 10^k)

де `D_k` — значення `k`-ї BCD-декади (від `0` до `9`), а `10^k` — її десяткова вага. Такий підхід забезпечує швидке та завадостійке перетворення набраних уставок без блокування процесора.
