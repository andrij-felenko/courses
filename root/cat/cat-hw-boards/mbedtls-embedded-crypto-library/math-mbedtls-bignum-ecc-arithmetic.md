## Проблема обробки великих чисел у мікроконтролерах

Асиметрична криптографія оперує числами від 2048 біт. Обчислення таких значень на 32-бітному ядрі Xtensa LX106 натрапляють на [обмеження оперативної пам'яті](root:cat-hw-boards/esp8266-soc-architecture-overview) та розрядності тракту: його @@en|арифметично-логічний пристрій@@ (від @@en|Arithmetic Logic Unit@@) обробляє лише 32-бітні слова у регістрах `a0`–`a15`.

Один 32-бітний @@en|регістр@@ (від @@la|registrum@@ — внесений список) вміщує до 2³² - 1 (≈ 4.29 × 10⁹), а модуль RSA-2048 сягає 10⁶¹⁶. Запис такого значення у тип `uint32_t` викликає @@en|переповнення@@ (від @@en|overflow@@): біт переносу втрачається, а старші 2016 біт не мають місця.

Усі 16 регістрів ядра дають лише 512 біт, що замало навіть для 1024-бітного ключа. Крім того, апаратні інструкції не прокидають біт переносу між регістрами при множенні. Тому під час встановлення [шифрованих з'єднань](root:cat-hw-boards/esp8266-at-ssl-tls) пряма машинова арифметика непридатна.

Розв'язком є програмне представлення великих чисел масивами у пам'яті DRAM. Бібліотека mbedTLS реалізує це як @@en|багаторозрядне ціле число@@ через @@en|модуль MPI@@ (від @@en|Multi-Precision Integer@@), який розбиває надвелике число на масив машинних слів і програмно виконує арифметику у стовпчик із передачею переносу.

Робота модуля MPI на мікроконтролері вимагає мінімізації динамічної пам'яті, константного часу виконання для захисту від атак за побічними каналами та швидкої базової арифметики. Це створює підґрунтя для побудови математичної структури представлення великих чисел.

## Представлення та базові операції модуля MPI

У модулі MPI бібліотеки mbedTLS будь-яке позитивне або негативне велике число `X` подається алгебраїчною сумою за @@en|основою числення@@ (від @@la|basis@@ — основа) `B = 2³²`. Математично це відповідає розкладу числа за степенями основи:

X = s × ∑ (aᵢ × Bⁱ)     [при i від 0 до n-1]
  = s × (a₀ + a₁ × 2³² + a₂ × 2⁶⁴ + ... + aₙ₋₁ × 2³²⁽ⁿ⁻¹⁾)

тут `s ∈ {-1, 1}` визначає знак числа, `n` — кількість використаних блоків, а кожен коефіцієнт `aᵢ` є 32-бітним беззнаковим цілим числом у діапазоні від `0` до `2³² - 1`.

У коді бібліотеки окремий блок `aᵢ` називається @@en|лимб@@ (від @@en|limb@@ — деталь, член). Структура `mbedtls_mpi` містить знак `s`, кількість виділених лимбів `n` та вказівник `p` на масив лимбів у оперативній пам'яті. Для 2048-бітного числа RSA потрібно `n = 64` лимби по 32 біти кожен.

![Внутрішнє представлення структури mbedtls_mpi у вигляді масиву 32-бітних лимбів та подекадне додавання із зсувами при редукції](img/mbedtls-mpi-bignum-structure-and-operations.svg)
*Схема розбиття багаторозрядного числа на 32-бітні лимби у пам'яті та механізм послідовного переносу біта переповнення між сусідніми блоками при додаванні.*

Базові арифметичні операції над структурою `mbedtls_mpi` виконуються ітеративною обробкою лимбів. При додаванні двох чисел `A` та `B` розраховується сума відповідних лимбів `aᵢ` та `bᵢ` з урахуванням біта переносу `cᵢ` від попереднього кроку:

Sᵢ = (aᵢ + bᵢ + cᵢ) mod 2³²     [значення поточного лимба результату]
cᵢ₊₁ = ⌊(aᵢ + bᵢ + cᵢ) ÷ 2³²⌋    [перенос у наступний старший лимб]

Складність додавання двох `n`-лимбових чисел становить `O(n)` машинних інструкцій. Віднімання виконується аналогічно через обчислення біта позичення.

Класичне множення за шкільним алгоритмом виконує множення кожного лимба першого числа на кожен лимб другого числа, що потребує `n²` операцій множення 32-бітних слів. Для 2048-бітного числа (`n = 64`) це означає 4096 машинних множень.

Щоб зменшити це навантаження, mbedTLS застосовує [алгоритм Карацуби](root:sf-algorithms/karatsuba-multiplication). Метод розбиває кожне `n`-лимбове число на дві половини по `k = n / 2` лимбів: `X = X₁ × Bᵏ + X₀` та `Y = Y₁ × Bᵏ + Y₀`. Замість чотирьох множень напівчисел обчислюються лише три добутки:

P₀ = X₀ × Y₀                     [добуток молодших частин]
P₂ = X₁ × Y₁                     [добуток старших частин]
P₁ = (X₀ + X₁) × (Y₀ + Y₁) - P₀ - P₂   [проміжний перехресний добуток]

Підсумковий добуток відновлюється за формулою:

X × Y = P₂ × B²ᵏ + P₁ × Bᵏ + P₀

Алгоритм зменшує обчислювальну складність з `O(n²)` до `O(nˡᵒᵍ² ³) ≈ O(n¹˙⁵⁸⁵)`. Для `n = 64` це скорочує кількість множень приблизно з 4096 до 729.

Після виконання множення результат має довжину `2n` лимбів. Для приведення його до криптографічного модуля виконується @@en|модульна редукція@@ (від @@la|reductio@@ — повернення), тобто обчислення залишку від ділення `R = X mod M`. У найпростішому випадку це потребує ділення куточком у багаторозрядній арифметиці зі складністю `O(n²)`.

Нижче наведено приклад реалізації подекадного додавання лимбів довгого числа у мовах C та C++:

#include <stddef.h>

// Додавання двох масивів лимбів однакової довжини n
uint32_t mbedtls_mpi_add_limbs(uint32_t *res, const uint32_t *a, const uint32_t *b, size_t n) {

    for (size_t i = 0; i < n; i++) {

    }

}

## Математика модульного піднесення до степеня RSA

Операція підписання та розшифрування у криптосистемі RSA базується на обчисленні @@en|модульного піднесення до степеня@@ (від @@la|exponentia@@ — показник):

C = Mᵈ mod N

де `M` — вхідне повідомлення, `d` — секретний показник степеня довжиною 2048 біт, а `N = p × q` — модуль RSA довжиною 2048 біт, утворений множенням двох простих чисел `p` та `q` по 1024 біти кожне.

Пряме піднесення `M` до степеня `d` з подальшою редукцією за модулем `N` неможливе, оскільки число `Mᵈ` мало б розмір у мільйони біт. Замість цього застосовується алгоритм бінарного піднесення до степеня (квадрування та множення). Степень `d` розкладається у двійковий вигляд: `d = ∑ (dᵢ × 2ⁱ)` при `dᵢ ∈ {0, 1}`. Кількість операцій множення скорочується з `O(d)` до `O(log d)`. Для 2048-бітного степеня це вимагає 2048 квадрувань та пересічно 1024 множення.

Однак виконання звичайної редукції за модулем `N` після кожного множення потребує класичного багаторозрядного ділення зі складністю `O(n²)`. В результаті загальна складність модульного піднесення до степеня сягає `O(n³)`. Для 64-лимбових чисел це вимагає понад `2048 × 64² ≈ 8.3 × 10⁶` операцій з лимбами.

Для прискорення обчислень mbedTLS використовує [редукцію Монтгомері](root:sf-algorithms/montgomery-multiplication). Ідея полягає в переході у @@en|простір Монтгомері@@, де важка операція ділення на модуль `N` замінюється простим зсувом бітів та діленням на допоміжну основу `R = 2³²ᵏ > N` (де `k` — кількість лимбів модуля `N`). Ділення на `R` у комп'ютерній арифметиці виконується миттєво відкиданням `k` молодших лимбів.

Число `A` переводиться у простір Монтгомері множенням на `R mod N`:

A~ = (A × R) mod N

Множення двох чисел у просторі Монтгомері виконується через операцію `REDC(A~ × B~)`:

REDC(T) = (T + (T × N' mod R) × N) ÷ R

тут `N'` — константа, яка задовольняє співвідношення `R × R⁻¹ - N × N' = 1`. Результат `REDC(A~ × B~)` дорівнює `(A × B × R) mod N = C~`, що є зображенням добутку `A × B` у просторі Монтгомері. Оскільки ділення відбувається лише на `R = 2³²ᵏ`, складність одного модульного множення зменшується з `O(n²)` ділень до `O(n²)` зсувів та додавань, позбавляючись від найважчої частини класичного ділення.

Другим потужним математичним прискоренням є [Китайська теорема про залишки](root:sf-security/chinese-remainder-theorem-crypto) (CRT, від @@en|Chinese Remainder Theorem@@). Замість піднесення до степеня за 2048-бітним модулем `N`, обчислення розщеплюються на два незалежні модулі `p` та `q` довжиною по 1024 біти:

mₚ = Cᵈᵖ mod p     [де dₚ = d mod (p - 1)]
mⲇ = Cᵈⲇ mod q     [де dⲇ = d mod (q - 1)]

Оскільки складність піднесення до степеня пропорційна кубу довжини модуля `O(n³)`, зменшення довжини модуля удвічі скорочує обсяг обчислень для кожної половини у `2³ = 8` разів. Два обчислення по 1024 біти потребують `1/8 + 1/8 = 1/4` від часу обчислення 2048-бітної операції. Реконструкція підсумкового результату `M` виконується за формулою Гарнера:

h = (qᵢₙᵥ × (mₚ - mⲇ)) mod p     [де qᵢₙᵥ = q⁻¹ mod p]
M = mⲇ + h × q

Завдяки CRT загальне прискорення підписання RSA на мікроконтролері досягає майже 4 разів.

Під час виконання цих обчислень виникає загроза, яку становить @@en|атака за побічними каналами@@ (від @@en|side-channel attack@@). Оскільки час виконання множення залежить від значень бітів секретного ключа `d`, аналізатор може відновити ключ за коливаннями споживання струму чи затримками виконання. Для захисту від таких атак mbedTLS застосовує математичне @@en|маскування@@ (від @@en|blinding@@). Перед піднесенням до степеня вхідне значення `M` множиться на випадковий числовий фактор `rᵉ mod N`:

M' = (M × rᵉ) mod N

Після обчислення `(M')ᵈ mod N = Mᵈ × r mod N` результат множиться на `r⁻¹ mod N`, що повністю знімає маскувальну величину `r`. Оскільки `M'` стає випадковим для кожного нового підпису, витік інформації про секретний ключ `d` через побічні канали повністю блокується.

## Скалярне множення точок на еліптичних кривих

Обчислювальна складність 2048-бітної арифметики RSA ставить жорсткі рамки перед 32-бітними мікроконтролерами. Виконання піднесення до степеня за модулем з 64 лимбів вимагає мільйонів машинних тактів ядра, що створює помітні затримки при встановленні [шифрованих з'єднань TLS](root:cat-hw-boards/esp8266-at-ssl-tls). Алгебра @@en|криптографії еліптичних кривих@@ (від @@gr|ἐλλειπτικός@@ — недосконалий, зрізаний; від @@en|Elliptic Curve Cryptography@@) пропонує розв'язання цієї проблеми: досягнення аналогічного або вищого рівня стійкості за рахунок значно коротших ключів.

Еліптична крива над скінченним простим @@en|полем Галуа@@ (названим на честь французького математика Еваріста Галуа) `F_p` визначається множиною точок `P = (x, y)`, що задовольняють канонічне рівняння Вейєрштрасса:

y² = x³ + a × x + b mod p     [умова 4 × a³ + 27 × b² ≠ 0 mod p]

тут `p` — велике просте число (наприклад, 256 біт для кривої `secp256r1`), а `a` та `b` — коефіцієнти кривої. Множина точок кривої разом із спеціальною @@en|точкою на нескінченності@@ (від @@la|infinitas@@ — безмежність), що позначається як `O`, утворює абелеву групу щодо операції додавання.

Додавання двох різних точок `P = (x₁, y₁)` та `Q = (x₂, y₂)` геометрично відповідає проведенню січної лінії через `P` та `Q`, знаходженню третьої точки перетину з кривою та її дзеркальному відображенню відносно осі `X`. Алгебраїчно коефіцієнт нахилу січної `λ` та координати нової точки `R = P + Q = (x₃, y₃)` обчислюються за формулами:

λ = (y₂ - y₁) × (x₂ - x₁)⁻¹ mod p   [нахил січної лінії при P ≠ Q]
x₃ = λ² - x₁ - x₂ mod p              [абсциса сумарної точки]
y₃ = λ × (x₁ - x₃) - y₁ mod p        [ордината сумарної точки]

Якщо точки збігаються (`P = Q`), січна лінія перетворюється на дотичну, а операція називається @@en|подвоєнням точки@@ (від @@en|point doubling@@). Нахил дотичної обчислюється через похідну:

λ = (3 × x₁² + a) × (2 × y₁)⁻¹ mod p  [нахил дотичної при P = Q]
x₃ = λ² - 2 × x₁ mod p                [абсциса подвоєної точки]
y₃ = λ × (x₁ - x₃) - y₁ mod p         [ордината подвоєної точки]

Кожна така операція вимагає модульного множення, квадрування та обчислення оберненого елемента `(x₂ - x₁)⁻¹ mod p`. Операція інвертування є найважчою, тому бібліотека mbedTLS переводить координати точок у @@en|проективні координати Якобі@@ (названі на честь Карла Якобі), де точка подається трійкою `(X, Y, Z)` з відношенням `x = X ÷ Z²` та `y = Y ÷ Z³`. Це дозволяє замінити модульне ділення на серію множень лимбів і виконувати єдине інвертування лише в самому кінці обчислень.

Центральною операцією у криптографії еліптичних кривих є @@en|скалярне множення@@ (від @@la|scalaris@@ — східчастий), яке полягає в обчисленні точки `Q = k × P`, де `k` — 256-бітне ціле число (секретний ключ), а `P` — базова точка кривої. Класичний @@en|алгоритм подвоєння та додавання@@ (від @@en|double-and-add@@) послідовно аналізує біти `kᵢ` скаляра `k`. Якщо `kᵢ = 1`, виконується і подвоєння, і додавання точки, а якщо `kᵢ = 0` — лише подвоєння. Така асиметрія створює вразливість: споживання струму та час виконання залежать від значення бітів секретного ключа `k`.

Для забезпечення константного часу виконання mbedTLS реалізує [скалярне множення Монтгомері](root:sf-security/montgomery-ladder) за алгоритмом драбини Монтгомері. Алгоритм підтримує паралельний стан із двох точок `(R₀, R₁)`, для яких зберігається інваріант `R₁ - R₀ = P`. На кожному кроці для кожного біта `kᵢ` виконується суворо однакова послідовність з одного додавання та одного подвоєння точок:

*Графічне зображення додавання точок на кривій над скінченним полем F_p та граф станів драбини Монтгомері для константного часу скалярного множення.*

Незалежно від того, дорівнює біт `kᵢ` нулю чи одиниці, обчислювальні витрати кожного кроку ідентичні. Це повністю нівелює можливість витоку секретного скаляра через [аналіз затримки виконання](root:cat-hw-boards/esp8266-soc-architecture-overview).

Скалярне множення є основою протоколу обміну ключами ECDHE (від @@en|Elliptic Curve Diffie-Hellman Ephemeral@@) та цифрового підпису ECDSA (від @@en|Elliptic Curve Digital Signature Algorithm@@). У протоколі ECDHE кожен вузол генерує тимчасовий скаляр `d` і передає відкриту точку `Q = d × P`. Спільний секрет `Z` обчислюється як абсциса точки `Z = x(dₐ × Qᵦ) = x(dₐ × dᵦ × P)`.

Порівняння складності ECC та RSA демонструє кардинальну перевагу еліптичних кривих. Ключ `secp256r1` довжиною 256 біт забезпечує рівень криптографічної стійкості у 128 біт, що відповідає RSA-3072. Водночас 256-бітному скаляру відповідає масив лише з `n = 8` 32-бітних лимбів у модулі MPI, порівняно з `n = 64` лимбами для RSA-2048. Оскільки складність множення лимбів становить `O(n²)`, зменшення кількості лимбів у 8 разів скорочує кількість машинних множень на один крок у 64 рази, роблячи обчислення на 32-бітному ядрі Xtensa надзвичайно швидкими.

## Автентифікація GHASH та генерація ентропії CTR-DRBG

Після завершення асиметричного обміну ключами протокол TLS переходить до симетричного шифрування та перевірки цілісності даних. У сучасних шифр-сюїтах основним механізмом шифрування є режим AES-GCM, для якого криптографічний захист від підробки забезпечує @@en|алгоритм автентифікації GHASH@@ (від @@en|Galois Hash@@). Увесь обсяг обчислень GHASH спирається на [поле Галуа GF(2^128)](root:sf-security/galois-field-ghash-gcm) — скінченне розширене поле з `2¹²⁸` елементів.

Елементами поля `GF(2¹²⁸)` є 128-бітні вектори, які алгебраїчно розглядаються як двобінарні поліноми ступеня менше 128 з коефіцієнтами з поля `GF(2)`:

A(x) = a₁₂₇ × x¹²⁷ + a₁₂₆ × x¹²⁶ + ... + a₁ × x + a₀     [де aᵢ ∈ {0, 1}]

Додавання двох елементів у полі `GF(2¹²⁸)` виконується як побітне додавання коефіцієнтів за модулем 2, що відповідає машиновій операції @@en|побітового виключного АБО@@ (від @@en|Exclusive OR@@). Оскільки операція XOR не викликає переносу між розрядами, додавання 128-бітних блоків у ядрі Xtensa виконується за 4 інструкції зі складністю `O(1)`.

Множення двох поліномів `A(x)` та `B(x)` виконується за модулем @@en|незвідного многочлена@@ (від @@la|irreducibilis@@ — неподільний) `P(x)` ступеня 128, визначеного стандартом NIST:

P(x) = x¹²⁸ + x⁷ + x² + x + 1     [незвідний двобінарний многочлен]

Оскільки `x¹²⁸ ≡ x⁷ + x² + x + 1 mod P(x)`, множення елемента `A(x)` на базисний поліном `x` (що відповідає зсуву 128-бітного масиву вліво на 1 біт) при наявності одиниці у старшому біті `a₁₂₇` потребує виконання XOR з константою `0xE1000000000000000000000000000000`. 

Ітеративне обчислення коду автентифікації GHASH над блоками зашифрованих даних `Xᵢ` з використанням ключа автентифікації `H = E_K(0¹²⁸)` виконується за рекурентною формулою:

Yᵢ = (Yᵢ₋₁ ⊕ Xᵢ) × H mod P(x)     [послідовне оновлення хеш-блоку]

Для прискорення множення у `GF(2¹²⁸)` mbedTLS застосовує табличну оптимізацію Shoup. Попередньо розраховуються добутки ключа `H` на всі 4-бітні або 8-бітні комбінації поліномів, що дає змогу замінити важкі бітові зсуви вибіркою з таблиць у пам'яті DRAM. Завдяки цьому [мережевий стек lwIP](root:cat-hw-boards/lwip-architecture-esp8266) обробляє підтвердження цілісності пакетів майже без затримок.

Паралельно із шифруванням симетричних даних криптографічний стек mbedTLS вимагає постійного джерела якісних псевдовипадкових чисел для генерування вектора ініціалізації, сесійних ключів та маскувальних множників RSA і ECC. З цією метою використовується [генератор CTR-DRBG](root:sf-security/ctr-drbg-random-generator) (від @@en|Counter Deterministic Random Bit Generator@@), побудований на блоковому шифрі AES у режимі лічильника відповідно до стандарту NIST SP 800-90A.

Внутрішній стан генератора CTR-DRBG складається з 256-бітного симетричного ключа `K` та 128-бітного значення лічильника `V`. Алгоритм генерації псевдовипадкових бітів послідовно інкрементує лічильник `V` та шифрує його за допомогою блокового шифру AES-256:

Vᵢ = (Vᵢ₋₁ + 1) mod 2¹²⁸         [інкремент лічильника]
Outᵢ = AES-Encrypt(K, Vᵢ)        [генерація псевдовипадкового блоку]

Отриманий потік блоків `Outᵢ` подається криптографічним функціям. Після кожного запиту стан генератора обов'язково оновлюється функцією `CTR-DRBG-Update`, яка виконує шифрування додаткових даних та XOR з поточними значеннями `K` та `V`, забезпечуючи властивість @@en|незворотності стану@@ (від @@en|forward secrecy@@).

Математична стійкість детермінованого генератора критично залежить від криптографічної @@en|ентропії@@ (від @@gr|εντροπία@@ — перетворення) вхідних даних, якими оновлюється генератор під час ініціалізації. Ймовірнісна модель оцінки ентропії за Шенноном визначає кількість інформації на символ вибірки:

H(X) = - ∑ P(xᵢ) × log₂ P(xᵢ)     [сумування за всіма можливими станами xᵢ]

На мікроконтролері ESP8266 основним джерелом ентропії є апаратні шуми аналогово-цифрового перетворювача та випадкові фазові флуктуації Wi-Fi радіотракту. Джерело має забезпечувати мінімальну ентропію `H_∞ ≥ 256` біт. Якщо вхідний вектор ентропії містить менше 256 біт дійсного шуму, передбачуваність генератора зростає. Це призводить до катастрофічних наслідків: повторне використання одноразового числа в ECDSA дозволяє зловмиснику миттєво обчислити приватний ключ `d` через розв'язання системи лінійних рівнянь.

## Оптимізація та розрахунок швидкодії рукостискання TLS

Усі оцінки швидкодії TLS-з'єднань на мікроконтролерах зводяться до математичного підсумку: скільки обчислювальних тактів процесора витрачається на процедуру встановлення зв'язку. Знаючи алгоритмічну складність окремих криптографічних модулів mbedTLS, можна скласти підсумковий [розрахунок затримок рукостискання](root:sf-security/tls-handshake-performance-budget) на ядрі Xtensa LX106 з тактовою частотою 80 МГц (або 160 МГц при розгоні).

Обчислювальний бюджет процедури рукостискання TLS 1.2 складається із 3 основних етапів: перевірки сертифіката сервера, обміну ключами та ініціалізації симетричного шифру.

Розглянемо два типи шифр-сюїтів однакового рівня безпеки:

1. Застарілий сюїт `TLS_RSA_WITH_AES_128_GCM_SHA256`:
   - Перевірка підпису RSA-2048 сертифіката сервера: відкритий показник степеня `e = 65537 = 2¹⁶ + 1` вимагає 16 квадрувань та 1 множення 64-лимбових чисел MPI. Обсяг обчислень складає приблизно 70 тисяч машинних тактів (≈ 15 мс при 80 МГц).
   - Асиметричний обчислювальний етап RSA-2048 (розшифрування Pre-Master Secret секретним ключем): модульне піднесення до степеня з CRT та маскуванням виконує близько `8.3 × 10⁶` лимбових множень. На частоті 80 МГц це вимагає близько 1.15 секунди чистого часу процесора.

2. Сучасний рекомендувальний сюїт `TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256`:
   - Скалярне множення точок на кривій `secp256r1` для протоколу ECDHE (драбина Монтгомері): 256 кроків, кожен з яких виконує 8-лимбові операції над проективними координатами. Сумарно це вимагає близько `6.5 × 10⁵` машинних інструкцій (≈ 65 мс при 80 МГц).
   - Перевірка цифрового підпису ECDSA-256 сертифіката сервера: подвійне скалярне множення `s⁻¹ × H(m) × G + s⁻¹ × r × Q` вимагає близько `1.1 × 10⁶` інструкцій (≈ 110 мс при 80 МГц).

Загальне зіставлення двох підходів зведено в розрахункову формулу часових затримок рукостискання:

T_RSA = T_CRT + T_RSA_dec + T_DRBG_GHASH     [компоненти RSA рукостискання]
      = 15 мс + 1150 мс + 5 мс
      = 1170 мс                              [загальний час CPU при 80 МГц]

T_ECDHE = T_ECDHE_step + T_ECDSA_ver + T_DRBG_GHASH  [компоненти ECDHE рукостискання]
        = 65 мс + 110 мс + 5 мс
        = 180 мс                             [загальний час CPU при 80 МГц]

Перехід з RSA-2048 на ECDHE-ECDSA скорочує процесорний час рукостискання майже у 6.5 разів (з 1.17 секунди до 180 мілісекунд). Це не лише підвищує чутливість пристрою, але й запобігає виникненню таймаутів у [мережевих сокетах lwIP](root:cat-hw-boards/esp01-tcp-udp-sockets), усуваючи повторні перезапити TCP-кадрів.

Крім того, використання еліптичних кривих суттєво заощаджує оперативну пам'ять DRAM пристрою. У той час як для виконання RSA-2048 потрібні десятки тимчасових масивів `mbedtls_mpi` по 64 лимби (сумарно понад 4 КБ стекового простору лише під математичні змінні), обчислення на кривій `secp256r1` оперують 8-лимбовими масивами (по 32 байти на координату), скорочуючи споживання оперативної пам'яті у 8 разів.

Обґрунтований вибір криптографічних конфігурацій для мікроконтролерів ESP8266 передбачає:
- Використання шифр-сюїтів ECDHE з кривими `secp256r1` або `Curve25519`.
- Переведення тактової частоти ядра Xtensa LX106 з 80 МГц на 160 МГц під час виконання рукостискання TLS, що зменшує часову затримку ECDHE до рекордних 90 мс.
- Забезпечення обов'язкової апаратної підкачки ентропії в генератор CTR-DRBG перед початком кожного TLS-з'єднання.

Це гарантує оптимальне балансування між стійким 128-бітним криптографічним захистом та високою швидкодією вбудованої системи.
