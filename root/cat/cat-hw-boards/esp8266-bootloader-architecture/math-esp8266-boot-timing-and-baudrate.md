## Сбої запуску через просідання живлення

Подача живлення на плату мікроконтролера в реальних пристроях часто супроводжується хаотичними зависаннями процесорного ядра або помилковим вибором режиму виконання коду. Розробник підключає живлення до популярних [модулів ESP-01](root:cat-hw-boards/esp-01) і очікує, що система розпочне виконання прошивки з флеш-пам'яті або перейде в режим завантаження через послідовний порт. Натомість мікроконтролер видає в термінал сміттєві символи, блокує шину даних або непередбачувано зупиняє виконання інструкцій. Першою інтуїтивною реакцією стає випадкова заміна зовнішніх конденсаторів та підтягуючих резисторів на платі без розуміння фізичних процесів, які відбуваються всередині кремнієвого кристала.

Спроби вирішити проблему хаотичним підбором ємностей не дають стабільного результату, оскільки перехідні процеси під час увімкнення підпорядковуються суворим законам електродинаміки. У розробці вбудованих систем неконтрольований спад або повільне наростання напруги живлення називають просіданням живлення (англ. @@en|brownout@@, від *brown* — «тьмяніти» через спад напруги розжарювання). Під час подачі напруги живлення `VDD` на внутрішні блоки кристала, опис яких дає стаття про особливості [архітектури SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview), шини системи перебувають під впливом двох ключових керуючих сигналів. Це лінія ввімкнення внутрішніх аналогових стабілізаторів `CHIP_PU` та лінія скидання процесорного ядра `RST`.

Логічні рівні на цих виводах визначають стан, у якому перебуває мікроконтролер під час подачі живлення. Спеціальні тригери та цифрові вхідні буфери кристала фіксують логічні стани зовнішніх виводів у моменти виходу зі стану скидання (англ. @@en|reset@@, від *re-* — «знову» та *set* — «встановлювати»). Ці внутрішні регістри-фіксатори мають назву засувки защеплення (англ. @@en|strapping latches@@, від *strap* — «стягувати, затискати» та *latch* — «фіксувати стан»). Вони зчитують логічні рівні на конфігураційних виводах `GPIO0`, `GPIO2` та `GPIO15` строго в момент, коли напруга на виводі `RST` досягає порогу логічного нуля або одиниці.

Якщо джерело живлення має високий внутрішній опір або велику ємність на виході, напруга `VDD` наростає повільно. У цей момент внутрішні компаратори модуля апаратного скидання під час увімкнення (англ. @@en|power-on reset@@) фіксують вихід зі стану скидання раніше, ніж напруга на шині живлення досягне мінімального робочого рівня `VDD,min = 3.0 В`. Через це цифрові засувки опиняються в стані невизначеності, який викликає явище метастабільності (англ. @@en|metastability@@). Для запобігання апаратним збоям необхідно відмовитися від емпіричного підбору деталей і побудувати математичну модель заряджання RC-кола з урахуванням критичної швидкості наростання живлення `dV/dt`.

## Розрахунок RC-ланцюгів скидання та dV/dt

Апаратний скид процесорного ядра Tensilica LX106 в ESP8266 контролюється перехідними процесами в зовнішньому або внутрішньому RC-ланцюзі, який складається з резистора підтяжки `R` до шини `VDD` та конденсатора `C`, підключеного до спільного проводу `GND`. Вхідний буфер лінії `RST` має стандартні пороги спрацьовування КМОН-логіки. Для надійної фіксації логічного нуля напруга не повинна перевищувати поріг `V_IL = 0.25 · VDD`, а для фіксації логічної одиниці напруга має піднятися вище порогу `V_IH = 0.75 · VDD`.

Динаміка зміни напруги `V_RST(t)` на ємності `C` описується диференціальним рівнянням першого порядку. Часова константа (англ. @@en|time constant@@) цього кола позначається символом `τ` і дорівнює добутку опору на ємність `τ = R · C`. Розглянемо видок напруги для ідеального ступінчастого стрибка живлення, коли напруга `VDD` миттєво зростає від `0` до номінального значення `VDD,0`:

R · C · (dV_RST(t) / dt) + V_RST(t) = VDD
= dV_RST(t) / dt + (1 / τ) · V_RST(t) = VDD / τ          [диференціальне рівняння RC-кола]
= V_RST(t) = VDD · (1 - e^(-t / τ))                       [загальний розв'язок при V_RST(0) = 0]

Час `t_rst`, протягом якого напруга на виводі `RST` досягає тригерного порогу виходу зі скидання `V_IH = 0.75 · VDD`, обчислюється шляхом підстановки значення порогу в отримане рівняння:

0.75 · VDD = VDD · (1 - e^(-t_rst / τ))
= e^(-t_rst / τ) = 0.25                                 [спрощення та скорочення VDD]
= -t_rst / τ = ln(0.25)                                 [логарифмування двох частин рівняння]
= t_rst = τ · ln(4)                                     [перехід до додатного логарифма]
= t_rst ≈ 1.3863 · R · C                                [чисельний коефіцієнт часу скидання]

У реальних джерелах живлення напруга `VDD` не змінюється миттєво, а зростає за лінійним законом з певною крутизною. Швидкість наростання напруги (англ. @@en|slew rate@@) позначається як `S = dV/dt`. Тоді функція живлення має вигляд `VDD(t) = S · t`. Диференціальне рівняння заряджання конденсатора в умовах лінійного фронту живлення набуває вигляду:

dV_RST(t) / dt + (1 / τ) · V_RST(t) = (S · t) / τ

Розв’язок цього диференціального рівняння шукають через інтегрувальний множник `e^(t / τ)`:

d/dt [V_RST(t) · e^(t / τ)] = (S / τ) · t · e^(t / τ)
= V_RST(t) · e^(t / τ) = S · (t · e^(t / τ) - τ · e^(t / τ) + τ) [інтегрування по частинах]
= V_RST(t) = S · t - S · τ · (1 - e^(-t / τ))            [залежність напруги скидання від часу]

З отриманої формули видно, що напруга скидання `V_RST(t)` відстає від напруги живлення `VDD(t)` на величину `ΔV(t) = S · τ · (1 - e^(-t / τ))`. При довготривалому наростанні `t ≫ τ` це відставання стабілізується на рівні `ΔV = S · τ`.

Щоб мікроконтролер не вийшов зі стану скидання раніше, ніж живлення `VDD` досягне мінімально припустимого рівня `VDD,min = 3.0 В`, напруга `V_RST` повинна залишатися нижчою за поріг `V_IL = 0.25 · VDD` протягом усього часу наростання живлення `t_ramp = VDD,min / S`. Якщо крутизна `S = dV/dt` є занадто малою, напруга `V_RST` перетне поріг `V_IH` при нестабільній напрузі живлення, що призведе до помилкового зчитування стану конфігураційних виводів.

**Обчислення критерію dV/dt для типових номіналів R = 10 кОм та C = 1 мкФ**
```
τ = R · C = 10000 · 10⁻⁶ = 0.01 c = 10 мс
t_rst = 1.3863 · 0.01 = 0.01386 c = 13.86 мс            [час виходу зі скидання при ступені]
(dV/dt)_min = (VDD,min · (1 - 0.25)) / τ                [поріг утримання скидання при наростанні]
(dV/dt)_min = (3.0 · 0.75) / 0.01 = 225 В/c            [мінімальна крутизна фронту живлення]
```
*Висновок: якщо джерело живлення подає напругу з крутизною менше 225 В/с (наростання до 3.3 В триває довше 14.6 мс), при даній ємності мікроконтролер почне завантаження до стабілізації живлення.*

## Часові вікна защеплення засувок завантаження

Математичний розрахунок часу виходу зі стану скидання `t_rst` дає змогу визначити точний момент, коли внутрішні апаратні засувки фіксують стан конфігураційних виводів. Мікроконтролер ESP8266 підтримує різні [режими завантаження мікроконтролера](root:cat-hw-boards/esp8266-boot-modes), вибрати які можна через рівні на трьох виводах: `GPIO15`, `GPIO0` та `GPIO2`. Детальний опис схемотехніки підтяжки містять [конфігураційні виводи завантаження](root:cat-hw-boards/esp8266-boot-strapping-pins).

Для стабільного вибору режиму апаратура кристала вимагає виконання двох часових умов:
1. Час встановлення (англ. @@en|setup time@@, від *set up* — «встановлювати заздалегідь») `t_setup ≥ 10 нс`. Логічний рівень на виводах має повністю стабілізуватися до моменту, коли напруга `V_RST` перетне поріг `V_IH`.
2. Час утримання (англ. @@en|hold time@@, від *hold* — «утримувати») `t_hold ≥ 20 нс`. Логічний рівень повинен зберігатися незмінним після перетину порогу `V_IH`.

Під час увімкнення внутрішні резистори підтяжки мікроконтролера вимкнені, а лінія має власну паразитну ємність (англ. @@en|parasitic capacitance@@) `C_L = C_pin + C_trace + C_ext`, яка зазвичай становить від `25 пФ` до `50 пФ`. Струм витоку (англ. @@en|leakage current@@) вхідних каскадів становить близько `I_leak ≈ 10 мкА`.

Для забезпечення логічного нуля на `GPIO15` зовнішній заземлюючий резистор (англ. @@en|pull-down@@) `R_pulldown` повинен обмежувати падіння напруги від струму витоку:

V_GPIO15 = I_leak · R_pulldown ≤ V_IL,max = 0.25 · VDD = 0.825 В
= R_pulldown ≤ 0.825 В / 10 мкА = 82.5 кОм              [максимальний опір pull-down]

Для забезпечення логічної одиниці на `GPIO0` або `GPIO2` зовнішній підтягуючий резистор (англ. @@en|pull-up@@) `R_pullup` повинен забезпечувати напругу, вищу за `V_IH`:

V_GPIO0 = VDD - I_leak · R_pullup ≥ V_IH,min = 0.75 · VDD = 2.475 В
= R_pullup ≤ 0.825 В / 10 мкА = 82.5 кОм                [максимальний опір pull-up]

Крім статичних рівнів напруги, існує динамічне обмеження. Заряджання паразитної ємності `C_L` через резистор `R_pullup` відбувається з власною часовою константою `τ_gpio = R_pullup · C_L`. Час наростання напруги на лінії до рівня `V_IH` становить `t_rise,gpio = 1.3863 · R_pullup · C_L`.

Головна умова надійної фіксації режиму завантаження полягає в тому, що сигнал на GPIO повинен досягти рівня `V_IH` з урахуванням часу встановлення `t_setup` раніше, ніж зніметься апаратне скидання `RST`:

t_rise,gpio + t_setup ≤ t_rst = 1.3863 · R_rst · C_rst
= 1.3863 · R_pullup · C_L + t_setup ≤ 1.3863 · R_rst · C_rst [підстановка формул заряджання]
= R_pullup · C_L ≤ R_rst · C_rst - (t_setup / 1.3863)     [критерій узгодження часових констант]

**Розрахунок допустимого навантаження на GPIO0 при R_rst = 10 кОм та C_rst = 100 нФ**
```
τ_rst = 10000 · 100 × 10⁻⁹ = 1 мс
t_rst = 1.3863 · 1 мс = 1.3863 мс                        [час утримання апаратного скидання]
C_L = 50 пФ                                              [паразитна ємність лінії з зовнішньою периферією]
R_pullup,max = t_rst / (1.3863 · C_L)                    [граничний опір підтяжки]
R_pullup,max = 1.3863 × 10⁻³ / (1.3863 · 50 × 10⁻¹²) = 20 МОм [верхнє динамічне обмеження]
```
*Висновок: якщо паралельно підтягуючому резистору додати конденсатор завадозахисту C_ext = 100 нФ (що часто роблять для кнопок), t_rise,gpio зросте до 1.386 мс. У результаті рівень на GPIO0 не встигне піднятися до V_IH до моменту фіксації засувок, і мікроконтролер помилково перейде в режим UART Download замість Flash Boot.*

Правильно розраховані часові константи кола скидання та зовнішніх підтяжок гарантують стабільну фіксацію логічних рівнів, що готує систему до коректної роботи тактових дільників [інтерфейсу UART в ESP8266](root:cat-hw-boards/esp8266-uart-hardware-fifo).

## Математика дільників тактової частоти UART0

Після успішної фіксації рівня на виводах защеплення під час увімкнення та виходу зі стану скидання, первинний завантажник (англ. @@en|ROM bootloader@@) мікроконтролера розпочинає виконання апаратного коду з внутрішнього ПЗП. Для виведення діагностичних повідомлень про причини скидання та стан шин живлення апаратура ініціалізує послідовний порт (англ. @@en|UART@@, від *Universal Asynchronous Receiver-Transmitter* — «універсальний асинхронний приймач-передавач»). Однак розробник, який підключає до плат [модулів ESP-01](root:cat-hw-boards/esp-01) стандартний термінал на швидкості 115200 бод, замість зрозумілого тексту бачить хаотичний набір нечитабельних символів. Причина полягає в тому, що системний завантажник виводить початкові логи на нестандартній швидкості 74880 бод.

Фізичне походження цієї швидкості криється в математичній моделі тактування, яку описує [архітектура SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview). Основним джерелом тактового сигналу для внутрішніх генераторів є зовнішній кварцовий резонатор (англ. @@en|crystal oscillator@@). У екосистемі ESP8266 застосовуються резонатори з тактовою частотою `f_XTAL`, яка зазвичай становить `26 МГц` або `40 МГц`. Внутрішня апаратура периферійного модуля, будову якого висвітлюють [FIFO-буфери інтерфейсу UART](root:cat-hw-boards/esp8266-uart-hardware-fifo), формує імпульси передачі даних шляхом ділення опорної частоти за допомогою спеціального регістру дільника `UART_CLKDIV`.

Під час проектування прошивки системного ПЗП інженери компанії Espressif розраховували коефіцієнти ділення UART0 виходячи з опорної частоти резонатора `f_ref = 40 МГц` для забезпечення стандартної швидкості `Baud_target = 115200 бод`. Формула передавальної базової швидкості (англ. @@en|baud rate@@, від імені французького інженера *Émile Baudot*) визначається відношенням тактової частоти `f_clk` до значення дільника `CLKDIV`:

Baud = f_clk / CLKDIV
= CLKDIV = f_clk / Baud                    [вираження дільника через частоту та швидкість]

Підставивши у формулу еталонні значення системного ПЗП для частоти `40 МГц`, дістаємо зафіксоване в коді завантажника значення дільника `CLKDIV_ROM`:

CLKDIV_ROM = 40000000 / 115200
= CLKDIV_ROM = 347.222222...               [значення дільника в ПЗП для 40 МГц]

Більшість серійних платформ, таких як [огляд сімейства Wi-Fi модулів](root:cat-hw-boards/esp-01-module-family-overview), комплектуються кварцовим резонатором на `26 МГц`. Коли внутрішня апаратура UART0 працює від резонатора `26 МГц` із фіксованим дільником `CLKDIV_ROM = 347.2222`, реальна швидкість передачі `Baud_actual` описується пропорційним співвідношенням:

Baud_actual = f_XTAL / CLKDIV_ROM
= Baud_actual = 26000000 / (40000000 / 115200) [підстановка виразу дільника ПЗП]
= Baud_actual = 115200 · (26000000 / 40000000) [перегрупування множників]
= Baud_actual = 115200 · (13 / 20)           [скорочення співвідношення частот]
= Baud_actual = 115200 · 0.65                [точний чисельний коефіцієнт]
= Baud_actual = 74880 бод                    [фактична швидкість завантажника]

Математичне виведення показує, що швидкість 74880 бод є результатом точного множення 115200 на коефіцієнт `0.65`. Це співвідношення є строгим і не містить теоретичної похибки округлення.

Внутрішній регістр `UART_CLKDIV(0)` периферійного модуля UART0 має 32-бітну структуру і складається з двох частин. Нижні 20 біт `UART_CLKDIV_CNT` задають цілочисельну частину дільника `INT`, а біти 20..23 містять 4-бітну дробову частину (англ. @@en|fractional divider@@, від *fraction* — «дріб, частка») `FRAC`, яка забезпечує дискретність ділення `1/16`. Повний результуючий коефіцієнт обчислюється як `CLKDIV = INT + (FRAC / 16)`.

Розуміння будови регістру `UART_CLKDIV` дає змогу точно розраховувати дробові коефіцієнти для будь-яких системних частот та стандартних швидкостей передачі даних.

## Точний розрахунок швидкостей 74880 та 115200

Після завершення роботи первинного завантажника та передачі керування прошивці користувача виникає потреба переналаштувати UART0 на стандартні швидкості або розрахувати похибку швидкості передачі (англ. @@en|baud rate error@@). Асинхронний кадр даних формату 8N1 складається з 1 стартового біта, 8 бітів даних та 1 стопового біта, утворюючи інтервал у 10 бітових періодів. Приймач фіксує стан лінії в середині кожного біта. Для запобігання зсуву моментів стробування за межі бітового інтервалу накопичена часова похибка за 10 бітів не повинна перевищувати `±5%`. З урахуванням фазового джиттера та апаратної нестабільності допустима похибка швидкості обмежується величиною `E_baud ≤ ±2.5%`.

Якщо похибка перевищує цей поріг, приймач зчитує стоповий біт у момент перехідного процесу, що викликає апаратну помилку кадрування (англ. @@en|framing error@@, від *frame* — «кадр, рамка»). Для обчислення оптимальних значень регістру `UART_CLKDIV` використовують алгоритм розкладання теоретичного дільника `CLKDIV_exact = f_clk / Baud_target` на цілу частину `INT` та дробову частину `FRAC`:

INT = floor(CLKDIV_exact)                   [ціла частина дільника]
= FRAC = round((CLKDIV_exact - INT) · 16)   [дробова частина у шістнадцятих долях]
= CLKDIV_hw = INT + (FRAC / 16)             [відновлений апаратний дільник]
= Baud_actual = f_clk / CLKDIV_hw           [фактична швидкість передачі]
= E_baud = ((Baud_actual - Baud_target) / Baud_target) · 100% [відносна похибка]

Розглянемо практичні обчислення для найбільш поширених конфігурацій кварцових резонаторів та швидкостей передачі.

**Обчислення коефіцієнтів UARTDIV для 115200 бод при частоті резонатора 26 МГц**
```
CLKDIV_exact = 26000000 / 115200 = 225.694444... [теоретичний розрахунковий дільник]
INT = floor(225.694444) = 225                   [цілочисельний реєстровий дільник]
FRAC = round((225.694444 - 225) · 16) = round(11.1111) = 11 [дробовий дільник 11/16]
CLKDIV_hw = 225 + 11 / 16 = 225.6875            [фактичний апаратний дільник]
Baud_actual = 26000000 / 225.6875 = 115205.26 бод [реальна швидкість передачі]
E_baud = ((115205.26 - 115200) / 115200) · 100% = +0.00456% [похибка швидкості]
```
*Висновок: використання дробового дільника FRAC = 11 забезпечує похибку +0.0046%, що в сотні разів менше критичного порогу 2.5% і гарантує відсутність помилок кадрування.*

**Обчислення рассинхронізації при намаганні зчитати логи 74880 бод на швидкості 115200 бод**
```
E_mismatch = ((115200 - 74880) / 74880) · 100%  [відносна різниця швидкостей]
E_mismatch = (40320 / 74880) · 100% = +53.85%   [величезне частотне відхилення]
```
*Висновок: розходження у 53.85% суттєво перевищує допустимий поріг 2.5%, через що приймач виявляє помилку кадрування вже на другому біті кадру і відображає хаотичне сміття.*

**Обчислення коефіцієнтів UARTDIV для системної швидкості 74880 бод при частоті 40 МГц**
```
CLKDIV_exact = 40000000 / 74880 = 534.188034... [теоретичний дільник для 40 МГц]
INT = floor(534.188034) = 534                   [цілочисельний коефіцієнт]
FRAC = round((534.188034 - 534) · 16) = round(3.0085) = 3 [дробовий коефіцієнт]
CLKDIV_hw = 534 + 3 / 16 = 534.1875             [відновлений дільник]
Baud_actual = 40000000 / 534.1875 = 74880.075 бод [фактична швидкість]
E_baud = ((74880.075 - 74880) / 74880) · 100% = +0.0001% [мізерна похибка]
```
*Висновок: системний дільник ПЗП формує швидкість 74880 бод з точністю до тисячних часток відсотка.*

Розрахунок похибок дільників UART0 разом із розрахованими часовими константами RC-кіл CHIP_PU та RST завершує повний математичний аналіз апаратного завантаження ESP8266. Використання узгоджених номіналів підтягуючих резисторів та правильно вибраних реєстрових значень UART_CLKDIV під час проведення такої процедури як [оновлення прошивки та прошивання ESP-01](root:cat-hw-boards/esp01-firmware-flashing) забезпечує апаратну надійність усього циклу ініціалізації SoC.
