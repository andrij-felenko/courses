## Нестабільний старт та проблема перехідних процесів

Під час подачі живлення на схему напруга на шині живлення зростає не миттєво, а описується перехідним процесом наростання від `0` В до робочих `3.3` В за час від кількох мікросекунд до кількох мілісекунд. Крутизна фронту цього наростання `dV/dt` безпосередньо визначає тривалість перебування схеми у проміжному стані: при занадто малому значенні `dV/dt` напруга повільно долає порогову напругу спрацьовування внутрішніх логічних елементів чипа `V_th`, викликаючи затримку формування чітких логічних рівнів. У цьому проміжному діапазоні вхідні КМОН-інвертори працюють у лінійному режимі з високим наскрізним струмом, через що їхні порогові напруги перемикання дрейфують разом із миттєвим рівнем живлення. Якщо внутрішні логічні блоки мікроконтролера виходять із режиму скидання раніше, ніж напруга досягне мінімального порогу стабільного функціонування КМОН-транзисторів, виникає непередбачувана поведінка системних засувок (англ. @@en|Latch@@, від *latch* — засувка, фіксатор). Первинний завантажувач мікроконтролера в [архітектурі SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview) опитує фізичні стани [конфігураційних виводів ESP8266](root:cat-hw-boards/esp8266-boot-strapping-pins) `GPIO0`, `GPIO2` та `GPIO15` у перші ж цикли після зняття внутрішнього сигналу скидання.

Якщо напруга живлення в цей момент перебуває у перехідній зоні, вхідні інвертори отримують недостовірні логічні рівні через нестабільну роботу підтягувальних резисторів. Засувка фіксує помилкову комбінацію бітів, через що системний ROM-завантажувач обирає некоректний [режим завантаження ESP8266](root:cat-hw-boards/esp8266-boot-modes) — наприклад, намагається завантажити код із зовнішнього SDIO-інтерфейсу замість локальної SPI Flash-пам'яті. Для запобігання передчасному старту застосовують апаратну систему скидання при включенні (англ. @@en|Power-On Reset@@, скорочено @@en|POR@@, від *power* — живлення, *on* — включення, *reset* — скидання), яка утримує лінію `RST` у низькому стані до повної стабілізації живлення.

Математична умова надійного функціонування системи @@en|POR@@ зводиться до порівняння тривалості імпульсу скидання `t_POR` із часом завершення перехідних процесів у КМОН-структурі. Сигнал на лінії `RST` повинен утримуватися у низькому стані (не перевищуючи поріг `V_IL ≤ 0.25 × VDD`) протягом часу `t_POR`, який обчислюється як сума тривалості наростання живлення `t_rise` та додаткового інтервалу стабілізації `t_hold ≥ 200` мкс. Якщо тривалість імпульсу не задовольняє нерівність `t_POR ≥ t_rise + 200` мкс, системний завантажувач у збійному режимі опитує [конфігураційні виводи ESP8266](root:cat-hw-boards/esp8266-boot-strapping-pins), що призводить до хибного вибору джерела виконання коду. Для розрахунку точного значення `t_POR` та вибору параметрів зовнішніх компонентів використовують диференціальні рівняння перезаряду ємності в RC-колах.

## Розрахунок часової константи RC-кола скидання

Найпростішим апаратним розв'язком для формування затримки скидання є послідовний RC-ланцюг, підключений до лінії `RST`. Напруга на конденсаторі `C` під час його заряду через підтягувальний резистор `R` від джерела живлення `V_DD` описується експоненціальною залежністю від часу `t`:

```
V_RST(t) = V_DD × (1 - e⁻ᵗ⁽ᴿ⁲ᶜ⁾)
```

Часова константа `τ` (грецька літера тау) визначає час, за який напруга досягає близько `63.2%` від номіналу `V_DD`, і обчислюється як добуток опору та ємності:

```
τ = R × C
```

Для надійного тримання мікроконтролера в стані скидання напруга на виводі `RST` повинна залишатися нижче максимального порогу логічного нуля `V_IL = 0.25 × V_DD` протягом мінімального необхідного часу `t_reset = 200` мкс. Розрахунок часу досягнення порогової напруги `V_IL` проводиться алгебраїчним перетворенням:

```
V_IL = V_DD × (1 - e⁻ᵗ_reset ⁽ᴿ⁲ᶜ⁾)
0.25 × V_DD = V_DD × (1 - e⁻ᵗ_reset ⁽ᴿ⁲ᶜ⁾)  [підстановка порогу V_IL]
0.25 = 1 - e⁻ᵗ_reset ⁽ᴿ⁲ᶜ⁾                 [скорочення V_DD]
e⁻ᵗ_reset ⁽ᴿ⁲ᶜ⁾ = 0.75                     [виділення експоненти]
t_reset = - R × C × ln(0.75)               [логарифмування обох частин]
t_reset = 0.2877 × R × C                   [обчислення -ln(0.75) ≈ 0.2877]
```

![Графік експоненціальної кривої заряду RC-ланцюга скидання з позначенням порогової напруги V_IL та часової константи tau; з неї видно розрахункову область безпечного защеплення strapping-виводів.](img/esp8266-rc-reset-por-charge-curve.svg)
*Графік експоненціальної кривої заряду RC-ланцюга скидання з позначенням порогової напруги V_IL та часової константи tau.*

Щоб забезпечити `t_reset ≥ 200` мкс, мінімальне значення часової константи розраховується як:

```
τ_min = t_reset ÷ 0.2877
= 0.0002 ÷ 0.2877                          [підстановка часу 200 мкс]
≈ 0.000695 с                               [695.2 мкс]
```

При виборі стандартного опору підтяжки `R = 10` кОм (`10000` Ом) мінімальна необхідна ємність становить:

```
C_min = τ_min ÷ R
= 0.000695 ÷ 10000                         [ділення на опір 10 кОм]
= 69.5 × 10⁻⁹ Ф                            [69.5 нФ]
```

Для забезпечення запасу стійкості обирають найближчий більший стандартний номінал керамічного конденсатора `C = 100` нФ (`100 × 10⁻⁹` Ф), що дає часову константу `τ = 1000` мкс (`1` мс) та фактичну затримку `t_reset = 287.7` мкс, що гарантує надійне защеплення конфігураційних виводів.

Однак при короткочасному просіданні напруги живлення (англ. @@en|Brownout@@, від *brown* — тьмяний та *out* — вихід) виникає небезпека: конденсатор не встигає розрядитися через великий опір підтяжки `R = 10` кОм. Для прискорення скидання паралельно резистору підключають розрядний діод Шотткі (англ. @@en|Discharge Diode@@, від *discharge* — розряджати) анодом до лінії `RST`, а катодом до шини `V_DD`. Розрахунок часу розряду `t_discharge` ємності `C = 100` нФ через низький опір відкритого діода `R_D = 10` Ом до прямого падіння напруги `V_D = 0.3` В при падінні `V_DD` до нуля виконується за формулою:

```
t_discharge
= - R_D × C × ln(V_D ÷ V_DD)                  [визначення часу розряду через діод]
= - 10 × 100 × 10⁻⁹ × ln(0.3 ÷ 3.3)           [підстановка R_D = 10 Ом, C = 100 нФ, V_D = 0.3 В, V_DD = 3.3 В]
= - 10⁻⁶ × ln(0.0909)                          [перемноження опору та ємності]
= - 10⁻⁶ × (- 2.398)                          [обчислення логарифма ln(0.0909) ≈ -2.398]
≈ 2.4 × 10⁻⁶ с                                [підсумкове значення 2.4 мкс]
```

З отриманого результату видно, що розрядний діод скорочує час скидання з `2.88` мс до `2.4` мкс. Це гарантує повне зняття заряду з конденсатора під час імпульсних просідань живлення і запобігає зависанню засувок [конфігураційних виводів завантаження](root:cat-hw-boards/esp8266-boot-strapping-pins).

## Алгебра дільників тактування UART та швидкості

Після успішного завершення скидання первинний завантажувач у масовій пам'яті ПЗП (англ. @@en|Read-Only Memory@@, скорочено @@en|ROM@@, від *read* — читати, *only* — лише, *memory* — пам'ять) ініціалізує послідовний порт `UART0` для виводу системного діагностичного логу. Передача даних виконується з тактуванням від внутрішнього регістра дільника `UART_CLKDIV`. Швидкість передачі бітів у бодах (англ. @@en|baud@@, від прізвища інженера Жана Бодо) `Baud` визначається відношенням опорної частоти кварцового резонатора `f_xtal` до значення дільника `N_div`:

```
Baud = f_xtal ÷ N_div
```

Код ROM-завантажувача первинно розроблявся для опорної частоти резонатора `f_design = 40` МГц (`40000000` Гц) та стандартної швидкості `Baud_target = 115200` бод, під яку в код було зашито дільник `N_div`:

```
N_div = f_design ÷ Baud_target
= 40000000 ÷ 115200                        [ділення опорної частоти 40 МГц на цільову швидкість]
≈ 347.2222                                 [фіксований дільник у ROM]
```

Однак у масових модулях серій ESP-01 та ESP-12 виробники встановили кварцовий резонатор із частотою `f_actual = 26` МГц (`26000000` Гц). При використанні незмінного дільника `N_div ≈ 347.2222` фактична швидкість виводу початкового логу стає нестандартною:

```
Baud_actual = f_actual ÷ N_div
= 26000000 ÷ 347.2222                      [підстановка фактичної частоти 26 МГц]
= 74880 бод                                [фактична швидкість логу ROM]
```

Для коректного зчитування первинних текстових повідомлень завантажувача у системному терміналі необхідно примусово встановлювати швидкість `74880` бод. Відносна похибка обчислення між `74880` бод та `115200` бод становить:

На рівні апаратного регістра `UART_CLKDIV` дільник частоти складається з цілої та дробової частин (англ. @@en|fractional divider@@, від *fractional* — дробовий та *divide* — ділити). Дробовий коефіцієнт формується періодичним додаванням одного додаткового такту системного резонатора `f_actual`, що викликає фазове тремтіння моментів опитування бітів (англ. @@en|bit jitter@@, від *bit* — біт та *jitter* — тремтіння, флуктуація). Для визначення максимального фазового зміщення вибірки розраховують тривалість одного біта `T_bit`, період опорного такту `T_clk` та відносний джит `J_rel`:

```
T_bit = 1 ÷ Baud
= 1 ÷ 74880                                    [тривалість 1 біта при 74880 бод]
≈ 1.3355 × 10⁻⁵ с                              [13.355 мкс]

T_clk = 1 ÷ f_actual
= 1 ÷ 26000000                                 [період одного такту резонатора 26 МГц]
≈ 3.846 × 10⁻⁸ с                               [38.46 нс]

J_rel = T_clk ÷ T_bit × 100%
= (3.846 × 10⁻⁸) ÷ (1.3355 × 10⁻⁵) × 100%      [відношення такту резонатора до тривалості біта]
≈ 0.288%                                       [відносний фазовий джит вибірки]
```

З обчисленого результату видно, що максимальне часове відхилення між сусідніми бітами не перевищує `0.288%` від тривалості біта `13.355` мкс. Оскільки приймач UART виконує стробування сигналу посередині кожного бітового інтервалу, такий незначний джит є абсолютно безпечним і не призводить до зсуву фази стробування чи втрати синхронізації при прийомі кадрів за вказаним у [огляді мікроконтролера ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview) опорним тактуванням.

```
Error = (115200 - 74880) ÷ 115200 × 100%
= 40320 ÷ 115200 × 100%                    [різниця швидкостей]
= 35%                                      [похибка частоти]
```

Оскільки похибка `35%` значно перевищує допустимий допуск послідовної синхронізації UART у `2.5%`, спроба відкрити порт на швидкості `115200` бод під час старту 26-мегагерцового чипа призводить до відображення хаотичних нечитабельних символів.

## Алгоритмічний розрахунок контрольної суми CRC32

Перед передачею керування завантаженому виконуваному коду ROM-завантажувач перевіряє цілісність образу у флеш-пам'яті шляхом обчислення циклічного надлишкового коду (англ. @@en|Cyclic Redundancy Check@@, скорочено @@en|CRC32@@, від *cyclic* — циклічний, *redundancy* — надлишковість, *check* — перевірка). Математичний алгоритм спирається на ділення многочлена даних над скінченним полем Галуа `GF(2)` на стандартний утворювальний поліном IEEE 802.3:

```
P(x) = x³² + x²⁶ + x²³ + x²² + x¹⁶ + x¹² + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1
```

Побайтова процедура верифікації ініціалізує 32-бітний регістр накопичувача значенням `CRC_0 = 0xFFFFFFFF`. Для кожного байта даних `B_i` вектор стану оновлюється через операцію побітового виключного АБО (`XOR`) із використанням таблиці попередньо обчислених констант `Table_CRC`:

```
Index_i = (CRC_(i-1) XOR B_i) AND 0xFF
CRC_i = (CRC_(i-1) >> 8) XOR Table_CRC[Index_i]
```

Після обробки всіх `M` байтів корисного навантаження прошивки підсумкове значення інвертується `CRC_final = CRC_M XOR 0xFFFFFFFF` і порівнюється з 4-байтовою контрольною сумою `CRC_header`, записаною наприкінці бінарного заголовка:

```
Valid = (CRC_final ≡ CRC_header)
```

Якщо `Valid = 1`, ROM-завантажувач вважає прошивку неушкодженою і передає управління на початкову адресу вхідної точки `entry_point`. У разі невідповідності `Valid = 0` завантажувач зупиняє виконання та повторно переходить у режим очікування прошивки.

Коли обчислене значення не збігається з заголовочним (`Valid = 0`), @@en|ROM@@-завантажувач негайно зупиняє подальший розбір флеш-пам'яті, щоб запобігти виконанню пошкоджених інструкцій мікроконтролером. Первинна програма виводить діагностичне текстове повідомлення `csum err` у послідовний порт @@en|UART0@@ на розрахованій апаратній швидкості та автоматично переключає мікроконтролер у [аварійний режим завантаження](root:cat-hw-boards/esp8266-boot-modes) по @@en|UART@@. У цьому стані внутрішній алгоритм очікує на прийом нових кадрів прошивки через послідовний інтерфейс за допомогою спеціальних команд [прошивання ESP-01](root:cat-hw-boards/esp01-firmware-flashing), що дозволяє відновлювати працездатність пристрою навіть у разі повного пошкодження образу у флеш-пам'яті.
