## Проблема збоїв старту та вибору завантаження

Під час подачі живлення мікроконтролер ESP8266 може потрапити в нескінченне циклічне перезавантаження — @@en|boot loop@@ (від англ. *boot loop* — циклічне перезавантаження). Це відбувається через те, що процесорне ядро не має вбудованої флеш-пам'яті й після скидання мусить визначити, звідки зчитувати програмний код. Якщо напруга живлення зростає надто повільно або на сигнальних виводах виникає плаваючий потенціал через RC-затримки паразитної ємності, первинний завантажувач у зчитувальному вікні защеплення фіксує помилковий режим. Докладніше про апаратне забезпечення чипа описано в [архітектурі SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview).

## Первинний ROM-завантажувач та страпінг-виводи

Первинну ініціалізацію виконує незамінна мікропрограма в масочному ПЗУ — @@en|ROM Bootloader@@ (від англ. *Read-Only Memory Bootloader* — первинний завантажувач у постійній пам'яті). У момент зняття сигналу скидання завантажувач опитує @@en|strapping pins@@ (від англ. *bootstrap pins* — конфігураційні виводи завантаження) GPIO0, GPIO2 та GPIO15. Якщо виявлено комбінацію `0-1-1`, починається виконання прошивки зі зовнішньої Flash-пам'яті; комбінація `0-0-1` переводить кристал у режим @@en|UART download@@ (від англ. *Universal Asynchronous Receiver-Transmitter download* — завантаження через послідовний порт) для запису нового коду. При цьому системний лог виводиться на нестандартній швидкості 74880 бод. Параметри виводів деталізовано в [конфігураційних виводах завантаження](root:cat-hw-boards/esp8266-boot-strapping-pins) та [режимах завантаження ESP8266](root:cat-hw-boards/esp8266-boot-modes).

## Структура бінарного образу та відображення пам'яті

Після вибору старту з флеш-пам'яті завантажувач зчитує заголовок бінарного образу, який починається з сигнатурного байта `0xE9`. Заголовок містить адреси розміщення сегментів у оперативній пам'яті IRAM (інструкції) та DRAM (дані). Цілісність коду перевіряється побайтовим обчисленням контрольної суми. Для економії SRAM основний код програми не копіюється повністю, а виконується на місці — за принципом @@en|XIP@@ (від англ. *eXecute In Place* — виконання коду безпосередньо з пам'яті) через 16-кілобайтні сторінки підсистеми @@en|MMU@@ (від англ. *Memory Management Unit* — блок управління пам'яттю) та кеш-пам'ять ICACHE. Деталі програмування розкрито під час [прошиванні плати ESP-01](root:cat-hw-boards/esp01-firmware-flashing).

## Вторинний завантажувач та механізм FOTA-оновлень

Для підтримки оновлень у пристрої використовується вторинний завантажувач (наприклад, eBoot). Він розміщується на початку флеш-пам'яті та керує перемиканням між двома робочими слотами прошивки — `user1.bin` та `user2.bin`. Технологія @@en|FOTA@@ (від англ. *Firmware Over-The-Air* — оновлення прошивки по повітрю) завантажує новий бінарний файл у вільний слот, перевіряє його цілісність і лише після цього змінює прапорець завантаження. Сектори калібрування радіомодуля при цьому залишаються захищеними. Повний порядок бездротового запису висвітлено в [бездротовому оновленні FOTA](root:cat-hw-boards/esp8266-fota-update).

## Діагностика збоїв та апаратні схеми скидання

При виникненні аварійних ситуацій завантажувач виводить у послідовний порт код причини скидання `rst cause`. Значення `rst cause:1` вказує на спрацьовування апаратного сторожового таймера @@en|WDT@@ (від англ. *Watchdog Timer* — сторожовий таймер) через зациклення коду, а `rst cause:4` — на програмне скидання. Для автоматичного переведення чипа в режим прошивання застосовують схему на двох NPN-транзисторах, яка притягує лінії `RST` та `GPIO0` у відповідній часовій послідовності за сигналами DTR і RTS.
