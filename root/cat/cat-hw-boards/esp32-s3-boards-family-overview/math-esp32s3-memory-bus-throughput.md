## Пропускна здатність Quad та Octal SPI

Під час проєктування високонавантажених обчислювальних систем на базі [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller) вибір між 4-бітним інтерфейсом @@en|Quad SPI@@ (SDR, англ. @@en|Single Data Rate@@ — одинарна швидкість даних) та 8-бітним @@en|Octal SPI@@ (DDR, англ. @@en|Double Data Rate@@ — подвоєна швидкість даних) для зовнішньої Flash та @@en|PSRAM@@ (англ. @@en|Pseudo Static RAM@@, псевдостатична оперативна пам'ять, від грец. @@el|pseudes@@ — несправжній) безпосередньо визначає швидкість обміну даними.

Фізична пропускна здатність шини `R_raw` обчислюється як добуток тактової частоти `f_clk`, кількості паралельних ліній даних `N_lanes` та коефіцієнта передач за один такт `K_ddr`. У режимі Quad SPI (SDR) за один такт передається один біт на лінію (`K_ddr = 1`), тому для частоти `f_clk = 80` МГц та `N_lanes = 4` пропускна здатність становить:

```
R_raw_quad80 = (f_clk × N_lanes × K_ddr) ÷ 8
= (80 × 10⁶ × 4 × 1) ÷ 8
= 40.0 × 10⁶ Б/с             [пропускна здатність Quad SPI 80 МГц]
= 40.0 МБ/с
```

Перехід на 8-бітну шину Octal SPI у режимі DDR зчитує дані по обох зрізах тактового сигналу (`K_ddr = 2`). При тій самій частоті `f_clk = 80` МГц та `N_lanes = 8` фізичний потік зростає в чотири рази:

```
R_raw_octal80 = (80 × 10⁶ × 8 × 2) ÷ 8
= 160.0 × 10⁶ Б/с            [пропускна здатність Octal SPI 80 МГц]
= 160.0 МБ/с
```

При використанні максимальної тактової частоти `f_clk = 120` МГц у режимі Octal SPI (DDR) граничний потік досягає значення:

```
R_raw_octal120 = (120 × 10⁶ × 8 × 2) ÷ 8
= 240.0 × 10⁶ Б/с            [гранична пропускна здатність Octal SPI 120 МГц]
= 240.0 МБ/с
```

Однак реальна пропускна здатність `R_real` зменшується через службові накладні витрати на відправку командного байта `T_cmd`, адреси `T_addr` та фіксованих циклів очікування `T_dummy`. Коефіцієнт корисного використання шини `E_bus` для блоку даних розміром `L_block = 64` байти (розмір кеш-лінії) з оверхедом `L_overhead = 8` байтів обчислюється як:

```
E_bus = L_block ÷ (L_block + L_overhead)
= 64 ÷ (64 + 8)
= 64 ÷ 72
≈ 0.8889                    [ефективність використання шини ~ 88.89%]
```

Реальна пропускна здатність шини Octal SPI при 80 МГц з урахуванням оверхеду становить:

При зменшенні розміру блоку передачі до `L_block = 16` байтів (наприклад, при поодиноких вибірках некешованих даних) частка оверхеду службових циклів `L_overhead = 8` байтів суттєво зростає. Коефіцієнт ефективності шини `E_bus_16` знижується до `16 ÷ (16 + 8) = 16 ÷ 24 ≈ 0.6667` (66.67%), а реальна пропускна здатність @@en|Octal SPI@@ при 80 МГц падає до `160.0 × 0.6667 ≈ 106.7` МБ/с. Порівняно з блоками по 64 байти (`E_bus ≈ 88.89%`), втрати ефективності через кадрові накладні витрати збільшуються з 11.11% до 33.33%, що вимагає мінімізації дрібних транзакцій по зовнішній шині [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller).

Підвищення тактової частоти шини до `f_clk = 120` МГц збільшує теоретичну швидкість @@en|Octal SPI@@ (@@en|DDR@@) до `R_raw_octal120 = 240.0` МБ/с, однак при малих транзакціях розміром `L_block = 16` байтів падіння ефективності залишається пропорційно високим. З урахуванням коефіцієнта `E_bus_16 ≈ 0.6667` реальна пропускна здатність розраховується як:

```
R_real_octal120_16 = R_raw_octal120 × E_bus_16
= 240.0 × (16 ÷ 24)           [підстановка значення ефективності 66.67%]
= 240.0 × 0.6667
≈ 160.0 МБ/с                 [реальний потік Octal SPI 120 МГц при блоці 16 Б]
```

Отже, при дрібних транзакціях по 16 байтів шина на частоті 120 МГц забезпечує лише 160.0 МБ/с реального потоку, втрачаючи 80.0 МБ/с (рівно 33.33% від фізичної межі) на службові цикли. Це означає, що при неоптимальному розмірі вибірок робота [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller) на частоті 120 МГц дає лише незначний виграш порівняно з 80-мегагерцовою шиною при кадрах по 64 байти (`160.0` МБ/с проти `142.2` МБ/с), але ціною суттєво вищого динамічного енергоспоживання та підвищеного рівня випромінюваних завад.

```
R_real_octal80 = R_raw_octal80 × E_bus
= 160.0 × 0.8889
≈ 142.2 МБ/с                [реальний потік даних Octal SPI 80 МГц]
```

## Затримки кеш-пам'яті та граничний фреймрейт

Розрахована реальна швидкість шини безпосередньо впливає на затримку виконання інструкцій процесорними ядрами Xtensa LX7 на частоті `f_cpu = 240` МГц (період такту `T_cpu = 4.167` нс). При промаху кеш-пам'яті L1/L2 процесор зупиняє виконання потоку на час завантаження кеш-лінії обсягом `L_line = 64` байти з @@en|PSRAM@@.

*Схема розкладу пропускної здатності шини SPI та часових затримок промаху кешу L1/L2, з якої видно порівняння режимів Quad та Octal SPI.*

Час вибірки лінії кешу `t_fetch` та повна затримка промаху `t_miss` з урахуванням апаратної затримки активації контролера `t_access = 100` нс для Octal SPI при 80 МГц (`R_real = 142.2` МБ/с) становить:

При послідовній обробці масиву в циклі з `K = 100` послідовними промахами кешу (наприклад, при потоковому читанні блоку пам'яті @@en|PSRAM@@ обсягом 6.4 КБ) сумарний час простою процесорного ядра `T_stall_total` та загальна кількість втрачених тактів `N_stall_total` обчислюються так:

```
T_stall_total = K × t_miss
= 100 × (550 × 10⁻⁹)
= 55000 × 10⁻⁹ с              [сумарний час простою ядра]
= 55.0 мкс

N_stall_total = K × N_stall
= 100 × 132
= 13200 такти                [сумарні витрати тактів на очікування]
```

Якщо ідеальний час виконання арифметичних операцій у циклі становить `N_ideal = 2000` тактів, то фактичний час виконання зростає до `N_actual = 2000 + 13200 = 15200` тактів. Це спричиняє обчисливельне сповільнення алгоритму у `15200 ÷ 2000 = 7.6` раза виключно через затримки вибірки даних для процесорних ядер [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller).

```
t_fetch = L_line ÷ R_real
= 64 ÷ (142.2 × 10⁶)
≈ 450 × 10⁻⁹ с               [час вибірки кадрової лінії кешу]
= 450 нс

t_miss = t_access + t_fetch
= 100 + 450
= 550 нс                     [повна часова затримка промаху кешу]
```

Тривалість простою процесорного ядра в тактах `N_stall` обчислюється відношенням затримки `t_miss` до періоду такту `T_cpu`:

```
N_stall = t_miss ÷ T_cpu
= 550 × 10⁻⁹ ÷ (4.167 × 10⁻⁹)
≈ 132 такти                 [тривалість простою процесорного ядра]
```

Для завдань обробки відеопотоків із [камера-модуля ESP32-CAM](root:cat-hw-boards/esp32-cam) або виведення графіки на дисплей із роздільністю `320 × 240` пікселів у форматі RGB565 (`2` байти на піксель) обсяг одного кадру `S_frame` становить:

```
S_frame = 320 × 240 × 2
= 153600 байт                [обсяг одного кадру ~ 150 КБ]
```

Гранична частота оновлення кадрів `FPS_max` при передачі даних з [плати Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) для шини Quad SPI 80 МГц (`R_real ≈ 35.5` МБ/с) та Octal SPI 80 МГц (`R_real ≈ 142.2` МБ/с) обчислюється як:

Однак у реальних графічних і мультимедійних застосунках теоретична гранична частота кадрів вимагає коригування через необхідність подвійної буферизації (англ. @@en|double buffering@@). Для усунення зорових артефактів розриву зображення система виділяє в @@en|PSRAM@@ два окремих кадрових буфери — активний для зчитування контролером дисплея та фоновий для рендерингу нових даних. Для [плати Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) з роздільністю кадру `320 × 240` пікселів це подвоює необхідний обсяг пам'яті до `S_buf = 2 × 153600 = 307200` байт (близько `307.2` КБ), що забирає понад `15%` від загального обсягу `2` МБ @@en|PSRAM@@ і зменшує доступну оперативну пам'ять для інших завдань. Одночасний запис нового кадру та зчитування попереднього подвоює навантаження на шину пам'яті, створюючи арбітражні затримки між процесорними ядрами [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller) та периферійними каналами @@en|DMA@@. У результаті підсумковий реальний фреймрейт `FPS_real` для шини @@en|Quad SPI@@ знижується приблизно удвічі — до `115` кадрів/с, тоді як режим @@en|Octal SPI@@ зберігає високу планку близько `462` кадрів/с, забезпечуючи значний запас пропускної здатності для плавного оновлення інтерфейсу.

```
FPS_quad = (35.5 × 10⁶) ÷ 153600
≈ 231 кадрів/с               [максимальний фреймрейт для Quad SPI]

FPS_octal = (142.2 × 10⁶) ÷ 153600
≈ 925 кадрів/с               [максимальний фреймрейт для Octal SPI]
```

## Баланс виводів GPIO та питоме енергоспоживання

Окрім швидкісних характеристик, вибір конфігурації шини визначає кількість вільних периферійних виводів @@en|GPIO@@ (англ. @@en|General Purpose Input/Output@@ — ввід-вивід загального призначення). Кристал @@en|ESP32-S3@@ містить `45` фізичних виводів `N_gpio_total = 45`.

Стандартна шина Quad SPI займає `6` виводів (`CLK`, `CS`, `HD`, `WP`, `D0`, `D1`), тоді як Octal SPI вимагає `12` виводів (`CLK`, `CS`, `D0`–`D7`, `DQS`, `CS1`), що вилучає додатково `6` виводів `N_octal_extra = 6`. Кількість вільних ліній `N_gpio_free` обчислюється як:

```
N_gpio_quad = 45 - 6
= 39 виводів                 [вільні GPIO при Quad SPI]

N_gpio_octal = 45 - 12
= 33 виводи                  [вільні GPIO при Octal SPI]
```

Зменшення доступного ресурсу виводів становить `(39 - 33) ÷ 39 × 100% ≈ 15.38%`.

Динамічна потужність перезаряджання ємності шини `P_bus` залежить від ємності навантаження лінії `C_load = 15` пФ, напруги живлення `V_dd = 3.3` В, частоти `f_clk = 80` МГц та кількості активних ліній `N_lanes = 8`:

```
P_bus = N_lanes × (C_load × V_dd² × f_clk)
= 8 × (15 × 10⁻¹² × (3.3)² × 80 × 10⁶)
= 8 × (15 × 10⁻¹² × 10.89 × 80 × 10⁶)
≈ 0.1045 Вт                  [динамічна потужність шини ~ 104.5 мВт]
```

З урахуванням внутрішнього динамічного струму кристала @@en|PSRAM@@ `I_core = 40` мА сумарне питоме енергоспоживання `P_total` складає:

При живленні автономного вузла на базі [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller) від літій-полімерного акумулятора ємністю `C_bat = 1000` мА·год та урахуванні коефіцієнта корисної дії стабілізатора `η = 0.85` сумарний струм споживання підсистеми пам'яті `I_total` та тривалість автономної роботи `T_work` обчислюються так:

Окрім виснаження акумулятора, підвищення робочої частоти шини пам'яті до `f_clk = 120` МГц створює додаткове теплове навантаження на кристали всередині компактного корпусу @@en|SiP@@ (англ. @@en|System-in-Package@@ — система в корпусі). При безупинному обміні даними на частоті 120 МГц динамічна потужність перезаряджання ємності шини пам'яті `P_bus_120` зростає пропорційно частоті, а разом із внутрішнім споживанням процесорних ядер та кристала @@en|PSRAM@@ сумарне тепловиділення досягає `P_heat ≈ 0.35` Вт. За апаратної величини теплового опору перехід-довкілля `θ_JA ≈ 40` °C/Вт (англ. @@en|junction-to-ambient thermal resistance@@ — тепловий опір від напівпровідникового переходу до навколишнього середовища) підйом температури кристала `ΔT` відносно довкілля обчислюється як добуток виділюваної потужності на тепловий опір:

```
P_bus_120 = 8 × (15 × 10⁻¹² × (3.3)² × 120 × 10⁶)
= 8 × (15 × 10⁻¹² × 10.89 × 120 × 10⁶)    [підстановка підвищеної частоти 120 МГц]
≈ 0.1568 Вт                              [динамічна потужність шини Octal SPI на 120 МГц]

P_heat = P_bus_120 + P_core_120
= 0.1568 + 0.1932
= 0.3500 Вт                              [сумарна потужність тепловиділення ~ 350 мВт]

ΔT = P_heat × θ_JA
= 0.35 × 40
= 14 °C                                  [підвищення температури кристала над довкіллям]
```

Такий локальний перегрів на 14 °C для компактного [модуля Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) у герметичному корпусі або за підвищеної зовнішньої температури може наблизити кристал @@en|ESP32-S3@@ до межі терморегуляції, що вимагає передбачити пасивне тепловідведення чи обмежити граничну частоту обміну даними.

```
I_total = I_core + (P_bus ÷ V_dd)
= 40 + (0.1045 ÷ 3.3)
= 40 + 31.67
= 71.67 мА                   [загальний струм споживання пам'яті]

T_work = (C_bat × η) ÷ I_total
= (1000 × 0.85) ÷ 71.67
= 850 ÷ 71.67
≈ 11.86 годин                [тривалість автономного функціонування]
```

Отже, при безупинному обміні даними за шиною пам'яті в режимі пікового навантаження акумулятор ємністю 1000 мА·год забезпечує близько 11.86 годин безперервної роботи, після чого напруга джерела знижується до порогового рівня вимкнення.

```
P_total = P_bus + (V_dd × I_core)
= 0.1045 + (3.3 × 0.040)
= 0.1045 + 0.1320
≈ 0.2365 Вт                  [сумарна споживана потужність ~ 236.5 мВт]
```
