## Проблема вузьких місць шини SPI

Висока обчислювальна частота процесорного ядра (240 МГц для двоядерного Xtensa LX7 в чипі [Мікроконтролер ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller)) не забезпечує пропорційного прискорення розрахунків, якщо система вимушена тривалий час очікувати на надходження даних. У компактних модулях бездротового зв'язку фізичні габарити корпуса й обмежена кількість виводів унеможливлюють розведення широкої 32-бітної паралельної шини пам'яті. Через це зовнішня флеш-пам'ять та розширена оперативна пам'ять @@en|PSRAM (від англ. Pseudo-Static RAM — псевдостатична оперативна пам'ять)@@ підключаються до @@en|SoC (від англ. System-on-Chip — система на кристалі)@@ через послідовні шини SPI.

Доступ процесорних ядер до зовнішнього адресового простору реалізується через апаратний блок @@en|MMU (від англ. Memory Management Unit — блок керування пам'яттю)@@ та двоканальний L1-кеш (із виділеними обсягами ICache для інструкцій та DCache для даних). Коли виконуваний код або елементи масиву знаходяться у внутрішній статичній пам'яті SRAM, зчитування відбувається за один такт. Проте при зверненні до великих кадрових буферів або ваг нейромереж виникає ситуація, коли необхідного адресового блоку немає в кеші — @@en|cache miss (від англ. cache miss — промах кешу)@@.

При промаху L1-кешу процесорне ядро вимушене повністю зупинити конвеєр обчислень. Блок MMU формує запит до зовнішньої пам'яті, надсилає по послідовній шині код команди зчитування, адресу блоку, витримує такти очікування стабілізації та побайтово копіює новий 32-байтний або 64-байтний рядок кешу.

![Схема часових затримок при промаху L1-кешу MMU та зверненні до SiP PSRAM.](img/esp32s3-sip-cache-latency-pipeline.svg)
*Схема часових затримок при промаху L1-кешу MMU та зверненні до SiP PSRAM.*

Сумарна затримка доступу — @@en|latency (від англ. latency — часова затримка доступу)@@ — складається з затримки арбітражу шини, фази передачі команди, холостих тактів та безпосереднього зчитування даних. У двоядерній конфігурації чипа [Мікроконтролер ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller) додатковим джерелом втрат є міжядерний арбітраж: коли обидва ядра Xtensa LX7 одночасно звертаються до спільного контролера пам'яті, шинний матричний арбітр чергує їхні запити. При вибірці розширеного 64-байтного рядка L1-кешу `S_line = 64 байти` тривалість виконання базової транзакції зчитування зростає до `t_trans = 400 нс`. Усереднені часові втрати арбітражу `t_arb` та підсумкова затримка вибірки `t_total` за умов взаємної конкуренції двох активних ядер Xtensa LX7 обчислюються так:

t_arb = t_trans ÷ 2
      = 400 ÷ 2                           [усереднений час очікування вивільнення шини другим ядром]
      = 200 нс                            [додаткова затримка міжядерного арбітражу]

t_total = t_trans + t_arb
        = 400 + 200                        [сума базового часу передачі 64 байтів та затримки арбітражу]
        = 600 нс                            [підсумкова тривалість вибірки 64-байтного рядка L1-кешу]

Зростання підсумкової затримки до `t_total = 600 нс` означає, що при паралельній вибірці даних міжядерні затримки арбітражу створюють додаткові 33.3% часових втрат `t_arb ÷ t_total = 200 ÷ 600 = 0.333`, що пропорційно знижує реальну обчислювальну продуктивність процесорних ядер.

t_arb = t_trans ÷ 2
      = 200 ÷ 2             [усереднена затримка очікування завершення поточної транзакції іншим ядром]
      = 100 нс              [додаткові часові втрати міжядерного арбітражу]

t_total = t_trans + t_arb
        = 200 + 100         [сумування базового часу транзакції та затримки міжядерного арбітражу]
        = 300 нс            [підсумкова тривалість очікування вибірки за умов конкуренції двох ядер]

У модулях із @@en|SiP (від англ. System-in-Package — система у корпусі)@@-виконанням, як-от [Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare), короткі провідники всередині спільного корпуса зменшують паразитну ємність ліній, але послідовна природа шини SPI та міжядерні затримки все одно створюють апаратне «вузьке місце». Якщо пропускна здатність шини є недостатньою, процесор витрачає понад 60–70% робочого часу на очікування вибірки з пам'яті. Для запобігання простоям потрібна чітка математична модель розрахунку швидкодії шинного інтерфейсу.

## Модель пропускної здатності QSPI та OPI

Теоретична пропускна здатність послідовної шини пам'яті `B_theoretical` (у мегабайтах за секунду, МБ/с) визначається добутком тактової частоти шини `f_clk` (у мегагерцах, МГц), кількості паралельних ліній даних `N_lines` та коефіцієнта режиму передачі `M_mode`, поділеним на 8 (кількість бітів у байті).

Для режимів зчитування використовують дві основні модифікації тактування:
- @@en|SDR (від англ. Single Data Rate — одна передача за такт)@@: біти передаються лише по наростаючому фронту тактового сигналу (`M_mode = 1`).
- @@en|DDR (від англ. Double Data Rate — дві передачі за такт)@@: біти передаються по обох фронтах — наростаючому та спадаючому (`M_mode = 2`).

Загальна формула теоретичної пропускної здатності має вигляд:

```
B_theoretical = f_clk × N_lines × M_mode ÷ 8      [переведення бітів за секунду в мегабайти за секунду]
```

Розглянемо покроковий розрахунок для трьох стандартних конфігурацій шини ESP32-S3:

**1. Розрахунок для Quad SPI (QSPI) SDR на частоті 80 МГц (N_lines = 4, M_mode = 1)**
```
B_theoretical = 80 × 4 × 1 ÷ 8
              = 320 ÷ 8                           [добуток частоти на 4 лінії даних]
              = 40 МБ/с                           [теоретична пропускна здатність QSPI SDR]
```

**2. Розрахунок для Octal SPI (OPI) DDR на частоті 80 МГц (N_lines = 8, M_mode = 2)**
```
B_theoretical = 80 × 8 × 2 ÷ 8
              = 1280 ÷ 8                          [подвоєна частота вибірки по 8 лініях]
              = 160 МБ/с                          [теоретична пропускна здатність Octal DDR]
```

**3. Розрахунок для Octal SPI (OPI) DDR на граничній частоті 120 МГц (N_lines = 8, M_mode = 2)**
```
B_theoretical = 120 × 8 × 2 ÷ 8
              = 1920 ÷ 8                          [максимальна частота шини ESP32-S3]
              = 240 МБ/с                          [пікова теоретична пропускна здатність OPI DDR]
```

Передавання даних у часі між режимами QSPI та Octal SPI у SDR/DDR суттєво відрізняється щільністю упаковки бітів на кожен такт.

![Часова діаграма передавання даних по шинах QSPI та Octal SPI у режимах SDR і DDR.](img/esp32s3-spi-bandwidth-timing-diagram.svg)
*Часова діаграма передавання даних по шинах QSPI та Octal SPI у режимах SDR і DDR.*

Реальна пропускна здатність `B_real` завжди менша за теоретичну через накладні витрати протоколу @@en|overhead@@ (від @@en|overhead@@ — накладні витрати протоколу). Під час кожного зчитування ряду кешу контролер витрачає часові такти на передачу команди `T_cmd`, адреси `T_addr` та холостих тактів очікування `T_dummy`. Кількість холостих тактів `T_dummy` залежить від робочої частоти та часу стабілізації сигналів у пам'яті. Розглянемо порівняльний розрахунок ефективності `η` для зчитування 32-байтного блоку при командних фазах `T_cmd + T_addr = 4` тактам:

```
η_SDR(4) = 32 ÷ (4 + 4 + 32)
         = 32 ÷ 40                         [ефективність SDR при T_dummy = 4 тактів]
         = 0.800                           [80.0% використання шини у режимі SDR]

η_SDR(8) = 32 ÷ (4 + 8 + 32)
         = 32 ÷ 44                         [ефективність SDR при T_dummy = 8 тактів]
         ≈ 0.727                           [72.7% використання шини у режимі SDR]

η_DDR(4) = 16 ÷ (4 + 4 + 16)
         = 16 ÷ 24                         [ефективність DDR при T_data = 16 та T_dummy = 4]
         ≈ 0.667                           [66.7% використання шини у режимі DDR]

η_DDR(8) = 16 ÷ (4 + 8 + 16)
         = 16 ÷ 28                         [ефективність DDR при T_data = 16 та T_dummy = 8]
         ≈ 0.571                           [57.1% використання шини у режимі DDR]
```

Оскільки у режимі DDR тривалість передачі даних `T_data` скорочується вдвічі за кількістю тактів (з 32 до 16), частка холостих тактів `T_dummy` у загальному часі транзакції зростає. При збільшенні `T_dummy` з 4 до 8 тактів ефективність SDR знижується на 7.3%, тоді як у режимі DDR падіння ефективності складає 9.6%.

Коефіцієнт корисної дії шини `η` (ефективність) обчислюється як відношення часу передачі корисних даних `T_data` до повного тривалості транзакції:

```
η = T_data ÷ (T_cmd + T_addr + T_dummy + T_data)      [частка корисного часу передавання даних]
B_real = B_theoretical × η                             [фактична пропускна здатність]
```

При зчитуванні 32-байтного рядка кешу в режимі OPI DDR 80 МГц тривалість `T_data` становить 32 такти, а службові фази `T_cmd + T_addr + T_dummy` займають близько 8 тактів, що дає `η = 32 ÷ (8 + 32) = 0.8` (80% ефективності). Таким чином, реальний потік даних складає `B_real = 160 × 0.8 = 128 МБ/с`. Знання цієї величини є критичним при проєктуванні високошвидкісних пристроїв обробки відео, таких як модуляція відеопотоку у модулях [ESP32-CAM (OV2640 + microSD)](root:cat-hw-boards/esp32-cam).

**Розрахунок для 64-байтного рядка кешу в режимі OPI DDR на частоті 80 МГц (B_theoretical = 160 МБ/с)**

При збільшенні довжини вибірки рядка кешу з 32 до 64 байтів тривалість передачі корисного навантаження `T_data` зростає до 64 тактів, тоді як фіксовані службові фази `T_cmd + T_addr + T_dummy` залишаються незмінними й займають 8 тактів. Розрахунок коефіцієнта ефективності та фактичної пропускної здатності має вигляд:

```
η = 64 ÷ (8 + 64)
  = 64 ÷ 72                              [відношення корисних тактів до повного циклу]
  ≈ 0.889                                [88.9% ефективності використання шини]

B_real = 160 × 0.889
       ≈ 142.2 МБ/с                      [фактична пропускна здатність для 64-байтного рядка]
```

Збільшення розміру рядка кешу вдвічі амортизує постійні накладні витрати протоколу SPI, що підвищує ефективність використання шини майже на 9% та наближає реальну швидкість зчитування до теоретичного межі 160 МБ/с.

## Аналіз затримок та накладних витрат

Своєчасна вибірка даних із зовнішньої пам'яті залежить не лише від максимальної пропускної здатності фізичних ліній, а й від тривалості супутніх затримок на рівні шинного контролера та протоколу обміну — @@en|latency@@ (від англ. @@en|latency@@ — часова затримка відгуку). Кожна транзакція зчитування з SiP-інтегрованої пам'яті @@en|PSRAM@@ складається з двох послідовних фаз: фази передачі командно-адресного заголовка та фази безпосереднього пересилання корисного навантаження. Оскільки системна пам'ять кешується через блок @@en|MMU@@ (від англ. @@en|Memory Management Unit@@ — блок керування пам'яттю), промах кешу процесорного ядра (англ. @@en|cache miss@@) ініціалізує вибірку повного 32-байтового рядка L1-кешу.

Під час передачі командного заголовка шина витрачає фіксовану кількість тактів на відправлення коду операції (англ. @@en|opcode@@), адреси цільової комірки та витримування холостих тактів стабілізації — @@en|dummy cycles@@ (від англ. @@en|dummy cycles@@ — холості/технологічні такти затримки для фазового вирівнювання). У режимі Octal SPI @@en|DDR@@ (від англ. @@en|Double Data Rate@@ — подвійна швидкість передачі даних) передача 8-байтового заголовка займає 4 повних такти шини, після чого контролер витримує 10 холостих тактів для стабілізації стробу DQS. Час зчитання 32-байтового рядка кешу на частоті 80 МГц з урахуванням накладних витрат обчислюється покроково:

    N_cycles = 4 + 10 + 16 = 30 циклів        [сума командних, холостих та дата-тактів]
    T_clk = 1 / 80000000 = 12.5 нс             [період тактування шини 80 МГц]
    t_bus = 30 × 12.5 нс = 375 нс              [тривалість шинної транзакції]
    T_read = 375 нс + 25 нс = 400 нс           [підсумкова затримка з арбітражем MMU]

Розрахунок показує, що з 30 тактів шини лише 16 тактів витрачаються на корисні дані, а 14 тактів (майже 47% часу) становлять накладні витрати протоколу. Порівняно з дискретними мікросхемами на окремій друкованій платі, SiP-конфігурація в чипі [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32s3-microcontroller) виграє у швидкості завдяки мінімальній ємності внутрішніх мікропровідників (менше 2 пФ проти 15 пФ у зовнішнього монтажу), що дозволяє знизити арбітражний штраф `t_arb` з 60 нс до 25 нс. Крім того, на тривалість холостих тактів безпосередньо впливає фазовий зсув (англ. @@en|phase shift@@) стробу даних @@en|DQS@@ (від англ. @@en|Data Strobe@@ — строб даних). На високих частотах 80–120 МГц контролер шини вимагає вирівнювання фронтів DQS відносно тактового сигналу `CLK`: через розкид часу поширення сигналу в довгих зовнішніх трасах дискретних чипів доводиться збільшувати кількість холостих тактів `N_dummy` з 6 до 10 для формування безпечного часового вікна вибірки, що додає `4 × 12.5 нс = 50 нс` додаткової затримки на кожну транзакцію. У чипі @@en|SiP@@ мала довжина розварювання виводів забезпечує стабільність фази DQS із розфазуванням `Δt_dqs < 0.5 нс`, що дає змогу використовувати мінімальну кількість холостих тактів `N_dummy` без ризику збоїв зчитання даних.

## Розрахунок вимог під дисплеї та ШІ

Проєктування графічних та інтелектуальних embedded-систем вимагає попереднього розрахунку часового бюджету шини пам'яті для уникнення мерехтіння зображення або просідання частоти кадрів. Головним споживачем пропускної здатності в графічних пристроях є кадровий буфер — @@en|framebuffer@@ (від англ. @@en|framebuffer@@ — кадровий буфер), який зчитується контролером дисплея з фіксованою частотою оновлення.

Розглянемо приклад розрахунку необхідної пропускної здатності для кольорового TFT-дисплея з роздільною здатністю 480 × 320 пікселів у форматі RGB565 (2 байти на піксель) при частоті оновлення 60 Гц. Обсяг одного кадрового буфера та мінімальний безперервний потік даних обчислюються наступним чином:

    S_frame = 480 × 320 × 2 = 307200 байтів     [обсяг одного кадрового буфера]
    S_total = 307200 × 2 = 614.4 КБ           [подвійна буферизація double buffering]
    B_req = 307200 × 60 = 18432000 байтів/с    [мінімальний безперервний потік 18.43 МБ/с]

Якщо пристрій одночасно виконує нейромережеву модель @@en|TinyML@@ (від англ. @@en|Tiny Machine Learning@@ — компактне машинне навчання), яка зчитує 1 МБ вагових коефіцієнтів зі швидкістю 10 ітерацій на секунду (10 МБ/с), сумарне навантаження від дисплея та ШІ досягає 28.43 МБ/с. При використанні застарілих шин @@en|Quad SPI SDR@@ 40 МГц із реальним потоком близько 12–15 МБ/с система увійде в стан голодування шини (англ. @@en|bus starvation@@), що спричинить викривлення кадру. При підключенні паралельного сенсора камери, як на [модулі ESP32-CAM](root:cat-hw-boards/esp32-cam), що записує відеопотік у форматі @@en|YUV422@@ (2 байти на піксель) із роздільною здатністю 640 × 480 пікселів при 30 кадрах на секунду, вхідний потік даних додає суттєве навантаження на підсистему пам'яті. Розрахунок кадрового буфера камери та підсумкового часового бюджету шини виконується за формулами:

    S_cam = 640 × 480 × 2 = 614400 байтів          [обсяг одного кадру YUV422]
    B_cam = 614400 × 30 = 18432000 байтів/с        [потік камери 18.43 МБ/с]
    B_sum = 18.43 + 10.00 + 18.43 = 46.86 МБ/с     [сумарний потік дисплея, ШІ та камери]
    T_bus = (46.86 / 110) × 100% = 42.6%          [частка часового бюджету Octal SPI DDR]

Сумарний потік 46.86 МБ/с повністю перевищує можливості шини @@en|Quad SPI SDR@@, але застосування плати на кшталт [Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) з @@en|Octal SPI DDR@@ пам'яттю пропускною здатністю понад 110 МБ/с споживає лише 42.6% часового бюджету шини, залишаючи понад 57% ресурсу для фонових операцій @@en|Wi-Fi@@ та обробки промахів L1-кешу.
