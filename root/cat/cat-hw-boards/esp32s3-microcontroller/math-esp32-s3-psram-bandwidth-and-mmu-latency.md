## Проблема вичерпання смуги та затримок пам'яті

При розробці графічних систем та обробці потокового відео на мікроконтролерах інженери нерідко розраховують на номінальну пропускну здатність зовнішньої оперативної пам'яті, припускаючи, що передача даних відбувається безперервно з частотою тактування шини. Проте під час практичного виведення кадрового буфера високої роздільної здатності з псевдостатичної пам'яті (від англ. @@en|PSRAM@@, від @@en|Pseudo Static RAM@@ — псевдостатична оперативна пам'ять) на дисплей виникають артефакти кадрування та просідання частоти оновлення. Наприклад, на [платі Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) номінальна частота шини 80 МГц на папері обіцяє високий потік даних, але реальна швидкість виходить суттєво нижчою через приховані апаратні накладні витрати.

Причина відхилення дійсної швидкості від теоретичної полягає в тому, що кожна транзакція зчитування або запису супроводжується обов'язковими командними інтервалами, фазами передачі адреси та фіктивними тактами очікування (від англ. @@en|dummy cycles@@ — такти паузи для вирівнювання фази перед видачею даних). Крім того, центральний процесор звертається до зовнішньої пам'яті не безпосередньо, а через крок трансляції блоком керування пам'яттю (від англ. @@en|MMU@@, від @@en|Memory Management Unit@@ — модуль управління пам'яттю) та кеш-пам'ять першого рівня (від англ. @@en|L1 Cache@@ — швидка буферна пам'ять першого рівня). Кожен промах у кеші змушує шинний контролер перезавантажувати цілу кеш-лінію обсягом 32 або 64 байти, де розмір рядка безпосередньо визначає кількість системних транзакцій завантаження: при рядку у 32 байти для зчитування масиву виникає вдвічі більше окремих звернень із накладними витратами фаз команди та адреси, тоді як 64-байтний рядок зменшує кількість транзакцій удвічі за рахунок просторової локальності, але подвоює час блокування шини під час одного промаху. У разі витіснення модифікованих блоків до цього додається додатковий штраф на зворотне перезаписування («write-back»), тривалість якого так само пропорційна розміру кеш-лінії. Для точного прогнозування продуктивності необхідний факторний розрахунок дійсної пропускної здатності та затримок.

## Математична модель пропускної здатності Quad/Octal SPI

Для обчислення межі передачі даних через послідовний периферійний інтерфейс розраховують теоретичну пропускну здатність `B_th`, яка визначається частотою тактування шини `f`, шириною шини даних `w` у бітах та коефіцієнтом режимів передачі `m` (значення `m = 1` для режиму одинарної швидкості SDR, а `m = 2` для режиму подвійної швидкості DDR):

B_th = (f · w · m) ÷ 8      [переведення бітів у байти]

![Часова діаграма фаз транзакцій Quad SPI SDR та Octal SPI DDR із показаними командними інтервалами та тактами очікування dummy cycles](img/esp32-s3-qspi-opi-bus-timing.svg)
*Часова діаграма фаз транзакцій Quad SPI SDR та Octal SPI DDR із показаними командними інтервалами та тактами очікування dummy cycles.*

Реальний час виконання транзакції зчитування `N_data` байтів складається з фази команди тривалістю `T_cmd` тактів, фази адреси `T_addr` тактів, павзи очікування `T_dummy` тактів і фази передачі даних `T_data = (8 · N_data) ÷ (w · m)` тактів. Сумарна кількість тактів `T_total` обчислюється наступним чином:

T_total
= T_cmd + T_addr + T_dummy + T_data                   [сума тактів усіх фаз]
= T_cmd + T_addr + T_dummy + (8 · N_data) ÷ (w · m)   [підстановка тривалості фази даних]

Коефіцієнт корисної дії шини `η` визначається як відношення часу корисної передачі даних `T_data` до загального часу транзакції `T_total`:

η = T_data ÷ T_total      [частка корисних тактів у транзакції]

Розглянемо практичний приклад для [сімейства мікроконтролерів ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview). Обчислимо дійсну пропускну здатність шини Quad SPI SDR (`w = 4`, `m = 1`) на частоті `f = 80` МГц для зчитування блоку даних `N_data = 32` байти при `T_cmd = 8`, `T_addr = 6`, `T_dummy = 6`:

**Умова:** `f = 80` МГц, `w = 4` біти, `m = 1`, `N_data = 32` байти, `T_cmd = 8`, `T_addr = 6`, `T_dummy = 6`.

T_data = (8 × 32) ÷ (4 × 1) = 64      [тривалість фази даних у тактах]
T_total = 8 + 6 + 6 + 64 = 84          [загальна кількість тактів]
B_th = (80 × 10⁶ × 4 × 1) ÷ 8 = 40 × 10⁶ [теоретична межа в байтах на секунду]
η = 64 ÷ 84 ≈ 0.7619                   [коефіцієнт корисної дії шини]
B_eff = 40 × 0.7619 = 30.486           [дійна пропускна здатність у МБ/с]

Отже, при номінальній швидкості 40 МБ/с через апаратні накладні витрати фаз команди та паузи очікування дійсна пропускна здатність для 32-байтового блоку становить лише 30.486 МБ/с (ккд `η ≈ 76.2%`). При переході на 8-бітну шину Octal SPI DDR (`w = 8`, `m = 2`) на частоті 80 МГц теоретична швидкість досягає 160 МБ/с, а за рахунок паралельного введення адреси та даних коефіцієнт використання шини зростає до 90–94%.

Для гіпотетичного або перспективного розширення до 16-бітної шини @@en|Hexadectal SPI@@ (від грец. *ἕξ* — шість та *δέκα* — десять; @@en|Hexadectal SPI@@) у режимі @@en|DDR@@ (англ. @@en|Double Data Rate@@, від англ. *double* — подвійний + *data* — дані + *rate* — швидкість; `w = 16`, `m = 2`) на частоті 80 МГц теоретична межа пропускної здатності зростає у два рази порівняно з @@en|Octal SPI DDR@@ і обчислюється як:

```
B_th_16 = (80 · 10⁶ × 16 × 2) ÷ 8
= 320 · 10⁶             [теоретична межа 320 МБ/с]
```

Для блоку даних `N_data = 32` байти фаза даних займає `T_data = (8 × 32) ÷ (16 × 2) = 8` тактів, а при сумарних накладних витратах команд та фаз адресації `T_overhead = 12` тактів загальний час транзакції становить `T_total = 12 + 8 = 20` тактів (ККД `η = 8 ÷ 20 = 0.40` або 40%). Проте для великих пакетів даних кеш-ліній (наприклад, `N_data = 128` байтів, де `T_data = 32` такти) ККД шини зростає до `η = 32 ÷ 44 ≈ 0.727`, забезпечуючи дійсну швидкість `B_eff = 320 × 0.727 ≈ 232.6` МБ/с. Порівняно з класичним подвійним розширенням у [родині плат на ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview), 16-бітна шина забезпечує подвоєння пікового потоку, але вимагає виділення 16 окремих фізичних ліній даних, що створює компроміс між швидкістю та кількістю вільних контактів.

## Затримки L1-кешу, MMU та витіснення Write-Back

При зверненні ядра процесора до адресного простору PSRAM читання починається з перевірки наявності даних у квітучих лініях L1-кешу. Якщо вибірка потрапляє в кеш (від англ. @@en|cache hit@@ — влучання в кеш), затримка становить лише 1 такт процесорного ядра. Проте в разі відсутності даних (від англ. @@en|cache miss@@ — промах кешу) виникає довгий ланцюжок апаратних затримок.

![Схема послідовності обробки промаху L1-кешу та трансляції адресації MMU із висвітленням витіснення write-back і затримок арбітражу AXI](img/esp32-s3-l1-cache-mmu-miss-flow.svg)
*Схема послідовності обробки промаху L1-кешу та трансляції адресації MMU із висвітленням витіснення write-back і затримок арбітражу AXI.*

Сумарний часовий штраф промаху кешу `t_miss` обчислюється як сума затримки трансляції адреси блоком MMU `t_mmu`, арбітражу системної шини AXI між ядрами `t_arb`, часу скидання модифікованої кеш-лінії у зовнішню пам'ять `t_wb` (від англ. @@en|write-back penalty@@ — штраф зворотного запису) та часу вибірки нової лінії `t_fill`:

t_miss = t_mmu + t_arb + t_wb + t_fill      [загальна затримка промаху кешу]

Час зворотного запису модифікованого рядка довжиною `L_line` байтів `t_wb` та час його подальшого заповнення `t_fill` визначаються параметрами шини. Якщо рядок кешу чистий, значення `t_wb = 0`. Обчислимо затримку вибірки 32-байтового рядка кешу для Quad SPI SDR (частота 80 МГц) при промаху з витісненням «брудного» рядка:

**Умова:** `L_line = 32` байти, `t_mmu = 4` такти, `t_arb = 6` тактів, `t_wb = 76` тактів шини, `t_fill = 84` такти шини, співвідношення частоти ядра (240 МГц) до частоти шини (80 МГц) дорівнює `K_clk = 3`.

t_bus_total = 76 + 84 = 160                 [сума тактів шини для WB та Fill]
t_core_bus = 160 × 3 = 480                  [переведення тактів шини в такти ядра]
t_miss = 4 + 6 + 480 = 490                  [сумарний штраф у тактах ядра]

Таким чином, один промах L1-кешу з витісненням модифікованої лінії блокує виконання інструкцій ядра на 490 тактів процесора (понад 2 мікросекунди). При одночасному зверненні обох ядер @@en|Core 0@@ та @@en|Core 1@@ до @@en|PSRAM@@ через апаратні конфлікти системної шини @@en|AXI@@ затримка арбітражу `t_arb` суттєво зростає. Коли @@en|Core 1@@ ініціює зчитування в момент, коли @@en|Core 0@@ вже здійснює вибірку рядка кешу довжиною `L_line = 32` байти (`t_fill = 84` такти шини), арбітр призупиняє @@en|Core 1@@ на час повного завершення транзакції першого ядра:

```
t_arb = t_arb0 + t_fill × K_clk
= 6 + 84 × 3              [сума базової затримки та тривалості утримання шини першим ядром]
= 6 + 252                 [переведення 84 тактів шини в такти ядра з коефіцієнтом K_clk = 3]
= 258                     [штраф міжядерного арбітражу у тактах ядра]
```

У результаті затримка арбітражу зростає з базових 6 до 258 тактів процесора, що збільшує загальний штраф промаху кешу до 742 тактів і вимагає чіткого впорядкування доступу та оптимізації алгоритмів обходу масивів.

## Розрахунок граничного фреймрейту та розривів кадрів

Для виведення динамічного зображення на дисплейний модуль мікроконтролер формує графічний кадр у пам'яті та передає його через периферійний контролер. Для уникнення візуального артефакту розриву кадру (від англ. @@en|screen tearing@@ — розрив зображення через одночасне оновлення та зчитування кадрового буфера) застосовують режим подвійної буферизації. При цьому модуль прямого доступу до пам'яті (від англ. @@en|Direct Memory Access@@ — прямий доступ до пам'яті, або @@en|DMA@@) зчитує готовий перший буфер для відправки на дисплей, а ядро процесора паралельно будує наступний кадр у другому буфері. Якщо обидва кадрові буфери розміщені у зовнішній псевдостатичній пам'яті PSRAM, шина пам'яті повинна одночасно обслуговувати два інтенсивних потоки даних — зчитування для DMA та запис від процесора.

Обсяг одного кадрового буфера `V_frame` визначається добутком кількості пікселів по ширині `W` та висоті `H` на глибину кольору `bpp` (від англ. @@en|bytes per pixel@@ — кількість байтів на піксель, де `bpp = 2` для формату RGB565 та `bpp = 3` для RGB888):

`V_frame = W × H × bpp`

При подвійній буферизації загальний потік даних за один кадр становить `2 × V_frame`. Обчислимо максимальну частоту оновлення кадрів `FPS_max` з рівності доступної ефективної пропускної здатності `B_eff` та необхідного потоку даних подвійного буфера:

```
B_eff = 2 × W × H × bpp × FPS_max      [баланс пропускної здатності для подвійної буферизації]
FPS_max = B_eff ÷ (2 × W × H × bpp)     [ділення обидвох частин на обсяг транзакцій двох буферів]
```

Отримана формула показує, що гранична частота оновлення кадрів обернено пропорційна роздільності екрана та глибині кольору і прямо пропорційна ефективній пропускній здатності шини.

**Умова:** Розглянемо дисплей з роздільністю 480×320 пікселів у колірному форматі RGB565 (`bpp = 2` байти) на [платі Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) з Quad SPI PSRAM на частоті 80 МГц, що надає ефективну пропускну здатність `B_eff = 32` МБ/с (33 554 432 байт/с).

```
V_frame = 480 × 320 × 2 = 307200 байт       [обсяг одного кадрового буфера]
V_double = 2 × 307200 = 614400 байт         [сумарний обсяг даних двох буферів за один кадр]
FPS_max = 33554432 ÷ 614400 ≈ 54.61 Гц      [максимальна частота кадрів без розривів]
```

Розрахунок свідчить, що чотирипровідна шина Quad SPI на [модулях на ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) забезпечує частоту до 54 кадрів/с для роздільності 480×320 при RGB565. Збільшення роздільності до 800×480 при 24-бітному кольорі RGB888 потребуватиме понад 138 МБ/с пропускної здатності, що робить неминучим перехід на восьмипровідну шину Octal SPI DDR.

Для усунення блокувальних затримок чекання вертикальної синхронізації (від англ. @@en|VSYNC@@ — вертикальний синхроімпульс) застосовують потрійну буферизацію (від англ. @@en|triple buffering@@ — використання трьох графічних буферів). У цій схемі один буфер відображається через DMA, другий заповнюється процесором, а третій утримує останній готовий кадр, що вимагає одночасного обслуговування трьох обсягів даних `3 × V_frame` за один графічний цикл. Обчислимо потрібну пропускну здатність шини пам'яті та граничну частоту кадрів `FPS_max` при використанні потрійної буферизації:

```
B_eff = 3 × W × H × bpp × FPS_max      [баланс пропускної здатності при потрійній буферизації]
FPS_max = B_eff ÷ (3 × W × H × bpp)     [визначення частоти кадрів з обсягу трьох буферів]
```

Отримана залежність показує, що потрійна буферизація збільшує навантаження на шину пам'яті у 1.5 раза порівняно з подвійною буферизацією.

**Умова:** Розглянемо виведення зображення роздільністю 480×320 у форматі RGB565 (`bpp = 2` байти) з потрійною буферизацією при ефективній пропускній здатності `B_eff = 32` МБ/с (33 554 432 байт/с).

```
V_triple = 3 × 480 × 320 × 2 = 921600 байт      [сумарний обсяг даних трьох буферів на кадр]
FPS_max = 33554432 ÷ 921600 ≈ 36.41 Гц          [гранична частота кадрів при потрійній буферизації]
```

Виведення підтверджує, що усунення мікрозатримок рендерингу ціною потрійної буферизації знижує граничну частоту кадрів для роздільності 480×320 з 54.61 Гц до 36.41 Гц на шині Quad SPI, що вимагає врахування цього пропускного ліміту при проєктуванні графічного інтерфейсу.

## Оптимізація доступу до масивів методом Tiling

При обробці двовимірних графічних буферів чи матриць даних у PSRAM порядок обходу елементів суттєво впливає на продуктивність через архітектуру кешу L1 та блоку керування пам'яттю MMU. Матриці зберігаються у пам'яті послідовно по рядках (від англ. @@en|row-major@@ — порядкове розміщення). Зчитування одного елемента завантажує в кеш суцільну лінійку розміром `L_line = 32` байти. Якщо програма обробляє зображення по стовпчиках (від англ. @@en|column-major@@ — постовпчиковий обхід), кожен наступний крок циклу адресує пам'ять із кроком у цілий рядок `W × bpp` байтів. Оскільки цей крок значно перевищує розмір кеш-лінії, кожне звернення спричиняє промах кешу (від англ. @@en|cache miss@@ — відсутність даних у кеші) та викликає затримку вибірки `t_miss` з перезавантаженням сторінок MMU.

Для усунення цього штрафу застосовують метод блокового обходу (від англ. @@en|tiling@@, або @@en|blocking@@ — розбиття на підмасиви). Матриця розміром `N × N` ділиться на квадратні блоки (плитки) розміром `T × T` елементів так, щоб обсяг даних блока повністю вміщався в кеш-пам'ять @@en|L1-кеш@@ (від англ. @@en|Level 1 cache@@ — кеш першого рівня) без витіснення суміжних ліній. Граничний розмір плитки `T` математично визначається через загальний обсяг кешу `S_cache`, асоціативність його каналів `W_assoc` (англ. @@en|set associativity@@ — асоціативність множин кешу) та розмір одного елемента `bpp` (байтів на елемент). Щоб запобігти конфліктним витісненням усередині n-канальних множин, сумарний обсяг блока `T² × bpp` не повинен перевищувати ефективний обсяг одного каналу кешу `S_cache ÷ W_assoc`. Рівняння межі квадратного блока `T` має вигляд:

        T² × bpp ≤ S_cache ÷ W_assoc
        T ≤ √((S_cache ÷ W_assoc) ÷ bpp)      [залежність розміру плитки від асоціативності та обсягу кешу]

Для 32-кілобайтового кешу пам'яті `S_cache = 32768` байтів із 4-канальною асоціативністю `W_assoc = 4` та 32-бітними елементами `bpp = 4` байти допустима межа становить `T ≤ √(8192 ÷ 4) = √2048 ≈ 45.25`, що робить вибір `T = 32` (або `T = 16`) оптимальним для заповнення ліній без колізій. Обчислимо кількість промахів кешу `N_miss_tile` при обході блоками розміру `T × T` елементів у порівнянні з наївним обходом:

```
N_miss_tile = (N ÷ T)² × (T² ÷ (L_line ÷ bpp))    [розбиття на (N/T)² блоків з використанням завантажених ліній]
= N² ÷ (L_line ÷ bpp)                             [спрощення рівняння до відношення елементів до кеш-лінії]
```

З виведеної формули видно, що блоковий обхід зменшує кількість промахів кешу у `L_line ÷ bpp` разів порівняно з постовпчиковим обходом.

**Умова:** Розглянемо обробку графічного масиву розміром 512×512 32-бітних пікселів (`bpp = 4` байти) у PSRAM. Довжина лінії кешу `L_line = 32` байти (містить 8 пікселів), затримка промаху кешу з урахуванням MMU становить `t_miss = 200` нс. Потрібно обчислити штраф затримки при постовпчиковому обході та при застосуванні блоків `T = 16`.

```
N_total = 512 × 512 = 262144 елементів            [загальна кількість елементів масиву]
N_miss_naive = 262144                             [промахи кешу при наївному постовпчиковому обході]
T_latency_naive = 262144 × 200 × 10⁻⁹ = 0.0524 с  [суммарний штраф затримки промахів кешу]
N_miss_tile = 262144 ÷ 8 = 32768                   [промахи кешу при блоковому обході]
T_latency_tile = 32768 × 200 × 10⁻⁹ = 0.00655 с   [оптимізований штраф затримки кешу]
```

Застосування блокового обходу зменшує сумарну затримку вибірки даних з 52.4 мс до 6.55 мс (у 8 разів), локалізуючи звернення в межах завантажених ліній кешу L1 та запобігаючи частим перезавантаженням сторінок MMU.
