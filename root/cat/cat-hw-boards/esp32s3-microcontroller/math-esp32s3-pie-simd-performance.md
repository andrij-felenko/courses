## Обмеження скалярних обчислень у мікроконтролерах

Обробка потокових даних — таких як вибірки аудіосигналу чи кадрів зображення з камери у [модулі ESP32-CAM](root:cat-hw-boards/esp32-cam-camera-module-family) — вимагає виконання масивних циклічних обчислень. Базовою математичною операцією цифрової обробки сигналів та згорткових нейромереж є множення з накопиченням @@en|MAC@@ (від англ. @@en|Multiply-Accumulate@@ — множення з накопиченням). Спроба нарощувати швидкодію скалярного обчислення через підйом тактової частоти `f_cpu` понад 240 МГц наражається на електричний бар'єр у структурі @@en|CMOS@@ (від англ. @@en|Complementary Metal-Oxide-Semiconductor@@ — доповняльний метал-оксид-напівпровідник): динамічна потужність `P_dyn = C_load × V_dd² × f_cpu` зростає квадратично від напруги живлення ядра `V_dd`, яку доводиться піднімати для збереження тактів перемикання затворів. Це викликає лавиноподібне зростання теплового пакета й струмів витоку, що робить розгін за частотою неможливим. У 7-стадійному конвеєрі процесора Xtensa LX7 виконання скалярної операції @@en|MAC@@ вимагає послідовних команд завантаження операндів `a[i]` та `b[i]` із пам'яті в скалярні регістри `AR`, апаратної арифметичної обробки та команд керування циклом (інкремент індексу й перевірка умови переходу). У результаті на обробку одного елемента витрачається 4–6 тактів процесора, а підсумковий час обчислення визначається як `T_scalar = N × (t_load + t_mac + t_loop)`, де більша частина часу витрачається на накладні операції обслуговування циклу. Традиційний скалярний підхід обробляє один елемент масиву за один крок:

```
MAC_scalar = a[i] × b[i] + accumulator
```

При частоті дискретизації аудіо `f_s = 44100` Гц та розмірі фільтра `N = 256` коефіцієнтів скалярний процесор мусить виконувати понад 11.3 мільйона операцій на секунду лише на один канал. Якщо ж мова йде про обробку кадрів нейромережею TinyML на [платах із родини ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview), обсяг обчислень сягає сотень мільйонів операцій. Оскільки скалярний конвеєр процесора обмежений вибіркою однієї інструкції за такт, подальше підвищення продуктивності через збільшення тактової частоти впирається в ліміти енергоспоживання. Єдиним ефективним шляхом розв'язання цієї проблеми є паралелізація обчислень на рівні векторного апарату.

## Математична модель 128-бітної векторизації PIE

Для подолання скалярного бар'єра [чип ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) та його процесорну архітектуру @@en|Xtensa LX7@@ оснащено 128-бітним апаратним векторним розширенням @@en|PIE@@ (від англ. @@en|Processor Instruction Extensions@@ — розширення інструкцій процесора), що реалізує парадигму @@en|SIMD@@ (від англ. @@en|Single Instruction Multiple Data@@ — одна інструкція — багато даних). Векторний регістровий файл складається з восьми 128-бітних регістрів `Q0`–`Q7`. Розрахунок теоретичної продуктивності для 16-бітних векторних операцій @@en|MAC@@ при розрядності `b = 16` дає `N_p = 128 ÷ 16 = 8` паралельних елементів у регістрі; при тактовій частоті ядра `f_cpu = 240` МГц теоретична межа становить `P_16bit = 8 × 240 · 10⁶ = 1920 · 10⁶` MAC/s або 1.92 GMAC/s. Щоб запобігти викривленню обчислень при сумуванні добутків, математична модель сопроцесора передбачає розширення розрядності акумулятора (від англ. @@en|accumulator bit-width expansion@@ — розширення розрядності акумулятора): при множенні 8-бітних операндів добутки розрядністю 16 бітів накопичуються у 32-бітній проміжній сітці (а для 16-бітних операндів — у 32- чи 40-бітній), усуваючи апаратне переповнення (від англ. @@en|overflow@@ — переповнення). При згортанні підсумкового значення у вихідну розрядність застосовується арифметичне насичення (від англ. @@en|saturation arithmetic@@ — арифметичне насичення), яке обмежує результат граничними значеннями діапазону замість циклічного зрізання старших бітів.

Математично 128-бітний вектор `Q` представляє собою впорядкований масив елементів одинакової розрядності `b` бітів. Число паралельних елементів `N_p` у одному векторі визначається співвідношенням:

```
N_p = 128 ÷ b
```

Для 8-бітних даних `b = 8` вектор вміщує `N_p = 128 ÷ 8 = 16` елементів, а для 16-бітних даних `b = 16` — відповідно `N_p = 128 ÷ 16 = 8` елементів. Векторна інструкція `ee.vld.128` завантажує за один такт одразу `N_p` значень, після чого паралельний суматор-помножувач здійснює векторне множення з накопиченням. Теоретичне прискорення `S_th` відносно скалярного виконання виражається формулою:

```
S_th = N_p × f_cpu
= (128 ÷ b) × f_cpu      [підстановка кількості паралельних каналів N_p]
```

При тактовій частоті ядра `f_cpu = 240` МГц теоретична продуктивність для 8-бітних векторних операцій MAC становить:

```
P_8bit = 16 × 240 · 10⁶
= 3840 · 10⁶ MAC/s       [множення кількості елементів на тактову частоту]
= 3.84 GMAC/s            [переведення в гіга-операції]
```

## Розрахунок утилізації та штрафів конвеєра

У реальному фізичному кристалі [чипів ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) теоретична межа швидкодії знижується через накладні витрати на вибірку інструкцій, підготовку адресних покажчиків та затримки конвеєра (@@en|pipeline stalls@@). Зокрема, структура накладних витрат `T_overhead` включає фіксовані штрафні такти на ініціалізацію векторизованих циклів апаратними інструкціями @@en|LOOP@@: хоча апаратний цикл усуває переходи на кожній ітерації, попереднє завантаження лічильника й адресних межевих регістрів вимагає 2–3 початкових такти процесора, що помітно знижує утилізацію при обробці коротких векторних масивів. Підсумковий коефіцієнт утилізації конвеєра `η` визначається математичною відносною формулою:

```
η = T_exec ÷ (T_exec + T_stall + T_overhead)
```

де `T_exec` — корисний час виконання векторних обчислень, `T_stall` — затримки очікування даних із пам'яті, а `T_overhead` — такти на налаштування циклу.

Якщо масив вирівняно некоректно, завантаження 128-бітного вектора вимагає двох додаткових тактів для зсуву та вирівнювання за межею шини, що знижує коефіцієнт утилізації `η` з 0.95 до 0.62.

Для мінімізації накладних витрат `T_overhead` та підвищення коефіцієнта утилізації конвеєра застосовують розгортання циклів (англ. @@en|loop unrolling@@). Якщо для обробки масиву з `N` векторних блоків обрано коефіцієнт розгортання `k`, керуючі інструкції циклу виконуються один раз на `k` ітерацій, що виражається залежністю накладних витрат:

```
T_overhead(k) = (N ÷ k) × t_ctrl + T_setup
```

де `t_ctrl` — такти на перевірку умови й зміну покажчиків адреси, а `T_setup` — фіксований час ініціалізації циклу. Оптимальне значення `k` шукають шляхом мінімізації питомих витрат на один вектор `t_overhead_elem`:

```
t_overhead_elem(k) = T_overhead(k) ÷ N
= (t_ctrl ÷ k) + (T_setup ÷ N)      [ділення на N]
```

Зі зростанням `k` доданок `t_ctrl ÷ k` прямує до нуля, проте верхня межа `k` обмежена апаратною кількістю векторних регістрів чипа ESP32-S3. Оскільки перевищення доступної кількості регістрів спричиняє тиск на регістровий файл (англ. @@en|register pressure@@) і вимагає скидання даних у оперативну пам'ять, оптимальний коефіцієнт `k_opt` визначається граничною умовою `k × r_iter ≤ R_max`, де `r_iter` — кількість регістрів на один векторний блок, а `R_max = 8` — загальна кількість 128-бітних регістрів. Для ядра Xtensa LX7 це дає оптимальне значення `k_opt = 4`, яке знижує накладні витрати `T_overhead` на 75% без штрафів скидання даних.

## Модель впливу пам'яті та кешу

Векторний конвеєр PIE живиться даними з внутрішньої оперативної пам'яті SRAM або через зовнішню оперативну пам'ять @@en|PSRAM@@. Доступ до зовнішньої PSRAM проходить через кеш першого рівня @@en|L1 DCache@@ та шину Octal SPI. Реальна продуктивність `P_real` виражається з урахуванням ймовірності кеш-промаху `p_miss`:

```
P_real = P_th ÷ (1 + p_miss × Latency_miss)
```

Середня затримка при кеш-промаху `Latency_miss` для 8-бітної шини Octal SPI на [модулях Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) становить 32 такти процесора. Розрахунок реальної швидкодії при `p_miss = 0.05` (5% кеш-промахів):

```
P_real
= 3.84 ÷ (1 + 0.05 × 32)                   [підстановка теоретичної швидкодії та 5% промахів]
= 3.84 ÷ (1 + 1.6)                         [обчислення штрафу за кеш-промахи]
= 3.84 ÷ 2.6                               [додавання базового такту]
≈ 1.477 GMAC/s                             [підсумкова ефективна продуктивність]
```

Звідси видно, що навіть 5% кеш-промахів знижують ефективну швидкодію векторного апарату більш ніж удвічі.

**Приклад покрокового розрахунку швидкодії при високому відсотку кеш-промахів (10%):**

При некоректній організації фрагментованих векторних масивів у зовнішній пам'яті або відсутності локальності звернень частка кеш-промахів зростає до `p_miss = 0.10` (10%).

```
P_real_10
= P_th ÷ (1 + p_miss × Latency_miss)        [формула реальної продуктивності з урахуванням затримок]
= 3.84 ÷ (1 + 0.10 × 32)                   [підстановка теоретичної швидкодії 3.84 GMAC/s та 10% промахів]
= 3.84 ÷ (1 + 3.2)                         [обчислення коефіцієнта затримки шини Octal SPI]
= 3.84 ÷ 4.2                               [сумування тактового нормативу з штрафним множником]
≈ 0.914 GMAC/s                             [підсумкова ефективна швидкодія при 10% промахів]
```

Висновок: зростання частки кеш-промахів до 10% знижує продуктивність обчислювального конвеєра до `0.914 GMAC/s`, що становить менше `24%` від теоретичного піку `3.84 GMAC/s` і призводить до понад чотириразового падіння обчислювальної потужності векторного ядра.

```
P_real = P_th ÷ (1 + p_miss × Latency_miss)
```

```
P_real = 3.84 ÷ (1 + 0.05 × 32)
= 3.84 ÷ (1 + 1.6)        [обчислення штрафу за кеш-промахи]
= 3.84 ÷ 2.6              [додавання базового такту]
≈ 1.477 GMAC/s            [підсумкова ефективна продуктивність]
```

Звідси видно, що навіть 5% кеш-промахів знижують ефективну швидкодію векторного апарату більш ніж удвічі.

## Оцінка часу інференсу моделей TinyML

Для визначення придатності мікроконтролера ESP32-S3 до завдань штучного інтелекту @@en|TinyML@@ (від англ. @@en|Tiny Machine Learning@@ — компактне машинне навчання) використовують підсумкову модель часу виконання шару нейромережі `t_layer`. Залежно від типу шару обчислюють повну кількість операцій множення з накопиченням @@en|MAC@@: для повнозв'язаного шару @@en|Dense@@ (від англ. @@en|Dense Layer@@ — повнозв'язаний шар) із `N_in` вхідними елементами та `N_out` вихідними нейронами обсяг операцій становить `N_mac = N_in × N_out`, тоді як для згорткового шару з `K` фільтрами розміром `W × H` над вхідною матрицею розміром `C_in × X × Y` загальне число необхідних MAC-операцій `N_mac` становить:

```
N_mac = K × C_in × W × H × X × Y
```

Підставивши знайдене значення продуктивності `P_real`, обчислюємо необхідний час розрахунку шару:

```
t_layer = N_mac ÷ P_real
```

Розрахуємо час виконання згорткового шару з `N_mac = 14.77` мільйонів операцій при `P_real = 1.477` GMAC/s:

```
t_layer = (14.77 · 10⁶) ÷ (1.477 · 10⁹)
= 0.010 s                [ділення кількості операцій на продуктивність]
= 10 ms                  [переведення у мілісекунди]
```

Таким чином, повна оцінка часу обробки дозволяє завчасно розраховувати максимальну частоту кадрів обробки зображень (до 100 кадрів на секунду для даної нейромережі) та будувати збалансовані алгоритми реального часу.
