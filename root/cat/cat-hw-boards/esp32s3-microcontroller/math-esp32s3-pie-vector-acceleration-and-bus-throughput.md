## Обчислювальний бар'єр скалярних алгоритмів TinyML

Обробка потокових аудіосигналів та тензорів зображень у завданнях @@en|TinyML@@ (від англ. *tiny machine learning* — мікроскопічне машинне навчання) вимагає виконання мільйонів послідовних математичних операцій за чітко обмежений часовий інтервал. У класичних мікроконтролерних архітектурах обробка векторів реалізується через скалярний цикл, у якому кожна пара елементів обробляється послідовно за допомогою інструкції @@en|MAC@@ (від англ. *Multiply-Accumulate* — множення з накопиченням).

Кожна ітерація скалярного циклу складається з послідовної вибірки операндів із пам'яті, обчислення добутку, додавання результату до акумулятора та декременту лічильника циклу з перевіркою умови переходу. Накладні витрати на управління циклом `t_loop` включають інкремент індексу та умовний стрибок, забираючи 2 процесорні такти на кожен елемент, що дорівнює сумарному часу самих арифметичних операцій `t_mul + t_add = 2`. Якщо вектор має довжину `N`, то загальна кількість процесорних тактів `T_scalar` для його обробки обчислюється як сума витрат на управління циклом та безпосередні обчислення:

T_scalar = N · (t_fetch + t_mul + t_add + t_loop)
= N · (2 + 1 + 1 + 2)      [сумування процесорних тактів на один елемент]
= 6 · N                    [загальна кількість тактів для скалярного обчислення]

Зокрема, для короткого вектора довжиною `N = 16` елементів виконання скалярного циклу вимагає `6 · 16 = 96` тактів, з яких 32 такти витрачаються виключно на службові переходи `t_loop`. Для довшого вектора `N = 256` витрати зростають пропорційно до 1536 тактів, де 512 тактів ідуть на управління циклом, демонструючи стійкі 33.3% продуктивності ядра, втрачені на перевірку умов замість корисних обчислень.

Ситуація ускладнюється, коли обсяг тензорів перевищує розмір внутрішньої статичної пам'яті SRAM і дані розміщуються у зовнішній @@en|PSRAM@@ (від англ. *Pseudo Static RAM* — псевдостатична оперативна пам'ять). У цьому випадку до кожного процесорного такту обчислень додається затримка звернення до зовнішньої шини `t_mem_delay`. При поелементному скалярному читанні процесорне ядро більшість часу простоює в очікуванні готовності шини, через що реальний час обробки зростає в рази.

Математично це утворює обчислювальний бар'єр: зростання частоти скалярного ядра не здатне компенсувати часову складність `O(N)` при високих затримках шини пам'яті. Для подолання цього бар'єра необхідно одночасно підвищити щільність обчислень на один такт за допомогою @@en|SIMD@@ (від англ. *Single Instruction, Multiple Data* — одна інструкція, багато даних) та забезпечити пакетну вибірку даних із пам'яті, що мінімізує оверхед шинного арбітражу.

У мікроконтролерах на кшталт [родини плат на ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) таке поєднання досягається впровадженням 128-бітних векторних регістрів прискорювача @@en|PIE@@ (англ. @@en|Processor Instruction Extension@@) та 8-бітної шини @@en|Octal SPI@@. Паралельна обробка кількох операндів за один такт скорочує обчислювальний цикл, а конвеєризація вибірки зменшує відносний вплив затримок `t_mem_delay`, трансформуючи лінійний оверхед скалярних обчислень у високоефективний потоковий режим.

## Математична модель векторних інструкцій PIE

Для прискорення математичних обчислень у [родині плат ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) застосовується векторне розширення ядра Xtensa LX7 під назвою @@en|PIE@@ (від англ. *Processor Instruction Extensions* — розширення інструкцій процесора). Архітектура PIE надає 128-бітні векторні регістри, які дозволяють пакувати та паралельно обробляти декілька цілочисельних даних за один процесорний такт.

Кількість елементів `P`, які пакуються в один 128-бітний регістр, залежить від розрядності даних. Для 8-бітних чисел зі знаком (`int8`) та 16-бітних чисел (`int16`) коефіцієнт пакування обчислюється наступним чином:

P_8 = 128 / 8 = 16        [кількість 8-бітних елементів у векторі]
P_16 = 128 / 16 = 8       [кількість 16-бітних елементів у векторі]

Апаратний прискорювач PIE містить паралельні обчислювальні блоки MAC, здатні виконувати векторні операції за один такт `t_vmac = 1`. Щоб запобігти цикловому переповненню розрядної сітки при паралельному сумуванні добутків, у блоках MAC застосовується арифметика з насиченням (@@en|saturation arithmetic@@). При досягненні граничних значень діапазону (наприклад, +127 або -128 для 8-бітних чисел зі знаком `int8`) результат не циклується до протилежного знака, а фіксується на верхній чи нижній межі. Крім того, проміжні результати накопичуються у розширених 32-бітних регістрах акумулятора, утримуючи точність перед остаточною квантизацією. Загальний час виконання векторної обробки `T_vector` для масиву розміром `N` елементів з урахуванням налаштування конвеєра `t_overhead` виражається формулою:

T_vector = (N / P) · t_vmac + t_overhead
= (N / 16) · 1 + t_overhead      [для 8-бітних векторів при P = 16]
= N / 16 + t_overhead            [кількість тактів при конвеєрній обробці]

*Схема тактування та конвеєризації векторних інструкцій PIE порівняно зі скалярним циклом.*

Теоретичний коефіціент прискорення `S_vector`, який забезпечує векторний прискорювач PIE порівняно зі скалярним виконанням коду, становить:

S_vector = T_scalar / T_vector
= (6 · N) / (N / 16)             [нехтуючи початковим оверхедом t_overhead]
= 96                             [кратне теоретичне прискорення для 8-бітних даних]

При тактовій частоті процесора `F_cpu` пікова продуктивність обчислювального ядра `OPS_peak` визначається кількістю операцій множення та додавання (2 MAC операції на елемент), виконуваних щотакту:

OPS_peak = 2 · P · F_cpu
= 2 · 16 · 240 · 10⁶             [для частоти 240 МГц та 8-бітного вектора]
= 7.68 · 10⁹                     [операцій за секунду або 7.68 GOPS]

Такий рівень продуктивності дозволяє виконувати складні цифрові фільтри та згорткові шари нейромереж прямо на мікроконтролері. Проте досягнення пікової швидкості можливе лише за умови, що шина пам'яті здатна поставляти 128 біт даних на кожен такт ядра без затримок.

## Пропускна здатність шини Octal SPI

У мікроконтролерних платах на кшталт [Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) та компактних модулях серії [ESP32-S3-Zero](root:cat-hw-boards/esp32-s3-zero) для підключення об'ємної зовнішньої пам'яті PSRAM використовується високошвидкісна 8-бітна шина @@en|Octal SPI@@ (від грец. *ὀκτώ* — вісім, та англ. *Serial Peripheral Interface* — послідовний периферійний інтерфейс). Шина працює в режимі @@en|DDR@@ (від англ. *Double Data Rate* — подвійна швидкість передачі даних), передаючи дані як по наростаючому, так і по спадаючому фронту тактового сигналу.

Теоретична сира пропускна здатність шини `B_raw` залежить від ширини шини `W_bus` (1 байт = 8 біт), кількості фронтів на такт `N_edges = 2` та тактової частоти шини `F_bus`:

B_raw = W_bus · N_edges · F_bus
= 1 · 2 · 80 · 10⁶               [ширина 1 байт, 2 фронти DDR, частота 80 МГц]
= 160 · 10⁶                      [байтів за секунду, або 160 МБ/с]

Проте реальна пропускна здатність завжди нижча за сиру через наявність протокольного оверхеду. Будь-яка транзакція читання з PSRAM складається з фази команди `t_cmd`, фази адреси `t_addr`, затримки синхронізації `t_dummy` для вирівнювання фази через @@en|DLL@@ (від англ. *Delay-Locked Loop* — контур із затримкою автопідстроювання фази) та тривалості передачі корисного блоку даних розміром `L_burst` байтів. Синхронізація зчитування на високих частотах контролюється спеціальним стробувальним сигналом @@en|DQS@@ (від англ. *Data Strobe Signal* — стробувальний сигнал даних). На математичну стійкість цього часового вікна суттєво впливає температурний дрейф напівпровідникового кристала: при зміні температури на `ΔT` затримка поширення сигналу в кремнієвих елементах змінюється на значення `Δt_gate = α_temp · ΔT`, де `α_temp` — температурний коефіцієнт затримки. Це викликає фазовий зсув стробу `Δt_DQS` відносно центру часового вікна даних `t_DVW`, що зменшує часовий запас зчитування `t_margin = t_DVW / 2 - |Δt_DQS|`. Якщо фазовий зсув перевищує половину вікна допуску (`|Δt_DQS| > t_DVW / 2`), виникає бітова помилка зчитування, тому підсистема контролера ESP32-S3 вимагає закладання додаткових тактів фіксованої затримки `t_dummy` для забезпечення безпечного запасу калібрування контуру @@en|DLL@@ при нагріванні.

![Часова діаграма передачі даних по 8-бітній шині Octal SPI в режимі DDR із фазовим зсувом DQS та інтервалом затримки DLL. З неї видно співвідношення корисних даних та службового оверхеду на синхронізацію.](img/octal-spi-ddr-dqs-timing.svg)
*Часова діаграма передачі даних по 8-бітній шині Octal SPI в режимі DDR із фазовим зсувом DQS та інтервалом затримки DLL.*

Загальна тривалість транзакції `T_trans` у тактах шини виражається формулою:

T_trans = t_cmd + t_addr + t_dummy + (L_burst / 2)
= 1 + 4 + 6 + (L_burst / 2)      [типові значення затримок для Octal SPI PSRAM]
= 11 + (L_burst / 2)             [загальна кількість тактів шини на пакет]

Ефективна пропускна здатність `B_eff` визначається відношенням часу передачі корисних даних до загального часу транзакції:

B_eff = B_raw · ( (L_burst / 2) / (11 + (L_burst / 2)) )
= B_raw · ( L_burst / (22 + L_burst) )      [формула ефективності шини Octal SPI]

Для малого пакета розміром `L_burst = 32` байти ефективність становить `32 / (22 + 32) ≈ 0.5925`, що дає `B_eff ≈ 94.8 МБ/с`. Для великого пакетного читання `L_burst = 256` байтів ефективність зростає до `256 / (22 + 256) ≈ 0.9208`, а швидкість досягає `B_eff ≈ 147.3 МБ/с`. Таким чином, для максимального використання пропускної здатності шини Octal SPI необхідно організовувати зчитування даних довгими безперервними блоками.

## Часова складність матричної згортки PSRAM

Оцінка реального часу виконання нейромережевих шарів у [компактних модулях ESP32-S3](root:cat-hw-boards/esp32-s3-zero) вимагає об'єднання часової моделі векторного прискорювача PIE з затримками вибірки даних через шину Octal SPI. Розглянемо згортковий шар @@en|TinyML@@ з розміром вхідного тензора `H × W × C_in`, де `H` та `W` — висота й ширина кадру, а `C_in` — кількість вхідних каналів. За умови використання ядра згортки `K × K` та кількості вихідних каналів `C_out` загальна кількість операцій множення з накопиченням `N_mac` обчислюється як:

N_mac = H · W · C_in · C_out · K²      [загальна кількість MAC операцій у згортці]

Час обчислення `t_compute`, необхідний прискорювачу PIE для виконання цих операцій при коефіцієнті пакування `P = 16` (для 8-бітних даних) та частоті ядра `F_cpu`, визначається виразом:

t_compute = N_mac / (P · F_cpu)
= (H · W · C_in · C_out · K²) / (16 · F_cpu)      [тривалість обчислень на ядрі]

Паралельно обсяг даних `D_total` у байтах, які необхідно передати через шину Octal SPI з зовнішньої PSRAM (включаючи вхідний тензор, коефіцієнти вагових матриць та запис результату), складає:

D_total = H · W · C_in + K² · C_in · C_out + H · W · C_out      [сумарний обсяг байтів]

Тривалість зчитування та запису даних через шину `t_memory` при ефективній пропускній здатності `B_eff` дорівнює:

t_memory = D_total / B_eff

За умови послідовного виконання обчислень без використання апаратного фонового обміну через DMA загальна затримка виконання шару `T_total` є простою сумою двох компонентів:

T_total = t_compute + t_memory

При використанні подвійної буферизації в локальній @@en|SRAM@@ процесорне ядро обробляє поточний блок даних паралельно з завантаженням наступного блоку через @@en|DMA@@. Для організації безперервної схеми подвійних буферів (англ. *ping-pong buffering*) локальна пам'ять виділяє два вхідні буфери обсягом `S_in` та два вихідні буфери `S_out` для збереження результатів згортки. Мінімально необхідний обсяг внутрішньої оперативної пам'яті `M_SRAM` для реалізації такого перекриття обчислень визначається формулою:

M_SRAM = 2 · S_in + 2 · S_out
= 2 · W_tile · H_tile · (C_in + C_out) · B_pixel      [сумарний обсяг двох пар буферів у SRAM]

де `W_tile` та `H_tile` — розміри оброблюваного фрагмента кадру (тайла), `C_in` та `C_out` — кількість вхідних і вихідних каналів, а `B_pixel` — байтова глибина одного елемента. Щоб апаратне перекриття повністю приховувало затримку обміну, розмір тайла обирається так, аби час обчислень `t_compute(tile)` не перевищував час шинного транспорту `t_memory(tile)`, при цьому сумарний обсяг `M_SRAM` мусить жорстко вміщатися у доступну ємність внутрішнього домену. У цьому випадку загальний час обробки визначається найповільнішою ланкою ланцюжка:

T_total = max(t_compute, t_memory) + t_setup      [часова модель із DMA буферизацією]

Додатково на затримку впливає вирівнювання адрес у пам'яті. Якщо адреси масивів у PSRAM не вирівняні за 16-байтною межею (128 біт), векторні інструкції PIE генерують додаткові вибірки для зсуву операндів, що збільшує `t_compute` на 15–25%.

Отже, під час проектування шарів у [модулях Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) мінімізація підсумкової затримки `T_total` вимагає комбінованої оптимізації: розміщення кадрових буферів за вирівняними адресами усуває продуктивні втрати на зсув операндів, а застосування подвійної буферизації через DMA приховує затримку передачі `t_memory` за обчислювальним інтервалом `t_compute`.

## Балансування обчислювальної інтенсивності та шини

Для визначення того, яка саме ланцюгова ланка обмежує швидкість системи — векторний прискорювач чи шина пам'яті, — застосовується модель @@en|Roofline model@@ (від англ. *Roofline model* — модель вирахунку граничної продуктивності). Основним параметром цієї моделі є арифметична інтенсивність `I_a` (від англ. *Arithmetic Intensity* — арифметична інтенсивність), яка показує кількість математичних операцій, виконуваних на кожен зчитаний із пам'яті байт:

I_a = N_mac / D_total      [кількість MAC операцій на 1 байт шинного трафіку]

Критичне значення арифметичної інтенсивності `I_crit` відповідає точці перегину, в якій обчислювальна потужність ядра дорівнює максимальній швидкості поставки даних шиною Octal SPI:

I_crit = (P · F_cpu) / B_eff

Розрахуємо критичну інтенсивність для плати [Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) при частоті ядра `F_cpu = 240 МГц`, 8-бітному векторі `P = 16` та ефективній пропускній здатності шини Octal SPI `B_eff = 147.3 МБ/с`:

I_crit = (16 · 240 · 10⁶) / (147.3 · 10⁶)
= 3840 / 147.3              [співвідношення швидкості обчислень до пропускної здатності]
≈ 26.07                     [необхідна кількість MAC операцій на байт]

Якщо алгоритм має `I_a < I_crit`, система знаходиться в області обмеження пам'яттю (@@en|memory-bound@@ domain). У цьому режимі векторний прискорювач PIE більшість часу простоює в очікуванні вибірки операндів із PSRAM, і підвищення частоти процесора не дає жодного прискорення.

Якщо ж `I_a ≥ I_crit`, система переходить в область обмеження обчисленнями (@@en|compute-bound@@ domain), де потенціал шини Octal SPI використовується повністю, а продуктивність визначається швидкістю PIE.

Для переведення алгоритмів із зони обмеження пам'яттю в зону обмеження обчисленнями застосовують прийом @@en|Tiling@@ (від англ. *tiling* — розбиття на плитки). Велику матрицю ділять на малі блоки (тайли), які повністю вміщуються у швидкий внутрішній кеш SRAM [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview). Це дозволяє багаторазово використовувати зчитані з PSRAM дані для декількох векторних інструкцій PIE підряд, штучно підвищуючи значення `I_a` вище за критичну позначку `I_crit`.
