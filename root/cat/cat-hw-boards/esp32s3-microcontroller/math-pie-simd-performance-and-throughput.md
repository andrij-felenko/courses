## Обмеження скалярних обчислень та потреба векторної обробки

Виконання алгоритмів цифрової обробки сигналів та інференсу компактних нейронних мереж на мікроконтролерах вимагає обробки великих масивів числових даних. Спроба реалізувати матричне множення чи згортку зображення за допомогою класичного 32-бітного скалярного арифметико-логічного блоку (англ. @@en|Arithmetic Logic Unit@@, @@en|ALU@@, від лат. *arithmetica* — наука про числа та *logica* — наука про міркування) впирається в жорсткі часові обмеження. У традиційній скалярній архітектурі кожна арифметична операція обробляє лише один операнд за один такт. Якщо вхідні дані представлені 16-бітними числами з фіксованою комою (наприклад, аудіовідліки чи квантовані ваги нейромережі), 32-бітне скалярне ядро змушене послідовно зчитувати кожен елемент з пам'яті, виконувати зсув регістрів, обчислювати добуток та додавати його до акумулятора. Для вектора довжиною 1024 елементи скалярне ядро виконує 1024 окремі інструкції множення та 1024 інструкції додавання, не враховуючи накладних витрат на інкремент покажчиків та перевірку умов циклу.

Розв'язанням цієї проблеми в [архітектурі ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) стало впровадження 128-бітного векторного співпроцесора @@en|PIE@@ (англ. @@en|Processor Instruction Extension@@, @@en|PIE@@, від лат. *processus* — просування та *instructio* — вказівка — розширення інструкцій процесора). Співпроцесор працює за принципом @@en|SIMD@@ (англ. @@en|Single Instruction, Multiple Data@@, від лат. *singularis* — поодинокий та *datus* — даний — одна інструкція, множинні дані), дозволяючи однією командою виконувати паралельні арифметичні дії над кількома елементами даних, упакованими у ширші 128-бітні регістри `Q0`–`Q7`. Внутрішня апаратна топологія співпроцесора спирається на виділену 128-бітну двопортову шину даних, що з'єднує векторний регістровий файл `Q0`–`Q7` напряму з локальним кід-кешем L1 даних та внутрішньою RAM пам’яттю. Завдяки паралельним магістралям зчитування та запису співпроцесор здатен вибірково завантажувати повний 16-байтовий вектор за один такт ядра без розбиття кадру на послідовні 32-бітні шинні транзакції, що виключає затримки сериалізації та забезпечує безперервний вибірковий потік операндів до обчислювальних каналів.

Однак максимальна пропускна здатність 128-бітного завантаження досягається лише за умови суворого апаратного вирівнювання вхідного масиву даних у пам'яті за 16-байтовою межею (англ. @@en|16-byte memory alignment@@). Внутрішні шини співпроцесора @@en|PIE@@ оптимізовані під адреси, кратні 16 байтам (коли 4 молодші біти фізичної адреси дорівнюють нулю). Якщо векторний покажчик `addr` порушує цю умову (`addr % 16 ≠ 0`), контролер не здатний прочитати весь 128-бітний блок за один такт. Фізично затребуваний вектор перетинає межу двох суміжних 16-байтових блоків пам'яті, змушуючи контролер @@en|DRAM@@ шини виконувати двоетапну вибірку: спершу зчитується перший 128-бітний слово-блок у проміжний буфер зсуву (англ. @@en|alignment shift buffer@@), після чого виконується другий шинний такт зчитування наступного слова. Апаратний каскадний зсувач (англ. @@en|barrel shifter@@) виконує побайтове вирівнювання операндів, об'єднуючи старші байти першого блоку з молодшими байтами другого блоку перед записом у векторні регістри `Q0`–`Q7`. Цей двоетапний апаратний конвеєр подвоює затримку завантаження даних. Розрахунок додаткових накладних витрат тактів очікування при порушенні вирівнювання виражається так:

```
N_unaligned = N_aligned × 2
= 1 × 2
= 2                         [подвоєння тактів завантаження невирівняного вектора]

ΔT_align = N_unaligned - N_aligned
= 2 - 1
= 1 такт                    [додаткова затримка на кожне 128-бітне завантаження]
```

Таким чином, для масиву з 1024 елементів (64 вектори по 16 байтів) невирівняне розміщення в пам'яті додає 64 зайві такти очікування шини, зводячи нанівець обчислювальний виграш модулів [родини ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) від залучення векторних інструкцій.

```
N_unaligned = N_aligned × 2
= 1 × 2
= 2                         [подвоєння тактів завантаження невирівняного вектора]

ΔT_align = N_unaligned - N_aligned
= 2 - 1
= 1 такт                    [додаткова затримка на кожне 128-бітне завантаження]
```

Завдяки 128-бітній ширині векторного регістра один викликовий такт співпроцесора @@en|PIE@@ замінює від 8 до 16 скалярних операцій залежно від розрядності даних. При обробці 16-бітних чисел у 128-бітний регістр вміщується 8 паралельних каналів, а при роботі з 8-бітними квантованими даними — 16 каналів. При пакуванні 8-бітних квантованих операндів у 128-бітні регістри `Q0`–`Q7` обчислювальна економія інструкцій розраховується так: для обчислення скалярного добутку двох векторів довжиною 16 елементів скалярному процесорному ядру потрібно виконати 16 інструкцій зчитування для першого вектора, 16 інструкцій для другого вектора, 16 інструкцій множення та 15 інструкцій додавання, що сумарно становить 63 скалярні команди. У векторному співпроцесорі @@en|PIE@@ ця ж операція вимагає лише двох 128-бітних векторних завантажень та одного паралельного векторного множення з акумуляцією, зменшуючи загальну кількість інструкцій з 63 до 3 команд. Таким чином, швидкість обробки 8-бітних масивів зростає у 21 раз за кількістю викликів команд, що дозволяє кардинально підняти обчислювальну щільність ядра без збільшення тактової частоти чипа.

## Математична модель паралелізму та тактова ефективність інструкцій

Для кількісної оцінки швидкодії співпроцесора @@en|PIE@@ виведемо математичну залежність між шириною векторного регістра, розрядністю даних та тактовою частотою процесорного ядра.

Позначимо параметри математичної моделі:
- `V_len` — ширина векторного регістра в бітах (`V_len = 128` біт);
- `b` — розрядність одного оброблюваного елемента в бітах (`b = 16` або `b = 8` біт);
- `S_speedup` — теоретичний коефіцієнт паралельного прискорення;
- `f_cpu` — тактова частота ядра процесора @@en|Xtensa LX7@@ в Герцах (`f_cpu = 240 × 10⁶` Гц);
- `P_peak` — пікова теоретична продуктивність у кількості операцій множення з накопиченням (англ. @@en|Multiply-Accumulate@@, @@en|MAC@@, від лат. *multiplicare* — помножувати та *accumulare* — нагромаджувати) за секунду.

Теоретичний коефіцієнт прискорення `S_speedup` обчислюється як відношення ширини регістра `V_len` до розрядності операнда `b`:

```
S_speedup
= V_len ÷ b               [ділення ширини векторного регістра на розрядність операнда]
```

Виконаємо розрахунок коефіцієнта прискорення `S_16` для 16-бітних елементів:

```
S_16
= 128 ÷ 16                [підстановка ширини регістра 128 біт та розміру елемента 16 біт]
= 8                       [кількість паралельних обчислювальних каналів]
```

Для 8-бітних елементів коефіцієнт прискорення `S_8` складає:

```
S_8
= 128 ÷ 8                 [підстановка ширини регістра 128 біт та розміру елемента 8 біт]
= 16                      [кількість паралельних обчислювальних каналів]
```

Спеціалізовані векторні інструкції співпроцесора @@en|PIE@@ поєднують вибірку даних з пам'яті та арифметичні обчислення в єдиному конвеєрі. Інструкція `EE.VLD.128.IP` завантажує 128 бітів даних з оперативності в регістр з автоінкрементом адреси, а інструкція `EE.VMULAS.S16.ACC` виконує 8 паралельних 16-бітних множень із додаванням результатів до 40-бітного акумулятора за 1 такт. З математичного боку, завантаження 16-байтового вектора через `EE.VLD.128.IP` суміщає модифікацію адреси покажчика `addr = addr + 16` із записом даних у регістровий файл в одному конвеєрному такті. Для послідовного масиву обсягом `N_bytes` кількість необхідних завантажень становить `K = N_bytes ÷ 16`, а загальна кількість тактів вибірки `T_fetch` у конвеєрному циклі дорівнює `T_fetch = K` тактів (1 такт на один 128-бітний вектор після 1-тактового початкового заповнення конвеєра). Наприклад, вибірка 1024 байтів даних (64 вектори по 16 байтів) виконується за 64 такти замість 128 тактів, які знадобилися б при роздільному виклику інструкцій завантаження та модифікації адреси. При підсумовуванні 16-бітних добутків розрядність кожного результату досягає 32 бітів, тому додавання 8 паралельних добутків за один такт у 40-бітний акумулятор надає 8 додаткових захисних бітів (англ. @@en|guard bits@@), що дозволяє виконати до `2⁸ = 256` послідовних накопичувальних операцій без арифметичного переповнення. Алгебраїчний вибір 40-бітного розрядного формату обґрунтований необхідністю покрити максимальне значення добутку двох знакових 16-бітних чисел `(-32768) × (-32768) = 1073741824` (`2³⁰`), де для `K` послідовних ітерацій накопичення сумарний діапазон акумулятора становить `2³²⁺⁸ = 2⁴⁰` бітів, забезпечуючи динамічний діапазон зважених сум `20 · log₁₀(2⁴⁰) ≈ 240.8` дБ для лінійних та згорткових шарів активації. Якщо ж накопичене значення досягає меж діапазону від `-2³⁹` до `2³⁹ - 1` (`-549755813888` до `549755813887`), апаратна логіка насичення (англ. @@en|saturation@@) автоматично обрізає результат до граничного значення, запобігаючи циклічному викривленню знака при виконанні обчислень для моделей [родини ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview). PIE@@ | Практичний синтаксис C/C++ викликів описують [асемблерні векторні інструкції](root:hw-arch/esp32s3-pie-assembly-intrinsics) співпроцесора.

Обчислимо пікову продуктивність `P_peak_16` у кількості операцій @@en|MAC@@ за секунду для 16-бітного режиму при частоті `f_cpu = 240 МГц`:

```
P_peak_16
= f_cpu × S_16            [множення тактової частоти ядра на кількість паралельних каналів]
= 240 × 10⁶ × 8           [підстановка частоти 240 МГц та 8 каналів]
= 1.92 × 10⁹              [пікова продуктивність у MAC/с (1.92 GMAC/с)]
```

Для 8-бітного режиму пікова продуктивність `P_peak_8` дорівнює:

```
P_peak_8
= f_cpu × S_8             [множення тактової частоти ядра на 16 паралельних каналів]
= 240 × 10⁶ × 16          [підстановка частоти 240 МГц та 16 каналів]
= 3.84 × 10⁹              [пікова продуктивність у MAC/с (3.84 GMAC/с)]
```

Розглянемо практичний приклад розрахунку кількості тактів процесора `C_cycles` та підсумкового часу обчислення `t_calc` для виконання матричного добутку двох квадратних матриць розмірністю `64 × 64` з 16-бітними елементами. Фізичний час виконання для обчислювальних модулів [родини ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) визначається прямим діленням кількості необхідних тактів на тактову частоту ядра `f_cpu = 240 × 10⁶` Гц: `t_calc = C_cycles ÷ f_cpu`. Для ідеальних 32768 тактів паралельних векторних обчислень це дає `32768 ÷ (240 × 10⁶) ≈ 1.3653 × 10⁻⁴` секунди, або рівно 136.5 мікросекунд (мкс) без урахування затримок пропуску кешу.

Обчислимо загальну кількість операцій @@en|MAC@@ `N_mac` для матричного добутку розмірністю `M × K × N` при `M = 64, K = 64, N = 64`:

```
N_mac
= M × K × N               [загальна кількість множень-додавань для матричного добутку]
= 64 × 64 × 64            [підстановка розмірності матриць 64х64]
= 262144                  [сумарна кількість операцій MAC]
```

Обчислимо мінімальну кількість тактів обчислення `C_cycles` з урахуванням 8 паралельних каналів інструкції `EE.VMULAS.S16.ACC`:

```
C_cycles
= N_mac ÷ S_16            [ділення сумарної кількості MAC на 8 паралельних каналів]
= 262144 ÷ 8              [підстановка 262144 MAC та 8 каналів]
= 32768                   [ідеальна кількість тактів процесора для обчислення добутку]
```

## Розрахунок швидкодії матричного множення та інференсу нейромереж

Перехід від розрахунку окремих інструкцій до підсумкової продуктивності системи вимагає врахування повного обсягу обчислень згорткових шарів нейромережі. На [родині плат ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) ключовою метрикою швидкодії в завданнях комп'ютерного зору є частота кадрів (англ. @@en|Frames Per Second@@, @@en|FPS@@ — кадрів за секунду), яка характеризує кількість оброблених зображень за одиницю часу.

Теоретична частота кадрів `FPS_theo` залежить від тактової частоти процесорного ядра `f_CPU`, кількості паралельних обчислювальних каналів векторного співпроцесора `SIMD_lanes` та загальної кількості операцій множення з накопиченням `N_MAC`, необхідних для обробки одного кадру:

```
FPS_theo
= (f_CPU × SIMD_lanes) ÷ N_MAC   [теоретична гранична частота кадрів]
```

Проте в реальних системах швидкість обмежена не лише обчислювальним ядром, а й пропускною здатністю шини пам'яті. При зчитуванні вагових коефіцієнтів та тензорів із зовнішньої псевдостатичної оперативної пам'яті (англ. @@en|Pseudo Static Random-Access Memory@@, @@en|PSRAM@@), встановленої на [платі Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare), виникають часові затримки шини та кеш-промахи. Математична модель коефіцієнта ефективності `η_mem` опирається на співвідношення між обсягом L1 кешу даних (32 КБ), розміром масиву вагових коефіцієнтів `S_tensor` та пропускною здатністю 8-бітної шини @@en|Octal SPI@@ у режимі DDR (до 160 МБ/с). При випередному зчитуванні з ідеальною попадальністю в кеш (`h_L1 = 1.0`) значення `η_mem` прямує до 1.0. Однак коли обсяг тензора перебільшує 32 КБ, частка кеш-влучань `h_L1` падає відповідно до відношення `32 / S_tensor`, а запізнення перезавантаження кеш-ліній по шині Octal SPI знижує коефіцієнт за формулою `η_mem = h_L1 + (1 - h_L1) × (B_bus / B_req)`, що дає підсумкове значення `η_mem` у практичному діапазоні від `0.45` до `0.65`. Ураховуючи ці втрати, реальна частота кадрів `FPS_real` обчислюється як:

Для компенсації простоїв ядра при зчитуванні із зовнішньої пам'яті застосовують математичну модель подвійної буферизації (англ. @@en|ping-pong buffering@@). Алгоритм розбиває обробку тензора у внутрішній @@en|SRAM@@ на два рівні буфери: поки векторний співпроцесор @@en|PIE@@ виконує обчислення над блоком `k` у буфері `A`, контролер прямого доступу до пам'яті (англ. @@en|Direct Memory Access@@, @@en|DMA@@) паралельно завантажує наступний блок `k + 1` з оперативної пам'яті @@en|PSRAM@@ по шині @@en|Octal SPI@@ у буфер `B`. Замість послідовної суми часів `T_single = T_compute + T_fetch` тривалість обробки одного блоку в режимі перекриття `T_overlap` визначається максимумом з обох складових:

Якщо системна конфігурація переходить у режим аварійного відкату на 4-бітну шину @@en|Quad SPI@@ (англ. @@en|Quad SPI fallback@@), фізична пропускна здатність зчитування з @@en|PSRAM@@ спадає зі `160.0` МБ/с до `40.0` МБ/с. Це викликає чотириразове збільшення тривалості вибірки даних `T_fetch_quad`, внаслідок чого обчислювальний конвеєр втрачає ефективність перекриття і стає повністю обмеженим пропускною здатністю шини:

```
T_fetch_quad = T_fetch × (B_octal ÷ B_quad)
= 1.065 × (160.0 ÷ 40.0)      [підстановка відношення пропускних здатностей]
= 1.065 × 4
= 4.260 × 10⁻³ с             [час вибірки блоку в режимі Quad SPI ~ 4.260 мс]

T_overlap_quad = max(T_compute, T_fetch_quad)
= max(1.302, 4.260)           [визначення лімітуючої складової шини]
= 4.260 × 10⁻³ с             [тривалість кадру під обмеженням шини]

FPS_real_quad = 1 ÷ T_overlap_quad
= 1 ÷ (4.260 × 10⁻³)          [обчислення підсумкового фреймрейту]
≈ 234.7                       [реальна частота кадрів у режимі Quad SPI]
```

Отриманий розрахунок показує, що зниження пропускної здатності шини при переході на @@en|Quad SPI@@ зменшує підсумкову частоту кадрів інференсу з 768.0 до 234.7 кадрів за секунду (падіння у `768.0 ÷ 234.7 ≈ 3.27` раза). Оскільки час вибірки `T_fetch_quad = 4.260` мс суттєво перевищує час векторного множення `T_compute = 1.302` мс, векторний співпроцесор @@en|PIE@@ на [родині плат ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) понад 69% робочого часу простоює в очікуванні даних з оперативної пам'яті, що зводить нанівець переваги 128-бітного паралелізму.

```
T_single = T_compute + T_fetch

T_overlap = max(T_compute, T_fetch)

S_pingpong = T_single ÷ T_overlap
= (T_compute + T_fetch) ÷ max(T_compute, T_fetch)
```

Якщо час вибірки блоку `T_fetch = 1.065` мс менший за час векторного обчислення `T_compute = 1.302` мс (`T_fetch ≤ T_compute`), затримка шини повністю приховується (`T_overlap = T_compute = 1.302` мс). У цьому випадку коефіцієнт прискорення обміну становить:

```
S_pingpong = (1.302 + 1.065) ÷ max(1.302, 1.065)
= 2.367 ÷ 1.302
≈ 1.818                     [коефіцієнт прискорення подвійної буферизації ~ 1.82×]
```

Завдяки паралелізму обчислень та фонового зчитування коефіцієнт ефективності пам'яті `η_mem` зростає від 0.55 до граничного значення 1.0, що дозволяє підвищити реальний фреймрейт на [платі Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) з 422.4 до теоретичного максимуму 768 кадрів за секунду.

```
FPS_real
= FPS_theo × η_mem              [корегування теоретичної частоти на затримки пам'яті]
```

**Умова розрахунку**: Обчислити теоретичну та реальну частоту кадрів для згорткового блоку обсягом `N_MAC = 5.0 × 10⁶` операцій (5 @@en|MMAC@@, від англ. @@en|Mega Multiply-Accumulate@@ — мільйон операцій множення з накопиченням) на один кадр при частоті ядра `f_CPU = 240` МГц у режимі 8-бітних векторних обчислень INT8 (`SIMD_lanes = 16`) та коефіцієнті ефективності шини `η_mem = 0.55`.

```
f_SIMD
= 240 × 10⁶ × 16                [обчислення пікової швидкості векторного блоку INT8]
= 3.84 × 10⁹ ops/s              [пікова продуктивність 3.84 GMAC/с]

FPS_theo
= 3.84 × 10⁹ ÷ (5.0 × 10⁶)     [відношення пікової швидкості до обсягу кадру]
= 768.0                         [теоретична межа кадрів за секунду]

FPS_real
= 768.0 × 0.55                  [урахування затримок шини та кеш-промахів]
= 422.4                         [реальна частота кадрів FPS]
```

Обчислення показують, що реальна частота становить 422.4 кадрів за секунду, оскільки затримки вибірки даних із зовнішньої пам'яті зменшують підсумкову продуктивність векторного співпроцесора на 45%. Математично ця 45% втрата обчислювального часу виражається через тривалість простою (англ. @@en|CPU stall cycles@@) процесорних ядер при перезавантаженні 32-байтових кеш-ліній @@en|L1@@ з оперативної пам'яті @@en|PSRAM@@ на [платі Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare). При виконанні 5.0 × 10⁶ операцій чистий обчислювальний час одного кадру `T_theo` та реальний час з урахуванням затримок шини `T_real` розраховуються так:

```
T_theo = N_MAC ÷ f_SIMD
= (5.0 × 10⁶) ÷ (3.84 × 10⁹)
≈ 1.302 × 10⁻³ с            [чистий час обчислень ~ 1.302 мс]

T_real = T_theo ÷ η_mem
= 1.302 ÷ 0.55
≈ 2.367 × 10⁻³ с            [підсумковий час кадру ~ 2.367 мс]

T_stall = T_real - T_theo
= 2.367 - 1.302
= 1.065 × 10⁻³ с            [час затримки вибірки ~ 1.065 мс]
```

При частоті ядра `f_CPU = 240` МГц тривалість простою `T_stall = 1.065` мс відповідає 255600 тактам очікування на кожен кадр. Оскільки частка втраченого часу `T_stall ÷ T_real = 1.065 ÷ 2.367 ≈ 0.45` становить точно 45%, під час неперервного інференсу векторний співпроцесор @@en|PIE@@ майже половину робочого часу перебуває в стані очікування завершення шинних транзакцій кешу.
