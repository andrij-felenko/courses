## Відмови пам’яті та збої виконання

Спроба виділити пам'ять під великий тензор моделі штучного інтелекту чи під буфер кадру камери за допомогою стандартної функції `malloc()` у середовищі @@en|ESP-IDF@@ часто завершується поверненням вказівника `NULL` або аварійним перезавантаженням мікроконтролера. Причиною є обмежений обсяг внутрішньої оперативної пам'яті @@en|SRAM@@ (всього 512 кБ у @@en|ESP32-S3@@), з якої під динамічну кучу доступно близько 300 кБ. При спробі звернення за помилковим вказівником або використанні непідготовленого буфера оперативна система генерує паніку ядра (англ. @@en|Core Panic@@) з фатальними кодами помилок: `Guru Meditation Error: Core 0 panic'ed (LoadProhibited)` при спробі читання з непроініціалізованої пам'яті, `StoreProhibited` при спробі запису за нульовою адресою, або `Cache disabled but cached memory region accessed`, коли контролер @@en|DMA@@ намагається звернутися до зовнішньої пам'яті при вимкненому кеші.

Якщо розробник додає зовнішню мікросхему псевдостатичної пам'яті @@en|PSRAM@@ й намагається передати адресу з неї в периферійний контролер прямого доступу до пам'яті (англ. @@en|Direct Memory Access@@, @@en|DMA@@), виникає фатальна помилка паніки ядра. Апаратна причина полягає в тому, що зовнішня енергонезалежна пам'ять @@en|Flash@@ та псевдостатична пам'ять @@en|PSRAM@@ підключені через спільну апаратну шину @@en|SPI@@ і транслюються у віртуальний адресний простір ядра через блок керування пам'яттю (англ. @@en|Memory Management Unit@@, @@en|MMU@@) та внутрішній кеш. Під час виконання операцій запису або стирання секторів у @@en|Flash@@ драйвер з міркувань цілісності шини тимчасово вимикає кеш та блокує таблиці трансляції @@en|MMU@@. Якщо в цей момент процесор або периферійний контролер @@en|DMA@@ робить спробу звернутися за адресою у @@en|PSRAM@@ чи прочитати код з @@en|Flash@@, контролер @@en|MMU@@ блокує трансляцію адреси та генерує фатальний збій `Cache disabled but cached memory region accessed`. Оскільки контролер @@en|DMA@@ у мікроконтролері @@en|ESP32-S3@@ працює безпосередньо з шинною матрицею внутрішньої оперативної пам'яті @@en|SRAM@@ і позбавлений прямого доступу до зовнішньої шини SPI-пам'яті при вимкненому кеші, передача адрес із @@en|PSRAM@@ у DMA-драйвери є неприпустимою. Конструктивні відмінності плат і варіанти модулів описує [оглядова стаття про родину ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview).

Одночасно при спробі відлагодження через стандартний @@en|UART@@-порт розробник стикається з відсутністю логів, якщо фізичний конвертер послідовного порту відсутній на платі або його виводи задіяно під інші завдання. Для розробки стабільного програмного забезпечення необхідно використовувати спеціалізоване системне API фреймворку ESP-IDF для адресації пам'яті та ведення консольного логування.

## Конфігурування Kconfig та логування usb_serial_jtag

Налаштування режимів взаємодії з пам'яттю та консоллю логування виконується на етапі компіляції прошивки через систему конфігурації @@en|Kconfig@@ (`menuconfig`). Для активації зовнішньої PSRAM у меню `Component config -> ESP PSRAM config` обирається відповідний режим підключення: @@en|Quad SPI@@ (4 лінії даних) або @@en|Octal SPI@@ (8 ліній даних). Наприклад, модуль [Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare) використовує високошвидкісний шинний режим Octal SPI, який забезпечує подвоєну пропускну здатність читання й запису.

Параметр `CONFIG_SPIRAM_USE_MALLOC` дає змогу задати поріг розміру буфера, починаючи з якого стандартний виклик `malloc()` буде автоматично перенаправляти запит у зовнішню псевдостатичну пам'ять @@en|PSRAM@@ замість внутрішньої оперативної пам'яті @@en|SRAM@@. Зокрема, конфігураційна опція `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL` визначає нижню межу виділення в байтах (за замовчуванням 16384 байти): усі масиви, розмір яких менший за це значення, гарантовано залишаються у швидкій внутрішній пам'яті @@en|SRAM@@ для забезпечення максимальної швидкості обробки. Запити, що перевищують даний поріг, розподільник виділяє з @@en|PSRAM@@. Додатковий параметр `CONFIG_SPIRAM_MALLOC_RESERVE_INTERNAL` резервує критичний обсяг внутрішньої кучі для задач операційної системи @@en|FreeRTOS@@ та викликів переривань. Алгоритм автоматичного перенаправлення спочатку перевіряє наявність суцільного вільного блоку в @@en|PSRAM@@, і лише в разі її вичерпання або відсутності потрібного обсягу резервує залишки внутрішньої пам'яті, що запобігає вичерпанню ресурсів системного ядра.

Для виведення логів без використання зовнішніх UART-чипів у ESP32-S3 передбачено вбудований контролер @@en|usb_serial_jtag@@. У меню Kconfig за шляхом `Component config -> ESP System Settings -> Channel for console output` обирається параметр `USB Serial/JTAG Controller`. Після цього стандартні макроси логування виводять дані безпосередньо через USB-порт.

На відміну від класичного послідовного порту @@en|UART@@, інтерфейс @@en|usb_serial_jtag@@ не вимагає узгодження швидкості передачі (англ. @@en|baud rate@@) на кшталт 115200 бод, оскільки обмін даними відбувається на апаратній швидкості @@en|USB Full Speed@@ (до 12 Мбіт/с). Для запобігання блокуванню системних задач @@en|FreeRTOS@@ при відключеному USB-кабелі в меню Kconfig за шляхом `Component config -> ESP System Settings` налаштовується розмір кільцевого буфера виведення. У разі переповнення буфера драйвер автоматично скидає старі повідомлення або працює в неблокуючому режимі, гарантуючи стійкість виконання основного циклу прошивки.

## Динамічний розподіл пам'яті з heap_caps_malloc

Стандартний `malloc()` не враховує апаратні атрибути пам'яті мікроконтролера. Фреймворк ESP-IDF надає розширений аллокатор `heap_caps_malloc()`, який приймає бітову маску прапорців типу `MALLOC_CAP_*`.

Основні прапорці виділення пам'яті:
- `MALLOC_CAP_INTERNAL` — виділяє пам'ять виключно у внутрішній швидкій SRAM мікроконтролера.
- `MALLOC_CAP_SPIRAM` — виділяє буфер у зовнішній псевдостатичній пам'яті PSRAM.
- `MALLOC_CAP_DMA` — виділяє пам'ять у внутрішній SRAM із вирівнюванням, яке задовольняє вимоги контролера DMA.
- `MALLOC_CAP_8BIT` — забезпечує доступ до пам'яті з побайтовою адресацією.
- `MALLOC_CAP_32BIT` — виділяє пам'ять, доступну лише через 32-бітні вирівняні операції читання та запису.

При налаштуванні буферів для периферії прапорці комбінуються за допомогою побітового «АБО» (`|`). Прапорець `MALLOC_CAP_8BIT` є обов'язковим для звичайних символьних масивів та текстових буферів, де потрібен доступ до окремих байтів. Для спеціалізованої периферії комбінування з `MALLOC_CAP_32BIT` гарантує чотирибайтове вирівнювання (англ. @@en|word alignment@@), що відсікає регіони пам'яті з підтримкою лише 8-бітних шин і забезпечує максимальну швидкість читання 32-бітними словами. Проте для передачі даних через контролер прямого доступу до пам'яті (від англ. @@en|Direct Memory Access@@, @@en|DMA@@) звичайного вирівнювання по слову недостатньо. У мікроконтролерах [родини плат ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) підсистема кешування даних оперує кеш-лініями (англ. @@en|cache line@@) фіксованого розміру `32` або `64` байти. Якщо розмістити DMA-буфер без вирівнювання за межами кеш-лінії, його краї опиняться в одній лінії кешу з іншими змінними процесора. Це призведе до порушення когерентності кешу (англ. @@en|cache coherency@@), коли інвалідація або скидання кеш-рядків ядрами CPU перезапише або пошкодить нові байти, прийняті периферією через DMA. Для гарантії когерентності застосовують спеціалізовану функцію `heap_caps_aligned_alloc(alignment, size, caps)`, яка приймає величину вирівнювання `alignment` (наприклад, `32` або `64` байти), забезпечуючи початок і розмір буфера строго кратими розміру кеш-лінії.

## Прискорення TinyML за допомогою ESP-NN та SIMD

Двоядерний процесор @@en|Xtensa LX7@@ у складі ESP32-S3 містить векторне розширення інструкцій (англ. @@en|Single Instruction, Multiple Data@@, @@en|SIMD@@), яке виконує паралельні математичні обчислення над декількома елементами даних за один такт. Для спрощення використання цих апаратних можливостей компанія @@en|Espressif@@ розробила оптимізовану C-бібліотеку @@en|ESP-NN@@, яка застосовується в завданнях машинного навчання на мікроконтролерах (@@en|TinyML@@).

Бібліотека надає високопродуктивні реалізації векторних операцій:
- `esp_nn_conv_s8()` — квантована 2D-згортка для 8-бітних цілих чисел (`int8`).
- `esp_nn_depthwise_conv_s8()` — поглиблена 2D-згортка.
- `esp_nn_add_elementwise_s8()` — поелементне векторизоване додавання тензорів.
- `esp_nn_mat_mult_s8()` — оптимізоване множення матриць.

Для досягнення максимальної продуктивності векторизованих викликів у мікроконтролерах [родини плат на ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) висуваються суворі вимоги до організації буферів у пам'яті. Векторні інструкції ядра процесора здатні за один такт завантажувати 128-бітні блоки даних (16 елементів `int8`) безпосередньо у 128-бітні SIMD-регістри. Щоб запобігти накладним витратам на невирівняне читання та викличеним ним затримкам шини, вхідні тензори й масиви вагових коефіцієнтів повинні мати суворе 16-байтне вирівнювання в пам'яті (англ. @@en|16-byte alignment@@). Крім того, вихідні математичні параметри моделей штучного інтелекту піддаються симетричному 8-бітному квантуванню (англ. @@en|int8 quantization@@) із нульовою точкою зміщення `zero_point = 0` та масштабувальним коефіцієнтом `scale`. Квантування переводить 32-бітні числа з плаваючою комою у 8-бітні цілі числа зі знаком, що дає змогу апаратному конвеєру сумування й множення (англ. @@en|Multiply-Accumulate@@, @@en|MAC@@) паралельно виконувати до 16 операцій за один тактовий імпульс.

![Схема векторизованого виконання обчислень ESP-NN з використанням інструкцій Xtensa LX7 SIMD](img/esp32-s3-esp-nn-simd-pipeline.svg)
*Векторизований конвеєр обчислень бібліотеки ESP-NN на ядрі Xtensa LX7.*

Завдяки SIMD-інструкціям швидкість виконання згорткових шарів нейромереж зростає в 3–4 рази порівняно зі звичайними циклами мови C.

Для підтвердження ефективності векторизації наведено результати вимірів часу виконання операції 2D-згортки для масиву розміром `32 × 32 × 3` з ядром `3 × 3` при тактовій частоті ядра 240 МГц: еталонна C-реалізація потребує 12.4 мс на один прохід, тоді як апаратно прискорена функція `esp_nn_conv_s8()` витрачає всього 3.2 мс. Для поглибленої згортки (англ. @@en|depthwise convolution@@) час обробки зменшується з 4.1 мс до 1.1 мс, що дає можливість обробляти дані нейромережевих моделей у реальному часі.

## Діагностика помилок та аналіз витоків кучі

Для забезпечення стійкості прошивки системні виклики фреймворку ESP-IDF повертають код помилки типу `esp_err_t`. Макрос `ESP_ERROR_CHECK()` перевіряє повернутий код: якщо він не дорівнює `ESP_OK`, викликається обробник паніки з виведенням стек-трейсу.

Діагностика стану пам'яті здійснюється спеціальними функціями аналізу кучі:
- `heap_caps_get_free_size(MALLOC_CAP_SPIRAM)` — повертає поточний обсяг вільної PSRAM.
- `heap_caps_get_minimum_free_size(MALLOC_CAP_INTERNAL)` — повертає мінімальний залишок внутрішньої SRAM за весь час роботи системи.
- `heap_caps_check_integrity(MALLOC_CAP_INVALID, true)` — здійснює перевірку цілісності метаданих кучі для виявлення випадків виходу за межі масивів.
- `heap_caps_dump_all()` — виводить у консоль детальний дамп усіх блоків динамічної пам'яті з їхніми фізичними адресами й розмірами.

Для системного виявлення витоків пам'яті в меню Kconfig за шляхом `Component config -> Heap memory debugging` активується режим трасування `CONFIG_HEAP_TRACING_STANDALONE`. Виклик функції `heap_caps_dump_all()` до та після виконання контрольної процедури дозволяє порівняти стан блоків кучі й точно визначити фізичні адреси масивів, які не були повернуті в систему.
