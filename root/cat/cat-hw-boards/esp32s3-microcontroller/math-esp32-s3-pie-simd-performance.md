## Обмеження скалярних обчислень у DSP

Обробка сигналів у реальному часі та обчислення задач штучного інтелекту на мікроконтролерах вимагають виконання великого обсягу векторних операцій. Цифрові фільтри, матричні згортки та алгоритми @@en|DSP@@ (англ. @@en|Digital Signal Processing@@, від грец. *ψηφιακός* — цифровий та лат. *signalum* — знак) будуються на послідовному множенні векторів коефіцієнтів на вектор вхідних відліків. У разі класичного скалярного виконання процесор розраховує лише один елемент за ітерацію, що створює обчислювальне вузьке місце при підвищенні частоти дискретизації або збільшенні розміру матриць. Основна причина падіння швидкодії полягає у суттєвих математичних та апаратних накладних витратах скалярного циклу мови @@en|C@@: окрім самої операції множення, кожна ітерація вимагає виконання інструкцій порівняння та умовного переходу для перевірки меж циклу, декременту лічильника, інкременту вказівників на елементи масивів пам'яті, а також зсуву та вирівнювання даних. У результаті корисна обчислювальна робота займає лише один такт процесора, а допоміжні системні операції керування конвеєром витрачають ще 4–5 тактів, знижуючи підсумкову ефективність процесорного ядра до 20% від його теоретичного піку.

Для оцінки обмежень скалярного підходу розглянемо КІХ-фільтр (фільтр із скінченною імпульсною характеристикою) з `K = 128` коефіцієнтами при частоті дискретизації аудіосигналу `f_s = 48000` Гц. Кількість скалярних операцій множення з накопиченням @@en|MAC@@ (англ. @@en|Multiply-Accumulate@@, від лат. *multiplicare* — множити та *accumulare* — накопичувати) за одну секунду розраховується як добуток частоти на кількість коефіцієнтів:

```
F_mac = f_s × K
= 48000 × 128           [підстановка частоти дискретизації та кількості коефіцієнтів]
= 6144000               [кількість скалярних MAC-операцій за секунду]
= 6.144 · 10⁶           [скалярне навантаження 6.144 MMAC/s]
```

У скалярному циклі мови C кожна операція множення й додавання супроводжується інструкціями керування циклом, ікременту вказівників та завантаження з пам'яті. У процесорі @@en|Xtensa LX7@@ (від лат. *extensus* — витягнутий) розрахунок одного скалярного елемента потребує в середньому `T_cycle = 5` тактів. Загальні витрати тактів процесора за секунду складають:

```
C_scalar = F_mac × T_cycle
= 6.144 · 10⁶ × 5       [множення кількості MAC-операцій на середню кількість тактів циклу]
= 3.072 · 10⁷           [30.72 мільйонів тактів за секунду]
```

Це навантаження займає понад 12.8% обчислювальної потужності одного ядра з частотою 240 МГц. Для задач комп'ютерного зору на [ESP32-CAM (OV2640 + microSD)](root:cat-hw-boards/esp32-cam), де обробляється кадр розміром `640 × 480` пікселів із частотою 30 кадрів за секунду та ядром згортки `3 × 3`, скалярне навантаження перевищує `414.72 · 10⁶` тактів, що фізично неможливо виконати на одному ядрі без векторного прискорення, детально описаного в матеріалі [Родина плат і модулів на ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview).

## Математична модель 128-бітного рушія PIE

Для подолання обчислювального бар'єру в мікроконтролері ESP32-S3 інтегровано векторний копроцесорний рушій @@en|PIE@@ (англ. @@en|Processor Instruction Extension@@, від лат. *processus* — просування та *instructio* — вказівка). Рушій оперує 128-бітними векторними регістрами від `Q0` до `Q7`, які дозволяють завантажувати й обробляти упаковані масиви даних за принципом @@en|SIMD@@ (англ. @@en|Single Instruction, Multiple Data@@, від лат. *singulus* — один та *instructio* — вказівка). Для запобігання втраті точності при багаторазовому додаванні добутків у векторній математиці застосовуються 40-бітні регістри-акумулятори `QACC`. Оскільки множення двох знакових 8-бітних чисел `int8 × int8` дає 16-бітний результат, послідовне сумування 16 таких добутків швидко переповнило б стандартний 32-бітний регістр. Завдяки наявності 8 додаткових захисних розрядів розширення (від англ. @@en|guard bits@@ — розряди переповнення) акумулятори `QACC` накопичують до 256 послідовних 32-бітних сум без проміжного насичення чи зрізання значущих бітів, що гарантує математичну точність при векторному обчисленні згорткових шарів нейромереж.

*_Схема паралельного виконання 128-бітних SIMD-інструкцій у векторному конвеєрі PIE та накопичення результатів у регістрах QACC._*

У 128-бітному регістрі одночасно розміщується 16 елементів знакового 8-бітного цілого типу `int8`. Під час виконання однієї векторної інструкції паралельного множення з накопиченням рушій PIE здійснює 16 операцій `int8 × int8` з додаванням до 40-бітних регістрів-акумуляторів `QACC`. Після обчислення масиву згорткових добутків 40-бітний акумулятор `QACC` підлягає математичним процедурам нормалізації та насичення. Нормалізація вимагає зсуву 40-бітного значення праворуч на `S` бітів (`QACC >> S`) для узгодження масштабу фіксованої коми (англ. *fixed-point scaling*, @@en|fixed-point scaling@@) із подальшим округленням до цільового 8-бітного чи 16-бітного типу. У разі виходу результату за допустимі межі розрядності апаратний блок насичення (англ. *saturation logic*, @@en|saturation logic@@) обрізає значення до граничних значень `INT8_MAX = 127` та `INT8_MIN = -128` замість циклічного переповнення (англ. *wrap-around*, @@en|wrap-around@@). Описаний подвійний механізм нормування й апаратного захисту від переповнення дозволяє будувати високоточні нейромережеві моделі у пристроях з [родини плат на ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) без затримок на програмну перевірку меж.

```
P_cycle = 16            [кількість паралельних MAC-операцій int8 за один такт]
```

Для тактової частоти ядра `f_cpu = 240` МГц (`240 · 10⁶` Гц) теоретична пікова продуктивність `P_peak` у вимірі MOPS (мільйонів операцій за секунду) розраховується з урахуванням того, що кожен MAC містить дві математичні дії (множення та додавання):

```
P_peak = f_cpu × P_cycle × 2
= 240 · 10⁶ × 16 × 2    [підстановка частоти процесора та кількості дій на MAC]
= 7680 · 10⁶            [7.68 мільярдів арифметичних операцій за секунду]
= 7.68                  [7.68 GOPS пікової векторної швидкодії]
```

Теоретичний коефіцієнт прискорення `S_theory` відносно 1-тактового скалярного виконання становить:

```
S_theory = P_cycle
= 16                    [максимальне теоретичне прискорення у 16 разів]
```

## Розрахунок накладних витрат вирівнювання пам'яті

Дійсна продуктивність векторного конвеєра відрізняється від теоретичного піку через накладні витрати на доступ до пам'яті, вирівнювання адрес та насичення результатів. Для досягнення максимальної швидкості 128-бітне векторне слово має бути вирівняне в операційній пам'яті за межовою адресою, кратною 16 байтам (`A mod 16 = 0`). Крім того, у двоядерній архітектурі процесора @@en|Xtensa LX7@@ суттєвим чинником падіння реальної пропускної здатності є затримки міжядерного арбітражу системної шини @@en|AXI@@ при одночасному зверненні ядер @@en|Core 0@@ та @@en|Core 1@@ до @@en|L1@@-кешу. Коли обидва ядра одночасно ініціюють промах кешу та вимагають вибірки 128-бітних векторних слів з оперативної пам'яті, арбітр шини почергово призупиняє виконання команд одного з ядер на додаткові 6–12 тактів. У разі постійної конкуренції за шину ці арбітражні паузи викличуть накопичення затримок у векторному конвеєрі, знижуючи підсумкову обчислювальну ефективність рушія @@en|PIE@@ ще на 15–25%.

Якщо адреса вектора є невирівняною (`A mod 16 ≠ 0`), системна шина L1-кешу виконує два послідовні зчитування із застосуванням зсувного регістра вирівнювання `EE.VALIGN`. У результаті час вибірки векторного слова зростає з `T_aligned = 1` такту до `T_unaligned = 3` тактів. Коефіцієнт ефективності вирівнювання пам'яті `η_align` формулюється як:

```
η_align = T_aligned / T_unaligned
= 1 / 3                 [відношення тактів вирівняного та невирівняного доступу]
≈ 0.333                 [падіння ефективності вибірки до 33.3%]
```

Повний час виконання циклу для масиву з `N` елементів `int8` при обробці блоками по 16 елементів обчислюється за формулою:

```
T_total = (N / 16) × (T_exec + T_load_overhead) + T_setup
```

Для масиву з `N = 1024` елементів при вирівняній пам'яті (`T_exec = 1`, `T_load_overhead = 0`, `T_setup = 4` такти):

```
T_aligned_total = (1024 / 16) × 1 + 4
= 64 × 1 + 4            [обчислення тактів для 64 векторних ітерацій]
= 68                    [68 тактів процесора]
```

При невирівняній пам'яті (`T_load_overhead = 2` такти на кожен векторний блок):

```
T_unaligned_total = (1024 / 16) × (1 + 2) + 4
= 64 × 3 + 4            [обчислення тактів невирівняного циклу]
= 196                   [196 тактів процесора]
```

Дійсний коефіцієнт реального прискорення `S_real` вирівняного векторного коду відносно скалярного циклу (`T_scalar_total = 1024 × 4 = 4096` тактів) розраховується як:

```
S_real = T_scalar_total / T_aligned_total
= 4096 / 68             [відношення тактів скалярного та векторного виконання]
≈ 60.235                [дійне прискорення у 60.24 рази порівняно зі скалярним циклом]
```

## Обчислення тактового бюджету реального часу

Отримана математична модель дозволяє розраховувати граничну складність алгоритмів штучного інтелекту та обробки сигналів для плат розробки [Waveshare ESP32-S3R2 (16 МБ Flash, 2 МБ PSRAM)](root:cat-hw-boards/esp32-s3r2-waveshare) або [ESP32-S3-Zero (Type-C, 4 МБ)](root:cat-hw-boards/esp32-s3-zero). Проте при роботі з масивними кадровими буферами високої роздільної здатності підсумковий тактовий бюджет мусить враховувати додаткові штрафні затримки на витіснення модифікованих кеш-ліній (англ. *write-back penalty*, @@en|write-back penalty@@). Оскільки підсистема пам'яті використовує режим зворотного запису (англ. *write-back*, @@en|write-back@@), заповнення кешу L1 примушує контролер скидати застарілі «брудні» кеш-лінійки (англ. *dirty cache lines*, @@en|dirty cache line@@) у зовнішню оперативну пам'ять @@en|PSRAM@@ (від англ. @@en|Pseudo Static RAM@@ — псевдостатична оперативна пам'ять). Кожна така операція скидання через шину @@en|Octal SPI@@ додає затримку у `T_writeback = 16`–`24` тактів на 32 байти даних, що збільшує накладний коефіцієнт конвеєра `K_pipeline` та зменшує підсумкову реальну частоту кадрів.

Для заданої цільової частоти обробки кадрів або блоків даних `f_target` (наприклад, 30 кадрів/с для відео) граничний бюджет тактів `B_frame` на один кадр при частоті ядра 240 МГц складає:

```
B_frame = f_cpu / f_target
= 240 · 10⁶ / 30         [ділення частоти процесора на частоту кадрів]
= 8.0 · 10⁶             [8 мільйонів тактів на один кадр]
```

Якщо нейромережева модель TinyML для обробки одного кадру потребує `M_ops` MAC-операцій, необхідна кількість тактів `C_req` з урахуванням конвеєрного коефіцієнта накладних витрат `K_pipeline = 1.2` становить:

```
C_req = (M_ops / 16) × K_pipeline
```

Для згорткового шару нейромережі з обсягом `M_ops = 50 · 10⁶` MAC-операцій на кадр:

```
C_req = (50 · 10⁶ / 16) × 1.2
= 3.125 · 10⁶ × 1.2      [обчислення необхідних тактів процесора]
= 3.75 · 10⁶            [3.75 мільйонів тактів на кадр]
```

Частка завантаження ядра процесора `R_budget` обчислюється як:

```
R_budget = C_req / B_frame
= 3.75 · 10⁶ / 8.0 · 10⁶ [відношення витрачених тактів до доступного бюджету]
= 0.46875               [завантаження 46.88% одного ядра CPU]
```

Максимальна гранична частоти обробки кадрів `FPS_max` для даної моделі розраховується за формулою:

```
FPS_max = f_cpu / C_req
= 240 · 10⁶ / 3.75 · 10⁶ [підстановка частоти процесора та тактів на кадр]
= 64                    [гранична швидкодія 64 кадри за секунду]
```

Математичний розрахунок підтверджує, що векторне прискорення 128-бітного рушія PIE дає змогу реалізовувати обробку потокового відео та аудіо у реальному часі із запасом обчислювального бюджету понад 50%.
