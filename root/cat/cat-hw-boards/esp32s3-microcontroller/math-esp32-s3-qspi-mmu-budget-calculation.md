## Проблема обмеження швидкодії шини пам'яті

Під час розробки графічних застосунків, обробки відеопотоків із фотоматриць чи виведення зображень на дисплеї високої роздільності розробники на пристроях з [родини плат ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) часто стикаються з несподіваним падінням частоти кадрів. Замість очікуваних 30 або 60 кадрів за секунду реальна швидкість рендерингу знижується до 5–10 кадрів, причому обчислювальна потужність процесорних ядер задіяна лише частково.

Причина полягає в апаратному дисбалансі між обсягом і пропускною здатністю оперативної пам'яті. Внутрішня статична пам'ять @@en|SRAM@@ (англ. @@en|Static Random-Access Memory@@ — статична оперативна пам'ять) працює на частоті процесорного ядра й забезпечує нульові затримки доступу, проте її обсяг обмежений значенням близько `512 КБ`. Великі кадрові буфери роздільною здатністю VGA чи SVGA доводиться розміщувати у зовнішній псевдостатичній пам'яті @@en|PSRAM@@ (англ. @@en|Pseudo Static RAM@@ — псевдостатична оперативна пам'ять). Ситуація ускладнюється тим, що при одночасному виконанні мультипотокових обчислень обидва процесорні ядра @@en|Xtensa LX7@@ звертаються до зовнішнього масиву через спільну апаратну шину арбітражу пам'яті. Коли перше ядро здійснює зчитування піксельних даних для рендерингу, а друге ядро паралельно намагається оновити кадр у кеші або виконати транзакцію @@en|DMA@@, апаратний кросбар-арбітр змушений послідовно квантувати доступ. Оскільки транзакція підкачування рядка кешу із зовнішньої PSRAM триває десятки тактових циклів, виникає критична затримка арбітражу (англ. @@en|arbitration latency@@ — затримка узгодження доступу), під час якої друге ядро повністю блокується в стані очікування шини @@en|bus stall@@. Одночасна конфліктна адресація призводить до серійних простоїв виконання інструкцій, і цей колізійний дефіцит пропускної здатності додатково знижує підсумковий темп обробки відеопотоку на [платах ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview).

На відміну від внутрішньої SRAM, зовнішня PSRAM підключена до обчислювального кристала через послідовні шини. Спроба передати значний обсяг графічних даних створює пропускне обмеження шини (англ. @@en|bottleneck@@ — пляшкове горло). Коли сумарний потік від контролера прямого доступу до пам'яті @@en|DMA@@ та запитів кешу процесора перевищує межу фізичної пропускної здатності інтерфейсу SPI, виникають тривалі паузи очікування. Це формує обчислювальну задачу розрахунку шинного бюджету для визначення граничних можливостей відеопідсистеми.

## Формули пропускної здатності QSPI та Octal SPI

Для кількісної оцінки потенціалу підсистеми пам'яті необхідно вивести математичну модель обчислення теоретичної пропускної здатності послідовних шин. Швидкість передачі визначається трьома фізичними факторами: шириною шини даних у бітах, частотою тактування та режимом стробування сигналів.

![Порівняльна графоаналітична діаграма теоретичної пропускної здатності шин QSPI та Octal SPI у режимах SDR/DDR на 80/120 МГц з математичною формулою розрахунку.](img/esp32s3-qspi-ospi-bandwidth-chart.svg)
_*Залежність теоретичної пропускної здатності шини від ширини шини даних, частоти тактування та режиму стробування SDR/DDR.*_

Теоретична пропускна здатність шини `B_theory` у байтах за секунду розраховується як добуток тактової частоти `f_clk` у герцах, ширини шини даних `N_bits` та коефіцієнта режиму передачі `M_DDR`, поділений на 8 бітів у байті:

    B_theory = (f_clk × N_bits × M_DDR) ÷ 8

У цій формулі використовуються такі параметри:
* `N_bits` — кількість паралельних ліній даних: `N_bits = 4` для шини @@en|Quad SPI@@ (QSPI) та `N_bits = 8` для шини @@en|Octal SPI@@ (OSPI);
* `M_DDR` — коефіцієнт передачі за такт: `M_DDR = 1` для режиму @@en|SDR@@ (англ. @@en|Single Data Rate@@ — передача по одному фронту тактового сигналу) та `M_DDR = 2` для режиму @@en|DDR@@ (англ. @@en|Double Data Rate@@ — передача по наростаючому й спадаючому фронтах);
* `f_clk` — частота тактування шини (типово 80 МГц або 120 МГц).

Розрахуємо теоретичну межу пропускної здатності для стандартної конфігурації Quad SPI SDR на частоті 80 МГц, де `N_bits = 4`, `M_DDR = 1` та `f_clk = 80000000` Гц:

    B_QSPI_SDR_80 = (80000000 × 4 × 1) ÷ 8      [формула питомого потоку байтів]
                  = 320000000 ÷ 8               [сумарний бітовий потік]
                  = 40000000                    [пропускна здатність у байтах/с]
                  = 40.0                        [значення у мегабайтах за секунду (МБ/с)]

Для високошвидкісних модулів розширення, таких як [плата Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare), застосовується 8-бітна шина Octal SPI у режимі DDR (`N_bits = 8`, `M_DDR = 2`).

Обчислення пропускної здатності для Octal SPI DDR на частоті 80 МГц має вигляд:

    B_OSPI_DDR_80 = (80000000 × 8 × 2) ÷ 8      [формула подвійної передачі по 8 біт]
                  = 1280000000 ÷ 8              [сумарний бітовий потік]
                  = 160000000                   [байт/с]
                  = 160.0                       [значення у МБ/с]

При підвищенні частоти тактування шини Octal SPI DDR до 120 МГц пропускна здатність зростає, проте на цій граничній частоті стрімко проявляються фізичні обмеження друкованого монтажу. Через скорочення тривалості напівперіоду такту до 4.16 нс паразитні параметри трас викликають зсув фаз сигналів та міжсимвольну інтерференцію (від англ. @@en|intersymbol interference@@, де @@en|intersymbol@@ — міжсимвольний, @@en|interference@@ — завада), коли попередні біти накладаються на наступні. Затримка поширення імпульсів у провідниках розмиває дійсне вікно даних, що вимагає застосування сигналу стробування DQS для фазового вирівнювання зчитування.

    B_OSPI_DDR_120 = (120000000 × 8 × 2) ÷ 8    [підстановка частоти 120 МГц]
                   = 1920000000 ÷ 8             [сумарний бітовий потік]
                   = 240000000                  [байт/с]
                   = 240.0                      [значення у МБ/с]

Отже, перехід від 4-бітної шини QSPI SDR (40 МБ/с) до 8-бітної шини Octal SPI DDR на частоті 120 МГц (240 МБ/с) підвищує теоретичну межу передачі даних ровно у 6 разів. Проте це значення описує лише сирий потік шини без урахування затримок трансляції адрес контролером пам'яті.

Для обчислення реальної пропускної здатності `B_real` необхідно врахувати протокольні накладні витрати командної фази шини SPI, які складаються з передачі коду операції `N_cmd`, фізичної адреси `N_addr` та холостих тактів очікування стабілізації даних (англ. @@en|dummy cycles@@, від англ. @@en|dummy@@ — холостий та @@en|cycle@@ — цикл) `N_dummy`. Під час підкачування одного 32-байтного рядка кешу в режимі @@en|Octal SPI DDR@@ тривалість фази даних `N_data` становить 16 тактів, а загальна кількість тактів транзакції `N_total` та ефективність шини `eta` обчислюються так:

    N_total = N_cmd + N_addr + N_dummy + N_data
            = 1 + 4 + 6 + 16                   [1 такт команди, 4 адреси, 6 очікування, 16 даних]
            = 27                               [сумарні такти однієї транзакції]

    eta = N_data ÷ N_total
        = 16 ÷ 27                              [ділення корисних тактів на загальні]
        ≈ 0.5926                               [коефіцієнт корисного використання шини (59.26%)]

    B_real = B_OSPI_DDR_120 × eta
           = 240.0 × 0.5926                    [множення пікової швидкості на ефективність]
           ≈ 142.2                             [реальна пропускна здатність у МБ/с]

Таким чином, протокольні витрати командної фази знижують реальний потік даних шини 120 МГц з 240 МБ/с до 142.2 МБ/с на платах на кшталт [Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare), що створює нижчий обчислювальний поріг для прямоточного пересилання відеокадрів.

## Математика трансляції адресації MMU та L1-кешу

Фізична пам'ять псевдостатичного оперативного запам'ятовувача в [родині плат ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) відображається у віртуальний 32-бітний адресний простір процесорного ядра через блок управління пам'яттю @@en|MMU@@ (англ. @@en|Memory Management Unit@@ — блок управління пам'яттю). Апаратний транслятор ділить адресний простір на фіксовані сторінки розміром `S_page = 64` КБ (`65536` байтів). При зверненні процесора до віртуальної адреси кеш-контролер L1 перевіряє наявність даних у процесорному кеші. Якщо дані відсутні, виникає промах кешу (англ. @@en|cache miss@@), і система блокується на час вибірки нового рядка кешу розміром `S_line = 32` байти з зовнішньої @@en|PSRAM@@ через шину @@en|Octal SPI@@ або @@en|Quad SPI@@. Проте якщо послідовний або нелінійний доступ до даних перетинає межу 64-кілобайтної сторінки `S_page`, апаратний контролер @@en|MMU@@ змушений виконати додаткову трансляцію та перезавантажити внутрішні регістри відображення сторінок. Ця процедура додає додатковий апаратний штраф затримки у вигляді кількох тактів очікування процесора ще до запуску шинного циклу вибірки рядка кешу з зовнішньої @@en|PSRAM@@.

Загальна часова затримка одного промаху кешу `T_miss` визначається сумою тактових фаз шинного протоколу. Вона охоплює фазу передачі команди `N_cmd`, фазу виставляння адреси `N_addr`, апаратні такти очікування відгуку матриці пам'яті `N_dummy` та безпосередньо фазу зчитування даних `N_data`. Для зменшення цієї затримки кеш-контролер [чипів родини ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview) реалізує апаратне попереднє вибірання (англ. @@en|hardware prefetching@@, від @@en|hardware@@ — апаратне забезпечення, @@en|prefetch@@ — вибирати наперед), яке асинхронно завантажує наступний 32-байтний рядок кешу (англ. @@en|cache line@@) під час послідовного читання. Проте при скануванні з кроком (англ. @@en|stride@@), що перевищує розмір рядка, передбачувач збивається, через що кожне звернення спричиняє повний шинний цикл `T_miss`. Для 8-бітної шини @@en|Octal SPI@@ у режимі подвійної передачі даних @@en|DDR@@ (англ. @@en|Double Data Rate@@ — подвійна швидкість даних) при робочій частоті шини `f_spi = 80` МГц (період тактування `t_clk = 1000 / f_spi = 12.5` нс) затримка вибірки одного 32-байтного рядка обчислюється так:

```
T_miss = (N_cmd + N_addr + N_dummy + N_data) × t_clk
= (1 + 2 + 6 + 16) × 12.5       [підстановка фазових тактів та періоду при 80 МГц]
= 25 × 12.5                     [підсумовування фазових тактів]
= 312.5 ns                      [обчислення часової затримки одного промаху]
```

![Схема-модель трансляції сторінок MMU 64 КБ та фазових затримок L1-кешу при промасі доступу до PSRAM.](img/esp32s3-mmu-cache-penalty-model.svg)
_*Схема-модель трансляції сторінок MMU обсягом 64 КБ та фазових затримок L1-кешу при промасі доступу до PSRAM._*

Характер доступу до даних у пам'яті визначає кількість промахів кешу `N_miss`. При лінійному послідовному зчитуванні один промах виникає лише раз на `32` байти, адже наступні `31` байт зчитуються безпосередньо з швидкої кеш-пам'яті L1 зі швидкістю `1` такт процесора. Проте при нелінійній обробці (наприклад, при повороті зображення на 90 градусів або вертикальному скануванні колонок кадру) кожен наступний піксель розташований у пам'яті зі зсувом на ширину рядка кадру. Для зображення роздільністю `320 × 240` пікселів у форматі `RGB565` (розмір кадру `153.6` КБ) вертикальний обхід викликає промах кешу при кожному зверненні до пікселя (`N_miss = 76800` промахів). Сумарне часове покарання `T_penalty` обчислюється наступним чином:

```
T_penalty = N_miss × T_miss
= 76800 × 312.5                 [підстановка кількості промахів та часу одного промаху]
= 24000000 ns                   [множення]
= 24 ms                         [переведення у мілісекунди]
```

Додаткові `24` мілісекунди очікування лише на вибірку рядків кешу суттєво знижують обчислювальну продуктивність ядра при обробці відеоданих у зовнішній пам'яті [плат Waveshare ESP32-S3R2](root:cat-hw-boards/esp32-s3r2-waveshare).

## Обчислення бюджету кадрів та межі FPS

Практичний інженерний розрахунок швидкодії відеопідсистеми спирається на зіставлення реальної пропускної здатності шини пам'яті `B_real` та сумарного обсягу шинного трафіку `S_traffic`, необхідного для обслуговування одного кадру. При прямоточному передаванні кадрів через контролер прямого доступу @@en|DMA@@ (англ. @@en|Direct Memory Access@@ — прямий доступ до пам'яті) підсистема пам'яті випробує подвійне навантаження: апаратний модуль камери записує вхідний кадр у перший буфер @@en|PSRAM@@, тоді як контролер дисплея паралельно зчитує попередній кадр із другого буфера.

Розмір одного кадрового масиву `S_frame` у кадровому буфері (англ. @@en|framebuffer@@, від @@en|frame@@ — кадр, @@en|buffer@@ — буфер) залежить від ширини кадру `W` в пікселях, висоти `H` та питомого обсягу пам'яті на піксель `bpp` (англ. @@en|bytes per pixel@@ — байтів на піксель). Для кадру роздільної здатності @@en|VGA@@ (`640 × 480` пікселів) у кольоровій моделі `RGB565` (`bpp = 2` байти) обсяг одного буфера становить:

S_frame = W × H × bpp
        = 640 × 480 × 2                 [підстановка роздільності та глибини кольору 2 байти]
        = 614400 bytes                  [обчислення обсягу кадру RGB565]

Якщо ж застосувати повноколірну модель `RGB888` з глибиною `bpp = 3` байти на піксель (по одному байту на червоний, зелений та синій канали), обсяг одного кадру зростає в `1.5` раза:

S_frame_RGB888 = W × H × bpp
               = 640 × 480 × 3          [підстановка 3 байтів на піксель для RGB888]
               = 921600 bytes           [обчислення обсягу кадру RGB888 в байтах]

При використанні подвійної буферизації `N_buf = 2` підсумковий шинний трафік одного кадру `S_traffic_RGB888` досягає величини:

S_traffic_RGB888 = N_buf × S_frame_RGB888
                 = 2 × 921600           [добуток кількості буферів на обсяг кадру]
                 = 1843200 bytes        [обчислення сумарного трафіку в байтах]
                 = 1.8432 МБ            [переведення значення у мегабайти]

Цей 50-відсотковий приріст обсягу трафіку суттєво обмежує граничний поріг частоти кадрів `FPS_max_RGB888`. На швидкісній шині @@en|Octal SPI@@ DDR з реальною пропускною здатністю `B_real ≈ 200 МБ/с` (`200000000` байтів/с) гранична швидкість обробки кадрів знижується з `162.75` до:

FPS_max_RGB888 = B_real / S_traffic_RGB888
               = 200000000 / 1843200    [ділення пропускної здатності на трафік RGB888]
               ≈ 108.5 FPS              [граничний поріг частоти для RGB888 на Octal SPI]

На повільнішій шині @@en|Quad SPI@@ DDR на частоті `80 МГц` (`B_real ≈ 64 МБ/с` або `64000000` байтів/с) поріг частоти кадрів для `RGB888` падає від `52.08` до критичних:

FPS_max_RGB888_QSPI = B_real / S_traffic_RGB888
                    = 64000000 / 1843200 [ділення пропускної здатності QSPI на трафік RGB888]
                    ≈ 34.72 FPS         [граничний поріг частоти для RGB888 на Quad SPI]

Тим самим перехід на формат `RGB888` вичерпує понад `33.3%` допустимого часового бюджету шини [мікроконтролера ESP32-S3](root:cat-hw-boards/esp32-s3-boards-family-overview), роблячи високі частоти обробки недосяжними без апаратного стиснення.

```
S_frame = W × H × bpp
= 640 × 480 × 2                 [підстановка роздільності та глибини кольору]
= 614400 bytes                  [обчислення обсягу кадру]
```

З урахуванням подвійної буферизації `N_buf = 2` сумарний обсяг даних `S_traffic`, які передаються через шину пам'яті за один кадр, становить `S_traffic = N_buf × S_frame = 2 × 614400 = 1228800` байтів (`1.2288` МБ).

Гранично досяжна частота кадрів `FPS_max` (від англ. @@en|Frames Per Second@@ — кадрів на секунду) обчислюється як відношення пропускної здатності шини `B_real` до сумарного трафіку одного кадру `S_traffic`. Для шини @@en|Octal SPI@@ DDR на частоті 120 МГц з реальною швидкістю `B_real ≈ 200` МБ/с (`200000000` байтів/с) граничний поріг становить:

```
FPS_max = B_real / S_traffic
= 200000000 / 1228800           [підстановка пропускної здатності та навантаження]
≈ 162.75 FPS                    [обчислення граничної частоти кадрів]
```

Для порівняння, на шині @@en|Quad SPI@@ DDR з робочою частотою 80 МГц та реальною пропускною здатністю `B_real ≈ 64` МБ/с (`64000000` байтів/с) той самий обхід відеопам'яті обмежений значно нижчим порогом:

```
FPS_max = B_real / S_traffic
= 64000000 / 1228800            [підстановка пропускної здатності та навантаження]
≈ 52.08 FPS                     [обчислення граничної частоти кадрів]
```

Якщо в застосунку на [модулях ESP32-CAM](root:cat-hw-boards/esp32-cam) застосовується стиснення @@en|JPEG@@ (де середня величина кадру `S_frame ≈ 51200` байтів), сумарний трафік зменшується до `S_traffic = 2 × 51200 = 102400` байтів, що піднімає теоретичну межу шини Quad SPI до `625` @@en|FPS@@. Математичний розрахунок доводить, що для нестиснутого відео високої роздільності `RGB565` використання Octal SPI є безальтернативною апаратною вимогою. Ситуація додатково ускладнюється при переході до триплексної буферизації (від англ. @@en|triple buffering@@, де @@en|triple@@ — потрійний, @@en|buffering@@ — буферизація; `N_buf = 3`), яка усуває розриви кадрів під час асинхронного виводу: сумарний трафік одного циклу для `RGB565 VGA` зростає до `S_traffic = 3 × 614400 = 1843200` байтів, знижуючи межу швидкодії шини Octal SPI DDR 120 МГц з `162.75` до `108.5` @@en|FPS@@ через додаткове 50-відсоткове навантаження на пам'ять.
