# Інструменти прошивання мікроконтролерів ESP: esptool та GUI-завантажувачі

## Чому ESP не приймає прошивку

Звичайна робота мікроконтролерів @@en|ESP8266@@ та @@en|ESP32@@ спирається на виконання інструкцій безпосередньо із зовнішньої флеш-пам'яті через пряме адресування @@en|XIP@@ (англ. @@en|Execute in Place@@ від @@en|execute@@ — виконувати та @@en|place@@ — місце). Під час читання коду через шину @@en|SPI@@ (англ. @@en|Serial Peripheral Interface@@) спроба перезаписати сектори пам'яті спричиняє апаратний збій процесора.

Для безпечного запису даних чип переходить в ізольований сервісний режим за допомогою вбудованого первинного завантажувача @@en|ROM Bootloader@@ (англ. @@en|Read-Only Memory Bootloader@@). Вибір режиму здійснюється в момент зняття сигналу скидання @@en|EN@@ (англ. @@en|Enable@@ — увімкнення). Якщо на виводі @@en|GPIO0@@ утримується логічна одиниця, чип запускає основну програму. Низький рівень логічного нуля на `GPIO0` змушує `ROM Bootloader` очікувати нову прошивку через послідовний порт @@en|UART@@ (англ. @@en|Universal Asynchronous Receiver-Transmitter@@).

## Автоматичне скидання та керування виводами

Для автоматизації переходу в режим завантаження застосовують схему на двох біполярних транзисторах @@en|NPN@@-типу. Вони керуються сигналами термінала @@en|DTR@@ (англ. @@en|Data Terminal Ready@@) та @@en|RTS@@ (англ. @@en|Request to Send@@) перетворювача @@en|USB-UART@@.

![{Схема двох NPN-транзисторів для автоматичного перемикання ліній EN та GPIO0}](img/esp-auto-reset-transistor-circuit.svg)
*Схема автоскиду комутує лінії EN та GPIO0 за допомогою сигналів DTR і RTS перетворювача USB-UART.*

Сигнал `DTR` заземлює лінію `GPIO0`, а переключення `RTS` викликає коротке скидання через вивід `EN`. Завдяки затримці фільтрувального @@en|RC@@-ланцюжка (англ. @@en|Resistor-Capacitor@@) на лінії `EN` потенціал `GPIO0` залишається низьким під час ініціалізації первинного завантажувача. Перевірити стан зневаджувача можна через [архітектуру програматора DAPLink](root:cat-hw-boards/daplink-programmer-architecture).

## Протокол завантаження та розмітка пам'яті

Передача прошивки по послідовному порту використовує кадри протоколу @@en|SLIP@@ (англ. @@en|Serial Line Internet Protocol@@) з екрануванням службових байтів. 

![{Розмітка секторів флеш-пам'яті ESP32 із вказуванням адрес зсуву}](img/esp32-flash-memory-partition-layout.svg)
*Карта пам'яті показує вирівнювання адрес завантажувача, таблиці розділів та коду застосунку по межах секторів 4 КБ.*

Запис здійснюється з вирівнюванням адрес по межах секторів 4 @@en|КБ@@ (кілобайт). У чипах `ESP32` вторинний завантажувач розташовується за адресою `0x1000`, таблиця розділів @@en|partition table@@ (англ. @@en|partition table@@) — за `0x8000`, а основний застосунок — з `0x10000`. По завершенню запису `ROM Bootloader` звіряє цілісність даних через хеш @@en|MD5@@ (англ. @@en|Message Digest 5@@).

## Вибір інструменту прошивання ESP

Консольна утиліта @@en|esptool@@ на мові @@en|Python@@ є базовим інструментом для автоматизації запису та налаштування через скрипти @@en|CI/CD@@ (англ. @@en|Continuous Integration / Continuous Delivery@@). 

Для швидкої роботи без командного рядка застосовують графічні обгортки з інтерфейсом @@en|GUI@@ (англ. @@en|Graphical User Interface@@). Утиліта @@en|NodeMCU PyFlasher@@ спрощує вивантаження єдиного бінарного файла, а офіційний інструмент @@en|ESP Flash Download Tool@@ надає можливість одночасного запису кількох образів за різними адресами на виробництві.

## Діагностика збоїв і відновлення прошивки

Невдале прошивання найчастіше викликане просіданням живлення 3.3 В, завадами на лінії `UART` або неправильним режимом роботи флеш-пам'яті. 

![{Блок-схема послідовності дій для діагностики помилок прошивання}](img/esp-flashing-troubleshooting-flowchart.svg)
*Блок-схема діагностики показує кроки перевірки живлення, лінії UART та стирання флеш-пам'яті при збоях.*

Для відновлення знижують швидкість передачі, підключають зовнішній стабілізатор та виконують повне стирання пам'яті командою `erase_flash`. Порівняти сервісні протоколи можна з описом [прошивки та протоколу ST-Link V2.1](root:cat-hw-boards/stlink-v21-firmware-architecture).
