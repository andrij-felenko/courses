## Затримки AT-команд та проблема переповнення

Керування периферійними вузлами вбудованого пристрою на базі [модуля ESP-01](root:cat-hw-boards/esp-01) через текстовий протокол @@en|AT@@ ставить перед розробником проблему апаратно-часового балансу. На відміну від прямого маніпулювання регістрами у власному коді, обмін текстовими командами через послідовний порт @@en|UART@@ (від англ. @@en|Universal Asynchronous Receiver-Transmitter@@ — універсальний асинхронний прийматопередавач) додає суттєві накладні витрати часу. При циклічному опитуванні аналогових сенсорів чи динамічній зміні параметрів широтно-імпульсної модуляції (англ. @@en|Pulse-Width Modulation@@, @@en|PWM@@) наївне надсилання текстових запитів без урахування швидкості обміну (англ. @@en|baud rate@@) та часу кодування швидко призводить до десинхронізації системи.

Кожна транзакція текстового протоколу складається з трьох послідовних фаз: передачі символів запиту host-контролером, внутрішньої обробки інструкції парсером прошивки @@en|Espressif AT@@ та повернення текстової відповіді. Загальний час транзакції `t_trans` визначається сумою цих трьох складових:

```
t_trans = t_tx + t_proc + t_rx
```

де `t_tx` — час передачі байтів запиту по лінії `TX`, `t_proc` — затримка виконання команди в ядрах прошивки з урахуванням кванту часу операційної системи, а `t_rx` — тривалість прийому вихідного рядка відповіді. Якщо керуючий контролер надсилає наступний запит із періодом `T_req`, що є меншим за час повної транзакції (`T_req < t_trans`), апаратний приймальний буфер @@en|FIFO@@ (від англ. @@en|First In, First Out@@ — першим прийшов, першим вийшов) обсягом 128 байтів переповнюється. Це викликає втрату символів, збій парсингу відповіді та блокування обчислювального конвеєра [архітектури SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview).

*Часова діаграма транзакції UART під час обміну AT-командами.*

Для побудови стійкого інтерфейсу необхідно розрахувати часовий баланс між швидкістю шини @@en|UART@@, тривалістю аналого-цифрового перетворення та частотою оновлення @@en|PWM@@.

З математичного боку алгоритм апаратного заповнення буфера прийому керується порогом генерації переривань обробника (англ. @@en|Interrupt Service Routine@@, @@en|ISR@@). Для кадру формату 8N1 один символ містить 10 біт, тому тривалість передачі одного байта `t_byte` залежить від швидкості обміну `B` як `t_byte = 10 ÷ B`. При накопиченні порогової кількості байтів `N_thresh` у буфері @@en|FIFO@@ загальною місткістю `N_fifo = 128` байтів контролер [архітектури SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview) викликає переривання. Загальний час накопичення даних до моменту генерації переривання `t_fifo` обчислюється через підстановку тривалості байта:

```
t_fifo = N_thresh × t_byte           [визначення часу накопичення порогового обсягу]
       = N_thresh × (10 ÷ B)         [підстановка виразу тривалості байта t_byte]
       = (10 × N_thresh) ÷ B         [алгебраїчне спрощення виразу]
```

Для упередження втрати даних решта вільних осередків буфера `N_fifo - N_thresh` повинна вміщати всі байти, що надходять за час апаратної затримки реакції операційної системи `t_latency` (включаючи час перемикання контексту та джиттер FreeRTOS). З урахуванням швидкості обміну `B` оптимальний поріг спрацьовування переривань `N_thresh_opt` виводиться з нерівності безпечного запасу:

```
N_thresh_opt
= N_fifo - (t_latency ÷ t_byte)        [віднімання кількості байтів, що надходять за час затримки]
= N_fifo - (t_latency ÷ (10 ÷ B))      [підстановка часу передачі одного байта t_byte]
= N_fifo - (t_latency × B) ÷ 10        [алгебраїчне спрощення виразу]
```

Перевищення налаштованого порогу понад обчислене значення `N_thresh_opt` призводить до того, що найменший сплеск затримки операційної системи викликає апаратне переповнення приймача та збій обробки текстових команд.

```
t_fifo = N_thresh × t_byte           [визначення часу накопичення порогового обсягу]
       = N_thresh × (10 ÷ B)         [підстановка виразу тривалості байта t_byte]
       = (10 × N_thresh) ÷ B         [алгебраїчне спрощення виразу]
```

Отримане співвідношення показує апаратну затримку реакції буфера. Якщо час обробки переривання та перемикання контексту операційної системи `t_isr` перевищує інтервал заповнення залишку осередків `(N_fifo - N_thresh) × t_byte`, виникає апаратне переповнення (англ. @@en|buffer overflow@@) і частина байтів втрачається.

Для забезпечення беззбійного обміну мінімально припустимий період опитування `T_req_min` визначається виразом, у якому до сумарного часу транзакції `t_trans` додається часовий запас безпеки `t_margin`:

```
T_req_min = t_trans + t_margin       [сумування часу транзакції та технологічного запасу]
          = t_tx + t_proc + t_rx + t_margin  [розгортання складових затримки UART]
```

Значення `t_margin` розраховують виходячи з максимального фазового джиттера операційної системи та випадкових затримок обслуговування переривань [режимів завантаження мікроконтролера](root:cat-hw-boards/esp8266-boot-modes). Якщо обраний період опитування задовольняє умову `T_req ≥ T_req_min`, буфер @@en|FIFO@@ встигає повністю звільнятися між транзакціями, що гарантує цілісність текстових відповідей пристрою.

## Квантування та перерахунок відліків АЦП

Для зчитування аналогових сигналів у [сімействі модулів ESP-01](root:cat-hw-boards/esp-01-module-family-overview) використовується один канал 10-бітного аналого-цифрового перетворювача (англ. @@en|Analog-to-Digital Converter@@, @@en|ADC@@), виведений на контакт @@en|TOUT@@. Вхідний діапазон вимірюваної напруги обмежено опорним потенціалом `V_ref` = 1.0 В. При виконанні текстової команди зчитування прошивка повертає цілочисельний відлік `D_raw` у діапазоні від 0 до 1023, який відповідає квантованій величині напруги.

Кількість дискретних рівнів квантування для 10-бітного перетворювача становить `N` = 2¹⁰ = 1024. Крок квантування або ціна молодшого значущого розряду (англ. @@en|Least Significant Bit@@, @@en|LSB@@) `V_LSB` визначається діленням опорної напруги на максимальне кодове значення:

```
V_LSB
= V_ref ÷ (2¹⁰ - 1)
= 1.0 ÷ 1023                                               [ділення опорного потенціалу на 1023 дискрети]
≈ 0.0009775 V                                              [значення ціни LSB у вольтах]
≈ 0.9775 mV                                                [переведення у мілівольти]
```

Формула перерахунку отриманого цифрового відліку `D_raw` у фізичну вхідну напругу `V_in` має лінійний вигляд, проте ідеальна лінійна модель не враховує реальні апаратні відхилення аналогового тракту мікроконтролера. На практиці опорний потенціал `V_ref` у конкретному кристалі ESP8266 може відхилятися від номінального значення 1.0 В у межах від 0.95 В до 1.05 В через технологічний розкид кремнієвих пластин, змінюючи справжній масштабний коефіцієнт `V_LSB`. Крім того, вбудований аналого-цифровий перетворювач володіє інтегральною (від англ. @@en|Integral Non-Linearity@@, @@en|INL@@) та диференціальною нелінійністю (від англ. @@en|Differential Non-Linearity@@, @@en|DNL@@), які спричиняють викривлення передавальної характеристики біля країв діапазону вимірювання (нижче 0.1 В та вище 0.9 В). Сумарний вплив дрейфу `V_ref` та нелінійності підсилює реальну похибку вимірювання до ±15–30 мВ, що значно перевищує теоретичний крок дискретизації і вимагає застосування кастомних калібрувальних коефіцієнтів у точних вимірювальних застосунках. Для компенсації похибки зсуву нуля (англ. @@en|offset error@@) та похибки масштабування (англ. @@en|gain error@@) застосовують двочкове калібрування (англ. @@en|two-point calibration@@). Використовуючи два відомих еталонних потенціали `V₁` та `V₂` у лінійній зоні (наприклад, 0.1 В та 0.9 В) і фіксуючи відповідні відліки `D₁` та `D₂`, обчислюють реальний масштабний множник `A_cal` та напругу зсуву `V_off`:

```
A_cal = (V₂ - V₁) ÷ (D₂ - D₁)                              [обчислення реальної ціни розряду з урахуванням gain error]
V_off = V₁ - (A_cal · D₁)                                  [визначення зсуву нульового рівня offset error]
V_cal = A_cal · D_raw + V_off                              [підсумкова лінійна формула каліброваної напруги]
```

Отримана залежність `V_cal` коригує кут нахилу та нульову точку передавальної функції АЦП для даного екземпляра мікроконтролера, компенсуючи апаратний розкид параметрів.

```
V_in = D_raw · V_LSB
     = D_raw · (1.0 ÷ 1023)                                [множення відліку на крок квантування]
```

Оскільки аналогова величина неперервна, а цифровий код дискретний, процес квантування супроводжується неусувною похибкою `ΔV_quant`, яка дорівнює половині ціни молодшого розряду:

```
ΔV_quant = ± 0.5 · V_LSB
         = ± 0.5 · 0.9775                                  [обчислення півкроку дискретизації]
         ≈ ± 0.4887 mV                                     [абсолютна похибка квантування]
```

![Графік передавальної функції 10-бітного АЦП, де показано ступені квантування напруги від 0 до 1 В.](img/adc-quantization-transfer-function.svg)
*Графік передавальної функції 10-бітного АЦП.*

Обчислимо практичне значення напруги при отриманні відповіді від АЦП.

**Умова розрахунку:** обчислити вхідну напругу `V_in` та інтервал невизначеності при отриманні сирого текстового відліку `D_raw` = 768 за командою зчитування АЦП.

```
V_in
= 768 · (1.0 ÷ 1023)                                       [підстановка відліку 768 у формулу перетворення]
= 768 · 0.000977517                                        [множення на точне значення V_LSB]
= 0.750733 V                                               [обчислена напруга в вольтах]
≈ 750.73 mV                                                [переведення у мілівольти]

V_min
= 750.73 - 0.4887                                          [віднімання півкроку квантування]
≈ 750.24 mV                                                [нижня межа виміряної напруги]

V_max
= 750.73 + 0.4887                                          [додавання півкроку квантування]
≈ 751.22 mV                                                [верхня межа виміряної напруги]
```

Таким чином, відлік 768 відповідає напрузі 750.73 мВ з абсолютною похибкою квантування ±0.49 мВ. Урахування цієї математичної залежності дозволяє точно інтерпретувати дані сенсорів перед надсиланням їх по мережі.

## Розрахунок частоти та заповнення ШІМ

Генерація імпульсних керувальних сигналів у прошивках @@en|Espressif AT@@ реалізується через програмну широтно-імпульсну модуляцію (від англ. @@en|Pulse-Width Modulation@@, @@en|PWM@@ — широтно-імпульсна модуляція). Керування параметрами сигналу на виводах @@en|GPIO@@ здійснюється за допомогою системної AT-команди, де розробник задає частоту `f_pwm` та коефіцієнт заповнення імпульсу `D_pwm`.

Часовий період одного повного циклу ШІМ `T_pwm` виражається через задану частоту `f_pwm` за базовим співвідношенням:

```
T_pwm
= 1 ÷ f_pwm                          [обчислення періоду через частоту]
= 1 ÷ 1000                           [підстановка частоти 1000 Гц]
= 0.001 s                            [переведення в секунди]
= 1000 μs                            [переведення в мікросекунди]
```

Тривалість активного високого рівня `T_high` обчислюється пропорційно до коефіцієнта заповнення `D_pwm`, визначеного у відсотках від `0%` до `100%`:

```
T_high
= T_pwm × (D_pwm ÷ 100)              [розрахунок активного періоду від коефіцієнта заповнення]
= 1000 × (75 ÷ 100)                  [підстановка періоду 1000 мкс та заповнення 75%]
= 750 μs                             [тривалість високого рівня імпульсу]
```

Відповідно, тривалість пасивного низького рівня становить `T_low = T_pwm - T_high = 1000 - 750 = 250` мкс. Апаратний таймер [архітектури SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview) обробляє ці часові інтервали шляхом порівняння лічильника з розрахованими значеннями тактів, забезпечуючи дискретне перемикання станів виводу з базовим точним кроком системного таймера `t_tick = 1` мкс. Оскільки часовий дискрет обмежений величиною `t_tick`, загальна кількість доступних рівнів квантування тривалості імпульсу за один період `N_ticks` та дискретність градації коефіцієнта заповнення `ΔD_pwm` обчислюються за залежностями:

```
N_ticks
= T_pwm ÷ t_tick                         [кількість дискретних кроків таймера за період]
= 1000 ÷ 1                                [підстановка періоду 1000 мкс та такту 1 мкс]
= 1000                                    [число дискретних рівнів тривалості]
```

```
ΔD_pwm
= (1 ÷ N_ticks) × 100                    [градація коефіцієнта заповнення у відсотках]
= (1 ÷ 1000) × 100                       [розрахунок для 1000 рівнів квантування]
= 0.1%                                    [мінімальний крок зміни заповнення]
```

Отже, при частоті ШІМ `f_pwm = 1000` Гц коефіцієнт заповнення `D_pwm` змінюється з дискретністю `0.1%` (1000 градацій). Підвищення частоти генерації до `f_pwm = 10` кГц зменшує період до `T_pwm = 100` мкс, через що кількість кроків `N_ticks` скорочується до 100, а дискретність `ΔD_pwm` погіршується до `1%`, що обмежує точність плавного регулювання напруги.

Для розрахунку цілочисельного значення лічильника таймера `Duty_ticks`, яке передається у внутрішні регістри [архітектури SoC ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview) при обробці @@en|AT@@-команд, застосовують співвідношення `Duty_ticks = N_ticks × (D_pwm ÷ 100)`. Наприклад, для заданого коефіцієнта заповнення `D_pwm = 35.4%` при частоті `f_pwm = 1000` Гц значення кроків обчислюється як `1000 × 0.354 = 354` тактів. Через наявність мінімальної часової дискретності `t_tick = 1` мкс виникає апаратне обмеження на мінімальний активний імпульс `T_min = 1` мкс, яке визначає мертву зону (від англ. @@en|dead zone@@ — мертва зона) керування `D_min = ΔD_pwm = 0.1%`. Усі значення заповнення `D_pwm < D_min` округлюються програмним ядром до `0%`, що призводить до повного вимкнення сигналу і має враховуватись під час розрахунку точних передавальних характеристик виконавчих пристроїв. Проте в реальних умовах робоча точність обмежується не лише квантуванням таймера, а й фазовим джиттером (від англ. @@en|phase jitter@@ — фазовий джиттер) програмного @@en|PWM@@. Оскільки таймерні переривання обробника (англ. @@en|Interrupt Service Routine@@, @@en|ISR@@) витісняються високопріоритетними перериваннями (англ. @@en|High-Priority Interrupt@@ — високопріоритетне переривання) стейк-машини @@en|Wi-Fi@@, момент перемикання фронту затримується на час `t_jitter` (типово від 2 до 10 мкс під час передачі пакетів). Відносна похибка коефіцієнта заповнення `ΔD_jitter`, викликана цією часовою затримкою, обчислюється за виразом:

```
ΔD_jitter
= (t_jitter ÷ T_pwm) × 100             [розрахунок відхилення заповнення через затримку ISR]
= (5 ÷ 1000) × 100                     [підстановка затримки 5 мкс та періоду 1000 мкс]
= 0.5%                                 [динамічна нестабільність коефіцієнта заповнення]
```

При збільшенні частоти ШІМ до `f_pwm = 10` кГц (`T_pwm = 100` мкс) та сама затримка `t_jitter = 5` мкс спричиняє зростання джиттера заповнення до `ΔD_jitter = (5 ÷ 100) × 100 = 5%`, що призводить до видимого миготіння світлодіодів чи апаратних пульсацій струму двигуна під час мережевого обміну.

Через округлення дрібової частини при переведенні у цілочисельні такти виникає абсолютна похибка квантування коефіцієнта заповнення `ΔD`, граничне значення якої не перевищує половини мінімального дискретного кроку `ΔD_max = ΔD_pwm ÷ 2`. Для фактично згенерованого заповнення `D_actual` відносна похибка квантування `ε_quant` обчислюється як:

```
ε_quant = (ΔD ÷ D_req) × 100            [розрахунок відносної похибки від запитаного заповнення]
        = (0.05 ÷ 35.4) × 100            [підстановка максимального відхилення 0.05% та D_req = 35.4%]
        ≈ 0.141%                         [максимальна відносна похибка дискретизації]
```

Отриманий результат показує високу точність утримання симетрії імпульсів у низькочастотному діапазоні, що відповідає специфікаціям периферійних таймерів, розгляданих в [огляді мікроконтролера ESP8266](root:cat-hw-boards/esp8266-soc-architecture-overview).

## Часовий баланс UART та гранична частота

При побудові автоматизованих вимірювальних систем виникає задача розрахунку максимально припустимої частоти опитування датчиків через послідовний порт (від англ. @@en|Universal Asynchronous Receiver-Transmitter@@, @@en|UART@@). Швидкість обміну даними (англ. @@en|baud rate@@) визначає число бітів, що передаються за одну секунду. З урахуванням кадрування (1 старт-біт, 8 бітів даних, 1 стоп-біт) кожен байт вимагає передачі `N_bits = 10` фізичних бітів.

Час передачі одного байта `t_byte` при швидкості `B = 115200` бод обчислюється формулою:

```
t_byte
= N_bits ÷ B                         [ділення кількості бітів на швидкість baud rate]
= 10 ÷ 115200                        [підстановка 10 бітів та швидкості 115200 бод]
≈ 0.0000868 s                        [переведення в секунди]
= 86.8 μs                            [тривалість передачі одного байта]
```

Повний часовий баланс однієї транзакції `t_trans` складається з часу передачі текстового запиту `t_req`, системної затримки обробки парсером `t_proc` та часу прийому відповіді `t_resp`. При активації апаратного контролю потоку (англ. @@en|Hardware Flow Control@@, @@en|RTS/CTS@@ — від англ. @@en|Request to Send / Clear to Send@@) у шині @@en|UART@@ часовий баланс ускладнюється через паузові затримки арбітражу буфера. Коли приймальний буфер @@en|FIFO@@ ESP8266 досягає верхнього порогу заповнення під час системної обробки `t_proc`, лінія `RTS` переходить у високий стан, блокуючи передачу хоста на додатковий час очікування `t_wait_hfc`. У результаті скоригований час транзакції `t_trans_hfc` та ефективна пропускна здатність шини `BW_eff_hfc` в байтах на секунду обчислюються як:

```
t_trans_hfc = (N_req + N_resp) · t_byte + t_proc + t_wait_hfc
BW_eff_hfc  = (N_req + N_resp) ÷ t_trans_hfc
```

Розглянемо приклад опитування аналогово-цифрового перетворювача командою `AT+SYSADC?` (довжина запиту `N_req = 12` байтів з урахуванням `\r\n`) та відповіддю `+SYSADC:742\r\n\r\nOK\r\n` (`N_resp = 17` байтів):

```
t_trans
= (N_req + N_resp) × t_byte + t_proc  [сумування часу передачі та обробки]
= (12 + 17) × 86.8 + 1500             [підстановка 29 байтів та затримки парсера 1.5 мс]
= 29 × 86.8 + 1500                    [обчислення байтового часу передачі]
= 2517.2 + 1500                       [додавання затримки виконання]
= 4017.2 μs                           [сумарна часова затримка транзакції]
≈ 4.02 ms                             [переведення в мілісекунди]
```

Гранична теоретична частота опитування `f_poll_max` становить `f_poll_max = 1 ÷ t_trans = 1 ÷ 0.00402 ≈ 248.7` Гц. Для запобігання переповненню апаратного приймального буфера в [модулях ESP-01](root:cat-hw-boards/esp-01) при безперервному потоці даних рекомендована робоча частота опитування повинна становити не більше 50–100 Гц. При підвищенні швидкості послідовного порту до `B = 921600` бод тривалість передачі одного байта зменшується до `t_byte = 10 ÷ 921600 ≈ 10.85` мкс, а сумарний час передачі 29 байтів кадру падає до `t_frame = 29 × 10.85 ≈ 314.65` мкс. З урахуванням системної затримки парсера `t_proc = 1500` мкс нова затримка транзакції `t_trans` обчислюється так:

```
t_trans
= t_frame + t_proc                   [сумування часу кадру та затримки парсера]
= 314.65 + 1500                      [підстановка обчисленого часу передачі]
= 1814.65 μs                         [сумарний час транзакції в мікросекундах]
≈ 1.81 ms                            [переведення в мілісекунди]
```

Гранична частота зростає до `f_poll_max = 1 ÷ 0.001815 ≈ 551` Гц. Для практичної частоти опитування `f_poll = 100` Гц (з періодом `T_poll = 10` мс) коефіцієнт завантаження лінії `K_load` та запас міцності `M_safe` визначаються співвідношеннями:

```
K_load
= t_trans ÷ T_poll                   [відношення часу транзакції до періоду опитування]
= 1.815 ÷ 10                         [підстановка значень у мілісекундах]
= 0.1815                             [коефіцієнт завантаження]
= 18.15%                             [відсоткова частка часового ресурсу]
```

Запас міцності становить `M_safe = 100% - K_load = 81.85%`, що гарантує відсутність переповнення буфера та забезпечує часовий резерв для фонових задач стека.
