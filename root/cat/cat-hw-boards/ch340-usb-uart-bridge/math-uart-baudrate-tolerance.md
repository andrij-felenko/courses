## Спотворення даних при UART-обміні

Підключення плати з роз'ємом Type-C на базі мікросхеми CH340, якою оснащена [плата-адаптер для ESP32-CAM](root:cat-hw-boards/esp32-cam-programmer), іноді підносить неприємний сюрприз: у моніторі послідовного порту замість очікуваних текстових повідомлень з'являється набір хаотичних символів. Налаштування швидкості на комп'ютері й у програмі мікроконтролера виставлені однаково — наприклад, 115200 @@en|baud rate@@ (англ. *baud* — бод, одиниця швидкості маніпуляції). Проте приймач періодично втрачає байтові межі й фіксує помилку кадрування @@en|framing error@@ (англ. *frame* — кадр, *error* — помилка).

Причина цього явища криється у фізичній природі послідовного інтерфейсу @@en|UART@@ (англ. *Universal Asynchronous Receiver-Transmitter* — універсальний асинхронний приймач-передавач). На відміну від синхронних шин, асинхронний зв'язок не має окремої лінії передачі тактового сигналу. Приймач і передавач спираються виключно на власні локальні тактові генератори.

Тривалість передачі одного біта `T_bit` прямо залежить від обраної швидкості обміну `BaudRate`:

```
T_bit = 1 / BaudRate
      = 1 / 115200          [підстановка номінальної швидкості]
      ≈ 8.68 μs            [тривалість бітового інтервалу]
```

Проте реальна точка синхронізації на початку кадру `t = 0` зміщується ще до початку відліку бітових інтервалів через асиметрію фізичних процесів у лінії. Еквівалентна паразитна ємність лінії `C_line` @@en|parasitic capacitance@@ (англ. *parasite* від грец. *parasitos* — утриманець, та лат. *capacitas* — місткість) разом із опорами вихідного каскаду формує RC-кола з різними сталими часу розряджання та заряджання. При спадному фронті стартового біта активний N-канальний транзистор розряджає ємність через низький опір `R_dn`, задаючи малу сталу часу `τ_fall = R_dn · C_line` та швидкий спад сигналу до порогової напруги приймача `V_th` за час `t_fall = τ_fall · ln(V_CC / V_th)`. Натомість відновлення високого рівня відбувається через значно більший опір підтягувального резистора `R_up > R_dn` зі сталою часу `τ_rise = R_up · C_line`, затягуючи зростання сигналу до часу `t_rise = τ_rise · ln(V_CC / (V_CC - V_th))`. Різниця цих часових інтервалів визначає початковий фазовий зсув:

```
Δt_init = t_rise - t_fall
        = (τ_rise - τ_fall) · ln(2)        [підстановка V_th = 0.5 × V_CC]
        = (R_up - R_dn) · C_line · ln(2)   [різниця часових констант заряджання та розряджання]
```

Цей початковий фазовий зсув `Δt_init` зміщує момент детектування стартового фронту від ідеальної часової позначки `t = 0`, зменшуючи допустимий часовий запас для подальших вибірок даних.

```
T_bit = 1 / BaudRate
      = 1 / 115200          [підстановка номінальної швидкості]
      ≈ 8.68 μs            [тривалість бітового інтервалу]
```

Якщо реальна частота генератора передавача або приймача відхиляється від номінального значення навіть на відсоток, фактична тривалість біта `T_bit` змінюється. Оскільки синхронізація відбувається лише один раз на початку кожного кадру за спадним фронтом стартового біта, на початковий момент відліку `t = 0` одразу впливає асиметрія тривалості спадного та висхідного фронтів сигналу. Через різницю швидкостей перезаряду паразитної ємності лінії крутий спадний фронт детектується швидше за пологий висхідний, утворюючи початковий фазовий зсув ще до початку зчитування даних. Надалі це відхилення швидкостей накопичується з кожним наступним бітом: на початку кадру така похибка є непомітною, але до кінця байта моменти зчитування сигналу зміщуються від безпечного центра біта до його нестабільних країв.

Для оцінки стійкості зв'язку необхідно дослідити внутрішній математичний механізм тактування прийому — систему 16-кратного передискретизування кадру.

Саме на межах бітових інтервалів найменший зсув моменту вибірки призводить до зчитування неправильного логічного стану, що й спричиняє появу хаотичних символів. Оскільки асинхронний приймач позбавлений зовнішнього тактового сигналу, єдиним способом утримати точку вимірювання в безпечному центрі біта є суворий контроль відносного відхилення частот обох пристроїв. Обчислення цих часових допусків дозволяє визначити критичну межу похибки швидкості, за якої зв'язок залишається надійним.

## Модель 16-кратного передискретизування кадру UART

Щоб надійно зчитати вхідний потік даних без спільного тактового сигналу, приймач UART застосовує технологію @@en|oversampling@@ (англ. *over* — понад, *sample* — вибірка, зразок) — передискретизування вхідного сигналу на тактовій частоті `f_oversample`, яка у `N = 16` разів перевищує номінальну швидкість `BaudRate`.

Тривалість одного такту внутрішнього лічильника дискретизації `t_clk` обчислюється через тривалість біта `T_bit`:

```
t_clk = T_bit / 16
```

У стані спокою лінія зв'язку перебуває у високому логічному рівні 1. Початок кадру визначається спадним фронтом — переходом лінії з 1 у 0, що позначає @@en|start bit@@ (англ. *start bit* — стартовий біт). Момент виявлення цього фронту приймач приймає за вихідну точку відліку часу `t = 0`.

Після виявлення спадного фронту приймач відраховує 8 тактів `t_clk` і робить перевірочну вибірку в точці `t = 7.5 · t_clk`, яка відповідає геометричному центру стартового біта. Для захисту від коротких високочастотних імпульсних завад апаратні приймачі виконують мажоритарне голосування: зчитування сигналу здійснюється тричі поспіль на 7-му, 8-му та 9-му тактах дискретизації (`t = 6.5 · t_clk`, `t = 7.5 · t_clk`, `t = 8.5 · t_clk`). Логічне значення біта визначається за більшістю однакових значень серед цих трьох відліків, що фільтрує поодинокі голчасті завади в центрі бітового інтервалу. Якщо мажоритарний підсумок підтверджує низький рівень 0, стартовий біт вважається дійсним, і лічильник переходить у режим відліку інтервалів по 16 тактів для кожного з наступних бітів кадру.

Математичний ефект придушення завад мажоритарним голосуванням 2 з 3 @@en|majority voting@@ (англ. *majority* від лат. *major* — більший, та *vote* — голос) визначається ймовірністю одночасного спотворення двох або трьох сусідніх відліків. Якщо ймовірність появи випадкового імпульсного шуму під час зчитування одного такту становить `p`, то помилка прийняття рішення виникає лише тоді, коли хибний рівень зафіксовано принаймні на двох із трьох відліків 7-го, 8-го чи 9-го тактів. Підсумкова ймовірність помилки детектування `P_err` описується біноміальним розподілом:

```
P_err = 3 × p² × (1 - p) + p³
      = 3 × p² - 2 × p³           [спрощення полінома]
      ≈ 3 × p²                    [при малій ймовірності завади p < 0.1]
```

При рідкісних імпульсних завадах з ймовірністю спотворення поодинокого відліку `p = 0.01` (1%) ймовірність помилкового визначення значення біта знижується до `P_err ≈ 3 × (0.01)² = 0.0003` (0.03%), тобто результуюча завадостійкість зростає більше ніж у 30 разів.

Кадр стандартного формату 8N1 містить `M = 10` бітів: 1 стартовий біт, 8 бітів даних (`D0`–`D7`) та 1 @@en|stop bit@@ (англ. *stop bit* — стоповий біт).

![{Схема часової діаграми 10-бітного кадру UART з позначенням 16 тактових імпульсів на біт та точок вибірки на 8-му відліку}](img/uart-16x-oversampling-frame.svg)
*Часова діаграма 10-бітного кадру UART 8N1 із 16-кратним передискретизуванням та точками вибірки в середині кожного біта.*

Номінальний час вибірки `t_sample(k)` для `k`-го біта кадру (де `k ∈ {0, 1, 2, ..., 9}`) розраховується за формулою:

```
t_sample(k) = (k + 0.5) × T_bit
            = (k + 0.5) × 16 × t_clk      [вираження через такти дискретизації]
            = (16 × k + 8) × t_clk        [розкриття дужок]
```

Розрахуємо теоретичні точки вибірки для ключових бітів кадру:

```
t_sample(0) = (16 × 0 + 8) × t_clk = 8 × t_clk     [центр стартового біта]
t_sample(1) = (16 × 1 + 8) × t_clk = 24 × t_clk    [центр першого біта даних D0]
t_sample(8) = (16 × 8 + 8) × t_clk = 136 × t_clk   [центр восьмого біта даних D7]
t_sample(9) = (16 × 9 + 8) × t_clk = 152 × t_clk   [центр стопового біта]
```

При розсинхронізації генераторів передавача та приймача на відносну величину `δ` (де `δ = (BaudRate_rx - BaudRate_tx) / BaudRate_tx`) реальний момент вибірки зміщується. Накопичений часовий зсув фази `Δt_phase(k)` для `k`-го біта становить:

```
Δt_phase(k) = k × δ × T_bit
```

Найбільша величина зсуву фази накопичується до моменту зчитування стопового біта при `k = 9.5` бітових інтервалів від початкового фронту.

## Математичне обґрунтування межі розсинхронізації 2,5%

Щоб зчитане значення біта було достовірним, точка вибірки приймача повинна потрапляти в інтервал стабільного логічного рівня сигналу. Оскільки тривалість біта дорівнює `T_bit`, а ідеальна точка вибірки розташована в його центрі (`0.5 × T_bit`), теоретичне вікно допустимого зміщення становить `±0.5 × T_bit`.

Однак через апаратну дискретність прийому 16-кратним тактовим сигналом реальне вікно звужується. Детектування спадного фронту стартового біта може відбутися з затримкою до одного такту `t_clk`, що дає невизначеність синхронізації в `±0.5 × t_clk` (тобто `±0.03125 × T_bit`). З урахуванням цієї похибки дискретизації максимально допустимий фазовий зсув `Δt_max` становить:

```
Δt_max = (0.5 - 0.0625) × T_bit
       = 0.4375 × T_bit             [безпечна півширина вікна вибірки]
```

Визначаємо граничне відносне відхилення швидкостей `δ_max` із умови, що накопичений зсув на стоповому біті (`k = 9.5` бітових інтервалів) не перевищує безпечного вікна `Δt_max`:

```
Δt_phase(9.5) = 9.5 × δ_max × T_bit
9.5 × δ_max × T_bit = 0.4375 × T_bit       [рівняння граничного стану]
δ_max = 0.4375 / 9.5                       [ділення на інтервал кадру]
      ≈ 0.04605                            [теоретичний допуск 4.61%]
```

![{Діаграма фазового зсуву точки вибірки відносно центру бітового інтервалу при розсинхронізації швидкостей}](img/uart-baudrate-phase-drift-tolerance.svg)
*Зсув точки вибірки впродовж 10-бітного кадру при похибці швидкості та межа допуску в 2,5%.*

У реальних фізичних колах передачі даних присутній фазовий джитер @@en|jitter@@ (від англ. @@en|jitter@@, тремтіння фази) та скінченна швидкість наростання фронтів через паразитну ємність лінії. Математична модель описує це розширення фронту через сталу часу `τ = R × C` (від англ. @@en|RC time constant@@), де вихідний опір драйвера й лінії `R` разом із паразитною ємністю `C` формують експоненціальний процес заряджання `u(t) = U_CC × (1 - e⁻ᵗ/τ)`. Тривалість наростання сигналу до порогу спрацьовування приймача `t_rise ≈ τ × ln(2) ≈ 0.693 × R × C` зміщує момент переходу логічного рівня, перетворюючи ідеальний прямокутний імпульс на трапецієподібний і скорочуючи тривалість ділянки зі стабільним логічним рівнем. Разом із тремтінням фази це розмивання фронтів додатково звужує вікно стабільності сигналу приблизно на `±0.21 × T_bit`.

У результаті практична гранично допустима похибка швидкості обміну зменшується до:

```
δ_practical ≈ ±2.5%
```

Якщо сумарна розсинхронізація між приймачем і передавачем перевищує `|δ_total| > 5%` (або похибка кожного з пристроїв перевищує `±2.5%`), точка вибірки стопового біта зсувається за межі його часового інтервалу. Приймач замість високого рівня 1 зчитує низький рівень сусіднього біта, що призводить до реєстрації @@en|framing error@@ та втрати всього кадру даних.

## Розрахунок похибки швидкості обміну CH340

При спробі встановити високу або нестандартну швидкість передачі даних через мікросхему CH340 розробники часто стикаються з раптовою появою помилок кадрування (@@en|framing error@@). Причина полягає в тому, що інтегральний USB-UART мост не може синтезувати довільну частоту тактування шини. Внутрішній генератор CH340 працює на фіксованій опорній частоті `f_clk = 12` МГц (`12 · 10⁶` Гц), а будь-яка задана швидкість обміну (@@en|baud rate@@) отримується шляхом цілочисельного або дискретного ділення цієї частоти.

Формування тактової частоти передавача й приймача в CH340 описується коефіцієнтом ділення `N_div`, який обчислюється відносно заданої номінальної швидкості `B_target`. Для режимів із 16-кратним передискретизуванням (@@en|oversampling@@) цей параметр показує співвідношення між частотою внутрішнього генератора `f_clk = 12` МГц та базовим тактуванням кадру. При виборі надвисокої швидкості `921 600` біт/с дробове значення дільника виходить меншим за одиницю, що виставляє апаратне обмеження дільника `N_act = 1.0` і призводить до виходу похибки далеко за допустимі межі:

**Обчислення похибки CH340 для високошвидкісного режиму 921 600 біт/с**

```
N_div = 12000000 / (16 × 921600)
= 12000000 / 14745600                  [розрахунок знаменника для 16x oversampling]
≈ 0.8138                             [теоретичний дробовий дільник]

N_act = max(1.0, round(0.8138))
= 1.0                                [найменший допустимий дільник для 16x]

B_real = 12000000 / (16 × 1.0)
= 750000.0                           [гранично можлива швидкість при 16x]

E_baud = ((750000 - 921600) / 921600) × 100%
= (-171600 / 921600) × 100%          [абсолютна різниця частот]
≈ -18.62%                            [критична похибка]
```

Отримана похибка `E_baud = -18.62%` катастрофічно перевищує межу `2.5%`, через що передача 10-бітного кадру на цій швидкості при 16-кратному oversampling є неможливою без перемикання дільника у режим зменшеного передискретизування.

`N_div = f_clk / (16 × B_target)`

Оскільки апаратний лічильник дільника мікросхеми оперує дискретними значеннями з кроком `0.5` (завдяки внутрішньому дільнику (@@en|prescaler@@)), фактичне значення дільника `N_act` є результатом заокруглення розрахованого значення `N_div` до найближчого підтримуваного кроку:

`N_act = round(N_div)`

Через таке заокруглення фактично згенерована швидкість передачі `B_real` відрізняється від бажаної:

`B_real = f_clk / (16 × N_act)`

Відносна апаратна похибка швидкості обміну `E_baud` (@@en|baud rate error@@) виражається у відсотках і показує відхилення реальної швидкості від номінальної:

`E_baud = ((B_real - B_target) / B_target) × 100%`

При налаштуванні зв'язку, наприклад під час прошивки мікроконтролера через [програматор CH340](root:cat-hw-boards/esp32-cam-programmer), важливо знати, чи не перевищує ця похибка допустимий поріг у `2.5%`.

**Обчислення похибки CH340 для стандартної швидкості 115 200 біт/с**

```
N_div = 12000000 / (16 × 115200)
= 12000000 / 1843200                  [знаменник для 16-кратного oversampling]
≈ 6.5104                             [дробовий розрахований дільник]

N_act = round(6.5104)
= 6.5                                [найближчий апаратний крок дільника]

B_real = 12000000 / (16 × 6.5)
= 12000000 / 104                     [фактичний коефіцієнт ділення]
≈ 115384.6                           [фактична швидкість у біт/с]

E_baud = ((115384.6 - 115200) / 115200) × 100%
= (+184.6 / 115200) × 100%           [абсолютне відхилення частоти]
≈ +0.16%                             [відносна похибка]
```

Для стандартної швидкості `115 200` біт/с похибка дільника становить лише `+0.16%`, що значно менше за критичну межу `2.5%`. Порівнюючи з іншими рішеннями, як-от [адаптер CP2102](root:cat-hw-boards/cp2102-usb-uart), CH340 впевнено забезпечує стабільне з'єднання на цій швидкості.

Однак при використанні нестандартних швидкостей, наприклад `128 000` біт/с, ситуація змінюється:

**Обчислення похибки CH340 для нестандартної швидкості 128 000 біт/с**

```
N_div = 12000000 / (16 × 128000)
= 12000000 / 2048000                  [обчислення теоретичного дільника]
= 5.8593                             [дробове значення]

N_act = round(5.8593)
= 6.0                                [заокруглення до найближчого кроку]

B_real = 12000000 / (16 × 6.0)
= 12000000 / 96                      [фактичний коефіцієнт ділення]
= 125000.0                           [фактична швидкість у біт/с]

E_baud = ((125000 - 128000) / 128000) × 100%
= (-3000 / 128000) × 100%            [відхилення швидкості]
= -2.34%                             [відносна похибка]
```

Значення `E_baud = -2.34%` формально перебуває в межах `2.5%`, але залишає критично малий запас міцності — усього `0.16%`. Будь-який додатковий часовий зсув призведе до збоїв зв'язку.

Цей залишковий запас у `0.16%` стає першою жертвою реальних умов експлуатації пристрою, адже зміна температури навколишнього середовища чи просідання напруги живлення викликають додатковий дрейф опорної частоти генератора. Оскільки апаратна похибка дільника є незмінною величиною для обраного режиму обміну, будь-яке температурне відхилення додається до неї напряму, виводячи підсумкову похибку за межу допустимого допуску. Це робить оцінку сумарного бюджету часових похибок обов'язковим етапом аналізу стійкості послідовного зв'язку.

## Вплив температурного дрейфу на стійкість

Розрахована апаратна похибка дільника `E_baud` є лише однією зі складових загального часового розбалансу. У реальних умовах тактова частота генератора CH340 зміщується через температурний дрейф (@@en|clock drift@@). Модифікації мікросхеми зі вбудованим RC-генератором піддаються впливу температури навколишнього середовища, що додає додаткову похибку `E_temp`.

Загальний бюджет похибки `E_total` (@@en|error budget@@) каналу зв'язку між CH340 та мікроконтролером складається з трьох незалежних чинників:

`E_total = |E_baud| + |E_temp| + |E_mcu|`

де `|E_baud|` — модуль похибки дільника CH340, `|E_temp|` — відносне відхилення частоти генератора CH340 через нагрів або охолодження, а `|E_mcu|` — власна похибка тактування цільового мікроконтролера.

Для збереження достовірності вибірки бітів у 10-бітному кадрі (@@en|UART@@ 8N1) сумарна похибка повинна задовольняти умову стійкості:

`E_total ≤ 2.5%`

Відповідно, максимально припустимий температурний дрейф `E_temp_max` обмежується залишковим часовим бюджетом:

`E_temp_max = 2.5% - |E_baud| - |E_mcu|`

Якщо температурний коефіцієнт вбудованого @@en|RC-генератора@@ становить `α_temp` (у `% / °C`), то при відхиленні температури `ΔT` від кімнатної додаткова відносна похибка обчислюється як `E_temp = α_temp × ΔT`. Для визначення максимального температурного діапазону `ΔT_max`, у межах якого зв'язок зберігає стійкість, розділимо залишковий часовий бюджет `E_temp_max` на температурний коефіцієнт `α_temp`.

Припустимо, що для швидкості 115200 @@en|бод@@ похибка дільника `|E_baud| = 0.16%`, власна похибка тактування мікроконтролера `|E_mcu| = 0.8%`, а коефіцієнт дрейфу генератора `α_temp = 0.025% / °C`:

```
E_temp_max = 2.5% - |E_baud| - |E_mcu|    [гранична температурна похибка]
           = 2.5% - 0.16% - 0.8%          [підстановка величин похибок]
           = 1.54%                        [залишковий бюджет похибки]
ΔT_max     = E_temp_max / α_temp          [граничний температурний діапазон]
           = 1.54 / 0.025                 [ділення бюджету на коефіцієнт дрейфу]
           = 61.6                         [максимальне відхилення в °C]
```

Отриманий результат `ΔT_max = 61.6 °C` показує, що при номінальній кімнатній температурі +25 °C пристрій зберігає стійкий обмін даними в робочому діапазоні від -36.6 °C до +86.6 °C, що повністю перекриває стандартні промислові вимоги до електронного обладнання.

`E_temp = α_temp × ΔT`

Розглянемо практичний випадок, коли цільовий мікроконтролер має власну похибку RC-генератора `|E_mcu| = 0.8%`, а температурний зсув генератора CH340 під навантаженням створює `|E_temp| = 0.5%`.

**Обчислення сумарного бюджету похибки при нестандартній швидкості 128 000 біт/с**

```
E_total = |E_baud| + |E_mcu| + |E_temp|
= 2.34% + 0.8% + 0.5%                 [додавання всіх джерел похибки]
= 3.64%                               [сумарне відхилення частоти]
```

Оскільки `3.64% > 2.5%`, сумарний фазовий зсув перевищує безпечний інтервал 16-кратного передискретизування (@@en|oversampling@@). Строб вибірки на 10-му біті (стоп-біті) виходить за межі стабільного рівня сигналу, спричиняючи помилку кадрування (@@en|framing error@@).

Тепер проведемо той самий розрахунок для стандартної швидкості `115 200` біт/с:

**Обчислення сумарного бюджету похибки при стандартній швидкості 115 200 біт/с**

```
E_total = |E_baud| + |E_mcu| + |E_temp|
= 0.16% + 0.8% + 0.5%                 [додавання похибок для 115200 біт/с]
= 1.46%                               [сумарне відхилення частоти]
```

Значення `1.46% ≤ 2.5%` підтверджує, що при стандартній швидкості `115 200` біт/с лінійка швидкостей CH340 зберігає достатній запас стійкості навіть при температурних коливаннях та нестабільності внутрішнього генератора мікроконтролера.
