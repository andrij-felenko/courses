## Проблема прямого доступу до периферії SoC

Під час розробки високонавантажених вбудованих систем виникають задачі, у яких стандартні високорівневі абстракції SDK та інтерпретатор [керування GPIO виводами ESP8266 через AT-команди](root:cat-hw-boards/esp8266-at-gpio-control) виявляються занадто повільними. Програмні обгортки викликів базового API створюють значні накладні витрати на обчислення масок, перевірку переданих аргументів та збереження контексту функцій. Наприклад, виклик високорівневої функції вимагає від 30 до 50 тактових циклів процесора (близько 375–625 нс при базовій частоті 80 МГц) лише на збереження контексту та перевірки аргументів, тоді як прямий запис у регістр через відображений у пам'ять ввід-вивід @@en|memory-mapped I/O@@ виконується всього за 1–2 тактові цикли (12.5–25 нс). У задачах генерації прецизійних часових імпульсів, генерації програмного шімування чи реалізації протоколів швидкого біт-бенгінгу @@en|bit-banging@@ така різниця у кілька мікросекунд призводить до спотворення сигналів на фізичній лінії.

Для забезпечення максимальної швидкодії процесорне ядро Xtensa LX106 повинне взаємодіяти з периферійними блоками без посередників через механізм відображення регістрів у пам'ять — @@en|memory-mapped I/O@@ (від англ. *Memory-Mapped Input/Output* — ввід-вивід із відображенням у простір пам'яті). Шляхом прямого розіменування volatile-вказівників на фізичні адреси блоку @@en|IOMUX@@ та регістрів @@en|GPIO@@ розробник виконує запис та зчитування станів виводів за один або два тактові цикли процесора, усуваючи системний джитер і гарантуючи строго детермінований час виконання критичних ділянок коду.

На рівні асемблера процесорного ядра Xtensa LX106 розіменування `volatile`-вказівників транслюється безпосередньо у спеціалізовані інструкції архітектури @@en|load/store@@ (від англ. *load/store* — завантаження та збереження): `l32i` (від англ. *Load 32-bit Immediate*) для читання та `s32i` (від англ. *Store 32-bit Immediate*) для запису 32-бітного слова. Використання модифікатора `volatile` блокує оптимізації компілятора, які намагаються зберегти значення регістрів у внутрішніх кеш-регістрах ядра `a0`–`a15` чи вилучити повторні звернення. Інструкція `s32i` передає вміст регістра процесора безпосередньо на периферійну шину за один тактовий цикл, що виключає затримки на збереження стекового кадру. Завдяки цьому прямою інструкцією `s32i` виконують детермінований запис у регістр `GPIO_OUT_W1TS` для генерації швидких сигналів без залучення функцій SDK під час роботи в [архітектурі завантажувача ESP8266](root:cat-hw-boards/esp8266-bootloader-architecture).

:::tabs
@tab C
```c
#include <stdint.h>

// Прямий атомарний запис через інструкцію s32i
void set_gpio2_high(void) {
    *(volatile uint32_t *)0x60000304 = (1 << 2);
}

// Пряме читання вхідних рівнів через інструкцію l32i
uint32_t read_gpio_inputs(void) {
    return *(volatile uint32_t *)0x60000318;
}
```

## Фізичний розподіл пам'яті та шини AHB/APB

Апаратна архітектура систем на кристалі ESP8266 спирається на 32-бітний заповнений адресний простір обсягом 4 ГБ, у якому кожен фізичний блок пам'яті та периферійний модуль має чітко закріплений діапазон адрес.

![Схема 32-бітного адресового простору ESP8266 з відображенням блоків IRAM, DRAM, IROM та периферійних шин AHB/APB](img/esp8266-soc-address-space-map.svg)
*Схема 32-бітного адресового простору ESP8266 з відображенням блоків IRAM, DRAM, IROM та периферійних шин AHB/APB.*

Основна пам'ять системи розділена на кілька специфічних зон:
- `0x40000000` – `0x4000FFFF`: маскове ПЗП @@en|Mask ROM@@ (64 КБ), що містить первинний завантажувач та базові системні функції.
- `0x40100000` – `0x4010BFFF`: внутрішня оперативна пам'ять інструкцій @@en|IRAM@@ (від англ. *Instruction RAM* — оперативна пам'ять інструкцій) обсягом 32 КБ, з якої ядро виконує критичні обробники переривань без затримок кешу.
- `0x3FFE8000` – `0x3FFFFFFF`: оперативна пам'ять даних @@en|DRAM@@ (від англ. *Data RAM* — оперативна пам'ять даних) обсягом 80 КБ для стеків, динамічної купи та статичних змінних.
- `0x40200000` – `0x403C0000`: область @@en|IROM@@ (від англ. *Instruction ROM* — пам'ять інструкцій ROM), яка через контролер кешу динамічно відображає код з флеш-пам'яті, що описують [режими завантаження мікроконтролера ESP8266](root:cat-hw-boards/esp8266-boot-modes).
- `0x60000000` – `0x600013FF`: конфігураційні регістри периферійних модулів (GPIO, IOMUX, UART, SPI, Timers).

Система шин SoC використовує дві різні архітектурні магістралі для обміну даними. Для високошвидкісного безпосереднього пересилання великих масивів даних між периферією та оперативною пам'яттю задіяно апаратну шину @@en|AHB@@ (від англ. *Advanced High-performance Bus* — системна шина високої продуктивності), через яку працюють апаратні канали прямого доступу до пам'яті @@en|DMA@@ (від англ. *Direct Memory Access* — прямий доступ до пам'яті) на системній частоті процесора 80 або 160 МГц. У той же час доступ процесорного ядра до керуючих регістрів периферії здійснюється через периферійну шину @@en|APB@@ (від англ. *Advanced Peripheral Bus* — периферійна шина), яка працює на тактовій частоті 80 МГц і з'єднана з шиною AHB через спеціалізований міст-арбітр. Оскільки міст здійснює міжшинну синхронізацію тактових частот і узгодження фаз, кожне зчитування або запис у регістри APB спричиняє затримку у 2–4 тактові цикли очікування @@en|wait states@@. Якщо в цей момент шина AHB заблокована інтенсивним DMA-обміном, міст-арбітр тимчасово призупиняє процесорне ядро, що збільшує затримку доступу до регістрів. Розуміння цієї різниці дозволяє уникнути конфліктів шинного арбітражу під час одночасної обробки DMA-транзакцій та прямого запису в конфігураційні регістри.

Під час виникнення шинних блокувань @@en|bus lock@@ (від англ. *bus lock* — блокування шини) мостовий арбітр APB/AHB переходить у режим примусового стримування процесорного ядра, щоб запобігти колізіям під час одночасного доступу до ресурсів. Коли контролер прямого доступу до пам'яті виконує пакетну передачу даних по шині @@en|AHB@@ або контролер кешу блокує магістраль для підвантаження інструкцій з флеш-пам'яті, арбітр тимчасово призупиняє приймання запитів процесора до периферійного простору `0x60000000`. Оскільки ядро Xtensa LX106 не може завершити конвеєрну інструкцію зчитування чи запису в регістри @@en|APB@@ без підтвердження транзакції від мосту, апаратна логіка арбітра змушує прошивати конвеєр порожніми тактами. Це породжує стілл-цикли @@en|stall cycles@@ (від англ. *stall cycle* — цикл зупинки конвеєра), під час яких виконання коду повністю заморожується до моменту вивільнення шини. Крім того, при серії швидких послідовних записів у конфігураційні регістри внутрішній буфер мосту переповнюється, викликаючи апаратний шинний затор @@en|bus stall@@ (від англ. *bus stall* — зупинка шинного обміну), що збільшує затримку обробки переривань на 10–20 тактових циклів і вимагає оптимізації реалтайм-коду.

## Карта регістрів GPIO та мультиплексор IOMUX

Кожен фізичний вивід системи на кристалі ESP8266 є мультиплексованим і з'єднується з внутрішніми периферійними блоками через мультиплексор вводу-виводу @@en|IOMUX@@ (від англ. *Input/Output Multiplexer* — мультиплексор вводу-виводу). Базова адреса регістрів конфігурації IOMUX розташована за зміщенням `0x60000800`. Для кожного фізичного контакту виділено окремий 32-бітний регістр `PERIPHS_IO_MUX_<pin>_U`, бітові поля якого задають призначену функцію (селектор `FUNC` від 0 до 3), підключення внутрішнього підтягувального резистора (біт `FUNC_PULLUP`), підтяжки до землі (біт `FUNC_PULLDOWN`) та навантажувальну здатність вихідного каскаду.

![Структурна схема мультиплексора IOMUX та регістрів керування станами GPIO-каскадів](img/esp8266-iomux-gpio-control-block.svg)
*Структурна схема мультиплексора IOMUX та регістрів керування станами GPIO-каскадів.*

Після перемикання селектора `IOMUX` у режим загального призначення (GPIO) керування електричним станом лінії передається блоку регістрів GPIO (базова адреса `0x60000300`). Контролер використовує атомарні регістри запису одиниці для встановлення та скидання бітів, що виключає ризик гонки даних @@en|race condition@@ при паралельному доступі:
- `GPIO_ENABLE_W1TS` (`0x60000310`): запис `1` у відповідну позицію переводить вивід у режим виходу (Set Enable).
- `GPIO_ENABLE_W1TC` (`0x60000314`): запис `1` вимикає вихідний буфер і переводить вивід у режим входу (Clear Enable).
- `GPIO_OUT_W1TS` (`0x60000304`): запис `1` встановлює на виводі високий логічний рівень 3.3 В.
- `GPIO_OUT_W1TC` (`0x60000308`): запис `1` встановлює низький рівень 0 В.
- `GPIO_IN` (`0x60000318`): регістр прямого читання поточних логічних станів усіх цифрових входів.
- `GPIO_STATUS` (`0x6000031C`), `GPIO_STATUS_W1TS` (`0x60000320`) та `GPIO_STATUS_W1TC` (`0x60000324`): атомарні регістри читання, фіксації та квитування прапорів апаратних переривань для кожного виводу.
- `GPIO_PINx` (`0x60000328 + x × 4` для кожної ніжки `x` від `0` до `15`): індивідуальні регістри конфігурації виводу, де поле `INT_TYPE` (біти `7..9`) задає умову спрацювання переривання (від англ. @@en|Interrupt Type@@, тип переривання): `1` — наростаючий фронт, `2` — спадаючий фронт, `3` — будь-який фронт, `4` — низький рівень, `5` — високий рівень.

Потреба у перенаправленні функцій периферійних інтерфейсів виникає при конфліктах ліній під час розведення плати чи підключення до [огляду сімейства Wi-Fi модулів](root:cat-hw-boards/esp-01-module-family-overview). Мультиплексор вводу-виводу дозволяє перемикати призначення виводів (від англ. *pin multiplexing*) шляхом модифікації бітового селектора `MCU_SEL` у регістрі `PERIPHS_IO_MUX_<pin>_U`. Наприклад, для перенаправлення апаратного інтерфейсу @@en|HSPI@@ на альтернативні ніжки `GPIO13` (лінія MOSI) та `GPIO14` (лінія CLK) біти функції маскують і записують значення альтернативного селектора `0x2`. Це вимикає пряме керування через регістри `GPIO_OUT` і підключає вивід безпосередньо до апаратного контролера периферії на шині @@en|APB@@.

## Специфікація та регістри контролера DMA

Для вивільнення обчислювальних ресурсів ядра Xtensa LX106 при обміні великими масивами даних в ESP8266 задействовано контролер прямого доступу до пам'яті @@en|DMA@@ (від англ. *Direct Memory Access* — прямий доступ до пам'яті). Модуль DMA функціонує на системній шині AHB і здатний апаратно пересилати байти між оперативною пам'яттю DRAM та FIFO-буферами периферійних інтерфейсів @@en|HSPI@@ (від англ. *High-Speed Serial Peripheral Interface*) та @@en|I2S@@ (від англ. *Inter-IC Sound* — міжмікросхемна звукова шина) без залучення процесора.

Організація передавання опирається на зв'язані списки дескрипторів пам'яті, які розробник розміщує у DRAM. Кожен дескриптор являє собою 12-байтову структуру:

```c
typedef struct lldesc_s {
    uint32_t length : 12;      // Фактичний розмір корисних даних у байтах
    uint32_t size   : 12;      // Загальна ємність буфера в DRAM
    uint32_t sub_sof: 1;       // Початок суб-кадру
    uint32_t reserved: 5;      // Зарезервоване поле
    uint32_t eof    : 1;       // Ознака кінця кадру (End of Frame)
    uint32_t owner  : 1;       // Прапор володіння (1 — DMA, 0 — CPU)
    uint8_t* buf;              // Вказівник на буфер у DRAM
    struct lldesc_s* next_link;// Вказівник на наступний дескриптор списку
} lldesc_t;
```

Керування каналами здійснюється через спеціалізовані регістри периферійного модуля (на прикладі HSPI):
- `SPI_DMA_IN_LINK` (`0x60000E8C`): визначає початкову адресу дескриптора прийому та запускає вибірку бітом `SPI_DMA_INLINK_START`.
- `SPI_DMA_OUT_LINK` (`0x60000E88`): встановлює початковий дескриптор передачі та запускає відправлення бітом `SPI_DMA_OUTLINK_START`.
- `SPI_DMA_CONF` (`0x60000E84`): відповідає за скидання FIFO-буферів (`SPI_AHBM_RST`, `SPI_AHBM_FIFO_RST`) та вибір пріоритетів шинного арбітражу.

Для організації безперервної передачі потокових даних у [мережеві сокети TCP](root:cat-hw-boards/esp01-tcp-udp-sockets) без участі ядра процесора створюють кільцевий зв'язаний список (від англ. *linked list*) з декількох дескрипторів. У цій схемі вказівник `next_link` останнього дескриптора вказує на перший дескриптор, утворюючи зациклений @@en|ring buffer@@ у пам'яті @@en|DRAM@@. Контролер @@en|DMA@@ почергово вибирає буфери, зчитує дані й автоматично переходить до наступного вузла списку. Якщо процесор @@en|CPU@@ не встигає обробити вивільнений буфер і встановити прапор `owner` у `1` до повернення контролера, @@en|DMA@@ зупиняє передачу на цьому дескрипторі для запобігання втраті даних.

При завершенні обробки кадру контролер DMA автоматично скидає біт `owner` у `0`, повертаючи контроль над буфером процесору, та генерує переривання `SPI_DMA_IN_SUC_EOF_INT`. Це дозволяє організовувати безперервні кільцеві буфери потокового аудіо або мережевих кадрів під час виконання [оновлення прошивки ESP8266 по повітрю (FOTA)](root:cat-hw-boards/esp8266-fota-update).

Обробка переривання кінця кадру (від англ. *EOF interrupt*) починається у момент, коли біт `SPI_DMA_IN_SUC_EOF_INT` виставляється у регістрі `SPI_INT_ST`. Процесорний обробник @@en|ISR@@ (від англ. *Interrupt Service Routine* — служба обробки переривань) першочергово скидає прапор квитування у регістрі `SPI_INT_CLR` записом `1` у біт `SPI_DMA_IN_SUC_EOF_INT_CLR`. Після підтвердження переривання процесор зчитує прийняті байти з буфера DRAM, після чого вручну повертає прапор `owner = 1` у структурі дескриптора. Якщо контролер @@en|DMA@@ призупинив вибірку кільцевого списку через затримку ядра, відтворення поновлюють повторним записом біта `SPI_DMA_INLINK_START` у регістрі `SPI_DMA_IN_LINK`, що гарантує безперервну потокову роботу без втрати синхронізації при обміні з [мережевими сокетами TCP](root:cat-hw-boards/esp01-tcp-udp-sockets).

## Електричні межі та тригери Шмітта

Виводи @@en|GPIO@@ (з англ. @@en|General-Purpose Input/Output@@ — виводи загального призначення) у мікроконтролері ESP8266 виготовлені за технологією @@en|CMOS@@ (з англ. @@en|Complementary Metal-Oxide-Semiconductor@@ — комплементарний метал-оксид-напівпровідник) з номінальною напругою живлення `V_DD = 3.3 В`. Пряме підключення ліній з напругою 5 В створює високу напруженість електричного поля в затворах транзисторів і призводить до незворотного деструктивного пробою діелектрика. Каскади виводу мають жорстко обмежену навантажувальну здатність: максимальний струм втікання (@@en|sink current@@) та витікання (@@en|source current@@) для кожного виводу становить `12 мА`. При перевищенні цього порога вихідні транзистори виходять із лінійного режиму, кристалізаційне тепло спричиняє локальний перегрів, а внутрішні паразитичні структури можуть увійти в стан засувки (@@en|latch-up@@), що повністю коротить шини живлення SoC.

Для захисту від електричного шуму, наведень та завад під час перехідних процесів усі вхідні цифрові каскади ESP8266 містять @@en|Schmitt trigger@@ (тригер Шмітта, названий на честь винахідника Отто Шмітта). Вхідний каскад реалізує @@en|hysteresis@@ (з грец. ὕстеρησις — відставання): рівень напруги перемикання з логічного нуля в одиницю `V_IH` перевищує рівень зворотного перемикання `V_IL`. За специфікацією ESP8266 поріг низького рівня `V_IL` не перевищує `0.25 × V_DD` (близько 0.825 В), а поріг високого рівня `V_IH` становить не менше `0.75 × V_DD` (близько 2.475 В). Різниця між ними утворює зону завадостійкості завтовшки понад 1.6 В, завдяки чому випадкові коливання напруги на вході не викликають дрижання сигналу чи повторних хибних переривань процесора.

![Порогові рівні напруг тригера Шмітта та КМОН-каскаду ESP8266, що визначають чіткі межі розпізнавання логічних 0 і 1 та завадостійкість входів](img/esp8266-gpio-schmitt-trigger-levels.svg)
*Діаграма вхідних порогових напруг V_IL та V_IH тригера Шмітта ESP8266, яка ілюструє гістерезис і гарантує стабільне зчитування логічних рівнів при перехідних процесах.*

Під час проєктування схем із кнопками або сенсорами з відкритим колектором вивід залишається у стані високого імпедансу. Для збереження стабільного логічного рівня застосовують зовнішній @@en|pull-up resistor@@ (підтягувальний резистор). Його опір `R_pullup` підбирають так, щоб падіння напруги від струму витоку входу `I_leak` (до 1 мкА) не опускало потенціал нижче порога `V_IH = 2.5 В`. Проте, окрім статичного струму витоку, ключовим обмеженням виступає паразитна ємність друкованої плати та вхідного каскаду `C_line` (зазвичай 10–30 пФ). Разом із підтягувальним резистором вона утворює RC-ланцюг, тривалість наростання фронту сигналу в якому визначається формулою `t_rise ≈ 2.2 × R_pullup × C_line`. Вибір надто великого опору (наприклад, 100–800 кОм) розтягує фронт наростання напруги до 5–20 мкс, через що сигнал тривалий час перебуває в невизначеній зоні між порогами `V_IL` та `V_IH`, спричиняючи спотворення завадостійких фронтів і збої у високочастотних протоколах обміну.

**Розрахунок граничного опору підтяжки за струмом витоку**
```text
R_max = (V_DD - V_IH) ÷ I_leak
      = (3.3 - 2.5) ÷ (1 × 10⁻⁶)         [підстановка напруги живлення, порогу V_IH та струму витоку]
      = 0.8 ÷ 0.000001                   [обчислення різниці напруг]
      = 800000 Ом                        [граничний опір 800 кОм]
```

Для забезпечення високої швидкості наростання фронту сигналів на високочастотних шинах опір обмежують значеннями 4.7–10 кОм. Під час підключення зовнішніх резисторів важливо враховувати стан [конфігураційних виводів старту](root:cat-hw-boards/esp8266-boot-strapping-pins), адже надто малий опір підтяжки може випадково змінити режим завантаження SoC.

Окрім розрахунку підтяжки, безпечне узгодження з зовнішньою периферією вимагає струмообмеження та узгодження логічних рівнів напруги. При керуванні світлодіодами, оптопарами чи реле вихідний струм каскаду не повинен перевищувати граничні `12 мА`, що досягається послідовним включенням баластного резистора. Для взаємодії з 5-вольтовими пристроями прямого з'єднання уникають: сигнальні лінії пропускають через двонаправлений узгоджувач рівнів (від англ. *level shifter*) або переводять вивід у режим відкритого стоку (від англ. *open-drain*). Подача 5 В безпосередньо на вхід відкриває паразитичні захисні діоди (від англ. *clamping diode*) між виводом та шиною `V_DD`, через які струм починає підживлювати внутрішні кола @@en|SoC@@, порушуючи штатні [режими завантаження мікроконтролера ESP8266](root:cat-hw-boards/esp8266-boot-modes) та спричиняючи деструктивний пробій.

Окрему специфіку захисту каскадів має вбудований 10-бітний аналого-цифровий перетворювач @@en|ADC@@ (від англ. *Analog-to-Digital Converter* — аналого-цифровий перетворювач) на основі регістра послідовного наближення @@en|SAR@@ (від англ. *Successive Approximation Register*), вхід якого виведено на окремий вивід `TOUT` (або `ADC0`). На відміну від цифрових портів GPIO, вхідний аналоговий тракт чипа розрахований на максимальну вхідну напругу лише `1.0 В`. Пряме підключення до `TOUT` цифрових сигналів із рівнем 3.3 В або 5 В призводить до струмового перевантаження вхідного підсилювача та незворотного виходу з ладу аналогового каскаду. Якщо компактні [модулі ESP-01](root:cat-hw-boards/esp-01) виводять чистий аналоговий вхід кристала без захисту, то системні плати розробки оснащують зовнішнім резистивним дільником напруги (типово 220 кОм / 100 кОм), який пропорційно знижує діапазон вимірюваної напруги від `0–3.3 В` до безпечних `0–1.0 В`. Для обчислення розрахункових номіналів дільника при вимірюванні сигналу `V_in` використовують формулу:

        V_adc = V_in · (R2 ÷ (R1 + R2))
        = 3.3 · (100000 ÷ (230000 + 100000))                  [підстановка опорів 230 кОм та 100 кОм]
        = 3.3 · (100000 ÷ 330000)                             [обчислення суми опорів дільника]
        = 1.0 В                                               [безпечна максимальна напруга на входи ADC]

Дотримання цієї розв'язки повністю унеможливлює потрапляння високої напруги на вхід `TOUT` та гарантує точність оцифрування аналогових сигналів.
