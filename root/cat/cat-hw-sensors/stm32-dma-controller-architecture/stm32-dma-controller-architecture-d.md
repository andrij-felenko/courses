# Поглиблений аналіз регістрової моделі DMA, режимів FIFO та Master DMA (MDMA)

Високопродуктивний контролер DMA у мікроконтролерах STM32 — це складний програмований апаратний автомат із власним пулом черг та арбітражем шин. Глибоке розуміння його внутрішньої структури необхідне для виключення апаратних блокувань шини, уникнення помилок виходу за межі 1 КБ (AHB 1KB Boundary Error) та побудови наднадійних відеотрактів високої чіткості.

---

## 1. Детальний аналіз регістрової карти потоку DMA (Stream Registers)

Конфігурація кожного з 8 потоків контролерів DMA1 та DMA2 виконується через спеціалізований блок регістрів `DMA_Stream_TypeDef`:

### Регістр конфігурації потоку (DMA_SxCR)

```text
+---------------+------------+-------------------------------------------------------------------------+
| Біти          | Поле       | Опис та функціональне значення                                          |
+---------------+------------+-------------------------------------------------------------------------+
| [27:25]       | CHSEL[2:0] | Channel Selection: вибір одного з 8 апаратних каналів периферії:         |
|               |            | 000: Канал 0 .. 001: Канал 1 (DCMI на DMA2_Stream1) .. 111: Канал 7    |
+---------------+------------+-------------------------------------------------------------------------+
| [24:23]       | MBURST[1:0]| Memory Burst Transfer: пакетний режим на боці пам'яті:                  |
|               |            | 00: Single (поодинокий) | 01: INC4 (4 слова)                            |
|               |            | 10: INC8 (8 слів)       | 11: INC16 (16 слів)                           |
+---------------+------------+-------------------------------------------------------------------------+
| [22:21]       | PBURST[1:0]| Peripheral Burst Transfer: пакетний режим на боці периферії:            |
|               |            | 00: Single | 01: INC4 | 10: INC8 | 11: INC16                            |
+---------------+------------+-------------------------------------------------------------------------+
| [19]          | CT         | Current Target: активний буфер у двобуферному режимі DBM:                |
|               |            | 0: Поточний цільовий буфер Memory 0 (DMA_SxM0AR)                        |
|               |            | 1: Поточний цільовий буфер Memory 1 (DMA_SxM1AR)                        |
+---------------+------------+-------------------------------------------------------------------------+
| [18]          | DBM        | Double-Buffer Mode: активація апаратного подвійного буфера:             |
|               |            | 1: Увімкнено (автоматичне перемикання CT при NDTR=0)                    |
|               |            | 0: Вимкнено (одиночний або стандартний кільцевий режим)                  |
+---------------+------------+-------------------------------------------------------------------------+
| [17:16]       | PL[1:0]    | Priority Level: пріоритет арбітражу потоку:                             |
|               |            | 00: Low | 01: Medium | 10: High | 11: Very High                         |
+---------------+------------+-------------------------------------------------------------------------+
| [14:13]       | MSIZE[1:0] | Memory Data Size: розрядність транзакцій пам'яті:                       |
|               |            | 00: Byte (8 біт) | 01: Half-Word (16 біт) | 10: Word (32 біти)          |
+---------------+------------+-------------------------------------------------------------------------+
| [12:11]       | PSIZE[1:0] | Peripheral Data Size: розрядність транзакцій периферії:                 |
|               |            | 00: Byte (8 біт) | 01: Half-Word (16 біт) | 10: Word (32 біти)          |
+---------------+------------+-------------------------------------------------------------------------+
| [10]          | MINC       | Memory Increment: автоматичний інкремент адреси пам'яті (+1/+2/+4)      |
+---------------+------------+-------------------------------------------------------------------------+
| [9]           | PINC       | Peripheral Increment: автоматичний інкремент адреси регістра периферії   |
+---------------+------------+-------------------------------------------------------------------------+
| [8]           | CIRC       | Circular Mode: кільцевий режим роботи лічильника NDTR                    |
+---------------+------------+-------------------------------------------------------------------------+
| [7:6]         | DIR[1:0]   | Data Transfer Direction: напрямок пересилання:                          |
|               |            | 00: Peripheral-to-Memory (Прийом від камери/АЦП)                         |
|               |            | 01: Memory-to-Peripheral (Передача на дисплей/ЦАП)                      |
|               |            | 10: Memory-to-Memory (Швидке копіювання RAM -> RAM, лише DMA2)          |
+---------------+------------+-------------------------------------------------------------------------+
| [0]           | EN         | Stream Enable: увімкнення роботи потоку (1 = Active, 0 = Stopped)       |
+---------------+------------+-------------------------------------------------------------------------+
```

### Регістр керування FIFO потоку (DMA_SxFCR)

Регістр `DMA_SxFCR` визначає логіку взаємодії внутрішнього 16-байтового буфера:
- **Біт [2] — `DMDIS` (Direct Mode Disable):**
  - `0`: Прямий режим (Direct Mode). FIFO вимкнено; кожне надходження слова з периферії негайно викликає запит на транзакцію в пам'ять.
  - `1`: Режим FIFO. Дані накопичуються у FIFO до досягнення заданого порогу `FTH`.
- **Біти [1:0] — `FTH[1:0]` (FIFO Threshold Selection):**
  - `00`: Поріг 1/4 FIFO (1 слово = 4 байти);
  - `01`: Поріг 1/2 FIFO (2 слова = 8 байтів);
  - `10`: Поріг 3/4 FIFO (3 слова = 12 байтів);
  - `11`: Поріг FULL FIFO (4 слова = 16 байтів).

## 2. Критичне правило вирівнювання Burst: обмеження межі 1 КБ AHB

Згідно зі специфікацією шини AMBA AHB, будь-яка пакетна передача (Burst) **ні за яких умов не повинна перетинати межу адреси, кратну 1 КБ (0x400 = 1024 байти)**.

Формула перевірки межі адреси:
```text
(Base_Address & 0x3FF) + (Burst_Length * Beat_Size) <= 1024
де:
  Base_Address & 0x3FF — зсув початкової адреси всередині поточного кілобайтного сектора,
  Burst_Length — кількість слів у пакеті (4, 8 або 16),
  Beat_Size — розмір одного слова (Word = 4 байти).
```

### Наслідки порушення правила 1 КБ:

Якщо буфер у пам'яті виділений компілятором за невирівняною адресою (наприклад, `0x200003F4`), а потік DMA налаштовано на `MBURST = INC4` (16 байтів):
1. Пакет починається за адресою `0x200003F4` (+16 байтів завершується на `0x20000404`).
2. Пакет перетинає межу `0x20000400` (межу 1 КБ).
3. Апаратний арбітр AHB генерує шинну аварію **AHB Transfer Error (TEIF)**!
4. Потік DMA негайно апаратно вимикається (`EN = 0`), а передача відеокадру аварійно переривається.

> **Золоте правило розробника:** Усі буфери пам'яті, що обслуговуються пакетами Burst DMA, повинні бути вирівняні в коді атрибутом `alignas(32)` або директивою GCC `__attribute__((aligned(32)))`.

## 3. Архітектура Master DMA (MDMA) у мікроконтролерах STM32H7

У мікроконтролерах флагманської серії STM32H7 поряд із традиційними блоками DMA1/DMA2 інтегровано 64-бітний суперконтролер **Master DMA (MDMA)**, підключений безпосередньо до матриці шин AXI.

### Головні переваги MDMA:

1. **Двовимірне переміщення блоків (2D Block Transfer):**
   - MDMA має вбудовану апаратну підтримку зміщення рядків (Stride Addressing):
   ```text
   Source_Address_next = Source_Address_curr + Source_Block_Stride
   ```
   Це дозволяє вирізати будь-яке довільне прямокутне вікно пікселів із великого кадру без програмної участі процесора.
2. **Зв'язані списки дескрипторів (Linked-List Descriptor Queue):**
   - Замість перезапуску DMA ядром процесора, MDMA самостійно зчитує з пам'яті ланцюжок структур-дескрипторів `MDMA_LinkNodeTypeDef`, автоматично змінюючи джерела, приймачі та розміри пакетів.
3. **Каскадне тригерування (DMA Request Router):**
   - MDMA може запускатися за апаратними подіями прапорця Transfer Complete від потоків DMA1 або DMA2. Щойно DMA2 завершує прийом рядка камери в SRAM1, MDMA автономно підхоплює його і пересилає у зовнішню SDRAM на швидкості до 1.6 ГБ/с.

## 4. Виробнича низькорівнева реалізація подвійного буфера DMA для DCMI

Нижче наведено високоефективний код драйвера прямої конфігурації регістрів `DMA2_Stream1` для захоплення відеопотоку камери в режимі апаратного подвійного буфера (DBM) без оверхеду бібліотеки HAL:

```c
#include "stm32f4xx.h"
#include <stdint.h>
#include <stdbool.h>

/* Вирівнювання буферів на межу 32 байти для виключення колізій Burst */
#define BUFFER_SIZE_WORDS   (800 * 600 / 2) /* 240 000 слів по 32 біти для SVGA */

__attribute__((section(".sram1_bss"), aligned(32)))
static uint32_t camera_ping_buffer[BUFFER_SIZE_WORDS];

__attribute__((section(".sram1_bss"), aligned(32)))
static uint32_t camera_pong_buffer[BUFFER_SIZE_WORDS];

/* Вказівник на функцію зворотного виклику завершення обробки кадру */
typedef void (*frame_ready_cb_t)(uint32_t *active_buffer);
static frame_ready_cb_t g_frame_callback = 0;

/**
 * @brief Пряма регістрова ініціалізація DMA2_Stream1 для камери DCMI
 */
void dcmi_dma_double_buffer_init(frame_ready_cb_t callback) {
    g_frame_callback = callback;

    /* 1. Вмикаємо тактування контролера DMA2 */
    RCC->AHB1ENR |= RCC_AHB1ENR_DMA2EN;

    /* 2. Гарантоване вимикання потоку перед конфігурацією */
    DMA2_Stream1->CR &= ~DMA_SxCR_EN;
    while (DMA2_Stream1->CR & DMA_SxCR_EN) {
        /* Очікування скидання апаратного біта готовності */
    }

    /* 3. Очищення всіх прапорців переривань для Stream 1 */
    DMA2->LIFCR = DMA_LIFCR_CTCIF1 | DMA_LIFCR_CHTIF1 | 
                  DMA_LIFCR_CTEIF1 | DMA_LIFCR_CDMEIF1 | DMA_LIFCR_CFEIF1;

    /* 4. Встановлення фізичної адреси регістра даних DCMI */
    DMA2_Stream1->PAR = (uint32_t)(&(DCMI->DR));

    /* 5. Встановлення адрес подвійного буфера Memory 0 та Memory 1 */
    DMA2_Stream1->M0AR = (uint32_t)camera_ping_buffer;
    DMA2_Stream1->M1AR = (uint32_t)camera_pong_buffer;

    /* 6. Кількість 32-бітних слів для передачі */
    DMA2_Stream1->NDTR = BUFFER_SIZE_WORDS;

    /* 7. Налаштування регістру конфігурації FIFO (DMA_SxFCR):
     * - DMDIS = 1 (увімкнути режим FIFO)
     * - FTH = 11 (поріг спрацьовування: FULL FIFO = 16 байтів)
     * - FEIE = 0 (помилки FIFO вимкнено для уникнення хибних переривань) */
    DMA2_Stream1->FCR = DMA_SxFCR_DMDIS | DMA_SxFCR_FTH;

    /* 8. Конфігурація регістру потоку (DMA_SxCR):
     * - CHSEL = 001 (Канал 1: DCMI)
     * - MBURST = 01 (INC4 Burst для швидкісного запису в SRAM)
     * - PBURST = 00 (Single для периферійного DCMI DR)
     * - DBM = 1 (Double-Buffer Mode)
     * - PL = 11 (Very High Priority — найвищий арбітраж)
     * - MSIZE = 10 (Word 32-bit)
     * - PSIZE = 10 (Word 32-bit для регістра DCMI->DR)
     * - MINC = 1 (Інкремент адреси в буфері пам'яті)
     * - PINC = 0 (Фіксована адреса регістра периферії)
     * - DIR = 00 (Peripheral-to-Memory)
     * - TCIE = 1 (Увімкнути переривання Transfer Complete) */
    DMA2_Stream1->CR = (1 << DMA_SxCR_CHSEL_Pos)      |
                       (1 << DMA_SxCR_MBURST_Pos)     |
                       DMA_SxCR_DBM                   |
                       DMA_SxCR_PL                    |
                       (2 << DMA_SxCR_MSIZE_Pos)      |
                       (2 << DMA_SxCR_PSIZE_Pos)      |
                       DMA_SxCR_MINC                  |
                       DMA_SxCR_TCIE;

    /* 9. Увімкнення переривання в контролері NVIC */
    NVIC_SetPriority(DMA2_Stream1_IRQn, 1);
    NVIC_EnableIRQ(DMA2_Stream1_IRQn);

    /* 10. Запуск потоку DMA */
    DMA2_Stream1->CR |= DMA_SxCR_EN;
}

/**
 * @brief Обробник переривання завершення передачі кадру DMA2 Stream 1
 */
void DMA2_Stream1_IRQHandler(void) {
    /* Перевірка прапорця Transfer Complete (TCIF1) */
    if (DMA2->LISR & DMA_LISR_TCIF1) {
        /* Апаратне очищення прапорця */
        DMA2->LIFCR = DMA_LIFCR_CTCIF1;

        /* Біт CT у регістрі CR вказує на буфер, який ЗАРАЗ пише DMA.
         * Тобто ГОТОВИМ для читання процесором є ПРОТИЛЕЖНИЙ буфер! */
        if (g_frame_callback) {
            if (DMA2_Stream1->CR & DMA_SxCR_CT) {
                /* DMA зараз переключився на M1AR (Pong), отже M0AR (Ping) готовий! */
                g_frame_callback(camera_ping_buffer);
            } else {
                /* DMA зараз пише в M0AR (Ping), отже M1AR (Pong) готовий! */
                g_frame_callback(camera_pong_buffer);
            }
        }
    }

    /* Обробка помилок передачі (TEIF1) */
    if (DMA2->LISR & DMA_LISR_TEIF1) {
        DMA2->LIFCR = DMA_LIFCR_CTEIF1;
        /* Перезапуск потоку у разі колізії шини */
        DMA2_Stream1->CR |= DMA_SxCR_EN;
    }
}
```

## 5. Типові помилки конфігурації та методи їх діагностики

1. **Не запускається потік DMA (біт `EN` скидається в 0 відразу після встановлення):**
   - *Причина:* Прапорці переривань попередньої сесії в регістрах `LISR`/`HISR` не були очищені перед спробою ввімкнення `DMA_SxCR_EN`.
   - *Виправлення:* Обов'язковий запис одиниць у біти очищення регістрів `LIFCR`/`HIFCR` безпосередньо перед активацією потоку.
2. **Шинна аварія TEIF під час першого ж такту:**
   - *Причина:* Порушення обмеження межі 1 КБ для пакета Burst або спроба звернення контролера DMA1 до периферії швидкісної шини AHB2 (наприклад, DCMI).
   - *Виправлення:* Використання вирівнювання `__attribute__((aligned(32)))` та задіяння виключно контролера `DMA2`.
3. **Дзеркальне переплутування кадрів у Double-Buffer Mode:**
   - *Причина:* Програма починає обробку буфера `camera_pong_buffer`, коли біт `CT = 1`.
   - *Виправлення:* Пам'ятайте, що біт `CT` позначає активний буфер прийому, тому обробляти слід буфер, протилежний значенню `CT` (`CT ? Buffer0 : Buffer1`).
