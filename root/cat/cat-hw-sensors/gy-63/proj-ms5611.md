# ⚙️ GY-63 у коді: робочий барометр і варіометр на готовій бібліотеці

<preknowlist>
- [Шина I2C](root:com-devices/i2c-bus) — дві лінії SDA/SCL, ведучий і ведений: бібліотека розмовляє з давачем саме по ній.
- [Атмосферний тиск](root:ph-mechanics/atmospheric-pressure) — тиск повітря падає з висотою; на цьому тримається переведення тиску у висоту.
</preknowlist>

Плата під'єднана, шина бачить щось за адресою `0x77`. Мета — швидко дістати з GY-63 живі числа (температуру, тиск, висоту), а тоді зробити те єдине, заради чого MS5611 узагалі беруть: варіометр, що показує відносну висоту з точністю до десятка сантиметрів. Уся нудна механіка — скид, читання калібрувальної пам'яті, запуск перетворень, паузи, обидва порядки компенсації — схована у вивіреній бібліотеці, тож перші мілібари з'являються на екрані за п'ять хвилин.

Весь код — справжній C/C++ під Arduino-ядро (`Wire`), однаково збирається під класичну Arduino (UNO/Nano) і під ESP32; різниця лише в тому, як задати ніжки шини на старті. Це не псевдокод — його можна скопіювати в скетч і залити.

## Готова бібліотека RobTillaart/MS5611

Найшвидший старт — узяти вивірену бібліотеку. Для MS5611 найпоширеніша й найдоглянутіша — **`MS5611` від Роба Тілларта** (RobTillaart): ставиться з менеджера бібліотек Arduino IDE (`Sketch → Include Library → Manage Libraries`, шукати «MS5611 RobTillaart»). Вона ховає весь конвеєр і при цьому не приховує важливого — дає доступ і до сирих коефіцієнтів, і до перевірки їхньої контрольної суми, що нам знадобиться нижче.

Ось повний робочий скетч під ESP32, що раз на секунду друкує температуру, тиск і висоту в монітор порту.

:::tabs
```cpp
#include <Wire.h>
#include "MS5611.h"

// Конструктор приймає адресу; 0x77 — коли CSB вільний або на GND, 0x76 — коли CSB на VCC.
MS5611 baro(0x77);

float seaLevel_hPa = 1013.25;   // опорний тиск на рівні моря; уточнимо його нижче

void setup() {
  Serial.begin(115200);
  while (!Serial && millis() < 2000) { }

  // На ESP32/STM32/Pico задайте ніжки шини ДО begin():
  Wire.begin(21, 22);            // SDA=21, SCL=22 — типово для ESP32
  // На класичній Arduino (UNO/Nano) ніжки жорсткі (A4/A5): просто Wire.begin();

  if (!baro.begin()) {
    Serial.println(F("MS5611 не відповідає. Перевірте дроти, адресу (0x76/0x77) і живлення."));
    while (true) { delay(1000); }
  }

  // Режим згладжування: від OSR_ULTRA_LOW (найшвидший, найгрубіший)
  // до OSR_ULTRA_HIGH (найдовша пауза ~9 мс, роздільність ~0.012 мбар — ті самі «10 см»).
  baro.setOversampling(OSR_ULTRA_HIGH);

  Serial.println(F("MS5611 на зв'язку."));
}

void loop() {
  int result = baro.read();      // повний вимір: D1, D2, обидва порядки компенсації
  if (result != MS5611_READ_OK) {
    Serial.print(F("read() error: "));
    Serial.println(result);
    delay(1000);
    return;
  }

  float t = baro.getTemperature();          // °C
  float p = baro.getPressure();             // мбар (гПа)
  float h = baro.getAltitude(seaLevel_hPa); // м над рівнем опорного тиску

  Serial.print(F("T = "));   Serial.print(t, 2);
  Serial.print(F(" °C   P = ")); Serial.print(p, 2);
  Serial.print(F(" hPa   h = ")); Serial.print(h, 1);
  Serial.println(F(" m"));

  delay(1000);
}
```
```python
# MicroPython (Pico/ESP32): драйвер micropython-ms5611 (jposada202020) —
# аналог RobTillaart, теж ховає скид, читання PROM, паузи й обидва порядки компенсації.
#   pip install micropython-ms5611  (або скопіювати модуль на плату)
import time
from math import pow
from machine import Pin, I2C
from micropython_ms5611 import ms5611

sea_level_hPa = 1013.25          # опорний тиск на рівні моря; уточнимо його нижче

# Ніжки шини задаємо тут-таки: SDA=21, SCL=22 — типово для ESP32 (на Pico свої).
i2c  = I2C(0, sda=Pin(21), scl=Pin(22))
# Конструктор приймає адресу; 0x77 — коли CSB вільний або на GND, 0x76 — на VCC.
baro = ms5611.MS5611(i2c, 0x77)  # кине RuntimeError, якщо давач не відповів

# Режим згладжування: PRESS_OSR_4096 — найдовша пауза ~9 мс, роздільність
# ~0.012 мбар (ті самі «10 см»); є й швидші PRESS_OSR_256 … PRESS_OSR_2048.
baro.pressure_oversample_rate    = ms5611.PRESS_OSR_4096
baro.temperature_oversample_rate = ms5611.TEMP_OSR_4096

while True:
    t, p_kPa = baro.measurements      # повний вимір: обидва порядки компенсації
    p = p_kPa * 10.0                  # драйвер віддає кПа → у гПа (мбар)
    # висоти в драйвері немає — рахуємо тією самою барометричною формулою:
    h = 44330.0 * (1.0 - pow(p / sea_level_hPa, 0.1903))

    print("T = {:.2f} °C   P = {:.2f} hPa   h = {:.1f} m".format(t, p, h))
    time.sleep(1)
```
:::

Кілька місць треба прочитати уважно — вони не випадкові.

`baro.begin()` **повертає `bool`, і його перевіряють**. Усередині бібліотека шле давачу команду скиду, дає йому час перезавантажити калібрувальну пам'ять і читає шість коефіцієнтів. Якщо ви переплутали `SDA` зі `SCL`, забули землю, або задали не ту адресу (`0x76` замість `0x77`), `begin()` поверне `false`. Спіймати це тут набагато легше, ніж потім гадати, чому тиск дорівнює нулю. Ми зупиняємось у вічному циклі, бо без давача робити нічого.

`baro.read()` **повертає код результату**, а не сам тиск. `MS5611_READ_OK` (нуль) означає успіх; ненульове — щось не так на шині. Це навмисно: один виклик `read()` запускає **два** перетворення (тиск і температуру), кожне з паузою, читає обидва 24-бітних числа і проганяє повну компенсацію. Готові числа ви потім забираєте окремими `getPressure()` / `getTemperature()` — вони лише повертають уже обчислене, повторно давач не смикають.

`setOversampling(...)` **задає компроміс** роздільність-проти-швидкості один раз. Бібліотека тримає enum `osr_t`: `OSR_ULTRA_LOW`, `OSR_LOW`, `OSR_STANDARD`, `OSR_HIGH`, `OSR_ULTRA_HIGH`. Що вищий режим, то дрібніша роздільність і тихіший шум, але й довша пауза всередині `read()` (від ~0.6 мс до ~9 мс на одне перетворення). Для варіометра, де ловлять десятисантиметрові зміни, беруть `OSR_ULTRA_HIGH`; для швидкого опитування в керуванні висотою дрона іноді свідомо жертвують роздільністю заради частоти.

`getAltitude(seaLevel_hPa)` **приймає опорний тиск** на рівні моря й повертає висоту в метрах за барометричною формулою (є й `getAltitudeFeet()` — те саме у футах). Число `1013.25` тут — стандартна атмосфера; чому його треба уточнювати під погоду й як «обнулити» висоту в поточній точці, розберемо окремим розділом нижче.

Що бібліотека зробила за вас в одному `read()`: послала команду запуску перетворення тиску, витримала паузу під обраний OSR, прочитала 24 біти АЦП, те саме для температури, обчислила `dT` і `TEMP`, виправила зсув і чутливість на температуру, застосувала компенсацію другого порядку для холоду — і все у правильній 64-бітній арифметиці. Зручно. Але щоб **лагодити** дивну поведінку — тиск 300 мбар на столі, −40 °C у теплій кімнаті, стрибки на графіку — треба знати, що саме там усередині.

Бібліотека — правильний вибір у більшості проєктів: вивірена, доглянута, ховає нудні дрібниці. Але вона не завжди підходить: не влазить у пам'ять крихітного МК, не лягає на ядро без Arduino-обгортки (ESP-IDF, RTOS, голий регістровий доступ), не дає тонко керувати паузами чи читати давач по SPI так, як вам треба. Тоді той самий вимір роблять голими руками — скид, читання PROM **із перевіркою контрольної суми CRC-4**, запуск АЦП, пауза за режимом згладжування, повна компенсація в 64-бітній арифметиці. Увесь цей байтовий протокол, із робочим кодом і даташитним прикладом для звірки, зібрано в [довіднику по сирому MS5611](root:cat-hw-sensors/gy-63/api-ms5611.md); а тут лишаємось на бібліотеці й доводимо до діла те, заради чого MS5611 беруть, — висоту.

## Від тиску до висоти й «обнулення» P₀

Раз давач бачить тиск так дрібно, найчастіша задача — перевести його у **висоту**. Атмосфера влаштована так, що тиск падає з висотою за відомим законом; стандартна барометрична формула дає висоту з поточного тиску `P` і опорного тиску на рівні моря `P₀`:

```
h ≈ 44330 · (1 − (P / P₀)^0.1903)      // метри
```

Саме її ховає `getAltitude()` бібліотеки. Але число `P₀` залежить від погоди, тому **абсолютну** висоту без свіжого `P₀` точно не порахуєш. Зате давач чудово ловить **зміну** висоти, і найкорисніший прийом — «обнулити» висоту в поточній точці: запам'ятати теперішній тиск як `P₀` і далі показувати підйом чи спуск відносно нього. Це і є та кнопка «reset altitude» у варіометрах і висотомірах.

Одна тонкість вирішує все: `P₀` треба брати **усередненим**, а не з одного виміру. Давач такий чутливий, що поодинокий вимір гуляє від подиху чи поштовху повітря; візьміть за нуль середнє з кількох десятків вимірів, поки прилад стоїть нерухомо, — інакше сам «нуль» вийде хитким, і висота стрибатиме навколо нуля навіть на місці. Ось як це виглядає з тією ж бібліотекою:

```cpp
// Продовження того самого скетча: об'єкт baro вже створено вище.
float g_p0_hPa = 1013.25;        // опорний тиск; поки не обнулили — стандартна атмосфера

// Барометрична формула висоти (те, що всередині getAltitude()).
static float altitude_m(float pressure_hPa, float seaLevel_hPa) {
  return 44330.0f * (1.0f - powf(pressure_hPa / seaLevel_hPa, 0.1903f));
}

// «Обнулити» висоту: узяти поточний тиск за нуль. Усереднюємо ~40 вимірів,
// поки прилад нерухомий (напр. на землі перед злетом), щоб «нуль» не гуляв.
void zeroAltitude() {
  double sum = 0.0;
  const int N = 40;
  for (int i = 0; i < N; i++) {
    baro.read();                 // повний вимір із компенсацією
    sum += baro.getPressure();   // мбар (гПа)
    delay(20);
  }
  g_p0_hPa = (float)(sum / N);   // тепер ця точка = 0 м
}

// Відносна висота над точкою обнулення (метри).
float relativeAltitude_m() {
  baro.read();
  return altitude_m(baro.getPressure(), g_p0_hPa);
}
```

Тепер `zeroAltitude()` кличуть один раз на «нулі», а `relativeAltitude_m()` — у циклі: воно й дає ту миттєву відносну висоту, заради якої MS5611 узагалі беруть. Абсолютну висоту над рівнем моря дасть і GPS; барометр цінний саме тим, що бачить «набрали ви метр за секунду чи ні» одразу, без чекання супутників, і на десятисантиметровій роздільності. Дрон утримує задану висоту, порівнюючи поточний тиск із запам'ятаним `P₀`; варіометр планериста показує швидкість підйому як похідну тієї самої відносної висоти.

## Фізичні пастки: світло, протяг, не той чип

Код може бути бездоганним, а показ — брехати, бо причина лежить поза кодом. Три речі дають майже все «плавання» саме на MS5611, і жоден фільтр їх не прибере, поки не усунути фізичне джерело.

**Світло вбиває точність.** Не програмна, а фізична, але код її не виправить. Кремнієва мембрана MS5611 **чутлива до світла**: пряме сонце чи лампа в дірочку ковпачка дають стрибки в кілька мілібар (метри «висоти» на рівному місці). На дронах давач заклеюють шматочком чорного поролону — він пропускає повітря, але не світло. Якщо барометр «плаває» при зміні освітлення — це воно, і жодне усереднення в коді не допоможе, поки не затінити давач.

**Протяг і подих.** Давач ловить навіть помах руки поряд, зачинення дверей, вітер у дірочку. Для стабільного показу його ховають від прямого потоку — той самий поролон згладжує миттєві поштовхи. У коді це проявляється як «шум», який хочеться усереднити фільтром, але спершу приберіть фізичну причину.

**Не той чип.** MS5611 зовні схожий на дешевші BMP180/BMP280, але це **інші** мікросхеми з іншими командами й формулами. Код звідси з BMP280 не заговорить, і навпаки. Маркування «GY-63» майже завжди означає MS5611; «GY-BMP280» чи «GY-68» — зовсім інші давачі, і драйвер для них потрібен свій.

За цим порогом GY-63 перестає бути просто давачем і стає приладом: маючи стабільну відносну висоту, її диференціюють у швидкість підйому (той самий варіометр планериста), заводять у регулятор утримання висоти дрона або порівнюють із порогами для лічильника поверхів. Бібліотека дала готове число — далі все залежить від того, що ви з тим числом робите.
