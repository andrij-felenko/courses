# Поглиблена конфігурація та бітові поля регістрів OV2640

Низькорівневе програмування сенсора OV2640 вимагає детального розуміння структури його бітових полів, оскільки багато регістрів містять складові параметри, зміна яких без збереження сусідніх бітів призводить до непередбачуваної поведінки аналогового ядра або цифрового сигнального процесора (DSP). У цьому розділі наведено вичерпний розбір конфігураційних блоків обох банків пам'яті, математику масштабування кадрів, налаштування апаратного компресора JPEG та виробничу реалізацію драйвера на мові C.

---

## 1. Детальний аналіз бітових полів регістрів Банку 1 (Sensor Core)

Банк 1 активується попереднім записом команди:
```text
SCCB_Write(0xFF, 0x01);
```

Усі подальші 8-бітні адреси від 0x00 до 0xFE взаємодіють безпосередньо з кремнієвою матрицею пікселів, схемами автопідсилення та зчитування.

```text
+---------------+--------------------------------------------------------------------------+
| Регістр       | Функціональне призначення та бітова структура                            |
+---------------+--------------------------------------------------------------------------+
| 0x12 (COM7)   | Загальне керування та вибір роздільної здатності матриці:                |
|               | - Біт [7]: SRST — Програмне скидання мікросхеми (1 = Reset, автоскид).   |
|               | - Біт [6]: Reserved (завжди зберігати 0).                                 |
|               | - Біти [5:0]: Вибір базового режиму матриці:                             |
|               |   * 0x00: Режим UXGA (1600x1200) — повний кадр матриці.                  |
|               |   * 0x40: Режим SVGA (800x600) — апаратний субсемплінг (Binning 2x2).   |
|               |   * 0x20: Режим CIF (352x288).                                           |
+---------------+--------------------------------------------------------------------------+
| 0x04 (REG04)  | Керування геометрією зчитування (дзеркало) та вікном експозиції:          |
|               | - Біт [7]: H-Mirror (1 = Горизонтальне віддзеркалення зображення).       |
|               | - Біт [6]: V-Flip (1 = Вертикальний переворот кадру «догори ногами»).   |
|               | - Біт [4]: Вибір зони вимірювання AEC (1 = повне поле, 0 = центр кадру). |
+---------------+--------------------------------------------------------------------------+
| 0x11 (CLKRC)  | Внутрішній дільник тактової частоти пікселів:                            |
|               | - Біт [7]: Подвоєння частоти через внутрішній PLL (1 = x2, 0 = 1x).     |
|               | - Біти [5:0]: Дільник вхідного сигналу XVCLK:                           |
|               |   F_core = F_xvclk / (CLKRC[5:0] + 1). Значення від 0 до 63.             |
+---------------+--------------------------------------------------------------------------+
| 0x13 (COM8)   | Швидке вмикання апаратних алгоритмів автокорекції:                       |
|               | - Біт [2]: AGC Enable (1 = Автоматичне регулювання підсилення).          |
|               | - Біт [0]: AEC Enable (1 = Автоматичне регулювання експозиції).          |
|               | - Біт [5]: Banding filter enable (подавлення мерехтіння 50/60 Гц).       |
+---------------+--------------------------------------------------------------------------+
| 0x00 (GAIN)   | Ручний коефіцієнт аналогового підсилювача PGA (працює при AGC=0):         |
|               | - Біти [7:6]: Додаткове дискретне підсилення (+6 дБ / +12 дБ).           |
|               | - Біти [5:0]: Лінійний діапазон підсилення вихідного сигналу фотодіодів.  |
+---------------+--------------------------------------------------------------------------+
```

### Налаштування часу експозиції (AEC)

Час накопичення заряду фотодіодом визначається кількістю тактових періодів рядка. У ручному режимі (при скинутому біті `COM8[0] = 0`) експозиція задається комбінацією 16 бітів, розділених між трьома регістрами:
- Молодші 8 біт: регістр `0x10` (`AEC[7:0]`).
- Старші біти: регістр `0x04` (біти `REG04[1:0]` задають біти `AEC[9:8]`).
- Додаткові розширені біти тривалої експозиції: регістр `0x45` (`AECV[5:0]`).

Формула повного часу накопичення заряду:
```text
T_exposure = AEC_Total_Value * T_row
де T_row — тривалість передачі одного повного рядка сенсора (включаючи Horizontal Blanking).
```

## 2. Конфігурація Банку 0 (DSP Engine, Масштабування та JPEG)

Банк 0 активується записом:
```text
SCCB_Write(0xFF, 0x00);
```

Цей банк відповідає за фінальну геометрію зображення, цифрове масштабування (Sizing), перетворення колірного простору та роботу апаратного блоку стиснення JPEG.

### Регістр 0xDA (IMAGE_MODE)

Цей регістр визначає режим вихідного потоку пікселів на паралельній шині D[7:0]:
- **Біти [7:4] — Тип вихідного потоку:**
  - `0x00`: Необроблений вихід YUV422 або RGB565 (неспресований потік постійного розміру).
  - `0x10`: Потік апаратного стиснення **JPEG**.
  - `0x20`: Формат RAW Bayer (обхід блоків балансу білого та гами).
- **Біт [3] — Байт-свап (Byte Swap):**
  - `0`: Старший байт (MSB) передається першим.
  - `1`: Молодший байт (LSB) передається першим. Критично для вирівнювання RGB565 під контролери дисплеїв з прямою чи оберненою адресацією слів пам'яті.

### Налаштування якості стиснення JPEG (Регістр 0x44: QS)

Якість стисненого зображення в режимі JPEG регулюється значенням регістра `0x44` (`QS` — Quantization Scale / Масштаб квантування). Цей 6-бітний параметр безпосередньо впливає на коефіцієнти ділення в матриці квантування дискретного косинусного перетворення (DCT):

```text
Значення QS (0x44)  |  Ступінь стиснення  |  Якість кадру      |  Типовий розмір (UXGA)
--------------------+---------------------+--------------------+-----------------------
0x02 .. 0x05        |  Мінімальне         |  Максимальна       |  180 .. 250 КБ
0x08 .. 0x0C        |  Середнє            |  Оптимальна (баланс)|  80 .. 140 КБ
0x14 .. 0x20        |  Високе             |  Помітні артефакти|  35 .. 60 КБ
0x30 .. 0x3F        |  Екстремальне       |  Низька (шум блоків)| 15 .. 25 КБ
```

> **Порада для вбудованих систем:** При роботі через мікроконтролери без зовнішньої оперативної пам'яті (PSRAM) рекомендується встановлювати `QS` у діапазоні `0x0A .. 0x12`. Це гарантує, що розмір кадру навіть висококонтрастної сцени не перевищить внутрішній статичний буфер SRAM (зазвичай 40–60 КБ).

## 3. Модуль масштабування вікна (Windowing & Sizing Engine)

Сенсор OV2640 здатний самостійно зменшувати роздільну здатність кадру з базової матриці 1600x1200 до менших форматів (наприклад, 640x480 VGA або 320x240 QVGA) за допомогою двох послідовних ступенів:

1. **Аналоговий біннінг (Binning) у Банку 1:**
   - Об'єднання сусідніх фотодіодів матриці 2x2 у спільний зарядний вузол.
   - Виконується апаратно за один крок через біт `COM7[6]`. Дозволяє миттєво перейти від 1600x1200 (UXGA) до 800x600 (SVGA), водночас учетверо підвищуючи світлочутливість сенсора в умовах слабкого освітлення.
2. **Цифровий ресемплер DSP (DSP Sizing Block) у Банку 0:**
   - Керується групою регістрів `0xC0 .. 0xCF`.
   - Регістри `0xC2` (`ZMOW` — Zoom Output Width) та `0xC3` (`ZMOH` — Zoom Output Height) визначають горизонтальний та вертикальний розмір кінцевого вихідного прямокутника пікселів.
   - Регістр `0xC4` (`ZMHH`) містить старші 2 біти для ширини та висоти вікна.

```text
Кінцева ширина кадру W_out = (ZMHH[1:0] << 8) | ZMOW[7:0]
Кінцева висота кадру H_out = (ZMHH[3:2] << 8) | ZMOH[7:0]
```

Завдяки цьому мікроконтролер повністю звільняється від необхідності програмного програмного ресайзингу зображення, що заощаджує мільйони тактів ядра під час запуску моделей комп'ютерного зору (наприклад, MobileNet або YOLO).

## 4. Виробнича реалізація драйвера на мові C

Нижче наведено модульний виробничий код драйвера ініціалізації сенсора OV2640. Реалізація включає захищений механізм перемикання банків пам'яті, контроль апаратного ідентифікатора, та послідовне завантаження таблиць конфігурації.

```c
#include <stdint.h>
#include <stdbool.h>

/* Базові адреси на шині SCCB */
#define OV2640_SCCB_ADDR       0x60  /* 7-бітна адреса 0x30, зсунута вліво */
#define OV2640_REG_BANK_SEL    0xFF  /* Регістр перемикання банку */

/* Ідентифікатори сенсора в Банку 1 */
#define OV2640_PID             0x0A
#define OV2640_VER             0x0B
#define OV2640_PID_VAL         0x26
#define OV2640_VER_VAL         0x42

/* Зовнішні прототипи апаратного рівня (HAL) мікроконтролера */
extern bool hal_sccb_write(uint8_t dev_addr, uint8_t reg_addr, uint8_t data);
extern bool hal_sccb_read(uint8_t dev_addr, uint8_t reg_addr, uint8_t *data);
extern void hal_delay_ms(uint32_t ms);

/* Структура дескриптора регістрової пари */
typedef struct {
    uint8_t reg;
    uint8_t val;
} ov2640_regval_t;

/* Кеш активного банку для мінімізації зайвих транзакцій SCCB */
static int8_t current_bank = -1;

/**
 * @brief Безпечне перемикання активного банку регістрів OV2640
 * @param bank 0 (DSP/JPEG) або 1 (Sensor Core)
 * @return true у разі успішного запису
 */
bool ov2640_select_bank(uint8_t bank) {
    if (current_bank == bank) {
        return true; /* Банк уже активний, повторний запис не потрібен */
    }
    if (hal_sccb_write(OV2640_SCCB_ADDR, OV2640_REG_BANK_SEL, bank)) {
        current_bank = bank;
        return true;
    }
    return false;
}

/**
 * @brief Запис регістра в явно вказаному банку пам'яті
 */
bool ov2640_write_reg(uint8_t bank, uint8_t reg, uint8_t val) {
    if (!ov2640_select_bank(bank)) {
        return false;
    }
    return hal_sccb_write(OV2640_SCCB_ADDR, reg, val);
}

/**
 * @brief Читання регістра з вказаного банку пам'яті
 */
bool ov2640_read_reg(uint8_t bank, uint8_t reg, uint8_t *val) {
    if (!ov2640_select_bank(bank)) {
        return false;
    }
    return hal_sccb_read(OV2640_SCCB_ADDR, reg, val);
}

/**
 * @brief Послідовний запис масиву регістрових налаштувань
 */
bool ov2640_write_regs_list(uint8_t default_bank, const ov2640_regval_t *regs, size_t count) {
    for (size_t i = 0; i < count; i++) {
        if (regs[i].reg == 0xFF) {
            /* Явне перемикання банку всередині таблиці */
            if (!ov2640_select_bank(regs[i].val)) {
                return false;
            }
        } else {
            if (!hal_sccb_write(OV2640_SCCB_ADDR, regs[i].reg, regs[i].val)) {
                return false;
            }
        }
    }
    return true;
}

/**
 * @brief Ініціалізація та верифікація апаратного підключення OV2640
 */
bool ov2640_init(void) {
    uint8_t pid = 0, ver = 0;

    current_bank = -1; /* Скидаємо стан локального кешу */

    /* Крок 1: Програмне скидання ядра (SRST) у Банку 1 */
    if (!ov2640_write_reg(1, 0x12, 0x80)) {
        return false; /* Помилка зв'язку по шині SCCB */
    }
    hal_delay_ms(10); /* Час на стабілізацію генератора та скидання АЦП */

    /* Крок 2: Верифікація ID сенсора */
    if (!ov2640_read_reg(1, OV2640_PID, &pid) || !ov2640_read_reg(1, OV2640_VER, &ver)) {
        return false;
    }

    if (pid != OV2640_PID_VAL || (ver != 0x41 && ver != 0x42)) {
        return false; /* Зчитано невідомий ідентифікатор мікросхеми */
    }

    /* Крок 3: Встановлення базового тактування (Bank 1, CLKRC: PLL x1, Prescaler = 0) */
    ov2640_write_reg(1, 0x11, 0x00);

    /* Крок 4: Конфігурація дзеркала та орієнтації (без перевороту) */
    ov2640_write_reg(1, 0x04, 0x00);

    return true;
}

/**
 * @brief Налаштування виходу в режим апаратного стиснення JPEG
 * @param quality_scale Коефіцієнт якості QS (0x02 - ультра-якість, 0x30 - низька якість)
 */
bool ov2640_set_jpeg_mode(uint8_t quality_scale) {
    /* Перемикаємося в Банк 0 (DSP) */
    if (!ov2640_select_bank(0)) {
        return false;
    }

    /* Вмикаємо режим JPEG у регістрі IMAGE_MODE (Bank 0, 0xDA = 0x10) */
    if (!hal_sccb_write(OV2640_SCCB_ADDR, 0xDA, 0x10)) {
        return false;
    }

    /* Встановлюємо коефіцієнт квантування QS (Bank 0, 0x44) */
    if (!hal_sccb_write(OV2640_SCCB_ADDR, 0x44, quality_scale)) {
        return false;
    }

    /* Перезавантажуємо цифровий конвеєр DSP (Bank 0, 0xE0 = 0x00, потім 0x04) */
    hal_sccb_write(OV2640_SCCB_ADDR, 0xE0, 0x00);
    hal_delay_ms(2);
    hal_sccb_write(OV2640_SCCB_ADDR, 0xE0, 0x04);

    return true;
}
```

## 5. Типові апаратні проблеми та контрольний перелік діагностики

Під час запуску камерних модулів на базі OV2640 розробники найчастіше стикаються з такими дефектами:

1. **Нестабільне читання ID (читається 0x00 або 0xFF):**
   - Перевірте сигнал XVCLK: сенсор принципово не відповідає на запити SCCB, якщо на вивід вхідного тактування не подається стабільний сигнал меандру частотою не менше 6 МГц.
   - Перевірте напругу цифрового ядра DVDD (1.3 В). Якщо внутрішній регулятор модуля несправний або замкнений, цифрова логіка не стартує.
   - Перевірте вивід вимикання живлення `PWDN`: для нормальної роботи на ньому повинен бути стабільний логічний 0.
2. **Артефакти кадрів у режимі JPEG (помилка `Invalid JPEG Marker`):**
   - Джиттер або затримки на шині DMA мікроконтролера, що призводять до випадання байтів у моменти пікового трафіку.
   - Помилкова полярність стробу PCLK: стробування даних контролером DCMI повинно відбуватися строго по спадному або наростаючому фронту залежно від налаштувань регістра полярності Банку 1 `0x03`.
3. **Зсув колірних каналів (фіолетові або зелені смуги):**
   - Невірний порядок байтів у форматі RGB565 / YUV422. Лікується інверсією біта байт-свапу в регістрі Банку 0 `0xDA[3]`.
