# 📋 Si7021 / HTU21D: протокол GY-21 на дротах — команди, регістри, CRC

<preknowlist>
- [Шина I2C](root:com-devices/i2c-bus) — дві лінії SDA/SCL, ведучий шле адресу й байти, ведений відповідає ACK/NACK; на цьому стоїть кожен рядок нижче.
- [Адресація I2C](root:com-devices/i2c-addressing) — 7-бітна адреса пристрою, читання проти запису; GY-21 сидить на фіксованій `0x40`.
- [CRC — циклічний надлишковий код](root:com-modulation/crc) — як кілька байтів згортають у контрольне число, щоб зловити зіпсований біт; давач шле такий байт після кожного виміру.
</preknowlist>

Це — контракт давача Si7021/HTU21D на рівні дротів: за якою адресою він озивається, якими байтами йому наказують міряти, скільки чекати відповіді, як зібрати з неї сире число, як перевірити його цілість і які регістри всередині можна крутити. Сюди заглядають, коли пишуть драйвер без бібліотеки, лагодять чужий або переносять код на голе ядро без Arduino-обгортки. Усе нижче однакове для Si7021 і для HTU21D — обидва належать до родини SHT21 і говорять тим самим протоколом; де вони розходяться, зазначено окремо.

## Адреса й команди

Адреса на шині — **`0x40`**, зашита намертво й джамперами не змінюється (тому на одній парі `SDA`/`SCL` живе лише один такий давач). Повний набір команд:

```
Команда      Байти       Дія                                     Відповідь
----------   ---------   -------------------------------------   ---------------------
вимір T      0xF3        температура, режим no-hold master       3 байти: MSB, LSB, CRC
вимір T      0xE3        температура, режим hold master          3 байти: MSB, LSB, CRC
вимір RH     0xF5        вологість, режим no-hold master         3 байти: MSB, LSB, CRC
вимір RH     0xE5        вологість, режим hold master            3 байти: MSB, LSB, CRC
читати reg   0xE7        прочитати регістр налаштувань 1         1 байт
писати reg   0xE6 <val>  записати регістр налаштувань 1          —
серійник 1   0xFA 0x0F   перша половина серійного номера         8 байтів (SNA + CRC)
серійник 2   0xFC 0xC9   друга половина серійного номера         6 байтів (SNB + CRC)
скидання     0xFE        м'яке скидання у стан за замовчуванням  —
```

Нижче кожен рядок цієї таблиці розкрито: як зчитати вимір, як порахувати CRC, як розібрати серійний номер, що лежить у регістрі налаштувань і чим відрізняються два режими виміру.

## Один вимір: команда, пауза, три байти

Уся логіка виміру вкладається в чотири дії, і вони однакові для температури й вологості — відрізняється лише командний байт.

**Крок 1 — послати команду.** Ведучий пише давачу **один байт**: `0xF3` для температури, `0xF5` для вологості. Це команди в режимі **«без утримання шини»** (no-hold master) — про цей режим і його альтернативу окремо нижче, поки просто запам'ятаймо ці два числа.

**Крок 2 — витримати паузу.** Отримавши команду, давач починає вимір, і поки він міряє, читати нічого. Температура в повній роздільності готова приблизно за 7 мс, вологість — до 12 мс. Щоб не тримати межу впритул, беремо із запасом: 10 мс для температури, 20 мс для вологості. (Бібліотеки зазвичай не сплять фіксовано, а опитують давач циклом, поки той не відповість ACK замість NACK, — але для розуміння протоколу проста пауза наочніша.)

**Крок 3 — прочитати три байти.** Ведучий читає з давача **три байти**: старший байт результату (MSB), молодший байт результату (LSB) і байт **контрольної суми** (CRC).

**Крок 4 — зібрати число, обнулити службові біти, перевести у людські одиниці.** Два байти результату складають у 16-бітне сире значення. Але **два молодших біти цього числа — не дані, а прапорці стану** (зокрема, ознака типу виміру). Їх обнуляють маскою `0xFFFC` — «залишити всі біти, крім двох найменших». А далі — формула з документації давача:

```
Температура (°C) = 175.72 · raw / 65536 − 46.85
Вологість   (%)  = 125.0  · raw / 65536 −  6.0
```

Тут `raw` — те саме 16-бітне число з уже обнуленими молодшими бітами, `65536` — це 2¹⁶, повний розмах шістнадцяти бітів. Формули однакові для Si7021 і HTU21D — тому код нижче не мусить знати, який саме чип на платі.

Ось ця логіка одним шматком. Функція повертає `true`, якщо вимір вдався (зокрема, зійшлася контрольна сума), і кладе результат у передане за посиланням число.

:::tabs
```cpp
#include <Wire.h>

static const uint8_t GY21_ADDR = 0x40;   // фіксована адреса, джамперами не змінюється
static const uint8_t CMD_TEMP  = 0xF3;   // вимір T, no-hold master
static const uint8_t CMD_HUM   = 0xF5;   // вимір RH, no-hold master

// Перевірка CRC-8 (означимо трохи нижче):
uint8_t si7021_crc8(const uint8_t *data, uint8_t len);

// Спільне ядро: послати команду `cmd`, зачекати `wait_ms`, прочитати 3 байти,
// звірити CRC і повернути 16-бітне СИРЕ значення (з обнуленими службовими бітами).
// Повертає true при успіху; false — якщо давач не відповів або CRC не зійшлася.
static bool gy21_read_raw(uint8_t cmd, uint16_t wait_ms, uint16_t *raw_out) {
  // -- Крок 1: послати командний байт --
  Wire.beginTransmission(GY21_ADDR);
  Wire.write(cmd);
  if (Wire.endTransmission() != 0) return false;   // давач не підтвердив команду

  // -- Крок 2: витримати паузу, поки давач міряє --
  delay(wait_ms);

  // -- Крок 3: прочитати рівно 3 байти (MSB, LSB, CRC) --
  if (Wire.requestFrom((int)GY21_ADDR, 3) != 3) return false;
  uint8_t msb = Wire.read();
  uint8_t lsb = Wire.read();
  uint8_t crc = Wire.read();

  // -- Крок 4a: перевірити контрольну суму над двома байтами даних --
  uint8_t buf[2] = { msb, lsb };
  if (si7021_crc8(buf, 2) != crc) return false;     // зіпсовано в дорозі — відкинути

  // -- Крок 4b: зібрати число й обнулити 2 службових біти --
  uint16_t raw = ((uint16_t)msb << 8) | lsb;
  raw &= 0xFFFC;

  *raw_out = raw;
  return true;
}

// Публічні читання: та сама функція, різний командний байт і пауза + формула.
bool gy21_read_temperature(float *t_out) {
  uint16_t raw;
  if (!gy21_read_raw(CMD_TEMP, 10, &raw)) return false;
  *t_out = 175.72f * raw / 65536.0f - 46.85f;
  return true;
}

bool gy21_read_humidity(float *rh_out) {
  uint16_t raw;
  if (!gy21_read_raw(CMD_HUM, 20, &raw)) return false;
  float rh = 125.0f * raw / 65536.0f - 6.0f;
  // Формула може дати трохи <0 або трохи >100 біля країв — притиснути до 0..100:
  if (rh < 0.0f)   rh = 0.0f;
  if (rh > 100.0f) rh = 100.0f;
  *rh_out = rh;
  return true;
}
```
```python
# CircuitPython: сирий обмін через busio.I2C, без бібліотеки давача
import time
import board
import busio

GY21_ADDR = 0x40   # фіксована адреса, джамперами не змінюється
CMD_TEMP  = 0xF3   # вимір T, no-hold master
CMD_HUM   = 0xF5   # вимір RH, no-hold master

i2c = busio.I2C(board.SCL, board.SDA)

# si7021_crc8() означимо трохи нижче.

# Спільне ядро: послати команду `cmd`, зачекати `wait_ms`, прочитати 3 байти,
# звірити CRC і повернути 16-бітне СИРЕ значення (з обнуленими службовими бітами).
# Повертає raw при успіху; None — якщо давач не відповів або CRC не зійшлася.
def gy21_read_raw(cmd, wait_ms):
    while not i2c.try_lock():
        pass
    try:
        # -- Крок 1: послати командний байт --
        try:
            i2c.writeto(GY21_ADDR, bytes([cmd]))
        except OSError:
            return None                  # давач не підтвердив команду

        # -- Крок 2: витримати паузу, поки давач міряє --
        time.sleep(wait_ms / 1000)

        # -- Крок 3: прочитати рівно 3 байти (MSB, LSB, CRC) --
        buf = bytearray(3)
        try:
            i2c.readfrom_into(GY21_ADDR, buf)
        except OSError:
            return None
        msb, lsb, crc = buf[0], buf[1], buf[2]
    finally:
        i2c.unlock()

    # -- Крок 4a: перевірити контрольну суму над двома байтами даних --
    if si7021_crc8(buf[:2]) != crc:      # зіпсовано в дорозі — відкинути
        return None

    # -- Крок 4b: зібрати число й обнулити 2 службових біти --
    raw = (msb << 8) | lsb
    raw &= 0xFFFC
    return raw


# Публічні читання: та сама функція, різний командний байт і пауза + формула.
def gy21_read_temperature():
    raw = gy21_read_raw(CMD_TEMP, 10)
    if raw is None:
        return None
    return 175.72 * raw / 65536 - 46.85


def gy21_read_humidity():
    raw = gy21_read_raw(CMD_HUM, 20)
    if raw is None:
        return None
    rh = 125.0 * raw / 65536 - 6.0
    # Формула може дати трохи <0 або трохи >100 біля країв — притиснути до 0..100:
    if rh < 0.0:
        rh = 0.0
    if rh > 100.0:
        rh = 100.0
    return rh
```
:::

Кілька місць варті окремого слова.

`Wire.endTransmission()` **повертає код, і 0 — це успіх** (давач відповів ACK на адресу й команду). Ненульове — давач мовчить: не та адреса, обірвана земля, переплутані `SDA`/`SCL`. Ми перевіряємо це одразу, бо немає сенсу чекати й читати з пристрою, який навіть не підтвердив команду.

`Wire.requestFrom(..., 3)` **повертає, скільки байтів реально прийшло**. Якщо давач з якоїсь причини віддав менше трьох, читати `Wire.read()` наосліп небезпечно (поверне `-1`, який мовчки перетвориться на `0xFF`), тож ми звіряємо кількість заздалегідь.

Притискання вологості до діапазону `0..100` — не косметика. Формула лінійна й на краях може дати, скажімо, `100.3 %` або `−0.2 %` через похибку останніх бітів. Показати «вологість 100.3 %» — виглядає як помилка, хоч насправді давач у нормі. Тому обрізаємо.

## Контрольна сума CRC-8

Функцію `si7021_crc8`, яку кличе читання вище, лишилося написати. Це найважливіша частина протоколу — саме вона відрізняє «читаю число» від «читаю число, якому можна вірити».

Навіщо взагалі CRC. Лінії I2C на макетній платі з довгими дротами ловлять перешкоди — увімкнувся поряд двигун, довгий шлейф працює як антена, — і один біт у переданому байті може перевернутися. Зіпсований байт дасть безглузде, але **правдоподібне на вигляд** число: не помилку, не `NaN`, а, скажімо, `−45 °C` у теплій кімнаті або `78 %` замість `45 %`. Око такого не зловить, а прошивка — прийме за правду. Щоб цього не сталося, давач після двох байтів даних шле третій — контрольну суму, обчислену з тих самих двох байтів. Ведучий рахує суму сам і звіряє: зійшлося — дані цілі; ні — вимір відкидаємо й повторюємо.

Тепер конкретика. Давачі родини SHT21/Si7021/HTU21D використовують **CRC-8** з поліномом **x⁸ + x⁵ + x⁴ + 1**. Що це означає на пальцях: беремо потік бітів даних, «ділимо» його (за особливими правилами двійкової арифметики без переносів — це XOR) на число, що відповідає цьому поліному, і залишок від ділення і є контрольна сума. Поліном x⁸+x⁵+x⁴+1 у вісьмох робочих бітах — це `0b0011_0001`, тобто `0x31` (степінь x⁸ — це той дев'ятий біт, що «випадає» за межу байта під час зсуву, тож у самій константі XOR-а він не потрібен). Початкове значення регістра — `0x00`.

Класична реалізація «по байту»: XOR-имо байт у контрольний регістр, потім вісім разів зсуваємо регістр уліво на один біт; якщо перед зсувом старший біт був `1`, після зсуву XOR-имо регістр із `0x31`. Ось і все.

:::tabs
```cpp
// CRC-8, поліном x⁸+x⁵+x⁴+1 (0x31), початкове значення 0x00.
// Рахуємо над `len` байтами; для GY-21 len = 2 (два байти даних виміру).
uint8_t si7021_crc8(const uint8_t *data, uint8_t len) {
  uint8_t crc = 0x00;                      // початкове значення регістра
  for (uint8_t i = 0; i < len; i++) {
    crc ^= data[i];                        // внести черговий байт
    for (uint8_t bit = 0; bit < 8; bit++) {
      if (crc & 0x80)                       // старший біт = 1?
        crc = (uint8_t)((crc << 1) ^ 0x31); //   зсув + XOR з поліномом
      else
        crc = (uint8_t)(crc << 1);          //   інакше просто зсув
    }
  }
  return crc;
}
```
```python
# CRC-8, поліном x⁸+x⁵+x⁴+1 (0x31), початкове значення 0x00.
# Рахуємо над байтами `data`; для GY-21 це 2 байти даних виміру.
def si7021_crc8(data):
    crc = 0x00                             # початкове значення регістра
    for byte in data:
        crc ^= byte                        # внести черговий байт
        for _ in range(8):
            if crc & 0x80:                  # старший біт = 1?
                crc = ((crc << 1) ^ 0x31) & 0xFF  # зсув + XOR з поліномом
            else:
                crc = (crc << 1) & 0xFF     # інакше просто зсув
    return crc
```

Як переконатися, що це не «майже правильно», а точно правильно. У документації давача є **тестові вектори** — пари «вхідні байти → правильна CRC». Проженемо через нашу функцію три з них:

**Перевірка функції на тестових векторах із документації.**
:::tabs
```cpp
si7021_crc8({0xDC},        1) == 0x79   // одиночний контрольний байт з даташита
si7021_crc8({0x68, 0x3A},  2) == 0x7C   // 0x683A ≈ 24.7 °C
si7021_crc8({0x4E, 0x85},  2) == 0x6B   // 0x4E85 ≈ 32.3 % RH
```
```python
assert si7021_crc8(bytes([0xDC]))        == 0x79   # одиночний контрольний байт з даташита
assert si7021_crc8(bytes([0x68, 0x3A]))  == 0x7C   # 0x683A ≈ 24.7 °C
assert si7021_crc8(bytes([0x4E, 0x85]))  == 0x6B   # 0x4E85 ≈ 32.3 % RH
```
:::

Усі три збігаються з очікуваними значеннями з документації — отже, реалізація коректна, і їй можна довіряти на реальних даних. Це не формальність: варто помилитися в поліномі (взяти дзеркальний `0x8C` чи інший степінь) — і функція теж «щось рахуватиме», навіть проходитиме на випадкових даних частину часу, але систематично відкидатиме правильні виміри. Тестові вектори — єдиний спосіб довести, що CRC саме той.

> 🔧 **Навіщо це.** У серйозній прошивці CRC перевіряють **завжди**, а не «коли лишився час». Ціна перевірки — вісім зсувів на байт, тобто мікросекунди; ціна пропуску — раз на кількасот вимірів у результат просочується сміття, яке потім проявиться як стрибок на графіку, хибне спрацювання термостата чи запис у лог, з якого потім довго з'ясовують, чому «датчик показав −45». Один зіпсований біт коштує рівно стільки, скільки ви заклали в перевірку.

## Електронний серійний номер і модель чипа

Під маркуванням «GY-21» ховається або Si7021, або HTU21D, і на вигляд їх не розрізнити — корпус той самий. Але чип можна **спитати**: у Si7021 є команда, що повертає **електронний серійний номер** — унікальний для кожного чипа, і всередині нього закодовано **тип пристрою**.

Механіка така. Серійний номер читається двома командами по два байти кожна. Перша — `0xFA 0x0F` — повертає першу половину номера (з проміжними байтами CRC), друга — `0xFC 0xC9` — другу. Нас цікавить один-єдиний байт із другої половини — **найстарший її байт (SNB3)**: саме він кодує модель. Значення `0x15` означає **Si7021**, `0x14` — Si7020, `0x0D` — Si7013, `0x00` чи `0xFF` — інженерний зразок.

А HTU21D цю пару команд **не підтримує так само**: він або не відповість очікуваним чином, або поверне не ті дані. Тому саме факт, що прочитати `0x15` вдалося, і є ознакою «це Si7021»; якщо не вдалося — перед вами майже напевно HTU21D (чи інший сумісний клон). Ось так «неможливо розрізнити на вигляд» перетворюється на «розрізнити однією командою».

:::tabs
```cpp
// Читає найстарший байт другої половини серійного номера (SNB3),
// що кодує модель чипа. Повертає true й кладе байт у *id_out при успіху.
bool si7021_read_model_id(uint8_t *id_out) {
  // -- Друга половина серійного номера: команда 0xFC 0xC9 --
  Wire.beginTransmission(GY21_ADDR);
  Wire.write(0xFC);
  Wire.write(0xC9);
  if (Wire.endTransmission() != 0) return false;

  // Пристрій віддає 6 байтів: SNB3, SNB2, CRC, SNB1, SNB0, CRC.
  // Нам потрібен найперший (SNB3) — він і є ідентифікатор моделі.
  if (Wire.requestFrom((int)GY21_ADDR, 6) != 6) return false;
  uint8_t snb3 = Wire.read();      // <- ідентифікатор моделі
  // решту байтів дочитуємо, щоб не лишати «хвіст» у буфері шини:
  while (Wire.available()) Wire.read();

  *id_out = snb3;
  return true;
}

// Зручна обгортка: назвати модель словами.
const char* gy21_model_name() {
  uint8_t id;
  if (!si7021_read_model_id(&id)) return "HTU21D або сумісний (не Si70xx)";
  switch (id) {
    case 0x15: return "Si7021";
    case 0x14: return "Si7020";
    case 0x0D: return "Si7013";
    case 0x00:
    case 0xFF: return "Si70xx (інженерний зразок)";
    default:   return "невідомий Si70xx";
  }
}
```

> 🔧 **Навіщо це.** Розрізняти чипи треба не заради цікавості, а коли **важлива швидкість реакції на вологість**: HTU21D наздоганяє зміну за кілька секунд, Si7021 — за десятки. Якщо ваш прилад ловить швидкі стрибки вологи (дихання людини, відкриття дверей теплиці), варто знати, який давач у руках, — і за потреби взяти плату явно з HTU21D. Для повільного клімат-моніторингу різниця неважлива, і код спокійно працює з будь-яким.

## Регістр налаштувань 1: роздільність і нагрівач

У давача є маленький **нагрівальний елемент** просто на кристалі. Навіщо гріти давач вологості? Здавалося б, абсурд — ми ж міряємо повітря, а не підігріваємо його. Але сенс є: якщо на мембрану осів **конденсат** (винесли прилад із тепла на холод, і волога сконденсувалася на давачі), показ вологості залипає на 100 %, поки крапельки не випаруються. Нагрівач їх **випаровує** — і давач швидше повертається до реальних значень. Друге застосування — вимірювання точки роси в лабораторних умовах. У звичайному режимі нагрівач тримають **вимкненим**, бо він, звісно, псує вимір температури.

Керує нагрівачем **регістр налаштувань 1** (user register 1). Читається командою `0xE7`, записується `0xE6`. За вмикання/вимикання нагрівача відповідає **біт 2** цього регістра (0 — вимкнено, 1 — увімкнено). Решта бітів регістра — це роздільність вимірів; за замовчуванням увесь регістр дорівнює `0x3A`, що якраз і означає «12 біт вологості, 14 біт температури, нагрівач вимкнено».

Найважливіше правило роботи з регістром: **не затирайте чужі біти**. Щоб змінити один біт, треба прочитати весь регістр, поміняти в ньому потрібний біт і записати назад — інакше ви ненароком скинете налаштування роздільності. Це загальний прийом «read-modify-write», і на регістрах він обов'язковий.

:::tabs
```cpp
static const uint8_t REG_READ  = 0xE7;   // читати регістр налаштувань 1
static const uint8_t REG_WRITE = 0xE6;   // писати регістр налаштувань 1
static const uint8_t HEATER_BIT = 0x04;  // біт 2 = вмикання нагрівача (HTRE)

// Прочитати регістр налаштувань 1. Повертає true й кладе байт у *reg_out.
static bool gy21_read_user_reg(uint8_t *reg_out) {
  Wire.beginTransmission(GY21_ADDR);
  Wire.write(REG_READ);
  if (Wire.endTransmission() != 0) return false;
  if (Wire.requestFrom((int)GY21_ADDR, 1) != 1) return false;
  *reg_out = Wire.read();
  return true;
}

// Увімкнути (on=true) чи вимкнути (on=false) вбудований нагрівач —
// НЕ чіпаючи бітів роздільності (read-modify-write).
bool gy21_set_heater(bool on) {
  uint8_t reg;
  if (!gy21_read_user_reg(&reg)) return false;   // 1) прочитати поточний стан

  if (on) reg |=  HEATER_BIT;                      // 2) виставити або
  else    reg &= ~HEATER_BIT;                      //    скинути лише біт 2

  Wire.beginTransmission(GY21_ADDR);               // 3) записати назад
  Wire.write(REG_WRITE);
  Wire.write(reg);
  return (Wire.endTransmission() == 0);
}
```
```python
REG_READ   = 0xE7   # читати регістр налаштувань 1
REG_WRITE  = 0xE6   # писати регістр налаштувань 1
HEATER_BIT = 0x04   # біт 2 = вмикання нагрівача (HTRE)

# Прочитати регістр налаштувань 1. Повертає байт або None.
def gy21_read_user_reg():
    while not i2c.try_lock():
        pass
    try:
        buf = bytearray(1)
        try:
            i2c.writeto_then_readfrom(GY21_ADDR, bytes([REG_READ]), buf)
        except OSError:
            return None
        return buf[0]
    finally:
        i2c.unlock()


# Увімкнути (on=True) чи вимкнути (on=False) вбудований нагрівач —
# НЕ чіпаючи бітів роздільності (read-modify-write).
def gy21_set_heater(on):
    reg = gy21_read_user_reg()             # 1) прочитати поточний стан
    if reg is None:
        return False

    if on:
        reg |= HEATER_BIT                   # 2) виставити або
    else:
        reg &= ~HEATER_BIT & 0xFF           #    скинути лише біт 2

    while not i2c.try_lock():               # 3) записати назад
        pass
    try:
        try:
            i2c.writeto(GY21_ADDR, bytes([REG_WRITE, reg]))
        except OSError:
            return False
        return True
    finally:
        i2c.unlock()
```
:::

Логіка `reg |= HEATER_BIT` виставляє біт 2 у одиницю, не торкаючись інших; `reg &= ~HEATER_BIT` — навпаки, обнуляє тільки його (`~HEATER_BIT` — це `0b1111_1011`, маска «усе, крім біта 2»). Це і є суть безпечної роботи з регістром: змінюєш рівно те, що хотів. Роздільність вимірів лежить у бітах 7 і 0 того самого регістра (чотири комбінації від 12/14 біт до 8/12) — і саме тому read-modify-write обов'язковий: запис нагрівача не повинен зачепити роздільність.

> 🔧 **Навіщо це.** У сухому приміщенні нагрівач вам не знадобиться жодного разу. Але щойно прилад працює **надворі, у теплиці, у холодильній камері** — усюди, де можливий перепад температур із конденсатом, — уміння програмно «просушити» давач рятує від годин залипання на 100 %. Це саме той випадок, коли сирий доступ до регістру дає те, чого проста бібліотека часто взагалі не пропонує.

## М'яке скидання (0xFE)

Найпростіша команда — **програмне скидання** (reset), один байт `0xFE`. Отримавши її, давач перезавантажується у стан «як після подачі живлення»: регістр налаштувань повертається до `0x3A` (стандартна роздільність, нагрівач вимкнено), усі поточні операції обриваються.

:::tabs
```cpp
// М'яке скидання давача у стан за замовчуванням.
bool gy21_reset() {
  Wire.beginTransmission(GY21_ADDR);
  Wire.write(0xFE);
  bool ok = (Wire.endTransmission() == 0);
  delay(15);        // давачу треба ~15 мс на перезавантаження
  return ok;
}
```
```python
# М'яке скидання давача у стан за замовчуванням.

        pass
    try:
        try:
            i2c.writeto(GY21_ADDR, bytes([0xFE]))
            ok = True
        except OSError:
            ok = False
    finally:
        i2c.unlock()
    time.sleep(0.015)   # давачу треба ~15 мс на перезавантаження
    return ok
```
:::

Пауза після скидання обов'язкова: поки давач перезавантажується (близько 15 мс), він не відповідатиме на команди, і якщо одразу послати вимір, дістанете помилку. Скидання корисне на старті прошивки (привести давач у відомий стан незалежно від того, що з ним робили до перезапуску контролера) або як спроба «оживити» давач, що завис після наведеної перешкоди, не знімаючи живлення.

## Два режими: утримувати чи не утримувати шину

Скрізь вище ми бралися командами `0xF3`/`0xF5` — це режим **«без утримання шини»** (no-hold master). Але в давача є й другий набір команд для тих самих вимірів — `0xE3` (температура) і `0xE5` (вологість) — режим **«з утриманням шини»** (hold master). Різницю варто розуміти, бо вибір впливає на всю структуру коду.

У режимі **з утриманням** давач, поки міряє, **тримає лінію такту (SCL) притиснутою до нуля** — фізично не дає ведучому нічого робити на шині. Ведучий послав команду й одразу читає; давач «підвішує» його рівно на час виміру, а коли готовий — відпускає SCL, і читання завершується вже готовими даними. Зручно — не треба самому вгадувати паузу. Але ціна велика: **вся шина заблокована** на ці 10–20 мс, жоден інший пристрій на ній не може обмінятися ні байтом, а якщо ваш контролер не вміє коректно обробляти «розтягування такту» (clock stretching), можливі й зависання.

У режимі **без утримання** давач одразу відпускає шину після прийому команди й міряє «мовчки». Ведучий сам витримує паузу (або опитує давач циклом, поки той не відповість замість NACK), і поки давач думає, **шина вільна** — на ній можуть працювати інші пристрої. Саме тому цей режим кращий за замовчуванням, особливо коли на шині живе не один давач: ви не блокуєте всіх заради одного виміру.

```
0xF3 / 0xF5 — no-hold  : шина вільна, ведучий сам чекає паузу   ← типовий вибір
0xE3 / 0xE5 — hold     : давач тримає SCL, шина зайнята на весь вимір
```

Практичний висновок: беріть **no-hold** (`0xF3`/`0xF5`), якщо тільки у вас немає особливої причини навпаки. Особлива причина — рідкісна: наприклад, дуже простий контролер без надійного таймера, якому легше «повисіти» на утриманні, ніж відрахувати паузу.

## Пастки протоколу

Три помилки псують результат навіть тоді, коли обмін начебто «працює».

**Забули маску `0xFFFC`.** Не обнулили два молодших службових біти — і в результат просочується похибка в кілька останніх одиниць. На температурі це дрібниця (соті градуса), але на межі й на вологості видно. Маска коштує один рядок — не пропускайте його.

**Пропустили CRC.** Найпідступніша, бо код «працює», поки шина чиста. Досить довшого дроту, наведення від двигуна поряд чи поганого контакту — і раз на сотні вимірів у дані прослизне перевернутий біт, який дасть правдоподібне, але хибне число. Без перевірки CRC ви його не зловите. Ставте перевірку з самого початку, а не «потім допишу».

**Плутанина no-hold vs hold.** Узяли команду одного режиму, а читаєте за логікою іншого — і дістаєте сміття або зависання. Якщо послали `0xF3`/`0xF5` (no-hold), **обов'язково витримайте паузу** перед читанням; якщо читаєте одразу без паузи — прочитаєте недороблений результат або нарветеся на NACK. І навпаки: під команди `0xE3`/`0xE5` (hold) ваш контролер має вміти розтягування такту.
