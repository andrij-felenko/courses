# Поглиблений інженерний аналіз та промислова розробка для AHT20

Мікроелектромеханічний датчик AHT20 є високоточним промисловим компонентом для вимірювання температури та вологості, орієнтованим на системи з високими вимогами до енергоефективності, метрологічної стабільності та надійності обміну даними по шині I2C.

У цьому детальному посібнику розглядаються порівняльний метрологічний аналіз AHT20 з ринковими конкурентами, параметричний розрахунок електричних параметрів шини I2C, швидкісні табличні алгоритми перевірки контрольної суми CRC-8, архітектура асинхронного драйвера для операційних систем реального часу (FreeRTOS) та протоколи відновлення шини при зависаннях.

---

## 1. Порівняльний метрологічний аналіз AHT20 та конкурентів: похибки, дрейф, час відгуку

Для вибору оптимального датчика в інженерних проектах необхідно порівняти характеристики AHT20 з аналогами провідних світових виробників (Sensirion SHT30/SHT40, Bosch BME280, Texas Instruments HDC1080 та застарілим DHT22).

### Порівняльна таблиця сенсорів вологості та температури

| Параметр | AHT20 (ASAIR) | SHT30 (Sensirion) | BME280 (Bosch) | DHT22 (AM2302) |
| :--- | :--- | :--- | :--- | :--- |
| **Технологія осередку** | Ємнісний MEMS + SiP | CMOSens (ємнісний) | MEMS (ємнісний) | Дискретний полімер |
| **Точність вологості** | **+/-2.0% RH** | +/-2.0% RH (SHT31: +/-1.5%) | +/-3.0% RH | +/-2.0% RH |
| **Точність температури** | **+/-0.3 °C** | +/-0.2 °C | +/-0.5 °C | +/-0.5 °C |
| **Діапазон вологості** | **0 .. 100% RH** | 0 .. 100% RH | 0 .. 100% RH | 0 .. 99.9% RH |
| **Діапазон температур** | **-40 .. +85 °C** | -40 .. +125 °C | -40 .. +85 °C | -40 .. +80 °C |
| **Час відгуку t_63% (RH)** | **5 .. 8 с** | 6 .. 8 с | 1 с | 15 .. 30 с |
| **Струм у режимі сну** | **0.25 мкА** | 0.20 мкА | 0.10 мкА | 50 мкА |
| **Роздільна здатність** | **20 біт (0.024% RH)** | 16 біт (0.01% RH) | 16 біт (0.008% RH) | 16 біт (0.1% RH) |
| **Інтерфейс передачі** | I2C (до 400 кГц) | I2C (до 1000 кГц) | I2C / SPI | Single-Wire (кастом) |
| **Валідація пакету** | CRC-8 (поліном 0x31) | CRC-8 (поліном 0x31) | Без апаратного CRC | 8-біт арифметична сума |

### Крива розподілу похибки вологості

Як і більшість ємнісних полімерних давачів, AHT20 має нерівномірну похибку за шкалою вологості:
- У комфортному діапазоні **20% ... 80% RH** (за температури 25 °C) гарантована похибка становить не більше **+/-2.0% RH**.
- На краях діапазону (нижче 10% RH та вище 90% RH) абсолютна похибка дещо розширюється і становить **+/-3.0% ... +/-3.5% RH** через нелінійне насичення мікропор полімеру та крайові діелектричні ефекти.
- Довгостроковий дрейф сенсора становить менше **0.5% RH на рік** у нормальному повітряному середовищі, що в 4 рази краще за дискретні резистивні та ємнісні датчики попередніх поколінь.

## 2. Апаратна інтеграція I2C: розрахунок підтягуючих резисторів, ємність шини та DMA

Надійна передача даних по шині I2C у промислових приладах вимагає точного узгодження номіналу підтягуючих резисторів R_pull з сумарною паразитною ємністю лінії C_bus.

### Розрахунок номіналу підтягуючих резисторів (I2C Specification UM10204)

1. **Мінімальний допустимий опір (R_pull_min):** Визначається максимально допустимим струмом відкритого стоку мікросхеми (для AHT20 максимальний вихідний струм опускання шини I_OL становить 3.0 мА при напрузі насичення V_OL_max = 0.4 В):
   ```
   R_pull_min = (V_DD - V_OL_max) / I_OL
   ```
   Для живлення V_DD = 3.3 В:
   ```
   R_pull_min = (3.3 В - 0.4 В) / 0.003 А = 2.9 В / 0.003 А ≈ 967 Ом
   ```
   Для живлення V_DD = 5.0 В:
   ```
   R_pull_min = (5.0 В - 0.4 В) / 0.003 А = 4.6 В / 0.003 А ≈ 1533 Ом
   ```

2. **Максимальний допустимий опір (R_pull_max):** Визначається максимально допустимою тривалістю наростання фронту сигналу t_r (за стандартом для Fast-mode 400 кГц тривалість фронту t_r не повинна перевищувати 300 нс):
   ```
   R_pull_max = t_r / (0.8473 * C_bus)
   ```
   Якщо сумарна ємність шини (доріжки друкованої плати + вхідна ємність пінів мікроконтролера та AHT20) становить C_bus = 50 пФ:
   ```
   R_pull_max = 300e-9 с / (0.8473 * 50e-12 Ф) ≈ 300e-9 / 4.236e-11 ≈ 7080 Ом (7.1 кОм)
   ```
   Таким чином, оптимальним інженерним вибором є номінал **R_pull = 4.7 кОм** для компактних плат або **2.2 кОм** при довжині траси понад 30–50 см.

## 3. Високоефективний табличний розрахунок CRC-8 (Lookup Table) та верифікація пакета

Побітовий алгоритм обчислення CRC-8 у циклі вимагає 8 ітерацій зсуву та умовних переходів на кожен байт (загалом 48 ітерацій на фрейм), що створює помітне процесорне навантаження при частих опитуваннях або роботі на низьких тактових частотах ядра (наприклад, 2–4 МГц у режимах енергозбереження).

Табличний метод замінює обчислення всього байта однією операцією вибірки з 256-байтного масиву `lut[256]`, який розміщується в пам'яті Flash (ROM).

### Генерація та константна таблиця CRC-8 (Flash ROM)

/**
 * @brief Високошвидкісний табличний розрахунок CRC-8
 */
uint8_t aht20_fast_crc8(const uint8_t *data, size_t length) {
    uint8_t crc = 0xFF; /* Початковий вектор */
    for (size_t i = 0; i < length; ++i) {
        crc = aht20_crc8_lut[crc ^ data[i]];
    }
    return crc;
}

Табличний розрахунок виконується всього за 6 ітерацій (по одній операції на байт), скорочуючи час виконання перевірки до менше 0.5 мікросекунди при частоті ядра 48 МГц.

## 4. Повний асинхронний драйвер на FreeRTOS з використанням черг та блокування м'ютексом

У реальних вбудованих пристроях шина I2C зазвичай використовується спільно декількома мікросхемами (наприклад, датчиком тиску BMP280, годинником реального часу RTC або пам'яттю EEPROM). Спільний доступ вимагає синхронізації через м'ютекс RTOS, а пауза 80 мс повинна віддавати процесор іншим задачам через системний планувальник.

Нижче наведено повнофункціональний асинхронний модуль опитування AHT20 під керуванням FreeRTOS:

```c
#include "FreeRTOS.h"
#include "task.h"
#include "semphr.h"
#include <stdint.h>
#include <stdbool.h>

/* Дескриптор м'ютекса спільної шини I2C */
extern SemaphoreHandle_t xI2CMutex;

typedef struct {
    float humidity;
    float temperature;
    uint32_t timestamp_ms;
    bool is_valid;
} aht20_telemetry_t;

/* Черга для передачі результатів у систему телеметрії */
extern QueueHandle_t xTelemetryQueue;

/**
 * @brief Задача періодичного опитування сенсора AHT20 у FreeRTOS
 */
void vAHT20_Task(void *pvParameters) {
    const TickType_t xFrequency = pdMS_TO_TICKS(10000); /* Опитування кожні 10 секунд */
    TickType_t xLastWakeTime = xTaskGetTickCount();
    uint8_t tx_trigger[3] = {0xAC, 0x33, 0x00};
    uint8_t rx_buf[7] = {0};

    for (;;) {
        /* Очікуємо наступного періоду опитування без навантаження на процесор */
        vTaskDelayUntil(&xLastWakeTime, xFrequency);

        /* 1. Захоплення шини I2C для запуску вимірювання */
        if (xSemaphoreTake(xI2CMutex, pdMS_TO_TICKS(100)) == pdTRUE) {
            /* Запуск перетворення */
            platform_i2c_write(0x38, tx_trigger, 3);
            /* Відпускаємо м'ютекс, щоб інші задачі могли користуватися I2C під час оцифрування */
            xSemaphoreGive(xI2CMutex);
        } else {
            continue; /* Не вдалося захопити шину */
        }

        /* 2. Апаратне очікування завершення оцифрування (85 мс) у режимі сну задачі */
        vTaskDelay(pdMS_TO_TICKS(85));

        /* 3. Захоплення шини I2C для зчитування результатів */
        if (xSemaphoreTake(xI2CMutex, pdMS_TO_TICKS(100)) == pdTRUE) {
            bool read_ok = platform_i2c_read(0x38, rx_buf, 7);
            xSemaphoreGive(xI2CMutex);

            if (read_ok) {
                /* Перевірка статусу (BUSY == 0) та валідація CRC-8 */
                if ((rx_buf[0] & 0x80) == 0 && aht20_fast_crc8(rx_buf, 6) == rx_buf[6]) {
                    uint32_t raw_rh = ((uint32_t)rx_buf[1] << 12) | 
                                      ((uint32_t)rx_buf[2] << 4)  | 
                                      ((uint32_t)rx_buf[3] >> 4);

                    uint32_t raw_temp = (((uint32_t)rx_buf[3] & 0x0F) << 16) | 
                                        ((uint32_t)rx_buf[4] << 8)            | 
                                        ((uint32_t)rx_buf[5]);

                    aht20_telemetry_t report;
                    report.humidity = ((float)raw_rh / 1048576.0f) * 100.0f;
                    report.temperature = (((float)raw_temp / 1048576.0f) * 200.0f) - 50.0f;
                    report.timestamp_ms = (uint32_t)(xTaskGetTickCount() * portTICK_PERIOD_MS);
                    report.is_valid = true;

                    /* Відправляємо виміряні дані в чергу телеметрії */
                    xQueueSend(xTelemetryQueue, &report, 0);
                }
            }
        }
    }
}
```

## 5. Технічні вимоги до надійності, відновлення після збоїв та калібрувальні протоколи

У реальних індустріальних системах можливі ситуації нештатної поведінки шини, викликані просіданням живлення або імпульсними завадами.

### Процедура відновлення шини I2C при зависанні (Bus Lockup Recovery)

Якщо мікроконтролер перезавантажується у той момент, коли AHT20 передавав біт «0» і утримував лінію SDA притиснутою до землі, лінія SDA блокується (SDA Stuck Low), оскільки сенсор чекає чергового тактового імпульсу SCL для завершення передачі біта.

Для програмного розблокування шини при ініціалізації контролера реалізують спеціальну процедуру "прокачування" тактових імпульсів:
1. Перемикають вивід піна SCL у режим виходу загального призначення (GPIO Output).
2. Генерують **9 послідовних імпульсів тактування SCL** з частотою близько 100 кГц. Отримавши до 9 імпульсів, ведений пристрій виштовхує поточний байт і відпускає лінію SDA у високий стан.
3. Генерують умову **I2C STOP** (перехід SDA з низького в високий стан при високому SCL).
4. Переконфігурують виводи SCL та SDA назад у режим периферійного апаратного блоку I2C.

### Автоматичне повторне калібрування сенсора

Якщо в процесі експлуатації опитування байта стану показує `CAL_EN == 0` (біт 3 скинуто через електростатичний розряд ESD або скидання пам'яті ASIC), драйвер повинен автоматично ініціювати цикл реініціалізації:
- Надіслати команду програмного скидання (Soft Reset): байт `0xBA`, почекати 20 мс.
- Надіслати команду ініціалізації `0xBE 0x08 0x00`, почекати 10 мс.
- Переконатися, що біт 3 байта стану знову дорівнює 1.

Така багаторівнева стратегія захисту гарантує цілодобову безперебійну роботу сенсора в необслуговуваних метеорологічних та промислових системах автоматизації.
