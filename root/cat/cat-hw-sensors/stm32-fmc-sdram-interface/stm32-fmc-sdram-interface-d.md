# Поглиблена конфігурація регістрів FMC, таймінгів SDRAM та кешування

Налаштування інтерфейсу зовнішньої синхронної динамічної пам'яті (SDRAM) через контролер FMC вимагає точного узгодження часових параметрів у наносекундах із тактовою сіткою мікроконтролера. Помилка навіть на один такт у параметрах `CAS Latency` або `tRP` призводить до спотворення графічних фреймбуферів, пошкодження текстур або виникнення важкодіагностованих апаратних помилок `HardFault` ядра процесора.

У цьому розділі наведено поглиблений розбір регістрової структури FMC, налаштування політик кешування MPU для відеотракту та повний низькорівневий виробничий драйвер на мові C.

## 1. Детальний аналіз регістрової моделі FMC SDRAM

Керування двома банками SDRAM (Bank 5 та Bank 6) здійснюється набором регістрів `FMC_Bank5_6`:

```text
+------------------+--------------------------------------------------------------------------+
| Регістр          | Функціональне призначення та ключові бітові поля                         |
+------------------+--------------------------------------------------------------------------+
| FMC_SDCR[1:2]    | SDRAM Control Register (Керування параметрами пам'яті):                  |
|                  | - [14:13] RPIPE[1:0]: Затримка читання конвеєра (0, 1 або 2 такти SDCLK)|
|                  | - [12] RBURST: Дозвіл пакетного читання (Read Burst enable)              |
|                  | - [11:10] SDCLK[1:0]: Дільник частоти шини: 10 = HCLK/2, 11 = HCLK/3   |
|                  | - [9] WP: Захист від запису (Write Protection, 1 = Read Only)            |
|                  | - [8:7] CAS[1:0]: Апаратна затримка CAS: 01 = 1 такт, 10 = 2, 11 = 3     |
|                  | - [6] NB: Кількість внутрішніх банків мікросхеми: 0 = 2 банки, 1 = 4     |
|                  | - [5:4] MWID[1:0]: Розрядність шини даних: 00 = 8 біт, 01 = 16, 10 = 32  |
|                  | - [3:2] NR[1:0]: Кількість біт адреси рядка: 00 = 11, 01 = 12, 10 = 13   |
|                  | - [1:0] NC[1:0]: Кількість біт адреси стовпчика: 00 = 8, 01 = 9, 10 = 10 |
+------------------+--------------------------------------------------------------------------+
| FMC_SDTR[1:2]    | SDRAM Timing Register (Таймінги в тактах SDCLK мінус 1):                 |
|                  | - [27:24] TRCD[3:0]: RAS to CAS delay (типово 2 такти)                   |
|                  | - [23:20] TRP[3:0]: Row Precharge delay (типово 2 такти)                 |
|                  | - [19:16] TWR[3:0]: Recovery delay після запису (типово 2 такти)         |
|                  | - [15:12] TRC[3:0]: Row cycle delay (типово 6-7 тактів)                  |
|                  | - [11:8] TRAS[3:0]: Self-refresh / Row active time (типово 4-5 тактів)   |
|                  | - [7:4] TXSR[3:0]: Exit self-refresh delay (типово 6-8 тактів)           |
|                  | - [3:0] TMRD[3:0]: Load Mode Register delay (типово 2 такти)             |
+------------------+--------------------------------------------------------------------------+
| FMC_SDCMR        | SDRAM Command Mode Register (Видача службових команд):                   |
|                  | - [2:0] MODE[2:0]: Команда: 001 = Clock Config, 010 = PALL,             |
|                  |                    011 = Auto-Refresh, 100 = Load Mode Register          |
|                  | - [4:3] CTB[2:1]: Вибір цільового банку: 1 = Bank 1, 2 = Bank 2, 3 = Both|
|                  | - [8:5] NRFS[3:0]: Кількість послідовних циклів Auto-Refresh (1..16)     |
|                  | - [21:9] MRD[12:0]: 13-бітне слово конфігурації Mode Register SDRAM      |
+------------------+--------------------------------------------------------------------------+
| FMC_SDRTR        | SDRAM Refresh Timer Register:                                            |
|                  | - [13:1] COUNT[12:0]: 13-бітний період між регенераціями рядків          |
|                  | - [14] REIE: Дозвіл переривання помилки регенерації Refresh Error         |
+------------------+--------------------------------------------------------------------------+
```

## 2. Структура слова регістра режимів (Mode Register Definition — MRD)

Під час виконання кроку `Load Mode Register` (LMR) контролер FMC передає 13-бітне бітове слово, яке записується у внутрішній статичний регістр самої мікросхеми SDRAM через адресну шину A[12:0]:

```text
Біти MRD    |  Функція                 |  Значення для конфігурації STM32
------------+--------------------------+------------------------------------------------
[2:0]       |  Burst Length (BL)       |  000: Довжина пакета = 1 слово (обов'язково!)
[3]         |  Burst Type              |  0: Послідовний режим (Sequential)
[6:4]       |  CAS Latency (CL)        |  010: CL = 2 такти або 011: CL = 3 такти
[8:7]       |  Operating Mode          |  00: Стандартний робочий режим
[9]         |  Write Burst Mode        |  1: Одиночний запис (Single Location Write)
[12:10]     |  Reserved                |  000: Зарезервовано виробником
```

Бітова маска конфігураційного слова для `CL = 2`:
```c
#define SDRAM_MODEREG_BURST_LENGTH_1             ((uint16_t)0x0000)
#define SDRAM_MODEREG_BURST_TYPE_SEQUENTIAL      ((uint16_t)0x0000)
#define SDRAM_MODEREG_CAS_LATENCY_2              ((uint16_t)0x0020)
#define SDRAM_MODEREG_OPERATING_MODE_STANDARD    ((uint16_t)0x0000)
#define SDRAM_MODEREG_WRITEBURST_MODE_SINGLE     ((uint16_t)0x0200)

/* Підсумкове значення слова MRD */
#define SDRAM_MODE_REG_VALUE (SDRAM_MODEREG_BURST_LENGTH_1 | \
                              SDRAM_MODEREG_BURST_TYPE_SEQUENTIAL | \
                              SDRAM_MODEREG_CAS_LATENCY_2 | \
                              SDRAM_MODEREG_OPERATING_MODE_STANDARD | \
                              SDRAM_MODEREG_WRITEBURST_MODE_SINGLE)
/* 0x0220 = 0b0000_0010_0010_0000 */
```

## 3. Налаштування MPU та політики кешування L1 D-Cache

Оскільки зовнішня SDRAM розташована в адресному просторі `0xC0000000`, ядро Cortex-M7 (у STM32F7 та STM32H7) за замовчуванням сприймає її як зовнішній пристрій без кешування (Device Memory), що знижує швидкість доступу у 10–15 разів.

Для отримання максимальної швидкодії графіки обов'язково налаштовується модуль MPU:

```text
Тип пам'яті MPU               |  Швидкість CPU  |  Особливості роботи з відеотрактом DMA/LTDC
------------------------------+-----------------+-----------------------------------------------
Normal, Non-Cacheable         |  Середня        |  100% когерентність без викликів Cache-Clean.
Normal, Write-Through         |  Висока         |  Читання кешується, запис відразу йде в SDRAM.
Normal, Write-Back (Cached)   |  Максимальна    |  Потребує SCB_CleanDCache перед запуском LTDC.
```

### Рекомендована сегментація SDRAM у графічних проектах:
- **Ділянка 1 (0xC0000000, 8 МБ) — Write-Through / Non-Cacheable:**
  Використовується для подвійного буфера екрана (Front-Buffer та Back-Buffer) контролера LTDC та вихідного буфера камери DCMI. Будь-який піксель, намальований процесором або перенесений DMA, миттєво з'являється у фізичній пам'яті, що виключає появу смуг та розривів кадру (Tearing).
- **Ділянка 2 (0xC0800000, 8 МБ) — Write-Back / Read-Allocate:**
  Використовується як динамічна купа (SDRAM Heap) для важких обчислень, масивів штучного інтелекту (CMSIS-NN / TensorFlow Lite) та стиснення кадрів JPEG.

## 4. Виробничий низькорівневий драйвер ініціалізації SDRAM на мові C

Нижче наведено виробничий драйвер повної ініціалізації зовнішньої пам'яті IS42S16400J (16-бітний інтерфейс, 8 МБ) для мікроконтролера STM32F429 / F746:

```c
#include "stm32f4xx.h"
#include <stdint.h>
#include <stdbool.h>

#define SDRAM_TIMEOUT           ((uint32_t)0xFFFF)
#define SDRAM_BASE_ADDR         ((uint32_t)0xC0000000)

/* Допоміжна функція очікування завершення внутрішньої команди FMC */
static bool fmc_sdram_wait_ready(void) {
    uint32_t timeout = SDRAM_TIMEOUT;
    while ((FMC_Bank5_6->SDSR & FMC_SDSR_BUSY) && (--timeout > 0));
    return (timeout > 0);
}

/**
 * @brief Повна апаратна ініціалізація зовнішньої SDRAM за стандартом JEDEC
 */
bool fmc_sdram_init(void) {
    /* 1. Увімкнення тактування контролера FMC та портів GPIO */
    RCC->AHB3ENR |= RCC_AHB3ENR_FMCEN;
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOBEN | RCC_AHB1ENR_GPIOCEN | RCC_AHB1ENR_GPIODEN |
                    RCC_AHB1ENR_GPIOEEN | RCC_AHB1ENR_GPIOFEN | RCC_AHB1ENR_GPIOGEN;

    /* (Примітка: налаштування пінів GPIO в режим Alternate Function AF12 опускається для стислості) */

    /* 2. Конфігурація регістру таймінгів FMC_SDTR1 (при тактовій SDCLK = 90 МГц, такт = 11.1 нс)
     * - TRCD = 2 такти (11.1 * 2 = 22.2 нс >= 18 нс) -> код (2 - 1) = 1
     * - TRP  = 2 такти (22.2 нс >= 18 нс)           -> код (2 - 1) = 1
     * - TWR  = 2 такти                             -> код (2 - 1) = 1
     * - TRC  = 6 тактів (66.6 нс >= 60 нс)          -> код (6 - 1) = 5
     * - TRAS = 4 такти (44.4 нс >= 42 нс)          -> код (4 - 1) = 3
     * - TXSR = 7 тактів                            -> код (7 - 1) = 6
     * - TMRD = 2 такти                             -> код (2 - 1) = 1 */
    FMC_Bank5_6->SDTR[0] = (1 << FMC_SDTR1_TRCD_Pos) |
                           (1 << FMC_SDTR1_TRP_Pos)  |
                           (1 << FMC_SDTR1_TWR_Pos)  |
                           (5 << FMC_SDTR1_TRC_Pos)  |
                           (3 << FMC_SDTR1_TRAS_Pos) |
                           (6 << FMC_SDTR1_TXSR_Pos) |
                           (1 << FMC_SDTR1_TMRD_Pos);

    /* 3. Конфігурація регістру керування FMC_SDCR1:
     * - NC = 00 (8 біт адреси стовпчика: 256 стовпчиків)
     * - NR = 01 (12 біт адреси рядка: 4096 рядків)
     * - MWID = 01 (16-бітна шина даних)
     * - NB = 1 (4 внутрішні банки)
     * - CAS = 10 (CAS Latency = 2 такти)
     * - WP = 0 (Запис дозволено)
     * - SDCLK = 10 (FMC_SDCLK = HCLK / 2 = 180 / 2 = 90 МГц)
     * - RBURST = 1 (Read Burst дозволено)
     * - RPIPE = 01 (Затримка конвеєра читання = 1 такт) */
    FMC_Bank5_6->SDCR[0] = (0 << FMC_SDCR1_NC_Pos)    |
                           (1 << FMC_SDCR1_NR_Pos)    |
                           (1 << FMC_SDCR1_MWID_Pos)  |
                           FMC_SDCR1_NB               |
                           (2 << FMC_SDCR1_CAS_Pos)   |
                           (2 << FMC_SDCR1_SDCLK_Pos) |
                           FMC_SDCR1_RBURST           |
                           (1 << FMC_SDCR1_RPIPE_Pos);

    /* =================== ВИКОНАННЯ ПОСЛІДОВНОСТІ JEDEC =================== */

    /* Крок 1: Команда Clock Configuration Enable (MODE = 001, CTB1 = 1) */
    FMC_Bank5_6->SDCMR = (1 << FMC_SDCMR_MODE_Pos) | FMC_SDCMR_CTB1;
    if (!fmc_sdram_wait_ready()) return false;

    /* Обов'язкова апаратна пауза > 100 мкс для стабілізації кристала */
    for (volatile uint32_t i = 0; i < 20000; i++) __NOP();

    /* Крок 2: Команда Precharge All (MODE = 010, CTB1 = 1) */
    FMC_Bank5_6->SDCMR = (2 << FMC_SDCMR_MODE_Pos) | FMC_SDCMR_CTB1;
    if (!fmc_sdram_wait_ready()) return false;

    /* Крок 3: Команда Auto-Refresh (MODE = 011, NRFS = 8 циклів, CTB1 = 1) */
    FMC_Bank5_6->SDCMR = (3 << FMC_SDCMR_MODE_Pos) | FMC_SDCMR_CTB1 | (8 << FMC_SDCMR_NRFS_Pos);
    if (!fmc_sdram_wait_ready()) return false;

    /* Крок 4: Команда Load Mode Register (MODE = 100, CTB1 = 1, MRD = 0x0220) */
    FMC_Bank5_6->SDCMR = (4 << FMC_SDCMR_MODE_Pos) | FMC_SDCMR_CTB1 | (0x0220 << FMC_SDCMR_MRD_Pos);
    if (!fmc_sdram_wait_ready()) return false;

    /* Крок 5: Запис лічильника авторегенерації у регістр FMC_SDRTR
     * Формула: COUNT = (64 мс / 4096) * 90 МГц - 20 = 1386 */
    FMC_Bank5_6->SDRTR = (1386 << FMC_SDRTR_COUNT_Pos);

    return true; /* SDRAM повністю готова до роботи за адресою 0xC0000000 */
}
```

## 5. Типові дефекти та чек-лист апаратного аудиту

1. **Мерехтіння або вертикальні кольорові смуги на дисплеї LTDC:**
   - *Причина:* Занижене значення лічильника регенерації у регістрі `FMC_SDRTR` або перегрів пам'яті (при 70 °C період утримання заряду конденсаторів DRAM скорочується вдвічі: з 64 мс до 32 мс).
   - *Виправлення:* Зменшити значення COUNT на 30–40% для забезпечення подвійного запасу регенерації.
2. **Артефакти окремих випадкових бітів при читанні (Bit-Flip):**
   - *Причина:* Неправильно вибраний дільник конвеєра `RPIPE` у регістрі `FMC_SDCR`. На частоті 90 МГц затримка поширення сигналу по друкованій платі становить 1.5–2 нс, тому `RPIPE` обов'язково повинен бути встановлений у `1 такт`.
3. **Зависання мікроконтролера в HardFault при першому записі:**
   - *Причина:* Спроба звернення до пам'яті до скидання біта `FMC_SDSR_BUSY` або незадіяне тактування порту FMC через регістр `RCC_AHB3ENR`.
