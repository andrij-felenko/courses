# Поглиблений аналіз архітектури L1 D-Cache, SCB-інструкцій та MPU в Cortex-M7

Ядро ARM Cortex-M7 оснащене надшвидкісною підсистемою пам'яті, де доступ до локального L1-кешу виконується всього за 1 такт процесора, тоді як читання з фізичного ОЗП (SRAM або тим більше зовнішньої SDRAM) через багатошарову матрицю AXI вимагає від 6 до 40 тактів очікування. Для оптимізації роботи з великими потоками даних (камери DCMI, графічні буфери LTDC) розробник повинен володіти апаратною структурою ліній кешу, реєстрами контролера SCB та точними правилами налаштування MPU.

---

## 1. Внутрішня апаратна структура L1 Data Cache у Cortex-M7

Кеш даних Cortex-M7 організований як **4-канальний множинно-асоціативний кеш (4-Way Set Associative)**:
- **Розмір лінії (Cache Line):** фіксований і становить рівно **32 байти (8 слів по 32 біти)**.
- **Структура лінії:**
  1. `Tag` (Тег адреси): старші біти фізичної адреси пам'яті;
  2. `Data` (Поле даних): 256 бітів (32 байти);
  3. `V` (Valid bit): ознака дійсності даних у лінії;
  4. `D` (Dirty bit): ознака модифікації (встановлюється в 1, якщо процесор записав дані в кеш у режимі Write-Back, але ще не скинув їх у RAM).

Адресація лінії кешу розбиває 32-бітну адресу пам'яті на три поля:
```text
[31 ................. 12] [11 ........... 5] [4 ..... 0]
      Tag (Тег)             Index (Номер Set)   Offset (0..31)
```

Залежно від конфігурації мікроконтролера (наприклад, 16 КБ D-Cache):
- Кількість наборів (Sets): 128 наборів;
- Кількість каналів (Ways): 4 канали;
- Загальний обсяг: `128 Sets * 4 Ways * 32 Bytes = 16 384 байти (16 КБ)`.

## 2. Системні регістри SCB та машинний цикл обслуговування кешу

Керування лініями кешу здійснюється через виділені регістри блоку керування ядром `SCB (System Control Block)`:

```text
+-------------------+--------------------------------------------------------------------------+
| Регістр SCB       | Асемблерне призначення та дія на рівні апаратури                         |
+-------------------+--------------------------------------------------------------------------+
| SCB->DCCMVAC      | Data Cache Clean by MVA (Modified Virtual Address):                      |
|                   | Записує лінію, що містить вказану адресу, в фізичну пам'ять RAM,        |
|                   | якщо встановлено Dirty-біт. Скидає Dirty-біт (D = 0). Valid залишається 1.|
+-------------------+--------------------------------------------------------------------------+
| SCB->DCIMVAC      | Data Cache Invalidate by MVA:                                            |
|                   | Скидає Valid-біт лінії (V = 0). Вміст лінії анулюється.                  |
|                   | УВАГА: Якщо лінія була Dirty, незбережені дані процесора будуть ЗНИЩЕНІ!|
+-------------------+--------------------------------------------------------------------------+
| SCB->DCCIMVAC     | Data Cache Clean and Invalidate by MVA:                                  |
|                   | Спочатку скидає лінію в RAM (якщо Dirty), а потім інвалідує (V = 0).     |
+-------------------+--------------------------------------------------------------------------+
```

### Як функція CMSIS обробляє довільний діапазон пам'яті:

Реалізація функції `SCB_InvalidateDCache_by_Addr()` виконує циклічний прохід по всіх 32-байтових лініях, що перетинають заданий масив:

```c
void SCB_InvalidateDCache_by_Addr(uint32_t *addr, int32_t dsize) {
    if (dsize <= 0) return;

    /* Вирівнювання початкової адреси вниз на межу 32 байти */
    uint32_t op_addr = (uint32_t)addr & ~0x1F;
    int32_t op_size  = dsize + ((uint32_t)addr & 0x1F);

    /* Бар'єр пам'яті перед початком операції */
    __DSB();

    while (op_size > 0) {
        SCB->DCIMVAC = op_addr; /* Інвалідація 32-байтової лінії */
        op_addr += 32;
        op_size -= 32;
    }

    /* Бар'єри синхронізації інструкцій та конвеєра даних */
    __DSB();
    __ISB();
}
```

> **Критичний аналіз коду:** Зверніть увагу на перший рядок функції: `op_addr = (uint32_t)addr & ~0x1F;`. Якщо ваш масив починався не з межі 32 байти (наприклад, `0x20000004`), функція округлить адресу вниз до `0x20000000` і інвалідує перші 4 байти, які належали іншій змінній! Якщо та змінна була Dirty, вона буде незворотно знищена. Саме тому вирівнювання `aligned(32)` є життєво необхідним.

## 3. Налаштування регістрів MPU для створення Non-Cacheable регіону

Для виключення оверхеду на постійну інвалідацію кадрових буферів камери рекомендується виділити окремий сектор пам'яті в `SRAM1` або `AXI-SRAM` і позначити його в MPU як **Normal Non-Cacheable, Shareable**.

### Бітові поля регістра MPU_RASR (Region Attribute and Size Register):

```text
Біти RASR   |  Поле         |  Значення для Normal Non-Cacheable
------------+---------------+------------------------------------------------------------------
[28]        |  XN           |  1: Заборона виконання коду (Execute Never)
[26:24]     |  AP[2:0]      |  011: Повний доступ читання/запис для Privileged та User
[21:19]     |  TEX[2:0]     |  001: Зовнішня нормальна пам'ять (Outer Normal)
[18]        |  S            |  1: Дозвіл спільного використання (Shareable)
[17]        |  C            |  0: Кешування вимкнено (Non-Cacheable)
[16]        |  B            |  0: Буферизацію відкладеного запису вимкнено (Non-Bufferable)
[5:1]       |  SIZE[4:0]    |  Розмір регіону: 0x0F = 64 КБ, 0x10 = 128 КБ, 0x11 = 256 КБ
[0]         |  ENABLE       |  1: Регіон активовано
```

### Пряма регістрова ініціалізація MPU на мові C:

```c
#include "stm32h7xx.h"

#define DCMI_BUFFER_BASE_ADDR   0x24000000 /* AXI-SRAM D1 Domain */
#define DCMI_BUFFER_SIZE_CODE   0x11       /* 256 КБ: 2^(17+1) = 2^18 = 256 КБ (код 17 = 0x11) */

void mpu_setup_camera_noncacheable_region(void) {
    /* 1. Зупинка конвеєра та вимикання MPU */
    __DMB();
    MPU->CTRL = 0;

    /* 2. Вибір номеру регіону (наприклад, Region 2) та базової адреси */
    MPU->RNR  = 2;
    MPU->RBAR = DCMI_BUFFER_BASE_ADDR;

    /* 3. Конфігурація атрибутів:
     * - XN = 1 (біт 28)
     * - AP = 011 (біти 26:24 = 3)
     * - TEX = 001 (біти 21:19 = 1)
     * - S = 1 (біт 18)
     * - C = 0 (біт 17)
     * - B = 0 (біт 16)
     * - SIZE = 0x11 (біти 5:1 = 256 КБ)
     * - ENABLE = 1 (біт 0) */
    MPU->RASR = (1 << 28) |
                (3 << 24) |
                (1 << 19) |
                (1 << 18) |
                (0 << 17) |
                (0 << 16) |
                (DCMI_BUFFER_SIZE_CODE << 1) |
                1;

    /* 4. Увімкнення MPU з збереженням стандартної карти для фонової пам'яті */
    MPU->CTRL = MPU_CTRL_ENABLE_Msk | MPU_CTRL_PRIVDEFENA_Msk;

    /* 5. Бар'єри синхронізації пам'яті та інструкцій ядра */
    __DSB();
    __ISB();
}
```

## 4. Порівняння продуктивності: Non-Cacheable MPU проти Maintenance

Розрахуємо витрати процесорного часу для відеопотоку камери формату SVGA (800x600, RGB565 = 960 000 байтів) при 30 кадрах/с:

1. **Кількість ліній кешу для одного кадру:**
```text
Lines_count = 960 000 / 32 = 30 000 ліній
```

2. **Оверхед інвалідації через функцію `SCB_InvalidateDCache_by_Addr()`:**
Кожна ітерація циклу інвалідації (`SCB->DCIMVAC = op_addr;`) разом із бар'єрами займає близько **4 тактів процесора**:
```text
Cycles_per_frame = 30 000 ліній * 4 такти = 120 000 тактів
```

При частоті ядра `480 МГц` (STM32H7):
```text
Time_per_frame = 120 000 / 480 000 000 с = 0.00025 с = 250 мікросекунд (0.25 мс)
Сумарне навантаження при 30 FPS: 0.25 мс * 30 = 7.5 мс щосекунди (близько 1% часу процесора).
```

### Порівняльна таблиця вибору підходу:

```text
Критерій порівняння               |  Підхід MPU Non-Cacheable         |  Підхід Cached + SCB Maintenance
----------------------------------+-----------------------------------+------------------------------------
Швидкість читання ядром CPU       |  Середня (кожен доступ іде в ОЗП) |  Максимальна (читання з L1 D-Cache)
Надійність когерентності          |  100% апаратна гарантія           |  Потребує суворого вирівнювання 32Б
Ризик False Sharing               |  Повністю відсутній               |  Високий ризик знищення змінних
Оверхед на виклики функцій        |  0 тактів процесора               |  ~250 мкс на кожен відеокадр
Рекомендоване застосування        |  Вхідні буфери камери DCMI,       |  Обробка алгоритмами OpenCV / AI,
                                  |  кільцеві буфери Ethernet та USB  |  де пікселі читаються багато разів
```

## 5. Виробничий контрольний чек-лист розробника для Cortex-M7

1. **Перевірка директиви вирівнювання:**
   Переконайтеся у файлі `.map`, що початкова адреса буфера `dma_buffer` ділиться на 32 без залишку (`Addr % 32 == 0`).
2. **Перевірка доповнення розміру:**
   Переконайтеся, що розмір буфера `sizeof(dma_buffer)` ділиться на 32 без залишку (`Size % 32 == 0`).
3. **Порядок викликів операцій обслуговування:**
   - Для **DMA TX (передача):** спочатку `SCB_CleanDCache()`, потім запуск DMA.
   - Для **DMA RX (прийом):** спочатку дочекайтеся переривання `Transfer Complete`, потім викличте `SCB_InvalidateDCache()`, і лише після цього читайте буфер процесором.
