# Поглиблений інженерний аналіз та розробка драйверів для цифрового сенсора DHT22 (AM2302)

Цифровий датчик вологості й температури DHT22 (AM2302) є комбінованим інтелектуальним сенсором, що поєднує тонкоплівковий ємнісний датчик вологості, термістор NTC та спеціалізований сигнальний мікроконтролер. Незважаючи на уявну простоту підключення через однопровідний інтерфейс Single-Wire, надійна робота сенсора у виробничих умовах вимагає точного розуміння фізико-хімічних процесів чутливих елементів, строгого дотримання мікросекундних таймінгів та проектування стійких неблокуючих драйверів.

У цьому детальному технічному керівництві розглядаються термодинаміка сорбції вологи, математична модель лінеаризації NTC, проектування драйвера на базі апаратного таймера захоплення, аналіз паразитних ємностей кабельних ліній та методи відновлення полімеру після конденсації.

## 1. Фізико-хімічні принципи вимірювання: діелектрична поляризація полімеру та калібрування NTC

Точність вимірювання відносної вологості в AM2302 визначається властивостями інтегрованого ємнісного сенсора, де робочим тілом виступає гігроскопічний полімерний діелектрик.

### Механізм діелектричної поляризації в полімерній плівці

Ємність плоского конденсатора з полімерним діелектриком описується формулою:

```
C = (epsilon_0 * epsilon_r * A) / d
```

де `epsilon_0` — діелектрична стала вакууму (8.854e-12 Ф/м), `A` — площа електродів, `d` — товщина полімерного шару (зазвичай 1–5 мкм), а `epsilon_r` — відносна діелектрична проникність матеріалу.

У сухому стані діелектрична проникність чистого гідрофобного полімеру становить `epsilon_polymer ≈ 3.0 .. 4.0`. Водночас молекули води мають виражений постійний дипольний момент, і відносна діелектрична проникність рідкої води сягає `epsilon_water ≈ 80.0`. 

Коли сенсор контактує з вологим повітрям, молекули водяної пари дифундують крізь пористий золотий електрод у мікропори полімеру. Результуюча діелектрична проникність суміші описується рівнянням змішування Лоренца-Лоренца або моделі Лооренга:

```
epsilon_r^(1/3) = (1 - v_w) * epsilon_polymer^(1/3) + v_w * epsilon_water^(1/3)
```

де `v_w` — об'ємна частка адсорбованої води, прямо пропорційна парціальному тиску водяної пари та відносній вологості повітря (RH). Завдяки високій діелектричній проникності води ємність сенсора зростає практично лінійно в межах від 100 пФ до 140 пФ при зміні вологості від 0% до 100% RH.

### Гістерезис адсорбції та температурна залежність

Сорбція водяної пари полімерною матрицею описується термодинамічною ізотермою адсорбції БЕТ (Брунауера-Еммета-Теллера). Через різницю енергій адсорбції на сухі центри та капілярної конденсації в мікропорах виникає сорбційний гістерезис: значення виміряної вологості при циклі осушення дещо вище, ніж при циклі зволоження. Для високоякісних сенсорів AM2302 максимальна петля гістерезису не перевищує +/-1.0% RH.

Крім того, діелектрична проникність самої води залежить від температури. Внутрішній 8-бітний контролер AM2302 здійснює апаратну температурну компенсацію ємнісного сигналу за показами вбудованого термістора NTC:

```
RH_compensated = RH_measured + (T - 25.0) * alpha_T
```

де `alpha_T` — температурний коефіцієнт полімеру (зазвичай близько +0.05% RH/°C).

### Математична модель термістора NTC

Вимірювання температури виконується прецизійним NTC-термістором. Залежність опору від абсолютної температури підпорядковується розширеному рівнянню Стейнхарта-Харта:

```
1 / T = A + B * ln(R) + C * (ln(R))^3
```

або у спрощеній експоненційній Beta-формі:

```
R(T) = R_0 * exp( Beta * (1/T - 1/T_0) )
```

де `R_0` = 10.0 кОм при `T_0` = 298.15 K (+25 °C), а параметр `Beta` становить близько 3950 K. Внутрішній мікроконтролер AM2302 опитує опір термістора за допомогою внутрішнього АЦП, обчислює натуральний логарифм за попередньо розрахованими таблицями LUT (Look-Up Table) в OTP ROM і формує значення температури з дискретністю 0.1 °C.

## 2. Апаратна реалізація драйвера на мікроконтролерах: Timer Input Capture проти Bit-Banging

Більшість аматорських бібліотек використовують програмний метод "ногодрингу" (Bit-Banging) з блокуючими затримками на базі циклів зайнятого очікування. У реальних вбудованих системах цей підхід неприйнятний через такі фактори:
- Повне блокування процесорного ядра на 4–5 мс під час зчитування.
- Потреба у відключенні глобальних переривань (`__disable_irq()`), що неприпустимо при роботі RTOS (FreeRTOS, Zephyr), протоколів передачі даних (CAN, Modbus, BLE, Wi-Fi).
- Джиттер переривань викликає спотворення часових інтервалів і призводить до збоїв перевірки контрольної суми (Checksum Error).

### Конфігурація апаратного таймера захоплення (Input Capture)

Промисловий підхід полягає у використанні периферійного таймера мікроконтролера в режимі захоплення вхідного сигналу (Input Capture).

```
   Лінія DATA ──► [ Цифровий фільтр ] ──► [ Детектор фронтів ] ──► [ Регістр CCR1 (Час) ]
                                                               └──► [ Генератор DMA / IRQ ]
```

Таймер налаштовується на тактову частоту 1 МГц (період 1 таймерного тику = рівно 1.0 мкс). Канал захоплення конфігурується для відстеження фронтів:
1. За висхідним фронтом (Rising Edge) значення лічильника таймера скидається в 0.
2. За наступним низхідним фронтом (Falling Edge) значення лічильника автоматично фіксується в апаратному регістрі захоплення CCR1.
3. Значення в CCR1 безпосередньо відображає тривалість високого стану `T_high` у мікросекундах без жодного втручання процесора.

### Кінцевий автомат станів драйвера (FSM)

Прийом пакету здійснюється кінцевим автоматом станів, що викликається перериваннями таймера або обробником подій:

```
[ IDLE ] 
   │  (Команда на опитування)
   ▼
[ START_PULL_LOW ] ───── (Витримка 1.5 мс через апаратний таймер)
   │
   ▼
[ START_RELEASE ]  ───── (Відпускання піна, перехід в Input Capture)
   │
   ▼
[ WAIT_ACK_LOW ]   ───── (Очікування спаду 80 мкс від DHT22)
   │
   ▼
[ WAIT_ACK_HIGH ]  ───── (Очікування підйому 80 мкс від DHT22)
   │
   ▼
[ CAPTURE_BITS ]   ───── (Апаратне збереження 40 імпульсів у масив DMA/RAM)
   │
   ▼
[ PARSE_AND_CHECK ] ──── (Декодування 40 бітів, перевірка Checksum)
   │
   ▼
[ COMPLETE / ERROR ]
```

Така архітектура дозволяє мікроконтролеру витрачати на обслуговування датчика менше 0.05% процесорного часу.

## 3. Аналіз часових допусків, джиттеру та впливу параметрів кабельної лінії

Шина Single-Wire є відкритою пасивною лінією: активне переведення в LOW здійснюється транзистором, а підйом у HIGH — виключно підтягуючим резистором R_pull. Це створює асиметрію фронтів, яка посилюється з ростом довжини кабелю.

### Вплив паразитної ємності кабелю

Еквівалентний час наростання напруги на лінії від 10% до 90% (t_rise) визначається постійною часу `tau = R_pull * C_line`:

```
t_rise ≈ 2.2 * R_pull * C_line
```

Для стандартного кабелю типу "кручена пара" UTP категорія 5e погонна ємність між жилами становить `C_spec ≈ 52 пФ/м`. 

Розрахуємо тривалість фронту для різних довжин кабелю при `R_pull = 4.7 кОм`:
- **Довжина 1 метр (C = 52 пФ):**
  ```
  t_rise = 2.2 * 4700 Ом * 52e-12 Ф ≈ 0.54 мкс
  ```
  Фронт ідеальний, спотворення тривалості імпульсів не перевищує 1%.
- **Довжина 10 метрів (C = 520 пФ):**
  ```
  t_rise = 2.2 * 4700 Ом * 520e-12 Ф ≈ 5.37 мкс
  ```
  Імпульс логічного «0» тривалістю 26 мкс затягується і на рівні логічного порогу входу (0.7 * VDD) фіксується як імпульс довжиною 31–32 мкс.
- **Довжина 30 метрів (C = 1560 пФ):**
  ```
  t_rise = 2.2 * 4700 Ом * 1560e-12 Ф ≈ 16.1 мкс
  ```
  Короткий імпульс біта «0» зливається з порогом розпізнавання біта «1», виникають масові помилки контрольної суми.

### Розрахунок мінімального опору підтяжки

Для забезпечення довжини лінії до 20–30 метрів номінал резистора підтяжки необхідно зменшувати, враховуючи максимальний вихідний струм відкритого стоку сенсора AM2302 (`I_sink_max ≈ 4.0 мА` при напрузі насичення `V_OL < 0.4 В`):

```
R_pull_min = (V_DD - V_OL) / I_sink_max = (5.0 В - 0.4 В) / 0.004 А = 1150 Ом
```

Отже, безпечним компромісним значенням для довгих ліній зв'язку є резистор **R_pull = 1.5–2.2 кОм**.

### Допуски таймінгів та поріг дискримінації

Згідно з офіційним протоколом AM2302 часові інтервали передачі бітів мають такі межі:

| Параметр сигналу | Номінальне значення | Технологічний допуск | Значення на довгому кабелі |
| :--- | :--- | :--- | :--- |
| **Пауза між бітами (LOW)** | 50 мкс | 48 .. 55 мкс | 48 .. 58 мкс |
| **Високий рівень біта «0»** | 26–28 мкс | 22 .. 30 мкс | 26 .. 38 мкс |
| **Високий рівень біта «1»** | 70 мкс | 68 .. 75 мкс | 68 .. 82 мкс |

Оптимальний поріг дискримінації бітів розраховується як середня геометрична або арифметична точка між максимальним затягнутим нулем і мінімальною одиницею:

```
T_threshold = (38 мкс + 68 мкс) / 2 = 53 мкс (на практиці обирають 48–50 мкс)
```

Правило прийняття рішення: якщо виміряний `T_high > 48 мкс`, біт інтерпретується як 1, інакше як 0.

## 4. Повний виробничий C-драйвер для мікроконтролера STM32 (DWT/Timer)

Нижче наведено модульний виробничий код драйвера DHT22 на мові C, призначений для мікроконтролерів сімейства STM32 (Cortex-M3/M4/M7). Драйвер використовує апаратний лічильник тактів ядра DWT (Data Watchpoint and Trace) для формування прецизійних мікросекундних таймінгів із захистом від зависання через сторожові тайм-аути.

```c
#include <stdint.h>
#include <stdbool.h>

/**
 * @brief Статуси завершення транзакції DHT22
 */
typedef enum {
    DHT22_OK = 0,
    DHT22_ERR_TIMEOUT_START = 1,
    DHT22_ERR_TIMEOUT_ACK = 2,
    DHT22_ERR_TIMEOUT_DATA = 3,
    DHT22_ERR_CHECKSUM = 4,
    DHT22_ERR_SAMPLING_RATE = 5
} dht22_status_t;

typedef struct {
    float humidity_rh;
    float temperature_c;
    dht22_status_t status;
} dht22_data_t;

/* Апаратні налаштування GPIO (замінити на власні дефайни) */
#define DHT22_GPIO_PORT         GPIOB
#define DHT22_GPIO_PIN          GPIO_PIN_7

/* Прототипи допоміжних функцій затримок DWT */
static inline void dwt_delay_init(void) {
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;
}

static inline void dwt_delay_us(uint32_t us, uint32_t cpu_freq_hz) {
    uint32_t ticks = us * (cpu_freq_hz / 1000000UL);
    uint32_t start = DWT->CYCCNT;
    while ((DWT->CYCCNT - start) < ticks);
}

/**
 * @brief Перемикання виводу GPIO в режим відкритого стоку
 */
static void dht22_set_pin_output_od(void) {
    GPIO_InitTypeDef gpio = {0};
    gpio.Pin = DHT22_GPIO_PIN;
    gpio.Mode = GPIO_MODE_OUTPUT_OD;
    gpio.Pull = GPIO_PULLUP;
    gpio.Speed = GPIO_SPEED_FREQ_HIGH;
    HAL_GPIO_Init(DHT22_GPIO_PORT, &gpio);
}

/**
 * @brief Перемикання виводу GPIO в режим входу з підтяжкою
 */
static void dht22_set_pin_input(void) {
    GPIO_InitTypeDef gpio = {0};
    gpio.Pin = DHT22_GPIO_PIN;
    gpio.Mode = GPIO_MODE_INPUT;
    gpio.Pull = GPIO_PULLUP;
    HAL_GPIO_Init(DHT22_GPIO_PORT, &gpio);
}

/**
 * @brief Очікування зміни стану піна з контролем тайм-ауту (мкс)
 */
static bool dht22_wait_pin_state(GPIO_PinState state, uint32_t timeout_us, uint32_t cpu_hz) {
    uint32_t timeout_ticks = timeout_us * (cpu_hz / 1000000UL);
    uint32_t start = DWT->CYCCNT;
    while (HAL_GPIO_ReadPin(DHT22_GPIO_PORT, DHT22_GPIO_PIN) != state) {
        if ((DWT->CYCCNT - start) >= timeout_ticks) {
            return false; /* Тайм-аут */
        }
    }
    return true;
}

/**
 * @brief Повне опитування сенсора DHT22 з верифікацією даних
 */
dht22_status_t dht22_read(dht22_data_t *out_data, uint32_t cpu_hz) {
    uint8_t payload[5] = {0};
    dwt_delay_init();

    /* 1. Фаза старту хоста: притискаємо лінію до LOW на 1.5 мс */
    dht22_set_pin_output_od();
    HAL_GPIO_WritePin(DHT22_GPIO_PORT, DHT22_GPIO_PIN, GPIO_PIN_RESET);
    dwt_delay_us(1500, cpu_hz);

    /* 2. Відпускаємо лінію в HIGH на 30 мкс */
    HAL_GPIO_WritePin(DHT22_GPIO_PORT, DHT22_GPIO_PIN, GPIO_PIN_SET);
    dht22_set_pin_input();
    dwt_delay_us(30, cpu_hz);

    /* 3. Очікування підтвердження ACK від DHT22 (80 мкс LOW, потім 80 мкс HIGH) */
    if (!dht22_wait_pin_state(GPIO_PIN_RESET, 100, cpu_hz)) {
        out_data->status = DHT22_ERR_TIMEOUT_ACK;
        return DHT22_ERR_TIMEOUT_ACK;
    }
    if (!dht22_wait_pin_state(GPIO_PIN_SET, 100, cpu_hz)) {
        out_data->status = DHT22_ERR_TIMEOUT_ACK;
        return DHT22_ERR_TIMEOUT_ACK;
    }
    if (!dht22_wait_pin_state(GPIO_PIN_RESET, 100, cpu_hz)) {
        out_data->status = DHT22_ERR_TIMEOUT_ACK;
        return DHT22_ERR_TIMEOUT_ACK;
    }

    /* 4. Прийом 40 бітів даних (5 байтів) */
    for (int i = 0; i < 40; ++i) {
        /* Чекаємо завершення паузи 50 мкс (перехід у HIGH) */
        if (!dht22_wait_pin_state(GPIO_PIN_SET, 75, cpu_hz)) {
            out_data->status = DHT22_ERR_TIMEOUT_DATA;
            return DHT22_ERR_TIMEOUT_DATA;
        }

        /* Фіксуємо тривалість сигналу HIGH */
        uint32_t t_start = DWT->CYCCNT;
        if (!dht22_wait_pin_state(GPIO_PIN_RESET, 90, cpu_hz)) {
            out_data->status = DHT22_ERR_TIMEOUT_DATA;
            return DHT22_ERR_TIMEOUT_DATA;
        }
        uint32_t pulse_ticks = DWT->CYCCNT - t_start;
        uint32_t pulse_us = pulse_ticks / (cpu_hz / 1000000UL);

        /* Поріг 48 мкс: більше 48 мкс -> 1, менше -> 0 */
        int byte_idx = i / 8;
        payload[byte_idx] <<= 1;
        if (pulse_us > 48) {
            payload[byte_idx] |= 1;
        }
    }

    /* 5. Перевірка контрольної суми */
    uint8_t calc_sum = (payload[0] + payload[1] + payload[2] + payload[3]) & 0xFF;
    if (calc_sum != payload[4]) {
        out_data->status = DHT22_ERR_CHECKSUM;
        return DHT22_ERR_CHECKSUM;
    }

    /* 6. Декодування результатів */
    uint16_t raw_humidity = ((uint16_t)payload[0] << 8) | payload[1];
    out_data->humidity_rh = (float)raw_humidity / 10.0f;

    uint16_t raw_temp = ((uint16_t)payload[2] << 8) | payload[3];
    if (raw_temp & 0x8000) {
        /* Від'ємна температура: біт 15 встановлено */
        out_data->temperature_c = -((float)(raw_temp & 0x7FFF) / 10.0f);
    } else {
        out_data->temperature_c = (float)raw_temp / 10.0f;
    }

    out_data->status = DHT22_OK;
    return DHT22_OK;
}
```

## 5. Метрологічний аналіз, дрейф характеристик, захист від конденсації та методика відновлення

Тривала експлуатація ємнісних полімерних сенсорів у системах вентиляції та теплицях супроводжується поступовим дрейфом метрологічних параметрів.

### Чинники дрейфу та отруєння чутливого шару

1. **Контамінація летючими органічними сполуками (ЛОС/VOC):** Пари формальдегіду, спиртів, миючих засобів і розчинників незворотно зв'язуються з функціональними групами полімеру, що спричиняє постійне штучне завищення показів вологості (до +5..+10% RH).
2. **Тривалий вплив високої вологості (> 90% RH):** При тривалому перебуванні в атмосфері близькій до точки роси відбувається набухання полімеру та розрив водневих зв'язків структури діелектрика.
3. **Ефект конденсації водяної плівки:** Якщо температура корпусу опускається нижче поточної точки роси, на електродах конденсується суцільна мікроплівка рідкої води. Оскільки вода є провідником і має величезну діелектричну проникність, вихід сенсора "залипає" на значенні 99.9% RH і не повертається до норми протягом годин або навіть діб після зниження вологості повітря, поки краплі не випаруються повністю.

### Процедура регенерації полімерного сенсора (Baking & Rehydration)

Для відновлення заводських метрологічних характеристик забрудненого або зволоженого сенсора виробник регламентує двохетапний цикл термообробки (Reconditioning Procedure):

1. **Етап високотемпературного випалу (Baking):**
   - Датчик поміщають у сушильну термошафу за температури від **+80 °C до +85 °C** та низької вологості (< 5% RH) на час **24 години**.
   - Під дією високої температури відбувається повна десорбція органічних молекул та випаровування зв'язаної води з глибинних мікропор діелектрика.
2. **Етап нормалізуючої регідратації (Rehydration):**
   - Датчик витримують у середовищі з температурою **+20...+30 °C** та контрольованою підвищеною вологістю **> 75% RH** (наприклад, над насиченим розчином хлориду натрію NaCl) протягом **12 годин**.
   - Це відновлює природну рівновагу полімерної матриці.

### Рекомендації з інженерного монтажу

- **Орієнтація перфорації:** Корпус датчика повинен монтуватися решіткою донизу для запобігання прямому затіканню рідких крапель конденсату всередину чутливої зони.
- **Теплова ізоляція:** Сенсор повинен бути максимально віддалений від внутрішніх джерел тепла на друкованій платі (стабілізаторів живлення, силових транзисторів, Wi-Fi модулів ESP32), оскільки паразитичний підігрів навіть на 1.0 °C призводить до заниження відносної вологості на 3–5% RH від реального значення в приміщенні.
- **Захисний фільтр:** В умовах сильної запиленості рекомендується встановлювати змінний дихаючий ковпачок з пористого спеченого бронзового або фторопластового (PTFE) фільтра з порами 10–20 мкм.
