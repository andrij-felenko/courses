# ⚙️ Валідатор карти пінів і апаратних ресурсів мікроконтролера

Розробка сучасної вбудованої системи на базі 32-бітного мікроконтролера починається не з написання функцій `main()` і не з трасування доріжок на друкованій платі, а з розв'язання задачі комбінаторної оптимізації: як розмістити десятки периферійних інтерфейсів на обмеженій кількості фізичних виводів чіпа без апаратних колізій. Якщо в системі одночасно задіяні інтерфейси SPI, I2C, кілька портів UART, швидкісний ШІМ для моторів, аналогові канали АЦП та лінії зовнішніх переривань від датчиків, ручне складання таблиці виводів перетворюється на пошук голки в сіні. Помилка в одному номері альтернативної функції (AF), вибір однакового індексу для двох зовнішніх переривань або призначення двох активних інтерфейсів на один потік DMA виявляються лише на етапі запуску макета в лабораторії, коли виправлення вимагає перерізання мідних провідників на виготовленій платі або повної переробки трасування.

Цей проект присвячено побудові системного програмного валідатора карти пінів на мовах C99 та C++20. Модуль автоматично аналізує повну таблицю призначень фізичних виводів мікроконтролера, перевіряє правила мультиплексування, детектує конфлікти каналів прямого доступу до пам'яті (DMA), контролює узгодженість базових частот таймерів, перевіряє унікальність ліній зовнішніх переривань (EXTI) та розраховує топологічний штраф за взаємне розташування чутливих аналогових і шумних цифрових ліній.

## Формалізація задачі: багаторесурсна задача задоволення обмежень (CSP)

З точки зору дискретної математики та комп'ютерних наук розподіл виводів мікроконтролера є класичною задачею задоволення обмежень (англ. *Constraint Satisfaction Problem — CSP*). 

Формально задача описується трійкою кортежу (X, D, C), де:
* X = {x_1, x_2, ..., x_n} — множина цільових периферійних функцій, які необхідно реалізувати в пристрої (наприклад, x_1 = SPI1_SCK, x_2 = TIM1_CH1, x_3 = EXTI_ACCEL, x_4 = ADC1_IN2);
* D = {D(x_1), D(x_2), ..., D(x_n)} — сімейство доменів допустимих значень, де кожен домен D(x_i) містить підмножину фізичних виводів мікроконтролера P = {p_1, p_2, ..., p_m}, які згідно з апаратною документацією виробника здатні виконувати функцію x_i;
* C = {c_1, c_2, ..., c_k} — множина апаратних, схемотехнічних і топологічних обмежень.

### Математична модель апаратних обмежень:

1. **Обмеження взаємного виключення паду (Pad Exclusivity Constraint):**
   Кожен фізичний контактний майданчик кристала p_j може бути зайнятий щонайбільше однією активною периферійною функцією. Якщо дві функції x_i та x_k мають спільний вивід, виникає нерозв'язна колізія.

2. **Обмеження селектора альтернативних функцій (AF Matrix Constraint):**
   Призначення функції x_i на вивід p_j є допустимим тоді й лише тоді, коли в кремнієвій матриці чіпа для цього виводу визначено відповідний код альтернативної функції з діапазону від AF0 до AF15.

3. **Обмеження мультиплексора зовнішніх переривань (EXTI Uniqueness Constraint):**
   Контролер зовнішніх переривань містить шістнадцять незалежних ліній EXTI0 ... EXTI15. До лінії з номером k можна підключити вивід з індексом k від порту A, B, C, D, E, F або G, але рівно один у кожен момент часу.
   Якщо розробник призначає переривання готовності даних датчика на пін PA0, то виводи PB0, PC0, PD0 більше не можуть використовуватися як джерела незалежних апаратних переривань.

4. **Обмеження частотної узгодженості таймерів (Timer Frequency Consistency Constraint):**
   Кожен апаратний таймерний блок TIM_y містить один загальний лічильний регістр CNT, один регістр переддільника частоти PSC та один регістр автоперезавантаження ARR. Якщо кілька каналів ШІМ призначені на виводи одного таймера, їхні цільові базові частоти повторення повинні строго збігатися.

5. **Обмеження арбітражу потоків DMA (DMA Stream Contention Constraint):**
   У класичних контролерах DMA (наприклад, архітектури STM32F4/F7) кожен потік Stream_s контролера DMA_c має апаратний комутатор на 8 каналів Channel_0 ... Channel_7. Два периферійні блоки не можуть одночасно здійснювати передавання даних через один і той самий потік DMA.

6. **Топологічне обмеження фізичної близькості (Proximity Noise Penalty):**
   Швидкісні цифрові сигнали з високою крутістю фронтів di/dt та dv/dt (лінії тактування шини SPI, QSPI, SDIO, виходи ШІМ) створюють ємнісні та індуктивні перехресні завади на сусідні виводи. Якщо такий сигнал розташований на фізично суміжній ніжці корпусу з високоїмпедансним аналоговим входом АЦП або опорною напругою VREF+, генерується топологічне попередження про ризик спотворення вимірювань.

### Алгоритмічний підхід до розв'язання CSP:
Для автоматичного пошуку безконфліктного розподілу застосовується алгоритм пошуку з поверненням (Backtracking Search), підсилений двома евристиками:
* **Евристика найменшої кількості залишкових значень (MRV, *Minimum Remaining Values*):** першими призначаються периферійні блоки з найвужчим доменом доступних виводів (наприклад, апаратні канали USB OTG, лінія годинника RTC LSE або розширений таймер TIM1).
* **Евристика найбільшого ступеня обмеження (Degree Heuristic):** серед функцій з однаковим розміром домену першою обирається та, що накладає найбільше обмежень на сусідні вузли (наприклад, потік DMA, який ділить ресурси з чотирма іншими блоками).
* **Алгоритм дугової узгодженості (Arc Consistency AC-3 / Forward Checking):** після кожного призначення піна домени всіх пов'язаних функцій негайно відфільтровуються; якщо для будь-якої нерозподіленої функції домен стає порожнім, алгоритм негайно відкочується назад, не витрачаючи час на перебір тупикових гілок.

## Порівняння архітектур DMA: фіксована матриця проти DMAMUX Crossbar

При проектуванні вбудованих систем критично важливо розуміти різницю між двома основними поколіннями контролерів DMA, оскільки алгоритм валідації суттєво залежить від типу мікроконтролера:

### 1. Фіксована матриця потоків (STM32F1 / F4 / F7)
У цій архітектурі контролер DMA містить фіксовані потоки, кожен із яких підключений до мультиплексора з 8 апаратних каналів. Прив'язка периферійного запиту до конкретного потоку і каналу жорстко зашита в кремній.
* **Перевага:** простота апаратної реалізації та мінімальна затримка запуску передавання (менше двох тактів шини).
* **Недолік:** висока ймовірність колізій. Наприклад, якщо `SPI1_RX` та `ADC1` жорстко прив'язані до `DMA2_Stream0`, розробник фізично позбавлений можливості одночасно вичитувати дані з АЦП і приймати байти по SPI у фоновому режимі.

### 2. Матричний комутатор DMAMUX (STM32G4 / H7 / U5 / WB)
У новіших мікроконтролерах між периферійними блоками та каналами DMA встановлено повнофункціональний неблокуючий комутатор `DMAMUX`.
* **Принцип роботи:** Будь-яке джерело запиту (Request ID від 0 до 127) може бути програмно зкомутоване на будь-який із доступних каналів DMA (від 0 до 15).
* **Розширені можливості:** DMAMUX містить власні генератори подій (Event Generators) та канали синхронізації (Synchronization Channels). Це дозволяє запускати пересилання блоку даних DMA не за перериванням, а за зовнішнім перепадом напруги на виводі EXTI або за тригером таймера без участі процесорного ядра.
* **Вимоги до валідатора:** Для систем із DMAMUX валідатор знімає обмеження фіксованої прив'язки потоків і перевіряє лише сумарну кількість одночасно активних каналів, гарантуючи, що загальна кількість периферійних транзакцій не перевищує пропускну здатність шини контролера.

## Повний реєстровий рівень: матриця комутації та бітові поля

Щоб валідатор міг не лише перевіряти карту пінів, а й автоматично генерувати код ініціалізації апаратних регістрів, необхідно точно формалізувати структуру конфігураційних регістрів мікроконтролера.

### 1. Регістри портів GPIO (на прикладі архітектури STM32 / ARM Cortex-M):
Для кожного порту введення-виведення (GPIOA..GPIOH) виділено блок 32-бітних регістрів:
* `GPIOx_MODER` (Mode Register): 2 біти на кожен пін y від 0 до 15. Біти [2y+1:2y] визначають режим:
  - `00`: Input (цифровий вхід);
  - `01`: General Purpose Output (цифровий вихід);
  - `10`: Alternate Function (альтернативна функція периферії);
  - `11`: Analog Mode (аналоговий вхід/вихід АЦП/ЦАП, цифровий буфер вимкнено).
* `GPIOx_OTYPER` (Output Type Register): 1 біт на пін. Біт [y] визначає схемотехніку вихідного каскаду:
  - `0`: Output Push-Pull (двотактний активний вихід);
  - `1`: Output Open-Drain (відкритий стік для шин I2C / 1-Wire).
* `GPIOx_OSPEEDR` (Output Speed Register): 2 біти на пін. Біти [2y+1:2y] задають крутість фронтів драйвера:
  - `00`: Low Speed (діапазон 2–8 МГц);
  - `01`: Medium Speed (діапазон 12.5–50 МГц);
  - `10`: High Speed (діапазон 25–100 МГц);
  - `11`: Very High Speed (діапазон 50–180 МГц).
* `GPIOx_PUPDR` (Pull-Up/Pull-Down Register): 2 біти на пін. Біти [2y+1:2y] керують внутрішніми резисторами підтяжки:
  - `00`: No Pull-Up, No Pull-Down (плаваючий вхід);
  - `01`: Pull-Up (підтяжка до VDD через резистор приблизно 40 кОм);
  - `10`: Pull-Down (підтяжка до VSS через резистор приблизно 40 кОм).
* `GPIOx_AFRL` та `GPIOx_AFRH` (Alternate Function Low/High Registers): 4 біти на кожен пін. Задають код альтернативної функції `AF0`..`AF15` (від 0x0 до 0xF), комутуючи пін до відповідного периферійного модуля.

### 2. Регістри мультиплексора зовнішніх переривань (SYSCFG_EXTICR):
Системний контролер конфігурації містить чотири 32-бітні регістри `SYSCFG_EXTICR1`..`SYSCFG_EXTICR4`. Кожен регістр обслуговує 4 лінії переривань, виділяючи 4 біти на лінію:
* `EXTICR1[3:0]` вибирає порт для лінії `EXTI0`: `0000` = PA0, `0001` = PB0, `0010` = PC0, `0011` = PD0 тощо.
* `EXTICR1[7:4]` вибирає порт для лінії `EXTI1`: `0000` = PA1, `0001` = PB1, `0010` = PC1 тощо.
* `EXTICR4[15:12]` вибирає порт для лінії `EXTI15`.

Ця апаратна структура однозначно доводить, що лінія `EXTIn` може отримувати сигнал лише від одного фізичного порту одночасно.

### 3. Регістри конфігурації таймерів та каналів ШІМ:
* `TIMx_PSC` (Prescaler Register): 16-бітний дільник вхідної тактової частоти шини таймера.
* `TIMx_ARR` (Auto-Reload Register): 16-бітний або 32-бітний регістр періоду лічення.
* `TIMx_CCR1`..`TIMx_CCR4` (Capture/Compare Registers): індивідуальні регістри шпаруватості каналів 1..4.
* `TIMx_CCMR1` / `TIMx_CCMR2` (Capture/Compare Mode Registers): налаштування режиму ШІМ (PWM Mode 1 або PWM Mode 2, активний високий чи активний низький рівень).
* `TIMx_BDTR` (Break and Dead-Time Register): апаратне налаштування тривалості мертвого часу (в наносекундах) між комплементарними виходами `CHx` та `CHxN`, а також конфігурація полярності входу аварійного захисту `BKIN`.

## Електромагнітна топологія та оцінка паразитного зв'язку між ніжками чіпа

Фізична близькість контактних площадок на кристалі та ніжок на корпусі створює паразитні канали витоку завад. Розглянемо фізичну модель паразитного зв'язку двох суміжних виводів:

### 1. Ємнісний зв'язок (Capacitive Crosstalk)
Два суміжних виводи корпусу мають паразитну ємність C_m в діапазоні від 0.5 до 1.2 пФ. При перемиканні цифрового сигналу з амплітудою V = 3.3 В і крутістю фронту t_r = 1 нс струм зміщення, що наводиться в суміжне коло з імпедансом R_victim, створює паразитний сплеск напруги на ближньому кінці (NEXT, *Near-End Crosstalk*):

```
                     R_victim × C_m
V_next ≈ V_source × ────────────────     [наведена ємнісна завада]
                          t_r
```

Якщо R_victim = 10 кОм (типовий вхідний імпеданс АЦП або датчика з дільником), то розрахунковий сплеск без захисту міг би перевищити напругу живлення:

```
V_next ≈ 3.3 × (10000 × 10^-12) / 10^-9 = 33 В (обмежено живленням до 3.3 В)
```

Це означає, що аналоговий вхід буде повністю забитий цифровим імпульсом, викликаючи спотворення результатів перетворення АЦП на час до 50–100 нс після кожного перемикання цифрового виводу.

### 2. Індуктивний зв'язок (Inductive Crosstalk)
Струм високої частоти di/dt, що протікає через вивідну рамку чіпа з взаємною індуктивністю M від 0.5 до 1.5 нН, наводить ЕРС взаємоіндукції в сусідній сигнальний контур:

```
          di
V_ind = M ──     [індуктивна перехресна наводка]
          dt
```

При комутації струму 20 мА за 1 нс амплітуда індуктивної завади складе:

```
V_ind = 10^-9 × (0.02 / 10^-9) = 20 мВ     [амплітуда індуктивного сплеску]
```

Для 12-бітного АЦП з опорною напругою 3.3 В ціна одного молодшого розряду становить LSB = 3.3 В / 4096 ≈ 0.8 мВ. Сплеск у 20 мВ еквівалентний похибці у 25 LSB. Валідатор оцінює ці ризики та видає рекомендацію рознесення таких ліній або розміщення між ними заземленого виводу-екрана.

## Детальний розбір інженерних тестових сценаріїв

Для практичної верифікації алгоритмів валідатора розглянемо п'ять характерних інженерних ситуацій, що виникають під час проектування друкованих плат.

### Сценарій 1: Колізія ліній зовнішніх переривань EXTI
* **Контекст проектування:** На платі встановлено два сенсори: тривісний акселерометр та барометричний датчик тиску. Акселерометр видає імпульс готовності даних `ACC_DRDY` тривалістю 50 нс із частотою 1 кГц, а барометр сигналізує про завершення вимірювання сигналом `BARO_INT`.
* **Початкове призначення:** Розробник вибрав вивід `PA0` для `ACC_DRDY` та вивід `PB0` для `BARO_INT`.
* **Діагностика валідатора:**
  Модуль фіксує помилку `Колізія EXTI0: сигнал 'BARO_INT' (PB0) блокує лінію переривання порту PA`.
* **Фізична сутність:** Обидва піни мають однаковий молодший індекс (0). Системний регістр `SYSCFG_EXTICR1` фізично здатний зкомутувати на вхід детектора перепаду напруги лише один із портів. Одночасна обробка переривань стає неможливою.
* **Шлях усунення:** Перепризначити сигнал `BARO_INT` на вивід `PB1` (лінія `EXTI1`), що вимагає зміни одного рядка в таблиці Netlist до передачі плати в трасування.

### Сценарій 2: Конфлікт потоків контролера DMA при одночасній передачі
* **Контекст проектування:** Мультимедійний пристрій записує аудіопотік на SD-карту пам'яті через інтерфейс `SDIO` і паралельно оновлює графіку на кольоровому TFT-дисплеї через шину `SPI1`.
* **Початкове призначення:** Інтерфейс `SDIO` сконфігуровано на потік `DMA2_Stream3` (Channel 4), а передавання буфера пікселів `SPI1_TX` налаштовано на той самий потік `DMA2_Stream3` (Channel 3).
* **Діагностика валідатора:**
  Модуль генерує помилку `Колізія DMA2_Stream3: одночасний запит від 'SDIO_DATA' та 'SPI1_TX'`.
* **Фізична сутність:** Потік `DMA2_Stream3` має єдиний внутрішній набір регістрів лічильника передач (`NDTR`) та покажчиків адреси пам'яті (`M0AR`, `PAR`). Якщо графічний драйвер запускає фонове оновлення дисплея, запис чергового кластера на SD-карту заблокує DMA-контролер, викликаючи збій файлової системи через переповнення буфера FIFO.
* **Шлях усунення:** Перенаправити запити передавача `SPI1_TX` на альтернативний потік `DMA2_Stream5` (Channel 3), який апаратно підтримує цей самий периферійний блок і не конфліктує з шиною SDIO.

### Сценарій 3: Конфлікт базової частоти ШІМ для силового ключа та звукового випромінювача
* **Контекст проектування:** Силовий блок містить понижувальний імпульсний стабілізатор напруги (100 кГц) та п'єзоелектричний випромінювач звуку (резонанс на 2.7 кГц).
* **Початкове призначення:** Сигнал керування транзистором призначено на `PA8` (`TIM1_CH1`), а звуковий сигнал призначено на `PA9` (`TIM1_CH2`).
* **Діагностика валідатора:**
  Модуль фіксує критичну помилку `Конфлікт частоти TIM1: сигнал 'BUZZER' вимагає 2700 Гц, але таймер вже налаштовано на 100000 Гц`.
* **Фізична сутність:** Регістр автоперезавантаження `TIM1->ARR` задає однаковий період для всіх чотирьох каналів таймера. Якщо встановити період під 100 кГц, бузер не зможе видати чутний звук. Якщо встановити період під 2.7 кГц, силовий дросель перетворювача увійде в глибоке магнітне насичення, викликаючи струмовий пробій транзистора.
* **Шлях усунення:** Винести сигнал бузера на незалежний таймер загального призначення `TIM3` (вивід `PB4` або `PC6`), зберігши таймер `TIM1` виключно для високочастотної силової частини.

### Сценарій 4: Топологічний ризик завад (Proximity Noise Warning)
* **Контекст проектування:** Високошвидкісна зовнішня пам'ять QSPI Flash працює на тактовій частоті 80 МГц з крутими фронтами (t_r ≈ 0.8 нс). Поруч із нею підключається аналоговий датчик температури (термопара з вихідним сигналом амплітудою в мілівольти).
* **Початкове призначення:** Сигнал `QSPI_CLK` виведено на ніжку 28 корпусу LQFP-64 (`PB2`), а вхід вимірювального підсилювача `THERMO_IN` підключено до суміжної ніжки 27 (`PB1` у режимі `ADC1_IN9`).
* **Діагностика валідатора:**
  Модуль видає попередження `Топологічний ризик завад: швидкісний цифровий сигнал 'QSPI_CLK' (ніжка 28) розташований поруч із чутливим аналоговим входом 'THERMO_IN' (ніжка 27)`.
* **Фізична сутність:** Між суміжними ніжками корпусу LQFP існує паразитний ємнісний зв'язок C_pad від 0.6 до 1.0 пФ та взаємна індуктивність вивідної рамки M ≈ 0.8 нН. Струмові сплески при перезаряджанні ємності шини пам'яті наводитимуть високочастотний шум на аналоговий тракт АЦП, викликаючи розкид вимірювань температури на десятки градусів.
* **Шлях усунення:** Перенести сигнал `THERMO_IN` на вивід аналогового кластера `PC0` (ніжка 8), який живиться від окремого фільтрованого домену `VDDA` і розташований на протилежній стороні чіпа.

### Сценарій 5: Комплексна верифікація та генерація безконфліктної карти
* **Контекст проектування:** Повний проект польотного контролера безпілотного апарата (4 мотори ШІМ DShot, гіроскоп SPI, барометр I2C, GPS UART, телеметрія CAN, монітор батареї АЦП, SWD налагодження).
* **Результат валідації:** Після усунення проміжних колізій валідатор повертає стан `is_valid = true` з нульовою кількістю помилок та попереджень і формує готовий заголовочний файл ініціалізації апаратних регістрів.

## Глибокий аналіз промислових інженерних кейсів

Розгляньмо детальні специфікації двох комплексних апаратних систем, на яких перевірялася ефективність розробленого модуля:

### Кейс 1: Трифазний векторний інвертор керування BLDC/PMSM (FOC)

Векторне керування двигуном (Field-Oriented Control) вимагає найжорсткішої синхронізації між формуванням ШІМ та вимірюванням фазних струмів:
1. **Силові ключі:** 6 виходів ШІМ від таймера `TIM1` — три пари комплементарних сигналів з апаратним мертвим часом (`TIM1_CH1`/`TIM1_CH1N` на PA8/PB13, `TIM1_CH2`/`TIM1_CH2N` на PA9/PB14, `TIM1_CH3`/`TIM1_CH3N` на PA10/PB15). Частота комутації 20 кГц (двотактний режим, тактова частота таймера 84 МГц).
2. **Аварійне відключення:** сигнал перевантаження за струмом від апаратного компаратора підключається до виводу `TIM1_BKIN` (PB12). При появі логічного нуля виходи ШІМ блокуються апаратно за 50 нс без участі процесора.
3. **Вимірювання струму фаз:** три канали швидкісного АЦП (`ADC1_IN1`, `ADC1_IN2`, `ADC2_IN3` на PA1, PA2, PA3). Запуск перетворення здійснюється внутрішнім апаратним тригером `TIM1_TRGO` точно посередині періоду ШІМ, коли завади від перемикання ключів завершилися.
4. **Датчик положення (інкрементальний енкодер):** канали A і B енкодера підключаються до таймера `TIM2` (`TIM2_CH1` на PA0, `TIM2_CH2` на PA1? Стоп!).

**Апаратний конфлікт, який детектує валідатор:**
Пін `PA1` одночасно запропоновано під `ADC1_IN2` (аналоговий вхід струму фази B) та під `TIM2_CH2` (вхід енкодера).
Валідатор негайно видає помилку Фази 1 (Physical Pad Collision).
*Розв'язання:* перенести входи енкодера на таймер `TIM3` (`TIM3_CH1` на PA6, `TIM3_CH2` на PA7) або використати альтернативний порт таймера `TIM2` (`TIM2_CH1` на PA15, `TIM2_CH2` на PB3 через AF1).

### Кейс 2: Низькоспоживаючий бездротовий сенсорний вузол (IoT Sensor)

Пристрій живиться від літієвої батареї CR2032 і більшу частину часу проводить у режимі глибокого сну Standby зі споживанням до 2 мкА:
1. **Тактування:** наднизькоспоживаючий годинниковий кварц 32.768 кГц на виводах `PC14` (`OSC32_IN`) та `PC15` (`OSC32_OUT`).
2. **Зовнішні події пробудження:** датчик удару підключено до лінії `EXTI0`, а сигнал відкриття корпусу (тампер) підключено до лінії `EXTI13`.
3. **Обмін даними:** спалах радіопередавача через шину `SPI1` на швидкості 8 Мбіт/с тривалістю 2 мс кожні 10 секунд.

**Апаратні пастки, що контролюються модулем:**
1. **Колізія лінії пробудження:** якщо датчик удару розмістити на `PA0`, а додаткову кнопку користувача — на `PB0`, виникає колізія `EXTI0`. Валідатор змушує призначити кнопку на `PC13`, що сумісно з лінією `EXTI13`.
2. **Паразитний струм витоку через SPI:** при переході в сон мікроконтролер вимикає живлення радіотрансивера. Якщо лінії `SPI1_SCK`, `SPI1_MOSI` залишити в стані Push-Pull High, струм витоку через захисні діоди вимкненого трансивера складе до 3 мА, розрядивши батарею за 3 дні. Валідатор генерує конфігурацію переходу в сон: `MODER = 11` (Analog Mode) для всіх ліній зв'язку з периферією.

## Розширені інженерні крайові випадки

Практична експлуатація мікроконтролерів у польових умовах вимагає врахування додаткових нетривіальних апаратних факторів:

### 1. Динамічне перепризначення виводів під час виконання програми (Dynamic Remap)
У деяких системах один фізичний вивід мікроконтролера змінює своє функціональне призначення залежно від поточного стану кінцевого автомата пристрою (FSM):
* **Приклад:** При старті пристрою вивід `PA9` працює як лінія `USART1_TX` для виведення діагностичних повідомлень завантажувача. Після завантаження основної операційної системи цей самий пін динамічно перемикається в режим `TIM1_CH2` для генерації частоти звукової індикації.
* **Вимоги до валідатора:** Для коректної підтримки таких схем валідатор повинен підтримувати концепцію **робочих профілів** (англ. *Operational Profiles*). Перевірка взаємного виключення ресурсів виконується окремо для кожного профілю, гарантуючи, що несумісні периферійні блоки ніколи не активуються в один і той самий проміжок часу.

### 2. Струми витоку в режимах глибокого сну (Deep Sleep Leakage)
В автономних пристроях з живленням від літієвих батарей мікроконтролер більшу частину життєвого циклу проводить у режимах глибокого сну (Stop, Standby, Shutdown), де струм споживання ядра знижується до діапазону 0.5–2 мкА. 
Проте, якщо стан виводів GPIO не узгоджений із зовнішньою схемотехнікою плати, виникають паразитні струми витоку, які перевищують споживання ядра в сотні разів:
* **Плаваючий цифровий вхід (Floating Input):** Якщо пін не має зовнішньої підтяжки і залишається в режимі цифрового входу (`MODER = 00`), його потенціал під дією теплових наведень дрейфує в районі половини напруги живлення VDD/2. Внутрішній CMOS-тригер Шмітта входить у лінійну зону, де обидва вхідні транзистори (P-MOS та N-MOS) одночасно відкриті, викликаючи постійний наскрізний струм витоку до 50–100 мкА на кожен пін.
* **Зовнішній резистор підтяжки до живлення:** Якщо на платі встановлено підтягувальний резистор R_ext = 10 кОм до шини 3.3 В, а вивід мікроконтролера під час сну налаштовано як вихід низького рівня (`Output Low`), через нього постійно протікає струм:

```
          3.3 В
I_leak = ─────── = 330 мкА     [струм витоку на землю через підтяжку]
          10 кОм
```

* **Правило безпечної конфігурації:** Перед переходом у режим сну прошивка зобов'язана перевести всі вільні або неактивні виводи в режим **Analog Input** (`MODER = 11`), за якого цифровий буфер повністю знеструмлюється, розриваючи всі внутрішні шляхи витоку струму.

### 3. Розрахунок підтягувальних резисторів для швидкісних шин I2C (Fast Mode Plus)
Шина I2C використовує виходи типу «відкритий стік» (Open-Drain). Формування фронту наростання напруги від логічного нуля до логічної одиниці здійснюється виключно зовнішнім резистором підтяжки R_p, який заряджає сумарну паразитну ємність провідників плати та входів мікросхем C_b.

Згідно зі специфікацією I2C для режиму Fast Mode Plus (1 Мбіт/с) час наростання фронту t_r не повинен перевищувати 120 нс. Напруга на ємності зростає за експоненційним законом.

Час наростання від рівня 30% до 70% напруги живлення визначається виразом:

```
t_r ≈ 0.8473 × R_p × C_b     [час наростання фронту I2C]
```

Звідси гранично допустимий опір резистора підтяжки розраховується так:

```
          t_r_max
R_p_max = ─────────────     [максимальний опір підтяжки I2C]
          0.8473 × C_b
```

Якщо ємність плати з розведеними датчиками складає C_b = 150 пФ, то:

```
R_p_max = (120 * 10^-9) / (0.8473 × 150 * 10^-12) ≈ 944 Ом     [розрахунковий номінал]
```

Якщо розробник помилково покладається на внутрішні підтягувальні резистори мікроконтролера (R_pu ≈ 40 кОм), час наростання складе t_r ≈ 5.08 мкс, що в 42 рази перевищує ліміт стандарту і призведе до повної непрацездатності шини I2C на високих швидкостях. Валідатор зобов'язаний виявляти шини з режимом Fast Mode і попереджати про необхідність обов'язкового встановлення зовнішніх дискретних резисторів малого номіналу (близько 1 кОм).

### 4. Узгодження імпедансу швидкісних сигнальних ліній
Для сигналів тактування з частотою понад 25 МГц (наприклад, `SDIO_CLK`, `QSPI_CLK`, `SPI1_SCK`) довжина доріжки на платі L_trace часто перевищує критичну довжину довгої лінії:

```
          t_r
L_crit = ─────     [критична довжина лінії передачі]
         2 × t_pd
```

де t_pd ≈ 6.5 нс/м — питома затримка поширення сигналу в склотекстоліті FR-4. При t_r = 1 нс критична довжина становить L_crit ≈ 7.7 см. 

Якщо довжина провідника перевищує L_crit, на виході мікроконтролера обов'язково встановлюють послідовний демпфуючий резистор R_s, який узгоджує низький вихідний опір драйвера R_driver (близько 20–25 Ом) із хвильовим імпедансом доріжки Z_0 (типово 50 Ом):

```
R_s = Z_0 - R_driver = 50 - 22 = 28 Ом     [розрахунок демпфуючого резистора]
```

Розміщення резистора R_s номіналом 27–33 Ом безпосередньо біля виводу мікроконтролера гасить відбиту хвилю і повністю ліквідує дзвін на фронтах сигналу.
