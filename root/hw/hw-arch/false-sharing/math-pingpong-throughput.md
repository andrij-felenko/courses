# 🧮 Розрахунок пінг-понгу: стеля 1/t, поріг беззбитковості й чому крива йде вниз

Володіння кеш-лінією — послідовний ресурс: власник у кожну мить рівно один, тож усі записи в цю лінію, з якого б ядра вони не йшли, шикуються в одну спільну чергу. А чергу з одним обслуговувачем рахують звичайними формулами вузького місця. Нижче — виведення сумарного й поядерного темпу як функції трьох чисел (число ядер `n`, час передачі лінії `t`, частка спільних записів `p`), стеля, яка не залежить від `n` узагалі, точна умова, за якої чотири ядра стають повільнішими за одне, і порівняння форми отриманої кривої із законом Амдала.

### Три числа, з яких усе складається

Одиниця роботи — одне звернення циклу до пам'яті. З кожних `1/p` таких звернень рівно одне влучає в спірну лінію, решта йдуть у власні дані ядра й нікого не обходять.

```
w — запис у лінію, якою ядро вже володіє (влучання в L1)   ≈ 1.4 нс
t — передача володіння лінією іншому ядру                  ≈ 20 нс усередині кристала
                                                           ≈ 100 нс через межу кристала
p — частка спільних записів серед усієї роботи циклу        0 … 1
n — число ядер, що працюють одночасно

r = t / w — курс обміну: у скільки разів спільний запис дорожчий за власний
    r = 20 / 1.4  ≈ 14.3      (усередині кристала)
    r = 100 / 1.4 ≈ 71.4      (через межу кристала)
```

Курс `r` — головне число всієї моделі. Абсолютні наносекунди далі скорочуються майже скрізь, і лишається саме відношення: `p` каже, як часто ви платите, `r` — у скільки разів дорожче.

Дві домовленості, які варто назвати одразу, бо від них залежить, у який бік модель бреше. Перша: **один корисний запис на одну передачу**. У тісному циклі це так і є — щойно ядро дістало лінію, запит сусіда вже стоїть у черзі й забирає її майже негайно. Друга: спільний запис коштує `t`, а не `t + w`; сам запис після приїзду лінії ми відкидаємо. Заниження тут `w/t ≈ 7 %`, тобто модель трохи **оптимістична** — справжня машина буде на кілька відсотків гіршою за розрахунок.

### Стеля: лінія віддає 1/t записів на секунду, скільки б ядер не було

Візьмімо всі спільні записи, що сталися за секунду, з усіх ядер разом, і викладімо їх у порядку часу. Між двома сусідніми записами цього ряду, якщо вони зроблені різними ядрами, мусить повністю пройти передача володіння — інакше другий запис не мав би права статися. У насиченому режимі черга за лінією обслуговується по колу: ядро, що щойно писало, стає в її хвіст, тож сусідні записи в ряду майже завжди належать різним ядрам. Отже, інтервал між сусідніми записами не менший за `t`, і сумарний темп спільних записів обмежений зверху:

```
X ≤ 1 / t

t = 20 нс  →  X ≤ 1 / (20·10⁻⁹ с)  = 50·10⁶ /с  = 50 млн/с
t = 100 нс →  X ≤ 1 / (100·10⁻⁹ с) = 10·10⁶ /с  = 10 млн/с

для порівняння, записи у власну лінію: 1/w = 1/1.4 нс ≈ 714 млн/с
```

У цій формулі немає `n`. Це не недогляд виведення, а його суть: додавання ядра додає **клієнта** в чергу, а не обслуговувача. Обслуговувач один і завжди один — сама лінія. Той самий висновок дає й [закон Літтла](root:math-probability/littles-law) у застосуванні до одного вузла: темп дорівнює зайнятості, поділеній на час обслуговування, а зайнятість одного ресурсу не буває більшою за одиницю.

Оцінка «сусідні записи належать різним ядрам» — найпесимістичніша з можливих. Якби наступного охочого обирали навмання з `n` ядер, частка передач упала б до `(n−1)/n`, і стеля піднялася б у `n/(n−1)` разів: удвічі при `n = 2`, на третину при `n = 4`, на 14 % при `n = 8`. На порядки, про які йдеться далі, така поправка не впливає.

### Попит: скільки часу одне ядро хоче на одиницю роботи

Тепер погляньмо з боку ядра. Частка `1−p` його звернень коштує `w`, частка `p` коштує `t`. Середній час на одиницю роботи — це попит одного ядра:

```
D(p) = (1 − p)·w + p·t = w·(1 + p·(r − 1))
```

**Підстановка: w = 1.4 нс, t = 20 нс (r ≈ 14.3).**

```
p = 0      D = 1.4000 нс   темп одного ядра 1/D = 714 млн/с
p = 0.1 %  D = 1.4186 нс                        705 млн/с
p = 1 %    D = 1.5860 нс                        631 млн/с
p = 10 %   D = 3.2600 нс                        307 млн/с
p = 100 %  D = 20.000 нс                         50 млн/с
```

Уже тут видно перше: `D` росте лінійно з `p` із крутизною `w·(r−1) ≈ 18.6 нс`, тобто **один відсоток** спільних записів додає до часу на одиницю роботи цілих тринадцять відсотків. Але це ще не масштабування — це просто латентність передачі, яку ядро платить навіть тоді, коли ніякої черги немає й лінія віддається йому на першу вимогу.

### Модель: дві гілки й злам між ними

Хай `R` — сумарний темп корисної роботи всіх `n` ядер, одиниць роботи за секунду. Тоді спільних записів на секунду виходить `p·R`, і вони мусять уміститися в спроможність лінії:

```
попит         R   ≤ n / D      — n ядер, кожне зі своєю швидкістю 1/D
спроможність  p·R ≤ 1 / t      — усі спільні записи крізь одне вушко

R(n) = min( n/D , 1/(p·t) )
```

Ліва гілка — режим, у якому лінія ще не насичена: кожне ядро працює на повній для себе швидкості, а сумарний темп росте пропорційно `n`. Права — режим насичення: лінія віддає все, що може, і додавання ядер уже нічого не додає. Точка зламу — там, де гілки зрівнялися:

```
n / D = 1 / (p·t)   ⟹   n* = D / (p·t) = (1 + p·(r − 1)) / (p·r)

при малому p:  n* ≈ 1 / (p·r)
```

**Підстановка: t = 20 нс.**

```
спільних записів лінія віддає 1/t = 50 млн/с за будь-якого p,
тож стеля корисної роботи — 50/p млн оп./с:

p = 0.1 %   стеля 50 000 млн оп./с    n* = 1.4186/0.02 ≈ 71
p = 1 %     стеля  5 000 млн оп./с    n* = 1.5860/0.20 ≈ 7.9
p = 10 %    стеля    500 млн оп./с    n* = 3.2600/2.00 ≈ 1.6
p = 100 %   стеля     50 млн оп./с    n* = 20.000/20.0 =  1.0
```

Читати це треба так. При одному спільному записі на сотню звернень масштабування живе рівно до восьми ядер, а далі полиця: шістнадцять ядер дадуть рівно стільки ж, скільки вісім, і шістдесят чотири — теж стільки ж. При кожному десятому — злам настає, ще не встигнувши початися: другого ядра вже забагато. При `p = 1` злам стоїть на `n* = 1`, тобто перше ж друге ядро потрапляє в насичення.

![Три криві сумарного темпу для p = 1 %, 10 % і 100 % у логарифмічних осях: кожна росте лінійно з числом ядер до свого зламу, далі переходить у горизонтальну полицю, рівень якої дорівнює 1/(p·t) і не залежить від n; синя штрихова лінія показує рівень одного потоку 714 млн/с, і полиці для p = 10 % та p = 100 % лежать нижче за неї](img/scaling.svg)
*Дві гілки формули на одному полотні. Ліва частина кожної кривої — попит `n/D`, права — спроможність `1/(p·t)`, і крива йде по меншій із них. Що більша частка спільних записів, то раніше настає злам і то нижче лежить полиця; при `p = 10 %` і більше полиця опиняється **під** рівнем одного потоку — усе, що в червоній зоні, означає, що паралелізм працює в мінус.*

### Стеля прискорення й поріг, за яким ядра починають шкодити

Порівнювати треба з одним ядром, і тут є тонкість, без якої весь розрахунок втрачає сенс. Одне ядро не платить `t` **ніколи**: відбирати лінію нема кому, тож вона осідає в його кеші назавжди, і навіть «спільний» запис коштує йому звичайні `w`. Тому база — це `R(1) = 1/w`, а не `1/D`. Множник `p·(t − w)` існує рівно тому, що є суперники.

```
S(n) = R(n) / R(1) = w · min( n/D , 1/(p·t) )

S(n) = min( n / (1 + p·(r − 1)) ,  1 / (p·r) )
```

Наносекунди зникли — лишилися дві безрозмірні величини. Стеля прискорення:

```
S∞ = 1 / (p·r)
```

Гіпербола. Удесятеро рідший спільний запис — удесятеро вища стеля. І звідси одразу випливає поріг беззбитковості: `S∞ = 1` означає, що вся машина, скільки б у ній не було ядер, робить рівно стільки, скільки робило б одне.

```
1 / (p*·r) = 1   ⟹   p* = 1/r = w/t

t = 20 нс   →  p* = 1.4/20  = 7.0 %
t = 100 нс  →  p* = 1.4/100 = 1.4 %
```

**Якщо більше за сім відсотків звернень циклу б'ють у спірну лінію, жодне число ядер не пережене одного ядра.** Не «виграш буде малий» — виграш буде від'ємний, і що більше ядер ви додасте, то більшою буде поразка в перерахунку на ядро. Через межу кристала поріг падає до півтора відсотка: одного спільного запису на сімдесят звичайних уже досить, щоб паралелізм пішов у збиток.

![Дві прямі з нахилом −1 у логарифмічних осях: стеля прискорення S∞ = 1/(p·r) як функція частки спільних записів p, окремо для t = 20 нс і t = 100 нс; горизонтальна штрихова лінія позначає рівень беззбитковості S∞ = 1, а кружечки — точки її перетину при p = 7 % і p = 1.4 %](img/threshold.svg)
*Стеля прискорення проти частки спільних записів. У логарифмічних осях гіпербола `1/(p·r)` — це пряма з нахилом −1, а курс обміну `r` лише зсуває її вниз: чим дорожча передача, тим лівіше зустрічається з одиницею. Кружечки — пороги беззбитковості; праворуч від них уся червона зона, де багатоядерна машина віддає менше за однопоточну.*

Питання «наскільки рідкісним має бути спільний запис, щоб масштабування дожило до `n` ядер» — це вимога `n* ≥ n`, тобто

```
p ≤ (1 + p·(r − 1)) / (n·r)   ≈   1 / (n·r)

n = 4,  t = 20 нс   →  p ≤ 1.7 %     один спільний запис на 57 звернень
n = 16, t = 20 нс   →  p ≤ 0.44 %    один на 229
n = 16, t = 100 нс  →  p ≤ 0.088 %   один на 1140
```

Числа праворуч і є практичною відповіддю. Щоб шістнадцять ядер справді дали шістнадцятикратне прискорення, спільна лінія має чіплятися **раз на дві сотні** ітерацій, а якщо ядра роз'їхалися по різних кристалах — раз на тисячу.

### Чотири ядра проти одного: числа

**Тісний цикл, кожне звернення б'є в спірну лінію: p = 1, n = 4.**

```
одне ядро:        R(1) = 1/w = 714 млн оп./с

n = 4, t = 20 нс: R(4) = min(4/20, 1/20) = 1/20 = 50 млн оп./с
                  на одне ядро: 50/4              = 12.5 млн оп./с
                  сумарно      714 / 50           ≈ 14× повільніше
                  на ядро      714 / 12.5         ≈ 57× повільніше

n = 4, t = 100 нс: R(4) = 1/100 = 10 млн оп./с
                   на ядро                        = 2.5 млн оп./с
                   сумарно     714 / 10           ≈ 71× повільніше
                   на ядро     714 / 2.5          ≈ 286× повільніше
```

Два стовпчики уповільнення розходяться в `n` разів, і плутати їх не можна. Сумарне уповільнення дорівнює курсу обміну `r` і від числа ядер не залежить: у насиченні `S∞ = 1/(p·r)`, тобто при `p = 1` рівно `1/r`. Поядерне уповільнення дорівнює `n·r` і росте разом із бригадою: кожен новий учасник не додає роботи, а лише ділить ту саму фіксовану порцію на більше число ротів.

### Чому крива не полиця, а спад: t залежить від n

Модель `min(…)` дає горизонтальну полицю, а виміри на великих машинах показують справжній спад. Причина в тому, що `t` — не стала: вона залежить від того, **між якими саме** двома ядрами їде лінія. Розсадімо ядра кластерами по `m` штук зі спільним кешем усередині кластера. Наступний охочий у черзі опиняється в тому самому кластері з імовірністю `(m−1)/(n−1)`, а в чужому — з рештою:

```
t̄(n) = t_близ·(m − 1)/(n − 1) + t_дал·(n − m)/(n − 1),   n > m
```

**Підстановка: m = 8, t_близ = 20 нс, t_дал = 100 нс, p = 1.**

```
n         t̄(n)                          сумарно      на ядро
1           —                            714 млн/с    714
2 … 8     20.0 нс                         50.0          50/n
16        (7·20 + 8·100)/15  = 62.7 нс     16.0          1.00
32        (7·20 + 24·100)/31 = 81.9 нс     12.2          0.38
```

Перехід від восьми ядер до шістнадцяти зменшив **сумарний** темп у 3.1 раза. Ось де береться спадна крива: додане ядро не тільки стає в чергу, воно ще й подовжує середню дорогу лінії для всіх решти. Полиця `1/(p·t̄)` починає повзти вниз, а поядерний темп падає одразу з двох причин — і через `1/n`, і через `t̄(n)`, — тож ці два множники перемножуються. Та сама залежність часу від фізичної відстані між вузлами робить нерівномірним і доступ до головної пам'яті на великих машинах ([NUMA](root:hw-arch/numa)); тут вона проступає прямо у формулі стелі, підмінюючи сталу `t` величиною, що росте разом із `n`.

### Чим ця форма не Амдалова

[Закон Амдала](root:sf-algorithms/amdahls-law) для послідовної частки `f` дає

```
S_Амдала(n) = 1 / ( f + (1 − f)/n ),      стеля 1/f
```

Наша модель у тому самому гладкому вигляді (гармонійне з'єднання двох гілок замість `min`):

```
S(n) ≈ 1 / ( p·r + (1 + p·(r − 1))/n ),   стеля 1/(p·r)
```

Формули однакові за будовою, і саме тому їх варто покласти поруч — уся різниця зосереджена в трьох місцях, і кожне з них перевіряється підстановкою.

**Стеля.** У Амдала `f` — це частка, отже `f ≤ 1`, отже `1/f ≥ 1`: полиця завжди лежить **над** рівнем одного процесора. У нас на місці `f` стоїть не частка, а добуток `p·r` — частку помножено на курс обміну 14 або 71. Такий добуток вільно перевалює за одиницю, і тоді стеля падає нижче одиниці. Уся хвороба вміщається в один рядок: `f_еф = p·r`, і при `p > 1/r` цей «відсоток послідовного коду» більший за сто відсотків. Як частка — нісенітниця; як ціна — точна правда.

**Крутизна першої гілки.** У Амдала при `f → 0` крива тулиться до ідеальної прямої `S = n`. У нас крутизна дорівнює `1/(1 + p·(r−1))` і завжди менша за одиницю: при `p = 1 %` вона вже 0.88, тобто чотири ядра дадуть 3.5× замість чотирьох, ще навіть не діставшись до зламу. Кожне ядро окремо повільніше, ніж було на самоті, бо спільний запис коштує `t` замість `w` навіть за цілком порожньої черги.

**Монотонність.** Амдалова `S(n)` строго росте й ніколи не повертає гіршого, ніж було: додане ядро в найгіршому разі не дає нічого. Наша `S(n)` виходить на полицю, а з `t̄(n)`, що росте, — справді спадає. Закон Амдала вміє пояснити «приросту немає»; пояснити «стало гірше» він не вміє в принципі.

Причина розходження одна, і вона в аксіомі. Амдал припускає, що **сумарна робота стала**: паралелізм лише інакше її розкладає, тож коефіцієнти в його знаменнику й дають у сумі одиницю. Хибне спільне цю аксіому порушує: сам акт поділу роботи між ядрами **створює** роботу, якої на одному ядрі не було зовсім. Кожен спільний запис, що коштував `w`, починає коштувати `t = r·w`, і пиріг росте від того, що його ріжуть. Щойно обсяг роботи залежить від числа виконавців, стеля дістає право опуститися нижче одиниці — і форма кривої перестає бути Амдаловою. Розбір самої пари формул Амдала й Літтла, з якої тут узято ліву половину, — у [вставці про два співвідношення продуктивності](root:sf-apps/performance-tactics/math-amdahl-little.md).

### Єдиний важіль — це p

У формулі `S(n) = min( n/(1 + p·(r−1)), 1/(p·r) )` вам не належить майже нічого. Курс `r` заданий кристалом, `t̄(n)` — його топологією, `n` — це те, що ви хочете збільшити. Вільна змінна одна: `p`.

Накопичення проміжного результату в локальній змінній зі скиданням у спільну пам'ять раз на `k` ітерацій ділить частку на `k`:

```
p → p/k    ⟹    стеля S∞ = k/(p₀·r)     — росте лінійно з k
                поріг    p₀ ≤ k/r
```

**Скільки треба накопичувати, щоб шістнадцять ядер дали шістнадцятикратне прискорення (t = 20 нс, p₀ = 1).**

```
потрібне p = 1/(n·r) = 1/(16·14.3) = 0.44 %
k = p₀ / p = 229

було (p = 1):     S(16) = min(16/14.3, 1/14.3) = 0.07  → у 14 разів ГІРШЕ за одне ядро
стало (p = 1/229): S(16) = min(16/1.058, 16.0)  = 15.1 → у 15 разів краще

різниця в 15.1 / 0.07 ≈ 216 разів
```

Скидання лічильника раз на дві з половиною сотні ітерацій замість кожної переставляє той самий цикл через поріг беззбитковості й далі — з мінус чотирнадцяти на плюс п'ятнадцять. Розкладка даних при цьому не змінена жодним байтом: рухали виключно `p`. Рознесення по межах ліній діє інакше — воно робить `p = 0` і викидає праву гілку з формули зовсім, тому там, де воно можливе, воно й сильніше; але там, де значення справді потрібне сусідам під час роботи, лишається множник `k`, і його одного вистачає, щоб перевести знак.
