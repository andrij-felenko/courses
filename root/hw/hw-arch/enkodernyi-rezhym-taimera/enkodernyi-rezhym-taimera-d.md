Коли вал безколекторного двигуна або промислового сервоприводу обертається зі швидкістю 6000 об/хв із встановленим оптичним диском на 1024 лінії, на виходах сенсора виникає понад 400 000 перемикань логічних рівнів щосекунди. Спроба обробляти кожну таку подію програмно через зовнішні переривання GPIO (EXTI) миттєво паралізує ядро мікроконтролера сотнями тисяч перемикань контексту, а брязкіт контактів і високочастотний шум від силового інвертора спричинять катастрофічний дрейф розрахованого положення. Апаратний енкодерний режим таймера усуває ці проблеми на рівні кремнієвої логіки: апаратура таймера самостійно захоплює квадратурні сигнали, фільтрує завади, визначає напрямок руху та інкрементує або декрементує лічильник без жодного такту навантаження на центральний процесор.

## Фізика квадратурного сигналу: ортогональність фаз і вектор руху

Інкрементальний енкодер генерує два прямокутні цифрові сигнали, які прийнято позначати як Канал A (вхід таймера TI1) та Канал B (вхід таймера TI2). Фізичне розташування фотодетекторів в оптичних датчиках або елементів Холла в магнітних сенсорах розраховане так, що сигнали каналів зміщені у просторі на чверть кроку растра. У часовій області це утворює електричний фазовий зсув рівно на 90 градусів (π/2 радіан або 1/4 повного періоду коливання T).

![Квадратурні сигнали каналів A та B для прямого та зворотного напрямків обертання](/root/hw/hw-arch/enkodernyi-rezhym-taimera/img/quadrature-signals.svg)
*Фазовий зсув 90° між каналами TI1 (A) та TI2 (B): при обертанні вперед канал A випереджає канал B, а при обертанні назад канал B випереджає канал A, що дозволяє апаратурі таймера однозначно визначати вектор руху.*

Якщо вал рухається у прямому напрямку (CW — Clockwise), активний фронт каналу A настає раніше за фронт каналу B. У момент висхідного фронту на каналі A рівень на каналі B залишається низьким (`0`). Коли напрямок обертання змінюється на протилежний (CCW — Counter-Clockwise), фазові співвідношення дзеркально інвертуються: тепер канал B випереджає канал A, і у момент висхідного фронту каналу A рівень каналу B уже встановлений у високий стан (`1`).

Один канал імпульсів здатен повідомити системі лише кутову швидкість (частоту проходження міток), але принципово не містить інформації про знак переміщення. Ба більше: якщо механізм зупиниться точно на лінії спрацьовування оптичного детектора, навіть мікроскопічна вібрація статора викликатиме серію хибних спрацьовувань. Одноканальний лічильник сприйме це як безперервний рух вперед, накопичуючи фатальну похибку. Два ортогональні сигнали формують двовимірний простір станів, у якому будь-яке коливання вперед-назад коректно компенсується зустрічними відліками.

## Граф станів коду Грея та захист від механічного джитеру

Сукупність логічних рівнів двох каналів (A, B) утворює двійковий 2-бітний код, який змінюється за правилами циклічного коду Грея. При обертанні вперед система послідовно проходить чотири стани:

```
00  →  10  →  11  →  01  →  00
```

При зміні напрямку обертання порядок переходів стає реверсивним:

```
00  →  01  →  11  →  10  →  00
```

Головна математична особливість коду Грея полягає в тому, що кодова відстань Геммінга між сусідніми станами завжди дорівнює одиниці (d_H = 1). Під час переходу вала з однієї дискретної позиції в сусідню змінюється стан лише одного каналу — або A, або B. Одночасна зміна обох бітів (`00 ↔ 11` або `10 ↔ 01`) у справній механічній та оптичній системі фізично неможлива, оскільки вимагала б абсолютно синхронного перетину двох зміщених оптичних масок.

![Граф переходів квадратурного декодера та захист від брязкоту](/root/hw/hw-arch/enkodernyi-rezhym-taimera/img/encoder-state-transitions.svg)
*Діаграма станів квадратурного автомата: дозволені переходи з кроком +1 та −1 мають одиничну дистанцію Геммінга; подвійні перемикання (діагоналі ERR) детектуються як апаратна помилка або шум.*

Апаратний автомат таймера безперервно відстежує стан пари (A, B). Якщо вал зазнає вібрації чи механічного удару на межі перемикання каналу A, рівень сигналу A хаотично стрибає між `0` та `1`, тоді як канал B стабільно утримує значення `0`. Апаратура інтерпретує це як цикл `00 → 10 → 00 → 10`, виконуючи кроки:

```
+1  →  −1  →  +1  →  −1  =  0
```

Поточний лічильник положення коливається між значеннями N та N+1, не накопичуючи жодного систематичного зсуву. Якщо ж на лініях фіксується заборонений діагональний перехід (наприклад, `00 → 11`), спеціалізовані розширені таймери (наприклад, контролери позиціонування в сервоконтролерах STM32 або DSP-процесорах) реєструють помилку енкодерного інтерфейсу, сигналізуючи про обрив кабелю, неприпустимо високу швидкість обертання або потужну електромагнітну заваду.

## Режими підрахунку: X1, X2 та X4

Залежно від вимог до кутової роздільності та швидкодії алгоритму керування, енкодерний інтерфейс таймера можна сконфігурувати в один із трьох режимів множення відліків.

![Режими підрахунку імпульсів енкодера X1, X2 та X4](/root/hw/hw-arch/enkodernyi-rezhym-taimera/img/encoder-modes-x1-x2-x4.svg)
*Порівняння роздільної здатності: режим X1 фіксує лише висхідний фронт каналу A, режим X2 рахує обидва фронти каналу A, а режим X4 детектує всі зміни рівнів на обох каналах, збільшуючи роздільну здатність у 4 рази.*

### Режим X1 (базовий підрахунок)

У режимі X1 таймер детектує лише один фронт (наприклад, наростання) на вибраному каналі TI1, перевіряючи рівень другого каналу TI2 для вибору знака. За один повний період коливання квадратурного сигналу T значення регістра лічильника `CNT` змінюється рівно на одиницю (`+1` або `-1`). Цей режим застосовують у системах із низькими вимогами до кутової точності або там, де частота імпульсів на максимальній швидкості наближається до граничної смуги пропускання вхідних кіл таймера.

### Режим X2 (підрахунок по одному каналу)

У конфігурації X2 (у документації мікроконтролерів STM32 — режим `Encoder Mode 1` або `Encoder Mode 2`) лічильник тактується як висхідним, так і спадним фронтом сигналу на каналі TI1 (або відповідно TI2). Кожен перехід на активному каналі аналізується відносно поточного логічного рівня неактивного каналу. За один електричний період T лічильник фіксує два відліки (`+2` або `-2`), подвоюючи базову роздільну здатність диска.

### Режим X4 (повне квадратурне множення)

Режим X4 (в архітектурі STM32/ARM — `Encoder Mode 3`, біти `SMS = 011` у регістрі `TIMx_SMCR`) є промисловим стандартом для сервоприводів і робототехніки. Тут лічильними подіями є всі чотири фронти: наростання і спад на вході TI1, а також наростання і спад на вході TI2. 

Повна апаратна таблиця істинності для режиму X4 демонструє строгу детермінованість кожного кроку:

| Активний фронт на вході | Рівень сигналу TI1 (A) | Рівень сигналу TI2 (B) | Обертання CW (A випереджає B) | Обертання CCW (B випереджає A) |
|---|---|---|---|---|
| **TI1** Наростання (↑) | 1 | 0 | Інкремент (`+1`, DIR=0) | Декремент (`−1`, DIR=1) |
| **TI1** Спад (↓) | 0 | 1 | Інкремент (`+1`, DIR=0) | Декремент (`−1`, DIR=1) |
| **TI2** Наростання (↑) | 1 | 1 | Інкремент (`+1`, DIR=0) | Декремент (`−1`, DIR=1) |
| **TI2** Спад (↓) | 0 | 0 | Інкремент (`+1`, DIR=0) | Декремент (`−1`, DIR=1) |

Якщо енкодер має диск на 1024 CPR (Counts Per Revolution — ліній на оберт), у режимі X4 таймер зафіксує рівно:

```
N_counts = 1024 × 4 = 4096 імпульсів на повний оберт вала
```

Кутова дискретність системи покращується вчетверо: замість 0.351° на відлік система отримує точність позиціонування 0.0878° (360° / 4096), причому цей виграш досягається виключно внутрішньою логікою таймера без встановлення дорожчих оптичних дисків чи зовнішніх інтерполяторів.

## Внутрішній тракт таймера: синхронізація, фільтрація та керування DIR

Робота енкодерного режиму спирається на спеціалізований апаратний конвеєр обробки вхідних сигналів.

![Апаратний тракт обробки енкодерних сигналів усередині таймера](/root/hw/hw-arch/enkodernyi-rezhym-taimera/img/encoder-hardware-pipeline.svg)
*Внутрішня архітектура таймера: вхідні лінії проходять через цифрові фільтри ICxF, блоки інверсії CCxP і потрапляють до веденого контролера Slave Mode Controller, який формує тактові імпульси та виставляє апаратний біт напрямку DIR.*

### Захист від метастабільності та конвеєрна синхронізація

Сигнали від механічного або оптичного енкодера надходять у мікроконтролер асинхронно відносно його внутрішньої тактової сітки `f_TIMCLK`. Якщо подати такий сигнал безпосередньо на логічні вентилі декодера, фронт перемикання може збігтися з активним фронтом внутрішнього тактового генератора. Це викличе явище метастабільності — тригер зависне у невизначеному проміжному стані на кілька наносекунд, що призведе до збою лічильника або пропуску кроку.

Щоб запобігти метастабільності, на вході кожного каналу таймера встановлено двокаскадний синхронізатор на D-тригерах. Сигнал із виводу GPIO спершу фіксується першим тригером на такті внутрішньої частоти `f_CK_INT`, а потім переписується у другий тригер. Лише після проходження цієї схеми синхронізації сигнал надходить до блоку цифрової фільтрації.

### Цифрові фільтри придушення брязкоту (IC1F / IC2F)

Промислове середовище насичене завадами: комутація обмоток двигуна ШІМ-ключами інвертора зі швидкістю наростання напруги dU/dt > 5 кВ/мкс наводить паразитні ємнісні голки на кабельних трасах датчика. При використанні механічних енкодерів (наприклад, ручок інтерфейсу користувача) додається контактний брязкіт тривалістю 1–5 мс.

Для усунення цих артефактів кожен вхід таймера оснащено цифровим фільтром мажоритарного типу (біти `IC1F[3:0]` та `IC2F[3:0]` у регістрі `TIMx_CCMR1`). Фільтр складається з дільника тактової частоти f_DTS (Digital Timer Sampling clock, що формується з базової частоти таймера f_CK_INT через біти `CKD[1:0]` у регістрі `TIMx_CR1`) та N-розрядного зсувного регістра вибірок.

Апаратна логіка фільтра вимагає, щоб новий логічний рівень на вході залишався незмінним протягом N послідовних тактів частоти дискретизації (N=6 або N=8). Якщо під час вибірки стається короткий імпульс шуму, тривалість якого менша за `N × T_SAMPLING`, він скидає конвеєр фільтра і повністю відсікається, не потрапляючи до лічильного ядра:

| Значення `ICxF[3:0]` | Джерело дискретизації f_SAMPLING | Кількість вибірок підтвердження N | Мінімальна тривалість валідного імпульсу t_min |
|---|---|---|---|
| `0000` | Без фільтрації (f_CK_INT) | 1 (прямий вхід) | 1 такт f_CK_INT |
| `0001` | f_CK_INT | 2 | 2 такти f_CK_INT |
| `0010` | f_CK_INT | 4 | 4 такти f_CK_INT |
| `0011` | f_CK_INT | 8 | 8 тактів f_CK_INT |
| `0100` | f_DTS / 2 | 6 | 12 × T_DTS |
| `0101` | f_DTS / 2 | 8 | 16 × T_DTS |
| `0110` | f_DTS / 4 | 6 | 24 × T_DTS |
| `0111` | f_DTS / 4 | 8 | 32 × T_DTS |
| `1000` | f_DTS / 8 | 6 | 48 × T_DTS |
| `1001` | f_DTS / 8 | 8 | 64 × T_DTS |
| `1010` | f_DTS / 16 | 5 | 80 × T_DTS |
| `1011` | f_DTS / 16 | 6 | 96 × T_DTS |
| `1100` | f_DTS / 16 | 8 | 128 × T_DTS |
| `1101` | f_DTS / 32 | 5 | 160 × T_DTS |
| `1110` | f_DTS / 32 | 6 | 192 × T_DTS |
| `1111` | f_DTS / 32 | 8 | 256 × T_DTS |

Для оптичного енкодера на двигуні зазвичай обирають фільтр `ICxF = 0011` (8 тактів на частоті 84–168 МГц), що гарантує відсікання наносекундних комутаційних сплесків без обмеження максимальної частоти обертання. Для механічних ручок використовують `ICxF = 1111` із максимальним передподілом `CKD`, забезпечуючи фільтрацію брязкоту на рівні кількох мілісекунд.

### Конфігурація полярності та реверс каналів (CC1P / CC2P)

Після фільтрації сигнали надходять на селектори полярності `CC1P` та `CC2P` (у регістрі `TIMx_CCER`). Встановлення біта `CC1P = 1` призводить до апаратної інверсії сигналу каналу A перед подачею на квадратурний декодер. Це дозволяє програмно змінити напрямок рахунку енкодера на зворотний без фізичного перепаювання проводів на клемах плати.

### Автономне керування бітом напрямку DIR

Сигнали `TI1FP1` та `TI2FP2` надходять у ведений контролер режиму (Slave Mode Controller). Декодер формує внутрішній тактовий строб `CK_CNT`, що подається безпосередньо на лічильник `CNT`, оминаючи стандартний передільник `PSC` (Prescaler у режимі енкодера апаратно вимикається або фіксується на коефіцієнті 1). Одночасно декодер керує апаратним бітом `DIR` у керуючому регістрі `TIMx_CR1`:

- `DIR = 0`: вал обертається вперед (Upcounting), лічильник рахує від 0 до значення в регістрі автоматичного перезавантаження `ARR`.
- `DIR = 1`: вал обертається назад (Downcounting), лічильник рахує у зворотному напрямку від `ARR` вниз до 0.

Програмний код у будь-який момент може прочитати стан біта `DIR`, щоб миттєво дізнатися поточний напрямок обертання ротора без необхідності обчислення похідних чи збереження історії відліків.

## Індексний нульовий імпульс (канал Z) та апаратне скидання

Більшість прецизійних оптичних енкодерів мають додатковий третій вихід — канал Z (Index Marker або Reference Pulse). Цей сигнал генерує рівно один вузький строб на повний оберт механічного вала в наперед визначеному кутовому положенні (зазвичай тривалістю в один або пів періоду квадратурної сітки).

У системах точного позиціонування (ЧПУ-верстати, поворотні осі маніпуляторів, сервоприводи) канал Z виконує функцію абсолютної референтної мітки («нульової точки»). Після подачі живлення система не знає абсолютного кута ротора. Для калібрування виконується процедура виходу в нуль (Homing): двигун повільно обертається до появи імпульсу Z.

Апаратна реалізація прив'язки індексного сигналу до таймера можлива двома способами:

1. **Апаратне скидання лічильника через вхід ETR (External Trigger):** Сигнал каналу Z підключають до виводу `TIMx_ETR`. Таймер конфігурують у режим веденого скидання (`Slave Mode = Reset`, біти `SMS = 100` у `TIMx_SMCR`). У момент надходження імпульсу Z апаратура таймера миттєво записує `CNT = 0` без затримок на виклик переривань.
2. **Апаратне захоплення мітки в регістр CCR3/CCR4:** Сигнал каналу Z підключають до каналу TI3 або TI4 того самого таймера, налаштованого в режим захоплення (Input Capture). У момент проходження нульової мітки апаратура копіює поточне значення `CNT` у регістр `TIMx_CCR3` і піднімає переривання. Програмний контролер порівнює захоплене число з очікуваним періодом (наприклад, 4096) для перевірки відсутності пропуску імпульсів під час швидкісного обертання.

## Обробка переповнення лічильника та неперервна 64-бітна позиція

Більшість апаратних таймерів загального призначення у мікроконтролерах мають 16-бітну розрядність лічильного регістра `TIMx_CNT` (діапазон значень від `0` до `65535`, `ARR = 0xFFFF`). Лише окремі спеціалізовані таймери (як-от TIM2 та TIM5 у сімействах STM32F4/F7/H7) мають 32-бітний лічильник.

При роздільній здатності 4096 імп/об 16-бітний таймер робить повний оберт регістра всього за:

```
65536 / 4096 = 16 повних обертів вала
```

Після шістнадцятого оберту лічильник переповнюється і скидається в 0. Якщо система керує ходовим гвинтом верстата або колесом робота, який здійснює тисячі обертів, необхідний надійний математичний механізм розгортання апаратного циклічного значення в неперервну 64-бітну знакову координату (`int64_t total_position`).

![Часова діаграма обробки переповнення 16-бітного таймера](/root/hw/hw-arch/enkodernyi-rezhym-taimera/img/overflow-tracking-timeline.svg)
*Розгортання переповнень: апаратний регістр CNT скидається при досягненні меж 0 та 65535, а програмний шар підсумовує цілі періоди таймера у 64-бітну знакову координату.*

Існує дві інженерні стратегії розв'язання цієї задачі.

### Стратегія 1: Акумулятор переповнень через Update Interrupt

При переході лічильника через верхню межу ($65535 \to 0$ при `DIR=0`) або нижню межу ($0 \to 65535$ при `DIR=1`) таймер генерує подію оновлення (Update Event) і встановлює прапорець `UIF` у регістрі статусу `TIMx_SR`, викликаючи апаратне переривання `TIMx_IRQHandler`.

Нижче наведено обробник переривання для оновлення акумулятора обертів на мовах C та C++:

:::tabs
```c
#include <stdint.h>

static volatile int32_t g_overflow_count = 0;

void TIMx_IRQHandler(void) {
    if (TIMx->SR & TIM_SR_UIF) {
        TIMx->SR = ~TIM_SR_UIF; // Скидання прапорця переривання оновлення
        if ((TIMx->CR1 & TIM_CR1_DIR) == 0) {
            g_overflow_count++; // Переповнення вгору (Upcounting)
        } else {
            g_overflow_count--; // Недоповнення вниз (Downcounting)
        }
    }
}
```
```cpp
#include <cstdint>
#include <atomic>

class OverflowTracker {
public:
    static inline std::atomic<int32_t> overflow_count{0};

    static void handle_timer_irq(TimerHardware& tim) noexcept {
        if (tim.SR & (1U << 0)) { // Перевірка прапорця UIF
            tim.SR = ~(1U << 0);  // Скидання прапорця UIF
            if ((tim.CR1 & (1U << 4)) == 0) {
                overflow_count.fetch_add(1, std::memory_order_relaxed);
            } else {
                overflow_count.fetch_sub(1, std::memory_order_relaxed);
            }
        }
    }
};
```

#### Небезпека стану гонитви (Race Condition) та безблокувальне читання

Якщо основний потік програми або високопріоритетний цикл керування читає пару `(overflow_count, TIMx->CNT)` у момент, коли лічильник якраз переходить через 0, виникає класичний стан гонитви. Якщо прочитати `overflow_count` до спрацьовування переривання, а `CNT` — після переповнення (коли він уже став 0), результуюча координата отримає колосальний стрибок на +65536 або -65536 відліків.

Для гарантування абсолютної узгодженості застосовують безблокувальний алгоритм подвійного зчитування:

:::tabs
```c
#include <stdint.h>

int64_t get_encoder_position_atomic(void) {
    int32_t high1, high2;
    uint16_t low;
    do {
        high1 = g_overflow_count;
        low = (uint16_t)TIMx->CNT;
        high2 = g_overflow_count;
    } while (high1 != high2); // Повторюємо, якщо під час зчитування виникло переривання

    // Перевірка на випадок, коли переповнення сталось, але прапорець UIF ще не оброблений
    if ((TIMx->SR & TIM_SR_UIF) && (low < 32768)) {
        if ((TIMx->CR1 & TIM_CR1_DIR) == 0) {
            high1++;
        } else {
            high1--;
        }
    }
    return ((int64_t)high1 << 16) | low;
}
```
```cpp
#include <cstdint>
#include <atomic>

int64_t get_atomic_position(const TimerHardware& tim, const std::atomic<int32_t>& overflow_cnt) noexcept {
    int32_t high1{0}, high2{0};
    uint16_t low{0};
    do {
        high1 = overflow_cnt.load(std::memory_order_acquire);
        low = static_cast<uint16_t>(tim.CNT);
        high2 = overflow_cnt.load(std::memory_order_acquire);
    } while (high1 != high2);

    if ((tim.SR & (1U << 0)) && (low < 32768U)) {
        if ((tim.CR1 & (1U << 4)) == 0) {
            high1++;
        } else {
            high1--;
        }
    }
    return (static_cast<int64_t>(high1) << 16) | low;
}
```

### Стратегія 2: Дельта-метод без переривань (Fixed-period Polling)

Якщо система має детермінований цикл керування (наприклад, переривання від системного таймера з періодом T_ctrl = 1 мс), відстежувати позицію можна взагалі без використання переривань таймера енкодера.

Для цього використовують властивості арифметики доповняльного коду знакових чисел. Якщо різниця між поточним значенням 16-бітного регістра `CNT` та його попереднім значенням кастується до знакового типу `int16_t`, переповнення через $65535 \to 0$ коректно трансформується у малу додатну дельту:

```
Попередній відлік:  65530
Поточний відлік:    5
Беззнакова різниця: 5 - 65530 = -65525 (як uint16_t: 0x000B = 11)
Знакове приведення: (int16_t)(5 - 65530) = +11 відліків
```

Аналогічно, реверсний перехід через нуль ($2 \to 65532$) дає:

```
Знакове приведення: (int16_t)(65532 - 2) = (int16_t)(0xFFFA) = −6 відліків
```

Єдина фізична умова коректності дельта-методу — частота опитування повинна гарантувати, що за час T_ctrl вал не встигне повернутися більше ніж на половину діапазону лічильника (|ΔCNT| < ARR/2 = 32768 відліків). При роздільності 4096 імп/об і частоті опитування 1 кГц максимальна швидкість становить:

```
v_max = (32768 відліків / 4096 імп/об) × 1000 Гц = 8000 об/с = 480 000 об/хв
```

Це на кілька порядків перевищує механічні межі будь-якого електродвигуна, що робить дельта-метод найбільш надійним, швидким і стійким до гонитвових помилок.

## Вимірювання кутової швидкості: метод M, метод T та комбінований підхід M/T

Знаючи зміну лічильника енкодера, система керування електроприводом розраховує миттєву кутову швидкість ω. Залежно від швидкісного діапазону використовують один із методів.

### Метод частоти (M-метод)

M-метод базується на фіксованому періоді вимірювання Δt. Швидкість розраховується як кількість імпульсів ΔCNT, зафіксованих за квант часу:

```
ω = (ΔCNT / (PPR × 4)) × (2π / Δt)  [рад/с]
```

M-метод демонструє високу точність на середніх і високих швидкостях, де за період Δt накопичується велика кількість імпульсів (ΔCNT ≫ 100). Однак на наднизьких швидкостях проявляється шум квантування: якщо за мілісекунду надходить лише 0 або 1 імпульс, дискретність виміряної швидкості стає неприпустимо грубою, що викликає вібрацію контуру швидкості сервоприводу.

### Метод періоду (T-метод)

T-метод вимірює часовий інтервал ΔT між двома сусідніми фронтами енкодера за допомогою високочастотного тактового генератора таймера (f_clk ≈ 100 МГц). Він забезпечує мікросекундну точність на повзучих швидкостях, але втрачає ефективність на високих обертах, де інтервал між імпульсами скорочується до одиниць тактів ядра.

### Гібридний підхід (M/T-інтегратор)

У прецизійних сервоконтролерах застосовують комбінований метод M/T: швидкість оцінюється цифровим спостерігачем стану (Luenberger Observer або фільтром Калмана), який об'єднує інтеграл положення з моделі двигуна з миттєвими відліками таймера, усуваючи шум дискретизації на низьких обертах без внесення фазової затримки.

## Синхронізація з ШІМ та векторним керуванням FOC

У сучасних системах векторного керування синхронними двигунами (FOC — Field Oriented Control) кутове положення ротора необхідно зчитувати у строго визначений момент часу — у центрі періоду генерації ШІМ (коли всі ключі інвертора знаходяться у пасивному нульовому стані й комутаційні завади в лініях сенсорів мінімальні).

Для забезпечення нульового фазового джитера таймер ШІМ (наприклад, TIM1) налаштовують у режим генератора тригера (Master Mode: `MMS = Compare Pulse` або `Update Event`), а таймер енкодера (наприклад, TIM2/TIM3) підключають через внутрішню шину зв'язку ITRx (Internal Trigger). У момент тригера апаратура може автоматично ініціювати DMA-транзакцію, яка копіює значення регістра `TIMx_CNT` прямо в масив вхідних даних для алгоритму перетворень Парка і Кларк без участі CPU.

## Типові інженерні пастки при роботі з енкодером

Під час апаратного налаштування та експлуатації квадратурних таймерів інженери найчастіше стикаються з чотирма критичними помилками:

1. **Ненульовий передільник PSC:** Якщо у регістр `TIMx_PSC` записати значення більше 0, вхідний дільник буде ділити події декодера. Це призводить до того, що зміна напрямку обертання буде детектуватися із запізненням на (PSC+1) імпульсів, руйнуючи точність і викликаючи втрату позиції при реверсі. Для енкодерного режиму `PSC` завжди повинен дорівнювати 0.
2. **Фазова затримка цифрового фільтра на високих обертах:** Якщо встановити занадто «важкий» цифровий фільтр (наприклад, 8 вибірок із дільником 32), тривалість підтвердження стану перевищить чверть періоду вхідного сигналу на максимальній швидкості двигуна. Фільтр почне сприймати корисні імпульси як шум і відкидати їх, спричиняючи втрату лічби. Гранична кутова швидкість обертання вала обмежується формулою:
```
ω_max = 2π / (4 × PPR × t_filter)  [рад/с]
```
3. **Недостатня підтяжка ліній з відкритим колектором:** Більшість промислових оптичних датчиків мають виходи типу NPN Open Collector. Використання слабкої внутрішньої підтяжки мікроконтролера (30–50 кОм) разом із ємністю довгого екранованого кабелю (100–300 пФ/м) утворює RC-ланцюг, що перетворює круті прямокутні фронти на пологі експоненти. Різниця у швидкості наростання каналів A і B призводить до спотворення 90-градусного фазового зсуву та хибного детектування реверсу. Необхідно встановлювати зовнішні резистори підтяжки номіналом 1.0–2.2 кОм біля самого роз'єму мікроконтролера.
4. **Некоректне значення ARR:** Якщо встановити значення `ARR` відмінним від `0xFFFF` (для 16-бітного режиму) без прив'язки до кількості ліній енкодера, знакове кастування `int16_t` у дельта-методі перестане працювати коректно, оскільки розрив циклічності станеться не на ступені двійки.

## Практична реалізація: повний апаратний драйвер на C та ідіоматичному C++

Нижче наведено повноцінний промисловий драйвер конфігурації таймера в режимі квадратурного енкодера (на прикладі архітектури STM32 / ARM Cortex-M із прямим доступом до регістрів `TIMx`). Драйвер реалізує налаштування цифрових фільтрів, 64-бітний трекінг позиції за дельта-методом, розрахунок кутової швидкості та фільтрацію низьких частот першого порядку.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

/* Структура регістрів базового таймера STM32 (CMSIS-сумісна) */
typedef struct {
    volatile uint32_t CR1;
    volatile uint32_t CR2;
    volatile uint32_t SMCR;
    volatile uint32_t DIER;
    volatile uint32_t SR;
    volatile uint32_t EGR;
    volatile uint32_t CCMR1;
    volatile uint32_t CCMR2;
    volatile uint32_t CCER;
    volatile uint32_t CNT;
    volatile uint32_t PSC;
    volatile uint32_t ARR;
} TimerRegs;

/* Конфігурація та стан драйвера енкодера */
typedef struct {
    TimerRegs* tim;
    uint32_t ppr;               /* Кількість ліній на оберт (Pulses Per Revolution) */
    uint32_t counts_per_rev;    /* PPR * 4 для режиму X4 */
    uint16_t last_cnt;          /* Попереднє значення апаратного CNT */
    int64_t total_position;     /* Накопичена 64-бітна абсолютна позиція */
    float velocity_rad_s;       /* Фільтрована кутова швидкість у рад/с */
    float lpf_alpha;            /* Коефіцієнт експоненційного фільтра швидкості */
} EncoderDriverC;

/* Ініціалізація таймера в апаратному квадратурному режимі X4 */
void encoder_init(EncoderDriverC* enc, TimerRegs* tim, uint32_t ppr, float cutoff_hz, float dt) {
    enc->tim = tim;
    enc->ppr = ppr;
    enc->counts_per_rev = ppr * 4;
    enc->last_cnt = 0;
    enc->total_position = 0;
    enc->velocity_rad_s = 0.0f;

    /* Розрахунок коефіцієнта фільтра низьких частот: alpha = dt / (dt + RC) */
    if (cutoff_hz > 0.0f) {
        float rc = 1.0f / (2.0f * 3.1415926535f * cutoff_hz);
        enc->lpf_alpha = dt / (dt + rc);
    } else {
        enc->lpf_alpha = 1.0f;
    }

    /* 1. Вимикаємо таймер перед налаштуванням */
    tim->CR1 = 0;

    /* 2. Конфігурація вхідних каналів у регістрі CCMR1:
     *    CC1S = 01 (вхід TI1 підключено до IC1)
     *    CC2S = 01 (вхід TI2 підключено до IC2)
     *    IC1F = 0011 (цифровий фільтр: 8 вибірок f_CK_INT)
     *    IC2F = 0011 (цифровий фільтр: 8 вибірок f_CK_INT)
     */
    tim->CCMR1 = (0x1 << 0) | (0x3 << 4) | (0x1 << 8) | (0x3 << 12);

    /* 3. Полярність вхідних сигналів у CCER:
     *    CC1P = 0, CC1NP = 0 (неінвертований, наростання)
     *    CC2P = 0, CC2NP = 0 (неінвертований, наростання)
     */
    tim->CCER = 0;

    /* 4. Конфігурація веденого режиму в SMCR:
     *    SMS[2:0] = 011 (Encoder Mode 3: рахунок по всіх фронтах TI1 та TI2 — X4)
     */
    tim->SMCR = (0x3 << 0);

    /* 5. Максимальний діапазон рахунку: ARR = 0xFFFF (для 16-бітного таймера) */
    tim->ARR = 0xFFFF;
    tim->PSC = 0; // Передільник вимкнено (коефіцієнт 1)
    tim->CNT = 0;

    /* 6. Запуск таймера: CEN = 1 */
    tim->CR1 |= (1 << 0);
    enc->last_cnt = (uint16_t)tim->CNT;
}

/* Періодичне опитування стану (викликається у високопріоритетному циклі з фіксованим dt) */
void encoder_update(EncoderDriverC* enc, float dt) {
    uint16_t current_cnt = (uint16_t)(enc->tim->CNT);

    /* Обчислення знакового приросту за властивостями доповняльного коду int16_t */
    int16_t delta = (int16_t)(current_cnt - enc->last_cnt);
    enc->last_cnt = current_cnt;

    /* Накопичення 64-бітної координати */
    enc->total_position += delta;

    /* Миттєва швидкість: відліки -> радіани за секунду */
    float instant_velocity = ((float)delta / (float)enc->counts_per_rev) * (2.0f * 3.1415926535f) / dt;

    /* Експоненційне згладжування шуму квантування */
    enc->velocity_rad_s += enc->lpf_alpha * (instant_velocity - enc->velocity_rad_s);
}

/* Отримання поточної абсолютної позиції в радіанах */
float encoder_get_angle_rad(const EncoderDriverC* enc) {
    return ((float)enc->total_position / (float)enc->counts_per_rev) * (2.0f * 3.1415926535f);
}

/* Отримання поточного напрямку безпосередньо з апаратного біта DIR */
bool encoder_is_reversing(const EncoderDriverC* enc) {
    return (enc->tim->CR1 & (1 << 4)) != 0; // Біт 4: DIR
}
```

```cpp
#include <cstdint>
#include <concepts>
#include <numbers>
#include <atomic>

/* Апаратне відображення регістрів таймера */
struct TimerHardware {
    volatile uint32_t CR1;
    volatile uint32_t CR2;
    volatile uint32_t SMCR;
    volatile uint32_t DIER;
    volatile uint32_t SR;
    volatile uint32_t EGR;
    volatile uint32_t CCMR1;
    volatile uint32_t CCMR2;
    volatile uint32_t CCER;
    volatile uint32_t CNT;
    volatile uint32_t PSC;
    volatile uint32_t ARR;
};

/* Режими множення квадратурного декодера */
enum class EncoderMode : uint32_t {
    X1_TI1 = 0x1, /* Рахунок лише на каналі TI1 */
    X2_TI2 = 0x2, /* Рахунок лише на каналі TI2 */
    X4_TI12 = 0x3 /* Повний квадратурний рахунок на обох каналах */
};

/* Рівень цифрової фільтрації вхідних каналів ICxF */
enum class FilterLevel : uint32_t {
    None = 0x0,
    Samples2_CK_INT = 0x1,
    Samples4_CK_INT = 0x2,
    Samples8_CK_INT = 0x3,
    Samples6_DTS_Div4 = 0x6,
    Samples8_DTS_Div32 = 0xF /* Максимальне придушення брязкоту контактів */
};

/* Знімок стану енкодера для атомарного передавання в контури керування */
struct EncoderSnapshot {
    int64_t total_ticks{0};
    double angle_rad{0.0};
    float velocity_rad_s{0.0f};
    bool is_reverse{false};
};

/* RAII-драйвер енкодерного інтерфейсу таймера */
template <uintptr_t TimerBaseAddress>
class QuadratureEncoder {
public:
    static TimerHardware& hardware() noexcept {
        return *reinterpret_cast<TimerHardware*>(TimerBaseAddress);
    }

    struct Config {
        uint32_t pulses_per_revolution{1024};
        EncoderMode mode{EncoderMode::X4_TI12};
        FilterLevel filter{FilterLevel::Samples8_CK_INT};
        bool invert_direction{false};
        float velocity_filter_cutoff_hz{50.0f};
        float update_period_s{0.001f};
    };

    explicit QuadratureEncoder(const Config& cfg) noexcept
        : counts_per_rev_(cfg.pulses_per_revolution * (cfg.mode == EncoderMode::X4_TI12 ? 4 : 2)),
          dt_(cfg.update_period_s) {
        init_hardware(cfg);
        init_filter(cfg.velocity_filter_cutoff_hz);
    }

    ~QuadratureEncoder() noexcept {
        hardware().CR1 &= ~1U; // Зупинка таймера
    }

    /* Заборона копіювання (апаратний ресурс унікальний) */
    QuadratureEncoder(const QuadratureEncoder&) = delete;
    QuadratureEncoder& operator=(const QuadratureEncoder&) = delete;
    QuadratureEncoder(QuadratureEncoder&&) noexcept = default;
    QuadratureEncoder& operator=(QuadratureEncoder&&) noexcept = default;

    /* Періодичне оновлення стану (виклик з ISR періоду керування або RTOS потоку) */
    void update() noexcept {
        const auto current_cnt = static_cast<uint16_t>(hardware().CNT);
        const auto delta = static_cast<int16_t>(current_cnt - last_cnt_);
        last_cnt_ = current_cnt;

        total_position_ += delta;

        // Миттєва швидкість
        const float instant_velocity = (static_cast<float>(delta) / static_cast<float>(counts_per_rev_)) *
                                       (2.0f * std::numbers::pi_v<float>) / dt_;

        // Фільтрація першого порядку
        velocity_rad_s_ += lpf_alpha_ * (instant_velocity - velocity_rad_s_);

        // Оновлення кешованого знімка
        const bool reverse = (hardware().CR1 & (1U << 4)) != 0;
        snapshot_.store({
            .total_ticks = total_position_,
            .angle_rad = (static_cast<double>(total_position_) / counts_per_rev_) * (2.0 * std::numbers::pi_v<double>),
            .velocity_rad_s = velocity_rad_s_,
            .is_reverse = reverse
        }, std::memory_order_relaxed);
    }

    [[nodiscard]] EncoderSnapshot get_snapshot() const noexcept {
        return snapshot_.load(std::memory_order_relaxed);
    }

    [[nodiscard]] int64_t get_ticks() const noexcept {
        return total_position_;
    }

    [[nodiscard]] float get_velocity() const noexcept {
        return velocity_rad_s_;
    }

    void reset_position() noexcept {
        hardware().CNT = 0;
        last_cnt_ = 0;
        total_position_ = 0;
        velocity_rad_s_ = 0.0f;
    }

private:
    void init_hardware(const Config& cfg) noexcept {
        auto& tim = hardware();

        tim.CR1 = 0; // Вимкнення лічильника

        const auto filter_val = static_cast<uint32_t>(cfg.filter);
        // Канал 1: CC1S = 01, IC1F = filter; Канал 2: CC2S = 01, IC2F = filter
        tim.CCMR1 = (0x1U << 0) | (filter_val << 4) | (0x1U << 8) | (filter_val << 12);

        // Полярність входів (інверсія за потреби)
        tim.CCER = cfg.invert_direction ? (1U << 1) : 0U; // CC1P інвертує канал A

        // Встановлення режиму декодера в SMCR
        tim.SMCR = static_cast<uint32_t>(cfg.mode);

        tim.ARR = 0xFFFFU; // 16-бітний максимальний період
        tim.PSC = 0;
        tim.CNT = 0;

        tim.CR1 |= (1U << 0); // Старт таймера (CEN = 1)
        last_cnt_ = static_cast<uint16_t>(tim.CNT);
    }

    void init_filter(float cutoff_hz) noexcept {
        if (cutoff_hz > 0.0f) {
            const float rc = 1.0f / (2.0f * std::numbers::pi_v<float> * cutoff_hz);
            lpf_alpha_ = dt_ / (dt_ + rc);
        } else {
            lpf_alpha_ = 1.0f;
        }
    }

    uint32_t counts_per_rev_{4096};
    float dt_{0.001f};
    float lpf_alpha_{1.0f};
    uint16_t last_cnt_{0};
    int64_t total_position_{0};
    float velocity_rad_s_{0.0f};
    std::atomic<EncoderSnapshot> snapshot_{};
};
```

## Інженерний підсумок вибору та налаштування

Апаратний енкодерний режим перетворює периферійний таймер мікроконтролера на спеціалізований цифровий сопроцесор відстеження положення ротора.

| Критерій проектування | Програмне декодування (EXTI ISR) | Апаратний енкодерний режим таймера |
|---|---|---|
| **Навантаження на CPU** | До 50–90% при високих швидкостях | **0% (повна апаратна автономність)** |
| **Максимальна частота імпульсів** | 50–200 кГц (обмежено часом входу в ISR) | **Повна частота шини таймера (до 50–150 МГц)** |
| **Стійкість до брязкоту контактів** | Потребує складних програмних таймаутів | **Апаратні цифрові фільтри ICxF (мажоритарна логіка)** |
| **Реакція на вібрацію на межі** | Ризик накопичення хибних інкрементів | **Абсолютне самоскасування коливань (+1/−1)** |
| **Апаратне визначення напрямку** | Програмний аналіз сусіднього піна в ISR | **Миттєве апаратне перемикання біта DIR** |
| **Множення роздільності** | Складне ручне розгалуження в коді | **Режими X1, X2, X4 вибором бітів SMCR.SMS** |

Завдяки повній ізоляції від процесорного ядра апаратний декодер усуває будь-який ризик втрати імпульсів через затримки переривань чи виконання критичних секцій у сусідніх модулях прошивки, гарантуючи детерміноване та математично точне позиціонування у робототехніці та системах автоматизованого електроприводу.
