# 📋 Довідник листків та бітових прапорців інструкції CPUID

Інструкція `CPUID` (опкод `0F A2`) є основним апаратним інтерфейсом інтроспекції архітектури x86/x86-64. Вона виконується на будь-якому рівні привілеїв ([кільця 0–3](root:hw-arch/protection-rings)), не викликає виключень захисту пам'яті й зчитує конфігурацію кремнію безпосередньо з апаратної логіки та таблиць мікрокоду процесора.

Цей довідник містить повну специфікацію вхідних регістрів, розкладку полів вихідних регістрів, формули обчислення параметрів та бітові маски архітектурних розширень для всіх ключових листків (leaves) та підлистків (sub-leaves).

## Загальний контракт виклику

Перед виконанням команди `CPUID` програма завантажує номер потрібного листка в регістр `EAX`, а за необхідності вибору підлистка (наприклад, для перебору рівнів кешу чи таблиць розширених функцій) — номер підлистка в регістр `ECX`.

Усі 64-бітні регістри `RAX`, `RBX`, `RCX`, `RDX` у 64-бітному режимі автоматично обнуляють свої старші 32 біти. Вихідні дані завжди повертаються у вигляді чотирьох 32-бітних значень.

```
Вхід:
  EAX = Номер листка (Function / Leaf)
  ECX = Номер підлистка (Sub-leaf / Sub-function, за замовчуванням 0)

Вихід:
  EAX, EBX, ECX, EDX = 32-бітні значення конфігурації
```

## Листок 0x00000000: Максимальний базовий листок та рядок виробника

Використовується для визначення доступного діапазону стандартних функцій та ідентифікації виробника процесора.

* **Вхід:** `EAX = 0x00000000`
* **Вихідні регістри:**
  * `EAX`: Максимальний підтримуваний номер базового листка (наприклад, `0x00000020` для сучасних ядер).
  * `EBX`: Перші 4 байти ASCII-рядка виробника (символи 0..3).
  * `EDX`: Наступні 4 байти ASCII-рядка виробника (символи 4..7).
  * `ECX`: Останні 4 байти ASCII-рядка виробника (символи 8..11).

*Порядок зчитування:* символи формуються в послідовності `EBX` → `EDX` → `ECX` у порядку little-endian.

## Листок 0x00000001: Сигнатура процесора та базові прапорці можливостей

* **Вхід:** `EAX = 0x00000001`
* **Вихід `EAX` — Сигнатура процесора (Family / Model / Stepping):**

```
 31      28 27        20 19      16 15 14 13 12 11       8 7      4 3       0
┌──────────┬────────────┬──────────┬─────┬─────┬──────────┬────────┬────────┐
│ Зарезерв │ Ext Family │Ext Model │Typ  │0  0 │BaseFamily│BaseMod │Stepping│
└──────────┴────────────┴──────────┴─────┴─────┴──────────┴────────┴────────┘
```

Обчислення підсумкового сімейства та моделі виконується за стандартизованими формулами:

```
Stepping ID = EAX[3:0]
Base Model  = EAX[7:4]
Base Family = EAX[11:8]
Type        = EAX[13:12]
Ext Model   = EAX[19:16]
Ext Family  = EAX[27:20]

Підсумкове Family:
  Якщо Base Family ≠ 15:
    Display Family = Base Family
  Якщо Base Family = 15:
    Display Family = Base Family + Ext Family

Підсумкова Model:
  Якщо Base Family ∈ {6, 15}:
    Display Model = (Ext Model << 4) | Base Model
  Інакше:
    Display Model = Base Model
```

## Листок 0x00000004: Детерміновані параметри топології кеш-пам'яті

Цей листок повертає детальну геометрію кешів процесора (L1 Instruction, L1 Data, L2, L3). Конкретний рівень кешу обирається передачею індексу в регістр `ECX` (`ECX = 0, 1, 2, 3...`), доки `EAX[4:0]` не поверне `0` (кеш відсутній).

* **Вхід:** `EAX = 0x00000004`, `ECX = Cache Index`
* **Вихід `EAX`:**
  * Біти `4:0` — Тип кешу (`0` = немає, `1` = Data, `2` = Instruction, `3` = Unified).
  * Біти `7:5` — Рівень кешу (`1` = L1, `2` = L2, `3` = L3).
  * Біти `25:14` — Максимальна кількість логічних ядер, що ділять цей кеш (`+ 1`).
  * Біти `31:26` — Максимальна кількість ядер у фізичному сокеті (`+ 1`).
* **Вихід `EBX` — Розбиття рядка та секцій:**
  * Біти `11:0` — Розмір рядка когерентності (Line Size) у байтах: `(EBX[11:0] + 1)`.
  * Біти `21:12` — Кількість фізичних секцій рядка: `(EBX[21:12] + 1)`.
  * Біти `31:22` — Асоціативність кешу (Ways of Associativity): `(EBX[31:22] + 1)`.
* **Вихід `ECX`:** Кількість наборів кешу (Sets): `(ECX + 1)`.
* **Формула підсумкового розміру кешу:**

```
Розмір кешу (байти) = (Ways + 1) · (Partitions + 1) · (LineSize + 1) · (Sets + 1)
```

## Листок 0x00000006: Керування живленням та термальні сенсори

* **Вхід:** `EAX = 0x00000006`
* **Вихідні регістри:**
  * `EAX[0]`: Цифровий термальний сенсор (Digital Thermal Sensor / DTS);
  * `EAX[1]`: Технологія Intel Turbo Boost;
  * `EAX[2]`: Зворотний зв'язок апаратної координації (ARAT / APERF/MPERF MSRs);
  * `EAX[7]`: Апаратне керування продуктивністю HWP (Hardware-Controlled Performance States / Intel Speed Shift);
  * `EAX[8]`: Сповіщення HWP про зміну стану (HWP Notification);
  * `EAX[9]`: Керування активністю HWP Activity Window;
  * `EAX[10]`: Оптимізація енергоспоживання HWP Energy Performance Preference.

| 24 | `AMX_TILE` | Архітектура 2D-матричних регістрів (Tiles) |
| 25 | `AMX_INT8` | Матричне множення 8-бітних цілих чисел |
| 26 | `SPEC_CTRL` | Апаратні засоби захисту від Spectre: `IBRS` (Indirect Branch Restricted Speculation) та `IBPB` |
| 27 | `STIBP` | Захист непрямих переходів у гіперпотоках Single Thread Indirect Branch Predictors |
| 28 | `L1D_FLUSH` | Інструкція повного скидання L1 Data кешу при перемиканні контексту |
| 29 | `ARCH_CAPABILITIES`| Наявність регістра `IA32_ARCH_CAPABILITIES` (де процесор звітує про апаратну неуразливість до Meltdown/MDS) |
| 31 | `SSBD` | Спекулятивний бар'єр обходу збереження Speculative Store Bypass Disable |

### Підлисток ECX = 1: Новітні інструкції та розширення

* **Вхід:** `EAX = 0x00000007`, `ECX = 1`
* **Вихід `EAX`:**
  * Біт 4 — `AVX_VNNI`: 256-бітні нейромережеві інструкції VNNI на регістрах YMM;
  * Біт 5 — `AVX512_BF16`: Векторна арифметика формату bfloat16 для AVX-512;
  * Біт 7 — `CMPCCXADD`: Атомарне умовне додавання `CMPccXADD`;
  * Біт 21 — `AMX_FP16`: Матричні операції з числами половинної точності float16;
  * Біт 22 — `PREFETCHI`: Інструкції попередньої вибірки коду в кеш інструкцій;
  * Біт 23 — `AVX_IFMA`: 256-бітні інструкції множення-додавання з 52-бітною точністю.

## Листок 0x0000000A: Моніторинг продуктивності (Architectural Performance Monitoring)

Використовується системними профилювальниками (`perf`, VTune) для виявлення апаратних лічильників подій PMU.

* **Вхід:** `EAX = 0x0000000A`
* **Вихідні регістри:**
  * `EAX[7:0]`: Версія архітектурного PMU (наприклад, Version 4 або Version 5);
  * `EAX[15:8]`: Кількість лічильників продуктивності загального призначення на ядро;
  * `EAX[23:16]`: Розрядність лічильників продуктивності в бітах (зазвичай 48 бітів);
  * `EDX[4:0]`: Кількість фіксованих апаратних лічильників (Fixed Counters: Instructions Retired, Unhalted Core Cycles, Unhalted Reference Cycles);
  * `EDX[12:5]`: Розрядність фіксованих лічильників у бітах.

---

## Листок 0x0000000B та 0x0000001F: Розширена топологія процесора (x2APIC Topology)

Ці листки дозволяють операційній системі однозначно побудувати дерево апаратних потоків, ядер, кластерів (Tiles/Modules) та фізичних сокетів.

* **Вхід:** `EAX = 0x0000001F` (або `0x0000000B`), `ECX = Level Number (0, 1, 2...)`
* **Вихідні регістри:**
  * `EAX[4:0]`: Кількість бітів зсуву в APIC ID для переходу на наступний рівень ієрархії;
  * `EBX[15:0]`: Кількість логічних процесорів на поточному рівні ієрархії;
  * `ECX[7:0]`: Номер поточного рівня (`ECX_in`);
  * `ECX[15:8]`: Тип рівня (`1` = SMT/Hyper-Threading, `2` = Core, `3` = Module, `4` = Tile, `5` = Die, `6` = Package);
  * `EDX`: 32-бітний x2APIC ID поточного логічного процесора.

---

## Листок 0x0000000D: Розширений стан процесора (XSAVE / XCR0)

Цей листок описує розмір та структуру пам'яті для інструкцій збереження стану `XSAVE`/`XRSTOR`.

* **Підлисток `ECX = 0`:**
  * `EAX`: Бітова маска молодших 32 бітів `XCR0` (підтримувані компоненти: біт 0 = x87, біт 1 = SSE, біт 2 = AVX, біти 5..7 = AVX-512).
  * `EBX`: Розмір області пам'яті в байтах для збереження всіх увімкнених у `XCR0` компонентів.
  * `ECX`: Максимальний розмір області пам'яті в байтах для збереження абсолютно всіх підтримуваних кристалом компонентів.
  * `EDX`: Бітова маска старших 32 бітів `XCR0`.
* **Підлисток `ECX = 1`:**
  * `EAX[0]`: Підтримка оптимізованої інструкції `XSAVEOPT`.
  * `EAX[1]`: Підтримка компактного збереження `XSAVEC`.
  * `EAX[3]`: Підтримка збереження стану супервізора `XSAVES`.

---

## Розширений діапазон: 0x80000000 – 0x80000028

Цей простір листків, спочатку розроблений AMD і стандартизований для всієї екосистеми x86-64, містить інформацію про 64-бітний режим, фізичну пам'ять і текстове ім'я процесора.

### Листок 0x80000000: Максимальний розширений листок
* **Вхід:** `EAX = 0x80000000`
* **Вихід `EAX`:** Максимальний доступний номер розширеного листка (наприклад, `0x80000028`).

### Листок 0x80000001: Розширені сигнатури та прапорці
* **Вхід:** `EAX = 0x80000001`
* **Вихід `EDX`:**
  * Біт 11 — `SYSCALL`: Підтримка швидких системних викликів `SYSCALL`/`SYSRET` у 64-бітному режимі.
  * Біт 20 — `NX` (No-Execute / Execute-Disable `XD`): Апаратний біт заборони виконання даних у таблицях сторінок.
  * Біт 26 — `Page1GB`: Підтримка гігабайтних сторінок пам'яті (1 GB Huge Pages).
  * Біт 27 — `RDTSCP`: Інструкція атомарного зчитування TSC та ідентифікатора процесора `RDTSCP`.
  * Біт 29 — `LM` (Long Mode): Повноцінна 64-бітна архітектура x86-64.

### Листки 0x80000002, 0x80000003, 0x80000004: Повна назва процесора (Brand String)
Три листки поспіль повертають текстову назву процесора у форматі ASCII загальною довжиною 48 байтів (по 16 байтів на кожен листок, по 4 байти в регістрах `EAX`, `EBX`, `ECX`, `EDX`).

```
Листок 0x80000002 -> Байти 0..15  назви
Листок 0x80000003 -> Байти 16..31 назви
Листок 0x80000004 -> Байти 32..47 назви
Приклад результату: "AMD Ryzen 9 5950X 16-Core Processor            "
```

### Листок 0x80000007: Керування живленням та Invariant TSC
* **Вхід:** `EAX = 0x80000007`
* **Вихід `EDX[8]` — `Invariant TSC` (Non-stop TSC):** Гарантує, що лічильник тактів `RDTSC` цокає з постійною частотою незалежно від зміни частоти ядер через енергозбереження ([DVFS](root:hw-arch/dvfs)) чи переходів у глибокі стани сну (C-states).

### Листок 0x80000008: Обмеження адресного простору
* **Вхід:** `EAX = 0x80000008`
* **Вихід `EAX`:**
  * Біти `7:0` — Максимальна ширина фізичної адреси в бітах (наприклад, 48 бітів = 256 ТБ фізичної RAM);
  * Біти `15:8` — Максимальна ширина віртуальної адреси в бітах (зазвичай 48 бітів для 4-рівневих таблиць або 57 бітів для 5-рівневих сторінок PML5).

### Листок 0x8000001F: Апаратне шифрування пам'яті AMD SEV / SME
* **Вхід:** `EAX = 0x8000001F`
* **Вихідні регістри:**
  * `EAX[0]`: Апаратне прозоре шифрування оперативної пам'яті Secure Memory Encryption (SME);
  * `EAX[1]`: Апаратне шифрування пам'яті віртуальних машин Secure Encrypted Virtualization (SEV);
  * `EAX[3]`: Захищений стан регістрів віртуальної машини SEV-ES (Encrypted State);
  * `EAX[4]`: Захист пам'яті від підміни гіпервізором SEV-SNP (Secure Nested Paging);
  * `EBX[5:0]`: Позиція біта шифрування (C-bit) у записах сторінок пам'яті (зазвичай біт 47 або 51).

## Діапазон віртуалізації гіпервізорів: 0x40000000 – 0x400000FF

Якщо у Листку `0x00000001` біт `ECX[31]` встановлено в `1`, система виконується всередині віртуальної машини, а діапазон `0x40000000`..`0x400000FF` повертає ідентифікатор гіпервізора та його паравіртуальні інтерфейси.

* **Вхід:** `EAX = 0x40000000`
* **Вихід `EBX`, `ECX`, `EDX` — 12-символьний ASCII-ідентифікатор гіпервізора:**
  * `"KVMKVMKVM\0\0\0"` — Linux KVM
  * `"Microsoft Hv"` — Microsoft Hyper-V
  * `"VMwareVMware"` — VMware ESXi / Workstation
  * `"XenVMMXenVMM"` — Xen Hypervisor
  * `"bhyve bhyve "` — FreeBSD bhyve
  * `"TCGTCGTCGTCG"` — Емулятор QEMU TCG (без апаратної віртуалізації KVM)
