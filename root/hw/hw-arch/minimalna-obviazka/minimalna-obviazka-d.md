- [Brown-out](root:hw-arch/brownout) — фізика просідання напруги живлення, сіра зона логіки та апаратний захист.

</preknowlist>

Коли розробник створює власну друковану плату й розпаює на ній новий «голий» мікроконтролер, перше подання живлення часто закінчується мовчанням: відладчик видає помилку «Cannot connect to target», споживання струму хаотично коливається, а на лініях вводу-виводу спостерігається високочастотний дзвін. Поширена помилка початківців — вважати мікроконтролер закінченим чорним ящиком, якому для роботи достатньо подати два дроти живлення. Кремнієвий кристал із мільйонами польових транзисторів не має внутрішніх джерел стабільності: без належного зовнішнього оточення він потрапляє в стан невизначеності.

Набір зовнішніх пасивних і комутаційних компонентів, що переводять мікроконтролер із хаотичного кремнію в детерміновану обчислювальну систему, називається **мінімальною обв'язкою** (англ. *minimum essential circuitry*, *minimal breakout*). Вона охоплює п'ять обов'язкових апаратних підсистем: розподіл та високочастотне блокування шин живлення, ланцюг надійного апаратного скидання, схему конфігурації завантаження (strapping-піни), тактовий генератор на базі п'єзорезонаторів та інтерфейс внутрішньосхемного програмування й налагодження.

### Підсистема живлення: від стабілізатора до кремнієвого кристала

КМОН-логіка (англ. *CMOS*, комплементарна структура метал-оксид-напівпровідник) мікропроцесорного ядра у статичному стані споживає мізерний струм витоку (мікроампери). Проте в момент перемикання логічного вентиля з «0» в «1» обидва транзистори плеча на частки наносекунди відкриваються одночасно (наскрізний струм короткого замикання), а вихідна ємність затворів наступних каскадів заряджається:

```
I_peak = C_load · (dV / dt)
```

Коли на тактовій частоті 100 МГц одночасно перемикаються десятки тисяч внутрішніх вентилів ядра та 32-розрядні магістралі шини даних, споживання струму кристала вистрілює імпульсами амплітудою в сотні міліампер і тривалістю фронту `dt = 1–2 нс`. 

Швидкість наростання струму досягає екстремальних величин:

```
di / dt = 0.5 А / (2 · 10^-9 с) = 2.5 · 10^8 А/с
```

Кожна друкована доріжка на платі має власну розподілену паразитну індуктивність (типово `L_trace ≈ 1 нГн/мм`), а внутрішні зварні золоті мікродротики від кристала до ніжки корпусу мікросхеми додають ще `L_lead ≈ 2–4 нГн`. За законом Фарадея зміна струму на індуктивності викликає імпульсне падіння напруги:

```
V_drop = L · (di / dt)
```

Якщо конденсатор живлення стоїть на відстані 20 мм від виводу мікроконтролера, індуктивність петлі живлення становить близько `L = 20 нГн`. Падіння напруги в момент фронту тактового сигналу сягне:

```
V_drop = (20 · 10^-9 Гн) · (2.5 · 10^8 А/с) = 5.0 В
```

Такий стрибок повністю знищує напругу живлення 3.3 В, заганяючи чіп у глибокий [brown-out](root:hw-arch/brownout) або скидаючи стан тригерів конвеєра інструкцій.

![Архітектура розподілу живлення та декаплінгу мікроконтролера](/root/hw/hw-arch/minimalna-obviazka/img/power-and-decoupling.svg)
*Ієрархія шин живлення: резервуарний конденсатор, локальні MLCC біля кожної пари VDD/VSS, фільтрація аналогового домену VDDA та стабілізація регулятора VCAP.*

Для подолання цієї фізичної межі розгортають трирівневу ієрархію розв'язки (англ. *decoupling*):

1. **Вхідний резервуарний конденсатор (Bulk Capacitor):** танталовий або керамічний конденсатор ємністю 4.7–10 мкФ (класу X7R/X5R, типорозміру 0805 або 1206), розташований на вході живлення друкованої плати після лінійного стабілізатора (LDO). Він діє як локальне джерело енергії для компенсації повільних коливань навантаження в діапазоні від одиниць кілогерців до 1 МГц, де далеке джерело живлення не встигає зреагувати через індуктивність підвідних дротів.
2. **Локальні високочастотні блокувальні конденсатори:** керамічні багатошарові конденсатори (MLCC, англ. *Multi-Layer Ceramic Capacitor*) номіналом 100 нФ (0.1 мкФ) типорозміру 0402 або 0603. **Суворе правило схемотехніки:** один конденсатор 100 нФ встановлюється на **кожну** пару виводів `VDD / VSS` мікроконтролера. Якщо мікроконтролер у корпусі LQFP64 має чотири виводи `VDD`, на платі повинно стояти рівно чотири окремих конденсатори по 100 нФ. Один спільний конденсатор на весь корпус не працює, оскільки кожен вивід живить свій внутрішній фізичний сектор кристала.
3. **Правило трасування розв'язки:** провідник живлення від джерела повинен спершу проходити через контактну площадку SMD-конденсатора, і лише потім заходити на вивід мікроконтролера. Вивід землі конденсатора з'єднується з внутрішнім суцільним полігоном `GND` за допомогою перехідного отвору (via), розміщеного безпосередньо біля площадки (відстань < 1 мм), що мінімізує площу замкненого високочастотного контуру струму.

#### Ізоляція аналогового домену (VDDA та VSSA)

Мікроконтролери з вбудованими аналого-цифровими перетворювачами (SAR ADC), компараторами та фазовими детекторами PLL мають виділені виводи живлення `VDDA` та аналогової землі `VSSA`. Якщо живити `VDDA` прямо від цифрової шини `VDD`, комутаційний шум амплітудою 30–100 мВ модулюватиме опорну напругу АЦП, спотворюючи вимірювання датчиків на 4–6 молодших розрядів.

Для чистого живлення аналогового вузла формують П-подібний фільтр низьких частот:
* Послідовно в шину вмикається **феритова бусина** (англ. *Ferrite Bead*) з імпедансом `Z = 60–120 Ом` на частоті 100 МГц та активним опором постійному струму `R_dc < 0.1 Ом`. Бусина не пропускає високочастотний шум, перетворюючи його на тепло у феритовому осерді.
* Після бусини паралельно виводу `VDDA` встановлюється пара конденсаторів: керамічний 1 мкФ (накопичувач струму вибірки АЦП) та високочастотний керамічний 10 нФ (діелектрик C0G/NP0 для фільтрації шуму вище 50 МГц).
* Аналогова земля `VSSA` підключається до загальної цифрової землі `VSS` в єдиній точці — безпосередньо під мікроконтролером, або через нульовий резистор (англ. *0-ohm link*), щоб уникнути протікання зворотних струмів цифрової логіки через чутливий аналоговий шар.

> 🔌 Повний інженерний аналіз імпедансних характеристик феритових бусин, усунення LC-антирезонансу та підбір фільтрів розібрано у вставці [Фільтрація живлення: феритові бусини, LC-ланки та VCAP-декаплінг](root:hw-arch/minimalna-obviazka/comp-decoupling-ferrite-filter.md).

#### Внутрішній регулятор ядра (VCAP / VCORE)

Сучасні 32-бітні ядра ARM Cortex-M4/M7 працюють не від 3.3 В, а від низької напруги ядра `VCORE = 1.2 В` або `1.8 В`, що генерується внутрішнім вбудованим LDO-стабілізатором для зниження динамічного нагріву. 

Виводи `VCAP_1` та `VCAP_2` (наприклад, у сімействах STM32F4/F7) виведені назовні виключно для підключення зовнішніх стабілізуючих конденсаторів зворотного зв'язку LDO. Сюди підключають низькоіндуктивні керамічні конденсатори ємністю **2.2 мкФ** (або 4.7 мкФ) з еквівалентним послідовним опором `ESR < 1 Ом`. Якщо розробник забуде розпаяти ємності на виводах `VCAP`, внутрішній стабілізатор ядра втратить стійкість, звалиться в автогенерацію, і мікроконтролер не зможе виконати жодної інструкції.

> 🔧 **Навіщо це.** Нехтування правилом «100 нФ на кожен пін VDD» — головна причина плаваючих помилок на виробництві. Плата може стабільно проходити короткі тести на столі інженера при кімнатній температурі, але почне хаотично скидатися або втрачати пакети в польових умовах, щойно підніметься температура або одночасно увімкнуться кілька периферійних модулів (SPI Flash, таймери ШІМ та обчислення алгоритмів FPU).

### Ланцюг апаратного скидання (NRST)

Лінія `NRST` (англ. *Negative Reset*) — це асинхронний вхід апаратного скидання процесора з активним низьким рівнем (Active-Low). Поки на виводі `NRST` утримується логічний нуль (напруга нижче порога спрацьовування внутрішнього тригера Шмітта `V_IL ≈ 0.3 · VDD`), обчислювальне ядро зупинене, лічильник команд `PC` (Program Counter) заблокований, а всі регістри периферії скинуті до заводських станів.

Щойно напруга на `NRST` піднімається вище порога `V_IH ≈ 0.7 · VDD`, мікроконтролер починає послідовність апаратного запуску: зчитує початкову адресу верхівки стека з комірки пам'яті `0x00000000` та адресу вектора скидання `Reset_Handler` з комірки `0x00000004`.

![Схеми ланцюга скидання NRST та конфігурації boot-пінів](/root/hw/hw-arch/minimalna-obviazka/img/reset-and-boot-circuit.svg)
*Схемотехніка вузла скидання: інтегрований pull-up, зовнішній RC-фільтр завад, тактова кнопка та strapping-резистори вибору режиму BOOT.*

#### Фізика запуску та фільтрація перешкод

Усередині мікроконтролера вивід `NRST` уже підтягнутий до внутрішньої шини `VDD` через слабкий резистор підтяжки (англ. *internal pull-up*):

```
R_PU ≈ 30–50 кОм (типово 40 кОм)
```

Однак залишати вивід `NRST` відкритим або підключеним лише довгою доріжкою до кнопки категорично заборонено. Довга друкована доріжка скидання працює як рамкова антена: електромагнітні завади від комутації індуктивних навантажень (реле, електромотори), статичні розряди ESD або високочастотне радіовипромінювання наводять у лінії імпульси напруги. Оскільки опір підтяжки `40 кОм` є відносно високоомним, навіть незначний наведений струм величиною `80 мкА` просаджує напругу лінії:

```
ΔV = 80 мкА · 40 кОм = 3.2 В
```

Це викликає миттєве хибне перезавантаження процесора.

Для надійного захисту паралельно виводу `NRST` на землю встановлюють зовнішній керамічний конденсатор:

```
C_NRST = 100 нФ
```

Цей конденсатор вирішує два критичних завдання:
1. **Фільтрація високочастотних перешкод:** для швидких наведених завад імпеданс конденсатора `X_C = 1 / (2·π·f·C)` прямує до нуля, надійно закорочуючи сплески на землю.
2. **Формування часової затримки Power-On Reset (POR):** у момент первинної подачі живлення напруга на шині `VDD` наростає поступово через перехідні процеси стабілізатора. Конденсатор `C_NRST` заряджається через резистор підтяжки `R_PU` з постійною часу:

```
τ = R_PU · C_NRST = 40 кОм · 100 нФ = 4.0 мс
```

Завдяки цьому лінія `NRST` утримується в стані логічного нуля протягом перших кількох мілісекунд, доки напруга живлення `VDD` гарантовано не вийде на стабільний номінальний рівень `3.3 В` і не завершаться перехідні процеси у внутрішніх генераторах зміщення кристала.

#### Підключення кнопки скидання та лінія відладчика

Тактова кнопка скидання (Manual Reset Button) підключається паралельно конденсатору `C_NRST` безпосередньо на землю. При натисканні контакти замикають лінію на нуль, викликаючи миттєвий розряд ємності. Для захисту контактів кнопки від ерозії великим струмом розряду розрядженого конденсатора в професійних схемах послідовно з кнопкою іноді ставлять резистор 10–47 Ом, хоча для ємності 100 нФ енергія розряду є безпечною:

```
E = (C · V^2) / 2 = (100 · 10^-9 Ф · 3.3^2 В^2) / 2 ≈ 0.54 мкДж
```

Лінія `NRST` також виводиться на рознім відладчика SWD. Інтерфейс програматора керує цією лінією через транзистор із **відкритим стоком** (Open-Drain), що дозволяє програматору примусово скидати мікроконтролер у будь-який момент часу, не входячи у конфлікт із зовнішньою кнопкою скидання.

### Конфігурація режиму завантаження (Boot Pins / Strapping)

Під час апаратного скидання внутрішній завантажувальний автомат процесора (Boot Sequencer) опитує логічні рівні на спеціальних конфігураційних виводах — **strapping-пінах** (англ. *strapping pins*, виводи конфігурації засувки). Фіксація стану пінів відбувається апаратно в момент зняття сигналу скидання (наростаючий фронт на `NRST`), після чого ці виводи можуть використовуватися як звичайні порти вводу-виводу GPIO.

У сімействі ARM Cortex-M (зокрема STM32) режим старту задається комбінацією рівнів на пінах `BOOT0` та `BOOT1` (який часто суміщений із піном `PB2` або конфігурується через Flash Option Bytes):

| Стан BOOT0 | Стан BOOT1 | Джерело завантаження (Boot Source) | Фізична адреса відображення | Призначення та застосування |
| :--- | :--- | :--- | :--- | :--- |
| **0** | **X** (будь-який) | **Main Flash Memory** | `0x08000000` | **Штатний режим.** Виконання користувацької програми, прошитої у внутрішню енергонезалежну пам'ять Flash. |
| **1** | **0** | **System Memory (ROM Bootloader)** | `0x1FFF0000` (або `0x1FFFF000`) | **Сервісний режим.** Запуск заводського незмінного завантажувача з маскового ROM для прошивки через UART, USB DFU, CAN, I2C. |
| **1** | **1** | **Embedded SRAM** | `0x20000000` | **Тестовий режим.** Запуск коду безпосередньо з оперативної пам'яті. Дозволяє тестувати прошивку без зносу ресурсу запису Flash. |

#### Схемотехнічні вимоги до піна BOOT0

Вивід `BOOT0` не має внутрішнього стійкого зміщення на деяких кристалах або має надто слабкий pull-down. **Найгрубша помилка розробника плати — залишити пін `BOOT0` плаваючим у повітрі (NC — Not Connected).** 

Високоомний високочутливий вхід за рахунок паразитної ємності та наведеного статичного потенціалу при кожному включенні довільно зчитуватиметься як «0» або «1». У результаті пристрій один раз запускатиме прошивку, а наступного разу несподівано зависатиме у системному завантажувачі, прикидаючись «мертвим» для користувача.

Схемотехнічна реалізація вузла BOOT:
1. Вивід `BOOT0` **завжди** підтягують до землі `GND` через зовнішній резистор:
   ```
   R_BOOT0 = 10 кОм
   ```
2. Для забезпечення можливості аварійного відновлення або оновлення прошивки по USB/UART на платі встановлюють 3-контактний рознім із джампером (крок 2.54 мм) або мікроперемикач:
   * Положення джампера `1-2` замикає `BOOT0` на `GND` (Штатний запуск із Flash).
   * Положення джампера `2-3` підтягує `BOOT0` до шини `3.3 В VDD` (Вхід у режим прошивки System Bootloader).
3. Пін `BOOT1` (`PB2`), якщо він використовується, аналогічно підтягують до землі резистором `10 кОм`.

### Тактові генератори: розведення кварців HSE та LSE

Мікроконтролер має вбудований внутрішній RC-генератор (HSI, англ. *High-Speed Internal*, зазвичай 8 або 16 МГц). Внутрішній RC-генератор дозволяє запустити ядро без жодної зовнішньої деталі, проте його частота зазнає сильного температурного дрейфу й технологічного розкиду (похибка становить `±1% ... ±2.5%`).

Цієї стабільності достатньо для виконання коду, але вона категорично непридатна для:
* Інтерфейсу USB 2.0 Full-Speed (потрібна апаратна точність частоти `±0.25%`);
* Швидкісних шин CAN / CAN-FD на довгих лініях зв'язку (похибка повинна бути `< 1.0%`);
* UART на високих швидкостях (115200 бод, 921600 бод) при зміні температури від -40°C до +85°C;
* Календарного відліку точного часу (RTC) — похибка RC-генератора дасть відхилення годинника на десятки хвилин щодня.

Для стабільного тачного ритму застосовують зовнішні кварцові резонатори: високочастотний **HSE** (англ. *High-Speed External*, 8–25 МГц) та годинниковий **LSE** (англ. *Low-Speed External*, 32.768 кГц).

![Трасування тактових генераторів та захисне земляне кільце Guard Ring](/root/hw/hw-arch/minimalna-obviazka/img/crystal-oscillator-layout.svg)
*Схема генератора П'єрса, навантажувальні конденсатори C1/C2 та правила топології на друкованій платі із захисним кільцем Guard Ring.*

#### Високочастотний генератор HSE (8–25 МГц)

Внутрішня схема мікроконтролера між виводами `OSC_IN` та `OSC_OUT` являє собою інвертуючий CMOS-підсилювач, охоплений негативним зворотним зв'язком через внутрішній резистор `R_F ≈ 1 МОм` (генератор П'єрса). Зовнішній кварцовий резонатор працює як високодобротна індуктивність у вузькій смузі паралельного резонансу, створюючи разом із навантажувальними конденсаторами `C_1` та `C_2` фазовий зсув на 180°, необхідний для виникнення стійких автоколивань.

Розрахунок навантажувальних конденсаторів `C_1, C_2` виконується за паспортом резонатора (`C_L`, зазвичай 12–18 пФ) з урахуванням паразитної ємності монтажу й виводів `C_s ≈ 3–5 пФ`:

```
C_1 = C_2 = 2 · (C_L - C_s)
```

Для кварцу 8.000 МГц із паспортом `C_L = 16 пФ` при `C_s = 4 пФ`:

```
C_1 = C_2 = 2 · (16 пФ - 4 пФ) = 24 пФ
```

Обирають найближчий номінал керамічних конденсаторів 22 пФ або 24 пФ виключно з діелектриком класу **C0G (NP0)**, що не змінює ємність при коливаннях температури.

Для захисту малопотужних кварців від механічного перевантаження струмом збудження (Drive Level) послідовно у вивід `OSC_OUT` додають демпфуючий резистор `R_ext = 100–330 Ом`.

#### Годинниковий генератор LSE (32.768 кГц)

Резонатор на 32.768 кГц (частота `2^15 Гц`, що зручно ділиться 15-розрядним двійковим лічильником рівно до 1 Гц) виконується у вигляді мініатюрного камертона (англ. *tuning fork crystal*). 

Головна особливість генератора LSE — екстремально низьке споживання енергії (менше 1 мкА для тривалої роботи від батарейки `CR2032` на виводі `VBAT`). Зворотний бік ультранизького струму — дуже високий еквівалентний опір резонатора (`ESR = 40–80 кОм`) та надзвичайно слабкий вихідний струм збудження. Генератор LSE легко зривається від найменшого витоку струму або наведень від сусідніх цифрових ліній. 

Конденсатори для LSE обирають з меншою ємністю (типово `C_1 = C_2 = 10–15 пФ` для кварців із `C_L = 6–9 пФ`).

> 🧮 Повний математичний вивід формул навантажувальної ємності, розрахунок рівня збудження (Drive Level) та формулу запасу генерації (Gain Margin) наведено у вставці [Розрахунок навантажувальних ємностей і стійкості генератора П'єрса](root:hw-arch/minimalna-obviazka/math-crystal-load-capacitance.md).

#### Топологічні правила розведення кварцових резонаторів на друкованій платі

1. **Мінімальна довжина трас:** кварц та його конденсатори розташовують максимально близько до виводів мікроконтролера (довжина провідників не більше 5–8 мм).
2. **Захисне земляне кільце (Guard Ring):** навколо кварцу, виводів і конденсаторів на верхньому шарі плати прокладають суцільну доріжку землі `GND`, яка екранує чутливий вузол від бокових поверхневих наведень. Кільце з'єднують із загальним земляним шаром в єдиній точці.
3. **Заборона сигнальних трас під кварцом (Keep-out Zone):** на всіх внутрішніх та нижніх шарах плати безпосередньо під площею кварцового генератора заборонено прокладати будь-які цифрові сигнальні лінії (особливо шини ШІМ, SPI, I2C, тактові лінії). Під кварцом повинен бути монолітний, нерозрізаний екран землі `GND`.
4. **Симетрія:** траси `OSC_IN` та `OSC_OUT` повинні бути симетричними за довжиною та шириною для збереження фазового балансу генератора.

### Інтерфейси налагодження SWD та JTAG

Для прошивки Flash-пам'яті, покрокового виконання коду та читання регістрів ядра ARM Cortex-M використовують інтерфейси апаратного налагодження. Історичний стандарт **JTAG** (англ. *Joint Test Action Group*, стандарт IEEE 1149.1) вимагає 5 сигнальних ліній (`TDI`, `TDO`, `TMS`, `TCK`, `TRST`), що займає забагато виводів на компактних мікроконтролерах.

Корпорація ARM розробила альтернативний двопровідний інтерфейс **SWD** (англ. *Serial Wire Debug*), який повністю замінює JTAG у мікроконтролерах Cortex-M, забезпечуючи ту саму швидкість і функціональність лише по двох лініях:

1. **SWDIO (Serial Wire Data Input/Output):** двонаправлена лінія передачі даних із синхронізацією по фронтах. Усередині мікроконтролера пін має штатну підтяжку pull-up до `VDD` (`10–40 кОм`).
2. **SWCLK (Serial Wire Clock):** лінія тактування даних від програматора (частота від 500 кГц до 10 МГц). Усередині мікроконтролера має штатну підтяжку pull-down до `GND` (`10–40 кОм`), щоб лінія не пливла за відсутності підключеного кабелю.

![Інтерфейси відладки SWD та розпіновка діагностичних рознімів](/root/hw/hw-arch/minimalna-obviazka/img/swd-jtag-interface.svg)
*Апаратне з'єднання SWD: підключення ліній SWDIO/SWCLK з демпфуючими резисторами та стандарти рознімів Arm 10-pin і 4-pin SIL.*

#### Повний склад ліній розніму SWD

Для надійного програмування на плату виводять рознім із 4 або 5 контактів:

1. **VCC / VDD (Target Voltage Reference):** контакт підключається до шини живлення 3.3 В цільової плати. **Важливо:** через цей пін програматор (ST-LINK, J-Link, Black Magic Probe) вимірює рівень напруги плати, щоб налаштувати власні вихідні перетворювачі логічних рівнів (Level Shifters).
2. **SWDIO:** підключається до виводу `PA13` (STM32).
3. **SWCLK:** підключається до виводу `PA14` (STM32).
4. **GND:** спільний опорний нульовий провідник сигналу.
5. **NRST (опціонально, але критично важливо):** пін апаратного скидання.

#### Чому лінія NRST необхідна на рознімі відладчика

Багато плат-перехідників виводять лише 4 контакти: `VCC`, `SWDIO`, `SWCLK`, `GND`. Проте відсутність підключення лінії `NRST` призводить до фатальної пастки блокування мікроконтролера («Brick»):

Якщо в прошивці розробник припустився помилки — наприклад, переконфігурував піни `PA13/PA14` під звичайні GPIO або периферію, вимкнув тактування блоку відладки в регістрі RCC або перевів мікроконтролер у режим глибокого сну `Standby / Stop` у перші ж мікросекунди після запуску, — програмний відладчик більше не зможе встановити контакт із ядром через SWD.

Наявність фізичної лінії `NRST` на рознімі дозволяє програматору виконати апаратний протокол **Connect Under Reset**: відладчик примусово притискає `NRST` до землі, подає команду зупинки ядра по шині SWD ще до старту першої інструкції прошивки, і лише після цього знімає скидання, повертаючи контроль над заблокованим чіпом.

#### Захист ліній SWD

Для придушення високочастотного дзвону, викликаного паразитними ємностями кабелю програматора, та захисту внутрішніх буферів мікроконтролера від коротких замикань послідовно в лінії `SWDIO` та `SWCLK` безпосередньо біля розніму встановлюють демпфуючі резистори:

```
R_damp = 22–47 Ом
```

### Повна принципова схема мінімального вузла

Об'єднавши всі п'ять підсистем, отримуємо закінчену схему мінімального робочого обчислювального модуля (Minimal MCU Breakout):

![Повна принципова схема мінімального модуля ARM Cortex-M](/root/hw/hw-arch/minimalna-obviazka/img/mcu-minimal-breakout-schematic.svg)
*Консолідована принципова схема мінімального модуля: живлення з декаплінгом, NRST з RC-фільтром, BOOT-перемикач, кварци HSE/LSE та рознім SWD.*

#### Контрольний список першого включення (Power-up Checklist)

Перед першим підключенням зібраної друкованої плати до ПК виконують обов'язкову послідовність апаратного контролю:

1. **Контроль опору шини живлення (Омметр):** виміряти опір між шинами `VDD` та `GND` без підключеного живлення. Опір повинен становити від десятків кілоом до мегаомів. Опір менше 10–50 Ом вказує на коротке замикання (пробитий керамічний конденсатор, мікроперемичка припою під корпусом LQFP/QFN).
2. **Контроль напруги без МК (якщо чіп на панельці) або з обмеженням струму:** подати живлення від лабораторного джерела з виставленим обмеженням струму `I_limit = 50 мА`. Справний мінімальний модуль у режимі скидання споживає не більше 5–15 мА.
3. **Перевірка напруги ядра VCAP:** виміряти напругу на конденсаторах `VCAP_1 / VCAP_2`. Вона повинна стабільно триматися на рівні `1.20 В ± 0.05 В`. Якщо там 0 В або 3.3 В — внутрішній LDO несправний або замкнений.
4. **Перевірка постійної напруги на виводі NRST:** на піні скидання повинен бути стабільний високий рівень `3.3 В`. При натисканні на кнопку рівень повинен чітко падати до 0 В, а після відпускання — повертатися до 3.3 В без деренчання.
5. **Детектування програматором:** підключити відладчик SWD і виконати команду визначення ID ядра (`OpenOCD` або `STM32CubeProgrammer`). Відладчик повинен стабільно зчитувати значення Device ID (наприклад, `0x411` для STM32F411) та унікальний 96-бітний UID чіпа.

### Worked-приклад: Програмна верифікація апаратної обв'язки

Після апаратного старту перше завдання системної прошивки — перевірити стабільність зовнішнього кварцового генератора HSE. Якщо кварц пошкоджено, відсутні навантажувальні конденсатори або на платі з'явився мікротріск доріжки, спроба безальтернативного перемикання системного такту на несправний HSE намертво повісить мікроконтролер.

Нижче наведено алгоритм безпечної ініціалізації: ядро вмикає генератор HSE, запускає апаратний таймер очікування стабілізації (HSE Ready Timeout), і лише за умови підтвердження прапорця готовності перемикає системну шину на кварц і запускає систему захисту тактування **CSS** (англ. *Clock Security System*). Якщо кварц не запустився, система реєструє апаратну помилку та продовжує роботу на внутрішньому RC-генераторі HSI.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

/* Регістри підсистеми тактування RCC (Reset and Clock Control) для STM32 */
#define RCC_BASE            0x40023800U
#define RCC_CR              (*(volatile uint32_t *)(RCC_BASE + 0x00U))
#define RCC_CFGR            (*(volatile uint32_t *)(RCC_BASE + 0x08U))
#define RCC_CSR             (*(volatile uint32_t *)(RCC_BASE + 0x74U))

/* Бітові маски керування тактуванням */
#define RCC_CR_HSION        (1U << 0)
#define RCC_CR_HSIRDY       (1U << 1)
#define RCC_CR_HSEON        (1U << 16)
#define RCC_CR_HSERDY       (1U << 17)
#define RCC_CR_CSSON        (1U << 19)

#define RCC_CFGR_SW_HSI     (0x00U << 0)
#define RCC_CFGR_SW_HSE     (0x01U << 0)
#define RCC_CFGR_SWS_MASK   (0x03U << 2)
#define RCC_CFGR_SWS_HSE    (0x01U << 2)

#define RCC_CSR_RMVF        (1U << 24)
#define RCC_CSR_PORRSTF     (1U << 27)
#define RCC_CSR_PINRSTF     (1U << 26)

#define HSE_STARTUP_TIMEOUT 0x5000U

typedef enum {
    RESET_CAUSE_COLD_POWER_ON,
    RESET_CAUSE_EXTERNAL_PIN,
    RESET_CAUSE_OTHER
} reset_cause_t;

/* Діагностика причини скидання за апаратними прапорцями RCC_CSR */
reset_cause_t hardware_diagnose_reset_cause(void) {
    reset_cause_t cause = RESET_CAUSE_OTHER;
    uint32_t csr = RCC_CSR;

    if (csr & RCC_CSR_PORRSTF) {
        cause = RESET_CAUSE_COLD_POWER_ON;
    } else if (csr & RCC_CSR_PINRSTF) {
        cause = RESET_CAUSE_EXTERNAL_PIN;
    }

    /* Очищення прапорців скидання */
    RCC_CSR |= RCC_CSR_RMVF;
    return cause;
}

/* Безпечний запуск зовнішнього кварцового генератора HSE з fallback на HSI */
bool hardware_clock_init_hse(void) {
    uint32_t timeout = HSE_STARTUP_TIMEOUT;

    /* 1. Переконуємося, що внутрішній HSI активний */
    RCC_CR |= RCC_CR_HSION;
    while (!(RCC_CR & RCC_CR_HSIRDY)) {}

    /* 2. Подаємо сигнал запуску на генератор HSE */
    RCC_CR |= RCC_CR_HSEON;

    /* 3. Очікуємо стабілізації амплітуди коливань резонатора */
    while (!(RCC_CR & RCC_CR_HSERDY) && (--timeout > 0)) {}

    if (timeout == 0) {
        /* Апаратний збій кварцу: вимикаємо HSE і лишаємося на HSI */
        RCC_CR &= ~RCC_CR_HSEON;
        return false;
    }

    /* 4. Перемикаємо системну шину SYSCLK на джерело HSE */
    RCC_CFGR = (RCC_CFGR & ~0x03U) | RCC_CFGR_SW_HSE;

    /* 5. Очікуємо підтвердження апаратного перемикання комутатора */
    while ((RCC_CFGR & RCC_CFGR_SWS_MASK) != RCC_CFGR_SWS_HSE) {}

    /* 6. Активуємо Clock Security System (CSS) для апаратного контролю */
    RCC_CR |= RCC_CR_CSSON;

    return true;
}
```

```cpp
#include <cstdint>
#include <expected>

namespace hw {

/* Регістри контролера тактування та скидання (RCC) */
inline constexpr std::uintptr_t rcc_base = 0x40023800U;

struct RccRegisters {
    volatile std::uint32_t cr;
    volatile std::uint32_t pllcfgr;
    volatile std::uint32_t cfgr;
    volatile std::uint32_t cir;
    volatile std::uint32_t ahb1rstr;
    volatile std::uint32_t ahb2rstr;
    volatile std::uint32_t reserved[20];
    volatile std::uint32_t csr;
};

inline auto& rcc() noexcept {
    return *reinterpret_cast<RccRegisters*>(rcc_base);
}

enum class ResetCause : std::uint8_t {
    ColdPowerOn,
    ExternalPinReset,
    Other
};

enum class ClockError : std::uint8_t {
    HseOscillatorTimeout,
    SwitchFailed
};

class SystemStartup {
public:
    static constexpr std::uint32_t hse_timeout_cycles = 0x5000U;

    [[nodiscard]] static ResetCause diagnose_and_clear_reset_flags() noexcept {
        const std::uint32_t csr_val = rcc().csr;
        ResetCause cause = ResetCause::Other;

        if ((csr_val & (1U << 27)) != 0) {
            cause = ResetCause::ColdPowerOn;
        } else if ((csr_val & (1U << 26)) != 0) {
            cause = ResetCause::ExternalPinReset;
        }

        rcc().csr |= (1U << 24); // Очистити прапорці скидання (RMVF)
        return cause;
    }

    [[nodiscard]] static std::expected<void, ClockError> init_hse_clock() noexcept {
        // 1. Забезпечити роботу резервного генератора HSI
        rcc().cr |= (1U << 0);
        while ((rcc().cr & (1U << 1)) == 0) {}

        // 2. Увімкнути живлення генератора HSE
        rcc().cr |= (1U << 16);

        // 3. Очікування виходу резонатора на стабільну амплітуду
        std::uint32_t timeout = hse_timeout_cycles;
        while (((rcc().cr & (1U << 17)) == 0) && (--timeout > 0)) {}

        if (timeout == 0) {
            rcc().cr &= ~(1U << 16); // Вимкнути несправний HSE
            return std::unexpected(ClockError::HseOscillatorTimeout);
        }

        // 4. Перемикання джерела SYSCLK на HSE
        rcc().cfgr = (rcc().cfgr & ~0x03U) | 0x01U;

        // 5. Очікування підтвердження комутатора
        while ((rcc().cfgr & (0x03U << 2)) != (0x01U << 2)) {}

        // 6. Увімкнення апаратного супервізора частоти (CSS)
        rcc().cr |= (1U << 19);

        return {};
    }
};

} // namespace hw
```

Цей приклад демонструє нерозривний зв'язок між залізом і низькорівневим кодом: прошивка не може сліпо довіряти апаратним лініям і повинна містити захисні механізми верифікації, які враховують реальну фізику запуску зовнішніх резонаторів і стан ліній живлення.
