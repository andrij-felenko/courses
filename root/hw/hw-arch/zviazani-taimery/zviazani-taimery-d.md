# Зв'язані таймери: майстер, підлеглий, внутрішній тригер

- [Період і переповнення](root:hw-arch/timer-overflow) — автоперезавантаження (ARR), подія оновлення UEV та генерація періодів.
- [Захоплення й порівняння](root:hw-arch/capture-compare) — канали CCR, компаратори рівнів та вихідні опорні сигнали OCxREF.

- [Тактове дерево мікроконтролера](root:hw-arch/stm32-clock-tree) — джерела тактування, подільники шин APB та синхронізація таймерних доменів.
</preknowlist>

Коли мікроконтролер керує силовими ключами трифазного інвертора, генерує квадратурні сигнали зі змінним фазовим зсувом або вимірює частоту сигналу методом прямого підрахунку імпульсів, виникає потреба в синхронізації кількох апаратних таймерів із точністю до одного такту системної шини (одиниці наносекунд). Спроба координувати роботу периферійних модулів через програмні переривання процесора призводить до неминучого фазового розсинхрону. Час реакції ядра ARM Cortex-M на переривання становить щонайменше 12 тактів конвеєра на збереження регістрів у стек, а з урахуванням очікування шини пам'яті (Flash wait-states), кеш-промахів і конкуренції з іншими обробниками перетворюється на плаваючий джитер величиною 20–50 тактів (100–300 нс на частоті 168 МГц).

У силовій електроніці з частотою комутації 20–100 кГц такий часовий розкид є неприпустимим: якщо аналого-цифровий перетворювач почне вибірку струму шунта навіть на 100 нс пізніше відведеного моменту, він зафіксує не реальний струм фази двигуна, а потужний комутаційний сплеск від відкриття силового польового транзистора, де швидкість наростання напруги `dV / dt` перевищує `50 В / нс`. Аналогічно, програмне керування вікном вимірювання частотоміра додає похибку стробування, що зводить нанівець кварцову стабільність приладу, а спроба програмно наростити розрядність таймера при переповненні створює небезпечні вікна гонки даних під час читання старших і молодших слів.

Для розв'язання задачі повністю детермінованої міжпериферійної взаємодії в кремній мікроконтролерів інтегрують **внутрішню тригерну матрицю таймерів** (англ. *Timer Interconnect / Master-Slave Synchronization*). Вона дозволяє зв'язувати таймери в конфігурації «майстер — підлеглий» (Master-Slave), запускати, зупиняти, скидати чи тактувати один лічильник за внутрішніми подіями іншого, а також апаратно ініціювати вибірку АЦП чи пересилання DMA без пробудження процесора і без жодної втраченої частки наносекунди.

### Внутрішня тригерна матриця: шини TRGO та входи ITR0–ITR3

Усередині кристала мікроконтролера кожен універсальний і розширений таймер містить два незалежні комутаційні вузли: формувач вихідного тригера **TRGO** (англ. *Trigger Output*) та селектор вхідного тригера **TRGI** (англ. *Trigger Input*). Фізично це набір виділених кремнієвих ліній, що з'єднують виходи одних таймерних блоків із мультиплексорами інших в обхід системних магістралей APB/AHB. Сигнал передається з нульовою програмною затримкою — поширення імпульсу лінією займає частки наносекунди і повністю вкладається в один такт таймерного домену.

![Внутрішня тригерна матриця таймерів](/root/hw/hw-arch/zviazani-taimery/img/timer-trigger-matrix.svg)
*Внутрішня тригерна матриця: вихід TRGO майстра комутується через шини ITR0–ITR3 до входу TRGI підлеглого таймера.*

#### Джерела подій виходу TRGO майстра

Таймер, призначений роллю майстра (Master), налаштовує формування сигналу `TRGO` за допомогою 3-бітового поля **MMS** (англ. *Master Mode Selection*) у регістрі керування `TIMx_CR2` (біти `[6:4]`):

| Значення MMS | Назва джерела | Фізична поведінка сигналу TRGO на виході майстра |
| :--- | :--- | :--- |
| `000` (`0b000`) | **Reset** | Програмне встановлення біта `UG` у регістрі `TIMx_EGR` або апаратний сигнал скидання генерує позитивний імпульс на лінії `TRGO`. Використовується для одночасного скидання групи таймерів. |
| `001` (`0b001`) | **Enable (CEN)** | Лінія `TRGO` повторює стан біта `CEN` (Counter Enable) з `TIMx_CR1`. Сигнал стає активним високим у момент пуску лічильника і тримається до повної його зупинки. Ідеально підходить для режиму стробування (Gated Mode). |
| `010` (`0b010`) | **Update (UEV)** | Подія оновлення лічильника (переповнення при рахунку вгору або обнулення при рахунку вниз) генерує імпульс тривалістю в один такт таймера. Базовий режим для каскадування лічильників у 32-бітні масиви. |
| `011` (`0b011`) | **Compare Pulse** | Збіг значення лічильника `CNT` із регістром захоплення-порівняння `CCR1` (прапорець `CC1IF`) генерує короткий позитивний імпульс на `TRGO`, навіть якщо фізичний пін виходу каналу 1 вимкнено. |
| `100` (`0b100`) | **Compare OC1REF** | Вихідний опорний сигнал каналу 1 `OC1REF` транслюється на лінію `TRGO`. Дозволяє видавати на тригерну шину прямокутний ШІМ-сигнал зі змінною шпаруватістю. |
| `101` (`0b101`) | **Compare OC2REF** | Сигнал `OC2REF` транслюється на `TRGO`. |
| `110` (`0b110`) | **Compare OC3REF** | Сигнал `OC3REF` транслюється на `TRGO`. |
| `111` (`0b111`) | **Compare OC4REF** | Сигнал `OC4REF` транслюється на `TRGO`. Дозволяє сформувати тригер у довільній фазовій точці періоду ШІМ без зміни робочого виходу каналу. |

У сучасних контролерах високої продуктивності (серії STM32G4, STM32H7) реалізовано розширений генератор **TRGO2** (поле `MMS2[3:0]`), який додає ще 8 додаткових джерел (зокрема збіги каналів `CCR5`, `CCR6`, комбіновані події оновлення для роботи з високошвидкісними АЦП і контролерами цифрового живлення HRTIM).

#### Комутація тригерних шин ITR0–ITR3

Підлеглий таймер (Slave) не підключається до виходу майстра довільно: виробник чіпа жорстко зашиває в кремній таблицю крос-комутації. На вхідний селектор тригера таймера подаються чотири внутрішні лінії — **ITR0**, **ITR1**, **ITR2**, **ITR3**. 

Типова матриця міжз'єднань для базових таймерів загального призначення має такий вигляд:

| Підлеглий таймер (Slave) | Лінія ITR0 | Лінія ITR1 | Лінія ITR2 | Лінія ITR3 |
| :--- | :--- | :--- | :--- | :--- |
| **TIM1** (Advanced) | TIM5 TRGO | TIM2 TRGO | TIM3 TRGO | TIM4 TRGO |
| **TIM2** (General 32-bit) | TIM1 TRGO | TIM8 TRGO | TIM3 TRGO | TIM4 TRGO |
| **TIM3** (General 16-bit) | TIM1 TRGO | TIM2 TRGO | TIM5 TRGO | TIM4 TRGO |
| **TIM4** (General 16-bit) | TIM1 TRGO | TIM2 TRGO | TIM3 TRGO | TIM8 TRGO |
| **TIM5** (General 32-bit) | TIM2 TRGO | TIM3 TRGO | TIM4 TRGO | TIM8 TRGO |
| **TIM8** (Advanced) | TIM1 TRGO | TIM2 TRGO | TIM4 TRGO | TIM5 TRGO |

Щоб налаштувати підлеглий таймер на прийом сигналу від обраного майстра, інженер записує відповідний номер ITR у поле **TS** (англ. *Trigger Selection*, біти `[6:4]`) регістра керування слейв-режимами `TIMx_SMCR`:

```
TS = 000 (0b000)  →  Вибір входу ITR0
TS = 001 (0b001)  →  Вибір входу ITR1
TS = 010 (0b010)  →  Вибір входу ITR2
TS = 011 (0b011)  →  Вибір входу ITR3
TS = 100 (0b100)  →  Детектор фронтів TI1F_ED (фронт і спад каналу 1)
TS = 101 (0b101)  →  Фільтрований вхід каналу 1 (TI1FP1)
TS = 110 (0b110)  →  Фільтрований вхід каналу 2 (TI2FP2)
TS = 111 (0b111)  →  Зовнішній фільтрований тригерний вхід (ETRF)
```

Сигнал із виходу обраного мультиплексора позначається як **TRGI** (внутрішній тригерний вхід) і надходить на кінцевий автомат контролера підлеглого режиму.

#### Синхронізація тактових доменів APB1 та APB2

Важлива архітектурна деталь: у мікроконтролерах таймери можуть живитися від різних тактових шин. Наприклад, `TIM1` та `TIM8` розташовані на швидкісній шині APB2 (тактується на повній частоті ядра 168 МГц), тоді як `TIM2..TIM5` розташовані на повільнішій шині APB1 (тактується на частоті 84 МГц).

Коли сигнал `TRGO` перетинає границю тактових доменів (Clock Domain Crossing), схема тригерного входу автоматично здійснює синхронізацію двома послідовними D-тригерами для запобігання метастабільності. Ця апаратна синхронізація вносить детерміновану затримку в 1–2 такти приймаючого таймера, яку необхідно враховувати при прецизійному розрахунку фазових зсувів між таймерами різних шин.

### Режими роботи слейв-таймера (Slave Modes)

Контролер підлеглого режиму в таймері керується 3-бітовим полем **SMS** (англ. *Slave Mode Selection*, біти `[2:0]` у `TIMx_SMCR`, розширено до 4 біт `SMS[3:0]` у нових серіях). Вибір значення `SMS` визначає, як саме внутрішня лічильна схема таймера реагуватиме на активні перепади чи логічні рівні лінії `TRGI`.

![Часові діаграми режимів слейв-таймера](/root/hw/hw-arch/zviazani-taimery/img/slave-modes-timing.svg)
*Поведінка лічильника CNT слейв-таймера у чотирьох режимах роботи відносно керівного сигналу TRGI.*

Розгляньмо фізику та часові характеристики кожного з чотирьох основних режимів:

#### 1. Режим скидання (Reset Mode: SMS = 0100)

У режимі скидання підлеглий таймер продовжує безперервно тактуватися від власного внутрішнього генератора `CK_INT` через встановлений власний передільник `PSC`. 

У момент виникнення наростаючого фронту на лінії `TRGI` (вихідний імпульс майстра) внутрішній логічний вентиль примусово перезавантажує лічильник:
* При конфігурації рахунку вгору (Upcounting): значення `CNT` скидається в `0x0000`;
* При конфігурації рахунку вниз (Downcounting): значення `CNT` завантажує вміст регістра автоперезавантаження `ARR`;
* Одночасно генерується внутрішній імпульс оновлення (UEV), що призводить до перезавантаження тіньових регістрів передзавантаження (Preload registers) для `ARR` та `CCRx`.

Лічильник при цьому **не зупиняється**: одразу в наступному такті він продовжує лічбу з нового початкового стану.

**Інженерне застосування:** фазове вирівнювання кількох паралельних ШІМ-генераторів, циклічна синхронізація генераторів пилкоподібної напруги для резонансних перетворювачів, апаратний перезапуск сторожових таймерів за регулярною подією обміну.

#### 2. Режим стробування (Gated Mode: SMS = 0101)

У режимі стробування внутрішнє тактування лічильника `CNT` дозволене виключно тоді, коли на лінії `TRGI` утримується високий логічний рівень (`TRGI = 1`):

1. Коли майстер виставляє на `TRGO` логічну одиницю (наприклад, утримуючи прапорець `CEN = 1` при `MMS = 001`), слейв-таймер безперервно інкрементує свій лічильник `CNT` на кожному власному такті.
2. Щойно сигнал `TRGI` падає в логічний нуль (`TRGI = 0`), логічний вентиль схеми тактування блокує проходження імпульсів від передільника до лічильника. Лічильник миттєво «замерзає», фіксуючи поточне накопичене значення в регістрі `CNT`.
3. При наступному переході `TRGI` в стан «1» рахунок продовжується з тієї самої точки, де він був зупинений, без скидання в нуль.

При цьому внутрішній лічильник передільника (Prescaler counter) також синхронно зупиняє роботу, що запобігає появі похибки фази при дробленні базової частоти.

**Інженерне застосування:** апаратне вимірювання тривалості зовнішніх імпульсів або пакетів сигналів, стробування лічильників у частотомірах, накопичення сумарного часу перебування системи в активному стані.

#### 3. Режим тригера (Trigger Mode: SMS = 0110)

У режимі тригера таймер за замовчуванням перебуває у вимкненому стані (`CEN = 0` у регістрі `CR1`).

При надходженні позитивного фронту на лінію `TRGI`:
1. Апаратний тригер засувки автоматично встановлює біт `CEN = 1` у регістрі керування `TIMx_CR1`.
2. Лічильник починає рахунок від `0` (або попереднього значення) і далі працює повністю **автономно**.
3. Подальші спади, фронти чи рівні на лінії `TRGI` більше ніяк не впливають на роботу слейв-таймера. Він продовжує крутитися за власним періодом, доки програма явно не скине біт `CEN = 0` через запис у регістр.

Головна відмінність від режиму скидання (Reset Mode) полягає в тому, що Trigger Mode — це одноразовий апаратний «старт за командою майстра», тоді як Reset Mode багаторазово обнуляє лічильник на кожному новому тригерному імпульсі.

**Інженерне застосування:** гарантований синхронний запуск складного багатоканального ШІМ-пакета (наприклад, одночасний старт трьох фаз двигуна з жорстко заданими фазовими зсувами), запуск генерації одиночного імпульсу (One-Pulse Mode) із прецизійною затримкою.

#### 4. Режим зовнішнього тактування 1 (External Clock Mode 1: SMS = 0111)

У цьому режимі внутрішнє тактування від шини APB повністю відключається від входу лічильника. Замість сигналу `CK_INT` джерелом тактових імпульсів для лічильника стає сам тригерний вхід `TRGI`:

```
Кожен наростаючий фронт на TRGI  →  CNT = CNT + 1
```

Якщо для слейв-таймера налаштовано власний передільник `PSC`, він ділитиме вхідні імпульси з лінії `TRGI` на коефіцієнт `(PSC + 1)` перед тим, як подати їх на інкремент основного регістра `CNT`.

**Інженерне застосування:** побудова каскадних лічильників великої розрядності (32-бітних і 64-бітних таймерів із двох 16-бітних), підрахунок подій переповнення майстра, лічильники кроків для верстатів із числовим програмним керуванням.

#### 5. Розширені та комбіновані режими сучасних таймерів

У нових поколіннях мікроконтролерів (Cortex-M4/M7/M33) поле `SMS` розширено до 4 бітів, що дозволило реалізувати комбіновані слейв-режими:
* **Combined Reset + Trigger Mode (`SMS = 1000`):** перший наростаючий фронт на `TRGI` запускає лічильник (встановлює `CEN = 1`), а всі наступні фронти скидають лічильник у нуль без його зупинки. Це усуває потребу в комбінуванні кількох таймерів для побудови генераторів із фазовим автопідстроюванням.
* **Combined Gated + Reset Mode (`SMS = 1001`):** таймер рахує лише при `TRGI = 1`, а перехід `TRGI` з `1` в `0` автоматично скидає значення `CNT` у нуль.

### Каскадування лічильників: створення 32-бітного віртуального таймера

Більшість таймерів мікроконтролера є 16-розрядними (максимальне значення лічильника `ARR = 0xFFFF = 65 535`). При тактуванні від швидкої шини 84 МГц без передільника 16-бітний таймер переповнюється за надзвичайно короткий проміжок часу:

```
T_overflow = 65536 / 84000000 Гц ≈ 0.00078019 с ≈ 780.2 мкс
```

Якщо системі потрібно заміряти часові інтервали тривалістю в кілька хвилин із наносекундною роздільністю, 16 біт не вистачає. Апаратне каскадування дозволяє об'єднати два 16-бітні таймери в один монолітний 32-розрядний віртуальний лічильник із діапазоном до `4 294 967 296` тактів (понад 51 секунда безперервного ходу на частоті 84 МГц із роздільністю 11.9 нс).

![Каскадування таймерів у 32-бітний лічильник](/root/hw/hw-arch/zviazani-taimery/img/cascaded-counters.svg)
*Каскадне об'єднання таймерів: подія UEV майстра тактує підлеглий таймер у режимі External Clock Mode 1.*

#### Апаратна топологія каскаду

1. **Master-таймер (наприклад, TIM2 або TIM3 — молодші 16 біт):**
   * Тактується від системної шини APB з нульовим передільником (`PSC = 0`);
   * Регістр автоперезавантаження налаштовується на повну шкалу: `ARR = 0xFFFF`;
   * Режим майстра конфігурується на видачу події оновлення: `CR2.MMS = 010` (Update Event UEV).
2. **Slave-таймер (наприклад, TIM3 або TIM4 — старші 16 біт):**
   * Вихідний тригер майстра підключається через матрицю: `SMCR.TS = 001` (вхід `ITR1`);
   * Режим підлеглого встановлюється в пряме тактування від тригера: `SMCR.SMS = 0111` (External Clock Mode 1);
   * Передільник виставляється в `PSC = 0`, а межа рахунку — `ARR = 0xFFFF`.

#### Фізика роботи лічильного каскаду

1. Молодший лічильник `TIM2->CNT` швидко рахує такт за тактом: `0x0000, 0x0001, ..., 0xFFFE, 0xFFFF`.
2. Наступний такт переводить `TIM2->CNT` назад у стан `0x0000`, викликаючи апаратну подію переповнення (UEV).
3. Подія UEV відкриває вихідний логічний ключ і формує на внутрішній лінії `TRGO` прямокутний імпульс тривалістю рівно в один такт шини APB.
4. Цей імпульс миттєво по кремнієвій доріжці надходить на вхід `ITR1` підлеглого таймера `TIM3`.
5. Контролер `TIM3`, працюючи в режимі External Clock Mode 1, сприймає наростаючий фронт на `ITR1` як тактовий імпульс і збільшує свій лічильник старших бітів на одиницю: `TIM3->CNT = 0x0001`.

Увесь процес відбувається на суто вентильному рівні без звернення до процесора і без використання каналів прямого доступу до пам'яті (DMA).

#### Проблема гонки переповнення при читанні 32-бітного значення

Оскільки фізично 32-бітне число розподілене між двома незалежними 16-бітними регістрами `TIM2->CNT` (молодша частина) та `TIM3->CNT` (старша частина), процесор не може зчитати їх однією 32-розрядною машинною інструкцією пам'яті. Необхідно виконати два послідовних 16-бітних читання за різними адресами пам'яті:

:::tabs
```c
/* Наївний небезпечний спосіб читання каскаду */
uint16_t low  = (uint16_t)TIM2_REGS->CNT;
uint16_t high = (uint16_t)TIM3_REGS->CNT;
uint32_t val  = ((uint32_t)high << 16) | (uint32_t)low; // НЕБЕЗПЕЧНО!
```
```cpp
/* Наївний небезпечний спосіб читання каскаду */
const auto low  = static_cast<std::uint16_t>(HardwareTimer<tim2_base>::regs().cnt);
const auto high = static_cast<std::uint16_t>(HardwareTimer<tim3_base>::regs().cnt);
const auto val  = (static_cast<std::uint32_t>(high) << 16) | static_cast<std::uint32_t>(low); // НЕБЕЗПЕЧНО!
```
:::

У цій наївній реалізації криється класична **гонка даних (Race Condition)**. 

Уявімо послідовність подій у часі:
1. Лічильник майстра підходить до переповнення: `TIM2->CNT = 0xFFFF`, старший лічильник `TIM3->CNT = 0x0005`.
2. Процесор зчитує молодший регістр і отримує: `low = 0xFFFF`.
3. Рівно в наступний такт, доки процесор декодує наступну інструкцію читання, лічильник майстра переповнюється: `TIM2->CNT` стає `0x0000`, на `TRGO` вистрілює імпульс, і старший лічильник `TIM3->CNT` стає `0x0006`.
4. Процесор зчитує старший регістр і отримує: `high = 0x0006`.
5. Складене значення: `val = (0x0006 << 16) | 0xFFFF = 0x0006FFFF`.

Реальний час відповідав значенню `0x0005FFFF` або `0x00060000`, але отримана величина `0x0006FFFF` відкидає систему на 65 535 тактів уперед у майбутнє. Такий викид повністю руйнує роботу фільтрів Калмана, регуляторів PID та алгоритмів інтерполяції траєкторій.

#### Алгоритм подвійного зчитування (Double-Read Atomic Loop)

Для отримання гарантовано когерентного 32-бітного значення застосовують неблокуючий алгоритм подвійного зчитування старшого слова:

:::tabs
```c
uint32_t timer_cascade_read_32bit_atomic(volatile uint32_t *master_cnt_reg, volatile uint32_t *slave_cnt_reg) {
    uint16_t high1;
    uint16_t low;
    uint16_t high2;

    do {
        high1 = (uint16_t)(*slave_cnt_reg);  // 1. Первинна фіксація старшого слова
        low   = (uint16_t)(*master_cnt_reg); // 2. Зчитування молодшого слова
        high2 = (uint16_t)(*slave_cnt_reg);  // 3. Повторна перевірка старшого слова
    } while (high1 != high2); // Якщо старше слово змінилося під час читання low — повторити

    return ((uint32_t)high1 << 16) | (uint32_t)low;
}
```
```cpp
[[nodiscard]] inline std::uint32_t read_cascaded_32bit_atomic(
    volatile const std::uint32_t& master_cnt_reg,
    volatile const std::uint32_t& slave_cnt_reg) noexcept {
    std::uint16_t high1{};
    std::uint16_t low{};
    std::uint16_t high2{};

    do {
        high1 = static_cast<std::uint16_t>(slave_cnt_reg);  // 1. Первинна фіксація старшого слова
        low   = static_cast<std::uint16_t>(master_cnt_reg); // 2. Зчитування молодшого слова
        high2 = static_cast<std::uint16_t>(slave_cnt_reg);  // 3. Повторна перевірка старшого слова
    } while (high1 != high2);

    return (static_cast<std::uint32_t>(high1) << 16) | static_cast<std::uint32_t>(low);
}
```
:::

Математичне обґрунтування надійності: умова `high1 == high2` гарантує, що між моментом початку операції та моментом отримання `low` переповнення молодшого лічильника не сталося, і пара `(high1, low)` належить до єдиного неподільного кванту часу. Оскільки молодший таймер рахує 65 536 тактів до наступного переповнення, а цикл перевірки займає менше 10 машинних інструкцій ядра, цикл виконується рівно один раз у 99.998% випадків і щонайбільше двічі при прямому потраплянні на границю переповнення.

### Практичні застосування зв'язаних таймерів

#### 1. Синхронний запуск АЦП із прецизійним фазовим зсувом від ШІМ інвертора

У системах векторного керування електродвигунами (FOC, англ. *Field Oriented Control*) трифазний міст живить обмотки статора напругою з широтно-імпульсною модуляцією. Для розрахунку вектора магнітного потоку мікроконтролер повинен із високою точністю вимірювати миттєві струми у фазах за допомогою резистивних шунтів, розташованих у нижніх плечах напівмостів.

![Синхронізація ШІМ інвертора та вибірки АЦП](/root/hw/hw-arch/zviazani-taimery/img/inverter-adc-synchronization.svg)
*Генерація тригера TRGO на вершині симетричного ШІМ (CNT = ARR) для вибірки струму під час провідності нижніх ключів.*

##### Фізичні обмеження вимірювання струму

Шунт у нижньому плечі підключений послідовно з нижнім силовим транзистором (Low-Side MOSFET/IGBT). Струм фази протікає через шунт виключно тоді, коли нижній транзистор відкритий, а верхній транзистор напівмоста надійно закритий. Якщо запустити вибірку АЦП у довільний момент:
1. При відкритому верхньому транзисторі струм через нижній шунт дорівнює нулю.
2. У моменти перемикання транзисторів (фронти ШІМ) паразитні індуктивності виводів корпусу та друкованих доріжок генерують високочастотний комутаційний дзвін амплітудою в одиниці вольт. Замір у ці моменти дає повністю спотворені покази.

##### Розв'язання задачі через зв'язку TIM1 Master → ADC Injected Trigger

Для симетричного керування силовим мостом таймер `TIM1` переводять у режим симетричного рахунку з вирівнюванням по центру (Center-Aligned Mode 1, біти `CMS = 01` у `TIM1_CR1`). Лічильник `CNT` безперервно рахує вгору від `0` до `ARR`, а потім вниз від `ARR` до `0`, формуючи трикутний сигнал носія.

1. У моменти, коли лічильник наближається до вершини `CNT = ARR`, усі три верхні транзистори інвертора закриваються, а всі три нижні транзистори надійно відкриваються.
2. Комутаційні перехідні процеси повністю згасають за час мертвого інтервалу (Dead-Time, зазвичай 200–800 нс).
3. Таймер `TIM1` налаштовують на формування тригера `TRGO`:
   * Варіант А: `CR2.MMS = 010` (Update Event UEV). При рахунку вгору подія оновлення виникає рівно в точці піку `CNT = ARR`.
   * Варіант Б: `CR2.MMS = 111` (Compare OC4REF). У регістр `TIM1->CCR4` записують значення `(ARR - t_settle)`, де `t_settle` — час попереднього збудження схеми вибірки-зберігання АЦП.
4. Внутрішня тригерна лінія `TIM1_TRGO` підключається до апаратного тригера інжектованої групи аналого-цифрового перетворювача (`ADC_CR2.JEXTSEL = TIM1_TRGO`).
5. АЦП автоматично виконує синхронну паралельну вибірку напруг на шунтах двох або трьох фаз рівно в центрі інтервалу провідності нижніх ключів. 

Результат: абсолютний захист від комутаційного шуму, нульовий джитер фази вимірювання і звільнення 100% ресурсу ядра CPU для обчислень перетворень Парка і Кларк.

#### 2. Апаратний частотомір з нульовим програмним джитером

Класична задача вимірювання частоти полягає в підрахунку кількості імпульсів невідомого вхідного сигналу `N_pulses` за фіксований стробовий інтервал часу `T_gate` (наприклад, рівно 1.000000 секунда):

```
f_in = N_pulses / T_gate
```

![Апаратний частотомір на зв'язаних таймерах](/root/hw/hw-arch/zviazani-taimery/img/frequency-meter-architecture.svg)
*Вимірювання частоти стробуванням: майстер формує секундне вікно вимірювання, а слейв підраховує вхідні імпульси.*

##### Чому програмне стробування не працює

Якщо розробник відкриває та закриває лічбу програмно через таймерні переривання (наприклад, викликаючи `TIM3->CR1 |= TIM_CR1_CEN` у першому обробнику та `TIM3->CR1 &= ~TIM_CR1_CEN` у другому через 1 секунду), тривалість вимірювального вікна `T_gate` зазнає впливу затримок входу в переривання. Затримка всього в 5 мікросекунд на закритті вікна при частоті сигналу 10 МГц додає 50 фальшивих імпульсів, погіршуючи точність на 50 ppm.

##### Апаратна архітектура зв'язки TIM2 (Master Timebase) → TIM3 (Slave Pulse Counter)

1. **Master-таймер TIM2 (Формувач секундного вікна стробування):**
   * Базовий тактовий сигнал: `f_CLK = 84 МГц`, стабілізований прецизійним термокомпенсованим кварцовим генератором (TCXO);
   * Передільник: `PSC = 8399` (частота лічби стає `84 МГц / 8400 = 10 кГц`, тобто один тік дорівнює 100 мкс);
   * Період: `ARR = 9999` (загальний період таймера `(9999 + 1) * 100 мкс = 1.000000 с`);
   * Канал 1: налаштовується в режим генерації ШІМ (PWM Mode 1) із порогом `CCR1 = 5000` (тривалість високого рівня становить рівно 0.500000 с) або використовується режим `CR2.MMS = 001` (Enable CEN) у парі з режимом One-Pulse Mode для формування одиночного вимірювального вікна тривалістю 1.000000 с;
   * Вихідний тригер: `CR2.MMS = 001` (CEN) або `100` (OC1REF) транслює каліброване вікно на лінію `TRGO`.
2. **Slave-таймер TIM3 (Апаратний акумулятор імпульсів):**
   * Зовнішній сигнал невідомої частоти `f_in` подається безпосередньо на вхідний пін зовнішнього тактування `TIM3_ETR` або канал `TIM3_CH1` (вивід GPIO з альтернативною функцією);
   * Селектор тригера: `SMCR.TS = 001` (прийом стробу від `TIM2_TRGO` через лінію `ITR1`);
   * Режим підлеглого: `SMCR.SMS = 0101` (Gated Mode);
   * Лічильник `TIM3->CNT` налаштовується на рахунок зовнішніх імпульсів піна `ETR`.

##### Процес вимірювання

1. Програма ініціалізує лічильник `TIM3->CNT = 0` і запускає майстер-таймер `TIM2`.
2. Лінія `TRGO` переходить у високий логічний рівень. Вхід `TRGI` слейв-таймера миттєво відкриває проходження зовнішніх імпульсів `f_in` на лічильник `CNT`.
3. Під час утримання стробу `TIM3->CNT` на апаратному рівні накопичує кожен перепад досліджуваного сигналу (до 50–100 МГц залежно від сімейства МК).
4. Рівно через 1.000000 секунду апаратний вихід `TRGO` майстра падає в нуль. Підлеглий таймер `TIM3` миттєво апаратно блокує вхід, фіксуючи результат.
5. За спадом сигналу `TRGO` генерується переривання або запит DMA, який переносить накопичене число `CNT` в оперативну пам'ять.

Точність такого частотоміра обмежена виключно похибкою дискретності `±1 імпульс` на границях вікна та стабільністю опорного кварцового резонатора.

### Повний драйвер зв'язки Master-Slave таймерів

Нижче наведено повний виробничий драйвер конфігурації зв'язаних таймерів на регістрах прямого доступу (без використання блокуючих абстракцій HAL) для мов C та C++. Драйвер реалізує конфігурацію майстра, налаштування підлеглого в різних режимах, ініціалізацію 32-бітного каскаду з атомарним читанням та налаштування частотоміра.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

/* Базові адреси периферійних таймерів STM32 (шина APB1 / APB2) */
#define TIM1_BASE_ADDR   0x40010000U
#define TIM2_BASE_ADDR   0x40000000U
#define TIM3_BASE_ADDR   0x40000400U

/* Структура регістрів таймера загального призначення */
typedef struct {
    volatile uint32_t CR1;
    volatile uint32_t CR2;
    volatile uint32_t SMCR;
    volatile uint32_t DIER;
    volatile uint32_t SR;
    volatile uint32_t EGR;
    volatile uint32_t CCMR1;
    volatile uint32_t CCMR2;
    volatile uint32_t CCER;
    volatile uint32_t CNT;
    volatile uint32_t PSC;
    volatile uint32_t ARR;
    volatile uint32_t RCR;
    volatile uint32_t CCR1;
    volatile uint32_t CCR2;
    volatile uint32_t CCR3;
    volatile uint32_t CCR4;
    volatile uint32_t BDTR;
    volatile uint32_t DCR;
    volatile uint32_t DMAR;
} timer_regs_t;

#define TIM1_REGS ((timer_regs_t *)TIM1_BASE_ADDR)
#define TIM2_REGS ((timer_regs_t *)TIM2_BASE_ADDR)
#define TIM3_REGS ((timer_regs_t *)TIM3_BASE_ADDR)

/* Бітові маски керування */
#define TIM_CR1_CEN_BIT        (1U << 0)
#define TIM_CR1_ARPE_BIT       (1U << 7)
#define TIM_EGR_UG_BIT         (1U << 0)

/* Джерела тригера майстра (CR2.MMS) */
typedef enum {
    TIMER_TRGO_SRC_RESET   = 0x00U,
    TIMER_TRGO_SRC_ENABLE  = 0x01U,
    TIMER_TRGO_SRC_UPDATE  = 0x02U,
    TIMER_TRGO_SRC_CC1_PULSE = 0x03U,
    TIMER_TRGO_SRC_OC1REF  = 0x04U,
    TIMER_TRGO_SRC_OC2REF  = 0x05U,
    TIMER_TRGO_SRC_OC3REF  = 0x06U,
    TIMER_TRGO_SRC_OC4REF  = 0x07U
} timer_trgo_src_t;

/* Вхідні тригерні лінії слейва (SMCR.TS) */
typedef enum {
    TIMER_TRGI_SEL_ITR0    = 0x00U,
    TIMER_TRGI_SEL_ITR1    = 0x01U,
    TIMER_TRGI_SEL_ITR2    = 0x02U,
    TIMER_TRGI_SEL_ITR3    = 0x03U,
    TIMER_TRGI_SEL_TI1F_ED = 0x04U,
    TIMER_TRGI_SEL_TI1FP1  = 0x05U,
    TIMER_TRGI_SEL_TI2FP2  = 0x06U,
    TIMER_TRGI_SEL_ETRF    = 0x07U
} timer_trgi_sel_t;

/* Режими роботи слейв-таймера (SMCR.SMS) */
typedef enum {
    TIMER_SLAVE_MODE_DISABLED   = 0x00U,
    TIMER_SLAVE_MODE_RESET      = 0x04U,
    TIMER_SLAVE_MODE_GATED      = 0x05U,
    TIMER_SLAVE_MODE_TRIGGER    = 0x06U,
    TIMER_SLAVE_MODE_EXT_CLOCK1 = 0x07U
} timer_slave_mode_t;

/* Ініціалізація майстер-таймера */
void timer_master_config(timer_regs_t *timer, uint16_t prescaler, uint16_t auto_reload, timer_trgo_src_t trgo_source) {
    timer->CR1 &= ~TIM_CR1_CEN_BIT; // Зупинити лічильник перед налаштуванням
    timer->PSC = prescaler;
    timer->ARR = auto_reload;

    /* Налаштування бітів MMS[2:0] у регістрі CR2 */
    uint32_t cr2_val = timer->CR2;
    cr2_val &= ~(0x07U << 4);
    cr2_val |= ((uint32_t)trgo_source & 0x07U) << 4;
    timer->CR2 = cr2_val;

    timer->EGR |= TIM_EGR_UG_BIT; // Перезавантажити тіньові регістри
}

/* Ініціалізація підлеглого таймера (Slave) */
void timer_slave_config(timer_regs_t *timer, uint16_t prescaler, uint16_t auto_reload,
                        timer_trgi_sel_t trigger_input, timer_slave_mode_t slave_mode) {
    timer->CR1 &= ~TIM_CR1_CEN_BIT;
    timer->PSC = prescaler;
    timer->ARR = auto_reload;

    /* Налаштування бітів TS[2:0] та SMS[2:0] у регістрі SMCR */
    uint32_t smcr_val = timer->SMCR;
    smcr_val &= ~((0x07U << 4) | 0x07U);
    smcr_val |= (((uint32_t)trigger_input & 0x07U) << 4);
    smcr_val |= ((uint32_t)slave_mode & 0x07U);
    timer->SMCR = smcr_val;

    timer->EGR |= TIM_EGR_UG_BIT;
}

/* Побудова 32-бітного лічильника з двох 16-бітних таймерів (TIM2 Master -> TIM3 Slave) */
void timer_cascade_32bit_init(void) {
    /* TIM2: Майстер молодших 16 біт (рахує на повній швидкості, TRGO = Update Event) */
    timer_master_config(TIM2_REGS, 0, 0xFFFFU, TIMER_TRGO_SRC_UPDATE);

    /* TIM3: Слейв старших 16 біт (вхід ITR1, такт від переповнення майстра) */
    timer_slave_config(TIM3_REGS, 0, 0xFFFFU, TIMER_TRGI_SEL_ITR1, TIMER_SLAVE_MODE_EXT_CLOCK1);

    /* Очищення лічильників */
    TIM2_REGS->CNT = 0;
    TIM3_REGS->CNT = 0;

    /* Запуск слейва, потім запуск майстра */
    TIM3_REGS->CR1 |= TIM_CR1_CEN_BIT;
    TIM2_REGS->CR1 |= TIM_CR1_CEN_BIT;
}

/* Неблокуюче атомарне зчитування 32-бітного каскаду */
uint32_t timer_cascade_32bit_read(void) {
    uint16_t high1;
    uint16_t low;
    uint16_t high2;

    do {
        high1 = (uint16_t)TIM3_REGS->CNT;
        low   = (uint16_t)TIM2_REGS->CNT;
        high2 = (uint16_t)TIM3_REGS->CNT;
    } while (high1 != high2);

    return ((uint32_t)high1 << 16) | (uint32_t)low;
}

/* Конфігурація апаратного частотоміра (секундний строб на TIM2, лічба імпульсів на TIM3) */
void timer_frequency_meter_init(uint32_t apb_clock_hz) {
    /* Розрахунок передільника для формування секундного вікна: база часу 10 кГц */
    uint16_t psc_master = (uint16_t)((apb_clock_hz / 10000U) - 1U);
    uint16_t arr_master = 9999U; // (9999 + 1) / 10000 Гц = 1.000000 с

    /* TIM2 генерує строб тривалості роботи CEN на вихід TRGO */
    timer_master_config(TIM2_REGS, psc_master, arr_master, TIMER_TRGO_SRC_ENABLE);

    /* TIM3 працює в режимі Gated Mode за стробом від ITR1 */
    timer_slave_config(TIM3_REGS, 0, 0xFFFFU, TIMER_TRGI_SEL_ITR1, TIMER_SLAVE_MODE_GATED);

    /* Вхід ETR таймера TIM3 підключається до зовнішнього піна */
    TIM3_REGS->SMCR |= (1U << 14); // ECE: Дозвіл тактування від зовнішнього піна ETR
}
```

```cpp
template <std::uintptr_t BaseAddress>
class HardwareTimer {
public:
    [[nodiscard]] static TimerRegisters& regs() noexcept {
        return *reinterpret_cast<TimerRegisters*>(BaseAddress);
    }

    static void enable() noexcept {
        regs().cr1 |= (1U << 0);
    }

    static void disable() noexcept {
        regs().cr1 &= ~(1U << 0);
    }

    static void reset_counter() noexcept {
        regs().cnt = 0;
    }

    static void configure_master(std::uint16_t prescaler, std::uint16_t period,
                                 MasterTriggerSource trgo_src) noexcept {
        disable();
        regs().psc = prescaler;
        regs().arr = period;

        std::uint32_t cr2 = regs().cr2;
        cr2 &= ~(0x07U << 4);
        cr2 |= (static_cast<std::uint32_t>(trgo_src) & 0x07U) << 4;
        regs().cr2 = cr2;

        regs().egr |= (1U << 0); // Оновлення конфігурації (UG)
    }

    static void configure_slave(std::uint16_t prescaler, std::uint16_t period,
                                TriggerInput trgi_input, SlaveMode mode) noexcept {
        disable();
        regs().psc = prescaler;
        regs().arr = period;

        std::uint32_t smcr = regs().smcr;
        smcr &= ~((0x07U << 4) | 0x07U);
        smcr |= (static_cast<std::uint32_t>(trgi_input) & 0x07U) << 4;
        smcr |= (static_cast<std::uint32_t>(mode) & 0x07U);
        regs().smcr = smcr;

        regs().egr |= (1U << 0);
    }
};

/* Апаратний 32-бітний каскадний таймер */
class CascadedTimer32 {
public:
    using Master = HardwareTimer<tim2_base>;
    using Slave  = HardwareTimer<tim3_base>;

    static void init() noexcept {
        // Master (TIM2): рахує молодші 16 біт, генерує TRGO по кожному переповненню
        Master::configure_master(0, 0xFFFFU, MasterTriggerSource::UpdateEvent);

        // Slave (TIM3): інкрементується за фронтом тригера ITR1 (TRGO майстра)
        Slave::configure_slave(0, 0xFFFFU, TriggerInput::Itr1, SlaveMode::ExtClockMode1);

        Master::reset_counter();
        Slave::reset_counter();

        Slave::enable();
        Master::enable();
    }

    [[nodiscard]] static std::uint32_t read_atomic() noexcept {
        std::uint16_t high1{};
        std::uint16_t low{};
        std::uint16_t high2{};

        do {
            high1 = static_cast<std::uint16_t>(Slave::regs().cnt);
            low   = static_cast<std::uint16_t>(Master::regs().cnt);
            high2 = static_cast<std::uint16_t>(Slave::regs().cnt);
        } while (high1 != high2);

        return (static_cast<std::uint32_t>(high1) << 16) | static_cast<std::uint32_t>(low);
    }
};

class HardwareFrequencyMeter {
public:
    using Timebase = HardwareTimer<tim2_base>;
    using Counter  = HardwareTimer<tim3_base>;

    [[nodiscard]] static std::expected<void, TimerError> init(std::uint32_t apb_clock_hz) noexcept {
        if (apb_clock_hz < 10000U) {
            return std::unexpected(TimerError::BusClockTooLow);
        }

        const auto psc = static_cast<std::uint16_t>((apb_clock_hz / 10000U) - 1U);
        constexpr std::uint16_t arr = 9999U; // Вікно рівно 1.000000 с

        Timebase::configure_master(psc, arr, MasterTriggerSource::EnableCen);
        Counter::configure_slave(0, 0xFFFFU, TriggerInput::Itr1, SlaveMode::GatedMode);

        Counter::regs().smcr |= (1U << 14);

        return {};
    }

    static void start_measurement() noexcept {
        Counter::reset_counter();
        Timebase::reset_counter();
        Timebase::enable();
    }
};
```

### Діагностичний контрольний список конфігурації Master-Slave зв'язки

Перед запуском обладнання в роботу перевірте такі критичні точки конфігурації:

1. **Тактування обох таймерів у контролері RCC:** якщо увімкнути тактування майстра, але забути подати такт на підлеглий таймер у регістрі `RCC_APB1ENR` / `RCC_APB2ENR`, регістри слейва залишаться в стані скидання, і лічильник не реагуватиме на лінію `TRGI`.
2. **Перевірка відповідності лінії ITR матриці чіпа:** таблиця з'єднань різниться між родинами мікроконтролерів (наприклад, STM32F407 та STM32H743 мають різні номери ITR для таймерів `TIM5` і `TIM8`). Завжди звіряйте номер `ITRx` за Reference Manual конкретного кристала.
3. **Послідовність запуску `CEN`:** у каскадних конфігураціях та режимах стробування підлеглий таймер (Slave) завжди повинен бути увімкнений (`CEN = 1` або налаштований у відповідний `SMS`) **до** того, як запуститься майстер. Якщо запустити майстер першим, підлеглий таймер пропустить перший тригерний імпульс.
4. **Очищення прапорців переривань при старті:** примусове оновлення `EGR |= TIM_EGR_UG` для завантаження конфігурації передільника встановлює прапорець переповнення `SR.UIF`. Якщо переривання дозволені, перед запуском необхідно програмно очистити `SR.UIF = 0`, щоб уникнути помилкового спрацьовування обробника при старті.
