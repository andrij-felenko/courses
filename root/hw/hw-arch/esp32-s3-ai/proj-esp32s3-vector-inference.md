# Прискорений інференс квантованого повнозв'язного шару на ESP32-S3

Цей проєкт реалізує високопродуктивний модуль інференсу квантованого повнозв'язного шару нейронної мережі (*Fully Connected / Dense Layer*) у форматі `int8` для мікроконтролера ESP32-S3. Без апаратного прискорення обчислення матричного множення на вбудованих системах стає головним споживачем тактових циклів процесора, сповільнюючи роботу всього пристрою та виснажуючи джерело автономного живлення. Нижче наведено повну реалізацію обчислювального ядра на базі векторних інструкцій співпроцесора Xtensa PIE, систему вимірювання затримок на рівні апаратних лічильників та блок верифікації бітової точності проти еталонного скалярного алгоритму.

---

### Математична постановка задачі та згортання нуль-пункту

Повнозв'язний шар нейромережі трансформує вхідний вектор активацій `x` розмірністю `N` у вихідний вектор `y` розмірністю `M` за допомогою матриці вагових коефіцієнтів `W` розміром `[M × N]` та вектора зміщень `b` довжиною `M`.

У квантованому представленні з фіксованою комою (*Affine Quantization*) дійсні значення чисел `r` пов'язані з 8-бітними цілочисловими значеннями `q ∈ [-128, 127]` через масштабний коефіцієнт `S` та цілочисловий нуль-пункт `Z`:

```
r = S · (q - Z)                       [зв'язок дійсного та квантованого значень]
```

Для симетрично квантованих ваг нуль-пункт ваг дорівнює нулю (`Z_w = 0`). Тоді аналітичний вираз для обчислення кожного елемента вихідного вектора `y[m]` має вигляд:

```
acc[m] = b[m] + ∑ ( (x[n] - Z_in) · W[m, n] )     [накопичення суми по n від 0 до N-1]
y[m] = clamp( round( acc[m] · M ) + Z_out, -128, 127 )
```

де:
* `acc[m]` — 32-бітний цілочисловий акумулятор (`int32`), що накопичує суму добутків без втрати точності.
* `b[m]` — 32-бітне квантоване зміщення (*quantized bias*), що обчислюється як `b[m] = round(bias_real[m] / (S_in · S_w))`.
* `M = (S_in · S_w) / S_out` — дійсний масштабний коефіцієнт реквантування (`0 < M < 1`), який у цілочисловій арифметиці представляється як `M = M_0 · 2^(-shift)`, де `M_0` — ціле додатне 32-бітне число (`int32`), а `shift` — величина правого бітового зсуву.
* `clamp(v, min, max)` — функція насичення, що обмежує вихідне значення діапазоном `[-128, 127]`.

#### Алгебраїчне розкриття дужок та офлайн-згортання зміщення

Якщо виконувати операцію `(x[n] - Z_in)` у runtime безпосередньо всередині внутрішнього циклу, векторному процесору довелося б на кожному кроці завантажувати вектор нуль-пункту `Z_in` та віднімати його від вектора активацій. Це сповільнило б конвеєр щонайменше на один такт на кожен векторний блок.

Застосуємо алгебраїчне розкриття суми:

```
∑ ( (x[n] - Z_in) · W[m, n] )
= ∑ (x[n] · W[m, n] - Z_in · W[m, n])          [дистрибутивність множення]
= ∑ (x[n] · W[m, n]) - Z_in · ∑ W[m, n]       [винесення константи Z_in за знак суми]
```

Оскільки вагові коефіцієнти `W[m, n]` є статичними й відомими на етапі компіляції моделі, сума рядка ваг `RowSum[m] = ∑ W[m, n]` може бути обчислена заздалегідь під час підготовки моделі (*Offline Pre-computation*).

Тоді згорнуте ефективне зміщення `b_eff[m]` обчислюється як:

```
b_eff[m] = b[m] - Z_in · ∑ W[m, n]             [згортання нуль-пункту у зміщення]
```

Завдяки цьому під час інференсу векторне ядро виконує чисте скалярне перемноження `∑ (x[n] · W[m, n])` без жодних проміжних віднімань `Z_in`, починаючи накопичення одразу зі значення `b_eff[m]`. Це усуває всі зайві інструкції та дозволяє повністю задіяти апаратний помножувач MAC на максимальній швидкості.

#### Поканальне квантування (Per-Channel Quantization)

У складних нейромережах ваги різних вихідних нейронів мають різний динамічний діапазон. При по-тензорному квантуванні (*Per-Tensor*) єдиний масштабний коефіцієнт `S_w` змушений покривати весь тензор, що призводить до втрати точності на нейронах із малими вагами.

При поканальному квантуванні (*Per-Channel / Per-Axis*) кожен вихідний нейрон `m` отримує власний масштабний коефіцієнт `S_w[m]`. Відповідно, масштаб реквантування стає масивом `M[m] = (S_in · S_w[m]) / S_out`, що розпадається на два вектори цілих чисел: `output_multiplier[m]` та `output_shift[m]`.

Векторний конвеєр обробляє поканальні параметри природним чином: реквантування виконується на зовнішньому рівні циклу після накопичення повного скалярного добутку для нейрона `m`, не сповільнюючи внутрішній цикл множення.

### Архітектура та організація регістрів Xtensa PIE

Векторний співпроцесор PIE у ядрі Xtensa LX7 надає 8 широких 128-бітних регістрів (`q0`–`q7`). Для максимальної швидкодії алгоритму множення матриці на вектор розроблено таку карту розподілу регістрів:

* **Регістр `q0` (Вхідні активації):** утримує поточний блок із 16 квантованих байтів вектора `x`.
* **Регістр `q1` (Ваги нейрона `m`):** утримує 16 байтів ваг `W[m, 0..15]`.
* **Регістр `q2` (Ваги нейрона `m+1`):** утримує 16 байтів ваг `W[m+1, 0..15]`.
* **Регістри `q3` та `q4` (Добутки):** утримують проміжні 16-бітні та 32-бітні добутки векторного множення `EE.VMUL.S8`.
* **Регістри `q5`, `q6`, `q7` (Робочі регістри реквантування):** використовуються під час фази масштабування `M_0`, бітового зсуву та насичення.
* **Скалярні регістри `a2`–`a7`:** використовуються для збереження базових адрес вхідного вектора, матриці ваг, вектора зміщень та лічильників блоків.

```
+-----------------------------------------------------------------------------------+
|                     Карта регістрів Xtensa PIE для шару FC                        |
|                                                                                   |
|  +-----------------------------------------------------------------------------+  |
|  | q0: Вхідний вектор x[0..15] (16 байтів int8, спільний для m та m+1)         |  |
|  +-----------------------------------------------------------------------------+  |
|                                                                                   |
|  +-------------------------------------+ +-------------------------------------+  |
|  | q1: Рядок ваг W[m, 0..15] (16 байт) | | q2: Рядок ваг W[m+1, 0..15] (16 байт)|  |
|  +-------------------------------------+ +-------------------------------------+  |
|                   |                                           |                   |
|                   v                                           v                   |
|  +-------------------------------------+ +-------------------------------------+  |
|  | q3: Добутки x · W[m] (8× MAC пар)   | | q4: Добутки x · W[m+1] (8× MAC пар) |  |
|  +-------------------------------------+ +-------------------------------------+  |
|                   |                                           |                   |
|                   v                                           v                   |
|  +-------------------------------------+ +-------------------------------------+  |
|  | Акумулятор acc0 (int32)             | | Акумулятор acc1 (int32)             |  |
|  +-------------------------------------+ +-------------------------------------+  |
+-----------------------------------------------------------------------------------+
```

#### Порядок виконання інструкцій у тілі циклу

Внутрішній блок циклу обробки 16 байтів входу будується за принципом чергування завантаження та обчислення:

1. `EE.LD.128.USAR.IP q0, a2, 16` — завантажує 16 байтів вхідного вектора в `q0` і збільшує вказівник `a2` на 16.
2. `EE.LD.128.USAR.IP q1, a3, 16` — завантажує 16 байтів ваг першого нейрона в `q1` і збільшує вказівник `a3` на 16.
3. `EE.LD.128.USAR.IP q2, a4, 16` — завантажує 16 байтів ваг другого нейрона в `q2` і збільшує вказівник `a4` на 16.
4. `EE.VMUL.S8 q3, q0, q1` — паралельне знакове множення 8-бітних елементів для першого нейрона.
5. `EE.VMUL.S8 q4, q0, q2` — паралельне знакове множення 8-бітних елементів для другого нейрона.
6. Векторне накопичення сум у 32-бітних акумуляторах.

Оскільки завантажений вектор `q0` використовується двічі (для нейрона `m` та нейрона `m+1`), ефективна кількість звернень до шини внутрішньої пам'яті скорочується на 33% порівняно з почерговою обробкою кожного нейрона окремо.

### Глибинний розбір системи команд Xtensa PIE

Для побудови максимально швидких ядер інференсу необхідно розуміти точну семантику кожної інструкції розширення PIE, що використовується в конвеєрі обчислень:

1. **`EE.LD.128.USAR.IP qr, as, imm` (Завантаження 128 біт з автоінкрементом):**
   
   Ця команда виконує вибірку 16 послідовних байтів із пам'яті за адресою, збереженою у 32-бітному скалярному регістрі `as`, та записує їх у 128-бітний векторний регістр `qr`. Одночасно апаратний суматор збільшує значення `as` на константу `imm` (типово 16). Обидві дії виконуються за 1 машинний такт без використання додаткових циклів АЛП. Якщо адреса в `as` не кратна 16 байтам, ядро генерує апаратне виключення невідповідності вирівнювання.

2. **`EE.VMUL.S8 qr, qs, qt` (Векторне множення байтів зі знаком):**
   
   Інструкція розглядає регістри `qs` та `qt` як масиви з шістнадцяти 8-бітних знакових цілих чисел (`int8`). Вісім паралельних помножувачів за 1 такт обчислюють добутки першої половини елементів (`b0..b7`), розширюючи результат до 16-бітних знакових чисел, які зберігаються у відповідних полях вихідного регістра `qr`. Наступна мікрооперація або парна інструкція обробляє другу вісімку байтів (`b8..b15`).

3. **`EE.VMULA.S8.ACCX.LD.IP qr, as, imm` (Суперскалярне множення з накопиченням та завантаженням):**
   
   Найпотужніша комбінована інструкція PIE. Вона одночасно передає поточний вміст регістрів у помножувач MAC із додаванням до розширеного акумулятора `ACCX` і паралельно ініціює вибірку наступного 128-бітного блоку з пам'яті за адресою `as` з автоінкрементом. Завдяки цьому конвеєр досягає 100% насичення обчислювальних блоків.

4. **`EE.SRC.Q.LD.IP qr, qs, qt, as, imm` (Векторне циклічне вікно):**
   
   Використовується в згорткових ядрах для реалізації зсувного вікна. Інструкція бере два послідовні 128-бітні регістри `qs` та `qt`, апаратно зсуває байти на задану величину зсуву та записує вирівняний вектор у `qr`, одночасно підкачуючи наступну порцію даних із пам'яті за покажчиком `as`.

5. **`EE.VMAX.S8` та `EE.VMIN.S8` (Векторний максимум та мінімум):**
   
   Паралельно порівнюють 16 пар чисел `int8` за 1 такт, обираючи максимальне або мінімальне значення для кожного байта. Застосовуються для миттєвої реалізації функцій активації ReLU (`VMAX` із нульовим вектором) та ReLU6 (`VMIN` із вектором шісток).

### Аналіз точності арифметики фіксованої точки

При переході від обчислень із плаваючою комою (*Float32*) до цілочислової арифметики *Int8* виникає питання збереження числової стабільності та запобігання переповненню акумуляторів.

#### Оцінка меж переповнення 32-бітного акумулятора

У повнозв'язному шарі кожен доданок суми є добутком двох 8-бітних чисел зі знаком:

```
min(x · W) = (-128) · 127 = -16256
max(x · W) = (-128) · (-128) = 16384
```

У найгіршому теоретичному випадку, коли всі операнди набувають максимального за модулем значення `128`, сума `N` добутків дорівнює `N · 16384`.

Діапазон 32-бітного знакового цілого числа `int32` становить від `-2 147 483 648` до `+2 147 483 647`. Максимальна довжина вхідного вектора `N_max`, за якої переповнення неможливе математично, дорівнює:

```
N_max = (2 147 483 647) / 16384 = 131 072 елементи
```

Оскільки на мікроконтролерах розмірність шарів зазвичай не перевищує 512–2048 елементів, 32-бітний акумулятор `int32` має запас міцності понад **64×** і гарантує абсолютну математичну стійкість до переповнення без потреби використання повільних 64-бітних операцій.

#### Нормалізація масштабного коефіцієнта (Q31 Fixed-Point)

Масштабний множник реквантування `M = (S_in · S_w) / S_out` завжди знаходиться в діапазоні `(0, 1)`. Для точного представлення в цілих числах значення `M` нормалізується у форматі **Q31**:

```
M = M_0 · 2^(-shift),   де 0.5 ≤ (M_0 / 2^31) < 1.0
```

Ціле 32-бітне число `M_0` обчислюється як:

```
M_0 = round( M · 2^(31 + shift) )
```

Величина `shift` підбирається автоматично за допомогою підрахунку провідних нулів (`__builtin_clz`), максимізуючи розрядність `M_0` у 31 біті, що зводить похибку округлення реквантування до менш ніж `0.00001%`.

### Модель Roofline: пропускна здатність пам'яті проти обчислень

Для розуміння граничної швидкодії інференсу на ESP32-S3 корисно зіставити характеристики обчислювального блоку та підсистеми пам'яті в моделі Roofline:

* **Пікова обчислювальна потужність ядра (Compute Peak):** 
  При частоті 240 МГц одне ядро виконує 8 операцій MAC за такт, що становить `240 · 10^6 × 8 = 1.92 GMAC/s` (або `3.84 GOPS` операцій множення та додавання).

* **Пропускна здатність внутрішньої SRAM (SRAM Bandwidth):**
  128-бітна шина пам'яті передає 16 байтів за такт. При частоті 240 МГц це забезпечує пікову швидкість `240 · 10^6 × 16 = 3.84 ГБ/с`.

* **Пропускна здатність зовнішньої Octal PSRAM (PSRAM Bandwidth):**
  У режимі 80 МГц DDR 8-бітна шина передає 160 МБ/с на кожну пару ліній, досягаючи сумарно `400–800 МБ/с`.

Арифметична інтенсивність повнозв'язного шару розраховується як відношення кількості операцій MAC до обсягу прочитаних із пам'яті байтів. Для матриці ваг розміром `[M × N]` і вхідного вектора `N` кількість операцій дорівнює `M · N` MAC, а обсяг прочитаних даних становить `M · N + N` байтів. Тобто арифметична інтенсивність дорівнює:

```
I = (M · N) / (M · N + N) ≈ 1 MAC / байт
```

Це означає, що для підтримки темпу обчислень 1.92 GMAC/s процесор повинен отримувати дані зі швидкістю щонайменше 1.92 ГБ/с. Внутрішня SRAM із пропускною здатністю 3.84 ГБ/с повністю задовольняє цю вимогу із двократним запасом. Натомість зовнішня PSRAM (0.4–0.8 ГБ/с) стає жорстким вузьким місцем (*Memory Bottleneck*), знижуючи продуктивність у 3–5 разів без застосування подвійної буферизації через GDMA.

### Потокова підкачка ваг через GDMA для великих моделей

Коли розмір матриці ваг перевищує кілька сотень кілобайтів, розмістити всю модель у внутрішній SRAM неможливо. Щоб уникнути катастрофічного падіння швидкодії через кеш-промахи зовнішньої PSRAM, застосовують апаратну конвеєризацію з дескрипторними ланцюжками **GDMA**.

Пам'ять матриці ваг розбивається на однакові блоки (тайли), кратні розміру рядка (наприклад, по 4 КБ). У внутрішній пам'яті SRAM виділяються два робочі буфери: `Buffer_A` та `Buffer_B`.

Контролер GDMA програмується зв'язаним списком дескрипторів `lldesc_t`:

```
+-----------------------------------------------------------------------------------+
|               Конвеєр подвійної буферизації GDMA (Ping-Pong)                      |
|                                                                                   |
|  Крок K:                                                                          |
|  [ CPU (SIMD Core) ] ── обчислює блок N на Buffer_A (SRAM, 1 такт)                |
|  [ GDMA Controller ] ── перекачує блок N+1 із PSRAM у Buffer_B (фоновий DMA)      |
|                                                                                   |
|  Крок K+1 (після завершення обох операцій):                                       |
|  [ CPU (SIMD Core) ] ── перемикається на Buffer_B (обчислює блок N+1)             |
|  [ GDMA Controller ] ── перекачує блок N+2 із PSRAM у Buffer_A (фоновий DMA)      |
+-----------------------------------------------------------------------------------+
```

Ключовим моментом надійності є синхронізація пам'яті: перед передачею буфера процесору викликається функція інвалідації кешу `esp_cache_msync()`, що гарантує узгодженість даних між контролером DMA та L1-кешем ядра.

### Детальний аналіз продуктивності та профілювання конвеєра

Розгляньмо кількісні результати бенчмарку для шару з 256 входами та 128 виходами (`256 × 128 = 32 768` операцій MAC):

1. **Скалярне виконання:**
   
   Загальна кількість тактів становить близько **168 500 тактів** (приблизно 5.14 такта на одну операцію MAC). За тактової частоти 240 МГц час виконання одного шару дорівнює **702 мікросекундам**.

2. **Векторне SIMD-виконання (PIE):**
   
   Загальна кількість тактів падає до **23 800 тактів** (приблизно 0.72 такта на одну операцію MAC завдяки 8-кратному паралелізму та розгортанню циклу). Час виконання шару скорочується до **99 мікросекунд**.

3. **Коефіцієнт реального прискорення:**
   
   Підсумкове прискорення становить **7.08×**, що покриває понад 88% теоретичного максимуму апаратного 8-кратного векторного блоку. Решта 12% припадає на накладні витрати виклику функції, завантаження зміщень та фінальну стадію реквантування.

#### Апаратні лічильники продуктивності (Perfmon & Event Counters)

Окрім базового таймера тактів `CCOUNT`, процесор Xtensa LX7 в ESP32-S3 містить блок апаратного моніторингу продуктивності **Perfmon** (*Performance Monitor*). Він дозволяє підраховувати специфічні мікроархітектурні події:
* Кількість успішно виконаних інструкцій (*Instructions Retired*).
* Кількість тактів зупинки конвеєра через очікування шини пам'яті (*Load-Store Wait Cycles*).
* Кількість промахів у L1 кеші інструкцій та кеші даних (*I-Cache / D-Cache Misses*).

При правильній організації пам'яті у внутрішній SRAM лічильник `Load-Store Wait Cycles` дорівнює нулю, а співвідношення `Cycles / Instruction` (CPI) для векторного тіла циклу наближається до **0.5–0.75**, що свідчить про успішне спрацьовування суперскалярної подвійної видачі інструкцій.

### Типові пастки реалізації та правила надійності

Під час розробки та інтеграції власних SIMD-ядер на ESP32-S3 слід суворо враховувати п'ять апаратних особливостей:

1. **Пастка невирівняних адрес (Alignment Trap):**
   
   Спроба виконати інструкцію `EE.LD.128.USAR.IP` над покажчиком, адреса якого не ділиться на 16 (наприклад, `0x3FC90001`), призведе до негайного виклику апаратного переривання `LoadStoreAlignmentCause`. Звичайний виклик `malloc()` не гарантує 16-байтне вирівнювання (він вирівнює лише на 4 або 8 байтів). Завжди використовуйте функцію `heap_caps_aligned_alloc(16, size, MALLOC_CAP_INTERNAL)` або макрос `__attribute__((aligned(16)))`.

2. **Пастка розміщення буферів у повільній PSRAM:**
   
   Якщо вхідний вектор або матриця ваг розташовані у зовнішній PSRAM, кожен рядок матриці викликатиме промах кешу даних L1. Прискорення замість `6×–7×` впаде до `1.2×–1.5×`. Буфери активацій поточного шару повинні гарантовано знаходитися у внутрішній пам'яті SRAM.

3. **Пастка числового переповнення акумулятора:**
   
   При підсумовуванні добутків 8-бітних чисел (`int8 × int8 = int16`, максимальне значення `128 × 128 = 16384`) сума 256 елементів може сягати `256 × 16384 = 4 194 304`. Вона гарантовано вміщується у 32-бітний акумулятор `int32` (діапазон до `2.14 × 10^9`). Однак якщо шар має понад 130 000 входів (що рідко зустрічається на мікроконтролерах), слід використовувати 40-бітні розширені акумулятори `ACCX`.

4. **Пастка некратного розміру вхідного вектора (Padding):**
   
   Якщо кількість входів нейромережі не ділиться на 16 (наприклад, шар із 150 входами), пряме 128-бітне завантаження вийде за межі виділеного масиву на останній ітерації. Рішення — завжди вирівнювати розмірність матриць ваг та буферів угору до найближчого кратного 16 числа за допомогою додавання фіктивних нульових ваг (*zero-padding*).

5. **Багатоядерне розпаралелювання (Multicore Task Affinity):**
   
   ESP32-S3 має два незалежні ядра Xtensa LX7, кожне з яких містить власний векторний блок PIE. Для важких моделей рекомендується ділити вихідні нейрони між двома ядрами (наприклад, ядро 0 обчислює виходи `0..63`, а ядро 1 — виходи `64..127`), прив'язуючи задачі через `xTaskCreatePinnedToCore()`. Це подвоює сумарну пропускну здатність інференсу до **14×** порівняно з одноядерним скалярним виконанням.
