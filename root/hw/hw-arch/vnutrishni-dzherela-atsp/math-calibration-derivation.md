# 🧮 Математичне виведення формул відновлення напруги та температури

Вбудовані аналогові вимірювання в мікроконтролері спираються на логометричне перетворення: цифровий вихідний код АЦП є відношенням вимірюваної напруги до поточної опорної напруги перетворювача. Нижче наведено аналітичні вирази для розрахунку напруги живлення, довільних вхідних каналів та температури кристала з урахуванням заводського двоточкового калібрування.

---

### Математична модель SAR АЦП та виведення напруги живлення (VDDA)

Аналого-цифровий перетворювач послідовного наближення (SAR ADC) формує цифровий код шляхом порівняння заряду вибіркового конденсатора з ваговими коефіцієнтами ємнісної матриці ЦАП перерозподілу заряду. Опорним потенціалом для ємнісної матриці виступає напруга на шині `V_REF+`. У більшості мікроконтролерів без окремого виводу опори шина `V_REF+` жорстко підключена до шини живлення аналогової периферії `VDDA`.

Для 12-бітного перетворювача ідеальний вихідний код при перетворенні довільної вхідної напруги `V_IN` записується базовим рівнянням квантування:

```text
Raw_IN = 4095 * (V_IN / VDDA)                           [1. Базове рівняння квантування SAR АЦП]
```

Опорна напруга `V_REFINT`, сформована внутрішнім кремнієвим стабілізатором забороненої зони (bandgap reference), має високу внутрішню стабільність і практично не залежить від коливань шини живлення завдяки високому коефіцієнту придушення нестабільності живлення (PSRR > 55 дБ):

```text
V_REFINT = const ≈ 1.212 В                              [2. Фізична стабільність опори VREFINT]
```

Під час вимірювання каналу внутрішньої опори за поточної невідомої напруги живлення `VDDA` поточний сирий код АЦП дорівнює:

```text
Raw_VREFINT = 4095 * (V_REFINT / VDDA)                  [3. Код опори в поточному робочому режимі]
```

Під час заводського калібрування на автоматизованому тестовому стенді (ATE) живлення процесора встановлюється на суворо фіксований еталонний рівень `V_DDA_CAL = 3000 мВ` з точністю вище 0.05%. Відповідний виміряний цифровий код `VREFINT_CAL` прошивається у постійну пам'ять (Flash ROM):

```text
VREFINT_CAL = 4095 * (V_REFINT / V_DDA_CAL)             [4. Заводський калібрувальний код у ROM]
```

Поділивши рівняння (4) на рівняння (3), отримуємо пропорційне співвідношення між еталонним і робочим відліками:

```text
VREFINT_CAL / Raw_VREFINT = (4095 * V_REFINT / V_DDA_CAL) / (4095 * V_REFINT / VDDA)
                          = VDDA / V_DDA_CAL            [5. Скорочення невідомої константи V_REFINT]
```

Звідси поточна реальна напруга живлення `VDDA` аналітично виражається через відомі величини:

```text
VDDA = V_DDA_CAL * (VREFINT_CAL / Raw_VREFINT)          [6. Формула точного відновлення напруги VDDA]
```

При еталонній напрузі заводського стенду `V_DDA_CAL = 3000 мВ`:

```text
VDDA (мВ) = 3000 * VREFINT_CAL / Raw_VREFINT            [7. Підсумкова розрахункова формула в мілівольтах]
```

**Критичний теоретичний висновок:** Фізичне абсолютне значення напруги `V_REFINT` повністю скоротилося в процесі ділення. Технологічний розкид напруги bandgap від кристала до кристала (наприклад 1.205 В в одному чіпі та 1.225 В в іншому) не вносить жодної похибки в розрахунок `VDDA`, оскільки повністю компенсується індивідуальним фабричним коефіцієнтом `VREFINT_CAL`.

### Відновлення абсолютної напруги на зовнішньому аналоговому вході

Для довільного аналогового каналу `X` з невідомою вхідною напругою `V_IN_X` сирий вихідний код перетворення становить:

```text
Raw_X = 4095 * (V_IN_X / VDDA)                          [8. Рівняння перетворення зовнішнього каналу]
```

Виразимо шукану вхідну напругу `V_IN_X`:

```text
V_IN_X = VDDA * (Raw_X / 4095)                          [9. Відновлення вхідного потенціалу через VDDA]
```

Підставивши вираз для поточної напруги `VDDA` з формули (6):

```text
V_IN_X = [ V_DDA_CAL * (VREFINT_CAL / Raw_VREFINT) ] * (Raw_X / 4095)
       = V_DDA_CAL * (VREFINT_CAL * Raw_X) / (4095 * Raw_VREFINT)  [10. Точна формула зовнішнього каналу]
```

Цей результат забезпечує абсолютну стабільність вимірювання напруги на будь-якому вході мікроконтролера без зовнішнього джерела опорної напруги, навіть якщо батарея живлення розряджається з 3.6 В до 2.0 В або під дією імпульсних навантажень просідає шина живлення.

### Фізична модель та двоточкове калібрування датчика температури

Пряма напруга p-n переходу кремнієвого термодіода або біполярного транзистора при постійному прямому струмі зміщення описується напівпровідниковим рівнянням:

```text
V_BE(T) = V_G0 * (1 - T / T0) + V_BE0 * (T / T0) - (η - α) * (k * T / q) * ln(T / T0)  [11. Модель p-n переходу]
```

де:
- `V_G0` — напруга екстрапольованої ширини забороненої зони кремнію при абсолютному нулі (1.205 В);
- `V_BE0` — напруга прямого переходу при опорній кімнатній температурі T0 (близько 0.65 В при 300 К);
- `k` — стала Больцмана, `q` — елементарний заряд електрона;
- `η, α` — технологічні параметри рекомбінації та температурної залежності рухливості носіїв заряду.

У робочому температурному інтервалі від -40 °C до +125 °C нелінійний член з логарифмом вносить відхилення менше 0.5 °C. Тому реальна характеристика термодатчика з високою точністю лінеаризується:

```text
V_SENSE(T) = V_SENSE(T0) + S * (T - T0)                 [12. Лінеаризована передавальна характеристика]
```

де `S = dV / dT` — температурний коефіцієнт напруги (типово -2.0 мВ/°C ... -2.5 мВ/°C або +2.5 мВ/°C у схемах з диференційним підсилювачем).

Оскільки технологічний зсув `V_SENSE(T0)` через варіації легування досягає ±45 мВ, що дає похибку некаліброваного датчика до ±18 °C, застосовується калібрування за двома точками:
- `TS_CAL1` — код при T1 = 30 °C (`VDDA = 3000 мВ`);
- `TS_CAL2` — код при T2 = 110 °C або 130 °C (`VDDA = 3000 мВ`).

#### Крок 1. Нормалізація виміряного коду датчика температури

Якщо поточна напруга живлення `VDDA` відрізняється від еталонних 3000 мВ, сирий код `Raw_TS` масштабується до шкали калібрування:

```text
Raw_TS_norm = Raw_TS * (VDDA / 3000)                    [13. Приведення до еталонного VDDA]
```

Підставивши `VDDA` з формули (7):

```text
Raw_TS_norm = Raw_TS * [ (3000 * VREFINT_CAL / Raw_VREFINT) / 3000 ]
            = Raw_TS * VREFINT_CAL / Raw_VREFINT        [14. Нормалізований код температури]
```

#### Крок 2. Лінійна інтерполяція між двома калібрувальними точками

Рівняння прямої, що проходить через точки `(T1, TS_CAL1)` та `(T2, TS_CAL2)`:

```text
(T - T1) / (T2 - T1) = (Raw_TS_norm - TS_CAL1) / (TS_CAL2 - TS_CAL1)  [15. Лінійна пропорція]
```

Виразивши температуру `T`:

```text
T = [ (T2 - T1) / (TS_CAL2 - TS_CAL1) ] * (Raw_TS_norm - TS_CAL1) + T1  [16. Температура кристала]
```

Для T1 = 30 °C та T2 = 130 °C (`T2 - T1 = 100 °C`):

```text
T (°C) = 100 * (Raw_TS_norm - TS_CAL1) / (TS_CAL2 - TS_CAL1) + 30     [17. Підсумкова формула]
```

### Аналіз чутливості та розповсюдження похибок

Визначимо похибку розрахунку `VDDA`, викликану шумом квантування АЦП ±0.5 LSB у каналі `Raw_VREFINT`.

Візьмемо частинну похідну від функції `VDDA(Raw_VREFINT)`:

```text
d(VDDA) / d(Raw_VREFINT) = - (V_DDA_CAL * VREFINT_CAL) / (Raw_VREFINT)^2
                         = - VDDA / Raw_VREFINT         [18. Чутливість напруги до шуму АЦП]
```

При `VDDA = 3.3 В` та `V_REFINT = 1.212 В`:
- `Raw_VREFINT = 4095 * (1.212 / 3.3) ≈ 1504 LSB`;
- Шумова похибка `d(VDDA)` при зміні на 1 LSB:

```text
|d(VDDA)| = 3300 мВ / 1504 ≈ 2.19 мВ на 1 LSB шуму      [19. Вага одного кванта шуму]
```

Аналогічно, для каналу температури чутливість коду становить близько 3.4 LSB на 1 °C. Отже, похибка оцифрування в 1 LSB відповідає похибці визначення температури близько 0.29 °C:

```text
dT / d(Raw_TS) = 100 °C / (TS_CAL2 - TS_CAL1) ≈ 100 / 345 ≈ 0.29 °C / LSB  [20. Чутливість температури]
```

Випадковий білий шум АЦП амплітудою ±2 LSB дає коливання розрахункової напруги живлення близько ±4.4 мВ. Для усунення цієї похибки застосовується апаратне або програмне оверсемплювання (усереднення 16–64 вимірювань), що знижує дисперсію шуму у корінь з N разів.

### Цілочисельна арифметика фіксованої коми з округленням

Щоб уникнути використання повільних бібліотек плаваючої коми на процесорах без апаратного FPU (Cortex-M0/M0+/M3), обчислення виконуються в цілих числах з додаванням половини дільника для симетричного математичного округлення:

:::tabs
=== "C"
```c
#include <stdint.h>

/**
 * @brief Цілочисельний розрахунок фізичних параметрів
 */
void calculate_fixed_point(uint16_t vrefint_cal,
                           uint16_t ts_cal1,
                           uint16_t ts_cal2,
                           uint16_t raw_vrefint,
                           uint16_t raw_ts,
                           uint16_t raw_channel,
                           uint32_t *out_vdda_mv,
                           int32_t  *out_temp_01c,
                           uint32_t *out_channel_mv) {
    if (raw_vrefint == 0) return;

    /* 1. Розрахунок VDDA в мВ з математичним округленням */
    uint32_t vdda_mv = ((uint32_t)3000 * vrefint_cal + (raw_vrefint / 2U)) / raw_vrefint;
    *out_vdda_mv = vdda_mv;

    /* 2. Нормалізація коду термодатчика до напруги 3.0 В */
    uint32_t ts_norm = ((uint32_t)raw_ts * vrefint_cal + (raw_vrefint / 2U)) / raw_vrefint;

    /* 3. Розрахунок температури в десятих частках °C (0.1 °C) */
    int32_t delta_cal = (int32_t)ts_cal2 - (int32_t)ts_cal1;
    if (delta_cal != 0) {
        int32_t temp_01c = ((int32_t)(ts_norm - ts_cal1) * 1000 + (delta_cal / 2)) / delta_cal + 300;
        *out_temp_01c = temp_01c;
    }

    /* 4. Відновлення напруги зовнішнього входу в мВ */
    uint32_t vin_mv = (vdda_mv * (uint32_t)raw_channel + 2047U) / 4095U;
    *out_channel_mv = vin_mv;
}
```
=== "C++"
```cpp
#include <cstdint>
#include <tuple>

namespace McuAdc::Math {

struct CalculationResult {
    uint32_t vdda_mv{0};
    int32_t  temperature_deci_celsius{0};
    uint32_t channel_mv{0};
};

[[nodiscard]] constexpr CalculationResult calculate_fixed_point(
    uint16_t vrefint_cal,
    uint16_t ts_cal1,
    uint16_t ts_cal2,
    uint16_t raw_vrefint,
    uint16_t raw_ts,
    uint16_t raw_channel) noexcept {
    
    if (raw_vrefint == 0) {
        return {};
    }

    CalculationResult res;

    // 1. VDDA в мВ з симетричним округленням
    const uint32_t vdda_mv = (static_cast<uint32_t>(3000) * vrefint_cal + (raw_vrefint / 2U)) / raw_vrefint;
    res.vdda_mv = vdda_mv;

    // 2. Нормалізація термодатчика
    const uint32_t ts_norm = (static_cast<uint32_t>(raw_ts) * vrefint_cal + (raw_vrefint / 2U)) / raw_vrefint;

    // 3. Температура в 0.1 °C
    const int32_t delta_cal = static_cast<int32_t>(ts_cal2) - static_cast<int32_t>(ts_cal1);
    if (delta_cal > 0) {
        res.temperature_deci_celsius = ((static_cast<int32_t>(ts_norm - ts_cal1) * 1000 + (delta_cal / 2)) / delta_cal) + 300;
    }

    // 4. Зовнішній канал
    res.channel_mv = (vdda_mv * static_cast<uint32_t>(raw_channel) + 2047U) / 4095U;

    return res;
}

} // namespace McuAdc::Math
```
