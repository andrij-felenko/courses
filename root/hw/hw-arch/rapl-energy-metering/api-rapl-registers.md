# 📋 Регістри та інтерфейси RAPL: MSR, sysfs powercap та perf PMU

Для взаємодії з апаратною підсистемою керування живленням та обліку енергії процесорів x86 операційна система Linux та діагностичні утиліти використовують три взаємодоповнюючі інтерфейси: прямий доступ до моделе-залежних регістрів MSR, віртуальну файлову систему `sysfs` через підсистему Power Capping Framework та лічильники продуктивності ядра `perf_event`. Цей довідник містить вичерпний опис бітових полів регістрів, числових адрес Intel та AMD, формул перерахунку одиниць вимірювання, ієрархії файлів драйвера та параметрів конфігурації.

### Структура регістра одиниць вимірювання MSR_RAPL_POWER_UNIT (0x606)

Регістр `MSR_RAPL_POWER_UNIT` визначає двійкові показники степеня для масштабування числових значень у всіх інших MSR підсистеми RAPL. Програмне забезпечення зчитує цей регістр першим при ініціалізації драйвера для обчислення цін квантів.

```
Бітова розкладка MSR_RAPL_POWER_UNIT:
 63                               20 19      16 15  13 12       8 7    4 3       0
┌───────────────────────────────────┬──────────┬──────┬──────────┬──────┬──────────┐
│ Зарезервовано (повинно бути 0)    │    TU    │ Рез  │   ESU    │ Рез  │    PU    │
└───────────────────────────────────┴──────────┴──────┴──────────┴──────┴──────────┘
```

Поля регістра та формули перерахунку:
- **`PU` (Power Units, біти [3:0])**: цілочисельний показник степеня для потужності. Базова одиниця потужності в ватах розраховується як:
  ```
  Unit_Power = 1 / (2^PU)   [Вати]
  ```
  *Типове значення*: `PU = 3`, тобто `1 / 2^3 = 0.125` Вт на відлік. Якщо у полі ліміту записано число 800, реальний ліміт становить `800 · 0.125 = 100.0` Вт.
- **`ESU` (Energy Status Units, біти [12:8])**: цілочисельний показник степеня для лічильників накопиченої енергії. Базовий квант енергії в джоулях дорівнює:
  ```
  Unit_Energy = 1 / (2^ESU)   [Джоулі]
  ```
  *Типове значення*: `ESU = 16`, що відповідає `1 / 65536 ≈ 15.258789` мкДж на один квант лічильника. Для домену оперативної пам'яті DRAM на деяких серверних процесорах Intel Xeon поколінь Haswell-EP та Broadwell-EP використовується фіксований коефіцієнт `ESU = 14` (ціна кванта `1 / 16384 ≈ 61.035` мкДж).
- **`TU` (Time Units, біти [19:16])**: цілочисельний показник степеня для часових вікон обмеження потужності. Базова одиниця часу в секундах дорівнює:
  ```
  Unit_Time = 1 / (2^TU)   [Секунди]
  ```
  *Типове значення*: `TU = 10`, що відповідає `1 / 1024 ≈ 0.97656` мілісекунди на одиницю.

### Структура регістрів лічильників енергії MSR_*_ENERGY_STATUS

Регістри `MSR_PKG_ENERGY_STATUS`, `MSR_PP0_ENERGY_STATUS`, `MSR_DRAM_ENERGY_STATUS` та `MSR_PLATFORM_ENERGY_STATUS` мають уніфіковану 64-бітну організацію:

```
Бітова розкладка MSR_*_ENERGY_STATUS:
 63                                              32 31                             0
┌──────────────────────────────────────────────────┬─────────────────────────────────┐
│ Зарезервовано (завжди повертає 0)                │ Total Energy Consumed (32 біти) │
└──────────────────────────────────────────────────┴─────────────────────────────────┘
```

Особливості функціонування лічильника:
- Молодші 32 біти регістра містять монотонно зростаюче беззнакове ціле число накопичених квантів енергії.
- Старші 32 біти зарезервовані архітектурою і завжди повертають нулі при читанні інструкцією `RDMSR`.
- При досягненні максимального значення `2^32 - 1 = 4 294 967 295` лічильник апаратно переповнюється і скидається в нуль, продовжуючи безперервне нарощування.
- Різниця енергії між двома послідовними замірами у квантах лічильника для типу даних `uint32_t`:
  ```
  ΔE_ticks = (uint32_t)(E_current - E_previous)
  ```
- Реальна витрачена енергія у джоулях за інтервал спостереження:
  ```
  ΔE_Joules = ΔE_ticks · Unit_Energy
  ```

### Структура регістра керування лімітами MSR_PKG_POWER_LIMIT (0x610)

Цей регістр дозволяє ядру операційної системи або низькорівневому системному демону динамічно обмежувати максимальну потужність сокета на двох незалежних часових горизонтах: PL1 (довготривалий ліміт TDP) та PL2 (короткочасний турбо-сплеск).

```
Бітова розкладка MSR_PKG_POWER_LIMIT:
 63 62 61   56 55   54 53 49 48 47 46        32 31 30 29   24 23   22 21 17 16 15 14        0
┌──┬──┬───────┬───────┬──┬─────┬──┬─────────────┬──┬──┬───────┬───────┬──┬─────┬──┬─────────────┐
│L │L2│  Y2   │  Z2   │C2│ Рез │E2│ Power Lim 2 │L │L1│  Y1   │  Z1   │C1│ Рез │E1│ Power Lim 1 │
└──┴──┴───────┴───────┴──┴─────┴──┴─────────────┴──┴──┴───────┴───────┴──┴─────┴──┴─────────────┘
```

Повний опис бітових полів:
- **`Power Limit 1` (біти [14:0])** та **`Power Limit 2` (біти [46:32])**: беззнакові 15-бітні цілі числа ліміту потужності. Фізична потужність у ватах обчислюється як: `P_limit = Value · Unit_Power`.
- **`Enable (E1 / E2)` (біти 15 та 47)**: `1` — ліміт активний і примусово утримується апаратним мікроконтролером PCU; `0` — ліміт вимкнено.
- **`Clamping Limit (C1 / C2)` (біти 16 та 48)**: `1` — мікроконтролеру PCU дозволено знижувати робочу тактову частоту ядер нижче базової номінальної частоти P1 (аж до найнижчого P-стану енергозбереження Pn) задля утримання ліміту; `0` — частота ядер ніколи не опускається нижче базової паспортної позначки, навіть якщо це призведе до тимчасового перевищення встановленого ліміту потужності.
- **`Time Window Exponent (Y1 / Y2)` (біти [21:17] та [53:49])** — 5-бітний двійковий показник степеня часового вікна.
- **`Time Window Mantissa (Z1 / Z2)` (біти [23:22] та [55:54])** — 2-бітна мантиса часового вікна.
- **Формула часового вікна**: тривалість ковзного вікна інтегрування енергії в секундах обчислюється як:
  ```
  Time_Window = (1 + Z / 4) · 2^Y · Unit_Time
  ```
- **`Lock (L)` (біт 63)**: при записі `1` у цей біт весь конфігураційний регістр апаратно блокується від будь-яких подальших змін через команду `WRMSR`. Розблокування можливе лише при повному скиданні платформи (апаратному перезавантаженні).

### Структура регістра специфікацій кремнію MSR_PKG_POWER_INFO (0x614)

Регістр `MSR_PKG_POWER_INFO` містить незмінні заводські параметри процесорного кристала, зашиті під час виробництва та тестування на фабриці:

```
Бітова розкладка MSR_PKG_POWER_INFO:
 63       55 54      48 47       32 31       16 15        0
┌───────────┬──────────┬───────────┬───────────┬───────────┐
│ Зарезерв  │ Max Time │ Max Power │ Min Power │ TDP Power │
└───────────┴──────────┴───────────┴───────────┴───────────┘
```

- **`Thermal Spec Power` (біти [14:0])**: номінальний паспортний тепловий пакет TDP кристала у ватах (`Value · Unit_Power`).
- **`Minimum Power` (біти [30:16])**: мінімальна потужність, нижче якої процесор не може стабільно функціонувати навіть у стані максимального тротлінгу.
- **`Maximum Power` (біти [46:32])**: максимальна пікова електрична потужність, яку здатні витримати внутрішні провідники кремнію без фізичної деградації.
- **`Maximum Time Window` (біти [54:48])**: максимальне часове вікно, яке підтримує апаратний інтегратор PCU для згладжування сплесків навантаження.

### Інтерфейс Linux Power Capping Framework (sysfs)

Ядро Linux експортує ієрархічне дерево керування живленням через віртуальну файлову систему за шляхом `/sys/class/powercap/intel-rapl/`.

```
Ієрархія файлової системи sysfs:
/sys/class/powercap/intel-rapl/
├── intel-rapl:0/                    (Сокет 0 / PKG)
│   ├── name                         ("package-0")
│   ├── enabled                      (1 або 0)
│   ├── energy_uj                    (накопичена енергія в мікроджоулях)
│   ├── max_energy_range_uj          (максимальне значення лічильника в мкДж)
│   ├── constraint_0_name            ("long_term" / ліміт PL1)
│   ├── constraint_0_power_limit_uw  (ліміт потужності PL1 у мікроватах)
│   ├── constraint_0_time_window_us  (часове вікно PL1 у мікросекундах)
│   ├── constraint_1_name            ("short_term" / ліміт PL2)
│   ├── constraint_1_power_limit_uw  (ліміт потужності PL2 у мікроватах)
│   ├── constraint_1_time_window_us  (часове вікно PL2 у мікросекундах)
│   ├── intel-rapl:0:0/              (Субдомен ядер PP0 / Core)
│   │   ├── name                     ("core")
│   │   ├── energy_uj
│   │   └── max_energy_range_uj
│   ├── intel-rapl:0:1/              (Субдомен графіки PP1 / Uncore)
│   │   ├── name                     ("uncore" або "dram")
│   │   └── energy_uj
│   └── intel-rapl:0:2/              (Субдомен оперативної пам'яті DRAM)
│       ├── name                     ("dram")
│       └── energy_uj
└── intel-rapl:1/                    (Сокет 1 для багатопроцесорних серверів)
```

Атрибути файлів sysfs та їхні особливості:
- `energy_uj`: текстовий файл, читання якого повертає поточне 64-бітне значення накопиченої енергії у мікроджоулях. Драйвер ядра `intel_rapl_common.c` автоматично зчитує апаратний 32-бітний MSR, множить його на коефіцієнт `Unit_Energy` та транслює у мікроджоулі.
- `max_energy_range_uj`: період повного переповнення внутрішнього апаратного лічильника, перерахований у мікроджоулі.
- `constraint_N_power_limit_uw`: запис числа у цей файл дозволяє виставити ліміт потужності у мікроватах (`1 Вт = 1 000 000 мкВт`).
- `constraint_N_time_window_us`: запис числа виставляє тривалість ковзного вікна інтегрування у мікросекундах.
- **Права доступу**: після усунення уразливості PLATYPUS файли `energy_uj` мають права `0400` (*тільки читання суперкористувачем root*). Файли керування лімітами мають права `0600`.

### Інтерфейс підсистеми Perf Events у Linux

Підсистема `perf_event` ядра Linux надає віртуальний драйвер PMU з назвою `power`. Цей драйвер транслює апаратні лічильники RAPL у формат стандартних системних подій моніторингу.

Каталог опису подій знаходиться за шляхом `/sys/bus/event_source/devices/power/events/`:
- `energy-pkg`: накопичена енергія процесорного сокета (код конфігурації події `event=0x02`). Одиниця вимірювання за замовчуванням — Джоулі.
- `energy-cores`: накопичена енергія обчислювальних ядер PP0 (код події `event=0x01`).
- `energy-ram`: накопичена енергія каналів оперативної пам'яті DRAM (код події `event=0x03`).
- `energy-gpu`: накопичена енергія інтегрованого графічного ядра PP1 (код події `event=0x04`).
- `energy-psys`: накопичена енергія системної плати SoC (код події `event=0x05`).

Приклад моніторингу за допомогою системної CLI-утиліти:
```
perf stat -a -e power/energy-pkg/,power/energy-cores/,power/energy-ram/ sleep 5
```

Коди помилок та статусів при роботі з інтерфейсами:
- `EACCES` / `EPERM` (`13` / `1`): спроба відкриття файлу сенсора без прав адміністратора (відсутність можливості ядра `CAP_SYS_RAWIO`).
- `ENODEV` / `ENOENT` (`19` / `2`): запитаний апаратний домен (наприклад, DRAM на клієнтському чипі або PP1 на серверному Xeon) фізично не реалізований у поточному степінгу кремнію.
- `EBUSY` (`16`): конфлікт доступу до MSR або спроба перезапису регістра після встановлення біта `Lock`.
- `EINVAL` (`22`): передано значення ліміту потужності або часового вікна, що виходить за межі діапазону регістра `MSR_PKG_POWER_INFO`.
