# Strapping-піни й режими завантаження

<preknowlist>
- [Причини reset](root:hw-arch/reset-causes) — як формується сигнал скидання і як працює Power-on Reset.
- [Bootloader](root:hw-arch/bootloader) — хто перехоплює керування після скидання і навіщо потрібні щаблі завантаження.
- [Тактування й живлення](root:hw-arch/clock-power) — стабілізація напруг та частот при старті мікроконтролера.
- [Регістри вводу-виводу (MMIO)](root:hw-arch/memory-mapped-io) — як конфігуруються апаратні піни та периферія.
- [Мікроконтролер](root:hw-arch/microcontroller) — базова структура однокристальної системи та підключення Flash.
</preknowlist>

Коли напруга живлення мікроконтролера перетинає поріг стабілізації, лічильник команд (*program counter*) ще не зробив жодного такту, а внутрішня пам'ять SRAM заповнена випадковим сміттям. Проте апаратура кристала вже в цю частку наносекунди має однозначно знати відповіді на фундаментальні запитання: з якої фізичної шини завантажувати перший сектор коду — з внутрішньої Flash, зовнішньої Quad-SPI мікросхеми, SD-карти, шини eMMC чи з порту USB/UART? Яку напругу видати внутрішньому стабілізатору на виводи живлення пам'яті — 3.3 В чи 1.8 В? Яку початкову частоту тактування обрати для шини SPI? Процесор не може виконати конфігураційну інструкцію з програми, доки не знає, звідки цю інструкцію зчитати. Виникає класична проблема «курки та яйця».

Виділяти під кожен апаратний параметр окремий ізольований перемикач чи вивід корпусу занадто дорого: збільшення кількості виводів (*pin count*) прямо роздуває площу кремнієвого кристала, розміри корпусу (BGA/QFN) та собівартість чипа. Інженерний вихід із цього глухого кута полягає в часовому мультиплексуванні (*time-division multiplexing*): група стандартних ліній вводу-виводу загального призначення (GPIO) отримує подвійну роль. У крихітне часове вікно тривалістю в кілька десятків наносекунд — рівно в момент відпускання сигналу скидання (*Reset Release*) — мікроконтролер опитує електричні потенціали на цих ніжках, намертво замикає їх у внутрішніх апаратних засувках (*hardware latches*) і лише після цього передає піни в розпорядження звичайного драйвера GPIO. Ці конфігураційні виводи називають **strapping-пінами** (від англ. *strap* — «стяжка, фіксатор, ремінець»).

Ціна такого компромісу — крайня вразливість апаратури до зовнішніх схемотехнічних зв'язків. Звичайний світлодіод, обмотка реле чи підтягувальний резистор шини I2C, необачно розпаяний на strapping-виводі, перетворюється на паразитного диверсанта: під час кожного перезавантаження навантаження стягує напругу на піні, чип замикає хибний режим і назавжди зависає у bootloader або безперервно падає у циклічний перезапуск (*boot loop*).

> 🔧 **Навіщо це.** Знання фізики strapping-вузлів позбавляє від найбільш виснажливого класу «містичних» апаратних дефектів: чому щойно розведена друкована плата успішно прошивається на столі через відлагоджувач, але відмовляється самостійно стартувати після подачі живлення від батареї; чому підключення датчика температури викликає циклічний збій читання Flash; як проєктувати схеми ізоляції навантаження, що дозволяють безпечно задіяти всі 100% виводів мікроконтролера без ризику апаратного блокування.

### Фізичний механізм: апаратна засувка й часові таймінги

Щоб зрозуміти, як логічний стан фізичного піна перетворюється на незмінну апаратну конфігурацію чипа, розглянемо структуру вхідного каскаду strapping-вузла в кремнії.

![Внутрішня структура strapping-засувки та часова діаграма захоплення рівнів під час відпускання сигналу скидання](/root/hw/hw-arch/strapping-piny-i-rezhymy-zavantazhennia/img/reset-latch-timing.svg)
*Апаратний механізм strapping-вузла. Ліворуч: кремнієвий вхідний буфер з інтегрованими слабкими підтяжками передає рівень на вхід D апаратної засувки, керованої сигналом RESET_N. Праворуч: часова діаграма відпускання скидання. Рівень на піні має бути стабільним протягом часу встановлення t_su до висхідного фронту RESET_N та часу утримання t_h після нього. Після стробу засувка стає непрозорою, фіксуючи конфігурацію в системному регістрі незалежно від подальших змін на GPIO.*

Вхідний вузол містить три ключові елементи:
1. **Інтегровані слабкі резистори підтяжки (*weak pull-up / pull-down*):** Напівпровідникові структури на польових транзисторах, що формують еквівалентний опір `R_int ≈ 40–100 кОм` до шини `VDD` або `GND`. Їхнє завдання — гарантувати визначений логічний стан (0 або 1) за замовчуванням, якщо фізичний вивід залишено вільним у повітрі (*floating*).
2. **Прозора D-засувка (*Transparent D-Latch*) або стробований тригер:** Вхід даних `D` засувки підключено до лінії виводу через буфер Шмітта, а вхід стробування / дозволу запису `LE` (*Latch Enable*) з'єднано з системною магістраллю внутрішнього скидання `RESET_N`.
3. **Мультиплексор вводу-виводу (GPIO Matrix):** Комутатор, що після завершення фази старту відключає пін від конфігураційної логіки ядра й підключає його до цифрових портів користувача.

#### Послідовність подій у часі (Reset Sequence)

Старт системи розгортається у чотири строго детерміновані фази:

1. **Фаза утримання скидання (`RESET_N = 0`):** Доки зовнішній пін скидання притиснуто до нуля або внутрішня схема [Power-on Reset](root:hw-arch/reset-causes) очікує стабілізації живлення `VDD`, засувка перебуває у прозорому стані: вихід `Q` повторює рівень на вході `D`. Вихідні драйвери GPIO примусово переведені у стан високого імпедансу (*Hi-Z*). Рівень напруги на піні формується виключно внутрішнім слабким резистором та зовнішніми компонентами на платі.
2. **Фаза встановлення (*Setup Time*, `t_su`):** Перед тим, як сигнал скидання почне наростати, напруга на strapping-піні повинна досягти стабільного значення й перебувати вище порога логічної одиниці `V_IH` або нижче порога логічного нуля `V_IL` щонайменше протягом інтервалу `t_su` (типово від 10 до 100 наносекунд).
3. **Момент виходу зі скидання (*Reset De-assertion Edge*):** Напруга `RESET_N` перетинає поріг логічного перемикання (висхідний фронт). За цим фронтом апаратна засувка стає «непрозорою» (зачиняється). Стан на вході `D` у цю єдину мить копіюється у внутрішній системний регістр засувок (наприклад, `GPIO_STRAP_REG` у ESP32 або `SRC_SBMR` у NXP i.MX RT).
4. **Фаза утримання (*Hold Time*, `t_h`):** Рівень на піні повинен залишатися незмінним протягом кількох наносекунд після фронту `RESET_N`, щоб виключити стан метастабільності тригера.
5. **Фаза нормальної роботи (`RESET_N = 1`):** Системна логіка конфігурації заблокована на рівні апаратури кристала. Будь-які подальші зміни напруги на фізичному виводі — перемикання прошивкою в логічну одиницю, зміна частоти, імпульси ШІМ — жодним чином не впливають на збережений у засувці режим роботи ядра. Фізичний вивід повністю передається під контроль модуля [регістрів MMIO](root:hw-arch/memory-mapped-io).

Якщо під час інтервалу `t_su` напруга на піні потрапляє в «сіру зону» невизначеності між `V_IL(max) ≈ 0.25 · V_DD` та `V_IH(min) ≈ 0.75 · V_DD` через повільний перезаряд паразитної ємності, тригер засувки захоплює випадковий біт або входить у метастабільний стан, викликаючи непередбачувану поведінку мікроконтролера.

### Пастки сумісного використання пінів: розбір апаратних конфліктів

Через постійний дефіцит вільних GPIO розробники часто змушені призначати strapping-виводи під звичайну периферію. Розглянемо класичні апаратні пастки на прикладі найпопулярніших платформ.

![Типові конфлікти сумісного використання пінів та методи схемотехнічної ізоляції](/root/hw/hw-arch/strapping-piny-i-rezhymy-zavantazhennia/img/pin-sharing-traps-circuits.svg)
*Пастки підключення периферії на strapping-виводи та методи їхнього усунення. Ліворуч: типові аварійні схеми — світлодіод стягує GPIO0 до нуля, блокуючи запуск з Flash; підтяжка реле на GPIO12 перемикає LDO пам'яті на 1.8 В; відсутність ємності на EN ламає автопрошивку. Праворуч: безпечні рішення з тристабільними буферами 74LVC1G125, N-MOSFET ключами та апаратним спалюванням eFuse.*

#### Пастка 1: Світлодіод або кнопка на ESP32 GPIO0 (Download Mode Trap)
Пін `GPIO0` у класичному ESP32 є головним селектором режиму:
- `GPIO0 = 1` (високий рівень) під час скидання → запуск користувацької програми з SPI Flash.
- `GPIO0 = 0` (низький рівень) під час скидання → вхід у вбудований ROM UART Bootloader (режим очікування завантаження прошивки).

Усередині чипа пін `GPIO0` має слабкий pull-up до 3.3 В опором близько 45 кОм. Якщо розробник підключає до цього піна звичайний світлодіод індикації катодом до землі через струмообмежувальний резистор 1 кОм, виникає резистивний дільник напруги. Розрахунок потенціалу в точці скидання дає:

```
V_GPIO0 = V_DD · (R_led / (R_pullup + R_led))
V_GPIO0 = 3.3 В · (1 кОм / (45 кОм + 1 кОм)) ≈ 0.071 В
```

Оскільки 0.071 В значно менше порога `V_IL ≈ 0.8 В`, мікроконтролер при кожному ввімкненні або натисканні кнопки Reset бачить стабільний нуль і назавжди зависає у режимі UART Bootloader. Прошивка з Flash не запускається ніколи. Аналогічний ефект дає підключення виходу цифрового датчика (наприклад, PIR-сенсора руху або виходу `DO` компаратора), якщо в початковий момент його вихід відкритий на землю.

#### Пастка 2: Модуль реле чи I2C підтяжка на ESP32 GPIO12 (MTDI / Flash Voltage Disaster)
Пін `GPIO12` (сигнал `MTDI` інтерфейсу JTAG) керує вихідною напругою внутрішнього стабілізатора LDO (`VDD_SDIO`), який живить мікросхему SPI Flash пам'яті всередині модуля ESP32-WROOM:
- `GPIO12 = 0` під час скидання → `VDD_SDIO = 3.3 В` (штатний режим для стандартної Flash пам'яті).
- `GPIO12 = 1` під час скидання → `VDD_SDIO = 1.8 В` (режим для низьковольтної пам'яті).

За замовчуванням пін має внутрішній pull-down на 45 кОм. Якщо розробник використовує `GPIO12` для керування модулем реле або транзисторним ключем з класичним захисним резистором підтяжки 4.7 кОм або 10 кОм до шини `+3.3V`, у момент скидання на піні формується напруга:

```
V_GPIO12 = 3.3 В · (45 кОм / (10 кОм + 45 кОм)) ≈ 2.7 В
```

Це впевнена логічна одиниця (`V_GPIO12 > V_IH`). Внутрішній регулятор LDO перемикається на вихідну напругу **1.8 В**. Мікросхема SPI Flash, розрахована на 3.3 В, опиняється в стані глибокого голодування (*brownout*): її внутрішній цифровий автомат пам'яті не відповідає на команди читання. ROM-завантажувач не може вичитати заголовок другого завантажувача з нульового сектора й падає у нескінченний циклічний перезапуск, викидаючи в консоль характерне повідомлення:

```text
rst:0x10 (RTCWDT_RTC_RESET),boot:0x25 (SPI_FAST_FLASH_BOOT)
flash read err, 1000
ets_main.c 371
ets Jun  8 2016 00:22:57
```

Пристрій стає повністю непрацездатним.

#### Пастка 3: Конфлікт виведення діагностики на ESP32 GPIO15 (MTDO)
Пін `GPIO15` (`MTDO`) конфігурує виведення системного логу вбудованого ROM-завантажувача на порт `UART0` під час старту. Якщо під час скидання цей пін притиснутий до нуля зовнішнім навантаженням, ROM повністю глушить початковий вивід у термінал. Розробник бачить порожнечу в консолі на швидкості 115200 бод, що робить неможливою діагностику ранніх збоїв завантаження.

### Схемотехніка безпечної підтяжки, ізоляції та автопрограмування

Щоб виключити конфлікти між конфігурацією на старті та роботою прошивки, застосовують три класи схемотехнічних рішень: розрахунок жорстких підтяжок, активну ізоляцію та схеми керування лініями скидання.

#### 1. Розрахунок зовнішніх підтягувальних резисторів
Щоб надійно пересилити внутрішній слабкий pull-down номіналом `R_int(min) = 40 кОм` і гарантувати рівень логічної одиниці `V_pin ≥ 0.8 · V_DD = 2.64 В`, складаємо рівняння подільника:

```
V_pin = V_DD · (R_int / (R_ext + R_int)) ≥ 0.8 · V_DD
R_int / (R_ext + R_int) ≥ 0.8
R_ext ≤ 0.25 · R_int
R_ext ≤ 0.25 · 40 кОм = 10 кОм
```

Звідси випливає інженерне правило:
- **10 кОм** — граничний максимальний номінал зовнішнього підтягувального резистора для strapping-ліній.
- **4.7 кОм або 3.3 кОм** — рекомендований надійний номінал у промислових умовах із підвищеним рівнем електромагнітних завад (струм через підтяжку `I_pull ≈ 0.7–1.0 мА` гарантовано розряджає паразитні ємності монтажу за лічені наносекунди).

#### 2. Буферизація та ізоляція навантажень
Якщо strapping-пін конче необхідно використовувати як вихід для комутації навантаження, застосовують апаратну розв'язку:

- **Тристабільний буфер `74LVC1G125`:** Вхід дозволу `~OE` з'єднують із лінією скидання або керуючим не-strapping GPIO через pull-up 10 кОм. Під час скидання вихід буфера перебуває в ізольованому стані *Hi-Z* (струм витоку `< 1 мкА`), повністю відсікаючи навантаження від піна.
- **Ключ на N-MOSFET (наприклад, `2N7002` або `BSS138`):** Затвор польового транзистора підключають до strapping-піна, а між затвором і землею встановлюють резистор розрядки `100 кОм`. Оскільки затвор має майже нескінченний опір постійному струму, він не створює навантаження на пін, а резистор 100 кОм надійно тримає ключ закритим до старту прошивки.
- Детальні схеми комутації та розрахунки оптопар наведено у вставці [Схемотехніка ізоляції та буферизації strapping-виводів](root:hw-arch/strapping-piny-i-rezhymy-zavantazhennia/comp-strapping-isolators.md).

#### 3. Вузол автоматичного прошивання DTR/RTS на біполярних транзисторах
Для плат розробки з USB-UART мостами (CH340C, CP2102N, FT232R) стандартом де-факто є транзисторна схема автоматичного введення чипа в режим завантажувача без використання механічних кнопок.

```text
           +3.3V                   +3.3V
             │                       │
           [10k]                   [10k]
             │                       │
DTR ──[10k]─┤Base Q1       RTS ──[10k]─┤Base Q2
             │                       │
   RTS ──────┴Emitter Q1    DTR ─────┴Emitter Q2
             │                       │
             Collector Q1            Collector Q2
             │                       │
             ▼                       ▼
          ESP32 EN                ESP32 GPIO0
             │
          [100nF ... 1uF]
             │
            GND
```

**Чому схема побудована на перехресних емітерах:** Коли термінальна програма на ПК відкриває COM-порт, операційна система за замовчуванням одночасно виставляє сигнали `DTR = 0` та `RTS = 0` (в активний низький рівень). Якби керування йшло прямо, мікроконтролер скидався б при кожному відкритті монітора порту. У перехресній схемі при однакових рівнях (`DTR = RTS`) обидва транзистори закриті, і лінії `EN` та `GPIO0` залишаються підтягнутими до 3.3 В.

**Таблиця переходів утиліти прошивання (esptool):**

```
1. Фаза скидання:    DTR = 0 (3.3V), RTS = 1 (0V)   -> Q1 відкритий -> EN = 0 (чип у Reset)
2. Фаза вибору Boot: DTR = 1 (0V),   RTS = 0 (3.3V) -> Q2 відкритий -> GPIO0 = 0, Q1 закритий -> EN наростає
3. Завершення:       DTR = 1 (0V),   RTS = 1 (0V)   -> обидва закриті -> чип працює в Bootloader
```

Критично важливим елементом є конденсатор ємністю `0.1–1 мкФ`, підключений між лінією `EN` та землею. Він формує RC-затримку наростання напруги на виводі скидання:

```
τ = R · C = 10 кОм · 100 нФ = 1.0 мс
```

Без цієї ємності напруга на `EN` злітає миттєво, чип виходить зі скидання ще до того, як пін `GPIO0` встигне сісти в нуль через паразитну ємність кабелю, і вхід у bootloader зривається з фатальною помилкою тайм-ауту.

### Режими завантаження в промислових мікроконтролерах і процесорах

Принципи апаратного конфігурування через strapping-піни є універсальними для всієї індустрії напівпровідників — від простих 32-бітних мікроконтролерів до багатоядерних гетерогенних процесорів застосунків (*Application Processors*).

![Матриця та шляхи вибору режимів завантаження на STM32, ESP32 та NXP i.MX RT](/root/hw/hw-arch/strapping-piny-i-rezhymy-zavantazhennia/img/boot-matrix-flow.svg)
*Порівняльна матриця апаратного вибору завантаження. STM32: ремап нульової адреси через вивід BOOT0 або Option Bytes; ESP32: вибір між Flash та ROM Download через GPIO0/2/12; NXP i.MX RT: 4-позиційний перемикач BOOT_MODE з вибором інтерфейсів за пінами BOOT_CFG та можливістю повного блокування через eFuse BT_FUSE_SEL.*

#### 1. Архітектура завантаження STM32 (Cortex-M)
У класичних лінійках мікроконтролерів STM32 (STM32F1, F4, F7) спосіб завантаження задається логічними рівнями на двох пінах: `BOOT0` та `BOOT1` (часто суміщений із `PB2`). У момент відпускання скидання контролер перемикає внутрішній матричний комутатор пам'яті (*System Memory Remap*), проектуючи обраний фізичний блок пам'яті на нульову адресу `0x00000000`:

| `BOOT0` | `BOOT1` | Джерело завантаження (Mapped to `0x00000000`) | Призначення режиму |
|:---:|:---:|:---|:---|
| **0** | **X** | **Main Flash Memory** (`0x08000000`) | Штатний запуск програми користувача. |
| **1** | **0** | **System Memory** (`0x1FFF0000`) | Запуск заводського ROM Bootloader (оновлення через USART, USB DFU, CAN, I2C). |
| **1** | **1** | **Embedded SRAM** (`0x20000000`) | Пряме виконання коду з оперативної пам'яті (налагодження без зносу Flash). |

**Еволюція в сучасних STM32 (серії G0, G4, L4+, H7, U5):**
У нових серіях виробник відмовився від виділеного піна `BOOT1`, а конфігурацію переніс у енергонезалежні регістри конфігурації Flash — **Option Bytes**. За допомогою бітів `nSWBOOT0` та `nBOOT0` у регістрі `FLASH->OPTR` інженер може програмно відключити опитування фізичного піна `BOOT0`, назавжди звільнивши його під звичайний GPIO. Крім того, біт `BOOT_LOCK` дозволяє на рівні заліза заблокувати можливість входу в System Memory Bootloader, що захищає комерційний пристрій від несанкціонованого зчитування прошивки через вбудований завантажувач DFU.

#### 2. Процесори NXP i.MX RT (Crossover MCUs)
Процесори сімейства i.MX RT (наприклад, RT1060 із частотою 600 МГц) не мають внутрішньої Flash-пам'яті програм і повинні завантажувати код із зовнішніх носіїв за принципом [XIP (Execute-in-Place)](root:hw-arch/xip-memory-mapped-flash). Для конфігурації використовується дворівнева система:

1. **Два піни вибору базового режиму `BOOT_MODE[1:0]`:**
   - `00` — **Boot from Fuses:** процесор повністю ігнорує зовнішні конфігураційні піни й бере параметри завантаження з одноразово прошитих електронних запобіжників (*OTP eFuse*).
   - `01` — **Serial Downloader:** вхід у режим відновлення через USB OTG або UART (завантаження образу через утиліту NXP MCUbootUtility / sdphost).
   - `10` — **Internal Boot:** вибір носія та параметрів шини визначається групою strapping-пінів `BOOT_CFG[1..4]` (до 32 ліній, запаралелених на виводи LCD/GPIO).
   - `11` — **Зарезервовано.**

2. **Захист у серійному виробництві (eFuse Override):**
   На етапі прототипування плата використовує режим `BOOT_MODE = 10` та набір перемикачів на шині `BOOT_CFG` для вибору між FlexSPI NOR Flash, SD-картою чи eMMC. Перед випуском у серію параметри завантаження намертво записують у блок eFuse і спалюють біт `BT_FUSE_SEL = 1`. Після цього процесор назавжди ігнорує рівні на пінах `BOOT_CFG`, що дає дві переваги: по-перше, зловмисник не може перехопити керування чипом через маніпуляцію зовнішніми ніжками; по-друге, всі 32 лінії `BOOT_CFG` звільняються для вільного використання як звичайні виводи інтерфейсів.

#### 3. Багатоядерні SoC (TI Sitara, Allwinner, Rockchip)
У мікропроцесорах архітектури Cortex-A (наприклад, TI Sitara AM335x, що стоїть у BeagleBone) набір strapping-пінів об'єднано у 16-бітну шину `SYSBOOT[15:0]`. Ця шина в момент зняття сигналу скидання `PORz` визначає:
- Послідовність опитування носіїв (*Boot Device Order*), наприклад: `SPI0 -> MMC0 (eMMC) -> UART0 -> USB0`.
- Частоту вхідного кварцового резонатора (19.2 МГц, 24 МГц, 25 МГц або 26 МГц) для попереднього налаштування внутрішньої PLL до старту ROM-коду.
- Розрядність шини зовнішньої пам'яті (8-біт чи 16-біт NAND Flash).

### Посібник з проєктування strapping-вузлів та діагностика в коді

Для забезпечення 100% надійності апаратури на етапі розведення друкованої плати та написання прошивки дотримуються наведеного нижче зведення правил.

#### Пам'ятка інженера-схемотехніка
1. **Золоте правило:** Якщо на платі є вільні не-strapping GPIO, **ніколи** не призначайте на strapping-піни критичні керуючі ланцюги (затвори силових MOSFET, реле, лінії Chip Select енергонезалежної пам'яті).
2. **Якщо пін довелося задіяти як вхід:** Підключайте лише пасивні кнопки (з урахуванням напрямку внутрішньої підтяжки) або виходи датчиків, які в момент подачі живлення перебувають у стані високого імпедансу (*Hi-Z*).
3. **Якщо пін довелося задіяти як вихід:** Використовуйте буферизацію через тристабільні буфери (`74LVC1G125`), N-MOSFET ключі з розрядними резисторами або комутатори живлення периферії із затримкою.
4. **Блокування через eFuse:** На платформах ESP32 та i.MX RT у серійних виробах фіксуйте конфігурацію спалюванням eFuse (наприклад, `espefuse.py set_flash_voltage 3.3V` намертво відключає опитування небезпечного піна `GPIO12`).

#### Архітектурний патерн «Re-arming GPIO» у прошивці
Коли прошивка успішно пройшла фазу ROM-завантажувача та ініціалізації [C runtime стартапу](root:hw-arch/bootloader), strapping-пін необхідно перевести в робочий режим. Робити це слід з обережністю, щоб уникнути паразитного клацання реле чи хибного імпульсу (*glitch-free transition*):

1. Спершу сконфігурувати внутрішній вихідний регістр даних `GPIO_OUT_REG` у безпечний вихідний стан (наприклад, 0 для вимкненого реле).
2. Лише після встановлення рівня ввімкнути вихідний драйвер `GPIO_ENABLE_REG`.
3. За потреби вимкнути внутрішні підтяжки `PULLUP_DIS` / `PULLDOWN_DIS`.

#### Програмна діагностика стану засувок на C та C++

У критичних промислових системах прошивка під час старту повинна вичитати стан апаратних засувок скидання й перевірити, чи не стартувала система в аварійному режимі. Повні сигнатури та карти бітів описано у вставці [Регістри засувок завантаження та Option Bytes](root:hw-arch/strapping-piny-i-rezhymy-zavantazhennia/api-strapping-registers.md).

Нижче наведено приклад виробничого діагностичного модуля, що перевіряє стан засувок ESP32 та STM32 на ранньому етапі виконання.

:::tabs
```c
#include <stdint.h>
#include <stdbool.h>

#define ESP32_GPIO_STRAP_REG  (*(volatile const uint32_t *)0x3FF44038U)

#define STRAP_BIT_BOOT_MODE   (1U << 0)
#define STRAP_BIT_FLASH_1V8   (1U << 5)

typedef enum {
    BOOT_HEALTH_OK = 0,
    BOOT_ERR_DOWNLOAD_MODE_LATCHED = 1,
    BOOT_ERR_CRITICAL_FLASH_VOLTAGE = 2
} BootHealthStatus;

BootHealthStatus verify_system_strapping_health(void) {
    uint32_t strap_val = ESP32_GPIO_STRAP_REG;

    // Перевірка 1: Чи не зафіксовано небезпечну напругу Flash 1.8V на GPIO12
    if ((strap_val & STRAP_BIT_FLASH_1V8) != 0U) {
        return BOOT_ERR_CRITICAL_FLASH_VOLTAGE;
    }

    // Перевірка 2: Чи завантажилися ми у нормальному режимі SPI Flash (GPIO0 == 1)
    if ((strap_val & STRAP_BIT_BOOT_MODE) == 0U) {
        return BOOT_ERR_DOWNLOAD_MODE_LATCHED;
    }

    return BOOT_HEALTH_OK;
}
```
```cpp
#include <cstdint>
#include <bitset>
#include <expected>
#include <span>

namespace HardwareDiag {

enum class BootFault : uint8_t {
    FlashVoltageMismatch,
    UnexpectedDownloadMode,
    InvalidStrappingPattern
};

struct BootDiagnostics {
    uint32_t rawRegisterValue{0};
    bool isSpiFlashBoot{false};
    bool isFlashVoltageNormal{true};

    [[nodiscard]] constexpr bool isHealthy() const noexcept {
        return isSpiFlashBoot && isFlashVoltageNormal;
    }
};

class StrappingSupervisor {
public:
    static constexpr uintptr_t kEsp32StrapAddress = 0x3FF44038U;

    [[nodiscard]] static std::expected<BootDiagnostics, BootFault> evaluateStartupState() noexcept {
        auto* regPtr = reinterpret_cast<volatile const uint32_t*>(kEsp32StrapAddress);
        const uint32_t rawValue = *regPtr;
        std::bitset<32> strapBits(rawValue);

        BootDiagnostics diag{};
        diag.rawRegisterValue = rawValue;
        diag.isSpiFlashBoot = strapBits.test(0);      // GPIO0 стан
        diag.isFlashVoltageNormal = !strapBits.test(5); // GPIO12 стан (0 = 3.3V)

        if (!diag.isFlashVoltageNormal) {
            return std::unexpected(BootFault::FlashVoltageMismatch);
        }

        if (!diag.isSpiFlashBoot) {
            return std::unexpected(BootFault::UnexpectedDownloadMode);
        }

        return diag;
    }
};

} // namespace HardwareDiag
```

### Підсумок: фізичний цикл життя strapping-піна

Апаратне конфігурування через strapping-виводи об'єднує схемотехніку плати та цифрову логіку кристала у єдиний взаємопов'язаний вузол. Цикл життя конфігураційного піна складається з трьох послідовних станів:

```
[Фаза скидання: RESET=0]  -->  [Фронт RESET_N: Засувка LE]  -->  [Робочий хід: RESET=1]
 - Драйвери GPIO у Hi-Z        - Захоплення рівня за t_su/t_h     - Засувка непрозора (Locked)
 - Рівень формується зовніш-    - Фіксація в системному регістрі  - Пін переходить до MMIO
   ньою та внутрішньою          - Вибір Flash / DFU / Напруги     - Прошивка керує GPIO
   підтяжками (R_int || R_ext)
```

Коректне проєктування таких вузлів з урахуванням імпедансів підтяжок, застосування тристабільної буферизації або апаратного блокування через eFuse гарантує стабільний та передбачуваний старт мікроелектронної системи за будь-яких умов експлуатації.
