# 🧮 Математика MII: обчислення ResMII, контурів RecMII та матриці MRT

Мінімальний інтервал ініціалізації (`MII`, англ. *Minimum Initiation Interval*) визначає фундаментальну теоретичну нижню межу тривалості одного такту стабільного ядра конвеєра. Він є розв'язком задачі оптимізації розкладу операцій за наявності двох незалежних систем нерівностей: обмеженості фізичних обчислювальних ресурсів процесора та інформаційних зв'язків між ітераціями.

### 1. Формальна модель графа залежностей за даними (DDG)

Тіло циклу представляється як орієнтований мультиграф залежностей:
```
G = (V, E, d, δ, Res)
```
де:
- `V = {v₁, v₂, ..., v_n}` — множина операцій (вершин), що складають одну ітерацію циклу.
- `E ⊆ V × V` — множина спрямованих дуг інформаційної залежності.
- `d: E → ℕ` — функція латентності: `d(u, v)` задає мінімальну кількість тактів, необхідних для завершення операції `u` перед тим, як її результат зможе використати операція `v`.
- `δ: E → ℕ₀` — функція дистанції за ітераціями: `δ(u, v)` показує, на скільки ітерацій уперед передається значення. Якщо `δ = 0`, залежність діє всередині тієї самої ітерації; якщо `δ = 1`, операція `v` в ітерації `i` потребує даних від операції `u` з ітерації `i - 1`.
- `Res: V → R` — функція відображення операцій на множину типів фізичних ресурсів процесора `R = {r₁, r₂, ..., r_m}`.

### 2. Виведення ресурсного бар'єра (ResMII)

Нехай мікроархітектура процесора містить множину типів функціональних блоків `R`. Для кожного типу ресурсу `r ∈ R` процесор має `U(r)` паралельних пристроїв (наприклад, 2 порти пам'яті, 2 цілочислові АЛП, 1 помножувач).

Нехай `Count(r)` — загальна кількість операцій у тілі циклу, які потребують ресурсу типу `r`:
```
Count(r) = |{v ∈ V : Res(v) = r}|
```

У стабільному стані конвеєра з інтервалом ініціалізації `II` кожні `II` тактів процесор запускає нову ітерацію. Оскільки за період у `II` тактів `U(r)` блоків можуть виконати щонайбільше `U(r) · II` операцій типу `r`, за принципом Діріхле отримуємо фундаментальну нерівність:
```
Count(r) ≤ U(r)·II              [пропускна здатність блоку r за II тактів]
II ≥ Count(r) / U(r)           [ділення на кількість блоків U(r)]
II ≥ ⌈Count(r) / U(r)⌉         [II є цілим числом тактів]
```

Оскільки це обмеження має виконуватися одночасно для всіх типів ресурсів `r ∈ R`, ресурсний бар'єр `ResMII` визначається як максимум за всіма ресурсами:
```
ResMII = max_{r ∈ R} ⌈Count(r) / U(r)⌉
```

### 3. Виведення рекурентного бар'єра (RecMII)

Нехай `t(u)` позначає момент запуску операції `u ∈ V` у нульовій ітерації циклу (`ітерація 0`), де `0 ≤ t(u) < Schedule_Length`.

Тоді в довільній ітерації `i` та сама операція `u` стартує в абсолютному часі:
```
Time(u, i) = t(u) + i·II
```

Розгляньмо довільну дугу залежності `e = (u, v) ∈ E` із затримкою `d(u, v)` та дистанцією `δ(u, v)`. Результат операції `u`, запущеної в ітерації `i`, використовується операцією `v` в ітерації `i + δ(u, v)`. Щоб уникнути порушення причинно-наслідкового зв'язку за даними (RAW-конфлікт), операція `v` повинна стартувати не раніше ніж через `d(u, v)` тактів після старту `u`:

```
Time(v, i + δ(u, v)) - Time(u, i) ≥ d(u, v)
(t(v) + (i + δ(u, v))·II) - (t(u) + i·II) ≥ d(u, v)     [підстановка формули часу]
t(v) - t(u) + δ(u, v)·II ≥ d(u, v)                     [зведення подібних: i·II скорочується]
t(v) - t(u) ≥ d(u, v) - δ(u, v)·II                     [базова нерівність конвеєрного розкладу]
```

Нехай у графі `G` існує орієнтований контур (замкнений цикл зворотного зв'язку) `C = (v₀ → v₁ → v₂ → ... → v_k = v₀)`, що складається з `k` ребер. Додамо базові нерівності для всіх ребер вздовж цього контуру:

```
∑_{i=0}^{k-1} (t(v_{i+1}) - t(v_i)) ≥ ∑_{e ∈ C} (d(e) - δ(e)·II)   [сума нерівностей вздовж контуру]
0 ≥ ∑_{e ∈ C} d(e) - II · ∑_{e ∈ C} δ(e)                           [ліва частина є телескопічною сумою і тотожно дорівнює 0]
II · ∑_{e ∈ C} δ(e) ≥ ∑_{e ∈ C} d(e)                               [перенесення II·∑δ у ліву частину]
II ≥ (∑_{e ∈ C} d(e)) / (∑_{e ∈ C} δ(e))                           [ділення на сумарну дистанцію контуру]
```

Оскільки інтервал ініціалізації `II` повинен задовольняти цю нерівність для **кожного** простого контуру `C` у графі `G`, рекурентний бар'єр становить:
```
RecMII = max_{C ⊆ G} ⌈(∑_{e ∈ C} d(e)) / (∑_{e ∈ C} δ(e))⌉
```

Якщо граф `G` є ациклічним (рекурентні зв'язки відсутні, усі `δ = 0`), то `RecMII = 1`.

Загальний мінімальний інтервал ініціалізації дорівнює максимуму обох бар'єрів:
```
MII = max(ResMII, RecMII)
```

### 4. Алгоритми пошуку найгіршого контуру RecMII

Задача знаходження `max_C (∑d / ∑δ)` відома в теорії графів як задача пошуку контуру з максимальним співвідношенням (Maximum Cycle Ratio). Компілятори розв'язують її двома основними методами:

#### Метод матриці найдовших шляхів (All-Pairs Longest Path)
Для тестового значення `II` компілятор будує зважений граф `G' = (V, E)`, де кожному ребру `e = (u, v)` присвоюється вага:
```
w(u, v) = d(u, v) - II·δ(u, v)
```

Компілятор запускає алгоритм Флойда-Воршелла для пошуку найдовших шляхів між усіма парами вершин:
```
D[u][v] = max_{k} (D[u][k] + D[k][v])
```

Якщо на головній діагоналі матриці з'являється додатне значення (`D[u][u] > 0`), це означає наявність контуру з додатною вагою:
```
∑ (d(e) - II·δ(e)) > 0  ⇒  II < (∑ d(e)) / (∑ δ(e))
```
Отже, поточне значення `II` є замалим для розкладу і має бути збільшене.

#### Двійковий пошук Лоулера (Lawler's Binary Search)
Оскільки `1 ≤ RecMII ≤ ∑_{v ∈ V} Latency(v)`, компілятор виконує двійковий пошук за значенням `II`, на кожному кроці перевіряючи наявність циклів додатного ваги алгоритмом Беллмана-Форда за час `O(|V| · |E|)`.

### 5. Покроковий розрахунок: біквадратний IIR-фільтр

Розгляньмо обчислення рекурентного цифрового фільтра другого порядку:
```
y[i] = x[i] + c₁·y[i - 1] + c₂·y[i - 2]
```

Операції та їхні латентності:
1. `L_x`: читання `x[i]` (ресурс `Mem`, `d = 2`).
2. `M1`: множення `c₁ · y[i-1]` (ресурс `Mul`, `d = 2`).
3. `M2`: множення `c₂ · y[i-2]` (ресурс `Mul`, `d = 2`).
4. `A1`: додавання `t1 = x[i] + M1` (ресурс `ALU`, `d = 1`).
5. `A2`: додавання `y[i] = t1 + M2` (ресурс `ALU`, `d = 1`).
6. `S_y`: збереження `y[i]` (ресурс `Mem`, `d = 1`).

Ресурси процесора: 1 порт пам'яті (`U(Mem) = 1`), 1 помножувач (`U(Mul) = 1`), 1 АЛП (`U(ALU) = 1`).

#### Крок 1. Обчислення ResMII
```
Count(Mem) = 2 (L_x, S_y)  ⇒  ⌈2 / 1⌉ = 2
Count(Mul) = 2 (M1, M2)    ⇒  ⌈2 / 1⌉ = 2
Count(ALU) = 2 (A1, A2)    ⇒  ⌈2 / 1⌉ = 2
ResMII = max(2, 2, 2) = 2 такти
```

#### Крок 2. Обчислення контурів RecMII
У графі існують два рекурентні контури, утворені зворотними зв'язками від результату `A2` (який обчислює `y[i]`):
- **Контур C1 (`y[i-1]`):** `A2 → M1 → A1 → A2`
  - Затримка: `d(A2, M1) + d(M1, A1) + d(A1, A2) = 0 + 2 + 1 = 3 такти` (передача з регістра `A2` на вхід `M1` відбувається з `d = 0` після завершення обчислення `A2`).
  - Дистанція: `δ(A2, M1) = 1`, решта `δ = 0`. Сумарна `∑δ = 1`.
  - Співвідношення: `⌈3 / 1⌉ = 3 такти`.

- **Контур C2 (`y[i-2]`):** `A2 → M2 → A2`
  - Затримка: `d(A2, M2) + d(M2, A2) = 2 + 1 = 3 такти`.
  - Дистанція: `δ(A2, M2) = 2`. Сумарна `∑δ = 2`.
  - Співвідношення: `⌈3 / 2⌉ = 2 такти`.

Звідси рекурентний бар'єр становить:
```
RecMII = max(⌈3 / 1⌉, ⌈3 / 2⌉) = max(3, 2) = 3 такти
```

#### Крок 3. Підсумковий MII
```
MII = max(ResMII, RecMII) = max(2, 3) = 3 такти
```
Висновок: хоча апаратних ресурсів вистачає для видачі нової ітерації кожні 2 такти, рекурентний зв'язок `y[i-1]` через помножувач та АЛП створює непереборний інформаційний бар'єр у 3 такти. Будь-який розклад із `II < 3` порушить залежність за даними.

### 6. Математична формалізація таблиці модульного резервування (MRT)

Таблиця модульного резервування представляється булевою матрицею розміру `II × |R|`:
```
MRT[s][r] ∈ {0, 1},  де s ∈ {0, 1, ..., II - 1}, r ∈ R
```

Функція відображення часу `t(u)` на рядок таблиці визначається як:
```
Slot(u) = t(u) mod II
```

Розклад `t: V → ℕ₀` є коректним (безконфліктним за ресурсами), якщо для кожного типу ресурсу `r ∈ R` та для кожного часового слота `s ∈ {0, ..., II - 1}` кількість призначених операцій не перевищує фізичну ємність:
```
|{u ∈ V : Res(u) = r ∧ (t(u) mod II) = s}| ≤ U(r)
```

Ця умова гарантує, що при накладанні нескінченної кількості послідовних ітерацій із кроком `II` жоден функціональний блок процесора не отримає двох або більше команд на виконання в один і той самий такт.
