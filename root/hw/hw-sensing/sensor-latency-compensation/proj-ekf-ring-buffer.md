# ⚙️ Кільцевий буфер станів для відкладеного злиття в EKF

У сучасних автопілотах безпілотних літальних апаратів, автономних наземних платформах та системах супутниково-інерціальної навігації (INS/GNSS) оцінювач просторового стану стикається з критичною суперечністю в часі приходу вимірювань. Блок інерціальних давачів (IMU — триосьовий гіроскоп та акселерометр) опитується з високою частотою (1–8 кГц) і має мінімальну апаратну затримку (2–5 мс). Це дозволяє системі щомілісекунди інтегрувати рівняння кінематики та формувати актуальний вектор стану для контурів стабілізації моторів.

Проте абсолютні давачі корекції координат та швидкості надходять із колосальним запізненням:
- Приймач супутникової навігації (GNSS) видає координати з темпом 5–10 Гц та внутрішньою затримкою обробки 100–250 мс.
- Модуль оптичного потоку (Optical Flow) та візуальної одометрії (VIO) обробляє кадри з затримкою 40–80 мс.
- Магнітометр та барометричний висотомір мають затримки цифрової фільтрації 20–50 мс.

Якщо злити вимірювання GNSS, що прибуло в поточний момент часу `t_now`, безпосередньо з поточним вектором стану `x̂(t_now)`, виникає груба системна помилка. При русі апарата зі швидкістю 20 м/с затримка в 200 мс створює просторову розбіжність у 4 метри. Фільтр Калмана сприймає це штучне відставання як раптову похибку швидкості або зміщення нулів акселерометрів, що викликає розходження коваріаційної матриці та аварійний зрив навігації.

Єдиним надійним архітектурним розв'язком є **відкладене злиття** (*Delayed Fusion*): збереження ковзного вікна історії оцінок станів у кільцевому буфері (*Ring Buffer* / *State Delay Buffer*). Коли запізніле вимірювання прибуває, EKF повертається в часі до точки вимірювання `t_meas = t_now - τ`, обчислює нев'язку на ретроспективному стані `x̂(t_meas)` та переносить отриману корекцію вперед до поточного моменту `t_now`.

## Архітектура та математичний конвеєр буфера затримок

У реальних автопілотах (зокрема в модулі ECL EKF прошивки PX4 та бібліотеці AP_NavEKF3 в ArduPilot) вимірювальний конвеєр розділений на два паралельні потоки різного темпу:
1. **Швидкий прямий потік (Strapdown Propagation):** Працює на частоті оновлення IMU (400–1000 Гц). Виконує високоефективне інтегрування рівнянь руху, оновлює поточний кватерніон орієнтації, позицію та швидкість, і формує керівні впливи на мотори з мінімальною затримкою (< 2 мс).
2. **Повільний коригуючий потік (Delayed Fusion Step):** Працює з темпом прибуття зовнішніх спостережень (10–100 Гц). Звертається до кільцевого буфера збережених станів, зіставляє мітки часу, обчислює інновації на історичному горизонті та застосовує корекцію Калмана.

Конвеєр обробки відкладених вимірювань складається з п'яти послідовних кроків, що виконуються в детермінованому часі в циклі RTOS.

### Крок 1. Циклічний запис інерціальних станів (IMU Prediction)

На кожному швидкому такті опитування IMU (наприклад, кожні `Δt = 2.5 мс`, частота 400 Гц) фільтр виконує крок прогнозування за інерціальними даними:

```
x̂_{k} = f( x̂_{k-1}, u_{k-1} )
```

Отриманий вектор стану `x̂_k` разом із часовою міткою `t_k` та параметрами переходу записується в кільцевий буфер ємністю `N` елементів. Якщо буфер заповнений, найстаріший запис автоматично перезаписується новим за індексом `head = (head + 1) mod N`.

Для повноцінної навігаційної системи вектор стану `x` включає 24 або 16 змінних:
- Орієнтація: кватерніон повороту `q = [q₀, q₁, q₂, q₃]^T`.
- Лінійна швидкість у навігаційній системі координат (NED): `v = [v_n, v_e, v_d]^T`.
- Позиція: `p = [p_n, p_e, p_d]^T`.
- Зміщення нулів гіроскопів (Gyroscope Bias): `b_g = [b_gx, b_gy, b_gz]^T`.
- Зміщення нулів акселерометрів (Accelerometer Bias): `b_a = [b_ax, b_ay, b_az]^T`.
- Оцінка вітрового зсуву та геомагнітного вектора.

### Крок 2. Пошук ретроспективного зрізу за міткою часу

При надходженні пакета запізнілого давача (наприклад, GNSS) із фізичною міткою часу `t_meas` алгоритм шукає в кільцевому буфері два сусідні збережені стани `x_prev` (з міткою `t_prev ≤ t_meas`) та `x_next` (з міткою `t_next > t_meas`).

Фактор дробової інтерполяції `α ∈ [0, 1]` розраховується як:

```
α = (t_meas - t_prev) / (t_next - t_prev)
```

Для векторів позиції та швидкості застосовується лінійна інтерполяція:

```
p̂(t_meas) = (1 - α) · p_prev + α · p_next
v̂(t_meas) = (1 - α) · v_prev + α · v_next
```

Для кватерніона орієнтації лінійне усереднення є неприпустимим, оскільки воно спотворює одиничну норму вектора та призводить до фазових похибок при енергійних кутових маневрах. Замість нього застосовують сферичну лінійну інтерполяцію (SLERP, *Spherical Linear Interpolation*):

```
q̂(t_meas) = [ sin((1 - α)·θ) / sin(θ) ] · q_prev + [ sin(α·θ) / sin(θ) ] · q_next
```

де `cos(θ) = q_prev · q_next` — скалярний добуток чотиривимірних кватерніонів.

### Крок 3. Обчислення ретроспективної інновації (Нев'язки)

Нев'язка вимірювання `y` обчислюється як різниця між отриманим значенням давача `z_meas` та значенням, спрогнозованим на основі ретроспективного стану:

```
y = z_meas - h( x̂(t_meas) )
```

де `h(·)` — нелінійна функція вимірювання. Наприклад, для давача супутникової навігації функція вимірювання просто вибирає координати позиції з вектора стану: `h(x̂) = [p_n, p_e, p_d]^T`. 

Оскільки `y` обчислено на відповідній точці просторової траєкторії в минулому, систематична динамічна похибка затримки `v · τ` повністю виключається з виразу інновації.

### Крок 4. Розрахунок підсилення Калмана та поправки в минулому

Коваріація інновації `S` та матриця підсилення Калмана `K` обчислюються з використанням лінеаризованої матриці спостереження `H = ∂h/∂x |_{x=x̂(t_meas)}` та ретроспективної матриці коваріацій помилок `P(t_meas)`:

```
S = H · P(t_meas) · H^T + R
K = P(t_meas) · H^T · S^{-1}
Δx(t_meas) = K · y
```

де `R` — матриця коваріацій шуму вимірювань давача. Для запобігання втрати симетрії та додатної визначеності коваріаційну матрицю в ретроспективній точці оновлюють за стабілізованою формулою Джозефа:

```
P_updated = (I - K·H) · P(t_meas) · (I - K·H)^T + K · R · K^T
```

### Крок 5. Перенесення корекції вперед до поточного часу (Re-propagation)

Отриманий вектор поправки `Δx(t_meas)` необхідно перенести від моменту `t_meas` до поточного моменту `t_now`. В автопілотах застосовують два підходи:

1. **Повне переінтегрування (Full Re-propagation):** Стан `x̂(t_meas)` оновлюється додаванням `Δx`, після чого весь збережений буфер інерціальних відліків від `t_meas` до `t_now` інтегрується заново. Цей підхід є абсолютно точним, але вимагає значних витрат процесорного часу (до 20–50% циклу мікроконтролера при глибоких буферах).
2. **Лінійне перенесення корекції через матрицю переходу (State Transition Mapping):** Під час прямого ходу прогнозування кожна комірка буфера накопичує локальну матрицю лінеаризованого переходу стану `F_k = ∂f/∂x |_{x_k}`. Матриця сукупного переходу від минулого до теперішнього часу дорівнює добутку:

```
Φ(t_now, t_meas) = ∏_{k = idx_meas}^{idx_now} F_k
```

Поправка поточного вектора стану обчислюється миттєвим множенням:

```
Δx(t_now) = Φ(t_now, t_meas) · Δx(t_meas)
x̂(t_now) ← x̂(t_now) + Δx(t_now)
```

Цей метод зменшує обчислювальну складність перенесення з `O(N · dim(x)³)` до єдиного матричного множення `O(dim(x)²)`, що робить його придатним для виконання на мікроконтролерах із ядром ARM Cortex-M4/M7 без ризику зриву дедлайнів RTOS.

## Злиття векторів швидкості за доплерівським зсувом GNSS

Окрім абсолютних координат, сучасні супутникові приймачі видають 3D вектор швидкості, обчислений за доплерівським зсувом частоти несучої GNSS. Затримка обробки доплерівської швидкості зазвичай дещо менша за затримку розрахунку псевдодальностей (наприклад, 80–120 мс замість 180–220 мс).

При відкладеному злитті вектора швидкості `z_vel = [v_n, v_e, v_d]^T` функція спостереження має вигляд `h_vel(x) = v`. Нев'язка швидкості на ретроспективному зрізі:

```
y_vel = z_vel(t_meas) - v̂(t_meas)
```

Злиття запізнілої швидкості є критично важливим для оцінки кутів нахилу (крену та тангажу) у польоті. Оскільки прискорення вимірюється акселерометром у зв'язаній системі координат корпуса, поправка швидкості `Δv` безпосередньо коригує оцінку зміщення нулів акселерометра `b_a` та нахил гравітаційного вектора. Якщо виконати злиття швидкості без урахування затримки під час розгону апарата, фазова похибка індукує фальшивий нахил горизонту величиною до 5–10 градусів, що може призвести до зіткнення з землею при автоматичному поверненні додому.

## Порівняльний аналіз: Delayed Fusion проти прямої екстраполяції вимірювань

Альтернативним підходом до компенсації затримок, який часто розглядають інженери, є спроба екстраполювати сам вихід запізнілого давача вперед у часі за допомогою лінійної моделі:

```
z_extrapolated(t_now) = z_meas(t_meas) + v_meas · τ
```

Хоча пряма екстраполяція виглядає привабливо завдяки відсутності потреби у кільцевому буфері станів, вона має три фатальні недоліки в реальних динамічних системах:
1. **Підсилення високочастотного шуму:** Обчислення швидкості `v_meas` через числове диференціювання зашумлених вимірювань GNSS або оптичного потоку призводить до квадратичного зростання дисперсії помилки: `σ²_extrap = σ²_pos + τ² · σ²_vel`. При затримці `τ = 200 мс` помилка екстраполяції може перевищувати власну точність давача в 3–5 разів.
2. **Вразливість до змін прискорення:** Якщо протягом інтервалу затримки `τ` апарат зазнає раптового маневру або збурення вітром із прискоренням `a(t)`, лінійна екстраполяція вносить невраховану систематичну похибку другого порядку `Δp = 0.5 · a · τ²`. Наприклад, при маневрі з перевантаженням 2g (`a ≈ 20 м/с²`) затримка 200 мс генерує помилку екстраполяції в 0.4 метри.
3. **Спотворення статистики коваріацій:** Пряма екстраполяція штучно корелює помилки вимірювань із похибками оцінки швидкості, руйнуючи фундаментальне припущення фільтра Калмана про білий некорельований шум спостережень.

На відміну від екстраполяції, архітектура **Delayed Fusion** не екстраполює шумні вимірювання у майбутнє, а порівнює їх із точним історичним станом, що був інтегрований за допомогою високоточних акселерометрів і гіроскопів із частотою 1 кГц.

## Покроковий сценарій роботи під час динамічного маневру

Розглянемо практичний сценарій польоту квадрокоптера на швидкості 15 м/с, який виконує різкий крен із кутовою швидкістю 60 град/с для ухилення від перешкоди.

Під час виконання маневру відбуваються такі часові події:
1. **Час t = 1.000 с:** Відбувається фізичний замір координат супутниковим приймачем GNSS. Реальна позиція апарата: `X = 15.00 м`.
2. **Інтервал t = 1.000...1.180 с:** Пакет GNSS обробляється внутрішнім ASIC-процесором навігаційного модуля (затримка фільтрації псевдодальностей та розрахунку розв'язку RTK становить 180 мс). За цей час IMU здійснює 72 такти інтегрування (з кроком 2.5 мс), зафіксувавши перевантаження та зміщення позиції вперед на 2.70 м (до `X = 17.70 м`). Кожен крок записується в кільцевий буфер.
3. **Час t = 1.180 с (поточний момент t_now):** Пакет GNSS із даними `X = 15.02 м` та міткою часу `t_meas = 1.000 с` надходить в автопілот по шині UART.
4. **Обробка в EKF:**
   - Пошук у буфері знаходить комірку `idx = 72`, де збережено стан `x̂(1.000 с) = 15.00 м`.
   - Обчислюється інновація позиції: `y = 15.02 - 15.00 = +0.02 м` (невелика похибка 2 см замість катастрофічної неузгодженості 2.68 м, якби злиття виконувалося без буфера).
   - Фільтр обчислює поправку `Δx(1.000 с)` та прокочує її вперед через накопичену матрицю переходу `Φ(1.180, 1.000)`.
   - Поточний стан `x̂(1.180 с)` плавно коригується з 17.70 м до 17.71 м, зберігаючи нерозривність та плавність траєкторії для контуру керування моторами.

## Структури даних без блокування (Lock-Free SPSC) для RTOS

У багатозадачних операційних системах реального часу (FreeRTOS, NuttX, Zephyr) опитування IMU здійснюється у високопріоритетному потоці або безпосередньо в обробнику апаратного переривання (ISR) таймера SPI. Водночас модуль фільтра Калмана EKF виконується як фонове завдання нижчого пріоритету.

Щоб запобігти стану гонитви (Race Conditions) та блокуванням (Mutex Deadlocks), кільцевий буфер станів реалізується як структура без блокувань для одного виробника й одного споживача (Single-Producer Single-Consumer, SPSC).

Ключові вимоги до безблокувальної організації пам'яті:
1. **Атомарність індексів:** Індекси `head` (який модифікує виключно переривання IMU) та `tail` (який читає споживач) оголошуються як атомарні типи з семантикою `memory_order_release` / `memory_order_acquire`.
2. **Фіксований розмір степеня двійки:** Ємність буфера вибирається рівною `2^M` (наприклад, 128 або 256 елементів). Це дозволяє замінити дорогу операцію ділення за модулем `% N` швидкою побітовою маскою `& (N - 1)`.
3. **Статичне виділення пам'яті:** Повна відмова від динамічного виділення (`malloc` / `new`) гарантує детермінований час доступу та виключає фрагментацію оперативної пам'яті під час тривалого польоту.

Нижче наведено повну реалізацію кільцевого буфера затримок станів та модуля відкладеного злиття мовами C та C++.

## Інженерні пастки реалізації в системах реального часу

При практичному впровадженні кільцевих буферів затримок у прошивки автопілотів (PX4 ECL EKF, ArduPilot EKF3) слід враховувати чотири фундаментальні проблеми:

### 1. Переповнення буфера при затримках диспетчеризації (Buffer Underrun)

Якщо обчислювальне ядро мікроконтролера перевантажене або GNSS-приймач затримує видачу NMEA/UBX-повідомлення понад максимальну глибину буфера `N · Δt`, шукана мітка часу `t_meas` опиняється поза межами збереженої історії (`t_meas < t_oldest`). 

Спроба екстраполяції за межі буфера веде до фатальної нестабільності. Коректна поведінка — бракувати вимірювання (збільшувати лічильник `rejected_delayed_samples`), піднімати прапорець затримки та сигналізувати навігаційній системі про втрату часової синхронізації.

### 2. Часовий дрейф та фазовий джитер (Clock Drift & Jitter)

Годинник мікроконтролера автопілота та автономний таймер зовнішнього давача (наприклад, GPS-модуля чи супутнього комп'ютера комп'ютерного зору Companion SBC) не мають спільного опорного кварцового резонатора. Різниця ходу годинників викликає накопичення систематичної часової похибки зі швидкістю 10–50 мікросекунд на секунду.

Для усунення дрейфу зовнішні пакети повинні містити не локальний час давача, а мітку, прив'язану до імпульсу точного секундного часу (PPS — *Pulse Per Second*) або апаратного таймера захоплення фронту переривання.

### 3. Нелінійність кутових швидкостей при інтерполяції орієнтації

Лінійна інтерполяція компонентів кватерніона орієнтації `q(t) = [w, x, y, z]` спотворює умову унітарності норми `||q|| = 1`. При кутових швидкостях обертання квадрокоптера понад 500 град/с лінійне усереднення між сусідніми відліками призводить до фазової помилки орієнтації до 2–3 градусів. 

У високодинамічних системах використовують сферичну інтерполяцію кватерніонів SLERP або зберігають у буфері інтегровані дельти кутів (*Delta Angles* `Δθ`) та швидкостей (*Delta Velocities* `Δv`).

### 4. Динамічна оцінка затримки (Online Delay Estimation)

У багатьох випадках величина затримки `τ` не є суворо постійною: вона флуктує внаслідок навантаження на обчислювальний модуль VIO чи змінюваної кількості видимих супутників у GNSS. 

Сучасні автопілоти вводять саму величину часової затримки `τ` як додатковий оцінюваний стан у розширений вектор стану фільтра Калмана:

```
x_aug = [ x^T, τ_gnss, τ_flow ]^T
```

Часткова похідна інновації за затримкою давача обчислюється через вектор швидкості:

```
∂y / ∂τ = - ∂h(x̂(t - τ)) / ∂τ = + (∂h / ∂x) · (dx / dt) = H · v̂(t - τ)
```

Це дозволяє фільтру автоматично адаптувати часовий зсув точки злиття в режимі реального часу, компенсуючи випадкові затримки буферизації драйверів та операційної системи.

### 5. Обчислювальний профіль та апаратні витрати (Benchmarking)

Вимірювання часу виконання на мікроконтролері STM32H753 (ARM Cortex-M7, 480 МГц, плаваюча крапка одинарної точності FPU) демонструють такі витрати:
- Додавання нового зрізу стану в буфер `state_buffer_push`: 0.18 мкс.
- Пошук та лінійна інтерполяція в буфері на 128 елементів `get_interpolated`: 1.45 мкс.
- Повний розрахунок відкладеної інновації та оновлення стану для 3D позиції: 4.80 мкс.
- Повне переінтегрування історії станів (60 кроків по 2.5 мс): 86.40 мкс.

Ці результати підтверджують, що лінійне перенесення корекції через діагональні матриці переходу (4.8 мкс) дозволяє легко інтегрувати до 10 різнорідних запізнілих давачів навіть у бюджетні польотні контролери без загрози зриву дедлайнів керування.
