# 📋 Регістровий інтерфейс і карта пам'яті MEMS-барометра

Цифровий MEMS-барометр (типовий представник архітектур Bosch BMP388 або STMicroelectronics LPS22HB) підключається до хост-контролера за допомогою стандартних послідовних шин I2C (на швидкостях Standard 100 кГц, Fast 400 кГц та Fast-Mode Plus 1 МГц) або SPI (у 4-провідному чи 3-провідному режимах на частотах тактування до 10 МГц). Усі взаємодії — від переведення чипа між станами енергозбереження до зчитування 24-бітних результатів тиску та температурного калібрування — здійснюються через лінійний 8-бітний регістровий простір.

Нижче наведено повний опис карти регістрів, форматів керуючих бітових полів, структури енергонезалежної пам'яті калібрувальних коефіцієнтів NVM, поведінки буфера FIFO та часових діаграм пакетного обміну.

### Загальна карта регістрів

Усі регістри барометра адресуються 8-бітним числом. Багатобайтові значення (наприклад, 24-бітні відліки АЦП та 16-бітні коефіцієнти підгонки) зберігаються за принципом Little-Endian: молодший байт розміщується за меншою адресою пам'яті.

| Адреса | Назва регістра | Доступ | Опис призначення та функціонал |
|---|---|---|---|
| `0x00` | `CHIP_ID` | R | Апаратний ідентифікатор кристала (фіксоване значення `0x50` для BMP388 або `0xB1` для LPS22HB) |
| `0x02` | `ERR_REG` | R | Прапорці апаратних збоїв (помилка конфігурації `conf_err`, збій пам'яті `nvm_err`, відмова команди `cmd_err`) |
| `0x03` | `STATUS` | R | Прапорці готовності даних (`drdy_press`, `drdy_temp`) та завершення виконання внутрішньої команди `cmd_rdy` |
| `0x04` | `PRESS_XLSB` | R | Молодші біти [7:0] 24-бітного значення тиску з АЦП |
| `0x05` | `PRESS_LSB` | R | Середні біти [15:8] 24-бітного значення тиску з АЦП |
| `0x06` | `PRESS_MSB` | R | Старші біти [23:16] 24-бітного значення тиску з АЦП |
| `0x07` | `TEMP_XLSB` | R | Молодші біти [7:0] 24-бітного значення температури з АЦП |
| `0x08` | `TEMP_LSB` | R | Середні біти [15:8] 24-бітного значення температури з АЦП |
| `0x09` | `TEMP_MSB` | R | Старші біти [23:16] 24-бітного значення температури з АЦП |
| `0x0C` | `FIFO_LENGTH_0` | R | Поточна кількість збережених байтів у FIFO (молодший байт [7:0]) |
| `0x0D` | `FIFO_LENGTH_1` | R | Поточна кількість збережених байтів у FIFO (старший біт [8]) |
| `0x0E` | `FIFO_DATA` | R | Порт послідовного читання пакетів із внутрішнього FIFO-буфера |
| `0x15` | `FIFO_CONFIG_1` | R/W | Налаштування збереження в FIFO (дозвіл запису тиску `fifo_press_en`, температури `fifo_temp_en`, поведінка при переповненні `fifo_stop_on_full`) |
| `0x17` | `FIFO_CONFIG_2` | R/W | Налаштування децимації та джерела вибірок FIFO |
| `0x18` | `INT_CTRL` | R/W | Налаштування апаратного виводу переривання INT (активний рівень, push-pull / open-drain, защіпка latch) |
| `0x19` | `IF_CONF` | R/W | Налаштування інтерфейсу шини (перемикання 3-провідного SPI, відключення I2C watchdog) |
| `0x1B` | `PWR_CTRL` | R/W | Керування живленням та сенсорами (`mode[1:0]`, дозвіл вимірювання тиску `press_en`, температури `temp_en`) |
| `0x1C` | `OSR` | R/W | Коефіцієнти передискретизації сигма-дельта АЦП (`osr_p[2:0]` для тиску, `osr_t[2:0]` для температури) |
| `0x1D` | `ODR` | R/W | Частота оновлення вихідних даних у безперервному режимі (`odr_sel[4:0]`) |
| `0x1F` | `CONFIG` | R/W | Налаштування апаратного фільтра IIR (`iir_filter[2:0]`) |
| `0x31..0x45` | `NVM_PAR_T1..P11` | R | 21 байт індивідуальних заводських коефіцієнтів полінома NVM |
| `0x7E` | `CMD` | W | Регістр виконання апаратних команд (`0xB6` = Soft Reset, `0xB0` = очищення FIFO-буфера) |

### Деталізація керуючих бітових полів

#### 1. Регістр режиму живлення `PWR_CTRL` (`0x1B`)

Регістр `PWR_CTRL` відповідає за переведення чипа між станами енергозбереження та запуск аналогових вимірювальних трактів. Якщо один із каналів (тиск чи температура) вимкнено відповідним бітом, АЦП пропускає цей етап перетворення, що пропорційно скорочує час циклу та струм споживання.

```
Біти:  [7:6]    [5:4]        [3:2]     [1]        [0]
Поле:  резерв   mode[1:0]    резерв    temp_en    press_en
```

- `mode[1:0]`:
  - `00b`: **Sleep Mode** — аналогові підсилювачі та АЦП вимкнені, цифровий інтерфейс I2C/SPI залишається активним. Струм споживання становить менше `1.0 мкА`. Регістри зберігають свої значення.
  - `01b` / `10b`: **Forced Mode** (режим разового опитування) — давач миттєво прокидається, виконує рівно один синхронний цикл перетворення температури та тиску відповідно до встановлених коефіцієнтів OSR, оновлює регістри даних і автоматично повертається в режим Sleep. Цей режим є ідеальним для автономних приладів з низькою частотою опитування (метеостанції, розумні трекери).
  - `11b`: **Normal Mode** (безперервний режим) — чип автоматично й циклічно виконує вимірювання з періодом, заданим у регістрі `ODR`, і записує результати у вихідні регістри або FIFO-буфер.
- `temp_en`: встановлення біта в `1` вмикає тракт зчитування температури на основі PTAT-сенсора. Оскільки температурна компенсація тиску спирається на дійсну температуру кристала, біт `temp_en` повинен бути встановлений у `1` під час будь-яких вимірювань тиску.
- `press_en`: встановлення біта в `1` вмикає живлення п'єзорезистивного моста та аналогового підсилювача тиску.

#### 2. Регістр передискретизації `OSR` (`0x1C`)

Регістр `OSR` визначає внутрішню кратність інтегрування сигма-дельта модулятора АЦП незалежно для каналів тиску (`osr_p`) та температури (`osr_t`). Вибір OSR задає компроміс між часом перетворення (струмом споживання) та середньоквадратичним шумом вимірювання (RMS noise).

```
Біти:  [7:6]    [5:3]        [2:0]
Поле:  резерв   osr_t[2:0]   osr_p[2:0]
```

| Значення бітів | Кратність OSR | Ефективна розрядність АЦП (ENOB) | Власний RMS-шум тиску | Час одного перетворення |
|---|---|---|---|---|
| `000b` | 1× (Ultra Low Power) | 16 бітів | ~10.0 Па (~80 см висоти) | 1.8 мс |
| `001b` | 2× (Low Power) | 17 бітів | ~5.0 Па (~40 см висоти) | 3.2 мс |
| `010b` | 4× (Standard Resolution) | 18 бітів | ~2.5 Па (~20 см висоти) | 6.0 мс |
| `011b` | 8× (High Resolution) | 19 бітів | ~1.5 Па (~12 см висоти) | 11.5 мс |
| `100b` | 16× (Ultra High Resolution) | 20 бітів | ~0.8 Па (~6.5 см висоти) | 22.5 мс |
| `101b` | 32× (Highest Resolution) | 21 біт | ~0.5 Па (~4.0 см висоти) | 44.5 мс |

Для температури зазвичай обирають `osr_t = 1×` або `2×`, оскільки температура корпусу змінюється відносно повільно, а для тиску в задачах навігації та альтиметрії встановлюють `osr_p = 8×` або `16×`.

#### 3. Регістр частоти видачі даних `ODR` (`0x1D`)

У режимі Normal Mode регістр `ODR` задає період генерації нових вибірок. Якщо час вимірювання (сума часу вибірки тиску й температури за вибраних OSR) перевищує період, встановлений у `ODR`, сенсор автоматично розширює період до мінімально можливого фізичного часу вимірювання.

- `0x00`: 200 Гц (період вибірки `5.0 мс`)
- `0x01`: 100 Гц (період вибірки `10.0 мс`)
- `0x02`: 50 Гц (період вибірки `20.0 мс`)
- `0x03`: 25 Гц (період вибірки `40.0 мс`) — типове налаштування для систем стабілізації дронів
- `0x04`: 12.5 Гц (період вибірки `80.0 мс`)
- `0x05`: 6.25 Гц (період вибірки `160.0 мс`)
- `0x06`: 3.125 Гц (період вибірки `320.0 мс`)
- `0x07`: 1.5625 Гц (період вибірки `640.0 мс`)

#### 4. Регістр конфігурації апаратного IIR-фільтра `CONFIG` (`0x1F`)

Вбудований у цифрове ядро сенсора рекурсивний фільтр нескінченної імпульсної характеристики (IIR) першого порядку згладжує короткочасні викиди тиску (наприклад, від поривів вітру чи вібрацій) без залучення обчислювальних ресурсів зовнішнього мікроконтролера.

```
Біти:  [7:4]    [3:1]           [0]
Поле:  резерв   iir_filter[2:0] резерв
```

| `iir_filter` | Коефіцієнт згладжування `c` | Формула фільтрації | Придушення шуму | Затримка реакції (Step Response) |
|---|---|---|---|---|
| `000b` | Вимкнено (Bypass) | `P_fil[k] = P_raw[k]` | 0 дБ | 0 відліків |
| `001b` | 2 | `P_fil[k] = (P_fil[k-1] + P_raw[k]) / 2` | 3 дБ | 1.5 відліка |
| `010b` | 4 | `P_fil[k] = (3·P_fil[k-1] + P_raw[k]) / 4` | 6 дБ | 3 відліки |
| `011b` | 8 | `P_fil[k] = (7·P_fil[k-1] + P_raw[k]) / 8` | 9 дБ | 7 відліків |
| `100b` | 16 | `P_fil[k] = (15·P_fil[k-1] + P_raw[k]) / 16` | 12 дБ | 15 відліків |
| `101b` | 32 | `P_fil[k] = (31·P_fil[k-1] + P_raw[k]) / 32` | 15 дБ | 31 відлік |

### Робота з апаратним буфером FIFO та лічильником часу

Прецизійні MEMS-барометри містять апаратний FIFO-буфер об'ємом 512 байтів (до 73 повних вибірок тиску й температури разом із часовими мітками). Використання FIFO дозволяє мікроконтролеру перебувати в режимі глибокого сну (*Deep Sleep*) і прокидатися за апаратним перериванням `FIFO Watermark` (позначка заповнення), вичитуючи накопичений пакет за одну швидкісну транзакцію SPI.

#### Формат кадрів у FIFO-буфері

Дані записуються у FIFO у вигляді структурованих кадрів (*Frames*). Кожен кадр починається з однобайтового заголовка (*Header*):

- `0x90`: Кадр містить тільки 3 байти сирого тиску `[PRESS_XLSB, PRESS_LSB, PRESS_MSB]`.
- `0x88`: Кадр містить тільки 3 байти сирої температури `[TEMP_XLSB, TEMP_LSB, TEMP_MSB]`.
- `0x98`: Повний кадр, що містить 6 байтів даних `[PRESS_XLSB..MSB, TEMP_XLSB..MSB]`.
- `0xA0`: Системний кадр часової мітки (*Sensor Time*), що містить 24-бітне значення внутрішнього апаратного таймера (дискретність 39.0625 мкс).
- `0x80`: Кадр порожнього стану / завершення потоку (*Empty / End of Data*).

Під час вичитування буфера через регістр `FIFO_DATA` (`0x0E`) хост-контролер аналізує заголовок кожного кадру й автоматично відновлює синхронізовану в часі послідовність вимірювань для навігаційного фільтра.

### Структура калібрувальних коефіцієнтів NVM (`0x31..0x45`)

Заводські константи підгонки записуються в одноразово програмовану енергонезалежну пам'ять (OTP/NVM) кристала після заводського калібрування на пластині. Драйвер зобов'язаний зчитати ці 21 байт під час запуску й зберегти їх у внутрішній структурі для щосекундного використання у формулах температурної корекції.

```
Адреса  Символ    Тип даного  Масштабний дільник        Фізичне призначення коефіцієнта
──────────────────────────────────────────────────────────────────────────────────────────
0x31    T1        uint16_t    2⁻⁸                       Базове зміщення нуля термометра
0x33    T2        uint16_t    2³⁰                       Лінійна крутизна термометра
0x35    T3        int8_t      2⁴⁸                       Квадратична нелінійність термометра
0x36    P1        int16_t     (P1 - 2¹⁴) / 2²⁰          Зсув нуля характеристики тиску (Offset)
0x38    P2        int16_t     (P2 - 2¹⁴) / 2²⁹          Чутливість до тиску (Sensitivity)
0x3A    P3        int8_t      2³²                       Температурний коефіцієнт чутливості (TCS)
0x3B    P4        int8_t      2³⁷                       Температурний коефіцієнт зсуву нуля (TCO)
0x3C    P5        uint16_t    2⁻³                       Масштабний коефіцієнт тиску
0x3E    P6        uint16_t    2⁶                        Температурна нелінійність тиску 1-го порядку
0x40    P7        int8_t      2⁸                        Температурна нелінійність тиску 2-го порядку
0x41    P8        int8_t      2¹⁵                       Крос-чутливість тиск × температура
0x42    P9        int16_t     2⁴⁸                       Квадратична нелінійність деформації мембрани
0x44    P10       int8_t      2⁴⁸                       Кубічна нелінійність деформації мембрани
0x45    P11       int8_t      2⁶⁵                       Крос-нелінійність тиск² × температура
```

### Протокол пакетного зчитування даних (Burst Read)

Щоб уникнути спотворення даних внаслідок неузгодженого оновлення (коли мікроконтролер читає старший байт нового вимірювання, а молодший байт ще належить старому), зчитування результатів АЦП виконується виключно **пакетною неподільною транзакцією**:

1. Мікроконтролер відправляє команду запису адреси початкового регістра `0x04` (`PRESS_XLSB`).
2. Без видачі сигналу Stop генерується сигнал Repeated Start і надсилається адреса читання.
3. Послідовно читаються 6 байтів підряд із автоінкрементом адреси всередині чипа: `PRESS_XLSB`, `PRESS_LSB`, `PRESS_MSB`, `TEMP_XLSB`, `TEMP_LSB`, `TEMP_MSB`.

:::tabs
```c
// Формування 24-бітних цілих значень із буфера транзакції
uint32_t parse_raw_pressure(const uint8_t buf[6]) {
    return ((uint32_t)buf[2] << 16) | ((uint32_t)buf[1] << 8) | buf[0];
}

uint32_t parse_raw_temperature(const uint8_t buf[6]) {
    return ((uint32_t)buf[5] << 16) | ((uint32_t)buf[4] << 8) | buf[3];
}
```
```cpp
// Ідіоматичний розбір 24-бітних значень у C++
#include <span>
#include <cstdint>

struct RawAdcSamples {
    uint32_t pressure;
    uint32_t temperature;
};

[[nodiscard]] constexpr RawAdcSamples parse_raw_samples(std::span<const uint8_t, 6> buf) noexcept {
    const uint32_t raw_p = static_cast<uint32_t>(buf[0]) |
                          (static_cast<uint32_t>(buf[1]) << 8) |
                          (static_cast<uint32_t>(buf[2]) << 16);

    const uint32_t raw_t = static_cast<uint32_t>(buf[3]) |
                          (static_cast<uint32_t>(buf[4]) << 8) |
                          (static_cast<uint32_t>(buf[5]) << 16);

    return { raw_p, raw_t };
}
```
:::

Отримані беззнакові 24-бітні величини передаються у модуль поліноміальної компенсації для приведення до дійсних паскалів і градусів Цельсія.
