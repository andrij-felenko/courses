# 📋 Протокол зв'язку й командний інтерфейс NDIR-модуля (Sensirion SCD30)

Оптичний сенсор двоокису вуглецю Sensirion SCD30 взаємодіє з провідним мікроконтролером через двопровідну шину I2C за протоколом командних фреймів із верифікацією контрольних сум CRC-8. Обмін даними вимагає врахування апаратних особливостей модуля: тривалого розтягування тактового сигналу SCL під час оптичних вимірювань, імпульсного енергоспоживання інфрачервоного випромінювача та суворого дотримання послідовності байтів Big-Endian у реєстрах конфігурації й калібрування.

---

### 1. Електричні параметри та фізичний рівень I2C

Сенсор SCD30 функціонує як ведений пристрій (*I2C slave*) з апаратно фіксованою 7-бітною адресою `0x61`. У 8-бітному представленні з урахуванням біта напрямку передачі (*R/W bit*) адреса набуває вигляду:
* Байт запису команди (*Write*): `0xC2` (біти `[7:1] = 0x61`, біт `0 = 0`);
* Байт читання даних (*Read*): `0xC3` (біти `[7:1] = 0x61`, біт `0 = 1`).

#### Часові обмеження та розтягування тактового сигналу (Clock Stretching)

1. **Тактова частота**: сенсор гарантовано підтримує стандартний режим (*Standard-mode*) з тактовою частотою лінії SCL до **100 кГц**. Робота на підвищених частотах (Fast-mode 400 кГц) виробником не гарантується і часто призводить до втрати окремих бітів або зависання автомата станів приладу.
2. **Розтягування тактового сигналу (*Clock Stretching*)**: під час виконання внутрішніх вимірювань, роботи АЦП, зчитування сигнатур із внутрішньої Flash-пам'яті та розрахунку алгоритмів лінеаризації мікроконтролер сенсора примусово притягує лінію SCL до землі (рівень логічного нуля). Провідний контролер (*I2C Master*) **зобов'язаний** очікувати звільнення лінії SCL сенсором:
   * Типова тривалість розтягування SCL під час запису команд: до **30 мс**;
   * Максимальна тривалість розтягування SCL під час виконання вимірювання: до **150 мс**.
   Якщо апаратний контролер I2C або програмний драйвер хоста має жорсткий таймаут очікування лінії SCL (наприклад, стандартні 10 мс у деяких RTOS), транзакція буде аварійно обірвана з помилкою шини (*I2C Timeout / Bus Error*). Таймаут очікування SCL у конфігурації хоста необхідно встановлювати не менше **200 мс**.
3. **Вимоги до живлення та підтягувальних резисторів**:
   * Лінії SDA та SCL вимагають зовнішніх підтягувальних резисторів до шини `VDD = 3.3` В номіналом `4.7` кОм (або `2.2` кОм при довжині шлейфу понад 15 см для компенсації паразитної ємності).
   * Під час спалаху внутрішньої оптичної лампи розжарювання або розігріву MEMS-нагрівача споживання струму стрибає від чергових 5 мкА до пікових **75–100 мА** на час близько 50 мс. У разі слабкого стабілізатора живлення або тонких доріжок плати напруга просідає, що провокує скидання мікроконтролера модуля (*Brown-Out Reset*). Безпосередньо біля виводів VDD і GND модуля обов'язково встановлюють блокувальний керамічний конденсатор ємністю `10..47` мкФ із низьким еквівалентним послідовним опором (Low-ESR).

### 2. Структура протокольних фреймів і розрахунок CRC-8

Усі транзакції обміну на шині I2C структуровані у вигляді 16-бітних командних слів (*Big-Endian*, старший байт MSB передається першим). 

#### Формати передачі даних

1. **Команда без аргументів** (наприклад, зупинка вимірювань `0x0104` або м'яке скидання `0xD304`):
   ```
   [START] -> [0xC2 (Addr+W)] -> [Cmd_MSB] -> [Cmd_LSB] -> [STOP]
   ```
2. **Команда із 16-бітним аргументом** (наприклад, запуск вимірювань `0x0010` із тиском `1013` гПа):
   ```
   [START] -> [0xC2] -> [Cmd_MSB] -> [Cmd_LSB] -> [Arg_MSB] -> [Arg_LSB] -> [CRC8] -> [STOP]
   ```
3. **Зчитування результату**: кожні **два байти корисних даних (16-бітне слово)** обов'язково супроводжуються **одним байтом контрольної суми CRC-8**. Якщо сенсор віддає 32-бітне число (2 слова), пакет містить 6 байтів:
   ```
   [START] -> [0xC3 (Addr+R)] -> [Word0_MSB] -> [Word0_LSB] -> [CRC0] -> [Word1_MSB] -> [Word1_LSB] -> [CRC1] -> [STOP]
   ```

#### Математична специфікація контрольної суми CRC-8

Контрольна сума CRC-8 гарантує захист від спотворення бітів під дією електромагнітних завад, шумів живлення та перехідних процесів:
* **Твірний поліном**: `0x31` (`x⁸ + x⁵ + x⁴ + 1`);
* **Початкове значення (Initialization Value)**: `0xFF`;
* **Фінальна маска XOR (Final XOR)**: `0x00` (результат не інвертується);
* **Напрямок зсуву**: від старшого біта до молодшого (MSB-first).

:::tabs
```c
#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

#define SCD30_CRC8_POLYNOMIAL  0x31
#define SCD30_CRC8_INIT        0xFF

/**
 * @brief Розрахунок контрольної суми CRC-8 за алгоритмом Sensirion.
 * @param data Вказівник на буфер даних (зазвичай 2 байти 16-бітного слова).
 * @param len Кількість байтів для розрахунку.
 * @return 8-бітне значення контрольної суми.
 */
uint8_t scd30_compute_crc8(const uint8_t *data, size_t len) {
    uint8_t crc = SCD30_CRC8_INIT;
    for (size_t i = 0; i < len; ++i) {
        crc ^= data[i];
        for (uint8_t bit = 8; bit > 0; --bit) {
            if (crc & 0x80) {
                crc = (crc << 1) ^ SCD30_CRC8_POLYNOMIAL;
            } else {
                crc = (crc << 1);
            }
        }
    }
    return crc;
}

/**
 * @brief Перевірка цілісності двох байтів даних за допомогою отриманого CRC.
 */
bool scd30_check_crc8(const uint8_t data[2], uint8_t expected_crc) {
    return scd30_compute_crc8(data, 2) == expected_crc;
}
```
```cpp
#include <cstdint>
#include <span>
#include <array>

namespace sensirion::scd30 {

constexpr uint8_t Crc8Polynomial = 0x31;
constexpr uint8_t Crc8Init = 0xFF;

/**
 * @brief Розрахунок контрольної суми CRC-8 на етапі компіляції або виконання.
 */
[[nodiscard]] constexpr uint8_t compute_crc8(std::span<const uint8_t> data) noexcept {
    uint8_t crc = Crc8Init;
    for (const uint8_t byte : data) {
        crc ^= byte;
        for (uint8_t bit = 8; bit > 0; --bit) {
            if ((crc & 0x80) != 0) {
                crc = static_cast<uint8_t>((crc << 1) ^ Crc8Polynomial);
            } else {
                crc = static_cast<uint8_t>(crc << 1);
            }
        }
    }
    return crc;
}

/**
 * @brief Верифікація отриманого слова даних та контрольного байта.
 */
[[nodiscard]] constexpr bool check_crc8(std::span<const uint8_t, 2> word, uint8_t expected_crc) noexcept {
    return compute_crc8(word) == expected_crc;
}

} // namespace sensirion::scd30
```

### 4. Детальний аналіз пакету вимірювання (Read Measurement `0x0300`)

Під час запиту команди `0x0300` хост зчитує 18 байтів. Корисні дані складаються з трьох 32-бітних чисел із плаваючою комою (*IEEE-754 Single-Precision Float*), кожне з яких розбите на два 16-бітних слова:

1. **Концентрація CO₂** (`float32`, ppm):
   * Байти 0–1: `CO2_Word0` (MSB числа з плаваючою комою: біт знака, порядок та старша частина мантиси `[31:16]`);
   * Байт 2: `CRC8` від байтів 0 і 1;
   * Байти 3–4: `CO2_Word1` (молодша частина мантиси `[15:0]`);
   * Байт 5: `CRC8` від байтів 3 і 4;
2. **Температура навколишнього середовища** (`float32`, градуси Цельсія °C):
   * Байти 6–7: `Temp_Word0` `[31:16]`;
   * Байт 8: `CRC8` від байтів 6 і 7;
   * Байти 9–10: `Temp_Word1` `[15:0]`;
   * Байт 11: `CRC8` від байтів 9 і 10;
3. **Відносна вологість повітря** (`float32`, % RH):
   * Байти 12–13: `RH_Word0` `[31:16]`;
   * Байт 14: `CRC8` від байтів 12 і 13;
   * Байти 15–16: `RH_Word1` `[15:0]`;
   * Байт 17: `CRC8` від байтів 15 і 16.

:::tabs
```c
#include <stdint.h>
#include <string.h>
#include <stdbool.h>

typedef struct {
    float co2_ppm;
    float temperature_c;
    float relative_humidity_pct;
} scd30_raw_measurement_t;

/**
 * @brief Повний парсинг та валідація 18-байтового фрейму SCD30.
 * @param rx_buf Буфер із 18 отриманими байтами.
 * @param out_meas Вказівник на структуру для збереження результатів.
 * @return 0 при успіху, -1 при помилці валідації CRC.
 */
int scd30_unpack_measurement_frame(const uint8_t rx_buf[18], scd30_raw_measurement_t *out_meas) {
    // Перевірка цілісності всіх 6 контрольних сум CRC-8
    for (size_t i = 0; i < 6; ++i) {
        uint8_t calculated_crc = scd30_compute_crc8(&rx_buf[i * 3], 2);
        if (calculated_crc != rx_buf[i * 3 + 2]) {
            return -1; // Пакет пошкоджено завадами на шині
        }
    }

    // Реконструкція 32-бітних слів Big-Endian
    uint32_t raw_co2 = ((uint32_t)rx_buf[0] << 24) |
                       ((uint32_t)rx_buf[1] << 16) |
                       ((uint32_t)rx_buf[3] << 8)  |
                       ((uint32_t)rx_buf[4]);

    uint32_t raw_temp = ((uint32_t)rx_buf[6] << 24) |
                        ((uint32_t)rx_buf[7] << 16) |
                        ((uint32_t)rx_buf[9] << 8)  |
                        ((uint32_t)rx_buf[10]);

    uint32_t raw_rh = ((uint32_t)rx_buf[12] << 24) |
                      ((uint32_t)rx_buf[13] << 16) |
                      ((uint32_t)rx_buf[15] << 8)  |
                      ((uint32_t)rx_buf[16]);

    // Копіювання у пам'ять float (IEEE-754) без порушення strict-aliasing
    memcpy(&out_meas->co2_ppm, &raw_co2, sizeof(float));
    memcpy(&out_meas->temperature_c, &raw_temp, sizeof(float));
    memcpy(&out_meas->relative_humidity_pct, &raw_rh, sizeof(float));

    return 0;
}
```
```cpp
#include <cstdint>
#include <array>
#include <span>
#include <optional>
#include <bit>

namespace sensirion::scd30 {

struct MeasurementResult {
    float co2_ppm{0.0f};
    float temperature_c{0.0f};
    float relative_humidity_pct{0.0f};
};

/**
 * @brief Безпечний розбір 18-байтового фрейму вимірювання за стандартом C++20.
 */
[[nodiscard]] std::optional<MeasurementResult> unpack_measurement_frame(
    std::span<const uint8_t, 18> rx_buf) noexcept 
{
    // Валідація 6 пар даних і відповідних CRC-8 байтів
    for (size_t i = 0; i < 6; ++i) {
        const auto word_slice = rx_buf.subspan(i * 3, 2);
        const uint8_t expected_crc = rx_buf[i * 3 + 2];
        if (compute_crc8(word_slice) != expected_crc) {
            return std::nullopt;
        }
    }

    const auto extract_float = [](const uint8_t* p) noexcept -> float {
        const uint32_t raw_bits = (static_cast<uint32_t>(p[0]) << 24) |
                                  (static_cast<uint32_t>(p[1]) << 16) |
                                  (static_cast<uint32_t>(p[3]) << 8)  |
                                  (static_cast<uint32_t>(p[4]));
        return std::bit_cast<float>(raw_bits);
    };

    MeasurementResult res{};
    res.co2_ppm = extract_float(&rx_buf[0]);
    res.temperature_c = extract_float(&rx_buf[6]);
    res.relative_humidity_pct = extract_float(&rx_buf[12]);

    return res;
}

} // namespace sensirion::scd30
```

### 5. Обробка помилок та типові крайові випадки шини I2C

1. **Зчитування даних без перевірки Data Ready**: якщо відправити команду читання `0x0300` до того, як внутрішній оптичний цикл завершився і команда `0x0202` повернула `0x0001`, модуль відповість сигналом NACK або поверне застарілий буфер попереднього вимірювання. Опитування `0x0202` є обов'язковим кроком перед кожним читанням `0x0300`.
2. **Зависання лінії SDA на низькому рівні (I2C Bus Lockup)**: якщо мікроконтролер хоста перезавантажився або був скинутий під час транзакції читання в момент, коли сенсор виставляв біт нуля на лінію SDA, сенсор залишається чекати наступних тактових імпульсів SCL, утримуючи SDA примусово в нулі. Для відновлення працездатності шини хост під час ініціалізації повинен виконати процедуру ручного скидання шини: згенерувати **9 тактових імпульсів на лінії SCL** через GPIO, після чого видати умову `STOP`. Це змушує ведений пристрій завершити передачу поточного байта й відпустити лінію SDA.
3. **Фільтрація невалідних значень**: після запуску модуля перші 2–3 вимірювання можуть містити нульові значення або значення за межами фізичного діапазону (`CO2 < 300` ppm або `CO2 > 40000` ppm), поки прогрівається оптична кювета й стабілізується тепловий режим. У драйвері слід ігнорувати перші два відліки після старту неперервного вимірювання.
