# ⚙️ Адаптивний фільтр EPA NowCast для мікроконтролера

Коли концентрація дрібнодисперсного пилу в місті стрімко зростає через лісову пожежу, піщану бурю або аварійний викид промислового підприємства, стандартне 24-годинне просте ковзне середнє (Simple Moving Average, SMA) створює неприпустиме фазове запізнення у 12 годин. Прилад показує зелений рівень «Добре», коли за вікном уже стоїть небезпечний для життя смог. Якщо ж повністю відмовитися від усереднення й показувати миттєві хвилинні виміри, екран приладу хаотично стрибатиме через локальні пориви вітру, вихлоп автомобіля, що проїхав повз, або випадковий шум лазерного сенсора.

Алгоритм **EPA NowCast** розв'язує цю суперечність: він автоматично аналізує дисперсію концентрацій за останні 12 годин і динамічно адаптує вагові коефіцієнти від майже рівномірних (у стабільному атмосферному стані) до крутоспадних експоненційних (під час різких сплесків).

У цій проектній вставці наведено повну математичну модель, покроковий числовий розбір, архітектуру кільцевого буфера для вбудованих систем на C та C++, а також аналіз крайових випадків у роботі польових давачів.

### Математичний механізм адаптивного зважування

Фільтр зберігає 12 останніх погодинних вимірювань C₀, C₁, ..., C₁₁, де C₀ — найсвіжіша година, а C₁₁ — значення 11 годин тому.

#### 1. Пошук розмаху концентрацій
Серед усіх дійсних (валідованих) годин у вікні знаходяться мінімальне C_min та максимальне C_max значення:

```
C_min = min(C_0, C_1, ..., C_11)        [найчистіша година у 12-годинному вікні]
C_max = max(C_0, C_1, ..., C_11)        [найбрудніша година у 12-годинному вікні]
```

#### 2. Динамічний ваговий множник w
Швидкість зміни стану атмосфери оцінюється відношенням екстремумів:

```
w = C_min / C_max                    [відношення екстремумів]
якщо w < 0.5, то w = 0.5             [нижня межа ваги за стандартом EPA]
якщо C_max == 0, то w = 1.0          [захист від ділення на нуль при ідеально чистому повітрі]
```

- **Стабільна атмосфера (C_min ≈ C_max):** w наближається до 1.0. Ваги wⁱ для всіх 12 годин майже однакові (1.0, 0.98, 0.96...). Фільтр працює як звичайне 12-годинне середнє, максимально пригнічуючи вимірювальний шум сенсора.
- **Різкий спалах смогу (C_max ≫ C_min):** w = 0.5. Ваги спадають у геометричній прогресії: 1.0, 0.5, 0.25, 0.125, 0.0625... Сума перших двох годин становить 1.0 + 0.5 = 1.5 із загальної суми приблизно 2.0, тобто 75% підсумкового показника формується даними за останні 120 хвилин.

#### 3. Адаптивно-зважене інтегрування

```
C_NowCast = (C_0·w⁰ + C_1·w¹ + C_2·w² + ... + C_11·w¹¹) / (w⁰ + w¹ + w² + ... + w¹¹)
```

#### 4. Критерій валідності EPA
Згідно з настановами EPA, розрахунок NowCast вважається достовірним лише за умови, що з трьох останніх годин (C₀, C₁, C₂) наявні щонайменше дві валідні години вимірювань. Якщо прилад пропустив дві останні години через втрату живлення або збій шини I²C/UART, фільтр зобов'язаний повернути статус помилки нестачі даних.

### Покроковий числовий приклад розрахунку

Розглянемо реальний сценарій: о 10:00 ранку спалахнула лісова пожежа, і концентрація PM2.5 стрімко зросла від фонових 10 мкг/м³ до 180 мкг/м³.

Історія вимірювань за 12 годин (від C₀ до C₁₁):
- C₀ (12:00, поточна): 180.0 мкг/м³
- C₁ (11:00): 140.0 мкг/м³
- C₂ (10:00): 60.0 мкг/м³
- C₃...C₁₁ (01:00–09:00): по 10.0 мкг/м³

Покроковий розрахунок:
1. C_min = 10.0, C_max = 180.0.
2. Ваговий коефіцієнт: w = 10.0 / 180.0 = 0.0555... Оскільки w < 0.5, встановлюємо w = 0.5.
3. Ваговий вектор wⁱ: `[1.000, 0.500, 0.250, 0.125, 0.0625, 0.03125, 0.0156, 0.0078, 0.0039, 0.0020, 0.0010, 0.0005]`.
4. Сума ваг: ∑ wⁱ = 1.999 ≈ 2.000.
5. Зважена сума концентрацій:
```
Чисельник = 180·1.0 + 140·0.5 + 60·0.25 + 10·(0.125 + 0.0625 + ... + 0.0005)
          = 180.0   + 70.0    + 15.0    + 10·0.249
          = 265.0   + 2.49    = 267.49

C_NowCast = 267.49 / 1.999 ≈ 133.8 мкг/м³
```

Порівняємо це з класичним 24-годинним середнім, яке показало б лише (180 + 140 + 60 + 21 · 10) / 24 ≈ 24.6 мкг/м³ (категорія «Помірне»). NowCast дав 133.8 мкг/м³ (категорія «Шкідливе»), що відповідає реальній загрозі для населення.

### Архітектура та часова синхронізація у вбудованих приладах

У польових мікроконтролерах давачі опитуються не раз на годину, а щосекунди або щохвилини для підтримки інтегрального накопичення. Робота фільтра будується за дворівневою схемою:

1. **Субпогодинний інтегратор (Sub-hourly accumulator):** хвилинні виміри накопичуються в 60-елементному буфері поточної години. Наприкінці кожної 60-ї хвилини таймер RTC генерує подію фіксації середньогодинного значення, яке заштовхується в 12-годинний кільцевий буфер NowCast.
2. **Компенсація нестабільності годинника (RTC Jitter):** якщо вбудований годинник дрейфує або прилад синхронізує час через NTP/GPS зі стрибком часу, алгоритм перевіряє часові мітки точок і заповнює втрачені інтервали лінійною інтерполяцією лише тоді, коли перерва не перевищує 30 хвилин. Триваліші пропуски маркуються прапорцем `valid = false`.

### Пастки та інженерні крайові випадки

1. **Захист від ділення на нуль при ідеально чистому повітрі.** Якщо прилад працює в чистій кімнаті або тестовій камері з нульовим вмістом пилу, усі елементи буфера мають значення `0.0`. Вираз `c_min / c_max` призведе до `0.0 / 0.0 = NaN` або апаратного збою арифметичного співпроцесора. Умова `if (c_max > 0.0f)` забезпечує коректну поведінку: w = 1.0, а результат дорівнює строго `0.0`.
2. **Пропуски даних та асинхронні опитування.** Якщо прилад перезавантажився або зв'язок із сенсором переривався, неприпустимо записувати нуль у буфер як дійсну концентрацію. Невалідна година позначається `valid = false`. Вона виключається з пошуку мінімуму/максимуму та не додає ваги до знаменника. Це запобігає штучному заниженню рівня небезпеки.
3. **Обмеження оперативної пам'яті.** Структура на 12 комірок типу `float` разом із булевими прапорцями займає менше 80 байтів пам'яті. Вона повністю розміщується в статичній пам'яті стека або глобальної секції BSS, не вимагаючи динамічного розподілу пам'яті через `malloc` чи `new`, що робить її безпечною для вбудованих систем реального часу з жорсткими вимогами надійності (MISRA-C).
