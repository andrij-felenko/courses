# ⚙️ Практика: Лінеаризація тріангуляційного далекоміра — таблиця й керування по 1/d

## Задача

Аналоговий ІЧ-тріангуляційний далекомір (наприклад, поширені давачі Sharp серії GP2Y0A) віддає на вихід **напругу**, а не сантиметри. І зв'язана ця напруга з відстанню не прямо, а **гіперболічно**: давач міряє зсув світлової плями x, а відстань d = f·b/x, тож вихід тягне за собою множник 1/d. Унаслідок цього однаковий крок напруги біля давача й удалині означає зовсім різний крок відстані, а «взяти напругу за сантиметри» (помножити на сталий коефіцієнт) дає число, яке бреше тим сильніше, чим далі ціль.

Інженерна задача конкретна. Мікроконтролер (візьмемо ESP32) читає цю напругу своїм АЦП. Треба перетворити її на **чесну відстань у сантиметрах** — щоб робот знав, що до краю столу лишилося 12 см, а не «якась напруга 1.6 В». Або, у іншому й дуже поширеному випадку, відстань як така й не потрібна: треба лише **тримати сталий проміжок** до стіни чи до попередника в колоні — і тоді, як побачимо, переводити в сантиметри взагалі не варто.

Розберемо два робочі шляхи: (а) **калібрувальна таблиця** з кількох знятих пар «напруга → відстань» і лінійною інтерполяцією між вузлами — коли потрібні справжні сантиметри; (б) **керування прямо по 1/d** (а на практиці — по самій напрузі, що йому пропорційна) — коли потрібне не число, а утримання уставки. Поза обсягом лишаються: синхронне детектування засвітки (його робить сам давач), боротьба з шумом — її бере [усереднення відліків](root:embedded/signal-acquisition), і точність самого АЦП — її дає [калібрування АЦП](topic:hw-sensing/adc-errors).

## Ідея

### Шлях А: таблиця «напруга → відстань» з інтерполяцією

Спокуса перша й хибна — підставити ідеальну формулу d = f·b/x і рахувати відстань аналітично. На папері вона точна, але реальний давач від неї відходить: лінза має аберації, складання — перекоси, а «нуль» зсуву плями плаває. Тому замість того щоб довіряти формулі, **знімають саму криву** — ставлять ціль на кілька відомих відстаней, записують напругу на кожній, і ці пари стають **вузлами таблиці**. Між вузлами відстань рахують **лінійною інтерполяцією**: на короткому відрізку гіпербола майже пряма, тож пряма між двома сусідніми вузлами дає мізерну похибку, якщо вузли досить часті там, де крива крута (зблизька).

Таблиця ловить **справжню** характеристику конкретного екземпляра, а не ідеальну. Це той самий хід, що й [калібрування](topic:hw-sensing/calibration) будь-якого нелінійного давача: не виводити вихід із теорії, а **зміряти** його по опорних точках і інтерполювати.

**Приклад (як напруга стає сантиметрами).** Хай у таблиці є вузли (0.75 В → 45 см) і (1.05 В → 30 см), а давач показав 0.90 В. Напруга лежить рівно посередині інтервалу:

```
t = (0.90 − 0.75) / (1.05 − 0.75) = 0.15 / 0.30 = 0.5
d = 45 + 0.5 · (30 − 45) = 45 − 7.5 = 37.5 см
```

Пляма, що дала 0.90 В, відповідає 37.5 см — і це число чесне рівно настільки, наскільки чесно зняті два сусідні вузли.

### Шлях Б: керувати прямо по 1/d

Тепер хитрість, що часто рятує від усієї таблиці. Згадаймо: зсув плями x ∝ 1/d, а вихідна напруга давача U ∝ x (положення плями). Отже, **U ∝ 1/d** — сама напруга вже є майже лінійною мірою величини 1/d (її називають «оберненою відстанню», або просто близькістю). А коли задача — не назвати відстань, а **тримати** її сталою (їхати за стіною на сталому проміжку, утримувати дистанцію в колоні), регуляторові байдуже до сантиметрів: йому досить будь-якої величини, що монотонно й по змозі **лінійно** залежить від відстані. Напруга — саме така.

**Приклад (чому 1/d — зручний важіль).** Порахуймо нахил характеристики у двох кінцях. Між вузлами 0.40 В (80 см) і 0.55 В (60 см) відстань падає на 20 см за 0.15 В; між 1.55 В (20 см) і 2.30 В (12 см) — лише на 8 см за 0.75 В:

```
далеко:   Δd/ΔU = 20 см / 0.15 В ≈ 133 см/В
зблизька: Δd/ΔU =  8 см / 0.75 В ≈  11 см/В   (у 12 разів менший)
```

Нахил d(U) змінився у **дванадцять разів** — крива справді гіперболічна, лінійним коефіцієнтом її не випрямиш. Тепер ті самі вузли в координаті 1/d:

```
далеко:   Δ(1/d)/ΔU = (1/60 − 1/80) / 0.15 ≈ 0.028 (В·см)⁻¹
зблизька: Δ(1/d)/ΔU = (1/12 − 1/20) / 0.75 ≈ 0.044 (В·см)⁻¹   (лише в 1.6 раза більший)
```

Нахил 1/d за напругою майже сталий — **1/d практично пряма** за U. Ось чому для регулятора зручніше керувати прямо по 1/d (або по сирій напрузі, що йому пропорційна): жодної таблиці, жодного випрямлення, а петля керування дістає величину, лінійну там, де давач і працює.

## Робочий код (C/C++, ESP32 / Arduino)

### Таблиця та інтерполяція

Вузли тримаємо в масиві, **відсортованому за зростанням напруги**. Що ближча ціль, то більший зсув плями й більша напруга, тож зростанню напруги відповідає **спадання** відстані:

:::tabs
```cpp
struct CalPoint {
    float v;   // напруга з давача, В
    float d;   // виміряна відстань, см
};

// Зняті калібруванням пари, відсортовані за зростанням v.
// Густіше там, де крива крута (зблизька, велика напруга).
const CalPoint LUT[] = {
    { 0.40f, 80.0f },   // далеко: слабкий зсув плями, мала напруга
    { 0.55f, 60.0f },
    { 0.75f, 45.0f },
    { 1.05f, 30.0f },
    { 1.55f, 20.0f },
    { 2.30f, 12.0f },
    { 2.75f, 10.0f },   // близько: мінімальна надійна відстань
};
const int LUT_N = sizeof(LUT) / sizeof(LUT[0]);

// Лінійна інтерполяція: напруга → відстань (см).
float voltageToDistance(float v) {
    // За межами таблиці не екстраполюємо — там давач бреше. Клемп.
    if (v <= LUT[0].v)         return LUT[0].d;
    if (v >= LUT[LUT_N - 1].v) return LUT[LUT_N - 1].d;

    // Знайти інтервал [i, i+1], куди потрапила напруга.
    int i = 0;
    while (i < LUT_N - 1 && LUT[i + 1].v < v) i++;

    // Пряма між двома вузлами.
    float t = (v - LUT[i].v) / (LUT[i + 1].v - LUT[i].v);
    return LUT[i].d + t * (LUT[i + 1].d - LUT[i].d);
}
```
```micropython
# Зняті калібруванням пари (напруга В, відстань см),
# відсортовані за зростанням напруги.
# Густіше там, де крива крута (зблизька, велика напруга).
LUT = (
    (0.40, 80.0),   # далеко: слабкий зсув плями, мала напруга
    (0.55, 60.0),
    (0.75, 45.0),
    (1.05, 30.0),
    (1.55, 20.0),
    (2.30, 12.0),
    (2.75, 10.0),   # близько: мінімальна надійна відстань
)

# Лінійна інтерполяція: напруга → відстань (см).
def voltage_to_distance(v):
    # За межами таблиці не екстраполюємо — там давач бреше. Клемп.
    if v <= LUT[0][0]:
        return LUT[0][1]
    if v >= LUT[-1][0]:
        return LUT[-1][1]

    # Знайти інтервал [i, i+1], куди потрапила напруга.
    i = 0
    while i < len(LUT) - 1 and LUT[i + 1][0] < v:
        i += 1

    # Пряма між двома вузлами.
    v0, d0 = LUT[i]
    v1, d1 = LUT[i + 1]
    t = (v - v0) / (v1 - v0)
    return d0 + t * (d1 - d0)
```
:::

Функція `voltageToDistance` — чиста: дай їй напругу, дістанеш сантиметри, жодного звернення до заліза. Її легко перевірити на столі — підставити 0.90 В і впевнитися, що вийде 37.5 см.

### Читання давача з усередненням

Сирий відлік АЦП тремтить, тож усереднюємо кілька й переводимо в вольти:

:::tabs
```cpp
const int   SENSOR_PIN = 34;
const float ADC_VREF   = 3.3f;
const int   ADC_MAX    = 4095;

float readSensorVolts(int pin, int n = 16) {
    long acc = 0;
    for (int k = 0; k < n; k++) acc += analogRead(pin);
    return (float(acc) / n) * (ADC_VREF / ADC_MAX);
}

void setup() {
    Serial.begin(115200);
    analogReadResolution(12);                       // 0..4095
    analogSetPinAttenuation(SENSOR_PIN, ADC_11db);  // вхід ~0..3.3 В
}

void loop() {
    float v = readSensorVolts(SENSOR_PIN);
    float d = voltageToDistance(v);
    Serial.printf("U=%.3f В  d=%.1f см\n", v, d);
    delay(50);
}
```
```micropython
from machine import ADC, Pin
import time

SENSOR_PIN = 34
ADC_VREF   = 3.3
ADC_MAX    = 4095

adc = ADC(Pin(SENSOR_PIN))
adc.width(ADC.WIDTH_12BIT)   # 0..4095
adc.atten(ADC.ATTN_11DB)     # вхід ~0..3.3 В

def read_sensor_volts(n=16):
    acc = 0
    for _ in range(n):
        acc += adc.read()
    return (acc / n) * (ADC_VREF / ADC_MAX)

while True:
    v = read_sensor_volts()
    d = voltage_to_distance(v)
    print("U=%.3f В  d=%.1f см" % (v, d))
    time.sleep_ms(50)
```
:::

### Альтернатива: утримання проміжку по 1/d

Коли потрібні не сантиметри, а стала дистанція, відкидаємо таблицю зовсім. Уставку задаємо одразу **в напрузі**, що відповідає бажаному проміжку, і годуємо помилкою пропорційний регулятор:

:::tabs
```cpp
const float V_SETPOINT = 1.05f;  // напруга бажаного проміжку (~30 см за таблицею)
const float KP         = 200.0f; // коефіцієнт П-регулятора

void loopHoldGap() {
    float v     = readSensorVolts(SENSOR_PIN);
    float err   = v - V_SETPOINT;     // v більша → ціль ближча, ніж треба
    int   drive = int(-KP * err);     // ближча → їхати назад
    drive = constrain(drive, -255, 255);
    setMotor(drive);                  // ваш драйвер мотора
    delay(20);
}
```
```micropython
V_SETPOINT = 1.05  # напруга бажаного проміжку (~30 см за таблицею)
KP         = 200.0  # коефіцієнт П-регулятора

while True:
    v     = read_sensor_volts()
    err   = v - V_SETPOINT       # v більша → ціль ближча, ніж треба
    drive = int(-KP * err)       # ближча → їхати назад
    drive = max(-255, min(255, drive))
    set_motor(drive)             # ваш драйвер мотора
    time.sleep_ms(20)
```
:::

Жодного `voltageToDistance`, жодної таблиці: петля працює прямо на напрузі, яка ∝ 1/d, а отже майже лінійна за відстанню в робочій зоні. Якщо хочеться саме «оберненої відстані» в явному вигляді (щоб коефіцієнти регулятора мали фізичний сенс), її дешево дістати як `invD = k * v` з єдиним калібрувальним коефіцієнтом k — це одна точка, а не ціла таблиця.

## Складність і пастки на МК

**Мертва зона коло нуля.** Найнебезпечніша пастка тріангуляції — [немонотонність ближче за мінімальну дальність](topic:hw-sensing/sensor-characteristics): дуже близька ціль дає таку саму (або й меншу) напругу, як далека, і таблиця впевнено покаже «далеко» там, де ціль майже впритул. Таблиця цього не ловить сама — її треба захистити: відкидати або позначати недостовірними відліки, що лежать поза робочим діапазоном напруг, і **ніколи** не заводити вузли нижче за мінімальну дальність. Для уникання зіткнень це питання безпеки, а не точності.

**Вузли мусять бути монотонні.** Інтерполяція передбачає, що напруга строго зростає від вузла до вузла. Якщо при калібруванні дві сусідні точки дали однакову або «перевернуту» напругу (шум, тремтлива рука), різниця `LUT[i+1].v - LUT[i].v` стане нулем чи від'ємною — ділення зірветься або дасть дич. Перевіряйте монотонність таблиці при старті; усереднюйте довше під час зняття вузлів.

**Густота вузлів — за крутизною.** Лінійна інтерполяція тим точніша, чим пряміша крива на відрізку. Гіпербола крута зблизька (велика напруга) й полога вдалині, тож вузли ставлять **густіше там, де круто** — інакше пряма між далекими вузлами зріже «горб» кривої. Рівномірний крок напруги тут — погана ідея; кроком керує форма характеристики.

**Опорна напруга АЦП.** Функція `readSensorVolts` ділить на сталу `ADC_VREF = 3.3`, але реальна опора АЦП плаває від чипа до чипа й від температури. Якщо давач і АЦП живляться від **спільної** шини, вигідно міряти ratiometric — тоді коливання живлення скорочуються в обчисленні. Інакше варто [відкалібрувати сам АЦП](topic:hw-sensing/adc-errors/proj-two-point-cal.md): без цього таблиця, знята на одному чипі, на іншому трохи зсунеться.

**Шум і усереднення.** Один відлік тремтить, особливо вдалині, де [роздільність тане](topic:hw-sensing/sensor-characteristics) (та сама обернена залежність d ∝ 1/x). Усереднення кількох відліків (тут — 16) гасить випадковий шум; де треба швидко й гладко водночас — додають [медіанний чи ковзний фільтр](root:embedded/signal-acquisition). Не плутайте усереднення (б'є випадковий шум) із калібруванням (б'є системну криву): це різні хвороби, і таблиця не лікує жодної з них.

**Float чи ціле.** На ESP32 float апаратний, тож таблиця у float — нормально. На дрібному AVR без FPU інтерполяцію краще перевести в цілі числа (напругу тримати в кодах АЦП, відстань — у міліметрах, рахувати в `int32_t`), а саму таблицю покласти у флеш через `PROGMEM`. Логіка та сама, лише без плаваючої коми.

**Бінарний пошук — коли вузлів багато.** Лінійний прохід `while` по таблиці — O(N), і для семи вузлів це дешевше за будь-який бінарний пошук. Та якщо таблиця розрослася до десятків вузлів і кличеться в гарячому циклі, інтервал шукають бінарним пошуком за O(log N). Для типового далекоміра з кількома вузлами це зайве.

**Поверхня цілі.** Жодна таблиця не врятує, якщо пляма «попливла» через дзеркальну, скошену чи прозору ціль: давач бачить не ту відстань, і відкалібрований вихід чесно перекаже хибний вимір. Калібрування лікує форму кривої, а не фізику відбиття — тримайте давач у його робочих умовах (матові поверхні, у межах дальності).

## Підсумок

Сире число з тріангуляційного давача — не відстань, а напруга, гіперболічно зв'язана з нею. Потрібні сантиметри — знімай криву калібруванням у кілька вузлів і інтерполюй між ними лінійно, не довіряючи ідеальній формулі. Потрібно лише тримати дистанцію — не випрямляй нічого, керуй прямо по 1/d (по самій напрузі), яка майже лінійна там, де давач працює. І хоч би який шлях ти обрав, шануй мінімальну дальність: нижче за неї крива повертає, і будь-яке калібрування там бреше разом із давачем.
