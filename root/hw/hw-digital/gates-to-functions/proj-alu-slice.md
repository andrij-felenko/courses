# ⚙️ Складаємо АЛП у коді: від однієї скибки до слова з прапорцями

**Задача.** Однобітна скибка АЛП (повний суматор + банка логіки + мультиплексор за кодом операції) — це красива одиниця, та сама по собі вона не рахує нічого корисного. Реальний процесор оперує **словом** — 8, 16, 32 біти. Складімо з однакових скибок повноцінний n-бітний АЛП, що вміє додавати, віднімати й виконувати побітову логіку, а заразом виставляє **прапорці** (*flags*) — біти стану, за якими процесор потім вирішує, куди стрибати. Це той самий блок, що лежить у серці будь-якого мікроконтролера; зібравши його в C, легко зрозуміти, що насправді відбувається за однією машинною командою.

Писатимемо так, щоб код **повторював залізо**, а не зрізав кути зручними операторами мови. Тому жодного готового `a + b` для самого додавання: суму ми складаємо біт за бітом, женучи перенос розрядами — точно як [ланцюговий суматор](root:hw-digital/combinational-circuits) жене його дротами. Тоді з коду видно кожен вентиль.

### Ідея: ряд однакових скибок і перенос, що біжить

Одна скибка обробляє розряд: бере доданки `a`, `b`, перенос-вхід `cin`, код операції `op` — і віддає біт результату `y` та перенос-вихід `cout`. Багатобітне слово — це **ряд** таких скибок, з'єднаних переносом: `cout` молодшого розряду стає `cin` наступного. Перенос «біжить» від наймолодшого біта до найстаршого, і коли він добіг до кінця — слово додане.

Три деталі перетворюють простий ряд суматорів на справжній АЛП:

- **Вибір операції.** У кожній скибці паралельно рахуються сума, `a AND b`, `a OR b`. Мультиплексор за кодом `op` пропускає на вихід рівно один результат. Залізо рахує **все завжди** — вибір нічого не вимикає, лише спрямовує.
- **Віднімання задарма.** Доповняльний код (*two's complement*) дає `a − b = a + (~b) + 1`. Тому віднімач не потрібен: досить інвертувати `b` й завести одиницю в перенос наймолодшого розряду. Одна керувальна лінія `sub` робить і те, і те — XOR кожного біта `b` із `sub`, а сам `sub` стає початковим переносом.
- **Прапорці.** Після того як слово порахувалося, кілька бітів стану описують результат: **Z** (zero) — усе слово нульове; **C** (carry) — перенос вийшов за старший розряд; **N** (negative) — старший біт результату одиниця (знак у доповняльному коді); **V** (overflow) — знаковий результат не вліз. За цими бітами працюють умовні переходи процесора.

### Робочий код

:::tabs
```cpp
#include <stdint.h>

// Коди операцій АЛП
enum { OP_ADD = 0, OP_SUB = 1, OP_AND = 2, OP_OR = 3, OP_XOR = 4 };

// Прапорці стану (бітова маска)
enum { FLAG_Z = 1, FLAG_C = 2, FLAG_N = 4, FLAG_V = 8 };

#define ALU_BITS 8                      // ширина слова

// одна скибка: розряд a,b + перенос cin, код op → біт y, перенос cout
static uint8_t alu_slice(uint8_t a, uint8_t b, uint8_t cin,
                         uint8_t op, uint8_t *cout) {
    uint8_t sum  = a ^ b ^ cin;                       // біт суми = непарність трьох
    uint8_t carry= (a & b) | (cin & (a ^ b));         // перенос = «більшість»
    *cout = carry;
    switch (op) {                                     // мультиплексор за кодом
        case OP_AND: return a & b;
        case OP_OR:  return a | b;
        case OP_XOR: return a ^ b;
        default:     return sum;                      // ADD і SUB обидва йдуть сумою
    }
}

// n-бітний АЛП: рахує result і виставляє прапорці у *flags
uint32_t alu(uint32_t a, uint32_t b, uint8_t op, uint8_t *flags) {
    uint8_t is_arith = (op == OP_ADD || op == OP_SUB);
    uint8_t sub      = (op == OP_SUB);
    uint8_t cin      = sub;                           // SUB: початковий перенос = 1
    uint32_t result  = 0;
    uint8_t  cout    = 0, cprev = 0;

    for (int i = 0; i < ALU_BITS; i++) {
        uint8_t ai = (a >> i) & 1;
        uint8_t bi = (b >> i) & 1;
        bi ^= sub;                                    // SUB інвертує b (доповняльний код)
        cprev = cout;                                 // запам'ятати перенос ДО старшого біта
        uint8_t yi = alu_slice(ai, bi, cin, op, &cout);
        result |= (uint32_t)yi << i;
        cin = cout;                                   // перенос біжить у наступний розряд
    }

    // прапорці
    uint8_t f = 0;
    if ((result & ((1u << ALU_BITS) - 1)) == 0) f |= FLAG_Z;   // нуль
    if ((result >> (ALU_BITS - 1)) & 1)         f |= FLAG_N;   // знак
    if (is_arith) {
        if (cout)            f |= FLAG_C;                       // перенос за межі слова
        if (cout != cprev)   f |= FLAG_V;                       // знакове переповнення
    }
    *flags = f;
    return result & ((1u << ALU_BITS) - 1);
}
```
```python
# Коди операцій АЛП
OP_ADD, OP_SUB, OP_AND, OP_OR, OP_XOR = 0, 1, 2, 3, 4

# Прапорці стану (бітова маска)
FLAG_Z, FLAG_C, FLAG_N, FLAG_V = 1, 2, 4, 8

ALU_BITS = 8                                          # ширина слова


def alu_slice(a, b, cin, op):
    """одна скибка: розряд a,b + перенос cin, код op → (біт y, перенос cout)"""
    s     = a ^ b ^ cin                               # біт суми = непарність трьох
    carry = (a & b) | (cin & (a ^ b))                 # перенос = «більшість»
    if op == OP_AND:   y = a & b
    elif op == OP_OR:  y = a | b
    elif op == OP_XOR: y = a ^ b
    else:              y = s                           # ADD і SUB обидва йдуть сумою
    return y, carry


def alu(a, b, op):
    """n-бітний АЛП: повертає (result, flags)"""
    is_arith = op in (OP_ADD, OP_SUB)
    sub      = 1 if op == OP_SUB else 0
    cin      = sub                                    # SUB: початковий перенос = 1
    result   = 0
    cout = cprev = 0

    for i in range(ALU_BITS):
        ai = (a >> i) & 1
        bi = (b >> i) & 1
        bi ^= sub                                     # SUB інвертує b (доповняльний код)
        cprev = cout                                  # запам'ятати перенос ДО старшого біта
        yi, cout = alu_slice(ai, bi, cin, op)
        result |= yi << i
        cin = cout                                    # перенос біжить у наступний розряд

    # прапорці
    mask = (1 << ALU_BITS) - 1
    f = 0
    if (result & mask) == 0:                f |= FLAG_Z   # нуль
    if (result >> (ALU_BITS - 1)) & 1:      f |= FLAG_N   # знак
    if is_arith:
        if cout:            f |= FLAG_C                    # перенос за межі слова
        if cout != cprev:   f |= FLAG_V                    # знакове переповнення
    return result & mask, f
```

Перевіримо на руках. `alu(200, 100, OP_ADD)` для 8 бітів: 200+100 = 300, а в байт лізе лише 300−256 = 44; перенос вийшов за старший розряд, тож **C** піднятий — процесор бачить, що сталося обгортання. `alu(5, 5, OP_SUB)` дає 0 і піднятий **Z**. `alu(0, 1, OP_SUB)` дає 255 (тобто −1 у доповняльному коді) і піднятий **N**. Жодного `if` для віднімання в самому циклі — його зробили інверсія `b` і початковий перенос.

### Пастки

- **Знаковий vs беззнаковий перенос — це різні прапорці.** **C** ловить вихід за межі для **беззнакових** чисел, **V** — для **знакових**. Класична помилка — перевіряти не той: для `if (a > b)` зі знаковими операндами дивляться на комбінацію **N** і **V**, а не на **C**. Плутанина тут дає переходи, що спрацьовують навпаки на від'ємних числах.
- **Переповнення рахується за переносами у старший біт, а не «на око».** Правило `cout != cprev` (перенос у старший розряд відрізняється від переносу з нього) — точне і дешеве; спроба ловити **V** порівнянням знаків доданків і результату легко дає крайові помилки. Саме тому в коді збережено `cprev`.
- **`1u << ALU_BITS` на повну ширину типу — невизначена поведінка.** Для 32-бітного слова `1u << 32` у C не визначено. Маску беруть обережно (для повного машинного слова — інша гілка чи ширший тип), інакше компілятор має право видати будь-що.
- **Ланцюговий перенос повільний.** Цей цикл відповідає [ланцюговому суматору](root:hw-digital/combinational-circuits): що ширше слово, то довше біжить перенос. У залізі це критичний шлях, який прискорюють схемами передбачення переносу; у симуляції на C затримки немає, але важливо пам'ятати, що модель **повільна за природою**, і реальний АЛП так широке слово в лоб не складає.
