# C++ симуляція апаратного множника Бута

Симуляція апаратного множника на мові високого рівня, такій як C++, дозволяє краще зрозуміти низькорівневі процеси, що відбуваються всередині арифметико-логічного пристрою (ALU). Нижче представлено повний код на C++17, який симулює роботу класичного (Radix-2) алгоритму Бута для 16-бітних знакових чисел.

### Постановка задачі

Мета — написати програму, що приймає два 16-бітних числа у доповняльному коді (множене M та множник Y) і обчислює їхній 32-бітний добуток, імітуючи апаратні регістри та такти зсуву. Програма не повинна використовувати вбудований оператор множення `*` для обчислення результату (лише для перевірки). Всі операції мають виконуватися через побітові логічні операції та додавання.

### Архітектура симулятора

Для моделювання апаратного забезпечення нам потрібні структури, що відповідають фізичним регістрам:
- `A` (Accumulator) — 16-бітний регістр для накопичення старшої частини результату.
- `Q` (Multiplier) — 16-бітний регістр, що спочатку містить множник, а згодом міститиме молодшу частину результату.
- `Q_minus_1` — 1-бітний тригер (регістр), що зберігає попередній біт множника.
- `M` (Multiplicand) — 16-бітний регістр, що містить множене.

Алгоритм виконується за 16 тактів (ітерацій). На кожному такті ми аналізуємо молодший біт `Q[0]` та `Q_minus_1`. Після можливого додавання або віднімання ми виконуємо арифметичний зсув вправо всієї 33-бітної структури [A, Q, Q_minus_1].

### Порядковий аналіз коду

1. **Ініціалізація змінних:** Ми використовуємо беззнакові типи `uint16_t` для моделювання регістрів. Це важливо, оскільки в C++ поведінка зсуву вправо для знакових від'ємних чисел (хоч зазвичай і виконує розширення знака) залежить від реалізації (implementation-defined у старих стандартах), тому краще робити арифметичний зсув вручну та контрольовано на беззнакових типах, де зсув гарантовано логічний (заповнює нулями).
2. **Головний цикл `step < 16`:** Алгоритм для N-бітних чисел завжди вимагає рівно N ітерацій.
3. **Аналіз пар:** Виконується проста перевірка умов `if (Q0 == 1 && Q_minus_1 == 0)` для визначення дії. Зауважте, що віднімання `A = A - M` в беззнаковій арифметиці C++ автоматично працює за правилами доповняльного коду, симулюючи переповнення.
4. **Арифметичний зсув:** Це найскладніша частина для симуляції. В апаратурі це просто дроти. У софті ми маємо явно зберегти знаковий біт `A` (`sign_A`), зсунути `A` вправо і повернути знак на місце (це і є розширення знака). Потім ми беремо молодший біт `A`, який витісняється, і ставимо його на позицію старшого біта `Q` (після зсуву `Q` вправо). Молодший біт `Q` стає новим `Q_minus_1`.

### Складність та продуктивність

З програмної точки зору цей алгоритм працює за час O(N), де N — розрядність числа (тут N=16). Апаратна складність класичного алгоритму Бута також лінійно залежить від кількості біт, вимагаючи 16 тактів тактового генератора. 
Саме тому на практиці використовують Radix-4 Booth (або вищі radix), який обробляє більше бітів за крок і скорочує кількість ітерацій до N/2, що дозволяє суттєво пришвидшити обчислення у сучасних центральних процесорах. Але як софтверна модель для вивчення архітектури комп'ютерів, базова симуляція Бута залишається неперевершеним інструментом.
