Коли два двійкові розряди складаються між собою, результат не завжди вміщується в один біт: `0 + 0 = 0`, `0 + 1 = 1`, `1 + 0 = 1`, але `1 + 1 = 10₂`. При складанні двох одиниць значення молодшого розряду стає нулем, а в наступну вагову позицію виникає одиниця переповнення. Двійкове додавання одного розряду через це розпадається на два незалежні логічні сигнали: біт суми, який обчислює парність кількості одиниць, та біт переносу, що фіксує вихід результату за межі поточного розряду.

Якщо розглянути таблицю істинності для двох однорозрядних входів `A` та `B`, вихід суми `S` набуває одиниці лише тоді, коли один із входів дорівнює одиниці, а інший — нулю. Це операція виключного АБО (`S = A ⊕ B`). Вихідний перенос `Cout` стає одиницею виключно тоді, коли обидва вхідні сигнали одночасно активні, що відповідає кон'юнкції (`Cout = A · B`). Пристрій, побудований на одному вентилі XOR та одному вентилі AND, виконує додавання двох бітів і зветься **напівсуматором** (англ. *half adder*, від давньоангл. *healf* — половина і лат. *addere* — додавати, приєднувати). Префікс «напів-» вказує на його фундаментальне конструктивне обмеження: схема має лише два інформаційні входи й принципово не здатна приймати сигнал переносу, що міг прийти від сусіднього молодшого розряду.

![Схема напівсуматора та повного суматора](/root/hw/hw-digital/sumator-i-perenos/img/half-and-full-adder.svg)
*Порівняння схемотехніки напівсуматора та повного суматора. Напівсуматор формує суму S = A ⊕ B і перенос Cout = A · B для двох бітів. Повний суматор об'єднує два напівсуматори й логічний елемент OR, забезпечуючи повноцінне тривходове додавання з урахуванням вхідного переносу Cin.*

## Повний суматор і тривходова комбінаційна логіка

Щоб обробляти багаторозрядні двійкові числа, кожен розряд, крім наймолодшого, мусить складати не два, а три двійкові сигнали: власний біт першого доданка `Aᵢ`, власний біт другого доданка `Bᵢ` та вхідний перенос `Cᵢ` (або `Cin`), породжений розрядом `i - 1`.

Сума трьох бітів визначається двома параметрами: молодшим бітом арифметичної суми `Aᵢ + Bᵢ + Cᵢ` (значення `Sᵢ`) та старшим бітом суми (новий вихідний перенос `Cᵢ₊₁` або `Cout`). Значення `Sᵢ` дорівнює одиниці, коли серед трьох входів активна непарна кількість одиниць — рівно одна або всі три:

```
Sᵢ = Aᵢ ⊕ Bᵢ ⊕ Cᵢ
```

Вихідний перенос `Cᵢ₊₁` формується за мажоритарним принципом: він дорівнює одиниці тоді й тільки тоді, коли серед трьох входів `(Aᵢ, Bᵢ, Cᵢ)` щонайменше два мають одиничний стан:

```
Cᵢ₊₁ = (Aᵢ · Bᵢ) + (Aᵢ · Cᵢ) + (Bᵢ · Cᵢ)
```

Цю функцію можна факторизувати, використавши вже обчислене значення `Aᵢ ⊕ Bᵢ`:

```
Cᵢ₊₁ = (Aᵢ · Bᵢ) + (Cᵢ · (Aᵢ ⊕ Bᵢ))
```

Схема, яка реалізує ці дві функції для трьох входів, зветься **повним суматором** (англ. *full adder*). Її зручно будувати на основі двох напівсуматорів та одного двовходового елемента логічного АБО:
1. Перший напівсуматор бере входи `Aᵢ` та `Bᵢ`, обчислюючи проміжну суму `S₁ = Aᵢ ⊕ Bᵢ` та проміжний перенос `C₁ = Aᵢ · Bᵢ`.
2. Другий напівсуматор приймає проміжну суму `S₁` та вхідний перенос `Cᵢ`, генеруючи остаточний біт суми `Sᵢ = S₁ ⊕ Cᵢ` та другий проміжний перенос `C₂ = S₁ · Cᵢ = (Aᵢ ⊕ Bᵢ) · Cᵢ`.
3. Елемент OR збирає обидва переноси: `Cᵢ₊₁ = C₁ + C₂`. Оскільки сигнали `C₁` та `C₂` ніколи не можуть одночасно набувати одиниці (якщо `Aᵢ = Bᵢ = 1`, то `S₁ = 0`, і відповідно `C₂ = 0`), замість елемента OR можна без зміни логіки використати ще один XOR, проте звичайний OR є електрично простішим і швидшим.

### Транзисторна реалізація та інверсний перенос

У кремнієвій КМОН-схемотехніці (CMOS) повний суматор рідко збирають із дискретних вентилів XOR та AND через надмірну кількість транзисторів і великі паразитні затримки. Класична декомпозиція на логічні вентилі вимагає від 16 до 20 транзисторів, створюючи три послідовні яруси перемикання між входом `Cᵢ` та виходом `Cᵢ₊₁`.

Замість цього на рівні транзисторної топології застосовують схему **дзеркального суматора** (англ. *mirror adder*), що складається з 28 транзисторів. У ній мережа транзисторів PMOS у підтяжці до напруги живлення дзеркально повторює мережу NMOS у підтяжці до землі. Дзеркальний суматор оптимізує шлях генерації переносу: сигнал від входу `Cᵢ` до виходу проходить лише через один комбінований каскад із двох транзисторів.

Фундаментальною властивістю КМОН-логіки є природна інверсія сигналу: вентилі NAND, NOR та AND-OR-Invert (AOI) перемикаються за один транзисторний ярус, тоді як прямі елементи AND та OR вимагають додаткового вихідного інвертора, що збільшує час затримки та енергоспоживання. Через це в оптимізованих суматорах вихід переносу генерують в інверсній формі:

```
C̄ᵢ₊₁ = (Āᵢ · B̄ᵢ) + (C̄ᵢ · (Āᵢ + B̄ᵢ))
```

Чергуючи в багаторозрядному суматорі парні розряди з прямою логікою та непарні розряди з інверсною логікою (де входи й виходи інтерпретуються як активні нулі), інженери повністю вилучають проміжні інвертори з ланцюга переносу. Це зменшує час розповсюдження сигналу на 30–40% без зміни загальної площі кристала.

## Ланцюговий суматор і проблема розповсюдження переносу

Найпростіший спосіб побудови `N`-розрядного суматора полягає у послідовному з'єднанні `N` повних суматорів, де вихід переносу `Cᵢ₊₁` кожного попереднього блоку підключається до входу переносу `Cᵢ₊₁` наступного блоку.

![4-розрядний ланцюговий суматор і критичний шлях переносу](/root/hw/hw-digital/sumator-i-perenos/img/ripple-carry-4bit.svg)
*4-розрядний ланцюговий суматор (RCA) та його критичний шлях. Сигнал переносу C₀ послідовно проходить крізь усі чотири повні суматори, через що загальна затримка обчислення зростає прямо пропорційно розрядності слова O(N).*

Такий пристрій зветься **ланцюговим суматором** або **каскадним суматором** (англ. *ripple-carry adder*, скорочено RCA, від давньоангл. *ripplen* — утворювати брижі, дрібні хвилі на воді). Назва точно відображає фізичний процес у схемі: сигнал переносу, подібно до хвилі на воді чи ланцюжка кісточок доміно, мусить послідовно «просочитися» крізь усі комірки від нульового розряду до `N - 1`.

Розглянемо найгірший випадок додавання (англ. *worst-case critical path*). Нехай до 32-розрядного суматора надходять числа:
- `A = 0x7FFF_FFFF` (`0b0111_1111_..._1111`)
- `B = 0x0000_0001` (`0b0000_0000_..._0001`)
- `C₀ = 0`

У наймолодшому розряді `i = 0` додаються `A₀ = 1` та `B₀ = 1`. Цей розряд породжує перенос `C₁ = 1`. У всіх наступних розрядах від `i = 1` до `i = 30` значення входів дорівнюють `Aᵢ = 1` та `Bᵢ = 0`. Кожен такий розряд не здатний визначити свій вихідний перенос `Cᵢ₊₁`, доки на його вхід не надійде стабільний сигнал `Cᵢ` від молодшого сусіда. Одиниця переносу змушена пройти через усі 31 проміжні логічні каскади, доки не дійде до старшого розряду `i = 31`, де `A₃₁ = 0` і `B₃₁ = 0`, що нарешті зупинить хвилю поширення і сформує правильне значення суми `S₃₁ = 1`.

Загальний час формування результату ланцюгового суматора описується рівнянням критичного шляху:

```
t_RCA = t_setup + (N - 1) · t_carry + t_sum
```

Тут:
- `t_setup` — час формування проміжного сигналу `A₀ ⊕ B₀` та початкового переносу `C₁` у нульовому розряді (зазвичай 1 затримка елемента XOR або AND-OR-Invert);
- `t_carry` — час затримки поширення переносу крізь одну комірку повного суматора від входу `Cᵢ` до виходу `Cᵢ₊₁` (зазвичай 2 вентильні затримки інвертованої логіки або 30–50 пікосекунд у сучасному техпроцесі);
- `t_sum` — час генерації фінального біта суми `S_{N-1}` після надходження фінального переносу (1 затримка XOR).

Асимптотична часова складність ланцюгового суматора є строго лінійною: `O(N)`. Якщо для 8-бітного слова затримка становить близько 8 каскадів переносу, то для 64-бітного слова вона сягає 64 каскадів.

> 🔧 **Навіщо це.** Якщо один каскад переносу має затримку 40 пс, то 64-розрядне ланцюгове додавання потребує понад `64 · 40 = 2560 пс = 2.56 нс`. У процесорі з тактовою частотою 3 ГГц тривалість одного такту становить лише `1 / (3 · 10⁹) ≈ 333 пс`. Ланцюговий суматор виконував би базову операцію додавання протягом 8 повних тактів процесора, зупиняючи конвеєр команд. Щоб арифметика виконувалася за один такт, суматор зобов'язаний розірвати послідовний ланцюг залежностей.

## Функції генерації та проходження переносу

Щоб позбутися лінійного очікування, необхідно відокремити властивості самих вхідних бітів від сигналу, який передається між розрядами. Поведінку будь-якого розряду `i` щодо переносу можна повністю охарактеризувати ще до того, як перенос реально надійде на його вхід.

Для будь-якої комбінації бітів `(Aᵢ, Bᵢ)` існують рівно три взаємовиключні сценарії поведінки:

1. **Генерація** (англ. *generate*, від лат. *generare* — породжувати, створювати): обидва вхідні біти дорівнюють одиниці (`Aᵢ = 1`, `Bᵢ = 1`). У цьому випадку `1 + 1 = 10₂`, тобто розряд створює вихідний перенос `Cᵢ₊₁ = 1` безумовно, незалежно від значення вхідного переносу `Cᵢ`. Сигнал генерації розряду `i` описується кон'юнкцією:
   ```
   Gᵢ = Aᵢ · Bᵢ
   ```

2. **Проходження** або **поширення** (англ. *propagate*, від лат. *propagare* — розповсюджувати, передавати нащадкам): рівно один із вхідних бітів дорівнює одиниці (`Aᵢ = 1, Bᵢ = 0` або `Aᵢ = 0, Bᵢ = 1`). У цьому випадку власної суми недостатньо для створення переносу, але якщо від попереднього розряду прийде `Cᵢ = 1`, то `1 + 0 + 1 = 10₂`, і перенос вийде в наступний розряд. Розряд працює як провідник або транзитний канал. Сигнал проходження описується операцією XOR або OR:
   ```
   Pᵢ = Aᵢ ⊕ Bᵢ        (або Pᵢ = Aᵢ + Bᵢ)
   ```
   У схемах прискореного переносу перевагу надають версії на основі `XOR`, оскільки сигнал `Pᵢ = Aᵢ ⊕ Bᵢ` одночасно використовується на фінальному етапі для формування біта суми: `Sᵢ = Pᵢ ⊕ Cᵢ`.

3. **Гасіння** або **поглинання** (англ. *kill* або *absorb*, від лат. *absorbere* — поглинати): обидва вхідні біти дорівнюють нулю (`Aᵢ = 0`, `Bᵢ = 0`). За будь-якого вхідного переносу `0 + 0 + Cᵢ ≤ 1`, тому перенос ніколи не виникає і не проходить далі:
   ```
   Kᵢ = Āᵢ · B̄ᵢ = (Aᵢ + Bᵢ)̄
   ```

![Логіка генерації та проходження переносу](/root/hw/hw-digital/sumator-i-perenos/img/generate-propagate-cell.svg)
*Логічна декомпозиція бітової пари на сигнали генерації Gᵢ та проходження Pᵢ. Сигнали обчислюються водночас для всіх розрядів за один ярус логіки, що дозволяє визначити долю переносу ще до його фізичного надходження.*

Використовуючи сигнали генерації `Gᵢ` та проходження `Pᵢ`, фундаментальне рівняння вихідного переносу записується у вигляді компактної рекурентної формули:

```
Cᵢ₊₁ = Gᵢ + Pᵢ · Cᵢ
```

Цей вираз стверджує: перенос у розряд `i + 1` виникає тоді, коли поточний розряд сам згенерував перенос (`Gᵢ = 1`), АБО коли поточний розряд відкритий для проходження (`Pᵢ = 1`) І перенос надійшов із попереднього розряду (`Cᵢ = 1`).

Головна перевага декомпозиції полягає в тому, що всі значення `Gᵢ` та `Pᵢ` для всіх розрядів слова `i ∈ [0, N - 1]` обчислюються абсолютно паралельно за один-єдиний ярус логічних вентилів, оскільки вони залежать лише від зовнішніх входів `A` та `B`.

## Паралельне розкриття рекурентності: суматор CLA

Маючи рекурентне співвідношення `Cᵢ₊₁ = Gᵢ + Pᵢ · Cᵢ`, його можна розгорнути алгебраїчно, підставляючи вирази для молодших переносів один в один аж до початкового вхідного переносу `C₀`.

Розгорнемо рівняння для перших чотирьох розрядів:

Для розряду 0:
```
C₁ = G₀ + P₀·C₀
```

Для розряду 1:
```
C₂ = G₁ + P₁·C₁
   = G₁ + P₁·(G₀ + P₀·C₀)                                    [підстановка C₁]
   = G₁ + P₁·G₀ + P₁·P₀·C₀                                   [дистрибутивність кон'юнкції]
```

Для розряду 2:
```
C₃ = G₂ + P₂·C₂
   = G₂ + P₂·(G₁ + P₁·G₀ + P₁·P₀·C₀)                         [підстановка C₂]
   = G₂ + P₂·G₁ + P₂·P₁·G₀ + P₂·P₁·P₀·C₀                     [дистрибутивність кон'юнкції]
```

Для розряду 3:
```
C₄ = G₃ + P₃·C₃
   = G₃ + P₃·(G₂ + P₂·G₁ + P₂·P₁·G₀ + P₂·P₁·P₀·C₀)          [підстановка C₃]
   = G₃ + P₃·G₂ + P₃·P₂·G₁ + P₃·P₂·P₁·G₀ + P₃·P₂·P₁·P₀·C₀   [дистрибутивність кон'юнкції]
```

Структура отриманих виразів має чіткий фізичний зміст. Наприклад, вихідний перенос 4-бітної групи `C₄` з'являється у п'яти взаємно незалежних випадках:
- Розряд 3 сам згенерував перенос (`G₃`);
- Розряд 2 згенерував перенос, а розряд 3 пропустив його крізь себе (`P₃ · G₂`);
- Розряд 1 згенерував перенос, а розряди 2 і 3 пропустили його (`P₃ · P₂ · G₁`);
- Розряд 0 згенерував перенос, а розряди 1, 2 і 3 пропустили його (`P₃ · P₂ · P₁ · G₀`);
- Зовнішній перенос `C₀` пройшов наскрізь через усі чотири розряди (`P₃ · P₂ · P₁ · P₀ · C₀`).

Суматор, який обчислює переноси безпосередньо за цими формулами, зветься **суматором із прискореним переносом** (англ. *carry-lookahead adder*, скорочено CLA).

У такій схемі кожен перенос `C₁, C₂, C₃, C₄` формується як двоярусна комбінаційна логіка «І-АБО» (AND-OR), де всі кон'юнкції обчислюються паралельно на першому ярусі, а результат збирається одним елементом OR на другому ярусі. Теоретична затримка формування всіх переносів становить сталу величину `O(1)` — рівно дві вентильні затримки незалежно від номера біта.

### Електричні обмеження: коефіцієнти розгалуження fan-in та fan-out

Якщо пряме розкриття рекурентності дає сталу затримку `O(1)`, чому не можна побудувати 64-розрядний суматор у вигляді єдиного гігантського блоку CLA?

Причиною є фундаментальні фізичні та електричні закони напівпровідникових схем:

1. **Коефіцієнт розгалуження за входом** (англ. *fan-in*, від англ. *fan* — віяло): позначає кількість входів, підключених до одного логічного вентиля. У формулі для `C₆₄` останній терм містив би кон'юнкцію з 65 змінних: `P₆₃ · P₆₂ · ... · P₀ · C₀`. У КМОН-технології елемент AND на 65 входів вимагає послідовного з'єднання 65 NMOS-транзисторів між виходом і землею. Сумарний опір відкритого каналу дорівнює сумі опорів: `R_total = 65 · R_on`. Водночас ємність кожного проміжного p-n переходу додається до загальної ємності вузла. Час перезаряджання RC-ланцюжка зростає пропорційно квадрату кількості послідовних транзисторів: `t_delay ∝ N²`. У реальному кремнії вентилі з fan-in більше 4 (рідше 5) практично не застосовуються через катастрофічну деградацію фронтів сигналів.

2. **Коефіцієнт розгалуження за виходом** (англ. *fan-out*): позначає кількість входів інших вентилів, якими навантажено вихід поточного елемента. Сигнал `P₀` входить у вирази для `C₁, C₂, C₃, ..., C₆₄`. Це означає, що один вихід мусить одночасно перезаряджати вхідні ємності 64 різних логічних вентилів, що спричиняє спотворення форми імпульсу та вимагає встановлення потужних буферних підсилювачів, які вносять додаткову затримку.

Через ці обмеження класичний суматор CLA будують як **ієрархічний блочний суматор** (англ. *block carry-lookahead adder*). 64-розрядне слово розбивають на 4-розрядні блоки. Кожен 4-розрядний блок формує внутрішні переноси за наведеними формулами, а також обчислює два групові сигнали:
- **Групове проходження** (Block Propagate):
  ```
  P_group = P₃ · P₂ · P₁ · P₀
  ```
- **Групова генерація** (Block Generate):
  ```
  G_group = G₃ + P₃·G₂ + P₃·P₂·G₁ + P₃·P₂·P₁·G₀
  ```

Групові сигнали надходять до блоку прискореного переносу другого рівня (Lookahead Carry Unit, LCU), який обчислює переноси між 4-бітними блоками. Для 64 бітів ієрархія CLA містить 3 рівні блоків, що дає затримку критичного шляху порядку `O(log N)` з обмеженим коефіцієнтом fan-in ≤ 4.

## Проміжні архітектури: Carry-Skip та Carry-Select

Між простим ланцюговим суматором `O(N)` і повним блочним CLA `O(log N)` існує клас проміжних схем, які суттєво зменшують затримку при значно менших апаратних витратах на вентилі.

### Суматор із пропуском переносу (Carry-Skip / Bypass Adder)

Ідея **суматора із пропуском переносу** (англ. *carry-skip adder* або *carry-bypass adder*) спирається на просте спостереження: якщо в групі з `k` розрядів усі біти проходження дорівнюють одиниці (`P_{i} = 1` для всіх `i` у блоці), то перенос, що надійшов на вхід блоку, гарантовано пройде на його вихід без змін.

Схема розбиває `N`-розрядне слово на блоки розміром `k` (наприклад, по 4 біти):
1. Усередині кожного блоку перенос розповсюджується звичайним ланцюговим способом (RCA).
2. Паралельно вентиль AND обчислює сигнал групового проходження `P_block = P₀ · P₁ · ... · P_{k-1}`.
3. Вихідний перенос блоку формується мультиплексором 2-в-1: якщо `P_block = 1`, мультиплексор пропускає вхідний перенос блоку напряму на вихід в обхід усього 4-бітного ланцюжка повних суматорів, витрачаючи лише одну затримку мультиплексора.

Критичний шлях у такій схемі складається з генерації переносу в першому блоці, пропуску крізь проміжні блоки через мультиплексори та споживання переносу в останньому блоці:

```
t_skip ≈ t_block_ripple + (N / k - 2) · t_mux + t_block_ripple
```

Мінімізація цієї функції за розміром блоку дає оптимальний розмір `k ∝ √N` і загальну асимптотичну часову складність `O(√N)`. Подальша оптимізація полягає у використанні **блоків змінної довжини** (наприклад, схеми з розмірами блоків 2–3–4–5–5–4–3–2 для 32 бітів), що вирівнює час прибуття сигналів до мультиплексорів і ще більше зменшує затримку.

### Суматор із вибором переносу (Carry-Select Adder, CSA)

**Суматор із вибором переносу** (англ. *carry-select adder*) застосовує стратегію спекулятивного обчислення. Оскільки вхідний перенос до будь-якого блоку може набувати лише двох значень — `0` або `1`, блок може заздалегідь обчислити два альтернативні результати суми одночасно.

Кожен блок містить два паралельні суматори однакової розрядності:
- Перший суматор обчислює суму в припущенні, що вхідний перенос `Cin = 0`;
- Другий суматор паралельно обчислює суму в припущенні, що вхідний перенос `Cin = 1`.

Коли справжній сигнал переносу від попереднього блоку нарешті добігає, він керує мультиплексорами, які миттєво комутують правильний, уже готовий вектор суми та вихідний перенос на вихід блоку.

У схемі з фіксованим розміром блоку затримка становить `O(√N)`. У схемі зі зростаючими блоками (Square-Root Carry-Select Adder), де розміри блоків збільшуються на 1 у кожній наступній позиції (наприклад, 2, 3, 4, 5, 6 бітів), час обчислення всередині довшого блоку точно збігається з часом приходу сигналу керування мультиплексором від попередніх каскадів. Це робить суматор вибору переносу одним із найпопулярніших рішень для блоків помірної розрядності (16–32 біти), де важлива простота топології без складної матриці префіксів.

## Паралельні префіксні мережі: алгоритм Коггі-Стоуна

Подальшим розвитком ідеї прискореного переносу став перехід від спеціалізованих комбінаційних формул до універсальної алгебраїчної структури — **паралельного префіксного обчислення**.

Визначимо оператор об'єднання двох суміжних бітових груп `(G_L, P_L)` (старша, ліва група) та `(G_R, P_R)` (молодша, права група). Введемо бінарну операцію префіксного об'єднання `○` (англ. *prefix associative operator*):

```
(G_L, P_L) ○ (G_R, P_R) = (G_L + P_L · G_R,  P_L · P_R)
```

Ця операція має вирішальну математичну властивість: вона є **строго асоціативною**. Доведемо асоціативність прямою підстановкою для трьох блоків `A`, `B` та `C`:

```
[(G_A, P_A) ○ (G_B, P_B)] ○ (G_C, P_C)
= (G_A + P_A·G_B, P_A·P_B) ○ (G_C, P_C)                      [застосування оператора до лівої пари]
= ((G_A + P_A·G_B) + (P_A·P_B)·G_C, (P_A·P_B)·P_C)          [застосування оператора до результату і C]
= (G_A + P_A·G_B + P_A·P_B·G_C, P_A·P_B·P_C)               [асоціативність логічних AND та OR]
= (G_A + P_A·(G_B + P_B·G_C), P_A·(P_B·P_C))               [винесення P_A за дужки]
= (G_A, P_A) ○ (G_B + P_B·G_C, P_B·P_C)                     [згортання за означенням оператора ○]
= (G_A, P_A) ○ [(G_B, P_B) ○ (G_C, P_C)]                    [отримано праву асоціативну форму]
```

Оскільки оператор `○` асоціативний, задача обчислення всіх проміжних переносів зводиться до класичної задачі паралельного префіксного сканування (англ. *prefix sum problem*). Замість послідовного ланцюжка операцій обчислення можна організувати у вигляді збалансованого дерева.

Схеми, що реалізують цей принцип, звуться **паралельними префіксними суматорами** (англ. *parallel prefix adders*, від лат. *praefixus* — прикріплений спереду).

![8-розрядне паралельне префіксне дерево Коггі-Стоуна](/root/hw/hw-digital/sumator-i-perenos/img/kogge-stone-8bit.svg)
*Топологія 8-розрядного паралельного префіксного дерева Коггі-Стоуна. Завдяки логарифмічній глибині в 3 яруси об'єднання префіксні сигнали для всіх 8 бітів формуються водночас із постійним коефіцієнтом розгалуження fan-out = 2.*

Найшвидшою та найбільш регулярною топологією префіксного суматора є **суматор Коггі-Стоуна** (англ. *Kogge-Stone adder*, розроблений Пітером Коггі та Гарольдом Стоуном у 1973 році).

Архітектура Коггі-Стоуна складається з трьох послідовних фаз:
1. **Попередня обробка** (Pre-processing): для кожного вхідного біта `i` обчислюються базові сигнали `gᵢ = aᵢ · bᵢ` та `pᵢ = aᵢ ⊕ bᵢ`.
2. **Префіксне дерево** (Prefix Network): на кожному ярусі `k` (де `k = 0, 1, ..., ⌈log₂ N⌉ - 1`) кожен вузол `i` комбінує свій поточний стан `(G, P)` зі станом вузла `i - 2ᵏ` за допомогою оператора `○`.
3. **Фінальна генерація суми** (Post-processing): значення переносу для біта `i` безпосередньо дорівнює накопиченому сигналу `G_{i-1:0}` (з урахуванням `C₀`), а вихідний біт суми обчислюється як `Sᵢ = pᵢ ⊕ Cᵢ`.

Характеристики архітектури Коггі-Стоуна:
- **Логічна глибина (затримка)**: рівно `⌈log₂ N⌉` ярусів префіксних елементів. Для 32-бітного слова це лише 5 ярусів; для 64-бітного слова — 6 ярусів.
- **Коефіцієнт fan-out**: на кожному рівні вихід кожного елемента навантажений рівно на 2 наступні вузли, що гарантує високу крутизну фронтів і мінімальні електричні затримки в кремнії.
- **Ціна за швидкість**: велика кількість внутрішніх елементів (`O(N log₂ N)`) та висока щільність міжз'єднань (wiring tracks), що потребує багатьох металевих шарів топології мікросхеми.

Існують інші популярні топології префіксних мереж, які балансують між швидкістю, площею кристала та складністю трасування:
- **Суматор Брента-Кунга** (Brent-Kung): мінімізує кількість вентилів і ліній трасування за рахунок збільшення логічної глибини до `2 · log₂ N - 1`. Має малу площу, але працює приблизно вдвічі повільніше за Коггі-Стоуна на 64-бітних числах.
- **Суматор Скланського** (Sklansky): має мінімальну глибину `log₂ N`, але на окремих вузлах коефіцієнт fan-out подвоюється на кожному кроці, досягаючи `N / 2`, що призводить до деградації швидкості на широких словах.
- **Суматор Хана-Карлсона** (Han-Carlson): гібридна схема, яка поєднує структуру Брента-Кунга на зовнішніх рівнях і Коггі-Стоуна на внутрішніх, досягаючи глибини `log₂ N + 1` при майже вдвічі меншій кількості проводів.

## Збереження переносу: Carry-Save Adder (CSA)

Окреме місце в цифровій арифметиці посідає проблема додавання не двох, а багатьох чисел одночасно (наприклад, при апаратному множенні, де необхідно скласти 64 часткові добутки, або в цифрових фільтрах сигналів).

Якщо складати `M` чисел послідовно за допомогою класичних дводіапазонних суматорів, перенос розповсюджуватиметься на кожному кроці додавання, що створить колосальну затримку `O(M · log N)`.

Рішенням є **суматор зі збереженням переносу** (англ. *carry-save adder*, скорочено CSA). Схема CSA не поширює перенос по горизонталі між сусідніми розрядами. Замість цього масив із `N` незалежних повних суматорів приймає три `N`-розрядні операнди `A, B, C` і формує два вихідні `N`-розрядні вектори:
- Вектор сум `S`, де `Sᵢ = Aᵢ ⊕ Bᵢ ⊕ Cᵢ`;
- Вектор переносів `C`, де `Cᵢ = (Aᵢ · Bᵢ) + (Cᵢ · (Aᵢ ⊕ Bᵢ))`, зсунутий ліворуч на одну позицію.

Затримка стиснення трьох операндів у два в суматорі Carry-Save становить рівно 1 затримку повного суматора `O(1)` незалежно від розрядності слова `N`. Лише на останньому етапі, коли залишаються фінальні два вектори, застосовується швидкий префіксний суматор Коггі-Стоуна для формування кінцевого двійкового результату. На цьому принципі будуються всі сучасні помножувачі на деревах Воллеса (Wallace Tree) та Дадди (Dadda Tree).

## Порівняльний аналіз топологій і кремнієва специфіка

Вибір архітектури суматора в сучасних цифрових системах є результатом компромісу між часом затримки критичного шляху, площею на кристалі, енергоспоживанням та специфікою цільової платформи (ASIC чи FPGA).

| Архітектура суматора | Затримка критичного шляху | Складність за площею (вентилі) | Максимальний Fan-out | Щільність трасування | Типове застосування |
|---|---|---|---|---|---|
| **Ripple Carry (RCA)** | `O(N)` | `O(N)` | 1 (мінімальний) | Мінімальна (лише сусіди) | Лічильники, 4–8 біт, мікроконтролери з ультранизьким споживанням |

| **Carry-Select (CSA)** | `O(√N)` | `O(N)` (подвійна логіка) | `O(√N)` | Середня | 16–32 біти, конвеєрні блоки фіксованої частоти |

### Парадокс реалізації в ПЛІС (FPGA)

В інженерній практиці проектування цифрових схем на базі ПЛІС (FPGA) виникає характерний ефект: 64-розрядний ланцюговий суматор, описаний простим оператором `+` у Verilog/VHDL, часто працює швидше і займає в рази менше ресурсів, ніж складний префіксний суматор Коггі-Стоуна.

Причина полягає в апаратній архітектурі кристала FPGA:
- Усі сучасні FPGA (наприклад, сімейства AMD Xilinx 7-Series, UltraScale+, Intel Cyclone, Stratix) містять у кожній логічній комірці (CLB/ALM) спеціалізовані апаратні ланцюжки переносу — апаратні кремнієві примітиви (наприклад, блоки `CARRY4` або `CARRY8`).
- Ланцюжок переносу в FPGA побудований на жорстко розведених кремнієвих мультиплексорах і транзисторах, фізично розташованих впритул один до одного. Затримка проходження переносу через один біт у такому ланцюжку становить менше 10–15 пікосекунд, а сигнал не виходить у загальну матрицю програмованої комутації (interconnect).
- Якщо реалізувати суматор Коггі-Стоуна на FPGA, його численні логічні зв'язки будуть прокладені через загальні програмовані трасувальні ресурси матриці комутації. Затримка проходження сигналу крізь один програмований ключ комутації (interconnect switch) становить 150–300 пс. Через це виграш від логарифмічної кількості ярусів повністю нівелюється паразитними затримками програмованої комутації.

У замовних мікросхемах (ASIC), навпаки, проектувальник має повний контроль над геометрією провідників і розмірами транзисторів, тому в процесорних ядрах із тактовою частотою від 2 до 5 ГГц 64-розрядні блоки АЛП будують виключно на базі паралельних префіксних мереж Коггі-Стоуна або Хана-Карлсона.

## Програмна бітова емуляція та замір логічних затримок

Нижче наведено закінчену програму мовами C та C++, яка виконує повентильну бітову емуляцію 64-розрядного ланцюгового суматора (RCA) та 64-розрядного суматора Коггі-Стоуна (Kogge-Stone). Програма моделює кількість логічних ярусів (глибину перемикання вентилів на критичному шляху), перевіряє коректність результатів на наборі тестів і демонструє різницю між лінійною складністю `O(N)` та логарифмічною `O(log₂ N)`.

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <stdbool.h>

// Структура для повернення результату та метрики логічної затримки
typedef struct {
    uint64_t sum;
    uint8_t  carry_out;
    uint32_t gate_levels; // Кількість ярусів вентилів на критичному шляху
} AdderResult;

// Емуляція 64-розрядного ланцюгового суматора (Ripple Carry Adder)
AdderResult ripple_carry_adder_64(uint64_t a, uint64_t b, uint8_t cin) {
    AdderResult res;
    res.sum = 0;
    uint8_t c = cin & 1;
    uint32_t carry_chain_delay = 0;

    for (int i = 0; i < 64; i++) {
        uint8_t ai = (uint8_t)((a >> i) & 1);
        uint8_t bi = (uint8_t)((b >> i) & 1);

        // Повний суматор розряду:
        // S_i = ai ^ bi ^ c
        // Cout = (ai & bi) | (c & (ai ^ bi))
        uint8_t prop = (uint8_t)(ai ^ bi);
        uint8_t gen  = (uint8_t)(ai & bi);
        uint8_t si   = (uint8_t)(prop ^ c);
        c = (uint8_t)(gen | (c & prop));

        res.sum |= ((uint64_t)si << i);
        carry_chain_delay += 2; // Кожен каскад переносу додає 2 вентильні затримки (AND-OR / AOI)
    }

    res.carry_out = c;
    // Повний критичний шлях: 1 ярус підготовки (XOR) + 64 * 2 (переноси) + 1 ярус фінальної суми
    res.gate_levels = 1 + carry_chain_delay + 1;
    return res;
}

// Емуляція 64-розрядного суматора Коггі-Стоуна (Kogge-Stone Prefix Adder)
AdderResult kogge_stone_adder_64(uint64_t a, uint64_t b, uint8_t cin) {
    AdderResult res;
    res.sum = 0;

    uint8_t g[64];
    uint8_t p[64];

    // Рівень 0: Попередня генерація бітових сигналів g_i та p_i (1 вентильний ярус)
    for (int i = 0; i < 64; i++) {
        uint8_t ai = (uint8_t)((a >> i) & 1);
        uint8_t bi = (uint8_t)((b >> i) & 1);
        g[i] = (uint8_t)(ai & bi);
        p[i] = (uint8_t)(ai ^ bi);
    }

    // Врахування вхідного переносу cin у нульовий розряд
    g[0] = (uint8_t)(g[0] | (p[0] & (cin & 1)));

    uint8_t cur_g[64];
    uint8_t cur_p[64];
    for (int i = 0; i < 64; i++) {
        cur_g[i] = g[i];
        cur_p[i] = p[i];
    }

    uint32_t prefix_stages = 0;
    // Префіксне дерево: кроки зміщення 1, 2, 4, 8, 16, 32 (log2(64) = 6 ярусів)
    for (int stride = 1; stride < 64; stride <<= 1) {
        uint8_t next_g[64];
        uint8_t next_p[64];

        for (int i = 0; i < 64; i++) {
            if (i >= stride) {
                // Оператор "крапка" (G_L, P_L) o (G_R, P_R) = (G_L | (P_L & G_R), P_L & P_R)
                next_g[i] = (uint8_t)(cur_g[i] | (cur_p[i] & cur_g[i - stride]));
                next_p[i] = (uint8_t)(cur_p[i] & cur_p[i - stride]);
            } else {
                next_g[i] = cur_g[i];
                next_p[i] = cur_p[i];
            }
        }

        for (int i = 0; i < 64; i++) {
            cur_g[i] = next_g[i];
            cur_p[i] = next_p[i];
        }
        prefix_stages++;
    }

    // Фінальне формування бітів суми S_i = p_i ^ C_{i-1}
    for (int i = 0; i < 64; i++) {
        uint8_t c_in_bit = (i == 0) ? (cin & 1) : cur_g[i - 1];
        uint8_t si = (uint8_t)(p[i] ^ c_in_bit);
        res.sum |= ((uint64_t)si << i);
    }

    res.carry_out = cur_g[63];
    // Затримка: 1 (g/p) + 6 * 2 (кожен префіксний вузол AND-OR = 2 затримки) + 1 (фінальний XOR суми)
    res.gate_levels = 1 + (prefix_stages * 2) + 1;
    return res;
}

int main(void) {
    uint64_t a = 0x7FFFFFFFFFFFFFFF;
    uint64_t b = 0x0000000000000001;
    uint8_t cin = 0;

    AdderResult rca = ripple_carry_adder_64(a, b, cin);
    AdderResult ksa = kogge_stone_adder_64(a, b, cin);

    printf("64-Bit Addition Comparison (A = 0x%016llX, B = 0x%016llX)\n",
           (unsigned long long)a, (unsigned long long)b);
    printf("Hardware Result:        0x%016llX\n", (unsigned long long)(a + b + cin));
    printf("RCA Sum:                0x%016llX (Carry: %u, Gate Delay Depth: %u levels)\n",
           (unsigned long long)rca.sum, rca.carry_out, rca.gate_levels);
    printf("Kogge-Stone Sum:        0x%016llX (Carry: %u, Gate Delay Depth: %u levels)\n",
           (unsigned long long)ksa.sum, ksa.carry_out, ksa.gate_levels);

    if (rca.sum == (a + b + cin) && ksa.sum == (a + b + cin)) {
        printf("Verification: SUCCESS. Speedup factor in gate depth: %.2fx\n",
               (double)rca.gate_levels / (double)ksa.gate_levels);
    }
    return 0;
}
```

```cpp
#include <iostream>
#include <iomanip>
#include <cstdint>
#include <array>
#include <span>
#include <concepts>

// Результат моделювання суматора з метриками затримки
struct AdderEvaluation {
    std::uint64_t sum{0};
    std::uint8_t  carry_out{0};
    std::uint32_t logic_depth{0};
};

// Абстрактний інтерфейс цифрового суматора
class DigitalAdder64 {
public:
    virtual ~DigitalAdder64() = default;
    [[nodiscard]] virtual AdderEvaluation add(std::uint64_t a, std::uint64_t b, std::uint8_t cin) const = 0;
};

// 64-розрядний ланцюговий суматор (Ripple Carry Adder)
class RippleCarryAdder64 final : public DigitalAdder64 {
public:
    [[nodiscard]] AdderEvaluation add(std::uint64_t a, std::uint64_t b, std::uint8_t cin) const override {
        AdderEvaluation eval;
        std::uint8_t carry = cin & 1U;

        for (std::size_t i = 0; i < 64; ++i) {
            const auto ai = static_cast<std::uint8_t>((a >> i) & 1U);
            const auto bi = static_cast<std::uint8_t>((b >> i) & 1U);

            const auto prop = static_cast<std::uint8_t>(ai ^ bi);
            const auto gen  = static_cast<std::uint8_t>(ai & bi);
            const auto sum_bit = static_cast<std::uint8_t>(prop ^ carry);

            carry = static_cast<std::uint8_t>(gen | (carry & prop));
            eval.sum |= (static_cast<std::uint64_t>(sum_bit) << i);
        }

        eval.carry_out = carry;
        // 1 рівень генерації P + 64 комірки * 2 рівні вентилів на перенос + 1 рівень XOR суми
        eval.logic_depth = 1 + (64 * 2) + 1;
        return eval;
    }
};

// 64-розрядний паралельний префіксний суматор Коггі-Стоуна (Kogge-Stone Adder)
class KoggeStoneAdder64 final : public DigitalAdder64 {
public:
    [[nodiscard]] AdderEvaluation add(std::uint64_t a, std::uint64_t b, std::uint8_t cin) const override {
        AdderEvaluation eval;
        std::array<std::uint8_t, 64> gen{};
        std::array<std::uint8_t, 64> prop{};

        // Етап 1: Попередня генерація бітових сигналів G та P
        for (std::size_t i = 0; i < 64; ++i) {
            const auto ai = static_cast<std::uint8_t>((a >> i) & 1U);
            const auto bi = static_cast<std::uint8_t>((b >> i) & 1U);
            gen[i]  = static_cast<std::uint8_t>(ai & bi);
            prop[i] = static_cast<std::uint8_t>(ai ^ bi);
        }

        gen[0] = static_cast<std::uint8_t>(gen[0] | (prop[0] & (cin & 1U)));

        auto cur_g = gen;
        auto cur_p = prop;
        std::uint32_t prefix_layers = 0;

        // Етап 2: Паралельне префіксне дерево (log2(64) = 6 ярусів)
        for (std::size_t stride = 1; stride < 64; stride <<= 1U) {
            auto next_g = cur_g;
            auto next_p = cur_p;

            for (std::size_t i = stride; i < 64; ++i) {
                // Асоціативний оператор префіксної композиції: (G_L | (P_L & G_R), P_L & P_R)
                next_g[i] = static_cast<std::uint8_t>(cur_g[i] | (cur_p[i] & cur_g[i - stride]));
                next_p[i] = static_cast<std::uint8_t>(cur_p[i] & cur_p[i - stride]);
            }

            cur_g = next_g;
            cur_p = next_p;
            ++prefix_layers;
        }

        // Етап 3: Фінальне обчислення бітів суми S_i = P_i ^ C_{i-1}
        for (std::size_t i = 0; i < 64; ++i) {
            const std::uint8_t carry_in_bit = (i == 0) ? (cin & 1U) : cur_g[i - 1];
            const auto sum_bit = static_cast<std::uint8_t>(prop[i] ^ carry_in_bit);
            eval.sum |= (static_cast<std::uint64_t>(sum_bit) << i);
        }

        eval.carry_out = cur_g[63];
        // 1 рівень генерації P/G + 6 ярусів префіксів * 2 вентилі (AND-OR) + 1 рівень XOR
        eval.logic_depth = 1 + (prefix_layers * 2) + 1;
        return eval;
    }
};

int main() {
    constexpr std::uint64_t op_a = 0x7FFFFFFFFFFFFFFFULL;
    constexpr std::uint64_t op_b = 0x0000000000000001ULL;
    constexpr std::uint8_t  cin  = 0;

    const RippleCarryAdder64 rca;
    const KoggeStoneAdder64  ksa;

    const auto res_rca = rca.add(op_a, op_b, cin);
    const auto res_ksa = ksa.add(op_a, op_b, cin);
    const auto expected = op_a + op_b + cin;

    std::cout << "64-Bit Adder Benchmark & Gate Depth Analysis\n"
              << "Operand A:        0x" << std::hex << std::setw(16) << std::setfill('0') << op_a << "\n"
              << "Operand B:        0x" << std::hex << std::setw(16) << std::setfill('0') << op_b << "\n"
              << "Expected Sum:     0x" << std::hex << std::setw(16) << std::setfill('0') << expected << "\n\n"
              << std::dec
              << "Ripple Carry:     0x" << std::hex << std::setw(16) << std::setfill('0') << res_rca.sum
              << std::dec << " | Critical Path: " << res_rca.logic_depth << " gate levels\n"
              << "Kogge-Stone:      0x" << std::hex << std::setw(16) << std::setfill('0') << res_ksa.sum
              << std::dec << " | Critical Path: " << res_ksa.logic_depth << " gate levels\n\n";

    if (res_rca.sum == expected && res_ksa.sum == expected) {
        const double speedup = static_cast<double>(res_rca.logic_depth) / static_cast<double>(res_ksa.logic_depth);
        std::cout << "Verification: SUCCESSFUL.\n"
                  << "Critical path reduction factor: " << std::fixed << std::setprecision(2) << speedup << "x\n";
    }

    return 0;
}
```

## Підсумковий синтез

Проблема обчислення переносу в цифрових суматорах відображає фундаментальну еволюцію апаратної обчислювальної техніки: від механічного моделювання послідовних операцій до паралельного розкриття просторово-часових залежностей.

1. **Напівсуматор і повний суматор** встановлюють мінімальний математичний базис: розбиття операції додавання бітів на суму за модулем 2 (`XOR`) та функцію мажоритарного переносу (`AND-OR`).
2. **Ланцюговий суматор (RCA)** має мінімальну апаратну складність `O(N)` за площею, але створює лінійне пляшкове горло затримки `O(N)`, обмежуючи тактову частоту процесора часом фізичного пробігу сигналу крізь усі комірки.
3. **Концепція генерації (G) та проходження (P)** перетворює перенос із фізичного сигналу, який потрібно пасивно очікувати, на математичну функцію, що обчислюється наперед для всіх бітів одночасно.
4. **Суматори CLA та префіксні мережі Коггі-Стоуна** трансформують лінійну часову складність `O(N)` у логарифмічну `O(log N)`, використовуючи асоціативність оператора префіксної композиції. Це дозволяє сучасним 64-розрядним процесорам виконувати цілочисельне додавання за один субнаносекундний такт конвеєра.
