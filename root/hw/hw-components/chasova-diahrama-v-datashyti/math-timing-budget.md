# 🧮 Розрахунок часового бюджету та частотних меж цифрових шин

Коли цифровий інтерфейс збоїть на граничній частоті або в промисловому температурному діапазоні, причина криється в порушенні часового балансу (англ. *timing margin budget*). Запас за часом — це різниця між тривалістю тактового циклу та сумою всіх фізичних затримок поширення сигналу й апаратних вимог приймача. Нижче наведено суворе математичне виведення рівнянь часового бюджету для синхронних шин із тактовим стробуванням (SPI, паралельна пам'ять), асинхронних ліній з відкритим стоком (I2C) та ліній передачі зі значним ємнісним навантаженням.

## 1. Бюджет синхронного тактового циклу: встановлення (Setup)

У синхронній системі передавач виставляє дані за активним фронтом такту (англ. *launch edge*), а приймач зчитує їх за наступним активним фронтом (англ. *capture edge*), віддаленим на період `T_clk = 1 / f_clk`.

Повна затримка шляху даних складається з:
1. `t_co_max` — максимальної внутрішньої затримки передавача від тактового фронту до появи стабільного логічного рівня на вихідному виводі;
2. `t_flight` — часу поширення електромагнітної хвилі провідником друкованої плати від виводу передавача до виводу приймача;
3. `t_setup` — мінімального часу, протягом якого дані на вході приймача мають залишатися незмінними до приходу фронту такту;
4. `t_skew` — часового перекосу тактових ліній (різниці між моментами приходу такту на передавач і приймач);
5. `t_jitter` — фазового тремтіння (джиттеру) тактового генератора.

```
M_setup
= T_clk - (t_co_max + t_flight + t_setup + t_skew + t_jitter)   [визначення запасу за встановленням]
```

Для надійної роботи системи запас за часом встановлення має бути строго додатним:

```
M_setup > 0
T_clk - (t_co_max + t_flight + t_setup + t_skew + t_jitter) > 0   [підстановка визначення M_setup]
T_clk > t_co_max + t_flight + t_setup + t_skew + t_jitter         [додавання затримок до обох частин]
```

Звідси випливає теоретична максимальна тактова частота шини `f_max`:

```
f_max
= 1 / T_clk_min                                                   [зв'язок частоти й мінімального періоду]
= 1 / (t_co_max + t_flight + t_setup + t_skew + t_jitter)         [підстановка сумарної затримки]
```

## 2. Бюджет утримання даних (Hold)

Час утримання гарантує, що передавач не змінить дані занадто швидко, поки приймач ще фіксує стан за поточним тактовим фронтом. Оскільки оновлення даних і стробування відбуваються від одного й того самого тактового фронту, період `T_clk` не входить у нерівність утримання.

Дані змінюються передавачем за мінімальний час `t_co_min` і доходять до приймача за час `t_flight`. Приймач вимагає стабільності протягом `t_hold` після тактового фронту. З урахуванням перекосу такту `t_skew`:

```
M_hold
= (t_co_min + t_flight) - (t_hold + t_skew)                       [визначення запасу за утриманням]
```

Умова відсутності збою утримання:

```
M_hold > 0
t_co_min + t_flight > t_hold + t_skew                             [перенесення вимог приймача вправо]
```

> Якщо `t_co_min + t_flight < t_hold + t_skew`, виникає порушення утримання (англ. *hold violation / race condition*). Це фатальна помилка проєктування: її неможливо усунути зниженням тактової частоти `f_clk`, оскільки період `T_clk` не впливає на цей часовий інтервал. Єдиний фізичний порятунок — штучне додавання затримки в лінію даних (збільшення довжини траси друкованої плати або послідовний RC-фільтр).

## 3. Вплив ємнісного навантаження на затримку виходу (Capacitive Derating)

Значення `t_co` у даташитах вказується для строго фіксованої тестової ємності `C_test` (зазвичай 15 або 30 пФ). У реальній системі повна ємність лінії `C_actual` складається з ємності траси друкованої плати `C_trace` та вхідних ємностей усіх підключених приймачів `C_in`:

```
C_actual = C_trace + ∑ C_in                                       [сума паразитної ємності траси та входів]
```

Коли `C_actual > C_test`, вихідний каскад витрачає додатковий час на перезаряджання надлишкової ємності. Додаткова затримка визначається вихідним опором драйвера `R_drv` у лінійній області:

```
Δt_co = R_drv · (C_actual - C_test)                               [додаткова затримка перезаряджання]
t_co_real = t_co_spec + Δt_co                                     [реальна затримка передавача]
```

Для типових LVCMOS-драйверів із вихідним опором 25–40 Ом коефіцієнт зростання затримки становить приблизно `k_cap ≈ 0.05...0.08 нс/пФ`. Якщо лінія навантажена ємністю 50 пФ замість тестових 15 пФ, затримка `t_co` зростає на:

```
Δt_co
= 0.06 · (50 - 15)                                                [підстановка різниці ємностей]
= 0.06 · 35                                                       [обчислення добутку]
= 2.1 нс                                                          [додаткова затримка сигналу]
```

Це зміщення безпосередньо віднімається від запасу встановлення `M_setup` і може перетворити працездатну шину на збійну.

## 4. Час наростання лінії з відкритим стоком (I2C / Open-Drain)

На шинах з відкритим колектором або стоком (I2C, SMBus, 1-Wire) спад напруги `1 → 0` формується активним відкриттям нижнього польового транзистора (час спаду `t_f` дуже малий, зазвичай 2–10 нс). Наростання `0 → 1` відбувається пасивно — через зовнішній підтяжний резистор `R_p`, який заряджає сумарну паразитну ємність шини `C_b`.

Рівняння заряду ємності через опір підтяжки від напруги живлення `V_DD`:

```
V(t) = V_DD · (1 - e^(-t / (R_p · C_b)))
```

Стандарт I2C визначає час наростання `t_r` як інтервал переходу напруги від рівня логічного нуля `V_IL = 0.3 · V_DD` до рівня логічної одиниці `V_IH = 0.7 · V_DD`.

Знайдемо момент часу `t_1`, коли напруга досягає `0.3 · V_DD`:

```
0.3 · V_DD = V_DD · (1 - e^(-t_1 / (R_p · C_b)))                  [рівняння для порогу 0.3 V_DD]
0.3 = 1 - e^(-t_1 / (R_p · C_b))                                  [скорочення на V_DD]
e^(-t_1 / (R_p · C_b)) = 0.7                                      [перенесення доданків]
-t_1 / (R_p · C_b) = ln(0.7)                                      [натуральний логарифм обох частин]
t_1 = -R_p · C_b · ln(0.7)                                        [множення на -R_p · C_b]
t_1 = R_p · C_b · ln(1 / 0.7)                                     [властивість логарифма ln(1/x) = -ln(x)]
t_1 = R_p · C_b · ln(1.42857)                                     [обчислення частки 1 / 0.7]
t_1 ≈ 0.35667 · R_p · C_b                                         [наближене значення ln(1.42857)]
```

Знайдемо момент часу `t_2`, коли напруга досягає `0.7 · V_DD`:

```
0.7 · V_DD = V_DD · (1 - e^(-t_2 / (R_p · C_b)))                  [рівняння для порогу 0.7 V_DD]
0.7 = 1 - e^(-t_2 / (R_p · C_b))                                  [скорочення на V_DD]
e^(-t_2 / (R_p · C_b)) = 0.3                                      [перенесення доданків]
t_2 = R_p · C_b · ln(1 / 0.3)                                     [розв'язання відносно t_2]
t_2 = R_p · C_b · ln(3.33333)                                     [обчислення частки 1 / 0.3]
t_2 ≈ 1.20397 · R_p · C_b                                         [наближене значення ln(3.33333)]
```

Обчислимо повний час наростання фронту `t_r`:

```
t_r
= t_2 - t_1                                                       [визначення часу наростання від 30% до 70%]
= R_p · C_b · (ln(1 / 0.3) - ln(1 / 0.7))                         [підстановка виразів t_1 та t_2]
= R_p · C_b · ln((1 / 0.3) / (1 / 0.7))                           [властивість різниці логарифмів]
= R_p · C_b · ln(0.7 / 0.3)                                       [спрощення дробу]
= R_p · C_b · ln(2.33333)                                         [ділення 0.7 на 0.3]
≈ 0.84730 · R_p · C_b                                             [кінцевий числовий коефіцієнт]
```

Звідси отримуємо точну формулу граничного опору підтяжки для заданої ємності лінії `C_b` та максимального дозволеного стандартом часу наростання `t_r_max`:

```
R_p_max = t_r_max / (0.8473 · C_b)
```

## 5. Бюджет асиметрії тактового сигналу (Duty Cycle Penalty)

Реальні тактові генератори генерують сигнал зі шпаруватістю, відмінною від ідеальних 50%. Допустимий діапазон шпаруватості вказується як `D = 45%...55%` або `40%...60%`.

Якщо зчитування даних відбувається по протилежному фронту (як у деяких режимах SPI або DDR), тривалість напівперіоду скорочується:

```
T_half_min = T_clk · D_min                                        [мінімальна тривалість напівперіоду]
```

Для тактової частоти 100 МГц (`T_clk = 10 нс`) при шпаруватості 40/60% мінімальний напівперіод становить лише `10 · 0.40 = 4.0 нс` замість 5.0 нс. Штраф за асиметрію складає `1.0 нс`, який має бути повністю врахований у рівнянні бюджету встановлення для операцій, прив'язаних до півтакту.

## 6. Практичні приклади числового розрахунку

### Приклад 1: Читання SPI Flash на частоті 50 МГц (T_clk = 20 нс)

Вихідні параметри з даташитів мікросхем і топології друкованої плати:
- Передавач (SPI NOR Flash W25Q128JV): `t_co_max = 7.0 нс`, `t_co_min = 1.5 нс`;
- Приймач (STM32H7 SPI Master): `t_setup = 3.5 нс`, `t_hold = 1.0 нс`;
- Траса друкованої плати: довжина `L = 120 мм`, діелектрик FR-4 (`v_prop ≈ 6.5 пс/мм`);
- Затримка траси: `t_flight = 120 · 0.0065 = 0.78 нс`;
- Перекіс і джиттер такту: `t_skew = 0.5 нс`, `t_jitter = 0.4 нс`.

Розрахунок запасу за встановленням `M_setup`:

```
M_setup
= T_clk - (t_co_max + t_flight + t_setup + t_skew + t_jitter)     [базова формула запасу]
= 20.0 - (7.0 + 0.78 + 3.5 + 0.5 + 0.4)                           [підстановка числових значень у наносекундах]
= 20.0 - 12.18                                                    [сума всіх затримок кола]
= 7.82 нс                                                         [позитивний часовий запас M_setup > 0]
```

Розрахунок запасу за утриманням `M_hold`:

```
M_hold
= (t_co_min + t_flight) - (t_hold + t_skew)                       [базова формула запасу утримання]
= (1.5 + 0.78) - (1.0 + 0.5)                                      [підстановка значень]
= 2.28 - 1.50                                                     [обчислення різниці]
= 0.78 нс                                                         [позитивний часовий запас M_hold > 0]
```

Обидва запаси додатні (`M_setup = +7.82 нс`, `M_hold = +0.78 нс`), тому шина на частоті 50 МГц функціонуватиме абсолютно надійно у всьому діапазоні температур.

### Приклад 2: Вибір підтяжки для I2C Fast-Mode (400 кГц)

Стандарт I2C Fast-Mode обмежує максимальний час наростання: `t_r_max = 300 нс`.
Сумарна виміряна ємність шини (довгий шлейф + 5 давачів): `C_b = 180 пФ`.

Розрахунок максимально допустимого опору `R_p_max`:

```
R_p_max
= t_r_max / (0.8473 · C_b)                                        [формула максимального опору]
= 300 · 10^(-9) / (0.8473 · 180 · 10^(-12))                       [переведення в одиниці СІ (секунди і фаради)]
= 300 · 10^(-9) / (152.514 · 10^(-12))                            [множення знаменника]
= 1967 Ом ≈ 1.96 кОм                                              [максимальний опір підтяжки]
```

Для забезпечення гарантованого запасу обираємо найближчий стандартний номінал з ряду E24 у бік зменшення: `R_p = 1.8 кОм` (або `1.5 кОм`). Резистор 4.7 кОм чи 10 кОм у такій системі призведе до завалювання фронтів і втрати пакетів ACK.
