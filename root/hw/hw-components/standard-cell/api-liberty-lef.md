# 📋 Специфікація форматів Liberty (.lib) та LEF

У методології напівзамовного проектування цифрових інтегральних схем бібліотека стандартних комірок взаємодіє з інструментами автоматизації проектування (EDA) через формалізовані стандартизовані інтерфейси. Розробнику та комп'ютерним програмам синтезу й автотрасування потрібні два абсолютно різні погляди на одну й ту саму кремнієву комірку:

1. **Електричний та часовий погляд:** як саме змінюється напруга на виході при перемиканні входів, скільки пікосекунд триває затримка поширення сигналу залежно від ємності підключених проводів, скільки струму витікає крізь закриті транзистори у стані спокою та скільки енергії споживається під час перемикання. Цей рівень формалізується специфікацією **Liberty (`.lib`)**.
2. **Абстрактний фізичний та геометричний погляд:** які зовнішні габарити має прямокутник комірки, у яких точках на сітці металізації розташовані контактні майданчики входів і виходів для підключення проводів автороутером, та які області внутрішнього простору зайняті провідниками першого шару металу і заборонені для перетину іншими сигналами. Цей рівень описується специфікацією **LEF (`.lef`, Library Exchange Format)**.

Синтезатор логіки (наприклад, Synopsys Design Compiler чи Yosys) зчитує файл `.lib`, щоб обрати найменший і найшвидший вентиль для реалізації булевої функції, а програма розміщення й трасування (Cadence Innovus, Synopsys IC Compiler II чи OpenROAD) використовує одночасно `.lib` для розрахунку затримок та `.lef` для геометричного пакування вентилів у кремнієві ряди без виникнення топологічних коротких замикань.

---

## 1. Повна специфікація формату Liberty (.lib)

Формат Liberty був розроблений компанією Synopsys у 1987 році та згодом стандартизований консорціумом Open EDA Group і стандартами IEEE 1481 та IEEE 1603. Це людиночитаний текстовий формат з ієрархічною структурою груп, блоків та параметрів, схожою на синтаксис мови програмування C.

### 1.1. Заголовок бібліотеки та визначення середовища

Файл починається з кореневої групи `library (ім'я_бібліотеки)`, у якій задаються глобальні правила інтерпретації всіх числових даних, що містяться всередині.

```text
library (tsmc_cln28hpm_lvt_ss_0p81v_125c) {
  technology (cmos);
  delay_model : table_lookup;
  
  /* Одиниці вимірювання фізичних величин */
  time_unit                     : "1ps";
  voltage_unit                  : "1V";
  current_unit                  : "1mA";
  pulling_resistance_unit       : "1kohm";
  capacitive_load_unit (1.0, ff);
  leakage_power_unit            : "1pW";
  
  /* Порогові рівні для вимірювання затримок та крутості фронтів */
  slew_lower_threshold_pct_fall : 20.0;
  slew_upper_threshold_pct_fall : 80.0;
  slew_lower_threshold_pct_rise : 20.0;
  slew_upper_threshold_pct_rise : 80.0;
  input_threshold_pct_fall      : 50.0;
  input_threshold_pct_rise      : 50.0;
  output_threshold_pct_fall     : 50.0;
  output_threshold_pct_rise     : 50.0;
  
  /* Границі за замовчуванням */
  default_max_transition        : 250.0;
  default_max_capacitance       : 120.0;
  
  /* Робочий кут процесу, напруги та температури (PVT Corner) */
  operating_conditions (slow_0p81v_125c) {
    process     : 1.0;
    voltage     : 0.81;
    temperature : 125.0;
  }
  default_operating_conditions : slow_0p81v_125c;
```

Кожен числовий атрибут у заголовку має суворе призначення:
- `capacitive_load_unit`: вказує множник та розмірність вихідної ємності. Значення `(1.0, ff)` означає, що число 5.4 у будь-якій таблиці ємності читається інструментом як 5.4 фемтофарада (`fF = 10⁻¹⁵ Ф`).
- `slew_lower_threshold_pct` та `slew_upper_threshold_pct`: визначають точки перетину сигналом відсотків від напруги живлення під час вимірювання крутості перехідного процесу (Slew). Стандартний діапазон 20%–80% або 10%–90% визначає, як саме екстраполюється нахил сигналу.
- `operating_conditions`: задає кут характеризації. Для аналізу найгіршого випадку (Worst-Case Slow, SS) напруга занижується на 10% від номіналу (0.81 В для 0.9 В техпроцесу), а температура піднімається до +125°C, що сповільнює рухливість носіїв заряду в каналі транзистора.

### 1.2. Шаблони таблиць пошуку (lu_table_template)

Для розрахунку нелінійних затримок використовуються таблиці вибірки (NLDM, Non-Linear Delay Model). Щоб не повторювати координати опорних сіток у кожній комірці, у заголовку файлу оголошуються спільні шаблони `lu_table_template`.

```text
  lu_table_template (delay_template_7x7) {
    variable_1 : input_net_transition;
    variable_2 : total_output_net_capacitance;
    index_1 ("5.0, 15.0, 35.0, 80.0, 150.0, 280.0, 500.0");
    index_2 ("0.5, 2.0, 6.0, 18.0, 45.0, 100.0, 220.0");
  }
  
  lu_table_template (constraint_template_4x4) {
    variable_1 : related_pin_transition;
    variable_2 : constrained_pin_transition;
    index_1 ("10.0, 40.0, 120.0, 300.0");
    index_2 ("10.0, 40.0, 120.0, 300.0");
  }
```

Змінна `variable_1` завжди позначає аргумент першого виміру (крутість вхідного фронту `S_in` у пікосекундах), а `variable_2` — другого виміру (сумарна вихідна ємність навантаження `C_L` у фемтофарадах). Списки `index_1` та `index_2` задають вузли сітки, для яких на кластері моделювання було виконано точні аналогові симуляції SPICE.

### 1.3. Опис комірки та стан-залежного витоку (cell group)

Кожна логічна комірка описується окремим блоком `cell (ім'я_комірки)`. Блок містить загальні атрибути, опис логічної функції виходів та деталізацію статичного струму витоку.

```text
  cell (NAND2_X1) {
    area           : 0.7056;
    cell_footprint : "nand2";
    
    /* Статична потужність витоку за станами входів */
    leakage_power () {
      value : 14.2;
      when  : "!A & !B";
    }
    leakage_power () {
      value : 48.6;
      when  : "!A & B";
    }
    leakage_power () {
      value : 52.1;
      when  : "A & !B";
    }
    leakage_power () {
      value : 184.5;
      when  : "A & B";
    }
```

Статичний струм витоку суттєво залежить від того, в якому логічному стані перебувають входи комірки:
- Коли обидва входи `A = 0` та `B = 0`, обидва послідовно з'єднані NMOS-транзистори у нижньому плечі закриті. Проміжний вузол між ними набуває плаваючого потенціалу, що створює зворотне зміщення переходу підкладки та підсилює підпороговий бар'єр (так званий ефект стека, англ. *Stack Effect*). Завдяки цьому сумарний струм витоку падає до мінімального значення 14.2 пВт.
- Коли обидва входи `A = 1` та `B = 1`, обидва паралельно з'єднані верхні PMOS-транзистори закриті, але перебувають під повною різницею потенціалів `VDD`, що дає максимальний струм витоку 184.5 пВт.

Інструменти оптимізації потужності використовують ці дані разом із коефіцієнтами ймовірності станів кожного сигналу для точного підрахунку статичних втрат процесора.

### 1.5. Моделі послідовнісних комірок: часові обмеження Setup та Hold

Для тригерів (DFF) та засувок у секції `timing ()` додаються спеціальні типи часових обмежень, які інструмент STA перевіряє для запобігання збоям метастабільності:

```text
  pin (D) {
    direction : input;
    timing () {
      related_pin     : "CLK";
      timing_type     : setup_rising;
      
      /* Таблиця часу встановлення Setup Time */
      rise_constraint (constraint_template_4x4) {
        values ( \
          "15.2, 18.4, 25.1, 42.6", \
          "16.1, 19.3, 26.2, 43.8", \
          "18.5, 21.8, 28.9, 46.7", \
          "24.2, 27.6, 35.1, 53.4" \
        );
      }
    }
    timing () {
      related_pin     : "CLK";
      timing_type     : hold_rising;
      
      /* Таблиця часу утримання Hold Time */
      rise_constraint (constraint_template_4x4) {
        values ( \
          "5.1, 4.8, 4.2, 3.1", \
          "5.8, 5.4, 4.9, 3.8", \
          "7.2, 6.9, 6.3, 5.1", \
          "10.4, 9.8, 9.1, 7.8" \
        );
      }
    }
  }
```

- `setup_rising`: мінімальний час до приходу фронту тактового сигналу `CLK`, протягом якого вхідні дані `D` повинні залишатися стабільними.
- `hold_rising`: мінімальний час після приходу фронту тактового сигналу `CLK`, протягом якого дані `D` заборонено змінювати.

### 1.6. Моделювання керування живленням та мультидоменних схем

У сучасних системах на кристалі з динамічним керуванням напругою (DVFS) та вимкненням живлення блоків (Power Gating) файл Liberty описує спеціалізовані піни живлення та призначення комірок:

```text
  /* Опис фізичних виводів живлення комірки */
  pg_pin (VDD) {
    pg_type        : primary_power;
    voltage_name   : VDD;
  }
  pg_pin (VSS) {
    pg_type        : primary_ground;
    voltage_name   : VSS;
  }
  pg_pin (VDDG) {
    pg_type        : backup_power;
    voltage_name   : VDDG;
  }
```

Для спеціальних комірок живлення додаються атрибути:
- `is_level_shifter : true`: позначає транслятор рівнів, де вхідний пін належить одному домену напруги (наприклад, 0.75 В), а вихідний — іншому (1.1 В).
- `is_isolation_cell : true`: позначає ізоляційну комірку, що фіксує вихід у константу 0 або 1 при активному сигналі `ISO`.
- `retention_cell : "SRPG"`: позначає тригер із тіньовою засувкою, що зберігає біт стану під час знеструмлення основного живлення `VDD` за рахунок резервного живлення `VDDG`.

### 1.7. Моделі шуму та варіативності на кристалі (POCV / LVF)

Для обліку випадкових технологічних флуктуацій виробництва (дрейфу довжини каналу, випадкового розподілу домішок легування) сучасні версії Liberty використовують розширення **LVF (Liberty Variation Format)** або **POCV (Parametric On-Chip Variation)**.

Замість одного детермінованого числа затримки в таблиці додаються матриці середньоквадратичного відхилення `sigma`:

```text
        ocv_sigma_cell_rise (delay_template_7x7) {
          values ( \
            "0.8, 1.1, 1.6, 2.9, 5.4, 11.2, 22.8", \
            "0.9, 1.2, 1.8, 3.1, 5.6, 11.4, 23.1", \
            "1.2, 1.5, 2.1, 3.4, 6.0, 11.8, 23.6", \
            "1.7, 2.0, 2.6, 4.0, 6.6, 12.5, 24.3", \
            "2.6, 2.9, 3.5, 5.0, 7.6, 13.6, 25.5", \
            "4.1, 4.5, 5.1, 6.7, 9.4, 15.5, 27.5", \
            "6.8, 7.2, 7.9, 9.6, 12.4, 18.7, 31.0" \
          );
        }
```

Програма статичного часового аналізу підсумовує математичні сподівання затримок уздовж шляху і додає статистичний розкид `3·σ`, що гарантує надійність роботи схеми з імовірністю 99.73%.

## 2. Повна специфікація формату LEF (Library Exchange Format)

Специфікація LEF була створена компанією Cadence Design Systems як відкритий геометричний стандарт. Її призначення — дати інструментам фізичного проєктування повну інформацію про координати та геометричні межі структур комірки, не перевантажуючи програму мільйонами непотрібних дрібних полігонів внутрішніх транзисторів і захищаючи інтелектуальну власність напівпровідникової фабрики.

### 2.1. Опис технологічних шарів у Technology LEF (tech.lef)

Файл технологічного опису містить константи сітки та правила для кожного шару металізації:

```text
VERSION 5.8 ;
BUSBITCHARS "[]" ;
DIVIDERCHAR "/" ;

UNITS
  DATABASE MICRONS 2000 ;  # 1 мікрон = 2000 дискретних одиниць бази даних DBU
END UNITS

# Шар контакту з транзисторами (Contact)
LAYER CONTACT
  TYPE CUT ;
  SPACING 0.050 ;
END CONTACT

# Перший шар металізації (Metal 1)
LAYER M1
  TYPE ROUTING ;
  DIRECTION HORIZONTAL ;    # Переважний напрямок трасування — горизонтальний
  PITCH 0.140 ;             # Крок сітки треків = 140 нм
  WIDTH 0.065 ;             # Мінімальна ширина провідника = 65 нм
  SPACING 0.065 ;           # Мінімальний технологічний зазор = 65 нм
  RESISTANCE RPERSQ 0.38 ;  # Питомий опір квадрата = 0.38 Ом/квадрат
  CAPACITANCE CPERSQDIST 0.00021 ;
  
  # Правило мінімальної площі провідника для запобігання відриву металу
  MINENCLOSEDAREA 0.012 ;
END M1

# Перехідний отвір між Metal 1 та Metal 2
LAYER VIA1
  TYPE CUT ;
  SPACING 0.060 ;
END VIA1

# Другий шар металізації (Metal 2)
LAYER M2
  TYPE ROUTING ;
  DIRECTION VERTICAL ;      # Переважний напрямок трасування — вертикальний
  PITCH 0.160 ;
  WIDTH 0.070 ;
  SPACING 0.070 ;
  RESISTANCE RPERSQ 0.32 ;
END M2
```

Чергування напрямків трасування (шар M1 — горизонтальний, шар M2 — вертикальний, шар M3 — знову горизонтальний) є непорушним правилом проектування СБІС, оскільки ортогональна структура запобігає паралельному перехресному наведенню шумів (Cross-talk) між сусідніми шарами та спрощує роботу алгоритмів автотрасування Дейкстри і лабіринтного трасування Лі.

### 2.2. Опис посадкового місця ряду (SITE statement)

```text
SITE CoreSite
  CLASS CORE ;
  SIZE 0.140 BY 1.260 ;   # Ширина 1 сайту (140 нм) на висоту (1.26 мкм = 9 треків M1)
  SYMMETRY X Y ;          # Дозволені перетворення: пряме (R0), віддзеркалене по X (MX), по Y (MY)
END CoreSite
```

### 2.3. Геометричний опис макрокомірки (Macro LEF)

Файл комірок описує кожну комірку як геометричний макрос `MACRO`:

```text
MACRO NAND2_X1
  CLASS CORE ;
  ORIGIN 0.000 0.000 ;
  SIZE 0.840 BY 1.260 ;   # Ширина 6 сайтів (6 × 0.140 мкм) на висоту 1.260 мкм (9T)
  SYMMETRY X Y ;
  SITE CoreSite ;
  
  /* Шина живлення VDD на верхньому краї комірки (шар Metal 1) */
  PIN VDD
    DIRECTION INOUT ;
    USE POWER ;
    SHAPE ABUTMENT ;
    PORT
      LAYER M1 ;
        RECT 0.000 1.160 0.840 1.260 ;
    END
  END VDD
  
  /* Шина землі VSS на нижньому краї комірки (шар Metal 1) */
  PIN VSS
    DIRECTION INOUT ;
    USE GROUND ;
    SHAPE ABUTMENT ;
    PORT
      LAYER M1 ;
        RECT 0.000 0.000 0.840 0.100 ;
    END
  END VSS
  
  /* Вхідний логічний пін A */
  PIN A
    DIRECTION INPUT ;
    USE SIGNAL ;
    PORT
      LAYER M1 ;
        RECT 0.240 0.580 0.320 0.680 ;
    END
  END A
  
  /* Вхідний логічний пін B */
  PIN B
    DIRECTION INPUT ;
    USE SIGNAL ;
    PORT
      LAYER M1 ;
        RECT 0.440 0.380 0.520 0.480 ;
    END
  END B
  
  /* Вихідний логічний пін Y */
  PIN Y
    DIRECTION OUTPUT ;
    USE SIGNAL ;
    PORT
      LAYER M1 ;
        RECT 0.680 0.480 0.780 0.780 ;
    END
  END Y
  
  /* Шари внутрішніх перешкод (Obstructions / OBS) */
  OBS
    LAYER M1 ;
      # Забороняє роутеру прокладати сторонні горизонтальні траси крізь комірку
      RECT 0.080 0.180 0.760 1.080 ;
  END
END NAND2_X1
```

Елементи геометрії LEF:
- `SHAPE ABUTMENT`: позначає, що металева смуга пінів VDD/VSS доходить суворо до краю рамки комірки (`SIZE`). При щільному примиканні (*abutment*) сусідніх комірок у ряду ці прямокутники автоматично зливаються у неперервну суцільну лінію живлення кристала.
- `RECT x1 y1 x2 y2`: координати прямокутника піна. Кожен такий прямокутник у виробленому LEF проектується так, щоб він повністю накривав хоча б одну точку перетину горизонтального треку M1 та вертикального треку M2. Це гарантує, що автотрасувальник зможе опустити на цей пін стандартний перехідний отвір VIA1 без виникнення порушень зазорів (DRC).
- `OBS (Obstructions)`: визначає внутрішні шари перешкод (зони відчуження). Оскільки всередині комірки шар Metal 1 уже використаний для з'єднання стоків PMOS та NMOS транзисторів, блок OBS забороняє алгоритму P&R прокладати крізь цей внутрішній прямокутник сторонні дроти інших сигналів, запобігаючи паразитичним коротким замиканням.

### 2.4. Правила генерації перехідних отворів (VIARULE)

Для з'єднання провідників між шарами металу у файлі Technology LEF описуються правила генерації стандартних матриць перехідних отворів:

```text
VIARULE M1_M2_GENERATE GENERATE
  LAYER M1 ;
    ENCLOSURE 0.010 0.010 ;
  LAYER VIA1 ;
    RECT -0.025 -0.025 0.025 0.025 ;
    SPACING 0.060 BY 0.060 ;
  LAYER M2 ;
    ENCLOSURE 0.010 0.010 ;
END M1_M2_GENERATE
```

Оператор `ENCLOSURE` гарантує, що верхній та нижній металевий шар перекривають отвір перехідного отвору щонайменше на 10 нанометрів у кожну сторону, захищаючи структуру від технологічного зміщення фотошаблонів під час літографії.

## 3. Таблиця зв'язку між форматами Liberty, LEF та Verilog

Усі інструменти маршруту проектування спираються на сувору відповідність між абстрактними поданнями однієї й тієї самої комірки:

| Рівень опису | Liberty (.lib) | LEF (.lef) | Verilog (.v) | Відповідальний інструмент САПР |
| :--- | :--- | :--- | :--- | :--- |
| **Ім'я елемента** | `cell (INV_X2)` | `MACRO INV_X2` | `module INV_X2 (Y, A);` | Усі інструменти (Synthesis, P&R, STA) |
| **Логічна поведінка** | `function : "!A";` | *відсутня (прихована)* | `assign Y = ~A;` | Логічний синтез та симуляція |
| **Геометрія та площа** | `area : 0.4704;` | `SIZE 0.560 BY 0.840;` | *відсутня* | Placement & Floorplanning |
| **Вхідні/вихідні піни** | `pin (A) { dir: in; }` | `PIN A { DIR INPUT; }` | `input A; output Y;` | Global & Detail Routing |
| **Затримка сигналу** | Таблиці `cell_rise/fall` | *відсутня* | Блок `specify` / SDF | Static Timing Analysis (STA) |
| **Внутрішні перешкоди** | *відсутні* | Секція `OBS { RECT... }` | *відсутня* | Detail Router (DRC clean) |

## 4. Верифікація та контроль якості бібліотек (Library QA)

Перед випуском бібліотеки стандартних комірок для виробництва вона проходить через автоматизовані тести контролю якості (QA, Quality Assurance):

1. **Перевірка монотонності таблиць затримок:** таблиці Liberty повинні бути суворо монотонними. При зростанні вихідної ємності навантаження `C_L` або крутості вхідного фронту `S_in` час затримки `t_pd` зобов'язаний суворо монотонно зростати. Будь-який чисельний збій у симуляторі SPICE, що призвів до локального зменшення затримки у сусідній комірці таблиці, створює математичний від'ємний нахил, який ламає градієнтні алгоритми оптимізації таймінгів STA.
2. **Перевірка еквівалентності відбитка (Footprint Consistency):** усі варіанти комірки з однаковим параметром `cell_footprint` (наприклад, `AND2_X1_HVT` та `AND2_X1_LVT`) зобов'язані мати ідентичну кількість пінів, однаковий порядок виводів та точну відповідність булевої функції, щоб заміна комірки не змінила логіки роботи пристрою.
3. **Геометрична валідація LEF проти GDSII:** координати та шари прямокутників `PIN` у файлі LEF попіксельно зіставляються з повним кресленням топології GDSII. Металевий пін у LEF повинен гарантовано лежати всередині реального фізичного шару металу на кремнії.
4. **Контроль доступності пінів (Pin Accessibility Check):** на техпроцесах 7 нм і нижче металеві лінії настільки тонкі, що інструмент перевіряє, скільки фізичних позицій (*access points*) для опускання перехідного отвору VIA1 має кожен пін. Якщо пін має лише одну точку доступу і вона блокується сусіднім трасуванням, комірка вважається дефектною і перемальовується топологом.
5. **Компіляція та валідація бази даних:** текстові файли `.lib` компілюються у двійковий формат `.db` за допомогою утиліти `lc_shell` (Library Compiler), що перевіряє синтаксичну цілісність посилань та коректність булевих виразів. Файли LEF транслюються у внутрішні бази даних OpenAccess або NDM, створюючи єдине перевірене середовище проектування.

## 5. Типові пастки та помилки при інтеграції бібліотек

Практичний досвід розробки ASIC свідчить про наявність кількох типових пасток при роботі з моделями бібліотек:

1. **Неузгодженість типу однорідності (Unateness Mismatch):** якщо для інвертора помилково вказано `timing_sense : positive_unate` замість `negative_unate`, синтезатор неправильно розрахує полярність логічного дерева і вставить зайві інвертори, що спотворить функціональну поведінку схеми.
2. **Проблема прихованих пінів підкладки (Hidden Power/Ground Pins):** якщо в транзисторному нетлісті SPICE присутні виводи `VDD`, `VSS`, `VBP` (bias PMOS) та `VBN` (bias NMOS), але виводи зміщення підкладки відсутні у файлі LEF, етап фізичної верифікації LVS завершиться фатальною помилкою невідповідності кількості вузлів (*Net Count Mismatch*).
3. **Пастка від'ємних інтерпольованих затримок (Negative Delay Trap):** при екстраполяції таблиць затримок NLDM для дуже крутих фронтів чистий лінійний нахил може перетнути нуль і стати від'ємним числом. Більшість таймерів STA при виявленні затримки `t_pd < 0` аварійно завершують роботу або блокують розрахунок часового бюджету конвеєра.
4. **Розбіжність одиниць вимірювання (Units Mismatch):** якщо файл Liberty скомпільовано в одиницях часу наносекунди (`1ns`), а файл обмежень проекту SDC очікує пікосекунди (`1ps`), розраховані синтезатором затримки виявляться помилковими у 1000 разів, що призведе до повного руйнування часового дерева схеми.

Розуміння формату та внутрішніх обмежень моделей Liberty та LEF дозволяє інженерам вчасно виявляти топологічні та часові аномалії ще до відправки проекту на фабрику.
