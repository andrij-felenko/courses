# 🧮 Математична модель енергетичного бюджету DTIM та TWT

Автономний пристрій із бездротовим інтерфейсом Wi-Fi підпорядковується закону збереження електричного заряду: кожна мілісекунда перебування радіочастотного тракту в активному стані вимагає перенесення певної кількості кулонів від хімічного джерела живлення до напівпровідникового кристала. Якщо виміряти миттєвий струм у часі `i(t)`, то сумарний заряд `Q`, спожитий за повний цикл роботи тривалістю `T_цикл`, є інтегралом струму за часом:

```
Q = ∫ i(t) dt      [інтегрування миттєвого струму за періодом T_цикл]
```

Оскільки апаратний стан вузла змінюється дискретними кроками (глибокий сон, перехідний процес запуску генератора, прийом кадру, передача підтвердження), інтеграл розпадається на суму добутків середнього струму кожної фази `I_k` на її тривалість `t_k`:

```
Q_цикл = ∑ I_k · t_k = Q_сон + Q_пробудження + Q_прийом + Q_передача
```

Середній струм `I_сер`, який визначає швидкість вичерпання ємності батареї, дорівнює сумарному заряду, поділеному на період циклу:

```
I_сер = Q_цикл / T_цикл
```

Ця формула є спільною для всіх бездротових технологій, проте внутрішня структура компонентів заряду `Q_k` у протоколах IEEE 802.11 має специфічну залежність від конфігурації маякових інтервалів DTIM, дрейфу низькочастотного тактового генератора та механізмів планування трафіку.

## Захисний інтервал та дрейф низькочастотного кварцу

У режимі періодичного прослуховування маяків (англ. *beacon listening*) бездротовий вузол спить між кадрами DTIM, використовуючи для відліку часу допоміжний генератор реального часу (RTC) із частотою 32.768 кГц. Кожен кварцовий резонатор має технологічну похибку номіналу та температурний дрейф частоти, що вимірюється в мільйонних частках (англ. *parts per million*, ppm). Якщо сумарне відхилення частоти становить `Δf_ppm`, то за час сну `T_сон` внутрішній годинник вузла накопичує абсолютну похибку часу `Δt_дрейф`:

```
Δt_дрейф = T_сон · (Δf_ppm · 10⁻⁶)
```

Оскільки точка відліку часу може зміститися як у бік відставання, так і в бік випередження відносно годинника точки доступу, приймач зобов'язаний увімкнутися завчасно — на величину захисного інтервалу `t_захист` (англ. *guard time*), щоб не пропустити преамбулу маякового кадру:

```
t_захист = 2 · Δt_дрейф + t_стабілізація
= 2 · T_сон · Δf_ppm · 10⁻⁶ + t_стабілізація
```

де `t_стабілізація` — апаратний час виходу високочастотного кварцового генератора (40 МГц) на стабільну амплітуду та захоплення частоти фазовим автопідстроюванням синтезатора (PLL).

Нехай період DTIM дорівнює `T_сон = 1.024 с` (DTIM = 10 при інтервалі маяка 102.4 мс), похибка генератора `Δf_ppm = ±50 ppm`, а час виходу синтезатора на режим `t_стабілізація = 1.5 мс`. Обчислимо мінімальний захисний інтервал:

```
t_захист
= 2 · 1.024 · 50 · 10⁻⁶ + 0.0015 с    [підстановка параметрів]
= 0.0001024 + 0.0015 с               [розрахунок дрейфу: 102.4 мкс]
≈ 1.602 мс                           [сумарне випередження увімкнення RX]
```

Якщо вузол збільшує період сну до 10 секунд (DTIM = 100), дрейф зростає до `2 · 10 · 50 · 10⁻⁶ = 1.0 мс`, що разом із часом стабілізації вимагає увімкнення приймача за 2.5 мс до розрахункового часу приходу маяка. Увесь цей час радіочастотний тракт споживає повний струм прийому `I_rx ≈ 65–85 мА`, слухаючи порожній ефір.

## Енергетична ціна прослуховування DTIM-маяка

Кожен сеанс перевірки наявності буферизованого трафіку без передачі корисних даних вимагає витрати заряду `Q_маяк`:

```
Q_маяк = I_актив_старт · t_стабілізація + I_rx · (t_захист_дрейф + t_маяк + t_затримка_csma)
```

де:
- `t_маяк` — тривалість передачі кадру Beacon в ефірі (залежить від базової швидкості та розміру елементів інформації, типово 0.8–2.5 мс);
- `t_затримка_csma` — випадкова затримка виходу маяка в ефір через зайнятість середовища стороннім трафіком (механізм CSMA/CA на точці доступу). У завантажених мережах ця затримка може досягати 5–15 мс, протягом яких клієнт змушений залишатися в режимі RX.

Розрахуємо середній струм фонового чергування `I_фоновий` вузла, який перебуває в стані Light-Sleep (`I_сон = 1.2 мА`) і перевіряє маяки з періодом DTIM-3 (`T_dtim = 307.2 мс`):

```
Q_маяк
= 25 мА · 1.5 мс + 70 мА · (0.031 мс + 1.2 мс + 0.5 мс) [стабілізація + прийом маяка]
= 37.5 мкКл + 70 мА · 1.731 мс                         [додавання фаз прийому]
= 37.5 мкКл + 121.17 мкКл                              [добуток струму RX на час]
≈ 158.67 мкКл                                          [сумарний заряд на один маяк]

Q_сон
= I_сон · (T_dtim − t_актив)                           [заряд фази сну]
= 1.2 мА · (307.2 мс − 3.231 мс)                       [віднімання активного часу]
= 1.2 мА · 303.969 мс                                  [множення струму на тривалість]
≈ 364.76 мкКл                                          [заряд утримання оперативної пам'яті]

I_фоновий
= (Q_маяк + Q_сон) / T_dtim                            [визначення середнього струму]
= (158.67 мкКл + 364.76 мкКл) / 307.2 мс               [сума зарядів за період]
= 523.43 мкКл / 307.2 мс                               [ділення заряду на час циклу]
≈ 1.704 мА                                             [середній струм у режимі DTIM-3]
```

Як бачимо, навіть за повної відсутності передачі корисних пакетів вузол споживає 1.7 мА. Від акумулятора ємністю 2000 мА·год такий пристрій пропрацює не більше:

```
t_життя = 2000 мА·год / 1.704 мА ≈ 1173 год ≈ 48.9 доби
```

## Математичне порівняння Legacy PS-Poll та U-APSD

Коли в карті індикації трафіку TIM виявлено буферизовані дані, клієнт повинен ініціювати їх завантаження. Порівняємо заряди, необхідні для отримання `N` пакетів двома різними методами.

### 1. Модель Legacy PS-Poll

Для кожного з `N` кадрів вузол виконує окремий цикл CSMA/CA, відправляє керівний кадр `PS-Poll`, очікує підтвердження `ACK`, приймає кадр даних `Data` і відправляє свій `ACK`:

```
Q_pspoll_1
= Q_контеншн + Q_tx(PS-Poll) + Q_sifs + Q_rx(Data) + Q_sifs + Q_tx(ACK)
```

Заряд одного циклу покадрового вилучення:

```
Q_pspoll_1
= I_rx · (DIFS + CW_сер · SlotTime) + I_tx · t_pspoll + 2 · I_rx · SIFS + I_rx · t_data + I_tx · t_ack
```

Для `N` буферизованих пакетів сумарний заряд масштабується лінійно:

```
Q_pspoll_сума = N · Q_pspoll_1
```

При типових значеннях (`t_pspoll = 40 мкс`, `t_ack = 30 мкс`, `t_data = 250 мкс`, `SIFS = 10 мкс`, `DIFS = 28 мкс`, середній бекоф `CW_сер · SlotTime = 7.5 · 9 мкс = 67.5 мкс`, `I_tx = 220 мА`, `I_rx = 75 мА`):

```
Q_pspoll_1
= 75 · (0.028 + 0.0675) + 220 · 0.040 + 2 · 75 · 0.010 + 75 · 0.250 + 220 · 0.030 [підстановка параметрів у мкКл]
= 7.16 + 8.80 + 1.50 + 18.75 + 6.60 мкКл                                           [проміжне додавання складових]
≈ 42.81 мкКл                                                                        [заряд на один пакет]
```

Для пакета з 4 кадрів сумарний заряд складе `4 · 42.81 = 171.24 мкКл`.

### 2. Модель WMM U-APSD

У режимі U-APSD клієнт виконує лише одну процедуру змагання за канал, відправляє один тригерний кадр (англ. *Trigger Frame*), після чого точка доступу передає всі `N` пакетів у межах єдиного інтервалу обслуговування (англ. *Service Period*, SP) з короткими міжкадровими інтервалами SIFS:

```
Q_uapsd_сума
= Q_контеншн + Q_tx(Trigger) + ∑ [Q_sifs + Q_rx(Data_k)] + Q_sifs + Q_tx(BlockACK)
```

Обчислимо заряд для тих самих 4 пакетів:

```
Q_uapsd_сума
= 75 · (0.028 + 0.0675) + 220 · 0.040 + 4 · (75 · 0.010 + 75 · 0.250) + 75 · 0.010 + 220 · 0.036 [підстановка значень]
= 7.16 + 8.80 + 4 · (0.75 + 18.75) + 0.75 + 7.92                                                   [розкриття добутків]
= 15.96 + 78.00 + 8.67                                                                             [підсумовування фаз]
≈ 102.63 мкКл                                                                                      [сумарний заряд]
```

Виграш у витраті енергії становить:

```
ΔQ = (171.24 − 102.63) / 171.24 ≈ 40.1% економії заряду
```

## Модель розкладу Target Wake Time (Wi-Fi 6)

У протоколі Wi-Fi 6 (IEEE 802.11ax) механізм TWT повністю усуває необхідність прослуховування проміжних DTIM-маяків та змагання за доступ до каналу за протоколом CSMA/CA. Точка доступу призначає клієнту детермінований інтервал обслуговування TWT SP із фіксованим початком `t_twt_start` та тривалістю `t_sp`.

Енергетичний баланс за один інтервал передачі `T_twt` (наприклад, 1 година = 3600 с) у режимі Deep-Sleep (`I_deep = 10 мкА`):

```
Q_цикл_twt = Q_deep_sleep + Q_boot + Q_sp
```

де:
- `Q_deep_sleep = I_deep · (T_twt − t_актив) ≈ 0.010 мА · 3599.95 с ≈ 36.0 мКл`;
- `Q_boot = I_cpu_boot · t_boot ≈ 20 мА · 15 мс = 0.3 мКл`;
- `Q_sp = I_tx · t_tx + I_rx · t_rx ≈ 240 мА · 5 мс + 70 мА · 10 мс = 1.2 мКл + 0.7 мКл = 1.9 мКл`.

Сумарний заряд циклу:

```
Q_цикл_twt
= 36.0 мКл + 0.3 мКл + 1.9 мКл                       [додавання компонентів]
= 38.2 мКл                                           [сумарний заряд за 1 годину]

I_сер_twt
= 38.2 мКл / 3600 с                                  [визначення середнього струму]
= 0.0382 Кл / 3600 с                                 [переведення одиниць]
≈ 10.61 мкА                                          [середній струм за цикл TWT]
```

Порівняємо з режимом DTIM-3, де фоновий струм становив 1.704 мА: середній струм вузла знизився у `1704 мкА / 10.61 мкА ≈ 160 разів`.

Розрахуємо теоретичний термін служби від елемента живлення Li-SOCl2 типорозміру AA з ємністю `C = 2400 мА·год` при коефіцієнті корисної ємності `k_use = 0.85` (`C_eff = 2040 мА·год`):

```
T_експлуатації
= C_eff / I_сер_twt                                  [розрахунок часу життя]
= 2040 мА·год / 0.01061 мА                           [підстановка значень]
≈ 192 271 год                                        [час у годинах]
≈ 8011 діб                                           [переведення в доби]
≈ 21.9 року                                          [переведення в роки]
```

У реальних умовах граничний термін буде обмежений струмом внутрішнього саморозряду літієвої комірки (~1% на рік, що еквівалентно постійному витоку близько 2.7 мкА) і становитиме близько 15–18 років безперервної автономної роботи.
